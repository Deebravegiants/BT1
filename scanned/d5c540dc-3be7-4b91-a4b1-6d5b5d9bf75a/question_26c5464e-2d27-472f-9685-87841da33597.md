[EmporiumUpgradeable.verifyWallet, usedMessages] Attacker crafts a CircomData.emporiumMessage value M and gets it consumed (usedMessages[M]=true) on Emporium instance A via a legitimate small runAction call, then reuses the exact same signed EmporiumStack (with signerAddress, ops, maxFee, deadline) and CircomData against a freshly redeployed Emporium instance B (same bytecode/address pattern via HinkalFactory.deployHinkal on a forked/duplicate chain state) where usedMessages[M] is false because B's storage is separate EmporiumStorageLocation. Preconditions: proof was already accepted once on A. Call sequence: runAction(B,...) -> verifyWallet checks $.usedMessages[M] against B's own storage only, passes, replays stack.ops. Equality broken: usedMessages[M] should be a global one-time-use flag per (message, wallet-owner intent) but is only local per contract instance, so 'one signed EmporiumOperation set == one execution' fails across instances. Impact: Critical, attacker/relay can force the wallet owner's authorised call graph to execute twice, double-moving wallet funds through IHinkalWallet.callHinkalWallet. Foundry test: deploy two EmporiumStorage-bearing proxies, replay identical stack+circomData, assert both runAction calls succeed (SINGLE_SPEND analog for messages breaks).
