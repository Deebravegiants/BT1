## Analog CVE-2019-15610 finding

### Title
Stale LDAP-cached role/session retains privileged access after upstream group removal - (File: core/sessions/ldapauth/sync.go)

### Summary
CVE-2019-15610 describes retained access in Nextcloud Circles after a member was removed, because the removal was not propagated to enforcement checks. The chainlink LDAP authentication provider has an analogous class of bug: user roles are cached in local `ldap_sessions` / `ldap_user_api_tokens` tables at login time, and this cache is only refreshed by an explicit sync job — not on every authenticated request. If `UpstreamSyncInterval` is left at its default of `'0s'`, the periodic background sync is disabled entirely and the state is only refreshed once at node startup, per the code comment. [1](#0-0) [2](#0-1) 

### Finding Description
`AuthenticationProvider.AuthorizedUserWithSession` is the per-request authorization check used to authenticate every gin request via `AuthenticateBySession`. [3](#0-2) 
For the LDAP driver, this check looks up the session's cached role from the local `ldap_sessions` table rather than the LDAP server, since queries directly against the LDAP directory are not made per-request. This cached role/user_email/user_role mapping is only updated when `LDAPServerStateSyncer.Work` runs — triggered either at node startup (when `UpstreamSyncInterval` is `0s`, per the `Start` method), on a timer (only if `UpstreamSyncInterval` is configured to a non-zero duration), or during explicit login/logout flows. [2](#0-1) [4](#0-3) 

The `Work` function is the only code path that purges sessions/API tokens for users removed from LDAP groups (`emailsToPurge`/`apiTokenEmailsToPurge`) and updates the cached `user_role` for still-present users. [5](#0-4) 
Until that sync runs again, a user who has been removed from their group upstream (analogous to being "removed from a circle" in the CVE) retains their previously cached role and continues to be authorized by `AuthorizedUserWithSession`, since that function only checks the local `ldap_sessions` row, not live upstream state, for each incoming request.

The documentation for `UpstreamSyncInterval` explicitly acknowledges this is only refreshed "during login/logout actions" absent a periodic interval, confirming the cached authorization state is not continuously re-validated against the source of truth. [6](#0-5) 

### Impact Explanation
A user whose LDAP group membership is revoked by an administrator (e.g., demoted from Admin to no access, or removed entirely) retains their prior role's authorization for existing sessions/API tokens until the next sync event. With `UpstreamSyncInterval` at its documented default of `'0s'` (sync disabled outside login/logout/startup), a revoked but still-active session can continue exercising the previously granted role — including Admin-level node API operations — for an indefinite period if the session doesn't naturally expire or if no other user triggers a login/logout that runs `Work`. This is a concrete authorization/role-bypass condition reachable by an already-authenticated, but subsequently de-privileged, client.

### Likelihood Explanation
This requires the deployment to use the LDAP authentication method (`WebServer.AuthenticationMethod = 'ldap'`) and to leave `UpstreamSyncInterval` at its documented default of `0s` (or configure a long interval), which per the config docs is the standard/default configuration. No special network position or credentials beyond a previously valid session/API token are required — the actor is simply a legitimately-authenticated user who was later demoted/removed upstream.

### Recommendation
- Re-validate a session's role against the LDAP source of truth (or at minimum re-check group membership) on each `AuthorizedUserWithSession` call, not only at fixed sync intervals, or drastically shorten the effective cache lifetime.
- Consider making `UpstreamSyncInterval = '0s'` no longer disable periodic sync (i.e., set a mandatory minimum non-zero interval), since the current default silently defers all revocation enforcement to login/logout/startup events only.
- Ensure `SessionTimeout` and the sync interval are tightly bounded so that a revoked user's stale cached role cannot outlive a bounded, short window.

### Proof of Concept
1. Configure `WebServer.AuthenticationMethod = 'ldap'` with default `UpstreamSyncInterval = '0s'`.
2. User A logs in while a member of the `NodeAdmins` LDAP group; `CreateSession` inserts a row into `ldap_sessions` with `user_role = 'admin'`. [7](#0-6) 
3. Administrator removes User A from the `NodeAdmins` LDAP group upstream (analogous to removing an email from a Nextcloud circle).
4. Because `UpstreamSyncInterval` is `0s`, the periodic `Work` sync does not run again automatically, and no other login/logout event triggers it. [8](#0-7) 
5. User A continues making authenticated requests using their still-valid session cookie/token; `AuthorizedUserWithSession` (via the ORM's session lookup) keeps returning the stale cached `user_role = 'admin'`, granting continued admin-level API access despite upstream revocation.

func (l *LDAPServerStateSyncer) Start(ctx context.Context) error {
	// If enabled, start a background task that calls the Sync/Work function on an
	// interval without needing an auth event to trigger it
	// Use IsInstant to check 0 value to omit functionality.
	if !l.config.UpstreamSyncInterval().IsInstant() {
		l.lggr.Info("LDAP Config UpstreamSyncInterval is non-zero, sync functionality will be called on a timer, respecting the UpstreamSyncRateLimit value")
		go l.run()
	} else {
		// Ensure upstream server state is synced on startup manually if interval check not set
		l.Work(ctx)
	}
	return nil
}

func (l *LDAPServerStateSyncer) Work(ctx context.Context) {
	// Purge expired ldap_sessions and ldap_user_api_tokens
	recordCreationStaleThreshold := l.config.SessionTimeout().Before(time.Now())
	err := l.deleteStaleSessions(ctx, recordCreationStaleThreshold)
	if err != nil {
		l.lggr.Error("unable to expire local LDAP sessions: ", err)
	}
	recordCreationStaleThreshold = l.config.UserAPITokenDuration().Before(time.Now())
	err = l.deleteStaleAPITokens(ctx, recordCreationStaleThreshold)
	if err != nil {
		l.lggr.Error("unable to expire user API tokens: ", err)
	}

	// Optional rate limiting check to limit the amount of upstream LDAP server queries performed
	if !l.config.UpstreamSyncRateLimit().IsInstant() {
		if !time.Now().After(l.nextSyncTime) {
			return
		}

		// Enough time has elapsed to sync again, store the time for when next sync is allowed and begin sync
		l.nextSyncTime = time.Now().Add(l.config.UpstreamSyncRateLimit().Duration())
	}

	l.lggr.Info("Begin Upstream LDAP provider state sync after checking time against config UpstreamSyncInterval and UpstreamSyncRateLimit")

// AuthenticateBySession authenticates the request by the session cookie.

// Implements authMethod
func AuthenticateBySession(c *gin.Context, authr Authenticator) error {
	ctx := c.Request.Context()
	session := sessions.Default(c)
	sessionID, ok := session.Get(SessionIDKey).(string)
	if !ok {
		return auth.ErrorAuthFailed
	}

	user, err := authr.AuthorizedUserWithSession(ctx, sessionID)
	if err != nil {
		return err
	}

	c.Set(SessionUserKey, &user)

	return nil
}
