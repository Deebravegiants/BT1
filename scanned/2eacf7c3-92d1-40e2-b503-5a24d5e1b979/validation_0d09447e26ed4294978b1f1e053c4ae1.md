## Title
CORS wildcard-origin allowlist bypass via missing-dot suffix match in gateway HTTP server - (File: `core/services/gateway/network/httpserver.go`)

## Summary
The gateway's public-facing HTTP server implements a wildcard-origin CORS allowlist by stripping the `*.` prefix from a configured allowed origin and then checking `strings.HasSuffix(originHost, allowedHost)`. Because this suffix check does not verify that the character preceding the match is a `.` (i.e., that the origin is actually a subdomain), an attacker who registers a domain that merely ends with the allowed domain's characters (with no separating dot) is treated as a trusted subdomain. This is the same bug class as CVE-2024-10963 (pam_access misinterpreting configuration entries as hostnames, allowing an attacker to impersonate a trusted host and bypass access control).

## Finding Description
`isAllowedOrigin` computes the host allowlist match as follows: [1](#0-0) 

For a configured entry like `https://*.ethereum.org`, `allowedHost` becomes `ethereum.org` after stripping `*.`, and the code performs `strings.HasSuffix(originHost, "ethereum.org")`. This check is purely a string-suffix match with no requirement that `originHost` contains a `.` immediately before the matched suffix. As a result, an attacker-registered domain such as `evilethereum.org` satisfies `HasSuffix("evilethereum.org", "ethereum.org") == true`, even though `evilethereum.org` is not a subdomain of `ethereum.org` at all — it's an entirely different, attacker-controlled domain that merely shares a trailing character sequence.

The scheme and port are also matched via naive string comparisons after the same lowercase-and-split logic (`splitURL`), which does not perform any canonicalization beyond `net.SplitHostPort`/`url.Parse`, so the only gate protecting the origin space is this suffix comparison: [2](#0-1) 

This allowlist directly gates whether the server reflects the `Origin` header back with `Access-Control-Allow-Origin`, effectively granting the origin CORS trust: [3](#0-2) 

This is reachable by any unprivileged client on the internet-facing gateway HTTP server simply by sending a request with a crafted `Origin` header from a domain they control (e.g. `evilethereum.org`), with no prior authentication needed to trigger the check.

## Impact Explanation
When `CORSEnabled` is set and `CORSAllowedOrigins` contains a wildcard entry such as `*.ethereum.org`, an attacker who registers any domain ending in the allowed suffix without a dot separator (e.g., `evilethereum.org`, `notethereum.org`) can have their origin treated as trusted. Browsers from that attacker-controlled origin will then receive `Access-Control-Allow-Origin: <attacker-origin>` on gateway responses, allowing cross-origin JavaScript on the attacker's site to read authenticated/sensitive gateway responses via a victim's browser (credentialed or session-bound requests), which is a cross-user/cross-origin response confusion and access-control bypass consistent with the impact criteria (unauthorized access to responses intended for another origin/user).

## Likelihood Explanation
Exploitation only requires: (1) the gateway operator to configure at least one wildcard entry in `CORSAllowedOrigins` (a documented, supported feature — see `CORSAllowedOrigins` wildcard test coverage in `core/services/gateway/network/httpserver_test.go`), and (2) the attacker to register a cheap domain that has the allowed domain as a raw string suffix. No network position, credentials, or race conditions are needed — the attacker simply serves a page from their domain and has a victim's browser visit it, then issues a cross-origin fetch to the gateway. This matches the CVSS `AC:H` characterization in the source CVE (some attacker setup/domain registration required, but otherwise trivial and remotely triggerable).

## Recommendation
Fix `isAllowedOrigin` in `core/services/gateway/network/httpserver.go` to require a `.` (or exact equality) immediately before the matched suffix when validating wildcard hosts, e.g.:
```go
if strings.HasPrefix(allowedHost, "*.") {
    suffix := allowedHost[1:] // keep the leading dot, e.g. ".ethereum.org"
    if strings.HasSuffix(originHost, suffix) {
        return true
    }
}
```
This ensures `originHost` must literally be `<something>.ethereum.org` (or exactly `ethereum.org`, already handled by the exact-match branch), not just share a trailing byte sequence. Add regression tests for adversarial inputs like `evilethereum.org`, `notethereum.org`, and other suffix-sharing domains to ensure they are rejected.

## Proof of Concept
1. Configure the gateway HTTP server with `CORSEnabled = true` and `CORSAllowedOrigins = ["https://*.ethereum.org"]`.
2. Attacker registers `https://evilethereum.org` and serves a page there with a cross-origin `fetch()`/`XMLHttpRequest` to the gateway endpoint, setting `Origin: https://evilethereum.org`.
3. Server's `handleRequest` calls `isAllowedOrigin("https://evilethereum.org")`:
   - `splitURL` yields `originHost = "evilethereum.org"`.
   - Loop compares against allowed entry `https://*.ethereum.org` → `allowedHost` stripped to `"ethereum.org"`.
   - `strings.HasSuffix("evilethereum.org", "ethereum.org")` returns `true`.
4. Server responds with `Access-Control-Allow-Origin: https://evilethereum.org`, granting the attacker's origin CORS access to the gateway response, which the browser will expose to attacker JavaScript on `evilethereum.org`. [1](#0-0)

func (s *httpServer) isAllowedOrigin(origin string) bool {
	originScheme, originHost, originPort, err := s.splitURL(origin)
	if err != nil {
		s.lggr.Debug("error parsing origin URL", err)
		return false
	}
	for _, allowed := range s.config.CORSAllowedOrigins {
		// probably better to do this once when server starts and store it in a map
		// this is an easier solution so we don't have to apply more changes to the code
		// just need to be careful when specifying allowed origins in the config file
		allowedScheme, allowedHost, allowedPort, err := s.splitURL(allowed)
		if err != nil {
			s.lggr.Debug("error parsing allowed origin URL", err)
			continue
		}
		// skip if the scheme doesn't match at all
		if originScheme != allowedScheme {
			continue
		}
		// skip if the port doesn't match at all
		if originPort != allowedPort {
			continue
		}
		// check for exact host match (e.g., remix.com)
		if originHost == allowedHost {
			return true
		}
		// check for wildcard host match (e.g., *.remix.com)
		if strings.HasPrefix(allowedHost, "*.") {
			allowedHost = allowedHost[2:]
			if strings.HasSuffix(originHost, allowedHost) {
				return true
			}
		}
	}
	return false
}

func (s *httpServer) handleRequest(w http.ResponseWriter, r *http.Request) {
	if s.config.CORSEnabled {
		origin := r.Header.Get("Origin")
		if s.isAllowedOrigin(origin) {
			w.Header().Set("Access-Control-Allow-Origin", origin)
			w.Header().Set("Access-Control-Allow-Methods", "GET, POST, OPTIONS")
			w.Header().Set("Access-Control-Allow-Headers", "Content-Type")
		}

		// handle preflight requests
		if r.Method == http.MethodOptions {
			w.WriteHeader(http.StatusNoContent)
			return
