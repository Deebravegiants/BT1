Target: ShopifyAPI::Utils::SessionUtils.current_session_id / .cookie_session_id. Attacker action: unprivileged internet user sends a GET to a non-embedded app's callback with header 'Cookie: shopify_app_session=offline_another-shop.myshopify.com'. Preconditions: Context.embedded? == false, no shopify_id_token supplied, victim shop 'another-shop.myshopify.com' already completed OAuth and its session is stored under that exact key. Call sequence: current_session_id(nil, cookies, false) -> cookies[SessionCookie::SESSION_COOKIE_NAME] returned verbatim -> host app loads Auth::Session for that id. Binding that breaks: session_id_returned == cookies['shopify_app_session'] should require session_id_returned == HMAC_verified(cookies['shopify_app_session'], Context.api_secret_key), but no such check exists. Impact: Critical, cross-tenant access - attacker's session acts as 'another-shop' and can read/write its data, exfiltrating its access token. Proof idea: minitest calling SessionUtils.current_session_id(nil, {'shopify_app_session' => 'offline_another-shop.myshopify.com'}, false) and asserting it returns the victim's session id with no signature verification performed.
