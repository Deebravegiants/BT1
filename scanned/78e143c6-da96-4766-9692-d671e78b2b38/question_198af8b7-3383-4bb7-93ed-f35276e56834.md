Binding that breaks: SESSION DERIVATION / SHOP BINDING - the storage key is not an injective function of (shop, user_id) because '_' is unescaped and both shop and user_id are attacker-influenceable strings (shop via which store name they register, user_id is fixed by Shopify but shop name is chosen freely at signup). Impact: Critical - potential cross-tenant session id collision leading to one shop's online session overwriting or being read as another's in a SessionStorage implementation keyed by this id (the id is the only isolation boundary the gem provides). Proof idea: minitest asserting Session.from with shop='shop1.myshopify.com', associated_user.id=2 and shop='shop1.myshopify.com'... construct two Session.from calls whose (shop, associated_user.id) pairs are distinct but whose computed id strings are identical, e.g. shop='a_1.myshopify.com', user 2 vs shop='a.myshopify.com', user '1_2', and assert the resulting ids are equal.
