### Title
JWT replay-protection check-then-record race in gateway HTTP trigger authorization allows one-time JWT reuse - ([File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go])

### Summary
`WorkflowMetadataHandler.Authorize` implements JWT replay protection for the internet-facing HTTP trigger gateway by checking a cache for the JWT's `jti` claim and, only after the full auth flow succeeds, recording that `jti` as used. The check (`isReplay`) and the record (`recordUsage`) are two separate, non-atomic operations protected by different lock acquisitions, creating the same class of Time-of-check Time-of-use (TOCTOU) race described in the Spring Security `JdbcOneTimeTokenService` advisory (CVE-2026-22751): concurrent requests carrying the identical JWT can both pass the "not yet used" check before either marks it used.

### Finding Description
`Authorize` is called from `httpTriggerHandler.authorizeRequest` for every inbound `workflow.execute` trigger request received by the gateway's HTTP Trigger Handler (an internet-facing, unprivileged-caller entry point) [1](#0-0) .

Inside `Authorize`, the JWT is verified, then the `jti` claim is checked against a cache via `isReplay`, and only near the end of the function — after signer/authorization checks succeed — is `recordUsage` called to mark the `jti` consumed: [2](#0-1) 

The cache implementation uses separate lock scopes for the check and the write: [3](#0-2) 

`isReplay` takes an `RLock`, checks map membership, and releases the lock; `recordUsage` later takes a separate `Lock` to insert the entry. Between these two independent critical sections there is a window in which two goroutines processing the same JWT (same `jti`) concurrently can both see `isReplay(claims.ID) == false`, both pass the authorized-signer check, and both call `recordUsage`, with the second call simply overwriting the timestamp rather than being rejected. This is a textbook check-then-act TOCTOU: the validity check and the consumption/marking are not performed as a single atomic operation, exactly matching the root cause pattern in GHSA-x2wq-9x2f-fhj7 for `JdbcOneTimeTokenService`, where the one-time-token "is it already used" check and "mark used" update are not atomic.

### Impact Explanation
The JWT (with a unique `jti`) is meant to be single-use — this is the entire purpose of the replay-protection cache exposed by `Authorize`'s error message: "JWT token has already been used. Please generate a new one with new id (jti)" [4](#0-3) . If an attacker (or a legitimate but hostile client) captures/replays a valid JWT and fires two (or more) requests concurrently, both can pass authorization and both trigger workflow executions via `httpTriggerHandler.HandleUserTriggerRequest`, which fans the trigger out to DON nodes [5](#0-4) . This amounts to unauthorized duplicate triggering of a workflow execution using a token that should only be usable once, bypassing the request-impersonation/replay protection that operators rely on for the HTTP trigger capability. Note that request-ID based in-flight de-duplication (`setupCallback`) is a separate, distinct control keyed on `req.ID`, not on the JWT `jti` — it does not close this race for tokens tied to different `req.ID` values or for the JWT-specific replay guarantee.

### Likelihood Explanation
Exploitation requires simply sending the same JWT twice in close temporal proximity (a trivial replay of a captured token, or a legitimate caller's own retry logic firing concurrently), which is easy for any external, unprivileged caller of the HTTP trigger gateway endpoint to attempt. The race window is narrow (bounded by the time to execute the signer/authorization checks between the read-lock release and the write-lock acquisition) but is real and non-hypothetical, similar to the narrow but exploitable window in the analogous Spring Security CVE (rated Medium severity, AC:H reflecting the narrow timing requirement).

### Recommendation
Make the check-and-record operation atomic: acquire a single write lock across both the `isReplay` check and the `recordUsage` insertion (or use a single `LoadOrStore`-style primitive, e.g. `sync.Map.LoadOrStore` or an explicit mutex-protected "check-and-set" method) inside `WorkflowMetadataHandler.Authorize`, so that only one of two concurrent requests bearing the same `jti` can ever pass.

### Proof of Concept
1. Client obtains/derives a valid signed JWT for a `workflow.execute` HTTP trigger request with a fixed `jti`.
2. Client sends this identical JWT concurrently as two separate HTTP trigger requests (e.g., two goroutines/threads hitting the gateway endpoint at nearly the same time) as exercised conceptually by `TestWorkflowMetadataHandler_Authorize`'s "JWT replay protection" subtest, but invoked in parallel rather than sequentially [6](#0-5) .
3. Both calls to `Authorize` execute `isReplay(claims.ID)` before either has called `recordUsage(claims.ID)`, so both return a valid `*AuthorizedKey` and both proceed to trigger a workflow execution, defeating the single-use guarantee.

func (h *httpTriggerHandler) HandleUserTriggerRequest(ctx context.Context, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback, requestStartTime time.Time) error {
	triggerReq, err := h.validatedTriggerRequest(ctx, req, callback)
	if err != nil {
		return err
	}

	workflowID, err := h.resolveWorkflowID(ctx, triggerReq, req.ID, callback)
	if err != nil {
		return err
	}

	key, err := h.authorizeRequest(ctx, workflowID, req, callback)
	if err != nil {
		return err
	}

	if err = h.checkRateLimit(ctx, workflowID, req.ID, callback); err != nil {
		return err
	}

	strippedWorkflowID := strings.TrimPrefix(workflowID, "0x")
	legacyExecutionID, err := workflows.EncodeExecutionID(strippedWorkflowID, req.ID) //nolint:staticcheck // legacy ID kept for observability comparison
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInternal, internalErrorMessage, callback)
		return errors.New("error generating execution ID: " + err.Error())
	}
	// Workflows shouldn't use more than one HTTP trigger. If we ever need to support multiple triggers, we'd need to pass
	// trigger index to the Gateway handler and somehow allow senders to pick. For now, we use trigger index 0.
	// Execution IDs here are used only for logging.
	executionIDWithTriggerIndex, err := workflows.GenerateExecutionIDWithTriggerIndex(strippedWorkflowID, req.ID, 0)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInternal, internalErrorMessage, callback)
		return errors.New("error generating execution ID with trigger index: " + err.Error())
	}
	h.lggr.Debugw("processing request",
		"legacyExecutionID", legacyExecutionID,
		"executionIDWithTriggerIndex", executionIDWithTriggerIndex,
		"requestID", req.ID,
		"workflowID", workflowID)

	reqWithKey, err := reqWithAuthorizedKey(triggerReq, *key)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInternal, internalErrorMessage, callback)
		return errors.New("error marshaling trigger request: " + err.Error())
	}

	doneCh, err := h.setupCallback(ctx, req.ID, callback, requestStartTime, workflowID)
	if err != nil {
		return err
	}

	return h.sendWithRetries(ctx, legacyExecutionID, executionIDWithTriggerIndex, reqWithKey, workflowID, doneCh)

func (h *httpTriggerHandler) authorizeRequest(ctx context.Context, workflowID string, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback) (*gateway_common.AuthorizedKey, error) {
	h.lggr.Debugw("authorizing request", "workflowID", workflowID, "requestID", req.ID)
	key, err := h.workflowMetadataHandler.Authorize(workflowID, req.Auth, req)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInvalidRequest, "Auth failure: "+err.Error(), callback)
		return nil, errors.Join(errors.New("auth failure"), err)
	}
	return key, nil
}

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil

func (cache *jwtReplayCache) isReplay(jti string) bool {
	cache.mu.RLock()
	defer cache.mu.RUnlock()

	_, exists := cache.cache[jti]
	return exists
}

func (cache *jwtReplayCache) recordUsage(jti string) {
	cache.mu.Lock()
	defer cache.mu.Unlock()

	cache.cache[jti] = time.Now()
}
