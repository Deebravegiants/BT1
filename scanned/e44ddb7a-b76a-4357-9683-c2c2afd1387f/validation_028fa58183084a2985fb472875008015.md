### Title
Timing-unsafe string comparison of Prometheus Authorization bearer token enables password recovery - (File: core/web/router.go)

### Summary
The chainlink node's HTTP router protects its `/metrics` (Prometheus) endpoint with a static bearer token comparison that uses Go's plain `!=` string operator instead of a constant-time comparison. This mirrors the exact bug class in the external report (V8 `String::SlowEquals` timing leak): both Go's runtime string comparison and V8's are optimized to short-circuit / return as soon as a length or byte mismatch is found, creating a measurable timing side channel that an unauthenticated network client can exploit to recover the secret token character-by-character.

### Finding Description
`prometheusHandler` builds the expected value as `"Bearer " + token` and compares it against the client-supplied `Authorization` header using `header != bearer`: [1](#0-0) 

This handler is registered directly on the gin engine to serve the metrics path with no additional authentication layer: [2](#0-1) 

Go's built-in string equality (used by `!=`) compiles down to a length check followed by a `memcmp`/`bytealg.Compare` style comparison that returns as soon as the first mismatching byte is found — functionally identical to the V8 `String::SlowEquals` / `StringComparator::Equals` behavior described in the external report. Because this comparison is used to authenticate an unprivileged, unauthenticated HTTP request (any client that can reach the metrics endpoint, no session or API key required), an attacker can:
1. Probe different token lengths and observe response-time differences to discover the token length.
2. Brute-force one character at a time, observing that the correct-prefix guesses take measurably longer to reject than incorrect ones, exactly as demonstrated in the external PoC against `passphrase === CONFIG.passphrase`.

This is architecturally the same bug class as the reported `authenticate.ts` vulnerability: a secret compared with a non-constant-time equality operator, reachable by an unauthenticated remote party, whose runtime is used to leak the secret's characters.

This directly contrasts with the rest of the codebase's authentication paths, which correctly use `subtle.ConstantTimeCompare` for password/secret verification, e.g.: [3](#0-2) [4](#0-3) [5](#0-4) 

The `prometheusHandler` in `core/web/router.go` is the one path that deviates from this pattern and uses a raw, timing-unsafe `!=` comparison for a secret token.

### Impact Explanation
If exploited, an attacker who recovers the Prometheus auth token gains unauthorized access to the node's `/metrics` endpoint. Prometheus metrics on a Chainlink node can expose operational/internal information (job counts, error rates, internal service health, potentially indirectly informative of node identity/activity) that is intended to be gated behind the configured `Prometheus.AuthToken`. While metrics exposure is generally lower severity than full credential/key disclosure, it is still an authentication bypass of a configured access control, and depending on deployment (metrics scraped over a network boundary rather than localhost) could leak information useful for further reconnaissance or highlight when jobs run, aiding a more targeted attack.

### Likelihood Explanation
Exploitability requires precise timing measurement, which is easier when the attacker is network-adjacent (colocated cloud instance, same LAN, or low-jitter path) — same precondition noted in the original report. The token comparison happens on every unauthenticated GET to the metrics path, giving the attacker unlimited retries with no rate limiting visible in the handler itself, similar to the original vulnerable code. This makes the attack practically feasible for an attacker with network proximity to the node, though it is harder to execute over a high-latency/jittery internet path than the original localhost PoC assumed.

### Recommendation
Replace the raw `!=` string comparison in `prometheusHandler` with a constant-time comparison, consistent with the rest of the codebase's authentication pattern. For example, use `crypto/subtle.ConstantTimeCompare` on the byte slices of `header` and `bearer` (padding/normalizing lengths as done in `constantTimeEmailCompare` elsewhere in the code, or using `hmac.Equal` on a fixed-size hash of both values), instead of Go's native string equality operator.

### Proof of Concept
Analogous to the report's C-based PoC against `authenticate.ts`, an attacker can:
1. Send repeated `GET /metrics` requests with `Authorization: Bearer <guess>` for successive prefix guesses of increasing length/content.
2. Measure server response latency to the `header != bearer` check in `prometheusHandler` for each guess.
3. Because Go's string comparison short-circuits at the first non-matching byte, correct-prefix guesses will exhibit measurably longer processing time than incorrect ones, allowing the attacker to recover the `Prometheus.AuthToken` byte-by-byte, mirroring the "staircase" timing pattern demonstrated in the original report.

Note: I was not able to fully verify how metrics-path network exposure is configured by default (e.g., whether it's typically bound to localhost only in production deployments), since that depends on deployment-specific bind/listener configuration not fully visible in the indexed code. This affects the practical network reachability of the analog but not the underlying code-level timing-unsafe comparison bug itself.

func prometheusUse(p *ginprom.Prometheus, e *gin.Engine, handlerOpts promhttp.HandlerOpts) {
	var (
		r prometheus.Registerer = p.Registry
		g prometheus.Gatherer   = p.Registry
	)
	if p.Registry == nil {
		r = prometheus.DefaultRegisterer
		g = prometheus.DefaultGatherer
	}
	h := promhttp.InstrumentMetricHandler(r, promhttp.HandlerFor(g, handlerOpts))
	e.GET(p.MetricsPath, prometheusHandler(p.Token, h))
	p.Engine = e
}

// AuthenticateUserByToken returns true on successful authentication of the
// user against the given Authentication Token.
func AuthenticateUserByToken(token *auth.Token, user *User) (bool, error) {
	hashedSecret, err := auth.HashedSecret(token, user.TokenSalt.ValueOrZero())
	if err != nil {
		return false, err
	}
	return subtle.ConstantTimeCompare([]byte(hashedSecret), []byte(user.TokenHashedSecret.ValueOrZero())) == 1, nil
}
