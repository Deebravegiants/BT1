### Title
CORS wildcard-origin allowlist bypass via unanchored suffix match in Gateway's `isAllowedOrigin()` — ([File: core/services/gateway/network/httpserver.go])

### Summary
The Chainlink Gateway's user-facing HTTP server implements its own CORS origin-allowlist check in `isAllowedOrigin()`. For wildcard entries (e.g. `https://*.ethereum.org`), it strips the `*.` prefix and then checks `strings.HasSuffix(originHost, allowedHost)` with no separator/boundary check. This allows an attacker-registered domain that merely *ends with* the allowed suffix (without being an actual subdomain, i.e. without a preceding `.`) to be treated as a trusted origin — the same class of bug as the sanic-cors advisory (CWE-346, improper origin validation via unanchored string/regex matching).

### Finding Description
`isAllowedOrigin` parses the scheme/host/port of both the incoming `Origin` header and each configured allowed origin, then for wildcard-configured hosts does: [1](#0-0) 

```go
// check for wildcard host match (e.g., *.remix.com)
if strings.HasPrefix(allowedHost, "*.") {
    allowedHost = allowedHost[2:]
    if strings.HasSuffix(originHost, allowedHost) {
        return true
    }
}
```

`strings.HasSuffix` treats `allowedHost` purely as a trailing character sequence, not as a dot-delimited subdomain suffix. If the operator configures `CORSAllowedOrigins = ["https://*.ethereum.org"]` intending to trust only actual subdomains of `ethereum.org`, an attacker who registers `evilethereum.org` (or any domain ending in the literal string `ethereum.org` without a preceding dot) will have `HasSuffix("evilethereum.org", "ethereum.org") == true`, causing the request's `Origin` to be echoed back in `Access-Control-Allow-Origin` and CORS to be granted: [2](#0-1) 

```go
func (s *httpServer) handleRequest(w http.ResponseWriter, r *http.Request) {
	if s.config.CORSEnabled {
		origin := r.Header.Get("Origin")
		if s.isAllowedOrigin(origin) {
			w.Header().Set("Access-Control-Allow-Origin", origin)
			w.Header().Set("Access-Control-Allow-Methods", "GET, POST, OPTIONS")
			w.Header().Set("Access-Control-Allow-Headers", "Content-Type")
		}
```

This CORS check protects the Gateway's `UserServerConfig` HTTP endpoint, which is the internet-facing entry point for unprivileged clients submitting requests (e.g. via the sample config's `[UserServerConfig]` with `CORSEnabled`/`CORSAllowedOrigins`), analogous to sanic-cors's `try_match()` allowing an attacker domain beginning with a trusted origin string to bypass the allowlist — here the failure mode is a suffix rather than prefix, but the root cause (string containment check without boundary/anchoring) is identical. [3](#0-2) 

### Impact Explanation
If an operator configures a wildcard `CORSAllowedOrigins` entry (a documented, supported pattern per the tests in `httpserver_test.go`), an attacker can register a look-alike domain (e.g. `evil-ethereum.org`'s suffix trick isn't quite right, but `xethereum.org`/`notethereum.org` style domains ending exactly in the configured suffix without a dot boundary work) and host a malicious webpage there. Browsers visiting that page, if a user has an authenticated session/cookie for the Gateway UI/API, would have their cross-origin requests permitted by `Access-Control-Allow-Origin` + credentialed CORS, enabling unauthorized cross-origin access to Gateway API responses that should be restricted to genuine subdomains of the trusted domain.

### Likelihood Explanation
Exploitability depends on an operator using the wildcard-origin feature (`*.domain.com`) instead of exact-origin lists, and on an attacker being able to register a domain with the matching literal suffix — feasible for many real top-level/second-level domain combinations. The wildcard suffix path is explicitly exercised and intended to be supported functionality (see `TestHTTPServer_HandleRequest_CORSEnabled_FromAllowedOriginWildcards`), so it is a reachable, real-world misconfiguration risk rather than a purely theoretical one. [4](#0-3) 

### Recommendation
Fix the wildcard matching to require a proper subdomain boundary, e.g. check `originHost == allowedHost || strings.HasSuffix(originHost, "."+allowedHost)` instead of a bare `strings.HasSuffix`, mirroring the fix direction needed for sanic-cors's `try_match()` (end-anchoring / boundary-aware matching rather than raw substring/suffix comparison).

### Proof of Concept
1. Operator configures Gateway `UserServerConfig` with `CORSEnabled = true` and `CORSAllowedOrigins = ["https://*.ethereum.org"]`.
2. Attacker registers `https://malicious-siteethereum.org` (a domain string literally ending in `ethereum.org` but not a real subdomain) and hosts a page there.
3. A victim with an authenticated session against the Gateway visits the attacker's page; the page issues a `fetch` to the Gateway's `/user` path with `credentials: 'include'` and `Origin: https://malicious-siteethereum.org`.
4. `isAllowedOrigin` computes `originHost = "malicious-siteethereum.org"`, `allowedHost = "ethereum.org"` after stripping `*.`, and `strings.HasSuffix("malicious-siteethereum.org", "ethereum.org")` returns `true`, so the server sets `Access-Control-Allow-Origin: https://malicious-siteethereum.org`, allowing the attacker's page to read the authenticated response cross-origin.

func TestHTTPServer_HandleRequest_CORSEnabled_FromAllowedOriginWildcards(t *testing.T) {
	t.Parallel()
	_, handler, url := startNewServer(t, 100_000, 100_000, true,
		[]string{"https://*.ethereum.org", "https://*.valid.domain.com", "http://*.gov"})

	handler.On("ProcessRequest", mock.Anything, mock.Anything, mock.Anything).Return([]byte("response"), 200)

	origin := "https://remix.ethereum.org"
	resp, respBytes := sendRequest(t, url, []byte("0123456789"), http.MethodPost, &origin) //nolint:bodyclose // sendRequest closes the body
	require.Equal(t, http.StatusOK, resp.StatusCode)
	require.Equal(t, []byte("response"), respBytes)
	require.Equal(t, origin, resp.Header.Get("Access-Control-Allow-Origin"))
	require.Equal(t, "GET, POST, OPTIONS", resp.Header.Get("Access-Control-Allow-Methods"))
	require.Equal(t, "Content-Type", resp.Header.Get("Access-Control-Allow-Headers"))

	handler.On("ProcessRequest", mock.Anything, mock.Anything, mock.Anything).Return([]byte("response"), 200)

	origin = "https://another.valid.domain.com"
	resp, respBytes = sendRequest(t, url, []byte("0123456789"), http.MethodPost, &origin) //nolint:bodyclose // sendRequest closes the body
	require.Equal(t, http.StatusOK, resp.StatusCode)
	require.Equal(t, []byte("response"), respBytes)
	require.Equal(t, origin, resp.Header.Get("Access-Control-Allow-Origin"))
	require.Equal(t, "GET, POST, OPTIONS", resp.Header.Get("Access-Control-Allow-Methods"))
	require.Equal(t, "Content-Type", resp.Header.Get("Access-Control-Allow-Headers"))
