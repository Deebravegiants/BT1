# Q0730: tower_epoch_credits_iter breaks lamport conservation (points.rs)

## Question
Can an unprivileged attacker entering through a transaction that lands in a block and is replayed by every node on the cluster reach `tower_epoch_credits_iter` in `runtime/src/inflation_rewards/points.rs` with amounts split across many transactions so per-step rounding accumulates, and make the lamports `tower_epoch_credits_iter` removes differ from the lamports it credits, so that the invariant "Sum of lamports before and after the operation is equal, except for the explicit fee/rent burn." breaks and the result is Loss of Funds?

## Target
- File/function: `runtime/src/inflation_rewards/points.rs` -> `tower_epoch_credits_iter()` (around line 187)
- Entrypoint: a transaction that lands in a block and is replayed by every node on the cluster
- Attacker controls: amounts split across many transactions so per-step rounding accumulates
- Exploit idea: Drive `tower_epoch_credits_iter` so the lamports it removes and the lamports it adds differ, minting or destroying value outside the inflation schedule.
- Invariant to test: Sum of lamports before and after the operation is equal, except for the explicit fee/rent burn.
- Expected Immunefi impact: Loss of Funds - theft or creation of lamports/tokens without the owner's signature (6,250-25,000 SOL)
- Fast validation: Property test around `tower_epoch_credits_iter`: assert `sum_lamports_before == sum_lamports_after + burned` over randomized inputs.
