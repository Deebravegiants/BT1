### Title
Unauthenticated unbounded JSON body decode in `PipelineRunsController.Resume` enables memory-exhaustion DoS — ([File: core/web/pipeline_runs_controller.go])

### Summary
The `PATCH /v2/jobs/:ID/runs/:runID` resume endpoint decodes the full HTTP request body via `json.NewDecoder(c.Request.Body).Decode(&rr)` with no `http.MaxBytesReader` wrap, no `Content-Length` check, and no gin body-size middleware anywhere in `core/web`. Unlike Mailpit's `send.go`, chainlink's own gateway HTTP server (`core/services/gateway/network/httpserver.go:211-224`) already centralizes a `MaxBytesReader`/`MaxRequestBytesLimiter` wrap for *every* incoming request before handing off to any handler — the "cleaner fix" the Mailpit advisory itself recommends. That protection was never extended to the legacy `core/web` gin API, and `Resume` is reachable without authentication.

### Finding Description
`core/web/pipeline_runs_controller.go:134-147`:
```go
func (prc *PipelineRunsController) Resume(c *gin.Context) {
    taskID, err := uuid.Parse(c.Param("runID"))
    ...
    rr := pipeline.ResumeRequest{}
    decoder := json.NewDecoder(c.Request.Body)
    err = errors.Wrap(decoder.Decode(&rr), "failed to unmarshal JSON body")
``` [1](#0-0) 

`pipeline.ResumeRequest` contains a `json.RawMessage Value` field, so the decoder buffers the entire attacker-controlled body (any size) into memory as raw bytes before any validation occurs: [2](#0-1) 

The success path logs `audit.UnauthedRunResumed`, confirming this endpoint is intentionally exempt from user/API-key authentication — it is meant to be callable by external task-resumption callers (e.g. bridge adapters) without a session: [3](#0-2) 

Grepping the entire `core/web` package for `MaxBytesReader`, `ContentLength`, or `LimitReader` middleware returns zero results, confirming there is no global body-size cap protecting gin-based controllers the way the gateway's `handleRequest` protects gateway JSON-RPC traffic: [4](#0-3) 

This is the exact bug class in the report: a sibling endpoint sharing the same unauthenticated reachability as a "hardened" one (the gateway) but never receiving the equivalent fix.

### Impact Explanation
An unauthenticated remote client can PATCH an arbitrarily large JSON body (e.g., a multi-hundred-MB `value` field) to `/v2/jobs/{ID}/runs/{runID}` for any syntactically valid UUID `runID`. `json.NewDecoder` will read and buffer the full body into a `json.RawMessage` before validation/lookup fails, driving per-request RSS growth proportional to attacker-supplied body size. Repeated/concurrent requests compound memory pressure on the node process, risking OOM-triggered restarts — a CWE-770 uncontrolled resource consumption DoS with availability impact, matching the Mailpit CVSS vector (`AV:N/AC:L/PR:N/UI:N/A:L`).

### Likelihood Explanation
High. The endpoint requires no credentials (confirmed by the `UnauthedRunResumed` audit label and absence of an auth middleware check in the handler), and `taskID` only needs to parse as a UUID — it does not need to correspond to a real pending task run for the body to be fully read into memory first. The attack requires only network reachability to the node's `/v2` API surface, no bridge/EI secrets needed.

### Recommendation
Wrap `c.Request.Body` with `http.MaxBytesReader(c.Writer, c.Request.Body, <configurable limit>)` before constructing the JSON decoder in `Resume`, matching the pattern already used centrally in `core/services/gateway/network/httpserver.go:218`. Better, add this as gin middleware applied to the whole `core/web` router (or at least to all JSON-body-accepting, non-multipart routes) so future handlers inherit the cap by default, rather than patching call sites individually.

### Proof of Concept
```bash
# Against a running chainlink node with default (no-auth) resume path exposed
RUNID=$(uuidgen)
python3 - <<PY
import requests
big_value = '"' + ('A' * 200_000_000) + '"'
body = '{"value": %s}' % big_value
r = requests.patch("http://<node>:6688/v2/jobs/1/runs/$RUNID",
                    data=body,
                    headers={"Content-Type": "application/json"})
print(r.status_code)
PY
# Observe node RSS growth proportional to body size, with no server-side cap.
```
