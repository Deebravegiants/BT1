### Title
Sensitive External Initiator credentials (`AccessKey`, `OutgoingToken`) exposed to low-privileged authenticated users via unrestricted `GET /v2/external_initiators` - ([File: core/web/external_initiators_controller.go])

### Summary
The `ExternalInitiatorsController.Index` handler returns `AccessKey` and `OutgoingToken` for every configured External Initiator to any authenticated caller, without any `RequiresEditRole`/`RequiresAdminRole` gate, unlike nearly every other index/list endpoint in the same router (keys, jobs, etc., which gate mutating actions but still expose secrets on read in this specific case).

### Finding Description
`ExternalInitiatorsController.Index` builds `presenters.ExternalInitiatorResource` for every stored `bridges.ExternalInitiator` and serializes it directly: [1](#0-0) 

The presenter struct includes the `AccessKey` and `OutgoingToken` fields in the JSON payload: [2](#0-1) 

These are credential materials used to authenticate External Initiator requests (`AccessKey`/`Secret` pair) and to authenticate outgoing webhook callbacks (`OutgoingToken`/`OutgoingSecret` pair), as defined on the underlying model: [3](#0-2) 

In `core/web/router.go`, the route for this Index handler is registered without any `auth.RequiresEditRole`/`auth.RequiresAdminRole` wrapper — in contrast to sibling routes in the same file (`keys/*`, `jobs`, `chains`) that explicitly gate mutating operations with role checks while list/read routes are left open only to basic session/token authentication: [4](#0-3) [5](#0-4) 

This mirrors the CWE-212 pattern in the Strapi advisory: an authenticated but lower-privileged actor (any authenticated node-operator user, regardless of role) can retrieve secret/token material belonging to a resource they should not be able to fully read, via a standard listing endpoint that fails to redact sensitive fields before returning the JSON response.

### Impact Explanation
Disclosure of `AccessKey` and `OutgoingToken` for all configured External Initiators to any authenticated user (even a low-privileged "view" role, if such a role can reach this route) undermines the confidentiality guarantees of the External Initiator authentication scheme and could facilitate impersonation of outgoing webhook calls if `OutgoingToken` alone (or combined with other leaked material) is accepted downstream.

### Likelihood Explanation
Any user who can authenticate to the Chainlink node's admin API (session or API token) and reach `/v2/external_initiators` can trigger this without further privilege — the confirmed test coverage shows the Index endpoint returning `AccessKey` and `OutgoingToken` in its response for regular authenticated calls, with no explicit role check visible in the route registration I found: [6](#0-5) 

I was not able to fully verify within the available context whether an intermediate middleware group applies a role restriction to this specific route before it's registered (the surrounding router.go groupings for other resources were reviewed but the exact wrapping group for `external_initiators` route registration line was not captured in full) — this should be confirmed directly in `core/web/router.go` around the `EICreate`/`external_initiators` handler set.

### Recommendation
Restrict `GET /v2/external_initiators` to admin or edit-role users only, and/or strip `AccessKey`/`OutgoingToken` from the list/index presenter (`ExternalInitiatorResource`), returning only non-sensitive identifying fields (name, URL, timestamps) on list, consistent with how `Secret`/`OutgoingSecret` are already withheld from the index resource (only returned once, at creation time, via `ExternalInitiatorAuthentication`).

### Proof of Concept
1. Authenticate as any valid Chainlink node operator user (any role that can reach `/v2/external_initiators`).
2. `GET /v2/external_initiators`
3. Observe the JSON response includes `accessKey` and `outgoingToken` for every configured External Initiator, as shown by the test assertions: [7](#0-6)

func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}

func NewExternalInitiatorResource(ei bridges.ExternalInitiator) ExternalInitiatorResource {
	return ExternalInitiatorResource{
		JAID:          NewJAID(strconv.FormatInt(ei.ID, 10)),
		Name:          ei.Name,
		URL:           ei.URL,
		AccessKey:     ei.AccessKey,
		OutgoingToken: ei.OutgoingToken,
		CreatedAt:     ei.CreatedAt,
		UpdatedAt:     ei.UpdatedAt,
	}
}
