### Title
Unauthenticated exposure of LOOPP plugin Prometheus metrics and pprof profiling data via `/discovery` and `/plugins/:name/*` routes - ([File: core/web/router.go])

### Summary
`loopRoutes` registers `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` directly on the top-level `api` router group, which only has rate-limiting and cookie-session middleware applied — no authentication requirement. This is analogous to the Fluentd Monitor Agent advisory: an internal diagnostics/metrics API is reachable by any network client without credentials and can leak internal plugin state.

### Finding Description
In `core/web/router.go`, `NewRouter` builds the `api` group with only rate limiting and session middleware, then calls: [1](#0-0) 

`loopRoutes` is registered here with **no** `auth.Authenticate(...)` middleware: [2](#0-1) 

Contrast this with `metricRoutes`, which serves the equivalent pprof endpoints for the core node itself, and is deliberately placed *inside* the authenticated `authv2` group: [3](#0-2) 

The handlers themselves proxy requests to internal LOOPP (Local Out Of Process Plugin) processes and return their raw responses to the caller: [4](#0-3) [5](#0-4) 

Because these routes are unauthenticated, any client with network access to the Chainlink node's HTTP port can:
1. Enumerate loaded LOOPP plugins and their Prometheus scrape targets via `/discovery`.
2. Pull each plugin's `/metrics` Prometheus output (labels, internal counters, potentially job/contract identifiers).
3. Pull each plugin's `/debug/pprof/*` output (goroutine dumps, heap profiles, full stack traces including argument values) via `/plugins/:name/debug/pprof/*profile`, and trigger CPU/execution `profile`/`trace` captures.

pprof heap/goroutine dumps and Prometheus metric labels can contain sensitive runtime data (memory contents, internal identifiers, configuration values) depending on what the specific LOOPP plugin exposes — directly mirroring the Fluentd advisory's concern that a monitor/metrics API can leak plugin-internal state to unauthenticated callers.

### Impact Explanation
An unauthenticated network attacker reaching the node's web server port can extract internal plugin metrics and full pprof debug dumps (heap, goroutine stacks, CPU profiles) for any registered LOOPP plugin, without any credentials. Depending on which plugins are loaded, this could disclose internal identifiers, configuration state, or memory contents that should only be visible to authenticated node operators — the same class of unintended internal-state disclosure the Fluentd Monitor Agent advisory describes. This is a real deviation from the codebase's own established pattern (the core-process pprof/`expvar` routes are explicitly gated behind session authentication in `debugRoutes` and `metricRoutes`), suggesting the missing auth on `loopRoutes` is an oversight rather than intended design.

### Likelihood Explanation
High for any deployment where the node's HTTP API port is reachable from an untrusted network — no credentials, tokens, or session cookies are required; a single unauthenticated GET request to `/discovery` or `/plugins/<name>/metrics` or `/plugins/<name>/debug/pprof/heap` is sufficient.

### Recommendation
Move `loopRoutes(app, api)` registration into the authenticated group (or wrap it with `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)`), consistent with how `metricRoutes` is scoped inside `authv2`. At minimum, `/plugins/:name/debug/pprof/*` and `/plugins/:name/metrics` should require the same authentication as other node debug endpoints.

### Proof of Concept
Against a running node with a LOOPP plugin registered (e.g., a Solana/Median relayer plugin), without any session cookie or API token:
```
GET /discovery HTTP/1.1
Host: node:6688
```
returns the list of plugin scrape targets, then:
```
GET /plugins/<plugin-name>/metrics HTTP/1.1
Host: node:6688
```
and
```
GET /plugins/<plugin-name>/debug/pprof/heap?debug=1 HTTP/1.1
Host: node:6688
```
both return `200 OK` with the plugin's raw metrics/pprof payload, with no `Authorization` header or session cookie presented, as confirmed by the absence of any `auth.Authenticate` middleware around `loopRoutes` in `core/web/router.go` line 91.

func loopRoutes(app chainlink.Application, r *gin.RouterGroup) {
	loopRegistry := NewLoopRegistryServer(app)
	r.GET("/discovery", ginHandlerFromHTTP(loopRegistry.discoveryHandler))
	r.GET("/plugins/:name/metrics", loopRegistry.pluginMetricHandler)
	r.GET("/plugins/:name/debug/pprof/*profile", loopRegistry.pluginPPROFHandler)
	r.POST("/plugins/:name/debug/pprof/symbol", loopRegistry.pluginPPROFPOSTSymbolHandler)
}

func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/metrics", l.loopHostName, p.EnvCfg.PrometheusPort)
	req, err := http.NewRequestWithContext(gc.Request.Context(), http.MethodGet, pluginURL, nil)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)
	if err != nil {
		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q metrics", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
