## Finding

### Title
Unauthenticated `requestID` collision allows a specific user's confidential-relay request to be censored — (File: `core/services/gateway/handlers/confidentialrelay/handler.go`)

### Summary
The `MesonSwap` bug in the report stems from using a caller-supplied, non-owner-bound value (`encodedSwap`) as the sole existence key for a pending operation, so a front-runner who submits the same value first blocks the legitimate submitter. The `confidentialrelay` gateway handler in this repo has the same shape of bug: it keys in-flight requests purely by the caller-supplied `req.ID` string, with no binding to the caller's authenticated identity, and rejects any request whose ID is already registered.

### Finding Description
`HandleJSONRPCUserMessage` immediately calls `newActiveRequest`, which takes the lock, checks `h.activeRequests[req.ID] != nil`, and — if occupied — returns an error before any owner/identity-scoped authorization has bound that ID to a particular caller: [1](#0-0) 

The registration itself is keyed solely on the raw `req.ID`: [2](#0-1) 

This is confirmed by the handler's own test, which shows that submitting a second request with the identical `ID` (`"req-dup"`) fails immediately with `"request ID already exists"` regardless of who sent it: [3](#0-2) 

This is materially different from the sibling `vault` gateway handler, which explicitly defends against this exact class of bug: `GatewayVaultRequestProcessor.authorizeAndStamp` runs `AuthorizeRequest` first, and only after authorization succeeds does it **prefix the ID with the authorized owner** (`authorizedOwner + separator + originalRequestID`) before it is used as the dedup/bookkeeping key: [4](#0-3) 

The vault handler's own `newActiveRequest` collision check therefore only fires within the same authorized owner's ID-namespace, not across arbitrary callers: [5](#0-4) 

The `confidentialrelay` handler has no equivalent owner-prefixing step — `req.ID` is used verbatim as the map key, with authorization/authentication (if any) happening only downstream at the node level, not at the gateway's dedup gate.

### Impact Explanation
Any unprivileged network caller able to predict or capture a target's `requestID` (e.g., IDs are often client-supplied and may be logged, echoed, or otherwise observable/guessable, similar to a mempool-visible `encodedSwap`) can submit a request with that same ID first. The legitimate caller's subsequent, correctly-authorized request is then rejected outright with `"in-flight request ID: %s"` / `"request ID already exists"`, denying that specific workflow execution or capability call from ever being processed by this DON — a targeted denial-of-service/censorship condition on the gateway's user-facing entry point, without needing to compromise any node or bypass cryptographic authentication.

### Likelihood Explanation
Likelihood is moderate: it requires an attacker to know (or successfully guess) a specific `requestID` in advance of the legitimate submission and to win the race to submit it to the gateway. Because the ID space and predictability depend on caller-side ID generation (not enforced to be a high-entropy, unguessable value at this layer, and not bound to the caller identity at all), the difficulty is comparable to the "Low" difficulty rated in the source report.

### Recommendation
Mirror the mitigation already implemented for the vault handler: perform authorization/authentication first, then scope the in-flight-request dedup key to the authenticated caller/owner (e.g., prefix `req.ID` with the authorized identity before inserting into `activeRequests`), so that a different, unauthenticated or differently-authorized caller cannot collide with and block another caller's request ID.

### Proof of Concept
1. Attacker observes/guesses a target's upcoming confidential-relay `requestID` value `X` for method `MethodCapabilityExec`/`MethodSecretsGet`.
2. Attacker sends `jsonrpc.Request{ID: X, ...}` to the gateway before the legitimate caller's request arrives.
3. `HandleJSONRPCUserMessage` → `newActiveRequest` succeeds for the attacker and stores `X` in `h.activeRequests`.
4. Legitimate caller's request with `ID: X` arrives; `newActiveRequest` finds `h.activeRequests[X] != nil` and returns `"request ID already exists: X"`, per [6](#0-5) , so the legitimate request is never fanned out to the DON — reproduced directly by `TestConfidentialRelayHandler_DuplicateRequestID` [3](#0-2) .

**Uncertainty:** I was not able to fully trace, within the tool-call budget, whether some upstream transport-level step (e.g., WebSocket connection authentication in `core/services/gateway/network` or per-connection allowlisting in `connectionmanager.go`) restricts which callers can reach `HandleJSONRPCUserMessage` at all, which would affect who counts as an "unprivileged" attacker able to race a specific `requestID`. This should be verified before treating the finding as fully exploitable from a fully-unauthenticated network position; it is unambiguous, however, that the dedup key itself is not owner-scoped, unlike the vault handler's explicit fix for the same problem class.

func (h *handler) HandleJSONRPCUserMessage(ctx context.Context, req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) error {
	if req.ID == "" {
		return errors.New("request ID cannot be empty")
	}
	if len(req.ID) > 200 {
		return errors.New("request ID is too long: " + strconv.Itoa(len(req.ID)) + ". max is 200 characters")
	}

	labels := h.extractRequestLabels(req)
	l := h.requestLogger(req, labels)
	l.Debugw("handling confidential relay request", "nodes", len(h.donConfig.Members), "f", h.donConfig.F)

	ar, err := h.newActiveRequest(req, labels, callback)
	if err != nil {
		return err
	}

	return h.fanOutToNodes(ctx, l, ar)
}

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], labels requestLabels, callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID, "executionID", labels.ExecutionID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		labels:    labels,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

func TestConfidentialRelayHandler_DuplicateRequestID(t *testing.T) {
	t.Parallel()
	h, cb, don, _ := setupHandler(t, 4)
	don.On("SendToNode", mock.Anything, mock.Anything, mock.Anything).Return(nil)

	params := json.RawMessage(`{"workflow_id":"wf1"}`)
	req := jsonrpc.Request[json.RawMessage]{
		ID:     "req-dup",
		Method: MethodCapabilityExec,
		Params: &params,
	}

	err := h.HandleJSONRPCUserMessage(t.Context(), req, cb)
	require.NoError(t, err)

	cb2 := common.NewCallback()
	err = h.HandleJSONRPCUserMessage(t.Context(), req, cb2)
	require.ErrorContains(t, err, "request ID already exists")
}

func (p *GatewayVaultRequestProcessor) authorizeAndStamp(
	ctx context.Context,
	req *jsonrpc.Request[json.RawMessage],
	stamp func(prefixedRequestID string) error,
) (*AuthorizedGatewayVaultRequest, error) {
	incomingOwner := ""
	if idx := strings.Index(req.ID, vaulttypes.RequestIDSeparator); idx != -1 {
		incomingOwner = req.ID[:idx]
	}

	p.lggr.Debugw("authorizing gateway vault request", "method", req.Method, "requestID", req.ID)
	authResult, err := p.authorizer.AuthorizeRequest(ctx, *req)
	if err != nil {
		authErr := fmt.Errorf("request not authorized: %w", err)
		p.lggr.Errorw("gateway vault request authorization failed", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "", "incomingOwner", incomingOwner, "error", authErr)
		return nil, authErr
	}

	originalRequestID := req.ID
	authorizedOwner := authResult.AuthorizedOwner()
	prefixedRequestID := authorizedOwner + vaulttypes.RequestIDSeparator + originalRequestID
	req.ID = prefixedRequestID

	if err := stamp(prefixedRequestID); err != nil {
		p.lggr.Errorw("failed to stamp authorized request params", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, fmt.Errorf("failed to stamp authorized request params: %w", err)
	}

	p.lggr.Debugw("authorized gateway vault request", "method", req.Method, "requestID", req.ID, "owner", authorizedOwner, "orgID", authResult.OrgID(), "workflowOwner", authResult.WorkflowOwner())
	return &AuthorizedGatewayVaultRequest{
		Req:        *req,
		AuthResult: authResult,
	}, nil
}
