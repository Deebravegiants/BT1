Target: ShopifyAPI::Auth::Oauth::AuthQuery#to_signable_string vs a would-be attacker who controls only 'state' to attempt session/CSRF-token forgery. Attacker action: start their own OAuth flow (own dev shop) to obtain a validly signed callback with an attacker-chosen 'state' equal to a value they predict or previously observed as a victim's SessionCookie value (SessionCookie.value = SecureRandom.alphanumeric(NONCE_LENGTH), 15 chars). Preconditions: NONCE_LENGTH = 15 alphanumeric chars provides a large but finite space; attacker cannot brute force this within scope (excluded as this is a strength, not a bug) but the question targets whether 'state' is bound to shop. Call sequence: Oauth.validate_auth_callback checks `state == auth_query.state` against the cookie for the CURRENT request's shop-agnostic cookie, not scoped per-shop. Binding: the shop for which the cookie's state nonce was issued == the shop in auth_query.shop being completed. Impact: Critical if a single global session_cookie value can be replayed across different 'shop' callbacks to complete OAuth for an unintended shop (session fixation / cross-tenant), since state is compared as a bare string equality with no shop binding. Proof: minitest constructing cookies={'shopify_app_state' => 'ST'} and an AuthQuery for shop='other-shop.myshopify.com' also using state='ST' (both attacker's own valid signed values), asserting validate_auth_callback proceeds without ever checking that 'ST' was originally issued for 'other-shop.myshopify.com'.
