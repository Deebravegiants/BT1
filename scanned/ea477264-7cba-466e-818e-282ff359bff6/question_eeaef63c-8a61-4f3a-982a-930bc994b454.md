Target: `ShopifyAPI::Utils::HttpUtils.normalize_headers`. Attacker action: sends the proxy request with two headers that both fold to the same normalized key, e.g. `Content-Type: application/graphql` and `HTTP_Content_Type: application/json` (Rack-style duplicate), or `X-My_Header` vs `X-My-Header`. Preconditions: host app forwards its raw Rack env headers hash into `proxy_query`. Call sequence: `headers.to_h { |k, v| [k.downcase.sub('http_', '').gsub('_','-'), v] }` -> later-iterated key silently overwrites the earlier one in the resulting Hash -> `normalized_headers['content-type']` used to pick the `application/graphql` vs `application/json` branch. Binding that breaks: the content-type the app's own router validated == the content-type `proxy_query` branches on; hash-collapsing on ambiguous key names breaks that equality. Scoped impact: High, content-type confusion lets an attacker choose which parsing branch (raw-string GraphQL vs JSON-with-variables) runs regardless of what the app validated. Proof idea: minitest passing a headers hash with both `'Content-Type'` and `'HTTP_CONTENT_TYPE'` keys with different values and asserting which one `normalize_headers` yields.
