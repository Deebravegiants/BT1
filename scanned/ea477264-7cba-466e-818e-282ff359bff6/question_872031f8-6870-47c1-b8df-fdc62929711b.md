Target: `AuthScopes#covers?` used with an empty required-scope object. Attacker action: for their own dev shop, sets scope to the empty string `''` (or a string of only delimiters `,,,`). Preconditions: app builds `AuthScopes.new('')` as the 'required' side of a `covers?` call, `AuthScopes#store_scopes` reduces it to an empty Set via `reject(&:empty?)`. Call sequence: `store_scopes([])` -> `@compressed_scopes = Set.new` -> any `receiver.covers?(empty_auth_scopes)` evaluates `Set.new <= expanded_scopes` which is vacuously true for every receiver, including one with zero granted scopes. Binding that breaks: `covers?` should return true only when the specific required permission is actually present in `expanded_scopes`; an empty operand makes it return true unconditionally regardless of what was granted. Scoped impact: High, authorization-truth violation — a session with no granted scopes still 'covers' a vacuous requirement. Proof idea: minitest asserting `AuthScopes.new([]).covers?(AuthScopes.new(''))` (or vice versa) returns true even when the receiver's `compressed_scopes` is empty.
