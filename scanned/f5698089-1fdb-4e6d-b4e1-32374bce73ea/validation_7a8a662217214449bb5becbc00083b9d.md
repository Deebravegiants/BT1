### Title
Stale in-memory allowlist cache in `allowListBasedAuth`/`workflowRegistry` can authorize Vault requests after on-chain state changes - ([File: core/services/workflows/syncer/v2/workflow_registry.go])

### Summary
The reported bug class in the external report is a time-of-check/time-of-use (TOCTOU) issue: a resource's authoritative state (validator balance) is checked once and cached, then used later to authorize/execute an action, without re-validating against the current source-of-truth state. The closest analog reachable from an unprivileged client in this codebase is the Vault gateway's allowlist-based authorization path, which authorizes incoming JSON-RPC requests using an in-memory cache of on-chain allowlist state that is only ever appended to and pruned by local expiry — never reconciled against the authoritative on-chain state between polls.

### Finding Description
`allowListBasedAuth.AuthorizeRequest` authorizes a Vault request purely against the syncer's cached allowlist, retrieved via `workflowRegistrySyncer.GetAllowlistedRequests(ctx)`: [1](#0-0) 

The cache itself is maintained by `workflowRegistry.syncAllowlistedRequests`, which every 5 seconds fetches only *new* entries beyond `lastSeenAllowlistedRequestsCount` and merges them into the existing in-memory slice, pruning solely by comparing each entry's `ExpiryTimestamp` to the current time: [2](#0-1) 

`GetAllowlistedRequests` simply returns a copy of this locally accumulated slice without any live check against the contract: [3](#0-2) 

This mirrors the report's root cause exactly: an authorization/resource decision is based on a value captured at an earlier point in time (`_addRebalanceRequest` snapshotting `validator.balance`) and is trusted at a later point (`closeRebalanceRequest`) without re-verifying it is still accurate. Here, the "balance" analog is "is this request digest currently allowlisted," and the only invalidation path implemented is time-based expiry — there is no code path that removes or refreshes an entry if the underlying on-chain allowlist entry changes state before its `ExpiryTimestamp` (e.g., is revoked/deactivated on-chain, analogous to the validator balance decreasing). The fetch logic (`getAllowlistedRequests`) only pages through entries with index >= `lastSeenAllowlistedRequestsCount`, so it structurally cannot detect changes to already-seen entries: [4](#0-3) 

### Impact Explanation
If the on-chain contract exposes any mechanism to invalidate/replace an allowlisted request before its expiry (revocation, owner rotation, or correction of a mistakenly-published digest), every Vault DON node would continue to accept and authorize the now-invalid request until its original `ExpiryTimestamp` elapses, since the syncer never re-verifies previously-seen entries. This is a direct allowlist-bypass window analogous to the report's "balance increased — funds left behind" case: the authorization decision keeps using stale state after the authoritative state has moved on, permitting requests (`secrets.create/update/delete`, etc., gated by `AuthorizeRequest`) that should no longer be allowed.

### Likelihood Explanation
Likelihood is **Medium/Uncertain** and depends on functionality I could not fully verify in this pass: whether the `WorkflowRegistry` contract exposes an explicit revoke/replace-before-expiry operation for allowlisted requests. If such a path exists on-chain, the vulnerability is directly triggerable by any owner revoking their own allowlist entry (or by a compromised/rotated key), with the stale cache persisting the authorization on every DON node for up to the full remaining validity window. This should be confirmed against the `WorkflowRegistry` contract's allowlist mutation methods before treating this as a confirmed high-severity finding — I was not able to inspect the Solidity contract in this pass.

### Recommendation
1. Have `syncAllowlistedRequests` reconcile previously-seen entries against current on-chain state (not just prune by local expiry), or re-fetch the full active set periodically rather than only new entries beyond `lastSeenAllowlistedRequestsCount`.
2. Reduce the trust window by shortening `defaultTickIntervalForAllowlistedRequests` (currently 5s) relative to any expected revocation SLA, and/or add an explicit "removed/revoked" event type that the syncer subscribes to and immediately purges from `allowListedRequests`.
3. Consider adding a secondary liveness check (e.g., re-verify the specific digest against the contract) for authorization decisions with security-sensitive side effects (secrets create/update/delete), rather than relying solely on the cached snapshot in `allowListBasedAuth.AuthorizeRequest`.

### Proof of Concept
Not directly demonstrable without confirming a contract-level revoke/replace method for allowlisted requests; the code-level TOCTOU gap is shown structurally above: `syncAllowlistedRequests` only appends new entries and prunes by expiry [5](#0-4) , and `AuthorizeRequest` trusts this cache without re-validation [6](#0-5) .

func (r *allowListBasedAuth) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	r.lggr.Debugw("AllowListBasedAuth authorizing request", "method", req.Method, "requestID", req.ID)
	requestDigest, err := req.Digest()
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to create digest", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, err
	}
	requestDigestBytes, err := hex.DecodeString(requestDigest)
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to decode digest", "method", req.Method, "requestID", req.ID, "requestDigest", requestDigest, "error", err)
		return nil, err
	}
	requestDigestBytes32 := [32]byte(requestDigestBytes)
	if r.workflowRegistrySyncer == nil {
		r.lggr.Errorw("AllowListBasedAuth workflowRegistrySyncer is nil", "method", req.Method, "requestID", req.ID)
		return nil, errors.New("internal error: workflowRegistrySyncer is nil")
	}
	allowlistedRequest, allowedRequestsStrs, err := r.findAllowlistedItemWithRetry(ctx, req, requestDigest, requestDigestBytes32)
	if err != nil {
		return nil, err
	}
	if allowlistedRequest == nil {
		r.lggr.Debugw("AllowListBasedAuth request digest not allowlisted",
			"method", req.Method,
			"requestID", req.ID,
			"digestHexStr", requestDigest,
			"allowedRequestsStrs", allowedRequestsStrs)
		return nil, errors.New("request not allowlisted")
	}

	if time.Now().UTC().Unix() > int64(allowlistedRequest.ExpiryTimestamp) {
		authorizedRequestStr := string(allowlistedRequest.RequestDigest[:])
		r.lggr.Debugw("AllowListBasedAuth authorization expired", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", authorizedRequestStr, "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
		return nil, errors.New("request authorization expired")
	}

func (w *workflowRegistry) syncAllowlistedRequests(ctx context.Context) {
	ticker := w.getTicker(defaultTickIntervalForAllowlistedRequests)
	w.lggr.Debug("starting syncAllowlistedRequests")
	for {
		select {
		case <-ctx.Done():
			w.lggr.Debug("shutting down syncAllowlistedRequests, %s", ctx.Err())
			return
		case <-ticker:
			newAllowListedRequests, totalAllowlistedRequests, head, err := w.getAllowlistedRequests(ctx, w.contractReader)
			if err != nil {
				w.lggr.Errorw("failed to call getAllowlistedRequests", "err", err)
				continue
			}
			w.allowListedMu.Lock()
			// Prune expired requests
			activeAllowlistedRequests := []workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest{}
			expiredRequestsCount := 0
			for _, request := range w.allowListedRequests {
				if int64(request.ExpiryTimestamp) > time.Now().Unix() {
					activeAllowlistedRequests = append(activeAllowlistedRequests, request)
				} else {
					expiredRequestsCount++
				}
			}

			// Add new requests
			activeAllowlistedRequests = append(activeAllowlistedRequests, newAllowListedRequests...)
			w.allowListedRequests = activeAllowlistedRequests
			w.lastSeenAllowlistedRequestsCount = totalAllowlistedRequests
			w.lggr.Debugw("synced allowlisted requests",
				"newRequestsNum", len(newAllowListedRequests),
				"expiredRequestsNum", expiredRequestsCount,
				"activeRequestsNum", len(w.allowListedRequests),
				"lastSeenOnchainRequestsNum", w.lastSeenAllowlistedRequestsCount,
				"blockHeight", head.Height,
			)
			w.allowListedMu.Unlock()
		}
	}

func (w *workflowRegistry) GetAllowlistedRequests(_ context.Context) []workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest {

	defer w.allowListedMu.RUnlock()
	allowListedRequests := make([]workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest, len(w.allowListedRequests))
	copy(allowListedRequests, w.allowListedRequests)
	return allowListedRequests

func (w *workflowRegistry) getAllowlistedRequests(ctx context.Context, contractReader types.ContractReader) ([]workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest, *big.Int, *types.Head, error) {
	if contractReader == nil {
		return nil, nil, nil, errors.New("cannot fetch allow listed requests: nil contract reader")
	}
	contractBinding := types.BoundContract{
		Address: w.workflowRegistryAddress,
		Name:    WorkflowRegistryContractName,
	}

	// Read current total allowlisted requests
	var headAtLastRead *types.Head
	var totalAllowlistedRequestsResult *big.Int
	readIdentifier := contractBinding.ReadIdentifier(TotalAllowlistedRequestsMethodName)
	headAtLastRead, err := contractReader.GetLatestValueWithHeadData(
		ctx, readIdentifier, primitives.Unconfirmed, nil, &totalAllowlistedRequestsResult,
	)
	if err != nil {
		return []workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest{}, w.lastSeenAllowlistedRequestsCount, &types.Head{Height: "0"}, errors.New("failed to get latest value with head data. error: " + err.Error())
	}

	if w.lastSeenAllowlistedRequestsCount.Cmp(totalAllowlistedRequestsResult) == 0 {
		return []workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest{}, totalAllowlistedRequestsResult, headAtLastRead, nil
	}
