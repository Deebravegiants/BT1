## Title
Unauthenticated Nil-Pointer Dereference DoS in Gateway JSON-RPC Request Decoding - (File: core/services/gateway/api/jsonrpccodec.go)

### Summary
The MXIT CVE describes a null-pointer dereference triggered by malformed protocol data that an unauthenticated remote party can send, crashing the process. An analogous unrecovered nil-pointer dereference exists in the chainlink Gateway's internet-facing JSON-RPC decoding path: `JSONRPCCodec.DecodeJSONRequest` unconditionally dereferences the `Params` pointer of an incoming request before any nil-check or authentication takes place.

### Finding Description
`DecodeJSONRequest` unmarshals the request body directly: [1](#0-0) 

```go
func (*JSONRPCCodec) DecodeJSONRequest(request jsonrpc2.Request[json.RawMessage]) (*Message, error) {
	var msg Message
	err := json.Unmarshal(*request.Params, &msg)
	...
```

`request.Params` is typed as `*json.RawMessage` (a pointer), and it is populated only when the incoming JSON payload contains a `"params"` field. This function is invoked unconditionally, for every request that reaches the gateway's public user-facing HTTP endpoint, in `gateway.ProcessRequest`: [2](#0-1) 

```go
func (g *gateway) ProcessRequest(ctx context.Context, rawRequest []byte, auth string) (rawResponse []byte, httpStatusCode int) {
	// decode
	jsonRequest, err := jsonrpc2.DecodeRequest[json.RawMessage](rawRequest, auth)
	if err != nil {
		return newError("", api.UserMessageParseError, err.Error())
	}
	msg, err := g.codec.DecodeJSONRequest(jsonRequest)
	...
```

Note that this call happens *before* the message body's DON ID is resolved, before `msg.Validate()` runs, and before any authorization or allowlist check occurs. Contrast this with the well-guarded parallel path in `ValidatedMessageFromReq`, which explicitly checks `req.Params == nil` before dereferencing: [3](#0-2) 

and with `validatedTriggerRequest` in the v2 HTTP trigger handler, which likewise checks for nil params first: [4](#0-3) 

`DecodeJSONRequest`, however, has no such guard. If an unauthenticated client sends a syntactically valid JSON-RPC 2.0 envelope (matching `jsonrpc2.DecodeRequest`'s own validation, e.g. correct `"jsonrpc":"2.0"`, `"id"`, `"method"`) but omits the `"params"` field entirely, `request.Params` remains `nil`, and `*request.Params` dereferences a nil pointer, causing a runtime panic.

### Impact Explanation
An unrecovered panic in a goroutine handling an HTTP request will, in Go's default `net/http` server behavior, only crash that connection's goroutine (the standard library recovers panics per-request in `net/http`), but if the gateway's own HTTP handling wraps this call without an explicit `recover()`, and depending on how the framework in `httpserver.go` invokes `ProcessRequest`, this could either (a) be caught by the stdlib per-connection recovery (client-visible 500, low impact) or (b) if invoked in a spawned goroutine outside the request's own recovery scope (e.g., an async worker), crash the whole gateway process. I could not fully confirm from available context whether `ProcessRequest` runs synchronously inside the standard HTTP handler goroutine (which would only fail one request) or is dispatched to a separate goroutine without panic recovery (which would take down the entire gateway service and all in-flight DON traffic) — this needs verification in `core/services/gateway/network/httpserver.go`, which I was not able to fully inspect this session.

Regardless of blast radius, this a reachable, unauthenticated-triggerable nil dereference/crash from a single malformed request, matching the CVE's bug class (DoS via null pointer dereference from untrusted-actor-supplied data) closely.

### Likelihood Explanation
High likelihood of reachability: no authentication, no rate limiting, and no upstream validation stands between the public HTTP request body and this dereference. Any client capable of reaching the gateway's user-facing port can trigger it with a single, trivially crafted request.

### Recommendation
Add a nil-check on `request.Params` in `DecodeJSONRequest` before dereferencing it, mirroring the pattern already used in `ValidatedMessageFromReq` and `validatedTriggerRequest`:
```go
func (*JSONRPCCodec) DecodeJSONRequest(request jsonrpc2.Request[json.RawMessage]) (*Message, error) {
	if request.Params == nil {
		return nil, errors.New("missing params attribute")
	}
	var msg Message
	err := json.Unmarshal(*request.Params, &msg)
	...
```
Additionally, verify/add a top-level `recover()` around request-handling goroutines in `core/services/gateway/network/httpserver.go` so that any future unhandled parsing panic degrades to a single failed request instead of a full gateway crash.

### Proof of Concept
Send a JSON-RPC request to the gateway's public user endpoint that omits `"params"`:
```json
{"jsonrpc":"2.0","id":"1","method":"anything"}
```
Because `jsonrpc2.DecodeRequest` only validates envelope-level fields (version, id, method) and does not require `params`, this passes decoding and reaches `g.codec.DecodeJSONRequest(jsonRequest)` in `ProcessRequest`, where `*request.Params` panics with a nil-pointer dereference.

func (*JSONRPCCodec) DecodeJSONRequest(request jsonrpc2.Request[json.RawMessage]) (*Message, error) {

	err := json.Unmarshal(*request.Params, &msg)
	if err != nil {

	}
