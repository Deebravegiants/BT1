Target `EmporiumUpgradeable.handleOut`. Because `circomData.erc20TokenAddresses.length==0` when the Min circuit path is selected, `utxoSet = new UTXO[](0)` and the `for` loop producing `UTXO`s never runs, no matter how much ETH the attacker's own `ops` pulled INTO Emporium during the call. Attacker action: legitimate self-funded op that transfers attacker's own ETH into Emporium (e.g., `op.endpoint = address(this)`, i.e., a no-op receive, or any endpoint that forwards `op.value` back to Emporium). The equality that breaks: `balanceChange` computed inside `handleOut` per token (would be positive) never gets converted into a `UTXO`, so tokens Hinkal sent it/left there != tokens returned as a shielded output (`0`). Impact: Critical permanent freezing of user funds sent through this specific Emporium-Min path (funds enter Emporium, no UTXO or refund is ever produced). Proof: Foundry test depositing ETH via an EmporiumMin `ops` entry and asserting the resulting `utxoSet.length==0` while `address(Emporium).balance` increased.
