### Title
Deregistering a parathread with a pending `SlotLeasePeriodStart::Next` temporary/permanent slot assignment lets a later re-registrant seize the deferred lease - (File: polkadot/runtime/common/src/assigned_slots/mod.rs)

### Summary
`assign_temp_parachain_slot` with `SlotLeasePeriodStart::Next` only snapshots the manager into `TemporarySlots` and defers the actual `Leaser::lease_out` call to `allocate_temporary_slot_leases`, which runs later in `on_initialize`/`manage_lease_period_start`. Nothing in `paras_registrar::deregister` (an unprivileged, manager-callable extrinsic) invalidates this pending `TemporarySlots`/`PermanentSlots` entry, so if the ParaId is deregistered and later re-registered before the deferred allocation runs, the free lease materializes against a ParaId that now belongs to a different registrant.

### Finding Description
In `assign_temp_parachain_slot` (`polkadot/runtime/common/src/assigned_slots/mod.rs:317-399`), when `lease_period_start == SlotLeasePeriodStart::Next`, the `configure_slot_lease` call is skipped entirely (the `if` guard at line 363 only fires for `Current`), and the pallet simply persists a `ParachainTemporarySlot { manager, period_begin, .. }` snapshot via `TemporarySlots::<T>::insert(id, temp_slot)` at line 393. Materialization of the actual lease is deferred to `allocate_temporary_slot_leases` (lines 491-567), invoked from `on_initialize`/`manage_lease_period_start` (lines 613-627) at the start of the target lease period.

Critically, `allocate_temporary_slot_leases` never re-validates the para's current state before granting the lease: it reads `temp_slot.manager` straight out of storage (line 542, `temp_slot.manager.clone()`) and calls `Self::configure_slot_lease(*id, temp_slot.manager.clone(), lease_period_index, temp_slot.period_count)` (lines 540-546) without calling `T::Registrar::manager_of(id)` again, without checking `T::Registrar::is_parathread(id)` again, and without checking that the para even still exists in the same form it had at assignment time.

The only code path that removes a `TemporarySlots`/`PermanentSlots` entry is `unassign_parachain_slot` (lines 404-449), which is gated by `T::AssignSlotOrigin::ensure_origin` (line 405) — i.e., privileged only. There is no hook wired from `paras_registrar::deregister` (an unprivileged, manager-triggered extrinsic) into `assigned_slots` to purge a pending `TemporarySlots`/`PermanentSlots` entry when the underlying para is deregistered. As a result:

1. Privileged `AssignSlotOrigin` calls `assign_temp_parachain_slot(Next, id)` for para `id` owned by manager `M`. A `TemporarySlots` entry `{manager: M, period_begin: next_period, ...}` is stored, but no lease exists yet in `slots::Leases`.
2. The unprivileged manager (or whoever controls `id` at that time) calls `paras_registrar::deregister` for `id`. Because the para is still a parathread (the slot pallet never touched its lifecycle in the `Next` branch), the registrar's parathread-deregistration path is not blocked by any lease-awareness check inside `assigned_slots`.
3. `id` becomes available again (immediately or after the registrar's cooldown), and a different account registers a new para under the same `id`.
4. At the start of `next_period`, `manage_lease_period_start` → `allocate_temporary_slot_leases` iterates the stale `TemporarySlots` entry, and unconditionally calls `configure_slot_lease` for `id`, causing `Leaser::lease_out`/`Slots` to promote `id` to a lease-holding parachain. Since parachain-slot promotion is keyed on `ParaId`, not on the stored manager account, whichever entity now controls `id` benefits from the free slot upgrade that was intended for the original manager, even though the recorded manager field in the stale `ParachainTemporarySlot`/resulting `Leases` entry is stale.

This is a genuine "has_temporary_slot / has_permanent_slot desync from `slots::Leases`" scenario: `TemporarySlots::<T>::contains_key(id)` (`has_temporary_slot`, line 592-594) remains true and is used purely as a local bookkeeping flag, unrelated to whether the registrar's current owner of `id` is still the party the slot was meant for.

### Impact Explanation
A scarce, free parachain slot lease (normally requiring privileged `AssignSlotOrigin` sign-off, or a paid deposit through ordinary slot auctions/coretime) can end up materializing for a ParaId controlled by an unrelated party at the time of allocation, rather than the manager for whom `AssignSlotOrigin` originally intended it. This is a lease-seizure of a privileged/scarce resource by manipulation of an ordinary, unprivileged extrinsic (`deregister`/`register`), matching the scoped impact.

### Likelihood Explanation
Requires: (a) `AssignSlotOrigin` to have used `SlotLeasePeriodStart::Next` (a normal/common usage pattern, not an edge case — used whenever `Current` allocation isn't immediately available due to `MaxTemporarySlotPerLeasePeriod`), and (b) an unprivileged manager to deregister/re-register the ParaId within the window between assignment and the next lease-period boundary. Both actions are ordinary extrinsics reachable by a signed account with no elevated privilege, so this is realistically triggerable whenever governance uses the deferred (`Next`) assignment path, which the pallet explicitly supports as a fallback (see comment at lines 378-389).

### Recommendation
Before granting a deferred lease in `allocate_temporary_slot_leases`, re-validate the para's current state: confirm `T::Registrar::manager_of(id)` still equals the stored `manager`, and/or confirm `T::Registrar::is_parathread(id)` still holds and the para wasn't deregistered/re-registered in the interim (e.g., by tracking a registration generation/nonce). Additionally, hook `assigned_slots` into para deregistration (or have `paras_registrar::deregister` reject/clean up when `assigned_slots::has_temporary_slot`/`has_permanent_slot` returns true for `id`) so that pending `TemporarySlots`/`PermanentSlots` entries are purged atomically with deregistration rather than surviving as stale state.

### Proof of Concept
Integration test in `polkadot/runtime/common/src/assigned_slots/mod.rs` tests module:
1. Register para `id=1` with manager `A` via `TestRegistrar::register`.
2. Call `AssignedSlots::assign_temp_parachain_slot(RuntimeOrigin::root(), id, SlotLeasePeriodStart::Next)`; assert `TemporarySlots::<Test>::get(id)` is `Some` with `manager == A` and no lease yet exists (`Slots::already_leased(id, ...) == false`).
3. Call `TestRegistrar::deregister(RuntimeOrigin::signed(A), id)` (or the actual `paras_registrar::deregister` extrinsic) and assert it succeeds while `TemporarySlots::<Test>::contains_key(id)` is still `true`.
4. Call `TestRegistrar::register(B, id, ...)` with a different manager `B`.
5. Advance blocks to the next lease period boundary (`System::run_to_block` past `manage_lease_period_start`).
6. Assert that `Slots::already_leased(id, ...)` becomes `true` and/or `TestRegistrar::is_parachain(id) == true`, proving `id` (now owned by `B`) received the free lease intended for `A`, and that `TemporarySlots::<Test>::get(id).manager` still reads the stale value `A` — demonstrating the desync between `assigned_slots` bookkeeping, `slots::Leases`, and the registrar's actual current manager. 	fn allocate_temporary_slot_leases(lease_period_index: LeasePeriodOf<T>) -> DispatchResult {
		let mut active_temp_slots = 0u32;
		let mut pending_temp_slots = Vec::new();
		TemporarySlots::<T>::iter().for_each(|(para, slot)| {
				match slot.last_lease {
					Some(last_lease)
						if last_lease <= lease_period_index &&
							lease_period_index <
								(last_lease.saturating_add(slot.period_count)) =>
					{
						// Active slot lease
						active_temp_slots += 1;
					}
					Some(last_lease)
						// Slot w/ past lease, only consider it every other slot lease period (times period_count)
						if last_lease.saturating_add(slot.period_count.saturating_mul(2u32.into())) <= lease_period_index => {
							pending_temp_slots.push((para, slot));
					},
					None if slot.period_begin <= lease_period_index => {
						// Slot hasn't had a lease yet
						pending_temp_slots.insert(0, (para, slot));
					},
					_ => {
						// Slot not being considered for this lease period (will be for a subsequent one)
					},
				}
		});

		let mut newly_created_lease = 0u32;
		if active_temp_slots < T::MaxTemporarySlotPerLeasePeriod::get() &&
			!pending_temp_slots.is_empty()
		{
			// Sort by lease_count, favoring slots that had no or less turns first
			// (then by last_lease index, and then Para ID)
			pending_temp_slots.sort_by(|a, b| {
				a.1.lease_count
					.cmp(&b.1.lease_count)
					.then_with(|| a.1.last_lease.cmp(&b.1.last_lease))
					.then_with(|| a.0.cmp(&b.0))
			});

			let slots_to_be_upgraded = pending_temp_slots.iter().take(
				(T::MaxTemporarySlotPerLeasePeriod::get().saturating_sub(active_temp_slots))
					as usize,
			);

			for (id, temp_slot) in slots_to_be_upgraded {
				TemporarySlots::<T>::try_mutate::<_, _, Error<T>, _>(id, |s| {
					// Configure temp slot lease
					Self::configure_slot_lease(
						*id,
						temp_slot.manager.clone(),
						lease_period_index,
						temp_slot.period_count,
					)
					.map_err(|_| Error::<T>::CannotUpgrade)?;

					// Update temp slot lease info in storage
					*s = Some(ParachainTemporarySlot {
						manager: temp_slot.manager.clone(),
						period_begin: temp_slot.period_begin,
						period_count: temp_slot.period_count,
						last_lease: Some(lease_period_index),
						lease_count: temp_slot.lease_count + 1,
					});

					newly_created_lease += 1;

					Ok(())
				})?;
			}
		}

		ActiveTemporarySlotCount::<T>::set(active_temp_slots + newly_created_lease);

		Ok(())
	}

	/// Returns whether a para has been assigned a permanent slot.
	fn has_permanent_slot(id: ParaId) -> bool {
		PermanentSlots::<T>::contains_key(id)
	}

	/// Returns whether a para has been assigned temporary slot.
	fn has_temporary_slot(id: ParaId) -> bool {
		TemporarySlots::<T>::contains_key(id)
	}

	/// Returns whether a para is currently a lease holding parachain.
	fn is_parachain(id: ParaId) -> bool {
		T::Registrar::is_parachain(id)
	}

	/// Returns current lease period index.
	fn current_lease_period_index() -> LeasePeriodOf<T> {
		T::Leaser::lease_period_index(frame_system::Pallet::<T>::block_number())
			.and_then(|x| Some(x.0))
			.unwrap()
	}
