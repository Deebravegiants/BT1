## Analysis: `lockedCapitals` unbounded-loop DoS → Chainlink Vault allowlist auth analog

I found a valid analog in the Chainlink Vault DON authorization path. It matches the "unbounded array/list scanned on every request" bug class from the report, and it sits squarely in the internet-facing gateway's allowlist handling area explicitly called out as in-scope.

### Title
Unbounded, attacker-inflatable allowlist scanned on every Vault request causes per-request resource exhaustion - (File: `core/capabilities/vault/allow_list_based_auth.go`)

### Summary
`allowListBasedAuth.AuthorizeRequest`, which authorizes every incoming Vault DON JSON-RPC request (secrets create/get/list/delete) from any unprivileged client, calls `findAllowlistedItemWithRetry`, which linearly scans the *entire* in-memory allowlisted-requests slice — and additionally formats every entry into a debug string — up to 11 times per single incoming request. The underlying slice `workflowRegistry.allowListedRequests` only shrinks when entries expire; it is never bounded, so any workflow owner can grow it arbitrarily by registering many long-expiry allowlist entries on-chain, degrading authorization performance for all other unprivileged Vault clients.

### Finding Description
`AuthorizeRequest` delegates to `findAllowlistedItemWithRetry`, which for every retry attempt (up to `retryCount+1 = 11` iterations by default) does: [1](#0-0) 

Inside each attempt it fetches the full copy of the allowlist via `GetAllowlistedRequests`, builds a formatted debug string for **every single entry** unconditionally (regardless of whether debug logging is enabled), and then performs a second full linear scan via `fetchAllowlistedItem`: [2](#0-1) 

The source list, `w.allowListedRequests`, is populated by `syncAllowlistedRequests`, which only prunes entries once their `ExpiryTimestamp` has passed; it does not cap the number of *active* (non-expired) entries that can accumulate: [3](#0-2) 

`GetAllowlistedRequests` returns a full copy of this unbounded slice on every call: [4](#0-3) 

This is directly analogous to the `lockedCapitals` issue: a list that grows monotonically from user/owner-driven actions and is fully re-scanned from index 0 on every unrelated request, with per-request cost proportional to the *total accumulated* size rather than to the request itself.

### Impact Explanation
Any workflow owner (an unprivileged, permissionless role relative to the Chainlink node/gateway operator) can register many allowlisted requests with far-future expiry timestamps on the WorkflowRegistry contract. Because pruning only removes *expired* entries, the active list size is effectively attacker-controlled and unbounded. Every subsequent Vault request from *any* client — not just the attacker — pays the cost of up to 11 full linear scans plus 11 full string-formatting passes over this list inside `AuthorizeRequest`. As the list grows, this degrades Vault DON authorization latency/CPU for all tenants, and at sufficient scale can cause sustained resource exhaustion / request timeouts for the whole gateway's allowlist-based authorization path — a service-availability degradation triggered by a normal (non-privileged-key) protocol actor.

### Likelihood Explanation
Exploitability requires only the ability to register allowlisted requests as a workflow owner via the on-chain WorkflowRegistry contract (not an admin/operator key on the Chainlink node itself), then simply send/replay Vault requests to trigger repeated scans. No node compromise, no privileged credentials, and no malicious-peer assumptions are needed — this fits the "malicious normal user abusing valid product/protocol flows" and "resource exhaustion via reachable user actions" categories.

### Recommendation
- Cap the maximum number of active allowlisted entries tracked in memory (e.g., per-owner or global), rejecting/evicting beyond the cap.
- Replace the linear `fetchAllowlistedItem` scan with an O(1) map lookup keyed by `RequestDigest`, maintained incrementally as entries are added/pruned in `syncAllowlistedRequests`.
- Guard the `allowedRequestsStrs` debug-string construction behind an explicit debug-level check so it isn't unconditionally built (and doesn't scale with allowlist size) on every authorization attempt.
- Consider bounding expiry duration for allowlist entries so pruning keeps the working set small regardless of registration rate.

### Proof of Concept
1. As a workflow owner, submit N (e.g., 100k) `AllowlistRequest` transactions to the WorkflowRegistry contract, each with a far-future `ExpiryTimestamp` and unique `RequestDigest`.
2. Wait for `syncAllowlistedRequests` to sync them into `w.allowListedRequests` (bounded only by chain gas cost to the attacker, not by any node-side cap).
3. As any (unrelated) unprivileged client, send a normal Vault request (e.g., `secrets/list`) to the gateway.
4. Observe `AuthorizeRequest` → `findAllowlistedItemWithRetry` performing up to 11 iterations, each copying and linearly scanning/formatting the full N-sized slice, causing measurably increased CPU/latency proportional to N for this and all subsequent unrelated Vault requests.

```go
func (r *allowListBasedAuth) findAllowlistedItemWithRetry(ctx context.Context, req jsonrpc.Request[json.RawMessage], requestDigest string, requestDigestBytes32 [32]byte) (*workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest, []string, error) {
	for attempt := 0; attempt <= r.retryCount; attempt++ {
		allowedRequests := r.workflowRegistrySyncer.GetAllowlistedRequests(ctx)
		allowedRequestsStrs := make([]string, 0, len(allowedRequests))
		for _, rr := range allowedRequests {
			allowedReqStr := fmt.Sprintf("AuthorizedOwner: %s, RequestDigest: %s, ExpiryTimestamp: %d", rr.Owner.Hex(), hex.EncodeToString(rr.RequestDigest[:]), rr.ExpiryTimestamp)
			allowedRequestsStrs = append(allowedRequestsStrs, allowedReqStr)
		}
		r.lggr.Debugw("AllowListBasedAuth loaded allowlisted requests", "method", req.Method, "requestID", req.ID, "attempt", attempt+1, "allowedRequests", allowedRequestsStrs)

		allowlistedRequest := r.fetchAllowlistedItem(allowedRequests, requestDigestBytes32)
		if allowlistedRequest != nil {
			return allowlistedRequest, allowedRequestsStrs, nil
		}
		if attempt == r.retryCount {
			return nil, allowedRequestsStrs, nil
		}

		r.lggr.Debugw("AllowListBasedAuth request digest not yet allowlisted, retrying",
			"method", req.Method,
			"requestID", req.ID,
			"digestHexStr", requestDigest,
			"attempt", attempt+1,
			"maxAttempts", r.retryCount+1,
			"retryInterval", r.retryInterval)
		if err := sleepWithContext(ctx, r.retryInterval); err != nil {
			r.lggr.Debugw("AllowListBasedAuth retry canceled", "method", req.Method, "requestID", req.ID, "error", err)
			return nil, nil, err
		}
	}

	return nil, nil, nil // unreachable: loop always returns
}

func (r *allowListBasedAuth) fetchAllowlistedItem(allowListedRequests []workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest, digest [32]byte) *workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest {
	for _, item := range allowListedRequests {
		if item.RequestDigest == digest {
			return &item
		}
	}
	return nil
```

```go
func (w *workflowRegistry) syncAllowlistedRequests(ctx context.Context) {
	ticker := w.getTicker(defaultTickIntervalForAllowlistedRequests)
	w.lggr.Debug("starting syncAllowlistedRequests")
	for {
		select {
		case <-ctx.Done():
			w.lggr.Debug("shutting down syncAllowlistedRequests, %s", ctx.Err())
			return
		case <-ticker:
			newAllowListedRequests, totalAllowlistedRequests, head, err := w.getAllowlistedRequests(ctx, w.contractReader)
			if err != nil {
				w.lggr.Errorw("failed to call getAllowlistedRequests", "err", err)
				continue
			}
			w.allowListedMu.Lock()
			// Prune expired requests
			activeAllowlistedRequests := []workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest{}
			expiredRequestsCount := 0
			for _, request := range w.allowListedRequests {
				if int64(request.ExpiryTimestamp) > time.Now().Unix() {
					activeAllowlistedRequests = append(activeAllowlistedRequests, request)
				} else {
					expiredRequestsCount++
				}
			}

			// Add new requests
			activeAllowlistedRequests = append(activeAllowlistedRequests, newAllowListedRequests...)
			w.allowListedRequests = activeAllowlistedRequests
			w.lastSeenAllowlistedRequestsCount = totalAllowlistedRequests
			w.lggr.Debugw("synced allowlisted requests",
				"newRequestsNum", len(newAllowListedRequests),
				"expiredRequestsNum", expiredRequestsCount,
				"activeRequestsNum", len(w.allowListedRequests),
				"lastSeenOnchainRequestsNum", w.lastSeenAllowlistedRequestsCount,
				"blockHeight", head.Height,
			)
			w.allowListedMu.Unlock()
```

```go
func (w *workflowRegistry) GetAllowlistedRequests(_ context.Context) []workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest {
	w.allowListedMu.RLock()
	defer w.allowListedMu.RUnlock()
	allowListedRequests := make([]workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest, len(w.allowListedRequests))
	copy(allowListedRequests, w.allowListedRequests)
	return allowListedRequests
}
```
