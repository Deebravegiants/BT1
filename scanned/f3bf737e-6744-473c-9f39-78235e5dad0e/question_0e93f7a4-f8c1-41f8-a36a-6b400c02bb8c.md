Target: ShopifyAPI::Auth::Oauth.validate_auth_callback interplay with SessionCookie value = session.id for non-embedded apps. Attacker action: drive a non-embedded OAuth completion where auth_query.shop is an unsanitized string containing characters that are valid in an HTTP cookie value context but would have been rejected/normalized by ShopValidator.sanitize! (e.g. mixed case or a trailing slash), then, on a second real (properly sanitized, e.g. via ClientCredentials) flow for the 'same' shop in canonical form, observe that the two resulting session ids differ. Preconditions: Context.embedded? is false so cookie.value = session.id is actually issued to the browser (session_cookie.rb SESSION_COOKIE_NAME = 'shopify_app_session'). Call sequence: validate_auth_callback -> session.id = "offline_#{auth_query.shop}" (raw) -> SessionCookie.new(value: session.id, ...) -> browser stores 'shopify_app_session' = that raw id -> app's SessionRepository.retrieve(id) is later called with this exact cookie value on every request needing SessionUtils.cookie_session_id. Binding: the id embedded in the browser cookie == ShopValidator.sanitize!-derived canonical id for that tenant; broken here. Impact: Critical - a merchant's browser now carries a session-cookie value that indexes a session keyed by a non-canonical shop string; if the app's storage layer at any point also creates a canonical entry (e.g. via a webhook-driven re-provision using a properly sanitized shop), the two diverge, and an attacker who can influence which cookie value a victim's browser receives (e.g. via the open-redirect in begin_auth described separately) can pin the victim's session to an attacker-chosen non-canonical id used elsewhere for the attacker's own tenant data, achieving cross-tenant confusion. Proof idea: minitest asserting SessionCookie#value emitted by validate_auth_callback for shop 'Some-Shop.MyShopify.com/' differs from ShopifyAPI::Utils::ShopValidator.sanitize!('Some-Shop.MyShopify.com/'), i.e. the cookie the browser receives never matches the canonical tenant key.
