Target: ShopifyAPI::Webhooks::Request#shop and #topic vs #to_signable_string. Attacker action: send a POST to the app's registered webhook endpoint including a genuinely-obtained (from the attacker's own shop) hmac-sha256 header and raw body, but with the 'X-Shopify-Topic' header changed from the originally-issued topic to a more sensitive topic the attacker wants the handler to run for (e.g. changing 'orders/create' to 'app/uninstall' or 'shop/redact'), while keeping the raw body bytes identical to what was originally signed for the original topic (since bodies for different topics have different shapes, choose a body that happens to be valid JSON for both handlers, or note that Registry.process only uses request.topic to pick the handler and request.parsed_body for content - topic is never included in to_signable_string). Preconditions: Registry.process(request) is used as documented, with a handler registered for the target topic. Call sequence: HmacValidator.validate(request) checks only @raw_body against the hmac header, which is untouched and thus valid -> handler = @registry[request.topic]&.handler resolves purely off the (unsigned) topic header -> handler.handle(data: WebhookMetadata.new(topic: request.topic, shop: request.shop, body: request.parsed_body, ...)) executes the handler for the attacker-chosen topic. Binding: request.topic must be inside the bytes covered by to_signable_string (SIGNATURE COVERAGE); it is not - to_signable_string returns only @raw_body. Impact: Critical - authentication bypass in the sense that a validly-signed webhook for topic X is accepted and dispatched as topic Y, letting an attacker trigger a handler (e.g. an uninstall/redact/cross-tenant data handler) it was never actually authorized for by Shopify's signature. Proof idea: minitest constructing a Webhooks::Request with a real hmac/body pair and asserting HmacValidator.validate returns true regardless of which 'shopify-topic' header value is supplied, then asserting Registry.process dispatches to whichever handler is registered for the (unsigned) header value.
