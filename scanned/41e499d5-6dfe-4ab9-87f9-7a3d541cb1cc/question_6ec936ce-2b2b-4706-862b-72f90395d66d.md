Target: `ShopifyAPI::Utils::GraphqlProxy.proxy_query` (lib/shopify_api/utils/graphql_proxy.rb). Attacker action: attacker sends a POST to the host app's GraphQL-proxy endpoint (built per docs/usage/graphql.md) with body `{"query":"mutation{ orderClose(input:{id:\"...\"}) }"}}` while only ever having been granted `read_orders` scope at install. Preconditions: app is embedded, merchant completed OAuth with only read scopes, an online session exists and `session.online?` is true. Call sequence: `proxy_query(session:, headers:, body:)` -> checks only `Context.private?` and `session.online?` -> never calls `session.scope.covers?` -> builds `Clients::Graphql::Admin.new(session: session)` -> executes attacker's literal `query` string against the merchant's live Admin GraphQL API. Binding: 'scope granted to this session' == 'scope enforced before proxying a query' breaks because `proxy_query`'s only gate is `session.online?`. Scoped impact: Critical, cross-tenant/authorization bypass - the proxy executes attacker-chosen mutations against the merchant's store data (orders, products, customers) irrespective of the session's actual granted scope, since GraphQL-level scope enforcement is left entirely to Shopify's API and the gem performs none.
