Target: ShopifyAPI::Auth::Oauth::AuthQuery attr_reader for `code`, `host`, `shop`, `state`, `timestamp`, `hmac` - all typed `String` (non-nilable). Attacker action: submit a callback query string entirely missing one of the five parameters, e.g. no `timestamp` key at all, relying on Rack producing a hash without that key so `request.parameters.symbolize_keys.except(...)` never includes `:timestamp`. Preconditions: host app builds `AuthQuery.new(**request.parameters...)` as documented; Ruby raises `ArgumentError: missing keyword: :timestamp` rather than the gem defaulting it. Call sequence: `AuthQuery.new` keyword args are required with no defaults -> missing key raises before `to_signable_string` or `HmacValidator.validate` ever runs. Binding: this confirms the five REQUIRED fields can't be silently omitted and substituted with `nil`/empty defaults that would change what's inside `to_signable_string` versus a real callback - a defensive boundary, not a vulnerability. Impact: none (defensive finding) - included to rule this vector out as a bypass path. Proof idea: minitest asserting `AuthQuery.new(code: \"x\", host: \"h\", shop: \"s\", state: \"t\")` (timestamp omitted) raises `ArgumentError`, ruling out a null-field-substitution bypass of `to_signable_string`.
