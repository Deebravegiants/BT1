### Title
Unauthenticated LOOP Plugin `pprof` Debug Endpoints Expose Process Memory/Profiling Data on the Node's Public HTTP API - ([File: core/web/router.go], [File: core/web/loop_registry.go])

### Summary
The chainlink node's main HTTP API router registers LOOP-plugin pprof forwarding routes (`/plugins/:name/debug/pprof/*profile` and `/plugins/:name/debug/pprof/symbol`) on the top-level, unauthenticated route group, while the functionally identical pprof endpoints for the core node itself are gated behind admin session/token authentication. This mirrors the Reconmap bug class: a debug/introspection endpoint that should inherit the surrounding authorization policy is instead left open to any unauthenticated remote caller, disclosing sensitive internal process data.

### Finding Description
`NewRouter` builds an `api` route group with only rate-limiting and session middleware — no authentication is attached at this level [1](#0-0) . `loopRoutes` is called directly on this unauthenticated `api` group and registers the plugin metrics and pprof-forwarding handlers with no auth middleware at all: [2](#0-1) 

By contrast, the node's own `/debug/pprof/*` handlers (`pprof.Index`, `pprof.Profile`, `pprof.Trace`, `pprof.Handler("heap")`, `pprof.Handler("goroutine")`, etc.) are defined in `metricRoutes`, but that function is only ever invoked inside the `authv2` group, which requires `auth.Authenticate(... auth.AuthenticateByToken, auth.AuthenticateBySession)`: [3](#0-2) [4](#0-3) 

The plugin-side equivalents (`pluginPPROFHandler`, `pluginPPROFPOSTSymbolHandler`) forward arbitrary pprof requests — including CPU profiling for attacker-chosen `seconds`, heap dumps, and symbol lookups — straight through to the plugin's local pprof server with no caller identity check: [5](#0-4) 

The project's own documentation confirms only `/discovery` and `/plugins/<name>/metrics` are intended to be unauthenticated, for Prometheus scraping — pprof was not meant to be part of that unauthenticated surface: [6](#0-5) 

Because `pluginPPROFHandler`/`pluginPPROFPOSTSymbolHandler` are registered on the same unauthenticated `api` group as the metrics-discovery routes, any unauthenticated remote client that can reach the node's HTTP port (the same port serving the operator UI and admin API) can pull heap dumps, goroutine stacks, and CPU profiles from any registered LOOP plugin process (e.g. Median, Solana, Starknet relayer plugins) by iterating over plugin names, exactly as the Reconmap bug let an unauthenticated caller iterate sequential project IDs.

### Impact Explanation
`pprof` heap and goroutine dumps expose in-memory data structures of the plugin process, which can include decrypted secrets, private keys, RPC credentials, and other sensitive runtime state handled by relayer/plugin processes. `debug/pprof/profile` with an attacker-controlled `seconds` parameter also allows a remote unauthenticated caller to pin CPU for a controllable duration, and `symbol` lookups aid in reverse engineering binary internals — all without any authentication, unlike the equivalent core-node pprof endpoints which correctly require admin authentication.

### Likelihood Explanation
The routes are reachable from any unauthenticated client that can reach the node's public HTTP API port — no special network position, credentials, or role is required, and plugin names can be discovered directly via the also-unauthenticated `/discovery` endpoint [7](#0-6) , which enumerates registered plugin names, making enumeration trivial.

### Recommendation
Move `pluginPPROFHandler` and `pluginPPROFPOSTSymbolHandler` registrations into an authenticated route group (mirroring `metricRoutes(authv2)`), or add `auth.Authenticate(...)`/`auth.RequiresAdminRole` middleware directly in `loopRoutes` for the pprof-forwarding routes while leaving `/discovery` and `/plugins/:name/metrics` unauthenticated as documented/intended.

### Proof of Concept
1. Start a chainlink node with a LOOP plugin registered (e.g. Median/Solana relayer).
2. Without any session cookie or API token, request `GET /discovery` to enumerate registered plugin names [7](#0-6) .
3. For a discovered plugin name `foo`, request `GET /plugins/foo/debug/pprof/heap?debug=1` with no credentials — the request is forwarded and returned successfully because no auth middleware guards this route [2](#0-1) , unlike the equivalent `GET /v2/debug/pprof/heap` which requires admin authentication [4](#0-3) .

// discoveryHandler implements service discovery of prom endpoints for LOOPs in the registry
func (l *LoopRegistryServer) discoveryHandler(w http.ResponseWriter, req *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	groups := make([]*targetgroup.Group, 0, 1+len(l.registry.List()))

	// add node metrics to service discovery
	groups = append(groups, pluginGroup(l.discoveryHostName, l.exposedPromPort, "/metrics"))

	// add all the plugins
	for _, registeredPlugin := range l.registry.List() {
		group := pluginGroup(l.discoveryHostName, l.exposedPromPort, pluginMetricPath(registeredPlugin.Name))
		group.Labels[LabelMetaPluginName] = model.LabelValue(registeredPlugin.Name)
		groups = append(groups, group)
	}

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}

func (l *LoopRegistryServer) pluginPPROFPOSTSymbolHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/symbol", l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	body, err := io.ReadAll(gc.Request.Body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error reading plugin pprof request body: %s", err))
		return
	}
	l.doRequest(gc, "POST", pluginURL, bytes.NewReader(body), timeout, pluginName)
}
