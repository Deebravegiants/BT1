### Title
Missing role-based authorization on `/v2/debug/pprof/*` allows any authenticated user (including View role) to read runtime memory dumps, goroutine stacks and command-line data - ([File: core/web/router.go])

### Summary
The pprof debug endpoints mounted at `/v2/debug/pprof/*` are registered via `metricRoutes(authv2)` and only inherit the base `authv2` group's authentication middleware (`auth.AuthenticateByToken`/`auth.AuthenticateBySession`). Unlike every other sensitive endpoint in the router (`/v2/users`, `/v2/transfers*`, `/v2/keys/*/export`, `/v2/keys/*/import`, `/v2/vault/dkg_results/*`, etc.), none of the pprof routes are wrapped with `auth.RequiresAdminRole`, `auth.RequiresEditRole`, or even `auth.RequiresRunRole`. Any authenticated API user - even one with the lowest privilege `UserRoleView` - can hit these endpoints.

### Finding Description
`core/web/router.go` defines the middleware pattern used consistently throughout the file: an `authv2` group requires only base authentication, and then each individual route adds a role gate matching its sensitivity (`auth.RequiresAdminRole`, `auth.RequiresEditRole`, or `auth.RequiresRunRole`) as seen at [1](#0-0) , [2](#0-1) , and [3](#0-2) .

However, `metricRoutes` is called directly on `authv2` with a comment claiming these are "Debug routes accessible via authentication" and registers the full pprof route set without any role wrapper: [4](#0-3) [5](#0-4) 

The role enforcement helpers (`RequiresRunRole`, `RequiresEditRole`, `RequiresAdminRole`) are defined in `core/web/auth/auth.go` and demonstrate the intended layered check (authenticate, then check `user.Role`) that pprof skips entirely: [6](#0-5) .

This is structurally identical to the SiYuan `renderSprig` bug: a sensitive, data-exfiltration-capable endpoint that follows the authenticated-route pattern used by every other endpoint in the file, but is missing the additional role-based authorization gate that peer endpoints consistently apply.

Notably, the project's own RBAC regression test suite (`core/web/auth/auth_test.go`) enumerates every route and its required minimum role to prevent exactly this class of regression, yet the pprof endpoints registered by `metricRoutes` are conspicuously absent from `routesRolesMap`, meaning there is no automated test coverage asserting a minimum role for these routes: [7](#0-6) .

### Impact Explanation
`pprof` endpoints (`/debug/pprof/heap`, `/goroutine`, `/cmdline`, `/profile`, `/trace`, `/allocs`, etc.) can leak:
- Full heap memory dumps, which in a Chainlink node's process may contain decrypted private keys, session tokens, DKG shares, or database credentials held in memory during signing/transaction operations.
- Goroutine stack traces revealing internal state, connection strings, or in-flight request data.
- `cmdline`, revealing process invocation arguments which can include secrets passed via CLI flags.

Any authenticated user, even one provisioned with the minimal `UserRoleView` role (intended only for read-only dashboard access), can pull this information - a direct analog to the SiYuan report where a low-privilege "Reader" account could access data intended to be restricted to admins. This is an unauthorized information disclosure via CWE-285 (Improper Authorization) / CWE-732 (Incorrect Permission Assignment).

### Likelihood Explanation
Any operator that provisions non-admin API users (e.g., `view` or `run` role tokens for monitoring/automation integrations) is exposed. The route is trivially reachable with a valid session or API token - no special conditions are required, and the request path (`GET /v2/debug/pprof/heap`) is a standard, publicly documented pprof convention, making exploitation straightforward once any authenticated credential is obtained.

### Recommendation
Wrap the pprof route group registered in `metricRoutes` with an explicit role check (at minimum `auth.RequiresAdminRole`, consistent with other operationally sensitive endpoints such as `/v2/keys/*/export` and `/v2/transfers`) rather than relying solely on the base `authv2` authentication group. Add corresponding entries to `routesRolesMap` in `core/web/auth/auth_test.go` so that regression tests catch any future removal of the role gate.

### Proof of Concept
1. Provision a Chainlink node and create a non-admin API user (e.g. `chainlink admin users create --role=view`), obtaining a session cookie or API token/secret pair.
2. Authenticate as that view-role user against `/sessions` or via `X-API-KEY`/`X-API-SECRET` headers.
3. Issue: `GET /v2/debug/pprof/heap` (or `/goroutine`, `/cmdline`) with the low-privilege credentials.
4. Observe a `200 OK` response containing a full heap/goroutine dump, despite the account never being granted `edit`/`run`/`admin` privileges - confirming the missing role check identified at `core/web/router.go:185-199,445-446`.

// RequiresAdminRole extracts the user object from the context, and asserts the user's role is 'admin'
func RequiresAdminRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role != clsessions.UserRoleAdmin {
			c.Abort()
			addForbiddenErrorHeaders(c, "admin", string(user.Role), user.Email)
			jsonAPIError(c, http.StatusForbidden, errors.New("Forbidden"))
			return
		}
		handler(c)
	}
}
