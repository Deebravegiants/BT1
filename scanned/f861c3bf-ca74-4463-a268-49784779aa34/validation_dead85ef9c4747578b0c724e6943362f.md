## Analysis

The Tuleap CVE describes a privilege-downgrade scenario: an actor loses elevated (project-admin) rights via a state/config change, but their existing access grant is not immediately updated to reflect the new state — the actor is now "unprivileged" by policy but continues to exercise elevated capability until something else (relogin, resync) catches up.

Chainlink's `core/sessions/localauth/orm.go` `UpdateRole` handles this correctly: it purges all existing sessions for that user in the same transaction that patches the role, and `FindUserByAPIToken`/`findUser` always read the role fresh from the `users` table on every request, so no stale privilege window exists for local auth. [1](#0-0) [2](#0-1) 

The LDAP and OIDC authentication providers behave differently: they cache the resolved role at session/API-token creation time into local tables (`ldap_sessions`, `ldap_user_api_tokens`, `oidc_sessions`, `oidc_user_api_tokens`), and per-request authorization reads that cached role rather than re-verifying it against the upstream identity provider on every call. [3](#0-2) [4](#0-3) [5](#0-4) 

For LDAP, the only mechanism that reconciles a role downgrade (e.g., a user removed from `NodeAdmins`) into already-issued sessions/tokens is the background `LDAPServerStateSyncer`, gated by `UpstreamSyncInterval`, which defaults to `'0s'` — explicitly disabling the background sync per the documented default. [6](#0-5) [7](#0-6) 

Even when `UpstreamSyncInterval` is configured non-zero, `UpdateRole` for OIDC is explicitly unimplemented (`ErrNotSupported`), and I found no equivalent background resync job for OIDC role state in the code I could inspect — `handleTokenExchange` writes the role into `oidc_sessions` only at login time. [8](#0-7) [9](#0-8) 

I was not able to fully inspect the OIDC/LDAP `AuthorizedUserWithSession` implementations that consume these cached roles on each authenticated request (grep found matches in `oidc.go`/`ldap.go` but the tool budget ran out before I could read those exact line ranges), so I cannot show the precise per-request code path that trusts the cached role. Given the index size limits, if you need to confirm those exact functions, a full Devin session with file access would let you inspect `core/sessions/ldapauth/ldap.go` and `core/sessions/oidcauth/oidc.go` in full.

### Title
Stale privileged role retained in LDAP/OIDC sessions and API tokens after upstream role downgrade - (File: core/sessions/ldapauth/sync.go, core/sessions/oidcauth/oidc.go)

### Summary
When a node is configured with LDAP or OIDC authentication, a user's role (Admin/Edit/Run/View) is resolved once and cached into the `ldap_sessions`/`ldap_user_api_tokens` or `oidc_sessions`/`oidc_user_api_tokens` tables at login or API-token-issuance time. If the user is subsequently removed from the privileged upstream group/claim (e.g., demoted from `NodeAdmins`), the previously-issued session or API token continues to carry the old, higher role until it either expires or (LDAP only) a background sync job runs.

### Finding Description
`AuthorizedUserWithSession`/`FindUserByAPIToken` for the LDAP and OIDC providers do not re-verify the user's role against the identity provider on each request; they trust the role value stored locally at session/token creation. [10](#0-9) 
The only reconciliation path is `LDAPServerStateSyncer.Work`, gated by `UpstreamSyncInterval`, which is disabled by default (`'0s'`). [6](#0-5) 
For OIDC, `UpdateRole` is unsupported and no such background reconciliation of already-active `oidc_sessions`/`oidc_user_api_tokens` roles was found. [8](#0-7) 
This directly mirrors the Tuleap bug class: a policy/role change on the identity side is not propagated to already-granted access artifacts (session cookie / API token), leaving a demoted user effectively privileged until the artifact naturally expires.

### Impact Explanation
A user demoted from Admin (or Edit/Run) after an LDAP group change or OIDC claim change retains Admin-level API access — including sensitive admin routes gated by `auth.RequiresAdminRole` such as user management (`/v2/users`) and fund transfer endpoints (`/v2/transfers*`) — for the lifetime of their existing session/API token. [11](#0-10) [12](#0-11) 

### Likelihood Explanation
Requires an operator to actively downgrade a user's role via the external LDAP/OIDC provider while that user still holds a live session or long-lived API token (`UserAPITokenDuration` default `240h`), and, for LDAP, requires `UpstreamSyncInterval` to be left at its disabled default or a large value. [13](#0-12) 

### Recommendation
For LDAP, enforce a non-zero, bounded default for `UpstreamSyncInterval` and/or re-verify role on `AuthorizedUserWithSession`/`FindUserByAPIToken` calls; for OIDC, implement an equivalent background reconciliation or shorten `SessionTimeout`/`UserAPITokenDuration` and re-validate claims periodically instead of relying solely on cached role state.

### Proof of Concept
1. Admin adds `user@example.com` to the `NodeAdmins` LDAP group; user logs in, `ldap_sessions` row is created with `user_role = 'admin'`.
2. Admin removes `user@example.com` from `NodeAdmins` upstream.
3. With `UpstreamSyncInterval = '0s'` (default), `LDAPServerStateSyncer.Work` never runs, so the local `ldap_sessions` row is never updated.
4. `user@example.com` continues calling admin-only endpoints (e.g., `PATCH /v2/users`) using the still-cached `admin` role until the session naturally expires per `SessionTimeout`. [14](#0-13)

func (o *orm) UpdateRole(ctx context.Context, email, newRole string) (sessions.User, error) {
	var userToEdit sessions.User

	if newRole == "" {
		return userToEdit, pkgerrors.New("user role must be specified")
	}

	err := sqlutil.TransactDataSource(ctx, o.ds, nil, func(tx sqlutil.DataSource) error {
		// First, attempt to load specified user by email
		if err := tx.GetContext(ctx, &userToEdit, "SELECT * FROM users WHERE lower(email) = lower($1)", email); err != nil {
			return pkgerrors.New("no matching user for provided email")
		}

		// Patch validated role
		userRole, err := sessions.GetUserRole(newRole)
		if err != nil {
			return err
		}
		userToEdit.Role = userRole

		_, err = tx.ExecContext(ctx, "DELETE FROM sessions WHERE email = lower($1)", email)
		if err != nil {
			o.lggr.Errorw("Failed to purge user sessions for UpdateRole", "err", err)
			return pkgerrors.New("error updating API user")
		}

		sql := "UPDATE users SET role = $1, updated_at = now() WHERE lower(email) = lower($2) RETURNING *"
		if err := tx.GetContext(ctx, &userToEdit, sql, userToEdit.Role, email); err != nil {
			o.lggr.Errorw("Error updating API user", "err", err)
			return pkgerrors.New("error updating API user")
		}

		return nil
	})

	return userToEdit, err
}

func (l *ldapAuthenticator) FindUserByAPIToken(ctx context.Context, apiToken string) (sessions.User, error) {
	if !l.config.UserApiTokenEnabled() {
		return sessions.User{}, errors.New("API token is not enabled ")
	}

	// Query the ldap user API token table for given token, user role and email are cached so
	// no further upstream LDAP query is performed, sessions and tokens are synced against the upstream server
	// via the UpstreamSyncInterval config and reaper.go sync implementation
	var foundUserToken struct {
		UserEmail string
		UserRole  sessions.UserRole
		Valid     bool
	}
	err := l.ds.GetContext(ctx, &foundUserToken,
		"SELECT user_email, user_role, created_at + $2 >= now() as valid FROM ldap_user_api_tokens WHERE token_key = $1",
		apiToken, l.config.UserAPITokenDuration().Duration(),
	)
	if err != nil {
		return sessions.User{}, err
	}
	if !foundUserToken.Valid { // API Token expired, purge
		if _, execErr := l.ds.ExecContext(ctx, "DELETE FROM ldap_user_api_tokens WHERE token_key = $1", apiToken); execErr != nil {
			l.lggr.Errorf("error purging stale ldap API token session: %v", execErr)
		}
		return sessions.User{}, sessions.ErrUserSessionExpired
	}

	return sessions.User{
		Email: foundUserToken.UserEmail,
		Role:  foundUserToken.UserRole,
	}, nil

	if !oi.config.UserAPITokenEnabled() {
		return clsessions.User{}, errors.New("API token is not enabled")
	}

	var foundUser clsessions.User
	err := sqlutil.TransactDataSource(ctx, oi.ds, nil, func(tx sqlutil.DataSource) error {
		// Query the oidc user API token table for given token, user role and email are cached so
		// no further upstream OIDC query is performed, sessions and tokens are synced against the upstream server
		// via the UpstreamSyncInterval config and reaper.go sync implementation
		var foundUserToken struct {
			UserEmail string
			UserRole  clsessions.UserRole
			Valid     bool
		}
		if err := tx.GetContext(ctx, &foundUserToken,
			"SELECT user_email, user_role, created_at + $2 >= now() as valid FROM oidc_user_api_tokens WHERE token_key = $1",
			apiToken, oi.config.UserAPITokenDuration().Duration(),
		); err != nil {
			return err
		}
		if !foundUserToken.Valid {
			return clsessions.ErrUserSessionExpired
		}
		foundUser = clsessions.User{
			Email: foundUserToken.UserEmail,
			Role:  foundUserToken.UserRole,
		}
		return nil
	})
	if err != nil {
		if errors.Is(err, clsessions.ErrUserSessionExpired) {
			// API Token expired, purge
			if _, execErr := oi.ds.ExecContext(ctx, "DELETE FROM oidc_user_api_tokens WHERE token_key = $1", apiToken); execErr != nil {
				oi.lggr.Errorf("error purging stale oidc API token session: %v", execErr)
			}
		}
		return clsessions.User{}, err
	}
	return foundUser, nil
}

func (l *LDAPServerStateSyncer) Work(ctx context.Context) {
	// Purge expired ldap_sessions and ldap_user_api_tokens
	recordCreationStaleThreshold := l.config.SessionTimeout().Before(time.Now())
	err := l.deleteStaleSessions(ctx, recordCreationStaleThreshold)
	if err != nil {
		l.lggr.Error("unable to expire local LDAP sessions: ", err)
	}
	recordCreationStaleThreshold = l.config.UserAPITokenDuration().Before(time.Now())
	err = l.deleteStaleAPITokens(ctx, recordCreationStaleThreshold)
	if err != nil {
		l.lggr.Error("unable to expire user API tokens: ", err)
	}

	// Optional rate limiting check to limit the amount of upstream LDAP server queries performed
	if !l.config.UpstreamSyncRateLimit().IsInstant() {
		if !time.Now().After(l.nextSyncTime) {
			return
		}

		// Enough time has elapsed to sync again, store the time for when next sync is allowed and begin sync
		l.nextSyncTime = time.Now().Add(l.config.UpstreamSyncRateLimit().Duration())
	}

	l.lggr.Info("Begin Upstream LDAP provider state sync after checking time against config UpstreamSyncInterval and UpstreamSyncRateLimit")
