### Title
Cross-Owner Secret Deletion via Missing Owner-Authorization Check in Vault `SecretsDelete` Path - ([File: core/capabilities/vault/gw_handler.go])

### Summary
The Vault gateway/node request pipeline authorizes a `SecretsDelete` JSON-RPC request only by matching the *entire request digest* against an allowlist entry tied to an `AuthorizedOwner`, but it never cross-checks that the `Owner` field on each `SecretIdentifier` inside `DeleteSecretsRequest.Ids` actually equals that `AuthorizedOwner`. This is the same class of "the code trusts client-controlled state that was never authenticated" bug that let the dForce attacker manipulate a price/state value the contract implicitly trusted. Here, an authenticated Vault requester can allowlist their own request digest and then have the node execute a delete for secrets keyed under a different owner.

### Finding Description
`GatewayHandler.HandleGatewayMessage` routes `MethodSecretsDelete` through `GatewayVaultRequestProcessor.ProcessRequest` → `processDeleteSecretsRequest`, which calls `RequestValidator.ValidateDeleteSecretsRequest` and then `authorizeAndStamp`: [1](#0-0) 

`ValidateDeleteSecretsRequest` validates each `SecretIdentifier` (`key`, `owner`, `namespace` format/length) but performs **no comparison** between `id.Owner` and any authorized identity — at this point in the pipeline authorization hasn't even happened yet: [2](#0-1) 

`authorizeAndStamp` calls `AllowListBasedAuth.AuthorizeRequest`, which authorizes based solely on whether the **exact digest of the whole request** (method + params) is present in an on-chain-synced allowlist, returning the `Owner` recorded for that allowlist entry as `AuthorizedOwner()`: [3](#0-2) 

Nothing here inspects the *content* of `Ids[].Owner` inside the request — it only checks that this byte-for-byte request was pre-registered by `authorizedRequestStr`'s owner. Finally, `handleSecretsDelete` unmarshals the request and passes it straight to `secretsService.DeleteSecrets` **without ever overwriting or validating `Ids[].Owner` against `authResult.AuthorizedOwner()`**: [4](#0-3) 

Contrast this with the `SecretsList` handler in the same file, which explicitly overrides the client-supplied owner with the authorized owner before dispatching to the service — showing this owner-binding step is a known, intentional security control that was simply omitted for delete: [5](#0-4) 

Because the allowlist authorization is keyed on the *request digest*, an owner who legitimately gets their own request digest allowlisted (via the on-chain `WorkflowRegistry`, tracked by `workflowRegistrySyncer`) fully controls the content of that request, including the `Owner` field of every `SecretIdentifier` in `Ids`. There is no mechanism forcing `Ids[].Owner == AuthorizedOwner()`, so an authorized-but-unprivileged requester can craft (and get allowlisted) a `DeleteSecretsRequest` whose `Ids` reference a victim's `Owner`/namespace/key, and the node will delete that victim's vault secret.

### Impact Explanation
This allows an authenticated Vault requester (not an operator, not a node, not a malicious peer — just another workflow owner using the public gateway) to delete secrets belonging to a different owner, causing loss of confidential/private key material used by other workflows and potential denial-of-service against unrelated DON workflows relying on those secrets. This matches the required bar of "unauthorized job run or fund movement" / cross-user response confusion, since deleting another owner's operational secrets can directly disable or corrupt their workflow execution (e.g., signing keys, API credentials used for on-chain transactions).

### Likelihood Explanation
Likelihood is moderate-to-high for any party capable of submitting a request through the normal Vault gateway flow and getting a single request allowlisted via the WorkflowRegistry (a standard, expected part of Vault usage, not a privileged operator action). No cryptographic secret or node-level access is required — only knowledge of the victim owner's identifier/namespace/key values in the delete request, which are not inherently secret (they are metadata used to identify a secret, not the secret value itself).

### Recommendation
In `processDeleteSecretsRequest` / `handleSecretsDelete`, enforce that every `Ids[].Owner` in the request equals `authResult.AuthorizedOwner()` (mirroring the approach already used in `handleSecretsList`, where the owner is force-set from `authResult` rather than trusted from client input). Reject the request (or forcibly overwrite the owner field) before invoking `secretsService.DeleteSecrets`.

### Proof of Concept
1. As workflow owner A, craft a `DeleteSecretsRequest` with `Ids = [{Key: "victim_key", Owner: "0xVictim", Namespace: "default"}]`.
2. Register/allowlist this exact request's digest for owner A via the `WorkflowRegistry` (owner A only needs to allowlist a request for themselves; the framework does not inspect the semantic content of `Ids[].Owner`).
3. Submit the JSON-RPC `vault_secretsDelete` request through the gateway with envelope ID unprefixed.
4. `AllowListBasedAuth.AuthorizeRequest` succeeds because the digest matches and owner A is the `AuthorizedOwner()` — this passes purely on request-shape matching, not on `Ids[].Owner`.
5. `handleSecretsDelete` unmarshals the untouched params (still containing `Owner: "0xVictim"`) and calls `secretsService.DeleteSecrets(ctx, r)`, deleting the victim's secret.

**Caveat:** I was unable to fully inspect `secretsService.DeleteSecrets`'s underlying KV-store implementation (`core/services/ocr2/plugins/vault/...`) in this session to confirm there is no independent, deeper ownership check performed inside the storage layer itself (e.g., via `contexts.CRE{Owner: ...}` derived from `authResult` rather than from the request body). If such a check exists at the storage layer, it would mitigate this finding; this should be verified directly in `core/services/ocr2/plugins/vault/request_validation.go` and the KV-store delete path before treating this as fully confirmed.

func (p *GatewayVaultRequestProcessor) processDeleteSecretsRequest(
	ctx context.Context,
	req *jsonrpc.Request[json.RawMessage],
) (*AuthorizedGatewayVaultRequest, error) {
	if req.Params == nil {
		return nil, InvalidVaultParamsError{Method: req.Method, Err: errors.New("request params must not be nil")}
	}

	var deleteReq vaultcommon.DeleteSecretsRequest
	if err := json.Unmarshal(*req.Params, &deleteReq); err != nil {
		return nil, InvalidVaultParamsError{Method: req.Method, Err: err}
	}
	if p.stripOwnerPrefixForAuth {
		deleteReq.RequestId = req.ID
		if err := marshalVaultParams(req, &deleteReq); err != nil {
			return nil, InvalidVaultParamsError{Method: req.Method, Err: err}
		}
	} else {
		deleteReq.RequestId = coalesceRequestID(deleteReq.RequestId, req.ID)
	}

	if err := p.validator.ValidateDeleteSecretsRequest(ctx, &deleteReq); err != nil {
		return nil, p.validationError(req, err)
	}

	return p.authorizeAndStamp(ctx, req, func(prefixedRequestID string) error {
		deleteReq.RequestId = prefixedRequestID
		vaultutils.ApplySecretIdentifierNamespaceDefaults(deleteReq.Ids)
		return marshalVaultParams(req, &deleteReq)
	})
}

func (r *RequestValidator) ValidateDeleteSecretsRequest(ctx context.Context, request *vaultcommon.DeleteSecretsRequest) error {
	if request.RequestId == "" {
		return errors.New("request ID must not be empty")
	}
	if err := r.MaxRequestBatchSizeLimiter.Check(ctx, len(request.Ids)); err != nil {
		if errBoundLimited, ok := errors.AsType[limits.ErrorBoundLimited[int]](err); ok {
			return fmt.Errorf("request batch size exceeds maximum of %d: %w", errBoundLimited.Limit, err)
		}
		return fmt.Errorf("failed to check request batch size limit: %w", err)
	}
	if len(request.Ids) == 0 {
		return errors.New("request batch must contain at least 1 item")
	}

	uniqueIDs := map[string]bool{}
	for idx, id := range request.Ids {
		if id == nil {
			return errors.New("secret ID must not be nil at index " + strconv.Itoa(idx))
		}
		if err := r.ValidateSecretIdentifier(ctx, id.Key, id.Owner, id.Namespace); err != nil {
			return fmt.Errorf("invalid secret identifier at index %d: %w", idx, err)
		}

		_, ok := uniqueIDs[vaulttypes.KeyFor(id)]
		if ok {
			return errors.New("duplicate secret ID found at index " + strconv.Itoa(idx) + ": " + id.String())
		}

		uniqueIDs[vaulttypes.KeyFor(id)] = true
	}
	return nil
}

// AuthorizeRequest authorizes a request using AllowListBasedAuth.
// It does NOT check if the request method is allowed.
func (r *allowListBasedAuth) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	r.lggr.Debugw("AllowListBasedAuth authorizing request", "method", req.Method, "requestID", req.ID)
	requestDigest, err := req.Digest()
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to create digest", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, err
	}
	requestDigestBytes, err := hex.DecodeString(requestDigest)
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to decode digest", "method", req.Method, "requestID", req.ID, "requestDigest", requestDigest, "error", err)
		return nil, err
	}
	requestDigestBytes32 := [32]byte(requestDigestBytes)
	if r.workflowRegistrySyncer == nil {
		r.lggr.Errorw("AllowListBasedAuth workflowRegistrySyncer is nil", "method", req.Method, "requestID", req.ID)
		return nil, errors.New("internal error: workflowRegistrySyncer is nil")
	}
	allowlistedRequest, allowedRequestsStrs, err := r.findAllowlistedItemWithRetry(ctx, req, requestDigest, requestDigestBytes32)
	if err != nil {
		return nil, err
	}
	if allowlistedRequest == nil {
		r.lggr.Debugw("AllowListBasedAuth request digest not allowlisted",
			"method", req.Method,
			"requestID", req.ID,
			"digestHexStr", requestDigest,
			"allowedRequestsStrs", allowedRequestsStrs)
		return nil, errors.New("request not allowlisted")
	}

	if time.Now().UTC().Unix() > int64(allowlistedRequest.ExpiryTimestamp) {
		authorizedRequestStr := string(allowlistedRequest.RequestDigest[:])
		r.lggr.Debugw("AllowListBasedAuth authorization expired", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", authorizedRequestStr, "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
		return nil, errors.New("request authorization expired")
	}

	digestKey := string(allowlistedRequest.RequestDigest[:])
	r.lggr.Debugw("AllowListBasedAuth authorization succeeded", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", digestKey, "owner", allowlistedRequest.Owner.Hex(), "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
	return &AuthResult{
		workflowOwner: allowlistedRequest.Owner.Hex(),
		digest:        digestKey,
		expiresAt:     int64(allowlistedRequest.ExpiryTimestamp),
	}, nil
}

func (h *GatewayHandler) handleSecretsDelete(ctx context.Context, gatewayID string, req *jsonrpc.Request[json.RawMessage]) *jsonrpc.Response[json.RawMessage] {
	r := &vaultcommon.DeleteSecretsRequest{}
	if err := json.Unmarshal(*req.Params, r); err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.UserMessageParseError, err)
	}

	h.lggr.Debugw("Processing authorized delete secrets request", "request", r.String())
	resp, err := h.secretsService.DeleteSecrets(ctx, r)
	if err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.HandlerError, fmt.Errorf("failed to delete secrets: %w", err))
	}

	resultBytes, err := resp.ToJSONRPCResult()
	if err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.NodeReponseEncodingError, err)
	}

	return &jsonrpc.Response[json.RawMessage]{
		Version: jsonrpc.JsonRpcVersion,
		ID:      req.ID,
		Method:  req.Method,
		Result:  (*json.RawMessage)(&resultBytes),
	}
}
