### Title
Unauthenticated Vault Gateway request can be front-run using only the public allowlisted digest, letting anyone consume it before the legitimate owner submits it - (File: core/capabilities/vault/allow_list_based_auth.go, core/capabilities/vault/authorizer.go, core/capabilities/vault/request_replay_guard.go)

### Summary
The Vault gateway's `AllowListBasedAuth` path authorizes a JSON-RPC request purely by recomputing a deterministic digest over its own public fields (`method`, `params`, `id`) and checking it against an on-chain, publicly readable allowlist entry — no signature, token, or proof of ownership is required for this path. The digest is then permanently consumed by a replay guard as soon as it is authorized. This is analogous to the reported `CrabNetting.checkOrder()` bug: any unprivileged caller who can reconstruct the exact request bytes that hash to a known-allowlisted digest can submit them to the gateway ahead of the legitimate owner, consuming the one-time authorization and causing the real request to be rejected as already used (or, since the processor then executes on the attacker-submitted copy, having its result routed back to the attacker instead of the legitimate owner).

### Finding Description
`authorizer.authorizeRequest` routes any request with an empty `req.Auth` field to the allowlist path for backward compatibility: [1](#0-0) 

`allowListBasedAuth.AuthorizeRequest` computes the digest solely from the request's own content (`req.Digest()`, a hash of method/params/id) and checks it against on-chain allowlisted digests from the workflow registry — it performs no signature check on the caller: [2](#0-1) 

Once authorized, the composite authorizer immediately consumes the digest via the replay guard, and any subsequent submission of the identical request — including the legitimate owner's own submission — is rejected with `ErrRequestAlreadySeen`: [3](#0-2) [4](#0-3) 

The allowlist entries themselves (digest, owner, expiry) are read from an on-chain registry contract via `workflowRegistrySyncer.GetAllowlistedRequests`, i.e., public data that anyone can query, exactly as the order objects in the `checkOrder` report were public/observable off-chain data: [5](#0-4) 

This is confirmed by the project's own test, which shows the authorization succeeds purely from digest matching, with replay protection living entirely in the generic `Authorizer` (not tied to caller identity): [6](#0-5) 

### Impact Explanation
Because authorization on this path is content-based rather than caller-based, anyone who learns/observes the exact `method`+`params`+`id` bytes that hash to an on-chain allowlisted digest (e.g., by observing them in transit to the internet-facing gateway, or reconstructing them from known public request shapes) can submit that exact request to the gateway before the legitimate owner does. The `RequestReplayGuard.CheckAndRecord` call consumes the digest on the very first authorized submission, so:
- The legitimate owner's genuine request is subsequently rejected with `ErrRequestAlreadySeen`, denying the intended vault operation (secrets create/update/delete/list, public key fetch) exactly as `checkOrder()` blocked legitimate auctions.
- Because the processor executes whichever copy was authorized first, the attacker (not the legitimate owner) receives the gateway's response for that operation, which is a cross-user response confusion consequence beyond simple griefing.

### Likelihood Explanation
No signature, secret, or identity proof is required for this authorization path — only knowledge of the request's public fields, which are as observable as an off-chain order object was in the original report. Any unprivileged party with visibility into a pending request (e.g., via the internet-facing gateway ingress) can win the race with a purely content-based, unauthenticated resubmission.

### Recommendation
Bind the allowlist-based authorization (and its replay consumption) to proof of caller identity rather than to request content alone — e.g., require the caller to additionally prove control of the allowlisted owner (a signature over the digest, similar to the JWT path's `RequestDigest` claim binding) before `CheckAndRecord` is allowed to consume the slot. Alternatively, do not treat first-authorized-wins as sufficient: require the executing processor to also validate that the submitter is the intended workflow owner before consuming the one-time allowlist entry.

### Proof of Concept
1. Observe (or otherwise learn) the exact `method`, `params`, and `id` of a pending Vault request whose digest is allowlisted on-chain for owner `O` (allowlist entries are public via `GetAllowlistedRequests`).
2. As an unrelated, unauthenticated client, submit a JSON-RPC request with identical `method`/`params`/`id` and empty `Auth` to the gateway's Vault endpoint before owner `O`'s real client does.
3. `authorizer.authorizeAllowListBasedAuth` → `allowListBasedAuth.AuthorizeRequest` succeeds (digest matches the allowlist entry, no signature check), and `replayGuard.CheckAndRecord` marks the digest consumed, per [3](#0-2) .
4. When owner `O`'s legitimate request subsequently arrives with the same digest, it is rejected with `ErrRequestAlreadySeen`, per [7](#0-6) , denying the owner's operation while the attacker's copy is the one that gets executed and answered.

func (a *authorizer) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	authResult, err := a.authorizeRequest(ctx, req)
	if err != nil {
		return nil, err
	}
	if authResult == nil {
		err = errors.New("auth mechanism returned nil auth result")
		a.lggr.Errorw("auth mechanism returned nil auth result", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "")
		return nil, err
	}
	if err := a.replayGuard.CheckAndRecord(authResult.Digest(), authResult.ExpiresAt()); err != nil {
		a.lggr.Debugw("replay guard rejected request", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "digest", authResult.Digest(), "expiresAt", authResult.ExpiresAt(), "hasAuth", req.Auth != "", "error", err)
		return nil, err
	}

func (a *authorizer) authorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	// Requests without req.Auth continue using the allowlist-based path for backwards compatibility.
	// Existing clients do not populate the auth field yet, so treating an empty value as JWT would break them.
	if req.Auth == "" {
		return a.authorizeAllowListBasedAuth(ctx, req)
	}
	return a.authorizeJWTBasedAuth(ctx, req)
}

// AuthorizeRequest authorizes a request using AllowListBasedAuth.
// It does NOT check if the request method is allowed.
func (r *allowListBasedAuth) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	r.lggr.Debugw("AllowListBasedAuth authorizing request", "method", req.Method, "requestID", req.ID)
	requestDigest, err := req.Digest()
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to create digest", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, err
	}
	requestDigestBytes, err := hex.DecodeString(requestDigest)
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to decode digest", "method", req.Method, "requestID", req.ID, "requestDigest", requestDigest, "error", err)
		return nil, err
	}
	requestDigestBytes32 := [32]byte(requestDigestBytes)
	if r.workflowRegistrySyncer == nil {
		r.lggr.Errorw("AllowListBasedAuth workflowRegistrySyncer is nil", "method", req.Method, "requestID", req.ID)
		return nil, errors.New("internal error: workflowRegistrySyncer is nil")
	}
	allowlistedRequest, allowedRequestsStrs, err := r.findAllowlistedItemWithRetry(ctx, req, requestDigest, requestDigestBytes32)
	if err != nil {
		return nil, err
	}
	if allowlistedRequest == nil {
		r.lggr.Debugw("AllowListBasedAuth request digest not allowlisted",
			"method", req.Method,
			"requestID", req.ID,
			"digestHexStr", requestDigest,
			"allowedRequestsStrs", allowedRequestsStrs)
		return nil, errors.New("request not allowlisted")
	}

// CheckAndRecord returns ErrRequestAlreadySeen if the digest was previously
// recorded and has not yet expired. Otherwise it records the digest with
// the given expiry timestamp (unix seconds, UTC).
//
// Expired entries are cleaned up on every call.
func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}

func TestAuthorizer_RejectsAllowListBasedAuthReplay(t *testing.T) {
	allowListBasedAuth := vaultmocks.NewAuthorizer(t)
	// Use a method without secret identifiers so the owner-binding check is a no-op.
	req := jsonrpc.Request[json.RawMessage]{ID: "1", Method: vaulttypes.MethodPublicKeyGet}
	allowListBasedAuth.EXPECT().AuthorizeRequest(mock.Anything, req).Return(vault.NewAuthResult("", "0xabc", "digest-1", time.Now().Add(time.Minute).Unix()), nil).Twice()

	a := vault.NewAuthorizer(allowListBasedAuth, nil, logger.TestLogger(t))

	authResult, err := a.AuthorizeRequest(t.Context(), req)
	require.NoError(t, err)
	require.Empty(t, authResult.OrgID())
	require.Equal(t, "0xabc", authResult.WorkflowOwner())
	require.Equal(t, "0xabc", authResult.AuthorizedOwner())

	authResult, err = a.AuthorizeRequest(t.Context(), req)
	require.Nil(t, authResult)
	require.ErrorIs(t, err, vault.ErrRequestAlreadySeen)
}
