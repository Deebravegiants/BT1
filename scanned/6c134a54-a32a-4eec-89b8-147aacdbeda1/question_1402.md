# Q1402: num_unflushed_roots settles one authorization twice (accounts_cache.rs)

## Question
Can an unprivileged attacker entering through ordinary transactions that create, write, resize, close and reopen accounts the attacker pays for reach `num_unflushed_roots` in `accounts-db/src/accounts_cache.rs` with an interleaving where the write lands between the read and the validation, and have `num_unflushed_roots` apply the same authorized effect a second time, so that the invariant "One signed authorization produces exactly one state effect." breaks and the result is Loss of Funds?

## Target
- File/function: `accounts-db/src/accounts_cache.rs` -> `num_unflushed_roots()` (around line 388)
- Entrypoint: ordinary transactions that create, write, resize, close and reopen accounts the attacker pays for
- Attacker controls: an interleaving where the write lands between the read and the validation
- Exploit idea: Get `num_unflushed_roots` to apply the same logical effect twice from a single user authorization by re-entering it or replaying the surrounding flow.
- Invariant to test: One signed authorization produces exactly one state effect.
- Expected Immunefi impact: Loss of Funds - theft or creation of lamports/tokens without the owner's signature (6,250-25,000 SOL)
- Fast validation: Integration test: submit the flow twice (and once re-entrantly) and assert the second application is rejected and balances moved once.
