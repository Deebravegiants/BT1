Attacker input: intent.signer_id explicitly set by the caller to a string naming a different EVM account than this.config.signer.address. Preconditions: IntentSignerViem is constructed with a viem Account for attacker's own key, but no accountId override; the caller (an ordinary SDK user) builds an IntentPayload with signer_id already populated to another user's lowercase EVM address before calling signIntent. Equality that breaks: signer_id in the signed payload == the intents user id derived from the public key that produced signature — the attacker's key produced the signature, but signer_id names victimAddress, so identity != key. Scoped impact: Critical — if this MultiPayload is submitted via publishIntent and the intents contract or SDK's own downstream checks do not independently re-derive signer_id from the recovered ECDSA signer, the intent could be executed while nominally debiting the victim's account balance rather than the attacker's. Whose funds: victimAddress's balance under intents.near. Proof idea: vitest test constructing an IntentPayload with signer_id set to an address different from the IntentSignerViem's configured account, calling signIntent, then independently ECDSA-recovering the ERC-191 signature's signer address and asserting it differs from JSON.parse(payload).signer_id, proving the identity equality fails while the SDK still returns a well-formed signed MultiPayload.
