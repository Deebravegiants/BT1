## Finding: Verbose/Debug Web-Server Logging Exposes User Passwords via GraphQL Requests

### Title
Debug-level HTTP request logging exposes plaintext passwords in GraphQL mutations (`updateUserPassword`, `createAPIToken`, `deleteAPIToken`) - ([File: core/web/router.go])

### Summary
When the node's `Log.Level` is set to `debug` (a standard, supported, non-privileged configuration option), every HTTP request handled by the node's web server — including the GraphQL `/query` endpoint — has its full request body logged. The sanitization logic that is supposed to redact sensitive fields such as `password` only inspects **top-level** JSON keys, but GraphQL requests wrap all mutation arguments inside a nested `variables` object. As a result, plaintext passwords submitted to `updateUserPassword`, `createAPIToken`, and `deleteAPIToken` mutations are written unredacted into the node's logs, mirroring the exact bug class described in CVE-2019-3781 (password exposure via verbose/debug logging).

### Finding Description
The Gin logging middleware `loggerFunc` is registered globally via `engine.Use(...)` in `NewRouter`, so it applies to every route, including `POST /query` (the GraphQL endpoint). [1](#0-0) 

`loggerFunc` reads the raw request body and logs it at `Debug` level using `readBody`, which calls `readSanitizedJSON` to redact sensitive fields before logging: [2](#0-1) 

`readSanitizedJSON` only unmarshals the body into a flat `map[string]any` and redacts keys matching the `blacklist` (`password`, `newpassword`, `oldpassword`, etc.) — it does **not** recurse into nested objects: [3](#0-2) 

GraphQL requests always have the shape `{"query": "...", "variables": {...}, "operationName": "..."}`. All mutation input arguments — including passwords — are nested inside `variables`, not at the top level. For example, `updateUserPassword` takes an `UpdatePasswordInput` with `oldPassword`/`newPassword` fields: [4](#0-3) [5](#0-4) 

and `createAPIToken`/`deleteAPIToken` take a raw `password` field: [6](#0-5) 

Because `readSanitizedJSON` sees only the top-level keys `query`/`variables`/`operationName`, none of which match the blacklist, the entire nested `variables` payload — including the plaintext `oldPassword`, `newPassword`, or API-token `password` — passes through unredacted and is written to the `Debugw` log line's `"body"` field.

### Impact Explanation
Any node operator running with `Log.Level = 'debug'` (a supported, documented configuration, not an edge case) will have plaintext user passwords written to disk-based or console logs whenever a user changes their password or creates/deletes an API token through the GraphQL API/UI. Anyone with read access to those logs (e.g., a lower-privileged operator, a log-shipping pipeline, or a local user with filesystem access) can recover another operator's Chainlink node account password or the password required to mint/delete API tokens, enabling account takeover of the node's admin UI/API — a direct password-disclosure vulnerability analogous to CVE-2019-3781.

### Likelihood Explanation
`Log.Level = 'debug'` is a normal, commonly used operational setting (e.g. for troubleshooting), not an obscure or insecure-only build flag. No special privileges are required to trigger the exposure — any authenticated user changing their own password, or any user submitting a password-protected API token operation, causes their password to be captured verbatim in the node's own logs. The REST-flavored blacklist redaction gives a false sense of security since it works for the legacy `/v2/user/password` REST endpoint (flat body) but silently fails for the GraphQL endpoint (nested body), making this an easy-to-miss regression.

### Recommendation
Update `readSanitizedJSON` (and `redact`) in `core/web/router.go` to recursively walk nested JSON objects/arrays (not just top-level keys) when redacting blacklisted field names, so that GraphQL `variables` payloads are sanitized the same way flat REST bodies are. Alternatively, special-case the `/query` GraphQL route to redact known sensitive input fields (`password`, `oldPassword`, `newPassword`) anywhere in the parsed variables tree before logging.

### Proof of Concept
1. Start a Chainlink node with `Log.Level = 'debug'`.
2. As an authenticated user, send:
```
POST /query
{"query":"mutation($input: UpdatePasswordInput!){ updateUserPassword(input:$input){ ... } }",
 "variables":{"input":{"oldPassword":"CurrentSecretPass123!","newPassword":"NewSecretPass456!"}}}
```
3. Inspect the node's debug logs — the `Debugw` entry for `POST /query` will contain a `"body"` field with the full JSON, including `oldPassword` and `newPassword` in plaintext, because `readSanitizedJSON` only checks the top-level keys `query`/`variables` and never inspects the nested `input` object.

func loggerFunc(lggr logger.Logger) gin.HandlerFunc {
	return func(c *gin.Context) {
		buf, err := io.ReadAll(c.Request.Body)
		if err != nil {
			lggr.Error("Web request log error: ", err.Error())
			// Implicitly relies on limits.RequestSizeLimiter
			// overriding of c.Request.Body to abort gin's Context
			// inside io.ReadAll.
			// Functions as we would like, but horrible from an architecture
			// and design pattern perspective.
			if !c.IsAborted() {
				c.AbortWithStatus(http.StatusBadRequest)
			}
			return
		}
		rdr := bytes.NewBuffer(buf)
		c.Request.Body = io.NopCloser(bytes.NewBuffer(buf))

		start := time.Now()
		c.Next()
		end := time.Now()

		lggr.Debugw(fmt.Sprintf("%s %s", c.Request.Method, c.Request.URL.Path),
			"method", c.Request.Method,
			"status", c.Writer.Status(),
			"path", c.Request.URL.Path,
			"ginPath", c.FullPath(),
			"query", redact(c.Request.URL.Query()),
			"body", readBody(rdr, lggr),
			"clientIP", c.ClientIP(),
			"errors", c.Errors.String(),
			"servedAt", end.Format("2006-01-02 15:04:05"),
			"latency", fmt.Sprintf("%v", end.Sub(start)),
		)
	}

func readSanitizedJSON(buf *bytes.Buffer) (string, error) {
	var dst map[string]any
	err := json.Unmarshal(buf.Bytes(), &dst)
	if err != nil {
		return "", err
	}

	cleaned := map[string]any{}
	for k, v := range dst {
		if isBlacklisted(k) {
			cleaned[k] = "*REDACTED*"
			continue
		}
		cleaned[k] = v
	}

	b, err := json.Marshal(cleaned)
	if err != nil {
		return "", err
	}
	return string(b), err
}

func redact(values url.Values) string {
	cleaned := url.Values{}
	for k, v := range values {
		if isBlacklisted(k) {
			cleaned[k] = []string{"REDACTED"}
			continue
		}
		cleaned[k] = v
	}
	return cleaned.Encode()
}

// NOTE: keys must be in lowercase for case insensitive match
var blacklist = map[string]struct{}{
	"password":             {},
	"newpassword":          {},
	"oldpassword":          {},
	"current_password":     {},
	"new_account_password": {},
}

func isBlacklisted(k string) bool {
	lk := strings.ToLower(k)
	if _, ok := blacklist[lk]; ok || strings.Contains(lk, "password") {
		return true
	}
	return false
}
