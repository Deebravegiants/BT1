### Title
OIDC callback "state" parameter remains valid for replay during the token-exchange window - ([File: core/sessions/oidcauth/oidc.go])

### Summary
The chainlink node's OIDC SSO login flow validates the CSRF `state` parameter against a value stored in the gin session, but the deletion of that stored state is not persisted to the session backing store until after the entire token-exchange/claims-verification round trip to the external identity provider completes. This creates a window during which the same `state` (and accompanying authorization `code`) can be reused/replayed against `handleTokenExchange`, mirroring the bug class described in CVE-2020-14302 (Keycloak accepting multiple invocations with the same `state` parameter due to insufficiently strict single-use enforcement).

### Finding Description
`handleSignIn` generates a random `state`, stores it on the session, and redirects the browser to the OIDC provider: [1](#0-0) 

`handleTokenExchange` is the callback handler invoked by the frontend with the `code`/`state` returned by the IdP. It compares the request's `state` against the session-stored value, and only calls `ginSession.Delete("state")` in-memory — the deletion is not written back to the actual session store until `ginSession.Save()` is called much later, after the OAuth code exchange (`oi.oauth2Config.Exchange`), ID-token verification, and claim-to-role mapping have all completed: [2](#0-1) 

Because the invalidation of `state` is deferred to the very end of a multi-step, network-bound handler (an HTTP round trip to the external IdP plus JWKS/ID-token verification), an attacker who can send a second (replayed/raced) request with the same `code` and `state` before the first request's `Save()` completes will still find `storedState` present and matching, passing the check at: [3](#0-2) 

This is the same root-cause pattern as CVE-2020-14302: the endpoint that consumes the external IdP's callback accepts multiple invocations bound to the same `state` value because single-use enforcement is not atomic/immediate.

### Impact Explanation
A successful replay during the window would cause the second invocation to also attempt `oi.oauth2Config.Exchange(ctx, req.Code)`. In practice, most compliant OIDC providers enforce single-use authorization codes server-side, which limits the practical exploitability of replaying the `code` itself. However, the local `state` check is the node's own CSRF/replay defense and its effectiveness is undermined by the deferred persistence, so the node cannot rely on it to strictly single-use-gate the callback route as intended — weakening defense-in-depth against request-replay/race attacks targeting the login callback path. This affects unprivileged actors interacting with the node's authentication endpoint (`handleTokenExchange`), which is registered on the OIDC authenticator's router extension per `sessions.AuthenticationProvider.ExtendRouter`.

### Likelihood Explanation
Exploitation requires an attacker capable of racing two near-simultaneous requests to the callback endpoint with an intercepted/observed `code`+`state` pair (e.g., via shared network vantage, browser history/proxy logs, or a man-in-the-middle before TLS termination) during the short window where the external token exchange and ID-token verification are in flight. This is a narrow, timing-dependent condition and does not by itself bypass upstream IdP-side single-use code enforcement, so likelihood is lower than a full replay bypass but the underlying validation gap (delayed state invalidation) is present and reachable from an unprivileged network position without any credentials.

### Recommendation
Persist ("save") the session immediately after validating and deleting the `state` value — before performing the OAuth code exchange and any external network calls — so the `state` becomes single-use atomically with respect to the local session store, closing the replay window regardless of how long the downstream IdP round trip takes.

### Proof of Concept
1. Configure `WebServer.OIDC` and initiate login via `/oidc-login` (or equivalent `handleSignIn` route), obtaining a `state` value and being redirected to the IdP.
2. After successful IdP authentication, the frontend receives `code`/`state` and would normally call the `handleTokenExchange` endpoint once.
3. An attacker positioned to observe/replay the callback request (e.g., via a proxy or race condition against slow IdP response times) fires a second identical `POST` request with the same `code`/`state` concurrently with the legitimate request.
4. Because `ginSession.Delete("state")` at `core/sessions/oidcauth/oidc.go:184` is not flushed via `ginSession.Save()` until after the (potentially slow) `Exchange`/`Verify` calls complete (`core/sessions/oidcauth/oidc.go:266`), the second request's state-comparison check at lines 174-183 still succeeds, demonstrating the state value was not atomically invalidated on first use.

func (oi *oidcAuthenticator) handleSignIn(c *gin.Context) {
	// generate state and store on session
	state := oi.generateState()
	session := sessions.Default(c)
	session.Set("state", state)
	err := session.Save()
	if err != nil {
		c.JSON(http.StatusInternalServerError, gin.H{"error": "Failed to save session"})
		return
	}

	// redirect to provider
	url := oi.oauth2Config.AuthCodeURL(state, oauth2.AccessTypeOffline)
	c.Redirect(http.StatusFound, url)
}

func (oi *oidcAuthenticator) handleTokenExchange(c *gin.Context) {
	// parse and validate the incoming JSON request
	var req ExchangeTokenRequest
	if err := c.ShouldBindJSON(&req); err != nil {
		c.JSON(http.StatusBadRequest, ExchangeTokenResponse{
			Success: false,
			Message: "Invalid request: " + err.Error(),
		})
		return
	}

	// check state matches stored value on the session
	ginSession := sessions.Default(c)
	storedState := ginSession.Get("state")
	if storedState == nil || req.State != storedState.(string) {
		c.JSON(http.StatusBadRequest, ExchangeTokenResponse{
			Success: false,
			Message: "Invalid state parameter",
		})
		return
	}
	ginSession.Delete("state")

	// Begin token exchange to retrieve attested claims of authenticated user
	ctx := context.Background()
	oauth2Token, err := oi.oauth2Config.Exchange(ctx, req.Code)
	if err != nil {
		oi.lggr.Errorf("Failed to exchange token: %v", err)
		c.JSON(http.StatusInternalServerError, ExchangeTokenResponse{
			Success: false,
			Message: "OIDC exchange failed",
		})
		return
	}

	// Request token from provider for claims lookup and verification
	rawIDToken, ok := oauth2Token.Extra("id_token").(string)
	if !ok {
		oi.lggr.Errorf("No id_token field in oauth2 token: %v", err)
		c.String(http.StatusInternalServerError, "Missing id_token field in response")
		return
	}

	// Verify claim and retrieve attested user id claims
	idToken, err := oi.provider.Verifier(oi.oidcConfig).Verify(ctx, rawIDToken)
	if err != nil {
		oi.lggr.Errorf("Failed to verify ID token: %v", err)
		c.String(http.StatusInternalServerError, "Failed to verify ID token")
		return
	}

	var claims map[string]any
	if err = idToken.Claims(&claims); err != nil {
		oi.lggr.Errorf("Failed to parse OIDC return claims: %v", err)
		c.String(http.StatusInternalServerError, "Failed to parse OIDC return claims")
		return
	}
	idClaims, err := oi.ExtractIDClaimValues(claims, oi.config.ClaimName())
	if err != nil {
		oi.lggr.Errorf("Failed to extract ID claims from ID token. ClaimName: '%s': error %v", oi.config.ClaimName(), err)
		c.String(http.StatusInternalServerError, "Failed to extract ID claims from claims")
		return
	}
	email, ok := claims["email"].(string)
	if !ok {
		oi.lggr.Errorf("Failed to get email from claims. error: %v", err)
		c.String(http.StatusInternalServerError, "Failed to get email from claims")
	}
	oi.lggr.Tracef("Received and validated ID claims: %v\n", idClaims)

	// Map the claims to a role and insert a newly created session paired with role mapping for user
	role, err := oi.IDClaimsToUserRole(
		idClaims,
		oi.config.AdminClaim(),
		oi.config.EditClaim(),
		oi.config.RunClaim(),
		oi.config.ReadClaim(),
	)
	if err != nil {
		oi.lggr.Errorf("Failed to map configured RBAC role name against received list of group claims: %v", err)
		c.String(http.StatusBadRequest, "No matching role within attested user group claims")
		return
	}

	// Save new user authenticated clSession and role to oidc_sessions table
	// Sessions are set to expire after the duration + creation date elapsed
	clSession := clsessions.NewSession()
	_, err = oi.ds.ExecContext(
		ctx,
		"INSERT INTO oidc_sessions (id, user_email, user_role, created_at) VALUES ($1, $2, $3, now())",
		clSession.ID,
		strings.ToLower(email),
		role,
	)
	if err != nil {
		oi.lggr.Errorf("unable to create new session in oidc_sessions table %v", err)
		c.String(http.StatusInternalServerError, "Error creating session")
	}

	oi.auditLogger.Audit(audit.AuthLoginSuccessNo2FA, map[string]any{"email": email})

	// save session
	ginSession.Set(webauth.SessionIDKey, clSession.ID)
	err = ginSession.Save()
	if err != nil {
		oi.lggr.Errorf("failed to saved session %v", err)
		c.String(http.StatusInternalServerError, "Authentication failed")
		return
	}
