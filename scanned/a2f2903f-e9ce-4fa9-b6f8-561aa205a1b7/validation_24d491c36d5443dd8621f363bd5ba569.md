### Title
`Deposit::refund_all` sends the entire multi-contributor native storage-deposit hold to the terminating transaction's origin, letting one contributor claim another's `NativeDepositOf` entry - (File: `substrate/frame/revive/src/exec.rs`, `substrate/frame/revive/src/deposit_payment.rs`)

### Summary
`Stack::do_terminate` calls `T::Deposit::refund_all(&contract_account, exec_config.funds(origin.account_id()?))`, which — for both the default `()` backend and the `PGasDeposit` backend — releases the contract's *entire* `StorageDepositReserve` hold to a single recipient without consulting the per-contributor `NativeDepositOf[contract][contributor]` caps that gate every other refund path. Any signed account that triggers contract termination (there is no ownership check on who may call the terminate path) receives, as `origin`, 100% of the native deposit hold, including amounts contributed by other unrelated signers.

### Finding Description
`NativeDepositOf<T>` is documented as "Bounds how much native value the user can receive back from that contract's storage deposit" [1](#0-0) , and every partial refund path (`refund_on_hold`) enforces this cap: `let contribution = NativeDepositOf::<T>::get(from, to); let native_requested = amount.min(contribution);` [2](#0-1) .

`refund_all`, however, deliberately skips this cap:
```
fn refund_all(from, dst) -> ... {
    let amount = T::Currency::balance_on_hold(&reason.into(), from);
    <Self as Deposit<T>>::refund_on_hold(reason, from, dst, amount)?; // no per-contributor cap
    Ok(amount)
}
``` [3](#0-2) , and the same pattern in the PGAS-backed implementation: "`refund_all` bypasses the per-payer `NativeDepositOf` cap ... so the full native hold goes to the terminator" [4](#0-3) .

`do_terminate` invokes this with the *transaction origin* as recipient — not even the specified `beneficiary`:
```
let refund = T::Deposit::refund_all(&contract_account, exec_config.funds(origin.account_id()?))?;
...
Self::transfer(&origin, contract_account, &args.beneficiary, balance, ...)?;
``` [5](#0-4) . The contract's residual free balance goes to `args.beneficiary`, but the entire storage-deposit hold (contributed by potentially several distinct accounts via `NativeDepositOf`) is paid out to whichever account's signature is the extrinsic `origin` that reached the terminate path.

The terminate path itself has no access control tying it to a specific "owner" contributor: `terminate_caller` only checks the frame's parent `entry_point`/`delegate` state, not caller identity [6](#0-5) , and the `System` precompile's `terminate` call forwards to `terminate_caller` unconditionally for any caller [7](#0-6) . The fixture contract `MultiContributorStorage.sol` reflects this: `terminate(address beneficiary)` has no access modifier at all [8](#0-7) .

Exploit flow:
1. Account A calls `growStorage()` on the shared contract → `NativeDepositOf[contract][A]` becomes nonzero via `record_native_deposit`/native fallback charge.
2. Account B calls `growStorage()` in a separate transaction → `NativeDepositOf[contract][B]` becomes nonzero.
3. Either A or B (unprivileged, no special permission required) signs and submits a transaction calling `terminate(beneficiary)`. `do_terminate` → `refund_all` pays the *entire* `balance_on_hold` (A's + B's contributions) to the calling account's own address (`origin.account_id()`), not split by `NativeDepositOf` entries.

The repository's own test confirms this exact outcome is reproducible and observed: `refund_all_drains_multi_contributor_native_hold` shows ALICE growing storage, CHARLIE growing storage, and ALICE (the tx origin for `terminate`) receiving a balance delta `>= native_held` — i.e., her own contribution *plus* CHARLIE's — even though the specified `beneficiary` was a third account (DJANGO) [9](#0-8) .

### Impact Explanation
An unprivileged contributor to a shared contract's storage deposit can, by simply being the one to call `terminate`, receive another unrelated contributor's `NativeDepositOf` entry entirely — i.e., steal another user's deposited native funds. The amount at risk is bounded only by `balance_on_hold(StorageDepositReserve, contract)`, which can include many contributors' cumulative deposits.

### Likelihood Explanation
Preconditions are trivial and match ordinary usage: any contract whose storage-writing entry points are payable by multiple distinct signed callers (a common pattern — shared registries, multi-user state, etc.) accumulates multiple `NativeDepositOf` rows for the same holder. Termination is reachable by any account able to invoke the contract's terminate path (no ownership check enforced by the pallet), so the race to be "the terminator" is fully attacker-controlled and repeatable across any such contract.

### Recommendation
Either (a) restrict `refund_all`'s payout to the current caller's own `NativeDepositOf` share and refund remaining contributors proportionally/individually (iterating `NativeDepositOf::iter_prefix(contract)` and paying each contributor their own capped amount before/at termination), or (b) explicitly document and gate this behavior so it cannot be triggered by an arbitrary unprivileged contributor — e.g., require termination to be restricted to a single deposit owner, or make `refund_all` split the hold pro-rata across all `NativeDepositOf` rows for that holder rather than paying it all to `origin`.

### Proof of Concept
Reuse and extend the existing test `refund_all_drains_multi_contributor_native_hold` in `substrate/frame/revive/src/tests/deposit_payment.rs`:
1. ALICE and CHARLIE each call `growStorage()` in separate signed extrinsics on `MultiContributorStorage`; record `alice_entry = NativeDepositOf::<Test>::get(&account_id, &ALICE)` and `charlie_entry = NativeDepositOf::<Test>::get(&account_id, &CHARLIE)`, both nonzero.
2. Record `charlie_before = Balances::balance(&CHARLIE)`.
3. Have ALICE (not CHARLIE) sign and submit `terminate(beneficiary=DJANGO)`.
4. Assert `Balances::balance(&CHARLIE) == charlie_before` (CHARLIE receives nothing) while `Balances::balance(&ALICE) - alice_before >= alice_entry + charlie_entry` (ALICE receives her own deposit plus CHARLIE's).
5. This demonstrates the invariant violation: a contributor's refund exceeds their own `NativeDepositOf` entry, at the expense of another contributor who received zero of their recorded deposit back.

	/// Refunds the full native hold to `dst` ignoring the per-contributor cap, then settles the
	/// PGAS hold via [`Self::settle_pgas_refund`] (refunding `RefundPercent` to `dst` and burning
	/// the rest). The native cap only makes sense for partial refunds on a live contract; at
	/// termination there is one recipient and the contract is gone.
	///
	/// Note: callers must run inside a storage layer so partial state rolls back on error.
	fn refund_all(
		from: &T::AccountId,
		dst: Funds<T::AccountId>,
	) -> Result<BalanceOf<T>, DispatchError> {
		let to = match &dst {
			Funds::Balance(to) | Funds::TxFee(to) => *to,
		};
		let native = <() as Deposit<T>>::refund_all(from, dst)?;
		let reason = HoldReason::StorageDepositReserve;

		let pgas = Self::pgas_on_hold(reason, from);
		let pgas = Self::settle_pgas_refund(reason, from, to, pgas)?;
		Ok(native.saturating_add(pgas))
	}

	fn terminate_caller(&mut self, beneficiary: &H160) -> Result<(), DispatchError> {
		ensure!(self.top_frame().delegate.is_none(), Error::<T>::PrecompileDelegateDenied);
		let parent = self.frames_mut().nth(1).ok_or_else(|| Error::<T>::ContractNotFound)?;
		ensure!(parent.entry_point == ExportedFunction::Call, Error::<T>::TerminatedInConstructor);
		ensure!(parent.delegate.is_none(), Error::<T>::PrecompileDelegateDenied);

		let info = parent.contract_info();
		let trie_id = info.trie_id.clone();
		let code_hash = info.code_hash;
		let contract_address = T::AddressMapper::to_address(&parent.account_id);
		let beneficiary = T::AddressMapper::to_account_id(beneficiary);

		let parent_account_id = parent.account_id.clone();

		// balance transfer is immediate
		Self::transfer(
			&self.origin,
			&parent_account_id,
			&beneficiary,
			<Contracts<T>>::evm_balance(&contract_address),
			Preservation::Preserve,
			&mut top_frame_mut!(self).frame_meter,
			&self.exec_config,
		)?;

		// schedule for delayed deletion
		let args = TerminateArgs { beneficiary, trie_id, code_hash, only_if_same_tx: false };
		self.top_frame_mut().contracts_to_be_destroyed.insert(parent_account_id, args);

		Ok(())
	}

/// A contract whose storage was paid for by two different signers, both via the native
/// fallback path, can still be terminated. [`Deposit::refund_all`] bypasses the per-payer
/// [`NativeDepositOf`] cap (one recipient at termination, contract gone), so the full native
/// hold goes to the terminator and any PGAS hold is settled via `settle_pgas_refund`.
#[test_case(FixtureType::Solc)]
#[test_case(FixtureType::Resolc)]
fn refund_all_drains_multi_contributor_native_hold(fixture_type: FixtureType) {
	let (code, _) = compile_module_with_type("MultiContributorStorage", fixture_type).unwrap();
	ExtBuilder::default().build().execute_with(|| {
		Balances::set_balance(&ALICE, 100_000_000_000);
		Balances::set_balance(&CHARLIE, 100_000_000_000);

		let Contract { addr, account_id } =
			builder::bare_instantiate(Code::Upload(code)).build_and_unwrap_contract();

		assert_ok!(
			builder::bare_call(addr)
				.data(MultiContributorStorage::growStorageCall {}.abi_encode())
				.build()
				.result,
		);
		assert_ok!(
			BareCallBuilder::<Test>::bare_call(RuntimeOrigin::signed(CHARLIE), addr)
				.data(MultiContributorStorage::growStorageCall {}.abi_encode())
				.build()
				.result,
		);

		let alice_entry = NativeDepositOf::<Test>::get(&account_id, &ALICE);
		let charlie_entry = NativeDepositOf::<Test>::get(&account_id, &CHARLIE);
		assert!(alice_entry > 0);
		assert!(charlie_entry > 0);

		let hold: <Test as Config>::RuntimeHoldReason = HoldReason::StorageDepositReserve.into();
		let native_held = Balances::balance_on_hold(&hold, &account_id);
		let pgas_held = AssetsHolder::balance_on_hold(PGAS_ASSET_ID, &hold, &account_id);
		assert_eq!(pgas_held, 0, "every charge fell back to native");
		assert_eq!(native_held, alice_entry + charlie_entry);

		let alice_before = Balances::balance(&ALICE);
		assert_ok!(
			builder::bare_call(addr)
				.data(
					MultiContributorStorage::terminateCall { beneficiary: DJANGO_ADDR.0.into() }
						.abi_encode(),
				)
				.build()
				.result,
		);
		let alice_after = Balances::balance(&ALICE);

		assert!(get_contract_checked(&addr).is_none(), "contract should be gone");
		assert_eq!(
			Balances::balance_on_hold(&hold, &account_id),
			0,
			"the full multi-contributor native hold has been released",
		);
		// ALICE receives the full storage-deposit hold (her own + CHARLIE's). The actual delta
		// also picks up the code-upload deposit refund and any tx-level deposit accounting,
		// so it is at least `native_held`.
		assert!(
			alice_after.saturating_sub(alice_before) >= native_held,
			"expected ALICE balance delta >= {}, got {}",
			native_held,
			alice_after.saturating_sub(alice_before),
		);
	});
}
