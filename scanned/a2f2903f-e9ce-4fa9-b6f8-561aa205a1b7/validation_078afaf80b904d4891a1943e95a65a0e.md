### Title
Silent, permanent loss of issuance-based payouts when `elapsed` exceeds `MaxElapsedPerDrip` in `pallet-dap::drip_issuance` - (File: `substrate/frame/dap/src/lib.rs`)

### Summary
`pallet-dap`'s regular issuance drip (`drip_issuance`) computes the amount to mint from `elapsed = now - LastIssuanceTimestamp`, then clamps `elapsed` to `MaxElapsedPerDrip` if it is too large, mints only for the clamped window, but unconditionally advances `LastIssuanceTimestamp` to `now`. The excess time beyond the ceiling is never minted and never carried over, so the inflation/reward budget intended for that window is permanently and silently lost. This is the same accounting pattern as the Autonolas H‑04 finding: an amount is implicitly "reserved"/expected for a period, but a hard cap enforced at mint time causes part of it to be dropped without reverting or reconciling, harming payout recipients.

### Finding Description
`drip_issuance` in `substrate/frame/dap/src/lib.rs` computes: [1](#0-0) 

Specifically:
- `elapsed = now.saturating_sub(last)` is computed from the last drip timestamp.
- If `elapsed > T::MaxElapsedPerDrip::get()`, the pallet emits `ElapsedClamped` and sets `elapsed = max_elapsed`.
- `LastIssuanceTimestamp` is then unconditionally set to `now` (not `last + max_elapsed`), and `mint_and_distribute(elapsed)` mints only for the clamped duration. [2](#0-1) 

The `MaxElapsedPerDrip` config doc frames this as a "safety ceiling ... Prevents accidental over-minting", but it has no compensating carry-over mechanism: [3](#0-2) 

This means any time beyond the ceiling (e.g. from a period of no blocks, chain stall, or long maintenance window) is simply thrown away — the corresponding issuance that `IssuanceCurve` would have minted for that window (and would have been distributed to stakers/validators/budget recipients via `mint_and_distribute`) never gets minted, ever.

This is structurally identical to the Autonolas H‑04 bug: an expected/implied amount (issuance for the full elapsed window) does not match what is actually mintable under a hard boundary/cap (`MaxElapsedPerDrip`), and the difference is silently dropped rather than reverted, deferred, or accounted for elsewhere. Notably, the polkadot-sdk team already identified and fixed exactly this failure mode for the **migration** path (`InnerMigrateV1ToV2`), as documented in `prdoc/stable2606/pr_11809.prdoc`: [4](#0-3) 

The migration fix performs a proper one-shot "catch-up" drip over the full `[last_inflation, now]` window (bounded only by a one-shot ceiling `M`, not `MaxElapsedPerDrip`): [5](#0-4) 

However, the regular, ongoing `drip_issuance` path retains the same unfixed drop-and-jump pattern: it clamps `elapsed`, mints only the clamped amount, and then jumps `LastIssuanceTimestamp` straight to `now`, discarding the remainder with no catch-up.

### Impact Explanation
Any gap between successive `drip_issuance` calls that exceeds `MaxElapsedPerDrip` (e.g. due to a parachain stall, missed blocks, degraded liveness, or a runtime upgrade/pause) results in permanent, silent loss of the issuance that should have been minted and distributed to `BudgetRecipients` (staker rewards, validator incentives, treasury, etc., depending on runtime wiring) for the un-covered portion of elapsed time. Unlike the migration path, there is no reconciliation — the lost inflation is gone forever once `LastIssuanceTimestamp` advances to `now`. This directly reduces payouts to stakers/validators/other budget recipients relying on `pallet-dap` for rewards, mirroring the "lost payouts" impact in the original report.

### Likelihood Explanation
This is not attacker-triggerable by a normal unprivileged extrinsic call; it requires a period where `on_initialize` (and hence `drip_issuance`) is not invoked frequently enough, i.e., a block-production gap larger than `MaxElapsedPerDrip`. Such gaps can occur from network-level liveness issues, congestion, or misconfiguration of `MaxElapsedPerDrip`/`IssuanceCadence`, rather than from a deliberate user action. This weakens the "attacker-controlled entry path" requirement relative to a directly user-exploitable bug, and the polkadot-sdk team's decision to add a `MaxElapsedPerDrip` ceiling in the first place (per the doc comment) suggests intentional trade-off against over-minting — but the docstring only mentions preventing "over-minting," not the actual effect of causing "under-minting"/permanent reward loss, and the parallel bug was already treated as a real issue worth fixing for the migration path. Given that the disqualification criteria call for a "reachable attacker-controlled entry path" for an "unprivileged user," this issue is a systemic/liveness-triggered accounting bug rather than a directly exploitable one.

### Recommendation
Apply the same fix pattern used in `MigrateV1ToV2` to the regular `drip_issuance` path: when clamping `elapsed` to `MaxElapsedPerDrip`, advance `LastIssuanceTimestamp` only by the clamped amount (`last + max_elapsed`) instead of jumping to `now`, so the un-minted remainder is retained and credited on a subsequent drip rather than being permanently discarded.

### Proof of Concept
1. Configure a runtime with `pallet-dap`, `IssuanceCadence = X`, `MaxElapsedPerDrip = Y` (`Y > X`).
2. Simulate a block-production gap so that between two consecutive `on_initialize` calls, `now - LastIssuanceTimestamp = Y + Δ` (`Δ > 0`), e.g. via a parachain stall or by directly manipulating the mock `Time` provider in tests as done in `substrate/frame/dap/src/tests/drip.rs`.
3. Observe `drip_issuance` clamps `elapsed` to `Y`, mints/distributes only the issuance for `Y`, emits `ElapsedClamped`, and sets `LastIssuanceTimestamp = now`.
4. Verify via `Currency::total_issuance()` deltas that the `Δ`-sized portion of issuance is never minted on this or any future drip — confirming the permanent loss, in contrast to the reconciled migration path in `substrate/frame/dap/src/migrations.rs`. [1](#0-0)

		pub(crate) fn drip_issuance() -> Weight {
			let now_moment = T::Time::now();
			let now: u64 = now_moment.saturated_into();
			let last = LastIssuanceTimestamp::<T>::get();
			let mut elapsed = now.saturating_sub(last);

			let cadence = T::IssuanceCadence::get();
			if cadence > 0 && elapsed < cadence {
				return T::DbWeight::get().reads(2);
			}

			// First block after genesis: initialize timestamp, don't drip.
			// For existing chains, use `migrations::MigrateV1ToV2` to seed this
			// value from ActiveEra.start so this branch is never hit post-upgrade.
			if last == 0 {
				LastIssuanceTimestamp::<T>::put(now);
				return T::DbWeight::get().reads_writes(2, 2);
			}

			// Apply safety ceiling on elapsed time.
			let max_elapsed = T::MaxElapsedPerDrip::get();
			if elapsed > max_elapsed {
				Self::deposit_event(Event::Unexpected(UnexpectedKind::ElapsedClamped {
					actual_elapsed: elapsed,
					ceiling: max_elapsed,
				}));
				elapsed = max_elapsed;
			}

			// Always advance the clock so elapsed time doesn't accumulate across skipped drips.
			LastIssuanceTimestamp::<T>::put(now);

			let _ = Self::mint_and_distribute(elapsed);
			T::WeightInfo::drip_issuance()
		}
