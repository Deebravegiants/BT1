## Analog Vulnerability Found

### Title
Missing Event Emission for Critical Staking Configuration Updates - (File: `substrate/frame/staking/src/pallet/mod.rs` and `substrate/frame/staking-async/src/pallet/mod.rs`)

### Summary
Both `pallet-staking` and `pallet-staking-async` define a rich `Event<T>` enum used to log changes to important state (bonding, slashing, era changes, validator preferences, etc.), but the `set_staking_configs` and `set_invulnerables` extrinsics — which mutate the most security-sensitive risk parameters in the staking system — silently update storage without depositing any corresponding event. This mirrors the reported `MarginCalculator` pattern exactly: events exist for other state changes, but the functions that alter the parameters governing permissionless/protective logic (`ChillThreshold`, bond minimums, count caps, commission floor) never emit them.

### Finding Description
`set_staking_configs` in `pallet-staking` uses `ConfigOp` semantics to set or remove `MinNominatorBond`, `MinValidatorBond`, `MaxNominatorsCount`, `MaxValidatorsCount`, `ChillThreshold`, `MinCommission`, and `MaxStakedRewards`, then returns `Ok(())` with no `Self::deposit_event(...)` call at all: [1](#0-0) 

The same absence of an emitted event exists in the `staking-async` pallet's equivalent call, which additionally sets `AreNominatorsSlashable` and `ChillInactiveThreshold`: [2](#0-1) 

`set_invulnerables`, which overwrites the list of stashes exempt from slashing, has the identical problem — it stores the new list via `<Invulnerables<T>>::put(invulnerables)` with no event deposited: [3](#0-2) 

Meanwhile, the pallet's `Event<T>` enum demonstrates that other, arguably less consequential state changes (e.g. `ForceEra`, `ValidatorPrefsSet`) are properly logged, underscoring the inconsistency: [4](#0-3) 

These silently-updated parameters are read by `chill_other`, a permissionless extrinsic any signed account can call to forcibly chill another validator/nominator once the configured `ChillThreshold`, `MaxNominatorsCount`/`MaxValidatorsCount`, and `MinNominatorBond`/`MinValidatorBond` conditions are met: [5](#0-4) 

Because no event is emitted when these thresholds change, off-chain monitoring tools, block explorers, and affected stakers have no on-chain signal that the eligibility conditions for `chill_other` (or the bond minimums enforced elsewhere) were just altered — directly analogous to the `spotShock` scenario in the original report, where the lack of a `SpotShockUpdated` event let a parameter change affecting permissionless liquidation-like actions go unnoticed.

### Impact Explanation
If `ChillThreshold`, `MinNominatorBond`, `MinValidatorBond`, or the max count parameters are changed (via governance/root, which is the same "owner" trust level as the original `MarginCalculator` `spotShock` setter), any nominator or validator whose stake now falls under the new threshold becomes immediately callable by `chill_other` from any unprivileged signed account. Because the parameter change itself emits no event, affected stakers have no automated way to detect the change and top up their bond before being force-chilled, losing their active nominating/validating status and associated rewards eligibility. This is a data-validation/observability gap with real operational consequences for unprivileged stakers, even though the root cause is a privileged parameter update.

### Likelihood Explanation
`set_staking_configs` and `set_invulnerables` are legitimate, expected governance operations that are exercised periodically to tune network-wide bonding/slashing parameters, so the code path is regularly reachable in production — it is not a hypothetical or dead code path. The missing event is deterministic (100% of calls, not just malicious ones, are unlogged), so any legitimate parameter tuning also produces this transparency gap, making the likelihood of the observability failure occurring high, while the resulting `chill_other` exploitation window depends on stake sizes and does not require any additional privilege beyond a normal signed account.

### Recommendation
- Short term: Emit an event (e.g. `StakingConfigsChanged { min_nominator_bond, min_validator_bond, max_nominator_count, max_validator_count, chill_threshold, min_commission, max_staked_rewards, .. }` for `pallet-staking`/`pallet-staking-async`, and `InvulnerablesSet { invulnerables }` for `set_invulnerables`) so that every change to these parameters is logged on-chain and consumable by off-chain monitoring.
- Long term: Add test coverage (as already flagged for related events, e.g. `pallet-bags-list`'s `ScoreUpdated` follow-up: [6](#0-5) ) asserting that all root/governance-gated configuration-mutating extrinsics across FRAME pallets deposit an event reflecting the change, and audit other pallets with `ConfigOp`-style bulk setters for the same omission.

### Proof of Concept
1. Governance/root calls `Staking::set_staking_configs(Root, ConfigOp::Set(new_lower_min_nominator_bond), ConfigOp::Noop, ConfigOp::Noop, ConfigOp::Noop, ConfigOp::Set(new_chill_threshold), ConfigOp::Noop, ConfigOp::Noop)` as defined at `substrate/frame/staking/src/pallet/mod.rs:1897-1927`.
2. Storage items `MinNominatorBond` and `ChillThreshold` are updated via `config_op_exp!` macro calls to `put`, but no event is deposited — inspecting the emitted events for that block shows nothing related to the config change.
3. Any signed account can now call `Staking::chill_other(origin, target_stash)` (`substrate/frame/staking/src/pallet/mod.rs:1954-2017`) against nominators who satisfy the new (lowered) threshold, since the threshold check at line 1989 (`ChillThreshold::<T>::get()`) reads the newly-set, unannounced value.
4. Because there is no `Event` to alert them, affected nominators had no on-chain notification to increase their bond or otherwise react before being chilled.

		#[pallet::call_index(23)]
		#[pallet::weight(T::WeightInfo::chill_other())]
		pub fn chill_other(origin: OriginFor<T>, stash: T::AccountId) -> DispatchResult {
			// Anyone can call this function.
			let caller = ensure_signed(origin)?;
			let ledger = Self::ledger(Stash(stash.clone()))?;
			let controller = ledger
				.controller()
				.defensive_proof(
					"Ledger's controller field didn't exist. The controller should have been fetched using StakingLedger.",
				)
				.ok_or(Error::<T>::NotController)?;

			// In order for one user to chill another user, the following conditions must be met:
			//
			// * `controller` belongs to a nominator who has become non-decodable,
			//
			// Or
			//
			// * A `ChillThreshold` is set which defines how close to the max nominators or
			//   validators we must reach before users can start chilling one-another.
			// * A `MaxNominatorCount` and `MaxValidatorCount` which is used to determine how close
			//   we are to the threshold.
			// * A `MinNominatorBond` and `MinValidatorBond` which is the final condition checked to
			//   determine this is a person that should be chilled because they have not met the
			//   threshold bond required.
			//
			// Otherwise, if caller is the same as the controller, this is just like `chill`.

			if Nominators::<T>::contains_key(&stash) && Nominators::<T>::get(&stash).is_none() {
				Self::chill_stash(&stash);
				return Ok(());
			}

			if caller != controller {
				let threshold = ChillThreshold::<T>::get().ok_or(Error::<T>::CannotChillOther)?;
				let min_active_bond = if Nominators::<T>::contains_key(&stash) {
					let max_nominator_count =
						MaxNominatorsCount::<T>::get().ok_or(Error::<T>::CannotChillOther)?;
					let current_nominator_count = Nominators::<T>::count();
					ensure!(
						threshold * max_nominator_count < current_nominator_count,
						Error::<T>::CannotChillOther
					);
					MinNominatorBond::<T>::get()
				} else if Validators::<T>::contains_key(&stash) {
					let max_validator_count =
						MaxValidatorsCount::<T>::get().ok_or(Error::<T>::CannotChillOther)?;
					let current_validator_count = Validators::<T>::count();
					ensure!(
						threshold * max_validator_count < current_validator_count,
						Error::<T>::CannotChillOther
					);
					MinValidatorBond::<T>::get()
				} else {
					Zero::zero()
				};

				ensure!(ledger.active < min_active_bond, Error::<T>::CannotChillOther);
			}

			Self::chill_stash(&stash);
			Ok(())
		}
