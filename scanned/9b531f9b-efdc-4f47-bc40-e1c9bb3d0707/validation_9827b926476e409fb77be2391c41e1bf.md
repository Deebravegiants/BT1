### Title
Vault node-side gateway handler logs the full JSON-RPC request — including the caller-supplied JWT `Auth` bearer token — to the node log at Debug level - ([File: core/capabilities/vault/gw_handler.go])

### Summary
`GatewayHandler.HandleGatewayMessage` in the node-side Vault capability logs the entire incoming `jsonrpc.Request[json.RawMessage]` object, unredacted, before any authorization/validation occurs. That request type carries the caller's `Auth` field, which the gateway/vault protocol uses to transport a JWT bearer token for JWT-based authorization (`Authorization: Bearer <token>` on the wire, forwarded into `req.Auth`, as seen in the test helpers that build these requests). This is directly analogous to CVE-2022-38663 (Jenkins Git Plugin), where a credential value was written to a log/output stream instead of being masked.

### Finding Description
In `core/capabilities/vault/gw_handler.go`: [1](#0-0) 

```go
func (h *GatewayHandler) requestLogger(req *jsonrpc.Request[json.RawMessage], gatewayID string) logger.Logger {
	return h.lggr.With("requestID", req.ID, "method", req.Method, "gatewayID", gatewayID)
}

func (h *GatewayHandler) HandleGatewayMessage(ctx context.Context, gatewayID string, req *jsonrpc.Request[json.RawMessage]) (err error) {
	reqLggr := h.requestLogger(req, gatewayID)
	reqLggr.Debugw("received message from gateway", "req", req)
```

`reqLggr.Debugw("received message from gateway", "req", req)` serializes the whole `jsonrpc.Request` struct — struct field logging via zap's structured logger typically reflects/marshals the entire value — as a single log field. The gateway/vault test helpers demonstrate that this request type carries a caller-supplied bearer token in an `Auth` field, extracted from an `Authorization: Bearer <token>` header on the wire and used for JWT-based authorization of unprivileged Vault callers: [2](#0-1) 

This `Auth`/JWT token is the credential that authorizes an unprivileged workflow-owner request to the Vault DON via the gateway (`AuthorizeRequest` in `core/capabilities/vault/gateway_vault_request_processor.go`, called from `authorizeAndStamp`): [3](#0-2) 

By contrast, the gateway-side vault handler (`core/services/gateway/handlers/vault/handler.go`/`handler_test.go`) explicitly tests and asserts that raw, sensitive request params/markers must **never** appear in any log field: [4](#0-3) 

This shows the project is aware of, and actively defends against, exactly this class of bug elsewhere — but the node-side `GatewayHandler.HandleGatewayMessage` in `core/capabilities/vault/gw_handler.go` has no equivalent redaction and dumps the raw request (including `Auth`) before authorization runs.

### Impact Explanation
If Debug-level logging is enabled on a Vault-capable node (a common operational/troubleshooting setting, and the same level the offending Jenkins log lived at), every incoming Vault gateway request — including its JWT bearer token used for authorization — is written verbatim into the node's log output. Anyone with read access to node logs (log aggregation systems, shared debug output, support tooling, etc.) could harvest live JWT tokens and replay them to impersonate the legitimate workflow owner against the Vault capability, i.e., request/impersonation and secret-disclosure-adjacent risk (CWE-522: Insufficiently Protected Credentials), matching the bug class of the reported advisory.

### Likelihood Explanation
The log line executes unconditionally on every gateway message received by the node's Vault handler, prior to any authorization check, so it fires for every unprivileged client-originated Vault request whenever the node logger is configured at Debug level for this component. No special conditions or attacker capability beyond normal request submission are needed to trigger the exposure; the only gating factor is the deployment's log level, which is an operational choice rather than a security control.

### Recommendation
Redact or omit the `Auth`/JWT token field before logging the request in `HandleGatewayMessage` (e.g., log only `req.ID`, `req.Method`, and `gatewayID`, or a scrubbed copy of `req` with `Auth` cleared), mirroring the pattern already enforced and tested in `core/services/gateway/handlers/vault/handler_test.go` (`TestVaultHandler_InvalidParamsDoesNotLogRawParams`). Apply the same scrub to any other debug/info log statements in this file that pass the full `req`/`response` objects (e.g., the `"Sent message to gateway", "resp", response"` line) to ensure no credential-bearing field is ever serialized into logs.

### Proof of Concept
1. Configure a Vault-capable node with `Debug` log level enabled for the `VaultHandler` logger (a supported, documented logging configuration).
2. As an unprivileged workflow owner, send any Vault gateway request (e.g., `MethodSecretsCreate`) through the gateway with `Authorization: Bearer <token>` set, per the flow exercised in `system-tests/tests/smoke/cre/vault_don_test_helpers.go` (`sendVaultJWTRequestToGatewayExpectError`/`sendConcurrentVaultCreate`).
3. Inspect the node's log output for the `"received message from gateway"` line emitted by `GatewayHandler.HandleGatewayMessage` — the JWT bearer token supplied in the request's `Auth` field appears in cleartext in the `"req"` field of the log entry, before any authorization decision is made.

*Note: I could not directly inspect the `jsonrpc.Request` struct definition (it lives in the external `chainlink-common` dependency, not indexed in this repo), so the exact serialized shape of the `Auth` field in the zap log line is inferred from its documented usage in the test helpers rather than from the struct source itself. A Devin session with full repo/dependency access could confirm the exact field name and zap serialization behavior.*

func (p *GatewayVaultRequestProcessor) authorizeAndStamp(
	ctx context.Context,
	req *jsonrpc.Request[json.RawMessage],
	stamp func(prefixedRequestID string) error,
) (*AuthorizedGatewayVaultRequest, error) {
	incomingOwner := ""
	if idx := strings.Index(req.ID, vaulttypes.RequestIDSeparator); idx != -1 {
		incomingOwner = req.ID[:idx]
	}

	p.lggr.Debugw("authorizing gateway vault request", "method", req.Method, "requestID", req.ID)
	authResult, err := p.authorizer.AuthorizeRequest(ctx, *req)
	if err != nil {
		authErr := fmt.Errorf("request not authorized: %w", err)
		p.lggr.Errorw("gateway vault request authorization failed", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "", "incomingOwner", incomingOwner, "error", authErr)
		return nil, authErr
	}
