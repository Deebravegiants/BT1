## Finding

Chainlink node's LOOP registry debug/pprof endpoints are mounted without any authentication middleware, unlike their sibling debug/metrics endpoints, letting any unauthenticated client trigger expensive CPU/heap profiling operations against the node — a direct analog of the lollms `/api/files/extract-text` bug class (endpoint missing the auth dependency present on siblings → unauthenticated resource-exhaustion DoS / info disclosure).

### Title
Unauthenticated LOOP plugin pprof/metrics endpoints allow resource-exhaustion DoS and info disclosure - (File: `core/web/loop_registry.go`, `core/web/router.go`)

### Summary
`loopRoutes` registers `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` on the `api` router group without any `auth.Authenticate(...)` wrapper, while the functionally equivalent `metricRoutes` (also debug endpoints) are explicitly mounted only inside the authenticated `authv2` group with the comment "Debug routes accessible via authentication."

### Finding Description
`NewRouter` builds a single unauthenticated `api` group and calls `loopRoutes(app, api)` directly, with no session/token/external-initiator auth methods applied: [1](#0-0) 

Compare this to `v2Routes`, where the same class of debug functionality (`metricRoutes`) is deliberately placed behind `authv2` — the authenticated group — with an explicit comment calling out that debug routes require authentication: [2](#0-1) 

`loopRoutes` itself registers the pprof/metrics handlers with no auth middleware argument at all: [3](#0-2) 

The `pluginPPROFHandler` forwards the request to the internal LOOP plugin's pprof endpoint and accepts a client-controlled `seconds` query parameter that directly sets how long a CPU profile capture (and thus the corresponding goroutine/timeout) runs, up to `PPROFOverheadSeconds` additional buffer: [4](#0-3) 

The handler proxies raw response bytes back to the caller without redaction, and `pluginMetricHandler`/`discoveryHandler` similarly expose internal plugin names, hostnames, and Prometheus scrape targets to any caller: [5](#0-4) [6](#0-5) 

### Impact Explanation
An unauthenticated remote client can:
- Trigger repeated/long-running CPU/heap profile captures against LOOP plugins by hitting `/plugins/:name/debug/pprof/*profile?seconds=N`, consuming node and plugin CPU/goroutines — resource-exhaustion DoS, mirroring the CVE's DoS impact.
- Enumerate internal plugin names, internal Prometheus ports/hostnames, and pprof/metrics data — information disclosure about the node's internal topology, mirroring the CVE's info-disclosure impact.
- This directly violates the pattern the codebase itself establishes elsewhere (debug endpoints require auth), so it is an inconsistency/bypass rather than an intentionally public endpoint.

### Likelihood Explanation
High: these routes require no credentials, no CORS restriction beyond default, and are reachable from any network client that can reach the node's web server port, exactly like the CVE's unauthenticated file endpoint.

### Recommendation
Wrap `loopRoutes` registration with the same `auth.Authenticate(...)` middleware (and appropriate role check) used for `metricRoutes`/`authv2`, or otherwise restrict these endpoints to trusted/internal callers (e.g., separate internal-only listener, IP allowlist) consistent with how the node treats other debug routes.

### Proof of Concept
```
# No credentials required:
curl "http://<node>:6688/discovery"
curl "http://<node>:6688/plugins/<plugin-name>/metrics"
curl "http://<node>:6688/plugins/<plugin-name>/debug/pprof/profile?seconds=60"
```
Repeated concurrent calls to the profile endpoint with a large `seconds` value can be used to hold node/plugin resources for extended periods without any authentication, unlike every other debug-oriented route in `core/web/router.go`. [1](#0-0) [3](#0-2) [2](#0-1) [4](#0-3)

// discoveryHandler implements service discovery of prom endpoints for LOOPs in the registry
func (l *LoopRegistryServer) discoveryHandler(w http.ResponseWriter, req *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	groups := make([]*targetgroup.Group, 0, 1+len(l.registry.List()))

	// add node metrics to service discovery
	groups = append(groups, pluginGroup(l.discoveryHostName, l.exposedPromPort, "/metrics"))

	// add all the plugins
	for _, registeredPlugin := range l.registry.List() {
		group := pluginGroup(l.discoveryHostName, l.exposedPromPort, pluginMetricPath(registeredPlugin.Name))
		group.Labels[LabelMetaPluginName] = model.LabelValue(registeredPlugin.Name)
		groups = append(groups, group)
	}

	b, err := l.jsonMarshalFn(groups)
	if err != nil {
		w.WriteHeader(http.StatusInternalServerError)
		_, err = w.Write([]byte(err.Error()))
		if err != nil {
			l.logger.Error(err)
		}
		return
	}
	_, err = w.Write(b)
	if err != nil {
		w.WriteHeader(http.StatusInternalServerError)
		l.logger.Error(err)
	}
}

func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/metrics", l.loopHostName, p.EnvCfg.PrometheusPort)
	req, err := http.NewRequestWithContext(gc.Request.Context(), http.MethodGet, pluginURL, nil)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)
	if err != nil {
		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q metrics", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}

const PPROFOverheadSeconds = 30

func pprofURLVals(gc *gin.Context) (urlVals url.Values, timeout time.Duration) {
	urlVals = make(url.Values)
	if db, ok := gc.GetQuery("debug"); ok {
		urlVals.Set("debug", db)
	}
	if gc, ok := gc.GetQuery("gc"); ok {
		urlVals.Set("gc", gc)
	}
	timeout = PPROFOverheadSeconds * time.Second
	if sec, ok := gc.GetQuery("seconds"); ok {
		urlVals.Set("seconds", sec)
		if i, err := strconv.Atoi(sec); err == nil {
			timeout = time.Duration(i+PPROFOverheadSeconds) * time.Second
		}
	}
	return urlVals, timeout
}

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
