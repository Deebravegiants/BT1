### Title
Unauthenticated Health/Readiness Endpoints Leak Internal Error Details - (File: core/web/health_controller.go)

### Summary
The Monstra CVE describes a custom error page that discloses internal server details (PATH, DOCUMENT_ROOT, SERVER_ADMIN) to any unauthenticated visitor. The chainlink node has an analogous class of bug: the unauthenticated `/health`, `/health.txt`, and `/readyz?full` HTTP endpoints return the raw `.Error()` strings of internal health-check failures to any unprivileged caller.

### Finding Description
`healthRoutes` mounts `Health`, `Readyz`, `PublicReadyz`, and `/health.txt` on the top-level router group `r`, which only has rate limiting and session middleware applied — no `auth.Authenticate(...)` gate is present for these routes [1](#0-0) , compared to almost every other `/v2/*` route which requires `auth.Authenticate` with token/session credentials [2](#0-1) .

`HealthController.Readyz` returns detailed per-check `Output: err.Error()` for every failing internal health check whenever the caller passes `?full`, without any authentication requirement [3](#0-2) . Similarly, `HealthController.Health` always populates `Output: err.Error()` for failing checks and serves them in JSON, HTML, or plaintext depending on `Accept`/`Negotiate` — again reachable without authentication [4](#0-3) .

Only `PublicReadyz` was hardened to strip details ("never returns per-check details ... to avoid leaking internal service state on publicly reachable endpoints") [5](#0-4) , implying the project itself recognized `Readyz`/`Health` as sources of internal-state leakage but did not remove the unauthenticated `full`/error-detail paths from `Readyz` and `Health` themselves.

The content of `err.Error()` values in this context is determined by whatever internal `services.Checker` health checks register (e.g. DB, RPC, keystore, relayer service checks) — these error strings commonly embed internal identifiers, chain/RPC endpoint info, or other backend state that should not be exposed pre-authentication.

### Impact Explanation
An unauthenticated, unprivileged network client can call `GET /health`, `GET /health.txt`, or `GET /readyz?full` and receive verbose error strings describing why internal subsystems are failing. This is a direct analog of the CVE's information-leakage bug class (exposing internal implementation/environment details to any visitor), and can aid reconnaissance for further attacks (e.g., identifying misconfigured RPC endpoints, DB issues, or internal service names) without needing valid session/API credentials.

### Likelihood Explanation
Any client capable of reaching the node's web server (which is internet-facing on many deployments) can trigger this without authentication — no special role or session is required, matching the "unprivileged actor" and "internet-facing gateway" scope of this scan.

### Recommendation
Apply the same treatment already used for `PublicReadyz` to `Health`/`Readyz`: strip or redact `Output`/error detail fields from responses served without authentication, or require `auth.Authenticate` on `/health` (full) and `/readyz?full` while keeping a minimal public boolean-status endpoint (as `PublicReadyz` already provides) for load balancers.

### Proof of Concept
1. Without any session cookie or API token, send `GET /readyz?full` to a running chainlink node.
2. Observe the JSON response includes `checks[].output` containing raw internal error strings from failing health checks [6](#0-5) .
3. Alternatively, send `GET /health` or `GET /health.txt` unauthenticated and observe the same `Output` field populated with internal error text [7](#0-6) .

```go
// PublicReadyz is a minimal readiness endpoint intended for public load balancer health checks.
// Unlike Readyz, it never returns per-check details regardless of query parameters, to avoid
// leaking internal service state on publicly reachable endpoints.
func (hc *HealthController) PublicReadyz(c *gin.Context) {
	ready, _ := hc.App.GetHealthChecker().IsReady()
	if !ready {
		c.Status(http.StatusServiceUnavailable)
		return
	}
	c.Status(http.StatusOK)
}
```

```go
func (hc *HealthController) Readyz(c *gin.Context) {
	status := http.StatusOK

	checker := hc.App.GetHealthChecker()

	ready, errors := checker.IsReady()

	if !ready {
		status = http.StatusServiceUnavailable
	}

	c.Status(status)

	if _, ok := c.GetQuery("full"); !ok {
		return
	}

	checks := make([]presenters.Check, 0, len(errors))

	for name, err := range errors {
		status := HealthStatusPassing
		var output string

		if err != nil {
			status = HealthStatusFailing
			output = err.Error()
		}

		checks = append(checks, presenters.Check{
			JAID:   presenters.NewJAID(name),
			Name:   name,
			Status: status,
			Output: output,
		})
	}

	// return a json description of all the checks
	jsonAPIResponse(c, checks, "checks")
```

```go
func (hc *HealthController) Health(c *gin.Context) {
	_, failing := c.GetQuery("failing")

	status := http.StatusOK

	checker := hc.App.GetHealthChecker()

	healthy, errors := checker.IsHealthy()

	if !healthy {
		status = http.StatusMultiStatus
	}

	c.Status(status)

	checks := make([]presenters.Check, 0, len(errors))
	for name, err := range errors {
		status := HealthStatusPassing
		var output string

		if err != nil {
			status = HealthStatusFailing
			output = err.Error()
		} else if failing {
			continue // omit from returned data
		}

		checks = append(checks, presenters.Check{
			JAID:   presenters.NewJAID(name),
			Name:   name,
			Status: status,
			Output: output,
		})
	}

	switch c.NegotiateFormat(gin.MIMEJSON, gin.MIMEHTML, gin.MIMEPlain) {
	case gin.MIMEJSON:
		break // default

	case gin.MIMEHTML:
		if err := newCheckTree(checks).WriteHTMLTo(c.Writer); err != nil {
			hc.App.GetLogger().Errorw("Failed to write HTML health report", "err", err)
			c.AbortWithStatus(http.StatusInternalServerError)
		}
		return

	case gin.MIMEPlain:
		if err := writeTextTo(c.Writer, checks); err != nil {
			hc.App.GetLogger().Errorw("Failed to write plaintext health report", "err", err)
			c.AbortWithStatus(http.StatusInternalServerError)
		}
		return
	}

	slices.SortFunc(checks, presenters.CmpCheckName)
	jsonAPIResponseWithStatus(c, checks, "checks", status)
}
```
