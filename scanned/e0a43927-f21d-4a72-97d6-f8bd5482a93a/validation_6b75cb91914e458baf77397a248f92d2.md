## Analysis

The Jenkins Consul KV Builder bug class is: **a secret credential is persisted in cleartext and returned unmasked to users who have access to the config/store**, so it can be read by principals who shouldn't be able to see it. The closest reachable analog in this repo is the Chainlink node's **External Initiator `OutgoingToken`**.

### Title
Cleartext storage and unrestricted disclosure of External Initiator `OutgoingToken` via `GET /v2/external_initiators` - (File: `core/web/router.go`, `core/web/presenters/external_initiators.go`)

### Summary
The `OutgoingToken` (and `OutgoingSecret`) used to authenticate the Chainlink node's outgoing webhook calls to a registered External Initiator is stored in plaintext in Postgres and is returned in full, unmasked, by the `GET /v2/external_initiators` endpoint to *any* authenticated user — including the lowest-privilege `View` role, which is not permitted to create, modify, or delete external initiators.

### Finding Description
`external_initiators.outgoing_token` and `outgoing_secret` are declared as plain `text` columns with no encryption at rest: [1](#0-0) 

The value is generated once at creation time via `utils.NewSecret` and stored as-is: [2](#0-1) 

The list/index endpoint `GET /v2/external_initiators` is registered under the authenticated group but is **not wrapped by any role-requiring middleware** (`RequiresEditRole`/`RequiresAdminRole`/`RequiresRunRole`), unlike the sibling `POST`/`DELETE` routes on the same resource which explicitly require Edit role: [3](#0-2) 

The handler serializes every stored external initiator, including the plaintext `OutgoingToken`, into the response resource with no redaction: [4](#0-3) 

The controller's `Index` action performs no additional authorization check before returning this data: [5](#0-4) 

This is confirmed by the project's own RBAC route table, which explicitly documents that `GET /v2/external_initiators` is `viewOnlyAllowed: true`, i.e., reachable by the `View` role: [6](#0-5)  and the corresponding test assertion that View-role sessions receive non-Unauthorized/Forbidden responses for this route: [7](#0-6) 

The end-to-end controller test confirms the field is actually populated on list responses, not just at creation: [8](#0-7) 

### Impact Explanation
`OutgoingToken` is the credential the Chainlink node presents to prove its identity to the external initiator when notifying it of new job runs. Any authenticated node user with only `View` role (the least-privileged authenticated role, intended for read-only dashboards) can retrieve this plaintext credential for every registered external initiator. An attacker who compromises or is granted only a low-privilege account can use the disclosed token to impersonate the node's outgoing calls to third-party external-initiator systems, potentially triggering unintended job-run notifications or spoofing traffic that the external system trusts as coming from the node. This satisfies the "key/secret disclosure" / "request impersonation" bug classes called out in scope.

### Likelihood Explanation
Likelihood is high for any Chainlink deployment that (a) uses External Initiators (a supported, documented feature gated only by `JobPipeline.ExternalInitiatorsEnabled`) and (b) provisions multiple users with different roles (View/Run/Edit/Admin), which is the standard multi-user RBAC model the node ships with. No special network position or privileged access is required beyond an ordinary authenticated View-role API session/token.

### Recommendation
- Restrict `GET /v2/external_initiators` (and the underlying `Index`) to at least `RequiresEditRole` (or `RequiresAdminRole`), consistent with the write operations on the same resource.
- Remove `OutgoingToken`/`OutgoingSecret` from the list/index presenter entirely, returning them only once at creation time (as is already done via `ExternalInitiatorAuthentication` in the `Create` response), or mask them in list responses.
- Consider storing `outgoing_secret`/`outgoing_token` encrypted at rest rather than as plaintext `text` columns.

### Proof of Concept
1. As an Admin, create an external initiator: `POST /v2/external_initiators {"name":"foo"}` — note the returned `outgoingToken`.
2. Create (or use) a low-privilege user/API token with `View` role only.
3. As the `View` user, call `GET /v2/external_initiators`.
4. Observe the response includes the same plaintext `outgoingToken` for `foo`, confirming disclosure to a role that has no create/update/delete rights over this resource: [9](#0-8)

func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}

	t.Parallel()
	app := cltest.NewApplicationEVMDisabled(t)
	require.NoError(t, app.Start(t.Context()))

	router := web.Router(t, app, nil)
	ts := httptest.NewServer(router)
	defer ts.Close()

	// Create a test run user to work with
	u := &cltest.User{Role: sessions.UserRoleView}
	client := app.NewHTTPClient(u)

	// Assert all view only routes
	for i, route := range routesRolesMap {
		t.Run(fmt.Sprintf("%d-%s-%s", i, route.verb, route.path), func(t *testing.T) {
			t.Parallel()
			var resp *http.Response
			var cleanup func()

			switch route.verb {
			case "GET":
				resp, cleanup = client.Get(route.path)
			case "POST":
				resp, cleanup = client.Post(route.path, nil)
			case "DELETE":
				resp, cleanup = client.Delete(route.path)
			case "PATCH":
				resp, cleanup = client.Patch(route.path, nil)
			case "PUT":
				resp, cleanup = client.Put(route.path, nil)
			default:
				t.Fatalf("Unknown HTTP verb %s\n", route.verb)
			}
			defer cleanup()

			// If this route only allows view only, don't expect an unauthorized response
			switch {
			case route.viewOnlyAllowed:
				assert.NotEqual(t, http.StatusUnauthorized, resp.StatusCode)
				assert.NotEqual(t, http.StatusForbidden, resp.StatusCode)
			case !route.EditAllowed:
				assert.Equal(t, http.StatusForbidden, resp.StatusCode)
			default:
				assert.Equal(t, http.StatusUnauthorized, resp.StatusCode)
			}
		})
	}
}
