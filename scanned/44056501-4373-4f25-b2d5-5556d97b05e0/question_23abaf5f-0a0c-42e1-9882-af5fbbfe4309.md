Target: `GraphqlProxy.proxy_query` and `Context.private?` guard. Attacker action: sends a proxy request while the host app happens to be misconfigured as private (`Context.private?` true) using a *public*-app-issued session id that still resolves to a real online session object. Preconditions: mixed private/public configuration drift in the host app (a documented but easy misconfiguration). Call sequence: `raise Errors::PrivateAppError` fires only on the `Context.private?` flag, independent of whether the supplied `session` itself is a legitimately-scoped one; the check is a global mode flag, not a per-session credential check. Binding that breaks: the mode-flag state (`Context.private?`) == the actual security model under which `session`'s access token was issued; the two can drift without the gem detecting it. Scoped impact: High, scope/config-check bypass class of issue if `Context.private?` is toggled at runtime between requests. Proof idea: minitest toggling `Context.private = true/false` between two `proxy_query` calls with the same session, asserting the guard is purely global-state-driven and not session-derived.
