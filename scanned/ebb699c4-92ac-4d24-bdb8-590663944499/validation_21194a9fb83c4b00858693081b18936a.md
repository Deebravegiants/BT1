This is a very interesting finding. In `core/capabilities/vault/gw_handler.go`, `HandleGatewayMessage` logs the raw incoming request at debug level before authorization, and the individual handlers log the request payload with `.String()` at debug level after unmarshaling attacker-controlled JSON.

### Title
Vault gateway handler logs unencrypted secrets and ciphertext material at debug level from unprivileged/unauthenticated gateway requests - ([File: core/capabilities/vault/gw_handler.go])

### Summary
`GatewayHandler.HandleGatewayMessage` in `core/capabilities/vault/gw_handler.go` logs the full incoming JSON-RPC request (`"req", req`) at `Debugw` level immediately upon receipt, before any authentication or authorization is performed. Additionally, `handleSecretsCreate`, `handleSecretsUpdate`, `handleSecretsDelete`, and `handleSecretsList` each log the parsed request body (`vaultCapRequest.String()` / `r.String()`) at debug level. These requests originate from the gateway, which forwards messages relayed from external, unprivileged workflow/DON callers over the internet-facing gateway.

### Finding Description [1](#0-0)  shows the handler logging the raw request payload at debug level before the switch statement that performs authorization (`h.requestProcessor.ProcessRequest`). This mirrors the goreleaser bug class: sensitive request content is written to debug logs without redaction, and the write happens on a path reachable by an external, less-trusted actor (a workflow/DON participant submitting a request through the gateway) rather than by the node operator.

The subsequent handlers reinforce this: `handleSecretsCreate` [2](#0-1) , `handleSecretsUpdate` [3](#0-2) , `handleSecretsDelete` [4](#0-3) , and `handleSecretsList` [5](#0-4)  all call `.String()` on the deserialized vault-capability request/response types and pass it directly into `Debugw`. Unlike `core/web/router.go`, which explicitly redacts password-like fields before logging request bodies (`isBlacklisted`, `readSanitizedJSON`) [6](#0-5) , there is no equivalent redaction applied to the vault request/response `.String()` output. Whether `CreateSecretsRequest.String()` / `UpdateSecretsRequest.String()` actually include plaintext secret values or only ciphertext (TDH2-encrypted payloads) could not be fully confirmed from the code I retrieved — the vault capability is designed around encrypted secrets, so the practical severity depends on whether `.String()` for these proto-generated types includes the raw encrypted blob, associated owner/identifier metadata, or (in an implementation bug) plaintext.

### Impact Explanation
If a node operator runs with `Log.Level = 'debug'` (a supported, documented configuration, not `--debug` per se, but functionally analogous to goreleaser's `--debug`), every vault create/update/delete/list request relayed through the gateway — including from workflow authors who are not node operators — gets written into the node's logs. At minimum, this leaks metadata (owner IDs, secret identifiers, request IDs) about which secrets exist and who created them, aiding credential/secret enumeration. If any field within these request/response `.String()` representations carries plaintext prior to encryption (or if update/create payloads include ciphertext that could be replayed), a lower-privileged actor's data ends up in operator-accessible logs unexpectedly, and could be exposed via log aggregation, support bundles, or shared debugging output — precisely the harm class described in CVE-2024-23840.

### Likelihood Explanation
The unauthenticated logging line at `HandleGatewayMessage` line 182 executes for every gateway-forwarded message before authorization, so it is reachable by any external caller able to reach the gateway (moderate likelihood, gated only by whether the node runs at debug log level, which is common during troubleshooting). The per-handler debug logs execute only after successful authorization, reducing likelihood somewhat, but they still capture request content originating from the external workflow author rather than the node operator.

### Recommendation
Apply the same redaction discipline used in `core/web/router.go` (`isBlacklisted`/`readSanitizedJSON`) to gateway-bound debug logging in `core/capabilities/vault/gw_handler.go`: avoid logging the raw `req` object in `HandleGatewayMessage`, and replace `.String()` calls in `handleSecretsCreate`/`handleSecretsUpdate`/`handleSecretsDelete`/`handleSecretsList` with a sanitized summary (e.g., only method, owner, and identifiers — never ciphertext or full payload) before passing to `Debugw`.

### Proof of Concept
1. Configure a node with `Log.Level = 'debug'` and connect it to a gateway with the Vault capability enabled.
2. As an unprivileged workflow author (not a node operator), submit a `secrets_create`/`secrets_update` request through the gateway targeting the node.
3. Inspect the node's debug logs: observe the `"received message from gateway"` line at `gw_handler.go:182` containing the full raw request, and the `"Processing authorized create secrets request"` line at `gw_handler.go:281` containing `vaultCapRequest.String()`.
4. Confirm that request metadata/content submitted by the unprivileged caller is now present in node-operator-accessible logs without redaction, unlike equivalent web-request logging in `router.go` which redacts password fields.

func (h *GatewayHandler) handleSecretsCreate(ctx context.Context, gatewayID string, req *jsonrpc.Request[json.RawMessage]) *jsonrpc.Response[json.RawMessage] {
	vaultCapRequest := vaultcommon.CreateSecretsRequest{}
	if err := json.Unmarshal(*req.Params, &vaultCapRequest); err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.UserMessageParseError, err)
	}

	h.lggr.Debugw("Processing authorized create secrets request", "request", vaultCapRequest.String())
	vaultCapResponse, err := h.secretsService.CreateSecrets(ctx, &vaultCapRequest)

func readSanitizedJSON(buf *bytes.Buffer) (string, error) {
	var dst map[string]any
	err := json.Unmarshal(buf.Bytes(), &dst)
	if err != nil {
		return "", err
	}

	cleaned := map[string]any{}
	for k, v := range dst {
		if isBlacklisted(k) {
			cleaned[k] = "*REDACTED*"
			continue
		}
		cleaned[k] = v
	}

	b, err := json.Marshal(cleaned)
	if err != nil {
		return "", err
	}
	return string(b), err
}
