### Title
Node API/EI token brute-force protection is far weaker than login brute-force protection - ([File: core/web/router.go])

### Summary
Chainlink's node web server enforces two different rate-limit tiers: a strict `Unauthenticated` tier (5 requests/20s, default) applied only to `POST /sessions` login attempts, and a much looser `Authenticated` tier (1000 requests/min, default) applied globally to all other API routes, including the ones that perform the actual credential check for API tokens (`X-API-KEY`/`X-API-SECRET`) and External Initiator tokens (`X-Chainlink-EA-AccessKey`/`X-Chainlink-EA-Secret`).

### Finding Description
The engine-level route group `api` wraps essentially all `/v2/*` routes (and everything else besides `/sessions`) with the `Authenticated` rate limiter, not the strict `Unauthenticated` one: [1](#0-0) 

Compare this with the dedicated `/sessions` login endpoint, which is intentionally placed in its own group using the far stricter `Unauthenticated` limiter to prevent password brute-forcing: [2](#0-1) 

However, credential-guessing is not limited to `/sessions`. The `/v2/*` routes accept authentication via `AuthenticateByToken` (API key/secret) and, for `userOrEI` routes such as `/v2/ping`, via `AuthenticateExternalInitiator` (EI access key/secret) as well: [3](#0-2) [4](#0-3) 

These handlers perform a full secret comparison per request: [5](#0-4) [6](#0-5) 

Because these routes only inherit the outer `api` group's `Authenticated` rate limiter (1000 req/min by default) rather than the `Unauthenticated` (5 req/20s) limiter used for `/sessions`, an unauthenticated caller supplying a guessed `AccessKey` with random `Secret` values can attempt roughly 200x more credential guesses per unit time against `X-API-SECRET` or `X-Chainlink-EA-Secret` than against the password login form, despite these headers not requiring any prior session — directly analogous to the Nextcloud CVE-2023-32319 pattern where an alternate authentication entry point (WebDAV Basic Auth) bypassed the brute-force protection applied to the primary login path.

### Impact Explanation
If an `AccessKey` (API token key or External Initiator access key) is known or guessable (e.g., leaked via logs, a compromised low-privilege channel, or enumeration), an attacker can brute-force the corresponding `Secret` at a rate far higher than the platform's designed anti-brute-force threshold for credentials, since the `Authenticated` limiter (intended for legitimate high-volume authenticated traffic) is applied instead of the `Unauthenticated` limiter meant to throttle credential-guessing. Successful brute-force yields full API-token-level access (job runs, key management, transfers depending on role) or External-Initiator-level access to trigger job runs.

### Likelihood Explanation
Exploitability depends on the attacker already possessing or guessing a valid `AccessKey`, which is a non-trivial precondition (the secret is the part typically protected, but the access key itself may be less protected/rotated and could leak via other channels, e.g., External Initiator records return via `/v2/external_initiators` to Edit-role users, or the key could be enumerated). Given this precondition, the rate-limiting gap is real and demonstrable, but the overall likelihood is moderate since it requires prior partial credential knowledge.

### Recommendation
Apply the same strict `Unauthenticated`-tier rate limiter (or a dedicated per-key failed-auth-attempt limiter) to the initial credential-validation step of `AuthenticateByToken` and `AuthenticateExternalInitiator`, independent of the general `Authenticated` per-IP rate limiter used for already-authorized traffic on `/v2/*`. Consider limiting by `AccessKey`/IP combination with lockout/backoff on repeated failures, matching the protection given to `/sessions`.

### Proof of Concept
1. Obtain or guess a valid External Initiator `AccessKey` (or API token access key).
2. Send repeated requests to `POST /v2/jobs/:ID/runs` (or `GET /v2/ping`) with `X-Chainlink-EA-AccessKey: <known key>` and randomized `X-Chainlink-EA-Secret` values.
3. Because these requests fall under the `api` group's `Authenticated` rate limit (1000/min) rather than the `Unauthenticated` limit (5/20s) enforced on `/sessions`, the attacker can attempt roughly 1000 secret guesses per minute per IP without triggering `429 Too Many Requests`, versus being locked out after 5 attempts in 20 seconds on the login form — confirmed by the routing/middleware structure in [1](#0-0)  versus [2](#0-1) .

func sessionRoutes(app chainlink.Application, r *gin.RouterGroup) {
	config := app.GetConfig()
	rl := config.WebServer().RateLimit()
	unauth := r.Group("/", rateLimiter(
		rl.UnauthenticatedPeriod(),
		rl.Unauthenticated(),
	))
	sc := NewSessionsController(app)
	unauth.POST("/sessions", sc.Create)
	auth := r.Group("/", auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession))
	auth.DELETE("/sessions", sc.Destroy)
}

func AuthenticateByToken(c *gin.Context, authr Authenticator) error {
	ctx := c.Request.Context()
	token := &auth.Token{
		AccessKey: c.GetHeader(APIKey),
		Secret:    c.GetHeader(APISecret),
	}
	if token.AccessKey == "" {
		return auth.ErrorAuthFailed
	}

	if token.Secret == "" {
		return auth.ErrorAuthFailed
	}

	// We need to first load the user row so we can compare tokens using the stored salt
	user, err := authr.FindUserByAPIToken(ctx, token.AccessKey)
	if err != nil {
		if errors.Is(err, sql.ErrNoRows) || errors.Is(err, clsessions.ErrUserSessionExpired) {
			return auth.ErrorAuthFailed
		}
		return err
	}

	ok, err := clsessions.AuthenticateUserByToken(token, &user)
	if err != nil {
		return err
	}
	if !ok {
		return auth.ErrorAuthFailed
	}

	c.Set(SessionUserKey, &user)

	return nil
}

// AuthenticateExternalInitiator compares an auth against an initiator and
// returns true if the password hashes match
func AuthenticateExternalInitiator(eia *auth.Token, ea *ExternalInitiator) (bool, error) {
	hashedSecret, err := auth.HashedSecret(eia, ea.Salt)
	if err != nil {
		return false, err
	}
	return subtle.ConstantTimeCompare([]byte(hashedSecret), []byte(ea.HashedSecret)) == 1, nil
}
