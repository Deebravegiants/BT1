I have enough evidence to confirm the analog vulnerability. The `loopRoutes` function registers pprof-forwarding endpoints without any authentication middleware, unlike the sibling `debugRoutes` function which explicitly requires session authentication.

### Title
Unauthenticated exposure of LOOP plugin pprof/profiling and metrics endpoints - (File: `core/web/router.go`)

### Summary
The `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` routes are registered via `loopRoutes(app, api)` on the top-level `api` group, which only carries rate limiting and session-cookie middleware but no authentication requirement, unlike the analogous `/debug/vars` route registered by `debugRoutes`, which is explicitly wrapped in `auth.Authenticate(...)`.

### Finding Description
In `NewRouter`, the router builds an `api` group with only generic middleware (size limits, logging, recovery, CORS, security headers, rate limiting, and session cookie parsing) — no authentication gate: [1](#0-0) 

Immediately after, `debugRoutes` is called, which correctly wraps its `/debug/vars` endpoint with session authentication: [2](#0-1) 

But `loopRoutes`, called in the same list, registers its handlers directly on the unauthenticated `api`/`r` group with no `auth.Authenticate` wrapper at all: [3](#0-2) 

These handlers proxy requests to internal LOOP plugin processes and forward pprof profiling data and raw plugin metrics to the caller. `pluginPPROFHandler` and `pluginPPROFPOSTSymbolHandler` blindly forward the caller's query parameters (including the `debug`, `gc`, and `seconds` pprof control parameters) to an internal `http://<loopHostName>:<port>/debug/pprof/...` URL and return the raw response body to the unauthenticated client: [4](#0-3) [5](#0-4) 

This is structurally the same bug class as the Nacos `/derby` finding: an internal diagnostic/management surface (`ConfigOpsController`'s unauthenticated `/derby` SQL endpoint) that was left unauthenticated while a sibling endpoint in the same controller (`/data/remove`) was properly protected with `@Secured`. Here, the sibling `/debug/vars` route is authenticated but the LOOP plugin debug/pprof/metrics routes are not, despite sitting on the same internet-facing gin router and same route group.

### Impact Explanation
An unauthenticated remote client can pull Go pprof profiling data (heap, goroutine, cpu profile via `seconds`, block, mutex, allocs, trace) and raw prometheus-formatted metrics for any registered LOOP plugin (relayer, median plugin, etc.) purely by guessing/enumerating the plugin name (obtainable via the also-unauthenticated `/discovery` endpoint which lists all registered plugin names). Exposed profiling data can leak internal memory layout, running goroutine stacks with argument values, and application internals useful for further attacks or information disclosure, and CPU/heap profile requests can also be used as a light DoS/resource-exhaustion vector by unauthenticated actors (`seconds` param controls a blocking profile duration up to attacker's choosing, bounded loosely by `PPROFOverheadSeconds`).

### Likelihood Explanation
Very high. Exploitation only requires an unauthenticated HTTP GET/POST to a known, internet-facing chainlink node route; no credentials, tokens, or session cookies are needed since `loopRoutes` sits outside any `auth.Authenticate` group, unlike essentially every other data-yielding route in the router.

### Recommendation
Wrap `loopRoutes` registrations behind the same session/token authentication middleware used elsewhere (e.g., `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)`), consistent with `debugRoutes` and the authenticated `metricRoutes(authv2)` pprof group already used for the node's own `/debug/pprof/*`. If external Prometheus scraping without session cookies is required, gate these routes with a dedicated scrape-only credential/token instead of leaving them fully open.

### Proof of Concept
```
# List registered plugin names (no auth required)
curl http://<node>:6688/discovery

# Pull heap/goroutine/cpu profile for an internal plugin - no auth required
curl http://<node>:6688/plugins/<plugin-name>/debug/pprof/heap
curl http://<node>:6688/plugins/<plugin-name>/debug/pprof/profile?seconds=30

# Pull raw plugin metrics - no auth required
curl http://<node>:6688/plugins/<plugin-name>/metrics
```

```go
func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
```

```go
func (l *LoopRegistryServer) pluginPPROFPOSTSymbolHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/symbol", l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	body, err := io.ReadAll(gc.Request.Body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error reading plugin pprof request body: %s", err))
		return
	}
	l.doRequest(gc, "POST", pluginURL, bytes.NewReader(body), timeout, pluginName)
}
```
