## Title
CORS Allowlist Bypass via Improper Suffix Matching in Gateway HTTP Server - (File: core/services/gateway/network/httpserver.go)

### Summary
The gateway's CORS origin-allowlist check in `isAllowedOrigin` uses an unanchored `strings.HasSuffix` comparison when validating wildcard-configured origins (e.g. `*.ethereum.org`), allowing an attacker-registered domain that merely *ends with* the allowed suffix (e.g. `evilethereum.org`) to be treated as a trusted sub-domain of `ethereum.org`. This is a domain-allowlist bypass analogous to the CSRF bug class in CVE-2018-14520, where insufficiently validated request origins let an untrusted site trigger privileged HTTP actions against the target service.

### Finding Description
`isAllowedOrigin` strips the `*.` prefix from a configured wildcard origin and then checks whether the request's `Origin` header host ends with that string: [1](#0-0) 

Because `strings.HasSuffix` performs a raw substring/suffix comparison without requiring a `.` boundary before the suffix, a host such as `notreallyethereum.org` or `evilethereum.org` (no dot separating the attacker-chosen prefix from `ethereum.org`) will satisfy `strings.HasSuffix(originHost, "ethereum.org")` and be granted the allowed-origin status meant only for genuine sub-domains of `ethereum.org`. The result is reflected directly in the CORS response headers: [2](#0-1) 

This is confirmed as intended (if flawed) wildcard-matching behavior by the accompanying test suite, which validates that arbitrary sub-domains of the configured suffix are treated as allowed, but does not test the boundary case of a domain that merely shares a suffix string: [3](#0-2) 

### Impact Explanation
The gateway HTTP server is the internet-facing entry point that receives raw requests and forwards them to `ProcessRequest` for handling (e.g., workflow trigger/HTTP-action processing): [4](#0-3) 

An operator who configures `CORSAllowedOrigins` with a wildcard entry (e.g. `https://*.ethereum.org`) intends to trust only genuine sub-domains of that domain. Due to the suffix-matching flaw, an attacker who registers a look-alike domain (e.g. `https://evilethereum.org`) can have their page's browser-based requests pass the origin check, receive `Access-Control-Allow-Origin` reflecting their malicious origin, and successfully issue authenticated/allowed cross-origin requests to the gateway that the allowlist was designed to block — a direct allowlist-bypass enabling request impersonation from an unprivileged, attacker-controlled web origin, mirroring the CSRF/untrusted-origin bug class of the reported CVE.

### Likelihood Explanation
Exploitation requires only that the node operator configure a wildcard `CORSAllowedOrigins` entry (a documented, supported configuration pattern) and that the attacker register a domain sharing the suffix string without a dot boundary — both low-effort, realistic conditions. No privileged access or network positioning is required; the attacker only needs to lure a victim's browser to their page.

### Recommendation
Fix `isAllowedOrigin` to enforce a proper domain-boundary check, e.g. verify `originHost == allowedHost` or `strings.HasSuffix(originHost, "."+allowedHost)` after stripping the `*.` prefix, so that only genuine sub-domains (separated by a literal dot) match the wildcard, not arbitrary strings sharing the trailing characters.

### Proof of Concept
1. Configure the gateway with `CORSAllowedOrigins: ["https://*.ethereum.org"]` and `CORSEnabled: true`.
2. From a browser controlled by the attacker, host a page at `https://evilethereum.org` (or `https://notreallyethereum.org`) that issues `fetch()`/XHR requests to the gateway endpoint with `Origin: https://evilethereum.org`.
3. Observe in `handleRequest`/`isAllowedOrigin` that `strings.HasSuffix("evilethereum.org", "ethereum.org")` returns `true`, so the server responds with `Access-Control-Allow-Origin: https://evilethereum.org`, `Access-Control-Allow-Methods`, and `Access-Control-Allow-Headers`, and processes the forwarded request — despite `evilethereum.org` not being an intended sub-domain of `ethereum.org`. [5](#0-4)

func (s *httpServer) isAllowedOrigin(origin string) bool {
	originScheme, originHost, originPort, err := s.splitURL(origin)
	if err != nil {
		s.lggr.Debug("error parsing origin URL", err)
		return false
	}
	for _, allowed := range s.config.CORSAllowedOrigins {
		// probably better to do this once when server starts and store it in a map
		// this is an easier solution so we don't have to apply more changes to the code
		// just need to be careful when specifying allowed origins in the config file
		allowedScheme, allowedHost, allowedPort, err := s.splitURL(allowed)
		if err != nil {
			s.lggr.Debug("error parsing allowed origin URL", err)
			continue
		}
		// skip if the scheme doesn't match at all
		if originScheme != allowedScheme {
			continue
		}
		// skip if the port doesn't match at all
		if originPort != allowedPort {
			continue
		}
		// check for exact host match (e.g., remix.com)
		if originHost == allowedHost {
			return true
		}
		// check for wildcard host match (e.g., *.remix.com)
		if strings.HasPrefix(allowedHost, "*.") {
			allowedHost = allowedHost[2:]
			if strings.HasSuffix(originHost, allowedHost) {
				return true
			}
		}
	}
	return false
}

func (s *httpServer) handleRequest(w http.ResponseWriter, r *http.Request) {
	if s.config.CORSEnabled {
		origin := r.Header.Get("Origin")
		if s.isAllowedOrigin(origin) {
			w.Header().Set("Access-Control-Allow-Origin", origin)
			w.Header().Set("Access-Control-Allow-Methods", "GET, POST, OPTIONS")
			w.Header().Set("Access-Control-Allow-Headers", "Content-Type")
		}

		// handle preflight requests
		if r.Method == http.MethodOptions {
			w.WriteHeader(http.StatusNoContent)
			return
		}
	}
