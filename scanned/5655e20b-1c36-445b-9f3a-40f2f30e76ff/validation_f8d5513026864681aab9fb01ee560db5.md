### Title
Missing role check on `GET /v2/external_initiators` leaks all External Initiators' `OutgoingToken` secrets to any authenticated low-privilege user - (File: core/web/router.go)

### Summary
The `/v2/external_initiators` `GET` (Index) route is registered without any role restriction, while every other mutating route for the same resource (`Create`, `Destroy`) requires `RequiresEditRole`. Any user authenticated with the lowest privilege level (`view`) can call this endpoint and receive the `OutgoingToken` secret for every External Initiator configured on the node.

### Finding Description
In `core/web/router.go`, the External Initiator routes are set up as: [3](#0-2) 

`GET /v2/external_initiators` has no `auth.RequiresXRole` wrapper, unlike `POST` (`RequiresEditRole`) and `DELETE` (`RequiresEditRole`). It only inherits the generic `authv2` group authentication (`AuthenticateByToken` or `AuthenticateBySession`) shown at [2](#0-1) , which succeeds for any valid API user token/session regardless of role, including `view`.

The handler `(eic *ExternalInitiatorsController) Index` at [4](#0-3)  fetches all External Initiators via `BridgeORM().ExternalInitiators` and serializes each with `presenters.NewExternalInitiatorResource`, which includes the `OutgoingToken` field: [5](#0-4) 

`OutgoingToken` is a sensitive secret generated at creation time (`utils.NewSecret(utils.DefaultSecretSize)`) that the node uses to authenticate its outbound webhook calls to the external initiator's URL: [6](#0-5) 

Because `Index` applies no role check, any authenticated identity that can obtain a `view`-role session/token (the lowest privilege level in the RBAC model defined in `core/web/auth/auth.go`) can enumerate every initiator's `OutgoingToken`, not just their own.

### Impact Explanation
An attacker who compromises or is issued a low-privilege (`view`) API credential — a scenario directly analogous to an account-compromise incident where an attacker gains a foothold with limited legitimate access — can escalate impact by harvesting `OutgoingToken` secrets belonging to other, unrelated External Initiators. With the stolen `OutgoingToken`, an attacker can impersonate the Chainlink node when calling back to the external initiator's own service (per the outgoing-auth design in `bridges.NewExternalInitiator`), potentially triggering unauthorized actions on the initiator's system or spoofing legitimate node callbacks.

### Likelihood Explanation
Any node operator that provisions `view`-role users (a common minimal-privilege setup for dashboards/monitoring) inherently exposes this endpoint to those users. No special conditions are required beyond a valid low-privilege session or API token — the request is a simple authenticated `GET`.

### Recommendation
Add a role gate consistent with the rest of the External Initiator routes, e.g. wrap `Index` with `auth.RequiresEditRole` (or at minimum `RequiresRunRole`) in `core/web/router.go`, matching the protection already applied to `Create` and `Destroy`. Additionally, consider omitting `OutgoingToken`/other secrets from list responses entirely, only returning them once at creation time (as `Create` already does via `NewExternalInitiatorAuthentication`).

### Proof of Concept
1. Create a user with `view` role (or obtain a `view`-role API token) via the admin-only user management endpoints.
2. Authenticate as that user (`POST /sessions` or with `X-API-KEY`/`X-API-SECRET` headers) — `AuthenticateBySession`/`AuthenticateByToken` succeed for any role.
3. Send `GET /v2/external_initiators` with the `view` credentials.
4. Observe the JSON:API response includes `outgoingToken` for every configured External Initiator (see `ExternalInitiatorResource.OutgoingToken` in `core/web/presenters/external_initiators.go`), which a `view`-role user should never be entitled to read.

func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}

// NewExternalInitiator generates an ExternalInitiator from an
// auth.Token, hashing the password for storage
func NewExternalInitiator(
	eia *auth.Token,
	eir *ExternalInitiatorRequest,
) (*ExternalInitiator, error) {
	salt := utils.NewSecret(utils.DefaultSecretSize)
	hashedSecret, err := auth.HashedSecret(eia, salt)
	if err != nil {
		return nil, pkgerrors.Wrap(err, "error hashing secret for external initiator")
	}

	return &ExternalInitiator{
		Name:           strings.ToLower(eir.Name),
		URL:            eir.URL,
		AccessKey:      eia.AccessKey,
		HashedSecret:   hashedSecret,
		Salt:           salt,
		OutgoingToken:  utils.NewSecret(utils.DefaultSecretSize),
		OutgoingSecret: utils.NewSecret(utils.DefaultSecretSize),
	}, nil
}
