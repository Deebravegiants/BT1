## Finding

### Title
Bridge outgoing authentication token exposed to Viewer-role users via `GET /v2/bridge_types/:BridgeName` - (File: core/web/bridge_types_controller.go)

### Summary
The Grafana advisory describes a case where a notification-integration secret/config (VictorOps) was reachable by users holding only the lowest ("Viewer") permission level, because the endpoint was not gated behind the correct role check. Chainlink has a directly analogous pattern in the Bridge Types API: the `Show` handler returns a `BridgeResource` that includes `OutgoingToken`, but the route is registered with no role-restriction middleware at all, while the sibling `Create`/`Update`/`Destroy` routes explicitly require `RequiresEditRole`.

### Finding Description
The bridge types routes are registered in `v2Routes`: [1](#0-0) 

`Create`, `Update`, and `Destroy` are wrapped in `auth.RequiresEditRole`, but `Show` (and `Index`) are not wrapped in any role check — they are reachable by any authenticated session/token regardless of role, including `UserRoleView`.

`BridgeTypesController.Show` fetches the bridge record and serializes it via `presenters.NewBridgeResource`: [2](#0-1) 

The presenter unconditionally includes `OutgoingToken` (no `omitempty`, unlike `IncomingToken` which is intentionally hidden except at creation time): [3](#0-2) 

`OutgoingToken` is the credential Chainlink uses to authenticate itself when calling out to the external bridge/adapter (`bridges.BridgeType.OutgoingToken`), i.e. a secret analogous to the VictorOps integration key in the Grafana case.

The project's own RBAC route test explicitly documents that `GET /v2/bridge_types/:BridgeName` is `viewOnlyAllowed: true`: [4](#0-3) [5](#0-4) 

This confirms, by the codebase's own test intent, that View-role users are expected to be able to call this endpoint successfully — and doing so discloses the bridge's `OutgoingToken` secret.

### Impact Explanation
Any authenticated user with only View role (or a Run-role external-initiator-derived session, since `AuthenticateExternalInitiator` also assigns at minimum `UserRoleRun` — see `core/web/auth/auth.go:143-146`) can retrieve the `OutgoingToken` for any bridge by name via a simple `GET`. This token is a secret used for outbound authentication to the bridge adapter; its disclosure to an unprivileged/read-only user violates the principle that only Edit/Admin roles should see or manage bridge secrets, matching CWE-200 (information exposure) exactly as in the Grafana VictorOps advisory.

### Likelihood Explanation
High: the endpoint requires no special role beyond basic authentication, so any account provisioned with only view-level access (a common practice for auditors/read-only integrations) can enumerate bridge names via the paginated `Index`/`GET /v2/bridge_types` (also role-unrestricted) and then call `Show` on each to harvest `OutgoingToken` values.

### Recommendation
Wrap `authv2.GET("/bridge_types/:BridgeName", bt.Show)` (and consider `Index`) with at least `auth.RequiresEditRole`, or strip `OutgoingToken` from the `BridgeResource` returned to non-privileged roles (mirroring the `omitempty`/creation-only treatment already applied to `IncomingToken`).

### Proof of Concept
1. Create a Chainlink node user with `UserRoleView`.
2. Authenticate as that user (session cookie or API token).
3. Call `GET /v2/bridge_types/<existing-bridge-name>`.
4. Observe the JSON response contains `outgoingToken` populated with the bridge's live secret, despite the requester having only view permissions.

// Show returns the details of a specific Bridge.
func (btc *BridgeTypesController) Show(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	bt, err := btc.App.BridgeORM().FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}

	t.Parallel()
	app := cltest.NewApplicationEVMDisabled(t)

	router := web.Router(t, app, nil)
	ts := httptest.NewServer(router)
	defer ts.Close()

	// Create a test run user to work with
	u := &cltest.User{Role: sessions.UserRoleView}
	client := app.NewHTTPClient(u)

	// Assert all view only routes
	for i, route := range routesRolesMap {
		t.Run(fmt.Sprintf("%d-%s-%s", i, route.verb, route.path), func(t *testing.T) {
			t.Parallel()
			var resp *http.Response
			var cleanup func()

			switch route.verb {
			case "GET":
				resp, cleanup = client.Get(route.path)
			case "POST":
				resp, cleanup = client.Post(route.path, nil)
			case "DELETE":
				resp, cleanup = client.Delete(route.path)
			case "PATCH":
				resp, cleanup = client.Patch(route.path, nil)
			case "PUT":
				resp, cleanup = client.Put(route.path, nil)
			default:
				t.Fatalf("Unknown HTTP verb %s\n", route.verb)
			}
			defer cleanup()

			// If this route only allows view only, don't expect an unauthorized response
			switch {
			case route.viewOnlyAllowed:
				assert.NotEqual(t, http.StatusUnauthorized, resp.StatusCode)
				assert.NotEqual(t, http.StatusForbidden, resp.StatusCode)
			case !route.EditAllowed:
				assert.Equal(t, http.StatusForbidden, resp.StatusCode)
			default:
				assert.Equal(t, http.StatusUnauthorized, resp.StatusCode)
			}
		})
	}
}
