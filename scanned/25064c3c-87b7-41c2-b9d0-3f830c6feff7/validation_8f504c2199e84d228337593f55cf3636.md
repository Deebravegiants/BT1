### Title
Broken Access Control: `/v2/external_initiators` Index Leaks Outgoing Credentials to Any Authenticated Role (File: core/web/router.go)

### Summary
The `GET /v2/external_initiators` route is mounted in the authenticated `authv2` group but, unlike every other mutating/sensitive route in the same file, it has no `auth.RequiresEditRole`/`RequiresAdminRole`/`RequiresRunRole` wrapper. Any authenticated principal — including a user whose role is `UserRoleView` (the lowest privilege tier) or an `AuthenticateByToken`/`AuthenticateBySession` session — can call this endpoint and enumerate every `ExternalInitiator` record's `OutgoingToken`, which is a secret credential the node uses to authenticate its own outgoing calls to the external initiator's endpoint.

### Finding Description
`v2Routes` wires up the `ExternalInitiatorsController` and applies `auth.RequiresEditRole` to `Create` and `Destroy`, but leaves `Index` unprotected beyond the base `authv2` authentication middleware: [2](#0-1) 

`Index` builds its response using `presenters.NewExternalInitiatorResource`, which serializes the `OutgoingToken` field for each initiator: [3](#0-2) 

The `OutgoingToken` is a randomly-generated secret created at `ExternalInitiator` creation time, stored alongside `OutgoingSecret`, and used by the node to authenticate outbound requests to the initiator's URL: [4](#0-3) 

Compared to the other `Index` endpoints in the router that only expose non-secret data (e.g. ETH addresses, CSA public keys), this endpoint uniquely returns live secret material while requiring only the weakest authenticated role, which breaks the intended role-tiering (`view` < `run` < `edit` < `admin`) enforced everywhere else in this file.

### Impact Explanation
A user provisioned with only `UserRoleView` (read-only dashboard access) or a `run`-scoped API token can retrieve `OutgoingToken` values for all configured external initiators via a single unauthenticated-with-respect-to-role GET request. Possession of this token allows an attacker to impersonate the Chainlink node when calling back into the external initiator's own API/webhook endpoint (the initiator trusts requests bearing this token as originating from the node), potentially enabling unauthorized triggering or spoofing of external-initiator-side operations. This matches the reported bug class — sensitive configuration/credential surface reachable without adequate role-based access control — mapped onto Chainlink's actual RBAC model (`RequiresEditRole`/`RequiresAdminRole` vs. plain authentication).

### Likelihood Explanation
Exploitation only requires an account or API token with the lowest privilege role (`view`) or any successfully authenticated session, since the route sits behind the generic `authv2` authentication middleware and not behind the role gates applied to the sibling endpoints. Any operator that provisions `view`-role users/tokens for read-only dashboards or monitoring would unintentionally grant them access to these secrets.

### Recommendation
Wrap the `Index` route with an appropriate role check consistent with the sensitivity of the data it returns, e.g. `auth.RequiresEditRole(eia.Index)` (matching `Create`/`Destroy`), and/or redact `OutgoingToken`/`OutgoingSecret` from `ExternalInitiatorResource` for listing purposes, only exposing them at creation time via `ExternalInitiatorAuthentication` as is already done in `Create`.

### Proof of Concept
1. Provision a Chainlink node user with `UserRoleView` (or issue a `run`-scoped token) and obtain a valid session/API token via `AuthenticateBySession`/`AuthenticateByToken`.
2. Ensure at least one `ExternalInitiator` exists (created previously by an `edit`/`admin` user via `POST /v2/external_initiators`).
3. As the low-privilege principal, call `GET /v2/external_initiators`.
4. Observe the JSON:API response includes `outgoingToken` for each initiator, per `ExternalInitiatorResource`, without any `edit`/`admin`/`run` role check being enforced — confirmed by the absence of a `RequiresXRole` wrapper on this specific route in `router.go` line 264, in contrast to `Create`/`Destroy` on lines 265–266.

func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}

// ExternalInitiator represents a user that can initiate runs remotely
type ExternalInitiator struct {
	ID             int64
	Name           string
	URL            *models.WebURL
	AccessKey      string
	Salt           string
	HashedSecret   string
	OutgoingSecret string
	OutgoingToken  string

	CreatedAt time.Time
	UpdatedAt time.Time
}

// NewExternalInitiator generates an ExternalInitiator from an
// auth.Token, hashing the password for storage
func NewExternalInitiator(
	eia *auth.Token,
	eir *ExternalInitiatorRequest,
) (*ExternalInitiator, error) {
	salt := utils.NewSecret(utils.DefaultSecretSize)
	hashedSecret, err := auth.HashedSecret(eia, salt)
	if err != nil {
		return nil, pkgerrors.Wrap(err, "error hashing secret for external initiator")
	}

	return &ExternalInitiator{
		Name:           strings.ToLower(eir.Name),
		URL:            eir.URL,
		AccessKey:      eia.AccessKey,
		HashedSecret:   hashedSecret,
		Salt:           salt,
		OutgoingToken:  utils.NewSecret(utils.DefaultSecretSize),
		OutgoingSecret: utils.NewSecret(utils.DefaultSecretSize),
	}, nil
