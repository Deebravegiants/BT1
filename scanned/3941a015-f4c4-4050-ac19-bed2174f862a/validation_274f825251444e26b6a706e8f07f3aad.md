### Title
Missing Allowlist/Rate-Limit Enforcement on Gateway `web_api_trigger` Messages Allows Unauthorized Workflow Trigger Broadcast to DON Nodes - (File: `core/services/gateway/handlers/capabilities/handler.go`)

### Summary
The gateway's WebAPI capabilities handler accepts and forwards `web_api_trigger` messages from any caller who can produce a syntactically valid, self-signed message — signature validation only proves possession of *an* ECDSA keypair, not membership in any authorized/allowlisted set of senders. The code contains an explicit `// TODO: apply allowlist and rate-limiting here` marker at the point where such checks should occur, and no allowlist or per-sender rate limit is actually enforced before the message is broadcast to every node in the DON.

### Finding Description
The gateway's internet-facing HTTP endpoint (`gateway.ProcessRequest`) routes legacy user messages to `Handler.HandleLegacyUserMessage` [1](#0-0) . For the WebAPI capabilities handler, `HandleLegacyUserMessage` only validates payload decoding, a non-zero timestamp, message staleness, and the method name; it explicitly defers allowlisting and rate-limiting with a `TODO` comment before broadcasting the request to every DON member node: [2](#0-1) 

The only "authentication" performed is `msg.Validate()` / `common.ValidatedRequestFromMessage`, which merely recovers a signer address from an ECDSA signature over the message body — it does not check that address against any authorized list of senders: [3](#0-2) 

Any unprivileged party can generate their own private key, sign a `web_api_trigger` message body, and submit it to the public gateway user endpoint. The message will pass `Validate()` (signature format is correct, fields are non-empty), pass the handler's timestamp/method checks, and then be forwarded via `don.SendToNode` to all configured DON members — with no check that the recovered signer is a permitted/allowlisted trigger caller and no rate limiting applied to that sender. This is confirmed by the handler's own test file, which contains the note: `// TODO: Validate Senders and rate limit check, pending question in trigger about where senders and rate limits are validated` [4](#0-3) .

This is inconsistent with other gateway handlers in the same codebase (e.g., the Vault handler), which explicitly authorize every gateway-routed request via an `Authorizer`/allowlist before processing: [5](#0-4) , and reject unauthorized senders with `"request not authorized"` [6](#0-5) .

### Impact Explanation
An unprivileged, unauthenticated remote actor (anyone able to send HTTP requests to the gateway's public user endpoint) can craft a self-signed `web_api_trigger` message and have it broadcast as a legitimate, "authenticated" (signed) message to every node in a targeted DON, without being on any allowlist. Depending on how the DON's capability/workflow layer consumes `web_api_trigger` messages downstream, this can result in unauthorized triggering of workflow jobs on chainlink nodes and/or uncontrolled resource consumption (no rate limiting per sender), since the sender-address check that would normally gate this ("allowlist") is a `TODO` that was never implemented for this code path.

### Likelihood Explanation
High from a reachability standpoint: this is the primary, internet-facing gateway request path (`gateway.ProcessRequest` → `HandleLegacyUserMessage`), reachable by any client with no privileges beyond the ability to generate an ECDSA keypair and format a JSON-RPC request — both trivial. The only friction is that the caller must know the correct `DonID`/`Method`/payload schema, which is public in the gateway config and API docs.

### Recommendation
Implement the deferred allowlist check in `HandleLegacyUserMessage` (and the equivalent JSON-RPC path if applicable) before forwarding a `web_api_trigger` message to `don.SendToNode`: validate `msg.Body.Sender` (the address recovered by `Validate()`) against the DON's configured allowlist of authorized triggering identities, and apply per-sender rate limiting, mirroring the pattern already used by the Vault gateway handler's `Authorizer`/`allowListBasedAuth` flow.

### Proof of Concept
1. Generate an arbitrary ECDSA keypair (no registration or permission required).
2. Construct an `api.Message` with a valid `MessageID`, `Method = "web_api_trigger"`, a target `DonID`, and a well-formed `TriggerRequestPayload` with a non-zero, non-stale `Timestamp`.
3. Sign the message body with the arbitrary private key using `Message.Sign`, producing a signature that satisfies `Message.Validate()`.
4. Submit the signed message to the gateway's public user-facing endpoint as a legacy JSON-RPC request targeting the chosen `DonID`.
5. Observe that `handler.HandleLegacyUserMessage` passes all checks (decode, timestamp, method) and calls `don.SendToNode` for every member of the DON — with no allowlist/rate-limit rejection, since that check is not implemented (per the `TODO` comment).

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageID) == 0 || len(m.Body.MessageID) > MessageIDMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageID, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonID) == 0 || len(m.Body.DonID) > MessageDonIDMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonID, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}
