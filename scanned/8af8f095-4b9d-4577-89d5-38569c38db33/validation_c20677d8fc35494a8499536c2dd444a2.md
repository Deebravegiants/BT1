### Title
Session cookie hardcoded to a 30-day browser lifetime, decoupled from the enforced idle `SessionTimeout` and refreshed indefinitely on activity - (`File: core/services/chainlink/config_web_server.go`)

### Summary
The CVE describes RabbitMQ's management UI persisting signed-in credentials in browser local storage with no expiration, so a stolen/leaked value remains usable indefinitely. Chainlink's operator UI has an analogous, though weaker, issue: the gin session cookie that carries the session ID is configured with a fixed 30-day `MaxAge` in the browser regardless of the operator-configured `SessionTimeout`, and each authenticated request refreshes the underlying session's `last_used` timestamp server-side, so a session can remain valid for up to that full 30-day window as long as it is used periodically.

### Finding Description
`webServerConfig.SessionOptions()` hardcodes the gin-contrib/sessions cookie options with `MaxAge: 86400 * 30` (30 days), independent of the configurable `SessionTimeout` (default `15m`): [1](#0-0) 

This cookie carries the `SessionIDKey` used by `AuthenticateBySession` and `AuthenticateGQL` to look up the authenticated user for every request: [2](#0-1) [3](#0-2) 

Server-side, the local-auth ORM validates the session by checking `last_used + sessionDuration >= now()` and, critically, updates `last_used` to `now()` on every successful authorization: [4](#0-3) 

Because `last_used` is refreshed on each use, the only two mechanisms that could force expiry of an actively-used session are: (1) the browser discarding the cookie after `MaxAge` (30 days, hardcoded, not tied to `SessionTimeout`), or (2) the background session reaper, which purges rows based on `created_at`, not `last_used`, per `SessionReaperExpiration` (default `240h` / 10 days) but only for genuinely stale/unused sessions: [5](#0-4) 

Logging out only deletes the specific session row server-side (`Destroy` -> `DeleteUserSession`) and clears the local session data in that same client's cookie — it does not add any independent hard cap that shortens the 30-day cookie lifetime for a copy of the cookie held elsewhere: [6](#0-5) 

Net effect: the operator-configured `SessionTimeout` (idle timeout, default 15 minutes) is not an effective ceiling on how long a session/credential value can remain valid — it only requires periodic reuse, similar in spirit to the RabbitMQ issue where a signed-in credential in browser storage had no expiration and could be leveraged indefinitely if exfiltrated by another means.

### Impact Explanation
If a session cookie value is exfiltrated (e.g., via a client-side vulnerability, misconfigured proxy log, browser extension, or physical device access) and the attacker periodically replays it, the attacker can remain authenticated as the victim (potentially an Admin-role user) for up to 30 days, since the cookie itself doesn't expire sooner and each replay resets the idle timer. This undermines the intended security control of `SessionTimeout`, which operators configure specifically to bound the window in which a stolen session is useful.

### Likelihood Explanation
Exploitation still requires an initial vector to obtain the session cookie value (this analysis does not identify a cookie-theft primitive itself in the reviewed code, so this is a "credential lifetime/expiration" weakness rather than a standalone full exploit chain). Given that, likelihood is moderate: it amplifies the impact of any other cookie-disclosure bug but is not independently triggerable by an unprivileged remote actor without such a vector.

### Recommendation
Derive the gin session cookie `MaxAge` from the configured `SessionTimeout` (or a bounded absolute maximum) instead of a hardcoded 30-day constant, and consider enforcing an absolute (not just idle) session lifetime server-side (e.g., based on `created_at` rather than solely `last_used`) so that a continuously-replayed session cannot be extended indefinitely.

### Proof of Concept
1. Log in to the operator UI/API to obtain the session cookie (`clsession` or equivalent), noting the `Set-Cookie` header's `Max-Age=2592000` (30 days) regardless of the configured `WebServer.SessionTimeout` value: [1](#0-0) 
2. Obtain a copy of this cookie value through any means (out of scope for this report).
3. Replay the cookie against an authenticated endpoint (e.g., `GET /v2/...` protected by `AuthenticateBySession`) at intervals shorter than `SessionTimeout` (default 15 min) — the request succeeds and `last_used` is reset each time: [7](#0-6) 
4. Repeat step 3 for up to 30 days; the session remains valid the entire time, even though the configured idle `SessionTimeout` is only 15 minutes.

func AuthenticateBySession(c *gin.Context, authr Authenticator) error {
	ctx := c.Request.Context()
	session := sessions.Default(c)
	sessionID, ok := session.Get(SessionIDKey).(string)
	if !ok {
		return auth.ErrorAuthFailed
	}

	user, err := authr.AuthorizedUserWithSession(ctx, sessionID)
	if err != nil {
		return err
	}

	c.Set(SessionUserKey, &user)

	return nil
}

// findValidSession finds an unexpired session by its ID and returns the associated email.
func (o *orm) findValidSession(ctx context.Context, sessionID string) (email string, err error) {
	if err := o.ds.GetContext(ctx, &email, "SELECT email FROM sessions WHERE id = $1 AND last_used + $2 >= now() FOR UPDATE", sessionID, o.sessionDuration); err != nil {
		o.lggr.Infof("query result: %v", email)
		return email, pkgerrors.Wrap(err, "no matching user for provided session token")
	}
	return email, nil
}

// updateSessionLastUsed updates a session by its ID and sets the LastUsed field to now().
func (o *orm) updateSessionLastUsed(ctx context.Context, sessionID string) error {
	_, err := o.ds.ExecContext(ctx, "UPDATE sessions SET last_used = now() WHERE id = $1", sessionID)
	return err
}

// AuthorizedUserWithSession will return the API user associated with the Session ID if it
// exists and hasn't expired, and update session's LastUsed field.
// AuthorizedUserWithSession will return the API user associated with the Session ID if it
// exists and hasn't expired, and update session's LastUsed field.
func (o *orm) AuthorizedUserWithSession(ctx context.Context, sessionID string) (user sessions.User, err error) {
	if len(sessionID) == 0 {
		return sessions.User{}, sessions.ErrEmptySessionID
	}

	email, err := o.findValidSession(ctx, sessionID)
	if err != nil {
		return sessions.User{}, sessions.ErrUserSessionExpired
	}

	user, err = o.findUser(ctx, email)
	if err != nil {
		return sessions.User{}, sessions.ErrUserSessionExpired
	}

	if err := o.updateSessionLastUsed(ctx, sessionID); err != nil {
		return sessions.User{}, err
	}

	return user, nil
}

func (sr *sessionReaper) Work(ctx context.Context) {
	recordCreationStaleThreshold := sr.config.SessionReaperExpiration().Before(
		sr.config.SessionTimeout().Before(time.Now()))
	err := sr.deleteStaleSessions(ctx, recordCreationStaleThreshold)
	if err != nil {
		sr.lggr.Error("unable to reap stale sessions: ", err)
	}
}

// DeleteStaleSessions deletes all sessions before the passed time.
func (sr *sessionReaper) deleteStaleSessions(ctx context.Context, before time.Time) error {
	_, err := sr.ds.ExecContext(ctx, "DELETE FROM oidc_sessions WHERE created_at < $1", before)
	return err
}

// Destroy removes the specified session ID from the database.
func (sc *SessionsController) Destroy(c *gin.Context) {
	defer sc.App.WakeSessionReaper()
	ctx := c.Request.Context()

	session := sessions.Default(c)
	defer session.Clear()
	sessionID, ok := session.Get(auth.SessionIDKey).(string)
	if !ok {
		jsonAPIResponse(c, Session{Authenticated: false}, "session")
		return
	}
	if err := sc.App.AuthenticationProvider().DeleteUserSession(ctx, sessionID); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	sc.App.GetAuditLogger().Audit(audit.AuthSessionDeleted, map[string]any{"sessionID": sessionID})
	jsonAPIResponse(c, Session{Authenticated: false}, "session")
}
