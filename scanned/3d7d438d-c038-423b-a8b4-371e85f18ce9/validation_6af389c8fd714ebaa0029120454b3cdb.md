## Analog Found: Response cache key omits WorkflowID, allowing cross‑workflow response reuse despite documented workflow isolation

### Title
Outbound HTTP response cache key excludes `WorkflowID`, causing cross-workflow response confusion contrary to documented isolation - (File: `core/services/gateway/handlers/capabilities/v2/response_cache.go`)

### Summary
The `responseCache` used by the HTTP Handlers V2 gateway is documented as being workflow-scoped ("Workflow Isolation: Cache entries are scoped by workflow ID to prevent cross-workflow data leakage" [1](#0-0) ), but the actual cache key (`req.Hash()`) used by `Fetch`/`Set`/`isExpiredOrNotCached` does not incorporate `WorkflowID` — it is only sensitive to method, URL, headers, body and `WorkflowOwner` [2](#0-1) . This is directly proven by the test suite itself.

### Finding Description
`responseCache` stores cached HTTP action responses in a map keyed by `req.Hash()` [3](#0-2) . The comment states the hash is "of the request (method, URL, headers, body, workflowOwner)" — `workflowOwner`, not `workflowID`.

The test file explicitly documents and asserts this behavior:
- "having different workflowID results in same Hash" → `require.Equal(t, hash1, hash2, ...)` [4](#0-3) 
- "having same workflowOwner results in the same Hash" and "having different workflowOwner results in different Hash" confirm the key is scoped only to `WorkflowOwner`, not `WorkflowID` [5](#0-4) .

This directly contradicts the README's claim: "Cache Key: Generated from workflow ID and request hash" and "Workflow Isolation: Cache entries are scoped by workflow ID to prevent cross-workflow data leakage" [6](#0-5) .

Just as the original report's bug arose from computing a shared aggregate (`totalSupply`/`_balances`) keyed on an identity (`assetHash`) that failed to reflect the true underlying state (shares vs. raw balance) — causing one user's stored value to be silently reused/confused with another's — here the cache's storage key fails to reflect the true isolation unit (per-workflow) that the system is documented to guarantee, causing one workflow's cached HTTP response to be served to a different workflow under the same owner.

### Impact Explanation
Any unprivileged workflow node/workflow (sharing the same `WorkflowOwner`) that issues an HTTP action request with the same method/URL/headers/body as a different workflow owned by the same address will receive the other workflow's cached response instead of making its own outbound call. This is a concrete cross-user (cross-workflow) response confusion: data intended for/generated by one workflow execution context is delivered to a different workflow, silently bypassing the documented workflow-level isolation guarantee, and defeats the purpose of the `Store`/`MaxAgeMs` per-workflow cache semantics described in the HTTP Handlers V2 design [7](#0-6) .

### Likelihood Explanation
This requires no privileged access — any onboarded workflow owner running two (or more) workflows that issue outbound HTTP requests with identical method/URL/headers/body will trigger the collision as soon as caching (`CacheSettings.Store`) is enabled, which is a standard/expected workflow capability configuration, not an attack requiring external conditions.

### Recommendation
Include `WorkflowID` (not just `WorkflowOwner`) in the `Hash()` computation used as the cache key, matching the documented behavior, or explicitly document/scope the cache as owner-level (not workflow-level) if that is the intended design and update callers/README accordingly.

### Proof of Concept
The existing test `TestRequestHash` in `response_cache_test.go` is itself the proof of concept: it constructs two requests differing only in `WorkflowID` and asserts `hash1 == hash2` [4](#0-3) . Combined with `Fetch`, this means: Workflow A (owner X) issues a GET to `https://api.example.com/data` with `CacheSettings.Store=true`; a fresh response gets cached under `Hash()`. Workflow B (also owner X, different `WorkflowID`) later issues the identical GET; because `Hash()` ignores `WorkflowID`, `Fetch` returns Workflow A's cached response to Workflow B without performing a new outbound request [8](#0-7) .

## 3. HTTP Action Message Handling

### 3.1 Process Flow

1. **Request Reception**: Gateway receives HTTP action request from a workflow node
2. **Rate Limiting**: Validates node rate limits
3. **Request Parsing**: Extracts `OutboundHTTPRequest` from the JSON-RPC message
4. **Cache Check**: Determines if request should use cached response or fetch fresh data
5. **HTTP Execution**: Makes actual HTTP request to external endpoint
6. **Response Caching**: Stores cacheable responses (2xx, 4xx status codes) only if `CacheSettings.Store` is `true`
7. **Node Response**: Sends HTTP response back to requesting node

### 3.2 Caching Behavior

- **Cacheable Responses**: 2xx (success) and 4xx (client error) status codes.
- **Cache TTL**: Configurable, default 10 minutes
- **Cache Key**: Generated from workflow ID and request hash
- **Cache Invalidation**: Time-based expiration with periodic cleanup
- **Cache Strategy**: All cacheable responses are cached; Non-zero `CacheSettings.MaxAgeMs` determines whether to return a cached value or make a fresh request
- **Workflow Isolation**: Cache entries are scoped by workflow ID to prevent cross-workflow data leakage

// isExpiredOrNotCached returns true if the cached response is expired or not cached.
// IMPORTANT: this method does not lock the cache map. MUST be called with cacheMu write-locked.
func (rc *responseCache) isExpiredOrNotCached(req gateway.OutboundHTTPRequest) bool {
	cachedResp, exists := rc.cache[req.Hash()]
	if !exists || time.Now().After(cachedResp.storedAt.Add(rc.ttl)) {
		return true
	}
	return false
}

// Fetch fetches a response from the cache if it exists and
// the age of cached response is less than the max age of the request.
// If the cached response is expired or not cached, it fetches a new response from the fetchFn
// and caches the response if it is cacheable and storeOnFetch is true.
//
// The mutex is only held during cache map access (microseconds), not during fetchFn execution.
// Singleflight deduplicates concurrent requests to the same cache key so only one fetchFn
// runs per key, while requests to different keys execute in parallel.
// Cache read and write happen inside the singleflight callback to ensure the key remains
// in-flight until the result is stored, preventing duplicate fetches.
func (rc *responseCache) Fetch(ctx context.Context, req gateway.OutboundHTTPRequest, fetchFn func() gateway.OutboundHTTPResponse, storeOnFetch bool) gateway.OutboundHTTPResponse {
	cacheKey := req.Hash()
	cacheMaxAge := time.Duration(req.CacheSettings.MaxAgeMs) * time.Millisecond

	// Fast path: check cache without singleflight overhead.
	rc.cacheMu.RLock()
	cachedResp, exists := rc.cache[cacheKey]
	rc.cacheMu.RUnlock()
	if exists && cachedResp.storedAt.Add(cacheMaxAge).After(time.Now()) {
		rc.metrics.IncrementCacheHitCount(ctx, rc.lggr)
		return cachedResp.response
	}

	// Slow path: singleflight deduplicates concurrent fetches per key.
	// Cache check + store happen inside the flight so the key isn't released
	// until the result is cached, closing the race window between singleflight
	// completion and cache write.
	result, _, _ := rc.flight.Do(cacheKey, func() (any, error) {
		// Re-check cache: a previous flight may have just stored the result.
		rc.cacheMu.RLock()
		cachedResp, exists := rc.cache[cacheKey]
		rc.cacheMu.RUnlock()
		if exists && cachedResp.storedAt.Add(cacheMaxAge).After(time.Now()) {
			rc.metrics.IncrementCacheHitCount(ctx, rc.lggr)
			return cachedResp.response, nil
		}

		response := fetchFn()

		if storeOnFetch && isCacheableStatusCode(response.StatusCode) {
			rc.cacheMu.Lock()
			rc.cache[cacheKey] = &cachedResponse{
				response: response,
				storedAt: time.Now(),
			}
			rc.cacheMu.Unlock()
		}

		return response, nil
	})

	return result.(gateway.OutboundHTTPResponse)
}

// Set caches a response if it is cacheable (2xx or 4xx and cache is empty or expired for the given request)
func (rc *responseCache) Set(req gateway.OutboundHTTPRequest, response gateway.OutboundHTTPResponse) {
	rc.cacheMu.Lock()
	defer rc.cacheMu.Unlock()
	if isCacheableStatusCode(response.StatusCode) && rc.isExpiredOrNotCached(req) {
		rc.cache[req.Hash()] = &cachedResponse{
			response: response,
			storedAt: time.Now(),
		}
	}
}
