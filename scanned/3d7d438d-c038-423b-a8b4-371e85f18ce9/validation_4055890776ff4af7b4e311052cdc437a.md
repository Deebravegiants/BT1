## Finding [1](#0-0) 

### Title
CORS wildcard-origin allowlist bypass via unanchored suffix match in gateway HTTP server - (File: `core/services/gateway/network/httpserver.go`)

### Summary
The goshs advisory's root cause is a naive string-boundary check (`strings.HasPrefix(cleanPath, sftpRoot)`) used for a security boundary, allowing a sibling path (`goshsroot_evil`) to pass validation intended to stay within `goshsroot`. The Chainlink gateway's CORS origin check contains the analogous flaw: `isAllowedOrigin` in `core/services/gateway/network/httpserver.go` strips the `*.` wildcard marker and then checks `strings.HasSuffix(originHost, allowedHost)` without verifying a `.` boundary precedes the match, so an attacker-controlled host that merely *ends with* the allowed suffix (not an actual subdomain of it) is treated as an allowed origin.

### Finding Description
`isAllowedOrigin` iterates over configured `CORSAllowedOrigins` and, for wildcard entries (`*.example.com`), does: [2](#0-1) 
```go
if strings.HasPrefix(allowedHost, "*.") {
    allowedHost = allowedHost[2:]
    if strings.HasSuffix(originHost, allowedHost) {
        return true
    }
}
```
This strips `*.` to get `example.com` and then checks whether the request's `Origin` host ends with that string. This is a raw suffix comparison, not a domain-boundary check — exactly the same class of bug as goshs's raw prefix comparison. A malicious origin such as `evilexample.com` or `notexample.com` will satisfy `strings.HasSuffix("evilexample.com", "example.com")` even though it is not a subdomain of `example.com` at all; there is no requirement that the character immediately preceding the matched suffix be a literal `.`.

This check gates `handleRequest`, which sets `Access-Control-Allow-Origin` to the attacker-reflected `Origin` header when the bypass succeeds: [3](#0-2) 

`handleRequest` is the entry point for all unauthenticated/external traffic to the gateway's JSON-RPC HTTP endpoint (`ProcessRequest`), making this reachable by any unprivileged internet client that can control an `Origin` header and register a domain ending in the configured wildcard suffix (e.g. registering `evilchainlink.com` when the operator allowlists `*.chainlink.com`).

### Impact Explanation
This is an allowlist/CORS-origin bypass in the gateway's internet-facing HTTP server. An operator configuring `CORSAllowedOrigins: ["*.trusted-domain.com"]` intends to scope browser-based access to that domain and its subdomains only. Because of the unanchored suffix match, any domain that happens to end with `trusted-domain.com` (without an actual dot-delimited subdomain relationship) is granted the same CORS trust, allowing a malicious site to have its `fetch`/`XHR` responses from the gateway readable by its own JavaScript, and to set custom headers via preflight that would otherwise be blocked. If any downstream client relies on Origin-based access differentiation, or if credentials/cookies are ever added to this response path in the future, this becomes a full cross-origin data exfiltration / CSRF vector against the gateway.

### Likelihood Explanation
Exploitation only requires the attacker to control a domain string that ends with the configured allowed suffix and to have that origin's page make a cross-origin request to the gateway — no authentication or privileged access is needed. The bug is purely in string-matching logic, deterministic, and triggers on every CORS-enabled request.

### Recommendation
Replace the suffix check with a proper domain-boundary comparison: require an exact match or that the origin host equals `allowedHost` or ends with `"."+allowedHost` (i.e., the character immediately preceding the suffix must be a dot), mirroring the goshs fix of requiring `root` equality or `root+separator` prefix rather than a raw substring/prefix/suffix test. Add regression tests for sibling-domain cases (e.g., `evilexample.com` vs `*.example.com`), not just the intended subdomain cases.

### Proof of Concept
1. Configure the gateway with `CORSAllowedOrigins: ["*.trusted-domain.com"]` and `CORSEnabled: true`.
2. Send a request to the gateway HTTP endpoint with header `Origin: evil-trusted-domain.com` (note: no dot separator before `trusted-domain.com`, so it is not a real subdomain).
3. Observe that `isAllowedOrigin` returns `true` (`strings.HasSuffix("evil-trusted-domain.com", "trusted-domain.com")` is `true`), and the server reflects `Access-Control-Allow-Origin: evil-trusted-domain.com` in the response, granting the attacker's origin CORS trust it was never intended to receive. func (s *httpServer) isAllowedOrigin(origin string) bool {
```go
	originScheme, originHost, originPort, err := s.splitURL(origin)
	if err != nil {
		s.lggr.Debug("error parsing origin URL", err)
		return false
	}
	for _, allowed := range s.config.CORSAllowedOrigins {
		// probably better to do this once when server starts and store it in a map
		// this is an easier solution so we don't have to apply more changes to the code
		// just need to be careful when specifying allowed origins in the config file
		allowedScheme, allowedHost, allowedPort, err := s.splitURL(allowed)
		if err != nil {
			s.lggr.Debug("error parsing allowed origin URL", err)
			continue
		}
		// skip if the scheme doesn't match at all
		if originScheme != allowedScheme {
			continue
		}
		// skip if the port doesn't match at all
		if originPort != allowedPort {
			continue
		}
		// check for exact host match (e.g., remix.com)
		if originHost == allowedHost {
			return true
		}
		// check for wildcard host match (e.g., *.remix.com)
		if strings.HasPrefix(allowedHost, "*.") {
			allowedHost = allowedHost[2:]
			if strings.HasSuffix(originHost, allowedHost) {
				return true
			}
		}
	}
	return false
}
```

```go
func (s *httpServer) handleRequest(w http.ResponseWriter, r *http.Request) {
	if s.config.CORSEnabled {
		origin := r.Header.Get("Origin")
		if s.isAllowedOrigin(origin) {
			w.Header().Set("Access-Control-Allow-Origin", origin)
			w.Header().Set("Access-Control-Allow-Methods", "GET, POST, OPTIONS")
			w.Header().Set("Access-Control-Allow-Headers", "Content-Type")
		}

		// handle preflight requests
		if r.Method == http.MethodOptions {
			w.WriteHeader(http.StatusNoContent)
			return
		}
	}
```
