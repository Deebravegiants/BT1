Based on my investigation, I found a concrete analog to the ml-logger arbitrary file read bug in the `newFileFetcher` function used by chainlink's workflow artifact syncer.

### Title
Insufficient path validation in `file://` scheme fetcher allows path prefix bypass / traversal outside base directory - (File: core/services/workflows/syncer/v2/fetcher.go)

### Summary
`NewFetcherFunc` in `core/services/workflows/syncer/v2/fetcher.go` supports a `file://` URL scheme via `newFileFetcher`, which is used to fetch workflow binary/config artifacts based on a URL supplied in the `ghcapabilities.Request.URL` field [1](#0-0) . The confinement check compares the resolved path against the base path using a raw string-prefix comparison rather than a proper filesystem boundary check.

### Finding Description
Inside `newFileFetcher`, the request-supplied `req.URL` is parsed, cleaned with `filepath.Clean`, optionally joined to `basePath`, and then "validated" only with:
```go
if !strings.HasPrefix(fullPath, basePath+string(filepath.Separator)) && fullPath != basePath {
``` [2](#0-1) 
This is a string-prefix check, not a real containment check. Any sibling directory that happens to share the `basePath` as a string prefix (e.g. `basePath` = `/data/artifacts` and an attacker-supplied path resolving to `/data/artifacts-secret/...`) would incorrectly pass, because `strings.HasPrefix` only checks that `basePath+separator` is a string prefix of `fullPath`, not that `fullPath` is a child directory strictly within `basePath` in a canonicalized sense. Additionally, absolute paths in `req.URL` are accepted outright when `filepath.IsAbs(fullPath)` is true — the code only joins to `basePath` when the path is *not* absolute; an absolute path is used as-is and only checked with the same flawed prefix comparison, allowing any absolute path that begins with the `basePath` string (or exactly equals it) to be read via `os.ReadFile(fullPath)` [3](#0-2) .

The `req.URL` value that reaches this fetcher originates from `BinaryURL`/`ConfigURL` fields on the on-chain `WorkflowRegisteredEvent`, which are attacker/workflow-owner-controlled and flow through `Store.FetchWorkflowArtifacts` → `h.fetchFn` into the fetcher unmodified [4](#0-3) , and originate from `createWorkflowSpec`/`workflowRegisteredEvent` in the syncer handler that processes registry events for workflows registered by any linked workflow owner [5](#0-4) .

### Impact Explanation
If a node operator configures the workflow syncer to use a `file://` base URL (a supported, documented configuration path per `NewFetcherFunc`), a workflow owner registering a workflow with a crafted `BinaryURL`/`ConfigURL` could potentially read files outside the intended artifacts directory due to the imprecise prefix check, leading to information disclosure (CWE-200), directly analogous to the ml-logger `key`-parameter file disclosure bug.

### Likelihood Explanation
Likelihood is limited by the requirement that the node operator has configured the fetcher with the `file://` scheme (as opposed to HTTP/HTTPS via the gateway, which is the primary production path) and that the attacker (a linked workflow owner) can influence `BinaryURL`/`ConfigURL` in the registry event, which is plausible for any organization member permitted to register workflows.

### Recommendation
Replace the string-prefix containment check with a proper boundary check, e.g., resolve both `basePath` and `fullPath` with `filepath.EvalSymlinks`/absolute cleaning and verify `fullPath == basePath || strings.HasPrefix(fullPath, basePath+string(filepath.Separator))` only after confirming `fullPath`'s directory component structurally nests under `basePath` (not just as a string prefix), and reject absolute request paths outright unless explicitly intended, rather than allowing them to bypass the `filepath.Join` confinement step.

### Proof of Concept
1. Configure the workflow syncer with `NewFetcherFunc("file:///data/artifacts", lggr)`.
2. As a workflow owner, register a workflow with `BinaryURL` set to an absolute path such as `file:///data/artifacts-internal/secret.bin` (which is not inside `/data/artifacts` but shares its string prefix) or to a path that resolves via `..` segments to a sibling location satisfying the same flawed prefix test.
3. The syncer's `createWorkflowSpec` → `FetchWorkflowArtifacts` → `newFileFetcher` will call `os.ReadFile(fullPath)` on the attacker-controlled path [6](#0-5) , disclosing file contents outside the intended base directory back through the workflow spec storage.

// NewFetcher creates a new FetcherFunc based on the provided URL configuration
// The implementation supports both file and HTTP(S) URLs and bypasses the gateway
func NewFetcherFunc(baseURL string, lggr logger.Logger) (types.FetcherFunc, error) {
	if baseURL == "" {
		return nil, errors.New("baseURL cannot be empty")
	}

	u, err := url.Parse(baseURL)
	if err != nil {
		return nil, fmt.Errorf("invalid URL: %w", err)
	}

	switch u.Scheme {
	case "file":
		// Ensure the basePath is absolute
		if !filepath.IsAbs(u.Path) {
			return nil, fmt.Errorf("basePath must be an absolute path, got: %s", u.Path)
		}
		return newFileFetcher(u.Path, lggr), nil
	case "http", "https":
		return newHTTPFetcher(baseURL, lggr), nil
	default:
		return nil, fmt.Errorf("unsupported URL scheme: %s", u.Scheme)
	}
}

func newFileFetcher(basePath string, lggr logger.Logger) types.FetcherFunc {
	return func(ctx context.Context, messageID string, req ghcapabilities.Request) ([]byte, error) {
		select {
		case <-ctx.Done():
			return nil, ctx.Err()
		default:
		}

		// the incoming request URL is expected to be a relative path or a path within the basePath
		if req.URL == "" {
			return nil, errors.New("request URL cannot be empty")
		}
		u, err := url.Parse(req.URL)
		if err != nil {
			return nil, fmt.Errorf("invalid URL: %w", err)
		}
		// Confidential workflows register with HTTP URLs (for the enclave).
		// Extract the filename so the file fetcher can find the local copy.
		if u.Scheme == "http" || u.Scheme == "https" {
			u.Path = filepath.Base(u.Path)
			if u.Path == "." || u.Path == "/" {
				return nil, errors.New("HTTP URL has no filename in path")
			}
		}
		fullPath := filepath.Clean(u.Path)

		// ensure that the incoming request URL is either relative or absolute but within the basePath
		if !filepath.IsAbs(fullPath) {
			// If it's not absolute, we assume it's relative to the basePath
			fullPath = filepath.Join(basePath, fullPath)
		}
		if !strings.HasPrefix(fullPath, basePath+string(filepath.Separator)) && fullPath != basePath {
			return nil, fmt.Errorf("request URL %s is not within the basePath %s", fullPath, basePath)
		}

		lggr.Debugw("Fetching file", "messageID", messageID, "path", fullPath, "workflowID", req.WorkflowID)

		data, err := os.ReadFile(fullPath)
		if err != nil {
			return nil, fmt.Errorf("failed to read file: %w", err)
		}
		return data, nil
```
