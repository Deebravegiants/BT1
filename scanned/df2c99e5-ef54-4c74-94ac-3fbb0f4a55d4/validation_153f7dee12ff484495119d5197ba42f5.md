### Title
CORS wildcard origin allowlist bypass via unanchored suffix match - (File: core/services/gateway/network/httpserver.go)

### Summary
The Gateway's HTTP server implements CORS origin validation in `isAllowedOrigin`. For wildcard entries in `CORSAllowedOrigins` (e.g. `https://*.remix.org`), it strips the `*.` prefix and then checks the client-supplied `Origin` header's host with a raw `strings.HasSuffix` comparison, without verifying that the match is anchored on a subdomain boundary (i.e. that the character preceding the suffix is a `.`).

### Finding Description
`isAllowedOrigin` parses both the request `Origin` and each configured allowed origin into scheme/host/port, then for wildcard-configured hosts does:
```go
if strings.HasPrefix(allowedHost, "*.") {
    allowedHost = allowedHost[2:]
    if strings.HasSuffix(originHost, allowedHost) {
        return true
    }
}
``` [1](#0-0) 

This is the exact bug class described in the Rack advisory: relying on `end_with?`/`HasSuffix` for host allowlisting without validating a proper domain boundary. Given a configured wildcard `https://*.remix.org`, an attacker-registered domain such as `https://evilremix.org` or `https://attacker-remix.org` will pass `strings.HasSuffix("evilremix.org", "remix.org")` because Go's `strings.HasSuffix` performs a raw substring match with no notion of hostname label boundaries. The stripped `allowedHost` also has no leading `.` re-added before the comparison, so there's no anchor requiring the origin to actually be a subdomain of `remix.org`.

The `handleRequest` function then reflects the attacker-controlled `Origin` value back in `Access-Control-Allow-Origin` and enables `Access-Control-Allow-Methods`/`Access-Control-Allow-Headers`, without requiring the "host is syntactically a real subdomain" check the advisory recommends: [2](#0-1) 

Unlike the Rack case (where the character class itself is over-permissive), here the parsing of `Origin` uses `url.Parse` + `net.SplitHostPort`, so this is not identical in root cause, but it reproduces the same class of vulnerability: a naive substring/suffix host check used for allowlisting, without hostname-boundary validation, enabling bypass by any attacker who can register or control a domain that merely ends with the trusted suffix.

### Impact Explanation
This is the Gateway's public HTTP endpoint (`config.Path`), reachable by unprivileged/unauthenticated clients over the network as configured in `NewHTTPServer`. [3](#0-2)  A successful bypass lets an attacker-controlled origin (e.g. a browser-based client hosted on `evilremix.org`) receive CORS headers granting it the ability to make credentialed cross-origin requests to the Gateway API and read responses that should only be accessible to origins under the legitimately trusted `*.remix.org` allowlist. This can expose Gateway responses (job/task results, handler responses) to an origin the operator did not intend to trust, i.e. cross-user/cross-origin response confusion enabled by an allowlist bypass — directly matching the "Impact" criteria of allowlist bypass / cross-user response confusion.

### Likelihood Explanation
Exploitation requires (a) the Gateway operator to configure at least one wildcard entry in `CORSAllowedOrigins` (a supported and documented feature, see `sample_config.toml`), and (b) an attacker registering or controlling a domain name that has the trusted suffix as a substring at the end (e.g. `evil<trusted-domain>`), which is inexpensive and requires no privileged access — only crafting an `Origin` header, something any web client fully controls. No authentication or special network position is needed; it is exploitable purely from an unprivileged client sending an HTTP request with a spoofed `Origin` header.

### Recommendation
Anchor the wildcard suffix match on a subdomain boundary. For example, after stripping `*.`, require:
```go
if originHost == allowedHost || strings.HasSuffix(originHost, "."+allowedHost) {
    return true
}
```
This ensures `evilremix.org` does not match `*.remix.org`, while `sub.remix.org` still does. The same principle applies broadly: never use bare `HasPrefix`/`HasSuffix` for security-relevant host/origin comparisons — always validate on label (`.`) boundaries or perform exact matches after canonicalizing/parsing the host.

### Proof of Concept
1. Configure the Gateway with `CORSAllowedOrigins = ["https://*.remix.org"]` and `CORSEnabled = true`.
2. Send an HTTP request to the Gateway's configured `Path` with header `Origin: https://evilremix.org`.
3. Observe that `isAllowedOrigin` returns `true` because `strings.HasSuffix("evilremix.org", "remix.org")` is `true`, and the server responds with `Access-Control-Allow-Origin: https://evilremix.org`, `Access-Control-Allow-Methods: GET, POST, OPTIONS`, and `Access-Control-Allow-Headers: Content-Type`, granting the attacker's origin credentialed cross-origin access despite not being a genuine subdomain of `remix.org`. func (s *httpServer) isAllowedOrigin(origin string) bool {
	originScheme, originHost, originPort, err := s.splitURL(origin)
	if err != nil {
		s.lggr.Debug("error parsing origin URL", err)
		return false
	}
	for _, allowed := range s.config.CORSAllowedOrigins {
		// probably better to do this once when server starts and store it in a map
		// this is an easier solution so we don't have to apply more changes to the code
		// just need to be careful when specifying allowed origins in the config file
		allowedScheme, allowedHost, allowedPort, err := s.splitURL(allowed)
		if err != nil {
			s.lggr.Debug("error parsing allowed origin URL", err)
			continue
		}
		// skip if the scheme doesn't match at all
		if originScheme != allowedScheme {
			continue
		}
		// skip if the port doesn't match at all
		if originPort != allowedPort {
			continue
		}
		// check for exact host match (e.g., remix.com)
		if originHost == allowedHost {
			return true
		}
		// check for wildcard host match (e.g., *.remix.com)
		if strings.HasPrefix(allowedHost, "*.") {
			allowedHost = allowedHost[2:]
			if strings.HasSuffix(originHost, allowedHost) {
				return true
			}
		}
	}
	return false
}

func (s *httpServer) handleRequest(w http.ResponseWriter, r *http.Request) {
	if s.config.CORSEnabled {
		origin := r.Header.Get("Origin")
		if s.isAllowedOrigin(origin) {
			w.Header().Set("Access-Control-Allow-Origin", origin)
			w.Header().Set("Access-Control-Allow-Methods", "GET, POST, OPTIONS")
			w.Header().Set("Access-Control-Allow-Headers", "Content-Type")
		}

		// handle preflight requests
		if r.Method == http.MethodOptions {
			w.WriteHeader(http.StatusNoContent)
			return
		}
	}
