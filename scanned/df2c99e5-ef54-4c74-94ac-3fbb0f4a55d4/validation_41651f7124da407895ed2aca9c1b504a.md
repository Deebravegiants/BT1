### Title
Replay-guard digest is permanently consumed before the Vault operation actually succeeds, permanently locking out legitimate retries of a failed request - (File: core/capabilities/vault/authorizer.go)

### Summary
The digest-based replay guard in the Vault gateway authorization pipeline records a request's digest as "seen" as soon as authorization succeeds, before the corresponding secrets operation (create/update/delete/list) has actually completed. If any step downstream of authorization fails (ciphertext-size validation, param stamping, or the underlying `SecretsService` call), the client's identical retry of the same request is rejected with `ErrRequestAlreadySeen` until the original digest's TTL expires, even though the original operation never took effect.

### Finding Description
`authorizer.AuthorizeRequest` calls `a.replayGuard.CheckAndRecord(authResult.Digest(), authResult.ExpiresAt())` immediately after the allowlist/JWT auth succeeds, and returns success at that point: [1](#0-0) 

This happens inside `GatewayVaultRequestProcessor.authorizeAndStamp`, which is invoked *before* the request has been fully processed — the create/update flow still runs `ValidateCiphertextSizes` afterward, and the actual RPC dispatch to `SecretsService.CreateSecrets`/`UpdateSecrets`/`DeleteSecrets` happens later in `gw_handler.go`: [2](#0-1) [3](#0-2) 

The replay guard itself simply marks a digest "seen" and rejects any later `CheckAndRecord` call with the same digest until its expiry: [4](#0-3) 

This is structurally analogous to the reported bug class: an early, optimistic state mutation (shares burned / digest marked used) is committed based on an expected successful outcome, but a later step in the same call chain can still fail (asset transfer fails silently / `ValidateCiphertextSizes`, param stamping, or `SecretsService` call fails), leaving the actor’s legitimate operation "spent" without having actually occurred, and with no path to redo it under the same request identity until the record expires.

### Impact Explanation
An unprivileged, otherwise-legitimate workflow owner whose vault request (`secrets.create`/`update`/`delete`) fails for reasons unrelated to authorization (e.g., a ciphertext-size validation error added after auth, a transient `SecretsService` backend error, or a marshaling failure in `stamp()`) will have their request's digest permanently marked as already-processed. Any automatic or manual retry using the same request contents (same digest) is rejected by the replay guard with `ErrRequestAlreadySeen` for the lifetime of the authorization (`expiresAt`), producing a denial of service against the specific secret operation the user intended to perform — the operation can neither complete nor be resubmitted identically until expiry. This mirrors the "funds locked" impact pattern (state consumed, desired effect never achieved, no remediation path) but here the consumed resource is the digest-based authorization slot rather than shares/assets.

### Likelihood Explanation
This triggers on any downstream failure occurring after authorization succeeds but before the vault operation is durably applied — which includes routine, non-attacker-controlled failure modes such as backend/database errors in `SecretsService`, ciphertext size limit violations, or JSON marshaling errors during stamping. Because these are ordinary operational failure paths (not requiring a malicious actor), the likelihood of hitting this window during normal usage is moderate, though the effect (a stuck retry) is only visible in the window before the auth record expires.

### Recommendation
Defer replay-guard recording until after the full request pipeline (validation, stamping, and the underlying `SecretsService` call) has succeeded, or make the replay guard's success recording conditional/rollback-able if a later stage fails. Concretely, in `authorizer.AuthorizeRequest`, do not call `a.replayGuard.CheckAndRecord` unconditionally on auth success; instead expose a way for the caller (`GatewayVaultRequestProcessor`/`GatewayHandler`) to commit the digest only once `handleSecretsCreate`/`handleSecretsUpdate`/`handleSecretsDelete` have returned a non-error response, or provide an explicit "release"/"un-record" path invoked on any post-auth failure so the same digest can be retried immediately.

### Proof of Concept
Not independently verifiable without live execution; based on static code review of `core/capabilities/vault/authorizer.go`, `core/capabilities/vault/gateway_vault_request_processor.go`, and `core/capabilities/vault/gw_handler.go`, the following sequence is supported by the code:
1. Client sends `secrets.create` with digest `D` and `expiresAt` `T`.
2. `AllowListBasedAuth`/`JWTBasedAuth` succeeds; `authorizer.AuthorizeRequest` calls `replayGuard.CheckAndRecord(D, T)`, which succeeds and marks `D` as seen.
3. Later in the same call, `ValidateCiphertextSizes` fails (or `SecretsService.CreateSecrets` returns an error in `handleSecretsCreate`), so the overall create operation fails and an error response is sent to the gateway.
4. Client retries the identical request (same digest `D`) before `T` expires.
5. `replayGuard.CheckAndRecord(D, T)` now returns `ErrRequestAlreadySeen`, and the retry is rejected with "request was already authorized previously," even though the secret was never actually created.

func (a *authorizer) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	authResult, err := a.authorizeRequest(ctx, req)
	if err != nil {
		return nil, err
	}
	if authResult == nil {
		err = errors.New("auth mechanism returned nil auth result")
		a.lggr.Errorw("auth mechanism returned nil auth result", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "")
		return nil, err
	}
	if err := a.replayGuard.CheckAndRecord(authResult.Digest(), authResult.ExpiresAt()); err != nil {
		a.lggr.Debugw("replay guard rejected request", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "digest", authResult.Digest(), "expiresAt", authResult.ExpiresAt(), "hasAuth", req.Auth != "", "error", err)
		return nil, err
	}
	if ownerErr := validateSecretOwnersMatchAuthorized(req, authResult.AuthorizedOwner()); ownerErr != nil {
		a.lggr.Errorw("owner binding rejected request", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "hasAuth", req.Auth != "", "error", ownerErr)
		return nil, ownerErr
	}
	a.lggr.Debugw("request authorized", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "digest", authResult.Digest(), "expiresAt", authResult.ExpiresAt(), "hasAuth", req.Auth != "")
	return authResult, nil
}

func (p *GatewayVaultRequestProcessor) processCreateSecretsRequest(
	ctx context.Context,
	req *jsonrpc.Request[json.RawMessage],
	publicKey *tdh2easy.PublicKey,
) (*AuthorizedGatewayVaultRequest, error) {
	if req.Params == nil {
		return nil, InvalidVaultParamsError{Method: req.Method, Err: errors.New("request params must not be nil")}
	}

	var createReq vaultcommon.CreateSecretsRequest
	if err := json.Unmarshal(*req.Params, &createReq); err != nil {
		return nil, InvalidVaultParamsError{Method: req.Method, Err: err}
	}
	if p.stripOwnerPrefixForAuth {
		createReq.RequestId = req.ID
		if err := marshalVaultParams(req, &createReq); err != nil {
			return nil, InvalidVaultParamsError{Method: req.Method, Err: err}
		}
	} else {
		createReq.RequestId = coalesceRequestID(createReq.RequestId, req.ID)
	}

	skipLabelValidation := publicKey == nil
	if err := p.validator.ValidateEncryptedSecretsStructure(ctx, publicKey, createReq.RequestId, createReq.EncryptedSecrets, skipLabelValidation); err != nil {
		return nil, p.validationError(req, err)
	}

	authorized, err := p.authorizeAndStamp(ctx, req, func(prefixedRequestID string) error {
		createReq.RequestId = prefixedRequestID
		vaultutils.ApplyEncryptedSecretNamespaceDefaults(createReq.EncryptedSecrets)
		return marshalVaultParams(req, &createReq)
	})
	if err != nil {
		return nil, err
	}

	if err := p.validator.ValidateCiphertextSizes(ctx, authorized.AuthResult.AuthorizedOwner(), createReq.EncryptedSecrets); err != nil {
		return nil, p.validationError(req, err)
	}
	return authorized, nil
}

func (h *GatewayHandler) HandleGatewayMessage(ctx context.Context, gatewayID string, req *jsonrpc.Request[json.RawMessage]) (err error) {
	reqLggr := h.requestLogger(req, gatewayID)
	reqLggr.Debugw("received message from gateway", "req", req)

	var response *jsonrpc.Response[json.RawMessage]
	var authResult *AuthResult

	switch req.Method {
	case vaulttypes.MethodSecretsCreate, vaulttypes.MethodSecretsUpdate:
		publicKey, pkErr := h.getMasterPublicKey(ctx)
		if pkErr != nil {
			response = h.gatewayErrorResponse(ctx, gatewayID, req, pkErr)
			break
		}
		authorized, pipelineErr := h.requestProcessor.ProcessRequest(ctx, req, publicKey)
		if pipelineErr != nil {
			response = h.gatewayErrorResponse(ctx, gatewayID, req, pipelineErr)
			break
		}
		authResult = authorized.AuthResult
	case vaulttypes.MethodSecretsDelete, vaulttypes.MethodSecretsList:
		authorized, pipelineErr := h.requestProcessor.ProcessRequest(ctx, req, nil)
		if pipelineErr != nil {
			response = h.gatewayErrorResponse(ctx, gatewayID, req, pipelineErr)
			break
		}
		authResult = authorized.AuthResult
	case vaulttypes.MethodPublicKeyGet:
		response = h.handlePublicKeyGet(ctx, gatewayID, req)
	default:
		response = h.errorResponse(ctx, gatewayID, req, api.UnsupportedMethodError, errors.New("unsupported method: "+req.Method))
	}

	if response == nil {
		switch req.Method {
		case vaulttypes.MethodSecretsCreate:
			response = h.handleSecretsCreate(ctx, gatewayID, req)
		case vaulttypes.MethodSecretsUpdate:
			response = h.handleSecretsUpdate(ctx, gatewayID, req)
		case vaulttypes.MethodSecretsDelete:
			response = h.handleSecretsDelete(ctx, gatewayID, req)
		case vaulttypes.MethodSecretsList:
			response = h.handleSecretsList(ctx, gatewayID, req, authResult)
		}
	}

	if err = h.gatewayConnector.SendToGateway(ctx, gatewayID, response); err != nil {
		reqLggr.Errorw("Failed to send message to gateway", "error", err)
		return err
	}

	reqLggr.Infow("Sent message to gateway", "resp", response)
	h.metrics.requestSuccess.Add(ctx, 1, metric.WithAttributes(
		attribute.String("gateway_id", gatewayID),
	))
	return nil
}

// CheckAndRecord returns ErrRequestAlreadySeen if the digest was previously
// recorded and has not yet expired. Otherwise it records the digest with
// the given expiry timestamp (unix seconds, UTC).
//
// Expired entries are cleaned up on every call.
func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}
