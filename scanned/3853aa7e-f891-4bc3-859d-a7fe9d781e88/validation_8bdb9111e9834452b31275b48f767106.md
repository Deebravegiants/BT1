## Finding: Incomplete Origin Validation in Chainlink Gateway HTTP Server (CORS Wildcard Bypass)

The reported Bokeh vulnerability (CVE-2026-21883) is a classic **CWE-1385 "Missing Origin Validation"** bug: a wildcard/subdomain host-matching routine that fails to enforce a proper boundary (dot separator) between the matched suffix and the rest of the hostname, allowing an attacker-registered domain like `example.com.attacker.com` (or conversely a domain that merely *ends with* the allowed string) to pass validation.

An analogous flaw exists in the Chainlink Gateway's internet-facing HTTP server.

### Title
Incomplete origin/hostname validation in Gateway `isAllowedOrigin` wildcard matching allows CORS bypass via unanchored suffix comparison - (File: core/services/gateway/network/httpserver.go)

### Summary
The Chainlink Gateway's `httpServer.isAllowedOrigin` function validates the `Origin` header against a configured allowlist (`CORSAllowedOrigins`) before reflecting it back in `Access-Control-Allow-Origin`. Its wildcard-matching branch strips the `*.` prefix from an allowed pattern and then performs a raw `strings.HasSuffix` comparison against the request's hostname, without checking that the preceding character is a `.` (domain boundary). This is structurally the same root-cause defect as the Bokeh `match_host` flaw: absence of a boundary check turns a "subdomain-of" check into a "string-ends-with" check.

### Finding Description [1](#0-0) 

```go
func (s *httpServer) isAllowedOrigin(origin string) bool {
	...
	for _, allowed := range s.config.CORSAllowedOrigins {
		...
		// check for exact host match (e.g., remix.com)
		if originHost == allowedHost {
			return true
		}
		// check for wildcard host match (e.g., *.remix.com)
		if strings.HasPrefix(allowedHost, "*.") {
			allowedHost = allowedHost[2:]
			if strings.HasSuffix(originHost, allowedHost) {
				return true
			}
		}
	}
	return false
}
```

If an operator configures `CORSAllowedOrigins` with a wildcard entry such as `https://*.mycompany.com` (a legitimate, documented pattern per [2](#0-1) ), the code strips the `*.` to get `mycompany.com`, then checks `strings.HasSuffix(originHost, "mycompany.com")`. This check succeeds for `originHost = "attackermycompany.com"` just as readily as for the intended `foo.mycompany.com`, because `HasSuffix` performs a raw character comparison with no requirement that a `.` immediately precede the matched suffix — exactly the same class of defect as the Bokeh `zip()`-based `match_host` bug (both fail to validate a segment/label boundary, only checking that one string is a "tail" of the other).

This function is invoked from `handleRequest` for every incoming Gateway HTTP request when `CORSEnabled` is set: [3](#0-2) . The `httpServer` is the transport used by the Gateway's WebAPI/Capabilities-v2, Vault, and Confidential Relay handlers to serve responses to external, unprivileged HTTP clients (per the gateway's role as the DON's internet-facing endpoint for `web_api_target`/`web_api_trigger`/vault/compute-action requests).

### Impact Explanation
When the flawed wildcard match succeeds for an attacker-controlled hostname, the Gateway reflects that attacker origin into `Access-Control-Allow-Origin`: [4](#0-3) . A victim lured to a page hosted on a domain crafted to satisfy the unanchored suffix check (e.g. `attackermycompany.com` against an allowlist entry `*.mycompany.com`) can then issue cross-origin `fetch`/`XHR` requests to the Gateway and have the browser allow the malicious page's JavaScript to read the JSON-RPC response body — which may contain WebAPI/capability responses, vault-handler data, or confidential-relay payloads intended only for legitimately allowlisted subdomains. This is the same "cross-user response confusion via incomplete origin validation" bug class as the Bokeh CSWSH advisory, applied to the Gateway's CORS enforcement rather than a raw WebSocket `CheckOrigin`.

### Likelihood Explanation
Exploitability depends on an operator having configured a wildcard entry in `CORSAllowedOrigins` (a supported, documented configuration pattern, see sample configs referencing `CORSAllowedOrigins`/`CORSEnabled` in `core/scripts/gateway/sample_config.toml` and `core/scripts/gateway/sample_config_tls.toml`). Registering a domain that satisfies an unanchored suffix match is trivial and entirely within an unprivileged attacker's control (no special network position or privileges required), matching the "unprivileged-actor analog" scope of this review.

### Recommendation
Require the wildcard match to validate a domain-label boundary rather than a raw suffix, e.g.:
```go
if strings.HasPrefix(allowedHost, "*.") {
    suffix := allowedHost[1:] // ".mycompany.com" (keep leading dot)
    if strings.HasSuffix(originHost, suffix) && originHost != suffix[1:] {
        return true
    }
}
```
This mirrors the Bokeh project's fix, which corrected `match_host` to require full-label equality for every matched segment instead of relying on unguarded prefix/suffix comparisons.

### Proof of Concept
1. Operator configures Gateway with `CORSEnabled = true` and `CORSAllowedOrigins = ["https://*.mycompany.com"]`.
2. Attacker registers `attackermycompany.com` and hosts a malicious page there.
3. Victim (with legitimate access/credentials to the Gateway) visits the attacker page.
4. The page's JavaScript issues `fetch("https://gateway.mycompany.internal/...", {mode: "cors"})` with `Origin: https://attackermycompany.com`.
5. `isAllowedOrigin` computes `allowedHost = "mycompany.com"` and evaluates `strings.HasSuffix("attackermycompany.com", "mycompany.com")`, which returns `true`, so the Gateway responds with `Access-Control-Allow-Origin: https://attackermycompany.com`.
6. The browser permits the attacker page's JavaScript to read the response body, which the Gateway operator intended to restrict to genuine `*.mycompany.com` subdomains.

func (s *httpServer) isAllowedOrigin(origin string) bool {
	originScheme, originHost, originPort, err := s.splitURL(origin)
	if err != nil {
		s.lggr.Debug("error parsing origin URL", err)
		return false
	}
	for _, allowed := range s.config.CORSAllowedOrigins {
		// probably better to do this once when server starts and store it in a map
		// this is an easier solution so we don't have to apply more changes to the code
		// just need to be careful when specifying allowed origins in the config file
		allowedScheme, allowedHost, allowedPort, err := s.splitURL(allowed)
		if err != nil {
			s.lggr.Debug("error parsing allowed origin URL", err)
			continue
		}
		// skip if the scheme doesn't match at all
		if originScheme != allowedScheme {
			continue
		}
		// skip if the port doesn't match at all
		if originPort != allowedPort {
			continue
		}
		// check for exact host match (e.g., remix.com)
		if originHost == allowedHost {
			return true
		}

			allowedHost = allowedHost[2:]

				return true
			}
		}
	}
	return false
}

	if s.config.CORSEnabled {
		origin := r.Header.Get("Origin")
