Based on my research, I found a legitimate analog in `pallet-uniques` (and structurally the same pattern exists in `pallet-nfts`): `transfer_ownership` moves the collection's `owner` field but leaves the `issuer`, `admin`, and `freezer` roles pointing at whichever accounts held them before the sale — exactly the "stale privileged role survives an ownership handoff" pattern described in the M-22 report.

### Title
Stale `Admin`/`Issuer`/`Freezer` roles survive collection ownership transfer, letting the previous owner force-transfer or burn NFTs from the new owner - (File: `substrate/frame/uniques/src/lib.rs`, `substrate/frame/nfts/src/features/transfer.rs`)

### Summary
`pallet-uniques::transfer_ownership` (and the structurally identical `pallet-nfts::do_transfer_ownership`) only updates the collection's `owner` field. The `admin`, `issuer`, and `freezer` roles — which by default are set to the creator/owner and which retain destructive powers over every item in the collection — are never reset or transferred along with ownership. This is the same root cause as M-22: an "ownership" handoff (NFT/collection transfer) does not propagate to a separately-tracked privileged role that the new owner reasonably expects to control.

### Finding Description
In `pallet-uniques`, `CollectionDetails` stores four independent accounts: [1](#0-0) 

`transfer_ownership` only mutates `details.owner`; `admin`, `issuer`, and `freezer` are left untouched: [2](#0-1) 

The `admin` field is explicitly documented as able to "thaw tokens, force transfers and burn tokens from any account" — i.e. it can move or destroy any item in the collection without the item owner's consent, similarly to how `pallet-nfts` role gating works via `CollectionRole::Admin`/`Freezer` in `substrate/frame/nfts/src/features/roles.rs` and `substrate/frame/nfts/src/features/lock.rs`. [3](#0-2) 

In `pallet-nfts`, the equivalent `do_transfer_ownership` likewise only rewrites `details.owner`, never touching `CollectionRoleOf` team-role storage; those roles are only reset by an explicit, separate `set_team` call, whose helper `do_set_team` shows that role assignment is completely decoupled from the owner field: [4](#0-3) [5](#0-4) 

So exactly as in the Sherlock report — where `veNFTVault` ownership (receiptID) transfer did not update the `managerAddress` used for privileged actions like `claimBribesMultiple()` — here the "collection owner" NFT-style handoff does not update the `admin`/`issuer`/`freezer` "manager" roles used for privileged actions like force-transfer, burn, and freeze.

### Impact Explanation
A seller who lists/sells a `uniques`/`nfts` collection (transferring `owner` via the two-step `set_accept_ownership` + `transfer_ownership` flow) retains the `admin` role by default. After the sale completes and the buyer believes they now fully control the collection and its items, the former owner (still `admin`) can:
- Force-transfer any item in the collection to themselves (`admin.transfer` semantics — "force transfers ... from any account"), effectively stealing NFTs that were part of the deal or minted afterward by the new owner.
- Burn items belonging to the new owner or other holders.
- Freeze/thaw items to grief or block resale.

This is a direct asset-theft path analogous to the bribe theft in the original report, not merely a griefing/DoS issue.

### Likelihood Explanation
Likelihood is moderate-to-high for any marketplace or secondary-sale flow built on `pallet-uniques`/`pallet-nfts` where buyers assume `transfer_ownership` conveys full control. Nothing in the dispatchable's success path or its doc comment (`substrate/frame/nfts/README.md` lines 75-77) warns that team roles are untouched; a runtime/dApp integrator or end user could easily overlook the need to also call `set_team` atomically with the ownership transfer. No privileged access is required by the attacker — the "attacker" is simply the natural previous owner exploiting a role they already held, exactly mirroring the external report's threat model.

### Recommendation
When `transfer_ownership`/`do_transfer_ownership` succeeds, either:
1. Reset `issuer`, `admin`, and `freezer` to the new owner by default (matching the mental model that ownership transfer conveys full control), or
2. Require the caller to atomically pass new team-role assignments as part of `transfer_ownership`, or
3. At minimum, clearly document (and ideally enforce in tooling/wallets) that `set_team` must be called in the same transaction/batch as `transfer_ownership` to avoid stale privileged roles.

### Proof of Concept
1. Account A creates a `uniques`/`nfts` collection; by default `owner == issuer == admin == freezer == A`.
2. Account B calls `set_accept_ownership(Some(collection))`.
3. A calls `transfer_ownership(collection, B)` — `details.owner` becomes `B`, but `details.admin` (uniques) / `CollectionRoleOf` (nfts) still names `A`.
4. B, believing they now fully own and control the collection, mints/holds items in it.
5. A, still holding the `Admin` role, calls `Uniques::transfer` (admin force-transfer path) or `Nfts` admin-equivalent to move or burn B's items without B's consent — asset theft complete.

		pub fn transfer_ownership(
			origin: OriginFor<T>,
			collection: T::CollectionId,
			new_owner: AccountIdLookupOf<T>,
		) -> DispatchResult {
			let origin = ensure_signed(origin)?;
			let new_owner = T::Lookup::lookup(new_owner)?;

			let acceptable_collection = OwnershipAcceptance::<T, I>::get(&new_owner);
			ensure!(acceptable_collection.as_ref() == Some(&collection), Error::<T, I>::Unaccepted);

			Collection::<T, I>::try_mutate(collection.clone(), |maybe_details| {
				let details = maybe_details.as_mut().ok_or(Error::<T, I>::UnknownCollection)?;
				ensure!(origin == details.owner, Error::<T, I>::NoPermission);
				if details.owner == new_owner {
					return Ok(());
				}

				// Move the deposit to the new owner.
				T::Currency::repatriate_reserved(
					&details.owner,
					&new_owner,
					details.total_deposit,
					Reserved,
				)?;

				CollectionAccount::<T, I>::remove(&details.owner, &collection);
				CollectionAccount::<T, I>::insert(&new_owner, &collection, ());

				details.owner = new_owner.clone();
				OwnershipAcceptance::<T, I>::remove(&new_owner);
				frame_system::Pallet::<T>::dec_consumers(&new_owner);

				Self::deposit_event(Event::OwnerChanged { collection, new_owner });
				Ok(())
			})
		}

	pub(crate) fn do_transfer_ownership(
		origin: T::AccountId,
		collection: T::CollectionId,
		new_owner: T::AccountId,
	) -> DispatchResult {
		// Check if the new owner is acceptable based on the collection's acceptance settings.
		let acceptable_collection = OwnershipAcceptance::<T, I>::get(&new_owner);
		ensure!(acceptable_collection.as_ref() == Some(&collection), Error::<T, I>::Unaccepted);

		// Try to retrieve and mutate the collection details.
		Collection::<T, I>::try_mutate(collection, |maybe_details| {
			let details = maybe_details.as_mut().ok_or(Error::<T, I>::UnknownCollection)?;
			// Check if the `origin` is the current owner of the collection.
			ensure!(origin == details.owner, Error::<T, I>::NoPermission);
			if details.owner == new_owner {
				return Ok(());
			}

			// Move the deposit to the new owner.
			T::Currency::repatriate_reserved(
				&details.owner,
				&new_owner,
				details.owner_deposit,
				Reserved,
			)?;

			// Update account ownership information.
			CollectionAccount::<T, I>::remove(&details.owner, &collection);
			CollectionAccount::<T, I>::insert(&new_owner, &collection, ());

			details.owner = new_owner.clone();
			OwnershipAcceptance::<T, I>::remove(&new_owner);
			frame_system::Pallet::<T>::dec_consumers(&new_owner);

			// Emit `OwnerChanged` event.
			Self::deposit_event(Event::OwnerChanged { collection, new_owner });
			Ok(())
		})
	}

	pub(crate) fn do_set_team(
		maybe_check_owner: Option<T::AccountId>,
		collection: T::CollectionId,
		issuer: Option<T::AccountId>,
		admin: Option<T::AccountId>,
		freezer: Option<T::AccountId>,
	) -> DispatchResult {
		Collection::<T, I>::try_mutate(collection, |maybe_details| {
			let details = maybe_details.as_mut().ok_or(Error::<T, I>::UnknownCollection)?;
			let is_root = maybe_check_owner.is_none();
			if let Some(check_origin) = maybe_check_owner {
				ensure!(check_origin == details.owner, Error::<T, I>::NoPermission);
			}

			let roles_map = [
				(issuer.clone(), CollectionRole::Issuer),
				(admin.clone(), CollectionRole::Admin),
				(freezer.clone(), CollectionRole::Freezer),
			];

			// only root can change the role from `None` to `Some(account)`
			if !is_root {
				for (account, role) in roles_map.iter() {
					if account.is_some() {
						ensure!(
							Self::find_account_by_role(&collection, *role).is_some(),
							Error::<T, I>::NoPermission
						);
					}
				}
			}

			let roles = roles_map
				.into_iter()
				.filter_map(|(account, role)| account.map(|account| (account, role)))
				.collect();

			let account_to_role = Self::group_roles_by_account(roles);

			// Delete the previous records.
			Self::clear_roles(&collection)?;

			// Insert new records.
			for (account, roles) in account_to_role {
				CollectionRoleOf::<T, I>::insert(&collection, &account, roles);
			}

			Self::deposit_event(Event::TeamChanged { collection, issuer, admin, freezer });
			Ok(())
		})
	}
