## Analysis

The CVE describes a WebSocket/CORS same-origin policy bypass in Chrome. The closest reachable analog in this repo is the gateway's HTTP CORS origin allowlist check, which has a genuine domain-suffix matching flaw that lets an attacker's arbitrary domain satisfy a wildcard allow-rule without actually being a subdomain of the allowed domain.

### Title
CORS wildcard-origin allowlist bypass via unanchored suffix match - (File: core/services/gateway/network/httpserver.go)

### Summary
`isAllowedOrigin` in the gateway's internet-facing HTTP server treats any `CORSAllowedOrigins` wildcard entry like `*.example.com` as matched by `strings.HasSuffix(originHost, allowedHost)` after stripping the `*.` prefix, with no check that the matched suffix is preceded by a `.` (or is the full host). This allows attacker-controlled domains that merely end with the same characters (e.g. `fakeexample.com` for an allowlisted `*.example.com`) to be treated as an allowed origin.

### Finding Description
`isAllowedOrigin` parses the request `Origin` header and each configured allowed origin, then for wildcard entries strips the leading `*.` and checks `strings.HasSuffix(originHost, allowedHost)`: [1](#0-0) 

This is not a valid subdomain check — it only verifies that `originHost` ends with the same character sequence as `allowedHost`, not that it is `allowedHost` itself or a proper subdomain (`*.allowedHost`) separated by a dot. For example, if an operator configures `CORSAllowedOrigins = ["https://*.ethereum.org"]`, an attacker hosting content at `https://fakeethereum.org` satisfies `HasSuffix("fakeethereum.org", "ethereum.org")` and is treated as an allowed origin.

This check gates `handleRequest`, which reflects the `Origin` back in `Access-Control-Allow-Origin` and enables `Access-Control-Allow-Methods`/`Access-Control-Allow-Headers` for that origin: [2](#0-1) 

The existing tests only exercise cases where the attacker origin does not share a common suffix with the allowed domain (e.g. `https://ethereum.remix.org` vs `*.ethereum.org`), so this boundary-check gap is not covered: [3](#0-2) 

### Impact Explanation
The gateway HTTP server is the internet-facing entry point that forwards a client's raw request into `gateway.ProcessRequest`, which decodes and routes JSON-RPC requests to per-DON/per-service handlers (including the Vault secrets handler and workflow trigger handlers): [4](#0-3) 

If an operator relies on wildcard CORS entries to scope browser-originated access to a legitimate UI domain (e.g. `*.mycompany.com`), an attacker who registers a lookalike domain sharing the same suffix (`evilmycompany.com`) can have their page's cross-origin requests get the `Access-Control-Allow-Origin`/`Allow-Methods`/`Allow-Headers` reflected, defeating the intended same-origin restriction. Combined with credentialed browser requests (cookies/bearer tokens held by the victim's browser/extension calling the gateway), this enables cross-origin request forgery against the gateway API from an unprivileged attacker-controlled page — mirroring the CVE's "bypass same origin policy via a crafted HTML page" bug class, though here the root cause is an allowlist string-matching flaw rather than a WebSocket protocol flaw.

### Likelihood Explanation
Exploitability depends on the operator using a wildcard entry in `CORSAllowedOrigins` (a supported and documented configuration pattern) and lacking control over which look-alike domains attackers can register. Given wildcard CORS is an explicit, supported feature of the gateway config, this is a realistic misconfiguration-adjacent bug reachable purely from an unprivileged remote HTML page with no additional privileges — no malicious node/peer or operator access is required.

### Recommendation
Fix `isAllowedOrigin` to require a proper subdomain boundary: after stripping `*.`, only match when `originHost == allowedHost` or `originHost` ends with `"." + allowedHost` (equivalently, verify `strings.HasSuffix(originHost, "."+allowedHost)` in addition to the current exact-match branch), rather than a bare `HasSuffix` check.

### Proof of Concept
1. Configure the gateway with `CORSEnabled = true` and `CORSAllowedOrigins = ["https://*.ethereum.org"]`.
2. From an attacker-registered domain `https://fakeethereum.org`, send `OPTIONS`/`POST` to the gateway's request path with header `Origin: https://fakeethereum.org`.
3. Observe the response reflects `Access-Control-Allow-Origin: https://fakeethereum.org` (via `isAllowedOrigin` → `handleRequest`), because `strings.HasSuffix("fakeethereum.org", "ethereum.org")` returns `true` even though `fakeethereum.org` is not a subdomain of `ethereum.org`. [5](#0-4)

func (s *httpServer) isAllowedOrigin(origin string) bool {
	originScheme, originHost, originPort, err := s.splitURL(origin)
	if err != nil {
		s.lggr.Debug("error parsing origin URL", err)
		return false
	}
	for _, allowed := range s.config.CORSAllowedOrigins {
		// probably better to do this once when server starts and store it in a map
		// this is an easier solution so we don't have to apply more changes to the code
		// just need to be careful when specifying allowed origins in the config file
		allowedScheme, allowedHost, allowedPort, err := s.splitURL(allowed)
		if err != nil {
			s.lggr.Debug("error parsing allowed origin URL", err)
			continue
		}
		// skip if the scheme doesn't match at all
		if originScheme != allowedScheme {
			continue
		}
		// skip if the port doesn't match at all
		if originPort != allowedPort {
			continue
		}
		// check for exact host match (e.g., remix.com)
		if originHost == allowedHost {
			return true
		}
		// check for wildcard host match (e.g., *.remix.com)
		if strings.HasPrefix(allowedHost, "*.") {
			allowedHost = allowedHost[2:]
			if strings.HasSuffix(originHost, allowedHost) {
				return true
			}
		}
	}
	return false
}

func (s *httpServer) handleRequest(w http.ResponseWriter, r *http.Request) {
	if s.config.CORSEnabled {
		origin := r.Header.Get("Origin")
		if s.isAllowedOrigin(origin) {
			w.Header().Set("Access-Control-Allow-Origin", origin)
			w.Header().Set("Access-Control-Allow-Methods", "GET, POST, OPTIONS")
			w.Header().Set("Access-Control-Allow-Headers", "Content-Type")
		}
