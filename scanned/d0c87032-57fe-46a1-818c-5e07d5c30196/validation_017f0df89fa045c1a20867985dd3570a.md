## Analysis

I found a strong analog in `core/services/gateway/handlers/confidentialrelay/handler.go`. This is the internet-facing gateway's handler for confidential-relay requests, reachable by any unprivileged client that can send a JSON-RPC message to the gateway's user-facing endpoint (`HandleJSONRPCUserMessage`).

The `activeRequests map[string]*activeRequest` on the `handler` struct [1](#0-0)  has **no size cap**. Every incoming user message calls `newActiveRequest`, which only checks for duplicate IDs before inserting into the map — there is no bound on how many distinct concurrent entries can exist: [2](#0-1) 

Compare this to the sibling `RequestCache` implementation used elsewhere in the gateway handlers package, which explicitly enforces `maxCacheSize` and rejects new entries once full: [3](#0-2) 

Unlike the `RequestCache`, and unlike the v2 HTTP capability handler (which has global/per-node/per-org rate limiters guarding all node and user-triggered paths, e.g. [4](#0-3) ), `HandleJSONRPCUserMessage` in the confidentialrelay gateway handler has **no rate limiter and no cap at all** on the number of `activeRequests` it will hold. The only rate limiters in this handler (`globalNodeRateLimiter`, `perNodeRateLimiters`) are applied on the `HandleNodeMessage` path (node → gateway), not on the user-request ingestion path (client → gateway) [5](#0-4) .

Each `activeRequest` holds the full request, a `responses` map, and stays alive until either quorum is reached, the grace window elapses, or `removeExpiredRequests` sweeps it after `requestTimeout` (default 30s) [6](#0-5) [7](#0-6) . An attacker with no privileges can send a burst of distinct-ID requests (each requires only a unique `req.ID` under 200 chars, checked at [8](#0-7) ) faster than the node-fanout/timeout cycle can retire them, growing `activeRequests` unboundedly for up to `requestTimeout` per wave, exhausting gateway memory and also triggering the fan-out send to every DON node for each bogus request (`fanOutToNodes`, sent to all `donConfig.Members`) [9](#0-8) , amplifying load onto every workflow node as well as the gateway.

This mirrors the reported bug class exactly: an unprivileged, unbounded resource-consuming action (deposits per period / here, user requests per handler) with no cap, leading to resource exhaustion / DoS that also degrades service for legitimate users (the fan-out consumes node bandwidth and per-node send timeouts for all DON members on every bogus request).

I was not able to fully verify whether an outer layer (e.g., the gateway's `UserServerConfig.MaxRequestBytes`/`RequestTimeoutMillis`, seen in `deployment/cre/jobs/pkg/gateway_job_test.go`) or another wrapping component (e.g., a WebSocket/HTTP connection-count limiter) constrains the *rate* of distinct `HandleJSONRPCUserMessage` calls before they reach this handler, since that logic lives outside the file inspected; if such an upstream limiter exists and caps concurrent in-flight requests per client, the practical severity would be reduced accordingly.

### Title
Unbounded `activeRequests` map in confidential-relay gateway handler enables unprivileged DoS via unbounded fan-out - (File: `core/services/gateway/handlers/confidentialrelay/handler.go`)

### Summary
The confidential-relay gateway handler's `HandleJSONRPCUserMessage` accepts any JSON-RPC request from an unprivileged client and inserts it into an in-memory `activeRequests` map with no maximum size limit and no per-client/global rate limiting, unlike the sibling `RequestCache` type used elsewhere in the gateway which enforces `maxCacheSize`.

### Finding Description
`newActiveRequest` only rejects a request if its ID already exists in the map; it never checks the map's total size before inserting [2](#0-1) . `HandleJSONRPCUserMessage`, the entry point for this path, only validates that `req.ID` is non-empty and under 200 characters [10](#0-9)  — no authentication beyond whatever the outer gateway user-message dispatch requires, and no rate limiting is applied on this path. The handler does define `globalNodeRateLimiter` and `perNodeRateLimiters`, but both are consulted only inside `HandleNodeMessage` (node → gateway traffic) [5](#0-4) , not on the client-facing ingestion path. Each accepted request also triggers `fanOutToNodes`, which sends the request to every member of `donConfig.Members` [9](#0-8) , so unbounded acceptance also unboundedly amplifies outbound load to the DON.

### Impact Explanation
Sustained submission of distinct-ID requests grows `activeRequests` without bound for up to `requestTimeout` (30s default) per wave, consuming gateway memory and CPU (each entry carries a mutex, timestamps, and a growing `responses` map) and forcing a full fan-out to every DON node per request, which can degrade or deny service for legitimate users' relay requests and burden the workflow DON with pointless traffic — a direct structural analog to the uncapped-deposit DoS in the source report.

### Likelihood Explanation
Likelihood is Medium: any unprivileged actor able to reach the gateway's user-facing JSON-RPC endpoint can trigger this without needing a flash loan or timing a frontrun — simply issuing many concurrent requests with unique IDs is sufficient, and the only per-request cost is generating a valid ID.

### Recommendation
- Add an explicit maximum size to `activeRequests` (mirroring `RequestCache.maxCacheSize`) and reject new requests once the cap is reached.
- Apply a rate limiter (global and/or per-client) on the `HandleJSONRPCUserMessage` ingestion path, not just on `HandleNodeMessage`.
- Consider bounding `fanOutToNodes` amplification by rejecting requests early once resource limits are hit, instead of always fanning out first.

### Proof of Concept
1. An unprivileged client connects to the gateway's user-facing endpoint that routes to this confidential-relay handler.
2. The client issues a rapid burst of JSON-RPC requests (method `MethodSecretsGet` or `MethodCapabilityExec`), each with a distinct, valid `req.ID` (any string ≤200 chars) and arbitrary/garbage params.
3. Each request passes the ID-uniqueness check in `newActiveRequest` and is added to `activeRequests`, then fanned out to every DON member via `fanOutToNodes`.
4. Because there is no cap or rate limit on this path, the attacker can keep submitting requests faster than the 30s timeout sweep retires old entries, growing the map unboundedly and repeatedly fanning out to the entire DON, exhausting gateway resources and DON node bandwidth.

func (h *handler) removeExpiredRequests(ctx context.Context) {
	h.mu.RLock()
	var expiredRequests []*activeRequest
	now := h.clock.Now()
	for _, userRequest := range h.activeRequests {
		if now.Sub(userRequest.createdAt) > h.requestTimeout {
			expiredRequests = append(expiredRequests, userRequest)
		}
	}
	h.mu.RUnlock()

	for _, er := range expiredRequests {
		responses := er.copiedResponses()
		l := h.requestLogger(er.req, er.labels)
		l.Debugw("request expired, evaluating collected relay responses",
			"collected", len(responses),
			"nodes", len(h.donConfig.Members),
			"unanswered", len(h.donConfig.Members)-len(responses),
		)
		summary, err := h.bundler.Bundle(er.req, responses, l)
		if err != nil {
			l.Errorw("failed to build relay response bundle", "error", err)
			if sendErr := h.sendResponseAndClearRequest(ctx, er, h.constructErrorResponse(er.req, api.FatalError, err)); sendErr != nil {
				l.Errorw("error returning bundle failure on expiry", "error", sendErr)
			}
			continue
		}
		// Expiry makes further responses unavailable to this request. The common
		// readiness path forwards a viable partial bundle or returns a timeout.
		if err := h.forwardBundleOrTerminateIfReady(ctx, l, er, summary, 0, true); err != nil {
			l.Errorw("error forwarding bundle on expiry", "error", err)
		}
	}
}

func (h *handler) HandleJSONRPCUserMessage(ctx context.Context, req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) error {
	if req.ID == "" {
		return errors.New("request ID cannot be empty")
	}
	if len(req.ID) > 200 {
		return errors.New("request ID is too long: " + strconv.Itoa(len(req.ID)) + ". max is 200 characters")
	}

	labels := h.extractRequestLabels(req)
	l := h.requestLogger(req, labels)
	l.Debugw("handling confidential relay request", "nodes", len(h.donConfig.Members), "f", h.donConfig.F)

	ar, err := h.newActiveRequest(req, labels, callback)
	if err != nil {
		return err
	}

	return h.fanOutToNodes(ctx, l, ar)

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], labels requestLabels, callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID, "executionID", labels.ExecutionID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		labels:    labels,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

func (h *handler) fanOutToNodes(ctx context.Context, l logger.Logger, ar *activeRequest) error {
	var (
		group      errgroup.Group
		nodeErrors atomic.Uint32
	)

	// Each send is bounded independently. A node whose websocket accepts no writes blocks
	// until its context is cancelled, and because the caller only reads the response callback
	// after this function returns, an unbounded send would hold the request open until the
	// client gives up, discarding a bundle that already reached quorum.
	sendCtx, cancel := context.WithTimeout(ctx, h.nodeSendTimeout)
	defer cancel()

	for _, node := range h.donConfig.Members {
		group.Go(func() error {
			err := h.don.SendToNode(sendCtx, node.Address, &ar.req)
			if err != nil {
				nodeErrors.Add(1)
				l.Errorw("error sending request to node", "node", node.Address, "error", err)
			}
			return nil
		})
	}

	return &requestCache[T]{cache: make(map[globalID]*pendingRequest[T]), timeout: timeout, maxCacheSize: maxCacheSize}
}

func (c *requestCache[T]) NewRequest(lggr logger.Logger, request *api.Message, callback handlers.Callback, responseData *T) error {
	if request == nil {
		return errors.New("request is nil")
	}
	if responseData == nil {
		return errors.New("responseData is nil")
	}
	key := globalID{request.Body.Sender, request.Body.MessageID}
	c.mu.Lock()
	defer c.mu.Unlock()
	_, ok := c.cache[key]
	if ok {
		return errors.New("request already exists")
	}
	if len(c.cache) >= int(c.maxCacheSize) {
		return errors.New("request cache is full")
	}
