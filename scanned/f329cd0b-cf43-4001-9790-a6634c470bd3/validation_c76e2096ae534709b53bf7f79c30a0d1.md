### Title
Reserved-balance under-accounting when a bidder wins multiple disjoint `SlotRange`s for the same `para` in one auction - ([File: polkadot/runtime/common/src/auctions/mod.rs])

### Finding Description
`Pallet::handle_bid` (and the `bid` extrinsic that calls it) computes the amount to reserve for a bidder/para pair from a single scalar stored in `ReservedAmounts::<T>` keyed by `(bidder, para)`, and updates it based only on the bid amount for the *currently submitted* `SlotRange`. The `Winning` storage, however, keeps one independent winning-bid slot per `SlotRange` variant (there are multiple, non-overlapping combinations such as periods `0-1` and `2-3`), and nothing prevents the same `(bidder, para)` from simultaneously holding the top bid on two or more disjoint ranges within the same auction.

Because `reserve_required`/`ReservedAmounts::insert` is derived only from the latest bid's `amount` relative to the previously tracked scalar for that para (not the sum of all currently-winning ranges for that para), a bidder can:
1. Bid `amount = X` on `SlotRange` covering periods `0-1` for `para` → reserves `X`, `ReservedAmounts[(bidder,para)] = X`.
2. Bid `amount = X` (or any amount ≤ X) on a disjoint `SlotRange` covering periods `2-3` for the same `para` → since the new bid is not greater than the tracked scalar, no additional currency is reserved and `ReservedAmounts` is not increased, even though this second bid is now also winning and recorded independently in `Winning`.

At auction end, `manage_auction_end`/`distribute_winnings` iterates over all winning entries and calls `Leaser::lease_out` once per winning `(range, para)` pair, committing lease periods and expected deposits for *both* disjoint ranges. The cumulative economic exposure recorded across `Winning` (X + X = 2X) exceeds the actual reserved balance (X) tracked by `ReservedAmounts`, breaking the invariant that reserved currency backs the sum of all currently-winning bid amounts for that bidder/para.

### Impact Explanation
A bidder can win more aggregate lease value (across multiple disjoint lease-period ranges for the same parachain) than what is actually held in reserve, since `ReservedAmounts` and `Balances::reserved_balance` reflect only the last/largest single-range bid rather than the sum of all currently-winning ranges. This is a reserved-balance accounting mismatch: user-controlled asset backing (Core Invariant: "must remain fully backed") is violated for the auction's committed lease deposits.

### Likelihood Explanation
This requires only unprivileged, ordinary signed `bid` extrinsics from an account with sufficient free balance to place the first bid, no privileged origin or malicious node/relay assumptions. The scenario (bidding on two or more disjoint `SlotRange`s for the same `para` within a single auction) is a normal, legitimate auction strategy and easily reachable via the public `bid` extrinsic, making it fully reproducible by any user.

### Recommendation
Compute `reserve_required` from the sum of `amount` across *all* currently-winning `SlotRange` entries for the `(bidder, para)` pair (scan `Winning` for all ranges currently attributed to that bidder/para) rather than from a single previous scalar, and update `ReservedAmounts` to that cumulative total before reserving/unreserving the delta.

### Proof of Concept
Rust integration test in `polkadot/runtime/common/src/auctions/tests.rs`:
1. Start a new auction with `Auctions::new_auction`.
2. As bidder `1`, call `Auctions::bid(para=1, auction_index, first_slot=0, last_slot=1, amount=100)`.
3. Assert `Balances::reserved_balance(1) == ReservedAmounts::<Test>::get((1,1)).unwrap() == 100`.
4. As bidder `1`, call `Auctions::bid(para=1, auction_index, first_slot=2, last_slot=3, amount=100)` (disjoint range, same para).
5. Assert failure of invariant: `Balances::reserved_balance(1)` remains `100` while `Winning` now contains two independent winning entries for `(1, para=1)` totalling `200` in committed `amount`.
6. Progress to auction end and assert `manage_auction_end`/`distribute_winnings` calls `lease_out` twice for `para=1`, committing `200` total lease deposit obligation while only `100` is actually reserved—demonstrating the under-backed state.
