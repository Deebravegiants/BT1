Confirmed: `readLoop` in `core/services/gateway/connector/connector.go` runs in a dedicated goroutine per gateway connection with no panic recovery around `handler.HandleGatewayMessage(...)` [1](#0-0) . A panic inside `HandleGatewayMessage` therefore propagates unrecovered and crashes the node process. `req.Method` and `req.Params` come directly from the gateway-forwarded, unauthenticated-at-this-layer JSON-RPC request body [2](#0-1) .

### Title
Unauthenticated NULL-Pointer-Dereference DoS via `vault_publicKeyGet` with nil `params` in `GatewayHandler.HandleGatewayMessage` - (File: core/capabilities/vault/gw_handler.go)

### Summary
`GatewayHandler.HandleGatewayMessage` dispatches `MethodPublicKeyGet` directly to `handlePublicKeyGet` without any params-nil validation or authorization pipeline, unlike every other vault method [3](#0-2) . `handlePublicKeyGet` unconditionally dereferences `*req.Params` [4](#0-3) , causing a nil-pointer-dereference panic if `Params` is nil, which crashes the node's read loop goroutine and, since it is unrecovered, the process.

### Finding Description
For `MethodSecretsCreate`, `MethodSecretsUpdate`, `MethodSecretsDelete`, and `MethodSecretsList`, every request first passes through `GatewayVaultRequestProcessor.ProcessRequest`, whose method-specific handlers (`processCreateSecretsRequest`, `processUpdateSecretsRequest`, `processDeleteSecretsRequest`, `processListSecretIdentifiersRequest`) explicitly check `req.Params == nil` and return an `InvalidVaultParamsError` before any unmarshal happens [5](#0-4) [6](#0-5) [7](#0-6) . Only after this pipeline succeeds does `HandleGatewayMessage` call the corresponding `handleSecretsCreate`/`handleSecretsUpdate`/`handleSecretsDelete`/`handleSecretsList`, meaning `req.Params` is guaranteed non-nil by the time those functions dereference it [8](#0-7) .

`MethodPublicKeyGet` is the exception: it is handled entirely inside the initial `switch`, bypassing `requestProcessor.ProcessRequest` (and therefore bypassing the nil check, authorization, and any validation) and calling `h.handlePublicKeyGet(ctx, gatewayID, req)` directly [9](#0-8) . `handlePublicKeyGet` immediately does:
```go
r := &vaultcommon.GetPublicKeyRequest{}
if err := json.Unmarshal(*req.Params, r); err != nil {
``` [4](#0-3) 
If `req.Params` is `nil` (a JSON-RPC request omitting the `"params"` field, which is legal per the JSON-RPC 2.0 spec), `*req.Params` dereferences a nil `*json.RawMessage`, causing an unrecovered panic.

This message reaches the node handler via `gatewayConnector.readLoop`, which unmarshals the raw websocket payload into a `jsonrpc.Request[json.RawMessage]` and dispatches it to the registered handler with no panic recovery [1](#0-0) . The gateway (`core/services/gateway/gateway.go`) forwards externally-submitted requests to nodes largely as-is for JSON-RPC style requests keyed by method/DON ID [10](#0-9) , so an external, unprivileged caller able to submit a gateway request with method `vault_publicKeyGet` and no/`null` `params` can trigger this panic on every node handling the message.

### Impact Explanation
A crash in the unrecovered `readLoop` goroutine kills the process hosting the gateway connector (the Chainlink node), producing a denial-of-service. Because the same crafted message is broadcast/relayed to potentially the whole DON, this could be leveraged to crash multiple nodes participating in the vault capability, directly analogous to the CVE-2018-18937 NULL pointer dereference causing a crash from attacker-supplied, improperly-validated input.

### Likelihood Explanation
No authentication/allowlist gate exists for the `MethodPublicKeyGet` path before the vulnerable dereference — the nil-check is bypassed entirely because this method skips `GatewayVaultRequestProcessor.ProcessRequest`. The only requirement is that the message reach the node's handler with `req.Method == vaulttypes.MethodPublicKeyGet` and `req.Params == nil`, which is straightforward for a client submitting to the gateway.

### Recommendation
Add an explicit `req.Params == nil` check at the start of `handlePublicKeyGet` (and ideally route `MethodPublicKeyGet` through the same validated params pattern used for the other vault methods) before calling `json.Unmarshal(*req.Params, r)`, returning an `api.UserMessageParseError`/`InvalidParamsError` response instead of panicking. Additionally, consider wrapping `handler.HandleGatewayMessage` invocations in `readLoop` with panic recovery to prevent any single malformed message from crashing the node process.

### Proof of Concept
1. Attacker submits (via the gateway) a JSON-RPC request with `method: "vault_publicKeyGet"` and no `params` field (or `"params": null"`).
2. Gateway forwards it to a node's `GatewayConnector.readLoop`, which unmarshals into `jsonrpc.Request[json.RawMessage]{Method: "vault_publicKeyGet", Params: nil}` [11](#0-10) .
3. `GatewayHandler.HandleGatewayMessage` matches `case vaulttypes.MethodPublicKeyGet:` and calls `h.handlePublicKeyGet(ctx, gatewayID, req)` directly, with no nil check [9](#0-8) .
4. `handlePublicKeyGet` executes `json.Unmarshal(*req.Params, r)`, dereferencing the nil `*json.RawMessage`, causing a panic [4](#0-3) .
5. The panic propagates unrecovered up through `readLoop`, crashing the node process.

func (c *gatewayConnector) readLoop(gatewayState *gatewayState) {
	defer c.closeWait.Done()
	ctx, cancel := c.shutdownCh.NewCtx()
	defer cancel()

	for {
		select {
		case <-c.shutdownCh:
			return
		case item := <-gatewayState.conn.ReadChannel():
			var req jsonrpc.Request[json.RawMessage]
			err := json.Unmarshal(item.Data, &req)
			if err != nil {
				c.lggr.Errorw("parse error when reading from Gateway", "id", gatewayState.config.ID, "err", err)
				break
			}
			c.handlersMu.RLock()
			handler, exists := c.handlers[req.Method]
			c.handlersMu.RUnlock()
			if !exists {
				c.lggr.Errorw("no handler for method", "id", gatewayState.config.ID, "method", req.Method)
				break
			}
			// do not break on error. HandleGatewayMessage handles errors
			// by sending a response back to the Gateway.
			err = handler.HandleGatewayMessage(ctx, gatewayState.config.ID, &req)
			if err != nil {
				c.lggr.Warnw("failed to handle message from Gateway", "id", gatewayState.config.ID, "method", req.Method, "err", err)
			}
		}
	}

func (g *gateway) ProcessRequest(ctx context.Context, rawRequest []byte, auth string) (rawResponse []byte, httpStatusCode int) {
	// decode
	jsonRequest, err := jsonrpc2.DecodeRequest[json.RawMessage](rawRequest, auth)
	if err != nil {
		return newError("", api.UserMessageParseError, err.Error())
	}
	msg, err := g.codec.DecodeJSONRequest(jsonRequest)
	if err != nil {
		return newError(jsonRequest.ID, api.UserMessageParseError, err.Error())
	}
	if len(jsonRequest.ID) > 200 {
		// Arbitrary limit to prevent abuse
		return newError(jsonRequest.ID, api.UserMessageParseError, "request ID is too long: "+strconv.Itoa(len(jsonRequest.ID))+". max is 200 characters")
	}
	isLegacyRequest := false
	var h handlers.Handler
	var handlerKey string
	if msg == nil || msg.Body.DonID == "" {
		serviceName := jsonRequest.ServiceName()
		if handler, ok := g.serviceToMultiHandler[serviceName]; ok {
			h = handler
			handlerKey = serviceName
		} else if donID, ok := g.serviceNameToDonID[serviceName]; ok {
			// Fallback to legacy service name -> DON ID mapping
			if handler, ok := g.handlers[donID]; ok {
				h = handler
				handlerKey = donID
			}
		}
		if h == nil {
			return newError(jsonRequest.ID, api.HandlerError, "Service name not found: "+serviceName)
		}
	} else {
		// Legacy request with DON ID - validate and fetch handler
		isLegacyRequest = true
		if err = msg.Validate(); err != nil {
			return newError(jsonRequest.ID, api.UserMessageParseError, err.Error())
		}
		handlerKey = msg.Body.DonID
		var ok bool
		h, ok = g.handlers[handlerKey]
		if !ok {
			return newError(jsonRequest.ID, api.UnsupportedDONIdError, "Unsupported DON ID: "+handlerKey)
		}
	}
