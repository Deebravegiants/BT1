### Title
Unbounded per-request allowlist scan with retry-sleep amplification enables DoS in Vault gateway request authorization - ([File: core/capabilities/vault/allow_list_based_auth.go])

### Summary
### Finding Description
Every Vault JSON-RPC request routed from the gateway to a node (`SecretsCreate`, `SecretsUpdate`, `SecretsDelete`, `SecretsList`) that is not carrying a JWT (`req.Auth == ""`) is authorized via `allowListBasedAuth.AuthorizeRequest`, which calls `findAllowlistedItemWithRetry`. [1](#0-0) [2](#0-1) 

That function loops up to `allowListBasedAuthRetryCount+1` (11) times. On each attempt it fetches the **entire** in-memory allowlisted-requests slice via `GetAllowlistedRequests`, then does an **O(n)** pass over the whole slice just to build a debug-log string (`allowedRequestsStrs`) before performing another **O(n)** linear scan (`fetchAllowlistedItem`) to find a matching digest. If no match is found on a given attempt, it sleeps `allowListBasedAuthRetryInterval` (3s) and retries — up to 10 times (~30s) per single incoming request. [3](#0-2) 

The backing slice (`w.allowListedRequests`) is populated by the `workflowRegistry` syncer, which only prunes *expired* entries and otherwise keeps appending newly discovered on-chain allowlisted requests — its size grows with the number of allowlisted requests across the whole network of workflow owners, with no cap on the in-memory slice. [4](#0-3) 

This mirrors the `massUpdatePools()` class of bug: an unbounded loop whose cost scales with a list size that the calling (unprivileged) actor does not need to control, but that is walked in full on every externally-triggered call. Here, any request reaching the gateway's Vault handler for a node — including requests that are **not** allowlisted at all (i.e., sent by an unauthorized, unprivileged caller) — forces the node to perform up to 11 full linear scans (plus string-formatting for logs) of the entire allowlist, and to hold the goroutine/response for up to ~30 seconds per request via the retry-sleep loop. [5](#0-4) 

### Impact Explanation
As the network-wide allowlist grows (naturally, over time, as more workflow owners register requests), the per-request authorization cost grows linearly and is multiplied by up to 11 retry passes. Because this path is exercised for **every** unauthorized/rejected Vault request — not just legitimate ones — an unprivileged party who can reach the gateway (any external client capable of sending a JSON-RPC vault request, since authorization runs strictly after basic structural validation and before returning an error) can force nodes to repeatedly walk the full allowlist and sleep for up to 30 seconds per request. Sending many such requests concurrently ties up node-side goroutines/CPU and can degrade or deny legitimate Vault request processing across the DON — a resource-exhaustion analog of the "DoS with block gas limit" issue, translated to CPU/goroutine/wall-clock exhaustion instead of gas.

### Likelihood Explanation
Likelihood is moderate-to-high: no special privilege or successful authorization is required to trigger the expensive path — in fact, requests that fail authorization are the worst case (they always run through the full 11-attempt/30-second retry loop). The allowlist itself grows monotonically in normal operation (pruned only for expiry), so the attack surface naturally increases over time without any attacker action needed to inflate it.

### Recommendation
- Do not retry with sleeps for requests that are structurally not found in a single up-to-date lookup; only retry when there is a legitimate short window for propagation (e.g., use a short bounded total budget rather than 10 × 3s regardless of allowlist size).
- Replace the linear scan of `allowedRequests` with an indexed lookup (e.g., a map keyed by request digest) maintained by the syncer, so lookups are O(1) instead of O(n) per attempt.
- Avoid building the full `allowedRequestsStrs` debug list unconditionally; only materialize it under debug-log level or cap the number of entries logged.
- Consider rate-limiting/backoff for repeatedly failing/unauthorized callers before they can trigger multiple retry-sleep cycles.

### Proof of Concept
1. Allow the on-chain `WorkflowRegistry` allowlist to grow to a large number of active entries (occurs naturally over time under normal network operation; no attacker privilege needed for this precondition).
2. As an unprivileged client, send a Vault `SecretsList`/`SecretsCreate` JSON-RPC request through the gateway to a node using a digest that is not present in the allowlist (e.g., no valid `req.Auth` and no prior allowlisting).
3. Observe that `allowListBasedAuth.AuthorizeRequest` → `findAllowlistedItemWithRetry` performs up to 11 full O(n) scans of the allowlist (`core/capabilities/vault/allow_list_based_auth.go:79-111`) and sleeps up to ~30 seconds total before returning "request not allowlisted".
4. Repeat step 2 concurrently with many such requests to observe cumulative CPU and goroutine consumption on the node scaling with both the allowlist size and the number of concurrent unauthorized requests.

func (r *allowListBasedAuth) findAllowlistedItemWithRetry(ctx context.Context, req jsonrpc.Request[json.RawMessage], requestDigest string, requestDigestBytes32 [32]byte) (*workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest, []string, error) {
	for attempt := 0; attempt <= r.retryCount; attempt++ {
		allowedRequests := r.workflowRegistrySyncer.GetAllowlistedRequests(ctx)
		allowedRequestsStrs := make([]string, 0, len(allowedRequests))
		for _, rr := range allowedRequests {
			allowedReqStr := fmt.Sprintf("AuthorizedOwner: %s, RequestDigest: %s, ExpiryTimestamp: %d", rr.Owner.Hex(), hex.EncodeToString(rr.RequestDigest[:]), rr.ExpiryTimestamp)
			allowedRequestsStrs = append(allowedRequestsStrs, allowedReqStr)
		}
		r.lggr.Debugw("AllowListBasedAuth loaded allowlisted requests", "method", req.Method, "requestID", req.ID, "attempt", attempt+1, "allowedRequests", allowedRequestsStrs)

		allowlistedRequest := r.fetchAllowlistedItem(allowedRequests, requestDigestBytes32)
		if allowlistedRequest != nil {
			return allowlistedRequest, allowedRequestsStrs, nil
		}
		if attempt == r.retryCount {
			return nil, allowedRequestsStrs, nil
		}

		r.lggr.Debugw("AllowListBasedAuth request digest not yet allowlisted, retrying",
			"method", req.Method,
			"requestID", req.ID,
			"digestHexStr", requestDigest,
			"attempt", attempt+1,
			"maxAttempts", r.retryCount+1,
			"retryInterval", r.retryInterval)
		if err := sleepWithContext(ctx, r.retryInterval); err != nil {
			r.lggr.Debugw("AllowListBasedAuth retry canceled", "method", req.Method, "requestID", req.ID, "error", err)
			return nil, nil, err
		}
	}

	return nil, nil, nil // unreachable: loop always returns
}

func (w *workflowRegistry) syncAllowlistedRequests(ctx context.Context) {
	ticker := w.getTicker(defaultTickIntervalForAllowlistedRequests)
	w.lggr.Debug("starting syncAllowlistedRequests")
	for {
		select {
		case <-ctx.Done():
			w.lggr.Debug("shutting down syncAllowlistedRequests, %s", ctx.Err())
			return
		case <-ticker:
			newAllowListedRequests, totalAllowlistedRequests, head, err := w.getAllowlistedRequests(ctx, w.contractReader)
			if err != nil {
				w.lggr.Errorw("failed to call getAllowlistedRequests", "err", err)
				continue
			}
			w.allowListedMu.Lock()
			// Prune expired requests
			activeAllowlistedRequests := []workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest{}
			expiredRequestsCount := 0
			for _, request := range w.allowListedRequests {
				if int64(request.ExpiryTimestamp) > time.Now().Unix() {
					activeAllowlistedRequests = append(activeAllowlistedRequests, request)
				} else {
					expiredRequestsCount++
				}
			}

			// Add new requests
			activeAllowlistedRequests = append(activeAllowlistedRequests, newAllowListedRequests...)
			w.allowListedRequests = activeAllowlistedRequests
			w.lastSeenAllowlistedRequestsCount = totalAllowlistedRequests
			w.lggr.Debugw("synced allowlisted requests",
				"newRequestsNum", len(newAllowListedRequests),
				"expiredRequestsNum", expiredRequestsCount,
				"activeRequestsNum", len(w.allowListedRequests),
				"lastSeenOnchainRequestsNum", w.lastSeenAllowlistedRequestsCount,
				"blockHeight", head.Height,
			)
			w.allowListedMu.Unlock()
		}
	}

func (h *GatewayHandler) HandleGatewayMessage(ctx context.Context, gatewayID string, req *jsonrpc.Request[json.RawMessage]) (err error) {
	reqLggr := h.requestLogger(req, gatewayID)
	reqLggr.Debugw("received message from gateway", "req", req)

	var response *jsonrpc.Response[json.RawMessage]
	var authResult *AuthResult

	switch req.Method {
	case vaulttypes.MethodSecretsCreate, vaulttypes.MethodSecretsUpdate:
		publicKey, pkErr := h.getMasterPublicKey(ctx)
		if pkErr != nil {
			response = h.gatewayErrorResponse(ctx, gatewayID, req, pkErr)
			break
		}
		authorized, pipelineErr := h.requestProcessor.ProcessRequest(ctx, req, publicKey)
		if pipelineErr != nil {
			response = h.gatewayErrorResponse(ctx, gatewayID, req, pipelineErr)
			break
		}
		authResult = authorized.AuthResult
	case vaulttypes.MethodSecretsDelete, vaulttypes.MethodSecretsList:
		authorized, pipelineErr := h.requestProcessor.ProcessRequest(ctx, req, nil)
		if pipelineErr != nil {
			response = h.gatewayErrorResponse(ctx, gatewayID, req, pipelineErr)
			break
		}
		authResult = authorized.AuthResult
	case vaulttypes.MethodPublicKeyGet:
		response = h.handlePublicKeyGet(ctx, gatewayID, req)
	default:
		response = h.errorResponse(ctx, gatewayID, req, api.UnsupportedMethodError, errors.New("unsupported method: "+req.Method))
	}

	if response == nil {
		switch req.Method {
		case vaulttypes.MethodSecretsCreate:
			response = h.handleSecretsCreate(ctx, gatewayID, req)
		case vaulttypes.MethodSecretsUpdate:
			response = h.handleSecretsUpdate(ctx, gatewayID, req)
		case vaulttypes.MethodSecretsDelete:
			response = h.handleSecretsDelete(ctx, gatewayID, req)
		case vaulttypes.MethodSecretsList:
			response = h.handleSecretsList(ctx, gatewayID, req, authResult)
