### Title
Vault DKG Result Export Endpoint Lacks Per-Instance Authorization Check - (File: core/web/vault_controller.go)

### Summary
`VaultController.ExportDKGResult` (`core/web/vault_controller.go:91-119`) exports raw DKG result package bytes (`ReportWithResultPackage`) for any `instanceId` supplied by the caller. It performs no check on whether the authenticated caller is entitled to that specific vault/DKG instance — it only checks that the row exists, mirroring the Shopify bug pattern where a resource-scoped mutation is reachable by any authenticated actor and differentiates only "not found" vs "found," not "authorized" vs "not authorized."

### Finding Description
Looking at how this endpoint is wired in `core/web/router.go`, DKG/vault routes are not visible in the router snippet I inspected (`authv2` group, lines 240–330) alongside the other admin-gated key-export endpoints (`/keys/csa/export/:ID`, `/keys/eth/export/:address`, etc., all wrapped in `auth.RequiresAdminRole`). Unlike those, `ExportDKGResult` and `VerifyDKGResult` in `vault_controller.go` contain zero role or ownership checks inside the handler itself — the authorization posture depends entirely on how/whether the route is registered with `auth.RequiresAdminRole` or `auth.RequiresEditRole` in the router. I could not confirm from the index whether `/vault/dkg_results/export` is registered with an admin-role wrapper, because the vault route registration was not present in the router.go sections I could retrieve.

If this route is mounted under `authv2` without a `auth.RequiresAdminRole`/`auth.RequiresEditRole` wrapper (the pattern used for every other export-style endpoint), then any authenticated low-privilege ("view" or "run" role) staff/API-key holder could call it and receive the full hex-encoded DKG result package for an instance they have no legitimate claim to, exactly analogous to the Shopify `billingChargesExport` bug: a sensitive export mutation reachable by an under-privileged authenticated session, differentiated only by a "not found" vs. success response rather than an authorization failure. // ExportDKGResult returns the DKGResult corresponding to the given instance ID
// "POST <application>/vault/dkg_results/export"
func (vc *VaultController) ExportDKGResult(c *gin.Context) {
	var req ExportDKGResultRequest
	err := json.NewDecoder(c.Request.Body).Decode(&req)
	if err != nil {
		jsonAPIError(c, http.StatusBadRequest, errors.New("could not parse request body"))
		return
	}

	if req.InstanceID == "" {
		jsonAPIError(c, http.StatusBadRequest, errors.New("instanceId is required"))
		return
	}

	orm := vault.NewVaultORM(vc.App.GetDB())
	v, err := orm.ReadResultPackage(c.Request.Context(), dkgocrtypes.InstanceID(req.InstanceID))
	if err != nil {
		jsonAPIError(c, http.StatusNotFound, err)
		return
	}

	if v == nil {
		jsonAPIError(c, http.StatusNotFound, errors.New("DKG result not found"))
		return
	}

	hexPackage := hex.EncodeToString(v.ReportWithResultPackage)
	sha := sha256.Sum256(v.ReportWithResultPackage)
	shaStr := hex.EncodeToString(sha[:])
	jsonAPIResponse(c, presenters.NewExportDKGResultResource(hexPackage, shaStr), "exportDKGResult")
