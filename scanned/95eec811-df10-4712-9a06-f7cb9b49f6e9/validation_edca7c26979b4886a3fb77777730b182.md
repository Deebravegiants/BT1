### Title
Unbounded growth of the vault/confidential-relay gateway `activeRequests` map allows request-ID-based DoS - ([File: core/services/gateway/handlers/vault/handler.go], [File: core/services/gateway/handlers/confidentialrelay/handler.go])

### Summary
The gateway's vault and confidential-relay handlers track every in-flight user request in an `activeRequests map[string]*activeRequest`, keyed by the client-supplied `req.ID`. Unlike the generic `RequestCache` used elsewhere in the gateway (which enforces a `maxCacheSize`), these two handlers add entries with no cap, and entries are only removed on success or by a periodic timer sweep that itself iterates the entire map. This is the same bug class as the reported `_isSafe`/`_isSolidSafe` DoS: an unbounded, attacker-growable collection that is iterated by a critical availability path (here, request completion/expiry handling for every user on the DON), with no decrement/limit tied to cheap, repeated client actions.

### Finding Description
`newActiveRequest` in both handlers unconditionally inserts a new map entry for every JSON-RPC user request that passes basic validation/authorization, keyed by the request's own `ID` field: [1](#0-0) [2](#0-1) 

Compare this to the generic `requestCache` used elsewhere in the gateway, which explicitly bounds cache size: [3](#0-2) 

Neither `vault/handler.go`'s `newActiveRequest` nor `confidentialrelay/handler.go`'s `newActiveRequest` has an equivalent `len(h.activeRequests) >= maxCacheSize` guard. Entries are only removed:
- On successful/erroring completion of a request (`sendResponse`/`sendResponseAndClearRequest`), or
- By a periodic sweep (`removeExpiredRequests`) that walks the *entire* `activeRequests` map every tick, looking for entries older than `requestTimeout` (default ~30s): [4](#0-3) [5](#0-4) 

The only per-request guard present is that an *exact-duplicate* `req.ID` is rejected (`h.activeRequests[req.ID] != nil` → error). This does **not** prevent volume-based growth: a caller who is authorized (or, for vault's `MethodPublicKeyGet`, entirely unauthenticated) can submit many requests with distinct IDs faster than the `requestTimeout` window expires them, keeping the map large. There is no length-based rejection, and no rate limiter gates the *creation* of new active requests — the handlers' rate limiters (`nodeRateLimiter`, `globalNodeRateLimiter`, `perNodeRateLimiters`) all throttle node→gateway *responses*, not user→gateway request creation: [6](#0-5) [7](#0-6) 

The gateway's top-level `ProcessRequest` dispatches straight into `HandleJSONRPCUserMessage` with only a request-ID *length* check (max 200 chars) and no volume/size cap before invoking the handler: [8](#0-7) 

This mirrors the reported bug class: `state.openPositions[trader]` in the audited contract grows without bound because nothing decrements it fast enough relative to cheap repeated user actions, and the array is later iterated by a critical path (`getTotalExposure`) used for liquidation safety checks. Here, `activeRequests` grows without a size cap because nothing prevents a client from creating new entries faster than the timeout-based cleanup removes them, and it is iterated by the availability-critical paths `removeExpiredRequests` and `forwardGracedRequests` (confidential relay) on every tick for every active DON.

### Impact Explanation
An attacker (any authorized workflow/vault caller, or an unauthenticated caller for `MethodPublicKeyGet` on the vault handler) can flood the gateway with distinct-ID requests to grow `activeRequests` unbounded for the lifetime of `requestTimeout`. This:
- Increases memory usage per handler instance,
- Increases the CPU/lock-hold cost of `removeExpiredRequests`/`forwardGracedRequests`, which run under `h.mu` and are on the hot path for *every* legitimate request's timeout handling and quorum-grace forwarding,
- Can degrade or stall processing of legitimate vault/confidential-relay requests for the whole DON while the map is large, since these sweeps hold the mutex while scanning.

This is a service-availability (DoS) impact against the gateway's vault and confidential-relay request-handling paths, not a fund-loss or auth-bypass bug.

### Likelihood Explanation
Likelihood is moderate: exploitation requires only sending many JSON-RPC requests with unique IDs within the `requestTimeout` window (default ~30s), which is cheap for any client that can reach the gateway HTTP endpoint and pass method-level authorization (or none, for the public-key path). No special privileges are needed beyond what a normal user/workflow already has.

### Recommendation
- Add an explicit maximum size to `activeRequests` in both `vault/handler.go` and `confidentialrelay/handler.go`, rejecting new requests once the cap is reached (mirroring `requestCache.maxCacheSize` in `core/services/gateway/handlers/common/requestcache.go`).
- Add a per-caller/per-owner rate limiter that gates *request creation* (not just node responses), similar to the `userRateLimiter` already used in `core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go`'s `checkRateLimit`.
- Consider shortening the sweep interval or using a min-heap/expiry-ordered structure instead of full map scans to bound cleanup cost independent of map size.

### Proof of Concept
1. Obtain a valid signer/authorization for a workflow (or none, for `vaulttypes.MethodPublicKeyGet` before the public key is cached).
2. Send a burst of JSON-RPC requests to the gateway (`ProcessRequest` → `HandleJSONRPCUserMessage`) for the vault or confidential-relay handler, each with a distinct `req.ID`, faster than `requestTimeout` (default 30s) can expire them via `removeExpiredRequests`.
3. Observe `activeRequests` growing without bound in `newActiveRequest` ( [1](#0-0) ), increasing memory and the lock-held cost of the periodic `removeExpiredRequests`/`forwardGracedRequests` sweeps, degrading gateway responsiveness for all users of that DON's vault/confidential-relay handler.

// removeExpiredRequests removes expired requests from the pending requests map
func (h *handler) removeExpiredRequests(ctx context.Context) {
	h.mu.RLock()
	var expiredRequests []*activeRequest
	now := h.clock.Now()
	for _, userRequest := range h.activeRequests {
		if now.Sub(userRequest.createdAt) > h.requestTimeout {
			expiredRequests = append(expiredRequests, userRequest)
		}
	}
	h.mu.RUnlock()

	for _, er := range expiredRequests {
		responses := er.copiedResponses()
		var nodeResponses strings.Builder
		for nodeKey, nodeResponse := range responses {
			_, _ = fmt.Fprintf(&nodeResponses, "%s ---::: %v               ", nodeKey, nodeResponse)
		}
		nodeResponsesStr := nodeResponses.String()
		err := h.sendResponse(ctx, er, h.errorResponse(er.req, api.RequestTimeoutError, errors.New("request expired without getting quorum of responses from nodes. Available responses: "+nodeResponsesStr), []byte(nodeResponsesStr)))
		if err != nil {
			h.lggr.Errorw("error sending response to user", "requestID", er.req.ID, "error", err)
		}
	}
}

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

func (h *handler) removeExpiredRequests(ctx context.Context) {
	h.mu.RLock()
	var expiredRequests []*activeRequest
	now := h.clock.Now()
	for _, userRequest := range h.activeRequests {
		if now.Sub(userRequest.createdAt) > h.requestTimeout {
			expiredRequests = append(expiredRequests, userRequest)
		}
	}
	h.mu.RUnlock()

	for _, er := range expiredRequests {
		responses := er.copiedResponses()
		l := h.requestLogger(er.req, er.labels)
		l.Debugw("request expired, evaluating collected relay responses",
			"collected", len(responses),
			"nodes", len(h.donConfig.Members),
			"unanswered", len(h.donConfig.Members)-len(responses),
		)
		summary, err := h.bundler.Bundle(er.req, responses, l)
		if err != nil {
			l.Errorw("failed to build relay response bundle", "error", err)
			if sendErr := h.sendResponseAndClearRequest(ctx, er, h.constructErrorResponse(er.req, api.FatalError, err)); sendErr != nil {
				l.Errorw("error returning bundle failure on expiry", "error", sendErr)
			}
			continue
		}
		// Expiry makes further responses unavailable to this request. The common
		// readiness path forwards a viable partial bundle or returns a timeout.
		if err := h.forwardBundleOrTerminateIfReady(ctx, l, er, summary, 0, true); err != nil {
			l.Errorw("error forwarding bundle on expiry", "error", err)
		}
	}
}

	nodeRateLimiter, ok := h.perNodeRateLimiters[nodeAddr]

		return fmt.Errorf("received message from unexpected node %s", nodeAddr)
	}
	if !nodeRateLimiter.Allow(ctx) {
		l.Debugw("node is rate limited", "nodeAddr", nodeAddr)
		return nil
	}
	if !h.globalNodeRateLimiter.Allow(ctx) {
		l.Debug("global relay rate limit exceeded")
		return nil
	}

func (c *requestCache[T]) NewRequest(lggr logger.Logger, request *api.Message, callback handlers.Callback, responseData *T) error {
	if request == nil {
		return errors.New("request is nil")
	}
	if responseData == nil {
		return errors.New("responseData is nil")
	}
	key := globalID{request.Body.Sender, request.Body.MessageID}
	c.mu.Lock()
	defer c.mu.Unlock()
	_, ok := c.cache[key]
	if ok {
		return errors.New("request already exists")
	}
	if len(c.cache) >= int(c.maxCacheSize) {
		return errors.New("request cache is full")
	}

// Called by the server
func (g *gateway) ProcessRequest(ctx context.Context, rawRequest []byte, auth string) (rawResponse []byte, httpStatusCode int) {
	// decode
	jsonRequest, err := jsonrpc2.DecodeRequest[json.RawMessage](rawRequest, auth)
	if err != nil {
		return newError("", api.UserMessageParseError, err.Error())
	}
	msg, err := g.codec.DecodeJSONRequest(jsonRequest)
	if err != nil {
		return newError(jsonRequest.ID, api.UserMessageParseError, err.Error())
	}
	if len(jsonRequest.ID) > 200 {
		// Arbitrary limit to prevent abuse
		return newError(jsonRequest.ID, api.UserMessageParseError, "request ID is too long: "+strconv.Itoa(len(jsonRequest.ID))+". max is 200 characters")
	}
	isLegacyRequest := false
	var h handlers.Handler
	var handlerKey string
	if msg == nil || msg.Body.DonID == "" {
		serviceName := jsonRequest.ServiceName()
		if handler, ok := g.serviceToMultiHandler[serviceName]; ok {
			h = handler
			handlerKey = serviceName
		} else if donID, ok := g.serviceNameToDonID[serviceName]; ok {
			// Fallback to legacy service name -> DON ID mapping
			if handler, ok := g.handlers[donID]; ok {
				h = handler
				handlerKey = donID
			}
		}
		if h == nil {
			return newError(jsonRequest.ID, api.HandlerError, "Service name not found: "+serviceName)
		}
	} else {
		// Legacy request with DON ID - validate and fetch handler
		isLegacyRequest = true
		if err = msg.Validate(); err != nil {
			return newError(jsonRequest.ID, api.UserMessageParseError, err.Error())
		}
		handlerKey = msg.Body.DonID
		var ok bool
		h, ok = g.handlers[handlerKey]
		if !ok {
			return newError(jsonRequest.ID, api.UnsupportedDONIdError, "Unsupported DON ID: "+handlerKey)
		}
	}

	startTime := time.Now()
	var method string
	callback := handlerscommon.NewCallback()
	if isLegacyRequest {
		method = msg.Body.Method
		err = h.HandleLegacyUserMessage(ctx, msg, callback)
	} else {
		method = jsonRequest.Method
		err = h.HandleJSONRPCUserMessage(ctx, jsonRequest, callback)
	}
