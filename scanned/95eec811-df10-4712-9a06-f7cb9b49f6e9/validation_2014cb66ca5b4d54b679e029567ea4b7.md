### Title
Permanent lockout of legitimate requests via replay guard consuming the digest before owner-binding validation - (File: `core/capabilities/vault/authorizer.go`)

### Summary
`AuthorizeRequest` in `core/capabilities/vault/authorizer.go` records a request's digest into the `RequestReplayGuard` *before* checking that the authenticated caller actually owns the secrets referenced in the request. If that later ownership check fails, the request is rejected, but the digest has already been permanently "spent" in the replay guard, so any subsequent legitimate retry of the exact same (valid) request is unconditionally rejected as a replay — even though it was never actually serviced.

### Finding Description
`AuthorizeRequest` performs its checks in this order:
1. Resolve `authResult` (allowlist- or JWT-based auth).
2. `a.replayGuard.CheckAndRecord(authResult.Digest(), authResult.ExpiresAt())` — this both checks *and unconditionally records* the digest as seen.
3. `validateSecretOwnersMatchAuthorized(req, authResult.AuthorizedOwner())` — only *after* the digest has been recorded. [1](#0-0) 

`CheckAndRecord` stores the digest in `g.seen` as soon as it is not a duplicate, with no way to roll back: [2](#0-1) 

This mirrors the Limbo `stake()` bug class: a piece of state that gates future access to a benefit (there: `rewardDebt`; here: the "digest already seen" replay-guard entry) is committed unconditionally, while the actual granted benefit (there: reward payout; here: successful authorization/service of the request) is conditioned on a check performed afterward (there: `amount > 0`; here: `validateSecretOwnersMatchAuthorized`). If that later condition fails for a legitimate, well-formed, first-time request (e.g., a transient mismatch, race with authorized-key/owner registration propagating, or a caller who corrects an owner field and resubmits the identical JSON-RPC payload/digest), the digest is already burned and the client can never successfully retry that exact request — `ErrRequestAlreadySeen` is returned instead of the true validation error, blocking recovery.

### Impact Explanation
An unprivileged client whose otherwise-valid request digest gets recorded but then fails the owner-binding check (for any reason — a legitimate transient error, or a bug/race in owner resolution) permanently loses the ability to submit that exact request again, since `jsonrpc.Request.Digest()` is deterministic over the request content. This can manifest as denial of service against a legitimate workflow owner's secret operations (create/update/delete/list), since a retried identical request is always rejected with `ErrRequestAlreadySeen` rather than being re-evaluated, and the caller has no way to distinguish "already processed" from "was rejected on binding and now permanently blocked." This is analogous to the confirmed Medium-severity Limbo finding where legitimate users permanently lose access to a benefit because bookkeeping state is committed ahead of/independently from the gating condition.

### Likelihood Explanation
Reachable directly by any unprivileged client calling the Vault JSON-RPC gateway path with authenticated (allowlist or JWT) requests — no privileged or node-only access is required. It requires only that a request pass authentication but fail the (separate) owner-binding validation, which is plausible for automated retry logic, client-side bugs, propagation races in workflow/owner state, or a user correcting-and-resubmitting the same payload.

### Recommendation
Reorder the checks so replay recording happens only after all authorization checks (including `validateSecretOwnersMatchAuthorized`) succeed, or make `CheckAndRecord` a two-phase operation (reserve on check, commit only on final success) so a subsequent, legitimate identical request is not permanently blocked by an earlier check that failed for reasons unrelated to actual replay.

### Proof of Concept
1. Client sends a JSON-RPC vault request (e.g., `vault.secrets.create`) with a valid auth token/allowlist entry, but with `EncryptedSecrets[].Id.Owner` momentarily not matching the resolved `workflowOwner` (e.g., due to normalization edge case or stale owner mapping).
2. `AuthorizeRequest` computes `authResult`, calls `replayGuard.CheckAndRecord(digest, expiresAt)` which succeeds and records the digest.
3. `validateSecretOwnersMatchAuthorized` fails, returning an owner-mismatch error; the request is rejected.
4. The client fixes nothing (the request was actually valid) and resubmits the identical request (same digest) after the transient condition clears.
5. `replayGuard.CheckAndRecord` now returns `ErrRequestAlreadySeen` for the identical digest, permanently blocking the legitimate request until the digest's `expiresAt` elapses — confirmed by existing test behavior showing `CheckAndRecord` unconditionally records on first call: [3](#0-2)

func (a *authorizer) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	authResult, err := a.authorizeRequest(ctx, req)
	if err != nil {
		return nil, err
	}
	if authResult == nil {
		err = errors.New("auth mechanism returned nil auth result")
		a.lggr.Errorw("auth mechanism returned nil auth result", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "")
		return nil, err
	}
	if err := a.replayGuard.CheckAndRecord(authResult.Digest(), authResult.ExpiresAt()); err != nil {
		a.lggr.Debugw("replay guard rejected request", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "digest", authResult.Digest(), "expiresAt", authResult.ExpiresAt(), "hasAuth", req.Auth != "", "error", err)
		return nil, err
	}
	if ownerErr := validateSecretOwnersMatchAuthorized(req, authResult.AuthorizedOwner()); ownerErr != nil {
		a.lggr.Errorw("owner binding rejected request", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "hasAuth", req.Auth != "", "error", ownerErr)
		return nil, ownerErr
	}
	a.lggr.Debugw("request authorized", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "digest", authResult.Digest(), "expiresAt", authResult.ExpiresAt(), "hasAuth", req.Auth != "")
	return authResult, nil
}

func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}

func TestRequestReplayGuard_DuplicateRejected(t *testing.T) {
	guard := NewRequestReplayGuard()
	futureExpiry := time.Now().UTC().Unix() + 100

	err := guard.CheckAndRecord("digest-1", futureExpiry)
	require.NoError(t, err)

	err = guard.CheckAndRecord("digest-1", futureExpiry)
	require.ErrorIs(t, err, ErrRequestAlreadySeen)
}
