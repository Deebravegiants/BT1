### Title
ECDSA signature verification omits canonical-form (low-S / valid-range) validation, permitting signature malleability across gateway/JWT authentication - ([File: core/utils/eth_signatures.go])

### Summary
`GetSignersEthAddress` in `core/utils/eth_signatures.go` recovers a signer's address from a raw `(r, s, v)` signature by calling `crypto.SigToPub` after only checking length (65 bytes) and normalizing `v`. It never validates that `s` is in the canonical lower half of the secp256k1 curve order (`s <= N/2`), nor that `r`/`s` are within `[1, N-1]`. [1](#0-0)  This is the same class of defect as CVE-2021-33589: "does not implement a required step in a cryptographic algorithm, resulting in weaker [guarantees] than on the tin." Here the missing step is ECDSA signature canonicalization/range validation, which is required to prevent signature malleability (for any valid `(r, s)`, `(r, N-s)` with flipped `v` is also a valid signature for the same message and recovers to the same address).

### Finding Description
`GetSignersEthAddress` is the single low-level primitive used throughout the authenticated, internet-facing gateway and JWT-based auth paths:
- Gateway message envelope signature verification: `Message.ExtractSigner` → `gw_common.ExtractSigner` → `utils.GetSignersEthAddress`, invoked from `Message.Validate()` on every inbound gateway message. [2](#0-1) [3](#0-2) 
- Node/gateway handshake auth header verification: `UnpackSignedAuthHeader` → `common.ExtractSigner`. [4](#0-3) 
- Ethereum-address-based JWT signing method used for CRE/vault request authentication: `SigningMethodEth.Verify` → `GetSignersEthAddress`, and `VerifyRequestJWT` which recovers the signer's public key from the token signature before validating claims. [5](#0-4) [6](#0-5) 

Because `s` is never constrained to the canonical low half of the curve order, an unprivileged attacker who observes any one valid signature (e.g., a legitimately signed gateway message, JWT, or handshake header sent over the wire) can locally compute a second, distinct, byte-different signature `(r, N-s, 1-v)` that recovers to the identical signer address, without possessing the private key. `GetSignersEthAddress` will accept this malleated signature as valid because it performs no canonical-form check. [1](#0-0) 

### Impact Explanation
Chainlink's own replay/dedup and idempotency mechanisms in these flows are keyed by request digest/message ID content, not by the raw signature bytes (e.g., `RequestReplayGuard.CheckAndRecord` keyed by digest, and the vault "duplicate requestId" guard). [7](#0-6)  However, any code path elsewhere that treats the raw signature bytes as a unique/opaque token — for example logging, caching, or downstream systems that assume "one message body ⇒ one canonical signature" — is undermined by this malleability, and any future or third-party consumer of these primitives that relies on signature uniqueness for anti-replay or dedup purposes is silently unsafe. More generally, this is a foundational cryptographic-hygiene gap: the verification function used to authenticate gateway messages, connection handshakes, and JWTs is not implementing the standard, required ECDSA canonical-signature check that the Ethereum ecosystem (EIP-2) and most signature libraries enforce. This weakens the security guarantees advertised by "signature verification" in these authentication paths without needing the private key, mirroring the "weaker than on the tin" characterization of the CVE.

### Likelihood Explanation
Exploitation requires only observing one valid signature over the wire (which is inherent to the protocol — signatures are sent unencrypted in the gateway message envelope and JWT), and elementary modular arithmetic (`s' = N - s`) to derive a second valid signature; no cryptographic secrets are needed. This is trivially and reliably reproducible by any unprivileged network client capable of sending requests to the gateway or presenting a JWT.

### Recommendation
Add explicit canonical-form validation in `GetSignersEthAddress` (and any other raw ECDSA verification helper reachable from these auth paths): reject signatures where `s > secp256k1n/2` (as chainlink's own KMS code already does, per `secp256k1HalfN` in `deployment/environment/devenv/internal/kms/kms_client.go`), and validate `r`, `s` are within `[1, N-1]` before calling `crypto.SigToPub`. [8](#0-7)  Audit all call sites (`gw_common.ExtractSigner`, `SigningMethodEth.Verify`, handshake auth) to ensure no downstream logic relies on raw signature bytes as a unique/idempotency token.

### Proof of Concept
1. Generate an ECDSA keypair and sign a gateway `Message` body via `Message.Sign(privateKey)`, producing signature `(r, s, v)`. [9](#0-8) 
2. Compute `s' = secp256k1N - s` and `v' = 1 - v` (flip parity), producing a distinct 65-byte signature blob for the exact same message body.
3. Submit the message with the malleated signature; `Message.Validate()` calls `ExtractSigner()` → `GetSignersEthAddress`, which accepts the malleated signature and recovers the same sender address, because no canonical-form check exists. [2](#0-1) [1](#0-0) 

Note: I was unable to fully verify (within the available search iterations) whether any specific downstream cache, quota, or dedup mechanism keys directly off raw signature bytes rather than digest/message-ID (which would elevate this from a cryptographic-hygiene defect to a concrete authorization/dedup bypass). The `RequestReplayGuard` and vault "duplicate requestId" checks inspected are digest/ID-keyed and not directly bypassable by this malleability alone. If a background agent has full repo access, it should grep for any use of `.Signature` string/bytes as a map/cache key across `core/services/gateway/**` and `core/capabilities/**` to confirm or rule out a concrete authorization-bypass instance.

func GetSignersEthAddress(msg []byte, sig []byte) (recoveredAddr common.Address, err error) {
	if len(sig) != 65 {
		return recoveredAddr, errors.New("invalid signature: signature length must be 65 bytes")
	}

	// Adjust the V component of the signature in case it uses 27 or 28 instead of 0 or 1
	if sig[64] == 27 || sig[64] == 28 {
		sig[64] -= 27
	}
	if sig[64] != 0 && sig[64] != 1 {
		return recoveredAddr, errors.New("invalid signature: invalid V component")
	}

	prefixedMsg := fmt.Sprintf("%s%d%s", EthSignedMessagePrefix, len(msg), msg)
	hash := crypto.Keccak256Hash([]byte(prefixedMsg))

	sigPublicKey, err := crypto.SigToPub(hash[:], sig)
	if err != nil {
		return recoveredAddr, err
	}

	recoveredAddr = crypto.PubkeyToAddress(*sigPublicKey)
	return recoveredAddr, nil
}

func (m *SigningMethodEth) Verify(signingString string, signature []byte, key any) error {
	var ethAddr gethcommon.Address
	switch k := key.(type) {
	case gethcommon.Address:
		ethAddr = k
	default:
		return jwt.ErrInvalidKeyType
	}
	recoveredAddr, err := GetSignersEthAddress([]byte(signingString), signature)
	if err != nil {
		return err
	}
	if !bytes.Equal(recoveredAddr.Bytes(), ethAddr.Bytes()) {
		return jwt.ErrSignatureInvalid
	}
	return nil
}

// CheckAndRecord returns ErrRequestAlreadySeen if the digest was previously
// recorded and has not yet expired. Otherwise it records the digest with
// the given expiry timestamp (unix seconds, UTC).
//
// Expired entries are cleaned up on every call.
func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}
