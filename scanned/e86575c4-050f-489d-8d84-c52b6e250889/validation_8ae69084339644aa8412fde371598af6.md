### Title
Unauthenticated remote proxy to internal LOOP plugin `pprof`/metrics debug endpoints - ([File: core/web/router.go])

### Summary
`loopRoutes` is mounted directly on the base `api` router group in `NewRouter` with no authentication middleware, unlike every other route group (`v2Routes`, `sessionRoutes`, `debugRoutes`) which wrap their handlers in `auth.Authenticate(...)`. This exposes `GET /discovery`, `GET /plugins/:name/metrics`, `GET /plugins/:name/debug/pprof/*profile`, and `POST /plugins/:name/debug/pprof/symbol` to any unauthenticated remote client hitting the node's web server.

### Finding Description
In `core/web/router.go`, `NewRouter` builds the base group `api` with only rate limiting and session middleware (no auth check), then calls: [1](#0-0) 

`debugRoutes` and `sessionRoutes`/`v2Routes` explicitly re-wrap themselves with `auth.Authenticate(...)` before registering sensitive handlers: [2](#0-1) [3](#0-2) 

`loopRoutes`, however, registers its handlers directly on the unauthenticated `r` group with no such wrapper: [4](#0-3) 

These handlers, implemented in `core/web/loop_registry.go`, proxy arbitrary GET/POST requests to the internal LOOP plugin's `pprof` HTTP server based on attacker-supplied `:name` and `:profile` path parameters and query parameters (`debug`, `gc`, `seconds`): [5](#0-4) 

The `pluginPPROFPOSTSymbolHandler` even forwards the raw POST request body to the internal `/debug/pprof/symbol` endpoint of the plugin: [6](#0-5) 

By contrast, when the same `pprof` handlers are registered locally for the node itself (in `metricRoutes`), they are never mounted from any authenticated call site shown, but the LOOP-plugin proxy variant here is a distinct, unauthenticated-by-design gateway to internal plugin debug ports that a remote unauthenticated caller can trigger over the public web server.

This mirrors the root cause of CVE-2020-9381: a controller endpoint intended for privileged/internal use is reachable via the public HTTP interface without the authentication middleware applied elsewhere in the same router, letting any unprivileged remote client interact with internal-only functionality (in this case, `pprof` profiling/symbol resolution and metrics scraping of a chainlink LOOP plugin process).

### Impact Explanation
An unauthenticated remote attacker can:
- Enumerate registered LOOP plugins and their internal metrics topology via `/discovery`.
- Pull raw metrics from `/plugins/:name/metrics`, which can leak internal operational/state information.
- Trigger CPU/heap/goroutine profiling (`/plugins/:name/debug/pprof/profile`, `.../heap`, `.../goroutine`, etc.) against the plugin process, causing resource exhaustion/DoS (the `seconds` parameter directly controls the length of a CPU profile) and potentially leaking sensitive in-memory data (heap dumps can contain secrets, keys) captured from the LOOP plugin process.
- POST arbitrary bodies to the plugin's internal `/debug/pprof/symbol` endpoint.

This is a real availability/information-disclosure risk on a production node reachable from the internet-facing web server, without requiring any credentials, matching a "concrete authentication bypass" class of finding.

### Likelihood Explanation
High — the routes are registered unconditionally in `NewRouter` for any node running with LOOP plugins configured, and there is no feature flag or auth guard visible in the code path shown. Exploitation requires only network access to the node's HTTP port and knowledge/enumeration of a valid `:name` plugin identifier (discoverable via the also-unauthenticated `/discovery` endpoint).

### Recommendation
Wrap `loopRoutes` registration with the same `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)` (and an appropriate role check, e.g. `auth.RequiresAdminRole` for the pprof/symbol POST endpoint) used by `v2Routes` and `debugRoutes`, so that only authenticated operators can reach plugin discovery, metrics, and pprof/debug endpoints.

### Proof of Concept
Without any session cookie or API token, against a running chainlink node:
```
GET /discovery HTTP/1.1
Host: <node>
```
returns the list of registered LOOP plugins and their metrics scrape targets. Then:
```
GET /plugins/<plugin-name>/debug/pprof/profile?seconds=60 HTTP/1.1
Host: <node>
```
forces the node to proxy a 60-second CPU profile request to the internal plugin process, and:
```
POST /plugins/<plugin-name>/debug/pprof/symbol HTTP/1.1
Host: <node>
Content-Length: ...

<body>
```
forwards attacker-controlled data to the plugin's internal `/debug/pprof/symbol` endpoint — all without authentication, per [4](#0-3)  and [5](#0-4) .

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}

func (l *LoopRegistryServer) pluginPPROFPOSTSymbolHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/symbol", l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	body, err := io.ReadAll(gc.Request.Body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error reading plugin pprof request body: %s", err))
		return
	}
	l.doRequest(gc, "POST", pluginURL, bytes.NewReader(body), timeout, pluginName)
}
