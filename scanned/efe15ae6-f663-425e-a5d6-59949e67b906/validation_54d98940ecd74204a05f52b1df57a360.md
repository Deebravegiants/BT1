### Title
Unauthenticated-role disclosure of External Initiator secrets via `GET /v2/external_initiators` - (File: core/web/router.go)

### Summary
The `GET /v2/external_initiators` endpoint returns the `AccessKey` and `OutgoingToken` for every External Initiator configured on the node, but unlike the sibling `POST`/`DELETE` routes for the same resource, it is not gated by `auth.RequiresEditRole` (or any role check at all).

### Finding Description
In the v2 router, the External Initiators routes are registered as: [1](#0-0) 

`Create` and `Destroy` are wrapped in `auth.RequiresEditRole(...)`, but `Index` is only wrapped in `paginatedRequest(eia.Index)` — no role check is applied. The enclosing route group (`authv2`) only requires that the caller pass `auth.Authenticate` with either `AuthenticateByToken` or `AuthenticateBySession`: [2](#0-1) 

This means any authenticated user/API token — regardless of role (including a low-privilege "Run" role identity such as an external initiator itself, which is assigned `UserRoleRun` upon successful `AuthenticateExternalInitiator`) — can call `Index` and receive the full list of configured External Initiators through `ExternalInitiatorsController.Index`: [3](#0-2) 

The response is built from `presenters.NewExternalInitiatorResource`, which serializes the `AccessKey` and `OutgoingToken` fields in plaintext for every initiator record: [4](#0-3) 

`OutgoingToken` is a genuine secret generated at creation time (`utils.NewSecret(...)`) that the node uses to authenticate its own outbound webhook calls to the initiator's `URL`: [5](#0-4) 

By contrast, creating or deleting an External Initiator intentionally requires the higher "Edit" role. The asymmetry — write operations gated, but a full listing (including secrets) left ungated relative to role — is the root cause.

### Impact Explanation
An authenticated but low-privileged actor (e.g., a user/API-token whose role is below "Edit", or the "Run"-role identity assumed by an External Initiator itself) can enumerate every External Initiator's `AccessKey` and `OutgoingToken` on the node. Possession of `OutgoingToken`/`AccessKey` allows impersonating the node's outbound callback authentication to any external initiator's URL, and reveals the `AccessKey` half of the initiator's own inbound credential pair, reducing the effective secrecy of the External Initiator's overall credential set (paired with `HashedSecret`/`Salt`, which remain server-side, but the AccessKey identifier is no longer secret to unauthorized viewers). This is a cross-role secret disclosure that violates the intended `RequiresEditRole` boundary applied to the rest of this resource's endpoints.

### Likelihood Explanation
Any node operator that has created at least one API token/session with a role lower than Edit (or that has External Initiators registered, whose credentials assume the `Run` role) can trivially reach this endpoint — it requires only a single authenticated `GET` request with no special conditions, and the response format is stable and easy to parse.

### Recommendation
Wrap `eia.Index` with the same role restriction used for `Create`/`Destroy` (e.g., `auth.RequiresEditRole(paginatedRequest(eia.Index))`), and/or stop returning `OutgoingToken`/`AccessKey` in the general listing presenter, exposing full credentials only at creation time as is already done via `ExternalInitiatorAuthentication`.

### Proof of Concept
1. Obtain any valid authenticated session or API token, or authenticate as an External Initiator via `AuthenticateExternalInitiator` (which grants `UserRoleRun`).
2. Issue `GET /v2/external_initiators` with those credentials.
3. Observe the JSON response contains `accessKey` and `outgoingToken` for every registered External Initiator, even though the caller's role is below the "Edit" role required to create/manage those initiators. [1](#0-0) [6](#0-5)

func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}

// NewExternalInitiator generates an ExternalInitiator from an
// auth.Token, hashing the password for storage
func NewExternalInitiator(
	eia *auth.Token,
	eir *ExternalInitiatorRequest,
) (*ExternalInitiator, error) {
	salt := utils.NewSecret(utils.DefaultSecretSize)
	hashedSecret, err := auth.HashedSecret(eia, salt)
	if err != nil {
		return nil, pkgerrors.Wrap(err, "error hashing secret for external initiator")
	}

	return &ExternalInitiator{
		Name:           strings.ToLower(eir.Name),
		URL:            eir.URL,
		AccessKey:      eia.AccessKey,
		HashedSecret:   hashedSecret,
		Salt:           salt,
		OutgoingToken:  utils.NewSecret(utils.DefaultSecretSize),
		OutgoingSecret: utils.NewSecret(utils.DefaultSecretSize),
	}, nil
}
