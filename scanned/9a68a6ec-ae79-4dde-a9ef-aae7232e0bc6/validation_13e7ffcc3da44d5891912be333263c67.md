Based on the search, the closest legitimate analog to the "duplicate bond withdrawal" bug class — an action that transfers value/mutates state without invalidating the credential that authorized it, permitting repeat use — is the **unauthenticated `/v2/resume/:runID` endpoint** in `PipelineRunsController.Resume`, backed by `pipeline.runner.ResumeRun` / `orm.UpdateTaskRunResult`.

### Title
Unauthenticated pipeline run resume endpoint allows duplicate task-run completion and concurrent re-execution of the same suspended run - (File: core/web/pipeline_runs_controller.go)

### Summary
The `Resume` endpoint is mounted in the unauthenticated route group and lets any caller who knows a task run UUID submit a result for it via `PATCH /v2/resume/:runID`, without any check that the task has not already been resumed, and without any locking against concurrent resumes of the same task.

### Finding Description
`v2Routes` mounts `prc.Resume` on the *unauthenticated* group (`unauthedv2`), unlike almost every other v2 route which requires token/session auth [1](#0-0) . The handler decodes a `ResumeRequest`, resolves a `taskID`, and directly calls `App.ResumeJobV2` [2](#0-1) , which forwards to `pipelineRunner.ResumeRun` [3](#0-2) .

`ResumeRun` calls `orm.UpdateTaskRunResult(ctx, taskID, ...)`, which unconditionally overwrites the task run's `output`/`error`/`finished_at` columns for the given `taskID` as long as the parent run's state is `running` or `suspended` — there is no check that this specific task run has not already been completed, and no row lock (`FOR UPDATE`) is taken on the run before reading its state [4](#0-3) . If the parent run is still `suspended`, `start` is returned `true` and a new goroutine calls `r.Run()` again for that same run ID [5](#0-4) .

Because the task-run UUID (the "token" that authorizes the resume, analogous to the un-burned bond NFT in the report) is never invalidated or single-use-enforced at the row level, and no lock excludes concurrent readers, two (or more) concurrent `PATCH /v2/resume/<taskID>` calls with the same `taskID` can both observe `run.State == RunStatusSuspended` before either write takes effect, both set `start = true`, and both launch independent goroutines executing `r.Run()` against the same suspended run. This mirrors the report's root cause: the entitlement (the ability to advance/complete a specific run) is consumed by an action that transfers/mutates state (persisting task output, advancing the pipeline, and running downstream tasks) without burning/invalidating the token that grants that entitlement, enabling repeat/duplicate execution from the same credential.

### Impact Explanation
Pipeline runs can contain `ETHTx` and other fund-moving/finalizing tasks. A duplicate concurrent restart of the same run can lead to duplicate downstream task execution (e.g., duplicate on-chain transaction submission, duplicate external side effects for jobs such as VRF/DirectRequest fulfillment), analogous to the "double withdrawal" impact in the reported bug: the same underlying entitlement is consumed more than once because nothing invalidates it after first use. Because the endpoint is completely unauthenticated, any actor who obtains or guesses a `taskID` (e.g., via response-URL leakage, logs, or a compromised bridge adapter) can attempt the race, not just the legitimate bridge/adapter that was given the task ID.

### Likelihood Explanation
Exploitability requires knowledge of a valid, in-flight (`suspended`) task UUID, which is normally only known to the external adapter chosen by the job's pipeline (delivered via the `X-Chainlink-Pending`/`responseURL` mechanism seen in tests) [6](#0-5) . This limits the likelihood to actors who can observe or intercept that callback URL, or to the legitimate adapter misbehaving/retrying. Given it requires no authentication at all and no state changes to prevent replays, likelihood for a race/duplicate-resume is non-trivial once the UUID is known.

### Recommendation
- Enforce single-use semantics on `UpdateTaskRunResult`: only update a `pipeline_task_runs` row if it is currently unfinished (e.g., add `AND finished_at IS NULL` to the `UPDATE`), and treat a no-op update (0 rows affected) as an already-resumed/invalid resume request.
- Take a row lock (`SELECT ... FOR UPDATE`) on the parent `pipeline_runs` row in `UpdateTaskRunResult`, consistent with the existing `StoreRun` locking pattern, to serialize concurrent resumes of the same run/task.
- Consider requiring the resume request to include a secret/token bound to the task run (not just the UUID) so the endpoint isn't purely "possession of a UUID" based.

### Proof of Concept
1. A pipeline run enters `suspended` state waiting on an async bridge task, producing a task UUID `T` (delivered to the external adapter's callback URL).
2. Attacker/adapter issues two concurrent requests: `PATCH /v2/resume/T` with body A and `PATCH /v2/resume/T` with body B.
3. Both requests independently call `orm.UpdateTaskRunResult(ctx, T, ...)`, which reads the run row (state = `suspended`, no lock), each writes an output for task `T`, and each sees `start=true`.
4. Both requests spawn `r.Run(ctx, &run, false, nil)` goroutines for the same run ID, causing duplicate execution of downstream tasks (e.g., duplicate `ETHTx` submission) for one logical job run [5](#0-4) .

func (prc *PipelineRunsController) Resume(c *gin.Context) {
	taskID, err := uuid.Parse(c.Param("runID"))
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	rr := pipeline.ResumeRequest{}
	decoder := json.NewDecoder(c.Request.Body)
	err = errors.Wrap(decoder.Decode(&rr), "failed to unmarshal JSON body")
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	result, err := rr.ToResult()
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	if err := prc.App.ResumeJobV2(c.Request.Context(), taskID, result); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
	c.Status(http.StatusOK)
}

func (o *orm) UpdateTaskRunResult(ctx context.Context, taskID uuid.UUID, result Result) (run Run, start bool, err error) {
	if result.OutputDB().Valid && result.ErrorDB().Valid {
		panic("run result must specify either output or error, not both")
	}
	err = o.transact(ctx, func(tx *orm) error {
		sql := `
		SELECT pipeline_runs.*, pipeline_specs.dot_dag_source "pipeline_spec.dot_dag_source", job_pipeline_specs.job_id "job_id"
		FROM pipeline_runs
		JOIN pipeline_task_runs ON (pipeline_task_runs.pipeline_run_id = pipeline_runs.id)
		JOIN pipeline_specs ON (pipeline_specs.id = pipeline_runs.pipeline_spec_id)
		JOIN job_pipeline_specs ON (job_pipeline_specs.pipeline_spec_id = pipeline_specs.id)
		WHERE pipeline_task_runs.id = $1 AND pipeline_runs.state in ('running', 'suspended')
		FOR UPDATE`
		if err = tx.ds.GetContext(ctx, &run, sql, taskID); err != nil {
			return fmt.Errorf("failed to find pipeline run for task ID %s: %w", taskID.String(), err)
		}

		// Update the task with result
		sql = `UPDATE pipeline_task_runs SET output = $2, error = $3, finished_at = $4 WHERE id = $1`
		if _, err = tx.ds.ExecContext(ctx, sql, taskID, result.OutputDB(), result.ErrorDB(), time.Now()); err != nil {
			return fmt.Errorf("failed to update pipeline task run: %w", err)
		}

		if run.State == RunStatusSuspended {
			start = true
			run.State = RunStatusRunning

			sql = `UPDATE pipeline_runs SET state = $2 WHERE id = $1`
			if _, err = tx.ds.ExecContext(ctx, sql, run.ID, run.State); err != nil {
				return fmt.Errorf("failed to update pipeline run state: %w", err)
			}
		}

		return loadAssociations(ctx, tx.ds, []*Run{&run})
	})

	return run, start, err
}

func (r *runner) ResumeRun(ctx context.Context, taskID uuid.UUID, value any, err error) error {
	run, start, err := r.orm.UpdateTaskRunResult(ctx, taskID, Result{
		Value: value,
		Error: err,
	})
	if err != nil {
		return fmt.Errorf("failed to update task run result: %w", err)
	}

	// TODO: Should probably replace this with a listener to update events
	// which allows to pass in a transactionalised database to this function
	if start {
		// start the runner again
		go func() {
			ctx, cancel := r.chStop.NewCtx()
			defer cancel()
			if _, err := r.Run(ctx, &run, false, nil); err != nil {
				r.lggr.Errorw("Resume run failure", "err", err)
			}
			r.lggr.Debug("Resume run success")
		}()
	}
	return nil
}
