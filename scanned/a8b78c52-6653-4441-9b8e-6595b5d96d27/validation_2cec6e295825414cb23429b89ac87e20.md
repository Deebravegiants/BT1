## Analysis

The external CVE describes application logs that leak sensitive data in plaintext because logging lacks proper redaction. A structurally similar issue exists in this chainlink repo's HTTP request-logging middleware.

### Root cause

`loggerFunc` in `core/web/router.go` is a Gin middleware that logs every incoming HTTP request body (at Debug level) after attempting to sanitize it: [1](#0-0) 

The sanitization is performed by `readBody` → `readSanitizedJSON`, and the "REDACTED" logic only inspects **top-level keys** of the parsed JSON body: [2](#0-1) 

The blacklist that drives redaction only matches keys literally named/containing "password": [3](#0-2) 

### Why this is exploitable via the GraphQL API

Chainlink's GraphQL endpoint wraps all mutation arguments inside a top-level `variables` object, e.g. `{"query": "...", "variables": {"input": {"password": "<plaintext>"}}}`. Because `readSanitizedJSON` only checks the top-level keys (`query`, `variables`) — never descending into `variables.input.password` — the actual plaintext password value is **never redacted** and gets written verbatim into the node's log output whenever `Log.Level = 'debug'`.

Several standard, non-admin, authenticated GraphQL mutations pass the user's real password this way, requiring only `authenticateUser` (not admin): [4](#0-3) [5](#0-4) 

The corresponding GraphQL schema confirms these mutations take a `password` field nested under `input`: [6](#0-5) 

### Impact

Any authenticated (non-admin) node user calling `createAPIToken`, `deleteAPIToken`, or `updateUserPassword` causes their real account password to be written unredacted into the node's console/log file whenever debug-level logging is enabled — matching the CVE's "sensitive data exposed via application logs" bug class. This is a genuine secret-redaction gap: the existing redaction mechanism gives a false sense of protection because it silently fails for nested JSON payloads, which is exactly how the GraphQL transport encodes all mutation input.

### Recommendation
`readSanitizedJSON` should recursively walk nested objects/arrays (not just top-level keys) when checking `isBlacklisted`, or the redaction blacklist should be replaced with a recursive sanitizer that also covers other sensitive field names (`secret`, `token`, `accessKey`, etc.), not just "password".

### Caveat
I could not fully trace where `loggerFunc` is registered onto the Gin engine (i.e., confirm it wraps the `/query` GraphQL route specifically) within the available indexed context — the middleware registration call site itself wasn't found in the search results. Based on the docstring and code structure it appears to be applied as global request logging middleware, but this specific wiring could not be conclusively verified from the indexed content.

### Title
Shallow JSON redaction in HTTP request-logging middleware leaks plaintext user passwords to logs - (File: core/web/router.go)

### Summary
`loggerFunc`'s body-sanitization logic (`readSanitizedJSON`/`isBlacklisted`) only redacts top-level JSON keys, but GraphQL mutation arguments are nested under `variables.input`, so real user passwords sent to `createAPIToken`, `deleteAPIToken`, and `updateUserPassword` are logged in plaintext at Debug level.

### Finding Description
The redaction blacklist checks `dst` map keys directly from the top-level unmarshaled JSON body [2](#0-1) , but never recurses into nested objects. Since the GraphQL transport always nests mutation input arguments one or two levels deep (`variables.input.password`), the blacklist match never triggers for these fields, and the full raw body — including plaintext passwords — is passed to `lggr.Debugw(..., "body", ...)` [7](#0-6) .

### Impact Explanation
Any authenticated, non-admin node user can trigger this by calling `createAPIToken`, `deleteAPIToken`, or `updateUserPassword` [4](#0-3) , causing their real password to be written to node logs, log files, or forwarded audit/log sinks in plaintext — a direct secret-disclosure issue.

### Likelihood Explanation
Requires only that the node runs with `Log.Level = 'debug'` (a supported, documented configuration) [8](#0-7) , and that any regular authenticated user (no special privilege) performs a standard self-service action.

### Recommendation
Make `readSanitizedJSON` recurse into nested maps/arrays when applying `isBlacklisted`, and broaden the blacklist beyond "password" to cover generic secret/token/key field names.

### Proof of Concept
1. Set `Log.Level = 'debug'`.
2. As an authenticated regular user, send a GraphQL mutation: `{"query":"mutation($input: CreateAPITokenInput!){createAPIToken(input:$input){token{accessKey secret}}}","variables":{"input":{"password":"MyRealPassword123"}}}`.
3. Observe node logs: the Debug log entry for this request's `body` field contains `"password":"MyRealPassword123"` unredacted, because `isBlacklisted` never inspected the nested `variables.input.password` key.

func loggerFunc(lggr logger.Logger) gin.HandlerFunc {
	return func(c *gin.Context) {
		buf, err := io.ReadAll(c.Request.Body)
		if err != nil {
			lggr.Error("Web request log error: ", err.Error())
			// Implicitly relies on limits.RequestSizeLimiter
			// overriding of c.Request.Body to abort gin's Context
			// inside io.ReadAll.
			// Functions as we would like, but horrible from an architecture
			// and design pattern perspective.
			if !c.IsAborted() {
				c.AbortWithStatus(http.StatusBadRequest)
			}
			return
		}
		rdr := bytes.NewBuffer(buf)
		c.Request.Body = io.NopCloser(bytes.NewBuffer(buf))

		start := time.Now()
		c.Next()
		end := time.Now()

		lggr.Debugw(fmt.Sprintf("%s %s", c.Request.Method, c.Request.URL.Path),
			"method", c.Request.Method,
			"status", c.Writer.Status(),
			"path", c.Request.URL.Path,
			"ginPath", c.FullPath(),
			"query", redact(c.Request.URL.Query()),
			"body", readBody(rdr, lggr),
			"clientIP", c.ClientIP(),
			"errors", c.Errors.String(),
			"servedAt", end.Format("2006-01-02 15:04:05"),
			"latency", fmt.Sprintf("%v", end.Sub(start)),
		)
	}

func readSanitizedJSON(buf *bytes.Buffer) (string, error) {
	var dst map[string]any
	err := json.Unmarshal(buf.Bytes(), &dst)
	if err != nil {
		return "", err
	}

	cleaned := map[string]any{}
	for k, v := range dst {
		if isBlacklisted(k) {
			cleaned[k] = "*REDACTED*"
			continue
		}
		cleaned[k] = v
	}

	b, err := json.Marshal(cleaned)
	if err != nil {
		return "", err
	}
	return string(b), err
}

func (r *Resolver) CreateAPIToken(ctx context.Context, args struct {
	Input struct{ Password string }
}) (*CreateAPITokenPayloadResolver, error) {
	if err := authenticateUser(ctx); err != nil {
		return nil, err
	}

	session, ok := webauth.GetGQLAuthenticatedSession(ctx)
	if !ok {
		return nil, errors.New("Failed to obtain current user from context")
	}
	dbUser, err := r.App.AuthenticationProvider().FindUser(ctx, session.User.Email)
	if err != nil {
		return nil, err
	}

	err = r.App.AuthenticationProvider().TestPassword(ctx, dbUser.Email, args.Input.Password)
	if err != nil {
		r.App.GetAuditLogger().Audit(audit.APITokenCreateAttemptPasswordMismatch, map[string]any{"user": dbUser.Email})

		return NewCreateAPITokenPayload(nil, map[string]string{
			"password": "incorrect password",
		}), nil
	}

	newToken, err := r.App.AuthenticationProvider().CreateAndSetAuthToken(ctx, &dbUser)
	if err != nil {
		return nil, err
	}

	r.App.GetAuditLogger().Audit(audit.APITokenCreated, map[string]any{"user": dbUser.Email})
	return NewCreateAPITokenPayload(newToken, nil), nil
}
