### Title
Denial of Service via unhandled panic in `normalizeHex()` due to insufficient hex-length validation in `validateHexInput()` - (File: `core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go`)

### Summary
`validateHexInput()` fails to guarantee that a validated `workflowID`/`workflowOwner` string, once its `0x` prefix is stripped, is not longer than the field's expected hex-digit length. When such an over-long-but-"validated" string is later passed to `normalizeHex()`, the padding calculation goes negative and `strings.Repeat()` panics, crashing the goroutine handling the request. This mirrors the reported `HexUtils.hexStringToBytes32()` bug class, where missing exact-length checks on hex input allow silent truncation/padding of out-of-range data — here the same missing-length-check pattern instead causes an unhandled runtime panic.

### Finding Description
`validateHexInput()` [1](#0-0)  only checks that the input is lowercase, that its **total** length (including any `0x` prefix) does not exceed `expectedLength`, and that `hex.DecodeString` succeeds on the input after stripping a leading `0x` prefix. Crucially, it does not require the `0x` prefix to be present, and it does not check that the length is not merely `<=` but exactly matches, nor does it separately bound the *hex-digit* length once the prefix is stripped.

Because a hex digit alphabet (`0-9a-f`) cannot contain the literal characters `0x`, if a user submits an input **without** the `0x` prefix (e.g. a raw 42-character `workflowOwner` value with no prefix), `strings.TrimPrefix(input, "0x")` is a no-op, so `hexStr` remains the full input string. `hex.DecodeString` on this string succeeds as long as the length is even, so `validateHexInput` treats it as valid even though `len(hexStr)` equals `expectedLength` rather than `expectedLength-2`.

The normalization step then does:
```go
// core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go:333-340
func normalizeHex(input string, length int) string {
	hexStr := strings.TrimPrefix(input, "0x")
	expectedHexLength := length - 2
	paddedHex := strings.Repeat("0", expectedHexLength-len(hexStr)) + hexStr
	return "0x" + paddedHex
}
``` [2](#0-1) 

If `len(hexStr) > expectedHexLength` (which can happen for a validated, prefix-less input at or near `expectedLength`), `expectedHexLength-len(hexStr)` becomes negative. Go's `strings.Repeat` panics with `"strings: negative Repeat count"` when given a negative count, so this call panics.

`normalizeHex` is invoked directly from `resolveWorkflowID` on both `workflowID` and `workflowOwner` values that only passed through `validateWorkflowID`/`validateWorkflowOwner` (i.e., `validateHexInput`) [3](#0-2) , which is reached from `HandleUserTriggerRequest`, the entry point for unauthenticated/unprivileged workflow-execute HTTP trigger requests arriving from the internet-facing gateway [4](#0-3) . This is invoked from `gatewayHandler.HandleJSONRPCUserMessage` [5](#0-4) , which in turn is invoked synchronously from the HTTP request path in `httpserver.go`'s `handleRequest` → `s.handler.ProcessRequest` [6](#0-5) . I found no `recover()`/`WrapRecover` wrapping this specific call chain (only `core/recovery/recover.go` provides such helpers, used elsewhere in the codebase, but not observed wrapping this synchronous HTTP request handling path).

### Impact Explanation
A crafted, unauthenticated JSON-RPC `workflows.execute` request with a `workflowOwner` (42 chars) or `workflowID` (66 chars) hex value that omits the `0x` prefix but is otherwise valid lowercase hex of the *full* expected length will pass `validateHexInput` and then trigger a panic in `normalizeHex`. If this panic is not recovered by an outer boundary (none was found on this synchronous request path), it will crash the goroutine servicing the HTTP request — and depending on Go's runtime behavior for unrecovered panics in spawned goroutines, potentially the entire gateway process, resulting in denial of service for all workflows/users relying on that gateway node.

### Likelihood Explanation
High likelihood of triggering: the malformed input is trivial to construct (any lowercase hex string of the right length without a `0x` prefix), requires no authentication, and is reachable directly at the gateway's public HTTP endpoint for `workflows.execute` trigger requests before any authorization or workflow-existence checks are performed.

### Recommendation
In `validateHexInput`, require the `0x` prefix to be present and enforce that the hex-digit portion (after stripping `0x`) has an exact expected length (`expectedLength-2`), rather than only bounding the total length with `<=`. Alternatively/additionally, in `normalizeHex`, guard against `expectedHexLength-len(hexStr) < 0` and return an error instead of calling `strings.Repeat` with a negative count.

### Proof of Concept
1. Compute a 42-character (for `workflowOwner`) all-lowercase hex string with **no** `0x` prefix, e.g. `"1234567890abcdef1234567890abcdef123456ab"` (42 chars, valid hex, all lowercase).
2. Send a JSON-RPC `workflows.execute` request to the gateway's HTTP trigger endpoint with `workflow.workflowOwner` set to that string and `workflow.workflowName`/`workflow.workflowTag` set to any valid strings, and no `workflowID`.
3. `validateWorkflowOwner` → `validateHexInput("1234...ab", 42)` passes: lowercase check passes, `len(input) == 42` is not `> 42`, and `hex.DecodeString` on the untrimmed 42-char string succeeds (even length, valid hex digits).
4. `resolveWorkflowID` calls `normalizeHex(workflowOwner, 42)`: `hexStr` = the 42-char string (no `0x` to trim), `expectedHexLength = 40`, `strings.Repeat("0", 40-42)` = `strings.Repeat("0", -2)`, which panics with `"strings: negative Repeat count"`.

func validateHexInput(input string, expectedLength int) error {
	if input != strings.ToLower(input) {
		return errors.New("must be lowercase")
	}

	if len(input) > expectedLength {
		return fmt.Errorf("hex string too long: expected at most %d characters, got %d", expectedLength, len(input))
	}

	hexStr := strings.TrimPrefix(input, "0x")
	_, err := hex.DecodeString(hexStr)
	if err != nil {
		return errors.New("must be a valid hex string")
	}

	return nil
}

func (s *httpServer) handleRequest(w http.ResponseWriter, r *http.Request) {
	if s.config.CORSEnabled {
		origin := r.Header.Get("Origin")
		if s.isAllowedOrigin(origin) {
			w.Header().Set("Access-Control-Allow-Origin", origin)
			w.Header().Set("Access-Control-Allow-Methods", "GET, POST, OPTIONS")
			w.Header().Set("Access-Control-Allow-Headers", "Content-Type")
		}

		// handle preflight requests
		if r.Method == http.MethodOptions {
			w.WriteHeader(http.StatusNoContent)
			return
		}
	}

	maxRequestBytes, err := s.config.MaxRequestBytesLimiter.Limit(r.Context())
	if err != nil {
		msg := "Failed to get request size limit"
		s.lggr.Errorw(msg, "err", err)
		http.Error(w, msg, http.StatusInternalServerError)
		return
	}
	source := http.MaxBytesReader(nil, r.Body, int64(maxRequestBytes))
	rawMessage, err := io.ReadAll(source)
	if err != nil {
		s.lggr.Error("error reading request", err)
		w.WriteHeader(http.StatusBadRequest)
		return
	}

	// Optionally extract jwt token from authorization header
	authHeader := r.Header.Get("Authorization")
	jwtToken := ""
	if authHeader != "" {
		jwtToken = strings.TrimPrefix(authHeader, "Bearer ")
	}

	startTime := time.Now()
	rawResponse, httpStatusCode := s.handler.ProcessRequest(r.Context(), rawMessage, jwtToken)
	duration := time.Since(startTime)
	s.hMetrics.RecordRequestDuration(r.Context(), httpStatusCode, duration)
	s.hMetrics.RecordRequestCount(r.Context(), httpStatusCode)
