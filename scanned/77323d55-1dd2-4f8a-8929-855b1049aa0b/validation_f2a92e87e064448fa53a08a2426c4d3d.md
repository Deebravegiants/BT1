### Title
Stale allowlist entries in `AllowListBasedAuth` remain valid after on-chain revocation, allowing continued unauthorized Vault requests - (File: `core/services/workflows/syncer/v2/workflow_registry.go`)

### Summary
The Vault gateway authorizes off-chain JSON-RPC requests via `allowListBasedAuth.AuthorizeRequest`, which checks an in-memory list of allowlisted request digests (`workflowRegistry.allowListedRequests`) synced from the `WorkflowRegistry` contract [1](#0-0) . This local cache is only pruned by locally-stored expiry timestamps, never by re-validating already-seen entries against current on-chain state, mirroring the ArtGobblers root cause: a piece of state that grants access (approval / allowlist entry) is not invalidated when the underlying resource is revoked/deleted, letting a stale credential be "revived."

### Finding Description
`syncAllowlistedRequests` refreshes the local allowlist every 5 seconds by pruning entries whose `ExpiryTimestamp` has locally elapsed and appending `newAllowListedRequests` fetched from the chain [2](#0-1) .

The fetch itself (`getAllowlistedRequests`) is index-based and incremental: it short-circuits entirely if `lastSeenAllowlistedRequestsCount` equals the on-chain `totalAllowlistedRequests`, and otherwise only queries indices starting at `lastSeenAllowlistedRequestsCount` (i.e., only newly appended entries), never re-querying indices already seen in a prior cycle [3](#0-2) .

Because of this "only fetch new indices" strategy combined with "only prune on local expiry," an allowlisted-request entry that was already synced into `w.allowListedRequests` is never re-checked against the contract's current authoritative state. If the request is revoked/deactivated on-chain (through any mechanism other than the count strictly monotonically decreasing and being re-fetched), the node's local cache has no path to learn about that revocation before the entry's own `ExpiryTimestamp` is reached — the digest continues to be treated as authorized by `AuthorizeRequest` [4](#0-3) , exactly analogous to a burnt token's stale `approve()` continuing to authorize `transferFrom` in the ArtGobblers bug: the deletion/revocation of the authorizing resource is not reflected in the cached state that is consulted for authorization decisions.

I was not able to confirm from the indexed contract bindings whether `WorkflowRegistryV2` exposes an explicit "revoke/remove allowlist entry" function distinct from natural expiry; the index only surfaced the Go-side wrapper types (`WorkflowRegistryOwnerAllowlistedRequest`, `GetActiveAllowlistedRequestsReverseMethodName`), not the Solidity source, so this caveat should be verified against the actual `WorkflowRegistry` contract before treating this as fully proven.

### Impact Explanation
If the workflow owner (or governance) revokes/deactivates an allowlisted request digest on-chain before its natural expiry, any node in the Vault DON that already cached the entry continues to authorize matching Vault requests using that digest until the locally stored expiry passes. This is a request-impersonation / allowlist-bypass vector: an unprivileged caller who previously obtained (or replays) an allowlisted, but now-revoked, request digest can still get it accepted by `AuthorizeRequest`, potentially performing Vault operations (e.g., secret retrieval) the owner intended to stop.

### Likelihood Explanation
Likelihood depends entirely on whether the on-chain contract provides an early-revocation path (separate from expiry). Given the index-only incremental sync design (`lastSeenAllowlistedRequestsCount` gating what indices get re-fetched) and expiry-only pruning on the client, any such revocation path would not propagate to nodes until the stale entry's own expiry, so likelihood is high whenever revocation-before-expiry is a supported contract operation; it is unconfirmed here whether that operation exists.

### Recommendation
- On each sync tick, re-validate previously cached allowlist entries against the contract's authoritative "active" state rather than relying solely on locally stored `ExpiryTimestamp` for pruning.
- If the contract supports early revocation, ensure the syncer either re-fetches the full active set periodically (not just indices beyond `lastSeenAllowlistedRequestsCount`) or subscribes to revocation events and removes the corresponding digest from `w.allowListedRequests` immediately.
- Add a regression test simulating on-chain revocation before expiry to confirm the cached digest is invalidated promptly.

### Proof of Concept
Conceptual PoC (contract-dependent, not fully verified against Solidity source):
1. Owner allowlists a request digest `D` with `ExpiryTimestamp = T+1h`.
2. Node A syncs and caches `D` in `w.allowListedRequests`.
3. Owner revokes `D` on-chain at `T+5m` (assuming a revoke path exists), without changing `totalAllowlistedRequests` count or without the syncer re-querying already-seen indices.
4. Node A's next `syncAllowlistedRequests` tick only prunes by `ExpiryTimestamp` (`T+1h`), so `D` remains in the cache.
5. An unprivileged client submits a Vault request whose digest matches `D` at `T+10m`; `AuthorizeRequest` still returns success because `D` is present and not yet expired locally, despite being revoked on-chain [5](#0-4) .

// AuthorizeRequest authorizes a request using AllowListBasedAuth.
// It does NOT check if the request method is allowed.
func (r *allowListBasedAuth) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	r.lggr.Debugw("AllowListBasedAuth authorizing request", "method", req.Method, "requestID", req.ID)
	requestDigest, err := req.Digest()
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to create digest", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, err
	}
	requestDigestBytes, err := hex.DecodeString(requestDigest)
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to decode digest", "method", req.Method, "requestID", req.ID, "requestDigest", requestDigest, "error", err)
		return nil, err
	}
	requestDigestBytes32 := [32]byte(requestDigestBytes)
	if r.workflowRegistrySyncer == nil {
		r.lggr.Errorw("AllowListBasedAuth workflowRegistrySyncer is nil", "method", req.Method, "requestID", req.ID)
		return nil, errors.New("internal error: workflowRegistrySyncer is nil")
	}
	allowlistedRequest, allowedRequestsStrs, err := r.findAllowlistedItemWithRetry(ctx, req, requestDigest, requestDigestBytes32)
	if err != nil {
		return nil, err
	}
	if allowlistedRequest == nil {
		r.lggr.Debugw("AllowListBasedAuth request digest not allowlisted",
			"method", req.Method,
			"requestID", req.ID,
			"digestHexStr", requestDigest,
			"allowedRequestsStrs", allowedRequestsStrs)
		return nil, errors.New("request not allowlisted")
	}

	if time.Now().UTC().Unix() > int64(allowlistedRequest.ExpiryTimestamp) {
		authorizedRequestStr := string(allowlistedRequest.RequestDigest[:])
		r.lggr.Debugw("AllowListBasedAuth authorization expired", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", authorizedRequestStr, "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
		return nil, errors.New("request authorization expired")
	}

	digestKey := string(allowlistedRequest.RequestDigest[:])
	r.lggr.Debugw("AllowListBasedAuth authorization succeeded", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", digestKey, "owner", allowlistedRequest.Owner.Hex(), "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
	return &AuthResult{
		workflowOwner: allowlistedRequest.Owner.Hex(),
		digest:        digestKey,
		expiresAt:     int64(allowlistedRequest.ExpiryTimestamp),
	}, nil
}

func (w *workflowRegistry) syncAllowlistedRequests(ctx context.Context) {
	ticker := w.getTicker(defaultTickIntervalForAllowlistedRequests)
	w.lggr.Debug("starting syncAllowlistedRequests")
	for {
		select {
		case <-ctx.Done():
			w.lggr.Debug("shutting down syncAllowlistedRequests, %s", ctx.Err())
			return
		case <-ticker:
			newAllowListedRequests, totalAllowlistedRequests, head, err := w.getAllowlistedRequests(ctx, w.contractReader)
			if err != nil {
				w.lggr.Errorw("failed to call getAllowlistedRequests", "err", err)
				continue
			}
			w.allowListedMu.Lock()
			// Prune expired requests
			activeAllowlistedRequests := []workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest{}
			expiredRequestsCount := 0
			for _, request := range w.allowListedRequests {
				if int64(request.ExpiryTimestamp) > time.Now().Unix() {
					activeAllowlistedRequests = append(activeAllowlistedRequests, request)
				} else {
					expiredRequestsCount++
				}
			}

			// Add new requests
			activeAllowlistedRequests = append(activeAllowlistedRequests, newAllowListedRequests...)
			w.allowListedRequests = activeAllowlistedRequests
			w.lastSeenAllowlistedRequestsCount = totalAllowlistedRequests
			w.lggr.Debugw("synced allowlisted requests",
				"newRequestsNum", len(newAllowListedRequests),
				"expiredRequestsNum", expiredRequestsCount,
				"activeRequestsNum", len(w.allowListedRequests),
				"lastSeenOnchainRequestsNum", w.lastSeenAllowlistedRequestsCount,
				"blockHeight", head.Height,
			)
			w.allowListedMu.Unlock()
		}
	}
}
