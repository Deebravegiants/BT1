Target: ShopifyAPI::Utils::SessionUtils.current_session_id when Context.embedded? is true and no shopify_id_token is sent. Attacker action: POST/GET to the app with headers omitting Authorization/shopify_id_token but Cookie: shopify_app_session=<any string>. Preconditions: embedded app configured, attacker never authenticated. Call sequence: current_session_id(nil, cookies, online) hits the `else` branch (fallback to cookie) because shopify_id_token is falsy, calling cookie_session_id(cookies) which returns the header value verbatim. Binding that breaks: session_id_used_for_token_lookup == bytes_authenticated_under(Context.api_secret_key) is false; instead session_id_used_for_token_lookup == unauthenticated_cookie_bytes. Scoped impact: Critical, theft of another merchant's access token - whichever session id the attacker guesses or copies from a leaked-but-unauthenticated source is loaded. Proof idea: WebMock/minitest test asserting current_session_id returns the cookie value even for embedded apps, with zero calls to any HMAC or JWT verification method.
