Target: ShopifyAPI::Utils::SessionUtils.current_session_id and .cookie_session_id. Attacker action: send a GET to a non-embedded app's callback route with header Cookie: shopify_app_session=offline_victim-shop.myshopify.com, no shopify_id_token. Preconditions: Context.embedded? is false (default host app config), no prior OAuth ever completed by attacker. Call sequence: SessionUtils.current_session_id(nil, cookies, false) -> cookies['shopify_app_session'] present -> cookie_session_id(cookies) returns the raw cookie value verbatim, which is then used as the storage key passed to session storage's load. Binding that breaks: session_id_returned == cookies['shopify_app_session'] (attacker-chosen bytes), NOT session_id_returned == HMAC_verify(Context.api_secret_key, cookie). Scoped impact: Critical, cross-tenant access - attacker's request loads victim-shop's offline session and its access_token via ShopifyAPI::Clients::HttpClient. Proof idea: minitest stubbing a fake SessionStorage, call SessionUtils.current_session_id(nil, {'shopify_app_session' => 'offline_victim-shop.myshopify.com'}, false), assert returned id equals attacker-supplied string with no signature check performed (SESSION_DERIVATION binding violated).
