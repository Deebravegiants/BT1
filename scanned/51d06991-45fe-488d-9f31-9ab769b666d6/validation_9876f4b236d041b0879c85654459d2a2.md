### Title
Unauthenticated nil-pointer dereference panic in Gateway JSON-RPC request decoding when `params` is omitted or null - (File: core/services/gateway/api/jsonrpccodec.go)

### Summary
`JSONRPCCodec.DecodeJSONRequest` unconditionally dereferences the JSON-RPC request's `Params` field (`*request.Params`) without checking for `nil`. This function is invoked from the internet-facing Gateway's `ProcessRequest` entry point for every incoming user HTTP request, before any authentication, method routing, or DON/service validation takes place, so any unauthenticated remote caller can trigger a nil-pointer dereference panic by sending a syntactically valid JSON-RPC request that omits the `params` field (or sets it to `null`).

### Finding Description
The Gateway's user-facing HTTP endpoint accepts raw JSON-RPC requests and processes them in `gateway.ProcessRequest`: [1](#0-0) 

`jsonRequest` is decoded generically as `jsonrpc2.Request[json.RawMessage]`, whose `Params` field is a pointer (`*json.RawMessage`). It is entirely legal per the JSON-RPC 2.0 spec for a request to omit `params`, leaving it `nil`. Immediately, `g.codec.DecodeJSONRequest(jsonRequest)` is called — this happens for *every* request, both "legacy" and new-style, before `msg.Validate()` or any DON/service lookup: [2](#0-1) 

```go
func (*JSONRPCCodec) DecodeJSONRequest(request jsonrpc2.Request[json.RawMessage]) (*Message, error) {
	var msg Message
	err := json.Unmarshal(*request.Params, &msg)
	...
}
```

`*request.Params` dereferences the pointer with no nil check. If `Params` is `nil`, this panics with a nil pointer dereference. Elsewhere in the same package, the equivalent legacy helper `ValidatedMessageFromReq` explicitly guards against this exact case (`if req.Params == nil { return nil, errors.New("missing params attribute") }`), confirming that a nil `Params` is a reachable, expected state that the codec's `DecodeJSONRequest` fails to handle: [3](#0-2) 

The request reaches this code via the unauthenticated HTTP path with no panic-recovery wrapper in the gateway-specific code: [4](#0-3) 

This mirrors the Firebird `op_slice` bug class exactly: an unauthenticated, syntactically-valid-but-incomplete request causes the server to dereference an unprepared/null pointer in its packet/message-parsing routine, triggering a panic.

### Impact Explanation
Any unauthenticated caller reaching the Gateway's user HTTP port can crash the goroutine handling their request with an unrecovered panic. Because Go's standard `net/http` server recovers panics per-connection (logging them and closing the connection), the direct effect is at minimum a reliable, repeatable denial-of-service against that connection/request and a logged panic/stack trace in the Gateway process; if the panic occurs in code invoked outside of `net/http`'s own goroutine recovery scope (e.g., in a background goroutine spawned without `defer recover()`), it can crash the entire Gateway process. Either way, this is an availability impact reachable without any authentication, consistent with the CVSS profile of the referenced Firebird CVE (`AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:H`).

### Likelihood Explanation
High. The trigger is trivial: a single HTTP POST with a JSON-RPC request body omitting `"params"` (or `"params": null"`), requiring no authentication, no valid signature, and no knowledge of DON/service configuration. It is reachable on the very first line of request processing, before any allowlist, subscription, or DON-ID checks occur.

### Recommendation
Add an explicit nil-check for `request.Params` at the top of `JSONRPCCodec.DecodeJSONRequest` (and any other codec method that dereferences a `*json.RawMessage` params pointer), returning a decode error consistent with how `ValidatedMessageFromReq` already handles this case, before calling `json.Unmarshal(*request.Params, &msg)`.

### Proof of Concept
Send the following to the Gateway's user-facing HTTP endpoint (the `Path` configured in `HTTPServerConfig`), with no `Authorization` header required:

```
POST /<gateway_path> HTTP/1.1
Content-Type: application/json

{"jsonrpc":"2.0","id":"1","method":"anything"}
```

Note the absence of the `params` field. This is parsed by `jsonrpc2.DecodeRequest` into a `jsonrpc2.Request[json.RawMessage]` with `Params == nil`, then passed straight into `gateway.ProcessRequest` → `JSONRPCCodec.DecodeJSONRequest`, where `*request.Params` panics with a nil pointer dereference.

func (s *httpServer) handleRequest(w http.ResponseWriter, r *http.Request) {
	if s.config.CORSEnabled {
		origin := r.Header.Get("Origin")
		if s.isAllowedOrigin(origin) {
			w.Header().Set("Access-Control-Allow-Origin", origin)
			w.Header().Set("Access-Control-Allow-Methods", "GET, POST, OPTIONS")
			w.Header().Set("Access-Control-Allow-Headers", "Content-Type")
		}

		// handle preflight requests
		if r.Method == http.MethodOptions {
			w.WriteHeader(http.StatusNoContent)
			return
		}
	}

	maxRequestBytes, err := s.config.MaxRequestBytesLimiter.Limit(r.Context())
	if err != nil {
		msg := "Failed to get request size limit"
		s.lggr.Errorw(msg, "err", err)
		http.Error(w, msg, http.StatusInternalServerError)
		return
	}
	source := http.MaxBytesReader(nil, r.Body, int64(maxRequestBytes))
	rawMessage, err := io.ReadAll(source)
	if err != nil {
		s.lggr.Error("error reading request", err)
		w.WriteHeader(http.StatusBadRequest)
		return
	}

	// Optionally extract jwt token from authorization header
	authHeader := r.Header.Get("Authorization")
	jwtToken := ""
	if authHeader != "" {
		jwtToken = strings.TrimPrefix(authHeader, "Bearer ")
	}

	startTime := time.Now()
	rawResponse, httpStatusCode := s.handler.ProcessRequest(r.Context(), rawMessage, jwtToken)
	duration := time.Since(startTime)
	s.hMetrics.RecordRequestDuration(r.Context(), httpStatusCode, duration)
	s.hMetrics.RecordRequestCount(r.Context(), httpStatusCode)

	w.Header().Set("Content-Type", s.config.ContentTypeHeader)
	w.WriteHeader(httpStatusCode)
	_, err = w.Write(rawResponse) //nolint:gosec // G705: response body is written with an explicit Content-Type, not rendered as HTML
	if err != nil {
		s.lggr.Error("error when writing response", err)
	}
}
