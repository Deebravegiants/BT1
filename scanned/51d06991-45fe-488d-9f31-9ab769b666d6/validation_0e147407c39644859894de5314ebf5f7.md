## Finding: Missing Authorization on Debug/pprof Diagnostic Endpoints

This is a direct analog of the Kill Bill `AdminResource` issue: several administrative/diagnostic routes are wrapped only in generic session authentication and are never wrapped with `auth.RequiresAdminRole` (or even `auth.RequiresRunRole`), so any authenticated user — including the lowest-privilege `view` role — can reach them.

### Title
Missing Authorization on Debug/pprof Endpoints Allows Low-Privilege "view" Users to Dump Server Internals and Trigger Resource Exhaustion - (File: core/web/router.go)

### Summary
The `/v2/debug/pprof/*` routes are registered via `metricRoutes(authv2)` inside the `authv2` route group, which only requires the request to pass generic session/token authentication (`auth.Authenticate`) — there is no accompanying `auth.RequiresAdminRole` or `auth.RequiresRunRole` wrapper on any of these handlers, unlike virtually every other sensitive endpoint in the router (`/users`, `/keys/*/import`, `/keys/*/export`, `PATCH /log`, `/transfers`, etc.) which are explicitly wrapped with `auth.RequiresAdminRole` or `auth.RequiresEditRole`.

### Finding Description
In [1](#0-0) , `LogController.Patch` (which changes global log level / SQL logging) is correctly protected with `auth.RequiresAdminRole(lgc.Patch)`. However immediately below, `metricRoutes(authv2)` is invoked with a comment "Debug routes accessible via authentication" — but this only means *authenticated*, not role-gated.

`metricRoutes` registers the full `net/http/pprof` handler set unauthenticated by role: [2](#0-1) 

```
pprofGroup.GET("/", ...)
pprofGroup.GET("/cmdline", ...)
pprofGroup.GET("/profile", ...)
pprofGroup.POST("/symbol", ...)
pprofGroup.GET("/symbol", ...)
pprofGroup.GET("/trace", ...)
pprofGroup.GET("/allocs", ...)
pprofGroup.GET("/heap", ...)
...
```

None of these are wrapped with `auth.RequiresEditRole` or `auth.RequiresAdminRole`, the way admin-sensitive actions elsewhere are, e.g. `auth.RequiresAdminRole(ekc.Delete)`, `auth.RequiresAdminRole(ekc.Export)` at [3](#0-2) .

Confirming this gap: the project's own RBAC regression test suite, `routesRolesMap` in `core/web/auth/auth_test.go`, which enumerates every route and its required minimum role and is asserted against `view`/`run`/`edit`/`admin` test users, contains **no entries at all for `/v2/debug/pprof/*`**: [4](#0-3) . This means the missing-authorization gap is not caught by the existing test coverage — mirroring exactly how the Kill Bill `AdminResource` endpoints lacked permission annotations that would otherwise have been enforced.

The role hierarchy itself is defined and enforced elsewhere via `RequiresRunRole`/`RequiresEditRole`/`RequiresAdminRole` in [5](#0-4) , confirming that a "view" role user is intended to have only minimal (`account:read`-equivalent) privileges, yet is not blocked from these operational endpoints.

### Impact Explanation
A user provisioned with only the `view` role (the equivalent of Kill Bill's minimal `account:read` permission) can:
- Read full heap and goroutine dumps (`/v2/debug/pprof/heap`, `/goroutine`), which can leak in-memory secrets (API keys, private keys, session tokens, database credentials) that transiently reside in process memory.
- Read `/v2/debug/pprof/cmdline`, disclosing the exact process command line/arguments (potential secret/flag disclosure).
- Trigger `/v2/debug/pprof/profile?seconds=N` or `/trace?seconds=N` with a large `seconds` value, tying up CPU/goroutines and writer timeouts on the node for the duration — a denial-of-service / "put out of rotation" style impact directly analogous to the CVE's `putOutOfRotation` primitive.

This matches the CVSS vector of the original finding: confidentiality impact (VC:L via secret/internal-state disclosure) and availability impact (VA:H via CPU/goroutine exhaustion), reachable with only low (view-role) privileges over the network.

### Likelihood Explanation
High. This requires no more than a valid low-privilege API session/token — the same authentication already required to call other, harmless `view`-permitted endpoints. Any operator who provisions "view" accounts for monitoring/read-only dashboards inadvertently grants access to invasive debug primitives.

### Recommendation
Wrap all `metricRoutes` (pprof) handlers with `auth.RequiresAdminRole` (or at minimum `auth.RequiresEditRole`), consistent with how other operationally sensitive endpoints (`PATCH /log`, key import/export, user management) are protected. Add corresponding entries to `routesRolesMap` in `core/web/auth/auth_test.go` so the RBAC regression suite covers `/v2/debug/pprof/*` and prevents future regressions.

### Proof of Concept
1. Create/obtain a Chainlink node API user with role `view` (e.g., via `POST /v2/users` as admin, `{"role": "view"}`).
2. Authenticate as that user (`POST /sessions` or API token flow).
3. Issue `GET /v2/debug/pprof/heap?debug=1` — the request succeeds (HTTP 200) and returns a full heap dump, despite the requester holding only the lowest privilege role.
4. Issue `GET /v2/debug/pprof/profile?seconds=60` repeatedly from multiple view-role sessions to consume CPU/goroutines on the node, degrading service for legitimate operations — demonstrating the DoS analog to `putOutOfRotation`.

// RequiresRunRole extracts the user object from the context, and asserts the user's role is at least
// 'run'
func RequiresRunRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// RequiresEditRole extracts the user object from the context, and asserts the user's role is at least
// 'edit'
func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// RequiresAdminRole extracts the user object from the context, and asserts the user's role is 'admin'
func RequiresAdminRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role != clsessions.UserRoleAdmin {
			c.Abort()
			addForbiddenErrorHeaders(c, "admin", string(user.Role), user.Email)
			jsonAPIError(c, http.StatusForbidden, errors.New("Forbidden"))
			return
		}
		handler(c)
	}
}
