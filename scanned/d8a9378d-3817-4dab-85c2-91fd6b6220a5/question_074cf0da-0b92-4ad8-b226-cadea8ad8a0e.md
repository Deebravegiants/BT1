Target: `mergeIntentPayloads` (packages/intents-sdk/src/intents/intent-executer-impl/intent-executer.ts). Attacker input: a solver-relayed quote is fed into an integrator's `intentPayloadFactory`, which returns `customPayload.intents` containing a second `ft_withdraw` intent object that is structurally identical in value to one already present in `basePayload.intents` but is a distinct object reference. Preconditions: `IntentExecuter.signAndSendIntent` is called with `intents: [ft_withdraw_A]` and the factory appends `ft_withdraw_A_copy` (same token/amount/receiver_id, new object). Call sequence: `defaultIntentPayloadFactory` builds `basePayload`; `mergeIntentPayloads` computes `Array.from(new Set([...customPayloadIntents, ...basePayload.intents]))`; since `Set` dedupes by reference not value, both `ft_withdraw` intents survive; `IntentSignerNEP413.signIntent`/`IntentSignerViem.signIntent` serialize the merged `intents` array verbatim. Equality broken: intents.length in the signed `MultiPayload` != number of distinct-by-value intents the caller supplied. Impact: Critical - double debit of the withdrawal amount from the signer's balance in a single signed payload. Proof idea: vitest test mocking the relayer HTTP call, asserting `intentSigner.signIntent` is called with an `intents` array whose length equals `new Set(intents.map(JSON.stringify)).size`, not the raw array length.
