Unauthenticated actor can consume the Vault replay guard for another owner's allowlisted request, causing denial-of-service on that owner's legitimate Vault operation - ([File: core/capabilities/vault/allow_list_based_auth.go], [File: core/capabilities/vault/request_replay_guard.go], [File: core/capabilities/vault/authorizer.go])

### Summary
The Rio Network report describes an unprivileged actor exploiting a permissionless "report" function (`reportOutOfOrderValidatorExits`) whose success criteria depend only on public, externally-observable state (validator exit status) rather than on who is entitled to trigger the state transition. Because the function accepts any caller and consumes a limited resource (the exit slot for a specific validator index), an attacker can front-run/replay the condition and permanently deny the legitimate withdrawal path for other users.

The same bug class is reachable in chainlink's Vault gateway authorization pipeline. `allowListBasedAuth.AuthorizeRequest` (core/capabilities/vault/allow_list_based_auth.go:34-77) grants authorization purely by matching the SHA/keccak digest of an inbound JSON-RPC request against a *publicly readable* on-chain allowlist (`workflowRegistrySyncer.GetAllowlistedRequests`), with no verification of who is submitting the HTTP/gateway request. The resulting `AuthResult` digest is then passed into a single-use `RequestReplayGuard.CheckAndRecord` (core/capabilities/vault/request_replay_guard.go:35-47) via `authorizer.AuthorizeRequest` (core/capabilities/vault/authorizer.go:99-118), which permanently marks that digest as "seen" until expiry.

### Finding Description
1. A workflow owner allowlists a specific request (method + params + id) on-chain via the Workflow Registry. This on-chain allowlist entry, containing the `RequestDigest`, `Owner`, and `ExpiryTimestamp`, is public data readable by anyone via `GetAllowlistedRequests` [1](#0-0) .
2. For methods whose params do not embed secret ciphertext the caller cannot otherwise reproduce (e.g. `MethodSecretsDelete`, `MethodSecretsList`, which only reference `Owner`/`Namespace`/`Key` identifiers), an attacker who observes/derives the same request content can compute an identical digest and submit it to the internet-facing gateway before the legitimate owner's workflow node does.
3. `allowListBasedAuth.AuthorizeRequest` finds the digest match and returns a valid `AuthResult` bound to the victim owner — it never checks the identity of the HTTP/gateway caller, only that the *content digest* is allowlisted [2](#0-1) .
4. `authorizer.AuthorizeRequest` then calls the replay guard with that digest, which succeeds exactly once and permanently records the digest as consumed until its expiry [3](#0-2) [4](#0-3) .
5. When the legitimate owner's node later submits the exact same (now-consumed) request, `CheckAndRecord` returns `ErrRequestAlreadySeen`, and the genuine request is rejected with "request was already authorized previously" — exactly mirroring the Rio bug's consequence: a resource meant for one legitimate actor is irrevocably consumed by an unrelated, unprivileged party, blocking the intended operation until the allowlist entry expires.

This is directly analogous to the Rio class: a permissionless action gate keyed only on externally observable/public conditions (validator withdrawn status / request digest) rather than caller identity, allowing anyone to consume a single-use resource meant for a specific legitimate party and thereby block their operation.

### Impact Explanation
An attacker can deny a workflow owner's legitimate Vault operation (secret delete/list, and potentially create/update if ciphertext content can be reconstructed or guessed) by racing the gateway with the same request content. Because the digest is derived from request structure, not signed by or bound to the true submitter, this also raises a request-impersonation concern: the operation executes attributed to the victim owner's authorization even though it was actually triggered by an unrelated caller. At minimum this is an availability/DoS impact against a specific owner's Vault workflow (secrets management availability); at worst it enables an unauthorized party to trigger a privileged secret-management action under another owner's authorization context.

### Likelihood Explanation
Likelihood is bounded by two factors: (a) the attacker needs advance knowledge of the exact allowlisted request digest, which for content-free-of-ciphertext methods (`SecretsDelete`, `SecretsList`) is derivable from public/guessable identifiers (owner address, namespace, key), and (b) the attacker must win the race against the legitimate owner's node before it submits its own request within the retry window. This is feasible for a determined, unprivileged network attacker monitoring the on-chain allowlist events and racing the public gateway endpoint, but requires timing precision, making it a realistic but not trivial griefing vector.

### Recommendation
Bind authorization to the identity of the request originator (e.g., require the calling workflow node/owner to sign the specific request, verified in `AuthorizeRequest`, rather than granting authorization to whoever first replays the correct digest). Alternatively, scope the replay guard key to (owner, digest) and require proof that the submitter is the DON-side of the intended owner's workflow (already partially attempted via `validateSecretOwnersMatchAuthorized`), and reject the pattern where authorization solely depends on reproducing public on-chain content without any caller-bound signature over the gateway request itself.

### Proof of Concept
1. Owner `0xabc` allowlists a `SecretsDelete` request on-chain for `{Owner: "0xabc", Namespace: "ns", Key: "foo"}` with digest `D` and expiry `T`.
2. Attacker monitors the Workflow Registry allowlist event/state and computes the identical JSON-RPC request `{Method: MethodSecretsDelete, Params: {Owner:"0xabc", Namespace:"ns", Key:"foo"}}`, whose digest also equals `D` (confirmed reproducible via `allow_list_based_auth_test.go`'s `testAuthForRequests`, which shows digest equality drives authorization success) [5](#0-4) .
3. Attacker submits this request to the public gateway before the legitimate owner's node does. `allowListBasedAuth.AuthorizeRequest` succeeds (digest `D` matches, not expired) and `authorizer.AuthorizeRequest` records digest `D` in the replay guard as consumed [6](#0-5) .
4. When the legitimate owner's node subsequently submits the same request, `CheckAndRecord` returns `ErrRequestAlreadySeen` (`"request was already authorized previously"`) [4](#0-3) , and the owner's legitimate delete never executes until the on-chain allowlist entry expires and is re-registered.

func (r *allowListBasedAuth) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	r.lggr.Debugw("AllowListBasedAuth authorizing request", "method", req.Method, "requestID", req.ID)
	requestDigest, err := req.Digest()
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to create digest", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, err
	}
	requestDigestBytes, err := hex.DecodeString(requestDigest)
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to decode digest", "method", req.Method, "requestID", req.ID, "requestDigest", requestDigest, "error", err)
		return nil, err
	}
	requestDigestBytes32 := [32]byte(requestDigestBytes)
	if r.workflowRegistrySyncer == nil {
		r.lggr.Errorw("AllowListBasedAuth workflowRegistrySyncer is nil", "method", req.Method, "requestID", req.ID)
		return nil, errors.New("internal error: workflowRegistrySyncer is nil")
	}
	allowlistedRequest, allowedRequestsStrs, err := r.findAllowlistedItemWithRetry(ctx, req, requestDigest, requestDigestBytes32)
	if err != nil {
		return nil, err
	}
	if allowlistedRequest == nil {
		r.lggr.Debugw("AllowListBasedAuth request digest not allowlisted",
			"method", req.Method,
			"requestID", req.ID,
			"digestHexStr", requestDigest,
			"allowedRequestsStrs", allowedRequestsStrs)
		return nil, errors.New("request not allowlisted")
	}

	if time.Now().UTC().Unix() > int64(allowlistedRequest.ExpiryTimestamp) {
		authorizedRequestStr := string(allowlistedRequest.RequestDigest[:])
		r.lggr.Debugw("AllowListBasedAuth authorization expired", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", authorizedRequestStr, "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
		return nil, errors.New("request authorization expired")
	}

	digestKey := string(allowlistedRequest.RequestDigest[:])
	r.lggr.Debugw("AllowListBasedAuth authorization succeeded", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", digestKey, "owner", allowlistedRequest.Owner.Hex(), "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
	return &AuthResult{
		workflowOwner: allowlistedRequest.Owner.Hex(),
		digest:        digestKey,
		expiresAt:     int64(allowlistedRequest.ExpiryTimestamp),
	}, nil

var ErrRequestAlreadySeen = errors.New("request was already authorized previously")

// RequestReplayGuard prevents replay of already-processed requests by tracking
// request digests with expiry timestamps. It is safe for concurrent use.
//
// Used by both the AllowListBasedAuth flow and the JWTBasedAuth flow to ensure
// that a given request digest is only accepted once.
type RequestReplayGuard struct {
	mu      sync.Mutex
	seen    map[string]int64 // digest → unix expiry timestamp
	nowFunc func() time.Time // injectable for testing
}

// NewRequestReplayGuard creates a replay guard for authorized Vault requests.
func NewRequestReplayGuard() *RequestReplayGuard {
	return &RequestReplayGuard{
		seen:    make(map[string]int64),
		nowFunc: time.Now,
	}
}

// CheckAndRecord returns ErrRequestAlreadySeen if the digest was previously
// recorded and has not yet expired. Otherwise it records the digest with
// the given expiry timestamp (unix seconds, UTC).
//
// Expired entries are cleaned up on every call.
func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}
