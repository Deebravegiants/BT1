Attacker action: attacker sends a validly signed 'customers/data_request' body (their own shop) with 'X-Shopify-Shop-Domain' set to a victim shop, hoping the handler exports/emails the victim's customer PII to a URL embedded in the (attacker-authored, unsigned-topic but signed-body) JSON payload. Preconditions: handler implementation (per docs) uses WebhookMetadata#shop to look up which merchant's data-export destination to use, and WebhookMetadata#body for the destination/customer identifiers. Call sequence: Registry.process -> HmacValidator.validate(true) -> handler.handle(data: WebhookMetadata.new(shop: victim, body: attacker_json, topic: 'customers/data_request', ...)). Binding: shop whose PII is exported == shop authenticated by the signature — fails. Impact: Critical, exfiltration of a merchant's customer data (or being tricked into exporting data to an attacker-controlled destination named in the unsigned-context body) — a cross-tenant data exposure. Proof idea: minitest with a Mocha-mocked handler asserting the exact WebhookMetadata#shop value delivered equals the attacker-controlled header, never the shop that actually produced the HMAC.
