### Title
Unvalidated negative `offset`/`limit` GraphQL pagination arguments cause a slice-bounds panic in `NodeStatuses` reachable by any authenticated view-role user - ([File: core/services/chainlink/relayer_chain_interoperators.go])

### Summary
The GraphQL `Nodes` query accepts client-supplied `Offset`/`Limit` `*int32` arguments that are converted to `int` via `pageOffset`/`pageLimit` with **no bounds validation** (no check for `offset >= 1`, no upper bound on `limit`), unlike the JSONAPI REST pagination helper `ParsePaginatedRequest`, which strictly validates `page >= 1` and `size >= 1`. This is the same missing-input-validation-on-pagination bug class as the reported `/api/news-trading/feed` issue, just reached through the chainlink GraphQL API instead of a REST endpoint.

### Finding Description
`pageOffset`/`pageLimit` in the resolver package perform no validation and simply cast the raw `int32` argument: [1](#0-0) .

The `Nodes` resolver only requires a valid authenticated session (`authenticateUser`, which grants access to any role including the lowest `view` role) before forwarding these unvalidated values straight into `NodeStatuses`: [2](#0-1)  and [3](#0-2) .

`NodeStatuses` in `CoreRelayerChainInteroperators` then performs an unchecked slice operation using the caller-supplied `offset`:
```go
if len(result) < offset {
    return nil, 0, nil
}
result = result[offset:]
``` [4](#0-3) 

If `offset` is negative (e.g. `-1`), the guard `len(result) < offset` is false (a non-negative length is never less than a negative number), so execution proceeds to `result[offset:]` with a negative index, which is a slice-bounds-out-of-range condition in Go and will panic at runtime.

Contrast this with the REST pagination path, which explicitly rejects `page < 1` / `size < 1` before ever computing an offset: [5](#0-4) , and with the `Chains` resolver, which does defend against `offset` being out of range by returning an error instead of panicking: [6](#0-5) . The `Nodes`/`NodeStatuses` path lacks this equivalent bound check.

### Impact Explanation
The router does register `gin.Recovery()` middleware [7](#0-6) , so a panic here is caught and converted into a 500 response rather than crashing the whole process. This limits the impact to per-request denial of service / error responses rather than full node crash, which reduces severity compared to the original report's "server crash" framing. Any authenticated user, including one with only the minimal `UserRoleView` role, can trigger this without any special privilege, matching the "unprivileged-actor" analog scope (session-authenticated but least-privileged role).

### Likelihood Explanation
Trivial to trigger: a single authenticated GraphQL request `query { nodes(offset: -1) { ... } } }` from any logged-in user (view role or above) is sufficient. No preconditions beyond a valid session are required.

### Recommendation
- Validate `Offset`/`Limit` GraphQL pagination arguments in `pageOffset`/`pageLimit` (or at the top of each resolver) to reject negative offsets and non-positive/oversized limits, mirroring the validation already done in `ParsePaginatedRequest` for REST endpoints.
- Apply the same bound check used in the `Chains` resolver (`offset >= count` → return error) to `NodeStatuses`/`CoreRelayerChainInteroperators.NodeStatuses` before slicing, and add an explicit `offset < 0` / `limit < 0` check to prevent negative-index slicing.

### Proof of Concept
1. Log in as any user with the `view` role (lowest privilege) to obtain a valid session cookie.
2. Send a GraphQL request:
```graphql
query {
  nodes(offset: -1, limit: 10) {
    results {
      name
    }
  }
}
```
3. Execution reaches `result[offset:]` with `offset = -1`, causing a runtime panic that is caught by `gin.Recovery()` and surfaces as an internal server error, confirming the missing input validation on the pagination parameter.

// pageOffset returns the default page offset if nil, otherwise it returns the

func pageOffset(offset *int32) int {
	if offset == nil {

	}

// pageLimit returns the default page limit if nil, otherwise it returns the
// provided limit.
func pageLimit(limit *int32) int {
	if limit == nil {
		return PageDefaultLimit
	}

	return int(*limit)
}

func ParsePaginatedRequest(sizeParam, pageParam string) (int, int, int, error) {
	var err error
	page := 1
	size := PaginationDefault

	if sizeParam != "" {
		if size, err = strconv.Atoi(sizeParam); err != nil || size < 1 {
			return 0, 0, 0, fmt.Errorf("invalid size param, error: %w", err)
		}
	}

	if pageParam != "" {
		if page, err = strconv.Atoi(pageParam); err != nil || page < 1 {
			return 0, 0, 0, fmt.Errorf("invalid page param, error: %w", err)
		}
	}

	offset := (page - 1) * size
	return size, page, offset, nil
}
