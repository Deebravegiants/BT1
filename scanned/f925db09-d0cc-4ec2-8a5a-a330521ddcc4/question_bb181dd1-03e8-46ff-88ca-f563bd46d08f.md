Target: LifiExternalAction.callRouter (native branch, inputToken == address(0)). Attacker crafts `externalActionMetadata` that calls a router mock forwarding `msg.value` but reverting on `outputToken` transfer for exactly one wei so the router keeps `inputAmount` and sends back a partial ETH refund to `address(this)` (LifiExternalAction) via `router.call{value: inputAmount}` returning leftover ETH as part of success. Since `swappedAmount` is measured only on `outputToken` balance delta, any refunded ETH lands in LifiExternalAction's ETH balance permanently, uncounted by `-deltaAmountChanges`. Preconditions: `LifiExternalAction.receive()` payable exists, inputToken=address(0) in circomData.erc20TokenAddresses. Call sequence: transact -> _externalTransact transfers native `X` ETH to LifiExternalAction before runAction -> swap -> callRouter sends `inputAmount` to router, router refunds partial ETH to LifiExternalAction. Equality that breaks: ETH leaving the action to msg.sender (only `outputToken` UTXO, 0 ETH) != `-deltaAmountChanges[ethIndex] = X` in ETH Hinkal sent it; the refunded ETH balance is stranded and can be withdrawn by the next unprivileged caller whose own swap's `callRouter` for `outputToken==address(0)` measures `getERC20OrETHBalance(address(0))` before/after and captures the pre-existing stranded ETH as part of `swappedAmount`. Impact: Critical, theft of a prior user's ETH input by a later unrelated caller.
