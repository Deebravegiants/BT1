## Analysis Summary

The bBRO report describes a **premature state-removal bug**: user storage (`STAKERS`) gets deleted based on a *partial* zero-check (`pending_bro_reward.is_zero() && total_staked().is_zero()`), permanently orphaning any bBRO amount that wasn't accounted for in that check.

Searching `pallet-staking` / `pallet-staking-async` for the analogous class (state-removal that silently forfeits an unclaimed value the user is still entitled to), the relevant mechanism is `kill_stash`, which is invoked from both `reap_stash` and `do_withdraw_unbonded` whenever a stash's `Ledger` balance falls under the existential deposit. This removes `Ledger`, `Bonded`, and `Payee` — and `payout_stakers`/`do_payout_stakers_by_page` hard-requires a live `Ledger` entry (`Self::ledger(account)`), returning `Error::NotStash` if it's gone. This is structurally the same fault pattern: a storage-removal condition that doesn't check for outstanding claimable value (here, unclaimed era rewards within `HistoryDepth`) before deleting the records needed to claim it.

### Title
Permanent loss of unclaimed era staking rewards when a stash's `Ledger`/`Payee` records are destroyed via `kill_stash` - (File: `substrate/frame/staking/src/pallet/impls.rs`)

### Summary
`kill_stash` removes a stash's `Ledger`, `Bonded`, and `Payee` entries whenever `ledger.active` falls under the existential deposit, without checking whether the stash still has unclaimed staking rewards for eras within `HistoryDepth`. Since `do_payout_stakers_by_page` requires a live `Ledger` entry for the stash and returns `Error::NotStash` otherwise, any pending, legitimately-earned reward becomes permanently unclaimable once the stash is killed.

### Finding Description
`kill_stash` is called from two places:
- `do_withdraw_unbonded`, once `ledger.unlocking` is empty and `ledger.active < ED` (or zero) [1](#0-0) 
- `reap_stash`, callable by **any signed account** against a target stash once `origin_balance`/`ledger_total` fall below ED [2](#0-1) 

`kill_stash` unconditionally wipes `Ledger`, `Bonded`, and `Payee` via `StakingLedger::kill` [3](#0-2) [4](#0-3) 

Nothing in either call path checks whether the stash still has unclaimed era rewards. `do_payout_stakers_by_page` (the function used to claim rewards, callable up to `HistoryDepth` eras back) requires a still-existing `Ledger` record for the stash and fails with `NotStash` if it is missing: [5](#0-4) 

The underlying reward data (`ErasValidatorReward`, `ErasRewardPoints`, exposure/`ClaimedRewards`) is retained independently of `Ledger`/`Payee` and is *not* cleared by `kill_stash` — the reward is still "owed" on-chain, but the accounts needed to compute/route the payout (`Ledger`, `Payee`) have been deleted, making the claim permanently impossible (analogous to the bBRO contract deleting `STAKERS[user]` while `pending_bro_reward > 0`). The async variant of the pallet has the identical structure (`StakingLedger::kill`, `kill_stash`, `do_payout_stakers_by_page`) [6](#0-5) [7](#0-6) 

### Impact Explanation
A staker (validator or nominator) who has an outstanding, unclaimed era reward (within `HistoryDepth`) permanently and irrecoverably loses that reward the moment their stash is killed — whether that happens through their own `withdraw_unbonded()` call after their bonding period elapses, or through a third party calling the permissionless `reap_stash` once their balance has fallen under ED (e.g., through slashing). There is no recovery path: `Ledger`/`Payee` are gone, so `payout_stakers`/`payout_stakers_by_page` unconditionally return `NotStash`.

### Likelihood Explanation
This requires a specific but realistic sequencing: the stash has an unclaimed reward from a recent era, and then either voluntarily fully unbonds+withdraws, or is reaped by someone else after falling below ED (e.g., via slashing) before calling `payout_stakers`. Because `reap_stash` is intentionally permissionless (any signed account can invoke it against any reapable target), a third party can trigger the kill on a victim's stash without the victim's consent, as long as the victim's balance has already dropped under ED. This is a real, if narrow, denial of legitimate funds rather than a purely theoretical concern, and mirrors the exact defect class (destructive storage removal without a check for outstanding claimable value) described in the bBRO report.

### Recommendation
Before executing `kill_stash` (in both `reap_stash` and `do_withdraw_unbonded`), check for any unclaimed/unpaid era rewards for the stash within `HistoryDepth` (using the same bookkeeping `is_rewards_claimed`/`ClaimedRewards` machinery already used by `payout_stakers`) and either force-pay them out first or block the kill until they are claimed — mirroring the general principle that a storage removal must not proceed while the removed data set is required to redeem an outstanding balance.

### Proof of Concept
1. Stash `S` nominates/validates and earns a reward for era `E` (`ErasValidatorReward`, `ErasRewardPoints` populated for `E`).
2. `S` calls `chill` + `unbond(all)`; after `BondingDuration` eras pass, `S` calls `withdraw_unbonded`, which finds `ledger.active == 0` and invokes `kill_stash`, removing `Ledger`, `Bonded`, `Payee` for `S` [1](#0-0) .
3. Before this, `S` never called `payout_stakers(S, E)` for era `E` reward.
4. Any account now calls `payout_stakers(S, E)`; `do_payout_stakers_by_page` calls `Self::ledger(Stash(S))`, which fails since `Ledger` was removed, and the branch returns `Error::NotStash` [5](#0-4) .
5. `S`'s era-`E` reward remains permanently unclaimed with no way to retrieve it, even though `ErasValidatorReward`/`ErasRewardPoints`/exposure for era `E` still show it as owed.

	/// Clears all data related to a staking ledger and its bond in both [`Ledger`] and [`Bonded`]
	/// storage items and updates the stash staking lock.
	pub(crate) fn kill(stash: &T::AccountId) -> DispatchResult {
		let controller = <Bonded<T>>::get(stash).ok_or(Error::<T>::NotStash)?;

		<Ledger<T>>::get(&controller).ok_or(Error::<T>::NotController).map(|ledger| {
			Ledger::<T>::remove(controller);
			<Bonded<T>>::remove(&stash);
			<Payee<T>>::remove(&stash);

			// kill virtual staker if it exists.
			if <VirtualStakers<T>>::take(&ledger.stash).is_none() {
				// if not virtual staker, clear locks.
				asset::kill_stake::<T>(&ledger.stash)?;
			}

			Ok(())
		})?
	}
