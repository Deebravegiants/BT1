The Mute Amplifier bug (fee accrual permanently stops once a timestamp comparison flips after expiry) has a direct structural analog in `pallet-asset-rewards`, but the Substrate version is more severe: it causes a permanent arithmetic underflow that bricks the entire pool (not just fees).

### Title
Permanent underflow DoS in `pallet-asset-rewards` freezes all staked funds and rewards once a pool's `last_update_block` is updated past `expiry_block` — (File: `substrate/frame/asset-rewards/src/lib.rs`)

### Summary
`update_pool_rewards` unconditionally sets `last_update_block` to the current (unbounded) block number, while `reward_per_token` computes elapsed blocks as `last_block_reward_applicable(expiry_block) - last_update_block`, which is only valid when `last_update_block <= expiry_block`. Once any call happens after a pool's `expiry_block`, `last_update_block` is pushed past `expiry_block`, and every subsequent call permanently underflows, reverting every dispatchable on that pool — including the admin's own recovery call.

### Finding Description
`update_pool_rewards` sets the update checkpoint to the raw current block, not capped at expiry: [1](#0-0) 

`reward_per_token` computes `rewardable_blocks_elapsed` as `last_block_reward_applicable(pool_info.expiry_block).ensure_sub(pool_info.last_update_block)?`, where `last_block_reward_applicable` clamps `now` to `expiry_block`: [2](#0-1) 

Trace of the bug (analogous to the Mute report's `_mostRecentValueCalcTime` becoming `> endTime` and never satisfying `_mostRecentValueCalcTime < endTime` again):
1. Pool has `expiry_block = E`. Some call at block `L0 <= E` sets `last_update_block = L0`.
2. First post-expiry call (e.g. `unstake` by any staker) at block `N1 > E`: `reward_per_token` computes `E - L0` (valid), succeeds; `update_pool_rewards` then sets `last_update_block = N1` (> `E`, uncapped).
3. Any subsequent call at block `N2 > N1` (`stake`, `unstake`, `harvest_rewards`, or even the admin's `set_pool_reward_rate_per_block`/`set_pool_expiry_block`) computes `last_block_reward_applicable(E) = E` again, then `E.ensure_sub(N1)` — but `N1 > E`, so this **underflows** and returns `Err(ArithmeticError)`, aborting the whole extrinsic.

All mutating entry points funnel through this same path before doing anything else: [3](#0-2) [4](#0-3) [5](#0-4) 

Critically, `set_pool_expiry_block` — the only conceivable admin remedy — also calls `reward_per_token` first and would itself revert with the same underflow, so there is no in-protocol recovery path once triggered: [6](#0-5) 

### Impact Explanation
Unlike the original Mute Amplifier bug (only LP fees get trapped, principal remains withdrawable), here `unstake` itself goes through the same reverting code path, so once triggered:
- All staked tokens remain frozen (`AssetsFreezer`) forever — no staker can withdraw principal.
- All accrued/pending reward-asset balances in the pool account are unreachable via `harvest_rewards`.
- The admin cannot recover the pool via `set_pool_reward_rate_per_block` or `set_pool_expiry_block`, since these also call `reward_per_token` first.

This is a complete, permanent denial of service and fund lock for any pool that reaches this state, which is strictly worse than the referenced finding.

### Likelihood Explanation
This requires no privileged role and no attacker-specific setup: any unprivileged staker calling any pool-mutating extrinsic (`stake`, `unstake`, or `harvest_rewards`) after the pool's `expiry_block` naturally advances `last_update_block` past `expiry_block`. This is expected, normal usage of an expired pool (e.g. a late unstake as in the Mute PoC), making the trigger condition highly likely to occur organically for any pool that isn't extended before natural expiry with zero staked/updates in between.

### Recommendation
In `update_pool_rewards`, clamp the stored `last_update_block` to `last_block_reward_applicable(pool_info.expiry_block)` instead of the raw current block number, mirroring the clamp already used in `reward_per_token`: [1](#0-0) 

### Proof of Concept
1. `create_pool` with `expiry_block = 25` (as in the existing test suite's `DEFAULT_EXPIRE_AFTER` setup): [7](#0-6) 
2. Staker stakes tokens before expiry.
3. Advance `System::set_block_number` to e.g. `30` (past expiry) and call `unstake` (or `harvest_rewards`) once — this succeeds and sets `PoolInfo.last_update_block = 30`.
4. Advance to block `40` and call `stake`/`unstake`/`harvest_rewards`/`set_pool_expiry_block` again on the same pool — `reward_per_token`'s `last_block_reward_applicable(25).ensure_sub(30)` underflows (`25 - 30`), returning `ArithmeticError`, and the call reverts.
5. Repeat step 4 with any other account or the admin's `set_pool_expiry_block` — all revert identically, permanently locking staked funds and reward-asset balances in the pool.

		/// Derives the current reward per token for this pool.
		pub(super) fn reward_per_token(
			pool_info: &PoolInfoFor<T>,
		) -> Result<T::Balance, DispatchError> {
			if pool_info.total_tokens_staked.is_zero() {
				return Ok(pool_info.reward_per_token_stored);
			}

			let rewardable_blocks_elapsed: u32 =
				match Self::last_block_reward_applicable(pool_info.expiry_block)
					.ensure_sub(pool_info.last_update_block)?
					.try_into()
				{
					Ok(b) => b,
					Err(_) => return Err(Error::<T>::BlockNumberConversionError.into()),
				};

			Ok(pool_info.reward_per_token_stored.ensure_add(
				pool_info
					.reward_rate_per_block
					.ensure_mul(rewardable_blocks_elapsed.into())?
					.ensure_mul(PRECISION_SCALING_FACTOR.into())?
					.ensure_div(pool_info.total_tokens_staked)?,
			)?)
		}

		/// Derives the amount of rewards earned by a staker.
		///
		/// This is a helper function for `update_pool_rewards` and should not be called directly.
		fn derive_rewards(
			staker_info: &PoolStakerInfo<T::Balance>,
			reward_per_token: &T::Balance,
		) -> Result<T::Balance, DispatchError> {
			Ok(staker_info
				.amount
				.ensure_mul(reward_per_token.ensure_sub(staker_info.reward_per_token_paid)?)?
				.ensure_div(PRECISION_SCALING_FACTOR.into())?
				.ensure_add(staker_info.rewards)?)
		}

		fn last_block_reward_applicable(pool_expiry_block: BlockNumberFor<T>) -> BlockNumberFor<T> {
			let now = T::BlockNumberProvider::current_block_number();
			if now < pool_expiry_block {
				now
			} else {
				pool_expiry_block
			}
		}
