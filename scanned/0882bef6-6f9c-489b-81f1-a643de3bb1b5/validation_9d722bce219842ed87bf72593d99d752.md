### Title
Bridge Outgoing Authentication Token Disclosed to Read-Only Users via GET /v2/bridge_types - (File: core/web/bridge_types_controller.go)

### Summary
`GET /v2/bridge_types` and the equivalent GraphQL `bridges` query are reachable by any authenticated user, including the lowest-privilege `view` role, yet the response serializer unconditionally includes each bridge's `OutgoingToken` — a plaintext secret used to authenticate the node to external adapters.

### Finding Description
The route is registered under the generic `authv2` group with no role gate beyond authentication, unlike the bridge mutation routes which require `RequiresEditRole`: [1](#0-0) 

`BridgeTypesController.Index` fetches all bridges from the ORM and serializes them via `presenters.NewBridgeResource` with no redaction: [2](#0-1) 

`BridgeResource` includes `OutgoingToken` as a plain, non-omitted JSON field (unlike `IncomingToken`, which is `omitempty` and only populated at creation time): [3](#0-2) 

The `OutgoingToken` is a per-bridge secret generated alongside the (hashed) `IncomingToken`, stored in plaintext in `BridgeType.OutgoingToken`, and returned as-is by the presenter: [4](#0-3) 

The same unredacted field is also exposed through the GraphQL `Bridge` type/resolver, which only requires a valid session (any role) via `authenticateUser`, not `authenticateUserCanEdit`/`authenticateUserIsAdmin`: [5](#0-4) [6](#0-5) 

This mirrors the reported bug class: a list/read route that is authenticated but not authorization-gated to the level of its sibling mutation routes, combined with a resource serializer/filter that fails to redact a secret-bearing field.

### Impact Explanation
`OutgoingToken` is the credential the Chainlink node itself would use to authenticate to the configured external adapter/bridge endpoint. Disclosure to a low-privilege `view`-role user (or any authenticated GraphQL client) lets that user impersonate the node when calling the external adapter directly, or use the token to interact with the downstream bridge/EA infrastructure it protects — a credential/secret disclosure impacting confidentiality of a connected downstream system, consistent with CVSS VC:H in the source report.

### Likelihood Explanation
Any authenticated user regardless of role can trigger this by issuing `GET /v2/bridge_types` (or the GraphQL `bridges`/`bridge` query); no special privilege, timing, or race condition is required, and the field is returned unconditionally whenever bridges exist. Likelihood is high for any deployment that grants `view`-role API/GraphQL access to less-trusted operators.

### Recommendation
- Redact `OutgoingToken` from `presenters.BridgeResource` for list/show responses (only surface secrets at creation, similar to how `IncomingToken` is `omitempty` and populated only on create), or
- Require `auth.RequiresEditRole`/`RequiresAdminRole` (matching the mutation routes) on `GET /v2/bridge_types` and `GET /v2/bridge_types/:BridgeName`, and apply an analogous role gate in the GraphQL `bridges`/`bridge` resolvers.

### Proof of Concept
1. Create a `view`-role API user/session (`auth.RequiresRunRole`/`RequiresEditRole` is not applied to the bridge GET routes, only `auth.Authenticate`).
2. As that low-privilege user, call `GET /v2/bridge_types` (or run the GraphQL `bridges { results { outgoingToken } }` query).
3. Observe the response includes `attributes.outgoingToken` (or `outgoingToken` in GraphQL) with the plaintext secret, as shown in the existing test fixtures: [7](#0-6) [8](#0-7)

// Index lists Bridges, one page at a time.
func (btc *BridgeTypesController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	bridges, count, err := btc.App.BridgeORM().BridgeTypes(ctx, offset, size)

	resources := make([]presenters.BridgeResource, 0, len(bridges))
	for _, bridge := range bridges {
		resources = append(resources, *presenters.NewBridgeResource(bridge))
	}

	paginatedResponse(c, "Bridges", size, page, resources, count, err)
}

// BridgeType is used for external adapters and has fields for
// the name of the adapter and its URL.
type BridgeType struct {
	Name                   BridgeName    `db:"name"`
	URL                    models.WebURL `db:"url"`
	Confirmations          uint32        `db:"confirmations"`
	IncomingTokenHash      string        `db:"incoming_token_hash"`
	Salt                   string        `db:"salt"`
	OutgoingToken          string        `db:"outgoing_token"`
	MinimumContractPayment *assets.Link  `db:"minimum_contract_payment"`
	CreatedAt              time.Time     `db:"created_at"`
	UpdatedAt              time.Time     `db:"updated_at"`
	UseConnectionManager   bool          `db:"use_connection_manager" json:"useConnectionManager"`
}

// NewBridgeType returns a bridge type authentication (with plaintext
// password) and a bridge type (with hashed password, for persisting)
func NewBridgeType(btr *BridgeTypeRequest) (*BridgeTypeAuthentication,
	*BridgeType, error,
) {
	incomingToken := utils.NewSecret(24)
	outgoingToken := utils.NewSecret(24)
	salt := utils.NewSecret(24)

	hash, err := incomingTokenHash(incomingToken, salt)
	if err != nil {
		return nil, nil, err
	}

	return &BridgeTypeAuthentication{
		Name:                   btr.Name,
		URL:                    btr.URL,
		Confirmations:          btr.Confirmations,
		IncomingToken:          incomingToken,
		OutgoingToken:          outgoingToken,
		MinimumContractPayment: btr.MinimumContractPayment,
		UseConnectionManager:   btr.UseConnectionManager,
	}, &BridgeType{
		Name:                   btr.Name,
		URL:                    btr.URL,
		Confirmations:          btr.Confirmations,
		IncomingTokenHash:      hash,
		Salt:                   salt,
		OutgoingToken:          outgoingToken,
		MinimumContractPayment: btr.MinimumContractPayment,
		UseConnectionManager:   btr.UseConnectionManager,
	}, nil
