### Title
Wildcard CORS origin check uses naive suffix match, allowing subdomain-impersonation bypass - (File: core/services/gateway/network/httpserver.go)

### Summary
The Gateway's user-facing HTTP server (`httpServer.handleRequest`) implements CORS origin validation via `isAllowedOrigin`, which supports wildcard entries like `https://*.ethereum.org` in `CORSAllowedOrigins`. The wildcard match strips the `*.` prefix and then checks `strings.HasSuffix(originHost, allowedHost)` with no requirement that the matched suffix be preceded by a `.` (domain label boundary). [1](#0-0) 

### Finding Description
`isAllowedOrigin` is reached for every incoming request to the gateway's unprivileged, internet-facing user endpoint whenever `CORSEnabled` is true. [2](#0-1)  It parses the operator-configured wildcard allowlist entry (e.g. `https://*.ethereum.org`), strips the `*.` prefix to get `ethereum.org`, and then does a raw string-suffix comparison against the request's `Origin` host: [3](#0-2) 

```go
if strings.HasPrefix(allowedHost, "*.") {
    allowedHost = allowedHost[2:]
    if strings.HasSuffix(originHost, allowedHost) {
        return true
    }
}
```

This is a classic domain-suffix confusion bug: `strings.HasSuffix` matches any string ending with the literal characters `ethereum.org`, not just proper subdomains separated by a `.`. An attacker who registers (or controls) a completely unrelated domain such as `evilxethereum.org` (no dot before "ethereum.org") would pass this check, because `"evilxethereum.org"` ends with the exact byte sequence `"ethereum.org"`. The intended semantics ("any subdomain of ethereum.org") are not what is implemented; the actual semantics are "any domain whose name ends with these characters," which is a materially broader and attacker-controllable set of origins. This directly matches the "Origin Validation Error" bug class cited in the external report. [4](#0-3) 

Once `isAllowedOrigin` returns true, the server reflects the attacker's `Origin` value back in `Access-Control-Allow-Origin` and grants `GET, POST, OPTIONS` plus `Content-Type` header access: [5](#0-4) 

### Impact Explanation
This CORS check gates who can make cross-origin, script-readable requests to the gateway's unprivileged user API (`ProcessRequest`, dispatched via `httpServer.handleRequest` → `gateway.ProcessRequest`), which handles arbitrary JSON-RPC/legacy user messages routed to DON handlers (job/capability execution, vault operations, etc.) [6](#0-5) . An attacker who registers a domain ending in the literal configured suffix (e.g. `notreallyethereum.org` for an allowlist of `https://*.ethereum.org`) can host a malicious page that performs authenticated-looking cross-origin fetches against the gateway and read the JSON responses in the browser, defeating the operator's intent to scope browser-based access to a specific trusted domain family. This can enable cross-user response confusion or credential/token leakage for any deployment relying on wildcard CORS entries to restrict which third-party web frontends may interact with the gateway.

### Likelihood Explanation
Exploitability only requires that the target gateway operator configured a wildcard entry in `CORSAllowedOrigins` (a supported, documented pattern demonstrated in the codebase's own tests, e.g. `https://*.ethereum.org`) [7](#0-6) , and that an unprivileged attacker registers or controls any domain name ending in that literal suffix string. Domain registration is cheap and fully attacker-controlled, and no authentication or privileged access to the gateway or DON is needed — only the ability to send an HTTP request with a crafted `Origin` header from a browser context on the attacker's domain.

### Recommendation
Fix the suffix check to require a proper subdomain boundary, e.g.:
```go
if strings.HasPrefix(allowedHost, "*.") {
    suffix := allowedHost[1:] // ".ethereum.org" (keep the dot)
    if originHost == allowedHost[2:] || strings.HasSuffix(originHost, suffix) {
        return true
    }
}
```
This ensures `originHost` must equal the base domain or end with `.` + base domain, preventing sibling/impersonating domains from matching.

### Proof of Concept
1. Configure the gateway with `CORSEnabled = true` and `CORSAllowedOrigins = ["https://*.ethereum.org"]`.
2. From a browser page hosted on `https://evilxethereum.org` (attacker-registered, not a subdomain of `ethereum.org`), issue `fetch('https://<gateway-host>/user', {method: 'POST', body: ...})` with `Origin: https://evilxethereum.org`.
3. `isAllowedOrigin` computes `allowedHost = "ethereum.org"` and evaluates `strings.HasSuffix("evilxethereum.org", "ethereum.org")`, which is `true`, so the server responds with `Access-Control-Allow-Origin: https://evilxethereum.org`, letting the attacker's page read the gateway's JSON-RPC response programmatically. func (s *httpServer) isAllowedOrigin(origin string) bool {
	originScheme, originHost, originPort, err := s.splitURL(origin)
	if err != nil {
		s.lggr.Debug("error parsing origin URL", err)
		return false
	}
	for _, allowed := range s.config.CORSAllowedOrigins {
		// probably better to do this once when server starts and store it in a map
		// this is an easier solution so we don't have to apply more changes to the code
		// just need to be careful when specifying allowed origins in the config file
		allowedScheme, allowedHost, allowedPort, err := s.splitURL(allowed)
		if err != nil {
			s.lggr.Debug("error parsing allowed origin URL", err)
			continue
		}
		// skip if the scheme doesn't match at all
		if originScheme != allowedScheme {
			continue
		}
		// skip if the port doesn't match at all
		if originPort != allowedPort {
			continue
		}
		// check for exact host match (e.g., remix.com)
		if originHost == allowedHost {
			return true
		}
		// check for wildcard host match (e.g., *.remix.com)
		if strings.HasPrefix(allowedHost, "*.") {
			allowedHost = allowedHost[2:]
			if strings.HasSuffix(originHost, allowedHost) {
				return true
			}
		}
	}
	return false
