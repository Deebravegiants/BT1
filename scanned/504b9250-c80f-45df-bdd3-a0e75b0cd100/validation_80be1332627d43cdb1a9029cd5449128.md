### Title
Unauthenticated `PATCH /v2/resume/:runID` endpoint allows anyone to resume/mutate a pipeline run's task result - ([File: core/web/router.go])

### Summary
Chainlink's web router registers the pipeline-run resume endpoint on a route group with **no authentication middleware whatsoever**, unlike virtually every other state-mutating `/v2` route which is wrapped in `auth.Authenticate(...)` plus a role check (`RequiresRunRole`/`RequiresEditRole`/`RequiresAdminRole`). This mirrors the reported bug class: a state-changing function (`setPoolActive`) that should be access-controlled but is callable by anyone.

### Finding Description
In `core/web/router.go`, `v2Routes` creates an `unauthedv2` group with no auth middleware and registers the resume handler directly on it: [1](#0-0) 

```go
unauthedv2 := r.Group("/v2")

prc := PipelineRunsController{app}
psec := PipelineJobSpecErrorsController{app}
unauthedv2.PATCH("/resume/:runID", prc.Resume)

authv2 := r.Group("/v2", auth.Authenticate(app.AuthenticationProvider(),
	auth.AuthenticateByToken,
	auth.AuthenticateBySession,
))
```

Every other mutating action in this file (users, keys, bridge types, jobs, transfers, chains, external initiators, replay, etc.) is wrapped in `auth.Authenticate` and further gated by `auth.RequiresRunRole` / `auth.RequiresEditRole` / `auth.RequiresAdminRole` (see, e.g., `authv2.POST("/replay_from_block/:number", auth.RequiresRunRole(rc.ReplayFromBlock))` at [2](#0-1) ). `prc.Resume`, by contrast, has zero authentication.

The handler itself performs no additional authorization check — it parses the path parameter as a UUID, decodes an attacker-supplied JSON body into a `pipeline.ResumeRequest`, and immediately calls into the application to mutate pipeline-run state: [3](#0-2) 

```go
func (prc *PipelineRunsController) Resume(c *gin.Context) {
	taskID, err := uuid.Parse(c.Param("runID"))
	...
	rr := pipeline.ResumeRequest{}
	decoder := json.NewDecoder(c.Request.Body)
	err = errors.Wrap(decoder.Decode(&rr), "failed to unmarshal JSON body")
	...
	result, err := rr.ToResult()
	...
	if err := prc.App.ResumeJobV2(c.Request.Context(), taskID, result); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
	c.Status(http.StatusOK)
}
```

`ResumeJobV2` forwards straight to the pipeline runner: [4](#0-3) 

```go
func (app *ChainlinkApplication) ResumeJobV2(
	ctx context.Context,
	taskID uuid.UUID,
	result pipeline.Result,
) error {
	return app.pipelineRunner.ResumeRun(ctx, taskID, result.Value, result.Error)
}
```

`ResumeRun` writes the attacker-supplied value/error into the task run and, if this was the last pending task, immediately restarts pipeline execution with that value/error baked in: [5](#0-4) 

The presence of the dedicated audit event name `audit.UnauthedRunResumed` confirms the developers deliberately accepted that this path is unauthenticated by design — the UUID `runID` (a per-task ID, not the run ID) is meant to act as an unguessable bearer secret, analogous to a webhook callback token. This is architecturally similar to designs elsewhere in the codebase where a secret/token embedded in the URL substitutes for a role check. Note this is the **only** state-mutating `/v2` route lacking `auth.Authenticate`.

### Impact Explanation
If a UUID task ID for a suspended (async/bridge) pipeline task run is disclosed or becomes guessable/leaked (e.g., via logs, error messages, a compromised bridge/external adapter, or any of the many code paths that read `pipeline_task_runs.id`), any unauthenticated network client can:
- Inject an arbitrary attacker-controlled `value`/`error` into that pipeline task, directly influencing downstream job/task outputs (feed reports, on-chain transmission decisions, etc.), and
- Force early completion/restart of a suspended run, potentially racing the legitimate callback (a "frontrun the resume" scenario directly analogous to the described `setPoolActive`/bid-frontrunning issue).

This is a full authentication bypass on a state-mutating endpoint — the only gate is knowledge of a UUID, which is a much weaker control than the account-authentication + role checks (`auth.RequiresRunRole`, etc.) applied to every functionally similar endpoint in this router (e.g., `/v2/jobs/:ID/runs` requires `RequiresRunRole`, but `/v2/resume/:runID` requires nothing).

### Likelihood Explanation
Exploitability depends entirely on an attacker obtaining a valid `taskID`. Chainlink relies on UUIDv4 unguessability as the sole protection, which is a deliberate design tradeoff rather than a coding oversight — this reduces likelihood relative to a pure "forgot the modifier" bug, but the endpoint is still unauthenticated network-facing code that departs from the router's own consistent RBAC pattern, and any leakage of the UUID (logs, monitoring, third-party bridge behavior, timing/side channels) fully compromises it with no additional authentication barrier.

### Recommendation
- Require some form of authentication/authorization on `PATCH /v2/resume/:runID` (e.g., move it into `authv2` and gate with `auth.RequiresRunRole`, or require a pre-shared bridge/external-initiator credential specifically scoped to that job), rather than relying solely on UUID secrecy.
- At minimum, add rate limiting/anomaly detection specific to this route (distinct from the generic authenticated-route rate limiter, since this route is unauthenticated) and ensure `runID`/task UUIDs are never logged, echoed in errors, or otherwise exposed.
- Document and audit all code paths that could leak a task run UUID, since the entire security of this endpoint rests on that value remaining secret.

### Proof of Concept
1. Obtain (or guess/leak) the UUID of a currently-suspended task run (`pipeline_task_runs.id`) belonging to an async/bridge task on a target Chainlink node — e.g., via a bridge/external adapter log, an internal monitoring dashboard, or a timing side channel.
2. Without any authentication headers/cookies, send:
```
PATCH /v2/resume/<taskID> HTTP/1.1
Content-Type: application/json

{"value": "<attacker-controlled-value>"}
```
3. The router dispatches directly to `PipelineRunsController.Resume` (no `auth.Authenticate` middleware runs), which decodes the body and calls `App.ResumeJobV2(ctx, taskID, result)` → `pipelineRunner.ResumeRun`, writing the attacker's value into the task run and potentially restarting the pipeline immediately with the forged result, all without any credential.

```go
// Resume finishes a task and resumes the pipeline run.
// Example:
// "PATCH <application>/jobs/:ID/runs/:runID"
func (prc *PipelineRunsController) Resume(c *gin.Context) {
	taskID, err := uuid.Parse(c.Param("runID"))
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	rr := pipeline.ResumeRequest{}
	decoder := json.NewDecoder(c.Request.Body)
	err = errors.Wrap(decoder.Decode(&rr), "failed to unmarshal JSON body")
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	result, err := rr.ToResult()
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	if err := prc.App.ResumeJobV2(c.Request.Context(), taskID, result); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
	c.Status(http.StatusOK)
}
```

```go
func (r *runner) ResumeRun(ctx context.Context, taskID uuid.UUID, value any, err error) error {
	run, start, err := r.orm.UpdateTaskRunResult(ctx, taskID, Result{
		Value: value,
		Error: err,
	})
	if err != nil {
		return fmt.Errorf("failed to update task run result: %w", err)
	}

	// TODO: Should probably replace this with a listener to update events
	// which allows to pass in a transactionalised database to this function
	if start {
		// start the runner again
		go func() {
			ctx, cancel := r.chStop.NewCtx()
			defer cancel()
			if _, err := r.Run(ctx, &run, false, nil); err != nil {
				r.lggr.Errorw("Resume run failure", "err", err)
			}
			r.lggr.Debug("Resume run success")
		}()
	}
	return nil
}
```
