### Title
Missing Timestamp Freshness Validation in Web API Trigger Payload Processing - ([File: core/capabilities/webapi/trigger/trigger.go])

### Summary
The `TriggerRequestPayload` schema explicitly documents that its `timestamp` field "needs to be within certain freshness to be processed," but the actual handler code that processes incoming trigger events (`processTrigger`) never validates this timestamp against the current time. This mirrors the root cause of the Pyth `_validateAndGetPrice` finding: a field intended to gate acceptance based on time-freshness is defined in the data model/schema but the validation logic that should enforce that freshness constraint is absent or disconnected from the actual check performed.

### Finding Description
The JSON schema for the web API trigger explicitly requires a `timestamp` field and documents its purpose: [1](#0-0) 

This is reflected in the generated Go struct with the same doc comment: [2](#0-1) 

However, `processTrigger` in `core/capabilities/webapi/trigger/trigger.go`, which is the function invoked for every inbound `web_api_trigger` gateway message from an external/unprivileged sender, never reads or validates `payload.Timestamp`. The only checks performed are: non-empty topics, sender allowlist membership, and rate limiting: [3](#0-2) 

The message enters the system through `HandleGatewayMessage`, which decodes the JSON payload from the gateway's message envelope and dispatches directly to `processTrigger` without any timestamp/staleness check performed beforehand either: [4](#0-3) 

This is analogous to the Pyth `PythOracle` bug: the report's issue is that a value meant to gate acceptance based on time validity (`oracleVersion`) is used inconsistently/without proper validation against the current time, letting stale or arbitrary values pass. Here, the documented freshness gate on `Timestamp` is simply never enforced at all in the trigger ingestion path, so a sender-controlled/stale `timestamp` value (or an arbitrarily old or future one) is accepted identically to a fresh one.

### Impact Explanation
An external, allowlisted-but-otherwise-unprivileged sender (any address in `trigger.allowedSenders`, which is workflow-owner configured but represents the untrusted internet-facing side of the gateway) can submit `web_api_trigger` messages with a stale or manipulated `timestamp` value. Because there is no freshness enforcement in `processTrigger`, a previously valid/old trigger payload (e.g. captured earlier, or replayed via a route that bypasses the DON's own message-level replay checks) can be resubmitted and will be forwarded to the workflow engine as if it were a fresh, current event, since `TriggerEventID` is only deduplicated based on `sender+TriggerEventId`, not correlated with timestamp freshness. This can cause acceptance of stale trigger data driving workflow executions with outdated inputs, compromising the correctness of automation/workflow decisions that depend on the declared freshness guarantee.

### Likelihood Explanation
Reachable directly by any address present in a workflow's `allowedSenders` list issuing a `web_api_trigger` request through the gateway — no elevated privileges beyond being an allowed sender are required, and the check is entirely missing rather than merely misconfigured, making exploitation straightforward given a valid/allowed sender identity and a captured/crafted payload.

### Recommendation
Enforce timestamp freshness explicitly in `processTrigger` (or earlier, in `HandleGatewayMessage`) before dispatching to registered workflow trigger channels: compute `age := time.Now().Unix() - payload.Timestamp` and reject (respond with `ERROR` status) if `age` exceeds a configured maximum freshness window (and optionally reject timestamps too far in the future). This restores the guarantee documented in the schema (`event_trigger-schema.json`) and generated struct comments.

### Proof of Concept
1. Workflow W registers a `web_api_trigger` with `allowedSenders = [S]`, `allowedTopics = [T]`.
2. Attacker/allowed sender S sends (or replays) a `web_api_trigger` gateway message with `payload.Timestamp` set to an arbitrary/old unix timestamp (e.g., far in the past) and `topics = [T]`.
3. `HandleGatewayMessage` decodes the payload and calls `processTrigger`, which only checks `allowedSenders`, `allowedTopics`, and rate limiting — the stale `Timestamp` value is never inspected.
4. `processTrigger` forwards the event to the workflow's trigger channel as `ACCEPTED`, and the workflow engine executes on the stale payload, despite the schema's explicit freshness requirement never being enforced.

func (h *triggerConnectorHandler) processTrigger(ctx context.Context, gatewayID string, body *api.MessageBody, sender ethCommon.Address, payload webapicap.TriggerRequestPayload) error {
	// Pass on the payload with the expectation that it's in an acceptable format for the executor
	wrappedPayload, err := values.WrapMap(payload)
	if err != nil {
		return fmt.Errorf("error wrapping payload %w", err)
	}
	topics := payload.Topics

	// empty topics is error for V1
	if len(topics) == 0 {
		return errors.New("empty Workflow Topics")
	}

	h.mu.Lock()
	triggers := slices.Collect(maps.Values(h.registeredWorkflows))
	h.mu.Unlock()

	// workflows that have matched topics
	matchedWorkflows := 0
	// workflows that have matched topic and passed all checks
	fullyMatchedWorkflows := 0
	for _, trigger := range triggers {
		for _, topic := range topics {
			if trigger.allowedTopics[topic] {
				matchedWorkflows++
				if !trigger.allowedSenders[sender.String()] {
					err = fmt.Errorf("unauthorized Sender %s, messageID %s", sender.String(), body.MessageID)
					h.lggr.Debugw(err.Error())
					continue
				}
				if !trigger.rateLimiter.Allow(body.Sender) {
					err = fmt.Errorf("request rate-limited for sender %s, messageID %s", sender.String(), body.MessageID)
					continue
				}
				fullyMatchedWorkflows++

func (h *triggerConnectorHandler) HandleGatewayMessage(ctx context.Context, gatewayID string, req *jsonrpc.Request[json.RawMessage]) error {
	msg, err := hc.ValidatedMessageFromReq(req)
	if err != nil {
		h.lggr.Errorw("error validating message from request", "err", err, "request", req)
		return nil
	}
	body := &msg.Body
	sender := ethCommon.HexToAddress(body.Sender)
	var payload webapicap.TriggerRequestPayload
	err = json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw("error decoding payload", "err", err)
		err = h.sendResponse(ctx, gatewayID, body, ghcapabilities.TriggerResponsePayload{Status: "ERROR", ErrorMessage: fmt.Errorf("error %s decoding payload", err.Error()).Error()})
		if err != nil {
			h.lggr.Errorw("error sending response", "err", err)
		}
		return nil
	}

	switch body.Method {
	case ghcapabilities.MethodWebAPITrigger:
		resp := h.processTrigger(ctx, gatewayID, body, sender, payload)
		var response ghcapabilities.TriggerResponsePayload
		if resp == nil {
			response = ghcapabilities.TriggerResponsePayload{Status: "ACCEPTED"}
		} else {
			response = ghcapabilities.TriggerResponsePayload{Status: "ERROR", ErrorMessage: resp.Error()}
			h.lggr.Errorw("Error processing trigger", "gatewayID", gatewayID, "body", body, "response", resp)
		}
		err = h.sendResponse(ctx, gatewayID, body, response)
		if err != nil {
			h.lggr.Errorw("Error sending response", "body", body, "response", response, "err", err)
		}
		return nil
