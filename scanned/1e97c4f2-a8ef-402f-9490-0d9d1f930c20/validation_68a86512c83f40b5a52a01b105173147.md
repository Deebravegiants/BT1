### Title
Missing memory-expansion gas metering in EVM interpreter memory ops allows near-1MB alloc/zero-fill per call at fixed opcode gas cost - (File: substrate/frame/revive/src/vm/evm/memory.rs)

### Summary
`Memory::<T>::resize` only enforces a hard ceiling (`crate::limits::EVM_MEMORY_BYTES` = 1 MiB) and performs `self.data.resize(target_len, 0)` without any per-word gas cost being charged for the *delta* being grown. The callers in `substrate/frame/revive/src/vm/evm/instructions/memory.rs` (`mload`, `mstore`, `mstore8`) and `mcopy` only charge the fixed Ethereum opcode base cost (`VERYLOW`/`BASE`/`copy_cost_verylow`), never the standard EVM "memory expansion" formula (`3*words + words²/512`) that Ethereum uses specifically to make the cost proportional to the size memory is grown to.

### Finding Description
In `Memory::<T>::resize` (`substrate/frame/revive/src/vm/evm/memory.rs:66-79`), the target length is computed and, if it exceeds `EVM_MEMORY_BYTES`, execution halts with `OutOfGas`; otherwise `self.data.resize(target_len, 0)` is executed unconditionally with no relationship between the size of the resize and any gas/weight charge tied to that specific growth. [1](#0-0) 

Every call site that triggers a resize only pays a fixed, size-independent opcode cost before calling `resize`:
- `mload`/`mstore`/`mstore8` charge `EVMGas(VERYLOW)` (a constant few gas) regardless of how far `offset` pushes memory growth. [2](#0-1) 
- `mcopy` charges `copy_cost_verylow(len)`, which is proportional to the copy length `len`, not to the actual memory expansion caused by `max(dst, src) + len` (an attacker can set a huge `dst`/`src` offset with `len` = 32, paying for a tiny copy while forcing memory growth close to the 1 MiB ceiling). [3](#0-2) 

Real EVM implementations (including upstream `revm`) charge an explicit memory-expansion cost (quadratic-ish in the number of words) on top of the opcode's fixed cost, precisely so that the resource cost of growing/zero-filling large memory regions is priced. That formula is completely absent here — `revm::interpreter::gas::{BASE, VERYLOW, copy_cost_verylow}` are imported, but no `memory_gas`/`memory_expansion_cost` function is ever invoked at these call sites.

An attacker (an ordinary EOA/contract caller using `eth_transact`/`bare_call`) can therefore submit a call whose bytecode does a single `MSTORE(offset≈EVM_MEMORY_BYTES-32, value)`. This is charged only `VERYLOW` (3 gas), yet it makes `Memory::resize` allocate and zero-fill up to ~1 MiB of memory (`self.data.resize(target_len, 0)`), because `target_len` is derived purely from the attacker-controlled `offset`/`len` and is only capped by the `EVM_MEMORY_BYTES` constant, not gas-priced.

### Impact Explanation
Because the per-call memory buffer is capped at `EVM_MEMORY_BYTES` (1 MiB) and is freshly allocated per interpreter/call frame, each individual call can force at most one ~1 MiB allocation+zero-fill; this cost is bounded and already accounted for in `MEMORY_REQUIRED`/`per_frame_memory` sizing in `substrate/frame/revive/src/limits.rs`, so this is not an unbounded-memory or OOM vulnerability. [4](#0-3) 
However, the *gas* charged for triggering this work is essentially fixed (a handful of gas units) and independent of how much memory is actually grown, unlike upstream Ethereum semantics. This means an attacker can pack many cheap transactions/calls (each containing one strategically-offset `MSTORE`/`MLOAD`/`MCOPY`) into a block, each incurring a near-1 MiB allocation+`memset` at negligible declared gas/fee cost. Repeated across many transactions in a block, this creates a real mismatch between charged gas/weight and actual CPU/allocation work performed, which can degrade block-production performance — a genuine violation of the gas-proportional-to-work invariant, though scoped to a soft-DoS/performance-degradation impact rather than fund loss, consensus break, or unbounded memory growth.

### Likelihood Explanation
This requires no privileged access — any unprivileged signed account can call `bare_call`/submit an Ethereum-style transaction containing this bytecode pattern, and it is trivially and cheaply repeatable across many transactions within the same block since the per-instruction gas cost (a few gas units) does not scale with the forced allocation size. The only limiting factor is the number of transactions that fit in a block under normal fee/weight limits, but since each such call is gas-cheap, an attacker can maximize the count of "1 MiB alloc" calls per block for a fraction of the cost of an equivalent legitimately-metered operation.

### Recommendation
Implement the standard EVM memory-expansion gas cost formula in the memory-touching opcode handlers (`mload`, `mstore`, `mstore8`, `mcopy`, and any other call site that calls `Memory::resize`, e.g. `resize_memory` in `call_helpers.rs`): before/while calling `resize`, compute `memory_cost(new_words) - memory_cost(current_words)` (using the quadratic Ethereum formula) and charge it via `charge_or_halt` in addition to the fixed opcode cost, halting with `OutOfGas` if the charge fails, mirroring upstream `revm`'s `resize_memory!`/`record_memory_cost` behavior.

### Proof of Concept
Rust unit/integration test plan (in `substrate/frame/revive/src/vm/evm/instructions/memory.rs` or an EVM interpreter test harness):
1. Deploy/construct a minimal EVM bytecode: `PUSH32 <offset≈EVM_MEMORY_BYTES-32> PUSH32 0 MSTORE STOP`.
2. Invoke it via `bare_call` with a gas limit only slightly above the sum of fixed opcode costs (`PUSH*2 + MSTORE VERYLOW`), asserting the call succeeds (does not run out of gas) despite forcing `Memory::resize` to grow to near `EVM_MEMORY_BYTES`.
3. Assert: `gas_consumed` for the call is `O(10)` gas units while `memory.size()` after execution is `~EVM_MEMORY_BYTES`.
4. Fuzz/invariant test: for varying `offset` values near the `EVM_MEMORY_BYTES` boundary, assert that `gas_consumed / bytes_resized` ratio is not bounded below a reasonable minimum (i.e., demonstrate the ratio degenerates as `offset` grows, proving gas is not proportional to work), then repeat the call N times across simulated block-authoring to measure aggregate wall-clock/weight-vs-declared-gas divergence.

	pub fn resize(&mut self, offset: usize, len: usize) -> ControlFlow<Halt> {
		let current_len = self.data.len();
		let target_len = revm::interpreter::num_words(offset.saturating_add(len)) * 32;
		if target_len > crate::limits::EVM_MEMORY_BYTES as usize {
			log::debug!(target: crate::LOG_TARGET, "check memory bounds failed: offset={offset} target_len={target_len} current_len={current_len}");
			return ControlFlow::Break(Error::<T>::OutOfGas.into());
		}

		if target_len > current_len {
			self.data.resize(target_len, 0);
		}

		ControlFlow::Continue(())
	}

pub fn mload<E: Ext>(interpreter: &mut Interpreter<E>) -> ControlFlow<Halt> {
	interpreter.ext.charge_or_halt(EVMGas(VERYLOW))?;
	let ([], top) = interpreter.stack.popn_top()?;
	let offset = as_usize_or_halt::<E::T>(*top)?;
	interpreter.memory.resize(offset, 32)?;
	*top = U256::from_big_endian(interpreter.memory.slice_len(offset, 32));
	ControlFlow::Continue(())
}

/// Implements the MSTORE instruction.
///
/// Stores a 32-byte word to memory.
pub fn mstore<E: Ext>(interpreter: &mut Interpreter<E>) -> ControlFlow<Halt> {
	interpreter.ext.charge_or_halt(EVMGas(VERYLOW))?;
	let [offset, value] = interpreter.stack.popn()?;
	let offset = as_usize_or_halt::<E::T>(offset)?;
	interpreter.memory.resize(offset, 32)?;
	interpreter.memory.set(offset, &value.to_big_endian());
	ControlFlow::Continue(())
}

pub fn mcopy<E: Ext>(interpreter: &mut Interpreter<E>) -> ControlFlow<Halt> {
	let [dst, src, len] = interpreter.stack.popn()?;

	// Into usize or fail
	let len = as_usize_or_halt::<E::T>(len)?;
	// Deduce gas
	let Some(gas_cost) = copy_cost_verylow(len) else {
		return ControlFlow::Break(Error::<E::T>::OutOfGas.into());
	};
	interpreter.ext.charge_or_halt(EVMGas(gas_cost))?;
	if len == 0 {
		return ControlFlow::Continue(());
	}

	let dst = as_usize_or_halt::<E::T>(dst)?;
	let src = as_usize_or_halt::<E::T>(src)?;
	// Resize memory
	interpreter.memory.resize(max(dst, src), len)?;
	// Copy memory in place
	interpreter.memory.copy(dst, src, len);
	ControlFlow::Continue(())
}
