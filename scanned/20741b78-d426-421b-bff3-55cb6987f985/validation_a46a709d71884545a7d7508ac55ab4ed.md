### Title
Unbounded, lock-serialized growth of the Vault gateway replay-guard map allows an authorized-but-low-privilege workflow owner to DoS all Vault gateway traffic - (File: core/capabilities/vault/request_replay_guard.go)

### Summary
The Vault gateway's replay-protection guard stores every authorized request's digest in a single in-memory map that is never bounded in size and is fully scanned, under an exclusive mutex, on every single request. A workflow owner (an unprivileged actor relative to node operators, distinguished from them only by passing normal allowlist/JWT auth) can keep sending distinct, validly-authorized Vault requests to grow this map without limit. Because the cleanup scan is O(n) and runs while holding `RequestReplayGuard.mu` for the whole `authorizer.AuthorizeRequest` call path, this degrades and eventually can block *all* subsequent Vault requests across *all* DONs/owners served by that gateway handler — the same "attacker inflates an internally-iterated collection until legitimate operations fail" pattern described in the Canto `GetAllBalances`/coinswap report.

### Finding Description
`RequestReplayGuard` keeps a `map[string]int64` of digest → expiry and is checked/cleaned on every call: [1](#0-0) 
`CheckAndRecord` always runs `clearExpiredLocked`, which iterates the *entire* map, before deciding whether to admit the new digest: [2](#0-1) 
```go
func (g *RequestReplayGuard) clearExpiredLocked() {
	now := g.nowFunc().UTC().Unix()
	for digest, expiry := range g.seen {
		if now > expiry {
			delete(g.seen, digest)
		}
	}
}
``` [3](#0-2) 

This guard is invoked, holding a package-wide `sync.Mutex`, on **every** authorized Vault gateway request — both the allowlist path and the JWT path funnel through the same `authorizer.AuthorizeRequest`: [4](#0-3) 

The `authorizer` (and its single shared `replayGuard`) is constructed once per `GatewayHandler` instance and used for all vault methods (`SecretsCreate`, `SecretsUpdate`, `SecretsDelete`, `SecretsList`) reachable from the internet-facing gateway: [5](#0-4) [6](#0-5) 

Each successfully-authorized request contributes a unique digest to `seen` (digests are derived per-request, as shown by the one-entry-per-call test behavior), and there is no cap on the number of live (non-expired) entries the map may hold: [7](#0-6) 

Unlike the coinswap bug (where `GetAllBalances` iterates a `sdk.Coins` array grown via `AddLiquidity`/token transfers), here the analogous "array" is the `seen` map, and the analogous unprivileged growth vector is any authorized workflow owner continuously submitting distinct legitimate requests (each producing a new digest with its own expiry). No node-operator privilege, malicious peer, or network-layer position is required — only being able to reach the gateway's public Vault JSON-RPC endpoint as a normal, allowlisted/JWT-authenticated workflow owner.

### Impact Explanation
As `seen` grows (bounded only by however long entries remain unexpired and how many distinct requests an owner can send), every subsequent `CheckAndRecord` call — for every owner, every DON, every method — must scan the entire map while holding the guard's exclusive lock. This:
- Increases per-request authorization latency linearly with map size for **all** tenants sharing the gateway handler, not just the abusive owner.
- Can starve the mutex under load, serializing all Vault authorization calls behind the O(n) scan.
- In the worst case (very large map, high request rate) causes authorization timeouts/failures for legitimate Vault operations (create/update/delete/list secrets), i.e., availability impact on the Vault capability gateway path, mirroring the Medium-severity coinswap finding's "swap/RemoveLiquidity might fail" conclusion.

This does not grant fund movement, key disclosure, or auth bypass — impact is denial of service against the Vault gateway's core secrets functions.

### Likelihood Explanation
Likelihood is moderate-to-high in any deployment where a workflow owner can be reasonably long-lived (large `expiresAt`) or can generate many distinct authorized requests quickly (e.g., repeated `SecretsList`/`SecretsCreate` calls with unique nonces/request IDs), since no map-size limit, LRU eviction, or per-owner cap exists in `RequestReplayGuard`. It requires only standard allowlist/JWT-authorized access to the gateway — a routine unprivileged capability for CRE workflow owners — not any special role or malicious-node position.

### Recommendation
- Bound `RequestReplayGuard.seen` (e.g., a fixed-capacity LRU/TTL cache, or `chainlink-common`'s bounded cache utilities) instead of an unbounded map.
- Avoid full-map iteration on the hot path: use a min-heap/ordered structure keyed by expiry, or lazily expire entries via a background ticker (as `ClearExpired` already exists for) rather than scanning on every `CheckAndRecord`.
- Cap replay-guard entries per authorized owner to prevent one workflow owner from monopolizing the shared structure.
- Consider sharding the replay guard per-owner or per-DON so a single abusive tenant cannot degrade cross-tenant Vault gateway latency.

### Proof of Concept
1. As an allowlisted (or JWT-authorized) workflow owner, repeatedly call the Vault gateway's `SecretsList` (or any authorized method) with unique request IDs/nonces so each call authorizes with a distinct digest and a far-future `expiresAt` (bounded only by JWT/allowlist token validity).
2. Each call passes through `authorizer.AuthorizeRequest` → `replayGuard.CheckAndRecord`, adding a new entry to `seen` and never removing it (not yet expired). [8](#0-7) 
3. As `seen` grows into the hundreds of thousands/millions of entries, every subsequent request from *any* owner incurs an O(n) full-map scan under `g.mu` inside `clearExpiredLocked`. [2](#0-1) 
4. Authorization latency for all Vault gateway traffic increases proportionally, eventually causing request timeouts / effective denial of service for the Vault secrets capability across the gateway handler instance.

func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}
```

func (a *authorizer) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	authResult, err := a.authorizeRequest(ctx, req)
	if err != nil {
		return nil, err
	}
	if authResult == nil {
		err = errors.New("auth mechanism returned nil auth result")
		a.lggr.Errorw("auth mechanism returned nil auth result", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "")
		return nil, err
	}
	if err := a.replayGuard.CheckAndRecord(authResult.Digest(), authResult.ExpiresAt()); err != nil {
		a.lggr.Debugw("replay guard rejected request", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "digest", authResult.Digest(), "expiresAt", authResult.ExpiresAt(), "hasAuth", req.Auth != "", "error", err)
		return nil, err
	}
	if ownerErr := validateSecretOwnersMatchAuthorized(req, authResult.AuthorizedOwner()); ownerErr != nil {
		a.lggr.Errorw("owner binding rejected request", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "hasAuth", req.Auth != "", "error", ownerErr)
		return nil, ownerErr
	}
	a.lggr.Debugw("request authorized", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "digest", authResult.Digest(), "expiresAt", authResult.ExpiresAt(), "hasAuth", req.Auth != "")
	return authResult, nil
}

func (h *GatewayHandler) HandleGatewayMessage(ctx context.Context, gatewayID string, req *jsonrpc.Request[json.RawMessage]) (err error) {
	reqLggr := h.requestLogger(req, gatewayID)
	reqLggr.Debugw("received message from gateway", "req", req)

	var response *jsonrpc.Response[json.RawMessage]
	var authResult *AuthResult

	switch req.Method {
	case vaulttypes.MethodSecretsCreate, vaulttypes.MethodSecretsUpdate:
		publicKey, pkErr := h.getMasterPublicKey(ctx)
		if pkErr != nil {
			response = h.gatewayErrorResponse(ctx, gatewayID, req, pkErr)
			break
		}
		authorized, pipelineErr := h.requestProcessor.ProcessRequest(ctx, req, publicKey)
		if pipelineErr != nil {
			response = h.gatewayErrorResponse(ctx, gatewayID, req, pipelineErr)
			break
		}
		authResult = authorized.AuthResult
	case vaulttypes.MethodSecretsDelete, vaulttypes.MethodSecretsList:
		authorized, pipelineErr := h.requestProcessor.ProcessRequest(ctx, req, nil)
		if pipelineErr != nil {
			response = h.gatewayErrorResponse(ctx, gatewayID, req, pipelineErr)
			break
		}
		authResult = authorized.AuthResult
	case vaulttypes.MethodPublicKeyGet:
		response = h.handlePublicKeyGet(ctx, gatewayID, req)
	default:
		response = h.errorResponse(ctx, gatewayID, req, api.UnsupportedMethodError, errors.New("unsupported method: "+req.Method))
	}

	if response == nil {
		switch req.Method {
		case vaulttypes.MethodSecretsCreate:
			response = h.handleSecretsCreate(ctx, gatewayID, req)
		case vaulttypes.MethodSecretsUpdate:
			response = h.handleSecretsUpdate(ctx, gatewayID, req)
		case vaulttypes.MethodSecretsDelete:
			response = h.handleSecretsDelete(ctx, gatewayID, req)
		case vaulttypes.MethodSecretsList:
			response = h.handleSecretsList(ctx, gatewayID, req, authResult)

func TestRequestReplayGuard_DifferentDigestsIndependent(t *testing.T) {
	guard := NewRequestReplayGuard()
