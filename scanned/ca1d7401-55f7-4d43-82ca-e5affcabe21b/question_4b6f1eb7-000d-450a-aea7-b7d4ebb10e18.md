[File: packages/intents-sdk/src/intents/intent-signer-impl/intent-signer-nep413.ts, method IntentSignerNEP413.signIntent] signIntent builds message signer_id as `intent.signer_id ?? this.accountId`, so a caller-supplied intent.signer_id (any NEAR account id string) fully overrides this.accountId and gets embedded in the signed NEP413 message while this.signMessageFn still signs with the configured account's key. Attacker input: intent.signer_id = 'victim.near', intent.intents = intents that debit balances registered under 'victim.near'. Preconditions: attacker configures IntentSignerNEP413 with their own accountId/signMessage but calls signIntent with an IntentPayload carrying a foreign signer_id. Call sequence: IntentSignerNEP413.signIntent(intent) -> signRaw builds nep413Payload.message containing signer_id:'victim.near', hashes it, signs with attacker's key via signMessageFn, returns MultiPayloadNep413{signer_id embedded in message, public_key: attacker's publicKey, signature: attacker's signature}. Equality broken: signer_id in the signed payload == intents user id derived from public_key that produced signature (public_key belongs to attacker, signer_id names victim). Impact: Critical, funds registered under 'victim.near' targeted by a payload the attacker fully controls and signs themselves. Proof idea: vitest test calling IntentSignerNEP413.signIntent with intent.signer_id='victim.near' while accountId='attacker.near', asserting the returned payload's message contains signer_id='victim.near' with public_key belonging to 'attacker.near'.
