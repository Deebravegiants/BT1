## Analysis Result

<title>NULL Pointer Dereference in Vault Gateway PublicKeyGet Handler Crashes Node's Gateway Connector - ([File: core/capabilities/vault/gw_handler.go])</title>

### Summary
`GatewayHandler.handlePublicKeyGet` dereferences `req.Params` without checking for `nil`, unlike every other request path in the same handler. A gateway message with `Params: null` for the `vault.publicKey.get` method reaches this code before any authorization check runs, causing a Go nil-pointer dereference panic in the connector's single read-loop goroutine, which has no panic recovery.

### Finding Description
In `HandleGatewayMessage`, the `MethodPublicKeyGet` case is dispatched directly to `handlePublicKeyGet` and, unlike `MethodSecretsCreate`/`MethodSecretsUpdate`/`MethodSecretsDelete`/`MethodSecretsList`, it bypasses `h.requestProcessor.ProcessRequest` / `Authorizer.AuthorizeRequest` entirely: [1](#0-0) 

`handlePublicKeyGet` then unmarshals into `req.Params` directly:
```go
func (h *GatewayHandler) handlePublicKeyGet(ctx context.Context, gatewayID string, req *jsonrpc.Request[json.RawMessage]) *jsonrpc.Response[json.RawMessage] {
	r := &vaultcommon.GetPublicKeyRequest{}
	if err := json.Unmarshal(*req.Params, r); err != nil {
``` [2](#0-1) 

`req.Params` is a `*json.RawMessage`. If the incoming JSON-RPC request omits `params` or sets it to `null`, this field is `nil`, and `*req.Params` panics with a nil pointer dereference. Every other handler in this codebase (e.g. `processCreateSecretsRequest`, `handleCapabilityExecute`) explicitly guards against this: [3](#0-2) [4](#0-3) 

The message reaches this code from the gateway's `readLoop`, which invokes `handler.HandleGatewayMessage` synchronously in a per-gateway goroutine with no `recover()`: [5](#0-4) 

### Impact Explanation
A panic here is unrecovered and crashes the process (Go panics that unwind out of a goroutine terminate the whole program by default). This kills the node's connection to that gateway and, since panics are process-fatal in Go unless caught, likely crashes the entire chainlink node binary — a denial of service directly analogous to the NULL pointer dereference DoS described in CVE-2022-2850. Because this path is dispatched before `AuthorizeRequest`/allowlist checks, no workflow-owner authorization or allowlisting is required to reach it — only the ability to send a message to the gateway targeting the Vault DON with method `vault.publicKey.get`.

### Likelihood Explanation
High. `PublicKeyGet` is a routine, low-privilege operation intentionally exempt from allowlist/JWT authorization (it only returns a public key), so it is reachable by any client capable of sending gateway messages to the DON. Triggering it only requires omitting or nulling the `params` field, which is trivial to craft.

### Recommendation
Add a `req.Params == nil` guard in `handlePublicKeyGet`, mirroring the checks already present in `processCreateSecretsRequest` / `handleCapabilityExecute`, returning an `api.InvalidParamsError`/`UserMessageParseError` response instead of dereferencing a nil pointer. Additionally, consider adding a `recover()` in the connector's `readLoop`/`HandleGatewayMessage` dispatch path so a single malformed message cannot take down the node process.

### Proof of Concept
Send (via the gateway to the DON) a JSON-RPC request:
```json
{"jsonrpc":"2.0","id":"1","method":"vault.publicKey.get","params":null}
```
This is decoded into a `jsonrpc.Request[json.RawMessage]` with `Params == nil`, routed straight to `handlePublicKeyGet` (bypassing authorization), and `*req.Params` panics inside the connector's unrecovered read-loop goroutine.

func (c *gatewayConnector) readLoop(gatewayState *gatewayState) {
	defer c.closeWait.Done()
	ctx, cancel := c.shutdownCh.NewCtx()
	defer cancel()

	for {
		select {
		case <-c.shutdownCh:
			return
		case item := <-gatewayState.conn.ReadChannel():
			var req jsonrpc.Request[json.RawMessage]
			err := json.Unmarshal(item.Data, &req)
			if err != nil {
				c.lggr.Errorw("parse error when reading from Gateway", "id", gatewayState.config.ID, "err", err)
				break
			}
			c.handlersMu.RLock()
			handler, exists := c.handlers[req.Method]
			c.handlersMu.RUnlock()
			if !exists {
				c.lggr.Errorw("no handler for method", "id", gatewayState.config.ID, "method", req.Method)
				break
			}
			// do not break on error. HandleGatewayMessage handles errors
			// by sending a response back to the Gateway.
			err = handler.HandleGatewayMessage(ctx, gatewayState.config.ID, &req)
			if err != nil {
				c.lggr.Warnw("failed to handle message from Gateway", "id", gatewayState.config.ID, "method", req.Method, "err", err)
			}
		}
	}
