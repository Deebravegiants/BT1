### Title
View-role users can read Bridge/External Initiator `OutgoingToken`/`AccessKey` secrets via GET endpoints intended for minimal-permission users - (File: `core/web/router.go`)

### Summary
The Jenkins Cisco Spark Notifier advisory (CVE-2023-24451) describes a missing permission check that lets an actor with only `Overall/Read` enumerate credential IDs. In this codebase, the analogous unprivileged-role path is worse in one respect: the `GET /v2/bridge_types`, `GET /v2/bridge_types/:BridgeName`, and `GET /v2/external_initiators` endpoints are reachable by a session/token-authenticated user with only the `View` role, and they return the actual secret token values (`OutgoingToken`, and for external initiators also `AccessKey`), not just opaque IDs.

### Finding Description
`v2Routes` wires these endpoints with no elevated-role middleware: [1](#0-0) 

The RBAC route map explicitly documents that `GET /v2/bridge_types`, `GET /v2/bridge_types/MOCK`, and `GET /v2/external_initiators` are `viewOnlyAllowed: true`, meaning the lowest role (`View`) can call them without a 401/403: [2](#0-1) 

`BridgeTypesController.Index`/`Show` and `ExternalInitiatorsController.Index` serialize the full DB row (via `presenters.NewBridgeResource` / `presenters.NewExternalInitiatorResource`) which includes the plaintext `OutgoingToken` (and `AccessKey` for external initiators) without any redaction: [3](#0-2) [4](#0-3) [5](#0-4) [6](#0-5) 

The `OutgoingToken` is a generated secret (`utils.NewSecret(24)` for bridges, `utils.NewSecret(utils.DefaultSecretSize)` for external initiators) created specifically to authenticate outbound Chainlink traffic to the External Adapter / External Initiator: [7](#0-6) [8](#0-7) 

This mirrors the Jenkins bug class (CWE-862 Missing Authorization) applied to secret material reachable by an unprivileged authenticated caller: a role intended only for passive viewing of dashboards/jobs can pull authentication secrets for outbound integrations, which the `Edit`/`Admin`-gated write operations (`POST`/`DELETE` on the same resources) suggest were meant to be treated as sensitive/privileged.

### Impact Explanation
Any authenticated node user provisioned with the minimal `View` role (e.g., a read-only auditor/dashboard account) can retrieve the `OutgoingToken` for every configured bridge and external initiator. Possession of this token would let that low-privilege user (or anyone who steals their session/API token) impersonate the Chainlink node to the corresponding External Adapter/External Initiator endpoints that trust this token for authenticating outbound requests, or replay/forge requests presented as coming from the node. This satisfies "key/secret disclosure" from the validation criteria.

### Likelihood Explanation
Likelihood is moderate to high: the only prerequisite is a valid `View`-role session or API token — no bridge- or job-specific edit permission is needed, and the endpoint is a simple, unauthenticated-w.r.t.-role GET with pagination, directly reachable from any UI/API client. This is a design/authorization gap rather than a race condition or exotic exploit chain.

### Recommendation
Gate `GET /v2/bridge_types`, `GET /v2/bridge_types/:BridgeName`, and `GET /v2/external_initiators` (and their resolver/GraphQL equivalents) behind `auth.RequiresEditRole` (or a new "credentials" permission) instead of allowing bare `Authenticate`, or strip `OutgoingToken`/`AccessKey` from the `Index`/`Show` presenters for View-role callers, mirroring how `IncomingToken` is only ever returned once at creation time in `BridgeTypeAuthentication`.

### Proof of Concept
1. Create a Chainlink node user with role `view` (`core/cmd/admin_commands.go` `users create --role view`, or via `UserController.Create`).
2. Authenticate as that user and call:
   - `GET /v2/bridge_types` or `GET /v2/bridge_types/<name>`
   - `GET /v2/external_initiators`
3. Observe the JSON response contains `outgoingToken` (bridges) and `accessKey`/`outgoingToken` (external initiators) in plaintext, confirmed by the route's `viewOnlyAllowed: true` entry in `core/web/auth/auth_test.go` and the presenter code in `core/web/presenters/bridges.go` and `core/web/presenters/external_initiators.go`.

Note: I was unable to fully verify within the available search results whether `OutgoingToken` is currently attached as an outbound authentication header anywhere in the live bridge-task/webhook-notify code paths (the grep for `OutgoingToken` usage in `task.bridge.go` and initiator-notify code did not show it being injected into request headers in the versions of those files I could inspect) — if it turns out to be vestigial/unused for authentication in this specific codebase revision, the severity should be downgraded from "secret disclosure with re-authentication impact" to "unnecessary secret exposure," though the missing-authorization pattern (View role reading data intended for higher roles) still holds either way.

// Index lists Bridges, one page at a time.
func (btc *BridgeTypesController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	bridges, count, err := btc.App.BridgeORM().BridgeTypes(ctx, offset, size)

	resources := make([]presenters.BridgeResource, 0, len(bridges))
	for _, bridge := range bridges {
		resources = append(resources, *presenters.NewBridgeResource(bridge))
	}

	paginatedResponse(c, "Bridges", size, page, resources, count, err)
}

// Show returns the details of a specific Bridge.
func (btc *BridgeTypesController) Show(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	bt, err := btc.App.BridgeORM().FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}

// NewBridgeType returns a bridge type authentication (with plaintext
// password) and a bridge type (with hashed password, for persisting)
func NewBridgeType(btr *BridgeTypeRequest) (*BridgeTypeAuthentication,
	*BridgeType, error,
) {
	incomingToken := utils.NewSecret(24)
	outgoingToken := utils.NewSecret(24)
	salt := utils.NewSecret(24)

	hash, err := incomingTokenHash(incomingToken, salt)
	if err != nil {
		return nil, nil, err
	}

	return &BridgeTypeAuthentication{
		Name:                   btr.Name,
		URL:                    btr.URL,
		Confirmations:          btr.Confirmations,
		IncomingToken:          incomingToken,
		OutgoingToken:          outgoingToken,
		MinimumContractPayment: btr.MinimumContractPayment,
		UseConnectionManager:   btr.UseConnectionManager,
	}, &BridgeType{
		Name:                   btr.Name,
		URL:                    btr.URL,
		Confirmations:          btr.Confirmations,
		IncomingTokenHash:      hash,
		Salt:                   salt,
		OutgoingToken:          outgoingToken,
		MinimumContractPayment: btr.MinimumContractPayment,
		UseConnectionManager:   btr.UseConnectionManager,
	}, nil
}

// NewExternalInitiator generates an ExternalInitiator from an
// auth.Token, hashing the password for storage
func NewExternalInitiator(
	eia *auth.Token,
	eir *ExternalInitiatorRequest,
) (*ExternalInitiator, error) {
	salt := utils.NewSecret(utils.DefaultSecretSize)
	hashedSecret, err := auth.HashedSecret(eia, salt)
	if err != nil {
		return nil, pkgerrors.Wrap(err, "error hashing secret for external initiator")
	}

	return &ExternalInitiator{
		Name:           strings.ToLower(eir.Name),
		URL:            eir.URL,
		AccessKey:      eia.AccessKey,
		HashedSecret:   hashedSecret,
		Salt:           salt,
		OutgoingToken:  utils.NewSecret(utils.DefaultSecretSize),
		OutgoingSecret: utils.NewSecret(utils.DefaultSecretSize),
	}, nil
}
