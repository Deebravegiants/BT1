Log injection is present in this codebase and matches the CVE-2020-5225 bug class closely: unsanitized, attacker-controlled strings reach the node's log output where newline/carriage-return characters are preserved, letting a caller forge fake log lines.

### Title
Log injection via unsanitized newline characters in gateway request IDs (and other user-controlled fields) reaching the console logger - (File: core/logger/prettyconsole.go)

### Summary
The default Chainlink node log encoder (`JSONConsole = false`, the default) renders every log entry through `sanitized.String()`, which deliberately passes `\n`, `\r`, and `\t` through unescaped while escaping other control characters. Multiple internet-facing entry points log attacker-controlled strings (most notably the Gateway's JSON-RPC `id` field) as either the log message or a structured field value without stripping newlines, so those characters flow straight into `sanitized.String()` and are written to the process's stdout/stderr log stream unescaped, forging additional, fake log lines — the same root cause as the SimpleSAMLphp `reportID` bug (unsanitized user-controlled identifier concatenated into a log line, permitting newline injection).

### Finding Description
`sanitized.String()` is applied to both the `msg` field and every field value before they are written by `PrettyConsole.Write`: [1](#0-0) 
This is the encoder used for the default log path (`JSONConsole = false` by default, which sets `OutputPaths = []string{"pretty://console"}`): [2](#0-1) [3](#0-2) 

The Gateway's JSON-RPC `Request.ID` is fully attacker-controlled (any string except one containing `/`) and is validated with essentially no other sanitization: [4](#0-3) 
This ID is then logged repeatedly as the `requestID` field before/around request processing — including in the error path that runs prior to (or in cases of failure of) authorization: [5](#0-4) 
The same unsanitized `requestID` is logged throughout the gateway (e.g. `gateway.go` `ProcessRequest`, the confidential-relay and vault handlers), all of which are on the unauthenticated/unprivileged front door of the gateway: [6](#0-5) 

A secondary reachable path is the LDAP login flow, where the caller-supplied `sr.Email` (from an unauthenticated/low-privilege `CreateSession` login request body) is interpolated directly into the log *message* via `Infof`, not as a structured field: [7](#0-6) 
`ldap.EscapeFilter` only escapes LDAP filter metacharacters, not newlines, so a crafted email such as `attacker@evil.com\n2024-01-01T00:00:00Z [CRIT] fake incident` retains its embedded newline through this call.

Because `sanitized.String()` explicitly special-cases and preserves `\n`/`\r`/`\t` ("// allowed"), any of these values, once they reach the console log sink, produce literal new lines in the emitted log stream — indistinguishable from genuine, separate log entries.

### Impact Explanation
An unauthenticated or low-privileged caller can forge arbitrary fake log entries (including fabricated timestamps, levels such as `[CRIT]`, and message content) in the Chainlink node's operational log stream. This can be used to:
- Mislead node operators/SOC tooling that parse the pretty-console log stream (or that stream captured to disk by container/process log capture, which is the common production deployment pattern),
- Obscure or frame other log lines (log forgery / audit-trail tampering),
- Potentially trigger false alerts or suppress real ones if downstream alerting keys off literal log line content.

This mirrors the CVE-2020-5225 impact (log injection allowing an attacker to inject arbitrary log content via an unsanitized identifier), and matches the CVSS profile of Medium severity with confidentiality/integrity impact via forged log data rather than direct system compromise.

### Likelihood Explanation
High for the gateway path: the JSON-RPC request `id` is fully attacker-supplied on the gateway's internet-facing HTTP entry point, requires no authentication to submit, and the only validation applied rejects `/` but not newlines. Every processed request logs this ID via `Warnw`/`Errorw`/`Debugw`. The LDAP path requires a valid (but non-privileged) LDAP-bindable account, consistent with the source CVE's `PR:L`.

### Recommendation
Strip or escape `\n`, `\r`, and `\t` (not "allow" them) in `sanitized.String()` in `core/logger/prettyconsole.go`, and additionally reject/sanitize control characters (not just `/`) in gateway request IDs in `validateRequestID` (`core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go`). Ensure user-supplied identifiers (`sr.Email`, workflow/request IDs) are never interpolated into the log *message* string; always pass them as structured key/value fields, and sanitize those field values consistently regardless of encoder.

### Proof of Concept
1. Send an unauthenticated JSON-RPC request to the Gateway's HTTP trigger endpoint with `"id": "abc\n2024-01-01T00:00:00Z [CRIT] FAKE: node compromised"`.
2. The gateway logs this ID as the `requestID` field (e.g., in `handleUserError` / `gateway.ProcessRequest`).
3. With the default `JSONConsole = false` config, the log line passes through `sanitized.String()`, which preserves the embedded `\n`, producing two apparent log lines in the node's console/stdout log stream — the second one fabricated and attacker-controlled. [8](#0-7) [4](#0-3)

type sanitized string

// String replaces control characters with Go escape sequences, except for newlines and tabs.
// See strconv.QuoteRune.
func (s sanitized) String() string {
	var out strings.Builder
	for _, r := range s {
		switch r {
		case '\n', '\r', '\t':
			// allowed
		default:
			// escape others
			if unicode.IsControl(r) {
				q := strconv.QuoteRune(r)
				out.WriteString(q[1 : len(q)-1]) // trim quotes
				continue
			}
		}
		out.WriteRune(r)
	}
	return out.String()
}

func (h *httpTriggerHandler) validateRequestID(ctx context.Context, requestID string, callback handlers.Callback) error {
	if requestID == "" {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "'id' field is required and cannot be empty. Use a new unique request 'id' for each request", callback)
		return errors.New("empty request ID")
	}
	// Request IDs from users must not contain "/", since this character is reserved
	// for internal node-to-node message routing (e.g., "http_action/{workflowID}/{uuid}").
	if strings.Contains(requestID, "/") {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "request ID must not contain '/'", callback)
		return errors.New("request ID must not contain '/'")
	}
	return nil
}

	case jsonrpc.ErrInternal, jsonrpc.ErrServerOverloaded, jsonrpc.ErrUnknown, jsonrpc.ErrLimitExceeded, jsonrpc.ErrConflict:
		h.lggr.Errorw("returning error to user", "code", code, "message", message, "requestID", requestID)
	default:
		h.lggr.Warnw("returning error to user", "code", code, "message", message, "requestID", requestID)

	resp := &jsonrpc.Response[json.RawMessage]{
		Version: "2.0",
		ID:      requestID,
		Error: &jsonrpc.WireError{
			Code:    code,
			Message: message,
		},
	}
