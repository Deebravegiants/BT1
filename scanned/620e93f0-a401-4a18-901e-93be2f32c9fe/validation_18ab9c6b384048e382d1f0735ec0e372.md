### Title
API Token Authentication Bypasses WebAuthn MFA Enforced on Session Login - (File: core/web/auth/auth.go)

### Summary
Chainlink's Operator UI/node HTTP API supports two authentication mechanisms: session cookies (created via password + optional WebAuthn/MFA challenge) and API key/secret tokens (`X-API-KEY`/`X-API-SECRET` headers). When a user enables WebAuthn MFA, the session-based login flow in `orm.CreateSession` (`core/sessions/localauth/orm.go:144-230`) enforces the WebAuthn challenge before a session is granted. However, the token-based authentication path, `AuthenticateByToken` in `core/web/auth/auth.go:78-112`, never checks whether the user has MFA enrolled and never requires any second factor — it authenticates solely on the API key and secret via `FindUserByAPIToken` (`core/sessions/localauth/orm.go:49-53`) and `sessions.AuthenticateUserByToken` (`core/sessions/session.go:66-74`).

### Finding Description
`AuthenticateByToken` reads `X-API-KEY`/`X-API-SECRET` headers, looks up the user by `token_key` with `FindUserByAPIToken`, and performs a constant-time secret comparison with `AuthenticateUserByToken`. Neither function references `GetUserWebAuthn`, `web_authns`, or any MFA state. This is architecturally the exact bug class described in the Froxlor advisory: the primary (password) login path enforces a second factor, but a parallel credential-based authentication path (API key+secret) grants full access with no MFA check whatsoever. Any holder of a leaked API key+secret pair for an MFA-protected admin/user account gets unrestricted access to every gin route protected only by `webauth.Authenticate(authr, webauth.AuthenticateByToken)`, bypassing the WebAuthn protection the user explicitly enabled. ### Impact Explanation
API tokens are created via `NewAPIToken` (`core/web/user_controller.go:244-286`) which only re-validates the account password (`TestPassword`) — not WebAuthn — and are long-lived (single active token per user, revoked only on regeneration). If such a token leaks (logs, CI secrets, backups), an attacker gets the same privileges as a full password+MFA session login for that user's role (Admin/Edit/Run/Read), including job management, key/wallet operations, and bridge/config endpoints — with the account's MFA protection providing zero defense. [4](#0-3) 

### Likelihood Explanation
Requires possession of a leaked API key+secret, which is the same threat model the Froxlor report and Chainlink's own MFA feature description assume ("hardware/OS security key required to authenticate" — implying it should be required for all authenticated access). No additional privilege or network position is needed beyond having the token — a single unprivileged HTTP request is sufficient.

### Recommendation
When a user with `AuthenticateByToken` is authenticated, check `GetUserWebAuthn` for the resolved user (as `orm.CreateSession` already does) and reject or require an additional signed WebAuthn/TOTP assertion if MFA credentials are present, mirroring the enforcement already present in the session-login path.

### Proof of Concept
1. Enroll a WebAuthn/MFA token for an admin user via the Operator UI (`FinishRegistration` in `core/web/webauthn_controller.go:62-104`).
2. Confirm password-only login fails without a MFA challenge (`orm.CreateSession`, `core/sessions/localauth/orm.go:181-199` returns a WebAuthn challenge and blocks session creation until it's solved).
3. Using the same account's existing (or newly password-authorized) API key/secret, call any protected endpoint with `X-API-KEY`/`X-API-SECRET` headers only, e.g.:
   ```
   curl -H "X-API-KEY: <key>" -H "X-API-SECRET: <secret>" https://node:6688/v2/jobs
   ```
4. Observe the request succeeds with full access, without any WebAuthn/MFA prompt or verification, confirming the token-auth path fully bypasses the MFA the account owner enabled. [5](#0-4)

func AuthenticateByToken(c *gin.Context, authr Authenticator) error {
	ctx := c.Request.Context()
	token := &auth.Token{
		AccessKey: c.GetHeader(APIKey),
		Secret:    c.GetHeader(APISecret),
	}
	if token.AccessKey == "" {
		return auth.ErrorAuthFailed
	}

	if token.Secret == "" {
		return auth.ErrorAuthFailed
	}

	// We need to first load the user row so we can compare tokens using the stored salt
	user, err := authr.FindUserByAPIToken(ctx, token.AccessKey)
	if err != nil {
		if errors.Is(err, sql.ErrNoRows) || errors.Is(err, clsessions.ErrUserSessionExpired) {
			return auth.ErrorAuthFailed
		}
		return err
	}

	ok, err := clsessions.AuthenticateUserByToken(token, &user)
	if err != nil {
		return err
	}
	if !ok {
		return auth.ErrorAuthFailed
	}

	c.Set(SessionUserKey, &user)

	return nil
}

func (u *UserController) NewAPIToken(c *gin.Context) {
	ctx := c.Request.Context()
	var request clsession.ChangeAuthTokenRequest
	if err := c.ShouldBindJSON(&request); err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	sessionUser, ok := webauth.GetAuthenticatedUser(c)
	if !ok {
		jsonAPIError(c, http.StatusInternalServerError, errors.New("failed to obtain current user from context"))
		return
	}
	user, err := u.App.AuthenticationProvider().FindUser(ctx, sessionUser.Email)
	if err != nil {
		if errors.Is(err, clsession.ErrNotSupported) {
			jsonAPIError(c, http.StatusBadRequest, errUnsupportedForAuth)
			return
		}
		u.App.GetLogger().Errorf("failed to obtain current user record: %s", err)
		jsonAPIError(c, http.StatusInternalServerError, errors.New("unable to create API token"))
		return
	}
	// In order to create an API token, login validation with provided password must succeed
	err = u.App.AuthenticationProvider().TestPassword(ctx, sessionUser.Email, request.Password)
	if err != nil {
		u.App.GetAuditLogger().Audit(audit.APITokenCreateAttemptPasswordMismatch, map[string]any{"user": user.Email})
		jsonAPIError(c, http.StatusUnauthorized, errors.New("incorrect password"))
		return
	}
	newToken := auth.NewToken()
	if err := u.App.AuthenticationProvider().SetAuthToken(ctx, &user, newToken); err != nil {
		if errors.Is(err, clsession.ErrNotSupported) {
			jsonAPIError(c, http.StatusBadRequest, errUnsupportedForAuth)
			return
		}
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	u.App.GetAuditLogger().Audit(audit.APITokenCreated, map[string]any{"user": user.Email})
	jsonAPIResponseWithStatus(c, newToken, "auth_token", http.StatusCreated)
}
