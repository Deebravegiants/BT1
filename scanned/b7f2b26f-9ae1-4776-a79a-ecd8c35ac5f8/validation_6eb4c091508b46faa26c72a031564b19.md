### Title
Unauthenticated flood of `web_api_trigger` requests exhausts the shared `savedCallbacks` bound, causing cross-user response loss/DoS in the Gateway's legacy capability handler - (File: core/services/gateway/handlers/capabilities/handler.go)

### Summary
The Axelar report describes a shared, size-bounded resource (the flow-limit "capacity per epoch") that any single unprivileged actor can exhaust, starving all other legitimate users of the same resource. The chainlink-analog is `handler.HandleLegacyUserMessage` in the Gateway's legacy capabilities handler, which accepts unauthenticated `web_api_trigger` requests from the internet-facing Gateway HTTP endpoint and stores a callback in a single shared, capacity-bounded map (`savedCallbacks`, capped at `MaxSavedCallbacks`) with **no allowlist and no rate limiting** applied — a gap the code itself flags with a `TODO`. An attacker can flood this endpoint to evict other users' pending callbacks from the map before their corresponding node responses arrive, silently dropping their results — an availability/DoS impact directly analogous to the flow-limit exhaustion in the report.

### Finding Description
`gateway.ProcessRequest` routes any legacy (DON-ID-addressed) JSON request straight to `h.HandleLegacyUserMessage(ctx, msg, callback)` [1](#0-0) . This is reachable directly from the internet-facing user HTTP server (`gw_net.HTTPServer` set via `SetHTTPRequestHandler`), with no session, token, or external-initiator authentication required, since legacy requests are routed purely by DON ID [2](#0-1) .

Inside `HandleLegacyUserMessage`, immediately after validating the message age, the code contains an explicit acknowledgment of the missing control:
```go
// TODO: apply allowlist and rate-limiting here
if msg.Body.Method != MethodWebAPITrigger {
``` [3](#0-2) 

The handler then unconditionally stores the callback keyed by `msg.Body.MessageID` in a shared map and fans the request out to every DON member node:
```go
h.mu.Lock()
h.savedCallbacks[msg.Body.MessageID] = &savedCallback{id: msg.Body.MessageID, createdAt: time.Now(), Callback: callback}
don := h.don
h.mu.Unlock()

for _, member := range h.donConfig.Members {
    err = errors.Join(err, don.SendToNode(ctx, member.Address, req))
}
``` [4](#0-3) 

`savedCallbacks` is a single, DON-wide map, bounded by `MaxSavedCallbacks` (default `20000`), pruned periodically by `pruneCallbacks`:
```go
maxSize := h.config.MaxSavedCallbacks
...
if len(h.savedCallbacks) > maxSize {
    ...
    for _, e := range entries[:len(entries)-maxSize/2] {
        delete(h.savedCallbacks, e.id)
        evicted++
    }
}
``` [5](#0-4) 

Since there is no per-sender/per-user quota (unlike the v2 HTTP trigger path, which has `nodeRateLimiter`/`userRateLimiter` with per-workflow scoping, e.g. [6](#0-5) ), a single unprivileged caller can submit far more than `MaxSavedCallbacks/2` legacy trigger requests in a short window (each request only needs a unique `MessageID` and a fresh timestamp), forcing `pruneCallbacks` to evict the oldest half of the map — including other users' still-pending callbacks. When the real DON node response for an evicted `MessageID` eventually arrives, `handleWebAPITriggerMessage` will find `found == false` and silently drop it:
```go
savedCb, found := h.savedCallbacks[msg.Body.MessageID]
delete(h.savedCallbacks, msg.Body.MessageID)
...
if found {
    return savedCb.SendResponse(...)
}
return nil
``` [7](#0-6) 

The evicted legitimate caller's original HTTP request in `gateway.ProcessRequest` is left blocking on `callback.Wait(ctx)` until it eventually times out and returns a `RequestTimeoutError` [8](#0-7) , i.e., a cheap, unauthenticated flood by one actor causes other, unrelated users' requests to silently fail/time out — the same "single actor exhausts a shared capacity-limited resource, everyone else is denied service" pattern as the Axelar flow-limit issue, except here there is no operator-configurable mitigation at all (no rate limiter is even wired up for this path), whereas Axelar's flow limit is at least adjustable by the token operator.

### Impact Explanation
This is an availability/DoS issue reachable by any unauthenticated internet client hitting the Gateway's user-facing HTTP port with legacy `web_api_trigger` requests. It doesn't compromise funds or secrets directly, but it can cause legitimate workflow triggers from other users/nodes to be dropped or timed out, degrading the "function/availability" of the Gateway service for all tenants sharing a DON — the same qualifying criterion ("function of the protocol or its availability could be impacted") cited by the judge in the original report.

### Likelihood Explanation
Likelihood is high for any deployment still using the legacy (non-v2) `web_api_trigger` handler: the attack requires only crafting valid-looking JSON-RPC legacy requests with unique message IDs and current timestamps, well within reach of an unauthenticated actor, and the code path has explicitly no allowlist/rate limiting (confirmed by the inline `TODO`). Exploitability is limited only by whatever generic HTTP server-level protections (if any) sit in front of the Gateway's user port, which are outside this handler.

### Recommendation
Implement the `TODO` in `HandleLegacyUserMessage`: apply an allowlist and per-sender/per-IP rate limiting (mirroring the pattern already used in the v2 HTTP trigger handler's `userRateLimiter`/`checkRateLimit`) before accepting and storing a callback in `savedCallbacks`. Additionally, consider partitioning `savedCallbacks` (e.g., per-sender sub-limits) so that no single caller can evict entries belonging to other callers, and/or reject new legacy trigger requests once the map is near capacity rather than silently evicting the oldest half.

### Proof of Concept
1. Identify a DON exposed via the Gateway's legacy `web_api_trigger` method (message includes a `DonID`, routed via `g.handlers[donID]` in `gateway.go`).
2. Send `MaxSavedCallbacks` (default 20000) or more legacy JSON-RPC requests with method `web_api_trigger`, each with a unique `MessageID` and a `Timestamp` within `MaxAllowedMessageAgeSec`, faster than the `CallbackPruneIntervalSec` cycle.
3. Each request enters `HandleLegacyUserMessage` unrestricted (no allowlist/rate limit check) and inserts an entry into `h.savedCallbacks`.
4. Once `len(savedCallbacks) > MaxSavedCallbacks`, `pruneCallbacks` evicts the oldest half — including any legitimate, still-in-flight callbacks from other real users submitted just before the flood.
5. Those legitimate callers' `callback.Wait(ctx)` in `gateway.ProcessRequest` times out (`RequestTimeoutError`) even though the DON nodes may have already/will process and respond to their original requests — the response is discarded because the `MessageID` was evicted, confirming the cross-user denial-of-service.

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageID]
	delete(h.savedCallbacks, msg.Body.MessageID)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JSONRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
}

func (h *httpTriggerHandler) checkRateLimit(ctx context.Context, workflowID, requestID string, callback handlers.Callback) error {
	workflowRef, found := h.workflowMetadataHandler.GetWorkflowReference(workflowID)
	if !found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "workflow reference not found", callback)
		return errors.New("workflow reference not found")
	}

	orgID := h.resolveOrgID(ctx, workflowRef.workflowOwner)
	ctx = contexts.WithCRE(ctx, contexts.CRE{Owner: workflowRef.workflowOwner, Org: orgID, Workflow: workflowID})
	if err := h.userRateLimiter.AllowErr(ctx); err != nil {
		lggr := logger.With(h.lggr, platform.KeyWorkflowID, workflowID, platform.KeyWorkflowOwner, workflowRef.workflowOwner, "requestID", requestID, "err", err)
		if errLimited, ok := errors.AsType[limits.ErrorRateLimited](err); ok {
			switch errLimited.Scope {
			case settings.ScopeWorkflow:
				lggr.Errorf("failed to start execution: per workflow rate limit exceeded")
				h.metrics.IncrementWorkflowThrottled(ctx, h.lggr)
			default:

			}
			h.handleUserError(ctx, requestID, jsonrpc.ErrLimitExceeded, "rate limit exceeded", callback)
			return err
		}
		return fmt.Errorf("failed to check rate limit: %w", err)
	}
	return nil
}
