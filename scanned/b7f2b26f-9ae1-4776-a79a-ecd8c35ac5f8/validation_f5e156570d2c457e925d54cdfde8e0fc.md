### Title
Missing request-ID collision check in legacy WebAPI trigger handler allows cross-user response hijacking - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
The gateway's legacy `web_api_trigger` message path stores an unprivileged caller's response callback in a shared map keyed only by the client-supplied `MessageID`, with no check for whether that ID is already in use. This is the same class of bug as the BurgerSwap incident: a missing invariant/precondition check (there it was the `x*y>=k` reserve check; here it is a "does this ID already exist" check) lets an unprivileged actor overwrite shared state that a different request is relying on, letting the attacker capture a response that belongs to someone else.

### Finding Description
`gateway.ProcessRequest` (`core/services/gateway/gateway.go:221-295`) is the internet-facing entry point for the Gateway's HTTP server. For legacy (DON-ID-addressed) requests it calls: [1](#0-0) 

which dispatches to `handler.HandleLegacyUserMessage`: [2](#0-1) 

The `MessageID` here comes straight from the untrusted request body (`msg.Body.MessageID`), and is used, without any existence check, as the key to register the caller's callback: [3](#0-2) 

When a node later responds, `handleWebAPITriggerMessage` looks the response up purely by `MessageID` and forwards it to whatever callback is currently stored under that key, deleting the entry as it does: [4](#0-3) 

Because the write at line 412 is an unconditional map assignment (`h.savedCallbacks[msg.Body.MessageID] = &savedCallback{...}`), a second unprivileged client that submits a `web_api_trigger` request with the same `MessageID` as an in-flight legitimate request silently overwrites the original caller's saved callback. When the DON node eventually answers, the response is delivered to whichever callback is currently registered — i.e., potentially the attacker's callback rather than the original requester's — while the original legitimate caller's request is left hanging with no response and no error.

This is notably inconsistent with the rest of the codebase, where equivalent request-tracking maps explicitly guard against this exact collision:
- The v2 HTTP trigger handler checks for an existing entry and returns `jsonrpc.ErrConflict` before registering a callback: [5](#0-4) 
- The Vault gateway handler explicitly rejects duplicate request IDs: [6](#0-5) 
- The outgoing connector handler's `responses.new` also checks-then-inserts under a lock: [7](#0-6) 

Only the legacy `HandleLegacyUserMessage` path omits this check — the missing invariant enforced everywhere else in the same codebase.

### Impact Explanation
An unprivileged client can hijack the response to another user's in-flight `web_api_trigger` request by resubmitting the same `MessageID`. Depending on what data the WebAPI trigger response carries, this results in cross-user response confusion / potential disclosure of another workflow's trigger response to an attacker, and denial of service for the original legitimate caller whose request silently never completes. This falls squarely in the accepted "cross-user response confusion" impact category.

### Likelihood Explanation
Exploitability depends on the attacker being able to guess or observe another caller's `MessageID`, and on winning a narrow race window (the response must arrive after the attacker's overwrite but the original request must still be in flight). `MessageID` is client-chosen and not validated for entropy/uniqueness at this layer, so if callers use predictable IDs (or the ID is otherwise observable, e.g., leaked in logs, echoed elsewhere, or brute-forced) exploitation is plausible. This is a real code-level gap in the codebase, but I could not confirm from the indexed code exactly how `MessageID` is generated by all legitimate legacy clients (i.e., how much entropy/predictability exists in practice), which affects real-world likelihood.

### Recommendation
In `HandleLegacyUserMessage`, before inserting into `h.savedCallbacks`, check for an existing entry under `h.mu` and reject the request (mirroring the `http_trigger_handler.setupCallback` and Vault `newActiveRequest` patterns) instead of silently overwriting it.

### Proof of Concept
1. Attacker submits a legacy `web_api_trigger` gateway request with `MessageID = "X"` at roughly the same time a legitimate user's workflow trigger request also uses (or is made to reuse) `MessageID = "X"`.
2. Whichever request executes the assignment at `core/services/gateway/handlers/capabilities/handler.go:412` last "wins" the shared `savedCallbacks["X"]` slot.
3. When the DON node responds with `MessageID = "X"`, `handleWebAPITriggerMessage` (lines 148-161) delivers the response to whichever callback is currently stored — potentially the attacker's — while the other caller's request never receives a response.

Note: I could not fully verify in the index how `MessageID` values are generated/exposed for every legitimate caller of this legacy path (this affects exact predictability/likelihood); a Devin session with full repo access could trace all producers of legacy `web_api_trigger` messages to confirm real-world exploitability more precisely.

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageID]
	delete(h.savedCallbacks, msg.Body.MessageID)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JSONRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JSONRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) { //nolint:gosec // G115: comparing unix timestamps, both fit within uint
		h.lggr.Errorw("stale message")
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),
			ErrorCode: api.HandlerError,
		})
	}
	// TODO: apply allowlist and rate-limiting here
	if msg.Body.Method != MethodWebAPITrigger {
		h.lggr.Errorw("unsupported method", "method", body.Method)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.UnsupportedMethodError),
				"invalid method "+msg.Body.Method,
				nil,
			),
			ErrorCode: api.UnsupportedMethodError,
		})
	}
	req, err := common.ValidatedRequestFromMessage(msg)
	if err != nil {
		h.lggr.Errorw(ErrTransformingMessageToRequest)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrTransformingMessageToRequest,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	h.mu.Lock()
	h.savedCallbacks[msg.Body.MessageID] = &savedCallback{id: msg.Body.MessageID, createdAt: time.Now(), Callback: callback}
	don := h.don
	h.mu.Unlock()

	// Send original request to all nodes
	for _, member := range h.donConfig.Members {
		err = errors.Join(err, don.SendToNode(ctx, member.Address, req))
	}
	return err

func (r *responses) new(id string) (chan *api.Message, error) {
	r.mu.Lock()
	defer r.mu.Unlock()

	_, ok := r.chs[id]
	if ok {
		return nil, fmt.Errorf("already have response for id: %s", id)
	}

	// Buffered so we don't wait if sending
	ch := make(chan *api.Message, 1)
	r.chs[id] = ch
