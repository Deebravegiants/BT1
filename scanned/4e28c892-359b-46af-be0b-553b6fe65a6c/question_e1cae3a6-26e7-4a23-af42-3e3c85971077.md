[Target: SessionUtils.current_session_id embedded fallback] Attacker sends a request with no Authorization Bearer header but with a forged/stale `shopify_app_session` cookie value for a session id string they guessed or previously observed (e.g., 'offline_victim.myshopify.com' is a fully deterministic, guessable format per SessionUtils.offline_session_id). Precondition: Context.embedded? is true, no shopify_id_token present, so current_session_id falls back to cookie_session_id(cookies) which simply returns cookies[SESSION_COOKIE_NAME] with zero validation that this string corresponds to a session the current unsigned cookie bearer is entitled to. Call sequence: cookie_session_id returns the raw cookie value; nothing in SessionUtils verifies this cookie was ever signed or issued by this gem for this browser. Binding broken: SESSION DERIVATION states a session id must be derived only from bytes authenticated under Context.api_secret_key, but cookie_session_id derives it from an entirely unauthenticated cookie value equal to the deterministic string 'offline_{shop}'. Impact: Critical, cross-tenant access - an attacker who knows or guesses a victim's shop domain can set cookie shopify_app_session='offline_victim.myshopify.com' and have current_session_id return that exact session id, which the host app then uses to look up and load the victim's real offline Session (with real access_token) from its session storage. Proof idea: minitest calling SessionUtils.current_session_id(nil, {'shopify_app_session' => 'offline_victim.myshopify.com'}, false) and asserting it returns that attacker-supplied deterministic string with no HMAC/signature check performed anywhere in the call path, directly violating SESSION_DERIVATION.
