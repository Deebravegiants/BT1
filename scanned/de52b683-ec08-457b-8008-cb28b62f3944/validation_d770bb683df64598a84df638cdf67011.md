### Title
Verifier signature replay across crowdloan fund lifecycles due to missing `fund_index` in signed payload - (File: `polkadot/runtime/common/src/crowdloan/mod.rs`)

### Summary
`Pallet::do_contribute` verifies KYC signatures against the payload `(index, &who, old_balance, value)`, where `index` is the `ParaId` and `old_balance` is the contributor's balance in the *current* fund's child-trie. Because this payload omits the fund's unique `fund_index`, and `old_balance` resets to `0` whenever a new fund's child-trie is created, a signature obtained for a contributor's first contribution to a fund can be replayed verbatim as the first contribution to any later fund created for the same `ParaId`.

### Finding Description
In `do_contribute`, the verifier check is: [1](#0-0) 

The `old_balance` used in the payload comes from `contribution_get(fund.fund_index, &who)`, which reads from a child-trie keyed by `fund.fund_index` via `id_from_index`: [2](#0-1) 

`fund_index` itself is never included in the signed payload — only the `ParaId` (`index`), `who`, `old_balance`, and `value` are signed. `fund_index` is assigned monotonically from `NextFundIndex` at `create` time and is never reused for the same `ParaId` in the normal, non-overflow case: [3](#0-2) 

However, `dissolve` removes the `Funds` entry for a `ParaId` once `raised` is zero, allowing a brand-new fund to be `create`d again for the *same* `ParaId`: [4](#0-3) 

Since the new fund gets a fresh child-trie (`id_from_index(new_fund_index)`), any contributor's `old_balance` in that new fund starts at `0`, exactly matching the `old_balance` value that was signed for their very first contribution to the *previous* fund for that same `ParaId`. Because the signed payload is `(index, who, old_balance, value)` and `index` (`ParaId`) is unchanged across the dissolve/recreate cycle, the exact same `(index, who, 0, value)` payload — and therefore the exact same `MultiSignature` — is valid again in the new fund. The extrinsic and its embedded signature are public on-chain, so the contributor (`who`, who must resubmit the extrinsic as themselves since `who` is part of the signed payload) can simply resubmit their old `contribute` call unmodified in the new fund to bypass the verifier's fresh authorization requirement. No wraparound of `NextFundIndex` is needed — a simple dissolve-then-recreate cycle for the same `ParaId` is sufficient, since it is the `old_balance == 0` state, not `fund_index` reuse, that produces the payload collision.

None of the existing checks in `do_contribute` (cap, period, VRF delay, auctioneer status) reference `fund_index` or otherwise distinguish which fund lifecycle a signature was issued for.

### Impact Explanation
This allows a contributor to bypass the crowdloan's KYC/verifier gate for a newly created fund tied to the same parachain, reusing authorization that was only ever intended to cover a single, specific contribution event in a specific (now-dissolved) fund. This directly violates the stated invariant that "a verifier signature authorizes exactly one contribution event, not replayable across fund lifecycles," and undermines the KYC/whitelisting guarantee that crowdloan organizers rely on (e.g., jurisdictional restrictions, accredited-investor gating).

### Likelihood Explanation
Preconditions are realistic and require no privileged access: (1) a fund with `verifier = Some(...)` is created for a `ParaId`; (2) a contributor makes their first contribution (`old_balance == 0`) and the signature/extrinsic becomes publicly visible on-chain; (3) that fund is later dissolved (a routine, permissionless outcome for failed/expired crowdloans once `raised` reaches zero, e.g., after `refund`); (4) a new fund is created for the same `ParaId` (a common real-world scenario — re-attempting a crowdloan for the same parachain in a later lease period/auction). The attacker is simply the original contributor account replaying its own previously-signed, previously-broadcast extrinsic — no cryptographic forgery is needed.

### Recommendation
Include `fund.fund_index` (or another value unique to the fund's lifetime) in the signed payload, e.g. change the payload to `(fund.fund_index, index, &who, old_balance, value)`, so that a signature is cryptographically bound to a specific fund instance and cannot be replayed after dissolve/recreate cycles for the same `ParaId`.

### Proof of Concept
Rust unit test in `polkadot/runtime/common/src/crowdloan/mod.rs` test module:
1. Create fund `F1` for `ParaId(1)` with `verifier = Some(pubkey)`.
2. Sign payload `(ParaId(1), who=1, old_balance=0, value=100)` with the verifier key -> `sig`.
3. Call `contribute(who=1, index=1, value=100, Some(sig))` -> succeeds, `Contributed` event emitted.
4. `refund` the fund (contribution killed, `raised` back to 0), then `dissolve` fund `F1` (removes `Funds` entry, `fund_index` advances).
5. `create` a new fund `F2` for the same `ParaId(1)` with a new (or same) `verifier`.
6. Call `contribute(who=1, index=1, value=100, Some(sig))` reusing the *same* `sig` from step 2, without any new signing by the verifier.
7. Assert this call **succeeds** (rather than returning `Error::<T>::InvalidSignature`), proving the old signature is replayable across the fund lifecycle boundary and the verifier's fresh-authorization intent is bypassed.

		pub fn dissolve(origin: OriginFor<T>, #[pallet::compact] index: ParaId) -> DispatchResult {
			let who = ensure_signed(origin)?;

			let fund = Funds::<T>::get(index).ok_or(Error::<T>::InvalidParaId)?;
			let pot = Self::fund_account_id(fund.fund_index);
			let now = frame_system::Pallet::<T>::block_number();

			// Only allow dissolution when the raised funds goes to zero,
			// and the caller is the fund creator or we are past the end date.
			let permitted = who == fund.depositor || now >= fund.end;
			let can_dissolve = permitted && fund.raised.is_zero();
			ensure!(can_dissolve, Error::<T>::NotReadyToDissolve);

			// Assuming state is not corrupted, the child trie should already be cleaned up
			// and all funds in the crowdloan account have been returned. If not, governance
			// can take care of that.
			debug_assert!(Self::contribution_iterator(fund.fund_index).count().is_zero());

			// Crowdloan over, burn all funds.
			let _imba = CurrencyOf::<T>::make_free_balance_be(&pot, Zero::zero());
			let _ = frame_system::Pallet::<T>::dec_providers(&pot).defensive();

			CurrencyOf::<T>::unreserve(&fund.depositor, fund.deposit);
			Funds::<T>::remove(index);
			Self::deposit_event(Event::<T>::Dissolved { para_id: index });
			Ok(())
