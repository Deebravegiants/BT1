## Title
Unbounded per-sender rate-limiter map growth via case-variant address strings in Web API Trigger - ([File: core/capabilities/webapi/trigger/trigger.go])

### Summary
The Web API trigger's authorization check normalizes the sender address before comparing it against the `allowedSenders` allowlist, but the rate limiter that gates repeated requests is keyed by the **raw, un-normalized** sender string from the request body. Because Ethereum addresses are case-insensitive but their string encodings are not, a single already-allowlisted sender can generate a virtually unlimited number of distinct map keys (via casing permutations of the same address) that all pass authorization, each creating a brand-new, permanently retained rate-limiter entry — closely mirroring the CL-2026-07 root cause: a map that deduplicates/keys on unsanitized, attacker-influenceable strings with no bound and no garbage collection.

`sender` is derived via `ethCommon.HexToAddress(body.Sender)` in `HandleGatewayMessage`: [2](#0-1) 

`ethCommon.Address.String()` always returns the canonical EIP-55 checksummed representation, so the `allowedSenders[sender.String()]` check is case-insensitive with respect to the original input. However, `trigger.rateLimiter.Allow(body.Sender)` passes the **original, unnormalized** `body.Sender` string straight into the rate limiter's internal per-sender map, which is defined in the underlying rate limiter implementation as an ever-growing `map[string]*rate.Limiter` with no eviction, no TTL, and no maximum size — the same pattern seen in `core/services/workflows/ratelimiter/ratelimiter.go`: [3](#0-2) 

Since a 40-hex-character Ethereum address string admits up to 2^40 distinct casing permutations that all resolve to the *same* address (and thus the same allowlist entry), a single legitimately-allowlisted, authenticated sender can trivially generate an effectively unbounded number of unique raw strings, each of which:
1. Passes the `allowedSenders` check (because it is compared after normalization).
2. Creates a brand-new entry in the rate limiter's `perSender` map (because that check uses the raw string).

Unlike the dispatcher's `Allow(sender)` call (which is fed straight from an internal p2p peer identifier and is out of scope as a network-layer/peer-only issue), this path is reachable directly from `HandleGatewayMessage`, the internet-facing gateway message handler for the Web API trigger capability, driven by unprivileged/external HTTP-originated requests relayed through the gateway.

### Impact Explanation
Each new map entry retains a `*rate.Limiter` object indefinitely for the lifetime of the trigger registration; there is no cleanup, TTL, or cap on the `perSender` map size. An attacker who controls (or has compromised/observed) one allowlisted sender address can repeatedly resend/re-sign trigger requests with different casing of their own address, causing continuous, permanent memory growth in the node process — a low-cost quota/allowlist bypass that defeats the very purpose of the per-sender rate limiter and can degrade or crash the node hosting the Web API trigger capability, affecting all workflows served by that gateway/node.

### Likelihood Explanation
Exploitation requires only the ability to submit an already-authorized `web_api_trigger` request with a syntactically different (but semantically identical) sender address string — this is a request-crafting issue, not a cryptographic or authentication bypass, so it is straightforward for anyone with legitimate/authorized producer access to the trigger to abuse. It does not require breaking allowlist enforcement, exploiting the network layer, or a malicious peer/node.

### Recommendation
Normalize the sender string once (e.g., always store/compare against `sender.String()` or a canonical lower-case form) and use that single normalized value as the rate limiter key instead of the raw `body.Sender`. Additionally, consider bounding the `perSender` map with an LRU eviction policy or TTL-based reaping (similar to the `jwtReplayCache`/`responseCache` patterns already used elsewhere in the gateway) so that no single map used for rate limiting can grow without bound regardless of key normalization.

### Proof of Concept
1. Register a Web API trigger workflow with `AllowedSenders = ["0xABCDEF1234567890ABCDEF1234567890ABCDEF12"]` (case doesn't matter for the allowlist check).
2. As the holder of that address's signing key, send a stream of `web_api_trigger` gateway messages where `body.Sender` is set to distinct casing variants of the same address (e.g., `0xabcdef...`, `0xAbCdEf...`, etc.), signing each message appropriately.
3. Each request passes `trigger.allowedSenders[sender.String()]` (normalized check succeeds every time).
4. Each request calls `trigger.rateLimiter.Allow(body.Sender)` with a distinct raw string, inserting a new, permanent entry into the underlying `perSender` map.
5. Repeating this with enough casing variants causes continuous memory growth in the node process with no corresponding cleanup mechanism.

// Wrapper around Go's rate.Limiter that supports both global and a per-sender rate limiting.
type RateLimiter struct {
	global    *rate.Limiter
	perSender map[string]*rate.Limiter
	config    Config
	mu        sync.Mutex
}

type Config struct {
	GlobalRPS      float64 `json:"globalRPS"`
	GlobalBurst    int     `json:"globalBurst"`
	PerSenderRPS   float64 `json:"perSenderRPS"`
	PerSenderBurst int     `json:"perSenderBurst"`
}

func NewRateLimiter(cfg Config) (*RateLimiter, error) {
	if cfg.GlobalRPS <= 0.0 || cfg.PerSenderRPS <= 0.0 {
		return nil, errors.New("RPS values must be positive")
	}
	if cfg.GlobalBurst <= 0 || cfg.PerSenderBurst <= 0 {
		return nil, errors.New("burst values must be positive")
	}

	return &RateLimiter{
		global:    rate.NewLimiter(rate.Limit(cfg.GlobalRPS), cfg.GlobalBurst),
		perSender: make(map[string]*rate.Limiter),
		config:    cfg,
	}, nil
}

func (rl *RateLimiter) Allow(sender string) (senderAllow bool, globalAllow bool) {
	rl.mu.Lock()
	senderLimiter, ok := rl.perSender[sender]
	if !ok {
		senderLimiter = rate.NewLimiter(rate.Limit(rl.config.PerSenderRPS), rl.config.PerSenderBurst)
		rl.perSender[sender] = senderLimiter
	}
	rl.mu.Unlock()

	senderAllow = senderLimiter.Allow()
	globalAllow = rl.global.Allow()
	return senderAllow, globalAllow
}
