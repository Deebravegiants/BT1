## Finding

The Horde/gollem CVE is about a file-serving component that resolves a client-supplied filename and serves the underlying file's bytes without enforcing per-user/per-resource authorization when the filename exactly matches a known file. There is a structurally similar pattern in this repo's local CRE workflow artifact fetcher.

### Title
Cross-workflow artifact disclosure via unauthenticated filename resolution in local file-based `WorkflowFetcher` - (File: `core/services/workflows/syncer/v2/fetcher.go`)

### Summary
When a chainlink node is configured with `CRE.WorkflowFetcher.URL = "file://<basePath>"` (a supported, documented production/deployment mode, not just a test convenience), workflow binary/config artifacts are read from a shared local directory using a filename that comes directly from the `BinaryURL`/`ConfigURL` fields of an on-chain `WorkflowRegisteredEvent`. These fields are attacker-controlled: any account that can register a workflow in the `WorkflowRegistry` contract sets `BinaryURL`/`ConfigURL` themselves. The file fetcher only validates that the resolved path stays within `basePath` — it never checks that the requesting/registering workflow owner is actually entitled to the specific file being read.

### Finding Description
`newFileFetcher` resolves the incoming `req.URL` to a file under `basePath` and reads it directly with `os.ReadFile`, with no ownership or ACL check tying the requested filename to the workflow/owner making the request: [1](#0-0) 

The only guard is a directory-traversal check (`strings.HasPrefix(fullPath, basePath+...)`), and for HTTP-shaped URLs it deliberately strips everything but the exact basename before looking the file up: [2](#0-1) 

This function is wired as the `FetcherFunc` for the workflow registry v2 syncer: [3](#0-2) 

The `BinaryURL`/`ConfigURL` used as the fetch target are taken verbatim from the on-chain `WorkflowRegisteredEvent` payload, which is populated by whoever registers the workflow: [4](#0-3) [5](#0-4) 

The `file://` fetcher mode is not merely a unit-test artifact — it is a documented, actively used deployment configuration where the DON's operator places all registered workflows' binaries/configs into one shared directory (`/home/chainlink/workflows`) on every node: [6](#0-5) [7](#0-6) 

Because the "exact filename" is the only thing checked (basename resolution for HTTP-looking URLs, or a relative path for others), any workflow owner who knows or guesses another workflow's artifact filename in that shared directory (e.g. `<workflowID>.wasm`, or a filename referenced in another owner's on-chain registration event, which is publicly readable on-chain) can register their own workflow with `BinaryURL`/`ConfigURL` pointing at that filename and have the node's fetcher happily read and hand back that other workflow's binary/config content into their own workflow spec — with no check that they are the legitimate owner of that artifact.

### Impact Explanation
This allows an unprivileged workflow owner to read the compiled binary/config of another tenant's workflow that resides in the same shared artifact directory, by crafting a `BinaryURL`/`ConfigURL` value at registration time. Depending on what's embedded in those artifacts (secrets, business logic, configuration), this is a confidentiality bypass — analogous to the Horde CVE's "crafted filename bypasses authorization for file download."

### Likelihood Explanation
Likelihood depends on: (1) the DON being configured with `CRE.WorkflowFetcher.URL="file://..."` (a real, documented deployment mode used in multi-tenant Docker/system-test environments where multiple workflow owners share nodes), and (2) an attacker being able to determine or guess another workflow's artifact filename (on-chain registration data, including `BinaryURL`, is publicly visible, making this practical rather than requiring a blind guess).

### Recommendation
When serving artifacts via the local file fetcher, bind the resolved filename to the requesting `workflowID`/owner (e.g., store artifacts under owner/workflow-scoped subdirectories and reject any request whose resolved path does not match the expected `<owner>/<workflowID>` prefix), rather than trusting an attacker-suppliable filename with only a basePath-containment check.

### Proof of Concept
1. Deploy a node with `[CRE.WorkflowFetcher] URL = "file:///home/chainlink/workflows"` and have Workflow A's artifacts placed there as `home/chainlink/workflows/A.wasm`.
2. As a different, unprivileged workflow owner, register Workflow B on the same `WorkflowRegistry`, setting `BinaryURL = "https://any-host/whatever/A.wasm"` (or simply `"A.wasm"`).
3. When the syncer processes Workflow B's `WorkflowRegisteredEvent`, `createWorkflowSpec` → `FetchWorkflowArtifacts` → `newFileFetcher` resolves the basename `A.wasm`, finds it inside the shared `basePath`, and returns Workflow A's binary content, which gets stored as Workflow B's spec — disclosing Workflow A's artifact to Workflow B's owner with no ownership check.

func newFileFetcher(basePath string, lggr logger.Logger) types.FetcherFunc {
	return func(ctx context.Context, messageID string, req ghcapabilities.Request) ([]byte, error) {
		select {
		case <-ctx.Done():
			return nil, ctx.Err()
		default:
		}

		// the incoming request URL is expected to be a relative path or a path within the basePath
		if req.URL == "" {
			return nil, errors.New("request URL cannot be empty")
		}
		u, err := url.Parse(req.URL)
		if err != nil {
			return nil, fmt.Errorf("invalid URL: %w", err)
		}
		// Confidential workflows register with HTTP URLs (for the enclave).
		// Extract the filename so the file fetcher can find the local copy.
		if u.Scheme == "http" || u.Scheme == "https" {
			u.Path = filepath.Base(u.Path)
			if u.Path == "." || u.Path == "/" {
				return nil, errors.New("HTTP URL has no filename in path")
			}
		}
		fullPath := filepath.Clean(u.Path)

		// ensure that the incoming request URL is either relative or absolute but within the basePath
		if !filepath.IsAbs(fullPath) {
			// If it's not absolute, we assume it's relative to the basePath
			fullPath = filepath.Join(basePath, fullPath)
		}
		if !strings.HasPrefix(fullPath, basePath+string(filepath.Separator)) && fullPath != basePath {
			return nil, fmt.Errorf("request URL %s is not within the basePath %s", fullPath, basePath)
		}

		lggr.Debugw("Fetching file", "messageID", messageID, "path", fullPath, "workflowID", req.WorkflowID)

		data, err := os.ReadFile(fullPath)
		if err != nil {
			return nil, fmt.Errorf("failed to read file: %w", err)
		}
		return data, nil
	}

func newFetcherServiceV2(
	opts Opts,
	capCfg config.Capabilities,
	lggr logger.Logger,
	gatewayConnectorWrapper *gatewayconnector.ServiceWrapper,
) (wftypes.FetcherFunc, wftypes.LocationRetrieverFunc, []commonsrv.Service, error) {
	if opts.FetcherFunc != nil {
		return opts.FetcherFunc, nil, []commonsrv.Service{}, nil
	}

	if gatewayConnectorWrapper == nil {
		return nil, nil, nil, errors.New("unable to create workflow registry syncer without gateway connector")
	}

	wfStorage := capCfg.WorkflowRegistry().WorkflowStorage()
	storageClient := opts.StorageClient
	if wfStorage.URL() != "" {
		workflowOpts := []storage.WorkflowClientOpt{
			storage.WithJWTGenerator(opts.JWTGenerator),
		}
		if wfStorage.TLSEnabled() {
			workflowOpts = append(workflowOpts, storage.WithWorkflowTransportCredentials(credentials.NewClientTLSFromCert(nil, "")))
		}

		sc, err := storage.NewWorkflowClient(lggr, wfStorage.URL(), workflowOpts...)
		if err != nil {
			return nil, nil, nil, fmt.Errorf("failed to create storage client: %w", err)
		}

		storageClient = sc
	}

	if storageClient == nil {
		return nil, nil, nil, errors.New("must have a storage client")
	}

	fetcher := syncerV2.NewFetcherService(lggr, gatewayConnectorWrapper, storageClient)
	return fetcher.Fetch, fetcher.RetrieveURL, []commonsrv.Service{fetcher}, nil
}

func (h *eventHandler) createWorkflowSpec(ctx context.Context, payload WorkflowRegisteredEvent) (*job.WorkflowSpec, error) {
	ctx, span := h.tracer.Start(ctx, "fetch_artifacts",
		trace.WithAttributes(
			attribute.String("component", "workflow_syncer"),
			attribute.String("workflow_name", payload.WorkflowName),
		))
	defer span.End()

	wfID := payload.WorkflowID.Hex()
	owner := hex.EncodeToString(payload.WorkflowOwner)
	orgID, err := h.fetchOrganizationID(ctx, owner)
	if err != nil {
		h.lggr.Warnw("Failed to get organization from linking service", "workflowOwner", owner, "error", err)
	}
	ctx = contexts.WithCRE(ctx, contexts.CRE{Org: orgID, Owner: owner, Workflow: wfID})

	// With Workflow Registry contract v2 the BinaryURL and ConfigURL are expected to be identifiers that put through the Storage Service.
	decodedBinary, config, err := h.workflowArtifactsStore.FetchWorkflowArtifacts(ctx, wfID, payload.BinaryURL, payload.ConfigURL)
	if err != nil {
		return nil, err
	}
