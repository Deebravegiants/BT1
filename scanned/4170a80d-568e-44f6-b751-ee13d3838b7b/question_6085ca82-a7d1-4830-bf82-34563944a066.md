Target: IntentSignerViem.signIntent (packages/intents-sdk/src/intents/intent-signer-impl/intent-signer-viem.ts). Attacker input: an IntentPayload whose intent.signer_id field is explicitly set to another user's EVM address (e.g. victim '0xVictim...') while this.config.signer is the attacker's own viem Account. Preconditions: caller of signIntent (e.g. IntentExecuter.signAndSendIntent) forwards intentParams including signer_id from an untrusted source (a batch composition path, a payload factory, or a caller-supplied field) without cross-checking it against the signer's own address. Call sequence: signIntent builds payload JSON with signer_id: intent.signer_id ?? this.config.accountId ?? utils.authHandleToIntentsUserId(...) — since intent.signer_id is provided, it takes precedence and is used verbatim; signRaw then signs that JSON with the attacker's private key via signMessage, producing a fully valid MultiPayloadErc191 whose payload.signer_id names the victim but whose signature was produced by the attacker's key. Equality that breaks: signer_id in the signed payload == the intents user id derived from the public key that produced signature. Here the SDK happily builds and signs a payload where these are unequal, deferring entirely to the intents.near contract's ecrecover-based check to reject it — the SDK performs no local assertion that intent.signer_id (if supplied) matches authHandleToIntentsUserId({identifier: this.config.signer.address, method:'evm'}). Scoped impact: Critical — any code path that lets a caller pass an arbitrary signer_id through to IntentSignerViem.signIntent (e.g. a payload-factory hook, mergeIntentPayloads, or a naive integrator wrapper) will produce a validly-signed-looking artifact whose declared identity does not match its cryptographic signer, and if the relayer/contract path is ever bypassed or misconfigured, funds under the named signer_id could be targeted without the named party's key. Proof idea: vitest test calling signer.signIntent({signer_id: '0xVictimAddress', verifying_contract, deadline, nonce, intents:[]}) with signer being an attacker Account, then asserting the parsed payload.signer_id !== authHandleToIntentsUserId({identifier: signer.address, method:'evm'}) — i.e. the SDK signs a self-inconsistent payload without throwing.
