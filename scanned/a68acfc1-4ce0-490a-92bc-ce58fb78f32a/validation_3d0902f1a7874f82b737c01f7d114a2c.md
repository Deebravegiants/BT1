### Title
Unauthenticated `/v2/resume/:runID` endpoint allows overwriting already-recorded pipeline task results without validating current task state - (File: `core/web/pipeline_runs_controller.go`, `core/services/pipeline/orm.go`)

### Summary
The reported bug class — mutating a state record (`claimPromo`) without verifying its current status and without validating the externally-supplied payload before persisting it — has a direct analog in the chainlink node's pipeline resume flow. The `Resume` handler is mounted as a fully **unauthenticated** route, and the underlying `UpdateTaskRunResult` query updates a task run's `output`/`error`/`finished_at` unconditionally, without checking whether that specific task run has already been completed.

### Finding Description
The route is registered without any authentication middleware: [1](#0-0) 

`Resume()` accepts an attacker/external-controlled JSON body and passes it straight through to `App.ResumeJobV2`, with only structural (not business-state) validation: [2](#0-1) 

This calls into `ResumeRun` → `UpdateTaskRunResult`: [3](#0-2) 

The ORM method guards only on the *pipeline run's* state (`running` or `suspended`), not on whether the specific `pipeline_task_runs` row (identified only by `taskID`) has already been finished: [4](#0-3) 

Because `running` is included in the allowed states, a task run can be resumed a second time (with different/attacker-controlled data) while the parent run is still executing (i.e., after the first legitimate resume already set `finished_at`), silently overwriting the previously recorded `output`/`error` for that step — exactly mirroring the reported bug's core defect: “updates state without validation that the current status is `pending`” and “does not validate the transaction hash” (i.e., accepts unvalidated payload as ground truth).

### Impact Explanation
Any external party who can guess/obtain a task run UUID (used as the sole "secret" for this route, since there is no API key/session check) can inject or overwrite a pipeline task's stored result. This can corrupt data used to drive job outputs (e.g., bridge/VRF/ETH-tx callback results) for that pipeline run, leading to incorrect on-chain reporting or state confusion, without the taskID owner (the legitimate bridge/external system) being verified.

### Likelihood Explanation
Medium: the taskID (UUID) is not a widely-known secret and exploitation requires the attacker to know or infer it, but the endpoint is unauthenticated at the router level and there is no additional guard that the task hasn't already been finished, matching the root cause of the reported bug (missing pre-update state check + missing payload validation).

### Recommendation
1. In `UpdateTaskRunResult` (`core/services/pipeline/orm.go`), add a check that the targeted `pipeline_task_runs` row's `finished_at` is currently `NULL` before applying the update (i.e., `WHERE id = $1 AND finished_at IS NULL`), analogous to adding `status = 'pending'` in `claimPromo()`.
2. Validate/sanitize the `ResumeRequest` payload content more strictly before persisting it as a trusted result.
3. Consider requiring a per-run/per-task shared secret (beyond the UUID) if a stronger authentication boundary is desired for this admittedly deliberately-unauthenticated callback endpoint.

### Proof of Concept
1. Discover/obtain a pending pipeline task UUID for a run currently in the `running` state (e.g., via a resumed job with multiple async steps).
2. Send the legitimate first `PATCH /v2/resume/:runID` with a valid result — task is marked finished, run transitions/stays `running`.
3. Send a second `PATCH /v2/resume/:runID` with a different attacker-chosen result body — because the ORM query only filters on `pipeline_runs.state IN ('running','suspended')` and not on the task's own completion state, the update succeeds and overwrites the previously stored `output`/`error` for that task, with no authentication or idempotency check preventing it.

// Resume finishes a task and resumes the pipeline run.
// Example:
// "PATCH <application>/jobs/:ID/runs/:runID"
func (prc *PipelineRunsController) Resume(c *gin.Context) {
	taskID, err := uuid.Parse(c.Param("runID"))
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	rr := pipeline.ResumeRequest{}
	decoder := json.NewDecoder(c.Request.Body)
	err = errors.Wrap(decoder.Decode(&rr), "failed to unmarshal JSON body")
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	result, err := rr.ToResult()
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	if err := prc.App.ResumeJobV2(c.Request.Context(), taskID, result); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
	c.Status(http.StatusOK)
}

func (o *orm) UpdateTaskRunResult(ctx context.Context, taskID uuid.UUID, result Result) (run Run, start bool, err error) {
	if result.OutputDB().Valid && result.ErrorDB().Valid {
		panic("run result must specify either output or error, not both")
	}
	err = o.transact(ctx, func(tx *orm) error {
		sql := `
		SELECT pipeline_runs.*, pipeline_specs.dot_dag_source "pipeline_spec.dot_dag_source", job_pipeline_specs.job_id "job_id"
		FROM pipeline_runs
		JOIN pipeline_task_runs ON (pipeline_task_runs.pipeline_run_id = pipeline_runs.id)
		JOIN pipeline_specs ON (pipeline_specs.id = pipeline_runs.pipeline_spec_id)
		JOIN job_pipeline_specs ON (job_pipeline_specs.pipeline_spec_id = pipeline_specs.id)
		WHERE pipeline_task_runs.id = $1 AND pipeline_runs.state in ('running', 'suspended')
		FOR UPDATE`
		if err = tx.ds.GetContext(ctx, &run, sql, taskID); err != nil {
			return fmt.Errorf("failed to find pipeline run for task ID %s: %w", taskID.String(), err)
		}

		// Update the task with result
		sql = `UPDATE pipeline_task_runs SET output = $2, error = $3, finished_at = $4 WHERE id = $1`
		if _, err = tx.ds.ExecContext(ctx, sql, taskID, result.OutputDB(), result.ErrorDB(), time.Now()); err != nil {
			return fmt.Errorf("failed to update pipeline task run: %w", err)
		}

		if run.State == RunStatusSuspended {
			start = true
			run.State = RunStatusRunning

			sql = `UPDATE pipeline_runs SET state = $2 WHERE id = $1`
			if _, err = tx.ds.ExecContext(ctx, sql, run.ID, run.State); err != nil {
				return fmt.Errorf("failed to update pipeline run state: %w", err)
			}
		}

		return loadAssociations(ctx, tx.ds, []*Run{&run})
	})

	return run, start, err
}
