### Title
Missing allowlist and rate-limiting enforcement on legacy WebAPI trigger user messages allows any client to broadcast unauthenticated requests to an entire DON - (File: core/services/gateway/handlers/capabilities/handler.go)

### Summary
The gateway's legacy WebAPI handler explicitly skips the allowlist and rate-limiting checks it is supposed to perform on inbound user-triggered messages before forwarding them to every member node of a DON.

### Finding Description
`HandleLegacyUserMessage` parses and validates only the message's structure (payload decoding and staleness), then forwards the request to every node in the DON without any authorization/allowlist or rate-limit check. The code contains an explicit unresolved `TODO: apply allowlist and rate-limiting here` marker right before the request is dispatched: [1](#0-0) 

After that TODO, only the `Method` field is validated (must equal `MethodWebAPITrigger`); there is no check of caller identity, DON membership, or workflow ownership before the request is saved as a pending callback and broadcast: [2](#0-1) 

This mirrors the root cause pattern in the reference report: a protective check (there, the circuit breaker; here, the allowlist/rate-limit gate) exists conceptually but is not actually enforced at the point where it must gate a state-changing/costly action (broadcasting to all DON nodes), letting an unprivileged caller's request go through and cause resource consumption/exposure that the check was meant to prevent.

### Impact Explanation
Any external, unauthenticated caller able to reach this gateway handler's `HandleLegacyUserMessage` path can force it to fan out arbitrary trigger requests to every node member of the configured DON, consuming node compute/network resources, filling the `savedCallbacks` map (bounded only by `MaxSavedCallbacks`/prune interval), and bypassing the intended per-caller/allowlist gating that other methods in the same gateway package (`HandleJSONRPCUserMessage`, the v2 HTTP trigger handler) do enforce (see JWT/allowlist and rate-limit checks in `core/services/gateway/handlers/capabilities/v2/http_trigger_handler_test.go`).

### Likelihood Explanation
High: this is the default code path for any legacy user message reaching this handler; no privileged role or special network position is required, and the missing check is unconditional (not behind a feature flag), only requiring correct message structure and a non-stale timestamp.

### Recommendation
Implement the allowlist and rate-limiting checks referenced by the TODO before saving the callback and broadcasting the message to DON members in `HandleLegacyUserMessage`, mirroring the enforcement pattern used in the v2 HTTP trigger handler (JWT verification + `limits.RateLimiter` checks) so unauthenticated/unallowlisted callers cannot trigger DON-wide broadcasts.

### Proof of Concept
1. Send a JSON message to the gateway's legacy user-message endpoint with `Body.Method = "web_api_trigger"`, a valid non-stale `Timestamp`, and any `TriggerRequestPayload`.
2. Because no allowlist/rate-limit check exists between payload validation and dispatch (`core/services/gateway/handlers/capabilities/handler.go:384-420`), the gateway will register a callback and call `don.SendToNode` for every DON member, regardless of the caller's identity or authorization.
3. Repeating this from a single unauthenticated client saturates DON nodes and the gateway's callback map without any throttling.
