## Finding

### Title
Confidential relay gateway handler processes JSON-RPC requests with unvalidated `Method` names, enabling authenticated-caller DoS via unbounded active-request fan-out - ([File: core/services/gateway/handlers/confidentialrelay/handler.go])

### Summary
The confidential relay gateway `Handler.HandleJSONRPCUserMessage` accepts and fully processes a JSON-RPC request regardless of whether `req.Method` is one of the two methods it declares via `Methods()`. Combined with `multiHandler.getHandler`'s single-handler bypass, any authenticated gateway caller can submit requests carrying an arbitrary, unsanitized method string and still have them fanned out to every node in the DON, mirroring the CVE-2024-33667 root cause: an endpoint accepting a generic method name without checking it against an allowlist.

### Finding Description
`Handler.Methods()` declares only two supported method names: [1](#0-0) 

However, `HandleJSONRPCUserMessage` never checks `req.Method` against this allowlist before doing real work — it only validates the request ID, then unconditionally creates an `activeRequest` and fans it out to every DON member node: [2](#0-1) 

This is in contrast to the sibling handlers in this codebase, which explicitly reject unrecognized methods before doing any work, e.g. the vault gateway handler's `default:` branch and its `IsGatewaySecretsMethod` allowlist check: [3](#0-2) [4](#0-3) 
and the capabilities handler and the confidentialrelay's own node-message-side handler (`serveGatewayMessage`), both of which have explicit `default:`/unsupported-method rejection paths: [5](#0-4) [6](#0-5) 

The routing layer compounds the exposure. `multiHandler.getHandler` looks up a handler by exact method name in `methodToHandler`, but if only one handler type is configured for a DON (a documented, intentional backward-compatibility path), it bypasses that lookup entirely and routes *any* method string straight to the sole handler: [7](#0-6) 

So when a DON is configured with only the confidential-relay handler, a caller's request method is never checked against `Methods()` at any layer before `fanOutToNodes` runs.

Each such request allocates an `activeRequest` (tracked in `h.activeRequests` until `RequestTimeoutSec`, default 30s) and spawns a fan-out goroutine that calls `SendToNode` against every DON member, consuming the shared per-node and global rate-limiter budgets that are meant to bound legitimate `MethodSecretsGet`/`MethodCapabilityExec` traffic: [8](#0-7) [9](#0-8) 

### Impact Explanation
An authenticated gateway caller (an "agent"/workflow owner able to reach the confidential-relay gateway endpoint) can submit a flood of JSON-RPC requests with arbitrary, non-allowlisted `Method` values and unique IDs. Because the method is never validated, each request still: (1) allocates a tracked `activeRequest` entry held in memory for up to `RequestTimeoutSec`, and (2) triggers a real network fan-out to every relay-DON node, consuming the finite global/per-node rate-limiter tokens. This can exhaust the rate limiters and memory bookkeeping meant to protect the relay DON, denying service to legitimate confidential relay requests — the same "authenticated actor causes remote DoS via unsanitized generic method name" pattern as CVE-2024-33667.

### Likelihood Explanation
Reaching this path requires only an authenticated, unprivileged caller of the gateway's user-facing JSON-RPC endpoint (no special role or node-operator access), and no crafted params are needed — an arbitrary `Method` string is sufficient. The bypass is more directly exploitable when a DON is configured with only the confidential-relay handler (the `len(m.typeToHandler) == 1` fast path), which is an explicitly supported configuration, not an edge case.

### Recommendation
Add an explicit allowlist check of `req.Method` against `h.Methods()` (or a `switch`/`default: unsupported method` branch, matching the pattern already used in `vault/handler.go`, `capabilities/handler.go`, and the node-message side of this same package) at the top of `confidentialrelay.Handler.HandleJSONRPCUserMessage`, before any `activeRequest` is created or fan-out occurs. Additionally, reconsider the single-handler bypass in `multiHandler.getHandler` so it still validates the method against `methodToHandler` (or the handler's own `Methods()`) rather than unconditionally routing any string to the sole registered handler.

### Proof of Concept
1. Configure a gateway DON with only the `confidentialrelay` handler registered (single-handler `multiHandler` configuration).
2. As an authenticated gateway user, repeatedly POST JSON-RPC requests such as:
```json
{"jsonrpc":"2.0","id":"<unique>","method":"garbage.method.<n>","params":{}}
```
3. Each request bypasses `multiHandler`'s per-method lookup (single-handler fast path) and is delivered to `confidentialrelay.Handler.HandleJSONRPCUserMessage`, which does not check `Method` against `Methods()` and proceeds to create an `activeRequest` and fan it out via `SendToNode` to every DON member.
4. Repeating this at volume exhausts `globalNodeRateLimiter`/`perNodeRateLimiters` capacity and grows `h.activeRequests`, degrading or denying legitimate `secretsGet`/`capabilityExec` relay traffic until requests time out (`RequestTimeoutSec`).

func (h *handler) removeExpiredRequests(ctx context.Context) {
	h.mu.RLock()
	var expiredRequests []*activeRequest
	now := h.clock.Now()
	for _, userRequest := range h.activeRequests {
		if now.Sub(userRequest.createdAt) > h.requestTimeout {
			expiredRequests = append(expiredRequests, userRequest)
		}
	}
	h.mu.RUnlock()

	for _, er := range expiredRequests {
		responses := er.copiedResponses()
		l := h.requestLogger(er.req, er.labels)
		l.Debugw("request expired, evaluating collected relay responses",
			"collected", len(responses),
			"nodes", len(h.donConfig.Members),
			"unanswered", len(h.donConfig.Members)-len(responses),
		)
		summary, err := h.bundler.Bundle(er.req, responses, l)
		if err != nil {
			l.Errorw("failed to build relay response bundle", "error", err)
			if sendErr := h.sendResponseAndClearRequest(ctx, er, h.constructErrorResponse(er.req, api.FatalError, err)); sendErr != nil {
				l.Errorw("error returning bundle failure on expiry", "error", sendErr)
			}
			continue
		}
		// Expiry makes further responses unavailable to this request. The common
		// readiness path forwards a viable partial bundle or returns a timeout.
		if err := h.forwardBundleOrTerminateIfReady(ctx, l, er, summary, 0, true); err != nil {
			l.Errorw("error forwarding bundle on expiry", "error", err)
		}
	}

func (h *handler) HandleJSONRPCUserMessage(ctx context.Context, req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) error {
	if req.ID == "" {
		return errors.New("request ID cannot be empty")
	}
	if len(req.ID) > 200 {
		return errors.New("request ID is too long: " + strconv.Itoa(len(req.ID)) + ". max is 200 characters")
	}

	labels := h.extractRequestLabels(req)
	l := h.requestLogger(req, labels)
	l.Debugw("handling confidential relay request", "nodes", len(h.donConfig.Members), "f", h.donConfig.F)

	ar, err := h.newActiveRequest(req, labels, callback)
	if err != nil {
		return err
	}

	return h.fanOutToNodes(ctx, l, ar)
}

func (h *handler) HandleNodeMessage(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	msg, err := common.ValidatedMessageFromResp(resp)
	if err != nil {
		return err
	}
	if msg.Body.Sender != nodeAddr {
		return errors.New("message sender mismatch when reading from node ")
	}
	start := time.Now()
	switch msg.Body.Method {
	case MethodWebAPITrigger:
		err = h.handleWebAPITriggerMessage(ctx, msg, nodeAddr)
	case MethodWebAPITarget, MethodComputeAction, MethodWorkflowSyncer:
		err = h.handleWebAPIOutgoingMessage(ctx, msg, nodeAddr)
	default:
		err = fmt.Errorf("unsupported method: %s", msg.Body.Method)
	}
	h.metrics.recordHandleDuration(ctx, time.Since(start), msg.Body.Method, err == nil)
	return err
}

func (m *multiHandler) getHandler(method string) (handlers.Handler, error) {
	// If there's only one handler, return it directly.
	// This preserves backwards compatibility for cases where the method
	// isn't specified on responses (and for cases where only one handler is registered more generally).
	if len(m.typeToHandler) == 1 {
		for _, handler := range m.typeToHandler {
			return handler, nil
		}
	}

	handler, ok := m.methodToHandler[method]
	if !ok {
		return nil, errors.New("no handler found for method " + method)
	}

	return handler, nil
}
