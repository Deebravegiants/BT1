### Title
Revoked/demoted LDAP user privileges remain valid on existing sessions and API tokens until the next upstream sync (or indefinitely if `UpstreamSyncInterval` is unset) - ([File: core/sessions/ldapauth/sync.go])

### Summary
The LDAP authentication provider caches a user's role locally in `ldap_sessions` and `ldap_user_api_tokens` at login/token-creation time. All subsequent authorization checks (`AuthorizedUserWithSession`, `FindUserByAPIToken`) read only this locally cached role and never re-check the upstream LDAP directory in real time. The cached role is only reconciled with the authoritative upstream group membership by a periodic background job (`LDAPServerStateSyncer.Work`). If that job's interval is long, or disabled (`UpstreamSyncInterval` set to 0/instant), a user whose privileges are revoked or downgraded upstream (e.g. removed from the Admin LDAP group) keeps using their already-issued session cookie or API token at the old, stale, higher role indefinitely between syncs — or forever if periodic sync is disabled.

### Finding Description
This is structurally the same bug class as the `TribalChief` report: a privileged, mutable piece of state (`rewardMultipliers` / here, the user's role) is snapshotted into a **local** copy at the time of a prior action (deposit / login), and later authorization decisions consult only that local copy instead of the live, authoritative source. Just as `TribalChief` failed to react to an *increase* of the multiplier because it only compared against the stale value, this LDAP provider fails to react to a *decrease* (revocation) of a user's role because authorization only consults the stale, locally cached `ldap_sessions`/`ldap_user_api_tokens` row.

Evidence:
- The package doc explicitly acknowledges the caching design and states the sync "happens... via the defined sync interval" [1](#0-0) .
- `AuthorizedUserWithSession` returns the role straight from the local `ldap_sessions` table with no upstream check: [2](#0-1) .
- `FindUserByAPIToken` likewise only reads the locally cached role from `ldap_user_api_tokens`: [3](#0-2) .
- The only place the local cache is reconciled with the real upstream state is `LDAPServerStateSyncer.Work`, which builds the current `upstreamUserStateMap` and issues `UPDATE ldap_sessions/ldap_user_api_tokens SET user_role = CASE ...`: [4](#0-3) .
- Crucially, this reconciliation only runs on a ticker if `UpstreamSyncInterval` is non-zero; if it is zero/instant, sync is performed **once at startup and never again**, meaning role changes made upstream after node startup are never propagated to already-issued sessions/tokens for the life of the process: [5](#0-4) .

### Impact Explanation
A user who is demoted or fully revoked in the upstream LDAP directory (e.g., an admin is removed from the "Admin" LDAP group after being terminated or after a security incident) retains their previously-granted role (e.g. `UserRoleAdmin`) for every request authenticated via their existing session cookie or API token, until the periodic sync job runs and updates the row — or forever if the operator has not configured `UpstreamSyncInterval` to a nonzero value. This is a concrete role/authorization bypass: it allows continued privileged API access (job/spec management, bridge/EI management, key management, etc., gated by `UserRoleAdmin`/`UserRoleEdit` via `web/auth` role checks) after the authoritative directory has revoked that access.

### Likelihood Explanation
Likelihood is moderate-to-high in any deployment using the LDAP authentication driver with a long or disabled `UpstreamSyncInterval` (a config choice explicitly supported by the code, see `IsInstant()` branch). No attacker action is required beyond continuing normal, previously-authorized use of an existing session/API token — this is triggered purely by legitimate ongoing use after an administrative revocation event, i.e., reachable via ordinary authenticated HTTP requests using credentials the user already legitimately possesses.

### Recommendation
- Re-validate the user's role against the upstream LDAP source (or at minimum enforce a hard-coded maximum staleness) on every `AuthorizedUserWithSession` / `FindUserByAPIToken` call rather than trusting the locally cached role indefinitely.
- Disallow configuring `UpstreamSyncInterval` as "instant"/zero when running in a mode intended for continuous operation, or otherwise still run periodic sync even when the interval is unset, so revocations always eventually propagate.
- Consider immediately invalidating/downgrading cached sessions and tokens on detection of a role change, rather than only updating the role value (i.e., force re-authentication for demoted/revoked accounts rather than silently degrading, to reduce the exposure window further).

### Proof of Concept
1. Configure the Chainlink node with the LDAP auth driver and `UpstreamSyncInterval = "0s"` (instant/disabled periodic sync), matching a supported configuration path in `sync.go`'s `Start()`.
2. A user in the upstream "Admin" LDAP group logs in, creating a row in `ldap_sessions` with `user_role = 'admin'` (`CreateSession`, `ldap.go`).
3. An LDAP administrator removes the user from the Admin group upstream (revocation) after node startup.
4. Because `Start()` only calls `Work()` once at startup when `UpstreamSyncInterval` is instant, no further reconciliation ever runs.
5. The revoked user continues to send requests with their existing session cookie; `AuthorizedUserWithSession` returns `Role: "admin"` straight from the stale `ldap_sessions` row, and admin-gated endpoints (e.g., `RequiresAdminRole`-style checks in `web/auth`) continue to authorize them as admin indefinitely.

// FindUserByAPIToken retrieves a possible stored user and role from the ldap_user_api_tokens table store
func (l *ldapAuthenticator) FindUserByAPIToken(ctx context.Context, apiToken string) (sessions.User, error) {
	if !l.config.UserApiTokenEnabled() {
		return sessions.User{}, errors.New("API token is not enabled ")
	}

	// Query the ldap user API token table for given token, user role and email are cached so
	// no further upstream LDAP query is performed, sessions and tokens are synced against the upstream server
	// via the UpstreamSyncInterval config and reaper.go sync implementation
	var foundUserToken struct {
		UserEmail string
		UserRole  sessions.UserRole
		Valid     bool
	}
	err := l.ds.GetContext(ctx, &foundUserToken,
		"SELECT user_email, user_role, created_at + $2 >= now() as valid FROM ldap_user_api_tokens WHERE token_key = $1",
		apiToken, l.config.UserAPITokenDuration().Duration(),
	)
	if err != nil {
		return sessions.User{}, err
	}
	if !foundUserToken.Valid { // API Token expired, purge
		if _, execErr := l.ds.ExecContext(ctx, "DELETE FROM ldap_user_api_tokens WHERE token_key = $1", apiToken); execErr != nil {
			l.lggr.Errorf("error purging stale ldap API token session: %v", execErr)
		}
		return sessions.User{}, sessions.ErrUserSessionExpired
	}

	return sessions.User{
		Email: foundUserToken.UserEmail,
		Role:  foundUserToken.UserRole,
	}, nil
}

// AuthorizedUserWithSession will return the API user associated with the Session ID if it
// exists and hasn't expired, and update session's LastUsed field. The state of the upstream LDAP server
// is polled and synced at the defined interval via a SleeperTask
func (l *ldapAuthenticator) AuthorizedUserWithSession(ctx context.Context, sessionID string) (sessions.User, error) {
	if len(sessionID) == 0 {
		return sessions.User{}, errors.New("session ID cannot be empty")
	}
	// Query the ldap_sessions table for given session ID, user role and email are cached so
	// no further upstream LDAP query is performed
	var foundSession struct {
		UserEmail string
		UserRole  sessions.UserRole
		Valid     bool
	}
	if err := l.ds.GetContext(ctx, &foundSession,
		"SELECT user_email, user_role, created_at + $2 >= now() as valid FROM ldap_sessions WHERE id = $1",
		sessionID, l.config.SessionTimeout().Duration(),
	); err != nil {
		return sessions.User{}, sessions.ErrUserSessionExpired
	}
	if !foundSession.Valid {
		// Sessions expired, purge
		if _, execErr := l.ds.ExecContext(ctx, "DELETE FROM ldap_sessions WHERE id = $1", sessionID); execErr != nil {
			l.lggr.Errorf("error purging stale ldap session: %v", execErr)
		}
		return sessions.User{}, sessions.ErrUserSessionExpired
	}
	return sessions.User{
		Email: foundSession.UserEmail,
		Role:  foundSession.UserRole,
	}, nil
}

func (l *LDAPServerStateSyncer) Start(ctx context.Context) error {
	// If enabled, start a background task that calls the Sync/Work function on an
	// interval without needing an auth event to trigger it
	// Use IsInstant to check 0 value to omit functionality.
	if !l.config.UpstreamSyncInterval().IsInstant() {
		l.lggr.Info("LDAP Config UpstreamSyncInterval is non-zero, sync functionality will be called on a timer, respecting the UpstreamSyncRateLimit value")
		go l.run()
	} else {
		// Ensure upstream server state is synced on startup manually if interval check not set
		l.Work(ctx)
	}
	return nil
}

	// upstreamUserStateMap is now the most up to date source of truth
	// Now sync database sessions and roles with new data
	err = sqlutil.TransactDataSource(ctx, l.ds, nil, func(tx sqlutil.DataSource) error {
		// First, purge users present in the local ldap_sessions table but not in the upstream server
		type LDAPSession struct {
			UserEmail string
			UserRole  sessions.UserRole
		}
		var existingSessions []LDAPSession
		if err = tx.SelectContext(ctx, &existingSessions, "SELECT user_email, user_role FROM ldap_sessions WHERE localauth_user = false"); err != nil {
			return fmt.Errorf("unable to query ldap_sessions table: %w", err)
		}
		var existingAPITokens []LDAPSession
		if err = tx.SelectContext(ctx, &existingAPITokens, "SELECT user_email, user_role FROM ldap_user_api_tokens WHERE localauth_user = false"); err != nil {
			return fmt.Errorf("unable to query ldap_user_api_tokens table: %w", err)
		}

		// Create existing sessions and API tokens lookup map for later
		existingSessionsMap := make(map[string]LDAPSession)
		for _, sess := range existingSessions {
			existingSessionsMap[sess.UserEmail] = sess
		}
		existingAPITokensMap := make(map[string]LDAPSession)
		for _, sess := range existingAPITokens {
			existingAPITokensMap[sess.UserEmail] = sess
		}

		// Populate list of session emails present in the local session table but not in the upstream state
		emailsToPurge := []any{}
		for _, ldapSession := range existingSessions {
			if _, ok := upstreamUserStateMap[ldapSession.UserEmail]; !ok {
				emailsToPurge = append(emailsToPurge, ldapSession.UserEmail)
			}
		}
		// Likewise for API Tokens table
		apiTokenEmailsToPurge := []any{}
		for _, ldapSession := range existingAPITokens {
			if _, ok := upstreamUserStateMap[ldapSession.UserEmail]; !ok {
				apiTokenEmailsToPurge = append(apiTokenEmailsToPurge, ldapSession.UserEmail)
			}
		}

		// Remove any active sessions this user may have
		if len(emailsToPurge) > 0 {
			_, err = tx.ExecContext(ctx, "DELETE FROM ldap_sessions WHERE user_email = ANY($1)", pq.Array(emailsToPurge))
			if err != nil {
				return err
			}
		}

		// Remove any active API tokens this user may have
		if len(apiTokenEmailsToPurge) > 0 {
			_, err = tx.ExecContext(ctx, "DELETE FROM ldap_user_api_tokens WHERE user_email = ANY($1)", pq.Array(apiTokenEmailsToPurge))
			if err != nil {
				return err
			}
		}

		// For each user session row, update role to match state of user map from upstream source
		var queryWhenClause strings.Builder
		emailValues := []any{}
		// Prepare CASE WHEN query statement with parameterized argument $n placeholders and matching role based on index
		for email, user := range upstreamUserStateMap {
			// Only build on SET CASE statement per local session and API token role, not for each upstream user value
			_, sessionOk := existingSessionsMap[email]
			_, tokenOk := existingAPITokensMap[email]
			if !sessionOk && !tokenOk {
				continue
			}
			emailValues = append(emailValues, email)
			fmt.Fprintf(&queryWhenClause, "WHEN user_email = $%d THEN '%s' ", len(emailValues), user.Role)
		}

		// If there are remaining user entries to update
		if len(emailValues) != 0 {
			// Set new role state for all rows in single Exec
			query := fmt.Sprintf("UPDATE ldap_sessions SET user_role = CASE %s ELSE user_role END", &queryWhenClause)
			_, err = tx.ExecContext(ctx, query, emailValues...)
			if err != nil {
				return err
			}

			// Update role of API tokens as well
			query = fmt.Sprintf("UPDATE ldap_user_api_tokens SET user_role = CASE %s ELSE user_role END", &queryWhenClause)
			_, err = tx.ExecContext(ctx, query, emailValues...)
			if err != nil {
				return err
			}
		}

		l.lggr.Info("local ldap_sessions and ldap_user_api_tokens table successfully synced with upstream LDAP state")
		return nil
	})
	if err != nil {
		l.lggr.Error("Error syncing local database state: ", err)
	}
	l.lggr.Info("Upstream LDAP sync complete")
}
