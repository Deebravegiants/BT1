[Hinkal.prooflessDeposit -> markUtxosAsBlocked / createBlockedUtxos] Can an unprivileged EOA pass `createBlockedUtxos=true` on a `prooflessDeposit` whose `stealthAddressStructures`/`onChainEncryptedOutputs` are crafted so the emitted `BlockedUtxosCreated` event (the ONLY on-chain signal of blocking, per `HinkalBase.markUtxosAsBlocked`, which is a no-argument event carrying no leaf/commitment identifiers) cannot be correlated by off-chain listeners to the specific leaves just inserted, letting the attacker's own leaves be minted as ordinary (non-blocked) spendable UTXOs in the on-chain Merkle tree while any downstream compliance/consumer logic believes them blocked? Preconditions: attacker submits deposit with `createBlockedUtxos=true`. Equality: the set of leaves this call inserted into the Merkle tree (and thus spendable via a valid nullifier later) must equal the set of leaves any consumer treats as 'blocked' — since the event carries no leaf IDs, this equality cannot be verified on-chain at all.
