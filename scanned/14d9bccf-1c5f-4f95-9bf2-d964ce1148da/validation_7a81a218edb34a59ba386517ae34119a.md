### Title
Legacy Web API Trigger Path Bypasses Allowlist and Rate-Limiting Enforced on the JSON-RPC Path - (File: `core/services/gateway/handlers/capabilities/handler.go`)

### Summary
The gateway's capabilities handler exposes two entry points for triggering workflow runs from external (unprivileged) callers: a legacy envelope path (`HandleLegacyUserMessage`) and a JSON-RPC path (`HandleJSONRPCUserMessage`). The JSON-RPC based v2 HTTP trigger handler enforces authentication, per-workflow-owner authorization, and rate limiting before dispatching to DON nodes. The legacy path, however, explicitly skips these checks — marked by a literal `// TODO: apply allowlist and rate-limiting here` — and immediately fans the request out to every DON member.

This is structurally analogous to the reported bug class: a protocol offers two paths to reach the same privileged outcome (job/workflow execution), one of which enforces the full set of protective checks (auth, rate limits — the "cooldown"/penalty-equivalent gate), while the other allows the same outcome through a faster, unguarded route, letting an unprivileged caller skip the enforcement mechanism entirely.

### Impact Explanation
Any external caller able to reach the legacy message-envelope endpoint (`HandleLegacyUserMessage`) for the `web_api_target`/`web_api_trigger`/`compute_action`/`workflow_syncer` handler can trigger workflow execution across all DON members without passing through any allowlist or rate-limiting check. This can result in unauthorized workflow execution requests and abuse of DON node resources (denial-of-service via unbounded request flooding), since the per-node rate limiter (`nodeRateLimiter`) that exists in this handler is only applied on the *outgoing* (node→client) path (`handleWebAPIOutgoingMessage`), not on the *incoming* legacy trigger path.

### Likelihood Explanation
The vulnerable code path is reachable directly from an unprivileged external actor sending a legacy-format message to the gateway; no special privileges or node compromise are required. The gap is explicitly flagged by the author via the TODO comment, indicating it is a known, still-open enforcement gap rather than a hypothetical scenario.

### Recommendation
Apply the same allowlist and rate-limiting checks used by the v2 JSON-RPC HTTP trigger handler (`authorizeRequest`, `checkRateLimit` in `http_trigger_handler.go`) to `HandleLegacyUserMessage` before request payloads are forwarded to DON members, or deprecate/remove the legacy path if it is no longer required, ensuring all routes into workflow triggering enforce the same authorization/rate-limit gate.

### Proof of Concept
1. Send a legacy-format `api.Message` (not JSON-RPC) targeting `MethodWebAPITrigger` directly to the gateway's legacy message handling entry point.
2. Observe that `HandleLegacyUserMessage` only checks payload decodability and message staleness (`payload.Timestamp`), then immediately loops over `h.donConfig.Members` calling `don.SendToNode` for every member — no call to any authorizer or rate limiter occurs on this path, unlike `httpTriggerHandler.HandleUserTriggerRequest`, which requires `authorizeRequest` and `checkRateLimit` to succeed first. func (h *handler) HandleNodeMessage(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	msg, err := common.ValidatedMessageFromResp(resp)
	if err != nil {
		return err
	}
	if msg.Body.Sender != nodeAddr {
		return errors.New("message sender mismatch when reading from node ")
	}
	start := time.Now()
	switch msg.Body.Method {
	case MethodWebAPITrigger:
		err = h.handleWebAPITriggerMessage(ctx, msg, nodeAddr)
	case MethodWebAPITarget, MethodComputeAction, MethodWorkflowSyncer:
		err = h.handleWebAPIOutgoingMessage(ctx, msg, nodeAddr)
	default:
		err = fmt.Errorf("unsupported method: %s", msg.Body.Method)
	}
	h.metrics.recordHandleDuration(ctx, time.Since(start), msg.Body.Method, err == nil)
	return err
}

	if err != nil {
		return err
	}

	workflowID, err := h.resolveWorkflowID(ctx, triggerReq, req.ID, callback)
	if err != nil {
		return err
	}

	key, err := h.authorizeRequest(ctx, workflowID, req, callback)
	if err != nil {
		return err
	}

	if err = h.checkRateLimit(ctx, workflowID, req.ID, callback); err != nil {
		return err
	}

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}
