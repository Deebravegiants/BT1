### Title
Unauthenticated `/health` endpoint discloses internal service topology and error details to anonymous callers - (File: core/web/router.go, core/web/health_controller.go)

### Summary
The CVE describes an unauthenticated GeoServer REST endpoint (`/geoserver/rest/about/status`) that leaks internal configuration details to anonymous users because the endpoint was left off the security allowlist. The analogous chainlink pattern is `HealthController.Health`, wired up with no authentication middleware at all, which returns per-service health check names and, on failure, raw error strings.

### Finding Description
`healthRoutes` registers `/health` directly on the `api` router group with no auth middleware, unlike the rest of the node API which requires `auth.Authenticate(...)` with token/session/admin checks: [1](#0-0) 

`HealthController.Health` iterates over every registered service's health check and returns its full name and, when unhealthy, the `err.Error()` output string verbatim in the JSON/HTML/plaintext response: [2](#0-1) 

This is architecturally distinct from `PublicReadyz`, which the code explicitly documents as being hardened against this exact leak: it never returns per-check details regardless of query parameters "to avoid leaking internal service state on publicly reachable endpoints." That comment demonstrates the team is aware of and has patched this bug class for one endpoint but not for `/health`: [3](#0-2) 

Test fixtures confirm the disclosed content includes fully-qualified internal service/component identifiers (chain IDs, subsystem names) and diagnostic error text: [4](#0-3) [5](#0-4) 

The bug class match to CVE-2023-28442 is: an anonymous, unauthenticated caller can query a status-style REST endpoint that was not put behind the authentication gate applied to the rest of the API surface, and receive internal configuration/topology/error information back.

### Impact Explanation
An anonymous network client can enumerate exact registered chain IDs, subsystem names (`EVM.<chainID>.HeadTracker.HeadListener`, `Txm.Broadcaster`, `Mercury.WSRPCPool`, etc.), and failure diagnostics for a chainlink node without any credentials. This reveals which chains/subsystems the node operates, its architecture (e.g., whether Mercury, TelemetryManager, WorkflowStore, CRE are enabled), and specific failure conditions (e.g., "Listener connected = false") that could help an attacker time an attack against a degraded node or fingerprint the node's configuration for targeted follow-up attacks. This is information disclosure, not itself a fund-movement or auth-bypass primitive, so severity is bounded relative to the CVE's own "sensitive config" classification.

### Likelihood Explanation
High — the endpoint requires no credentials, no special request crafting, and is reachable by any client that can route to the node's HTTP listener (`GET /health`). No mitigating rate limiting/auth group is applied to this specific route, in contrast to nearly every other route in `router.go` which uses `auth.Authenticate(...)`.

### Recommendation
Apply the same hardening already used for `PublicReadyz` to `/health`: either require authentication (session/token) for the detailed `/health` response, or split it into a minimal public liveness endpoint (status code only) and a separate authenticated endpoint that returns per-check names/errors. At minimum, redact or generalize `err.Error()` output before returning it to unauthenticated callers.

### Proof of Concept
```
curl http://<node-host>:<port>/health
```
No credentials are required; the response includes a JSON array of `checks` with `name`/`status`/`output` fields, as shown by the checked-in fixture `core/web/testdata/body/health-failing.json` and `testdata/scripts/health/multi-chain.txtar`, both reachable from `healthRoutes` in `core/web/router.go` without any `auth.Authenticate` middleware in the call chain.

```go
// PublicReadyz is a minimal readiness endpoint intended for public load balancer health checks.
// Unlike Readyz, it never returns per-check details regardless of query parameters, to avoid
// leaking internal service state on publicly reachable endpoints.
func (hc *HealthController) PublicReadyz(c *gin.Context) {
	ready, _ := hc.App.GetHealthChecker().IsReady()
	if !ready {
		c.Status(http.StatusServiceUnavailable)
		return
	}
	c.Status(http.StatusOK)
}
```

```go
func (hc *HealthController) Health(c *gin.Context) {
	_, failing := c.GetQuery("failing")

	status := http.StatusOK

	checker := hc.App.GetHealthChecker()

	healthy, errors := checker.IsHealthy()

	if !healthy {
		status = http.StatusMultiStatus
	}

	c.Status(status)

	checks := make([]presenters.Check, 0, len(errors))
	for name, err := range errors {
		status := HealthStatusPassing
		var output string

		if err != nil {
			status = HealthStatusFailing
			output = err.Error()
		} else if failing {
			continue // omit from returned data
		}

		checks = append(checks, presenters.Check{
			JAID:   presenters.NewJAID(name),
			Name:   name,
			Status: status,
			Output: output,
		})
	}
```
