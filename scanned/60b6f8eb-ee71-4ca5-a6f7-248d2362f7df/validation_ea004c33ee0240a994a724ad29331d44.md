### Title
Global, attacker-chosen `requestID` key in the HTTP-trigger gateway's callback map lets any authorized workflow owner grief other users' `workflows.execute` requests — ([File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go])

### Summary
The reported Tempus bug is a griefing DoS: an unprivileged attacker pre-populates shared mutable state (yield-share balance) that a later `assert`/uniqueness check relies on, causing a legitimate user's transaction to revert. The `httpTriggerHandler` in the CRE gateway has the same shape: request completion state is tracked in a single global map keyed only by the caller-supplied `requestID` string, with no per-owner/per-workflow namespacing, and a strict "already exists" rejection.

### Finding Description
`httpTriggerHandler.callbacks` is declared as `map[string]savedCallback // requestID -> savedCallback` [1](#0-0) . The only validation applied to the client-supplied `requestID` is that it is non-empty and does not contain `/` — it is otherwise an arbitrary attacker-chosen string, not scoped to a workflow or owner: [2](#0-1) 

`HandleUserTriggerRequest` validates the request, authorizes it against the caller's *own* workflow, checks rate limits, and only then calls `setupCallback(ctx, req.ID, ...)`: [3](#0-2) 

`setupCallback` performs a strict existence check against the *global* `h.callbacks` map and rejects the request outright if the same `requestID` is already in flight — regardless of which workflow or owner reserved it: [4](#0-3) 

Because authorization only requires that the caller own *some* workflow (not the specific `requestID`), any authenticated-but-otherwise-unprivileged workflow owner can submit a `workflows.execute` request using a `requestID` they expect (or guess) another user will use. The entry lives in `h.callbacks` until it's processed or reaped by `cleanupCallback`/the periodic reaper, giving an attacker a window to "occupy" that ID and force the victim's request to be bounced with `jsonrpc.ErrConflict` ("has already been used") — exactly analogous to how the Tempus attacker front-runs the yield-share balance to break `assert(yieldShares.balanceOf(address(this)) == 0)`.

### Impact Explanation
An authenticated but otherwise unprivileged CRE gateway client (any workflow owner able to submit HTTP-trigger requests) can deny service to unrelated users/workflows by pre-claiming a `requestID`, since the uniqueness check is global rather than scoped to the caller's own owner/workflow namespace. This is a griefing/DoS vector against `workflows.execute` calls, not a fund-theft or auth-bypass bug, but it fits the same "unprivileged actor breaks a strict global invariant to grief another user's otherwise-valid request" bug class as the source report.

### Likelihood Explanation
Exploitability depends on the attacker being able to predict or race a victim's chosen `requestID` (e.g., deterministic/idempotency-style IDs, or a race where the attacker submits fractionally earlier). Since IDs are arbitrary strings entirely controlled by callers and are not namespaced per caller, collisions across independent, mutually-untrusting users are structurally possible whenever ID generation is not a high-entropy random value on both sides.

### Recommendation
Scope the `callbacks` map key by `(workflowOwner, workflowID, requestID)` (or equivalent authorized identity) rather than by the raw client-supplied `requestID` alone, so that one user's request cannot collide with, or be blocked by, another user's identically-named `requestID`.

### Proof of Concept
1. Attacker authenticates for their own workflow `W_A` and sends `workflows.execute` with `id = "X"`.
2. `setupCallback` inserts `h.callbacks["X"]` and keeps it until the attacker's execution completes/times out.
3. Victim, unaware of the collision, sends a legitimate `workflows.execute` for workflow `W_B` also using `id = "X"` (e.g. a deterministic idempotency key derived from a shared naming scheme).
4. `setupCallback` finds `h.callbacks["X"]` already present and rejects the victim's request with `jsonrpc.ErrConflict`, denying the legitimate call, mirroring the Tempus front-run-then-assert-fails pattern.

func (h *httpTriggerHandler) HandleUserTriggerRequest(ctx context.Context, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback, requestStartTime time.Time) error {
	triggerReq, err := h.validatedTriggerRequest(ctx, req, callback)
	if err != nil {
		return err
	}

	workflowID, err := h.resolveWorkflowID(ctx, triggerReq, req.ID, callback)
	if err != nil {
		return err
	}

	key, err := h.authorizeRequest(ctx, workflowID, req, callback)
	if err != nil {
		return err
	}

	if err = h.checkRateLimit(ctx, workflowID, req.ID, callback); err != nil {
		return err
	}

	strippedWorkflowID := strings.TrimPrefix(workflowID, "0x")
	legacyExecutionID, err := workflows.EncodeExecutionID(strippedWorkflowID, req.ID) //nolint:staticcheck // legacy ID kept for observability comparison
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInternal, internalErrorMessage, callback)
		return errors.New("error generating execution ID: " + err.Error())
	}
	// Workflows shouldn't use more than one HTTP trigger. If we ever need to support multiple triggers, we'd need to pass
	// trigger index to the Gateway handler and somehow allow senders to pick. For now, we use trigger index 0.
	// Execution IDs here are used only for logging.
	executionIDWithTriggerIndex, err := workflows.GenerateExecutionIDWithTriggerIndex(strippedWorkflowID, req.ID, 0)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInternal, internalErrorMessage, callback)
		return errors.New("error generating execution ID with trigger index: " + err.Error())
	}
	h.lggr.Debugw("processing request",
		"legacyExecutionID", legacyExecutionID,
		"executionIDWithTriggerIndex", executionIDWithTriggerIndex,
		"requestID", req.ID,
		"workflowID", workflowID)

	reqWithKey, err := reqWithAuthorizedKey(triggerReq, *key)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInternal, internalErrorMessage, callback)
		return errors.New("error marshaling trigger request: " + err.Error())
	}

	doneCh, err := h.setupCallback(ctx, req.ID, callback, requestStartTime, workflowID)
	if err != nil {
		return err
	}

	return h.sendWithRetries(ctx, legacyExecutionID, executionIDWithTriggerIndex, reqWithKey, workflowID, doneCh)
}

func (h *httpTriggerHandler) validateRequestID(ctx context.Context, requestID string, callback handlers.Callback) error {
	if requestID == "" {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "'id' field is required and cannot be empty. Use a new unique request 'id' for each request", callback)
		return errors.New("empty request ID")
	}
	// Request IDs from users must not contain "/", since this character is reserved
	// for internal node-to-node message routing (e.g., "http_action/{workflowID}/{uuid}").
	if strings.Contains(requestID, "/") {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "request ID must not contain '/'", callback)
		return errors.New("request ID must not contain '/'")
	}
	return nil
}

func (h *httpTriggerHandler) setupCallback(ctx context.Context, requestID string, callback handlers.Callback, requestStartTime time.Time, workflowID string) (<-chan struct{}, error) {
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()

	if _, found := h.callbacks[requestID]; found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrConflict, fmt.Sprintf("requestID: %s has already been used. Ensure the requestID is unique for each request.", requestID), callback)
		return nil, fmt.Errorf("in-flight request ID: %s", requestID)
	}
