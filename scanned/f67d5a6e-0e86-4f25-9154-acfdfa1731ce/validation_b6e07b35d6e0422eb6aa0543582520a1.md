## Analysis: Decimal Conversion Handling in `pallet-psm`

The external report describes a class of vulnerability: a system that must consistently convert amounts between two different decimal precisions has multiple call sites where the decimal alignment is wrong or inconsistently enforced, leading to incorrect accounting. Searching the repo turned up `pallet-psm`, a Peg Stability Module pallet that was specifically built to handle exactly this problem — converting between an "internal" asset (e.g. pUSD) and "external" stablecoins of arbitrary decimal precision.

Comparing the `mint` and `redeem` extrinsics reveals an inconsistency analogous to the BakerFi bug class: decimals-validity is enforced on one path but not the other.

### Title
Missing live-decimals validation in `redeem` allows stale-decimals accounting drift - (File: `substrate/frame/psm/src/lib.rs`)

### Summary
`pallet-psm::mint` re-validates that an external asset's live on-chain decimals still match the decimals snapshot taken when it was approved, via `Self::ensure_decimals_match`, and aborts with `DecimalsMismatch` otherwise. `redeem` does not perform this check and instead uses the raw `PsmInfo::internal_decimals` / `ExternalAssetInfo::decimals` snapshot values directly for its `internal_to_external` / `external_to_internal` conversions, even if the underlying asset's live decimals have since diverged.

### Finding Description
In `mint`, decimals are validated before any conversion: [1](#0-0) 

`ensure_decimals_match` compares `T::Fungibles::decimals(...)` (the live value) against the snapshot stored in `ExternalAssetInfo`/`PsmInfo` and returns `Error::DecimalsMismatch` on drift: [2](#0-1) 

`redeem`, however, reads the snapshot decimals directly and performs the conversion without calling `ensure_decimals_match`: [3](#0-2) 

Since `redeem` skips this check, if an approved external asset's live decimals metadata (settable by that asset's own owner/admin via the fungibles backend, independent of the PSM's `full_admin`) is changed after approval, `internal_to_external`/`external_to_internal` in `redeem` will scale by the wrong power of ten relative to the asset's actual precision, while `mint` for the same asset would simply halt with `DecimalsMismatch`.

### Impact Explanation
A decimals drift causes `redeem`'s `external_to_internal`/`internal_to_external` scaling factor (`10^|ext_decimals − internal_decimals|`) to be computed against a stale exponent. Depending on the direction of drift, this either:
- Overpays external reserve amounts to redeemers relative to the internal amount burned (`effective_internal_net`), draining the PSM reserve faster than debt is reduced, or
- Underpays redeemers relative to the internal amount actually burned, causing user fund loss.

Because `PsmDebt` and reserve accounting for a whole PSM instance are shared across all its external assets, a miscalibrated redemption path on one external can distort the aggregate solvency invariant (`current_debt >= effective_internal_net`, reserve vs. debt checks) documented as the pallet's core safety property.

### Likelihood Explanation
This requires that: (1) an external asset's decimals metadata is mutable post-approval by an entity other than the PSM's `full_admin` (true for any `pallet-assets`-style asset where the asset owner controls `set_metadata`), and (2) the PSM approves at least one external asset whose metadata isn't under the PSM admin's control — a realistic configuration since PSMs are designed to onboard third-party stablecoins. `mint`'s explicit re-check strongly suggests the pallet authors intended decimals drift to be treated as a live, checkable risk; its absence in `redeem` is most likely an oversight rather than an intentional design choice, making this a genuine asymmetry rather than a theoretical-only issue.

### Recommendation
Call `Self::ensure_decimals_match(&info, &internal_asset, &external_asset, &external)` in `redeem` before performing `internal_to_external`/`external_to_internal`, mirroring `mint`, so that decimal drift halts redemption with `DecimalsMismatch` on both paths symmetrically.

### Proof of Concept
1. PSM admin approves external asset `X` (18 decimals) against internal asset (6 decimals) via `add_external_asset`; snapshot `ExternalAssetInfo.decimals = 18` is stored.
2. `X`'s asset owner later calls the underlying fungibles' metadata-setting call to change `X`'s decimals to, e.g., 6 (a call outside the PSM's control since the PSM admin does not own asset `X`).
3. Any subsequent `mint` call for `X` now fails with `Error::DecimalsMismatch` (correctly halts).
4. A `redeem` call for `X`, however, proceeds using the stale snapshot value `ext_decimals = 18` in `internal_to_external`/`external_to_internal`, computing a scaling factor of `10^12` that no longer reflects `X`'s real 6-decimal precision — resulting in a redemption amount that is off by a factor of `10^12` relative to what the live asset decimals would justify, while still passing the `reserve < external_out` and `current_debt >= effective_internal_net` checks using the same skewed numbers. [4](#0-3)

		pub(crate) fn internal_to_external(
			amount: BalanceOf<T>,
			ext_decimals: u8,
			internal_decimals: u8,
		) -> Result<BalanceOf<T>, Error<T>> {
			use core::cmp::Ordering::*;
			match ext_decimals.cmp(&internal_decimals) {
				Equal => Ok(amount),
				Less => {
					let diff = (internal_decimals - ext_decimals) as u32;
					let factor = Self::pow10(diff)?;
					Ok(amount.checked_div(&factor).unwrap_or_else(BalanceOf::<T>::zero))
				},
				Greater => {
					let diff = (ext_decimals - internal_decimals) as u32;
					let factor = Self::pow10(diff)?;
					amount.checked_mul(&factor).ok_or(Error::<T>::ConversionOverflow)
				},
			}
		}

		pub(crate) fn ensure_decimals_match(
			info: &PsmInfo<T>,
			internal_asset: &T::AssetId,
			external_asset: &T::AssetId,
			external: &ExternalAssetInfo,
		) -> Result<(u8, u8), DispatchError> {
			ensure!(
				T::Fungibles::decimals(external_asset.clone()) == external.decimals,
				Error::<T>::DecimalsMismatch
			);
			ensure!(
				T::Fungibles::decimals(internal_asset.clone()) == info.internal_decimals,
				Error::<T>::DecimalsMismatch
			);
			Ok((external.decimals, info.internal_decimals))
		}
