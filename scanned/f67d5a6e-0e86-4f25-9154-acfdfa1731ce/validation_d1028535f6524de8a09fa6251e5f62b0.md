## Finding [1](#0-0) 

### Title
UMP delivery fee computed on pre-`wrap_version` XCM instead of the actually-queued encoded bytes - (File: cumulus/primitives/utility/src/lib.rs)

### Summary
`ParentAsUmp::validate` computes the delivery price with `P::price_for_delivery((), &xcm)` on the latest-version `Xcm<()>` *before* calling `W::wrap_version(&d, xcm)`, but the bytes that are actually queued into UMP (`data = versioned_xcm.encode()`) are taken *after* the version conversion. If `wrap_version` converts the message into an older/verbose wire format that is larger than the latest-version encoding, the attacker pays for a smaller message than what is actually placed in the UMP queue.

### Finding Description
In `cumulus/primitives/utility/src/lib.rs`, `ParentAsUmp::validate`:
```
let price = P::price_for_delivery((), &xcm);                       // priced on latest-version Xcm<()>
let versioned_xcm = W::wrap_version(&d, xcm)...;                    // may downgrade to an older wire version
...
let data = versioned_xcm.encode();                                  // actual bytes queued into UMP
``` [2](#0-1) 

`P` is typically `ExponentialPrice`, whose `price_for_delivery` charges `B::get() + msg.encoded_size() * M::get()`, using `msg.encoded_size()` on the pre-wrap `Xcm<()>` value, not on the final `data.len()`: [3](#0-2) 

`W::wrap_version` (implemented by `pallet_xcm::Pallet<T>`) chooses the version to encode into based on `SupportedVersion` for the destination (or `SafeXcmVersion` as a fallback when unknown), capped at `XCM_VERSION`: [4](#0-3) 
This means the destination (the relay chain, `Parent`) can be assigned an older XCM version than the runtime's current `XCM_VERSION` — either because it was never discovered/subscribed (fallback to `SafeXcmVersion`) or because it has an explicitly recorded older `force_xcm_version`. When `into_version()` converts the latest-version `Xcm<()>` down into that older wire format, the byte-for-byte encoding can differ (grow or shrink) from the latest-version encoding, because instruction/asset encodings differ across XCM versions.

The identical ordering bug exists in `ChildParachainRouter::validate` (DMP path) in `polkadot/runtime/common/src/xcm_sender.rs`, which also computes `price` before `wrap_version`: [5](#0-4) 

The reachable path for an unprivileged user is `pallet_xcm::send` (dispatched via `SendController::send`, which internally calls the configured `XcmRouter`, of which `ParentAsUmp` is a component for `Parent` destinations): [6](#0-5) 

No check in the existing code re-derives or re-validates the fee against the post-wrap `data.len()`; the only post-wrap checks are `check_is_decodable()` (decode-depth) and `T::can_send_upward_message` (max-size), neither of which affects the fee amount already fixed by `price`.

### Impact Explanation
This is a fee/byte-accounting asymmetry: the sending parachain's UMP delivery fee (an on-chain economic cost, ultimately reflected via the relay chain's or the parachain's fee-factor/exponential pricing model) is computed from a byte count that does not match the actual bytes enqueued for delivery. In an environment where `wrap_version` converts to an older/larger wire encoding (e.g. destination pinned or defaulted to an older version than local `XCM_VERSION`), an attacker constructing a message that is compact in the latest version but bulkier in the wrapped version pays less than the true UMP byte cost. This matches the scoped impact: underpriced UMP delivery / fee accounting asymmetry, without any other privilege beyond a normal signed call to `pallet_xcm::send`.

### Likelihood Explanation
Preconditions: (1) a signed account permitted by `SendXcmOrigin`/`LocalOriginToLocation` to call `pallet_xcm::send` targeting `Parent` (this is enabled on system parachains such as Asset Hub, which allow local signed origins to send arbitrary XCM to `Parent` via `SignedToAccountId32`), and (2) the destination (`Parent`) resolves to a wire version older than the runtime's current `XCM_VERSION` via `SupportedVersion`/`SafeXcmVersion` fallback — a state that is plausible whenever version discovery/negotiation hasn't happened yet or was pinned to an older version. Given these, the exploit is fully deterministic and repeatable each time `send` is called with a crafted message, so likelihood is Medium: it depends on the destination's negotiated/default XCM version being behind the sender's current version, which is a common transient (or intentionally pinned) state rather than a rare edge case.

### Recommendation
Compute `price_for_delivery` on the actually-delivered, post-`wrap_version` encoded bytes (`data.len()` / `versioned_xcm.encoded_size()`) rather than on the pre-wrap `Xcm<()>`. Apply the same fix symmetrically to `ChildParachainRouter::validate` in `polkadot/runtime/common/src/xcm_sender.rs`.

### Proof of Concept
Add a test in `cumulus/primitives/utility/src/lib.rs`'s `test_xcm_router` module:
1. Implement a `WrapVersion` stub that converts an input `Xcm<()>` into an intentionally larger `VersionedXcm` (e.g. wraps into `VersionedXcm::V3` while injecting extra padding/metadata) to simulate version-conversion inflation, mirroring `TestUsesOnlyStoredVersionWrapper` in `polkadot/runtime/parachains/src/mock.rs`.
2. Call `<ParentAsUmp<CanSendUpwardMessageSender, StubWrapVersion, SomePriceForMessageDelivery> as SendXcm>::validate(...)` with a compact `Xcm<()>`.
3. Assert that `price` returned equals `SomePriceForMessageDelivery::price_for_delivery((), &pre_wrap_xcm)` (current behavior) while `versioned_xcm.encode().len()` (the actually delivered bytes) is strictly larger — proving the fee under-counts the real UMP payload size.
4. Expected outcome after fix: `price` should be derived from `versioned_xcm.encode().len()`, matching the queued bytes exactly.

impl<T: Config> WrapVersion for Pallet<T> {
	fn wrap_version<RuntimeCall: Decode + GetDispatchInfo>(
		dest: &Location,
		xcm: impl Into<VersionedXcm<RuntimeCall>>,
	) -> Result<VersionedXcm<RuntimeCall>, ()> {
		Self::get_version_for(dest)
			.or_else(|| {
				Self::note_unknown_version(dest);
				SafeXcmVersion::<T>::get()
			})
			.ok_or_else(|| {
				tracing::trace!(
					target: "xcm::pallet_xcm::wrap_version",
					?dest, "Could not determine a version to wrap XCM for destination",
				);
				()
			})
			.and_then(|v| xcm.into().into_version(v.min(XCM_VERSION)))
	}
