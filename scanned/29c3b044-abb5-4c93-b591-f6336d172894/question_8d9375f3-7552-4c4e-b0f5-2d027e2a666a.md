Target: `IntentSignerNEP413.signIntent` setting `recipient: intent.verifying_contract` inside the NEP-413 payload, versus `IntentPayloadBuilder.setVerifyingContract`. Attacker input: none from outside; the vulnerability is that `setVerifyingContract` is a public builder method 'to be used with caution' that any code path (including one fed by attacker-controlled `routeConfig` or integration glue code forwarding a bridge-specific contract override) can call with an arbitrary string, and `signIntent` blindly copies it into the signed NEP-413 `recipient` field. Preconditions: a caller (or code driven by attacker-supplied `routeConfig`/env override) calls `sdk.intentBuilder().setVerifyingContract(attackerSuppliedContract).addIntent(...).buildAndSign(nep413Signer)`. Call sequence: `IntentPayloadBuilder.buildWithSalt` sets `verifying_contract = this.verifyingContract` (attacker value) and the resulting payload is passed unmodified into `IntentSignerNEP413.signIntent`, which sets NEP-413 `recipient = intent.verifying_contract` and hashes/signs via `hashNEP413Message`; the wallet then produces a valid signature over a message whose `recipient` is the attacker-chosen contract, not necessarily `envConfig.contractID`. Equality broken: SIGNED == BUILT holds locally, but the deeper identity — the (nonce, verifying_contract) pair binds the signature to exactly one contract the caller intended — fails, since nothing in `signIntent` cross-checks `intent.verifying_contract` against the SDK's `envConfig.contractID` before signing. Impact: Critical — a valid NEP-413 signature is produced whose `recipient`/verifying contract differs from the intents contract the user believes they're authorizing, letting funds be routed to/executed by an unintended contract with no recovery. Proof idea: vitest test calling `intentBuilder().setVerifyingContract('malicious.near')` then `buildAndSign(nep413Signer)` and asserting the returned `MultiPayloadNep413.payload.recipient === 'malicious.near'` while `sdk`'s own `envConfig.contractID` is a different value, with no thrown error from `signIntent` or `IntentExecuter`.
