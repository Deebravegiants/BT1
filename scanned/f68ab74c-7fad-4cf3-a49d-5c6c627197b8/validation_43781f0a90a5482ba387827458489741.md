## Title
Unauthorized Disclosure of External Initiator `outgoingToken` Secret to Any Authenticated User (Including View-Only Role) - (File: `core/web/external_initiators_controller.go`)

### Summary
`GET /v2/external_initiators` is registered without any role-gating middleware, unlike its sibling `Create`/`Destroy` routes on the same resource. Any authenticated user — including one with the lowest `view` role — can list all configured external initiators, and the response includes the `outgoingToken` field, which is a secret credential the node uses to authenticate itself when calling out to that initiator's URL. This mirrors the reported Rocket.Chat pattern: an endpoint that discloses a sensitive credential field (`client_secret`/`outgoingToken`) to any authenticated caller regardless of role, as long as they can hit the endpoint (here, no per-record secret is even needed — the full list is returned).

### Finding Description
The route table wires `Index` with no role check while `Create` and `Destroy` are explicitly wrapped with `auth.RequiresEditRole`: [1](#0-0) 

`ExternalInitiatorsController.Index` fetches all external initiators from the ORM and maps each into `presenters.ExternalInitiatorResource` with no redaction: [2](#0-1) 

The presenter includes `OutgoingToken` in the returned JSON payload: [3](#0-2) 

`OutgoingToken` is a secret generated at creation time (`utils.NewSecret(utils.DefaultSecretSize)`), stored alongside `OutgoingSecret`, and used by the node to authenticate itself to the initiator's webhook endpoint: [4](#0-3) 

The regression test suite explicitly documents `/v2/external_initiators` GET as allowed for `viewOnlyAllowed: true`, i.e. reachable by the lowest-privilege role: [5](#0-4) 

This is analogous to the reported bug class: an authenticated-but-unprivileged actor can read a sensitive credential field through a GET endpoint that lacks the same role check applied to mutating operations on the same resource (`Create`/`Destroy` require `RequiresEditRole`, but `Index` does not).

### Impact Explanation
Any authenticated node user, regardless of assigned role (even `view`, the most restricted role, intended for read-only dashboards), can enumerate every external initiator record and obtain its `outgoingToken`. If that token is used by the receiving external initiator service to trust webhook calls purportedly coming from this Chainlink node, disclosure allows a low-privileged internal user to impersonate the node toward that external service, or otherwise misuse credentials they were not meant to hold. This is a broken-access-control / secret-disclosure issue consistent with CWE-284/CWE-200.

### Likelihood Explanation
High for any environment where operators provision `view`-role API users for read-only dashboards/monitoring alongside `admin`/`edit` users — a common practice. No special conditions are required beyond having any valid authenticated session or API token; the endpoint is reachable directly at `GET /v2/external_initiators`.

### Recommendation
Gate `GET /v2/external_initiators` with at least `auth.RequiresEditRole` (matching `Create`/`Destroy`), or, if broader read access is intentional, redact `OutgoingToken`/`OutgoingSecret` from `ExternalInitiatorResource` for non-privileged roles the same way `IncomingToken` is deliberately withheld from `BridgeResource` except at creation time (`resource.IncomingToken = bta.IncomingToken` is set explicitly only in `BridgeTypesController.Create`, not in `Index`/`Show`, per `core/web/bridge_types_controller.go` lines 98-99 and 111-146 — the external initiator presenter should follow the same redaction pattern).

### Proof of Concept
1. Provision a Chainlink node API user with role `view` (or obtain a session/token for an existing low-privilege account).
2. As that user, issue: `GET /v2/external_initiators`.
3. Observe the JSON:API response contains `outgoingToken` (and `accessKey`) for every configured external initiator, despite the user lacking `edit`/`admin` privileges — confirmed by the route being unwrapped by any `Requires*Role` middleware in `core/web/router.go` (line 264) and by the presenter unconditionally serializing `OutgoingToken` (`core/web/presenters/external_initiators.go` lines 57-65).

func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}

// NewExternalInitiator generates an ExternalInitiator from an
// auth.Token, hashing the password for storage
func NewExternalInitiator(
	eia *auth.Token,
	eir *ExternalInitiatorRequest,
) (*ExternalInitiator, error) {
	salt := utils.NewSecret(utils.DefaultSecretSize)
	hashedSecret, err := auth.HashedSecret(eia, salt)
	if err != nil {
		return nil, pkgerrors.Wrap(err, "error hashing secret for external initiator")
	}

	return &ExternalInitiator{
		Name:           strings.ToLower(eir.Name),
		URL:            eir.URL,
		AccessKey:      eia.AccessKey,
		HashedSecret:   hashedSecret,
		Salt:           salt,
		OutgoingToken:  utils.NewSecret(utils.DefaultSecretSize),
		OutgoingSecret: utils.NewSecret(utils.DefaultSecretSize),
	}, nil
}
