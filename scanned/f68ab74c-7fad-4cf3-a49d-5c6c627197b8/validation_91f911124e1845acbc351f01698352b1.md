### Title
Stale cached role in LDAP/OIDC session and API-token tables allows continued privileged access after upstream role revocation - (File: core/sessions/ldapauth/ldap.go, core/sessions/oidcauth/oidc.go, core/sessions/ldapauth/sync.go)

### Summary
This is analogous to the FootiumEscrow bug class: a previously granted delegated authorization (the club owner's token approval) is not revoked when the underlying source of authority (NFT ownership) changes, so the stale grant remains exploitable until someone notices. In chainlink's LDAP/OIDC auth drivers, a user's role/membership is cached locally in `ldap_sessions`, `ldap_user_api_tokens`, `oidc_sessions`, and `oidc_user_api_tokens` at login/token-creation time, and is only reconciled with the upstream identity provider on a periodic sync (`UpstreamSyncInterval`), not on every authenticated request.

### Finding Description
`AuthenticateByToken` and `AuthenticateBySession` (`core/web/auth/auth.go`) call `FindUserByAPIToken` / `AuthorizedUserWithSession` on the configured `Authenticator`, trusting whatever role is returned to set `SessionUserKey` for RBAC decisions: [1](#0-0) 

For the LDAP driver, `FindUserByAPIToken` reads the role directly from the locally cached `ldap_user_api_tokens` row rather than querying LDAP live: [2](#0-1) 

Similarly, `AuthorizedUserWithSession` reads the cached role from `ldap_sessions`: [3](#0-2) 

The OIDC driver behaves the same way for both API tokens and sessions: [4](#0-3) [5](#0-4) 

Reconciliation with the upstream "source of truth" (analogous to Club NFT ownership in the report) only happens via `LDAPServerStateSyncer.Work`, which runs on a timer defined by `UpstreamSyncInterval`, updating or purging cached role/session rows: [6](#0-5) [7](#0-6) 

By contrast, the local (non-LDAP/OIDC) auth provider correctly re-derives the role live from the `users` table on every token lookup, so a role change via `UpdateRole` takes effect immediately even though it doesn't proactively revoke the token itself: [8](#0-7) [9](#0-8) 

The LDAP/OIDC drivers do not have this live-lookup property — the cached role is authoritative between sync cycles.

### Impact Explanation
If an admin/operator downgrades or removes a user's privileged group membership upstream (e.g., removing them from the LDAP "admin" group after they leave a team or are found to be compromised), that user's existing local session cookie or previously issued API token continues to authenticate with the old, now-revoked role until the next `UpstreamSyncInterval` tick. During that window, the "de-authorized" holder retains whatever privileged actions their cached role allowed (job management, key management, other user management, etc.) — mirroring the escrow case where the prior NFT owner retains fund-moving capability after losing ownership.

### Likelihood Explanation
Exploitability depends entirely on the configured `UpstreamSyncInterval`; if set to a large value (or the instant/manual sync path is only invoked at node startup per `Start`), the exposure window can be long. This requires that LDAP or OIDC auth be enabled (not the default local auth) and that an admin already revoked/relies on periodic sync rather than issuing an explicit local purge, so it is a real but conditionally-triggered gap rather than a directly attacker-controlled bypass.

### Recommendation
For LDAP/OIDC drivers, avoid caching role as authoritative for the full sync interval: either re-validate role against upstream (or a short-TTL cache) on each authenticated request, or expose/require an explicit "force sync" hook invoked whenever an admin performs a group/role change action, and reduce reliance on the fixed periodic ticker for security-sensitive downgrades. At minimum, document that `UpstreamSyncInterval` directly bounds the propagation delay of privilege revocation, matching the guidance FootiumEscrow received to not let a stale grant persist beyond the point where the underlying authority changed.

### Proof of Concept
1. Configure chainlink node with LDAP auth (`UpstreamSyncInterval` set to e.g. 24h) and log in as `userA`, who is a member of the upstream admin group, obtaining a session (or API token via `CreateAndSetAuthToken`/`SetAuthToken`), cached with `UserRoleAdmin` in `ldap_sessions` / `ldap_user_api_tokens`. [10](#0-9) 
2. Administrator removes `userA` from the admin group in the upstream LDAP directory.
3. Before the next `LDAPServerStateSyncer.Work` tick (bounded by `UpstreamSyncInterval`), `userA` continues to hit admin-gated endpoints using the existing session ID or API token; `AuthorizedUserWithSession`/`FindUserByAPIToken` return the stale cached `UserRoleAdmin`, and `AuthenticateBySession`/`AuthenticateByToken` in `core/web/auth/auth.go` accept it, granting continued admin access. [11](#0-10)

// FindUserByAPIToken retrieves a possible stored user and role from the ldap_user_api_tokens table store
func (l *ldapAuthenticator) FindUserByAPIToken(ctx context.Context, apiToken string) (sessions.User, error) {
	if !l.config.UserApiTokenEnabled() {
		return sessions.User{}, errors.New("API token is not enabled ")
	}

	// Query the ldap user API token table for given token, user role and email are cached so
	// no further upstream LDAP query is performed, sessions and tokens are synced against the upstream server
	// via the UpstreamSyncInterval config and reaper.go sync implementation
	var foundUserToken struct {
		UserEmail string
		UserRole  sessions.UserRole
		Valid     bool
	}
	err := l.ds.GetContext(ctx, &foundUserToken,
		"SELECT user_email, user_role, created_at + $2 >= now() as valid FROM ldap_user_api_tokens WHERE token_key = $1",
		apiToken, l.config.UserAPITokenDuration().Duration(),
	)
	if err != nil {
		return sessions.User{}, err
	}
	if !foundUserToken.Valid { // API Token expired, purge
		if _, execErr := l.ds.ExecContext(ctx, "DELETE FROM ldap_user_api_tokens WHERE token_key = $1", apiToken); execErr != nil {
			l.lggr.Errorf("error purging stale ldap API token session: %v", execErr)
		}
		return sessions.User{}, sessions.ErrUserSessionExpired
	}

	return sessions.User{
		Email: foundUserToken.UserEmail,
		Role:  foundUserToken.UserRole,
	}, nil
}

// SetAuthToken updates the user to use the given Authentication Token.
func (l *ldapAuthenticator) SetAuthToken(ctx context.Context, user *sessions.User, token *auth.Token) error {
	if !l.config.UserApiTokenEnabled() {
		return errors.New("API token is not enabled ")
	}

	salt := utils.NewSecret(utils.DefaultSecretSize)
	hashedSecret, err := auth.HashedSecret(token, salt)
	if err != nil {
		return fmt.Errorf("LDAPAuth SetAuthToken hashed secret error: %w", err)
	}

	err = sqlutil.TransactDataSource(ctx, l.ds, nil, func(tx sqlutil.DataSource) error {
		// Is this user a local CLI Admin or upstream LDAP user?
		// Check presence in local users table. Set localauth_user column true if present.
		// This flag omits the session/token from being purged by the sync daemon/reaper.go
		isLocalCLIAdmin := false
		err = l.ds.QueryRowxContext(ctx, "SELECT EXISTS (SELECT 1 FROM users WHERE email = $1)", user.Email).Scan(&isLocalCLIAdmin)
		if err != nil {
			return fmt.Errorf("error checking user presence in users table: %w", err)
		}

		// Remove any existing API tokens
		if _, err = l.ds.ExecContext(ctx, "DELETE FROM ldap_user_api_tokens WHERE user_email = $1", user.Email); err != nil {
			return fmt.Errorf("error executing DELETE FROM ldap_user_api_tokens: %w", err)
		}
		// Create new API token for user
		_, err = l.ds.ExecContext(
			ctx,
			"INSERT INTO ldap_user_api_tokens (user_email, user_role, localauth_user, token_key, token_salt, token_hashed_secret, created_at) VALUES ($1, $2, $3, $4, $5, $6, now())",
			user.Email,
			user.Role,
			isLocalCLIAdmin,
			token.AccessKey,
			salt,
			hashedSecret,
		)
		if err != nil {
			return fmt.Errorf("failed insert into ldap_user_api_tokens: %w", err)
		}
		return nil
	})
	if err != nil {
		return errors.New("error creating API token")
	}

	l.auditLogger.Audit(audit.APITokenCreated, map[string]any{"user": user.Email})
	return nil
}

func (l *LDAPServerStateSyncer) Start(ctx context.Context) error {
	// If enabled, start a background task that calls the Sync/Work function on an
	// interval without needing an auth event to trigger it
	// Use IsInstant to check 0 value to omit functionality.
	if !l.config.UpstreamSyncInterval().IsInstant() {
		l.lggr.Info("LDAP Config UpstreamSyncInterval is non-zero, sync functionality will be called on a timer, respecting the UpstreamSyncRateLimit value")
		go l.run()
	} else {
		// Ensure upstream server state is synced on startup manually if interval check not set
		l.Work(ctx)
	}
	return nil
}

func (l *LDAPServerStateSyncer) Close() error {
	close(l.stopCh)
	<-l.done
	return nil
}

func (l *LDAPServerStateSyncer) run() {
	defer close(l.done)
	ctx, cancel := l.stopCh.NewCtx()
	defer cancel()
	ticker := time.NewTicker(l.config.UpstreamSyncInterval().Duration())
	defer ticker.Stop()

	for {
		select {
		case <-ctx.Done():
			return
		case <-ticker.C:
			l.Work(ctx)
		}
	}
}

// UpdateRole overwrites role field of the user specified by email.
func (o *orm) UpdateRole(ctx context.Context, email, newRole string) (sessions.User, error) {
	var userToEdit sessions.User

	if newRole == "" {
		return userToEdit, pkgerrors.New("user role must be specified")
	}

	err := sqlutil.TransactDataSource(ctx, o.ds, nil, func(tx sqlutil.DataSource) error {
		// First, attempt to load specified user by email
		if err := tx.GetContext(ctx, &userToEdit, "SELECT * FROM users WHERE lower(email) = lower($1)", email); err != nil {
			return pkgerrors.New("no matching user for provided email")
		}

		// Patch validated role
		userRole, err := sessions.GetUserRole(newRole)
		if err != nil {
			return err
		}
		userToEdit.Role = userRole

		_, err = tx.ExecContext(ctx, "DELETE FROM sessions WHERE email = lower($1)", email)
		if err != nil {
			o.lggr.Errorw("Failed to purge user sessions for UpdateRole", "err", err)
			return pkgerrors.New("error updating API user")
		}

		sql := "UPDATE users SET role = $1, updated_at = now() WHERE lower(email) = lower($2) RETURNING *"
		if err := tx.GetContext(ctx, &userToEdit, sql, userToEdit.Role, email); err != nil {
			o.lggr.Errorw("Error updating API user", "err", err)
			return pkgerrors.New("error updating API user")
		}

		return nil
	})

	return userToEdit, err
}
