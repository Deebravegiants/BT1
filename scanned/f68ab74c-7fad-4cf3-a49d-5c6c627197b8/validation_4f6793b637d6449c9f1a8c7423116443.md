Unauthenticated task resumption allows any unprivileged client to inject arbitrary results into async pipeline runs (bridge/async task response impersonation) - (File: core/web/pipeline_runs_controller.go)

### Summary
`PATCH /v2/resume/:runID` is intentionally mounted in the **unauthenticated** router group and forwards any request body directly into `ResumeJobV2`/`pipelineRunner.ResumeRun`, which finalizes the pending async task keyed only by a `taskID` UUID. Anyone who can guess or observe a pending task's UUID can post a completion result for it with no authentication, no ownership check, and no verification that the caller is the bridge/external adapter that was actually asked to compute that value — mirroring the "unclear semantics" bug class in the report, where an event/action is emitted on behalf of an actor who never actually performed it.

### Finding Description
The route is registered without any auth middleware: [1](#0-0) 

The handler decodes an arbitrary JSON body into a `pipeline.ResumeRequest`, converts it to a `Result`, and calls `App.ResumeJobV2` using only the `runID` path parameter (a `taskID` UUID) — there is no session/token/external-initiator check, and no validation that the caller corresponds to the awaited async task (e.g., the bridge or adapter that the pipeline is waiting on): [2](#0-1) 

This flows straight into the pipeline runner, which updates the task's stored result and, if all pending tasks are now resolved, restarts the run with whatever value/error was supplied: [3](#0-2) [4](#0-3) 

The `taskID` is a `uuid.UUID` with no per-run secret/nonce validation tied to it, so the only "authentication" for completing an async task is knowledge of the UUID. The audit log even records this action under a dedicated `UnauthedRunResumed` event, acknowledging that this specific endpoint operates without authentication: [5](#0-4) 

This is the same class of problem the report describes for `Transfer`: an action/record is attributed to (or accepted as coming from) an actor without verifying it's actually that actor — here, task completion is accepted from any unauthenticated caller, effectively letting an unprivileged party impersonate the async bridge/adapter that was supposed to supply the result and inject its own value/error into the job run pipeline.

### Impact Explanation
If an attacker discovers or brute-forces a pending `taskID` (UUIDs are not typically treated as high-entropy secrets exposed to untrusted parties, and may leak via logs, monitoring, or timing), they can:
- Force a stuck/async pipeline task to resolve with attacker-chosen data or an attacker-chosen error, corrupting the on-chain report/job output that downstream OCR/other consumers rely on.
- Repeatedly hit the endpoint to disrupt legitimate job runs (denial of service) or to race the legitimate adapter's real callback.

This directly corresponds to "unauthorized job run" / "request impersonation" in the accepted vulnerability classes.

### Likelihood Explanation
Exploitation requires knowledge of the `runID`/`taskID` UUID for a currently pending async task. This is a real constraint, but the ID space here is not protected by any additional secret or per-request signature — it's a bare path parameter on a fully unauthenticated route. Any information leak of task IDs (e.g., through logs, error messages, or predictable creation ordering in externally-visible systems) makes this directly exploitable, and the code explicitly tags this endpoint as "unauthed" in its own audit trail, indicating this is a known, accepted design gap rather than a hardened boundary.

### Recommendation
- Require the resuming caller to present a credential established at task-creation time (e.g., a per-task secret/HMAC token returned only to the bridge/adapter that owns the async callback), not just the `taskID`.
- Alternatively, gate `/v2/resume/:runID` behind the same external-initiator/API-token authentication used elsewhere, and bind the credential's identity to the specific bridge task it is permitted to resolve.
- At minimum, rate-limit and monitor this endpoint, and ensure `taskID` values are never leaked in logs/URLs accessible to untrusted parties.

### Proof of Concept
1. Discover or predict a pending task's UUID (`runID`) for an async bridge/adapter task (e.g., via log exposure, timing, or observing job run metadata through another unauthenticated/low-privilege channel).
2. Send: `PATCH /v2/resume/<taskID>` with body `{"error": null, "data": {"result": "<attacker-controlled value>"}}` with no auth headers at all.
3. Observe: `ResumeJobV2` → `pipelineRunner.ResumeRun` accepts the value, marks the task run finished, and restarts/completes the pipeline run using the attacker-supplied result — with no verification the caller is the bridge/adapter chainlink was actually waiting on. [6](#0-5) [2](#0-1)

func (prc *PipelineRunsController) Resume(c *gin.Context) {
	taskID, err := uuid.Parse(c.Param("runID"))
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	rr := pipeline.ResumeRequest{}
	decoder := json.NewDecoder(c.Request.Body)
	err = errors.Wrap(decoder.Decode(&rr), "failed to unmarshal JSON body")
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	result, err := rr.ToResult()
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	if err := prc.App.ResumeJobV2(c.Request.Context(), taskID, result); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
	c.Status(http.StatusOK)
}

func (r *runner) ResumeRun(ctx context.Context, taskID uuid.UUID, value any, err error) error {
	run, start, err := r.orm.UpdateTaskRunResult(ctx, taskID, Result{
		Value: value,
		Error: err,
	})
	if err != nil {
		return fmt.Errorf("failed to update task run result: %w", err)
	}

	// TODO: Should probably replace this with a listener to update events
	// which allows to pass in a transactionalised database to this function
	if start {
		// start the runner again
		go func() {
			ctx, cancel := r.chStop.NewCtx()
			defer cancel()
			if _, err := r.Run(ctx, &run, false, nil); err != nil {
				r.lggr.Errorw("Resume run failure", "err", err)
			}
			r.lggr.Debug("Resume run success")
		}()
	}
	return nil
}
