## Title
Unbounded, Unauthenticated Growth of the Vault Gateway `activeRequests` Map via `vault.publicKey_get` Flooding — (File: `core/services/gateway/handlers/vault/handler.go`)

### Summary
The gateway-side Vault handler exempts the `vault.publicKey_get` JSON-RPC method from any authentication/authorization check and, whenever the public-key cache is empty, stores every such request in an in-memory map (`h.activeRequests`) keyed by the attacker-controlled `req.ID`. Unlike the sibling `common.RequestCache` abstraction used elsewhere in the gateway package (which enforces an explicit `maxCacheSize`), this map has **no maximum-size check** — the only bound on growth is a periodic time-based prune loop. An unauthenticated client can flood this endpoint with unique request IDs faster than the prune loop reclaims them, causing unbounded heap growth analogous to the SignalK `requests = {}` DoS pattern.

### Finding Description
`HandleJSONRPCUserMessage` explicitly documents and implements a bypass of authorization for `MethodPublicKeyGet`: [1](#0-0) 

When `getCachedPublicKey()` returns `nil` (e.g. before the first successful key fetch, or whenever the node-side vault fails to answer and the cache never warms up), every incoming request — regardless of client identity — is inserted into `h.activeRequests` via `newActiveRequest`: [2](#0-1) 

The only guard in `newActiveRequest` is a duplicate-ID check (`if h.activeRequests[req.ID] != nil`), not a size cap. Since `req.ID` is fully attacker-controlled (bounded only to ≤200 chars, checked earlier in `HandleJSONRPCUserMessage`), an attacker can trivially generate unlimited unique IDs and insert unlimited entries. [3](#0-2) 

Reclamation only happens via a background ticker that fires every `defaultCleanUpPeriod` (5 seconds) and removes entries older than `h.requestTimeout` (defaults to 30 seconds when unset): [4](#0-3) [5](#0-4) 

This is structurally the same bug class as the SignalK advisory: an unauthenticated, internet-facing endpoint accepts and stores arbitrary client-supplied requests in an unbounded in-memory structure, with only infrequent, time-based (not size-based) pruning as a backstop. Contrast this with `core/services/gateway/handlers/common/requestcache.go`, which enforces `maxCacheSize` and rejects new entries once full: [6](#0-5) 

The vault handler's `activeRequests` map has no equivalent check. There is also no per-client rate limiter applied to this code path — `h.nodeRateLimiter` in this handler only throttles node→gateway responses in `HandleNodeMessage`, not the initial user-initiated `publicKey_get` request.

### Impact Explanation
While the per-entry object is small (a `jsonrpc.Request`, an empty responses map, and a callback), an unauthenticated attacker who can sustain a request rate exceeding what the 5-second/30-second prune window can reclaim can grow `h.activeRequests` without bound, consuming gateway memory and eventually degrading or crashing the gateway process (heap exhaustion / GC pressure), denying service to legitimate DON participants and workflow owners relying on the same gateway instance. This satisfies the "unauthorized/no-cost resource exhaustion via unbounded per-request memory allocation" class described in the source advisory, reachable from an unprivileged client request with no authentication required (explicitly by design for this method).

### Likelihood Explanation
High reachability: `vault.publicKey_get` is intentionally unauthenticated ("Public key requests don't require authorization... we cache this value quite aggressively so don't need to worry about DoS" — a design assumption that only holds once the cache is warm). Any window where the cache is empty (startup, node unavailability, cache TTL expiry) restores the unbounded-insertion path, and there is no per-client throttle preventing an attacker from exploiting that window repeatedly or from being the reason the cache never successfully populates (e.g., DoS on the fetch itself competes with normal fetches for the same map).

### Recommendation
- Add a `maxActiveRequests` (or reuse the `common.RequestCache` pattern with `maxCacheSize`) bound to `h.activeRequests` in `core/services/gateway/handlers/vault/handler.go`, rejecting/limiting new entries once the cap is reached.
- Apply a per-IP/per-connection rate limiter to the unauthenticated `publicKey_get` path specifically, since it bypasses `requestProcessor.ProcessRequest`'s authorization gate.
- Reduce reliance on a purely time-based prune loop for unauthenticated paths; prefer eviction/limiting at insertion time.

### Proof of Concept
1. Start (or wait for) a state where the vault gateway's public key cache is empty (`getCachedPublicKey()` returns `nil`), e.g. at process startup before the first successful `fetchVaultPublicKey` completes, or during sustained node unavailability.
2. Send a high-rate flood of JSON-RPC requests to the gateway's public HTTP endpoint with `method: "vault.publicKey_get"` and a unique `id` (≤200 chars) per request, with no `Auth` header/field.
3. Each request enters `HandleJSONRPCUserMessage` → `newActiveRequest`, inserting a new unbounded entry into `h.activeRequests` keyed by the unique `id`, with no authorization check and no cap on total map size.
4. Sustain the flood at a rate exceeding the 5-second prune tick's ability to expire entries (default `requestTimeout` 30s), causing `h.activeRequests` to grow unbounded and gateway memory to climb, mirroring the reported SignalK OOM/DoS pattern.

	return h.StartOnce("VaultHandler", func() error {
		h.lggr.Debug("starting vault handler")

			if err := h.jwtAuth.Start(context.Background()); err != nil {
				return fmt.Errorf("failed to start JWTBasedAuth: %w", err)
			}
		}
		go func() {
			ctx, cancel := h.stopCh.NewCtx()
			defer cancel()
			ticker := h.clock.NewTicker(defaultCleanUpPeriod)
			tickerVaultPublicKeyRefresh := h.clock.NewTicker(1 * time.Minute)
			defer ticker.Stop()
			defer tickerVaultPublicKeyRefresh.Stop()
			for {
				select {
				case <-ticker.Chan():
					h.removeExpiredRequests(ctx)
				case <-tickerVaultPublicKeyRefresh.Chan():
					// periodically, fetch vault public key, so we can cache it
					h.fetchVaultPublicKey(ctx)
				case <-h.stopCh:
					return
				}
			}
		}()
		return nil
	})
}

// removeExpiredRequests removes expired requests from the pending requests map
func (h *handler) removeExpiredRequests(ctx context.Context) {
	h.mu.RLock()
	var expiredRequests []*activeRequest
	now := h.clock.Now()
	for _, userRequest := range h.activeRequests {
		if now.Sub(userRequest.createdAt) > h.requestTimeout {
			expiredRequests = append(expiredRequests, userRequest)
		}
	}
	h.mu.RUnlock()

	for _, er := range expiredRequests {
		responses := er.copiedResponses()
		var nodeResponses strings.Builder
		for nodeKey, nodeResponse := range responses {
			_, _ = fmt.Fprintf(&nodeResponses, "%s ---::: %v               ", nodeKey, nodeResponse)
		}
		nodeResponsesStr := nodeResponses.String()
		err := h.sendResponse(ctx, er, h.errorResponse(er.req, api.RequestTimeoutError, errors.New("request expired without getting quorum of responses from nodes. Available responses: "+nodeResponsesStr), []byte(nodeResponsesStr)))
		if err != nil {
			h.lggr.Errorw("error sending response to user", "requestID", er.req.ID, "error", err)
		}
	}
}

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}
