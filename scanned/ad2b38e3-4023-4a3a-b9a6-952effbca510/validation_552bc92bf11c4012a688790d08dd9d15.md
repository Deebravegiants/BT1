### No vulnerability found for this question.

**Rationale:** The described exploit requires the attacker to falsify `is_first_block_in_core_with_digest`, but that function reads the `CumulusDigestItem::BlockBundleInfo` digest item embedded in the block header [1](#0-0) , which is set by the collator/node during block authoring based on relay-chain core assignment — it is not derived from or influenced by any signed extrinsic's content, ordering, or weight declaration. A normal signed user has no reachable path to write or forge this digest item; doing so would require a malicious collator/node, which is explicitly out of scope per the rules.

Additionally, `BlockWeightMode` is unconditionally reset at the start of every block by `DynamicMaxBlockWeightHooks::pre_inherents`, which runs before any inherents or extrinsics and sets a fresh `context` equal to the current block number based on the (node-controlled) digest, not a stale prior-block value [2](#0-1) . The `is_stale()` check in `pre_validate_extrinsic` is a defensive fallback for genuinely off-chain contexts (e.g. `validate_transaction` outside block execution) [3](#0-2) , not an in-block re-entrancy gap that a signed user's extrinsic sequence can exploit, since within a single block the mode context is fixed to that block's number from the start.

Even hypothetically, if `PotentialFullCore`/`FullCore` were wrongly entered on a non-first-core block, both `pre_validate_extrinsic` and `post_dispatch_extrinsic` explicitly register `FULL_CORE_WEIGHT` as extra mandatory weight when `!is_first_block_in_core_with_digest` [4](#0-3) [5](#0-4) , which forces the block's total accounted weight over the actual max block weight and would cause the block to be rejected by `CheckWeight`/consensus rather than silently over-consuming — so even a successful mode confusion is designed to fail closed, not open.

Since the attacker-controlled surface (extrinsic content/ordering) cannot forge the digest that gates `is_first_block_in_core`, and the mode is freshly derived per block from node-controlled data with a fail-closed penalty path, this does not constitute a reachable, unprivileged exploit matching the scoped impact.

			} else {
				BlockWeightMode::<Config>::fraction_of_core(None)

				"Block initialization logic took longer than the target block weight, going to use the full core",
