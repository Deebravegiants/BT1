### Title
Silent reward loss when era reward pot has insufficient funds in non-minting `pallet-staking-async` payout path - (File: `substrate/frame/staking-async/src/pallet/impls.rs`)

### Summary
This is a valid, structurally similar analog to the Convex/AMPH bug. Instead of assuming an external protocol will always mint a token, `pallet-staking-async`'s new "DAP" (non-minting) payout path assumes the era-specific reward pot always holds enough balance to fund every staker's/nominator's payout, and silently swallows any transfer failure rather than reverting the extrinsic.

### Finding Description
In legacy mode, `pallet-staking`/`pallet-staking-async` pays rewards by minting new tokens directly via `asset::mint_into_existing`/`mint_creating`, which cannot silently fail for reasons outside the runtime's control. [2](#0-1) 

The newer non-minting ("DAP") mode instead transfers from a pre-funded, era-specific "reward pot" account (`RewardPot::Era`) that is expected to be externally/pre-funded ("at era boundary, the balance is snapshotted into an era-specific pot") [3](#0-2) 

`make_payout_from_provider` performs this transfer, but if it fails (e.g. pot underfunded due to rounding, incomplete funding, or `IssuanceCurve`/`UnclaimedRewardHandler` misconfiguration), the error is only logged and the function returns `None`, treating the reward as if it were simply zero rather than propagating the failure: [4](#0-3) 

Critically, `do_payout_stakers_by_page` marks the page as claimed via `Eras::<T>::set_rewards_as_claimed(era, &stash, page)` *before* any of the individual payouts (validator or nominators) are attempted, and this call is never reverted even if downstream `make_payout_from_provider` calls fail: [5](#0-4) [6](#0-5) 

This mirrors the Amphora/Convex pattern exactly: the caller (`Vault.claimRewards` / `do_payout_stakers_by_page`) computes an expected reward and assumes the underlying funding mechanism (CVX mint / pot transfer) will always succeed, but the funding mechanism can silently no-op on failure (Convex operator change / pot underfunding) instead of reverting, and the caller has already committed state (marked claimed) that prevents any retry.

### Impact Explanation
If the era reward pot is underfunded relative to the sum of all page payouts for that era (possible through rounding errors across pages/nominators, `StakerRewardCalculator` share computation edge cases, or `IssuanceCurve`/budget misconfiguration in `pallet-dap`), any staker whose payout is processed after the pot is exhausted permanently loses their reward: the page is already marked claimed, `AlreadyClaimed` will be returned on retry, and the transfer failure is only visible in node logs, not surfaced to the caller or reverted.

### Likelihood Explanation
Likelihood is low-to-medium and requires either an accounting/rounding edge case in the pot funding step or a misconfiguration of `IssuanceCurve` / `UnclaimedRewardHandler` by the runtime team deploying non-minting mode (currently opt-in via `DisableMinting`). It does not require any special caller privilege — any staker calling `payout_stakers` after the pot is drained triggers the silent loss, matching the "no special access, but special condition" pattern of the original medium-severity finding.

### Recommendation
In `make_payout_from_provider`, do not silently swallow the `T::Currency::transfer` error. Either:
1. Verify pot balance/expected total payout amount before marking the page as claimed and abort the whole page payout with an explicit error if funds are insufficient, or
2. Move `Eras::<T>::set_rewards_as_claimed` to occur only after all transfers in the page have been confirmed successful, or track failed transfers explicitly (e.g. via `UnclaimedRewardHandler`) so the amount isn't lost and can be retried/refunded.

### Proof of Concept
1. Deploy a runtime with `pallet-staking-async` in non-minting (`DisableMinting = true`) mode.
2. Due to rounding in `calculate_staker_reward`/`Perbill::mul_floor` across many nominator pages, or a slightly under-funded `GeneralPots`/`EraPots` snapshot, the era's staker-rewards pot ends up with less balance than the sum of all individual nominator/validator entitlements for that era.
3. A staker calls `payout_stakers(era, validator)` for a page whose transfer is attempted after the pot is already drained by earlier pages' payouts.
4. `Eras::<T>::set_rewards_as_claimed` at line 386 has already executed for that page.
5. `make_payout_from_provider`'s `T::Currency::transfer` fails (insufficient pot balance); the error is logged and `None` is returned; the extrinsic still returns `Ok`.
6. The staker's reward for that page is permanently lost — a subsequent claim attempt returns `Error::<T>::AlreadyClaimed`. [7](#0-6) 

**Note on confidence:** I was not able to fully verify within the available tool budget whether the pot-funding mechanism in `pallet-dap`/`GeneralPots`/`EraPots` provides a hard invariant that guarantees the pot always holds at least the sum of all page payouts before any payout is claimable (which would make the underfunding scenario unreachable in practice). If such an invariant is enforced elsewhere (e.g., an exact-match funding step at era rotation with no rounding loss), this finding's likelihood would be significantly reduced or the issue could be considered only theoretical. A Devin session with full repository access could trace `T::RewardPots`, `pallet_dap`'s pot-funding extrinsics/hooks, and `StakerRewardCalculator` rounding behavior to close this gap.

	fn payout_from_provider(
		era: EraIndex,
		stash: &T::AccountId,
		validator_payout: BalanceOf<T>,
		exposure: &crate::PagedExposure<T::AccountId, BalanceOf<T>>,
		overview_own: BalanceOf<T>,
		total_nominator_payout: BalanceOf<T>,
	) -> u32 {
		let mut nominator_payout_count: u32 = 0;

		if let Some((amount, dest)) = Self::make_payout_from_provider(era, stash, validator_payout)
		{
			Self::deposit_event(Event::<T>::Rewarded { stash: stash.clone(), dest, amount });
		}

		let total_nominator_stake = exposure.total().saturating_sub(overview_own);
		for nominator in exposure.others().iter() {
			let nominator_exposure_part =
				Perbill::from_rational(nominator.value, total_nominator_stake);
			let nominator_reward: BalanceOf<T> =
				nominator_exposure_part.mul_floor(total_nominator_payout);

			if let Some((amount, dest)) =
				Self::make_payout_from_provider(era, &nominator.who, nominator_reward)
			{
				nominator_payout_count.saturating_inc();
				Self::deposit_event(Event::<T>::Rewarded {
					stash: nominator.who.clone(),
					dest,
					amount,
				});
			}
		}

		nominator_payout_count
	}

/// Mint `value` into an existing account `who`.
///
/// This does not increase the total issuance.
pub fn mint_into_existing<T: Config>(
	who: &T::AccountId,
	value: BalanceOf<T>,
) -> Option<PositiveImbalanceOf<T>> {
	// since the account already exists, we mint exact value even if value is below ED.
	T::Currency::deposit(who, value, Precision::Exact).ok()
}

/// Mint `value` and create account for `who` if it does not exist.
///
/// If value is below existential deposit, the account is not created.
///
/// Note: This does not increase the total issuance.
pub fn mint_creating<T: Config>(who: &T::AccountId, value: BalanceOf<T>) -> PositiveImbalanceOf<T> {
	T::Currency::deposit(who, value, Precision::BestEffort).unwrap_or_default()
}
