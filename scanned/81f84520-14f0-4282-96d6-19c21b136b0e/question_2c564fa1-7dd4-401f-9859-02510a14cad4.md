Target: Auth::Oauth.begin_auth / query['redirect_uri']. Attacker action: GET /install?shop=arbitrary-string (no dot, no myshopify suffix) causing begin_auth to build redirect_uri from Context.host (trusted) but auth_route host from the raw shop. Preconditions: Context.host configured per README. Call sequence: begin_auth builds auth_route = auth_base_uri(shop) + '/oauth/authorize?...redirect_uri=#{Context.host}#{redirect_path}...'; the redirect_uri itself is safe, but the outer host attacker controls entirely. Binding: the host receiving the authorize GET (and thus able to observe/intercept the subsequent user-supplied code once Shopify would redirect back) must equal a ShopValidator-approved Shopify domain. Impact: High -> phishing/SSRF: browser is redirected to an attacker-controlled 'https://arbitrary-string/admin/oauth/authorize?...' page which can harvest the client_id and state and present a fake Shopify consent screen, setting up forced OAuth completion. Proof idea: minitest calling begin_auth(shop: 'attacker.example', redirect_path: '/cb') and asserting result[:auth_route] starts with 'https://' + ShopValidator.sanitize!('attacker.example'); currently it does not raise or normalize.
