Call sequence: `Session.from(shop: auth_query.shop, ...)` -> `id = \"offline_#{shop}\"` (or `\"#{shop}_#{associated_user.id}\"`). Binding that breaks: SHOP BINDING - the shop authenticated by HMAC must equal the canonical shop key used everywhere else (`sanitize_shop_domain` output), but `Session.from` uses the raw, non-canonicalized string. Impact: Critical - cross-tenant/session-duplication: the host app's session store, keyed by `session.id`, can end up with two distinct records for what Shopify considers a single shop, one of which an attacker seeded with `shop` text they control, letting a later `Context.active_session` lookup by naive string key serve the wrong session. Proof idea: minitest comparing `Session.from(shop: 'shop-name.myshopify.com', ...).id` against `Session.from(shop: 'Shop-Name.MYSHOPIFY.COM', ...).id` and against `Utils::ShopValidator.sanitize!('Shop-Name.MYSHOPIFY.COM')`, asserting they differ.
