### Title
CORS wildcard-origin allowlist bypass via unanchored suffix match in Gateway HTTP server - (File: core/services/gateway/network/httpserver.go)

### Summary
The Gateway's internet-facing HTTP server implements a custom CORS origin allowlist (`isAllowedOrigin`) that supports wildcard entries such as `https://*.ethereum.org`. The wildcard match is implemented with an unanchored `strings.HasSuffix` check that does not verify a domain-label boundary (a leading `.`) before the allowed suffix. Any attacker who registers a domain whose name merely ends with the configured suffix string (e.g. `evilethereum.org`, which is a distinct top-level domain, not a subdomain of `ethereum.org`) will be treated by the gateway as a trusted, allow-listed origin.

### Finding Description
`isAllowedOrigin` parses the incoming `Origin` header and each configured allowed origin into scheme/host/port, then for wildcard entries strips the leading `*.` and checks `strings.HasSuffix(originHost, allowedHost)`: [1](#0-0) 

This suffix check has no boundary requirement (it does not require the character preceding the matched suffix to be a `.`), so any origin host that literally ends with the configured suffix string satisfies the wildcard rule — including hosts that are not DNS subdomains of the intended domain at all, e.g. an attacker-registered domain `evil-ethereum.org` or `notethereum.org` would satisfy an allowlist entry of `*.ethereum.org` (stripped to `ethereum.org`) purely as a string suffix.

`handleRequest` then reflects the attacker's `Origin` value into `Access-Control-Allow-Origin` for any origin accepted by `isAllowedOrigin`, along with `Access-Control-Allow-Methods`/`Access-Control-Allow-Headers`, when `CORSEnabled` is set: [2](#0-1) 

The existing unit tests only validate the intended matches and simple non-matches (e.g. `ethereum.remix.org`, missing port, wrong scheme) but never test a same-string-suffix domain that is not an actual subdomain, so the boundary-check gap is untested: [3](#0-2) 

This is directly analogous to the reported Verba issue: a same-origin/allowlist check that can be satisfied by any Origin value that merely matches a prefix/suffix pattern rather than an exact, boundary-anchored domain, letting an unauthenticated remote party masquerade as a trusted origin for the CORS check.

### Impact Explanation
This is an allowlist-bypass in the Gateway's origin validation, one of the explicitly in-scope bug classes (`allowlist ... bypass`). It applies to the internet-facing Gateway HTTP server (`core/services/gateway/network/httpserver.go`) used to front JSON-RPC message handlers for the DON/capabilities gateway. An attacker-controlled website that is not an intended trusted UI (e.g. not the real Remix IDE origin) can register a domain that merely ends with the configured wildcard suffix and have the gateway treat it as allowlisted, causing the browser to permit that page's JavaScript to read cross-origin responses and to send preflighted requests that the operator intended to restrict to a specific trusted UI/domain. This weakens the intended origin-based access restriction the operator configured via `CORSAllowedOrigins`, even though it does not itself enable outbound SSRF.

### Likelihood Explanation
Exploitation requires only: (1) the gateway operator has `CORSEnabled = true` with at least one wildcard entry in `CORSAllowedOrigins` (a supported, documented configuration pattern, exercised by the existing wildcard test cases), and (2) the attacker registers/controls a domain string that ends with the configured suffix. Domain registration is trivial and entirely attacker-controlled, and no authentication or prior access to the gateway is required — the check happens purely on the `Origin` request header of an unauthenticated HTTP request.

### Recommendation
Fix `isAllowedOrigin` in `core/services/gateway/network/httpserver.go` to anchor the wildcard suffix match on a label boundary, e.g. require `originHost == allowedHost || strings.HasSuffix(originHost, "."+allowedHost)` instead of a bare `strings.HasSuffix`. Add regression tests covering non-subdomain strings that merely share a suffix (e.g. `evil-ethereum.org` against `*.ethereum.org`) to ensure they are rejected.

### Proof of Concept
1. Configure the gateway HTTP server with `CORSEnabled = true` and `CORSAllowedOrigins = ["https://*.ethereum.org"]`.
2. From an attacker-controlled site served at `https://evil-ethereum.org`, send a request to the gateway endpoint with header `Origin: https://evil-ethereum.org`.
3. `isAllowedOrigin` strips the wildcard prefix to get `allowedHost = "ethereum.org"` and checks `strings.HasSuffix("evil-ethereum.org", "ethereum.org")`, which evaluates `true` even though `evil-ethereum.org` is not a subdomain of `ethereum.org`.
4. The server responds with `Access-Control-Allow-Origin: https://evil-ethereum.org`, allowing the attacker's page to make cross-origin requests to the gateway and read the responses, bypassing the intended origin allowlist. [4](#0-3)

func (s *httpServer) isAllowedOrigin(origin string) bool {
	originScheme, originHost, originPort, err := s.splitURL(origin)
	if err != nil {
		s.lggr.Debug("error parsing origin URL", err)
		return false
	}
	for _, allowed := range s.config.CORSAllowedOrigins {
		// probably better to do this once when server starts and store it in a map
		// this is an easier solution so we don't have to apply more changes to the code
		// just need to be careful when specifying allowed origins in the config file
		allowedScheme, allowedHost, allowedPort, err := s.splitURL(allowed)
		if err != nil {
			s.lggr.Debug("error parsing allowed origin URL", err)
			continue
		}
		// skip if the scheme doesn't match at all
		if originScheme != allowedScheme {
			continue
		}
		// skip if the port doesn't match at all
		if originPort != allowedPort {
			continue
		}
		// check for exact host match (e.g., remix.com)
		if originHost == allowedHost {
			return true
		}
		// check for wildcard host match (e.g., *.remix.com)
		if strings.HasPrefix(allowedHost, "*.") {
			allowedHost = allowedHost[2:]
			if strings.HasSuffix(originHost, allowedHost) {
				return true
			}
		}
	}
	return false
}

func (s *httpServer) handleRequest(w http.ResponseWriter, r *http.Request) {
	if s.config.CORSEnabled {
		origin := r.Header.Get("Origin")
		if s.isAllowedOrigin(origin) {
			w.Header().Set("Access-Control-Allow-Origin", origin)
			w.Header().Set("Access-Control-Allow-Methods", "GET, POST, OPTIONS")
			w.Header().Set("Access-Control-Allow-Headers", "Content-Type")
		}

		// handle preflight requests
		if r.Method == http.MethodOptions {
			w.WriteHeader(http.StatusNoContent)
			return
		}
	}
