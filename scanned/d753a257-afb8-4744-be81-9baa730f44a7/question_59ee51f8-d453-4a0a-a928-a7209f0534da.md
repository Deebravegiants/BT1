Attacker action: attacker who has one validly signed webhook for topic A (which they legitimately registered/received) discovers topic B is also registered by the same app (e.g. from docs) and resends the same signed body under X-Shopify-Topic: B, where B's handler expects a differently-shaped JSON payload than A's body. Preconditions: app registers multiple :http topics via Registry.add_registration; JSON body A happens to parse under handler B's expected keys or handler B does defensive parsing that no-ops/throws in an unsafe way. Call sequence: HmacValidator.validate(request) true -> handler = @registry['B'].handler -> handler.handle(WebhookMetadata.new(topic: 'B', body: request.parsed_body,...)). Binding: topic_the_hmac_authenticates == topic_the_handler_believes_it_received; broken because signature never encodes topic. Impact: Critical, cross-handler/cross-tenant confusion causing handler B to act on attacker-supplied body content it was never meant to receive, on behalf of whichever shop header is set.
