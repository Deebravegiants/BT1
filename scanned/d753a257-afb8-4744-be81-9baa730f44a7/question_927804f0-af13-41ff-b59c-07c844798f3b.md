target=ShopifyAPI::Webhooks::Request#shop. Attacker action: attacker sends a validly-signed webhook body from their own shop but sets X-Shopify-Shop-Domain to an arbitrary victim myshopify.com domain the attacker does not own. Preconditions: host app's WebhookHandler#handle trusts data.shop to select or create tenant records (as documented usage). Call sequence: Request.new -> HmacValidator.validate(request) (checks raw_body only) -> Registry.process reads request.shop -> WebhookMetadata.new(shop: request.shop). Binding: shop_authenticated_by_signature == shop_used_by_handler_to_select_tenant must hold, but signature never covers shop-domain. Impact: Critical, cross-tenant access - handler could write/update data attributed to victim shop despite auth being rooted only in attacker's own valid HMAC secret usage on their own request. Proof idea: minitest asserting that two Request objects built from the same (raw_body, hmac header) but different shop-domain headers both pass HmacValidator.validate.
