### Title
Vault write-request authorization relies solely on an unpersisted, per-process replay guard, allowing a caller to re-execute an already-authorized `CreateSecrets`/`UpdateSecrets`/`DeleteSecrets` request after any node restart - ([File: core/capabilities/vault/authorizer.go])

### Summary
`AllowListBasedAuth.AuthorizeRequest` never invalidates or consumes the on-chain allowlist entry it authorizes against — the entry stays valid for repeated use until its own expiry timestamp elapses [1](#0-0) . The test suite makes this explicit: *"Same request is still authorized here; replay protection lives in the generic Authorizer"* [2](#0-1) . The only thing that stops the same allowlisted digest from being reused is `authorizer.replayGuard`, an in-memory `map[string]int64` created once per process with no persistence [3](#0-2) [4](#0-3) .

### Finding Description
`authorizer.AuthorizeRequest` calls the allowlist- or JWT-based authorizer to validate the request, and only *after* that succeeds does it call `a.replayGuard.CheckAndRecord(authResult.Digest(), authResult.ExpiresAt())` to reject digests it has already "seen" [5](#0-4) . This guard is:
- purely in-memory (`seen map[string]int64`), constructed fresh via `NewRequestReplayGuard()` whenever `NewAuthorizer` is instantiated [6](#0-5) ,
- created once per `GatewayHandler` on node start-up [7](#0-6) ,
- never written to durable storage or synchronized with other DON members.

The underlying authorization source of truth — the on-chain `WorkflowRegistryOwnerAllowlistedRequest` entry keyed by `RequestDigest` and `ExpiryTimestamp` — is read-only and unaffected by whether the request was already processed; `AuthorizeRequest` re-derives and re-validates it every single call, with no "consumed" flag or removal step [8](#0-7) . Consequently, the *entire* burden of preventing a "claim many times for the same tier"-style re-execution of a privileged Vault write (`CreateSecrets`, `UpdateSecrets`, `DeleteSecrets`) rests on volatile, single-process memory that is wiped by any node restart (routine upgrades, crash/OOM, deploys, etc.) — a normal operational event, not an attacker-controlled or malicious-node/network-layer action. Any unprivileged caller who already holds a validly signed, still-unexpired allowlist entry can simply wait for/observe a node process restart (or interact with a freshly restarted node in a rolling deployment) and resubmit the exact same JSON-RPC request; `AuthorizeRequest` will authorize it again because the replay guard's map is empty again, and `HandleGatewayMessage` will re-invoke `handleSecretsCreate`/`handleSecretsUpdate`/`handleSecretsDelete` on that node [9](#0-8) .

This mirrors the reported bug class exactly: a one-time-use authorization ("tier claimed") is validated by a boolean/flag that either (a) is never actually set to consumed, or (b) is stored somewhere that gets reset, so the same privileged action can be triggered repeatedly instead of once.

### Impact Explanation
A caller with a legitimately signed but intended-to-be-single-use allowlist authorization can re-trigger the same privileged Vault mutation (secret create/update/delete) multiple times across the DON simply by timing requests around node restarts, instead of the single execution the on-chain allowlist entry was meant to authorize. Depending on downstream OCR consensus/state-transition idempotency (not fully verifiable from the indexed code for delete/update state transition handlers), this can result in redundant or duplicate secret mutations being committed by the DON, and demonstrates that authorization state that should be a durable, one-time consumption check is instead an ephemeral, non-persisted counter — a Medium-severity control weakness consistent with the reported class (repeatable privileged claim due to missing/insufficient consumed-state tracking).

### Likelihood Explanation
Node restarts are routine (deployments, upgrades, crash recovery) rather than requiring any privileged or malicious action, and the caller only needs to hold a still-valid (unexpired) allowlist entry and resend the identical request — well within reach of an ordinary unprivileged workflow-owner client of the gateway. The likelihood of hitting this window in a live, continuously-deployed DON is non-trivial, though it does depend on the allowlist entry's expiry window and operational restart cadence.

### Recommendation
Persist replay/consumption state durably (e.g., in the OCR key-value store already used for secrets/metadata, or in a per-request "consumed digests" set that survives process restarts and is agreed upon via consensus) rather than relying solely on `RequestReplayGuard`'s in-memory map. Alternatively, have the allowlist-authorization source itself mark/remove the digest as consumed upon first successful authorization (mirroring the fix pattern of setting `tierClaimed[_tier] = true` and clearing `payoutSchedule[_tier]` in the original report), so a restart of any single node cannot resurrect an already-used authorization.

### Proof of Concept
1. Workflow owner obtains an on-chain allowlist entry for `MethodSecretsUpdate` with `RequestDigest = D` and `ExpiryTimestamp = T` (e.g., 5 minutes out).
2. Owner sends the corresponding JSON-RPC request to the gateway; `AllowListBasedAuth.AuthorizeRequest` succeeds, `replayGuard.CheckAndRecord(D, T)` records it, and `handleSecretsUpdate` executes the update [10](#0-9) .
3. A node in the DON restarts (deploy/crash) before `T` elapses, creating a brand-new `authorizer` with an empty `replayGuard.seen` map [7](#0-6) .
4. Owner resends the byte-identical request. `AllowListBasedAuth.AuthorizeRequest` re-validates successfully (the on-chain entry is untouched and unexpired) [11](#0-10) , `replayGuard.CheckAndRecord` on the restarted node accepts it as new, and the Vault write executes a second time — demonstrating the "claim" (here, a privileged secret mutation) is not durably restricted to one execution.

// AuthorizeRequest authorizes a request using AllowListBasedAuth.
// It does NOT check if the request method is allowed.
func (r *allowListBasedAuth) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	r.lggr.Debugw("AllowListBasedAuth authorizing request", "method", req.Method, "requestID", req.ID)
	requestDigest, err := req.Digest()
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to create digest", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, err
	}
	requestDigestBytes, err := hex.DecodeString(requestDigest)
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to decode digest", "method", req.Method, "requestID", req.ID, "requestDigest", requestDigest, "error", err)
		return nil, err
	}
	requestDigestBytes32 := [32]byte(requestDigestBytes)
	if r.workflowRegistrySyncer == nil {
		r.lggr.Errorw("AllowListBasedAuth workflowRegistrySyncer is nil", "method", req.Method, "requestID", req.ID)
		return nil, errors.New("internal error: workflowRegistrySyncer is nil")
	}
	allowlistedRequest, allowedRequestsStrs, err := r.findAllowlistedItemWithRetry(ctx, req, requestDigest, requestDigestBytes32)
	if err != nil {
		return nil, err
	}
	if allowlistedRequest == nil {
		r.lggr.Debugw("AllowListBasedAuth request digest not allowlisted",
			"method", req.Method,
			"requestID", req.ID,
			"digestHexStr", requestDigest,
			"allowedRequestsStrs", allowedRequestsStrs)
		return nil, errors.New("request not allowlisted")
	}

	if time.Now().UTC().Unix() > int64(allowlistedRequest.ExpiryTimestamp) {
		authorizedRequestStr := string(allowlistedRequest.RequestDigest[:])
		r.lggr.Debugw("AllowListBasedAuth authorization expired", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", authorizedRequestStr, "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
		return nil, errors.New("request authorization expired")
	}

	digestKey := string(allowlistedRequest.RequestDigest[:])
	r.lggr.Debugw("AllowListBasedAuth authorization succeeded", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", digestKey, "owner", allowlistedRequest.Owner.Hex(), "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
	return &AuthResult{
		workflowOwner: allowlistedRequest.Owner.Hex(),
		digest:        digestKey,
		expiresAt:     int64(allowlistedRequest.ExpiryTimestamp),
	}, nil
}

type RequestReplayGuard struct {
	mu      sync.Mutex
	seen    map[string]int64 // digest → unix expiry timestamp
	nowFunc func() time.Time // injectable for testing
}

// NewRequestReplayGuard creates a replay guard for authorized Vault requests.
func NewRequestReplayGuard() *RequestReplayGuard {
	return &RequestReplayGuard{
		seen:    make(map[string]int64),
		nowFunc: time.Now,
	}
}

// CheckAndRecord returns ErrRequestAlreadySeen if the digest was previously
// recorded and has not yet expired. Otherwise it records the digest with
// the given expiry timestamp (unix seconds, UTC).
//
// Expired entries are cleaned up on every call.
func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}

func (a *authorizer) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	authResult, err := a.authorizeRequest(ctx, req)
	if err != nil {
		return nil, err
	}
	if authResult == nil {
		err = errors.New("auth mechanism returned nil auth result")
		a.lggr.Errorw("auth mechanism returned nil auth result", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "")
		return nil, err
	}
	if err := a.replayGuard.CheckAndRecord(authResult.Digest(), authResult.ExpiresAt()); err != nil {
		a.lggr.Debugw("replay guard rejected request", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "digest", authResult.Digest(), "expiresAt", authResult.ExpiresAt(), "hasAuth", req.Auth != "", "error", err)
		return nil, err
	}
	if ownerErr := validateSecretOwnersMatchAuthorized(req, authResult.AuthorizedOwner()); ownerErr != nil {
		a.lggr.Errorw("owner binding rejected request", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "hasAuth", req.Auth != "", "error", ownerErr)
		return nil, ownerErr
	}
	a.lggr.Debugw("request authorized", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "digest", authResult.Digest(), "expiresAt", authResult.ExpiresAt(), "hasAuth", req.Auth != "")
	return authResult, nil
}

func (h *GatewayHandler) HandleGatewayMessage(ctx context.Context, gatewayID string, req *jsonrpc.Request[json.RawMessage]) (err error) {
	reqLggr := h.requestLogger(req, gatewayID)
	reqLggr.Debugw("received message from gateway", "req", req)

	var response *jsonrpc.Response[json.RawMessage]
	var authResult *AuthResult

	switch req.Method {
	case vaulttypes.MethodSecretsCreate, vaulttypes.MethodSecretsUpdate:
		publicKey, pkErr := h.getMasterPublicKey(ctx)
		if pkErr != nil {
			response = h.gatewayErrorResponse(ctx, gatewayID, req, pkErr)
			break
		}
		authorized, pipelineErr := h.requestProcessor.ProcessRequest(ctx, req, publicKey)
		if pipelineErr != nil {
			response = h.gatewayErrorResponse(ctx, gatewayID, req, pipelineErr)
			break
		}
		authResult = authorized.AuthResult
	case vaulttypes.MethodSecretsDelete, vaulttypes.MethodSecretsList:
		authorized, pipelineErr := h.requestProcessor.ProcessRequest(ctx, req, nil)
		if pipelineErr != nil {
			response = h.gatewayErrorResponse(ctx, gatewayID, req, pipelineErr)
			break
		}
		authResult = authorized.AuthResult
	case vaulttypes.MethodPublicKeyGet:
		response = h.handlePublicKeyGet(ctx, gatewayID, req)
	default:
		response = h.errorResponse(ctx, gatewayID, req, api.UnsupportedMethodError, errors.New("unsupported method: "+req.Method))
	}

	if response == nil {
		switch req.Method {
		case vaulttypes.MethodSecretsCreate:
			response = h.handleSecretsCreate(ctx, gatewayID, req)
		case vaulttypes.MethodSecretsUpdate:
			response = h.handleSecretsUpdate(ctx, gatewayID, req)
		case vaulttypes.MethodSecretsDelete:
			response = h.handleSecretsDelete(ctx, gatewayID, req)
		case vaulttypes.MethodSecretsList:
			response = h.handleSecretsList(ctx, gatewayID, req, authResult)
		}
