Target: VersionedNonceBuilder.decodeNonce magic-prefix/length check (packages/intents-sdk/src/intents/expirable-nonce.ts). Attacker input: a 32-byte base64 nonce that happens to start with VERSIONED_MAGIC_PREFIX by chance (e.g., produced by a non-SDK signer sharing the same 4-byte prefix coincidentally, or a counterparty-forwarded nonce with a spoofed prefix) but whose remaining 27 bytes are NOT a real salt+deadline+random borsh structure. Preconditions: this nonce is passed into sdk.invalidateNonces(). Call sequence: decodeNonce passes the prefix check, deserialize(SALTED_NONCE_BORSH_SCHEMA, borshData) does not throw (borsh deserialization of fixed-size fields succeeds on any 27 bytes), v.is(saltedNonceSchema, decoded.value) passes because array/bigint types are structurally satisfied regardless of semantic meaning. Equality broken: the deadline used for invalidation setDeadline() is derived from bytes that are not actually a deadline, so the computed invalidation deadline is unrelated to the real intent's expiry — it can be nonsensically before OR after the true deadline. Impact: Critical, invalidateNonces can silently produce an invalidation intent with the wrong deadline, letting the targeted intent still execute. Proof idea: vitest feeding a crafted 32-byte nonce with correct prefix but random tail bytes, assert the resulting invalidation deadline is unrelated to any real nonce deadline and can exceed the original intent's actual on-chain deadline.
