### Title
CORS wildcard-origin allowlist bypass via unanchored suffix match - ([File: core/services/gateway/network/httpserver.go])

### Summary
The gateway's CORS origin check treats any Origin header whose hostname merely ends with the configured wildcard base domain as an allowed subdomain, without requiring a `.` boundary. An attacker can register a domain such as `evilethereum.org` to satisfy a wildcard allowlist entry of `*.ethereum.org`, causing the gateway to reflect `Access-Control-Allow-Origin` for an attacker-controlled site.

### Finding Description
`isAllowedOrigin` implements wildcard host matching for `CORSAllowedOrigins` entries of the form `*.domain`: [1](#0-0) 

For a wildcard entry, the code strips the `*.` prefix and then checks `strings.HasSuffix(originHost, allowedHost)`. This is a pure string-suffix comparison with no requirement that the character preceding the matched suffix in `originHost` be a `.` (i.e., no subdomain boundary check). Consequently, `originHost = "evilethereum.org"` (or `"attacker-controlled-remix.ethereum.org.evil.com"` style tricks, or more directly `"notethereum.org"`) satisfies `HasSuffix(originHost, "ethereum.org")` even though it is not a subdomain of `ethereum.org` at all — it is an entirely different, attacker-registrable domain that merely shares a trailing character sequence.

This is the same root-cause class as the Jenkins Audit Trail advisory (CVE-2020-2288): a pattern-matching check intended to recognize "this URL/host belongs to the allowed set" is bypassable by appending/prepending characters around the matched substring, because the match isn't anchored to a real structural boundary (there, request-path suffixes; here, hostname-label boundaries).

`isAllowedOrigin` is invoked directly from the request-handling path for every incoming HTTP request to the gateway when `CORSEnabled` is true: [2](#0-1) 

If `isAllowedOrigin` returns true, the server sets `Access-Control-Allow-Origin` to the attacker's exact Origin value, `Access-Control-Allow-Methods` to `GET, POST, OPTIONS`, and `Access-Control-Allow-Headers` to `Content-Type`, which permits a malicious website to make cross-origin browser requests to the gateway and read the JSON-RPC response.

### Impact Explanation
An unprivileged remote attacker who controls a domain sharing a suffix with an operator's configured wildcard entry (e.g., registering `evil-ethereum.org` when the operator allowlists `*.ethereum.org`) can get their site treated as an allowed CORS origin. This lets an attacker-hosted webpage, when visited by a victim whose browser has an authenticated session or is otherwise trusted by network position, issue cross-origin requests to the gateway's HTTP(S) endpoint and read the responses that should only be readable by the legitimately allowlisted frontend origins (e.g., a workflow UI). This is a confidentiality-impact issue similar in class/severity to the referenced CVE (Medium, low confidentiality impact) rather than a full authentication bypass, since it only affects the CORS same-origin reflection decision, not the underlying request authorization.

### Likelihood Explanation
Exploitation requires: (1) the gateway operator configuring at least one wildcard `*.domain` entry in `CORSAllowedOrigins`, and (2) the attacker registering/controlling a domain string that shares the suffix without a proper subdomain boundary. Both conditions are realistic and require no privileged access or interaction with the node beyond normal HTTP/browser-based requests, so this is reachable by any unprivileged external actor able to lure a victim to a crafted webpage.

### Recommendation
Fix the wildcard match to require a proper label boundary, e.g.:
```go
if strings.HasPrefix(allowedHost, "*.") {
    base := allowedHost[2:]
    if originHost == base || strings.HasSuffix(originHost, "."+base) {
        return true
    }
}
```
This ensures `originHost` must either equal the base domain or end with `.` + base domain, preventing suffix-only matches like `evilethereum.org` against `ethereum.org`.

### Proof of Concept
Given gateway config `CORSAllowedOrigins = ["https://*.ethereum.org"]`:
1. Attacker registers/serves a page from `https://evilethereum.org`.
2. Victim's browser sends a cross-origin request to the gateway with header `Origin: https://evilethereum.org`.
3. `isAllowedOrigin` computes `allowedHost = "ethereum.org"` and `originHost = "evilethereum.org"`; `strings.HasSuffix("evilethereum.org", "ethereum.org")` is `true`, so the function returns `true`.
4. The gateway responds with `Access-Control-Allow-Origin: https://evilethereum.org`, permitting the attacker page's script to read the JSON-RPC response, as demonstrated by the matching test pattern at [3](#0-2)  which only tests the *negative* (non-matching) suffix cases, not the boundary-less true-positive bypass case described above.

func (s *httpServer) handleRequest(w http.ResponseWriter, r *http.Request) {
	if s.config.CORSEnabled {
		origin := r.Header.Get("Origin")
		if s.isAllowedOrigin(origin) {
			w.Header().Set("Access-Control-Allow-Origin", origin)
			w.Header().Set("Access-Control-Allow-Methods", "GET, POST, OPTIONS")
			w.Header().Set("Access-Control-Allow-Headers", "Content-Type")
		}

		// handle preflight requests
		if r.Method == http.MethodOptions {
			w.WriteHeader(http.StatusNoContent)
			return
		}
	}
