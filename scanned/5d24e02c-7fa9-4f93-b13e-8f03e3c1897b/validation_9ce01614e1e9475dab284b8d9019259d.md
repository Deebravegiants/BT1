### Title
Vault gateway `DeleteSecrets` path does not bind requested secret owners to the authorized caller identity - ([File: core/capabilities/vault/gateway_vault_request_processor.go])

### Summary
The reported OpenQ bug is a caller-supplied identity (`_funder`) being trusted instead of the authenticated actor (`msg.sender`) when moving funds. The closest structural analog in this codebase is in the Vault gateway request pipeline: for `SecretsDelete` requests, the owner of each secret to be deleted is taken directly from the untrusted, client-supplied JSON-RPC params and is never cross-checked or rewritten against the authorized owner derived from authentication, unlike the `SecretsList` and `SecretsCreate`/`SecretsUpdate` paths which explicitly rebind or cryptographically verify ownership.

### Finding Description
`GatewayVaultRequestProcessor.processDeleteSecretsRequest` unmarshals the caller-supplied `DeleteSecretsRequest`, validates only structural constraints via `ValidateDeleteSecretsRequest` (batch size, non-empty, per-id `key`/`owner`/`namespace` character/length checks), and then calls `authorizeAndStamp`, which authorizes the *request envelope* and stamps a new `RequestId` prefixed with the authorized owner — but it never rewrites or validates that `deleteReq.Ids[i].Owner` equals `authResult.AuthorizedOwner()`. [1](#0-0) 

This contrasts with the two other request types:
- `SecretsList`: the gateway handler explicitly overwrites the caller-supplied owner with the authorized owner before querying: `r.Owner = authResult.AuthorizedOwner()`. [2](#0-1) 
- `SecretsCreate`/`SecretsUpdate`: ownership is cryptographically bound because `EnsureRightLabelOnSecret` checks that the TDH2 ciphertext's label matches `WorkflowOwnerToLabel(owner)` for the owner declared in each `EncryptedSecret.Id`, so a caller cannot claim ownership of a secret it did not encrypt for that owner label. [3](#0-2) 

For delete, `ValidateDeleteSecretsRequest` only validates identifier formatting (`ValidateSecretIdentifier`) for each id, with no comparison to the authorized owner: [4](#0-3) 

The delete request is then forwarded, with the unmodified caller-supplied `Ids` (and their `Owner` fields), straight to `h.secretsService.DeleteSecrets(ctx, r)`: [5](#0-4) 

I was not able to locate a `secretsService.DeleteSecrets` implementation in the indexed portion of the codebase that re-validates the `Owner` field of each `SecretIdentifier` against the authenticated caller before performing the delete — the pipeline's own comments state that "AuthorizeRequest ... validates that payload owners match the authorized workflow owner" for create/update, but no equivalent statement or code path exists for delete in the files I could inspect.

### Impact Explanation
If `DeleteSecrets` on the secrets-service side does not perform its own independent ownership check on `Ids[].Owner`, any caller that is authorized to reach the delete method (e.g. an allowlisted workflow or JWT-authenticated tenant) could submit `Ids` entries whose `Owner` field names a different owner than the one it was actually authorized for, causing deletion of another tenant's vault secrets — a cross-user, unauthorized state-mutating action analogous to the funds-source confusion in the original report (acting on behalf of an identity different from the authenticated one).

### Likelihood Explanation
Likelihood is uncertain without visibility into `secretsService.DeleteSecrets`'s internal implementation, which is outside what I could retrieve from the index. The likelihood is elevated by the fact that this is the *only* one of the four vault RPC methods (`Create`, `Update`, `Delete`, `List`) where the owner used for the downstream secrets-service call is taken verbatim from client input rather than rebound to `authResult.AuthorizedOwner()` or cryptographically verified via a ciphertext label.

### Recommendation
In `processDeleteSecretsRequest` (or in `handleSecretsDelete`), after authorization, rewrite/validate every `deleteReq.Ids[i].Owner` against `authResult.AuthorizedOwner()` before calling `secretsService.DeleteSecrets`, mirroring the pattern already used for `SecretsList` (`r.Owner = authResult.AuthorizedOwner()`). Alternatively, confirm and, if absent, add an explicit ownership check inside the `secretsService.DeleteSecrets` implementation itself.

### Proof of Concept
1. An actor obtains authorization to invoke `vaulttypes.MethodSecretsDelete` for owner A (e.g., via allowlist/JWT for workflow A).
2. The actor crafts a `DeleteSecretsRequest` whose `Ids` contain `SecretIdentifier{Owner: "ownerB", Key: "...", Namespace: "..."}`.
3. `ValidateDeleteSecretsRequest` only checks that `owner` is non-empty and alphanumeric — it accepts `"ownerB"` without complaint. [4](#0-3) 
4. `authorizeAndStamp` authorizes the envelope for owner A's request ID prefix but never inspects or rewrites `deleteReq.Ids[].Owner`. [6](#0-5) 
5. `handleSecretsDelete` forwards the request, including `Ids[].Owner = "ownerB"`, unmodified to `secretsService.DeleteSecrets`. [5](#0-4) 
6. If `DeleteSecrets` trusts the `Owner` field on each id rather than the authenticated owner, owner B's secret is deleted by an actor only authorized as owner A.

func (p *GatewayVaultRequestProcessor) processDeleteSecretsRequest(
	ctx context.Context,
	req *jsonrpc.Request[json.RawMessage],
) (*AuthorizedGatewayVaultRequest, error) {
	if req.Params == nil {
		return nil, InvalidVaultParamsError{Method: req.Method, Err: errors.New("request params must not be nil")}
	}

	var deleteReq vaultcommon.DeleteSecretsRequest
	if err := json.Unmarshal(*req.Params, &deleteReq); err != nil {
		return nil, InvalidVaultParamsError{Method: req.Method, Err: err}
	}
	if p.stripOwnerPrefixForAuth {
		deleteReq.RequestId = req.ID
		if err := marshalVaultParams(req, &deleteReq); err != nil {
			return nil, InvalidVaultParamsError{Method: req.Method, Err: err}
		}
	} else {
		deleteReq.RequestId = coalesceRequestID(deleteReq.RequestId, req.ID)
	}

	if err := p.validator.ValidateDeleteSecretsRequest(ctx, &deleteReq); err != nil {
		return nil, p.validationError(req, err)
	}

	return p.authorizeAndStamp(ctx, req, func(prefixedRequestID string) error {
		deleteReq.RequestId = prefixedRequestID
		vaultutils.ApplySecretIdentifierNamespaceDefaults(deleteReq.Ids)
		return marshalVaultParams(req, &deleteReq)
	})
}

func (p *GatewayVaultRequestProcessor) authorizeAndStamp(
	ctx context.Context,
	req *jsonrpc.Request[json.RawMessage],
	stamp func(prefixedRequestID string) error,
) (*AuthorizedGatewayVaultRequest, error) {
	incomingOwner := ""
	if idx := strings.Index(req.ID, vaulttypes.RequestIDSeparator); idx != -1 {
		incomingOwner = req.ID[:idx]
	}

	p.lggr.Debugw("authorizing gateway vault request", "method", req.Method, "requestID", req.ID)
	authResult, err := p.authorizer.AuthorizeRequest(ctx, *req)
	if err != nil {
		authErr := fmt.Errorf("request not authorized: %w", err)
		p.lggr.Errorw("gateway vault request authorization failed", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "", "incomingOwner", incomingOwner, "error", authErr)
		return nil, authErr
	}

	originalRequestID := req.ID
	authorizedOwner := authResult.AuthorizedOwner()
	prefixedRequestID := authorizedOwner + vaulttypes.RequestIDSeparator + originalRequestID
	req.ID = prefixedRequestID

	if err := stamp(prefixedRequestID); err != nil {
		p.lggr.Errorw("failed to stamp authorized request params", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, fmt.Errorf("failed to stamp authorized request params: %w", err)
	}

	p.lggr.Debugw("authorized gateway vault request", "method", req.Method, "requestID", req.ID, "owner", authorizedOwner, "orgID", authResult.OrgID(), "workflowOwner", authResult.WorkflowOwner())
	return &AuthorizedGatewayVaultRequest{
		Req:        *req,
		AuthResult: authResult,
	}, nil
}

func (h *GatewayHandler) handleSecretsDelete(ctx context.Context, gatewayID string, req *jsonrpc.Request[json.RawMessage]) *jsonrpc.Response[json.RawMessage] {
	r := &vaultcommon.DeleteSecretsRequest{}
	if err := json.Unmarshal(*req.Params, r); err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.UserMessageParseError, err)
	}

	h.lggr.Debugw("Processing authorized delete secrets request", "request", r.String())
	resp, err := h.secretsService.DeleteSecrets(ctx, r)
	if err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.HandlerError, fmt.Errorf("failed to delete secrets: %w", err))
	}

	resultBytes, err := resp.ToJSONRPCResult()
	if err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.NodeReponseEncodingError, err)
	}

	return &jsonrpc.Response[json.RawMessage]{
		Version: jsonrpc.JsonRpcVersion,
		ID:      req.ID,
		Method:  req.Method,
		Result:  (*json.RawMessage)(&resultBytes),
	}
}

func (r *RequestValidator) ValidateDeleteSecretsRequest(ctx context.Context, request *vaultcommon.DeleteSecretsRequest) error {
	if request.RequestId == "" {
		return errors.New("request ID must not be empty")
	}
	if err := r.MaxRequestBatchSizeLimiter.Check(ctx, len(request.Ids)); err != nil {
		if errBoundLimited, ok := errors.AsType[limits.ErrorBoundLimited[int]](err); ok {
			return fmt.Errorf("request batch size exceeds maximum of %d: %w", errBoundLimited.Limit, err)
		}
		return fmt.Errorf("failed to check request batch size limit: %w", err)
	}
	if len(request.Ids) == 0 {
		return errors.New("request batch must contain at least 1 item")
	}

	uniqueIDs := map[string]bool{}
	for idx, id := range request.Ids {
		if id == nil {
			return errors.New("secret ID must not be nil at index " + strconv.Itoa(idx))
		}
		if err := r.ValidateSecretIdentifier(ctx, id.Key, id.Owner, id.Namespace); err != nil {
			return fmt.Errorf("invalid secret identifier at index %d: %w", idx, err)
		}

		_, ok := uniqueIDs[vaulttypes.KeyFor(id)]
		if ok {
			return errors.New("duplicate secret ID found at index " + strconv.Itoa(idx) + ": " + id.String())
		}

		uniqueIDs[vaulttypes.KeyFor(id)] = true
	}
	return nil
}

// EnsureRightLabelOnSecret verifies that the TDH2 ciphertext label matches the workflow
// owner label (Ethereum address, left-padded to 32 bytes). owner must be non-empty;
// when the public key is nil, verification is skipped for the same reasons as
// verifyEncryptedSecret.
func EnsureRightLabelOnSecret(publicKey *tdh2easy.PublicKey, secret, owner string) error {
	cipherText, err := verifyEncryptedSecret(publicKey, secret)
	if err != nil {
		return err
	}
	if cipherText == nil {
		return nil
	}
	if owner == "" {
		return errors.New("owner must not be empty for secret label verification")
	}

	expected := vaultutils.WorkflowOwnerToLabel(owner)
	secretLabel := cipherText.Label()
	if secretLabel == expected {
		return nil
	}

	return fmt.Errorf("secret label [%s] does not match workflow owner label [%s]",
		hex.EncodeToString(secretLabel[:]), hex.EncodeToString(expected[:]))
}
