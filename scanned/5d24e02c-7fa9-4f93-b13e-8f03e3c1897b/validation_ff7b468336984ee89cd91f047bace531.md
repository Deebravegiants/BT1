## Title
Cross-workflow/cross-user Request ID squatting causes DOS in `httpTriggerHandler` gateway callback map - (File: `core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go`)

### Summary
The Chainlink gateway's `httpTriggerHandler` accepts an unrestricted, user-supplied `requestID` from JSON-RPC HTTP trigger requests and uses it directly as the key in a single, global `callbacks` map shared across **all workflows and all callers**. Because the uniqueness check on this map is not scoped per-workflow or per-owner, any unprivileged caller who can obtain authorization for *their own* (unrelated) workflow can pre-register the same `requestID` value that a victim intends to use, causing the victim's legitimate request to be rejected with a conflict error. This is the same bug class as the reported `OrderProcessor.requestOrder()` issue: a user-chosen identifier, observable/guessable before the intended request lands, lets another party squat it and block the original caller.

### Finding Description
`HandleUserTriggerRequest` validates and authorizes an inbound HTTP trigger request, then calls `setupCallback`, which registers the request under the *raw* `requestID` supplied by the caller: [1](#0-0) 

The only enforcement is that this exact string has not been used before *anywhere on this gateway instance*: [1](#0-0) 

`validateRequestID` only forbids empty strings and the `/` character; it does not scope the ID to a workflow, owner, or auth key: [2](#0-1) 

`authorizeRequest` (called before `setupCallback`) only verifies that the caller holds a valid signed JWT for *some* registered workflow — it does not tie the `requestID` namespace to that workflow: [3](#0-2) 

Because `h.callbacks` is a single `map[string]savedCallback` keyed purely by the caller-supplied `requestID`, and any authorized workflow owner can drive the code path that inserts into this map, an attacker who registers their own (unrelated, low-cost) workflow can submit an `HTTPTriggerRequest` using the exact `requestID` string a victim is about to use for a *different* workflow. If the attacker's request lands first, the victim's later request with the same ID hits the duplicate check and is rejected: [4](#0-3) 

This mirrors the reported analog exactly: a user-supplied nonce/ID, not bound to the submitting principal, whose exposure (e.g., via client-side generation patterns, predictable sequencing, logs, or timing) allows a third party to front-run and squat it, denying the legitimate requester service.

### Impact Explanation
An unrelated, unprivileged caller (anyone who can register and authorize against any workflow — a normal, low-privilege platform action) can selectively deny specific HTTP-triggered workflow executions for other users by squatting their `requestID` before their request is processed. This is a targeted denial-of-service on the gateway's workflow trigger path: the victim's legitimate call fails with `jsonrpc.ErrConflict` ("requestID ... has already been used") instead of executing the intended workflow.

### Likelihood Explanation
Exploitability depends on the attacker being able to predict or observe the victim's chosen `requestID` before the victim's request completes processing (e.g., deterministic/sequential IDs generated by client tooling, IDs reused across retries, or IDs visible through logging/monitoring/network timing). Given the gateway explicitly documents this as a global namespace (`Request IDs from users must not contain "/" ... reserved for internal node-to-node routing`) with no per-workflow/per-owner scoping, likelihood is moderate — it requires some knowledge of the target ID pattern but no privileged access.

### Recommendation
Scope the `callbacks` map key (and the duplicate-detection namespace) to the authorized principal, e.g. `workflowID + "::" + requestID` or `authorizedOwner + "::" + requestID`, similar to the prefixing already done in the vault handler (`authorizedOwner + vaulttypes.RequestIDSeparator + originalRequestID` in `core/capabilities/vault/gateway_vault_request_processor.go`), so that request IDs from one workflow/owner cannot collide with or block requests from another.

### Proof of Concept
1. Attacker registers/owns Workflow A (a normal, unprivileged action available to any platform user) and obtains a valid signed JWT for it.
2. Attacker learns or predicts that victim intends to submit an HTTP trigger request to Workflow B with `requestID = "X"` (e.g., sequential/deterministic client IDs, or observed timing/logs).
3. Attacker sends `HandleUserTriggerRequest` for Workflow A with `req.ID = "X"`, which passes `authorizeRequest` for Workflow A and succeeds in `setupCallback`, inserting `h.callbacks["X"]`.
4. Victim sends their legitimate request for Workflow B with `req.ID = "X"`; `setupCallback` finds `h.callbacks["X"]` already present and returns `jsonrpc.ErrConflict` ("requestID: X has already been used..."), denying the victim's workflow execution — as demonstrated by the existing test `duplicate request ID` at [4](#0-3) .

func (h *httpTriggerHandler) validateRequestID(ctx context.Context, requestID string, callback handlers.Callback) error {
	if requestID == "" {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "'id' field is required and cannot be empty. Use a new unique request 'id' for each request", callback)
		return errors.New("empty request ID")
	}
	// Request IDs from users must not contain "/", since this character is reserved
	// for internal node-to-node message routing (e.g., "http_action/{workflowID}/{uuid}").
	if strings.Contains(requestID, "/") {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "request ID must not contain '/'", callback)
		return errors.New("request ID must not contain '/'")
	}
	return nil
}

func (h *httpTriggerHandler) authorizeRequest(ctx context.Context, workflowID string, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback) (*gateway_common.AuthorizedKey, error) {
	h.lggr.Debugw("authorizing request", "workflowID", workflowID, "requestID", req.ID)
	key, err := h.workflowMetadataHandler.Authorize(workflowID, req.Auth, req)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInvalidRequest, "Auth failure: "+err.Error(), callback)
		return nil, errors.Join(errors.New("auth failure"), err)
	}
	return key, nil
}

func (h *httpTriggerHandler) setupCallback(ctx context.Context, requestID string, callback handlers.Callback, requestStartTime time.Time, workflowID string) (<-chan struct{}, error) {
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()

	if _, found := h.callbacks[requestID]; found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrConflict, fmt.Sprintf("requestID: %s has already been used. Ensure the requestID is unique for each request.", requestID), callback)
		return nil, fmt.Errorf("in-flight request ID: %s", requestID)
	}
