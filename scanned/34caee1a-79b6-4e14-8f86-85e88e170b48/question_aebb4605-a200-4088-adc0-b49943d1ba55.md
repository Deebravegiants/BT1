Target: `ShopifyAPI::Auth::Oauth.validate_auth_callback` cookie/session id derivation for non-embedded apps (`cookie = SessionCookie.new(value: session.id, ...)`). Attacker action: attacker completes a self-owned dev-shop OAuth flow but supplies `shop=victim-shop.myshopify.com%00attacker.com`-style or unicode-confusable domain string (e.g., using a homoglyph or trailing dot `victim-shop.myshopify.com.`) as the `shop` query param, which still HMAC-validates because they compute the signature themselves over their own chosen string, and the sanitize! step that would normally reject non-canonical forms is entirely absent. Preconditions: app is non-embedded (`Context.embedded?` false) so `SessionCookie.value = session.id` is set in the browser directly. Call sequence: `Session.from(shop: auth_query.shop, ...)` builds `id = "offline_#{shop}"` using the raw, non-canonicalized string, and this id is placed verbatim into a cookie returned to the attacker's own browser. Binding that breaks: SHOP BINDING - the shop string used for session id equality checks elsewhere in the app (e.g., a lookup keyed by canonical `shop.myshopify.com`) must equal the canonicalized form that `ShopValidator.sanitize_shop_domain` would have produced; without that call, two different byte-strings that Shopify considers the same shop (or an attacker-chosen distinct string) can produce colliding or non-colliding ids arbitrarily. Scoped impact: Critical - if the host app's session store does simple string equality on `shop` for tenant isolation, an attacker-chosen non-canonical shop string can either collide with a legitimate stored session (cross-tenant access) or create a duplicate untrusted session entry that the app later trusts as belonging to the canonical shop. Proof idea: minitest calling `validate_auth_callback` twice with `shop: "victim-shop.myshopify.com"` and `shop: "Victim-Shop.MyShopify.Com"` (differing only in case, which `ShopValidator.sanitize_shop_domain` normalizes via `.downcase.strip` but `Oauth` never invokes), asserting the two resulting session ids differ even though they represent the same shop.
