### Title
Insufficient session termination when a new MFA (WebAuthn) credential is enrolled - (File: core/web/webauthn_controller.go)

### Summary
When a user enrolls a new WebAuthn/MFA credential via `WebAuthnController.FinishRegistration`, the node saves the new credential but never invalidates the user's other existing sessions. This mirrors the reported Joomla bug class: MFA management actions that change a user's authentication factors without terminating pre-existing sessions.

### Finding Description
`WebAuthnController.FinishRegistration` completes MFA enrollment and persists the new credential via `sessions.AddCredentialToUser` / `SaveWebAuthn`, then returns success — with no call to invalidate other active sessions for that user. [1](#0-0) 

By contrast, the password-change flow explicitly clears all other sessions for the user before applying the change, via `orm.ClearNonCurrentSessions(ctx, sessionID)`, showing this is the pattern the codebase considers necessary for a security-sensitive credential change: [2](#0-1) 

The `ClearNonCurrentSessions` method exists on the `AuthenticationProvider` interface and is implemented across all three auth backends (local, LDAP, OIDC), confirming it is the designated primitive for revoking stale sessions after a security-relevant account change: [3](#0-2) 

Enrolling a new WebAuthn credential is a comparable trust-boundary-changing action (it adds a new factor that can be used to authenticate as the user, and per Joomla's advisory class, this is exactly the type of MFA-method modification that should force re-authentication of all other sessions), yet `FinishRegistration` does not call `ClearNonCurrentSessions` or `DeleteUserSession` for other active sessions belonging to the same user.

### Impact Explanation
If an attacker gains a foothold sufficient to add a WebAuthn credential to a victim's account (e.g., via a fixed/hijacked session, XSS-driven request forgery against `/v2/enroll_webauthn`, or a stolen but still-valid session cookie), any of the victim's other legitimate sessions remain valid and unaffected. This weakens the security benefit of MFA enrollment as a recovery/hardening action — a compromised account cannot be effectively "locked out" of attacker-controlled sessions simply by adding MFA, unlike the password-change path which does force other sessions to expire.

### Likelihood Explanation
Exploitation requires the attacker to already have an authenticated context capable of hitting `/v2/enroll_webauthn` (session or token auth is required by the router), so this is not exploitable by a fully unauthenticated attacker. It is however concretely reachable by an unprivileged/limited attacker who already holds one valid session (e.g., via XSS, session fixation, or a leaked cookie) and wants to entrench persistence while other sessions (including the legitimate user's) stay alive unaffected.

### Recommendation
In `WebAuthnController.FinishRegistration` (core/web/webauthn_controller.go), after successfully saving the new WebAuthn credential, call `orm.ClearNonCurrentSessions(ctx, sessionID)` (using the current session ID, similar to `updateUserPassword` in core/web/user_controller.go) to terminate all other active sessions for that user, forcing re-authentication everywhere except the session that performed the enrollment.

### Proof of Concept
1. Attacker obtains a valid authenticated session for a target user (e.g. via XSS token theft, or session fixation if cookies aren't fully hardened).
2. Attacker calls `GET /v2/enroll_webauthn` then `POST /v2/enroll_webauthn` (`WebAuthnController.BeginRegistration` / `FinishRegistration`) to enroll their own WebAuthn key.
3. The legitimate user's original session(s) remain valid and unrevoked — verified by the absence of any `ClearNonCurrentSessions`/`DeleteUserSession` call in the `FinishRegistration` handler, contrasted with the explicit call present in the password-update path (core/web/user_controller.go:341-360).

```go
func (w *WebAuthnController) FinishRegistration(c *gin.Context) {
	ctx := c.Request.Context()
	user, ok := auth.GetAuthenticatedUser(c)
	if !ok {
		logger.Sugared(w.App.GetLogger()).AssumptionViolationf("failed to obtain current user from context")
		jsonAPIError(c, http.StatusInternalServerError, errors.New("unable to register key"))
		return
	}

	orm := w.App.AuthenticationProvider()
	uwas, err := orm.GetUserWebAuthn(ctx, user.Email)
	if err != nil {
		w.App.GetLogger().Errorf("failed to obtain current user MFA tokens: error in GetUserWebAuthn: %s", err)
		jsonAPIError(c, http.StatusInternalServerError, errors.New("unable to register key"))
		return
	}

	webAuthnConfig := w.App.GetWebAuthnConfiguration()

	credential, err := w.inProgressRegistrationsStore.FinishWebAuthnRegistration(*user, uwas, c.Request, webAuthnConfig)
	if err != nil {
		w.App.GetLogger().Errorf("error in FinishWebAuthnRegistration: %s", err)
		jsonAPIError(c, http.StatusBadRequest, errors.New("registration was unsuccessful"))
		return
	}

	if sessions.AddCredentialToUser(ctx, w.App.AuthenticationProvider(), user.Email, credential) != nil {
		w.App.GetLogger().Errorf("Could not save WebAuthn credential to DB for user: %s", user.Email)
		jsonAPIError(c, http.StatusInternalServerError, errors.New("internal Server Error"))
		return
	}

	// Forward registered credentials for audit logs
	credj, err := json.Marshal(credential)
	if err != nil {
		w.App.GetLogger().Errorf("error in Marshal credentials: %s", err)
		jsonAPIError(c, http.StatusBadRequest, errors.New("registration was unsuccessful"))
		return
	}
	w.App.GetAuditLogger().Audit(audit.Auth2FAEnrolled, map[string]any{"email": user.Email, "credential": string(credj)})

	c.String(http.StatusOK, "{}")
}
```

```go
func (u *UserController) updateUserPassword(c *gin.Context, user *clsession.User, newPassword string) error {
	ctx := c.Request.Context()
	sessionID, err := getCurrentSessionID(c)
	if err != nil {
		return err
	}
	orm := u.App.AuthenticationProvider()
	if err := orm.ClearNonCurrentSessions(ctx, sessionID); err != nil {
		u.App.GetLogger().Errorf("failed to clear non current user sessions: %s", err)
		return errors.New("unable to update password")
	}
	if err := orm.SetPassword(ctx, user, newPassword); err != nil {
		if errors.Is(err, clsession.ErrNotSupported) {
			return errUnsupportedForAuth
		}
		u.App.GetLogger().Errorf("failed to update current user password: %s", err)
		return errors.New("unable to update password")
	}
	return nil
}
```
