### Title
`EmporiumStack.signerAddress` is never verified to be a contract before being called as a `HinkalWallet`, allowing relay fees to be silently dropped - (File: `contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol`)

### Summary
`EmporiumUpgradeable.runAction` and its helper `payRelayFees`/`sendToRelayFromWallet` treat `stack.signerAddress` as the address of a deployed `HinkalWallet` contract and invoke `IHinkalWallet(stack.signerAddress).doSendToRelay(...)` on it, yet `verifyWallet` only proves that `signerAddress` is an address that produced a raw ECDSA signature (i.e., an EOA), never that it is actual contract code. Because `doSendToRelay` has a `void` return type, calling it on an address with no code succeeds silently in Solidity instead of reverting, so the relay fee transfer is skipped while the rest of the transaction (and the internal `deltaAmountChanges` accounting) proceeds as if the fee had been paid.

### Finding Description
`verifyWallet` authenticates `stack.signerAddress` purely via `ECDSA.tryRecover`: [1](#0-0) 
This only proves that whoever crafted `(v, r, s)` controls the private key behind `signerAddress` — i.e., `signerAddress` must be capable of acting as an EOA signer. There is no check anywhere in `runAction` or `verifyWallet` that `signerAddress` actually has contract code (no `extcodesize`, no registry/factory lookup against deployed `HinkalWallet` instances).

Despite this, `runAction` and `payRelayFees` treat `signerAddress` as a `HinkalWallet` contract and call it through the `IHinkalWallet` interface: [2](#0-1) [3](#0-2) 

`doSendToRelay` on `IHinkalWallet` has no return value: [4](#0-3) 

In Solidity, a high-level external call to a function with no return value does not decode any return data. If the target address has no code (an EOA), the underlying `CALL` still returns success with empty return data, and since nothing is decoded, the call appears to succeed with no revert and no state effect. This is precisely the class of bug flagged in the external report (KintoWallet `_recoverer` not restricted to a contract): a function meant to operate on a contract wallet is reachable with an EOA, and here that silently no-ops a value-moving call instead of reverting.

`payRelayFees` computes `relayFee` deterministically from the (signature-committed) `feeStructure.flatFee` and routes it through `payRelay` → `sendToRelayFromWallet` → `IHinkalWallet(signerAddress).doSendToRelay(...)`: [5](#0-4) [6](#0-5) 

Because `signerAddress` is part of `circomData.externalActionData.externalActionMetadata`, which is bound into `calldataHash` and ultimately into the EdDSA `signedMessageHash` verified by the circuit, the *value* of `signerAddress` is authorized by the shielded-note owner — but its *type* (EOA vs. contract) is never constrained. Any unprivileged caller can therefore construct an `EmporiumStack` where `signerAddress` is their own EOA (trivially self-signed with their own key), pass `verifyWallet`, and have `doSendToRelay` silently do nothing while the surrounding transaction (proof verification, balance/slippage checks, UTXO creation) completes normally.

### Impact Explanation
The relay that services the transaction is never actually paid the fee it is owed, even though the protocol's accounting (`deltaAmountChanges`, `feeStructure.flatFee`) assumes the fee leg executed. This is a direct, unauthorized loss of protocol/relay fee revenue with no revert to signal failure — matching "High - theft ... of protocol/relay fees" in the accepted impact list. It does not require any admin, relay, or another user's key: the attacker only needs their own EOA key, which they already control.

### Likelihood Explanation
Likelihood is high for any user who wants to avoid paying relay fees on stateful (`invokeWallet`) Emporium operations: they simply set `signerAddress` in their self-authored `EmporiumStack` to an EOA under their control and self-sign with `ECDSA` (standard `eth_sign`/`personal_sign`-style recover), satisfying `verifyWallet` with no additional privilege.

### Recommendation
Before calling `IHinkalWallet(stack.signerAddress).callHinkalWallet(...)` or `doSendToRelay(...)`, verify that `signerAddress` has contract code (e.g., `signerAddress.code.length > 0`) and/or that it is a `HinkalWallet` instance registered/deployed by the protocol (e.g., via a factory-tracked mapping), rather than relying solely on an ECDSA recovery match. Additionally, consider changing `doSendToRelay` to return an explicit success value and have callers require `success == true`, so that calls to non-contract addresses cannot silently no-op.

### Proof of Concept
1. Attacker deploys/uses an ordinary EOA address `E` (their own account) as `signerAddress`.
2. Attacker builds `EmporiumOperation[]` with `invokeWallet = true` (or simply relies on the fee path) and crafts `EmporiumStack{ v, r, s, signerAddress: E, ops, maxFee, deadline }` such that `(v,r,s)` is a valid ECDSA signature over the EIP-712 hash produced by `_hashEmporiumOps`/`EMPORIUM_SIGNATURE_TYPEHASH`, self-signed with `E`'s private key.
3. Attacker embeds this stack into `circomData.externalActionData.externalActionMetadata`, computes matching `calldataHash`/`signedMessageHash`, and produces a valid ZK proof (they are the legitimate owner of the shielded notes being spent).
4. Calls `Hinkal.transact(...)` → `EmporiumUpgradeable.runAction` → `verifyWallet` passes (recoveredAddress == E == signerAddress).
5. `payRelayFees` computes `relayFee = feeStructure.flatFee` and calls `sendToRelayFromWallet(relay, E, relayFee, feeToken)` → `IHinkalWallet(E).doSendToRelay(relay, relayFee, feeToken)`.
6. Since `E` is an EOA with no code, the external call to the void-returning `doSendToRelay` succeeds with no state change; no tokens move to `relay`.
7. Transaction completes successfully; relay fee is never paid despite the protocol's accounting treating it as settled.

```text
    function payRelayFees(
        CircomData calldata circomData,
        address signerAddress,
        int256[] calldata deltaAmountChanges
    ) internal {
        FeeStructure calldata feeStructure = circomData.feeStructure;

        bool foundToken = false;

        for (uint256 i = 0; i < circomData.erc20TokenAddresses.length; i++) {
            // tokens deposited into Emporium are not charged
            if (deltaAmountChanges[i] >= 0) {
                continue;
            }

            address erc20TokenAddress = circomData.erc20TokenAddresses[i];
            bool isFeeToken = erc20TokenAddress == feeStructure.feeToken;

            if (isFeeToken) {
                foundToken = true;
            }

            uint256 relayFee = 0;
            uint256 flatFee = isFeeToken ? feeStructure.flatFee : 0;

            if (signerAddress == address(0)) {
                uint256 sumAbs = uint256(-deltaAmountChanges[i]);

                EmporiumStorageVars storage $ = _getEmporiumStorage();
                relayFee = $._hinkalHelper.calculateRelayFee(
                    sumAbs,
                    flatFee,
                    feeStructure.variableRate
                );
            } else {
                relayFee = flatFee;
            }

            payRelay(
                circomData.relay,
                signerAddress,
                relayFee,
                erc20TokenAddress
            );
        }

        if (!foundToken && feeStructure.flatFee != 0) {
            require(
                signerAddress != address(0),
                "Gas Token in Emporium is not found"
            );

            payRelay(
                circomData.relay,
                signerAddress,
                feeStructure.flatFee,
                feeStructure.feeToken
            );
        }
    }
```
