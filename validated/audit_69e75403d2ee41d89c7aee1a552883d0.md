### Title
Ratio-matched hostile pre-seed can force `_seedDirectMint`'s non-empty-pool `mint()` to donate protocol LP value to the pre-seeder - ([File: packages/contracts/src/Bonding.sol])

### Summary
`Bonding._seedRebalancing` is supposed to neutralize a hostile HyperSwap V2 pre-seed by swapping the pool back toward the curve-close ratio before depositing. When the corrective swap size rounds to zero, the code silently falls back to `_seedDirectMint`, which calls `pair.mint(lpLock)` unconditionally — even against a pre-seeded pool with non-trivial, non-dust reserves. On a non-empty pool, Uniswap V2's `mint()` uses `min(amount0*totalSupply/reserve0, amount1*totalSupply/reserve1)`, which donates the mismatched side to the pre-existing LP supply. Because that pre-existing LP supply is 100% owned by the attacker who pre-seeded the pair, the attacker can redeem an inflated share of the protocol's curve-raised LT/tokens.

### Finding Description
`_seedUniswapV2Direct` branches on `IUniswapV2Pair(pair).totalSupply() == 0` [1](#0-0) . When an attacker has pre-created the HyperSwap V2 TOKEN/LT pair and self-funded a `mint()` before graduation (Regime 3, "mint pre-seed"), `totalSupply != 0`, so the code enters `_seedRebalancing`.

`_seedRebalancing` first checks whether both reserves are below `DIRECT_MINT_PRESEED_BPS` (1 bp) of the LP targets; if so it takes the "overpower with direct mint" shortcut, which the natspec explicitly says is safe only because the reserves are "negligible" [2](#0-1) . Otherwise it attempts a corrective swap via `_pairRebalance`, and **if that swap fails to execute it falls back to the same `_seedDirectMint` unconditionally, without re-checking that reserves are actually dust-sized**: [3](#0-2) 

`_pairRebalance` returns `false` — and thus triggers this fallback — whenever the no-fee-model required swap `s` rounds to zero, or the pair's fee-charging `getAmountOut(s)` rounds to zero: [4](#0-3) 

`_noFeeSwapInput` computes `s = sqrt(reserveIn*reserveOut*targetN/targetD) - reserveIn`, using integer `sqrt` and floor division [5](#0-4) . This value truncates to `0` whenever the pre-seeded ratio is already extremely close to the eventual curve-close ratio — this is *not* restricted to small absolute reserves; an attacker can pre-seed with large, non-dust reserve amounts as long as the ratio is engineered to sit inside this rounding dead-zone (or the fee-adjusted output of the minimal corrective swap floors to zero).

Once that dead-zone is hit, execution falls through to `_seedDirectMint`, which transfers the *entire* cached `tokensForLP`/`ltFromPair` (the protocol's curve-raised LT and up to `LP_RESERVE` = 250M tokens) into the pool and calls `pair.mint(lpLock)` [6](#0-5) . Against a non-empty pool, standard V2 `mint()` semantics mint `min(amount0*totalSupply/reserve0, amount1*totalSupply/reserve1)` LP to `lpLock`; the side that isn't the binding minimum is "donated" as extra reserves with no corresponding new LP claim. Since the attacker owns 100% of `totalSupply` from their own earlier self-funded `mint`, that donated value inflates the redeemable worth of the attacker's own (unlocked, freely transferable) LP tokens — the attacker can later call `pair.burn` and withdraw a slice of the protocol's graduation liquidity that was never reflected in `LPLock`'s locked position.

This directly contradicts the code's own stated safety invariant that the direct-mint fallback is safe "against dust reserves" only [7](#0-6) : the fallback is reachable from `_pairRebalance` returning `false` for reasons unrelated to reserve size (rounding of the *corrective delta*, not of the reserves themselves).

### Impact Explanation
This lets an unprivileged attacker steal a slice of the protocol- and creator-earned graduation liquidity (curve-raised LT plus up to 250M launched tokens) that should be permanently locked via `LPLock.recordLock` [8](#0-7) . Because the attacker's own LP position from the pre-seed mint is never routed through `LPLock`, the diverted value is fully withdrawable by the attacker — this is a direct theft of LP-bound funds and an "LP seeded away from the curve close price," matching the validated impact classes for this contest. It is repeatable for every token launch the attacker chooses to target, since pre-creating/pre-seeding the pair is fully permissionless and unprivileged.

### Likelihood Explanation
Reachable with only unprivileged transactions: (1) call `IUniswapV2Factory.createPair`/pre-fund and `mint()` the TOKEN/LT pair before a target token graduates (explicitly listed as in-scope: "pre-creating or pre-seeding the HyperSwap V2 TOKEN/LT pair before graduation"); (2) size the pre-seed ratio to land inside the `_noFeeSwapInput` rounding dead-zone relative to the token's known/observable `(tokensForLP, ltFromPair)` trajectory — an attacker can iterate/adjust the pre-seed (top up via `transfer`+`sync`, or add via `mint`) while watching the curve state up to the moment `finalizeGraduation` is called, since phase 2 is permissionless and its timing/inputs (`pendingGraduation`) are visible on-chain once `TokenGraduating` fires. Because `(tokensForLP, ltFromPair)` are frozen and public in `pendingGraduation` right after phase 1, the attacker has a deterministic target to ratio-match before calling `finalizeGraduation` themselves (it's permissionless).

### Recommendation
- In `_seedRebalancing`, do not treat "`_pairRebalance` returned false" as equivalent to "reserves are dust." Explicitly re-check the `DIRECT_MINT_PRESEED_BPS` dust bound (or an equivalent bound on the *absolute* reserve size) before falling back to `_seedDirectMint`; if reserves are non-dust and the corrective swap still can't execute, revert or route through a safe balanced deposit (e.g., router `addLiquidity` at the current ratio without minting into an unlocked mismatch) instead of `pair.mint` against non-empty reserves.
- Alternatively, make `_seedDirectMint`'s `pair.mint` path itself detect a non-zero `totalSupply` and refuse to call `mint` directly in that case, forcing the caller into `_routerDepositAndDispose`'s quote-based balanced deposit regardless of how small the reserves appear.

### Proof of Concept
1. Attacker computes/approximates the target token's eventual curve-close ratio (LP is fixed at `tokensForLP/ltFromPair` once phase 1 fires and is publicly readable via `pendingGraduation`).
2. Attacker calls `IUniswapV2Factory.createPair(token, lt)` then self-funds and calls `pair.mint(attacker)` with sizable (non-dust) `(tokenAmt, ltAmt)` chosen so that, versus the eventual `(tokensForLP, ltFromPair)`, `_noFeeSwapInput`'s `sqrt(reserveIn*reserveOut*targetN/targetD) - reserveIn` rounds to `0`, or the resulting `getAmountOut` on the pair rounds to `0`.
3. Anyone calls `Bonding.finalizeGraduation(token)`. `_seedRebalancing` computes `s = 0` (or `expectedOut = 0`), `_pairRebalance` returns `false`, and execution falls into `_seedDirectMint`, transferring the full `tokensForLP`/`ltFromPair` into the already non-empty pool and calling `pair.mint(lpLock)`.
4. V2's `min()` formula mints `lpLock` LP proportional to the binding side only; the non-binding side's excess sits as reserves backing the attacker's pre-existing 100%-owned LP supply.
5. Attacker calls `pair.burn` on their own (unlocked) LP tokens and withdraws the inflated share of TOKEN/LT — extracting value that should have been wholly locked in `LPLock`.

```text
    function _pairRebalance(
        RebalanceParams memory p
    ) internal returns (bool) {
        uint256 s = _noFeeSwapInput(p.reserveIn, p.reserveOut, p.targetN, p.targetD, p.maxSwap);
        if (s == 0) return false;

        // Quote from the pair so the output tracks its live fee; a value
        // derived from a stale fee rate would trip the pair's K-check.
        uint256 expectedOut = IUniswapV2Pair(p.pair).getAmountOut(s, p.tokenIn);
        if (expectedOut == 0) return false;

        IERC20(p.tokenIn).safeTransfer(p.pair, s);
        (uint256 amount0Out, uint256 amount1Out) = p.tokenInIs0 ? (uint256(0), expectedOut) : (expectedOut, uint256(0));
        IUniswapV2Pair(p.pair).swap(amount0Out, amount1Out, address(this), new bytes(0));
        return true;
    }
```

```text
    function _noFeeSwapInput(
        uint256 reserveIn,
        uint256 reserveOut,
        uint256 targetN,
        uint256 targetD,
        uint256 maxSwap
    ) internal pure returns (uint256) {
        if (reserveIn == 0 || reserveOut == 0 || targetN == 0 || targetD == 0 || maxSwap == 0) {
            return 0;
        }
        uint256 product = Math.mulDiv(reserveIn * reserveOut, targetN, targetD);
        uint256 newIn = Math.sqrt(product);
        if (newIn <= reserveIn) return 0;
        uint256 s = newIn - reserveIn;
        return s > maxSwap ? maxSwap : s;
    }
```

```text
    /// @notice Record an LP lock. LP tokens must already sit at this address.
    function recordLock(
        address token,
        address lpPair,
        uint256 amount
    ) external {
        LPLockStorage storage $ = _s();
        if (!$.isLocker[msg.sender]) revert NotAuthorized();
        if (lpPair == address(0)) revert ZeroAddress();
        if (amount == 0) revert ZeroAmount();
        // `lockedAt` is the one-shot sentinel: it is always set to a non-zero
        // timestamp on the first lock, so the guard holds for any `amount`.
        if ($.locks[token].lockedAt != 0) revert AlreadyLocked();
        if (IERC20(lpPair).balanceOf(address(this)) < amount) revert InsufficientLPBalance();
        $.locks[token] = LockInfo({lpPair: lpPair, amount: amount, lockedAt: block.timestamp});
        emit LPLocked(token, lpPair, amount);
    }
```
