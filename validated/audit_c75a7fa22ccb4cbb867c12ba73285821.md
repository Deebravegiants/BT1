## Title
Missing Source Authorization Check on `RequestState` Handling Allows Unauthenticated Replay Trigger - (File: `orb-relay-client/src/client.rs`)

### Summary
The report's root bug class is a privileged/state-mutating action (`RequestBandPrice`) being triggered without verifying that the caller is an authorized party. `orb-relay-client`'s `PollerAgent::main_loop` contains the same class of flaw: incoming messages are normally gated by an explicit check that the message's `src.id` matches the connected session's `dst_id` [1](#0-0) , but the `RequestState` message type is special-cased to bypass this check entirely and unconditionally triggers a reply [2](#0-1) .

### Finding Description
In `PollerAgent::main_loop`, every inbound `RelayPayload` is dispatched based on its decoded protobuf payload type. For all message types except `self_serve::app::v1::RequestState`, the code enforces that `src.id == self.config.dst_id` before calling `handle_message`, rejecting anything else as "unexpected source" [1](#0-0) . However, the `RequestState` branch is checked *first* and unconditionally replies with `self.last_message` to `sender_tx` without any equivalent `src.id` verification [2](#0-1) .

This client (`orb-relay-client`) is used by orb-core during self-serve signups to communicate over `orb_relay` with the paired App, including announcing the orb ID and coordinating biometric-capture triggers [3](#0-2)  and gating the start of biometric capture on a `StartCapture` message received over this same channel [4](#0-3) . The `wait_for_msg`/`check_for_msg` helpers used for these safety-critical waits pull messages out of the same shared buffer populated by this loop [5](#0-4) [6](#0-5) .

### Impact Explanation
Because the `RequestState` handler skips the `src.id` authorization check that every other message type is subject to, any entity able to place a `RequestState`-typed payload onto this stream (regardless of whether it is the legitimately paired App for this session) can force the orb to immediately re-transmit its last outgoing message (e.g. `AnnounceOrbId`, `CaptureStarted`, signup-state messages) to whoever is on the other end of the connection. This breaks the trust boundary the surrounding code otherwise enforces (`src.id != self.config.dst_id` guard), which is exactly the "missing access control before privileged action" pattern from the report: an operation is not properly checking that the caller is the authorized session participant before it is executed.

### Likelihood Explanation
The relay session is established per orb/app pairing using an `orb_relay_app_id`/`session_id` obtained from a validated user QR-code flow [7](#0-6) , so exploitation requires the ability to inject a payload with an arbitrary `src` on that specific stream (e.g., a relay-server-side routing weakness, or a scenario where the same relay connection multiplexes multiple senders, which the existing `src.id` check for non-`RequestState` messages already anticipates). The code explicitly demonstrates that messages from unexpected sources can arrive on this stream (hence the existing guard for other message types), making the missing guard on `RequestState` a concrete gap rather than a theoretical one.

### Recommendation
Apply the same `src.id == self.config.dst_id` authorization check to the `RequestState` branch before replaying `self.last_message`, consistent with how all other inbound message types are validated.

### Proof of Concept
1. Establish a relay connection where the stream can deliver a `RelayPayload` whose `payload` decodes as `self_serve::app::v1::RequestState` but whose `src.id` differs from `self.config.dst_id`.
2. Observe that the `else if src.id != self.config.dst_id` rejection path [1](#0-0)  is never reached for this message type because the `RequestState` branch is checked first and unconditionally executes `sender_tx.send(self.last_message.clone())` [2](#0-1) .

        for msg in self.get_buffered_messages().await {
            if let Some(payload) = &msg.payload {
                if let Some(specific_payload) = T::matches(payload) {
                    return Some(specific_payload);
                }
                tracing::warn!(
                    "While waiting for payload of type {:?}, we got: {:?}",
                    type_name::<T>(),
                    debug_any(&msg.payload)
                );
            }
        }
        None
    }

    pub async fn wait_for_msg<T: PayloadMatcher>(&self, wait: Duration) -> Result<T::Output> {
        let start_time = tokio::time::Instant::now();
        loop {
            if let Some(payload) = self.check_for_msg::<T>().await {
                return Ok(payload);
            }
            if start_time.elapsed() >= wait {
                return Err(eyre::eyre!(
                    "Timeout waiting for payload of type {:?}",
                    std::any::type_name::<T>()
                ));
            }
            tokio::time::sleep(Duration::from_millis(100)).await;
        }
    }
