### Title
Residual (non-output) token balances stranded on the shared `CallDispatcher` after postdispatch calldata execution are drainable by any caller — ([File: evm/src/apps/intentsv2/IntentsBase.sol])

### Summary
`IntentsBase._execute()` only sweeps back the specific output tokens declared in `order.output.assets` after running a solver-attached postdispatch call through the `CallDispatcher`. Because `CallDispatcher.dispatch()` has no access control and is a single shared contract for the whole gateway, any token balance left on it that is *not* one of the order's declared output tokens (e.g. an intermediate/residual token produced by a DEX route, reward token, or dust from an "exact-output" style swap) is never collected, and — unlike the reported GlueX bug where funds merely sit in the Executor — here they can be stolen immediately by any unprivileged account calling `CallDispatcher.dispatch()` directly with a transfer call, since the dispatcher is not restricted to the gateway.

### Finding Description
`_execute()` runs solver-supplied calldata via the shared `CallDispatcher`, then sweeps only the tokens present in `order.output.assets[0..outputsLen)`: [1](#0-0) 

The sweep loop is keyed strictly off `order.output.assets`, so any token balance the postdispatch calldata leaves on the dispatcher that is not in that fixed list is skipped entirely — no `DustCollected` event, no transfer back to the gateway, nothing. This is structurally identical to the GlueX finding: the flow assumes calldata execution consumes/produces exactly the declared tokens (an "exact input"/"exact output" assumption), but real DEX routes (e.g. `swapTokensForExactTokens`-style calls, multi-hop routes, or routes that pay out an unexpected token) can leave unaccounted-for balances behind.

The critical amplification versus the GlueX report is that `CallDispatcher.dispatch()` itself is completely permissionless: [2](#0-1) 

There is no `onlyGateway`/`onlyOwner` check — `dispatch` can be invoked by anyone, targeting any contract, including the dispatcher's own held ERC-20 tokens (via `transfer`) or native ETH (via `call{value:...}`). Because the same `CallDispatcher` instance is shared across all orders (`_params.dispatcher`), once one order's postdispatch call strands a non-output token there, any third party — not just the filling solver — can call the dispatcher directly to sweep that balance to themselves before governance's `_sweepDust` (which only operates on the gateway's own balance, `address(this)`, not the dispatcher's) can ever recover it.

The predispatch path documented for `placeOrder` follows the analogous pattern (assets sent to the dispatcher, calldata executed, results transferred back for escrow) and is subject to the same class of gap for any token produced outside the expected transfer list.

### Impact Explanation
This constitutes concrete, permanent theft of protocol/user funds: any residual token left in the shared, unauthenticated `CallDispatcher` after a `fillOrder()` postdispatch execution is not merely "stuck" (as in the reported analog) but actively stealable by any unprivileged third party who front-runs or simply calls `CallDispatcher.dispatch()` before a sweep ever happens. Given the dispatcher is a single shared contract across all orders and all users of the IntentGateway, this is a systemic, repeatable drain vector, not a one-off accounting quirk — qualifying as Medium/High severity theft of funds.

### Likelihood Explanation
Likelihood is realistic: postdispatch calldata (`order.output.call`) is solver-controlled and explicitly designed to route through arbitrary DeFi protocols/DEXes per the documented composability feature. Any route that is not a clean 1:1 "exact-output-for-declared-token" swap (e.g., multi-hop paths returning intermediate tokens, reward-token payouts, slippage-protected swaps that refund a different token) will leave a balance the `outputsLen`-scoped sweep cannot see. No special privilege is needed to trigger the stranding (an ordinary solver's fill can create it) nor to steal it (any address can call the public `CallDispatcher.dispatch()`).

### Recommendation
- Restrict `CallDispatcher.dispatch()` to only be callable by the registered `IntentGateway`(s) (e.g., an `onlyGateway` modifier keyed off `_params` or a per-gateway allowlist), removing the permissionless drain vector entirely.
- In `_execute()`, do not scope the sweep exclusively to `order.output.assets`; either require postdispatch calldata to be validated/simulated against an explicit allowlist of tokens it may touch, or sweep the dispatcher's full balance of any token referenced by the executed calls (not just declared outputs), crediting the excess as protocol dust via `DustCollected`/`_sweepDust`.
- Apply the same review to the predispatch flow to ensure any token minted/received that isn't part of the expected transfer set back to the gateway is also swept rather than left on the dispatcher.

### Proof of Concept
1. A solver calls `IntentsV2.fillOrder()` for an order whose `order.output.call` routes through a DEX in a way that leaves a small balance of Token X (not one of `order.output.assets`) on the shared `CallDispatcher` (analogous to the `swapTokensForExactTokens` scenario in the external report, where more input than needed is sent through the router and change is returned to the dispatcher rather than the declared output token).
2. `_execute()` runs, sweeps only the declared output tokens, and returns; the Token X balance remains on `CallDispatcher`.
3. Any third-party attacker, with no relation to the order, calls `CallDispatcher.dispatch(abi.encode([Call({to: TokenX, value: 0, data: abi.encodeWithSelector(IERC20.transfer.selector, attacker, balance)})]))` directly — this succeeds because `dispatch()` has no caller restriction — draining the stranded Token X to the attacker's address.

    function _execute(Order calldata order, uint256 outputsLen) internal {
        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            } else {
                uint256 balance = IERC20(token).balanceOf(dispatcher);
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            }

            unchecked {
                ++i;
            }
        }

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
