### Title
Unvalidated route lets attacker-injected hop code run under the caller's signed auth tree and drain wallet tokens - (File: contracts/controller/src/strategies/swap.rs)

### Summary
The "command injection" bug class (CVE-2016-6655) maps onto XOXNO Lending as **arbitrary contract invocation injected through user-supplied route data**. Every controller strategy verb (`multiply`, `swap_debt`, `swap_collateral`, `repay_debt_with_collateral`) forwards caller-supplied `swap_xdr` bytes to the swap router without validating the pool/token addresses inside it. The router then `invoke_contract`s whatever contracts the payload names. A malicious route can therefore place attacker-controlled code on the call stack beneath the victim's `require_auth`, and that code can append a `token.transfer(victim → attacker, X)` as a child of the victim's signed authorization tree. Simulation faithfully records this child, the wallet signs the whole tree, and the victim loses arbitrary wallet tokens — a loss neither the router's `min_out` check nor the controller's risk gates bound.

### Finding Description
`swap_tokens` reads the configured router, authorizes exactly one input transfer from the controller, and executes the caller-supplied `StrategySwap` payload verbatim: [1](#0-0) 

Neither the controller nor the router constrains which contracts a hop may name. The router dispatches each hop's `pool` address to `env.invoke_contract` (e.g., `comet::swap` calls `ctx.hop.pool.swap_exact_amount_in`, and `dispatch_hop` only measures balance deltas around the call): [2](#0-1) [3](#0-2) 

Because hop code executes while the original `caller.require_auth()` frame is still on the stack, any `token.transfer` it issues against the caller appears as a sub-invocation of the caller's own auth entry. The threat model states this plainly: "a route can put third-party code on the call stack below the caller's authorization … a token transfer that such code makes from the caller … executes if the caller signs that tree. The loss is then the caller's wallet, not the routed amount." [4](#0-3) 

The harness test proves the mechanics end-to-end: a `RogueHopPool` embedded in the `swap_xdr` of a `swap_collateral` call records the wallet-draining `transfer` under Alice's signed `swap_collateral` entry, and the transfer executes once she signs the simulated tree: [5](#0-4) [6](#0-5) 

### Impact Explanation
**Theft of user funds.** An attacker who can influence a victim's route construction (malicious quote server, phishing frontend, tampered SDK output — exactly the channels `skills/xoxno-swap-aggregator/payload.md` warns must be re-verified client-side) can steal *any* token the victim's wallet holds, in *any* amount, by embedding a rogue "pool" contract whose `swap` function issues `token.transfer(victim, attacker, balance)`. The theft is entirely outside the routed amount: `min_out`, the controller's `RouterOverspend`/`NoSwapOutput` measurements, and post-trade health-factor checks all pass, because the fair output is still delivered while the wallet is drained on the side. No privileged role is needed — the attacker only needs to author the route bytes a victim signs.

### Likelihood Explanation
Likelihood is driven by the signing UX rather than by contract access. `simulateTransaction` produces the auth tree automatically and wallets sign the returned tree as a blob; an honest route produces zero child invocations under `swap_collateral`/`swap_debt` (and exactly one input transfer under `execute_strategy`), but nothing at the contract layer *enforces* that invariant. The threat model itself pushes the defense onto clients ("a client must decode the route it signs"), and the SDK verification helpers (`verifyRouteBytes`, `verifyRoutePayload`) are opt-in — a route delivered through any unverified channel silently carries the poisoned child. Any user who signs a route produced by a compromised or malicious quote source is drained.

### Recommendation
Enforce at the contract layer, not in documentation:

1. In the swap router, maintain an owner-managed allowlist of permitted hop `pool` addresses per venue (or per token pair) and reject hops naming unlisted contracts in `dispatch_hop`.
2. Alternatively/additionally, run each hop's external call under a *re-auth-scoped* context so venue code cannot piggyback on the caller's auth tree — e.g., have the router custody the input itself and ensure no `require_auth`-able caller frame is reachable from hop code.
3. In the controller, consider restricting accepted `swap_xdr` to routes whose hop set resolves to known venues, since `swap_tokens` is the privileged entry that forwards attacker bytes into a signed flow.

### Proof of Concept
Already demonstrated in-repo by `tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs`:

1. `RogueHopPool` is deployed with a plan `(victim=alice, wallet_token, to=attacker, amount=WALLET_BALANCE)`; its `swap` executes `token.transfer(victim, to, amount)`.
2. Attacker crafts `swap_xdr` routing `swap_collateral(alice, account, USDC→ETH)` through the rogue pool address.
3. Simulation records `token.transfer(alice, attacker, WALLET_BALANCE)` as a child of Alice's `swap_collateral` auth entry (`simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry` asserts the recorded tree and Alice's wallet → 0).
4. `enforced_auth_moves_the_wallet_token_only_when_the_signed_tree_lists_the_rogue_transfer` confirms that once Alice signs the simulation-produced tree, the transfer executes and `WALLET_BALANCE` moves to the attacker — while the swap itself still settles fairly (`FAIR_OUT_ETH` credited), so all contract-side output/risk checks pass.

fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
}
