### Title
RAY value overflow before index-cap enforcement permanently freezes an oversized market - (File: contracts/pool/src/interest.rs)

### Summary
High severity: once a market’s scaled supply or debt value exceeds the `i128` result domain, every interest accrual panics before the borrow-index ceiling can stop growth, permanently blocking exits, repayments, liquidations, and recapitalization. [1](#0-0) [2](#0-1) 

### Finding Description
Market positions and totals are stored as RAY-scaled shares, while accrual reconstructs their underlying value through `scaled_to_original`. [3](#0-2) 

`scaled_to_original` calls `Ray::mul`, which evaluates `scaled * index / RAY` and panics with `MathOverflow` when the resulting RAY value does not fit in `i128`. [4](#0-3) [5](#0-4) 

Although intermediate products are widened to `I256`, the final converted market value itself still has to fit `i128`. [6](#0-5) 

The ordering is unsafe because `accrue_step` evaluates both the old total debt and old total supply before computing or capping the next borrow index. [7](#0-6) 

`update_borrow_index` clamps only the index to `MAX_BORROW_INDEX_RAY`; it does not protect the earlier `borrowed * borrow_index / RAY` or `supplied * supply_index / RAY` value reconstruction. [8](#0-7) 

Every market mutation leg calls `synced_market`, which unconditionally invokes `global_sync` before the operation-specific state transition. [9](#0-8) 

The direct index-sync operation has the same behavior: it loads each market and calls `global_sync` before committing state. [10](#0-9) 

An unprivileged caller can reach this path through `Controller::update_indexes(caller, assets)`, which only requires caller authorization and forwards `assets` to the pool’s owner-only `update_indexes`. [11](#0-10) [12](#0-11) 

The repository’s integration test demonstrates the reachable state: a one-billion-token, eighteen-decimal market at 98% utilization eventually fails accrual with `MATH_OVERFLOW`, while the stored borrow index remains below its cap. [13](#0-12) 

### Impact Explanation
Once the stored scaled position reaches the RAY-value ceiling, no accrual can complete and `last_timestamp` cannot advance, so every operation that accrues first reverts on `MathOverflow`. [14](#0-13) [9](#0-8) 

Suppliers cannot withdraw, borrowers cannot repay, and liquidators cannot rescue the account because those paths all load the same interest-synced market. [15](#0-14) [16](#0-15) [17](#0-16) 

Because both indexes are otherwise non-decreasing during accrual and the failing values are reconstructed from already-stored state, there is no unprivileged path that can lower the state enough to recover the market. [18](#0-17) [19](#0-18) 

The result is permanent freezing of user funds and a market unable to operate, satisfying the highest-impact availability class even though it does not directly transfer funds. [2](#0-1) 

### Likelihood Explanation
The condition is not reachable from ordinary small balances: the demonstrated market contains one billion whole units of an eighteen-decimal asset and approximately 98% debt utilization. [20](#0-19) 

A successful attack also requires the market configuration to admit that size and enough ledger accrual for the relevant index to cross the value ceiling. [21](#0-20) 

Those requirements make this a capital- and state-dependent availability failure rather than an immediate zero-cost denial of service, but the triggering `update_indexes` call itself is permissionless. [11](#0-10) [22](#0-21) 

### Recommendation
Compute current debt and supply values through saturating or explicitly bounded conversion before accrual, and clamp the borrow index before attempting to derive a new total value. [7](#0-6) [18](#0-17) 

Alternatively, cap stored `borrowed` and `supplied` share totals so `shares * index / RAY` is always representable at the protocol’s maximum index, and enforce that bound in every minting path. [23](#0-22) [24](#0-23) 

A recovery path should also be able to write the capped index and timestamp without first reconstructing an unrepresentable total, otherwise the state cannot be repaired once crossed. [25](#0-24) 

### Proof of Concept
The existing integration test is a direct proof of concept: it creates an eighteen-decimal market, deposits `BILLION * 10^18` base units, supplies collateral, borrows `98%` of the deposited market asset, then repeatedly calls `update_indexes` until the call returns `MATH_OVERFLOW`. [26](#0-25) 

At that point, the stored borrow index is still below `MAX_BORROW_INDEX_RAY`, proving that value reconstruction fails before index-cap enforcement. [27](#0-26) 

The same test then demonstrates that both a supplier withdrawal and borrower repayment fail with `MATH_OVERFLOW`, establishing the permanent market-freeze condition. [17](#0-16)
