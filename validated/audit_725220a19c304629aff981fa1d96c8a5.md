### Title
Debt-value overflow in `scaled_to_original` permanently freezes a market — every entrypoint accrues first and panics - ([File: contracts/pool/src/interest.rs])

### Summary
The CVE class is "an unauthenticated input reaches a code path that crashes the service." In XOXNO Lending the crash surface is the shared accrual step: `accrue_step` computes `scaled_to_original(borrowed, borrow_index)` before doing anything else, and `global_sync` runs it before every pool mutation (`supply`, `borrow`, `withdraw`, `repay`, `seize_positions`, `flash_loan`, `claim_revenue`, `recapitalize`). When `borrowed * borrow_index` no longer fits in `i128`, the accrual panics with `MathOverflow`, which bricks the market permanently for all users — the borrow index cap at `MAX_BORROW_INDEX_RAY` is applied *after* the overflowing multiply, so it never engages in time. ### Finding Description
Every controller verb calls into the pool, which first runs `global_sync` → `accrue_chunk` → `accrue_step` (`contracts/pool/src/interest.rs:20-53`). `accrue_step` begins with `scaled_to_original(env, borrowed, borrow_index)` (`common/src/rates/simulate.rs:60`), an i128 multiply-divide that raises `GenericError::MathOverflow` when `borrowed * borrow_index` exceeds `i128::MAX` (`common/src/math/fp_core.rs:108-118`). `update_borrow_index` caps the index at `MAX_BORROW_INDEX_RAY` (`common/src/rates/index.rs:13-19`), but at that point `scaled_to_original` has already overflowed. The invariants doc admits this: "Debt-value overflow can still revert accrual before that ceiling is reached. Bounded indexes do not guarantee representable position or market values" (`docs/reference/invariants.md`, INV-IDX-01). A dedicated regression test proves the freeze: after the cliff, `update_indexes`, `withdraw`, and `repay` all revert with `MATH_OVERFLOW` and "The market is frozen: exits and repayments accrue first and hit the same panic" (`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:316-361`).

Unlike a per-transaction fail-closed revert, the bad state is *stored*: `last_timestamp` only advances if accrual completes, so once the product overflows, every future call re-enters the same overflow. Nothing can unwind it — `repay`/`clean_bad_debt`/`withdraw`/`seize_positions` all accrue first.

### Impact Explanation
Permanent freezing of all user funds in that market: suppliers cannot withdraw, borrowers cannot repay, liquidators cannot liquidate, and revenue cannot be claimed. The market is insolvent-in-practice — collateral and debt are locked forever. This satisfies the "permanent freezing of funds" / "contract unable to operate" impact bar.

### Likelihood Explanation
Reachable by unprivileged `supply` and `borrow` only, with no privileged action and no price oracle needed. Two requirements: (a) enormous scale — the regression test seeds ~10^27 wei-scale principal (a billion tokens at 18 decimals) at ~98% utilization, and (b) time — sustained high utilization on a steep curve grows `borrowed * borrow_index` past `i128::MAX` within a few years. Both are achievable by well-capitalized attackers or simply by organic growth of a large high-utilization market; notably the market can be pushed into this state deliberately by supplying a whale-sized position, borrowing ~98% of it, and waiting. Likelihood is low-to-moderate in practice due to capital and time requirements, but the failure is deterministic and irreversible once crossed.

### Recommendation
In `accrue_step`, bound `borrowed`/`supplied` before unscaling (e.g., cap the debt value used for utilization at `i128::MAX / MAX_BORROW_INDEX_RAY`, or compute `scaled_to_original` via a saturating variant like `mul_div_floor_saturating` already present in `fp_core.rs`), and/or clamp `borrow_index` *before* the unscale so the index cap actually engages. A `try_*` path that marks the market "accrue-locked" and still permits `repay`/`seize_positions`/`withdraw` against the last committed indexes would preserve exit liquidity past the cliff.

### Proof of Concept
See the existing harness test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` (`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-361`):

1. `supply(BOB, BIG18, 1e9 * 10^18)`; `supply(ALICE, COL, …)`; `borrow(ALICE, BIG18, 98% of principal)` — all unprivileged calls.
2. `advance_time(YEAR_SECS)` in a loop calling `update_indexes(["BIG18"])` until it reverts `MATH_OVERFLOW` (~a few years at 98% utilization on the XLM curve).
3. Assert `borrow_index < MAX_BORROW_INDEX_RAY` — the index cap never engaged.
4. `try_withdraw(BOB, BIG18, 1)` → `MATH_OVERFLOW`; `try_repay(ALICE, BIG18, 1.0)` → `MATH_OVERFLOW`. Market permanently frozen.

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
