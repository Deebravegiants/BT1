### Title
Third-party collateral top-up permanently defeats the `clean_bad_debt` dust gate on an insolvent account - (File: contracts/controller/src/positions/supply.rs)

### Summary
`clean_bad_debt` admits an insolvent account only when its remaining collateral is at or below the fixed $5 dust threshold (`is_socializable_bad_debt`). The gate reads a live, manipulable USD total rather than an irreversible marker — the same bug class as `preventShutdown` reading `shutdownVotes` (a counter anyone can push back to 0) instead of `quorumVotes`. Here, any unprivileged address may `supply` into a foreign account's *existing* supply positions (`require_third_party_existing_supply`), so an attacker can top up a victim's collateral leg by just over $5 and make the permissionless cleanup path permanently revert with `CannotCleanBadDebt`, even though the account remains deeply insolvent.

### Finding Description
Two permissionless facts combine:

1. Third-party supply to a foreign account is allowed for any hub asset the account already holds: `contracts/controller/src/positions/supply.rs` lines 78–97 only require `account.supply_positions.contains_key(hub_asset)` for non-owner/non-delegate callers. This is documented as intended in INV-AUTH-03 ("Third-party supply cannot create a foreign asset slot") — the check restricts *new slots*, not top-ups.

2. The bad-debt gate in `contracts/controller/src/positions/liquidation/curve.rs` lines 25–27 is:
   ```rust
   pub(crate) fn is_socializable_bad_debt(total_debt: Wad, total_collateral: Wad) -> bool {
       total_debt > total_collateral && total_collateral <= Wad::from(BAD_DEBT_USD_THRESHOLD)
   }
   ```
   reached from `socialize_bad_debt` (`contracts/controller/src/positions/liquidation/mod.rs` lines 229–235) which reverts `CannotCleanBadDebt` for the `DustCapped` gate.

An account sitting at, say, $3 collateral / $50 debt is permissionlessly cleanable. An attacker calls `supply(attacker, victim_id, spoke_id, [(existing_collateral_asset, >$5)])`, raising `total_collateral` to >$8. Every subsequent `clean_bad_debt` call reverts. Unlike the Flayer report (where votes could be returned to 0), the attacker cannot *lower* the collateral again — the denial is one-way and self-maintaining; only an oracle price move or owner `withdraw` can reopen the gate.

Residual mitigations exist but do not close the hole: `force_socialize_bad_debt` is `#[only_owner]` (governance, Sensitive delay tier), and liquidation bonus is capped by remaining collateral so liquidating an account this underwater is unprofitable — precisely why the dust gate exists.

### Impact Explanation
The permissionless socialization path is rendered useless for any targeted insolvent account, for a cost bounded by the dust threshold (~$5). Bad debt persists until governance executes `force_socialize_bad_debt` — a privileged, timelocked path — so suppliers' written-down index (and any backing shortfall) stays unresolved. This maps to temporary freezing of funds / delayed insolvency resolution: Medium.

### Likelihood Explanation
Triggering requires one `supply` call with ~$5 of an asset the victim already supplies; no privileged role, no front-running requirement, no economic loss beyond the donated amount (which becomes protocol revenue if the account is ever cleaned). Any account approaching the dust band can be pre-griefed before it even becomes eligible, since the top-up is allowed at any time.

### Recommendation
Make the gate resistant to third-party manipulation, analogous to the report's "check `quorumVotes`" fix:
- Gate on a monotonic/irreversible signal instead of the live collateral total — e.g., mark the account socializable once `is_socializable_bad_debt` first holds (latch it), or evaluate the dust condition against debt-vs-collateral *ex post* at cleanup time including the top-up.
- Alternatively, reject third-party top-ups on accounts whose `D > C` (insolvent), so the gate's inputs can't be inflated by non-owners.

### Proof of Concept
1. `supply(Bob, ...)` seeds liquidity; `supply(Alice, account_id=0, USDC)`; `borrow(Alice, acct, ETH)` — normal setup.
2. Crash USDC price so Alice holds ~$3 collateral against ~$10 debt (`set_price("USDC", usd_cents(3))`). `can_be_liquidated(Alice) == true`; `is_socializable_bad_debt` admits.
3. Attacker calls `supply(attacker, alice_id, SPOKE, [(hub_asset(USDC), $6)])` — succeeds because Alice already holds a USDC supply position (`supply.rs:89-95`).
4. `clean_bad_debt(anyone, alice_id)` now reverts `CannotCleanBadDebt` (collateral $9 > $5); `liquidate` yields at most ~$9 of collateral vs ~$10 debt, so no profitable path closes the account.
5. Only owner-gated `force_socialize_bad_debt` can still resolve it.

Existing harness support: `tests/test-harness/tests/controller/supply.rs` `test_third_party_supply_to_existing_account_succeeds` proves step 3 succeeds for non-owner callers; `tests/test-harness/tests/controller/bad_debt_index.rs` `test_force_socialize_bad_debt_above_dust_threshold` proves the dust gate rejects exactly this state.
