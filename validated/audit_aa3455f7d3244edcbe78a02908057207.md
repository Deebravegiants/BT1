### Title
GatewayVaultManagementEnabled write-pause is enforced only at the gateway relay, not at the node handler - (File: core/services/gateway/handlers/vault/handler.go, core/capabilities/vault/gw_handler.go)

### Summary
The vault write-methods "pause" (`GatewayVaultManagementEnabled` gate) is checked in the gateway-side `handler` before it fans a `secrets/create|update|delete` request out to nodes, but the node-side `GatewayHandler` (which actually performs the mutation via `secretsService.CreateSecrets/UpdateSecrets/DeleteSecrets`) has no such check.

### Finding Description
`handler.handleSecretsCreate/handleSecretsUpdate/handleSecretsDelete` in the internet-facing gateway call `h.writeMethodsEnabled.AllowErr(ctx)` and reject the request with `UnsupportedMethodError` if vault write methods are disabled. [1](#0-0) 

That gate is populated from a settings-driven `limits.GateLimiter` built over `cresettings.Default.GatewayVaultManagementEnabled` and is only wired into this one gateway-side `handler` struct. [2](#0-1) 

The gateway then simply forwards the (already-past-the-gate) JSON-RPC request to each DON node via `SendToNode`. [3](#0-2) 

On the node side, `GatewayHandler` (which the gateway connector delivers node-bound messages to) processes `MethodSecretsCreate`/`MethodSecretsUpdate`/`MethodSecretsDelete` purely through `requestProcessor.ProcessRequest` (auth/validation) and then dispatches straight to `handleSecretsCreate`/`handleSecretsUpdate`/`handleSecretsDelete`, which call `h.secretsService.CreateSecrets`/`UpdateSecrets`/`DeleteSecrets` directly — there is no `writeMethodsEnabled`/gate check anywhere in this file or in `GatewayHandler`'s struct fields. [4](#0-3) [5](#0-4) [6](#0-5) 

This is structurally identical to the reported bug class: the "pause" control lives in a wrapper contract/component (`SpiritFactory` ↔ gateway `handler`) while the component that actually performs the state-changing operation (`PancakePair.swap()` ↔ node `GatewayHandler`) has unrestricted access and never consults it.

### Impact Explanation
If a node receives a `secrets/create`, `secrets/update`, or `secrets/delete` JSON-RPC message through any path other than the gateway's `handleSecretsCreate/Update/Delete` gate (e.g., a gateway operator or automation that dispatches directly to `GatewayConnectorHandler.HandleGatewayMessage`, or any future additional relay/ingress that reuses `GatewayHandler`), the operator-configured "vault write methods disabled" kill switch is silently bypassed, and secret create/update/delete proceeds as long as allowlist/JWT authorization and owner-binding pass. This defeats an operational safety control intended to halt all secret mutations DON/network-wide.

### Likelihood Explanation
Exploitation requires only a request that reaches `GatewayHandler.HandleGatewayMessage` directly and passes the normal allowlist/JWT `AuthorizeRequest` + replay-guard + owner-binding checks (which are unrelated to the write-pause setting and are satisfiable by any legitimately-allowlisted client) — the write-pause is not part of that authorization path at all, so any authorized-but-supposedly-frozen write request succeeds. This is not gated behind any privileged/operator role and does not require a malicious peer or node.

### Recommendation
Enforce `GatewayVaultManagementEnabled` (or an equivalent gate) inside `GatewayHandler.handleSecretsCreate/handleSecretsUpdate/handleSecretsDelete` in `core/capabilities/vault/gw_handler.go`, i.e., at the point where `secretsService.CreateSecrets/UpdateSecrets/DeleteSecrets` is actually invoked, rather than (or in addition to) the gateway relay's `handler.handleSecretsCreate/Update/Delete`. This mirrors the report's recommendation to move pause enforcement into the component with unrestricted execution access (`PancakePair`), analogously the node-side handler that performs the real state mutation.

### Proof of Concept
1. Operator sets `GatewayVaultManagementEnabled` to disabled to freeze all vault secret writes.
2. A legitimately-allowlisted client's `secrets/create` request submitted through the normal gateway `handler.HandleJSONRPCUserMessage` path is correctly rejected by `writeMethodsEnabled.AllowErr(ctx)`. [7](#0-6) 
3. The same JSON-RPC `secrets/create` request (with valid allowlist/JWT auth) delivered to a node's `GatewayHandler.HandleGatewayMessage` via `AddHandler`-registered `GatewayConnectorHandler` (i.e., any path that reaches the node handler without transiting the gateway's `handleSecretsCreate`) is processed to completion: `ProcessRequest` succeeds and `handleSecretsCreate` calls `secretsService.CreateSecrets` unconditionally. [8](#0-7) [9](#0-8) 
4. The secret is created despite the operator-configured write-pause, demonstrating the pause is enforced only in the gateway relay wrapper and not in the node component that performs the actual privileged operation.

func (h *handler) handleSecretsCreate(ctx context.Context, ar *activeRequest) error {
	l := logger.With(h.lggr, "method", ar.req.Method, "requestID", ar.req.ID)

	err := h.writeMethodsEnabled.AllowErr(ctx)
	if errors.Is(err, limits.ErrorNotAllowed{}) {
		l.Warnw("secrets write method called but write methods are disabled", "error", err)
		return h.sendResponse(ctx, ar, h.errorResponse(ar.req, api.UnsupportedMethodError, errors.New("vault write methods(create/update/delete) are disabled: "+err.Error()), nil))
	} else if err != nil {
		l.Errorw("error checking if write methods are enabled", "error", err)
		return h.sendResponse(ctx, ar, h.errorResponse(ar.req, api.FatalError, errors.New("error checking if write methods are enabled: "+err.Error()), nil))
	}

	return h.fanOutToVaultNodes(ctx, l, ar)
}

func (h *handler) fanOutToVaultNodes(ctx context.Context, l logger.Logger, ar *activeRequest) error {
	var nodeErrors []error
	for _, node := range h.donConfig.Members {
		err := h.don.SendToNode(ctx, node.Address, &ar.req)
		if err != nil {
			nodeErrors = append(nodeErrors, err)
			l.Errorw("error sending request to node", "node", node.Address, "error", err)
		}
	}

	if len(nodeErrors) == len(h.donConfig.Members) && len(nodeErrors) > 0 {
		return h.sendResponse(ctx, ar, h.errorResponse(ar.req, api.FatalError, errors.New("failed to forward user request to nodes"), nil))
	}

	l.Debugw("successfully forwarded request to Vault nodes")
	return nil

func (h *GatewayHandler) HandleGatewayMessage(ctx context.Context, gatewayID string, req *jsonrpc.Request[json.RawMessage]) (err error) {
	reqLggr := h.requestLogger(req, gatewayID)
	reqLggr.Debugw("received message from gateway", "req", req)

	var response *jsonrpc.Response[json.RawMessage]
	var authResult *AuthResult

	switch req.Method {
	case vaulttypes.MethodSecretsCreate, vaulttypes.MethodSecretsUpdate:
		publicKey, pkErr := h.getMasterPublicKey(ctx)
		if pkErr != nil {
			response = h.gatewayErrorResponse(ctx, gatewayID, req, pkErr)
			break
		}
		authorized, pipelineErr := h.requestProcessor.ProcessRequest(ctx, req, publicKey)
		if pipelineErr != nil {
			response = h.gatewayErrorResponse(ctx, gatewayID, req, pipelineErr)
			break
		}
		authResult = authorized.AuthResult
	case vaulttypes.MethodSecretsDelete, vaulttypes.MethodSecretsList:
		authorized, pipelineErr := h.requestProcessor.ProcessRequest(ctx, req, nil)
		if pipelineErr != nil {
			response = h.gatewayErrorResponse(ctx, gatewayID, req, pipelineErr)
			break
		}
		authResult = authorized.AuthResult
	case vaulttypes.MethodPublicKeyGet:
		response = h.handlePublicKeyGet(ctx, gatewayID, req)
	default:
		response = h.errorResponse(ctx, gatewayID, req, api.UnsupportedMethodError, errors.New("unsupported method: "+req.Method))
	}

	if response == nil {
		switch req.Method {
		case vaulttypes.MethodSecretsCreate:
			response = h.handleSecretsCreate(ctx, gatewayID, req)
		case vaulttypes.MethodSecretsUpdate:
			response = h.handleSecretsUpdate(ctx, gatewayID, req)
		case vaulttypes.MethodSecretsDelete:
			response = h.handleSecretsDelete(ctx, gatewayID, req)
		case vaulttypes.MethodSecretsList:
			response = h.handleSecretsList(ctx, gatewayID, req, authResult)
		}
	}

func (h *GatewayHandler) handleSecretsCreate(ctx context.Context, gatewayID string, req *jsonrpc.Request[json.RawMessage]) *jsonrpc.Response[json.RawMessage] {
	vaultCapRequest := vaultcommon.CreateSecretsRequest{}
	if err := json.Unmarshal(*req.Params, &vaultCapRequest); err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.UserMessageParseError, err)
	}

	h.lggr.Debugw("Processing authorized create secrets request", "request", vaultCapRequest.String())
	vaultCapResponse, err := h.secretsService.CreateSecrets(ctx, &vaultCapRequest)
	if err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.FatalError, err)
	}

	jsonResponse, err := toJSONResponse(vaultCapResponse, req.Method)
	if err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.NodeReponseEncodingError, err)
	}
	return jsonResponse
}

func (h *GatewayHandler) handleSecretsUpdate(ctx context.Context, gatewayID string, req *jsonrpc.Request[json.RawMessage]) *jsonrpc.Response[json.RawMessage] {

func (h *GatewayHandler) handleSecretsDelete(ctx context.Context, gatewayID string, req *jsonrpc.Request[json.RawMessage]) *jsonrpc.Response[json.RawMessage] {
	r := &vaultcommon.DeleteSecretsRequest{}
	if err := json.Unmarshal(*req.Params, r); err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.UserMessageParseError, err)
	}

	h.lggr.Debugw("Processing authorized delete secrets request", "request", r.String())
	resp, err := h.secretsService.DeleteSecrets(ctx, r)
	if err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.HandlerError, fmt.Errorf("failed to delete secrets: %w", err))
	}

	resultBytes, err := resp.ToJSONRPCResult()
	if err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.NodeReponseEncodingError, err)
	}

	return &jsonrpc.Response[json.RawMessage]{
		Version: jsonrpc.JsonRpcVersion,
		ID:      req.ID,
		Method:  req.Method,
		Result:  (*json.RawMessage)(&resultBytes),
	}
}
