### Title
Unescaped `-` delimiter in `StateMachine` string encoding corrupts request routing/timeout decoding - (File: `modules/ismp/core/src/host.rs`)

### Summary
`StateMachine`'s `Display`/`FromStr` implementation encodes `Substrate`, `Tendermint` and `Relay` chain identifiers as ASCII strings joined with a literal `-` delimiter (e.g. `"SUBSTRATE-<4 raw bytes>"`, `"RELAY-<4 raw bytes>-<para_id>"`), and decodes them by naively splitting on `-` and taking the last segment. Neither side escapes or rejects a `-` (0x2D) byte inside the embedded chain-id bytes, and invalid UTF‑8 in those bytes is silently coerced to the sentinel string `"XXXX"`. This is the same bug class as CVE-2020-28015 (an unescaped line/field delimiter inside an address-like value that a trusted downstream parser blindly tokenizes on), here applied to the state-machine identifier that is embedded, unvalidated, into every cross-chain `PostRequest`/`GetRequest`/timeout event that crosses the EVM string boundary.

### Finding Description
- `Display` for `StateMachine::Substrate`, `Tendermint`, and `Relay` builds the wire string directly from the raw consensus/para id bytes with no check that those bytes are hyphen-free, printable ASCII: [1](#0-0) 
- `FromStr` reverses this by `name.split('-').last()` and copying the trailing fixed-length segment, so any embedded `-` inside the id silently truncates/misparses the value instead of erroring predictably: [2](#0-1) 
- This exact string form is the canonical wire encoding for `source`/`dest` on every EVM-side `PostRequest`/`GetRequest`, and is decoded back via `StateMachine::from_str(String::from_utf8(...))` in the ABI conversion layer that both pallet-ismp and Tesseract relayers rely on to reconstruct a router-level request from an EVM log: [3](#0-2) 
- The same fragile parser is reused to decode the `dest` field of `PostRequestTimeoutHandled` / `GetRequestTimeoutHandled` events, which drive fee-refund logic: [4](#0-3) 
- On the EVM side, the destination string is constructed with zero validation on the caller-supplied id bytes, e.g. `StateMachine.substrate(bytes4 id)` does `"SUBSTRATE-" + string(abi.encodePacked(id))` for whatever 4 bytes the caller (or an app built on top of Hyperbridge) supplies: [5](#0-4) 
- `EvmHost.dispatch(DispatchPost)` accepts this attacker/caller-controlled `dest` bytes as-is and stores/emits them verbatim, with no on-chain check that the bytes are a well-formed, hyphen-free identifier: [6](#0-5) 

Consequently, any unprivileged caller of `IDispatcher.dispatch()` can construct a `DispatchPost`/`DispatchGet` whose `dest` (or an app's configured `Substrate`/`Relay` id containing a stray `0x2D` byte) breaks the `StateMachine::from_str` round-trip once relayers/pallet-ismp attempt to reconstruct the request off the EVM log.

### Impact Explanation
When the destination/source id bytes contain an embedded `-`, `StateMachine::from_str` either:
1. Fails length validation and returns `Err`, so the message cannot be reconstructed/decoded by the relayer/handler pipeline — the request becomes permanently stuck and undeliverable, and because the *same* parser decodes the timeout event's `dest`, the fee escrowed for that request (`_requestCommitments`) can also never be reliably reconciled through the timeout path, or
2. Silently truncates to whatever bytes trail the final `-`, causing the reconstructed `StateMachine` to resolve to a different 4-byte id than intended.

Either outcome is a route that cannot deliver messages, satisfying the "route unable to deliver messages" impact class. The blast radius is currently best supported for the request that embeds the delimiter itself (self-inflicted stuck funds/DoS on that message), which is a concrete, reachable bug; a broader cross-request collision (two distinct legitimate chain ids both collapsing to the `"XXXX"` sentinel, or to the same truncated tail) is plausible given the code as written but I was not able to fully trace, within the available iterations, whether any fee/reward accounting or destination-authorization check keyed on the *decoded* `StateMachine` value (e.g. in `pallet_ismp`'s request handler or `pallet_ismp_relayer`'s `Fees`/`Nonce` double-maps) can be reached with a colliding value from an external, untrusted party. That broader claim should be treated as unconfirmed.

### Likelihood Explanation
High for the self-contained "stuck message" case: it requires only a single `dispatch()` call with a `dest`/id containing a `-` byte or a non-UTF8 byte sequence, which is entirely within the caller's control and requires no special privileges, front-running, or race conditions. It only manifests for destinations of the `SUBSTRATE-`/`TNDRMINT-`/`RELAY-` families (the numeric `EVM-`/`POLKADOT-`/`KUSAMA-` variants are less exposed since `u32::from_str` rejects non-digit trailing content most of the time, though `"EVM-1-2"` would still misparse to `Evm(2)`).

### Recommendation
- Use a delimiter-safe, length-prefixed or fixed-width encoding for `StateMachine::Substrate`/`Tendermint`/`Relay` (e.g., hex-encode the 4-byte id, or SCALE/RLP length-prefix it) instead of raw ASCII bytes joined with `-`.
- Reject id bytes that are not valid UTF-8 or that contain the delimiter character at construction time (`Display`) rather than silently degrading to `"XXXX"`.
- Make `FromStr` split on the *first* `-` only (`splitn(2, '-')`) or use a fixed-offset substring instead of `split('-').last()`, and validate round-trip equality (`FromStr(Display(x)) == x`) in tests for arbitrary byte inputs, including ones containing `0x2D` and invalid UTF‑8.
- Add a fuzz/property test asserting `StateMachine::from_str(&sm.to_string()) == Ok(sm)` for all `Substrate`/`Tendermint`/`Relay` byte patterns, not just the currently-tested "happy path" ASCII ids.

### Proof of Concept
1. Construct a destination id whose 4 raw bytes are `b"AB-C"` (contains ASCII `-`, 0x2D at index 2).
2. Via the Solidity library, `StateMachine.substrate(bytes4("AB-C"))` produces the destination bytes `"SUBSTRATE-AB-C"` — see [5](#0-4) .
3. Call `EvmHost.dispatch(DispatchPost{ dest: "SUBSTRATE-AB-C", ... })` — accepted with no validation, per [6](#0-5) .
4. When the emitted `PostRequestEvent`/`PostRequest` is later reconstructed via `TryFrom<PostRequestEvent> for router::PostRequest` / `TryFrom<PostRequest> for router::PostRequest`, `StateMachine::from_str("SUBSTRATE-AB-C")` executes `"SUBSTRATE-AB-C".split('-').last()` → `"C"`, which is 1 byte, failing the `bytes.len() != 4` check in [7](#0-6)  and returning `Err("invalid state machine: ...")`.
5. The request can no longer be decoded by any component (pallet-ismp/tesseract) that relies on this `TryFrom`, and the identical failure mode applies to decoding the corresponding `PostRequestTimeoutHandled` event's `dest` field ( [8](#0-7) ), so the escrowed relayer fee for this request cannot be refunded through the normal timeout-decoding path either.

Note: I could not, within the remaining investigation budget, confirm or rule out a stronger cross-user collision scenario (e.g., two different legitimate `StateMachine` values both being funneled into the `"XXXX"` sentinel and then keyed together in `pallet_ismp_relayer`'s `Fees`/`Nonce` storage, or in `pallet-ismp`'s incoming-request destination check). That would require tracing `modules/ismp/core/src/handlers/request.rs` and `pallet_ismp_relayer`'s reward/withdrawal code paths in more depth than the available tool budget allowed, and should be verified separately if this finding is escalated.

impl FromStr for StateMachine {
	type Err = String;

	fn from_str(s: &str) -> Result<Self, Self::Err> {
		let s = match s {
			name if name.starts_with("EVM-") => {
				let id = name
					.split('-')
					.last()
					.and_then(|id| u32::from_str(id).ok())
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				StateMachine::Evm(id)
			},
			name if name.starts_with("POLKADOT-") => {
				let id = name
					.split('-')
					.last()
					.and_then(|id| u32::from_str(id).ok())
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				StateMachine::Polkadot(id)
			},

			name if name.starts_with("RELAY-") => {
				let values = name.split('-').collect::<Vec<_>>();
				let id = values
					.last()
					.and_then(|id| u32::from_str(id).ok())
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				let relay = values
					.get(1)
					.and_then(|id| {
						let bytes = id.as_bytes();
						if bytes.len() == 4 {
							let mut dest = [0u8; 4];
							dest.copy_from_slice(bytes);
							Some(dest)
						} else {
							None
						}
					})
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				StateMachine::Relay { relay, para_id: id }
			},
			name if name.starts_with("KUSAMA-") => {
				let id = name
					.split('-')
					.last()
					.and_then(|id| u32::from_str(id).ok())
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				StateMachine::Kusama(id)
			},
			name if name.starts_with("SUBSTRATE-") => {
				let name = name
					.split('-')
					.last()
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				let bytes = name.as_bytes();
				if bytes.len() != 4 {
					Err(format!("invalid state machine: {name}"))?
				}
				let mut id = [0u8; 4];
				id.copy_from_slice(bytes);
				StateMachine::Substrate(id)
			},
			name if name.starts_with("TNDRMINT-") => {
				let name = name
					.split('-')
					.last()
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				let bytes = name.as_bytes();
				if bytes.len() != 4 {
					Err(format!("invalid state machine: {name}"))?
				}
				let mut id = [0u8; 4];
				id.copy_from_slice(bytes);
				StateMachine::Tendermint(id)
			},
			name => Err(format!("Unknown state machine: {name}"))?,
		};

		Ok(s)
	}
}

     * @notice Generate an identifier for a Substrate-based chain
     * @dev Creates a standardized identifier in the format "SUBSTRATE-{id}"

     * @return The formatted state machine identifier as bytes

        return bytes(string.concat("SUBSTRATE-", string(abi.encodePacked(id))));
