### Title
Signup "block-when-no-internet" pause check is bypassed in the operator/button-initiated signup path - (File: src/plans/mod.rs)

### Summary
The M-5 report describes a class of bug where a protocol-level "pause" control exists but is not consistently enforced across all entry points that trigger the sensitive action, letting the action proceed even when the operator wants it blocked. `orb-core` has a directly analogous gap: the `block_signup_when_no_internet` config flag is meant to act as a pause switch that prevents new signups from starting, but the enforcement function `check_signup_conditions` is only called on one of the several signup-initiation code paths.

### Finding Description
`check_signup_conditions` is the function that enforces the `block_signup_when_no_internet` pause flag before a signup is allowed to proceed: [1](#0-0) 

It is only invoked from `idle_scan_user_qr_code`, which is the self-serve path that continuously scans for a user QR code without requiring a button press: [2](#0-1) 

However, `idle_wait_for_signup_request` explicitly documents four supported signup-initiation scenarios, and only routes through `idle_scan_user_qr_code` (and thus `check_signup_conditions`) for the "self-serve without button" scenario. The other branch — used for normal operator-initiated signups and for self-serve mode with the button-press trigger — calls `idle_wait_for_button_press` and then immediately proceeds to start the signup via `orb.ui.signup_start_operator()`, without ever calling `check_signup_conditions`: [3](#0-2) 

The subsequent `do_signup` function, which drives the rest of the signup flow (QR scan completion, biometric capture, PCP upload), also never calls `check_signup_conditions`: [4](#0-3) 

This mirrors the `BlueBerryBank.withdrawLend` bug class exactly: a "pause"-style flag (`block_signup_when_no_internet`) exists and is enforced on one code path, but a semantically equivalent alternate path to trigger the same sensitive operation (starting a signup) omits the check entirely.

### Impact Explanation
When an operator or fleet manager sets `block_signup_when_no_internet = true` intending to halt all new signups during an outage (e.g., to prevent biometric capture and local processing/queuing of a signup that cannot be verified/uploaded to the backend, or during an incident requiring signups to be paused), the standard operator-driven flow (button press → operator QR → user QR) and the self-serve-with-button-trigger flow are unaffected by this control. Signups can still be started and biometric capture performed even though the protocol explicitly wanted to block them. This is a control-bypass on the signup start gate, undermining the operator's ability to pause the primary sensitive action (initiating a signup / biometric capture) in exactly the way the referenced report describes for `withdrawLend`.

### Likelihood Explanation
Likelihood is moderate to high in any deployment that is not "self-serve without button" (i.e., default operator-mode kiosks, and self-serve deployments that use the button trigger), since these are common configurations and the flag `block_signup_when_no_internet` is a real backend-configurable value fetched via `Config::from_backend`: [5](#0-4) 

No special privileges are required to trigger a signup through the normal button-press path; a normal operator/user interaction is enough to hit the un-gated path.

### Recommendation
Move the `check_signup_conditions` call (or an equivalent gate) so that it is invoked unconditionally at the top of `idle_wait_for_signup_request`, before branching into any of the four scenarios, or add an explicit call to it in the `else` branch (button-press path) right before `orb.ui.signup_start_operator()` is invoked at: [6](#0-5) 

This ensures the pause control applies uniformly across all signup-initiation paths, consistent with the intent already implemented for the self-serve QR-scanning path.

### Proof of Concept
1. Configure the orb backend to set `block_signup_when_no_internet = true` and put the orb's network in a "no internet" state (as detected by `orb.net_monitor`).
2. Run the orb in normal (non-self-serve) mode, or self-serve mode with `self_serve_button = true`.
3. Press the button to initiate a signup as usual.
4. Observe that `idle_wait_for_signup_request` takes the `else` branch (`idle_wait_for_button_press` → `signup_start_operator`) and proceeds directly into `do_signup`, without ever calling `check_signup_conditions`, so the biometric capture and signup flow start normally despite the "no internet" block being configured — unlike the self-serve-without-button path, where `check_signup_conditions` at line 475 would have rejected the same condition via `orb.ui.no_internet_for_signup()`.

    async fn idle_wait_for_signup_request(
        &mut self,
        orb: &mut Orb,
        qr_codes: &QrCodes,
        self_serve: bool,
        self_serve_button: bool,
        operator_qr_expiration_time: Duration,
    ) -> Result<Option<QrCodes>> {
        // We currently support 4 scenarios:
        // 1. Internal testing with a biometric input file.
        // 2. Self-serve mode that always scans for a user QR code.
        // 3. Self-serve mode that expects a button press to ask for a user QR code.
        // 4. Normal mode that expects a button press to ask for an operator QR code and then a user QR code.
        //
        // Scenarios 3 and 4 are handled by the same code path in the following last else-statement.
        let ui_idle_delay = self.ui_idle_delay.take();
        let qr_codes = if self.oneshot || self.has_biometric_input() {
            qr_codes.clone()
        } else if self_serve && !self_serve_button {
            orb.set_phase("User QR-code idle scanning").await;
            let QrCodes::Operator { operator_data } = &qr_codes else {
                panic!("operator QR code needs to be scanned beforehand in self-serve mode");
            };
            let Some((user_qr_code, user_data, user_qr_code_string)) = self
                .idle_scan_user_qr_code(
                    orb,
                    operator_data,
                    operator_qr_expiration_time,
                    ui_idle_delay,
                )
                .await?
            else {
                return Ok(None);
            };
            qr_codes.with_user_qr_code(user_qr_code, user_data, user_qr_code_string)
        } else {
            orb.set_phase("Idle waiting for button press").await;
            self.idle_wait_for_button_press(orb, ui_idle_delay).await?;
            orb.ui.signup_start_operator();
            qr_codes.clone()
        };
        Ok(Some(qr_codes))
    }

async fn check_signup_conditions(orb: &mut Orb) -> Result<bool> {
    if let Some(report) = orb.net_monitor.last_report()? {
        // Drop the mutex lock fast.
        let Config { block_signup_when_no_internet, .. } = *orb.config.lock().await;
        if block_signup_when_no_internet && report.is_no_internet() {
            orb.ui.no_internet_for_signup();
            dd_incr!("main.count.signup.result.failure.internet_check", "type:too_slow_to_start");
            return Ok(false);
        }
        if report.is_slow_internet() {
            orb.ui.slow_internet_for_signup();
            dd_incr!("main.count.signup.result.failure.internet_check", "type:too_slow_to_start");
            return Ok(true);
        }
    }
    Ok(true)
}
