## Analysis

The core code path is `IntentGatewayV2.placeOrder` when `order.predispatch.call.length > 0`. This sweeps the *entire* current balance of the shared `CallDispatcher` for each input token — not the delta produced by the predispatch call itself — and credits it toward the caller's own order, exactly mirroring the `Converter.convert` bug class (an unprivileged caller triggers a balance-based sweep of a shared contract, with no accounting for whose funds those actually are). [1](#0-0) 

### Title
Unprivileged `placeOrder` predispatch path drains any pre-existing token balance sitting on the shared `CallDispatcher` - (File: evm/src/apps/IntentGatewayV2.sol)

### Summary
`placeOrder`'s predispatch branch measures how much of each required input token to escrow by reading `IERC20(token).balanceOf(dispatcher)` (the *entire* current balance of the shared, singleton `CallDispatcher`) and sweeping all of it into the gateway, rather than only the amount produced by the caller's own predispatch call. Any tokens already sitting on the `CallDispatcher` for unrelated reasons become attributable to whichever caller next places an order touching that token.

### Finding Description
`CallDispatcher` is a shared, persistent, address-known contract reused across many apps and flows: `HyperFungibleToken.onAccept`, `WrappedHyperFungibleToken.onAccept`, `IntentsBase._execute` (output-calldata sweep), and `IntentGatewayV2.placeOrder`'s own predispatch/output paths all route tokens through the same dispatcher instance and then sweep its balance back out. [2](#0-1) 

In `placeOrder`, when a user supplies `order.predispatch.call` and `order.predispatch.assets`:
1. The caller's declared predispatch assets are transferred to `dispatcher`.
2. `order.predispatch.call` (fully attacker/user-controlled calldata) is executed by the dispatcher.
3. For each required input token, the code reads `balance = IERC20(token).balanceOf(dispatcher)` — the dispatcher's *total* balance, not `balanceAfter - balanceBeforePredispatch` — and builds a sweep call that transfers that whole `balance` back to the gateway.
4. `received = balanceOf(gateway) after - balanceOf(gateway) before` is then credited to `order.inputs[i].amount` (or counted as “dust” if it exceeds the requested amount), and finally escrowed under the caller's own `commitment` in `_orders[commitment][token]`. [3](#0-2) 

Because the sweep is balance-based rather than delta-based relative to the point right before the predispatch assets were even deposited, any token balance that happens to be resting on the dispatcher when `placeOrder` executes — e.g., residual dust from a previous `IntentsBase._execute`/output sweep, a partially-processed HFT `onAccept` calldata dispatch, or any other flow that transiently parks tokens on this shared contract — gets swept into the current caller's order and escrowed as if the caller had supplied it themselves. A caller only needs to submit a `predispatch.call` that is a no-op (or trivially satisfies the dispatcher's `NotContract`/success checks) while declaring `predispatch.assets` of a token they already control (even a tiny/zero-cost amount is required by the `amount == 0` check, but it can be minimal), then declare `order.inputs` for whatever token they know/observe is sitting on the dispatcher. This lets them mint themselves an escrowed order input funded by funds that belong to other in-flight operations or the protocol, i.e., steal them.

This is structurally identical to the `Converter.convert` vulnerability: an unprivileged, single-transaction call relies on `balanceOf(address(this))`/`balanceOf(shared contract)` after an attacker-controlled external call to decide how much value to move, with no verification that the funds being swept actually originated from the caller's own deposit in that same call.

### Impact Explanation
Any unprivileged user submitting `placeOrder` with a crafted `predispatch.call`/`predispatch.assets` can capture tokens that transiently reside on the shared `CallDispatcher` from unrelated protocol flows (other users' in-flight cross-chain calldata executions, or dust not yet swept by `IntentsBase._execute`), escrowing them as their own order input. This is concrete theft of funds not belonging to the caller, reachable from a single `placeOrder` transaction — satisfying the “concrete theft of funds” bar for High severity.

### Likelihood Explanation
Exploitability depends on the `CallDispatcher` holding a non-zero balance of some token at the moment of the attack, which can occur naturally given that the same dispatcher instance is reused by `HyperFungibleToken`/`WrappedHyperFungibleToken` (`onAccept` message data execution) and `IntentsBase`/`IntentGatewayV2` output sweeps — all of which briefly move tokens onto the dispatcher before sweeping them out. An attacker can also self-fund the dispatcher first (e.g., front-run/back-run their own transactions or exploit any transient leftover from a reverted/partial call) to guarantee the balance is non-zero, then immediately call `placeOrder` to claim it. The attack requires only standard transaction submission, no privileged role, and no proof/relayer involvement.

### Recommendation
Snapshot each required input token's dispatcher balance immediately **before** transferring the caller's own predispatch assets into the dispatcher, and compute `received` as the delta from that pre-transfer snapshot to the post-sweep balance, rather than sweeping the dispatcher's total balance. Alternatively, require the predispatch flow to use a per-order-scoped intermediate contract/escrow instead of a shared singleton `CallDispatcher`, or make `CallDispatcher.dispatch` refuse to be entered with pre-existing balances left over from a different caller's flow (e.g., zero out balances at the end of every dispatch that ever holds tokens temporarily).

### Proof of Concept
1. Wait for (or trigger) a moment where the shared `CallDispatcher` holds a non-zero balance of token `T` — e.g., immediately after any `HyperFungibleToken.onAccept`/`WrappedHyperFungibleToken.onAccept` with non-empty `data`, or after an `IntentsBase._execute` output-calldata call, before its sweep-back completes, or simply by the attacker sending `T` directly to the known `CallDispatcher` address in a prior transaction as “dust.”
2. Attacker calls `IntentGatewayV2.placeOrder` with:
   - `order.predispatch.assets` = a minimal (non-zero) amount of some token they own, and `order.predispatch.call` = a trivial call to a contract they control that does nothing malicious-looking (must satisfy `CallDispatcher.dispatch`'s `extcodesize`/success checks).
   - `order.inputs` = `[{token: T, amount: X}]` where `X <= currentDispatcherBalanceOfT`.
3. Inside `placeOrder`, `balance = IERC20(T).balanceOf(dispatcher)` includes the pre-existing `T` balance unrelated to the attacker's predispatch call; the full `balance` is swept to the gateway and credited to `order.inputs[0].amount`, then escrowed under the attacker's `commitment` in `_orders[commitment][T]`.
4. The attacker (as order owner) can later cancel or have the order refunded/filled, withdrawing the escrowed `T` — tokens that were never actually contributed by the attacker.

import {ICallDispatcher, Call} from "@hyperbridge/core/interfaces/ICallDispatcher.sol";

/**
 * @title The CallDispatcher
 * @author Polytope Labs (hello@polytope.technology)
 *
 * @notice This contract is used to dispatch calls to other contracts.
 */
contract CallDispatcher is ICallDispatcher {
    /**
     * @dev error thrown when the target is not a contract.
     */
    error NotContract(address target);

    /**
     * @dev error thrown when a call fails.
     */
    error CallFailed(address target, bytes result);

    /**
     * @dev Receive function to accept ETH transfers
     */
    receive() external payable {}

    /**
     *  @dev reverts if the target is not a contract or if any of the calls reverts.
     */
    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
}
