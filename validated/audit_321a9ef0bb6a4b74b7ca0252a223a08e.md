## Title
Single stale `nativeOracle` freezes gas-fee payment for every registered token in `SimplexPaymaster` - (`evm/src/utils/SimplexPaymaster.sol`)

### Summary
`SimplexPaymaster` uses one shared `nativeOracle` (native-asset/USD Chainlink feed) to price *every* registered ERC-20 token when a bundler processes a UserOperation. `_tokenPrice` and `_fetchDetails` — invoked on the validation path for every single UserOp that pays gas through this paymaster — call `_getOraclePrice(nativeOracle, ...)` and revert with `StaleOraclePrice` if that one feed is older than `maxOracleAge`, regardless of which token the sender is actually using. Because the native/USD feed is a single point of failure shared across all tokens, its staleness DoSes gas-fee sponsorship for the entire paymaster, mirroring the reported class of bug: dependence on a single oracle price freezing all financial operations rather than isolating the affected asset.

### Finding Description
`_tokenPrice` prices every token relative to the same native/USD feed: [1](#0-0) 

`_getOraclePrice` reverts unconditionally when the queried feed's `updatedAt` is older than `maxOracleAge`: [2](#0-1) 

This function is reached from `_fetchDetails`, which is called during ERC-4337 validation for *every* UserOp routed through this paymaster (mode `0x00` permit or `0x02` permit2), independent of which registered token the sender chose: [3](#0-2) 

Since `nativeOracle` is a single contract-wide storage slot (not per-token), a single stale feed — the same class of failure described in the report, where one market's stale oracle poisoned the whole NAV calculation — reverts `_tokenPrice` for USDC, USDT, or any other registered token simultaneously. There is no per-token or global fallback: `getTokenPrice`, `estimateTokenCost`, and the validation-time `_fetchDetails`/`_validatePaymasterUserOp` path all funnel through the same `_getOraclePrice(nativeOracle, ...)` call. The existing test suite explicitly demonstrates the staleness revert: [4](#0-3) 

Recovery requires a governance round-trip (an `UpdateParams` request delivered through `onAccept`, authenticated as coming from Hyperbridge via the relayer) to replace `nativeOracle`: [5](#0-4) [6](#0-5) 

Until that governance action lands, every bandwidth purchaser (any account submitting a UserOp that names this paymaster in `paymasterAndData`) is unable to have their operation sponsored by any of the registered stablecoins, even though only the shared native-asset feed — not any of the token-specific feeds — is unresponsive.

### Impact Explanation
This is a full denial-of-service of the paymaster's core function: sponsoring gas for UserOps across *all* supported tokens simultaneously, triggered purely by the staleness of one shared oracle feed. Unlike a per-token oracle failure (which `_deactivateToken` can isolate), the `nativeOracle` staleness cannot be worked around per-token since it is used in every price computation. Users/solvers relying on this paymaster to pay gas in stablecoins are frozen out until a governance-authorized relayer intervenes with an `UpdateParams` request, which requires cross-chain governance delivery through Hyperbridge — not an immediate, permissionless fix. This matches the reported bug class (single stale oracle price freezing an entire market/mechanism) applied to the bandwidth-purchase (gas-sponsorship) path.

### Likelihood Explanation
Chainlink feeds staling (sequencer outages, feed deprecation, provider downtime, or a chain reorg delaying updates) is a realistic and previously-seen operational event; `maxOracleAge` is deliberately tight in some deployments (e.g., BSC stablecoins ~27s per code comments), making transient staleness plausible. No attacker action is needed — any natural oracle staleness event on the single `nativeOracle` triggers the DoS for all tokens, and any account can trigger/observe the revert simply by submitting a UserOp through the paymaster.

### Recommendation
Do not let a single shared native/USD feed become a system-wide single point of failure for all token pricing:
- Consider caching/using the last-known-good native price with a wider allowable staleness window specifically for the shared feed, or maintain a fallback price source.
- Alternatively, allow governance to instantly pause/deactivate the paymaster's dependence on the stale native feed (e.g., an emergency multi-oracle fallback or TWAP-based backstop) rather than requiring a full `UpdateParams` governance round trip through the cross-chain relayer path.
- At minimum, make the recovery path (relayer-delivered `UpdateParams`) independent of the affected chain's oracle infrastructure so it can be executed promptly.

### Proof of Concept
1. Deploy `SimplexPaymaster` with `nativeOracle` and two registered tokens (e.g., USDC, USDT) each with their own healthy oracle, as in `SimplexPaymasterTest.t.sol` setup.
2. Advance `nativeOracle.updatedAt` beyond `maxOracleAge` (e.g., `nativeOracle.setUpdatedAt(block.timestamp - paymaster.maxOracleAge() - 1)`), simulating a feed outage — see `testStaleOracleReverts`: [4](#0-3) 
3. Call `paymaster.getTokenPrice(address(usdc6))` and `paymaster.getTokenPrice(address(usdt))` (or submit any UserOp with `paymasterData` naming either token) — both revert with `StaleOraclePrice`, even though the USDC and USDT feeds are themselves fresh, because both computations route through the same stale `nativeOracle`.
4. Observe that no UserOp naming any registered token can be sponsored by this paymaster until governance delivers an `UpdateParams` request replacing `nativeOracle`, demonstrating the system-wide freeze from a single stale feed.

        uint256 tokenUsd = _getOraclePrice(cfg.tokenOracle, cfg.tokenOracleDecimals);

    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
