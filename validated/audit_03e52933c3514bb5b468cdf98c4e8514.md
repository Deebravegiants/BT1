### Title
Zero-value destination-specific protocol fee override cannot waive fees — falls back to the global default - ([File: evm/src/apps/IntentGatewayV2.sol])

### Summary
`IntentGatewayV2.placeOrder` computes the protocol fee to deduct from an order's inputs by first reading a per-destination override from `_destinationProtocolFees[destinationHash]`, and treating `0` as "no override configured," falling back to the global `_params.protocolFeeBps`. This means governance can never configure an explicit 0% fee for a specific destination — any attempt to waive fees for a given chain via `ParamsUpdate.destinationFees` with `destinationFeeBps = 0` is silently ignored, and the global default fee is still charged. This mirrors the Rubicon `RubiconFeeController` bug: a mechanism that is supposed to allow disabling/zeroing a fee override actually falls back to charging a base/default fee instead.

### Finding Description
`_updateParams` stores destination fee overrides verbatim, allowing `feeBps` to be `0`: [1](#0-0) 

At order placement, the fee actually applied is computed as: [2](#0-1) 

Because `_destinationProtocolFees` is a plain `uint256` mapping with no separate "is-set" flag, the value `0` is indistinguishable between "never configured" and "explicitly configured to charge zero fee for this destination." The code unconditionally treats `0` as "unset" and substitutes the global `_params.protocolFeeBps`, which is exactly the same class of bug as the reported issue: a fee-disabling configuration is silently overridden by a base/default fee, contradicting the evident intent of `DestinationFee` overrides (to let governance set a fee, including zero, per destination). This is confirmed by the codebase's own test `testPlaceOrderDestinationFeeWithFallback`, which asserts the fallback behavior for "destination fee not set (or is 0)" — treating "not set" and "set to 0" identically: [3](#0-2) 

The protocol fee deduction itself is applied to every input token in the order: [4](#0-3) 

### Impact Explanation
Any unprivileged user calling `placeOrder` to a destination that governance intended to exempt from protocol fees (by setting `destinationFeeBps = 0` for that chain) is instead charged the global default `protocolFeeBps`. The excess amount is permanently retained by the gateway as "dust" (`DustCollected`) and is not refundable — per the documentation, the protocol fee "is deducted at placement and is not refunded if the order expires, receives no bids, or is cancelled." This causes real, unintended, permanent loss of user funds relative to the fee schedule governance configured, exactly matching the "unintended loss of funds" impact language of the reference report.

### Likelihood Explanation
This triggers deterministically and silently any time governance configures a `DestinationFee` override of `0` for a chain — a plausible and reasonable configuration (e.g., waiving fees to bootstrap volume on a new destination, or a promotional 0-fee route) — and then any user places an order to that destination. No attacker action is required; the affected party is the ordinary order-placer who is charged more than the on-chain (or documented) intended fee schedule for that route. The bug is latent until governance actually attempts to zero out a route's fee, at which point every subsequent order to that destination is silently overcharged until detected.

### Recommendation
Distinguish "no override configured" from "override explicitly set to 0%." Options:
- Store overrides in a mapping keyed with an explicit `isSet` boolean (e.g., `mapping(bytes32 => DestinationFeeConfig)` with a `configured` flag), or
- Use a sentinel value (e.g., `type(uint256).max` for "unset") instead of `0`, reserving `0` to mean "explicitly zero fee."
Then update `placeOrder`'s fee-resolution logic to only fall back to `_params.protocolFeeBps` when the destination has genuinely never been configured, and apply `0` fee verbatim when explicitly configured that way. Update the `testPlaceOrderDestinationFeeWithFallback` test accordingly to separately cover "unset" vs. "explicitly zero" cases.

### Proof of Concept
1. Governance calls `onAccept` with a `ParamsUpdate` containing `destinationFees = [{destinationFeeBps: 0, chain: "ARBITRUM"}]`, intending orders routed to Arbitrum to pay no protocol fee.
2. `_updateParams` stores `_destinationProtocolFees[keccak256("ARBITRUM")] = 0` (see `evm/src/apps/intentsv2/IntentsBase.sol:617-627`).
3. A user calls `placeOrder` with `order.destination = "ARBITRUM"` and `inputAmount = 1000 USDC`.
4. In `placeOrder`, `protocolFeeBps = _destinationProtocolFees[destinationHash]` evaluates to `0`, so the code executes `if (protocolFeeBps == 0) { protocolFeeBps = _params.protocolFeeBps; }`, substituting e.g. the global 1% (100 bps) default instead of the intended 0%.
5. `10 USDC` is deducted as `DustCollected` from the user's escrowed input, and the user's fill amount is reduced accordingly — a fee governance explicitly attempted to waive for that destination.

    function testPlaceOrderDestinationFeeWithFallback() public {
        // Test that when destination fee is not set (or is 0), it falls back to default protocol fee
        IntentGatewayV2 customGateway = _deployGatewayProxy();
        Params memory customParams = Params({
            host: address(host),
            dispatcher: address(dispatcher),
            solverSelection: false,
            surplusShareBps: 10000,
            protocolFeeBps: 100, // 1% default
            priceOracle: address(0)
        });
        customGateway.initialize(customParams, new bytes[](0), address(0));

        // Place order to destination without specific fee set
        uint256 inputAmount = 1000 * 1e6; // 1000 USDC
        uint256 expectedDefaultFee = (inputAmount * 100) / 10000; // 10 USDC (1% default)

        deal(address(usdc), user, inputAmount);

        bytes memory unknownDestination = bytes("UNKNOWN_CHAIN");

        Order memory order = Order({
            user: bytes32(0),
            source: bytes(""),
            destination: unknownDestination,
            deadline: block.timestamp + 1 hours,
            nonce: 0,
            fees: 0,
            session: address(0),
            predispatch: DispatchInfo({assets: new TokenInfo[](0), call: ""}),
            inputs: new TokenInfo[](1),
            output: PaymentInfo({beneficiary: bytes32(uint256(uint160(user))), assets: new TokenInfo[](1), call: ""})
        });

        order.inputs[0] = TokenInfo({token: bytes32(uint256(uint160(address(usdc)))), amount: inputAmount});
        order.output.assets[0] = TokenInfo({token: bytes32(uint256(uint160(address(dai)))), amount: 2000 * 1e18});

        vm.startPrank(user);
        usdc.approve(address(customGateway), inputAmount);

        vm.recordLogs();
        customGateway.placeOrder(order, bytes32(0));
        vm.stopPrank();

        // Verify DustCollected event was emitted with default fee (1%)
        Vm.Log[] memory entries = vm.getRecordedLogs();
        uint256 collectedFee = 0;

        for (uint256 i = 0; i < entries.length; i++) {
            if (entries[i].topics[0] == keccak256("DustCollected(address,uint256)")) {
                (address token, uint256 amount) = abi.decode(entries[i].data, (address, uint256));
                if (token == address(usdc)) {
                    collectedFee = amount;
                }
            }
        }

        assertEq(collectedFee, expectedDefaultFee, "Should use default protocol fee when destination fee not set");
    }
