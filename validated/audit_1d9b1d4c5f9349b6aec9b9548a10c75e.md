### Title
Permanent market freeze from Ray-value overflow during interest accrual - (File: `common/src/rates/simulate.rs`)

### Summary
An unprivileged user can permanently freeze an overlarge, highly utilized market by allowing interest to accrue until either scaled debt or scaled supply multiplied by its index exceeds `i128::MAX`, then calling `update_indexes`. Every subsequent pool operation loads the market through `synced_market`, which executes `global_sync` before the requested mutation, so repayments, withdrawals, liquidations, and further index updates all revert with `MathOverflow`. [1](#0-0) [2](#0-1) 

### Finding Description
`accrue_step` unconditionally materializes the market’s complete scaled values with `scaled_to_original(borrowed, borrow_index)` and `scaled_to_original(supplied, supply_index)`. [3](#0-2) 

`scaled_to_original` is a checked `Ray` multiplication and panics when `scaled * index / RAY` cannot fit in `i128`. [4](#0-3) 

Although `update_borrow_index` caps the index at `MAX_BORROW_INDEX_RAY`, the cap is applied only after computing `old_index * interest_factor`, and neither index cap bounds `borrowed * borrow_index` or `supplied * supply_index`. [5](#0-4) [6](#0-5) 

All market mutations call `synced_market`, which runs `interest::global_sync` before the operation. [2](#0-1) 

`global_sync` calls `accrue_chunk` for each elapsed accrual interval, so once total scaled value approaches the representable limit, even a risk-reducing operation such as `repay` cannot execute because accrual panics first. [7](#0-6) 

The permissionless trigger is `Controller.update_indexes(caller, vec![hub_asset])`, which forwards the selected markets to the pool. [8](#0-7) 

### Impact Explanation
This is a permanent freezing-of-funds condition for the affected `(hub, asset)` market. Suppliers cannot withdraw, borrowers cannot repay, liquidators cannot liquidate through the pool’s synchronized paths, and callers cannot use `update_indexes` to recover because all those paths perform the same overflowing accrual before reaching their own logic. [2](#0-1) [9](#0-8) 

The repository’s regression test demonstrates the concrete failure state: after the market reaches the Ray-value ceiling, both `update_indexes` and subsequent `withdraw` and `repay` calls return `MathOverflow`, while the borrow index remains below `MAX_BORROW_INDEX_RAY`. [10](#0-9) 

### Likelihood Explanation
The trigger itself is unprivileged: any caller can invoke `update_indexes` for a listed market, and the preceding market growth can be built through ordinary `supply` and `borrow` positions. [8](#0-7) 

Exploitation requires an exceptionally large market and sustained high utilization; the included test uses one billion 18-decimal tokens at 98% utilization on the XLM curve and advances time until the value ceiling is crossed. [11](#0-10) 

The attack is therefore economically expensive, but it is not merely a transaction-resource failure: after the state is reached, all later accrual-dependent transactions deterministically revert because they must evaluate the same overflowing multiplication. [12](#0-11) 

### Recommendation
Refactor accrual so utilization and accrued interest do not require materializing full `scaled * index` values in `i128`.

- Use wider intermediate arithmetic or saturating checked helpers for `borrowed * borrow_index` and `supplied * supply_index`.
- Compute accrued interest from the index delta, such as a widened `borrowed * (new_index - old_index) / RAY`, instead of subtracting two potentially overflowing total-debt products.
- Apply `MAX_BORROW_INDEX_RAY` before evaluating debt value, and add an explicit safe terminal state once debt value reaches the representable ceiling.
- Add an invariant test proving that an over-threshold market remains repayable, withdrawable, and liquidatable rather than trapping inside `accrue_step`.
- Enforce market-level value limits below `i128::MAX / current_index` at entry, while still keeping exit and repayment paths safe for markets already above the limit.

### Proof of Concept
1. In a market with 18 decimals and a steep utilization curve, call `supply` with approximately `1_000_000_000 * 10^18` base units.
2. Supply sufficient collateral in another market and call `borrow` for approximately 98% of that liquidity.
3. Let ledger time advance while utilization remains high.
4. Call `Controller.update_indexes(caller, [hub_asset])`.
5. `synced_market -> global_sync -> accrue_chunk -> accrue_step` executes `scaled_to_original` for the market totals. Once `borrowed * borrow_index` or `supplied * supply_index` exceeds `i128::MAX`, the call panics with `MathOverflow`.
6. Subsequent `withdraw`, `repay`, `liquidate`, and `update_indexes` attempts all panic for the same reason because every path performs accrual before the operation.

The in-repository reproduction is `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap`, which supplies one billion 18-decimal units, borrows 98%, advances time until `update_indexes` fails with `MathOverflow`, and then confirms both `withdraw` and `repay` fail identically. /// Applies `interest_factor` to `old_index` to produce the new borrow index,
```rust
/// capped at `MAX_BORROW_INDEX_RAY`.
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}
```

```rust
pub fn update_supply_index(env: &Env, supplied: Ray, old_index: Ray, rewards_increase: Ray) -> Ray {
    if supplied == Ray::ZERO || rewards_increase == Ray::ZERO {
        return old_index;
    }

    let total_supplied_value = supplied.mul(env, old_index);

    if total_supplied_value == Ray::ZERO {
        return old_index;
    }

    let new_value = total_supplied_value.checked_add(env, rewards_increase);
    let grown = fp_core::mul_div_floor_saturating(env, new_value.raw(), RAY, supplied.raw());

    let bounded_old = old_index.raw().min(MAX_SUPPLY_INDEX_RAY);
    Ray::from(grown.min(MAX_SUPPLY_INDEX_RAY).max(bounded_old))
```

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```

```rust
/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
