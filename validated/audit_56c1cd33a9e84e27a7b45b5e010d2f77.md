## Finding

The Aptos-native custody analog to the Alchemix "inaccurate slippage protection" bug exists in `bonding_curve_launchpad`, a Move package in this repository that manages a constant-product AMM (`LiquidityPair`) holding real APT and fungible-asset (FA) custody in `FungibleStore` objects.

### Title
Missing slippage protection in `bonding_curve_launchpad::swap` allows sandwich-attack theft of APT/FA value — (File: `aptos-move/move-examples/bonding_curve_launchpad/sources/bonding_curve_launchpad.move`)

### Summary
The Alchemix bug reduces to one custody invariant: *any swap that hands custody-held value from a pool to a user must bound the output against a caller-supplied minimum, not just an internally derived/assumed value.* In `bonding_curve_launchpad`, this invariant is entirely absent — worse than the original report, which at least attempted (incorrectly) to bound output.

### Finding Description
The public entry point `swap` takes no `amount_out_min`/slippage parameter at all: [1](#0-0) 

It forwards directly to `liquidity_pairs::swap_fa_to_apt` / `swap_apt_to_fa`, which compute the output purely from the pool's current on-chain reserves at execution time via the constant-product formula, and unconditionally transfer that computed amount out of custody (`liquidity_pair.fa_store` for FA, `aptos_account::transfer` for APT): [2](#0-1) [3](#0-2) [4](#0-3) 

There is no check anywhere in `swap`, `swap_fa_to_apt`, or `swap_apt_to_fa` comparing the computed `apt_gained`/`fa_gained` against any value supplied or expected by the swapper. Compare this to the companion `swap::router` module in the same repo, which correctly threads an `amount_out_min` through to an assertion: [5](#0-4) 

`bonding_curve_launchpad` omits this entirely, even though its `LiquidityPair` object directly custodies both the FA reserve (`fa_store`, a `FungibleStore` object) and virtual/real APT reserve, and moves real value out of that custody on every swap.

### Impact Explanation
Because the swap's output amount is derived solely from mutable, attacker-observable/attacker-manipulable on-chain reserves with zero minimum-output enforcement, any swap transaction can be sandwiched:
1. Attacker front-runs the victim's `swap` call with a same-direction trade that shifts `fa_reserves`/`apt_reserves` unfavorably for the victim.
2. Victim's transaction executes and receives an amount computed off the manipulated reserves — silently accepting whatever `get_amount_out` returns, however low.
3. Attacker back-runs to restore reserves and extract the difference, which is real APT/FA value transferred out of the liquidity pair's custody to the attacker instead of the victim.

This is a custody accounting corruption that moves value to the wrong holder (the attacker) with no bound — a direct "Theft ... of APT, fungible assets, token objects" impact per the custody gate, and is strictly worse than the referenced Alchemix bug because there is no protective assumption at all, not even an inaccurate one.

### Likelihood Explanation
High likelihood: any swap transaction submitted to a public mempool against this AMM can be sandwiched by a searcher/validator with ordinary front-running tooling. No privileged access, admin assumption, or protocol misconfiguration is required — the vulnerable code path (`swap` → `swap_fa_to_apt`/`swap_apt_to_fa`) is the only user-facing trading entry point in the module.

### Recommendation
Add a `min_amount_out: u64` parameter to `bonding_curve_launchpad::swap` and thread it through to `liquidity_pairs::swap_fa_to_apt`/`swap_apt_to_fa`, asserting the computed `apt_gained`/`fa_gained` is `>= min_amount_out` before transferring funds out of custody — mirroring the pattern already implemented correctly in `swap::router::swap` (`fungible_asset::amount(&out) >= amount_out_min`).

### Proof of Concept
Conceptual sequence (no live PoC executed, derived from code reading):
1. Attacker observes a pending `swap(account, name, symbol, swap_to_apt=false, amount_in=X)` (buy FA with APT) in the mempool.
2. Attacker submits `swap(attacker, name, symbol, false, large_amount)` with higher gas/priority to execute first, pushing `apt_reserves` up and `fa_reserves` down per `get_amount_out`'s constant-product math at lines 104-111 of `liquidity_pairs.move`.
3. Victim's `swap` executes next: `get_amount_out` now returns a much smaller `fa_gained` for the same `amount_in`, and this value is transferred with no floor check.
4. Attacker submits a reverse `swap(attacker, name, symbol, true, ...)` to sell the FA back into APT, capturing the spread extracted from the victim, all within the absence of any `assert!(amount_out >= min)` in the vulnerable module.

    #[view]
    public fun get_amount_out(
        fa_reserves: u128,
        apt_reserves: u128,
        swap_to_apt: bool,
        amount_in: u64
    ): (u64, u64, u128, u128) {
        if (swap_to_apt) {
            let divisor = fa_reserves + (amount_in as u128);
            let apt_gained = (math128::mul_div(apt_reserves, (amount_in as u128), divisor) as u64);
            let fa_updated_reserves = fa_reserves + (amount_in as u128);
            let apt_updated_reserves = apt_reserves - (apt_gained as u128);
            assert!(apt_gained > 0, ELIQUIDITY_PAIR_SWAP_AMOUNTOUT_INSIGNIFICANT);
            (amount_in, apt_gained, fa_updated_reserves, apt_updated_reserves)
        } else {
            let divisor = apt_reserves + (amount_in as u128);
            let fa_gained = (math128::mul_div(fa_reserves, (amount_in as u128), divisor) as u64);
            let fa_updated_reserves = fa_reserves - (fa_gained as u128);
            let apt_updated_reserves = apt_reserves + (amount_in as u128);
            assert!(fa_gained > 0, ELIQUIDITY_PAIR_SWAP_AMOUNTOUT_INSIGNIFICANT);
            (fa_gained, amount_in, fa_updated_reserves, apt_updated_reserves)
        }
    }

    /// Facilitate swapping between a given FA to APT.
    public(friend) fun swap_fa_to_apt(
        name: String,
        symbol: String,
        transfer_ref: &TransferRef,
        swapper_account: &signer,
        fa_object_metadata: Object<Metadata>,
        amount_in: u64
    ) acquires Pairs, LiquidityPair {
        // Verify the liquidity pair exists and is enabled for trading.
        assert_liquidity_pair_exists(name, symbol);
        let liquidity_pair = borrow_global_mut<LiquidityPair>(get_pair_obj_address(name, symbol));
        assert!(liquidity_pair.is_enabled, ELIQUIDITY_PAIR_DISABLED);
        // Determine the amount received of APT, when given swapper-supplied amount_in of FA.
        let (fa_given, apt_gained, fa_updated_reserves, apt_updated_reserves) = get_amount_out(
            liquidity_pair.fa_reserves,
            liquidity_pair.apt_reserves,
            true,
            amount_in
        );
        // Verify the swapper holds the FA.
        let swapper_address = signer::address_of(swapper_account);
        let does_primary_store_exist_for_swapper = primary_fungible_store::primary_store_exists(
            swapper_address,
            fa_object_metadata
        );
        assert!(does_primary_store_exist_for_swapper, EFA_PRIMARY_STORE_DOES_NOT_EXIST);
        // Perform the swap.
        // Swapper sends FA to the liquidity pair object. The liquidity pair object sends APT to the swapper, in return.
        let liquidity_pair_signer = object::generate_signer_for_extending(&liquidity_pair.extend_ref);
        let from_swapper_store = primary_fungible_store::ensure_primary_store_exists(
            swapper_address,
            fungible_asset::transfer_ref_metadata(transfer_ref)
        );
        fungible_asset::transfer_with_ref(transfer_ref, from_swapper_store, liquidity_pair.fa_store, fa_given);
        aptos_account::transfer(&liquidity_pair_signer, swapper_address, apt_gained);
        // Record state changes to the liquidity pair's reserves, and emit changes as events.
        let former_fa_reserves = liquidity_pair.fa_reserves;
        let former_apt_reserves = liquidity_pair.apt_reserves;
        liquidity_pair.fa_reserves = fa_updated_reserves;
        liquidity_pair.apt_reserves = apt_updated_reserves;
        event::emit(
            LiquidityPairReservesUpdated {
                former_fa_reserves,
                former_apt_reserves,
                new_fa_reserves: fa_updated_reserves,
                new_apt_reserves: apt_updated_reserves
            }
        );
        event::emit(
            LiquidityPairSwap {
                is_fa_else_apt: false,
                gained: (apt_gained as u128),
                swapper_address
            }
        );
    }

    /// Facilitate swapping between APT to a given FA.
    public(friend) fun swap_apt_to_fa(
        name: String,
        symbol: String,
        transfer_ref: &TransferRef,
        swapper_account: &signer,
        fa_object_metadata: Object<Metadata>,
        amount_in: u64
    ) acquires Pairs, LiquidityPair {
        // Verify the liquidity pair exists and is enabled for trading.
        assert_liquidity_pair_exists(name, symbol);
        let liquidity_pair = borrow_global_mut<LiquidityPair>(get_pair_obj_address(name, symbol));
        assert!(liquidity_pair.is_enabled, ELIQUIDITY_PAIR_DISABLED);
        // Determine the amount received of FA, when given swapper-supplied amount_in of APT.
        let (fa_gained, apt_given, fa_updated_reserves, apt_updated_reserves) = get_amount_out(
            liquidity_pair.fa_reserves,
            liquidity_pair.apt_reserves,
            false,
            amount_in
        );
        // Perform the swap.
        // Swapper sends APT to the liquidity pair object. The liquidity pair object sends FA to the swapper, in return.
        // Requires the liquidity pair object's address, which is retrieved using the stored extend_ref.
        let swapper_address = signer::address_of(swapper_account);
        let liquidity_pair_address = object::address_from_extend_ref(&liquidity_pair.extend_ref);
        let to_swapper_store = primary_fungible_store::ensure_primary_store_exists(
            swapper_address,
            fungible_asset::transfer_ref_metadata(transfer_ref)
        );
        aptos_account::transfer(swapper_account, liquidity_pair_address, apt_given);
        fungible_asset::transfer_with_ref(transfer_ref, liquidity_pair.fa_store, to_swapper_store, fa_gained);
        // Record state changes to the liquidity pair's reserves, and emit changes as events.
        let former_fa_reserves = liquidity_pair.fa_reserves;
        let former_apt_reserves = liquidity_pair.apt_reserves;
        liquidity_pair.fa_reserves = fa_updated_reserves;
        liquidity_pair.apt_reserves = apt_updated_reserves;
        event::emit(
            LiquidityPairReservesUpdated {
                former_fa_reserves,
                former_apt_reserves,
                new_fa_reserves: fa_updated_reserves,
                new_apt_reserves: apt_updated_reserves
            }
        );
        event::emit(
            LiquidityPairSwap {
                is_fa_else_apt: true,
                gained: (fa_gained as u128),
                swapper_address
            }
        );
        // Check for graduation requirements. The APT reserves must be above the pre-defined
        // threshold to allow for graduation.
        if (liquidity_pair.is_enabled && apt_updated_reserves > APT_LIQUIDITY_THRESHOLD) {
            graduate(liquidity_pair, fa_object_metadata, transfer_ref, apt_updated_reserves, fa_updated_reserves);
        }
    }

    public fun swap(
        in: FungibleAsset,
        amount_out_min: u64,
        to_token: Object<Metadata>,
        is_stable: bool,
    ): FungibleAsset {
        let from_token = fungible_asset::asset_metadata(&in);
        let pool = liquidity_pool::liquidity_pool(from_token, to_token, is_stable);
        let out = liquidity_pool::swap(pool, in);

        out
    }
