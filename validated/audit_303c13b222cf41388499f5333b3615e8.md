Based on the investigation, I found a replay-protection analog with a similar structural flaw to the reported bug class: a security guard that unconditionally "forgets" its protection state after a fixed time window, independent of the actual validity window of the credential it is meant to protect — enabling reuse (replay) of a still-valid signed request once that window passes.

### Title
JWT replay-cache eviction is decoupled from token validity, allowing replay of previously-used JWTs after `JWTReplayPeriodMs` elapses - ([File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go])

### Summary
`WorkflowMetadataHandler.Authorize` prevents replay of HTTP-trigger JWTs by tracking used JTIs (`jti` claims) in an in-memory `jwtReplayCache`, keyed by the time the JTI was first *recorded*, not by the JWT's own expiry. A background ticker purges any cache entry whose recorded time is older than `cleanupPeriod` (`JWTReplayPeriodMs`). Once an entry is purged, `isReplay` returns `false` again for that same `jti`, so if the underlying JWT is still cryptographically valid (i.e. its own `exp` claim, if enforced at all by `utils.VerifyRequestJWT`, extends beyond `JWTReplayPeriodMs`), the exact same signed request can be resubmitted and will be accepted a second time.

### Finding Description
`Authorize` calls `utils.VerifyRequestJWT` to check the signature/claims, then checks `h.jwtCache.isReplay(claims.ID)`, and finally calls `h.jwtCache.recordUsage(claims.ID)`: [1](#0-0) 

The cache is a simple `jti -> firstSeenTime` map, and cleanup deletes any entry whose `firstSeenTime` predates `now - cleanupPeriod`: [2](#0-1) 

The cleanup ticker runs on `h.jwtCache.cleanupPeriod` (i.e., `JWTReplayPeriodMs`), completely independent of the JWT's own signed expiry: [3](#0-2) 

This mirrors the reported bug-class pattern precisely: a protection mechanism (block hash in the oracle report / JTI entry in the replay cache) is only reliable within a bounded window (255 blocks / `JWTReplayPeriodMs`); once that window elapses, the tracked value reverts to an "unseen" state (zero hash / evicted cache entry), and a previously-valid signed payload becomes replayable again — as long as the underlying credential (signature / JWT) is still otherwise accepted by the verifier.

### Impact Explanation
If `JWTReplayPeriodMs` is configured shorter than the actual lifetime attackers can obtain for a valid JWT (or if `utils.VerifyRequestJWT` does not itself strictly bound token lifetime independent of this cache), an unprivileged attacker who captures or is given a previously-used, legitimately-signed HTTP-trigger JWT can replay it after the cache TTL expires to re-trigger the same authorized workflow execution — a form of unauthorized job/run replay via request impersonation of a prior legitimate call.

### Likelihood Explanation
Exploitability is fully dependent on the exact `exp` enforcement inside `utils.VerifyRequestJWT`, which I was not able to inspect before running out of tool calls. If that function independently enforces a short, hard `exp` bound at or below `JWTReplayPeriodMs`, this issue is not exploitable. If it merely defers to the caller-supplied `exp` claim (allowing longer-lived tokens) or does not enforce expiry tightly relative to the cache window, the replay window described above is real. This uncertainty should be resolved by reviewing `utils.VerifyRequestJWT`/`utils.CreateRequestJWT` (referenced in `core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler_test.go`) before treating this as a confirmed, exploitable bypass.

### Recommendation
Bind the JWT replay-cache retention to the token's own `exp` claim rather than a fixed global cleanup period — i.e., only evict a `jti` once its associated JWT's `exp` has actually passed, or reject any JWT whose `exp` exceeds `JWTReplayPeriodMs` at verification time (mirroring the recommendation in the reference report to never let the anti-replay value fall back to a bypassable default, and instead always tie it to the actual credential lifetime).

### Proof of Concept
Not fully constructible without access to `utils.VerifyRequestJWT`'s expiry enforcement; the theoretical flow is:
1. Attacker (or any observer) obtains a valid signed HTTP-trigger JWT with `jti=X` and captures its use timestamp.
2. `WorkflowMetadataHandler.Authorize` records `X` in `jwtReplayCache` at time T.
3. Wait longer than `JWTReplayPeriodMs` (cache cleanup ticker deletes `X` at `T+cleanupPeriod`).
4. If the JWT's own `exp` is still valid at `T+cleanupPeriod+ε` (i.e., `VerifyRequestJWT` does not independently reject it), resubmit the identical JWT+request; `isReplay` returns `false` and the request is authorized again, re-triggering the workflow.

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}

func newJWTReplayCache(cleanupPeriod time.Duration) *jwtReplayCache {
	return &jwtReplayCache{
		cache:         make(map[string]time.Time),
		cleanupPeriod: cleanupPeriod,
	}
}

func (cache *jwtReplayCache) isReplay(jti string) bool {
	cache.mu.RLock()
	defer cache.mu.RUnlock()

	_, exists := cache.cache[jti]
	return exists
}

func (cache *jwtReplayCache) recordUsage(jti string) {
	cache.mu.Lock()
	defer cache.mu.Unlock()

	cache.cache[jti] = time.Now()
}

// cleanupOldEntries removes expired entries from the cache
func (cache *jwtReplayCache) cleanupOldEntries(cutoff time.Time) int {
	cache.mu.Lock()
	defer cache.mu.Unlock()
	var expiredCount int
	for jti, createdAt := range cache.cache {
		if createdAt.Before(cutoff) {
			delete(cache.cache, jti)
			expiredCount++
		}
	}
	return expiredCount
}
