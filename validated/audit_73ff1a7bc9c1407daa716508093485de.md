### Title
Solver bids in the intents auction are fully visible on-chain and via mempool/RPC before the auction closes, absent any commit-reveal scheme, enabling bid-sniping/copy-bidding — (File: modules/pallets/intents-coprocessor/src/lib.rs)

### Summary
The `pallet-intents-coprocessor` bidding mechanism records every solver's `place_bid` in plaintext, both in the transaction pool and once included on-chain, with no obfuscation or delayed reveal. This is the same class of defect as the referenced audit finding — "voting does not use a commit-reveal scheme" — applied to Hyperbridge's intent-solver auction rather than a funding-round vote: any party can observe a competitor's exact bid content before the auction window closes and react to it in-band.

### Finding Description
`place_bid` accepts a `commitment` and a raw `user_op` (the solver's full fill terms — outputs, relayer fee, etc.) and stores it unencrypted, both by pushing to offchain storage (`offchain_index::set`) and recording an on-chain marker in the `Bids` double-map, immediately emitting a `BidPlaced` event: [1](#0-0) 

Before the bid is even included in a block, its full plaintext content is already exposed: `run_bid_watcher` decodes `place_bid` extrinsics straight out of the mempool import-notification stream and republishes them via a broadcast channel: [2](#0-1) 

This mempool feed and the on-chain/offchain bid store are both exposed via a dedicated public RPC surface, `intents_getBidsForOrder` and a live `intents_subscribeBids` subscription, that merges the in-flight mempool cache with finalized on-chain bids for any caller who supplies (or omits) a commitment filter: [3](#0-2) 

The SDK's auction loop itself is built around this real-time visibility: it polls `fetchBids` throughout `auctionTimeMs` and yields a `NEW_BID` event to consumers for every bid it observes as it arrives, well before the round closes: [4](#0-3) 

There is no commitment/hash-then-reveal step anywhere in this flow — a solver's price, outputs, and relayer fee are broadcast the instant the bid transaction hits the pool, not after the auction closes.

### Impact Explanation
Because every bid is broadcast in cleartext as soon as it is submitted (via mempool watcher, RPC subscription, and on-chain storage), a rival solver monitoring `intents_subscribeBids`/the mempool can trivially observe a competitor's exact fill terms and submit a marginally better bid (undercut by the smallest useful unit) just before the `auctionTimeMs` window elapses. This defeats the purpose of a sealed/competitive auction: honest solvers who invest in price discovery are systematically copy-bid and out-bid at zero cost by an observer who does no independent pricing, which degrades solver competition and creates an unfair, gameable market for order flow — directly analogous to the referenced report's concern that visible votes/bids before finalization suppress honest participation and let other participants react to (and undermine) a party's revealed intent.

### Likelihood Explanation
High likelihood of exploitation with low cost: watching the mempool or subscribing to the already-provided `intents_subscribeBids` RPC requires no special privilege — it is explicitly designed for "sub-second bid discovery" — and submitting a copy-cat `place_bid` extrinsic with a trivially adjusted output is a single unprivileged transaction available to any account with the modest storage deposit.

### Recommendation
Introduce a commit-reveal scheme for `place_bid`: solvers first submit a hash commitment of their bid terms during the collection window, then reveal the full bid only after the window closes (or reveal is gated behind a short delay/blinding factor), so bid contents cannot be observed and undercut in real time. Alternatively, encrypt bid payloads (e.g., threshold encryption released only after the auction closes) before they are broadcast to the mempool/offchain storage/RPC subscribers.

### Proof of Concept
1. Solver A calls `place_bid(commitment, user_op_A)` with competitive outputs.
2. Solver B, subscribed to `intents_subscribeBids` (or simply watching the node's tx pool via `run_bid_watcher`'s exposed cache), observes Solver A's `user_op_A` — including exact output amounts and relayer fee — immediately, well before `auctionTimeMs` elapses: [5](#0-4) 
3. Solver B constructs `user_op_B` that copies Solver A's terms but improves the output by a negligible amount, and calls `place_bid(commitment, user_op_B)` before the auction closes.
4. The SDK's `BidManager.sortBids`/`selectAndExecuteBest` selects the best (Solver B's) bid, meaning Solver A's genuine price-discovery work is always displaced by a copy-cat with zero independent risk-taking, at no cost beyond the storage deposit: [6](#0-5)

		pub fn place_bid(
			origin: OriginFor<T>,
			commitment: H256,
			user_op: BoundedVec<u8, ConstU32<1_048_576>>,
		) -> DispatchResult {
			let filler = ensure_signed(origin)?;

			// Validate user_op is not empty
			ensure!(!user_op.is_empty(), Error::<T>::InvalidUserOp);

			// Phantom orders have stricter rules: one bid per filler, no updates, and only
			// within the configured acceptance window after the order was registered. Every
			// chain's active order is checked, not just the most recently generated one.
			if let Some(active) = CurrentPhantomOrder::<T>::get() {
				if let Some((_, info)) = active.iter().find(|(c, _)| *c == commitment) {
					let window: BlockNumberFor<T> = Self::phantom_bid_window().into();
					ensure!(
						frame_system::Pallet::<T>::block_number() <= info.created_at_block + window,
						Error::<T>::PhantomOrderBidWindowClosed
					);
					ensure!(
						!Bids::<T>::contains_key(&commitment, &filler),
						Error::<T>::DuplicatePhantomBid
					);
				}
			}

			// If a bid already exists, unreserve the old deposit first
			if let Some(old_deposit) = Bids::<T>::get(&commitment, &filler) {
				<T as Config>::Currency::unreserve(&filler, old_deposit);
			}

			let deposit = Self::storage_deposit_fee();

			// Reserve the new deposit
			<T as Config>::Currency::reserve(&filler, deposit)
				.map_err(|_| Error::<T>::InsufficientBalance)?;

			// Store the bid in offchain storage
			let bid = Bid { filler: filler.clone(), user_op: user_op.to_vec() };
			let offchain_key = Self::offchain_bid_key(&commitment, &filler);
			offchain_index::set(&offchain_key, &bid.encode());

			// Store deposit amount in onchain storage for discoverability and accurate refunds
			Bids::<T>::insert(&commitment, &filler, deposit);

			Self::deposit_event(Event::BidPlaced { filler, commitment, deposit });

			Ok(())
		}

			self.bid_cache.get_bids(&commitment).map_err(runtime_error_into_rpc_error)?;

		let best_hash = self.client.info().best_hash;
		let prefix = bids_storage_prefix(&commitment);
		let prefix_key = sp_core::storage::StorageKey(prefix.clone());

		let keys = self
			.client
			.storage_keys(best_hash, Some(&prefix_key), None)
			.map_err(runtime_error_into_rpc_error)?;

			// Key layout after prefix: blake2_128(filler) ++ filler_encoded

	async fn subscribe_bids(
		&self,
		pending: PendingSubscriptionSink,
		commitment: Option<H256>,
	) -> SubscriptionResult {
		let mut rx = self.bid_sender.subscribe();
		let sink = pending.accept().await.map_err(|e| {
			runtime_error_into_rpc_error(format!("Failed to accept subscription: {e}"))
		})?;

		tokio::spawn(async move {
			while let Ok(bid) = rx.recv().await {
				if let Some(ref filter) = commitment {
					if &bid.commitment != filter {
						continue;
					}
				}
				if let Ok(msg) = SubscriptionMessage::from_json(&bid) {
					if sink.send(msg).await.is_err() {
						break;
					}
				}
			}
		});

		Ok(())
	}
