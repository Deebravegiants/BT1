### Title
Resource Quota Bypass via Retry Recursion Overwriting Already-Forbidden Waiter Results - ([File: staging/src/k8s.io/apiserver/pkg/admission/plugin/resourcequota/controller.go])

### Summary
`quotaEvaluator.checkQuotas` batches concurrent admission requests for a namespace and recurses on `UpdateQuotaStatus` conflicts (`remainingRetries`), but the per-attribute evaluation loop that starts each recursive call unconditionally overwrites `admissionAttribute.result`, including results that were already finalized as forbidden (quota exceeded) in an earlier pass. Under concurrent load this lets a request that legitimately failed a quota check get silently converted to a success, while its resource usage is never charged to the quota, allowing the effective hard limit to be exceeded.

### Finding Description
`checkAttributes` (lines 184-214) batches all queued `admissionWaiter`s for a namespace and calls `checkQuotas(quotas, admissionAttributes, 3)`. Inside `checkQuotas` (lines 228-342), the first loop (lines 237-267) calls `e.checkRequest` for every waiter and sets:
- `admissionAttribute.result = err` on failure (line 241), or
- `admissionAttribute.result = nil` if the request causes no quota delta (lines 262-264),

both **unconditionally**, with no check on the waiter's current `result` value.

Later, when `UpdateQuotaStatus` hits an optimistic-concurrency conflict (line 288), the failed quota subset is re-fetched (line 319) and `checkQuotas` recurses on `quotasToCheck` with the **full original `admissionAttributes` slice**, including waiters that already received a final forbidden result in the prior pass (line 341: `e.checkQuotas(quotasToCheck, admissionAttributes, remainingRetries-1)`).

In this recursive call, the first loop re-runs `checkRequest` for *every* waiter — even ones already marked forbidden — but now only against the smaller `quotasToCheck` subset. If a previously-forbidden waiter's resource does not match any quota in that subset, `CheckRequest` returns `(quotas, nil)` with `interestingQuotaIndexes` empty (`controller.go` lines 594-596), so `newQuotas == quotas` and `atLeastOneChangeForThisWaiter` is `false`, causing line 263 to reset `admissionAttribute.result = nil` — silently discarding the earlier forbidden verdict.

Notably, the code elsewhere is clearly aware that only sentinel/default-deny results should be updated across passes: the three places that finalize results after the update phase (lines 297-301, 306-312, 322-327) all guard with `if IsDefaultDeny(admissionAttribute.result)`. The first per-attribute loop (lines 237-267) lacks this guard, which is the root cause.

Because the waiter's forbidden result is reset to `nil` without its usage ever being merged into the "running" `quotas` accumulator (the `continue` on line 242 skips `quotas = newQuotas`), that pod's consumption is never reflected in the `ResourceQuota.Status.Used` value written via `UpdateQuotaStatus`. The pod is nonetheless admitted (`quotaEvaluator.Evaluate`, line 685, returns `waiter.result == nil`), so it is persisted in etcd. This produces an unaccounted, quota-uncharged resource that lets total live resources exceed the declared hard limit.

### Impact Explanation
This is a resource quota / admission control bypass: an ordinary namespace-scoped user with only `pods/create` permission can exceed a `ResourceQuota` hard limit (e.g., pod count, CPU/memory) by causing enough request contention to trigger the update-conflict retry path. This maps to Kubernetes' "Resource exhaustion" / "quota/admission bypass" bounty impact class — it undermines a security/isolation control (namespace resource quotas) that operators rely on for multi-tenant fairness and DoS protection, without requiring any elevated privilege.

### Likelihood Explanation
Exploitation only requires standard namespace RBAC to create the quota-governed resource (e.g., Pods) and the ability to fire many concurrent requests — trivially available to any tenant. The conflict path is triggered by ordinary optimistic-concurrency contention on `ResourceQuota.Status`, which becomes increasingly likely as concurrency increases (multiple apiserver replicas, or several batches processed back-to-back by the single-namespace work queue). No timing is adversarially exact; higher request volume makes the race more, not less, likely to manifest — matching the proof idea of firing many concurrent Pod creates against a low hard limit.

### Recommendation
Guard every write to `admissionAttribute.result` inside the initial per-attribute loop (lines 237-267) with the same `IsDefaultDeny(admissionAttribute.result)` check used later in the function, so that a result already finalized (forbidden or success) in a prior pass of the same `checkQuotas`/recursion chain can never be overwritten. Alternatively, filter `admissionAttributes` passed into the recursive call (line 341) down to only those waiters whose result `IsDefaultDeny`, and merge their accepted usage back into the running quota totals before recursing.

func (e *quotaEvaluator) checkQuotas(quotas []corev1.ResourceQuota, admissionAttributes []*admissionWaiter, remainingRetries int) {
	// yet another copy to compare against originals to see if we actually have deltas
	originalQuotas, err := copyQuotas(quotas)
	if err != nil {
		utilruntime.HandleError(err)
		return
	}

	atLeastOneChanged := false
	for i := range admissionAttributes {
		admissionAttribute := admissionAttributes[i]
		newQuotas, err := e.checkRequest(quotas, admissionAttribute.attributes)
		if err != nil {
			admissionAttribute.result = err
			continue
		}

		// Don't update quota for admissionAttributes that correspond to dry-run requests
		if admissionAttribute.attributes.IsDryRun() {
			admissionAttribute.result = nil
			continue
		}

		// if the new quotas are the same as the old quotas, then this particular one doesn't issue any updates
		// that means that no quota docs applied, so it can get a pass
		atLeastOneChangeForThisWaiter := false
		for j := range newQuotas {
			if !quota.Equals(quotas[j].Status.Used, newQuotas[j].Status.Used) {
				atLeastOneChanged = true
				atLeastOneChangeForThisWaiter = true
				break
			}
		}

		if !atLeastOneChangeForThisWaiter {
			admissionAttribute.result = nil
		}

		quotas = newQuotas
	}
