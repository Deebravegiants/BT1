### Title
Bad-debt index floor leaves phantom supply claims that drain future deposits - (File: contracts/pool/src/interest.rs)

### Summary

When bad debt meets or exceeds the market’s total supplied value, `apply_bad_debt_to_supply_index` clamps the supply index to `SUPPLY_INDEX_FLOOR_RAW` instead of reducing claims to zero. Existing scaled supply positions therefore retain a positive claim. A later deposit into the same market can be withdrawn by an old supplier even though the earlier bad debt consumed all prior backing.

### Finding Description

`apply_bad_debt_to_supply_index` computes `total_supplied_value`, caps `bad_debt` at that value, and derives the new index from the remainder. When `bad_debt >= total_supplied_value`, `remaining` becomes zero, so `new_supply_index` becomes zero and is then raised to `SUPPLY_INDEX_FLOOR_RAW`. [1](#0-0) 

The stored scaled supply positions are not reduced or removed. Because the index floor is nonzero, `unscale_supply_floor` still returns a positive withdrawal value for those old shares. The pool test demonstrates that an old scaled position remains stranded after a full wipeout, a new deposit is credited, and the stranded position withdraws the entire fresh deposit. [2](#0-1) 

The permissionless path is `Controller::clean_bad_debt`, which reaches pool bad-debt socialization once the target account is insolvent and its remaining collateral is below the dust threshold. [3](#0-2) 

### Impact Explanation

An attacker who already holds supply shares in the affected market can wait for another user to supply after the wipeout and then withdraw against the attacker’s floor-preserved shares. This drains cash belonging to the new supplier and leaves the market unable to cover the new supplier’s recorded claim. The demonstrated sequence ends with the old supplier extracting exactly the new deposit and the new supplier’s claim exceeding pool cash. [4](#0-3) 

This is theft of user funds and protocol insolvency, not merely a failed transaction.

### Likelihood Explanation

The attacker needs a supply position before a full bad-debt write-down and must wait for or induce another deposit afterward. The clean-up path itself is permissionless. [3](#0-2) 

The precondition is severe bad debt at least equal to the market’s total supplied value. That can arise when accrued liabilities exceed supplier claims while the borrower’s collateral is insufficient. The floor makes the failure deterministic once that condition is reached: no edge case in caller authorization or token semantics is required. [5](#0-4) 

### Recommendation

Do not preserve scaled supply claims after a complete write-down. When bad debt consumes the entire supplied value, explicitly zero the effective claim mechanism or record a wiped-out generation so pre-wipeout shares cannot withdraw against later deposits.

Possible approaches:

- Remove the supply-index floor for full wipeouts and make floor-unscaled claims resolve to zero.
- Reset the market’s supply ledger to a new epoch after complete socialization.
- Track a `wipeout_epoch` per market and position, rejecting withdrawals of pre-epoch shares.
- Block new supply until governance recapitalizes and explicitly clears or settles stranded claims.

### Proof of Concept

The repository already contains a concrete proof in `test_raw_cache_floor_residual_can_consume_fresh_cash_without_supply_guard`:

1. Market has `scaled_a = 1_000_000 * RAY`.
2. Apply `bad_debt = 2_000_000 * RAY`.
3. `apply_bad_debt_to_supply_index` clamps `supply_index` to `SUPPLY_INDEX_FLOOR_RAW`.
4. `unscale_supply_floor(scaled_a)` still returns a positive stranded claim.
5. A second supplier deposits `c` and receives `scaled_b`.
6. The old supplier withdraws `stranded` and receives exactly `c`.
7. Pool cash reaches zero while the second supplier’s recorded claim remains `c`. [2](#0-1)

pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}

fn test_raw_cache_floor_residual_can_consume_fresh_cash_without_supply_guard() {
    let t = TestSetup::new();
    t.as_contract(|| {
        let scaled_a_raw = 1_000_000 * RAY;
        let mut cache = t.fresh_cache(PoolStateRaw {
            supplied: scaled_a_raw,
            borrowed: 0,
            revenue: 0,
            borrow_index: RAY,
            supply_index: RAY,
            last_timestamp: 0,
            cash: 0,
        });
        let scaled_a = Ray::from(scaled_a_raw);

        apply_bad_debt_to_supply_index(&mut cache, Ray::from(2_000_000 * RAY));
        assert_eq!(
            cache.supply_index().raw(),
            SUPPLY_INDEX_FLOOR_RAW,
            "wipeout must clamp supply index UP to the floor, not reset the base"
        );

        let stranded = cache.unscale_supply_floor(scaled_a);
        assert!(stranded > 0, "floor clamp leaves userA a phantom claim");
        assert_eq!(cache.cash(), 0, "empty market: no cash to extract yet");

        let c = stranded;
        let scaled_b = cache.calculate_scaled_supply(c);
        cache.mint_supply(scaled_b);
        cache.credit_cash(c);

        let b_claim = cache.unscale_supply_floor(scaled_b);
        assert_eq!(b_claim, c, "userB's honest claim equals their deposit");

        let (burn, gross) = cache.resolve_withdrawal(i128::MAX, scaled_a);
        cache.require_reserves(gross);
        cache.burn_supply(burn);
        cache.debit_cash(gross);

        assert!(gross > 0, "stranded position pays out non-zero");
        assert_eq!(
            gross, c,
            "userA drains exactly userB's fresh deposit out of the pool"
        );

        assert!(
            cache.cash() < b_claim,
            "pool cash ({}) can no longer cover userB's claim ({}): honest supplier lost funds",
            cache.cash(),
            b_claim
        );
        assert_eq!(cache.cash(), 0, "userA drained the pool to empty");
