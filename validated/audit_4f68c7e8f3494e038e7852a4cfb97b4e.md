Audit Report

## Title
Full remaining fee credit is forfeited (not just `corrected_fee`) and misreported as `corrected_fee_with_tip` when a transaction's own dispatch kills the payer's account - ([File: substrate/frame/transaction-payment/src/payment.rs])

## Summary
In `FungibleAdapter::correct_and_deposit_fee`, when a dispatched call causes the payer's account to be killed (no providers left), the code forwards the entire pre-withdrawn `remaining_credit` (i.e., `fee_with_tip`) to `OU::on_unbalanceds` instead of splitting off only `corrected_fee` and refunding the excess, as is done in the account-alive branch. This produces a fee overcharge equal to `fee_with_tip - corrected_fee` whenever the call kills the account and the declared weight exceeds actual weight, while the emitted `TransactionFeePaid` event still reflects only `corrected_fee_with_tip`, misreporting what was actually confiscated.

## Finding Description
`withdraw_fee` withdraws `fee_with_tip` from `who` up front using `Preservation::Preserve` before the call executes [1](#0-0) . After dispatch, `correct_and_deposit_fee` computes `corrected_fee` from `corrected_fee_with_tip` and then branches on `frame_system::Pallet::<T>::account_exists(who)`:

```rust
// skip refund if account was killed by the tx
let fee_credit = if frame_system::Pallet::<T>::account_exists(who) {
    let (mut fee_credit, refund_credit) = remaining_credit.split(corrected_fee);
    if !refund_credit.peek().is_zero() {
        if let Err(not_refunded) = F::resolve(who, refund_credit) {
            fee_credit.subsume(not_refunded);
        }
    }
    fee_credit
} else {
    remaining_credit
};
``` [2](#0-1) 

When `who`'s account was killed by the call's own effects (e.g., a "transfer all" style call that removes all providers), the entire `remaining_credit` — equal to the full `fee_with_tip` withdrawn pre-dispatch — is passed to `OU::on_unbalanceds` rather than only `corrected_fee`, and the function still returns `Ok(())`. This is a deliberate but under-protective design choice (comment: "skip refund if account was killed by the tx"), because since the withdrawal happened before dispatch with `Preservation::Preserve`, the account being alive at withdrawal time does not guarantee it survives the call's own logic, allowing `corrected_fee < fee_with_tip` combined with account death to produce a forfeiture of the full amount.

## Impact Explanation
This is a genuine, reproducible accounting discrepancy: the pallet's stated invariant (fee correction should not confiscate more than `corrected_fee`) is violated whenever a transaction's own dispatch kills the sender's account. The excess is unconditionally donated to `OU::on_unbalanceds`, and the `TransactionFeePaid` event (constructed from `corrected_fee_with_tip` computed before `correct_and_deposit_fee` runs) does not reflect the larger amount actually taken, making the overcharge silently unobservable from events. This is a legitimate accounting/self-overcharge bug rather than theft from third parties, matching a fee-overcharge/accounting-asymmetry impact class.

## Likelihood Explanation
The path is reachable by any unprivileged signed account: submit a call that transfers away the account's entire remaining balance (killing all providers) combined with a declared weight in `DispatchInfo` that overestimates actual post-dispatch weight so that `corrected_fee < fee_with_tip`. No privileged origin, governance, or race condition is required — the sequence is deterministic and depends only on ordinary balance-transfer/proxy/multisig call patterns plus weight overestimation, both of which are fully within the control of a normal user.

## Recommendation
When `account_exists(who)` is `false` post-dispatch, still compute `corrected_fee` and forward only `remaining_credit - corrected_fee` (or as much of it as can be salvaged) to `OU`, treating any un-refundable dust as unavoidable; alternatively, explicitly document and emit a distinguishing event (e.g., an over-collection event) so that the gap between `corrected_fee_with_tip` and the amount actually taken is observable rather than silently absorbed and misreported via `TransactionFeePaid`.

## Proof of Concept
1. In a mock runtime using `FungibleAdapter`, construct a call that transfers away the entire balance of `who` (killing all providers) during dispatch.
2. Declare a `DispatchInfo` weight substantially larger than the call's actual post-dispatch weight, so that `corrected_fee_with_tip < fee_with_tip`.
3. Drive the extrinsic through `withdraw_fee` → dispatch → `correct_and_deposit_fee` (as `ChargeTransactionPayment`'s post-dispatch hook would).
4. Assert `frame_system::Pallet::<Test>::account_exists(who)` is `false`, and that the value forwarded to `OU::on_unbalanceds` equals the full `fee_with_tip` rather than `corrected_fee`, while the emitted `TransactionFeePaid` event reports only `corrected_fee_with_tip` — demonstrating the overcharge and event misreporting described above.
