### Title
Accrued debt overflow permanently freezes a saturated market - (File: common/src/rates/scaling.rs)

### Summary

A large, highly utilized market can reach a state where `borrowed * borrow_index` no longer fits in `i128`, even though the stored borrow index remains below `MAX_BORROW_INDEX_RAY`. Interest synchronization calls `accrue_step` before advancing `last_timestamp`; that step evaluates total borrowed value through `scaled_to_original`, which performs checked RAY multiplication and panics on overflow. [1](#0-0) [2](#0-1) 

Once this state is reached, every controller operation touching the market first asks the pool to accrue indexes, so the same overflow repeatedly reverts withdrawals, repayments, liquidations, and explicit `update_indexes` calls. [3](#0-2) [4](#0-3) 

### Finding Description

Each market stores `borrowed` as RAY-scaled debt shares and `borrow_index` as a RAY index. During accrual, `Cache::calculate_utilization` converts both totals back to RAY asset values; the borrowed leg calls `scaled_to_original(borrowed, borrow_index)`, which delegates to checked `Ray::mul`. [5](#0-4) [2](#0-1) 

The index itself can remain representable while the product `scaled_debt * index / RAY` exceeds `i128::MAX`. `global_sync` does not bound the current debt value against the representable domain before calling `accrue_step`; it also updates indexes and timestamps only after `accrue_step` returns. [6](#0-5) 

The in-repository regression test constructs an 18-decimal market containing `1_000_000_000 * 10^18` base units of supply and a 98% borrow, advances time, and observes `MathOverflow` from `update_indexes`. [7](#0-6) 

The same test confirms that the stored `borrow_index` is still below `MAX_BORROW_INDEX_RAY`, meaning the index ceiling cannot prevent the arithmetic cliff. [8](#0-7) 

### Impact Explanation

This is a permanent freezing-of-funds condition for the affected market. Suppliers cannot withdraw, borrowers cannot repay, liquidators cannot unwind the position, and the permissionless `Controller::update_indexes(caller, assets)` recovery path also reverts because it invokes the same pool accrual routine. [9](#0-8) [4](#0-3) 

The pool commit is never reached because `accrue_step` panics before `cache.commit()`, so `last_timestamp` is not advanced and later transactions retry accrual over an even longer interval rather than bypassing the overflowing state. [10](#0-9) [11](#0-10) 

The regression test explicitly demonstrates that withdrawal and repayment still fail with `MathOverflow` after the cliff is reached. [12](#0-11) 

### Likelihood Explanation

Triggering this requires a very large token market and sustained high utilization, but the prerequisite state is reachable through ordinary user calls. An attacker or whale can supply `1e9` whole units of an 18-decimal asset, provide enough separate collateral, and borrow 98% of that liquidity through `Controller::supply` and `Controller::borrow` when the market's valid configuration permits those caps and does not enforce a lower utilization ceiling. [13](#0-12) 

No privileged call is needed after the market and risk parameters exist: `Controller::update_indexes` only authorizes the submitted caller and forwards the requested hub assets to the pool's accrual operation. [9](#0-8) 

### Recommendation

Cap the economic debt value, not just `borrow_index`. During accrual, detect that `borrowed * borrow_index` would exceed `i128::MAX` before multiplying, then either clamp the index at the largest value that keeps the market's accrued debt representable or enter an explicit capped-accrual mode that still permits repayments, withdrawals, and liquidations. [5](#0-4) 

At borrow time, reject any scaled-debt level for which a permitted future index could overflow the debt-value calculation. The bound should be enforced against both the market's configured maximum rate/index trajectory and the `i128` domain, rather than relying on `MAX_BORROW_INDEX_RAY` alone. [2](#0-1) [8](#0-7)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);

fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
