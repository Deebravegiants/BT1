### Title
Malicious swap routes can inject unauthorized token transfers into the caller’s authorization tree - ([File: contracts/controller/src/strategies/swap.rs])

### Summary
An unprivileged route author can cause a strategy transaction to execute arbitrary third-party code beneath the user-signed `swap_collateral` authorization, enabling that code to transfer unrelated wallet tokens if the user signs the recorded authorization tree. [1](#0-0) [2](#0-1) 

### Finding Description
`swap_collateral` accepts caller-supplied opaque `swap` bytes after authenticating the caller and verifying ownership or delegation. [3](#0-2)  The shared swap helper passes those bytes unchanged to the configured router’s `execute_strategy` while the caller’s root authorization remains active for descendant contract calls. [4](#0-3)  The controller’s own contract authorization is intentionally limited to one exact input-token transfer, but that limit does not prevent route-selected third-party code from requesting a separate authorization from the original caller. [5](#0-4) 

A malicious route can therefore name an attacker-controlled venue that invokes `token.transfer(victim, attacker, amount)` on an unrelated token. [6](#0-5) [7](#0-6)  Soroban simulation records that transfer as a child of the victim’s `swap_collateral` authorization entry, and enforcement executes it when the returned poisoned tree is signed. [8](#0-7) [9](#0-8) 

The route can simultaneously return a fair swap output, so the controller’s positive-output measurement and later account-risk checks do not bound or detect the unrelated wallet transfer. [10](#0-9) [11](#0-10) 

### Impact Explanation
The victim can lose arbitrary unrelated wallet tokens, including tokens never supplied to or listed by the lending protocol. [12](#0-11) [13](#0-12)  The demonstrated loss is the victim’s entire external token balance while the requested collateral swap still succeeds. [14](#0-13) 

### Likelihood Explanation
The attacker must induce the victim to submit a malicious route and sign the authorization tree containing the injected child transfer. [15](#0-14)  This is realistic because `swap` is opaque caller-supplied data, route venues are reached as descendant contracts, and the malicious transfer is hidden inside an otherwise successful fair-output strategy. [16](#0-15) [17](#0-16)  A signed honest tree rejects the transfer atomically, so exploitation depends on wallet or user acceptance of the poisoned tree rather than bypassing Soroban authentication. [18](#0-17) 

### Recommendation
Do not allow opaque routes to invoke arbitrary contracts under the strategy caller’s authorization tree. [1](#0-0)  Restrict router execution to governance-allowlisted venue adapters or otherwise make venue dispatch deterministic and incapable of calling attacker-supplied contract addresses. [19](#0-18)  Wallets and integrations should also reject any strategy authorization tree containing children beyond the expected protocol token transfer, but this client-side check should be a defense-in-depth measure rather than the protocol’s only control. [20](#0-19) 

### Proof of Concept
1. Give the victim a normal collateralized account and an unrelated wallet-token balance. [21](#0-20) 
2. Deploy a malicious venue whose `swap` function executes `token::Client::new(wallet_token).transfer(victim, attacker, victim_balance)`. [22](#0-21) 
3. Encode a route that pays a fair output through that malicious venue. [23](#0-22) 
4. Have the victim call `swap_collateral(victim, victim_account_id, usdc_market, amount, eth_market, malicious_swap)`. [24](#0-23) [25](#0-24) 
5. The simulation-produced authorization tree contains the unrelated wallet-token transfer as a child of the victim’s `swap_collateral` entry. [26](#0-25) 
6. Signing that tree completes the strategy and moves the victim’s entire unrelated wallet balance to the attacker. [9](#0-8)

/// Authorizes, on behalf of the current contract, one `transfer(from, to, amount)`
/// call on `token_addr` made deeper in the next contract call (for example by
/// the pool). The entry allows no further sub-invocations.
pub fn authorize_transfer_as_current(
    env: &Env,
    token_addr: &Address,
    from: &Address,
    to: &Address,
    amount: i128,
) {
    let entry = InvokerContractAuthEntry::Contract(SubContractInvocation {
        context: ContractContext {
            contract: token_addr.clone(),
            fn_name: symbol_short!("transfer"),
            args: (from.clone(), to.clone(), amount).into_val(env),
        },
        sub_invocations: Vec::new(env),
    });
    env.authorize_as_current_contract(vec![env, entry]);

fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);

/// Returns the instance swap aggregator or fails with `AggregatorNotSet`.
pub(crate) fn get_swap_aggregator(env: &Env) -> Address {
    env.storage()
        .instance()
        .get(&ControllerKey::SwapAggregator)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::AggregatorNotSet))
}

/// Stores the swap aggregator in instance storage.
pub(crate) fn set_swap_aggregator(env: &Env, addr: &Address) {
    env.storage()
        .instance()
        .set(&ControllerKey::SwapAggregator, addr);
}
