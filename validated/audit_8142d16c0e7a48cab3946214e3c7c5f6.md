### Title
Missing EVM memory-expansion gas charge lets contracts grow memory up to the hard cap at flat opcode cost - (File: substrate/frame/revive/src/vm/evm/memory.rs, substrate/frame/revive/src/vm/evm/instructions/memory.rs)

### Summary
`Memory::<T>::resize` correctly enforces an absolute cap (`target_len > EVM_MEMORY_BYTES`) so memory cannot grow unboundedly, but no opcode that calls `resize` (`mload`, `mstore`, `mstore8`, `mcopy`) charges the EVM quadratic memory-expansion gas cost - they only charge the flat static opcode cost (`VERYLOW`/`BASE`, plus a linear copy cost for `mcopy`). This decouples the actual `Vec::resize` work (byte-moving/zeroing cost, which scales with memory size) from the gas paid, letting a contract call cheaply force large memory growth up to the hard cap using only flat-cost opcodes.

### Finding Description
`resize()` computes `target_len = num_words(offset+len) * 32`, rejects it if it exceeds `EVM_MEMORY_BYTES`, and otherwise does `self.data.resize(target_len, 0)`: [1](#0-0) 

The callers of `resize` — `mload`, `mstore`, `mstore8`, and `mcopy` — only charge fixed/static gas amounts before calling `resize`, with no term proportional to the new memory size (real EVM memory-expansion cost is `3*words + words²/512`, charged incrementally on every expansion): [2](#0-1) [3](#0-2) 

Because `resize()` itself performs no gas accounting (it is a pure bounds-check + `Vec::resize`, with no `ext.charge_or_halt` call inside it or in its callers tied to `target_len - current_len`), an attacker-controlled contract can issue a sequence of cheap `MSTORE`/`MLOAD` opcodes (flat `VERYLOW` = 3 gas each) with strictly increasing offsets to grow memory all the way to the `EVM_MEMORY_BYTES` cap, paying only `O(n)` flat gas for `n` opcodes rather than the `O(n²)`-ish quadratic cost real EVM implementations charge for the same memory growth. The `target_len > EVM_MEMORY_BYTES` check does correctly stop growth beyond the hard cap, but it does not compensate for the missing per-expansion gas charge below that cap.

### Impact Explanation
An attacker (any contract caller reaching the EVM interpreter path via a normal `call`/`instantiate` extrinsic) can force the node to perform large `Vec::resize` byte-zeroing operations (up to the `EVM_MEMORY_BYTES` limit) while paying only flat per-opcode gas, instead of the gas that would reflect the real cost of that memory growth. This is a gas/weight underpricing of an actual resource-consuming operation (memory allocation and zero-fill within a call frame), which can be used to make execution disproportionately cheap relative to the work performed, though impact is bounded by the fixed `EVM_MEMORY_BYTES` cap and per-block/per-extrinsic weight limits.

### Likelihood Explanation
Trivially reachable and repeatable: any contract call using the EVM interpreter (`pallet-revive`) can execute a loop of `MSTORE`/`MLOAD` with increasing offsets. No privileged origin, signature bypass, or special preconditions are needed beyond deploying/calling an EVM contract.

### Recommendation
Charge the standard EVM quadratic memory-expansion gas cost inside (or immediately around) `Memory::<T>::resize`, based on the delta between `current_len` and `target_len` in words, mirroring `revm`'s `memory_gas`/`gas::memory_gas` calculation, and charge it via `ext.charge_or_halt` before performing `self.data.resize`.

### Proof of Concept
Rust unit/integration test in `substrate/frame/revive/src/vm/evm/memory.rs` or an EVM interpreter test:
1. Deploy a bytecode loop executing `PUSH <offset>; MSTORE` for offsets `0, 32, 64, ..., N*32` (N large, well under `EVM_MEMORY_BYTES`).
2. Record total gas charged by the interpreter for the full sequence vs. `EVM_MEMORY_BYTES`-scale quadratic formula `3*words + words²/512`.
3. Assert that gas charged for the sequence is `O(N)` (flat `VERYLOW * N`) rather than the expected `O(N²)`-scaling quadratic cost, proving memory growth is underpriced relative to EVM spec.

	pub fn resize(&mut self, offset: usize, len: usize) -> ControlFlow<Halt> {
		let current_len = self.data.len();
		let target_len = revm::interpreter::num_words(offset.saturating_add(len)) * 32;
		if target_len > crate::limits::EVM_MEMORY_BYTES as usize {
			log::debug!(target: crate::LOG_TARGET, "check memory bounds failed: offset={offset} target_len={target_len} current_len={current_len}");
			return ControlFlow::Break(Error::<T>::OutOfGas.into());
		}

		if target_len > current_len {
			self.data.resize(target_len, 0);
		}

		ControlFlow::Continue(())
	}

pub fn mload<E: Ext>(interpreter: &mut Interpreter<E>) -> ControlFlow<Halt> {
	interpreter.ext.charge_or_halt(EVMGas(VERYLOW))?;
	let ([], top) = interpreter.stack.popn_top()?;
	let offset = as_usize_or_halt::<E::T>(*top)?;
	interpreter.memory.resize(offset, 32)?;
	*top = U256::from_big_endian(interpreter.memory.slice_len(offset, 32));
	ControlFlow::Continue(())
}

	interpreter.ext.charge_or_halt(EVMGas(VERYLOW))?;
	let [offset, value] = interpreter.stack.popn()?;
	let offset = as_usize_or_halt::<E::T>(offset)?;
	interpreter.memory.resize(offset, 32)?;
	interpreter.memory.set(offset, &value.to_big_endian());
	ControlFlow::Continue(())
}

pub fn mcopy<E: Ext>(interpreter: &mut Interpreter<E>) -> ControlFlow<Halt> {
	let [dst, src, len] = interpreter.stack.popn()?;

	// Into usize or fail
	let len = as_usize_or_halt::<E::T>(len)?;
	// Deduce gas
	let Some(gas_cost) = copy_cost_verylow(len) else {
		return ControlFlow::Break(Error::<E::T>::OutOfGas.into());
	};
	interpreter.ext.charge_or_halt(EVMGas(gas_cost))?;
	if len == 0 {
		return ControlFlow::Continue(());
	}

	let dst = as_usize_or_halt::<E::T>(dst)?;
	let src = as_usize_or_halt::<E::T>(src)?;
	// Resize memory
	interpreter.memory.resize(max(dst, src), len)?;
	// Copy memory in place
	interpreter.memory.copy(dst, src, len);
	ControlFlow::Continue(())
}
