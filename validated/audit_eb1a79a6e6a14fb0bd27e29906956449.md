The comment at `vesting.move:921-922` explicitly documents the exact bug-class from the report and shows the developers already recognized it and partially mitigated it — but only for the beneficiary-registration case, not for the direct-transfer-opt-out case.

### Title
Malicious shareholder can permanently lock all vested/staked APT for every shareholder in a `vesting::VestingContract` — (File: `aptos-move/framework/aptos-framework/sources/vesting.move`)

### Summary
`vesting::distribute` withdraws all withdrawable stake in one call and then loops over *every* shareholder, paying each one via `aptos_account::deposit_coins`. If the deposit to a single shareholder aborts, the whole atomic transaction reverts, so no shareholder gets paid and the withdrawn stake is never actually removed from the vesting pool. The code already guards against one cause of this (unregistered beneficiary, see the comment at [1](#0-0) ), but does not guard against a shareholder simply opting out of un-registered direct transfers on their own account.

### Finding Description
`distribute` in `staking_contract.move`/`vesting.move` performs a two-phase pattern analogous to the EigenLayer bug: phase 1 (`unlock_rewards`/`vest`) commits an irreversible schedule/accounting change in an earlier transaction, and phase 2 (`distribute`) later extracts the real coins from the stake pool and pays out all shareholders in a single loop: [2](#0-1) 

Payment to each shareholder goes through `aptos_account::deposit_coins`: [3](#0-2) 

`deposit_coins` only bypasses the `can_receive_direct_coin_transfers` check if the recipient is *already registered* for `AptosCoin`. If a shareholder's account exists but has never registered an `AptosCoin` `CoinStore`, that shareholder can unilaterally set their own `DirectTransferConfig.allow_arbitrary_coin_transfers` to `false`: [4](#0-3) 

Once set, any call to `distribute()` that reaches that shareholder in the `for_each_ref` loop will abort with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`, and because Move transactions are atomic, the entire `distribute()` call — including the already-executed `withdraw_stake` from the underlying `StakePool` — rolls back. The coins are never actually removed from custody nor delivered; they simply remain locked as "withdrawable but never withdrawn" stake indefinitely.

Critically, unlike `batch_transfer`-style helpers, there is no `indicesToSkip`-equivalent, no per-shareholder retry, and no way to exclude a bad recipient from `distribute()`. Worse, `terminate_vesting_contract` — the only path meant to let the admin unwind a vesting contract — itself calls `distribute()` first: [5](#0-4) 

So even the admin's termination/recovery path is blocked by the same malicious shareholder.

Developers were aware of this exact class of bug for the *beneficiary* address (added via `set_beneficiary`) and added an explicit registration check with a comment referencing "distribute() wouldn't fail and block all other accounts": [1](#0-0) 

However, this check is never applied to the **shareholders themselves** at `create_vesting_contract` time — [6](#0-5)  only validates `withdrawal_address` registration (`assert_account_is_registered_for_apt(withdrawal_address)`), not each shareholder. A shareholder who is a valid grant recipient at creation time can later deregister/opt-out of direct transfers, or a shareholder could simply never have registered a `CoinStore` in the first place, and set `allow_arbitrary_coin_transfers = false` any time before the next `distribute()` call.

The identical unprotected pattern also exists in `staking_contract::distribute_internal`, which is explicitly documented as callable by *anyone*, not just the staker/operator: [7](#0-6) 

### Impact Explanation
This is a custody-grade permanent-lock issue: a single unprivileged shareholder among potentially many can indefinitely freeze the entire pool of APT owed to *all* shareholders in a vesting contract (rewards + vested grant), and simultaneously block the admin's only unwind path (`terminate_vesting_contract` → `admin_withdraw`). Because the underlying stake keeps earning/unlocking more rewards over time (via `unlock_rewards`/`vest`), the amount of permanently stuck value grows unbounded until someone identifies and neutralizes the malicious shareholder — for which there is no on-chain mechanism (no removal, no skip-index, no per-shareholder retry).

### Likelihood Explanation
Any address that is or becomes a shareholder in a `VestingContract` (or a staker in a `staking_contract` distribution pool) can trigger this by calling the permissionless `aptos_account::set_allow_direct_coin_transfers(false)` on their own account before that account has an `AptosCoin` `CoinStore` registered. This requires no special privilege, no admin cooperation, and no cost beyond a normal transaction — only the precondition that the shareholder's `AptosCoin` store is not yet registered when `distribute()` next executes.

### Recommendation
- In `create_vesting_contract`, require `assert_account_is_registered_for_apt(shareholder)` for every shareholder (mirroring the existing check on `withdrawal_address` and `set_beneficiary`'s new-beneficiary check), or force-register the `CoinStore` for each shareholder at creation time.
- In `distribute`/`distribute_internal`, harden the payout loop to not depend on unregistered/opt-out recipients: e.g., use `primary_fungible_store`/force-deposit semantics that cannot be blocked by `DirectTransferConfig`, or catch failures per-recipient (e.g., route a failing recipient's share to a claimable escrow) instead of aborting the whole batch.
- Add a `skip`/pull-based claim model so an individual shareholder's inability to receive funds cannot block distribution to everyone else.

### Proof of Concept
Not independently executable from static review alone (would require a Move unit test), but the trace is:
1. Admin calls `create_vesting_contract` with shareholders `[A, B]`, where `B`'s account exists but has never called `coin::register<AptosCoin>`.
2. `B` calls `aptos_account::set_allow_direct_coin_transfers(B_signer, false)` — [8](#0-7)  shows the standard usage pattern of this function.
3. Time passes; rewards/vesting accrue and unlock via `unlock_rewards`/`vest`.
4. Anyone calls `distribute(contract_address)`. The loop reaches `B`, calls `aptos_account::deposit_coins(B, ...)`, which hits `can_receive_direct_coin_transfers(B) == false` and aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` inside `deposit_coins` — [3](#0-2) .
5. The entire `distribute` transaction reverts; `A`'s share and `B`'s share both remain undistributed and the stake stays "withdrawable" but un-withdrawn.
6. `terminate_vesting_contract` also fails for the same reason since it invokes `distribute` first — [5](#0-4) , leaving all shareholders' funds permanently locked with no on-chain recovery mechanism.

    /// Distribute any withdrawable stake from the stake pool.
    public entry fun distribute(contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        let coins = withdraw_stake(vesting_contract, contract_address);
        let total_distribution_amount = coin::value(&coins);
        if (total_distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        // Distribute coins to all shareholders in the vesting contract.
        let grant_pool = &vesting_contract.grant_pool;
        let shareholders = &grant_pool.shareholders();
        shareholders.for_each_ref(|shareholder| {
            let shareholder = *shareholder;
            let shares = pool_u64::shares(grant_pool, shareholder);
            let amount = pool_u64::shares_to_amount_with_total_coins(grant_pool, shares, total_distribution_amount);
            let share_of_coins = coin::extract(&mut coins, amount);
            let recipient_address = get_beneficiary(vesting_contract, shareholder);
            aptos_account::deposit_coins(recipient_address, share_of_coins);
        });

        // Send any remaining "dust" (leftover due to rounding error) to the withdrawal address.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(vesting_contract.withdrawal_address, coins);
        } else {
            coin::destroy_zero(coins);
        };

        );

    /// Distribute all unlocked (inactive) funds according to distribution shares.
    fun distribute_internal(
        staker: address,
        operator: address,
        staking_contract: &mut StakingContract,
    ) acquires BeneficiaryForOperator {
        let pool_address = staking_contract.pool_address;
        // Create the Staker resource if it doesn't exist to backfill the Staker resource for each pool.
        if (!exists<Staker>(pool_address)) {
            let pool_signer =
                &account::create_signer_with_capability(&staking_contract.signer_cap);
            move_to(pool_signer, Staker { staker });
        };
        let (_, inactive, _, pending_inactive) = stake::get_stake(pool_address);
        let total_potential_withdrawable = inactive + pending_inactive;
        let coins =
            stake::withdraw_with_cap(
                &staking_contract.owner_cap, total_potential_withdrawable
            );
        let distribution_amount = coin::value(&coins);
        if (distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        let distribution_pool = &mut staking_contract.distribution_pool;
        update_distribution_pool(
            distribution_pool,
            distribution_amount,
            operator,
            staking_contract.commission_percentage
        );

        // Buy all recipients out of the distribution pool.
        while (distribution_pool.shareholders_count() > 0) {
            let recipients = distribution_pool.shareholders();
            let recipient = recipients[0];
            let current_shares = distribution_pool.shares(recipient);
            let amount_to_distribute =
                distribution_pool.redeem_shares(recipient, current_shares);
            // If the recipient is the operator, send the commission to the beneficiary instead.
            if (recipient == operator) {
                recipient = beneficiary_for_operator(operator);
            };
            aptos_account::deposit_coins(
                recipient, coin::extract(&mut coins, amount_to_distribute)
            );

            emit(
                Distribute {
                    operator,
                    pool_address,
                    recipient,
                    amount: amount_to_distribute
                }
            );
        };

        // In case there's any dust left, send them all to the staker.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(staker, coins);
            distribution_pool.update_total_coins(0);
        } else {
            coin::destroy_zero(coins);
        }
    }
