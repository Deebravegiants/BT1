### Title
Auth check uses stale cached `Account.owner` — NFT buyer gets no control, NFT seller keeps spending authority - (File: contracts/controller/src/account.rs)

### Summary
`position-nft::transfer` moves account ownership in the NFT contract, but the controller's account-spending gate `require_owner_or_delegate` compares the caller against the `owner` field stored inside the `Account` struct, which is written once at `create_account` and never re-stamped from the NFT. A caller who sells/transfers their position NFT therefore retains full borrow/withdraw authority over the account, while the new NFT owner — the party `require_account_owner` (`account.rs:143`) actually recognizes as owner — is rejected. This is the direct analog of a signature check that runs but does not verify the real signer: `caller.require_auth()` executes, yet it is checked against the wrong identity.

### Finding Description
- `create_account` stores `owner` inside `Account` at mint time (`account.rs:64-70`).
- `is_owner_or_delegate`/`require_owner_or_delegate` (`account.rs:115-140`) take `owner` from that stored struct: `if caller == owner { return true; }` and `storage::get_delegates(env, account_id, owner)`.
- `position-nft::transfer` is stock OpenZeppelin (`contract.rs:111` in `permissionless_entrypoints.txt`); it mutates `NFTStorageKey::Owner` only and performs no callback into the controller, so `Account.owner` is never updated.
- Meanwhile `require_account_owner` (`account.rs:143-148`) reads `storage::account_owner(env, account_id)` — the live NFT owner — proving the codebase treats the NFT as the source of truth and keeps two divergent owner records.
- The stale path is reachable by the original owner after transferring the NFT:
  - `withdraw` → `process_withdraw` calls `require_owner_or_delegate(env, account_id, caller, &account.owner)` (`positions/supply.rs:150`).
  - `borrow` → `process_borrow` same check (`positions/debt.rs:43`).
  - `swap_collateral`, `swap_debt`, `repay_debt_with_collateral`, `multiply`, `flash_position`, `migrate_from_blend` all gate on `require_owner_or_delegate` per `permissionless_entrypoints.txt:53-56`.
- The declared invariant is even violated in docs: `permissionless_entrypoints.txt:111` claims "delegate grants from the previous owner go inactive" after transfer, but `is_owner_or_delegate` looks up delegates keyed by the stale `account.owner`, so the seller's delegates also retain authority.

### Impact Explanation
Theft of user funds. After buying/receiving a position NFT, the victim's collateral can be drained by the previous owner: `borrow(caller=old_owner, account_id, borrows, to=Some(old_owner))` draws debt against the victim's collateral to an arbitrary `recipient` (`debt.rs:45-47`), and `withdraw` can pull collateral out up to solvency limits. Conversely the new NFT owner cannot `borrow`/`withdraw`/`add_delegate` on the account they own — funds are effectively controlled by the seller, breaking the NFT = account-owner invariant that `permissionless_entrypoints.txt:106` asserts ("The NFT owner is the account owner").

### Likelihood Explanation
A single unprivileged address triggers this with one `position-nft::transfer` followed by `controller::borrow`/`withdraw`; no governance, oracle, or timing dependence. It requires only a victim willing to acquire a position NFT — e.g., via secondary-market sale, OTC account transfer, or using the NFT as collateral elsewhere. Severity is bounded to accounts that change hands after creation, so Medium–High; the auth bypass is unconditional once the NFT moves.

### Recommendation
Make the NFT the single source of truth for spending authority: inside `is_owner_or_delegate`/`require_owner_or_delegate`, resolve the owner via `storage::account_owner(env, account_id)` (the same read `require_account_owner` performs) instead of trusting `Account.owner`, or delete `Account.owner` entirely and always read `owner_of` from the position-nft contract. Delegate grants should be keyed by the live NFT owner so a transfer actually deactivates the seller's delegates, matching the documented invariant.

### Proof of Concept
```rust
// 1. Alice supplies collateral; account 7 is minted, Account.owner = ALICE.
let acct = t.supply(ALICE, "USDC", 100_000.0); // returns account_id 7

// 2. Alice transfers the position NFT to Bob (position-nft::transfer).
//    NFT owner_of(7) = BOB; controller Account.owner still = ALICE.
let nft = soroban_sdk::token::TokenClient::new(&env, &t.position_nft); // NFT client
nft.transfer(&alice, &bob, &7);

// 3. Alice (no longer the owner) still passes require_owner_or_delegate,
//    because it compares caller to the stale Account.owner field.
//    Borrow to herself against Bob's collateral:
t.ctrl_client().borrow(&alice, &7, &debts, &Some(alice.clone()));
//    Succeeds: caller == account.owner (stale). Debt is booked on account 7,
//    proceeds go to `to` = Alice, collateral backing is Bob's.

// 4. Bob, the actual NFT owner, is rejected:
//    require_owner_or_delegate compares BOB to stored ALICE -> NotAuthorized (#44).
assert_contract_error(
    t.ctrl_client().try_withdraw(&bob, &7, &withdrawals, &None),
    GenericError::NotAuthorized as u32,
);
```
