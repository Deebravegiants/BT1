### Title
Permissionless LTV restamping can force a borrower's collateral snapshot to a newly lowered LTV and freeze their withdrawals/borrows - (File: contracts/controller/src/risk/params.rs)

### Summary
`update_account_threshold` is callable by any authenticated address for arbitrary `account_ids`, and with `has_risks = false` it restamps every listed supply position's cached `loan_to_value` to the currently listed value unconditionally (no health-factor gate, no owner consent). When governance lowers an asset's LTV, an attacker can immediately force a victim's account onto the new, lower LTV, collapsing the LTV-weighted collateral used to gate `borrow`, `withdraw`, and all strategy exits — freezing the user's funds even though the account was solvent and untouchable moments earlier.

### Finding Description
Each `AccountPosition` stores a snapshot of `loan_to_value` taken at supply time, so accounts legitimately keep their old LTV until a keeper restamps it. `update_account_threshold(caller, has_risks, account_ids)` only calls `validation::require_authorized_caller` (i.e., `caller.require_auth()` on an attacker-supplied address) and then iterates `sync_account_thresholds` over any account ids [1](#0-0) . In `LtvOnly` scope, `refresh_supply_risk_params` unconditionally writes `position.loan_to_value = effective_config.loan_to_value` — the `FullTuple`-only liquidation-parameter gate (`favors_liquidator` / HF ≥ 1.05) does not apply [2](#0-1) . The HF ≥ 1.05 assertion at the end of `sync_account_thresholds` runs only when `full_tuple` is set [3](#0-2) . This mirrors the reported bug class: a permissionless function applies attacker-chosen parameters to a victim's pending state — here the "output asset" is the victim's own risk parameters. Unlike the report, the strategy entrypoints that would swap a user's assets (`swap_debt`, `swap_collateral`, `repay_debt_with_collateral`) are properly guarded by `account::require_owner_or_delegate` [4](#0-3) , so the analog lives in the keeper entrypoint instead.

### Impact Explanation
Temporary freezing of funds. Solvency checks for `borrow`, `withdraw` and the six strategies require LTV-weighted collateral to cover debt, using each position's *cached* `loan_to_value`. An account with debt whose old LTV still covered a withdrawal can, after a forced restamp to a lower listed LTV, fail the solvency check and be unable to withdraw collateral or borrow until prices/debt move enough — a state the victim did not consent to and cannot reverse (a second `update_account_threshold` call cannot raise the value back, since the listed config is now the lower number).

### Likelihood Explanation
Requires only that governance has legitimately lowered (or newly listed with a lower) `loan_to_value` for a spoke asset the victim supplies — a routine, non-privileged-bug precondition. The trigger itself is fully unprivileged: any address calls `update_account_threshold(anyone, false, [victim_id])`, paying only gas, and can batch many victim accounts per call since `account_ids` is unbounded.

### Recommendation
Restrict the harmful direction: in `sync_account_thresholds`/`refresh_supply_risk_params`, only lower a position's stored `loan_to_value` when the caller is the account owner/delegate, or apply the same hypothetical-solvency gate used for liquidation params — i.e., skip (or revert on) positions where the new LTV would push the account below its solvency check, analogous to `clears_min_hf`. Alternatively, always evaluate solvency against the *listed* LTV rather than the snapshot, removing the stale-LTV grace entirely so keepers cannot selectively time it against victims.

### Proof of Concept
1. Governance lowers `loan_to_value` of asset X in the victim's spoke from 0.8 to 0.5 (legitimate config change).
2. Victim's account holds X as collateral with debt; its cached snapshot still says 0.8, so `withdraw` of part of the collateral would pass the LTV-coverage check.
3. Attacker calls `update_account_threshold(attacker, false, [victim_id])`. `require_authorized_caller` only auths the attacker's own address; `sync_account_thresholds` restamps `position.loan_to_value = 0.5` via `refresh_supply_risk_params` in `LtvOnly` scope, with no HF gate [5](#0-4) .
4. Victim's subsequent `withdraw`/`borrow`/`swap_collateral` reverts on the solvency check because LTV-weighted collateral no longer covers debt — funds are frozen until market conditions change or debt is repaid.

```rust
pub(crate) fn update_account_threshold(
    env: &Env,
    caller: Address,
    has_risks: bool,
    account_ids: Vec<u64>,
) {
    validation::require_authorized_caller(env, &caller);

    let scope = if has_risks {
        RiskRefreshScope::FullTuple
    } else {
        RiskRefreshScope::LtvOnly
    };

    let mut cache = Context::new(env);

    for account_id in account_ids {
        cache.reset_spoke_context();
        sync_account_thresholds(env, account_id, scope, &mut cache);
    }
```
