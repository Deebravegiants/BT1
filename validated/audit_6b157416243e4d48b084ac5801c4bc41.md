### Title
Unsigned `feeStructure.feeToken` lets a relay drain a wallet in an arbitrary (higher-value) ERC-20 during Emporium fee collection - (File: `contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol`)

### Summary
`EmporiumUpgradeable.verifyWallet()` binds the signer's authorization only to `emporiumMessage`, the hash of `stack.ops`, `maxFee` and `deadline`, and separately checks `feeStructure.flatFee <= stack.maxFee`. The `feeStructure.feeToken` field — the ERC‑20 that will actually be pulled from the signer's stealth wallet — is never included in the EIP‑712 digest that the wallet owner signs.

### Finding Description
The Emporium fee flow is:
- `payRelayFees()` picks `flatFee = feeStructure.flatFee` whenever `erc20TokenAddress == feeStructure.feeToken` for one of the (attacker/relay-controlled) `circomData.erc20TokenAddresses` with a negative delta, then calls `payRelay()` → `sendToRelayFromWallet()` → `IHinkalWallet(signerAddress).doSendToRelay(relay, relayFee, feeToken)`. [1](#0-0) [2](#0-1) 

- The only cryptographic authorization for this whole action is `verifyWallet()`, whose signed payload is `EMPORIUM_SIGNATURE_TYPEHASH(emporiumMessage, opsHash, maxFee, deadline)`, plus a separate numeric check `feeStructure.flatFee > stack.maxFee → revert`. Neither the digest nor this check constrains which token `feeStructure.feeToken` is. [3](#0-2) 

- `circomData` (including `feeStructure`) is assembled and submitted by whoever calls `Hinkal.transact()` (typically a relay), not by the signer. The integrity check on `circomData` (`getHashedCalldata`) only proves the data wasn't altered after the *relay* built it — it does not prove the *wallet owner* agreed to the specific `feeToken`, since `feeToken` is excluded from the EIP‑712 hash that the wallet owner actually signs. [4](#0-3) [5](#0-4) 

Consequently, a malicious relay can construct `circomData.erc20TokenAddresses` to include a high-value token the signer's wallet holds/approved (with a negative delta from an op the signer did authorize), set `feeStructure.feeToken` to that high-value token, and set `feeStructure.flatFee` up to `stack.maxFee` (the numeric cap the signer *did* sign, presumably denominated by the user in a cheap gas token like USDC). Since `feeToken` is unconstrained, the relay redenominates the same numeric fee amount into a far more valuable asset (e.g. WBTC instead of USDC), extracting value the signer never authorized to be taken in that token.

### Impact Explanation
This is a "temporary/permanent freezing" and, more directly, a "theft of protocol/relay fees" and "unauthorised asset movement a wallet owner never authorised" scenario per the rules: the relay moves value out of the user's Hinkal wallet in a token and amount the signer's EIP‑712 signature never bound, purely because `feeToken` is excluded from the signed struct. This is High severity: theft of value from the user's wallet by an unprivileged relay, executing an asset movement never authorised by the signer.

### Likelihood Explanation
Any relay that assembles `circomData`/`EmporiumStack` for a user (the normal, permissionless relay role in this design — no admin/owner/manager privilege required) can perform this attack whenever the signer holds or has any op in the batch touching a valuable ERC‑20. No cryptographic collision is needed — it simply exploits the fact that `feeToken` is not part of the signed payload.

### Recommendation
Include `feeStructure.feeToken` (and ideally the whole `FeeStructure`) inside `EMPORIUM_SIGNATURE_TYPEHASH` / the digest recovered in `verifyWallet()`, so the signer explicitly authorizes both the fee token and the fee amount, not just a token-agnostic numeric cap.

### Proof of Concept
1. Signer signs an `EmporiumStack` authorizing some `ops` with `maxFee = 5` (intending 5 USDC as relay fee) and `deadline`.
2. Malicious relay includes the signer's stealth wallet's WBTC balance as one of `circomData.erc20TokenAddresses` (with a legitimate negative delta from an authorized op), and sets `circomData.feeStructure = {feeToken: WBTC, flatFee: 5, variableRate: 0}`.
3. `verifyWallet()` only checks `flatFee (5) <= maxFee (5)` — passes, since the token isn't checked.
4. `payRelayFees()` finds `erc20TokenAddress == feeStructure.feeToken` (WBTC) → `flatFee = 5`, and calls `sendToRelayFromWallet` → `IHinkalWallet(signerAddress).doSendToRelay(relay, 5, WBTC)`, pulling 5 whole WBTC (far exceeding the 5 USDC the user believed they capped) to the relay. [6](#0-5)

```text
    function payRelayFees(
        CircomData calldata circomData,
        address signerAddress,
        int256[] calldata deltaAmountChanges
    ) internal {
        FeeStructure calldata feeStructure = circomData.feeStructure;

        bool foundToken = false;

        for (uint256 i = 0; i < circomData.erc20TokenAddresses.length; i++) {
            // tokens deposited into Emporium are not charged
            if (deltaAmountChanges[i] >= 0) {
                continue;
            }

            address erc20TokenAddress = circomData.erc20TokenAddresses[i];
            bool isFeeToken = erc20TokenAddress == feeStructure.feeToken;

            if (isFeeToken) {
                foundToken = true;
            }

            uint256 relayFee = 0;
            uint256 flatFee = isFeeToken ? feeStructure.flatFee : 0;

            if (signerAddress == address(0)) {
                uint256 sumAbs = uint256(-deltaAmountChanges[i]);

                EmporiumStorageVars storage $ = _getEmporiumStorage();
                relayFee = $._hinkalHelper.calculateRelayFee(
                    sumAbs,
                    flatFee,
                    feeStructure.variableRate
                );
            } else {
                relayFee = flatFee;
            }

            payRelay(
                circomData.relay,
                signerAddress,
                relayFee,
                erc20TokenAddress
            );
        }
```

```text
    function verifyWallet(
        EmporiumStack memory stack,
        CircomData calldata circomData
    ) internal {
        EmporiumStorageVars storage $ = _getEmporiumStorage();

        if ($.usedMessages[circomData.emporiumMessage]) {
            revert UsedMessage();
        }

        $.usedMessages[circomData.emporiumMessage] = true;

        if (stack.signerAddress == address(0)) {
            return;
        }

        bytes32 hashedMessage = _hashTypedDataV4(
            keccak256(
                abi.encode(
                    EMPORIUM_SIGNATURE_TYPEHASH,
                    circomData.emporiumMessage,
                    _hashEmporiumOps(stack.ops),
                    stack.maxFee,
                    stack.deadline
                )
            )
        );

        (address recoveredAddress, ECDSA.RecoverError err) = ECDSA.tryRecover(
            hashedMessage,
            stack.v,
            stack.r,
            stack.s
        );
        bool verified = err == ECDSA.RecoverError.NoError &&
            recoveredAddress == stack.signerAddress;
        if (!verified) {
            revert InvalidSignature();
        }

        if (block.timestamp > stack.deadline) {
            revert SignatureExpired();
        }

        if (circomData.feeStructure.flatFee > stack.maxFee) {
            revert FeeExceedsSignedMax();
        }
    }
```
