### Title
Emporium relay-fee `variableRate` is unauthenticated by the signer's EIP-712 signature, allowing a malicious relay to inflate fees taken from a signed Emporium operation - (File: contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol)

### Summary
This is the analog of the TraitForge bug class: a value that is *acted on* by the contract (here, the relay fee actually charged) is not covered by the equality/authentication mechanism that is supposed to bind it (here, the signer's EIP-712 signature), which lets an unprivileged actor (the relay/caller) change it without invalidating the check that is supposed to gate it.

### Finding Description
`verifyWallet()` in `EmporiumUpgradeable.sol` recovers the signer from an EIP-712 typed hash built from `EMPORIUM_SIGNATURE_TYPEHASH`, which only commits to `circomData.emporiumMessage`, the hash of `stack.ops`, `stack.maxFee`, and `stack.deadline` [1](#0-0) . It then only bounds `circomData.feeStructure.flatFee` against `stack.maxFee`:
```
if (circomData.feeStructure.flatFee > stack.maxFee) {
    revert FeeExceedsSignedMax();
}
``` [2](#0-1) 

`circomData.feeStructure.variableRate` (the percentage-based relay fee, "measured in beeps = 0.01 of 1%", capped generically at 10000 by `HinkalHelper.dimensionsCheck`) is never checked against anything the signer actually signed [3](#0-2) . The only global sanity bound is `variableRate <= 10000` in `HinkalHelper`, i.e. up to 100% of the withdrawn amount can be taken as a variable fee, and this bound is not signer-specific [4](#0-3) .

Because `feeStructure` (including `variableRate`) is part of the SNARK's `calldataHash` integrity check and the prover-side signed message used for `Hinkal.transact`'s own EdDSA signature (`signedMessageHash`), it is bound to the *value of the note being spent by the shielded prover*. But in the Emporium flow, `verifyWallet`'s EIP-712 signature is a **second, independent authorization** by the Emporium operation signer (`stack.signerAddress`), and it is this signature — not the SNARK proof — that is meant to authorize *how the withdrawn/managed funds get spent*, including how much goes to the relay. Since `variableRate` is excluded from `EMPORIUM_SIGNATURE_TYPEHASH`, a malicious relay assembling the `circomData.feeStructure` (which it controls off-chain before submission, since `circomData` is passed as `calldata` by whoever calls `Hinkal.transact`/executes the external action) can set an arbitrary `variableRate` up to the global 10000 cap while keeping `flatFee <= stack.maxFee`, and the wallet's signature still validates.

`payRelayFees` then applies this attacker-controlled `variableRate` to compute `relayFee` and transfers it out of the signer's funds via `sendToRelayFromWallet` / `payRelay`, moving value that the signer never actually authorized in their signed payload [5](#0-4) .

### Impact Explanation
This breaks the "unauthorised asset movement" equality class: a `transferFrom`/wallet operation (fee payment via `sendToRelayFromWallet`) executes without being authorised by the signer whose EIP-712 signature is meant to gate the Emporium operation. This constitutes theft of protocol/relay-fee-adjacent value from the signer's shielded/withdrawn balance — a malicious relay can drain up to 100% of the transferred amount as "variable fee," which qualifies as High/Critical-level theft depending on amount, since the signer's `maxFee` bound only covers the flat component.

### Likelihood Explanation
Any relay (an unprivileged, potentially malicious actor per the threat model) that assembles the `CircomData.feeStructure` for a transaction using the Emporium external action can trivially set `variableRate` to the maximum allowed (10000 = 100%) without the signer's signature becoming invalid, since `variableRate` is absent from `EMPORIUM_SIGNATURE_TYPEHASH`. No special privilege beyond acting as (or colluding with) the relay is required, making this a directly reachable and easy-to-exploit path whenever a user relies on relay-mediated Emporium operations with a wallet signature.

### Recommendation
Include `circomData.feeStructure.variableRate` (and ideally the whole `feeStructure`) inside the EIP-712 typed data hashed in `verifyWallet` (`EMPORIUM_SIGNATURE_TYPEHASH`), and add an explicit signer-set cap/comparison for `variableRate` analogous to the existing `flatFee > stack.maxFee` check, so the signer's authorization actually binds the percentage-based fee taken from their funds.

### Proof of Concept
1. User signs an Emporium `EmporiumStack` (`ops`, `maxFee`, `deadline`) via EIP-712, expecting `flatFee <= maxFee` and a reasonable `variableRate` to apply.
2. Relay constructs `circomData.feeStructure = {feeToken, flatFee: <= stack.maxFee>, variableRate: 10000}` and submits the transaction.
3. `verifyWallet` recovers the signer correctly (their signature never covered `variableRate`) and only reverts if `flatFee > maxFee`; with `flatFee` set within bound, verification passes [6](#0-5) .
4. `payRelayFees` computes `relayFee` using `variableRate = 10000`, taking up to 100% of the delta amount, and sends it to the relay from the signer's wallet, without the signer ever having agreed to that rate.

    function verifyWallet(
        EmporiumStack memory stack,
        CircomData calldata circomData
    ) internal {
        EmporiumStorageVars storage $ = _getEmporiumStorage();

        if ($.usedMessages[circomData.emporiumMessage]) {
            revert UsedMessage();
        }

        $.usedMessages[circomData.emporiumMessage] = true;

        if (stack.signerAddress == address(0)) {
            return;
        }

        bytes32 hashedMessage = _hashTypedDataV4(
            keccak256(
                abi.encode(
                    EMPORIUM_SIGNATURE_TYPEHASH,
                    circomData.emporiumMessage,
                    _hashEmporiumOps(stack.ops),
                    stack.maxFee,
                    stack.deadline
                )
            )
        );

        (address recoveredAddress, ECDSA.RecoverError err) = ECDSA.tryRecover(
            hashedMessage,
            stack.v,
            stack.r,
            stack.s
        );
        bool verified = err == ECDSA.RecoverError.NoError &&
            recoveredAddress == stack.signerAddress;
        if (!verified) {
            revert InvalidSignature();
        }

        if (block.timestamp > stack.deadline) {
            revert SignatureExpired();
        }

        if (circomData.feeStructure.flatFee > stack.maxFee) {
            revert FeeExceedsSignedMax();
        }
    }
