### Title
Bad-debt wipeout leaves phantom supply claims that drain later deposits - (File: contracts/pool/src/interest.rs)

### Summary
When bad debt equals or exceeds a market’s total supplied value, `apply_bad_debt_to_supply_index` clamps the new supply index upward to `SUPPLY_INDEX_FLOOR_RAW` instead of reducing it to zero. [1](#0-0)  The seize path then burns the borrower’s entire debt position while leaving every existing scaled supply share outstanding. [2](#0-1)  Those economically wiped shares retain a nonzero claim equal to roughly 0.1% of the former supplied value, which can be withdrawn after a victim adds fresh cash. [3](#0-2) 

### Finding Description
`clean_bad_debt` is permissionless and sends all of the insolvent account’s borrow positions to the pool as `PoolSeizeEntry` records. [4](#0-3)  For a borrow-side entry, the pool converts the entire scaled debt position to asset value, passes it to `apply_bad_debt_to_supply_index`, and burns the scaled debt. [5](#0-4) 

`apply_bad_debt_to_supply_index` caps the loss at `cache.supplied() * cache.supply_index()`. [6](#0-5)  If the bad debt consumes all supplier value, `remaining` is zero, so `reduction_factor` and the computed `new_supply_index` are zero. [7](#0-6)  The subsequent `max(SUPPLY_INDEX_FLOOR_RAW)` resurrects the wiped index, while no corresponding cleanup reduces the scaled supply shares held by other suppliers. [8](#0-7) 

This is a storage-level analogue of a dangling pointer: the suppliers’ scaled-share “handles” remain after their backing value has been fully socialized, but the floor makes later dereference through withdrawal produce value again. The controller’s normal `withdraw` path submits the still-stored scaled position to the pool, and the pool pays the resulting amount from current cash. [9](#0-8) [10](#0-9) 

### Impact Explanation
A wiped supplier can steal funds from the next depositor in the same market. The residual claim is bounded by `SUPPLY_INDEX_FLOOR_RAW / RAY` times the pre-wipeout supplied value, so large wiped markets leave a correspondingly large phantom claim. [3](#0-2) 

For example, wiping out a market with `1,000` units of supplied value leaves scaled supply that still unscales to `1` unit. If a later depositor supplies `1` unit, the wiped supplier can withdraw that unit even though the correct post-socialization claim is zero. This directly transfers the fresh depositor’s principal to the holder of the stale shares. [11](#0-10) 

### Likelihood Explanation
The trigger requires socialized borrow debt to equal or exceed the market’s total supplied claim, most naturally a fully lent market whose debt becomes bad debt after collateral loss or liquidation leaves only dust. `clean_bad_debt` is callable by any authorized address once the dust-gated insolvency condition is satisfied. [12](#0-11) 

After cleanup, the market remains usable: a fresh supply mints shares against the floor index and credits real cash, while the old scaled positions were never removed. [13](#0-12)  The attacker only needs to have held supply shares before the wipeout and then call `withdraw`; no privileged role or contract upgrade is required. [11](#0-10) 

### Recommendation
Do not clamp a complete bad-debt write-down to a nonzero index. When `capped == total_supplied_value`, record a zero-value generation for all pre-existing shares or reset the market with an explicit new index generation, so old scaled shares cannot later unscale into assets. Fresh deposits must then mint against a new generation or a safe reset index rather than the floor. [1](#0-0) 

Add an end-to-end test covering full bad-debt socialization, a fresh supply, and withdrawal by a pre-wipeout supplier. The expected result is that the old supplier receives zero and all fresh cash remains claimable by the new supplier. [2](#0-1) 

### Proof of Concept
1. A market has total scaled supply `S = 1,000 * RAY`, `supply_index = RAY`, cash fully borrowed, and a debt position whose value is `1,000` asset units.
2. The borrower’s collateral becomes dust-level and insolvent, then an unprivileged caller invokes `Controller::clean_bad_debt(caller, account_id)`. The controller sends the borrow position as a `PoolSeizeEntry`. [4](#0-3) 
3. The pool computes `bad_debt = 1,000` and `total_supplied_value = 1,000`, so `remaining = 0` and the computed index is zero. [14](#0-13) 
4. The floor changes the index to `RAY / 1,000`; the old `S` shares therefore still represent `S * RAY/1,000 = 1` asset unit. [8](#0-7) 
5. A victim supplies `1` unit to the still-active market, giving the pool real cash. [15](#0-14) 
6. The pre-wipeout supplier calls `withdraw` for their full stored position. The pool pays out the residual `1` unit, draining the victim’s deposit even though socialization should have reduced the old claim to zero. [16](#0-15)

pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));

/// Authorizes permissionless dust-gated cleanup outside flash loans.
pub(crate) fn process_clean_bad_debt(env: &Env, caller: &Address, account_id: u64) {
    caller.require_auth();
    validation::require_not_flash_loaning(env);
    clean_bad_debt_standalone(env, account_id);
}

/// Admission condition for bad-debt socialization.
#[derive(Clone, Copy, PartialEq)]
enum BadDebtGate {
    /// Permissionless: insolvent *and* collateral at or below the dust threshold.
    DustCapped,
    /// Owner-only: insolvent alone, with no cap on the collateral left behind.
    InsolventOnly,
}

/// Requires open debt and the selected insolvency gate, then cleans up the account.
fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    bad_debt::execute_bad_debt_cleanup(env, &mut cache, account_id, &account, &totals);
}
