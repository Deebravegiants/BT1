### Title
Stale-rate reward accounting in `update_cost_per_block` lets governance rate changes retroactively re-price unclaimed consensus-relay blocks - ([File: modules/pallets/consensus-incentives/src/lib.rs])

### Summary
`pallet-consensus-incentives` rewards relayers for delivering ISMP `ConsensusMessage`s based on how many state-machine blocks have advanced since the last reward, multiplied by a configurable `cost_per_block`. When `cost_per_block` is updated, the pallet never settles/checkpoints the reward owed for the span of blocks that already accrued under the *previous* rate. The next relayer to submit a `ConsensusMessage` has the *entire* outstanding block span (including blocks that elapsed before the rate change) priced at the *new* rate, exactly mirroring the reported bug class where a reward-config update is applied to unclaimed rewards instead of only to future accrual.

### Finding Description
`update_cost_per_block` simply overwrites the stored rate with no settlement step: [1](#0-0) 

The reward calculation reads the *current* `StateMachinesCostPerBlock` value and multiplies it by the full block span since `LastRewardedHeight` (or `previous_commitment_height` as a fallback baseline): [2](#0-1) 

`LastRewardedHeight` (the watermark used as `baseline`) is only advanced inside `process_message`, which runs as part of `FeeHandler::on_executed`, itself invoked by `pallet-ismp`'s unsigned `ConsensusMessage` handling pipeline — i.e., triggerable by any unprivileged relayer submitting a valid consensus proof: [3](#0-2) [4](#0-3) 

Because the watermark is only updated when a reward is successfully paid, blocks that advance without a corresponding successful reward payout (e.g., prior `process_message` calls that failed signature verification, or simply a gap between relayer submissions) remain "unclaimed" against the old rate. If governance calls `update_cost_per_block` while such an unclaimed span exists, the pallet does not checkpoint/pay out the span at the old rate first — it just swaps the rate. The very next successful `ConsensusMessage` then computes `reward = (latest_height - baseline) * new_cost_per_block`, applying the new rate across a span that partially or fully occurred under the old rate. This is structurally identical to the reported Sui `update_reward_config` bug, where `reward_per_share` must be settled against the old `reward_per_day` before the new configuration takes effect.

### Impact Explanation
If `cost_per_block` is raised, any outstanding unrewarded block span is retroactively priced at the higher rate, causing the treasury (`T::TreasuryAccount`) to pay out more than was budgeted for blocks that occurred under the lower rate — an unbudgeted/over-mint style drain of treasury funds via the reward-accounting path (`T::Currency::transfer` from treasury to relayer, plus a matching `ReputationAsset` mint). If lowered, relayers are underpaid for work already performed under the higher rate. Either direction is a concrete relayer-reward-accounting miscalculation reachable purely by submitting ordinary relay traffic (a `ConsensusMessage`), not requiring any privileged action by the relayer — only the routine governance action of updating the incentive rate, which is an expected, non-malicious operational parameter change. This falls squarely within the allowed "relayer fee and reward accounting" analog category.

### Likelihood Explanation
Rate changes to `StateMachinesCostPerBlock` are an expected, routine governance operation (adjusting incentives for changing infra/gas costs), and unclaimed spans naturally accumulate whenever `process_message` fails (e.g., a bad/expired signature) or whenever there is any delay between consecutive consensus-relay submissions for a given state machine. Any relayer submitting the next valid `ConsensusMessage` after a rate change automatically triggers the mispriced payout — no attacker coordination or malicious governance is required, only an ordinary configuration update landing while relay traffic is in flight.

### Recommendation
Before mutating `StateMachinesCostPerBlock` in `update_cost_per_block` (and `remove_incentives`), settle the currently accrued span at the *old* rate: compute the reward owed between `LastRewardedHeight`/`previous_commitment_height` and the state machine's current `latest_commitment_height` using the existing rate, pay it out (or explicitly checkpoint `LastRewardedHeight` to the current height so no span carries across the rate boundary), and only then apply the new `cost_per_block`. This mirrors the audit's remediation of invoking a "self-update" (settlement) before writing the new `reward_config`.

### Proof of Concept
1. Governance calls `update_cost_per_block(state_machine_id, cost_per_block = R1)`.
2. A relayer's `ConsensusMessage` for `state_machine_id` fails signature verification inside `on_executed` (or simply no relayer submits for a while), so `process_message`/`calculate_reward` never runs and `LastRewardedHeight` is not advanced, even though the underlying state machine height has already advanced to `H2` via `pallet-ismp`'s normal consensus-client update path.
3. Governance calls `update_cost_per_block(state_machine_id, cost_per_block = R2)` with `R2 >> R1`, with no settlement of the outstanding `(H2 - baseline)` span at `R1`.
4. A relayer then submits a valid `ConsensusMessage` that advances the height further to `H3`. `on_executed` → `process_message` → `calculate_reward` computes `reward = (H3 - baseline) * R2`, paying the relayer (and minting matching reputation tokens) for the entire `H2 - baseline` block span at the new higher rate `R2` instead of the old rate `R1` that was in effect when those blocks were actually delivered, draining excess funds from `T::TreasuryAccount`.

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}

impl<T: Config> FeeHandler for Pallet<T>
where
	<T as frame_system::Config>::AccountId: From<[u8; 32]>,
{
	fn on_executed(
		messages: Vec<MessageWithWeight>,
		events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});

		if let Some(relayer_account) = maybe_relayer_account {
			// When a batch contains multiple `StateMachineUpdated` events for the
			// same `state_machine_id` (sequential consensus updates for the same
			// chain), `calculate_reward` reads the same persisted
			// `(latest_commitment_height, previous_commitment_height)` pair on
			// every iteration and pays the same block-span reward N times.
			// Collapse the per-state-machine event stream to the single highest
			// `latest_height` so each state machine receives one reward per
			// batch, sized by the actual span of its commitment advance.
			let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
			for event in events {
				if let IsmpEvent::StateMachineUpdated(update) = event {
					highest_per_state_machine
						.entry(update.state_machine_id)
						.and_modify(|h| {
							if update.latest_height > *h {
								*h = update.latest_height;
							}
						})
						.or_insert(update.latest_height);
				}
			}

			for (state_machine_id, latest_height) in highest_per_state_machine {
				let state_machine_height =
					StateMachineHeight { id: state_machine_id.clone(), height: latest_height };

				let _ = Self::process_message(
					state_machine_height,
					state_machine_id,
					relayer_account.clone().into(),
				);
			}
		}

		// Return with actual weight information
		// We use Pays::No to indicate that someone (the message sender) doesn't pay for this
		// operation, though we're using this mechanism to reward relayers rather than charge fees
		Ok(PostDispatchInfo { actual_weight: None, pays_fee: Pays::No })
	}
