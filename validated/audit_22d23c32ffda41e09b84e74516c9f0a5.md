**Rationale:**

The `dependent_edges`/`cross_shard_dependencies` mechanism in `cross_shard_client.rs` is part of Aptos's sharded block executor, a codepath used only for experimental/benchmark sharded execution (invoked via `V::execute_block_sharded` in `execution/executor/src/workflow/do_get_execution_output.rs`, exercised by `aptos-move/aptos-vm/tests/sharded_block_executor.rs`, `execution/executor-service`, and `aptos-move/aptos-transaction-benchmarks`), not by the standard mainnet block execution path (`AptosVMBlockExecutor::execute_block`, which uses Block-STM's MVHashMap-based conflict detection with real read/write sets rather than static hints). [1](#0-0) [2](#0-1) 

More decisively, the `dependent_edges` are derived from `AnalyzedTransaction::read_hints`/`write_hints`, which are computed via `get_read_write_hints`. That function only implements static analysis for `coin::transfer`, `aptos_account::transfer`, and `create_account`; any other payload — including multisig transactions — falls into `_ => todo!("Only entry function transactions are supported for now")`, which panics rather than silently producing an incorrect or omitted dependent edge. [3](#0-2) 

So a multisig approve/execute pair spanning two shards as described in the proof idea cannot currently be partitioned through this analyzed-transaction/hint-based dependency mechanism at all — it would hit `todo!()` and abort, not produce a stale cross-shard view. Since this sharded/partitioner path is not part of Aptos mainnet's production consensus execution and multisig transactions aren't supported by its static read/write-hint analysis, this doesn't cross a real custody boundary reachable by unprivileged mainnet transactions.

impl AnalyzedTransactionProvider for Transaction {
    fn get_read_write_hints(&self) -> (Vec<StorageLocation>, Vec<StorageLocation>) {
        let process_entry_function = |func: &EntryFunction,
                                      sender_address: AccountAddress|
         -> (Vec<StorageLocation>, Vec<StorageLocation>) {
            match (
                *func.module().address(),
                func.module().name().as_str(),
                func.function().as_str(),
            ) {
                (AccountAddress::ONE, "coin", "transfer") => {
                    let receiver_address = bcs::from_bytes(&func.args()[0]).unwrap();
                    rw_set_for_coin_transfer(sender_address, receiver_address, true)
                },
                (AccountAddress::ONE, "aptos_account", "transfer") => {
                    let receiver_address = bcs::from_bytes(&func.args()[0]).unwrap();
                    rw_set_for_coin_transfer(sender_address, receiver_address, false)
                },
                (AccountAddress::ONE, "aptos_account", "create_account") => {
                    let receiver_address = bcs::from_bytes(&func.args()[0]).unwrap();
                    rw_set_for_create_account(sender_address, receiver_address)
                },
                _ => todo!(
                    "Only coin transfer and create account transactions are supported for now"
                ),
            }
        };
        match self {
            Transaction::UserTransaction(signed_txn) => match signed_txn.payload().executable_ref()
            {
                Ok(TransactionExecutableRef::EntryFunction(func))
                    if !signed_txn.payload().is_multisig() =>
                {
                    process_entry_function(func, signed_txn.sender())
                },
                _ => todo!("Only entry function transactions are supported for now"),
            },
            _ => empty_rw_set(),
        }
    }
}
