## Title
Missing shop-domain validation in `Oauth.begin_auth` enables forced-OAuth-completion / session fixation - (`lib/shopify_api/auth/oauth.rb`)

### Summary
`ShopifyAPI::Auth::Oauth.begin_auth` builds the OAuth authorization redirect URL directly from the caller-supplied `shop:` argument without validating that it is a genuine `*.myshopify.com` (or other trusted Shopify) domain. Every other credential-bearing flow in this gem funnels the `shop` value through `Utils::ShopValidator.sanitize!` before using it to build a request host, but `begin_auth` does not.

### Finding Description
`begin_auth` computes the redirect target with an unsanitized shop value: [1](#0-0) 

and the URI itself is built from that raw string: [2](#0-1) 

Compare this with `ClientCredentials.client_credentials`, which explicitly sanitizes the shop before it is ever used to build a request host or to receive credentials: [3](#0-2) 

`Utils::ShopValidator.sanitize!` restricts the host to a small allow-list of trusted Shopify domains (`myshopify.com`, `myshopify.io`, `spin.dev`, `shop.dev`, `shopify.com`): [4](#0-3) [5](#0-4) 

`begin_auth` is documented as taking a raw `shop` string as its primary, developer-supplied input during "step 3 — Begin OAuth", which in the standard OAuth-begin pattern is populated directly from the unauthenticated `?shop=` query parameter sent by the merchant's browser before any HMAC has been produced (an HMAC only exists on the *callback*, not on the initial install hit): [6](#0-5) 

The identity binding that is broken: the `shop` string trusted to construct the authorization-endpoint host in `begin_auth` ≠ the `shop` string that is later cryptographically bound via HMAC in `validate_auth_callback`. `begin_auth` has no way to enforce that equality up front, and unlike `client_credentials` it makes no attempt to.

`validate_auth_callback` returns a `SessionCookie` whose *value* is the `state` nonce the caller previously generated and put both in a cookie sent to the victim's browser and in the query string of the (attacker-redirected) authorization URL: [7](#0-6) 

and the callback only checks that the returned `state` equals the cookie value, not that the browser actually visited Shopify in between: [8](#0-7) 

### Impact Explanation
Because the `state` value is embedded in the query string of `auth_route`, if `auth_route` is redirected to an attacker-controlled host (by supplying a non-Shopify `shop`), the attacker's server receives the victim's `state` value directly. The attacker can complete a *real*, Shopify-signed OAuth grant on their own store (any developer can install the app on a store they control) and then bounce the victim's browser to the app's genuine `redirect_path` with the attacker's own `code`/`hmac`/`shop`, but the victim's original `state`. Since `validate_auth_callback` only compares `state == auth_query.state`, this passes, and the app persists the *attacker's* session (`shop`, `access_token`) as the value written into the victim's browser cookie — a session-fixation / forced-OAuth-completion attack, explicitly listed as a High-impact class in scope. No `api_secret_key`, access token, or privileged access is required by the attacker.

### Likelihood Explanation
Exploitability depends entirely on whether the host application passes the untrusted `?shop=` install parameter straight into `begin_auth`, which is exactly the documented step-3 usage shown in `docs/usage/oauth.md`. The gem provides `Utils::ShopValidator` for this exact purpose and already applies it in the sibling `client_credentials` flow, but not in `begin_auth`, making the omission a concrete, in-gem gap rather than a host-application misuse of an undocumented API.

### Recommendation
Call `Utils::ShopValidator.sanitize!(shop)` (or equivalent) inside `Oauth.begin_auth` before it is used to build `auth_base_uri`, mirroring the behavior already present in `ClientCredentials.client_credentials`, so a non-Shopify `shop` value raises `Errors::InvalidShopError` instead of producing a redirect URL to an arbitrary host.

### Proof of Concept
1. App exposes `/login?shop=<value>` which calls `ShopifyAPI::Auth::Oauth.begin_auth(shop: params[:shop], redirect_path: "/callback")` (per documented usage).
2. Attacker sends victim a link `/login?shop=evil.example.com`.
3. `begin_auth` returns `auth_route = "https://evil.example.com/admin/oauth/authorize?client_id=...&scope=...&redirect_uri=https://app.example/callback&state=<STATE>&..."` and a cookie `state=<STATE>` is set on the victim's browser.
4. Victim's browser is redirected to `evil.example.com`, leaking `<STATE>`, `client_id`, `scope`, `redirect_uri` to the attacker.
5. Attacker completes a real OAuth grant on their own Shopify dev store, obtaining a Shopify-issued, correctly-HMAC'd `code`.
6. Attacker's page 302's the victim's browser to `https://app.example/callback?code=<attacker_code>&hmac=<valid_hmac>&shop=<attacker-shop>.myshopify.com&state=<STATE>&timestamp=...&host=...`.
7. `validate_auth_callback` accepts it (`state == auth_query.state`, HMAC valid for attacker's own genuine query), and the victim's browser is left holding a session cookie referencing the attacker's shop/session — session fixation achieved. [9](#0-8)

        def begin_auth(shop:, redirect_path:, is_online: true, scope_override: nil)
          scope = if scope_override.nil?
            ShopifyAPI::Context.scope
          elsif scope_override.is_a?(ShopifyAPI::Auth::AuthScopes)
            scope_override
          else
            ShopifyAPI::Auth::AuthScopes.new(scope_override)
          end

          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = SecureRandom.alphanumeric(NONCE_LENGTH)

          cookie = SessionCookie.new(value: state, expires: Time.now + 60)

          query = {
            client_id: ShopifyAPI::Context.api_key,
            scope: scope.to_s,
            redirect_uri: "#{ShopifyAPI::Context.host}#{redirect_path}",
            state: state,
            "grant_options[]": is_online ? "per-user" : "",
          }

          query_string = URI.encode_www_form(query)
          auth_route = auth_base_uri(shop) + "/oauth/authorize?#{query_string}"

          { auth_route: auth_route, cookie: cookie }
        end

        def validate_auth_callback(cookies:, auth_query:)
          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::InvalidOauthError, "Invalid OAuth callback." unless Utils::HmacValidator.validate(auth_query)
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = cookies[SessionCookie::SESSION_COOKIE_NAME]
          raise Errors::NoSessionCookieError unless state

          raise Errors::InvalidOauthError,
            "Invalid state in OAuth callback." unless state == auth_query.state

          null_session = Auth::Session.new(shop: auth_query.shop)
          body = {
            client_id: Context.api_key,
            client_secret: Context.api_secret_key,
            code: auth_query.code,
            expiring: Context.expiring_offline_access_tokens ? 1 : 0, # Only applicable for offline tokens
          }

          client = Clients::HttpClient.new(session: null_session, base_path: "/admin/oauth")
          response = begin
            client.request(
              Clients::HttpRequest.new(
                http_method: :post,
                path: "access_token",
                body: body,
                body_type: "application/json",
              ),
            )
          rescue ShopifyAPI::Errors::HttpResponseError => e
            raise Errors::RequestAccessTokenError,
              "Cannot complete OAuth process. Received a #{e.code} error while requesting access token."
          end

          session_params = T.cast(response.body, T::Hash[String, T.untyped]).to_h
          session = Session.from(shop: auth_query.shop,
            access_token_response: Oauth::AccessTokenResponse.from_hash(session_params))

          cookie = if Context.embedded?
            SessionCookie.new(
              value: "",
              expires: Time.now,
            )
          else
            SessionCookie.new(
              value: session.id,
              expires: session.expires ? session.expires : nil,
            )
          end

          { session: session, cookie: cookie }

        sig { params(shop: String).returns(String) }
        def auth_base_uri(shop)
          return "https://#{shop}/admin" unless defined?(DevServer) && shop.include?(".my.shop.dev")

          # For first-party apps in development only, we leverage DevServer to build the admin base URI
          admin_web = T.unsafe(Object.const_get("DevServer")) # rubocop:disable Sorbet/ConstantsFromStrings
            .new("admin-web")
          admin_host = admin_web.host!(nonstandard_host_prefix: "admin")
          shop_name = shop.split(".").first

          "https://#{admin_host}/store/#{shop_name}"
        end
