Audit Report

## Title
Bridge Outgoing Token Disclosed in Plaintext to View-Role Users via GraphQL - (File: core/web/resolver/query.go)

## Summary
The `Bridge`/`Bridges` GraphQL resolvers only call `authenticateUser`, the lowest-privilege gate, and return `BridgeType.OutgoingToken` in plaintext via `BridgeResolver.OutgoingToken()`. However, this same plaintext exposure is present identically in the pre-existing REST API (`core/web/bridge_types_controller.go` `Show`/`Index` via `presenters.NewBridgeResource`, which unconditionally sets `OutgoingToken: b.OutgoingToken`), indicating this is a long-standing, consistent design decision across both API surfaces rather than a GraphQL-specific regression or bypass.

## Finding Description
`Resolver.Bridge`/`Resolver.Bridges` in `core/web/resolver/query.go` call `authenticateUser(ctx)` [1](#0-0) , which only verifies a valid session exists, granting inherent "view" access [2](#0-1) . `BridgeResolver.OutgoingToken()` returns the raw token [3](#0-2) , and `BridgeType.OutgoingToken` is stored as a plain string column, unlike `IncomingTokenHash` which is hashed [4](#0-3) .

Critically, this is not unique to GraphQL: the REST `BridgeTypesController.Show` and `Index` handlers build `presenters.BridgeResource` via `NewBridgeResource`, which unconditionally copies `OutgoingToken: b.OutgoingToken` into the JSON response with no redaction or role check beyond standard route authentication [5](#0-4) [6](#0-5) . This demonstrates that plaintext exposure of `OutgoingToken` to any authenticated node user (regardless of role) is the existing, symmetric behavior of the Chainlink node's admin API as a whole, not an inconsistency introduced or unique to the GraphQL layer. The claim's contrast with `authenticateUserCanEdit`/`authenticateUserIsAdmin` used elsewhere does not establish that bridge-token visibility was ever intended to be edit/admin-gated — the REST equivalent, which predates the GraphQL API and view-role RBAC tiering, exposes the identical field to the identical class of authenticated users.

## Impact Explanation
While the token is technically a secret used to authenticate outbound calls to external adapters, and its disclosure to a "view" role user is undesirable from a strict least-privilege standpoint, the finding does not represent a broken security boundary specific to GraphQL or a role-bypass vulnerability — the REST API has always returned this same field to any authenticated user with no additional role check. This is existing, unremediated, cross-API-consistent behavior rather than a newly introduced authorization flaw exploitable via a novel bypass path.

## Likelihood Explanation
Exploitability requires only a valid authenticated session (any role), which is a real precondition met trivially by any provisioned user, including "view" role. However, because the identical exposure already exists via the REST API and is consistent behavior across the whole `bridges` API surface (not a GraphQL-specific inconsistency), this does not constitute a distinct, newly exploitable vulnerability introduced by the GraphQL resolvers alone.

## Recommendation
If tightening access to `OutgoingToken` is desired, it should be addressed uniformly across both the REST (`presenters.NewBridgeResource`) and GraphQL (`BridgeResolver.OutgoingToken`) code paths, e.g., by omitting or redacting `OutgoingToken` for `UserRoleView` sessions consistently, rather than treating this as a GraphQL-only role-check gap.

## Proof of Concept
N/A — see Finding Description; the same behavior is reproducible via `GET /v2/bridge_types/:BridgeName` on the REST API in addition to the GraphQL `bridge`/`bridges` queries cited in the original report.

// Bridge retrieves a bridges by name.
func (r *Resolver) Bridge(ctx context.Context, args struct{ ID graphql.ID }) (*BridgePayloadResolver, error) {
	if err := authenticateUser(ctx); err != nil {
		return nil, err
	}

	name, err := bridges.ParseBridgeName(string(args.ID))
	if err != nil {
		return nil, err
	}

	bridge, err := r.App.BridgeORM().FindBridge(ctx, name)
	if err != nil {
		if errors.Is(err, sql.ErrNoRows) {
			return NewBridgePayload(bridge, err), nil
		}

		return nil, err
	}

	return NewBridgePayload(bridge, nil), nil
}

// Show returns the details of a specific Bridge.
func (btc *BridgeTypesController) Show(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	bt, err := btc.App.BridgeORM().FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}
