## Title
Stack exhaustion via unbounded recursive `RuntimeCall` decoding in `pallet-hyper-fungible-token`'s cross-chain calldata execution - (File: `modules/pallets/hyper-fungible-token/src/module.rs`)

### Summary
The `on_accept` handler of `pallet-hyper-fungible-token` decodes an attacker-supplied, SCALE-encoded `RuntimeCall` using the plain, depth-unbounded `Decode::decode` API, reachable from any incoming cross-chain token transfer that carries optional calldata. This is the same bug class as CVE-2015-7978 (unbounded recursive traversal of attacker-controlled structure causing stack exhaustion): a deeply self-nested call value (e.g. `Sudo::sudo(Box<RuntimeCall>)` or `Utility::batch` chains) drives the codec's recursive decoder past the stack limit, aborting the node process. The codebase already recognizes and fixes this exact bug class elsewhere (`pallet-call-decompressor`), which explicitly bounds decode depth via `decode_all_with_depth_limit` and carries a regression test (`decompress_stack_exhaustion_poc`) proving unbounded decoding previously caused stack exhaustion — but the equivalent guard was never applied to the HFT calldata path.

### Finding Description
`pallet_hyper_fungible_token::module::on_accept` processes an incoming ISMP `PostRequest` from a registered peer EVM/Substrate contract, and when `message.data` is non-empty, decodes it as `SubstrateCalldata`: [1](#0-0) 

The `runtime_call` field of `SubstrateCalldata` is itself an opaque `Vec<u8>` supplied entirely by the sender, and it is decoded with unbounded recursion: [2](#0-1) 

`T::RuntimeCall::decode` uses `parity-scale-codec`'s standard `Decode::decode`, which — unlike `decode_all_with_depth_limit` — has no configured recursion cap in this call site. Because `RuntimeCall` variants such as `Sudo::sudo { call: Box<RuntimeCall> }` or `Utility::batch { calls: Vec<RuntimeCall> }` are recursive/self-referential types, an attacker can craft a payload consisting of thousands of nested wrapper calls. Decoding such a payload recurses once per nesting level, exhausting the node's call stack and crashing/panicking the process — a remote, unauthenticated (from the perspective of the destination chain's stack, since only the sending EVM contract must be a registered peer, which is standard permissionless bridging) denial of service.

The project has already fixed the identical bug class in a sibling pallet. `pallet-call-decompressor::decode_and_execute` and its `validate_unsigned` path use `decode_all_with_depth_limit(MAX_EXTRINSIC_DECODE_DEPTH_LIMIT, ...)`: [3](#0-2) 

with a comment and regression test explicitly documenting a prior stack-exhaustion PoC using 1000 nested `Sudo::sudo` calls, now caught and returned as a clean `ErrorDecodingCall`: [4](#0-3) 

This confirms both (a) that the codebase's default `Decode::decode` has no built-in depth protection for `RuntimeCall`, and (b) that this specific class was already treated as a security issue requiring an explicit fix — a fix that was never propagated to `pallet-hyper-fungible-token`'s `on_accept` calldata-execution path, which is exposed to the same attacker-controlled recursive input.

### Impact Explanation
A successful stack-exhaustion crash in `on_accept` (invoked during normal ISMP message delivery/relaying) halts block production/state transition for the affected node — a runtime panic/abort while processing a dispatched message is a denial-of-service on message delivery for that chain, matching the "route unable to deliver messages" acceptance criterion. Because `on_accept` runs during block execution (post request handling), a single relayed malicious message can potentially crash validating/collating nodes processing that block, which is a High-severity availability impact for a live bridge deployment.

### Likelihood Explanation
Exploitation requires only:
1. A registered EVM (or Substrate) peer contract for the destination HFT pallet (a normal, permissionless bridging configuration — anyone can call `send`/the contract's transfer function with arbitrary `data`).
2. Encoding a `SubstrateCalldata.runtime_call` as a deeply nested recursive `RuntimeCall` value (trivial to construct, as demonstrated by the existing `decompress_stack_exhaustion_poc` test using `Sudo::sudo` nesting).
3. Triggering delivery of the crafted `PostRequest`, which any relayer can do since HFT's calldata field is attacker-controlled end-to-end and only the source contract address (not payload content) is authenticated.

No privileged role or governance action is needed, making this reachable by any unprivileged sender who can send tokens cross-chain with calldata.

### Recommendation
Replace `T::RuntimeCall::decode(&mut &*substrate_data.runtime_call)` in `on_accept` with a depth-limited decode, mirroring `pallet-call-decompressor`'s fix, e.g. `T::RuntimeCall::decode_all_with_depth_limit(MAX_DEPTH, &mut &*substrate_data.runtime_call)`, choosing `MAX_DEPTH` to accommodate legitimate calls while rejecting adversarial nesting. Add a regression test analogous to `decompress_stack_exhaustion_poc` for the HFT `on_accept` calldata path.

### Proof of Concept
Adapt the existing `decompress_stack_exhaustion_poc` pattern to the HFT flow:
1. Build a `RuntimeCall` value nested ~1000 levels deep via repeated `RuntimeCall::Sudo(pallet_sudo::Call::sudo { call: Box::new(previous) })`.
2. SCALE-encode it and wrap it as `SubstrateCalldata { signature: None, runtime_call: <encoded nested call> }`, then encode that as `message.data`.
3. Construct an ABI-encoded `Message { from, to, amount, data }` and wrap it in a `PostRequest` with `source`/`from` matching a registered `ContractToAsset` entry.
4. Call `HyperFungibleToken::on_accept(post)` as in `modules/pallets/testsuite/src/tests/pallet_hyper_fungible_token.rs::should_receive_asset_with_calldata` — instead of a valid `Balances::transfer_allow_death` call, use the deeply nested call.
5. Observe that `T::RuntimeCall::decode` at `module.rs:189` recurses without a depth bound and exhausts the stack, in contrast to the bounded, cleanly-erroring behavior verified for `pallet-call-decompressor`.

#[test]
fn decompress_stack_exhaustion_poc() {
	let mut ext = new_test_ext();
	ext.execute_with(|| {
		use crate::runtime::RuntimeCall;
		use codec::Encode;

		let inner_call = RuntimeCall::System(frame_system::Call::remark { remark: Vec::new() });

		let mut nested_calls =
			RuntimeCall::Sudo(pallet_sudo::Call::sudo { call: Box::new(inner_call) });

		for _ in 1..1000 {
			nested_calls =
				RuntimeCall::Sudo(pallet_sudo::Call::sudo { call: Box::new(nested_calls) });
		}

		let encoded = nested_calls.encode();
		let mut buffer = vec![0u8; 1000000];
		let compressed = zstd_safe::compress(&mut buffer[..], encoded.as_slice(), 3).unwrap();
		let final_compressed_call = buffer[..compressed].to_vec();

		let res = pallet_call_decompressor::Pallet::<Test>::decompress_call(
			RuntimeOrigin::none(),
			final_compressed_call.to_vec(),
			encoded.len() as u32,
		)
		.err()
		.unwrap();

		assert_eq!(
			res,
			DispatchError::Module(ModuleError {
				index: 10,
				error: [3, 0, 0, 0],
				message: Some("ErrorDecodingCall")
			})
		);
	});
}
