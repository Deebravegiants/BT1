### Title
Predispatch Swap Leftovers in `IntentGatewayV2.placeOrder` Are Never Swept, Permanently Freezing User Funds - (File: `evm/src/apps/IntentGatewayV2.sol`)

### Summary
`IntentGatewayV2.placeOrder()` lets a user attach arbitrary swap calldata (`order.predispatch.call`) that is executed by the `CallDispatcher` before the resulting tokens are escrowed. After execution, the gateway only recovers balances for the tokens explicitly listed in `order.inputs` — any other token balance left on the `CallDispatcher` (e.g. an intermediate hop of a multi-step swap, or output routed to a token not declared as an input) is never checked, never swept, and has no recovery path, permanently freezing those funds. This mirrors the JOJO report's root cause: swap calldata is user/frontend supplied, and the contract only checks the balance of the asset it expects, not for arbitrary leftovers.

### Finding Description
In `placeOrder`, when `order.predispatch.call.length > 0`, the flow is:
1. Predispatch assets are sent to the `dispatcher` (a `CallDispatcher` instance) and `ICallDispatcher(dispatcher).dispatch(order.predispatch.call)` executes user-supplied calldata (e.g., a Uniswap swap) [1](#0-0) .
2. The gateway then builds sweep calls **only for the tokens listed in `order.inputs`**, transferring back whatever balance of those specific tokens sits on the dispatcher [2](#0-1) .
3. It measures the delta and treats any excess of the *declared input tokens* as dust via `DustCollected`, but never inspects the dispatcher for balances of tokens **not present in `order.inputs`** [3](#0-2) .

By contrast, the postdispatch/fill-side path `_execute()` explicitly iterates over every token in `order.output.assets` after dispatch and sweeps any residual balance back to the gateway, emitting `DustCollected` for each [4](#0-3) . The predispatch path in `placeOrder` has no equivalent generic sweep — it is hardcoded to only the input-token set.

`CallDispatcher` itself is a bare forwarding contract with no owner, no rescue function, and only a generic `dispatch()` entrypoint gated by "target must be a contract" [5](#0-4) , so any token balance it accumulates outside of a `placeOrder`/`_execute` sweep call is unrecoverable through any protocol-provided function.

Because `predispatch.call` is arbitrary, attacker- or frontend-supplied calldata (analogous to "bad calldata sent to third-party swap traders" in the source report), a swap that:
- routes through an intermediate token before reaching the declared input token, or
- partially fails/reverts mid-multicall leaving one leg's output stuck, or
- simply produces a different token than what's declared as `order.inputs` due to a bug or malformed order

...leaves that balance permanently stuck in the `CallDispatcher`, with no code path to ever recover it.

### Impact Explanation
Funds sent by the user into predispatch calldata that end up as any token other than the declared `order.inputs` set are permanently frozen — no owner or governance sweep exists for `CallDispatcher`, and the gateway's own sweep is scoped strictly to `order.inputs`. This is a concrete permanent loss/freezing of user funds reachable from a single, unprivileged `placeOrder` transaction, satisfying the "permanent freezing of funds" acceptance criterion.

### Likelihood Explanation
Any user calling `placeOrder` with `predispatch.call` set can trigger this — it does not require a malicious actor; a legitimate multi-hop swap, slippage-driven partial fill, or a frontend bug constructing calldata that doesn't perfectly match `order.inputs` composition is sufficient. Given `IntentGatewayV2Test.sol` already demonstrates realistic swap-based predispatch scenarios exercising this exact code path (`testDustCollectionFromPredispatchSwapWithUniswapV2`), the mechanics are actively used in practice, making accidental (or crafted) leftover-producing calldata plausible.

### Recommendation
After executing `order.predispatch.call`, sweep **all** non-zero token balances left on the `CallDispatcher`, not just the tokens declared in `order.inputs` — mirroring the approach already used in `_execute()` for postdispatch execution. Since the full set of tokens touched by predispatch calldata is not known in advance, consider requiring the caller to declare an exhaustive "sweep list" of tokens potentially touched by the calldata (predispatch assets ∪ inputs ∪ any documented intermediate hops), or add a permissionless/generic sweep function on `CallDispatcher` (or the gateway) that returns residual balances of any specified token back to the gateway/user.

### Proof of Concept
1. User calls `placeOrder` with `predispatch.assets = [ETH: 1e18]` and `predispatch.call` encoding: swap ETH → Token A → Token B via a two-hop router path, intending `order.inputs = [TokenB: X]`.
2. Due to slippage settings or a malformed/partial multicall, the first hop (ETH → Token A) completes and lands Token A on the `CallDispatcher`, but the second hop (Token A → Token B) reverts or is skipped, or the calldata is crafted to swap only part of the ETH.
3. `placeOrder`'s sweep logic (`evm/src/apps/IntentGatewayV2.sol:260-289`) only builds a transfer call for `TokenB` (the declared input) — it never inspects or transfers Token A's balance sitting on the `CallDispatcher`.
4. Token A remains on the `CallDispatcher` indefinitely; there is no function anywhere in `CallDispatcher.sol` or `IntentGatewayV2`/`IntentsBase` that can move it out, permanently locking those funds.

    /**
     * @dev Executes arbitrary calldata attached to an order's output via the CallDispatcher.
     * After dispatching the calls, any residual token balances left on the dispatcher
     * are swept back to this contract and accounted for as protocol dust.
     *
     * This enables composable order fulfillment — solvers can route through DEXes,
     * lending protocols, or other DeFi primitives as part of filling an order.
     *
     * @param order The order containing the output calldata to execute.
     * @param outputsLen The number of output assets to sweep after execution.
     */
    function _execute(Order calldata order, uint256 outputsLen) internal {
        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            } else {
                uint256 balance = IERC20(token).balanceOf(dispatcher);
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            }

            unchecked {
                ++i;
            }
        }

        if (sweepCount > 0) {
            Call[] memory finalCalls = new Call[](sweepCount);
            for (uint256 i; i < sweepCount;) {
                finalCalls[i] = sweepCalls[i];
                unchecked {
                    ++i;
                }
            }
            ICallDispatcher(dispatcher).dispatch(abi.encode(finalCalls));
        }
    }

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
