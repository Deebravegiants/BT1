## Confirmed: Stale confirmations from a revoked key are not purged on `DeleteKey`

The `DeleteKey` arm in `execute_request` only removes **requests originated by** the deleted key; it never scans the `confirmations` map for entries where that key merely **confirmed** someone else's request. [1](#0-0) 

### Root cause

- The filter `self.requests.iter().filter(|(_k, r)| r.signer_pk == pk)` only matches requests where `r.signer_pk` (the *originator*) equals the deleted key. [2](#0-1) 
- Confirmations added by `pk` on requests it did **not** originate live in a separate structure, `self.confirmations: UnorderedMap<RequestId, HashSet<PublicKey>>`, populated in `confirm()` via `confirmations.insert(env::signer_account_pk())`. [3](#0-2) 
- There is no code path in the `DeleteKey` branch (or anywhere else) that iterates `self.confirmations` values and strips a revoked `PublicKey` from HashSets belonging to *other* requests. Only `remove_request`/`delete_request`/successful `confirm` clear a request's confirmations wholesale, and only for the request being removed, not for stray references to a deleted key on other still-pending requests. [4](#0-3) 

### Exploit / reproduction

1. `pk_A` calls `add_request` for request `R` (e.g. a `Transfer`) with threshold `num_confirmations = 3`. `R`'s confirmations set starts empty.
2. `pk_B` calls `confirm(R)` — this is below threshold, so it just adds `pk_B` to `confirmations[R]` and returns; `R` stays pending.
3. Later, `pk_B`'s key is revoked via a separate multisig-approved `add_request_and_confirm` with a `DeleteKey { public_key: pk_B }` action. This action removes only requests where `signer_pk == pk_B` (i.e., requests *pk_B* created) — `R` was created by `pk_A`, so it is untouched, and `confirmations[R]` still contains `pk_B`.
4. `get_confirmations(R)` now still returns `pk_B`, even though `pk_B` has just had `promise.delete_key(pk)` executed against it and can no longer sign anything.
5. Two more live keys then confirm `R`. Because `confirmations[R].len() + 1 >= num_confirmations` is evaluated against a set that already illegitimately contains the revoked `pk_B`, `R` executes with effectively only 2 currently-valid signers instead of the intended 3-of-n quorum.

This breaks the invariant that `confirmations` for a live request must only contain currently-authorized keys, silently lowering the real quorum requirement below the configured `num_confirmations`.

### Impact

Matches the "High" impact bullet: confirmation-bypass / state-transition bypass in the multisig flow, letting the effective quorum be met with fewer legitimately live signers than configured, i.e., an unauthorized-execution/confirmation-bypass condition in `multisig/src/lib.rs`.

### Recommendation

In the `DeleteKey` arm, in addition to removing requests originated by `pk`, iterate all entries of `self.confirmations` and remove `pk` from every `HashSet`, e.g.:

```rust
let stale_confirmations: Vec<u32> = self.confirmations
    .iter()
    .filter(|(_k, cs)| cs.contains(&pk))
    .map(|(k, _cs)| k)
    .collect();
for request_id in stale_confirmations {
    let mut cs = self.confirmations.get(&request_id).unwrap();
    cs.remove(&pk);
    self.confirmations.insert(&request_id, &cs);
}
```

This ensures no revoked key's confirmation can count toward the k-of-n threshold on requests it did not originate.

        self.assert_valid_request(request_id);
        let mut confirmations = self.confirmations.get(&request_id).unwrap();
        assert!(
            !confirmations.contains(&env::signer_account_pk()),
            "Already confirmed this request with this key"
        );
        if confirmations.len() as u32 + 1 >= self.num_confirmations {
            let request = self.remove_request(request_id);
            /********************************

            ********************************/
            self.execute_request(request)
        } else {
            confirmations.insert(env::signer_account_pk());
            self.confirmations.insert(&request_id, &confirmations);
            PromiseOrValue::Value(true)
        }
    }

    fn remove_request(&mut self, request_id: RequestId) -> MultiSigRequest {
        // remove confirmations for this request
        self.confirmations.remove(&request_id);
        // remove the original request
        let request_with_signer = self
            .requests
            .remove(&request_id)
            .expect("Failed to remove existing element");
        // decrement num_requests for original request signer
        let original_signer_pk = request_with_signer.signer_pk;
        let mut num_requests = self.num_requests_pk.get(&original_signer_pk).unwrap_or(0);
        // safety check for underrun (unlikely since original_signer_pk must have num_requests_pk > 0)
        if num_requests > 0 {
            num_requests = num_requests - 1;
        }
        self.num_requests_pk
            .insert(&original_signer_pk, &num_requests);
        // return request
        request_with_signer.request
    }
