Audit Report

## Title
Missing `return` after failed email-claim extraction in `handleTokenExchange` allows authenticated session creation with unvalidated/empty identity - (File: core/sessions/oidcauth/oidc.go)

## Summary
In `oidcAuthenticator.handleTokenExchange`, the error branch handling failure of the `claims["email"].(string)` type assertion writes an HTTP error response but omits the `return` statement present in every other error branch of the function [1](#0-0) . As a result, execution falls through to role mapping, `oidc_sessions` row insertion, audit logging, and Gin session establishment using an empty-string `email`, and the client ultimately receives `200 {"success": true}` with a valid session cookie despite the identity extraction failure [2](#0-1) .

## Finding Description
`handleTokenExchange` performs OAuth2 code exchange, ID token verification, and claims parsing, with every prior error path (`ShouldBindJSON`, state mismatch, token exchange failure, missing `id_token`, ID token verification failure, claims parsing failure, `ExtractIDClaimValues` failure) correctly writing an error response and returning [3](#0-2) . The email-claim extraction branch breaks this pattern: it logs an error and writes `http.StatusInternalServerError` via `c.String`, but does not `return` [1](#0-0) . Control flow then proceeds unconditionally to `IDClaimsToUserRole`, an `INSERT INTO oidc_sessions` using `strings.ToLower(email)` (empty string when the assertion failed), an audit log call for `AuthLoginSuccessNo2FA`, setting `ginSession.Set(webauth.SessionIDKey, clSession.ID)`, saving the session, and finally `c.JSON(http.StatusOK, ExchangeTokenResponse{Success: true})` [4](#0-3) . Because Gin allows multiple writes with the last one taking effect, the client receives a 200 success response and an authenticated session cookie rather than the intended 500 error, even though the identity (email) was never validated.

## Impact Explanation
This is a genuine node API authentication/identity-integrity bug: a session is created and a Gin session cookie is issued for an unvalidated/empty-string identity, with a role derived from OIDC group claims via `IDClaimsToUserRole`. This maps to the in-scope "node API authentication or role bypass" / "cross-user response corruption" impact category, since a login can succeed (200 + cookie + audit success) despite the code's own logic determining the identity was invalid, and the resulting session could collide with other empty/invalid-email records.

## Likelihood Explanation
Reaching this requires an OIDC ID token where the `email` claim is missing or non-string while the configured RBAC group claim (Admin/Edit/Run/Read) is still present. This is only reachable within the normal, unprivileged `handleSignIn` → provider redirect → `handleTokenExchange` flow, and would occur with a misconfigured/non-compliant configured OIDC provider or a claims payload the attacker can influence at the IdP side, so likelihood depends on the trust/configuration of the deployed OIDC provider rather than a purely remote, provider-independent unprivileged bypass.

## Recommendation
Add `return` after writing the error response in the email-claim extraction failure branch, matching all other error branches in the function:
```go
email, ok := claims["email"].(string)
if !ok {
    oi.lggr.Errorf("Failed to get email from claims. error: %v", err)
    c.String(http.StatusInternalServerError, "Failed to get email from claims")
    return
}
```

## Proof of Concept
1. Configure/point the node at an OIDC provider (or a test double as used in `core/sessions/oidcauth/oidc_test.go`) whose ID token claims omit `email` (or set it to a non-string) while including one of the configured group claims (Admin/Edit/Run/Read).
2. Perform `GET` to the sign-in handler to obtain `state`, then complete the redirect flow and `POST` the resulting `code`/`state` to the token-exchange endpoint (`handleTokenExchange`).
3. Observe the `claims["email"].(string)` assertion fails, `IDClaimsToUserRole` still resolves a role, `INSERT INTO oidc_sessions (... user_email ...)` runs with `user_email=''`, `AuthLoginSuccessNo2FA` is audited, and the response is `200 {"success": true}` with a session cookie set — this can be written as a Go handler/integration test against `oidcAuthenticator.handleTokenExchange` mirroring the existing tests in `core/sessions/oidcauth/oidc_test.go` [5](#0-4) .

func (oi *oidcAuthenticator) handleTokenExchange(c *gin.Context) {
	// parse and validate the incoming JSON request
	var req ExchangeTokenRequest
	if err := c.ShouldBindJSON(&req); err != nil {
		c.JSON(http.StatusBadRequest, ExchangeTokenResponse{
			Success: false,
			Message: "Invalid request: " + err.Error(),
		})
		return
	}

	// check state matches stored value on the session
	ginSession := sessions.Default(c)
	storedState := ginSession.Get("state")
	if storedState == nil || req.State != storedState.(string) {
		c.JSON(http.StatusBadRequest, ExchangeTokenResponse{
			Success: false,
			Message: "Invalid state parameter",
		})
		return
	}
	ginSession.Delete("state")

	// Begin token exchange to retrieve attested claims of authenticated user
	ctx := context.Background()
	oauth2Token, err := oi.oauth2Config.Exchange(ctx, req.Code)
	if err != nil {
		oi.lggr.Errorf("Failed to exchange token: %v", err)
		c.JSON(http.StatusInternalServerError, ExchangeTokenResponse{
			Success: false,
			Message: "OIDC exchange failed",
		})
		return
	}

	// Request token from provider for claims lookup and verification
	rawIDToken, ok := oauth2Token.Extra("id_token").(string)
	if !ok {
		oi.lggr.Errorf("No id_token field in oauth2 token: %v", err)
		c.String(http.StatusInternalServerError, "Missing id_token field in response")
		return
	}

	// Verify claim and retrieve attested user id claims
	idToken, err := oi.provider.Verifier(oi.oidcConfig).Verify(ctx, rawIDToken)
	if err != nil {
		oi.lggr.Errorf("Failed to verify ID token: %v", err)
		c.String(http.StatusInternalServerError, "Failed to verify ID token")
		return
	}

	var claims map[string]any
	if err = idToken.Claims(&claims); err != nil {
		oi.lggr.Errorf("Failed to parse OIDC return claims: %v", err)
		c.String(http.StatusInternalServerError, "Failed to parse OIDC return claims")
		return
	}
	idClaims, err := oi.ExtractIDClaimValues(claims, oi.config.ClaimName())
	if err != nil {
		oi.lggr.Errorf("Failed to extract ID claims from ID token. ClaimName: '%s': error %v", oi.config.ClaimName(), err)
		c.String(http.StatusInternalServerError, "Failed to extract ID claims from claims")
		return
	}
