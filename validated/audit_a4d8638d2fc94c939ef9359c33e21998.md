### Title
Unbounded Uniswap V4 spot-price oracle lets an intent placer manipulate reserves to mis-price solver fills - ([File: sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts])

### Summary
Simplex's `FXFiller` prices "venue" (curveless) trading pairs directly off a Uniswap V4 pool's instantaneous spot price (`sqrtPriceX96`), with no TWAP, no trade-size/impact term, and only an optional, static-band `checkPriceGuard`. An intent placer who manipulates the referenced pool's reserves via ordinary swap calls — the exact bug class in the YSDAO/PancakeSwap V2 incident — can push the pool's spot price outside fair value but still inside (or with no) guard band, submit an Intent Gateway order against that manipulated price, and have the Simplex solver fill it at the distorted rate, extracting value from the solver's inventory.

### Finding Description
`UniswapV4FundingPlanner.getExoticTokenPrice` → `computeDirectPoolPriceUsd` reads the pool's current `token0Price`/`token1Price` (derived from `sqrtPriceX96`) as the USD price of the exotic token, picking whichever position has the largest raw liquidity: [1](#0-0) [2](#0-1) 

This raw mid is fed straight into `FXFiller.resolveLegRates`, which inverts it into the leg's trading rate for a curveless USD-stable pair, and the only defense is `checkPriceGuard`: [3](#0-2) [4](#0-3) 

`checkPriceGuard` compares the live quote against a static `referencePrice` within `maxDeviationBps` — it is entirely optional (both fields can be omitted, "leaving the chain unguarded"), and even when configured it is a static band unrelated to the cost of moving the pool, not a manipulation-resistance mechanism (no TWAP, no minimum liquidity check, no same-block detection): [5](#0-4) 

The project's own internal flow documentation states this plainly: *"there is no size or impact term ... `checkPriceGuard` is the only defense on this path, and it checks deviation from a static reference, not execution cost."* [6](#0-5) 

Once the (possibly manipulated) rate passes the guard, `computeLegPolicyOutput` linearly extends that single spot price across the entire order notional with no depth/impact adjustment, and the resulting output amount is what the filler actually pays out on `fillOrder`: [7](#0-6) [8](#0-7) 

The upstream incident (YSDAO on PancakeSwap V2) manipulated AMM reserves via ordinary contract calls to distort the pool-derived price and extract value; the analogous reachable path here is: an attacker swaps against the referenced Uniswap V4 pool (any unprivileged EOA/contract call, no special role needed) to move `sqrtPriceX96`, then — within the same or an adjacent block, and either inside a configured guard band or on a chain left unguarded — places an Intent Gateway order that the Simplex solver prices and fills off that distorted spot price.

### Impact Explanation
A manipulated pool price directly determines the amount of tokens the Simplex filler pays out on a live order fill (`finalOutputAmount`/`policyMaxOutput`), which is transferred to the order's beneficiary via `IntentGatewayV2.fillOrder`/`IntrinsicIntents._fillSameChain`. Depressing the exotic token's apparent USD price causes the solver to hand out more exotic tokens than fair value per unit of stablecoin received, letting the attacker profit at the solver's expense once the manipulated pool state reverts (arbitrage back). This is concrete theft of solver-held funds reachable from a single submitted order plus ordinary swap transactions — no admin, governance, or infrastructure compromise required. Severity is bounded by pair `maxOrderSize`/wallet balances but is otherwise a direct value-extraction path, consistent with Medium severity of the cited incident.

### Likelihood Explanation
The price guard is optional per chain/position (config can leave it unset), and even where configured it is a static percentage band chosen without regard to the actual cost of moving the referenced pool — a pool with modest liquidity can be pushed past a naive quote yet still inside a loosely-configured band, or the guard can simply be absent. The reachable trigger is an ordinary swap transaction on the public pool followed by a normal Intent Gateway order placement — both are unprivileged actions available to any user, matching the "reserve manipulation via contract calls" pattern of the referenced incident.

### Recommendation
Replace or supplement the raw `sqrtPriceX96` spot read with a manipulation-resistant price: a TWAP over a meaningful window, a liquidity-depth-weighted execution price (quoting the actual swap size rather than the mid), and/or same-block/same-transaction manipulation detection. Make the reference-price guard mandatory for any venue-priced pair rather than optional, and size the guard band relative to the pool's realistic slippage cost for the configured `maxOrderSize`, not an arbitrary static percentage.

### Proof of Concept
1. Attacker identifies a Simplex-configured Uniswap V4 pool (e.g. USDC/cNGN) used for venue pricing with no `referencePrice`/`maxDeviationBps` guard configured, or a wide band.
2. Attacker swaps a sizeable amount into the pool to move `sqrtPriceX96`, depressing the exotic token's `token1Price`/`token0Price` reading that `computeDirectPoolPriceUsd` will return.
3. In the same or next block, attacker places an Intent Gateway order (USDC → exotic token) sized within `maxOrderSize`.
4. `FXFiller.resolveLegRates` reads the manipulated pool price via `getExoticTokenPrice`; `checkPriceGuard` passes (absent or within a loose band); `computeLegPolicyOutput` linearly extends the distorted mid across the full order notional.
5. Solver fills the order, paying out more exotic tokens than fair value.
6. Attacker reverses the initial swap, restoring the pool to its original price and realizing the price difference as profit, extracted from the solver's inventory — mirroring the reserve-manipulation mechanics of the referenced YSDAO/PancakeSwap V2 incident.

	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}

				priceUsd: new Decimal(sdkPool.token0Price.toFixed(18)),
			}
		}

	}

	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {
			this.logger.warn(
				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
	}

	private computeLegPolicyOutput(
		inputAmount: bigint,
		inputIsToken0: boolean,
		token0Decimals: number,
		token1Decimals: number,
		/**
		 * Token0 left in the pair's per-order exposure budget, or `null` to price the whole
		 * input unbudgeted. Only a price probe passes `null`: it commits no capital, so there
		 * is no exposure to ration, and a clamped quantity would silently misprice it.
		 */
		remainingToken0: Decimal | null,
		rate: Decimal,
	): { token0Used: Decimal; policyMaxOutput: bigint } | null {
		let legMaxToken0: Decimal
		if (inputIsToken0) {
			legMaxToken0 = new Decimal(formatUnits(inputAmount, token0Decimals))
		} else {
			legMaxToken0 = new Decimal(formatUnits(inputAmount, token1Decimals)).div(rate)
		}

		const token0ForLeg = remainingToken0 === null ? legMaxToken0 : Decimal.min(legMaxToken0, remainingToken0)
		if (token0ForLeg.lte(0)) {
			return null
		}

		let policyMaxOutput: bigint
		if (inputIsToken0) {
			// Output is token1: convert the token0 allocation at the pair rate.
			policyMaxOutput = BigInt(
				token0ForLeg.mul(rate).mul(new Decimal(10).pow(token1Decimals)).floor().toFixed(0),
			)
		} else {
			// Output is token0: pay out the token0 equivalent of the token1 input.
			policyMaxOutput = BigInt(token0ForLeg.mul(new Decimal(10).pow(token0Decimals)).floor().toFixed(0))
		}

		return { token0Used: token0ForLeg, policyMaxOutput }
	}

## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.

```toml lineNumbers
[vault.uniswapV4]
# referencePrice is the expected cNGN per USD;
# reject if the quote is more than 2% off.
# The two go together — one without the other is rejected.
[[vault.uniswapV4.positions]]
chain           = "EVM-8453"
tokenId         = "2087350"
referencePrice  = "1575"
maxDeviationBps = 200
```

# Venue pricing (Uniswap V4 funded pairs)

Verified 2026-08-19.

```
resolveLegRates(...)
  curveless pair && token0 is a USD stable
    -> venuePriceMemo() -> getVenueUsdPrice(chain, token1)
         -> UniswapV4FundingPlanner.getExoticTokenPrice
              picks the position with the largest pool liquidity
              -> computeDirectPoolPriceUsd -> sdkPool.token0Price / token1Price
    -> checkPriceGuard(...)   reject if outside maxDeviationBps of the static reference
    -> rate = 1 / venueUsd
  otherwise -> the pair's ask/bid curve at the leg's notional
```

`computeDirectPoolPriceUsd` returns the **raw pool mid** derived from `sqrtPriceX96`. The pool's
fee tier is read and stored on the hydrated position (`pos.fee`) but never applied to the price,
and there is no size or impact term — `computeLegPolicyOutput` extends the mid linearly across the
whole priced quantity. `checkPriceGuard` is the only defense on this path, and it checks deviation
from a static reference, not execution cost. A venue-priced pair that has to swap through its own
pool to source inventory pays a fee tier it never quoted against.
