### Title
Unauthenticated "Magic" QR-code triggers Wi-Fi credential reset before operator authorization, causing orb-wide signup DoS - (File: src/plans/mod.rs)

### Summary
`handle_magic_operator_qr_code` executes `MagicResetWifi`/`MagicResetMirror` actions immediately after a QR code is decoded from the camera, and this happens *before* `verify_operator_qr_code` calls the backend to check that the scanned code belongs to an authorized operator. Anyone able to present a QR code to the Orb's camera (no credentials, no backend authorization) can therefore trigger `network::reset()`, wiping the Orb's Wi-Fi configuration and disconnecting it, denying signup service to all subsequent legitimate users until the device is manually re-provisioned.

### Finding Description
In `scan_initial_qr_codes` and `scan_remaining_qr_codes`, the flow is:
1. `scan_operator_qr_code` — captures and parses a QR code from the camera (attacker-controlled content, unauthenticated).
2. `handle_magic_operator_qr_code` — if the parsed code matches `Data::MagicResetWifi` or `Data::MagicResetMirror`, the corresponding privileged action runs immediately.
3. Only *after* that does `verify_operator_qr_code` call the backend (`backend::operator_status::request`) to confirm the operator's identity/authorization is `valid`. [1](#0-0) [2](#0-1) 

The QR-code parser accepts any camera input matching the regex `magic_action:(reset_wifi_credentials|reset_mirror_calibration)`: [3](#0-2) 

When `MagicResetWifi` is matched, `reset_wifi_and_ensure_network` is invoked, which calls `network::reset()`: [4](#0-3) 

`network::reset()` runs `wpa-supplicant-interface restore-default-config` and `reconfigure`, which overwrites the persisted Wi-Fi configuration with the default (empty) config and forces `wpa_supplicant` to reload it, disconnecting the Orb from its currently configured network: [5](#0-4) [6](#0-5) 

This mirrors the report's bug class: an unprivileged actor supplies attacker-controlled input (the exchange address/routerCalldata in the Permit2 case; here, the QR-code string) that is consumed by a privileged operation (`invalidateNonces` there; `network::reset()`/config wipe here) *before* any authorization check validates that the caller is entitled to trigger it. Just as the Permit2 nonce becomes permanently desynchronized for legitimate future swaps, the Orb's Wi-Fi state is wiped for legitimate future operator/signup sessions — and unlike the swap case, there is no automatic recovery: the Orb stays offline until a legitimate operator manually re-provisions Wi-Fi credentials via a genuine hotspot QR code.

### Impact Explanation
Any bystander who can show a crafted QR code to the Orb's camera during idle/self-serve scanning can force the device to drop its network connection. Because network connectivity is required to reach `SIGNUP_BACKEND_URL` for operator/user QR-code validation, signup polling, and biometric data upload, this results in denial of service for all legitimate signups on that Orb until Wi-Fi is manually restored. Repeated triggering (the QR code can be shown at any time the Orb is scanning for an operator QR code, which is the normal idle state) creates a persistent DoS with no operator authentication required.

### Likelihood Explanation
High likelihood: the attack requires no privileges, no valid operator or user QR code, and no interaction with the backend — only physical proximity to present a printed/displayed QR code with the fixed string `magic_action:reset_wifi_credentials` to the Orb's camera during its normal idle-scanning state. The regex and dispatch logic are simple and reliably reachable in the standard signup flow (`scan_initial_qr_codes`/`scan_remaining_qr_codes`), which run before any authorization check.

### Recommendation
Move the authorization/validation check (`verify_operator_qr_code`, or an equivalent authenticated-operator check) before dispatching any magic/privileged QR-code action, so that `MagicResetWifi`/`MagicResetMirror` only execute for a QR code that the backend has confirmed belongs to an authorized operator. Alternatively, require a second factor (e.g., a signed/backend-issued magic token) rather than trusting a static plaintext string decoded directly from camera input.

### Proof of Concept
1. Generate a QR code encoding the literal string `magic_action:reset_wifi_credentials`.
2. Present it to the Orb's camera while it is idly scanning for an operator QR code (no prior authentication or operator session required).
3. Observe that `handle_magic_operator_qr_code` matches `Data::MagicResetWifi` and calls `reset_wifi_and_ensure_network`, which runs `network::reset()` and disconnects the Orb from its Wi-Fi network — before any backend-based operator validation occurs.
4. The Orb is now unable to reach the signup backend, blocking all subsequent legitimate signups until Wi-Fi is manually reconfigured.

        orb: &mut Orb,
        qr_code: qr_scan::operator::Data,

static MAGIC_QR_CODE: Lazy<Regex> = Lazy::new(|| {
    Regex::new(
        r"(?x)
        ^
        magic_action
        :
        (?P<magic_action>[\w]+)
        $
    ",
    )
    .expect("bad regex")
});

/// Operator QR-code data.
#[derive(Clone, Debug)]
pub enum Data {
    /// Normal Operator QR-code.
    Normal(user::Data),
    /// Action to reconfigure WiFi.
    MagicResetWifi,
    /// Action to reset mirror calibration.
    MagicResetMirror,
}

impl Schema for Data {
    fn ui() -> ui::QrScanSchema {
        ui::QrScanSchema::Operator
    }

    fn try_parse(code: &str) -> Option<Self> {
        let normal = user::Data::try_parse(code)
            .filter(
                |d| if d.signup_extension() { d.signup_extension_config.is_some() } else { true },
            )
            .map(Data::Normal);
        if normal.is_some() {
            return normal;
        }
        if let Some(captures) = MAGIC_QR_CODE.captures(code) {
            return match captures
                .name("magic_action")
                .expect("magic_action group must be present")
                .as_str()
            {
                "reset_wifi_credentials" => Some(Data::MagicResetWifi),
                "reset_mirror_calibration" => Some(Data::MagicResetMirror),
                _ => None,
            };
        }
        None
    }

    spawn_blocking(move || {

            .arg("restore-default-config")
            .status()
            .wrap_err("running `wpa-supplicant-interface`")?

        Command::new(WPA_SUPPLICANT_INTERFACE_BIN)
            .arg("reconfigure")
            .status()
            .wrap_err("running `wpa-supplicant-interface`")?
            .success()
            .then_some(())
            .ok_or_else(|| eyre!("`wpa-supplicant-interface` terminated unsuccessfully"))

}
