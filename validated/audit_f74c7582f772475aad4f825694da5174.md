### Title
CatFee API Key and Secret Logged in Plaintext at `info` Level - (File: `tesseract/messaging/tron/src/lib.rs`)

### Summary
`TronClient::new` logs the entire `CatFeeConfig` struct — including the `api_key` and `api_secret` used to sign bandwidth-purchase (TRON energy) requests — in plaintext at `info` log level whenever CatFee integration is enabled. [1](#0-0)  This is the same bug class as GHSA-j6hh-h3cf-c2hf (sensitive credentials placed in logs), except here the sensitive data is exposed at the default `info` verbosity rather than requiring an operator to explicitly enable `trace`.

### Finding Description
`CatFeeConfig` derives `Debug` and stores both `api_key` and `api_secret` as plain `String` fields with no redaction: [2](#0-1) 

When a relayer/bandwidth-purchaser operator configures TRON with CatFee credentials (`catfee_api_key`, `catfee_api_secret` in `TronConfig`), `TronClient::new` builds a `CatFeeConfig` from these values and immediately logs it with the `{:#?}` (pretty Debug) formatter:

```rust
let catfee_config = CatFeeConfig {
    api_key: api_key.clone(),
    api_secret: api_secret.clone(),
    timeout: std::time::Duration::from_secs(config.tron_api_timeout_secs),
    ..Default::default()
};
log::info!(target: LOG_TARGET, "CatFee integration enabled: {:#?}", catfee_config);
``` [3](#0-2) 

Because `Debug` is derived without any custom masking, this line prints the raw `api_key` and `api_secret` values into whatever log sink the relayer node uses (stdout, log files, log aggregation, telemetry pipelines) at `info` — a level that is enabled by default in most deployments, unlike `trace`.

The `api_secret` is the HMAC-SHA256 signing key used to authenticate every CatFee order-creation and order-query call: [4](#0-3)  Anyone who can read the relayer's logs (log aggregator, monitoring dashboard, misconfigured log retention, shared hosting, support ticket paste, CI artifact, etc.) obtains both the `api_key` and the HMAC secret and can forge arbitrary signed requests to the CatFee API on behalf of the relayer's account — e.g., placing energy-purchase orders billed to the operator's CatFee balance, or querying/tampering with order state used to gate `purchase_energy_via_catfee` in the TRON transaction-submission path (`trigger_sign_broadcast` → `purchase_energy_via_catfee` → `catfee_client.purchase_energy`). [5](#0-4) [6](#0-5) 

### Impact Explanation
Leaking the CatFee `api_key`/`api_secret` lets an attacker with log access impersonate the relayer's bandwidth-purchasing identity against the CatFee service: they can drain the operator's prepaid CatFee balance by placing unauthorized energy orders, or disrupt the relayer's TRON message-submission pipeline (every `Message` submission to TRON goes through `trigger_sign_broadcast`, which calls `purchase_energy_via_catfee` before broadcasting) by exhausting funds or interfering with legitimate orders, causing message delivery failures/DoS on the TRON route. This is a concrete theft-of-funds / route-availability risk tied directly to the relayer's operational credentials, not merely a hypothetical.

### Likelihood Explanation
Any operator who enables CatFee integration (a supported, documented feature for TRON bandwidth purchasing) triggers this log line unconditionally at `info` level on every `TronClient::new` invocation (i.e., on every relayer start/restart) — no special configuration or elevated privilege is needed to trigger the leak, only ordinary log visibility, which is common in centralized logging/monitoring setups.

### Recommendation
Do not derive/log `CatFeeConfig` via its raw `Debug` implementation. Implement a redacted `Debug`/`Display` (masking `api_key` and fully hiding `api_secret`, mirroring the existing `maskSecret`/`maskToml` pattern used elsewhere in the codebase for filler config) and use that in the `log::info!` call in `TronClient::new`. Audit other `log::trace!`/`log::info!`/`log::error!` call sites in `tesseract/messaging/tron/` for similar unredacted logging of secrets or full request/response bodies that may carry credentials.

### Proof of Concept
1. Configure a TRON relayer with `catfee_api_key` and `catfee_api_secret` set in `TronConfig`.
2. Start the relayer with default (`info`) log level.
3. Observe the log line `"CatFee integration enabled: CatFeeConfig { api_key: "...", api_secret: "...", ... }"` printed to stdout/log file at startup, at `tesseract/messaging/tron/src/lib.rs:257`.
4. Any party with read access to these logs can extract `api_key`/`api_secret` and use `generate_signature` logic (documented in `catfee.rs` header comment) to forge authenticated CatFee API requests.

	/// Generate HMAC signature for API request
	///
	/// Signature format: Base64(HMAC-SHA256(secret, timestamp + method + requestPath))
	/// where requestPath includes query parameters
	fn generate_signature(&self, timestamp: &str, method: &str, request_path: &str) -> String {
		let message = format!("{}{}{}", timestamp, method, request_path);

		let mut mac = HmacSha256::new_from_slice(self.config.api_secret.as_bytes())
			.expect("HMAC can take key of any size");
		mac.update(message.as_bytes());

		BASE64.encode(mac.finalize().into_bytes())
	}

async fn purchase_energy_via_catfee(
	catfee_client: &CatFeeClient,
	receiver_address: &str,
	energy_required: u64,
) -> anyhow::Result<()> {
	log::info!(target: crate::LOG_TARGET, "Purchasing {} energy units via CatFee", energy_required);

	// Convert TRON hex address (41-prefixed) to base58 if needed
	let receiver_base58 = if is_base58_address(receiver_address) {
		// Already in base58 format
		receiver_address.to_string()
	} else {
		// Convert from hex to base58
		hex_to_base58(receiver_address)
			.context("Failed to convert TRON address from hex to base58")?
	};

	log::trace!(target: crate::LOG_TARGET, "Using receiver address (base58): {}", receiver_base58);

	// Maximum wait time for order completion (3 minutes)
	let max_wait = Duration::from_secs(180);

	// Period: 1 hour (sufficient for immediate transaction)
	let period_hours = 1;

	catfee_client
		.purchase_energy(energy_required, &receiver_base58, period_hours, max_wait)
		.await
		.context("Failed to purchase energy via CatFee")?;
```
