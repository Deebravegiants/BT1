Audit Report

## Title
Unauthenticated remote proxy to internal LOOP plugin `pprof`/metrics debug endpoints - ([File: core/web/router.go])

## Summary
`loopRoutes` is registered directly on the base `api` router group in `NewRouter` without any authentication middleware, unlike `debugRoutes`, `sessionRoutes`, and `v2Routes`, which explicitly wrap their sensitive handlers with `auth.Authenticate(...)`. This exposes `GET /discovery`, `GET /plugins/:name/metrics`, `GET /plugins/:name/debug/pprof/*profile`, and `POST /plugins/:name/debug/pprof/symbol` to any unauthenticated remote client.

## Finding Description
`NewRouter` builds the base group `api` with only rate limiting and session middleware (no auth) and calls `loopRoutes(app, api)` alongside the other route groups: [1](#0-0) . Compare this to `debugRoutes`, which re-wraps its group with `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)` before registering `/vars`: [2](#0-1) , `sessionRoutes`, which separates unauthenticated and authenticated sub-groups: [3](#0-2) , and `v2Routes`, which authenticates all endpoints except the explicitly carved-out `/resume/:runID`: [4](#0-3) .

By contrast, `loopRoutes` registers its handlers directly on the unauthenticated `r` group with no auth wrapper at all: [5](#0-4) . These handlers proxy requests to the internal LOOP plugin's pprof server based on attacker-controlled `:name`/`:profile`/query parameters: [6](#0-5) , and `pluginPPROFPOSTSymbolHandler` forwards the raw POST body to the plugin's internal `/debug/pprof/symbol` endpoint: [7](#0-6) . The `pluginMetricHandler` similarly proxies to the plugin's `/metrics` endpoint unauthenticated: [8](#0-7) .

There is no evidence of any authentication check applied anywhere in this call path — no role check, no session/token verification — confirming the broken security assumption relative to the sibling route groups.

## Impact Explanation
An unauthenticated remote attacker reaching the node's HTTP port can enumerate registered LOOP plugins via `/discovery`, scrape internal `/plugins/:name/metrics` data, and trigger CPU/heap/goroutine profiling on the plugin process via `/plugins/:name/debug/pprof/*` with attacker-controlled `seconds`/`debug`/`gc` parameters, and POST arbitrary data to the plugin's internal `/debug/pprof/symbol`. This is a concrete information-disclosure and resource-exhaustion risk against a production node's LOOP plugin process, reachable without any credentials — matching the "node API authentication bypass" impact class since a security boundary (authentication middleware applied consistently to every other sensitive route group) is absent here.

## Likelihood Explanation
High. The routes are registered unconditionally in `NewRouter` whenever the application starts (LOOP plugin registry is always constructed), requiring only network reachability to the node's web server and no credentials. Plugin names are discoverable via the equally unauthenticated `/discovery` endpoint, making full exploitation trivial and repeatable.

## Recommendation
Wrap `loopRoutes` registration with `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)`, consistent with `v2Routes`, and consider an admin-only role check for the pprof/symbol endpoints, matching the protection level applied to `debugRoutes`.

## Proof of Concept
Against a running chainlink node with LOOP plugins configured, without any session cookie or API token:
```
GET /discovery HTTP/1.1
Host: <node>
```
returns registered plugin metrics targets. Then:
```
GET /plugins/<plugin-name>/debug/pprof/profile?seconds=60 HTTP/1.1
Host: <node>
```
triggers a 60-second CPU profile proxy request to the internal plugin process, and:
```
POST /plugins/<plugin-name>/debug/pprof/symbol HTTP/1.1
Host: <node>
Content-Length: ...

<body>
```
forwards attacker-controlled data to the plugin's internal `/debug/pprof/symbol` endpoint — all without authentication, confirmed directly by `core/web/router.go` lines 230-236 and `core/web/loop_registry.go` lines 150-188.

```go
func sessionRoutes(app chainlink.Application, r *gin.RouterGroup) {
	config := app.GetConfig()
	rl := config.WebServer().RateLimit()
	unauth := r.Group("/", rateLimiter(
		rl.UnauthenticatedPeriod(),
		rl.Unauthenticated(),
	))
	sc := NewSessionsController(app)
	unauth.POST("/sessions", sc.Create)
	auth := r.Group("/", auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession))
	auth.DELETE("/sessions", sc.Destroy)
}
```

```go
func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/metrics", l.loopHostName, p.EnvCfg.PrometheusPort)
	req, err := http.NewRequestWithContext(gc.Request.Context(), http.MethodGet, pluginURL, nil)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)
	if err != nil {
		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q metrics", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}
```

```go
func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
```

```go
func (l *LoopRegistryServer) pluginPPROFPOSTSymbolHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/symbol", l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	body, err := io.ReadAll(gc.Request.Body)

		return
	}
	l.doRequest(gc, "POST", pluginURL, bytes.NewReader(body), timeout, pluginName)
```
