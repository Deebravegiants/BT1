## Title
Emporium relay-fee payment lets an unprivileged submitter drain a signer's `HinkalWallet` in an unauthorized token/recipient - (File: `contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol`)

### Summary
The Emporium external action lets a `HinkalWallet` owner authorize a batch of operations off-chain via an EIP-712 signature. The signed payload only commits to the `ops` array, `maxFee`, `deadline` and `emporiumMessage`, but the relay-fee token (`feeStructure.feeToken`) and the relay recipient (`circomData.relay`) are left outside the signed digest. Whoever submits the transaction (the ZK prover/relay — an unprivileged party relative to the wallet's EOA signer) can therefore choose an arbitrary `feeStructure.feeToken` and `circomData.relay`, causing the wallet to pay `flatFee` (bounded only by the raw numeric `maxFee`) worth of an entirely different, more valuable ERC-20 token than the signer intended, to a relay address of the attacker's choosing.

### Finding Description
`verifyWallet` computes the signed digest as: [1](#0-0) 

This digest binds `circomData.emporiumMessage`, the hash of `stack.ops`, `stack.maxFee` and `stack.deadline`. It never includes `circomData.feeStructure.feeToken`, `circomData.relay`, or `circomData.erc20TokenAddresses`.

`payRelayFees` uses these unsigned fields directly to move wallet funds when `signerAddress != address(0)`: [2](#0-1) 

Two paths let the caller choose the debited token freely:
1. The per-token loop sets `relayFee = flatFee` whenever `erc20TokenAddress == feeStructure.feeToken` — and `erc20TokenAddresses` is not signed, so the caller can order/populate it so any wallet-held token matches `feeStructure.feeToken`.
2. The `!foundToken` fallback branch calls `payRelay(circomData.relay, signerAddress, feeStructure.flatFee, feeStructure.feeToken)` even when `feeStructure.feeToken` is *not* one of the tokens involved in any op at all: [3](#0-2) 

The only guard is `feeStructure.flatFee > stack.maxFee` reverting with `FeeExceedsSignedMax`: [4](#0-3) 

`maxFee` is a raw numeric cap with no token binding, so a wallet owner who signs a small `maxFee` expecting it to be denominated in a stablecoin (e.g. `100` of USDC, 6 decimals) has that same numeric bound reinterpreted against `payRelay`, which finally invokes: [5](#0-4) 
which calls `IHinkalWallet(signerAddress).doSendToRelay(relay, relayFee, feeToken)` — an authenticated (`onlyEmporium`) but token/recipient-unrestricted transfer straight out of the wallet: [6](#0-5) 

Because the ZK-proof/`calldataHash` mechanism authenticates the *prover's* intent to spend their own shielded UTXOs, not the separate EOA `signerAddress` that owns the on-chain `HinkalWallet`, the prover/relay assembling `circomData` is an unprivileged party with respect to the wallet's funds. This breaks the intended equality: "value moved out of the wallet must equal what the wallet owner authorized via the wallet's own signed message," since the moved value's *token* and *destination* are decided entirely by the (potentially malicious) submitter rather than by the wallet signer's `EMPORIUM_SIGNATURE_TYPEHASH` signature.

### Impact Explanation
This allows theft of user funds held in a `HinkalWallet`: an attacker who observes/obtains a validly-signed `EmporiumStack` (e.g. from a legitimate dApp flow, since these signatures typically travel through off-chain relayers/provers) can redirect the relay-fee payment to any ERC-20 asset the wallet holds (up to the numeric `maxFee`) and route it to an attacker-controlled relay address, rather than the fee token/recipient the signer implicitly expected. This is a theft of protocol-adjacent user funds via an unauthorized wallet operation, matching the "transferFrom / wallet op not authorised by the prover or signer" analog class.

### Likelihood Explanation
Any party capable of submitting a Hinkal transaction with a previously-issued, unused `EmporiumStack` signature (a role explicitly outside the trust boundary of the wallet's EOA signer, since Emporium is designed to let relays/provers submit these txs) can exploit this without any privileged role, admin key, or race condition — only requiring that `feeStructure.flatFee <= stack.maxFee` and a token in the wallet with value.

### Recommendation
Include `feeStructure.feeToken` (and ideally `circomData.relay`) inside the `EMPORIUM_SIGNATURE_TYPEHASH` digest so the wallet signer explicitly authorizes which token and which relay may receive the flat fee, mirroring the `ops` binding already done for endpoint/callData/value.

### Proof of Concept
1. Wallet owner signs an `EmporiumStack` with `ops = [swap USDC via router]`, `maxFee = 5e6` (intending "5 USDC"), `deadline`, and a fresh `emporiumMessage`.
2. Prover/relay who obtains this signature crafts `circomData` where `erc20TokenAddresses` includes `WBTC` at the fee-relevant index (or simply sets `feeStructure.feeToken = WBTC`, `feeStructure.flatFee = 5e6` with WBTC's 8 decimals so 5e6 raw units == ~0.05 WBTC, worth far more than 5 USDC), and sets `circomData.relay = attackerRelay`.
3. `runAction` executes the signed `ops` (unaffected), then calls `payRelayFees`, which — because `flatFee (5e6) <= maxFee (5e6)` — calls `payRelay` → `sendToRelayFromWallet` → `IHinkalWallet(signerAddress).doSendToRelay(attackerRelay, 5e6, WBTC)`, draining WBTC from the wallet to `attackerRelay`, despite the signer never having authorized spending WBTC or paying that relay.

```text
    function payRelayFees(
        CircomData calldata circomData,
        address signerAddress,
        int256[] calldata deltaAmountChanges
    ) internal {
        FeeStructure calldata feeStructure = circomData.feeStructure;

        bool foundToken = false;

        for (uint256 i = 0; i < circomData.erc20TokenAddresses.length; i++) {
            // tokens deposited into Emporium are not charged
            if (deltaAmountChanges[i] >= 0) {
                continue;
            }

            address erc20TokenAddress = circomData.erc20TokenAddresses[i];
            bool isFeeToken = erc20TokenAddress == feeStructure.feeToken;

            if (isFeeToken) {
                foundToken = true;
            }

            uint256 relayFee = 0;
            uint256 flatFee = isFeeToken ? feeStructure.flatFee : 0;

            if (signerAddress == address(0)) {
                uint256 sumAbs = uint256(-deltaAmountChanges[i]);

                EmporiumStorageVars storage $ = _getEmporiumStorage();
                relayFee = $._hinkalHelper.calculateRelayFee(
                    sumAbs,
                    flatFee,
                    feeStructure.variableRate
                );
            } else {
                relayFee = flatFee;
            }

            payRelay(
                circomData.relay,
                signerAddress,
                relayFee,
                erc20TokenAddress
            );
        }

        if (!foundToken && feeStructure.flatFee != 0) {
            require(
                signerAddress != address(0),
                "Gas Token in Emporium is not found"
            );

            payRelay(
                circomData.relay,
                signerAddress,
                feeStructure.flatFee,
                feeStructure.feeToken
            );
        }
    }
```
