Audit Report

## Title
Unvalidated hex length causes panic (`strings.Repeat` negative count) via unauthenticated `workflows.execute` HTTP trigger request - ([File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go])

## Summary
`validateHexInput` only checks that the submitted `workflowID`/`workflowOwner` string is not longer than `workflowIDLength` (66) or `workflowOwnerLength` (42) and is valid hex, without requiring the `0x` prefix. `normalizeHex` then computes `strings.Repeat("0", (length-2)-len(hexStr))`, which becomes negative when the un-prefixed hex string is exactly at the maximum length, causing a panic that is reachable before JWT authorization and rate limiting.

## Finding Description
`validateHexInput` (L267-283) bounds only the total input length and validates hex-decodability but never enforces the `0x` prefix: [1](#0-0) 

`workflowIDLength` (66) and `workflowOwnerLength` (42) assume a `0x` prefix plus 64/40 hex chars: [2](#0-1) 

`normalizeHex` strips any `0x` prefix (a no-op if absent) and pads with `strings.Repeat("0", expectedHexLength-len(hexStr))` without checking that the count is non-negative: [3](#0-2) 

`resolveWorkflowID` calls `normalizeHex` directly on the field validated by `validateHexInput`, and this whole chain runs inside `HandleUserTriggerRequest` at lines 101-104, strictly *before* `authorizeRequest` (JWT/key check, L106-109) and `checkRateLimit` (L111-113): [4](#0-3) 

For a 66-character lowercase hex string with no `0x` prefix (e.g., 66 `a` characters): `validateHexInput` passes (`len(input)=66` is not `> 66`; `hex.DecodeString` succeeds on the even-length hex string). In `normalizeHex`, `TrimPrefix` is a no-op, so `len(hexStr)=66`, `expectedHexLength=64`, and `strings.Repeat("0", 64-66)` is called with count `-2`. Go's `strings.Repeat` panics on a negative count, per the language's documented behavior. The gateway's `ProcessRequest` routes the unauthenticated raw HTTP body directly into this handler chain with no pre-auth gate: [5](#0-4) 

## Impact Explanation
An unauthenticated client can craft a single JSON-RPC `workflows.execute` request with a `workflowID` (or `workflowOwner`) that is valid hex, exactly at the boundary length, and missing the `0x` prefix. This causes a Go runtime panic during workflow ID resolution, before any JWT authorization or per-workflow rate limiting is applied. While Go's `net/http` server recovers panics per-connection (preventing full process crash), the specific in-flight request/connection is aborted ungracefully and a stack trace is logged, and the attack is trivially repeatable pre-auth — matching a resource-exhaustion / denial-of-service class issue on a gateway endpoint reachable by any unprivileged caller.

## Likelihood Explanation
High likelihood: exploitation requires no credentials, no prior state, and a single crafted HTTP POST with a trivially constructible payload (any even-length lowercase hex string of exactly 66 or 42 characters without `0x` prefix). The vulnerable code executes unconditionally for any `workflowID`/`workflowOwner` field submitted, prior to authentication.

## Recommendation
- In `normalizeHex`, guard against `len(hexStr) >= expectedHexLength` before calling `strings.Repeat` (skip padding or reject the input if the un-prefixed hex payload is too long).
- In `validateHexInput`, require the `0x` prefix explicitly and validate the length of the hex payload *after* stripping the prefix against `expectedLength-2`, rather than validating the raw input length.
- Add unit tests for boundary-length hex inputs both with and without the `0x` prefix, for both `workflowID` and `workflowOwner`.

## Proof of Concept
Send an unauthenticated POST to the gateway's HTTP trigger endpoint:
```json
{
  "jsonrpc": "2.0",
  "id": "req-1",
  "method": "workflows.execute",
  "params": {
    "workflow": { "workflowID": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa" },

A minimal Go unit test calling `normalizeHex("aaaa...aaaa" /* 66 chars */, 66)` directly reproduces the panic deterministically.

func validateHexInput(input string, expectedLength int) error {
	if input != strings.ToLower(input) {
		return errors.New("must be lowercase")
	}

	if err != nil {

	}

}

// normalizeHex normalizes a hex string by stripping 0x prefix, padding with leading zeros, and adding 0x prefix back
func normalizeHex(input string, length int) string {
	hexStr := strings.TrimPrefix(input, "0x")
	// length-2 because we'll add "0x" prefix
	expectedHexLength := length - 2
	paddedHex := strings.Repeat("0", expectedHexLength-len(hexStr)) + hexStr
	return "0x" + paddedHex
}
