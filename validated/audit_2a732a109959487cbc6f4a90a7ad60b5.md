### Title
`BAD_DEBT_USD_THRESHOLD` is hardcoded to the default of `min_borrow_collateral_usd_wad`, so governance updates via `set_min_borrow_collateral_usd` never reach the liquidation bad-debt / dust-cleanup threshold - (File: contracts/controller/src/constants.rs)

### Summary
The FrankenDAO bug class is: a governance-updatable parameter exists, but one code path uses a hardcoded copy of its initial value, so updates silently do not apply there. XOXNO Lending has the same shape. The controller stores a configurable `min_borrow_collateral_usd_wad` (set at construction and updatable by a governance-executed `set_min_borrow_collateral_usd`, emitting `UpdateMinBorrowCollateralEvent`). Separately, `contracts/controller/src/constants.rs:3` defines `pub const BAD_DEBT_USD_THRESHOLD: i128 = DEFAULT_MIN_BORROW_COLLATERAL_USD_WAD;` — a compile-time constant pinned to the *default* ($5 WAD) of that same parameter. The liquidation engine uses this constant, not the stored value, in two places.

### Finding Description
In `contracts/controller/src/positions/liquidation/curve.rs`:

- `is_socializable_bad_debt` (lines 25-27) admits a position for bad-debt socialization when `total_debt > total_collateral && total_collateral <= BAD_DEBT_USD_THRESHOLD`. This is reached by the unprivileged `clean_bad_debt` entrypoint.
- `estimate_liquidation_amount` (lines 132-134) forces a full-debt close whenever a target-HF liquidation would leave residual debt below `BAD_DEBT_USD_THRESHOLD`. This is reached by the unprivileged `liquidate` entrypoint.

Both read the constant `DEFAULT_MIN_BORROW_COLLATERAL_USD_WAD` (`5 * WAD`, `common/src/constants/shared.rs:43`). Meanwhile `set_min_borrow_collateral_usd` writes the stored `min_borrow_collateral_usd_wad` consumed by `risk/validation.rs` for the borrow minimum check only. Exactly like `fullStakedTimeBonus / 2` ignoring `setMonsterMultiplier`, the bad-debt dust threshold stays at $5 forever regardless of governance updates.

### Impact Explanation
If governance raises the minimum borrow collateral (e.g. to $50) to reduce dust positions, the liquidation and bad-debt cleanup logic still uses $5: residual debts of $5–$50 that governance intended to be force-closed are left as partial liquidations, and insolvent accounts with $5–$50 of collateral cannot be socialized via `clean_bad_debt` — permanently freezing that bad debt on the books instead of writing it down via the supply index. Conversely if governance lowers the minimum, positions below it are still force-liquidated/socialized at the stale $5 bound, over-seizing borrower collateral relative to the configured policy. Impact is bounded to sub-threshold USD amounts per position, keeping this Medium rather than High.

### Likelihood Explanation
Requires a governance-executed `set_min_borrow_collateral_usd` to diverge the stored value from the default — a provided-for administrative action, same likelihood profile as the FrankenDAO `setMonsterMultiplier` proposal. Once executed, every unprivileged `liquidate` and `clean_bad_debt` call hits the stale constant with no further precondition.

### Recommendation
Replace the compile-time `BAD_DEBT_USD_THRESHOLD` with the stored `min_borrow_collateral_usd_wad` (read it into `LiquidationSnapshot`/context), or introduce a separately stored bad-debt threshold with its own setter so the coupling is explicit. Update `is_socializable_bad_debt` and the residual-debt branch of `estimate_liquidation_amount` to use the stored value.

### Proof of Concept
1. Governance executes `set_min_borrow_collateral_usd(50 * WAD)`; `UpdateMinBorrowCollateralEvent` confirms the stored value changed.
2. Attacker supplies dust collateral and borrows to create an account that becomes insolvent with, e.g., $20 collateral and $25 debt.
3. Any unprivileged caller invokes `clean_bad_debt(account_id)` expecting socialization under the new $50 floor — the call rejects because `is_socializable_bad_debt` compares collateral against the constant `5 * WAD`.
4. Similarly, a `liquidate` call on a solvent account whose target-HF close would leave $10 residual debt only fully closes because of the stale $5 check — behavior unchanged from before the governance update, proving the update had no effect on this path.

Note: verification was limited to the indexed snippets; I confirmed the constant definition and both use sites in `curve.rs`, and the existence of `set_min_borrow_collateral_usd`/stored config in `storage/protocol.rs`, `governance.rs`, and `risk/validation.rs`, but did not read those files line-by-line to confirm no other write path re-syncs the threshold.
