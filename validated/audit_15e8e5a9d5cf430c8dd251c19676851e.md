### Title
Suppliers can withdraw before bad-debt socialization and concentrate losses - (File: `contracts/pool/src/interest.rs`)

### Summary
A supplier can exit a debt asset at the pre-loss `supply_index` after an account becomes publicly insolvent but before `liquidate` or `clean_bad_debt` applies the write-down, leaving the remaining suppliers to absorb the full loss. The withdrawal path pays cash and burns shares at the current index, while bad debt is only socialized later by reducing that index for live supply shares. [1](#0-0) [2](#0-1) 

### Finding Description
`Controller::withdraw` is callable by an account owner or delegate, and a zero withdrawal amount requests the full supply position. [3](#0-2) [4](#0-3) 

The pool resolves the withdrawal at the current `supply_index`, burns the shares, checks available cash, utilization, and the no-debt-without-supply invariant, then debits cash; it does not reserve or immediately recognize bad debt implied by currently liquidatable accounts. [1](#0-0) [5](#0-4) 

Residual bad debt is only applied afterward when liquidation cleanup or standalone cleanup sends the debt position to `Pool::seize_positions`, which calls `apply_bad_debt_to_supply_index` and burns the debt. [6](#0-5) [2](#0-1) 

`apply_bad_debt_to_supply_index` proportionally reduces only the currently remaining supply shares, so shares already withdrawn before the call do not bear any portion of the write-down. [7](#0-6) 

The repository test `supplier_can_exit_ahead_of_bad_debt_writedown` demonstrates this race: after collateral crashes and Alice is liquidatable, Bob performs a full withdrawal before liquidation and exits whole, while Carol’s loss becomes more than three times her passive loss. [8](#0-7) 

### Impact Explanation
Suppliers who remain in the affected market absorb more than their pro-rata share of protocol bad debt, while early withdrawers receive cash at an index that has not yet recognized the loss. [9](#0-8) 

This is a user-fund redistribution flaw: the aggregate bad debt is fixed, but each exit at the pre-write-down index increases the burden on the remaining suppliers, with complete loss possible for a sufficiently small last supplier. [10](#0-9) 

### Likelihood Explanation
The attacker needs only an authorized supply account and enough pool cash for the withdrawal; `withdraw`, `liquidate`, and dust-capped `clean_bad_debt` are all reachable by unprivileged callers. [11](#0-10) [12](#0-11) 

Execution requires an account to become liquidatable or cleanup-eligible before the bad-debt write-down is processed, which makes this dependent on collateral-price movement and pending liquidation timing rather than continuously exploitable. [13](#0-12) [14](#0-13) 

The issue is consistent with Medium severity because loss concentration can materially harm remaining suppliers, but it requires recognized bad debt and sufficient available liquidity rather than allowing unconditional extraction. [15](#0-14) 

### Recommendation
Use asynchronous withdrawal requests or settlement epochs so withdrawals initiated after an adverse market event are settled after pending liquidation and bad-debt write-downs at the post-loss index. Alternatively, prevent normal debt-market withdrawals once a market enters a pending-loss state and expose a permissionless “recognize bad debt before withdrawal” path that applies the known write-down before cash can leave. The chosen mechanism must ensure suppliers withdrawing after the loss is observable still bear their pro-rata share rather than receiving the pre-loss index.

### Proof of Concept
The existing harness test establishes a 75%/25% supplier split, makes Alice insolvent through a public collateral-price crash, withdraws Bob’s full position, and then liquidates Alice; Bob receives at least his entire pre-crash balance while Carol’s loss is amplified over threefold. [16](#0-15) 

```rust

// supply(caller, account_id, spoke_id, assets)
// borrow(caller, account_id, borrows, to)
// withdraw(caller, account_id, withdrawals, to)
// liquidate(liquidator, account_id, debt_payments, seize_mode)

// 1. Bob and Carol supply the same debt asset.
t.supply(BOB, "ETH", 75.0);
t.supply(CAROL, "ETH", 25.0);

// 2. Alice supplies collateral and borrows the debt asset.
t.supply(ALICE, "USDC", 10.0);
t.borrow(ALICE, "ETH", 0.003);

// 3. Public oracle prices make Alice insolvent.
t.set_price("USDC", usd_cents(10));
t.assert_liquidatable(ALICE);

// 4. Bob exits before the bad-debt index write-down.
// Production call shape:
// withdraw(caller = BOB, account_id = bob_account,
//          withdrawals = [(ETH, 0)], to = None)
t.withdraw_all(BOB, "ETH");

// 5. A liquidator now realizes the residual bad debt.
t.liquidate(LIQUIDATOR, ALICE, "ETH", 0.001);

// 6. Bob exits whole, while Carol absorbs a concentrated loss.
assert!(bob_recovered >= bob_before_b);
assert!(carol_loss_b > carol_loss_a);
```

The production mechanics support the sequence because normal withdrawal pays `actual_amount` from existing reserves before liquidation, while `seize_positions` later reduces `supply_index` for the remaining debt-market suppliers. [17](#0-16) [7](#0-6)

pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));

/// Bad debt is written down only when a liquidation or cleanup call runs, and
/// `backing_shortfall` counts the unrecoverable debt at face value until then.
/// A supplier can exit at the pre-write-down index and leave the loss on the
/// suppliers who stay. Runs the same crash with Bob passive and with Bob
/// exiting first, and compares Carol's loss.
#[test]
fn supplier_can_exit_ahead_of_bad_debt_writedown() {
    // Scenario A: nobody dodges. Bob 75%, Carol 25% of the ETH supply.
    let mut a = setup();
    a.supply(BOB, "ETH", 75.0);
    a.supply(CAROL, "ETH", 25.0);
    a.supply(ALICE, "USDC", 10.0);
    a.borrow(ALICE, "ETH", 0.003);

    let carol_before_a = a.supply_balance(CAROL, "ETH");
    a.set_price("USDC", usd_cents(10));
    a.liquidate(LIQUIDATOR, ALICE, "ETH", 0.001);
    let carol_loss_a = carol_before_a - a.supply_balance(CAROL, "ETH");

    // Scenario B: identical state, but Bob withdraws before the write-down.
    let mut b = setup();
    b.supply(BOB, "ETH", 75.0);
    b.supply(CAROL, "ETH", 25.0);
    b.supply(ALICE, "USDC", 10.0);
    b.borrow(ALICE, "ETH", 0.003);

    let carol_before_b = b.supply_balance(CAROL, "ETH");
    let bob_before_b = b.supply_balance(BOB, "ETH");
    let bob_wallet_before = b.token_balance(BOB, "ETH");

    // The crash is public state. Alice is insolvent from here on, but no
    // write-down has been applied yet.
    b.set_price("USDC", usd_cents(10));
    b.assert_liquidatable(ALICE);

    // Bob exits at the un-written-down index. No gate stops him: the
    // liquidation buffer only guards borrow draws, and `backing_shortfall`
    // still values Alice's uncollateralised debt at face.
    b.withdraw_all(BOB, "ETH");
    let bob_recovered = b.token_balance(BOB, "ETH") - bob_wallet_before;

    b.liquidate(LIQUIDATOR, ALICE, "ETH", 0.001);
    let carol_loss_b = carol_before_b - b.supply_balance(CAROL, "ETH");

    assert!(
        bob_recovered >= bob_before_b,
        "Bob exits whole: supplied={:.9} recovered={:.9}",
        bob_before_b,
        bob_recovered
    );
    assert!(
        carol_loss_b > carol_loss_a,
        "dodging must push loss onto Carol: A={:.9} B={:.9}",
        carol_loss_a,
        carol_loss_b
    );

    // Carol holds 25% of supply, so passing the whole loss to her is ~4x.
    let amplification = carol_loss_b / carol_loss_a;
    assert!(
        amplification > 3.0,
        "expected ~4x concentration onto the remaining supplier, got {:.3}x \
         (A={:.9} B={:.9})",
        amplification,
        carol_loss_a,
        carol_loss_b
    );
