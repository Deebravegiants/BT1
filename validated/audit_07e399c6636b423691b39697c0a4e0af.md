### Title
Liquidator-chosen repayment can leave residual debt below the bad-debt dust threshold, bypassing the full-close promotion — ([File: contracts/controller/src/positions/liquidation/plan.rs](contracts/controller/src/positions/liquidation/plan.rs))

### Summary
The M-3 bug class is "a minimum-remainder invariant is checked against the requested amount, not the filled amount." XOXNO Lending has the same shape: `estimate_liquidation_amount` promotes a liquidation to a full close only when the *plan-estimated* residual would fall below `BAD_DEBT_USD_THRESHOLD`, but the actual repayment is bounded by what the liquidator submits in `debt_payments` and pulls in `apply_liquidation_repayments`. A liquidator can therefore deliver a partial repayment that leaves a residual debt below the dust threshold, and the post-liquidation cleanup gate only fires when the account is insolvent *and* holds collateral at or below the $5 cap, so a solvent account is left holding un-cleanable dust debt.

### Finding Description
In `estimate_liquidation_amount`, the dust invariant is enforced on the curve-derived ideal, not on what is actually repaid: [1](#0-0) 

`remaining_debt` is computed as `total_debt - ideal`. If the caller's `debt_payments` request less than `ideal`, `normalize_repayment_plan` (invoked from `build_liquidation_plan`) sizes the repay legs from the submitted payments, so the promotion at `curve.rs:133-134` never sees the true residual. [2](#0-1) 

On execution, `apply_liquidation_repayments` pulls the liquidator's offered amount per leg and scales seizure to the measured receipt, so nothing forces the residual back above the threshold: [3](#0-2) 

The only post-trade dust control is `check_bad_debt_after_liquidation`, which requires `is_socializable_bad_debt(total_debt, total_collateral)` — i.e., *insolvency plus* collateral ≤ `BAD_DEBT_USD_THRESHOLD`: [4](#0-3) [5](#0-4) 

A solvent account left with, e.g., $4 of debt and $1,000 of collateral satisfies neither gate. `clean_bad_debt` would revert with `CannotCleanBadDebt` (mod.rs:229-235), and `force_socialize_bad_debt` is owner-only. This mirrors the original bug exactly: `requestToClosePosition(100)` / `fillCloseRequest(99)` left dust the check skipped; here `liquidate(account, payment < ideal)` leaves dust the promotion skipped.

### Impact Explanation
The protocol's dust threshold exists because sub-threshold positions are uneconomical to liquidate (the threat model and `INV-LIQ` docs note the cleanup path is the intended disposal mechanism). A borrower or a griefing liquidator can deliberately strand a solvent account with dust debt: it accrues interest, occupies a borrow position slot, and cannot be removed by `clean_bad_debt` while solvent. If the account later drifts insolvent with collateral above $5, cleanup still requires the privileged `force_socialize_bad_debt` runbook. This is persistent dust debt that the protocol's own invariant (`estimate_leaves_no_sub_threshold_dust` in the Certora rules) is meant to exclude, reachable by any unprivileged liquidator.

### Likelihood Explanation
Any liquidator calling `liquidate` controls `debt_payments`. Leaving residual `total_debt - repaid < BAD_DEBT_USD_THRESHOLD` requires only choosing a payment slightly below the full debt — profitable since the seized collateral still scales to the measured receipt via `scale_seizures_to_received`. The borrower can also self-liquidate (mod.rs:31-32 permits owner self-liquidation in Transfer mode), so a borrower can manufacture the state intentionally. No price manipulation, privileged role, or oracle assumption is needed.

### Recommendation
Enforce the residual invariant on the *delivered* plan, not the estimate: after `normalize_repayment_plan` and `release_unbacked_repayment` produce the final `repayment.repay_usd`, compute `remaining = totals.total_debt - repay_usd` and either (a) reject when `0 < remaining < BAD_DEBT_USD_THRESHOLD`, or (b) promote the plan to a full close (pulling the whole debt via the `offered` mechanism with refund) as `estimate_liquidation_amount` already does for its ideal. Optionally relax `check_bad_debt_after_liquidation` to also socialize solvent accounts whose residual *debt* (not collateral) is below the dust threshold.

### Proof of Concept
1. Alice supplies $1,000 USDC and borrows $X of ETH such that HF < 1 after a small price move (e.g., via `t.set_price`).
2. Liquidator calls `liquidate(liquidator, alice_id, [(ETH, amount)], SeizeMode::Transfer)` where `amount`'s USD value equals `total_debt - $4` (below `BAD_DEBT_USD_THRESHOLD` = $5 WAD).
3. `estimate_liquidation_amount`'s ideal is either ≥ the offered amount or below it; either way the plan repays only the offered leg and the promotion branch at `curve.rs:133` does not fire for the true residual.
4. Post-call: `alice` retains a borrow position of ≈$4 with ≈$1,000 collateral. `clean_bad_debt(anyone, alice_id)` reverts `CannotCleanBadDebt` because `total_debt < total_collateral`; `check_bad_debt_after_liquidation` skipped cleanup for the same reason. The dust position persists and accrues interest indefinitely.

Uncertain element (not fully verified): the exact clamping behavior inside `normalize_repayment_plan` in `math.rs`, which I could not read in this session. If it unconditionally re-quotes every offered payment up to the promoted full-close amount, the offered-leg pull in `apply.rs:54-56` may still bound the fill to the submitted amount, but the residual-debt outcome depends on that normalization logic. The finding holds wherever the delivered repayment is allowed to be less than the promoted ideal while leaving `0 < remaining < BAD_DEBT_USD_THRESHOLD`.

/// Removes empty accounts or socializes insolvent debt under the collateral dust cap.
pub(crate) fn check_bad_debt_after_liquidation(
    env: &Env,
    cache: &mut Context,
    account_id: u64,
    account: &Account,
    totals: &AccountRiskTotals,
) {
    if account.borrow_positions.is_empty() {
        account::cleanup_account_if_empty(env, account, account_id);
        return;
    }

    if is_socializable_bad_debt(totals.total_debt, totals.total_collateral) {
        bad_debt::execute_bad_debt_cleanup(env, cache, account_id, account, totals);
    }
}
