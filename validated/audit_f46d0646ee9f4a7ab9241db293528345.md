Audit Report

## Title
Deprecated single-extension `StorageWeightReclaim::post_dispatch_details` mutates `BlockWeight` without coordinating via `ExtrinsicWeightReclaimed`, causing under/over-counted proof-size accounting when it does not wrap the full extension pipeline - ([File: cumulus/primitives/storage-weight-reclaim/src/lib.rs])

## Summary
The deprecated `allow_deprecated::StorageWeightReclaim::post_dispatch_details` directly `reduce`s/`accrue`s `frame_system::BlockWeight` based on its own computed `unspent`/`benchmarked_weight`/`consumed_weight` values, and never reads or writes `frame_system::ExtrinsicWeightReclaimed`, unlike the newer `cumulus_pallet_weight_reclaim::StorageWeightReclaim` and `frame_system::CheckWeight::post_dispatch_details`, which coordinate through that storage item via `Pallet::<T>::reclaim_weight`. If another extension's `post_dispatch_details` runs (in declaration-reverse order) between this deprecated extension and `CheckWeight`, and that extension further mutates the effective `post_info.actual_weight` used, `CheckWeight`'s independent reclaim computation can diverge from what was already applied, producing incorrect `BlockWeight` bookkeeping. This exactly matches the extension's own deprecation note.

## Finding Description
`post_dispatch_details` at [1](#0-0)  computes `unspent = post_info.calc_unspent(info).proof_size()`, `benchmarked_weight = info.total_weight().proof_size() - unspent`, and `consumed_weight` from the node-side proof size delta, then directly mutates `frame_system::BlockWeight` by `storage_size_diff` via `reduce`/`accrue`. It never touches `frame_system::ExtrinsicWeightReclaimed` and always returns `Ok(Weight::zero())`.

`frame_system::CheckWeight::post_dispatch_details` at [2](#0-1)  instead delegates to `crate::Pallet::<T>::reclaim_weight(info, post_info)`, which per the tests `extrinsic_already_refunded_more_precisely` and `extrinsic_already_refunded_less_precisely` at [3](#0-2)  reads/writes `ExtrinsicWeightReclaimed` to avoid double-adjusting `BlockWeight` when another extension already reclaimed part of the weight. Since the deprecated extension never populates this storage item, `CheckWeight::reclaim_weight` treats its prior adjustment as if nothing happened and computes its own reduction independently based on whatever `post_info.actual_weight` looks like at the time it runs.

This is consistent with, and explicitly documented by, the deprecation note on the struct: [4](#0-3) , which states the extension "ignores the post dispatch logic for extensions subsequent to itself."

I was unable to fully inspect `frame_system::Pallet::<T>::reclaim_weight`'s exact implementation in this session (the `substrate/frame/system/src/lib.rs` read returned truncated/incomplete content), so the precise arithmetic of how `ExtrinsicWeightReclaimed` interacts with `BlockWeight` beyond what the two cited tests demonstrate could not be independently re-derived from the primary source; the analysis relies on the test behavior shown in `check_weight.rs`.

## Impact Explanation
`CheckWeight::do_prepare` gates admission of extrinsics into a block based on the `BlockWeight` bookkeeping value, per [5](#0-4) . If this bookkeeping value is thrown out of sync with true PoV/proof-size consumption due to the uncoordinated double-adjustment, block weight/PoV accounting integrity is degraded. However, this requires an already-deprecated, non-default extension to be used, and specifically requires the runtime to be misconfigured with additional weight-refunding extensions positioned so their post-dispatch logic executes between the deprecated `StorageWeightReclaim` and `CheckWeight` in the pipeline — a configuration mistake the extension's own deprecation note explicitly warns against, not a bug exploitable purely through user-controlled extrinsic content in a correctly configured, currently-shipped runtime.

## Likelihood Explanation
The precondition (deprecated `StorageWeightReclaim` not positioned as outermost in a pipeline with other weight-refunding extensions in between it and `CheckWeight`) is a runtime-configuration issue, not something any current in-tree runtime does by default; the crate has already moved to `cumulus_pallet_weight_reclaim::StorageWeightReclaim` for exactly this reason and explicitly deprecated/documented the limitation of the old extension. No PoC or fork test was run to concretely demonstrate the magnitude of the discrepancy or that it results in exceeding `max_block` in practice; the report's PoC is a proposed test plan, not an executed one.

## Recommendation
For any runtime still using the deprecated single-extension `StorageWeightReclaim`, migrate to `cumulus_pallet_weight_reclaim::StorageWeightReclaim`, which coordinates via `frame_system::ExtrinsicWeightReclaimed`. If continued use of the deprecated extension is unavoidable, document/enforce that it must be the outermost extension in the pipeline, or backport the `ExtrinsicWeightReclaimed` coordination protocol into the deprecated implementation.

## Proof of Concept
As proposed in the submission: build a mock runtime with pipeline `[SomeWeightRefundingExtension, allow_deprecated::StorageWeightReclaim<T>, CheckWeight<T>]` (deprecated extension not first), dispatch a call whose `PostDispatchInfo.actual_weight` is further reduced by the dummy extension's `post_dispatch_details` after the deprecated extension has already run, and compare the resulting `BlockWeight::<T>::get()` against the true consumed proof size to show under/over-counting relative to a correctly-ordered pipeline. This test was not executed in this validation; it is a reasonable reproduction plan given the confirmed code behavior in `cumulus/primitives/storage-weight-reclaim/src/lib.rs` and `substrate/frame/system/src/extensions/check_weight.rs`, but requires the misconfiguration precondition to manifest.

	fn post_dispatch_details(
		pre: Self::Pre,
		info: &DispatchInfoOf<T::RuntimeCall>,
		post_info: &PostDispatchInfoOf<T::RuntimeCall>,
		_len: usize,
		_result: &DispatchResult,
	) -> Result<Weight, TransactionValidityError> {
		let Some(pre_dispatch_proof_size) = pre else {
			return Ok(Weight::zero());
		};

		let Some(post_dispatch_proof_size) = get_proof_size() else {
			log::debug!(
				target: LOG_TARGET,
				"Proof recording enabled during pre-dispatch, now disabled. This should not happen."
			);
			return Ok(Weight::zero());
		};
		// Unspent weight according to the `actual_weight` from `PostDispatchInfo`
		// This unspent weight will be refunded by the `CheckWeight` extension, so we need to
		// account for that.
		let unspent = post_info.calc_unspent(info).proof_size();
		let benchmarked_weight = info.total_weight().proof_size().saturating_sub(unspent);
		let consumed_weight = post_dispatch_proof_size.saturating_sub(pre_dispatch_proof_size);

		let storage_size_diff = benchmarked_weight.abs_diff(consumed_weight as u64);

		let block_size = frame_system::BlockSize::<T>::get().unwrap_or(0);
		let node_side_pov_size = post_dispatch_proof_size.saturating_add(block_size.into());

		// This value will be reclaimed by [`frame_system::CheckWeight`], so we need to calculate
		// that in.
		frame_system::BlockWeight::<T>::mutate(|current| {
			if consumed_weight > benchmarked_weight {
				log::error!(
					target: LOG_TARGET,
					"Benchmarked storage weight smaller than consumed storage weight. extrinsic: {} benchmarked: {benchmarked_weight} consumed: {consumed_weight} unspent: {unspent}",
					frame_system::Pallet::<T>::extrinsic_index().unwrap_or(0)
				);
				current.accrue(Weight::from_parts(0, storage_size_diff), info.class)
			} else {
				log::trace!(
					target: LOG_TARGET,
					"Reclaiming storage weight. extrinsic: {} benchmarked: {benchmarked_weight} consumed: {consumed_weight} unspent: {unspent}",
					frame_system::Pallet::<T>::extrinsic_index().unwrap_or(0)
				);
				current.reduce(Weight::from_parts(0, storage_size_diff), info.class)
			}

			// If we encounter a situation where the node-side proof size is already higher than
			// what we have in the runtime bookkeeping, we add the difference to the `BlockWeight`.
			// This prevents that the proof size grows faster than the runtime proof size.
			let block_weight_proof_size = current.total().proof_size();
			let missing_from_node = node_side_pov_size.saturating_sub(block_weight_proof_size);
			if missing_from_node > 0 {
				log::debug!(
					target: LOG_TARGET,
					"Node-side PoV size higher than runtime proof size weight. node-side: {node_side_pov_size} block_size: {block_size} runtime: {block_weight_proof_size}, missing: {missing_from_node}. Setting to node-side proof size."
				);
				current.accrue(Weight::from_parts(0, missing_from_node), info.class);
			}
		});
		Ok(Weight::zero())
	}

	#[test]
	fn extrinsic_already_refunded_more_precisely() {
		new_test_ext().execute_with(|| {
			// This is half of the max block weight
			let info =
				DispatchInfo { call_weight: Weight::from_parts(512, 0), ..Default::default() };
			let post_info = PostDispatchInfo {
				actual_weight: Some(Weight::from_parts(128, 0)),
				pays_fee: Default::default(),
			};
			let prior_block_weight = Weight::from_parts(64, 0);
			let accurate_refund = Weight::from_parts(510, 0);
			let len = 0_usize;
			let base_extrinsic = block_weights().get(DispatchClass::Normal).base_extrinsic;

			// Set initial info
			BlockWeight::<Test>::mutate(|current_weight| {
				current_weight.set(Weight::zero(), DispatchClass::Mandatory);
				current_weight.set(prior_block_weight, DispatchClass::Normal);
			});

			// Validate and prepare extrinsic
			let pre = CheckWeight::<Test>(PhantomData)
				.validate_and_prepare(Some(1).into(), CALL, &info, len, 0)
				.unwrap()
				.0;

			assert_eq!(
				BlockWeight::<Test>::get().total(),
				info.total_weight() + prior_block_weight + base_extrinsic
			);

			// Refund more accurately than the benchmark
			BlockWeight::<Test>::mutate(|current_weight| {
				current_weight.reduce(accurate_refund, DispatchClass::Normal);
			});
			crate::ExtrinsicWeightReclaimed::<Test>::put(accurate_refund);

			// Do the post dispatch
			assert_ok!(CheckWeight::<Test>::post_dispatch_details(
				pre,
				&info,
				&post_info,
				len,
				&Ok(())
			));

			// Ensure the accurate refund is used
			assert_eq!(crate::ExtrinsicWeightReclaimed::<Test>::get(), accurate_refund);
			assert_eq!(
				BlockWeight::<Test>::get().total(),
				info.total_weight() - accurate_refund + prior_block_weight + base_extrinsic
			);
		})
	}
