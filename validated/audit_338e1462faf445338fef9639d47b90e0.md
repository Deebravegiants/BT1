### Title
Unchecked `Ray` value growth overflows during accrual and permanently freezes a saturated market - (File: common/src/rates/simulate.rs)

### Summary
Market accrual converts scaled supply and debt into RAY-denominated principal before calculating utilization, and each multiplication can panic on `i128` overflow before the configured borrow-index cap can clamp growth. [1](#0-0) [2](#0-1) 

### Finding Description
`accrue_step` first computes `borrowed * borrow_index` and `supplied * supply_index` through `scaled_to_original`, which is implemented as the checked `Ray::mul` operation. [3](#0-2) [4](#0-3)  The borrow index is only clamped after `update_borrow_index` successfully computes the next product, so the cap does not prevent overflow while reconstructing the already-overflowing total value. [2](#0-1)  Every mutation goes through the pool cache, and `global_sync` executes this accrual before committing the market timestamp. [5](#0-4)  Once the product overflows, the transaction reverts before `mark_accrued`, leaving the same poisonous interval and market state for every later call. [6](#0-5) [7](#0-6) 

### Impact Explanation
The affected `(hub_id, asset)` market becomes unable to accrue, so operations that load the market cannot process withdrawals or repayments. [8](#0-7) [9](#0-8)  Public controller calls `withdraw`, `repay`, `liquidate`, and `update_indexes` all route into market mutation or explicit index accrual, leaving suppliers' principal and borrowers' repayment path frozen. [10](#0-9) [11](#0-10)  The repository's regression test demonstrates that after the value ceiling is reached, both `update_indexes` and subsequent `withdraw`/`repay` calls fail with `MATH_OVERFLOW` while the stored borrow index remains below `MAX_BORROW_INDEX_RAY`. [12](#0-11) 

### Likelihood Explanation
An unprivileged supplier can create the oversized scaled book through `supply`, and an unprivileged borrower can maintain high utilization through `borrow`; any caller can then invoke `update_indexes` as ledger time advances. [13](#0-12) [14](#0-13)  The trigger requires an extraordinarily large token amount and sustained high-interest utilization, so practical likelihood is low on assets whose supply and caps cannot reach the RAY-value boundary. [15](#0-14)  The impact is nevertheless permanent for any market that reaches the boundary because the state transition needed to escape it is itself unreachable. [5](#0-4) 

### Recommendation
Perform utilization and reward accounting on saturating or widened representations, or clamp scaled positions and indexes to a safe value before every `scaled_to_original` multiplication. [16](#0-15)  Ensure the borrow-index ceiling is applied before reconstruction can overflow, and add a recovery path that can commit a bounded accrual or wind down an overflowed market. [2](#0-1) 

### Proof of Concept
The existing executable regression supplies `1e18` principal units to an 18-decimal market, borrows 98% of it, repeatedly advances ledger time, and calls `update_indexes`. [17](#0-16)  Once `borrowed * borrow_index` or `supplied * supply_index` exceeds `i128::MAX`, `scaled_to_original` panics with `MATH_OVERFLOW`; the test then observes that a one-unit withdrawal and a repayment revert through the same accrual preflight. [3](#0-2) [18](#0-17)

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

```rust
/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
