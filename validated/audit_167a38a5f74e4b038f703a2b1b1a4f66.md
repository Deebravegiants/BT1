### Title
`validateDogeAddress` accepts Dogecoin addresses with a corrupted base58Check checksum, letting an uncontrollable address be signed into a withdrawal - (File: `packages/intents-sdk/src/lib/validateAddress.ts`)

### Summary
`validateDogeAddress` only checks a regex on character set/length and never decodes/verifies the base58Check checksum, unlike every other base58-based validator in the same file (BTC, Tron, Litecoin, Dash). A Dogecoin address with one mutated character (still matching the regex) is accepted by `validateAddress(address, Chains.Dogecoin)` and is embedded verbatim into the `ft_withdraw` memo used for the PoA relayer's `WITHDRAW_TO` target.

### Finding Description
The broken equality: `validateAddress(address, Chains.Dogecoin) === true` is claimed to imply "address is a valid, checksummed, spendable Dogecoin destination" — but the implementation breaks this.

`validateDogeAddress` is:
```
function validateDogeAddress(address: string) {
	return /^[DA][1-9A-HJ-NP-Za-km-z]{25,33}$/.test(address);
}
``` [1](#0-0) 

Compare this to every other base58 chain in the same file, which all decode the base58 payload and verify the double-SHA256 checksum bytes explicitly, e.g. `validateBtcBase58Address` [2](#0-1) , `validateTronBase58Address` [3](#0-2) , `validateLitecoinBase58Address` [4](#0-3) , and `validateDashAddress` [5](#0-4) . Dogecoin is the only base58-family chain missing this check.

Because a base58Check checksum is 4 bytes of double-SHA256 over 21 bytes of payload, flipping a single valid base58 character in the middle of a legitimate Dogecoin address overwhelmingly likely still (a) keeps the string inside the regex's charset/length range and (b) produces a different, essentially "random" 21-byte payload+checksum whose checksum verification would fail if actually checked — but the checksum is never checked here.

Downstream, `createWithdrawIntentPrimitive` takes `destinationAddress` (the caller-supplied string) and calls `createWithdrawMemo`, which places the raw address unchanged into the memo string as `WITHDRAW_TO:<address>`: [6](#0-5) 

There is no re-derivation or checksum re-verification at this stage — the address string that passed `validateAddress` is embedded verbatim into the memo that is signed as part of the intent and forwarded to the PoA bridge/relayer as the withdrawal target.

### Impact Explanation
An attacker (an ordinary NEAR Intents user withdrawing their own DOGE, or an integrator forwarding a user-supplied destination address) can supply a corrupted-checksum Dogecoin address that:
1. Passes SDK-side validation via `validateAddress(address, Chains.Dogecoin)`.
2. Is embedded verbatim by `createWithdrawIntentPrimitive`/`createWithdrawMemo` into the signed `ft_withdraw` intent's `memo` field as the `WITHDRAW_TO` target.
3. Is submitted to the PoA relayer, which will attempt to pay out to an address that does not decode to any real payload/checksum pairing controllable by anyone — the funds are debited on NEAR/omft side and the withdrawal cannot complete or be redirected once signed.

This matches the Critical category: "funds delivered to a wrong address/chain/contract with no recovery." Note the attacker in this specific scenario would most plausibly be harming themselves (mistyped/corrupted own destination address) unless it is a case of an integrator forwarding a counterparty-controlled `destinationAddress` string that the integrator did not manually validate beyond calling this SDK function — in which case a counterparty could intentionally submit a bad-checksum address to grief a withdrawal flow, stranding the debited funds with no on-chain recovery path through the SDK.

### Likelihood Explanation
Preconditions: The route must be Dogecoin (`nep141:doge.omft.near` or equivalent) via the PoA bridge withdrawal path, and the caller must supply a `destinationAddress` string. Attacker cost is trivial (any string satisfying the regex). This is fully repeatable per withdrawal call and requires no privileged access — any consumer of `validateAddress`/`createWithdrawIntentPrimitive`/`createWithdrawalIntents` for Dogecoin is affected. No other guard in the codebase (`compareAddresses`, `validateWithdrawal`, `supports()`, fee checks, contract-side signature/nonce checks) re-validates the base58Check checksum of the destination address; the intents contract itself only validates NEAR-side receiver_id/signature/nonce, not the external memo payload.

### Recommendation
Implement proper base58Check decoding and checksum verification for Dogecoin addresses, mirroring the pattern used for BTC/Tron/Litecoin/Dash in the same file: decode via `base58.decode`, require length 25 (version + hash160 + 4-byte checksum), validate the version byte (`0x1e` for P2PKH `D...`, `0x16` for P2SH `A...` on Dogecoin mainnet), and verify the trailing 4 bytes equal `sha256(sha256(payload)).slice(0,4)`.

### Proof of Concept
```ts
import { describe, expect, it } from "vitest";
import { base58 } from "@scure/base";
import { sha256 } from "@noble/hashes/sha2";
import { validateAddress } from "../lib/validateAddress";
import { Chains } from "../lib/caip2";
import { createWithdrawIntentPrimitive } from "../bridges/poa-bridge/poa-bridge-utils";

function buildValidDogeAddress(): string {
	// version 0x1e (D...) + 20-byte hash160 + correct checksum
	const version = 0x1e;
	const hash160 = new Uint8Array(20).fill(1);
	const payload = new Uint8Array([version, ...hash160]);
	const checksum = sha256(sha256(payload)).slice(0, 4);
	return base58.encode(new Uint8Array([...payload, ...checksum]));
}

describe("validateDogeAddress checksum bypass", () => {
	it("accepts a Dogecoin address with a mutated (invalid) checksum", () => {
		const valid = buildValidDogeAddress();

		// Flip one character in the base58 body while keeping regex charset/length valid
		const chars = valid.split("");
		const idx = 5;
		chars[idx] = chars[idx] === "z" ? "y" : "z";
		const mutated = chars.join("");

		expect(mutated).not.toBe(valid);
		// Equality claimed broken: validateAddress still returns true despite bad checksum
		expect(validateAddress(mutated, Chains.Dogecoin)).toBe(true);

		const decoded = base58.decode(mutated);
		const payload = decoded.subarray(0, 21);
		const checksum = decoded.subarray(21, 25);
		const expected = sha256(sha256(payload)).subarray(0, 4);
		expect(Array.from(checksum)).not.toEqual(Array.from(expected)); // checksum is actually invalid

		// The mutated, uncontrollable address is embedded verbatim into the signed withdrawal memo
		const result = createWithdrawIntentPrimitive({
			assetId: "nep141:doge.omft.near",
			destinationAddress: mutated,
			destinationMemo: undefined,
			amount: 1000000n,
		});
		expect(result.memo).toBe(`WITHDRAW_TO:${mutated}`);
	});
});
```

function validateBtcBase58Address(address: string): boolean {
	const decoded: Uint8Array = base58.decode(address);

	// version (1) + hash160 (20) + checksum (4) = 25 bytes
	if (decoded.length !== 25) return false;

	const version = decoded[0];
	// 0x00 = P2PKH mainnet, 0x05 = P2SH mainnet
	if (version !== 0x00 && version !== 0x05) return false;

	const payload = decoded.subarray(0, 21);
	const checksum = decoded.subarray(21, 25);
	const expectedChecksum = sha256(sha256(payload)).subarray(0, 4);

	for (let i = 0; i < 4; i++) {
		if (checksum[i] !== expectedChecksum[i]) return false;
	}
	return true;
}

function validateTronBase58Address(address: string): boolean {
	try {
		const decoded = base58.decode(address);

		if (decoded.length !== 25) return false;

		// The first 21 bytes are the address data, the last 4 bytes are the checksum.
		const data = decoded.slice(0, 21);
		const checksum = decoded.slice(21);

		const expectedChecksum = sha256(sha256(data)).slice(0, 4);
		for (let i = 0; i < 4; i++) {
			if (checksum[i] !== expectedChecksum[i]) return false;
		}

		return data[0] === 0x41;
	} catch {
		return false;
	}
}

function validateLitecoinBase58Address(
	address: string,

	let decoded: Uint8Array;

export function validateDashAddress(address: string): boolean {
	try {
		const decoded: Uint8Array = base58.decode(address);

		// version (1) + payload (20) + checksum (4)
		if (decoded.length !== 25) return false;

		const version = decoded[0];
		if (
			version !== 0x4c && // P2PKH
			version !== 0x10 // P2SH
		) {
			return false;
		}

		const payload = decoded.subarray(0, 21);
		const checksum = decoded.subarray(21, 25);

		const hash1 = sha256(payload);
		const hash2 = sha256(hash1);
		const expectedChecksum = hash2.subarray(0, 4);

		for (let i = 0; i < 4; i++) {
			if (checksum[i] !== expectedChecksum[i]) return false;
		}

		return true;
	} catch {
		return false;
	}
}

export function createWithdrawIntentPrimitive(params: {
	assetId: string;
	destinationAddress: string;
	destinationMemo: string | undefined;
	amount: bigint;
}): Extract<IntentPrimitive, { intent: "ft_withdraw" }> {
	const { contractId: tokenAccountId } = utils.parseDefuseAssetId(
		params.assetId,
	);
	return {
		intent: "ft_withdraw",
		token: tokenAccountId,
		receiver_id: tokenAccountId,
		amount: params.amount.toString(),
		memo: createWithdrawMemo({
			receiverAddress: params.destinationAddress,
			xrpMemo: params.destinationMemo,
		}),
		min_gas: MIN_GAS_AMOUNT,
	};
}

function createWithdrawMemo({
	receiverAddress,
	xrpMemo,
}: {
	receiverAddress: string;
	xrpMemo: string | undefined;
}) {
	// Strip "bitcoincash:" prefix from BCH CashAddr addresses
	const normalizedAddress = receiverAddress
		.toLowerCase()
		.startsWith("bitcoincash:")
		? receiverAddress.slice("bitcoincash:".length)
		: receiverAddress;

	const memo = ["WITHDRAW_TO", normalizedAddress];

	if (xrpMemo != null && xrpMemo !== "") {
		memo.push(xrpMemo);
	}

	return memo.join(":");
}
