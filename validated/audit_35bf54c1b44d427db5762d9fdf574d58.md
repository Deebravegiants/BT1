### Title
Unbounded, non-decaying VWAP in `VWAPOracle.spread()` lets a solver permanently skew the cross-chain price reference used by the intents pipeline - (File: evm/src/utils/VWAPOracle.sol)

### Summary
`VWAPOracle.spread()` returns an all-time cumulative volume-weighted average spread that is never bounded by time or decayed, mirroring the Olympus `OlympusPrice.v2.sol#_getCurrentPrice` bug class where a previously-computed moving-average value is fed into downstream pricing logic without any freshness check.

### Finding Description
`VWAPOracle` accumulates `weightedSpreadSum` and `totalVolume` on every `recordSpread` call and returns their ratio as the "current" spread: [1](#0-0) 

`recordSpread` is invoked once per fill by the `IntentGateway` (`restrict(_intentGateway)`), driven entirely by attacker/solver-controlled `inputs`/`outputs` amounts of a filled order: [2](#0-1) 

The struct tracks a `lastUpdate` timestamp, but it is only ever written, never read or checked anywhere in the contract: [3](#0-2) [4](#0-3) 

This is the same root cause as the referenced Olympus finding: a previously-computed aggregate (moving average / VWAP) is used as a real-time price signal without any staleness/freshness gate. Here it is worse in one respect — there is no window at all (unlike Olympus's fixed-length observation buffer), so the average is over the *entire history* of the oracle. Once `totalVolume` grows large, legitimate new fills barely move the reported spread even if the true current market spread has changed dramatically, and conversely, an early solver can seed a heavily skewed spread when `totalVolume` is still small, and that skew persists (diluting only slowly) for the life of the contract.

### Impact Explanation
`IIntentPriceOracle.spread()`/`decimals()` values are consumed by the intents-coprocessor pipeline (referenced in `modules/pallets/intents-coprocessor/src/types.rs`) as a price/spread reference for same-token cross-chain intents. Because the value is (a) attacker-fillable via ordinary order fills processed through `IntentGateway`/`recordSpread`, and (b) never checked for recency, a solver can:
- Seed a favorable/unfavorable cumulative spread early (when `totalVolume` is low) that persists and biases subsequent pricing/settlement decisions for other users' intents indefinitely.
- Rely on a value that no longer reflects current market conditions to get intents mispriced in the solver's favor, since the oracle has no mechanism to expire or decay old contributions.

This is a state/economic-integrity issue in the intents pricing pipeline reachable by any party able to get an order filled through `IntentGateway`, not a privileged-actor issue.

### Likelihood Explanation
`recordSpread` runs on the ordinary, permissionless order-fill path of `IntentGateway` — no special privileges are required to add manipulative data points, and once volume is large the design guarantees the value will not track real-time market spreads. The complete absence of any use of `lastUpdate` for staleness gating (confirmed by the file contents) makes this a straightforward, always-reachable design flaw rather than an edge case.

### Recommendation
Bound `VWAPOracle`'s average to a rolling window (e.g., decay/reset older observations, or maintain a fixed-length ring buffer of recent fills similar to `OlympusPrice.v2.sol`'s observation window) and use `lastUpdate` to reject/flag `spread()` reads when the most recent recorded fill is older than an acceptable `MAX_STALE_PERIOD`, so downstream consumers cannot act on data that no longer reflects the market.

### Proof of Concept
1. A solver fills a same-token order through `IntentGateway` with a small volume but an extreme spread (e.g., `outputAmountNormalized` far below `inputAmountNormalized`), while `totalVolume` for that (chain, token) pair is still 0, so `_updateCumulativeSpread` initializes `weightedSpreadSum`/`totalVolume` entirely from this single skewed fill (`evm/src/utils/VWAPOracle.sol:170-216, 276-281`).
2. `spread()` now permanently returns this skewed ratio for any consumer (`evm/src/utils/VWAPOracle.sol:141-147`), with no time bound — `lastUpdate` is written but never enforced.
3. Even if real market spreads normalize immediately afterward, later legitimate fills only slowly dilute the skew proportional to their volume relative to the poisoned `totalVolume`, so any pipeline (e.g., intents-coprocessor) relying on `spread()` continues to consume a stale/manipulated value for an extended, unbounded period.

        bytes32 chainHash = keccak256(sourceChain);
        CumulativeSpreadData memory data = _tokenSpreads[chainHash][token];
        if (data.totalVolume == 0) return 0;

        return data.weightedSpreadSum / int256(data.totalVolume);
    }

```text
    function recordSpread(
        bytes32 commitment,
        bytes memory sourceChain,
        TokenInfo[] calldata inputs,
        TokenInfo[] calldata outputs
    ) external restrict(_intentGateway) {
        // Validate inputs and outputs have the same length
        if (inputs.length != outputs.length || inputs.length == 0) {
            return;
        }

        bytes32 sourceChainHash = keccak256(sourceChain);
        uint256 tokensLen = inputs.length;
        for (uint256 i = 0; i < tokensLen; i++) {
            address inputToken = address(uint160(uint256(inputs[i].token)));
            address outputToken = address(uint160(uint256(outputs[i].token)));

            // Get decimals for input token from storage (remote chain)
            // Native tokens (address(0)) use 18 decimals
            uint8 inputDecimals = inputToken == address(0) ? 18 : _tokenDecimals[sourceChainHash][inputToken];
            if (inputDecimals == 0) continue; // Skip if decimals not configured

            // Get decimals for output token directly from contract (local chain)
            // Native tokens (address(0)) use 18 decimals
            uint8 outputDecimals = outputToken == address(0) ? 18 : IERC20Metadata(outputToken).decimals();

            // Normalize both amounts to 18 decimals for comparison
            uint256 inputAmountNormalized = _normalizeAmount(inputs[i].amount, inputDecimals);
            uint256 outputAmountNormalized = _normalizeAmount(outputs[i].amount, outputDecimals);

            // Calculate spread for this token: (output - input) / input * 10000
            // Positive spread = filler provided more tokens (good for user)
            // Negative spread = filler provided fewer tokens (filler captured spread)
            int256 spreadBps = 0;
            if (inputAmountNormalized > 0) {
                int256 amountDiff = int256(outputAmountNormalized) - int256(inputAmountNormalized);
                spreadBps = (amountDiff * int256(BPS_DENOMINATOR)) / int256(inputAmountNormalized);
            }

            // Update cumulative spread data for this token (weighted by volume)
            int256 weightedSpread = spreadBps * int256(inputAmountNormalized);
            _updateCumulativeSpread(_tokenSpreads[sourceChainHash][inputToken], weightedSpread, inputAmountNormalized);

            // Emit event for each token
            emit SpreadRecorded(commitment, outputToken, spreadBps);
        }
    }
```

    function _updateCumulativeSpread(CumulativeSpreadData storage data, int256 weightedSpread, uint256 volume) private {
        data.weightedSpreadSum += weightedSpread;
        data.totalVolume += volume;
        data.fillCount += 1;
        data.lastUpdate = block.timestamp;
    }
