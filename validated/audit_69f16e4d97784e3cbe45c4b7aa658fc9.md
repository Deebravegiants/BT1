### Title
`validateDogeAddress` skips base58Check checksum verification, allowing corrupted Dogecoin addresses to pass `PoaBridge.validateWithdrawal` and be embedded in the withdrawal memo - (File: `packages/intents-sdk/src/lib/validateAddress.ts`)

### Summary
`validateDogeAddress` only checks a regex pattern on character set/length and never decodes the base58 payload or verifies its double-SHA256 checksum, unlike every other base58Check-based validator in the same file (Bitcoin, Litecoin, Tron, Dash). This lets a caller submit a `D`/`A`-prefixed string with a corrupted checksum through `PoaBridge.validateWithdrawal`, which is then embedded verbatim into the `WITHDRAW_TO:<address>` memo sent on-chain.

### Finding Description
The claimed equality is: *the address encoded in the `WITHDRAW_TO:<address>` memo == an address capable of actually receiving funds on Dogecoin*.

`validateDogeAddress` is implemented as:
```
function validateDogeAddress(address: string) {
	return /^[DA][1-9A-HJ-NP-Za-km-z]{25,33}$/.test(address);
}
``` [1](#0-0) 

This is purely a character-class/length check with zero base58 decoding and zero checksum verification. Contrast this with the sibling validators in the same file that all decode the base58 payload and verify the trailing 4-byte double-SHA256 checksum before returning `true`, e.g. `validateBtcBase58Address` [2](#0-1) , `validateTronBase58Address` [3](#0-2) , `validateLitecoinBase58Address` [4](#0-3) , and `validateDashAddress` [5](#0-4) . Dogecoin's real address encoding is identical in structure (version byte + hash160 + 4-byte checksum, base58-encoded) but this checksum step is simply omitted for Doge.

`PoaBridge.validateWithdrawal` calls `validateAddress(args.destinationAddress, assetInfo.blockchain)` and only throws `InvalidDestinationAddressForWithdrawalError` if it returns `false`:
```
if (
    validateAddress(args.destinationAddress, assetInfo.blockchain) === false
) {
    throw new InvalidDestinationAddressForWithdrawalError(...);
}
``` [6](#0-5) 
No subsequent check re-verifies the address's cryptographic validity; the next checks are only about the token's own origin address (`compareAddresses`) and min-amount / XRPL-specific checks [7](#0-6) , none of which re-derive or checksum-verify a Doge address.

Once accepted, `createWithdrawalIntents` calls `createWithdrawIntentPrimitive`, which embeds the destination address verbatim into the intent memo via `createWithdrawMemo`:
```
const memo = ["WITHDRAW_TO", normalizedAddress];
...
return memo.join(":");
``` [8](#0-7) 
No re-validation or checksum check occurs at this stage — the string that passed the regex-only check flows straight into the signed intent's `memo` field, which the relayer's PoA bridge solver later parses to determine the payout destination.

**Exploit flow**: an unprivileged caller picks any 25–34 character base58 string starting with `D` (or `A`) satisfying the regex — trivial to construct by taking a valid Doge address and flipping one character in the last 4 checksum bytes, or by simply mistyping/truncating an address — and calls `createWithdrawalIntents`/`validateWithdrawal` with `assetId: "nep141:doge.omft.near"`. `validateAddress` returns `true` despite the checksum being wrong, so the string is accepted and signed into the intent's memo as the withdrawal destination.

Existing guards do not catch this: `validateWithdrawal`'s only address check is `validateAddress` itself (the vulnerable function); `compareAddresses` only compares the supplied destination against the token's own `origin_chain_address` and does not validate the destination's own checksum; there is no additional Dogecoin-specific checksum verification anywhere else in `poa-bridge.ts` or `poa-bridge-utils.ts`.

### Impact Explanation
Funds are debited from the user's balance and a `ft_withdraw` intent with `memo: "WITHDRAW_TO:<corrupted-address>"` is signed and submitted, instructing the PoA bridge solver to send Dogecoin to a destination that fails checksum verification and therefore cannot be spent/delivered by any standard Dogecoin wallet or node — this is a funds-delivered-to-wrong/invalid-destination scenario with no on-SDK recovery path, matching the Critical category ("funds delivered to a wrong address/chain/contract with no recovery"). This can be triggered repeatably on every Dogecoin withdrawal call by any user of the SDK, including via typos, not just deliberate attacks.

### Likelihood Explanation
Precondition is simply using the `nep141:doge.omft.near` PoA route, which is a standard supported asset/route in the SDK. The attacker/user needs no privilege beyond calling public SDK withdrawal methods with their own funds; constructing a checksum-invalid but regex-matching string costs nothing (flip one character of a real address, or a common fat-fingered address). Because the check is entirely client-side format validation with no cryptographic verification, this is 100% reproducible every time, and also occurs accidentally in real-world typo scenarios given the size of the affected class of inputs.

### Recommendation
Implement full base58Check decoding and double-SHA256 checksum verification in `validateDogeAddress`, mirroring `validateBtcBase58Address`/`validateLitecoinBase58Address`/`validateDashAddress`: decode the base58 string, require length 25 (or the appropriate P2PKH/P2SH length), validate the version byte(s) against Dogecoin mainnet values (`0x1e` for P2PKH, `0x16` for P2SH), and verify the last 4 bytes match `sha256(sha256(payload)).slice(0,4)`.

import { describe, it, expect } from "vitest";
import { base58 } from "@scure/base";
import { sha256 } from "@noble/hashes/sha2";
import { validateAddress } from "../src/lib/validateAddress";
import { Chains } from "../src/lib/caip2";
import { createWithdrawIntentPrimitive } from "../src/bridges/poa-bridge/poa-bridge-utils";

function buildCorruptedDogeAddress(): string {
  // version 0x1e (Doge P2PKH) + 20-byte payload
  const version = 0x1e;
  const hash160 = new Uint8Array(20).fill(1);
  const payload = new Uint8Array([version, ...hash160]);
  const checksum = sha256(sha256(payload)).slice(0, 4);
  // Corrupt one checksum byte
  const corruptedChecksum = new Uint8Array(checksum);
  corruptedChecksum[0] ^= 0xff;
  const full = new Uint8Array([...payload, ...corruptedChecksum]);
  return base58.encode(full); // starts with 'D', correct length, wrong checksum
}

describe("validateDogeAddress checksum bypass", () => {
  it("accepts a checksum-invalid Dogecoin address and embeds it in the memo", () => {
    const badAddress = buildCorruptedDogeAddress();

    // Left side of equality: SDK claims this is a valid Dogecoin address
    expect(validateAddress(badAddress, Chains.Dogecoin)).toBe(true);

    // Right side of equality: address is NOT actually spendable (checksum invalid)
    const decoded = base58.decode(badAddress);
    const payload = decoded.subarray(0, 21);
    const checksum = decoded.subarray(21, 25);
    const expectedChecksum = sha256(sha256(payload)).subarray(0, 4);
    const isRealAddress = checksum.every((b, i) => b === expectedChecksum[i]);
    expect(isRealAddress).toBe(false); // proves equality is broken

    // The corrupted address still flows into the signed intent memo
    const intent = createWithdrawIntentPrimitive({
      assetId: "nep141:doge.omft.near",
      destinationAddress: badAddress,
      destinationMemo: undefined,
      amount: 1000000n,
    });
    expect(intent.memo).toBe(`WITHDRAW_TO:${badAddress}`);
  });
});
```

function validateBtcBase58Address(address: string): boolean {
	const decoded: Uint8Array = base58.decode(address);

	// version (1) + hash160 (20) + checksum (4) = 25 bytes
	if (decoded.length !== 25) return false;

	const version = decoded[0];
	// 0x00 = P2PKH mainnet, 0x05 = P2SH mainnet
	if (version !== 0x00 && version !== 0x05) return false;

	const payload = decoded.subarray(0, 21);
	const checksum = decoded.subarray(21, 25);
	const expectedChecksum = sha256(sha256(payload)).subarray(0, 4);

	for (let i = 0; i < 4; i++) {
		if (checksum[i] !== expectedChecksum[i]) return false;
	}
	return true;
}

function validateTronBase58Address(address: string): boolean {
	try {
		const decoded = base58.decode(address);

		if (decoded.length !== 25) return false;

		// The first 21 bytes are the address data, the last 4 bytes are the checksum.
		const data = decoded.slice(0, 21);
		const checksum = decoded.slice(21);

		const expectedChecksum = sha256(sha256(data)).slice(0, 4);
		for (let i = 0; i < 4; i++) {
			if (checksum[i] !== expectedChecksum[i]) return false;
		}

		return data[0] === 0x41;
	} catch {
		return false;
	}
}

function createWithdrawMemo({
	receiverAddress,
	xrpMemo,
}: {
	receiverAddress: string;
	xrpMemo: string | undefined;
}) {
	// Strip "bitcoincash:" prefix from BCH CashAddr addresses
	const normalizedAddress = receiverAddress
		.toLowerCase()
		.startsWith("bitcoincash:")
		? receiverAddress.slice("bitcoincash:".length)
		: receiverAddress;

	const memo = ["WITHDRAW_TO", normalizedAddress];

	if (xrpMemo != null && xrpMemo !== "") {
		memo.push(xrpMemo);
	}

	return memo.join(":");
}
