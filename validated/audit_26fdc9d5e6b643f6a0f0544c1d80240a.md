### Title
Stale `account.owner` lets a former NFT holder retain borrow/withdraw authority after transferring the position NFT - (File: contracts/controller/src/account.rs)

### Summary
Authorization for every account-spending entrypoint (`borrow`, `withdraw`, `multiply`, `flash_position`, `swap_debt`, `swap_collateral`, `repay_debt_with_collateral`, `migrate_from_blend`, and `SeizeMode::Credit` receivers) is enforced by `require_owner_or_delegate`, which compares the caller to `account.owner` — a field written once at account creation inside `create_account_with`. The canonical owner, however, lives in the position-nft contract and is read separately by `require_account_owner` via `storage::account_owner`. Because position-nft `transfer`/`transfer_from` are stock OpenZeppelin methods with no controller callback, the stored `Account.owner` is never restamped when the NFT changes hands. The old owner therefore keeps full spending authority over an account it no longer owns, while the new NFT holder is rejected — an authorization check enforced against a non-canonical identity that a differently-constructed path (NFT transfer) bypasses, directly analogous to the Zuul sensitive-headers bypass where a restriction bound to one request representation fails to bind the canonical one.

### Finding Description
`create_account_with` persists `Account { owner: caller, .. }` at mint time (account.rs:64-70). `require_owner_or_delegate` admits `caller == account.owner` (account.rs:121) and delegates listed under that stored owner key (account.rs:126). In contrast, `require_account_owner` re-reads the live NFT owner via `storage::account_owner` (account.rs:144-146) — used only for `renew_account`, `add_delegate`, `remove_delegate`. The very existence of two owner sources confirms `account.owner` is a cached copy, not a live view. `position-nft::transfer` (permissionless_entrypoints.txt:111-113) is stock OZ code that moves the NFT without notifying the controller, so `Account.owner` is never updated. After a transfer, `is_owner_or_delegate` still authenticates the seller (`caller == stale owner`) and the seller's previously granted delegates (grants are keyed `(account_id, stored_owner)`), while the buyer fails `caller == account.owner` everywhere except the three owner-only functions that read the NFT.

### Impact Explanation
Theft of user funds / insolvency. An attacker sells or transfers an account NFT (e.g., via `transfer_from` to a buyer paying for the collateral), then — still authenticating as `account.owner` — calls `withdraw` draining all collateral to `to = attacker`, or `borrow` drawing maximum debt against the buyer's collateral before dumping the NFT. The buyer receives an NFT that authorizes nothing except `renew_account`/`add_delegate`/`remove_delegate`. Any account ever transferred on a secondary market is fully drainable by its original creator.

### Likelihood Explanation
Requires only that an account NFT changes hands — the intended, documented use of the position NFT. No privileges, no oracle manipulation, no timing constraint; the stale authority persists indefinitely after transfer. The attacker is the unprivileged seller.

### Recommendation
Derive spending authority from the live NFT owner everywhere: replace `account.owner` reads in `is_owner_or_delegate`/`require_owner_or_delegate` with `storage::account_owner(env, account_id)` (as `require_account_owner` already does), or restamp `Account.owner` inside `load_or_create_account`/`storage::get_account` from the NFT on every read.

### Proof of Concept
1. Alice calls `supply(account_id=0, spoke, [payment])`; `create_account` mints NFT id N and stores `Account.owner = Alice`.
2. Alice supplies collateral and optionally grants a delegate via `add_delegate`.
3. Alice calls `position-nft::transfer(Alice, Bob, N)` — stock OZ path, no controller hook; `Account.owner` remains `Alice`.
4. Bob calls `withdraw(N, ...)` → `require_owner_or_delegate` compares Bob to stored owner Alice → `NotAuthorized`. Bob cannot touch his own collateral.
5. Alice calls `withdraw(account_id=N, withdrawals=[(hub_asset, 0)], to=Some(Alice))` → `caller == account.owner` passes, `require_external_recipient` passes on Alice, all collateral paid out to Alice.
6. Alternatively Alice calls `borrow` to the account's debt ceiling, leaving Bob's NFT backing bad debt.

Key code: `Account.owner` fixed at creation, `contracts/controller/src/account.rs:64-70`; auth on stored owner, `account.rs:121`; delegate lookup keyed to stored owner, `account.rs:126`; separate live-owner read proving the divergence, `account.rs:144-146`; NFT transfer lacking a controller restamp hook, `scripts/permissionless_entrypoints.txt:111-113`.

Note on uncertainty: this finding hinges on `storage::account_owner` reading the NFT contract's owner live rather than a mirrored controller copy — inferred from `require_account_owner` existing as a distinct, stricter check and from the documented "delegate grants go inactive on transfer" design. If `storage::get_account` restamps `owner` from the NFT on load (not visible in the reviewed lines), the bug collapses to a permanent denial-of-service for buyers rather than seller-side theft.
