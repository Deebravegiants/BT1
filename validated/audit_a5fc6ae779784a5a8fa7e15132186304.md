Based on my analysis of `do_place_order` in `polkadot/runtime/parachains/src/on_demand/mod.rs`, there is no validation that `para_id` corresponds to a registered/on-demand-eligible parachain or parathread.

### Title
Missing ParaId validity check in `do_place_order` allows queue/spot-price manipulation via orders for unschedulable parachains - (File: polkadot/runtime/parachains/src/on_demand/mod.rs)

### Summary
`Pallet::do_place_order` (used by `place_order_with_credits`, `place_order_allow_death`, `place_order_keep_alive`) never checks whether the supplied `para_id` is a registered parachain/parathread capable of being assigned a core. An attacker with credits (or balance) can repeatedly enqueue orders for a bogus/never-serviced `ParaId`, inflating `queue.len()` and thus `traffic`/`spot_price` for all users of the shared queue via `calculate_spot_traffic`.

### Finding Description
In `do_place_order` (lines 471-558), the only checks performed before pushing an order are: (1) `spot_price <= max_amount` (line 490), (2) queue not full (line 492-496), and (3) sufficient credits/balance (lines 517-529 for the `Credits` branch). There is no call to `paras::Pallet::<T>` to verify `para_id` is a live parachain or parathread, and `polkadot_primitives::Id` (`ParaId`) is a bare `u32` wrapper that can be constructed to any arbitrary value by the caller. [1](#0-0) [2](#0-1) 

Once accepted, the order is pushed into `OrderStatus.queue` via `try_push` (line 547), which only enforces the bounded capacity, not para validity. `queue.len()` is then fed directly into `calculate_spot_traffic` on every block via `update_spot_traffic` (called both in `on_initialize` and at the top of `do_place_order`), raising `traffic` (and thus `spot_price` for every subsequent orderer, regardless of which para they order for) whenever queue utilization exceeds `on_demand_target_queue_utilization`. [3](#0-2) [4](#0-3) 

`pop_assignment_for_cores` (lines 108-131), which is what removes entries from the queue, also performs no validity check on `para_id` — it just dequeues distinct `para_id`s once `ready_at <= now` up to `num_cores`. If the bogus `para_id` is never actually scheduled onto a real core downstream (I was not able to fully trace whether the scheduler/assignment provider filters out unregistered paras before consuming a core slot, since that logic lives in `scheduler/assigner_coretime` which I could not fully inspect in this pass), the order for the fake para will either (a) sit in the queue keeping `queue_size` inflated until it ages out or is popped, or (b) be popped and silently discarded downstream while still having incremented traffic while queued. Either way, the credits/balance are consumed at `do_place_order` time regardless of eventual servicing — there is no refund path if the para never gets a core. [5](#0-4) 

### Impact Explanation
An attacker can burn their own credits placing orders for an unschedulable `ParaId` while contributing to `queue.len()`, which inflates `traffic` via `calculate_spot_traffic` and raises `spot_price` for all legitimate on-demand orderers sharing the same single global queue (there is one `OrderStatus` queue for the whole runtime, not per-para). This is a fee-market manipulation/griefing vector: honest users ordering blockspace for real, schedulable parachains pay an inflated price purely because of noise orders for a para that will never consume a core. The attacker's own cost is bounded by their credit grant, but the effect on other users' pricing is not bounded by that grant, since `spot_price` is a *global* multiplier applied to `on_demand_base_fee`.

### Likelihood Explanation
Preconditions are low-bar: any account holding on-demand credits (from any legitimate credit source, e.g. `credit_account`) or even just a funded balance account (via the deprecated `place_order_allow_death`/`place_order_keep_alive` calls) can call these extrinsics directly and repeatably — `para_id` is a plain user-supplied `u32`-wrapped value with no registration check. This is fully reachable via a normal signed extrinsic, requires no special origin, and can be repeated every block subject only to queue capacity (`on_demand_queue_max_size`) and available credits/balance.

### Recommendation
Add a validity check in `do_place_order` (or as an `ensure!` guard before the payment/queue-push logic) that `para_id` is a currently registered parachain or parathread (e.g., via `paras::Pallet::<T>::is_valid_para(para_id)` or equivalent lifecycle check), returning a new error (e.g. `Error::<T>::InvalidParaId`) if not. This prevents non-existent/unschedulable `ParaId`s from ever entering the shared queue and affecting `traffic`/`spot_price` calculations.

### Proof of Concept
Rust integration test in `polkadot/runtime/parachains/src/on_demand/tests.rs`:
1. Set up mock runtime state with no para registered for `ParaId::from(9999)` (never call `paras::Pallet::<T>` registration/onboarding for it).
2. Call `Pallet::<T>::credit_account(attacker, large_amount)`.
3. Repeatedly call `OnDemand::place_order_with_credits(RuntimeOrigin::signed(attacker), max_amount, ParaId::from(9999))` across several blocks, advancing `on_initialize` between calls.
4. Assert each call succeeds (`Ok(())`) despite `ParaId::from(9999)` never being a registered para, and assert `Credits::<T>::get(attacker)` decreases each time.
5. Assert `SpotPriceSet` events show monotonically increasing `spot_price` as `queue.len()` grows past `on_demand_target_queue_utilization`.
6. In parallel, have a second honest account place an order for a real, registered `ParaId`; assert it now pays the same inflated `spot_price` caused purely by the attacker's bogus-para orders, confirming cross-user griefing.

impl<N> OrderQueue<N> {
	/// Pop `num_cores` from the queue, assuming `now` as the current block number.
	pub fn pop_assignment_for_cores<T: Config>(
		&mut self,
		now: N,
		mut num_cores: u32,
	) -> impl Iterator<Item = ParaId>
	where
		N: Saturating + Ord + One + Copy,
	{
		let mut popped = BTreeSet::new();
		let mut remaining_orders = Vec::with_capacity(self.queue.len());
		for order in mem::take(&mut self.queue) {
			// Order is ready 2 blocks later (asynchronous backing):
			let ready_at = order.ordered_at.saturating_plus_one().saturating_plus_one();
			let is_ready = ready_at <= now;

			if num_cores > 0 && is_ready && popped.insert(order.para_id) {
				num_cores -= 1;
			} else {
				remaining_orders.push(order);
			}
		}
		self.queue = BoundedVec::truncate_from(remaining_orders);
		popped.into_iter()
	}

	/// Calculate and update spot traffic.
	fn update_spot_traffic(
		config: &configuration::HostConfiguration<BlockNumberFor<T>>,
		order_status: &mut OrderStatus<BlockNumberFor<T>>,
	) {
		let old_traffic = order_status.traffic;
		match Self::calculate_spot_traffic(
			old_traffic,
			config.scheduler_params.on_demand_queue_max_size,
			order_status.queue.len() as u32,
			config.scheduler_params.on_demand_target_queue_utilization,
			config.scheduler_params.on_demand_fee_variability,
		) {
			Ok(new_traffic) => {
				// Only update storage on change
				if new_traffic != old_traffic {
					order_status.traffic = new_traffic;

					// calculate the new spot price
					let spot_price: BalanceOf<T> = new_traffic.saturating_mul_int(
						config.scheduler_params.on_demand_base_fee.saturated_into::<BalanceOf<T>>(),
					);

					// emit the event for updated new price
					Pallet::<T>::deposit_event(Event::<T>::SpotPriceSet { spot_price });
				}
			},
			Err(err) => {
				log::debug!(
					target: LOG_TARGET,
					"Error calculating spot traffic: {:?}", err
				);
			},
		};
	}

	fn calculate_spot_traffic(
		traffic: FixedU128,
		queue_capacity: u32,
		queue_size: u32,
		target_queue_utilisation: Perbill,
		variability: Perbill,
	) -> Result<FixedU128, SpotTrafficCalculationErr> {
		// Return early if queue has no capacity.
		if queue_capacity == 0 {
			return Err(SpotTrafficCalculationErr::QueueCapacityIsZero);
		}

		// Return early if queue size is greater than capacity.
		if queue_size > queue_capacity {
			return Err(SpotTrafficCalculationErr::QueueSizeLargerThanCapacity);
		}

		// (queue_size / queue_capacity) - target_queue_utilisation
		let queue_util_ratio = FixedU128::from_rational(queue_size.into(), queue_capacity.into());
		let positive = queue_util_ratio >= target_queue_utilisation.into();
		let queue_util_diff = queue_util_ratio.max(target_queue_utilisation.into()) -
			queue_util_ratio.min(target_queue_utilisation.into());

		// variability * queue_util_diff
		let var_times_qud = queue_util_diff.saturating_mul(variability.into());

		// variability^2 * queue_util_diff^2
		let var_times_qud_pow = var_times_qud.saturating_mul(var_times_qud);

		// (variability^2 * queue_util_diff^2)/2
		let div_by_two: FixedU128;
		match var_times_qud_pow.const_checked_div(2.into()) {
			Some(dbt) => div_by_two = dbt,
			None => return Err(SpotTrafficCalculationErr::Division),
		}

		// traffic * (1 + queue_util_diff) + div_by_two
		if positive {
			let new_traffic = queue_util_diff
				.saturating_add(div_by_two)
				.saturating_add(One::one())
				.saturating_mul(traffic);
			Ok(new_traffic.max(<T as Config>::TrafficDefaultValue::get()))
		} else {
			let new_traffic = queue_util_diff.saturating_sub(div_by_two).saturating_mul(traffic);
			Ok(new_traffic.max(<T as Config>::TrafficDefaultValue::get()))
		}
	}
