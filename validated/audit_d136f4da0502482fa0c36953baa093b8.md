The user is reporting a vulnerability in the `PaprController.sol` contract where disabled collateral can still be used to mint debt. The core issue is that the `_increaseDebt` function does not check if the collateral is allowed, unlike the `_addCollateralToVault` function. This allows a user to add collateral, then have it disabled by the owner, and still mint debt against it.

### Disabled Collateral Can Be Used to Mint Debt - ()

### Finding Description
The `PaprController.sol` contract, specifically the `_increaseDebt` function, lacks a check to ensure that the collateral being used to mint debt is currently allowed. While the `_addCollateralToVault` function correctly verifies the `isAllowed` status of collateral, this check is absent in the debt minting process. This oversight permits users to mint new debt against collateral that has been explicitly disabled by the contract owner. 

### Impact Explanation
The impact of this vulnerability is that disabled collateral can still be used to mint debt. This can lead to protocol insolvency or bad debt if the value of the disabled collateral significantly drops or becomes unrecoverable, as the protocol would be backing debt with assets it no longer considers valid. 

### Likelihood Explanation
The likelihood of this vulnerability being exploited is high because it can be triggered by an unprivileged user. An attacker can add collateral, wait for it to be disabled by the owner (a routine operation), and then proceed to mint debt against it. The external report provides a proof of concept demonstrating this exact scenario. 

### Recommendation
It is recommended to add a check within the `_increaseDebt` function to verify that the collateral is allowed before minting new debt. This check should be similar to the one present in the `_addCollateralToVault` function. 

### Proof of Concept
The following steps demonstrate the vulnerability:
1. A user (borrower) adds collateral to their vault using `controller.addCollateral()`.
2. The contract owner then calls `controller.setAllowedCollateral()` to disable the previously added collateral by setting its `allowed` status to `false`.
3. Despite the collateral being disabled, the borrower can still successfully call `controller.increaseDebt()` to mint new debt against this disabled collateral.
4. The provided test `testIncreaseDebt_POC()` in `increaseDebt.t.sol` confirms this behavior, as it passes when it should have reverted.
