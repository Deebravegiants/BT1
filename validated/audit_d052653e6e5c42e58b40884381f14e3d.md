Audit Report

## Title
CORS Origin Allowlist Bypass via Unanchored Suffix Matching in Gateway HTTP Server - (File: `core/services/gateway/network/httpserver.go`)

## Summary
`isAllowedOrigin` implements wildcard host matching using `strings.HasSuffix(originHost, allowedHost)` after stripping the `*.` prefix, without verifying that a `.` label boundary precedes the matched suffix. This allows any registrable domain that merely ends with the trusted suffix string (e.g. `myethereum.org` against configured `*.ethereum.org`) to be treated as a trusted subdomain.

## Finding Description
The wildcard-matching branch at [1](#0-0)  strips the `*.` prefix from the configured allowed origin to get `allowedHost` (e.g., `ethereum.org`) and then performs a raw suffix comparison `strings.HasSuffix(originHost, allowedHost)`. This has no dot-boundary check, so `strings.HasSuffix("myethereum.org", "ethereum.org")` evaluates to `true` even though `myethereum.org` is an entirely separate, independently registrable domain and not a subdomain of `ethereum.org`.

This function is the sole gate for setting `Access-Control-Allow-Origin` to the caller-supplied `Origin` header value in `handleRequest`, at [2](#0-1) . There is no other origin validation, redaction, or additional boundary check performed before reflecting the origin into the CORS response header — the existing exact-match check (`originHost == allowedHost`) and scheme/port checks at lines 172-183 do not compensate for the unanchored suffix bug in the wildcard branch.

The existing test suite exercises negative cases only where the extra host segment is separated by a dot (`ethereum.remix.org` vs `*.ethereum.org`), which correctly fails, but never tests the no-dot-boundary concatenation case (`myethereum.org` vs `*.ethereum.org`), so the bug is untested and unnoticed.

## Impact Explanation
An operator who configures a wildcard CORS allowed origin (a supported, documented configuration pattern) inadvertently trusts any domain ending in that suffix string, not just true subdomains. An attacker who registers such a domain (e.g., `myethereum.org` when `*.ethereum.org` is configured) can host a malicious webpage there; when a victim's browser sends a request to the gateway with that `Origin`, the gateway reflects it back in `Access-Control-Allow-Origin`, allowing the attacker's page to make authenticated cross-origin requests to the gateway on behalf of the victim's browser session. This is a concrete CORS/allowlist bypass weakening the origin isolation boundary intended to restrict which web frontends may interact with the gateway API, matching the gateway request impersonation / allowlist bypass impact category.

## Likelihood Explanation
The bug is deterministic and code-based (not a race condition or dependent on unusual host state) — it triggers on any request with an `Origin` header value that string-ends-with a configured wildcard suffix. It requires the operator to have configured a wildcard `CORSAllowedOrigins` entry, which is a normal, documented, supported configuration path rather than a misconfiguration outside intended use. Registering a domain that happens to end in a trusted suffix (e.g., `myethereum.org`) is a low-cost, realistic action for an attacker. No special privilege, credential, or host access is needed by the attacker — only that a victim browser visits the attacker's page and it issues a cross-origin request to the gateway.

## Recommendation
Enforce a dot-boundary check in the wildcard-match branch so `originHost` must either exactly equal the base domain or end with `"." + baseDomain`, e.g.:
```go
if strings.HasPrefix(allowedHost, "*.") {
    base := allowedHost[2:]
    if originHost == base || strings.HasSuffix(originHost, "."+base) {
        return true
    }
}
```

## Proof of Concept
1. Configure the gateway with `CORSAllowedOrigins = ["https://*.ethereum.org"]` and `CORSEnabled = true`.
2. Send an HTTP request to the gateway's request-handling endpoint with header `Origin: https://myethereum.org`.
3. In `isAllowedOrigin`, `allowedHost` becomes `ethereum.org` after stripping `*.`; `strings.HasSuffix("myethereum.org", "ethereum.org")` returns `true`, so the function returns `true`.
4. `handleRequest` sets `Access-Control-Allow-Origin: https://myethereum.org` in the response, confirming the unrelated domain is incorrectly treated as trusted — verifiable as a Go unit test analogous to `TestHTTPServer_HandleRequest_CORSEnabled_FromNotAllowedOriginWildcards` at [3](#0-2)  but asserting the header IS set for `https://myethereum.org`, which would currently fail the intended security property.
