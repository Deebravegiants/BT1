### Title
Zero On-Chain Relayer Incentive for Permissionless `triggerGraduation`/`finalizeGraduation` Can Permanently Freeze Curve Trading and Parked Graduation Funds - ([File: packages/contracts/src/Bonding.sol])

### Summary
The external report flags that a fixed relayer fee can fall below actual gas cost, discouraging anyone from calling the incentivized function and degrading protocol usability. alt.fun's two-phase graduation flow reproduces this exact failure mode in its most severe form: `Bonding.triggerGraduation` and `Bonding.finalizeGraduation` are permissionless functions that *must* be called by someone to unstick the curve, yet they pay the caller **nothing** — no fee, no fee-vault split, no gas rebate. The design relies entirely on an off-chain "Cloudflare Worker keeper" as the sole economic actor, exactly the "out of band incentive" pattern OpenZeppelin's `ERC2771Forwarder` docs warn is fragile if that off-chain incentive disappears or gas costs rise.

### Finding Description
`triggerGraduation` is the documented permissionless escape hatch for the case where `canGraduate` flips true via LT price appreciation alone (no buy in the loop), because a closing buy on the curve can revert below BounceTech's LT mint floor [1](#0-0) . Once `canGraduate(tokenAddress)` is true, `Bonding.sell` unconditionally reverts with `TokenIsGraduating` regardless of whether anyone has actually called `triggerGraduation` yet [2](#0-1) , so every holder is locked out of selling from the moment the threshold is crossed.

`finalizeGraduation` (phase 2) is likewise permissionless — "anyone can call to rescue a stuck token" per the project's own documentation — but requires ~2.5M gas on a HyperEVM "big block," landing the curve-raised LT (`p.ltFromPair`) and the 250M `LP_RESERVE` tokens parked on `Bonding` until someone pays that gas [3](#0-2) . The AGENTS.md documentation explicitly states this is designed around an off-chain keeper: "A Cloudflare Worker keeper handles the happy path; anyone can call to rescue a stuck token" [4](#0-3) .

Neither `triggerGraduation` nor `finalizeGraduation` pays the caller any portion of the swept LT, the fee vault, or any bounty — `_sweepLTToOwner` sends any surplus LT to `owner()`, not the caller [5](#0-4) . This is the same bug class as the external report's "Constant Fee for Relayer," pushed to its extreme: the constant fee is fixed at **zero**. Any unprivileged wallet is technically able to call these functions, but has no rational economic reason to pay real gas for zero return once the off-chain keeper Worker is down, misconfigured, or simply outbid by rising HyperEVM gas prices for the big-block lane that phase 2 requires.

### Impact Explanation
If gas costs make it unprofitable for the off-chain keeper (or any volunteer) to call `triggerGraduation`/`finalizeGraduation`, a token can become permanently stuck: sellers are frozen out via the unconditional `TokenIsGraduating`/`canGraduate` check in `sell`, and the curve-raised LT plus 250M reserved tokens remain parked in `Bonding` indefinitely with no path to the HyperSwap LP. This matches the accepted impact criteria of "permanent freezing of trader, creator, or LP funds," and directly matches the report-cited in-scope shape "a permissionless two-phase graduation that parks all curve-raised LT and 250M tokens on Bonding between phases."

### Likelihood Explanation
The keeper is a single off-chain Cloudflare Worker with no on-chain fallback incentive; the protocol's own documentation treats "anyone can call to rescue" as the only guarantee against permanent bricking, but that guarantee is only credible if some economic actor is willing to eat ~2.5M gas of cost with zero payout. Any period of elevated HyperEVM gas prices, keeper downtime/misconfiguration, or an attacker deliberately congesting the "big block" lane makes this a realistic and low-cost griefing/DoS vector, consistent with Medium risk as rated in the analogous report.

### Recommendation
Introduce an on-chain relayer/keeper incentive for `triggerGraduation` and `finalizeGraduation` — e.g., skim a small, capped bounty (in LT or from the protocol fee share) to `msg.sender` on successful call, or make the bounty dynamically scale with `tx.gasprice`/`block.basefee` so it never falls below the caller's real cost, removing sole reliance on an off-chain, unincentivized keeper.

### Proof of Concept
1. A token's curve crosses `canGraduate` via LT exchange-rate appreciation alone (`lt.setExchangeRate(...)`), as in `test_canGraduate_returnsTrueWhenThresholdMet` [6](#0-5) .
2. From this point, any holder's `Bonding.sell` call reverts with `TokenIsGraduating` even though nobody has called `triggerGraduation` yet [2](#0-1) .
3. Assume the Cloudflare Worker keeper is offline or HyperEVM big-block gas is elevated. No unprivileged wallet has an economic reason to pay for `triggerGraduation` (confirmed permissionless but zero-reward in `test_triggerGraduation_isPermissionless` [7](#0-6) ) or the ~2.5M-gas `finalizeGraduation` [8](#0-7) .
4. The token remains stuck: sells are frozen, curve-raised LT and the 250M `LP_RESERVE` tokens stay parked on `Bonding`, with no automatic or economically-forced path to completion.

```text
    /// @notice Permissionless trigger for phase 1 of graduation. Same flow as
    ///         the inline post-buy trigger inside `_executeBuy`, but callable
    ///         without any buy. Closes the case where `canGraduate` is true
    ///         (LT appreciation pushed the curve past the USD threshold) but
    ///         the closing buy on the curve would mint below the BounceTech
    ///         LT mint floor and revert with `BelowMinTransactionSize`,
    ///         making the token un-graduatable via `Zap.buy`.
    /// @dev    `_enterGraduating` reads pair reserves and the launch-time
    ///         virtual reserve only — it does not depend on a buy having
    ///         just landed, so the same logic is safe to expose as a
    ///         standalone entry point. The lifecycle pre-checks mirror
    ///         `Bonding.buy`; the launch trading delay is intentionally
    ///         not enforced because `canGraduate` already requires either
    ///         the USD threshold or full curve sellout, both of which are
    ///         unreachable from a fresh launch within the delay window.
    function triggerGraduation(
        address tokenAddress
    ) external nonReentrant {
        TokenInfo storage info = _s().tokenInfo[tokenAddress];
        if (info.creator == address(0)) revert TokenNotTrading();
        if (info.lifecycle == Lifecycle.Graduating) revert TokenIsGraduating();
        if (info.lifecycle != Lifecycle.Curve) revert TokenNotTrading();
        if (!canGraduate(tokenAddress)) revert NotGraduatable();
        _enterGraduating(tokenAddress);
    }
```

```text
    function finalizeGraduation(
        address tokenAddress
    ) external nonReentrant {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[tokenAddress];
        if (info.lifecycle != Lifecycle.Graduating) revert NotGraduating();

        address lt = info.ltAddress;
        PendingGraduation memory p = $.pendingGraduation[tokenAddress];

        // Anything in this contract beyond `p.ltFromPair` belongs to a
        // concurrent graduation on the same LT (Phase 1 transferred it
        // via `Router.graduate`) or to stray dust. Either way it is
        // off-limits to this graduation's deposit and sweep — see
        // `_routerDepositAndDispose` and `_sweepLTToOwner`.
        // Saturating subtract: a balance below `p.ltFromPair` shouldn't
        // be reachable in normal operation, but we keep finalize from
        // bricking on a Panic if any future code path or non-canonical
        // LT briefly violates the invariant.
        uint256 ltBalance = IERC20(lt).balanceOf(address(this));
        uint256 protectedLT = ltBalance > p.ltFromPair ? ltBalance - p.ltFromPair : 0;

        address lpPair = _ensureUniswapV2Pair(tokenAddress, lt);
        uint256 liquidity = _seedUniswapV2Direct(tokenAddress, lt, lpPair, p.tokensForLP, p.ltFromPair, protectedLT);

        _sweepLTToOwner(lt, protectedLT);

        info.lifecycle = Lifecycle.Graduated;
        $.graduatedPair[tokenAddress] = lpPair;
        delete $.pendingGraduation[tokenAddress];

        LPLock($.lpLock).recordLock(tokenAddress, lpPair, liquidity);

        emit TokenGraduated(tokenAddress, lpPair, liquidity, p.tokensForLP, p.lpBurned, p.unsoldBurned);
    }
```

```text
    /// @dev Send LT held by this contract above `keep` to the owner,
    ///      emitting `LTRescued`. Called at the end of
    ///      `finalizeGraduation` with `keep = protectedLT` (any escrow
    ///      that doesn't belong to this graduation), so only THIS
    ///      graduation's rebalance residue lands on the owner. No-op on
    ///      the empty-pair fast path (nothing to sweep).
    function _sweepLTToOwner(
        address lt,
        uint256 keep
    ) internal {
        uint256 bal = IERC20(lt).balanceOf(address(this));
        if (bal <= keep) return;
        uint256 amount = bal - keep;
        address recipient = owner();
        IERC20(lt).safeTransfer(recipient, amount);
        emit LTRescued(lt, recipient, amount);
```

```markdown
- **Two-phase split.** Graduation is split across two transactions to fit HyperEVM's small-block (~2M gas) ceiling.
  - **Phase 1: `_enterGraduating`**, fired inline by the threshold-crossing buy (~150-200k of additional gas on top of the buy). Drains the curve, computes the LP-bound amounts, caches them in `pendingGraduation[token]`, flips `lifecycle: Curve → Graduating`, freezes trading. Emits `TokenGraduating`.
  - **Phase 2: `finalizeGraduation`**, **permissionless** big-block tx (~2.5M gas). Creates the HyperSwap pair if needed, seeds liquidity across the empty, donation, and hostile mint-pre-seed regimes, locks LP, flips `lifecycle: Graduating → Graduated`. Emits `TokenGraduated`. A Cloudflare Worker keeper handles the happy path; anyone can call to rescue a stuck token.
- **Brick resistance.** Phase 2 must never revert under any pre-seed shape. Empty/donation pairs use direct pair calls; hostile mint pre-seeds use direct `pair.swap` for rebalance plus router `addLiquidity` for the canonical quote-based deposit. Tested by `test_brick_resistance_frontRun_dust_seed` in [`test/TwoPhaseGraduation.t.sol`](test/TwoPhaseGraduation.t.sol).
```
