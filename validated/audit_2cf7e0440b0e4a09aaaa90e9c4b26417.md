### Title
Accrued-debt RAY value overflow permanently freezes all market operations - ([File: common/src/rates/simulate.rs])

### Summary
A permissionless `update_indexes` call can drive an oversized, high-utilization market past the `i128` RAY-value boundary; because accrual executes before repayment, withdrawal, liquidation, and cleanup accounting, the resulting `MathOverflow` permanently freezes the market rather than allowing risk-reducing recovery. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
The controller exposes `supply`, `borrow`, and permissionless `update_indexes`; `supply` accepts `assets: Vec<(HubAssetKey, i128)>`, `borrow` accepts `borrows: Vec<(HubAssetKey, i128)>`, and `update_indexes` accepts `assets: Vec<HubAssetKey>`. [4](#0-3) [5](#0-4) 

Each call reaching the pool loads a market `Cache` and invokes `interest::global_sync`, which loops over elapsed time and calls `accrue_chunk` before the requested mutation proceeds. [2](#0-1) [6](#0-5) 

`accrue_step` converts the stored scaled borrow total to a RAY-denominated original value through `scaled_to_original`, and then multiplies the same scaled debt by the newly grown borrow index when calculating rewards. [1](#0-0) [7](#0-6) 

`scaled_to_original` is an `i128`-backed `Ray` multiplication, and `Ray::mul` routes to checked fixed-point multiplication rather than saturating the position value. [8](#0-7) [9](#0-8) 

The borrow index itself is capped only after `old_index.mul(interest_factor)` succeeds, so this cap does not prevent the separately computed debt value from overflowing first. [10](#0-9) 

### Impact Explanation
Once `borrowed * borrow_index` no longer fits the RAY domain, every market path that synchronizes first traps with `MathOverflow`, including withdrawals, repayments, and liquidation seizure, so suppliers cannot exit and liquidators cannot reduce the debt. [3](#0-2) [11](#0-10) [12](#0-11) [13](#0-12) 

This is permanent freezing of user funds and protocol insolvency for the affected `(hub_id, asset)` book, not merely a fail-closed invalid request: no later valid repayment amount can bypass the accrual performed before `resolve_repay`. [12](#0-11) [2](#0-1) 

### Likelihood Explanation
The attack is permissionless in the transaction-auth sense but has high capital and maturity prerequisites: an attacker must place the market near the token/RAY capacity boundary and sustain sufficiently high utilization until index growth makes the aggregate debt unrepresentable. [14](#0-13) [15](#0-14) 

The repository’s harness demonstrates the concrete cliff with one billion 18-decimal tokens supplied, 98% borrowed, and a later `update_indexes` call failing before the index ceiling; it then demonstrates that both withdrawal and repayment hit the same error. [16](#0-15) 

Because the state can also arise from an ordinary whale market rather than a deliberately malicious account, the analog is Medium severity: deterministic and severe once reached, but dependent on extreme market size, rate configuration, utilization, and elapsed accrual. [17](#0-16) [18](#0-17) 

### Recommendation
Check the representable post-accrual debt and supply values before mutating the index, and make accrual clamp at the largest index whose aggregate RAY values remain representable rather than trapping. [10](#0-9) [7](#0-6) 

Risk-reducing paths should also have a recovery branch that permits repayment, liquidation seizure, or bad-debt write-down when projection arithmetic is already at the representability boundary, instead of unconditionally evaluating the overflowing projection first. [2](#0-1) [13](#0-12) 

Market admission and cap validation should bound total scaled shares by the maximum index that can still be accrued safely, rather than bounding only the admitted token amount or the index itself. [15](#0-14) [10](#0-9) 

### Proof of Concept
The checked-in scenario uses a single controller API surface: an attacker-controlled supplier creates the debt-market liquidity with `supply(caller=A, account_id=0, spoke_id=S, assets=[(D, 1_000_000_000 * 10^18)])`, an attacker-controlled borrower supplies sufficient listed collateral through another owned account, calls `borrow(caller=A, account_id=B, borrows=[(D, 980_000_000 * 10^18)], to=None)`, and later calls `update_indexes(caller=A, assets=[D])`. [4](#0-3) [5](#0-4) [19](#0-18)

controller.borrow(
    attacker,
    borrower_account,
    vec![(debt_asset, borrow_amount)],
    None,
);

// After the index crosses the RAY-value cliff, this permissionless call fails.
controller.update_indexes(attacker, vec![debt_asset]); // MathOverflow

// Recovery calls fail for the same reason before their own logic runs.
controller.withdraw(supplier, supplier_account, vec![(debt_asset, 1)], None);
controller.repay(anyone, borrower_account, vec![(debt_asset, repayment)]);

The test proves that the failing index remains below `MAX_BORROW_INDEX_RAY` and that withdrawal and repayment subsequently return `MATH_OVERFLOW`, establishing the permanent accrual-time deadlock. [20](#0-19)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;

    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

pub fn calculate_supplier_rewards(
    env: &Env,
    params: &MarketParams,
    borrowed: Ray,
    new_borrow_index: Ray,
    old_borrow_index: Ray,
) -> (Ray, Ray) {
    let old_total_debt = borrowed.mul(env, old_borrow_index);
    let new_total_debt = borrowed.mul(env, new_borrow_index);

    let accrued_interest = new_total_debt.checked_sub(env, old_total_debt);

    let protocol_fee = params.reserve_factor.apply_to_ray(env, accrued_interest);
    let supplier_rewards = accrued_interest.checked_sub(env, protocol_fee);

    (supplier_rewards, protocol_fee)

pub(crate) fn accounting(env: &Env, action: &PoolAction) -> RepayOutcome {
    let (mut cache, position) = ops::load_leg(env, action);
    let amount = action.amount;

    let (burned, overpayment) = cache.resolve_repay(amount, position);
    let net_repay = amount
        .checked_sub(overpayment)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));
    assert_with_error!(
        env,
        net_repay == 0 || burned.raw() > 0,
        GenericError::RepayRoundsToZeroShares
    );

    let position = position.checked_sub(env, burned);
    cache.burn_debt(burned);

    cache.credit_cash(net_repay);

    let snapshot = cache.commit();
    let mutation = cache.position_mutation(position, net_repay);

| Deposit conversion at the supply-index floor | About 170.14 million whole tokens before scaled-share overflow |

The token-to-RAY maximum is also the admitted cap maximum. Accrued position
values and market totals must independently fit the RAY domain; valid caps and
bounded indexes do not guarantee that future accrual fits. Value overflow can
occur before the index ceiling and block repayment/withdrawal because those
operations accrue first. At the borrow-index ceiling, further accrual produces
