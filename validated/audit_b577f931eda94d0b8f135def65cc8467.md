### Title
`SimplexPaymaster` prices gas via Chainlink feeds on Arbitrum without checking the L2 sequencer-uptime feed - (File: `evm/src/utils/SimplexPaymaster.sol`)

### Summary
`SimplexPaymaster` is a permissionless ERC-4337 paymaster deployed on multiple chains including Arbitrum [1](#0-0) . It prices stablecoin gas payments from two Chainlink `AggregatorV3Interface` feeds (`nativeOracle` and each token's `tokenOracle`) via `_getOraclePrice`, checking only positivity and staleness against `maxOracleAge`, with no Arbitrum sequencer-uptime-feed check [2](#0-1) .

### Finding Description
`_getOraclePrice` calls `oracle.latestRoundData()` and only reverts if `answer <= 0` or `block.timestamp - updatedAt > maxOracleAge`: [3](#0-2) 
This is the same pattern flagged in the external report: on Arbitrum, if the sequencer goes down, transactions (including force-included ones) can still be processed while the Chainlink feed's `updatedAt` stops advancing along with real market prices; once the sequencer resumes, or during any window where the on-chain feed value is technically "fresh enough" per `maxOracleAge` but stale relative to real-world price movement caused by sequencer downtime, `_tokenPrice`/`_getOraclePrice` will compute gas cost off a mispriced, uncorrected feed. Chainlink explicitly recommends gating L2 consumers on a sequencer-uptime feed (`isSequencerUp` + grace period) for this reason. `SimplexPaymaster` has no such gate anywhere in `_tokenPrice` or `_getOraclePrice` [4](#0-3) , and this pricing path is reached directly by any unprivileged bundler/UserOperation submitter through `fetchDetails`/`_prefund`, since gas cost for the sponsored transaction is derived from `_tokenPrice(cfg)` with no relayer or governance gating on the pricing call itself.

### Impact Explanation
A stale/mispriced feed during Arbitrum sequencer downtime lets a solver or attacker submit UserOperations whose `paymasterData` charges token amounts computed off a wrong price, allowing the attacker to underpay in stablecoins relative to true gas cost (draining the paymaster's EntryPoint deposit/native stake, which per `SimplexPaymasterStakeLockForkTest.t.sol` can never be recovered by governance [5](#0-4) ) or overpay (loss to solvers/users). This is a Medium-severity fund-loss vector directly reachable by any UserOperation sender, matching the report's "unfair liquidations"-style mispricing class applied here to gas-payment mispricing.

### Likelihood Explanation
Arbitrum sequencer outages have occurred historically, and `SimplexPaymaster` is actively deployed there with tokens registered per the release notes [6](#0-5) . Every UserOperation using the paymaster hits the unguarded `_getOraclePrice`/`_tokenPrice` path, so exploitation requires no special permissions — just submitting a UserOperation during/after a sequencer outage window.

### Recommendation
Add a Chainlink L2 sequencer-uptime-feed check (with the recommended grace period, e.g. 3600s) in `_getOraclePrice` or `_tokenPrice` for chains where the paymaster deploys onto an L2 rollup (Arbitrum, Optimism, Base), reverting pricing when the sequencer is down or within the grace period after it comes back up.

### Proof of Concept
1. Deploy/observe `SimplexPaymaster` on Arbitrum with feeds registered as in `DeploySimplexPaymaster.s.sol` [7](#0-6) .
2. Simulate an Arbitrum sequencer outage where the underlying Chainlink feed's `updatedAt` stalls while true asset prices move, but remains within `maxOracleAge` (default `90_000`s per the deploy script) [8](#0-7) .
3. Call `getTokenPrice`/`estimateTokenCost`, or submit a sponsored UserOperation, during this window — `_getOraclePrice` passes both its checks and returns the stale price [9](#0-8) , letting an attacker pay gas at the stale rate while the paymaster/EntryPoint deposit absorbs the mispricing loss.

    function _tokenPrice(TokenConfig memory cfg) internal view returns (uint256) {
        uint256 nativeUsd = _getOraclePrice(nativeOracle, nativeOracleDecimals);
        uint256 tokenUsd = _getOraclePrice(cfg.tokenOracle, cfg.tokenOracleDecimals);

        return (nativeUsd * (10 ** cfg.tokenDecimals) * (10_000 + markupBps)) / (tokenUsd * 10_000);
    }

    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
