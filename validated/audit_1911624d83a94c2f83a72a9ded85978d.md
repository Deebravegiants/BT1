### Title
Missing relayer authorization gate on Tron `IntentGatewayV2.onAccept`/`onGetResponse` allows a forged handler delivery to redeem or refund arbitrary escrow — ([File: evm/tron/contracts/apps/IntentGatewayV2.sol])

### Summary
The Tron port of the Intent Gateway (`evm/tron/contracts/apps/IntentGatewayV2.sol`) implements `onAccept` and `onGetResponse` with only `onlyHost` plus a `from == instance(source)` authentication check. It is missing the `_checkRelayer` gate that the canonical EVM gateway (`evm/src/apps/intentsv2/ExtrinsicIntents.sol`) enforces on every incoming delivery before decoding the request body. This is structurally the same defect as the reported `settleUpnl` bug: a privileged settlement/withdrawal entry point that should be restricted to a single trusted deliverer instead relies on a weaker, forgeable check.

### Finding Description
On the canonical EVM gateway, `onAccept` first calls `_checkRelayer(incoming.relayer)` [1](#0-0)  before it ever reads the request body or performs the `_authenticate` source-instance check. The documented purpose of this gate is defense against a compromised or swapped `HandlerV2`/host: "The address checked in step 3 is only as trustworthy as the contract in step 1 ... The HostManager therefore runs the same relayer check before decoding any governance action" [2](#0-1) .

The Tron `IntentGatewayV2.onAccept`, however, performs no relayer check at all — it goes straight from `onlyHost` to decoding the `RequestKind` and, for `RedeemEscrow`/`RefundEscrow`, to `authenticate(incoming.request)` and `withdraw(body, ...)`: [3](#0-2) 

`authenticate()` only checks that `request.from` equals the registered gateway address for `request.source`: [4](#0-3) 

Both `request.source` and `request.from` are attacker-controllable fields of the `PostRequest` that a forged/malicious delivery path constructs; they are public, known values (the registered peer-gateway addresses recorded in `_instances`), not secrets. The relayer check exists precisely to catch the case where the host's handler has been swapped to something malicious (e.g. via a manipulated `HostManager`/host-params rotation), so that even if `dispatchIncoming` is reached with attacker-forged request contents, `onAccept` still refuses anyone but the authorized relayer. Tron's `onAccept`/`onGetResponse` have no such backstop: [5](#0-4) 

`withdraw()` unconditionally finalizes `_filled[commitment]`, transfers all escrowed tokens/fees to the beneficiary named in the forged body, and is reachable for `RedeemEscrow`/`RefundEscrow` purely through `onlyHost` + the forgeable `authenticate()` check: [6](#0-5) 

The governance branch (`NewDeployment`, `UpdateParams`, `SweepDust`) is likewise reachable with only a `request.source == hyperbridge()` check and no relayer gate, letting a forged delivery register a malicious gateway instance, rewrite fee/dispatcher parameters, or sweep dust to an arbitrary beneficiary: [7](#0-6) 

### Impact Explanation
If the underlying host/handler on the Tron deployment is ever compromised or maliciously reconfigured (the same threat the relayer gate was added to mitigate on the EVM side), an attacker can forge `RedeemEscrow`/`RefundEscrow` deliveries to drain any escrowed order (theft of user/solver funds), forge `NewDeployment` to register a rogue "instance" that then passes `authenticate()` for future forged withdrawals, or forge `UpdateParams`/`SweepDust` to redirect protocol fees/dust. This is concrete theft of escrowed funds and unauthorized governance action — a direct analog of "unauthorized PartyB settling PNL" from the source report, where the privileged settlement path lacks the modifier that would have refused non-authorized callers.

### Likelihood Explanation
Exploitation requires the same precondition documented for the EVM gateway's relayer-gate rationale: a forged or hijacked message path at the host/handler layer. This is not a routine unprivileged-user attack, but it is exactly the scenario Hyperbridge itself calls out as reachable ("HostManager.onAccept can replace [the handler] through a SetHostParam request... this leaves ordinary relaying open" — mitigated on EVM only by the relayer check). Because Tron's gateway was not updated with this hardening while the EVM gateway explicitly was (per the relayer-allowlist changelog), the Tron deployment is left exposed to precisely the class of attack the rest of the codebase treats as Medium/High severity and defends against everywhere else.

### Recommendation
Add the same `_relayer`/`_checkRelayer` gate used in `evm/src/apps/intentsv2/ExtrinsicIntents.sol` and `evm/src/apps/intentsv2/IntentsBase.sol` to the Tron `IntentGatewayV2.onAccept` and `onGetResponse`, calling `_checkRelayer(incoming.relayer)` immediately after `onlyHost` and before any body decoding or `authenticate()` check, mirroring the canonical implementation exactly (including host-only `setRelayer`/rotation wiring).

### Proof of Concept
Not applicable in this static analysis — no live forged-handler harness was exercised. The finding is based on direct comparison of `evm/tron/contracts/apps/IntentGatewayV2.sol` against the hardened `evm/src/apps/intentsv2/ExtrinsicIntents.sol`/`IntentsBase.sol`, which conclusively shows the relayer-gate call is present in the latter and absent in the former at the equivalent code path.

        if (request.from.length != 20) revert InvalidInput();
        address module = address(bytes20(request.from));
        // IntentGateway only accepts incoming assets from itself or known instances
        if (instance(request.source) != module) revert Unauthorized();

    function onAccept(IncomingPostRequest calldata incoming) external override onlyHost {
        RequestKind kind = RequestKind(uint8(incoming.request.body[0]));
        if (kind == RequestKind.RedeemEscrow || kind == RequestKind.RefundEscrow) {
            authenticate(incoming.request);
            WithdrawalRequest memory body = abi.decode(incoming.request.body[1:], (WithdrawalRequest));
            return withdraw(body, kind == RequestKind.RefundEscrow);
        }

        // only hyperbridge is permitted to perfom these actions
        if (keccak256(incoming.request.source) != keccak256(IDispatcher(host()).hyperbridge())) revert Unauthorized();
        if (kind == RequestKind.NewDeployment) {
            NewDeployment memory body = abi.decode(incoming.request.body[1:], (NewDeployment));
            _instances[keccak256(body.stateMachineId)] = body.gateway;

            emit NewDeploymentAdded({stateMachineId: body.stateMachineId, gateway: body.gateway});
        } else if (kind == RequestKind.UpdateParams) {
            // Decode the body which includes optional destination-specific protocol fee updates
            ParamsUpdate memory update = abi.decode(incoming.request.body[1:], (ParamsUpdate));
            emit ParamsUpdated({previous: _params, current: update.params});
            _params = update.params;

            // Update destination-specific protocol fees if provided
            for (uint256 i; i < update.destinationFees.length;) {
                bytes32 stateMachineId = update.destinationFees[i].stateMachineId;
                uint256 feeBps = update.destinationFees[i].destinationFeeBps;
                _destinationProtocolFees[stateMachineId] = feeBps;

                unchecked {
                    ++i;
                }
                emit DestinationProtocolFeeUpdated(stateMachineId, feeBps);
            }
        } else if (kind == RequestKind.SweepDust) {
            SweepDust memory req = abi.decode(incoming.request.body[1:], (SweepDust));

            uint256 outputsLen = req.outputs.length;
            for (uint256 i; i < outputsLen;) {
                TokenInfo memory info = req.outputs[i];
                address token = address(uint160(uint256(info.token)));
                uint256 amount = info.amount;

                if (token == address(0)) {
                    (bool sent,) = req.beneficiary.call{value: amount}("");
                    if (!sent) revert InsufficientNativeToken();
                } else {
                    (bool success,) = token.call(abi.encodeWithSelector(IERC20.transfer.selector, req.beneficiary, amount));
                    if (!success) revert TransferFailed();
                }
                unchecked {
                    ++i;
                }
                emit DustSwept(token, amount, req.beneficiary);
            }
        }
    }

    function withdraw(WithdrawalRequest memory body, bool isRefund) internal {
        address beneficiary = address(uint160(uint256(body.beneficiary)));
        _filled[body.commitment] = beneficiary;

        // redeem escrowed tokens
        uint256 len = body.tokens.length;
        for (uint256 i; i < len;) {
            address token = address(uint160(uint256(body.tokens[i].token)));
            uint256 amount = body.tokens[i].amount;
            if (_orders[body.commitment][token] == 0) revert UnknownOrder();

            if (token == address(0)) {
                (bool sent,) = beneficiary.call{value: amount}("");
                if (!sent) revert InsufficientNativeToken();
            } else {
                (bool success,) = token.call(abi.encodeWithSelector(IERC20.transfer.selector, beneficiary, amount));
                if (!success) revert TransferFailed();
            }

            _orders[body.commitment][token] -= amount;
            unchecked {
                ++i;
            }
        }

        // redeem tx fees
        uint256 fees = _orders[body.commitment][TRANSACTION_FEES];
        if (fees > 0) {
            address feeToken = IDispatcher(host()).feeToken();
            (bool success,) = feeToken.call(abi.encodeWithSelector(IERC20.transfer.selector, beneficiary, fees));
            if (!success) revert TransferFailed();
            delete _orders[body.commitment][TRANSACTION_FEES];
        }

        if (isRefund) {
            emit EscrowRefunded({commitment: body.commitment});
        } else {
            emit EscrowReleased({commitment: body.commitment});
        }
    }
