### Title
`Pool::recapitalize` refunds the caller's declared `amount` without verifying any tokens were actually prefunded — an unprivileged caller drains pool custody — ([File: contracts/pool/src/ops/recapitalize.rs])

### Summary
`recapitalize::apply` credits `min(amount, backing_shortfall)` to the cash book and unconditionally calls `cache.transfer_out(&payer, refund)` where `refund = amount - applied`. The `amount` is a caller-supplied argument, not a measured balance delta. When the market is fully backed, `applied = 0` and the pool transfers the entire declared `amount` to `payer` even if nothing was ever transferred in. The controller-side path (`controller::markets::recapitalize`) does prefund via `transfer_amount_measured` and passes only the measured receipt, but the pool entrypoint itself trusts the declared value — the exact analog of Xen's MSI code acting on unsanitized register read-backs.

### Finding Description
In `contracts/pool/src/ops/recapitalize.rs`:

- `apply` calls `accounting(env, hub_asset, amount)` then `outcome.cache.transfer_out(&payer, outcome.refund)` (lines 32–34).
- `accounting` computes `applied = amount.min(guards::backing_shortfall(&cache))` and `refund = amount - applied` (lines 52–55). The refund is paid out of real token custody; nothing in this function reads `token.balance` or verifies a prefund occurred.

The pool test `test_unfunded_recapitalize_leaves_the_cash_book_overstating_custody` in `contracts/pool/tests/flows.rs` (lines 3408–3433) demonstrates the drain concretely: `t.client().recapitalize(&hub(&t.asset), &payer, &custody)` is invoked directly with a freshly generated `payer` and no prior transfer, after which `token.balance(&t.pool) == 0` — "the pool's entire custody has left the contract". The test treats this as a book/custody divergence issue, but the same call is also a direct theft primitive: `payer` receives `refund = custody - applied`.

The bug class from the report is "code acts on unsanitized values read back from a source the attacker can influence." Here the pool treats the `amount` argument — the caller's claim about how much it prefunded — as ground truth for sizing both the credit and the refund, instead of measuring its own balance increase as INV-ACCT-03 requires for every other token-funded path (`docs/reference/invariants.md` lines 114–119: "Token-funded supply, repayment and recapitalization credit the pool's measured balance increase").

### Impact Explanation
Critical: theft of user funds. Any unprivileged address can call `Pool::recapitalize` (or route through `clean_bad_debt`/`recapitalize` per-market) with `amount = pool token balance` into a healthy market (no backing shortfall ⇒ `applied = 0`, `refund = amount`), receiving the pool's entire custodied balance for that asset. Even in a shortfall market, `applied` is capped at the shortfall, so the caller can drain `custody - shortfall`. No collateral, position, or authorization is required — the pool has no `require_auth` on this path (the test calls it with an unauthenticated `Address::generate`).

### Likelihood Explanation
Trivially reachable: a single transaction to the pool contract with a `HubAssetKey` and the token balance. Requirements: the market exists and the pool holds custody. Even where `backing_shortfall > 0` limits `refund`, repeated calls or partially backed markets still leak the excess.

### Recommendation
Gate `Pool::recapitalize` so it only ever pays out what it actually received:

- Measure the pool's balance delta around the call (snapshot `token.balance(pool)` before, compare after) — or better, require the caller to be the controller (`require_auth` on the configured controller address), which already performs `transfer_amount_measured` in `contracts/controller/src/markets.rs` (lines 154–161).
- Alternatively, have `accounting` compute `applied` and `refund` from the measured receipt rather than the declared `amount`, making an unfunded call a no-op (`received = 0`, `refund = 0`).

### Proof of Concept
Covered by the existing test at `contracts/pool/tests/flows.rs` lines 3408–3433:

```rust
// A legitimate supplier deposits; pool custody == deposit.
token_admin.mint(&t.pool, &deposit);
t.client().supply(&t.sup(0, deposit));

// Attacker calls recapitalize with NO prefund.
let custody = token.balance(&t.pool);
t.client().recapitalize(&hub(&t.asset), &payer, &custody);

assert_eq!(token.balance(&t.pool), 0, "custody is gone");
// `payer` now holds `custody` tokens; the cash book still shows them.
```

In a healthy market `backing_shortfall == 0`, so `applied = 0` and `transfer_out(payer, amount)` moves the full declared amount to the attacker's `payer` address — direct theft of all suppliers' custodied tokens, reachable by any unprivileged address in one call.
