### Title
`isHostname` fails to detect IPv6 / IPv4-mapped IPv6 literals, letting `isSubdomain` misclassify IP-based origins as hostnames - ([File: modules/networking-common/src/cookie/validators.ts])

### Summary
`isHostname` only rejects strings matching a strict IPv4 regex and explicitly leaves IPv6 detection unimplemented (`// TODO: also make sure this ain't a v6 ip address`). Because `isSubdomain` relies on `isHostname` to enforce the RFC 6265 rule that IP-address origins must never be treated as having "parent"/"child" domain relationships, an IPv6 literal (especially an IPv4-mapped form like `::ffff:1.2.3.4`) can satisfy the dot-suffix check and be misclassified as a valid hostname, letting `assertMatchingDomain` accept a `Cookie.domain` value that is not actually a legitimate parent of the origin.

### Finding Description
`assertMatchingDomain(domain, originDomain)` at [1](#0-0)  permits a cookie whose `Domain` attribute is a suffix-with-dot-boundary of the current origin, provided `isSubdomain` confirms the origin `value` "is a host name (i.e., not an IP address)" per the RFC 6265 comment at [2](#0-1) . That IP-address exclusion is delegated entirely to `isHostname`, which is implemented as: [3](#0-2) 
This regex only matches canonical dotted-quad IPv4 strings anchored with `^...$`. Any IPv6 literal — including plain IPv6 (`::1`, `2001:db8::1`) and IPv4-mapped IPv6 (`::ffff:1.2.3.4`) — fails the `v4` regex and is therefore classified as a "hostname" by `!v4.test(value)`, even though it is an IP address.

For a normal colon-separated IPv6 literal, `isSubdomain`'s `endsWith('.')` boundary check will rarely succeed since IPv6 uses `:` separators, so most IPv6 inputs are practically harmless. However, an IPv4-mapped IPv6 literal such as `::ffff:1.2.3.4` embeds dotted-decimal octets, so a crafted `Domain` suffix (e.g. `"3.4"`) can satisfy `value.endsWith(domain)` and the trailing-dot boundary check while `isHostname("::ffff:1.2.3.4")` incorrectly returns `true`. This causes `isSubdomain(originDomain, domain)` to return `true`, and `assertMatchingDomain` accepts the cookie's `Domain` scope instead of throwing the intended "third party origin" error — violating the stated invariant that IP-address origins should never satisfy the hostname branch.

### Impact Explanation
This is a real logic defect in the domain-scoping guard that is supposed to enforce RFC 6265 origin binding for cookies, matching Hydra's "wrong-account/origin access" / "origin trust" impact category. In principle it lets a server reachable via an IPv4-mapped IPv6 address set a cookie `Domain` attribute that should be rejected as invalid/third-party, weakening the origin-binding invariant that downstream code (persisted cookies feeding origin-bound wallet state) relies on. Because the bug is confined to `isHostname`/`isSubdomain`/`assertMatchingDomain`, the concrete blast radius is limited to whatever consumer wires these into cookie persistence and trust decisions.

### Likelihood Explanation
Preconditions: the attacker needs to be the server the wallet networking layer is talking to (i.e., control a `Set-Cookie` response) via an IPv4-mapped IPv6-literal origin, and the wallet must actually invoke `assertMatchingDomain`/`isSubdomain`/`isHostname` on cookie set operations targeting that origin. I could not locate an actual `CookieJar`/consumer in this repository that calls `assertMatchingDomain` outside of `modules/networking-common/src/cookie/validators.spec.ts` — [4](#0-3)  and the module's public surface [5](#0-4) . This means the specific end-to-end `CookieJar.set -> validate -> assertMatchingDomain` chain described in the question is not demonstrable as currently wired within this repo; the underlying `isHostname` defect is confirmed and directly reachable through the exported `assertMatchingDomain` function itself, but full wallet-compromise reachability from an ordinary dapp/origin request could not be verified in this codebase scan.

### Recommendation
Extend `isHostname` to also detect IPv6 literals (including IPv4-mapped/compatible forms) — e.g., using a proper IPv6 regex or `URL`/`net.isIP`-style validation — and reject any value classified as an IP address (v4 or v6) from the hostname branch, matching the TODO already present in the code. Additionally, replace the fragile `value.replace(domain, '')` (which only replaces the first occurrence and can produce incorrect results for repeated substrings) with a proper suffix-slicing check, e.g. `value.slice(0, value.length - domain.length).endsWith('.')`.

### Proof of Concept
Unit test against the exported `isHostname`/`assertMatchingDomain` behavior:
```ts
import { assertMatchingDomain } from './validators'

it('does not treat IPv4-mapped IPv6 literal as a hostname suffix match', () => {
  // origin is an attacker-controlled IPv4-mapped IPv6 literal
  const originDomain = '::ffff:1.2.3.4'
  const maliciousCookieDomain = '3.4'

  expect(() => assertMatchingDomain(maliciousCookieDomain, originDomain)).toThrow(
    /Cannot set a cookie for a third party origin/
  )
})
```
Fuzz/invariant plan: generate a corpus of IPv6 literals (plain, compressed, IPv4-mapped, IPv4-compatible) plus valid hostnames; assert that for every IP-address-classified `value`, `isHostname(value)` returns `false`, and that `isSubdomain(value, suffix)` never returns `true` for any suffix when `value` is an IP address.

function assertMatchingDomain(domain: string | undefined, originDomain: string) {
  if (domain === undefined) return

  // Domain matching: https://datatracker.ietf.org/doc/html/rfc6265#section-5.1.3
  if (domain === originDomain) return

  if (isSubdomain(domain, originDomain)) {
    throw new Error(
      `Cannot set a cookie for a subdomain. Tried to set ${domain} with origin ${originDomain}`
    )
  }

  if (isSubdomain(originDomain, domain)) {
    return
  }

  throw new Error(
    `Cannot set a cookie for a third party origin. Tried to set ${domain} with origin ${originDomain}`
  )
}
```

function isSubdomain(value: string, domain: string): boolean {
  /*
   *  - The domain string is a suffix of the string.
   *  - The last character of the string that is not included in the
   *     domain string is a %x2E (".") character.
   *  - The string is a host name (i.e., not an IP address).
   */

  return value.endsWith(domain) && value.replace(domain, '').endsWith('.') && isHostname(value)
}
```
