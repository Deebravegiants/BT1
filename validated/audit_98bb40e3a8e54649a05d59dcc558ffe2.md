### Title
`swap_debt` mints debt in markets the account is not permitted to borrow — spoke `is_borrowable` and hub-active gates bypassed - (File: contracts/controller/src/strategies/swap_debt.rs)

### Summary
The direct `borrow` entrypoint gates every leg through `validate_position_entry_gates` → `require_can_borrow`, which enforces that the `(hub, token)` market is listed in the account's spoke and `is_borrowable == true` [1](#0-0) . The `swap_debt` strategy creates brand-new debt in an arbitrary `new_debt` hub asset through `borrow_into_controller` without ever calling `require_can_borrow` on it, and it only validates `existing_debt.hub_id` for hub activity — `new_debt.hub_id` is never checked [2](#0-1) . This is the same bug class as the Teller report: a borrow-eligibility restriction enforced on the primary path but absent on an alternate path that reaches the same outcome.

### Finding Description
`process_borrow` enforces two market-membership gates on each borrowed asset:

1. The market must be listed in `account.spoke_id` (`require_listed_unhalted_config` panics if the spoke asset record is absent).
2. The listing must have `is_borrowable == true` [3](#0-2) .

`process_swap_debt` reaches the identical end state — a new `DebtPosition` on the account and tokens drawn from the pool — via `borrow_into_controller(env, &mut account, new_debt, new_debt_amount, ...)` [4](#0-3) , but the only structural checks in the function are `existing_debt != new_debt`, `require_hub_active(existing_debt.hub_id)`, and `require_positive_amount` [5](#0-4) . There is no `require_can_borrow` (or any spoke-listing/`is_borrowable` check) applied to `new_debt` in this file, and no `require_hub_active(new_debt.hub_id)`. Since pool markets are keyed per `(hub_id, token)` globally rather than per spoke, any hub market that exists in the pool can be borrowed through this path even when the account's spoke does not list it or lists it as non-borrowable.

Caveat on verification: the body of `borrow_into_controller` (in `contracts/controller/src/strategies/mod.rs`) was not read in this pass; the finding holds unless that helper internally re-applies `require_can_borrow` against the caller's spoke, which the strategy's own prefetch/check ordering suggests it does not (strategies borrow "into controller" deliberately to bypass recipient/entry gates). The missing `require_hub_active(new_debt.hub_id)` check is unconditional and confirmed.

### Impact Explanation
An account owner or delegate can acquire debt in a market that governance deliberately excluded from the account's spoke or flagged `is_borrowable = false` (a flag the protocol treats as a borrow restriction — the certora rule `spoke_only_borrowable_assets` formally asserts `process_borrow` must revert in that state [6](#0-5) ). Concretely this can: (a) draw liquidity from a market whose risk parameters were never meant to back debt in that spoke, including markets priced under different oracle configurations; (b) leave the account holding debt in an asset with a delisted/missing spoke config — the codebase explicitly treats missing listings as exitable but not enterable, so the position may be hard to manage through normal paths. The direct impact on protocol solvency is bounded by the post-solvency check in `strategy_finalize`, so the practical severity is Medium: a governance-imposed borrow restriction is circumvented rather than collateral being stolen.

### Likelihood Explanation
Reachable by any account owner or active delegate via the public `swap_debt` entrypoint with arguments `(account_id, existing_debt = a listed debt position, new_debt = any hub asset with pool liquidity, new_debt_amount > 0, swap = passthrough or a self-route)`. Prerequisites are modest: the account needs an existing debt position and enough collateral headroom to pass `strategy_finalize`'s solvency check. The swap leg can even be a cross-hub passthrough of the same underlying token, making execution trivial when `new_debt.asset == existing_debt.asset` on a different hub [7](#0-6) .

### Recommendation
In `process_swap_debt`, before calling `borrow_into_controller`, add:

```rust
config::require_hub_active(env, new_debt.hub_id);
require_can_borrow(env, &mut cache, account.spoke_id, new_debt);
```

mirroring the destination check already present in `process_swap_collateral` (`require_can_supply` on `new` before withdrawing) [8](#0-7) . Audit `multiply`, `flash_position`, and `migrate_from_blend` for the same gap — any strategy path that creates debt must apply the spoke `is_borrowable` gate to the debt asset it creates.

### Proof of Concept
1. Governance lists market `(hub_A, USDC)` in spoke S with `is_borrowable = true`, and market `(hub_B, USDC)` exists in the pool but is **not** listed in spoke S (or is listed with `is_borrowable = false`).
2. Alice supplies collateral in spoke S and calls `borrow` for `(hub_B, USDC)` → reverts with `AssetNotInSpoke`/`AssetNotBorrowable` (enforced by `require_can_borrow`).
3. Alice instead calls `borrow` for `(hub_A, USDC)` (allowed), then calls `swap_debt` with `existing_debt = (hub_A, USDC)`, `new_debt = (hub_B, USDC)`, `new_debt_amount = debt + interest`, and a passthrough swap (same underlying token, `swap` route empty/trivial).
4. `process_swap_debt` performs `require_hub_active(hub_A)` only, never checks `(hub_B, USDC)` against spoke S, mints a `DebtPosition` on `(hub_B, USDC)`, repays the `(hub_A, USDC)` debt, and finalizes — Alice now holds debt in a market she was explicitly barred from borrowing, exactly the trust-check bypass of the reference report.

#[rule]
fn spoke_only_borrowable_assets(
    e: Env,
    caller: Address,
    account_id: u64,
    asset: Address,
    amount: i128,
) {
    cvlr_assume!(amount > 0 && amount <= crate::constants::WAD * 1000);
    crate::spec::fixture::seed_live_account(&e, account_id, &caller, &asset);

    let mut stored =
        crate::storage::get_spoke_asset(&e, crate::spec::fixture::SPOKE_ID, &hub0(&asset)).unwrap();
    stored.is_borrowable = false;
    crate::storage::set_spoke_asset(&e, crate::spec::fixture::SPOKE_ID, &hub0(&asset), &stored);

    let attrs = crate::storage::get_account_attrs(&e, account_id);
    cvlr_assume!(attrs.spoke_id > 0);

    let spoke_asset = crate::storage::get_spoke_asset(&e, attrs.spoke_id, &hub0(&asset));
    cvlr_assume!(spoke_asset.is_some());
    let cfg = spoke_asset.unwrap();
    cvlr_assume!(!cfg.is_borrowable);

    let mut borrows: Vec<(HubAssetKey, i128)> = Vec::new(&e);
    borrows.push_back((hub0(&asset), amount));
    crate::positions::process_borrow(&e, &caller, account_id, &borrows, None);

    cvlr_assert!(false);
}
