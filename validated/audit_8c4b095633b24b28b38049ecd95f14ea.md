Audit Report

## Title
Unauthenticated NULL-Pointer-Dereference DoS via `vault_publicKeyGet` with nil `params` in `GatewayHandler.HandleGatewayMessage` - (File: core/capabilities/vault/gw_handler.go)

## Summary
`GatewayHandler.HandleGatewayMessage` routes `MethodPublicKeyGet` directly to `handlePublicKeyGet` without going through `GatewayVaultRequestProcessor.ProcessRequest`, which is the only place performing a `req.Params == nil` check for the other vault methods. `handlePublicKeyGet` unconditionally executes `json.Unmarshal(*req.Params, r)`, so a JSON-RPC request with method `vault_publicKeyGet` and no/`null` `params` field causes a nil-pointer dereference panic that is unrecovered in `gatewayConnector.readLoop`, crashing the node process.

## Finding Description
In `core/capabilities/vault/gw_handler.go` L187-211, the `switch req.Method` statement handles `MethodSecretsCreate`/`MethodSecretsUpdate`/`MethodSecretsDelete`/`MethodSecretsList` by calling `h.requestProcessor.ProcessRequest(...)`, whose method handlers (e.g. `processCreateSecretsRequest`, `processDeleteSecretsRequest`, `processListSecretIdentifiersRequest` in `core/capabilities/vault/gateway_vault_request_processor.go`) explicitly check `if req.Params == nil` and return `InvalidVaultParamsError` before unmarshalling. `MethodPublicKeyGet`, however, is handled inline at L207-208 (`case vaulttypes.MethodPublicKeyGet: response = h.handlePublicKeyGet(ctx, gatewayID, req)`), completely bypassing this validation pipeline. `handlePublicKeyGet` (L364-368) immediately does `json.Unmarshal(*req.Params, r)` with no nil check on `req.Params`. If `req.Params` is `nil` — which is valid per JSON-RPC 2.0 (params is optional) — this dereferences a nil `*json.RawMessage` and panics.

This request reaches the node via `gatewayConnector.readLoop` (`core/services/gateway/connector/connector.go` L268-298), which unmarshals the raw message into `jsonrpc.Request[json.RawMessage]` and calls `handler.HandleGatewayMessage(ctx, ..., &req)` with **no panic recovery** anywhere in the loop or surrounding connector code (confirmed via search — no `recover()` calls exist in `core/services/gateway/connector` or `core/services/gateway/handlers`, aside from an unrelated test file). A panic here is therefore unrecovered and crashes the goroutine/process.

## Impact Explanation
This is a legitimate denial-of-service: an unrecovered panic in `readLoop` crashes the Chainlink node process. Since the vulnerable code path handles gateway-forwarded requests that reach every node subscribed to the vault capability's `MethodPublicKeyGet` method, a single malformed message can potentially crash multiple DON nodes. This maps to an in-scope "unauthorized action / DoS via node API" impact class analogous to a crash from unvalidated attacker-supplied input.

## Likelihood Explanation
The precondition is minimal: an actor able to submit a JSON-RPC request to the gateway with `method: "vault_publicKeyGet"` and no `params` field (or `"params": null`). No authentication token, allowlist membership, or special role is checked before the crash occurs, since the vulnerable path bypasses the request processor pipeline entirely. This is trivially and repeatably triggerable.

## Recommendation
Add an explicit `if req.Params == nil` check at the start of `handlePublicKeyGet` (or route `MethodPublicKeyGet` through `GatewayVaultRequestProcessor.ProcessRequest` like the other methods) and return an `api.UserMessageParseError`/`InvalidParamsError` response instead of panicking. Additionally, add panic recovery around `handler.HandleGatewayMessage(...)` in `gatewayConnector.readLoop` as defense-in-depth so a single malformed/malicious message from any handler cannot crash the node process.

## Proof of Concept
1. Submit to the gateway a JSON-RPC request: `{"jsonrpc":"2.0","id":"1","method":"vault_publicKeyGet"}` (no `params` key).
2. Gateway forwards this to a node; `gatewayConnector.readLoop` unmarshals it into `jsonrpc.Request[json.RawMessage]{Method: "vault_publicKeyGet", Params: nil}` and calls `handler.HandleGatewayMessage`.
3. `GatewayHandler.HandleGatewayMessage` matches `case vaulttypes.MethodPublicKeyGet` and calls `h.handlePublicKeyGet(ctx, gatewayID, req)` directly (`core/capabilities/vault/gw_handler.go` L207-208).
4. `handlePublicKeyGet` executes `json.Unmarshal(*req.Params, r)` at L366, dereferencing nil `*json.RawMessage`, panicking.
5. The panic propagates unrecovered through `readLoop`, crashing the node process. A Go unit test calling `GatewayHandler.HandleGatewayMessage(ctx, gatewayID, &jsonrpc.Request[json.RawMessage]{Method: vaulttypes.MethodPublicKeyGet, Params: nil})` directly reproduces the panic.
