### Title
`_getOraclePrice` doesn't check Arbitrum/Optimism/Base L2 sequencer-uptime feed before trusting Chainlink price data - (File: `evm/src/utils/SimplexPaymaster.sol`)

### Summary
`SimplexPaymaster` is a permissionless ERC-4337 paymaster deployed on Arbitrum, Optimism, and Base, converting ERC-20 stablecoin cost into native-gas terms using two Chainlink `AggregatorV3Interface` feeds (`nativeOracle` and each token's `tokenOracle`). The internal `_getOraclePrice` helper only guards against a non-positive answer and staleness relative to `maxOracleAge`; it never queries a sequencer-uptime feed (e.g. Chainlink's `0xFdB631F5EE196F0ed6FAa767959853A9F217697D` on Arbitrum) to confirm the sequencer has been up long enough (the standard `GRACE_PERIOD_TIME`) for the last round to reflect a live L1↔L2 message path.

### Finding Description
When an L2 sequencer goes down, L1→L2 messages queue up and are not delivered promptly, so a Chainlink price feed on that L2 can return a stale `answer`/`updatedAt` pair that nonetheless passes the contract's staleness check as long as `block.timestamp - updatedAt <= maxOracleAge` (which is intentionally generous — deployed with `MAX_ORACLE_AGE = 7 days` and a runtime default of 90,000 seconds, per `DeploySimplexPaymaster.s.sol`). During or immediately after a sequencer outage, a manipulated or frozen price can be accepted as fresh because there is no check equivalent to Chainlink's recommended sequencer-uptime-feed pattern (`latestRoundData()` on the `SequencerUptimeFeed` plus a grace period after `startedAt`). [3](#0-2) 

This affects every price-dependent path in the contract: `_fetchDetails` (charges the UserOp sender), `_tokenPrice`/`getTokenPrice`/`estimateTokenCost` (external price quotes), and `swapAndDeposit` (computes `amountOutMin` for a live on-chain swap of accrued stablecoin surplus). [4](#0-3) [5](#0-4) 

### Impact Explanation
If the Arbitrum, Optimism, or Base sequencer stalls or restarts and the underlying Chainlink feed answer becomes stale/mispriced within the L1-fallback window without yet exceeding `maxOracleAge`, a solver/attacker submitting UserOps through the paymaster could be charged an incorrect (favorable-to-attacker or unfavorable-to-victim) token amount for gas, since `_fetchDetails`/`_tokenPrice` still return a "valid" (non-reverting) price. Because `_prefund` uses this price to pull ERC-20 funds directly from the UserOp sender via Permit/Permit2, an artificially low price lets an attacker drain gas sponsorship cheaply, while `swapAndDeposit`'s `amountOutMin` (also derived from the same unguarded oracle read) could be manipulated to allow value extraction from the accrued treasury surplus during the swap.

### Likelihood Explanation
Requires an actual sequencer downtime/restart event on Arbitrum, Optimism, or Base (or a similar L2-specific stale-feed condition), which is an infrequent but historically observed occurrence. Any unprivileged UserOp sender/solver interacting with the paymaster during that window is a normal expected caller, so exploitation requires no elevated privileges — it only requires timing a transaction to the outage window.

### Recommendation
Add an L2 sequencer-uptime-feed check (per Chainlink's documented example) alongside the existing staleness/positivity checks in `_getOraclePrice`: read the `SequencerUptimeFeed`'s `latestRoundData()`, revert if `answer == 1` (sequencer down), and enforce a grace period after `startedAt` before trusting subsequent price feed reads, only where a sequencer-uptime feed exists for the target chain (Arbitrum, Optimism, Base).

### Proof of Concept
1. Deploy/observe `SimplexPaymaster` on Arbitrum (`0x7281Bccb4f0BCE44F3B8542d1fC5e51c2F5fC08C`).
2. Simulate/await an Arbitrum sequencer outage such that the `nativeOracle`/`tokenOracle` feed's `updatedAt` stalls but remains within `maxOracleAge` (up to 90,000s / 7 days per deployment config).
3. Call `getTokenPrice`/submit a UserOp through `_fetchDetails` → `_tokenPrice` → `_getOraclePrice`; observe the stale price is accepted without any sequencer-liveness check, since `_getOraclePrice` (`evm/src/utils/SimplexPaymaster.sol:662-676`) has no such gate.
4. An attacker times a UserOp or calls `swapAndDeposit` during this window to receive an unfavorable exchange rate for the paymaster/treasury.

    /// @dev Returns the token to charge and its price relative to native gas.
    ///
    ///      PaymasterERC20 computes `erc20Cost = weiCost * tokenPrice / 1e18`,
    ///      so tokenPrice must be token base units per wei, scaled by 1e18:
    ///        tokenPrice = (nativeUsd * 10^tokenDecimals) / tokenUsd
    ///      e.g. BNB at $600, USDC at $1 with 6 decimals: 0.001 BNB (1e15 wei)
    ///      should cost 0.60 USDC (600000 units), giving tokenPrice = 6e8, which
    ///      is exactly (600e8 * 1e6) / 1e8. Markup is applied on top.
    function _fetchDetails(
        PackedUserOperation calldata userOp,
        bytes32 /* userOpHash */
    )
        internal
        view
        override
        returns (uint256 validationData, IERC20 token, uint256 tokenPrice)
    {
        bytes calldata data = userOp.paymasterData();
        if (data.length < 21) revert InvalidPaymasterData(data.length);

        uint8 mode = uint8(data[0]);
        if (mode != 0x00 && mode != 0x02) revert InvalidMode(mode);

        address tokenAddr = address(bytes20(data[1:21]));

        TokenConfig memory cfg = tokenConfigs[tokenAddr];
        if (address(cfg.tokenOracle) == address(0)) revert TokenNotRegistered(tokenAddr);
        if (!cfg.active) revert TokenNotActive(tokenAddr);

        tokenPrice = _tokenPrice(cfg);
        token = IERC20(tokenAddr);
        validationData = 0; // no time-range restriction

        if (mode == 0x02) {
            (,,, uint256 deadline,,,) = _parsePermit2Data(data);
            // Surfacing the permit deadline as validUntil lets bundlers drop
            // expiring ops instead of discovering it through a Permit2 revert.
            uint48 validUntil = deadline > type(uint48).max ? 0 : uint48(deadline);
            validationData = ERC4337Utils.packValidationData(true, 0, validUntil);
        }
    }

    function _tokenPrice(TokenConfig memory cfg) internal view returns (uint256) {
        uint256 nativeUsd = _getOraclePrice(nativeOracle, nativeOracleDecimals);
        uint256 tokenUsd = _getOraclePrice(cfg.tokenOracle, cfg.tokenOracleDecimals);

        return (nativeUsd * (10 ** cfg.tokenDecimals) * (10_000 + markupBps)) / (tokenUsd * 10_000);
    }

    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
