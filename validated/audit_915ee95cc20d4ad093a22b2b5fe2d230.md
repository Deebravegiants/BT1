### Title
Unauthorized `transferFrom` of arbitrary victim's approved tokens via `originalSender` field in `DepositOnChainUtxosExternalAction` - (File: `contracts/external-actions/DepositOnChainUtxosExternalAction.sol`)

### Summary
`DepositOnChainUtxosExternalAction::runAction` pulls ERC20 tokens from `circomData.originalSender` — a caller-supplied address that is **not** cross-checked against `msg.sender` (the actual `transact()` caller) or against any signature — and moves them to the Hinkal contract while crediting the resulting on-chain UTXOs to the attacker's own `stealthAddressStructure`. Any address that has ever left a non-zero ERC20 allowance to Hinkal (e.g. from `HinkalWrapper._pullAndApproveDepositTokens`, or a normal `prooflessDeposit`/`transact()` deposit approval that wasn't fully consumed or was left standing) can have those tokens pulled and stolen by an unrelated third party generating their own valid proof.

### Finding Description
`runAction` sets:
```solidity
address userAddress = circomData.originalSender;
...
transferERC20TokenFrom(tokenAddress, userAddress, msg.sender, tokenTotal);
``` [1](#0-0) 

`originalSender` is an arbitrary `address` field of `CircomData` with no on-chain requirement that it equal `msg.sender` or the transaction's `externalActionData.externalAddress`/`tx.origin`. It is only folded into `calldataHash2` (and thus indirectly into `circomData.calldataHash`, one circuit public input) via `CircomDataBuilder::getHashedCalldata2`: [2](#0-1) 
and `calldataHash` is passed to the SNARK verifier as a public input in `formBasicInput`: [3](#0-2) 

This binding only proves that the *prover* (whoever generated the proof) chose that `originalSender` value — it does **not** prove that `originalSender` consented to, signed, or is even aware of the transaction. Unlike the Emporium flow (`EmporiumUpgradeable`), which recovers a signer via EIP-712/ECDSA and only moves funds from that signer's own `HinkalWallet`, there is no analogous authorization check tying `originalSender` to a real signature here.

Because `deltaAmounts[i]` is required to be `0` for every targeted token index (enforced via `onChainCreation[i] = true`, which forces `_calculateDeltaAmount` to return `0`): [4](#0-3) 
the shielded balance equation the proof enforces stays internally consistent (net zero shielded change for that token), while the actual, real-world token movement happens entirely outside the shielded-balance equality — pulled straight from `originalSender`'s wallet using their standing ERC20 allowance to Hinkal. Any address that has approved Hinkal for token transfers (a common pattern via `HinkalWrapper._pullAndApproveDepositTokens`, or leftover allowance from a prior deposit) can be named as `originalSender` by an unrelated attacker who supplies their own valid proof and their own `stealthAddressStructure`, receiving the resulting on-chain UTXO (i.e., stealing the shielded value credit) while the victim loses the pulled tokens.

This is the same bug class as the referenced `AccountableFixedTerm::coverDefault` report: a value-moving parameter (`provider`/`originalSender`) is used to `transferFrom` an address that never authorized this specific call, breaking the intended equality that only the depositor authorizing the deposit should have funds pulled from them.

### Impact Explanation
Critical — direct theft of externally-approved user funds. Any unprivileged actor able to call `transact()` (no special role required) can drain ERC20 tokens from any third-party address that has (or previously had) a standing allowance to Hinkal, crediting themselves shielded UTXOs backed by stolen funds.

### Likelihood Explanation
High. Standing/leftover ERC20 approvals to Hinkal are a normal byproduct of the deposit flows (`HinkalWrapper._pullAndApproveDepositTokens`, `Hinkal._internalTransact`/`prooflessDeposit`), so victim addresses with nonzero allowance are expected to exist in practice. Exploitation requires only crafting a valid proof with `onChainCreation=true` / `amountChanges=0` for the targeted token and setting `originalSender` to the victim — no cooperation or privilege from the victim is needed.

### Recommendation
Remove the free-form `originalSender` pull-target logic from `DepositOnChainUtxosExternalAction::runAction`. Either:
- Require `userAddress == msg.sender`/the actual `transact()` caller (analogous to the `externalActionData.externalAddress == msg.sender` check already used in `Hinkal::_internalTransact`), or
- Bind `originalSender` to a real, verified signature (EIP-712/ECDSA) proving that address explicitly authorized this specific transfer, similar to the Emporium signer-recovery pattern.

### Proof of Concept
1. Victim `V` previously called `HinkalWrapper.prooflessDeposit` (or any flow using `_pullAndApproveDepositTokens`/`transferERC20TokenFrom`), leaving `allowance(V, Hinkal) > 0` for token `T` (common when deposit approvals aren't tightly bound to exact one-time amounts, or a prior deposit leaves residual allowance).
2. Attacker `A` generates a valid Hinkal proof for a `transact()` call where:
   - `erc20TokenAddresses = [T]`, `onChainCreation = [true]`, `amountChanges = [0]` (so `_calculateDeltaAmount` returns 0 — no shielded balance change is required for `T`).
   - `externalActionData.externalAddress` = `DepositOnChainUtxosExternalAction` contract, with `externalActionMetadata` encoding `utxoAmounts = [[X]]` where `X ≤ allowance(V, Hinkal)`.
   - `originalSender = V` (the victim), `stealthAddressStructure` = attacker's own.
3. `Hinkal._externalTransact` invokes `DepositOnChainUtxosExternalAction.runAction`, which calls `transferERC20TokenFrom(T, V, msg.sender, X)`, pulling `X` tokens from `V` into Hinkal, and creates an on-chain UTXO of amount `X` under the attacker's `stealthAddressStructure`.
4. Attacker now holds a shielded UTXO worth `X` of token `T`, funded entirely by `V`'s allowance, without `V`'s knowledge or consent for this specific transaction. [5](#0-4) [6](#0-5)

    function runAction(
        CircomData calldata circomData,
        int256[] calldata deltaAmounts
    ) external override onlyAllowedRecipient returns (UTXO[] memory utxoSet) {
        uint256 tokenCount = circomData.erc20TokenAddresses.length;
        require(
            tokenCount > 0 && deltaAmounts.length == tokenCount,
            "DepositOnChainUtxosExternalAction: token count mismatch"
        );

        address userAddress = circomData.originalSender;
        require(
            userAddress != address(0),
            "DepositOnChainUtxosExternalAction: Invalid originalSender"
        );

        uint256[][] memory utxoAmounts = abi.decode(
            circomData.externalActionData.externalActionMetadata,
            (uint256[][])
        );
        require(
            utxoAmounts.length == tokenCount,
            "DepositOnChainUtxosExternalAction: metadata length mismatch"
        );

        utxoSet = new UTXO[](countUtxos(utxoAmounts));

        uint256 utxoIndex = 0;
        for (uint256 i = 0; i < tokenCount; i++) {
            require(
                deltaAmounts[i] == 0,
                "DepositOnChainUtxosExternalAction: Delta amount must be zero"
            );

            address tokenAddress = circomData.erc20TokenAddresses[i];
            uint256 tokenTotal = 0;

            for (uint256 j = 0; j < utxoAmounts[i].length; j++) {
                uint256 amount = utxoAmounts[i][j];
                require(
                    amount > 0,
                    "DepositOnChainUtxosExternalAction: UTXO amount must be positive"
                );
                tokenTotal += amount;

                utxoSet[utxoIndex] = UTXO({
                    amount: amount,
                    erc20Address: tokenAddress,
                    stealthAddressStructure: circomData.stealthAddressStructure,
                    timeStamp: circomData.timeStamp + utxoIndex
                });
                utxoIndex++;
            }

            if (tokenAddress != address(0) && tokenTotal > 0) {
                transferERC20TokenFrom(
                    tokenAddress,
                    userAddress,
                    msg.sender,
                    tokenTotal
                );
            }
        }

        emit BlockedUtxosCreated();
    }
