### Title
Unrestricted `CallDispatcher.dispatch()` Enables Theft of Residual Tokens Left Behind by Predispatch Swaps - (File: evm/src/utils/CallDispatcher.sol)

### Summary
`CallDispatcher.dispatch()` is a fully public, unrestricted entry point that executes arbitrary `Call[]` batches from `msg.sender`'s own context [3](#0-2) . This contract is deployed once per chain and shared across `IntentGatewayV2`, `HyperFungibleToken`, and `WrappedHyperFungibleToken`, all of which route calldata execution and token custody through the same `dispatcher` address [4](#0-3) [5](#0-4) . In `IntentGatewayV2`'s predispatch flow, tokens declared in `order.predispatch.assets` are transferred to the shared `dispatcher` and an arbitrary swap call is executed there, but only the tokens explicitly declared in `order.inputs` are swept back afterward [6](#0-5) . Any predispatch asset token that differs from the eventual `order.inputs` token (e.g. a partial-use swap, or a multi-hop route that leaves an intermediate token balance) is never swept and remains stranded on the `CallDispatcher`. Because `dispatch()` has no authorization check, any third party can call it directly with a `Call[]` that transfers that residual balance to themselves — the exact bug class described in the report, where `ProxyCall`'s `call()`/`approveTokenExecuteAndVerify()` only refunded `tokenOut` and left `tokenIn` (stablecoin) residue drainable via `ProxyCall.execute()`.

### Finding Description
`CallDispatcher.dispatch(bytes memory encoded)` decodes an ABI-encoded `Call[]` and executes each call in its own context with no `msg.sender` restriction, no owner check, and no caller allowlist [3](#0-2) . This makes it structurally identical to `ProxyCall.execute()` from the report — a generic "call anything" proxy that anyone can invoke — except that Hyperbridge's `CallDispatcher` additionally holds transient token balances belonging to multiple different apps and multiple different orders concurrently, since it is a single shared instance rather than a per-transaction ephemeral contract.

In `IntentGatewayV2`'s predispatch handling, `order.predispatch.assets` (arbitrary tokens, e.g. the user's ETH or source token) are transferred to `dispatcher`, then `order.predispatch.call` (attacker/solver-controlled swap calldata) is executed on the dispatcher [7](#0-6) . Afterward, the gateway sweeps back only the balances of tokens listed in `order.inputs` [8](#0-7) . If the predispatch call is a swap that does not fully consume the input token (identical to the "MockDEXRouter.swap2" pattern in the report's PoC, which only uses a fraction of `amountIn`), the un-consumed predispatch-asset token — which is not part of `order.inputs` — is left sitting on the shared `CallDispatcher` and is never accounted for or swept by the gateway logic.

Because the same `CallDispatcher` instance is reused across every order and every app configured with that dispatcher address, this residue does not disappear at the end of the transaction — it persists in the dispatcher's balance until the next unrelated call. Since `dispatch()` is callable by anyone, an attacker can then submit their own `Call[]` (e.g. `IERC20.transfer(attacker, balance)`) directly to `CallDispatcher.dispatch()` to steal any such residual balance, exactly mirroring how the report's attacker called `ProxyCall.execute()` with a crafted `transfer` payload to drain `ProxyCall`'s leftover `STABLECOIN`.

### Impact Explanation
Any residual ERC20 or native-token balance left on the shared `CallDispatcher` by an imperfect predispatch swap (or by any other integrator using the same dispatcher, since it is a general-purpose shared utility contract) is permanently exposed to theft by an arbitrary third party, resulting in direct loss of user/solver funds that were intended to be escrowed or returned. This is a direct, concrete theft-of-funds vulnerability class, matching the reachable "intent solver" fill path explicitly in scope.

### Likelihood Explanation
The predispatch call is order-author/solver-supplied calldata routed to arbitrary DEX/DeFi targets, so any swap that does not consume 100% of the input (partial fills, exact-output swaps, multi-hop routes with dust, or a malicious/buggy target) will strand tokens on the dispatcher. Given `CallDispatcher.dispatch()` is public and un-gated, exploitation requires only a single unprivileged transaction by any observer monitoring the dispatcher's token balances — no special privilege, timing race with governance, or node compromise is needed.

### Recommendation
Add an authorization check to `CallDispatcher.dispatch()` restricting callers to a configured, trusted set of app contracts (e.g., the specific `IntentGatewayV2`/HFT instances that are meant to use it), or make the dispatcher single-use/ephemeral per call so no balance can persist between invocations. Additionally, in `IntentGatewayV2`'s predispatch flow, sweep *all* tokens that were transferred to the dispatcher as `predispatch.assets` (not only those matching `order.inputs`) back to the gateway after `dispatch()` completes, so no token type can be silently stranded.

### Proof of Concept
1. User places a cross-chain/same-chain order with `predispatch.assets = [USDC: 1000]` and `predispatch.call` encoding a swap that (like the report's `MockDEXRouter.swap2`) only consumes a third of the input, e.g. `swapExactTokensForTokens`-style call that pulls `amountIn/2` USDC but only delivers `amountIn/3` of `order.inputs` token (say DAI) back.
2. `IntentGatewayV2` transfers 1000 USDC to `CallDispatcher`, executes the predispatch call, then sweeps back only the DAI balance matching `order.inputs`; the leftover ~500 USDC remains on `CallDispatcher` [6](#0-5) .
3. An unrelated attacker calls `CallDispatcher.dispatch(abi.encode(Call[]))` directly with `Call({to: USDC, value: 0, data: abi.encodeWithSelector(IERC20.transfer.selector, attacker, USDC.balanceOf(dispatcher))})` [3](#0-2) .
4. The call succeeds because `dispatch()` performs no caller check, and the attacker receives the stranded 500 USDC that belonged to the order's escrow flow.

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
