### Title
No vulnerability - default_account fallback cannot create unfunded lamports due to multi-layer conservation checks

### Summary
The `default_account` fallback in `load_transaction_account` (svm/src/account_loader.rs) does materialize a zero-lamport, `RENT_EXEMPT_RENT_EPOCH` account for writable-but-nonexistent keys, but this cannot be leveraged to create lamports out of nothing. Both per-instruction and per-transaction lamport-conservation invariants, enforced independently of this loader, reject any unbalanced creation before commit.

### Finding Description
When a writable account key referenced by a message does not exist, `load_transaction_account` in [1](#0-0)  falls back to `AccountSharedData::default()` with `rent_epoch` set to `RENT_EXEMPT_RENT_EPOCH`, which has zero lamports and empty data. This is expected behavior (e.g. for `system_instruction::create_account` targets) and by itself introduces no value.

Any lamport increase a program instruction performs on this or any other account is tracked via `add_lamports_delta` in [2](#0-1) , called from `BorrowedInstructionAccount::set_lamports` in [3](#0-2) . At the end of every instruction, `TransactionContext::pop` checks that the net lamports delta across that single instruction invocation is zero, returning `InstructionError::UnbalancedInstruction` otherwise, in [4](#0-3) . This means any program (including a malicious/no-op program without a matching `System::CreateAccount` funding transfer) that increases the default account's lamports without decreasing some other account's lamports by the same amount within the same instruction will fail immediately with `UnbalancedInstruction`.

Even if that per-instruction check were somehow bypassed, `execute_loaded_transaction` in [5](#0-4)  computes `lamports_before_tx` as the sum of all loaded account lamports before execution, and after execution, in [6](#0-5) , re-sums post-execution lamports and rejects the transaction with `TransactionError::UnbalancedTransaction` if the sums differ. This is a second, independent conservation check at the whole-transaction level.

Additionally, `verify_changes`/`check_rent_state` in [7](#0-6)  would flag the default account transitioning into an under-funded, non-rent-exempt state (`InsufficientFundsForRent`) if it ends up partially funded but not rent-exempt, as demonstrated in the existing test `test_basic_rent_transition_violation`.

Neither of these guards is bypassable by referencing a nonexistent writable pubkey; they operate purely on the final `TransactionContext` account state and apply uniformly to freshly materialized default accounts and pre-existing accounts alike.

### Impact Explanation
No impact. Capitalization mismatch or lamport creation from nothing cannot occur through this path, since both instruction-level (`UnbalancedInstruction`) and transaction-level (`UnbalancedTransaction`) lamport conservation checks are independent of, and unaware of, whether an account originated from the `default_account` fallback branch. Any attempt to fund such an account without an equal and opposite debit elsewhere in the same transaction is rejected before commit.

### Likelihood Explanation
Not applicable — the described exploit path is blocked deterministically by existing checks (`transaction-context/src/transaction.rs::pop`, `svm/src/transaction_processor.rs::execute_loaded_transaction`) that run on every transaction, not through best-effort or optional validation.

### Recommendation
No fix required for this specific concern. If further hardening is desired, consider adding an explicit unit test exercising a writable reference to a nonexistent account whose balance is increased without a matching decrease elsewhere, asserting the transaction is rejected with `InstructionError::UnbalancedInstruction` or `TransactionError::UnbalancedTransaction`, to guard against future regressions in the conservation checks.

    /// Overwrites the number of lamports of this account (transaction wide)
    pub fn set_lamports(&mut self, lamports: u64) -> Result<(), InstructionError> {
        // An account not owned by the program cannot have its balance decrease
        if !self.is_owned_by_current_program() && lamports < self.get_lamports() {
            return Err(InstructionError::ExternalAccountLamportSpend);
        }
        // The balance of read-only may not change
        if !self.is_writable() {
            return Err(InstructionError::ReadonlyLamportChange);
        }
        // don't touch the account if the lamports do not change
        let old_lamports = self.get_lamports();
        if old_lamports == lamports {
            return Ok(());
        }

        let lamports_balance = (lamports as i128).saturating_sub(old_lamports as i128);
        self.transaction_context
            .accounts
            .add_lamports_delta(lamports_balance)?;

        self.touch()?;
        self.account.set_lamports(lamports);
        Ok(())
    }

    pub fn pop(&mut self) -> Result<(), InstructionError> {
        if self.instruction_stack.is_empty() {
            return Err(InstructionError::CallDepth);
        }
        // Verify (before we pop) that the total sum of all lamports in this instruction did not change
        let detected_an_unbalanced_instruction =
            self.get_current_instruction_context()
                .and_then(|instruction_context| {
                    // Verify all executable accounts have no outstanding refs
                    self.accounts
                        .try_borrow_mut(
                            instruction_context.get_index_of_program_account_in_transaction()?,
                        )
                        .map_err(|err| {
                            if err == InstructionError::AccountBorrowFailed {
                                InstructionError::AccountBorrowOutstanding
                            } else {
                                err
                            }
                        })?;
                    Ok(self.accounts.get_lamports_delta() != 0)
                });
        // Always pop, even if we `detected_an_unbalanced_instruction`
        self.instruction_stack.pop();
        if let Some(instr_idx) = self.instruction_stack.last() {
            self.transaction_frame.current_executing_instruction = *instr_idx as u16;
        }
        if detected_an_unbalanced_instruction? {
            Err(InstructionError::UnbalancedInstruction)
        } else {
            Ok(())
        }
    }
