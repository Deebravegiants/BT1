### Title
`EngineMeter::charge_ref_time` never persists the fuel deduction, letting a contract execute more wasm instructions than its paid `gas_limit` - ([File: substrate/frame/contracts/src/gas.rs])

### Summary
`EngineMeter::charge_ref_time` computes the fuel amount to deduct for host-function overhead but discards the result of `checked_sub` instead of assigning it back to `self.fuel`. The `Syncable` value handed back to the wasmi engine (and used to reset its live fuel counter) is therefore the *pre-deduction* fuel value, so the engine's actual instruction-execution budget is never reduced by the ref_time cost of host calls, letting more real wasm computation run than the extrinsic's `gas_limit` should allow.

### Finding Description
`EngineMeter::charge_ref_time` is: [1](#0-0) 

```rust
fn charge_ref_time(&mut self, ref_time: u64) -> Result<Syncable, DispatchError> {
	let amount = ref_time
		.checked_div(T::Schedule::get().ref_time_by_fuel())
		.ok_or(Error::<T>::InvalidSchedule)?;

	self.fuel.checked_sub(amount).ok_or_else(|| Error::<T>::OutOfGas)?;
	Ok(Syncable(self.fuel))
}
```

The result of `self.fuel.checked_sub(amount)` is never assigned back to `self.fuel`; the method only uses it to check for underflow (raising `OutOfGas` if it would underflow) and then returns `Syncable(self.fuel)` — the **unmodified, pre-deduction** value.

`charge_ref_time` is invoked from `GasMeter::sync_to_executor`: [2](#0-1) 

which is called after leaving each host function, to compute how much *ref_time* was consumed by the host function's own weight-metered work (storage ops, hashing, event deposits, etc., charged via `GasMeter::charge`) and translate it into wasmi "fuel" units so that the live wasmi engine's fuel counter — the actual hard limiter of how many wasm instructions it will execute before trapping — is reduced accordingly. The `Syncable` returned here is what the caller in `substrate/frame/contracts/src/wasm/mod.rs` writes back into the wasmi store's fuel counter.

Because `self.fuel` is never actually decremented in `charge_ref_time`, every host-function call effectively "refunds" the engine's fuel counter back up to its pre-call level instead of debiting it for the host function's ref_time cost. `GasMeter::gas_left` (the frame-level weight ledger, updated correctly via `charge()` and via `sync_from_executor`/`EngineMeter::set_fuel`) still correctly tracks total weight spent and will eventually reject the call with `OutOfGas` — but only at the *next* `sync_from_executor` call (i.e., the next host function entry). Between two host-function calls, the wasmi engine is free to execute wasm instructions bounded only by its own (incorrectly inflated) fuel counter, not by the true remaining `gas_left`. A contract that performs enough host calls (each of which "leaks" unspent fuel back into the engine) followed by a tight compute loop with no further host calls can consume real CPU time beyond what its `gas_limit` should allow, since the wasmi trap will fire late (based on the inflated fuel) or not distinguish the excess until the next host call is made — which the attacker can simply avoid making.

### Impact Explanation
This is a gas/weight metering bypass: an unprivileged contract caller can craft a WASM contract that interleaves host-function calls (each of which "leaks" back unspent fuel due to the missing assignment) with a final long-running compute loop containing no further host calls. The engine's actual instruction budget exceeds what the paid `gas_limit` implies, allowing more computation per unit of paid weight than intended — undermining block-execution time bounds and enabling weight-metering DoS/resource-exhaustion against block authors, without exceeding the extrinsic's nominal `gas_limit` bookkeeping.

### Likelihood Explanation
The bug is deterministic and always triggers on the very first `sync_to_executor` call after any host function that charges nonzero additional weight (nearly all host functions - `seal_get_storage`, `seal_set_storage`, `seal_call`, hashing functions, `seal_deposit_event`, etc.). No special preconditions beyond deploying and calling an arbitrary contract are needed — this is fully reachable via a standard signed `pallet_contracts::call`/`instantiate` extrinsic, requiring no privileged origin.

### Recommendation
Fix `charge_ref_time` to actually persist the decrement:
```rust
fn charge_ref_time(&mut self, ref_time: u64) -> Result<Syncable, DispatchError> {
	let amount = ref_time
		.checked_div(T::Schedule::get().ref_time_by_fuel())
		.ok_or(Error::<T>::InvalidSchedule)?;
	self.fuel = self.fuel.checked_sub(amount).ok_or_else(|| Error::<T>::OutOfGas)?;
	Ok(Syncable(self.fuel))
}
```

### Proof of Concept
Rust unit test in `substrate/frame/contracts/src/gas.rs` tests module extending `EngineMeter`/`GasMeter` behavior:
1. Construct `GasMeter::<Test>::new(gas_limit)`.
2. Call `sync_from_executor(engine_fuel)` with an initial fuel value, then perform a `charge(SimpleToken(N))` to simulate host-function weight cost, then call `sync_to_executor(before)`.
3. Assert that the internal fuel value returned by the second `sync_from_executor` call (simulating the wasmi engine being handed the `Syncable` value and later reporting back an unrelated small decrement) reflects a reduction of `N / ref_time_by_fuel()`; with the current code the assertion fails because `self.fuel` was never reduced — proving the desync.
4. A higher-level integration test can deploy a contract that calls a host function `M` times (each incurring weight `W`), then loops N times with a low `gas_limit`; compare `GasMeter::gas_consumed()` reported at `OutOfGas` against the number of wasmi instructions actually executed (obtainable via a differential wasmi fuel-tracking harness) and assert they diverge by approximately `M * W / ref_time_by_fuel()` fuel units, demonstrating the contract ran more real computation than its `gas_limit` permitted.

	/// Hand over the gas metering responsibility from this meter to the executor.
	///
	/// Needs to be called when leaving a host function in order to calculate how much
	/// gas needs to be charged from the **executor**. It updates the last seen executor
	/// total value so that it is correct when `sync_from_executor` is called the next time.
	///
	/// It is important that this does **not** actually sync with the executor. That has
	/// to be done by the caller.
	pub fn sync_to_executor(&mut self, before: RefTimeLeft) -> Result<Syncable, DispatchError> {
		let ref_time_consumed = before.0.saturating_sub(self.gas_left().ref_time());
		self.engine_meter.charge_ref_time(ref_time_consumed)
	}
