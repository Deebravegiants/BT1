Confirmed exploit path: `gateway.ProcessRequest` at `core/services/gateway/gateway.go:221-295` is the entry point invoked directly by the internet-facing user-port HTTP server [1](#0-0) . Audit Report

## Title
Unauthenticated request-ID griefing DOS on the confidential relay gateway handler - ([File: core/services/gateway/handlers/confidentialrelay/handler.go])

## Summary
The `confidentialrelay` gateway handler's `HandleJSONRPCUserMessage` inserts every incoming request into the shared `activeRequests` map keyed solely by the caller-supplied `req.ID`, with no authentication or per-caller namespacing applied first. Any unauthenticated client able to reach the gateway's user-facing HTTP port can pre-register a chosen `req.ID`, causing a legitimate request with the same ID to be rejected with "request ID already exists" and denying service to that specific relay request.

## Finding Description
The gateway's `ProcessRequest` function is the HTTP entry point served on the public user port and performs no caller authentication before decoding and dispatching JSON-RPC requests — it only checks that `req.ID` is ≤200 characters. The request flows unauthenticated through `multiHandler.HandleJSONRPCUserMessage` into `confidentialrelay.handler.HandleJSONRPCUserMessage`, which checks only that `req.ID` is non-empty and within length limits before calling `newActiveRequest`. That function performs the uniqueness check directly against the raw, caller-supplied `req.ID` as the map key, with no derivation from an authenticated identity. This differs from the `vault` handler's sibling implementation, which routes requests through `GatewayVaultRequestProcessor.authorizeAndStamp` to authenticate the caller and prefix the ID with the authorized owner before the same style of collision check — a mitigation entirely absent from `confidentialrelay`.

## Impact Explanation
An attacker who can guess, observe, or predict the `req.ID` a victim will submit for a `secrets_get` or `capability_exec` relay call can submit it first, causing the victim's legitimate request to be rejected outright. This is an unauthenticated denial-of-service against a specific relay request, mapping to a gateway request-availability/DOS impact category — it does not achieve secret exfiltration, fund movement, or impersonation of the victim's response, only blocking of that one in-flight request until it expires (default `requestTimeout` ~30s).

## Likelihood Explanation
Exploitability is fully gated on the attacker's ability to know the exact `req.ID` before the victim submits it. The report does not demonstrate that IDs are predictable, sequential, or otherwise observable to an external unauthenticated attacker in this codebase; it only speculates about possible ID-generation weaknesses ("if IDs are generated with low entropy... or are otherwise observable"). Without a demonstrated low-entropy or leaked ID-generation scheme, this remains a low-likelihood, largely theoretical race condition requiring precise timing and ID knowledge that the report does not prove is attainable by an unprivileged external caller in practice.

## Recommendation
Bind the `activeRequests` key to an authenticated caller/session/connection identifier before the duplicate check in `newActiveRequest`, following the same pattern used by `GatewayVaultRequestProcessor.authorizeAndStamp`, rather than trusting the bare client-supplied `req.ID`.

## Proof of Concept
1. Determine or guess a victim's upcoming `req.ID` for a `secrets_get`/`capability_exec` relay call.
2. Submit a JSON-RPC request to the gateway's user HTTP port with that exact `req.ID` before the victim's request arrives.
3. Observe the victim's subsequent request fails with "request ID already exists" as demonstrated by `TestConfidentialRelayHandler_DuplicateRequestID`.

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], labels requestLabels, callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID, "executionID", labels.ExecutionID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		labels:    labels,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

	req *jsonrpc.Request[json.RawMessage],

	}
