Audit Report

## Title
Unauthenticated exposure of LOOP plugin `/discovery`, `/plugins/:name/metrics`, and `/plugins/:name/debug/pprof/*` endpoints enables information disclosure and DoS - (File: core/web/router.go, core/web/loop_registry.go)

## Summary
`loopRoutes` in `core/web/router.go` registers the `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` handlers directly on the public `api` gin group with no authentication middleware, unlike other sensitive routes such as `debugRoutes` and the authenticated `/v2` group. This allows any unauthenticated remote client that can reach the node's HTTP port to enumerate plugin discovery data, pull plugin metrics, and trigger/consume LOOP plugin pprof profiling and heap/goroutine dumps.

## Finding Description
`NewRouter` creates a single `api` route group protected only by a rate limiter and a cookie-session initializer (`sessions.Sessions`), neither of which performs authentication: [1](#0-0) 

It then calls `loopRoutes(app, api)` directly on this unauthenticated group, in contrast to `debugRoutes`, which explicitly wraps `/debug/vars` in `auth.Authenticate(...)`: [2](#0-1) 

`loopRoutes` itself has no auth wrapper at all: [3](#0-2) 

The handlers proxy attacker-supplied path/query parameters to internal LOOP plugin debug servers with no credential check inside the handler code: `discoveryHandler` returns plugin names/hosts unconditionally, `pluginMetricHandler` forwards to the plugin's `/metrics`, and `pluginPPROFHandler`/`pluginPPROFPOSTSymbolHandler` forward to the plugin's `/debug/pprof/*` endpoints using an attacker-controlled `seconds` query parameter that also sets the forwarding timeout: [4](#0-3) 

The rest of the router confirms that other exposed endpoints requiring protection are explicitly wrapped (`sessionRoutes` uses `auth.Authenticate` for `DELETE /sessions`, and `v2Routes` wraps its authenticated group with `auth.Authenticate(..., AuthenticateByToken, AuthenticateBySession)`), reinforcing that `loopRoutes` is the outlier lacking this wrapper: [5](#0-4) [6](#0-5) 

## Impact Explanation
An unauthenticated remote actor can call `/discovery` to enumerate internal plugin names/topology, call `/plugins/:name/metrics` to read plugin metrics, and call `/plugins/:name/debug/pprof/heap`, `/goroutine`, or `/profile?seconds=N` to obtain memory dumps or hold open CPU-profiling sessions against LOOP plugin processes — all without any session cookie, token, or API key. This maps to an in-scope "node API authentication bypass / information disclosure" category since these endpoints sit on the same public router as authenticated `/v2/*` routes but skip `auth.Authenticate` entirely, and pprof heap/goroutine dumps can leak sensitive in-memory application state beyond mere non-confidential server metadata.

## Likelihood Explanation
No credentials, tokens, or session state are required; any client capable of sending an HTTP request to the node's configured web/API port can trigger these handlers repeatedly, matching the "unprivileged actor" threshold required for a valid finding.

## Recommendation
Wrap `loopRoutes` (or at minimum the pprof and metrics handlers) with the same `auth.Authenticate(app.AuthenticationProvider(), ...)` middleware used by `debugRoutes` and the authenticated `/v2` group, or move these debug/discovery endpoints to a separate internal-only listener not exposed on the public API router.

## Proof of Concept
1. Start a chainlink node with the standard web server enabled and at least one LOOP plugin registered.
2. Without any session cookie or `X-API-KEY`/`X-API-SECRET` headers, send `GET http://<node>:<port>/discovery` — returns plugin discovery JSON per `discoveryHandler`.
3. Send `GET http://<node>:<port>/plugins/<plugin-name>/debug/pprof/heap` — returns the plugin's heap dump via `pluginPPROFHandler` with no auth check.
4. Send `GET http://<node>:<port>/plugins/<plugin-name>/debug/pprof/profile?seconds=60` repeatedly from multiple unauthenticated connections to hold open long-running profiling requests, per the `pprofURLVals`/`doRequest` timeout logic in `core/web/loop_registry.go`.

const PPROFOverheadSeconds = 30

func pprofURLVals(gc *gin.Context) (urlVals url.Values, timeout time.Duration) {
	urlVals = make(url.Values)
	if db, ok := gc.GetQuery("debug"); ok {
		urlVals.Set("debug", db)
	}
	if gc, ok := gc.GetQuery("gc"); ok {
		urlVals.Set("gc", gc)
	}
	timeout = PPROFOverheadSeconds * time.Second
	if sec, ok := gc.GetQuery("seconds"); ok {
		urlVals.Set("seconds", sec)
		if i, err := strconv.Atoi(sec); err == nil {
			timeout = time.Duration(i+PPROFOverheadSeconds) * time.Second
		}
	}
	return urlVals, timeout
}

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
