### No vulnerability found for this question.

**Rationale:** `validateEthAddress` in `packages/intents-sdk/src/lib/validateAddress.ts` intentionally performs format-only validation (rejecting only the null address and the well-known burn address `0x...dead`), and `compareAddresses` in `packages/intents-sdk/src/lib/compareAddresses.ts` is scoped narrowly to prevent withdrawing a token to its own contract address (`DestinationAddressMatchesTokenAddressError` in `hot-bridge.ts` `validateWithdrawal`, lines 277-284). Neither function claims, nor is documented to guarantee, that an arbitrary EVM address can actually receive value (e.g., is an EOA, has a payable fallback, etc.).

The scenario described requires the withdrawal-initiating user to supply `destinationAddress` themselves. This is not a case of an attacker manipulating a counterparty's funds, replaying a signature, or misrouting someone else's assets — it is the account owner directing their own withdrawal to an address they chose. Sending funds to a syntactically-valid but functionally-incompatible contract (e.g., a Gnosis Safe without a receive/fallback) is precisely the "funds sent by mistake to a correctly validated address" case that is explicitly out of scope per the rules, and also reflects a trust/documentation assumption about what "valid destination" means for a given bridge, not a code defect creating cross-user impact. function validateEthAddress(address: string) {
	if (
		address === "0x0000000000000000000000000000000000000000" ||
		address.toLowerCase() === "0x000000000000000000000000000000000000dead"
	) {
		return false;
	}
	return isAddress(address, { strict: true });
}

	async validateWithdrawal(args: {
		assetId: string;
		amount: bigint;
		destinationAddress: string;
		logger?: ILogger;
	}): Promise<void> {
		const assetInfo = this.parseAssetId(args.assetId);
		assert(assetInfo != null, "Asset is not supported");
		hotBlockchainInvariant(assetInfo.blockchain);

		if (
			validateAddress(args.destinationAddress, assetInfo.blockchain) === false
		) {
			throw new InvalidDestinationAddressForWithdrawalError(
				args.destinationAddress,
				assetInfo.blockchain,
			);
		}
		const nativeAsset = "native" in assetInfo;
		const token = nativeAsset ? "native" : assetInfo.address;
		if (
			!nativeAsset &&
			compareAddresses(token, args.destinationAddress, assetInfo.blockchain)
		) {
			throw new DestinationAddressMatchesTokenAddressError(token, args.assetId);
		}

		if (assetInfo.blockchain === Chains.Stellar) {
			const hasTrustline = await this.hotSdk.stellar.isTrustlineExists(
				args.destinationAddress,
				token,
			);

			if (!hasTrustline) {
				throw new TrustlineNotFoundError(
					args.destinationAddress,
					args.assetId,
					assetInfo.blockchain,
					token,
				);
			}
		}
	}
