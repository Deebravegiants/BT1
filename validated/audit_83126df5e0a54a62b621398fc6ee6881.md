### Title
Price-skew before Deposit/Withdraw can push `need_take_pnl_pc/coin` above real vault balances, permanently freezing swap/deposit/withdraw/withdrawpnl - (File: `program/src/math.rs`, `program/src/processor.rs`)

### Summary
`Calculator::calc_total_without_take_pnl_no_orderbook` subtracts the AMM's internally-tracked "unclaimed pnl" counters (`need_take_pnl_pc`, `need_take_pnl_coin`) from the *live* vault balances using `checked_sub(...).ok_or(AmmError::CheckedSubOverflow)?`. This function is called at the top of every core instruction — swap, deposit, withdraw, and withdrawpnl. If `need_take_pnl_pc`/`need_take_pnl_coin` is ever pushed above the corresponding vault's actual token balance, this subtraction underflows and every one of these instructions reverts, permanently bricking the pool (a DoS analogous to Moonwell's `exchangeRateStoredInternal` reverting and blocking liquidation when `totalReserves > totalCash + totalBorrows`).

### Finding Description
`calc_total_without_take_pnl_no_orderbook` computes the tradable/withdrawable reserves as `vault_amount - need_take_pnl`: [1](#0-0) 

This is invoked unconditionally in `process_deposit`, `process_withdraw`, `process_withdrawpnl`, `process_swap_base_in`/`_v2`, and `process_swap_base_out`/`_v2` before any other accounting is done: [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4) [6](#0-5) 

`need_take_pnl_pc/coin` is only mutated by `calc_take_pnl`, which is triggered on every `Deposit` and `Withdraw` (and `WithdrawPnl`) call, and derives the pnl "skim" amount purely from the *current spot* vault ratio (`x1`, `y1` normalized from the live, swap-manipulable `amm_pc_vault.amount` / `amm_coin_vault.amount`) versus a stored reference price (`target.calc_pnl_x`, `target.calc_pnl_y`): [7](#0-6) [8](#0-7) 

Because the pnl amount is a function of a single-block spot price with no TWAP/oracle protection, and the fee split (`pnl_numerator=12`, `pnl_denominator=100`, i.e. 12%) is a nontrivial fraction of the observed price move: [9](#0-8) 

any unprivileged caller can perform a large `SwapBaseIn`/`SwapBaseOut` to drastically skew the coin:pc ratio in one instruction, then immediately (same or next transaction) call `Deposit` or `Withdraw`, forcing `calc_take_pnl` to run against the artificially skewed spot ratio. This inflates `need_take_pnl_pc`/`need_take_pnl_coin` by amounts computed off the manipulated price rather than off actually-realized, durable reserve changes. The attacker can then swap back (or simply let other users' trades continue to move the vault balances), leaving `need_take_pnl_pc`/`coin` no longer consistently smaller than the corresponding vault balance for every possible future state. Once a vault's real token balance dips below the recorded `need_take_pnl_*` counter for that mint (e.g., after a legitimate withdraw or swap reduces the vault), `calc_total_without_take_pnl_no_orderbook`'s `checked_sub` fails and returns `AmmError::CheckedSubOverflow`, which propagates via `?` and aborts the instruction.

Because *every* core instruction (swap, deposit, withdraw, and even `WithdrawPnl` itself, which also calls this same function) calls `calc_total_without_take_pnl_no_orderbook` first, once this condition is triggered there is no unprivileged (or even privileged) path to reset `need_take_pnl_pc/coin` back down — `WithdrawPnl` cannot execute either, since it hits the identical underflow at the same call site: [4](#0-3) 

The pool becomes permanently frozen: no swaps, no deposits, no withdrawals, and the owner cannot even reclaim the skimmed pnl.

### Impact Explanation
This is a full, permanent denial of service on a specific pool's core functionality (swap, deposit, withdraw), freezing all LP funds and trader funds in that pool with no recovery path, since the only function that can reduce `need_take_pnl_*` (`process_withdrawpnl`) is gated behind the very same accounting call that reverts. This matches "permanent freezing of user or LP funds" per the validation criteria, reached entirely by unprivileged swap/deposit/withdraw transactions with attacker-chosen amounts.

### Likelihood Explanation
Triggering requires precise timing/amount tuning (a swap large enough to move price sufficiently, combined with a deposit/withdraw to lock in an inflated pnl skim, and enough subsequent activity or a further swap to push the corresponding vault balance below the now-inflated counter) — this is a multi-step, capital-intensive attack rather than a single trivial call, and its exact reliability depends on pool depth, existing `need_take_pnl` state, and concurrent trading activity, which could not be fully proven by static analysis alone. It is nonetheless reachable purely through the four documented swap instructions plus `Deposit`/`Withdraw`, with no privileged accounts required.

### Recommendation
Bound the pnl skim taken in `calc_take_pnl` by more than a single-block spot price (e.g., use a TWAP or clamp the skim to a fraction of realized fee accrual rather than raw price delta), and/or make `calc_total_without_take_pnl_no_orderbook` saturate/clamp to zero instead of hard-erroring, with an owner-callable recovery path (e.g., resetting `need_take_pnl_*` to the actual vault balance) that does not itself depend on the vulnerable subtraction.

### Proof of Concept
1. Attacker (or any user) sends a large `SwapBaseIn`/`SwapBaseInV2` that heavily skews `amm_coin_vault.amount` vs `amm_pc_vault.amount` relative to the pool's `target_orders.calc_pnl_x/y` reference — `process_swap_base_in_v2` reads live vault balances with no TWAP smoothing: [6](#0-5) 
2. Attacker immediately calls `Deposit` (or `Withdraw`), which invokes `calc_take_pnl` using the now-skewed spot price (`x1`, `y1`), inflating `amm.state_data.need_take_pnl_pc`/`need_take_pnl_coin` by up to 12% of the observed price delta: [10](#0-9) 
3. Attacker swaps back (or waits for normal trading) to reduce the real vault balance of one mint below the now-inflated `need_take_pnl_*` counter for that mint.
4. Any subsequent call to `Deposit`, `Withdraw`, `SwapBaseIn(V2)`, `SwapBaseOut(V2)`, or `WithdrawPnl` hits `calc_total_without_take_pnl_no_orderbook`'s `checked_sub` and returns `AmmError::CheckedSubOverflow`, permanently reverting all pool operations: [11](#0-10) 

Note: I was not able to fully simulate the numeric feasibility (exact swap sizes/depths needed to guarantee step 3 within available liquidity) using static code review alone; a Devin session with the repo's test harness (`program/src/processor.rs` test module, e.g. `test_calc_take_pnl`/`test_calc_pnl_precision`) would be needed to confirm concrete parameters that trigger the underflow end-to-end.

    pub fn calc_total_without_take_pnl_no_orderbook<'a>(
        pc_amount: u64,
        coin_amount: u64,
        amm: &'a AmmInfo,
    ) -> Result<(u64, u64), AmmError> {
        let total_pc_without_take_pnl = pc_amount
            .checked_sub(amm.state_data.need_take_pnl_pc)
            .ok_or(AmmError::CheckedSubOverflow)?;
        let total_coin_without_take_pnl = coin_amount
            .checked_sub(amm.state_data.need_take_pnl_coin)
            .ok_or(AmmError::CheckedSubOverflow)?;
        Ok((total_pc_without_take_pnl, total_coin_without_take_pnl))
    }

        target: &TargetOrders,
        amm: &mut AmmInfo,
        total_pc_without_take_pnl: &mut u64,
        total_coin_without_take_pnl: &mut u64,
        x1: U256,
        y1: U256,
    ) -> Result<(u128, u128), ProgramError> {
        // calc pnl
        let mut delta_x: u128;
        let mut delta_y: u128;
        let calc_pc_amount = Calculator::restore_decimal(
            target.calc_pnl_x.into(),
            amm.pc_decimals,
            amm.sys_decimal_value,
        );
        let calc_coin_amount = Calculator::restore_decimal(
            target.calc_pnl_y.into(),
            amm.coin_decimals,
            amm.sys_decimal_value,
        );
        let pool_pc_amount = U128::from(*total_pc_without_take_pnl);
        let pool_coin_amount = U128::from(*total_coin_without_take_pnl);
        if pool_pc_amount.checked_mul(pool_coin_amount).unwrap()
            >= (calc_pc_amount).checked_mul(calc_coin_amount).unwrap()
        {
            // last k is
            // let last_k: u128 = (target.calc_pnl_x as u128).checked_mul(target.calc_pnl_y as u128).unwrap();
            // current k is
            // let current_k: u128 = (x1 as u128).checked_mul(y1 as u128).unwrap();
            // current p is
            // let current_p: u128 = (x1 as u128).checked_div(y1 as u128).unwrap();
            let x2_power = Calculator::calc_x_power(
                target.calc_pnl_x.into(),
                target.calc_pnl_y.into(),
                x1,
                y1,
            );
            // let x2 = Calculator::sqrt(x2_power).unwrap();
            let x2 = x2_power.integer_sqrt();
            // msg!(arrform!(LOG_SIZE, "calc_take_pnl x2_power:{}, x2:{}", x2_power, x2).as_str());
            let y2 = x2.checked_mul(y1).unwrap().checked_div(x1).unwrap();
            // msg!(arrform!(LOG_SIZE, "calc_take_pnl y2:{}", y2).as_str());

            // transfer to token_coin_pnl and token_pc_pnl
            // (x1 -x2) * pnl / sys_decimal_value
            let diff_x = U128::from(x1.checked_sub(x2).unwrap().as_u128());
            let diff_y = U128::from(y1.checked_sub(y2).unwrap().as_u128());
            delta_x = diff_x
                .checked_mul(amm.fees.pnl_numerator.into())
                .unwrap()
                .checked_div(amm.fees.pnl_denominator.into())
                .unwrap()
                .as_u128();
            delta_y = diff_y
                .checked_mul(amm.fees.pnl_numerator.into())
                .unwrap()
                .checked_div(amm.fees.pnl_denominator.into())
                .unwrap()
                .as_u128();

            let diff_pc_pnl_amount =
                Calculator::restore_decimal(diff_x, amm.pc_decimals, amm.sys_decimal_value);
            let diff_coin_pnl_amount =
                Calculator::restore_decimal(diff_y, amm.coin_decimals, amm.sys_decimal_value);
            let pc_pnl_amount = diff_pc_pnl_amount
                .checked_mul(amm.fees.pnl_numerator.into())
                .unwrap()
                .checked_div(amm.fees.pnl_denominator.into())
                .unwrap()
                .as_u64();
            let coin_pnl_amount = diff_coin_pnl_amount
                .checked_mul(amm.fees.pnl_numerator.into())
                .unwrap()
                .checked_div(amm.fees.pnl_denominator.into())
                .unwrap()
                .as_u64();
            if pc_pnl_amount != 0 && coin_pnl_amount != 0 {
                amm.state_data.need_take_pnl_pc = amm
                    .state_data
                    .need_take_pnl_pc
                    .checked_add(pc_pnl_amount)
                    .unwrap();
                amm.state_data.need_take_pnl_coin = amm
                    .state_data
                    .need_take_pnl_coin
                    .checked_add(coin_pnl_amount)
                    .unwrap();

                // step3: update total_coin and total_pc without pnl
                *total_pc_without_take_pnl = (*total_pc_without_take_pnl)
                    .checked_sub(pc_pnl_amount)
                    .unwrap();
                *total_coin_without_take_pnl = (*total_coin_without_take_pnl)
                    .checked_sub(coin_pnl_amount)
                    .unwrap();
