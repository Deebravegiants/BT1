### Title
Unauthenticated privileged action trigger via magic QR-code actions bypassing operator identity verification - (File: src/plans/qr_scan/operator.rs, src/plans/mod.rs)

### Summary
`qr_scan::operator::Data::try_parse` matches any string against the `MAGIC_QR_CODE` regex and maps `magic_action:reset_wifi_credentials` / `magic_action:reset_mirror_calibration` directly to `Data::MagicResetWifi` / `Data::MagicResetMirror` with no identity or authorization data attached. In `MasterPlan::handle_magic_operator_qr_code`, these variants immediately execute `reset_wifi_and_ensure_network` (which calls `network::reset()`) or `reset_mirror_calibration`, and return before the code ever reaches `verify_operator_qr_code`, the only function that authenticates an operator QR-code against the backend.

### Finding Description
In `src/plans/qr_scan/operator.rs:40-61`, `Data::try_parse` checks the scanned string against `MAGIC_QR_CODE` and yields `Data::MagicResetWifi`/`Data::MagicResetMirror` purely from string content [1](#0-0) . In `src/plans/mod.rs`, both `scan_initial_qr_codes` and `scan_remaining_qr_codes` call `scan_operator_qr_code` then `handle_magic_operator_qr_code` before calling `verify_operator_qr_code` [2](#0-1) [3](#0-2) . `handle_magic_operator_qr_code` executes `reset_mirror_calibration`/`reset_wifi_and_ensure_network` directly on the magic variants and returns `Ok(None)`, so the loop never reaches `verify_operator_qr_code` for these actions [4](#0-3) . `verify_operator_qr_code` (`src/plans/mod.rs:1543-1578`) is the only place that calls `backend::operator_status::request` to authenticate the operator against the backend [5](#0-4) ; it is skipped entirely for magic actions. `reset_wifi_and_ensure_network` calls `network::reset()`, which shells out to `wpa-supplicant-interface restore-default-config` and `reconfigure` [6](#0-5) . `reset_mirror_calibration` re-derives calibration from config, stores it, and triggers `orb.recalibrate` [7](#0-6) . Thus any unprivileged party who can present a QR code to the Orb's RGB camera during the operator-scan phase can trigger these privileged side effects without any identity binding, contrary to the intended invariant that operator actions require backend-verified operator identity.

### Impact Explanation
An unauthenticated bystander can force the Orb to wipe its current WiFi configuration (`restore-default-config` + `reconfigure` via `wpa-supplicant-interface`) or force a mirror recalibration cycle, purely by showing a crafted QR code to the camera — no operator credentials, backend token, or physical/hardware access required. This causes denial of service to Orb operations (network disconnection requiring re-provisioning of WiFi credentials, and/or interruption/reset of ongoing operator or signup sessions since these branches run in the same scan loop used during signup flows), and constitutes an authorization bypass allowing an unprivileged actor to invoke privileged child-process actions (`wpa-supplicant-interface`) that are otherwise gated behind operator identity verification.

### Likelihood Explanation
High feasibility: the only precondition is that the attacker can present a printed/displayed QR code containing the literal string `magic_action:reset_wifi_credentials` or `magic_action:reset_mirror_calibration` to the RGB camera during the idle/operator QR-scan phase, which is the normal, publicly-facing state of a deployed Orb waiting for an operator. No secrets, tokens, or special hardware access are needed, and the action is fully repeatable.

### Recommendation
Require the magic QR-code actions to also pass through operator identity verification (`verify_operator_qr_code`) before being executed, or otherwise cryptographically bind/authenticate the magic action payload (e.g., signed action codes tied to a known operator identity or expiring, backend-issued tokens) rather than relying on unauthenticated plaintext string matching.

    async fn handle_magic_operator_qr_code(
        &self,
        orb: &mut Orb,
        qr_code: qr_scan::operator::Data,
    ) -> Result<Option<qr_scan::user::Data>> {
        match qr_code {
            qr_scan::operator::Data::Normal(qr_code) => {
                tracing::info!("Operator QR-code detected: {qr_code:?}");
                Ok(Some(qr_code))
            }
            qr_scan::operator::Data::MagicResetMirror => {
                tracing::info!("Magic QR-code detected: Reset Mirror");
                dd_incr!("main.count.signup.during.general.magic_qr.reset_mirror");
                let result = self.reset_mirror_calibration(orb).await;
                if let Err(err) = &result {
                    tracing::error!("Failed to reset mirror calibration: {err}");
                }
                orb.ui.magic_qr_action_completed(result.is_ok());
                Ok(None)
            }
            qr_scan::operator::Data::MagicResetWifi => {
                tracing::info!("Magic QR-code detected: Reset Wi-Fi");
                dd_incr!("main.count.signup.during.general.magic_qr.reset_wifi");
                let result = self.reset_wifi_and_ensure_network(orb).await;
                if let Err(err) = &result {
                    tracing::error!("Failed to reset wifi: {err}");
                }
                orb.ui.magic_qr_action_completed(result.is_ok());
                Ok(None)
            }
        }
    }

    /// Checks if `qr_code` is a valid operator QR-code through the backend.
    #[allow(clippy::cast_possible_truncation)]
    async fn verify_operator_qr_code(
        &self,
        orb: &mut Orb,
        qr_code: &qr_scan::user::Data,
        qr_capture_start: Instant,
    ) -> Result<Option<(u64, backend::operator_status::LocationData)>> {
        if qr_code.signup_extension() || self.operator_qr_code_override.is_some() {
            return Ok(Some((0, backend::operator_status::LocationData {
                team_operating_country: "DEV".to_string(),
                session_coordinates: Coordinates { latitude: 0.0f64, longitude: 0.0f64 },
                stationary_location_coordinates: None,
            })));
        }
        let http_start = Instant::now();
        match backend::operator_status::request(qr_code).await {
            Ok(backend::operator_status::Status { valid: true, location_data, reason: _ }) => {
                let location_data = location_data
                    .expect("to always have a result from the backend if valid == true");
                orb.ui.qr_scan_success(QrScanSchema::Operator);
                dd_incr!("main.count.global.distr_code_validated");
                tracing::info!("Operator QR-code validated: {qr_code:?}");
                dd_timing!("main.time.signup.distr_qr_code_capture", qr_capture_start);
                return Ok(Some((http_start.elapsed().as_millis() as u64, location_data)));
            }
            Ok(backend::operator_status::Status { valid: false, .. }) => {
                orb.ui.qr_scan_fail(QrScanSchema::Operator);
                dd_incr!("main.count.signup.result.failure.distr_qr_code", "type:invalid_qr");
            }
            Err(_) => {
                orb.ui.qr_scan_fail(QrScanSchema::Operator);
            }
        }
        Ok(None)
    }
