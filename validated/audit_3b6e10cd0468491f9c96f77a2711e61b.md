### Title
Unvalidated `amount_out` in SwapBaseOut/SwapBaseOutV2 causes `unwrap()` panic on `checked_sub` before the reserve-sufficiency check - (File: program/src/math.rs, program/src/processor.rs)

### Summary
`process_swap_base_out` and `process_swap_base_out_v2` compute `swap_in_before_add_fee` via `Calculator::swap_token_amount_base_out` using the raw, attacker-supplied `swap.amount_out` **before** validating that `swap.amount_out` is less than the pool's available reserves. Inside that function, the denominator is computed as `total_pc_without_take_pnl.checked_sub(amount_out).unwrap()` (or the coin equivalent), which returns `None` and panics whenever `amount_out >= total_*_without_take_pnl`. This mirrors the RUSTSEC-2026-0230 pattern: an operation that is only valid for a bounded input domain is invoked on unchecked, attacker-controlled data, and the failure path is an `unwrap()` panic rather than a returned error.

### Finding Description
In `program/src/math.rs`, `swap_token_amount_base_out` performs: [1](#0-0) 

For `SwapDirection::Coin2PC`, `denominator = total_pc_without_take_pnl.checked_sub(amount_out).unwrap()`. `checked_sub` on the `U128` type returns `None` when the subtrahend exceeds the minuend, and `.unwrap()` on `None` panics.

`process_swap_base_out` calls this function with the raw `swap.amount_out` immediately after computing pool reserves, with no prior bound check: [2](#0-1) 

The only place that checks `swap.amount_out` against `total_pc_without_take_pnl` / `total_coin_without_take_pnl` is inside the `match swap_direction` block, which executes **after** the panic-prone call: [3](#0-2) 

The identical pattern is duplicated in `process_swap_base_out_v2`: [4](#0-3) [5](#0-4) 

Because `SwapInstructionBaseOut::amount_out` is a plain `u64` unpacked directly from instruction data with no upper-bound validation, any unprivileged caller can submit `amount_out` equal to or greater than the AMM's current coin/pc reserves and trigger the panic deterministically.

### Impact Explanation
A panic in a Solana on-chain program aborts the transaction (and, depending on how the caller/CPI context handles it, can disrupt batched or composed transactions relying on this instruction succeeding gracefully with an error code rather than aborting). More importantly, this indicates a missing input-validation invariant: the reserve-sufficiency check that the code clearly intends to enforce (`AmmError::InsufficientFunds`) is performed too late, after an operation that assumes the invariant already holds. This is a robustness/availability defect reachable by any user submitting a single `SwapBaseOut` or `SwapBaseOutV2` transaction with attacker-chosen `amount_out`, consistent with the CVSS 7.5 AV:N/AC:L/PR:N/UI:N availability-only profile of the reference advisory.

### Likelihood Explanation
High. `SwapBaseOut`/`SwapBaseOutV2` are public, unprivileged instructions reachable from a single transaction. No special accounts, signer privileges, or preconditions beyond having a valid AMM pool are needed — the attacker only needs to set `amount_out >= total_pc_without_take_pnl` (or `total_coin_without_take_pnl` for the reverse direction), which is trivially satisfiable since the current reserves are readable on-chain.

### Recommendation
Move the reserve-sufficiency check (`swap.amount_out >= total_pc_without_take_pnl` / `total_coin_without_take_pnl`) to occur **before** calling `Calculator::swap_token_amount_base_out`, in both `process_swap_base_out` and `process_swap_base_out_v2`, returning `AmmError::InsufficientFunds` instead of allowing the unchecked subtraction to execute. Alternatively, replace the `checked_sub(...).unwrap()` calls inside `swap_token_amount_base_out` with a checked path that returns `AmmError::CalculationExRateFailure`/`InsufficientFunds` on `None` rather than panicking.

### Proof of Concept
1. Initialize or use an existing AMM pool with `total_pc_without_take_pnl = 1_000_000` and `total_coin_without_take_pnl = 1_000_000` (arbitrary example).
2. Submit a `SwapBaseOut` (opcode 11) or `SwapBaseOutV2` (opcode 17) instruction with `swap.amount_out = 1_000_000` (or any value `>= total_pc_without_take_pnl`) and a source-token mint matching `amm_coin_vault.mint` (selecting `SwapDirection::Coin2PC`).
3. Execution reaches [6](#0-5) , which calls `Calculator::swap_token_amount_base_out`.
4. Inside [7](#0-6) , `total_pc_without_take_pnl.checked_sub(amount_out)` returns `None`, and `.unwrap()` panics, aborting the transaction instead of returning `AmmError::InsufficientFunds`.
