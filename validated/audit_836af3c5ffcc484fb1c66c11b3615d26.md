### Title
Unprivileged third-party `supply` can push an insolvent account's collateral above the $5 dust cap and permanently block permissionless `clean_bad_debt` - (File: contracts/controller/src/positions/liquidation/curve.rs)

### Summary
The Lido bug class — a permissionless state bump (`KEYS_OP_INDEX_POSITION`) that invalidates a gated operation (`depositBufferedEther`) — maps onto XOXNO Lending as: anyone can call `controller::supply` to top up an existing collateral position of *someone else's* insolvent account, raising its `total_collateral` just above `BAD_DEBT_USD_THRESHOLD` ($5 WAD USD). This shuts the `BadDebtGate::DustCapped` predicate that the permissionless `clean_bad_debt` entrypoint requires, so bad-debt socialization is blocked even though the account is deeply insolvent and no liquidator can profitably drain it.

### Finding Description
`clean_bad_debt` is the only permissionless path that socializes residual debt of an insolvent account. `process_clean_bad_debt` requires only `caller.require_auth()` and delegates to `clean_bad_debt_standalone`, which uses `BadDebtGate::DustCapped` [1](#0-0) . That gate is `is_socializable_bad_debt`, which admits only when `total_debt > total_collateral && total_collateral <= BAD_DEBT_USD_THRESHOLD` ($5) [2](#0-1) . An account with, say, $12,000 debt and $4.99 collateral is socializable; with $5.01 collateral it is not — the Certora rules document exactly this straddle [3](#0-2) .

Meanwhile `supply` is permissionless in the third-party direction: `require_third_party_existing_supply` lets any caller add to a foreign account as long as the account already holds a supply position in that hub asset [4](#0-3) , and `process_deposit` performs no solvency check for the Deposit position type [5](#0-4) . An insolvent account necessarily holds at least one supply position, so the precondition is always satisfiable. A single unprivileged call

```
supply(caller, account_id = victim, payments = [(held_collateral_hub_asset, dust_amount)])
```

credited at the measured receipt pushes `totals.total_collateral` over the cap, and every subsequent `clean_bad_debt` reverts `CannotCleanBadDebt` [6](#0-5) . The attacker can re-top-up after any price drop or partial liquidation re-opens the gate, since each cleanup attempt consumes no collateral.

### Impact Explanation
Bad debt accrues borrow interest while unsocialized, worsening the eventual supply-index write-down borne by suppliers [7](#0-6) . Because the debt is under-collateralized, ordinary liquidation is unprofitable-to-pointless for the residual (seizing dust), so the account can sit insolvent indefinitely while its debt grows. The only remaining escape is the owner-gated `force_socialize_bad_debt` (`BadDebtGate::InsolventOnly`), which requires a governance timelock proposal and execution [8](#0-7) [9](#0-8) . This is a temporary freezing of funds / delayed insolvency resolution driven entirely by an unprivileged address — the same shape as the Lido report where an operator key bump wedges `depositBufferedEther` until governance intervenes.

### Likelihood Explanation
Cost per blocking round is just over $5 of a token the victim already holds, plus fees; on any re-opening (price move, partial liquidation, accrued debt crossing `total_collateral` again) the attacker repeats it. The collateral is forfeited when cleanup eventually lands (it becomes revenue) [10](#0-9) , so persistence costs ~$5 per governance cycle — cheap against a motivated griefer and trivially automatable, since both the gate inputs (`get_account_positions`, oracle prices) are readable on-chain.

### Recommendation
Decouple the dust gate from total collateral the attacker can inflate. Options:
- Make third-party `supply` revert when the target account's post-deposit state is insolvent (debt > collateral), or restrict third-party top-ups to solvent accounts.
- Gate socialization on *seizable* collateral or on the collateral present before the most recent third-party deposit snapshot.
- Alternatively let `clean_bad_debt` accept the dust cap on a per-position basis, seizing/socializing positions that were not just topped up, or allow the permissionless path with a higher cap when an account has been insolvent beyond a time bound.

### Proof of Concept
1. Alice supplies 100,000 USDC and borrows 6 ETH; USDC price crashes 10× → debt $12,000, collateral $10,000 (as in `deep_underwater_account_still_liquidates_to_the_dust_gate` [11](#0-10) ).
2. Liquidations drain collateral to $4 (debt still ~$11,996): `clean_bad_debt(caller, alice_id)` now satisfies `is_socializable_bad_debt` and would succeed.
3. Attacker Carol calls `supply(carol, alice_id, [(USDC, ~$1.01)])` — permitted because Alice already holds a USDC supply position [12](#0-11) .
4. `clean_bad_debt` now computes `total_collateral ≈ $5.01 > BAD_DEBT_USD_THRESHOLD` → `CannotCleanBadDebt` [13](#0-12) .
5. Socialization is blocked until governance executes `force_socialize_bad_debt`; Carol repeats step 3 whenever the gate re-opens.

/// Authorizes permissionless dust-gated cleanup outside flash loans.
pub(crate) fn process_clean_bad_debt(env: &Env, caller: &Address, account_id: u64) {
    caller.require_auth();
    validation::require_not_flash_loaning(env);
    clean_bad_debt_standalone(env, account_id);
}

/// Admission condition for bad-debt socialization.
#[derive(Clone, Copy, PartialEq)]
enum BadDebtGate {
    /// Permissionless: insolvent *and* collateral at or below the dust threshold.
    DustCapped,
    /// Owner-only: insolvent alone, with no cap on the collateral left behind.
    InsolventOnly,
}

/// Requires open debt and the selected insolvency gate, then cleans up the account.
fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    bad_debt::execute_bad_debt_cleanup(env, &mut cache, account_id, &account, &totals);
}

/// Socializes insolvent debt when remaining collateral is at or below the dust cap.
pub(crate) fn clean_bad_debt_standalone(env: &Env, account_id: u64) {
    socialize_bad_debt(env, account_id, BadDebtGate::DustCapped);
}

/// Straddle, first half. An attacker who raises `total_collateral` strictly above
/// `BAD_DEBT_USD_THRESHOLD` (`BAD_DEBT_USD_THRESHOLD + 1` is the cheapest such state) blocks
/// the permissionless dust-gated socialization path while staying insolvent. The gate is
/// value-based, not count-based, so one unit of a second collateral cannot block it: the
/// attacker must post value above the threshold and keep it there.
#[rule]
fn bad_debt_straddle_blocks_dust_gate(e: Env, debt_wad: i128, collateral_wad: i128) {
    let _ = e;
    cvlr_assume!(collateral_wad >= BAD_DEBT_USD_THRESHOLD + 1);
    cvlr_assume!(collateral_wad <= 1_000_000 * WAD);
    cvlr_assume!(debt_wad > collateral_wad && debt_wad <= 2_000_000 * WAD);

    // Symbolic straddle: anywhere strictly above the cap, the dust gate is shut.
    cvlr_assert!(!is_socializable_bad_debt(
        Wad::from(debt_wad),
        Wad::from(collateral_wad)
    ));

    // Explicit +1 witness: one raw WAD unit above the cap blocks it.
    cvlr_assert!(!is_socializable_bad_debt(
        Wad::from(BAD_DEBT_USD_THRESHOLD + 2),
        Wad::from(BAD_DEBT_USD_THRESHOLD + 1)
    ));
}

/// Checks supply entry gates and credits measured pool receipts.
pub(crate) fn process_deposit(
    env: &Env,
    caller: &Address,
    account: &mut Account,
    aggregated: &AggregatedPayments,
    cache: &mut Context,
) {
    validate_position_entry_gates(
        env,
        account,
        aggregated,
        cache,
        AccountPositionType::Deposit,
    );
    let pool_addr = cache.cached_pool_address();
    let mut entries: Vec<PoolSupplyEntry> = Vec::new(env);
    for (hub_asset, amount_in) in aggregated.iter() {
        let asset_config: AssetConfig = cache.require_spoke_asset(account.spoke_id, &hub_asset);
        let received = payments::transfer_amount_measured(
            env,
            &hub_asset.asset,
            caller,
            &pool_addr,
            amount_in,
            GenericError::AmountMustBePositive,
        );
        let position = account.get_or_create_supply_position(&hub_asset, &asset_config);
        entries.push_back(PoolSupplyEntry {
            action: make_pool_action(&position, received, hub_asset.clone()),
        });
    }

    let results = pool_supply_call(env, &pool_addr, &entries);
    for_each_leg(env, &entries, &results, |entry, result| {
        merge_supply_leg(env, account, &entry.action, &result, cache);
    });
}

### INV-LIQ-04 — Bad-debt socialization is explicit and total

Permissionless cleanup requires ceil risk debt greater than half-up unweighted
collateral and collateral at or below the fixed $5 dust threshold. Owner-only
forced cleanup omits the dust cap. Both require debt, readable account and NFT
state, valid required prices and no active flash guard. Listing flags and
global pause do not block standalone cleanup.

Cleanup reclassifies all remaining collateral shares as revenue and writes off
all remaining debt against each debt's market. It releases spoke usage and
atomically removes account entries and the NFT. It does not net same-market
supply against debt. Standalone cleanup emits `CleanBadDebtEvent` with
pre-cleanup USD totals, without a controller position-update batch.

Ordinary liquidation and cleanup apply no final account-health or full-backing
assertion. The index floor can leave a shortfall. Recapitalization fills that
shortfall without restoring the lost index or deleted account.
