### Title
RAY accounting overflow permanently freezes an oversized high-utilization market - (File: `common/src/rates/index.rs`)

### Summary
**Severity: Medium.** Interest accrual calculates total debt as `borrowed * borrow_index` before applying the borrow-index ceiling. For a sufficiently large market, the exact RAY-denominated result exceeds `i128::MAX` while the index itself is still below its cap, causing `MathOverflow` during accrual. Because every subsequent market operation accrues first, the market can no longer process withdrawals, repayments, liquidations, or other mutations.

### Finding Description
The pool stores debt as scaled RAY shares and reconstructs its current value by multiplying those shares by the borrow index. `calculate_supplier_rewards` evaluates both `borrowed.mul(old_borrow_index)` and `borrowed.mul(new_borrow_index)` during every accrual, while `Ray::mul` uses exact `I256` intermediate arithmetic and panics when the final RAY value cannot fit in `i128`. [1](#0-0) [2](#0-1) [3](#0-2) 

`update_borrow_index` caps only the index after growth; it does not cap or partition the `borrowed * index` result used to compute accrued interest. [4](#0-3)  For an 18-decimal market holding roughly `1e27` base units, approximately `9.8e26` base units of debt needs only an index around `170 * RAY` before the reconstructed RAY debt exceeds `i128::MAX`, far below the `1e9 * RAY` index ceiling. [5](#0-4) [6](#0-5) 

All pool operations load a synchronized market through `synced_market`, which invokes `interest::global_sync` before the requested mutation. [7](#0-6)  `global_sync` then calls `accrue_chunk`, and `accrue_chunk` calls the overflowing shared accrual calculation. [8](#0-7) [9](#0-8)  Consequently, once the panic condition is crossed, the next controller `update_indexes`, `withdraw`, `repay`, `liquidate`, `borrow`, `supply`, `clean_bad_debt`, `recapitalize`, or flash/strategy operation touching that market reverts.

### Impact Explanation
All token balances backing the affected market become inaccessible because suppliers cannot withdraw and borrowers or liquidators cannot repay or settle debt through the controller. [7](#0-6)  The regression test demonstrates the resulting market freeze by showing that both withdrawal and repayment fail with `MathOverflow` after accrual crosses the value ceiling. [10](#0-9) 

The state remains trapped because the failed accrual is rolled back rather than partially committed, so the next call attempts the same overflowing multiplication again. Governance also cannot recover the market by lowering its interest-rate model because `replace_rate_model` performs an accrued market sync before writing replacement parameters. [11](#0-10)  Absent a contract upgrade or another privileged recovery mechanism outside the listed surface, this is a permanent freezing of funds for that market.

### Likelihood Explanation
The issue requires an unusually large admitted market and sustained high utilization. A single unprivileged account can create the precondition by supplying the debt asset, supplying separate collateral, and borrowing most of the supplied liquidity, but the market's configured supply/borrow caps and available token issuance must permit the required scale. [12](#0-11) 

The regression scenario reaches the cliff after repeated yearly accrual at approximately 98% utilization under the tested rate curve. [13](#0-12)  Thus, the likelihood is constrained by capital requirements, market caps, utilization, and elapsed time, while the impact is market-wide and permanent once reached.

### Recommendation
Make accrual safe for every representable scaled-debt/index combination. For example:

- Detect when `borrowed * new_borrow_index / RAY` or `borrowed * old_borrow_index / RAY` cannot fit before calling `calculate_supplier_rewards`.
- Clamp or split the accrual at the largest representable debt value instead of letting `Ray::mul` panic.
- Enforce a market-level scaled-debt bound derived from `i128::MAX / MAX_BORROW_INDEX_RAY`, so an admitted market can never reach the value ceiling before the index cap.
- Add the same boundary check to supply accounting if `supplied * supply_index` can overflow before its cap.
- Add an invariant test proving that a market remains operable at the configured index ceilings.

The relevant calculations are in `common/src/rates/index.rs` and `common/src/rates/scaling.rs`. [14](#0-13) [15](#0-14) 

### Proof of Concept
For an 18-decimal debt market and a separate collateral market whose configured caps admit the required exposure:

1. The attacker calls controller `supply` with a leg for the 18-decimal asset and `amount = 1_000_000_000 * 10^18` base units.
2. The attacker calls controller `supply` again with enough collateral in a different listed asset.
3. The attacker calls controller `borrow` with a leg for the 18-decimal asset and `amount = 980_000_000 * 10^18` base units.
4. Time is allowed to pass while utilization remains high.
5. Anyone calls controller `update_indexes` for the debt market. Accrual eventually panics with `MathOverflow` inside the debt-value multiplication.
6. Subsequent controller `withdraw`, `repay`, `liquidate`, `borrow`, `supply`, or `update_indexes` calls for that market continue to panic because each one attempts accrual first.

The repository's regression test performs equivalent setup with `principal = BILLION * 10^18`, borrows 98% of it, advances yearly until `update_indexes` fails, and confirms the index cap did not engage before the overflow. [6](#0-5)  It then confirms that withdrawal and repayment both fail with `MathOverflow`. [10](#0-9)

/// Applies `interest_factor` to `old_index` to produce the new borrow index,
/// capped at `MAX_BORROW_INDEX_RAY`.
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}

pub fn update_supply_index(env: &Env, supplied: Ray, old_index: Ray, rewards_increase: Ray) -> Ray {
    if supplied == Ray::ZERO || rewards_increase == Ray::ZERO {
        return old_index;
    }

    let total_supplied_value = supplied.mul(env, old_index);

    if total_supplied_value == Ray::ZERO {
        return old_index;
    }

    let new_value = total_supplied_value.checked_add(env, rewards_increase);
    let grown = fp_core::mul_div_floor_saturating(env, new_value.raw(), RAY, supplied.raw());

    let bounded_old = old_index.raw().min(MAX_SUPPLY_INDEX_RAY);
    Ray::from(grown.min(MAX_SUPPLY_INDEX_RAY).max(bounded_old))
```

pub fn calculate_supplier_rewards(
    env: &Env,
    params: &MarketParams,
    borrowed: Ray,
    new_borrow_index: Ray,
    old_borrow_index: Ray,
) -> (Ray, Ray) {
    let old_total_debt = borrowed.mul(env, old_borrow_index);
    let new_total_debt = borrowed.mul(env, new_borrow_index);

    let accrued_interest = new_total_debt.checked_sub(env, old_total_debt);

    let protocol_fee = params.reserve_factor.apply_to_ray(env, accrued_interest);
    let supplier_rewards = accrued_interest.checked_sub(env, protocol_fee);

    (supplier_rewards, protocol_fee)

pub fn try_mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> Option<i128> {
    if x < 0 || y < 0 || d <= 0 {
        return None;
    }
    let half = d / 2;

    // Fast path: the biased product fits `i128`, so the whole computation is
    // native. `x * y + half` is non-negative here, so `/` is the floor the
    // widened path would produce.
    if let Some(biased) = x
        .checked_mul(y)
        .and_then(|product| product.checked_add(half))
    {
        return Some(biased / d);
    }

    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    x256.mul(&y256)
        .add(&I256::from_i128(env, half))
        .div(&d256)
        .to_i128()
}

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```

fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}
