### Title
Unbounded index accrual permanently freezes an oversized market - ([File: contracts/pool/src/interest.rs])

### Summary
Pool index synchronization iterates over the full elapsed interval in one-year chunks and performs uncapped RAY-valued interest arithmetic on each chunk. [1](#0-0)  An unprivileged caller can trigger this through `Controller::update_indexes`, while ordinary supply, borrow, repay, withdraw, and liquidation paths also synchronize the relevant market before mutating it. [2](#0-1)  At sufficiently large scaled balances and sustained high utilization, the projected RAY value overflows `i128` before `MAX_BORROW_INDEX_RAY` is reached, making subsequent synchronization panic. [3](#0-2) 

### Finding Description
`global_sync` derives `remaining` directly from `current_timestamp - last_timestamp`, repeatedly calls `accrue_chunk`, and only marks the market accrued after the complete interval has been processed. [1](#0-0)  Each chunk invokes `accrue_step` against the market’s unbounded scaled supply, debt, and indexes. [4](#0-3)  The chunk length is capped only at one year; there is no cap on the number of chunks or on the market’s RAY-denominated value before accrual arithmetic is attempted. [5](#0-4)  The regression test demonstrates that a billion whole 18-decimal-token market at 98% utilization eventually causes `try_update_indexes` to revert with `MATH_OVERFLOW` while the stored borrow index remains below `MAX_BORROW_INDEX_RAY`. [6](#0-5) 

### Impact Explanation
The affected market becomes permanently unusable because synchronization is a prerequisite for repayments, withdrawals, liquidations, and subsequent index updates. [7](#0-6)  The test explicitly confirms that both `withdraw` and `repay` fail with the same math overflow after the cliff is reached. [8](#0-7)  Suppliers cannot recover principal, borrowers cannot close positions, and liquidators cannot unwind the account, satisfying the permanent-freezing impact class. [3](#0-2) 

### Likelihood Explanation
Reaching the condition requires an exceptionally large market, high utilization, and enough elapsed time for index growth to push the RAY-valued debt calculation over `i128::MAX`. [9](#0-8)  No privileged runtime call is required to trigger the failure: an authorized but otherwise unprivileged caller can invoke `update_indexes(caller, assets)` with the market’s `HubAssetKey`, and the controller forwards that call to the pool. [10](#0-9)  The economic setup and time requirement reduce practical likelihood, but the resulting market-wide freeze is severe. [3](#0-2) 

### Recommendation
Bound the scaled-to-original intermediate values before applying accrual, cap the accrual horizon or number of chunks processed per call, and make failure to accrue leave `last_timestamp` unchanged without blocking liveness-critical exits where safe. [1](#0-0)  A safer design would detect an impending `i128` overflow before mutating indexes, clamp at an explicit market/index ceiling, and consistently enter a defined wind-down mode rather than panicking inside every later synchronization. [11](#0-10)  Regression coverage should retain the whale-market test and additionally assert the selected recovery path for repayments, withdrawals, and liquidation. [3](#0-2) 

### Proof of Concept
1. Create or select a listed 18-decimal market whose configured caps admit a scaled supply near `10^36` raw RAY units. [12](#0-11) 
2. Supply approximately one billion whole tokens and borrow approximately 98% of the supplied value against sufficient collateral. [13](#0-12) 
3. Advance ledger time repeatedly by one-year intervals without synchronizing the market. [14](#0-13) 
4. Call `Controller::update_indexes(caller, Vec::from_array(env, [HubAssetKey { hub_id, asset }]))`. [2](#0-1) 
5. `global_sync` eventually reverts with `MATH_OVERFLOW` while `borrow_index < MAX_BORROW_INDEX_RAY`; later `withdraw` and `repay` calls hit the same panic and cannot complete. [15](#0-14)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();

fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);

pub fn compound_interest(env: &Env, rate: Ray, delta_ms: u64) -> Ray {
    if delta_ms == 0 {
        return Ray::ONE;
    }

    let x = Ray::from({
        let r = I256::from_i128(env, rate.raw());
        let d = I256::from_i128(env, delta_ms as i128);
        r.mul(&d)
            .to_i128()
            .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
    });

    let mut sum = Ray::ONE.checked_add(env, x);
    let mut pow = x;
    for divisor in [2, 6, 24, 120, 720, 5_040, 40_320] {
        pow = pow.mul(env, x);
        sum = sum.checked_add(env, pow.div_by_int(env, divisor));
    }
    sum
