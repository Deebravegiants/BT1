## Finding: Stale `TombStone` Persists Across Ownership Transfers, Enabling Unauthorized Object Reclamation from `BURN_ADDRESS`

### Title
Stale TombStone survives standard `object::transfer`, letting a *former* owner reclaim an object burned by the current owner - (File: `aptos-move/framework/aptos-framework/sources/object.move`)

### Summary
`object::burn` marks an object as hidden via a `TombStone{ original_owner }` resource but deliberately does **not** change the object's `ObjectCore.owner` or disable ungated transfer. If the owner later transfers the object normally (`object::transfer` / `transfer_call`, which go through `transfer_raw_inner`), the stale `TombStone` is never cleared. Only the `LinearTransferRef` path (`transfer_with_ref`) clears it. This lets the original soft-burner reclaim the object out from under a completely different, later owner once that later owner independently sends the object to `BURN_ADDRESS`.

### Finding Description
`object::burn` [1](#0-0)  only requires the caller to currently own the object, then writes a `TombStone { original_owner }` at the object's address — it never touches `ObjectCore.owner` or `allow_ungated_transfer`.

Because ungated transfer remains enabled, the "burned" object can be transferred normally through `object::transfer` → `transfer_raw` → `transfer_raw_inner` [2](#0-1) . This inline function only updates `object_core.owner`; it contains no logic to remove an existing `TombStone`.

By contrast, the `LinearTransferRef` path explicitly clears a stale TombStone before transferring: [3](#0-2) . This shows the framework authors were aware that a stale TombStone must be cleared on ownership change, but that safeguard was only implemented for one of the two transfer code paths.

`object::unburn` [4](#0-3)  resolves a `TombStone` by checking:
1. If current owner == caller → clear tombstone (normal case, caller already owns it).
2. Else if current owner == `BURN_ADDRESS` → require caller == `TombStone.original_owner`, then transfer the object back to that recorded address via `transfer_raw_inner`.
3. Else → abort.

Exploit sequence:
1. Account **A** owns object `O`. `A` calls `object::burn(A, O)` → `TombStone{original_owner: A}` is created; `O.owner` stays `A`.
2. `A` sells/transfers `O` to **B** via the standard `object::transfer(A, O, B)` entry function (uses `transfer_raw_inner`, which ignores the existing `TombStone`). Now `O.owner == B`, but the stale `TombStone{original_owner: A}` remains.
3. `B`, unaware of the leftover tombstone, later performs a legitimate, independent burn of `O` by transferring it to `BURN_ADDRESS` (a normal, recognized burn pattern using `object::transfer`).
4. `A` calls `object::unburn(A, O)`. Branch 1 fails (`owner != A`). Branch 2 succeeds (`owner == BURN_ADDRESS` and `TombStone.original_owner == A`), so `transfer_raw_inner` sends `O` back to **A** — not to `B`, who was the actual, legitimate owner that performed the real burn.

The custody invariant broken: "objects burnt by their current owner must only be recoverable by that same current owner." Instead, a stale reference to a completely unrelated, earlier owner is trusted, allowing custody of the object to be redirected away from its rightful line of ownership.

### Impact Explanation
This is a custody-grade takeover of object ownership: an object that was legitimately, independently sent to `BURN_ADDRESS` by its current owner `B` can be reclaimed by an unrelated prior owner `A`, purely because `A` performed an earlier no-op "soft burn" that was never cleaned up on transfer. For high-value token objects, code objects, or resource-linked objects using this generic `object::burn`/`unburn` mechanism, this results in outright theft/reassignment of object ownership away from the legitimate current-owner lineage, and permanent loss of recovery rights for `B` (who reasonably expects only they can reclaim what they burned).

### Likelihood Explanation
The precondition sequence (burn → normal transfer → re-burn by new owner) is a plausible, unprivileged usage pattern requiring no special permissions — any user who has ever soft-burned an object and later sold/transferred it via the standard `object::transfer` entry function leaves an exploitable dangling claim. The trigger only requires the new owner to burn the same object at `BURN_ADDRESS`, which is a normal/expected user action, not an edge case.

### Recommendation
Clear any existing `TombStone` in `transfer_raw_inner` (or in `transfer_raw`) whenever ownership changes, mirroring the safeguard already present in `transfer_with_ref`:
```move
inline fun transfer_raw_inner(object: address, to: address) {
    let object_core = borrow_global_mut<ObjectCore>(object);
    if (object_core.owner != to) {
        if (exists<TombStone>(object)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object);
        };
        event::emit(Transfer { object, from: object_core.owner, to });
        object_core.owner = to;
    };
}
```
This ensures a `TombStone` can only ever refer to the immediately-preceding owner of the current burn event, preventing recovery-right hijacking by stale, unrelated former owners.

### Proof of Concept
Move-test outline (pseudo-code, using the existing `object` module test harness):
```move
#[test(a = @0xA1, b = @0xB2)]
fun test_stale_tombstone_reclaim(a: &signer, b: &signer) {
    let a_addr = signer::address_of(a);
    let b_addr = signer::address_of(b);

    let ctor = object::create_object(a_addr);
    let obj = object::object_from_constructor_ref<object::ObjectCore>(&ctor);

    // 1. A soft-burns (no ownership change)
    object::burn(a, obj);

    // 2. A transfers to B via ordinary transfer (TombStone NOT cleared)
    object::transfer(a, obj, b_addr);
    assert!(object::owner(obj) == b_addr, 0);

    // 3. B independently burns for real by sending to BURN_ADDRESS
    object::transfer_call(b, object::object_address(&obj), object::burn_address_for_test());

    // 4. A reclaims the object despite never having current custody
    object::unburn(a, obj);
    assert!(object::owner(obj) == a_addr, 1); // BUG: should not succeed / should not return to A
}
```
(Note: `burn_address_for_test` is illustrative — the constant `BURN_ADDRESS` is private in `object.move`; a full PoC would need to route through a public burn-to-address helper or `unburn`'s reachable branch to demonstrate the same effect end-to-end.)

    /// Allow origin owners to reclaim any objects they previous burnt.
    public entry fun unburn<T: key>(
        original_owner: &signer,
        object: Object<T>,
    ) {
        let object_addr = object.inner;
        assert!(exists<TombStone>(object_addr), error::invalid_argument(EOBJECT_NOT_BURNT));

        // The new owner of the object can always unburn it, but if it's the burn address, we go to the old functionality
        let object_core = borrow_global<ObjectCore>(object_addr);
        if (object_core.owner == signer::address_of(original_owner)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object_addr);
        } else if (object_core.owner == BURN_ADDRESS) {
            // The old functionality
            let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
            assert!(
                original_owner_addr == signer::address_of(original_owner),
                error::permission_denied(ENOT_OBJECT_OWNER)
            );
            transfer_raw_inner(object_addr, original_owner_addr);
        } else {
            abort error::permission_denied(ENOT_OBJECT_OWNER);
        };
    }
