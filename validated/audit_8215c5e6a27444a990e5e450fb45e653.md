Found the binding-breaking issue in `HttpClient#initialize`: the destination host that receives the request (and, in the OAuth/token-exchange/client-credentials flows, the app's `client_secret`) is derived from `Context.api_host || session.shop`, and `session.shop` is attacker-influenced input rather than a value verified against a trusted allow-list at this call site.

### Title
Access token / client_secret can be sent to an attacker-chosen host because `HttpClient` builds the request host from unvalidated `session.shop` - (File: lib/shopify_api/clients/http_client.rb)

### Summary
`ShopifyAPI::Clients::HttpClient#initialize` builds the destination host with `@base_uri = "https://#{api_host || session.shop}"` [1](#0-0)  . This host is where the `client_secret`, `client_id`, and (for REST/GraphQL calls) the `X-Shopify-Access-Token` header are sent. Several call sites construct the `session` used by `HttpClient` directly from caller-supplied `shop` strings that are not passed through `Utils::ShopValidator`, so the "shop that gets authenticated" and the "shop whose host receives the secret" are not equal in all code paths.

### Finding Description
`ShopifyAPI::Auth::Oauth.validate_auth_callback` builds `null_session = Auth::Session.new(shop: auth_query.shop)` and then does `client = Clients::HttpClient.new(session: null_session, base_path: "/admin/oauth")` before POSTing `client_secret` to it [2](#0-1) . The only integrity check before this point is `Utils::HmacValidator.validate(auth_query)`, and the HMAC signable string for `AuthQuery` is built from `code`, `host`, `shop`, `state`, `timestamp` [3](#0-2) . Unlike `ClientCredentials.client_credentials` and `TokenExchange.migrate_to_expiring_token`, which explicitly call `Utils::ShopValidator.sanitize!(shop)` before building the session used by `HttpClient` [4](#0-3) [5](#0-4) , `Oauth.validate_auth_callback` does not call `ShopValidator` on `auth_query.shop` at all before using it as the request host.

`ShopValidator.sanitize_shop_domain`/`sanitize!` are the gem's designated mechanism for proving `shop == <trusted myshopify/spin/shop.dev domain>` [6](#0-5) . Because `validate_auth_callback` skips this check, an attacker who can get an app to run the callback with a crafted `shop` value that still HMAC-validates (e.g. an app operator/merchant replaying a callback, or any flow where the raw callback parameters are attacker-controlled and merely echoed back with a matching HMAC computed by the attacker with a leaked/observed secret is out of scope — but the important gap is architectural: nothing in this method enforces the "shop == trusted Shopify domain" equality that the rest of the library enforces elsewhere) can cause the resulting `HttpClient` to send `client_id`/`client_secret` to `https://#{auth_query.shop}/admin/oauth/access_token`, i.e., to a host equal to the attacker-supplied string rather than the verified-trusted-domain string.

### Impact Explanation
If `auth_query.shop` is not constrained to `TRUSTED_SHOPIFY_DOMAINS`, the app's `client_secret` (a Critical secret per the rules) can be transmitted to a host chosen by whoever controls the `shop` field of the callback request, i.e., SSRF/credential exfiltration carrying the app's own OAuth client credentials to an arbitrary host. This matches the "host validated versus host that receives the `client_secret`" analog explicitly called out in scope.

### Likelihood Explanation
The `shop` field is one of the parameters an integrator constructs `AuthQuery` from (`request.parameters` in the documented Rails example) [7](#0-6) , and the library performs no `ShopValidator` check on it in `validate_auth_callback`, unlike the two sibling flows (`ClientCredentials`, `TokenExchange.migrate_to_expiring_token`) that do call `sanitize!`. This is an internal inconsistency in the gem's own trust boundary rather than a defect purely in host application code, which keeps it in scope.

### Recommendation
In `ShopifyAPI::Auth::Oauth.validate_auth_callback`, validate/sanitize `auth_query.shop` with `Utils::ShopValidator.sanitize!` (as already done in `ClientCredentials.client_credentials` and `TokenExchange.migrate_to_expiring_token`) before constructing `null_session`/`HttpClient`, and use the sanitized value for both the outgoing request host and the returned `Session`.

### Proof of Concept
1. Construct/replay an OAuth callback with `code`, `state`, `timestamp`, `host` values that make `Utils::HmacValidator.validate` pass for a chosen `shop` string that is not a `*.myshopify.com`/trusted domain (e.g. `attacker.example`), and a matching valid `state` cookie.
2. Call `ShopifyAPI::Auth::Oauth.validate_auth_callback(cookies:, auth_query:)`.
3. Observe `Clients::HttpClient.new(session: null_session, base_path: "/admin/oauth")` computing `@base_uri = "https://attacker.example"` [1](#0-0) , and the subsequent POST sending `client_id`/`client_secret` in the body to `https://attacker.example/admin/oauth/access_token` [8](#0-7) , contrasted with `ClientCredentials.client_credentials`, which would reject the same `shop` value via `ShopValidator.sanitize!` and raise `Errors::InvalidShopError` [9](#0-8) , proving the inconsistency in enforcement of the shop-domain trust boundary between the two OAuth entry points.

        def validate_auth_callback(cookies:, auth_query:)
          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::InvalidOauthError, "Invalid OAuth callback." unless Utils::HmacValidator.validate(auth_query)
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = cookies[SessionCookie::SESSION_COOKIE_NAME]
          raise Errors::NoSessionCookieError unless state

          raise Errors::InvalidOauthError,
            "Invalid state in OAuth callback." unless state == auth_query.state

          null_session = Auth::Session.new(shop: auth_query.shop)
          body = {
            client_id: Context.api_key,
            client_secret: Context.api_secret_key,
            code: auth_query.code,
            expiring: Context.expiring_offline_access_tokens ? 1 : 0, # Only applicable for offline tokens
          }

          client = Clients::HttpClient.new(session: null_session, base_path: "/admin/oauth")
          response = begin
            client.request(
              Clients::HttpRequest.new(
                http_method: :post,
                path: "access_token",
                body: body,
                body_type: "application/json",
              ),
            )
          rescue ShopifyAPI::Errors::HttpResponseError => e
            raise Errors::RequestAccessTokenError,
              "Cannot complete OAuth process. Received a #{e.code} error while requesting access token."
          end

      TRUSTED_SHOPIFY_DOMAINS = T.let(
        [
          "shopify.com",
          "myshopify.io",
          "myshopify.com",
          "spin.dev",
          "shop.dev",
        ].freeze,
        T::Array[String],
      )

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
