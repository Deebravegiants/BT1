### Title
`EvmHost` incoming GET-response/timeout dispatch skips the contract-existence check applied to POST requests, silently treating non-contract callees as successful deliveries - (File: `evm/src/core/EvmHost.sol`)

### Summary
`EvmHost.dispatchIncoming(PostRequest, address)` guards the low-level callback with an `extcodesize` check and early-returns (leaving the request retryable) when the destination has no code [1](#0-0) . The three sibling dispatch paths — `dispatchIncoming(GetResponse, address)`, `dispatchTimeOut(GetRequestTimeout, ...)`, and `dispatchTimeOut(PostRequestTimeout, ...)` — perform the exact same pattern of a low-level `.call()` into `_bytesToAddress(...)` but omit this check entirely [2](#0-1) [3](#0-2) [4](#0-3) .

### Finding Description
This is the same root-cause class as the referenced `OperateProxy.callFunction()` finding: a low-level `.call()` to an address with no code always returns `success: true` with empty return data, because the EVM has nothing to execute. The codebase already recognizes and mitigates this for the POST-request delivery path with an `extcodesize` check [5](#0-4) , but the mitigation was not applied uniformly to the other three callback sites that use the identical `(bool success,) = addr.call(...)` pattern:

- `dispatchIncoming(GetResponse memory response, address relayer)` calls `_bytesToAddress(response.request.from).call(...IApp.onGetResponse...)` with no prior code check, then unconditionally pays the relayer fee and emits `GetRequestHandled` if `success` is true [6](#0-5) .
- `dispatchTimeOut(GetRequestTimeout ...)` calls `_bytesToAddress(timeout.request.from).call(...IApp.onGetTimeout...)` with no code check, then refunds the fee to `meta.sender` and emits `GetRequestTimeoutHandled` if `success` [7](#0-6) .
- `dispatchTimeOut(PostRequestTimeout ...)` calls `_bytesToAddress(timeout.request.from).call(...IApp.onPostRequestTimeout...)`, same pattern [8](#0-7) .

In all three cases, if the target address has no deployed code at call time, the low-level call trivially "succeeds" without ever running the app's `onGetResponse`/`onGetTimeout`/`onPostRequestTimeout` logic. Because the code branches on `success`, the host: (a) does **not** roll back the receipt/commitment state it already wrote before the call (unlike the guarded POST path, which restores retryability), and (b) proceeds to pay out relayer fees or refunds and emit the "Handled" event as if the callback executed correctly.

This matters concretely for the intents/token apps built on `HyperApp`/`ExtrinsicIntents`/`HyperFungibleToken`, where these callbacks are where actual state transitions occur — e.g. `onPostRequestTimeout` re-mints/refunds burned tokens [9](#0-8) , and `onGetResponse` is the trigger for releasing escrow during source-chain order cancellation, per the documented Intent Gateway flow ("The `onGetResponse` handler verifies the empty proof and calls `withdraw()` to refund the escrowed tokens to the user"). If the callback target has no code when the message is delivered, the refund/mint/withdraw logic silently never executes, yet the protocol marks the delivery/timeout as handled and cannot be retried (for `dispatchIncoming`) or is treated as fee-eligible (for both timeout paths).

### Impact Explanation
If the app address recorded as `request.from` lacks code at delivery time (e.g., an EOA-initiated GET dispatch, a proxy/contract that self-destructs or is not yet deployed between dispatch and delivery, or any other transient/incorrect code-length condition), the affected message is consumed as "successfully handled" without its state-changing logic running. Depending on the app, this can permanently freeze escrowed/burned funds (no refund/mint ever occurs and the message is not retried) or cause relayer/fee accounting to pay out for work that was never actually performed. This matches the "permanent freezing of funds" / "unauthorized app action skipped without recovery" impact classes.

### Likelihood Explanation
Likelihood is moderate rather than trivially always-exploitable: unlike the original qBridge-style bug, `request.from`/`timeout.request.from` is generally the address of the app itself, not a value a third-party attacker can arbitrarily choose. However, it is not fully protected against: dispatching a GET request directly from an EOA (the host's `dispatch` entrypoints are not restricted to contracts), or the target self-destructing or otherwise losing code between the time a GET request/timeout is initiated and when the callback is delivered, both make the callee code-less and trigger the false-success path. Because the vulnerable code paths are reachable purely by relaying already-in-flight, unprivileged protocol messages (GET responses and timeouts), no special privilege is required to trigger the divergence once such a from-address condition exists.

### Recommendation
Apply the same `extcodesize`-based check used in `dispatchIncoming(PostRequest, address)` to `dispatchIncoming(GetResponse, address)`, `dispatchTimeOut(GetRequestTimeout, ...)`, and `dispatchTimeOut(PostRequestTimeout, ...)` before performing the low-level `.call()`, and early-return (or otherwise leave state consistent) instead of treating a call to a non-contract address as a valid delivery.

### Proof of Concept
1. An account with no code becomes the recorded `from` for a request — e.g., an EOA calls the host's GET-dispatch function directly, or an app contract self-destructs after dispatching a GET/POST request but before the corresponding response/timeout is delivered.
2. A relayer submits the proof for the `GetResponse` (or the timeout) through `HandlerV2`, which calls `EvmHost.dispatchIncoming(GetResponse, relayer)` / `dispatchTimeOut(...)`.
3. Inside `EvmHost`, `_bytesToAddress(response.request.from).call(...)` (or the timeout equivalents) is invoked against the code-less address; the EVM returns `success = true` with empty data because there is no code to execute [10](#0-9) .
4. The host proceeds down the `success == true` branch: it emits `GetRequestHandled`/`GetRequestTimeoutHandled`/`PostRequestTimeoutHandled` and pays out the relayer fee or refund, without the app's intended `onGetResponse`/`onGetTimeout`/`onPostRequestTimeout` logic (e.g., escrow release, token re-mint) ever running, and with no retry path available since the "handled" bookkeeping is not reverted as it is in the guarded POST-request path [11](#0-10) .

    function dispatchIncoming(PostRequest memory request, address relayer) external restrict(_hostParams.handler) {
        address destination = _bytesToAddress(request.to);
        uint256 size;
        assembly {
            size := extcodesize(destination)
        }
        if (size == 0) {
            // instead of reverting the entire batch, early return here.
            return;
        }

        // replay protection
        bytes32 commitment = request.hash();
        _requestReceipts[commitment] = relayer;

        (bool success,) = address(destination)
            .call(abi.encodeWithSelector(IApp.onAccept.selector, IncomingPostRequest(request, relayer)));

        if (!success) {
            // so that it can be retried
            delete _requestReceipts[commitment];
            return;
        }
        emit PostRequestHandled({commitment: commitment, relayer: relayer});

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,

        });

            return;

        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});

        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }
