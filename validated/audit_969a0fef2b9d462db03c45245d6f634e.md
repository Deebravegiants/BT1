### Title
`Oauth.validate_auth_callback` sends the app's `client_secret` to an unsanitized `shop` host, unlike every other credential-exchange path in the gem - (File: `lib/shopify_api/auth/oauth.rb`)

### Summary
`ClientCredentials.client_credentials`, `RefreshToken.refresh_access_token`, and `TokenExchange.exchange_token` all pass the caller-supplied shop domain through `Utils::ShopValidator.sanitize!` before using it to build the request host that receives the app's `client_secret`. `Oauth.validate_auth_callback` does not: it builds the `Session` (and therefore the `HttpClient` request host) directly from `auth_query.shop`, whose only check is that it is one of the fields covered by the request HMAC — not that it is a legitimate `*.myshopify.com`/trusted Shopify domain.

### Finding Description
The identity binding that should hold is:

`host that receives client_secret == a value validated as a trusted Shopify domain`

For every other OAuth-adjacent flow, this equality is enforced: [1](#0-0) [2](#0-1) [3](#0-2) 

But `Oauth.validate_auth_callback` builds the `null_session` used for the access-token POST straight from `auth_query.shop`, with only an HMAC check on the query, not a call to `Utils::ShopValidator.sanitize!`: [4](#0-3) 

`Utils::HmacValidator.validate` only verifies that the bytes of `shop` (among other fields) were part of what was HMAC-signed with `api_secret_key` — it says nothing about whether `shop` is a `*.myshopify.com`/trusted domain: [5](#0-4) [6](#0-5) 

That unsanitized `shop` value then becomes the literal request host, and the `client_secret` is placed in the POST body sent to it: [7](#0-6) [8](#0-7) 

`ShopValidator.sanitize!`/`sanitize_shop_domain` is the gem's only mechanism for constraining a shop string to `TRUSTED_SHOPIFY_DOMAINS` (`shopify.com`, `myshopify.io`, `myshopify.com`, `spin.dev`, `shop.dev`, plus any configured `myshopify_domain`): [9](#0-8) 

### Impact Explanation
This is exactly the "host validated versus host that receives the access token or `client_secret`" analog called out in scope. The equality that should hold — "host that receives `client_secret`" equals "a domain validated by `ShopValidator`" — is broken specifically on this one code path, while three sibling flows in the same file tree enforce it correctly. If the `shop` value threaded through `validate_auth_callback` is ever attacker-influenced (e.g., a host application takes `shop` from the callback query string as many integrations do, and merely re-verifies via `Utils::HmacValidator.validate(auth_query)` before calling this method, trusting the library to also enforce domain shape), the app's `client_secret` and the OAuth `code` will be POSTed to whatever host string was embedded in `auth_query.shop`, rather than to a value guaranteed to be a genuine Shopify domain. This is an inconsistency in the library's own defense-in-depth compared to `client_credentials.rb`, `refresh_token.rb`, and `token_exchange.rb`, which all treat `ShopValidator.sanitize!` as a required step before trusting a shop string as a request host for credential-bearing requests.

### Likelihood Explanation
Medium-to-High for this specific gem behavior: `AuthQuery.shop` is HMAC-covered but the HMAC alone constrains only byte integrity, not domain shape/target host, and this gem provides no automatic sanitization step in `validate_auth_callback` the way it does in the other three credential-exchange helpers. Any host application that mirrors the documented `AuthQuery` construction from raw callback query parameters and relies on this library's OAuth callback validation as its sole check inherits this gap, sending `client_secret` to a host determined only by an HMAC-signed-but-format-unchecked string.

### Recommendation
In `ShopifyAPI::Auth::Oauth.validate_auth_callback`, call `Utils::ShopValidator.sanitize!(auth_query.shop)` (as done in `ClientCredentials`, `RefreshToken`, and `TokenExchange`) and use the sanitized value to construct `null_session` and the final `Session`, rejecting the callback if the shop does not resolve to a trusted Shopify domain.

### Proof of Concept
1. A host application follows the documented pattern: parse OAuth callback query params into `ShopifyAPI::Auth::Oauth::AuthQuery` and call `ShopifyAPI::Auth::Oauth.validate_auth_callback(cookies:, auth_query:)`.
2. `validate_auth_callback` calls `Utils::HmacValidator.validate(auth_query)`, which only confirms the HMAC over `code, host, shop, state, timestamp` matches — it does not check that `shop` is `*.myshopify.com` or any trusted domain: [10](#0-9) 
3. `null_session = Auth::Session.new(shop: auth_query.shop)` is built directly from that unsanitized value, and `Clients::HttpClient.new(session: null_session, base_path: "/admin/oauth")` sets `@base_uri = "https://#{session.shop}"`, i.e., the exact host to which `client_id`/`client_secret`/`code` are POSTed: [11](#0-10) [12](#0-11) 
4. Compare to `ClientCredentials.client_credentials` and `RefreshToken.refresh_access_token`, which both call `Utils::ShopValidator.sanitize!(shop)` before doing the equivalent POST — confirming the missing check is specific to `validate_auth_callback` rather than a deliberate design choice.

        def validate_auth_callback(cookies:, auth_query:)
          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::InvalidOauthError, "Invalid OAuth callback." unless Utils::HmacValidator.validate(auth_query)
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = cookies[SessionCookie::SESSION_COOKIE_NAME]
          raise Errors::NoSessionCookieError unless state

          raise Errors::InvalidOauthError,
            "Invalid state in OAuth callback." unless state == auth_query.state

          null_session = Auth::Session.new(shop: auth_query.shop)
          body = {
            client_id: Context.api_key,
            client_secret: Context.api_secret_key,
            code: auth_query.code,
            expiring: Context.expiring_offline_access_tokens ? 1 : 0, # Only applicable for offline tokens
          }

          client = Clients::HttpClient.new(session: null_session, base_path: "/admin/oauth")
          response = begin
            client.request(
              Clients::HttpRequest.new(
                http_method: :post,
                path: "access_token",
                body: body,
                body_type: "application/json",
              ),
            )
          rescue ShopifyAPI::Errors::HttpResponseError => e
            raise Errors::RequestAccessTokenError,
              "Cannot complete OAuth process. Received a #{e.code} error while requesting access token."
          end

          session_params = T.cast(response.body, T::Hash[String, T.untyped]).to_h
          session = Session.from(shop: auth_query.shop,
            access_token_response: Oauth::AccessTokenResponse.from_hash(session_params))

          if result || Context.old_api_secret_key.nil? || T.must(Context.old_api_secret_key).empty?

          end
        end

        def validate_signature(verifiable_query, secret)
          received_signature = verifiable_query.hmac
          computed_signature = compute_signature(verifiable_query.to_signable_string, secret)
          OpenSSL.secure_compare(computed_signature, T.must(received_signature))
        end

      TRUSTED_SHOPIFY_DOMAINS = T.let(
        [
          "shopify.com",
          "myshopify.io",
          "myshopify.com",
          "spin.dev",
          "shop.dev",
        ].freeze,
        T::Array[String],
      )

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
