Audit Report

## Title
Low-privilege authenticated users (`view` role) can access `pprof` heap/profile dumps and `expvar` data that may expose private key material - ([File: core/web/router.go])

## Summary
The `net/http/pprof` debug routes registered by `metricRoutes` are mounted inside the `authv2` group via `metricRoutes(authv2)` with no role-based access control, unlike every other sensitive endpoint in the same router which is explicitly wrapped in `auth.RequiresEditRole` or `auth.RequiresAdminRole`. The `/v2/debug/vars` route registered by `debugRoutes` has the same gap. This allows any authenticated user holding the lowest-privilege `view` role to pull a live heap dump of the running node process, which the project's own documentation states may expose private key components.

## Finding Description
`v2Routes` builds the `authv2` group with only base authentication (`auth.Authenticate(..., auth.AuthenticateByToken, auth.AuthenticateBySession)`), and every sensitive route immediately around it is additionally wrapped with a role check, e.g. `authv2.DELETE("/keys/eth/:keyID", auth.RequiresAdminRole(ekc.Delete))` and `authv2.POST("/jobs", auth.RequiresEditRole(jc.Create))`. [1](#0-0) [2](#0-1) 

However, `metricRoutes(authv2)` — which registers `/debug/pprof/heap`, `/profile`, `/goroutine`, `/allocs`, etc. — is called at the end of the `authv2` block with no `RequiresEditRole`/`RequiresAdminRole` wrapper at all. [3](#0-2) [4](#0-3)  The `debugRoutes` function similarly exposes `/v2/debug/vars` (`expvar`) with only `auth.AuthenticateBySession`, no role check. [5](#0-4) 

`RequiresRunRole` and `RequiresEditRole` in `core/web/auth/auth.go` explicitly reject `UserRoleView`, confirming that `view` is treated as strictly lower-privileged than `run`/`edit`/`admin` throughout the codebase, and that omitting these wrappers from `metricRoutes`/`debugRoutes` is inconsistent with the rest of the router's access-control pattern. [6](#0-5) 

Because the pprof handlers are wired directly (`ginHandlerFromHTTP(pprof.Handler("heap").ServeHTTP)`) without any additional role gate, a request authenticated purely by a `view`-role session or API token satisfies the group's middleware chain and reaches the handler. [3](#0-2) 

## Impact Explanation
`GET /v2/debug/pprof/heap` returns a full heap dump of the running node process. The project's own configuration documentation for the now-hardcoded-enabled `InsecurePPROFHeap` setting states this "may potentially expose sensitive data e.g. private key components." Since access control here is broken relative to the router's own established pattern (every other key/credential-adjacent route requires at least `edit` or `admin`), a `view`-role credential — intended only for read-only dashboards/monitoring — can retrieve data that may include private key material or other secrets resident in memory. This maps to an in-scope key/secret exfiltration impact via a node-API privilege/role-check bypass.

## Likelihood Explanation
Exploitation requires nothing beyond a valid `view`-role session cookie or API token, which is the lowest-privilege credential the node issues and a common credential type for external monitoring/dashboard integrations. No additional access, timing, or race condition is needed — a single authenticated `GET` request to `/v2/debug/pprof/heap` (or `/v2/debug/vars`) is sufficient and repeatable at will.

## Recommendation
Wrap `metricRoutes(authv2)` and the `expvar` handler in `debugRoutes` with `auth.RequiresAdminRole` (or at minimum `auth.RequiresEditRole`), consistent with the access-control pattern applied to every other sensitive endpoint in `v2Routes`.

## Proof of Concept
1. As an admin, create a `view`-role user/API token via `authv2.POST("/users")` (`UserRoleView`).
2. Using only that `view`-role session cookie or `X-API-KEY`/`X-API-SECRET` token, send `GET /v2/debug/pprof/heap?debug=1` to the node.
3. Observe the request succeeds and returns a full heap profile — no `RequiresEditRole`/`RequiresAdminRole` check exists in `metricRoutes`, unlike sibling routes such as `authv2.DELETE("/keys/eth/:keyID", auth.RequiresAdminRole(...))`.
4. Repeat with `GET /v2/debug/vars` against `debugRoutes`, showing the same missing role check.

// RequiresRunRole extracts the user object from the context, and asserts the user's role is at least
// 'run'
func RequiresRunRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// RequiresEditRole extracts the user object from the context, and asserts the user's role is at least
// 'edit'
func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}
