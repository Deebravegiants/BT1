I found a confirmed concrete gap: `ValidateDeleteSecretsRequest` and `ValidateSecretIdentifier` never check the caller's authorized owner (from `AuthResult`) against the `Owner` field on each `SecretIdentifier` being deleted. This is different from the create/update path, which enforces `EnsureRightLabelOnSecret` (ciphertext label must equal the authorized owner) at `core/capabilities/vault/validator.go:321-341`, and different from list, which forcibly overwrites the request `Owner` with `authResult.AuthorizedOwner()` at `core/capabilities/vault/gw_handler.go:343`. Delete has no equivalent binding.

### Title
Vault delete-secrets path lacks owner-binding, allowing cross-tenant secret deletion by an authorized-but-unrelated caller - ([File: core/capabilities/vault/validator.go])

### Summary
`GatewayVaultRequestProcessor.processDeleteSecretsRequest` authorizes the JSON-RPC envelope (via allowlist/JWT digest match) but never verifies that the `Owner` field(s) inside the attacker-controlled `DeleteSecretsRequest.Ids` payload match the `AuthorizedOwner()` returned by the authorizer. `ValidateDeleteSecretsRequest` only checks structural constraints (non-empty ID, length limits, uniqueness), not ownership.

### Finding Description
For create/update requests, ownership binding is enforced explicitly and independently of the digest-authorization step: `EnsureRightLabelOnSecret` in `core/capabilities/vault/validator.go:321-341` cryptographically checks that the TDH2 ciphertext label equals `vaultutils.WorkflowOwnerToLabel(owner)` for the `Owner` claimed in each secret identifier, so a caller cannot smuggle another owner's identifier into a write. [1](#0-0) 

For list, `GatewayHandler.handleSecretsList` explicitly discards the client-supplied `Owner` and replaces it with `authResult.AuthorizedOwner()` before calling `ListSecretIdentifiers`, so the response is always scoped to the caller's authorized owner regardless of what was requested. [2](#0-1) 

For delete, however, `processDeleteSecretsRequest` unmarshals the raw client-controlled `DeleteSecretsRequest`, runs it through `ValidateDeleteSecretsRequest`, then hands it to `authorizeAndStamp` — but `authorizeAndStamp` only authorizes the JSON-RPC envelope digest/owner (via `AllowListBasedAuth`/`JWTBasedAuth`), it never inspects or rewrites the `Ids[].Owner` fields inside the request body. [3](#0-2) [4](#0-3) 

`ValidateDeleteSecretsRequest` confirms this: it validates `RequestId` non-empty, batch size limits, and per-identifier structural constraints (`ValidateSecretIdentifier`, which only checks length/charset, not ownership vs. the authenticated caller), and duplicate detection — but performs no comparison against an authorized owner at all. [5](#0-4) [6](#0-5) 

Finally, `handleSecretsDelete` on the node side re-unmarshals the same raw, unmodified `req.Params` and passes it straight to `secretsService.DeleteSecrets` with no owner substitution (unlike `handleSecretsList`, which stamps in `authResult.AuthorizedOwner()`). [7](#0-6) 

Because the allowlist-based authorization (`AllowListBasedAuth.AuthorizeRequest`) authorizes based on a digest of the *entire request* rather than validating field-level ownership of `Ids[].Owner`, and because a workflow owner (the entity being authorized) can construct any `DeleteSecretsRequest.Ids` payload and have it separately allowlisted on-chain for their own digest, the missing owner check means the only thing stopping a caller from deleting another owner's secret is that the caller must know the exact `key`/`namespace`/`owner` string of the target secret identifier — which is not treated as a secret, and is discoverable in various ways (e.g., via error messages, other workflows, shared namespaces, or brute-forcing common key names). If any such string is guessable/known, the delete goes through and the victim's secret is destroyed, since delete has no cryptographic proof-of-ownership analogous to `EnsureRightLabelOnSecret`, and no owner override analogous to `handleSecretsList`. [8](#0-7) 

### Impact Explanation
This allows an allowlisted-but-unrelated caller to delete secrets belonging to a different workflow owner/tenant, causing loss of availability (and potential downstream fund/operational risk if the deleted secret is a signing key, API credential, or similar used by dependent workflows) without any cryptographic ownership check — a direct analog of the "unauthorized fund movement / unauthorized state mutation via missing per-tenant authorization" bug class referenced in the TAC incident (an attacker acting within the system's normal trust boundary but able to affect state belonging to other tenants due to a missing ownership check on the mutating path).

### Likelihood Explanation
Likelihood depends on whether an attacker can learn or guess another owner's exact `SecretIdentifier{Key, Owner, Namespace}` tuple; this data is not itself cryptographically protected (unlike ciphertext), so it can plausibly leak through logs, shared documentation, predictable naming conventions, or error responses. The authorization step for `delete` only proves the caller controls a valid allowlisted digest for their own owner-scoped request — not that they own the referenced secret identifiers, so this is fully reachable from any unprivileged, digest-allowlisted client without further privilege escalation.

### Recommendation
Add an explicit owner-binding check in the delete path, mirroring the pattern used for create/update (`EnsureRightLabelOnSecret`) and list (`handleSecretsList`'s owner override): either (a) reject any `DeleteSecretsRequest.Ids[].Owner` that does not equal `authResult.AuthorizedOwner()` inside `authorizeAndStamp`'s `stamp` callback for delete, or (b) force-overwrite every `Ids[].Owner` with the authorized owner before dispatching to `secretsService.DeleteSecrets`, consistent with how list forces `r.Owner = authResult.AuthorizedOwner()`.

### Proof of Concept
1. Owner A allowlists (via `UserAllowlistRequest`/`AllowlistRequest`) a `DeleteSecretsRequest` JSON-RPC request whose digest matches a payload containing `Ids: [{Key: "known_key", Owner: "0xVictimOwnerB", Namespace: "default"}]`.
2. The DON authorizes the request because the *envelope digest* matches an allowlisted entry owned by Owner A — `AllowListBasedAuth.AuthorizeRequest` returns `AuthResult{workflowOwner: "0xOwnerA", ...}` since authorization is keyed off the caller's on-chain allowlist entry, not the payload's `Owner` fields.
3. `processDeleteSecretsRequest` → `ValidateDeleteSecretsRequest` → `authorizeAndStamp` all pass without any comparison of `Ids[].Owner` ("0xVictimOwnerB") to `AuthResult.AuthorizedOwner()` ("0xOwnerA").
4. `handleSecretsDelete` unmarshals the untouched params and calls `secretsService.DeleteSecrets` with `Owner: "0xVictimOwnerB"`, deleting Owner B's secret despite the request being authorized only for Owner A.

**Note on scope/confidence**: I was not able to fully inspect `secretsService.DeleteSecrets`'s internal implementation (which may perform an additional, out-of-band ownership check not visible in the reviewed files) or the `AuthResult`/`Authorizer` implementations beyond `allow_list_based_auth.go`, due to index coverage limits on some files. If `DeleteSecrets` internally re-validates `Ids[].Owner` against a caller-context owner threaded through `ctx` (e.g., via `contexts.WithCRE`), this finding would be mitigated — I recommend a Devin session with full repo access to confirm the `secretsService.DeleteSecrets` implementation and the `Authorizer`/`JWTBasedAuth` code before treating this as fully proven.

func (r *RequestValidator) ValidateDeleteSecretsRequest(ctx context.Context, request *vaultcommon.DeleteSecretsRequest) error {
	if request.RequestId == "" {
		return errors.New("request ID must not be empty")
	}
	if err := r.MaxRequestBatchSizeLimiter.Check(ctx, len(request.Ids)); err != nil {
		if errBoundLimited, ok := errors.AsType[limits.ErrorBoundLimited[int]](err); ok {
			return fmt.Errorf("request batch size exceeds maximum of %d: %w", errBoundLimited.Limit, err)
		}
		return fmt.Errorf("failed to check request batch size limit: %w", err)
	}
	if len(request.Ids) == 0 {
		return errors.New("request batch must contain at least 1 item")
	}

	uniqueIDs := map[string]bool{}
	for idx, id := range request.Ids {
		if id == nil {
			return errors.New("secret ID must not be nil at index " + strconv.Itoa(idx))
		}
		if err := r.ValidateSecretIdentifier(ctx, id.Key, id.Owner, id.Namespace); err != nil {
			return fmt.Errorf("invalid secret identifier at index %d: %w", idx, err)
		}

		_, ok := uniqueIDs[vaulttypes.KeyFor(id)]
		if ok {
			return errors.New("duplicate secret ID found at index " + strconv.Itoa(idx) + ": " + id.String())
		}

		uniqueIDs[vaulttypes.KeyFor(id)] = true
	}
	return nil
}

// EnsureRightLabelOnSecret verifies that the TDH2 ciphertext label matches the workflow
// owner label (Ethereum address, left-padded to 32 bytes). owner must be non-empty;
// when the public key is nil, verification is skipped for the same reasons as
// verifyEncryptedSecret.
func EnsureRightLabelOnSecret(publicKey *tdh2easy.PublicKey, secret, owner string) error {
	cipherText, err := verifyEncryptedSecret(publicKey, secret)
	if err != nil {
		return err
	}
	if cipherText == nil {
		return nil
	}
	if owner == "" {
		return errors.New("owner must not be empty for secret label verification")
	}

	expected := vaultutils.WorkflowOwnerToLabel(owner)
	secretLabel := cipherText.Label()
	if secretLabel == expected {
		return nil
	}

	return fmt.Errorf("secret label [%s] does not match workflow owner label [%s]",
		hex.EncodeToString(secretLabel[:]), hex.EncodeToString(expected[:]))
}

func (p *GatewayVaultRequestProcessor) processDeleteSecretsRequest(
	ctx context.Context,
	req *jsonrpc.Request[json.RawMessage],
) (*AuthorizedGatewayVaultRequest, error) {
	if req.Params == nil {
		return nil, InvalidVaultParamsError{Method: req.Method, Err: errors.New("request params must not be nil")}
	}

	var deleteReq vaultcommon.DeleteSecretsRequest
	if err := json.Unmarshal(*req.Params, &deleteReq); err != nil {
		return nil, InvalidVaultParamsError{Method: req.Method, Err: err}
	}
	if p.stripOwnerPrefixForAuth {
		deleteReq.RequestId = req.ID
		if err := marshalVaultParams(req, &deleteReq); err != nil {
			return nil, InvalidVaultParamsError{Method: req.Method, Err: err}
		}
	} else {
		deleteReq.RequestId = coalesceRequestID(deleteReq.RequestId, req.ID)
	}

	if err := p.validator.ValidateDeleteSecretsRequest(ctx, &deleteReq); err != nil {
		return nil, p.validationError(req, err)
	}

	return p.authorizeAndStamp(ctx, req, func(prefixedRequestID string) error {
		deleteReq.RequestId = prefixedRequestID
		vaultutils.ApplySecretIdentifierNamespaceDefaults(deleteReq.Ids)
		return marshalVaultParams(req, &deleteReq)
	})
}

func (p *GatewayVaultRequestProcessor) authorizeAndStamp(
	ctx context.Context,
	req *jsonrpc.Request[json.RawMessage],
	stamp func(prefixedRequestID string) error,
) (*AuthorizedGatewayVaultRequest, error) {
	incomingOwner := ""
	if idx := strings.Index(req.ID, vaulttypes.RequestIDSeparator); idx != -1 {
		incomingOwner = req.ID[:idx]
	}

	p.lggr.Debugw("authorizing gateway vault request", "method", req.Method, "requestID", req.ID)
	authResult, err := p.authorizer.AuthorizeRequest(ctx, *req)
	if err != nil {
		authErr := fmt.Errorf("request not authorized: %w", err)
		p.lggr.Errorw("gateway vault request authorization failed", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "", "incomingOwner", incomingOwner, "error", authErr)
		return nil, authErr
	}

	originalRequestID := req.ID
	authorizedOwner := authResult.AuthorizedOwner()
	prefixedRequestID := authorizedOwner + vaulttypes.RequestIDSeparator + originalRequestID
	req.ID = prefixedRequestID

	if err := stamp(prefixedRequestID); err != nil {
		p.lggr.Errorw("failed to stamp authorized request params", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, fmt.Errorf("failed to stamp authorized request params: %w", err)
	}

	p.lggr.Debugw("authorized gateway vault request", "method", req.Method, "requestID", req.ID, "owner", authorizedOwner, "orgID", authResult.OrgID(), "workflowOwner", authResult.WorkflowOwner())
	return &AuthorizedGatewayVaultRequest{
		Req:        *req,
		AuthResult: authResult,
	}, nil
}

// AuthorizeRequest authorizes a request using AllowListBasedAuth.
// It does NOT check if the request method is allowed.
func (r *allowListBasedAuth) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	r.lggr.Debugw("AllowListBasedAuth authorizing request", "method", req.Method, "requestID", req.ID)
	requestDigest, err := req.Digest()
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to create digest", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, err
	}
	requestDigestBytes, err := hex.DecodeString(requestDigest)
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to decode digest", "method", req.Method, "requestID", req.ID, "requestDigest", requestDigest, "error", err)
		return nil, err
	}
	requestDigestBytes32 := [32]byte(requestDigestBytes)
	if r.workflowRegistrySyncer == nil {
		r.lggr.Errorw("AllowListBasedAuth workflowRegistrySyncer is nil", "method", req.Method, "requestID", req.ID)
		return nil, errors.New("internal error: workflowRegistrySyncer is nil")
	}
	allowlistedRequest, allowedRequestsStrs, err := r.findAllowlistedItemWithRetry(ctx, req, requestDigest, requestDigestBytes32)
	if err != nil {
		return nil, err
	}
	if allowlistedRequest == nil {
		r.lggr.Debugw("AllowListBasedAuth request digest not allowlisted",
			"method", req.Method,
			"requestID", req.ID,
			"digestHexStr", requestDigest,
			"allowedRequestsStrs", allowedRequestsStrs)
		return nil, errors.New("request not allowlisted")
	}

	if time.Now().UTC().Unix() > int64(allowlistedRequest.ExpiryTimestamp) {
		authorizedRequestStr := string(allowlistedRequest.RequestDigest[:])
		r.lggr.Debugw("AllowListBasedAuth authorization expired", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", authorizedRequestStr, "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
		return nil, errors.New("request authorization expired")
	}

	digestKey := string(allowlistedRequest.RequestDigest[:])
	r.lggr.Debugw("AllowListBasedAuth authorization succeeded", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", digestKey, "owner", allowlistedRequest.Owner.Hex(), "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
	return &AuthResult{
		workflowOwner: allowlistedRequest.Owner.Hex(),
		digest:        digestKey,
		expiresAt:     int64(allowlistedRequest.ExpiryTimestamp),
	}, nil
}
