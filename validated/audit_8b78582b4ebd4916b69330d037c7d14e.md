## Title
Unauthorized bandwidth crediting lets any purchaser flood a victim app's subscription FIFO to permanently evict its paid allowance - (File: modules/pallets/bandwidth/src/lib.rs)

## Summary
`pallet-bandwidth`'s `on_accept` credits a `(app_chain, app)` bandwidth subscription bucket using the `app` and `chain` fields taken entirely from the inbound `BandwidthPurchaseMsg` body, with no check that the payer controls or is related to the target `app`. `BandwidthManager.purchase()` on the EVM side lets *any* caller specify an arbitrary `app` and pay only the cheapest configured tier. Because each `(chain, app)` bucket is a FIFO `BoundedVec` capped at `MAX_SUBSCRIPTIONS` (1024) that **evicts the oldest entry with no refund** once full, an unprivileged attacker can repeatedly purchase the cheapest tier for a victim's `app` identifier to fill the victim's queue and force-evict a legitimately paid, larger/longer subscription, permanently destroying its `remaining_bytes`. This mirrors the Ajna H-6 pattern: cheap, permissionless, repeatable "dust" entries injected into a bounded, FIFO-ordered protocol structure to force eviction/blocking of another party's economically significant position, causing them irrecoverable loss.

## Finding Description
`purchase()` in `evm/src/apps/BandwidthManager.sol` accepts an arbitrary `app` parameter from `msg.sender` with the only guards being non-empty `app`/`chain`, `months > 0`, and a known/priced `tier`: [1](#0-0) 

There is no check that `msg.sender` is, owns, or is authorized to spend on behalf of `app`. The message is then dispatched to `pallet-bandwidth`.

On the Hyperbridge side, `on_accept` only validates that the request came from the registered `BandwidthManager` contract for that source chain — it does not (and structurally cannot) validate that the purchaser has any relationship to the `app` being credited: [2](#0-1) 

The allowance storage is keyed by `(app_chain, app)` — deliberately independent of `request.source`/payer, to support cross-chain sponsorship — but this same design allows any payer to target any `app`: [3](#0-2) 

Each purchase appends to a `SubscriptionList` bounded at `MAX_SUBSCRIPTIONS` (1024). Once full, `push_subscription` evicts the *oldest* subscription — regardless of its remaining value — and emits `SubscriptionEvicted` with the lost bytes, explicitly acknowledging the loss is unrecoverable: [4](#0-3) 

This is structurally identical to the Ajna bug class: a cheap, repeatable, permissionless action (dust quote-token deposits in Ajna; dust Tier-1 bandwidth purchases here) is used to populate a bounded, order-processed data structure (Fenwick-bucket iteration in Ajna; FIFO `BoundedVec` here) in order to force an outcome harmful to another party (blocked debt settlement in Ajna; forced eviction of a legitimately-paid subscription here), with no dust/spend-authorization control at the entry point (`addQuoteToken()` in Ajna; `purchase()` here).

## Impact Explanation
A victim app that has purchased a large/long-duration tier (e.g., the $1000/8MB plan) can have that subscription evicted and its unused `remaining_bytes` permanently destroyed by an attacker who fills the remaining slots in the victim's FIFO queue with cheap Tier-1 purchases. This is a direct, unrecoverable loss of prepaid funds for the victim (`SubscriptionEvicted.lost_bytes` is by design non-refundable), and it can also be used to disrupt an app's dispatch capability by evicting its only live allowance right when it is needed, causing the `BandwidthGate` to reject the app's legitimate ISMP messages (`GateError::NoAllowance` / `Insufficient`). This satisfies "concrete theft or permanent freezing of funds" — the victim's paid-for bandwidth allowance is destroyed with no path to recovery, and their app's message-dispatch capability can be denied.

## Likelihood Explanation
The attack is fully permissionless: any address can call `BandwidthManager.purchase()` for any `app`/`chain` combination without holding any relationship to that app, at the cost of only Tier-1 purchases ($50 per 100 KB unit, scaled by `months`). The number of purchases needed to fill/evict from an existing queue is bounded by `1024 - len(list)`, which can be small if the victim has few subscriptions, making a targeted eviction economically feasible, especially against an app that just made its one large purchase and has not yet consumed it. No governance or admin action is required to trigger the eviction path — `push_subscription` is invoked unconditionally from `on_accept` for every purchase.

## Recommendation
Restrict who may credit an `(app_chain, app)` bucket, or otherwise decouple "who pays" from "what gets evicted": e.g., require the purchase message to be signed/authorized by the app itself (or a registered operator) for that specific `app`, or partition eviction risk so unrelated third-party purchases cannot evict a higher-tier/larger subscription that a different payer or the app owner placed. At minimum, mirror the Ajna fix pattern (`_revertIfAboveHeadAuctionPrice`-style gating) by adding an authorization/allowlist check in `push_subscription`/`on_accept` so that crediting an app's bandwidth requires either the app's own consent or a minimum-value threshold that makes griefing-by-eviction economically irrational, e.g., by not evicting subscriptions that still have significant unexpired duration/bytes remaining, or by evicting the eligible entry with lowest remaining value rather than strictly FIFO-oldest.

## Proof of Concept
1. Victim app `V` calls `BandwidthManager.purchase(app=V, tier=4 ($1000/8MB), months=1, chain="EVM-8453")`. `pallet-bandwidth::on_accept` pushes a `Subscription{tier:4, remaining_bytes: 8MB, expires_at: now+30d}` onto `Allowance[EVM-8453][V]` (list length 1).
2. Attacker `A` (no relationship to `V`) repeatedly calls `BandwidthManager.purchase(app=V, tier=1 ($50/100KB), months=1, chain="EVM-8453")`, 1023 times, each dispatching a cheap purchase message to `pallet-bandwidth`.
3. Each call runs `on_accept` → `push_subscription`, appending a new Tier-1 subscription for `(EVM-8453, V)`. Once `Allowance[EVM-8453][V].len() == 1024`, the 1025th call (`A`'s last purchase) forces `list.remove(0)` — evicting `V`'s Tier-4 subscription and emitting `SubscriptionEvicted{app: V, tier: 4, lost_bytes: 8MB (or whatever remains)}`.
4. `V`'s legitimately purchased 8 MB / 30-day allowance is now gone with no refund path; `V`'s app is left with only attacker-injected Tier-1 dust subscriptions (or none, if `A` stops purchasing), potentially causing `BandwidthGate::try_consume` to reject `V`'s subsequent dispatches with `GateError::Insufficient`/`NoAllowance`.

		/// Append a fresh subscription with a fixed expiry. If the list
		/// is already at `MaxSubscriptions`, evict the oldest entry and
		/// emit [`Event::SubscriptionEvicted`] so the lost bytes are
		/// auditable. Returns the new subscription's `expires_at`.
		fn push_subscription(
			app_chain: &StateMachine,
			app: &AppKey,
			tier: TierIndex,
			bytes: BandwidthBytes,
			duration_secs: u64,
		) -> u64 {
			let now = <T as pallet_ismp::Config>::TimestampProvider::now().as_secs();
			let expires_at = now.saturating_add(duration_secs);
			let new_sub =
				Subscription { tier, remaining_bytes: bytes, expires_at, purchased_at: now };

			let evicted = Allowance::<T>::mutate(app_chain, app, |list| {
				let evicted = if list.len() == MAX_SUBSCRIPTIONS as usize {
					Some(list.remove(0))
				} else {
					None
				};
				// Capacity is now guaranteed; try_push can't fail.
				let _ = list.try_push(new_sub);
				evicted
			});

			if let Some(old) = evicted {
				Self::deposit_event(Event::SubscriptionEvicted {
					app_chain: *app_chain,
					app: app.clone(),
					tier: old.tier,
					lost_bytes: old.remaining_bytes,
				});
			}

			expires_at
		}

	impl<T: Config> IsmpModule for Pallet<T> {
		fn on_accept(&self, request: PostRequest) -> Result<Weight, anyhow::Error> {
			let manager = BandwidthManager::<T>::get(&request.source).ok_or_else(|| {
				anyhow::anyhow!(format!("no bandwidth manager registered for {:?}", request.source))
			})?;

			if request.from != manager.0.to_vec() {
				return Err(anyhow::anyhow!(format!(
					"purchase from unauthorised sender on {:?}: expected {:x?}, got {:x?}",
					request.source, manager.0, request.from
				)));
			}

			let msg = PurchaseMessage::try_from(request.body.as_slice())?;
			let tier = TierIndex::try_from(msg.tier)
				.map_err(|_| anyhow::anyhow!(format!("unknown tier discriminant {}", msg.tier)))?;
			let cfg = Tiers::<T>::get(tier)
				.ok_or_else(|| anyhow::anyhow!(format!("tier {:?} is not configured", tier)))?;

			let bytes = cfg.bytes.saturating_mul(msg.months as u128);
			let duration = cfg.duration_secs.saturating_mul(msg.months as u64);

			let key = AppKey::truncate_from(msg.app);
			let expires_at = Self::push_subscription(&msg.chain, &key, tier, bytes, duration);

			Self::deposit_event(Event::BandwidthCredited {
				app_chain: msg.chain,
				app: key,
				paid_from: request.source,
				tier,
				bytes,
				expires_at,
			});

			Ok(Weight::zero())
		}
