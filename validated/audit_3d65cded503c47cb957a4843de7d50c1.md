Audit Report

## Title
Unbounded accumulation of per-request state in confidential relay gateway handler enables memory-exhaustion DoS - (File: core/services/gateway/handlers/confidentialrelay/handler.go)

## Summary
The confidential relay gateway's `HandleJSONRPCUserMessage` creates an `activeRequest` entry in `h.activeRequests` for every distinct incoming JSON-RPC request ID, with no cap on the total number of concurrently tracked requests. `newActiveRequest` only rejects a request whose exact ID already exists, never enforcing a size bound analogous to `requestCache[T].maxCacheSize` used by the sibling generic request-tracking primitive.

## Finding Description
`HandleJSONRPCUserMessage` accepts any JSON-RPC request with a non-empty ID ≤200 characters and immediately calls `h.newActiveRequest`, which inserts into `h.activeRequests` after only checking for an ID collision [1](#0-0) . `newActiveRequest` itself contains no size/count check before insertion [2](#0-1) .

Critically, this handler performs no authentication, attestation, or authorization check of its own before accepting the request into `activeRequests` — it is explicitly documented as "a dumb relay" that fans requests out to DON nodes without interpreting params [3](#0-2) . The actual attestation/workflow-DON-authorization checks (`verifyAttestationHash`, `verifyWorkflowAuthorization`) live downstream in the enclave-side capability handler (`core/capabilities/confidentialrelay/handler.go`), not in the gateway path that populates `activeRequests`. So an unprivileged caller reaching the gateway's HTTP endpoint can create entries before any of those checks execute.

Each entry survives up to `requestTimeout` (default 30s) via the periodic (1s-interval) cleanup goroutine [4](#0-3) , and each entry additionally holds a `responses` map sized up to `len(donConfig.Members)` [5](#0-4) .

By contrast, the generic `requestCache[T]` used elsewhere in the gateway explicitly enforces `maxCacheSize` and rejects new entries once full [6](#0-5) , confirming this is an intentional design pattern that the confidential relay handler does not follow. The HTTP layer's `MaxRequestBytesLimiter`/`MaxBytesReader` bounds only a single request body's size, not the number of distinct requests that reach the handler [7](#0-6) .

## Impact Explanation
An unprivileged caller able to submit many distinct, well-formed JSON-RPC requests (unique IDs) to the confidential relay's `MethodSecretsGet`/`MethodCapabilityExec` methods faster than the 30-second timeout expires them can drive unbounded growth of `h.activeRequests`, consuming gateway node memory and potentially causing OOM/availability loss for the gateway process. This maps to CWE-770 (Allocation of Resources Without Limits or Throttling) and is a legitimate availability/DoS finding against the gateway component.

## Likelihood Explanation
Reaching `newActiveRequest` requires no valid attestation, signature, or authorization — those checks happen only downstream at the enclave capability handler, after the gateway has already inserted the entry into its map. The gateway HTTP server enforces per-body size limits but no per-sender or global concurrency/rate cap ahead of this insertion point. A scripted client sending many uniquely-IDed requests can trigger unbounded growth realistically and repeatably.

## Recommendation
Add an explicit maximum-size guard to `h.activeRequests` (mirroring `requestCache[T].maxCacheSize`) and reject new requests once the cap is reached (e.g., with `429`/`RequestTimeoutError`). Additionally, consider gating entry into `newActiveRequest` with a global or per-sender rate limiter, since currently no rate limiter exists on the inbound user-request path (the existing `globalNodeRateLimiter`/`perNodeRateLimiters` only guard `HandleNodeMessage`, the DON-response path, not the user-request path).

## Proof of Concept
1. Configure a confidential relay handler with default `RequestTimeoutSec` (30s).
2. As an unauthenticated/unprivileged HTTP client, repeatedly POST JSON-RPC requests for `MethodSecretsGet` (or `MethodCapabilityExec`) to the gateway's user-facing HTTP endpoint, each with a distinct random `id`, without needing valid attestation data (the request is accepted into `activeRequests` before attestation is checked downstream).
3. Send these faster than the 1-second cleanup tick can expire them relative to the 30-second timeout (e.g., hundreds to thousands per second).
4. Observe `h.activeRequests` size and gateway process memory grow proportionally to request volume with no rejection until host memory pressure/OOM, since `newActiveRequest` only checks for duplicate IDs, never a total-count cap.

func (h *handler) removeExpiredRequests(ctx context.Context) {
	h.mu.RLock()
	var expiredRequests []*activeRequest
	now := h.clock.Now()
	for _, userRequest := range h.activeRequests {
		if now.Sub(userRequest.createdAt) > h.requestTimeout {
			expiredRequests = append(expiredRequests, userRequest)
		}
	}
	h.mu.RUnlock()

	for _, er := range expiredRequests {
		responses := er.copiedResponses()
		l := h.requestLogger(er.req, er.labels)
		l.Debugw("request expired, evaluating collected relay responses",
			"collected", len(responses),
			"nodes", len(h.donConfig.Members),
			"unanswered", len(h.donConfig.Members)-len(responses),
		)
		summary, err := h.bundler.Bundle(er.req, responses, l)
		if err != nil {
			l.Errorw("failed to build relay response bundle", "error", err)
			if sendErr := h.sendResponseAndClearRequest(ctx, er, h.constructErrorResponse(er.req, api.FatalError, err)); sendErr != nil {
				l.Errorw("error returning bundle failure on expiry", "error", sendErr)
			}
			continue
		}
		// Expiry makes further responses unavailable to this request. The common
		// readiness path forwards a viable partial bundle or returns a timeout.
		if err := h.forwardBundleOrTerminateIfReady(ctx, l, er, summary, 0, true); err != nil {
			l.Errorw("error forwarding bundle on expiry", "error", err)
		}
	}
}

func (h *handler) HandleJSONRPCUserMessage(ctx context.Context, req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) error {
	if req.ID == "" {
		return errors.New("request ID cannot be empty")
	}
	if len(req.ID) > 200 {
		return errors.New("request ID is too long: " + strconv.Itoa(len(req.ID)) + ". max is 200 characters")
	}

	labels := h.extractRequestLabels(req)
	l := h.requestLogger(req, labels)
	l.Debugw("handling confidential relay request", "nodes", len(h.donConfig.Members), "f", h.donConfig.F)

	ar, err := h.newActiveRequest(req, labels, callback)
	if err != nil {
		return err
	}

	return h.fanOutToNodes(ctx, l, ar)
}

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], labels requestLabels, callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID, "executionID", labels.ExecutionID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		labels:    labels,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

func (c *requestCache[T]) NewRequest(lggr logger.Logger, request *api.Message, callback handlers.Callback, responseData *T) error {
	if request == nil {

	}
	if responseData == nil {
		return errors.New("responseData is nil")
	}
	key := globalID{request.Body.Sender, request.Body.MessageID}
	c.mu.Lock()
	defer c.mu.Unlock()
	_, ok := c.cache[key]
	if ok {
		return errors.New("request already exists")
	}
	if len(c.cache) >= int(c.maxCacheSize) {
		return errors.New("request cache is full")
	}
