### Title
Sell path calls `Bonding.canGraduate()`, which reverts if the reserve LT's `exchangeRate()` reverts, freezing the only advertised exit path - ([File: packages/contracts/src/Zap.sol], [File: packages/contracts/src/Bonding.sol])

### Summary
`Zap._sellInternal` unconditionally calls `Bonding.canGraduate(tokenAddress)` before executing a sell, and `canGraduate` makes a live external call to `IBounceLeveragedToken(ltAddress).exchangeRate()` whenever the pair isn't fully drained. If that external call reverts — the same class of failure the original report describes for an oracle going offline or a price going to zero — every sell for that token reverts too, not just buys, contradicting the protocol's own documented invariant that holders can "always exit via redeem."

### Finding Description
`Bonding.canGraduate` reads the LT's `exchangeRate()` on the USD-trigger leg: [1](#0-0) 

`Zap._sellInternal` calls this view **before** doing anything else on the sell path, as a graduation-redirect gate: [2](#0-1) 

`_buyInternal`/`_executeBuy` documents explicitly that mint-pausing on the LT freezes buys but "sells keep working (sells go through `redeem`, not `mint`)... a sell-only market is preferable to freezing both sides, since holders can still exit to USDC": [3](#0-2) 

This design assumption is broken because the sell path itself makes an unguarded, unconditional external call to `exchangeRate()` via `canGraduate()` before it ever reaches `redeem()`. If `exchangeRate()` reverts for any reason external to alt.fun's own contracts (the LT's own oracle/read path failing, a stuck operator flag, or any other condition that makes the view call revert instead of returning a stale/degraded number — precisely analogous to a Chainlink feed going offline or a price collapsing to zero in the original report), the revert propagates straight up through `canGraduate` → `Zap._sellInternal`, aborting the sell before `redeem()` is ever invoked. The docs' "Retired LTs" note only covers the case where `exchangeRate()` keeps returning a stale value without reverting; it does not address the case where the call itself reverts, which is exactly the scenario the original report is about (oracle/price source going down, not just going stale).

Because `canGraduate` is on the required call path of every sell (not just an occasional graduation check), and there is no try/catch or fallback anywhere in `Zap` or `Bonding` around this external call, alt.fun's own architecture — not BounceTech's LT internals — is what turns a single external read failure into a total freeze of both sides of the market for that token, exactly matching the M-6 bug class ("if a token's price source goes down, the liquidation/exit function reverts because it unconditionally calls into that price source with no safeguard").

### Impact Explanation
While the LT's `exchangeRate()` is unavailable, holders of the affected token cannot sell through `Zap.sell`/`Zap.sellWithPermit` at all — the one path the team explicitly relies on as the "always available" exit valve is bricked along with buys. This is a direct freezing of trader funds: tokens are stuck (transfers to `Bonding`/`Pair`/`Zap` for a sell will simply revert), and holders cannot redeem their exposure to USDC while the underlying issue persists, at exactly the moment (LT distress / price collapse) when the ability to exit matters most — the same "protocol needs liquidations/exits most and they're frozen" scenario from the original report.

### Likelihood Explanation
The trigger condition (the LT's `exchangeRate()` reverting) is outside alt.fun's control and depends on BounceTech's own contract behavior, so likelihood is tied to an external dependency rather than an attacker-controlled action. However, no unprivileged action is required to trigger the freeze once the external condition occurs — it happens passively on the very next `Zap.sell` call by any ordinary trader. Given that the reserve asset design explicitly builds on a leveraged, rebasing, externally-priced token (`IBounceLeveragedToken`), and the protocol's own comments acknowledge accepted "drift" and "frozen leverage" scenarios for this dependency, a revert-on-read failure of `exchangeRate()` is a foreseeable extreme-market/degraded-oracle condition for this specific external dependency class.

### Recommendation
Do not gate the sell path on a live, unguarded external call to `exchangeRate()`. Wrap the `canGraduate()` call (or at minimum the `exchangeRate()` read inside it) in `try/catch` within `Zap._sellInternal`, and fall back to executing the ordinary curve/AMM sell + `redeem()` flow if the graduation check cannot be evaluated, rather than reverting the entire sell. This preserves the documented invariant that `redeem()`-based exits remain available regardless of the health of the LT's price-reporting view.

### Proof of Concept
1. A token is live on the bonding curve with `Lifecycle.Curve` and `IPair(pair).tokenBalance() != 0` (normal, non-sold-out state).
2. The paired `IBounceLeveragedToken`'s `exchangeRate()` begins reverting (analogous to an oracle outage or the LT entering a degraded/frozen price state upstream — outside alt.fun's control, mirroring the Chainlink-outage scenario in the original report).
3. Any holder calls `Zap.sell(tokenAddress, tokenAmount, minUsdcOut)`.
4. `_sellInternal` calls `bonding_.canGraduate(tokenAddress)` at [4](#0-3) , which calls `IBounceLeveragedToken(info.ltAddress).exchangeRate()` inside `canGraduate` at [5](#0-4) .
5. The revert propagates out of `canGraduate`, out of `_sellInternal`, and the entire `Zap.sell` transaction reverts — before `_sellOnCurve`/`redeem()` is ever reached — despite the protocol's documented claim that sells/redeems remain available when the LT's mint side is impaired.

```text
    function canGraduate(
        address token_
    ) public view returns (bool) {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[token_];
        if (info.creator == address(0)) return false;
        if (info.lifecycle != Lifecycle.Curve) return false;

        address pair = info.pair;
        if (IPair(pair).tokenBalance() == 0) return true;

        (, uint256 assetReserve) = IPair(pair).getReserves();
        uint256 realLtRaised = assetReserve - _launchTimeVirtualLtReserve(token_, pair);
        uint256 valueUsd = (realLtRaised * IBounceLeveragedToken(info.ltAddress).exchangeRate()) / 1e18;
        return valueUsd >= $.graduationThresholdUsd;
    }
```
