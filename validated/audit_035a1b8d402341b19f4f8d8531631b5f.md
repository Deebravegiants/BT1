### Title
Unprivileged view-role user can enumerate all External Initiators' `AccessKey`/`OutgoingToken` credentials via `GET /v2/external_initiators` - (File: core/web/external_initiators_controller.go)

### Summary
`GET /v2/external_initiators` is reachable by any authenticated user with the lowest privilege role (`view`), and returns, for every External Initiator configured on the node, its `AccessKey` and `OutgoingToken` fields in the paginated JSON response.

### Finding Description
The route is registered without any role restriction beyond generic authentication: [1](#0-0) 

and the route-role test table explicitly documents that `view`, `run`, and `edit` roles are all allowed on this GET endpoint: [2](#0-1) 

The handler `ExternalInitiatorsController.Index` fetches all initiators from the DB and serializes them without filtering sensitive fields: [3](#0-2) 

The presenter used for this list, `ExternalInitiatorResource`, includes `AccessKey` and `OutgoingToken` in the JSON payload: [4](#0-3) 

`AccessKey` is the identifier that, together with the (not-returned) `Secret`, is used by external initiators to authenticate inbound job-run trigger requests to the node (`AuthenticateExternalInitiator` in `core/bridges/external_initiator.go`), and `OutgoingToken` is a credential generated at creation time and stored alongside `OutgoingSecret` for use when the node calls out to the external initiator: [5](#0-4) 

While the `HashedSecret`/`OutgoingSecret` values themselves are not included in the list response (only in the one-time creation response, `ExternalInitiatorAuthentication`), disclosure of every configured initiator's `AccessKey` and `OutgoingToken` to any authenticated low-privilege (`view`) user is unintended cross-tenant/cross-scope information disclosure: a node may have multiple External Initiators configured by different admins/integrations, and a `view`-role account (which is meant to be read-only/observability) can enumerate the full set of `AccessKey`/`OutgoingToken` values it has no operational need to see. This mirrors the reported bug class (`getAllList` returning data belonging to all entities, not scoped to the caller) even though here it is gated behind authentication rather than fully anonymous.

### Impact Explanation
Exposure of `AccessKey` values for all External Initiators to a low-privileged `view` user increases the attack surface for credential-stuffing/guessing against the paired secret, and gives a `view`-role account visibility into integration topology (`OutgoingToken`, names, URLs) it should not have per the RBAC model's intent (view = read-only monitoring). This is a confidentiality-only issue (no direct write/impersonation capability from the leaked `AccessKey` alone, since `Secret`/`HashedSecret` are not exposed), consistent with the CVSS 5.3 (C:L) rating of the reference CVE.

### Likelihood Explanation
Any authenticated user, including one provisioned with only the `view` role (the lowest privilege tier in Chainlink's RBAC), can trivially call this endpoint — no special conditions or race required, and pagination confirms the full initiator set is enumerable across pages.

### Recommendation
Restrict `GET /v2/external_initiators` to `auth.RequiresEditRole` or `auth.RequiresAdminRole` (consistent with `POST`/`DELETE` on the same resource, which already require edit role), or strip `AccessKey`/`OutgoingToken` from the list presenter for non-privileged callers, only exposing full credential detail on a scoped, admin-only endpoint.

### Proof of Concept
1. Create a user with `view` role (e.g., via `chainlink admin users create --role=view`).
2. Have an admin create at least one External Initiator via `POST /v2/external_initiators`.
3. Authenticate as the `view`-role user and call `GET /v2/external_initiators`.
4. Observe the response includes `accessKey` and `outgoingToken` for every configured External Initiator, as verified by the existing test asserting these fields are present in the Index response: [6](#0-5)  — but with no test enforcing that only privileged roles may reach this data (`routesRolesMap` marks `viewOnlyAllowed: true` for this route) [2](#0-1) .

```go
func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}
```

```go
		URL:           ei.URL,
		AccessKey:     ei.AccessKey,

}
```
