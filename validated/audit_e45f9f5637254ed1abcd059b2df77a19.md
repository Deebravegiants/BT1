### Title
Uniswap V4 spot-price venue oracle with disabled overfill clamp lets a manipulated pool drain solver funding on fills - (File: `sdk/packages/simplex/src/strategies/fx.ts`)

### Summary
Simplex's `FXFiller` prices curveless cross-asset legs directly off a live Uniswap V4 pool's spot price (`sqrtPriceX96`) instead of a TWAP, guards that price only with an optional, static `maxDeviationBps` band, and — per an explicit code comment — has its per-leg overfill safety clamp **disabled**, turning what used to be a hard cap into a warning-only log line. An attacker who moves the pool price within a block (flash-swap style) and then has an order routed through this venue-priced leg can force the filler to compute and pay out an output amount far beyond the user-requested amount, with no on-chain cap to stop it.

### Finding Description
For pairs configured without bid/ask curves, `resolveLegRates` prices the leg from a Uniswap V4 pool quote rather than a static curve: [1](#0-0) 

The quote itself comes from `UniswapV4FundingPlanner.getExoticTokenPrice` / `computeDirectPoolPriceUsd`, which reads the pool's current tick/`sqrtPriceX96` via `StateView.getSlot0` on every refresh — a pure spot price with no time-weighting: [2](#0-1) [3](#0-2) 

The only defense against a manipulated/stale/thin pool is `checkPriceGuard`, which compares the live quote to a **static, operator-configured** `referencePrice`/`maxDeviationBps`. This guard is optional — the docs state "omit both to leave the chain unguarded" — and even when configured it only bounds *deviation from a stale reference*, not execution/slippage cost: [4](#0-3) [5](#0-4) 

Critically, the per-leg loss bound that historically existed to catch exactly this scenario has been intentionally disabled. The code computes an `overfillCeiling` from the user-requested amount and `maxOverfillBps`, but — per the inline comment — no longer enforces it; it only warns: [6](#0-5) 

Combined, this means: (1) the price the filler trusts for a venue-priced leg is a manipulable single-block pool read, (2) the only sanity check against manipulation is optional and reference-based rather than execution-cost-based, and (3) the hard cap that used to bound the blast radius of a bad price is now advisory-only. An attacker (an unprivileged order placer / "intent" user reachable actor) can therefore: manipulate the thin Uniswap V4 pool backing a configured exotic-token position (e.g. via a large swap or flash loan in the same block), submit/trigger an order whose destination leg is priced off that pool, and have the solver's `FXFiller` compute and release an output amount far beyond what the manipulated deviation guard should have blocked — with the disabled clamp providing no backstop.

### Impact Explanation
This directly parallels the Sturdy incident's bug class (price-oracle/pool-price manipulation used to extract more value than the true market rate). Here the "victim" is the solver's committed Uniswap V4 LP inventory (`UniswapV4FundingPlanner.planWithdrawalForToken` actually withdraws real liquidity and delivers real tokens to fill the order), so a successful exploit is concrete theft of solver-backing funds via a single manipulated fill, not merely a stale internal statistic. This is Medium-to-High severity depending on configured `maxOverfillBps`/pool depth, consistent with the report's Medium classification.

### Likelihood Explanation
Requires: (a) a filler operator using pool-based (curveless) venue pricing for at least one pair — an explicitly documented, supported configuration; (b) no `referencePrice`/`maxDeviationBps` guard configured, or a guard band wide enough / stale enough not to catch the manipulation; and (c) a Uniswap V4 pool thin enough to move meaningfully within one block. All three conditions are plausible in production given the guard is optional by design and the clamp is documented as intentionally disabled.

### Recommendation
- Re-enable the overfill clamp (or make it a hard reject) for venue-priced legs specifically, since these lack the intrinsic bid/ask spread protection that curve-priced legs have.
- Require `referencePrice`/`maxDeviationBps` to be mandatory (not optional) whenever `[vault.uniswapV4]` pool-based pricing is used for a pair.
- Replace or supplement the raw `sqrtPriceX96` spot read with a TWAP-based quote, or incorporate pool fee tier / size-impact into `computeDirectPoolPriceUsd` rather than treating the mid price as flat across the whole fill size.

### Proof of Concept
1. Filler operator configures a curveless USDC/EXOTIC pair funded via `[vault.uniswapV4]` with no `referencePrice`/`maxDeviationBps` guard (a supported, documented configuration).
2. Attacker manipulates the configured Uniswap V4 pool's spot price within a block (e.g., large swap or flash loan) to inflate `EXOTIC` price in USD terms.
3. Attacker (or a colluding solver-adjacent order) submits/triggers an intent order sized so `resolveLegRates` reads the manipulated venue price via `getVenueUsdPrice` → `UniswapV4FundingPlanner.getExoticTokenPrice`.
4. `checkPriceGuard` passes (no guard configured), and the filler's computed `policyMaxOutput` exceeds `overfillCeiling`; per [7](#0-6) , this only logs a warning and the unclamped, inflated output amount is still filled and withdrawn from the LP position.
5. Attacker receives output tokens valued well above the true price, extracted from the solver's Uniswap V4-backed liquidity.

	/**
	 * Validates a live venue quote against the static reference price for the chain.
	 * Returns true (pass) when no guard is configured, or no reference exists for the
	 * chain. Returns false when the quote (token1 per USD) deviates from the reference
	 * by more than `maxDeviationBps`, in which case the order must not be filled.
	 */
	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {
			this.logger.warn(
				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
	}

	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}

`computeDirectPoolPriceUsd` returns the **raw pool mid** derived from `sqrtPriceX96`. The pool's
fee tier is read and stored on the hydrated position (`pos.fee`) but never applied to the price,
and there is no size or impact term — `computeLegPolicyOutput` extends the mid linearly across the
whole priced quantity. `checkPriceGuard` is the only defense on this path, and it checks deviation
from a static reference, not execution cost. A venue-priced pair that has to swap through its own
pool to source inventory pays a fee tier it never quoted against.
