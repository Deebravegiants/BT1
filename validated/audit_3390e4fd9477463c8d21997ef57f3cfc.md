### Title
Spot Aquarius pool reserves are trusted without manipulation resistance, letting an attacker inflate LP collateral prices within the sanity band via direct donation — ([File: contracts/price-aggregator/src/providers/aquarius.rs](contracts/price-aggregator/src/providers/aquarius.rs))

### Summary
The embedza advisory class is "trusting a resource fetched over an unauthenticated channel": the counterparty's answer is accepted verbatim and used to drive privileged behavior. The on-chain analog in XOXNO Lending is the Aquarius LP price source in the price aggregator. `providers::aquarius::read` calls `pool.get_reserves()` and `pool.get_total_shares()` on an arbitrary-liquidity AMM pool and feeds the raw spot values directly into `fair_lp_price_wad` / `fair_stable_lp_price_wad` to value LP-share collateral for the controller's health-factor and borrow checks [1](#0-0) . Both quantities are permissionlessly manipulable: a direct token transfer to the Aquarius pool contract raises `get_reserves()` without minting shares, so the computed fair value per LP share rises proportionally to the donated value. The only brakes are the configured sanity band and `min_pool_value_wad`, which bound but do not prevent inflation.

### Finding Description
`fair_lp_price_wad` computes `2 * sqrt(value_a * value_b) / total_shares` for constant-product pools [2](#0-1)  and `D * min(price_a, price_b) / total_shares` for stable pools [3](#0-2) . Neither the numerator nor the denominator is manipulation-resistant:

- For a constant-product pair, donating `x` of token A multiplies the numerator by `sqrt(1 + x/reserve_a)`. To reach a `+33%` fair price (the top of a typical `max_sanity_price_wad` band such as the 0.9–1.2 WAD band seen in mainnet ops config `configs/ops/mainnet/6463...json`) the attacker donates ≈78% of leg A's value — recoverable only partially by a counter-trade, but the donation itself is the cost of attack.
- For a stable pair, donating both legs raises the invariant `D` roughly proportionally; `fair_stable_lp_price_wad` scales linearly in `D`.
- `min_pool_value_wad` only rejects *small* pools; it does not cap upward manipulation — donation increases measured pool value, so the floor check never fires against the attack.

The read path re-validates pool *binding* (`bound_tokens`, `pool_kind_matches`, `decimals_match`) but nothing about reserve authenticity or manipulation resistance [4](#0-3) . Unlike Reflector legs, which can be configured as `Twap(n)`, the Aquarius source has no smoothing — it is always a spot read.

Attack path (single unprivileged address, all listed in-scope actions):
1. Hold or acquire the listed LP share token (e.g. via `supply`/`approve` flows, or own Aquarius LP mint).
2. Transfer tokens directly to the Aquarius pool address (a plain SAC `transfer` — the equivalent of "direct token transfers to the pool"), inflating `get_reserves`.
3. Call controller `supply` with the LP token as collateral, then `borrow` (or `multiply`), letting `Context`-cached strict prices value the collateral at the inflated fair price [5](#0-4) .
4. Withdraw the borrowed assets. The position is undercollateralized at the true LP value; liquidation cannot recover the borrowed amount, so `clean_bad_debt`/`seize_positions` writes the shortfall down against suppliers.

### Impact Explanation
Theft of user funds / protocol insolvency: the attacker borrows more than the real value of the posted LP collateral, exits with the borrowed tokens, and leaves bad debt that is socialized across suppliers via the supply-index write-down path. The bound is the sanity band width (e.g. ~+33% above `min_sanity_price_wad` in the observed config) applied to collateral value times the market's LTV — for a high-LTV LP listing this suffices to make borrows exceed recoverable collateral.

### Likelihood Explanation
Medium. Requirements: an LP token must be listed as a borrowable/collateral asset with an `AquariusLp`/`AquariusStableLp` price source (mainnet configs show exactly this shape); the pool's TVL sets the donation capital needed; the manipulation must clear the sanity band check, which caps but does not eliminate the overvaluation. No privileged access, timing race, or oracle compromise is needed — only the attacker's own funds and standard entrypoints. The donated capital is partially lost to other LPs/arbitrageurs, which raises the attack cost and is the main mitigant.

### Recommendation
- Read Aquarius reserves in a manipulation-resistant way: prefer TWAP/historic reserve snapshots where the venue exposes them, or compare the spot read against an independent derivation (e.g. recompute expected reserves from a separate source) and revert on divergence beyond a tolerance.
- Widen protection symmetrically: configure the sanity band tightly around the observed fair price so that the donation needed to move the price to the band edge exceeds the extractable borrow value.
- Apply the existing `OracleTolerance`/`RequireDisjoint` machinery to LP sources by requiring a second independent leg whose agreement bounds spot deviation.
- Document a maximum expected reserve ratio or per-epoch reserve drift bound for LP sources so a step-change donation reverts with `InsufficientAquariusLiquidity`-style failure rather than silently repricing.

### Proof of Concept
Conceptual trace against `contracts/price-aggregator/src/providers/aquarius.rs`:

```text
Pool: constant_product, reserves (R_a, R_b), total_shares S, share listed as
collateral with min_sanity = P_min, max_sanity = P_max > P_min.

fair = 2 * sqrt(R_a*P_a * R_b*P_b) / S   (WAD scale)

Attacker: token_a.transfer(attacker -> aquarius_pool, x)
  => get_reserves returns (R_a + x, R_b), total_shares unchanged
  => fair' = fair * sqrt(1 + x/R_a)

Choose x = R_a * (k^2 - 1) with k = P_max / fair0 (≈1.33 for a 0.9–1.2 band)
  => fair' ≈ P_max   (passes the sanity band)

Then: controller.supply(LP), controller.borrow(max_by_inflated_value)
  => withdraw proceeds; LP collateral real value < debt
  => position liquidates insufficiently; clean_bad_debt writes the shortfall
     into the supply index — loss borne by suppliers.
```

All calls used: SAC `transfer` (direct token transfer), controller `supply`, `borrow`, `withdraw` — every step reachable by a single unprivileged address, and the inflated price flows through the normal Context-cached strict-price path used by health factor and `min_borrow_collateral_usd`.
