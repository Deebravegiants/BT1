### Title
Stale `TombStone.original_owner` survives ordinary `transfer_raw` transfers, allowing a prior owner to reclaim an object after it has legitimately changed hands - (File: `aptos-move/framework/aptos-framework/sources/object.move`)

### Summary
`object::burn` marks an object as soft-burnt by attaching a `TombStone{original_owner}` resource without changing `ObjectCore.owner`. Only the `TransferRef`/`LinearTransferRef` transfer path (`transfer_with_ref`) clears a stale `TombStone` on transfer. The ordinary transfer path used by `object::transfer`, `object::transfer_call`, and `object::transfer_to_object` (`transfer_raw` → `transfer_raw_inner`) never checks for or clears `TombStone`. This means the `original_owner` recorded at burn time can become stale as the object legitimately changes hands, and `unburn` will later restore ownership to that stale address instead of the object's actual last owner — an object-ownership analog of the Taiko bug where "history of the final state" is not tracked before a bond/ownership action is settled.

### Finding Description [1](#0-0) 

`burn` does not move the object to `BURN_ADDRESS`; it just tags it with `TombStone{original_owner}` while leaving `ObjectCore.owner` untouched (a "soft burn" hidden from indexers):
```
public entry fun burn<T: key>(owner: &signer, object: Object<T>) {
    let original_owner = signer::address_of(owner);
    assert!(is_owner(object, original_owner), error::permission_denied(ENOT_OBJECT_OWNER));
    let object_addr = object.inner;
    assert!(!exists<TombStone>(object_addr), EOBJECT_ALREADY_BURNT);
    move_to(&create_signer(object_addr), TombStone { original_owner });
}
``` [2](#0-1) 

The `TransferRef`-based transfer path explicitly invalidates a stale `TombStone` before applying a new owner, precisely to prevent a stale record from being reused later:
```
public fun transfer_with_ref(self: LinearTransferRef, to: address) {
    ...
    // Undo soft burn if present as we don't want the original owner to be able to reclaim by calling unburn later.
    if (exists<TombStone>(self.self)) {
        let TombStone { original_owner: _ } = move_from<TombStone>(self.self);
    };
    ...
    object.owner = to;
}
``` [3](#0-2) 

But the far more commonly used ungated transfer path — `object::transfer`, `object::transfer_call`, `object::transfer_to_object` — goes through `transfer_raw`/`transfer_raw_inner`, which never touches `TombStone` at all:
```
public fun transfer_raw(owner: &signer, object: address, to: address) {
    let owner_address = signer::address_of(owner);
    verify_ungated_and_descendant(owner_address, object);
    transfer_raw_inner(object, to);
}

inline fun transfer_raw_inner(object: address, to: address) {
    let object_core = borrow_global_mut<ObjectCore>(object);
    if (object_core.owner != to) {
        event::emit(Transfer { object, from: object_core.owner, to });
        object_core.owner = to;
    };
}
``` [4](#0-3) 

`unburn` trusts the stored `TombStone.original_owner` whenever the object's current owner is `BURN_ADDRESS`, regardless of how many legitimate owners the object passed through since the tag was created:
```
public entry fun unburn<T: key>(original_owner: &signer, object: Object<T>) {
    let object_addr = object.inner;
    assert!(exists<TombStone>(object_addr), error::invalid_argument(EOBJECT_NOT_BURNT));

    let object_core = borrow_global<ObjectCore>(object_addr);
    if (object_core.owner == signer::address_of(original_owner)) {
        let TombStone { original_owner: _ } = move_from<TombStone>(object_addr);
    } else if (object_core.owner == BURN_ADDRESS) {
        let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
        assert!(original_owner_addr == signer::address_of(original_owner), error::permission_denied(ENOT_OBJECT_OWNER));
        transfer_raw_inner(object_addr, original_owner_addr);
    } else {
        abort error::permission_denied(ENOT_OBJECT_OWNER);
    };
}
```

Concretely:
1. Owner A calls `object::burn(A, O)`. `TombStone{original_owner: A}` is attached; `ObjectCore.owner` stays A. Objects default to `allow_ungated_transfer = true`, so this doesn't lock the object.
2. A sells/transfers O to B via ordinary `object::transfer(A, O, B)` (ungated `transfer_raw` path). `ObjectCore.owner` becomes B. `TombStone{original_owner: A}` is **not cleared** because `transfer_raw_inner` never inspects `TombStone`.
3. B, unaware the object still carries a stale soft-burn tag (soft-burnt objects are only hidden from indexers, not flagged to holders in any on-chain-enforced way), later sends the object to the well-known `BURN_ADDRESS` via an ordinary transfer (`object::transfer(B, O, BURN_ADDRESS)`), intending a genuine burn. `ObjectCore.owner` becomes `BURN_ADDRESS`.
4. A calls `object::unburn(A, O)`. Since `object_core.owner == BURN_ADDRESS` and the stale `TombStone.original_owner == A` still matches, the assertion passes and `transfer_raw_inner` reassigns `ObjectCore.owner` back to A — even though A had no ownership claim since step 2, and the object had a fully separate legitimate owner (B) in between.

The custody invariant broken: "Object creation, transfer, burn ... ownership refs must preserve the intended controller." Here, the actual chain-of-custody (A → B → burn) is not preserved because a control field (`TombStone.original_owner`) set at one point in history is never invalidated on the non-`TransferRef` transfer path, letting a stale, unprivileged former owner reassign a live object's ownership away from its rightful last controller.

### Impact Explanation
This is an unauthorized owner reassignment of an on-chain Object — the exact custody-grade impact called out in the gate ("Unauthorized takeover of ... owner reassignment ... tied to live assets"). Any object that (a) was ever soft-burnt by a former owner via `object::burn`, (b) subsequently changed hands through ordinary `transfer`/`transfer_call` (the common, non-soulbound path used by most objects, NFTs, and token-object collections that don't explicitly disable ungated transfer), and (c) is ever moved to `BURN_ADDRESS` by any later owner via an ordinary transfer, can be silently reclaimed by the original, no-longer-privileged owner. Any resources/assets colocated under that object address (e.g., token metadata, associated stores) follow the object's owner field and are effectively stolen back. This directly corrupts custody accounting by moving control to the wrong holder.

### Likelihood Explanation
The precondition sequence (burn → resell without using a TransferRef-gated marketplace → destination reaches `BURN_ADDRESS` via ordinary transfer) is plausible: `object::burn` is a public entry function usable by anyone before selling an object, ordinary `object::transfer` is the default/most common transfer mechanism for objects without soulbound configuration, and `BURN_ADDRESS` is a fixed, publicly known constant that any holder could send an object to directly (bypassing the intended `object::burn` entry point) believing it is a genuine, irreversible burn. No special privilege is required by the attacker (A) beyond having once been a legitimate owner and calling `burn` before selling.

### Recommendation
Clear (or invalidate) any existing `TombStone` on every ownership-changing path, not only `transfer_with_ref`. Specifically, `transfer_raw_inner` should also `move_from<TombStone>` (if present) whenever `object_core.owner` changes, mirroring the logic already present in `transfer_with_ref`. Alternatively, bind the `TombStone.original_owner` check in `unburn` to a per-transfer generation/epoch counter on `ObjectCore` so that any ownership change since the tombstone was created invalidates the stale claim.

### Proof of Concept
Move-test-style pseudocode using existing framework functions (no test harness details fabricated beyond what's in `object.move`):
```
// Setup: create_object owned by A with allow_ungated_transfer = true (default)
let ctor = object::create_object(signer::address_of(&A));
let obj: Object<ObjectCore> = object::object_from_constructor_ref(&ctor);

// Step 1: A soft-burns
object::burn(&A, obj);                       // TombStone{original_owner: A} attached, owner still A

// Step 2: A sells to B via ordinary transfer
object::transfer(&A, obj, signer::address_of(&B));   // owner = B, TombStone untouched

// Step 3: B genuinely destroys the object
object::transfer_call(&B, object::object_address(&obj), BURN_ADDRESS); // owner = BURN_ADDRESS

// Step 4: A reclaims an object they no longer legitimately own
object::unburn(&A, obj);                     // succeeds: owner reset to A, bypassing B's ownership entirely
assert!(object::owner(obj) == signer::address_of(&A), 0); // passes -- custody stolen from B's burn / prior chain
```
This demonstrates that `ObjectCore.owner` is corrupted to a stale, unprivileged address purely due to `transfer_raw_inner` never invalidating `TombStone`.

    /// Allow origin owners to reclaim any objects they previous burnt.
    public entry fun unburn<T: key>(
        original_owner: &signer,
        object: Object<T>,
    ) {
        let object_addr = object.inner;
        assert!(exists<TombStone>(object_addr), error::invalid_argument(EOBJECT_NOT_BURNT));

        // The new owner of the object can always unburn it, but if it's the burn address, we go to the old functionality
        let object_core = borrow_global<ObjectCore>(object_addr);
        if (object_core.owner == signer::address_of(original_owner)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object_addr);
        } else if (object_core.owner == BURN_ADDRESS) {
            // The old functionality
            let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);

                original_owner_addr == signer::address_of(original_owner),
                error::permission_denied(ENOT_OBJECT_OWNER)
            );
            transfer_raw_inner(object_addr, original_owner_addr);
        } else {
            abort error::permission_denied(ENOT_OBJECT_OWNER);
        };
    }
