Audit Report

## Title
Missing Authorization on LOOP Plugin Discovery/Metrics/pprof Debug Routes - (File: `core/web/router.go`)

## Summary
The `loopRoutes` group in `core/web/router.go`, which exposes `/discovery`, `/plugins/:name/metrics`, and `/plugins/:name/debug/pprof/*` endpoints, is registered on the public API `gin.Engine` with no authentication middleware, unlike every other sensitive route (`/debug/vars`, `/v2/*`) in the same router. This allows any unauthenticated network client to retrieve service-discovery metadata and full pprof runtime dumps (heap, goroutine, trace, symbol) proxied from LOOP plugin processes.

## Finding Description
In `NewRouter`, `loopRoutes(app, api)` is called on the `api` route group, which only has rate-limiting and session-cookie middleware applied — no credential check [8](#0-7) . The `loopRoutes` function registers four handlers with zero auth wrapper: `discoveryHandler`, `pluginMetricHandler`, `pluginPPROFHandler`, and `pluginPPROFPOSTSymbolHandler` [4](#0-3) . This contrasts directly with `debugRoutes`, which wraps `/debug/vars` in `auth.Authenticate(..., auth.AuthenticateBySession)` [2](#0-1) , and with the node-level pprof routes registered via `metricRoutes(authv2)`, called only inside the token/session-authenticated `authv2` group [9](#0-8) . The handlers themselves proxy real internal data: `discoveryHandler` returns plugin names and Prometheus scrape targets [10](#0-9) , and `pluginPPROFHandler` forwards to `http://<loopHostName>:<PrometheusPort>/debug/pprof/<profile>` on the plugin's internal server, including heap, goroutine, trace, and profile — with the code comment confirming this was intended to be "internal btw the node and plugin," not public [11](#0-10) . No auth middleware or role check exists anywhere in this call chain.

## Impact Explanation
This is an information-disclosure vulnerability (CWE-862, Missing Authorization). Unauthenticated remote clients can pull heap dumps and full goroutine stack traces from LOOP plugin processes via `/plugins/<name>/debug/pprof/heap` and `/plugins/<name>/debug/pprof/goroutine?debug=2`, potentially exposing sensitive in-memory state, and can enumerate internal plugin/service topology via `/discovery` and `/plugins/<name>/metrics`. This falls within the "node API authentication bypass" impact category since a normally-authenticated-only surface (mirrored by the node's own `/v2/debug/pprof/*`) is reachable without any credentials.

## Likelihood Explanation
High. These routes are unconditionally registered whenever a Chainlink node with LOOP plugins starts, require no special configuration, and are reachable via a standard HTTP GET/POST to the node's normal API port — identical reachability to any other unauthenticated request, with no operator or privileged access needed to trigger it.

## Recommendation
Wrap the `loopRoutes` group with the same authentication middleware used for `metricRoutes`/`authv2`, e.g. `r.Group("/", auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession))`, or move these plugin-proxy endpoints to a separate internal-only listener not exposed on the public API port, consistent with the existing code comments describing them as internal-only.

## Proof of Concept
1. Start a Chainlink node with a LOOP plugin registered.
2. Without any session cookie or API token, send:
   - `GET /discovery` — returns JSON with plugin names/service-discovery targets.
   - `GET /plugins/<name>/debug/pprof/heap` — returns a full heap dump of the plugin process.
   - `GET /plugins/<name>/debug/pprof/goroutine?debug=2` — returns full goroutine stack traces.
3. Confirm all requests return `200 OK` with no authentication challenge, while an equivalent request to `/v2/debug/pprof/heap` or `/debug/vars` returns `401 Unauthorized` without valid credentials — demonstrating the router-level auth gap is specific to `loopRoutes`.

// discoveryHandler implements service discovery of prom endpoints for LOOPs in the registry
func (l *LoopRegistryServer) discoveryHandler(w http.ResponseWriter, req *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	groups := make([]*targetgroup.Group, 0, 1+len(l.registry.List()))

	// add node metrics to service discovery
	groups = append(groups, pluginGroup(l.discoveryHostName, l.exposedPromPort, "/metrics"))

	// add all the plugins
	for _, registeredPlugin := range l.registry.List() {
		group := pluginGroup(l.discoveryHostName, l.exposedPromPort, pluginMetricPath(registeredPlugin.Name))
		group.Labels[LabelMetaPluginName] = model.LabelValue(registeredPlugin.Name)
		groups = append(groups, group)
	}

	b, err := l.jsonMarshalFn(groups)
	if err != nil {
		w.WriteHeader(http.StatusInternalServerError)
		_, err = w.Write([]byte(err.Error()))
		if err != nil {
			l.logger.Error(err)
		}
		return
	}
	_, err = w.Write(b)
	if err != nil {
		w.WriteHeader(http.StatusInternalServerError)
		l.logger.Error(err)
	}
}

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
