### Title
Missing L2 sequencer uptime check in `SimplexPaymaster`'s Chainlink price oracle — ([File: evm/src/utils/SimplexPaymaster.sol])

### Summary
`SimplexPaymaster` reads Chainlink `AggregatorV3Interface.latestRoundData()` prices for both the native/USD oracle and every registered token/USD oracle, guarding only against a non-positive answer and an `updatedAt` older than `maxOracleAge`. It never checks a Chainlink L2 sequencer-uptime feed. The paymaster is deployed on op-stack/L2 rollups (Base, Optimism, Arbitrum, Soneium, per the chainlink price-feed address table) and is the sponsorship mechanism used by intent-gateway solver bids (`PERMIT2_SPONSORSHIP_BYTES` mode referenced in the phantom-order docs), so an unprivileged solver/user submitting a `UserOperation` through this paymaster can have their gas priced off a stale oracle answer during/after an L2 sequencer outage.

### Finding Description
`_getOraclePrice` is the sole gate on oracle freshness/validity: [1](#0-0) 

It reverts only when `answer <= 0` or `block.timestamp - updatedAt > maxOracleAge`. There is no call to a Chainlink `SequencerUptimeFeed` (`latestRoundData()` + `startedAt` grace-period check per Chainlink's documented L2 pattern) anywhere in the contract, and `PaymasterParams`/`TokenConfig` carry no sequencer-feed address: [2](#0-1) 

This function backs both the per-`UserOp` gas price (`_tokenPrice`, used in `_validatePaymasterUserOp`) and the treasury's fee-recycling swap (`swapAndDeposit`): [3](#0-2) [4](#0-3) 

On an L2 like Base/Optimism/Arbitrum, when the sequencer is down and later resumes, Chainlink's guidance is explicit that `updatedAt`-based staleness alone is insufficient: the feed can report an `updatedAt` that looks fresh relative to the L2's `block.timestamp` catch-up behavior while the underlying price is stale relative to the true off-chain market, or conversely the feed can be legitimately stale during the outage while transactions targeting the paymaster still land once the sequencer restarts (before feeds catch up). Because this contract is the exact code path an intent-gateway solver's sponsored bid exercises (per the Simplex/Phantom PERMIT2 mode), a solver controls the timing of their own transaction relative to the sequencer's recovery and can submit `UserOperation`s that price gas off a stale/mispriced Chainlink answer that nonetheless passes `_getOraclePrice`'s `maxOracleAge` check.

### Impact Explanation
`_tokenPrice`/`_getOraclePrice` directly set how much of a registered stablecoin (`usdc6`, etc.) a `UserOp` sender or sponsored solver pays for gas, and `swapAndDeposit` sizes `amountOutMin` for the treasury's fee-recycling swap off the same oracle reads. A stale/mispriced answer during a sequencer outage/recovery window lets a caller underpay for sponsored gas (extracting value from the paymaster's treasury) — a concrete theft-of-funds vector against the paymaster that backs solver-sponsored UserOps in the intent-gateway flow. This is High severity in the original report's own reasoning: price volatility correlates with sequencer downtime, and the paymaster's treasury funds are directly at risk.

### Likelihood Explanation
The paymaster is deployed on multiple L2 rollups with sequencers (Base, Optimism, Arbitrum, per the chainlink-price-feed address list), and is reachable by any unprivileged UserOp sender/intent solver — no privileged role is required to trigger `_validatePaymasterUserOp` → `_tokenPrice` → `_getOraclePrice`. The staleness window need only coincide with an L2 sequencer outage or its recovery period, which the report notes correlates with high-volatility events — exactly when this contract's mispricing is most damaging.

### Recommendation
Add a Chainlink `SequencerUptimeFeed` check (per Chainlink's documented L2 pattern) to `_getOraclePrice`/`_tokenPrice`: read the feed's `latestRoundData()`, revert if `answer == 1` (sequencer down), and enforce a grace period after `startedAt` (sequencer just came back up) before trusting any price read, in addition to the existing `maxOracleAge` staleness check. Store the sequencer-uptime-feed address per chain deployment (e.g., in `Params`) and gate `_validatePaymasterUserOp` and `swapAndDeposit` on it.

### Proof of Concept
1. Deploy `SimplexPaymaster` on an L2 rollup (e.g., Base) with a registered stablecoin and `nativeOracle`.
2. Simulate the L2 sequencer going offline for a period shorter than `maxOracleAge`, during which the true off-chain price of the native asset or stablecoin moves significantly (e.g. a market crash/spike).
3. Once the sequencer resumes (or during the outage if transactions can still be included), submit a `UserOperation` through `_validatePaymasterUserOp` (mode `0x00`/permit or Permit2) referencing the stale Chainlink round; `_getOraclePrice` accepts it because `block.timestamp - updatedAt <= maxOracleAge` still holds.
4. The solver/user pays for gas at the stale, mispriced rate, extracting value from the paymaster treasury — reproducible with the existing `MockOracle.setUpdatedAt` test helper in `evm/tests/foundry/SimplexPaymasterTest.t.sol` by setting an `updatedAt` within `maxOracleAge` but an `answer` that no longer reflects live market price (simulating the sequencer-outage price divergence that a true uptime-feed check would have caught).

    function swapAndDeposit(address token, uint256 amountIn) external {
        if (msg.sender != treasury) revert UnauthorizedCall();
        address router = IDispatcher(host()).uniswapV2Router();
        if (router == address(0)) revert InvalidRouter(router);
        TokenConfig memory cfg = tokenConfigs[token];
        if (address(cfg.tokenOracle) == address(0)) revert TokenNotRegistered(token);

        uint256 balance = IERC20(token).balanceOf(address(this));
        if (amountIn == 0 || amountIn > balance) amountIn = balance;

        uint256 nativeUsd = _getOraclePrice(nativeOracle, nativeOracleDecimals);
        uint256 tokenUsd = _getOraclePrice(cfg.tokenOracle, cfg.tokenOracleDecimals);
        uint256 expectedWei = (amountIn * tokenUsd * 1e18) / (nativeUsd * (10 ** cfg.tokenDecimals));
        uint256 amountOutMin = (expectedWei * (10_000 - swapSlippageBps)) / 10_000;

        uint256 nativeUsd = _getOraclePrice(nativeOracle, nativeOracleDecimals);
        uint256 tokenUsd = _getOraclePrice(cfg.tokenOracle, cfg.tokenOracleDecimals);

    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
