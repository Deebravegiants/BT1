### Title
Unbounded infinite loop in GRANDPA `AncestryChain::ancestry` from a cyclic attacker-supplied header chain in an unsigned consensus proof - ([File: modules/consensus/grandpa/primitives/src/justification.rs])

### Summary
The GRANDPA consensus client's `verify_consensus` entry point (`modules/ismp/clients/grandpa/src/consensus.rs`, `verify_consensus`) decodes an attacker/relayer-supplied `ConsensusMessage` and, before any signature/authority validation of the header set itself, builds an `AncestryChain` from the untrusted `votes_ancestries`/`unknown_headers` list and walks it with `AncestryChain::ancestry`. That function loops on parent-hash pointers taken directly from the untrusted header list without any bound on path length or cycle detection, mirroring the WBXML infinite-loop class in CVE-2017-11410: the relationship between the supplied "index" (header hash) and its claimed "length"/successor (`parent_hash`) is never validated for well-foundedness before being used to drive a loop.

### Finding Description
`AncestryChain::ancestry` in [1](#0-0)  walks from a `block` hash back to a `base` hash purely by following `parent_hash()` pointers stored in a `BTreeMap<Hash, Header>` that was built directly from attacker-controlled data:

```
fn ancestry(&self, base: H::Hash, block: H::Hash) -> Result<Vec<H::Hash>, finality_grandpa::Error> {
    let mut route = vec![block];
    let mut current_hash = block;
    while current_hash != base {
        match self.ancestry.get(&current_hash) {
            Some(current_header) => {
                current_hash = *current_header.parent_hash();
                route.push(current_hash);
            },
            _ => return Err(finality_grandpa::Error::NotDescendent),
        };
    }
    Ok(route)
}
```

The map (`AncestryChain::new`, [2](#0-1) ) is populated from `votes_ancestries` (part of the decoded, unauthenticated `GrandpaJustification`) or from `finality_proof.unknown_headers` (part of the decoded `ConsensusMessage`/`FinalityProof`). Neither of these lists is checked for acyclicity before the loop runs. If an attacker crafts two (or more) headers `H1`, `H2` whose self-hashes are `h1`/`h2` and whose `parent_hash` fields point at each other (`H1.parent_hash = h2`, `H2.parent_hash = h1`), inserting both into the map creates a cycle. Calling `ancestry(base, h1)` with a `base` that is never reached (e.g., not present in the constructed set, or a third disconnected hash) causes the `while` loop to alternate `h1 → h2 → h1 → h2 …` forever, because each hash is always found in the map (so the `None` branch that would terminate the loop is never taken) and `current_hash` never equals `base`.

This function is reached from `verify_with_voter_set` ( [3](#0-2) ) which is invoked from `GrandpaJustification::verify`, itself called from `verify_grandpa_finality_proof` ( [4](#0-3) ), which is called by `GrandpaConsensusClient::verify_consensus` and `verify_fraud_proof` ( [5](#0-4) , [6](#0-5) ) — both of which are dispatchable via pallet-ismp's unsigned/unauthenticated consensus-update and fraud-proof extrinsics, reachable by any relayer without special privileges. The `ancestry()` call at line 88 (`headers.ancestry(from, target.hash())`) in `verify_grandpa_finality_proof` uses the same unbounded map built from `finality_proof.unknown_headers`.

### Impact Explanation
An unprivileged relayer can submit a crafted GRANDPA consensus update (or fraud proof) containing a small cyclic set of forged headers. This drives `AncestryChain::ancestry` into an unbounded loop, consuming CPU/weight indefinitely within a pallet-ismp extrinsic. Depending on how this executes on-chain (weight metering, gas limits), this can stall block execution or make the GRANDPA-based route (and any state machine finalized through it) unable to process further consensus updates — a "route unable to deliver messages" condition, which is explicitly in scope. This is a High-severity DoS on a core, unauthenticated verification path.

### Likelihood Explanation
High. The attack requires only two forged header structures with a mutually-referencing `parent_hash` — trivially constructible off-chain — and no valid signatures, no real chain state, and no special permissions are needed to submit the consensus message/fraud proof, since this loop executes *before* the state/authority checks in the justification/finality-proof verification can reject it, or independent of those checks (the `unknown_headers`-driven ancestry call in `verify_grandpa_finality_proof` happens prior to justification verification at all).

### Recommendation
Bound the ancestry walk: track visited hashes in a `BTreeSet` and return an error (e.g., `Error::NotDescendent` or a new `CyclicAncestry` error) if a hash is revisited, or cap the loop iteration count by the size of the input header vector (`self.ancestry.len() + 1`). Apply this fix uniformly to every `AncestryChain::ancestry` call site (`justification.rs` verify_with_voter_set, `grandpa/verifier/src/lib.rs` verify_grandpa_finality_proof, and the fraud-proof handler).

### Proof of Concept
1. Construct two `SubstrateHeader`s `H1` and `H2` (only `parent_hash`, `number`, and any other required fields need to be set/consistent) such that `H1.hash() = h1`, `H2.hash() = h2`, `H1.parent_hash() == h2`, and `H2.parent_hash() == h1`.
2. Build a `GrandpaJustification` (or `FinalityProof`) whose `votes_ancestries` (or `unknown_headers`) is `vec![H1, H2]`, and whose commit/precommit target hash is `h1` (or any hash reachable into the cycle), with a `base_hash` chosen to be a hash not present in `{h1, h2}` (e.g., the genuine trusted `latest_hash`).
3. Submit this as the `proof` argument to `GrandpaConsensusClient::verify_consensus` (or as `proof_1`/`proof_2` to `verify_fraud_proof`) via the corresponding pallet-ismp extrinsic.
4. `AncestryChain::ancestry(base_hash, h1)` will loop `h1 → h2 → h1 → h2 → …` indefinitely, since both hashes are always present in the map and neither equals `base_hash`, hanging the call and consuming unbounded execution weight.

		proof_1: Vec<u8>,
		proof_2: Vec<u8>,
	) -> Result<(), Error> {
		// decode the consensus state
		let consensus_state: ConsensusState =
			codec::Decode::decode(&mut &trusted_consensus_state[..])
				.map_err(|e| GrandpaError::DecodeConsensusState(format!("{e:?}")))?;

		let first_proof: FinalityProof<SubstrateHeader> = codec::Decode::decode(&mut &proof_1[..])
			.map_err(|e| GrandpaError::DecodeFinalityProof(format!("{e:?}")))?;

		let second_proof: FinalityProof<SubstrateHeader> = codec::Decode::decode(&mut &proof_2[..])
			.map_err(|e| GrandpaError::DecodeFinalityProof(format!("{e:?}")))?;

		if first_proof.block == second_proof.block {
			return Err(GrandpaError::FraudProofsSameBlock.into());
		}

		let first_headers = AncestryChain::<SubstrateHeader>::new(&first_proof.unknown_headers);
		let first_target = first_proof
			.unknown_headers
			.iter()
			.max_by_key(|h| *h.number())
			.ok_or(GrandpaError::UnknownHeadersEmpty)?;

		let second_headers = AncestryChain::<SubstrateHeader>::new(&second_proof.unknown_headers);
		let second_target = second_proof
			.unknown_headers
			.iter()
			.max_by_key(|h| *h.number())
			.ok_or(GrandpaError::UnknownHeadersEmpty)?;

		if first_target.hash() != first_proof.block || second_target.hash() != second_proof.block {
			return Err(GrandpaError::FraudProofsDifferentChain.into());
		}

		let first_base = first_proof
			.unknown_headers
			.iter()
			.min_by_key(|h| *h.number())
			.ok_or(GrandpaError::UnknownHeadersEmpty)?;
		let first_chain = first_headers
			.ancestry(first_base.hash(), first_target.hash())
			.map_err(|_| GrandpaError::InvalidAncestry)?;

		let second_base = second_proof
			.unknown_headers
			.iter()
			.min_by_key(|h| *h.number())
			.ok_or(GrandpaError::UnknownHeadersEmpty)?;
		let second_chain = second_headers
			.ancestry(second_base.hash(), second_target.hash())
