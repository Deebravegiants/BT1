Audit Report

## Title
Cross-user response confusion via attacker-controlled `MessageID` collision in gateway `savedCallbacks` map - (`core/services/gateway/handlers/capabilities/handler.go`)

## Summary
`HandleLegacyUserMessage` stores the caller's response callback in the shared `h.savedCallbacks` map keyed solely by the caller-supplied `msg.Body.MessageID`, with no per-sender scoping or existing-entry check [1](#0-0) . `handleWebAPITriggerMessage` later looks the callback up purely by that same `MessageID`, deletes it, and forwards the DON's response to whichever callback is currently registered [2](#0-1) . Since `MessageID` is fully attacker-chosen and there is no binding to sender identity, an unprivileged second caller reusing the same `MessageID` during the response window can overwrite the first caller's callback entry, causing the DON's response to the first caller to be delivered to the second caller instead.

## Finding Description
`HandleLegacyUserMessage` validates payload structure, timestamp freshness, and method, but performs no check for whether an active callback already exists for `msg.Body.MessageID`, and does not scope the map key by the request's `Sender` [3](#0-2) . The `MessageID` value comes directly from the incoming request body and is entirely controlled by the caller, as confirmed by the CLI tool `core/scripts/gateway/web_api_trigger/invoke_trigger.go`, which lets any user pass an arbitrary `-id` flag (defaulting to `"12345"`). When a DON node later responds with `MethodWebAPITrigger`, `handleWebAPITriggerMessage` looks up and deletes `h.savedCallbacks[msg.Body.MessageID]` and delivers the response to whatever callback is currently stored there — with no verification that the responding node's message correlates to the same sender who originally registered the callback [2](#0-1) .

Notably, the test suite for this handler contains an explicit unresolved TODO acknowledging this exact gap: `// TODO: Validate Senders and rate limit check, pending question in trigger about where senders and rate limits are validated`, and the handler itself has `// TODO: apply allowlist and rate-limiting here` [4](#0-3) [5](#0-4) . This confirms that sender validation/deduplication for this ID space is a known, currently-unaddressed gap rather than an intentional design decision, and existing checks (payload decode, timestamp staleness, method whitelist, signature-on-message validation in `msg.Validate()`) do nothing to prevent `MessageID` collisions across distinct signers, since `MessageID` is independent of the signer/sender field.

Any two distinct, unprivileged callers (each with their own self-generated key, as required only by `msg.Validate()`'s signature check, not by any allowlist) can trigger this: User A registers `savedCallbacks["X"]`; before the DON responds, User B submits their own request also using `MessageID = "X"`, overwriting the entry; when the DON's response for User A's original request arrives (still tagged `MessageID: "X"`), it is delivered to User B's callback instead of User A's, and User A's connection receives no response (eventually timing out).

## Impact Explanation
This maps to the explicitly in-scope "cross-user response corruption" impact category. An attacker who can guess, predict, or intentionally reuse another user's chosen `MessageID` can receive workflow trigger responses intended for that other user, and/or deny that user their response. Because the legacy web API trigger endpoint requires only a self-generated signing key (not a privileged/allowlisted identity, per the still-outstanding sender-validation TODO), this is reachable by any unprivileged client capable of sending gateway requests.

## Likelihood Explanation
Exploitation requires the attacker to know/predict the victim's `MessageID` and time their own request to land within the response window (bounded by node round-trip latency and the 120-second `defaultCallbackMaxAgeSec` prune window) [6](#0-5) . This is a realistic, automatable race for a busy gateway/DON pair, especially given that IDs are often short and predictable (e.g., the CLI default `"12345"`), and no rate limiting or ID-collision rejection currently exists to increase attacker cost.

## Recommendation
Scope `savedCallbacks` keys by both the message `Sender` and `MessageID` (e.g., `sender + ":" + messageID`) instead of `MessageID` alone, and reject/duplicate-detect registration attempts when an active, non-expired callback already exists for the derived key rather than silently overwriting it. Additionally, verify in `handleWebAPITriggerMessage` that the responding node's message correlates to the original sender before dispatching the response.

## Proof of Concept
1. User A (key pair A) sends a legacy `web_api_trigger` request to the gateway with `MessageID = "X"`; `HandleLegacyUserMessage` stores `savedCallbacks["X"] = callbackA` and forwards the request to all DON members via `don.SendToNode` [7](#0-6) .
2. Before any DON node responds, User B (key pair B) sends their own legacy request also using `MessageID = "X"`; this overwrites `savedCallbacks["X"] = callbackB`.
3. A DON node responds to User A's original request (still tagged `MessageID: "X"`); `handleWebAPITriggerMessage` looks up `savedCallbacks["X"]`, finds `callbackB`, deletes the entry, and delivers User A's response payload to User B via `callbackB.SendResponse` [2](#0-1) .
4. User A's HTTP connection times out with no response, while User B receives data associated with User A's triggered workflow execution — verifiable with a Go unit test in `handler_test.go` that issues two `HandleLegacyUserMessage` calls with the same `MessageID` from different signers and asserts which callback receives the eventual `HandleNodeMessage` response.

```go
func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageID]
	delete(h.savedCallbacks, msg.Body.MessageID)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JSONRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
}
```

```go
func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JSONRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) { //nolint:gosec // G115: comparing unix timestamps, both fit within uint
		h.lggr.Errorw("stale message")
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),
			ErrorCode: api.HandlerError,
		})
	}
	// TODO: apply allowlist and rate-limiting here
	if msg.Body.Method != MethodWebAPITrigger {
		h.lggr.Errorw("unsupported method", "method", body.Method)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.UnsupportedMethodError),
				"invalid method "+msg.Body.Method,
				nil,
			),
			ErrorCode: api.UnsupportedMethodError,
		})
	}
	req, err := common.ValidatedRequestFromMessage(msg)
	if err != nil {
		h.lggr.Errorw(ErrTransformingMessageToRequest)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrTransformingMessageToRequest,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	h.mu.Lock()
	h.savedCallbacks[msg.Body.MessageID] = &savedCallback{id: msg.Body.MessageID, createdAt: time.Now(), Callback: callback}
	don := h.don
	h.mu.Unlock()

	// Send original request to all nodes
	for _, member := range h.donConfig.Members {
		err = errors.Join(err, don.SendToNode(ctx, member.Address, req))
	}
```
