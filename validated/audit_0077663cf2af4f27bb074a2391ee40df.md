### Title
Graduation LP can be seeded away from the curve-close price via an oversized pre-seed of the HyperSwap V2 pair, whose rebalance budget is capped by the curve's own raise, not by the attacker's pre-seed size - (File: packages/contracts/src/Bonding.sol)

### Summary
`finalizeGraduation` permissionlessly deposits the curve-raised LT and reserved tokens into a HyperSwap V2 `TOKEN/LT` pair. If that pair already holds LP (`totalSupply != 0`), `_seedRebalancing` tries to correct the pool ratio to the curve-close price with a single direct-to-pair swap before depositing via the router. The swap's size is capped at 99% of *Bonding's own* curve-raised inventory (`_swapBudget`), not scaled to the size of the pre-existing reserves. An attacker who pre-creates the pair and self-funds a `mint` with reserves that dwarf the curve's raise can make the required corrective swap exceed this budget, so the rebalance only partially corrects the ratio. `_routerDepositAndDispose` then deposits the graduation's entire remaining inventory via `IUniswapV2Router02.addLiquidity(..., 1, 1, ...)`, which computes the "optimal" split off the *still-skewed* pool ratio rather than the intended curve-close price, permanently locking the graduation's capital into an LP priced at the attacker's chosen ratio.

### Finding Description
`_seedUniswapV2Direct` ( [1](#0-0) ) branches on `IUniswapV2Pair(pair).totalSupply()`. When non-zero (Regime 3 — a "mint pre-seed"), it calls `_seedRebalancing` ( [2](#0-1) ), which computes a corrective swap size via `_noFeeSwapInput` and executes it with `_pairRebalance` ( [3](#0-2) ).

The ideal no-fee swap size to correct the ratio scales with the *size of the existing reserves* (`s ≈ sqrt(reserveIn·reserveOut·targetN/targetD) − reserveIn`), because it is derived purely from the pre-seeded `reserveIn`/`reserveOut`: [4](#0-3) 

But the swap is hard-capped at `maxSwap = _swapBudget(inventory)`, where `inventory` is Bonding's own curve-raised LT (`ltFromPair`) or reserved tokens (`tokensForLP`) for *this graduation only* — a value bounded by `graduationThresholdUsd` (default $9K, capped at ~3× on full sellout), completely independent of how large the attacker's pre-seed is: [5](#0-4) 

If an attacker pre-creates the pair (`v2Factory.createPair`, fully permissionless and unguarded by `_ensureUniswapV2Pair`, [6](#0-5) ) and self-funds a `mint` with reserves an order of magnitude larger than the graduating token's raise, at a ratio far from the curve-close price, the required corrective swap `s` exceeds `maxSwap`, so `_pairRebalance` only partially nudges the ratio (or, in the extreme, `_noFeeSwapInput` still returns a value, it just under-corrects). The pool's ratio after the swap remains dominated by the attacker's pre-seed.

`_routerDepositAndDispose` then deposits whatever inventory remains with `amountMin = 1` on both sides: [7](#0-6) 

`IUniswapV2Router02.addLiquidity` computes the optimal split from the *current* (still attacker-skewed) reserve ratio via its internal `quote()`, not from `tokensForLP`/`ltFromPair`'s intended curve-close ratio. Because `min=1` provides no real protection, the call succeeds regardless of how far the ratio has drifted, and the graduation's entire curve-raised LT and 250M-token allocation get locked into the LP at the attacker-controlled price rather than the true curve-close price. Any inventory not consumable at that ratio is either burned (token side, via `Token.burn`) or later swept to the protocol owner (LT side, via `_sweepLTToOwner`), rather than benefiting the LP or the graduating token's traders — value is transferred out of the locked liquidity's fair backing into the mispriced pool the attacker controls, where they retain the earlier LP position and can arbitrage/exit the resulting price dislocation.

### Impact Explanation
This is a High-severity finding: it results in the graduation's entire curve-raised LT reserve and 250M-token LP allocation (`LPLock`-held liquidity that is supposed to open the market at the curve-close price for all future holders) being permanently seeded at an attacker-dictated ratio instead of the fair price. This directly matches the Validate criterion "an LP seeded away from the curve close price" and constitutes concrete value transfer from every curve trader/holder of the graduating token to the pre-seeding attacker, who profits by arbitraging the mispriced pool immediately post-graduation while the mis-locked LP (held in the non-rescuable `LPLock`) cannot be corrected.

### Likelihood Explanation
Medium-High: the attack requires the attacker to notice a token nearing `canGraduate` (visible on-chain via `Bonding.canGraduate`/`previewLtUntilGraduation`) and to pre-create + pre-fund the HyperSwap `TOKEN/LT` pair with capital exceeding the token's graduation raise (as low as ~$9K–$27K worth of LT, which is a modest capital outlay for a griefing/arbitrage attacker) before `finalizeGraduation` is called. Since `finalizeGraduation` is permissionless and pair creation is fully open, there is no privileged step blocking this; the natspec around `_seedRebalancing`/`_swapBudget` explicitly acknowledges "small" pre-seeds are bounded but does not bound pre-seeds larger than the graduation's own inventory.

### Recommendation
Bound the acceptable pre-existing reserve size relative to the graduation's own `tokensForLP`/`ltFromPair` (e.g., revert or fall back to a protected/queued path if `reserveToken`/`reserveLT` exceed a safety multiple of the curve-close amounts), or size `maxSwap` dynamically off the *actual* corrective requirement rather than a fixed 99%-of-own-inventory budget, so the deposit can never be authorized at a ratio that has not been fully corrected to the target `tokensForLP/ltFromPair` price. Alternatively, replace `amountMin = 1, 1` in `_routerDepositAndDispose` with a bound derived from the intended curve-close ratio, reverting (and retrying later once inventory can force correction) if the achievable deposit ratio deviates beyond a tolerance.

### Proof of Concept
1. Attacker observes token `T` (paired with LT `L`) approaching `canGraduate(T) == true` via public `previewLtUntilGraduation`.
2. Before any graduation buy lands, attacker calls `IUniswapV2Factory.createPair(T, L)` then transfers a large, skewed amount of `T` and `L` (e.g., 50-100x the curve's expected raise, at a ratio far from the curve-close price) into the pair and calls `pair.mint(attacker)`.
3. The graduating buy fires; `Bonding._enterGraduating` caches `(tokensForLP, ltFromPair)` at the curve-close price and freezes trading.
4. Anyone calls `Bonding.finalizeGraduation(T)`. `_ensureUniswapV2Pair` finds the attacker's pre-existing pair. `_seedUniswapV2Direct` → `_seedRebalancing` computes the corrective swap `s`, which is capped at `_swapBudget(ltFromPair or tokensForLP)` — far smaller than what is needed to correct a 50-100x-larger pre-seed.
5. `_pairRebalance` executes the capped swap; the pool ratio remains close to the attacker's chosen ratio.
6. `_routerDepositAndDispose` deposits the remaining `tokensForLP`/`ltFromPair` via `addLiquidity(..., 1, 1, ...)`, locking the LP at the attacker's ratio; leftover token is burned, leftover LT is later swept to the protocol owner — none of it corrects the mispricing.
7. Attacker, holding the original LP mint, immediately arbitrages the mispriced pool against the fair curve-close price, extracting value that was contributed by curve traders and meant to back the locked LP.

    function _seedUniswapV2Direct(
        address tokenAddress,
        address lt,
        address pair,
        uint256 tokensForLP,
        uint256 ltFromPair,
        uint256 protectedLT
    ) internal returns (uint256 liquidity) {
        // Regime 2 — pull any donation pre-seed into this contract so it
        // doesn't pollute the post-swap ratio. Routed to `address(this)`
        // (NOT `lpLock`) so donated TOKEN can be burned and donated LT
        // can be swept to the owner via `_sweepLTToOwner` — `LPLock` has
        // no rescue path, so anything sent there is permanently stuck.
        // No-op on a freshly-created pair (balance == reserves == 0).
        IUniswapV2Pair(pair).skim(address(this));

        // Regime 1 — no LP minted yet (`totalSupply == 0`): a pristine empty
        // pair, or a dust pre-seed from `transfer(pair, dust) + sync()` that
        // leaves reserves non-zero while supply is still zero. Keying on
        // supply rather than reserves routes the dust shape here instead of
        // the rebalance path: with zero supply V2 mints from our amounts
        // alone, so the pool opens at the cached ratio and any dust becomes
        // reserves with no LP claim.
        if (IUniswapV2Pair(pair).totalSupply() == 0) {
            return _seedDirectMint(tokenAddress, lt, pair, tokensForLP, ltFromPair);
        }

        // Regime 3 — mint pre-seed: rebalance, then deposit balanced subset.
        // `lpLock_` re-read from storage inside `_routerDepositAndDispose`.
        // Reserves and token-ordering re-read inside `_seedRebalancing` to
        // keep this function's stack pressure under solc's 16-slot ceiling
        // without `viaIR`.
        return _seedRebalancing(tokenAddress, lt, pair, tokensForLP, ltFromPair, protectedLT);
    }

    function _seedRebalancing(
        address tokenAddress,
        address lt,
        address pair,
        uint256 tokensForLP,
        uint256 ltFromPair,
        uint256 protectedLT
    ) internal returns (uint256 liquidity) {
        (uint112 r0, uint112 r1,) = IUniswapV2Pair(pair).getReserves();
        bool tokenIs0 = IUniswapV2Pair(pair).token0() == tokenAddress;
        (uint256 reserveToken, uint256 reserveLT) = tokenIs0 ? (uint256(r0), uint256(r1)) : (uint256(r1), uint256(r0));

        // Below the band on BOTH sides, overpower the pre-seed with a direct
        // mint at the cached ratio: the rebalance swap is too coarse to reach
        // the ratio against such small reserves, and the pre-existing LP's
        // claim on the deposit stays bounded by `DIRECT_MINT_PRESEED_BPS`. A
        // side that is large relative to its LP target still takes the
        // rebalance path so it isn't donated under the empty-mint `min()`.
        if (
            reserveToken * BPS_DENOM <= tokensForLP * DIRECT_MINT_PRESEED_BPS
                && reserveLT * BPS_DENOM <= ltFromPair * DIRECT_MINT_PRESEED_BPS
        ) {
            return _seedDirectMint(tokenAddress, lt, pair, tokensForLP, ltFromPair);
        }

        // Budget reads `balanceOf(this)` rather than `tokensForLP` /
        // `ltFromPair` so any skim donation contributes to the rebalance
        // and not only to `_routerDepositAndDispose`'s deposit.
        // Direction: pool TOKEN-rich vs target ⇒ swap LT in (TOKEN out).
        // Pool LT-rich ⇒ swap TOKEN in (LT out). Bounded by uint112 reserves
        // and curve-close-shape targets, both products fit in uint256.
        // When `_pairRebalance` returns false the seed is too small for any
        // swap to move the ratio (its fee-charging quote rounds to zero), so
        // the reserves are negligible against this graduation's inventory:
        // overpower them with a direct mint at the cached ratio rather than
        // letting the router deposit at the attacker's ratio. A swap that
        // does fire leaves the pool ≈ at target for the router deposit.
        if (reserveToken * ltFromPair > reserveLT * tokensForLP) {
            // Pool TOKEN-rich. tokenIn = lt, tokenOut = tokenAddress.
            // tokenInIs0 = (lt is token0) = !tokenIs0.
            if (!_pairRebalance(
                    RebalanceParams({
                        pair: pair,
                        tokenIn: lt,
                        tokenInIs0: !tokenIs0,
                        reserveIn: reserveLT,
                        reserveOut: reserveToken,
                        targetN: ltFromPair,
                        targetD: tokensForLP,
                        maxSwap: _swapBudget(_ltSwapInventory(lt, protectedLT))
                    })
                )) {
                return _seedDirectMint(tokenAddress, lt, pair, tokensForLP, ltFromPair);
            }
        } else if (reserveToken * ltFromPair < reserveLT * tokensForLP) {
            // Pool LT-rich. tokenIn = tokenAddress, tokenInIs0 = tokenIs0.
            if (!_pairRebalance(
                    RebalanceParams({
                        pair: pair,
                        tokenIn: tokenAddress,
                        tokenInIs0: tokenIs0,
                        reserveIn: reserveToken,
                        reserveOut: reserveLT,
                        targetN: tokensForLP,
                        targetD: ltFromPair,
                        maxSwap: _swapBudget(IERC20(tokenAddress).balanceOf(address(this)))
                    })
                )) {
                return _seedDirectMint(tokenAddress, lt, pair, tokensForLP, ltFromPair);
            }
        }
        // else: pool already at curve-close ratio (rare — e.g. attacker
        // pre-seeded at exactly target). Skip swap, deposit directly.

        return _routerDepositAndDispose(tokenAddress, lt, protectedLT);
    }

    function _pairRebalance(
        RebalanceParams memory p
    ) internal returns (bool) {
        uint256 s = _noFeeSwapInput(p.reserveIn, p.reserveOut, p.targetN, p.targetD, p.maxSwap);
        if (s == 0) return false;

        // Quote from the pair so the output tracks its live fee; a value
        // derived from a stale fee rate would trip the pair's K-check.
        uint256 expectedOut = IUniswapV2Pair(p.pair).getAmountOut(s, p.tokenIn);
        if (expectedOut == 0) return false;

        IERC20(p.tokenIn).safeTransfer(p.pair, s);
        (uint256 amount0Out, uint256 amount1Out) = p.tokenInIs0 ? (uint256(0), expectedOut) : (expectedOut, uint256(0));
        IUniswapV2Pair(p.pair).swap(amount0Out, amount1Out, address(this), new bytes(0));
        return true;
    }

    function _noFeeSwapInput(
        uint256 reserveIn,
        uint256 reserveOut,
        uint256 targetN,
        uint256 targetD,
        uint256 maxSwap
    ) internal pure returns (uint256) {
        if (reserveIn == 0 || reserveOut == 0 || targetN == 0 || targetD == 0 || maxSwap == 0) {
            return 0;
        }
        uint256 product = Math.mulDiv(reserveIn * reserveOut, targetN, targetD);
        uint256 newIn = Math.sqrt(product);
        if (newIn <= reserveIn) return 0;
        uint256 s = newIn - reserveIn;
        return s > maxSwap ? maxSwap : s;
    }
