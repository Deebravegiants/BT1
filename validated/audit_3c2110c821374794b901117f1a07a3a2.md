### Title
Bad-debt supply-index floor clamp revives wiped-out supplier claims that drain future depositors - (File: contracts/pool/src/interest.rs)

### Summary
When `clean_bad_debt` socializes a loss that exceeds ~99.9% of a market's total supplied value, `apply_bad_debt_to_supply_index` clamps `supply_index` **up** to `SUPPLY_INDEX_FLOOR_RAW` (`RAY/1000`) instead of zeroing or proportionally writing down the surviving supply shares. Every pre-existing scaled supply position then retains a phantom claim worth `scaled × floor`. Because `require_reserves` only checks `cash`, the first fresh deposit into the wiped market becomes withdrawable by those wiped suppliers — a direct transfer of new depositors' principal to accounts whose claims were already destroyed by socialization. This is the XOXNO analog of M-16: a terminal state transition writes a sentinel index value, and the index math that runs afterwards pays out claims the transition was supposed to extinguish.

### Finding Description
`apply_bad_debt_to_supply_index` reduces `supply_index` pro-rata by the bad debt, capped at total supplied value, and then clamps the result at the floor [1](#0-0) . When `bad_debt >= total_supplied_value × (1 - 1/1000)`, `reduction_factor` floors to near zero, `new_supply_index` would go below `RAY/1000`, and the clamp sets it to exactly `SUPPLY_INDEX_FLOOR_RAW`. Suppliers' `scaled` share counts are untouched — nothing burns or rewrites them — so `unscale_supply_floor(scaled) = scaled × RAY/1000` remains a positive, withdrawable claim.

The permissionless path is `clean_bad_debt` → `socialize_bad_debt` with `BadDebtGate::DustCapped` [2](#0-1) , which calls `PoolSeizeEntry { side: Borrow }` → `seize::apply` → `apply_bad_debt_to_supply_index` + `burn_debt` [3](#0-2) . Bad debt is capped at `total_supplied_value`, so a sufficiently large underwater borrow book (e.g., an oracle crash on a collateral whose debt is denominated in another asset) forces the index to the floor.

After the wipeout, a victim's residual claim is serviced exactly like an honest one: `withdraw` runs `resolve_withdrawal` → `require_reserves` → `debit_cash`. `require_reserves` compares only against `cash`, which is zero until a fresh `supply` credits it [4](#0-3) . The pool unit test `test_raw_cache_floor_clamp_strands_claim_without_supply_guard` demonstrates end-to-end that the stranded claim drains a fresh deposit exactly.

### Impact Explanation
Theft of user funds / protocol insolvency. Wiped suppliers (whose claims the socialization intended to destroy, floored at 0.1% of face value) hold claims that survive at the floor value against a market with zero backing. Any subsequent depositor's principal is immediately seizable by those phantom claims. The loss equals `supplied_scaled × SUPPLY_INDEX_FLOOR` clipped by incoming deposits — bounded by ~0.1% of the pre-wipeout supply book, which can still be a large absolute amount, and it accrues to arbitrary wiped suppliers rather than to the protocol or honest users.

### Likelihood Explanation
Requires a bad-debt event that wipes ≥99.9% of a market's supplied value — extreme but reachable: `clean_bad_debt` is permissionless and only needs `debt > collateral` with collateral ≤ $5 [5](#0-4) . The dust gate caps per-account collateral, not per-market bad debt, so many small insolvent accounts (or one flash-position-driven blowup) on a thin market can accumulate write-downs past the threshold. The exploit is then passive: the wiped supplier just waits for any deposit and calls `withdraw`.

### Recommendation
When the computed index would fall below `SUPPLY_INDEX_FLOOR_RAW`, do not clamp the index upward while leaving scaled shares intact. Either (a) burn/scale down `supplied` and `revenue` shares proportionally so `scaled × floor` reflects the real residual backing, or (b) flag the market as wiped (e.g., zero the shares and require `recapitalize` before re-opening supply), consistent with INV-LIQ-04's statement that recapitalization fills the shortfall — it cannot restore phantom claims paid out to wiped suppliers.

### Proof of Concept
`contracts/pool/tests/interest.rs::test_raw_cache_floor_clamp_strands_claim_without_supply_guard` (lines 372-427) already encodes the exploit: wipe `1_000 * RAY` scaled supply with `5_000 * RAY` bad debt, index clamps to `SUPPLY_INDEX_FLOOR_RAW`, a fresh deposit of `stranded` units is minted, and the wiped position's `resolve_withdrawal(i128::MAX)` + `require_reserves` pays out exactly the fresh deposit, leaving `cash < fresh_claim` for the honest supplier. To drive it through the controller: build a market where an account's borrow (across repeated `clean_bad_debt` calls on dust-collateral accounts, or one large account permitted before `update_account_threshold` restamps) exceeds 99.9% of `supplied × supply_index`, call `clean_bad_debt`, then have a new user `supply` and the wiped supplier `withdraw`.

pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}

fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    bad_debt::execute_bad_debt_cleanup(env, &mut cache, account_id, &account, &totals);
}

/// Socializes insolvent debt when remaining collateral is at or below the dust cap.
pub(crate) fn clean_bad_debt_standalone(env: &Env, account_id: u64) {
    socialize_bad_debt(env, account_id, BadDebtGate::DustCapped);
}

fn test_raw_cache_floor_clamp_strands_claim_without_supply_guard() {
    let t = TestSetup::new();
    t.as_contract(|| {
        let old_scaled_raw = 1_000 * RAY;
        let mut cache = t.fresh_cache(PoolStateRaw {
            supplied: old_scaled_raw,
            borrowed: 0,
            revenue: 0,
            borrow_index: RAY,
            supply_index: RAY,
            last_timestamp: 0,
            cash: 0,
        });
        let old_scaled = Ray::from(old_scaled_raw);

        apply_bad_debt_to_supply_index(&mut cache, Ray::from(5_000 * RAY));
        assert_eq!(
            cache.supply_index().raw(),
            SUPPLY_INDEX_FLOOR_RAW,
            "wipeout clamps supply_index UP to RAY/1000 instead of resetting shares to 0",
        );

        let stranded = cache.unscale_supply_floor(old_scaled);
        assert!(stranded > 0, "floor clamp leaves S_old a phantom claim");
        assert_eq!(
            cache.cash(),
            0,
            "no cash yet: invariant only masked by require_reserves"
        );

        let fresh_cash = stranded;
        let fresh_scaled = cache.calculate_scaled_supply(fresh_cash);
        cache.mint_supply(fresh_scaled);
        cache.credit_cash(fresh_cash);

        let fresh_claim = cache.unscale_supply_floor(fresh_scaled);
        assert_eq!(
            fresh_claim, fresh_cash,
            "fresh supplier's claim equals deposit"
        );

        let (burn, gross) = cache.resolve_withdrawal(i128::MAX, old_scaled);
        cache.require_reserves(gross);
        cache.burn_supply(burn);
        cache.debit_cash(gross);

        assert!(gross > 0, "stranded wiped position pays out real tokens");
        assert_eq!(gross, fresh_cash, "S_old drains exactly the fresh deposit");
        assert!(
            cache.cash() < fresh_claim,
            "pool cash ({}) can no longer cover fresh supplier claim ({}): funds lost",
            cache.cash(),
            fresh_claim,
        );
    });
