Audit Report

## Title
Ethereum claim signatures are replayable across independent `mint_claim` cycles, allowing redirection of a newly re-minted claim to a stale `dest` - (File: polkadot/runtime/common/src/claims/mod.rs)

## Summary
`claim`/`claim_attest` are validated by recovering an Ethereum signer from a signature over only `prefix || dest` (and optionally a statement), with no nonce, claim-instance identifier, or amount bound into the signed payload. Since `validate_unsigned` only checks `Claims::<T>::contains_key(&signer)` and `Claims` is keyed purely by `EthereumAddress`, a previously valid/broadcast `claim` extrinsic becomes replayable against any later, independent `mint_claim` for the same address, redirecting newly minted funds to a stale `dest` without any fresh signature.

## Finding Description
`Pallet::claim` recovers the signer via `Self::eth_recover(&ethereum_signature, &data, &[][..])` where `data = dest.using_encoded(to_ascii_hex)` [1](#0-0) . The signed message construction includes only the configured prefix and the `dest`/statement bytes, with no nonce or mint-cycle identifier [2](#0-1) .

`validate_unsigned` re-derives the same signer for `Call::claim`/`Call::claim_attest` and only asserts `Claims::<T>::contains_key(&signer)` [3](#0-2) . `Claims` is a flat `StorageMap<EthereumAddress, BalanceOf<T>>` with no per-cycle or nonce information [4](#0-3) .

`mint_claim` (root-only) simply re-inserts a balance into `Claims` for the same `who` key without resetting any binding/nonce data [5](#0-4) . `process_claim` pays the currently stored balance to whatever `dest` is passed, then removes the entries [6](#0-5) .

Exploit flow: (1) root mints a claim for `eth_addr` with value `v1`; (2) the key holder signs `dest_A` and submits `claim(dest_A, sig)`, paying out `v1` and deleting the `Claims` entry — the extrinsic bytes are now public; (3) root later mints again for the same `eth_addr` with `v2` (e.g., topping up or reissuing), intending a fresh signature for a new destination; (4) anyone resubmits the old `claim(dest_A, sig)` bytes — `validate_unsigned` recovers the same `eth_addr`, finds `contains_key == true`, and accepts it; (5) `process_claim` pays `v2` to the stale `dest_A`, not the intended recipient.

## Impact Explanation
Funds from a second, independent `mint_claim` for a previously fully-claimed Ethereum address can be redirected to the original `dest` from the first claim cycle, without consent or a fresh signature from the Ethereum key holder. This is an unauthorized redirection of claim funds.

## Likelihood Explanation
Exploitation requires root to `mint_claim` twice for the same Ethereum address across its lifetime (once fully claimed/removed, then re-minted) — a plausible administrative scenario. Once that occurs, replay is trivial for any unprivileged actor: resubmitting historical, publicly available extrinsic bytes requires no new cryptographic material or privileged origin.

## Recommendation
Bind the signed message to the specific claim instance rather than only `dest` — e.g., include a per-address nonce/epoch (incremented on each `mint_claim`) or the claim value/mint block number in `ethereum_signable_message`, and validate it in both `validate_unsigned` and `process_claim`. Alternatively, ensure `mint_claim` cannot reuse an address's storage slot without also invalidating prior signatures via such a nonce.

## Proof of Concept
In `polkadot/runtime/common/src/claims/tests.rs`: (1) `mint_claim(root, eth(&alice), 100, None, None)`; (2) build `sig` over `dest=42`, call `Claims::claim(none, 42, sig.clone())`, assert success and `Claims::claims(eth(&alice)).is_none()`; (3) `mint_claim(root, eth(&alice), 200, None, None)` again (simulating a re-mint intended for `dest=99` with a not-yet-produced fresh signature); (4) call `Claims::validate_unsigned(External, &Call::claim{dest:42, ethereum_signature: sig.clone()})` and observe it returns `Ok(ValidTransaction{..})`, then dispatch `Claims::claim(none, 42, sig)` and observe `Balances::free_balance(42) == 300`, confirming the second mint's funds were redirected to the stale `dest=42` via replay of the old signature.

	// Constructs the message that Ethereum RPC's `personal_sign` and `eth_sign` would sign.
	fn ethereum_signable_message(what: &[u8], extra: &[u8]) -> Vec<u8> {
		let prefix = T::Prefix::get();
		let mut l = prefix.len() + what.len() + extra.len();
		let mut rev = Vec::new();
		while l > 0 {
			rev.push(b'0' + (l % 10) as u8);
			l /= 10;
		}
		let mut v = b"\x19Ethereum Signed Message:\n".to_vec();
		v.extend(rev.into_iter().rev());
		v.extend_from_slice(prefix);
		v.extend_from_slice(what);
		v.extend_from_slice(extra);
		v
	}

	// Attempts to recover the Ethereum address from a message signature signed by using
	// the Ethereum RPC's `personal_sign` and `eth_sign`.
	fn eth_recover(s: &EcdsaSignature, what: &[u8], extra: &[u8]) -> Option<EthereumAddress> {
		let msg = keccak_256(&Self::ethereum_signable_message(what, extra));
		let mut res = EthereumAddress::default();
		res.0
			.copy_from_slice(&keccak_256(&secp256k1_ecdsa_recover(&s.0, &msg).ok()?[..])[12..]);
		Some(res)
	}

	fn process_claim(signer: EthereumAddress, dest: T::AccountId) -> sp_runtime::DispatchResult {
		let balance_due = Claims::<T>::get(&signer).ok_or(Error::<T>::SignerHasNoClaim)?;

		let new_total =
			Total::<T>::get().checked_sub(&balance_due).ok_or(Error::<T>::PotUnderflow)?;

		let vesting = Vesting::<T>::get(&signer);
		if let Some(_) = vesting {
			if T::VestingSchedule::vesting_balance(&dest).is_some() {
				return Err(Error::<T>::VestedBalanceExists.into());
			}

			// A vesting schedule installs a balance lock, which requires the account to stay alive,
			// otherwise it is dusted and the lock placed on a non-existent account. The `dest` may
			// already hold funds, so a small claim that tops an existing account over the ED is
			// valid.
			let free_after = CurrencyOf::<T>::free_balance(&dest).saturating_add(balance_due);
			ensure!(
				free_after >= CurrencyOf::<T>::minimum_balance(),
				Error::<T>::ClaimBelowExistentialDeposit,
			);
		}

		// We first need to deposit the balance to ensure that the account exists.
		let _ = CurrencyOf::<T>::deposit_creating(&dest, balance_due);

		// Check if this claim should have a vesting schedule.
		if let Some(vs) = vesting {
			// This can only fail if the account already has a vesting schedule or its balance is
			// below the existential deposit, both of which are checked above.
			T::VestingSchedule::add_vesting_schedule(&dest, vs.0, vs.1, vs.2)
				.map_err(|_| Error::<T>::VestedBalanceExists)?;
		}

		Total::<T>::put(new_total);
		Claims::<T>::remove(&signer);
		Vesting::<T>::remove(&signer);
		Signing::<T>::remove(&signer);

		// Let's deposit an event to let the outside world know this happened.
		Self::deposit_event(Event::<T>::Claimed {
			who: dest,
			ethereum_address: signer,
			amount: balance_due,
		});

		Ok(())
	}
