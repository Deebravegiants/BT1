Audit Report

## Title
Missing fuel deduction in `EngineMeter::charge_ref_time` lets a contract run more wasm bytecode than `gas_limit` allows - ([File: substrate/frame/contracts/src/gas.rs])

## Summary
`EngineMeter::charge_ref_time` in `substrate/frame/contracts/src/gas.rs` computes the fuel-equivalent cost of a host-function call via `ref_time.checked_div(...)` but discards the result of `self.fuel.checked_sub(amount)` instead of assigning it back to `self.fuel`, then returns the unmodified, stale fuel value. This stale value is written directly into wasmi's internal fuel counter via `__caller__.set_fuel(fuel.into())` in the code generated by `substrate/frame/contracts/proc-macro/src/lib.rs`'s `sync_gas_after` block, meaning wasmi's own trap-enforcing fuel budget is never decremented for the weight cost of host-function calls (only for bytecode execution, which is captured separately via `sync_from_executor`).

## Finding Description [1](#0-0) 

`self.fuel.checked_sub(amount)` is evaluated solely as an underflow check — its `Ok` value (the properly decremented fuel) is thrown away, and `self.fuel` is never reassigned, so `Ok(Syncable(self.fuel))` returns the pre-call fuel value unchanged.

This return value flows directly into the wasmi engine's actual fuel counter: [2](#0-1) 

`sync_to_executor` calls into `charge_ref_time` with the ref_time consumed by the host call's own weight charges (base `HostFn` cost plus any per-call charges): [3](#0-2) 

Meanwhile, `sync_from_executor` correctly captures bytecode-execution fuel consumption into `gas_left` at the *next* host-call entry: [4](#0-3) 

Because `self.fuel` is never decremented for a host call's own weight cost, wasmi's real internal fuel counter retains extra headroom equal to that cost after every host-function call. In a pure-bytecode loop between two host calls, wasmi's own fuel-exhaustion trap is the *only* enforcement mechanism (since `gas_left` is only checked via `charge()` when a host function executes), so the loop can run for longer real execution time than the weight-based `gas_limit` should permit. The discrepancy is only reconciled retroactively the next time a host function is entered and `sync_from_executor` reduces `gas_left`, by which point the extra unmetered bytecode has already executed. The correct pattern is demonstrated in the equivalent `substrate/frame/revive/src/metering/weight.rs::sync_remaining_ref_time`, which does reassign `self.fuel`. [5](#0-4) 

## Impact Explanation
Any unprivileged contract caller can deploy a WASM contract that interleaves cheap host-function calls (e.g. `seal_gas_left`, `seal_caller`) with tight bytecode-only compute loops. Each host call fails to shrink wasmi's actual fuel counter by its own weight cost, so the following bytecode segment is allowed to execute more instructions than the true `gas_limit`/`Weight` budget permits, consuming excess real CPU/block time before the shortfall is caught (as `OutOfGas`) on the subsequent host call. This is a weight/gas-limit bypass permitting extra unmetered computation, matching an in-scope impact class.

## Likelihood Explanation
The flaw is unconditionally reachable on every `sync_to_executor` invocation, i.e. on every host-function exit in fuel-metered wasmi execution, requiring no special privilege — only an attacker-controlled contract that repeats host calls interspersed with bytecode loops. It is deterministic and fully reproducible.

## Recommendation
Fix `EngineMeter::charge_ref_time` to actually apply the computed decrement:
```rust
self.fuel = self.fuel.checked_sub(amount).ok_or_else(|| Error::<T>::OutOfGas)?;
Ok(Syncable(self.fuel))
```

## Proof of Concept
1. Unit-test `substrate/frame/contracts/src/gas.rs`'s `tests` module: construct `GasMeter::<Test>::new(gas_limit)`, call `sync_from_executor(engine_fuel)` then `sync_to_executor(before)` simulating a host call with a nonzero weight cost, and assert the fuel returned by `sync_to_executor` decreases by `host_cost.ref_time() / ref_time_by_fuel()` relative to the pre-call fuel — currently it does not decrease at all.
2. Integration-level reproduction: deploy a contract looping N times calling `seal_gas_left` followed by a tight wasm arithmetic loop; measure actual wasmi fuel consumed across the whole call versus `gas_meter.gas_consumed()` and show they diverge linearly with N instead of tracking within the expected rounding bound.

			.checked_reduce(weight_consumed)
