### Title
Permanent market freeze: `scaled_to_original` value overflow bricks a whale-scale market before the borrow-index cap engages - ([File: common/src/rates/simulate.rs](common/src/rates/simulate.rs))

### Summary
`accrue_step` computes `borrowed_original` and `supplied_original` via `scaled_to_original` before checking the borrow-index ceiling. For a market whose scaled supply/debt is large (high-decimals token, whale-scale book) and whose index has grown on a steep rate curve, the `i128` product `scaled_shares × index` overflows and panics with `MathOverflow`. Since `global_sync` runs this step at the top of every state-changing pool verb, the entire market becomes permanently uncallable — before `update_borrow_index`'s `MAX_BORROW_INDEX_RAY` clamp can stop index growth.

### Finding Description
The accrual path is shared: `interest::global_sync` → `accrue_chunk` → `accrue_step` in `common/src/rates/simulate.rs:51-94`. Lines 60-61 evaluate:

```rust
let borrowed_original = scaled_to_original(env, borrowed, borrow_index);
let supplied_original = scaled_to_original(env, supplied, supply_index);
```

`scaled_to_original` multiplies RAY-scaled shares by the RAY index; the product must fit `i128` (or the widened `I256` result must convert back to `i128` — see `mul_div_*` in `common/src/math/fp_core.rs:108-174`, which panics `MathOverflow` when the quotient exceeds `i128`). The borrow index is clamped at `MAX_BORROW_INDEX_RAY` only inside `update_borrow_index` (`common/src/rates/index.rs`), which runs *after* the overflowing `scaled_to_original` call — so the cap cannot protect the value computation.

The in-scope buffer-overflow analog: an unchecked-size computation overflows its fixed-width "buffer" (`i128`), and the resulting panic is triggered at the head of every entrypoint. `docs/reference/invariants.md:235-236` admits "Debt-value overflow can still revert accrual before that ceiling is reached" but documents only a transient revert, not that the condition is **unrecoverable**: once `borrowed × borrow_index > i128::MAX`, every subsequent call hits the same panic because `last_timestamp` keeps advancing and the index never decreases. The project's own regression test confirms the freeze: `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-356` drives a 18-decimal market at 98% utilization, observes `MATH_OVERFLOW` from `update_indexes` with `borrow_index < MAX_BORROW_INDEX_RAY`, and verifies `withdraw` and `repay` revert identically.

### Impact Explanation
Permanent freezing of funds in the affected market: once the product crosses `i128::MAX`, no user can `withdraw`, `repay`, `borrow`, `liquidate`, or `update_indexes` on that market — every path calls `global_sync` first. Supplier principal and borrower collateral backing that market are locked indefinitely. No recovery verb exists that bypasses accrual.

### Likelihood Explanation
Reachable by a single unprivileged address, though capital-intensive: supplying a very large amount of a high-decimals asset and borrowing ~98% of it, then letting the index compound (or keeping utilization pinned on the steep segment of the rate curve) pushes `scaled × index` past `i128::MAX` in a few years per the test. `update_indexes` is permissionless, so any attacker can trigger the fatal accrual the moment the threshold is crossed; a whale can also deliberately construct the cliff to freeze the market, grieving all other suppliers. Severity: High impact / bounded likelihood → Medium-High.

### Recommendation
Reorder `accrue_step` so the index clamp is evaluated before any `scaled × index` multiplication, and make `scaled_to_original` (or the step) saturate/skip accrual when the value exceeds `i128::MAX` rather than panicking — e.g., clamp the borrow index to `MAX_BORROW_INDEX_RAY` and set `borrow_rate = 0` when debt value is unrepresentable, so repay/withdraw can proceed while interest stops accruing. Alternatively, enforce a `supplied × max_index` ceiling at market-supply time so the overflow domain is unreachable.

### Proof of Concept
`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-356`:

```rust
let principal = BILLION * 10i128.pow(18);
t.supply_raw(BOB, "BIG18", principal);
let debt = principal / 100 * 98;
t.borrow_raw(ALICE, "BIG18", debt);
// advance years; try_update_indexes_for("BIG18") -> MATH_OVERFLOW
// with borrow_index < MAX_BORROW_INDEX_RAY
assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```

An unprivileged caller executes: `pool.supply(market, huge)` → `borrow(...)` near utilization max → wait/repeat `pool.update_indexes(hub)` → the panic in `scaled_to_original` permanently blocks every subsequent market verb.
