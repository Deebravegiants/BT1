This confirms the vault handler's `requestProcessor.ProcessRequest` mutates `req.ID` to include the authenticated owner prefix (`owner + RequestIDSeparator + requestID`) **before** `newActiveRequest` is called, so the in-flight map is effectively keyed by an authenticated, owner-scoped identifier. The `confidentialrelay` handler has no equivalent step, and the gateway's `ProcessRequest` in `core/services/gateway/gateway.go` dispatches to `HandleJSONRPCUserMessage` without any signature/auth check performed on the request before it reaches the handler for this service.

Audit Report

## Title
Unauthenticated request-ID squatting causes griefing DoS in Confidential Relay gateway handler - (File: core/services/gateway/handlers/confidentialrelay/handler.go)

## Summary
The `confidentialrelay` gateway handler's `HandleJSONRPCUserMessage` uses the raw, client-supplied `req.ID` as a global map key in `h.activeRequests` with no authentication, ownership binding, or per-caller namespacing, unlike the sibling `vault` handler which rewrites `req.ID` to an authenticated `owner + RequestIDSeparator + requestID` form via `requestProcessor.ProcessRequest` before registering it. Any actor able to reach the gateway's ingress for this handler's methods can pre-claim an arbitrary `req.ID`, causing a legitimate caller's subsequent request with the same ID to be rejected with `"request ID already exists"`.

## Finding Description
`HandleJSONRPCUserMessage` in `core/services/gateway/handlers/confidentialrelay/handler.go` performs only trivial length/emptiness checks on `req.ID` and then calls `h.newActiveRequest(req, labels, callback)` [1](#0-0) , which registers the request keyed by the bare `req.ID` and errors out if that key is already present [2](#0-1) . The package comment explicitly states the gateway "does not otherwise interpret params," confirming no authorization step exists in this path [3](#0-2) .

By contrast, the `vault` handler calls `h.requestProcessor.ProcessRequest`, which authorizes the request and rewrites `req.ID` to `owner + RequestIDSeparator + requestID` (via `authorizeAndStamp`/`processCreateSecretsRequest` etc. in `core/capabilities/vault/gateway_vault_request_processor.go`) before `newActiveRequest` is invoked [4](#0-3) [5](#0-4) . This means the vault handler's in-flight map key is bound to an authenticated owner identity, so a collision on the same `req.ID` from a different owner cannot occur (each owner's namespace is disjoint). The `confidentialrelay` handler has no analogous step: `h.getHandler`/`gateway.ProcessRequest` in `core/services/gateway/gateway.go` dispatch straight to `HandleJSONRPCUserMessage` based only on the JSON-RPC `ServiceName()`/method, with no signature verification or owner binding performed anywhere in that call path [6](#0-5) . The existing test `TestConfidentialRelayHandler_DuplicateRequestID` confirms that any second caller reusing the same `req.ID` is rejected regardless of identity [7](#0-6) .

Downstream, the actual capability handler (`core/capabilities/confidentialrelay/handler.go`, on the node side that receives the relayed message) does perform strong authentication — TEE attestation verification and Workflow-DON signature quorum checks (`verifyAttestationHash`, `verifyWorkflowAuthorization`) — but this occurs only *after* the gateway has already relayed the message to nodes, and it does not protect the gateway's own in-flight request registry, which is the layer being exploited here.

## Impact Explanation
This is an unauthenticated griefing/denial-of-service vector: an attacker who submits (or predicts) a specific `req.ID` before the legitimate caller does causes the legitimate caller's request to be rejected outright with `"request ID already exists"` at the gateway, before it ever reaches attestation/authorization checks on the node side. This matches an in-scope "gateway request impersonation / DoS" style impact — a caller can deny another caller's specific relay request without needing valid attestation, signatures, or funds. The severity is bounded (it's a griefing/DoS on individual request IDs, not data exfiltration or fund movement), but it is a concrete, reachable exploit path caused by a real gap in the code (missing per-owner namespacing that the sibling `vault` handler already implements).

## Likelihood Explanation
Exploitability depends on the attacker's ability to reach the gateway's JSON-RPC ingress for `MethodSecretsGet`/`MethodCapabilityExec` and to know or predict the target `req.ID` in advance. Based on the code reviewed, `gateway.ProcessRequest` performs no caller authentication before dispatching to `HandleJSONRPCUserMessage`, so any client that can send an HTTP request to the gateway's public port can attempt this — the same conclusion the original report reached. This is a real, currently-reachable gap; whether request IDs used by real enclaves/workflows are practically predictable by an external attacker (the report itself only speculates on this) is the main uncertainty, but the underlying missing-authorization behavior is verified and not speculative.

## Recommendation
1. Bind the in-flight `activeRequests` map key to an authenticated identity, following the `vault` handler's pattern of prefixing `req.ID` with an authorized owner/caller identity before registration.
2. Add an authorization/authentication step in `HandleJSONRPCUserMessage` (confidentialrelay) prior to `newActiveRequest`, or otherwise validate the caller before allowing them to claim a request ID.
3. Alternatively, derive the tracking key server-side from an authenticated attribute (e.g., a hash of verified caller identity + client-chosen ID) rather than trusting the raw client string as a global uniqueness key.

## Proof of Concept
Using the existing `TestConfidentialRelayHandler_DuplicateRequestID` test as a base: an attacker submits `HandleJSONRPCUserMessage` with a `req.ID` value (predicted or observed to belong to an intended legitimate execution) before the legitimate caller's request arrives; the legitimate caller's identical-ID request is then rejected with `"request ID already exists"`, confirmed at [7](#0-6) , denying that specific relay action with no authentication required from the attacker.

func (h *handler) HandleJSONRPCUserMessage(ctx context.Context, req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) error {
	if req.ID == "" {
		return errors.New("request ID cannot be empty")
	}
	if len(req.ID) > 200 {
		// Arbitrary limit to prevent abuse
		return errors.New("request ID is too long: " + strconv.Itoa(len(req.ID)) + ". max is 200 characters")
	}

	h.lggr.Debugw("handling vault request", "method", req.Method, "requestID", req.ID, "request", req)
	if req.Method == vaulttypes.MethodPublicKeyGet {
		// Public key requests don't require authorization,
		// Let's process this request right away.
		// Note we cache this value quite aggressively so don't need to worry about DoS.
		publicKeyResponseBytes, cachedPublicKey := h.getCachedPublicKey()
		if cachedPublicKey == nil {
			// Not found in cache. Fetch from nodes.
			ar, err := h.newActiveRequest(req, callback)
			if err != nil {
				h.lggr.Errorw("failed to create new activeRequest", "error", err)
				return err
			}
			return h.handlePublicKeyGet(ctx, ar)
		}
		h.lggr.Debugw("returning cached public key response")
		return h.handlePublicKeyGetSynchronously(ctx, req, publicKeyResponseBytes, callback)
	}

	if !vaulttypes.IsGatewaySecretsMethod(req.Method) {
		return h.sendImmediateUserResponse(ctx, req, callback, api.UnsupportedMethodError, errors.New("this method is unsupported: "+req.Method))
	}

	_, cachedPublicKey := h.getCachedPublicKey()
	authorized, err := h.requestProcessor.ProcessRequest(ctx, &req, cachedPublicKey)
	if err != nil {
		if vaultcap.IsInvalidVaultParamsError(err) {
			return h.sendImmediateUserResponse(ctx, req, callback, api.InvalidParamsError, err)
		}
		h.lggr.Errorw("request not authorized", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "", "error", err)
		return errors.New("request not authorized: " + err.Error())
	}
	authorizedOwner := authorized.AuthResult.AuthorizedOwner()

	h.lggr.Debugw("handling authorized vault request", "method", req.Method, "requestID", req.ID, "authorizedOwner", authorizedOwner)
	ar, activeRequestErr := h.newActiveRequest(req, callback)
	if activeRequestErr != nil {
		return activeRequestErr
	}

func (g *gateway) ProcessRequest(ctx context.Context, rawRequest []byte, auth string) (rawResponse []byte, httpStatusCode int) {
	// decode
	jsonRequest, err := jsonrpc2.DecodeRequest[json.RawMessage](rawRequest, auth)
	if err != nil {
		return newError("", api.UserMessageParseError, err.Error())
	}
	msg, err := g.codec.DecodeJSONRequest(jsonRequest)
	if err != nil {
		return newError(jsonRequest.ID, api.UserMessageParseError, err.Error())
	}
	if len(jsonRequest.ID) > 200 {
		// Arbitrary limit to prevent abuse
		return newError(jsonRequest.ID, api.UserMessageParseError, "request ID is too long: "+strconv.Itoa(len(jsonRequest.ID))+". max is 200 characters")
	}
	isLegacyRequest := false
	var h handlers.Handler
	var handlerKey string
	if msg == nil || msg.Body.DonID == "" {
		serviceName := jsonRequest.ServiceName()
		if handler, ok := g.serviceToMultiHandler[serviceName]; ok {
			h = handler
			handlerKey = serviceName
		} else if donID, ok := g.serviceNameToDonID[serviceName]; ok {
			// Fallback to legacy service name -> DON ID mapping
			if handler, ok := g.handlers[donID]; ok {
				h = handler
				handlerKey = donID
			}
		}
		if h == nil {
			return newError(jsonRequest.ID, api.HandlerError, "Service name not found: "+serviceName)
		}
	} else {
		// Legacy request with DON ID - validate and fetch handler
		isLegacyRequest = true
		if err = msg.Validate(); err != nil {
			return newError(jsonRequest.ID, api.UserMessageParseError, err.Error())
		}
		handlerKey = msg.Body.DonID
		var ok bool
		h, ok = g.handlers[handlerKey]
		if !ok {
			return newError(jsonRequest.ID, api.UnsupportedDONIdError, "Unsupported DON ID: "+handlerKey)
		}
	}

	startTime := time.Now()
	var method string
	callback := handlerscommon.NewCallback()
	if isLegacyRequest {
		method = msg.Body.Method
		err = h.HandleLegacyUserMessage(ctx, msg, callback)
	} else {
		method = jsonRequest.Method
		err = h.HandleJSONRPCUserMessage(ctx, jsonRequest, callback)
	}
	if err != nil {
		return newError(jsonRequest.ID, api.HandlerError, err.Error())
	}
