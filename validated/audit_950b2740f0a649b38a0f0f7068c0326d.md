### Title
Missing `extcodesize` check in `EvmHost` GET-response and timeout delivery paths lets low-level calls to no-code accounts silently "succeed" - ([File: evm/src/core/EvmHost.sol])

### Summary
`EvmHost.dispatchIncoming(GetResponse, ...)`, `dispatchTimeOut(GetRequestTimeout, ...)`, and `dispatchTimeOut(PostRequestTimeout, ...)` all route delivery through a raw `.call()` to `_bytesToAddress(...request.from)` without first checking that the target has code, unlike the sibling function `dispatchIncoming(PostRequest, ...)` in the same file, which explicitly guards against this with an `extcodesize` check.

### Finding Description
`dispatchIncoming(PostRequest, ...)` correctly protects against calling accounts with no code: [1](#0-0) 

But the three other delivery paths in the same contract omit this guard entirely and call directly: [2](#0-1) [3](#0-2) [4](#0-3) 

The `from` field of a request is set directly to the dispatching `msg.sender` with no requirement that it be a contract: [5](#0-4) [6](#0-5) 

Because `dispatch(DispatchGet)` and `dispatch(DispatchPost)` are unprivileged, externally callable functions, any EOA (or any account without code at the time of response/timeout delivery, e.g. one that self-destructed or a not-yet-deployed counterfactual address) can be the recorded `from`. At the EVM level, a low-level `.call()` to an account with no code always returns `success = true` regardless of the calldata supplied — Solidity's automatic "does this address have code" check only applies to normal, high-level function calls, not to `.call()`. Consequently, when the relayer later delivers the `GetResponse`/`GetRequestTimeout`/`PostRequestTimeout` message, the raw call to a no-code `from` address trivially "succeeds" even though the intended `IApp.onGetResponse`/`onGetTimeout`/`onPostRequestTimeout` logic never executed.

### Impact Explanation
Because the call is treated as a genuine success:
- The response/timeout receipt is permanently written (or, for the response path, kept) as delivered, so the message can never be retried or redelivered — this is a route that is permanently unable to deliver its message to the intended (non-existent) recipient, matching the "route unable to deliver messages" criterion.
- The relayer is unconditionally paid the escrowed fee, and a `*Handled` event is emitted, asserting on-chain that a real `IsmpModule` callback ran successfully when in fact no application logic executed at all.
- Any funds/state transitions that were only supposed to happen inside the (never-executed) `on_response`/`on_timeout` callback (e.g. releasing escrow, refunding a cross-chain transfer) are permanently unreachable once the receipt is finalized, since the protocol believes delivery already occurred.

This directly mirrors the referenced report's root cause (unguarded low-level `.call()` silently succeeding against no-code accounts) but manifests here as forged "successful delivery" bookkeeping and permanent inability to redeliver/timeout a message, rather than a direct ETH transfer.

### Likelihood Explanation
The `from` address is fully attacker/user-controlled at dispatch time (it is simply `msg.sender`), and dispatch is permissionless, so triggering a no-code `from` requires no privileged access — any unprivileged caller of `dispatch(DispatchGet)`/`dispatch(DispatchPost)` can set `from` to an EOA or a not-yet-deployed address. The bug is directly reachable from the normal relayer message-delivery flow (`HandlerV2` → `EvmHost.dispatchIncoming`/`dispatchTimeOut`), which is the exact reachable surface enumerated for this analysis.

### Recommendation
Add the same `extcodesize` (or equivalent) guard used in `dispatchIncoming(PostRequest, ...)` to `dispatchIncoming(GetResponse, ...)`, `dispatchTimeOut(GetRequestTimeout, ...)`, and `dispatchTimeOut(PostRequestTimeout, ...)` before performing the low-level `.call()`, so that calls to accounts without code are treated as failures (receipt not finalized / eligible for retry) rather than as successful deliveries. Alternatively, use OpenZeppelin's `Address.functionCall`, which reverts when the target has no code.

### Proof of Concept
1. An unprivileged EOA `A` calls `EvmHost.dispatch(DispatchGet{...})` directly, paying `get.fee`. `request.from` is recorded as `abi.encodePacked(A)` (see `evm/src/core/EvmHost.sol:992`), and `A` has no code.
2. A relayer obtains a valid storage-membership proof for the queried keys and submits it via `HandlerV2`, which calls `EvmHost.dispatchIncoming(GetResponse, relayer)`.
3. Inside `dispatchIncoming`, `_bytesToAddress(response.request.from)` resolves to `A` (an EOA). The low-level `.call(...)` to `A` returns `success = true` unconditionally, since EOAs (and any no-code address) trivially "succeed" any low-level call regardless of the calldata (`evm/src/core/EvmHost.sol:832-833`).
4. The host proceeds as if `IApp.onGetResponse` executed successfully: it keeps the `_responseReceipts` entry (permanently marking this response as delivered, so it can never be retried) and transfers the escrowed `fee` to `relayer`, emitting `GetRequestHandled` — even though no application logic ever ran (`evm/src/core/EvmHost.sol:841-846`).

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }
