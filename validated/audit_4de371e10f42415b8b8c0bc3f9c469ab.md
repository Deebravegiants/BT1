### Title
Unbounded memory allocation from attacker-controlled SCALE length in `Codec.DecodeHeader` - ([File: evm/src/consensus/Codec.sol])

### Summary
`Codec.DecodeHeader`, used to decode parachain headers during BEEFY consensus verification, allocates a `Digest[]` array whose size is taken directly from an untrusted SCALE compact-encoded length field in the submitted proof, without checking that value against the remaining bytes available in the proof buffer. This mirrors the `evm-core::Memory::copy_large` bug class: a length value read from attacker-controlled input is used to size a memory allocation before the input is validated to actually contain that much data, letting a malicious value drive an excessive allocation.

### Finding Description
In `evm/src/consensus/Codec.sol`:

```solidity
uint256 length = ScaleCodec.decodeUintCompact(slice);
Digest[] memory digests = new Digest[](length);

for (uint256 i = 0; i < length; i++) {
    ...
    digests[i] = digest;
}
``` [1](#0-0) 

`length` comes straight from `ScaleCodec.decodeUintCompact(slice)`, a SCALE compact integer decoded from the caller-supplied `para.header` bytes, with no bound check against `slice.data.length - slice.offset` before `new Digest[](length)` is executed. The subsequent loop then tries to read `length` digest items from the slice, but the `Digest[]` array itself is already allocated up front at the attacker-chosen size.

`DecodeHeader` is reached from `EcdsaBeefy.verifyParachainHeaderProof`, which iterates over every `Parachain` entry in the submitted `ParachainProof` and calls `Codec.DecodeHeader(para.header)` on each attacker-supplied header: [2](#0-1) 

This is invoked from `EcdsaBeefy.verify`, the entry point implementing `IConsensusV2`, which any relayer calls (directly or via `ConsensusRouter.verify`) to submit a consensus proof: [3](#0-2) [4](#0-3) 

Because the consensus client is called ahead of message dispatch/handling (`HandlerV2`/`EvmHost` state update flow), any unprivileged relayer submitting a BEEFY consensus update can supply a crafted `Parachain.header` whose SCALE-encoded digest count is an arbitrarily large value (subject only to the compact-int encoding, which can represent values well beyond any realistic header size), forcing Solidity to attempt allocation of a correspondingly huge `Digest[]` memory array before any content validation occurs.

### Impact Explanation
Solidity's `new T[](n)` allocation cost for dynamic memory arrays grows quadratically with `n` (memory expansion cost) and is charged before the allocation even completes meaningfully — an attacker can pick `length` to make the allocation exhaust the available gas, reverting the transaction. Since consensus proof verification is a gating step for advancing state-machine height and delivering all pending messages for that chain (POST/GET requests routed through `HandlerV2`), a relayer able to force reverts on `verify` for a target state machine can stall or degrade message delivery for that route — a denial-of-service on the consensus-update/relay path, consistent with the "route unable to deliver messages" impact class. This does not steal funds or forge state, so it is bounded to availability/DoS, matching the Medium severity of the original advisory.

### Likelihood Explanation
The path is reachable by any unprivileged relayer: `EcdsaBeefy.verify` and `ConsensusRouter.verify` are externally callable with proof bytes fully controlled by the caller, and `verifyParachainHeaderProof`/`Codec.DecodeHeader` operate on `pure` functions with no additional signature or membership gate applied to the header bytes before decoding the digest count. Crafting a proof with an inflated compact-int length in the digest-count field requires no privileged access, only knowledge of the SCALE encoding, making this straightforward to trigger.

### Recommendation
Bound `length` in `Codec.DecodeHeader` (and similarly in `decodeDigestItem`'s `Bytes.read(slice, length)`, which has the same issue) against the number of bytes actually remaining in `slice` before allocating, e.g. `require(length <= (slice.data.length - slice.offset));`, or impose an explicit maximum digest count consistent with real Substrate headers, rejecting the proof early instead of allocating unbounded memory.

### Proof of Concept
1. Construct a `Parachain.header` byte string that correctly encodes the parent hash, block number, state root, and extrinsics root fields expected by `DecodeHeader`.
2. For the digest-count field, encode a SCALE compact integer representing a very large value (e.g., using the 4-byte "mode 3" compact encoding to represent a value in the hundreds of millions/billions) instead of a realistic small digest count, without providing that many trailing digest bytes.
3. Submit this header as part of a `ParachainProof.parachains[]` entry to `EcdsaBeefy.verify` (via `ConsensusRouter.verify` or directly), alongside an otherwise-valid relay chain BEEFY proof.
4. Observe `Codec.DecodeHeader` attempting `new Digest[](length)` with the inflated `length`, causing the call to run out of gas/revert, and the enclosing relayer transaction/consensus update to fail — repeatable at negligible cost to the attacker (Note: exact gas thresholds and confirmation of the maximum reachable value from `ScaleCodec.decodeUintCompact`'s highest mode branch were not fully re-verified in this session due to tool-call limits reached before reading the remainder of the function; a Devin session with full file access should confirm the exact compact-int mode/byte-length ceiling to quantify the worst-case allocation size).

    function verify(bytes calldata previousState, bytes calldata encodedProof)
        external
        view
        returns (bytes memory, IntermediateState[] memory, uint256)
    {
        if (encodedProof.length == 0) revert EmptyProof();
        uint8 proofTypeByte = uint8(encodedProof[0]);

        if (proofTypeByte > uint8(type(ProofType).max)) {
            revert InvalidProofType(proofTypeByte);
        }

        ProofType proofType = ProofType(proofTypeByte);
        bytes calldata actualProof = encodedProof[1:];
        if (proofType == ProofType.Sp1) {
            return IConsensusV2(address(sp1Beefy)).verify(previousState, actualProof);
        } else if (proofType == ProofType.Ecdsa) {
            return IConsensusV2(address(ecdsaBeefy)).verify(previousState, actualProof);
        } else {
            revert InvalidProofType(proofTypeByte);
        }
    }
