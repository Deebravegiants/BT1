### Title
`EmporiumUpgradeable.verifyWallet` signature omits `relay` and `feeStructure`, letting the tx submitter redirect wallet relay-fee payments - (File: `contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol`)

### Summary
The `EmporiumSignature` EIP-712 payload that a wallet owner (`stack.signerAddress`) signs to authorize an Emporium `runAction` call binds only `message`, the hash of `ops`, `maxFee`, and `deadline`. It does **not** bind `circomData.relay` or `circomData.feeStructure` (feeToken/flatFee/variableRate). Because `runAction`/`payRelayFees` later use these unsigned `CircomData` fields to pull funds directly from the signer's `IHinkalWallet` via `doSendToRelay`, whoever submits the surrounding `transact()` call (the relay, or `msg.sender` for an internal tx) can freely choose the destination address and the fee token used to drain the signed wallet, subject only to a numeric cap (`flatFee <= maxFee`).

### Finding Description
`EmporiumOperation`/`EmporiumStack` signing: [1](#0-0) 

`verifyWallet` recovers the signer from a hash that only covers `emporiumMessage`, `_hashEmporiumOps(stack.ops)`, `stack.maxFee`, and `stack.deadline`: [2](#0-1) 

The `EmporiumStack` itself is decoded from `circomData.externalActionData.externalActionMetadata` inside `runAction`: [3](#0-2) 

After executing `stack.ops`, the contract pays the relay fee out of the *signer's wallet* using `circomData.relay` and `circomData.feeStructure`, neither of which is part of the signed hash: [4](#0-3) 

`sendToRelayFromWallet` calls `IHinkalWallet(signerAddress).doSendToRelay(relay, relayFee, feeToken)`, which unconditionally transfers `feeToken` from the wallet to `relay`: [5](#0-4) [6](#0-5) 

`CircomData.relay` and `CircomData.feeStructure` are attacker-controllable top-level fields of the `transact()` call and are not covered by the wallet owner's EIP-712 signature: [7](#0-6) 

Unlike the shielded-proof leg of the transaction (whose `calldataHash`/`signedMessageHash` do bind `feeStructure`, `relay`, etc., via `CircomDataBuilder.getHashedCalldata`/`getSignedMessageHash`), the *wallet owner's* Emporium ECDSA signature is a separate authorization that is checked independently in `verifyWallet` and never cross-checked against `circomData.relay`/`feeStructure`. The only guard is `flatFee > stack.maxFee` revert: [8](#0-7) 

This is the same root-cause pattern as the referenced Gondi finding: a single signed authorization (`RenegotiationOffer` there, `EmporiumSignature` here) is reused/consumed through a code path that can act on additional unsigned parameters, producing unintended, unauthorized asset movement — here, moving wallet funds to an address and in a token the wallet owner never approved.

### Impact Explanation
This breaks the equality the signature is supposed to enforce: "wallet owner authorized fee payment of X to the intended relay" vs. "wallet owner authorized fee payment of up to `maxFee` numeric units, in any ERC20 token, to any address chosen by whoever submits the transaction." Any party that can call `Hinkal.transact` with a previously-obtained valid `EmporiumStack` signature (e.g., a malicious relay, or the user's own front-end being MITM'd, or anyone who intercepts/observes the signed payload before submission) can:
- Redirect the relay-fee payment to their own address instead of the legitimate relay, and
- Choose an arbitrary ERC20 token held in the wallet as `feeToken` (not the one the user intended to pay fees in), up to the numeric cap `maxFee`.

This is theft of value from the signer's `IHinkalWallet` that was never actually consented to for that specific token/recipient — falling under "theft or permanent freezing of protocol/relay fees" / "unauthorised asset movement a wallet owner ... never authorised."

### Likelihood Explanation
Any address that can front-run or simply act as the transaction submitter for a previously produced `EmporiumStack` signature can exploit this — no relayer/admin/owner privilege is required, and the ZK proof/`calldataHash` check does not constrain the Emporium-internal EIP-712 signature's coverage of `relay`/`feeStructure`. The signed message is reusable across arbitrary `circomData.relay` and `circomData.feeStructure` values as long as `flatFee <= maxFee`.

### Recommendation
Include `circomData.relay` and the full `feeStructure` (feeToken, flatFee, variableRate) inside the `EMPORIUM_SIGNATURE_TYPEHASH` payload that `verifyWallet` hashes and recovers against, so the wallet owner's signature commits to exactly which relay address and which token/rate they authorized for fee payment.

### Proof of Concept
1. A wallet owner signs an `EmporiumStack` (`message`, `ops`, `maxFee=100`, `deadline`) intending to pay a flat fee of 100 units of `USDC` to the known Hinkal relay.
2. Before/while this signature is submitted, an attacker (acting as `msg.sender`/relay for the `Hinkal.transact` call) constructs `circomData` with `relay = attacker`, `feeStructure = {feeToken: WETH_held_by_wallet, flatFee: 100, variableRate: 0}`, and the previously observed `EmporiumStack` (same signature bytes) embedded in `externalActionData.externalActionMetadata`.
3. `runAction` → `verifyWallet` recovers the same signer address (since `relay`/`feeStructure` aren't part of the signed hash) and the check passes; `flatFee (100) <= maxFee (100)` also passes.
4. `payRelayFees` → `payRelay` → `sendToRelayFromWallet` → `IHinkalWallet(signerAddress).doSendToRelay(attacker, 100, WETH)` transfers 100 units of WETH from the wallet to the attacker's address instead of paying the intended relay in USDC.

    function payRelayFees(
        CircomData calldata circomData,
        address signerAddress,
        int256[] calldata deltaAmountChanges
    ) internal {
        FeeStructure calldata feeStructure = circomData.feeStructure;

        bool foundToken = false;

        for (uint256 i = 0; i < circomData.erc20TokenAddresses.length; i++) {
            // tokens deposited into Emporium are not charged
            if (deltaAmountChanges[i] >= 0) {
                continue;
            }

            address erc20TokenAddress = circomData.erc20TokenAddresses[i];
            bool isFeeToken = erc20TokenAddress == feeStructure.feeToken;

            if (isFeeToken) {
                foundToken = true;
            }

            uint256 relayFee = 0;
            uint256 flatFee = isFeeToken ? feeStructure.flatFee : 0;

            if (signerAddress == address(0)) {
                uint256 sumAbs = uint256(-deltaAmountChanges[i]);

                EmporiumStorageVars storage $ = _getEmporiumStorage();
                relayFee = $._hinkalHelper.calculateRelayFee(
                    sumAbs,
                    flatFee,
                    feeStructure.variableRate
                );
            } else {
                relayFee = flatFee;
            }

            payRelay(
                circomData.relay,
                signerAddress,
                relayFee,
                erc20TokenAddress
            );
        }

        if (!foundToken && feeStructure.flatFee != 0) {
            require(
                signerAddress != address(0),
                "Gas Token in Emporium is not found"
            );

            payRelay(
                circomData.relay,
                signerAddress,
                feeStructure.flatFee,
                feeStructure.feeToken
            );
        }
    }

    function verifyWallet(
        EmporiumStack memory stack,
        CircomData calldata circomData
    ) internal {
        EmporiumStorageVars storage $ = _getEmporiumStorage();

        if ($.usedMessages[circomData.emporiumMessage]) {
            revert UsedMessage();
        }

        $.usedMessages[circomData.emporiumMessage] = true;

        if (stack.signerAddress == address(0)) {
            return;
        }

        bytes32 hashedMessage = _hashTypedDataV4(
            keccak256(
                abi.encode(
                    EMPORIUM_SIGNATURE_TYPEHASH,
                    circomData.emporiumMessage,
                    _hashEmporiumOps(stack.ops),
                    stack.maxFee,
                    stack.deadline
                )
            )
        );

        (address recoveredAddress, ECDSA.RecoverError err) = ECDSA.tryRecover(
            hashedMessage,
            stack.v,
            stack.r,
            stack.s
        );
        bool verified = err == ECDSA.RecoverError.NoError &&
            recoveredAddress == stack.signerAddress;
        if (!verified) {
            revert InvalidSignature();
        }

        if (block.timestamp > stack.deadline) {
            revert SignatureExpired();
        }

        if (circomData.feeStructure.flatFee > stack.maxFee) {
            revert FeeExceedsSignedMax();
        }
    }
