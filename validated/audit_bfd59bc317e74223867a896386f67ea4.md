Confirmed: MessageID is fully client-supplied and signed only by the client's own key — nothing binds it to a particular sender when used as the lookup key for delivering DON responses back to callbacks.

### Title
Cross-user response hijacking via attacker-controlled `MessageID` collision in WebAPI Gateway legacy trigger handler - (File: core/services/gateway/handlers/capabilities/handler.go)

### Summary
The `WebAPIHandler`'s legacy trigger flow (`HandleLegacyUserMessage` / `handleWebAPITriggerMessage`) registers a pending callback keyed solely by the client-supplied `MessageBody.MessageID`, with no binding to the requesting client's identity (signer/session). Any authenticated caller who submits a message whose `MessageID` collides with another in-flight request's `MessageID` will silently overwrite that entry, causing the DON's eventual response for the victim's request to be delivered to the attacker's callback instead.

### Finding Description
`HandleLegacyUserMessage` stores the callback unconditionally: [1](#0-0) 
```
h.mu.Lock()
h.savedCallbacks[msg.Body.MessageID] = &savedCallback{id: msg.Body.MessageID, createdAt: time.Now(), Callback: callback}
```
There is no check for an existing entry, no uniqueness enforcement, and no tie to the caller's signer/sender. `Message.Validate()` only checks length/format of `MessageID`, `Method`, and `DonID`, and extracts a `Sender` from the signature, but that `Sender` is never compared against the entry when the response is later delivered: [2](#0-1) 

When a DON node later responds, `handleWebAPITriggerMessage` looks the callback up purely by `MessageID` and delivers the response to whichever callback is currently registered under that key, deleting the entry as it does so: [3](#0-2) 

If an attacker submits a new legacy trigger request using the exact same `MessageID` as a victim's still-pending request, the attacker's call to `HandleLegacyUserMessage` overwrites `h.savedCallbacks[MessageID]` with their own callback. When the node eventually replies for the original (victim) request with that `MessageID`, `handleWebAPITriggerMessage` finds the *attacker's* saved callback and forwards the victim's response payload to the attacker.

This is structurally analogous to the Onyx IDOR: an unprivileged/authenticated actor supplies an identifier (`MessageID` here, `file_id` in Onyx) that the internet-facing gateway trusts implicitly to route/authorize access to another party's data, without verifying that the identifier actually belongs to the requester.

### Impact Explanation
A successful collision lets an attacker capture the response content (including potentially sensitive computed data, target/action results) that a victim's workflow triggered — a cross-user response confusion issue matching "unauthorized access to another user's response data" through pure identifier guessing/collision, with no cryptographic binding of the message ID to its original signer at lookup time.

### Likelihood Explanation
Exploitability depends on the caller's ability to predict or brute-force a currently in-flight victim `MessageID` (up to 128 bytes) and win a race before the legitimate DON response arrives (`CallbackMaxAgeSec` defaults to 120s, giving a sizeable window): [4](#0-3) 
If callers (e.g., workflow clients) use low-entropy or sequential `MessageID`s, this becomes practically exploitable; if IDs are high-entropy UUIDs generated client-side, likelihood is lower but the lack of any server-side ownership check remains a design weakness, not a defense.

### Recommendation
Bind each `savedCallback` entry to the originating signer/sender (already computed by `Message.Validate()` via `ExtractSigner`), and verify that the sender delivering/receiving a response matches the sender who created the pending entry. Additionally, reject registration of a `MessageID` that already has an active, non-expired callback rather than silently overwriting it (as `HandleNodeMessage` in the dummy handler already does with a sender comparison, which the real `handler.go` implementation lacks for legacy messages).

### Proof of Concept
1. Victim submits a legacy WebAPI trigger request signed with their key, with `Body.MessageID = "X"`. `HandleLegacyUserMessage` stores `savedCallbacks["X"] = victimCallback` and forwards to DON nodes.
2. Before the DON responds, Attacker (any other authenticated/allow-listed submitter able to reach the gateway) submits their own legacy message also using `Body.MessageID = "X"` (their own valid signature over that same ID is accepted since `MessageID` is attacker-chosen). This overwrites `savedCallbacks["X"] = attackerCallback`.
3. The DON node completes the victim's original request and replies referencing `MessageID = "X"`. `handleWebAPITriggerMessage` looks up `savedCallbacks["X"]`, finds the attacker's callback (since it was overwritten), deletes the entry, and sends the victim's response payload to the attacker via `attackerCallback.SendResponse(...)`. [3](#0-2)

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageID]
	delete(h.savedCallbacks, msg.Body.MessageID)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JSONRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageID) == 0 || len(m.Body.MessageID) > MessageIDMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageID, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonID) == 0 || len(m.Body.DonID) > MessageDonIDMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonID, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}
