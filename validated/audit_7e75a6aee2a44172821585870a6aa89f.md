### Title
Simplex Uniswap V4 venue pricing consumes an unbuffered, manipulable spot price to size solver fills - ([File: sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts])

### Summary
The Allbridge report shows an attacker atomically inflating/collapsing a pool's internal balance ratio (via `deposit`/`withdraw`) inside a single transaction and then using that manufactured, momentarily-favorable rate through the bridge's swap function to extract value the pool never actually held. The reachable analog in this codebase is Simplex's Uniswap V4 "venue pricing" path for curveless pairs: it reads the **current, single-block spot price** (`sqrtPriceX96` → `token0Price`/`token1Price`) straight off a live Uniswap V4 pool and uses it, essentially unmodified, to size how much of the exotic token the solver will hand over for a filled intent.

### Finding Description
For a curveless pair whose `token0` is a USD stablecoin, `FXFiller.resolveLegRates` (`sdk/packages/simplex/src/strategies/fx.ts:1443-1466`) prices the leg entirely from `venueUsdPrice`, which resolves to `UniswapV4FundingPlanner.getExoticTokenPrice` → `computeDirectPoolPriceUsd` (`sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts:206-275`). That function returns `sdkPool.token0Price`/`token1Price` computed directly from the position's live `sqrtPriceX96`, refreshed just before pricing (`UniswapV4LiquidityState.refresh`, `sdk/packages/simplex/src/funding/uniswapV4/UniswapV4LiquidityState.ts:139-229`). There is no TWAP/oracle read anywhere in the package (confirmed by the absence of any `observe`/TWAP usage outside an unrelated ABI file), and the flow documentation itself states plainly: "`computeDirectPoolPriceUsd` returns the **raw pool mid** derived from `sqrtPriceX96`... there is no size or impact term" (`sdk/packages/simplex/docs/ai/flows/venue-pricing-uniswap-v4-funded-pairs.md:17-22`).

The only mitigation is `checkPriceGuard` (`sdk/packages/simplex/src/strategies/fx.ts:428-448`), which compares the live venue quote to a **static, operator-configured** `referencePrice` within `maxDeviationBps`. This guard is explicitly optional — `referencePrice`/`maxDeviationBps` may be omitted entirely, leaving the chain "unguarded" (`docs/content/developers/evm/simplex/pricing.mdx:72`, `sdk/packages/simplex/src/config/filler-toml.ts:413-424`). Even when configured, the guard only bounds deviation from a fixed number the operator chose at setup time; it does nothing to detect that the quote it is checking was itself produced by a swap the attacker just executed in the pool moments earlier. Because the pool is a public, permissionless Uniswap V4 pool (not something the solver custodies exclusively), any actor can move `sqrtPriceX96` with an ordinary swap immediately before submitting (or having a filler observe) the order, exactly as the Allbridge attacker moved `tokenBalance`/`vUsdBalance` before invoking `BridgeSwap.swap`.

### Impact Explanation
If a pair is configured without a price guard (a documented, supported configuration), an attacker can swap against the referenced Uniswap V4 pool to push its spot price to any level the pool's depth allows, then place/trigger an intent order sized against that transiently manipulated quote. `resolveLegRates`/`computeLegPolicyOutput` uses that rate essentially unconditionally to determine the payout amount, and the solver funds the fill by withdrawing liquidity from its own V4 position (`UniswapV4FundingPlanner.planWithdrawalForToken`) to cover the deficit. This lets an attacker cause the solver to deliver exotic tokens (or accept input) at a price far from fair value, draining solver-held funds — a direct theft of solver liquidity, matching the fund-loss class of the Allbridge exploit. Even with a guard configured, its static-reference check does not account for in-block manipulation, only for drift from a preset number; a stale/loosely-set reference still allows manipulated fills within the configured band that are unprofitable to the solver.

### Likelihood Explanation
Uniswap V4 pools referenced by `[vault.uniswapV4]` positions are public and permissionless; no admin, governance, or privileged role is required to move their price — a plain swap suffices, and the codebase confirms no TWAP or impact-aware pricing is used anywhere in this path. The guard is opt-in per-chain/per-position, and the docs frame the unguarded state as a normal, supported deployment choice ("omit both to leave the chain unguarded"), making this reachable by any operator's default or partial configuration and directly exploitable by any unprivileged actor who can execute a swap and place/trigger an order in the same window.

### Recommendation
Replace or supplement the raw spot-price read with a manipulation-resistant price (e.g., a TWAP over multiple blocks/observations, or a cross-check against an external oracle) before it is used to size fills. Make the price guard mandatory whenever venue pricing is enabled (reject startup instead of allowing an unguarded position), and additionally bound the maximum price impact/size the fill can be sized against relative to the pool's available depth, so a single-block price move cannot be monetized through a fill.

### Proof of Concept
Conceptual, mirroring the Allbridge pattern (exact numeric PoC would need the real Base mainnet CNGN/USDC V4 pool state used in `fx.mainnet.test.ts`):
1. Attacker identifies a Simplex-configured `[vault.uniswapV4]` position pricing a curveless pair (e.g. USDC/CNGN) with no `referencePrice`/`maxDeviationBps` set, or with a stale reference.
2. Attacker performs a large swap against that same Uniswap V4 pool, moving `sqrtPriceX96` so `computeDirectPoolPriceUsd` will return a USD price for the exotic token far below its real market value.
3. In the same block/window, attacker (or an accomplice acting as the order's counterparty) submits an intent order that FXFiller prices via `resolveLegRates`'s venue path; `checkPriceGuard` either does not exist for that chain or the deviation is small enough to pass because the reference itself is stale.
4. FXFiller fills the order using `UniswapV4FundingPlanner.planWithdrawalForToken`, withdrawing far more exotic-token value from its LP position than the input it received is worth.

	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}

	/**
	 * Computes the USD price of the non-stable token in a pool.
	 * Returns null if neither currency is USDC/USDT on this chain.
	 */
	private computeDirectPoolPriceUsd(
		pos: HydratedV4Position,
		sdkPool: V4Pool,
		chain: string,
	): { exoticToken: string; priceUsd: Decimal } | null {
		const usdc = this.configService.getUsdcAsset(chain).toLowerCase()
		const usdt = this.configService.getUsdtAsset(chain).toLowerCase()
		const c0 = pos.currency0.toLowerCase()
		const c1 = pos.currency1.toLowerCase()

		if (c0 === usdc || c0 === usdt) {
			// currency0 is stable → exotic is currency1
			// token1Price = "token0 per token1" = USD per exotic
			return {
				exoticToken: c1,
				priceUsd: new Decimal(sdkPool.token1Price.toFixed(18)),
			}
		}

		if (c1 === usdc || c1 === usdt) {
			// currency1 is stable → exotic is currency0
			// token0Price = "token1 per token0" = USD per exotic
			return {
				exoticToken: c0,
				priceUsd: new Decimal(sdkPool.token0Price.toFixed(18)),
			}
		}

		return null
	}

	/**
	 * Validates a live venue quote against the static reference price for the chain.
	 * Returns true (pass) when no guard is configured, or no reference exists for the
	 * chain. Returns false when the quote (token1 per USD) deviates from the reference
	 * by more than `maxDeviationBps`, in which case the order must not be filled.
	 */
	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {
			this.logger.warn(
				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
	}

```
resolveLegRates(...)
  curveless pair && token0 is a USD stable
    -> venuePriceMemo() -> getVenueUsdPrice(chain, token1)
         -> UniswapV4FundingPlanner.getExoticTokenPrice
              picks the position with the largest pool liquidity
              -> computeDirectPoolPriceUsd -> sdkPool.token0Price / token1Price
    -> checkPriceGuard(...)   reject if outside maxDeviationBps of the static reference
    -> rate = 1 / venueUsd
  otherwise -> the pair's ask/bid curve at the leg's notional
```

`computeDirectPoolPriceUsd` returns the **raw pool mid** derived from `sqrtPriceX96`. The pool's
fee tier is read and stored on the hydrated position (`pos.fee`) but never applied to the price,
and there is no size or impact term — `computeLegPolicyOutput` extends the mid linearly across the
whole priced quantity. `checkPriceGuard` is the only defense on this path, and it checks deviation
from a static reference, not execution cost. A venue-priced pair that has to swap through its own
pool to source inventory pays a fee tier it never quoted against.

## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.

```toml lineNumbers
[vault.uniswapV4]
# referencePrice is the expected cNGN per USD;
# reject if the quote is more than 2% off.
# The two go together — one without the other is rejected.
[[vault.uniswapV4.positions]]
chain           = "EVM-8453"
tokenId         = "2087350"
referencePrice  = "1575"
maxDeviationBps = 200
```
