### Title
Insolvent accounts evade permissionless bad-debt cleanup by keeping collateral above the $5 dust gate - (File: contracts/controller/src/positions/liquidation/curve.rs)

### Summary
The reported class is an unlock transition keyed to the wrong, actor-controlled condition: tokens that should release on an aggregate/time condition stay locked while a per-holder counter stays below a threshold, and the very party harmed by the transition controls that counter. XOXNO Lending has the same shape in bad-debt socialization. `clean_bad_debt` is the only permissionless path that writes off insolvency, but `is_socializable_bad_debt` admits an account only when `total_debt > total_collateral` **and** `total_collateral <= BAD_DEBT_USD_THRESHOLD` ($5 WAD) — the debtor can hold a small amount of collateral above $5 and the gate stays shut indefinitely, even though the economically correct condition (insolvency) already holds.

### Finding Description
`contracts/controller/src/positions/liquidation/mod.rs` gates the permissionless entrypoint on `BadDebtGate::DustCapped`, which evaluates `is_socializable_bad_debt(totals.total_debt, totals.total_collateral)` — `total_debt > total_collateral && total_collateral <= $5` in `curve.rs`. The same predicate runs inside the post-liquidation hook `check_bad_debt_after_liquidation` in `apply.rs`, so neither standalone cleanup nor the automatic cleanup-after-liquidation fires for a straddled account.

The straddle is cheap and permissionless: the debtor (or anyone) can call `supply` on the insolvent account, which by design can only top up assets the account already holds but needs no health check, pushing `total_collateral` a cent above $5. The Certora spec itself encodes the straddle: `bad_debt_straddle_blocks_dust_gate` notes an attacker "must post value above the threshold and keep it there" to block the dust gate while staying insolvent.

The gate fails precisely where it is needed most. Once `total_collateral > total_debt` is impossible, ordinary liquidation is the fallback — but the debtor's incentive is inverted: cleanup reclassifies **all** remaining collateral as revenue, so the debtor is motivated to keep the account straddled forever. And liquidation is not guaranteed to work: INV-LIQ-02 documents a dead band for whole-unit sub-3-decimal collateral legs where "every offer reverts until accrual or a price move ends that state," and `no_seize` flags or transfer-restricted (allowlisted) collateral block seizure entirely. In those states the only remaining resolution is `force_socialize_bad_debt`, an owner-only Sensitive-tier governance operation — i.e., the transition the protocol needs is locked behind an account-controlled condition, exactly like tokens that only unlock when the holder undelegates.

Meanwhile the debt keeps accruing on the borrow index, the unbacked portion grows, and the eventual write-down lands on suppliers via the supply-index haircut.

### Impact Explanation
Temporary freezing of funds / growing protocol insolvency. An insolvent account that cannot be liquidated (dead band, `no_seize`, or non-transferable collateral) and that is held above the $5 dust gate can never be cleaned up permissionlessly. Its debt continues compounding against the borrow index while collateral stays fixed, so the supplier-borne shortfall increases until governance executes the delayed forced path — which the runbook acknowledges requires a Sensitive-tier timelock and can be pre-empted by the debtor re-straddling after each accrual.

### Likelihood Explanation
Medium. The straddle costs only ~$5+ε of collateral held in the account, is reachable by any unprivileged address through the ordinary `supply` entrypoint (third-party supply to existing slots is explicitly permitted by INV-AUTH-03), and is directly incentivized because cleanup confiscates the debtor's residual collateral. It requires a state where liquidation is ineffective, which the codebase itself documents as reachable (whole-unit dead band, `no_seize`, gated collateral).

### Recommendation
Decouple the socialization condition from the debtor-controllable collateral level. Options: admit permissionless cleanup on insolvency alone once ordinary liquidation has been provably ineffective (e.g., after a failed-seizure or dead-band state), or cap the reclassifiable collateral so the dust gate measures only collateral that seizure could actually reach. At minimum, prevent `supply` top-ups to an already-insolvent account from re-opening the straddle after the gate has once been satisfiable.

### Proof of Concept
1. Alice supplies 100 USDC, borrows ETH; price crash leaves D = $12,000 > C = $10,000 (see `deep_underwater_account_still_liquidates_to_the_dust_gate` in `tests/test-harness/tests/controller/bad_debt_netting_and_exit_timing.rs`, which already asserts `clean_bad_debt` reverts `CANNOT_CLEAN_BAD_DEBT` at $10k collateral).
2. Put the account in a non-liquidatable state: `no_seize` on the collateral asset, or a whole-unit sub-3-decimal collateral leg inside the documented dead band.
3. Any unprivileged caller invokes `clean_bad_debt(caller, account_id)` → `CannotCleanBadDebt`, because `is_socializable_bad_debt` returns false at `total_collateral > $5` (`curve.rs:25-27`, `mod.rs:229-235`).
4. The account persists, debt accrues, supplier write-down grows; only `force_socialize_bad_debt` via delayed governance resolves it — and the debtor can re-straddle by topping up supply before execution.
