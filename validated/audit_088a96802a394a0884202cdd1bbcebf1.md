### Title
A borrower can plant an unpriceable dust collateral leg that blocks liquidation, bad-debt cleanup, and withdrawals - ([File: contracts/controller/src/positions/supply.rs])

### Summary
`supply` accepts a new listed collateral position without proving that the asset has a currently usable oracle price, while liquidation and bad-debt cleanup value every supply and borrow position through `calculate_account_risk_totals`. [1](#0-0) [2](#0-1)  A borrower can therefore add a dust position whose feed is stale or whose Aquarius LP value is below `min_pool_value_wad`; once the account becomes unhealthy, the bad leg makes the whole risk calculation fail. [3](#0-2) [4](#0-3) 

### Finding Description
`process_supply` performs entry-gate checks, transfers the supplied tokens to the pool, and persists the resulting supply position, but it does not require a successful strict price resolution for a newly created leg. [5](#0-4)  In contrast, `build_liquidation_plan` calls `calculate_account_risk_totals` before accepting a liquidation. [6](#0-5)  That function loads every supply and debt market and dereferences the cached price for each leg, so one unavailable collateral price aborts the entire account valuation. [7](#0-6)  `clean_bad_debt` uses the same all-position risk calculation before deciding whether socialization is allowed. [8](#0-7)  The repository’s regression test demonstrates that a stale WBTC price does not prevent `supply`, but later causes `liquidate`, `clean_bad_debt`, and even withdrawal of the poisoned leg to fail with `PRICE_FEED_STALE`. [4](#0-3) 

### Impact Explanation
An underwater borrower can delay liquidation and permissionless bad-debt cleanup while interest continues accruing, increasing the probability that the account becomes protocol bad debt. [6](#0-5) [9](#0-8)  The same malformed-position state also blocks the borrower from removing the dust leg, so collateral remains temporarily frozen until the oracle becomes usable again. [10](#0-9)  For an Aquarius LP collateral asset, the borrower or another liquidity provider can actively trigger this outage by reducing pool value below `min_pool_value_wad`, causing `InsufficientAquariusLiquidity`. [11](#0-10) 

### Likelihood Explanation
The attack requires only ordinary `supply` authorization and a listed collateral whose oracle can become unavailable, stale, or below its configured liquidity floor. [12](#0-11) [13](#0-12)  The cost is a dust-sized collateral deposit, and the shield persists only while that leg’s price remains unusable. [14](#0-13) [15](#0-14) 

### Recommendation
Require a successful strict price resolution before creating a new supply position, while still permitting top-ups of an existing leg and risk-reducing exits. [1](#0-0)  Add a regression covering a newly supplied stale or below-floor LP leg followed by `liquidate`, `clean_bad_debt`, and `withdraw`. [10](#0-9) 

### Proof of Concept
1. Supply sufficient USDC collateral and borrow ETH so the account is initially healthy. [16](#0-15) 
2. Make WBTC’s configured feed stale, then call `supply` with a dust WBTC amount; the call succeeds and records a nonzero supply position. [17](#0-16) 
3. Move USDC’s price down so the account becomes liquidatable, as demonstrated by an equivalent account without the poisoned leg. [18](#0-17) 
4. Call `liquidate` and `clean_bad_debt` on the poisoned account; both fail with `PRICE_FEED_STALE`, and `withdraw` of the WBTC dust also fails. [19](#0-18) 
5. Restore the WBTC price; the same liquidation then succeeds, proving the dust leg’s unavailable price caused the outage. [15](#0-14)

/// Checks supply entry gates and credits measured pool receipts.
pub(crate) fn process_deposit(
    env: &Env,
    caller: &Address,
    account: &mut Account,
    aggregated: &AggregatedPayments,
    cache: &mut Context,
) {
    validate_position_entry_gates(
        env,
        account,
        aggregated,
        cache,
        AccountPositionType::Deposit,
    );
    let pool_addr = cache.cached_pool_address();
    let mut entries: Vec<PoolSupplyEntry> = Vec::new(env);
    for (hub_asset, amount_in) in aggregated.iter() {
        let asset_config: AssetConfig = cache.require_spoke_asset(account.spoke_id, &hub_asset);
        let received = payments::transfer_amount_measured(
            env,
            &hub_asset.asset,
            caller,
            &pool_addr,
            amount_in,
            GenericError::AmountMustBePositive,
        );
        let position = account.get_or_create_supply_position(&hub_asset, &asset_config);
        entries.push_back(PoolSupplyEntry {
            action: make_pool_action(&position, received, hub_asset.clone()),
        });
    }

    let results = pool_supply_call(env, &pool_addr, &entries);
    for_each_leg(env, &entries, &results, |entry, result| {
        merge_supply_leg(env, account, &entry.action, &result, cache);
    });

/// Requires open debt and the selected insolvency gate, then cleans up the account.
fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    bad_debt::execute_bad_debt_cleanup(env, &mut cache, account_id, &account, &totals);
