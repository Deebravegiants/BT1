#No Vulnerability found for this question.

**Analysis:** The premise of this question misreads the data structure in `StorageFormatLegacyBuilder.addMany` (`features/public-key-provider/module/store/formats/storage/legacy.ts`, lines 48-64). `chain` is not a sibling field at the same object level as `derivationPath` keys — it is a property *inside* the value object assigned at `publicKeys[keyIdentifier.derivationPath]`:

```
publicKeys[keyIdentifier.derivationPath] = {
  ...(key.publicKey ? { publicKey: key.publicKey } : {}),
  ...(key.xpub ? { xpub: key.xpub } : {}),
  chain: [0, 0, 0],
}
``` [1](#0-0) 

A `derivationPath` equal to the literal string `'chain'` simply becomes an ordinary key in the `publicKeys` map (`Record<DerivationPath, PublicKeyWithMetaData>`), exactly like any other derivation path string such as `m/44'/0'/0'`. There is no reserved top-level `chain` field at that level to collide with — `chain` only exists nested per-entry, so this cannot clobber sibling metadata as the question describes. [2](#0-1) 

Regarding cross-entry/account collision: each `walletAccountName` has its own isolated `publicKeys` map (`this.#data[walletAccountName]`), so a colliding `derivationPath` only overwrites another key for the *same* wallet account — which is the intended update semantics of `addMany`, not cross-account corruption. [3](#0-2) 

As for `__proto__` as a `derivationPath`: when `this.#data[walletAccountName]` doesn't yet exist, `publicKeys` is created via `Object.create(null)`, so a bracket assignment with key `'__proto__'` sets a genuine own property named `"__proto__"`, not a prototype override, since there is no inherited accessor. [4](#0-3)  When `this.#data[walletAccountName]` already exists, it originates from `clone(data)` (`JSON.parse(JSON.stringify(data))`), a normal object with `Object.prototype` in its chain, so assigning to key `'__proto__'` would trigger the accessor and rebind that single object's internal prototype — but since `serialize()` re-clones via `JSON.stringify`/`JSON.parse`, only *own* enumerable properties survive, so the injected data doesn't persist as a readable entry and no other account's or path's own data is overwritten. This results in a silent no-op/self-inflicted loss of the attacker's own inserted key at most, not corruption of legitimate stored metadata, and does not touch global `Object.prototype`. [5](#0-4) 

Given this, the specific exploit chain described (collision with a reserved `chain` sibling field, or clobbering another account's stored derivationPath entry) is not supported by the actual object shape and serialization behavior in this file.

  addMany = async ({ walletAccountName, keys }: AddManyParams) => {
    assert(typeof walletAccountName === 'string', 'walletAccountName must be string')
    const publicKeys = this.#data[walletAccountName] ?? Object.create(null)

    keys.forEach((key) => {
      const keyIdentifier = new KeyIdentifier(key.keyIdentifier)

      assert(key.publicKey || key.xpub, 'publicKey or xpub must be defined')
      publicKeys[keyIdentifier.derivationPath] = {
        ...(key.publicKey ? { publicKey: key.publicKey } : {}),
        ...(key.xpub ? { xpub: key.xpub } : {}),
        chain: [0, 0, 0],
      }
    })

    this.#data[walletAccountName] = publicKeys
  }
