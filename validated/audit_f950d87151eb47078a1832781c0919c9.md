### Title
Unbounded in-memory `BidCache` growth from mempool `place_bid` extrinsics enables node memory-exhaustion DoS - (File: modules/pallets/intents-coprocessor/rpc/src/lib.rs)

### Summary
The Django CVE-2023-23969 analog is a size-unbounded cache populated from unauthenticated, attacker-controlled input. `run_bid_watcher` in `modules/pallets/intents-coprocessor/rpc/src/lib.rs` watches the transaction pool for `place_bid` extrinsics and inserts their contents into an in-process `BidCache` keyed by order commitment [1](#0-0) . Any unprivileged account can submit arbitrary numbers of signed `place_bid` extrinsics to the public mempool without them ever being included in a block, and each one is cached — with no cap on distinct commitments, no cap on distinct fillers per commitment, and no cap on the size of the attacker-supplied `user_op` bytes.

### Finding Description
`BidCache` is a `HashMap<H256, OrderBids>` guarded only by a time-based eviction (`remove_expired`, run on a periodic timer) — there is no maximum entry count and no maximum payload size enforced anywhere in the cache path [2](#0-1) .

Every transaction-pool import that decodes as a `place_bid` call is unconditionally inserted: [3](#0-2) 

`extract_bid` pulls `commitment`, the signer-derived `filler`, and the full `user_op` bytes straight out of the extrinsic with no length bound applied before caching [4](#0-3) . The only gate before insertion is that the extrinsic decodes as a signed `place_bid` call and is currently "ready" in the pool (`pool.ready_transaction`) — it does not need to ever be included in a block, pay a meaningful tip, or survive past the tx-pool's own retention window, since the RPC-side `BidCache` retains it for the full configured `ttl` (5 minutes in the shipped test constant) regardless of what the tx pool itself does with it [5](#0-4) .

An attacker (any account able to sign and broadcast a transaction, including a `place_bid` call whose associated order/commitment need not even be real) can therefore:
1. Submit many distinct fake commitments, each becoming a new `HashMap` entry that lives for the full `ttl`.
2. For a single commitment, submit many distinct filler-signed bids (`order.entries.push`), since the dedup only collapses entries with the exact same `filler` [6](#0-5) .
3. Pad each bid's `user_op` field to a large size, since `pallet_intents_coprocessor::Call::place_bid`'s `user_op` is copied into the cache as raw `Vec<u8>` with no length check visible in this file.

Because insertion happens off the back of transaction-pool import notifications (not block execution), this is far cheaper for the attacker than getting transactions included on-chain, and it runs unconditionally for every full/RPC node running this watcher — unlike `pallet_call_decompressor`, which does bound decompressed call size against `MaxCallSize` before use in a different, unrelated code path [7](#0-6) , no equivalent bound exists for `BidCache`.

### Impact Explanation
This is the same bug class as CVE-2023-23969: an unbounded, time-only-evicted cache populated from attacker-controlled request data leads to uncontrolled memory consumption (CWE-400/CWE-770). Sustained mempool spam of `place_bid` extrinsics can grow the RPC node's `BidCache` without bound within any `ttl` window, exhausting memory on nodes serving `intents_getBidsForOrder`/`intents_subscribeBids`, degrading or crashing the relayer/solver-facing RPC service that intent solvers depend on for sub-second bid discovery. This does not directly cause loss of funds or forged state, but it can render the bid-discovery route unable to deliver information to solvers, which the scan's validation criteria treats as a qualifying "route unable to deliver messages" condition for the affected service.

### Likelihood Explanation
High likelihood: `place_bid` is a normal signed extrinsic reachable by any account; the watcher processes every extrinsic that is merely "ready" in the pool, not one that has been included in a block, so an attacker pays only ordinary transaction-pool validation costs (and possibly nothing if the call is cheap/free to construct and gets evicted from the pool later while already cached). No special privileges, timing, or races are required.

### Recommendation
Bound `BidCache` on multiple axes independent of the TTL-based sweep: (1) cap the total number of distinct commitments tracked (e.g., LRU/bounded map with eviction on insert, not only on the periodic timer), (2) cap the number of distinct fillers per commitment, and (3) cap/reject `user_op` (and `filler`) byte lengths before insertion, mirroring the `MaxCallSize` style bound used in `pallet_call_decompressor::decompress` [8](#0-7) . Consider also rate-limiting cache insertions per source account/signer to prevent one account from filling the cache via many distinct fake commitments.

### Proof of Concept
1. Run a Hyperbridge node exposing the intents-coprocessor RPC watcher (`run_bid_watcher`).
2. From an unprivileged account, repeatedly submit signed `place_bid` extrinsics to the node's mempool, each with a distinct random `commitment` and a `user_op` padded to a large size (e.g., tens of KB), keeping the extrinsics valid enough to remain "ready" in the pool.
3. Observe `run_bid_watcher`'s `bid_cache.insert(...)` call executing for every submission [9](#0-8) , growing the `HashMap<H256, OrderBids>` inside `BidCache` without any size cap other than the time-based `remove_expired` sweep.
4. Repeat submissions faster than the `ttl`/`cleanup_interval` window to keep the cache growing, driving the RPC node's memory usage up until it is degraded or OOM-killed.

#[derive(Clone, Debug)]
struct BidEntry {
	filler: Vec<u8>,
	user_op: Vec<u8>,
}

#[derive(Clone, Debug)]
struct OrderBids {
	first_seen: Instant,
	entries: Vec<BidEntry>,
}

/// In-memory bid cache.
pub struct BidCache {
	bids: RwLock<HashMap<H256, OrderBids>>,
	ttl: Duration,
}

impl BidCache {
	pub fn new(ttl: Duration) -> Self {
		Self { bids: RwLock::new(HashMap::new()), ttl }
	}

	pub fn insert(
		&self,
		commitment: H256,
		filler: Vec<u8>,
		user_op: Vec<u8>,
	) -> Result<(), String> {
		let entry = BidEntry { filler: filler.clone(), user_op };

		let mut bids = self.bids.write().map_err(|e| format!("BidCache lock poisoned: {e}"))?;
		let order = bids
			.entry(commitment)
			.or_insert_with(|| OrderBids { first_seen: Instant::now(), entries: Vec::new() });
		if let Some(existing) = order.entries.iter_mut().find(|e| e.filler == filler) {
			*existing = entry;
		} else {
			order.entries.push(entry);
		}
		Ok(())
	}

pub fn extract_bid<T, Extra>(encoded: &[u8]) -> Option<(H256, Vec<u8>, Vec<u8>)>
where
	T: pallet_intents_coprocessor::Config,
	T::RuntimeCall: frame_support::traits::IsSubType<pallet_intents_coprocessor::Call<T>>
		+ DecodeWithMemTracking,
	T::AccountId: Encode + From<[u8; 32]> + DecodeWithMemTracking,
	Extra: DecodeWithMemTracking,
{
	let xt = sp_runtime::generic::UncheckedExtrinsic::<
		sp_runtime::MultiAddress<T::AccountId, ()>,
		T::RuntimeCall,
		sp_runtime::MultiSignature,
		Extra,
	>::decode(&mut &encoded[..])
	.ok()?;

	let filler = match &xt.preamble {
		sp_runtime::generic::Preamble::Signed(address, _, _) => match address {
			sp_runtime::MultiAddress::Id(id) => id.encode(),
			_ => return None,
		},
		_ => return None,
	};

	match xt.function.is_sub_type()? {
		pallet_intents_coprocessor::Call::place_bid { commitment, user_op } =>
			Some((commitment.clone(), filler, user_op.to_vec())),
		_ => None,
	}
}

/// notifying subscribers as they arrive. Also periodically cleans up expired
/// cache entries.
///
/// Generic over the runtime config `T` and signed extensions `Extra`.
pub async fn run_bid_watcher<P, Block, T, Extra>(
	pool: Arc<P>,
	bid_cache: Arc<BidCache>,
	bid_sender: broadcast::Sender<RpcBidInfo>,
	cleanup_interval: Duration,
) where
	Block: BlockT,
	P: TransactionPool<Block = Block> + 'static,
	T: pallet_intents_coprocessor::Config,
	T::RuntimeCall: frame_support::traits::IsSubType<pallet_intents_coprocessor::Call<T>>
		+ DecodeWithMemTracking,
	T::AccountId: Encode + From<[u8; 32]> + DecodeWithMemTracking,
	Extra: DecodeWithMemTracking + Send + 'static,
{
	use futures::StreamExt;

	let mut stream = pool.import_notification_stream();
	let mut timer = tokio::time::interval(cleanup_interval);

	loop {
		tokio::select! {
			Some(tx_hash) = stream.next() => {
				let tx = match pool.ready_transaction(&tx_hash) {
					Some(tx) => tx,
					None => continue,
				};

				let extrinsic_bytes = tx.data().encode();

				if let Some((commitment, filler, user_op)) = extract_bid::<T, Extra>(&extrinsic_bytes) {

						"bid in mempool for {commitment:?}",

						log::warn!(target: LOG_TARGET, "failed to cache bid: {e}");
						continue;
					}

					let _ = bid_sender.send(RpcBidInfo { commitment, filler, user_op });

		// and have a tiny zstd "bomb" expanded to gigabytes during transaction-pool
		// validation, before any size check. Enforcing it here protects both paths.
		ensure!(encoded_call_size < T::MaxCallSize::get() * ONE_MB, Error::<T>::CallSizeOutOfBound);

		let mut decoder = StreamingDecoder::new(compressed_bytes.as_slice())
			.map_err(|_| Error::<T>::DecompressionFailed)?;

		let claimed = encoded_call_size as usize;
		let mut result = Vec::new();
		let mut chunk = vec![0u8; 4096];

			let n = decoder.read(&mut chunk).map_err(|_| Error::<T>::DecompressionFailed)?;
			if n == 0 {
				break;
			}
			if result.len() + n > claimed {
				return Err(Error::<T>::DecompressionFailed.into());
			}
			result.extend_from_slice(&chunk[..n]);
		}

		ensure!(result.len() == claimed, Error::<T>::DecompressionFailed);
