### Title
Attacker can permanently evict a victim's paid bandwidth subscription by flooding its `(app_chain, app)` FIFO queue — ([File: modules/pallets/bandwidth/src/lib.rs])

### Summary
`BandwidthManager.purchase()` is a fully permissionless entry point on any EVM chain: any caller can pay the tier price and credit *any* `(chain, app)` pair of their choosing. [1](#0-0)  On the Hyperbridge side, `pallet-bandwidth` appends every credited purchase to a bounded, capped-at-1024 FIFO list keyed by `(app_chain, app)`, and evicts the oldest entry once the list is full — including entries paid for by someone else. [2](#0-1)  This mirrors the OpenQ report's bug class: an unprivileged attacker filling a small, shared, per-key resource limit to grief a specific legitimate user's slot.

### Finding Description
`purchase()` takes an arbitrary `app` (recipient identifier) and `chain` (credit chain) supplied entirely by the caller, with no relationship to `msg.sender` or the source chain enforced — this "sponsorship" model is explicit and by design. [1](#0-0)  The only pallet-side authorization check is that the message came from the registered `BandwidthManager` contract for its source chain — nothing gates *which app or chain* is being credited. [3](#0-2) 

`Allowance` stores subscriptions in a `BoundedVec<Subscription, MaxSubscriptions>` capped at 1024 per `(app_chain, app)` key. [4](#0-3)  `push_subscription` unconditionally evicts index 0 (the oldest entry, FIFO) whenever the list is already at cap, regardless of who paid for that entry or how much of its `remaining_bytes` is unused: [5](#0-4) 

Because `app`/`chain` are attacker-controlled and any account can call `purchase()` for the cheapest configured tier, an attacker can:
1. Determine a victim `(app_chain, app)` pair that currently holds one or more paid, unexpired subscriptions.
2. Submit up to 1024 cheap tier purchases targeting that exact `(app_chain, app)` pair.
3. Once the list reaches the 1024 cap, each further attacker purchase evicts the oldest entry — eventually evicting the victim's legitimately paid subscription(s), which are permanently and silently lost (`SubscriptionEvicted` explicitly documents `lost_bytes` as "what the user paid for and won't get to use"). [6](#0-5) 

This is functionally identical to the OpenQ pattern: a shared, attacker-reachable, capacity-limited list keyed by an identifier the victim doesn't control access to, which an attacker can pre-fill (or flood) to force out a legitimate, already-paid-for entry.

### Impact Explanation
A successful attack permanently destroys prepaid bandwidth that a legitimate app paid real fee-token value for — the evicted subscription's `remaining_bytes` are gone with no refund path (only governance's `force_credit`/`dispatch_withdraw` exist, and those don't compensate the victim automatically). [7](#0-6)  Once bandwidth is exhausted/evicted, `BandwidthGate::try_consume` will reject the victim app's ISMP dispatches on the router until it repurchases, which is a concrete loss of funds combined with denial of the app's cross-chain messaging capability — this satisfies "concrete theft or permanent freezing of funds" for the affected app's paid capacity.

### Likelihood Explanation
The attack requires no special privilege — `purchase()` is open to any caller and any `(app, chain)` pair is entirely attacker-supplied. [8](#0-7)  The cost is bounded by `1024 × cheapest_tier_price` in fee-token terms plus 1024 dispatch/gas costs — non-trivial, but a fixed, known, and attacker-controlled cost with no protocol-side rate limiting or per-payer/per-app quota preventing one account (or many colluding accounts) from filling a specific victim's queue. Targeting is deterministic since `(app_chain, app)` is public information observable from `BandwidthCredited`/`PurchaseMessage` events.

### Recommendation
- Do not evict indiscriminately by FIFO position alone; consider scoping subscriptions or eviction eligibility by payer/source, or require the evicting purchase to originate from an already-associated payer/source chain for that `(app_chain, app)`.
- Alternatively, bound eviction to same-payer entries, or require newly pushed subscriptions from a previously-unseen payer to fail (rather than evict) once the list is full, surfacing an explicit error the buyer can react to.
- Consider raising `MAX_SUBSCRIPTIONS` cost-of-attack (e.g., minimum tier price floor) or adding a per-`(app_chain, app)` purchase-source diversity check so an attacker can't cheaply dominate one victim's queue.
- Emit/allow querying "at risk of eviction" state so victims can top up before real loss occurs.

### Proof of Concept
1. Governance configures a cheap `TierIndex` (e.g., minimal `bytes`/`duration_secs`) with a small tier price on `BandwidthManager.sol` via `set_tier` + `dispatch_set_tiers`. [9](#0-8) 
2. Victim app buys legitimate bandwidth: `BandwidthManager.purchase(victimApp, tier, months, victimChain)`, crediting `Allowance[victimChain][victimApp]` with one `Subscription`. [8](#0-7) 
3. Attacker repeatedly calls `purchase(victimApp, cheapestTier, 1, victimChain)` 1024 times (any account, any source chain, since `app`/`chain` are caller-chosen and unrelated to `msg.sender`).
4. On the 1024th delivered purchase to `pallet-bandwidth`, `push_subscription` detects `list.len() == MAX_SUBSCRIPTIONS` and evicts index 0 — the victim's original subscription — emitting `SubscriptionEvicted { lost_bytes: <victim's paid bytes> }`. [10](#0-9) 
5. The victim's paid-for bandwidth is now unusable; further `try_consume` calls against `(victimChain, victimApp)` see only the attacker's low-value dummy entries.

```text
    function purchase(bytes calldata app, uint256 tier, uint256 months, bytes calldata chain)
        external
        returns (bytes32 commitment)
    {
        if (app.length == 0 || app.length > MAX_APP_LENGTH || chain.length == 0 || months == 0) {
            revert InvalidPurchase();
        }
        uint256 price18d = tierPrice[tier];
        if (price18d == 0) revert UnknownTier();

        uint256 total18d = price18d * months;
        address feeToken = IDispatcher(_host).feeToken();
        uint8 dec = IERC20Metadata(feeToken).decimals();
        uint256 scale = 10 ** (18 - dec);
        if (total18d % scale != 0) revert PriceNotRepresentable();
        uint256 amount = total18d / scale;

        IERC20(feeToken).safeTransferFrom(msg.sender, address(this), amount);

        BandwidthPurchaseMsg memory body = BandwidthPurchaseMsg({
            app: app,
            tier: tier,
            months: months,
            chain: chain
        });

        commitment = IDispatcher(_host).dispatch(
            DispatchPost({
                dest: IDispatcher(_host).hyperbridge(),
                to: PALLET_BANDWIDTH_MODULE_ID,
                body: abi.encode(body),
                timeout: 0,
                fee: 0,
                payer: address(this)
            })
        );

        emit BandwidthPurchased({
            payer: msg.sender,
            feeToken: feeToken,
            tier: tier,
            months: months,
            amountPaid: amount,
            app: app,
            chain: chain,
            commitment: commitment
        });
    }
```

```rust
//! # pallet-bandwidth
//!
//! Prepaid `(chain, app)` byte balances credited by tier purchases
//! from `BandwidthManager.sol`. Each purchase carries its own
//! `app_chain`, so any deployment can sponsor any app on any chain.
//!
//! Each `(chain, app)` row holds a FIFO list of [`Subscription`]s
//! (`BoundedVec`, capped at 1024). Every purchase appends a new
//! subscription with a fixed `expires_at`; expiry never extends and
//! same-tier repurchases don't stack — they queue. The gate drains
//! the oldest live subscription first; once empty it moves to the
//! next. Subscriptions that aren't reached before their expiry are
//! swept silently — what you paid for is yours only until it expires.
//! Pushes onto a full list evict the oldest entry and emit
//! [`Event::SubscriptionEvicted`].
```

```rust
		/// side holds prices; this pallet holds bytes/duration).
		/// `updates` is `(tier, price18d)` pairs.
		#[pallet::call_index(4)]
		#[pallet::weight(T::DbWeight::get().writes(1))]
		pub fn dispatch_set_tiers(
			origin: OriginFor<T>,
			target: StateMachine,
			updates: Vec<(TierIndex, U256)>,
		) -> DispatchResult {
			<T as pallet_ismp::Config>::AdminOrigin::ensure_origin(origin)?;
			ensure!(!updates.is_empty(), Error::<T>::EmptyTierBatch);
			let manager = BandwidthManager::<T>::get(&target).ok_or(Error::<T>::UnknownManager)?;

			let count = updates.len() as u32;
			let rows: Vec<Tier> = updates
				.into_iter()
				.map(|(t, p)| {
					let id_u32: u32 = t.into();
					Tier { tier: to_alloy_u256(U256::from(id_u32)), price: to_alloy_u256(p) }
				})
				.collect();

			let mut body = vec![ACTION_SET_TIERS];
			body.extend(rows.abi_encode_params());

			let commitment = Self::dispatch_governance(target, manager, body)?;
			Self::deposit_event(Event::TiersDispatched { target, count, commitment });
			Ok(())
		}
```

```rust
		fn push_subscription(
			app_chain: &StateMachine,
			app: &AppKey,
			tier: TierIndex,
			bytes: BandwidthBytes,
			duration_secs: u64,
		) -> u64 {
			let now = <T as pallet_ismp::Config>::TimestampProvider::now().as_secs();
			let expires_at = now.saturating_add(duration_secs);
			let new_sub =
				Subscription { tier, remaining_bytes: bytes, expires_at, purchased_at: now };

			let evicted = Allowance::<T>::mutate(app_chain, app, |list| {
				let evicted = if list.len() == MAX_SUBSCRIPTIONS as usize {
					Some(list.remove(0))
				} else {
					None
				};
				// Capacity is now guaranteed; try_push can't fail.
				let _ = list.try_push(new_sub);
				evicted
			});

			if let Some(old) = evicted {
				Self::deposit_event(Event::SubscriptionEvicted {
					app_chain: *app_chain,
					app: app.clone(),
					tier: old.tier,
					lost_bytes: old.remaining_bytes,
				});
			}

			expires_at
		}
```
