## Title
Use-after-validation invalid-UTF-8 `String` constructed via `from_utf8_unchecked` on attacker-controlled EVM request body — (File: `modules/pallets/demo/src/lib.rs`)

### Summary
`pallet_ismp_demo::IsmpModuleCallback::on_accept` builds a Rust `String` from an unvalidated, attacker-controlled byte buffer using `unsafe { String::from_utf8_unchecked(request.body) }` whenever the `PostRequest`'s `source_chain` is `StateMachine::Evm(_)`. This mirrors the bug class in the reported CPython advisory: a decode/escape path that skips proper validation and produces a value whose type-level invariant (well-formed UTF-8) no longer holds, so every later safe-Rust operation on that value — string slicing, char-boundary indexing, `Debug`/`Display` formatting, downstream comparisons — operates on memory it is not actually permitted to assume is valid, which is undefined behavior and can manifest as out-of-bounds reads or worse in optimized builds. [1](#0-0) 

### Finding Description
`request.body` is fully attacker-controlled: it is the raw payload of an ISMP `PostRequest` delivered by any unprivileged relayer once a valid state/consensus proof for the message exists. When `source_chain` is `StateMachine::Evm(_)`, the callback does:

```rust
StateMachine::Evm(_) => Pallet::<T>::deposit_event(Event::Request {
    source: source_chain,
    data: unsafe { String::from_utf8_unchecked(request.body) },
}),
``` [2](#0-1) 

`from_utf8_unchecked` is documented by the standard library as requiring the caller to guarantee the bytes are valid UTF-8, and violating that guarantee is undefined behavior — the exact same class of defect as the reported CPython issue, where an error handler ("ignore"/"replace") let invalid/partially-decoded byte state escape validation and be reused afterward. Here, there is no encoding validation at all before the bytes are wrapped in a `String`.

This is not dead demo-only code: `pallet_ismp_demo` is compiled into and wired up in the actual parachain runtime. The runtime's `ProxyModule::on_accept` (the production `IsmpRouter` implementation) dispatches any inbound `PostRequest` addressed to `pallet_ismp_demo::PALLET_ID` straight into this callback:
```rust
pallet_ismp_demo::PALLET_ID =>
    pallet_ismp_demo::IsmpModuleCallback::<Runtime>::default().on_accept(request),
``` [3](#0-2) 

and `pallet_ismp_demo` (`IsmpDemo`) is a live pallet in the runtime's `construct_runtime!` pallet list: [4](#0-3) 

### Impact Explanation
Once `Event::Request.data` holds a `String` value that is not valid UTF-8, any code that treats it as a normal Rust string is operating outside the language's soundness guarantees:
- Any `str`/`String` operation that indexes/slices by byte offset relies on the type's validity invariant to guarantee slice boundaries fall on character boundaries; on invalid data this becomes undefined behavior rather than a graceful panic, and in release/optimized builds the compiler may assume the invariant holds, producing out-of-bounds memory reads or corrupted control flow.
- Downstream consumers of the emitted event (RPC subscription decoding, `Debug`/serde serialization for indexers or off-chain clients) can hit the same class of failure this repository has already fixed once, where a serde helper crashing on non-UTF-8/incorrectly-sized bytes took down the node's RPC worker thread — see the pre-existing regression test guarding `as_utf8_string`. [5](#0-4) 

The overall effect is undefined behavior triggered by a single, unprivileged, attacker-crafted cross-chain message, with worst-case outcomes ranging from node/RPC crashes (denial of that delivery route) to memory corruption in the collator/full-node process depending on optimization and how the invalid string is subsequently consumed.

### Likelihood Explanation
High reachability, low cost: any relayer can submit a `PostRequest` from an EVM source chain addressed to the `ismp-ast` module id once the standard consensus/state proof for that message is accepted by `pallet-ismp`'s normal dispatch path — no special privilege, governance action, or malicious validator/collator is required, only a message whose `body` is not valid UTF-8 (trivial to construct, e.g. a single `0xFF` byte).

### Recommendation
Replace the unsafe conversion with a fallible one and reject (or handle) malformed input instead of skipping validation:
```rust
StateMachine::Evm(_) => Pallet::<T>::deposit_event(Event::Request {
    source: source_chain,
    data: String::from_utf8(request.body)
        .map_err(|_| IsmpError::Custom("Request body is not valid UTF-8".to_string()))?,
}),
```
This mirrors the upstream CPython fix direction: never let unvalidated/partially-processed byte data escape into a type whose safety guarantees the rest of the program depends on.

### Proof of Concept
1. From any EVM chain connected to Hyperbridge, an unprivileged actor dispatches an ISMP `PostRequest` with `to = ModuleId::Pallet(PalletId(*b"ismp-ast")).to_bytes()` and `body = vec![0xFF]` (or any non-UTF-8 byte sequence).
2. A relayer delivers the message with a valid state proof through the normal `pallet-ismp` handler; `ProxyModule::on_accept` routes it to `pallet_ismp_demo::IsmpModuleCallback::on_accept` because `source_chain` is `StateMachine::Evm(_)`.
3. `unsafe { String::from_utf8_unchecked(request.body) }` executes on the invalid bytes, producing a `String` that violates Rust's UTF-8 validity invariant, which is stored/emitted in `Event::Request { data, .. }`.
4. Any later safe-Rust operation on that `data` (string slicing, RPC JSON serialization of events, `Debug` formatting in logs) is undefined behavior and can panic, crash the RPC/indexing worker, or in optimized builds behave unpredictably.

impl<T: Config> IsmpModule for IsmpModuleCallback<T> {
	fn on_accept(&self, request: PostRequest) -> Result<Weight, anyhow::Error> {
		let source_chain = request.source;

		match source_chain {
			StateMachine::Evm(_) => Pallet::<T>::deposit_event(Event::Request {
				source: source_chain,
				data: unsafe { String::from_utf8_unchecked(request.body) },
			}),
			StateMachine::Polkadot(_) | StateMachine::Kusama(_) => {
				let payload =
					<Payload<T::AccountId, <T as Config>::Balance> as codec::Decode>::decode(
						&mut &*request.body,
					)
					.map_err(|_| IsmpError::Custom("Failed to decode request data".to_string()))?;
				<T::NativeCurrency as Mutate<T::AccountId>>::mint_into(
					&payload.to,
					payload.amount.into(),
				)
				.map_err(|_| IsmpError::Custom("Failed to mint funds".to_string()))?;
				Pallet::<T>::deposit_event(Event::<T>::BalanceReceived {
					from: payload.from,
					to: payload.to,
					amount: payload.amount,
					source_chain,
				});
			},
			source => Err(IsmpError::Custom(format!("Unsupported source {source:?}")))?,
		}

		Ok(weight())
	}
