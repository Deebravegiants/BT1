### Title
Unaccounted-token bypass in Emporium `runAction` via `dimensions={0,0,0}` allows draining pooled Emporium ETH/ERC20 balance with a trivial proof - ([File: contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol])

### Summary
`HinkalHelper.dimensionsCheck` and `CircomDataBuilder.formInputForCircom` can simultaneously be satisfied by `dimensions = {tokenNumber:0, nullifierAmount:0, outputAmount:0}` with `erc20TokenAddresses.length == 0` and `externalActionId == HINKAL_EMPORIUM_ACTION_ID`, routing the proof to the trivial `formInputEmporiumMin`/`MainEVMCircuitMin` path. This path proves nothing about ownership of funds, and because `circomData.erc20TokenAddresses` is empty, `EmporiumUpgradeable.runAction`'s balance-accounting loop (`balancesBefore`/`balancesAfter`/`handleOut`) never executes for any token, while the arbitrary `EmporiumStack.ops` loop still executes fully, letting an unprivileged EOA call arbitrary `endpoint.call{value: op.value}(op.callData)` funded from the Emporium contract's own pooled ETH/ERC20 balance with zero balance check and, if `signerAddress == address(0)`, zero signature check.

### Finding Description
Broken equality: the protocol design assumes "if `circomData.erc20TokenAddresses.length == 0` (Emporium-Min path), the transaction moves no ERC20/ETH accounted by Hinkal's per-token loop" is equivalent to "the transaction moves no ERC20/ETH at all." This is false: `EmporiumUpgradeable.runAction`'s `ops` loop (`contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol:91-118`) is independent of `circomData.erc20TokenAddresses` and executes regardless of its length.

Path:
1. `CircomDataBuilder.formInputForCircom` (`contracts/CircomDataBuilder.sol:134-148`) routes to `formInputEmporiumMin` whenever `externalActionId == HINKAL_EMPORIUM_ACTION_ID && erc20TokenAddresses.length == 0`, producing only 3 public signals (`emporiumMessage, timeStamp, calldataHash`) that correspond to the trivial `MainEVMCircuitMin` template (`circuits/MainEVMCircuitMin.circom:1-18`), which only computes `message <== Poseidon(1)([messageSeed])` — no nullifier, no root-membership, no amount constraint whatsoever.
2. `HinkalHelper.dimensionsCheck` (`contracts/HinkalHelper.sol:64-171`) is satisfiable with `dimensions={0,0,0}`: it forces `erc20TokenAddresses.length`, `amountChanges.length`, `onChainCreation.length`, `slippageValues.length`, `inputNullifiers.length`, `outCommitments.length`, `encryptedOutputs.length` all to `0` — all trivially true for empty arrays supplied by the attacker.
3. `Hinkal.transact` (`contracts/Hinkal.sol:30-90`) only requires `rootHashExists(circomData.rootHashHinkal, rootHashHinkalIndex)` to hold; with `m_index == MINIMUM_INDEX` (empty/initial tree) this is satisfied trivially by `_root == 0` (`contracts/MerkleBase.sol:53-64`), or by any previously published valid root the attacker copies from calldata — no ownership proof is required since the min circuit doesn't constrain `rootHashHinkal`.
4. `Hinkal._externalTransact` (`contracts/Hinkal.sol:234-261`) loops over `circomData.erc20TokenAddresses` (length 0 → no-op) and calls `EmporiumUpgradeable.runAction(circomData, deltaAmountChanges)` with `deltaAmountChanges` also of length 0.
5. In `runAction` (`contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol:76-160`): `balancesBefore`/`balancesAfter` are computed over the empty `erc20TokenAddresses` array (no-op), and the final loop at line 132 that enforces `balanceChange >= 0` per token never executes because its bound is `circomData.erc20TokenAddresses.length == 0`. Meanwhile the `stack.ops` loop (lines 91-118) — fully attacker-controlled via `abi.decode(circomData.externalActionData.externalActionMetadata, (EmporiumStack))` — executes unconditionally, calling `op.endpoint.call{value: op.value}(op.callData)` funded from the Emporium contract's own held ETH/ERC20 balance.
6. `verifyWallet` (lines 302-349) only enforces the EIP-712 signature check when `stack.signerAddress != address(0)`; if the attacker sets `signerAddress = address(0)`, it returns immediately after marking the `emporiumMessage` used — no signature, no `maxFee`/`deadline` check at all, and Case-2 "stateless" `op.endpoint.call{value: op.value}(...)` runs directly with funds held on the Emporium contract itself.

Root cause: the accounting for "did this call move ERC20/ETH" is delegated entirely to the `erc20TokenAddresses`/`dimensions` loop, but the actual value-moving code path (`stack.ops`) in `EmporiumUpgradeable.runAction` is not gated by or tied to that array at all. `dimensions={0,0,0}` is a valid, cheap, and unprivileged way to disable the only balance-check mechanism while leaving the value-moving mechanism fully active.

### Impact Explanation
Any ETH/ERC20 balance sitting on the Emporium contract (pooled from prior Hinkal transactions that transferred funds there, e.g. `deltaAmountChanges[i] < 0` transfers in `Hinkal._externalTransact`/`EmporiumUpgradeable` payment flows, or funds simply sent to it) can be drained by an arbitrary unprivileged EOA to any `endpoint`/`callData`/`value` of their choosing, with no balance check and (via `signerAddress = address(0)`) no signature check gating the call. This is direct theft of protocol/in-flight user funds held by the Emporium external action, matching **Critical** severity (direct theft of shielded/in-flight user funds via a verification bypass — the ZK proof required is a no-op `MainEVMCircuitMin` that constrains nothing about the theft). The attack is repeatable per unique `emporiumMessage` (bounded only by `usedMessages` nonce reuse protection, which does not prevent using a fresh nonce each time).

### Likelihood Explanation
Preconditions: Emporium must be a registered `externalActionMap[HINKAL_EMPORIUM_ACTION_ID]` recipient (already true for a functioning deployment) and must hold a non-zero ETH/ERC20 balance (which naturally occurs from normal protocol operation moving funds through it). Attacker cost is minimal: craft `Dimensions{0,0,0}`, empty arrays in `CircomData`, and a locally-generated trivial `MainEVMCircuitMin` proof (only requires knowledge of an arbitrary `messageSeed`, no private key or UTXO ownership needed) plus an `EmporiumStack` with `signerAddress = address(0)` and malicious `ops`. No relayer, no admin role, no victim key is required — fully feasible for any EOA that can call `Hinkal.transact` and `EmporiumUpgradeable.runAction` through it.

### Recommendation
Do not let `erc20TokenAddresses.length == 0` disable value-movement checks in `EmporiumUpgradeable.runAction`. Either (a) forbid routing to `formInputEmporiumMin`/`MainEVMCircuitMin` whenever the external action is Emporium and `stack.ops` is non-empty/contains ETH or token value, requiring the full `MainEVMCircuit` accounting path for any transaction that can move value; or (b) independently track and enforce a full balance-conservation check (`address(this).balance` and all tokens touched by `ops`) in `runAction` regardless of `circomData.erc20TokenAddresses.length`, disallowing net balance decreases unless authorized by a validly-signed `EmporiumStack` (i.e., always require `stack.signerAddress != address(0)` and a valid EIP-712 signature whenever any `op.value > 0` or `op.callData` targets a token-transferring call).

### Proof of Concept

1. Deploy `Hinkal`, `HinkalHelper`, `EmporiumUpgradeable`, register Emporium as `externalActionMap[HINKAL_EMPORIUM_ACTION_ID]`.
2. Fund the Emporium contract with ETH (e.g., via a legitimate prior `transact` call that moves funds there, or `vm.deal`).
3. Generate a real Groth16 proof for `MainEVMCircuitMin` with an arbitrary `messageSeed` (no relation to any deposit/UTXO).
4. Build `Dimensions{tokenNumber:0, nullifierAmount:0, outputAmount:0}` and `CircomData` with `erc20TokenAddresses=[]`, `amountChanges=[]`, `onChainCreation=[]`, `slippageValues=[]`, `inputNullifiers=[]`, `outCommitments=[]`, `encryptedOutputs=[]`, `externalActionData.externalActionId = HINKAL_EMPORIUM_ACTION_ID`, `externalActionData.externalAddress = <Emporium>`, `externalActionData.externalActionMetadata = abi.encode(EmporiumStack({signerAddress: address(0), ops: [EmporiumOperation({endpoint: attackerContract, invokeWallet: false, value: <emporiumBalance>, callData: ""})], maxFee:0, deadline:0}))`.

    function runAction(
        CircomData calldata circomData,
        int256[] calldata deltaAmountChanges
    ) external override onlyAllowedRecipient returns (UTXO[] memory) {
        EmporiumStack memory stack = abi.decode(
            circomData.externalActionData.externalActionMetadata,
            (EmporiumStack)
        );

        uint256[] memory balancesBefore = getBalancesForArray(
            circomData.erc20TokenAddresses
        );

        verifyWallet(stack, circomData);

        for (uint256 i = 0; i < stack.ops.length; i++) {
            EmporiumOperation memory op = stack.ops[i];

            bool success;
            bytes memory err;

            // CASE 1: Stateful Interaction
            if (op.invokeWallet && stack.signerAddress != address(0)) {
                (success, err) = IHinkalWallet(stack.signerAddress)
                    .callHinkalWallet(op.endpoint, op.callData, op.value);
            }
            // CASE 2: Stateless Interaction
            else {
                bytes4 selector = bytes4(op.callData);
                if (
                    selector == IHinkalWallet.callHinkalWallet.selector ||
                    selector == IHinkalWallet.doSendToRelay.selector
                ) {
                    revert UnauthorizedWalletCall();
                }

                (success, err) = op.endpoint.call{value: op.value}(op.callData);
            }

            if (!success) {
                revert CallFailed(err);
            }
        }

        payRelayFees(circomData, stack.signerAddress, deltaAmountChanges);

        uint256[] memory balancesAfter = getBalancesForArray(
            circomData.erc20TokenAddresses
        );

        UTXO[] memory utxoSet = new UTXO[](
            circomData.erc20TokenAddresses.length
        );

        uint256 utxoSetLength;

        for (uint256 i = 0; i < circomData.erc20TokenAddresses.length; i++) {
            int256 balanceChange = int256(balancesAfter[i]) -
                int256(balancesBefore[i]);

            if (deltaAmountChanges[i] < 0) {
                balanceChange -= deltaAmountChanges[i];
                // this equation reads: total change of emporium balance = what was moved to emporium (-deltaAmountChange) + how emporium balance changed through tx (balanceChange)
            }

            // the only case when balanceChange can be < 0, when there were some funds on emporium before the call
            if (balanceChange < 0) {
                revert BalanceChangeShouldBePositive();
            }

            UTXO memory utxoOut = handleOut(balanceChange, circomData, i);

            if (utxoOut.amount > 0) {
                utxoSet[utxoSetLength++] = utxoOut;
            }
        }

        if (utxoSetLength < circomData.erc20TokenAddresses.length) {
            utxoSet.skipLast(
                circomData.erc20TokenAddresses.length - utxoSetLength
            );
        }

        return utxoSet;
    }

    function verifyWallet(
        EmporiumStack memory stack,
        CircomData calldata circomData
    ) internal {
        EmporiumStorageVars storage $ = _getEmporiumStorage();

        if ($.usedMessages[circomData.emporiumMessage]) {
            revert UsedMessage();
        }

        $.usedMessages[circomData.emporiumMessage] = true;

        if (stack.signerAddress == address(0)) {
            return;
        }

        bytes32 hashedMessage = _hashTypedDataV4(
            keccak256(
                abi.encode(
                    EMPORIUM_SIGNATURE_TYPEHASH,
                    circomData.emporiumMessage,
                    _hashEmporiumOps(stack.ops),
                    stack.maxFee,
                    stack.deadline
                )
            )
        );

        (address recoveredAddress, ECDSA.RecoverError err) = ECDSA.tryRecover(
            hashedMessage,
            stack.v,
            stack.r,
            stack.s
        );
        bool verified = err == ECDSA.RecoverError.NoError &&
            recoveredAddress == stack.signerAddress;
        if (!verified) {
            revert InvalidSignature();
        }

        if (block.timestamp > stack.deadline) {
            revert SignatureExpired();
        }

        if (circomData.feeStructure.flatFee > stack.maxFee) {
            revert FeeExceedsSignedMax();
        }
    }

template MainEVMCircuitMin() {
  // Public inputs:
  signal input outTimeStamp;
  signal input calldataHash;

  signal input messageSeed;
