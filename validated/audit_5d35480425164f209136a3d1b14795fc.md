### No vulnerability found for this question.

**Reasoning:** The claimed exploit requires an unprivileged caller to inject a `MultiPayload` whose `verifying_contract` diverges from `envConfig.contractID`, but nothing in the reachable path from `estimateWithdrawalFee` → `processWithdrawal` lets a caller control `verifying_contract`.

- `IntentsSDK.estimateWithdrawalFee` / `_estimateWithdrawalFee` never constructs or accepts a `MultiPayload` at all — it only calls `bridge.estimateWithdrawalFee` and `bridge.validateWithdrawal` (address/min-amount/XRPL checks), as seen in [1](#0-0) .
- `createWithdrawalIntents` builds an `IntentPrimitive`, not a signed `MultiPayload`; PoaBridge's `createWithdrawalIntents` just calls `createWithdrawIntentPrimitive` [2](#0-1) .
- The actual `verifying_contract` is only set later, inside `IntentExecuter.signAndSendIntent`, and it is hard-coded from `this.envConfig.contractID` — not from any attacker-supplied field: `const verifyingContract = this.envConfig.contractID;` followed by `defaultIntentPayloadFactory(salt, { verifying_contract: verifyingContract, ...intentParams })` [3](#0-2) . The `intentParams` spread in that call comes only from `intents`, `relayParams`, and `signedIntents` as passed by `signAndSendWithdrawalIntent`/`processWithdrawal` — never `verifying_contract` [4](#0-3) .
- The only ways to override `verifying_contract` are `IntentPayloadBuilder.setVerifyingContract()` or a custom `intentPayloadFactory` merged via `mergeIntentPayloads` [5](#0-4) [6](#0-5) . Both are documented, opt-in integrator escape hatches (`args.intent.payload`), explicitly out of scope per the rules ("deliberately misuse a documented escape hatch").
- `findMatchingWithdrawal` in `poa-bridge.ts` matches by `nep141:<near_token_id>` on the withdrawal-status side [7](#0-6) , which is unrelated to `verifying_contract` and does not construct or validate any `MultiPayload`.

Since no unprivileged, documented input path allows a caller to set or influence `verifying_contract` independently of `envConfig.contractID`, the invariant `verifying_contract == contractID` cannot be broken through `estimateWithdrawalFee` or the subsequent `processWithdrawal` steps without deliberately using an out-of-scope escape hatch. The premise of the question does not hold against the actual code.

	protected async _estimateWithdrawalFee(args: {
		withdrawalParams: WithdrawalParams;
		quoteOptions?: QuoteOptions;
		logger?: ILogger;
	}): Promise<FeeEstimation> {
		for (const bridge of this.bridges) {
			if (await bridge.supports(args.withdrawalParams)) {
				const fee = await bridge.estimateWithdrawalFee({
					withdrawalParams: args.withdrawalParams,
					quoteOptions: args.quoteOptions,
					logger: args.logger,
				});

				if (args.withdrawalParams.feeInclusive) {
					if (args.withdrawalParams.amount <= fee.amount) {
						throw new FeeExceedsAmountError(fee, args.withdrawalParams.amount);
					}
				}
				const actualAmount = args.withdrawalParams.feeInclusive
					? args.withdrawalParams.amount - fee.amount
					: args.withdrawalParams.amount;

				await bridge.validateWithdrawal({
					assetId: args.withdrawalParams.assetId,
					amount: actualAmount,
					destinationAddress: args.withdrawalParams.destinationAddress,
					feeEstimation: fee,
					routeConfig: args.withdrawalParams.routeConfig,
					logger: args.logger,
					destinationMemo: args.withdrawalParams.destinationMemo,
					// When estimating fees before the exact amount is known, skip minimum amount validation while keeping all other validation intact.
					skipMinAmountValidation:
						args.withdrawalParams.amount === 0n &&
						args.withdrawalParams.feeInclusive === false,
				});

				return fee;
			}
		}

		throw new Error(
			`Cannot determine bridge for withdrawal = ${stringify(
				args.withdrawalParams,
			)}`,
		);
	}

function findMatchingWithdrawal(
	withdrawals: WithdrawalStatusResponse["withdrawals"],
	assetId: string,
): WithdrawalStatusResponse["withdrawals"][number] | undefined {
	// POA bridge only supports NEP-141 tokens. The API returns `near_token_id`
	// (e.g., "zec.omft.near") which we prefix with "nep141:" to match assetId format.
	// Note: `defuse_asset_identifier` cannot be used as it contains chain-native
	// format (e.g., "zec:mainnet:native") which differs from the assetId format.
	return withdrawals.find((w) => `nep141:${w.data.near_token_id}` === assetId);
}

async function mergeIntentPayloads(
	defaultPayload: IntentPayload,
	intentPayloadFactory: IntentPayloadFactory,
	salt: Salt,
): Promise<IntentPayload> {
	const customPayload = await intentPayloadFactory(defaultPayload);
	const customPayloadIntents = customPayload.intents ?? [];

	const { nonce: _nonce, ...basePayload } = defaultPayload;

	return defaultIntentPayloadFactory(salt, {
		...basePayload,
		...customPayload,
		intents: Array.from(
			new Set([...customPayloadIntents, ...basePayload.intents]),
		),
	});
}
