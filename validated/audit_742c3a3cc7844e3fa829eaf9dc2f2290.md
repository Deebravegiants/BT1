### Title
Bad-debt socialization write-down to the vault's liquidity index can be diluted by inflating `total-assets` within the same transaction - ([File: mainnet/contracts/vault/v0-vault-usdc.clar])

### Summary
The reported Yearn bug shows that a strategy's loss penalty is computed from a manipulable `_totalAssets()` value, letting the loss reporter flash-inflate that value in the same transaction to shrink the penalty. Zest's lending vaults (`v0-vault-usdc.clar`, `v0-vault-stx.clar`, `v0-vault-sbtc.clar`, `v0-vault-ststx.clar`, `v0-vault-ststxbtc.clar`, `v0-vault-usdh.clar`) contain the same pattern in `socialize-debt`, where the write-down applied to the shared liquidity index `lindex` is computed as a ratio against `(total-assets)`, a value that can be temporarily inflated by depositing into the vault immediately before the socialization call and withdrawing immediately after, all inside one atomic transaction.

### Finding Description
`socialize-debt` computes the new liquidity index proportionally to the loss relative to `total-assets`: [1](#0-0) 

```
(old-total-assets (total-assets))
(debt-reduction (mul-div-down scaled-amount idx INDEX-PRECISION))
...
(new-lindex (if (and (> old-total-assets u0) (> old-total-assets debt-reduction))
               (mul-div-down current-lindex (- old-total-assets debt-reduction) old-total-assets)
               u0))
```

`total-assets` is derived directly from the mutable `assets` data-var plus accrued interest: [2](#0-1) 

The `assets` var is increased by ordinary `deposit` calls and decreased by `withdraw`, both of which are ordinary user-callable entry points on the vault, unrelated to `socialize-debt`'s privileged caller check: [3](#0-2) 

`socialize-debt` is only reachable through the market's `liquidate` flow when a liquidated position leaves no collateral behind (bad debt), and it is invoked as a downstream `contract-call?` within the same top-level transaction as `liquidate`: [4](#0-3) 

Because Clarity transactions execute multiple contract-calls atomically, an attacker who controls the liquidation transaction (e.g., liquidates their own colluding under-collateralized position, or races/bundles a liquidation of any position that will end with no remaining collateral) can, in the same transaction:
1. Deposit a large amount into the affected vault, inflating the `assets` var and thus `total-assets()`.
2. Trigger `liquidate`, which cascades to `socialize-debt`, reading the now-inflated `old-total-assets`.
3. Withdraw the just-deposited amount back out.

The inflated `old-total-assets` makes the ratio `(old-total-assets - debt-reduction) / old-total-assets` closer to 1, so `new-lindex` is written down less than it should be relative to the real, un-inflated asset base. Meanwhile the real backing (`assets` var) is still correctly reduced by `principal-reduction` inside the same call. The net effect is that `lindex` — which converts LP token balances into claims on underlying assets — ends up overstating the true remaining backing after the bad-debt event.

### Impact Explanation
This breaks the fundamental vault solvency identity: `sum(LP claims via lindex) == real underlying backing`. Because the write-down applied to `lindex` can be diluted at will by whoever controls (or times) the liquidation transaction, the loss from bad debt is under-socialized to existing depositors. The mismatch is a protocol-insolvency condition: LP shares are valued as though more assets exist than actually remain, so a future depositor attempting to redeem will be unable to receive the full value implied by the index, producing permanent freezing/loss of funds for later withdrawers. This qualifies as Critical impact (protocol insolvency / permanent freezing of funds) under the stated criteria.

### Likelihood Explanation
The likelihood is high in principle because: (a) `deposit`/`withdraw` are unprivileged, unrestricted entry points reachable by any user; (b) `liquidate` is a permissionless, unprivileged entry point; (c) Clarity transactions allow atomic composition of multiple contract-calls, so the deposit-liquidate-withdraw sequence can be built into a single attacker-controlled transaction (optionally funded by external capital, which is permitted per scope since the flashloan-as-capital exception applies). The only friction is that the attacker (or a colluding borrower) must be the one causing a liquidation event that ends with `no-collateral-left`, which requires an actual bad-debt liquidation to exist — a naturally occurring or engineered event.

### Recommendation
Do not derive the bad-debt write-down ratio from a same-transaction-mutable `total-assets()` value. Snapshot/checkpoint `total-assets` (or the `lindex`-relevant asset base) prior to the start of the top-level transaction (e.g., at the beginning of the block, or via a value that cannot be moved by deposits/withdrawals executed later in the same atomic transaction), or restrict `deposit`/`withdraw` from affecting the value used in `socialize-debt` within the same transaction that also triggers a liquidation cascade. More generally, penalty/write-down computations should never depend on a balance-derived value that ordinary unprivileged calls (`deposit`, `withdraw`) can move within the same atomic execution as the event being penalized.

### Proof of Concept
1. Identify (or engineer, if colluding as both borrower and liquidator) a borrower position that will be fully liquidated with `no-collateral-left = true`, triggering `socialize-debt-asset` → vault `socialize-debt`.
2. In one transaction:
   a. Call the vault's `deposit` with a large amount `X`, increasing `assets` (and thus `total-assets()`).
   b. Call `market.liquidate` on the target position; this internally invokes `socialize-debt`, which reads the now-inflated `old-total-assets`, computing a smaller `new-lindex` write-down than would occur with the true, pre-deposit asset base.
   c. Call the vault's `withdraw` to redeem the shares from the deposit in step (a), removing `X` back out.
3. Compare `lindex` after the transaction to what it would have been without the extra deposit/withdraw bracket: it is measurably higher (less written down), while `assets` has already been correctly decremented by `principal-reduction`. This leaves `lindex`-derived LP claims overstated relative to real vault backing, an unrecoverable shortfall that surfaces as later depositors are unable to redeem at the implied index value.
