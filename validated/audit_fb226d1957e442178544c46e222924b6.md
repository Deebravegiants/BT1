All claims in the report are confirmed by direct code inspection: `loopRoutes` is registered directly on the unauthenticated `api` group with no auth middleware [1](#0-0) , while the node's own `debugRoutes` (`/debug/vars`) requires `auth.Authenticate(...)` [2](#0-1)  and `metricRoutes` (pprof endpoints) is deliberately mounted only inside `authv2`, which requires token/session authentication, with an explicit comment calling this out [3](#0-2) [4](#0-3) . The `loopRoutes` function itself registers `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, `/plugins/:name/debug/pprof/symbol` with zero auth middleware arguments [5](#0-4) . `pluginPPROFHandler` takes a client-controlled `seconds` query parameter that directly sets profiling duration (`timeout = time.Duration(i+PPROFOverheadSeconds) * time.Second`) and forwards to the internal plugin's pprof endpoint [6](#0-5) . `discoveryHandler` and `pluginMetricHandler` expose internal plugin names, hostnames, and Prometheus ports to any caller without auth [7](#0-6) [8](#0-7) .

This is a genuine, concrete, and verifiable inconsistency: the codebase explicitly treats debug/pprof-class routes as requiring authentication in two other places (`debugRoutes`, `metricRoutes` via `authv2`) but omits that protection for `loopRoutes`, which exposes materially similar functionality (arbitrary-duration CPU/heap profiling proxied to internal plugin processes, plus internal topology disclosure). The exploit path requires no credentials — an unauthenticated HTTP client reaching the node's web port can directly hit `/plugins/:name/debug/pprof/profile?seconds=N` or `/discovery` or `/plugins/:name/metrics`. This maps to an in-scope resource-exhaustion DoS and information-disclosure impact and is reproducible via the exact curl commands given.

Audit Report

## Title
Unauthenticated LOOP plugin discovery/metrics/pprof endpoints allow resource-exhaustion DoS and internal-topology disclosure - (File: `core/web/loop_registry.go`, `core/web/router.go`)

## Summary
`loopRoutes` in `core/web/router.go` registers `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` directly on the unauthenticated `api` router group, with no `auth.Authenticate(...)` wrapper, unlike the functionally identical `metricRoutes` (also pprof debug endpoints) which is explicitly placed inside the authenticated `authv2` group, and unlike `debugRoutes` (`/debug/vars`) which also requires session authentication. Any unauthenticated network client that can reach the node's web server can therefore trigger long-running CPU/heap profile captures against internal LOOP plugins and enumerate internal plugin names/hostnames/ports.

## Finding Description
`NewRouter` builds the `api` group with only rate-limiting and session middleware (no auth requirement) and calls `loopRoutes(app, api)` directly:
```go
api := engine.Group("/", rateLimiter(...), sessions.Sessions(...))
debugRoutes(app, api)
...
v2Routes(app, api)
loopRoutes(app, api)
```
`loopRoutes` registers its handlers with no auth middleware argument at all, while `debugRoutes` wraps its group in `auth.Authenticate(...)` and `metricRoutes` is only invoked inside `authv2` (which itself requires `auth.Authenticate(..., auth.AuthenticateByToken, auth.AuthenticateBySession)`), with the code comment "Debug routes accessible via authentication" directly documenting the intended security model that `loopRoutes` violates.

`pluginPPROFHandler` accepts a client-controlled `seconds` query parameter that is used to set the timeout/duration for a CPU profile capture forwarded to the internal plugin process, and returns the raw proxied response. `discoveryHandler` and `pluginMetricHandler` similarly expose internal plugin names, ports, and hostnames without any authentication check.

## Impact Explanation
An unauthenticated remote client can repeatedly invoke `/plugins/:name/debug/pprof/profile?seconds=N` with large `N` values to hold node/plugin goroutines and CPU for extended periods concurrently, producing a resource-exhaustion denial-of-service against the node's LOOP plugin subsystem. The same unauthenticated surface discloses internal plugin names, internal Prometheus ports, and hostnames via `/discovery` and `/plugins/:name/metrics`, constituting information disclosure about internal node topology. This maps to the in-scope "unauthenticated resource exhaustion / node API authentication bypass" impact category, since the security boundary the codebase itself establishes (debug/profiling routes require authentication) is bypassed for this specific route group.

## Likelihood Explanation
High. No credentials, tokens, or special network position are required — any client capable of reaching the node's HTTP listener port (the same port serving the authenticated API and UI) can invoke these routes. The attack is trivially repeatable and scriptable, and the endpoints are registered unconditionally whenever the node runs with LOOP plugins enabled.

## Recommendation
Wrap `loopRoutes(app, api)` registration with the same `auth.Authenticate(...)` middleware (and appropriate role, e.g. `auth.RequiresAdminRole` or similar) used for `debugRoutes`/`metricRoutes`, or move these routes into the `authv2` group. Alternatively, restrict access at the routing layer (e.g., separate internal-only listener or IP allowlist) consistent with how other debug/profiling endpoints are treated in this codebase.

## Proof of Concept
```
curl "http://<node>:6688/discovery"
curl "http://<node>:6688/plugins/<plugin-name>/metrics"
curl "http://<node>:6688/plugins/<plugin-name>/debug/pprof/profile?seconds=60"
```
All three requests succeed with no `Authorization` header, `Cookie`, or API token, verified by direct code review of `core/web/router.go` lines 86-91, 230-236, 238-248, 444-446 and `core/web/loop_registry.go` lines 52-166, none of which apply any `auth.Authenticate`/`auth.Requires*Role` middleware to the `loopRoutes` handlers, in contrast to sibling debug routes `debugRoutes` and `metricRoutes`.

// discoveryHandler implements service discovery of prom endpoints for LOOPs in the registry
func (l *LoopRegistryServer) discoveryHandler(w http.ResponseWriter, req *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	groups := make([]*targetgroup.Group, 0, 1+len(l.registry.List()))

	// add node metrics to service discovery
	groups = append(groups, pluginGroup(l.discoveryHostName, l.exposedPromPort, "/metrics"))

	// add all the plugins
	for _, registeredPlugin := range l.registry.List() {
		group := pluginGroup(l.discoveryHostName, l.exposedPromPort, pluginMetricPath(registeredPlugin.Name))
		group.Labels[LabelMetaPluginName] = model.LabelValue(registeredPlugin.Name)
		groups = append(groups, group)
	}

	b, err := l.jsonMarshalFn(groups)
	if err != nil {
		w.WriteHeader(http.StatusInternalServerError)
		_, err = w.Write([]byte(err.Error()))
		if err != nil {
			l.logger.Error(err)
		}
		return
	}
	_, err = w.Write(b)
	if err != nil {
		w.WriteHeader(http.StatusInternalServerError)
		l.logger.Error(err)
	}
}

func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/metrics", l.loopHostName, p.EnvCfg.PrometheusPort)
	req, err := http.NewRequestWithContext(gc.Request.Context(), http.MethodGet, pluginURL, nil)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)
	if err != nil {
		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)

		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))

		return
	}

}

func pprofURLVals(gc *gin.Context) (urlVals url.Values, timeout time.Duration) {
	urlVals = make(url.Values)
	if db, ok := gc.GetQuery("debug"); ok {
		urlVals.Set("debug", db)
	}
	if gc, ok := gc.GetQuery("gc"); ok {
		urlVals.Set("gc", gc)
	}
	timeout = PPROFOverheadSeconds * time.Second
	if sec, ok := gc.GetQuery("seconds"); ok {
		urlVals.Set("seconds", sec)
		if i, err := strconv.Atoi(sec); err == nil {
			timeout = time.Duration(i+PPROFOverheadSeconds) * time.Second
		}
	}
	return urlVals, timeout
}
