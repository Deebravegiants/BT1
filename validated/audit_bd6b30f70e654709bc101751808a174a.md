### Title
Unbounded `connectedOrigins` list allows linear-scan DoS on every dApp trust/auto-approve check - (File: features/connected-origins/module/connections.js)

### Summary
`@exodus/connected-origins` stores every dApp connection record in a single unbounded array (`connectedOriginsAtom`, `defaultValue: []`) and performs a full linear scan of that array on every trust/permission decision (`isTrusted`, `isAutoApprove`, `connect`, `disconnect`, `untrust`). There is no cap on the number of distinct origins that can be added, and no cap on the number of `activeConnections` per origin, mirroring the reported Swafe bug class where an unbounded `Vec` of per-account associations is scanned end-to-end on every recovery/verification call.

### Finding Description
The atom backing all connected dApp data is defined with no size bound: [1](#0-0) 

`ConnectedOrigins#add` looks up an existing entry by `origin` via a linear `.find()`, and if none exists, unconditionally pushes a brand-new record onto the array with no upper bound check: [2](#0-1) [3](#0-2) [4](#0-3) 

Every subsequent trust decision re-scans the full list: `#getOrigin` (used by `isTrusted`, `isAutoApprove`, `connect`, `disconnect`, `untrust`) does `data.find(...)`, and `#setAttributes` does a full `data.map(...)` rewrite of the whole array on every attribute change (e.g., toggling `autoApprove`, adding an active connection): [5](#0-4) [6](#0-5) 

The `connect` method additionally grows a nested `activeConnections` array per origin with no cap, deduplicating only by `id` via `uniqBy`, so a caller supplying ever-changing `id`s can grow this list unboundedly as well: [7](#0-6) 

This is structurally identical to the Swafe issue: an unbounded collection with no cap on insertion, linearly scanned on every subsequent permission/trust check that gates whether a request is auto-approved or must prompt the user.

### Impact Explanation
`isTrusted`/`isAutoApprove` gate whether a dApp request bypasses user confirmation for wallet operations (auto-approve flow), and are invoked on essentially every dApp interaction. If the `connectedOriginsAtom` array or an origin's `activeConnections` array can be grown without bound (e.g., by repeatedly calling `connect`/`add` with varying `origin`/`id` values from a malicious or scripted webpage integrating with the wallet's provider/RPC bridge), every subsequent trust check, attribute update (`#setAttributes` rewrites the entire array), and persisted-state serialization becomes increasingly expensive. This can degrade wallet responsiveness or cause resource exhaustion in the extension/background process handling dApp connections, and inflates persisted storage that must be encrypted/decrypted on load, similarly to the storage/serialization overhead impact called out in the original report.

### Likelihood Explanation
The unbounded growth path (`add`/`connect`) is reachable by any origin capable of interacting with the wallet's dApp connection surface without special privileges beyond initiating a wallet connection—an unprivileged-user analog to the "any party with the signing key" actor in the original report. No caps, quotas, or pagination exist anywhere in `connections.js`, so exploitation only requires repeated calls with distinct `origin`/`id` values, which is straightforward to script from a webpage.

### Recommendation
- Enforce a maximum number of entries in `connectedOriginsAtom` (and per-origin `activeConnections`), rejecting or evicting oldest/least-recently-used entries beyond the cap.
- Replace the `Array.find`/`Array.map` linear scans in `#getOrigin`/`#setAttributes` with a keyed lookup (e.g., a `Map`/object keyed by `origin`) to avoid O(n) cost per trust check as the list grows.
- Add rate limiting on `add`/`connect` calls per origin to prevent rapid unbounded growth.

### Proof of Concept
1. From a webpage using the wallet's dApp connect API, repeatedly call the equivalent of `exodus.connectedOrigins.add({ origin: uniqueOrigin_i, ... })` for `i = 1..N` with distinct `origin` values, and/or repeatedly call `connectedOrigins.connect({ origin, id: uniqueId_i })` for a single origin.
2. Because `#addNewItem` (`features/connected-origins/module/connections.js:76-106`) and `connect` (`features/connected-origins/module/connections.js:222-232`) never check any upper bound, the backing array/`activeConnections` grows without limit.
3. Each subsequent `isTrusted`/`isAutoApprove`/`connect`/`disconnect` call, and each persisted write via `#setData` → `#setAttributes` (which `.map`s the entire array), now costs O(N), degrading performance for legitimate dApp interactions and inflating encrypted storage size. [8](#0-7)

  add = async ({
    connectedAssetName,
    origin,
    name,
    icon,
    assetNames = [],
    trusted,
    favorite,
    walletAccount,
  }) => {
    const value = await this.#getOrigin({ origin })

    const allConnectedAssetNames = new Set([
      connectedAssetName,
      ...assetNames,
      ...(value?.assetNames ?? []),
    ])

    if (value) {
      await this.#setAttributes({
        origin,
        attributes: {
          icon: icon ?? value.icon,
          name: name ?? value.name,
          connectedAssetName: connectedAssetName ?? value.connectedAssetName,
          trusted: trusted ?? value.trusted,
          favorite: favorite ?? value.favorite,
          assetNames: [...allConnectedAssetNames],
          walletAccount: walletAccount ?? value.walletAccount,
        },
      })

      return
    }

    await this.#addNewItem({
      origin,
      icon,
      name,
      connectedAssetName,
      trusted,
      favorite,
      assetNames: [...allConnectedAssetNames],
      walletAccount,
    })
  }

  connect = async ({ id, origin }) => {
    const value = await this.#getOrigin({ origin })

    if (!value) return

    const activeConnections = value.activeConnections || []
    const newConnection = { id, createdAt: Date.now() }
    const newConnections = uniqBy([...activeConnections, newConnection], 'id')

    await this.#setAttributes({ origin, attributes: { activeConnections: newConnections } })
  }

  disconnect = async ({ id, origin }) => {
    const value = await this.#getOrigin({ origin })

    if (!value) return

    const activeConnections = value.activeConnections || []
    const newConnections = activeConnections.filter((connection) => connection.id !== id)

    await this.#setAttributes({ origin, attributes: { activeConnections: newConnections } })
  }
