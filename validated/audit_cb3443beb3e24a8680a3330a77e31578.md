### Title
Relayer reward for a backlog of unpaid consensus-update blocks is priced entirely at the *current* `StateMachinesCostPerBlock` rate rather than the rate(s) that applied while those blocks accrued, letting a relayer inflate (or governance-changes inadvertently mis-price) payouts for stale spans - (File: modules/pallets/consensus-incentives/src/impls.rs)

### Summary
`calculate_reward` in `pallet-consensus-incentives` computes a relayer's payout as `(latest_height - baseline) * block_cost`, where `block_cost` is whatever `StateMachinesCostPerBlock` currently holds at claim time [1](#0-0) . `baseline` can be far behind `latest_height` (e.g., a relayer that withholds submitting `StateMachineUpdated` proofs for a long time, or one that catches up a backlog in one batch), so a single *current* rate is retroactively applied to a span of blocks that occurred while a different `block_cost` was in effect. This mirrors the Astaria bug class: a value that should track how much has actually accrued moment-to-moment is instead priced with one static snapshot chosen at the wrong point in time, and the amount actually owed can drift far from what is paid.

### Finding Description
`process_message` reads the *current* `StateMachinesCostPerBlock` for a state machine and multiplies it by the full unpaid block span since `LastRewardedHeight` (or the previous commitment height baseline) [2](#0-1) . `calculate_reward` never records or applies the rate that was in force during each portion of that span - it uses only the value returned by `StateMachinesCostPerBlock::<T>::get(state_machine_id)` at the moment `on_executed` runs [1](#0-0) . `on_executed` is invoked as the `FeeHandler` for every relayed `Consensus` message, i.e., triggered directly by an unprivileged relayer submitting a consensus proof extrinsic [3](#0-2) . `update_cost_per_block` is a normal, expected governance operation (not malicious governance) that legitimately changes the per-block rate for a chain over time [4](#0-3) .

Because rewards are batched into a single per-state-machine claim keyed off `LastRewardedHeight` [5](#0-4) , a relayer can delay delivering consensus updates for a chain (submitting proofs is unprivileged and can be timed by anyone with a valid proof), accumulating a large unpaid `blocks` backlog, and then submit the delayed batch of updates once `StateMachinesCostPerBlock` has been raised via a subsequent, unrelated governance update. The whole backlog - blocks that accrued under the old, lower rate - is then paid out at the new, higher rate, extracting more BRIDGE/treasury funds than the protocol intended for that historical span. This is symmetrically also a griefing/underpayment vector if the rate is lowered before a backlog is claimed, but the theft-relevant direction is the inflation case.

### Impact Explanation
The reward is paid unconditionally out of `T::TreasuryAccount` via `T::Currency::transfer` for any nonzero computed amount [6](#0-5) , so an inflated `reward` is a direct, permanent drain of the on-chain treasury - it is unbacked value transferred to the relayer beyond what the actual per-block-cost accounting justifies for the delivered span. Because `LastRewardedHeight` only tracks height, not the rate-at-time-of-accrual, there is no way to later reconcile or claw back the overpayment. This is a Medium-severity fund-drain issue: it requires a rate change to occur (a normal governance action, not attacker-controlled) combined with an attacker (or even an honest but slow relayer) delaying a batch of consensus proofs across that rate change.

### Likelihood Explanation
`update_cost_per_block` is expected to be called periodically as chain economics or block-cost estimates change (it is a documented "governance-set" configuration, similar to `PhantomBidWindow` elsewhere in the codebase) [4](#0-3) . Any relayer capable of producing valid consensus proofs can choose when to submit them - nothing in `on_executed` or `process_message` requires timely submission, and a large backlog is explicitly anticipated by the `saturating_sub`/watermark logic [7](#0-6) . This makes the mispricing window realistically triggerable any time governance updates a chain's cost-per-block while a relayer (or several relayers competing to "win" delivery) hold back submission of updates for that chain.

### Recommendation
Track accrual against the rate that was active during each sub-span rather than a single point-in-time snapshot. Options:
- Record a rate-effective-height history (e.g., a `Vec<(height, block_cost)>` or a running "accrued-but-unpaid-value" accumulator updated whenever `update_cost_per_block` is called, integrating `unpaid_blocks_so_far * old_rate` before switching to the new rate) so a later claim only ever pays the sum of correctly-rated segments.
- Alternatively, force `update_cost_per_block` to first settle (flush) all state machines' pending rewards at the old rate before allowing the rate change to take effect, so no cross-rate backlog can exist.
- At minimum, cap the maximum unpaid block span that can be rewarded in one call (forcing frequent settlement) to bound the size of any single mispriced batch.

### Proof of Concept
1. Governance sets `StateMachinesCostPerBlock[SM] = 10` via `update_cost_per_block` [4](#0-3) .
2. A relayer possesses valid consensus proofs advancing `SM` from height 1000 to height 2000 but withholds submitting them (nothing prevents this - proof delivery is voluntary and unprivileged).
3. Governance later raises the rate: `StateMachinesCostPerBlock[SM] = 1000` (a normal, benign parameter update reflecting increased costs).
4. The relayer now submits the withheld consensus message advancing `SM` to height 2000. `on_executed` fires `process_message` → `calculate_reward`, computing `blocks = 2000 - 1000 = 1000` and `reward = 1000 * 1000 = 1_000_000`, all paid from the treasury at the *new* rate [8](#0-7) , even though 1000 of those blocks accrued while the rate was only 10 (i.e., should have been worth `1000*10 = 10_000`). The relayer extracts a 100x windfall from the treasury for the same delivery work, purely by timing submission around a rate change.
5. `LastRewardedHeight` is then set to 2000 [9](#0-8) , permanently baking in the overpayment with no reconciliation mechanism.

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)

	fn on_executed(
		messages: Vec<MessageWithWeight>,
		events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});

		if let Some(relayer_account) = maybe_relayer_account {
			// When a batch contains multiple `StateMachineUpdated` events for the
			// same `state_machine_id` (sequential consensus updates for the same
			// chain), `calculate_reward` reads the same persisted
			// `(latest_commitment_height, previous_commitment_height)` pair on
			// every iteration and pays the same block-span reward N times.
			// Collapse the per-state-machine event stream to the single highest
			// `latest_height` so each state machine receives one reward per
			// batch, sized by the actual span of its commitment advance.
			let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
			for event in events {
				if let IsmpEvent::StateMachineUpdated(update) = event {
					highest_per_state_machine
						.entry(update.state_machine_id)
						.and_modify(|h| {
							if update.latest_height > *h {
								*h = update.latest_height;
							}
						})
						.or_insert(update.latest_height);
				}
			}

			for (state_machine_id, latest_height) in highest_per_state_machine {
				let state_machine_height =
					StateMachineHeight { id: state_machine_id.clone(), height: latest_height };

				let _ = Self::process_message(
					state_machine_height,
					state_machine_id,
					relayer_account.clone().into(),
				);
			}
		}
