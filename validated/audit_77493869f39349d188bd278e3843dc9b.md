### Title
Token-Exchange trusts unsanitized JWT `dest` claim as the request host, allowing SSRF that exfiltrates the app's `client_secret` - (File: lib/shopify_api/auth/token_exchange.rb)

### Summary
`ShopifyAPI::Auth::TokenExchange.exchange_token` derives the shop/host used for the token-exchange HTTP request directly from the `dest` claim of the caller-supplied session token, without ever passing it through `Utils::ShopValidator`, unlike its sibling method `migrate_to_expiring_token`.

### Finding Description
`exchange_token` decodes the session token via `JwtPayload.new(session_token)`, which verifies the HS256 signature against `Context.api_secret_key` and checks `aud == Context.api_key`, but performs no validation on the `dest` claim's format or trustworthiness [3](#0-2) . `JwtPayload#shop` merely strips the `"https://"` prefix: `@dest.gsub("https://", "")` [4](#0-3) .

`exchange_token` then builds a session directly from this unsanitized value and uses it as the request host: [5](#0-4) 

Compare this to `migrate_to_expiring_token` in the same file, which explicitly sanitizes the shop before use: `validated_shop = Utils::ShopValidator.sanitize!(shop)` [6](#0-5) . `ShopValidator.sanitize!` enforces that the host belongs to a `TRUSTED_SHOPIFY_DOMAINS` allow-list (`shopify.com`, `myshopify.io`, `myshopify.com`, `spin.dev`, `shop.dev`) and raises `InvalidShopError` otherwise [7](#0-6) . `exchange_token` has no equivalent check on `dest_shop`.

The resulting `shop_session` (with `shop: dest_shop`) is passed to `Clients::HttpClient.new(session: shop_session, base_path: "/admin/oauth")`, which builds the request URL as `"https://#{api_host || session.shop}"` — using `session.shop` verbatim when `Context.api_host` is not configured [1](#0-0) . The request body posted to that host includes `client_id` and, critically, `client_secret: ShopifyAPI::Context.api_secret_key` [8](#0-7) .

The identity binding that should hold is: **the host that receives the app's `client_secret` == a trusted Shopify domain, as independently verified by this gem**. Because `dest_shop` is only bounded by JWT signature validity and an `aud` check, but never checked against the trusted-domain allow-list that the library itself defines and uses elsewhere (`ShopValidator`), this binding is broken for the token-exchange path specifically.

### Impact Explanation
If a session token can be obtained whose `dest` claim is not a genuine, `*.myshopify.com`/trusted-Shopify host — for example, a token that is otherwise validly signed for the app (e.g., replayed from a context the host app does not expect, or if `Context.old_api_secret_key` matches an older/weaker key, or the host application forwards an ID token from an untrusted source directly into `exchange_token` per the documented API) — the gem will send an HTTP POST containing the app's `client_secret` to attacker-controlled infrastructure named in `dest`. This is SSRF carrying the app's credentials and leaks the `client_secret`, which is a High-severity, Critical-adjacent outcome per the report's own credential-exfiltration criteria.

### Likelihood Explanation
Exploitability hinges entirely on an attacker's ability to get the host application to call `exchange_token` with a session token whose `dest` is untrusted while still passing JWT signature/`aud` checks. This is a narrower attack surface than a full unprivileged bypass (a validly-signed token from Shopify always carries a legitimate `dest`), so likelihood is lower than a pure logic bug, but the inconsistency between `exchange_token` and `migrate_to_expiring_token` (which does validate) indicates this specific check was simply omitted rather than deliberately deemed unnecessary, and is a defense-in-depth gap the library should close given that it already has the `ShopValidator` mechanism for exactly this purpose.

### Recommendation
In `ShopifyAPI::Auth::TokenExchange.exchange_token`, sanitize `dest_shop` through `Utils::ShopValidator.sanitize!` (as already done in `migrate_to_expiring_token`) before constructing `shop_session` and issuing the HTTP request, e.g.:
```ruby
dest_shop = Utils::ShopValidator.sanitize!(jwt_payload.shop)
```

### Proof of Concept
1. Obtain or induce the host application to pass a validly HS256-signed session token (signed with the app's `api_secret_key`, `aud` matching `Context.api_key`) whose `dest` claim is set to an attacker-controlled host, e.g. `"https://attacker.example.com"`.
2. Call `ShopifyAPI::Auth::TokenExchange.exchange_token(session_token: token, requested_token_type: ...)`.
3. `JwtPayload#shop` returns `"attacker.example.com"` unchanged [4](#0-3) .
4. `Clients::HttpClient` builds `@base_uri = "https://attacker.example.com"` [1](#0-0)  and POSTs the body containing `client_secret` to `https://attacker.example.com/admin/oauth/access_token` [9](#0-8) .
5. The attacker-controlled server logs the received `client_secret`, compromising the app's OAuth credential.

        [
          "shopify.com",
          "myshopify.io",
          "myshopify.com",
          "spin.dev",
          "shop.dev",

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
