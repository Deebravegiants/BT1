### Title
GetRequest fee escrow double-paid: `handleGetResponses` never clears `_requestCommitments`, letting `handleGetRequestTimeouts` pay it out a second time - (File: `evm/src/core/EvmHost.sol`)

### Summary
`EvmHost.dispatchIncoming(GetResponse,...)` pays the delivering relayer from `_requestCommitments[commitment].fee` but does not delete the `_requestCommitments` entry afterward. `HandlerV2.handleGetRequestTimeouts` / `EvmHost.dispatchTimeOut(GetRequestTimeout,...)` only check that a `_requestCommitments` entry still exists (`meta.sender != 0`) and that a non-membership proof of the destination's `ResponseReceipts` is valid at some historical `message.height`; neither checks the EVM host's own local `_responseReceipts` mapping to see whether the response was already delivered locally. This is the same bug class as CVE-2022-4382 (a race between two independent teardown/consumption paths over a shared resource that was never properly retired), letting the same fee escrow be consumed twice.

### Finding Description
- On response delivery, `EvmHost.dispatchIncoming(GetResponse,...)` reads and pays out the fee but leaves the commitment entry intact: [1](#0-0) 
- On timeout, `HandlerV2.handleGetRequestTimeouts` only verifies `meta.sender != address(0)` (i.e., the commitment record still exists) and a non-membership proof of `ResponseReceipts` on the *destination* chain at an arbitrary historical `message.height` chosen by the caller — it never queries the EVM host's own `_responseReceipts` for this commitment: [2](#0-1) 
- `EvmHost.dispatchTimeOut(GetRequestTimeout,...)` then deletes `_requestCommitments[commitment]` and, on success, refunds `meta.fee` a second time to the original sender: [3](#0-2) 

Contrast this with the Substrate `pallet-ismp` implementation of the identical flow, which explicitly re-checks `response_receipt` before allowing a `Get` timeout in order to prevent exactly this class of double-processing: [4](#0-3) 

Because the destination's `ResponseReceipts` non-membership proof is checked against a state height chosen by whoever submits the timeout message (any relayer or the caller via `batchCall`), an honest-looking proof from a height *before* the response was actually produced on the destination remains cryptographically valid even after the corresponding `GetResponse` has already been delivered and paid out on the EVM host. Nothing in `handleGetResponses`/`dispatchIncoming(GetResponse)` retires the `_requestCommitments` entry to prevent this stale-but-valid proof from being replayed through the timeout path.

### Impact Explanation
The escrowed `fee` for a single `GetRequest` is paid out twice from the host's token balance: once to the relayer via `dispatchIncoming(GetResponse,...)` and a second time to the original sender via `dispatchTimeOut(GetRequestTimeout,...)`. This is a direct, concrete drain of protocol/fee-token funds — every other user's escrowed fees back the extra payout, since the contract disburses more `feeToken()` than was ever collected for that request. It also causes the destination `IApp` module to receive both `onGetResponse` and `onGetTimeout` callbacks for the same logical request, which can desynchronize any module-side accounting that assumes exactly one terminal callback per request (e.g., a token bridge or intent-solving module that credits balances on response and refunds on timeout). This satisfies the "concrete theft ... of funds" bar required by the validation rules.

### Likelihood Explanation
Reachable by any unprivileged relayer submitting two ISMP messages for the same `GetRequest` commitment through the permissionless `HandlerV2.handleGetResponses` and `HandlerV2.handleGetRequestTimeouts` entry points (or bundled together via `batchCall`). No special privileges, governance action, or malicious admin is required — only possession of (a) a valid MMR membership proof for the `GetResponse` and (b) a valid, but stale, non-membership proof of `ResponseReceipts` at an earlier finalized destination height, both of which are routinely available to any relayer following the normal ISMP delivery protocol timing. This makes the finding Medium likelihood given the requirement to obtain two independently-valid proofs, but it does not require insider access or a race against block production — an attacker/relayer can simply hold the earlier non-membership proof and submit it any time after delivering the response.

### Recommendation
In `EvmHost.dispatchIncoming(GetResponse,...)`, delete `_requestCommitments[commitment]` once the response fee has been paid (mirroring how `dispatchTimeOut` deletes it), and/or have `HandlerV2.handleGetRequestTimeouts` / `EvmHost.dispatchTimeOut(GetRequestTimeout,...)` reject the timeout if `_responseReceipts[commitment].relayer != address(0)`, matching the guard already present in `modules/ismp/core/src/handlers/timeout.rs` for the pallet-ismp implementation.

### Proof of Concept
1. A user calls `EvmHost.dispatch(DispatchGet{...})`, escrowing `fee` and creating `_requestCommitments[commitment] = {sender, fee}` (`evm/src/core/EvmHost.sol:974-1013`).
2. Destination chain answers the query; relayer submits `HandlerV2.handleGetResponses` with a valid MMR proof. `EvmHost.dispatchIncoming(GetResponse,...)` sets `_responseReceipts[commitment]`, invokes the module's `onGetResponse`, and pays `fee` to the relayer — but leaves `_requestCommitments[commitment]` populated (`evm/src/core/EvmHost.sol:824-847`).
3. The same or a colluding relayer holds (or later obtains) a non-membership proof of `ResponseReceipts` for `commitment` at an earlier finalized destination height H (taken before the response was actually produced) and where `request.timeout() <= state.timestamp` at H.
4. Relayer submits `HandlerV2.handleGetRequestTimeouts` with that proof. The checks (`meta.sender != 0`, non-membership at height H) both pass since `_requestCommitments` was never cleared in step 2 (`evm/src/core/HandlerV2.sol:293-321`).
5. `EvmHost.dispatchTimeOut(GetRequestTimeout,...)` deletes `_requestCommitments[commitment]`, calls the module's `onGetTimeout`, and refunds `fee` a second time to `meta.sender` (`evm/src/core/EvmHost.sol:849-877`).
6. Net effect: the module received both `onGetResponse` and `onGetTimeout` for the same request, and `fee` was paid out twice from the host's token balance.

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    /**
     * @dev Dispatch an incoming GET timeout to the source module.
     * @notice Does not refund any protocol fees.
     * @param timeout - timed-out get request bundled with the relayer that submitted the timeout proof
     * @param meta - fee metadata for the original request
     * @param commitment - request commitment
     */
    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
