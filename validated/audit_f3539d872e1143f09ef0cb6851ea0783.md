## Title
DAO admin can silently retain control after `disable_admin()` by pre-planting a `pending_admin`, regaining custody of the DAO's treasury and NFTs - (File: `aptos-move/move-examples/dao/nft_dao/sources/nft_dao.move`)

## Summary
This is a direct Aptos-native analog of the LSP14 renounce-ownership bug: a two-step "offer/claim" pending-owner pattern where the final "disable/renounce" step forgets to clear the pending state, letting the original controller silently reclaim authority later.

## Finding Description
The `DAO` resource stores both a live `admin` address and an `Option<address> pending_admin` used for the offer/claim admin-transfer flow: [1](#0-0) 

`offer_admin` lets the current admin stage a `pending_admin`: [2](#0-1) 

`claim_admin` consumes `pending_admin` and sets `dao_config.admin` to it, whether or not the admin field currently matches the caller who created the offer: [3](#0-2) 

`disable_admin`, intended to permanently remove admin authority ("make sure no one can be admin of the DAO"), only zeroes `dao_config.admin` and never touches `dao_config.pending_admin`: [4](#0-3) 

Because `pending_admin` is left untouched, an admin can:
1. Call `offer_admin(admin, dao, B)` where `B` is an address they control, setting `pending_admin = Some(B)`.
2. Call `disable_admin(admin, dao)`, publicly setting `admin = @0x0` (appearing to renounce all admin power, e.g., to gain DAO members'/investors' trust).
3. At any later time, call `claim_admin` from `B`. Since `pending_admin` still equals `Some(B)`, `claim_admin` extracts it, sees `new_admin != @0x0`, checks `new_admin == caller_address` (true for `B`), and sets `dao_config.admin = B` — fully restoring admin control with no dependency on the admin field having been `@0x0`.

This exactly mirrors the LSP14 bug: the "renounce" step (`disable_admin`/`renounceOwnership`) doesn't clear the pending transfer state (`pending_admin`/`_pendingOwner`), so the party that renounced can reclaim control through the still-valid pending claim.

## Impact Explanation
The DAO admin is not a cosmetic role — it has direct custody powers over assets held in the DAO's resource account (`dao_signer_capability`):
- `admin_resolve` (via `resolve_internal` with `resolver` set) lets the admin bypass voting/time requirements and immediately execute a proposal's `transfer_fund` (moves `AptosCoin`/APT out of the DAO resource account) or `offer_nft` (moves NFTs out of the DAO) functions: [5](#0-4) [6](#0-5) 

- The admin can also veto proposals and change all governance parameters.

An admin can call `disable_admin` to convince the community/DAO participants that the DAO is now permission-less and admin cannot interfere (this is explicitly the documented purpose per the README's "DAO becomes mature... get rid of the admin address"), while secretly retaining a backdoor via the un-cleared `pending_admin`. They can later reclaim admin and use `admin_resolve` to drain the DAO's APT treasury and NFTs to an address of their choosing, bypassing normal voting entirely. This is a custody-grade takeover of resource-account-held value (APT + NFTs) via silently-retained admin authority.

## Likelihood Explanation
This requires the DAO's own admin to set up the trap before renouncing (`offer_admin` then `disable_admin`), which is entirely within their existing privileges and requires no external exploit — it's a rug-pull mechanism hidden in plain sight, exactly analogous to the referenced LSP14 finding. Any DAO relying on `disable_admin()` as a trust signal (as documented in the module's own README) is exposed.

## Recommendation
In `disable_admin`, also clear `pending_admin` (e.g., `option::extract(&mut dao_config.pending_admin)` if `option::is_some`, or simply overwrite it with `option::none()`), so no previously-staged offer can be claimed after admin powers are supposed to be permanently disabled. The same defensive clearing should be applied anywhere `admin` is force-reset outside of the offer/claim flow.

## Proof of Concept
```move
// Admin currently controls `dao` and also controls address B (e.g., another account they hold keys for).

// Step 1: stage a pending admin offer to an address they control
nft_dao::offer_admin(&admin_signer, dao, @B);
// dao_config.pending_admin == Some(@B)

// Step 2: publicly "renounce" admin power to build trust
nft_dao::disable_admin(&admin_signer, dao);
// dao_config.admin == @0x0
// dao_config.pending_admin is STILL Some(@B)  <-- bug: never cleared

// ... time passes, DAO grows a treasury, community believes it is admin-less ...

// Step 3: reclaim admin control at will
nft_dao::claim_admin(&b_signer, dao);
// dao_config.admin == @B  (admin authority fully restored)

// Step 4: abuse admin_resolve to drain funds/NFTs bypassing voting
nft_dao::create_proposal(&b_signer, dao, ..., function_names = ["transfer_fund"], ...);
nft_dao::resolve<AptosCoin>(proposal_id, dao); // as admin via admin_resolve path
```

    /// Claim DAO's admin from an offer. The new_admin will become the admin of the DAO.
    public entry fun claim_admin(account: &signer, dao: address) acquires DAO {
        // DAO offer exists
        assert!(exists<DAO>(dao), error::not_found(EDAO_NOT_EXIST));
        let dao_config = borrow_global_mut<DAO>(dao);
        assert!(option::is_some(&dao_config.pending_admin), error::invalid_argument(EADMIN_OFFER_NOT_EXIST));

        // Allow setting the admin to 0x0.
        let new_admin = option::extract(&mut dao_config.pending_admin);
        let old_admin = dao_config.admin;
        let caller_address = signer::address_of(account);
        if (new_admin == @0x0) {
            // If the admin is being updated to 0x0, for security reasons, this finalization must only be done by the
            // current admin.
            assert!(old_admin == caller_address, error::permission_denied(EINVALID_ADMIN_ACCOUNT));
        } else {
            // Otherwise, only the new admin can finalize the transfer.
            assert!(new_admin == caller_address, error::not_found(EADMIN_OFFER_NOT_EXIST));
        };

        // update the DAO's admin address
        dao_config.admin = new_admin;
        nft_dao_events::emit_admin_claim_event(old_admin, new_admin, dao);
    }

    /// Internal function for executing a DAO's proposal
    fun execute_proposal(proposal: &Proposal, dao: &DAO){
        vector::enumerate_ref(&proposal.function_names, |i, function_name| {
            let args = vector::borrow(&proposal.function_args, i);
            if (function_name == &string::utf8(b"transfer_fund")) {
                let res_signer = create_signer_with_capability(&dao.dao_signer_capability);
                let dst_addr = property_map::read_address(args, &string::utf8(b"dst"));
                let amount = property_map::read_u64(args, &string::utf8(b"amount"));
                transfer_fund(&res_signer, dst_addr, amount);
            } else if (function_name == &string::utf8(b"offer_nft")) {
                let res_signer = create_signer_with_capability(&dao.dao_signer_capability);
                let creator = property_map::read_address(args, &string::utf8(b"creator"));
                let collection = property_map::read_string(args, &string::utf8(b"collection"));
                let token_name = property_map::read_string(args, &string::utf8(b"token_name"));
                let property_version = property_map::read_u64(args, &string::utf8(b"property_version"));
                let dst = property_map::read_address(args, &string::utf8(b"dst"));
                offer_nft(&res_signer, creator, collection, token_name, property_version, dst);
            } else {
                assert!(function_name == &string::utf8(b"no_op"), error::invalid_argument(ENOT_SUPPROTED_FUNCTION));
            };
        });
    }

    /// Resolve an proposal
    fun resolve_internal(resolver: Option<address>, proposal_id: u64, nft_dao: address) acquires DAO, Proposals, ProposalVotingStatistics {
        // validate if proposal is ready to resolve
        let dao = borrow_global_mut<DAO>(nft_dao);
        // assert the proposal voting ended
        let proposals = borrow_global_mut<Proposals>(nft_dao);
        let proposal = table::borrow_mut(&mut proposals.proposals, proposal_id);

        if (option::is_some(&resolver)) {
            // only DAO admin can execute the proposal directly
            assert!(*option::borrow(&resolver) == dao.admin, error::permission_denied(EINVALID_ADMIN_ACCOUNT));
            execute_proposal(proposal, dao);
            proposal.resolution = PROPOSAL_RESOLVED_BY_ADMIN;
            // return early befor emitting the normal resolve event.
            return
        };
