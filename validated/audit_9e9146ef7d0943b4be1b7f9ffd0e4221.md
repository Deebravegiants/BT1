Audit Report

## Title
Missing path-containment check in `newHTTPFetcher` allows workflow-owner-controlled URL to escape the configured base path - (File: `core/services/workflows/syncer/v2/fetcher.go`)

## Summary
`newFileFetcher` in `core/services/workflows/syncer/v2/fetcher.go` enforces that a resolved path stays under `basePath` via an explicit separator-safe prefix check [1](#0-0) , but the sibling `newHTTPFetcher` only runs `filepath.Clean`/`filepath.Join` on the attacker-supplied `req.URL` and never re-verifies the resulting path is still under the configured base path segment [2](#0-1) . I traced the exact arithmetic: with `baseURL` path `/org-a/workflows/` and `req.URL = "../../org-b/secrets/config.json"`, `filepath.Clean` leaves the leading `..` segments intact (no leading slash to trim), and `filepath.Join("/org-a/workflows/", "../../org-b/secrets/config.json")` normalizes to `/org-b/secrets/config.json` — confirming the escape described in the PoC.

## Finding Description
`req.URL` reaching `newHTTPFetcher` originates from workflow-owner-supplied `binaryURL`/`configURL` fields passed unchanged into `ghcapabilities.Request{URL: ...}` in `Store.FetchWorkflowArtifacts` [3](#0-2) [4](#0-3) . These values are only redirected to a signed-URL when their parsed `Host` equals `ArtifactStorageHost` [5](#0-4) ; a relative-path value such as `"../../org-b/secrets/config.json"` parses with an empty `Host`, bypassing that check and flowing straight to the configured `fetchFn`. `newHTTPFetcher` cleans and joins this value onto the base URL's path with no post-join containment check, unlike `newFileFetcher`'s explicit `strings.HasPrefix(fullPath, basePath+string(filepath.Separator))` guard. This is a genuine asymmetry in the codebase between the two `FetcherFunc` implementations.

However, this code path is only reachable in an operator-configured deployment. The default/production wiring in `core/services/cre/cre.go`'s `newFetcherServiceV2` uses `syncerV2.NewFetcherService(...).Fetch` (the gateway-connector-based fetcher) as `fetchFn`, not `NewFetcherFunc`/`newHTTPFetcher` [6](#0-5) . `newHTTPFetcher` is only exercised when an `opts.FetcherFunc` override is supplied — an override used in local/dev CRE tooling. So exploitation additionally requires the operator to have opted into this non-default local HTTP-fetcher mode with a base URL that assumes sub-path scoping.

## Impact Explanation
Where triggered, the bug allows a workflow owner to make the node fetch content from arbitrary paths on the configured fetch host, beyond the sub-path the operator intended to restrict — an allowlist/scope bypass, not full SSRF (host is fixed). This maps to the "allowlist or subscription bypass" impact category, but severity is bounded because it only applies to a non-default, operator-opted-in HTTP fetcher configuration rather than the standard gateway-based production fetch path.

## Likelihood Explanation
Reaching this code requires an operator to deliberately configure the local/dev `NewFetcherFunc` HTTP fetcher (rather than the default gateway-connector-based `FetcherService.Fetch`) with a base URL that assumes an unenforced sub-path restriction, and a workflow owner registering a crafted relative `binaryURL`/`configURL` containing `../` sequences. No special privilege beyond ordinary workflow registration is needed once that specific configuration is in place, but it does not affect the default production configuration path.

## Recommendation
Add the same containment check used in `newFileFetcher` to `newHTTPFetcher`: after `filepath.Join`, verify the resulting `u.Path` retains the original base path as a prefix (with a separator boundary) and reject the request otherwise.

## Proof of Concept
1. Configure `NewFetcherFunc` (local/dev CRE fetcher override) with `baseURL = "https://artifacts.example.com/org-a/workflows/"`.
2. Register a workflow with `binaryURL = "../../org-b/secrets/config.json"` (parses with empty `Host`, bypassing the `ArtifactStorageHost` signed-URL redirection in `Store.FetchWorkflowArtifacts`).
3. `newHTTPFetcher` computes `cleanPath = "../../org-b/secrets/config.json"` and `u.Path = filepath.Join("/org-a/workflows/", cleanPath)`, which resolves to `/org-b/secrets/config.json`, escaping the intended `/org-a/workflows/` scope with no containment check, unlike `newFileFetcher` [2](#0-1) .

func newFetcherServiceV2(
	opts Opts,
	capCfg config.Capabilities,
	lggr logger.Logger,
	gatewayConnectorWrapper *gatewayconnector.ServiceWrapper,
) (wftypes.FetcherFunc, wftypes.LocationRetrieverFunc, []commonsrv.Service, error) {
	if opts.FetcherFunc != nil {
		return opts.FetcherFunc, nil, []commonsrv.Service{}, nil
	}

	if gatewayConnectorWrapper == nil {
		return nil, nil, nil, errors.New("unable to create workflow registry syncer without gateway connector")
	}

	wfStorage := capCfg.WorkflowRegistry().WorkflowStorage()
	storageClient := opts.StorageClient
	if wfStorage.URL() != "" {
		workflowOpts := []storage.WorkflowClientOpt{
			storage.WithJWTGenerator(opts.JWTGenerator),
		}
		if wfStorage.TLSEnabled() {
			workflowOpts = append(workflowOpts, storage.WithWorkflowTransportCredentials(credentials.NewClientTLSFromCert(nil, "")))
		}

		sc, err := storage.NewWorkflowClient(lggr, wfStorage.URL(), workflowOpts...)
		if err != nil {
			return nil, nil, nil, fmt.Errorf("failed to create storage client: %w", err)
		}

		storageClient = sc
	}

	if storageClient == nil {
		return nil, nil, nil, errors.New("must have a storage client")
	}

	fetcher := syncerV2.NewFetcherService(lggr, gatewayConnectorWrapper, storageClient)
	return fetcher.Fetch, fetcher.RetrieveURL, []commonsrv.Service{fetcher}, nil
}
