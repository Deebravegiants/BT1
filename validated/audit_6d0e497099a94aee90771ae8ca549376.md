### Title
Non-embedded OAuth session cookie value is used directly as the session-lookup key with no integrity binding, enabling cross-tenant session hijack via cookie forgery - (File: `lib/shopify_api/utils/session_utils.rb`, `lib/shopify_api/auth/oauth/session_cookie.rb`)

### Summary
For non-embedded apps, `ShopifyAPI::Auth::Oauth.validate_auth_callback` sets a browser cookie whose `value` is literally the session id (`"offline_#{shop}"` for offline sessions, or `"#{shop}_#{user_id}"` for online sessions). `ShopifyAPI::Utils::SessionUtils.current_session_id` / `cookie_session_id` then take that raw, unauthenticated cookie value straight from the incoming request and hand it back to the host application as the key used to fetch the persisted `Session` (containing the merchant's access token) from storage. The cookie has no HMAC, signature, or any cryptographic binding to the actual authenticated shop — it is bytes the client controls being trusted as an identity/session key.
