### Title
Simplex's Uniswap V4 venue pricing derives order fill prices directly from the pool's live spot price with no manipulation resistance - ([File: sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts])

### Summary
`UniswapV4FundingPlanner.getExoticTokenPrice` / `computeDirectPoolPriceUsd` prices a curveless order pair directly off the Uniswap V4 pool's current `sqrtPriceX96` (spot tick), exactly the "read the live reserves/spot price and use it as the trusted price" pattern flagged in the Tokemak `MavEthOracle` report. There is no TWAP, no reserve-depth sanity check, and the only mitigation (`checkPriceGuard`/`maxDeviationBps`) is optional and only bounds deviation from a static, manually configured reference — it does nothing to detect or prevent an attacker manipulating the pool immediately before an order is priced.

### Finding Description
When a pair has no `bidPriceCurve`/`askPriceCurve` configured and is backed by a `[vault.uniswapV4]` position, Simplex prices it entirely from the pool's live state: [1](#0-0) 

`computeDirectPoolPriceUsd` returns the raw pool mid computed straight from `sqrtPriceX96` via the Uniswap SDK's `token0Price`/`token1Price`: [2](#0-1) 

The project's own flow documentation confirms this is the raw spot mid with no execution-cost or manipulation defense beyond an optional static-reference deviation check: [3](#0-2) 

The pricing docs explicitly note the guard is optional ("omit both to leave the chain unguarded") and only checks deviation from a fixed `referencePrice`, not manipulation within tolerance or execution cost: [4](#0-3) 

Because `getExoticTokenPrice` is called on-demand (via `refresh()`) right before pricing/funding a fill, and because Uniswap V4 pool spot price can be moved arbitrarily within a single transaction (flash swap against the pool, or any large same-block swap) without needing to hold the pool's liquidity, an attacker can:
1. Manipulate the target pool's spot price via a swap.
2. Immediately submit (or have already pending) an intent order on the curveless pair that Simplex prices from that pool.
3. Have Simplex compute `bid`/`ask` off the skewed spot price — within the configured `maxDeviationBps` tolerance if one exists, or completely unguarded if the pair has no `referencePrice` configured — and fill the order, transferring solver-held funds at a manipulated exchange rate.
4. Reverse the pool manipulation (arbitrage it back), pocketing the difference at the solver's expense.

This is the same root cause as the reported issue: computing a price from directly-readable, atomically-manipulable pool state (spot reserves/price) instead of a manipulation-resistant mechanism (TWAP, external oracle cross-check, or liquidity-depth-aware pricing).

### Impact Explanation
A successful manipulation causes Simplex to fill an order at an incorrect price, directly transferring solver capital to the attacker (theft of solver-held liquidity) or, symmetrically, could cause the solver to under-price the user's expected output (loss of user funds). Since venue-priced pairs also fund the fill by withdrawing liquidity from the same manipulated position (`planWithdrawalForToken`), the attack combines mispricing with sourcing directly from the distorted pool. This is a High-severity, concrete-loss-of-funds issue reachable purely by submitting an intent order plus a pool swap, consistent with the reachable "intent solver" class in scope.

### Likelihood Explanation
Likelihood is meaningful whenever a pair's V4 position lives in a pool with liquidity thin enough to move price cheaply relative to the order size Simplex will fill, or whenever a chain/pair has been configured without `referencePrice`/`maxDeviationBps` (explicitly supported and documented as leaving the chain "unguarded"). Even where a static guard is configured, it only bounds absolute deviation, not manipulation that stays within the configured tolerance band, so a calibrated attack can still profit while remaining "valid" by the guard's own check.

### Recommendation
Do not price fills directly from a single spot read (`sqrtPriceX96` at query time). Use a manipulation-resistant price source instead: a time-weighted average price over the pool's oracle observations (if available), cross-validate against an independent price feed (e.g., CEX/aggregator price) before accepting a pool-derived quote, and/or require `referencePrice`/`maxDeviationBps` to be mandatory (not optional) for any pair relying on `[vault.uniswapV4]` pricing. Additionally, consider adding a liquidity-depth/slippage-aware price rather than treating the mid-tick price as the trade price for the full order size.

### Proof of Concept
1. Configure a curveless pair priced from a Uniswap V4 position (`[vault.uniswapV4]`) without `referencePrice`/`maxDeviationBps` (a supported, documented configuration).
2. Attacker performs a large swap against the pool backing that position, moving `sqrtPriceX96` far from the pool's pre-manipulation equilibrium.
3. Attacker (or an accomplice) submits an intent order on the affected pair; `getExoticTokenPrice`/`computeDirectPoolPriceUsd` reads the manipulated spot price and Simplex prices/fills the order accordingly (`sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts:206-275`).
4. Attacker reverses the initial swap, netting the price difference at the solver's expense.

	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}

	private computeDirectPoolPriceUsd(
		pos: HydratedV4Position,
		sdkPool: V4Pool,
		chain: string,
	): { exoticToken: string; priceUsd: Decimal } | null {
		const usdc = this.configService.getUsdcAsset(chain).toLowerCase()
		const usdt = this.configService.getUsdtAsset(chain).toLowerCase()
		const c0 = pos.currency0.toLowerCase()
		const c1 = pos.currency1.toLowerCase()

		if (c0 === usdc || c0 === usdt) {
			// currency0 is stable → exotic is currency1
			// token1Price = "token0 per token1" = USD per exotic
			return {
				exoticToken: c1,
				priceUsd: new Decimal(sdkPool.token1Price.toFixed(18)),
			}
		}

		if (c1 === usdc || c1 === usdt) {
			// currency1 is stable → exotic is currency0
			// token0Price = "token1 per token0" = USD per exotic
			return {
				exoticToken: c0,
				priceUsd: new Decimal(sdkPool.token0Price.toFixed(18)),
			}
		}

		return null
	}

## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.

```toml lineNumbers
[vault.uniswapV4]
# referencePrice is the expected cNGN per USD;
# reject if the quote is more than 2% off.
# The two go together — one without the other is rejected.
[[vault.uniswapV4.positions]]
chain           = "EVM-8453"
tokenId         = "2087350"
referencePrice  = "1575"
maxDeviationBps = 200
```
