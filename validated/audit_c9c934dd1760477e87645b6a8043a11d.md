### Title
Stale oracle snapshot survives an oracle update inside the `flash_position` callback - ([File: contracts/controller/src/strategies/flash_position.rs]) [1](#0-0) 

### Summary
`flash_position` prefetches every required price into an invocation-local `Context`, invokes an arbitrary receiver contract, then performs its final solvency checks with that unchanged snapshot. [1](#0-0)  The receiver can execute an already-ready governance `ConfigureAssetOracle` operation during the callback, but the subsequent risk gate still uses the pre-callback `PriceFeedRaw`. [2](#0-1) [3](#0-2) 

### Finding Description
`process_flash_position` calls `prefetch_strategy_prices` before `mint_and_forward` and `invoke_receiver`. [4](#0-3)  `Context::fetch_prices` fills `token_prices`, `cached_price` later returns that retained entry, and no code invalidates it after the external callback. [2](#0-1) 

A callback is not limited to token transfers: it is a caller-selected WASM contract invoked with arbitrary `data`. [5](#0-4) [6](#0-5)  Governance permits `executor=None`, so any address can execute a ready, non-expired scheduled operation. [7](#0-6)  A scheduled `AdminOperation::ConfigureAssetOracle` resolves to the price aggregator's owner-gated `set_oracle` entrypoint. [3](#0-2)  The aggregator registers the replacement oracle configuration and its validation/sanity settings for subsequent reads. [8](#0-7) 

After the callback returns, the controller deposits measured collateral and calls `strategy_finalize`, whose solvency gate uses the same `Context`; it does not refetch the replacement oracle's price or validity status. [9](#0-8) [10](#0-9)  This is the stale-object analogue: the callback changes the oracle object/configuration that the earlier price snapshot was derived from, while the lending flow continues using the stale snapshot as if it were still current.

### Impact Explanation
The attacker can open a `flash_position` account whose measured collateral passes LTV, health-factor, and minimum-collateral checks only under the pre-callback oracle result. [10](#0-9)  Once the transaction commits, subsequent controller valuations use the newly installed oracle, leaving the account undercollateralized or temporarily unpriceable while the attacker retains the borrowed asset proceeds. [11](#0-10)  If the collateral's new live value cannot cover the minted debt, liquidation leaves residual debt that `clean_bad_debt` ultimately socializes into the supply index, transferring the loss to suppliers. [12](#0-11) [13](#0-12) 

### Likelihood Explanation
The exploit requires a governance oracle operation affecting the declared collateral or debt asset to already be in the Ready state, which is a timing precondition rather than a privileged action by the attacker. [7](#0-6)  The attacker's receiver can encode the operation's `target`, `function`, `args`, `predecessor`, and `salt` in `data` and invoke `execute` with `executor=None` inside `execute_flash_position`. [14](#0-13)  Because controller reentry is blocked but governance and the price aggregator are separate contracts, this nested call does not need to reenter the controller to invalidate the assumptions behind its cached price. [15](#0-14) 

### Recommendation
Do not reuse an oracle snapshot across an arbitrary `flash_position` receiver callback for final risk checks. After `invoke_receiver` returns, either create a fresh `Context` and refetch every account and strategy asset price before `strategy_finalize`, or clear `token_prices`/`market_indexes` before finalization. If price consistency between the entry and settlement phases is required, record an oracle configuration/version or registry epoch in the price aggregator and reject the flash position whenever it changes during the callback.

### Proof of Concept
1. Governance has scheduled `ConfigureAssetOracle` for collateral token `C`, replacing its oracle with a configuration whose current resolved value is materially lower; the operation is Ready.
2. Attacker deploys receiver `R`, calls:
   ```text
   controller.flash_position(
       caller = R,
       account_id = 0,
       spoke_id = S,
       mode = Multiply,
       debt = D,
       amount = A,
       receiver = R,
       data = encoded_ready_oracle_op,
       collaterals = [(C, min_C)],
       refund_assets = [],
   )
   ```
3. Before the callback, the controller caches the old price for `C` and `D`, mints `A` of debt `D`, and forwards the measured tokens to `R`. [4](#0-3) 
4. Inside `execute_flash_position`, `R` executes:
   ```text
   governance.execute(
       executor = None,
       target = price_aggregator,
       function = "set_oracle",
       args = resolved_new_oracle_args_for_C,
       predecessor = scheduled_predecessor,
       salt = scheduled_salt,
   )
   ```
   then swaps part of `A` into at least `min_C` of `C` and transfers `min_C` to the controller. [7](#0-6) 
5. The measured collateral deposit succeeds, but `strategy_finalize` still reads the old cached `C` price from `Context::token_prices`. [16](#0-15)  The account therefore passes the final solvency gate even though a fresh aggregator read would value `C` under the replacement oracle installed during the callback. [9](#0-8) 
6. The transaction commits with `D` debt retained and `C` collateral retained; the attacker keeps the unspent proceeds and abandons or liquidates the undercollateralized account, leaving suppliers to absorb any residual bad debt. [13](#0-12)

    /// Fetches missing prices in one aggregator call; retains cached prices.
    pub(crate) fn fetch_prices(&mut self, assets: &Vec<Address>) {
        let missing = collect_uncached_keys(&self.env, assets, &self.token_prices);
        if missing.is_empty() {
            return;
        }
        let fetched = external::price_aggregator::fetch_prices(&self.env, &missing);
        for (asset, feed) in fetched.iter() {
            self.token_prices.set(asset, feed);
        }
    }

    /// Returns a previously loaded price; fails if the cache has no entry.
    pub(crate) fn cached_price(&mut self, asset: &Address) -> PriceFeed {
        let raw = self
            .token_prices
            .get(asset.clone())
            .unwrap_or_else(|| panic_with_error!(&self.env, OracleError::OracleNotConfigured));
        (&raw).into()
    }
