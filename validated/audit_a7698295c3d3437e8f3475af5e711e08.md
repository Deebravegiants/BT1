### Title
Unbounded accrued debt value permanently freezes an entire market before the borrow-index cap - (File: `common/src/rates/simulate.rs`)

### Summary
Pool accrual converts scaled debt into its underlying RAY value using `i128` arithmetic. A sufficiently large, high-decimal market can make that value exceed `i128::MAX` while `borrow_index` remains below the protocol’s `MAX_BORROW_INDEX_RAY` cap. Because every market mutation synchronizes interest before performing the requested operation, the first arithmetic overflow makes all subsequent withdrawals, repayments, liquidations, and index updates on that market revert permanently. [1](#0-0) 

### Finding Description
`Controller::update_indexes` is permissionless except for caller authorization and forwards the attacker-selected `assets` list to the pool. [2](#0-1) [3](#0-2) 

The pool iterates those markets and calls `interest::global_sync` for each one. [4](#0-3)  `global_sync` accrues all elapsed time in chunks of at most one year, but each chunk still computes debt and index values with bounded `i128` fixed-point arithmetic. [5](#0-4) 

The intended index ceiling does not prevent this failure: raw debt value can overflow `i128` before `borrow_index` reaches `MAX_BORROW_INDEX_RAY`. [6](#0-5)  Once the market enters that state, `last_timestamp` remains behind ledger time because the accrual transaction reverts, so every later call repeats the same overflowing calculation. [7](#0-6) 

### Impact Explanation
This permanently freezes the affected market rather than merely rejecting one oversized transaction. The repository’s own regression test demonstrates that the same `MathOverflow` blocks `update_indexes`, supplier withdrawal, and borrower repayment. [8](#0-7) 

Consequently, suppliers cannot withdraw, borrowers cannot reduce debt, liquidators cannot complete a liquidation that touches the market, and governance cannot rescue the book through ordinary market calls. This satisfies permanent freezing of user funds and can progress to protocol insolvency because the debt can neither be collected nor cleanly processed. [9](#0-8) 

### Likelihood Explanation
An unprivileged user can trigger the fatal accrual through `Controller::update_indexes(caller, assets)` once the market has reached the vulnerable state. [2](#0-1) [3](#0-2) 

The precondition is economically demanding: the production test uses a billion-unit, 18-decimal market at approximately 98% utilization and advances time until the RAY-value ceiling is reached. [10](#0-9)  The bug is therefore not an instant griefing attack on ordinary markets, but it is reachable through normal unprivileged `supply`, `borrow`, and `update_indexes` operations on a sufficiently large listed market. [2](#0-1) 

### Recommendation
Bound the value calculation before multiplying scaled debt by the borrow index. Accrual should check whether `scaled_amount * borrow_index / RAY` can exceed the representable range and cap or process the accrual through a wider intermediate type before converting to `i128`. The borrow-index ceiling should be enforced before any fixed-point value calculation that can overflow, and the accrual path should be able to clamp an over-limit market to `MAX_BORROW_INDEX_RAY` while still committing `last_timestamp`, preserving exits and repayments.

### Proof of Concept
The repository contains a native proof at `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs`. It creates `BIG18` with 18 decimals, supplies `principal = BILLION * 10^18`, supplies separate collateral, and borrows approximately 98% of the large market. [11](#0-10) 

It then advances ledger time one year at a time and calls the permissionless index-refresh path until the call fails. [12](#0-11)  The failure is `MathOverflow`, while `borrow_index` remains below `MAX_BORROW_INDEX_RAY`. [13](#0-12) 

The test subsequently proves market liveness is lost: both a 1-unit supplier withdrawal and a borrower repayment fail with the same `MathOverflow` because each operation accrues first. [14](#0-13)

        .with_market(col())
        .with_max_utilization_disabled_all_markets()

    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"

        t.advance_time(YEAR_SECS);

    assert_contract_error(failed, errors::MATH_OVERFLOW);

    assert!(

        "the index cap did not engage before the value overflow"

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
