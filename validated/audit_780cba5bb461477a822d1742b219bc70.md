Confirmed: `CallDispatcher` is a single shared, stateless, permissionless contract (any address's `Call[]` can target it) — it holds `receive() external payable {}` and forwards arbitrary calls via `dispatch`. Since `_params.dispatcher` points at one shared `CallDispatcher` instance used by every `placeOrder` call across all users, its balance is not scoped to a single order's execution, which is exactly why snapshotting balance-before is required to isolate what a specific order's predispatch call produced.

### Title
Predispatch sweep in Tron IntentGatewayV2.placeOrder uses shared dispatcher's raw balanceOf instead of before/after diff, causing stray funds to be misattributed as "dust" - (File: evm/tron/contracts/apps/IntentGatewayV2.sol)

### Summary
`IntentGatewayV2.placeOrder` on the Tron fork sweeps tokens from the shared `CallDispatcher` back into the gateway by reading `IERC20(token).balanceOf(dispatcher)` directly, rather than snapshotting the dispatcher's balance immediately before the predispatch call and diffing afterward. This mirrors the JOJO `FlashLoanLiquidate`/`FlashLoanRepay` bug class of using an absolute contract balance as a proxy for "amount received in this call."

### Finding Description
In `evm/tron/contracts/apps/IntentGatewayV2.sol` `placeOrder`, when `order.predispatch.call` and `order.predispatch.assets` are set:
1. Predispatch assets are transferred to the shared `dispatcher` (`_params.dispatcher`, a `CallDispatcher` instance shared by every user/order — see `evm/src/utils/CallDispatcher.sol`), and the arbitrary predispatch call is dispatched.
2. For each input token, the contract reads `balance = IERC20(token).balanceOf(dispatcher)` and treats the *entire* balance as belonging to this order: [1](#0-0) 
3. `dust = balance - requiredAmount` is emitted as `DustCollected`, and the whole `balance` is swept into the gateway via `transferCalls[i]` — none of this isolates funds actually produced by *this* order's predispatch call from any pre-existing residue sitting on the shared `dispatcher` (e.g., leftover from a prior order whose sweep call reverted or was only partially executed, a stray/donated transfer, or slippage residue from an unrelated swap routed through the same dispatcher).

By contrast, the non-Tron EVM version of the same contract fixes exactly this by snapshotting `balancesBefore[i]` before the sweep and computing `received = balanceOf(address(this)) - balancesBefore[i]`: [2](#0-1) 

The Tron contract lacks this before/after snapshot on the read side (`balanceOf(dispatcher)`), so it cannot distinguish "funds this predispatch call produced" from "whatever balance happens to sit on the shared dispatcher at that moment," exactly the root cause identified in the JOJO report (`balanceOf(address(this))` used instead of a delta check).

### Impact Explanation
Because `_orders[commitment][token] += reducedInputs[i].amount` only credits the fixed, user-declared `order.inputs` amount (not the swept `balance`), any surplus swept in as `dust` is pulled into the gateway but never credited to any commitment — it becomes unaccounted, permanently stuck balance. If that surplus originated from another user's stranded funds on the shared dispatcher (e.g., a prior predispatch execution that left residue due to slippage or a partially-failed sweep), those funds are permanently and irrecoverably absorbed into the gateway's general balance by whichever unrelated order next happens to sweep that token from the dispatcher — a permanent freezing/loss of funds for the original depositor, with no escrow entry pointing back to them. This satisfies the "permanent freezing of funds" impact bar.

### Likelihood Explanation
Likelihood is realistic because: (1) `dispatcher` is a single shared, permissionless `CallDispatcher` reused across all orders and all users — nothing scopes its balance per-call; (2) predispatch calls execute attacker/solver-supplied arbitrary calldata (`order.predispatch.call`), so imperfect sweeps, reverted partial legs, or AMM slippage routinely leave residue on the dispatcher between transactions; (3) any subsequent `placeOrder` with predispatch enabled for the same token will unconditionally absorb whatever balance sits there at that moment, with no way to attribute or refund it.

### Recommendation
Snapshot `balanceOf(dispatcher)` (and `address(dispatcher).balance` for native) immediately before dispatching the predispatch call, then compute the swept/received amount as the post-call balance minus that snapshot, matching the pattern already implemented in the non-Tron `evm/src/apps/IntentGatewayV2.sol`. Use this delta — not the raw balance — both for the `InsufficientNativeToken`/`InvalidInput` sufficiency check and for the `DustCollected` amount.

### Proof of Concept
1. Two independent orders, A and B, both use the same input token via the predispatch path, targeting the same shared `dispatcher`.
2. Order A's predispatch call executes a swap on the dispatcher that yields slightly more output token than `requiredAmount` (common with AMMs/aggregators), but Order A's final `transferCalls` sweep is executed as part of the same tx — so in isolation A's own dust is intentionally collected and correctly attributed to A's tx.
3. Now suppose a griefer directly `transfer`s stray tokens to the `dispatcher` address in a prior transaction (dispatcher has `receive() external payable {}` and, being a generic forwarding contract, can hold arbitrary ERC20 balances sent directly by anyone), or a previous order's transferCalls dispatch reverted after assets were deposited but its escrow bookkeeping already ran in a separate call, leaving stray balance.
4. The next unrelated user, Order C, calls `placeOrder` with predispatch for the same token. `balance = IERC20(token).balanceOf(dispatcher)` now includes both C's own predispatch proceeds and the stray/stranded tokens.
5. `dust = balance - requiredAmount` is computed and swept entirely into the gateway; the stray tokens are absorbed as unattributed `DustCollected` dust with no escrow entry crediting the original owner — those funds are now permanently unrecoverable by their rightful owner. [3](#0-2) [4](#0-3)

    /**
     * @dev Receive function to accept ETH transfers
     */
    receive() external payable {}

    /**
     *  @dev reverts if the target is not a contract or if any of the calls reverts.
     */
    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
