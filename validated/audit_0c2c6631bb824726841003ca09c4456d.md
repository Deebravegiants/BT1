### Title
Unrestricted `CallDispatcher.dispatch()` lets anyone drain native tokens held by the contract to an attacker-controlled address - (File: evm/src/utils/CallDispatcher.sol)

### Summary
`CallDispatcher` accepts native tokens via an unrestricted `receive()` and exposes a completely permissionless `dispatch()` function that forwards arbitrary amounts of the contract's own native-token balance to any attacker-chosen target. Unlike the reported `Anchor.sol`/`DonationVotingMerkleDistributionBaseStrategy.sol`/`RFPSimpleStrategy.sol` pattern (native tokens simply get stuck with no recovery path), here the missing access control on the "recovery" pathway is actively worse: it turns any native balance sitting in this contract into instantly stealable funds by any unprivileged caller, not merely frozen funds.

### Finding Description
`CallDispatcher` is a general-purpose call-forwarding utility used by Hyperbridge's cross-chain apps (e.g. `WrappedHyperFungibleToken`/`WrappedHyperFungibleTokenUpgradeable` invoke `ICallDispatcher(_dispatcher).dispatch(message.data)` after delivering a bridged transfer, and `IntentGatewayV2` documents receiving "swept balances from the CallDispatcher"). [1](#0-0) 

The contract declares:
```solidity
receive() external payable {}

function dispatch(bytes memory encoded) external {
    Call[] memory calls = abi.decode(encoded, (Call[]));
    ...
    (bool success, bytes memory result) = to.call{value: call.value}(call.data);
    if (!success) revert CallFailed(to, result);
}
``` [2](#0-1) 

`dispatch` has no `msg.sender` restriction (no `onlyOwner`, no `restrict`, no caller allowlist) and it is not `payable` — the `value` sent in each `Call` is pulled from the contract's own existing native-token balance, not from `msg.value` of the call to `dispatch`. Because `receive()` is unrestricted, any native token that lands in `CallDispatcher` (sent directly by mistake, or accumulated as part of any cross-chain execution flow that routes value through it) can be swept out by literally anyone: an attacker simply calls `dispatch()` themselves with a `Call[]` targeting a contract they control and `value` equal to the current balance.

### Impact Explanation
This exceeds the "stuck funds" class described in the reference report — it is a direct, permissionless theft primitive. Any native token balance the `CallDispatcher` holds at any point (accidental transfers, dust, or balances forwarded as part of app-level execution flows that use this shared dispatcher) can be extracted by the first attacker to call `dispatch()`, front-running the intended recipient. This satisfies the "concrete theft of funds" bar because the loss is not merely permanent illiquidity but active redirection of value to an attacker-chosen address.

### Likelihood Explanation
Likelihood is high for any scenario where native ETH temporarily or permanently resides in `CallDispatcher`: the `receive()` function accepts native tokens from anyone with no gate, and exploitation requires only a single unprivileged transaction calling the already-public `dispatch()` function with attacker-supplied calldata — no proofs, no privileged role, and no cross-chain message needed to trigger the drain itself.

### Recommendation
Restrict `CallDispatcher.dispatch()` to be callable only by the specific authorized app contract(s) that are meant to route calls through it (e.g., via an immutable allowlist set at construction, similar to `onlyHost`/`restrict` patterns used elsewhere in the codebase such as `EvmHost`'s `restrict(_hostParams.hostManager)` withdraw guard). Additionally, ensure the `receive()` function either rejects unsolicited native-token transfers or that any value routed through `dispatch()` originates from `msg.value` of the same call rather than from the contract's standing balance, eliminating the possibility of draining balances left by prior/failed operations.

### Proof of Concept
1. Native token is sent to `CallDispatcher` (e.g., accidental direct transfer via `receive()`, or a partial/failed execution flow leaves a balance).
2. Attacker deploys a trivial contract `Attacker` with a payable `receive()`.
3. Attacker calls `CallDispatcher.dispatch(encoded)` where `encoded` decodes to `Call[] { to: address(Attacker), value: address(CallDispatcher).balance, data: "" }`.
4. `dispatch()` executes `to.call{value: call.value}(call.data)` with no caller check, transferring the entire native balance to `Attacker`. [3](#0-2)

    /**
     * @dev Receive function to accept ETH transfers
     */
    receive() external payable {}

    /**
     *  @dev reverts if the target is not a contract or if any of the calls reverts.
     */
    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
```
