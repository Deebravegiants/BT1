### Title
Unbounded RAY debt-value multiplication permanently freezes large high-utilization markets before the borrow-index cap - (File: common/src/rates/index.rs)

### Summary
Interest accrual caps `borrow_index`, but it first multiplies the full scaled-debt book by the new index using an `i128` RAY result, so a sufficiently large market can overflow the debt value before the index cap is reached. [1](#0-0)  Every pool mutation loads and accrues the market before executing, so after the overflow all exits, repayments, liquidations, index updates, and other operations touching that market revert. [2](#0-1) 

### Finding Description
`global_sync` processes elapsed time in bounded chunks and invokes `accrue_chunk` for every chunk before committing the market. [3](#0-2)  `accrue_chunk` delegates index growth and interest allocation to `accrue_step`, then stores the resulting indexes and revenue shares. [4](#0-3)  Although `update_borrow_index` clamps the index to `MAX_BORROW_INDEX_RAY`, `calculate_supplier_rewards` still computes both old and new total debt as `borrowed.mul(index)`. [5](#0-4) [6](#0-5)  `Ray::mul` resolves to `mul_div_half_up`, which panics with `MathOverflow` if the resulting RAY value does not fit in `i128`. [7](#0-6) [8](#0-7)  Therefore, the market can hit a finite RAY-value ceiling well before `MAX_BORROW_INDEX_RAY` limits index growth.

The vulnerable state is reachable through normal controller usage: `supply` deposits user assets and `borrow` mints debt against collateral. [9](#0-8) [10](#0-9)  Withdrawals and repayments both call `ops::load_leg`, which always performs `global_sync` before processing the leg. [11](#0-10) [12](#0-11)  Permissionless `update_indexes` reaches the same accrual directly, while liquidation uses the same repayment and withdrawal pool primitives. [13](#0-12) [14](#0-13) [15](#0-14) 

### Impact Explanation
Once the market crosses the overflow boundary, every subsequent operation that must accrue interest reverts before any user-specific amount check or mutation. [16](#0-15)  Suppliers cannot withdraw, borrowers cannot repay, liquidators cannot unwind the account, and anyone calling `update_indexes` receives `MathOverflow`. [17](#0-16) [18](#0-17)  Because `last_timestamp` remains stale, waiting does not make the accrual smaller, so user funds in that market are permanently frozen absent a privileged code upgrade.

### Likelihood Explanation
The attack requires a very large debt book and enough elapsed high-rate accrual for `scaled_debt * borrow_index / RAY` to exceed `i128::MAX`, but the attacker only needs ordinary collateral, token liquidity, and public entrypoints. [19](#0-18)  The repository’s own controller-level reproduction uses a one-billion-token 18-decimal market at 98% utilization and shows that the XLM curve reaches the value overflow before the index cap. [20](#0-19)  Market caps and collateral requirements constrain when this is economically practical, but they do not remove the arithmetic boundary in markets that permit sufficiently large books.

### Recommendation
Make debt-value accrual saturating or widened rather than panicking: compute `borrowed * new_borrow_index` and the delta in `I256`, clamp debt value/index consistently, or calculate accrued interest through a bounded rate decomposition that cannot require an unrepresentable total. Keep `update_indexes`, repayment, withdrawal, liquidation, and bad-debt cleanup functional when the value ceiling is reached, and add coverage at the exact `i128` boundary.

### Proof of Concept
The repository already contains an executable model of this condition:

```rust
// On an 18-decimal market whose rate model and utilization ceiling permit
// sustained 98% utilization:
let principal = 1_000_000_000i128 * 10i128.pow(18);
let debt = principal / 100 * 98;

// Same unprivileged caller creates collateral and debt positions.
controller.supply(attacker, 0, spoke_id, vec![(BIG18, principal)]);
controller.supply(attacker, account_id, spoke_id, vec![(COL, collateral_amount)]);
controller.borrow(attacker, account_id, vec![(BIG18, debt)], None);

// Repeat until scaled_debt * projected_borrow_index exceeds i128::MAX.
controller.update_indexes(attacker, vec![BIG18]);

// Afterwards all of these panic with MathOverflow during accrual:
controller.repay(attacker, account_id, vec![(BIG18, 1)]);
controller.withdraw(attacker, account_id, vec![(BIG18, 1)], None);
controller.update_indexes(attacker, vec![BIG18]);
```

The test creates that market state, advances yearly accrual until `update_indexes` returns `MathOverflow`, confirms `borrow_index < MAX_BORROW_INDEX_RAY`, and then confirms that both withdrawal and repayment fail with the same overflow. [21](#0-20)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
