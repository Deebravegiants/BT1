### Title
`LastRewardedHeight` watermark is never lowered after a state-machine height rollback, permanently under-paying relayers for real work — ([File: modules/pallets/consensus-incentives/src/impls.rs])

### Summary
`pallet-consensus-incentives` pays a relayer `(latest_height - baseline) * cost_per_block` and then raises a monotonic watermark, `LastRewardedHeight`, to `max(old, latest_height)`. This is the direct analog of the Sherlock `navPerShareHighMark` bug: a "high mark" gate that is only ever pushed up and is never reset back down when the underlying accounted state (the state machine's real height) itself drops. When a state machine's committed height is rolled back below the previously recorded watermark (e.g. via the permissionless fisherman veto/fraud-proof path that deletes a bad commitment, `pallet_ismp::PreviousStateMachineHeight`/commitment deletion, exactly as exercised in the repo's own `reward_covers_only_unpaid_heights_after_rollback` test), any later *honest* relayer who re-delivers real, freshly-verified consensus proofs up to — but not yet past — the stale watermark is paid **zero** reward for that entire span, even though genuine new work was done and accepted on-chain.

### Finding Description
`LastRewardedHeight` is defined as a per-`StateMachineId` monotonic watermark: [1](#0-0) 

It's used as the reward baseline and only ever bumped upward via `.max(...)`, never lowered: [2](#0-1) 

The reward calculation uses `saturating_sub`, so once `latest_height` (the real, current, freshly-accepted commitment height for the state machine) falls below the stored watermark, `blocks` is clamped to zero and stays zero until `latest_height` climbs back past the old watermark: [3](#0-2) 

This is structurally identical to the LMPVault bug: `effectiveNavPerShareHighMark`/`navPerShareHighMark` is a monotonic high-water mark gating fee collection; when the underlying accounted value resets to a lower baseline (a full exit in LMPVault; a height rollback here) but the watermark itself is not reset, subsequent genuine "profit" (NAV growth in LMPVault; real chain progress here) below the old mark goes uncompensated. The repository's own test demonstrates the rollback scenario is reachable via `host.delete_state_commitment` plus a stale `PreviousStateMachineHeight` pointer, after which only the *delta above the previous watermark* is paid, never the amount already-rewarded work that has to be re-earned from the rolled-back point: [4](#0-3) 

Height rollbacks for a state machine's commitment are not exclusively an admin action — they occur through Hyperbridge's own permissionless dispute/fraud-proof machinery (`pallet-fishermen`, which vetoes and removes fraudulent or stale state commitments) as well as ordinary consensus-client re-synchronization after a detected fork. Once such a rollback drops `latest_commitment_height` below the recorded `LastRewardedHeight`, every subsequent relayer submitting valid `ConsensusMessage`s that re-advance the chain up to that old mark is rewarded `0` via `Self::calculate_reward`, because `saturating_sub` floors the delta at zero and `LastRewardedHeight` is never itself rolled back to match the new, lower, real height.

### Impact Explanation
This is a loss-of-funds/broken-incentive issue at the core relayer economics layer: relayers who deliver real, cryptographically verified consensus proofs receive no `$BRIDGE` reward and no reputation mint for that work whenever a chain's committed height has previously been rolled back below a stale watermark. Depending on how large the gap is, this can zero out rewards for an extended span of genuinely useful consensus relaying, degrading the "competitive, economically incentivized" relayer model the protocol depends on (per `docs/content/developers/explore/relayers.mdx`) and starving Hyperbridge's view of that state machine of fresh, well-incentivized consensus updates — which in turn risks delaying legitimate cross-chain message verification for that chain. It mirrors the Sherlock M-12 finding's assessed severity: a loss of protocol-controlled reward/fee accrual due to a stale high-water mark, rather than an outright fund-theft primitive.

### Likelihood Explanation
The rollback precondition is reachable through the protocol's own permissionless mechanisms (fisherman disputes / fraud-proof vetoes of state commitments, or ordinary fork-resolution on the source chain) rather than requiring a malicious admin or governance action — the same rollback pattern is deliberately exercised in-repo's regression test, showing the maintainers are aware height can move backward but only patched the "double payment" direction of the bug, not the "zero payment for real work" direction. Once a rollback of this shape occurs on any actively-relayed state machine, every subsequent honest relayer submission is silently affected until height recovers past the old mark.

### Recommendation
When a state machine's `latest_commitment_height` is observed to be lower than the stored `LastRewardedHeight` (i.e. a rollback occurred), reset `LastRewardedHeight` for that `state_machine_id` down to the new, lower `latest_commitment_height` (or to `previous_commitment_height`) rather than leaving the stale, higher watermark in place. This preserves the existing anti-double-payment guarantee for the *unrolled-back* span while ensuring relayers are correctly compensated for the genuinely new work performed to re-advance the chain past the rollback point.

### Proof of Concept
1. Governance configures `cost_per_block` for `state_machine_id` X via `update_cost_per_block`.
2. Relayer submits a valid `ConsensusMessage` advancing X to height 1025; `pallet-consensus-incentives::on_executed` pays the reward and sets `LastRewardedHeight[X] = 1025`.
3. A fisherman (or equivalent permissionless dispute mechanism) proves the commitment at 1025 was invalid/stale and it is deleted, rolling `latest_commitment_height(X)` back to, say, 1.
4. A new, honest relayer submits a fresh, fully valid `ConsensusMessage` advancing X from 1 to 1024 (real, freshly verified progress).
5. `calculate_reward` computes `baseline = LastRewardedHeight[X] = 1025`, `blocks = 1024.saturating_sub(1025) = 0` → reward paid is `0`, despite 1023 blocks of genuine new consensus work being delivered and accepted on-chain. The relayer earns nothing until height surpasses 1025 again. This exact mechanic (rollback → re-advance → reward computed against a stale, un-reset watermark) is already reproduced in the repository's `reward_covers_only_unpaid_heights_after_rollback` test, which only verifies the "no double pay" side and does not address the "zero pay for real re-advance below the old mark" side illustrated above. [5](#0-4)

```rust
// A relayer is paid once for advancing a state machine across a span of heights. When the latest
// height is rolled back and later resubmitted, the reward should still only cover the new blocks.
// The `LastRewardedHeight` watermark keeps each payout scoped to the span that has not been paid.
#[test]
fn reward_covers_only_unpaid_heights_after_rollback() {
	let mut ext = new_test_ext();
	ext.execute_with(|| {
		const BLOCK_COST: u128 = 100;
		let host = Ismp::default();
		let state_machine_id = setup_state_machine();
		let treasury_account: AccountId32 = PalletId(*b"treasury").into_account_truncating();

		pallet_consensus_incentives::Pallet::<Test>::update_cost_per_block(
			RuntimeOrigin::root(),
			state_machine_id,
			BLOCK_COST,
		)
		.unwrap();

		let (consensus_message, relayer_account) = setup_host_and_message(&host);
		let message = MessageWithWeight { message: consensus_message, weight: Weight::zero() };
		let updated = |height: u64| {
			vec![IsmpEvent::StateMachineUpdated(StateMachineUpdated {
				state_machine_id,
				latest_height: height,
			})]
		};

		// The chain has already advanced to 1025 and every block up to it has been rewarded once.
		host.store_state_machine_commitment(
			StateMachineHeight { id: state_machine_id, height: 1024 },
			commitment(),
		)
		.unwrap();
		host.store_latest_commitment_height(StateMachineHeight {
			id: state_machine_id,
			height: 1024,
		})
		.unwrap();
		host.store_state_machine_commitment(
			StateMachineHeight { id: state_machine_id, height: 1025 },
			commitment(),
		)
		.unwrap();
		host.store_latest_commitment_height(StateMachineHeight {
			id: state_machine_id,
			height: 1025,
		})
		.unwrap();

		let treasury_before_first = Balances::balance(&treasury_account);
		<pallet_consensus_incentives::Pallet<Test> as FeeHandler>::on_executed(
			vec![message.clone()],
			updated(1025),
		)
		.unwrap();

		assert_eq!(Balances::balance(&treasury_account), treasury_before_first - BLOCK_COST);
		assert_eq!(
			pallet_consensus_incentives::LastRewardedHeight::<Test>::get(state_machine_id),
			Some(1025)
		);

		// The previous-height pointer references an older height whose commitment is no longer
		// retained in the bounded map.
		pallet_ismp::PreviousStateMachineHeight::<Test>::insert(state_machine_id, 1);

		// Deleting the latest commitment rolls the latest height back to that previous pointer.
		host.delete_state_commitment(StateMachineHeight { id: state_machine_id, height: 1025 })
			.unwrap();
		assert_eq!(host.latest_commitment_height(state_machine_id).unwrap(), 1);

		// The next honest consensus update advances to 1030, carrying the stale pointer forward as
		// the new previous height.
		host.store_state_machine_commitment(
			StateMachineHeight { id: state_machine_id, height: 1030 },
			commitment(),
		)
		.unwrap();
		host.store_latest_commitment_height(StateMachineHeight {
			id: state_machine_id,
			height: 1030,
		})
		.unwrap();
		assert_eq!(host.previous_commitment_height(state_machine_id), Some(1));

		let treasury_before_second = Balances::balance(&treasury_account);
		<pallet_consensus_incentives::Pallet<Test> as FeeHandler>::on_executed(
			vec![message],
			updated(1030),
		)
		.unwrap();

		// The real advance is 1025 -> 1030, so only the 5 new blocks are paid rather than the full
		// span back to the previous pointer.
		assert_eq!(Balances::balance(&treasury_account), treasury_before_second - 5 * BLOCK_COST);
		assert_eq!(
			pallet_consensus_incentives::LastRewardedHeight::<Test>::get(state_machine_id),
			Some(1030)
		);
	})
}
```
