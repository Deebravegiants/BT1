### Title
Client-controlled `MessageID` collision in legacy WebAPI trigger gateway handler causes cross-user response hijack/DoS - (File: `core/services/gateway/handlers/capabilities/handler.go`)

### Summary
The gateway's legacy WebAPI-trigger flow keys its pending-request table (`savedCallbacks`) by `msg.Body.MessageID`, a value taken verbatim from the JSON-RPC `id` field supplied by the unprivileged, internet-facing caller. `HandleLegacyUserMessage` stores (overwrites) an entry under that attacker-chosen key with no uniqueness/ownership check, unlike the newer v2 trigger handler which explicitly rejects duplicate/in-flight IDs. An unprivileged caller can therefore submit a request whose `id` collides with another in-flight legitimate request, hijacking or freezing that other request's response — the same "unprivileged actor supplies an ID that collides with another actor's in-progress/authoritative state" root cause as the twTAP `tokenId` collision bug.

### Finding Description
The gateway's public HTTP entrypoint decodes an inbound JSON-RPC request and uses its user-supplied `id` as the canonical `MessageID` with no server-side regeneration or namespacing: [1](#0-0) 

`gateway.ProcessRequest` (the function invoked directly by the internet-facing HTTP server for user requests) forwards this attacker-controlled `MessageID`/request ID straight into the handler: [2](#0-1) 

For legacy DON-routed requests, `handler.HandleLegacyUserMessage` unconditionally writes into the shared `savedCallbacks` map keyed by this attacker-controlled ID, with **no check for an existing/in-flight entry**: [3](#0-2) 

When a node later responds, `handleWebAPITriggerMessage` looks up and deletes whatever callback is currently stored at that key and resolves it with the incoming payload — it has no way to verify the response actually belongs to the caller who currently owns that callback slot: [4](#0-3) 

The identical unauthenticated-overwrite pattern exists in the dummy/legacy handler implementation as well: [5](#0-4) 

By contrast, the newer v2 HTTP trigger handler explicitly guards against this exact class of bug by rejecting a request whose `requestID` is already in-flight: [6](#0-5) 

This confirms the missing guard in the legacy `handler.go`/`handler.dummy.go` path is a real gap, not an intentional design choice — the newer implementation was hardened against it while the legacy path (still reachable, `Methods()` returns `MethodWebAPITrigger` etc.) was not.

### Impact Explanation
Any unprivileged external caller of the gateway's public endpoint can pick an arbitrary JSON-RPC `id`. By choosing an `id` that matches (or racing to match) another legitimate in-flight request's `id`, the attacker's `HandleLegacyUserMessage` call silently overwrites the victim's `savedCallbacks` entry:
- The victim's original request never resolves its callback (the entry was deleted/replaced), so `callback.Wait(ctx)` in `gateway.ProcessRequest` times out — a denial of service for that specific legitimate request.
- Conversely, when the DON node's response for the victim's original request arrives keyed by the same `MessageID`, it is delivered to whichever callback is *currently* stored at that key — potentially the attacker's own callback — causing the attacker to receive a response payload that was not intended for them (cross-user response confusion / possible data disclosure).

This mirrors the external report's structural weakness: an unauthenticated participant can inject a colliding identifier into shared, unsynchronized state that another (equally unprivileged in this case, but state-critical) party relies on, permanently breaking that party's flow.

### Likelihood Explanation
The gateway's WebAPI-trigger entrypoint is explicitly internet-facing and designed to accept requests from external callers (webhook/trigger clients) without any prior registration of the `id` value. No authentication elevation is needed — only knowledge/prediction or observation of another request's `id` (which may be predictable, e.g., sequential, timestamp-based, or leaked via logs/telemetry) is required to trigger the collision.

### Recommendation
- In `handler.go`'s `HandleLegacyUserMessage` (and `handler.dummy.go`'s `HandleLegacyUserMessage`), check for an existing entry in `savedCallbacks` before inserting, and reject/duplicate-error the new request if the key is already in use — mirroring the guard already implemented in `http_trigger_handler.go`'s `setupCallback`.
- Consider deriving/namespacing the internal map key from a value not fully controlled by the caller (e.g., combine caller identity/session with the supplied ID, or generate a server-side UUID) so that no external, unauthenticated identifier can ever collide with another party's in-flight request.

### Proof of Concept
1. Legitimate User A sends a WebAPI trigger JSON-RPC request to the gateway's public HTTP endpoint with `id = "X"`. The gateway stores `savedCallbacks["X"] = callbackA` in `handler.go` and forwards it to DON nodes.
2. Before User A's response returns, an unprivileged Attacker sends their own request to the same public endpoint using the same `id = "X"`. `HandleLegacyUserMessage` unconditionally overwrites `savedCallbacks["X"] = callbackB` (no existing-key check, per `core/services/gateway/handlers/capabilities/handler.go:411-414`).
3. A DON node responds to User A's original trigger with `MessageID = "X"`. `handleWebAPITriggerMessage` looks up `savedCallbacks["X"]`, finds `callbackB` (the attacker's), deletes the entry, and delivers User A's response payload to the Attacker.
4. User A's `callback.Wait(ctx)` in `gateway.ProcessRequest` never resolves and eventually times out with `RequestTimeoutError`, while the Attacker has received a response not addressed to them.

func (g *gateway) ProcessRequest(ctx context.Context, rawRequest []byte, auth string) (rawResponse []byte, httpStatusCode int) {
	// decode
	jsonRequest, err := jsonrpc2.DecodeRequest[json.RawMessage](rawRequest, auth)
	if err != nil {
		return newError("", api.UserMessageParseError, err.Error())
	}
	msg, err := g.codec.DecodeJSONRequest(jsonRequest)
	if err != nil {
		return newError(jsonRequest.ID, api.UserMessageParseError, err.Error())
	}
	if len(jsonRequest.ID) > 200 {
		// Arbitrary limit to prevent abuse
		return newError(jsonRequest.ID, api.UserMessageParseError, "request ID is too long: "+strconv.Itoa(len(jsonRequest.ID))+". max is 200 characters")
	}
	isLegacyRequest := false
	var h handlers.Handler
	var handlerKey string
	if msg == nil || msg.Body.DonID == "" {
		serviceName := jsonRequest.ServiceName()
		if handler, ok := g.serviceToMultiHandler[serviceName]; ok {
			h = handler
			handlerKey = serviceName
		} else if donID, ok := g.serviceNameToDonID[serviceName]; ok {
			// Fallback to legacy service name -> DON ID mapping
			if handler, ok := g.handlers[donID]; ok {
				h = handler
				handlerKey = donID
			}
		}
		if h == nil {
			return newError(jsonRequest.ID, api.HandlerError, "Service name not found: "+serviceName)
		}
	} else {
		// Legacy request with DON ID - validate and fetch handler
		isLegacyRequest = true
		if err = msg.Validate(); err != nil {
			return newError(jsonRequest.ID, api.UserMessageParseError, err.Error())
		}
		handlerKey = msg.Body.DonID
		var ok bool
		h, ok = g.handlers[handlerKey]
		if !ok {
			return newError(jsonRequest.ID, api.UnsupportedDONIdError, "Unsupported DON ID: "+handlerKey)
		}
	}

	startTime := time.Now()
	var method string
	callback := handlerscommon.NewCallback()
	if isLegacyRequest {
		method = msg.Body.Method
		err = h.HandleLegacyUserMessage(ctx, msg, callback)
	} else {
		method = jsonRequest.Method
		err = h.HandleJSONRPCUserMessage(ctx, jsonRequest, callback)
	}
	if err != nil {
		return newError(jsonRequest.ID, api.HandlerError, err.Error())
	}

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageID]
	delete(h.savedCallbacks, msg.Body.MessageID)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JSONRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
}

func (d *dummyHandler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback Callback) error {
	d.mu.Lock()
	d.savedCallbacks[msg.Body.MessageID] = &savedCallback{msg.Body.MessageID, callback}
	don := d.don
	d.mu.Unlock()
	params, err := json.Marshal(msg)
	if err != nil {
		return err
	}
	rawParams := json.RawMessage(params)
	req := &jsonrpc.Request[json.RawMessage]{
		Version: "2.0",
		ID:      msg.Body.MessageID,
		Method:  msg.Body.Method,
		Params:  &rawParams,
	}
	for _, member := range d.donConfig.Members {
		err = errors.Join(err, don.SendToNode(ctx, member.Address, req))
	}
	return err
}
