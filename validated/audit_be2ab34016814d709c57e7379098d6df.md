The Polkadot SDK analog to the V3 Proxy swap function is `pallet_asset_conversion`'s `swap_exact_tokens_for_tokens` / `swap_tokens_for_exact_tokens` extrinsics and their underlying `Swap` trait implementation. Unlike the reported Solidity bug, where the router call hardcoded `msg.sender` instead of using the caller-supplied `to` parameter, the FRAME implementation correctly threads the caller-supplied `send_to` parameter through to the actual token transfer:

- The extrinsics `swap_exact_tokens_for_tokens`/`swap_tokens_for_exact_tokens` take `send_to: T::AccountId` as an explicit parameter and pass it into `do_swap_exact_tokens_for_tokens`/`do_swap_tokens_for_exact_tokens`. [1](#0-0) 

- Inside `do_swap_exact_tokens_for_tokens`, the `send_to` value is passed straight into `Self::swap(&sender, &path, &send_to, keep_alive)`, and it is emitted correctly in the `SwapExecuted` event as `send_to`. [2](#0-1) 

- The `swap` helper function withdraws from `sender` but resolves (deposits) the output credit to `send_to`, not the sender: `T::Assets::resolve(send_to, credit_out)`. [3](#0-2) 

- The `revive` precompile wrapper (`substrate/frame/asset-conversion/precompiles/src/lib.rs`) also decodes the caller-provided `sendTo` address and forwards it, separately from the `sender` derived from `caller_account_id`, with no substitution bug. [4](#0-3) 

- Tests confirm output tokens land at the distinct `recipient` account rather than the `swapper`/caller. [5](#0-4) 

There is no place where the swap logic substitutes `msg.sender`/caller for the caller-supplied destination account — the destination parameter is honored end-to-end at both the pallet-call level and the revive-precompile level. This differs fundamentally from the reported bug class (destination-parameter override), so no valid analog vulnerability exists in this code path.

		fn swap(
			sender: &T::AccountId,
			path: &BalancePath<T>,
			send_to: &T::AccountId,
			keep_alive: bool,
		) -> Result<(), DispatchError> {
			let (asset_in, amount_in) = path.first().ok_or(Error::<T>::InvalidPath)?;
			let credit_in = Self::withdraw(asset_in.clone(), sender, *amount_in, keep_alive)?;

#[test]
fn swap_exact_tokens_for_tokens_works() {
	new_test_ext().execute_with(|| {
		let provider = 1u64;
		let swapper = 2u64;
		let recipient = 3u64;

		setup_pool(provider, 10_000, 10_000);
		assert_ok!(Assets::mint(RuntimeOrigin::signed(provider), 1, swapper, 1_000));

		let swapper_asset1_before =
			<NativeAndAssets as Inspect<u64>>::balance(NativeOrWithId::WithId(1), &swapper);
		let recipient_native_before =
			<NativeAndAssets as Inspect<u64>>::balance(NativeOrWithId::Native, &recipient);

		let data = IAssetConversion::swapExactTokensForTokensCall {
			path: vec![encode_asset(1).into(), encode_native().into()],
			amountIn: U256::from(100),
			amountOutMin: U256::from(1),
			sendTo: account_addr(&recipient),
			keepAlive: false,
		}
		.abi_encode();

		let result = bare_call(swapper, data);
		let return_data = result.result.expect("swap must succeed");
		assert!(!return_data.did_revert(), "swap must not revert");

		let amount_out =
			IAssetConversion::swapExactTokensForTokensCall::abi_decode_returns(&return_data.data)
				.expect("return data must decode");
		assert!(amount_out > U256::ZERO, "must receive some tokens");

		let swapper_asset1_after =
			<NativeAndAssets as Inspect<u64>>::balance(NativeOrWithId::WithId(1), &swapper);
		assert_eq!(swapper_asset1_before - swapper_asset1_after, 100);

		let recipient_native_after =
			<NativeAndAssets as Inspect<u64>>::balance(NativeOrWithId::Native, &recipient);
		assert_eq!(
			U256::from(recipient_native_after - recipient_native_before),
			amount_out,
			"received amount must match return value"
		);
	});
