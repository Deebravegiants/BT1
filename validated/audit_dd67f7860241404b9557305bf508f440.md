### Title
Permissionless `CallDispatcher.dispatch()` lets anyone drain any dust/residual balance parked on the shared dispatcher - ([File: evm/src/utils/CallDispatcher.sol])

### Summary
`CallDispatcher.dispatch(bytes memory encoded)` is an unauthenticated, externally callable function with no access control (no `onlyGateway`/`onlyOwner` restriction), exactly analogous to the reported `D3Proxy.refundETH()` bug class: any address can invoke it to force the shared `CallDispatcher` to execute arbitrary `Call[]` and move out whatever ETH/token balance is currently sitting on the contract to any recipient the caller chooses.

### Finding Description
`CallDispatcher` is a singleton contract shared by every `IntentGatewayV2`/`IntentsBase` order (both same-chain and cross-chain), used to execute `predispatch`/`postdispatch` calldata during `placeOrder`/`fillOrder`: [1](#0-0) 

```
receive() external payable {}
function dispatch(bytes memory encoded) external {
    Call[] memory calls = abi.decode(encoded, (Call[]));
    ...
    (bool success, bytes memory result) = to.call{value: call.value}(call.data);
    if (!success) revert CallFailed(to, result);
}
```

`dispatch` performs no `msg.sender` check at all — anyone can call it directly with a crafted `Call[]` that transfers the dispatcher's current native or ERC20 balance to an address of their choosing (as long as the target is a contract, e.g. calling `token.transfer(attacker, balance)`).

`IntentsBase._execute` only sweeps back the tokens explicitly listed in `order.output.assets` after postdispatch calldata runs: [2](#0-1) 

Any token the postdispatch/predispatch call happens to leave on the dispatcher that is *not* part of the order's declared input/output token list is never swept by the gateway and remains parked on `CallDispatcher`'s balance indefinitely. Likewise, `receive() external payable {}` means the dispatcher can accumulate native ETH from any source, and any failed/partial sweep leaves residue there.

Because `dispatch()` has zero access control, once such residual value exists on the contract (dust from fee-on-transfer tokens, unswept side-effect tokens from arbitrary predispatch/postdispatch calldata, accidental direct transfers, or a transaction that reverts partway leaving assets stuck), any unprivileged actor can front-run the legitimate sweep/withdrawal path (or simply act opportunistically) and call `CallDispatcher.dispatch()` themselves to redirect that balance to their own address — the same "steal whatever balance currently sits in the contract" pattern flagged in the original `D3Proxy.refundETH()` report.

### Impact Explanation
Any ETH or ERC20 tokens that transiently or permanently reside on the shared `CallDispatcher` (used across all `IntentGatewayV2` orders) can be stolen by an unrelated third party with a single unauthenticated call. This is a direct, permanent loss-of-funds vector for protocol/user dust and any assets briefly routed through the dispatcher during predispatch/postdispatch execution, satisfying the "concrete theft or permanent freezing of funds" bar for this scan.

### Likelihood Explanation
Likelihood is High: `dispatch()` requires no special preconditions or races beyond the dispatcher holding a non-zero balance, which is a normal/expected occurrence given `CallDispatcher` executes arbitrary third-party calldata (predispatch swaps, postdispatch DeFi routing) for every solver-composable order, and `receive()` accepts value unconditionally. Any block where dust exists — even transiently between two calls within the same `placeOrder`/`fillOrder` execution if an attacker manages to reenter, or persistently when the sweep logic misses non-listed tokens — is directly exploitable by a plain EOA transaction.

### Recommendation
Restrict `CallDispatcher.dispatch()` to only be callable by the authorized `IntentGatewayV2`/`IntentsBase` contract(s) (e.g. an `onlyGateway` modifier set at construction, or making the dispatcher a per-order/per-call ephemeral proxy instead of a shared singleton). Additionally, ensure sweep logic in `_execute`/predispatch flows accounts for all tokens that could land on the dispatcher, not only those declared in `order.output.assets`/`order.inputs`, and add a self-sweep/rescue function restricted to the gateway to reclaim any residual balance.

### Proof of Concept
1. Any predispatch/postdispatch calldata (or a fee-on-transfer/rebasing token, or an accidental direct transfer) leaves a residual ERC20 or native balance on `CallDispatcher` after a `placeOrder`/`fillOrder` transaction completes, because `_execute`/the predispatch sweep in `IntentGatewayV2`/`IntentsBase` only sweeps tokens explicitly listed in the order's input/output arrays.
2. An attacker observes (via block explorer or mempool) that `CallDispatcher` now holds a non-zero balance of some token or ETH.
3. Attacker calls `CallDispatcher.dispatch(abi.encode(Call[]))` directly, with `Call{ to: token, value: 0, data: abi.encodeWithSelector(IERC20.transfer.selector, attacker, balance) }` (or `Call{ to: attackerContract, value: balance, data: "" }` for native ETH).
4. Since `dispatch()` has no caller restriction, the call succeeds and the dispatcher's balance is transferred to the attacker, with no way for the legitimate protocol/user to recover it.

    /**
     *  @dev reverts if the target is not a contract or if any of the calls reverts.
     */
    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }

        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
