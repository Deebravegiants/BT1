### Title
Iris-code attestation signature omits `signup_id`, enabling cross-signup replay of a captured `orb-sign-iris-code` signature - (File: `src/plans/enroll_user.rs`)

### Summary
`enroll_user::make_signature` builds the SHA-256 digest that is passed to `secure_element::sign` from `ORB_ID`, the user QR `user_id`, iris/mask codes, and code versions, but never includes the per-attempt `signup_id`. Because `secure_element::sign` only signs whatever raw digest it is given with no nonce/timestamp/session binding of its own, the resulting BASE64 signature is identical across any two signup attempts that share the same `orb_id`, `user_id`, and iris/mask/version fields, regardless of `signup_id`.

### Finding Description
`make_signature` in `src/plans/enroll_user.rs:290-304` computes: [1](#0-0) 
```
let mut ctx = Context::new(&SHA256);
ctx.update(ORB_ID.as_str().as_bytes());
ctx.update(user_qr_code.user_id.as_bytes());
ctx.update(pipeline.v2.ir_net_version.as_bytes());
ctx.update(pipeline.v2.iris_version.as_bytes());
ctx.update(pipeline.v2.eye_left.iris_code.as_bytes());
...
let signed = secure_element::sign(ctx.finish())?;
Ok(BASE64.encode(&signed))
```
`self.signup_id` (a fresh, randomly generated `SignupId::new(self.s3_region)` created per attempt in `src/plans/mod.rs:695`) is never passed into `make_signature`, so it never enters the hashed context. `secure_element::sign` simply forwards the raw digest bytes to the secure element / a deterministic ECDSA signer in test builds without adding any binding data of its own: [2](#0-1) 

The `signup_id` value is only used as a URL path segment and a form-independent identifier when the request is sent (`signup_post::request`, `src/backend/signup_post.rs:100-145`), completely decoupled from the signed digest. Since the signature is deterministic (SHA-256 + fixed-key/EC signer over the same bytes), any two signup attempts by the same identity (same `orb_id`, same `user_qr_code.user_id`, same iris/mask codes/versions — trivially true if an attacker re-submits a previously captured signup with a fresh `signup_id`) produce byte-identical `signature` values. Nothing in the client-side code re-derives or rejects a stale signature against the new `signup_id`.

### Impact Explanation
This breaks attestation non-replayability: an attacker who has observed one legitimate signup's multipart form fields (`signature`, `codes`, `userId`) — reachable from their own signup session/backend response, per the allowed attack surface — can resubmit those exact fields against a new `signup_id` and the signature will validate as being freshly produced by the secure element for that new session, even though the secure element never signed anything about that specific signup attempt. This allows forging a valid-looking hardware attestation for an arbitrary new signup session using stale material, undermining any backend guarantee that a "signature" corresponds to a distinct, freshly-attested biometric event tied to that `signup_id`. This maps to an attestation-forgery / cross-signup state bleed impact class.

### Likelihood Explanation
Fully client-side and deterministic: no operator/root access or key exfiltration is needed. Any party who can observe or record a legitimate signup's `signature`/`codes`/`userId` fields (their own session or a replayed backend response within that session) can trivially reconstruct a valid multipart body for a different `signup_id`, since the signed digest is a pure function of already-known/observable inputs and never varies with `signup_id`. This is deterministic and 100% repeatable, requiring no timing or race condition.

### Recommendation
Include `signup_id` (and ideally a server-issued nonce/timestamp) inside the `Context` hashed in `make_signature` before calling `secure_element::sign`, e.g. `ctx.update(signup_id.to_string().as_bytes())`, and require the backend to bind signature verification to the specific `signup_id` of the request. This ensures a captured signature cannot be replayed against any other signup session.

/// Signs this buffer with Secure Element and returns the output.
#[cfg(not(test))]
pub fn sign<T: AsRef<[u8]>>(data: T) -> Result<Vec<u8>> {
    fn inner(data: &[u8]) -> Result<Vec<u8>> {
        let encoded = BASE64.encode(data);

        tracing::info!("Running orb-sign-iris-code");
        let mut command = Command::new("/usr/bin/orb-sign-iris-code");
        command.stdin(Stdio::piped());
        command.stdout(Stdio::piped());
        command.stderr(Stdio::piped());
        let mut child = command.spawn().wrap_err("running orb-sign-iris-code")?;

        let mut stdin = child.stdin.take().unwrap();
        stdin.write_all(encoded.as_bytes())?;
        drop(stdin);

        let output = child.wait_with_output().wrap_err("waiting for orb-sign-iris-code")?;
        let success = output.status.success();
        for line in String::from_utf8_lossy(&output.stderr).lines() {
            if success {
                tracing::trace!("orb-sign-iris-code {}", line);
            } else {
                tracing::error!("orb-sign-iris-code {}", line);
            }
        }
        if !success {
            if let Some(code) = output.status.code() {
                bail!("orb-sign-iris-code exited with non-zero exit code: {code}");
            } else {
                bail!("orb-sign-iris-code terminated by signal");
            }
        }
        BASE64.decode(&output.stdout).wrap_err("decoding orb-sign-iris-code output")
    }

    inner(data.as_ref())
}
