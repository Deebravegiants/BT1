### Title
Fraud detection is unconditionally disabled, causing all captures to be tagged `SignupReason::Normal` - (File: src/plans/mod.rs)

### Summary
`MasterPlan::detect_fraud` at `src/plans/mod.rs:1392-1406` always returns `Ok(false)` regardless of pipeline content, with the explicit comment "FOSS: WE HAVE DELETED ALL FRAUD CHECKS". This means any biometric pipeline output, including degraded, occluded, or borderline liveness captures, will always be classified as non-fraudulent, since there is no logic that inspects `pipeline.occlusion`, `face_identifier_fraud_checks`, or any other fraud signal before returning.

### Finding Description
`detect_fraud` receives `pipeline: Option<&biometric_pipeline::Pipeline>` which contains fraud-relevant fields already computed earlier in the pipeline (e.g. `pipeline.occlusion`, `pipeline.face_identifier_fraud_checks`, visible at lines 1355-1359 in the surrounding `biometric_pipeline` function). Instead of evaluating these signals, the function only checks whether `pipeline` is `Some`, and if so, unconditionally returns `Ok(false)` [1](#0-0) . This result feeds into `SignupReason` determination and is passed down to `enroll_user` and eventually into upload/custody-package logic [2](#0-1) . Since the fraud checks were literally deleted (per the source comment) rather than merely stubbed for tests, any attacker who can complete a biometric_pipeline run (any presented face/iris capture that passes upstream capture/occlusion gating enough to produce `Some(pipeline)`) will always have `detect_fraud` return `false`, meaning the signup is never flagged as fraud through this path.

### Impact Explanation
This matches a fail-open fraud-detection bypass: the orb's fraud/liveness enforcement mechanism is inert in this build, so downstream code that treats `detect_fraud() == false` as "genuine" will accept and enroll/upload custody packages for any capture that reaches this stage, regardless of borderline occlusion or spoof signals. This is a real, non-mock code path (not behind `#[cfg(test)]`) reachable through normal `MasterPlan::run`.

### Likelihood Explanation
Preconditions are minimal: the attacker only needs to complete a normal biometric capture and pipeline run to obtain `Some(pipeline)`, which is achievable by any unprivileged user presenting themselves (or a spoofed capture that survives upstream capture-stage gating) to the orb. This is deterministic and always reproducible — the function always returns `Ok(false)` with no conditional logic distinguishing genuine from fraudulent captures.

### Recommendation
Restore or reimplement fraud-detection logic in `detect_fraud` that actually inspects the fraud signals already present on `pipeline` (occlusion results, face identifier fraud checks, liveness metrics, duplicate/replay signals) and returns `true` when any check fails, rather than unconditionally returning `Ok(false)`.

### Proof of Concept
Integration test plan:
1. Construct/mocked `biometric_pipeline::Pipeline` instances representing (a) a clean genuine capture, (b) a capture with `occlusion` indicating high occlusion/failure, and (c) a capture with `face_identifier_fraud_checks` indicating a duplicate/fraud signal.
2. Call `MasterPlan::detect_fraud(orb, debug_report, Some(&pipeline))` for each case.
3. Assert that for case (a) it returns `Ok(false)`, and for cases (b) and (c) it should return `Ok(true)` (fails today because current implementation returns `Ok(false)` for all three cases).
4. This demonstrates that `detect_fraud` cannot distinguish fraudulent from genuine captures, confirming the fail-open condition.
