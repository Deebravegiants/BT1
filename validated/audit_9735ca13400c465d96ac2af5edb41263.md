### Title
Missing shop-domain validation in OAuth authorization code callback leads to SSRF with `client_secret` - ([File: lib/shopify_api/auth/oauth.rb])

### Summary
`ShopifyAPI::Auth::Oauth.validate_auth_callback` builds the access-token request host directly from `auth_query.shop` and never passes it through `Utils::ShopValidator.sanitize!`, unlike every other OAuth grant flow in this gem.

### Finding Description
In the Authorization Code Grant flow, `validate_auth_callback` only checks that the query string (including `shop`) matches the HMAC signature, then immediately uses the raw `shop` value to build the token endpoint host and issues a POST containing `client_id`/`client_secret`: [1](#0-0) 

`auth_base_uri(shop)` builds `https://#{shop}/admin` (or a dev-server variant) directly from that unsanitized string: [2](#0-1) 

Compare this to every other credential-issuing flow in the gem, which explicitly calls `Utils::ShopValidator.sanitize!(shop)` before constructing the session/host used to send `client_secret`: [3](#0-2) [4](#0-3) [5](#0-4) 

`ShopValidator.sanitize!` is the gem's single mechanism for proving that a `shop` string resolves to a trusted `myshopify.com`/`myshopify.io`/etc. host, rejecting attacker-controlled domains: [6](#0-5) 

The equality this breaks is: *the host bound by the query-string HMAC* (an arbitrary attacker-influenceable string that only needs to be one of the fields signed) should equal *the host that ultimately receives `client_secret`*. `HmacValidator.validate` proves only that the concatenation of `code, host, shop, state, timestamp` was signed with the app's secret — it never proves `shop` is a real `*.myshopify.com` hostname or that it can't contain other characters: [7](#0-6) [8](#0-7) 

This is the same class of bug as the audit’s "unit not recalculated" report: one code path (`client_credentials`, `refresh_token`, `token_exchange`) enforces the domain-trust invariant before spending a credential, while the sibling path (`validate_auth_callback`) omits the very same check before performing the analogous credential-bearing action, letting the "recalculated"/validated value (a trusted host) drift out of sync with the value actually used (`auth_query.shop`).

### Impact Explanation
If a caller's host application passes through an attacker-influenced `shop` value into `begin_auth`/`validate_auth_callback` (a common integration pattern, since apps typically read `shop` from install/callback request params before this gem's HMAC check runs), `auth_base_uri` will send the POST request — carrying `client_id` and `client_secret` in the body — to a host built from that unsanitized string. This is SSRF carrying the app's own OAuth client credentials, matching the report's High-severity bucket.

### Likelihood Explanation
Exploitability is bounded by the fact that `shop` is included in the HMAC-signed query string, so exploitation requires either (a) a legitimate Shopify-issued callback for an attacker-owned/controlled shop being replayed against a victim app instance (forced OAuth completion / CSRF against `validate_auth_callback`, since `state`/cookie binding is the only other check), or (b) a host application invoking `begin_auth`/`validate_auth_callback` with a shop value it hasn't itself sanitized. Given that all sibling flows in this same gem defensively call `ShopValidator.sanitize!` specifically to close this class of issue, its absence here is a genuine inconsistency rather than an intentional trust boundary.

### Recommendation
Call `Utils::ShopValidator.sanitize!(auth_query.shop)` (and in `begin_auth`, on the `shop:` argument) before using the value to construct `auth_base_uri`/the OAuth session, mirroring `client_credentials.rb`, `refresh_token.rb`, and `token_exchange.rb`.

### Proof of Concept
1. A host application calls `ShopifyAPI::Auth::Oauth.begin_auth(shop: params[:shop], redirect_path: "/callback")` without pre-validating `params[:shop]` (permitted by this gem's public API, which performs no such validation itself, unlike its sibling methods).
2. `auth_base_uri` builds `https://attacker-controlled-host/admin/oauth/authorize?...`, sending `client_id`, `scope`, `redirect_uri`, and `state` to a host outside `*.myshopify.com`.
3. Separately/alternatively, an attacker who owns a real Shopify store completes a real OAuth authorize step for their own store, obtaining Shopify-signed `code`, `hmac`, `shop`, `state`, `timestamp`, and `host` values; if they can get these values submitted to the target app's callback route alongside a matching `state` cookie, `validate_auth_callback` will accept them and POST `client_id`/`client_secret` to `https://#{attacker_shop}/admin/oauth/access_token`, since `auth_base_uri` never confirms the host is a trusted Shopify domain (only that the app's own HMAC secret signed the string).

        def validate_auth_callback(cookies:, auth_query:)
          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::InvalidOauthError, "Invalid OAuth callback." unless Utils::HmacValidator.validate(auth_query)
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = cookies[SessionCookie::SESSION_COOKIE_NAME]
          raise Errors::NoSessionCookieError unless state

          raise Errors::InvalidOauthError,
            "Invalid state in OAuth callback." unless state == auth_query.state

          null_session = Auth::Session.new(shop: auth_query.shop)
          body = {
            client_id: Context.api_key,
            client_secret: Context.api_secret_key,
            code: auth_query.code,
            expiring: Context.expiring_offline_access_tokens ? 1 : 0, # Only applicable for offline tokens
          }

          client = Clients::HttpClient.new(session: null_session, base_path: "/admin/oauth")
          response = begin
            client.request(
              Clients::HttpRequest.new(
                http_method: :post,
                path: "access_token",
                body: body,
                body_type: "application/json",
              ),
            )
          rescue ShopifyAPI::Errors::HttpResponseError => e
            raise Errors::RequestAccessTokenError,
              "Cannot complete OAuth process. Received a #{e.code} error while requesting access token."
          end

      TRUSTED_SHOPIFY_DOMAINS = T.let(
        [
          "shopify.com",
          "myshopify.io",
          "myshopify.com",
          "spin.dev",
          "shop.dev",
        ].freeze,
        T::Array[String],
      )

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end

        sig { params(verifiable_query: VerifiableQuery).returns(T::Boolean) }
        def validate(verifiable_query)
          return false unless verifiable_query.hmac

          result = validate_signature(verifiable_query, Context.api_secret_key)
          if result || Context.old_api_secret_key.nil? || T.must(Context.old_api_secret_key).empty?
            result
          else
            validate_signature(verifiable_query, T.must(Context.old_api_secret_key))
          end
        end

        private

        sig { params(verifiable_query: VerifiableQuery, secret: String).returns(T::Boolean) }
        def validate_signature(verifiable_query, secret)
          received_signature = verifiable_query.hmac
          computed_signature = compute_signature(verifiable_query.to_signable_string, secret)
          OpenSSL.secure_compare(computed_signature, T.must(received_signature))
        end
