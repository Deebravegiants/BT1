### Title
Cross-Chain Calldata Authorization in `pallet-hyper-fungible-token` Lacks Domain Separation, Enabling Signature Replay for Arbitrary Runtime Call Execution - ([File: modules/pallets/hyper-fungible-token/src/module.rs])

### Summary
The Chartbrew CVE is a "vulnerable API" that lets an attacker turn a normal request into arbitrary code execution. The closest reachable analog in this codebase is the calldata-execution feature of `pallet-hyper-fungible-token`'s `on_accept` handler, which is directly reachable by anyone bridging tokens through `HyperFungibleToken`/`WrappedHyperFungibleToken` and delivered via the permissionless ISMP handler path. When a bridged transfer carries attached `data`, the pallet decodes a `SubstrateCalldata { signature, runtime_call }` payload and, if a signature is present, verifies it and then dispatches `runtime_call` as `RawOrigin::Signed(beneficiary)` [1](#0-0) . The signed payload that is authenticated is only `(nonce, runtime_call)` — it contains no chain/domain identifier (no genesis hash, spec version, destination state-machine id, or source contract binding) [2](#0-1) .

### Finding Description
For each signature scheme (`Ed25519`, `Sr25519`, `Ecdsa`) the verified message is built purely from the account's on-chain nonce and the encoded `runtime_call`:
```rust
let payload = (nonce, substrate_data.runtime_call.clone()).encode();
let msg = sp_io::hashing::keccak_256(&payload);
``` [3](#0-2) 

There is no binding to:
- the destination `StateMachine`/chain,
- the source contract or `ContractToAsset` mapping that authenticated this specific bridged asset,
- a genesis hash or runtime spec version,
- the ISMP request commitment itself.

After verification, `origin` is set to `beneficiary` (the token recipient decoded from the message) and the arbitrary `runtime_call` is dispatched with full `Signed` authority, subject only to `BaseCallFilter`:
```rust
runtime_call.dispatch(RawOrigin::Signed(origin.clone()).into())
``` [4](#0-3) 

Because the signed payload is chain-agnostic and only keyed on the beneficiary account's nonce, any signature a user produces to authorize a call on one deployment (e.g., a testnet, a fork, or any other parachain running this pallet with the same account and the same nonce value) is valid and replayable on every other deployment that shares that nonce state — the pallet has no way to distinguish "this call was authorized for chain/context X" from "authorized for any chain running this code." This is analogous to a vulnerable API accepting insufficiently-scoped input and turning it into execution of attacker/observer-chosen code path (here, an arbitrary filtered `RuntimeCall`) under another user's signed identity, without any additional per-context proof.

This differs from the legitimate "unsigned" branch, where the origin is derived from the message's `from` field (tied to the actual EVM `msg.sender` that dispatched the cross-chain send), which is self-authorizing and not attacker-controlled. The signed branch is the one exposed to cross-context replay because its authentication data is under-specified.

### Impact Explanation
An off-chain signature a user creates to authorize a specific runtime call (e.g., a stake, a governance vote, an approval, a deposit) as part of one bridged transfer can be captured (it is transmitted in the cross-chain message body, which is public/observable by relayers and anyone monitoring source-chain transactions) and replayed by a relayer or observer against any other Hyperbridge-connected chain/runtime instance of `pallet-hyper-fungible-token` where the beneficiary account's nonce still matches, causing dispatch of a `Signed` extrinsic on the victim's behalf on a chain/context they never intended to interact with. This is an unauthorized app action executed under a forged authorization context, reachable by any unprivileged token bridger or relayer who observes bridged calldata.

### Likelihood Explanation
Likelihood is moderate: it requires (a) a user to attach signed calldata to a bridged transfer (a supported, documented feature), and (b) the same account/nonce state existing across another chain/context that also runs this pallet (e.g., a parachain migration, testnet/mainnet pair, or multiple Hyperbridge-connected chains configured with the same `Config`). Given Hyperbridge's multi-chain design and the pallet's genericity, this is a realistic deployment scenario, not a contrived edge case.

### Recommendation
Bind the signed payload to an explicit domain separator before hashing, e.g. include the runtime's `frame_system::Pallet::<T>::block_hash(0)` (genesis hash), `<T as frame_system::Config>::Version::get().spec_version`, and the destination `StateMachine` identifier (or the ISMP request's source/dest fields) in the signed payload:
```rust
let payload = (GENESIS_HASH, SPEC_VERSION, dest_state_machine, nonce, substrate_data.runtime_call.clone()).encode();
```
This ensures a signature is only valid for the specific chain/runtime instance and message context it was created for, closing the cross-context replay window.

### Proof of Concept
1. Alice bridges tokens via `HyperFungibleToken` on chain S to beneficiary `Alice_dst` on chain D, attaching `data` = `SubstrateCalldata { signature: sig_over(nonce=0, call=Stake(amount)), runtime_call: Stake(amount) }`, intending to auto-stake on chain D only.
2. `pallet-hyper-fungible-token::on_accept` on chain D verifies `sig_over(nonce=0, call=Stake(amount))` against `Alice_dst`'s pubkey and dispatches `Stake(amount)` as `RawOrigin::Signed(Alice_dst)` [5](#0-4) .
3. A relayer/observer extracts `substrate_data` from the public cross-chain message and replays the identical `(signature, runtime_call)` bytes as `data` in a new bridged transfer targeting `Alice`'s equivalent account on chain D' (another Hyperbridge-connected chain running the same pallet, where `Alice`'s account nonce is still `0`).
4. Because the signed hash `(nonce, runtime_call)` contains no chain-specific domain separator, verification on chain D' succeeds, and `Stake(amount)` is dispatched as `RawOrigin::Signed(Alice)` on chain D' — an action Alice never authorized for that chain.

							.try_into()
							.map_err(|_| HftError::SignatureVerificationFailed)?;

						let substrate_account = T::EvmToSubstrate::convert(eth_address);
						if substrate_account != beneficiary {
							Err(HftError::SignatureVerificationFailed)?
						}
					},

					account.copy_from_slice(from_bytes);
					account.into()

			// reach dispatchables that the runtime has otherwise filtered out (e.g.
