## Title
Unauthenticated Vault gateway JSON-RPC handler allows unbounded memory growth via attacker-controlled request IDs - (File: core/services/gateway/handlers/vault/handler.go)

### Summary
The Chainlink Gateway's Vault handler exposes `HandleJSONRPCUserMessage`, which is reachable by unauthenticated external clients over the gateway's public HTTP/WS ingress. It registers every incoming request into an in-memory map (`h.activeRequests`) keyed by the client-supplied JSON-RPC `req.ID`, with no bound on the number of concurrent entries and no admission-time size/rate check. This mirrors the SiYuan `/api/system/uiproc` pattern: an unauthenticated endpoint that accepts and retains attacker-controlled identifiers without limits, enabling a memory-exhaustion denial of service.

### Finding Description
`newActiveRequest` in `core/services/gateway/handlers/vault/handler.go:457-472` inserts a new `*activeRequest` (holding the callback, full request body, and a responses map) into `h.activeRequests[req.ID]` under a mutex, checking only for a duplicate key — never a cap on total map size: [1](#0-0) 

`req.ID` is a caller-controlled JSON-RPC field parsed directly from the untrusted client message in `HandleJSONRPCUserMessage`. Because each unique ID passes the "already exists" check, an attacker can send unlimited requests with unique IDs, each allocating and retaining a map entry until `removeExpiredRequests` sweeps it after `h.requestTimeout`: [2](#0-1) 

This is structurally the same defect class as the confidential-relay handler's analogous `activeRequests` map (also keyed by client `req.ID`, same "already exists" check, no size cap): [3](#0-2) 

By contrast, the generic `RequestCache` used elsewhere in the gateway handlers explicitly enforces `maxCacheSize` at admission time: [4](#0-3) 

The Vault and confidential-relay handlers do not apply an equivalent cap before inserting into `activeRequests`, so an attacker can flood the handler with unique-ID requests faster than the `requestTimeout` sweep reclaims them, growing the map (and its buffered callbacks/response structures) without bound until the gateway process exhausts memory.

### Impact Explanation
Sustained unauthenticated requests with unique JSON-RPC IDs accumulate unbounded entries in `activeRequests`, each retaining a callback and a `responses` map until the timeout sweep runs. If the attacker's request rate exceeds the sweep's reclamation rate (bounded only by `h.requestTimeout`), the gateway node's memory grows continuously, leading to OOM and denial of service for the Vault (and similarly shaped confidential-relay) gateway path — degrading availability for all legitimate users of that gateway node, matching the "VA:H" impact of the referenced CVE.

### Likelihood Explanation
`HandleJSONRPCUserMessage` is invoked from the gateway's inbound HTTP handler for unauthenticated user-facing traffic, requiring no authentication, no valid signature, and no pre-registered workflow/owner — only a well-formed JSON-RPC envelope with a unique `id` field, which is trivial for a remote unprivileged attacker to generate repeatedly. This makes the likelihood high assuming the handler is exposed to the internet-facing gateway (unauthenticated ingress), consistent with the scope constraints of this analysis. I could not fully trace within the remaining budget whether an upstream rate limiter unconditionally throttles all callers before reaching `newActiveRequest`; this is the main remaining uncertainty.

### Recommendation
Add an admission-time cap on `h.activeRequests` (mirroring `RequestCache.maxCacheSize`) in `newActiveRequest` for both `core/services/gateway/handlers/vault/handler.go` and `core/services/gateway/handlers/confidentialrelay/handler.go`, rejecting new requests once the map reaches a configured maximum size, and/or enforce a global per-source rate limit ahead of request registration so unauthenticated callers cannot unboundedly grow server-side memory via unique request IDs.

### Proof of Concept
1. Connect to the gateway's public Vault JSON-RPC ingress without authentication.
2. Repeatedly send `HandleJSONRPCUserMessage` requests, each with a freshly generated unique `id` (e.g., UUIDs) and a valid method/params shape, faster than `h.requestTimeout`.
3. Each request passes the `h.activeRequests[req.ID] != nil` check (since IDs are unique) and is inserted via `newActiveRequest` at `core/services/gateway/handlers/vault/handler.go:457-472`, growing the map without bound.
4. Observe gateway process memory grow linearly with request volume until resource exhaustion/OOM, denying service to legitimate Vault gateway users.

// removeExpiredRequests removes expired requests from the pending requests map
func (h *handler) removeExpiredRequests(ctx context.Context) {
	h.mu.RLock()
	var expiredRequests []*activeRequest
	now := h.clock.Now()
	for _, userRequest := range h.activeRequests {
		if now.Sub(userRequest.createdAt) > h.requestTimeout {
			expiredRequests = append(expiredRequests, userRequest)
		}
	}
	h.mu.RUnlock()

	for _, er := range expiredRequests {
		responses := er.copiedResponses()
		var nodeResponses strings.Builder
		for nodeKey, nodeResponse := range responses {
			_, _ = fmt.Fprintf(&nodeResponses, "%s ---::: %v               ", nodeKey, nodeResponse)
		}
		nodeResponsesStr := nodeResponses.String()
		err := h.sendResponse(ctx, er, h.errorResponse(er.req, api.RequestTimeoutError, errors.New("request expired without getting quorum of responses from nodes. Available responses: "+nodeResponsesStr), []byte(nodeResponsesStr)))
		if err != nil {
			h.lggr.Errorw("error sending response to user", "requestID", er.req.ID, "error", err)
		}
	}
}

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

	}
	if responseData == nil {
		return errors.New("responseData is nil")
	}
	key := globalID{request.Body.Sender, request.Body.MessageID}
	c.mu.Lock()
	defer c.mu.Unlock()
	_, ok := c.cache[key]
	if ok {
		return errors.New("request already exists")
