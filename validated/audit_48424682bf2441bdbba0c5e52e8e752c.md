## Analog Found

### Title
Flash-loan spot-price manipulation of Uniswap V4 venue pricing in Simplex's `FXFiller` - ([File: sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts])

### Summary
The Behodler `FlanBackstop.purchasePyroFlan()` bug used a single-block LP balance ratio as its price oracle, defended only by a static maximum-deviation check that a flash loan (or several smaller ones) can satisfy while still skewing the price enough to profit. Hyperbridge's Simplex solver reproduces the identical pattern: `UniswapV4FundingPlanner.getExoticTokenPrice`/`computeDirectPoolPriceUsd` reads the *current* `sqrtPriceX96` of a single Uniswap V4 pool as the sole price for a "venue-priced" trading pair, and the only defense, `FXFiller.checkPriceGuard`, is a static-bound deviation check against a hand-configured reference price — not a TWAP, and not an execution-cost/size-impact model.

### Finding Description
When a Simplex-configured trading pair has no static bid/ask curves (a "curveless"/venue-priced pair), `FXFiller.resolveLegRates` prices the leg entirely from the live Uniswap V4 pool mid, obtained via `venueUsdPrice` → `getVenueUsdPrice` → `UniswapV4FundingPlanner.getExoticTokenPrice`: [1](#0-0) 

The USD price itself is derived straight from the pool's instantaneous `sqrtPriceX96`-derived mid (`sdkPool.token0Price`/`token1Price`), with no fee-tier adjustment and no size/impact term: [2](#0-1) 

The only sanity check applied to this quote is `checkPriceGuard`, a static percentage band around a hand-configured `referencePrice`: [3](#0-2) 

This guard is deliberately optional — `referencePrice`/`maxDeviationBps` can be left unset entirely, leaving the chain "unguarded", and both must be static config values set once at startup, not a moving-average price: [4](#0-3) 

The internal flow docs for this exact code path independently confirm the root cause: the pool's raw mid is used with no fee tier and no size/impact term, and the guard only checks deviation from a static reference, not execution cost: [5](#0-4) 

This is structurally the same bug class as the `FlanBackstop` report: a single-block/single-call spot price from an on-chain pool is trusted as the fill price for real value transfer, bounded only by a static maximum-deviation check. Exactly as the original report notes that a flash-loan attacker can "reduce the volume per flashloan and repeat the attack multiple times" to stay inside a bound check while still extracting value, an attacker here can move the Uniswap V4 pool price (via flash loan or by repeatedly trading in smaller increments) to just inside `maxDeviationBps` of the configured `referencePrice`, then submit an intent order that the `FXFiller` fills at the manipulated pool mid.

### Impact Explanation
Any unprivileged actor who can submit an intent order reachable by this solver (via `IntentGatewayV2`/`fillOrder`) can flash-loan-manipulate the referenced Uniswap V4 pool immediately before order placement/fill to push `computeDirectPoolPriceUsd`'s spot mid in their favor while staying inside the static guard band (or exploiting a chain where no guard is configured at all, which the docs explicitly allow). Because there is no size/impact term, the manipulated mid is applied linearly across the entire notional the leg fills, letting the attacker extract solver capital (real ERC-20/LP funds actually withdrawn and delivered on the destination chain) proportional to the price skew and order size — a concrete theft of solver funds, the same impact class as the referenced Behodler finding.

### Likelihood Explanation
Reachable from a single, ordinary user action: constructing and submitting an order that a curveless, venue-priced pair will fill, no privileged role required. The guard is per-chain and optional; the report's own configuration guidance ("omit both to leave the chain unguarded") and the guard's static reference (rather than a TWAP) mean many realistic deployments either have no protection or a protection with the same bypassable bound structure identified in the original H-05 report. Any liquid Uniswap V4 pool used for this pricing is a candidate for flash-loan or size-split manipulation.

### Recommendation
Replace the raw `sqrtPriceX96` spot mid in `computeDirectPoolPriceUsd` with a time-weighted average price (or otherwise manipulation-resistant observation, e.g. multiple-block observation window) before it is used to price fills in `FXFiller.resolveLegRates`/`referenceRate`. Additionally, make the `[vault.uniswapV4]` price guard (`referencePrice`/`maxDeviationBps`) mandatory rather than optional, and incorporate an execution-size/impact term so that large notional fills cannot be priced at the undamped instantaneous mid.

### Proof of Concept
1. Attacker identifies a Simplex `FXFiller` deployment with a curveless (venue-priced) pair backed by a Uniswap V4 position, per `[vault.uniswapV4]` in `filler-config-example.toml`, either without a price guard configured, or with one configured with a wide/legitimate-market-move band.
2. Attacker flash-loans (or repeatedly trades in smaller tranches to stay within `maxDeviationBps`) to move the pool's `sqrtPriceX96` so `computeDirectPoolPriceUsd` reports a skewed mid still inside the static reference band (or unguarded entirely).
3. Attacker immediately submits (or has already pre-signed) an intent order on the affected pair; `FXFiller.resolveLegRates` prices the leg from the skewed venue mid via `checkPriceGuard`, which passes since the deviation stays within the static bound.
4. `UniswapV4FundingPlanner.planWithdrawalForToken` withdraws real LP liquidity at the skewed rate and the solver delivers output tokens to the attacker at a price better than fair value, realizing the loss as the attacker's profit; attacker reverses the pool manipulation afterward (or lets arbitrage restore it), net of the flash-loan fee.

	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}

	private computeDirectPoolPriceUsd(
		pos: HydratedV4Position,
		sdkPool: V4Pool,
		chain: string,
	): { exoticToken: string; priceUsd: Decimal } | null {
		const usdc = this.configService.getUsdcAsset(chain).toLowerCase()
		const usdt = this.configService.getUsdtAsset(chain).toLowerCase()
		const c0 = pos.currency0.toLowerCase()
		const c1 = pos.currency1.toLowerCase()

		if (c0 === usdc || c0 === usdt) {
			// currency0 is stable → exotic is currency1
			// token1Price = "token0 per token1" = USD per exotic
			return {
				exoticToken: c1,
				priceUsd: new Decimal(sdkPool.token1Price.toFixed(18)),
			}
		}

		if (c1 === usdc || c1 === usdt) {
			// currency1 is stable → exotic is currency0
			// token0Price = "token1 per token0" = USD per exotic
			return {
				exoticToken: c0,
				priceUsd: new Decimal(sdkPool.token0Price.toFixed(18)),
			}
		}

		return null
	}

	/**
	 * Validates a live venue quote against the static reference price for the chain.
	 * Returns true (pass) when no guard is configured, or no reference exists for the
	 * chain. Returns false when the quote (token1 per USD) deviates from the reference
	 * by more than `maxDeviationBps`, in which case the order must not be filled.
	 */
	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {
			this.logger.warn(
				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
	}

## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.

```toml lineNumbers
[vault.uniswapV4]
# referencePrice is the expected cNGN per USD;
# reject if the quote is more than 2% off.
# The two go together — one without the other is rejected.
[[vault.uniswapV4.positions]]
chain           = "EVM-8453"
tokenId         = "2087350"
referencePrice  = "1575"
maxDeviationBps = 200
```

`computeDirectPoolPriceUsd` returns the **raw pool mid** derived from `sqrtPriceX96`. The pool's
