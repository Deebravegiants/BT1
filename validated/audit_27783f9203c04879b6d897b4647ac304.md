### Title
Self-inflicted oracle outage via dust Aquarius-LP collateral leg makes an underwater account unliquidatable and uncleanable - (File: contracts/price-aggregator/src/providers/aquarius.rs)

### Summary
The bug class in CVE-2018-25004 — an authorized user invoking a legitimate operation that flips the system into a denial-of-service state — maps onto XOXNO Lending as follows: `supply` credits a collateral leg without requiring a usable price for it, while `liquidate`, `withdraw`, and `clean_bad_debt` require strict prices for every leg on the account. An indebted borrower can supply a dust amount of an Aquarius LP token, then — as a liquidity provider in that same Aquarius pool — withdraw liquidity until the pool value falls below the configured `min_pool_value_wad`. Every subsequent strict price read for that leg returns `InsufficientAquariusLiquidity`, so the account cannot be liquidated, cannot be bad-debt-cleaned, and cannot even withdraw its own other collateral, for as long as the attacker keeps the pool below the floor.

### Finding Description
`aquarius::read` in `contracts/price-aggregator/src/providers/aquarius.rs` computes the LP fair price and then hard-rejects the read when the implied pool value is under the configured floor:

```rust
// contracts/price-aggregator/src/providers/aquarius.rs:118-122
let pool_value_wad = try_mul_div_half_up(&env, price_wad, total_shares, share_unit)
    .ok_or(OracleError::InvalidPrice)?;
if pool_value_wad < lp.min_pool_value_wad {
    return Err(OracleError::InsufficientAquariusLiquidity);
}
``` [1](#0-0) 

On the controller side, `process_supply` → `process_deposit` runs `validate_position_entry_gates` and credits measured receipts; no strict price for the supplied asset is required — the harness test `audit_supply_stale_shield` proves a supply succeeds while the asset's feed is already returning an error (`supply must accept the leg even though WBTC's feed is stale`). [2](#0-1) [3](#0-2) 

In contrast, liquidation and cleanup evaluate the account's full book through strict price reads (`fetch_prices` panics on any missing/invalid entry via `OracleNotConfigured`-style failure paths, and leg resolution propagates `InsufficientAquariusLiquidity`). The same harness tests show both `try_liquidate` and `try_clean_bad_debt_by_id` reverting with `PRICE_FEED_STALE` once a poisoned leg exists, and `try_withdraw` reverting too. [4](#0-3) [5](#0-4) 

The attacker-controlled variant: for an Aquarius LP collateral listing, `pool_value_wad` is `price_wad * total_shares / share_unit`, i.e., directly proportional to pool reserves/supply. A borrower who is also an LP in that pool withdraws their own liquidity until the value dips under `min_pool_value_wad`. That is a fully unprivileged action on a third-party AMM the threat model itself acknowledges ("liquidity providers can cause that outage by withdrawing pool value below `min_pool_value_wad`"). [6](#0-5) 

### Impact Explanation
While the leg's price is invalid:

- `liquidate` reverts for every repayment offer, so an underwater attacker account cannot be liquidated — the borrowed funds are effectively kept while interest accrues against suppliers.
- `clean_bad_debt` reverts (it requires valid prices for all legs), and the governed force-socialize path is also blocked per the threat model, so the position cannot even be written off while the outage lasts.
- `withdraw` reverts for the account, freezing its remaining collateral.

If the attacker maintains the outage until accrued interest turns the account insolvent, the eventual cleanup socializes the loss onto suppliers — a protocol insolvency / theft-of-funds outcome triggered entirely by unprivileged actions (own supply + own LP withdrawal). Even shorter outages give the attacker a free option: restore the LP liquidity when the price moves back in their favor.

### Likelihood Explanation
- Cost to the attacker is one dust supply deposit plus temporarily holding LP liquidity they may already own; position limits (max 5 supply legs) leave room for the poison leg.
- `min_pool_value_wad` is a listing-time configured floor; pools with modest TVL can be pushed under it with a single LP withdrawal. The ops alerting (`LendingLpPoolValueNearFloor`) acknowledges pools can sit within 25% of the floor, meaning a withdrawal of ~25% of pool value suffices.
- No timing, privilege, or third-party cooperation is needed; the attacker chooses when to trigger and when to release.
- Caveat: the shield also freezes the attacker's own collateral and the position only benefits if debt exceeds collateral or the attacker expects to repay later at better terms, so the payoff is bounded by the borrowed amount vs. planted collateral — consistent with Medium.

### Recommendation
- Make per-leg price degradation non-fatal in account-wide flows: during `liquidate` and `clean_bad_debt`, treat an unpriceable supply leg as zero-value (or skip it from seizure) rather than reverting the whole operation, so a single poisoned leg cannot brick the account's liquidation.
- Alternatively, decouple HF computation from seizure: compute health from priceable legs, and seize only priceable collateral, refunding/skipping legs whose price resolution fails.
- At listing time, bound `min_pool_value_wad` conservatively relative to the Aquarius pool's realistic liquidity concentration, and/or require the LP token's supply entry to succeed only when its price resolves (accept the gas cost of a strict read on `supply` for LP-type collateral legs).
- If skipping unpriceable legs is unacceptable for accounting reasons, allow `clean_bad_debt` to force-socialize an account whose only blocker is an unpriceable dust leg below the cleanup threshold, so bad debt can still be written off.

### Proof of Concept
Reproduced by the existing adversarial harness tests (stale-feed variant; the Aquarius variant replaces "feed goes stale" with "attacker withdraws LP below `min_pool_value_wad`"):

```rust
// tests/test-harness/tests/controller/audit_supply_stale_shield.rs
t.supply(ALICE, "USDC", 10_000.0);
t.borrow(ALICE, "ETH", 3.0);
// make WBTC feed invalid (stale / InsufficientAquariusLiquidity in the LP variant)
let plant = t.try_supply(ALICE, "WBTC", 0.001);
assert!(plant.is_ok());                       // supply needs no valid price
t.set_price("USDC", usd_cents(50));           // ALICE goes underwater
let liq = t.try_liquidate(LIQUIDATOR, ALICE, "ETH", 1.0);
assert_contract_error(liq, errors::PRICE_FEED_STALE);      // liquidation bricked
let clean = t.try_clean_bad_debt_by_id(alice_id);
assert_contract_error(clean, errors::PRICE_FEED_STALE);    // cleanup bricked
let wd = t.try_withdraw(ALICE, "WBTC", 0.0001);
assert_contract_error(wd, errors::PRICE_FEED_STALE);       // withdraw bricked
```

For the self-triggered Aquarius variant: list an Aquarius LP token as collateral with `min_pool_value_wad` set; attacker supplies dust LP + borrows; attacker calls `withdraw` on the Aquarius pool until `price_wad * total_shares / share_unit < min_pool_value_wad`; all three calls above then revert with `InsufficientAquariusLiquidity`/`NoLastPrice` until the attacker re-deposits liquidity.

pub(crate) fn process_deposit(
    env: &Env,
    caller: &Address,
    account: &mut Account,
    aggregated: &AggregatedPayments,
    cache: &mut Context,
) {
    validate_position_entry_gates(
        env,
        account,
        aggregated,
        cache,
        AccountPositionType::Deposit,
    );
    let pool_addr = cache.cached_pool_address();
    let mut entries: Vec<PoolSupplyEntry> = Vec::new(env);
    for (hub_asset, amount_in) in aggregated.iter() {
        let asset_config: AssetConfig = cache.require_spoke_asset(account.spoke_id, &hub_asset);
        let received = payments::transfer_amount_measured(
            env,
            &hub_asset.asset,
            caller,
            &pool_addr,
            amount_in,
            GenericError::AmountMustBePositive,
        );
        let position = account.get_or_create_supply_position(&hub_asset, &asset_config);
        entries.push_back(PoolSupplyEntry {
            action: make_pool_action(&position, received, hub_asset.clone()),
        });
    }

    let results = pool_supply_call(env, &pool_addr, &entries);
    for_each_leg(env, &entries, &results, |entry, result| {
        merge_supply_leg(env, account, &entry.action, &result, cache);
    });
}

/// Fetches resolved WAD prices; any missing entry fails with `OracleNotConfigured`.
pub(crate) fn fetch_prices(env: &Env, assets: &Vec<Address>) -> Map<Address, PriceFeedRaw> {
    let aggregator = storage::get_price_aggregator(env);
    let keyed = PriceAggregatorClient::new(env, &aggregator).prices(&token_keys(env, assets));
    let mut out = Map::new(env);
    for asset in assets.iter() {
        match keyed.get(PriceKey::Token(asset.clone())) {
            Some(feed) => out.set(asset, feed),
            None => panic_with_error!(env, OracleError::OracleNotConfigured),
        }
    }
    out
}
