### Title
Secure-element `sign()` silently returns an empty (invalid) signature on success, letting forged/empty attestations pass to the signup and biometric-package flows - ([File: src/secure_element.rs])

### Summary
`secure_element::sign()` invokes the external `orb-sign-iris-code` binary and only checks the process exit status before decoding its stdout as the signature bytes. It never validates that the decoded output is non-empty, so a process that exits successfully (`status.success() == true`) but writes no signature to stdout will be silently treated as having produced a valid (zero-length) signature, exactly mirroring the `TRST-M-4` bug class of confusing "no output" with "valid empty output."

### Finding Description
`sign()` spawns `/usr/bin/orb-sign-iris-code`, feeds it the base64-encoded data to sign, waits for completion, and only gates on `output.status.success()` before decoding stdout: [1](#0-0) 

If the exit code is `0` but stdout is empty (e.g. the signer crashes after setting exit status, is killed/truncated in a race, or is a tampered/misbehaving binary that still returns success), `BASE64.decode(&output.stdout)` succeeds and returns `Ok(vec![])` — an empty `Vec<u8>` — with no error raised. There is no check anywhere in this function (or its callers) for `signed.is_empty()`.

This empty "signature" then flows unchecked into two security-relevant call sites:
- `make_signature()` in the enrollment plan, which base64-encodes the (possibly empty) signature and sends it to the backend as the `signature` field proving the iris code was attested by the orb's secure element: [2](#0-1) [3](#0-2) 
- The Personal Custody Package builder, which also calls `secure_element::sign` to attest the uploaded biometric package: [4](#0-3) 

In both cases the code only propagates a hard error (`?`) if the external process explicitly failed; a "successful" but empty result is indistinguishable from a legitimately signed (non-empty) signature at this layer.

### Impact Explanation
The secure-element signature is meant to attest that the enrolled iris code/PCP truly originated from this orb's hardware security module, which is used by the backend as part of fraud/attestation checks. If the signing subprocess can be made to exit `0` with empty stdout (process crash after status set, resource exhaustion, corrupted/tampered binary, or an attacker-controlled `orb-sign-iris-code` replacement), orb-core will silently forward an empty/non-conforming "signature" as if it were a legitimate attestation, undermining the integrity guarantee the signature is supposed to provide for that signup's biometric attestation and enabling attestation forgery/misattributed-signup risk if backend validation logic is not equally strict about non-empty signature bytes.

### Likelihood Explanation
Requires an anomalous condition in the local `orb-sign-iris-code` process (partial crash, race between exit and stdout flush, or supply-chain/tamper of the signer binary) that yields exit code `0` with empty output — not attacker-controlled over the network, but plausible as a local fault-injection/tamper scenario given the orb runs the signer via `Command`/`Stdio::piped()` without any output-length assertion.

### Recommendation
In `secure_element::sign()`, after decoding, explicitly reject empty results (and ideally validate an expected minimum signature length) before returning `Ok`, e.g. `bail!("orb-sign-iris-code returned an empty signature")` when `decoded.is_empty()`. This closes the gap between "process succeeded" and "produced a valid signature," consistent with the recommended mitigation in the reported bug class.

### Proof of Concept
1. Replace/patch the `orb-sign-iris-code` binary (or trigger a crash-after-exit-set race) so it exits with status `0` while writing zero bytes to stdout.
2. Call `secure_element::sign(data)`; observe it returns `Ok(vec![])` instead of an error. [5](#0-4) 
3. `make_signature()` proceeds to `BASE64.encode(&signed)` producing an empty-string signature, which is then submitted in the signup request without any local rejection: [6](#0-5)

fn make_signature(user_qr_code: &qr_scan::user::Data, pipeline: &Pipeline) -> Result<String> {
    let mut ctx = Context::new(&SHA256);
    ctx.update(ORB_ID.as_str().as_bytes());
    ctx.update(user_qr_code.user_id.as_bytes());
    ctx.update(pipeline.v2.ir_net_version.as_bytes());
    ctx.update(pipeline.v2.iris_version.as_bytes());
    ctx.update(pipeline.v2.eye_left.iris_code.as_bytes());
    ctx.update(pipeline.v2.eye_left.mask_code.as_bytes());
    ctx.update(pipeline.v2.eye_left.iris_code_version.as_bytes());
    ctx.update(pipeline.v2.eye_right.iris_code.as_bytes());
    ctx.update(pipeline.v2.eye_right.mask_code.as_bytes());
    ctx.update(pipeline.v2.eye_right.iris_code_version.as_bytes());
    let signed = secure_element::sign(ctx.finish())?;
    Ok(BASE64.encode(&signed))
}
