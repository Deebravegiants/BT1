### Title
Unbounded `GetRequest` batch size with fixed, size-independent declared weight in `pallet-state-coprocessor::handle_get_requests` - (File: modules/pallets/state-coprocessor/src/impls.rs, modules/pallets/state-coprocessor/src/lib.rs)

### Summary
`pallet_state_coprocessor::Pallet::handle_unsigned` accepts a `GetRequestsWithProof` whose `requests: Vec<GetRequest>` field has no maximum length enforced anywhere in the call, in `validate_unsigned`, or in the declared extrinsic weight. [1](#0-0)  The extrinsic is dispatched via `ensure_none(origin)` (unsigned) and is validated purely by re-running the same unbounded handler in `validate_unsigned`, so any network participant able to gossip a transaction can submit it, exactly like the "authenticated network attacker" class in the reference advisory but here requiring no authentication at all. [2](#0-1) 

### Finding Description
`handle_get_requests` performs, per element of the caller-supplied `requests` vector: a `dedup_requests` pass, per-request timestamp/state-machine checks, a full membership-proof verification over all commitments, and then — in a second loop — a `verify_state_proof` call plus ABI-encoding of a `GetResponse` for every single request. [3](#0-2)  None of these steps bound `requests.len()`; an attacker can pad `GetRequestsWithProof.requests` with an arbitrarily large number of `GetRequest`s (each itself containing a `keys: Vec<Vec<u8>>` that can also be inflated), forcing the runtime to perform proof verification and memory allocation proportional to the attacker-chosen batch size before any economic check occurs.

The `#[pallet::weight]` attribute for `handle_unsigned` is a constant, `<T as frame_system::Config>::DbWeight::get().reads_writes(1, 2)`, independent of `requests.len()`. [4](#0-3)  Substrate's block-authoring/import pipeline uses the declared weight (not actual execution cost) to decide how many extrinsics fit in a block. Because the declared weight never scales with the size of `requests`, the runtime can under-charge and over-admit a single unsigned extrinsic whose real computational/allocation cost (Vec allocations, per-request proof verification, ABI encoding of each `GetResponse`) is far larger than the constant it declares. This is the direct analog of the Vaadin `DataCommunicator` bug: a "row count" parameter (`requests.len()`) controlled by the caller is not checked before performing per-row work, and the accounting layer (here, extrinsic weight) does not reflect it, enabling heap/CPU exhaustion.

This is reachable by an unprivileged actor: `handle_unsigned` is unsigned and open to any relayer, and `validate_unsigned` itself re-executes the entire unbounded handler before admitting the transaction to the pool, so the expensive work happens even for transactions that are ultimately rejected from the pool — a double-exposure to the same unbounded cost. [5](#0-4) 

By contrast, the ISMP core `request.rs`/`response.rs` handlers reject empty batches but likewise never cap batch size, though these are dispatched through `pallet-ismp::execute`, whose call-level weight I could not fully confirm scales with message count due to incomplete access to `modules/pallets/ismp/src/lib.rs` in this session. [6](#0-5) 

### Impact Explanation
Uncapped, cost-mismatched batches allow a single unsigned extrinsic to force disproportionate computation (multiple proof verifications, key lookups, allocations for each `GetRequest`/`GetResponse`) relative to the weight fee/block-space the runtime believes it is charging. Repeated submission of maximal-size batches can be used to stall block production or exhaust validator/collator memory processing the extrinsic pool and block execution — a resource-exhaustion denial of service against the chain that other relayers, apps, and users depend on for message delivery, matching CWE-400 and the "route unable to deliver messages" acceptance criterion.

### Likelihood Explanation
High: the call is unsigned (`ensure_none`), requires no economic stake or prior relationship, and the only "gate" (`BandwidthGate::try_consume`) is applied per-request only after the expensive proof-verification loop has already run, and even that gate is bypassed entirely by `validate_unsigned`'s pre-execution of the same unbounded logic. Any peer capable of submitting extrinsics to a collator's transaction pool can trigger the cost.

### Recommendation
- Enforce a hard maximum on `GetRequestsWithProof.requests.len()` (and on aggregate `keys` size) at the very start of `handle_get_requests`, before `dedup_requests` or any proof work.
- Make the declared `#[pallet::weight]` for `handle_unsigned` a function of `message.requests.len()` (and key sizes), using a proper `WeightInfo` benchmark, instead of a fixed `reads_writes(1, 2)`.
- Consider charging or bounding cost in `validate_unsigned` before re-running the full handler, e.g., a cheap length/size check that short-circuits oversized batches without doing proof verification.

### Proof of Concept
1. Construct a `GetRequestsWithProof` where `requests` contains N (e.g., tens of thousands) distinct `GetRequest`s, each with valid-looking but ultimately-failing (or minimal) proof data, all sharing the same `source`/`response` height so the early-loop checks pass.
2. Submit via `subxt::dynamic::tx("StateCoprocessor", "handle_unsigned", ...)` as an unsigned extrinsic, as done in the existing test helper flow. [7](#0-6) 
3. Observe that `validate_unsigned` and then transaction execution both run `handle_get_requests` over the full N-sized vector — performing N state-proof verifications and N ABI encodings — while the extrinsic's declared weight stays at the constant `reads_writes(1, 2)`, regardless of N. [8](#0-7)  Scaling N up increases actual execution time/memory disproportionately to the weight charged, enabling a heap/CPU-exhaustion DoS.

	pub fn handle_get_requests(
		GetRequestsWithProof { requests, source, response, address }: GetRequestsWithProof,
	) -> Result<(), Error> {
		// 1. Verify source proofs
		// 2. Extract fees
		// 3. Verify response proof
		// 4. insert GetResponse into mmr and request receipts
		// 5. emit Response events
		let host = <<T as Config>::IsmpHost>::default();

		// Reject duplicate requests within the batch.
		let wrapped: Vec<Request> = requests.iter().cloned().map(Request::Get).collect();
		dedup_requests::<<T as Config>::IsmpHost>(&wrapped)?;

		for req in requests.iter() {
			let full = Request::Get(req.clone());

			// Get requests time out are relative to Hyperbridge
			if full.timed_out(host.timestamp()) {
				Err(Error::RequestTimeout { meta: full.clone().into() })?
			}

			// Source of the request must match the proof
			if full.source_chain() != source.height.id.state_id {
				Err(Error::RequestProofMetadataNotValid { meta: full.clone().into() })?
			}

			// Proof must come from the requested chain
			if full.dest_chain() != response.height.id.state_id {
				Err(Error::RequestProofMetadataNotValid { meta: full.clone().into() })?
			}

			// This request has already been responded to. Mirror `handlers/response.rs:61`:
			// dedup against `response_receipt`, which the dispatch path writes for this exact
			// GetRequest hash after producing a response. The receipt also binds the response
			// commitment, so external auditors can attest "Hyperbridge produced response X for
			// request Y" from one map.
			let probe = GetResponse { get: req.clone(), values: Default::default() };
			if host.response_receipt(&probe).is_some() {
				Err(Error::DuplicateResponse { meta: (&probe).into() })?
			}
		}

		// Ensure the proof height is equal to each retrieval height specified in the Get
		// requests
		if !requests.iter().all(|get| get.height == response.height.height) {
			Err(Error::InsufficientProofHeight)?
		}

		// Verify source proof
		let source_state_machine = validate_state_machine(&host, source.height)?;
		let state_root = host.state_machine_commitment(source.height)?;

		// Verify membership proof to ensure that requests where committed on source chain
		let commitments = requests
			.iter()
			.map(|get| hash_request::<<T as Config>::IsmpHost>(&Request::Get(get.clone())))
			.collect();
		source_state_machine.verify_membership(&host, commitments, state_root, &source)?;

		// Verify response proof
		let dest_state_machine = validate_state_machine(&host, response.height)?;
		let state_root = host.state_machine_commitment(response.height)?;

		// Insert GetResponses into mmr
		let mut responses = vec![];
		// Total payload bytes across this batch, used to mint reputation to
		// the relayer named in `address`. Each response contributes its
		// abi-encoded size — the same quantity the bandwidth gate charges —
		// so the mint stays proportional to the work paid for.
		let mut total_bytes: u32 = 0;
		for req in requests {
			let values: Vec<StorageValue> = dest_state_machine
				.verify_state_proof(&host, req.keys.clone(), state_root.state_root, &response)?
				.into_iter()
				.map(|(key, value)| StorageValue { key, value })
				.collect();

			let response = GetResponse { get: req, values };

			// Meter the app's bandwidth using the full size of the
			// abi-encoded GetResponse. Charged after proof verification
			// so the value sizes are final.
			let bytes = ismp::abi::encode_get_response(&response).len() as u32;
			<T as Config>::BandwidthGate::try_consume(
				&response.get.source,
				&response.get.from,
				bytes,
			)
			.map_err(|err| Error::Custom(alloc::format!("bandwidth gate: {err}")))?;
			total_bytes = total_bytes.saturating_add(bytes);

			responses.push(response);
		}
