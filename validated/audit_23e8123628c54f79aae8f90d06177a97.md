## Analysis

Hyperbridge's `CallDispatcher` contract is the direct architectural analog of Connext's `Executor`: it receives tokens/ETH and then executes attacker/user-supplied `Call[]` arrays (arbitrary `to`, `value`, `data`) via a raw external call, exactly the pattern flagged in the report. The critical detail is that `CallDispatcher.dispatch()` has **no access control** and the contract is **shared and persistent** across multiple apps/chains, so any balance left behind is reachable by anyone.

### Title
Unrestricted `CallDispatcher.dispatch()` lets anyone steal any token/native balance stranded at the shared dispatcher - (File: `evm/src/utils/CallDispatcher.sol`)

### Summary
`CallDispatcher.dispatch(bytes memory encoded)` is `external` with zero access control, and it is deployed once and shared across `HyperFungibleToken`, `WrappedHyperFungibleToken`, and `IntentGatewayV2` on a given chain. Its purpose is to receive tokens temporarily and immediately execute an attached `Call[]`, but several code paths leave token or native balances resident at the dispatcher without ever sweeping them. Because `dispatch()` can be invoked directly by anyone (not just the apps that are supposed to own the transient funds), an attacker can submit their own `Call[]` targeting any ERC20 the dispatcher holds with `approve(attacker, type(uint256).max)`, then drain it via `transferFrom` — the same "malicious call data can steal unclaimed tokens" pattern as the original Connext `Executor` finding.

### Finding Description
`CallDispatcher.dispatch()` decodes an arbitrary `Call[]` and blindly forwards `to.call{value: call.value}(call.data)` for each entry, with no caller restriction: [1](#0-0) 

This dispatcher is intentionally shared: the same `CALL_DISPATCHER` address is configured for `HyperFungibleToken`/`WrappedHyperFungibleToken` deployments and separately referenced as `dispatcher` in `IntentGatewayV2`'s `Params`, confirmed by deployment scripts and testnet config using one `CALL_DISPATCHER` value across apps: [2](#0-1) [3](#0-2) 

Multiple call sites leave the dispatcher holding leftover balances without ever sweeping them back:

1. `HyperFungibleToken.onAccept()` mints tokens and then calls `ICallDispatcher(_dispatcher).dispatch(message.data)` with no follow-up sweep of any residual balance the dispatch call may leave behind (e.g. partial swap remainders, unconsumed intermediate tokens): [4](#0-3) 

2. `WrappedHyperFungibleToken.onAccept()` has the identical pattern — dispatch with no sweep-back: [5](#0-4) 

3. Even `IntentsBase._execute()`, which *does* sweep after dispatch, only sweeps the specific `order.output.assets` tokens/native balance — any other token the postdispatch calls incidentally cause the dispatcher to acquire (e.g. an intermediate swap-path token, DEX dust, or unrelated ERC20 sent by a different order's malicious calldata) is not swept and remains stranded indefinitely: [6](#0-5) 

The docs themselves acknowledge the dispatcher can retain funds beyond the intended amount ("Token approvals in the `Call[]` should use exact amounts rather than unlimited allowances, since the dispatcher contract holds tokens temporarily during execution") and that `receive()` accepts arbitrary ETH: [7](#0-6) 

Because `dispatch()` has no `onlyHost`/`onlyGateway`/`onlyOwner` guard, an attacker does not need to go through any app's `onAccept`/`fillOrder` path at all — they can call `CallDispatcher.dispatch()` directly with their own `Call[]`, e.g. `{to: strandedToken, value: 0, data: abi.encodeWithSelector(IERC20.approve.selector, attacker, type(uint256).max)}`, granting themselves an allowance over whatever balance of `strandedToken` the shared dispatcher is holding (accumulated across HFT deliveries, WrappedHFT deliveries, and IntentGatewayV2 fills), then draining it with `transferFrom`.

### Impact Explanation
This is a High severity, direct theft-of-funds vector: any ERC20 or native balance that accumulates at the shared `CallDispatcher` — whether from HFT/WrappedHFT calldata deliveries that never sweep, from IntentGatewayV2 fills whose postdispatch calls acquire tokens outside `order.output.assets`, or from stray/accidental transfers to the dispatcher's unguarded `receive()` — is claimable by any unprivileged actor, permanently and irrevocably, since `dispatch()` imposes no restriction on caller, target, or calldata.

### Likelihood Explanation
Likelihood is high: the dispatcher is a single, long-lived, shared contract used by every HFT/WrappedHFT deployment and by `IntentGatewayV2` on a chain, so it is a continuously growing target. No privileged role, race condition, or unusual precondition is required — any address can call `dispatch()` at any time, and normal usage (partial swap slippage, dust, imprecise routing in composable calldata) is expected to leave residual balances behind per the project's own documentation.

### Recommendation
Restrict `CallDispatcher.dispatch()` to a whitelist of authorized callers (the specific HFT/WrappedHFT/IntentGatewayV2 instances that are meant to use it), or make the dispatcher single-use/ephemeral (e.g., deploy a fresh minimal-proxy dispatcher instance per delivery via `CREATE2`/`CREATE` so no persistent shared balance ever exists). Additionally, ensure every code path that transfers value to the dispatcher (`HyperFungibleToken.onAccept`, `WrappedHyperFungibleToken.onAccept`) sweeps *all* residual balances (not just the tokens explicitly listed for the operation) back to a safe, protocol-controlled address before returning.

### Proof of Concept
1. Wait for (or induce, e.g., via a composable calldata swap that leaves dust) any ERC20 balance to sit at the shared `CallDispatcher` address as a result of a legitimate HFT/WrappedHFT/IntentGatewayV2 operation.
2. As an arbitrary unprivileged address, call:
```solidity
Call[] memory calls = new Call[](1);
calls[0] = Call({
    to: strandedToken,
    value: 0,
    data: abi.encodeWithSelector(IERC20.approve.selector, attacker, type(uint256).max)
});
CallDispatcher(dispatcherAddress).dispatch(abi.encode(calls));
```
`CallDispatcher.dispatch` has no caller restriction, so this succeeds unconditionally per [1](#0-0) .
3. `attacker` then calls `IERC20(strandedToken).transferFrom(dispatcherAddress, attacker, IERC20(strandedToken).balanceOf(dispatcherAddress))` to drain the full stranded balance.

```text
    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
```

```text
    function onAccept(IncomingPostRequest calldata incoming) public virtual override onlyHost whenNotPaused {
        PostRequest calldata request = incoming.request;

        bytes memory expectedSource = _supportedChains[request.source];
        if (expectedSource.length == 0) revert UnsupportedChain();
        if (keccak256(request.from) != keccak256(expectedSource)) revert UnauthorizedSource();

        Message memory message = abi.decode(request.body, (Message));
        address beneficiary = _toAddr(message.to);
        _mint(beneficiary, message.amount);

        if (message.data.length > 0) {
            ICallDispatcher(_dispatcher).dispatch(message.data);
        }

        emit Received({
            from: message.from,
            to: beneficiary,
            source: string(request.source),
            amount: message.amount
        });
    }
```

```text
        PostRequest calldata request = incoming.request;

        bytes memory expectedSource = _supportedChains[request.source];
        if (expectedSource.length == 0) revert UnsupportedChain();
        if (keccak256(request.from) != keccak256(expectedSource)) revert UnauthorizedSource();

        HyperFungibleToken.Message memory message = abi.decode(request.body, (HyperFungibleToken.Message));
        address beneficiary = _toAddr(message.to);

        if (_isWeth) {
            // Try a native-ETH push first (cheap for EOAs and payable contracts);
            // if the recipient cannot accept native value (no `receive()` / `fallback()
            // payable`), re-wrap the withdrawn ETH and deliver the underlying WETH as
            // an ERC-20 transfer instead. This mirrors the deposit-side flexibility of
            // `send()` (which accepts WETH from non-payable callers via `safeTransferFrom`)
            // so the refund path doesn't permanently lock funds for the same caller class.
            IWETH(_underlying).withdraw(message.amount);
            (bool sent,) = beneficiary.call{value: message.amount}("");
            if (!sent) {
                IWETH(_underlying).deposit{value: message.amount}();
                IERC20(_underlying).safeTransfer(beneficiary, message.amount);
            }
        } else {
            IERC20(_underlying).safeTransfer(beneficiary, message.amount);
        }

        if (message.data.length > 0) {
            ICallDispatcher(_dispatcher).dispatch(message.data);
        }
```

```text
    function _execute(Order calldata order, uint256 outputsLen) internal {
        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            } else {
                uint256 balance = IERC20(token).balanceOf(dispatcher);
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            }

            unchecked {
                ++i;
            }
        }
```
