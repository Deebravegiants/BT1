### Title
Unbounded accumulation of `calibration.mirror.{phi,theta}_offset_degrees` via repeated `continuous_calibration` calls permanently corrupts mirror aim for all future signups - ([File: src/plans/biometric_capture/mod.rs], [File: src/agents/mirror.rs])

### Summary
`continuous_calibration` adds a damped but unclamped delta to the persisted mirror calibration offsets after every successful biometric capture, and `mirror::Command::Recalibrate` in `Actuator::run` accepts any `Calibration` value unconditionally with no bound check. Because this offset is written to `CALIBRATION_FILE_PATH` and reloaded on every boot, an attacker who repeatedly completes genuine-looking successful signups while biasing their eye position can push the stored offset arbitrarily far in one direction, permanently degrading mirror aim for all subsequent signups on that Orb.

### Finding Description
`continuous_calibration` computes the minimum-magnitude mirror offset seen during a successful capture, scales it by `CONTINUOUS_CALIBRATION_REDUCER` (0.05), and unconditionally adds it to the persisted calibration: [1](#0-0) 

This new `Calibration` is stored to disk and sent to the mirror agent via `orb.recalibrate`: [2](#0-1) 

`Actuator::run` replaces its in-memory calibration offset with whatever value it receives, with no range validation: [3](#0-2) 

The only clamp in the pipeline is applied to the *final computed mirror position* (`eye tracker point + eye_pid_controller offset + calibration offset`) against hardware-range constants, right before dispatch to the MCU: [4](#0-3) 

That clamp protects the physical actuator from being commanded outside its mechanical range, but it does not protect the *calibration.mirror* base offset from growing without bound. `CONTINUOUS_CALIBRATION_REDUCER` only dampens the magnitude added per successful capture — it does not cap the cumulative sum. As offset magnitude grows across many successful captures, it increasingly dominates the true eye-tracker/PID correction terms, so the final (pre-clamp) target position saturates at the hardware boundary regardless of the real detected eye position, and the Orb effectively loses the ability to track real users' eyes. Because `Calibration::load` accepts any well-formed, version-matching file (no bounds validation), this corrupted state persists across reboots: [5](#0-4) 

An unprivileged attacker only needs to repeatedly complete genuine full signups (passing real iris/face capture, fraud, and liveness checks) while consistently biasing where their eye sits relative to the tracked center, so that `mirror_offsets` collected in `run_check` consistently skew in one direction: [6](#0-5) 

Each such session, `continuous_calibration` only fires `if capture.is_some()` (i.e., the signup was scored as biometrically successful), which gates the attack behind real capture success but does not bound the number of times it can be repeated: [7](#0-6) 

### Impact Explanation
Repeated exploitation permanently biases the persisted mirror calibration (`calibration.mirror.phi_offset_degrees`/`theta_offset_degrees`), which is stored on disk and reloaded on every boot. Once the accumulated offset is large enough, the mirror's actual commanded position (offset + true eye tracker signal) will saturate at the hardware-clamped boundary for essentially all subsequent legitimate signups, regardless of where an honest user's eye actually is. This degrades iris/face capture quality Orb-wide for that unit, potentially causing capture failures or degraded biometric quality that could interact with downstream fraud/liveness checks that rely on well-aimed, well-focused capture — a real integrity/availability impact requiring operator intervention (manual recalibration or calibration-file reset) to remediate.

### Likelihood Explanation
Exploitation requires repeatedly and successfully completing full biometric capture (passing iris/face quality, fraud, and liveness checks) many times while consistently biasing eye positioning — this is a real but effortful precondition (not a single-request exploit), and the per-session contribution is heavily damped (`min-by-abs` offset selection × 0.05 reducer). However, there is no logical upper bound anywhere in the code enforcing a cap on total accumulated drift, so with enough repeated successful sessions the attack is deterministically achievable by a physically-present unprivileged user/attacker.

### Recommendation
Clamp `calibration.mirror.phi_offset_degrees` / `theta_offset_degrees` to a sane physical bound (e.g., matching `MIRROR_PHI_MIN/MAX` and `MIRROR_THETA_MIN/MAX` ranges converted to degrees, or a smaller "reasonable drift" window) both when computing the new value in `continuous_calibration` and defensively in `mirror::Command::Recalibrate`/`Calibration::load`, so no single or cumulative update can push the stored offset outside an operationally safe range.

### Proof of Concept
Property/invariant test in `src/plans/biometric_capture/mod.rs` or `src/calibration.rs`:
1. Start with a baseline `Calibration` (offsets = 0).
2. Repeatedly call `continuous_calibration(orb, mirror_offsets)` with adversarial `mirror_offsets` vectors (e.g., `vec![Point{phi_degrees: 10.0, theta_degrees: 10.0}; N]`) for many iterations (e.g., 10,000), each simulating one successful signup.
3. After each call, read back `orb.calibration().mirror.phi_offset_degrees` / `theta_offset_degrees`.
4. Assert `phi_offset_degrees.abs()` and `theta_offset_degrees.abs()` stay below a defined safe bound (e.g., `MIRROR_PHI_MAX_PEARL - MIRROR_PHI_MIN_PEARL` in degrees) across all iterations — the current implementation will fail this assertion since the values grow monotonically without bound.

    pub async fn load<P: AsRef<Path>>(path: P) -> Result<Self> {
        let path = path.as_ref();
        if !path.exists() {
            tracing::error!("Calibration file: {} not exists", path.display());
            bail!("Calibration file not exists");
        }
        tracing::info!("Loading calibration file: {}", path.display());
        let contents = fs::read_to_string(path).await?;
        tracing::debug!("Calibration file contents: {contents:#?}");

        match serde_json::from_str::<Calibration>(&contents) {
            Ok(config) if config.mirror.version == VERSION => Ok(config),
            Ok(config) => {
                tracing::warn!(
                    "Calibration file version: {}, will update to: {VERSION}",
                    config.mirror.version
                );
                bail!("Calibration file version mismatch");
            }
            Err(e) => {
                tracing::error!("Calibration loading error: {e:#?}");
                Err(e.into())
            }
        }
    }
