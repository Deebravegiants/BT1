Audit Report

## Title
Gateway HTTP trigger response handler always reports `NoError`/success even when all nodes agree on a JSON-RPC error, masking failed workflow executions - ([File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go])

## Summary
`httpTriggerHandler.HandleNodeTriggerResponse` forwards the aggregated node response to the external caller but hardcodes `ErrorCode: api.NoError` regardless of whether the aggregated JSON-RPC response contains a `WireError`. Since `IdenticalNodeResponseAggregator.CollectAndAggregate` aggregates purely by content digest with no success/failure semantics, an error response that reaches quorum is delivered to the caller as if it succeeded.

## Finding Description
`CollectAndAggregate` in [1](#0-0)  groups responses solely by digest (`resp.Digest()`) and returns the aggregated response once `threshold` nodes agree — there is no check on `resp.Error`, so an identical error response reaches quorum and is returned just like a success response.

In `HandleNodeTriggerResponse`, the aggregated response is marshaled and sent to the caller with `ErrorCode` unconditionally set to `api.NoError`, never inspecting `aggResp.Error`: [2](#0-1) . The success metric is then unconditionally incremented: [3](#0-2) .

This differs from the pattern used elsewhere in the gateway, e.g. `vault/handler.go`'s `sendSuccessResponse`, which explicitly branches on `resp.Error != nil` to select the correct `ErrorCode` via `api.FromJSONRPCErrorCode`. That existing, working pattern confirms the `http_trigger_handler.go` omission is a real gap rather than intended behavior.

The `ErrorCode` set here is not cosmetic: `gateway.ProcessRequest` uses `response.ErrorCode` to compute the final HTTP status returned to the caller via `api.ToHTTPErrorCode(response.ErrorCode)` [4](#0-3) , and `api.ToHTTPErrorCode` maps `NoError` to HTTP `200` [5](#0-4) . Thus a JSON-RPC error body agreed upon by all nodes is delivered with an HTTP 200 status.

## Impact Explanation
An unprivileged external caller invoking an HTTP-triggered workflow through the gateway receives HTTP 200 for a request whose workflow execution deterministically failed at the DON level (JSON-RPC `error` present in the response body). Integrations that branch on HTTP status codes — a standard integration pattern — will treat a failed execution as successful. This also corrupts the `IncrementRequestSuccess`/error-rate metrics used for gateway observability and alerting.

## Likelihood Explanation
No malicious node or attacker action is required: any workflow that deterministically returns the same JSON-RPC error across `2f+1` nodes (e.g., input validation failure, capability error) reaches this code path through completely normal HTTP trigger usage by any unprivileged caller. This is a common, easily repeatable scenario rather than an edge case.

## Recommendation
In `HandleNodeTriggerResponse`, inspect `aggResp.Error` after `CollectAndAggregate` returns, mirroring `vault/handler.go`'s `sendSuccessResponse` pattern, and set `ErrorCode` via `api.FromJSONRPCErrorCode(aggResp.Error.Code)` (or an equivalent mapping) when an error is present, defaulting to `api.NoError` only when `aggResp.Error == nil`. Increment success/failure metrics based on the same condition.

## Proof of Concept
1. Register an HTTP-triggered workflow assigned to a DON/shard whose execution deterministically returns a JSON-RPC error (e.g., a capability validation failure).
2. As an unprivileged caller, invoke the HTTP trigger through the gateway (`HandleUserTriggerRequest` → `gateway.ProcessRequest`).
3. Have `threshold` (`2f+1`) nodes call `HandleNodeTriggerResponse` with identical error-bearing `jsonrpc.Response` payloads for the same request ID.
4. Observe `CollectAndAggregate` returns the error response once threshold is reached; `HandleNodeTriggerResponse` calls `SendResponse` with `ErrorCode: api.NoError`; `gateway.ProcessRequest` returns HTTP `200` (`api.ToHTTPErrorCode(api.NoError)`) with a body containing `"error": {...}`, confirming the mismatch between transport status and JSON-RPC payload content.

func (agg *IdenticalNodeResponseAggregator) CollectAndAggregate(
	resp *jsonrpc.Response[json.RawMessage],
	nodeAddress string) (*jsonrpc.Response[json.RawMessage], error) {
	if resp == nil {
		return nil, errors.New("response cannot be nil")
	}
	if nodeAddress == "" {
		return nil, errors.New("node address cannot be empty")
	}

	key, err := resp.Digest()
	if err != nil {
		return nil, fmt.Errorf("error generating digest for response: %w", err)
	}

	// Check if the node already submitted a different response
	if oldKey, exists := agg.nodeToResponse[nodeAddress]; exists && oldKey != key {
		if nodes, ok := agg.responses[oldKey]; ok {
			nodes.Remove(nodeAddress)
			// Clean up empty response groups
			if len(nodes) == 0 {
				delete(agg.responses, oldKey)
			}
		}
	}

	if _, ok := agg.responses[key]; !ok {
		agg.responses[key] = make(StringSet)
	}
	agg.responses[key].Add(nodeAddress)
	agg.nodeToResponse[nodeAddress] = key

	if len(agg.responses[key]) >= agg.threshold {
		return resp, nil
	}

	return nil, nil
}

func ToHTTPErrorCode(errorCode ErrorCode) int {
	gatewayErrorToHTTPError := map[ErrorCode]int{
		NoError:                  200, // OK
		UserMessageParseError:    400, // Bad Request
		UnsupportedDONIdError:    400, // Bad Request
		UnsupportedMethodError:   400, // Bad Request
		HandlerError:             400, // Bad Request
		InvalidParamsError:       400, // Bad Request
		RequestTimeoutError:      504, // Gateway Timeout
		NodeReponseEncodingError: 500, // Internal Server Error
		FatalError:               500, // Internal Server Error
		StaleNodeResponseError:   500, // Internal Server Error
		ConflictError:            409, // Conflict
		LimitExceededError:       429, // Too Many Requests
	}

	code, ok := gatewayErrorToHTTPError[errorCode]
	if !ok {
		return 500
	}
	return code
}
