### Title
Orb-Relay client processes `RequestState` messages without verifying sender identity, bypassing the origin check applied to all other message types - ([File: orb-relay-client/src/client.rs])

### Summary
The `PythPriceFeedUpdate` report describes a class of bug where a message type reachable from an untrusted external channel is processed without the authorization/origin check that is applied to every other message type, letting an unprivileged actor influence state that should only be updatable by a verified counterpart. `orb-core`'s `orb-relay-client` (used to carry protocol state — `AnnounceOrbId`, `CaptureStarted`, `CaptureTriggerTimeout`, `SignupEnded` — between the Orb and the user's mobile app during a self-serve signup) contains the same class of flaw: the `RequestState` message is special-cased to be answered *before* the sender-identity check that every other incoming payload must pass.

### Finding Description
In `PollerAgent::main_loop`, incoming messages from the relay stream are dispatched as follows: [1](#0-0) 

```rust
message = response_stream.next() => {
    match message {
        Some(Ok(RelayConnectResponse {
            msg: Some(relay_connect_response::Msg::Payload(RelayPayload {
                src: Some(src), dst, seq, payload: Some(payload),
            })),
        })) => {
            if self_serve::app::v1::RequestState::matches(&payload).is_some() {
                sender_tx.send(self.last_message.clone()).await...   // <-- no src check
            } else if src.id != self.config.dst_id {
                tracing::error!("Skipping received message from unexpected source: ...");
            } else {
                self.handle_message(...).await?;
            }
        }
        ...
```

Every other message type is gated by `src.id != self.config.dst_id` — a check that the sender is exactly the paired counterpart for this signup session [2](#0-1) . `RequestState`, however, is matched and answered unconditionally, before that identity check runs, causing the client (Orb) to immediately reply with `self.last_message` — the most recent state message sent for the current signup (e.g. `AnnounceOrbId`, `CaptureStarted`, `SignupEnded`) [3](#0-2) .

The developers themselves acknowledge that the relay queue can receive traffic from multiple sources and that auth/subscription separation is not yet implemented: [4](#0-3) 

This is functionally the same root cause as the Pyth bug: a message type that should only be honored from a specifically authenticated/paired counterpart is processed unconditionally, defeating the per-message-type trust boundary that the rest of the protocol relies on. In the self-serve signup flow, this same state (`last_message`) drives session-critical control decisions — e.g. `proceed_with_biometric_capture` blocks on `StartCapture` from the app and reports `CaptureStarted`/`CaptureTriggerTimeout` back over this same channel [5](#0-4) , and `orb_relay_announce_orb_id` uses this channel to bind the Orb to a specific `orb_relay_app_id` extracted from the user's QR code for the duration of the signup [6](#0-5) .

### Impact Explanation
Any entity capable of injecting a `RequestState` payload into the Orb's relay session — without being validated as the legitimate paired app for that `session_id`/`orb_relay_app_id` — can extract the current signup-session state (which QR-derived session is active, whether capture has started, whether a signup ended and its outcome) without passing the identity check the protocol otherwise enforces. Because the same connection multiplexes messages from potentially different sources (as the code comment states), this creates a state-disclosure and identity-binding weakness for the self-serve signup session, analogous to the "cross-signup state bleed" impact category.

### Likelihood Explanation
Exploitability depends on whether the backing relay server itself restricts writers to a given orb/session queue strictly to the paired app (server-side enforcement is outside this repository and cannot be verified here). Within `orb-core`'s own client code, however, the `RequestState` short-circuit is unconditionally reachable for any payload delivered to the client's stream, and it is the only message type in `main_loop` exempted from the `src.id != self.config.dst_id` origin check — making it a genuine gap in the client-side trust model regardless of server behavior.

### Recommendation
Apply the same `src.id != self.config.dst_id` origin check to `RequestState` before replying with `self.last_message`, so that state-replay only occurs for the verified paired counterpart, consistent with how all other message types are handled in `PollerAgent::main_loop`.

### Proof of Concept
Not independently reproducible from this repository alone, since it requires the ability to deliver a `RelayPayload{payload: RequestState}` to an Orb's active relay session — which depends on the (out-of-scope) relay server's session/queue authorization. Within the client code path shown above, any such delivered `RequestState` payload is answered with `self.last_message` without checking `src.id`, in contrast to every other payload type in the same match arm.

async fn proceed_with_biometric_capture(orb: &mut Orb) -> Result<bool> {
    let Config {
        self_serve,
        self_serve_app_skip_capture_trigger,
        self_serve_app_capture_trigger_timeout,
        ..
    } = *orb.config.lock().await;
    if !self_serve || self_serve_app_skip_capture_trigger {
        // Biometric capture not gated by a user action. Continue.
        orb.ui.signup_start();
        return Ok(true);
    }

    let orb_relay = orb.orb_relay.as_mut().expect("orb_relay to exist");

    tracing::info!("Waiting for self-serve biometric-capture trigger...");
    if let Err(e) = orb_relay
        .wait_for_msg::<self_serve::app::v1::StartCapture>(self_serve_app_capture_trigger_timeout)
        .await
    {
        if let Err(e) = orb_relay.send(self_serve::orb::v1::CaptureTriggerTimeout {}).await {
            tracing::warn!("failed to send CaptureTriggerTimeout: {e}");
        };
        orb.ui.signup_fail(SignupFailReason::Timeout);
        tracing::warn!("Self-serve biometric-capture start was not triggered: {e}");
        return Ok(false);
    };

    tracing::info!("Self-serve biometric-capture start triggered");
    orb.ui.signup_start();

    tracing::info!("Self-serve: Informing orb-relay that biometric_capture has started");
    orb_relay
        .send(self_serve::orb::v1::CaptureStarted {})
        .await
        .inspect_err(|e| tracing::error!("Relay: Failed to CaptureStarted: {e}"))?;

    Ok(true)
}

async fn orb_relay_announce_orb_id(
    orb: &mut Orb,
    orb_relay_app_id: String,
    is_self_serve_enabled: bool,
    reties: u32,
    timeout: Duration,
    wait_for_pending_messages: Duration,
    wait_for_shutdown: Duration,
) -> Result<()> {
    let mut relay = Client::new_as_orb(
        RELAY_BACKEND_URL.to_string(),
        get_orb_token()?,
        ORB_ID.to_string(),
        orb_relay_app_id,
    );
    if let Err(e) = relay.connect().await {
        dd_incr!("main.count.orb_relay.failure.connect");
        return Err(eyre::eyre!("Relay: Failed to connect: {e}"));
    }
    for _ in 0..reties {
        let now = Instant::now();
        if let Ok(()) = relay
            .send_blocking(
                common::v1::AnnounceOrbId {
                    orb_id: ORB_ID.to_string(),
                    mode_type: if is_self_serve_enabled {
                        common::v1::announce_orb_id::ModeType::SelfServe.into()
                    } else {
                        common::v1::announce_orb_id::ModeType::Legacy.into()
                    },
                    hardware_type: if identification::HARDWARE_VERSION.contains("Diamond") {
                        common::v1::announce_orb_id::HardwareType::Diamond.into()
                    } else {
                        common::v1::announce_orb_id::HardwareType::Pearl.into()
                    },
                },
                timeout,
            )
            .await
        {
            // Happy path. We have successfully announced and acknowledged the OrbId.
            dd_timing!("main.time.orb_relay.announce_orb_id", now);
            orb.orb_relay = if is_self_serve_enabled {
                Some(relay)
            } else {
                relay.graceful_shutdown(wait_for_pending_messages, wait_for_shutdown).await;
                None
            };
            return Ok(());
