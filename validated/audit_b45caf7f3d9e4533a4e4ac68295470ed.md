Audit Report

## Title
Unbounded per-request state accumulation in the Confidential Relay Gateway handler enables memory exhaustion from unprivileged HTTP callers - (File: core/services/gateway/handlers/confidentialrelay/handler.go)

## Summary
`HandleJSONRPCUserMessage` in the Confidential Relay Gateway handler accepts unauthenticated, user-originated `SecretsGet`/`CapabilityExec` JSON-RPC requests over the internet-facing HTTP gateway and, for each accepted request, inserts a long-lived `*activeRequest` into `h.activeRequests` with no cap on the number of concurrently tracked entries [1](#0-0) . Each entry is retained until `removeExpiredRequests` sweeps it after up to `RequestTimeoutSec` (default 30s) [6](#0-5) , and the only rate limiters present (`globalNodeRateLimiter`, `perNodeRateLimiters`) gate fan-out sends to DON member nodes, not admission of the initial request [7](#0-6) .

## Finding Description
`NewHandler` initializes `activeRequests: make(map[string]*activeRequest)` without any bound [8](#0-7) . The entrypoint `HandleJSONRPCUserMessage` validates only that `req.ID` is non-empty and ≤200 characters before calling `newActiveRequest`, which rejects only exact-duplicate IDs — never checking `len(h.activeRequests)` against any maximum before insertion [9](#0-8) . Unlike the sibling Vault handler, which requires `h.requestProcessor.ProcessRequest` (allowlist/JWT-based authorization tied to on-chain workflow registry allowlisting) to succeed before creating an `activeRequest` [10](#0-9) , the confidential relay handler performs no authorization step whatsoever — any caller who can reach the gateway's HTTP endpoint and route to this handler's DON/service can create entries. The HTTP transport layer (`httpServer.handleRequest`) enforces only a request body size cap via `MaxRequestBytesLimiter`; it optionally extracts a JWT bearer token but does not require or validate one before forwarding to `ProcessRequest` [11](#0-10) , and `gateway.ProcessRequest` performs only service/DON-name lookup and basic message decoding before invoking `HandleJSONRPCUserMessage` [12](#0-11) . No admission-time concurrency limiter (semaphore, max-map-size check, or per-caller quota) exists anywhere in this path.

## Impact Explanation
An attacker who can route JSON-RPC requests to the confidential relay handler's service/DON on the gateway's public HTTP endpoint can send a sustained flood of distinct-`ID` requests faster than the ~1s-period/30s-timeout cleanup sweep reclaims them, causing `h.activeRequests` (and its associated mutexes, response maps, and callback state) to grow without bound and exhaust gateway process memory. This is an availability impact on the Gateway component. It does not, by itself, provide secret exfiltration, authentication bypass, or fund movement — its in-scope classification rests on Gateway denial-of-service via unbounded per-request resource allocation.

## Likelihood Explanation
Reaching this handler requires no special credential — any client able to reach the gateway's confidential-relay service endpoint over HTTP (per gateway config routing) and construct a small valid JSON-RPC envelope with a unique `id` (≤200 chars) can trigger allocation; generating unique IDs is trivial. The attack is fully repeatable and scales linearly with request rate, bounded only by the attacker's own network throughput and the 30s reclaim window.

## Recommendation
Add an explicit bound on the number of concurrently tracked `activeRequest` entries in `h.activeRequests` — e.g., a semaphore or size check consulted in `newActiveRequest` before insertion, rejecting or backpressuring requests beyond a configured maximum — independent of the existing per-node/global fan-out rate limiters. Consider adding caller-level admission rate limiting or requiring some minimal authentication/allowlisting at this handler (mirroring the Vault handler's authorization step) before allocating server-side state.

## Proof of Concept
1. Configure a gateway instance with the confidential relay handler enabled for a test DON.
2. From an unauthenticated HTTP client, send a rapid burst of JSON-RPC requests targeting `confidentialrelay.MethodSecretsGet` (or `MethodCapabilityExec`) to the gateway's public endpoint, each with a unique `id` (e.g., UUIDs), at a rate exceeding what the DON can answer and faster than the 30s default `RequestTimeoutSec` expiry.
3. Instrument/observe `len(h.activeRequests)` (or process RSS) growing unboundedly with the number of distinct in-flight IDs, with no request rejected due to a concurrency cap — confirming that `newActiveRequest` only checks for ID collision, not total in-flight count.

func (h *handler) HandleJSONRPCUserMessage(ctx context.Context, req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) error {
	if req.ID == "" {
		return errors.New("request ID cannot be empty")
	}
	if len(req.ID) > 200 {
		return errors.New("request ID is too long: " + strconv.Itoa(len(req.ID)) + ". max is 200 characters")

	l := h.requestLogger(req, labels)

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], labels requestLabels, callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID, "executionID", labels.ExecutionID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		labels:    labels,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

func (h *handler) fanOutToNodes(ctx context.Context, l logger.Logger, ar *activeRequest) error {
	var (
		group      errgroup.Group
		nodeErrors atomic.Uint32
	)

	// Each send is bounded independently. A node whose websocket accepts no writes blocks
	// until its context is cancelled, and because the caller only reads the response callback
	// after this function returns, an unbounded send would hold the request open until the
	// client gives up, discarding a bundle that already reached quorum.
	sendCtx, cancel := context.WithTimeout(ctx, h.nodeSendTimeout)
	defer cancel()

	for _, node := range h.donConfig.Members {
		group.Go(func() error {
			err := h.don.SendToNode(sendCtx, node.Address, &ar.req)
			if err != nil {
				nodeErrors.Add(1)
				l.Errorw("error sending request to node", "node", node.Address, "error", err)
			}
			return nil
		})
	}

	_ = group.Wait()

	jsonRequest, err := jsonrpc2.DecodeRequest[json.RawMessage](rawRequest, auth)

		return newError("", api.UserMessageParseError, err.Error())
	}

		return newError(jsonRequest.ID, api.UserMessageParseError, err.Error())
	}
	if len(jsonRequest.ID) > 200 {
		// Arbitrary limit to prevent abuse
		return newError(jsonRequest.ID, api.UserMessageParseError, "request ID is too long: "+strconv.Itoa(len(jsonRequest.ID))+". max is 200 characters")
	}
	isLegacyRequest := false
	var h handlers.Handler
	var handlerKey string
	if msg == nil || msg.Body.DonID == "" {
		serviceName := jsonRequest.ServiceName()
		if handler, ok := g.serviceToMultiHandler[serviceName]; ok {
			h = handler
			handlerKey = serviceName
		} else if donID, ok := g.serviceNameToDonID[serviceName]; ok {
			// Fallback to legacy service name -> DON ID mapping
			if handler, ok := g.handlers[donID]; ok {
				h = handler
				handlerKey = donID
			}
		}
		if h == nil {
			return newError(jsonRequest.ID, api.HandlerError, "Service name not found: "+serviceName)
		}

		}
		handlerKey = msg.Body.DonID

		h, ok = g.handlers[handlerKey]
		if !ok {
			return newError(jsonRequest.ID, api.UnsupportedDONIdError, "Unsupported DON ID: "+handlerKey)
		}

	var method string
	callback := handlerscommon.NewCallback()

		method = msg.Body.Method
		err = h.HandleLegacyUserMessage(ctx, msg, callback)
	} else {
		method = jsonRequest.Method
		err = h.HandleJSONRPCUserMessage(ctx, jsonRequest, callback)
