## Finding

### Title
Missing role-based access control on Bridge `Show`/`Index` endpoints exposes bridge `OutgoingToken` secrets to view-only users - (File: `core/web/router.go`)

### Summary
Chainlink's RBAC model gates all sensitive write operations on bridges (`Create`, `Update`, `Destroy`) behind `auth.RequiresEditRole`, but the read path (`Show`/`Index`) is registered with no role check at all, so any authenticated user—including the lowest-privilege `view` role—can read the bridge's `OutgoingToken` secret. This mirrors the Weblate `AddonViewSet` bug class: an endpoint intended only for privileged management inadvertently exposes secret configuration data to any authenticated (including low-privileged) caller.

### Finding Description
The v2 router wires up bridge routes as: [1](#0-0) 

`Create`, `Update`, and `Destroy` are wrapped in `auth.RequiresEditRole`, but `GET /v2/bridge_types/:BridgeName` (`bt.Show`) and `GET /v2/bridge_types` (`bt.Index`) are reachable by any authenticated session/token regardless of role. `RequiresEditRole`/`RequiresRunRole`/`RequiresAdminRole` are role-gate middlewares defined in `core/web/auth/auth.go`: [2](#0-1) 

`BridgeTypesController.Show` fetches the bridge and serializes it unconditionally: [3](#0-2) 

The resulting `BridgeResource` presenter always includes `OutgoingToken` (no `omitempty`, always serialized to any caller): [4](#0-3) 

`OutgoingToken` is a per-bridge secret generated at creation time via `utils.NewSecret(24)` and stored alongside the bridge: [5](#0-4) 

The GraphQL resolver path exhibits the same pattern — `authenticateUser` (session presence only, no role check) is sufficient to query a `Bridge`, which also returns `outgoingToken`: [6](#0-5) [7](#0-6) 

The project's own RBAC route-map test explicitly documents this as `viewOnlyAllowed: true` for `GET /v2/bridge_types/:BridgeName` and `GET /v2/bridge_types`, in contrast to write operations which require edit: [8](#0-7) 

### Impact Explanation
`OutgoingToken` is a bridge-scoped secret intended to let the external adapter verify that a request genuinely originates from the Chainlink node (analogous in spirit to the `IncomingToken`/hash used to authenticate incoming callbacks). A `view`-role user — the lowest privilege tier, intended for read-only monitoring — can retrieve this secret for every configured bridge via `GET /v2/bridge_types/:BridgeName` or the equivalent GraphQL `bridge` query, without any edit/admin privilege. This is a direct analog of the Weblate `AddonViewSet` issue: a viewer with no configuration rights can read secret configuration data that should be restricted to users capable of managing (editing) that resource, violating the principle that read access to secrets should require at least the same privilege as write access.

### Likelihood Explanation
Any operator who provisions `view`-role API users/tokens for dashboards, monitoring, or read-only integrations is affected without any additional attacker action — a single authenticated GET request from an unprivileged account is sufficient. No malicious peer, node compromise, or network-layer trickery is required; it's a straightforward client request to the node's own HTTP/GraphQL API.

### Recommendation
Gate `BridgeTypesController.Show` and `Index` (and the GraphQL `bridge`/`bridges` resolvers) behind at least `auth.RequiresEditRole` (matching the write-path restriction), or strip `OutgoingToken` from the response for callers below edit privilege, similar to how `IncomingToken` is already `omitempty`d and only surfaced on creation.

### Proof of Concept
1. As an admin, create a bridge: `POST /v2/bridge_types` with `{"name":"mybridge","url":"https://adapter.example"}`. Note the returned bridge has an `outgoingToken` persisted server-side.
2. Create/authenticate as a `view`-role user (`app.NewHTTPClient` with `Role: sessions.UserRoleView`, or via `/v2/user/token` for a view user).
3. As that view user, call `GET /v2/bridge_types/mybridge`.
4. Observe the JSON API response includes `"outgoingToken": "<secret>"`, even though the view role cannot create, update, or delete bridges — demonstrating unauthorized secret disclosure through the read-only role.

// RequiresEditRole extracts the user object from the context, and asserts the user's role is at least
// 'edit'
func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// Show returns the details of a specific Bridge.
func (btc *BridgeTypesController) Show(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	bt, err := btc.App.BridgeORM().FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}

// NewBridgeType returns a bridge type authentication (with plaintext
// password) and a bridge type (with hashed password, for persisting)
func NewBridgeType(btr *BridgeTypeRequest) (*BridgeTypeAuthentication,
	*BridgeType, error,
) {
	incomingToken := utils.NewSecret(24)
	outgoingToken := utils.NewSecret(24)
	salt := utils.NewSecret(24)

	hash, err := incomingTokenHash(incomingToken, salt)
	if err != nil {
		return nil, nil, err
	}

	return &BridgeTypeAuthentication{
		Name:                   btr.Name,
		URL:                    btr.URL,
		Confirmations:          btr.Confirmations,
		IncomingToken:          incomingToken,
		OutgoingToken:          outgoingToken,
		MinimumContractPayment: btr.MinimumContractPayment,
		UseConnectionManager:   btr.UseConnectionManager,
	}, &BridgeType{
		Name:                   btr.Name,
		URL:                    btr.URL,
		Confirmations:          btr.Confirmations,
		IncomingTokenHash:      hash,
		Salt:                   salt,
		OutgoingToken:          outgoingToken,

	}, nil
