### Title
`CallDispatcher.dispatch()` has no access control, letting any unprivileged caller drain residual tokens/ETH left in the shared dispatcher - (File: evm/src/utils/CallDispatcher.sol)

### Summary
`CallDispatcher.dispatch()` is `external` with zero caller restriction, executing any attacker-supplied `Call[]` to any target address using whatever balance the dispatcher currently holds. `CallDispatcher` is a single shared contract wired into `IntentGatewayV2`/`IntentsBase` (predispatch/postdispatch) and the `HyperFungibleToken`/`WrappedHyperFungibleToken` `onAccept` flows, all of which temporarily route user or solver funds through it. Because the sweep-back logic only recovers the specific tokens listed in `order.inputs`/`order.output.assets`, any other token or native balance that ends up in the dispatcher (e.g. an intermediate swap-hop token, dust from a multi-hop `predispatch`/`postdispatch` call, or accidental transfers) is left sitting in a contract that anyone can command to send funds anywhere.

### Finding Description
`CallDispatcher.dispatch()` decodes an attacker-controlled `Call[]` and executes each entry with `to.call{value: call.value}(call.data)`, with no `onlyOwner`/allowlist/`msg.sender` check whatsoever: [1](#0-0) 

This is architecturally identical to the reported `WalletImpl.execCalls()` bug class: a permissionless "execute arbitrary call" primitive that operates on whatever assets the contract happens to hold at call time, with no restriction on who can trigger it.

`CallDispatcher` is not a per-user, ephemeral contract — it is the single shared `_params.dispatcher` instance used by `IntentGatewayV2.placeOrder()` (predispatch), `IntentsBase._execute()` (postdispatch), and `HyperFungibleToken`/`WrappedHyperFungibleToken.onAccept()` for calldata execution after mint/unlock: [2](#0-1) [3](#0-2) 

In `placeOrder`'s predispatch path, assets are transferred into the dispatcher, `dispatch()` runs user-supplied calldata, and only the exact `order.inputs[i].token` balances are swept back: [4](#0-3) 

Likewise, `_execute()`'s postdispatch sweep only iterates over `order.output.assets` (length `outputsLen`), not over every token that could plausibly end up in the dispatcher from an arbitrary multi-hop swap or DeFi interaction defined in `order.output.call`/`order.predispatch.call`. Any token balance produced as an intermediate byproduct of that calldata — not present in the enumerated asset list — is never swept and permanently remains in the dispatcher's balance, exposed to anyone.

Because `dispatch()` has no access control, any unprivileged address can immediately call `CallDispatcher.dispatch()` with a `Call{to: <leftoverToken>, data: transfer(attacker, balance)}` (or, for native ETH, `Call{to: attacker, value: balance}`) and take that residual balance for themselves, at any point after it accrues and before some other legitimate flow happens to also reference and sweep that same token.

### Impact Explanation
Any ERC20 or native balance that accrues in the shared `CallDispatcher` outside of the tracked `order.inputs`/`order.output.assets` set (or from any other integration wired to the same dispatcher instance) is fully and permanently exposed to theft by an arbitrary, unprivileged third party — the funds are not merely at risk of protocol-level "dust" mis-accounting, they can be siphoned to any attacker's address in a single unauthenticated call. This directly causes loss of funds that would otherwise belong to users, solvers, or the protocol's dust-collection mechanism, satisfying the "concrete theft of funds" bar.

### Likelihood Explanation
`CallDispatcher.dispatch()` is reachable by any EOA with no gating — the only requirement for exploitation is that the dispatcher holds a nonzero balance of some token/ETH at the time of the attacker's call. This can occur through normal use of composable `predispatch`/`postdispatch` calldata (e.g. multi-hop swaps producing an unlisted intermediate token, fee-on-transfer quirks, or partial execution leaving unswept remainders), all of which the protocol's own documentation acknowledges as a "dust" concern it tries to sweep — but the sweep is scoped only to explicitly enumerated assets, not to arbitrary residuals. Given the dispatcher is a shared, long-lived, permanently deployed contract used by multiple apps, any residual left by one flow is a standing target for any observer monitoring the dispatcher's token balances.

### Recommendation
Restrict `CallDispatcher.dispatch()` to a set of trusted callers (e.g. `onlyOwner`/allowlisted app contracts such as `IntentGatewayV2` and the HFT contracts), or make the dispatcher per-call/per-order (deployed ephemerally or via a proxy pattern scoped to the caller) so that no unrelated party's residual balance is ever reachable by an unprivileged `dispatch()` call. Additionally, broaden sweep logic to capture the full token surface touched by `predispatch`/`postdispatch` calldata rather than only the explicitly enumerated input/output assets, so dust cannot silently accumulate in a permissionlessly-drainable shared contract.

### Proof of Concept
1. A user places an order via `IntentGatewayV2.placeOrder()` with `predispatch.call` performing a multi-hop swap (e.g., TokenA → TokenB → TokenC) where only TokenC is listed in `order.inputs`.
2. After `dispatch(order.predispatch.call)` executes and the gateway sweeps only the TokenC balance back (per `evm/src/apps/IntentGatewayV2.sol` lines 258-289), any leftover TokenB dust from the intermediate hop remains in the shared `CallDispatcher`.
3. Any unrelated attacker observes the dispatcher's TokenB balance and calls `CallDispatcher.dispatch(abi.encode([Call({to: TokenB, value: 0, data: abi.encodeWithSelector(IERC20.transfer.selector, attacker, balance)})]))` directly — this succeeds because `dispatch()` performs no caller check (`evm/src/utils/CallDispatcher.sol` lines 44-61) — transferring the dust to the attacker.

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }

    function _execute(Order calldata order, uint256 outputsLen) internal {
        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            } else {
                uint256 balance = IERC20(token).balanceOf(dispatcher);
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            }

            unchecked {
                ++i;
            }
        }

        if (sweepCount > 0) {
            Call[] memory finalCalls = new Call[](sweepCount);
            for (uint256 i; i < sweepCount;) {
                finalCalls[i] = sweepCalls[i];
                unchecked {
                    ++i;
                }
            }
            ICallDispatcher(dispatcher).dispatch(abi.encode(finalCalls));
        }
    }

            to: beneficiary,
            source: string(request.source),
