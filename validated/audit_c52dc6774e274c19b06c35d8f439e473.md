[1](#0-0) ### Title
Accrual arithmetic overflow permanently freezes high-utilization whale markets - (File: contracts/pool/src/cache/scale.rs)

### Summary
RAY-scaled market totals are converted back to value inside `Cache::calculate_utilization`, so an otherwise valid market whose `borrowed * borrow_index` exceeds `i128` panics during interest accrual. [1](#0-0) [2](#0-1) 

The checked-in stress test demonstrates that this happens before `MAX_BORROW_INDEX_RAY` engages, and that subsequent repay and withdraw calls fail with `MathOverflow`. [3](#0-2) [4](#0-3) 

### Finding Description
An unprivileged caller can reach the failing path through `supply`, `borrow`, and later `update_indexes`; `account_id = 0` lets the same caller create and control both the supplier and borrower accounts. [5](#0-4) 

`update_indexes(caller, assets)` only authenticates the caller and forwards the requested markets to the pool, making the trigger permissionless once the market state exists. [6](#0-5) [7](#0-6) 

The pool's `accrue` entry loads each market and calls `interest::global_sync`, while `global_sync` only calls `mark_accrued` after every chunk succeeds. [8](#0-7) [9](#0-8) 

Each chunk calls `accrue_step`, which needs current utilization, and `calculate_utilization` multiplies the stored RAY-scaled borrow and supply totals by their indexes through `scaled_to_original`. [10](#0-9) [1](#0-0) 

When that multiplication no longer fits `i128`, the transaction panics before `mark_accrued`, leaving `last_timestamp` stale and forcing the next accrual attempt to repeat the same overflowing conversion. [11](#0-10) 

The checked-in PoC constructs this state with one billion 18-decimal units supplied, 98% borrowed, and sufficient attacker-controlled collateral. [12](#0-11) 

The test's cap-lifting helper is privileged setup, so exploitability in a particular deployment depends on whether its listed supply/borrow caps permit a comparably large book. [13](#0-12) 

### Impact Explanation
Once the boundary is crossed, the market cannot accrue successfully, and ordinary exits or repayments that accrue first revert with `MathOverflow`. [14](#0-13) [15](#0-14) [16](#0-15) 

This permanently freezes supplier funds under the protocol's normal ABI and prevents borrowers or liquidators from resolving the debt through operations that require accrual. [3](#0-2) [17](#0-16) 

### Likelihood Explanation
Likelihood is constrained because the attack requires an extremely large listed market, enough collateral to borrow most of it, cap headroom, and sustained high utilization until the scaled borrow value crosses `i128::MAX`. [12](#0-11) 

The trigger itself is nevertheless unprivileged because any caller can submit `update_indexes` for the affected `(hub_id, asset)` market after that state exists. [6](#0-5) [7](#0-6) 

### Recommendation
Compute aggregate utilization and other `scaled * index` values in `I256`, or explicitly saturate utilization at its RAY maximum before converting the product back to `i128`. [1](#0-0) [18](#0-17) 

Enforce the borrow-index ceiling before index growth can make the stored borrow value unrepresentable, and commit that capped state rather than reverting inside the utilization calculation. [9](#0-8) [19](#0-18) 

Use widened or checked value math on repayment, withdrawal, liquidation, and risk paths as needed so a capped market remains exitable instead of trapping funds behind the same `i128` conversion. [20](#0-19) 

### Proof of Concept
The following sequence mirrors the checked-in stress PoC using two accounts controlled by the same unprivileged caller. [12](#0-11) 

```rust
let big = HubAssetKey {
    hub_id,
    asset: big_asset,
};
let col = HubAssetKey {
    hub_id,
    asset: collateral_asset,
};

let principal = 1_000_000_000i128 * 10i128.pow(18);
let debt = principal / 100 * 98;
let collateral = 1_000_000_000i128 * 10_000_000 * 3;

let supplier_id = controller.supply(
    &attacker,
    &0,
    &spoke_id,
    &vec![env, (big.clone(), principal)],
);

let borrower_id = controller.supply(
    &attacker,
    &0,
    &spoke_id,
    &vec![env, (col, collateral)],
);

controller.borrow(
    &attacker,
    &borrower_id,
    &vec![env, (big.clone(), debt)],
    &None,
);
```

After ledger time advances far enough that `borrowed * borrow_index` exceeds `i128::MAX`, `controller.update_indexes(&attacker, &vec![env, big.clone()])` fails with `MathOverflow`. [1](#0-0) [21](#0-20) 

At that point `withdraw(attacker, supplier_id, [(big, 1)], None)` and `repay(attacker, borrower_id, [(big, 1)])` fail with the same error because both paths accrue the market first. [22](#0-21)

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```
