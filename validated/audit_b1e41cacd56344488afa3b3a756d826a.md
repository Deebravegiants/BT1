### Title
Unchecked RAY debt-value multiplication can permanently freeze a saturated market - ([File: common/src/rates/index.rs](common/src/rates/index.rs))

### Summary

The pool computes accrued debt as `borrowed * new_borrow_index` without first bounding the resulting RAY value to `i128::MAX`. A sufficiently large borrowed share balance can therefore make `calculate_supplier_rewards` panic with `MathOverflow` before the configured borrow-index ceiling is reached. Because every mutating pool path synchronizes interest before applying the requested action, the first overflow permanently blocks withdrawals, repayments, borrows, liquidations, and further index updates for that market. [1](#0-0) [2](#0-1) 

### Finding Description

Each accrual step unscales the scaled borrow balance with `scaled_to_original`, calculates utilization and interest, updates the borrow index, and then calculates the supplier rewards by multiplying `borrowed` by both the old and new borrow indexes. [3](#0-2) 

`update_borrow_index` caps only the index itself at `MAX_BORROW_INDEX_RAY`; it does not cap or check the market value represented by `borrowed * index`. [4](#0-3)  `calculate_supplier_rewards` subsequently performs two checked `Ray::mul` operations on the unbounded market value and panics if either result exceeds `i128::MAX`. [1](#0-0) 

The index ceiling is therefore not an effective safety bound for large markets: the debt-value product can overflow while the index remains far below `MAX_BORROW_INDEX_RAY`. [5](#0-4)  All pool mutation legs call `synced_market`, and `synced_market` always runs `interest::global_sync` before the operation-specific logic. [2](#0-1)  `global_sync` delegates each compounding window to `accrue_step`, so the overflow is encountered before withdrawal, repayment, borrowing, liquidation, recapitalization, or explicit index synchronization can proceed. [6](#0-5) [7](#0-6) 

The dedicated repository regression test demonstrates this exact condition: a large high-decimal market reaches the RAY value ceiling before `MAX_BORROW_INDEX_RAY`, after which `update_indexes`, `withdraw`, and `repay` all revert with `MathOverflow`. [8](#0-7) 

### Impact Explanation

Once the market reaches the overflowing state, suppliers cannot withdraw their deposits and borrowers cannot repay through the normal pool paths because those calls accrue interest first. [9](#0-8)  Liquidation and other pool operations use the same synchronized loading mechanism, so unhealthy debt also cannot be resolved through the affected market. [2](#0-1) 

The stored `last_timestamp` and indexes are not advanced before the panic, so waiting does not move the market past the bad accrual window; subsequent transactions repeat the same multiplication and fail again. [10](#0-9)  The demonstrated result is permanent freezing of supplier funds and protocol debt operations unless an out-of-scope contract upgrade or privileged recovery path can bypass the accrual precondition. [11](#0-10) 

### Likelihood Explanation

The triggering state does not require privileged calls during exploitation: an unprivileged user can create large supply and borrow positions through controller `supply` and `borrow`, and anyone can later invoke `update_indexes` for the affected `HubAssetKey`. [12](#0-11)  The exploitability depends on an existing listed market permitting sufficient supply, debt, utilization, and collateral value; the attacker cannot create those market parameters independently. [13](#0-12) 

For a high-decimal asset with a very large cap, the overflow threshold is approximately `i128::MAX / scaled_borrowed`, which can be many orders of magnitude below the configured `MAX_BORROW_INDEX_RAY`. [1](#0-0) [5](#0-4)  Sustained high utilization increases the index through repeated chunked accrual until the next call crosses the checked-multiplication boundary. [14](#0-13) 

### Recommendation

Before computing `borrowed * new_borrow_index`, derive an effective index ceiling from `i128::MAX / borrowed` and clamp `new_borrow_index` to the lesser of that value and `MAX_BORROW_INDEX_RAY`. [1](#0-0)  Apply the same value-domain bound to supply-index calculations, or use checked/saturating intermediate arithmetic that keeps subsequent `Ray::mul` operations inside `i128`. [15](#0-14) 

The clamp must be monotonic and must never reduce an already-stored index; if the implied market-value ceiling is below the stored index, the protocol needs an explicit recovery mode that bounds or resets accounting safely rather than repeatedly panicking in accrual. [16](#0-15) 

### Proof of Concept

1. In an existing high-decimal market with sufficiently high caps and collateral backing, call controller `supply` for a very large `amount` of the target asset.
2. Supply collateral in another listed market and call controller `borrow` for enough of the target asset to keep utilization high.
3. Allow ledger time to advance, then call controller `update_indexes` with the target market's `HubAssetKey`.
4. The pool loads the market, runs `global_sync`, computes `new_total_debt = borrowed.mul(new_borrow_index)`, and panics with `MathOverflow` when the RAY debt value exceeds `i128::MAX`. [17](#0-16) [1](#0-0) 
5. Subsequent `withdraw`, `repay`, and `update_indexes` calls re-enter `global_sync` before their operation logic and fail on the same multiplication, leaving the market frozen. [2](#0-1) [11](#0-10)

```rust
/// Applies `interest_factor` to `old_index` to produce the new borrow index,
/// capped at `MAX_BORROW_INDEX_RAY`.
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}
```

```rust
pub fn update_supply_index(env: &Env, supplied: Ray, old_index: Ray, rewards_increase: Ray) -> Ray {
    if supplied == Ray::ZERO || rewards_increase == Ray::ZERO {
        return old_index;
    }

    let total_supplied_value = supplied.mul(env, old_index);

    if total_supplied_value == Ray::ZERO {
        return old_index;
    }

    let new_value = total_supplied_value.checked_add(env, rewards_increase);
    let grown = fp_core::mul_div_floor_saturating(env, new_value.raw(), RAY, supplied.raw());

    let bounded_old = old_index.raw().min(MAX_SUPPLY_INDEX_RAY);
    Ray::from(grown.min(MAX_SUPPLY_INDEX_RAY).max(bounded_old))
}
```

```rust
pub fn calculate_supplier_rewards(
    env: &Env,
    params: &MarketParams,
    borrowed: Ray,
    new_borrow_index: Ray,
    old_borrow_index: Ray,
) -> (Ray, Ray) {
    let old_total_debt = borrowed.mul(env, old_borrow_index);
    let new_total_debt = borrowed.mul(env, new_borrow_index);

    let accrued_interest = new_total_debt.checked_sub(env, old_total_debt);

    let protocol_fee = params.reserve_factor.apply_to_ray(env, accrued_interest);
    let supplier_rewards = accrued_interest.checked_sub(env, protocol_fee);

    (supplier_rewards, protocol_fee)
```

```rust
pub fn accrue_step(
    env: &Env,
    params: &MarketParams,
    borrowed: Ray,
    supplied: Ray,
    borrow_index: Ray,
    supply_index: Ray,
    delta_ms: u64,

    let supplied_original = scaled_to_original(env, supplied, supply_index);

        calculate_supplier_rewards(env, params, borrowed, new_borrow_index, borrow_index);

    let new_supply_index = update_supply_index(env, supplied, supply_index, supplier_rewards);
```

```rust
/// Accrues borrow/supply indexes from `last_timestamp` to the cache's current time.
///
/// No-op when no time has elapsed. Splits long gaps into max-sized compound
/// windows, then sets `last_timestamp` to `current_timestamp`.
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```

```rust
/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}
```

```rust
/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
