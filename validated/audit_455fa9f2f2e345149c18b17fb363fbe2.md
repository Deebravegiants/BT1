## Title
Missing slippage protection in `bonding_curve_launchpad::swap` allows value extraction from swappers - (File: aptos-move/move-examples/bonding_curve_launchpad/sources/bonding_curve_launchpad.move)

## Summary
`bonding_curve_launchpad`'s public swap entry point takes only an `amount_in` and has no `amount_out_min`/slippage parameter, unlike the underlying `swap::router` module in the same repo which explicitly supports `amount_out_min` for this exact purpose. Combined with reserve-dependent constant-product pricing computed at execution time, a user's expected APT/FA output can be silently reduced by any transaction that changes `LiquidityPair` reserves ahead of theirs, moving value from the swapper to whoever manipulates ordering, with no on-chain guard to prevent or bound the loss.

## Finding Description
The public entry point: [1](#0-0) 
takes `amount_in` only and forwards to `liquidity_pairs::swap_fa_to_apt` / `swap_apt_to_fa`, neither of which accept or check a minimum-output/expected-price parameter: [2](#0-1) [3](#0-2) 

The output amount is derived purely from the live `fa_reserves`/`apt_reserves` at execution time via the constant-product formula: [4](#0-3) 
There is only a "non-zero output" assertion (`ELIQUIDITY_PAIR_SWAP_AMOUNTOUT_INSIGNIFICANT`), which guards against a zero-value swap but does nothing to bound how much less than expected a swapper receives. Any other swap against the same `LiquidityPair` (submitted by any unprivileged account, or the same account performing multiple sequential swaps) shifts `fa_reserves`/`apt_reserves` before a pending transaction executes, changing the effective price. Since Aptos transaction ordering within a block is not guaranteed to match submission order and MEV-style reordering/back-running is possible, a swapper has no mechanism to cap their loss.

This is a direct architectural regression relative to the sibling module in the very same PR/example set: `swap::router::swap_entry` explicitly threads `amount_out_min` through to `swap` and aborts with `EINSUFFICIENT_OUTPUT_AMOUNT` if unmet: [5](#0-4) 
`bonding_curve_launchpad` reimplements a constant-product AMM but drops this protection entirely, despite it already existing as a pattern in the same repository the launchpad depends on (`use swap::router; use swap::liquidity_pool;`).

## Impact Explanation
Every swapper's `apt_gained`/`fa_gained` amount is corrupted (in the sense of "moves value to the wrong holder") relative to their expectation at submission time, with the difference captured by whoever reorders/front-runs the trade — no privileged action or admin key is required, and the underlying reserves (`liquidity_pair.fa_reserves`, `liquidity_pair.apt_reserves`, and the object-held `fa_store`/APT coin store) are custody-relevant object-held value that any unprivileged account can cause to be misallocated. Because reserves are relatively small before graduation (threshold: `APT_LIQUIDITY_THRESHOLD = 600_000_000_000` octas) and virtual liquidity is only `INITIAL_VIRTUAL_APT_LIQUIDITY = 50_000_000_000`, price impact per trade is large, amplifying the loss a victim can suffer from a single adversarial reordering.

## Likelihood Explanation
High: this requires no privileged role, no misconfiguration, and no race beyond normal transaction submission/ordering. Any account can observe a pending swap in the mempool (or simply submit competing swaps against the same popular pair) and extract value from a legitimate swapper purely by transacting first. The bug is exercised on the default/only public code path (`swap` entry function) and is deterministic given reserve state.

## Recommendation
Add a `min_amount_out` (or `max_amount_in` for exact-output semantics) parameter to `bonding_curve_launchpad::swap` and thread it through to `liquidity_pairs::swap_fa_to_apt`/`swap_apt_to_fa`, aborting if the computed `apt_gained`/`fa_gained` falls below the caller-supplied minimum — mirroring the existing `swap::router::swap_entry`/`EINSUFFICIENT_OUTPUT_AMOUNT` pattern already present in the repository.

## Proof of Concept
1. `create_fa_pair` is called, creating a `LiquidityPair` with `fa_reserves = fa_initial_liquidity`, `apt_reserves = INITIAL_VIRTUAL_APT_LIQUIDITY` (`liquidity_pairs.move:187-197`).
2. Victim submits `bonding_curve_launchpad::swap(victim, name, symbol, false, amount_in)` (APT→FA) expecting `fa_gained` computed against the current reserves via `get_amount_out` (`liquidity_pairs.move:283`).
3. Before the victim's transaction executes, an attacker submits and gets ordered first: `swap(attacker, name, symbol, false, large_amount_in)`, shifting `apt_reserves` upward and `fa_reserves` downward (`liquidity_pairs.move:300-304`).
4. The victim's transaction then executes against the new, worse reserve ratio; `get_amount_out` returns a materially smaller `fa_gained` than what the victim expected when submitting, with no abort possible since there is no minimum-output check — only `assert!(fa_gained > 0, ...)` at `liquidity_pairs.move:109`.
5. The attacker can then reverse their swap to capture the price differential, completing a sandwich against the victim's transaction, all executed by unprivileged accounts using only public entry functions.

Note: I was unable to fully verify runtime transaction-ordering/mempool guarantees specific to this deployment (that depends on Aptos's block-building/validator behavior rather than this Move code), so the exact magnitude of extractable value in production depends on network conditions; the code-level absence of any slippage guard, however, is confirmed directly in the cited source.

    #[view]
    public fun get_amount_out(
        fa_reserves: u128,
        apt_reserves: u128,
        swap_to_apt: bool,
        amount_in: u64
    ): (u64, u64, u128, u128) {
        if (swap_to_apt) {
            let divisor = fa_reserves + (amount_in as u128);
            let apt_gained = (math128::mul_div(apt_reserves, (amount_in as u128), divisor) as u64);
            let fa_updated_reserves = fa_reserves + (amount_in as u128);
            let apt_updated_reserves = apt_reserves - (apt_gained as u128);
            assert!(apt_gained > 0, ELIQUIDITY_PAIR_SWAP_AMOUNTOUT_INSIGNIFICANT);
            (amount_in, apt_gained, fa_updated_reserves, apt_updated_reserves)
        } else {
            let divisor = apt_reserves + (amount_in as u128);
            let fa_gained = (math128::mul_div(fa_reserves, (amount_in as u128), divisor) as u64);
            let fa_updated_reserves = fa_reserves - (fa_gained as u128);
            let apt_updated_reserves = apt_reserves + (amount_in as u128);
            assert!(fa_gained > 0, ELIQUIDITY_PAIR_SWAP_AMOUNTOUT_INSIGNIFICANT);
            (fa_gained, amount_in, fa_updated_reserves, apt_updated_reserves)
        }
    }

    /// Facilitate swapping between a given FA to APT.
    public(friend) fun swap_fa_to_apt(
        name: String,
        symbol: String,
        transfer_ref: &TransferRef,
        swapper_account: &signer,
        fa_object_metadata: Object<Metadata>,
        amount_in: u64
    ) acquires Pairs, LiquidityPair {
        // Verify the liquidity pair exists and is enabled for trading.
        assert_liquidity_pair_exists(name, symbol);
        let liquidity_pair = borrow_global_mut<LiquidityPair>(get_pair_obj_address(name, symbol));
        assert!(liquidity_pair.is_enabled, ELIQUIDITY_PAIR_DISABLED);
        // Determine the amount received of APT, when given swapper-supplied amount_in of FA.
        let (fa_given, apt_gained, fa_updated_reserves, apt_updated_reserves) = get_amount_out(
            liquidity_pair.fa_reserves,
            liquidity_pair.apt_reserves,
            true,
            amount_in
        );
        // Verify the swapper holds the FA.
        let swapper_address = signer::address_of(swapper_account);
        let does_primary_store_exist_for_swapper = primary_fungible_store::primary_store_exists(
            swapper_address,
            fa_object_metadata
        );
        assert!(does_primary_store_exist_for_swapper, EFA_PRIMARY_STORE_DOES_NOT_EXIST);
        // Perform the swap.
        // Swapper sends FA to the liquidity pair object. The liquidity pair object sends APT to the swapper, in return.
        let liquidity_pair_signer = object::generate_signer_for_extending(&liquidity_pair.extend_ref);
        let from_swapper_store = primary_fungible_store::ensure_primary_store_exists(
            swapper_address,
            fungible_asset::transfer_ref_metadata(transfer_ref)
        );
        fungible_asset::transfer_with_ref(transfer_ref, from_swapper_store, liquidity_pair.fa_store, fa_given);
        aptos_account::transfer(&liquidity_pair_signer, swapper_address, apt_gained);
        // Record state changes to the liquidity pair's reserves, and emit changes as events.
        let former_fa_reserves = liquidity_pair.fa_reserves;
        let former_apt_reserves = liquidity_pair.apt_reserves;
        liquidity_pair.fa_reserves = fa_updated_reserves;
        liquidity_pair.apt_reserves = apt_updated_reserves;
        event::emit(
            LiquidityPairReservesUpdated {
                former_fa_reserves,
                former_apt_reserves,
                new_fa_reserves: fa_updated_reserves,
                new_apt_reserves: apt_updated_reserves
            }
        );
        event::emit(
            LiquidityPairSwap {
                is_fa_else_apt: false,
                gained: (apt_gained as u128),
                swapper_address
            }
        );
    }

    /// Facilitate swapping between APT to a given FA.
    public(friend) fun swap_apt_to_fa(
        name: String,
        symbol: String,
        transfer_ref: &TransferRef,
        swapper_account: &signer,
        fa_object_metadata: Object<Metadata>,
        amount_in: u64
    ) acquires Pairs, LiquidityPair {
        // Verify the liquidity pair exists and is enabled for trading.
        assert_liquidity_pair_exists(name, symbol);
        let liquidity_pair = borrow_global_mut<LiquidityPair>(get_pair_obj_address(name, symbol));
        assert!(liquidity_pair.is_enabled, ELIQUIDITY_PAIR_DISABLED);
        // Determine the amount received of FA, when given swapper-supplied amount_in of APT.
        let (fa_gained, apt_given, fa_updated_reserves, apt_updated_reserves) = get_amount_out(
            liquidity_pair.fa_reserves,
            liquidity_pair.apt_reserves,
            false,
            amount_in
        );
        // Perform the swap.
        // Swapper sends APT to the liquidity pair object. The liquidity pair object sends FA to the swapper, in return.
        // Requires the liquidity pair object's address, which is retrieved using the stored extend_ref.
        let swapper_address = signer::address_of(swapper_account);
        let liquidity_pair_address = object::address_from_extend_ref(&liquidity_pair.extend_ref);
        let to_swapper_store = primary_fungible_store::ensure_primary_store_exists(
            swapper_address,
            fungible_asset::transfer_ref_metadata(transfer_ref)
        );
        aptos_account::transfer(swapper_account, liquidity_pair_address, apt_given);
        fungible_asset::transfer_with_ref(transfer_ref, liquidity_pair.fa_store, to_swapper_store, fa_gained);
        // Record state changes to the liquidity pair's reserves, and emit changes as events.
        let former_fa_reserves = liquidity_pair.fa_reserves;
        let former_apt_reserves = liquidity_pair.apt_reserves;
        liquidity_pair.fa_reserves = fa_updated_reserves;
        liquidity_pair.apt_reserves = apt_updated_reserves;
        event::emit(
            LiquidityPairReservesUpdated {
                former_fa_reserves,
                former_apt_reserves,
                new_fa_reserves: fa_updated_reserves,
                new_apt_reserves: apt_updated_reserves
            }
        );
        event::emit(
            LiquidityPairSwap {
                is_fa_else_apt: true,
                gained: (fa_gained as u128),
                swapper_address
            }
        );
        // Check for graduation requirements. The APT reserves must be above the pre-defined
        // threshold to allow for graduation.
        if (liquidity_pair.is_enabled && apt_updated_reserves > APT_LIQUIDITY_THRESHOLD) {
            graduate(liquidity_pair, fa_object_metadata, transfer_ref, apt_updated_reserves, fa_updated_reserves);
        }
    }

    /// Swap an amount of fungible assets for another fungible asset. User can specifies the minimum amount they
    /// expect to receive. If the actual amount received is less than the minimum amount, the transaction will fail.
    public entry fun swap_entry(
        user: &signer,
        amount_in: u64,
        amount_out_min: u64,
        from_token: Object<Metadata>,
        to_token: Object<Metadata>,
        is_stable: bool,
        recipient: address,
    ) {
        let in = primary_fungible_store::withdraw(user, from_token, amount_in);
        let out = swap(in, amount_out_min, to_token, is_stable);
        primary_fungible_store::deposit(recipient, out);
    }
