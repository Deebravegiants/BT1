This codebase has **no on-chain analog** to Vether4's `addExcluded()` fee-exemption mechanism — there is no per-address exclusion list, and the reachable curve-side entry points (`Router.buy`/`Router.sell`) are gated `onlyRole(BONDING_ROLE)` while `Bonding.buy`/`Bonding.sell` are gated by the `_routers` allowlist, so an unprivileged wallet cannot call into the curve to strip the fee the way the report's central-forwarder contract did on Vether. [1](#0-0) [2](#0-1) 

However, the same root-cause class — a fee that is enforced only by an optional wrapper layer rather than by the asset/pool itself — does reproduce in this codebase's post-graduation venue.

### Title
Post-graduation trades can bypass the 0.75% Alt Fun fee entirely by calling the HyperSwap V2 pair directly instead of routing through `Zap` - (File: `packages/contracts/src/Zap.sol`)

### Summary
`Zap` is the only place the 0.75% protocol/creator fee is charged; `Bonding`, `Router`, and `Pair` hold no fee logic, and post-graduation the trading venue is a standard, permissionless HyperSwap V2 `TOKEN/LT` pair with a public `swap()` function. [3](#0-2) [4](#0-3)  Because the graduated pair enforces no fee of its own (only its native 0.3% LP fee) and imposes no access control tying trades to `Zap`, any unprivileged trader can transfer the input token directly to the pair and call `swap()` themselves, completely avoiding the Alt Fun fee — exactly the "avoid the wrapper, hit the underlying mechanism directly" pattern described in the Vether4 report, just applied to alt.fun's post-graduation AMM instead of a transfer-fee token.

### Finding Description
Fees are charged exclusively inside `Zap._executeBuy` / `Zap._sellInternal`, which skim the fee before routing the net amount to either the internal bonding-curve `Router` or, post-graduation, directly to the pair via `pair.swap(...)`: [5](#0-4) [6](#0-5) 

`Bonding.buy`/`Bonding.sell` are the only gates that restrict callers to allowlisted `Zap`s, and `Router.buy`/`Router.sell` are gated to `BONDING_ROLE` — but neither of these applies once a token graduates, because post-graduation trading moves off the internal `Router`/`Pair` entirely and onto the external HyperSwap V2 `TOKEN/LT` pair created in `finalizeGraduation`. [7](#0-6)  That pair is a standard `IUniswapV2Pair` with a public, permissionless `swap(amount0Out, amount1Out, to, data)` function and no allowlist tying its use to `Zap`: [8](#0-7) 

`Zap._swapOnUniswapV2` itself demonstrates the exact call pattern any trader can replicate unassisted: transfer the input token to the pair, then call `pair.swap(...)` directly, reading the fee-aware quote from `getAmountOut`. [9](#0-8)  Nothing in `Token.sol` (a plain ERC20 with owner-only burn) or in the LT enforces the 0.75% fee at the token/pool level — it exists only as an optional pre-swap deduction inside `Zap`. A trader (or an MEV/arbitrage bot, or a one-time "fee-free router" contract deployed by anyone, echoing the "once-off cost, then everyone reuses it" element of the referenced report) can permanently route every post-graduation trade straight to the pair, paying only HyperSwap's native 0.3% LP fee and stripping the Alt Fun 0.75% fee out of every trade indefinitely.

### Impact Explanation
Every graduated token's trading volume can migrate to direct-pair swaps, permanently starving `FeeVault` of the 0.5% protocol / 0.25% creator fee on all post-graduation volume. [10](#0-9)  Since post-grad trading is explicitly designed to continue indefinitely on the graduated pool ("After graduation, all trades continue through `Zap` via HyperSwap"), this is a systemic, unbounded loss of the protocol's designed revenue stream and directly undermines the creator fee-attribution/claim mechanism in `FeeVault.claim()`/`claimProtocol()`, matching the "FeeVault insolvency"/indirect-loss-of-funds impact class validated by the rules.

### Likelihood Explanation
High. No special privilege, timing, or contract deployment beyond a trivial helper is required — any EOA or simple forwarding contract can call `IERC20.transfer` + `pair.swap` once a token graduates, and sophisticated actors (arbitrage bots, aggregators) are economically incentivized to always trade at the better (fee-free) price on the raw pair rather than through `Zap`.

### Recommendation
Enforce the fee at a layer the trader cannot bypass: either (a) make the graduated `TOKEN`/`LT` pair itself fee-charging so `Zap` and direct callers pay the same rate, or (b) restrict `swap()` sender-forwarding so only `Zap` (or another allowlisted router) can extract full-value swaps from the pair (e.g., a taxed/whitelisted pair implementation), rather than relying on `Zap` being the only "polite" path to the pool.

### Proof of Concept
1. Graduate a token via `Bonding.finalizeGraduation`, producing a standard HyperSwap V2 `TOKEN/LT` pair recorded in `bonding.graduatedPair(token)`. [11](#0-10) 
2. Instead of calling `Zap.sell(token, amount, minOut)`, the trader (or a one-time deployed forwarder contract) calls `IERC20(token).transfer(pairAddr, amount)` then `IUniswapV2Pair(pairAddr).swap(0, ltOut, trader, "")`, computing `ltOut` from `pair.getAmountOut(amount, token)` — the same call sequence `Zap._swapOnUniswapV2` itself performs. [9](#0-8) 
3. The trade settles at the pool's native 0.3% LP fee only; no USDC is ever transferred to `FeeVault`, and no `FeeAccrued` event fires, because `Zap._accrueFee` was never invoked. [12](#0-11) 
4. Repeating this for all post-graduation trading permanently zeroes out the 0.75% Alt Fun fee for that token.

## Fees & FeeVault

All fees are charged by `Zap` in USDC and forwarded into `FeeVault`. The router holds no fee state — the vault is where balances live and where creators and the protocol claim.

- **Rate:** 0.75% on every buy/sell (curve **and** post-grad), split 0.5% protocol / 0.25% creator.
- **Accrual:** `Zap` transfers the fee USDC to `FeeVault`, then calls `FeeVault.accrue(token, creator, creatorAmount, protocolAmount, isBuy)`. Creator attribution comes from `Bonding.tokenInfo(token).creator` (set at launch, updatable via `transferCreator`).
- **Claims:** `FeeVault.claim()` pays the caller their pooled USDC balance across every token they've launched. `FeeVault.claimProtocol()` is permissionless and pays the configured `feeTo` — anyone can trigger the payout, but funds always go to the admin-set address.
- **Lifetime counters:** `lifetimeCreatorEarned(creator)` / `lifetimeProtocolEarned` never decrement on claim, so the UI can render "total earned / claimed / claimable" consistently.
- **Router swapability:** The vault has an owner-controlled depositor allowlist. A new router is whitelisted, the old router removed, and creator balances are untouched during the transition.

    ///      `accrue`. The vault trusts allowlisted depositors to pass truthful
    ///      amounts (cross-checked against its USDC balance).
    function _accrueFee(
        address token,
        address creator,
        uint256 feeAmount,
        bool isBuy
    ) internal {
        ZapStorage storage $ = _s();
        uint256 creatorShare = (feeAmount * $.creatorFeeBps) / BPS_DENOM;
        uint256 protocolShare = feeAmount - creatorShare;
        $.usdc.safeTransfer(address($.feeVault), feeAmount);
        $.feeVault.accrue(token, creator, creatorShare, protocolShare, isBuy);
    }

    function finalizeGraduation(
        address tokenAddress
    ) external nonReentrant {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[tokenAddress];
        if (info.lifecycle != Lifecycle.Graduating) revert NotGraduating();

        address lt = info.ltAddress;
        PendingGraduation memory p = $.pendingGraduation[tokenAddress];

        // Anything in this contract beyond `p.ltFromPair` belongs to a
        // concurrent graduation on the same LT (Phase 1 transferred it
        // via `Router.graduate`) or to stray dust. Either way it is
        // off-limits to this graduation's deposit and sweep — see
        // `_routerDepositAndDispose` and `_sweepLTToOwner`.
        // Saturating subtract: a balance below `p.ltFromPair` shouldn't
        // be reachable in normal operation, but we keep finalize from
        // bricking on a Panic if any future code path or non-canonical
        // LT briefly violates the invariant.
        uint256 ltBalance = IERC20(lt).balanceOf(address(this));
        uint256 protectedLT = ltBalance > p.ltFromPair ? ltBalance - p.ltFromPair : 0;

        address lpPair = _ensureUniswapV2Pair(tokenAddress, lt);
        uint256 liquidity = _seedUniswapV2Direct(tokenAddress, lt, lpPair, p.tokensForLP, p.ltFromPair, protectedLT);

        _sweepLTToOwner(lt, protectedLT);

        info.lifecycle = Lifecycle.Graduated;
        $.graduatedPair[tokenAddress] = lpPair;
        delete $.pendingGraduation[tokenAddress];

        LPLock($.lpLock).recordLock(tokenAddress, lpPair, liquidity);

        emit TokenGraduated(tokenAddress, lpPair, liquidity, p.tokensForLP, p.lpBurned, p.unsoldBurned);
    }
