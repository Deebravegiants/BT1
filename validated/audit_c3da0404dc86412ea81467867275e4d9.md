### Title
Unauthenticated TCP livestream control channel allows attacker-chosen redirection of raw biometric video stream - ([File: src/agents/livestream/upstream.rs])

### Summary
`Upstream::new` binds a `TcpListener` on `0.0.0.0:9201` with no authentication, token, or allowlist check. Any TCP peer that connects triggers `Event::Connected(addr)`, which is handled in `Agent::run` by unconditionally constructing `Downstream::new(addr.ip())`, wiring a GStreamer pipeline that UDP-streams live camera frames (IR eye/face, RGB, thermal, depth) to that peer's IP on port 9200.

### Finding Description
`Upstream::new` (`src/agents/livestream/upstream.rs:36-39`) only binds the listener; it performs no credential check. `Upstream::poll_next` (`src/agents/livestream/upstream.rs:64-68`) accepts any incoming connection via `self.listener.poll_accept(cx)` and emits `Event::Connected(addr)` with the raw peer `SocketAddr` — no identity, token, or IP allowlist is consulted anywhere in this path.

In `src/agents/livestream/mod.rs:185-188`, the `Agent::run` loop handles `Event::Connected(addr)` by logging and immediately calling `Downstream::new(addr.ip())?`, replacing any existing downstream. `Downstream::new` (`src/agents/livestream/downstream.rs:18-45`) builds a GStreamer pipeline (`appsrc -> nvvidconv -> nvv4l2h264enc -> rtph264pay -> udpsink`) and sets the `udpsink` `host` property directly to `addr.to_string()` (the attacker's IP) and `port` to the hardcoded 9200 — with zero validation that this IP belongs to a backend-authorized destination. Once frames arrive from camera agents, `gpu.render(events, move |buffer| downstream.push(&buffer))` (`src/agents/livestream/mod.rs:199`) pushes every rendered frame (which includes live IR eye/face and RGB video composited by `gpu.app`) into that pipeline, streaming it via UDP to the attacker-controlled address.

No auth token, TLS, mTLS, or IP allowlist exists in `Upstream::new` or anywhere in the `Event::Connected` handling to gate this. Because `TcpListener::bind(format!("0.0.0.0:{PORT}"))` binds all interfaces, this is reachable by anyone with network reachability to the Orb — not gated behind operator/root access, keys, or MCU tampering.

### Impact Explanation
An unprivileged attacker who can reach TCP port 9201 on the Orb (e.g., same LAN/Wi-Fi segment, or any network path to the device) can open a bare TCP connection with no payload and no credentials. This causes the Orb to redirect its live raw biometric camera feed — IR eye, IR face, RGB, thermal/depth overlays as rendered by the livestream GPU compositor — via UDP/RTP to the attacker's own IP on port 9200, for as long as the connection stays open (and each new connecting client hijacks the stream by replacing `downstream`). This is a direct biometric data disclosure to an unauthorized, attacker-chosen destination, violating the invariant that raw/near-raw imagery should only flow to backend-authorized sinks. Whoever is being scanned at that moment (unaware of this) has their live face/eye video exfiltrated.

### Likelihood Explanation
Feasibility is high and fully repeatable: the listener requires only a bare TCP connect (`connect->Event::Connected(addr)->Downstream::new`), with no handshake, no payload, and no state that resets or blocks repeat/concurrent connections from arbitrary sources. The only precondition is: (1) the `livestream` cargo feature is compiled in (`#[cfg(feature = "livestream")]` in `src/agents/mod.rs:16`), and (2) network reachability to port 9201, which for a deployed Orb depends on its network exposure (e.g., local Wi-Fi/LAN, VPN, or any routable network) — this is outside the scope of code fixable within this file but the code itself provides zero application-layer defense once reachable.

### Recommendation
Add authentication/authorization to the livestream control channel before honoring `Event::Connected`: e.g., require a signed/backend-issued session token exchanged over TLS (mTLS) before accepting the connection, verify the peer against a backend-authorized allowlist/pinned destination rather than trusting the raw TCP source `SocketAddr`, and bind the listener to a restricted interface (e.g., loopback/VPN-only) rather than `0.0.0.0`. At minimum, do not derive the `udpsink` destination directly from an unauthenticated TCP peer address in `Downstream::new`.

### Proof of Concept
Integration test in `src/agents/livestream/upstream.rs`:
1. Call `Upstream::new().await` to bind the listener on port 9201.
2. From a separate, unrelated `TcpStream::connect` (simulating an attacker with no credentials), connect to `127.0.0.1:9201`.
3. Poll `Upstream` as a `Stream` and assert it yields `Event::Connected(addr)` where `addr` equals the attacker socket's local address, with no prior authentication call, token exchange, or allowlist check having occurred.
4. Extend to `Agent::run`-level test: assert that after this `Event::Connected`, a `Downstream` is constructed (i.e., `downstream.is_some()`) and that GStreamer's `udpsink` `host` property equals the attacker's IP (verifiable via `pipeline.by_name` lookup and `get_property("host")` on the `udpsink` element), confirming frames are subsequently routed to the attacker-chosen destination.
