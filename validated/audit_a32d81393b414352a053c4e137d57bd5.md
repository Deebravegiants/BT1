### Title
`Oauth.begin_auth` and `Oauth.validate_auth_callback` use the caller-supplied `shop` domain without `ShopValidator` sanitization, unlike every other credential-issuing flow in the gem - (File: `lib/shopify_api/auth/oauth.rb`)

### Summary
`ShopifyAPI::Auth::ClientCredentials.client_credentials`, `ShopifyAPI::Auth::RefreshToken.refresh_access_token`, and `ShopifyAPI::Auth::TokenExchange.migrate_to_expiring_token` all call `Utils::ShopValidator.sanitize!(shop)` before using the `shop` value to build the host that receives `client_id`/`client_secret`. [1](#0-0) [2](#0-1) [3](#0-2) 

`ShopifyAPI::Auth::Oauth.begin_auth` and `ShopifyAPI::Auth::Oauth.validate_auth_callback`, however, never call `ShopValidator` on the `shop` value they receive — `begin_auth` builds the authorize-redirect host directly from the caller-supplied `shop` argument via `auth_base_uri(shop)`, and `validate_auth_callback` builds the access-token POST host directly from `auth_query.shop`. [4](#0-3) [5](#0-4) [6](#0-5) 

### Finding Description
The binding that should hold is: `shop == a value matching TRUSTED_SHOPIFY_DOMAINS`. Every other code path that turns a caller/session-supplied `shop` string into a network host for a Shopify OAuth token request enforces this via `Utils::ShopValidator.sanitize!`, which restricts the host to `myshopify.com`, `myshopify.io`, `shopify.com`, `spin.dev`, or `shop.dev` and raises `Errors::InvalidShopError` otherwise. [7](#0-6) [8](#0-7) 

In `Oauth.begin_auth`, the `shop` parameter (which in real-world integrations is typically sourced directly from a query parameter or header on the app's login route, e.g. the docs example `shop = request.headers["Shop"]`) is passed straight into `auth_base_uri(shop)`, producing `auth_route = "https://#{shop}/admin/oauth/authorize?..."` with no domain check. [9](#0-8) [10](#0-9) 

`Oauth.validate_auth_callback` is only slightly better protected: it verifies the HMAC over the query string via `Utils::HmacValidator.validate(auth_query)`, whose signable string includes the `shop` field. [11](#0-10) [12](#0-11) 

But after that check, `auth_query.shop` is used unmodified — never passed to `ShopValidator.sanitize!` — to build `null_session = Auth::Session.new(shop: auth_query.shop)`, and that session is fed into `Clients::HttpClient.new(session: null_session, base_path: "/admin/oauth")`, which then POSTs a body containing `client_id` and `client_secret` to a host derived from `auth_query.shop`. [13](#0-12) 

### Impact Explanation
`begin_auth` never handles secrets, so its unsanitized `shop` only enables forced-OAuth-completion / redirect abuse: an app that forwards an unvalidated `shop` (as the documentation's own example pattern encourages) into `begin_auth` will redirect the merchant's browser to `https://<attacker-controlled-host>/admin/oauth/authorize?client_id=...`, which is the "forced OAuth completion" class explicitly listed as an in-scope High impact.

`validate_auth_callback`'s use of unsanitized `auth_query.shop` to select the host that receives `client_id`/`client_secret` is comparable to the reported bug's root cause — a value that is checked for one purpose (matching the HMAC-signed payload) is trusted for a different purpose (choosing the credential-receiving host) without confirming it also satisfies the narrower “trusted Shopify domain” invariant that `ShopValidator` exists to enforce elsewhere in the same module family. In practice, exploiting this specific path requires Shopify's own OAuth server to have generated a valid HMAC over that `shop` value, so, unlike `begin_auth`, it is not trivially reachable by an unauthenticated internet attacker without also controlling or intercepting a legitimate Shopify-issued callback — this materially weakens confidence that it's independently exploitable, and I could not verify a path that lets an attacker forge a valid `hmac`/`shop` pair without the `api_secret_key`.

### Likelihood Explanation
`begin_auth` is High likelihood: the parameter is explicitly documented to be sourced from user-controllable input (`request.headers["Shop"]`) and the method performs no validation before using it to build a redirect URL, unlike the parallel `client_credentials`, `refresh_token`, and `migrate_to_expiring_token` flows.

`validate_auth_callback`'s exposure is lower likelihood since it depends on `Utils::HmacValidator.validate` passing, which requires a signature produced with `Context.api_secret_key`; I was unable to find a code path where that check is bypassable by an unprivileged caller.

### Recommendation
Apply `Utils::ShopValidator.sanitize!` (or `sanitize_shop_domain`) to the `shop` value in `Oauth.begin_auth` before constructing `auth_base_uri(shop)`, and to `auth_query.shop` in `Oauth.validate_auth_callback` before constructing `null_session` and issuing the access-token request, matching the pattern already used in `ClientCredentials.client_credentials`, `RefreshToken.refresh_access_token`, and `TokenExchange.migrate_to_expiring_token`.

### Proof of Concept
```ruby

        def begin_auth(shop:, redirect_path:, is_online: true, scope_override: nil)
          scope = if scope_override.nil?
            ShopifyAPI::Context.scope
          elsif scope_override.is_a?(ShopifyAPI::Auth::AuthScopes)
            scope_override
          else
            ShopifyAPI::Auth::AuthScopes.new(scope_override)
          end

          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = SecureRandom.alphanumeric(NONCE_LENGTH)

          cookie = SessionCookie.new(value: state, expires: Time.now + 60)

          query = {
            client_id: ShopifyAPI::Context.api_key,
            scope: scope.to_s,
            redirect_uri: "#{ShopifyAPI::Context.host}#{redirect_path}",
            state: state,
            "grant_options[]": is_online ? "per-user" : "",
          }

          query_string = URI.encode_www_form(query)
          auth_route = auth_base_uri(shop) + "/oauth/authorize?#{query_string}"

          { auth_route: auth_route, cookie: cookie }
        end
```

```ruby
        def validate_auth_callback(cookies:, auth_query:)
          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::InvalidOauthError, "Invalid OAuth callback." unless Utils::HmacValidator.validate(auth_query)
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = cookies[SessionCookie::SESSION_COOKIE_NAME]
          raise Errors::NoSessionCookieError unless state

          raise Errors::InvalidOauthError,
            "Invalid state in OAuth callback." unless state == auth_query.state

          null_session = Auth::Session.new(shop: auth_query.shop)
          body = {
            client_id: Context.api_key,
            client_secret: Context.api_secret_key,
            code: auth_query.code,
            expiring: Context.expiring_offline_access_tokens ? 1 : 0, # Only applicable for offline tokens
          }

          client = Clients::HttpClient.new(session: null_session, base_path: "/admin/oauth")
          response = begin
            client.request(
              Clients::HttpRequest.new(
                http_method: :post,
                path: "access_token",
                body: body,
                body_type: "application/json",
              ),
            )
          rescue ShopifyAPI::Errors::HttpResponseError => e
            raise Errors::RequestAccessTokenError,
              "Cannot complete OAuth process. Received a #{e.code} error while requesting access token."
          end

          session_params = T.cast(response.body, T::Hash[String, T.untyped]).to_h
          session = Session.from(shop: auth_query.shop,
            access_token_response: Oauth::AccessTokenResponse.from_hash(session_params))
```

```ruby
        def auth_base_uri(shop)
          return "https://#{shop}/admin" unless defined?(DevServer) && shop.include?(".my.shop.dev")

          # For first-party apps in development only, we leverage DevServer to build the admin base URI
          admin_web = T.unsafe(Object.const_get("DevServer")) # rubocop:disable Sorbet/ConstantsFromStrings
            .new("admin-web")
          admin_host = admin_web.host!(nonstandard_host_prefix: "admin")
          shop_name = shop.split(".").first

          "https://#{admin_host}/store/#{shop_name}"
        end
```
