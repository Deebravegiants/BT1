Confirmed: `Message.from` is declared as Solidity `bytes` (dynamic length), so `message.from.as_ref()` in `on_accept` can be any length the source-chain sender encodes — it is fully attacker-controlled, cross-chain-relayed, untrusted input.

### Title
Panic-inducing out-of-bounds slice/copy on attacker-controlled `Message.from` length in `hyper-fungible-token::on_accept` - (File: `modules/pallets/hyper-fungible-token/src/module.rs`)

### Summary
`HyperFungibleToken::on_accept` decodes an ABI-encoded `Message { bytes from; bytes to; uint256 amount; bytes data; }` from an inbound ISMP `PostRequest` body and, when optional calldata is present without a signature, derives the dispatch origin from `message.from` without validating its length before slicing/copying it into a fixed-size buffer.

### Finding Description
In `on_accept` [1](#0-0) :
```rust
let from_bytes = message.from.as_ref();
if source.is_evm() {
    T::EvmToSubstrate::convert(H160::from_slice(&from_bytes[from_bytes.len() - 20..]))
} else {
    let mut account = [0u8; 32];
    account.copy_from_slice(from_bytes);
    account.into()
}
```
`message.from` is declared `bytes from` (a dynamic-length Solidity ABI type) in the pallet's `Message` struct [2](#0-1) , so its length is entirely controlled by whoever constructs the source-chain message body (or by any relayer forging a `PostRequest` for a registered source contract). Two panics are reachable:
- `from_bytes.len() - 20` underflows/panics when `source.is_evm()` and `from_bytes.len() < 20`.
- `account.copy_from_slice(from_bytes)` panics (`copy_from_slice` requires exact length equality) when `source` is non-EVM and `from_bytes.len() != 32`.

This mirrors the CVE-2018-17407 bug class: an untrusted, attacker-supplied length/field is consumed into a fixed-size buffer operation without a length check first, causing a crash. The same pallet already demonstrates awareness of this exact class of bug and defends against it correctly in the sibling `on_timeout` handler [3](#0-2) , and in `on_accept`'s handling of `message.to` [4](#0-3)  — both explicitly check `.len() == 32` / `== 20` and return a typed `Err` otherwise. The `from_bytes` branch at line 176-186 is the one path that was missed.

### Impact Explanation
A panic inside `on_accept`, which runs during dispatch of `pallet_ismp::Call::handle_unsigned` / message execution triggered by relaying an inbound `PostRequest`, can abort execution of that transaction/block-processing path for any node executing it. Since ISMP message delivery for this module is triggered by any relayer delivering a proven request from a registered source contract, and the crashing field is fully attacker-chosen, this is a reachable "route unable to deliver messages" / node-crashing DoS: a single malicious `PostRequest` with calldata and no signature, and a malformed `from` length, halts processing of that request (and, depending on the runtime's panic handling in Wasm execution, can render the runtime unable to import/execute the block containing it).

### Likelihood Explanation
High. No privilege or special role is required — only that the module is registered for a source contract via `ContractToAsset` (i.e., feature has to be actively used, but any user who can get any assets bridged in). The attacker fully controls `message.from`'s byte length via ABI encoding on the source chain, and the vulnerable branch is reached whenever `message.data` is non-empty and `SubstrateCalldata.signature` is `None`, both attacker-controlled fields.

### Recommendation
Add the same explicit length validation used elsewhere in the pallet before slicing/copying `from_bytes` in the unsigned-origin branch: reject (return `HftError::InvalidSenderLength`/similar typed error) any length other than 20 (EVM) or 32 (non-EVM), instead of indexing/`copy_from_slice`-ing directly. This should follow the exact pattern already implemented in `on_timeout` [3](#0-2) .

### Proof of Concept
1. Register a source EVM contract for a given asset via `ContractToAsset`.
2. Construct a `PostRequest` whose `body` ABI-encodes a `Message` with:
   - `from`: any byte string of length `!= 20` (e.g., empty, or 5 bytes) since `source.is_evm()` is true, or length `!= 32` for a non-EVM source.
   - `data`: non-empty, ABI-decodable as `SubstrateCalldata { signature: None, runtime_call: <any valid encoded call> }`.
3. Relay/deliver this proven request to `pallet_ismp`, causing `on_accept` to execute.
4. Execution reaches `from_bytes[from_bytes.len() - 20..]` (underflow panic) or `account.copy_from_slice(from_bytes)` (length-mismatch panic), aborting the runtime call.
