### Title
Dust-gate straddle: third-party collateral top-up blocks permissionless bad-debt cleanup - (File: contracts/controller/src/positions/liquidation/curve.rs)

### Summary
The permissionless `clean_bad_debt` entrypoint only admits an account when its half-up collateral is at or below the fixed `$5` `BAD_DEBT_USD_THRESHOLD`. Because `supply` lets any caller add to an existing supply position on someone else's account, an unprivileged address can push a straddling insolvent account's collateral just above the threshold and indefinitely deny the permissionless socialization path — the direct analog of sacrificing one agent to push the count to the healing-disabled threshold.

### Finding Description
`process_clean_bad_debt` → `clean_bad_debt_standalone` → `socialize_bad_debt(env, account_id, BadDebtGate::DustCapped)` admits cleanup only via `is_socializable_bad_debt(total_debt, total_collateral)`, which requires `total_debt > total_collateral && total_collateral <= Wad::from(BAD_DEBT_USD_THRESHOLD)` (`5 * WAD`). A collateral value of `BAD_DEBT_USD_THRESHOLD + 1` shuts the gate while the account stays insolvent.

The reachable lever is `supply(caller, account_id, spoke_id, assets)`. `require_third_party_existing_supply` permits a non-owner/non-delegate caller to top up any supply position that already exists on the target account. For a badly collateralized account that already holds a supply position (the typical insolvent account shape), depositing enough of that same asset to lift `total_collateral` above `$5` makes every subsequent `clean_bad_debt` revert with `CannotCleanBadDebt` (`#114`). The Certora spec `bad_debt_straddle_blocks_dust_gate` proves the straddle symbolically, and `bad_debt_straddle_admitted_by_force_gate` shows the straddled state is only reachable again through the owner-gated, timelocked `force_socialize_bad_debt` (Sensitive delay tier per the runbook).

### Impact Explanation
While the straddle holds, the permissionless cleanup path is unusable: bad debt keeps accruing interest against the market instead of being socialized, and cleanup can only proceed through the slow governance-authorized `force_socialize_bad_debt` flow — a temporary denial of the protocol's bad-debt settlement function that delays loss realization and extends supplier exposure to a deteriorating book. If the attacker is the debtor, they additionally keep their account/NFT alive and prevent the collateral-to-revenue reclassification that cleanup would trigger.

### Likelihood Explanation
Requires an insolvent account whose `total_collateral` sits near (within a cheap top-up of) `$5`, and that the account already holds a supply position in a top-up-able asset. Cost is bounded: the attacker must donate enough collateral value to exceed `$5`, and any liquidation that drags collateral back below the threshold re-opens the gate, forcing repeat donations. Like the source finding, this is a strategic sacrifice — profitability is situational — so Medium at best.

### Recommendation
- Consider a small buffer/hysteresis on the dust gate, or admit cleanup when the excess over the threshold is traceable to recent third-party top-ups.
- Alternatively, restrict `supply` to owner/delegate on accounts that satisfy `total_debt > total_collateral`, or net the top-up window by letting cleanup ignore collateral added after insolvency was first observable.

### Proof of Concept
1. Alice supplies collateral and borrows; a price crash leaves `debt > collateral` with `collateral = $4.50` (≤ `$5` gate — `clean_bad_debt` is open).
2. Mallory calls `supply` with Alice's `account_id`, depositing into Alice's existing collateral position, raising `total_collateral` to `$5.01`.
3. `clean_bad_debt(caller, alice_id)` now reverts with `CannotCleanBadDebt` since `is_socializable_bad_debt` fails the dust cap, while `debt > collateral` still holds.
4. The account can only be removed via owner-gated `force_socialize_bad_debt` after its governance delay, or after liquidations push collateral back below `$5` — which Mallory can counter with further top-ups as long as she funds them.
