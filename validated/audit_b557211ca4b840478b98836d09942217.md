## Finding: `feeToken` migration in `EvmHost.updateHostParamsInternal` can be DOS'd by depositing 1 wei of the old fee token

### Title
Governance fee-token migration in `EvmHost.updateHostParamsInternal` can be permanently DoS'd by donating 1 wei of the old fee token - (File: `evm/src/core/EvmHost.sol`)

### Summary
`EvmHost.updateHostParamsInternal` requires the old `feeToken` balance held by the host to be exactly `0` before allowing the fee token to be changed. Any unprivileged account can transfer 1 wei of the current fee token to the host contract at any time, causing every future `SetHostParam` governance request that changes `feeToken` to revert with `CannotChangeFeeToken`.

### Finding Description
`updateHostParamsInternal` is the internal function that applies new `HostParams`, invoked by `updateHostParams`, which is restricted to `_hostParams.hostManager` — the contract that relays cross-chain governance requests from Hyperbridge: [1](#0-0) 

Before applying the new params it enforces: [2](#0-1) 

```solidity
address oldFeeToken = feeToken();
if (oldFeeToken != address(0) && oldFeeToken != params.feeToken) {
    uint256 balance = IERC20(oldFeeToken).balanceOf(address(this));
    if (balance != 0) revert CannotChangeFeeToken();
}
```

`feeToken` is an ordinary ERC20 token; nothing prevents any address from calling `IERC20(feeToken).transfer(address(host), 1)` directly, independent of any Hyperbridge/ISMP flow. The comment/test confirm this intended check is meant to force "sweeping" the old token before switching: [3](#0-2) 

Because the balance check is a strict `== 0` (via `!= 0` revert condition), a single wei sent by any outside party guarantees the check fails. The governance-issued `SetHostParam` request that changes `feeToken` is delivered through `HostManager.onAccept` → `EvmHost.updateHostParams`, so an attacker only needs to watch the mempool/relayed message queue (or simply keep re-donating 1 wei perpetually) to make every attempt revert.

### Impact Explanation
This blocks Hyperbridge's cross-chain governance from ever migrating the `feeToken` parameter on the affected `EvmHost`, since the attacker can re-donate 1 wei after every sweep attempt at negligible cost. This is a permanent denial of a privileged/governance action (`updateHostParams` fee-token migration path) analogous to the `setCollateral` DoS in the source report: the check is a strict-equality balance gate on a token whose balance any unprivileged party can trivially manipulate via a plain ERC20 transfer.

### Likelihood Explanation
High — the attack requires only 1 wei of the current fee token (attacker can acquire this from normal protocol usage, e.g., paying fees) and a standard `transfer` call to the host address. There is no privilege requirement, and the cost of repeating the griefing indefinitely is essentially zero (1 wei each time).

### Recommendation
Do not gate the fee-token swap on an exact-zero balance of the old token. Options:
- Sweep any residual balance of `oldFeeToken` to a beneficiary/`hostManager` as part of `updateHostParamsInternal` instead of reverting.
- Allow the balance check to be satisfied by sweeping in the same transaction (pull remaining balance to `params.admin`/`hostManager`) rather than requiring the caller to have already emptied it out-of-band.

### Proof of Concept
1. `EvmHost` is configured with `feeToken = TokenA`, and Hyperbridge governance later dispatches a `SetHostParam` request via `HostManager` to change `feeToken` to `TokenB`.
2. Before the request is delivered (or after every failed attempt), any attacker calls `TokenA.transfer(address(evmHost), 1)`.
3. When the `HostManager` delivers the `SetHostParam` request, `EvmHost.updateHostParams` → `updateHostParamsInternal` computes `balance = IERC20(TokenA).balanceOf(address(this)) == 1`, and reverts with `CannotChangeFeeToken` (as demonstrated by `testSweepFeeTokenBeforeUpdate` in [3](#0-2)  where minting 1 token unit reproduces the exact same revert).
4. The attacker repeats step 2 after each retry, permanently preventing the fee token migration.

```text
    function testSweepFeeTokenBeforeUpdate() public {
        feeToken.mint(address(host), 1 * 1e18);
        HostParams memory params = host.hostParams();
        params.feeToken = address(this);
        // we can't set host params
        vm.prank(host.hostParams().admin);
        vm.expectRevert(EvmHost.CannotChangeFeeToken.selector);
        host.updateHostParams(params);

        feeToken.burn(address(host), 1 * 1e18);
        // we can set host params
        vm.prank(host.hostParams().admin);
        host.updateHostParams(params);
        assert(host.hostParams().feeToken == address(this));
    }
```
