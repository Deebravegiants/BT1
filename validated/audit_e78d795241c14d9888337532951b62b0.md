### Title
Unvalidated `shop` parameter in `Oauth.begin_auth` allows forced OAuth authorization against an attacker-controlled host - (File: lib/shopify_api/auth/oauth.rb)

### Summary
`ShopifyAPI::Auth::Oauth.begin_auth` builds the OAuth "authorize" redirect URL directly from the caller-supplied `shop` value without validating that it is a genuine `*.myshopify.com` (or otherwise trusted Shopify) domain, even though the library has just introduced `ShopifyAPI::Utils::ShopValidator` for exactly this purpose and already wires it into every *other* credential-bearing OAuth entry point.

### Finding Description
`begin_auth` takes a `shop:` string and, without any sanitization, passes it to `auth_base_uri(shop)`: [1](#0-0) [2](#0-1) 

`auth_base_uri` simply interpolates the untrusted `shop` string into `"https://#{shop}/admin"`, and `begin_auth` appends `client_id`, `scope`, `redirect_uri`, and a freshly generated `state` nonce to that host and returns it as `auth_route` for the app to redirect the merchant's browser to: [3](#0-2) 

By contrast, in the same file's `validate_auth_callback`, the `shop` used is `auth_query.shop`, which is cryptographically bound by an HMAC computed over `code, host, shop, state, timestamp` and checked via `Utils::HmacValidator.validate`: [4](#0-3) [5](#0-4) 

The library's changelog documents that `ShopifyAPI::Utils::ShopValidator#sanitize!` was added specifically to constrain shop domains to `TRUSTED_SHOPIFY_DOMAINS` (`shopify.com`, `myshopify.io`, `myshopify.com`, `spin.dev`, `shop.dev`) before it is used as a network host: [6](#0-5) [7](#0-6) 

That sanitizer is invoked before the `shop` string is used to build a request host in every other flow that reaches a network call: `ClientCredentials.client_credentials`, `TokenExchange.migrate_to_expiring_token`, and (per `grep_search`) `refresh_token.rb` and `clients/graphql/storefront.rb`: [8](#0-7) [9](#0-8) 

`begin_auth` is the one exception: the equality that should hold — "the host validated equals the host that receives the app's `client_id`/`redirect_uri`/`state`" — is broken, because no validation occurs at all before the host is used to build the redirect target.

### Impact Explanation
If a host application (following the library's own documented pattern of taking `shop` straight from a request parameter, e.g. `shop = request.headers["Shop"]` as shown in `docs/usage/oauth.md`) passes an attacker-supplied `shop` value into `begin_auth`, the merchant's browser is redirected to `https://<attacker-host>/admin/oauth/authorize?client_id=...&scope=...&redirect_uri=...&state=<nonce>`. This leaks the app's `client_id`, requested `scope`, `redirect_uri`, and the CSRF `state` value to an attacker-controlled server and enables a forced-OAuth / session-fixation attack: the attacker can complete the OAuth authorize step on the real Shopify endpoint using their own shop while controlling the `state`/cookie value the victim's browser will present at the callback, allowing them to bind the victim's app session/installation to a shop of the attacker's choosing. This matches the "session fixation or forced OAuth completion" High-impact category.

### Likelihood Explanation
Exploitability depends entirely on the host application; per the gem's own documented example (`docs/usage/oauth.md`), `shop` is commonly taken directly from an unauthenticated request header/parameter and passed to `begin_auth`. Because the library ships `ShopValidator` specifically to close this class of issue and applies it everywhere else, an app author relying on the library's guidance without separately validating `shop` remains exposed at this one call site.

### Recommendation
Call `ShopifyAPI::Utils::ShopValidator.sanitize!(shop)` (or an equivalent strict `myshopify.com` domain check) inside `Oauth.begin_auth` before constructing `auth_base_uri`, mirroring the fix already applied in `ClientCredentials.client_credentials` and `TokenExchange.migrate_to_expiring_token`.

### Proof of Concept
```ruby
ShopifyAPI::Context.setup(api_key: "APP_KEY", api_secret_key: "APP_SECRET", ...)

# Attacker controls the "shop" query/header value passed by the host app
result = ShopifyAPI::Auth::Oauth.begin_auth(
  shop: "attacker-controlled.example.com",
  redirect_path: "/auth/callback"
)

result[:auth_route]
# => "https://attacker-controlled.example.com/admin/oauth/authorize?client_id=APP_KEY&scope=...&redirect_uri=https://myapp.com/auth/callback&state=<nonce>&grant_options%5B%5D=per-user"
```
The victim's browser is redirected to the attacker's host carrying the app's `client_id`, requested `scope`, real `redirect_uri`, and the CSRF `state` nonce — none of which are protected because `shop` was never validated against `ShopifyAPI::Utils::ShopValidator::TRUSTED_SHOPIFY_DOMAINS`.

          received_signature = verifiable_query.hmac

    module ShopValidator
      TRUSTED_SHOPIFY_DOMAINS = T.let(
        [
          "shopify.com",
          "myshopify.io",
          "myshopify.com",
          "spin.dev",
          "shop.dev",
        ].freeze,
        T::Array[String],
      )

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
