### Title
Iris-code signature does not bind `signup_reason`, allowing a fraud/failure signup to be misattributed as normal - ([File: src/plans/enroll_user.rs])

### Summary
The secure-element signature computed for a signup only covers the orb ID, user ID, and iris-code data, but never includes the `SignupReason` (`Normal`/`Failure`/`Fraud`) that is sent alongside it in the same backend request. This mirrors the reported Atlas issue: a hash/signature is computed over only part of the relevant state (control address ≈ biometric data), while the value that actually determines trust/behavior (`CallConfig` ≈ `signup_reason`) is left out of the signed material, so it can be changed after the fact without invalidating the signature.

### Finding Description
`make_signature` in `src/plans/enroll_user.rs` builds the SHA-256 digest that is signed by the Secure Element: [1](#0-0) 

The digest is computed over `ORB_ID`, `user_qr_code.user_id`, and the iris/mask codes plus their versions — it never includes `signup_reason`. The resulting `signature` is then sent to the backend in `signup_post::request` as a separate, independently-controlled form field from `reason`: [2](#0-1) 

`SignupReason` itself is defined as a plain, unsigned enum controlling whether a signup is treated as `Normal`, `Failure`, or `Fraud` by the backend: [3](#0-2) 

Because the cryptographic signature only attests to "these iris codes came from this orb for this user," and not to "this signup was flagged as Fraud/Failure/Normal," the `reason` value can be altered in transit or by any component between biometric-pipeline decision-making and the HTTP request construction without breaking signature verification on the backend. This is directly analogous to the Atlas report's root cause: the signed struct omits a security-relevant configuration value (`CallConfig` there, `SignupReason` here), so the same valid signature remains usable under a different, unintended trust context.

### Impact Explanation
If the `reason` field can be desynchronized from the signed iris-code payload (e.g., due to a bug in the retry/poll logic in `Plan::run`, or a compromised/buggy intermediate stage that resubmits a request with a different `reason` while reusing the same previously computed `signature`), the backend has no cryptographic way to detect that mismatch. A signup that the orb-core biometric pipeline internally determined was fraudulent (`SignupReason::Fraud`) could be submitted as `Normal`, or vice versa, since the signature does not bind the two together. This is a concrete fraud/liveness-enforcement bypass: the backend's decision to enroll (or reject) an identity commitment partly depends on `reason`, and that field is unauthenticated relative to the biometric proof.

### Likelihood Explanation
The `signature` and `reason` fields are computed and populated independently in `Plan::run` / `make_signature` / `signup_post::request` with no cross-check enforced before the network call. Any logic error, retry-path bug, or supply-chain compromise in the request-construction path (all within the normal signup flow reachable by any user going through enrollment, not a privileged/hardware/test-only path) could cause a `reason` mismatch to reach the backend undetected, since nothing before the network boundary or on the backend side (based on available code) verifies that `reason` was part of what was signed.

### Recommendation
Include `signup_reason` (and any other backend-trust-relevant flags, such as `signup_extension_config`/`SignupMode` when applicable) inside the data hashed and signed by the Secure Element in `make_signature`, so that the signature cryptographically commits to the exact reason/config under which the biometric data was captured and reported. The backend should then re-derive/verify that the submitted `reason` matches what was signed, mirroring the Atlas fix of folding the expected `CallConfig` into the hashed struct.

### Proof of Concept
Conceptual PoC (no live network access available in this environment):
1. During a signup, the biometric pipeline internally marks the signup as `SignupReason::Fraud` after `make_signature` has already computed `signature` from `ORB_ID + user_id + iris codes` only [4](#0-3) .
2. Due to a retry-path bug or intermediate tampering, `signup_post::request` is invoked with `signup_reason = SignupReason::Normal` while reusing the same, already-valid `signature` [5](#0-4) .
3. The backend accepts the request because the signature still validates (it never covered `reason`), processing a signup that should have been flagged as fraudulent as a normal, successful enrollment.

fn make_signature(user_qr_code: &qr_scan::user::Data, pipeline: &Pipeline) -> Result<String> {
    let mut ctx = Context::new(&SHA256);
    ctx.update(ORB_ID.as_str().as_bytes());
    ctx.update(user_qr_code.user_id.as_bytes());
    ctx.update(pipeline.v2.ir_net_version.as_bytes());
    ctx.update(pipeline.v2.iris_version.as_bytes());
    ctx.update(pipeline.v2.eye_left.iris_code.as_bytes());
    ctx.update(pipeline.v2.eye_left.mask_code.as_bytes());
    ctx.update(pipeline.v2.eye_left.iris_code_version.as_bytes());
    ctx.update(pipeline.v2.eye_right.iris_code.as_bytes());
    ctx.update(pipeline.v2.eye_right.mask_code.as_bytes());
    ctx.update(pipeline.v2.eye_right.iris_code_version.as_bytes());

/// Every signup needs to be tagged with a reason for the backend to process it.
#[derive(Serialize, Debug, Default, Copy, Clone, PartialEq, Eq)]
pub enum SignupReason {
    /// Signup was successfully processed on the Orb.
    #[default]
    Normal,
    /// Signup failed due to some agent dying in the biometric pipeline or some internal error.
    Failure,
    /// Signup was detected as a fraud attempt at the orb (not to be confused with the backend fraud checks).
    Fraud,
}

/// Converts the signup reason to screaming snake case.
impl SignupReason {
    /// Converts the signup reason to screaming snake case. Using Serde's renaming won't work because Serde
    /// automatically adds "" (quotes) to the produced string. I.e. the output from Serde is "\"NORMAL\"".
    #[must_use]
    pub fn to_screaming_snake_case(&self) -> &str {
        match self {
            SignupReason::Normal => "NORMAL",
            SignupReason::Failure => "FAILURE",
            SignupReason::Fraud => "FRAUD",
        }
    }
}
