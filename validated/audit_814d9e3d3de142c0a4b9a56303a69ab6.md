### Title
Bad-debt cleanup resurrects wiped supply claims through the supply-index floor - (File: contracts/pool/src/interest.rs)

### Summary
`apply_bad_debt_to_supply_index` clamps a fully written-down supply index upward to `SUPPLY_INDEX_FLOOR_RAW`, while the affected supply shares remain outstanding. The mismatch between the debt-cleanup routine and the surviving share claim creates a phantom withdrawal balance that can consume a later depositor’s cash.

### Finding Description
During borrow-side seizure, `seize::apply` computes the unpaid debt, calls `apply_bad_debt_to_supply_index`, and then burns only the borrower’s debt shares. [1](#0-0) 

When bad debt meets or exceeds the total supplied value, `remaining` becomes zero and the mathematically correct post-write-down supply index is zero. [2](#0-1) 

The routine nevertheless applies `new_supply_index.max(SUPPLY_INDEX_FLOOR_RAW)`, raising the wiped index back to `RAY / 1000` without removing or compensating the existing supply shares. [3](#0-2) 

A subsequent withdrawal resolves those stale shares against the clamped index, burns them, checks reserves, debits cash, and transfers the resulting amount to the withdrawer. [4](#0-3) 

The permissionless `clean_bad_debt` controller entrypoint reaches this path for an account whose remaining collateral is within the socializable-bad-debt bound. [5](#0-4) [6](#0-5) 

The in-repository regression test demonstrates the exact sequence: a wipeout clamps the index upward, leaves a positive stranded claim, a fresh deposit funds the pool, and the stale position withdraws that deposit, leaving the fresh supplier underbacked. [7](#0-6) 

### Impact Explanation
A supplier holding shares in a market that later undergoes full bad-debt socialization retains a claim equal to approximately the floor-scaled value rather than zero. [8](#0-7) 

Once another user deposits into the apparently restarted market, the stale supplier can withdraw before the new supplier and receive real pool cash that should belong to the new depositor. [9](#0-8) 

This is theft of user funds bounded by the phantom floor claim: at `SUPPLY_INDEX_FLOOR_RAW`, a wiped supplier retains roughly `0.1%` of its pre-wipeout scaled position value, plus any subsequent index accrual. [10](#0-9) 

### Likelihood Explanation
The attacker must hold supply in a market before a sufficiently large bad-debt cleanup, but the cleanup itself is permissionless through `clean_bad_debt`. [5](#0-4) 

Full wipeout requires bad debt at least equal to the total supplied value, such as an account whose collateral has already fallen to the dust threshold while debt remains. [11](#0-10) 

The attacker then needs a later supply into the affected market, after which a normal owner-authorized `withdraw` can extract the phantom balance. [12](#0-11) 

### Recommendation
Do not raise a fully socialized index to `SUPPLY_INDEX_FLOOR_RAW` while legacy supply shares remain outstanding. [3](#0-2) 

Instead, either allow the supply index to reach zero for a complete write-down or atomically remove/compensate all residual supply shares before applying the floor. The corresponding regression tests should assert that a complete bad-debt write-down leaves every pre-existing supply position with a zero withdrawal value and that fresh deposits cannot be drained by wiped shares. [10](#0-9) 

### Proof of Concept
1. An attacker holds `1_000` units of scaled supply in a market with supply index `RAY`.
2. A separate account retains bad debt at least equal to the market’s total supplied value, while its remaining collateral is within the bad-debt dust bound.
3. Any caller invokes `Controller::clean_bad_debt(caller, insolvent_account_id)`.
4. The pool’s borrow-side seizure computes `remaining = 0`, then stores `supply_index = SUPPLY_INDEX_FLOOR_RAW` instead of zero; the attacker’s shares remain recorded. [8](#0-7) 
5. The attacker’s stranded claim is now approximately `1` token rather than zero.
6. A victim calls `Controller::supply(caller, 0, spoke_id, [(hub_asset, 1)])`, depositing `1` token into the same pool.
7. The attacker calls `Controller::withdraw(attacker, attacker_account_id, [(hub_asset, 0)], Some(attacker))`.
8. The stale position withdraws the victim’s `1` token; the victim retains a recorded claim but the market’s cash is insufficient to pay it. [13](#0-12)

```rust
pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
```

```rust
/// Maps requested amount and position to shares burned and gross asset amount.
/// Panics if a nonzero gross amount would burn zero shares.
fn resolve_close_or_partial(cache: &Cache, amount: i128, position: Ray) -> (Ray, i128) {
    let (burned, gross_amount) = cache.resolve_withdrawal(amount, position);
    assert_with_error!(
        cache.env(),
        gross_amount == 0 || burned.raw() > 0,
        GenericError::WithdrawRoundsToZeroShares
    );
    (burned, gross_amount)
}

/// Burns `burned` from market supply and returns the user's remaining scaled position.
fn burn_position(env: &Env, cache: &mut Cache, position: Ray, burned: Ray) -> Ray {
    cache.burn_supply(burned);
    position.checked_sub(env, burned)
}

/// Enforces reserve, utilization, and solvency guards, then debits cash for
/// the net transfer. Liquidations and footprint-only closes skip utilization.
fn gate_and_debit(env: &Env, cache: &mut Cache, net_transfer: i128, skip_utilization_check: bool) {
    cache.require_reserves(net_transfer);

    if !skip_utilization_check {
        guards::require_utilization_below_max(env, cache);
    }
    guards::require_supply_for_debt(env, cache);
    cache.debit_cash(net_transfer);
}
```

```rust
#[test]
fn test_raw_cache_floor_clamp_strands_claim_without_supply_guard() {
    let t = TestSetup::new();
    t.as_contract(|| {
        let old_scaled_raw = 1_000 * RAY;
        let mut cache = t.fresh_cache(PoolStateRaw {
            supplied: old_scaled_raw,
            borrowed: 0,
            revenue: 0,
            borrow_index: RAY,
            supply_index: RAY,
            last_timestamp: 0,
            cash: 0,
        });
        let old_scaled = Ray::from(old_scaled_raw);

        apply_bad_debt_to_supply_index(&mut cache, Ray::from(5_000 * RAY));
        assert_eq!(
            cache.supply_index().raw(),
            SUPPLY_INDEX_FLOOR_RAW,
            "wipeout clamps supply_index UP to RAY/1000 instead of resetting shares to 0",
        );

        let stranded = cache.unscale_supply_floor(old_scaled);
        assert!(stranded > 0, "floor clamp leaves S_old a phantom claim");
        assert_eq!(
            cache.cash(),
            0,
            "no cash yet: invariant only masked by require_reserves"
        );

        let fresh_cash = stranded;
        let fresh_scaled = cache.calculate_scaled_supply(fresh_cash);
        cache.mint_supply(fresh_scaled);
        cache.credit_cash(fresh_cash);

        let fresh_claim = cache.unscale_supply_floor(fresh_scaled);
        assert_eq!(
            fresh_claim, fresh_cash,
            "fresh supplier's claim equals deposit"
        );

        let (burn, gross) = cache.resolve_withdrawal(i128::MAX, old_scaled);
        cache.require_reserves(gross);
        cache.burn_supply(burn);
        cache.debit_cash(gross);

        assert!(gross > 0, "stranded wiped position pays out real tokens");
        assert_eq!(gross, fresh_cash, "S_old drains exactly the fresh deposit");
        assert!(
            cache.cash() < fresh_claim,
            "pool cash ({}) can no longer cover fresh supplier claim ({}): funds lost",
            cache.cash(),
            fresh_claim,
        );
    });
```
