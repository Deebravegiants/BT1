### Title
Unaccounted arbitrary calls from Emporium via the Min-circuit path let any attacker drain Emporium's balances and consume standing token approvals - (File: `contracts/CircomDataBuilder.sol`, `contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol`)

### Summary
When `externalActionId == HINKAL_EMPORIUM_ACTION_ID` and `erc20TokenAddresses.length == 0`, `formInputForCircom` routes to `formInputEmporiumMin`, whose only constraint is `message == Poseidon(messageSeed)` — a relation any attacker can trivially satisfy with a self-chosen `messageSeed`. `EmporiumUpgradeable.runAction` is then invoked with an empty `erc20TokenAddresses` array, so its entire balance-accounting loop (`balancesBefore`/`balancesAfter`) is skipped, while the attacker-supplied `EmporiumStack.ops` (with `signerAddress == address(0)`, which bypasses signature verification entirely in `verifyWallet`) can still execute arbitrary low-level `.call()`s from Emporium's identity to any `endpoint`.

### Finding Description
The invariant that should hold is: *assets Emporium can move in a transaction == assets accounted for in `balancesBefore`/`balancesAfter`*.

Path:
1. `Hinkal.transact` → `hinkalHelper.performHinkalChecks` → `CircomDataBuilder.formInputForCircom` (`contracts/CircomDataBuilder.sol:139-148`) selects `formInputEmporiumMin` whenever `externalActionId == HINKAL_EMPORIUM_ACTION_ID` and `erc20TokenAddresses.length == 0`.
2. `formInputEmporiumMin` (`contracts/CircomDataBuilder.sol:150-161`) only feeds `emporiumMessage`, `timeStamp`, `calldataHash` into the proof — matching `MainEVMCircuitMin` (`circuits/MainEVMCircuitMin.circom`), whose sole constraint is `message <== Poseidon(messageSeed)`. This proves nothing about ownership, root hash, nullifiers, or the content of `externalActionMetadata` — it's a public one-way hash relation the attacker satisfies by simply picking `messageSeed` and computing `message`.
3. `dimensionsCheck`/`checkOnchainCreation` (`contracts/HinkalHelper.sol:64-202`) place no additional restriction preventing `externalActionId != 0` with `tokenNumber == 0`.
4. `Hinkal._externalTransact` (`contracts/Hinkal.sol:234-261`) builds `deltaAmountChanges` of length 0 and calls `EmporiumUpgradeable.runAction`.
5. In `runAction` (`contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol:76-160`): `balancesBefore`/`balancesAfter` are computed via `getBalancesForArray(circomData.erc20TokenAddresses)`, which is `[]` — the entire accounting loop at lines 132-151 never executes.
6. `verifyWallet` (lines 302-349) only checks `usedMessages[emporiumMessage]` and returns immediately with **no signature check at all** when `stack.signerAddress == address(0)` (lines 314-316).
7. The ops loop (lines 91-118) then executes `op.endpoint.call{value: op.value}(op.callData)` (CASE 2, since `signerAddress == 0` forces stateless path) for every attacker-supplied operation, with `msg.sender == Emporium`. This can call any ERC20's `transferFrom(victim, attacker, amount)` where `victim` had previously left a standing allowance to Emporium, or directly `.call{value: X}("")` to move any ETH already resident in Emporium (Emporium has a `receive()` function and the code's own comment at line 141 acknowledges "there were some funds on emporium before the call").

Because these calls are raw `.call()`s (not `SafeERC20`), a token that "silently returns false" on failure instead of reverting will report `success == true` even if the transfer failed on some legs — but the more direct, always-exploitable core issue is that **no accounting check exists at all** for token index 0-length case, and **no authorization check exists** for `signerAddress == 0` — funds moved by ops are simply never verified against any before/after delta.

No other guard intervenes: `performHinkalChecks` only checks `calldataHash` integrity (self-consistency of attacker-supplied data, not authorization), `rootHashExists`/`insertNullifiers` are irrelevant since `inputNullifiers`/`outCommitments` are forced to length 0 by `dimensionsCheck`, and `onlyAllowedRecipient` only checks `msg.sender == Hinkal`, which is trivially true since the call originates from `Hinkal.transact`.

### Impact Explanation
Critical — direct theft of funds. Any unprivileged attacker can:
- Drain any ETH or ERC20 balance sitting on the Emporium contract (residual, in-flight, or fee-related balances) with zero authorization.
- Consume any standing ERC20 `approve`/allowance previously granted to Emporium by any other user, transferring those tokens to themselves via `transferFrom`.

This is fully repeatable per distinct `emporiumMessage` (trivial to generate fresh ones), and each call costs the attacker only gas plus a locally-generated dummy proof for the trivial Min circuit relation.

### Likelihood Explanation
- No privileged role needed — matches the "unprivileged attacker" threat model exactly.
- Preconditions: (a) Emporium contract must be registered for `HINKAL_EMPORIUM_ACTION_ID` and have a verifier configured for the zero-token-dimension Min circuit (both are ordinary, expected protocol configuration, not a special/rare state); (b) Emporium must hold some value (ETH, residual token balance, or a standing allowance from any past user interaction) — which the code's own logic (`balanceChange` allowed to start non-zero, per the in-line comment) shows is an anticipated, normal state.
- Attacker cost is minimal: one transaction, a self-satisfied ZK proof, and crafted calldata.
- Fully repeatable against any future residual balance/allowance.

### Recommendation
- Do not allow `signerAddress == address(0)` to bypass authorization for arbitrary `ops`; require either a valid EIP-712 signature over the exact `ops` for every path, or restrict the unsigned path to a fixed, non-arbitrary, pre-vetted operation set.
- Remove or restrict the Min-circuit path (`formInputEmporiumMin`) so it cannot be paired with arbitrary `externalActionMetadata`/`ops`; if this path is meant only for read-only or already-scoped calls, bind the metadata hash into the circuit's public inputs meaningfully instead of just an off-chain `calldataHash` self-check.
- Enforce that `EmporiumUpgradeable.runAction` cannot execute state-changing/value-moving calls when `circomData.erc20TokenAddresses.length == 0`, or otherwise force balance accounting over every token/ETH actually touched by `ops`, independent of the caller-declared `erc20TokenAddresses` array.
- Replace raw `.call()` invocation targets/token interactions with `SafeERC20`-consistent, return-value-checked flows.

### Proof of Concept
Foundry test plan:
1. Deploy `Hinkal`, `HinkalHelper`, `EmporiumUpgradeable` (as allowed recipient), a mock ERC20 `Token`.
2. Simulate a pre-existing "victim" state: have `victim` call `Token.approve(emporium, largeAmount)` (standing approval) and/or send ETH directly to Emporium's address to simulate residual balance.
3. As `attacker` (fresh EOA, no special role):
   - Craft `EmporiumStack{ v:0, r:0, s:0, signerAddress: address(0), ops: [{endpoint: address(Token), invokeWallet:false, value:0, callData: abi.encodeCall(IERC20.transferFrom, (victim, attacker, largeAmount))}], maxFee:0, deadline: type(uint256).max }`, ABI-encode into `externalActionData.externalActionMetadata`.
   - Set `erc20TokenAddresses = []`, `amountChanges = []`, `inputNullifiers = []`, `outCommitments = []`, `onChainCreation = []`, `slippageValues = []`, dimensions with `tokenNumber = 0`.
   - Pick `messageSeed`, compute `message = Poseidon(messageSeed)`, set `circomData.emporiumMessage = message`, generate a valid Groth16 proof locally for `MainEVMCircuitMin`.
   - Compute `calldataHash` per `CircomDataBuilder.getHashedCalldata`.
   - Call `Hinkal.transact(a,b,c,dimensions,circomData)`.

    function runAction(
        CircomData calldata circomData,
        int256[] calldata deltaAmountChanges
    ) external override onlyAllowedRecipient returns (UTXO[] memory) {
        EmporiumStack memory stack = abi.decode(
            circomData.externalActionData.externalActionMetadata,
            (EmporiumStack)
        );

        uint256[] memory balancesBefore = getBalancesForArray(
            circomData.erc20TokenAddresses
        );

        verifyWallet(stack, circomData);

        for (uint256 i = 0; i < stack.ops.length; i++) {
            EmporiumOperation memory op = stack.ops[i];

            bool success;
            bytes memory err;

            // CASE 1: Stateful Interaction
            if (op.invokeWallet && stack.signerAddress != address(0)) {
                (success, err) = IHinkalWallet(stack.signerAddress)
                    .callHinkalWallet(op.endpoint, op.callData, op.value);
            }
            // CASE 2: Stateless Interaction
            else {
                bytes4 selector = bytes4(op.callData);
                if (
                    selector == IHinkalWallet.callHinkalWallet.selector ||
                    selector == IHinkalWallet.doSendToRelay.selector
                ) {
                    revert UnauthorizedWalletCall();
                }

                (success, err) = op.endpoint.call{value: op.value}(op.callData);
            }

            if (!success) {
                revert CallFailed(err);
            }
        }

        payRelayFees(circomData, stack.signerAddress, deltaAmountChanges);

        uint256[] memory balancesAfter = getBalancesForArray(
            circomData.erc20TokenAddresses
        );

        UTXO[] memory utxoSet = new UTXO[](
            circomData.erc20TokenAddresses.length
        );

        uint256 utxoSetLength;

        for (uint256 i = 0; i < circomData.erc20TokenAddresses.length; i++) {
            int256 balanceChange = int256(balancesAfter[i]) -
                int256(balancesBefore[i]);

            if (deltaAmountChanges[i] < 0) {
                balanceChange -= deltaAmountChanges[i];
                // this equation reads: total change of emporium balance = what was moved to emporium (-deltaAmountChange) + how emporium balance changed through tx (balanceChange)
            }

            // the only case when balanceChange can be < 0, when there were some funds on emporium before the call
            if (balanceChange < 0) {
                revert BalanceChangeShouldBePositive();
            }

            UTXO memory utxoOut = handleOut(balanceChange, circomData, i);

            if (utxoOut.amount > 0) {
                utxoSet[utxoSetLength++] = utxoOut;
            }
        }

        if (utxoSetLength < circomData.erc20TokenAddresses.length) {
            utxoSet.skipLast(
                circomData.erc20TokenAddresses.length - utxoSetLength
            );
        }

        return utxoSet;
    }
