### Title
Beefy consensus client accepts a zero (unset) child-trie overlay root as a valid finalized state commitment - (File: modules/ismp/clients/beefy/src/consensus.rs)

### Summary
This is the same bug class as CVE-2021-37682 (TFLite "use of uninitialized value"): a field (`quantization.params`) is only valid conditionally on a discriminant (`quantization.type != kTfLiteNoQuantization`), but the check is missing in many call sites, so uninitialized/default data is treated as valid. In `BeefyConsensusClient::verify_consensus`, `overlay_root` is initialized to `H256::default()` and is only overwritten if the parachain header carries an `ISMP_ID` consensus digest. Unlike `timestamp`, which is explicitly checked for the "not found" (zero) sentinel before being trusted, `overlay_root` has no equivalent validity check before being persisted into the finalized `StateCommitment`.

Both `timestamp` and `overlay_root` are set from optional digest entries with the same "unset" sentinel pattern (`0` / `H256::default()`), yet only `timestamp` is validated for the sentinel before use. `overlay_root` is unconditionally wrapped in `Some(overlay_root)` and stored: [2](#0-1) 

This mirrors the TFLite pattern exactly: a "type/presence" discriminant (`quantization.type` / "digest present") is supposed to gate use of a dependent field (`quantization.params` / `overlay_root`), but the gate is applied inconsistently — present for one field, missing for the sibling field that follows the identical code path.

Downstream, this `overlay_root` becomes the trusted trie root for ISMP request/response membership and non-membership checks in `modules/ismp/state-machines/substrate/src/lib.rs`, where the only guard is `Option::ok_or` (i.e., "is it `Some`", not "is it a real root"): [3](#0-2) [4](#0-3) 

A `Some(H256::zero())` value passes this guard identically to a genuine root.

### Impact Explanation
Any finalized parachain height whose header digest lacks the `ISMP_ID` consensus log (e.g., a block from a parachain runtime without `pallet-ismp` wired to always deposit it, or any code path/runtime upgrade window where the log is momentarily absent) gets committed by the BEEFY client with `overlay_root = Some(H256::zero())`. Once committed, this height is permanently finalized state (BEEFY consensus states/commitments are treated as immutable once accepted, evicted only by ring-buffer aging). Any subsequent relayer attempting to prove membership or non-membership of ISMP requests/responses dispatched at that height can never produce a valid trie proof against a zero root, since it is not the pallet's actual child-trie root. This permanently blocks message delivery for that height — a "route unable to deliver messages" / permanent freezing-of-funds condition for any request whose sole valid proof height falls on such a block, since escrowed funds tied to that request (fees, bridged assets, timeouts) cannot be settled.

### Likelihood Explanation
The condition is reachable purely from data already relayed by unprivileged BEEFY message submitters (`PROOF_TYPE_NAIVE` or `PROOF_TYPE_SP1` proofs), since parachain headers embedded in the finality proof are attacker-selected among the set the relay chain finalized. `is_parachain_tracked` filters by para-id, not by whether the ISMP digest is present, so any tracked-parachain header lacking the digest is processed identically to one that has it, with only `timestamp` guarded. The severity depends on whether such headers can occur on the tracked chains' actual runtimes (e.g., empty blocks, a `pallet-ismp` runtime upgrade gap, or a non-`pallet-ismp` chain being onboarded under a `BeefyClientConfig` that tracks it) — the code has no defense against it either way, which is the core CWE-908-class defect: the discriminant check that exists for `timestamp` is silently missing for `overlay_root`.

### Recommendation
Track whether the `ISMP_ID` digest was actually observed (e.g., use `Option<H256>` instead of a sentinel default, mirroring the explicit `TimestampNotFound` check), and return a hard error (e.g., `BeefyError::ChildTrieRootNotFound`) if the digest was absent, exactly as is already done for `timestamp`. This closes the asymmetry between the two identically-shaped digest fields.

### Proof of Concept
1. Craft or select a BEEFY finality proof (`PROOF_TYPE_NAIVE`/`PROOF_TYPE_SP1`) whose included parachain header for a tracked para-id contains an `ISMP_TIMESTAMP_ID` digest but no `ISMP_ID` digest (only the latter is optional under the current code).
2. Submit this proof via `verify_consensus`; it passes because only `timestamp == 0` is checked.
3. The resulting `StateCommitmentHeight` is stored with `commitment.overlay_root = Some(H256::zero())` for that height.
4. Any relayer later calling `verify_membership`/`verify_non_membership` against that height's commitment (`modules/ismp/state-machines/substrate/src/lib.rs:140-143`, `199-202`) receives `root = H256::zero()`, against which no legitimate trie proof can ever verify, permanently blocking delivery/timeout resolution of ISMP messages dispatched in that block.
