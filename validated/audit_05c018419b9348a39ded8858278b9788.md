### Title
GET-response fee is paid from a never-deleted `_requestCommitments` entry, letting a `GetRequestTimeout` be dispatched afterward and refund the same fee a second time - (File: `evm/src/core/EvmHost.sol`)

### Summary
Every request-lifecycle terminal path in `EvmHost.sol` deletes the `_requestCommitments[commitment]` entry to prevent it from being reused: `dispatchTimeOut` for both POST and GET explicitly `delete _requestCommitments[commitment]` for "replay protection" [1](#0-0) . However, the sibling terminal path for a successfully-delivered GET response, `dispatchIncoming(GetResponse ...)`, never deletes it — it only reads `_requestCommitments[commitment].fee` to pay the relayer, and leaves the fee metadata intact in storage [2](#0-1) . This mirrors the CVE-2024-39325 bug class exactly: a "status" field (`_requestCommitments[commitment]`, which functions as the fee/payment record for that request) is not reset once the corresponding payment action (fee) has been settled.

### Finding Description
`dispatchIncoming(GetResponse ...)` protects against replaying the *response* itself via `_responseReceipts[commitment]`, which `HandlerV2.handleGetResponses` checks before calling into the host (`DuplicateMessage` if already set) [3](#0-2) . But it never touches `_requestCommitments[commitment]`, the record that also gates the *timeout* path: `handleGetRequestTimeouts` only checks `meta.sender == address(0)` from `_requestCommitments` to decide whether the request is "known" and dispatchable as a timeout, and then verifies a non-membership proof for the response receipt against the source-chain state root at `message.height` [4](#0-3) .

Because `_requestCommitments[commitment]` is never deleted after a successful GET response delivery, `meta.sender` stays non-zero, so `handleGetRequestTimeouts` will still treat the request as "known" and pass it to `host.dispatchTimeOut(GetRequestTimeout, meta, commitment)`. `dispatchTimeOut` for GET requests does delete `_requestCommitments[commitment]` (replay-safe at that layer) and, on a successful `onGetTimeout` callback, refunds `meta.fee` to `meta.sender` a second time [1](#0-0) .

The remaining question is whether the non-membership proof check in `handleGetRequestTimeouts` (against `RESPONSE_RECEIPTS_STORAGE_PREFIX` at a *chosen historical* `message.height`) can be satisfied even though a response was later delivered on the source chain. If a relayer can supply `message.height` at (or based on) a height *before* the response was recorded on the source state machine — which is plausible since the request timeout is checked only against `state.timestamp` at that same historical height, and there is no requirement that `message.height` be the *current* finalized height — the non-membership proof for "no response receipt at that height" can validly verify even though a response commitment was delivered afterward. That would let a relayer collect the fee once via `dispatchIncoming(GetResponse)` and a second time via `dispatchTimeOut(GetRequestTimeout)` using a stale height's non-membership proof, exploiting the fact that `_requestCommitments` was never reset/cleared on the success path.

### Impact Explanation
If the historical-height non-membership proof can be crafted (relayer fully controls which finalized height/proof they submit, subject only to `challengePeriod` and the request's own `timeout()`), this allows theft of protocol/relayer fee funds: `IERC20(feeToken()).safeTransfer(meta.sender, meta.fee)` executes twice for one GET request, draining the fee token pool held by `EvmHost`. This is a direct funds-theft/duplicate-payment bug reachable by any relayer submitting proofs through the public `handleGetRequestTimeouts` entry point — no privileged role required.

### Likelihood Explanation
Medium. The attack requires the relayer to control or obtain a state root at a height where the response-receipt slot is provably empty, while the request itself has already timed out per `state.timestamp` at that height, and while the corresponding GET response has already been (or will be) separately delivered and rewarded via `dispatchIncoming(GetResponse)`. This is a timing/height-selection condition rather than a pure logic bypass, so it depends on the relative ordering/availability of finalized heights a relayer can supply, but nothing in the reviewed code path revalidates `_requestCommitments` freshness or blocks a timeout dispatch once a response has already been rewarded.

### Recommendation
In `EvmHost.dispatchIncoming(GetResponse memory response, address relayer)`, delete `_requestCommitments[commitment]` (mirroring the `dispatchTimeOut` paths) once the fee has been paid out, so that any subsequent `GetRequestTimeout` dispatch for the same commitment fails the `meta.sender == address(0)` / `UnknownMessage` check in `HandlerV2.handleGetRequestTimeouts`.

### Proof of Concept
Not independently executed against a live/test deployment; this is derived from static analysis of `EvmHost.sol` and `HandlerV2.sol`. A concrete PoC would need to: (1) dispatch a GET request with a nonzero fee, (2) have a relayer deliver a valid `GetResponse` via `handleGetResponses` to collect the fee once, (3) have the same relayer submit `handleGetRequestTimeouts` with a state root/height where the `RESPONSE_RECEIPTS_STORAGE_PREFIX` slot for the commitment is empty (e.g., a height prior to the response being recorded) but where `request.timeout() <= state.timestamp` is satisfied, and (4) confirm `onGetTimeout` succeeds and the fee is transferred a second time. **This last step — whether a relayer can actually obtain such a height/proof combination given the protocol's height-selection and challenge-period constraints — was not verified from the indexed code alone**; confirming it requires deeper study of how `message.height` is chosen/validated relative to `state_machine_commitment` update ordering, which may live in files outside what was retrieved (e.g., relayer/tesseract height-selection logic or additional constraints not visible in `HandlerV2.sol`).

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    /**
     * @dev Check the provided Get request timeouts, then dispatch to modules
     * @param host - Ismp host
     * @param message - batch get request timeouts
     */
    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
