[1](#0-0) ### Title

Accrual overflow can permanently freeze an oversized market before the borrow-index cap - (File: contracts/pool/src/interest.rs)

### Summary

The permissionless `Controller::update_indexes` path forwards each requested `HubAssetKey` to the pool, where `ops::market::accrue` loads the market and calls `interest::global_sync`. [1](#0-0) [2](#0-1) 

For a sufficiently large, highly utilized market, the scaled-debt-to-asset conversion can exceed `i128::MAX` while `borrow_index` is still below `MAX_BORROW_INDEX_RAY`, causing accrual to revert with `MathOverflow` before the index cap can engage. [3](#0-2) [4](#0-3) 

Because withdrawals and repayments synchronize the market before applying their mutations, the same overflow then prevents suppliers from exiting and borrowers from reducing debt. [5](#0-4) 

### Finding Description

`Controller::update_indexes(caller, assets)` requires only caller authorization and invokes the pool's `update_indexes` entrypoint. [1](#0-0) [6](#0-5) 

The pool loads each market's scaled `supplied`, `borrowed`, `revenue`, indexes and timestamp, then `global_sync` splits elapsed time into bounded chunks and applies `accrue_step` to the stored scaled totals and indexes. [7](#0-6) [8](#0-7) 

The vulnerable boundary is therefore the product of an attacker-influenced scaled balance and an interest index, not the index alone. [3](#0-2) 

The in-repository regression creates an 18-decimal market, supplies `1e27` raw units, borrows 98%, advances ledger time in yearly chunks, and observes `MathOverflow` while the stored borrow index remains below its configured cap. [9](#0-8) 

After that state is reached, both a one-unit withdrawal and a repayment revert with the same `MathOverflow`, leaving the overflow permanently repeatable under the deployed code. [5](#0-4) 

### Impact Explanation

This is a material denial of service: once the market crosses the numerical cliff, user collateral and supplied tokens cannot be withdrawn through the normal path, and borrowers cannot repay through the normal path. [5](#0-4) 

The freeze also prevents normal liquidation or interest-maintenance flows that require the market to synchronize, so the affected book cannot continue operating without a code-level remediation or equivalent privileged recovery mechanism. [2](#0-1) [8](#0-7) 

### Likelihood Explanation

The trigger does not require privileged execution at the final step: any authorized caller can submit `update_indexes` once ledger time makes the next accrual overflow. [1](#0-0) [2](#0-1) 

Likelihood is limited by the need for an allowed market to accumulate very large scaled exposure, sustained high utilization, and enough index growth for the product to approach `i128::MAX`; the regression demonstrates those conditions are representable in the contract's own state and rate model rather than requiring storage corruption. [9](#0-8) 

The issue should be treated as Medium severity because it can permanently freeze market funds under reachable accounting bounds, but it requires extreme market scale and accrual conditions rather than a single malformed call. [10](#0-9) 

### Recommendation

Bound market exposure by the maximum representable `scaled_balance * index` product, not only by token amount or by `MAX_BORROW_INDEX_RAY`. [3](#0-2) 

Inside accrual, calculate the next utilization and index with checked arithmetic and clamp or safely stop index growth before any unscale operation can overflow. [11](#0-10) 

Add a regression that asserts the index cap or exposure cap engages before `scaled_to_original` can overflow, and separately proves that a minimal withdrawal and repayment remain executable at that boundary. [10](#0-9) 

### Proof of Concept

The existing regression demonstrates the exploit state with an 18-decimal market, `principal = 1_000_000_000 * 10^18` raw units, and `debt = principal * 98 / 100`. [12](#0-11) 

A caller then invokes the public path equivalent to:

```rust
controller.update_indexes(
    caller,
    vec![HubAssetKey {
        hub_id,
        asset: big18_token,
    }],
);
```

The controller forwards that vector to `pool.update_indexes`, which loads the market and calls `global_sync`. [6](#0-5) [2](#0-1) 

The regression repeats the call as ledger time advances until it returns `MathOverflow`, while confirming that the stored borrow index is still below `MAX_BORROW_INDEX_RAY`. [13](#0-12) 

Subsequent calls equivalent to `withdraw(BOB, account_id, [(BIG18, 1)], None)` and `repay(payer, account_id, [(BIG18, amount)])` also revert with `MathOverflow`, proving persistent freezing rather than a one-call failure. [5](#0-4)

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {

        }

    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}
