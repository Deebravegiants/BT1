### Title
`CallDispatcher.dispatch()` has no caller/initiator authentication, letting anyone drain funds it transiently holds — (File: `evm/src/utils/CallDispatcher.sol`)

### Summary
The Astaria `flashAction()` bug is a missing-initiator problem: the callback recipient (`onFlashAction`) cannot verify who triggered the privileged call, so anyone can invoke it and the receiver has no way to authenticate legitimacy. The same root cause exists more severely in Hyperbridge's `CallDispatcher.dispatch()`, which is the arbitrary-call execution primitive used by `IntentGatewayV2`/`IntentsBase._execute()` to route escrowed order funds through DEXes and DeFi protocols. `dispatch()` is a fully public, unauthenticated function with no restriction on the caller, so it does not — and cannot — convey or check the "initiator" of the call, unlike other privileged dispatch entrypoints in the codebase (e.g., `EvmHost.dispatchIncoming`, which is gated with `restrict(_hostParams.handler)`).

### Finding Description
`IntentsBase._execute()` uses the gateway's configured `dispatcher` (`_params.dispatcher`) to run solver/user-attached calldata (`order.output.call`, and similarly `predispatch.call` during `placeOrder`) against arbitrary third-party targets, and to sweep back any residual balances left on the dispatcher: [1](#0-0) 

This dispatcher is `CallDispatcher.sol`, whose `dispatch()` entrypoint is `external` with no access-control modifier at all — it accepts ETH via `receive()` and blindly forwards `call.value`/`call.data` to any `to` address for every entry in the caller-supplied `Call[]` array: [2](#0-1) 

Because `dispatch()` never checks `msg.sender`, it cannot distinguish a legitimate invocation coming from `IntentGatewayV2`/`IntentsBase._execute()` (as part of a real order fill/predispatch) from an invocation made directly by an unrelated, unprivileged actor. This is precisely the class of bug in the referenced report: the privileged execution entrypoint does not authenticate or convey its initiator, so any receiver — or in this case, the dispatcher's own privileged trigger — cannot verify legitimacy. The `_execute()` function itself documents that the dispatcher can accumulate residual token/ETH balances ("any residual token balances left on the dispatcher are swept back... accounted for as protocol dust"), and the code explicitly checks `dispatcher.balance` and `IERC20(token).balanceOf(dispatcher)` after a `dispatch()` call, confirming the dispatcher is expected to (at least transiently) hold real funds: [3](#0-2) 

Since `dispatch()` is permissionless, any address can call `CallDispatcher.dispatch()` directly (front-running or racing the gateway's own sweep call, or acting whenever any balance is left on the dispatcher for any reason — partial sweeps, rounding, or unexpected leftover ERC-20/ETH from other integrations sharing the same dispatcher instance) and instruct it to transfer out whatever balance it currently holds to an attacker-controlled address.

### Impact Explanation
Funds sitting on the `CallDispatcher` (escrowed order inputs routed through `predispatch.call`, or output-side surplus/dust awaiting sweep in `_execute()`) are not protected by any authentication of the caller invoking `dispatch()`. An attacker who calls `dispatch()` directly with a malicious `Call[]` (e.g., `to: token, data: transfer(attacker, balance)`) can redirect any balance currently held by the dispatcher to themselves — a direct theft of protocol/user funds, satisfying the "concrete theft ... of funds" bar for this analog scan.

### Likelihood Explanation
The dispatcher is a shared, persistent contract address (`_params.dispatcher`) reused across every order fill and predispatch, so it is reachable at any time by any unprivileged EOA/contract, not just during a legitimate order's transaction. Any transient balance window — even one created by normal operation (e.g., between transferring predispatch assets to the dispatcher and its calldata executing, or leftover dust after `_execute()`'s sweep enumerates only the order's own output assets) — is exploitable because `dispatch()` performs zero sender validation, unlike the host's `dispatchIncoming` which is `restrict`ed to the handler. This makes the vulnerability trivially and repeatedly reachable by a single unprivileged transaction from any account.

### Recommendation
Restrict `CallDispatcher.dispatch()` to only be callable by the authorized initiator (e.g., only the registered `IntentGatewayV2`/gateway contract via a `restrict`/`onlyGateway` modifier), analogous to how `EvmHost.dispatchIncoming` is gated with `restrict(_hostParams.handler)`. If a shared dispatcher must remain usable by multiple callers, thread the initiator's identity through the call (mirroring AAVE/Uniswap's flashloan pattern) so any funds routed through it can be tied to and verified against the expected caller before execution, and ensure no token/ETH balance can persist on the dispatcher between transactions.

### Proof of Concept
1. Observe (via mempool or state) that `CallDispatcher` (the address returned by `_params.dispatcher`) currently holds a non-zero token or ETH balance — this can occur transiently during `placeOrder`'s `predispatch.call` flow or after an `_execute()` sweep that only accounts for the order's own `outputsLen` assets.
2. Call `CallDispatcher.dispatch(encoded)` directly (no `IntentGatewayV2` involvement needed) with `encoded` decoding to a `Call[]` whose `to` is the token contract and `data` is `transfer(attacker, balance)`, or `to: attacker, value: dispatcher.balance` for native ETH. [4](#0-3) 
3. Since `dispatch()` performs no `msg.sender`/initiator check, the call succeeds and the balance is transferred to the attacker, regardless of whether the caller is the legitimate `IntentGatewayV2` gateway.

    function _execute(Order calldata order, uint256 outputsLen) internal {
        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            } else {
                uint256 balance = IERC20(token).balanceOf(dispatcher);
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            }

            unchecked {
                ++i;
            }
        }

        if (sweepCount > 0) {
            Call[] memory finalCalls = new Call[](sweepCount);
            for (uint256 i; i < sweepCount;) {
                finalCalls[i] = sweepCalls[i];
                unchecked {
                    ++i;
                }
            }
            ICallDispatcher(dispatcher).dispatch(abi.encode(finalCalls));
        }
    }

     * @dev Receive function to accept ETH transfers

    receive() external payable {}

    /**
     *  @dev reverts if the target is not a contract or if any of the calls reverts.
     */
    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
}
