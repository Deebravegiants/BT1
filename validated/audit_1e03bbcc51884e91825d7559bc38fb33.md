## Title
Relayer reward for the entire consensus batch is attributed to `messages[0]`'s signer, letting a bundler steal other relayers' rewards - (File: `modules/pallets/consensus-incentives/src/impls.rs`)

### Summary
`pallet-consensus-incentives`'s `FeeHandler::on_executed` implementation determines the relayer to reward for **every** `StateMachineUpdated` event in a `handle_unsigned` batch by reading only `messages[0]`'s signature, then applies that single recovered account to the rewards for all state machines whose commitments advanced anywhere in the batch [1](#0-0) . Since `messages` in `handle_unsigned` is an arbitrary `Vec<Message>` assembled by whoever submits the unsigned extrinsic [2](#0-1) , and each `Message::Consensus` embeds its own self-authenticating `signer` field independent of the submitting account, an attacker can lift other relayers' already-broadcast (or independently reconstructible) consensus proofs, append them after their own message, and collect the reward that `process_message`/`Currency::transfer` pays out for all of them.

### Finding Description
`on_executed` is invoked once per `handle_unsigned` call with the full batch of executed messages and the events they produced [3](#0-2) . `handle_unsigned` is a permissionless `Unsigned`-origin extrinsic — anyone can construct the `messages: Vec<Message>` argument, and a single call may legitimately carry multiple `Message::Consensus` entries, as confirmed by the "mixed batch" test that exercises a `handle_unsigned` call containing two distinct consensus messages in one transaction [4](#0-3) .

Inside `on_executed`, the relayer to be rewarded is derived exclusively from `messages.get(0)`:

```rust
let maybe_relayer_account = messages.get(0).and_then(|first_message| {
    if let Message::Consensus(consensus_msg) = &first_message.message {
        ...verify_and_get_sr25519_pubkey...
    } else { None }
});
``` [5](#0-4) 

That single `relayer_account` is then applied to **every** state machine that advanced anywhere in the batch's `events`, via the `highest_per_state_machine` loop and subsequent `process_message` calls, without any check that the event's originating message index actually corresponds to `messages[0]`:

```rust
for (state_machine_id, latest_height) in highest_per_state_machine {
    let state_machine_height = StateMachineHeight { id: state_machine_id.clone(), height: latest_height };
    let _ = Self::process_message(state_machine_height, state_machine_id, relayer_account.clone().into());
}
``` [6](#0-5) 

`process_message` pays out a real treasury-funded token transfer plus a reputation mint to that single account for each state machine's reward span: [7](#0-6) 

Consensus messages are validated purely by the embedded proof and self-authenticating `signer` signature over the proof bytes — they are not bound to the account that submits the encompassing `handle_unsigned` extrinsic. This means any account can:
1. Include a trivial/cheap `Message::Consensus` for some state machine as `messages[0]` (their own valid signature).
2. Append other relayers' distinct, independently-valid `Message::Consensus` entries for other state machines as `messages[1..]` (sourced from the public transaction pool or otherwise reconstructed valid proofs).
3. Submit the combined batch via `handle_unsigned`.

`execute()` processes and accepts every message that carries a valid proof regardless of who submits the batch [8](#0-7) , producing `StateMachineUpdated` events for each. `on_executed` then credits the attacker's `messages[0]` account for the reward span of *every* one of those state machines — diverting rewards that should have gone to the relayers who actually produced the later messages in the batch.

### Impact Explanation
This is a direct, permissionless theft-of-funds vector against `pallet-consensus-incentives`'s treasury-backed relayer reward pool. An attacker pays only the (comparatively negligible) cost of resubmitting other relayers' public consensus data and collects the full reward for state-machine advances they did not perform the verification/delivery work for, at the expense of the treasury account and the legitimately entitled relayers. Given relayer incentive accounting is explicitly an in-scope critical protocol surface, and the misattribution is a concrete fund transfer (`T::Currency::transfer` plus `ReputationAsset::mint_into`), this qualifies as High severity.

### Likelihood Explanation
`handle_unsigned` is intentionally permissionless (any account, unsigned origin) so that anyone can relay ISMP messages for free [9](#0-8) ; batching multiple consensus messages into one call is an explicitly supported/tested pattern [4](#0-3) . Any relayer monitoring the network or transaction pool for other participants' pending consensus proofs can trivially reorder/rebundle them ahead of their own submission to claim the reward. No privileged access or race-condition timing beyond normal mempool visibility is required, making this readily exploitable by an ordinary participant.

### Recommendation
Attribute each `StateMachineUpdated` event's reward to the signer of the specific `Message::Consensus` entry that produced it, not to `messages[0]`. Concretely, iterate `messages` in lockstep with the events they generated (or otherwise associate each `IsmpEvent::StateMachineUpdated` with its originating message index), recover the signer per-message, and only reward the `relayer_account` recovered from the message that actually advanced that particular `state_machine_id`.

### Proof of Concept
1. Relayer B broadcasts (or it appears in the public tx pool as) a valid `handle_unsigned([Message::Consensus(proof_B, signer_B)])` for `state_machine_id = X`, correctly signed by B.
2. Attacker A observes this pending/broadcast consensus message and constructs their own `handle_unsigned` call:
   `messages = [Message::Consensus(proof_A_trivial, signer_A), Message::Consensus(proof_B, signer_B)]`
   where `proof_A_trivial` is any cheap valid consensus update A can produce for any state machine.
3. A submits this batch first (or simply before B's own submission lands). `execute()` processes both messages successfully, producing `StateMachineUpdated` events for both state machine A's target and `X` [3](#0-2) .
4. `on_executed` reads only `messages[0]` (A's message), recovers `relayer_account = A`, and pays A the reward for **both** state machine updates — including the one produced by B's proof — via `process_message` [10](#0-9) .
5. B's genuine reward for state machine `X` is misappropriated by A, even though B did the work of sourcing/signing that proof.

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	fn on_executed(
		messages: Vec<MessageWithWeight>,
		events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});

		if let Some(relayer_account) = maybe_relayer_account {
			// When a batch contains multiple `StateMachineUpdated` events for the
			// same `state_machine_id` (sequential consensus updates for the same
			// chain), `calculate_reward` reads the same persisted
			// `(latest_commitment_height, previous_commitment_height)` pair on
			// every iteration and pays the same block-span reward N times.
			// Collapse the per-state-machine event stream to the single highest
			// `latest_height` so each state machine receives one reward per
			// batch, sized by the actual span of its commitment advance.
			let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
			for event in events {
				if let IsmpEvent::StateMachineUpdated(update) = event {
					highest_per_state_machine
						.entry(update.state_machine_id)
						.and_modify(|h| {
							if update.latest_height > *h {
								*h = update.latest_height;
							}
						})
						.or_insert(update.latest_height);
				}
			}

			for (state_machine_id, latest_height) in highest_per_state_machine {
				let state_machine_height =
					StateMachineHeight { id: state_machine_id.clone(), height: latest_height };

				let _ = Self::process_message(
					state_machine_height,
					state_machine_id,
					relayer_account.clone().into(),
				);
			}

	pub fn execute(messages: Vec<Message>) -> Result<Vec<events::Event>, Error<T>> {
		let host = Pallet::<T>::default();

		let message_results = messages
			.iter()
			.map(|msg| handle_incoming_message(&host, msg.clone()))
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		let messages_with_weights = message_results
			.iter()
			.zip(messages)
			.map(|(result, message)| MessageWithWeight { message, weight: result.weight() })
			.collect::<Vec<_>>();

		let events = message_results
			.into_iter()
			// check that requests will be successfully dispatched
			// so we can not be spammed with failing txs
			.map(|result| match result {
				MessageResult::Request { events, .. } |
				MessageResult::Response { events, .. } |
				MessageResult::Timeout { events, .. } => events,
				MessageResult::ConsensusMessage(events) => events.into_iter().map(Ok).collect(),
				MessageResult::FrozenClient(_) => vec![],
			})
			.flatten()
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		T::FeeHandler::on_executed(messages_with_weights, events.clone())
			.map_err(|_| Error::<T>::ErrorChargingFee)?;
