### Title
Hardcoded $1 stablecoin peg in bid valuation lets a depegged/low-value "stable" output win the intents bid auction - ([File: sdk/packages/sdk/src/protocols/intents/BidManager.ts])

### Summary
`BidManager` values competing solver bids for an intent order by normalizing token amounts and treating any token classified as USDC/USDT as worth exactly $1, with no live price check. This mirrors the reported "Do not support USDC" bug class (blind trust in a stablecoin's peg) but reaches an actual fund-movement decision point in Hyperbridge's permissionless intents system: which unprivileged solver's bid gets selected to fill a user's order.

### Finding Description
`computeStablesUsdValue` sums bid/order output amounts for tokens classified as stables and divides by decimals, with each unit counted as exactly $1: [1](#0-0) 

This function is used directly to rank competing bids and pick winners in `sortAllStables`: [2](#0-1) 

And the same $1-pin assumption is applied when a bid's outputs are stable but mixed with non-stable legs in `computeOutputsUsdValue`, where only non-stable legs are priced via a live DEX quote while stable legs are valued at par with no market check at all: [3](#0-2) 

The same pattern — pegging USDC/USDT/DAI at $1 with no oracle or market check — recurs in the Simplex filler's confirmation-depth sizing (`FXFiller.usdFactors`, `ContractInteractionService.getInputUsdValue`) and the indexer's USD pricing (`getTokenUsdPriceWithFx`), confirming this is a systemic design assumption across the intents/solver stack rather than an isolated helper: [4](#0-3) [5](#0-4) 

Because Hyperbridge's intent gateway lets any solver submit a bid (an unprivileged, permissionless action), and `BidManager` is the code path that decides which bid is economically "best" for the user, an attacker acting as a solver could submit a bid whose output token is nominally classified as a supported stablecoin (or is deployed/re-mapped as one in a misconfigured or malicious deployment) but has actually depegged or is otherwise worth less than $1. `computeStablesUsdValue`/`computeOutputsUsdValue` would still score it at full par value, causing it to rank equally or better than a bid using a genuinely $1-valued asset, and get selected to fill the order — delivering less real value to the order's user than a correctly-priced competing bid would have.

### Impact Explanation
This breaks the core guarantee of solver selection: that the "best" bid is chosen based on actual economic value delivered to the user. A depegged or manipulated stable output can win an auction it should have lost, silently degrading the value users receive from otherwise-honest intent fills — a value-extraction vector directly analogous to the reported USDC-depeg risk, but concretely reachable through the unprivileged bid-submission path of the intents system rather than merely a documentation/design concern.

### Likelihood Explanation
Likelihood depends on (a) a stablecoin used in the supported set actually depegging (a real, recurring market event, as the original report notes), or (b) a solver being able to have a token counted as "stable" while it is not $1-backed. Bidding is permissionless, so any solver can attempt this whenever a real depeg event occurs, with no additional privilege required — it only requires normal participation in the existing bid auction.

### Recommendation
Do not treat USDC/USDT/DAI (or any token) as an unconditional $1 peg in bid valuation. Source a live price (oracle or DEX quote, as already done for non-stable legs in `computeOutputsUsdValue`) for every leg, including nominal stables, and use that live price for both `computeStablesUsdValue` and `computeOutputsUsdValue` so bid ranking reflects real value delivered rather than an assumed peg. Apply the same fix consistently to the Simplex filler's `usdFactors`/`getInputUsdValue` USD-anchor logic, since it shares the same trust assumption.

### Proof of Concept
1. A user places a cross-chain intent order expecting output in a token nominally classified as a stable (e.g., USDC).
2. Two solvers bid: Solver A offers 1000 "USDC" that is fully pegged; Solver B offers 1000 units of a token classified/mapped as a stable but currently trading at $0.85 (depegged, or a malicious/low-quality stable variant accepted by config).
3. `BidManager.sortAllStables` (or `computeOutputsUsdValue` for mixed baskets) computes both bids as worth $1000 via the hardcoded $1 assumption in `computeStablesUsdValue`, ranking them identically.
4. Ties/near-ties can result in Solver B's bid being selected (e.g. by submission order or another non-price tiebreaker), so the user receives $850 of real value while the accounting/selection logic recorded a $1000 fill.
5. No component in the bid-selection path re-checks the peg against a live price, so this degradation is undetected by the solver-selection logic itself.

	/**
	 * Case B: all outputs are USDC/USDT.
	 * Sum normalised USD values (treating each stable as $1) and sort descending.
	 * Partial fill bids are allowed.
	 */
	private sortAllStables(bids: Bid[], orderOutputs: TokenInfo[], chainId: string): Bid[] {
		const requiredUsd = this.computeStablesUsdValue(orderOutputs, chainId)
		console.log(`[BidManager] sortAllStables: required USD value=${requiredUsd.toString()}`)

		const validBids: { bid: Bid; usdValue: Decimal }[] = []

		for (const bid of bids) {
			const bidUsd = this.computeStablesUsdValue(bid.outputs, chainId)

			if (bidUsd === null) {
				console.warn(`[BidManager] Bid from solver=${bid.solverAddress} REJECTED: unable to compute USD value`)
				continue
			}

			if (bidUsd.lt(requiredUsd)) {
				console.log(
					`[BidManager] Bid from solver=${bid.solverAddress}: partial fill candidate ` +
						`(bid=${bidUsd.toString()}, required=${requiredUsd.toString()}, ` +
						`covers=${bidUsd.div(requiredUsd).mul(100).toFixed(2)}%)`,
				)
			} else {
				console.log(`[BidManager] Bid from solver=${bid.solverAddress} ACCEPTED: USD value=${bidUsd.toString()}`)
			}

			validBids.push({ bid, usdValue: bidUsd })
		}

		validBids.sort((a, b) => b.usdValue.comparedTo(a.usdValue))
		return validBids.map(({ bid }) => bid)
	}

	/**
	 * Sums the USD value of a basket of stable tokens (USDC/USDT only),
	 * normalising each amount by its decimal count and treating each token as $1.
	 *
	 * @param outputs - List of token/amount pairs where every token is a stable.
	 * @param chainId - State-machine ID used to look up decimals.
	 * @returns Total USD value as a `Decimal`.
	 */
	private computeStablesUsdValue(outputs: TokenInfo[], chainId: string): Decimal {
		let total = new Decimal(0)
		for (const output of outputs) {
			const tokenAddr = bytes32ToBytes20(output.token)
			const decimals = this.getStableDecimals(tokenAddr, chainId)
			total = total.plus(new Decimal(output.amount.toString()).div(new Decimal(10).pow(decimals)))
		}
		return total
	}

	private async computeOutputsUsdValue(
		outputs: { token: HexString; amount: bigint }[],
		chainId: string,
	): Promise<Decimal | null> {
		const configService = this.ctx.dest.configService
		const client = this.ctx.dest.client
		const usdcAddr = configService.getUsdcAsset(chainId)
		const usdcDecimals = configService.getUsdcDecimals(chainId)
		const { asset: wethAddr } = configService.getWrappedNativeAssetWithDecimals(chainId)

		let totalUsd = new Decimal(0)

		for (const output of outputs) {
			const tokenAddr = bytes32ToBytes20(output.token)

			if (this.isStableToken(tokenAddr, chainId)) {
				const decimals = this.getStableDecimals(tokenAddr, chainId)
				totalUsd = totalUsd.plus(new Decimal(output.amount.toString()).div(new Decimal(10).pow(decimals)))
				continue
			}

			try {
				const usdcAmount = await this.quoteTokenToUsdc(
					tokenAddr,
					output.amount,
					wethAddr,
					usdcAddr,
					chainId,
					client,
				)
				totalUsd = totalUsd.plus(new Decimal(usdcAmount.toString()).div(new Decimal(10).pow(usdcDecimals)))
			} catch {
				return null
			}
		}

		return totalUsd
	}

	private usdFactors(): Map<string, Decimal> {
		const factors = new Map<string, Decimal>()
		for (const symbol of USD_STABLE_SYMBOLS) factors.set(symbol, new Decimal(1))

		let grew = true
		while (grew) {
			grew = false
			for (const pair of this.pairs) {
				if (isSameTokenPair(pair)) continue
				const mid = pairMidRate(pair)
				if (!mid) continue
				const token0 = normalizeSymbol(pair.token0)
				const token1 = normalizeSymbol(pair.token1)
				const usd0 = factors.get(token0)
				const usd1 = factors.get(token1)
				if (usd0 && !usd1) {
					// 1 token0 = mid token1 ⇒ usd(token1) = usd(token0) / mid.
					factors.set(token1, usd0.div(mid))
					grew = true
				} else if (usd1 && !usd0) {
					factors.set(token0, usd1.mul(mid))
					grew = true
				}
			}
		}
		return factors
	}

	/**
	 * Calculates the total USD value of an order's inputs.
	 * Only stable (USDC/USDT) inputs contribute; non-stables contribute 0.
	 *
	 * @param order - The order to calculate input value for
	 * @returns The total USD value of inputs (sum of normalized stable amounts, or 0 if none)
	 */
	async getInputUsdValue(order: Order): Promise<Decimal> {
		let inputUsdValue = new Decimal(0)
		const inputs = order.inputs
		const sourceUsdc = this.configService.getUsdcAsset(order.source).toLowerCase()
		const sourceUsdt = this.configService.getUsdtAsset(order.source).toLowerCase()

		for (const input of inputs) {
			const tokenAddress = bytes32ToBytes20(input.token)
			const addr = tokenAddress.toLowerCase()
			if (addr !== sourceUsdc && addr !== sourceUsdt) continue
			const decimals = await this.getTokenDecimals(tokenAddress, order.source)
			const tokenAmount = new Decimal(formatUnits(input.amount, decimals))
			inputUsdValue = inputUsdValue.plus(tokenAmount)
		}

		return inputUsdValue
	}
