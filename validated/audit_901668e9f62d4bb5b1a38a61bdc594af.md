### Title
Bad-debt supply-index floor resurrects wiped suppliers' claims and drains pool cash - ([File: contracts/pool/src/interest.rs])

### Summary
When bad debt exceeds total supplied value, `apply_bad_debt_to_supply_index` computes a zeroed index but then clamps it upward to `SUPPLY_INDEX_FLOOR_RAW`. Existing supply shares therefore retain a positive withdrawal value even though the loss should have reduced them to zero. A permissionless `clean_bad_debt` call can reach this state, after which the holder of wiped supply shares can withdraw residual value and consume remaining or newly deposited pool cash.

### Finding Description
`Controller::clean_bad_debt` is permissionless and only requires caller authorization. [1](#0-0) 

Cleanup submits every remaining supply and borrow position to `pool_seize_positions`. [2](#0-1) 

For a borrow-side entry, the pool converts the scaled debt to a RAY-denominated bad-debt amount, applies it to the supply index, and burns the debt. [3](#0-2) 

`apply_bad_debt_to_supply_index` caps the loss at total supplied value and computes `remaining / total_supplied`, so a loss greater than or equal to all supplied value produces a zero reduction factor and a zero new index. [4](#0-3) 

The subsequent `.max(SUPPLY_INDEX_FLOOR_RAW)` raises that fully wiped index back to `RAY/1000`, preserving a positive claim for every preexisting scaled supply share. [5](#0-4) 

The pool does not burn those supplier shares during cleanup; deposit-side seizure merely reclassifies the liquidated account's shares as revenue, while unrelated suppliers keep their positions. [6](#0-5) [7](#0-6) 

### Impact Explanation
This is theft of user funds. A wiped supplier can withdraw value created solely by the floor clamp, taking pool cash that belongs to surviving suppliers or later depositors.

With a normalized index of `RAY`, the floor revives each wiped share at `0.1%` of its nominal share count. At sufficiently large supplied totals, that revived claim can withdraw a material fraction of the pool's remaining cash; after new deposits, it can consume the fresh backing as well. The in-repository test scenarios explicitly demonstrate that the floor leaves a positive stranded claim that can drain a fresh deposit when no additional supply guard intervenes. [8](#0-7) [9](#0-8) 

The same cleanup also reclassifies wiped collateral shares as revenue rather than reducing total supply, leaving additional floor-valued shares claimable through `claim_revenue`. [7](#0-6) [10](#0-9) 

### Likelihood Explanation
An unprivileged attacker can create the required state using only normal controller calls:

1. Supply the debt-market asset to acquire scaled supply shares.
2. Use a separate controlled account to borrow most of that cash.
3. Allow interest accrual to push the borrow-side obligation above total supplied value, or combine ordinary collateral depreciation with liquidation until the account has dust collateral and larger debt.
4. Call `clean_bad_debt(caller, account_id)` once `total_debt > total_collateral` and collateral is at or below the dust threshold.
5. Withdraw the attacker's still-existing supply shares, whose value is restored by the `RAY/1000` floor.

The admission gate is intentionally permissionless. [11](#0-10) [12](#0-11) 

### Recommendation
Do not clamp a fully socialized index upward after calculating the post-loss index.

At minimum:

- Track whether `remaining == 0`; in that case set `supply_index = 0`, or burn/cap all outstanding supply shares before applying the floor.
- Enforce a post-cleanup invariant that total floored supply value does not exceed cash plus collectible debt.
- Ensure deposit-side cleanup cannot leave floor-valued revenue shares whose value exceeds remaining backing.
- Add an end-to-end controller-to-pool test where bad debt exceeds total supplied value, then prove that wiped suppliers cannot withdraw revived value from remaining or fresh cash.

### Proof of Concept
Use `RAY = 10^27` and a floor of `RAY / 1000`.

1. Attacker calls `supply` and deposits `1_000_000` units of the borrowable asset, receiving approximately `1_000_000 * RAY` scaled supply shares.
2. A second attacker-controlled account supplies collateral and calls `borrow` for `990_000` units, leaving `10_000` units of cash.
3. Interest accrues until the open debt exceeds `1_000_000 * RAY` in value; ordinary collateral loss or liquidation reduces the borrower's collateral to at most the socialization dust threshold.
4. Attacker calls `clean_bad_debt(caller, borrower_account_id)`.
5. `execute_bad_debt_cleanup` sends the borrow position as `AccountPositionType::Borrow`; the pool computes `bad_debt >= supplied * supply_index`. [13](#0-12) 
6. `reduction_factor` becomes zero, but the index is written as `max(0, RAY / 1000)`. [14](#0-13) 
7. The attacker's unchanged `1_000_000 * RAY` supply shares now unscale to approximately `1_000` units despite the market loss having wiped supplier value to zero.
8. Attacker calls `withdraw` for the entire position and receives up to `1_000` units from cash that should be unavailable to the wiped claim; any later deposit provides additional withdrawable backing.

```rust
pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
```

```rust
/// Authorizes permissionless dust-gated cleanup outside flash loans.
pub(crate) fn process_clean_bad_debt(env: &Env, caller: &Address, account_id: u64) {
    caller.require_auth();
    validation::require_not_flash_loaning(env);
    clean_bad_debt_standalone(env, account_id);
}

/// Admission condition for bad-debt socialization.
#[derive(Clone, Copy, PartialEq)]
enum BadDebtGate {
    /// Permissionless: insolvent *and* collateral at or below the dust threshold.
    DustCapped,
    /// Owner-only: insolvent alone, with no cap on the collateral left behind.
    InsolventOnly,
}

/// Requires open debt and the selected insolvency gate, then cleans up the account.
fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    bad_debt::execute_bad_debt_cleanup(env, &mut cache, account_id, &account, &totals);
```
