### Title
`authorize_nonce_account` allows setting the nonce authority to `Pubkey::default()`, permanently bricking the nonce account and locking its funds - ([File: programs/system/src/system_instruction.rs])

### Summary
The system program's nonce-authorize instruction handler never validates that the new `nonce_authority` supplied to `AuthorizeNonceAccount` is a non-default `Pubkey`. A user (the current nonce authority) can accidentally (or be tricked into, e.g. by a buggy wallet/dApp default value) set the authority to `Pubkey::default()`, after which the nonce account can never again be advanced, re-authorized, or have its lamports withdrawn, because those operations all require a signature from the stored `authority`, and `Pubkey::default()` has no corresponding private key.

### Finding Description
`authorize_nonce_account()` only checks that the account is writable and that the current signer set satisfies `Versions::authorize`; it performs no validation on the `nonce_authority` value itself before storing it as the new authority: [1](#0-0) 

This is dispatched directly from the `SystemInstruction::AuthorizeNonceAccount` processor arm with no additional checks: [2](#0-1) 

The codebase's own unit test confirms this is accepted and results in the authority being stored as `Pubkey::default()` with no error: [3](#0-2) 

Once `data.authority == Pubkey::default()`, every subsequent privileged nonce operation fails permanently because they require `signers.contains(&data.authority)`:
- `advance_nonce_account` checks `signers.contains(&data.authority)` before advancing the durable nonce: [4](#0-3) 
- `authorize_nonce_account` itself requires the current authority to sign (`Versions::authorize`), so the authority can never be changed back either.
- Withdrawal of the nonce account's lamports (`withdraw_nonce_account`) likewise requires the initialized-state authority to sign.

Since no private key exists for `Pubkey::default()`, none of these instructions can ever succeed again for that account.

### Impact Explanation
This is the direct analog of the reported bug class ("setter doesn't check the new privileged value isn't the zero/default value, permanently losing the capability"). Here, the "privileged multisig" is the nonce account's `authority` field. Setting it to the default pubkey permanently and irrecoverably locks:
- The ability to advance the durable nonce (rendering the nonce account useless for its purpose).
- The ability to re-authorize to a valid key (the fix path is itself blocked).
- The ability to withdraw the account's lamports back out, since withdrawal requires the (now unsignable) authority.

This results in concrete, permanent loss of the lamports held in the nonce account with no recovery path — a real value-loss condition reachable by any ordinary, unprivileged user operating on their own nonce account (e.g., via a wallet bug, CLI misuse, or a malicious/buggy program constructing the instruction with an unvalidated authority argument), not a validator/operator-only scenario.

### Likelihood Explanation
Likelihood is user-error-driven rather than adversarial against a third party (the current authority must sign the `AuthorizeNonceAccount` instruction), so it's analogous in class and severity to the original M-07 finding: a plausible, low-effort mistake (e.g., a client library passing an uninitialized/default `Pubkey` for the new authority argument) with high, irreversible impact once triggered. There is no confirmation step or sanity check to prevent it.

### Recommendation
In `authorize_nonce_account()` (`programs/system/src/system_instruction.rs`), reject the instruction with `InstructionError::InvalidArgument` (or similar) if `*nonce_authority == Pubkey::default()`, mirroring the recommended fix of validating the new authority is non-zero before committing it to state.

### Proof of Concept
1. Initialize a nonce account with a valid authority `A` (owns some lamports).
2. `A` signs and submits `SystemInstruction::AuthorizeNonceAccount(Pubkey::default())` targeting the nonce account.
3. The instruction succeeds (as shown by `authorize_inx_ok` test at `programs/system/src/system_instruction.rs:1010-1038`), and `Versions::state().authority` becomes `Pubkey::default()`.
4. Any subsequent `AdvanceNonceAccount`, `AuthorizeNonceAccount`, or `WithdrawNonceAccount` instruction against this account fails with `MissingRequiredSignature`, because no signer can ever satisfy `signers.contains(&Pubkey::default())`.
5. The nonce account's lamports are now permanently locked in the account.
