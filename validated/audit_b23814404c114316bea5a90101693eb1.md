### Title
Missing Arbitrum sequencer uptime check in `SimplexPaymaster` Chainlink price consumption enables mispriced gas payments during sequencer outages - (File: evm/src/utils/SimplexPaymaster.sol)

### Summary
`SimplexPaymaster` prices ERC-20 gas payments using two Chainlink `AggregatorV3Interface` feeds (native/USD and token/USD) via `_getOraclePrice`, which only validates that the answer is positive and that `updatedAt` is within `maxOracleAge`. It never checks the L2 sequencer uptime status feed, which is the exact bug class described in the external report (TRST-M-3). Since the paymaster is a permissionless ERC-4337 component invoked on every UserOperation, an attacker can exploit price staleness that survives the timestamp check during/after an Arbitrum sequencer outage.

### Finding Description
`_getOraclePrice` is the sole gate on Chainlink data used for token pricing: [1](#0-0) 

This function is invoked from `_tokenPrice` (used by both the ERC-4337 validation path and `swapAndDeposit`): [2](#0-1) 

`AggregatorV3Interface` is declared as a minimal local interface with no sequencer-uptime companion feed and no call site anywhere checks one: [3](#0-2) 

A grep across the codebase for sequencer-uptime-related identifiers (`SequencerUptime`, `isSequencerUp`, `sequencerUptimeFeed`, `GRACE_PERIOD`) returned no matches, confirming this check is absent for every Chainlink consumer in the repo, including `SimplexPaymaster`.

When Arbitrum's sequencer goes down, the L1-batched Chainlink answer on L2 can appear to have a recent `updatedAt` (because the L2 block timestamp itself stalls or catches up in a burst once the sequencer resumes), while the underlying price is stale/incorrect relative to real market conditions during the outage window. The contract's only staleness defense (`block.timestamp - updatedAt > maxOracleAge`) does not detect this condition, exactly the scenario Chainlink's L2 Sequencer Uptime Feed docs warn about.

### Impact Explanation
`_getOraclePrice`/`_tokenPrice` set the exchange rate at which solvers' UserOperations pay for gas in USDC/USDT/etc. against the paymaster's markup logic (`_tokenPrice`, `estimateTokenCost`, `swapAndDeposit`). If the price feed is stale/incorrect during a sequencer outage:
- Solvers could pay artificially low token amounts for gas (undercharging), directly draining the paymaster's `treasury`-bound markup economics and enabling systematic underpayment across many UserOperations.
- `swapAndDeposit`, which is treasury-gated but still derives `amountOutMin` from `_getOraclePrice`, could execute swaps at a stale/incorrect price, causing the paymaster to receive less native asset than the true market rate, permanently leaking value from the contract that funds the `EntryPoint` deposit.

This is a Medium-severity issue: it enables mispriced value transfer from a shared, permissionless-facing contract, but requires the specific condition of an L2 sequencer outage to be exploitable, and the price deviation window is bounded and self-correcting once the sequencer resumes.

### Likelihood Explanation
Every UserOperation processed by the paymaster on Arbitrum during a sequencer downtime/restart window passes through `_getOraclePrice` with no additional protection. Sequencer outages, while infrequent, are a known and recurring operational risk for Arbitrum (and other L2 rollups this contract is deployed to, per `mainnet_rotation.rs`'s inclusion of chain id 42161). Any UserOperation sender (an unprivileged, permissionless actor) can trigger the vulnerable price read; no privileged role is required to reach it.

### Recommendation
Add an Arbitrum L2 Sequencer Uptime Feed check (`AggregatorV3Interface` pointed at Chainlink's dedicated sequencer-uptime aggregator) inside `_getOraclePrice`, reverting if `answer == 1` (sequencer down) or if less than a grace period has elapsed since `startedAt` of the last status change, before trusting `latestRoundData()` of the price feed. Apply this uniformly to every Chainlink consumption path in `SimplexPaymaster` (`_tokenPrice`, `swapAndDeposit`), and gate it per-chain (only enforced when deployed to an L2 with a published sequencer-uptime feed, e.g. Arbitrum).

### Proof of Concept
1. Deploy `SimplexPaymaster` on Arbitrum with `nativeOracle`/token oracles pointed at Chainlink ETH/USD and USDC/USD feeds, as done in `DeploySimplexPaymaster.s.sol`. [4](#0-3) 
2. Simulate an Arbitrum sequencer outage: the sequencer batch submission to L1 stalls, but once it resumes, previously-signed Chainlink round data is posted with an `updatedAt` timestamp that satisfies `block.timestamp - updatedAt <= maxOracleAge` despite reflecting stale off-chain market conditions from before/during the outage (this mirrors the exact scenario in `MockOracle`'s `setUpdatedAt`, showing the sole defense is timestamp-based freshness, easily satisfied by a batched update): [5](#0-4) 
3. Submit a UserOperation with `paymasterData` in PERMIT or PERMIT2 mode; `fetchDetails`/validation calls `_tokenPrice` → `_getOraclePrice`, computing gas cost off the stale price without any sequencer-uptime revert, allowing the solver to pay a mispriced (attacker-favorable) token amount for gas.     function _tokenPrice(TokenConfig memory cfg) internal view returns (uint256) {
        uint256 nativeUsd = _getOraclePrice(nativeOracle, nativeOracleDecimals);
        uint256 tokenUsd = _getOraclePrice(cfg.tokenOracle, cfg.tokenOracleDecimals);

        return (nativeUsd * (10 ** cfg.tokenDecimals) * (10_000 + markupBps)) / (tokenUsd * 10_000);
    }

    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }

        address nativeOracleAddr = config.get("NATIVE_ORACLE").toAddress();
        uint256 markupBps = vm.envOr("MARKUP_BPS", uint256(200)); // default 2%
        address treasury = vm.envOr("TREASURY", admin); // default to deployer
        // Stablecoin feeds on Ethereum and Base run a 24h heartbeat; a buffer over
        // 24h avoids transient StaleOraclePrice reverts on late pushes.
        uint256 maxOracleAge = vm.envOr("MAX_ORACLE_AGE", uint256(90_000));
        uint256 swapSlippageBps = vm.envOr("SWAP_SLIPPAGE_BPS", uint256(200)); // default 2%
        address relayer = vm.envAddress("GOVERNANCE_RELAYER");
        require(relayer != address(0), "GOVERNANCE_RELAYER is unset");

        bool hasUsdt = config.exists("USDT_TOKEN") && config.exists("USDT_ORACLE");
        uint256 tokenCount = hasUsdt ? 2 : 1;
        address[] memory tokens = new address[](tokenCount);
        AggregatorV3Interface[] memory oracles = new AggregatorV3Interface[](tokenCount);
        tokens[0] = config.get("USDC_TOKEN").toAddress();
        oracles[0] = AggregatorV3Interface(config.get("USDC_ORACLE").toAddress());
        if (hasUsdt) {
            tokens[1] = config.get("USDT_TOKEN").toAddress();
            oracles[1] = AggregatorV3Interface(config.get("USDT_ORACLE").toAddress());
        }

        SimplexPaymaster implementation = new SimplexPaymaster{salt: salt}();
        bytes memory initData = abi.encodeCall(
            SimplexPaymaster.initialize,
            (
                HOST_ADDRESS,
                SimplexPaymaster.Params({
                    nativeOracle: AggregatorV3Interface(nativeOracleAddr),
                    markupBps: markupBps,
