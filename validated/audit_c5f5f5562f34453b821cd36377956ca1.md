## Analysis: Griefing via forced eviction of prepaid bandwidth (pallet-bandwidth)

This is a valid analog. The reported bug class — an **unprivileged caller processing a shared queue that belongs to another party, forcing them to lose value they already paid for with no compensation** — maps directly onto `pallet-bandwidth`'s FIFO subscription list, reachable by anyone calling `purchase()` on `BandwidthManager.sol`.

### Title
Unprivileged bandwidth purchases can grief any `(chain, app)` subscription queue, permanently destroying another party's prepaid bandwidth via forced FIFO eviction - (File: `modules/pallets/bandwidth/src/lib.rs`)

### Summary
`BandwidthManager.purchase()` is fully permissionless and lets the caller name *any* `app` on *any* `chain` as the beneficiary of the credit [1](#0-0) . This is intentional to support cross-chain sponsorship [2](#0-1) . On the Hyperbridge side, each purchase unconditionally appends to a FIFO `SubscriptionList` capped at 1024 entries per `(chain, app)`; once at capacity, the *oldest* subscription is evicted and its unused `remaining_bytes` are permanently lost, with no refund to whoever paid for it [3](#0-2) .

### Finding Description
`purchase()` performs no authorization check tying `app`/`chain` to `msg.sender` — it only validates non-empty fields, non-zero `months`, and a configured tier price [4](#0-3) . `on_accept` in the pallet mirrors this: it authenticates the dispatch came from a registered `BandwidthManager` contract, but never checks who the underlying purchaser is or whether they have any relationship to the targeted `(app_chain, app)` [5](#0-4) .

Every accepted purchase calls `push_subscription`, which is the queue-mutation analog of `mintRollovers`: if the `(chain, app)` list is already at `MAX_SUBSCRIPTIONS` (1024), the *oldest* entry is silently removed regardless of how much `remaining_bytes` (i.e., already-paid-for, unconsumed value) it still holds [6](#0-5) . The only trace left is an audit event, `SubscriptionEvicted`, carrying the `lost_bytes` — there is no mechanism to refund or preserve that value [7](#0-6) .

Because any address on any registered source chain can dispatch a purchase for any target `(chain, app)` pair, an attacker can:
1. Identify an `(app_chain, app)` whose subscription list is at or near the 1024 cap (e.g., an app that receives frequent sponsorships or steady top-ups from third parties, matching the "rollover queue" pattern where many independent parties' positions sit in one shared structure).
2. Submit cheap tier-one purchases (`purchase(app, tier=1, months=1, chain)`) targeting that app, each one evicting the current oldest entry.
3. Repeat until the entry with the largest unconsumed `remaining_bytes` — potentially a multi-month purchase that a legitimate sponsor paid significant fees for — is pushed out and destroyed with zero compensation to whoever originally paid for it.

This is structurally identical to the reported Y2K Carousel issue: an unprivileged caller processes a shared, FIFO position queue in a way that forces another user's still-valuable, already-paid-for position out of the structure without giving them their entitled value, and the attacker gains nothing financially from doing so — it is pure griefing.

### Impact Explanation
The victim (whoever paid for the evicted subscription, whether the app itself or a sponsor) permanently loses `remaining_bytes` worth of bandwidth they already paid the manager contract in fee tokens for [4](#0-3) . Since bandwidth purchases are non-refundable and the eviction is irreversible, this constitutes a permanent, unrecoverable loss of prepaid value with no way for the victim to prevent or reverse it once their entry becomes the FIFO head under attack. If the affected app depends on that bandwidth allowance to keep dispatching messages (the gate rejects messages once allowance is exhausted [8](#0-7) ), the griefing can also cause a denial of service for that app's cross-chain messaging.

### Likelihood Explanation
The attack requires only calling a fully public function (`purchase()`) with attacker-chosen `app`/`chain` arguments and paying the cheapest configured tier price per eviction — no privileged role, no race against relayers, and no dependence on any other actor's mistake. The cost scales with how many entries must be evicted to reach the target subscription, and is cheapest when a queue is already near its 1024 cap (e.g., apps that receive many small third-party sponsorship top-ups), which is a realistic and encouraged usage pattern given the sponsorship model.

### Recommendation
- Restrict `push_subscription`'s eviction so that only subscriptions whose `remaining_bytes` are below a de-minimis threshold, or entries near expiry, are eligible for eviction — never the entry with the largest remaining value.
- Alternatively, track purchases per-payer (or per app-authorized sponsor) so that eviction only affects entries funded by the same address/relationship pushing new purchases, preventing a completely unrelated third party from forcing another payer's subscription out.
- Consider refunding (in fee token, cross-chain) the pro-rated unused value of an evicted subscription to whoever paid for it, mirroring the `entitledShares` mitigation pattern from the original report — credit the victim before destroying their position.
- At minimum, raise `MAX_SUBSCRIPTIONS` substantially or make it configurable per-app so griefing an established app is not cheaply achievable, and add monitoring/alerting on `SubscriptionEvicted` with non-trivial `lost_bytes`.

### Proof of Concept
1. Governance registers a `BandwidthManager` for source chain `EVM-8453` and configures `TierOne` with a small, cheap price [9](#0-8) .
2. A legitimate sponsor purchases a large multi-month `TierFour` subscription for `app = victimApp`, `chain = "EVM-1"`, crediting a subscription with large `remaining_bytes` and a long `expires_at` [10](#0-9) .
3. Over time (or via automation), the `(EVM-1, victimApp)` FIFO list fills to 1024 entries through ordinary usage/top-ups from various sponsors.
4. Attacker repeatedly calls `BandwidthManager.purchase(app=victimApp, tier=TierOne, months=1, chain="EVM-1")` from `EVM-8453`, each paying only the cheap tier-one price. Each call triggers `push_subscription`, which evicts the current FIFO head [6](#0-5) .
5. Once the legitimate sponsor's large `TierFour` subscription becomes the FIFO head, the attacker's next cheap purchase evicts it, emitting `SubscriptionEvicted { lost_bytes: <large amount> }` [7](#0-6) .
6. The sponsor/victim has irrecoverably lost the paid-for, unconsumed bandwidth; the attacker spent only cheap tier-one fees and gains nothing financially, matching the "griefing, no attacker profit" profile of the referenced report.

## Sponsorship

The purchase message carries its own `chain` (the _credit chain_) which is **independent of the source chain** that sent the message. This means a buyer on Ethereum can credit an app on Base by dispatching a purchase whose payload sets `chain = "EVM-8453"`.

The pallet keys allowance storage by `(app_chain, app)` taken from the message body, not by `request.source`. The event `BandwidthCredited` carries both — `app_chain` (where the credit lands) and `paid_from` (where the payment came from) — so the cross-chain payer is auditable.

This is what makes the system multi-tenant friendly: a treasury on a single chain can sponsor bandwidth for an app deployed across many chains, without having to deploy `BandwidthManager` on each chain the app lives on.

		/// Append a fresh subscription with a fixed expiry. If the list
		/// is already at `MaxSubscriptions`, evict the oldest entry and
		/// emit [`Event::SubscriptionEvicted`] so the lost bytes are
		/// auditable. Returns the new subscription's `expires_at`.
		fn push_subscription(
			app_chain: &StateMachine,
			app: &AppKey,
			tier: TierIndex,
			bytes: BandwidthBytes,
			duration_secs: u64,
		) -> u64 {
			let now = <T as pallet_ismp::Config>::TimestampProvider::now().as_secs();
			let expires_at = now.saturating_add(duration_secs);
			let new_sub =
				Subscription { tier, remaining_bytes: bytes, expires_at, purchased_at: now };

			let evicted = Allowance::<T>::mutate(app_chain, app, |list| {
				let evicted = if list.len() == MAX_SUBSCRIPTIONS as usize {
					Some(list.remove(0))
				} else {
					None
				};
				// Capacity is now guaranteed; try_push can't fail.
				let _ = list.try_push(new_sub);
				evicted
			});

			if let Some(old) = evicted {
				Self::deposit_event(Event::SubscriptionEvicted {
					app_chain: *app_chain,
					app: app.clone(),
					tier: old.tier,
					lost_bytes: old.remaining_bytes,
				});
			}

			expires_at
		}

		fn on_accept(&self, request: PostRequest) -> Result<Weight, anyhow::Error> {
			let manager = BandwidthManager::<T>::get(&request.source).ok_or_else(|| {
				anyhow::anyhow!(format!("no bandwidth manager registered for {:?}", request.source))
			})?;

			if request.from != manager.0.to_vec() {
				return Err(anyhow::anyhow!(format!(
					"purchase from unauthorised sender on {:?}: expected {:x?}, got {:x?}",
					request.source, manager.0, request.from
				)));
			}

			let msg = PurchaseMessage::try_from(request.body.as_slice())?;
			let tier = TierIndex::try_from(msg.tier)
				.map_err(|_| anyhow::anyhow!(format!("unknown tier discriminant {}", msg.tier)))?;
			let cfg = Tiers::<T>::get(tier)
				.ok_or_else(|| anyhow::anyhow!(format!("tier {:?} is not configured", tier)))?;

			let bytes = cfg.bytes.saturating_mul(msg.months as u128);
			let duration = cfg.duration_secs.saturating_mul(msg.months as u64);

			let key = AppKey::truncate_from(msg.app);
			let expires_at = Self::push_subscription(&msg.chain, &key, tier, bytes, duration);

			Self::deposit_event(Event::BandwidthCredited {
				app_chain: msg.chain,
				app: key,
				paid_from: request.source,
				tier,
				bytes,
				expires_at,
			});

			Ok(Weight::zero())
		}

impl<T: Config> BandwidthGate for Pallet<T> {
	fn try_consume(
		source: &ismp::host::StateMachine,
		app: &[u8],
		bytes: u32,
	) -> Result<(), GateError> {
		let key = AppKey::truncate_from(app.to_vec());
		if Allowlist::<T>::contains_key(source, &key) {
			return Ok(());
		}

		let need: u128 = bytes.into();
		let now = <T as pallet_ismp::Config>::TimestampProvider::now().as_secs();

		let total = pallet::Allowance::<T>::mutate(source, &key, |list| {
			// Sweep expired in-place. Order-preserving.
			list.retain(|s| s.expires_at > now);

			if list.is_empty() {
				return Err(GateError::NoAllowance);
			}

			let total: u128 = list.iter().map(|s| s.remaining_bytes).sum();
			if total < need {
				return Err(GateError::Insufficient { remaining: total, required: need });
			}

			// Drain from the front in insertion order. Once a sub is
			// fully consumed, pop it and continue with the next.
			// `get_mut` defends against a malformed list that satisfies
			// the `total >= need` precheck but is structurally empty;
			// we'd otherwise panic via `list[0]`.
			let mut left = need;
			while left > 0 {
				let Some(head) = list.get_mut(0) else {
					return Err(GateError::NoAllowance);
				};
				let take = head.remaining_bytes.min(left);
				head.remaining_bytes = head.remaining_bytes.saturating_sub(take);
				left = left.saturating_sub(take);
				if head.remaining_bytes == 0 {
					list.remove(0);
				}
			}

			Ok(total)
		})?;

		Self::deposit_event(Event::BandwidthConsumed {
			source: *source,
			app: key,
			bytes: need,
			remaining: total - need,
		});
		Ok(())
	}
