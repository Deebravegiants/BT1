### Title
Missing ownership check in `PipelineRunsController.Show` allows any authenticated node user to read any other job's run data by run ID - (File: core/web/pipeline_runs_controller.go)

### Summary
The reported Sublime bug is a missing-access-control pattern where a function takes a beneficiary identifier (`_lender`) supplied by the caller and performs a privileged/sensitive action on that identifier's behalf without checking that the caller is authorized for it. The closest reachable analog in the chainlink repo is `PipelineRunsController.Show`, which accepts a `runID` path parameter and returns the full run resource without verifying that the run belongs to the `:ID` job in the URL, or restricting the query to runs that the requester is permitted to see.

### Finding Description
`Show` looks up a pipeline run purely by `runID`, ignoring the `:ID` (job) path segment entirely: [1](#0-0) 

```go
func (prc *PipelineRunsController) Show(c *gin.Context) {
	...
	err := pipelineRun.SetID(c.Param("runID"))
	...
	pipelineRun, err = prc.App.PipelineORM().FindRun(ctx, pipelineRun.ID)
	...
	res := presenters.NewPipelineRunResource(pipelineRun, prc.App.GetLogger())
	jsonAPIResponse(c, res, "pipelineRun")
}
```

The route is registered as `GET /jobs/:ID/runs/:runID` under the generic `authv2` group with no per-route role check (unlike sibling routes that use `auth.RequiresRunRole`/`auth.RequiresEditRole`/`auth.RequiresAdminRole`): [2](#0-1) 

Because `FindRun` is keyed only by `runID` (an incrementing integer, per `pipelineRun.SetID`), any authenticated node account—including a "Run"-role-only actor—can enumerate `runID` values across any `jobID` prefix and retrieve run details (including task outputs / observation data) for jobs it does not own or was not granted access to, analogous to the Sublime bug where an unrelated actor could act on/read state tied to an unrelated principal (`_lender`) without an ownership check.

### Impact Explanation
This is a cross-user response confusion / authorization bypass: pipeline run resources can contain internal task outputs, request/response payloads, or job-specific data intended for the job owner only. Any authenticated account (not necessarily an admin) able to reach this endpoint can read other jobs' run history by iterating `runID`, which is not scoped to a per-user/job namespace and is not re-validated against the job identified in the path.

### Likelihood Explanation
`runID` is a simple database-sequential ID; the endpoint is reachable by any of the standard authenticated middleware chains (`AuthenticateByToken`, `AuthenticateBySession`) applied to the whole `authv2` group, and there is no additional role/ownership gate on `Show` itself, unlike neighboring routes. Exploitation only requires a valid low-privilege session/API token and iterating small integers, making this a low-effort, reliable read-path issue.

### Recommendation
In `PipelineRunsController.Show`, validate that the fetched run's `PipelineSpecID`/associated job matches the `:ID` job parameter from the path, and/or that the authenticated user has authorization for that specific job, before returning the resource — mirroring the fix pattern from the referenced report (require the actor to be authorized for the target entity, not just any authenticated caller).

### Proof of Concept
1. As a low-privilege authenticated user (any valid API token/session), call `GET /v2/jobs/1/runs/5` where job `1` does not belong to the caller but run id `5` does exist for a different job.
2. Observe that `Show` returns the full `pipelineRun` resource for run `5` regardless of whether it belongs to job `1` or any job the caller is entitled to view, because `FindRun` is only keyed by `runID` and no ownership check ties it back to the caller or the job in the path.
3. Iterate small integers for `runID` to enumerate and read other jobs' run outputs.

func (prc *PipelineRunsController) Show(c *gin.Context) {
	ctx := c.Request.Context()
	pipelineRun := pipeline.Run{}
	err := pipelineRun.SetID(c.Param("runID"))
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	pipelineRun, err = prc.App.PipelineORM().FindRun(ctx, pipelineRun.ID)
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	res := presenters.NewPipelineRunResource(pipelineRun, prc.App.GetLogger())
	jsonAPIResponse(c, res, "pipelineRun")
}
