### Title
Simplex FXFiller prices intent-order legs from a single-block Uniswap V4 spot price (`sqrtPriceX96`), letting a flash-loan-manipulated pool drain filler funds via a normal intent order - ([File: sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts])

### Summary
`UniswapV4FundingPlanner.getExoticTokenPrice` / `computeDirectPoolPriceUsd` values an "exotic" token purely from the current tick/`sqrtPriceX96` of a Uniswap V4 pool (via `state.refresh()` → `getSlot0`), the same class of oracle bug as the reported `USSDRebalancer.getOwnValuation`, which read `uniPool.slot0()` directly and was flash-loan manipulable. [1](#0-0) [2](#0-1) 

### Finding Description
`getExoticTokenPrice` refreshes on-demand pool state and then computes the USD mid price directly from `sdkPool.token0Price`/`token1Price`, which are derived from the pool's current `sqrtPriceX96`, not a time-weighted average: [3](#0-2) [4](#0-3) 

This spot price feeds `FXFiller.getVenueUsdPrice` → `resolveLegRates`/`referenceRate`, which convert it into the exchange rate the filler actually uses to price and fill an intent order leg (`rate = 1 / venueUsd`), and it also drives `sizeOrder`'s per-pair notional sizing used for confirmation depth: [5](#0-4) [6](#0-5) [7](#0-6) 

The only defense is `checkPriceGuard`, which compares the venue quote against a **static, operator-configured `referencePrice`** within `maxDeviationBps`. This guard is explicitly optional/per-chain and unenforced by default: `referencePrice`/`maxDeviationBps` must be set together and, per the project's own documentation, "omit both to leave the chain unguarded." Even when configured, it only bounds deviation from a fixed reference, not sudden intra-block manipulation, and its width (e.g. 200 bps = 2% in the shipped example config) can still leave large room for a flash-loan-sized single-block price swing: [8](#0-7) [9](#0-8) 
Docs confirm the design intent and its known weakness: "Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote... The two fields must be set together; omit both to leave the chain unguarded."

### Impact Explanation
An attacker who flash-loan-manipulates the configured Uniswap V4 pool (the pool paired with USDC/USDT that backs a curve-less trading pair) within the same block/transaction as submitting an intent order can shift `computeDirectPoolPriceUsd`'s output arbitrarily within the pool's liquidity depth. If no `referencePrice`/`maxDeviationBps` guard is configured for that chain (an accepted, documented configuration), the filler will price and fill the intent order leg entirely at the manipulated rate, causing the solver to hand out more of the exotic/stable token than the fair market value — direct theft of solver (filler) funds through a single, unprivileged intent order submission. Even with a guard configured, the static reference/percentage band bounds but does not eliminate the exposure to a same-block manipulation that stays inside the configured tolerance. This is a concrete funds-loss vector reachable by any user who can submit an intent order and manipulate the referenced pool (e.g. via a flash loan), matching the "intent solver bid price valuation" analog class explicitly in scope.

### Likelihood Explanation
Likelihood is Medium-to-High for deployments that run curve-less, venue-priced pairs without configuring `referencePrice`/`maxDeviationBps` (the guard is optional by design, and the docs walk through configuring it as an add-on, implying default deployments can omit it). The pool used is picked by "most liquidity," but Uniswap V4 pools for exotic/stable pairs (e.g. cNGN/USDC) can still have shallow enough liquidity relative to a flash-loan attacker's available capital to move the tick meaningfully within a single transaction. The attack requires only a standard flash loan plus a normal intent-order submission — no privileged access, no compromised keys, no governance action.

### Recommendation
- Do not treat the raw pool `sqrtPriceX96`/current tick as ground truth for solver pricing. Use a TWAP (Uniswap V3/V4 `observe`) over a meaningful window, or cross-check the spot price against an external oracle before pricing any leg.
- Make the price guard (`referencePrice`/`maxDeviationBps`) mandatory for every venue-priced (curve-less) pair rather than optional, and reject startup configuration that leaves a chain "unguarded" as `pricing.mdx` currently documents.
- Consider adding same-block/reentrancy protections (e.g., comparing spot price against the previous block's observed price) so a price that moved implausibly within one block is rejected outright, independent of the static reference band.

### Proof of Concept
Conceptual attack path (no PoC harness available in the indexed sources, but fully supported by the code paths cited above):
1. Operator configures a curve-less pair (e.g. `USDC/CNGN`) backed by `[vault.uniswapV4]` with **no** `referencePrice`/`maxDeviationBps` (a documented, allowed configuration) — [10](#0-9) .
2. Attacker takes a flash loan and swaps heavily against the configured V4 pool, shifting `sqrtPriceX96`/tick far from the fair market price in the same transaction.
3. Attacker (or a colluding account) immediately submits/bids on an intent order matching that pair.
4. `FXFiller.calculateProfitability` → `resolveLegRates` → `getVenueUsdPrice` → `UniswapV4FundingPlanner.getExoticTokenPrice` reads the manipulated `slot0`/tick and returns the skewed price — [1](#0-0) .
5. `computeLegPolicyOutput` prices the fill at this skewed rate with no guard rejecting it, and the filler executes the withdrawal/fill, transferring tokens at the manipulated rate — [11](#0-10) .
6. Attacker reverses the flash-loan swap, restoring the pool price and pocketing the difference extracted from the filler.

	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}

	private computeDirectPoolPriceUsd(
		pos: HydratedV4Position,
		sdkPool: V4Pool,
		chain: string,
	): { exoticToken: string; priceUsd: Decimal } | null {
		const usdc = this.configService.getUsdcAsset(chain).toLowerCase()
		const usdt = this.configService.getUsdtAsset(chain).toLowerCase()
		const c0 = pos.currency0.toLowerCase()
		const c1 = pos.currency1.toLowerCase()

		if (c0 === usdc || c0 === usdt) {
			// currency0 is stable → exotic is currency1
			// token1Price = "token0 per token1" = USD per exotic
			return {
				exoticToken: c1,
				priceUsd: new Decimal(sdkPool.token1Price.toFixed(18)),
			}
		}

		if (c1 === usdc || c1 === usdt) {
			// currency1 is stable → exotic is currency0
			// token0Price = "token1 per token0" = USD per exotic
			return {
				exoticToken: c0,
				priceUsd: new Decimal(sdkPool.token0Price.toFixed(18)),
			}
		}

		return null
	}

	/**
	 * Queries funding venues for `token1Address`'s USD price on a chain.
	 * Uniswap V4 is preferred; falls back to other venues. Returns null when no
	 * venue can price the token there.
	 */
	private async getVenueUsdPrice(chain: string, token1Address: string): Promise<Decimal | null> {
		if (this.fundingVenues.length === 0) return null

		// Prefer V4, fall back to others
		const v4 = this.fundingVenues.filter((v) => v.name === "UniswapV4")
		const venues = v4.length > 0 ? v4 : this.fundingVenues

		for (const venue of venues) {
			const usdPrice = await venue.getExoticTokenPrice(chain, token1Address)
			if (usdPrice?.isPositive()) return usdPrice
		}
		return null
	}

	/** Per-evaluation memo over `getVenueUsdPrice`, keyed by (chain, token1). */
	private venuePriceMemo(): (chain: string, token1Address: string) => Promise<Decimal | null> {
		const cache = new Map<string, Decimal | null>()
		return async (chain: string, token1Address: string) => {
			const key = `${chain}:${token1Address}`
			const cached = cache.get(key)
			if (cached !== undefined) return cached
			const price = await this.getVenueUsdPrice(chain, token1Address)
			cache.set(key, price)
			return price
		}
	}

	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {
			this.logger.warn(
				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
	}

	private async referenceRate(
		leg: ResolvedLeg,
		venueUsdPrice: (chain: string, token1Address: string) => Promise<Decimal | null>,
	): Promise<Decimal | null> {
		const policy = leg.pair.bidPricePolicy ?? leg.pair.askPricePolicy
		if (policy) {
			const rate = policy.getPrice(new Decimal(0))
			return rate.gt(0) ? rate : null
		}
		// Venue-priced pair: token0 is USD-stable (constructor invariant), so the
		// venue's USD-per-token1 quote inverts straight into token1-per-token0.
		const venueUsd = await venueUsdPrice(leg.token1Chain, leg.token1Address)
		if (!venueUsd) return null
		const venueRate = new Decimal(1).div(venueUsd)
		// Same guard as trade pricing: this rate sizes the order's USD notional
		// for confirmation depth, and a manipulated pool understating the value
		// would shrink the reorg protection — the exact attack the guard exists
		// to stop. Refusing to size skips the order, consistent with pricing.
		if (!this.checkPriceGuard(undefined, leg.token1Chain, venueRate)) return null
		return venueRate
	}

				// the venue-specific defense.

				return { rate: venueRate, oppositeRate: null, priceSource: "venue" }

# Venue pricing (Uniswap V4 funded pairs)

Verified 2026-08-19.

```
resolveLegRates(...)
  curveless pair && token0 is a USD stable
    -> venuePriceMemo() -> getVenueUsdPrice(chain, token1)
         -> UniswapV4FundingPlanner.getExoticTokenPrice
              picks the position with the largest pool liquidity
              -> computeDirectPoolPriceUsd -> sdkPool.token0Price / token1Price
    -> checkPriceGuard(...)   reject if outside maxDeviationBps of the static reference
    -> rate = 1 / venueUsd
  otherwise -> the pair's ask/bid curve at the leg's notional
```

`computeDirectPoolPriceUsd` returns the **raw pool mid** derived from `sqrtPriceX96`. The pool's
fee tier is read and stored on the hydrated position (`pos.fee`) but never applied to the price,
and there is no size or impact term — `computeLegPolicyOutput` extends the mid linearly across the
whole priced quantity. `checkPriceGuard` is the only defense on this path, and it checks deviation
from a static reference, not execution cost. A venue-priced pair that has to swap through its own
pool to source inventory pays a fee tier it never quoted against.
