### Title
Whale-position accrual overflows `i128` in `scaled_to_original` before the borrow-index cap engages, permanently freezing all exits on a market - (File: common/src/rates/simulate.rs)

### Summary
An analog of CVE-2024-57635 (crafted input drives the component into an unrecoverable crash) exists in the interest-accrual path. `accrue_step` computes `scaled_to_original(borrowed, borrow_index)` and `scaled_to_original(supplied, supply_index)` on every market mutation (`common/src/rates/simulate.rs:60-61`). The product `scaled_amount × index` can overflow `i128` while `borrow_index` is still far below `MAX_BORROW_INDEX_RAY`, because `update_borrow_index` clamps *after* the multiply and the clamp bound only guards the index, not the index × scaled-amount product (`common/src/rates/index.rs:13-19`). Once any market reaches that state, every entrypoint that loads the market — `withdraw`, `repay`, `borrow`, `supply`, `seize_positions` (liquidation and bad-debt cleanup), `claim_revenue`, `update_indexes` — accrues first via `interest::global_sync` (`contracts/pool/README.md` flow: `Cache::load → interest::global_sync → mutate → guards → commit`) and panics with `MathOverflow` forever. The index cap that was meant to bound growth never gets a chance to run.

### Finding Description
The repo's own regression test demonstrates the cliff: `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` (`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:316-361`) drives a ~10²⁷-unit market on the steep curve at 98% utilization until `update_indexes` fails with `MATH_OVERFLOW`, then asserts the panic is sticky — `try_withdraw_raw` and `try_repay` both revert with the same error, and `last.borrow_index < MAX_BORROW_INDEX_RAY`, i.e. the safety cap never engaged. The panic site is the pre-cap unscaling inside `accrue_step`, not the capped index update itself. Nothing in the accrual loop checks `scaled × index` against `i128::MAX` before multiplying; the certora spec acknowledges this boundary by pruning the panic path with an assumption (`certora/common/spec/rates_rules.rs:316-320`).

### Impact Explanation
Permanent freezing of user funds and a market unable to operate: once the overflow state is reached, no user can withdraw supplied tokens, no borrower can repay, no liquidator can seize (liquidation also accrues first), and `recapitalize`/`update_indexes` fail identically since they share `ops::synced_market`/`renewed_market`. All cash held in that market's book is frozen permanently; outstanding debt can never be collected, so the market is also functionally insolvent. There is no rescue path in the in-scope entrypoints — only a contract upgrade would unstick it.

### Likelihood Explanation
Reachable by unprivileged addresses through `controller.supply` and `controller.borrow`: an attacker opens a whale-sized position and leaves it at high utilization. Debt compounds faster than supply, so an untouched book drifts upward in utilization on its own (file header notes ~10 years to runaway on the XLM-shaped curve). Constraints that reduce likelihood: it requires a high-decimal or very high-cap market (the PoC lifts spoke caps to `max_cap_for_decimals(18)` and uses a 175% `max_borrow_rate` curve — both governance-validated but governance-chosen parameters), a large real token position, and years of elapsed accrual before the cliff is hit, none of which a single transaction can shortcut.

### Recommendation
Bound the product, not just the index: before `scaled_to_original` in `accrue_step`, saturate `borrow_index`/`supply_index` (or the returned original amount) so `scaled × index` stays inside `i128`; alternatively clamp accrual when `borrowed`/`supplied` scaled amounts exceed `i128::MAX / MAX_BORROW_INDEX_RAY`. A defensive option is to cap `borrow_index` earlier — at `min(MAX_BORROW_INDEX_RAY, i128::MAX / max(scaled))` — so the cap engages before the unscale overflows rather than after.

### Proof of Concept
`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-360`:
1. `supply_raw(BOB, "BIG18", 1e9 × 10¹⁸)` then `borrow_raw(ALICE, "BIG18", 98% of it)` on an 18-decimal market with the steep curve.
2. Advance time in 1-year steps calling `update_indexes`; within the tested window it fails with `MATH_OVERFLOW` while `borrow_index < MAX_BORROW_INDEX_RAY`.
3. `try_withdraw_raw(BOB, "BIG18", 1)` and `try_repay(ALICE, "BIG18", 1.0)` both revert with `MATH_OVERFLOW` — the freeze is permanent. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3)

```rust
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}
```

```rust
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
