### Title
Permanent market freeze: borrow-index growth overflows the i128 RAY value domain before the index cap engages, bricking every accrue-first entrypoint — ([File: contracts/pool/src/interest.rs])

### Summary
The MySQL CVE class is a remotely triggered complete denial of service — the service hangs and never recovers. The on-chain analog is an unrecoverable panic inside interest accrual: on a large, high-utilization market, `scaled_to_original(scaled, index)` overflows the i128 RAY value domain before `MAX_BORROW_INDEX_RAY` caps the index. Because `global_sync` accrues before every state-changing verb, the market permanently reverts on withdraw, repay, borrow, liquidate, and `update_indexes` — all funds in that book are frozen forever. [1](#0-0) 

### Finding Description
`global_sync` runs accrued interest in chunked compound steps via `accrue_chunk`/`accrue_step`, and is invoked at the head of every pool operation. The scaled-share engine stores supply and debt as RAY-scaled shares; unscaling multiplies by the live index, so the representable value domain is `i128::MAX / index`. The harness test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` demonstrates that at sustained ~98% utilization on the steep segment of an XLM-style curve, the borrow index grows past ~170x and the next accrual panics in `scaled_to_original` with `MATH_OVERFLOW` — while `borrow_index < MAX_BORROW_INDEX_RAY`, i.e., the designed index ceiling never engages. After that point `try_withdraw_raw`, `try_repay`, and `try_update_indexes_for` all revert with `MATH_OVERFLOW`. [2](#0-1) [3](#0-2) 

Reachable path for a single unprivileged address:

1. `supply(hub, whale_asset, huge_amount)` and `supply(hub, collateral_asset, huge_amount)` — permissionless, only bounded by governance caps.
2. `borrow(hub, whale_asset, ~98% of book)` — drives utilization onto the steep rate segment.
3. Wait (or simply let the position sit); each subsequent `update_indexes` compounds the index. No further attacker action is needed — the freeze is self-inflicted by accrual arithmetic.
4. Once the cliff is crossed, every user's supply and debt in that book is unrecoverable: liquidation, repayment, withdrawal, and even `recapitalize` (which reads scaled state) hit the same panic.

The codebase's own documentation acknowledges the cliff exists but the test explicitly asserts the documented 40-year bound in `docs/reference/formulas.md` is wrong — the cliff arrives earlier than documented, so cap tuning based on the published bound does not prevent it. [4](#0-3) 

### Impact Explanation
Permanent freezing of funds: once `accrue_chunk` panics, the book's `last_timestamp` can never advance, so every entrypoint that accrues first — `withdraw`, `repay`, `borrow`, `liquidate`, `clean_bad_debt`, `update_indexes` — reverts unconditionally. All supplier principal and all collateral backing debt in that (hub, token) book is locked forever; there is no admin recovery path that skips accrual. This matches the CVE's "complete DOS" class with the worst in-scope impact category.

### Likelihood Explanation
Medium. The trigger requires a very large principal (the PoC uses ~10^27 raw units on an 18-decimal asset) and sustained near-100% utilization over multiple years, so it is capital-bound rather than free. However: (a) it needs only one unprivileged address executing ordinary `supply`/`borrow` calls, (b) high-decimal low-price tokens make the raw-unit threshold economically cheap, (c) `borrow` on a steep utilization curve is exactly what rational borrowers do, so organic flow can finish the job an attacker starts, and (d) the index grows monotonically — once seeded, the freeze is inevitable absent governance rescue, which itself cannot act on a frozen book.

### Recommendation
- Enforce the `MAX_BORROW_INDEX_RAY` cap *before* the value-domain cliff: in `accrue_step`, clamp the new index first, and additionally bound `scaled * index` products (e.g., checked-mul returning a saturated/capped value rather than panicking) in `scaled_to_original`.
- Add a solvency-style guard: derive the maximum safe scaled total as `i128::MAX / MAX_BORROW_INDEX_RAY` and reject `supply`/`borrow` that would push the book's scaled totals past it, making the cap a hard admission bound rather than a monitoring concern.
- Fix the incorrect bound in `docs/reference/formulas.md` so cap-setting runbooks reflect the real cliff distance measured by the harness test.

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

```rust
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
```
