### Title
Uniswap V4 venue pricing in Simplex has no size/impact term and only a static-reference deviation guard, letting an attacker manipulate the spot pool price to extract value from a solver's fill - (File: sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts)

### Summary
The Ethereum Foundation report describes an MEV bot sandwiching a large Uniswap V3 sale, profiting from short-lived spot-price manipulation around a trade because the trade priced itself off the pool's instantaneous state rather than a manipulation-resistant reference. The analogous weakness exists in Hyperbridge's reference solver (Simplex): when a cross-chain intent-gateway pair has no static bid/ask curve, its price is derived directly from a Uniswap V4 pool's current `sqrtPriceX96` with no size/impact term and no TWAP, and the only defense is a static `referencePrice`/`maxDeviationBps` guard that bounds deviation, not execution cost.

### Finding Description
`UniswapV4FundingPlanner.getExoticTokenPrice` selects the most-liquid position for a token and calls `computeDirectPoolPriceUsd`, which returns the pool's **raw mid price** computed from `sdkPool.token0Price`/`token1Price` (derived from the pool's current `sqrtPriceX96`) with no adjustment for trade size or the pool's fee tier: [1](#0-0) [2](#0-1) 

As documented directly in the codebase's own flow notes: `computeDirectPoolPriceUsd` returns the raw pool mid derived from `sqrtPriceX96`; the pool's fee tier is read but never applied to the price, there is no size or impact term, and the linear extension across the whole priced quantity happens downstream in `computeLegPolicyOutput`. `checkPriceGuard` is described as "the only defense on this path, and it checks deviation from a static reference, not execution cost." [3](#0-2) 

The price guard itself is optional and only rejects a quote if it drifts beyond `maxDeviationBps` from a static `referencePrice`; if both are unset, "the chain unguarded," and even when set, an attacker only needs to move the pool within the configured tolerance band (commonly configured at 0.5%–2% per the documented examples) to still pass the guard while extracting the difference between the manipulated price and the true market price: [4](#0-3) 

Because Uniswap V4 pool state is public and freely tradable by anyone in the same or an adjacent block, an attacker can: (1) push the pool price in a chosen direction with a swap, (2) submit or wait for an intent order that the Simplex solver will price using this manipulated spot mid, and (3) potentially reverse the manipulating swap afterward — the same sandwich mechanic as the referenced Uniswap V3 MEV incident, but here the victim is the solver's cross-chain fill pricing rather than a direct AMM trade.

### Impact Explanation
When triggered, this results in the solver systematically over-delivering the exotic token (or under-charging) relative to the true market price, directly transferring solver capital to the attacker on every exploited fill — a concrete loss of funds for the party operating the reference Simplex filler, mirroring the $9,101 loss in the source incident. Because the price feed for an entire pair can be a single Uniswap V4 pool with no size-aware curve, the exposure scales with the manipulator's capital and the configured `maxDeviationBps` tolerance rather than being capped by protocol-level protections.

### Likelihood Explanation
This is reachable by any unprivileged actor who can trade against the same Uniswap V4 pool the solver reads from and then place (or wait for) an intent order matching the manipulated leg — no privileged access, governance, or trusted role is required. The main mitigating factor is that the `referencePrice`/`maxDeviationBps` guard, when configured, bounds the exploitable spread to the configured tolerance, and `maxOverfillBps` (documented in `filler-config-example.toml`) further clamps per-leg loss; however, both are optional operator configuration rather than protocol-enforced invariants, and the guard is explicitly documented as checking deviation, not execution cost, so it does not account for price-impact-based manipulation within the tolerance band.

### Recommendation
Replace or supplement the raw spot-mid read with a manipulation-resistant price source (e.g., a TWAP over multiple blocks, or a size-aware quote via the pool's actual swap function/quoter that reflects real execution cost), and make the deviation guard mandatory rather than optional for any pair relying solely on venue pricing. Additionally, incorporate the pool's fee tier and expected price impact into `computeLegPolicyOutput` so pricing reflects the true cost of sourcing inventory from the pool, not just its instantaneous mid.

### Proof of Concept
1. Attacker identifies a Simplex-configured pair priced solely via `[vault.uniswapV4]` (no bid/ask curves) with a configured or absent `maxDeviationBps` guard.
2. Attacker swaps against the underlying Uniswap V4 pool to shift `sqrtPriceX96` in the direction favorable to them, staying within any configured `maxDeviationBps` tolerance.
3. Attacker (or an accomplice) immediately places/triggers an intent order on the affected leg; `getExoticTokenPrice` → `computeDirectPoolPriceUsd` reads the manipulated spot mid, and `checkPriceGuard` passes because the deviation is within tolerance.
4. Simplex fills the order at the manipulated rate, and the attacker optionally reverses the manipulating swap, capturing the spread as profit at the solver's expense.

	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}

	private computeDirectPoolPriceUsd(
		pos: HydratedV4Position,
		sdkPool: V4Pool,
		chain: string,
	): { exoticToken: string; priceUsd: Decimal } | null {
		const usdc = this.configService.getUsdcAsset(chain).toLowerCase()
		const usdt = this.configService.getUsdtAsset(chain).toLowerCase()
		const c0 = pos.currency0.toLowerCase()
		const c1 = pos.currency1.toLowerCase()

		if (c0 === usdc || c0 === usdt) {
			// currency0 is stable → exotic is currency1
			// token1Price = "token0 per token1" = USD per exotic
			return {
				exoticToken: c1,
				priceUsd: new Decimal(sdkPool.token1Price.toFixed(18)),
			}
		}

		if (c1 === usdc || c1 === usdt) {
			// currency1 is stable → exotic is currency0
			// token0Price = "token1 per token0" = USD per exotic
			return {
				exoticToken: c0,
				priceUsd: new Decimal(sdkPool.token0Price.toFixed(18)),
			}
		}

		return null
	}

## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.

```toml lineNumbers
[vault.uniswapV4]
# referencePrice is the expected cNGN per USD;
# reject if the quote is more than 2% off.
# The two go together — one without the other is rejected.
[[vault.uniswapV4.positions]]
chain           = "EVM-8453"
tokenId         = "2087350"
referencePrice  = "1575"
maxDeviationBps = 200
```
