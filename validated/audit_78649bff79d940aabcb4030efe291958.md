### Title
Permissionless `Lifecycle.Graduating` freeze with no cancellation path if `finalizeGraduation` cannot succeed - (File: `packages/contracts/src/Bonding.sol`)

### Summary
`Bonding.sol` implements a two-phase graduation identical in structure to the reported MetaVest bug class: an unprivileged action moves a curve into a "pending" intermediate state (`Lifecycle.Graduating`), which permanently blocks the normal actions available in the prior state (buying/selling), and can only be resolved forward by a second permissionless call (`finalizeGraduation`). There is no timeout, no cancellation, and no way back to `Lifecycle.Curve` if that second call cannot succeed.

### Finding Description
`triggerGraduation` and the inline path inside `_executeBuy` are both callable by any unprivileged party once `canGraduate` is true, and they irreversibly flip `info.lifecycle` to `Lifecycle.Graduating`: [1](#0-0) [2](#0-1) 

Once in `Lifecycle.Graduating`, `buy` and `sell` unconditionally revert with `TokenIsGraduating`, and there is no owner or user function anywhere in `Bonding.sol` that can move the lifecycle back to `Curve`: [3](#0-2) [4](#0-3) 

The only exit from `Graduating` is `finalizeGraduation`, which is permissionless but depends on external, uncontrolled calls succeeding: creating/reading the HyperSwap V2 pair, `IUniswapV2Pair.mint`/`swap`, `Router.addLiquidity`, and `LPLock.recordLock`: [5](#0-4) 

The amounts consumed by `finalizeGraduation` (`tokensForLP`, `ltFromPair`) are cached once in `_prepareGraduationLiquidity` at the moment of `_enterGraduating` and are never recomputed: [6](#0-5) 

Because these cached values are fixed, any deterministic revert condition inside the underlying V2 mint/swap path (e.g. a first-mint that produces `liquidity == 0` under standard Uniswap V2 `sqrt` semantics, or any other permanent revert condition in `_seedUniswapV2Direct`/`_seedRebalancing`) will revert on every subsequent retry of `finalizeGraduation`, with no way to alter the inputs or recover: [7](#0-6) 

This is structurally the same defect class as the reported MetaVest issue: a state transition that is triggered permissionlessly and unconditionally locks out normal operations (there, voting/amendment actions; here, curve buy/sell), while the only forward path (there, reaching quorum; here, `finalizeGraduation` succeeding) has no timeout or cancellation mechanism if it cannot be satisfied.

### Impact Explanation
If `finalizeGraduation` cannot succeed for a given token, that token's curve is permanently frozen: traders can no longer buy or sell on the bonding curve (`TokenIsGraduating` on every call), the creator cannot add/remove anything on the curve, and all LT and tokens already raised on the curve (`ltFromPair`, `tokensForLP`, `unsoldBurned` accounting) remain stuck inside `Bonding` with no rescue function. This matches the "permanent freezing of trader/creator funds" impact bar in the validation rules.

### Likelihood Explanation
`_enterGraduating`/`triggerGraduation` are reachable by any unprivileged address the moment `canGraduate` is true — no special permissions are required. The severity of this analog hinges on whether a deterministic, unrecoverable revert inside `finalizeGraduation`'s seeding path is reachable for some configuration of cached `(tokensForLP, ltFromPair)` and pre-existing V2 pair state; the contract's own extensive brick-resistance natspec (three-regime `_seedUniswapV2Direct`, `addLiquidity(min=1)`, direct-mint fallback for small pre-seeds) indicates the authors specifically hardened against hostile pre-seed DoS, which reduces confidence that a trivially reachable permanent-revert path remains. I was not able to fully trace `_seedRebalancing`/`_pairRebalance`/`_routerDepositAndDispose` and `Router.graduate` end-to-end within the available tool budget to confirm or rule out a concrete unrecoverable-revert input, so likelihood here is not proven, only structurally plausible.

### Recommendation
Add an owner-gated (or timelocked, permissionless-after-a-window) recovery path that can either (a) retry `finalizeGraduation` with re-derived/adjusted seeding parameters instead of frozen `PendingGraduation` values, or (b) roll a stuck `Lifecycle.Graduating` token back to `Lifecycle.Curve` (or into an explicit rescue mode that returns raised LT/tokens to a claims process) if `finalizeGraduation` has failed for longer than a bounded grace period.

### Proof of Concept
Not fully constructible from the index alone: reaching a concrete "always-revert" state for `finalizeGraduation` requires precisely engineering pair pre-seed/reserve ratios that hit an unrecoverable V2 mint/swap revert inside `_seedRebalancing`/`_pairRebalance`, whose full bodies were truncated in this session. This would need to be validated with a Foundry test against the real `_seedRebalancing` implementation to confirm whether such an unrecoverable input combination exists; I could not verify this end-to-end within the available exploration budget.

    function finalizeGraduation(
        address tokenAddress
    ) external nonReentrant {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[tokenAddress];
        if (info.lifecycle != Lifecycle.Graduating) revert NotGraduating();

        address lt = info.ltAddress;
        PendingGraduation memory p = $.pendingGraduation[tokenAddress];

        // Anything in this contract beyond `p.ltFromPair` belongs to a
        // concurrent graduation on the same LT (Phase 1 transferred it
        // via `Router.graduate`) or to stray dust. Either way it is
        // off-limits to this graduation's deposit and sweep — see
        // `_routerDepositAndDispose` and `_sweepLTToOwner`.
        // Saturating subtract: a balance below `p.ltFromPair` shouldn't
        // be reachable in normal operation, but we keep finalize from
        // bricking on a Panic if any future code path or non-canonical
        // LT briefly violates the invariant.
        uint256 ltBalance = IERC20(lt).balanceOf(address(this));
        uint256 protectedLT = ltBalance > p.ltFromPair ? ltBalance - p.ltFromPair : 0;

        address lpPair = _ensureUniswapV2Pair(tokenAddress, lt);
        uint256 liquidity = _seedUniswapV2Direct(tokenAddress, lt, lpPair, p.tokensForLP, p.ltFromPair, protectedLT);

        _sweepLTToOwner(lt, protectedLT);

        info.lifecycle = Lifecycle.Graduated;
        $.graduatedPair[tokenAddress] = lpPair;
        delete $.pendingGraduation[tokenAddress];

        LPLock($.lpLock).recordLock(tokenAddress, lpPair, liquidity);

        emit TokenGraduated(tokenAddress, lpPair, liquidity, p.tokensForLP, p.lpBurned, p.unsoldBurned);
    }

    function _prepareGraduationLiquidity(
        address tokenAddress
    ) internal returns (uint256 tokensForLP, uint256 ltFromPair, uint256 lpBurned, uint256 unsoldBurned) {
        address pairAddr = _s().tokenInfo[tokenAddress].pair;
        (uint256 tokenReserve, uint256 assetReserve) = IPair(pairAddr).getReserves();

        unsoldBurned = IPair(pairAddr).tokenBalance();
        if (unsoldBurned > 0) {
            Token(tokenAddress).burn(pairAddr, unsoldBurned);
        }

        ltFromPair = assetReserve - _launchTimeVirtualLtReserve(tokenAddress, pairAddr);
        if (ltFromPair > 0) {
            _s().router.graduate(tokenAddress, ltFromPair);
        }

        tokensForLP = assetReserve == 0 ? 0 : (ltFromPair * tokenReserve) / assetReserve;
        if (tokensForLP > LP_RESERVE) tokensForLP = LP_RESERVE;

        lpBurned = LP_RESERVE - tokensForLP;
        if (lpBurned > 0) {
            Token(tokenAddress).burn(address(this), lpBurned);
        }
    }

    function _seedUniswapV2Direct(
        address tokenAddress,
        address lt,
        address pair,
        uint256 tokensForLP,
        uint256 ltFromPair,
        uint256 protectedLT
    ) internal returns (uint256 liquidity) {
        // Regime 2 — pull any donation pre-seed into this contract so it
        // doesn't pollute the post-swap ratio. Routed to `address(this)`
        // (NOT `lpLock`) so donated TOKEN can be burned and donated LT
        // can be swept to the owner via `_sweepLTToOwner` — `LPLock` has
        // no rescue path, so anything sent there is permanently stuck.
        // No-op on a freshly-created pair (balance == reserves == 0).
        IUniswapV2Pair(pair).skim(address(this));

        // Regime 1 — no LP minted yet (`totalSupply == 0`): a pristine empty
        // pair, or a dust pre-seed from `transfer(pair, dust) + sync()` that
        // leaves reserves non-zero while supply is still zero. Keying on
        // supply rather than reserves routes the dust shape here instead of
        // the rebalance path: with zero supply V2 mints from our amounts
        // alone, so the pool opens at the cached ratio and any dust becomes
        // reserves with no LP claim.
        if (IUniswapV2Pair(pair).totalSupply() == 0) {
            return _seedDirectMint(tokenAddress, lt, pair, tokensForLP, ltFromPair);
        }

        // Regime 3 — mint pre-seed: rebalance, then deposit balanced subset.
        // `lpLock_` re-read from storage inside `_routerDepositAndDispose`.
        // Reserves and token-ordering re-read inside `_seedRebalancing` to
        // keep this function's stack pressure under solc's 16-slot ceiling
        // without `viaIR`.
        return _seedRebalancing(tokenAddress, lt, pair, tokensForLP, ltFromPair, protectedLT);
    }

    /// @dev Transfer the full `(tokensForLP, ltFromPair)` to the pair and
    ///      `mint` the LP to `LPLock`, opening at the exact cached
    ///      curve-close ratio. Used by the empty-pair regime and as the
    ///      dust-pre-seed fallback in `_seedRebalancing` — against dust
    ///      reserves the V2 `min()` formula's donation to any pre-existing
    ///      LP is negligible (see `_seedUniswapV2Direct` natspec). Any TOKEN
    ///      remainder (a skimmed pure-donation pre-seed) is burned; the LT
    ///      remainder is left for `finalizeGraduation`'s `_sweepLTToOwner`
    ///      post-bookend.
    function _seedDirectMint(
        address tokenAddress,
        address lt,
        address pair,
        uint256 tokensForLP,
        uint256 ltFromPair
    ) internal returns (uint256 liquidity) {
        IERC20(tokenAddress).safeTransfer(pair, tokensForLP);
        IERC20(lt).safeTransfer(pair, ltFromPair);
        liquidity = IUniswapV2Pair(pair).mint(_s().lpLock);
        uint256 leftoverToken = IERC20(tokenAddress).balanceOf(address(this));
        if (leftoverToken > 0) {
            Token(tokenAddress).burn(address(this), leftoverToken);
        }
    }
