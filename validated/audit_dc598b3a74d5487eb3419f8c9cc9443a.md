The core claim here—that `MUTATE_TOKEN_PROPERTY_MAP_EVENT_TYPE`'s identity is based purely on `address`/`module`/`name` fields of a `StructTag` rather than any chain-verified provenance—is true, but it does not constitute a custody-boundary violation for several reasons:

1. **Events are not a custody surface.** `MutateTokenPropertyMapEvent` (in `types/src/account_config/events/mutate_token_property_map_event.rs`) is a passive `#[event]`-derived struct emitted only as a side-effect of real execution of the `0x3::token` module's `mutate_property_map`-style functions. [1](#0-0)  It carries no capability, ownership ref, or authority — it's a record, not a control object.

2. **On-chain emission is execution-gated, not attacker-controlled.** The only production code path that constructs and emits this exact typed event is `MutatePropertyMapTranslator::translate_event_v2_to_v1` inside the indexer, which derives the event strictly from a `MutatePropertyMap` V2 event that itself only exists because the Move VM executed the real `token.move` mutation logic and recorded it in `TokenStoreResource`. [2](#0-1)  An attacker cannot inject a `ContractEventV2`/`ContractEventV1` into the ledger's event log by simply crafting matching bytes off-chain — event logs are populated by the VM during consensus-ordered transaction execution, not by arbitrary user input to a deserializer.

3. **`try_from_bytes` is a local deserialization helper, not a chain-trust oracle.** `MutateTokenPropertyMapEvent::try_from_bytes` at lines 41-43 merely BCS-decodes bytes handed to it by a caller (e.g., the indexer translator operating on already-consensus-verified event data). [3](#0-2)  The function itself makes no claim about provenance, and no production code treats "bytes decode successfully" as proof of on-chain occurrence — it's always invoked on data already sourced from `ContractEventV1`/`ContractEventV2` structures that originate from executed transactions in storage.

4. **TypeTag/StructTag identity being structural (not cryptographically bound to a specific event instance) is true for every Move struct in the codebase**, including `MintEvent`, `BurnEvent`, `WithdrawEvent`, etc. This is inherent to how Move's type system and `MoveStructType` work, not a defect specific to this file. The reviewed proof idea (asserting `TypeTag` equality from struct fields) demonstrates a true but generic fact about Rust `PartialEq`/`StructTag` comparison — it does not demonstrate an attacker gaining the ability to insert a forged event into the actual ledger event stream or to change any on-chain asset controller, holder, freeze/mint/burn authority, or resource ownership.

Per the review's decision standard, this reduces to an event-level/type-identity observation with no unprivileged path that actually crosses a custody boundary or mutates real ownership/authority state, so it is rejected.

        let (key, sequence_number) = if let Some(state_value_bytes) =
            engine.get_state_value_bytes_for_resource(mutate.account(), &struct_tag)?
        {
            let token_store_resource: TokenStoreResource = bcs::from_bytes(&state_value_bytes)?;
            let key = *token_store_resource.mutate_token_property_events().key();
            let sequence_number = engine.get_next_sequence_number(
                &key,
                token_store_resource.mutate_token_property_events().count(),
            )?;
            (key, sequence_number)
        } else {
            // If the token store resource is not found, we skip the event translation to avoid panic
            // because the creation number cannot be decided.
            return Err(AptosDbError::from(anyhow::format_err!(
                "Token store resource not found"
            )));
        };
        let mutate_event = MutateTokenPropertyMapEvent::new(
            mutate.old_id().clone(),
            mutate.new_id().clone(),
            mutate.keys().clone(),
            mutate.values().clone(),
            mutate.types().clone(),
        );

        Ok(ContractEventV1::new(
            key,
            sequence_number,
            MUTATE_TOKEN_PROPERTY_MAP_EVENT_TYPE.clone(),
            bcs::to_bytes(&mutate_event)?,
        )?)
    }
