### Title
Contract loading/compilation gas is charged only after a successful load, and never charged on a compile/deserialize failure — ([File: runtime/near-vm-runner/src/wasmtime_runner/mod.rs])

### Summary
The size-dependent gas fee for loading/compiling a WASM contract on `FunctionCall` execution is charged *after* the expensive compile/deserialize step completes, and is skipped entirely when that step fails. This mirrors the reported Arbitrum Stylus bug class: an expensive, user-triggerable operation (bytecode decompression/activation there, WASM compilation/loading here) is not priced before it runs, so a crafted or evicted-cache contract lets an attacker cause real CPU work on validators while paying nothing for it.

### Finding Description
`WasmtimeVM::with_compiled_and_loaded` resolves the compiled module through a two-level cache; on a cache miss it invokes `compile_and_cache`, which performs full WASM compilation — the most CPU-expensive step in the pipeline [1](#0-0) . Only after this (and after `Module::deserialize`, export resolution, linking and `instantiate_pre`) does the code call `before_loading_executable`, and then — only on the success branch — `after_loading_executable`, which is what actually charges `add_contract_loading_fee` (`contract_loading_base + contract_loading_bytes * code_len`) [2](#0-1) .

The gas counter helpers make the ordering explicit: `before_loading_executable` only pre-charges the fee `if config.fix_contract_loading_cost` is set, and `after_loading_executable` is the "legacy" path that charges the same fee *after* loading completes when that flag is unset [3](#0-2) . Critically, when compilation fails (`pre_result` is `Err`), the code returns `OutcomeAbort(FunctionCallError::CompilationError(e))` directly, without ever invoking `after_loading_executable`/`add_contract_loading_fee` at all [4](#0-3) .

The protocol-model documentation for this release confirms `fix_contract_loading_cost` is nightly-only (protocol version 129) and **not active** on the current stable/mainnet protocol version (86), meaning the loading fee is unconditionally charged post-load (or not at all on failure) in production [5](#0-4) [6](#0-5) .

A compile can be forced outside of `DeployContractAction` because the on-disk compiled-contract cache is a size-bounded LRU that evicts entries, so a previously-deployed, previously-priced-at-deploy-time contract can later require a fresh, unpriced recompilation on an ordinary `FunctionCall` [7](#0-6) .

### Impact Explanation
NEAR's gas model burns only the gas actually metered and refunds the unused portion of `prepaid_gas` to the caller. Since the compile/deserialize/link/instantiate work happens before any size-based fee is charged, and is skipped entirely on failure, an attacker can force validators to perform real (and, per `runtime/near-vm-runner/RUNTIMES.md`, size-dependent/expensive) compilation work while paying only the flat `function_call_cost` action fee — with the size-based `contract_loading_bytes`/`contract_loading_base` charge either deferred past the point where it matters or dropped altogether on error. This is underpriced/free execution of a computationally expensive operation that can be triggered repeatedly and cheaply, enabling a compute-based denial-of-service against validating nodes.

### Likelihood Explanation
Likelihood is moderate: the "free on failure" case requires a contract whose compilation fails only at the backend level after passing `prepare_contract`'s validation (documented as a rare "defense-in-depth" scenario) [8](#0-7) , or requires the on-disk cache to have evicted a large deployed contract so that ordinary calls force full recompilation. Both are attacker-influenceable (deploy a large contract, spam the cache with other large contracts to evict it, then invoke the target with minimal `prepaid_gas`), and the "charged only after the expensive step" ordering applies unconditionally on stable protocol version 86 since the fix flag is nightly-only.

### Recommendation
Pre-charge the size-dependent loading fee (`contract_loading_base` + `contract_loading_bytes * wasm_code_bytes`) before attempting compilation/deserialization/linking, and ensure it is charged (or the call aborted for insufficient gas) even when compilation or loading subsequently fails — i.e., stabilize and enable the existing `fix_contract_loading_cost` behavior (already implemented on nightly, PV 129) on the production protocol path rather than leaving it gated. More broadly, audit other cache-miss-triggered expensive paths (e.g., `try_precompile_contract`/`compile_and_cache` reachable from `FunctionCall`) to confirm all are priced before the expensive work executes, not after.

### Proof of Concept
1. Deploy a large contract `C` (near `max_contract_size`) that compiles successfully via `DeployContractAction` (paying the deploy-time compile cost, priced correctly).
2. Deploy/call enough other large contracts to evict `C`'s compiled artifact from the size-bounded on-disk `FilesystemContractRuntimeCache` LRU [9](#0-8) .
3. Send a `FunctionCall` to `C` with `prepaid_gas` set just above the flat `function_call_cost` base fee.
4. On cache miss, `with_compiled_and_loaded` triggers `compile_and_cache`, performing full recompilation of `C`'s large WASM module [10](#0-9) ; the size-based loading fee is charged only after this work completes (`after_loading_executable`, `gas_counter.rs:260`), and would be skipped entirely if the recompilation instead failed with a `CompileModuleError` [4](#0-3) .
5. Repeating this against many large, evicted contracts lets an attacker impose expensive compilation work on every validating node for a cost far below the actual CPU expense incurred.

    /// Add a cost for loading the contract code in the VM.
    ///
    /// This cost does not consider the structure of the contract code, only the
    /// size. This is currently the only loading fee. A fee that takes the code
    /// structure into consideration could be added. But since that would have
    /// to happen after loading, we cannot pre-charge it. This is the main
    /// motivation to (only) have this simple fee.
    #[cfg(feature = "wasmtime_vm")]
    pub(crate) fn add_contract_loading_fee(&mut self, code_len: u64) -> Result<()> {
        self.pay_per(ExtCosts::contract_loading_bytes, code_len)?;
        self.pay_base(ExtCosts::contract_loading_base)
    }

    /// VM independent setup before loading the executable.
    ///
    /// Does VM independent checks that happen after the instantiation of
    /// VMLogic but before loading the executable. This includes pre-charging gas
    /// costs for loading the executable, which depends on the size of the WASM code.
    #[cfg(feature = "wasmtime_vm")]
    pub(crate) fn before_loading_executable(
        &mut self,
        config: &near_parameters::vm::Config,
        method_name: &str,
        wasm_code_bytes: u64,
    ) -> std::result::Result<(), super::errors::FunctionCallError> {
        if method_name.is_empty() {
            let error = super::errors::FunctionCallError::MethodResolveError(
                super::errors::MethodResolveError::MethodEmptyName,
            );
            return Err(error);
        }
        if config.fix_contract_loading_cost {
            if self.add_contract_loading_fee(wasm_code_bytes).is_err() {
                let error =
                    super::errors::FunctionCallError::HostError(super::HostError::GasExceeded);
                return Err(error);
            }
        }
        Ok(())
    }

    /// Legacy code to preserve old gas charging behaviour in old protocol versions.
    #[cfg(feature = "wasmtime_vm")]
    pub(crate) fn after_loading_executable(
        &mut self,
        config: &near_parameters::vm::Config,
        wasm_code_bytes: u64,
    ) -> std::result::Result<(), super::errors::FunctionCallError> {
        if !config.fix_contract_loading_cost {
            if self.add_contract_loading_fee(wasm_code_bytes).is_err() {
                return Err(super::errors::FunctionCallError::HostError(
                    super::HostError::GasExceeded,
                ));
            }
        }
        Ok(())
    }

/// Scan `dir` and build an [`LruWeightedCache`] tracking each on-disk
/// cache file by its byte size, ordered from least- to most-recently-
/// accessed by `st_atime`.
///
/// Files whose names don't parse as a [`CryptoHash`] are skipped.
/// If the scanned valid total already exceeds `max_bytes`, the oldest
/// tracked entries are unlinked until the index fits.
#[cfg(not(windows))]
fn build_disk_index(
    dir: &rustix::fd::OwnedFd,
    max_bytes: u64,
) -> std::io::Result<LruWeightedCache<CryptoHash, Instant>> {
    let mut index = LruWeightedCache::<CryptoHash, Instant>::without_item_cap(max_bytes);
    let mut entries: Vec<(CryptoHash, u64, i64, i64)> = Vec::new();

    let read_dir = Dir::read_from(dir)?;
    for entry in read_dir {
        let entry = match entry {
            Ok(e) => e,
            Err(_) => continue,
        };
        let filename = entry.file_name();
        if !entry.file_type().is_file() {
            continue;
        }
        let Some(key) = filename.to_str().ok().and_then(|s| CryptoHash::from_str(s).ok()) else {
            continue;
        };
        let stat = match statat(dir, filename, AtFlags::empty()) {
            Ok(s) => s,
            // Missing/unreadable: leave it alone for now; `get` will treat
            // it as a miss and the next compile will overwrite it.
            Err(_) => continue,
        };
        let size = u64::try_from(stat.st_size).unwrap_or(0);
        entries.push((key, size, stat.st_atime as i64, stat.st_atime_nsec as i64));
    }

    // Ascending by atime: most-recently-accessed ends up MRU.
    entries.sort_unstable_by_key(|(_, _, sec, nsec)| (*sec, *nsec));

    // Sizes by key, so we can total the bytes of any entries we trim below
    // (`insert` only hands back the evicted key, not its weight).
    let sizes: HashMap<CryptoHash, u64> =
        entries.iter().map(|&(key, size, _, _)| (key, size)).collect();

    let refreshed_at = Instant::now();
    let mut over_limit_trimmed: usize = 0;
    let mut trimmed_bytes: u64 = 0;
    for (key, size, _, _) in entries {
        for (victim, _) in index.insert(key, size, refreshed_at) {
            trimmed_bytes += sizes.get(&victim).copied().unwrap_or(0);
            match unlinkat(dir, victim.to_string(), AtFlags::empty()) {
                Ok(()) | Err(Errno::NOENT) => {}
                Err(err) => tracing::debug!(
                    target: "vm",
                    victim = %victim,
                    err = &err as &dyn std::error::Error,
                    "failed to unlink evicted compiled-contract cache file; on-disk cache may exceed its size limit"
                ),
            }
            over_limit_trimmed += 1;
        }
    }
