### Title
Enrollment can be reported as successful even when personal-custody-package credential binding silently fails - (File: `src/plans/mod.rs`)

### Summary
The reported ZetaChain issue describes a scenario where a critical finalization step (returning/minting funds on revert) can silently fail, yet the surrounding state machine treats the overall operation as terminally resolved (`Aborted`) without any path to recover the lost value, and — more generally — without keeping the "real" outcome linked to the fact that the finalization step never actually happened. The analogous pattern in `orb-core` is in `MasterPlan::do_signup`: the step that binds a user's biometric identity to durable custody credentials (the personal custody package, "PCP") can be silently skipped, while the enrollment result reported to the backend/operator UI is computed independently of whether that binding actually took place.

### Finding Description
In `MasterPlan::do_signup` [1](#0-0) , the credentials required to build the personal custody package are derived via `qr_codes.try_into()`:

```rust
let user_id = qr_codes.user_qr_code.user_id.clone();
let user_centric_signup = qr_codes.user_data.user_centric_signup;
if let Ok(mut credentials) = qr_codes.try_into() {
    ...
    let packages = match Box::pin(self.build_pcp(...)).await {
        Ok(Some(p)) => p,
        Ok(None) => { return Ok(result); }
        Err(e) => { tracing::error!("{e}"); return Ok(result); }
    };
    ...
}
```

If `qr_codes.try_into()` returns `Err` (i.e., the conversion into `personal_custody_package::Credentials` fails), the entire `if let Ok(...)` block — including building the PCP (`build_pcp`), uploading tier 0 (`upload_pcp_tier_0`), and uploading tiers 1/2 — is **silently skipped**. There is no `else` branch, no error log, and no early return.

Execution then falls straight through to the enrollment-success computation [2](#0-1) :

```rust
let success = if user_centric_signup && !orb.config.lock().await.ignore_user_centric_signups {
    debug_report.enrollment_status(match signup_reason {
        SignupReason::Normal => enroll_user::Status::Success,
        _ => enroll_user::Status::Error,
    });
    signup_reason == SignupReason::Normal
} else {
    Box::pin(self.enroll_user(orb, debug_report, &capture, pipeline.as_ref(), signup_reason)).await.is_success()
};
...
result.success = debug_report.enrollment_status.as_ref().map_or(false, enroll_user::Status::is_success);
Ok(result)
```

Both branches compute `success`/`enrollment_status` purely from `signup_reason` (derived earlier from pipeline/fraud outcome) and are completely decoupled from whether the PCP (which contains the encrypted iris/face credentials bound to the `self_custody_user_public_key` and backend keys, see `personal_custody_package::Plan::run` / `Package::build` [3](#0-2) ) was ever built or uploaded. In the `user_centric_signup` branch in particular, enrollment is marked `Success` as soon as `signup_reason == SignupReason::Normal`, with no dependency on `try_into()`/`build_pcp`/upload outcomes at all.

This mirrors the root cause of the referenced bug class: a critical, non-retriable step that permanently commits/binds user data (minting funds on revert vs. building/uploading the PCP that binds the identity credentials) can fail or be skipped, while the surrounding state machine proceeds to a terminal state (`Aborted` vs. `Success`) that does not reflect that failure and offers no recovery path.

### Impact Explanation
If credential conversion fails (or more generally, if the PCP build/upload path is bypassed for any reason while `signup_reason` remains `Normal`), the Orb can report a signup as successfully enrolled to the backend and to the operator/UI without the corresponding encrypted iris/face custody package ever being produced or uploaded. This is a cross-signup / identity-binding integrity failure: enrollment state becomes disconnected from the actual biometric-credential artifact that is supposed to anchor it, which can result in signups being recorded as complete while the durable, verifiable credential material backing that identity binding is missing.

### Likelihood Explanation
The `try_into()` conversion failure path and the decoupled success computation are both reachable through unprivileged user interaction with a single signup flow (no operator/malicious-node/hardware access required). Whether `qr_codes.try_into()` can practically fail for a legitimate, well-formed user/operator QR pair could not be fully confirmed within this investigation — the `TryFrom` implementation for `Credentials` was not located in the indexed portion of the codebase, so the exact failure conditions (e.g., malformed QR fields, missing keys) remain unverified. This uncertainty affects the practical likelihood, though the code structure itself demonstrates the missing coupling between the credential-binding step and the reported enrollment outcome regardless of how that path is triggered.

### Recommendation
- Do not allow the `try_into()` failure path to fall through silently; treat it as an explicit error and short-circuit signup with a distinct failure status (`return Ok(result)` with a proper `debug_report` failure marker), consistent with the `Ok(None)`/`Err(e)` handling already done for `build_pcp`.
- Make `success`/`enrollment_status` explicitly conditional on the PCP having been successfully built and uploaded (or otherwise not required by the specific signup mode), rather than deriving it solely from `signup_reason`.
- Add regression tests and metrics (`dd_incr!`) specifically for the "credentials conversion failed" case, mirroring the existing failure-path telemetry for `build_pcp`/`upload_pcp_tier_0`.

### Proof of Concept
Not applicable in the traditional sense (no externally exploitable transaction to replay), since this is a code-path/control-flow gap rather than a value-transfer bug. The control-flow gap is demonstrated directly by the code excerpt above: `qr_codes.try_into()` returning `Err` causes the PCP-building block to be skipped entirely (lines 574–637), yet `success` at lines 639–662 is computed independent of that block having run.

impl Plan {
    /// Runs the plan for building and uploading the personal custody package.
    pub async fn run(self) -> Result<PersonalCustodyPackages> {
        let Self {
            capture_start,
            signup_id,
            identification_image_ids,
            capture,
            pipeline,
            credentials,
            signup_reason,
            location_data,
        } = self;
        let pipeline_box = Box::new(pipeline);

        #[cfg(feature = "internal-pcp-export")]
        let signup_id2 = signup_id.clone();
        let packages = task::spawn_blocking(move || {
            let hyrax = (&*pipeline_box).into();
            Package {
                ts: UNIX_EPOCH.elapsed()?,
                capture_start,
                capture,
                identification_image_ids,
                pipeline: pipeline_box,
                hyrax,
                credentials,
                signup_id: signup_id.to_string(),
                signup_reason: signup_reason.to_screaming_snake_case(),
                location_data,
            }
            .build()
            .map(|(tier0, tier1, tier2)| {
                let tier0_checksum = digest(&SHA256, &tier0);
                let tier1_checksum = digest(&SHA256, &tier1);
                let tier2_checksum = digest(&SHA256, &tier2);
                PersonalCustodyPackages {
                    tier0,
                    tier0_checksum,
                    tier1,
                    tier1_checksum,
                    tier2,
                    tier2_checksum,
                }
            })
        })
        .await??;

        #[cfg(feature = "internal-pcp-export")]
        {
            tokio::fs::write(
                std::path::Path::new(&format!("/tmp/pcp.{}.tier0.tar.gz", &signup_id2)),
                &packages.tier0,
            )
            .await?;
            tokio::fs::write(
                std::path::Path::new(&format!("/tmp/pcp.{}.tier1.tar.gz", &signup_id2)),
                &packages.tier1,
            )
            .await?;
            tokio::fs::write(
                std::path::Path::new(&format!("/tmp/pcp.{}.tier2.tar.gz", &signup_id2)),
                &packages.tier2,
            )
            .await?;
        }

        Ok(packages)
    }
}
