### Title
Time-based user enumeration in Chainlink `/sessions` login endpoint - (File: `core/sessions/localauth/orm.go`)

### Summary
The `POST /sessions` login endpoint calls `AuthenticationProvider().CreateSession`, which (for the local, LDAP-fallback, and OIDC-fallback authenticators) performs a fast SQL lookup for the supplied email and returns immediately if no matching row exists, but performs an expensive `bcrypt.CompareHashAndPassword` call only when the email *does* exist. This produces a measurable timing discrepancy between "email exists" and "email does not exist" responses, allowing an unauthenticated client to enumerate valid node-operator accounts purely by measuring response latency — the same bug class described in CVE-2026-45410 for TREK.

### Finding Description
`SessionsController.Create` in [1](#0-0)  accepts unauthenticated JSON login requests and forwards them to `AuthenticationProvider().CreateSession`.

For the local authentication provider, `CreateSession` first performs `FindUser`, which does a single indexed SQL lookup and returns an error immediately if no user row matches the email — no cryptographic work is performed on this path: [2](#0-1) [3](#0-2) 

Only when a user row is found does the code proceed to `constantTimeEmailCompare` and `utils.CheckPasswordHash`, which internally calls `bcrypt.CompareHashAndPassword` — a deliberately slow, cost-factor-tunable hash comparison: [4](#0-3) 

The identical pattern (fast-path early return on missing user, slow bcrypt path on found user) also exists in the LDAP and OIDC authenticators' local-admin fallback login paths: [5](#0-4) [6](#0-5) 

In all three cases, the HTTP response for "user not found" and "user found but wrong password" is indistinguishable in status code and body (both hit `jsonAPIError(c, http.StatusUnauthorized, err)` in [7](#0-6) ), but the bcrypt comparison adds tens-to-hundreds of milliseconds of latency that is absent on the "email not found" path — exactly mirroring the TREK advisory's ~370ms vs ~10ms timing gap.

### Impact Explanation
An unauthenticated network client can enumerate valid Chainlink node operator/admin email addresses by measuring `/sessions` response timing, without needing any credentials. Account enumeration is a stepping stone for targeted credential-stuffing, phishing, or brute-force attacks against the node's admin API, which controls job runs, bridges, keys, and other sensitive node operations gated by the `sessions.User` role model in [8](#0-7) .

### Likelihood Explanation
The `/sessions` endpoint is intentionally reachable pre-authentication (it *is* the login endpoint) from any network client with access to the node's operator UI/API port. No special privileges, MITM, or malicious-peer capability is required — only the ability to send repeated timed HTTP POST requests, which is trivial to automate with statistical timing analysis to average out network jitter.

### Recommendation
Ensure a constant-time cost is incurred regardless of whether the user exists, e.g. always perform a dummy/precomputed bcrypt comparison against a static hash when `FindUser` fails before returning the "invalid email" error, so that the found-vs-not-found code paths take statistically indistinguishable time. Apply this fix uniformly to `core/sessions/localauth/orm.go` `CreateSession`, and the `localLoginFallback` functions in `core/sessions/ldapauth/ldap.go` and `core/sessions/oidcauth/oidc.go`.

### Proof of Concept
1. Send `POST /sessions` with a known-valid admin email and an incorrect password; measure response time (includes one bcrypt compare, e.g. ~100-300ms depending on cost factor).
2. Send `POST /sessions` with a random/nonexistent email and any password; measure response time (SQL lookup only, sub-10ms).
3. Repeat N times for statistical confidence; the consistent latency gap reveals which candidate emails correspond to real accounts, even though both requests return HTTP 401 with the same error shape.

func (sc *SessionsController) Create(c *gin.Context) {
	defer sc.App.WakeSessionReaper()
	ctx := c.Request.Context()
	sc.App.GetLogger().Debugf("TRACE: Starting Session Creation")

	session := sessions.Default(c)
	var sr clsessions.SessionRequest
	if err := c.ShouldBindJSON(&sr); err != nil {
		jsonAPIError(c, http.StatusBadRequest, fmt.Errorf("error binding json %w", err))
		return
	}

	// Does this user have 2FA enabled?
	userWebAuthnTokens, err := sc.App.AuthenticationProvider().GetUserWebAuthn(ctx, sr.Email)
	if err != nil {
		sc.App.GetLogger().Errorf("Error loading user WebAuthn data: %s", err)
		jsonAPIError(c, http.StatusInternalServerError, errors.New("internal Server Error"))
		return
	}

	// If the user has registered MFA tokens, then populate our session store and context
	// required for successful WebAuthn authentication
	if len(userWebAuthnTokens) > 0 {
		sr.SessionStore = sc.sessions
		sr.WebAuthnConfig = sc.App.GetWebAuthnConfiguration()
	}

	sid, err := sc.App.AuthenticationProvider().CreateSession(ctx, sr)
	if err != nil {
		jsonAPIError(c, http.StatusUnauthorized, err)
		return
	}

func (o *orm) CreateSession(ctx context.Context, sr sessions.SessionRequest) (string, error) {
	user, err := o.FindUser(ctx, sr.Email)
	if err != nil {
		return "", err
	}
	lggr := o.lggr.With("user", user.Email)
	lggr.Debugw("Found user")

	// Do email and password check first to prevent extra database look up
	// for MFA tokens leaking if an account has MFA tokens or not.
	if !constantTimeEmailCompare(strings.ToLower(sr.Email), strings.ToLower(user.Email)) {
		o.auditLogger.Audit(audit.AuthLoginFailedEmail, map[string]any{"email": sr.Email})
		return "", pkgerrors.New("Invalid email")
	}

	if !utils.CheckPasswordHash(sr.Password, string(user.HashedPassword)) {
		o.auditLogger.Audit(audit.AuthLoginFailedPassword, map[string]any{"email": sr.Email})
		return "", pkgerrors.New("Invalid password")
	}

func CheckPasswordHash(password, hash string) bool {
	err := bcrypt.CompareHashAndPassword([]byte(hash), []byte(password))
	return err == nil
}

func (l *ldapAuthenticator) localLoginFallback(ctx context.Context, sr sessions.SessionRequest) (sessions.User, error) {
	var user sessions.User
	sql := "SELECT * FROM users WHERE lower(email) = lower($1)"
	err := l.ds.GetContext(ctx, &user, sql, sr.Email)
	if err != nil {
		return user, err
	}
	if !constantTimeEmailCompare(strings.ToLower(sr.Email), strings.ToLower(user.Email)) {
		l.auditLogger.Audit(audit.AuthLoginFailedEmail, map[string]any{"email": sr.Email})
		return user, errors.New("invalid email")
	}

	if !utils.CheckPasswordHash(sr.Password, string(user.HashedPassword)) {
		l.auditLogger.Audit(audit.AuthLoginFailedPassword, map[string]any{"email": sr.Email})
		return user, errors.New("invalid password")
	}

	return user, nil
}
