### Title
LT Sent Directly to a Curve `Pair` (Donation or User Error) Is Permanently Locked With No Recovery Function - (File: `packages/contracts/src/Pair.sol`)

### Summary
Any LT (the reserve asset) transferred via a plain `IERC20.transfer` directly into a `Pair` contract — before or after the token's graduation — can never be moved back out. `Pair.transferAsset` is the only function capable of moving the asset token out of the pair, and it is gated `onlyRouter`, while `Router` only ever calls it from two paths: `Router.sell` (curve sells, `onlyRole(BONDING_ROLE)`) and `Router.graduate` (a one-shot call from `Bonding._prepareGraduationLiquidity` that transfers only the router-computed "real LT raised" and explicitly excludes any donated surplus). There is no sweep, rescue, or owner-withdraw function on `Pair`, `Router`, or `Bonding` for this leftover LT.

### Finding Description
`Pair.sol` exposes exactly two asset-moving functions, both `onlyRouter`: [1](#0-0) 

`Router.graduate` deliberately transfers only the LT amount computed from stored reserves minus the recovered virtual reserve, leaving any donated LT behind in the pair by design ("donation resistance"): [2](#0-1) 

The project's own docs and tests confirm the donated LT is permanently stuck in the pair once graduation fires — it is never drained into the LP and stays there indefinitely: [3](#0-2) [4](#0-3) 

After graduation, `Bonding`'s lifecycle flips so the curve `Pair` is no longer routed to at all — `Zap._sellInternal` sends post-graduation sells to the HyperSwap V2 pool instead of the curve `Pair`: [5](#0-4) 

So `Router.sell` (the only other `onlyRouter`-gated caller of `transferAsset`) can no longer be reached for that token either, since `Bonding`'s buy/sell entrypoints are lifecycle-gated to the `Curve` state (`isGraduating`/`isGraduated` checks throughout `Zap.sol`). Once a token graduates, the curve `Pair` becomes permanently unreachable for asset withdrawal — any LT sitting in it (donated pre- or post-graduation, or mistakenly sent by a user who transfers LT directly instead of calling `Zap.sell`) is frozen forever with zero recovery mechanism, privileged or otherwise.

This is the same bug class as the external report's `OptimismPortal.donateETH()` — a contract that accepts value with a corresponding balance but has no function, admin or otherwise, capable of ever moving it back out. Notably, alt.fun's own `FeeVault` explicitly solved this exact problem for USDC via `sweepDonations()`: [6](#0-5) 
but no analogous mechanism exists for LT stuck in a `Pair`.

### Impact Explanation
Any LT donated or mistakenly transferred directly to a `Pair` (a fully permissionless, single-transaction action reachable by any wallet holding LT) is permanently and irrecoverably frozen. This is a genuine, unbounded loss-of-funds class: it affects both pre-graduation curves (donations excluded from graduation per the "donation resistance" design) and — more importantly — every graduated token's abandoned curve `Pair`, where LT sent there afterward (e.g., by a user confusing the legacy curve pair address with the live HyperSwap pair, or a bot/integrator mis-targeting the old pair address) has literally no path out, ever.

### Likelihood Explanation
High reachability, low but non-zero occurrence likelihood: it requires only a plain `IERC20.transfer(pairAddr, amount)` from any LT holder — no special conditions, front-running, or privileged role needed. The most realistic trigger is user/integrator error (sending LT to the old curve pair address post-graduation instead of the new HyperSwap pool, or attempting a "manual donation" thinking it will be swept like `FeeVault` donations are).

### Recommendation
Add a permissionless (or owner-gated, paid to a fixed protocol/treasury address, mirroring `FeeVault.sweepDonations`) rescue function on `Pair`/`Router` that can transfer out any asset-token balance in excess of the tracked `_pool.assetReserve`, callable at least once a token has permanently exited the `Curve` lifecycle state (post-graduation), so donated/mis-sent LT is not lost forever. Ensure this cannot be abused to drain legitimately-owed reserve LT by bounding the sweep to `assetBalance() - assetReserve()`.

### Proof of Concept
1. Launch a token via `Zap.createToken`, let it trade and graduate normally (`Bonding.triggerGraduation` / `finalizeGraduation`).
2. After graduation, an unrelated wallet holding LT calls `IERC20(lt).transfer(pairAddr, amount)` directly on the now-abandoned curve `Pair` (by mistake, or as a "donation").
3. Confirm no function anywhere in `Pair`, `Router`, `Bonding`, or `Factory` can move this LT out: `Pair.transferAsset`/`transferToken` are `onlyRouter`; `Router.sell`/`Router.graduate` are `onlyRole(BONDING_ROLE)` and only ever invoked by `Bonding` through lifecycle-gated paths that no longer apply to a graduated token.
4. The LT balance shown by `IPair(pairAddr).assetBalance()` is permanently unrecoverable, exactly mirroring `test_inv_donation_zeroGapPreserved`'s assertion that donated LT "must remain locked in the curve pair" — with no time bound or exit mechanism.

```text
    /// @notice Transfer exactly `amount` of LT out of the pair to the caller.
    ///         Called by `Bonding._prepareGraduationLiquidity` during graduation
    ///         with `amount = stored assetReserve - virtualLtReserve` (i.e. the
    ///         real LT raised by the curve, excluding the virtual seed).
    /// @dev    Donation-resistant: passing an explicit `amount` instead of
    ///         draining `assetBalance()` ensures any LT that was donated
    ///         directly to the pair via `IERC20.transfer` is left behind and
    ///         excluded from LP seeding.
    ///
    ///         "Locked" here is a trust-assumption claim, not an on-chain
    ///         guarantee. `Pair.transferAsset` is gated by `onlyRouter`, and
    ///         `Router` only exposes it via this function and `sell`. Both
    ///         require `BONDING_ROLE`, which only `Bonding` holds. `Bonding`
    ///         in turn only calls `graduate` from
    ///         `_prepareGraduationLiquidity` — which is unreachable once the
    ///         token's lifecycle has flipped past `Curve`. So the leftover
    ///         is unreachable as long as (a) `BONDING_ROLE` is not granted
    ///         to any other address, and (b) future `Bonding` upgrades
    ///         preserve the lifecycle gate.
    function graduate(
        address token,
        uint256 amount
    ) external onlyRole(BONDING_ROLE) {
        address asset = assetTokenFor(token);
        address pairAddr = factory.getPair(token, asset);
        if (pairAddr == address(0)) revert PairNotFound();
        IPair(pairAddr).transferAsset(msg.sender, amount);
    }
```

```text
    ///         direct USDC transfers would otherwise inflate `balanceOf` above
    ///         the accrual tally and silently mask the `accrue` underfund
    ///         check. Permissionless — funds always go to the admin-set `feeTo`.
    function sweepDonations() external nonReentrant returns (uint256 amount) {
        FeeVaultStorage storage $ = _s();
        uint256 backed = $.totalAccruedCreator + $.protocolBalance;
        uint256 balance = $.usdc.balanceOf(address(this));
        if (balance <= backed) revert NothingToClaim();
        amount = balance - backed;
        address feeTo_ = $.feeTo;
        $.usdc.safeTransfer(feeTo_, amount);

    }
```
