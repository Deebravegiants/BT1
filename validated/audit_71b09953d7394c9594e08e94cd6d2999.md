### Title
Unvalidated `shop` parameter in `Oauth.begin_auth`/`validate_auth_callback` allows `client_secret` exfiltration via attacker-controlled OAuth host - (File: `lib/shopify_api/auth/oauth.rb`)

### Summary
`ShopifyAPI::Auth::Oauth.begin_auth` and `ShopifyAPI::Auth::Oauth.validate_auth_callback` build request URIs directly from the caller-supplied `shop` string without ever validating it against a trusted Shopify domain, unlike every other credential-bearing flow in this gem.

### Finding Description
Every other flow in the gem that sends the app's `client_secret` to a shop-derived host first calls `Utils::ShopValidator.sanitize!(shop)`, which restricts the host to `TRUSTED_SHOPIFY_DOMAINS` (`shopify.com`, `myshopify.io`, `myshopify.com`, `spin.dev`, `shop.dev`): [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) 

`ShopifyAPI::Auth::Oauth`, however, never calls `ShopValidator` at all. `begin_auth` builds the authorize URL directly from the raw `shop` argument: [5](#0-4) [6](#0-5) 

And `validate_auth_callback` sends the request that includes `client_secret` to a host built from `auth_query.shop` — again with no domain allow‑list check: [7](#0-6) 

The only check performed on `auth_query.shop` is via `Utils::HmacValidator.validate(auth_query)`, which verifies that the `hmac` field matches an HMAC over `code, host, shop, state, timestamp` computed with `Context.api_secret_key`: [8](#0-7) [9](#0-8) 

This HMAC check only proves that whoever produced the `AuthQuery` params also knows `api_secret_key` (i.e. it authenticates that the *callback query* was signed correctly) — it does **not** bind `shop` to a value that Shopify's own servers chose, nor does it check that `shop` resolves to `*.myshopify.com`/other trusted domains. The binding that is actually needed here — `host that receives client_secret == a trusted Shopify domain` — is never established; only `hmac(params) == computed_hmac(params)` is checked, which is an unrelated equality. Because `AuthQuery` is normally built directly from raw HTTP request/query parameters supplied by the host application (see `docs/usage/oauth.md` example `ShopifyAPI::Auth::Oauth::AuthQuery.new(request.parameters...)`), and the `shop` value in `begin_auth` typically also originates from an inbound HTTP parameter, nothing in this gem stops a `shop` value pointing at an attacker-controlled host from reaching `auth_base_uri`/`Clients::HttpClient` construction.

### Impact Explanation
If a value other than a genuine `*.myshopify.com` (or other trusted) domain reaches `shop`/`auth_query.shop`, `validate_auth_callback` will POST a body containing `client_id` and `client_secret` (`Context.api_secret_key`) to `https://#{shop}/admin/oauth/access_token`, i.e. an attacker-controlled host. This is a direct SSRF carrying the app's `client_secret` to an arbitrary destination — matching the "High: SSRF with the app's credentials" impact category. `begin_auth` similarly can redirect merchants/users to an arbitrary attacker-controlled "authorize" URL, enabling forced/hijacked OAuth flows.

### Likelihood Explanation
Every sibling auth entry point (`ClientCredentials`, `RefreshToken`, `TokenExchange.migrate_to_expiring_token`) treats `shop` as untrusted input and explicitly sanitizes it with `ShopValidator.sanitize!` before using it to build request hosts. `Oauth.begin_auth`/`validate_auth_callback` is the sole exception, and its own documentation shows the `shop`/`AuthQuery` values coming straight from inbound HTTP request parameters, making this an easily reachable, unprivileged-input code path rather than a purely theoretical gap.

### Recommendation
In `lib/shopify_api/auth/oauth.rb`, validate `shop` (in `begin_auth`) and `auth_query.shop` (in `validate_auth_callback`) with `Utils::ShopValidator.sanitize!` before using them to construct `auth_base_uri` or the `Session`/`HttpClient` used for the token exchange request, mirroring the pattern already used in `client_credentials.rb`, `refresh_token.rb`, and `token_exchange.rb#migrate_to_expiring_token`.

### Proof of Concept
1. Attacker crafts a link to the host application's OAuth start route with `shop=attacker-controlled.example.com` (or embeds it as the initial `shop` query param that the app forwards into `Oauth.begin_auth(shop: ...)`).
2. `begin_auth` calls `auth_base_uri("attacker-controlled.example.com")`, producing `https://attacker-controlled.example.com/admin/oauth/authorize?...`, and the merchant/user is redirected there instead of Shopify.
3. Separately/alternatively, if the host application builds `AuthQuery` straight from callback request parameters (as shown in the gem's own docs) and an attacker can influence that flow so `shop` names an attacker's host while still completing the request (e.g., a misconfigured/rogue "callback" hitting the app with a valid-looking payload), `validate_auth_callback` executes:
```ruby
client = Clients::HttpClient.new(session: Auth::Session.new(shop: auth_query.shop), base_path: "/admin/oauth")
client.request(Clients::HttpRequest.new(http_method: :post, path: "access_token",
  body: { client_id: Context.api_key, client_secret: Context.api_secret_key, code: auth_query.code, expiring: ... }))
```
sending `client_secret` to `https://#{auth_query.shop}/admin/oauth/access_token` — a host that was never checked against `Utils::ShopValidator::TRUSTED_SHOPIFY_DOMAINS`.

        def begin_auth(shop:, redirect_path:, is_online: true, scope_override: nil)
          scope = if scope_override.nil?
            ShopifyAPI::Context.scope
          elsif scope_override.is_a?(ShopifyAPI::Auth::AuthScopes)
            scope_override
          else
            ShopifyAPI::Auth::AuthScopes.new(scope_override)
          end

          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = SecureRandom.alphanumeric(NONCE_LENGTH)

          cookie = SessionCookie.new(value: state, expires: Time.now + 60)

          query = {
            client_id: ShopifyAPI::Context.api_key,
            scope: scope.to_s,
            redirect_uri: "#{ShopifyAPI::Context.host}#{redirect_path}",
            state: state,
            "grant_options[]": is_online ? "per-user" : "",
          }

          query_string = URI.encode_www_form(query)
          auth_route = auth_base_uri(shop) + "/oauth/authorize?#{query_string}"

          { auth_route: auth_route, cookie: cookie }
        end

        def validate_auth_callback(cookies:, auth_query:)
          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::InvalidOauthError, "Invalid OAuth callback." unless Utils::HmacValidator.validate(auth_query)
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = cookies[SessionCookie::SESSION_COOKIE_NAME]
          raise Errors::NoSessionCookieError unless state

          raise Errors::InvalidOauthError,
            "Invalid state in OAuth callback." unless state == auth_query.state

          null_session = Auth::Session.new(shop: auth_query.shop)
          body = {
            client_id: Context.api_key,
            client_secret: Context.api_secret_key,
            code: auth_query.code,
            expiring: Context.expiring_offline_access_tokens ? 1 : 0, # Only applicable for offline tokens
          }

          client = Clients::HttpClient.new(session: null_session, base_path: "/admin/oauth")
          response = begin
            client.request(
              Clients::HttpRequest.new(
                http_method: :post,
                path: "access_token",
                body: body,
                body_type: "application/json",
              ),
            )
          rescue ShopifyAPI::Errors::HttpResponseError => e
            raise Errors::RequestAccessTokenError,
              "Cannot complete OAuth process. Received a #{e.code} error while requesting access token."
          end

        sig { params(shop: String).returns(String) }
        def auth_base_uri(shop)
          return "https://#{shop}/admin" unless defined?(DevServer) && shop.include?(".my.shop.dev")

          # For first-party apps in development only, we leverage DevServer to build the admin base URI
          admin_web = T.unsafe(Object.const_get("DevServer")) # rubocop:disable Sorbet/ConstantsFromStrings
            .new("admin-web")
          admin_host = admin_web.host!(nonstandard_host_prefix: "admin")
          shop_name = shop.split(".").first

          "https://#{admin_host}/store/#{shop_name}"
        end
