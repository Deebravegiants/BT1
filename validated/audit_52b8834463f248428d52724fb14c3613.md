### Title
Bad-debt wipeout revives supplier shares at the supply-index floor, allowing withdrawal of post-cleanup liquidity - (File: contracts/pool/src/interest.rs)

### Summary
A total bad-debt write-down is supposed to reduce all supplier claims to zero, but `apply_bad_debt_to_supply_index` clamps the resulting supply index upward to `SUPPLY_INDEX_FLOOR_RAW`, preserving a nonzero claim for every old supply share. [1](#0-0)  A wiped supplier can therefore call the controller `withdraw` path after another user recapitalizes the market and receive tokens backed by the new liquidity. [2](#0-1) [3](#0-2) 

### Finding Description
The permissionless controller `clean_bad_debt(caller, account_id)` entrypoint accepts an insolvent dust-collateral account and sends all of its borrow positions to the pool as `PoolSeizeEntry` records. [4](#0-3) [5](#0-4) 

For each seized borrow position, the pool converts the debt shares to a RAY-denominated bad-debt amount, calls `apply_bad_debt_to_supply_index`, and burns the debt. [6](#0-5)  When `bad_debt >= total_supplied_value`, `remaining` is zero and `new_supply_index` is zero, but line 88 replaces it with `SUPPLY_INDEX_FLOOR_RAW`. [7](#0-6) 

The old `supplied` share total is not burned or invalidated, so every pre-wipe position retains a claim equal to approximately `scaled_supply * RAY / 1000`. [8](#0-7)  A subsequent `withdraw` resolves the requested payout from those still-recorded shares and checks reserves, utilization, and nonzero supply, but does not reject a market whose pre-withdrawal claims are unsupported. [9](#0-8) [3](#0-2) 

An attacker can reach this through:

1. `supply(caller=attacker, account_id=0, spoke_id=S, assets=[((H,X), amount)])`, creating supply shares.
2. `clean_bad_debt(caller=attacker, account_id=victim)` after that account's debt exceeds its collateral and passes the dust gate.
3. A third party calls `recapitalize(caller=victim_recapitalizer, hub_asset=(H,X), amount=R)`, which credits up to the measured backing shortfall as pool cash. [10](#0-9) 
4. `withdraw(caller=attacker, account_id=attacker_account, withdrawals=[((H,X),0)], to=Some(attacker))`, where zero selects withdraw-all at the controller layer. [11](#0-10) 

### Impact Explanation
The write-down is intended to socialize a total loss across suppliers, but the floor creates residual claims that were economically wiped out. [12](#0-11)  Tokens later injected by `recapitalize`, or otherwise credited as market cash, can be paid to those stale claims instead of remaining available for valid suppliers and borrowers. [10](#0-9) [13](#0-12) 

This causes theft of user funds and immediately recreates a backing shortfall after the residual withdrawal, producing protocol insolvency in the affected `(hub_id, asset)` market. [14](#0-13) 

### Likelihood Explanation
Triggering the bug requires a complete or near-complete bad-debt wipeout, which is a stressed-market condition rather than an arbitrary one-transaction exploit. [15](#0-14)  Once that state exists, both cleanup and withdrawal are unprivileged, and any subsequent recapitalization creates withdrawable cash. [4](#0-3) [2](#0-1) 

### Recommendation
Do not clamp a fully wiped supply index to a nonzero value while retaining the old `supplied` share set. [16](#0-15)  Track a market wipeout epoch or generation and permanently invalidate pre-wipe supply positions, or explicitly clear all corresponding controller-side supply positions before allowing the market to accept cash again. [17](#0-16)  Add an end-to-end regression test that performs `supply → total bad-debt cleanup → third-party recapitalize → withdraw` and asserts that the wiped supplier receives zero. [10](#0-9) 

### Proof of Concept
1. Attacker calls `supply` with `account_id=0` and deposits `1_000_000` units of asset `X`, receiving `1_000_000 * RAY` scaled supply at `supply_index = RAY`. [18](#0-17) 
2. A separate account's `X` debt becomes bad debt greater than or equal to the value of all `X` supply. [15](#0-14) 
3. Attacker calls `clean_bad_debt(attacker, victim_account_id)`, causing the pool to seize and burn the victim's borrow position. [19](#0-18) [6](#0-5) 
4. `remaining` becomes zero, so the calculated index is zero, but the floor sets `supply_index = RAY / 1000`; the attacker's old shares now retain a `1_000`-unit claim instead of being zeroed. [7](#0-6) [8](#0-7) 
5. A recapitalizer calls controller `recapitalize` for `(H,X)`; the pool credits the contributed amount to `cash` up to the backing shortfall. [2](#0-1) 
6. Attacker calls `withdraw(attacker, attacker_account_id, [((H,X),0)], Some(attacker))`; withdraw-all resolves the stale shares at the floored index, passes the reserve check using the recapitalizer's cash, and transfers the residual claim to the attacker. [20](#0-19) [3](#0-2)

```rust
/// Socializes `bad_debt` by reducing the supply index (capped at total supply value).
///
/// Used when seizing unpaid debt: remaining supplier claims shrink pro-rata.
/// No-op when total supplied value is zero. Floors the resulting index at
/// [`SUPPLY_INDEX_FLOOR_RAW`] to avoid a zero index.
pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}
```

```rust
/// Credits `min(amount, backing_shortfall)` to cash and commits. `refund` is
/// `amount - applied`.
pub(crate) fn accounting(
    env: &Env,
    hub_asset: HubAssetKey,
    amount: i128,
) -> RecapitalizationOutcome {
    require_nonneg_amount(env, amount);
    let mut cache = ops::renewed_market(env, &hub_asset);

    let applied = amount.min(guards::backing_shortfall(&cache));
    let refund = amount
        .checked_sub(applied)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));

    cache.credit_cash(applied);
    cache.commit();
```

```rust
/// Asset units by which supplier claims exceed cash + debt (0 if solvent).
pub(crate) fn backing_shortfall(cache: &Cache) -> i128 {
    let supplied_claim = cache.unscale_supply_floor(cache.supplied());
    let outstanding_debt = cache.unscale_borrow_ceil(cache.borrowed());
    let backing = cache.cash().saturating_add(outstanding_debt);
    supplied_claim.saturating_sub(backing).max(0)
}
```
