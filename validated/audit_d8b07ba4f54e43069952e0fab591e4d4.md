Audit Report

## Title
Legacy WebAPI trigger handler admits unauthenticated-caller requests to all DON nodes with no allowlist or rate limiting - (File: core/services/gateway/handlers/capabilities/handler.go)

## Summary
The Gateway's legacy `web_api_trigger` path (`HandleLegacyUserMessage` in `core/services/gateway/handlers/capabilities/handler.go`) validates only payload structure and message freshness before broadcasting the request to every DON member node via `don.SendToNode` and storing state in an unbounded `savedCallbacks` map. There is no allowlist or rate-limiting check on this admission path — it is explicitly marked with `// TODO: apply allowlist and rate-limiting here` — allowing any party who can produce a validly-signed but otherwise unauthorized message to trigger fan-out to all nodes.

## Finding Description
`gateway.ProcessRequest` calls `msg.Validate()` before dispatching to the legacy handler; `Validate()` (in `core/services/gateway/api/message.go`) only checks field lengths/null-termination and recovers a signer address from an arbitrary ECDSA signature — it does not check DON membership or any allowlist. `HandleLegacyUserMessage` then checks payload decodability and staleness, and immediately afterward stores the request in `h.savedCallbacks` and loops over `h.donConfig.Members` calling `don.SendToNode` for each, with the allowlist/rate-limit gate left as an unimplemented TODO comment directly above this code. The `handler` struct's only rate limiter (`nodeRateLimiter`) is used solely for outbound node→gateway traffic (`handleWebAPIOutgoingMessage`), never for inbound user requests. This contrasts with the v2 `httpTriggerHandler.checkRateLimit` and the vault handler's `Authorizer`, both of which gate admission before dispatching work.

## Impact Explanation
An unprivileged network caller with no DON-specific credential can repeatedly submit signed `web_api_trigger` requests to the Gateway's `/user`-style endpoint, causing unbounded fan-out to every node of a target DON per request and unbounded growth of the `savedCallbacks` map between prune cycles. This is a resource-exhaustion/flooding vector against the Gateway and all backing DON nodes, sourced from a single caller requiring no allowlisted identity — mapping to Chainlink's gateway request/resource-abuse impact category.

## Likelihood Explanation
High. Constructing a valid request requires only generating an arbitrary ECDSA keypair, signing a well-formed, non-stale payload as shown by the codebase's own `triggerRequest` test helper, and POSTing it to the gateway repeatedly — no DON membership or prior registration is required, and the existing "happy case" test in `handler_test.go` demonstrates this flow succeeds with a fabricated key.

## Recommendation
Implement caller authorization (allowlist/topic-based) and per-sender/per-topic rate limiting before `don.SendToNode` dispatch and before inserting entries into `savedCallbacks`, mirroring `httpTriggerHandler.checkRateLimit` (v2) and the vault handler's `Authorizer` pattern. Add regression tests verifying an unauthorized or rate-limited `web_api_trigger` request is rejected prior to any `SendToNode` call or `savedCallbacks` insertion.

## Proof of Concept
1. Generate an arbitrary ECDSA keypair (no DON registration needed).
2. Build a `web_api_trigger` `api.Message` with a fresh timestamp and valid `TriggerRequestPayload`, sign with the arbitrary key (as in `triggerRequest` helper in `handler_test.go`).
3. Submit repeatedly via `gateway.ProcessRequest`.
4. Observe each request passes staleness/decoding checks, is stored in `savedCallbacks`, and is broadcast via `don.SendToNode` to every DON member with no allowlist/rate-limit rejection — reproducible via the existing "happy case" test in `handler_test.go`.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageID) == 0 || len(m.Body.MessageID) > MessageIDMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageID, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonID) == 0 || len(m.Body.DonID) > MessageDonIDMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonID, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}
