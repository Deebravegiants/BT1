### Title
Multi-wavelength capture silently accepts missing 940nm/740nm frames as complete - ([File: src/plans/biometric_capture/multi_wavelength.rs])

### Summary
`Plan::perform_multi_wavelength` in [1](#0-0)  drives extra-wavelength (940nm/740nm) IR capture using a fixed timer and unconditionally breaks out of the capture loop once the timer fires, regardless of whether `handle_ir_eye_camera` ever populated the corresponding frame slot. If the IR camera/agent is stalled or slow for the duration of the timer, the `Option<camera::ir::Frame>` slots stay `None` and the plan proceeds exactly as if the frames had been captured.

### Finding Description
The state machine transitions to `State::ExtraWavelength` and only records a frame if `handle_ir_eye_camera` is called and delivers output before the timer expires: [2](#0-1) . The only exit condition from this state is `poll_extra`, which breaks purely on timer expiry with no check that a frame was actually received: [3](#0-2) . `perform_multi_wavelength` calls `orb.run(self)` twice (once per wavelength) each gated only by `AUTO_EXPOSURE_WAIT_TIME`, and then unconditionally re-enables IR net/autofocus/PID and returns `Ok(()))` with no verification of the captured slots: [1](#0-0) . The resulting `Option` values (`None` on starvation) are copied directly into the final `Output.capture` fields without any check or error path: [4](#0-3) . An attacker who can stall the IR eye camera agent for ~400ms per wavelength (e.g., via scene/timing manipulation causing the sensor/agent pipeline to be slow or momentarily unresponsive) can cause both extra-wavelength slots to remain `None` while the overall biometric capture flow (`run`) still completes successfully, since `biometric_capture.run_check` is unrelated to these wavelength fields.

### Impact Explanation
This file itself contains no downstream verdict logic that rejects a signup when the 940nm/740nm frames are missing — the absence is silently propagated as `None` into the final `Output`. I was unable to fully confirm, within the available tool budget, whether the consumers of `capture.eye_left.ir_frame_940nm`/`ir_frame_740nm` (in `src/plans/biometric_capture/mod.rs` and `src/agents/image_notary.rs`, both of which reference these fields) enforce their presence as a mandatory anti-spoofing/liveness gate downstream, or merely treat them as optional enrichment data. If those consumers rely on presence-checks to decide pass/fail (multi-wavelength material response is a common anti-spoofing signal against printed/screen presentation attacks), then this code path represents exactly the "missing signal treated as pass" flaw described in the question: a starved sensor produces `None`, and `None` is never converted into a hard failure anywhere in `multi_wavelength.rs`.

### Likelihood Explanation
Preconditions are limited to causing the IR camera agent to not deliver a frame within `AUTO_EXPOSURE_WAIT_TIME` (400ms) during either extra-wavelength window — plausible via scene conditions, IR LED timing interference, or transient agent unresponsiveness, all of which fall within "scene/timing conditions that starve the signal" as scoped by the question. No privileged access is required.

### Recommendation
In `poll_extra` (or after each `orb.run(self)` call in `perform_multi_wavelength`), verify that the relevant frame slot (`left_940nm`/`left_740nm`/`right_940nm`/`right_740nm`) was actually populated before breaking out of `State::ExtraWavelength`. If the slot remains `None` after the timer expires, treat it as a hard failure (retry the capture or fail the overall biometric capture) rather than silently continuing with `None`. Any downstream consumer that uses these fields for a fraud/liveness decision should explicitly reject on `None` rather than treating missing data as equivalent to a passing check.

### Proof of Concept
Add a fault-injection unit test for `multi_wavelength::Plan`:
1. Construct a `Plan` wrapping a `biometric_capture::Plan` with `target_left_eye = true`.
2. Drive `orb.run(&mut plan)` such that `handle_ir_eye_camera` is never invoked during the `ExtraWavelength` state for the 940nm window (simulate a stalled camera agent), but let the timer in `poll_extra` fire normally.
3. Assert that `perform_multi_wavelength` returns `Ok(())` and that `self.left_940nm.is_none()` after the call — confirming the plan proceeds without signaling failure.
4. Extend the test to run `Plan::run` to completion and assert that `output.capture.eye_left.ir_frame_940nm` is `None` in the final `Output`, while the overall result is still `Ok`, demonstrating that the missing signal is silently accepted rather than causing a hard failure.

    fn handle_ir_eye_camera(
        &mut self,
        orb: &mut Orb,
        output: port::Output<camera::ir::Sensor>,
    ) -> Result<BrokerFlow> {
        match &self.state {
            State::Normal => self.biometric_capture.handle_ir_eye_camera(orb, output),
            State::ExtraWavelength { target_left_eye, target_740nm, .. } => {
                let slot = match (target_left_eye, target_740nm) {
                    (true, true) => &mut self.left_740nm,
                    (true, false) => &mut self.left_940nm,
                    (false, true) => &mut self.right_740nm,
                    (false, false) => &mut self.right_940nm,
                };
                *slot = Some(output.value);
                Ok(BrokerFlow::Continue)
            }
        }
    }

    fn poll_extra(&mut self, orb: &mut Orb, cx: &mut Context<'_>) -> Result<BrokerFlow> {
        match &mut self.state {
            State::Normal => self.biometric_capture.poll_extra(orb, cx),
            State::ExtraWavelength { timer, .. } => {
                if let Poll::Ready(()) = timer.poll_unpin(cx) {
                    Ok(BrokerFlow::Break)
                } else {
                    Ok(BrokerFlow::Continue)
                }
            }
        }

    async fn perform_multi_wavelength(&mut self, orb: &mut Orb) -> Result<()> {
        orb.disable_ir_net();
        orb.disable_ir_auto_focus();
        orb.disable_eye_pid_controller();

        tracing::info!("Multi-wavelength extension: capturing 940nm");
        orb.set_ir_wavelength(IrLed::L940).await?;
        orb.set_ir_duration(1500)?;
        self.state = State::ExtraWavelength {
            timer: Box::pin(time::sleep(AUTO_EXPOSURE_WAIT_TIME)),
            target_left_eye: self.biometric_capture.target_left_eye,
            target_740nm: false,
        };
        orb.run(self).await?;

        tracing::info!("Multi-wavelength extension: capturing 740nm");
        orb.set_ir_wavelength(IrLed::L740).await?;
        orb.set_ir_duration(200)?;
        self.state = State::ExtraWavelength {
            timer: Box::pin(time::sleep(AUTO_EXPOSURE_WAIT_TIME)),
            target_left_eye: self.biometric_capture.target_left_eye,
            target_740nm: true,
        };
        orb.run(self).await?;

        orb.enable_ir_net().await?;
        orb.enable_ir_auto_focus()?;
        orb.enable_eye_pid_controller()?;
        self.state = State::Normal;
        Ok(())
    }
