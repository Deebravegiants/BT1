### Title
Silently swallowed per-chunk errors in `query_ismp_events` cause the relayer to permanently skip requests/responses - (File: `tesseract/messaging/evm/src/provider.rs`, `tesseract/messaging/substrate/src/provider.rs`)

### Summary
`query_ismp_events` on both the EVM and Substrate providers splits a block range into chunks and queries each one independently. If a chunk query fails, the error is only logged, and the function still returns `Ok(events)` containing whatever it managed to collect from the *other* chunks, silently dropping the events from the failed chunk. Every caller of this function (`outbound.rs`, `byzantine.rs`, EVM/Substrate `state_machine_update_notification`) treats the `Ok` return as "the whole range was scanned" and unconditionally advances its cursor/`latest_height` to the target height, so the missed block range is never re-queried. This is structurally identical to the Canto `processEvents` bug: a sub-operation that can fail is not propagated as an error, and the caller proceeds as if everything succeeded, permanently losing state.

### Finding Description
`query_ismp_events` chunks the height range and, on a per-chunk RPC error, only logs and continues rather than returning `Err`: [1](#0-0) 

The same pattern exists on the Substrate side: [2](#0-1) 

Every consumer of this function only branches on the outer `Result`, and on `Ok` immediately advances its height cursor to the new tip — with no way to know that some sub-range inside `[cursor+1, new_height]` was actually skipped due to an internal error:

- The main outbound fan-out loop calls `hyperbridge.query_ismp_events(cursor, synth)`, and only checks the outer `Err` case (`continue`s on outer error); on `Ok` it proceeds to process `events` and later sets `cursor = new_height` unconditionally, regardless of whether an inner chunk failed: [3](#0-2) [4](#0-3) 

- The EVM `state_machine_update_notification` background poller does the same: it matches on `Ok(events)`/`Err(err)` at the outer level and, on the `Ok` branch, proceeds to use `events` and does not roll `latest_height` back to retry the missed sub-range: [5](#0-4) 

- The Substrate `byzantine.rs` polling loop and `provider.rs::state_machine_update_notification` follow the identical pattern: [6](#0-5) [7](#0-6) 

Because the height cursor advances past the failed chunk regardless, any `PostRequest`, `PostResponse`, or `GetResponse` event emitted within the dropped sub-range is never observed by the relayer again. There is no separate re-scan of historical ranges once the cursor has moved forward, so these events are permanently invisible to the outbound/inbound relaying pipeline that is responsible for delivering them to the destination chain.

### Impact Explanation
A transient RPC failure on a single chunk (rate limiting, node hiccup, timeout) causes the relayer to silently and permanently skip all ISMP events emitted in that chunk's block range. Any request dispatched by a user/application in that window (funds escrowed via `IDispatcher`/pallet-ismp `dispatch_request`) will never be picked up for delivery — it can neither be relayed to the destination nor be actively rejected, so it will eventually only be resolved via timeout (if a timeout was configured and the app support timeouts), otherwise the escrowed relayer fee/funds are frozen indefinitely since the natural delivery path never re-visits that height range. This matches "permanent freezing of funds" / "a route unable to deliver messages" for a normal, unprivileged request dispatched by any user.

### Likelihood Explanation
Chunk-level RPC failures are a normal occurrence (rate limits, provider hiccups, transient network errors) and are explicitly anticipated by the existing `log::error!` handling — the code is written expecting these errors to occur regularly. Since the failure is swallowed rather than propagated, there is no operator-visible signal (beyond a log line among many) that any messages were dropped, making this a realistic, moderate/likely-to-occur scenario rather than a purely theoretical edge case.

### Recommendation
Propagate chunk-query failures out of `query_ismp_events` (e.g., return `Err` for the whole call, or return a partial success alongside the exact block sub-range that failed) so callers can retain the un-scanned range and retry it on the next pass instead of unconditionally advancing the cursor/`latest_height` past it. Alternatively, track the last *successfully scanned* height separately from the notified tip height, and only advance the cursor to the last fully-scanned height.

### Proof of Concept
1. Relayer is watching Hyperbridge (or an EVM/Substrate destination) via `query_ismp_events(previous_height, event)` where the range spans multiple chunks because it fell behind (e.g. was offline) or `query_batch_size`/`chunk_size` is small.
2. A user dispatches a `PostRequest` in block `H`, which falls inside chunk `i` of the range.
3. The RPC call for chunk `i` (`self.events(start, end)` / `ismp_queryEvents`) transiently fails (rate limit / timeout) while other chunks succeed.
4. `query_ismp_events` logs the error for chunk `i` and returns `Ok(events)` containing only chunks that succeeded.
5. The calling loop (`outbound.rs::run` or the EVM/Substrate background poller) sees `Ok`, processes the partial `events`, and sets `cursor = new_height` (or `latest_height = block_number`), i.e. past block `H`.
6. On the next iteration, `query_ismp_events` is called with `previous_height = new_height`, so block `H`'s range is never queried again.
7. The user's `PostRequest` from block `H` is never translated into a delivery message; its escrowed fee/funds remain locked with no relayer ever discovering and delivering (or timing it out via the delivery path) the request.

	async fn query_ismp_events(
		&self,
		previous_height: u64,
		event: StateMachineUpdated,
	) -> Result<Vec<Event>, Error> {
		let full_range = (previous_height + 1)..=event.latest_height;
		if full_range.is_empty() {
			return Ok(Default::default());
		}

		let mut events = vec![];
		let chunk_size = self.config.query_batch_size.unwrap_or(1_000_000_000);
		let chunks = full_range.end().saturating_sub(*full_range.start()) / chunk_size;
		for i in 0..=chunks {
			let start = (i * chunk_size) + *full_range.start();
			let end = if i == chunks { *full_range.end() } else { start + chunk_size - 1 };
			let result = self.events(start, end).await;
			match result {
				Ok(batch) => events.extend(batch),
				Err(err) => {
					log::error!(
						target: crate::LOG_TARGET, "Error while querying events in range {}..{} from {:?}: {err:?}",
						start,
						end,
						self.state_machine
					);
				},
			}
		}

		Ok(events)
	}

	async fn query_ismp_events(
		&self,
		previous_height: u64,
		event: StateMachineUpdated,
	) -> Result<Vec<Event>, anyhow::Error> {
		let range = (previous_height + 1)..=event.latest_height;
		if range.is_empty() {
			return Ok(Default::default());
		}

		let mut events = vec![];
		let chunk_size = 100;
		let chunks = range.end().saturating_sub(*range.start()) / chunk_size;
		for i in 0..=chunks {
			let start = (i * chunk_size) + *range.start();
			let end = if i == chunks { *range.end() } else { start + chunk_size - 1 };
			let params = rpc_params![
				BlockNumberOrHash::<H256>::Number(start as u32),
				BlockNumberOrHash::<H256>::Number(end as u32)
			];
			let response = self
				.rpc_client
				.request::<HashMap<String, Vec<Event>>>("ismp_queryEvents", params)
				.await;
			match response {
				Ok(response) => {
					let batch = response.values().into_iter().cloned().flatten();
					events.extend(batch)
				},
				Err(err) => {
					log::error!(
						target: crate::LOG_TARGET, "Error while querying events in range {}..{} from {:?}: {err:?}",
						start,
						end,
						self.state_machine
					);
				},
			}
		}

		Ok(events)
	}
