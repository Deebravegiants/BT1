### Title
CORS wildcard origin matching in the Gateway HTTP server is too lax, permitting subdomain/prefix spoofing bypass - (File: core/services/gateway/network/httpserver.go)

### Summary
The Chainlink Gateway's HTTP server implements a CORS allowlist check that supports wildcard entries such as `*.remix.com`. The wildcard match is implemented with a plain `strings.HasSuffix` comparison, without verifying a `.` boundary between the attacker-supplied origin's prefix and the allowed suffix. This mirrors the syslog-ng CVE-2024-47619 bug class: "wildcard matching too lax," where a suffix/substring based hostname match accepts strings that are not legitimate subdomains.

### Finding Description
`isAllowedOrigin` strips the `*.` prefix from a configured wildcard entry and then checks `strings.HasSuffix(originHost, allowedHost)`: [1](#0-0) 

Because `HasSuffix` performs a raw string-suffix comparison rather than a label-boundary-aware domain suffix check, any origin host that merely *ends with* the allowed domain string is accepted — e.g. if the operator configures `*.remix.com`, the check will also accept `evilremix.com` or `attacker-remix.com`, neither of which is a subdomain of `remix.com`. The origin is taken directly from the attacker-controlled `Origin` request header: [2](#0-1) 

If `isAllowedOrigin` returns true, the server reflects the attacker's `Origin` value back verbatim in `Access-Control-Allow-Origin`, granting that arbitrary origin cross-origin access to the gateway's HTTP endpoint.

### Impact Explanation
This is reachable by any unprivileged network client capable of sending a crafted `Origin` header from a browser context they control (e.g., hosting `evil-remix.com` or `attackerremix.com`). If an operator configures a wildcard CORS entry (a documented, supported feature), an attacker-registered domain that merely shares the suffix string can be granted CORS access to the gateway's `/` message endpoint, enabling cross-origin reads of gateway responses from victims' browsers when a legitimate wildcarded origin was intended to be trusted (e.g. `*.remix.com` mistakenly trusting `evilremix.com`). This is a request/response confusion vector, matching the "cross-user response confusion" category, mediated purely through the internet-facing gateway HTTP handler.

### Likelihood Explanation
Exploitability depends on an operator having configured a wildcard CORS entry in `CORSAllowedOrigins` (a supported config pattern per the code's own wildcard-handling logic and referenced in `core/scripts/gateway/sample_config.toml`). Given wildcards are an intentional, documented feature of this allowlist, and domain-suffix squatting (registering a domain that ends with a trusted suffix) is trivial and cheap for an attacker, likelihood is moderate-to-high wherever wildcard CORS entries are used.

### Recommendation
Fix the wildcard suffix check to require a proper label boundary, e.g.:
```go
if strings.HasPrefix(allowedHost, "*.") {
    allowedHost = allowedHost[2:]
    if originHost == allowedHost || strings.HasSuffix(originHost, "."+allowedHost) {
        return true
    }
}
```
This ensures `evilremix.com` no longer matches `*.remix.com`, while legitimate subdomains like `sub.remix.com` continue to match.

### Proof of Concept
1. Operator configures `CORSAllowedOrigins = ["https://*.remix.com"]`.
2. Attacker registers `https://evilremix.com` (or `https://attacker-remix.com`) and serves a page there.
3. A victim's browser (or attacker's own script) sends a cross-origin request to the gateway with `Origin: https://evilremix.com`.
4. `isAllowedOrigin` computes `allowedHost = "remix.com"` and checks `strings.HasSuffix("evilremix.com", "remix.com")`, which is `true`.
5. The gateway responds with `Access-Control-Allow-Origin: https://evilremix.com`, granting the attacker's origin CORS access it should not have received. [3](#0-2)

func (s *httpServer) isAllowedOrigin(origin string) bool {
	originScheme, originHost, originPort, err := s.splitURL(origin)
	if err != nil {
		s.lggr.Debug("error parsing origin URL", err)
		return false
	}
	for _, allowed := range s.config.CORSAllowedOrigins {
		// probably better to do this once when server starts and store it in a map
		// this is an easier solution so we don't have to apply more changes to the code
		// just need to be careful when specifying allowed origins in the config file
		allowedScheme, allowedHost, allowedPort, err := s.splitURL(allowed)
		if err != nil {
			s.lggr.Debug("error parsing allowed origin URL", err)
			continue
		}
		// skip if the scheme doesn't match at all
		if originScheme != allowedScheme {
			continue
		}
		// skip if the port doesn't match at all
		if originPort != allowedPort {
			continue
		}
		// check for exact host match (e.g., remix.com)
		if originHost == allowedHost {
			return true
		}
		// check for wildcard host match (e.g., *.remix.com)
		if strings.HasPrefix(allowedHost, "*.") {
			allowedHost = allowedHost[2:]
			if strings.HasSuffix(originHost, allowedHost) {
				return true
			}
		}
	}
	return false
}
