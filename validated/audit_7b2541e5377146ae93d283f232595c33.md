Audit Report

## Title
Broken Access Control: `/v2/external_initiators` Index Leaks Outgoing Credentials to Any Authenticated Role - (File: core/web/router.go)

## Summary
The `GET /v2/external_initiators` route is registered under the `authv2` group with only base authentication, unlike its sibling `Create`/`Destroy` routes which are wrapped with `auth.RequiresEditRole`. This allows any authenticated user, including one with the lowest-privilege `UserRoleView`, to enumerate all `ExternalInitiator` records including their `OutgoingToken` secret via `ExternalInitiatorsController.Index`.

## Finding Description
`v2Routes` in `core/web/router.go` mounts `GET /external_initiators` with no role wrapper: `authv2.GET("/external_initiators", paginatedRequest(eia.Index))`, while `POST` and `DELETE` on the same resource are wrapped with `auth.RequiresEditRole(eia.Create)` and `auth.RequiresEditRole(eia.Destroy)` respectively, as seen at [1](#0-0) . `ExternalInitiatorsController.Index` fetches all initiators and serializes them via `presenters.NewExternalInitiatorResource`, shown at [2](#0-1) . The presenter includes the `OutgoingToken` field in its JSON output for every listed initiator, as defined at [3](#0-2) . This `OutgoingToken` is the same secret generated at creation time and used by the node to authenticate its own outgoing calls to the initiator's URL, per [4](#0-3) .

The `authv2` group only requires successful authentication via `AuthenticateByToken` or `AuthenticateBySession` — it does not enforce any minimum role by itself, confirmed at [5](#0-4) . The role-gating middleware `RequiresRunRole`/`RequiresEditRole`/`RequiresAdminRole` in `core/web/auth/auth.go` is what actually restricts access by role, and since `Index` lacks any such wrapper, a `UserRoleView` session passes straight through to the handler, per [6](#0-5) .

## Impact Explanation
A user or token provisioned with only `UserRoleView` (the lowest, intended-read-only role) can retrieve `OutgoingToken` secrets for every configured `ExternalInitiator` via a single GET request. This token is used by the node to authenticate itself to the external initiator's endpoint, so its disclosure enables impersonation of the node when calling back into the initiator's API. This is a concrete secret/credential exfiltration through a broken role-based access control gate — an in-scope impact category (key/secret exfiltration and node API role bypass).

## Likelihood Explanation
Exploitation requires only a valid authenticated session or API token of any role, including the lowest `view` role, which is a normal, unprivileged-relative-to-this-resource credential that operators commonly provision for read-only dashboard/monitoring access. No admin/edit privilege, no host access, and no social engineering is required — a single authenticated GET request against a default-configured node with any existing `ExternalInitiator` records reproduces the leak reliably.

## Recommendation
Wrap the `Index` route with `auth.RequiresEditRole` (or at minimum `RequiresRunRole`) to match the sensitivity of the returned data, consistent with `Create`/`Destroy`. Additionally, consider removing `OutgoingToken`/`OutgoingSecret` from `ExternalInitiatorResource` entirely, exposing such secrets only once at creation time via `ExternalInitiatorAuthentication`, as is already done for `Create`.

## Proof of Concept
1. Create a user with `clsessions.UserRoleView` (or issue a view-scoped API token) and have an `edit`/`admin` user create at least one `ExternalInitiator` via `POST /v2/external_initiators`.
2. Authenticate as the `view`-role user via `POST /sessions` (or `X-API-KEY`/`X-API-SECRET` headers) to obtain a valid session/token.
3. Issue `GET /v2/external_initiators` with that session/token.
4. Observe the JSON:API response contains `outgoingToken` for each `ExternalInitiator`, confirming the leak — no `403 Forbidden`/`401` is returned despite the low-privilege role, in contrast to attempting `POST`/`DELETE` on the same resource which correctly returns `401 Unauthorized` for a `view`-role session per `RequiresEditRole`.

func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}

// ExternalInitiator represents a user that can initiate runs remotely
type ExternalInitiator struct {
	ID             int64
	Name           string
	URL            *models.WebURL
	AccessKey      string
	Salt           string
	HashedSecret   string
	OutgoingSecret string
	OutgoingToken  string

	CreatedAt time.Time
	UpdatedAt time.Time
}

// NewExternalInitiator generates an ExternalInitiator from an
// auth.Token, hashing the password for storage
func NewExternalInitiator(
	eia *auth.Token,
	eir *ExternalInitiatorRequest,
) (*ExternalInitiator, error) {
	salt := utils.NewSecret(utils.DefaultSecretSize)
	hashedSecret, err := auth.HashedSecret(eia, salt)
	if err != nil {
		return nil, pkgerrors.Wrap(err, "error hashing secret for external initiator")
	}

	return &ExternalInitiator{
		Name:           strings.ToLower(eir.Name),
		URL:            eir.URL,
		AccessKey:      eia.AccessKey,
		HashedSecret:   hashedSecret,
		Salt:           salt,
		OutgoingToken:  utils.NewSecret(utils.DefaultSecretSize),
		OutgoingSecret: utils.NewSecret(utils.DefaultSecretSize),
	}, nil

// RequiresEditRole extracts the user object from the context, and asserts the user's role is at least
// 'edit'
func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}
