### Title
Webhook shop-domain header trusted for tenant identification while excluded from the HMAC signature - (File: `lib/shopify_api/webhooks/request.rb`)

### Summary
`ShopifyAPI::Webhooks::Request` derives the tenant identity (`shop`) for a processed webhook from the `shopify-shop-domain`/`x-shopify-shop-domain` HTTP header, but the HMAC signature that `ShopifyAPI::Webhooks::Registry.process` validates is computed only over the raw request body, never over that header. This breaks the intended binding `hmac_valid(raw_body) == shop_is_authentic(shop_header)`.

### Finding Description
`Request#to_signable_string` returns only `@raw_body`: [1](#0-0) 

`Request#shop` is read straight from an HTTP header with no cross-check against the signed body: [2](#0-1) 

`Registry.process` validates the HMAC via `Utils::HmacValidator.validate(request)` (which calls `to_signable_string`, i.e. body-only) and then immediately hands `request.shop` to the app's handler as the trusted tenant identifier: [3](#0-2) 

`HmacValidator.validate`/`validate_signature` only ever signs `verifiable_query.to_signable_string`: [4](#0-3) 

Since the app's `client_secret` (`Context.api_secret_key`) is shared across every shop that installs the app (it is not per-tenant), any merchant who installs the app on their own store legitimately receives webhook deliveries with valid HMACs computed over their own webhook body using that same shared secret. Because the `shopify-shop-domain` header is never part of the signed bytes, an attacker who owns such a store can replay a body/HMAC pair they legitimately received while substituting the `shopify-shop-domain` header for a victim shop's domain. `Registry.process` will accept the HMAC (it is valid for the body) and dispatch the handler with `WebhookMetadata` claiming the victim's shop, even though the signed bytes say nothing about which shop they belong to.

This is exactly the "field acted on but not covered by the HMAC" / "shop authenticated versus shop stored as a session key" pattern: the equality that should hold is `authenticated_shop == shop_used_by_handler`, but the gem only proves `hmac_valid(body)`, and then separately trusts an unauthenticated header as `shop_used_by_handler`.

### Impact Explanation
Any handler that uses `WebhookMetadata#shop` (or `data.shop` per the documented `WebhookHandler#handle` interface) to select which tenant's data/session to act on — e.g. mandatory topics `shop/redact`, `customers/redact`, `customers/data_request`, or `app/uninstalled` to delete a stored session — can be tricked into performing that action against a different, unrelated victim shop. This crosses a tenant boundary using only bytes the gem itself failed to bind to an identity, matching the "cross-tenant access" impact class.

### Likelihood Explanation
Moderate-to-high: exploitation only requires the attacker to install the target app on their own (attacker-controlled) shop — no privileged credentials, TLS interception, or leaked secrets are needed — and then relay a legitimately-received, validly-signed webhook body to the app's webhook endpoint with a rewritten `shopify-shop-domain` header. The `Request` initializer performs no additional integrity check tying the header to the body.

### Recommendation
Include the shop domain (and topic, api_version, webhook_id) as part of the HMAC-signed material, or otherwise cryptographically bind the header to the body before trusting it. At minimum, `Registry.process`/`Request` should not surface `shop` (or any other header-derived field) to handlers as authenticated data unless it is covered by the same signature that `HmacValidator.validate` checks.

### Proof of Concept
```ruby
# Attacker installs the target app on their own shop "attacker.myshopify.com"
# and receives a legitimate webhook delivery for, e.g., "app/uninstalled":
raw_body = '{"id": 12345, "domain": "attacker.myshopify.com"}'
valid_hmac = <captured from the real Shopify delivery to attacker's endpoint>

# Attacker replays the exact same body + hmac to the victim app's webhook
# endpoint, but swaps only the shop-domain header:
headers = {
  "x-shopify-topic" => "app/uninstalled",
  "x-shopify-hmac-sha256" => valid_hmac,       # still valid: body unchanged
  "x-shopify-shop-domain" => "victim-shop.myshopify.com", # forged, unsigned
}

request = ShopifyAPI::Webhooks::Request.new(raw_body: raw_body, headers: headers)
ShopifyAPI::Webhooks::Registry.process(request)
# HmacValidator.validate(request) passes (it only checks raw_body),
# and the handler is invoked believing shop == "victim-shop.myshopify.com".
