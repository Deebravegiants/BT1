### Title
`Zap.sell` reverts with `TokenIsGraduating` when LT-price-driven graduation trips between transaction submission and inclusion, bricking slippage-protected sells - ([File: packages/contracts/src/Zap.sol])

### Summary
`Zap._sellInternal` re-checks `Bonding.canGraduate(tokenAddress)` at execution time and, if true, refuses to execute the sell unless the caller passed `minUsdcOut == 0`. `canGraduate`'s USD leg is driven by the external LT's `exchangeRate()`, which moves every time the LT rebalances/accrues (analogous to `borrowBalance` moving every block from interest accrual in the referenced Venus report). A trader who submits `Zap.sell(tokenAddress, tokenAmount, minUsdcOut)` with a nonzero `minUsdcOut` for legitimate slippage protection cannot guarantee which block their transaction lands in; if the exchange rate ticks the curve's real-LT-raised value over `graduationThresholdUsd` in the interim, the transaction unconditionally reverts with `TokenIsGraduating`, exactly the "exact match against a block-varying value" fragility the report describes for `liquidateAccount`.

### Finding Description
`canGraduate` computes its USD trigger from a live, externally-controlled price feed: [1](#0-0) 

`_sellInternal` gates on this same live value at the moment of execution, not at the moment of signing: [2](#0-1) 

The test suite confirms the revert is unconditional whenever `canGraduate` is true and `minUsdcOut != 0`: [3](#0-2) 

This mirrors the Venus `liquidateAccount` pattern precisely: the report's underlying cause is that `borrowBalance` (a value that changes every block) must not-exceed / must-hit a threshold for the call to succeed, and a transaction whose inclusion block is uncertain cannot guarantee that condition. Here, `exchangeRate()` (an externally-set BounceTech LT price, changeable at any block, not just via protocol interest accrual) similarly determines whether `canGraduate` flips true between when a user signs a sell with slippage protection and when it lands on-chain. Unlike the buy path — which recomputes its cap (`previewLtUntilGraduation`) atomically inside the same call and self-adjusts (`Zap._executeBuy`, packages/contracts/src/Zap.sol:279-410) — the sell path has no such tolerance: it is binary revert-or-execute based on a point-in-time external read.

### Impact Explanation
Any trader attempting to exit a position that is close to the graduation threshold with normal slippage protection (`minUsdcOut > 0`) can have their sell transaction reliably reverted by ordinary LT price movement (which requires no attacker action — it happens naturally as BounceTech's leveraged token tracks its underlying and accrues its streaming fee). To avoid the revert, the user is forced to resubmit with `minUsdcOut == 0`, at which point (per the code path) their sell doesn't even execute — it silently converts into a `triggerGraduation` call that returns `0` USDC and leaves their tokens untouched, i.e., the trader gets neither their sale proceeds nor slippage protection on retry. This is a genuine availability/DoS impact on the sell path near the graduation boundary, matching the "Medium — impacts protocol availability under normal conditions" classification the C4 judge ultimately applied to the analogous Venus finding.

### Likelihood Explanation
This requires no adversarial action: it happens whenever a curve token's raised LT value sits close to `graduationThresholdUsd` and the paired LT's `exchangeRate()` naturally drifts (streaming fee accrual, underlying price movement) between transaction signing and inclusion — a condition explicitly acknowledged elsewhere in the codebase's own comments about `exchangeRate()` drift (`packages/contracts/src/Bonding.sol:664-672`). Any unprivileged trader holding tokens on a near-threshold curve can trigger this simply by attempting a normal sell.

### Recommendation
Avoid a hard revert for sells that race a live threshold flip. Options: (1) allow `_sellInternal` to still execute the sell against the curve when `canGraduate` is momentarily true but the transaction was signed against `minUsdcOut` reflecting the pre-graduation price (i.e., let the `usdcOut >= minUsdcOut` check be the sole gate, rather than pre-emptively rejecting all nonzero-`minUsdcOut` sells); or (2) expose a "graduate-tolerant" sell variant / an off-chain-computable exact-preview so front-ends can size `minUsdcOut` against the guaranteed-current state; or, at minimum, (3) document and rate-limit this as an accepted UX tradeoff so front-ends default to smaller `minUsdcOut` tolerances near the threshold rather than reverting outright.

### Proof of Concept
1. Launch a token and buy up to `_usdcStageBeforeGraduation()` so the curve sits just under `graduationThresholdUsd` (as in `test_sell_triggersGraduation_whenGraduatable`, packages/contracts/test/Zap.t.sol:652-674).
2. A trader signs `zap.sell(tokenAddr, sellerTokens, minUsdcOut)` with a nonzero `minUsdcOut` for normal slippage protection, expecting to execute against the current curve price.
3. Before the transaction is mined, `lt.exchangeRate()` (BounceTech's live price feed) rises — the same behavior modeled by `_ratePumpForStagedGraduation()` — pushing `canGraduate(tokenAddr)` to `true`.
4. The transaction executes `_sellInternal`, hits the `canGraduate` branch, sees `minUsdcOut != 0`, and reverts with `TokenIsGraduating`, exactly as asserted in `test_sell_graduatable_withPositiveMinOut_reverts` (packages/contracts/test/Zap.t.sol:702-720) — the trader's tokens remain unsold and they receive nothing, despite having submitted a well-formed sell.

    function test_sell_graduatable_withPositiveMinOut_reverts() public {
        address tokenAddr = _createToken(0);
        _buyViaRouter(tokenAddr, trader, _usdcStageBeforeGraduation());
        lt.setExchangeRate(_ratePumpForStagedGraduation());
        assertTrue(bonding.canGraduate(tokenAddr));

        uint256 sellerTokens = Token(tokenAddr).balanceOf(trader);

        // the sell must revert rather than return 0 — and must NOT graduate.

        assertTrue(bonding.isTrading(tokenAddr), "reverted sell must not graduate the token");
