### Title
`EmporiumUpgradeable.verifyWallet` signature omits `stealthAddressStructure`/`relay` binding, letting a front-runner steal the signer's residual on-chain value - (File: `contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol`)

### Summary
The EIP-712 hash checked in `verifyWallet` only commits to `(emporiumMessage, ops, maxFee, deadline)` — it never commits to the `CircomData.stealthAddressStructure`, `CircomData.relay`, or `calldataHash` that the transaction submitter freely chooses. Anyone who observes a signed, not-yet-expired `EmporiumStack` (e.g. in the mempool) can re-wrap the exact same `(v,r,s,ops,maxFee,deadline,signerAddress)` bytes into their own `CircomData`, generate their own valid proof, and front-run the intended relay through `Hinkal.transact`, redirecting the signer's residual asset value and relay fee to themselves.

### Finding Description
Equality that must hold: (destination that receives the shielded UTXO/relay fee produced by executing signer's `ops`) == (destination the signer intended, i.e., the relay/stealth address they configured when authorizing the ops).

Trace:
- `EmporiumUpgradeable.verifyWallet` (`contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol:302-349`) marks `$.usedMessages[circomData.emporiumMessage] = true` (line 312) and then recovers the signer from `EMPORIUM_SIGNATURE_TYPEHASH` over only `(circomData.emporiumMessage, _hashEmporiumOps(stack.ops), stack.maxFee, stack.deadline)` (lines 318-328). Deadline is checked only afterward (line 342). [1](#0-0) 
- `runAction` decodes the `EmporiumStack` from `circomData.externalActionData.externalActionMetadata` (fully attacker-controlled bytes, only constrained by `calldataHash` self-consistency, not by the signature), executes `stack.ops`, then wraps any resulting balance increase into a UTXO via `handleOut`, which uses `circomData.stealthAddressStructure` — a field entirely outside the ECDSA-signed payload — as the beneficiary of the resulting shielded commitment. [2](#0-1) [3](#0-2) 
- Similarly, `payRelayFees`/`payRelay` route any relay fee to `circomData.relay`, which is likewise unsigned by the wallet owner. [4](#0-3) 
- `performHinkalChecks` only validates `calldataHash` self-consistency (`getHashedCalldata(circomData) == circomData.calldataHash`) and `originalSender`/`relay` mutual exclusivity — neither ties `stealthAddressStructure`/`relay` to the EIP-712 signer. [5](#0-4) 

Note: `msg.sender` inside `runAction`/`handleOut` is actually `address(Hinkal)` itself (Hinkal calls `IExternalActionV2(...).runAction(...)` directly — not the attacker's EOA), so `handleOut`'s `transferERC20TokenOrETH(..., msg.sender, ...)` moves tokens back onto the Hinkal contract's own balance, not to the attacker's wallet directly. The actual diversion of value happens through the shielded UTXO commitment (`createOnchainCommitment`/`insertCommitments` in `Hinkal.transact`), whose owner is determined solely by `circomData.stealthAddressStructure` supplied by whoever races the mempool with the harvested signature — not by `msg.sender`. The exploit's outcome (attacker captures the signer's residual value/fees) is real, but the mechanism is "unconstrained recipient field in CircomData", not "unconstrained msg.sender", as originally framed.

Root cause: the signature scope is too narrow — it authorizes *what operations run* but not *who benefits from the residual output or relay fee*, and `usedMessages` consumes the message atomically with signature verification, so the harvested stack can be executed exactly once by whoever submits it first with their own `stealthAddressStructure`/`relay`.

### Impact Explanation
An unprivileged racer who front-runs a legitimate relay's `Hinkal.transact` call with a harvested, valid, non-expired `EmporiumStack` can:
1. Redirect the signer's residual on-chain balance change (turned into a shielded UTXO by `handleOut`) to a `stealthAddressStructure` of their own choosing, i.e., steal shielded value that should have gone to the wallet owner or their configured relay.
2. Redirect any relay fee configured via `circomData.relay`/`feeStructure` to themselves instead of the intended relay.

This is a direct theft of user/relay funds triggered purely by field(s) never bound by the signature, matching Critical (theft of shielded funds) / High (theft of relay fees) depending on which value is diverted. It is repeatable for any signed-but-not-yet-executed `EmporiumStack` an attacker can observe, once per `emporiumMessage`.

### Likelihood Explanation
Preconditions: attacker must observe a valid, unexpired, signed `EmporiumStack` before it lands on-chain (mempool visibility or any other leak of the signed tuple), and must be able to construct a `CircomData`/proof around it. For the `invokeWallet` (stateful wallet-call) branch, `stack.signerAddress` is a `HinkalWallet` holding on-chain (non-shielded) funds, so the attacker does not need any of the victim's shielded secrets — they can build a fresh proof with zero/foreign input nullifiers. This makes the attack low-cost and fully within an unprivileged attacker's capability (deploy proof, choose own `stealthAddressStructure`/`relay`, submit with higher gas to win the race).

### Recommendation
Extend `EMPORIUM_SIGNATURE_TYPEHASH` (and the corresponding hash built in `verifyWallet`) to include the fields that determine where residual value and fees go, e.g., `circomData.stealthAddressStructure`, `circomData.relay`, and `circomData.calldataHash`/`msg.sender`-equivalent submitter binding, so the signer explicitly authorizes the destination of the residual UTXO and the relay collecting fees, not just the `ops`/`maxFee`/`deadline`.

### Proof of Concept
Foundry test plan:
1. Deploy `Hinkal`, `EmporiumUpgradeable`, a `HinkalWallet` for `signer`, and a token that returns residual value into `EmporiumUpgradeable` when an op runs.
2. `signer` signs an `EmporiumStack` (ops that produce a positive residual balance change) with `deadline` in the future and intended `stealthAddressStructure_A` (belonging to `signer`/their relay) baked into the CircomData they intend to submit.
3. Simulate mempool harvesting: attacker copies `(v,r,s,ops,maxFee,deadline,signerAddress)` and builds their own `CircomData` with `stealthAddressStructure_B` (attacker's own key) and generates their own Groth16 proof for the resulting `calldataHash`.
4. Attacker calls `Hinkal.transact` first.
5. Assert: `$.usedMessages[emporiumMessage] == true` after attacker's tx; assert the resulting `outCommitments`/`UTXO` in `Hinkal`'s tree is encrypted/bound to `stealthAddressStructure_B`, not `stealthAddressStructure_A`; assert the legitimate relay's subsequent `Hinkal.transact` call with `stealthAddressStructure_A` reverts with `UsedMessage()`.
6. Equality check: `beneficiary(stealthAddressStructure in inserted UTXO) == attacker's key`, not `signer's intended key` — proving the broken equality.

    function payRelayFees(
        CircomData calldata circomData,
        address signerAddress,
        int256[] calldata deltaAmountChanges
    ) internal {
        FeeStructure calldata feeStructure = circomData.feeStructure;

        bool foundToken = false;

        for (uint256 i = 0; i < circomData.erc20TokenAddresses.length; i++) {
            // tokens deposited into Emporium are not charged
            if (deltaAmountChanges[i] >= 0) {
                continue;
            }

            address erc20TokenAddress = circomData.erc20TokenAddresses[i];
            bool isFeeToken = erc20TokenAddress == feeStructure.feeToken;

            if (isFeeToken) {
                foundToken = true;
            }

            uint256 relayFee = 0;
            uint256 flatFee = isFeeToken ? feeStructure.flatFee : 0;

            if (signerAddress == address(0)) {
                uint256 sumAbs = uint256(-deltaAmountChanges[i]);

                EmporiumStorageVars storage $ = _getEmporiumStorage();
                relayFee = $._hinkalHelper.calculateRelayFee(
                    sumAbs,
                    flatFee,
                    feeStructure.variableRate
                );
            } else {
                relayFee = flatFee;
            }

            payRelay(
                circomData.relay,
                signerAddress,
                relayFee,
                erc20TokenAddress
            );
        }

        if (!foundToken && feeStructure.flatFee != 0) {
            require(
                signerAddress != address(0),
                "Gas Token in Emporium is not found"
            );

            payRelay(
                circomData.relay,
                signerAddress,
                feeStructure.flatFee,
                feeStructure.feeToken
            );
        }
    }

    function verifyWallet(
        EmporiumStack memory stack,
        CircomData calldata circomData
    ) internal {
        EmporiumStorageVars storage $ = _getEmporiumStorage();

        if ($.usedMessages[circomData.emporiumMessage]) {
            revert UsedMessage();
        }

        $.usedMessages[circomData.emporiumMessage] = true;

        if (stack.signerAddress == address(0)) {
            return;
        }

        bytes32 hashedMessage = _hashTypedDataV4(
            keccak256(
                abi.encode(
                    EMPORIUM_SIGNATURE_TYPEHASH,
                    circomData.emporiumMessage,
                    _hashEmporiumOps(stack.ops),
                    stack.maxFee,
                    stack.deadline
                )
            )
        );

        (address recoveredAddress, ECDSA.RecoverError err) = ECDSA.tryRecover(
            hashedMessage,
            stack.v,
            stack.r,
            stack.s
        );
        bool verified = err == ECDSA.RecoverError.NoError &&
            recoveredAddress == stack.signerAddress;
        if (!verified) {
            revert InvalidSignature();
        }

        if (block.timestamp > stack.deadline) {
            revert SignatureExpired();
        }
