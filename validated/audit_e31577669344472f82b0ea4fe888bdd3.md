## Custody Analog Found: Aptos CLI Silently Left‑Pads Short Addresses in Asset‑Moving Commands

### Title
CLI address parsing (`load_account_arg` → `AccountAddress::from_str`) silently zero-pads short/truncated addresses in `TransferCoins`, `MultisigAccount`, and staking/pool commands, enabling misdirected fund transfers - (File: `crates/aptos-cli-common/src/options.rs`)

### Summary
The external report's invariant is: *"address validation must reject non-canonical / short-form input rather than silently normalize it, because silent padding can redirect an action to an unintended address without user awareness."* The Aptos CLI reproduces exactly this pattern. `AccountAddress::from_str` in `third_party/move/move-core/types/src/account_address.rs` explicitly implements "relaxed" parsing that accepts SHORT addresses (1–63 hex chars) and silently left-pads them to 32 bytes via `from_hex_literal`, and the CLI's `load_account_arg` helper wraps this relaxed parser directly for security-relevant address inputs used to move real assets.

### Finding Description
`AccountAddress::from_str` is documented as relaxed and pads short hex strings with leading zeros: [1](#0-0) 

Its underlying `from_hex_literal` performs the silent left-padding when the supplied literal is shorter than the full 64 hex characters: [2](#0-1) 

The CLI's canonical account-address resolver, `load_account_arg`, calls this relaxed `AccountAddress::from_str` first, with no length/strictness enforcement, before falling back to profile lookup: [3](#0-2) 

This resolver is wired directly into custody-critical, asset-moving CLI commands, including:
- APT transfer recipient (`--account`) in `TransferCoins`: [4](#0-3) 
- Multisig account target (`--multisig-address`): [5](#0-4) 
- Staking pool address (`--pool-address`): [6](#0-5) 
- Faucet/account funding and creation (`Fund`, `CreateAccount`, `FundWithFaucet`): [7](#0-6) 

A separate, stricter type exists (`AccountAddressWithChecks`), but it is only used for genesis configuration, not for transfer/multisig/staking flows, and even it only enforces the length check when the `0x` prefix is absent — a `0x`-prefixed short string still falls through to `from_hex_literal` and gets padded: [8](#0-7) 

### Impact Explanation
Because `load_account_arg` accepts any 1–63 hex-character string (with or without `0x`) as valid and silently zero-pads it into a full 32-byte address, a user who supplies a truncated or mistyped recipient/target address (e.g., a copy-paste error dropping leading characters, or an address string missing leading zero bytes) will have the CLI construct and submit a real transaction — `aptos_stdlib::aptos_account_transfer`, a multisig invocation, or a staking pool operation — against a different, unintended, but syntactically "valid" address. There is no warning or rejection. This directly causes: theft/loss of APT, misdirected authority over a multisig account, or misdirected control of a staking pool, all of which are custody-grade, mainnet-relevant, and effectively non-recoverable once a transaction is confirmed (matching "permanent loss of value" and "owner reassignment" gate categories).

### Likelihood Explanation
This requires no attacker action — it is triggered purely by common client-side mistakes (a truncated clipboard paste, a manually-shortened address, or a script that emits a non-canonical/truncated hex string). Given the CLI is the primary interface for `aptos move run`, `aptos account transfer`, `aptos multisig`, and `aptos stake` commands used against mainnet, the exposure surface is broad and the precondition (typo/truncation) is realistic and has already been shown to be exploitable/impactful in the analogous Starknet Snap finding.

### Recommendation
- Change `load_account_arg` (and `AccountAddressWithChecks::from_str`) to require strict canonical form (`AccountAddress::from_str_strict`), rejecting any non-`0x`-prefixed or non-full-length address rather than silently padding it, for all commands that move funds or authority (transfer, multisig, staking, fund, create).
- Where backward compatibility with profile names must be preserved, only fall back to relaxed parsing for known profile-name lookups, never for raw hex strings that look like addresses but are the wrong length.
- Emit an explicit warning/error (not silent success) whenever an address argument is padded, so users can catch truncation before signing/submitting a transaction.

### Proof of Concept
1. A user intends to transfer APT to `0x0a11ce00000000000000000000000000000000000000000000000000000000` but accidentally truncates the copied hex string to `0xa11ce` (a plausible truncation from clipboard/editor mishap).
2. Run: `aptos account transfer --account 0xa11ce --amount 100000000`.
3. `TransferCoins::account` is populated via `load_account_arg("0xa11ce")` → `AccountAddress::from_str` → `from_hex_literal` pads it to `0x000000000000000000000000000000000000000000000000000000000a11ce` — a *different* address than intended, with no error or warning.
4. The CLI signs and submits `aptos_stdlib::aptos_account_transfer(padded_address, amount)`, sending real APT to the wrong, but "valid-looking," account, exactly mirroring the Starknet Snap short-address custody bug.

```rust
    /// NOTE: Where possible use from_str_strict or from_str instead.
    pub fn from_hex_literal(literal: &str) -> Result<Self, AccountAddressParseError> {
        if !literal.starts_with("0x") {
            return Err(AccountAddressParseError::LeadingZeroXRequired);
        }

        let hex_len = literal.len() - 2;

        // If the string is too short, pad it
        if hex_len < Self::LENGTH * 2 {
            let mut hex_str = String::with_capacity(Self::LENGTH * 2);
            for _ in 0..Self::LENGTH * 2 - hex_len {
                hex_str.push('0');
            }
            hex_str.push_str(&literal[2..]);
            AccountAddress::from_hex(hex_str)
        } else {
            AccountAddress::from_hex(&literal[2..])
        }
    }
```

```rust
impl FromStr for AccountAddress {
    type Err = AccountAddressParseError;

    /// NOTE: This function has relaxed parsing behavior. For strict behavior, please use
    /// the `from_str_strict` function. Where possible use `from_str_strict` rather than
    /// this function.
    ///
    /// Create an instance of AccountAddress by parsing a hex string representation.
    ///
    /// This function allows all formats defined by AIP-40. In short this means the
    /// following formats are accepted:
    ///
    /// - LONG, with or without leading 0x
    /// - SHORT, with or without leading 0x
    ///
    /// Where:
    ///
    /// - LONG is 64 hex characters.
    /// - SHORT is 1 to 63 hex characters inclusive.
    ///
    /// Learn more about the different address formats by reading AIP-40:
    /// <https://github.com/aptos-foundation/AIPs/blob/main/aips/aip-40.md>.
    fn from_str(s: &str) -> Result<Self, AccountAddressParseError> {
        if !s.starts_with("0x") {
            if s.is_empty() {
                return Err(AccountAddressParseError::TooShort);
            }
            AccountAddress::from_hex_literal(&format!("0x{}", s))
        } else {
            if s.len() == 2 {
                return Err(AccountAddressParseError::TooShort);
            }
            AccountAddress::from_hex_literal(s)
        }
    }
```

```rust
/// Loads an account arg and allows for naming based on profiles
pub fn load_account_arg(str: &str) -> Result<AccountAddress, CliError> {
    if let Ok(account_address) = AccountAddress::from_str(str) {
        Ok(account_address)
    } else if let Some(Some(account_address)) =
        CliConfig::load_profile(Some(str), ConfigSearchMode::CurrentDirAndParents)?
            .map(|p| p.account)
    {
        Ok(account_address)
    } else if let Some(Some(private_key)) =
        CliConfig::load_profile(Some(str), ConfigSearchMode::CurrentDirAndParents)?
            .map(|p| p.private_key)
    {
        let public_key = private_key.public_key();
        Ok(account_address_from_public_key(&public_key))
    } else {
        Err(CliError::CommandArgumentError(
            "'--account' or '--profile' after using aptos init must be provided".to_string(),
        ))
    }
}
```

```rust
impl FromStr for AccountAddressWithChecks {
    type Err = anyhow::Error;

    fn from_str(str: &str) -> Result<Self, Self::Err> {
        const NUM_CHARS: usize = AccountAddress::LENGTH * 2;
        let mut has_0x = false;
        let mut working = str.trim();

        // Checks if it has a 0x at the beginning, which is okay
        if working.starts_with("0x") {
            has_0x = true;
            working = &working[2..];
        }

        if working.len() > NUM_CHARS {
            bail!(
                "AccountAddress {} is too long {} must be {} hex characters with or without a 0x in front",
                str,
                working.len(),
               NUM_CHARS
            )
        } else if !has_0x && working.len() < NUM_CHARS {
            bail!(
                "AccountAddress {} is too short {} must be {} hex characters",
                str,
                working.len(),
                NUM_CHARS
            )
        }

        if !working.chars().all(|c| char::is_ascii_hexdigit(&c)) {
            bail!("AccountAddress {} contains a non-hex character", str)
        }

        let account_address = if has_0x {
            AccountAddress::from_hex_literal(str.trim())
        } else {
            AccountAddress::from_str(str.trim())
        }?;

        Ok(account_address.into())
    }
```
