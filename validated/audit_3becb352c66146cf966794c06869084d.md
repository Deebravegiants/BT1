### Title
Webhook `shop`/`topic`/`webhook_id`/`api_version` fields are not covered by the HMAC signature, allowing cross-tenant webhook spoofing - (File: `lib/shopify_api/webhooks/request.rb`)

### Summary
`ShopifyAPI::Webhooks::Request` implements `Utils::VerifiableQuery` and is verified by `ShopifyAPI::Utils::HmacValidator.validate` in `ShopifyAPI::Webhooks::Registry.process`. However, `to_signable_string` returns only `@raw_body`, so the HMAC check never binds the `shopify-shop-domain`, `shopify-topic`, `shopify-webhook-id`, or `shopify-api-version` HTTP headers to the signature. These header-derived values are passed unchanged into `WebhookMetadata` and delivered to the app's webhook handler as trusted, authenticated data.

### Finding Description
`ShopifyAPI::Webhooks::Request#shop`, `#topic`, `#webhook_id`, and `#api_version` are all read straight from HTTP headers via `shopify_header`: [1](#0-0) 

The only integrity check applied to a webhook request is the HMAC, computed over `to_signable_string`, which is defined as the raw body only: [2](#0-1) 

`HmacValidator.validate` computes the HMAC over `verifiable_query.to_signable_string` (the raw body) and compares it to the `hmac` claimed by the request, using the app's single `Context.api_secret_key`/`old_api_secret_key`: [3](#0-2) 

`Registry.process` treats this HMAC check as authenticating the entire request, then builds `WebhookMetadata` directly from the unauthenticated header fields and dispatches it to the app's handler as trusted data: [4](#0-3) 

Because the app-level webhook secret (`api_secret_key`) is shared across every shop that installs the app — it is not per-shop — a valid `hmac` for a given `raw_body` remains valid no matter what `shop-domain` header accompanies it. The equality the gem should enforce is:
`hmac == HMAC(api_secret_key, raw_body || shop || topic || webhook_id)`, but what it actually enforces is only:
`hmac == HMAC(api_secret_key, raw_body)`.

This breaks the identity binding between the authenticated bytes (`raw_body`) and the tenant-identifying field (`shop`) that the handler relies on to know which merchant the event belongs to.

### Impact Explanation
Any unprivileged party who has ever received one legitimate webhook delivery for this app (e.g., an attacker who installed the app on their own test shop) can capture the `raw_body` + valid `hmac-sha256` value from that delivery, then replay it to the app's webhook endpoint with the `shopify-shop-domain` header changed to any other merchant's shop domain. `Registry.process` will still validate the HMAC (since it only checks the unchanged body) and will invoke the handler with `WebhookMetadata#shop` set to the attacker-chosen victim shop. Any handler logic that keys tenant-scoped actions or storage writes off `data.shop` (as documented in `docs/usage/webhooks.md`) will act as if the event legitimately originated from the victim shop — a cross-tenant data/event confusion.

### Likelihood Explanation
Requires only network access to the app's public webhook endpoint and one previously-observed valid webhook body+HMAC pair (obtainable by installing the app on an attacker-controlled shop, which is a normal, unprivileged action). No access token, `client_secret`, or privileged credential is needed.

### Recommendation
Include `shop`, `topic`, and `webhook_id` (in addition to the raw body) in the signable string used for verification, or otherwise independently bind the header-derived tenant identifier to the signed payload before trusting it in `WebhookMetadata`.

### Proof of Concept
1. Install the target app on attacker-owned shop `attacker.myshopify.com`; capture a legitimate webhook POST — raw body `B` and header `shopify-hmac-sha256: H` (valid since `H = HMAC(api_secret_key, B)`).
2. Replay a POST to the app's webhook endpoint with the same body `B` and same `hmac-sha256: H`, but with `shopify-shop-domain: victim.myshopify.com`.
3. `ShopifyAPI::Utils::HmacValidator.validate` returns `true` because it only re-derives the HMAC from `B`, per `lib/shopify_api/webhooks/request.rb:35-38` and `lib/shopify_api/utils/hmac_validator.rb:26-31`.
4. `ShopifyAPI::Webhooks::Registry.process` calls the app's handler with `WebhookMetadata.new(shop: "victim.myshopify.com", body: parsed(B), ...)`, per `lib/shopify_api/webhooks/registry.rb:198-199`, causing the app to process attacker-controlled data attributed to the victim shop.
