### Title
Quadratic-complexity `bytes.concat` loop in BEEFY commitment encoding enables gas-griefing DoS on consensus updates - ([File: evm/src/consensus/Codec.sol])

### Summary
`Codec.Encode(Commitment memory commitment)` builds the BEEFY commitment payload by repeatedly calling `bytes.concat` inside a `for` loop, once per payload item, exactly the "quadratic complexity in buffering" pattern flagged in the Suricata DCERPC advisory (CVE-2026-31937). Each `bytes.concat` call allocates a brand-new memory buffer and copies the entire accumulated payload plus the new element into it, so the loop's total cost is O(n²) in the number of payload entries rather than O(n). [1](#0-0) 

### Finding Description
`Codec.Encode(Commitment memory)` is called from `EcdsaBeefy.verifyMmrUpdateProof` to compute `commitmentHash = keccak256(Codec.Encode(commitment))`, which is then used to `ECDSA.recover` every submitted signer against the authority set. This is on the direct path taken whenever anyone submits a BEEFY consensus proof through `IConsensusV2.verify` / `EcdsaBeefy.verify`, an entry point reachable by any unprivileged relayer submitting a consensus update. [2](#0-1) 

`commitment.payload` is an attacker-influenced array (it is decoded straight from the calldata `proof` via `abi.decode(proof, (RelayChainProof, ParachainProof))` in `verify`), and its length is not bounded before being handed to `Codec.Encode`. Because the encode loop reallocates and copies the whole growing buffer on every iteration, submitting a commitment with a large `payload` array (many small `PayloadItem`s) causes gas cost to grow quadratically with the number of payload entries, compounding the already-heavy per-item `abi.encodePacked`/`ScaleCodec.encodeBytes` work. [3](#0-2) 

This mirrors the DCERPC bug class precisely: a parsing/encoding routine that appends to a buffer in a loop without amortized allocation, so an attacker who controls the number of "chunks" (here, BEEFY payload items) can drive quadratic resource consumption in a routine on a message/consensus-verification hot path.

### Impact Explanation
An attacker (or any relayer) can craft a `BeefyConsensusProof`/`RelayChainProof` with an oversized `commitment.payload` array. Because `Codec.Encode` runs before the ECDSA authority checks even complete validation, the encode cost is paid regardless of whether the signatures ultimately validate. On EVM chains this manifests as an out-of-gas revert (denial of service on that consensus-update transaction, and potentially blocking legitimate BEEFY commitments if the relayer infrastructure retries with the same or similarly-shaped payload) rather than fund loss directly, but it can be used to grief/DoS the light-client update path used by `EvmHost`/`HandlerV2` for message delivery — a route that must reliably deliver messages. This satisfies the "route unable to deliver messages" acceptance criterion via resource exhaustion on the consensus-verification entry point.

### Likelihood Explanation
Likelihood is moderate-to-high for a griefing/DoS scenario: the caller of `EcdsaBeefy.verify`/`ConsensusRouter` needs no special privilege, and the payload array length is fully attacker-controlled through calldata. However, exploitation is bounded by EVM block gas limits and calldata gas costs (an attacker must actually supply enough payload bytes to make the quadratic blowup material within a single block's gas budget), and normal BEEFY commitments typically carry only a handful of payload items (e.g., the MMR-root entry), so this is a griefing vector requiring a deliberately malformed, oversized proof rather than a naturally occurring one.

### Recommendation
Rewrite `Codec.Encode(Commitment memory)` to pre-size a single output buffer (or use an incremental writer / `abi.encodePacked` with pre-computed length) instead of repeated `bytes.concat` in a loop, and/or enforce a maximum bound on `commitment.payload.length` before encoding, mirroring how MAX_CALL_SIZE-style bounds are enforced elsewhere in the codebase (e.g., `call-decompressor`'s `MaxCallSize` check).

### Proof of Concept
1. Construct a `RelayChainProof` whose `signedCommitment.commitment.payload` array contains a large number (e.g., thousands) of `PayloadItem`s with minimal `id`/`data` (to keep calldata cost reasonable relative to the quadratic memory-copy cost incurred inside `Codec.Encode`).
2. Submit this proof via `EcdsaBeefy.verify(previousState, proof)` (directly, or through the `ConsensusRouter`/`EvmHost` consensus-update path).
3. Measure gas consumption of the `Codec.Encode(commitment)` call at `evm/src/consensus/EcdsaBeefy.sol:152` as payload length increases; observe non-linear (quadratic) growth versus a baseline where payload growth is linear, eventually exceeding the block gas limit for a payload size well within calldata limits — demonstrating the DoS.

    function Encode(Commitment memory commitment) internal pure returns (bytes memory) {
        uint256 payloadLen = commitment.payload.length;
        bytes memory payload = bytes("");
        for (uint256 i = 0; i < payloadLen; i++) {
            payload = bytes.concat(
                payload,
                abi.encodePacked(commitment.payload[i].id),
                ScaleCodec.encodeBytes(commitment.payload[i].data)
            );
        }

        return bytes.concat(
            ScaleCodec.encodeUintCompact(payloadLen),
            payload,
            ScaleCodec.encode32(commitment.blockNumber),
            ScaleCodec.encode64(commitment.validatorSetId)
        );
    }

    function verifyMmrUpdateProof(BeefyConsensusState memory trustedState, RelayChainProof memory relayProof)
        internal
        pure
        returns (BeefyConsensusState memory, bytes32)
    {
        uint256 sigLen = relayProof.signedCommitment.votes.length;
        uint256 latestHeight = relayProof.signedCommitment.commitment.blockNumber;
        Commitment memory commitment = relayProof.signedCommitment.commitment;
        if (
            commitment.validatorSetId != trustedState.currentAuthoritySet.id
                && commitment.validatorSetId != trustedState.nextAuthoritySet.id
        ) {
            revert UnknownAuthoritySet();
        }

        bool isCurrentAuthorities = commitment.validatorSetId == trustedState.currentAuthoritySet.id;
        AuthoritySetCommitment memory authoritySet =
            isCurrentAuthorities ? trustedState.currentAuthoritySet : trustedState.nextAuthoritySet;
        if (!checkParticipationThreshold(sigLen, authoritySet.len)) revert SuperMajorityRequired();

        uint256 payloadLength = commitment.payload.length;
        bytes32 mmrRoot;
        for (uint256 i = 0; i < payloadLength; i++) {
            if (commitment.payload[i].id == MMR_ROOT_PAYLOAD_ID && commitment.payload[i].data.length == 32) {
                mmrRoot = Bytes.toBytes32(commitment.payload[i].data);
            }
        }
        if (mmrRoot == bytes32(0)) revert MmrRootHashMissing();

        // verify the commitment
        bytes32 commitmentHash = keccak256(Codec.Encode(commitment));
