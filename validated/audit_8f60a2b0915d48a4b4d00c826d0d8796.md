Audit Report

## Title
Unauthenticated pprof/metrics debug endpoints reachable via `loopRoutes`, bypassing the authentication constraints applied to the equivalent `/v2/debug/pprof` endpoints - (File: `core/web/router.go`)

## Summary
`NewRouter` builds an unauthenticated base `api` group (rate limiting + session-cookie middleware only, no auth), and registers `loopRoutes(app, api)` directly on it, while the equivalent standard Go pprof endpoints (`metricRoutes`) are only mounted inside the `authv2` group behind `auth.Authenticate(... AuthenticateByToken, AuthenticateBySession)`. As a result, `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*`, and `/plugins/:name/debug/pprof/symbol` are reachable by any unauthenticated client, forwarding raw profiling/metrics data from LOOP plugin processes with no credential check anywhere in the handler chain.

## Finding Description
`NewRouter` creates `api` with only rate limiting and session middleware: [1](#0-0)  and calls `loopRoutes(app, api)` alongside other route groups, several of which (e.g. `v2Routes`) construct their own internal authenticated sub-groups, but `loopRoutes` does not: [2](#0-1) 

`loopRoutes` registers all four endpoints with zero auth middleware: [3](#0-2) 

By contrast, standard pprof (`metricRoutes`) is only ever invoked from inside `authv2`, which requires `auth.Authenticate(... AuthenticateByToken, AuthenticateBySession)`: [4](#0-3)  The handlers `pluginMetricHandler`, `pluginPPROFHandler`, and `pluginPPROFPOSTSymbolHandler` perform no session/token/role check — they only look up the plugin by name and forward the request: [5](#0-4) [6](#0-5) 

This is an accurate description of the current code: the claim is verified line-for-line against `core/web/router.go` and `core/web/loop_registry.go` in this repository.

However, two mitigating factors reduce the severity of this finding relative to the report's framing:
1. **Design intent for `/metrics` and `/discovery`**: the code comments and the `discoveryHandler`/`pluginMetricPath` logic show this subsystem is explicitly built as a Prometheus service-discovery/scrape target exposed on the main node HTTP port, intended to be scraped without per-request credentials (this is standard practice for Prometheus `/metrics` endpoints, which are almost universally unauthenticated in the wild and rely on network-level controls). [7](#0-6) [8](#0-7) 
2. **pprof endpoints are not similarly justified**: there is no comment or design rationale in the code for why the pprof-forwarding endpoints (`pluginPPROFHandler`, `pluginPPROFPOSTSymbolHandler`) — which can leak heap contents, goroutine stacks, and consume CPU via the `seconds` param on a full profile — should be unauthenticated when the equivalent built-in `/v2/debug/pprof/*` routes are explicitly authenticated. The comment "unlike discovery, this endpoint is internal btw the node and plugin" only describes the internal forwarding target (`loopHostName`), not an intended access-control boundary for the externally-facing route itself. [9](#0-8) 

I could not find any git history, changelog, or acknowledgment in this snapshot repository (single "Initial commit") indicating this was already fixed, flagged, or intentionally accepted as a known/scoped exposure, so I cannot rule out that this is an accepted design trade-off for the metrics/discovery paths — but the inconsistency for the pprof-forwarding endpoints specifically (vs. the authenticated built-in pprof routes) stands as a real, code-verifiable asymmetry.

## Impact Explanation
An unauthenticated client reaching the node's main HTTP listener can:
- Enumerate loaded LOOP plugins via `GET /discovery`.
- Pull full pprof profiles (heap, goroutine, CPU profile with attacker-chosen `seconds`, trace) for any named plugin via `GET /plugins/:name/debug/pprof/*profile`, with no ownership/role check.
- Tie up node/plugin resources via long-duration CPU profile requests proxied through `doRequest`, which uses a timeout derived directly from the attacker-supplied `seconds` query parameter. [10](#0-9) 

This maps to unauthorized disclosure of internal runtime/memory state (profiling data) without credentials, which is a legitimate in-scope "node API authentication bypass" class of issue for the pprof-forwarding endpoints specifically, since the equivalent built-in pprof routes are explicitly gated. The `/metrics` and `/discovery` endpoints are lower severity, given they mirror standard, widely-accepted unauthenticated Prometheus scrape-target conventions.

## Likelihood Explanation
High for any deployment where the node's main HTTP listener (the same one serving `/v2` and the operator UI) is network-reachable, since no token or session cookie is required and plugin names are discoverable via the equally unauthenticated `/discovery` endpoint. No operator/admin privilege is needed to trigger any of these requests — this satisfies the "unprivileged actor" requirement.

## Recommendation
Apply the same authentication middleware used by `metricRoutes`/`authv2` (or an equivalent scrape-token/IP-allowlist mechanism appropriate for the Prometheus use case) to the pprof-forwarding routes in `loopRoutes`, at minimum for `/plugins/:name/debug/pprof/*` and `/plugins/:name/debug/pprof/symbol`. If `/metrics` and `/discovery` are intentionally meant to remain open for Prometheus scraping, document that decision explicitly and consider separating them into their own route group distinct from the pprof-forwarding endpoints, so the security boundary is clear and auditable.

## Proof of Concept
1. Start a chainlink node with at least one LOOP plugin registered (`app.GetLoopRegistry()` populated).
2. Without any session cookie or API token: `curl http://<node>:<port>/discovery` — returns plugin names/ports unauthenticated (`discoveryHandler`, `core/web/loop_registry.go:53-81`).
3. Using a discovered plugin name: `curl "http://<node>:<port>/plugins/<name>/debug/pprof/heap?debug=1"` — `pluginPPROFHandler` (`core/web/loop_registry.go:150-166`) forwards to the plugin's internal pprof endpoint and returns the profile with no auth check, contrasting with `GET /v2/debug/pprof/heap` which requires `auth.Authenticate` (`core/web/router.go:245-248`, `185-199`).
4. Optionally: `curl "http://<node>:<port>/plugins/<name>/debug/pprof/profile?seconds=60"` to demonstrate attacker-controlled resource consumption via the proxied CPU profile duration.

// discoveryHandler implements service discovery of prom endpoints for LOOPs in the registry
func (l *LoopRegistryServer) discoveryHandler(w http.ResponseWriter, req *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	groups := make([]*targetgroup.Group, 0, 1+len(l.registry.List()))

	// add node metrics to service discovery
	groups = append(groups, pluginGroup(l.discoveryHostName, l.exposedPromPort, "/metrics"))

	// add all the plugins
	for _, registeredPlugin := range l.registry.List() {
		group := pluginGroup(l.discoveryHostName, l.exposedPromPort, pluginMetricPath(registeredPlugin.Name))
		group.Labels[LabelMetaPluginName] = model.LabelValue(registeredPlugin.Name)
		groups = append(groups, group)
	}
```

func pprofURLVals(gc *gin.Context) (urlVals url.Values, timeout time.Duration) {
	urlVals = make(url.Values)
	if db, ok := gc.GetQuery("debug"); ok {
		urlVals.Set("debug", db)
	}
	if gc, ok := gc.GetQuery("gc"); ok {
		urlVals.Set("gc", gc)
	}
	timeout = PPROFOverheadSeconds * time.Second
	if sec, ok := gc.GetQuery("seconds"); ok {
		urlVals.Set("seconds", sec)
		if i, err := strconv.Atoi(sec); err == nil {
			timeout = time.Duration(i+PPROFOverheadSeconds) * time.Second
		}
	}
	return urlVals, timeout
}

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
```
