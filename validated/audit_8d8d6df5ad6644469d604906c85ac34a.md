### Title
Stale stored account owner retains spending authority after position-NFT transfer, letting the prior owner drain the account - (File: contracts/controller/src/account.rs)

### Summary
CVE-2018-6764 is a class where a protection mechanism consults an incorrectly determined identity (the container "hostname" resolved through a crafted NSS module) and is therefore bypassed. The controller exhibits the same class: it carries two different sources of account identity — the `owner` field stored inside the `Account` struct at creation time, and the live position-NFT owner read via `storage::account_owner` — and uses the stale stored field to authorize fund-moving operations after the NFT (i.e., the account) has been transferred.

### Finding Description
`create_account_with` persists `Account { owner: owner.clone(), .. }` when the NFT is minted (`contracts/controller/src/account.rs:64-70`). Account spending authority for `borrow`, `withdraw`, `multiply`, `flash_position`, `swap_debt`, `swap_collateral`, `repay_debt_with_collateral`, `migrate_from_blend`, and the `SeizeMode::Credit` receiver check is decided by `require_owner_or_delegate` / `is_owner_or_delegate`, which compares `caller == owner` against that stored `Account.owner` field (`contracts/controller/src/account.rs:115-140`), reached via `load_or_create_account` and `resolve_seize_receiver` (`contracts/controller/src/positions/liquidation/mod.rs:180`).

Separately, `require_account_owner` — used by `renew_account`, `add_delegate`, `remove_delegate` — does not trust the stored field: it re-reads the NFT owner with `storage::account_owner(env, account_id)` and compares it to `caller` (`contracts/controller/src/account.rs:143-148`). That divergence indicates the NFT owner is the live source of truth while `Account.owner` is a snapshot.

The position-NFT's `transfer`/`transfer_from` moves the token — "the NFT owner is the account owner, so each one moves or delegates control of a whole lending account" (`scripts/permissionless_entrypoints.txt:106-113`) — but no code path shown updates the stored `Account.owner`. The invariant file even notes "delegate grants from the previous owner go inactive," implying owner-change effects are handled lazily. If `storage::get_account` does not resync `owner` from the NFT on load, then after a transfer:

- The **new** owner (NFT holder) fails `caller == owner` in `is_owner_or_delegate` and cannot `borrow`, `withdraw`, or run any strategy on their own account — permanent freezing of the account's funds for the legitimate owner.
- The **old** owner still satisfies `caller == account.owner` and can `withdraw` all collateral `to` themselves and `borrow` to max LTV — theft of user funds. They can also still act as receiver-authorizing party in `SeizeMode::Credit`.

Whether `storage::get_account`/`storage::account_owner` resynchronizes `Account.owner` could not be confirmed within the available tool iterations; that is the crux of this finding and must be verified in `contracts/controller/src/storage/account.rs`.

### Impact Explanation
If the stored owner is stale, an unprivileged prior owner (an address that already has a key) can call `withdraw`/`borrow` on a sold or transferred account and take its full collateral and borrowing power — direct theft of user funds. Conversely the new owner is locked out of all owner/delegate-gated operations — freezing of funds.

### Likelihood Explanation
Reachable by a single unprivileged address: the ex-owner simply calls `controller::withdraw(caller=old_owner, account_id, withdrawals, to=Some(old_owner))`. No privileged role, oracle manipulation, or third-party contract honesty is required. Likelihood depends entirely on whether `get_account` resyncs the owner; the duplicated identity sources make this a realistic drift rather than a hypothetical.

### Recommendation
Make NFT ownership the single identity source: either (a) resolve `owner` inside `storage::get_account`/`is_owner_or_delegate` from `storage::account_owner` / NFT `owner_of` on every read, or (b) update `Account.owner` and migrate delegate storage on every position-NFT transfer via a controller-authorized hook. Add a regression test: transfer NFT, then assert `withdraw`/`borrow` reject the old owner and admit the new owner.

### Proof of Concept
```rust
// 1. Alice supplies collateral, obtains account_id A; Account.owner = alice.
// 2. Alice transfers position NFT token_id A to Bob via position-nft::transfer.
// 3. Bob calls controller.withdraw(bob, A, legs, Some(bob)) -> reverts
//    NotAuthorized because Account.owner is still alice.
// 4. Alice calls controller.withdraw(alice, A, legs, Some(alice)) -> passes
//    is_owner_or_delegate via stale Account.owner and steals the collateral.
```
