## Analog Assessment: SuiteCRM Authenticated RCE in Modules → Hyperbridge `CallDispatcher`

### Title
Unrestricted `CallDispatcher.dispatch()` allows any address to execute arbitrary calls from a shared, balance-holding contract - ([File: evm/src/utils/CallDispatcher.sol])

### Summary
`CallDispatcher.dispatch(bytes memory encoded)` is `external` with **no access control** — no `onlyGateway`, no caller allowlist, nothing. [1](#0-0)  It is invoked by `IntentsBase._execute` (postdispatch) and by the predispatch flow in `IntentGatewayV2.sol`/`IntentGatewayV2.sol` (tron variant) to run solver/user-supplied `Call[]` against tokens that were just transferred into the dispatcher, then sweep any residual balance back to the gateway. [2](#0-1)  The same dispatcher address is referenced from gateway `Params.dispatcher` and is a single shared, deployed contract — not spun up per-order. [3](#0-2) 

### Finding Description
The intended flow is: transfer assets to `dispatcher` → `ICallDispatcher(dispatcher).dispatch(...)` runs the order's calldata → any leftover balance is swept back atomically, all inside one gateway transaction. [4](#0-3)  Because `dispatch()` itself has no caller restriction, however, **any external account can call it directly** on the shared `CallDispatcher` instance and route arbitrary `to.call{value}(data)` invocations from that contract's context. [5](#0-4)  The design explicitly acknowledges that non-zero balances can persist on the dispatcher after a call sequence ("dust"), which is what the sweep-back loop and `DustCollected` event exist to reclaim [6](#0-5)  — i.e., the contract's own documentation assumes it can transiently or residually hold funds. Any value sitting on `CallDispatcher` — whether transient dust from imperfect sweeps, ETH sent via its unconditional `receive()`, or a partially-completed predispatch/postdispatch sequence — is claimable by an unrelated caller who front-runs or simply calls `dispatch()` before the gateway's own sweep executes.

This mirrors the SuiteCRM CVE-2026-29102 bug class at a structural level: a component meant to be reached only through a privileged, sequenced flow ("module" execution / calldata dispatch) is instead directly and unrestrictedly callable by any authenticated (here: any) actor, letting them drive arbitrary execution/state changes outside the intended caller chain.

### Impact Explanation
If `CallDispatcher` ever holds a non-zero token or ETH balance outside of the atomic gateway transaction that put it there (e.g., ETH sent directly via its `receive()`, dust not fully swept due to a token with non-standard transfer semantics, or any state where a `dispatch()` call partially succeeds and leaves balance before the sweep call executes), any external address can drain it by calling `dispatch()` with a `Call[]` transferring that balance to themselves. This is a direct theft-of-funds vector against a contract that is explicitly documented to hold intermediate token/ETH balances during composable order fulfillment.

### Likelihood Explanation
Within a single, non-reentrant gateway transaction the transfer-in → `dispatch()` → sweep-back sequence is atomic, so ordinary EVM transaction ordering cannot interleave an attacker's call between those steps in the common case. This limits — but does not eliminate — exploitability: the `receive()` function accepts unconditional ETH transfers, and dust-sweep logic (`IntentsBase._execute` sweep loop) explicitly anticipates leftover balances, meaning there are legitimate, reachable states in which `CallDispatcher` holds value it doesn't distribute in the same transaction it arrived. I was not able to fully verify from the indexed code whether any code path guarantees the sweep always leaves zero balance in all token/ETH edge cases (e.g., fee-on-transfer tokens, failed but non-reverting transfers) or whether `Params.dispatcher` is ever shared across multiple concurrent gateway deployments/chains — both of which materially affect real-world likelihood.

### Recommendation
Restrict `CallDispatcher.dispatch()` to a caller allowlist (e.g., `onlyGateway`/`onlyOwner` modifier set at construction, or per-gateway dedicated dispatcher instances) so that only the authorized `IntentGatewayV2`/`IntentsBase` contract(s) can invoke it. Additionally, ensure the sweep logic in `_execute` (and the equivalent predispatch/postdispatch paths in `evm/src/apps/IntentGatewayV2.sol` and the tron variant) fully drains all asset types before returning control, and consider rejecting unsolicited ETH via `receive()` unless it originates from the trusted gateway.

### Proof of Concept
Not independently reproducible from the indexed context alone — a full PoC would require confirming a concrete reachable state where `CallDispatcher` retains a non-zero balance across transaction boundaries (e.g., via `receive()` ETH deposits or an under-swept token), then demonstrating an attacker calling `CallDispatcher.dispatch(abi.encode(Call[]))` directly to move that balance to an attacker-controlled address. I recommend a Devin session with full repo/tooling access (Foundry) to build this PoC against `evm/src/utils/CallDispatcher.sol` and `evm/src/apps/intentsv2/IntentsBase.sol`, since the index does not let me confirm every code path (e.g. exact sweep coverage for all token behaviors) with certainty.

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }

    /**
     * @dev Executes arbitrary calldata attached to an order's output via the CallDispatcher.
     * After dispatching the calls, any residual token balances left on the dispatcher
     * are swept back to this contract and accounted for as protocol dust.
     *
     * This enables composable order fulfillment — solvers can route through DEXes,
     * lending protocols, or other DeFi primitives as part of filling an order.
     *
     * @param order The order containing the output calldata to execute.
     * @param outputsLen The number of output assets to sweep after execution.
     */
    function _execute(Order calldata order, uint256 outputsLen) internal {
        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            } else {
                uint256 balance = IERC20(token).balanceOf(dispatcher);
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            }

            unchecked {
                ++i;
            }
        }

        if (sweepCount > 0) {
            Call[] memory finalCalls = new Call[](sweepCount);
            for (uint256 i; i < sweepCount;) {
                finalCalls[i] = sweepCalls[i];
                unchecked {
                    ++i;
                }
            }
            ICallDispatcher(dispatcher).dispatch(abi.encode(finalCalls));
        }
    }
