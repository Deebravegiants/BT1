### Title
Swallowed NFT contract errors treated as "no owner" freeze positions and block liquidation - ([File: contracts/controller/src/external/position_nft.rs])

### Summary
`nft_try_owner_of_call` uses `try_owner_of` and maps **every** failure mode of the position-NFT contract — including contract panics and archived/expired owner entries — to `None`, which all callers interpret as "account has no owner". This is the Rust/Soroban analog of catching an exception to detect invalid data: an error from an external call is silently conflated with a semantic result, and the failure propagates as `AccountNotFound` on every state-changing path (withdraw, repay, liquidate, transfer-triggered checks), permanently freezing both collateral and debt on the affected account.

### Finding Description
The CVE class is CWE-395: catching a low-level exception to detect an invalid object rather than validating explicitly. In `contracts/controller/src/external/position_nft.rs:19-25`, `nft_try_owner_of_call` collapses three distinct outcomes — out-of-range ID, missing token, and **any** sub-call failure (`Err`, host error, archived `Owner`/`Balance` persistent entry) — into `None`:

```rust
match PositionNftClient::new(env, nft).try_owner_of(&token_id) {
    Ok(Ok(owner)) => Some(owner),
    _ => None,
}
```

Every account resolution goes through this: `try_account_owner` (`contracts/controller/src/storage/account.rs:35-38`) → `account_owner` / `try_get_account` / `get_account_borrow_only` (`account.rs:41-44`, `153-162`, `167-172`). `get_account_borrow_only` is the borrow-side loader used by debt operations and liquidation; unresolved ownership raises `AccountNotFound`. `nft_renew_call` renews only when ownership already resolved — the renew path itself calls `PositionNftClient::renew`, which fails identically once the owner entry is gone.

A reachable trigger: position-NFT `Owner`/`Balance` entries live in the NFT contract's own persistent storage with its own TTL. If a holder never transacts and no renew touches those entries (transfers are user-initiated; controller renewals run inside operations that first resolve ownership), `owner_of` traps on the archived entry, `try_owner_of` returns `Err`, and the account becomes permanently unresolvable.

### Impact Explanation
Temporary-to-permanent freezing of user funds and protocol insolvency:
- **Frozen collateral**: `withdraw`, `repay`, `supply` on the account all fail with `AccountNotFound` because `account_owner` panics (`account.rs:41-44`).
- **Unliquidatable debt**: liquidation loads the debtor account; with a debt position and no resolvable owner, the account can never be liquidated. As indexes accrue, the collateral backing the debt becomes unreachable — the same bad-debt outcome `clean_bad_debt`/`recapitalize` exist to manage, but those paths also require resolving the account and would fail identically.
- An unprivileged holder reaches this by simply not touching their NFT long enough for its TTL to lapse (or by transferring to an account that does so), while keeping an open borrow.

### Likelihood Explanation
Medium: requires the NFT owner entry TTL to lapse while the account holds positions — plausible for long-dormant leveraged positions, since controller-side renewals renew *controller* keys (`renew_user_account`, `account.rs:259-272`) and the NFT renewal is gated behind a successful ownership resolution, creating a dead-end once expired. No privileged action needed, but the window depends on storage TTL parameters. Not High because it requires dormancy rather than an active single-transaction trigger, and the NFT's own TTL policy may renew on transfers.

### Recommendation
Distinguish failure modes instead of collapsing to `None`:
- In `nft_try_owner_of_call`, only map `Ok(Err(_))` (token-not-found domain error) to `None`; propagate host/sub-call `Err` failures via `panic_with_error!` with a distinct error (e.g., `OwnershipLookupFailed`) so archival failures are visible and not conflated with "no owner".
- Add a permissionless `renew`/`touch` entrypoint on the controller that calls `nft_renew_call` for any `account_id`, so keeper/users can extend NFT TTLs before expiry — currently renewal is only reachable through operations that already require resolved ownership.
- Ensure `clean_bad_debt`/`recapitalize` can operate on a debt map without resolving NFT ownership (load `get_debt_positions` directly) so unresolvable accounts can still be written down.

### Proof of Concept
1. User supplies collateral, borrows, then transfers the position NFT to a fresh address and never interacts again.
2. Let the NFT contract's `Owner(token_id)`/`Balance(owner)` persistent entries expire (simulate by expiring ledger TTL in test env).
3. `PositionNftClient::try_owner_of(token_id)` → host `Err` → `nft_try_owner_of_call` returns `None`.
4. `controller.withdraw(account_id, ...)` → `account_owner` → `AccountNotFound`: collateral frozen.
5. `controller.liquidate(account_id, ...)` → `get_account_borrow_only` → `account_owner` → `AccountNotFound`: debt can never be liquidated → permanent bad debt despite on-ledger collateral.

Note on confidence: this relies on the position-NFT contract's `owner_of` panicking on archived/missing entries and on controller renewals not covering NFT-side keys — consistent with the documented fail-closed comment at `position_nft.rs:17-18`, though the NFT's `owner_of` implementation and TTL constants were not fully inspected in this pass.
