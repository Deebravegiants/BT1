### Title
Bad-debt write-down clamps `supply_index` up to `SUPPLY_INDEX_FLOOR_RAW`, resurrecting wiped-out supply claims that drain later recapitalized funds - (File: contracts/pool/src/interest.rs)

### Summary
`apply_bad_debt_to_supply_index` is the analog of the kernel's "publish, then overwrite the reference count" bug. When a bad-debt seizure writes off debt worth more than the market's entire supplied value, the computed `new_supply_index` collapses to zero — the correct accounting for a total wipeout — but the code then clamps it up to `SUPPLY_INDEX_FLOOR_RAW` (`RAY/1000`). Every previously wiped supplier's shares remain stored and suddenly carry a positive claim again (analogous to the `refcount_set` clobbering the reader's stolen reference: a terminal value is overwritten so dead objects become live). The existing unit test `test_raw_cache_floor_clamp_strands_claim_without_supply_guard` already demonstrates that the stranded position "pays out real tokens" once cash exists in the market.

### Finding Description
In `contracts/pool/src/interest.rs`, `apply_bad_debt_to_supply_index` computes `remaining = total_supplied_value - capped_bad_debt` and derives `reduction_factor = remaining / total_supplied_value`. On a full wipeout `capped == total_supplied_value`, so `new_supply_index == 0`, but line 88 applies `.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW))`, setting the index to `RAY/1000` while `supplied` shares are untouched. [1](#0-0) 

The write-down is reached permissionlessly: `controller::clean_bad_debt` (caller only needs `require_auth`) → `execute_bad_debt_cleanup` → `pool_seize_positions_call` → `seize::apply` for `AccountPositionType::Borrow`, which calls `apply_bad_debt_to_supply_index` and burns the debt. [2](#0-1) [3](#0-2) 

After the clamp, `guards::backing_shortfall` reports a shortfall equal to the phantom claim (`supplied × floor − cash`), so `supply`'s `require_backed_market` blocks new deposits — but `recapitalize` is permissionless and credits exactly `min(amount, backing_shortfall)` to cash, restoring backing for claims that should be worthless. [4](#0-3)  The stranded suppliers then `withdraw` and take the recapitalized tokens; the pool's own test shows `gross == fresh_cash`, i.e., the phantom claim drains exactly the injected cash. [5](#0-4) 

### Impact Explanation
Theft of user funds / protocol insolvency. Once a market's supply index is floored on a full wipeout, any tokens later added to that market — primarily via permissionless `recapitalize` (keeper, admin, or any user recapitalizing the book) — are claimable pro-rata by the wiped-out suppliers whose positions were economically zeroed. The recapitalizer's injection is drained by dead claims; if the attacker holds a large fraction of the market's supply shares, they capture that fraction of every recapitalization. Because `supplied` shares are never zeroed, the phantom claim persists indefinitely at the floor.

### Likelihood Explanation
Requires a full (or ≥1000×-supplied-value) bad-debt event on one market so that `new_supply_index` computes below `RAY/1000`. A single unprivileged attacker can construct near-total wipeouts: supply minimal collateral, borrow essentially all of a thin market's liquidity, then let interest accrual (or a price move) push the account insolvent with sub-$5 collateral, and call `clean_bad_debt` permissionlessly. With `cash ≈ 0` and `debt ≈ total supplied value`, `reduction_factor ≈ 0` and the index floors. Profit then depends on a subsequent recapitalization or any cash injection into the dead market — the standard recovery path the protocol itself provides (`recapitalize`). Medium likelihood, high severity when triggered.

### Recommendation
On a full wipeout, zero the claims rather than resurrecting them: when `capped == total_supplied_value` (or the computed index falls below the floor), burn/write off `supplied` (and `revenue`) shares to zero instead of clamping the index upward, so no phantom claim remains. Alternatively keep the floor but track a "wiped" flag that makes `withdraw`/`seize`/`recapitalize` treat stranded shares as zero until new supply is minted from a re-initialized index. At minimum, `recapitalize` should not count pre-wipeout shares toward `backing_shortfall` at the floored index without a deliberate re-listing step.

### Proof of Concept
The repo already pins the exploit mechanics in `contracts/pool/tests/interest.rs::test_raw_cache_floor_clamp_strands_claim_without_supply_guard`: [6](#0-5) 

End-to-end unprivileged path:
1. Attacker supplies a small amount of asset C as collateral and calls `borrow` to take ~all liquidity of market B (e.g., via a thin or attacker-seeded market).
2. Time passes / price moves so `total_debt > total_collateral ≤ $5`; attacker calls `clean_bad_debt(caller, account_id)` — permissionless, only `caller.require_auth()`.
3. `seize::apply` on the Borrow leg calls `apply_bad_debt_to_supply_index` with `bad_debt ≥ total_supplied_value`; index clamps to `RAY/1000`, `supplied` shares of market B (including attacker's own supply position in B, seeded beforehand) retain claims of `shares × floor`.
4. Any third party (or protocol keeper) calls `recapitalize(hub_asset_B, payer, amount)`; cash is credited up to the shortfall.
5. Attacker calls `withdraw` on their stranded B supply; `resolve_withdrawal` values the shares at the floored index and `require_reserves` passes against the recapitalized cash — attacker extracts real tokens for shares that should be worth zero.

pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}

/// Admission condition for bad-debt socialization.
#[derive(Clone, Copy, PartialEq)]
enum BadDebtGate {
    /// Permissionless: insolvent *and* collateral at or below the dust threshold.
    DustCapped,
    /// Owner-only: insolvent alone, with no cap on the collateral left behind.
    InsolventOnly,
}

/// Requires open debt and the selected insolvency gate, then cleans up the account.
fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    bad_debt::execute_bad_debt_cleanup(env, &mut cache, account_id, &account, &totals);
}

/// Socializes insolvent debt when remaining collateral is at or below the dust cap.
pub(crate) fn clean_bad_debt_standalone(env: &Env, account_id: u64) {
    socialize_bad_debt(env, account_id, BadDebtGate::DustCapped);
}

#[test]
fn test_raw_cache_floor_clamp_strands_claim_without_supply_guard() {
    let t = TestSetup::new();
    t.as_contract(|| {
        let old_scaled_raw = 1_000 * RAY;
        let mut cache = t.fresh_cache(PoolStateRaw {
            supplied: old_scaled_raw,
            borrowed: 0,
            revenue: 0,
            borrow_index: RAY,
            supply_index: RAY,
            last_timestamp: 0,
            cash: 0,
        });
        let old_scaled = Ray::from(old_scaled_raw);

        apply_bad_debt_to_supply_index(&mut cache, Ray::from(5_000 * RAY));
        assert_eq!(
            cache.supply_index().raw(),
            SUPPLY_INDEX_FLOOR_RAW,
            "wipeout clamps supply_index UP to RAY/1000 instead of resetting shares to 0",
        );

        let stranded = cache.unscale_supply_floor(old_scaled);
        assert!(stranded > 0, "floor clamp leaves S_old a phantom claim");
        assert_eq!(
            cache.cash(),
            0,
            "no cash yet: invariant only masked by require_reserves"
        );

        let fresh_cash = stranded;
        let fresh_scaled = cache.calculate_scaled_supply(fresh_cash);
        cache.mint_supply(fresh_scaled);
        cache.credit_cash(fresh_cash);

        let fresh_claim = cache.unscale_supply_floor(fresh_scaled);
        assert_eq!(
            fresh_claim, fresh_cash,
            "fresh supplier's claim equals deposit"
        );

        let (burn, gross) = cache.resolve_withdrawal(i128::MAX, old_scaled);
        cache.require_reserves(gross);
        cache.burn_supply(burn);
        cache.debit_cash(gross);

        assert!(gross > 0, "stranded wiped position pays out real tokens");
        assert_eq!(gross, fresh_cash, "S_old drains exactly the fresh deposit");
        assert!(
            cache.cash() < fresh_claim,
            "pool cash ({}) can no longer cover fresh supplier claim ({}): funds lost",
            cache.cash(),
            fresh_claim,
        );
    });
