I found a concrete unauthenticated nil-dereference panic in the gateway's JSON-RPC decode path, reachable before any auth check.

`JSONRPCCodec.DecodeJSONRequest` dereferences `request.Params` unconditionally: `json.Unmarshal(*request.Params, &msg)` with no nil check. [1](#0-0) 

This is called directly from the gateway's unauthenticated public entry point, `gateway.ProcessRequest`, immediately after decoding the raw JSON-RPC envelope and before any DON/service lookup, authorization, or rate limiting: [2](#0-1) 

A JSON-RPC request with `"params"` omitted (or explicitly `null`) will decode successfully via `jsonrpc2.DecodeRequest`, leaving `Request.Params` as a nil `*json.RawMessage`, and then panic on `*request.Params` in `DecodeJSONRequest`. Contrast this with the codebase's own defensive pattern used everywhere else in the same package family — `ValidatedMessageFromReq` explicitly nil-checks `req.Params` before dereferencing: [3](#0-2) 

and the vault-layer processors all guard the same way, e.g.: [4](#0-3) 

**Caveat on severity/impact.** I could not find a top-level recover wrapper around `httpServer.handleRequest` / `ProcessRequest` in this codebase: [5](#0-4) 

However, Go's standard `net/http` package automatically recovers panics per-request inside `conn.serve` and only aborts that single connection — it does not crash the whole process. I was not able to find any custom panic-recovery override or any code path where this decode function executes in a goroutine untouched by `net/http`'s own recovery (e.g., a background worker). Given this, this bug realistically causes an unauthenticated single-connection crash/abort per malformed request, not necessarily a full `istiod`-style process crash unless invoked outside the request goroutine's recover scope, which I could not confirm from the indexed code.

### Title
Unauthenticated nil-pointer panic on JSON-RPC request with missing/null `params` in gateway `DecodeJSONRequest` - (File: core/services/gateway/api/jsonrpccodec.go)

### Summary
The chainlink Gateway's public, unauthenticated HTTP endpoint decodes every incoming JSON-RPC request via `JSONRPCCodec.DecodeJSONRequest`, which unconditionally dereferences `request.Params` without a nil check. Any unauthenticated caller can send a JSON-RPC 2.0 request omitting the `params` field (or with `"params": null`) to trigger a nil-pointer dereference panic, unlike every sibling decode path in the codebase (`ValidatedMessageFromReq`, vault request processors) which explicitly guard against nil params.

### Finding Description
`gateway.ProcessRequest` is the entry point invoked directly by the internet-facing HTTP server for every incoming request, before any DON/service routing, authentication, or rate-limiting logic runs (`core/services/gateway/gateway.go:221-230`). It calls `g.codec.DecodeJSONRequest(jsonRequest)`, whose implementation is:
```go
func (*JSONRPCCodec) DecodeJSONRequest(request jsonrpc2.Request[json.RawMessage]) (*Message, error) {
	var msg Message
	err := json.Unmarshal(*request.Params, &msg)  // panics if request.Params == nil
	...
}
```
`jsonrpc2.DecodeRequest` (the earlier decode step) only validates the JSON-RPC envelope structure (version, method non-empty, etc., per `TestJsonRPCRequest_Decode_Incorrect`), but a request lacking `"params"` altogether decodes into a `Request` with `Params == nil` and does NOT get rejected before reaching `DecodeJSONRequest`. Every other equivalent decode/validation function in this codebase (`ValidatedMessageFromReq`, `processCreateSecretsRequest`, `processUpdateSecretsRequest`, `processDeleteSecretsRequest`, `processListSecretIdentifiersRequest`) explicitly checks `if req.Params == nil` first — `DecodeJSONRequest` is the sole exception in the reviewed paths.

### Impact Explanation
An unauthenticated remote attacker can crash the goroutine handling any request they send to the gateway's public HTTP listener simply by POSTing a JSON-RPC request without a `params` field. Because Go's `net/http` recovers panics per-connection, this most plausibly causes repeated connection resets/response failures for that request rather than a full process crash — a lesser DoS impact than the Istio `istiod` full-crash analog, but still an availability defect reachable from zero privilege on an internet-facing service, and it deviates from the CWE-1284 "improper validation of specified quantity in input" root cause class of the reference advisory.

### Likelihood Explanation
Trivial to trigger: a single crafted HTTP POST with `{"jsonrpc":"2.0","id":"x","method":"anything"}` (no `params` key) suffices, requires no authentication, no DON ID, and no valid method name.

### Proof of Concept
```
POST /<gateway-path> HTTP/1.1
Content-Type: application/jsonrpc

{"jsonrpc":"2.0","id":"1","method":"anything"}
```
This reaches `httpServer.handleRequest` → `handler.ProcessRequest` (`core/services/gateway/network/httpserver.go:234`) → `gateway.ProcessRequest` → `g.codec.DecodeJSONRequest(jsonRequest)` (`core/services/gateway/gateway.go:227`) → nil-pointer dereference panic at `json.Unmarshal(*request.Params, &msg)` (`core/services/gateway/api/jsonrpccodec.go:28`).

### Recommendation
Add a nil check for `request.Params` in `DecodeJSONRequest` before dereferencing, mirroring the pattern already used in `ValidatedMessageFromReq` and the vault request processors, returning a structured JSON-RPC parse/invalid-params error instead of panicking.

func (*JSONRPCCodec) DecodeJSONRequest(request jsonrpc2.Request[json.RawMessage]) (*Message, error) {
	var msg Message
	err := json.Unmarshal(*request.Params, &msg)
	if err != nil {
		return nil, err
	}
	msg.Body.MessageID = request.ID
	msg.Body.Method = request.Method
	return &msg, nil
}

func (s *httpServer) handleRequest(w http.ResponseWriter, r *http.Request) {
	if s.config.CORSEnabled {
		origin := r.Header.Get("Origin")
		if s.isAllowedOrigin(origin) {
			w.Header().Set("Access-Control-Allow-Origin", origin)
			w.Header().Set("Access-Control-Allow-Methods", "GET, POST, OPTIONS")
			w.Header().Set("Access-Control-Allow-Headers", "Content-Type")
		}

		// handle preflight requests
		if r.Method == http.MethodOptions {
			w.WriteHeader(http.StatusNoContent)
			return
		}
	}

	maxRequestBytes, err := s.config.MaxRequestBytesLimiter.Limit(r.Context())
	if err != nil {
		msg := "Failed to get request size limit"
		s.lggr.Errorw(msg, "err", err)
		http.Error(w, msg, http.StatusInternalServerError)
		return
	}
	source := http.MaxBytesReader(nil, r.Body, int64(maxRequestBytes))
	rawMessage, err := io.ReadAll(source)
	if err != nil {
		s.lggr.Error("error reading request", err)
		w.WriteHeader(http.StatusBadRequest)
		return
	}

	// Optionally extract jwt token from authorization header
	authHeader := r.Header.Get("Authorization")
	jwtToken := ""
	if authHeader != "" {
		jwtToken = strings.TrimPrefix(authHeader, "Bearer ")
	}

	startTime := time.Now()
	rawResponse, httpStatusCode := s.handler.ProcessRequest(r.Context(), rawMessage, jwtToken)
	duration := time.Since(startTime)
	s.hMetrics.RecordRequestDuration(r.Context(), httpStatusCode, duration)
	s.hMetrics.RecordRequestCount(r.Context(), httpStatusCode)

	w.Header().Set("Content-Type", s.config.ContentTypeHeader)
	w.WriteHeader(httpStatusCode)
	_, err = w.Write(rawResponse) //nolint:gosec // G705: response body is written with an explicit Content-Type, not rendered as HTML
	if err != nil {
		s.lggr.Error("error when writing response", err)
	}
}
