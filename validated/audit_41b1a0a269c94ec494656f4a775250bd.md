## Custody Analog Found

### Title
Stale `TombStone.original_owner` lets a **former** object owner reclaim custody of a fungible-asset store (or any value-holding object) after it has been legitimately transferred away — (`File: aptos-move/framework/aptos-framework/sources/object.move`)

### Summary
The external report's root custody invariant is: *a stateful, privilege-unaware side-effect (sUSDe's `cooldownDuration`) is consulted by a withdrawal/recovery path without validating that it still reflects the current, legitimate custody state, letting stale state either lock or misroute funds.* The Aptos analog is in `aptos_framework::object`'s burn/unburn "soft-burn" (`TombStone`) mechanism: the ordinary ungated transfer path (`transfer` → `transfer_raw` → `transfer_raw_inner`) does not clear a pre-existing `TombStone`, while the ref-based transfer path (`transfer_with_ref`) deliberately does, specifically to prevent this exact reclaim scenario. Because ordinary `object::transfer` is the primary mechanism by which ownership of value-holding objects (including `FungibleStore` objects used by `primary_fungible_store`/`fungible_asset`) changes hands, a stale `TombStone` can survive one or more legitimate transfers and later be used by the *original* (no-longer-legitimate) owner to redirect ownership of the object — and any fungible-asset balance it holds — back to themselves.

### Finding Description
`object::burn` marks an object as soft-burnt by attaching a `TombStone { original_owner }`, without touching `allow_ungated_transfer`: [1](#0-0) 

`object::unburn` has two recovery branches. If the *current* owner reclaims, the `TombStone` is simply dropped. But if the current owner is `BURN_ADDRESS`, the function trusts the `original_owner` recorded **inside the stale `TombStone`** to authorize returning ownership to that address: [2](#0-1) 

Crucially, `object::transfer` / `transfer_call` (the standard, ungated ownership-change entry points) go through `transfer_raw` → `transfer_raw_inner`, which updates `ObjectCore.owner` and emits an event but never checks for or removes an existing `TombStone`: [3](#0-2) 

By contrast, the `LinearTransferRef`-based path (`transfer_with_ref`) explicitly purges any `TombStone` and documents why: [4](#0-3) 

This asymmetry is the authority break: `TombStone.original_owner` is only guaranteed accurate immediately after `burn()`; once the object changes hands through the *ordinary* transfer path, the recorded `original_owner` becomes stale relative to the true custody chain, yet `unburn`'s `BURN_ADDRESS` branch still trusts it as an authorization credential.

Concrete corrupted-value trace:
1. `A` owns a value-holding object `O` (e.g., a `FungibleStore` reachable via `object::owns`, whose balance is spendable by whoever owns `O` per `fungible_asset::withdraw_sanity_check_impl`'s `object::owns` check — see `fungible_asset.move:974-987`).
2. `A` calls `object::burn(A, O)` → `TombStone{ original_owner: A }` is attached; `O.owner` is still `A`.
3. `A` legitimately sells/transfers `O` to `B` via `object::transfer(A, O, B)`. `O.owner` becomes `B`; the stale `TombStone{ original_owner: A }` is **not** removed (unlike the `transfer_with_ref` path).
4. `B`, unaware of the leftover `TombStone` (there is no way to inspect/clear it without calling `unburn` themselves, and `burn()` on `O` will now abort with `EOBJECT_ALREADY_BURNT` since a `TombStone` already exists), later sends `O` to `BURN_ADDRESS` for any legitimate reason (e.g., mimicking the documented "soft burn/retire" pattern, or simply transferring to that constant address, which is a normal, permitted transfer).
5. `A` calls `object::unburn(A, O)`. Since `O.owner == BURN_ADDRESS` and `TombStone.original_owner == A`, the second branch fires and `transfer_raw_inner(O, A)` reassigns ownership of `O` — and every fungible asset balance stored in it — back to `A`, even though `A` had no legitimate claim on `O` at the time it reached `BURN_ADDRESS`.

The corrupted field is `ObjectCore.owner`, which is redirected to the stale `TombStone.original_owner` instead of preserving the last legitimate custody chain (`B`, or whoever actually sent `O` to `BURN_ADDRESS`).

### Impact Explanation
This is a custody-grade impact: unauthorized owner reassignment of object-held value, moving fungible-asset/token custody to the wrong (stale, unprivileged) holder and destroying the legitimate current owner's recovery rights — directly matching the required "Supply or custody accounting corruption that moves value to the wrong holder or destroys recovery rights" and "unauthorized takeover of ... ownership reassignment ... tied to live assets" impact categories. Any object built on `object::burn`/`unburn` semantics (primary or secondary `FungibleStore`s, token objects, or any custom object holding value) is affected wherever ordinary `transfer`/`transfer_raw` is used between the burn and the eventual send to `BURN_ADDRESS`.

### Likelihood Explanation
Reaching the exploitable state requires only standard, permissionless operations: `object::burn` (by the original owner, on their own object, at any time), a normal `object::transfer` to a new owner (fully legitimate and common), and eventually a transfer to the fixed, well-known `BURN_ADDRESS` constant (`0xff...ff`) by that later owner for any reason (intentional or accidental, since it is an ordinary, permitted transfer target). No privileged access or race condition is required; the former owner (`A`) merely needs to remember that they burnt the object earlier and wait for it to end up at `BURN_ADDRESS`. Given that "soft burn to indicate retirement" is a documented, encouraged usage pattern, this is a realistic sequence for NFT/token marketplaces, vaults, or custody wrappers built on Aptos objects.

### Recommendation
Clear (or otherwise invalidate) any existing `TombStone` on every ownership change performed through the ungated `transfer_raw`/`transfer_raw_inner` path, mirroring the behavior already implemented in `transfer_with_ref` — i.e., apply the same "undo soft burn" logic there as well. Alternatively, disallow `transfer_raw`/`transfer` on objects that currently carry a `TombStone` (forcing an explicit `unburn` by the current owner first), so that `TombStone.original_owner` can never become stale relative to the live custody chain before it is consulted for the `BURN_ADDRESS` recovery branch.

### Proof of Concept
Conceptual Move test sequence (mirrors existing tests such as `test_burn_and_unburn_old` in `object.move`):
```
1. A: object::burn(A, hero)                       // TombStone{original_owner: A}, hero.owner = A
2. A: object::transfer(A, hero, B)                // hero.owner = B, TombStone NOT cleared (transfer_raw path)
3. B: object::transfer(B, hero, BURN_ADDRESS)     // hero.owner = BURN_ADDRESS
4. A: object::unburn(A, hero)                     // passes: owner==BURN_ADDRESS && TombStone.original_owner==A
                                                   // => hero.owner reassigned to A, bypassing B's custody
```
This can be directly adapted from the existing `test_burn_and_unburn_old` unit test at [5](#0-4)  by inserting an intermediate `object::transfer` to a third party `B` before the transfer to `BURN_ADDRESS`, and asserting that `A` (not `B`) regains ownership via `unburn`.

    /// Transfer to the destination address using a LinearTransferRef.
    public fun transfer_with_ref(self: LinearTransferRef, to: address) {
        assert!(!exists<Untransferable>(self.self), error::permission_denied(EOBJECT_NOT_TRANSFERRABLE));

        // Undo soft burn if present as we don't want the original owner to be able to reclaim by calling unburn later.
        if (exists<TombStone>(self.self)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(self.self);
        };

        let object = borrow_global_mut<ObjectCore>(self.self);
        assert!(
            object.owner == self.owner,
            error::permission_denied(ENOT_OBJECT_OWNER),
        );
        event::emit(
            Transfer {
                object: self.self,
                from: object.owner,
                to,
            },
        );
        object.owner = to;
    }

        if (object_core.owner != to) {
            event::emit(
                Transfer {
                    object,
                    from: object_core.owner,
                    to,
                },
            );
            object_core.owner = to;

    /// Allow origin owners to reclaim any objects they previous burnt.
    public entry fun unburn<T: key>(
        original_owner: &signer,
        object: Object<T>,
    ) {
        let object_addr = object.inner;
        assert!(exists<TombStone>(object_addr), error::invalid_argument(EOBJECT_NOT_BURNT));

        // The new owner of the object can always unburn it, but if it's the burn address, we go to the old functionality
        let object_core = borrow_global<ObjectCore>(object_addr);
        if (object_core.owner == signer::address_of(original_owner)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object_addr);
        } else if (object_core.owner == BURN_ADDRESS) {
            // The old functionality
            let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
            assert!(
                original_owner_addr == signer::address_of(original_owner),
                error::permission_denied(ENOT_OBJECT_OWNER)
            );
            transfer_raw_inner(object_addr, original_owner_addr);
        } else {
            abort error::permission_denied(ENOT_OBJECT_OWNER);
        };
    }
