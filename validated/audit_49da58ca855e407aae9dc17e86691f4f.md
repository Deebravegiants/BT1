### Title
`ShopifyAPI::Auth::Oauth.begin_auth`/`validate_auth_callback` omit `ShopValidator` sanitization applied everywhere else, allowing `client_secret` exfiltration to attacker-controlled host - (File: `lib/shopify_api/auth/oauth.rb`)

### Summary
Every other OAuth entry point in this gem — `ClientCredentials.client_credentials`, `RefreshToken.refresh_access_token`, and `TokenExchange.migrate_to_expiring_token` — calls `Utils::ShopValidator.sanitize!(shop)` before using the caller-supplied `shop` string to build the request host that receives `Context.api_secret_key`. `Auth::Oauth.begin_auth` and `Auth::Oauth.validate_auth_callback` do not.

### Finding Description
`Auth::Oauth.begin_auth(shop:, redirect_path:, ...)` takes `shop` directly and builds the authorization URL with `auth_base_uri(shop)` returning `"https://#{shop}/admin"` with no domain sanitization [1](#0-0) , and `auth_base_uri` has no `ShopValidator` call [2](#0-1) .

More critically, in `validate_auth_callback`, `null_session = Auth::Session.new(shop: auth_query.shop)` is built straight from the query-string `shop` value and used to construct the `HttpClient` that POSTs the OAuth token-exchange body — which includes `client_secret: Context.api_secret_key` — to `https://#{session.shop}/admin/oauth/access_token` [3](#0-2) . `HttpClient#initialize` derives `@base_uri` directly from `session.shop` with no domain validation: `@base_uri = "https://#{api_host || session.shop}"` [4](#0-3) .

Contrast this with the three sibling flows that all sanitize the shop before it is trusted as a network destination for the secret:
- `ClientCredentials.client_credentials`: `validated_shop = Utils::ShopValidator.sanitize!(shop)` before `Session.new(shop: validated_shop)` [5](#0-4) 
- `RefreshToken.refresh_access_token`: same pattern [6](#0-5) 
- `TokenExchange.migrate_to_expiring_token`: same pattern [7](#0-6) 

`ShopValidator.sanitize!`/`sanitize_shop_domain` exists precisely to guarantee the equality "the host that will receive `client_secret` == a trusted `*.myshopify.com`/`*.myshopify.io`/etc. domain," rejecting arbitrary hosts [8](#0-7) . `Auth::Oauth` breaks this binding: the identity check that is supposed to occur is "host receiving `client_secret` == trusted Shopify domain," but the actual check performed is only "the query string HMAC is valid" (`Utils::HmacValidator.validate(auth_query)`), which says nothing about whether the `shop` value is a legitimate Shopify domain [9](#0-8) .

### Impact Explanation
If a host application follows this gem's own documented pattern of taking `shop` from request input (the docs literally show `shop = request.headers["Shop"]` passed straight into `begin_auth` [10](#0-9) ) without separately calling `ShopValidator` itself (which none of the doc examples in `oauth.md` mention doing for the Authorization Code Grant flow, unlike the parity that exists in the other three grant types), an attacker can drive `shop` to point at an attacker-controlled host. Combined with `validate_auth_callback` never re-validating `auth_query.shop` against `ShopValidator`, this is High severity: SSRF that carries the app's `client_secret` to a host of the attacker's choosing, i.e., credential leakage/exfiltration of the app's `client_secret`.

### Likelihood Explanation
This requires the host application to not independently sanitize the shop parameter for the Authorization Code Grant flow — which is plausible given the gem's own documentation for this specific flow (unlike the other three OAuth methods) never shows or mentions `ShopValidator`, creating an inconsistent, easy-to-miss contract across the library's own public API surface.

### Recommendation
Call `Utils::ShopValidator.sanitize!(shop)` inside `Auth::Oauth.begin_auth` before constructing `auth_base_uri`, and inside `Auth::Oauth.validate_auth_callback` before constructing `null_session`/the `HttpClient`, mirroring `ClientCredentials`, `RefreshToken`, and `TokenExchange`.

### Proof of Concept
Not independently exploitable purely within this gem without a host application that forwards unsanitized `shop` input into `begin_auth`/`validate_auth_callback` (as the gem's own example code for this flow shows); the report above documents the internal inconsistency (missing `ShopValidator.sanitize!` call in `Auth::Oauth`, present in three sibling modules) as the concrete root cause supporting the analog. I could not fully verify within available time whether any downstream caller in this repo (outside `lib/shopify_api/auth/oauth.rb`) re-validates `shop` before calling `begin_auth`/`validate_auth_callback`, since these are meant to be invoked by host applications outside this gem.

        def begin_auth(shop:, redirect_path:, is_online: true, scope_override: nil)
          scope = if scope_override.nil?
            ShopifyAPI::Context.scope
          elsif scope_override.is_a?(ShopifyAPI::Auth::AuthScopes)
            scope_override
          else
            ShopifyAPI::Auth::AuthScopes.new(scope_override)
          end

          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end

          state = SecureRandom.alphanumeric(NONCE_LENGTH)

          cookie = SessionCookie.new(value: state, expires: Time.now + 60)

          query = {
            client_id: ShopifyAPI::Context.api_key,
            scope: scope.to_s,
            redirect_uri: "#{ShopifyAPI::Context.host}#{redirect_path}",
            state: state,
            "grant_options[]": is_online ? "per-user" : "",
          }

          query_string = URI.encode_www_form(query)
          auth_route = auth_base_uri(shop) + "/oauth/authorize?#{query_string}"

          { auth_route: auth_route, cookie: cookie }
        end

        def validate_auth_callback(cookies:, auth_query:)
          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::InvalidOauthError, "Invalid OAuth callback." unless Utils::HmacValidator.validate(auth_query)
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = cookies[SessionCookie::SESSION_COOKIE_NAME]
          raise Errors::NoSessionCookieError unless state

          raise Errors::InvalidOauthError,
            "Invalid state in OAuth callback." unless state == auth_query.state

          null_session = Auth::Session.new(shop: auth_query.shop)
          body = {
            client_id: Context.api_key,
            client_secret: Context.api_secret_key,
            code: auth_query.code,
            expiring: Context.expiring_offline_access_tokens ? 1 : 0, # Only applicable for offline tokens
          }

          client = Clients::HttpClient.new(session: null_session, base_path: "/admin/oauth")
          response = begin
            client.request(
              Clients::HttpRequest.new(
                http_method: :post,
                path: "access_token",
                body: body,
                body_type: "application/json",
              ),
            )
          rescue ShopifyAPI::Errors::HttpResponseError => e
            raise Errors::RequestAccessTokenError,
              "Cannot complete OAuth process. Received a #{e.code} error while requesting access token."
          end

          session_params = T.cast(response.body, T::Hash[String, T.untyped]).to_h
          session = Session.from(shop: auth_query.shop,
            access_token_response: Oauth::AccessTokenResponse.from_hash(session_params))

    module ShopValidator
      TRUSTED_SHOPIFY_DOMAINS = T.let(
        [
          "shopify.com",
          "myshopify.io",
          "myshopify.com",
          "spin.dev",
          "shop.dev",
        ].freeze,
        T::Array[String],
      )

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
