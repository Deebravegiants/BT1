Audit Report

## Title
Unauthenticated Exposure of Internal LOOP Plugin Debug/PPROF and Metrics Endpoints via Missing Auth Middleware in `loopRoutes` - (File: core/web/router.go)

## Summary
In `NewRouter`, the route groups `debugRoutes`, `sessionRoutes`, and `v2Routes` each explicitly wrap sensitive handlers with `auth.Authenticate(...)`, but `loopRoutes` is registered directly on the unauthenticated `api` group with no auth middleware at all. This lets any unauthenticated network client reach `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol`, which proxy straight into internal LOOP plugin processes.

## Finding Description
`NewRouter` builds the `api` group with only rate limiting and cookie-session middleware, not authentication, then calls `loopRoutes(app, api)` alongside the authenticated route groups: [1](#0-0) . By contrast, `debugRoutes` and `sessionRoutes` explicitly wrap their sensitive routes with `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)`: [2](#0-1) [3](#0-2) . `loopRoutes` registers its four handlers directly on the passed-in group with no authentication call whatsoever: [4](#0-3) .

The handlers themselves perform no authentication/authorization — `discoveryHandler` enumerates registered plugins and prometheus targets [5](#0-4) , `pluginMetricHandler` proxies to the plugin's internal metrics port [6](#0-5) , and `pluginPPROFHandler`/`pluginPPROFPOSTSymbolHandler` proxy arbitrary pprof profile requests (heap, goroutine, CPU profile with attacker-controlled `seconds`, block, mutex, threadcreate, symbol) straight to the plugin's internal port [7](#0-6) . None of these check session/token identity or role before proxying.

## Impact Explanation
An unauthenticated client with network access to the node's HTTP API can enumerate LOOP plugins, pull their raw Prometheus metrics, and pull full Go pprof dumps (heap/goroutine/cpu profile) from internal plugin processes — potentially leaking sensitive in-memory data and process internals — and can trigger CPU-profile requests with attacker-controlled duration causing extra load on the plugin. This is a concrete authentication-bypass on the node's HTTP API surface, matching the CWE-284 "missing router-level auth" bug class, and it is directly caused by first-party routing code rather than misconfiguration, a malicious peer, or a dependency defect.

## Likelihood Explanation
High: no credentials, tokens, or session cookies are required — only network reachability to the node's configured web-server port, which is the same reachability assumed for the already-authenticated sibling routes (`/debug`, `/sessions`, `/v2/*`) in the same router. The plugin name parameter is a simple path segment that can be enumerated or guessed via `/discovery`, which itself is unauthenticated and leaks plugin names.

## Recommendation
Wrap `loopRoutes` registration with the same `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession, auth.AuthenticateByToken)` middleware pattern used elsewhere in `router.go`, likely combined with `auth.RequiresAdminRole` given the operational/debug sensitivity of pprof and metrics data. Add regression tests (analogous to RBAC route-map tests) asserting `/discovery`, `/plugins/:name/metrics`, and the pprof proxy routes return 401/403 without valid credentials.

## Proof of Concept
Against a running chainlink node with the HTTP API reachable and at least one LOOP plugin registered, and with no `X-API-KEY`/`X-API-SECRET` headers or session cookie sent:
```
curl http://<node-host>:<api-port>/discovery
curl http://<node-host>:<api-port>/plugins/<plugin-name>/metrics
curl "http://<node-host>:<api-port>/plugins/<plugin-name>/debug/pprof/heap"
curl "http://<node-host>:<api-port>/plugins/<plugin-name>/debug/pprof/profile?seconds=30"
```
Each request reaches `LoopRegistryServer.discoveryHandler` / `pluginMetricHandler` / `pluginPPROFHandler` respectively (`core/web/router.go:230-236`, `core/web/loop_registry.go`) and returns plugin metadata, metrics, or a full pprof dump with no authentication challenge, confirming the missing `auth.Authenticate` wrapper on `loopRoutes` compared to `debugRoutes`/`sessionRoutes`/`v2Routes`.

// discoveryHandler implements service discovery of prom endpoints for LOOPs in the registry
func (l *LoopRegistryServer) discoveryHandler(w http.ResponseWriter, req *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	groups := make([]*targetgroup.Group, 0, 1+len(l.registry.List()))

	// add node metrics to service discovery
	groups = append(groups, pluginGroup(l.discoveryHostName, l.exposedPromPort, "/metrics"))

	// add all the plugins
	for _, registeredPlugin := range l.registry.List() {
		group := pluginGroup(l.discoveryHostName, l.exposedPromPort, pluginMetricPath(registeredPlugin.Name))
		group.Labels[LabelMetaPluginName] = model.LabelValue(registeredPlugin.Name)
		groups = append(groups, group)
	}

	b, err := l.jsonMarshalFn(groups)
	if err != nil {
		w.WriteHeader(http.StatusInternalServerError)
		_, err = w.Write([]byte(err.Error()))
		if err != nil {
			l.logger.Error(err)
		}
		return
	}
	_, err = w.Write(b)
	if err != nil {
		w.WriteHeader(http.StatusInternalServerError)
		l.logger.Error(err)
	}
}

func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))

	req, err := http.NewRequestWithContext(gc.Request.Context(), http.MethodGet, pluginURL, nil)

		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)
	if err != nil {
		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}
