### Title
Zero-proof-coverage asset theft via `EmporiumStack.signerAddress==0` ops when `erc20TokenAddresses.length==0` triggers `formInputEmporiumMin` - (`contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol` / `contracts/CircomDataBuilder.sol`)

### Summary
When `circomData.externalActionData.externalActionId == HINKAL_EMPORIUM_ACTION_ID` and `erc20TokenAddresses.length == 0`, `CircomDataBuilder.formInputForCircom` routes to `formInputEmporiumMin`, whose only public signals are `emporiumMessage`, `timeStamp`, `calldataHash`. `EmporiumUpgradeable.runAction` still executes every `EmporiumOperation` in the decoded `EmporiumStack` (attacker-controlled via `externalActionData.externalActionMetadata`) as `op.endpoint.call{value: op.value}(op.callData)` with `msg.sender == Emporium`, while `balancesBefore`/`balancesAfter` are computed only over the (empty) `erc20TokenAddresses` array, so any value moved by the call is never accounted for.

### Finding Description
The broken equality: **set of assets movable by `Emporium`'s identity during `op.endpoint.call{value:op.value}(op.callData)`** must equal **set of assets tracked in `balancesBefore`/`balancesAfter` (i.e., `circomData.erc20TokenAddresses`)**. When `erc20TokenAddresses.length == 0`, the right-hand side is the empty set while the left-hand side is unconstrained and attacker-chosen, so `VALUE_CONSERVATION` is broken by construction.

Code path:
- `CircomDataBuilder.formInputForCircom` (contracts/CircomDataBuilder.sol:134-148) selects `formInputEmporiumMin` whenever `externalActionId == HINKAL_EMPORIUM_ACTION_ID && erc20TokenAddresses.length == 0`. [1](#0-0) 
- `EmporiumUpgradeable.runAction` decodes `EmporiumStack` from `circomData.externalActionData.externalActionMetadata`, computes `balancesBefore`/`balancesAfter` only over `circomData.erc20TokenAddresses` (empty here), and unconditionally iterates `stack.ops`, executing `op.endpoint.call{value: op.value}(op.callData)` in the stateless branch (`stack.signerAddress == address(0)`). [2](#0-1) 
- `verifyWallet` only performs signature verification/EIP-712 checks when `stack.signerAddress != address(0)`; with `signerAddress == address(0)` it simply marks `emporiumMessage` used and returns — no signature, no constraint on `stack.ops` content at all. [3](#0-2) 
- The proof circuit actually used in this path, `MainEVMCircuitMin`, only constrains `message <== Poseidon([messageSeed])`; `calldataHash` is declared as a public input signal but is never used in any constraint of the template, so the circuit gives zero cryptographic guarantee over the actual `externalActionMetadata`/ops content. [4](#0-3) 
- The only on-chain guard tying `calldataHash` to the real calldata is `performHinkalChecks`'s self-consistency check `getHashedCalldata(circomData) == circomData.calldataHash` [5](#0-4)  — but since the attacker fully controls all of `circomData` (including `calldataHash` itself), they can always make this hash match their own attacker-chosen `externalActionData`/ops. This check prevents tampering by a third party, not attacker-authored malicious ops.
- `dimensionsCheck` only requires `erc20TokenAddresses.length == amountChanges.length == inputNullifiers.length == ... == dimensions.tokenNumber` — all can consistently be `0`, so it does not prevent this. [6](#0-5) 

Given all these facts, the attacker's exact call is `Hinkal.transact(circomData, ...)` where: `erc20TokenAddresses = []`, `amountChanges = []`, `inputNullifiers = []` (dimensions all 0), `externalActionData = {externalAddress: Emporium, externalActionId: HINKAL_EMPORIUM_ACTION_ID, externalActionMetadata: abi.encode(EmporiumStack{signerAddress: address(0), ops: [EmporiumOperation{endpoint: victim, invokeWallet:false, value:0, callData: <call that moves funds Emporium controls/is trusted by>}], maxFee:0, deadline:0, v/r/s: 0})}`, `calldataHash = getHashedCalldata(circomData)` (self-consistent), plus a locally-generated valid Groth16 proof for `MainEVMCircuitMin` (trivial since `messageSeed` is chosen by the attacker and `message`/`calldataHash` are otherwise unconstrained by the circuit).

This satisfies the question's premise: as long as Emporium holds ETH/ERC20 balance or has lingering approvals from a prior legitimate flow (e.g., a victim contract that trusts `msg.sender == Emporium` due to a prior interaction, or Emporium's own idle balance from dust/rounding left over from other users' emporium flows), `runAction` will execute the call and move value while `balancesBefore == balancesAfter == []`.

### Impact Explanation
This allows theft of any ETH/ERC20 that `Emporium`'s address can move via an arbitrary `.call` at the time of the attack — including funds/approvals belonging to other users routed through Emporium (e.g., leftover balances between the transfer-in and transfer-out steps of a legitimate multi-op flow) or any external contract that grants `Emporium`'s address standing approvals/trust. Since `Emporium` is the shared execution identity for all users of this action, a malicious unprivileged user forcing it to call attacker-chosen `endpoint`/`callData` with no accounting is a direct, unauthorized siphon of protocol/user funds — classified **Critical** (direct theft of in-flight/parked funds via a completely unconstrained action). It's fully repeatable per Emporium balance/approval state and costs the attacker only gas plus proof generation (which the circuit provides no meaningful barrier to).

### Likelihood Explanation
Preconditions required: `Emporium` must actually hold moveable value or approvals at attack time (e.g., mid-flight from other users' emporium operations, dust left by `handleOut`'s `balanceChange <= 0` skip logic, or third-party approvals granted to Emporium's address). The attack itself needs no privileged role — attacker fully controls `CircomData`, `EmporiumStack`, and generates their own valid proof for the trivial `MainEVMCircuitMin` circuit. Given that `Emporium` is a long-lived shared contract address used by many users' flows, non-zero transient balance/approval windows are plausible, making this a realistic, low-cost, repeatable attack whenever such a window exists.

### Recommendation
Do not allow `formInputEmporiumMin`/zero-token-dimension emporium flows to execute arbitrary `stack.ops` with `signerAddress == address(0)` without either (a) requiring `erc20TokenAddresses` to cover every asset touched by `op.endpoint`/`op.callData`, or (b) mandating a verified signature (non-zero `signerAddress`) for any op with `invokeWallet == false` in the min-input path. Additionally, wire `calldataHash` into an actual constraint inside `MainEVMCircuitMin` (e.g., constrain it against `message`/`messageSeed`) so the circuit provides real binding rather than being an unused public signal.

### Proof of Concept
Foundry fork test: deploy `Hinkal`, `EmporiumUpgradeable`, and a victim contract that trusts `msg.sender == Emporium` for a `transferFrom`/`withdraw`-style call (simulating leftover trust/approval); pre-fund Emporium with ETH/ERC20 balance. Build `CircomData` with `erc20TokenAddresses=[]`, `externalActionData.externalActionId = HINKAL_EMPORIUM_ACTION_ID`, `externalActionMetadata = abi.encode(EmporiumStack{signerAddress:address(0), ops:[EmporiumOperation{endpoint: victim, invokeWallet:false, value:0, callData: victim.withdrawTo.selector+attacker}]})`, set `calldataHash = getHashedCalldata(circomData)`, generate a real Groth16 proof for `MainEVMCircuitMin` with an attacker-chosen `messageSeed`. Call `Hinkal.transact(...)`. Assert: `balancesBefore.length == balancesAfter.length == 0` while `victim`'s/`Emporium`'s pre-funded balance strictly decreased and attacker's balance increased by the same amount — demonstrating value left Emporium/victim with zero entries in `deltaAmountChanges`/`balancesBefore`/`balancesAfter` accounting for it.

    function runAction(
        CircomData calldata circomData,
        int256[] calldata deltaAmountChanges
    ) external override onlyAllowedRecipient returns (UTXO[] memory) {
        EmporiumStack memory stack = abi.decode(
            circomData.externalActionData.externalActionMetadata,
            (EmporiumStack)
        );

        uint256[] memory balancesBefore = getBalancesForArray(
            circomData.erc20TokenAddresses
        );

        verifyWallet(stack, circomData);

        for (uint256 i = 0; i < stack.ops.length; i++) {
            EmporiumOperation memory op = stack.ops[i];

            bool success;
            bytes memory err;

            // CASE 1: Stateful Interaction
            if (op.invokeWallet && stack.signerAddress != address(0)) {
                (success, err) = IHinkalWallet(stack.signerAddress)
                    .callHinkalWallet(op.endpoint, op.callData, op.value);
            }
            // CASE 2: Stateless Interaction
            else {
                bytes4 selector = bytes4(op.callData);
                if (
                    selector == IHinkalWallet.callHinkalWallet.selector ||
                    selector == IHinkalWallet.doSendToRelay.selector
                ) {
                    revert UnauthorizedWalletCall();
                }

                (success, err) = op.endpoint.call{value: op.value}(op.callData);
            }

            if (!success) {
                revert CallFailed(err);
            }
        }

        payRelayFees(circomData, stack.signerAddress, deltaAmountChanges);

        uint256[] memory balancesAfter = getBalancesForArray(
            circomData.erc20TokenAddresses
        );

        UTXO[] memory utxoSet = new UTXO[](
            circomData.erc20TokenAddresses.length
        );

        uint256 utxoSetLength;

        for (uint256 i = 0; i < circomData.erc20TokenAddresses.length; i++) {
            int256 balanceChange = int256(balancesAfter[i]) -
                int256(balancesBefore[i]);

            if (deltaAmountChanges[i] < 0) {
                balanceChange -= deltaAmountChanges[i];
                // this equation reads: total change of emporium balance = what was moved to emporium (-deltaAmountChange) + how emporium balance changed through tx (balanceChange)
            }

            // the only case when balanceChange can be < 0, when there were some funds on emporium before the call
            if (balanceChange < 0) {
                revert BalanceChangeShouldBePositive();
            }

            UTXO memory utxoOut = handleOut(balanceChange, circomData, i);

            if (utxoOut.amount > 0) {
                utxoSet[utxoSetLength++] = utxoOut;
            }
        }

        if (utxoSetLength < circomData.erc20TokenAddresses.length) {
            utxoSet.skipLast(
                circomData.erc20TokenAddresses.length - utxoSetLength
            );
        }

        return utxoSet;
    }

    function verifyWallet(
        EmporiumStack memory stack,
        CircomData calldata circomData
    ) internal {
        EmporiumStorageVars storage $ = _getEmporiumStorage();

        if ($.usedMessages[circomData.emporiumMessage]) {
            revert UsedMessage();
        }

        $.usedMessages[circomData.emporiumMessage] = true;

        if (stack.signerAddress == address(0)) {
            return;
        }

        bytes32 hashedMessage = _hashTypedDataV4(
            keccak256(
                abi.encode(
                    EMPORIUM_SIGNATURE_TYPEHASH,
                    circomData.emporiumMessage,
                    _hashEmporiumOps(stack.ops),
                    stack.maxFee,
                    stack.deadline
                )
            )
        );

        (address recoveredAddress, ECDSA.RecoverError err) = ECDSA.tryRecover(
            hashedMessage,
            stack.v,
            stack.r,
            stack.s
        );
        bool verified = err == ECDSA.RecoverError.NoError &&
            recoveredAddress == stack.signerAddress;
        if (!verified) {
            revert InvalidSignature();
        }

        if (block.timestamp > stack.deadline) {
            revert SignatureExpired();
        }

        if (circomData.feeStructure.flatFee > stack.maxFee) {
            revert FeeExceedsSignedMax();
        }
    }

pragma circom 2.1.6;

include "../../node_modules/circomlib/circuits/poseidon.circom";

template MainEVMCircuitMin() {
  // Public inputs:
  signal input outTimeStamp;
  signal input calldataHash;

  // Private inputs:
  signal input messageSeed;

  // outputs:
  signal output message;
