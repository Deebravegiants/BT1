### Title
Incomplete query-parameter redaction allows sensitive values (API keys, tokens, session identifiers) to be written to node logs - ([File: core/web/router.go])

### Summary
The chainlink node's HTTP request logging middleware redacts query-string values before logging, but only for a hardcoded, narrow blacklist of password-like keys. Any other sensitive query parameter (e.g. `apikey`, `token`, `access_token`, `session`, `secret`, `key`) sent by an unprivileged client on a GET request is logged in full at Debug level, and query parameters are included in the request log line regardless of level via the `redact()` call.

### Finding Description
`loggerFunc` in `core/web/router.go` builds a structured log entry for every HTTP request handled by the node's API/gateway router, including the "query" field: [1](#0-0) 

The `redact` function only masks values whose key matches a small blacklist: [2](#0-1) 

The blacklist is limited to `password`, `newpassword`, `oldpassword`, `current_password`, `new_account_password`, and any key containing the substring "password". It does not cover other conventional sensitive query-parameter names such as `token`, `apikey`, `api_key`, `secret`, `auth`, or `session`. This directly parallels the OpenTelemetry advisory's root cause: query strings are logged/traced by default with only pass-through or partial masking, exposing EUII/credentials to telemetry/log backends. Here, an unprivileged client can trigger this simply by appending any of these parameter names to any request path handled by this router — the middleware is applied globally via `engine.Use(...)`: [3](#0-2) 

Note this is the node's own `gin` HTTP router (not the OpenTelemetry instrumentation itself — no `OpenTelemetry.Instrumentation.Http`/`AspNetCore` NuGet package was found in this Go codebase), so this is a same-bug-class analog implemented independently in `redact`, not the vulnerable dependency itself.

### Impact Explanation
If any current or future endpoint accepts a sensitive value via a query string parameter that isn't named with "password" (e.g., a bearer token, API key, or session identifier passed as `?token=...` or `?apikey=...`), that value will be persisted into the node's logs at Debug level in cleartext. Log files/aggregators are typically operator-accessible and often less tightly controlled than request bodies, so this creates a secret-disclosure path (CWE-201/CWE-212) analogous to the referenced advisory.

### Likelihood Explanation
Likelihood depends on whether any reachable, unprivileged-facing route accepts secrets via query parameters rather than headers or JSON bodies. The router lists `/query` (GraphQL), session, health, debug and v2 API routes — the JSON APIs primarily pass credentials via body/headers, reducing direct exploitability today. However, the blacklist itself is a latent, systemic weakness: it is an allow-nothing/deny-few list rather than a deny-by-default scheme, so any endpoint (including third-party/bridge/debug endpoints reachable under this router) that accepts a differently-named secret in the query string would silently leak it. This is a design gap rather than a confirmed exploitable endpoint in the code reviewed.

### Recommendation
Replace the narrow blacklist in `isBlacklisted` (`core/web/router.go`) with a broader redaction policy: match common sensitive parameter name patterns (`token`, `secret`, `key`, `auth`, `session`, `credential`, etc.) case-insensitively, or better, redact all query values by default and allowlist only known-safe parameter names (mirroring the OpenTelemetry fix's "redact everything by default" approach). Apply the same policy anywhere else request URLs/query strings are logged (e.g., verify `core/services/gateway` and `core/web/loop_registry.go` proxy paths don't log raw upstream URLs unintentionally).

### Proof of Concept
1. Send any authenticated or unauthenticated request to a route served by `NewRouter`, e.g. `GET /sessions?apikey=SUPERSECRETVALUE`.
2. With `LOG_LEVEL=debug` (or equivalent config), `loggerFunc` logs the request with `"query", redact(c.Request.URL.Query())`.
3. Because `apikey` is not in `blacklist` and does not contain the substring `password`, `redact()` passes its value through unchanged, so `apikey=SUPERSECRETVALUE` appears verbatim in the node's log output.

func redact(values url.Values) string {
	cleaned := url.Values{}
	for k, v := range values {
		if isBlacklisted(k) {
			cleaned[k] = []string{"REDACTED"}
			continue
		}
		cleaned[k] = v
	}
	return cleaned.Encode()
}

// NOTE: keys must be in lowercase for case insensitive match
var blacklist = map[string]struct{}{
	"password":             {},
	"newpassword":          {},
	"oldpassword":          {},
	"current_password":     {},
	"new_account_password": {},
}

func isBlacklisted(k string) bool {
	lk := strings.ToLower(k)
	if _, ok := blacklist[lk]; ok || strings.Contains(lk, "password") {
		return true
	}
	return false
}
