## Confirmed analog found

### Title
Unvalidated hex-length subtraction in `normalizeHex` causes a panic (negative `strings.Repeat` count), enabling unauthenticated DoS of the workflow HTTP trigger gateway - (File: `core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go`)

### Summary
`validateHexInput` bounds each hex field ("workflowID"/"workflowOwner") only by an upper length limit and hex-decodability, but does not require an even-aligned relationship between the raw string length and the `0x`-stripped length. `normalizeHex` then computes `expectedHexLength - len(hexStr)` and feeds it directly into `strings.Repeat`, which panics on a negative count. Because both individual fields pass their own bound checks yet their *combined* derived quantity can still be negative, this mirrors the reported bug class: individually-valid values whose difference is not re-validated before being passed into a domain-restricted function.

### Finding Description
`validateHexInput` (`http_trigger_handler.go:267-283`) enforces `len(input) <= expectedLength` and requires the (optionally `0x`-stripped) remainder to be valid hex — it never requires the `0x` prefix to be present. [1](#0-0) 

`resolveWorkflowID` then calls `normalizeHex(workflowID, workflowIDLength)` for user-supplied `workflowID`, and `normalizeHex(triggerReq.Params.Workflow.WorkflowOwner, workflowOwnerLength)` for `workflowOwner`: [2](#0-1) 

`normalizeHex` computes the padding length as `expectedHexLength - len(hexStr)` where `expectedHexLength = length - 2` (subtracting the `"0x"` prefix length), and passes it straight to `strings.Repeat`: [3](#0-2) 

If a caller supplies a `workflowID` (or `workflowOwner`) that is exactly `workflowIDLength` (66) or `workflowOwnerLength` (42) characters of valid lowercase hex **without** the `0x` prefix, `validateHexInput` accepts it (length ≤ expectedLength, and `hex.DecodeString` succeeds because the string still has an even number of hex digits). But in `normalizeHex`, `strings.TrimPrefix(input, "0x")` is a no-op (no prefix to strip), so `len(hexStr)` equals the full input length (66 or 42), while `expectedHexLength` is `length - 2` (64 or 40). The subtraction `expectedHexLength - len(hexStr)` becomes negative (e.g., `64 - 66 = -2`), and `strings.Repeat("0", -2)` panics with `"strings: negative Repeat count"`.

This is exactly analogous to the Panoptic finding: `validateHexInput` validates each field independently (like `tickLower`/`tickUpper` being independently in-bounds), but the *derived* quantity used downstream (`expectedHexLength - len(hexStr)`, analogous to `tickUpper - tickLower` fed into `getSqrtRatioAtTick`) is never checked for being within the domain the downstream primitive (`strings.Repeat`, analogous to `getSqrtRatioAtTick`) requires (non-negative).

### Impact Explanation
`strings.Repeat` panics (not returns an error) on a negative count. This panic occurs inside `resolveWorkflowID`, which is invoked synchronously while handling an unauthenticated HTTP trigger request (`workflows.execute`) at the internet-facing gateway, before any per-request authorization/signature check (`authorizeRequest` runs after `resolveWorkflowID`). Any unprivileged external caller of the workflow HTTP trigger endpoint can crash the goroutine handling the request. Depending on whether the gateway server recovers panics per-request (standard `net/http` behavior recovers per-connection, but goroutines spawned without recover can crash the process), this is at minimum a reliable request-level DoS trigger, and at worst can take down the gateway node process if the panic occurs outside of an HTTP-recovered goroutine context, since this handler processes JSON-RPC messages that may be dispatched via internal goroutines rather than directly inside `net/http`'s panic-recovering handler.

### Likelihood Explanation
High likelihood: it requires no authentication, no allowlisting, and no special node/operator privileges — only a single crafted `workflows.execute` JSON-RPC request with a `workflowID` or `workflowOwner` field that is valid hex, correct length, but missing the `0x` prefix. This is trivially reachable by any client of the public gateway HTTP endpoint.

### Recommendation
- In `normalizeHex`, always require and enforce presence of a `0x` prefix (reject inputs without it) rather than silently no-op'ing `TrimPrefix`, and/or clamp/validate that `expectedHexLength - len(hexStr)` is non-negative before calling `strings.Repeat`, returning an error instead of padding.
- Strengthen `validateHexInput` to require the `0x` prefix explicitly (it already rejects non-lowercase and oversized input, but never checks for the prefix), so the length invariants assumed by `normalizeHex` actually hold.
- Add a unit test submitting a 66-character (or 42-character) all-hex `workflowID`/`workflowOwner` without a `0x` prefix to confirm the handler returns a normal JSON-RPC error rather than panicking.

### Proof of Concept
Send a `workflows.execute` request to the gateway's user-facing endpoint with:
```json
{
  "jsonrpc": "2.0",
  "id": "1",
  "method": "workflows.execute",
  "params": {
    "workflow": {
      "workflowID": "1234567890abcdef1234567890abcdef1234567890abcdef1234567890abcdef"
    },
    "input": {}
  }
}
```
where `workflowID` is exactly 66 lowercase hex characters (no `0x` prefix). This passes `validateHexInput` (`len <= 66`, valid hex after a no-op `TrimPrefix`), then `resolveWorkflowID` calls `normalizeHex(workflowID, 66)`, computing `strings.Repeat("0", 64-66)` → panic: `strings: negative Repeat count`. The same applies to `workflowOwner` with `workflowOwnerLength` (42).

```go
func validateHexInput(input string, expectedLength int) error {
	if input != strings.ToLower(input) {
		return errors.New("must be lowercase")
	}

	if len(input) > expectedLength {
		return fmt.Errorf("hex string too long: expected at most %d characters, got %d", expectedLength, len(input))
	}

	hexStr := strings.TrimPrefix(input, "0x")
	_, err := hex.DecodeString(hexStr)
	if err != nil {
		return errors.New("must be a valid hex string")
	}

	return nil
}
```

```go
// normalizeHex normalizes a hex string by stripping 0x prefix, padding with leading zeros, and adding 0x prefix back
func normalizeHex(input string, length int) string {
	hexStr := strings.TrimPrefix(input, "0x")
	// length-2 because we'll add "0x" prefix
	expectedHexLength := length - 2
	paddedHex := strings.Repeat("0", expectedHexLength-len(hexStr)) + hexStr
	return "0x" + paddedHex
}
```

```go
func (h *httpTriggerHandler) resolveWorkflowID(ctx context.Context, triggerReq *jsonrpc.Request[gateway_common.HTTPTriggerRequest], requestID string, callback handlers.Callback) (string, error) {
	h.lggr.Debugw("resolving workflow ID", "workflowID", triggerReq.Params.Workflow.WorkflowID, "workflowOwner", triggerReq.Params.Workflow.WorkflowOwner, "workflowName", triggerReq.Params.Workflow.WorkflowName, "workflowTag", triggerReq.Params.Workflow.WorkflowTag, "requestID", requestID)
	workflowID := triggerReq.Params.Workflow.WorkflowID
	if workflowID != "" {
		workflowID = normalizeHex(workflowID, workflowIDLength)
		_, found := h.workflowMetadataHandler.GetWorkflowReference(workflowID)
		if !found {
			h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, fmt.Sprintf("Workflow not found. 'workflowID' %s is not a valid workflow ID", workflowID), callback)
			return "", errors.New("workflow not found")
		}
		return workflowID, nil
	}
	workflowOwner := normalizeHex(triggerReq.Params.Workflow.WorkflowOwner, workflowOwnerLength)
	workflowName := "0x" + hex.EncodeToString([]byte(workflows.HashTruncateName(triggerReq.Params.Workflow.WorkflowName)))
	workflowID, found := h.workflowMetadataHandler.GetWorkflowID(
		workflowOwner,
		workflowName,
		triggerReq.Params.Workflow.WorkflowTag,
	)
	if !found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "Workflow not found. Provide either a valid 'workflowID' or a valid combination of 'workflowOwner', 'workflowName', and 'workflowTag'", callback)
		return "", errors.New("workflow not found")
	}
	return workflowID, nil
}
```
