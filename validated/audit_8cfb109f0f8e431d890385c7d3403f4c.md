### Title
Unbounded borrow-index accrual overflows `i128` in `scaled_to_original`, permanently freezing the market and all user funds — ([File: common/src/rates.rs / contracts/pool/src/cache/scale.rs])

### Summary
CVE-2018-11218's bug class is unchecked arithmetic/bounds growth leading to memory corruption. The lending analog is an unchecked value-growth bound: RAY-scaled debt accrual can push the product `scaled_debt * borrow_index` past `i128::MAX` inside `scaled_to_original`, causing every subsequent market operation to panic with `MathOverflow`. The project's own integration test proves the freeze: `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` shows the `MAX_BORROW_INDEX_RAY` cap never engages in time, and afterwards `withdraw`, `repay`, and `update_indexes` all revert [1](#0-0) .

### Finding Description
The pool caches scaled supply/debt (`Ray` shares) and unscales them via `scaled_to_original(env, scaled, index)` — see `Cache::calculate_utilization`, `unscale_supply`, `unscale_borrow` in `contracts/pool/src/cache/scale.rs` [2](#0-1) . `scaled_to_original` multiplies `scaled * index` through the `mul_div` primitives in `common/src/math/fp_core.rs`, which panic with `GenericError::MathOverflow` when the result exceeds `i128` [3](#0-2) .

Accrual runs at the head of every verb (supply, borrow, withdraw, repay, liquidate, `update_indexes`), so once `borrowed_scaled * borrow_index` crosses `i128::MAX`, every entrypoint touching that market panics before any state change. The intended guard, `MAX_BORROW_INDEX_RAY`, caps the index itself — but the overflow is a bound on `scaled * index`, and at whale scale (~10^28 raw units of an 18-decimal asset) the index only needs to reach ~170× RAY, far below the cap, before the product overflows. The test confirms the cap never engages and the market is frozen with `MATH_OVERFLOW` on repay, withdraw, and `update_indexes` [4](#0-3) .

### Impact Explanation
Permanent freezing of funds: once the cliff is crossed, no supplier can withdraw, no borrower can repay, and no liquidator can act in that market — every path accrues first and panics. All deposits and outstanding debt in the market are bricked. `clean_bad_debt`/`recapitalize` also route through accrual, so there is no administrative escape short of a contract upgrade/migration.

### Likelihood Explanation
An unprivileged address can call `update_indexes` and can create the preconditions (large supply, ~98% borrow utilization on a steep rate curve). The barrier is wall-clock: the test required several years of ledger-time accrual at sustained maximum utilization, and an attacker cannot accelerate ledger timestamps. It is therefore not a prompt exploit, but it is a deterministic, irreversible liveness failure reachable purely through permissionless entrypoints — once any large whale market drifts into sustained high utilization, the market's death is only a matter of accrual, and there is no in-band recovery. Medium/High severity on impact, low-medium on attacker reachability.

### Recommendation
Enforce the overflow bound on the product, not just the index: in the accrual path (`simulate_update_indexes`/`update_indexes` in `common/src/rates.rs`), clamp or saturate `borrow_index` such that `borrowed_scaled * borrow_index` stays below `i128::MAX` given current `borrowed_scaled` — i.e., compute the effective cap as `min(MAX_BORROW_INDEX_RAY, i128::MAX / borrowed_scaled)` before storing the new index. Alternatively, widen `scaled_to_original` to `I256` intermediates and keep the `i128` result checked, so accrual saturates rather than panics, preserving withdraw/repay paths. The corrected bound should also be reflected in `docs/reference/formulas.md`, whose stated bound the test already flags as wrong [5](#0-4) .

### Proof of Concept
The existing harness test is the PoC (`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:320`):

```rust
// Whale market: 10B units of an 18-decimal asset, 98% borrowed, XLM curve.
let principal = BILLION * 10i128.pow(18);
t.supply_raw(BOB, "BIG18", principal);
t.borrow_raw(ALICE, "BIG18", principal / 100 * 98);

// Accrue year by year via permissionless update_indexes until panic.
loop {
    t.advance_time(YEAR_SECS);
    if let Err(e) = t.try_update_indexes_for(&["BIG18"]) { break e; }
}
// => MathOverflow; borrow_index is still < MAX_BORROW_INDEX_RAY (cap never engaged)

// Market is permanently frozen:
assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```

Root cause: `scaled_to_original` computes `scaled * index / RAY` in `i128` (with `I256` fallback only widening to a still-`i128`-checked result), and every market verb accrues before acting, so the overflow is a permanent liveness kill for that market.

/// grows past 170x in a few years, and the next accrual panics inside

fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {

        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );

pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {

        "mul_div_half_up: non-negative x, y and positive d"
    );

        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
