### No vulnerability found for this question.

**Reasoning:** `SaltManager.getCachedSalt()` intentionally caches the salt for `SALT_TTL_MS` (5 minutes) and does not re-poll `current_salt` on every call [1](#0-0) , and `IntentPayloadBuilder.buildWithSalt` embeds whatever salt it's given directly into the nonce via `VersionedNonceBuilder.encodeNonce` [2](#0-1) . This means a signed payload's nonce carries a concrete salt value, and the security question is whether the *contract itself* will still accept a nonce built from a salt that has since been rotated on-chain.

That validation — whether a nonce's embedded salt matches the contract's active epoch — happens inside the `intents.near` contract at execution time, not in this SDK. The premise of the question ("if relayer/contract validation is loose during the rotation window, execution could proceed") explicitly requires assuming a defect or weakness in `intents.near`'s own signature/nonce verification, which is out of scope per the rules ("defects inside intents.near, bridge contracts ... with no path through this repo" and "trust assumptions about ... the relayer"). The SDK's TTL-based caching does not create the divergence; it only determines what value the SDK signs with — enforcement of whether that value is still valid is the contract's responsibility, and the question itself concedes the relayer/contract path exists (`INVALID_SALT`) as the intended defense.

Since exploitability depends entirely on hypothetically loose on-chain/relayer validation rather than any SDK code path, this is a theoretical finding outside the audit's scope, not a defect in `SaltManager` or `IntentPayloadBuilder`.

	async getCachedSalt(): Promise<Salt> {
		if (this.isCacheValid()) {
			// biome-ignore lint/style/noNonNullAssertion: isCacheValid ensures currentSalt is set
			return this.currentSalt!;
		}

		if (this.fetchPromise) {
			return this.fetchPromise;
		}

		this.fetchPromise = this.fetchAndCache().finally(() => {
			this.fetchPromise = null;
		});

		return this.fetchPromise;
	}
