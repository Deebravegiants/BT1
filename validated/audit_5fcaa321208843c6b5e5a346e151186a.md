Audit Report

## Title
Unsanitized `profile` route parameter allows path injection in LOOP plugin pprof proxy - (File: core/web/loop_registry.go)

## Summary
`pluginPPROFHandler` builds the outbound URL to a LOOP plugin's internal pprof server by directly string-concatenating the unsanitized `profile` gin route parameter into the path: `fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), ...)` [1](#0-0) . This lets an authenticated caller inject `../` sequences or extra path/query segments, causing the node to forward the manipulated request to arbitrary paths on the plugin's local HTTP server rather than the intended `/debug/pprof/*` namespace.

## Finding Description
The handler validates only that the named plugin exists via `l.registry.Get(pluginName)`, then interpolates `gc.Param("profile")` directly into the target URL string with no allowlisting, character filtering, or `path.Clean`/containment check [2](#0-1) . Contrast with `pluginMetricHandler`, which hardcodes the fixed suffix `/metrics` and takes no user-controlled path segment [3](#0-2) . The route is registered under the authenticated group via `metricRoutes(authv2)` with only the comment "Debug routes accessible via authentication" — it is not wrapped in `auth.RequiresEditRole` or `auth.RequiresAdminRole`, unlike other admin-sensitive endpoints registered in the same block [4](#0-3) . Reviewing `core/web/auth/auth.go`, `RequiresRunRole`/`RequiresEditRole`/`RequiresAdminRole` are the only role-elevation gates available, and none of them wrap this handler, so any session that passes the basic `Authenticate` middleware (including `UserRoleView`) can reach it [5](#0-4) .

## Impact Explanation
Because host and port are fixed (`l.loopHostName`, `p.EnvCfg.PrometheusPort`), the attacker cannot reach arbitrary external hosts (this is not a full SSRF), but they can manipulate the trailing path/query of the request sent to the plugin's own local debug server, potentially reaching endpoints on that local HTTP listener outside the intended `/debug/pprof/*` surface, or injecting additional query parameters. This is an internal-service request-manipulation bug scoped to the plugin's own local port, with a low-privilege authenticated node-API user as the origin. It does not directly yield node private keys, fund movement, or job execution — the LOOP plugin's HTTP listener is minimal (primarily pprof/metrics), which somewhat limits realistic impact, but the missing input sanitization and missing role gate are real, verified code defects.

## Likelihood Explanation
High — exploitation requires only a valid authenticated session (any role, since no `RequiresEditRole`/`RequiresAdminRole` wrapper is applied) and a single crafted GET request with a manipulated `profile` parameter; no race conditions, admin access, or special setup needed.

## Recommendation
Allowlist/validate `profile` against the known pprof profile names (`goroutine`, `heap`, `threadcreate`, `block`, `mutex`, `allocs`, `profile`, `trace`, `cmdline`, `symbol`) before use, and construct the outbound URL via `url.URL{Path: path.Join("/debug/pprof/", profile)}` with a post-join prefix check rather than raw string concatenation. Additionally, wrap this and `pluginMetricHandler`/pprof routes with an explicit role check (e.g., `RequiresEditRole`) consistent with other debug-sensitive endpoints in the router.

## Proof of Concept
1. Authenticate as any user with a valid session/API token (any role, since the route lacks `RequiresEditRole`/`RequiresAdminRole`).
2. Send `GET /plugins/<validPluginName>/pprof/../../someOtherPath` (exact path per `metricRoutes` wiring in `core/web/router.go`).
3. Confirm via server logs (`l.logger.Infow("Forwarding plugin pprof request", ...)`) or a test double for `l.loopHostName`'s HTTP server that the outbound request path is `http://<loopHostName>:<PrometheusPort>/debug/pprof/../../someOtherPath` — i.e., unsanitized and verbatim, reachable beyond `/debug/pprof/*`.
4. A Go unit test constructing `pluginPPROFHandler` with a stub registry/plugin and asserting on the built `pluginURL` string for an injected `profile` value (e.g. `"../metrics"`) would demonstrate the string is passed through unmodified.

```go
func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
```

```go
// RequiresRunRole extracts the user object from the context, and asserts the user's role is at least
// 'run'
func RequiresRunRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// RequiresEditRole extracts the user object from the context, and asserts the user's role is at least
// 'edit'
func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}
```
