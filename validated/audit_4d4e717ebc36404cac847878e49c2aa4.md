Audit Report

## Title
View-role users can read the `OutgoingToken` secret for any External Initiator via `GET /v2/external_initiators` - (File: core/web/external_initiators_controller.go)

## Summary
The `GET /v2/external_initiators` endpoint returns each External Initiator's `OutgoingToken` to any authenticated user, including users with the lowest, read-only `view` role. `OutgoingToken` is a bearer secret that Chainlink itself presents to the initiator's remote webhook URL when notifying it of new jobs, so its disclosure to an unprivileged/view-only session lets that user impersonate the node to the external initiator.

## Finding Description
`ExternalInitiatorsController.Index` builds a `presenters.ExternalInitiatorResource` for every stored initiator and serializes it directly to the caller [1](#0-0) . `ExternalInitiatorResource` and its constructor `NewExternalInitiatorResource` explicitly include `OutgoingToken` unredacted, copied straight from the `bridges.ExternalInitiator` DB record [2](#0-1) . The route is registered with no minimum-role guard, unlike `Create`/`Destroy` on the same resource which require `auth.RequiresEditRole` [3](#0-2) . The RBAC route map used by the test suite confirms `GET /v2/external_initiators` is explicitly marked `viewOnlyAllowed: true`, meaning a `view`-role session can call it [4](#0-3) . By contrast, at creation time the token pair is only meant to be revealed once via `ExternalInitiatorAuthentication`, and mutating actions are gated behind `RequiresEditRole` [6](#0-5) , but the same value is trivially re-obtainable afterward by any authenticated user via `Index`, defeating the intent of restricting initiator secrets to privileged roles. No redaction, filtering, or role check exists on the `Index` handler to prevent this.

## Impact Explanation
A user granted only the `view` role can enumerate all configured External Initiators and harvest every `OutgoingToken`. With that token, the low-privileged actor can impersonate the Chainlink node against the initiator's remote endpoint, potentially triggering unauthorized actions on that third-party system or spoofing outgoing initiator traffic. This maps to the in-scope impact category of key/secret exfiltration via a node API role-bypass (a secret intended to be protected behind `edit`/`admin` privileges is exposed to any authenticated session, including `view`).

## Likelihood Explanation
Likelihood is high for any deployment using the External Initiator feature with multiple user roles configured (e.g., `view` accounts for auditors/read-only dashboards). No special conditions are required beyond having any valid authenticated session and calling a normal, paginated, documented API endpoint.

## Recommendation
Do not include `OutgoingToken` (or other initiator secrets) in the `ExternalInitiatorResource` returned by `Index`. Gate the listing endpoint with `auth.RequiresEditRole` (or higher) consistent with `Create`/`Destroy`, or strip secret fields from the list presenter and only reveal them once at creation, matching the pattern used for `ExternalInitiatorAuthentication`.

## Proof of Concept
1. As an admin/edit user, create an External Initiator: `POST /v2/external_initiators {"name":"foo","url":"http://example.com"}` and note the returned `outgoingToken`.
2. Authenticate as a `view`-role user/session.
3. Call `GET /v2/external_initiators` as that `view` user.
4. Observe the response body includes the plaintext `outgoingToken` for `foo`, as validated by the existing controller test assertions [7](#0-6) , confirming a `view`-privileged actor can obtain the secret without going through `RequiresEditRole`.

func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}

		AccessKey:     ei.AccessKey,

}
