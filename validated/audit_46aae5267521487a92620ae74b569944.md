Confirmed: `CallDispatcher.dispatch()` is used as a shared, single-instance intermediary across `IntentGatewayV2` (predispatch/postdispatch swaps), `HyperFungibleToken`/`WrappedHyperFungibleToken` calldata delivery, and it holds ERC20/native balances mid-flow with `receive() external payable {}`. It has no access-control modifier of any kind.

### Title
Unauthenticated `CallDispatcher.dispatch()` lets anyone sweep any ERC20/native balance left in the shared dispatcher - (File: evm/src/utils/CallDispatcher.sol)

### Summary
The `CallDispatcher` contract acts as the "Executor" analog to the LiFi report — a shared intermediate contract that `IntentGatewayV2` (predispatch/postdispatch calldata), `HyperFungibleToken`, and `WrappedHyperFungibleToken` all route calldata and token balances through. Unlike LiFi's `Executor.sol`, which at least gates execution behind a swap function with (imperfect) balance-delta accounting, Hyperbridge's `CallDispatcher.dispatch()` has **no caller restriction whatsoever** and directly forwards the contract's own native/token value to attacker-chosen targets with attacker-chosen calldata.

### Finding Description
`CallDispatcher.sol` is declared with a public `receive()` and an unauthenticated `dispatch` entrypoint: [1](#0-0) 

`dispatch(bytes memory encoded)` decodes an arbitrary `Call[]` and executes `to.call{value: call.value}(data)` for each entry, using the dispatcher's own balance for `value`, with the only checks being that `to` has code and that the sub-call succeeds. There is no `msg.sender` check, no `onlyGateway`/`onlyHost` modifier, and no reentrancy guard.

The dispatcher is designed to legitimately hold balances mid-transaction: order flows in `IntentGatewayV2`/`IntentsBase` push tokens or ETH to the dispatcher, invoke `ICallDispatcher(dispatcher).dispatch(order.predispatch.call)` / `dispatch(order.output.call)`, and then sweep back whatever balance remains for the specific tokens the order cares about: [2](#0-1) [3](#0-2) 

The sweep is scoped only to the token addresses listed in `order.inputs`/`order.output.assets` — any other asset the dispatcher happens to be holding (e.g., unspent native ETH refunded by a router mid-swap, dust from a partially executed multi-hop swap, or a token not enumerated in the order) is left behind. Documentation confirms the dispatcher is explicitly expected to "hold and forward native tokens" as part of composable swap calldata (e.g., `swapETHForExactTokens`, which by design refunds unspent ETH to `msg.sender` — the `CallDispatcher` itself): [4](#0-3) 

Because `dispatch()` is permissionless, once any ERC20 or native balance is left on the `CallDispatcher` — even a small refund from an exact-output swap, or the dust window between one order's `dispatch` call finishing and the sweep-back `dispatch` call executing in the same or a later transaction — any external account can call `CallDispatcher.dispatch()` directly with a `Call[]` that transfers that balance to itself (e.g., `{to: token, value: 0, data: transfer(attacker, balanceOf(dispatcher))}` for ERC20, or `{to: attacker, value: address(dispatcher).balance, data: ""}` for native ETH).

### Impact Explanation
This is a direct, unauthenticated theft vector against any token or native balance temporarily or permanently resident in the shared `CallDispatcher`. Since the same dispatcher instance is wired into multiple apps (`IntentGatewayV2`, `HyperFungibleToken`, `WrappedHyperFungibleToken`), balances originating from unrelated flows can be drained by any third party who is quick enough to front-run the legitimate sweep-back call, or who catches balances the sweep loop doesn't enumerate (tokens/native ETH not listed among that order's `inputs`/`output.assets`). This matches "concrete theft ... of funds" via an unbacked/unauthorized action reachable from a single, unprivileged transaction.

### Likelihood Explanation
High. No proof, relayer, or governance action is required — a plain EOA calling `CallDispatcher.dispatch(...)` is sufficient. The window of opportunity recurs naturally: any predispatch/postdispatch calldata that performs an exact-output swap (as shown in the project's own documentation and tests) leaves refunded native ETH or token dust on the dispatcher between the user/solver-supplied call and the protocol's sweep-back call, and any asset not explicitly enumerated in the order's `inputs`/`output.assets` is never swept at all and remains permanently exposed.

### Recommendation
Restrict `CallDispatcher.dispatch()` to a caller allowlist (e.g., only the registered `IntentGatewayV2`/`HyperFungibleToken`/`WrappedHyperFungibleToken` instances), or make the dispatcher stateless-by-design by requiring it to never hold value across calls (flash-style: revert if balance changes unexpectedly, or force per-order ephemeral dispatcher instances via CREATE2 that get self-destructed/never reused). At minimum, add an `onlyAuthorizedCaller` modifier gating `dispatch`, and audit all calldata patterns (e.g., Uniswap V2 exact-output swaps) that can leave refunds on the dispatcher to ensure 100% of any resulting balance is swept back atomically in the same call that produced it, not left for a follow-up sweep.

### Proof of Concept
1. A user/solver submits an `IntentGatewayV2.placeOrder`/`fillOrder` whose `predispatch.call`/`output.call` includes a Uniswap V2 `swapETHForExactTokens` call routed through the shared `CallDispatcher` (as shown in `docs/content/developers/evm/hyper-fungible-token/wrapped-hyper-fungible-token.mdx`), sending more native value than the exact-output swap consumes.
2. The Uniswap V2 router refunds the unspent ETH to `msg.sender`, which is the `CallDispatcher` contract, landing native ETH on the dispatcher's balance.
3. Before (or in place of) the protocol's own sweep-back `dispatch` call runs, an attacker calls `CallDispatcher.dispatch(abi.encode([Call({to: attacker, value: address(dispatcher).balance, data: ""})]))` directly.
4. Since `dispatch` has no caller restriction, the call succeeds and the refunded ETH (or any leftover ERC20 balance via a `transfer` call to an ERC20 token address) is sent to the attacker instead of being returned to the protocol/user. [5](#0-4)

    /**
     *  @dev reverts if the target is not a contract or if any of the calls reverts.
     */
    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
