### Title
Venue pricing derives fill rates from live Uniswap V4 spot price (`sqrtPriceX96`) with no TWAP, letting a flash-loan manipulate solver fills - (File: `sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts`, `sdk/packages/simplex/src/strategies/fx.ts`)

### Summary
Simplex's `FXFiller` prices curve-less pairs against the **instantaneous** Uniswap V4 pool price (`sqrtPriceX96` read via `getSlot0`), the same class of unmitigated spot-price reliance flagged in the Predy report. The only defense is an *optional*, static `referencePrice`/`maxDeviationBps` band that operators may leave unset ("omit both to leave the chain unguarded"), and even when set it only bounds drift from a stale reference — it is not a manipulation-resistant TWAP.

### Finding Description
`UniswapV4FundingPlanner.getExoticTokenPrice` selects the most-liquid position and calls `computeDirectPoolPriceUsd`, which returns the pool's raw mid price derived straight from the pool's current `sqrtPriceX96`/tick state read by `refresh()`: [1](#0-0) [2](#0-1) 

The live slot0 read that feeds this price has no averaging window at all: [3](#0-2) 

`FXFiller.resolveLegRates` consumes this venue price directly as the fill rate for the leg, gated only by `checkPriceGuard`: [4](#0-3) 

`checkPriceGuard` itself is a no-op ("passes every quote") whenever no `referencePrice`/`maxDeviationBps` guard is configured for the chain, and the configuration format explicitly allows omitting the guard entirely: [5](#0-4) [6](#0-5) 

The project's own internal flow documentation confirms the design gap: the fee tier is never applied and there is no size/impact term — the pool mid is extended linearly across the whole quantity, and the price guard (when present) checks deviation from a static reference, not execution cost: [7](#0-6) 

The same unguarded pool quote also sizes confirmation-depth policy via `referenceRate`, so a manipulated pool can shrink reorg protection in addition to mispricing fills: [8](#0-7) 

This mirrors the reported Predy bug class precisely: `Trade::getSqrtPrice` reading Uniswap's `slot0` spot price with no TWAP, exploitable via a flash-loan-funded liquidity/swap manipulation immediately before the priced action executes.

### Impact Explanation
Any unprivileged actor who can submit an intent order and simultaneously manipulate the referenced Uniswap V4 pool's spot price (a standard flash-loan swap) can force the Simplex solver to price a curve-less pair leg at an attacker-favorable rate:
- If the pool price is pushed down right before the solver quotes/fills, the solver (`FXFiller`) overpays the exotic token relative to its true value, directly transferring solver funds to the attacker.
- If pushed up, the attacker's own USD input is undervalued and the solver underpays, but the attacker can also use this to distort `referenceRate`'s USD notional sizing, weakening confirmation-depth protection for the order.
- Because the guard (`referencePrice`/`maxDeviationBps`) is entirely optional per operator configuration, deployments that omit it (a documented, supported configuration) have zero defense against this.

This is concrete theft of solver-held funds (the funding venue's LP-sourced inventory backing intent fills), matching the "concrete theft ... of funds" acceptance bar.

### Likelihood Explanation
Likelihood is high wherever a `[vault.uniswapV4]` venue-priced pair is configured without a guard, or where the guard's static reference is set loosely (the guard checks deviation from a fixed price, not manipulation resistance). Uniswap V4 flash-loan/flash-swap price manipulation within a single block is a well-known, cheap, and repeatable attack primitive; the solver refreshes pool state and prices synchronously with the fill, so an attacker controls the exact block the quote is taken in.

### Recommendation
- Require a manipulation-resistant TWAP (e.g., Uniswap V4 truncated oracle / observation-based TWAP) instead of the instantaneous `sqrtPriceX96` for `computeDirectPoolPriceUsd`.
- Make the price guard (`referencePrice`/`maxDeviationBps`) mandatory for any venue-priced pair rather than optional, and consider deriving the reference from an independent off-chain price feed rather than a static operator-set value.
- Apply the pool's fee tier and a size/impact term when deriving the quoted rate, rather than treating the mid price as valid across the whole notional.

### Proof of Concept
1. Operator configures a curve-less `[[pairs]]` entry priced via `[vault.uniswapV4]` with no `referencePrice`/`maxDeviationBps` (a documented, valid configuration) — see `sdk/packages/simplex/filler-config-example.toml` lines 281-292 and `sdk/packages/simplex/src/strategies/fx.ts` `checkPriceGuard` returning `true` when no guard exists.
2. Attacker takes a flash loan and swaps heavily against the exotic token's Uniswap V4 pool tied to that funding position, moving `sqrtPriceX96`/tick far from fair value.
3. Attacker (or an accomplice) submits an intent order on this pair; Simplex's `FXFiller.resolveLegRates` calls `venueUsdPrice` → `UniswapV4FundingPlanner.getExoticTokenPrice` → `computeDirectPoolPriceUsd`, which reads the manipulated `slot0` price with no averaging.
4. The solver computes and executes a fill at the manipulated rate via `computeLegPolicyOutput`, over- or under-paying the attacker.
5. Attacker reverses the flash-loan swap in the same transaction, restoring the pool and pocketing the mispriced difference from the solver's inventory.

		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}

	private computeDirectPoolPriceUsd(
		pos: HydratedV4Position,
		sdkPool: V4Pool,
		chain: string,
	): { exoticToken: string; priceUsd: Decimal } | null {
		const usdc = this.configService.getUsdcAsset(chain).toLowerCase()
		const usdt = this.configService.getUsdtAsset(chain).toLowerCase()
		const c0 = pos.currency0.toLowerCase()

			// currency0 is stable → exotic is currency1
			// token1Price = "token0 per token1" = USD per exotic

			}
		}

			// currency1 is stable → exotic is currency0
			// token0Price = "token1 per token0" = USD per exotic
			return {
				exoticToken: c0,
				priceUsd: new Decimal(sdkPool.token0Price.toFixed(18)),
			}
		}

		return null
	}

	/**
	 * Validates a live venue quote against the static reference price for the chain.
	 * Returns true (pass) when no guard is configured, or no reference exists for the
	 * chain. Returns false when the quote (token1 per USD) deviates from the reference
	 * by more than `maxDeviationBps`, in which case the order must not be filled.
	 */
	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {
			this.logger.warn(
				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
	}

	/**
	 * Minimum-size reference rate (token1 per token0) for a leg's pair: the
	 * bid curve at 0 (the side token1-input legs trade at), falling back to the
	 * ask curve, then the live venue quote for venue-priced pairs.
	 */
	private async referenceRate(
		leg: ResolvedLeg,
		venueUsdPrice: (chain: string, token1Address: string) => Promise<Decimal | null>,
	): Promise<Decimal | null> {
		const policy = leg.pair.bidPricePolicy ?? leg.pair.askPricePolicy
		if (policy) {
			const rate = policy.getPrice(new Decimal(0))
			return rate.gt(0) ? rate : null
		}
		// Venue-priced pair: token0 is USD-stable (constructor invariant), so the
		// venue's USD-per-token1 quote inverts straight into token1-per-token0.
		const venueUsd = await venueUsdPrice(leg.token1Chain, leg.token1Address)
		if (!venueUsd) return null
		const venueRate = new Decimal(1).div(venueUsd)
		// Same guard as trade pricing: this rate sizes the order's USD notional
		// for confirmation depth, and a manipulated pool understating the value
		// would shrink the reorg protection — the exact attack the guard exists
		// to stop. Refusing to size skips the order, consistent with pricing.
		if (!this.checkPriceGuard(undefined, leg.token1Chain, venueRate)) return null
		return venueRate
	}

# Venue pricing (Uniswap V4 funded pairs)

Verified 2026-08-19.

```
resolveLegRates(...)
  curveless pair && token0 is a USD stable
    -> venuePriceMemo() -> getVenueUsdPrice(chain, token1)
         -> UniswapV4FundingPlanner.getExoticTokenPrice
              picks the position with the largest pool liquidity
              -> computeDirectPoolPriceUsd -> sdkPool.token0Price / token1Price
    -> checkPriceGuard(...)   reject if outside maxDeviationBps of the static reference
    -> rate = 1 / venueUsd
  otherwise -> the pair's ask/bid curve at the leg's notional
```

`computeDirectPoolPriceUsd` returns the **raw pool mid** derived from `sqrtPriceX96`. The pool's
fee tier is read and stored on the hydrated position (`pos.fee`) but never applied to the price,
and there is no size or impact term — `computeLegPolicyOutput` extends the mid linearly across the
whole priced quantity. `checkPriceGuard` is the only defense on this path, and it checks deviation
from a static reference, not execution cost. A venue-priced pair that has to swap through its own
pool to source inventory pays a fee tier it never quoted against.
