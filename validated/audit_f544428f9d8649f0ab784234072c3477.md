Confirmed: `HttpClient#initialize` builds `@base_uri = "https://#{api_host || session.shop}"` directly from `session.shop`, with no domain validation at this layer. [1](#0-0) 

### Title
Token Exchange sends `client_secret` to an unsanitized shop host derived from the JWT `dest` claim - (File: lib/shopify_api/auth/token_exchange.rb)

### Summary
`ShopifyAPI::Auth::TokenExchange.exchange_token` takes the `shop` value directly from the session token's `dest` claim (`jwt_payload.shop`) and uses it, unsanitized, as the destination host for a request that carries the app's `client_id`/`client_secret` in the POST body. Every sibling credential-issuing method in the same module and adjacent modules (`migrate_to_expiring_token`, `ClientCredentials.client_credentials`) passes the caller-supplied `shop` through `Utils::ShopValidator.sanitize!` before using it to build the outbound request; `exchange_token` alone skips this step.

### Finding Description
`JwtPayload#shop` simply strips `"https://"` from the JWT's `dest` claim with no format check: `@dest.gsub("https://", "")`. [2](#0-1) 

In `exchange_token`, this raw value is used directly as the session's `shop`:
```ruby
jwt_payload = ShopifyAPI::Auth::JwtPayload.new(session_token)
dest_shop = jwt_payload.shop
...
shop_session = ShopifyAPI::Auth::Session.new(shop: dest_shop)
body = { client_id: ..., client_secret: ShopifyAPI::Context.api_secret_key, ... }
client = Clients::HttpClient.new(session: shop_session, base_path: "/admin/oauth")
``` [3](#0-2) 

`HttpClient#initialize` then builds the outbound request host straight from `session.shop`: `@base_uri = "https://#{api_host || session.shop}"`, with no allow-list check on that value. [1](#0-0) 

By contrast, the two other credential-exchange entry points in this same gem explicitly bind `shop` to a trusted-domain equality check before it is allowed to become the request host:
```ruby
validated_shop = Utils::ShopValidator.sanitize!(shop)
shop_session = ShopifyAPI::Auth::Session.new(shop: validated_shop)
```
in `TokenExchange.migrate_to_expiring_token` [4](#0-3)  and in `ClientCredentials.client_credentials` [5](#0-4) . `ShopValidator.sanitize!` enforces that the host equals (or is a proper subdomain match of) one of `TRUSTED_SHOPIFY_DOMAINS`, rejecting arbitrary attacker-controlled hosts. [6](#0-5) 

The binding that should hold is: **host that receives `client_secret` == a Shopify-trusted domain, verified by `ShopValidator`**. In `exchange_token` this equality is never checked — the host is whatever string happens to be in the `dest` claim of the decoded JWT.

### Impact Explanation
This is a credential-leakage / SSRF-with-app-credentials pattern: if `dest_shop` can ever be a non-Shopify host, the app's `client_secret` (and `client_id`) are POSTed to that host. The JWT signature (HMAC-SHA256 with `Context.api_secret_key`, verified in `JwtPayload#initialize`) does guarantee the token was minted using the app's secret, and in the normal Shopify flow the `dest` claim is populated by Shopify's own servers to the real installing shop's domain, not by the merchant/browser. Because of that server-side control over `dest`, I could not construct a concrete request sequence, reachable by an unprivileged internet user without already controlling how Shopify issues tokens, that forces `dest` to an attacker-chosen host through this gem's own code alone. The missing `ShopValidator.sanitize!` call is a genuine inconsistency and defense-in-depth gap relative to the gem's own established pattern (every other place that turns a `shop` string into a credential-carrying request host validates it first), but I cannot prove an exploitable end-to-end path confined to unprivileged-attacker-controlled inputs and this gem's code, as required by the validation rules (no forged/crafted `dest` value was demonstrable without an already-compromised or non-standard token-issuance path).

### Likelihood Explanation
Low/unproven under the stated constraints — exploitability depends on a code path, outside this gem, that lets an attacker influence the `dest` claim of a token that still passes this gem's own HMAC/`aud` checks, which was not established.

### Recommendation
For defense-in-depth and consistency with `migrate_to_expiring_token` and `client_credentials`, `exchange_token` should validate `dest_shop` with `Utils::ShopValidator.sanitize!` before using it to build `shop_session`, so the outbound host that receives `client_id`/`client_secret` is always provably bound to a trusted Shopify domain rather than trusting the JWT `dest` claim verbatim.

### Proof of Concept
Not demonstrable as a concrete exploit within scope: no attacker-controlled path was found, purely within this gem's code, that lets an unprivileged user set the JWT `dest` claim to an arbitrary non-Shopify host while still passing `JwtPayload`'s HMAC/`aud` verification. This finding is reported as a code-consistency/defense-in-depth gap rather than a proven vulnerability, per the required standard of concrete proof.

      TRUSTED_SHOPIFY_DOMAINS = T.let(
        [
          "shopify.com",
          "myshopify.io",
          "myshopify.com",
          "spin.dev",
          "shop.dev",
        ].freeze,
        T::Array[String],
      )

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
