## Title
Stale non-membership proof allows double-refund of GET-request relayer fees after response delivery — ([File: evm/src/core/EvmHost.sol])

### Summary
`EvmHost.dispatchIncoming(GetResponse, relayer)` pays out the relayer fee stored in `_requestCommitments[commitment]` when a `GetResponse` is successfully delivered, but never deletes that commitment entry. `HandlerV2.handleGetRequestTimeouts` / `EvmHost.dispatchTimeOut(GetRequestTimeout, ...)` treat the request as still "unknown/pending" purely from the continued presence of `_requestCommitments[commitment]`, and rely solely on a *non-membership proof taken at an attacker-chosen historical height* to prove no response was recorded on the destination. Because the commitment record is never invalidated once "consumed" by a successful response delivery, a relayer can replay a proof generated at an earlier height (before the response existed) to trigger a second fee payout for the same request — a stale-reference-reuse bug analogous to a use-after-free: a resource logically freed (finalized by delivery) is reachable and reusable through a second code path.

### Finding Description
The GET-request lifecycle on `EvmHost` is:

1. `dispatch(DispatchGet)` stores `_requestCommitments[commitment] = FeeMetadata({sender, fee})` [1](#0-0) .
2. When the response arrives, `HandlerV2.handleGetResponses` verifies an MMR proof and calls `host.dispatchIncoming(response, relayer)` [2](#0-1) .
3. `EvmHost.dispatchIncoming(GetResponse, ...)` calls the module and, on success, pays the relayer `_requestCommitments[commitment].fee` — but **never deletes `_requestCommitments[commitment]`**: [3](#0-2) 

Compare this to the two timeout paths, which both explicitly `delete _requestCommitments[commitment]` before invoking the app callback: [4](#0-3) 

Because the commitment is never cleared on the response path, `meta.sender` stays non-zero forever after a successful response delivery, so `handleGetRequestTimeouts` still classifies the request as "known"/pending: [5](#0-4) 

The only defense against re-claiming a request whose response already arrived is the non-membership proof of `RESPONSE_RECEIPTS_STORAGE_PREFIX ++ commitment` against `host.stateMachineCommitment(message.height).stateRoot`. This proof is checked at a **caller-supplied historical height**, not necessarily the latest known height. A relayer can:
- capture (or itself request) a valid non-membership proof at a height `H` taken *after* the GET request's timeout but *before* Hyperbridge processed/receipted the response, and
- submit that proof to `handleGetRequestTimeouts` *after* the legitimate `GetResponse` has already been delivered through `handleGetResponses` and the fee already paid.

Nothing in `handleGetRequestTimeouts` / `dispatchTimeOut(GetRequestTimeout,...)` checks `_responseReceipts[commitment]` (the local record proving the response was in fact already delivered on this very host) before paying out a second time. This directly mirrors an invariant the Rust core explicitly enforces for the analogous local case — "Reject the timeout if a response has already been received for this request" — which is present in `modules/ismp/core/src/handlers/timeout.rs` but has no counterpart on the `EvmHost`/`HandlerV2` code path: [6](#0-5) 

Historical state-machine commitments are retained for a large, configurable cap (seen at 192,000 in tests) before eviction [7](#0-6) , giving an attacker a wide window in which such a stale, pre-response-height non-membership proof remains submittable.

### Impact Explanation
Any permissionless relayer who calls `handlePostRequestTimeouts`... err `handleGetRequestTimeouts` [5](#0-4)  with a stale, pre-delivery non-membership proof can force `EvmHost.dispatchTimeOut(GetRequestTimeout,...)` to execute a second `onGetTimeout` callback and a second `safeTransfer` of `meta.fee` out of the host's fee-token reserve for a request whose fee was already paid out once via `dispatchIncoming(GetResponse,...)`. This is a direct double-payment / theft-of-funds vector against the protocol's fee-token balance, reachable from a single relayed message with no privileged role required.

### Likelihood Explanation
High: the attacker only needs to be a relayer capable of submitting `handleGetRequestTimeouts` (a permissionless call) with a proof taken at any retained historical height before the response was processed on the destination — no admin, governance, or consensus-forging capability is required, and generous commitment retention caps make such stale proofs available for a long window.

### Recommendation
- In `EvmHost.dispatchIncoming(GetResponse,...)`, delete `_requestCommitments[commitment]` once the response has been successfully processed (mirroring the deletion performed on both timeout paths), so a request can never be both "responded" and "known/pending" simultaneously.
- Additionally/alternatively, in `EvmHost.dispatchTimeOut(GetRequestTimeout,...)` or `HandlerV2.handleGetRequestTimeouts`, explicitly check `_responseReceipts[commitment]` is empty before honoring a timeout, exactly as `modules/ismp/core/src/handlers/timeout.rs` does for the local case.
- Consider requiring `message.height` used for the non-membership proof to be at or above the latest known commitment height (or otherwise bind the proof height to a point in time no earlier than the current stored fee-metadata state) to close the stale-proof replay window generally.

### Proof of Concept
1. Dispatch a `DispatchGet` from `EvmHost`; `_requestCommitments[commitment]` is set with `fee = F`.
2. Let the request time out relative to some Hyperbridge height `H0` at which Hyperbridge has *not yet* processed/receipted the response (`ResponseReceipts` absent at `H0`). Obtain (or have any relayer generate) a valid non-membership proof for `commitment` at height `H0`.
3. Independently, the response is legitimately produced and relayed: a relayer calls `HandlerV2.handleGetResponses`, which calls `EvmHost.dispatchIncoming(GetResponse,...)`, paying fee `F` to that relayer. `_requestCommitments[commitment]` remains populated (not deleted).
4. Any relayer now calls `HandlerV2.handleGetRequestTimeouts` with `message.height = H0` and the proof from step 2. `host.requestCommitments(commitment)` still returns non-zero `sender`, the non-membership proof at `H0` still verifies (it predates the response), so `dispatchTimeOut(GetRequestTimeout,...)` executes, deletes the (still-present) commitment, invokes `onGetTimeout`, and — if the app's `onGetTimeout` does not itself independently track fulfillment — pays `meta.fee = F` a second time out of the host's reserve.

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)

            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        uint256 timestamp = block.timestamp;
        uint256 delay = timestamp - host.stateMachineCommitmentUpdateTime(message.proof.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        uint256 responsesLength = message.responses.length;
        MerkleMountainRange.Leaf[] memory leaves = new MerkleMountainRange.Leaf[](responsesLength);

        for (uint256 i = 0; i < responsesLength; ++i) {
            GetResponseLeaf memory leaf = message.responses[i];
            // don't check for timeouts because it's checked on Hyperbridge

            // known request? also serves as source check
            FeeMetadata memory meta = host.requestCommitments(leaf.response.request.hash());
            if (meta.sender == address(0)) revert UnknownMessage();
            leaves[i] = MerkleMountainRange.Leaf(leaf.index, leaf.response.hash());
        }

        bytes32 root = host.stateMachineCommitment(message.proof.height).overlayRoot;
        if (root == bytes32(0)) revert StateCommitmentNotFound();
        bool valid = MerkleMountainRange.VerifyProof(root, message.proof.multiproof, leaves, message.proof.leafCount);
        if (!valid) revert InvalidProof();

        for (uint256 i = 0; i < responsesLength; ++i) {
            GetResponseLeaf memory leaf = message.responses[i];
            // duplicate response?
            if (host.responseReceipts(leaf.response.request.hash()).relayer != address(0)) revert DuplicateMessage();
            host.dispatchIncoming(leaf.response, _msgSender());

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
