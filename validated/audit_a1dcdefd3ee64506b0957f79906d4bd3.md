### Title
Reserve-donation inflates Aquarius LP collateral price within the sanity band, enabling under-collateralized borrows and bad debt - (File: contracts/price-aggregator/src/providers/aquarius.rs)

### Summary
The Inverse Finance analog maps onto XOXNO Lending's Aquarius LP collateral pricing. `providers::aquarius::read` values an LP share as `2 * sqrt(value_a * value_b) / total_shares` using the pool's live `get_reserves` (`common/src/oracle/lp.rs:57`, `aquarius.rs:90-114`). A swap cannot move this fair price (the reserve product is invariant), but a permissionless token transfer directly into the pool raises one reserve without minting shares, inflating the LP fair value by `sqrt(1 + donation/reserve)`. Markets such as `XLMAQUA_LP` list Aquarius LP tokens as collateral (`configs/mainnet/markets.json:1575-1590`) with sanity bands as wide as ~5.5x (e.g. `min 0.45` / `max 2.5` WAD in ops config `907bacd1...`). An attacker holding a large fraction of the pool's LP supply can flash-fund a donation, deposit the LP token via `controller.supply`, over-borrow at the inflated price, then withdraw liquidity to recover most of the donation — leaving bad debt.

### Finding Description
`read` calls `aquarius_pool_reserves_call` which reads `pool.get_reserves` — the pool's live token balances (`common/src/oracle/providers/aquarius.rs:45-57`). Nothing in the read path distinguishes swap-earned reserves from unaccounted donations, and there is no balance-vs-booked-reserve consistency check or TWAP. The leg prices come from independent feeds (`engine::resolve_nested`, `aquarius.rs:88-89`), so only the reserve ratio is attacker-controlled. Since `fair_lp_price_wad` scales with `sqrt(reserve_a * reserve_b)` (`lp.rs:72-84`), multiplying one reserve by `k` multiplies the LP price by `sqrt(k)` up to the oracle's `max_sanity_price_wad`, which is the only cap (`aquarius.rs:120-122` only enforces a minimum pool value; the band is enforced downstream in the engine).

Unlike Inverse's TWAP manipulation, this is a same-transaction spot manipulation: Soroban executes atomically, so the attacker can (1) take a flash loan of token A via `controller.flash_loan` or an external source, (2) transfer A directly to the Aquarius pool (donation inflates `get_reserves`), (3) `supply` pre-held LP shares as collateral and `borrow` the maximum, (4) repay the flash loan. The donation is recoverable in proportion to the attacker's LP share fraction by removing liquidity afterward, capping the true cost at `(1 - f) * donation`.

### Impact Explanation
Collateral valued above its true worth lets `borrow` pass `require_post_pool_risk_gates` (`ltv_collateral >= total_debt`, `health_factor >= 1 WAD`) on inflated numbers. When the donation is absent the price reverts inside the same sanity band, the position is instantly underwater, and liquidation cannot restore solvency because the collateral's real value is below the debt. Result: protocol insolvency / bad debt socialized through the supply-index write-down path — theft of supplier funds, the same loss shape as the Inverse exploit. Magnitude per attack is bounded by `min(sqrt(donation_ratio), max_sanity/true_price)` and the pool's deposited liquidity, but is repeatable across listed LP markets.

### Likelihood Explanation
Requires an unprivileged address only: direct token transfer to the pool, `controller.supply`, `controller.borrow`. Cost is dominated by the donation, which requires roughly `(band_ratio^2 - 1) * reserve` of one leg — cheapened arbitrarily by flash liquidity and partially recovered via the attacker's own LP share fraction `f`. It is most practical where the attacker can cheaply accumulate a large share of a thin Aquarius pool (matching the "thinly traded pair" precondition of the Inverse hack) and where the configured sanity band is wide relative to LTV. Not exploitable on pure-Reflector collateral markets since leg prices are exogenous.

### Recommendation
Price LP collateral donation-resistently: snapshot reserves at a prior ledger or use the pool's tracked/booked reserves rather than raw balances; alternatively compute fair value from cumulative balances net of unattributed balance increases, or bound per-read reserve deltas between successive observations. Tighten `min_sanity/max_sanity` bands on LP-share oracles toward the geometric-mean fair value and enforce a maximum implied deviation between the two leg-reserve ratios across reads.

### Proof of Concept
1. Attacker acquires fraction `f` of Aquarius pool P's LP shares (pool: tokens A/B, listed as collateral market `XLMAQUA_LP`).
2. In one transaction: flash-borrow token A; `token.transfer(attacker -> P, D)` with `D` chosen so `(r_a + D)/r_a >= (max_sanity/true_price)^2`; `P.get_reserves()` now returns the inflated `r_a + D`.
3. `controller.supply(LP_amount)` then `controller.borrow(debt_asset, amount)` — `aquarius::read` returns the inflated `price_wad` within the sanity band, so `calculate_account_risk_totals` overvalues collateral and the post-borrow gate passes.
4. Remove liquidity to recover `f` of the donation; repay flash loan. The borrowed funds exceed the collateral's true value; the position is abandoned, leaving bad debt that is socialized via the supply-index write-down in `clean_bad_debt`.
