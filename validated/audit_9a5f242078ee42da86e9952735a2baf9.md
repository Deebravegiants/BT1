### Title
Stale `_requestCommitments` entry after GET response delivery enables double-payment of relayer/refund fees via a later GET-timeout replay - ([File: evm/src/core/EvmHost.sol])

### Summary
`EvmHost.dispatchIncoming(GetResponse, address)` pays the relayer fee for a GET request out of `_requestCommitments[commitment]` but never deletes that entry, unlike every other fee-consuming path (`dispatchTimeOut` for both GET and POST timeouts, which explicitly `delete _requestCommitments[commitment]` before use). This is the state-management analog of a use-after-free: a resource ("request commitment" + its fee metadata) is consumed once (response delivery pays the relayer) but is never invalidated, so it can be "reused" a second time through the sibling GET-timeout code path, which pays it out again to the original sender.

### Finding Description
`EvmHost.dispatchIncoming(GetResponse memory response, address relayer)` (evm/src/core/EvmHost.sol:824-847) computes `commitment = response.request.hash()`, records a response receipt, invokes the destination app's `onGetResponse`, and on success reads `_requestCommitments[commitment].fee` and pays it to the relayer — but never clears `_requestCommitments[commitment]`: [1](#0-0) 

By contrast, `dispatchTimeOut(GetRequestTimeout, ...)` (evm/src/core/EvmHost.sol:849-877) treats clearing `_requestCommitments[commitment]` as "replay protection" before paying the same fee to `meta.sender`: [2](#0-1) 

`HandlerV2.handleGetResponses` (evm/src/core/HandlerV2.sol:217-247) explicitly documents that GET response delivery does **not** check for timeout: "don't check for timeouts because it's checked on Hyperbridge." Its only anti-replay check is the `responseReceipts` mapping, which is unrelated to `_requestCommitments`: [3](#0-2) 

`HandlerV2.handleGetRequestTimeouts` (evm/src/core/HandlerV2.sol:293-321) independently verifies the request is timed-out relative to `state.timestamp` at an arbitrary previously-stored `message.height`, and verifies a non-membership proof (that no response receipt exists in Hyperbridge's child trie) at that same historical height — it does not check whether the GET response has since been delivered on the destination EVM chain: [4](#0-3) 

Because `EvmHost` retains historical `_stateMachineCommitments` for every previously-verified height (only removed via `deleteStateMachineCommitment` on fisherman veto), an attacker/relayer can hold onto an older, still-valid consensus-verified height whose trie snapshot predates the response's inclusion on Hyperbridge. Combined with the fact that `_requestCommitments[commitment]` is never cleared after a GET response is delivered, this lets the same fee metadata be consumed twice: once by `dispatchIncoming(GetResponse,...)` (paid to the relayer who delivered the response) and again by `dispatchTimeOut(GetRequestTimeout,...)` (refunded to the original sender), using a genuinely valid (but stale) non-membership proof from before the response was posted.

### Impact Explanation
This directly drains `feeToken` from `EvmHost`'s balance — funds collected from all GET-request payers — by double-paying a single request's fee. This is theft of protocol/user funds reachable by any permissionless relayer submitting a legitimate consensus-verified but historically stale proof, matching the "concrete theft ... of funds" and "relayer fee and reward accounting" criteria explicitly in scope.

### Likelihood Explanation
Both proof paths (`handleGetResponses` and `handleGetRequestTimeouts`) are fully permissionless and require only a valid Merkle/consensus proof against *some* stored state commitment height, not necessarily the latest one. Since GET requests routinely carry finite timeouts and Hyperbridge produces many intermediate state commitments over the challenge/finalization window, a window in which the response is not yet in the trie but the request is already timed-out (per an older `state.timestamp`) is a normal and likely occurrence, not a contrived edge case.

### Recommendation
Delete (or otherwise invalidate) `_requestCommitments[commitment]` inside `dispatchIncoming(GetResponse, address)` immediately after successfully paying the relayer fee (mirroring the replay-protection pattern already used in both `dispatchTimeOut` overloads), and/or have `handleGetRequestTimeouts`/`dispatchTimeOut(GetRequestTimeout,...)` check `responseReceipts` for the commitment on the destination chain before paying any refund.

### Proof of Concept
1. User dispatches a `DispatchGet` with a fee; `_requestCommitments[commitment] = {sender, fee}` is stored (evm/src/core/EvmHost.sol dispatch(DispatchGet)).
2. Relayer A delivers the corresponding `GetResponse` via `handlePostRequests`/`handleGetResponses` → `EvmHost.dispatchIncoming(GetResponse,...)` succeeds, pays `fee` to relayer A, but leaves `_requestCommitments[commitment]` populated.
3. Relayer B (can be the same actor) submits `handleGetRequestTimeouts` referencing an earlier, still-stored `stateMachineCommitment` height whose trie snapshot predates the response's inclusion, with a valid non-membership proof for that height, and where the request's `timeout()` is already `<= state.timestamp` at that height.
4. `dispatchTimeOut(GetRequestTimeout,...)` finds `meta.sender != address(0)` (never cleared), deletes the entry, calls `onGetTimeout` on the app, and on success refunds `meta.fee` to `meta.sender` — a second payout of the same fee from the host's balance.

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
