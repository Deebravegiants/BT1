Confirmed: `evm/tron/contracts/apps/IntentGatewayV2.sol` has **no relayer-gate mechanism at all** — no `_relayer` storage variable, no `_checkRelayer` function, no `setRelayer`, and no `UnauthorizedRelayer` error — while its EVM counterpart `evm/src/apps/intentsv2/ExtrinsicIntents.sol` calls `_checkRelayer(incoming.relayer)` as the very first line of `onAccept` and `onGetResponse`.

### Title
Tron IntentGatewayV2.onAccept lacks relayer authorization gate present in EVM sibling, allowing any relayer to deliver privileged withdrawal/governance actions - (File: evm/tron/contracts/apps/IntentGatewayV2.sol)

### Summary
The Tron deployment of the intents escrow gateway (`evm/tron/contracts/apps/IntentGatewayV2.sol`) omits the `_checkRelayer` authorization step that the canonical EVM implementation (`evm/src/apps/intentsv2/ExtrinsicIntents.sol`) enforces on every `onAccept`/`onGetResponse` delivery. This is the same class of bug as the external report: a privileged callback interface is reachable by an unvalidated/untrusted caller because an origin/authorization check that should gate the bridge callback is missing.

### Finding Description
`ExtrinsicIntents.onAccept` (EVM) begins with `_checkRelayer(incoming.relayer)` [1](#0-0) , which reverts unless the message was submitted by the one authorized relayer once that relayer has been set [2](#0-1) . The project's own documentation describes this as a critical defense-in-depth control: "Once a relayer is set, rejects deliveries from anyone else before the body is read... so a forged consensus proof alone cannot reach this contract" [3](#0-2) .

The Tron variant's `onAccept` performs `onlyHost`, then branches on `RequestKind`, calling `authenticate(incoming.request)` for `RedeemEscrow`/`RefundEscrow` and a Hyperbridge-source check for governance actions (`NewDeployment`, `UpdateParams`, `SweepDust`) — but never calls anything resembling `_checkRelayer` [4](#0-3) . A full grep of the file confirms there is no `_relayer` state variable, no `setRelayer`, and no `UnauthorizedRelayer` error anywhere in this contract [5](#0-4) .

`EvmHost.dispatchIncoming` (and its Tron equivalent) forwards the handler's raw `_msgSender()` as `relayer` to `onAccept` without any restriction on who that submitter may be [6](#0-5) ; the relayer gate is the application-level control meant to restrict this open surface. Its absence in the Tron gateway means **any address that can produce a state/consensus proof accepted by the local `HandlerV2`** — not just the operator's designated relayer — can be the one to deliver `RedeemEscrow`, `RefundEscrow`, `NewDeployment`, `UpdateParams`, `SweepDust`, and `Execute` (in the EVM version) requests. This mirrors the OpenClaw bug class exactly: a privileged bridge/callback interface trusts any caller that reaches it instead of validating that the caller is the specific trusted relayer, relying only on weaker checks (module/source authentication) that do not substitute for caller authorization.

### Impact Explanation
On the EVM side, the relayer gate exists specifically to add a second, independent barrier against a compromised or malicious consensus/proof path (e.g., a forged or marginally-valid BEEFY proof) reaching escrow withdrawal or governance logic. Without it on Tron, if the underlying consensus/proof verification is ever bypassed, delayed, or targeted (e.g., a malicious/compromised relayer racing a legitimate delivery, or an attacker exploiting any weakness in proof verification), the attacker's own delivery — rather than the operator-designated relayer's — becomes the one that executes escrow redemption/refund, dust sweeps, parameter updates, and deployment registration on the Tron IntentGateway. This directly threatens theft or misdirection of escrowed intent funds and unauthorized governance changes to the gateway.

### Likelihood Explanation
Reachability is direct and unprivileged: any account capable of submitting a delivery to the local ISMP handler (a permissionless action any relayer can perform once proofs are available) can be the one whose address is forwarded as `relayer` into `onAccept`. Because the code path is otherwise identical to the audited-and-fixed EVM version, and the divergence appears to be an omission specific to the Tron port rather than an intentional design choice, this is a straightforward regression rather than a theoretical edge case.

### Recommendation
Add the same `_relayer` state, `setRelayer`/`_checkRelayer` machinery, and `_checkRelayer(incoming.relayer)` call at the top of `onAccept` (and any `onGetResponse`) in `evm/tron/contracts/apps/IntentGatewayV2.sol`, mirroring `evm/src/apps/intentsv2/ExtrinsicIntents.sol`, so that Tron deliveries are restricted to the single authorized relayer exactly as on EVM.

### Proof of Concept
1. Deploy/observe the Tron `IntentGatewayV2` with escrowed funds pending redemption on a source chain.
2. An attacker who is not the operator's intended relayer submits the delivery transaction to the local ISMP handler with a valid state/consensus proof (any relayer can do this — it is a permissionless dispatch step).
3. `dispatchIncoming` forwards `_msgSender()` (the attacker) as `incoming.relayer` to `onAccept` [6](#0-5) .
4. `onAccept` proceeds directly to `authenticate`/source checks and executes `withdraw`/governance logic with no relayer authorization check [4](#0-3) , whereas the EVM sibling would have reverted with `Unauthorized` at `_checkRelayer` first [1](#0-0) .

    function onAccept(IncomingPostRequest calldata incoming) external override onlyHost {
        RequestKind kind = RequestKind(uint8(incoming.request.body[0]));
        if (kind == RequestKind.RedeemEscrow || kind == RequestKind.RefundEscrow) {
            authenticate(incoming.request);
            WithdrawalRequest memory body = abi.decode(incoming.request.body[1:], (WithdrawalRequest));
            return withdraw(body, kind == RequestKind.RefundEscrow);
        }

        // only hyperbridge is permitted to perfom these actions
        if (keccak256(incoming.request.source) != keccak256(IDispatcher(host()).hyperbridge())) revert Unauthorized();
        if (kind == RequestKind.NewDeployment) {
            NewDeployment memory body = abi.decode(incoming.request.body[1:], (NewDeployment));
            _instances[keccak256(body.stateMachineId)] = body.gateway;

            emit NewDeploymentAdded({stateMachineId: body.stateMachineId, gateway: body.gateway});
        } else if (kind == RequestKind.UpdateParams) {
            // Decode the body which includes optional destination-specific protocol fee updates
            ParamsUpdate memory update = abi.decode(incoming.request.body[1:], (ParamsUpdate));
            emit ParamsUpdated({previous: _params, current: update.params});
            _params = update.params;

            // Update destination-specific protocol fees if provided
            for (uint256 i; i < update.destinationFees.length;) {
                bytes32 stateMachineId = update.destinationFees[i].stateMachineId;
                uint256 feeBps = update.destinationFees[i].destinationFeeBps;
                _destinationProtocolFees[stateMachineId] = feeBps;

                unchecked {
                    ++i;
                }
                emit DestinationProtocolFeeUpdated(stateMachineId, feeBps);
            }
        } else if (kind == RequestKind.SweepDust) {
            SweepDust memory req = abi.decode(incoming.request.body[1:], (SweepDust));

            uint256 outputsLen = req.outputs.length;
            for (uint256 i; i < outputsLen;) {
                TokenInfo memory info = req.outputs[i];
                address token = address(uint160(uint256(info.token)));
                uint256 amount = info.amount;

                if (token == address(0)) {
                    (bool sent,) = req.beneficiary.call{value: amount}("");
                    if (!sent) revert InsufficientNativeToken();
                } else {
                    (bool success,) = token.call(abi.encodeWithSelector(IERC20.transfer.selector, req.beneficiary, amount));
                    if (!success) revert TransferFailed();
                }
                unchecked {
                    ++i;
                }
                emit DustSwept(token, amount, req.beneficiary);
            }
        }
    }
