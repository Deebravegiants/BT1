### Title
Dogecoin `validateAddress` skips base58Check checksum verification, letting typo'd/invalid-checksum addresses reach the withdrawal memo - ([File: packages/intents-sdk/src/lib/validateAddress.ts])

### Summary
`validateDogeAddress` only checks the address against a regex `/^[DA][1-9A-HJ-NP-Za-km-z]{25,33}$/` and never verifies the base58Check sha256d checksum, unlike the sibling `validateBtcBase58Address`, `validateLitecoinBase58Address`, `validateTronBase58Address`, and `validateDashAddress` functions in the same file, which all decode with `base58.decode` and compare the trailing 4 bytes against `sha256(sha256(payload))`. Because `PoaBridge.validateWithdrawal` gates the withdrawal solely on `validateAddress(...)` [1](#0-0)  and `createWithdrawIntentPrimitive`/`createWithdrawMemo` embed `destinationAddress` verbatim into the `WITHDRAW_TO:<address>` memo without any further check [2](#0-1) , a Dogecoin-format string that satisfies the regex but has a corrupted checksum (e.g. one flipped base58 character) passes validation and gets committed into the withdraw intent.

### Finding Description
The claimed equality is: *"a string accepted by `validateAddress(address, Chains.Dogecoin)` is a real, payable Dogecoin address."* This equality is broken because `validateDogeAddress` performs regex-only structural validation [3](#0-2)  — it never decodes the base58 payload nor recomputes/verifies the trailing 4-byte checksum, in contrast to `validateBtcBase58Address` [4](#0-3)  and `validateDashAddress` [5](#0-4) , both of which are the same base58Check address family (version byte + 20-byte hash160 + 4-byte sha256d checksum) and both do decode + checksum-verify.

Exploit flow:
1. An unprivileged caller (an ordinary SDK user, or an integrator forwarding a counterparty-supplied `destinationAddress`) calls `sdk.validateWithdrawal(...)` or `PoaBridge.validateWithdrawal(...)` with `assetId` pointing to a Dogecoin token and a `destinationAddress` that matches the Doge regex but has an intentionally/accidentally corrupted checksum byte.
2. `validateAddress` returns `true`, so `InvalidDestinationAddressForWithdrawalError` is never thrown [1](#0-0) .
3. `createWithdrawalIntents` → `createWithdrawIntentPrimitive` → `createWithdrawMemo` embeds the same unmodified string into `memo: "WITHDRAW_TO:<address>"` of the `ft_withdraw` intent primitive [6](#0-5) .
4. This intent is signed by the user and submitted to the NEAR intents contract, which debits/burns the user's balance on NEAR independent of whether the destination chain transfer can ever be completed, since the PoA relayer only picks up and attempts the transfer after this debit.

No other guard in the reachable path catches this: `compareAddresses` only checks equality against the token's own origin address, not checksum validity [7](#0-6) ; `assert` sanity checks in `createWithdrawalIntents` only validate the relayer fee sign, not the address [8](#0-7) ; and there is no re-validation of the address at intent-creation time.

### Impact Explanation
The user's NEAR-side balance is debited by an `ft_withdraw` intent whose memo encodes a Dogecoin-format string that will fail base58Check decoding — it has no corresponding on-chain hash160/address, so no wallet can hold or claim it. Whether this results in permanent, no-recovery loss of funds ("Critical") or a withdrawal that gets stuck pending manual bridge-operator intervention ("High") depends on how the off-chain PoA relayer's own address-decoding logic handles the malformed string; that relayer behavior lives outside this repository and per the audit rules trust assumptions about the bridge API/relayer are out of scope. What is squarely in scope and provable from this repo is the concrete SDK-level defect: `validateAddress` fails to enforce the same checksum guarantee for Dogecoin that it enforces for structurally identical Bitcoin/Dash/Litecoin/Tron base58Check addresses, and the unvalidated string is what ends up signed into the on-chain withdrawal memo. This is repeatable on every call with a crafted address and affects any integrator/user relying on `validateAddress`/`validateWithdrawal` as the authoritative destination-address check for Dogecoin withdrawals.

### Likelihood Explanation
Low attacker cost: constructing a Doge-format string that matches the regex but fails the checksum requires only flipping one base58 character of a valid address (or is trivially produced by common user typos, which is the realistic, unprivileged trigger — no adversarial crafting needed). No special account state, route configuration, or token state is required beyond a Dogecoin-mapped `assetId`. It is fully repeatable per call.

### Recommendation
Make `validateDogeAddress` decode the base58 payload and verify the trailing 4-byte checksum against `sha256(sha256(payload.subarray(0,21)))`, mirroring `validateBtcBase58Address`/`validateDashAddress`/`validateLitecoinBase58Address`, and confirm the version byte matches Dogecoin's mainnet P2PKH (`0x1e`) / P2SH (`0x16`) values instead of relying on the `[DA]` prefix regex alone.

### Proof of Concept

```ts
// packages/intents-sdk/src/lib/validateAddress.spec.ts (new case)
import { base58 } from "@scure/base";
import { sha256 } from "@noble/hashes/sha2";
import { validateAddress } from "./validateAddress";
import { Chains } from "./caip2";

test("Doge regex-only validation accepts checksum-invalid address", () => {
  // Build a syntactically valid P2PKH payload with a deliberately WRONG checksum
  const version = new Uint8Array([0x1e]); // Dogecoin mainnet P2PKH
  const hash160 = new Uint8Array(20).fill(1);
  const payload = new Uint8Array([...version, ...hash160]);
  const correctChecksum = sha256(sha256(payload)).subarray(0, 4);
  const badChecksum = new Uint8Array(correctChecksum);
  badChecksum[0] = (badChecksum[0] + 1) % 256; // corrupt checksum

  const badAddress = base58.encode(new Uint8Array([...payload, ...badChecksum]));

  // regex still matches -> validateAddress wrongly returns true
  expect(validateAddress(badAddress, Chains.Dogecoin)).toBe(true);

  // Contrast: same corruption on BTC/Dash IS caught
  // (swap version byte to 0x00 for BTC and reuse test logic) -> expect(false)
});

test("createWithdrawIntentPrimitive embeds unmodified checksum-invalid address in memo", () => {
  const intent = createWithdrawIntentPrimitive({
    assetId: "nep141:doge.omft.near",
    destinationAddress: badAddress,
    destinationMemo: undefined,
    amount: 100n,
  });
  expect(intent.memo).toBe(`WITHDRAW_TO:${badAddress}`);
});
```

```typescript
	assetId: string;
	destinationAddress: string;
	destinationMemo: string | undefined;
	amount: bigint;

	return {

		token: tokenAccountId,
		receiver_id: tokenAccountId,
		amount: params.amount.toString(),
		memo: createWithdrawMemo({
			receiverAddress: params.destinationAddress,
			xrpMemo: params.destinationMemo,
		}),
		min_gas: MIN_GAS_AMOUNT,
	};
}

function createWithdrawMemo({
	receiverAddress,
	xrpMemo,
}: {
	receiverAddress: string;
	xrpMemo: string | undefined;
}) {
	// Strip "bitcoincash:" prefix from BCH CashAddr addresses
	const normalizedAddress = receiverAddress
		.toLowerCase()
		.startsWith("bitcoincash:")
		? receiverAddress.slice("bitcoincash:".length)
		: receiverAddress;

	const memo = ["WITHDRAW_TO", normalizedAddress];

	if (xrpMemo != null && xrpMemo !== "") {
		memo.push(xrpMemo);
	}

	return memo.join(":");
}
```

```typescript
function validateBtcBase58Address(address: string): boolean {
	const decoded: Uint8Array = base58.decode(address);

	// version (1) + hash160 (20) + checksum (4) = 25 bytes
	if (decoded.length !== 25) return false;

	const version = decoded[0];
	// 0x00 = P2PKH mainnet, 0x05 = P2SH mainnet
	if (version !== 0x00 && version !== 0x05) return false;

	const payload = decoded.subarray(0, 21);
	const checksum = decoded.subarray(21, 25);
	const expectedChecksum = sha256(sha256(payload)).subarray(0, 4);

	for (let i = 0; i < 4; i++) {
		if (checksum[i] !== expectedChecksum[i]) return false;
	}
	return true;
}
```

```typescript
export function validateDashAddress(address: string): boolean {
	try {
		const decoded: Uint8Array = base58.decode(address);

		// version (1) + payload (20) + checksum (4)
		if (decoded.length !== 25) return false;

		const version = decoded[0];
		if (
			version !== 0x4c && // P2PKH
			version !== 0x10 // P2SH
		) {
			return false;
		}

		const payload = decoded.subarray(0, 21);
		const checksum = decoded.subarray(21, 25);

		const hash1 = sha256(payload);
		const hash2 = sha256(hash1);
		const expectedChecksum = hash2.subarray(0, 4);

		for (let i = 0; i < 4; i++) {
			if (checksum[i] !== expectedChecksum[i]) return false;
		}

		return true;
	} catch {
		return false;
	}
}
```
