### Title
Unauthenticated TCP connect to port 9201 silently hijacks the active livestream session without emitting `Event::Closed`, redirecting biometric video output to an attacker - ([File: src/agents/livestream/upstream.rs])

### Summary
`Upstream::poll_next` unconditionally calls `self.listener.poll_accept(cx)` even when an existing connection's `EventReader::poll_stream` returns `Poll::Pending` (i.e., the current session is mid-read). Because of this, a second unprivileged TCP client connecting to port 9201 while a first client's read is pending will be accepted and will silently replace `self.stream`, without ever producing `Event::Closed` for the first session.

### Finding Description
`poll_next` first tries to progress the active connection: `event_reader.poll_stream(cx, Pin::new(stream))` [1](#0-0) . When this returns `Poll::Pending` (the normal case while a client is mid-handshake/mid-frame), the match arm is a no-op (`Poll::Pending => {}`) and execution falls through to `self.listener.poll_accept(cx)` [2](#0-1) . There is no guard preventing `poll_accept` from being polled while `self.stream` is still `Some`. If a second TCP client connects to port `9201` (bound on `0.0.0.0`, i.e., reachable on the local network, not just loopback) [3](#0-2)  while the first connection is stalled, `poll_accept` returns `Ready`, and `self.stream = Some((stream, EventReader::default()))` overwrites the previous `(TcpStream, EventReader)` tuple [4](#0-3) . The old `TcpStream` is dropped (silently closing the socket at the OS level) but the consumer (`src/agents/livestream/mod.rs`) never observes `Event::Closed` for session 1 — it only sees a new `Event::Connected(addr)` for session 2 [5](#0-4) . Since `EventReader::default()` is freshly constructed for the new connection, the partial length/buffer state from connection 1 does not leak into connection 2's parsed `UiEvents` — but the missing `Closed` transition and silent session replacement are real.

The consumer treats `Event::Connected(addr)` as authorization to start streaming: it unconditionally creates `downstream = Some(Arc::new(Downstream::new(addr.ip())?))`, which begins pushing rendered biometric camera frames (`IrEyeFrame`, `IrFaceFrame`, `RgbFrame`, `ThermalFrame`, `DepthFrame`) to `addr.ip()` [6](#0-5) . There is no authentication, token, or pairing check on the TCP accept path in `Upstream::new`/`poll_next` [7](#0-6) .

### Impact Explanation
An unprivileged network attacker who can reach the orb's port 9201 (bound to `0.0.0.0`) can hijack an in-progress livestream session from a legitimate operator/debug client. This silently redirects the biometric video feed — eye, face, RGB, thermal, and depth camera frames captured during signup/operation — to the attacker's socket, since `Event::Connected` unconditionally rebinds the `Downstream` push target with no re-authentication or verification that the new peer is authorized. This matches a biometric data disclosure / cross-session state bleed impact: the invariant that "aborting/replacing a session must fully reset state before the next user's events are attributed" is violated because the previous session is torn down and replaced without ever surfacing `Event::Closed`, so the higher-level agent state machine cannot distinguish an intentional disconnect from a hijack.

### Likelihood Explanation
Exploitation requires only: (1) network reachability to port 9201 on the orb (bound on all interfaces, not restricted to loopback), and (2) racing a `connect()` while an existing session's `poll_stream` is pending (e.g., between length-prefix reads, which is a normal, wide window during any live UI-event or handshake exchange). No credentials, keys, or operator access are needed — an attacker merely needs local network access to the orb, satisfying the "unprivileged attacker" constraint. The race window is not a tight one since `poll_stream` is `Pending` most of the time between UI event batches (only sent every `EVENTS_INTERVAL`), making repeated success highly feasible.

### Recommendation
Do not poll `self.listener.poll_accept(cx)` while `self.stream` is `Some`; only accept a new connection after the previous one closes/errors, or explicitly close/replace the old connection and emit `Event::Closed` before accepting a new one, e.g. by tracking pending-accept state separately and moving the accept check inside the `self.stream.is_none()` branch. Additionally, reject/authenticate the new peer before rebinding the `Downstream` target in `src/agents/livestream/mod.rs`.

### Proof of Concept
Unit/integration test plan in `src/agents/livestream/upstream.rs`:
1. Construct `Upstream::new()` bound to an ephemeral port (parameterize `PORT` for testability, or use a helper that binds `TcpListener` directly and constructs `Upstream` manually).
2. Connect `client1: TcpStream` to the listener; poll `Upstream::poll_next` and assert `Event::Connected(addr1)`.
3. From `client1`, write only 2 of the 4 length-prefix bytes, then poll `Upstream::poll_next` and assert `Poll::Pending` (never `Event::Closed`).
4. While still pending, connect `client2: TcpStream`, complete a valid handshake (4-byte length + rkyv-encoded empty `Vec<Event>`), and poll `Upstream::poll_next` again.
5. Assert that the returned event is `Event::Connected(addr2)` — proving session 1 was replaced — and that no `Event::Closed` was ever produced for `addr1` across the whole sequence of polls.
6. Assert `client1` is observably closed (e.g., writing to it after the swap returns a broken-pipe/reset error), confirming the silent teardown without a corresponding `Event::Closed`.

impl Stream for Upstream {
    type Item = Result<Event>;

    fn poll_next(mut self: Pin<&mut Self>, cx: &mut Context<'_>) -> Poll<Option<Self::Item>> {
        if let Some((stream, event_reader)) = &mut self.stream {
            match event_reader.poll_stream(cx, Pin::new(stream)) {
                Poll::Ready(events) => {
                    *event_reader = EventReader::default();
                    match events {
                        Ok(Some(events)) => {
                            return Poll::Ready(Some(Ok(Event::UiEvents(events))));
                        }
                        Ok(None) => {
                            self.stream = None;
                            return Poll::Ready(Some(Ok(Event::Closed)));
                        }
                        Err(err) => return Poll::Ready(Some(Err(err))),
                    }
                }
                Poll::Pending => {}
            }
        }
        match self.listener.poll_accept(cx) {
            Poll::Ready(Ok((stream, addr))) => {
                self.stream = Some((stream, EventReader::default()));
                Poll::Ready(Some(Ok(Event::Connected(addr))))
            }
            Poll::Ready(Err(err)) => {
                Poll::Ready(Some(Err(eyre!("Error accepting connection: {err}"))))
            }
            Poll::Pending => Poll::Pending,
        }
    }
