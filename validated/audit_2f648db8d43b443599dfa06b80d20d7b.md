### Title
Bad-debt wipeout clamps supply index at floor, leaving stranded shares that drain fresh deposits - (File: contracts/pool/src/interest.rs)

### Summary
`apply_bad_debt_to_supply_index` socializes bad debt by scaling down the supply index, but clamps the result at `SUPPLY_INDEX_FLOOR_RAW` (`RAY/1000`) instead of letting it reach zero. When bad debt meets or exceeds total supplied value, every scaled supply share retains a "phantom" claim of `scaled * floor` that has no real backing — the shares were written down, but the corresponding claim was never zeroed. This is the same class as CVE-2021-47635: an object is marked as owned/private without the matching reference/backing, so a later consumer treats a dead claim as live and pays out against resources it does not own.

### Finding Description
In `contracts/pool/src/interest.rs:73-89`, `apply_bad_debt_to_supply_index` computes `remaining = total_supplied_value - capped_bad_debt` and a `reduction_factor = remaining / total_supplied_value`. On full wipeout `reduction_factor` is zero, but `cache.set_supply_index(new_supply_index.max(SUPPLY_INDEX_FLOOR_RAW))` resurrects the index to `RAY/1000`. Because positions store only `scaled_amount` shares, every pre-existing supplier position still unscales to `scaled * RAY/1000 / RAY` of asset value — a claim backed by nothing.

The in-repo unit test `contracts/pool/tests/interest.rs:316-369` (`test_raw_cache_floor_residual_can_consume_fresh_cash_without_supply_guard`) demonstrates the exploit end-to-end at cache level: after a wipeout clamp, a stranded holder's `resolve_withdrawal(i128::MAX, scaled_a)` returns `gross > 0`, `require_reserves` passes once any new cash is credited, and `burn_supply`/`debit_cash` drain exactly a fresh depositor's `c` tokens, leaving `cash() == 0 < b_claim` — the honest supplier's claim is unpayable.

The unprivileged path is:
1. Market accumulates bad debt (unrepayable underwater positions); an unprivileged caller triggers `liquidate`/`clean_bad_debt`, which reaches `ops/seize.rs` → `apply_bad_debt_to_supply_index` with `bad_debt >= total_supplied_value`, clamping the index to the floor.
2. Any unprivileged address deposits fresh tokens via `supply`, or cash enters via `repay`/`claim` flows, crediting tracked `cash`.
3. The stranded-share holder calls `withdraw` (sentinel `0` → full position); `resolve_withdrawal` pays out `unscale_supply_floor(scaled, floor_index)` against the new cash.
4. The fresh supplier's claim is now undercollateralized — direct theft of user funds.

### Impact Explanation
Critical/High: permanent theft of user funds. Tokens deposited into the market after a wipeout are paid out to holders of phantom claims whose value was fully written off. The pool's tracked cash falls below the sum of honest supply claims, so some supplier cannot withdraw — textbook insolvency transfer.

### Likelihood Explanation
Requires a full-wipeout bad-debt event on a market, which is rare but reachable by design (seize path explicitly caps `bad_debt` at `total_supplied_value` and the floor branch is exercised in tests). Once clamped, any subsequent inflow — supply, repayment, liquidation proceeds — is drainable by the first stranded claimant to withdraw; withdrawal needs no privilege and `require_reserves` only checks that tracked cash covers the payout, which the fresh deposit provides. Uncertainty: whether the ops-level `require_backed_market` guard on `supply` blocks new deposits into a floored market (the test name suggests it does not fully cover this), and whether alternative cash-crediting flows (repay, liquidate) can seed the drain regardless.

### Recommendation
On wipeout, zero out supply claims rather than clamping the index: e.g., track a per-market "supply written off" flag or burn/adjust `supplied` and positions so that `scaled` shares no longer resolve to value. Alternatively, when `capped == total_supplied_value`, set the index to an effectively-zero value and explicitly gate `supply`/`withdraw` in floored markets until the market is re-initialized or recapitalized via `recapitalize`.

### Proof of Concept
See `contracts/pool/tests/interest.rs:316-369`. The test seeds `supplied = 1_000_000 RAY`, applies `apply_bad_debt_to_supply_index(2_000_000 RAY)` (wipeout), observes `supply_index == SUPPLY_INDEX_FLOOR_RAW` with `stranded = unscale_supply_floor(scaled_a) > 0`, then credits a fresh deposit `c` and shows the stranded holder's full withdrawal pays `gross == c`, draining the pool to `cash() == 0` while the fresh depositor's claim `b_claim == c` remains unpaid.
