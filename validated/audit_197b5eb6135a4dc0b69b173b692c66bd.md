### Title
Unconditional deletion of local biometric image directories after unconfirmed/failed uploads permanently destroys unrecovered signup data - ([File: src/agents/image_uploader.rs])

### Summary
In `upload_saved_images`, each individual image upload failure is silently absorbed by `upload_image` (which always returns `Ok(())` even when the network request fails), and after the loop completes the function unconditionally deletes the entire on-disk directory holding the images with `fs::remove_dir_all(image_dir)`. The same unconditional deletion pattern repeats one level up in `upload_signup_images`, which removes the whole per-signup directory after calling the sub-uploaders. This mirrors the reported Solidity bug class: state that should persist until a transfer (upload) is confirmed successful is wiped out regardless of whether the transfer actually completed, permanently erasing the "unpaid"/unsent data with no way to recover or retry it.

### Finding Description
`upload_image` in [1](#0-0)  issues the network upload request and, on failure, only logs the error and increments a metric — it never returns an `Err`, so the failure is fully swallowed.

`upload_saved_images` relies on that return value to decide whether to keep the local copy: it iterates all saved PNGs, calls `upload_image(...).await?` for each, and then — unconditionally, regardless of whether any of the uploads actually succeeded on the backend — deletes the whole image directory: [2](#0-1) .

Because `upload_image` never propagates a failure, the `?` at line 141 can never trigger, so the `fs::remove_dir_all(image_dir)` at line 143 always executes even when every single upload_image::request in the batch failed (e.g., due to network loss, presigned-URL request failure at [3](#0-2) , or backend errors).

The same pattern exists one layer up: `upload_signup_images` calls `upload_saved_images` for each image category and `upload_identification_images_impl` for identification images, then unconditionally removes the entire per-signup directory: [4](#0-3) . `upload_all_signup_images` further just logs a top-level error and moves on to the next signup path without retry bookkeeping: [5](#0-4) .

There is no persistent "unpaid"/"pending" marker analogous to `nft.unpaidRewards` retained anywhere in this flow — once `remove_dir_all` runs, the locally captured IR/RGB/thermal/identification images (feeding fraud review, debugging, and the personal-custody upload pipeline) are gone forever, with the only trace being a log line and a Datadog counter.

### Impact Explanation
This is reachable purely through normal, unprivileged usage of the device: any signup session where connectivity is interrupted while the `image-uploader` agent runs (which per the module docs runs "during idle state" and "during fraud detection", see doc-comment at [6](#0-5) ) will cause locally captured biometric images to be permanently deleted even though they were never successfully delivered to the backend. This is data loss of identification/fraud-relevant biometric captures with no possibility of retry, directly analogous to the original H-04 finding where unpaid user funds were irrecoverably erased by an unconditional `delete`.

### Likelihood Explanation
The `image-uploader` agent is explicitly designed to run in the background on Wi-Fi where connectivity is inherently less reliable ("Orbs in the field will only be in the idle state beyond `image_upload_delay` if they are connected to Wifi to upload overnight", comment at line 244-246), making transient network failures a routine, expected condition rather than an edge case — so the deletion-without-retry path will be hit organically during normal field operation.

### Recommendation
Make `upload_image` propagate upload failures (instead of swallowing them into `Ok(())`), and have `upload_saved_images`/`upload_signup_images` only delete the local directory (or only the successfully uploaded files) after confirming every image in the batch uploaded successfully; on partial or full failure, leave the files in place (or move them to a retry queue) so a subsequent run of `upload_all_signup_images` can retry them instead of unconditionally calling `fs::remove_dir_all`.

### Proof of Concept
1. Trigger a signup so identification/IR/RGB images are saved to `DATA_ACQUISITION_BASE_DIR/<signup_id>/...` by `image_notary` ( [7](#0-6) ).
2. Let the `image-uploader` agent start uploading (`Input::StartUpload`) while network connectivity is interrupted or the backend returns an error for one or more `PUT` requests in `upload_image::request` ( [3](#0-2) ).
3. Observe that `upload_image` in `image_uploader.rs` only logs `"Uploading image {log_image_path} failed"` and still returns `Ok(())` (lines 161-169).
4. Observe that `upload_saved_images` still executes `fs::remove_dir_all(image_dir)` unconditionally at line 143, and `upload_signup_images` removes the whole signup directory at line 190 — permanently deleting the unuploaded biometric images with no retained record that they failed to upload.

async fn upload_image(
    signup_id: &SignupId,
    image_id: &ImageId,
    presigned_url_type: UrlType,
    img_data: Vec<u8>,
    log_image_path: &str,
    dd_image_tag: &str,
) -> Result<()> {
    tracing::info!("Uploading image: {log_image_path}");
    let t = Instant::now();
    let response =
        upload_image::request(signup_id, image_id, presigned_url_type, img_data, dd_image_tag)
            .await;
    dd_timing!("main.time.data_acquisition.upload" + format!("{}.full", dd_image_tag), t);
    match response {
        Ok(()) => {
            dd_incr!("main.count.data_acquisition.upload.success" + format!("{}", dd_image_tag));
        }
        Err(e) => {
            dd_incr!("main.count.data_acquisition.upload.error" + format!("{}", dd_image_tag));
            tracing::error!("Uploading image {log_image_path} failed: {e}");
        }
    }
    Ok(())
}

pub async fn request(
    signup_id: &SignupId,
    image_id: &ImageId,
    presigned_url_type: UrlType,
    img_data: Vec<u8>,
    dd_image_type: &str,
) -> Result<()> {
    let t: Instant = Instant::now();
    let presigned_url::Response { url: presigned_url, .. } =
        presigned_url::request(&DATA_BACKEND_URL, signup_id, Some(image_id), presigned_url_type)
            .await?;
    dd_timing!("main.time.data_acquisition.upload" + format!("{}.presigned", dd_image_type), t);
    tracing::debug!("Image presigned_url: {:?}", presigned_url);
    let request =
        super::client()?.put(presigned_url).header(CONTENT_LENGTH, img_data.len()).body(img_data);
    let t = Instant::now();
    let response = request.send().await?;
    dd_timing!("main.time.data_acquisition.upload" + format!("{}.upload", dd_image_type), t);
    response.error_for_status()?;
    Ok(())
}
