### Title
Chainlink oracle price used without accounting for the feed's deviation threshold lets UserOp senders systematically underpay `SimplexPaymaster`, draining the gas subsidy - ([File: evm/src/utils/SimplexPaymaster.sol])

### Summary
`SimplexPaymaster` prices ERC-20 gas payments for every ERC-4337 UserOp directly from Chainlink `latestRoundData()`, checking only for staleness (`maxOracleAge`) and non-positive answers, but never accounting for the price-feed's onchain deviation/update threshold. Because Chainlink only pushes a new round when the price has moved by more than that threshold (or the heartbeat elapses), the reported on-chain price can lag the real market price by up to the threshold's magnitude at any moment. Any unprivileged account submitting a UserOp through this paymaster can time its fill to a period where the stale-but-"fresh" oracle price undercharges the true gas cost, systematically extracting value from the paymaster's treasury/deposit.

### Finding Description
`_getOraclePrice` only validates that the Chainlink answer is positive and not older than `maxOracleAge`; it applies no correction for the feed's deviation threshold: [1](#0-0) 

This price is then used directly (with only a governance-configured `markupBps` multiplier, which defaults to whatever governance sets and is not tied to any specific feed's deviation threshold) to compute the token price charged for gas: [2](#0-1) 

and to compute the exact token amount deducted from the UserOp sender for a given `gasAmount`/`maxFeePerGas`: [3](#0-2) 

Both `nativeOracle` and each token's `tokenOracle` are standard Chainlink `AggregatorV3Interface` feeds (documented as `BNB/USD`, `ETH/USD`, etc.), which by design only publish a new round when price moves beyond a fixed deviation threshold (commonly 0.5%–1% depending on the feed) or the heartbeat elapses. Between updates, `latestRoundData()` can return a price that differs from the true market price by up to that threshold while still passing the staleness check, exactly the bug class described in the referenced report ("threshold, which is different from the actual price").

Because `SimplexPaymaster` is a permissionless paymaster reachable by any UserOp sender (any account can construct a UserOp that uses this paymaster for gas payment), an attacker can monitor the oracle and the true market price and submit UserOps precisely when the stale on-chain price undercharges the real cost of gas — i.e. when the true native-asset price has risen (or the token price has fallen) since the last on-chain update but has not yet crossed the deviation threshold needed to trigger a new round. Each such UserOp lets the sender pay less ERC-20 token than the gas it actually consumes is worth, with the shortfall paid out of the paymaster's EntryPoint deposit (funded by the treasury). Repeated exploitation drains the paymaster's native deposit relative to the ERC-20 surplus it accumulates, silently running the subsidized-gas paymaster at a loss.

### Impact Explanation
This is a fund-loss issue reachable by any single unprivileged UserOp submission — no admin, governance, or relayer compromise is required. Systematic underpricing directly reduces the paymaster's `EntryPoint` deposit (funded by governance/treasury) relative to what it collects in ERC-20, i.e., real value is extracted from Hyperbridge-controlled funds through the paymaster's gas-sponsorship mechanism. Over time and repeated exploitation this can exhaust the paymaster's deposit, causing it to be unable to sponsor operations (denial of the gas-sponsorship service) in addition to the direct fund loss.

### Likelihood Explanation
Chainlink deviation thresholds are a normal, permanent, and public characteristic of every feed used here — this is not a rare edge case but a structural property of price oracles that exists on every block. An attacker only needs to monitor the configured feeds (native/USD and token/USD) versus the true market price and time UserOp submission accordingly; no special privileges, races against other transactions, or complex preconditions are required, making exploitation straightforward and repeatable.

### Recommendation
Apply a safety buffer to the oracle-derived price used for charging (e.g., bias `_tokenPrice`/`_getOraclePrice` against the payer by the known/expected deviation threshold of the configured feeds, similar to the original recommendation of "add 0.5% more than the value the oracle returned"), or require `markupBps` to be set to at least the sum of both feeds' expected deviation thresholds at registration/update time so normal fee markup structurally covers this gap rather than relying on governance to remember to configure it generously.

### Proof of Concept
1. Governance registers a token in `SimplexPaymaster` with a native/USD and token/USD Chainlink feed with a 0.5% deviation threshold, and sets `markupBps = 0` (or any value below the combined feed thresholds), per `_setParams`/`_registerToken` (`evm/src/utils/SimplexPaymaster.sol` lines 357-404).
2. Off-chain, the true price of the native asset rises by close to (but under) 0.5% relative to the last on-chain round, so the Chainlink aggregator has not yet pushed a new round (still within `maxOracleAge`).
3. An attacker submits a UserOp through this paymaster (mode 0x00/0x01/0x02 permit-funded gas payment) at this moment. `_tokenPrice` (lines 653-658) computes the token cost using the stale `nativeUsd`, undercharging the ERC-20 amount relative to the real cost of the gas consumed.
4. `estimateTokenCost`/the postOp deduction (lines 689-697) charges the attacker the stale-priced (lower) token amount while the EntryPoint deposit is debited the real (higher) native gas cost.
5. Repeating this whenever the price gap opens progressively drains the paymaster's native deposit relative to token inflows, extracting value without any privileged role being compromised.

```text
    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
```

```text
    /// @notice Estimate the token cost for a given gas amount and fee, mirroring
    ///         PaymasterERC20._erc20Cost (including its postOp gas cushion).
    function estimateTokenCost(address token, uint256 gasAmount, uint256 maxFeePerGas) external view returns (uint256) {
        TokenConfig memory cfg = tokenConfigs[token];
        if (address(cfg.tokenOracle) == address(0)) revert TokenNotRegistered(token);

        uint256 weiCost = gasAmount * maxFeePerGas + _postOpCost() * maxFeePerGas;
        return (weiCost * _tokenPrice(cfg)) / _tokenPriceDenominator();
    }
```
