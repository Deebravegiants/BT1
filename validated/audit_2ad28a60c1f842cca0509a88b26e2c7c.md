## Title
Stale non-membership proof at a permanently-cached historical height lets a GET request be timed out on the source chain after its response was already delivered — ([File: evm/src/core/HandlerV2.sol])

### Summary
`EvmHost.dispatchIncoming(GetResponse, ...)` and `EvmHost.dispatchTimeOut(GetRequestTimeout, ...)` never check each other's local completion markers before mutating state and invoking application callbacks. `handleGetRequestTimeouts` in `HandlerV2` accepts a non-membership proof against *any* previously-cached `StateMachineHeight` commitment, and `EvmHost` caches state commitments per-height forever (`_stateCommitments[stateId][height]`), never invalidating older, superseded heights. This is analogous to the MariaDB "use-after-poison" class: state that has already been logically consumed/finalized (the GET response was delivered) is re-actioned via a stale, previously-valid-but-now-superseded snapshot that the code never checks against the current local record.

### Finding Description
`EvmHost.dispatchIncoming(GetResponse memory response, address relayer)` records delivery only in `_responseReceipts[commitment]` and does **not** clear or check `_requestCommitments[commitment]`: [1](#0-0) 

`EvmHost.dispatchTimeOut(GetRequestTimeout, ...)` is the counterpart path invoked from `handleGetRequestTimeouts`. It only checks that `_requestCommitments[commitment]` still exists (`meta.sender != address(0)`) and a non-membership proof at an arbitrary historical `StateMachineHeight` — it never checks `_responseReceipts[commitment]`: [2](#0-1) 

`HandlerV2.handleGetRequestTimeouts` fetches `state = host.stateMachineCommitment(message.height)` for an attacker/relayer-chosen historical `height`, and only verifies non-membership of the `ResponseReceipts` key against **that** height's root — not against the latest height: [3](#0-2) 

Because `EvmHost` stores state commitments permanently, keyed by height (`_stateCommitments[height.stateMachineId][height.height] = commitment;`), and never deletes older entries: [4](#0-3) 

...a relayer can hold a genuinely-valid non-membership proof generated at an *earlier* finalized height `H1` (before the destination chain had recorded a `ResponseReceipts` entry for that GET request) and submit it to `handleGetRequestTimeouts` at any later time — even after the real response has already been delivered via `handleGetResponses`/`dispatchIncoming(GetResponse,...)` at a later height `H2 > H1`. Since neither `handleGetRequestTimeouts` nor `dispatchTimeOut` cross-checks the local `_responseReceipts` mapping or requires proof freshness relative to the current/latest height, the stale proof at `H1` is accepted, deleting `_requestCommitments[commitment]` and invoking `onGetTimeout` on the requesting application — even though that application already received and acted on the real `onGetResponse` callback for the same commitment.

This mirrors the CVE-2022-32081 bug class: a resource ("the GET request") that has already been finalized/consumed (poisoned by the response) is read/acted upon again through a stale but structurally-valid reference (the outdated height's non-membership proof) because the code fails to check the current logical state before acting.

### Impact Explanation
Any application implementing `onGetTimeout` with fund- or state-changing side effects (refunds, unlocking escrow, resetting pending flags, etc., as documented at `docs/content/developers/evm/messaging/get-requests.mdx:574-596`) can be forced into an inconsistent double-action: once via the legitimate `onGetResponse` and again via a stale `onGetTimeout` for the same commitment, since the two entry points are not mutually exclusive at the host level. Depending on the consuming application's assumptions (e.g., unconditional refund/cleanup logic on `onGetTimeout`), this can cause double-refunds, corrupted internal accounting, or forged application-level "timeout" state for a request that was actually fulfilled — a concrete unauthorized app action / potential fund-theft primitive reachable by any relayer submitting an old, otherwise-legitimate proof.

### Likelihood Explanation
Medium-High: no privileged role is required — any relayer or unprivileged actor holding an older finalized-height non-membership proof (which is easy to obtain honestly, since state commitments are permanently retained and consensus updates arrive continuously) can submit it via the permissionless `handleGetRequestTimeouts` entry point at any time after the response has since landed. No consensus forgery or governance/admin compromise is needed — only a naturally-occurring race between response delivery and the availability/use of an older cached height.

### Recommendation
- In `EvmHost.dispatchTimeOut(GetRequestTimeout, ...)`, reject if `_responseReceipts[commitment].relayer != address(0)` before processing the timeout.
- In `HandlerV2.handleGetRequestTimeouts`, require the supplied proof height to be at or after the *latest* known state-machine height for the destination, or otherwise ensure non-membership is proven relative to current-state freshness rather than an arbitrary historical checkpoint.
- Consider expiring/invalidating stale per-height cached commitments so a proof against superseded heights is not indefinitely replayable.

### Proof of Concept
1. App on chain A dispatches `GetRequest` R with key K to destination chain B (relayer fee irrelevant for GET).
2. At height H1 on B, key K's `ResponseReceipts` entry is absent (no response yet) and A's `EvmHost` has already cached `stateMachineCommitment(H1)` via a prior `handleConsensus` call. A relayer/attacker fetches and stores a non-membership proof for K at H1.
3. Subsequently, a legitimate relayer delivers the real `GetResponse` for R via `handleGetResponses` → `dispatchIncoming(GetResponse, relayer)`, which sets `_responseReceipts[commitment]` and calls `onGetResponse` on the app (e.g., unlocking escrow / marking order settled).
4. The attacker/relayer now calls `handleGetRequestTimeouts` on A's `HandlerV2` with `message.height = H1` and the earlier non-membership proof. `stateMachineCommitment(H1)` is still cached and unchanged in `EvmHost`, so the proof verifies.
5. `EvmHost.dispatchTimeOut(GetRequestTimeout, ...)` proceeds (no check of `_responseReceipts`), deletes `_requestCommitments[commitment]`, and invokes `onGetTimeout` on the application — causing it to execute timeout-cleanup/refund logic on a request it already fulfilled via `onGetResponse`.     /**
     * @dev Dispatch an incoming GET response to source module
     * @param response - get response
     */
    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    /**
     * @dev Dispatch an incoming GET timeout to the source module.
     * @notice Does not refund any protocol fees.
     * @param timeout - timed-out get request bundled with the relayer that submitted the timeout proof
     * @param meta - fee metadata for the original request
     * @param commitment - request commitment
     */
    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
