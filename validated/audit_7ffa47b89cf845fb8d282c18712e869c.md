Audit Report

## Title
Legacy Web API trigger handler lets any unauthenticated user hijack another user's pending callback via `MessageID` collision - (File: `core/services/gateway/handlers/capabilities/handler.go`)

## Summary
`HandleLegacyUserMessage` stores a pending callback in the shared `savedCallbacks` map keyed solely by the caller-supplied `msg.Body.MessageID`, with no uniqueness/collision check before insertion. Any caller who can produce a validly-signed (but not otherwise authorized) message — no allowlist check is performed in this handler — can supply a `MessageID` colliding with another in-flight request, silently overwriting the victim's saved callback entry, so that when the DON responds with that `MessageID` the response is delivered to whichever caller currently occupies the map slot.

## Finding Description
`gateway.go`'s `ProcessRequest` accepts a JSON-RPC request over HTTP, decodes it, and for legacy DON-addressed requests calls `msg.Validate()` then `h.HandleLegacyUserMessage(ctx, msg, callback)` [1](#0-0) . `Message.Validate()` only checks field lengths and that the signature cryptographically recovers to *some* signer address — it does not check that the signer is an authorized/allowlisted party for this handler [2](#0-1) . Indeed, the handler itself contains an explicit `// TODO: apply allowlist and rate-limiting here` comment confirming no ownership/authorization gating exists on this path [3](#0-2) . Since any caller can generate their own ECDSA keypair and sign an arbitrary `MessageID` themselves, this path is effectively reachable by an unprivileged/unauthenticated actor.

In `HandleLegacyUserMessage`, after validation, the callback is inserted unconditionally with no existence check:
```go
h.mu.Lock()
h.savedCallbacks[msg.Body.MessageID] = &savedCallback{id: msg.Body.MessageID, createdAt: time.Now(), Callback: callback}
don := h.don
h.mu.Unlock()
``` [4](#0-3) 

On the response side, `handleWebAPITriggerMessage` looks up and deletes the callback purely by `msg.Body.MessageID`, then delivers the response to whatever is found: [5](#0-4) 

This confirms the claim: a second request using the same `MessageID` overwrites the first caller's entry, and the DON's later response for that ID is delivered to the second (attacker's) callback instead of the original caller.

Notably, the codebase demonstrates awareness of this exact bug class elsewhere and fixes it: the newer v2 HTTP trigger handler's `setupCallback` explicitly rejects duplicate in-flight request IDs before registering a callback:
```go
if _, found := h.callbacks[requestID]; found {
    h.handleUserError(ctx, requestID, jsonrpc.ErrConflict, fmt.Sprintf("requestID: %s has already been used. ...", requestID), callback)
    return nil, fmt.Errorf("in-flight request ID: %s", requestID)
}
``` [6](#0-5) 
This confirms the legacy handler (`handler.go`) lacks the equivalent, already-established protection present in the parallel/successor implementation.

## Impact Explanation
An attacker who submits a `web_api_trigger` legacy request with a `MessageID` colliding with a victim's currently in-flight request causes: the victim's original HTTP call to the gateway to hang until `RequestTimeoutError` (denial of correct response delivery), and the response tied to the shared `MessageID` to be delivered to the attacker's callback instead — a form of cross-user response corruption/misdelivery on the gateway's request/response correlation path. This maps to the in-scope "gateway request impersonation / cross-user response corruption" impact category.

## Likelihood Explanation
The attacker needs only the ability to send a normal, validly-signed (by their own arbitrary keypair) `web_api_trigger` request to the gateway — no privileged role, no allowlist membership (none is enforced on this path), and no special access. The only additional requirement is guessing/knowing/racing for a victim's chosen `MessageID` within the ~120s callback lifetime (`defaultCallbackMaxAgeSec`) [7](#0-6) . This is realistic if client-side ID generation is predictable/low-entropy or otherwise observable, though it does require some knowledge of the target ID, moderating but not eliminating likelihood.

## Recommendation
Reject registration in `HandleLegacyUserMessage` if `msg.Body.MessageID` already exists in `savedCallbacks`, mirroring the duplicate-ID rejection already implemented in `httpTriggerHandler.setupCallback` (`core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go`), or bind the callback map key to a non-attacker-controlled per-connection/session identifier so cross-caller collisions are impossible.

## Proof of Concept
1. Using the existing test helper `triggerRequest` in `core/services/gateway/handlers/capabilities/handler_test.go`, construct two `api.Message`s signed by two different keys but with the same `MessageID` (e.g., both `"12345"`).
2. Call `handler.HandleLegacyUserMessage(ctx, msgVictim, cbVictim)` then `handler.HandleLegacyUserMessage(ctx, msgAttacker, cbAttacker)` — observe `h.savedCallbacks["12345"]` now references `cbAttacker`.
3. Simulate a DON node response with `MessageID = "12345"` via `handler.HandleNodeMessage(...)` and assert that `cbAttacker.Wait(ctx)` receives the response while `cbVictim.Wait(ctx)` times out, confirming misdelivery of the victim's response to the attacker.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageID) == 0 || len(m.Body.MessageID) > MessageIDMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageID, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonID) == 0 || len(m.Body.DonID) > MessageDonIDMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonID, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageID]
	delete(h.savedCallbacks, msg.Body.MessageID)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JSONRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
