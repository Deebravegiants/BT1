### Title
`socialize-debt` mutates `lindex`/`principal-scaled`/`total-borrowed` using stale, un-accrued indexes - ([File: mainnet/contracts/vault/v0-vault-usdh.clar])

### Summary
`socialize-debt` (and the identical implementation in `v0-vault-stx.clar`, `v0-vault-sbtc.clar`, `v0-vault-usdc.clar`, `v0-vault-ststx.clar`, `v0-vault-ststxbtc.clar`) reads `index`, `lindex`, `principal-scaled`, `total-borrowed` and `assets` directly with `var-get` and computes `total-assets` from them, without first calling `(try! (accrue))` to roll the borrow/liquidity indexes forward to the current block. [1](#0-0)  This mirrors the Fuji-report bug class: an operation that reads interest-bearing indexes without first refreshing them via the equivalent of `updateF1155Balances`. Every other state-mutating vault entrypoint (`deposit`, `redeem`, `transfer`, `system-borrow`, `system-repay`, `flashloan`) explicitly calls `(try! (accrue))` as the first binding before reading `index`/`lindex` [2](#0-1) [3](#0-2) [4](#0-3)  — `socialize-debt` is the outlier that omits this call.

### Finding Description
`socialize-debt` is invoked by the market contract to write down bad debt (and correspondingly write down the liquidity index, penalizing depositors) when a position defaults with a shortfall.  Its logic:

```
(define-public (socialize-debt (scaled-amount uint))
  (let ((scaled-principal (var-get principal-scaled))
        (borrowed (var-get total-borrowed))
        (idx (var-get index))
        (current-assets (var-get assets))
        (current-lindex (var-get lindex))
        (old-total-assets (total-assets))
        (debt-reduction (mul-div-down scaled-amount idx INDEX-PRECISION))
        ...
        (new-lindex (if (and (> old-total-assets u0) (> old-total-assets debt-reduction))
                       (mul-div-down current-lindex (- old-total-assets debt-reduction) old-total-assets)
                       u0)))
``` [5](#0-4) 

Both `idx` (the borrow index used to convert `scaled-amount` into a real `debt-reduction`) and `current-lindex` (the liquidity index being written down) are taken directly from storage rather than from `next-index` / `next-liquidity-index` (the functions `accrue` uses to compute up-to-date values). `total-assets`/`total-debt` similarly derive from the stale stored `index`, not the value it would have after accrual. [6](#0-5) 

Since indexes are only advanced when `accrue` is explicitly called (deposit/redeem/transfer/borrow/repay/flashloan), if a period elapses with no user activity before a default is socialized, `idx`/`lindex`/`total-debt` used inside `socialize-debt` under-state the true accrued debt and liquidity value. The write-down math (`new-lindex`) is derived from this understated base, permanently baking an inconsistency into `lindex` — the value used by every other function (`convert-to-shares-preview`, `convert-to-assets-preview`, via `total-supply-preview`/`total-assets-preview`) to price shares. This breaks the identity: `debt written off (using accrued reality) == debt written off (using stored index)` should hold, but does not when indexes are stale, permanently skewing the redemption value of shares (`inkind = shares * lindex / …`) away from the true backing.

### Impact Explanation
This causes protocol insolvency / permanent value miscalculation for depositors: the liquidity index (`lindex`), which is the single global scalar every depositor's share value is derived from, is set using a debt figure computed from a stale interest index. Depending on which way indexes drift, this either overcompensates the write-down (freezing/burning more value than the actual bad debt, permanently under-crediting all suppliers) or undercompensates it (leaving supplier shares overvalued relative to real backing, i.e., value effectively minted from nothing for whoever redeems first). Either direction is a protocol-wide, permanent mispricing of `lindex` affecting all vault depositors, not just one user — qualifying as permanent freezing of unclaimed yield / theft of unclaimed yield at minimum, and potentially insolvency for the vault's supply-side accounting.

### Likelihood Explanation
Likelihood is moderate-to-high: `socialize-debt` is a normal, expected operational path (triggered whenever the market registers a bad-debt liquidation shortfall), and there is no dependency on any out-of-scope privileged/DAO misconfiguration — it is simply a missing `(try! (accrue))` call, identical in class to the Fuji `updateF1155Balances` omission cited in the report. Any liquidation resulting in unpaid debt that occurs after even a short elapsed time since the last `accrue`-triggering action (deposit/redeem/borrow/repay/transfer/flashloan) on that vault will use stale indexes.

### Recommendation
Add `(try! (accrue))` as the first step of `socialize-debt`, exactly as is already done in `deposit`, `redeem`, `system-borrow`, `system-repay`, `transfer`, and `flashloan`, so that `index`, `lindex`, and `total-assets`/`total-debt` reflect the current block before the write-down math executes. Apply this fix uniformly across all six vault contracts (`v0-vault-usdh.clar`, `v0-vault-stx.clar`, `v0-vault-sbtc.clar`, `v0-vault-usdc.clar`, `v0-vault-ststx.clar`, `v0-vault-ststxbtc.clar`) since they share the identical `socialize-debt` implementation.

### Proof of Concept
1. Vault has active debt; last `accrue` call was performed at time T0.
2. No deposit/redeem/borrow/repay/transfer/flashloan occurs for a substantial period (indexes remain frozen at T0 values in storage).
3. A borrower's position becomes insolvent and the market calls `socialize-debt(scaled-amount)` at time T1 >> T0.
4. `socialize-debt` reads `idx = index@T0` (not accrued to T1) and `current-lindex = lindex@T0`, and computes `old-total-assets = total-assets()` which itself relies on `total-debt()` using the stale `index@T0` rather than what `next-index()` would compute for T1.
5. The resulting `new-lindex` is calculated from a debt/asset base that omits the real interest accrued between T0 and T1, permanently corrupting `lindex` relative to the true (accrued) backing — the very next `accrue()` call afterward will then apply the T0→T1 interest on top of this already-corrupted base, compounding the discrepancy into all future share-price conversions (`convert-to-shares-preview`/`convert-to-assets-preview`). (define-public (socialize-debt (scaled-amount uint))
  (let ((scaled-principal (var-get principal-scaled))
        (borrowed (var-get total-borrowed))
        (idx (var-get index))
        (current-assets (var-get assets))
        (current-lindex (var-get lindex))
        (old-total-assets (total-assets))
        (debt-reduction (mul-div-down scaled-amount idx INDEX-PRECISION))
        (principal-reduction (if (> scaled-principal u0)
                                (mul-div-down scaled-amount borrowed scaled-principal)
                                u0))
        ;; Write down lindex proportionally to loss in total-assets
        (new-lindex (if (and (> old-total-assets u0) (> old-total-assets debt-reduction))
                       (mul-div-down current-lindex (- old-total-assets debt-reduction) old-total-assets)
                       u0)))

    (try! (check-caller-auth))
    (asserts! (> scaled-amount u0) ERR-AMOUNT-ZERO)

    (var-set lindex new-lindex)
    (var-set principal-scaled (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0))
    (var-set total-borrowed (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0))
    (var-set assets (if (> current-assets principal-reduction) (- current-assets principal-reduction) u0))

    (print {
      action: "socialize-debt",
      caller: contract-caller,
      data: {
        scaled-amount: scaled-amount,
        debt-reduction: debt-reduction,
        principal-reduction: principal-reduction,
        old-lindex: current-lindex,
        new-lindex: new-lindex,
        old-total-assets: old-total-assets,
        principal-scaled: (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0),
        total-borrowed: (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0),
        index: idx
      }
    })

    (ok true)))
