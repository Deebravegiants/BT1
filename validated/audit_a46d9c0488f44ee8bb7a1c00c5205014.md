### Title
Unvalidated route venue contracts can drain the caller's wallet via recorded sub-invocations in the signed auth tree - (File: contracts/swap-aggregator/src/venues/mod.rs)

### Summary
The AutoTrader bug class — a counterparty-chosen contract in a trade path that produces attacker-controlled behavior under the victim's authorization — maps directly onto XOXNO Lending's strategy routes. Controller strategies (`multiply`, `swap_collateral`, `swap_debt`, `repay_debt_with_collateral`) and direct `execute_strategy` calls execute a caller-supplied `swap_xdr` whose `assets` registry names arbitrary pool and token addresses. `dispatch_hop` invokes whatever address the payload names with no allowlist. A malicious "pool" contract executed as a hop runs below the caller's `require_auth` entry and can call `token.transfer(victim, attacker, X)` on any token; Soroban recording-mode simulation attaches that call as a child of the caller's auth entry, so a victim who signs the simulated tree authorizes theft of unrelated wallet funds far exceeding the routed amount.

### Finding Description
`dispatch_hop` in `contracts/swap-aggregator/src/venues/mod.rs:23-40` dispatches each hop to a venue adapter keyed on the payload's opcode and resolves the pool address from the caller-controlled `assets` registry; there is no venue-address allowlist anywhere in the router or controller. The venue call runs while the sender's `require_auth` invocation (from `execute_strategy`, or the controller's strategy call authorized by the user) is on the stack. The threat model itself confirms the exposure: "a route can put third-party code on the call stack below the caller's authorization. A token transfer that such code makes from the caller is recorded by an honest simulation as a child of the caller's authorization entry, and it executes if the caller signs that tree" — `docs/explanation/threat-model.md:154-165`.

The test `tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs` proves end-to-end exploitability through the production-shaped path: `swap_collateral` with a route through `RogueHopPool` records a `wallet_token.transfer(alice → attacker, WALLET_BALANCE)` sub-invocation under Alice's `swap_collateral` auth entry; simulation shows the transfer succeeding and the full balance stolen, and signing the recorded (poisoned) tree executes the theft on the enforcing host.

### Impact Explanation
Theft of user funds. The loss is the victim's entire wallet balance of any token the rogue contract chooses — explicitly "the caller's wallet, not the routed amount" and "neither the payload minimum nor the final risk gate bounds it" (`docs/explanation/threat-model.md:158-161`). The measured-delta and `min_out` protections only bound the routed funds; they do not constrain what code inside a named venue does with the caller's still-open authorization scope.

### Likelihood Explanation
A single unprivileged attacker reaches this by giving the victim a crafted `swap_xdr` (e.g., via a compromised or malicious quote/frontend) that routes a hop through an attacker-deployed contract. The victim's client simulates the transaction; Soroban simulation records the malicious transfer into the auth tree automatically, and the victim signs the simulated envelope. No protocol privilege, no leaked key, and no oracle manipulation is needed — only that the victim signs an auth tree they did not fully decode, which is the common case since wallets do not present nested sub-invocations legibly. The mitigations are purely off-chain (client-side route decoding and auth-tree inspection), identical in spirit to the dYdX "trust the AutoTrader" stance the external report flags as insufficient.

### Recommendation
Add an on-chain allowlist of permitted venue/pool addresses (or venue factories whose pool addresses can be derived and verified) in the swap-aggregator, enforced in `dispatch_hop` before invoking `hop`'s pool — mirroring the report's recommendation of an AutoTrader whitelist. Alternatively, restrict each hop's pool call to addresses resolvable from governance-registered venues, so a payload cannot introduce arbitrary contracts beneath the caller's authorization.

### Proof of Concept
See `tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs:194-269`: `simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry` shows the rogue pool's `transfer(alice → attacker)` recorded inside Alice's signed auth tree with `wallet(alice) == 0` afterward; `enforced_auth_moves_the_wallet_token_only_when_the_signed_tree_lists_the_rogue_transfer` shows the same route executing the theft once the simulation-produced tree is signed. Supporting code: `contracts/swap-aggregator/src/venues/mod.rs:23-40` (unvalidated pool dispatch) and `docs/explanation/threat-model.md:154-165` (acknowledged exposure). pub(crate) fn dispatch_hop(
    env: &Env,
    router: &Address,
    hop: &SwapHop,
    amount_in: i128,
    tokens_cache: &mut Map<Address, Vec<Address>>,
) -> i128 {
    let ctx = HopContext::new(env, router, hop, amount_in);
    let before_in = ctx.input_balance();
    let before_out = ctx.output_balance();

    match hop.venue {
        SwapVenue::Soroswap => soroswap::swap(&ctx),
        SwapVenue::Aquarius => aquarius::swap(&ctx, tokens_cache),
        SwapVenue::Phoenix => phoenix::swap(&ctx),
        SwapVenue::Sushi => sushi::swap(&ctx),
        SwapVenue::CometDex => comet::swap(&ctx),
    };

#[test]
fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
}
