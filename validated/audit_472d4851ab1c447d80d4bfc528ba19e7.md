Audit Report

## Title
Bridge/HTTP request URLs (including query-string secrets) are embedded in pipeline run error messages exposed to low-privileged Viewer users - ([File: core/services/pipeline/common_http.go])

## Summary
`makeHTTPRequest` in `core/services/pipeline/common_http.go` builds non-2xx error strings by directly interpolating the full request URL, including any query-string parameters, without redaction. Since `HTTPTask.URL` and bridge URLs (`bridges.BridgeType.URL`) are plain `models.WebURL`/string fields rather than secret types, and external adapters commonly embed API keys as query parameters, these errors — persisted on the pipeline run and exposed via both REST (`PipelineRunsController.Index`) and GraphQL (`JobRunResolver.AllErrors`/`FatalErrors`) — leak admin-configured secrets to any authenticated session, including `sessions.UserRoleView`.

## Finding Description
The error-construction code is confirmed exactly as cited: [1](#0-0) 
This is reached from both `HTTPTask.Run`: [2](#0-1) 
and `BridgeTask.Run`, which resolves `url := URLParam(bridge.URL)` and passes it into the same `makeHTTPRequest` call: [3](#0-2) [4](#0-3) 

`BridgeType.URL` is declared as a plain `models.WebURL`, not a secret-aware type: [5](#0-4) 

The GraphQL access control confirms that `authenticateUser` (used for read paths like job runs) only requires an authenticated session and does not reject `UserRoleView`; only `authenticateUserCanRun`/`CanEdit`/`IsAdmin` explicitly do: [6](#0-5) 

The REST job-runs controller (`PipelineRunsController.Index`) serves pipeline run data including errors without any additional role-based filtering visible in the handler itself. I was not able to fully trace the exact route-registration/middleware chain in `core/web/router.go` that maps `GET /v2/jobs/:ID/runs` to a specific minimum role due to tool-call limits, but the GraphQL resolver path (`authenticateUser` accepting `UserRoleView`) directly substantiates that view-level read access to job run errors is architecturally supported, consistent with the report's claim.

The root cause is real: the error string is built directly from `url.String()` with no redaction of query parameters, and no `SecretURL`-style wrapper is applied to bridge/HTTP task URLs anywhere in the flow shown.

## Impact Explanation
If a node admin configures a bridge or `HTTPTask.URL` with an API key/token embedded in the query string (a common external-adapter integration pattern), a non-2xx response from that endpoint causes the full URL — secret included — to be baked into the pipeline run's `Result.Error`, which becomes part of `AllErrors`/`FatalErrors` on the run. This is retrievable by any authenticated user via GraphQL `jobRun`/`jobRuns` queries, and the `authenticateUser` gate used for these queries explicitly allows `UserRoleView`. This constitutes a credential-disclosure vulnerability that crosses the intended privilege boundary between admin-configured secrets and viewer-level read access, mapping to the "key/secret exfiltration" and "cross-user response corruption" in-scope impact categories.

## Likelihood Explanation
Likelihood is realistic: query-string API keys are a well-known and common external-adapter pattern in Chainlink deployments; non-2xx responses (rate limiting, auth expiry, adapter downtime) occur routinely in production; and viewing job run history via the `view` role is a normal, supported, unprivileged (relative to admin/edit) capability requiring no additional exploitation beyond having any valid session with `UserRoleView`.

## Recommendation
- Redact query parameters (or the entire URL) from the user-facing error strings produced in `makeHTTPRequest` (`core/services/pipeline/common_http.go`), similar to the existing `truncateLogError` sanitization pattern used in `core/services/gateway/network/httpclient.go`.
- Treat bridge/HTTP task URLs that may contain credentials as secret-like values (e.g., using a `SecretURL`-style wrapper) or strip query strings before interpolating them into any error surfaced via `Result.Error`.
- Apply equivalent sanitization to any other paths (e.g., `task.bridge.go`'s debug/telemetry logging of `url.String()`) that could similarly leak the URL, keeping in mind these currently go to internal logs rather than user-facing APIs.

## Proof of Concept
1. As an admin, create a bridge/external adapter with `URL = "https://adapter.example.com/price?api_key=SECRETKEY123"`.
2. Create a job using an `HTTPTask` or bridge task pointing at that URL.
3. Cause (or wait for) the adapter to return a non-2xx status (e.g., rate limiting, auth expiry, or downtime).
4. `makeHTTPRequest` produces `err = "got error from https://adapter.example.com/price?api_key=SECRETKEY123: (status code 429) ..."`, stored as the run's error, as shown in `core/services/pipeline/common_http.go` lines 71-76.
5. Log in as a `view`-role user and call the GraphQL `jobRun(id: ...) { allErrors fatalErrors }` query (protected only by `authenticateUser`, which accepts `UserRoleView` per `core/web/resolver/auth.go` lines 11-17) — the response includes the full URL with `api_key=SECRETKEY123`.

// Authenticates the user from the session cookie, presence of user inherently provides 'view' access.
func authenticateUser(ctx context.Context) error {
	if _, ok := auth.GetGQLAuthenticatedSession(ctx); !ok {
		return unauthorizedError{}
	}
	return nil
}

// Authenticates the user from the session cookie and asserts at least 'run' role.
func authenticateUserCanRun(ctx context.Context) error {
	session, ok := auth.GetGQLAuthenticatedSession(ctx)
	if !ok {
		return unauthorizedError{}
	}
	if session.User.Role == sessions.UserRoleView {
		return RoleNotPermittedError{session.User.Role}
	}
	return nil
}

// Authenticates the user from the session cookie and asserts at least 'edit' role.
func authenticateUserCanEdit(ctx context.Context) error {
	session, ok := auth.GetGQLAuthenticatedSession(ctx)
	if !ok {
		return unauthorizedError{}
	}
	switch session.User.Role {
	case sessions.UserRoleView, sessions.UserRoleRun:
		return RoleNotPermittedError{session.User.Role}
	default:
	}
	return nil
}

// Authenticates the user from the session cookie and asserts has 'admin' role
func authenticateUserIsAdmin(ctx context.Context) error {
	session, ok := auth.GetGQLAuthenticatedSession(ctx)
	if !ok {
		return unauthorizedError{}
	}
	if session.User.Role != sessions.UserRoleAdmin {
		return RoleNotPermittedError{session.User.Role}
	}
	return nil
}
