### Title
Unauthenticated "Magic QR-code" reset actions allow any bystander to DOS the signup pipeline - (File: `src/plans/qr_scan/operator.rs`, `src/plans/mod.rs`)

### Summary
`qr_scan::operator::Data::try_parse` accepts any QR-code payload matching `magic_action:(reset_wifi_credentials|reset_mirror_calibration)` and classifies it as `Data::MagicResetWifi`/`Data::MagicResetMirror` with no cryptographic or backend authentication of the presenter. `handle_magic_operator_qr_code` executes the corresponding reset action immediately upon detection, before the orb ever calls `verify_operator_qr_code` (the step that actually authenticates an operator against the backend). This is the same trust-boundary failure as the RollerPeriphery `approve()` bug in the report: an unprivileged caller/input reaches a state-mutating function with no authorization check, causing denial of service to the core deposit/mint (here, signup) flow.

### Finding Description
`Data::try_parse` in `src/plans/qr_scan/operator.rs` matches the `MAGIC_QR_CODE` regex against raw scanned QR text and returns `Data::MagicResetWifi` or `Data::MagicResetMirror` purely from string pattern matching, with no signature, token, or identity check tying the QR code to an authorized operator. [1](#0-0) 

In `src/plans/mod.rs`, both `scan_initial_qr_codes` and `scan_remaining_qr_codes` call `self.handle_magic_operator_qr_code(orb, operator_qr_code)` right after the operator QR-code is scanned, and only call `self.verify_operator_qr_code(...)` (the actual backend-authenticated check) afterward, for the `Normal` variant. [2](#0-1) [3](#0-2) 

`handle_magic_operator_qr_code` unconditionally executes `reset_mirror_calibration` or `reset_wifi_and_ensure_network` for the magic variants, with no gate requiring the presenter to be a trusted/authenticated operator. [4](#0-3) 

These reset routines perform real, disruptive state changes: `reset_wifi_and_ensure_network` tears down the WiFi connection via `network::reset()`, re-establishes it, and resets the RGB camera pipeline; `reset_mirror_calibration` stores/recomputes mirror calibration and re-enables/disables the mirror agent. [5](#0-4) 

### Impact Explanation
Any person able to present a QR code to the orb's camera during the operator-QR-scan phase — which is inherent to how a walk-up biometric verification kiosk operates and requires no operator credentials, backend token, or privileged access — can repeatedly trigger WiFi disconnection/reconnection cycles or mirror recalibration. This stalls or resets the device before any legitimate signup can proceed, denying the signup/enrollment service to all users in front of the orb, analogous to the report's unauthenticated `approve(0)` call blocking deposit/mint. There is no rate limiting or cooldown visible on this path, so the disruption can be sustained indefinitely.

### Likelihood Explanation
High. The trigger is a printed or displayed QR-code containing a fixed, publicly-knowable string (`magic_action:reset_wifi_credentials` or `magic_action:reset_mirror_calibration`); no secrets, credentials, or backend interaction are required to reach the vulnerable dispatch path.

### Recommendation
Do not execute state-mutating magic actions before the presenter is authenticated. Move the magic-QR dispatch to occur only after a successful `verify_operator_qr_code` result (or another backend-authenticated operator check), or require magic QR codes to carry a signed/verifiable token bound to a trusted operator identity before `reset_mirror_calibration`/`reset_wifi_and_ensure_network` are invoked.

### Proof of Concept
1. Generate a QR code encoding the literal string `magic_action:reset_wifi_credentials` (or `magic_action:reset_mirror_calibration`).
2. Present it to the orb's front camera during the idle/operator-QR-scan phase — no operator login, token, or backend session is needed.
3. Observe `handle_magic_operator_qr_code` matching `Data::MagicResetWifi`/`Data::MagicResetMirror` and calling `reset_wifi_and_ensure_network`/`reset_mirror_calibration` unconditionally, disrupting connectivity/calibration.
4. Repeat at will to keep the orb in a reset loop, denying signup service to legitimate users. [6](#0-5)

    fn try_parse(code: &str) -> Option<Self> {
        let normal = user::Data::try_parse(code)
            .filter(
                |d| if d.signup_extension() { d.signup_extension_config.is_some() } else { true },
            )
            .map(Data::Normal);
        if normal.is_some() {
            return normal;
        }
        if let Some(captures) = MAGIC_QR_CODE.captures(code) {
            return match captures
                .name("magic_action")
                .expect("magic_action group must be present")
                .as_str()
            {
                "reset_wifi_credentials" => Some(Data::MagicResetWifi),
                "reset_mirror_calibration" => Some(Data::MagicResetMirror),
                _ => None,
            };
        }
        None
    }

        orb.reset_rgb_camera().await?;
        Ok(())
    }

    ) -> Result<Option<qr_scan::user::Data>> {
        match qr_code {
            qr_scan::operator::Data::Normal(qr_code) => {
                tracing::info!("Operator QR-code detected: {qr_code:?}");
                Ok(Some(qr_code))
            }
            qr_scan::operator::Data::MagicResetMirror => {
                tracing::info!("Magic QR-code detected: Reset Mirror");
                dd_incr!("main.count.signup.during.general.magic_qr.reset_mirror");

                if let Err(err) = &result {
                    tracing::error!("Failed to reset mirror calibration: {err}");
                }
                orb.ui.magic_qr_action_completed(result.is_ok());
                Ok(None)

                if let Err(err) = &result {
                    tracing::error!("Failed to reset wifi: {err}");
                }
                orb.ui.magic_qr_action_completed(result.is_ok());
                Ok(None)
