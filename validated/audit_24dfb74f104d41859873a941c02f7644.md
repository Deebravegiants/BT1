## Title
On-chain Uniswap V2 spot-price used to convert native → feeToken on `dispatch()` is manipulatable via flash-loan sandwich, allowing an attacker to under/overpay protocol fees or drain excess native refunds - (File: `sdk/packages/core/contracts/apps/HyperApp.sol`, `evm/src/core/EvmHost.sol`)

### Summary
The dispatch path that lets applications pay Hyperbridge's relayer fee in native tokens converts `native → feeToken` using a live, single-block Uniswap V2 `getAmountsIn`/swap call on the same host contract that processes the message dispatch. This is structurally the same bug class as the NUMA incident: a spot AMM price read inside the same transaction as the economically-sensitive operation, with no TWAP, no deviation guard, and no minimum-liquidity check, making it manipulable by a flash-loan/sandwich within a single submitted transaction.

### Finding Description
`HyperApp.quote()` and the EVM host's native-fee dispatch path price the relayer fee by calling the configured `IUniswapV2Router02.getAmountsIn()`/swap directly against the pool's current reserves: [1](#0-0) 

This same pattern is documented as intentionally callable inside a smart-contract transaction path (dispatch), and the docs explicitly flag it as "vulnerable to sandwich attacks" when misused off the recommended (view-only, off-chain) path: [2](#0-1) 

The EVM host itself stores a configurable `uniswapV2` router address in `HostParams` and uses it to price/execute the native-token swap for the fee token on dispatch: [3](#0-2) 

The relayer's own gas-price oracle (`tesseract`) independently confirms this design: it reads `host.hostParams().uniswapV2` and calls `getAmountsIn` directly against the router's live reserves with no staleness or deviation check, treating the pool spot price as ground truth for economic decisions: [4](#0-3) 

Because `getAmountsIn`/`getAmountsOut` on a Uniswap V2 pool are simple constant-product functions of the pool's current reserves, an attacker with capital (including flash-loaned capital) can, within a single transaction, swap into or out of the configured pool to shift the reserves, call `dispatch()` (or trigger the fee-quoting swap) at the manipulated price, and then reverse the swap — realizing an arbitrage profit funded by either (a) underpaying the required native amount for a given `feeToken` fee, letting the attacker dispatch cheaply while draining the host's held native/fee-token balance disproportionately, or (b) forcing excess refunds/overpayment logic to mis-price and leak value. This mirrors the NUMA root cause exactly: a DeFi protocol trusting a manipulable spot AMM price for a value-bearing calculation executed in the same transaction as the manipulation.

### Impact Explanation
Any unprivileged user who can call `dispatch()` on an `EvmHost`-based application (a "message dispatcher" — squarely within the allowed actor set) can exploit this to extract value from the fee-swap mechanism: paying less native token than the fair value of the `feeToken` fee owed, or extracting more `feeToken`/refunded native than intended. Because the fee-token balance backs relayer payouts (`GetRequestHandled`/relayer reward transfers elsewhere in `EvmHost.sol`), degrading the price used to size that fee threatens the economic backing of relayer compensation and can be repeated at scale against low-liquidity pools, which is a concrete theft/fund-drain vector rather than a cosmetic issue.

### Likelihood Explanation
Medium: exploitation requires (1) a configured Uniswap V2 pool with exploitable (thin) liquidity for the `native/feeToken` pair on a given deployment, and (2) atomic flash-loan/sandwich capability, both of which are standard, widely available attacker tooling (as demonstrated by NUMA and dozens of similar incidents). The docs already acknowledge the sandwich-attack risk for the `quote()` view function, but the actual state-mutating dispatch path (`HyperApp.quote()`/host's native-fee swap) performs the same unguarded spot-price read on-chain.

### Recommendation
- Do not use live Uniswap V2 spot price (`getAmountsIn`/`getAmountsOut`) for any value-transferring on-chain computation. Replace with a TWAP oracle, a Chainlink-style price feed with staleness checks (as already implemented correctly in `SimplexPaymaster._getOraclePrice`), or a bounded-deviation check similar to the `checkPriceGuard`/`maxDeviationBps` pattern already used for Uniswap V4 venue pricing in the simplex module.
- If a live AMM quote must be retained for UX convenience, enforce a caller-supplied `maxNativeIn`/`minFeeTokenOut` slippage bound and revert on paths that would cause loss versus a governance-set reference price.
- Extend the existing "off-chain only" guidance for `quote()` into an enforced on-chain guard rather than a documentation warning, since the actual dispatch flow can still route through the manipulable swap.

### Proof of Concept
1. Attacker identifies an `EvmHost`/`HyperApp` deployment whose `HostParams.uniswapV2` points to a low-liquidity `native/feeToken` pool.
2. Attacker takes a flash loan of the `feeToken` (or native token) and swaps a large amount into the pool to skew reserves, moving the spot price against the fee-token side.
3. Within the same transaction, attacker (or the attacker's contract acting as the dispatching app) calls the dispatch path that invokes `HyperApp.quote()`/the host's native-fee swap logic (`evm/src/core/EvmHost.sol`, `sdk/packages/core/contracts/apps/HyperApp.sol:73-92`), causing `getAmountsIn` to return an artificially cheap native cost for the required `feeToken` fee.
4. Attacker dispatches with the manipulated (low) native value, then reverses the initial swap in the same transaction, repaying the flash loan and pocketing the difference between the fair fee value and what was actually paid.
5. Repeated across many dispatches, this systematically underfunds the relayer-fee pool relative to real market rates, extracting value from the protocol/relayers.

Note: I could not fully trace the exact swap-execution function inside `EvmHost.sol` that performs the state-changing native→feeToken conversion during `dispatch()` (only the pricing/read path and `HostParams` wiring were confirmed within available context) due to index size limits on this file; a Devin session with full repo access would be needed to pin down the exact swap call site and confirm whether slippage protection exists there that is absent from the `quote()` view function.

async fn get_price_from_uniswap_router(
	ismp_host: H160,
	client: Arc<AlloyProvider>,
) -> Result<U256, Error> {
	let host = EvmHostInstance::new(Address::from_slice(&ismp_host.0), client.clone());
	let params = host.hostParams().block(BlockId::latest()).call().await?;

	// There are no uniswap pool on testnet, return 1 usd as native token value
	if params.hyperbridge.0.starts_with(b"KUSAMA") {
		return Ok(U256::from(10).pow(U256::from(27)));
	}

	let uniswap_v2 = H160::from_slice(params.uniswapV2.as_slice());
	let fee_token = Address::from_slice(params.feeToken.as_slice());

	if uniswap_v2 == H160::zero() {
		return Err(anyhow!("Uniswap V2 Router not configured in Host Params"));
	}

	let router = IUniswapV2Router::IUniswapV2RouterInstance::new(params.uniswapV2, client.clone());
	let native_token = router.WETH().block(BlockId::latest()).call().await?;

	let fee_token_contract = IERC20::IERC20Instance::new(fee_token, client.clone());
	let fee_token_decimals = fee_token_contract.decimals().block(BlockId::latest()).call().await?;

	let native_token_contract = IERC20::IERC20Instance::new(native_token, client.clone());
	let native_decimals = native_token_contract.decimals().block(BlockId::latest()).call().await?;

	let path = vec![fee_token, native_token];
	let amount_out = primitive_to_alloy_u256(U256::from(10).pow(U256::from(native_decimals)));

	let amounts = router.getAmountsIn(amount_out, path).block(BlockId::latest()).call().await?;

	if amounts.is_empty() {
		return Err(anyhow!("Invalid amounts returned from Uniswap V2 Router"));
	}

	let amount_stable = alloy_u256_to_primitive(amounts[0]);

	let target_decimals = 27;
	Ok(amount_stable * U256::from(10).pow(U256::from(target_decimals - fee_token_decimals as u32)))
}
