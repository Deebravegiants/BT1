Audit Report

## Title
Non-atomic check-then-act in JWT replay cache allows replay of the same authorization token - (File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go)

## Summary
`WorkflowMetadataHandler.Authorize` checks JWT replay status via `jwtCache.isReplay` and only records usage via `jwtCache.recordUsage` after several more steps complete. The read and write to the replay-tracking map are performed in separate, non-atomic critical sections, so concurrent requests using the identical JWT can both pass the replay check.

## Finding Description
`Authorize` is the authentication gate for unprivileged HTTP-trigger workflow requests entering the gateway [4](#0-3) . It verifies the JWT signature, then calls `h.jwtCache.isReplay(claims.ID)` (acquiring `RLock`, checking map membership, releasing the lock), and only at the very end of the function calls `h.jwtCache.recordUsage(claims.ID)` (acquiring a separate `Lock`) [5](#0-4) . Between the `isReplay` check and the `recordUsage` write there is no held lock spanning both operations, so two goroutines processing requests with the same `jti` concurrently can both observe `isReplay == false` and both proceed to the authorized-key check, then both call `recordUsage`.

## Impact Explanation
The JWT replay cache exists specifically to prevent a captured/observed token from being reused. If a valid signed token is submitted twice at nearly the same time, both requests can be authorized and dispatched to the DON, bypassing the intended single-use guarantee — a request-impersonation/replay class bypass.

## Likelihood Explanation
Likelihood is limited: the race window is narrow (microseconds between the two lock acquisitions), and it requires possession of a validly-signed JWT that has not yet been recorded, plus the ability to send two copies of the exact same request concurrently to the gateway. It is a genuine, provable inconsistency in the intended one-time-use invariant, reachable by an unprivileged client without any elevated role.

## Recommendation
Perform the replay check and usage recording as a single atomic operation, e.g. add a `checkAndRecordJWTUsed(jti string) bool` method that acquires one write lock, checks and inserts into the map, and returns whether the token was already present — eliminating the separate `isReplay`/`recordUsage` calls in `Authorize`.

## Proof of Concept
1. Obtain a validly signed JWT for a registered workflow, with `jti = "X"`.
2. Fire two HTTP trigger requests carrying this identical JWT to the gateway at effectively the same time.
3. Both goroutines execute `Authorize`: both call `h.jwtCache.isReplay("X")` before either calls `h.jwtCache.recordUsage("X")`, both observe `false`.
4. Both requests pass the authorized-key check and are dispatched to the workflow DON — the token is used twice despite the intended one-time-use enforcement.

func (cache *jwtReplayCache) isReplay(jti string) bool {
