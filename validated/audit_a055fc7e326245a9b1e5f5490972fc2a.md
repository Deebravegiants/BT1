### Title
Chainlink Oracle Price Used Without Min/Max Sanity Bounds in `SimplexPaymaster._getOraclePrice` - ([File: evm/src/utils/SimplexPaymaster.sol])

### Summary
`SimplexPaymaster._getOraclePrice` only checks that the Chainlink `answer` is positive and not stale; it never validates the returned price against the feed's `minAnswer`/`maxAnswer` bounds. During a flash crash or depeg of a registered token, Chainlink will keep returning its clamped `minAnswer`/`maxAnswer` rather than reverting, and the paymaster will silently accept that stale-but-"valid" price to compute how much ERC-20 a user must pay for gas.

### Finding Description
`_getOraclePrice` in `evm/src/utils/SimplexPaymaster.sol` performs: [1](#0-0) 

The only checks are `answer <= 0` and staleness (`block.timestamp - updatedAt > maxOracleAge`). There is no cross-check against the aggregator's configured `minAnswer`/`maxAnswer` bounds, which is exactly the missing check described in the reported bug class. This price feeds directly into `_tokenPrice`, which computes the ERC-20 amount a UserOperation sender owes for gas: [2](#0-1) 

`_tokenPrice` is called from the permissionless ERC-4337 paymaster validation path (`getTokenPrice`, `estimateTokenCost`, and the `_prefund`/postOp accounting inherited from `PaymasterERC20`), meaning any unprivileged UserOperation sender using this paymaster to pay gas in a registered stablecoin can trigger this mispricing without any privileged role. The same unchecked price is also used in `swapAndDeposit` to size `amountOutMin` for the fee-recycling swap: [3](#0-2) 

### Impact Explanation
If a registered stablecoin (e.g., USDC/USDT) depegs sharply downward past the Chainlink feed's `minAnswer` floor, the feed continues returning the clamped minimum price instead of reverting. `_tokenPrice` will then price the depegged token as if it were still worth its floor price (e.g., ~$1), so a UserOperation sender can pay for gas using a token that is actually worth far less than the price the paymaster credits it at. This directly drains value from the paymaster's EntryPoint deposit/treasury — an unbacked value transfer funded by the paymaster's own gas subsidy, i.e., a fund-draining mispricing rooted in unchecked oracle bounds. It also corrupts `swapAndDeposit`'s slippage floor, letting a mis-priced swap execute against the treasury's holdings.

### Likelihood Explanation
Exploitation requires only a real-world depeg/flash-crash event on a registered token's Chainlink feed reaching its floor/ceiling (a known Chainlink limitation, not an attacker-controlled contract bug) plus a single unprivileged UserOperation submitted through the permissionless paymaster — no governance, relayer, or admin privilege is needed to trigger the mispricing once the market condition occurs.

### Recommendation
In `_getOraclePrice`, fetch and cache each oracle's `minAnswer`/`maxAnswer` (or equivalent bounds) at registration time, and revert if `answer` is at or near those bounds, mirroring the recommended fix in the source report:
```solidity
if (answer <= minPrice || answer >= maxPrice) revert InvalidOraclePrice(address(oracle), answer);
```
Apply the same bound check to both `nativeOracle` and every `TokenConfig.tokenOracle` before using the price in `_tokenPrice` and `swapAndDeposit`.

### Proof of Concept
1. Governance registers a stablecoin token with a Chainlink feed whose aggregator has `minAnswer = X` (e.g., far below $1 but still positive).
2. The stablecoin depegs below its true value under `X` (flash crash/bridge compromise); Chainlink's aggregator clamps and keeps reporting `answer = X` (or its `minAnswer`) as `latestRoundData()`, satisfying `answer > 0` and being continuously "fresh" (`updatedAt` keeps advancing on-chain per round).
3. Any user submits a UserOperation with `paymasterData` referencing this token; `_getOraclePrice` accepts the clamped price without reverting since it only checks positivity/staleness.
4. `_tokenPrice`/`estimateTokenCost` compute the required token amount using the stale, too-high price, letting the sender pay far fewer real dollars of the depegged token than the gas actually costs, draining the paymaster's EntryPoint deposit funded by `treasury`.

```text
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
```
