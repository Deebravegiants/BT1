Audit Report

## Title
NULL Pointer Dereference in `GatewayHandler.handlePublicKeyGet` via missing Params nil-check - (File: `core/capabilities/vault/gw_handler.go`)

## Summary
`handlePublicKeyGet` unconditionally dereferences `req.Params` (`*json.RawMessage`) in `json.Unmarshal(*req.Params, r)` without a nil check, while `HandleGatewayMessage` routes `MethodPublicKeyGet` directly to this handler, bypassing `GatewayVaultRequestProcessor.ProcessRequest`, which is the component that performs the `req.Params == nil` guard for the other vault methods. A gateway-forwarded JSON-RPC request for `MethodPublicKeyGet` with `params` omitted or `null` will cause a nil pointer dereference panic in the goroutine handling that gateway message.

## Finding Description
In `HandleGatewayMessage`, `MethodSecretsCreate`/`MethodSecretsUpdate`/`MethodSecretsDelete`/`MethodSecretsList` are all routed through `h.requestProcessor.ProcessRequest`, whose per-method processing functions (`processCreateSecretsRequest`, `processUpdateSecretsRequest`, `processDeleteSecretsRequest`, `processListSecretIdentifiersRequest`) each explicitly check `if req.Params == nil` before use. [1](#0-0) 

`MethodPublicKeyGet`, however, calls `h.handlePublicKeyGet` directly with no such gate, and `handlePublicKeyGet` immediately does `json.Unmarshal(*req.Params, r)` without checking `req.Params` for nil first. [2](#0-1) 

This confirms the claim's root cause precisely: `MethodPublicKeyGet`'s handler is the only vault method handler that dereferences `req.Params` without any preceding nil check anywhere in its call path, unlike `handleSecretsDelete` and `handleSecretsList`, which perform the identical unmarshal pattern but are protected upstream by `ProcessRequest`'s nil check in `processDeleteSecretsRequest`/`processListSecretIdentifiersRequest`. [3](#0-2) [4](#0-3) 

Since `GetPublicKeyRequest{}` requires no fields, a spec-compliant JSON-RPC 2.0 client can legitimately omit `params` entirely (or send `"params": null`), causing `req.Params` to decode to `nil` and the subsequent dereference to panic.

## Impact Explanation
This is a legitimate denial-of-service defect: an unauthenticated/unprivileged JSON-RPC request reaching the node's Vault gateway handler for `MethodPublicKeyGet` can trigger a nil pointer dereference panic in the goroutine that processes gateway messages, since this method path requires no authorization pipeline (it skips `Authorizer`/`ProcessRequest` entirely). Whether this crashes the whole node process or is isolated depends on panic-recovery behavior in the calling connector goroutine, which was not confirmed during this review, but at minimum it disrupts servicing of that gateway message and is a real, code-verified bug distinct from a false claim.

## Likelihood Explanation
High. No authentication, allowlisting, or parameter validation gates this code path before the nil dereference; any actor able to route a JSON-RPC request through the gateway to the node for `MethodPublicKeyGet` with `params` omitted or null can trigger it repeatedly and deterministically.

## Recommendation
Add an explicit `if req.Params == nil` check in `handlePublicKeyGet` before dereferencing, returning `api.UserMessageParseError` (or a dedicated `InvalidVaultParamsError`), consistent with the checks in `processCreateSecretsRequest`, `processUpdateSecretsRequest`, `processDeleteSecretsRequest`, and `processListSecretIdentifiersRequest`. Alternatively, route `MethodPublicKeyGet` through `GatewayVaultRequestProcessor` for consistency, or add a shared `req.Params == nil` guard in `HandleGatewayMessage` before any handler is invoked.

## Proof of Concept
1. As a gateway client, submit a JSON-RPC 2.0 request with `method` set to `vaulttypes.MethodPublicKeyGet` and either omit the `params` field or set `"params": null`.
2. The gateway forwards the request to the node's `GatewayHandler.HandleGatewayMessage`.
3. Execution enters the `vaulttypes.MethodPublicKeyGet` case, calling `h.handlePublicKeyGet(ctx, gatewayID, req)`.
4. `handlePublicKeyGet` executes `json.Unmarshal(*req.Params, r)`, dereferencing a nil `*json.RawMessage`, causing a runtime panic.
5. A Go unit test constructing `&jsonrpc.Request[json.RawMessage]{Method: vaulttypes.MethodPublicKeyGet, Params: nil}` and invoking `HandleGatewayMessage` would reproduce the panic directly.
