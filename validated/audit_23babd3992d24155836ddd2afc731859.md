### Title
Double-spend of GET-request relayer fee via missing `_requestCommitments` cleanup after response delivery - (File: `evm/src/core/EvmHost.sol`)

### Summary
`EvmHost.dispatchIncoming(GetResponse, address)` pays the relayer fee for a delivered GET response by reading `_requestCommitments[commitment].fee`, but — unlike every other terminal path for the same commitment (`dispatchTimeOut(GetRequestTimeout,...)`, `dispatchTimeOut(PostRequestTimeout,...)`) — it never deletes `_requestCommitments[commitment]` after paying. This leaves the fee-bearing `FeeMetadata` record alive after the resource it represents has already been "spent," so a later timeout delivery for the same commitment can consume it a second time.

### Finding Description
Compare the two terminal handlers for the same `_requestCommitments[commitment]` entry:

`dispatchIncoming(GetResponse memory response, address relayer)`: [1](#0-0) 
pays `fee = _requestCommitments[commitment].fee` to `relayer` on success but never calls `delete _requestCommitments[commitment]`.

`dispatchTimeOut(GetRequestTimeout memory timeout, FeeMetadata memory meta, bytes32 commitment)`: [2](#0-1) 
explicitly deletes `_requestCommitments[commitment]` up front for "replay protection," and on module-callback failure re-inserts `meta` "so it can be retried" — the same pattern in the JFS advisory (free-then-conditionally-reallocate without clearing on the success path).

Because the success path of `dispatchIncoming(GetResponse,...)` never clears `_requestCommitments[commitment]`, the `FeeMetadata` (`sender`, `fee`) for that GET request remains fully intact in storage after the fee has already been paid out once. If a relayer later also supplies a valid non-membership/timeout proof for the same commitment (a GET timeout is verified against the *destination* chain's storage independently of whether the response was already delivered to the *source*/host chain — `EvmHost` performs no cross-check against `_responseReceipts[commitment]` before running `dispatchTimeOut`), the handler will process the timeout, `delete _requestCommitments[commitment]` (a no-op cleanup at that point), and pay `meta.fee` to `meta.sender` a second time via `IERC20(feeToken()).safeTransfer(meta.sender, meta.fee)`.

This is the same bug class as CVE-2023-53616: a resource is released ("freed") along one code path without clearing the record that tracks it, so a second, independent code path can release ("free") the same resource again.

By contrast, the Substrate/`pallet-ismp` implementation of the identical protocol explicitly guards against this: `handlers::timeout::handle` rejects a GET timeout if a response was already received, via `host.response_receipt(&response).is_some()`: [3](#0-2) 
`EvmHost.sol` has no equivalent check, so the two on-chain host implementations diverge in a security-relevant way.

### Impact Explanation
A successful double-claim drains the fee token balance held by `EvmHost` — funds belonging to other users' request/response fees — paying out the same fee twice for a single GET request. This is a concrete theft/duplicate-mint-of-value bug (direct fee-token loss from the host's fee reserve), reachable by any relayer who can supply both a valid GetResponse delivery and a later valid timeout proof for the same commitment, i.e. from a single relayed proof/dispatched-request pathway without any privileged role.

### Likelihood Explanation
Exploitation requires timing/relay conditions (deliver the response, then also obtain and submit a timeout proof for the same commitment) but does not require any privileged access — a normal relayer or "malicious relayer" acting within the standard message-delivery flow can attempt it. Whether `HandlerV2.sol` (the entry point that calls `EvmHost.dispatchTimeOut`) independently rejects a timeout once a response commitment has already been consumed was not verified within the available exploration; if it performs no such cross-check (mirroring the missing check inside `EvmHost` itself), the path is directly reachable.

### Recommendation
In `EvmHost.dispatchIncoming(GetResponse memory response, address relayer)`, delete `_requestCommitments[commitment]` immediately after (or as part of) paying the relayer fee, mirroring the cleanup performed in both `dispatchTimeOut` variants. Additionally, mirror the Substrate host's defense-in-depth check by rejecting a `dispatchTimeOut` call for a GET request whose `_responseReceipts[commitment]` is already populated.

### Proof of Concept
1. A GET request is dispatched from `EvmHost`, creating `_requestCommitments[commitment] = FeeMetadata{sender, fee}`.
2. A relayer submits a valid response proof; `HandlerV2` calls `EvmHost.dispatchIncoming(GetResponse,...)`, which pays `fee` to the relayer and leaves `_requestCommitments[commitment]` untouched. [4](#0-3) 
3. The same relayer (or a colluding one) later submits a timeout message for the same commitment; `HandlerV2` calls `EvmHost.dispatchTimeOut(GetRequestTimeout, meta, commitment)`, which finds `_requestCommitments[commitment]` still populated with the original `fee`/`sender`, deletes it, and pays `meta.fee` to `meta.sender` again. [5](#0-4) 
4. Net effect: the fee token amount for a single GET request is paid out twice from `EvmHost`'s fee-token balance.

```text
    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }
```

```text
    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }
```
