### Title
Stale `TombStone.original_owner` allows a former owner to reclaim an object burned by a later, legitimate owner - (File: aptos-move/framework/aptos-framework/sources/object.move)

### Summary
`object::burn` performs a "soft burn": it attaches a `TombStone` resource recording the caller as `original_owner`, but it does **not** change the object's `owner` field or restrict further ungated transfers [1](#0-0) . The normal transfer path (`transfer`, `transfer_call`, `transfer_raw`, `transfer_to_object`) all funnel into `transfer_raw_inner`, which updates `ObjectCore.owner` but never clears an existing `TombStone` [2](#0-1) . Only the one-time `transfer_with_ref` (via `LinearTransferRef`) explicitly clears a stale `TombStone` before transferring [3](#0-2) . Because ordinary transfers do not clear the tombstone, an object can carry a stale `original_owner` field that no longer corresponds to its actual prior owner. `unburn` then trusts that stale field to authorize returning custody from `BURN_ADDRESS` [4](#0-3) .

### Finding Description
The custody invariant broken: "only the party who actually sent an object to the burn address should be able to reclaim it." Sequence:

1. Owner **A** owns the object and calls `object::burn(A, object)`. This only sets `TombStone { original_owner: A }`; ownership remains **A** [1](#0-0) .
2. **A** later transfers the object normally to **B** using `object::transfer` (a perfectly legal operation since `allow_ungated_transfer` is untouched by soft-burn). `transfer_raw_inner` only updates `object_core.owner`; it does **not** remove the pre-existing `TombStone` [2](#0-1) .
3. **B**, now the legitimate owner, decides to genuinely destroy the object by sending it to `BURN_ADDRESS` via the ordinary `object::transfer(B, object, BURN_ADDRESS)` entry function. `verify_ungated_and_descendant` only checks the object's own `allow_ungated_transfer` flag and the caller's ownership chain — it does not check whether a `TombStone` already exists, so this succeeds [5](#0-4) . `object_core.owner` becomes `BURN_ADDRESS`, but `TombStone.original_owner` is still the stale value **A**.
4. **A** (a former owner with no current legitimate claim) calls `object::unburn(A, object)`. Because `object_core.owner == BURN_ADDRESS` and `TombStone.original_owner == A`, the check passes and `transfer_raw_inner(object_addr, A)` restores ownership to **A** [6](#0-5) .

The corrupted field is `ObjectCore.owner`: it is reassigned to a stale/former principal (**A**) instead of the actual party (**B**) who performed the real burn to `BURN_ADDRESS`.

### Impact Explanation
This is unauthorized owner reassignment / theft of an object (and any value it represents, e.g. an NFT, capability-holding object, or any object-based asset) away from its legitimate current possessor at the time it was actually sent to the burn address. Any object that has ever been soft-burned by a prior owner and later changes hands through a standard transfer carries this latent, invisible backdoor for that prior owner to reclaim it after a subsequent genuine burn — with no signature or cooperation from the current/burning owner required beyond their own decision to send it to `BURN_ADDRESS`. Given objects underpin fungible-asset stores, token objects, and other value-bearing constructs, this satisfies the custody-grade "unauthorized owner reassignment" and "theft" impact categories.

### Likelihood Explanation
The preconditions are all reachable through public, unprivileged entry functions with no special permissions: `burn`, `transfer` (or `transfer_call`/`transfer_raw`), and `unburn` are all `public`/`entry` functions callable by any signer who is (at the relevant time) the object's current owner. No governance, admin, or privileged capability is required. The only behavioral requirement is that a soft-burned object subsequently changes hands via a normal transfer before being genuinely sent to `BURN_ADDRESS` — a realistic and unremarkable usage pattern, since soft-burn is documented as merely hiding the object from indexers and explicitly does not restrict further transfers.

### Recommendation
Clear (`move_from`) any existing `TombStone` inside `transfer_raw_inner` (or at minimum in the public `transfer`/`transfer_raw`/`transfer_to_object` entry points) whenever the object's owner actually changes, mirroring the behavior already implemented in `transfer_with_ref`. This ensures `TombStone.original_owner` can never reference a party other than the object's owner immediately prior to being sent to `BURN_ADDRESS`.

### Proof of Concept
```
// A owns `obj`
object::burn(&A, obj);                       // TombStone{original_owner: A}, owner stays A
object::transfer(&A, obj, address_of(&B));   // owner -> B, TombStone NOT cleared
object::transfer(&B, obj, BURN_ADDRESS);     // owner -> BURN_ADDRESS, TombStone still says A
object::unburn(&A, obj);                     // succeeds: owner -> A (theft from B)
```

    /// Allow origin owners to reclaim any objects they previous burnt.
    public entry fun unburn<T: key>(
        original_owner: &signer,
        object: Object<T>,
    ) {
        let object_addr = object.inner;
        assert!(exists<TombStone>(object_addr), error::invalid_argument(EOBJECT_NOT_BURNT));

        // The new owner of the object can always unburn it, but if it's the burn address, we go to the old functionality
        let object_core = borrow_global<ObjectCore>(object_addr);
        if (object_core.owner == signer::address_of(original_owner)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object_addr);
        } else if (object_core.owner == BURN_ADDRESS) {
            // The old functionality
            let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
            assert!(
                original_owner_addr == signer::address_of(original_owner),
                error::permission_denied(ENOT_OBJECT_OWNER)
            );
            transfer_raw_inner(object_addr, original_owner_addr);
        } else {
            abort error::permission_denied(ENOT_OBJECT_OWNER);
        };
    }
