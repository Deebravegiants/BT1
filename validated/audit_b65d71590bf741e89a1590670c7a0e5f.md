### Title
Bridge `OutgoingToken` secret exposed to any authenticated user regardless of role (view-only) - ([File: core/web/bridge_types_controller.go])

### Summary
Similar to the Open WebUI CVE where a non-admin user could read a system-prompt secret via `GET /api/models?` because the API returned admin-configured sensitive fields to any authenticated caller, the chainlink node exposes the bridge `OutgoingToken` — a credential secret used to authenticate the node's outbound requests to an external adapter — to any authenticated user, including users with the lowest `view` role, via `GET /v2/bridge_types` and `GET /v2/bridge_types/:BridgeName`.

### Finding Description
`BridgeTypesController.Index` and `.Show` both build responses with `presenters.NewBridgeResource(bt)`, which unconditionally copies `OutgoingToken` from the DB-backed `bridges.BridgeType` into the JSON:API response body: [1](#0-0) [2](#0-1) 

Unlike `IncomingToken`, which is marked `omitempty` and only populated transiently on `Create`, `OutgoingToken` has no such protection and is always serialized: [3](#0-2) 

These endpoints are registered under the generic authenticated group with no elevated-role middleware (`auth.RequiresEditRole`/`auth.RequiresAdminRole`) — only bare authentication is required: [4](#0-3) 

The RBAC test matrix in the codebase itself documents that `GET /v2/bridge_types` and `GET /v2/bridge_types/MOCK` are `viewOnlyAllowed: true`, confirming that the lowest-privilege `view` role can read this response: [5](#0-4) 

The `OutgoingToken` is a real secret generated at bridge creation time (`utils.NewSecret(24)`), stored in plaintext in the DB (`outgoing_token` column) and used to authenticate the node's own requests to the external bridge adapter: [6](#0-5) 

By contrast, `IncomingToken` (used by the external adapter to authenticate callbacks into the node) is hashed at rest and deliberately excluded from normal read responses via `omitempty`, showing the project's own security intent is to keep bridge secrets out of routine read paths — an intent that is not applied consistently to `OutgoingToken`.

### Impact Explanation
An attacker who obtains a low-privilege `view`-role API credential for the node (e.g., a read-only monitoring/dashboard key, which is explicitly designed to have no write or admin capability) can retrieve every configured bridge's `OutgoingToken` simply by calling `GET /v2/bridge_types`. With that token, the attacker can impersonate the Chainlink node when calling the external bridge adapter (submit forged "outgoing" authenticated requests), potentially manipulating off-chain data sources feeding job pipelines, or gaining information/side-channel access to the bridge integration the node depends on. This is a direct confidentiality break of a role-restricted secret, analogous in class (CWE-200, unprivileged-actor read of admin-controlled sensitive config) to the referenced CVE.

### Likelihood Explanation
Likelihood is moderate-to-high in any deployment that issues `view`-role API keys to less-trusted operators/tools (a common practice for monitoring), since no additional exploitation step beyond a single authenticated GET request is needed — no privilege escalation exploit chain, no timing/race condition, just direct read access by design of the route configuration.

### Recommendation
Restrict `OutgoingToken` exposure in `BridgeResource`/`BridgeTypesController.Index`/`.Show` to `edit`/`admin` roles (e.g., wrap `Index`/`Show` with `auth.RequiresEditRole`, or omit `OutgoingToken` from the presenter for lower roles), mirroring the `omitempty`/write-once treatment already given to `IncomingToken`.

### Proof of Concept
1. Create a node API user/token with role `view` (the lowest privilege tier, per `clsessions.UserRoleView`).
2. As that user, issue `GET /v2/bridge_types` (or `GET /v2/bridge_types/:BridgeName` for a known bridge name).
3. Observe the JSON:API response includes `"outgoingToken": "<secret>"` for every bridge, despite the requesting user having no edit/admin privileges — confirmed by the route's `viewOnlyAllowed: true` designation in the RBAC test table [5](#0-4)  and the unconditional field copy in `NewBridgeResource` [2](#0-1) .

// Index lists Bridges, one page at a time.
func (btc *BridgeTypesController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	bridges, count, err := btc.App.BridgeORM().BridgeTypes(ctx, offset, size)

	resources := make([]presenters.BridgeResource, 0, len(bridges))
	for _, bridge := range bridges {
		resources = append(resources, *presenters.NewBridgeResource(bridge))
	}

	paginatedResponse(c, "Bridges", size, page, resources, count, err)
}

// Show returns the details of a specific Bridge.
func (btc *BridgeTypesController) Show(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	bt, err := btc.App.BridgeORM().FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")

// NewBridgeType returns a bridge type authentication (with plaintext
// password) and a bridge type (with hashed password, for persisting)
func NewBridgeType(btr *BridgeTypeRequest) (*BridgeTypeAuthentication,
	*BridgeType, error,
) {
	incomingToken := utils.NewSecret(24)
	outgoingToken := utils.NewSecret(24)
	salt := utils.NewSecret(24)

	hash, err := incomingTokenHash(incomingToken, salt)
	if err != nil {
		return nil, nil, err
	}

	return &BridgeTypeAuthentication{
		Name:                   btr.Name,
		URL:                    btr.URL,
		Confirmations:          btr.Confirmations,
		IncomingToken:          incomingToken,
		OutgoingToken:          outgoingToken,
		MinimumContractPayment: btr.MinimumContractPayment,
		UseConnectionManager:   btr.UseConnectionManager,
	}, &BridgeType{
		Name:                   btr.Name,
		URL:                    btr.URL,
		Confirmations:          btr.Confirmations,
		IncomingTokenHash:      hash,
		Salt:                   salt,
		OutgoingToken:          outgoingToken,
		MinimumContractPayment: btr.MinimumContractPayment,
		UseConnectionManager:   btr.UseConnectionManager,
	}, nil
