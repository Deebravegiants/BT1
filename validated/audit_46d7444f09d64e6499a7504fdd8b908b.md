### Title
Governance `UpdateParams` on Tron `IntentGatewayV2` skips bps bounds validation, allowing `protocolFeeBps` and destination-specific fees to be set to unbounded/invalid values - (File: evm/tron/contracts/apps/IntentGatewayV2.sol)

### Summary
The Tron fork of `IntentGatewayV2` enforces `protocolFeeBps`/`surplusShareBps` bounds only at initialization time, but the cross-chain-governance-triggered `onAccept` handler for `RequestKind.UpdateParams` writes the new `Params` and per-destination fee overrides directly into storage with no equivalent validation, unlike the canonical EVM implementation which reuses `_validateParams`/`InvalidInput` checks for every update.

### Finding Description
In the reference `evm/src/apps/intentsv2/IntentsBase.sol`, both initial parameter setting and every subsequent governance update go through `_validateParams` and an inline `feeBps >= 10_000` check inside `_updateParams`: [1](#0-0) 

The Tron variant `evm/tron/contracts/apps/IntentGatewayV2.sol` defines its own `onAccept` for `RequestKind.UpdateParams` that decodes the `ParamsUpdate` struct sent by Hyperbridge governance and assigns it straight into `_params` and `_destinationProtocolFees` with **no bounds checking at all** — no call to any `_validateParams`-equivalent, no `protocolFeeBps`/`surplusShareBps` cap, no `feeBps >= 10_000` guard: [2](#0-1) 

Grepping the entire Tron contract confirms it declares `InvalidInput` as an error but this error is never referenced/thrown anywhere in the file (0 `revert InvalidInput` occurrences), meaning the `constructor`/`initialize` path for this contract likely also lacks the same validation that the canonical EVM `IntentsBase._validateParams` performs (`surplusShareBps > 10_000`, `protocolFeeBps >= 10_000`, host/dispatcher code checks). This mirrors exactly the reported bug class: a fee/bps parameter that is bounded at creation time (or bounded in the sibling implementation) but can be changed later to an out-of-range value through the update/change path with no re-validation.

### Impact Explanation
`protocolFeeBps` and per-destination `destinationFeeBps` directly determine how much of a solver's/filler's output is deducted as protocol fee when orders are placed and filled (`deductProtocolFee` logic mirrored in the SDK at `sdk/packages/sdk/src/protocols/intents/quote/shared.ts:46-50`). If governance (or a malicious/compromised relayer forging the `UpdateParams` payload, or simply a benign misconfiguration that is not caught by validation) sets `protocolFeeBps` at or above `10_000` (100%), fee arithmetic can consume the entire order amount or revert/underflow in downstream fee-subtraction logic, freezing user funds in escrow or making fills economically impossible. Because the fee value is entirely unbounded on this code path, this is a concrete freezing-of-funds / broken-accounting risk rather than a low-severity issue.

### Likelihood Explanation
The `onAccept` UpdateParams path is only reachable via a genuine Hyperbridge governance-originated cross-chain `PostRequest` (source must equal `hyperbridge()`), so exploitation requires either a compromised/malicious governance message or, more realistically, an unintentional value being sent by governance that the destination Tron gateway fails to reject (whereas the canonical EVM gateway would reject it with `InvalidInput`). This is a real inconsistency between the "reference" and "ported" implementations of the same fee-update mechanism — the exact analog of the reported bug class (fee bypassed on the update path despite being bounded elsewhere).

### Recommendation
Add the same validation used in `evm/src/apps/intentsv2/IntentsBase.sol::_validateParams`/`_updateParams` to the Tron `IntentGatewayV2.onAccept` `UpdateParams` branch: reject `update.params.protocolFeeBps >= 10_000`, `update.params.surplusShareBps > 10_000`, and each `update.destinationFees[i].destinationFeeBps >= 10_000` before writing to storage, reverting with `InvalidInput()` otherwise.

### Proof of Concept
1. Hyperbridge governance (or a forged/compromised message purporting to be from `hyperbridge()`) dispatches a `PostRequest` to the Tron `IntentGatewayV2` with `body[0] == RequestKind.UpdateParams` and an encoded `ParamsUpdate{ params: { protocolFeeBps: 10000, ... }, destinationFees: [...] }`.
2. `onAccept` decodes the body and executes `_params = update.params;` unconditionally: [3](#0-2) 
3. No revert occurs (contrast with `evm/src/apps/intentsv2/IntentsBase.sol` which would revert with `InvalidInput` for `protocolFeeBps >= 10_000`, as exercised in `evm/tests/foundry/IntentGatewayV2Test.sol:3848-3861` and `3878-3910`).
4. Subsequent `placeOrder`/fill flows on the Tron gateway now compute fees using the out-of-range `protocolFeeBps`, causing full-value fee extraction or fee-arithmetic failure that can trap funds in escrow.

    function _validateParams(Params memory p) internal view {
        if (p.host == address(0) || p.host.code.length == 0) revert InvalidInput();
        if (p.dispatcher == address(0) || p.dispatcher.code.length == 0) revert InvalidInput();
        if (p.surplusShareBps > 10_000) revert InvalidInput();
        if (p.protocolFeeBps >= 10_000) revert InvalidInput();
        if (p.priceOracle != address(0) && p.priceOracle.code.length == 0) revert InvalidInput();
    }

    /**
     * @dev Updates the gateway's configuration parameters and per-destination protocol fees.
     * Called by Hyperbridge governance to modify fee settings, host address, dispatcher,
     * price oracle, and other operational parameters.
     *
     * Validates all params before applying. Emits ParamsUpdated with the old and new params,
     * then iterates over any destination-specific fee overrides and applies them to
     * `_destinationProtocolFees`.
     *
     * @param update The parameter update containing new params and destination fee overrides.
     */
    function _updateParams(ParamsUpdate memory update) internal {
        _validateParams(update.params);

        emit ParamsUpdated({previous: _params, current: update.params});
        _params = update.params;

        for (uint256 i; i < update.destinationFees.length;) {
            bytes memory chain = update.destinationFees[i].chain;
            uint256 feeBps = update.destinationFees[i].destinationFeeBps;
            if (feeBps >= 10_000) revert InvalidInput();
            _destinationProtocolFees[keccak256(chain)] = feeBps;

            unchecked {
                ++i;
            }
            emit DestinationProtocolFeeUpdated(string(chain), feeBps);
        }
    }

        RequestKind kind = RequestKind(uint8(incoming.request.body[0]));

            authenticate(incoming.request);
            WithdrawalRequest memory body = abi.decode(incoming.request.body[1:], (WithdrawalRequest));
            return withdraw(body, kind == RequestKind.RefundEscrow);
        }

        // only hyperbridge is permitted to perfom these actions
        if (keccak256(incoming.request.source) != keccak256(IDispatcher(host()).hyperbridge())) revert Unauthorized();
        if (kind == RequestKind.NewDeployment) {
            NewDeployment memory body = abi.decode(incoming.request.body[1:], (NewDeployment));
            _instances[keccak256(body.stateMachineId)] = body.gateway;
