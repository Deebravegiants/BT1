### Title
Read-only ("view") role users can enumerate External Initiator AccessKeys and OutgoingTokens via unauthorized `GET /v2/external_initiators` - ([File: core/web/router.go])

### Summary
The `GET /v2/external_initiators` route is registered with no role restriction beyond generic authentication, allowing any authenticated user — including one with only the lowest privilege `UserRoleView` ("Overall/Read"-equivalent) role — to list every configured External Initiator, exposing each initiator's `AccessKey` and `OutgoingToken`. This mirrors CVE-2020-2188 exactly: a listing endpoint exposes credential identifiers/tokens to a lower-privileged principal than the operations that actually consume/manage those credentials.

### Finding Description
Chainlink's four user roles are `admin`, `edit`, `run`, `view`, from most to least privileged [1](#0-0) . Mutating operations on external initiators require at least `edit` role via `auth.RequiresEditRole` [2](#0-1) , but the `Index` (list) route is registered only inside the generic authenticated group with no role gate at all: [3](#0-2) 

Compare this to the other endpoints in the same router block, which explicitly wrap creation/deletion in `auth.RequiresEditRole`, while `Index` (the enumeration/list operation) has no such wrapper — any user who can authenticate (even `view` role) can call it.

The `Index` handler returns the full list of external initiators through the standard presenter, which includes the initiator's `AccessKey` and `OutgoingToken`: [4](#0-3) [5](#0-4) 

`AccessKey` is one half of the credential pair used by `AuthenticateExternalInitiator` to authenticate a caller as an external initiator (which is auto-granted `run` role capable of triggering job runs) [6](#0-5) , and `OutgoingToken` is the token Chainlink uses when calling back out to the initiator's registered URL. Enumerating these values via a permission-check gap is directly analogous to the Jenkins EC2 plugin flaw: Overall/Read-privileged (here, `view`-role) users can enumerate credential identifiers meant to be restricted to higher-privileged actors, which can be leveraged as reconnaissance/setup for a follow-on attack (e.g., correlating an `AccessKey` with a leaked/guessed `Secret`, or targeting the exposed `OutgoingToken`'s owning URL).

### Impact Explanation
A `view`-role user, who is supposed to have read-only, non-privileged access to the node, can enumerate all configured `AccessKey`/`OutgoingToken` values for every External Initiator on the node. This is a direct violation of the intended privilege boundary (`view` < `edit`) enforced everywhere else for this resource (create/delete require `edit`), matching CWE-285 (Improper Authorization) and CWE-863 (Incorrect Authorization) in the original advisory. While the paired `Secret`/`OutgoingSecret` values are not returned by `Index` (only at `Create` time), disclosure of `AccessKey`/`OutgoingToken` identifiers is exactly the class of "enumerate credential IDs, usable as part of a chained attack" described in the CVE.

### Likelihood Explanation
High reachability: any provisioned low-privilege (`view`) node user with a valid session/API token can call this endpoint directly with no additional prerequisites, since the route only requires generic authentication and no role check.

### Recommendation
Wrap the `Index` route for `/v2/external_initiators` with `auth.RequiresEditRole` (or a role at least as restrictive as the one required for `Create`/`Destroy`), consistent with the rest of the External Initiator management surface, so that only `edit`/`admin` users can enumerate `AccessKey`/`OutgoingToken` values.

### Proof of Concept
1. Create a Chainlink node user with `UserRoleView` (read-only) role.
2. Authenticate as that user (session or API token).
3. Issue `GET /v2/external_initiators` (as exercised in `core/web/external_initiators_controller_test.go` [7](#0-6) , but with a `view`-role session instead of the test's default admin client).
4. Observe the response returns `200 OK` with each initiator's `AccessKey` and `OutgoingToken`, despite the requester lacking `edit`/`admin` privileges — no `403 Forbidden`/`401` is raised, unlike calls to `Create`/`Destroy` on the same resource.

func AuthenticateExternalInitiator(c *gin.Context, store Authenticator) error {
	ctx := c.Request.Context()
	eia := &auth.Token{
		AccessKey: c.GetHeader(static.ExternalInitiatorAccessKeyHeader),
		Secret:    c.GetHeader(static.ExternalInitiatorSecretHeader),
	}

	ei, err := store.FindExternalInitiator(ctx, eia)
	if err != nil {
		if errors.Is(err, sql.ErrNoRows) {
			return auth.ErrorAuthFailed
		}

		return errors.Wrap(err, "finding external initiator")
	}

	ok, err := bridges.AuthenticateExternalInitiator(eia, ei)
	if err != nil {
		return err
	}
	if !ok {
		return auth.ErrorAuthFailed
	}

	// External initiator endpoints (wrapped with AuthenticateExternalInitiator) inherently assume the role
	// of 'run' (required to trigger job runs)
	c.Set(SessionExternalInitiatorKey, ei)
	c.Set(SessionUserKey, &clsessions.User{Role: clsessions.UserRoleRun})

	return nil
}

// RequiresEditRole extracts the user object from the context, and asserts the user's role is at least
// 'edit'
func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}

func NewExternalInitiatorResource(ei bridges.ExternalInitiator) ExternalInitiatorResource {

		JAID:          NewJAID(strconv.FormatInt(ei.ID, 10)),

func TestExternalInitiatorsController_Index(t *testing.T) {

		NamePrefix:    "foo",
		URL:           cltest.MustWebURL(t, "http://example.com/foo"),
		OutgoingToken: "outgoing_token",
