### Title
Rebalancer treats USDC/USDT as always worth exactly $1 instead of consulting an oracle, letting a depegged stablecoin drain the solver's genuine collateral - ([File: sdk/packages/simplex/src/services/RebalancingService.ts])

### Summary
`RebalancingService.getCurrentBalance` (sdk/packages/simplex/src/services/RebalancingService.ts:464-501) computes a chain's "USD value" of USDC/USDT purely from the raw ERC-20 `balanceOf`/`decimals()` read, with the comment "Returns balance in normalized USD value (treating token as $1)". `checkRebalanceTriggers` / `planTransfersForAsset` (same file, lines 209-370) then compare these nominal balances against configured `baseBalance` targets and greedily route real value (via CCTP/USDT0/Binance CEX, `RebalancingService.rebalance` line 179) from "surplus" chains to "deficit" chains — exactly the peg-target rebalancer pattern flagged in H-11, except the peg here is USDC/USDT↔USD, and it is hard-coded rather than oracle-derived. The same $1-fixed assumption is codified in the rulebook (sdk/packages/simplex/src/services/rebalancers/Rules.md:16, "USDC and USDT are both treated as $1") and repeated in `ContractInteractionService.getInputUsdValue` (sdk/packages/simplex/src/services/ContractInteractionService.ts:472-488) and in `BidManager.computeStablesUsdValue`/`computeOutputsUsdValue` (sdk/packages/sdk/src/protocols/intents/BidManager.ts:529-582), all of which price USDC/USDT at a fixed $1 with no live oracle check. [1](#0-0) 

### Finding Description
The root cause mirrors H-11 exactly: an automated fund-moving mechanism (a "rebalancer") is driven by a valuation that assumes a fixed peg (1 USDC/USDT = $1) instead of a live market price. `checkRebalanceTriggers` computes deficits/surpluses per chain using this fixed valuation: [2](#0-1) 
`planTransfersForAsset` then greedily matches surplus chains to deficit chains and calls `rebalance`, which executes a real cross-chain transfer of genuine value (CCTP mint/burn, USDT0 OFT, or a Binance CEX leg): [3](#0-2) [4](#0-3) 

If either stablecoin depegs (e.g. a real-world Tether/Circle reserve stress event, a chain-specific bridged/wrapped variant trading below par, or a blacklist/freeze event that leaves a non-transferable balance still countable by `balanceOf`), the "surplus" on the chain holding the depegged token is systematically overstated. Because the solver's inbound balances on each chain are populated by filling user orders — an unprivileged, attacker-controlled input — an attacker can deliberately route order flow so the solver accumulates the depegged/impaired stablecoin on one chain while chains holding the genuine, fully-backed stablecoin are drained to "top up" the falsely-detected deficit. Every rebalance cycle net-transfers real economic value from the healthy chains to the impaired one, converging on the same failure mode as the USSD `rebalance()` bug: a peg-vs.-market-price mismatch turns a "keep balances near target" safety mechanism into a value-extraction loop.

The same $1-fixed logic also feeds `ContractInteractionService.getInputUsdValue`, which sizes cross-chain confirmation depth, and `BidManager`'s stable-basket valuation, which selects the winning solver bid — both silently assume par with no fallback to a real price feed, so the same root cause (fixed-peg valuation with no oracle) propagates into other reachable decision points besides the rebalancer.

### Impact Explanation
This is a High-severity finding: it allows an unprivileged party (any user submitting fillable intents/orders) to steadily force the solver's automated rebalancer to move genuinely-backed stablecoin liquidity to chains holding a depegged/impaired stablecoin, realizing a net loss of real collateral on every triggered cycle — the same "drive the peg mechanism to consume all its collateral" outcome described in H-11, just applied to the USDC/USDT peg instead of DAI.

### Likelihood Explanation
Likelihood is Medium: it requires either (a) a real stablecoin depeg/freeze event coinciding with the solver's configured `baseBalances`/`triggerPercentage`, or (b) an attacker engineering order flow so the solver's balance mix skews toward the impaired asset on one chain. Both are realistic operational conditions for a live cross-chain solver (Simplex) rather than requiring any protocol-level compromise, and no oracle or price guard exists anywhere in this valuation path to stop it — unlike the Uniswap V4 venue-pricing path, which explicitly has a `referencePrice`/`maxDeviationBps` guard (sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts), this fixed-$1 rebalancer path has none.

### Recommendation
Replace the hard-coded $1 valuation in `RebalancingService.getCurrentBalance` (and the equivalent assumptions in `ContractInteractionService.getInputUsdValue` and `BidManager`'s stable-basket helpers) with a live price check against a reputable oracle (e.g., Chainlink USDC/USD, USDT/USD feeds) before computing deficits/surpluses, or gate rebalancing/confirmation-sizing with a maximum-deviation guard analogous to the one already implemented for Uniswap V4 venue pricing (`referencePrice`/`maxDeviationBps`), so that a depegged or frozen stablecoin cannot be counted at full nominal value when deciding to move genuinely-backed funds.

### Proof of Concept
1. Solver is configured with `[rebalancing].baseBalances` for USDC and USDT on chains A and B, `triggerPercentage = 0.5` (sdk/packages/simplex/filler-config-example.toml:102-123).
2. An attacker (or a real market event) causes the USDT deployment/bridge representation on chain B to depeg to, say, $0.80 real value while `decimals()`/`balanceOf()` still report full nominal amounts.
3. Attacker routes intent-order flow so the solver accumulates USDT on chain B (impaired) while chain B's USDC nominal balance is drawn down below `(1 - triggerPercentage) × baseBalance`, triggering a deficit (`RebalancingService.checkRebalanceTriggers`, lines 209-255).
4. `planTransfersForAsset` identifies chain A as a genuine USDC surplus source and schedules a transfer of real, fully-backed USDC from A to B to "fix" the detected deficit (lines 288-370), executed via `rebalance` → CCTP/USDT0/Binance (lines 179-200).
5. Because the impaired USDT sitting on chain B is simultaneously counted at full $1 (never actually assessed against real price), the solver's true collateral shrinks with every cycle: real USDC leaves A while B's asset mix is increasingly the impaired token — the identical drain pattern described in H-11, replacing DAI with USDC/USDT. 	async checkRebalanceTriggers(): Promise<TriggerCheckResult> {
		const rebalancingConfig = this.configService.getRebalancingConfig()
		if (!rebalancingConfig) {
			this.logger.debug("Rebalancing config not found, skipping trigger check")
			return { triggered: false, triggeredChains: [] }
		}

		const triggerPercentage = rebalancingConfig.triggerPercentage
		const chainIds = this.configService.getConfiguredChainIds()
		const triggeredChains: TriggerCheckResult["triggeredChains"] = []

		for (const chainId of chainIds) {
			const chain = `EVM-${chainId}`

			for (const asset of ["USDC", "USDT"] as const) {
				const baseBalance = this.configService.getBaseBalance(chainId, asset)
				if (baseBalance === undefined) {
					continue // Skip if base balance not configured
				}

				const currentBalance = await this.getCurrentBalance(chain, asset)
				if (currentBalance === undefined) {
					this.logger.warn({ chain, asset }, "Could not fetch current balance")
					continue
				}

				const threshold = baseBalance * (1 - triggerPercentage)
				if (currentBalance <= threshold) {
					const deficit = baseBalance - currentBalance
					triggeredChains.push({
						chain,
						asset,
						deficit,
					})
					this.logger.info(
						{ chain, asset, currentBalance, baseBalance, threshold, deficit },
						"Portfolio rebalancing trigger detected",
					)
				}
			}
		}

		return {
			triggered: triggeredChains.length > 0,
			triggeredChains,
		}
	}

	private async planTransfersForAsset(
		asset: "USDC" | "USDT",
		deficits: Array<{ chain: string; deficit: number }>,
		allChainIds: number[],
	): Promise<PlannedTransfer[]> {
		const transfers: PlannedTransfer[] = []

		// Compute surpluses for this asset
		const surpluses: Array<{ chain: string; surplus: number }> = []
		for (const chainId of allChainIds) {
			const chain = `EVM-${chainId}`
			const baseBalance = this.configService.getBaseBalance(chainId, asset)
			if (baseBalance === undefined) {
				continue
			}

			const currentBalance = await this.getCurrentBalance(chain, asset)
			if (currentBalance === undefined) {
				continue
			}

			if (currentBalance > baseBalance) {
				const surplus = currentBalance - baseBalance
				surpluses.push({ chain, surplus })
			}
		}

		// Check if total surplus is sufficient
		const totalDeficit = deficits.reduce((sum, d) => sum + d.deficit, 0)
		const totalSurplus = surpluses.reduce((sum, s) => sum + s.surplus, 0)

		if (totalSurplus < totalDeficit) {
			throw new Error(
				`Insufficient surplus to bring ${asset} balances back to base. ` +
					`Total deficit: ${totalDeficit}, Total surplus: ${totalSurplus}`,
			)
		}

		// Greedy matching: sort deficits and surpluses in descending order
		const sortedDeficits = [...deficits].sort((a, b) => b.deficit - a.deficit)
		// Create mutable copies of surpluses for tracking remaining amounts
		const workingSurpluses = surpluses.map((s) => ({ ...s })).sort((a, b) => b.surplus - a.surplus)

		// Match deficits with surpluses
		for (const deficitInfo of sortedDeficits) {
			let remainingDeficit = deficitInfo.deficit

			for (const surplusInfo of workingSurpluses) {
				if (remainingDeficit <= 0) {
					break
				}

				if (surplusInfo.surplus <= 0) {
					continue
				}

				// Skip if source and dest are the same chain
				if (surplusInfo.chain === deficitInfo.chain) {
					continue
				}

				const transferAmount = Math.min(remainingDeficit, surplusInfo.surplus)
				transfers.push({
					sourceChain: surplusInfo.chain,
					destChain: deficitInfo.chain,
					coin: asset,
					amount: transferAmount.toFixed(2),
				})

				remainingDeficit -= transferAmount
				surplusInfo.surplus -= transferAmount
			}

			if (remainingDeficit > 0) {
				throw new Error(
					`Could not fully satisfy deficit for ${asset} on ${deficitInfo.chain}. ` +
						`Remaining deficit: ${remainingDeficit}`,
				)
			}
		}

		return transfers
	}

	/**
	 * Get current balance for a token on a chain.
	 * Returns balance in normalized USD value (treating token as $1).
	 */
	private async getCurrentBalance(chain: string, asset: "USDC" | "USDT"): Promise<number | undefined> {
		try {
			const publicClient = this.chainClientManager.getPublicClient(chain)
			const tokenAddress =
				asset === "USDC" ? this.configService.getUsdcAsset(chain) : this.configService.getUsdtAsset(chain)

			if (!tokenAddress || tokenAddress === "0x") {
				this.logger.warn({ chain, asset }, "Token address not configured")
				return undefined
			}

			// Get decimals
			const decimals = await publicClient.readContract({
				address: tokenAddress as `0x${string}`,
				abi: ERC20_ABI,
				functionName: "decimals",
			})

			// Get balance
			const balanceWei = await publicClient.readContract({
				address: tokenAddress as `0x${string}`,
				abi: ERC20_ABI,
				functionName: "balanceOf",
				args: [this.walletAddress as `0x${string}`],
			})

			// Convert to normalized USD value
			const balanceDecimal = new Decimal(formatUnits(balanceWei, Number(decimals)))
			return balanceDecimal.toNumber()
		} catch (error) {
			this.logger.error({ error, chain, asset }, "Failed to get current balance")
			return undefined
		}
	}
