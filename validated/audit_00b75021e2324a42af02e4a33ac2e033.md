### Title
Unprivileged collateral top-ups can permanently block `clean_bad_debt` and delay bad-debt socialization - ([File: contracts/controller/src/positions/liquidation/mod.rs])

### Summary
`clean_bad_debt` is permissionless, but it only admits an insolvent account when its unweighted collateral is no greater than the fixed dust threshold. Any unprivileged caller can front-run cleanup with `Controller::supply` on an existing collateral position, raising `total_collateral` above that threshold and making every permissionless cleanup revert. The attacker can repeat this while the account remains insolvent, delaying the supply-index write-down and allowing informed suppliers to exit the debt market before losses are socialized.

### Finding Description
`Controller::clean_bad_debt(caller, account_id)` is callable by any authenticated address and delegates to `process_clean_bad_debt`. [1](#0-0) 

The permissionless path uses `BadDebtGate::DustCapped`, which requires both `total_debt > total_collateral` and `total_collateral <= BAD_DEBT_USD_THRESHOLD`. [2](#0-1) 

The threshold comparison is implemented by `is_socializable_bad_debt`. [3](#0-2) 

The threshold is `DEFAULT_MIN_BORROW_COLLATERAL_USD_WAD`; the tests characterize it as a $5 dust gate. [4](#0-3) [5](#0-4) 

`Controller::supply` permits a third party to top up an existing supply position on another account; it only rejects attempts to create a new asset slot for an account the caller does not control. [6](#0-5) 

The deposit is measured at the token level and merged into the account's supply position. [7](#0-6) 

Risk accounting adds every supply position's market value into unweighted `total_collateral`, so a modest top-up to an existing collateral leg directly invalidates the dust-gate condition. [8](#0-7) 

This differs from normal transaction ordering risk: the attacker does not need to manipulate an oracle or a swap route, only call the protocol's intended third-party supply path with their own assets.

### Impact Explanation
Once collateral rises above the dust gate while remaining below debt, `clean_bad_debt` consistently reverts with `CannotCleanBadDebt`. [9](#0-8) 

The debt therefore remains on the pool's books and is not written down through `apply_bad_debt_to_supply_index`. [10](#0-9) 

Until socialization occurs, `backing_shortfall` still counts the delinquent debt at face value when calculating market backing. [11](#0-10) 

A funded attacker can repeatedly restore collateral to just above the threshold, creating a griefing window in which other suppliers can withdraw at the pre-write-down index. The repository's own test demonstrates that a supplier exiting before bad-debt socialization can recover fully while concentrating the eventual loss on the suppliers who remain. [12](#0-11) 

The attacker can be the borrower seeking to keep an insolvent account alive, or a supplier who pays slightly more than the dust threshold as collateral and exits a much larger debt-market position before the write-down.

### Likelihood Explanation
The attack requires only an existing collateral position on the insolvent account and enough collateral value to push that account above the approximately $5 threshold. [13](#0-12) 

The attacker does not need ownership of the target account because third-party top-ups of existing positions are explicitly allowed. [14](#0-13) 

The griefing transaction must use a collateral market that remains backed, because pool supply rejects an already-short market; a collateral asset distinct from the bad-debt asset satisfies this in the normal cross-collateral configuration. [15](#0-14) 

The attack does not prevent the owner-only `force_socialize_bad_debt` recovery path, which bypasses the dust cap, but relying on that privileged intervention does not protect the intended permissionless cleanup mechanism. [16](#0-15) 

### Recommendation
Remove the permissionless dust cap and permit `clean_bad_debt` whenever `total_debt > total_collateral`, or replace it with a resource-bounding mechanism that cannot be manipulated by topping up the target account. `execute_bad_debt_cleanup` already sweeps every supply position, burns every debt position, reclassifies the recovered collateral as protocol revenue, and writes down residual debt. [17](#0-16) 

If the cap exists to bound iteration cost, bound the number of processed positions explicitly instead of making admission depend on attacker-controlled collateral value.

### Proof of Concept

1. Alice owns account `A` in spoke `S`, with an existing USDC supply position and ETH debt. The USDC collateral market is backed, while the account becomes insolvent after a USDC price fall: `total_debt > total_collateral`.
2. Immediately before liquidation or cleanup, arrange the state so `total_collateral <= BAD_DEBT_USD_THRESHOLD`.
3. A keeper submits:
   ```rust
   controller.clean_bad_debt(keeper, A)
   ```
   The call should satisfy `is_socializable_bad_debt`.
4. The attacker front-runs it with:
   ```rust
   controller.supply(
       attacker,
       A,
       S,
       vec![(usdc_hub_asset, top_up_amount)],
   )
   ```
   Because `A` already has a USDC supply position, `require_third_party_existing_supply` accepts the deposit even though `attacker` is neither Alice nor a delegate. [13](#0-12) 
5. The measured USDC transfer mints supply shares and increases `A`'s `total_collateral`. [7](#0-6) 
6. The keeper's `clean_bad_debt` now recomputes:
   ```text
   total_debt > total_collateral
   total_collateral > BAD_DEBT_USD_THRESHOLD
   ```
   so `is_socializable_bad_debt` returns false and the call reverts with `CannotCleanBadDebt`. [3](#0-2) 
7. While the bad debt remains unwritten, the attacker or an accomplice withdraws their ETH supply at the pre-write-down index. Subsequent cleanup or liquidation socializes the remaining loss onto the suppliers who did not exit. [18](#0-17)

/// Admission condition for bad-debt socialization.
#[derive(Clone, Copy, PartialEq)]
enum BadDebtGate {
    /// Permissionless: insolvent *and* collateral at or below the dust threshold.
    DustCapped,
    /// Owner-only: insolvent alone, with no cap on the collateral left behind.
    InsolventOnly,
}

/// Requires open debt and the selected insolvency gate, then cleans up the account.
fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    bad_debt::execute_bad_debt_cleanup(env, &mut cache, account_id, &account, &totals);

/// Asset units by which supplier claims exceed cash + debt (0 if solvent).
pub(crate) fn backing_shortfall(cache: &Cache) -> i128 {
    let supplied_claim = cache.unscale_supply_floor(cache.supplied());
    let outstanding_debt = cache.unscale_borrow_ceil(cache.borrowed());
    let backing = cache.cash().saturating_add(outstanding_debt);
    supplied_claim.saturating_sub(backing).max(0)
}
