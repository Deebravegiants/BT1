### Title
Unauthenticated route venues can inject arbitrary user-authorized token transfers into a signed swap authorization tree - ([File: contracts/swap-aggregator/src/venues/mod.rs](contracts/swap-aggregator/src/venues/mod.rs))

### Summary
`execute_strategy` accepts a fully caller-supplied route whose `pool` address is not allowlisted, then invokes that address as a Phoenix, Sushi, Comet, Aquarius, or Soroswap venue. Because the route executes below `sender.require_auth()`, a malicious venue can request additional `sender` authorization for an unrelated `token.transfer(sender, attacker, amount)`. Transaction simulation records that transfer as an extra child of the user's swap authorization, and a wallet that signs the returned tree authorizes both the intended input pull and the theft. The repository's adversarial test demonstrates this behavior through `swap_collateral`, where a rogue pool drains an unrelated token from Alice while still returning a valid swap output.

### Finding Description
`execute_strategy` decodes caller-controlled `swap_xdr` and passes it to `execute::run` without authenticating the venue addresses embedded in the payload. [1](#0-0) 

`execute::run` calls `sender.require_auth()`, derives `input_token`, `output_token`, and `min_out` from the payload, pulls the measured input, and then executes every decoded route instruction. [2](#0-1) 

`Program::decode` only validates structural bounds: registry lengths, opcode values, index ranges, `Prev` chaining, same-token hops, and weights. It does not validate that `assets[idx_a]` names a known or trusted pool. [3](#0-2) 

For each swap instruction, `execute_op` copies the caller-supplied `assets[op.idx_a]` directly into `SwapHop.pool` and passes that hop to `venues::dispatch_hop`. [4](#0-3) 

`dispatch_hop` then selects only a venue adapter enum and never checks the pool address before dispatching it. [5](#0-4)  Phoenix, for example, invokes the supplied `hop.pool.swap` after registering the router's own token-pull authorization. [6](#0-5)  Sushi and Comet similarly invoke the supplied pool address. [7](#0-6) [8](#0-7) 

A malicious contract used as `hop.pool` can therefore execute arbitrary contract code while the transaction has an active authorization entry for `sender`. If that contract calls `victim_token.transfer(sender, attacker, amount)`, the token contract calls `sender.require_auth()`, causing simulation to add the transfer as a child of the sender's authorization tree. The production router's measured balance checks do not reject this behavior because they only compare the router's `token_in` and `token_out` balances around the hop. [9](#0-8) 

The same issue also affects controller strategy swaps. The controller authorizes only its exact input transfer to the configured router and calls `execute_strategy(controller, amount_in, swap)`, but the account owner's original authorization remains the user-facing tree while route-selected venue code executes below it. [10](#0-9) 

The adversarial fixture proves the authorization behavior: simulation records a rogue pool's `transfer(Alice, attacker, WALLET_BALANCE)` as a sub-invocation of Alice's `swap_collateral` authorization, and the enforced-auth test shows that signing that simulation-produced tree permits the transfer. [11](#0-10) [12](#0-11) 

### Impact Explanation
An attacker can steal arbitrary spendable token balances from a user who submits and signs a malicious route. The stolen assets need not be the swap input, need not be listed by the lending protocol, and are not bounded by `total_in`, `min_out`, controller risk checks, or measured router output. In the demonstrated scenario, Alice's unrelated wallet token balance moves to the attacker while she still receives the expected swap output and the account remains valid. [13](#0-12) 

This is theft of user funds. The malicious pool can preserve a fair-looking route by accepting the authorized input and returning a positive output, so the router's `ZeroOutput`, exact-spend, minimum-output, and controller output checks can all pass. [14](#0-13) [15](#0-14) 

### Likelihood Explanation
Any unprivileged user can reach `execute_strategy` with a caller-supplied payload, and any account owner or active delegate can reach controller routes such as `swap_collateral`. [1](#0-0)  The attacker only needs to deploy or reference a contract that implements the selected venue call and persuade a victim to submit the poisoned route.

The host still requires the victim to sign the enlarged authorization tree, so the attack depends on wallet simulation/signing UX rather than bypassing Soroban authentication outright. However, simulation itself records the malicious transfer under the route authorization, and users or integrations that only verify the root call and nominal input transfer can approve it. [16](#0-15) 

Given the direct theft impact and the requirement for a malicious route plus signed poisoned tree, severity is High.

### Recommendation
Do not allow arbitrary addresses as route venues or pools. Maintain an on-chain allowlist of vetted pool contracts for each venue and require `hop.pool` to be present before `dispatch_hop` invokes it. Governance can manage the list, but ordinary callers should not be able to introduce executable code into a transaction that carries their authorization.

Also enforce a strict authorization-tree policy in every first-party client and document it as mandatory for integrators: a direct `execute_strategy` authorization should contain only the exact input transfer child, and controller strategy authorizations should contain only the expected protocol/controller children. Reject any additional token `transfer`, `approve`, or unknown contract invocation before signing. Client-side validation mitigates user signing risk but does not replace an on-chain venue allowlist for third-party integrations.

### Proof of Concept
The repository already contains an executable proof of the authorization-tree injection in `tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs`. [17](#0-16) 

1. Deploy `RogueHopPool` with `(victim = Alice, wallet_token, to = attacker, amount = Alice's full wallet balance)`. The pool's `swap` implementation reads that plan and calls `wallet_token.transfer(Alice, attacker, amount)`. [18](#0-17) 

2. Construct a route whose `hop_pool` is that contract and whose nominal trade is Alice's listed `USDC` into `ETH`. [19](#0-18) 

3. Have Alice call controller `swap_collateral(caller=Alice, account_id, asset_in=USDC, amount_in=5_000 USDC, asset_out=ETH, swap=poisoned_route)`. [20](#0-19) 

4. Simulate the transaction. Recording mode produces one Alice authorization rooted at `swap_collateral` and containing a child `wallet_token.transfer(Alice, attacker, WALLET_BALANCE)`. [21](#0-20) 

5. Sign and submit that authorization tree. Alice's unrelated wallet-token balance becomes zero, the attacker receives `WALLET_BALANCE`, and Alice's account still receives the expected `ETH` output. [22](#0-21) 

6. The enforcing-mode control confirms this is an authorization-scope failure rather than an unsigned transfer: without the malicious child in Alice's signed tree, the host rejects the rogue transfer and rolls back the swap; with the simulation-produced child present, the same transaction succeeds. [23](#0-22)

    /// Validates every instruction's opcode, mode, and indices before execution begins,
    /// including the `Prev` chain, same-token swaps, and split-weight bounds.
    fn validate(&self, env: &Env, assets_len: u32, amounts_len: u32, weight_count: u32) {
        for i in 0..self.op_count {
            let record = self.raw(i);
            let Some(opcode) = Opcode::from_u8(record[field::OPCODE]) else {
                panic_with_error!(env, Error::InvalidRouteXdr);
            };
            let mode = Mode::from_u8(record[field::MODE]);
            let (idx_a, idx_b, idx_c) = (
                record[field::POOL] as u32,
                record[field::TOKEN_IN] as u32,
                record[field::TOKEN_OUT] as u32,
            );

            // `Prev` is a purely structural link: the predecessor must exist,
            // must have a single output, and that output must be this
            // instruction's input.
            if mode == Mode::Prev {
                if i == 0 {
                    panic_with_error!(env, Error::BrokenTokenChain);
                }
                let previous = self.raw(i - 1);
                let produced = match Opcode::from_u8(previous[field::OPCODE]) {
                    // A swap produces its `token_out`, a mint its share token.
                    Some(Opcode::Swap(_)) => previous[field::TOKEN_OUT],
                    Some(Opcode::Mint) => previous[field::TOKEN_IN],
                    // A burn releases every constituent at once.
                    _ => panic_with_error!(env, Error::BrokenTokenChain),
                };
                if idx_b != produced as u32 {
                    panic_with_error!(env, Error::BrokenTokenChain);
                }
            }
            match mode {
                Mode::Fixed(idx) if idx as u32 >= amounts_len => {
                    panic_with_error!(env, Error::InvalidRouteXdr)
                }
                Mode::Ppm(idx) if idx as u32 >= weight_count => {
                    panic_with_error!(env, Error::InvalidRouteXdr)
                }
                _ => {}
            }

            if idx_a >= assets_len || idx_b >= assets_len {
                panic_with_error!(env, Error::InvalidRouteXdr);
            }
            match opcode {
                Opcode::Swap(_) => {
                    if idx_c >= assets_len {
                        panic_with_error!(env, Error::InvalidRouteXdr);
                    }
                    if idx_b == idx_c {
                        panic_with_error!(env, Error::SameToken);
                    }
                }
                // Liquidity legs spend the full vault balance, so only `Mode::All` is valid.
                Opcode::Burn | Opcode::Mint => {
                    if mode != Mode::All {
                        panic_with_error!(env, Error::InvalidRouteXdr);
                    }
                    if idx_c >= amounts_len {
                        panic_with_error!(env, Error::InvalidRouteXdr);
                    }
                }
            }
        }

pub(crate) fn dispatch_hop(
    env: &Env,
    router: &Address,
    hop: &SwapHop,
    amount_in: i128,
    tokens_cache: &mut Map<Address, Vec<Address>>,
) -> i128 {
    let ctx = HopContext::new(env, router, hop, amount_in);
    let before_in = ctx.input_balance();
    let before_out = ctx.output_balance();

    match hop.venue {
        SwapVenue::Soroswap => soroswap::swap(&ctx),
        SwapVenue::Aquarius => aquarius::swap(&ctx, tokens_cache),
        SwapVenue::Phoenix => phoenix::swap(&ctx),
        SwapVenue::Sushi => sushi::swap(&ctx),
        SwapVenue::CometDex => comet::swap(&ctx),
    };

    let received = ctx
        .output_balance()
        .checked_sub(before_out)
        .unwrap_or_else(|| panic_with_error!(env, Error::ZeroOutput));
    if received <= 0 {
        panic_with_error!(env, Error::ZeroOutput);
    }

    let after_in = ctx.input_balance();
    let spent = before_in
        .checked_sub(after_in)
        .unwrap_or_else(|| panic_with_error!(env, Error::InvalidAmount));
    if spent != amount_in {
        panic_with_error!(env, Error::InvalidAmount);
    }

fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };

        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),

        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
