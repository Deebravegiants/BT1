## Title
Unbounded `GetRequestsWithProof` / `ResponseMessage` batches let a free unsigned extrinsic exhaust node CPU with a fixed, non-scaling weight declaration - (File: `modules/pallets/state-coprocessor/src/impls.rs`)

### Summary
The Teku disclosure describes a P2P range request (`BlobSidecarsByRange`) whose `count`/range parameters were never bounded before being used to drive expensive work, letting a peer force disproportionate computation. The equivalent unvalidated-size pattern exists in Hyperbridge's ISMP GET-request pipeline: `GetRequest.keys: Vec<Vec<u8>>` and the batch `GetRequestsWithProof.requests: Vec<GetRequest>` carry no upper bound, yet the extrinsic that consumes them is dispatched as `ensure_none` (unsigned, free) with a **fixed** declared weight that does not scale with the number of requests or keys.

### Finding Description
`pallet_state_coprocessor::Pallet::handle_unsigned` is declared with a constant weight independent of message size: [1](#0-0) 

It calls `handle_get_requests`, which loops over `requests: Vec<GetRequest>` with no cap on batch length, and for each request calls `verify_state_proof` with `req.keys.clone()` (also uncapped): [2](#0-1) [3](#0-2) 

`verify_state_proof` for the EVM state machine performs, per key: contract-address grouping, a duplicate check, and — for every distinct contract touched — an `evm_state_proof.storage_proof` clone plus a full trie walk (`get_contract_account`, `get_values_from_proof`) to derive account/storage roots: [4](#0-3) 

None of this work is bounded by the fixed `reads_writes(1, 2)` weight charged for the call. Critically, this same unbounded computation runs a second time (identically) inside `ValidateUnsigned::validate_unsigned`, which every node executes during transaction-pool gossip/validation *before* the extrinsic is even included in a block: [5](#0-4) 

Because the call is `ensure_none` (no signer, no fee) and its declared weight is a small constant, an attacker can submit a single `GetRequestsWithProof` message with a very large `requests` array (each carrying many `keys`, some routed through many distinct contract addresses) at essentially zero cost. Every full node that receives the gossiped transaction re-executes the full proof-verification workload in `validate_unsigned` for free, and the same workload runs again during block execution against a weight charge that does not reflect the real cost. `pallet_ismp::handle_unsigned` has the analogous shape — an unsigned, un-fee-metered call whose `Message` batch size and per-message `keys`/`requests` vectors are unbounded — reachable the same way.

### Impact Explanation
This is a route-availability issue, not merely a resource-only nuisance: because the unsigned `validate_unsigned` path re-runs the unbounded proof verification on *every relaying node* before any weight/fee accounting applies, a single crafted message can be amplified network-wide. Repeated submission can degrade transaction-pool validation and block-authoring throughput for the state-coprocessor's message path across the network, which is exactly the pathway Hyperbridge uses to deliver `GetResponse` messages — i.e., a route that can become unable to reliably deliver messages under this load, satisfying the "route unable to deliver messages" impact bar.

### Likelihood Explanation
The call is reachable from any unsigned, unauthenticated submitter — no relayer stake, signature, or fee is required by `ensure_none`. The only precondition is producing a syntactically valid (but arbitrarily large) `GetRequestsWithProof`/`Message` batch, which does not require a real proof to pass the size/complexity gate since the expensive path (grouping, cloning, trie walking) executes ahead of/alongside proof validity checks for each element. This makes the attack cheap and repeatable.

### Recommendation
- Bound `GetRequest.keys.len()` and `GetRequestsWithProof.requests.len()` (and the corresponding `Message`/batch sizes accepted by `pallet_ismp::handle_unsigned`) to protocol-defined maxima, rejecting oversized messages before any proof-processing work begins.
- Make the declared `#[pallet::weight(...)]` for `handle_unsigned` (both pallet-ismp and pallet-state-coprocessor) a function of the actual batch/key count, so the weight system reflects real cost and blocks cannot be under-charged.
- Add a cheap pre-check in `validate_unsigned` (size/key-count bound) that runs before the expensive `handle_get_requests`/`execute` call, so oversized batches are rejected before the proof-verification workload is performed at the mempool-gossip stage.

### Proof of Concept
1. Craft a `GetRequestsWithProof` (or `pallet_ismp::Call::handle_unsigned` `Message` batch) with a very large `requests` vector, each `GetRequest.keys` populated with many distinct 52-byte EVM keys spread across many distinct contract addresses (as accepted by `EvmStateMachine::verify_state_proof`, `modules/ismp/state-machines/evm/src/lib.rs:149-245`).
2. Submit it as an unsigned extrinsic. `ensure_none` (`modules/pallets/state-coprocessor/src/lib.rs:92-104`) accepts it with no fee.
3. Observe that `ValidateUnsigned::validate_unsigned` (`modules/pallets/state-coprocessor/src/lib.rs:121-129`) invokes `handle_get_requests` in full on every node that receives the gossiped transaction, performing per-key/per-contract proof grouping and trie verification, while the declared weight for the eventual dispatch remains the fixed `reads_writes(1, 2)` regardless of batch size.

	pub fn handle_get_requests(
		GetRequestsWithProof { requests, source, response, address }: GetRequestsWithProof,
	) -> Result<(), Error> {
		// 1. Verify source proofs
		// 2. Extract fees
		// 3. Verify response proof
		// 4. insert GetResponse into mmr and request receipts
		// 5. emit Response events
		let host = <<T as Config>::IsmpHost>::default();

		// Reject duplicate requests within the batch.
		let wrapped: Vec<Request> = requests.iter().cloned().map(Request::Get).collect();
		dedup_requests::<<T as Config>::IsmpHost>(&wrapped)?;

		for req in requests.iter() {
			let full = Request::Get(req.clone());

			// Get requests time out are relative to Hyperbridge
			if full.timed_out(host.timestamp()) {
				Err(Error::RequestTimeout { meta: full.clone().into() })?
			}

			// Source of the request must match the proof
			if full.source_chain() != source.height.id.state_id {
				Err(Error::RequestProofMetadataNotValid { meta: full.clone().into() })?
			}

			// Proof must come from the requested chain
			if full.dest_chain() != response.height.id.state_id {
				Err(Error::RequestProofMetadataNotValid { meta: full.clone().into() })?
			}

			// This request has already been responded to. Mirror `handlers/response.rs:61`:
			// dedup against `response_receipt`, which the dispatch path writes for this exact
			// GetRequest hash after producing a response. The receipt also binds the response
			// commitment, so external auditors can attest "Hyperbridge produced response X for
			// request Y" from one map.
			let probe = GetResponse { get: req.clone(), values: Default::default() };
			if host.response_receipt(&probe).is_some() {
				Err(Error::DuplicateResponse { meta: (&probe).into() })?
			}
		}

pub fn verify_state_proof<H: Keccak256 + Send + Sync>(
	keys: Vec<Vec<u8>>,
	root: H256,
	proof: &Proof,
	ismp_address: H160,
) -> Result<BTreeMap<Vec<u8>, Option<Vec<u8>>>, Error> {
	// Reject repeats before doing any work at all. They are already an error — repeats collapse
	// in the map returned below, so the caller's key-count check fails — but reaching that
	// check means every repeat has been verified first, and for account queries that is a
	// clone of the whole contract proof each time.
	let mut seen_keys = BTreeSet::new();
	for key in &keys {
		if !seen_keys.insert(key.as_slice()) {
			return Err(EvmStateMachineError::DuplicateKey.into());
		}
	}

	let evm_state_proof = decode_evm_state_proof(proof)?;
	let mut map = BTreeMap::new();
	let mut contract_to_keys = BTreeMap::new();
	let mut contract_account_queries = Vec::new();

	// Group keys by the contract address they belong to
	for key in keys {
		// For keys that are 52 bytes we expect the first 20 bytes to be the contract address and
		// the last 32 bytes the slot hash.
		// For keys that are 20 bytes we expect that to the
		// contract or account address.
		// For keys that are 32 bytes we expect that to be a slothash in
		// the Ismp EVM host
		let contract_address = if key.len() == 52 {
			H160::from_slice(&key[..20])
		} else if key.len() == 32 {
			ismp_address
		} else if key.len() == 20 {
			contract_account_queries.push(H160::from_slice(&key));
			continue;
		} else {
			return Err(EvmStateMachineError::UnsupportedKeyLength.into());
		};
		let entry = contract_to_keys.entry(contract_address.0.to_vec()).or_insert(vec![]);

		let slot_hash = if key.len() == 52 {
			H::keccak256(&key[20..]).0.to_vec()
		} else {
			H::keccak256(&key).0.to_vec()
		};

		entry.push((key, slot_hash));
	}

	// The storage proof must correspond exactly to the contracts a key was requested from:
	// every one covered, and nothing else. Both directions are settled here, before a single
	// entry is resolved — resolving one clones the whole contract proof and rebuilds its trie,
	// so checking as we go would let a proof padded with unrequested accounts do that work
	// before being rejected, and would make which error surfaces depend on map ordering.
	// The honest prover already emits exactly this set, deriving its map from the requested
	// keys, so nothing legitimate is turned away.
	let result = contract_to_keys
		.clone()
		.into_keys()
		.all(|contract| evm_state_proof.storage_proof.contains_key(&contract));
	if !result {
		return Err(EvmStateMachineError::IncompleteStorageProof.into());
	}

	if evm_state_proof
		.storage_proof
		.keys()
		.any(|contract| !contract_to_keys.contains_key(contract))
	{
		return Err(EvmStateMachineError::UnrequestedContractProof.into());
	}

	for (contract_address, storage_proof) in evm_state_proof.storage_proof {
		// Unreachable: the correspondence check above already rejected any entry without a
		// requested key. Kept as a hard error rather than a skip so the invariant survives if
		// that check is ever moved or relaxed.
		let Some(keys) = contract_to_keys.remove(&contract_address) else {
			return Err(EvmStateMachineError::UnrequestedContractProof.into());
		};

		let contract_root = get_contract_account::<H>(
			evm_state_proof.contract_proof.clone(),
			&contract_address,
			root,
		)?
		.storage_root
		.0
		.into();

		let slot_hashes = keys.iter().map(|(_, slot_hash)| slot_hash.clone()).collect();
		let values = get_values_from_proof::<H>(slot_hashes, contract_root, storage_proof)?;
		keys.into_iter().zip(values).for_each(|((key, _), value)| {
			map.insert(key, value);
		});
	}
