### Title
Trusted/auto-approved origin's icon and name can be silently overwritten without re-consent, enabling identity spoofing while privileges are retained - (File: features/connected-origins/module/connections.js)

### Summary
`ConnectedOrigins#add` and `ConnectedOrigins#updateConnection` both call the private `#setAttributes` helper to merge new `icon`/`name` values into an already-stored, already-trusted origin record without checking or resetting `trusted`/`autoApprove` flags, and without any re-consent/approval step. An attacker-controlled origin can therefore change its displayed icon/name at any time after being trusted, while keeping `trusted: true` and `autoApprove: true`, letting it visually impersonate a different, more-trusted brand for future auto-approved signing requests.

### Finding Description
`add({ origin, name, icon, ... })` in [1](#0-0)  first loads the existing record via `#getOrigin`. If a `value` already exists (i.e., the origin is already known/trusted), it calls `#setAttributes` with `icon: icon ?? value.icon` and `name: name ?? value.name` — meaning any caller-supplied `icon`/`name` unconditionally overwrites the stored values, while `trusted` is preserved only because the caller happens not to override it (`trusted: trusted ?? value.trusted`). Crucially, `autoApprove` is never included in the attribute set passed to `#setAttributes`, so the merge in `#setAttributes` (`{ ...connection, ...attributes }`, [2](#0-1) ) leaves the previously-set `autoApprove: true` untouched on the existing record.

`updateConnection({ origin, icon, connectedAssetName })` is even more direct: [3](#0-2)  looks up the origin, and if any truthy `icon` is supplied, it sets `attributes.icon = icon` and calls `#setAttributes` — with no check of `trusted`, `autoApprove`, or any consent/approval gate at all. This is confirmed by the existing test `updateConnections should update icon` which shows an icon being replaced on an existing record without any additional confirmation step: [4](#0-3) .

The `icon`/`name` values ultimately originate from page-supplied metadata (favicon `<link>` tags and `og:site_name`/`<title>`), extracted in `getIcon`/`getTitle` in [5](#0-4) . Since these values come directly from DOM content the origin controls, they are attacker-influenced content that flows into the trust store's `icon`/`name` fields on every reconnect/update, without a corresponding integrity check tying the new identity metadata to a fresh user approval.

No code path in `#setAttributes`, `add`, or `updateConnection` resets `trusted` or `autoApprove` to `false` when `icon`/`name` change, nor does the module require a fresh approval prompt keyed to identity fields — only `untrust`/`setAutoApprove` explicitly change those flags, and neither is invoked as a side effect of an icon/name change.

### Impact Explanation
An origin that has already earned `trusted: true` and `autoApprove: true` (e.g., a legitimate small dapp the user approved once) can later change its favicon/title to imitate a well-known, more trusted brand's icon/name. Because `trusted`/`autoApprove` persist across this update, subsequent signing requests from that origin will be auto-approved by the wallet UI while displaying the spoofed identity, which is a privilege-retention + identity-spoofing issue directly affecting the approval UX for auto-approved signing. This matches "privilege persistence" combined with "wrong-origin identity/display" impact categories.

### Likelihood Explanation
This requires no privileged wallet state or leaked keys — only that the origin was previously granted trust/autoApprove (a normal one-time dapp connection flow) and that it can later serve different favicon/title metadata (fully within an origin's own control, e.g., by updating its page or via a compromised/rotated dapp deployment on the same origin). The update path (`add`/`updateConnection`) is exposed through the standard `connectedOriginsApi` used by RPC/dapp connection handling [6](#0-5) , making it reachable from ordinary reconnect/update flows. The issue is fully repeatable and deterministic given the code shown.

### Recommendation
In `#setAttributes` (or specifically in `add`/`updateConnection`), detect when `icon` and/or `name` differ from the currently stored trusted values and, if so, either (a) refuse to persist the change without an explicit re-consent/approval call, or (b) automatically demote `trusted`/`autoApprove` back to `false` pending re-approval whenever displayed identity fields change for an already-trusted origin. Consider storing the icon/name values that were actually shown at approval time and validating that any change to those fields on an already-approved origin triggers a fresh permission prompt.

### Proof of Concept
Unit test to add to `features/connected-origins/module/__tests__/connections.test.js`:
```js
test('changing icon on trusted+autoApprove origin should not silently persist without re-consent', async () => {
  await connectedOrigins.add({
    origin: 'legit-dapp.com',
    name: 'Legit Dapp',
    icon: 'legit_icon',
    connectedAssetName: 'ethereum',
    trusted: true,
  })
  await connectedOrigins.setAutoApprove({ origin: 'legit-dapp.com', value: true })

  // Attacker-controlled origin later serves spoofed metadata (e.g. mimicking "Exodus")
  await connectedOrigins.updateConnection({
    origin: 'legit-dapp.com',
    icon: 'exodus_icon_lookalike',
  })

  const origins = await connectedOriginsAtom.get()
  const record = origins.find((o) => o.origin === 'legit-dapp.com')

  // Current (vulnerable) behavior: icon changes AND trust/autoApprove persist
  expect(record.icon).toBe('exodus_icon_lookalike')
  expect(record.trusted).toBe(true)
  expect(record.autoApprove).toBe(true)

  // Expected (fixed) behavior: identity change should require re-consent —
  // e.g. autoApprove/trusted should be revoked, or the update should be rejected
  // until the user re-approves the new identity.
})
```
Expected result on a fixed implementation: the icon/name update on an already-trusted, auto-approved origin either fails without explicit re-consent, or resets `trusted`/`autoApprove` to `false`, rather than silently persisting the new identity with retained privileges as currently happens.

const ICON_MAX_SIZE = 120

const base64 = (buf) => btoa([...buf].map((byte) => String.fromCharCode(byte)).join('')) // eslint-disable-line unicorn/prefer-code-point

export const getTitle = () => {
  const siteName = document.querySelector('head > meta[property="og:site_name"]')

  if (siteName) return siteName.content

  const metaTitle = document.querySelector('head > meta[name="title"]')

  if (metaTitle) return metaTitle.content

  return document.title
}

const getIconSize = (icon) => {
  try {
    const matches = icon.sizes.value.match(/\d+/gmu)
    return parseInt(matches[0], 10)
  } catch {
    return 0
  }
}

const getIconDimensions = (image, size) => {
  const ratio = image.width / image.height

  let width, height, dWidth, dHeight, dx, dy

  if (ratio > 1) {
    width = Math.min(image.width, size)
    dWidth = width
    height = width
    dHeight = Math.round(width / ratio)
    dx = 0
    dy = Math.floor((dWidth - dHeight) / 2)
  } else {
    height = Math.min(image.height, size)
    dHeight = height
    width = height
    dWidth = Math.round(height * ratio)
    dy = 0
    dx = Math.floor((dHeight - dWidth) / 2)
  }

  return { width, height, dWidth, dHeight, dx, dy }
}

const getIconData = (href) => {
  const img = new Image()

  img.crossOrigin = 'anonymous'
  img.src = href

  return new Promise((resolve) => {
    img.addEventListener('load', () => {
      const canvas = document.createElement('canvas')
      const ctx = canvas.getContext('2d')
      const dimensions = getIconDimensions(img, ICON_MAX_SIZE)

      const width = dimensions.width
      const height = dimensions.height

      canvas.width = width
      canvas.height = height

      ctx.drawImage(img, dimensions.dx, dimensions.dy, dimensions.dWidth, dimensions.dHeight)

      const { data } = ctx.getImageData(0, 0, width, height)

      resolve({ width, height, data: base64(data) })
    })

    // If can't compute, enable connecting dapp without icon. UI will render empty state
    img.onerror = () => resolve(null) // eslint-disable-line unicorn/prefer-add-event-listener
  })
}

export const getIcon = async () => {
  const icons = document.querySelectorAll('head > link[rel~="icon"]')
  const sortedIcons = [...icons].sort((a, b) => getIconSize(b) - getIconSize(a))
  const href = sortedIcons[0]?.href || `${document.location.origin}/favicon.ico`

  return getIconData(href)
}
