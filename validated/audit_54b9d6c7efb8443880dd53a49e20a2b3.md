### Title
Attacker-deployed "double-entry" token lets `Hinkal.transact`'s per-index balance check credit shielded UTXO value for a second `erc20TokenAddresses` entry backed by the same real balance as a LiFi swap output — ([File: contracts/Hinkal.sol])

### Summary
`Hinkal.transact` checks solvency **per array index** of `circomData.erc20TokenAddresses`, comparing `balanceOf`-derived `balanceDif` for that index against `amountChanges[i] + utxoAmount[i]` independently for each index. There is no requirement that entries of `erc20TokenAddresses` refer to economically distinct reserves. An attacker can deploy a second token address whose `balanceOf(Hinkal)` mirrors a real token's balance (a "double-entry"/shared-storage token), place it as an extra index alongside the genuine LiFi swap output token, and claim an extra `amountChanges[i]` credit toward a shielded UTXO using the very same real balance increase that already fully backs the swap's on-chain commitment.

### Finding Description
The invariant that should hold is: **for each token address that appears once as a truly distinct reserve, `Σ real balance changes == Σ (amountChanges + on-chain UTXO minted)`.** The code instead enforces this equality independently, index-by-index, over an attacker-controlled array of addresses: [1](#0-0) 

For each `i` in `circomData.erc20TokenAddresses`:
- `balanceDif` is computed from `getBalancesForArray` (a plain `balanceOf(address(this))` snapshot before/after), plus `msg.value` only when `erc20TokenAddresses[i] == address(0)`. [2](#0-1) 
- `utxoAmount` for index `i` is summed only from `utxoSet[j]` entries whose `erc20Address` exactly equals `erc20TokenAddresses[i]`.
- The check requires `balanceDif == (onChainCreation[i] ? 0 : amountChanges[i]) + utxoAmount`.

`ExternalActionSwap.swap` (used by `LifiExternalAction`) performs exactly one real swap and returns a single `UTXO` for the output token: [3](#0-2) , with the actual balance change measured via `getERC20OrETHBalance` on both the router call target and the receiving contract: [4](#0-3) .

Nothing in `dimensionsCheck` or `checkOnchainCreation` restricts `erc20TokenAddresses` to unique, economically independent reserves — it only checks array-length consistency and that `amountChanges[i] == 0` when `onChainCreation[i]` is true: [5](#0-4) . `CircomDataBuilder` likewise treats each `erc20TokenAddresses[i]` as an opaque `uint160` public input with no uniqueness constraint: [6](#0-5) , and repo-wide search found no token whitelist enforcing distinctness.

**Attacker's call:** Deploy a "shared-ledger" token pair — a genuine `TokenA` used as the LI.FI swap's output token, and `TokenB`, a second address whose `balanceOf(addr)` simply forwards to/mirrors `TokenA`'s storage for the Hinkal contract (fully attacker-controlled contract code; no special privilege needed). Build `circomData` with `erc20TokenAddresses = [address(0), TokenA, TokenB]` (ETH leg funds the swap), `externalActionId` = LiFi swap action, `externalActionMetadata` = LI.FI router calldata swapping ETH → `TokenA`.

Exploit flow in `transact`:
1. `oldBalances` snapshot for `[ETH, TokenA, TokenB]`.
2. `_externalTransact` → `swap()` sends ETH to router, receives `X` `TokenA` tokens into Hinkal, returns `utxoSet = [{erc20Address: TokenA, amount: X}]`.
3. `newBalances` snapshot: because `TokenB.balanceOf(Hinkal)` mirrors `TokenA.balanceOf(Hinkal)`, index `TokenB` also shows `balanceDif = X`, even though no distinct `TokenB` tokens ever moved.
4. Loop index `TokenA`: `onChainCreation[TokenA]=true`, `amountChanges[TokenA]=0` (required by `checkOnchainCreation`), `utxoAmount = X` (matches). Check passes: `X == 0 + X`. One legitimate on-chain UTXO of `X` `TokenA` is minted.
5. Loop index `TokenB`: `onChainCreation[TokenB]=false`, attacker sets `amountChanges[TokenB] = X`, `utxoAmount = 0` (no UTXO in `utxoSet` matches `TokenB`). Check passes: `X == X + 0`. This credits the circuit's public input `amountChanges[TokenB] = X`, which the attacker's own ZK proof (private witness, self-generated for their own UTXOs) can satisfy via `inTotal + amountChanges === outTotal` for that token index — producing a real, spendable off-chain shielded output note worth `X` `TokenB`, with no additional real inflow.

Result: two independent shielded claims (`X` `TokenA` on-chain UTXO + `X` `TokenB` off-chain note) are created, backed by only `X` real tokens in a single shared reserve — the protocol becomes insolvent by `X` `TokenB` upon any future withdrawal of the `TokenB`-denominated note.

None of the listed guards catch this: `verifyProof`/circuit constraints only check arithmetic consistency of the attacker's own private inputs per token index, not that `erc20TokenAddresses` entries are economically distinct; `rootHashExists`, `insertNullifiers`, `dimensionsCheck`, `checkOnchainCreation`, and the slippage `require` (`balanceDif >= slippageValues[i]`) all pass because the balances genuinely rose by `X` at both addresses.

### Impact Explanation
The attacker mints shielded value without backing — the exact scenario the balance-diff check exists to prevent. This is a direct insolvency vector: `X` additional shielded `TokenB` tokens are created out of nothing, later redeemable for real assets that don't exist for `TokenB` independently of `TokenA`. This matches **Critical: minting shielded value without backing (protocol insolvency)**. The attack is repeatable per swap transaction and scales with swap size and number of extra "mirrored" token indices the attacker adds to `erc20TokenAddresses`.

### Likelihood Explanation
Preconditions are fully within an unprivileged attacker's control: they can deploy arbitrary token/proxy contracts, construct `CircomData` (including `erc20TokenAddresses`, `amountChanges`, `onChainCreation`, `slippageValues`), generate their own valid ZK proof for their own UTXOs, and choose the LiFi `externalActionMetadata`. No relayer, admin, or victim cooperation is required. Cost is limited to gas and the real swapped amount `X`, which is fully recovered as legitimate `TokenA` UTXO plus the extra minted `TokenB` value — the attack is a net gain, repeatable indefinitely.

### Recommendation
Enforce that `erc20TokenAddresses` entries correspond to distinct, verifiably independent ERC-20 contracts — e.g., require array uniqueness and additionally verify that balance deltas measured across different indices cannot originate from the same underlying storage (not generally solvable via `balanceOf` alone). More robustly, require that any credited `amountChanges[i] > 0` for a token be justified by an explicit, isolated transfer-in of that exact token (as done in `_internalTransact` deposit path via `transferERC20TokenFromOrCheckETH`) rather than by an incidental aggregate balance snapshot, closing the shared-index trust gap for the external-action path.

### Proof of Concept
Foundry test plan:
1. Deploy `TokenA` (standard ERC20) and `TokenB` whose `balanceOf(Hinkal)` reads/forwards to `TokenA`'s balance for that address (shared ledger).
2. Deploy/whitelist `LifiExternalAction` with a mock router that swaps ETH for `X` `TokenA` and transfers it to the caller.
3. Craft `CircomData` with `erc20TokenAddresses = [address(0), TokenA, TokenB]`, `onChainCreation = [false, true, false]`, `amountChanges = [-X_eth_in, 0, X]`, valid nullifiers/commitments and a proof generated locally for the attacker's own UTXO set satisfying circuit arithmetic per index.
4. Call `Hinkal.transact` with `msg.value = X_eth_in`.
5. Assert: `TokenA.balanceOf(Hinkal)` increased by `X` (one real inflow), while shielded value created = `X` (on-chain UTXO for `TokenA`) + `X` (off-chain note for `TokenB`) = `2X`.
6. Assert both sides of the per-index equality hold at each index individually (`balanceDif[i] == amountChanges/onchain-term + utxoAmount[i]`), yet aggregate real reserve (`X`) < aggregate shielded claim (`2X`), confirming insolvency.

    function getERC20OrETHBalance(
        address _erc20TokenAddress
    ) internal view returns (uint256) {
        if (_erc20TokenAddress == address(0)) {
            return address(this).balance;
        } else {
            IERC20 outToken = IERC20(_erc20TokenAddress);
            return outToken.balanceOf(address(this));
        }
    }

    function getBalancesForArrayMemory(

    function swap(
        CircomData calldata circomData,
        int256[] calldata deltaAmounts
    ) internal returns (UTXO[] memory utxoSet) {
        address inputToken = circomData.erc20TokenAddresses[0];
        uint256 inputAmount = uint256(-deltaAmounts[0]);

        if (inputToken == circomData.feeStructure.feeToken) {
            inputAmount -= circomData.feeStructure.flatFee;
        }

        address outputToken = circomData.erc20TokenAddresses[1];

        require(
            circomData.slippageValues[1] != 0,
            "swap output slippage floor not set"
        );

        require(
            block.timestamp <= circomData.timeStamp + SWAP_DEADLINE_WINDOW,
            "swap expired"
        );

        uint256 swappedAmount = callRouter(
            inputToken,
            inputAmount,
            outputToken,
            circomData.externalActionData.externalActionMetadata
        );

        uint256 relayFee = circomData.feeStructure.flatFee;

        uint256 hinkalFee = hinkalHelper.calculateRelayFee(
            swappedAmount,
            0,
            circomData.feeStructure.variableRate
        );

        if (circomData.feeStructure.feeToken == outputToken) {
            sendToRelay(circomData.relay, relayFee + hinkalFee, outputToken);
        } else {
            sendToRelay(
                circomData.relay,
                relayFee,
                circomData.feeStructure.feeToken
            );
            sendToRelay(circomData.relay, hinkalFee, outputToken);
        }

        uint256 totalFee = hinkalFee +
            (outputToken == circomData.feeStructure.feeToken ? relayFee : 0);
        uint256 amountToSendToHinkal = swappedAmount - totalFee;

        transferERC20TokenOrETH(outputToken, msg.sender, amountToSendToHinkal);

        utxoSet = new UTXO[](1);
        utxoSet[0] = UTXO({
            amount: amountToSendToHinkal,
            erc20Address: outputToken,
            stealthAddressStructure: circomData.stealthAddressStructure,
            timeStamp: block.timestamp
        });
    }

    function callRouter(
        address inputToken,
        uint256 inputAmount,
        address outputToken,
        bytes calldata externalActionMetadata
    ) internal override returns (uint256 swappedAmount) {
        uint256 balanceBefore = getERC20OrETHBalance(outputToken);

        if (inputToken == address(0)) {
            (bool success, ) = router.call{value: inputAmount}(
                externalActionMetadata
            );
            require(success, "LI.FI swap failed: native coin");
        } else {
            approveUnlimited(inputToken, router);
            (bool success, ) = router.call(externalActionMetadata);
            require(success, "LI.FI swap failed: erc-20 token");
        }

        swappedAmount = getERC20OrETHBalance(outputToken) - balanceBefore;
    }
