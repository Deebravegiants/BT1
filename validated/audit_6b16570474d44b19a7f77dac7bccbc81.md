### Title

Sustained high-utilization debt can overflow fixed-point accrual and permanently freeze a lending market - (File: `common/src/rates/index.rs`) [1](#0-0) 

### Summary

A market with sufficiently large scaled debt and sustained high utilization can grow `borrowed * borrow_index` beyond `i128::MAX` before `update_borrow_index` reaches its explicit index ceiling. [2](#0-1)   
The next accrual panics inside `calculate_supplier_rewards`, so the market can no longer process repayment, withdrawal, liquidation, revenue claims, or index updates without a contract upgrade. [3](#0-2) [4](#0-3) 

### Finding Description

The pool scales token balances to `RAY` and stores market debt as scaled shares. [5](#0-4)  Every synced market operation loads `Cache`, then calls `interest::global_sync` before mutation. [6](#0-5) 

`global_sync` decomposes elapsed time into bounded chunks and calls `accrue_chunk`, which invokes `accrue_step` using the current scaled borrow balance and both indexes. [7](#0-6)  `update_borrow_index` caps the index itself at `MAX_BORROW_INDEX_RAY`, but that cap does not bound the subsequent debt-value calculation. [8](#0-7) 

`calculate_supplier_rewards` then computes `borrowed * old_borrow_index` and `borrowed * new_borrow_index` as checked `i128` values. [1](#0-0)  When either product overflows, `Ray::mul` surfaces `MathOverflow`, causing `global_sync` and the enclosing operation to revert before state is committed. [9](#0-8) 

The existing test demonstrates the reachable condition: a one-billion-token, 18-decimal market at 98% utilization eventually causes `update_indexes` to fail with `MathOverflow`, while the stored borrow index remains below its configured cap. [10](#0-9)  The same test confirms that subsequent `withdraw` and `repay` calls fail because they accrue first. [11](#0-10) 

### Impact Explanation

This is a permanent denial of service for the affected market absent a privileged contract upgrade: suppliers cannot withdraw, borrowers or third parties cannot repay, and liquidation or cleanup paths that touch the market cannot proceed because they must sync accrued interest first. [6](#0-5) [11](#0-10) 

The failure also blocks ordinary remediation: `update_indexes` loops through `Cache::load` and `global_sync`, while `update_params` first accrues under the old model, so neither path can lower the rate model or advance `last_timestamp` once the debt-value multiplication overflows. [12](#0-11) [13](#0-12) 

### Likelihood Explanation

The exploit requires an unusually large market and sustained high utilization over multiple years, rather than an immediate one-transaction trigger. [14](#0-13)  Nevertheless, the initial state is reachable through the unprivileged `supply` and `borrow` controller entrypoints when configured caps, collateral, and liquidity permit the required size. [15](#0-14)  Once created, the market drifts toward the overflow through normal permissionless `update_indexes` calls; the test reaches it while still below the borrow-index cap. [16](#0-15) [17](#0-16) 

### Recommendation

Bound `borrowed * borrow_index` as a protocol invariant, not merely `borrow_index`, before allowing new debt or before storing index state. [2](#0-1) [3](#0-2) 

Concretely, derive a maximum scaled-debt value from `i128::MAX / MAX_BORROW_INDEX_RAY` and enforce it in borrow and strategy-debt minting, or change accrual to detect a debt-value overflow and clamp both the index and represented debt growth in a non-panicking way. [8](#0-7)  Provide an emergency accrual path that can advance `last_timestamp` without recomputing the overflowing total, so a market is not dependent on a Wasm upgrade for recovery. [18](#0-17) 

### Proof of Concept

1. Create or select an 18-decimal market with a steep rate curve such as the 175% maximum-rate XLM test curve, together with a collateral market. [19](#0-18) 
2. Supply approximately `1_000_000_000 * 10^18` raw units of the debt asset and supply enough collateral to borrow about 98% of it through `Controller::supply` and `Controller::borrow`. [20](#0-19) 
3. Let time advance at sustained high utilization and repeatedly invoke permissionless `Controller::update_indexes(caller, [hub_asset])`. [16](#0-15) [21](#0-20) 
4. `global_sync` calls `accrue_step`; `calculate_supplier_rewards` overflows while evaluating `borrowed * new_borrow_index`, returning `MathOverflow` before the index cap engages. [22](#0-21) [3](#0-2) 
5. Thereafter, `withdraw` and `repay` fail with the same `MathOverflow` because both load an interest-synced market before executing their mutations. [6](#0-5) [11](#0-10)

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}

/// Computes `x * y / d` rounded half up. Requires `x >= 0`, `y >= 0`, and `d > 0`; a
/// `debug_assert` checks this in debug builds. Panics with `GenericError::DivisionByZero` if
/// `d == 0`, and with `GenericError::MathOverflow` if any other precondition is violated or if
/// the result does not fit in `i128`.
pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    // The zero check runs first so debug and release builds agree on a zero
    // divisor: both surface `DivisionByZero` rather than tripping the assert.
    require_nonzero_divisor(env, d);
    debug_assert!(
        x >= 0 && y >= 0 && d > 0,
        "mul_div_half_up: non-negative x, y and positive d"
    );
    try_mul_div_half_up(env, x, y, d)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
}
