## Finding

### Title
Stale `TombStone` record from `object::burn()` allows a past owner to reclaim an object away from its legitimate current owner - (File: `aptos-move/framework/aptos-framework/sources/object.move`)

### Summary
Reducing the external Blend bug to one invariant: **removing/deactivating an entity's privileged state must clear all data that would let it regain authority later; a "soft" deactivation path that fails to reset such state re-enables the old authority once conditions coincidentally realign.** In `object.move`, `burn()`/`unburn()` implement exactly this "removed but state kept" pattern, and only one of the two transfer code paths (`transfer_with_ref`) clears the stale state, while the ordinary ungated `transfer`/`transfer_raw` path does not.

### Finding Description
`object::burn()` performs a *soft* burn: it does not change `ObjectCore.owner`, it only attaches a `TombStone { original_owner }` resource to the object address: [1](#0-0) 

`unburn()` allows reclaiming, with two branches: if the *current* owner calls it, the tombstone is simply dropped; but if the current owner is the special `BURN_ADDRESS`, the function trusts the tombstone's `original_owner` field and transfers the object straight back to that address, without checking that this stored `original_owner` is still meaningful: [2](#0-1) 

The only place in the reviewed code that clears a stale `TombStone` before an ownership change is `transfer_with_ref` (the `LinearTransferRef` path), which explicitly says it must "undo soft burn ... we don't want the original owner to be able to reclaim by calling unburn later": [3](#0-2) 

However, the ordinary ungated transfer entry points (`transfer`, `transfer_call`, `transfer_to_object`, all routed through `transfer_raw`/`verify_ungated_and_descendant`) contain no equivalent tombstone-clearing logic in any of the code paths inspected: [4](#0-3) [5](#0-4) 

This is the same class of bug as the Blend `Backstop` issue: a removal/soft-deactivation operation (`remove_pool` setting `index = i128::MAX`, or here `burn()` attaching a `TombStone`) leaves stale bookkeeping in place, and a *different* code path (`gulp_emissions`/`update_rz_emis_data` there, ordinary `transfer`/`transfer_raw` here) fails to invalidate that stale bookkeeping before the entity's state is later reused, letting a previously-removed/former-authority (`original_owner`) regain control it should no longer have.

### Impact Explanation
Concretely:
1. Owner A calls `object::burn(A, O)`. Ownership of `O` stays with A; `TombStone{original_owner: A}` is attached (this is a documented, intended "hide from indexer, reclaimable" feature).
2. A later legitimately transfers `O` to B via the ordinary `transfer`/`transfer_call` entry function (not via a `TransferRef`). Ownership moves to B, but because this path does not clear `TombStone`, the stale record `{original_owner: A}` remains attached to the object.
3. `burn()` cannot be called again by B while a `TombStone` exists (`assert!(!exists<TombStone>(...))`), so B has no visible warning and no way to "re-tombstone" the object as its own.
4. If the object subsequently ends up owned by `BURN_ADDRESS` through any ordinary ungated transfer (e.g., B or a later owner sends it there, intentionally or via a buggy/careless integration that reuses the legacy burn address as a sink), `unburn`'s second branch fires: it trusts the *stale* tombstone and sends the object back to A — not to whoever actually owned it before it reached `BURN_ADDRESS`.

This corrupts the `ObjectCore.owner` custody field: an address that legitimately lost ownership (A) reclaims custody of an object/token/asset it no longer had any rights to, at the expense of the party that most recently and rightfully owned it. For token objects, NFTs, or any object-held value, this is a direct custody/ownership-reassignment defect matching the "Unauthorized takeover of ... ownership reassignment" and "Supply or custody accounting corruption that moves value to the wrong holder" impact categories.

### Likelihood Explanation
Exploitability depends on an object reaching `BURN_ADDRESS` again after being transferred away following a soft `burn()`, via a normal transfer rather than through `transfer_with_ref`. This is plausible in real usage: `BURN_ADDRESS` is a fixed, well-known constant, so any owner (deliberately or via a UI that reuses it as a "burn" destination) can send an object there through ordinary `transfer`, re-triggering `unburn`'s legacy branch on stale tombstone data. The likelihood is moderate — it requires a chain of at least one soft-burn, one ordinary transfer, and a subsequent send to `BURN_ADDRESS` — but no privileged/admin action is needed at any step, only ordinary owner-signed transfers, which satisfies the "unprivileged root cause" bar.

### Recommendation
- Clear any existing `TombStone` at the object address whenever ownership changes through *any* transfer path (`transfer_raw`, `transfer_to_object`, etc.), not only `transfer_with_ref`, so that a stale `original_owner` can never outlive a legitimate ownership change.
- Alternatively, remove/deprecate the second (`BURN_ADDRESS`)-based branch of `unburn()` entirely, since it is explicitly labeled "the old functionality," and rely solely on the "current owner can drop TombStone" branch, which is the one that self-consistently respects present-day ownership.

### Proof of Concept
Conceptual reproduction (matches the reasoning above; not run against the framework's test harness in this session):
```
// 1. A owns object O.
object::burn(&A_signer, O);                 // TombStone{original_owner: A} attached, owner stays A

// 2. A transfers O to B through the normal ungated path (no TransferRef involved).
object::transfer(&A_signer, O, B_addr);      // owner becomes B; TombStone NOT cleared (bug)

// 3. B (or any later owner) sends O to the fixed BURN_ADDRESS via an ordinary transfer.
object::transfer_call(&B_signer, object_addr, BURN_ADDRESS);

// 4. A calls unburn using the still-existing, stale TombStone.
object::unburn<T>(&A_signer, O);
// unburn() sees object_core.owner == BURN_ADDRESS, and tombstone.original_owner == A -> matches,
// transfers O back to A, even though B was the rightful last owner before O reached BURN_ADDRESS.
```

I was not able to view the complete body of `transfer_raw` in this session (only `transfer`, `transfer_call`, `transfer_to_object`, and `verify_ungated_and_descendant` were retrieved); confirming that absolutely no branch inside `transfer_raw` clears `TombStone` would require reading the full function body, which the index did not return before the tool budget was exhausted. If a Devin session with full repository access shows that `transfer_raw` (or another intermediate helper) already clears `TombStone` on every ownership change, this finding does not hold and should be discarded.

    /// Transfer to the destination address using a LinearTransferRef.
    public fun transfer_with_ref(self: LinearTransferRef, to: address) {
        assert!(!exists<Untransferable>(self.self), error::permission_denied(EOBJECT_NOT_TRANSFERRABLE));

        // Undo soft burn if present as we don't want the original owner to be able to reclaim by calling unburn later.
        if (exists<TombStone>(self.self)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(self.self);
        };

        let object = borrow_global_mut<ObjectCore>(self.self);
        assert!(
            object.owner == self.owner,
            error::permission_denied(ENOT_OBJECT_OWNER),
        );
        event::emit(
            Transfer {
                object: self.self,
                from: object.owner,
                to,
            },
        );
        object.owner = to;
    }

    fun verify_ungated_and_descendant(owner: address, destination: address) {
        let current_address = destination;
        assert!(
            exists<ObjectCore>(current_address),
            error::not_found(EOBJECT_DOES_NOT_EXIST),
        );

        let object = borrow_global<ObjectCore>(current_address);
        assert!(
            object.allow_ungated_transfer,
            error::permission_denied(ENO_UNGATED_TRANSFERS),
        );

        let current_address = object.owner;
        let count = 0;
        while (owner != current_address) {
            count += 1;
            assert!(count < MAXIMUM_OBJECT_NESTING, error::out_of_range(EMAXIMUM_NESTING));
            // At this point, the first object exists and so the more likely case is that the
            // object's owner is not an object. So we return a more sensible error.
            assert!(
                exists<ObjectCore>(current_address),
                error::permission_denied(ENOT_OBJECT_OWNER),
            );

            assert!(
                object.allow_ungated_transfer,
                error::permission_denied(ENO_UNGATED_TRANSFERS),
            );
            current_address = object.owner;
        };

    /// Add a TombStone to the object.  The object will then be interpreted as hidden via indexers.
    /// This only works for objects directly owned and for simplicity does not apply to indirectly owned objects.
    /// Original owners can reclaim burnt objects any time in the future by calling unburn.
    /// Please use the test only [`object::burn_object_with_transfer`] for testing with previously burned objects.
    public entry fun burn<T: key>(owner: &signer, object: Object<T>) {
        let original_owner = signer::address_of(owner);
        assert!(is_owner(object, original_owner), error::permission_denied(ENOT_OBJECT_OWNER));
        let object_addr = object.inner;
        assert!(!exists<TombStone>(object_addr), EOBJECT_ALREADY_BURNT);
        move_to(&create_signer(object_addr), TombStone { original_owner });
    }

    /// Allow origin owners to reclaim any objects they previous burnt.
    public entry fun unburn<T: key>(
        original_owner: &signer,
        object: Object<T>,
    ) {
        let object_addr = object.inner;
        assert!(exists<TombStone>(object_addr), error::invalid_argument(EOBJECT_NOT_BURNT));

        // The new owner of the object can always unburn it, but if it's the burn address, we go to the old functionality
        let object_core = borrow_global<ObjectCore>(object_addr);
        if (object_core.owner == signer::address_of(original_owner)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object_addr);
        } else if (object_core.owner == BURN_ADDRESS) {
            // The old functionality
            let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
            assert!(
                original_owner_addr == signer::address_of(original_owner),
                error::permission_denied(ENOT_OBJECT_OWNER)
            );
            transfer_raw_inner(object_addr, original_owner_addr);
        } else {
            abort error::permission_denied(ENOT_OBJECT_OWNER);
        };
    }
