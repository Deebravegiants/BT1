## Finding

The exact bug class from the report — an unhandled/unprotected call to a Chainlink `latestRoundData()` price feed that only checks staleness but not call-revert (e.g. a deprecated/paused feed) — has a direct analog in this codebase's `SimplexPaymaster`, the permissionless ERC‑4337 paymaster that intent solvers/fillers use to pay gas in stablecoins when submitting bid/fill UserOps.

### Title
Unhandled Chainlink oracle revert in `SimplexPaymaster._getOraclePrice` can permanently DoS stablecoin-sponsored solver UserOps - (File: evm/src/utils/SimplexPaymaster.sol)

### Summary
`SimplexPaymaster._getOraclePrice` calls `AggregatorV3Interface.latestRoundData()` directly with no try/catch, and only guards against stale/non-positive answers, not against the call itself reverting. [1](#0-0) 

### Finding Description
`_getOraclePrice` is invoked from `_tokenPrice` (used by `_fetchDetails`/`getTokenPrice`/`estimateTokenCost`) and from `swapAndDeposit`. None of these wrap the oracle call in try/catch: [2](#0-1) [3](#0-2) 

If either the token/USD or native/USD Chainlink feed reverts outright (deprecated feed, `feedRegistry`-style pause, or any other on-chain revert Chainlink is known to produce — the same class the external report cites), every path that prices the paymaster's gas cost reverts unconditionally. This is reachable by any intent solver whose bid UserOp is delivered on-chain with `paymasterAndData` targeting this paymaster (mode `0x00`/`0x02`), since `_validatePaymasterUserOp` → `_fetchDetails` → `_tokenPrice` → `_getOraclePrice` is on the mandatory validation path for every sponsored UserOp: [4](#0-3) 

This is exactly the code path intent solvers use for gas-sponsored bids: [5](#0-4) 

### Impact Explanation
While the SDK's off-chain paymaster-selection logic (`buildPaymasterAndData`) gracefully falls back to native gas when the *builder* throws before submission, that fallback cannot help an already-signed, already-submitted UserOp whose `paymasterAndData` was built while the oracle was healthy but which lands on-chain after the feed starts reverting — the on-chain validation call reverts unconditionally with no recovery, causing `handleOps` to fail for every op using this paymaster until the feed is fixed. Governance's `swapAndDeposit`, which recycles collected ERC‑20 markup into the EntryPoint deposit, is blocked the same way, which can starve the paymaster's EntryPoint deposit and stop it from sponsoring any solver op on that chain — a chain-wide denial of the stablecoin-gas-sponsorship route for intent solvers for as long as the feed is broken (permanent if the feed is genuinely deprecated, matching Chainlink's own deprecation notices cited in the original report).

### Likelihood Explanation
Chainlink feed deprecations/pauses are a known, externally-triggered, non-malicious event (not an admin/governance/relayer compromise), and the paymaster's own design docs already anticipate "malicious oracle" scenarios without addressing the revert-on-call case, confirming this gap was not considered: [6](#0-5) 

### Recommendation
Wrap `latestRoundData()` (and `decimals()`) in try/catch inside `_getOraclePrice`, and on failure either revert with a distinct, catchable error that off-chain infra can react to, or fail safe by disabling the affected token via the existing `TokenDeactivated`/governance path rather than reverting every pricing call unconditionally. Consider a secondary oracle or a cached last-good price with an explicit circuit breaker, mirroring the mitigation referenced in the original report.

### Proof of Concept
1. Governance registers token `T` with Chainlink feed `F` via `RegisterToken`.
2. Chainlink deprecates/pauses `F`; calls to `F.latestRoundData()` revert.
3. Any UserOp using `T` via SimplexPaymaster (mode `0x00` or `0x02`) reaches `_validatePaymasterUserOp` → `_fetchDetails` → `_tokenPrice` → `_getOraclePrice`, which reverts, so `handleOps` reverts and the intent solver's fill/bid cannot be sponsored.
4. Governance's `swapAndDeposit(T, amountIn)` reverts the same way, so accumulated markup for `T` cannot be recycled into the EntryPoint deposit, and once the deposit is exhausted no UserOp using this paymaster on that chain can be sponsored regardless of token.

    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
