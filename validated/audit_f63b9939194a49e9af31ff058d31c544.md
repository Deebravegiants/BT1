## Title
Consensus reward `update_cost_per_block` does not settle pending block-span rewards before changing the rate, allowing relayers to be overpaid from the treasury - (File: `modules/pallets/consensus-incentives/src/impls.rs`)

### Summary
`pallet-consensus-incentives::calculate_reward` prices the *entire* unrewarded block span for a state machine — from the `LastRewardedHeight` watermark up to `latest_height` — using only the **current** `StateMachinesCostPerBlock` rate. When governance calls `update_cost_per_block` to change the rate, no reward is accrued/settled against the old rate first, so any backlog of un-rewarded blocks that occurred under the old rate is retroactively paid at the new rate.

### Finding Description
`update_cost_per_block` simply overwrites the stored rate and emits an event, without touching `LastRewardedHeight` or paying out anything for the blocks accumulated so far under the old rate: [1](#0-0) 

The reward calculation then always multiplies the whole outstanding span by whatever rate is currently stored: [2](#0-1) 

`calculate_reward` computes `blocks = latest_height - baseline` where `baseline` is the `LastRewardedHeight` watermark (or `previous_height` if the state machine has never been rewarded), then multiplies the whole `blocks` span by the single `block_cost` value read from storage at call time. There is no per-height/rate bucketing and no settlement step performed when the rate itself changes — exactly the same bug class as `LMPVault.setPerformanceFeeBps` in the referenced report, where changing a fee/reward rate without first accruing what is owed under the old rate causes economic loss (there: lost protocol fees; here: overpaid treasury funds).

Because `LastRewardedHeight` only advances when `process_message` actually succeeds in paying a reward (i.e., only when *some* relayer submits a qualifying `ConsensusMessage`), the un-rewarded span for an inactive/rarely-updated state machine can grow arbitrarily large between reward claims — this is entirely normal, permissionless relayer behavior, not privileged action: [3](#0-2) 

### Impact Explanation
If governance raises `cost_per_block` for a state machine (e.g., due to higher expected gas costs), any backlog of blocks accumulated since the last reward claim — potentially spanning a long period at the old, lower rate — gets paid out entirely at the new, higher rate the moment any relayer submits the next qualifying consensus message. This directly overpays from `T::TreasuryAccount`, draining treasury funds beyond what governance intended to allocate for that period. A relayer with knowledge of an impending rate increase (or simply a relayer that is slow/inactive and later happens to submit after a rate hike) captures an inflated reward for historical blocks it did not price under the new rate, at the expense of the treasury. This is a concrete loss of protocol-owned funds triggered by a normal, unprivileged relayer action (delivering a `ConsensusMessage`), not by a malicious admin.

### Likelihood Explanation
Reachable by any relayer through the ordinary, permissionless act of submitting a consensus update (`FeeHandler::on_executed` fires for every processed `Message::Consensus`). No special access is required to trigger the overpayment — only a rate change by governance (a routine parameter update, not malicious governance) combined with a relayer submitting the next update. Given that `LastRewardedHeight` watermarks can lag for extended periods on lower-traffic state machines, and rate updates are an expected operational action, this is straightforward to hit in normal operation, and can be intentionally timed by a relayer for profit.

### Recommendation
Before applying a new `cost_per_block`, settle the reward owed for the currently outstanding span at the *old* rate (i.e., call the equivalent of `calculate_reward`/`process_message` and advance `LastRewardedHeight` to the current `latest_height`) inside `update_cost_per_block`, or track rate changes with their effective height so `calculate_reward` can price each sub-span at the rate that was active for it.

### Proof of Concept
1. Governance sets `StateMachinesCostPerBlock[X] = C0` via `update_cost_per_block`.
2. State machine `X`'s consensus commitment advances by `N` blocks without any relayer submitting a qualifying reward-triggering message (so `LastRewardedHeight[X]` stays at the old watermark) — this is normal/expected when updates for `X` are infrequent.
3. Governance later raises the rate: `update_cost_per_block(X, C1)` with `C1 > C0`. No settlement occurs — `LastRewardedHeight` is untouched (see `modules/pallets/consensus-incentives/src/lib.rs:140-142`).
4. A relayer submits the next consensus `Message` for `X`. `calculate_reward` computes `blocks = latest_height - baseline = N` and reward `= N * C1` (see `modules/pallets/consensus-incentives/src/impls.rs:94-99`), instead of the correct `N * C0` (or a split between `C0` and `C1`).
5. The relayer is paid `N * (C1 - C0)` more than intended, transferred straight out of `T::TreasuryAccount` (`modules/pallets/consensus-incentives/src/impls.rs:53-58`).

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
