### Title
`HyperbridgeLzEndpoint.send()` discards `_refundAddress` and swap-generated excess native ETH is lost, not returned to the paying OApp - (File: sdk/packages/lz-endpoint/contracts/HyperbridgeLzEndpoint.sol)

### Summary
`HyperbridgeLzEndpoint.send()`, the entry point any LayerZero OApp/OFT uses to dispatch a cross-chain message through Hyperbridge, explicitly ignores the caller-supplied `_refundAddress` parameter and always sets `payer: address(this)` when constructing the `DispatchPost`. When the caller pays in native token (`msg.value > 0`), the request is forwarded to `EvmHost.dispatch()`, which swaps up to the full `msg.value` for the exact fee amount via Uniswap V2's `swapETHForExactTokens`. Any unused native ETH refunded by the Uniswap router lands on `EvmHost`, the caller of the swap — never on the LZ endpoint, and never on the OApp/user who actually supplied the `msg.value`. There is no mechanism anywhere in the flow to route this leftover ETH back to `_refundAddress` (or to the OApp/`msg.sender`) as LayerZero's own `send(params, refundAddress)` contract requires.

### Finding Description
`send()` is declared as:
```solidity
function send(
    MessagingParams calldata _params,
    address /* _refundAddress */
) external payable override whenNotPaused returns (MessagingReceipt memory) {
``` [1](#0-0) 

The parameter is commented out and unused for the rest of the function body. The constructed `DispatchPost` always hard-codes `payer: address(this)`:
```solidity
DispatchPost memory request = DispatchPost({
    dest: dest,
    to: abi.encodePacked(address(this)),
    body: body,
    timeout: 0,
    fee: relayerFee(_params.dstEid),
    payer: address(this)
});

if (msg.value > 0) {
    IDispatcher(_host).dispatch{value: msg.value}(request);
``` [2](#0-1) 

When `msg.value > 0`, `EvmHost.dispatch()` swaps native token for exactly `post.fee` worth of `feeToken`, using the full `msg.value` as the maximum input:
```solidity
function dispatch(DispatchPost memory post) external payable notFrozen returns (bytes32 commitment) {
    if (msg.value > 0) {
        address[] memory path = new address[](2);
        address uniswapV2 = _hostParams.uniswapV2;
        path[0] = IUniswapV2Router02(uniswapV2).WETH();
        path[1] = feeToken();
        IUniswapV2Router02(uniswapV2).swapETHForExactTokens{value: msg.value}(
            post.fee, path, address(this), block.timestamp
        );
``` [3](#0-2) 

`swapETHForExactTokens` on a standard Uniswap V2 router refunds any leftover ETH (`msg.value - amountIn`) to the immediate caller of the router — which is `EvmHost`, not `HyperbridgeLzEndpoint` and not the original OApp/user. `EvmHost.dispatch()` has no logic afterward to forward that leftover ETH anywhere; it is simply absorbed into the contract's native balance. Because the `_refundAddress` parameter that LayerZero's own interface (`ILayerZeroEndpointV2.send`) mandates for exactly this purpose is discarded at the entry point, there is no code path capable of returning the excess gas to the payer, matching the external report's root-cause pattern: refund address for excess cross-chain gas payment is not propagated to the correct address and the funds are effectively lost to the contract that happens to hold them at the time of the swap.

This differs from the mdx-documented ISMP-level relayer-fee refund (`payer` refunded on `PostRequestTimeout`), because here `timeout: 0` is always used for LZ-adapter dispatches, so that refund path never triggers, and even if it did, `payer: address(this)` means the "refund" would return the fee token to the endpoint contract, not to the OApp or its user.

### Impact Explanation
Any OApp/OFT that overpays native gas when calling `send()` — e.g. via LayerZero SDK quoting behavior that intentionally requests generous headroom, or the endpoint's own `quote()` which explicitly returns a "2x buffer" native fee estimate — will have its excess native ETH permanently stuck in `EvmHost`'s balance rather than refunded to the user who paid it. Given the quote function itself instructs callers to send up to double the required fee ("Excess native is refunded by the uniswap router" per its own comment, incorrectly assuming the refund reaches the user), this loss will recur systematically across many transactions, not just edge cases. This is a direct, reproducible loss of user funds (native ETH) with no recovery path exposed in the contract, matching Medium severity for permanent freezing/loss of funds via an unprivileged cross-chain messaging path.

### Likelihood Explanation
Likelihood is Medium-to-High: it happens whenever a user or integrated OApp supplies more native ETH than the exact relayer fee requires — which is the expected/recommended pattern given the endpoint's own `quote()` returns a 2x buffered estimate specifically to be used as `msg.value` for `send()`. Every native-fee LZ send through this adapter using the documented quote will trigger this loss.

### Recommendation
Restore proper use of the `_refundAddress` parameter in `send()`:
1. Do not discard `_refundAddress`; validate and store it (or use `msg.sender`/the OApp) as the intended refund recipient.
2. After computing how much native ETH is actually consumed by the fee swap, refund the unused `msg.value` (i.e., `msg.value - amountUsed`) directly to `_refundAddress`, either by having `EvmHost.dispatch()` return the actual amount spent so the endpoint can forward the difference, or by having `EvmHost.dispatch()` accept and use a refund address itself and forward leftover ETH there via a low-level call.
3. Do not hardcode `payer: address(this)`; use the OApp-provided refund address consistently for both the fee-token-timeout-refund path and the native-ETH excess-refund path.

### Proof of Concept
1. Owner configures `HyperbridgeLzEndpoint` with `setEidMapping` and `setRelayerFee`/`setDefaultRelayerFee`.
2. An OApp calls `quote(params, sender)` with `payInLzToken == false`; the endpoint returns `nativeFee = quote(request) * 2` as documented at [4](#0-3) .
3. The OApp calls `send(params, refundAddress)` with `msg.value == nativeFee` (2x the real fee), as instructed by the quote.
4. Inside `send()`, `_refundAddress` is discarded and `dispatch{value: msg.value}(request)` is called on `EvmHost`.
5. `EvmHost.dispatch()` swaps only `post.fee` worth of native ETH via `swapETHForExactTokens{value: msg.value}(post.fee, ...)`; the router refunds the ~50% excess ETH to `EvmHost` itself.
6. No code in `EvmHost.dispatch()` or `HyperbridgeLzEndpoint.send()` forwards that leftover ETH to `refundAddress` or to the OApp/user; it remains permanently in `EvmHost`'s balance, unrecoverable by the user who overpaid.
