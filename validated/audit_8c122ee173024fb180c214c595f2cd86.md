Spot-price Uniswap V4 pool pricing without TWAP/impact protection exposes Simplex intent solver to sandwich attacks - (File: `sdk/packages/simplex/src/strategies/fx.ts`, `sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts`)

### Summary
The Simplex intent-solver's `FXFiller` prices "venue" (curveless) pairs directly off a Uniswap V4 pool's instantaneous `sqrtPriceX96` mid, exactly the class of bug described in the external H-05 report (spot price used for slippage/pricing decisions instead of a manipulation-resistant TWAP/oracle source). An attacker who submits a cross-chain intent order for a venue-priced pair can move the pool's spot price immediately before the solver reads it, causing the solver to quote and fill the order at a manipulated rate.

### Finding Description
`resolveLegRates` in `sdk/packages/simplex/src/strategies/fx.ts` prices any curveless pair whose `token0` is a USD stable directly from `venueUsdPrice`, which resolves to `UniswapV4FundingPlanner.getExoticTokenPrice` → `computeDirectPoolPriceUsd`: [1](#0-0) 

This returns the **raw pool mid** derived straight from the pool's current `sqrtPriceX96` (via `sdkPool.token0Price`/`token1Price`), with no TWAP, no size/impact term, and the pool's own fee tier stored but never applied to the price, as the project's own internal documentation confirms: [2](#0-1) 

The only defense against a bad quote is `checkPriceGuard`, which merely bounds the quote's deviation from a **static, operator-configured reference price** — it does not account for execution cost or the fact that the solver itself must later swap through this same pool to source inventory: [3](#0-2) [4](#0-3) 

Critically, `referencePrice`/`maxDeviationBps` are **optional** — a chain can be left entirely unguarded (`vault.uniswapV4: a position price guard needs both... or neither`), and even when configured, the band only rejects gross mispricing relative to a stale operator-set number, not a price manipulated within that band: [5](#0-4) [6](#0-5) 

This is directly analogous to the H-05 pattern: a spot-price read from an AMM pool is used, unmediated by a TWAP/oracle, to determine the amount of tokens the protocol-side actor (here, the intent solver rather than `PositionInteractionFacet`) commits to a swap/fill.

### Impact Explanation
An intent order submitted by any unprivileged user is the trigger for this pricing path (`canFill`/order-filling flow in `fx.ts`). By front-running the solver's price read with a large swap in the configured Uniswap V4 pool (or via a flash-loan-funded trade), an attacker can push the pool mid within the allowed deviation band and obtain a more favorable fill rate than the pool's true liquidity-weighted price would support, then reverse the manipulation after the fill. Because the solver later must itself swap through that same pool to source the exotic token inventory (per the documented flow), it pays the real price-impact/fee cost that was never included in the quote given to the attacker, resulting in a direct funds loss to the solver on each such fill. Repeated exploitation could drain solver-funded liquidity used for cross-chain order fulfillment.

### Likelihood Explanation
Likelihood is Medium: it requires the targeted pair to be venue-priced (curveless, `token0` a USD stable) and either have no price guard configured or a guard band wide enough to allow profitable manipulation — both are legitimate, documented, non-default configurations that operators are expected to use for "exotic" tokens lacking curve data, and the attack only needs a single flash-loan-capable transaction plus a submitted intent order.

### Recommendation
Do not price fills solely from the pool's instantaneous `sqrtPriceX96`. Use a TWAP over a sufficiently long window (or an external oracle) for `computeDirectPoolPriceUsd`, and additionally factor the pool's fee tier and expected price impact of the solver's own sourcing swap into the quoted rate, rather than relying only on a static-reference deviation guard.

### Proof of Concept
1. Operator configures a venue-priced pair (e.g., `USDC/CNGN`) with `[vault.uniswapV4]` pointing at a low/medium-liquidity pool, either without `referencePrice`/`maxDeviationBps`, or with a guard band (e.g., 200 bps) wide enough to contain manipulation.
2. Attacker submits a large trade against the pool (optionally flash-loan funded) that shifts `sqrtPriceX96` toward a rate favorable to the attacker but still inside the guard band.
3. Attacker immediately submits a cross-chain intent order for the venue-priced pair; `resolveLegRates` → `getExoticTokenPrice` → `computeDirectPoolPriceUsd` reads the manipulated spot mid and `checkPriceGuard` passes since the move is within the configured band.
4. The FXFiller fills the order at the manipulated rate; attacker reverses their pool trade, and the solver is left to source the promised output token at the pool's real, worse-impacted price via `UniswapV4FundingPlanner.planWithdrawalForToken`, realizing a loss equal to the manipulated spread plus the unpriced fee/impact cost.

		}

	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {
			this.logger.warn(
				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
	}

## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.

```toml lineNumbers
[vault.uniswapV4]
# referencePrice is the expected cNGN per USD;
# reject if the quote is more than 2% off.
# The two go together — one without the other is rejected.
[[vault.uniswapV4.positions]]
chain           = "EVM-8453"
tokenId         = "2087350"
referencePrice  = "1575"
maxDeviationBps = 200
```
