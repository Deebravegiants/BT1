## Title
Stale `TombStone` survives ordinary object transfers, letting a former owner reclaim an object sent to the burn address — (File: `aptos-move/framework/aptos-framework/sources/object.move`)

## Summary
`object::burn` marks an object as (soft) burnt by attaching a `TombStone { original_owner }` resource without moving ownership [1](#0-0) . The paired `object::unburn` function combines two very different recovery behaviors under one control-flow branch selected by the *current* owner field [2](#0-1) : (1) the current owner simply clears the tombstone, or (2) if the object currently sits at the fixed `BURN_ADDRESS`, the address recorded in the tombstone is restored as owner. The only place that proactively clears a stale `TombStone` on ownership change is the `LinearTransferRef`-based `transfer_with_ref` path [3](#0-2) . Ordinary transfers (`transfer`, `transfer_to_object`, `transfer_raw`, all routed through `transfer_raw_inner`) never touch `TombStone` [4](#0-3) . This asymmetry lets a previous owner's tombstone survive a legitimate sale/transfer and later be used to reclaim the object from a new owner.

## Finding Description
1. Owner **A** calls `object::burn(A, obj)`. This only requires `A` to be the current owner and that no `TombStone` already exists; it moves `TombStone { original_owner: A }` into the object and does **not** change `ObjectCore.owner` [1](#0-0) . Ungated transfer is untouched, so the object is still freely transferable.
2. **A** later sells/transfers this (soft-burnt/hidden) object to **B** using the normal entry points `object::transfer`/`object::transfer_to_object`/`object::transfer_raw`. These all funnel into `transfer_raw_inner`, which only updates `ObjectCore.owner` and emits an event — it performs no `TombStone` cleanup [5](#0-4) . The stale `TombStone { original_owner: A }` remains attached to the object even though **B** is now the legitimate owner.
3. **B**, now owning the object, cannot call `object::burn` again to "reset" the tombstone because it aborts when a `TombStone` already exists (`assert!(!exists<TombStone>(object_addr), EOBJECT_ALREADY_BURNT)`) [6](#0-5) . If **B** wants to genuinely dispose of the object (a common, expected action — sending unwanted assets to the canonical burn address), the only avenue is a raw transfer: `object::transfer(B, obj, BURN_ADDRESS)`. `transfer_raw` places no restriction on the destination address being a real object, so this succeeds and sets `ObjectCore.owner = BURN_ADDRESS` [4](#0-3) [7](#0-6) .
4. **A** (the original burner, who no longer owns the object) calls `object::unburn(A, obj)`. `exists<TombStone>` is true. `ObjectCore.owner == BURN_ADDRESS`, so the code takes the "old functionality" branch: it checks `TombStone.original_owner (A) == signer::address_of(caller) (A)` — which trivially passes because the stale tombstone still names A — and calls `transfer_raw_inner(object_addr, A)`, restoring ownership to **A** [8](#0-7) .

The root cause is that `unburn`'s dual-purpose logic (self-unhide vs. BURN_ADDRESS-restore) is gated only on the *current* owner value and a *tombstone field that is never invalidated by ordinary transfers*, rather than being tied to the party that actually controls the object at burn time.

## Impact Explanation
This breaks the custody invariant that "object transfer, burn, and ownership refs must preserve the intended controller." A party (A) can regain ownership of a token/object it has already sold or given away, as soon as the new legitimate owner (B, or any subsequent owner in a chain of ordinary transfers) performs the normal, expected action of sending the object to the canonical burn address. Since NFTs/objects can represent arbitrary value (game items, RWAs, wrapped assets held as objects, etc.), this is an owner-reassignment / theft primitive: the current, rightful owner's intent to destroy/burn the asset is silently redirected back to a stale prior owner. This qualifies as "Object creation, transfer, burn, extensibility, and ownership refs must preserve the intended controller" and "Permanent lock or non-recoverable loss ... " is inverted here into an unauthorized recovery by the wrong party.

## Likelihood Explanation
The vulnerable path uses only public, unprivileged entry functions available to any account: `object::burn`, `object::transfer`/`transfer_to_object`/`transfer_raw`, and `object::unburn`. No admin, governance, or leaked-key assumption is required. The scenario (an object being soft-burnt/hidden, then later sold, then eventually sent to the burn address by a subsequent owner) is a realistic marketplace/NFT flow, especially since `burn()` being blocked once a stale tombstone exists effectively pushes downstream owners toward the raw-transfer-to-BURN_ADDRESS path.

## Recommendation
Clear any existing `TombStone` whenever ownership changes through the non-`TransferRef` paths as well, i.e., invalidate/remove `TombStone` inside `transfer_raw_inner` (or at minimum in `transfer_raw`/`transfer`) exactly as is already done in `transfer_with_ref` [9](#0-8) . Alternatively, bind reclaim eligibility to the actual owner at the time of the *specific* burn-to-`BURN_ADDRESS` action rather than a persisted `original_owner` field that can outlive intervening ownership changes.

## Proof of Concept
```
// Pseudocode using Move test harness semantics
let (ctor, obj) = object::create_object(...);          // owner = A
object::burn(&A, obj);                                  // TombStone{original_owner: A}, owner still A

object::transfer(&A, obj, address_of(&B));               // owner -> B, TombStone untouched (stale)

// B cannot re-burn (already exists<TombStone>), so B disposes normally:
object::transfer_raw(&B, object_address(obj), BURN_ADDRESS); // owner -> BURN_ADDRESS

// A steals it back:
object::unburn(&A, obj);
// exists<TombStone> == true
// ObjectCore.owner == BURN_ADDRESS  -> "old functionality" branch
// TombStone.original_owner (A) == address_of(A)  -> passes
// transfer_raw_inner(obj, A)  => owner is now A again, not B or burned.
assert!(object::owner(obj) == address_of(&A), 0); // succeeds: A regained the object B sent to burn
```

```text
    inline fun transfer_raw_inner(object: address, to: address) {
        let object_core = borrow_global_mut<ObjectCore>(object);
        if (object_core.owner != to) {
            event::emit(
                Transfer {
                    object,
                    from: object_core.owner,
                    to,
                },
            );
            object_core.owner = to;
        };
    }
```

```text
    public entry fun unburn<T: key>(
        original_owner: &signer,
        object: Object<T>,
    ) {
        let object_addr = object.inner;
        assert!(exists<TombStone>(object_addr), error::invalid_argument(EOBJECT_NOT_BURNT));

        // The new owner of the object can always unburn it, but if it's the burn address, we go to the old functionality
        let object_core = borrow_global<ObjectCore>(object_addr);
        if (object_core.owner == signer::address_of(original_owner)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object_addr);
        } else if (object_core.owner == BURN_ADDRESS) {
            // The old functionality
            let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
            assert!(
                original_owner_addr == signer::address_of(original_owner),
                error::permission_denied(ENOT_OBJECT_OWNER)
            );
            transfer_raw_inner(object_addr, original_owner_addr);
        } else {
            abort error::permission_denied(ENOT_OBJECT_OWNER);
        };
    }
```
