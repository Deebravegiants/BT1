### Title
`TokenExchange.exchange_token` sends the app's `client_secret` to a host derived from an unvalidated JWT `dest` claim - ([File: lib/shopify_api/auth/token_exchange.rb])

### Summary
`ShopifyAPI::Auth::TokenExchange.exchange_token` builds the `Session` used to reach Shopify's `/admin/oauth/access_token` endpoint directly from the session token's `dest` claim, without ever passing it through `ShopifyAPI::Utils::ShopValidator.sanitize!`. Every other credential-bearing flow in the same file (`migrate_to_expiring_token`) explicitly sanitizes the shop value with `ShopValidator.sanitize!` before using it to build the outbound request host. `exchange_token` skips that step, so the host that receives the app's `client_id`/`client_secret` is bound only to whatever string is present in the JWT `dest` claim, not to a verified Shopify-owned domain.

### Finding Description
`JwtPayload#initialize` verifies the token's signature and only checks `aud == Context.api_key`; it performs no validation of `iss`/`dest` against the list of trusted Shopify domains: [1](#0-0) 

`JwtPayload#shop` simply strips the `https://` prefix from `dest` and returns it verbatim: [2](#0-1) 

`TokenExchange.exchange_token` takes this unvalidated `dest_shop` and uses it directly to build the `Session`/`HttpClient` that performs the token-exchange POST containing `client_id` and `client_secret`: [3](#0-2) 

Compare this to `migrate_to_expiring_token` in the same module, which explicitly binds the shop value to a trusted Shopify domain via `Utils::ShopValidator.sanitize!` before building the identical credential-bearing request: [4](#0-3) 

`ShopValidator.sanitize!`/`sanitize_shop_domain` exist precisely to enforce the identity binding `resolved_host == one_of(TRUSTED_SHOPIFY_DOMAINS ∪ myshopify_domain)`: [5](#0-4) 

The library's own `HttpClient`/`Oauth` code shows the established pattern of turning a bare `shop` string directly into the request host (`"https://#{shop}/admin"`), which is the same mechanism `exchange_token`'s `Clients::HttpClient.new(session: shop_session, ...)` relies on: [6](#0-5) 

The break in identity binding is: `equality that should hold = request_host(dest_claim) == trusted_shopify_domain`, but the code only enforces `aud == api_key`; it never enforces `dest ∈ TRUSTED_SHOPIFY_DOMAINS`. Any value that ends up in the signed `dest` claim (which is populated by the party generating the session token for the embedded surface, and can reflect the top-level host the surface believes it's embedded in) is trusted as the destination host for the client_secret-bearing HTTP request.

### Impact Explanation
If a session token can be obtained whose `dest` claim resolves to a non-Shopify host (e.g., a merchant/attacker-controlled custom domain or embedding context not restricted to `*.myshopify.com`/`*.shopify.com`/`*.myshopify.io`/`*.spin.dev`/`*.shop.dev`), `exchange_token` will send the app's `client_id` and `client_secret` to that host — an SSRF that exfiltrates the app's OAuth client credentials to an attacker-controlled server. This maps to the High-severity "SSRF with the app's credentials" / "credential leakage" category, since the compromise of `client_secret` allows full impersonation of the app for every merchant (a Critical-adjacent outcome through this High-classified vector).

### Likelihood Explanation
The signature/`aud` check prevents outright JWT forgery, so exploitation requires a scenario where the token-issuing surface can be influenced to populate `dest` with a value outside the trusted domain set (this is exactly the threat `ShopValidator` was introduced to close, and is already treated as security-relevant by the sibling `migrate_to_expiring_token` method). The inconsistency — one method in the same file sanitizes, the other does not — indicates this is a maintenance gap rather than an intentional design choice, and it is the closest reachable analog to the report's "trusted value acted upon without being bound" bug class.

### Recommendation
In `exchange_token`, sanitize `dest_shop` the same way `migrate_to_expiring_token` does before constructing `shop_session`:
```ruby
validated_shop = Utils::ShopValidator.sanitize!(jwt_payload.shop, myshopify_domain: ShopifyAPI::Context.host_name)
shop_session = ShopifyAPI::Auth::Session.new(shop: validated_shop)
```
so that the host receiving `client_id`/`client_secret` is provably bound to a trusted Shopify domain, consistent with the rest of the module.

### Proof of Concept
1. Obtain/construct a session token whose payload has a valid signature (via the real `api_secret_key`) but whose `dest` claim is set to a value that resolves outside `ShopValidator::TRUSTED_SHOPIFY_DOMAINS` (e.g. through an embedding/session-token-issuance surface that lets the destination host reflect the current top-level frame's host rather than a canonicalized `*.myshopify.com` value).
2. Call `ShopifyAPI::Auth::TokenExchange.exchange_token(session_token: token, requested_token_type: ...)`.
3. `jwt_payload.shop` returns the attacker-influenced `dest` value unchanged; `shop_session = Session.new(shop: dest_shop)` is built without calling `ShopValidator.sanitize!`.
4. `Clients::HttpClient.new(session: shop_session, base_path: "/admin/oauth")` issues the POST containing `client_id`/`client_secret` to a host derived from `dest_shop`, sending the app's OAuth credentials to the attacker-controlled host instead of Shopify.

        [
          "shopify.com",
          "myshopify.io",
          "myshopify.com",
          "spin.dev",
          "shop.dev",
        ].freeze,
        T::Array[String],

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end
