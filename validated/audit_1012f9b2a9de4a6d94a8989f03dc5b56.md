### Title

Sustained high-utilization whale market permanently freezes withdrawals, repayments, and liquidations through RAY value overflow - (File: `contracts/pool/src/cache/scale.rs`)

### Summary

A market whose scaled debt grows beyond the `i128` RAY-value ceiling during interest accrual enters an unrecoverable reverting state. `update_indexes` is permissionless and forwards caller-selected `HubAssetKey`s to the pool, while every pool mutation loads a synced market that first runs `global_sync`. Once accrual overflows while valuing scaled borrow shares, subsequent supply, borrow, withdraw, repay, liquidation, cleanup, and revenue operations touching that market revert. The regression test demonstrates the exact cliff: after sustained 98% utilization on an 18-decimal market, `update_indexes`, `withdraw`, and `repay` all fail with `MathOverflow` while the borrow index remains below the configured index ceiling.

### Finding Description

The controller exposes `update_indexes(caller, assets)` as a permissionless signed entrypoint and invokes the pool for each supplied `HubAssetKey`. [1](#0-0)  The controller implementation only requires caller authorization before forwarding the assets to `pool_update_indexes_call`. [2](#0-1) 

In the pool, `update_indexes` calls `ops::market::accrue`, which loads each market and invokes `interest::global_sync` before committing. [3](#0-2) [4](#0-3)  Ordinary pool mutations use the same prerequisite: `synced_market` loads the `Cache` and calls `global_sync` before the requested operation. [5](#0-4) 

`global_sync` repeatedly compounds interest in chunks up to `MAX_COMPOUND_DELTA_MS` until the elapsed time has been consumed. [6](#0-5)  During utilization calculation, the stored scaled borrow and supply totals are converted back to value by `scaled_to_original`, which performs `scaled.mul(env, index)`. [7](#0-6)  That helper performs the multiplication directly and does not clamp the resulting value. [8](#0-7) 

The index ceilings are independent bounds: `MAX_BORROW_INDEX_RAY` is `1e36`, while a market can hold enough scaled shares that multiplying by a much smaller index still exceeds the maximum representable `i128` value. [9](#0-8)  The repository’s regression test constructs one billion 18-decimal units of supply and debt at 98% utilization, advances time until the next accrual overflows, and confirms that the borrow index is still below `MAX_BORROW_INDEX_RAY`. [10](#0-9)  The same test then confirms that both withdrawal and repayment revert with `MathOverflow`. [11](#0-10) 

### Impact Explanation

This is a permanent freezing of all funds in the affected market and a protocol-wide availability failure for every operation that must sync that market. Suppliers cannot withdraw, borrowers cannot repay, liquidators cannot resolve distressed positions, revenue cannot be claimed, and public index synchronization cannot complete. Because interest state remains committed only up to the last successful timestamp, later calls encounter an even larger elapsed interval and repeat the same overflow rather than recovering.

The resulting market can also accumulate unliquidatable bad debt as collateral prices change because liquidation paths depend on the same accrual-first market cache. That converts a local arithmetic failure into possible protocol insolvency, although the guaranteed impact is permanent freezing of supplier and borrower funds in the affected book.

### Likelihood Explanation

Likelihood is constrained by the capital and market conditions required. An unprivileged user can reach the failing path through ordinary `supply`, `borrow`, and `update_indexes` calls, but triggering the cliff requires an extremely large scaled position and sustained high utilization long enough for index growth to push the product over `i128::MAX`. The demonstrated configuration uses one billion 18-decimal whole units at 98% utilization, so this is not a cheap single-transaction attack. [12](#0-11) 

Nevertheless, no privileged call is needed to trigger the final failure once those market conditions exist: `update_indexes` accepts caller-selected markets and only requires the caller’s signature. The vulnerable arithmetic is on the mandatory shared accrual path rather than in an optional view, making the condition unavoidable after it is crossed.

### Recommendation

Make every accrual path value-overflow safe before mutating indexes. In particular:

- Compute utilization with widened `I256` arithmetic or a saturating/checked intermediate representation rather than requiring `scaled * index` to fit in `i128`.
- Enforce a lower effective market-state ceiling that guarantees `supplied * supply_index` and `borrowed * borrow_index` remain representable.
- Add a fail-safe cap or utilization check before index growth can make the market permanently uncallable.
- Add regression coverage using the existing whale-market test shape to prove `update_indexes`, `withdraw`, `repay`, and liquidation remain executable near both index and value limits.

### Proof of Concept

1. Create an 18-decimal market with a steep interest-rate curve and a separate collateral market.
2. Supply one billion whole units of the debt asset, provide sufficient collateral, and borrow 98% of the supplied amount, matching the regression setup. [12](#0-11) 
3. Allow sustained high-utilization interest to accrue across yearly chunks.
4. Call permissionless `Controller.update_indexes(caller, [debt_hub_asset])`.
5. Accrual calls `global_sync`; utilization converts scaled debt by `scaled_to_original`, whose multiplication exceeds `i128::MAX` and reverts with `MathOverflow`. [13](#0-12) [8](#0-7) 
6. Subsequent `withdraw` and `repay` calls also revert because they call `synced_market` and repeat accrual before processing the operation. [14](#0-13) 
7. The existing test pins this terminal state: `update_indexes`, `withdraw`, and `repay` fail with `MathOverflow`, and the stored index never reaches the index cap that would otherwise bound growth. [15](#0-14)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
