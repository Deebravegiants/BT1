### Title
Unprivileged theft of Emporium-held ERC20/ETH via the zero-token "Min" proof path bypassing all balance accounting - (contracts/CircomDataBuilder.sol / contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol)

### Summary
`formInputForCircom` routes any transaction with `externalActionId == HINKAL_EMPORIUM_ACTION_ID` and `erc20TokenAddresses.length == 0` to `formInputEmporiumMin`, a circuit that only proves `message == Poseidon(messageSeed)` and constrains nothing about the `EmporiumStack` ops. Because `erc20TokenAddresses` is empty, every balance-accounting loop in `Hinkal.transact` and `EmporiumUpgradeable.runAction` iterates zero times, so an attacker can supply an `EmporiumStack` with `signerAddress == address(0)` (which skips the EIP-712 signature check entirely) containing an arbitrary `op.endpoint.call(op.callData)`, e.g. a direct `ERC20.transfer(attacker, balance)` on any token the Emporium contract happens to hold, with zero accounting or authorization.

### Finding Description
The broken equality is:

`assets Emporium can move in a tx` == `assets accounted for in balancesBefore/balancesAfter (Σ over circomData.erc20TokenAddresses)`

**Path to the bug:**

1. `formInputForCircom` selects the trivial "Min" input when `erc20TokenAddresses.length == 0` for the Emporium action id: [1](#0-0) . `formInputEmporiumMin` only feeds `emporiumMessage`, `timeStamp`, `calldataHash` into the proof — no `signedMessageHash`, no `rootHashHinkal` binding of the actual op contents beyond the plain-Solidity `calldataHash` equality check.
2. `MainEVMCircuitMin` proves nothing but `message == Poseidon(messageSeed)`, a value the attacker freely chooses: [2](#0-1) .
3. `dimensionsCheck` only requires `erc20TokenAddresses.length == dimensions.tokenNumber`, which the attacker sets to 0, satisfying it trivially: [3](#0-2) .
4. In `Hinkal.transact`, the balance-diff/slippage/UTXO-accounting loop after `_externalTransact` iterates only over `circomData.erc20TokenAddresses` — with length 0 it executes zero times, enforcing nothing: [4](#0-3) .
5. `EmporiumUpgradeable.runAction` decodes an attacker-fully-controlled `EmporiumStack` from `externalActionMetadata` and, when `stack.signerAddress == address(0)`, `verifyWallet` returns immediately without any signature check: [5](#0-4) .
6. The ops loop then executes `op.endpoint.call{value: op.value}(op.callData)` directly as Emporium (only `callHinkalWallet`/`doSendToRelay` selectors are blocked; any other target/call, including an ERC20 `transfer`, is allowed): [6](#0-5) .
7. `balancesBefore`/`balancesAfter` in `runAction` are also computed over `circomData.erc20TokenAddresses`, again empty, so the `BalanceChangeShouldBePositive` guard never fires for the stolen token: [7](#0-6) .

Any token or ETH balance the Emporium contract holds — e.g., transient funds sitting between ops of a legitimate multi-step stateful `EmporiumStack` flow, dust, or funds a pre/post `preTransact`/`afterTransact` hook deposits into Emporium mid-flight (widening the check-to-write gap referenced in the question) — is fully exposed with none of `onlyAllowedRecipient`, `dimensionsCheck`, `verifyProof`, or the balance loops providing any real constraint, since all of them key off the attacker-chosen empty `erc20TokenAddresses` array.

### Impact Explanation
An unprivileged attacker can drain any ERC20/ETH balance resident on the `EmporiumUpgradeable` contract in a single transaction, using only a self-generated trivial proof and no signature, satisfying the "Critical: direct theft of shielded or in-flight user funds" category. The attack is fully repeatable for any subsequent balance that accrues on Emporium (e.g., after each legitimate multi-op flow leaves residual dust, or after a hook deposits mid-flow).

### Likelihood Explanation
Preconditions: Emporium must hold some non-zero token/ETH balance at the time of attack (plausible given its role as an intermediary for stateful multi-op `EmporiumStack` flows and hook-driven deposits). The attacker needs no special role — just the ability to call `Hinkal.transact` with a self-crafted `CircomData`/`Dimensions`, generate the trivial Min proof (only requires `messageSeed`), and pick an unused `emporiumMessage`. Cost is a single gas fee; feasibility is high since none of the guarding checks reference the actual op contents when `erc20TokenAddresses` is empty.

### Recommendation
Never allow zero-length `erc20TokenAddresses` to bypass balance accounting for Emporium actions that execute arbitrary `ops`. Either (a) require `signerAddress != address(0)` (i.e., a valid signature) whenever `EmporiumStack.ops` is non-empty regardless of `erc20TokenAddresses.length`, (b) bind the full `EmporiumStack` content into the circuit's public inputs/`signedMessageHash` even on the Min path so a proof can't be reused to authorize arbitrary ops, and/or (c) require `erc20TokenAddresses` to include every token touched by `ops.endpoint.call` targets so `balancesBefore`/`balancesAfter` cannot be trivially emptied out while still permitting arbitrary external calls.

### Proof of Concept
Foundry test plan:
1. Deploy `Hinkal`, `HinkalHelper`, `EmporiumUpgradeable` (registered under `HINKAL_EMPORIUM_ACTION_ID`), a mock ERC20, and register a verifier for `Dimensions(0,0,0)` + `HINKAL_EMPORIUM_ACTION_ID` backed by `MainEVMCircuitMin`.
2. Seed Emporium with `TOKEN.mint(emporiumAddress, 100e18)` to simulate residual/in-flight balance.
3. Craft `CircomData` with `erc20TokenAddresses = []`, `amountChanges = []`, `onChainCreation = []`, `slippageValues = []`, `inputNullifiers = []`, `outCommitments = []`, `externalActionData = {externalAddress: emporium, externalActionId: HINKAL_EMPORIUM_ACTION_ID, externalActionMetadata: abi.encode(EmporiumStack{v:0,r:0,s:0, signerAddress:address(0), ops:[{endpoint: token, invokeWallet:false, value:0, callData: abi.encodeCall(IERC20.transfer,(attacker,100e18))}], maxFee:0, deadline:type(uint256).max})}`, `rootHashHinkal` = any existing root, `calldataHash` = `getHashedCalldata(circomData)`.
4. Generate a locally-computed Min proof for `messageSeed` chosen by attacker, `emporiumMessage = Poseidon(messageSeed)`.
5. Call `Hinkal.transact(a,b,c,Dimensions(0,0,0),circomData)` from an unprivileged EOA.
6. Assert: before tx `TOKEN.balanceOf(emporium) == 100e18 && TOKEN.balanceOf(attacker) == 0`; after tx `TOKEN.balanceOf(emporium) == 0 && TOKEN.balanceOf(attacker) == 100e18`, with the tx succeeding and no `BalanceChangeShouldBePositive`/slippage revert triggered, proving the equality `assets moved == assets accounted (Σ erc20TokenAddresses)` is violated (0 accounted vs 100e18 moved).

        uint256 chainId,
        address verifyingContract,
        CircomData calldata circomData
    ) internal pure returns (uint256[] memory) {
        if (
            circomData.externalActionData.externalActionId ==
            HINKAL_EMPORIUM_ACTION_ID &&
            circomData.erc20TokenAddresses.length == 0
        ) {
            return formInputEmporiumMin(circomData);
        } else {
            return formInputNormal(chainId, verifyingContract, circomData);
        }

    function formInputEmporiumMin(
        CircomData calldata circomData
    ) internal pure returns (uint256[] memory input) {
        input = new uint256[](circomData.publicSignalCount);

        uint16 index = 0;

        input[index++] = circomData.emporiumMessage;

        input[index++] = circomData.timeStamp;
        input[index++] = circomData.calldataHash;
    }
