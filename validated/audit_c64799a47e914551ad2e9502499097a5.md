Confirmed: no rescue/sweep function exists in `ExternalActionBaseV2`, `Transferer`, or `ExternalActionSwap` for arbitrary stranded tokens.

### Title
Missing token-count validation in `ExternalActionSwap.swap` permanently strands pre-funded tokens at index ≥ 2 - (File: contracts/external-actions/swaps/ExternalActionSwap.sol)

### Summary
`ExternalActionSwap.swap` unconditionally reads only `circomData.erc20TokenAddresses[0]` and `[1]`, but `Hinkal.transact`'s balance-equality loop iterates over the full `erc20TokenAddresses` array, whose length is only constrained to equal `dimensions.tokenNumber` by `dimensionsCheck` — never fixed at 2. `Hinkal._externalTransact` pre-transfers tokens for every index with `deltaAmountChanges[i] < 0` before `runAction` is invoked, so any extra declared token (index 2+) is sent to the swap contract regardless of whether `swap()` ever touches it.

### Finding Description
Equality being checked, per index `i`, in `Hinkal.transact`:
`balanceDif[i] == (onChainCreation[i] ? 0 : amountChanges[i]) + utxoAmount[i]` [1](#0-0) 

For index 2 (an "extraToken" never referenced by the swap logic), with `amountChanges[2] = -X` and `onChainCreation[2] = false`:

- `_externalTransact` computes `deltaAmountChanges[2] = -X` and, because it is negative, transfers `X` of `extraToken` from Hinkal to `ExternalActionSwap` *before* calling `runAction`: [2](#0-1) 
- `ExternalActionSwap.swap` only ever reads `erc20TokenAddresses[0]` and `[1]` — there is no loop, no length check, and no handling of any other index: [3](#0-2) 
- The returned `utxoSet` has length 1 (only `outputToken`), so for index 2, `utxoAmount = 0` in `Hinkal.transact`'s matching loop: [4](#0-3) 
- `newBalances[2] - oldBalances[2] = -X` (Hinkal paid out X and got nothing back), so `balanceDif[2] = -X`, and the require becomes `-X == -X + 0`, which **holds**. The contract's own accounting is internally consistent, but this consistency masks the fact that `X` tokens left Hinkal and were never consumed, converted, or returned by the swap action.

Root cause: `dimensionsCheck` in `HinkalHelper.sol` only validates that all `CircomData` arrays have equal length (`dimensions.tokenNumber`); it imposes no upper bound or exact value of 2 for the swap action specifically: [5](#0-4)  The circuit `MainEVMCircuit.circom` is likewise generic over `tokenCount` and does not fix it at 2 for any particular `externalActionId` [6](#0-5) . Nothing in `ExternalActionSwap.sol` asserts `erc20TokenAddresses.length == 2` before indexing `[0]`/`[1]` and ignoring the rest. Compare with `EmporiumUpgradeable.runAction`, which correctly loops over **all** `circomData.erc20TokenAddresses.length` entries, computes `balanceChange` per index (including tokens the wallet ops didn't touch), and returns them via `handleOut` — precisely the pattern `ExternalActionSwap` is missing: [7](#0-6) .

The existing guards do not prevent this: `verifyProof`/`buildVerifierId` only assert cryptographic validity of whatever dimension the attacker chooses and that a verifier is registered for `(tokenNumber, nullifierAmount, outputAmount, externalActionId)` [8](#0-7) ; `performHinkalChecks`/`dimensionsCheck`/`checkOnchainCreation` check array-length consistency and calldata-hash integrity only, not swap-specific token count [9](#0-8) . `ExternalActionSwap` has no rescue function for stray tokens.

### Impact Explanation
Critical — permanent freezing of user funds. The user's `amountChanges[2]` withdrawal is deducted from their private balance (per circuit constraint `inTotal + amountChanges[i] === outTotal`), the tokens leave the Hinkal vault, but they are stranded in `ExternalActionSwap`/`LifiExternalAction` with no UTXO ever created and no rescue mechanism, so the funds are unrecoverable by the user. This is repeatable per transaction for any extra declared token index, as long as a verifier exists for that `(tokenNumber, externalActionId)` combination.

### Likelihood Explanation
The attack requires the on-chain deployment to have a registered verifier for the swap `externalActionId` combined with `tokenNumber > 2` (verifier registration is `onlyOwner`, keyed on `(tokenNumber, nullifierAmount, outputAmount, externalActionId)` via `buildVerifierId`). I could not find deployment/registration scripts in the indexed portion of the repo confirming whether such a verifier is actually deployed/registered for the swap action; only generic verifier contracts (`VerifierEVM2x6x1v4`, `VerifierEVM4x6x1v4`, etc.) exist as artifacts, and they are reusable across action IDs since `buildVerifierId` only depends on dimension counts and `externalActionId`, not on the verifier contract itself. If the owner registers a generic multi-token verifier under the swap action ID (e.g., to support future/other functionality), or if any deployed verifier ID coincidentally maps to a hash matching `(tokenNumber=3+, ..., swapActionId)`, the exploit becomes trivially executable by any unprivileged user who can generate a valid proof for their own UTXOs. The root cause — the missing length assertion in `ExternalActionSwap.swap` — is a code-level defect independent of that deployment detail, and should be fixed regardless of current verifier registration state.

### Recommendation
Add an explicit check at the top of `ExternalActionSwap.swap` (and `runAction`) enforcing `circomData.erc20TokenAddresses.length == 2` (matching `deltaAmounts.length == 2`), reverting otherwise. Alternatively/additionally, generalize `swap()` to loop over all declared token indices as `EmporiumUpgradeable.runAction` does, returning a UTXO (or explicit revert) for any unexpected non-zero `deltaAmountChanges[i]` beyond the two swap legs, so no token can be silently pre-funded and abandoned.

### Proof of Concept
Foundry test plan:
1. Deploy `Hinkal`, `HinkalHelper`, `VerifierFacade`, and `LifiExternalAction` (subclass of `ExternalActionSwap`); register the swap `externalActionId` in `Hinkal.externalActionMap`.
2. Register (or mock) a verifier under `buildVerifierId(Dimensions({tokenNumber: 3, ...}), swapActionId)` that accepts a locally generated valid Groth16 proof for `MainEVMCircuit(tokenCount=3, ...)` with `erc20TokenAddresses = [inputToken, outputToken, extraToken]`, `amountChanges = [-inputAmount, +swapOutput, -X]` (X = extra withdrawal from user's private balance for `extraToken`), satisfying `inTotal + amountChanges[i] === outTotal` for all three tokens.
3. Call `Hinkal.transact(...)` with this `CircomData`.
4. Assert: `extraToken.balanceOf(address(LifiExternalAction)) == X` after the call (tokens now stuck in the swap contract).
5. Assert: no UTXO commitment/leaf exists for `extraToken` at amount `X` (only two `insertCommitments` entries corresponding to swap's single `outputToken` UTXO plus off-chain outputs, none for `extraToken`).
6. Assert: the transaction did not revert — i.e., `balanceDif[2] == amountChanges[2] + 0` held exactly, proving the equality gate is satisfied while the funds are unrecoverable (no code path in `ExternalActionSwap` returns or represents `extraToken`).

    function swap(
        CircomData calldata circomData,
        int256[] calldata deltaAmounts
    ) internal returns (UTXO[] memory utxoSet) {
        address inputToken = circomData.erc20TokenAddresses[0];
        uint256 inputAmount = uint256(-deltaAmounts[0]);

        if (inputToken == circomData.feeStructure.feeToken) {
            inputAmount -= circomData.feeStructure.flatFee;
        }

        address outputToken = circomData.erc20TokenAddresses[1];

        require(
            circomData.slippageValues[1] != 0,
            "swap output slippage floor not set"
        );

        require(
            block.timestamp <= circomData.timeStamp + SWAP_DEADLINE_WINDOW,
            "swap expired"
        );

        uint256 swappedAmount = callRouter(
            inputToken,
            inputAmount,
            outputToken,
            circomData.externalActionData.externalActionMetadata
        );

        uint256 relayFee = circomData.feeStructure.flatFee;

        uint256 hinkalFee = hinkalHelper.calculateRelayFee(
            swappedAmount,
            0,
            circomData.feeStructure.variableRate
        );

        if (circomData.feeStructure.feeToken == outputToken) {
            sendToRelay(circomData.relay, relayFee + hinkalFee, outputToken);
        } else {
            sendToRelay(
                circomData.relay,
                relayFee,
                circomData.feeStructure.feeToken
            );
            sendToRelay(circomData.relay, hinkalFee, outputToken);
        }

        uint256 totalFee = hinkalFee +
            (outputToken == circomData.feeStructure.feeToken ? relayFee : 0);
        uint256 amountToSendToHinkal = swappedAmount - totalFee;

        transferERC20TokenOrETH(outputToken, msg.sender, amountToSendToHinkal);

        utxoSet = new UTXO[](1);
        utxoSet[0] = UTXO({
            amount: amountToSendToHinkal,
            erc20Address: outputToken,
            stealthAddressStructure: circomData.stealthAddressStructure,
            timeStamp: block.timestamp
        });
    }
