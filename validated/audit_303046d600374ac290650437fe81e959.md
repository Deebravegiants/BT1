Audit Report

## Title
Vault secret storage keys are case-sensitive while owner authorization is case-insensitive, allowing per-owner quota and duplicate-ID bypass - ([File: core/capabilities/vault/vaulttypes/types.go])

## Summary
`vaultutils.NormalizeOwner` lowercases/strips `0x` and is used only at authorization comparison sites (`validateEncryptedSecretOwnerMismatch`, `validateSecretIdentifierOwnerMismatch`, the `ListSecretIdentifiers` owner check), but the canonical storage/dedup key `vaulttypes.KeyFor` and the OCR plugin's KV-store metadata partition key (`metadataPrefix+owner`) use the raw, unnormalized `Id.Owner`/`owner` string. Because the gateway pipeline (`GatewayVaultRequestProcessor.authorizeAndStamp`) never rewrites `Id.Owner` to the canonical `AuthorizedOwner()` — it only stamps the request ID and namespace defaults — a client can submit the "same" authorized owner in different casings/`0x`-prefix forms, passing authorization each time but landing in distinct KV-store metadata partitions and distinct dedup buckets.

## Finding Description
Authorization equivalence is decided via `NormalizeOwner`, discarding case and `0x`-prefix information: [5](#0-4) 

That normalized comparison is the only check applied to `Id.Owner`/`EncryptedSecret.Id.Owner` before the value is passed through to the reporting plugin unmodified: [6](#0-5) 

The gateway processor's stamping step, which is the only place params are mutated post-authorization, only rewrites the request ID and applies namespace defaults — it never canonicalizes `Owner`: [7](#0-6) [2](#0-1) 

Downstream, `vaulttypes.KeyFor` builds the canonical storage/dedup key straight from `id.Owner` with no normalization, and the OCR reporting-plugin validator uses this raw key for intra-batch duplicate detection and, separately, `id.Owner` directly as the KV-store metadata partition key and per-owner quota lookup key — all as cited in the original report (`core/capabilities/vault/vaulttypes/types.go`, `core/capabilities/vault/validator.go`, `core/services/ocr2/plugins/vault/kvstore.go`). This confirms the mismatch: authorization treats case/prefix variants as the same owner, but storage/quota/dedup treat them as distinct.

## Impact Explanation
An authorized workflow owner can create independent KV-store metadata partitions per case-variant of their own address, each with its own `MaxSecretsPerOwner` quota bucket (`GetSecretIdentifiersCountForOwner`), multiplying effective storage/quota limits and causing unbounded per-owner secret growth in the shared OCR KV store. It can also defeat the intra-batch duplicate-ID check in `ValidateDeleteSecretsRequest`/the reporting plugin's `validateDuplicateSecretIdentifierUserError`, since `KeyFor` is case-sensitive. A `ListSecretIdentifiers`/`Delete` call issued with one casing will silently miss secrets stored under a different casing of the same authorized owner, causing user-visible state inconsistency (secrets appear to disappear or become undeletable). This maps to a resource-exhaustion / quota-bypass and cross-request state-corruption impact in the Vault capability, triggerable by any normal (non-privileged) authorized workflow owner.

## Likelihood Explanation
Fully reachable by any unprivileged workflow owner who is already authorized to submit Vault JSON-RPC requests through the gateway or OCR path (allowlist- or JWT-based auth). The attacker only needs to control the casing/`0x`-prefix of the `Owner` field they supply in `SecretIdentifier`/`EncryptedSecret.Id`, which is fully client-controlled JSON content and passes the existing `NormalizeOwner`-based authorization check by design. No race condition, elevated privilege, or unusual timing is required — this is a straightforward, deterministic, repeatable request-crafting bug.

## Recommendation
Canonicalize `Owner` once at request ingress (e.g., in `GatewayVaultRequestProcessor.authorizeAndStamp`, rewriting `Id.Owner`/`EncryptedSecret.Id.Owner` to `authResult.AuthorizedOwner()` before stamping params) so that every downstream consumer — `vaulttypes.KeyFor`, the request validator's duplicate-ID map, and the OCR KV-store's `metadataPrefix+owner` key / `GetSecretIdentifiersCountForOwner` — operates on a single canonical representation. Until that ingress-level fix lands, apply `vaultutils.NormalizeOwner` (or equivalent canonicalization) inside `KeyFor` itself and at the KV-store's metadata key construction sites so storage/quota/dedup equivalence matches authorization equivalence.

## Proof of Concept
1. Authorize a workflow with owner `abc123...def` (any casing accepted by the DON's authorizer).
2. Send `CreateSecrets` with `EncryptedSecret.Id.Owner = "ABC123...DEF"` (uppercase variant). `validateEncryptedSecretOwnerMismatch` passes since `NormalizeOwner` equates both forms; `GatewayVaultRequestProcessor` does not rewrite `Id.Owner`.
3. The OCR plugin's `KVStore.addIDToMetadata`/`WriteMetadata` stores the secret under `metadataPrefix+"ABC123...DEF"`, distinct from `metadataPrefix+"abc123...def"`.
4. Repeat step 2 with additional case permutations of the same address; each creates an independent metadata partition and quota bucket, up to `MaxSecretsPerOwner` secrets per casing variant — exceeding the intended per-owner limit.
5. Issue `ListSecretIdentifiers`/`DeleteSecrets` using the original lowercase owner casing and observe that secrets stored under other casings are not returned/deleted, demonstrating the cross-representation inconsistency. A Go unit test asserting `vaulttypes.KeyFor` and `KVStore.GetSecretIdentifiersCountForOwner` produce different results for `NormalizeOwner`-equal-but-differently-cased `Owner` values would confirm this at the unit level.

func (p *GatewayVaultRequestProcessor) authorizeAndStamp(
	ctx context.Context,
	req *jsonrpc.Request[json.RawMessage],
	stamp func(prefixedRequestID string) error,
) (*AuthorizedGatewayVaultRequest, error) {
	incomingOwner := ""
	if idx := strings.Index(req.ID, vaulttypes.RequestIDSeparator); idx != -1 {
		incomingOwner = req.ID[:idx]
	}

	p.lggr.Debugw("authorizing gateway vault request", "method", req.Method, "requestID", req.ID)
	authResult, err := p.authorizer.AuthorizeRequest(ctx, *req)
	if err != nil {
		authErr := fmt.Errorf("request not authorized: %w", err)
		p.lggr.Errorw("gateway vault request authorization failed", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "", "incomingOwner", incomingOwner, "error", authErr)
		return nil, authErr
	}

	originalRequestID := req.ID
	authorizedOwner := authResult.AuthorizedOwner()
	prefixedRequestID := authorizedOwner + vaulttypes.RequestIDSeparator + originalRequestID
	req.ID = prefixedRequestID

	if err := stamp(prefixedRequestID); err != nil {
		p.lggr.Errorw("failed to stamp authorized request params", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, fmt.Errorf("failed to stamp authorized request params: %w", err)
	}

	p.lggr.Debugw("authorized gateway vault request", "method", req.Method, "requestID", req.ID, "owner", authorizedOwner, "orgID", authResult.OrgID(), "workflowOwner", authResult.WorkflowOwner())
	return &AuthorizedGatewayVaultRequest{
		Req:        *req,
		AuthResult: authResult,
	}, nil
}

// validateSecretOwnersMatchAuthorized checks that secret identifiers in the request payload
// match the authorized workflow owner. This is read-only validation; owner prefixing and
// param stamping happen later in GatewayVaultRequestProcessor.
func validateSecretOwnersMatchAuthorized(req jsonrpc.Request[json.RawMessage], workflowOwner string) error {
	switch req.Method {
	case vaulttypes.MethodPublicKeyGet:
		return nil
	case vaulttypes.MethodSecretsCreate:
		if req.Params == nil {
			return errors.New("request params must not be nil")
		}
		var createReq vaultcommon.CreateSecretsRequest
		if err := json.Unmarshal(*req.Params, &createReq); err != nil {
			return err
		}
		return validateEncryptedSecretOwnerMismatch(createReq.EncryptedSecrets, workflowOwner)
	case vaulttypes.MethodSecretsUpdate:
		if req.Params == nil {
			return errors.New("request params must not be nil")
		}
		var updateReq vaultcommon.UpdateSecretsRequest
		if err := json.Unmarshal(*req.Params, &updateReq); err != nil {
			return err
		}
		return validateEncryptedSecretOwnerMismatch(updateReq.EncryptedSecrets, workflowOwner)
	case vaulttypes.MethodSecretsDelete:
		if req.Params == nil {
			return errors.New("request params must not be nil")
		}
		var deleteReq vaultcommon.DeleteSecretsRequest
		if err := json.Unmarshal(*req.Params, &deleteReq); err != nil {
			return err
		}
		return validateSecretIdentifierOwnerMismatch(deleteReq.Ids, workflowOwner)
	case vaulttypes.MethodSecretsList:
		if req.Params == nil {
			return errors.New("request params must not be nil")
		}
		var listReq vaultcommon.ListSecretIdentifiersRequest
		if err := json.Unmarshal(*req.Params, &listReq); err != nil {
			return err
		}
		if vaultutils.NormalizeOwner(listReq.Owner) != vaultutils.NormalizeOwner(workflowOwner) {
			return fmt.Errorf("list secrets owner %q does not match authorized workflow owner %q", listReq.Owner, workflowOwner)
		}
		return nil
	default:
		return fmt.Errorf("owner validation not implemented for method %q", req.Method)
	}
}

func validateEncryptedSecretOwnerMismatch(encryptedSecrets []*vaultcommon.EncryptedSecret, workflowOwner string) error {
	if len(encryptedSecrets) == 0 {
		return errors.New("request batch must contain at least 1 item")
	}
	for idx, encryptedSecret := range encryptedSecrets {
		if encryptedSecret == nil {
			return fmt.Errorf("encrypted secret must not be nil at index %d", idx)
		}
		if encryptedSecret.Id == nil {
			return fmt.Errorf("secret ID must not be nil at index %d", idx)
		}
		if vaultutils.NormalizeOwner(encryptedSecret.Id.Owner) != vaultutils.NormalizeOwner(workflowOwner) {
			return fmt.Errorf("encrypted secret owner at index %d %q does not match authorized workflow owner %q", idx, encryptedSecret.Id.Owner, workflowOwner)
		}
	}
	return nil
}

func validateSecretIdentifierOwnerMismatch(ids []*vaultcommon.SecretIdentifier, workflowOwner string) error {
	if len(ids) == 0 {
		return errors.New("request batch must contain at least 1 item")
	}
	for idx, id := range ids {
		if id == nil {
			return fmt.Errorf("secret ID must not be nil at index %d", idx)
		}
		if vaultutils.NormalizeOwner(id.Owner) != vaultutils.NormalizeOwner(workflowOwner) {
			return fmt.Errorf("secret identifier owner at index %d %q does not match authorized workflow owner %q", idx, id.Owner, workflowOwner)
		}
	}
	return nil
}
