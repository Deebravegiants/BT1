Audit Report

## Title
`paras_registrar::deregister` bypasses `assigned_slots::unassign_parachain_slot`, orphaning `TemporarySlots`/`TemporarySlotCount` accounting - (File: polkadot/runtime/common/src/assigned_slots/mod.rs)

## Summary
`assign_temp_parachain_slot` inserts a `TemporarySlots` entry and increments `TemporarySlotCount` unconditionally, but only synchronously invokes `configure_slot_lease` (which flips `ParaLifecycle` away from `Parathread`) when `lease_period_start == SlotLeasePeriodStart::Current` and `ActiveTemporarySlotCount::<T>::get() < T::MaxTemporarySlotPerLeasePeriod::get()`. In the deferred cases (`Next`, or per-period cap already reached), the para stays `ParaLifecycle::Parathread`, and `paras_registrar::do_deregister` — which only checks `paras::Pallet::lifecycle(id)` — allows the para manager to deregister via `ensure_root_para_or_owner` without ever going through `assigned_slots::unassign_parachain_slot`'s `AssignSlotOrigin` gate or its cleanup logic, leaving `TemporarySlots`/`TemporarySlotCount` permanently stale.

## Finding Description
In `assign_temp_parachain_slot` [1](#0-0) , the direct-lease branch executes only under the `Current` + under-cap condition, and regardless of outcome, the function unconditionally performs `TemporarySlots::<T>::insert(id, temp_slot)` and `TemporarySlotCount::<T>::mutate(|count| count.saturating_inc())`. When the branch is skipped, no call reaches `T::Leaser::lease_out`/`make_parachain`, so `paras::Pallet::lifecycle(id)` remains `Some(ParaLifecycle::Parathread)`.

`paras_registrar::do_deregister` only gates on lifecycle being `Parathread` or `None` [2](#0-1) , with no awareness of `assigned_slots` storage. The manager-initiated path `ensure_root_para_or_owner` [3](#0-2)  permits a plain signed call as long as the para is unlocked, entirely bypassing `T::AssignSlotOrigin`.

The only correct cleanup path, `unassign_parachain_slot`, removes `TemporarySlots`/`PermanentSlots` and decrements the associated counters, but it is gated by `T::AssignSlotOrigin::ensure_origin` [4](#0-3) . Because `do_deregister` never calls this or an equivalent hook, the storage desync described is real and confirmed by direct code reading: there is no cross-pallet check linking `paras_registrar`'s deregister path to `assigned_slots`' storage.

## Impact Explanation
This is a genuine, permanently reproducible accounting desync between `assigned_slots::TemporarySlotCount`/`TemporarySlots` and the real registrar/lifecycle state. The orphaned counter/entry consumes capacity against `MaxTemporarySlots` indefinitely, degrading the temporary-slot allocation mechanism for legitimate future assignments (a griefing/DoS effect scoped strictly to this pallet's own bookkeeping). The report's secondary claim — that `allocate_temporary_slot_leases` could later grant an unsanctioned lease turn to a re-registered, unrelated `ParaId` — was flagged by the researcher as unverified, and I likewise was unable to fully confirm within the available context whether `allocate_temporary_slot_leases`/`configure_slot_lease` re-validate para existence or manager identity before granting a lease turn to a stale `TemporarySlots` entry; this remains speculative. The confirmed impact is limited to internal storage desynchronization within `assigned_slots`, not a direct fund loss, chain-halt, or override of `paras_registrar`'s or `slots`' core invariants (a deregistered para simply cannot be a parachain, so no lease-granting collision can occur unless the same `ParaId` is re-registered and specifically re-inherits the stale entry — a scenario not demonstrated end-to-end).

## Likelihood Explanation
The claim's reachability is real: an unprivileged para manager can deliberately trigger `SlotLeasePeriodStart::Next` (governance-controlled call, since `assign_temp_parachain_slot` itself requires `T::AssignSlotOrigin`, but the manager doesn't need to control that call — they only need to be the manager and later call `deregister`), and since `deregister` requires no privilege beyond `ensure_root_para_or_owner`, the desync is deterministically achievable once the precondition (deferred/queued temp slot with lifecycle still `Parathread`) exists. Note, however, that assigned_slots itself is explicitly documented in the code as "This pallet should not be used on a production relay chain, only on a test relay chain (e.g. Rococo)" [5](#0-4) , meaning the affected pallet is test-network-only by design, significantly narrowing real-world/production impact.

## Recommendation
Add a cross-pallet check (e.g., a trait hook analogous to `OnSwap`) so that `paras_registrar::do_deregister`/`swap` reject the call, or trigger `assigned_slots` cleanup, whenever `assigned_slots::PermanentSlots`/`TemporarySlots` still contains an entry for the target `id`, and ensure counters (`TemporarySlotCount`, `PermanentSlotCount`, `ActiveTemporarySlotCount`) are decremented consistently in that scenario.

## Proof of Concept
The PoC in the report is plausible given the confirmed code paths: (1) register a para, (2) call `assign_temp_parachain_slot` with `SlotLeasePeriodStart::Next` (or with the per-period cap saturated) so `configure_slot_lease` is skipped and lifecycle stays `Parathread`, (3) call `deregister` as the para manager, (4) observe `TemporarySlots::contains_key(id)` still `true` and `TemporarySlotCount` not decremented while `paras::Pallet::lifecycle(id)` is `None`. This matches the code as read; I was not able to execute the test in this environment, but the storage/lifecycle logic reviewed directly supports the claimed behavior.

		/// Unassign a permanent or temporary parachain slot
		#[pallet::call_index(2)]
		#[pallet::weight((<T as Config>::WeightInfo::unassign_parachain_slot(), DispatchClass::Operational))]
		pub fn unassign_parachain_slot(origin: OriginFor<T>, id: ParaId) -> DispatchResult {
			T::AssignSlotOrigin::ensure_origin(origin.clone())?;

			ensure!(
				Self::has_permanent_slot(id) || Self::has_temporary_slot(id),
				Error::<T>::SlotNotAssigned
			);

			// Check & cache para status before we clear the lease
			let is_parachain = Self::is_parachain(id);

			// Remove perm or temp slot
			Self::clear_slot_leases(origin.clone(), id)?;

			if PermanentSlots::<T>::contains_key(id) {
				PermanentSlots::<T>::remove(id);
				PermanentSlotCount::<T>::mutate(|count| *count = count.saturating_sub(One::one()));
			} else if TemporarySlots::<T>::contains_key(id) {
				TemporarySlots::<T>::remove(id);
				TemporarySlotCount::<T>::mutate(|count| *count = count.saturating_sub(One::one()));
				if is_parachain {
					ActiveTemporarySlotCount::<T>::mutate(|active_count| {
						*active_count = active_count.saturating_sub(One::one())
					});
				}
			}

			// Force downgrade to on-demand parachain (if needed) before end of lease period
			if is_parachain {
				if let Err(err) = polkadot_runtime_parachains::schedule_parachain_downgrade::<T>(id)
				{
					// Treat failed downgrade as warning .. slot lease has been cleared,
					// so the parachain will be downgraded anyway by the slots pallet
					// at the end of the lease period .
					log::warn!(
						target: LOG_TARGET,
						"Failed to downgrade parachain {:?} at period {:?}: {:?}",
						id,
						Self::current_lease_period_index(),
						err
					);
				}
			}

			Ok(())
		}

	/// Ensure the origin is one of Root, the `para` owner, or the `para` itself.
	/// If the origin is the `para` owner, the `para` must be unlocked.
	fn ensure_root_para_or_owner(
		origin: <T as frame_system::Config>::RuntimeOrigin,
		id: ParaId,
	) -> DispatchResult {
		if let Ok(who) = ensure_signed(origin.clone()) {
			let para_info = Paras::<T>::get(id).ok_or(Error::<T>::NotRegistered)?;

			if para_info.manager == who {
				ensure!(!para_info.is_locked(), Error::<T>::ParaLocked);
				return Ok(());
			}
		}

		Self::ensure_root_or_para(origin, id)
	}

	fn do_deregister(id: ParaId) -> DispatchResult {
		match paras::Pallet::<T>::lifecycle(id) {
			// Para must be a parathread (on-demand parachain), or not exist at all.
			Some(ParaLifecycle::Parathread) | None => {},
			_ => return Err(Error::<T>::NotParathread.into()),
		}
		polkadot_runtime_parachains::schedule_para_cleanup::<T>(id)
			.map_err(|_| Error::<T>::CannotDeregister)?;

		if let Some(info) = Paras::<T>::take(&id) {
			<T as Config>::Currency::unreserve(&info.manager, info.deposit);
		}

		PendingSwap::<T>::remove(id);
		Self::deposit_event(Event::<T>::Deregistered { para_id: id });
		Ok(())
	}
