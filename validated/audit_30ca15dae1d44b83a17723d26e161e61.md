This is the analog: `IsmpCallFilter` treats "advancing BEEFY consensus state" as synonymous with "the message is a `Message::Consensus` variant naming a BEEFY `consensus_state_id`," while `handle_unsigned`'s `Message` enum also carries a `Message::FraudProof(FraudProofMessage)` variant that freezes/mutates that same consensus client's state via `freeze_client`. The filter's `match message { Message::Consensus(consensus) => ..., _ => false }` arm blindly waves through every non-`Consensus` variant — exactly like fickling's `if module in ("__builtin__", ...) { pass }` blindness, where the security check keys off a narrow, named category (an import module string / a `Message::Consensus` variant) instead of the actual state-mutating capability, and everything outside that category is silently treated as safe.

### Title
BEEFY consensus-bypass filter is blind to `Message::FraudProof`, letting an unsigned `handle_unsigned` extrinsic freeze the BEEFY client without SP1 verification - ([File: parachain/runtimes/gargantua/src/lib.rs])

### Summary
`IsmpCallFilter::contains` (mirrored in nexus) is the runtime's `BaseCallFilter`, and its stated purpose is: "Gargantua routes all BEEFY consensus updates through `pallet-beefy-consensus-proofs`, which requires SP1 zkVM verification... Allowing raw updates through `handle_unsigned` would bypass that requirement entirely, so any batch that carries a BEEFY consensus message is rejected." It implements this by matching only the `Message::Consensus` arm of the `ismp::messaging::Message` enum and defaulting every other variant to `false` (not blocked): `_ => false`. `pallet_ismp::Call::handle_unsigned` accepts `Vec<Message>` where `Message` also has a `FraudProof(FraudProofMessage)` variant that is handled by `ismp::handlers::consensus::freeze_client`, which calls `consensus_client.verify_fraud_proof(...)` and then `host.freeze_consensus_client(...)` directly on the raw `BeefyConsensusClient`/`ismp_beefy` implementation — completely independent of `pallet-beefy-consensus-proofs`'s SP1 verification gate that the filter comment says is mandatory.

### Finding Description
`handle_unsigned` is a permissionless, free (unsigned) extrinsic reachable by anyone with a submitted batch of `Message`s [1](#0-0) . Every dispatch of it is gated by the runtime's `BaseCallFilter = IsmpCallFilter`, whose entire justification is to force BEEFY state transitions through the SP1-gated `pallet-beefy-consensus-proofs` path and to reject any raw `handle_unsigned` batch that would advance BEEFY state directly [2](#0-1) .

The filter's implementation only inspects the `Message::Consensus(consensus)` arm and compares `host.consensus_client_id(consensus.consensus_state_id)` against `ismp_beefy::BEEFY_CONSENSUS_ID`; every other `Message` variant (`Request`, `Response`, `Timeout`, and critically `FraudProof`) falls into `_ => false`, meaning the filter does not block it [3](#0-2) . This is structurally identical to fickling's bug: the security check is keyed to one named surface (`Message::Consensus` / `"builtins"` import name) and everything else is implicitly "safe," even when the omitted category can drive the exact same protected state.

`ismp::messaging::Message` includes a `FraudProof` variant carrying a `FraudProofMessage { consensus_state_id, proof_1, proof_2 }`, which `pallet_ismp::execute` routes to `ismp::handlers::consensus::freeze_client` [4](#0-3) . `freeze_client` looks up the consensus client by `msg.consensus_state_id`, verifies the client is not already frozen, calls `consensus_client.verify_fraud_proof(host, trusted_state, msg.proof_1, msg.proof_2)`, and on success directly calls `host.freeze_consensus_client(msg.consensus_state_id)` — mutating the BEEFY consensus client's frozen state (a `MessageResult::FrozenClient` outcome) with no involvement of `pallet-beefy-consensus-proofs` or its SP1 zkVM gate. Since the filter's `match` only special-cases `Message::Consensus`, a `Message::FraudProof` batch targeting the BEEFY `consensus_state_id` is never inspected and is let through unconditionally by `IsmpCallFilter::contains` (returns `true` via the wildcard `_ => true` at the top-level `match call`, since the `handle_unsigned` arm itself returns `!any(...)` which evaluates to `true` because no message matches the `Consensus` arm).

The same pattern is duplicated verbatim in the nexus runtime [5](#0-4) , so the bypass is not runtime-specific.

### Impact Explanation
This lets any unprivileged actor submit an unsigned `Ismp::handle_unsigned([Message::FraudProof(FraudProofMessage{ consensus_state_id: BEEFY_STATE_ID, proof_1, proof_2 })])` extrinsic that reaches `freeze_client` and, if `verify_fraud_proof` can be satisfied (even incorrectly, via any bug/edge-case in the BEEFY client's fraud-proof verification, or simply as a griefing vector once any valid fraud proof exists), freezes the BEEFY consensus client directly — bypassing the SP1 zkVM verification gate the runtime designers explicitly built the filter to enforce. A frozen BEEFY client halts all further BEEFY-consensus state updates, which is the trust root for every state machine bound to it (Polkadot/Paseo state machines relayed through Hyperbridge). This is a denial-of-service on the entire cross-chain messaging route for those state machines — matching the "route unable to deliver messages" acceptance criterion — because once frozen, `update_client` for BEEFY messages will error via `host.is_consensus_client_frozen(...)` checks, stalling proof delivery, request/response handling, and relayer fee accounting for every app depending on that route. It is reachable from a single unsigned extrinsic submitted by any relayer/unprivileged party.

### Likelihood Explanation
The path is directly reachable: `handle_unsigned` is explicitly designed to be free and unsigned so "anyone" can execute ISMP messages, and `FraudProofMessage` is a first-class variant of the `Message` enum accepted by that call [6](#0-5) . The filter comment demonstrates the developers' clear intent to block exactly this class of bypass for `Message::Consensus`, but the implementation never extends that intent to `Message::FraudProof`, which is a straightforward oversight of the same shape as the fickling advisory (checking a named enum arm/import name rather than the full set of state-mutating variants). Exploitation likelihood depends on whether a valid (or exploitable) fraud proof can be constructed against the live BEEFY consensus state — this could not be fully verified from the indexed code alone (the BEEFY fraud-proof verification logic in `modules/ismp/clients/beefy` was not fully inspected in this pass), so this should be validated further, but the filter gap itself is concrete and unconditional.

### Recommendation
Extend `IsmpCallFilter::contains` (in both `gargantua` and `nexus` runtimes) to also inspect `Message::FraudProof` messages and reject any `handle_unsigned` batch whose `consensus_state_id` resolves to the BEEFY consensus client, mirroring the existing `Message::Consensus` check — i.e., route BEEFY freezing through the same `pallet-beefy-consensus-proofs`-gated path (or an explicitly SP1-verified freeze path) rather than allowing the raw ISMP fraud-proof handler to touch the BEEFY client's frozen state. More generally, replace the per-variant allowlist/blocklist matching with a check keyed on "does this message touch `consensus_state_id == BEEFY_CONSENSUS_ID`" across every `Message` variant that can read or mutate consensus-client state, not just `Consensus`.

### Proof of Concept
1. Identify the BEEFY `consensus_state_id` bound to `ismp_beefy::BEEFY_CONSENSUS_ID` via `Ismp::consensus_client_id`.
2. Construct (or obtain) any `proof_1`/`proof_2` pair satisfying `BeefyConsensusClient::verify_fraud_proof` for that state (this is the only unverified precondition; if the BEEFY fraud-proof verifier accepts it, this is a genuine unsigned-DoS primitive, and even a legitimately-detected byzantine BEEFY authority set would let anyone push the freeze without going through the SP1-gated pallet).
3. Submit:
```rust
RuntimeCall::Ismp(pallet_ismp::Call::handle_unsigned {
    messages: vec![Message::FraudProof(FraudProofMessage {
        consensus_state_id: BEEFY_CONSENSUS_STATE_ID,
        proof_1,
        proof_2,
    })],
})
```
as an unsigned extrinsic.
4. `IsmpCallFilter::contains` evaluates the `handle_unsigned` arm: `!messages.iter().any(|message| matches!(message, Message::Consensus(c) if ...))` — since the only message is `Message::FraudProof`, the `.any(...)` is `false`, so `!false == true`, and the call filter allows dispatch [7](#0-6) .
5. `Pallet::<T>::handle_unsigned` executes and routes to `freeze_client`, which freezes the BEEFY consensus client directly, bypassing `pallet-beefy-consensus-proofs`'s SP1 verification entirely [8](#0-7) .

/// Gargantua routes all BEEFY consensus updates through `pallet-beefy-consensus-proofs`, which
/// requires each proof to pass SP1 zkVM verification before it can advance the BEEFY state.
/// Allowing raw updates through `handle_unsigned` would bypass that requirement entirely, so
/// any batch that carries a BEEFY consensus message is rejected here. `fund_message` is also
/// disabled because gargantua uses the bandwidth model for request fees; per-message top-ups
/// have no role in that accounting.
///
/// A consensus message only names the state it updates, so we ask the host which client owns
/// that state and compare against BEEFY. Reading from the host remains correct even as more
/// states (Polkadot, Paseo) are bound to the same client over time.
pub struct IsmpCallFilter;
impl frame_support::traits::Contains<RuntimeCall> for IsmpCallFilter {
	fn contains(call: &RuntimeCall) -> bool {
		use ::ismp::{host::IsmpHost, messaging::Message};
		match call {
			RuntimeCall::Ismp(pallet_ismp::Call::fund_message { .. }) => false,
			RuntimeCall::Ismp(pallet_ismp::Call::handle_unsigned { messages }) => {
				let host = Ismp::default();
				!messages.iter().any(|message| match message {
					Message::Consensus(consensus) =>
						host.consensus_client_id(consensus.consensus_state_id) ==
							Some(ismp_beefy::BEEFY_CONSENSUS_ID),
					_ => false,
				})
			},
			_ => true,
		}
	}
}

/// Freeze a consensus client by providing a valid fraud proof.
pub fn freeze_client<H>(host: &H, msg: FraudProofMessage) -> Result<MessageResult, anyhow::Error>
where
	H: IsmpHost,
{
	let consensus_client_id = host
		.consensus_client_id(msg.consensus_state_id)
		.ok_or_else(|| Error::Custom("Unknown Consensus State Id".to_string()))?;

	host.is_consensus_client_frozen(msg.consensus_state_id)?;

	let consensus_client = host.consensus_client(consensus_client_id)?;
	let trusted_state = host.consensus_state(msg.consensus_state_id)?;

	consensus_client.verify_fraud_proof(host, trusted_state, msg.proof_1, msg.proof_2)?;

	host.freeze_consensus_client(msg.consensus_state_id)?;

	host.store_consensus_update_time(msg.consensus_state_id, host.timestamp())?;

	Ok(MessageResult::FrozenClient(msg.consensus_state_id))
}
