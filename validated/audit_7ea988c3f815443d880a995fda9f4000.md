Audit Report

## Title
Crowdloan verifier signature replay across dissolved-and-recreated funds due to signature payload lacking fund instance binding - (File: polkadot/runtime/common/src/crowdloan/mod.rs)

## Summary
`Pallet::do_contribute` signs/verifies the payload `(index, &who, old_balance, value)` where `index` is the `ParaId` and `old_balance` is read from the *current* fund's child trie via `contribution_get(fund.fund_index, &who)`. Because `create` allocates a fresh `fund_index` (and therefore a fresh, empty child trie) each time a crowdloan is created for a given `ParaId`, a signature issued for a contributor's first contribution (`old_balance == 0`) to a prior fund incarnation remains valid and replayable against a newly created fund for the same `ParaId`, provided the new fund reuses the same `verifier` key.

## Finding Description
The verified payload is constructed and checked at [1](#0-0) , using `old_balance` obtained from `contribution_get(fund.fund_index, &who)` at line 782. `fund_index` is a fresh, monotonically-incrementing counter allocated in `create` at [2](#0-1) , and `dissolve` removes the `Funds` entry for the `ParaId` (after confirming `raised` is zero) at [3](#0-2) , permitting a subsequent `create` for the same `ParaId` to allocate a new `fund_index` with a fresh, empty child trie. Since `old_balance` for any account in a brand-new fund trie is `0`, a previously issued signature over `(index, who, 0, value)` for the old fund remains structurally valid input to the check on lines 786-790 for the new fund, as `index`, `who`, `old_balance`, and `value` are unchanged — the payload contains no `fund_index` or other per-incarnation nonce to distinguish the two funds. This is confirmed by direct reading of the current repository code, matching the claim exactly.

## Impact Explanation
This allows a contributor to bypass the intended per-fund verifier/KYC gate: a signature meant to authorize a contribution to one specific crowdloan incarnation can be reused to authorize an equivalent contribution to a distinct, later incarnation of the crowdloan for the same `ParaId`, without any new sign-off from the verifier. Funds contributed are still fully backed by the contributor's own balance, so this is an authorization-bypass issue rather than a fund-draining exploit, but it does defeat the verifier's access-control purpose.

## Likelihood Explanation
The replay is triggerable entirely by an unprivileged contributor holding an old valid signature, requiring only that (1) the `ParaId`'s crowdloan is dissolved and recreated — a routine operational flow for retried auctions — and (2) the new fund's manager reuses the same `verifier` key, a plausible administrative choice. No privileged action, root access, or storage manipulation is needed by the attacker themselves.

## Recommendation
Bind the signed payload to the specific fund instance by including `fund.fund_index` (or another per-creation nonce) in the tuple that is signed and verified in `do_contribute`, so that a verifier signature is scoped to exactly one fund lifecycle and cannot be replayed after a `dissolve`/`create` cycle recreates the fund for the same `ParaId`.

## Proof of Concept
1. Create fund #1 for `ParaId(1)` with `verifier = V` via `create`.
2. Have `V` sign payload `(ParaId(1), who, 0, value)` off-chain to produce `sig`.
3. Call `contribute(ParaId(1), value, Some(sig))` from `who`; contribution succeeds and the trie entry for `who` becomes `value`.
4. Refund/kill contributions and call `dissolve(ParaId(1))` (satisfying `raised == 0` and the permission condition in lines 555-581).
5. Recreate fund #2 for the same `ParaId(1)` via `create`, reusing verifier `V` (new `fund_index` allocated, fresh empty child trie).
6. Replay `contribute(ParaId(1), value, Some(sig))` from `who` using the same old `sig`; the check at lines 782-791 passes because `old_balance` is again `0` in the new trie, demonstrating the signature was not scoped to fund #1's lifecycle.

			let who = ensure_signed(origin)?;

			let fund = Funds::<T>::get(index).ok_or(Error::<T>::InvalidParaId)?;
			let pot = Self::fund_account_id(fund.fund_index);
			let now = frame_system::Pallet::<T>::block_number();

			// Only allow dissolution when the raised funds goes to zero,
			// and the caller is the fund creator or we are past the end date.
			let permitted = who == fund.depositor || now >= fund.end;
			let can_dissolve = permitted && fund.raised.is_zero();
			ensure!(can_dissolve, Error::<T>::NotReadyToDissolve);

			// Assuming state is not corrupted, the child trie should already be cleaned up
			// and all funds in the crowdloan account have been returned. If not, governance
			// can take care of that.
			debug_assert!(Self::contribution_iterator(fund.fund_index).count().is_zero());

			// Crowdloan over, burn all funds.
			let _imba = CurrencyOf::<T>::make_free_balance_be(&pot, Zero::zero());
			let _ = frame_system::Pallet::<T>::dec_providers(&pot).defensive();

			CurrencyOf::<T>::unreserve(&fund.depositor, fund.deposit);
			Funds::<T>::remove(index);
			Self::deposit_event(Event::<T>::Dissolved { para_id: index });
			Ok(())
		}
