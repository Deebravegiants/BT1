### Title
Bad-debt supply-index floor leaves stranded claims that drain the next depositor's cash - (File: contracts/pool/src/interest.rs)

### Summary
When `apply_bad_debt_to_supply_index` socializes a wipeout larger than the market's total supplied value, it clamps `supply_index` up at `SUPPLY_INDEX_FLOOR_RAW` (`RAY/1000`) instead of zero. Suppliers whose claims were nominally wiped out keep `scaled_amount` shares that still unscale to a positive floor value. The next honest depositor's fresh `cash` can then be withdrawn by a wiped-out survivor, leaving the new depositor with an unbacked claim — protocol insolvency and theft of user funds. The bug is acknowledged by an in-repo unit test (`test_raw_cache_seizure_residual_would_drain_fresh_cash_without_supply_guard`, `contracts/pool/tests/interest.rs:430-494`).

### Finding Description
The analog to CVE-2018-12376's memory-corruption class is persistent accounting corruption: the bad-debt write-down does not actually bound the write-down to what suppliers own.

In `contracts/pool/src/interest.rs`, `apply_bad_debt_to_supply_index` computes `reduction_factor = (total_supplied_value - capped_bad_debt) / total_supplied_value`; when `bad_debt >= total_supplied_value` the factor is 0, and the result is floored at `SUPPLY_INDEX_FLOOR_RAW` (`contracts/pool/src/interest.rs:80-88`). Every supply share in the market — including shares whose indexed value was just written down to zero — is then re-valued at `RAY/1000` per share.

On the withdrawal side, `resolve_withdrawal` / `unscale_supply_floor` (`contracts/pool/src/cache/scale.rs:50-67`, `common/src/rates/scaling.rs`) converts those shares into a positive asset claim, and `withdraw::accounting` (`contracts/pool/src/ops/withdraw.rs:57-89`) only gates on `require_reserves` (cash present), `require_utilization_below_max`, and `require_supply_for_debt` — none of which verifies that the surviving shares are backed by pre-deposit value rather than by the floor artifact. The test at `contracts/pool/tests/interest.rs:479-485` shows exactly this: after a wipeout, `resolve_withdrawal(i128::MAX, alice_scaled)` yields `gross == deposit`, i.e., the wiped survivor extracts the new depositor's full deposit, and `cash < bob_claim` for the honest supplier (`contracts/pool/tests/interest.rs:487-492`).

Reachability by a single unprivileged address: `liquidate`/`clean_bad_debt` on the controller drives `pool.seize_positions`, which calls `apply_bad_debt_to_supply_index` (`contracts/controller/src/positions/liquidation/bad_debt.rs`, `contracts/pool/src/ops/seize.rs`). An attacker only needs a market where unpaid debt exceeds supplied value (dust-threshold bad debt cleanup is an unprivileged entrypoint per the rules) plus a tiny surviving supply position; any subsequent `supply` by a victim makes the attacker's stranded claim payable via a normal `withdraw`.

### Impact Explanation
Permanent loss / theft of user funds and market insolvency: the first depositor(s) into a previously wiped market fund withdrawals for accounts whose claims should have been zeroed, and the market's `supplied × supply_index` claim exceeds `cash + outstanding debt` — a broken `revenue <= supplied`-class invariant expressed as `owed > cash` (`contracts/pool/tests/interest.rs:471-477`).

### Likelihood Explanation
Requires a market to reach a state where bad debt meets or exceeds total supplied value — achievable on small/dust markets via `clean_bad_debt` or on undercollateralized liquidation cascades — plus a residual share-holder willing to wait for a fresh deposit. No privileged action, oracle manipulation, or timing beyond normal liquidation is needed.

### Recommendation
When `bad_debt` reaches `total_supplied_value`, burn or zero the outstanding supply shares (e.g., write `supplied = 0` and zero per-position claims at seize time) rather than clamping `supply_index` to `SUPPLY_INDEX_FLOOR_RAW` with shares still outstanding; alternatively, only apply the floor when `reduction_factor > 0`, and revert/flag the market (block `supply` and `withdraw`) once a full wipeout occurs until governance `recapitalize`s it.

pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}

#[test]
fn test_raw_cache_seizure_residual_would_drain_fresh_cash_without_supply_guard() {
    let t = TestSetup::new();
    t.as_contract(|| {
        let alice_scaled_raw = 1_000 * RAY;
        let borrowed_scaled_raw = 1_000 * RAY;
        let mut cache = t.fresh_cache(PoolStateRaw {
            supplied: alice_scaled_raw,
            borrowed: borrowed_scaled_raw,
            revenue: 0,
            borrow_index: RAY,
            supply_index: RAY,
            last_timestamp: 0,
            cash: 0,
        });
        let alice_scaled = Ray::from(alice_scaled_raw);
        let borrow_scaled = Ray::from(borrowed_scaled_raw);

        let bad_debt = cache.unscale_borrow_ceil_ray(borrow_scaled);
        apply_bad_debt_to_supply_index(&mut cache, bad_debt);
        cache.burn_debt(borrow_scaled);

        assert_eq!(
            cache.supply_index().raw(),
            SUPPLY_INDEX_FLOOR_RAW,
            "seize wipeout clamps supply_index UP to RAY/1000, leaving unburned shares a residual"
        );

        let alice_stranded = cache.unscale_supply_floor(alice_scaled);
        assert!(alice_stranded > 0, "wiped survivor keeps a stranded claim");
        assert_eq!(
            cache.cash(),
            0,
            "empty market: claim masked by require_reserves"
        );

        let deposit = alice_stranded;
        let bob_scaled = cache.calculate_scaled_supply(deposit);
        cache.mint_supply(bob_scaled);
        cache.credit_cash(deposit);

        let total_owed = cache.unscale_supply_floor(cache.supplied());
        assert!(
            total_owed > cache.cash(),
            "post-deposit books insolvent: owed {} > cash {}",
            total_owed,
            cache.cash()
        );

        let (burn, gross) = cache.resolve_withdrawal(i128::MAX, alice_scaled);
        cache.require_reserves(gross);
        cache.burn_supply(burn);
        cache.debit_cash(gross);

        assert!(gross > 0, "wiped position pays out real cash");
        assert_eq!(gross, deposit, "Alice extracts exactly Bob's fresh deposit");

        let bob_claim = cache.unscale_supply_floor(bob_scaled);
        assert!(
            cache.cash() < bob_claim,
            "cash {} cannot cover Bob's honest claim {}: fresh depositor lost funds",
            cache.cash(),
            bob_claim
        );
    });

pub(crate) fn accounting(
    env: &Env,
    is_liquidation: bool,
    entry: &PoolWithdrawEntry,
) -> WithdrawOutcome {
    require_nonneg_amount(env, entry.protocol_fee);
    let (mut cache, position) = ops::load_leg(env, &entry.action);

    let (burned, gross_amount) = resolve_close_or_partial(&cache, entry.action.amount, position);
    // Burn first: `protocol_fee_shares` caps the fee mint at `i128::MAX - supplied`.
    let remaining = burn_position(env, &mut cache, position, burned);
    let net_transfer = withhold_liquidation_fee(
        env,
        &mut cache,
        gross_amount,
        is_liquidation,
        entry.protocol_fee,
    );

    // A footprint-only close must not add a utilization gate to same-market
    // net settlement: it burns no shares and moves no cash.
    let empty_close = position.raw() == 0 && entry.action.amount == i128::MAX;
    gate_and_debit(env, &mut cache, net_transfer, is_liquidation || empty_close);

    let snapshot = cache.commit();
    let mutation = cache.position_mutation(remaining, gross_amount);
    WithdrawOutcome {
        cache,
        mutation,
        snapshot,
        net_transfer,
    }
}
