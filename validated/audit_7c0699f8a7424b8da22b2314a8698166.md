### Title
Node-provided secrets TOML file(s) loaded via `-s`/`--secrets` are never permission-checked or restricted, allowing plaintext credential disclosure to local unprivileged users - (File: `core/services/chainlink/config_general.go`, `core/cmd/shell_local.go`)

### Summary
The FOG advisory concerns a plaintext service-account credentials file (`/opt/fog/.fogsettings`) that is world-readable by default, letting any local unprivileged user read secrets and escalate. Chainlink has the analogous artifact: the operator-supplied secrets TOML file (passed via the `-s`/`--secrets` CLI flag) which contains plaintext database URL/password, keystore password, Mercury credentials, LDAP bind password, OIDC client secret, and Pyroscope/Prometheus tokens, as seen in the fixture `core/services/chainlink/testdata/secrets-full.toml`. Unlike Chainlink's own hardening logic for a fixed set of files, this arbitrary, user-specified file path is never checked or tightened.

### Finding Description
`GeneralConfigOpts.Setup` simply reads the secrets file(s) with `os.ReadFile` and merges them into the in-memory `Secrets` struct — no permission validation is performed on the file itself: [1](#0-0) 

Chainlink does have a permission-hardening routine, `checkFilePermissions`, invoked during `runNode`, but it only inspects `RootDir()` and a fixed whitelist of filenames — `secret`, `cookie`, `.password`, `.env`, `.api` — plus the `tls` subdirectory: [2](#0-1) 

The actual secrets TOML file(s) supplied via `-s`/`--secrets` (which is where real plaintext DB passwords, Mercury credentials, LDAP passwords, and OIDC client secrets live, per `secrets-full.toml`) can be located anywhere on disk and under any name, so it is never covered by this whitelist-based check. If an operator creates this file with default umask permissions (e.g., `0644`), any local unprivileged user/process on the host can read it and obtain the plaintext credentials — directly analogous to the FOG `.fogsettings` issue, where a "trusted" configuration/secrets artifact stored in plaintext is left broadly readable because file-permission hardening isn't applied to it.

### Impact Explanation
Exposure of the secrets file contents to an unprivileged local user grants access to database credentials, keystore password, LDAP bind credentials, OIDC client secret, and telemetry/Mercury credentials, which can be leveraged to access the node's Postgres database directly, decrypt/attempt to derive keystore material, or impersonate the node against external Mercury/telemetry services — a direct compromise of confidentiality and potentially integrity of node operations, matching the CVSS 5.3 (C:L/I:L/A:L) profile of the original advisory.

### Likelihood Explanation
Likelihood is moderate: it requires local unprivileged access to the host running the Chainlink node (e.g., a shared server, container escape, or another process on the same host) and depends on the operator's file creation umask/permissions for the secrets file, since Chainlink does not enforce restrictive permissions on it the way it does for the fixed whitelist files.

### Recommendation
Extend `checkFilePermissions` (or add an equivalent check in `GeneralConfigOpts.Setup`) to validate and, if necessary, tighten permissions (e.g., to `0600`/owner-only) on every path passed via `-s`/`--secrets` (and `-c`/`--config`, since it can also embed sensitive material like `AllowOrigins`, headers with tokens, etc.), rather than limiting the check to a hardcoded set of filenames under `RootDir`. Consider failing startup (not just warning) if the secrets file is group/world readable.

### Proof of Concept
1. On a shared host, create `secrets.toml` with contents from `core/services/chainlink/testdata/secrets-full.toml` (containing `Database.URL`, `Password.Keystore`, `Mercury.Credentials`, `WebServer.LDAP.ReadOnlyUserPass`, `WebServer.OIDC.ClientSecret`) using default umask (world-readable, e.g. `0644`).
2. Start the node: `chainlink -c config.toml -s secrets.toml node start`.
3. Observe that `checkFilePermissions` in `core/cmd/shell_local.go` never inspects `secrets.toml`'s path/permissions (it only checks `RootDir/{secret,cookie,.password,.env,.api}`), and `GeneralConfigOpts.Setup` in `core/services/chainlink/config_general.go` merely calls `os.ReadFile` on it.
4. Any other local unprivileged user on the host can `cat secrets.toml` and obtain the plaintext DB password, keystore password, LDAP password, and OIDC client secret.

func (o *GeneralConfigOpts) Setup(configFiles []string, secretsFiles []string) error {
	configs := []string{}
	for _, fileName := range configFiles {
		b, err := os.ReadFile(fileName)
		if err != nil {
			return errors.Wrapf(err, "failed to read config file: %s", fileName)
		}
		configs = append(configs, string(b))
	}

	if configTOML := env.Config.Get(); configTOML != "" {
		configs = append(configs, configTOML)
	}

	o.ConfigStrings = configs

	secrets := []string{}
	for _, fileName := range secretsFiles {
		b, err := os.ReadFile(fileName)
		if err != nil {
			return errors.Wrapf(err, "failed to read secrets file: %s", fileName)
		}
		secrets = append(secrets, string(b))
	}

	o.SecretsStrings = secrets
	return nil
}
