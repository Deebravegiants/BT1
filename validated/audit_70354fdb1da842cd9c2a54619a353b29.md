Based on my review of `packages/contracts/src/Bonding.sol`, `Router.sol`, `Pair.sol`, and `Zap.sol`, I could not confirm a valid analog to CVE-2019-14870 that meets the strict validation bar, but I want to flag an important limitation rather than assert a false negative.

**What I checked and ruled out:**
- The lifecycle/restriction checks (`Lifecycle.Curve` / `Graduating` / `Graduated`, `canGraduate`, `isGraduating`) are consistently enforced across all unprivileged entry points I could read: `Bonding.buy` [1](#0-0) , `Bonding.sell` [2](#0-1) , `Zap._buyInternal` [3](#0-2) , and `Zap._sellInternal` [4](#0-3) . I found no path where an equivalent restriction is checked in most functions but silently skipped in one specific alternate function (the CVE's core bug class — a "not-delegated" flag honored everywhere except S4U2Self).
- `Router.sol`'s trade functions are gated by `onlyRole(BONDING_ROLE)`, which only `Bonding` holds, so they aren't independently reachable by an unprivileged caller in a way that could bypass Bonding's lifecycle gate [5](#0-4) .

**Where I could not complete verification:**
The scan rules explicitly flag "pre-creating or pre-seeding the HyperSwap V2 TOKEN/LT pair before graduation" and the `_seedRebalancing / _pairRebalance / _seedDirectMint` fallbacks as the most bug-prone area — this is exactly the kind of place where a restriction (e.g., "LP must seed at curve-close price") could be enforced in the primary seeding path but be skipped or weakened in one of the fallback branches, which would be a structurally close analog to the CVE's "flag enforced everywhere except one path" pattern. However, `Bonding.sol` is 1534 lines and my read was truncated at line 1000, cutting off `finalizeGraduation`, `_prepareGraduationLiquidity`, `_seedUniswapV2Direct`, `_seedRebalancing`, `_pairRebalance`, `_seedDirectMint`, and `LPLock.recordLock` — the functions most likely to contain this class of bug per the scan's own hints.

Because I cannot prove or disprove root cause in that unread region, I'm not going to output a fabricated finding or a false "no vulnerability" conclusion. Given the indexing/read limits encountered here, a full read of `packages/contracts/src/Bonding.sol` (lines 1000–1534) and `LPLock.sol` would be needed — I'd recommend starting a Devin session with full file access to complete this specific analysis if you want a definitive answer.

        BondingStorage storage $ = _s();

        if (info.lifecycle == Lifecycle.Graduating) revert TokenIsGraduating();
        if (info.lifecycle != Lifecycle.Curve) revert TokenNotTrading();
        // A graduatable curve token must graduate, not sell back below the
        // threshold. The user-facing router triggers graduation up front via
        // `triggerGraduation`; rejecting here stops any router that skipped
        // that step from un-ripening a ready graduation.

        emit Trade(tokenAddress, trader, false, assetOut, amountIn, newCurveSupply, newLtReserve);

    function _sellInternal(
        address tokenAddress,
        uint256 tokenAmount,
        uint256 minUsdcOut
    ) internal returns (uint256 usdcOut) {
        if (tokenAmount == 0) revert InvalidInput();
        if (tokenAddress == address(0)) revert InvalidInput();
        ZapStorage storage $ = _s();
        Bonding bonding_ = $.bonding;
        if (bonding_.creatorOf(tokenAddress) == address(0)) revert TokenNotTrading();
        if (bonding_.isGraduating(tokenAddress)) revert TokenIsGraduating();

        // LT appreciation can push a curve token past the graduation threshold
        // with no buy. Selling now would drag the raised reserve back below it,
        // so graduate the token instead. The holder keeps their tokens and
        // exits on the graduated pool. Nothing is sold, so this fills `0` — only
        // take it when the caller set no floor; a positive `minUsdcOut` reverts
        // so the `usdcOut >= minUsdcOut` guarantee is never silently broken.
        if (bonding_.canGraduate(tokenAddress)) {
            if (minUsdcOut != 0) revert TokenIsGraduating();
            bonding_.triggerGraduation(tokenAddress);
            return 0;
        }
