### Title
`EngineMeter::charge_ref_time` never actually decrements engine fuel, letting contracts execute host-call-equivalent extra WASM instructions for free - (File: substrate/frame/contracts/src/gas.rs)

### Summary
`EngineMeter::charge_ref_time` computes `self.fuel.checked_sub(amount)` but discards the resulting value instead of assigning it back to `self.fuel`, so the engine's internal fuel budget is never actually reduced by the ref_time cost of host function calls. Because `sync_to_executor` hands this un-decremented fuel value back to the wasmi engine as the new remaining-fuel budget, the wasm interpreter is repeatedly granted a "refund" of fuel equal to every host call's own weight cost, letting the contract execute additional real WASM instructions beyond what its `gas_limit` should allow.

### Finding Description
`EngineMeter::charge_ref_time` is the mechanism used at the end of every host function call (via `GasMeter::sync_to_executor`) to fold the ref_time cost that the host function itself charged (via `GasMeter::charge`) back into the wasmi engine's fuel counter, so the engine won't let the contract run more bytecode than the overall remaining gas allows: [1](#0-0) 

```rust
fn charge_ref_time(&mut self, ref_time: u64) -> Result<Syncable, DispatchError> {
    let amount = ref_time
        .checked_div(T::Schedule::get().ref_time_by_fuel())
        .ok_or(Error::<T>::InvalidSchedule)?;

    self.fuel.checked_sub(amount).ok_or_else(|| Error::<T>::OutOfGas)?;
    Ok(Syncable(self.fuel))
}
```

`u64::checked_sub` is a non-mutating method returning `Option<u64>`. The computed `Option` is only used to detect underflow (`.ok_or_else(...)?`); its `Some(value)` payload — the correctly decremented fuel — is discarded, and `self.fuel` is never reassigned. The function then returns `Syncable(self.fuel)`, i.e. the *unchanged, pre-charge* fuel value, which `sync_to_executor` hands straight back to the executor to become wasmi's new fuel counter: [2](#0-1) 

Compare with `EngineMeter::set_fuel`, used by `sync_from_executor`, which correctly reassigns `self.fuel = fuel` on every call: [3](#0-2) 

Effect of the missing assignment: every time a host function returns, the wasmi engine is restored to a fuel level that does not account for the ref_time weight consumed by that host call. This means the engine is granted "free" bonus fuel equal to `ref_time_consumed / ref_time_by_fuel()` on every single host call. The contract can then burn that bonus fuel by executing additional real WASM instructions before the next fuel-exhaustion trap. At the following `sync_from_executor` call, the consumed-fuel delta is computed only from the *engine's* actual fuel counter drop; since the engine started from an artificially inflated baseline, the resulting `weight_consumed` charged against `gas_left` under-reports the true combined cost (host-call cost + bonus instructions actually executed). Because `Weight` subtraction here uses `checked_reduce`, `gas_left` itself is safely never negative — but the *actual* CPU work performed by the contract (extra WASM instructions genuinely executed by wasmi and whose side effects, e.g. storage writes/host calls made from that extra execution, are not reverted) exceeds what `gas_limit` should permit. This under-accounting compounds with every host call in the loop, since the "bonus" is granted anew each time `sync_to_executor`/`charge_ref_time` runs.

### Impact Explanation
An unprivileged contract caller can get real extra WASM execution "for free" relative to the supplied `gas_limit`, because the fuel budget handed back to the wasmi engine after every host call never reflects that host call's own charged weight. Repeated over many host calls in a loop, this compounds into a measurable weight-limit escape: the contract performs more computation (and can persist state changes from that computation) than its metered `gas_consumed()` reflects, which is a concrete gas/weight-limit bypass and DoS-style resource abuse against block weight budgeting.

### Likelihood Explanation
The bug is unconditional — it triggers on every host-function call regardless of `Schedule` parameters or fuel/ref_time boundary alignment (no adversarial quantization boundary is actually required, since the flaw is a missing assignment rather than a rounding edge case). Any contract that makes host calls in a loop with a `gas_limit` set just below what would otherwise be needed for that many instructions will reproduce it deterministically and repeatably, using only the standard `Contracts::upload_code` + `instantiate_with_code` + `call` extrinsics available to any signed account.

### Recommendation
Fix `EngineMeter::charge_ref_time` to actually update `self.fuel`:
```rust
self.fuel = self.fuel.checked_sub(amount).ok_or_else(|| Error::<T>::OutOfGas)?;
Ok(Syncable(self.fuel))
```
Add a regression test asserting that `EngineMeter`/`GasMeter` fuel strictly decreases across a `sync_to_executor` call proportional to the ref_time charged, and that total real wasmi fuel consumption across a full call never exceeds `gas_limit` converted to fuel units.

### Proof of Concept
Rust unit test in `substrate/frame/contracts/src/gas.rs` tests module:
1. Construct `GasMeter::<Test>::new(gas_limit)` with a small limit.
2. Call `sync_from_executor(initial_engine_fuel)` to establish baseline.
3. Call `gas_meter.charge(SimpleToken(cost))` to simulate a host call's own weight charge, reducing `gas_left`.
4. Call `sync_to_executor(before)` and inspect the returned `Syncable` value — assert it equals `previous_fuel - (cost / ref_time_by_fuel())`, i.e. that fuel was actually decremented (this assertion fails today, proving the bug).
5. Extend into an integration test: deploy a contract that loops calling a cheap host function (e.g. `seal_debug_message` or `seal_now`) `N` times with `gas_limit` set just enough for `N` calls' worth of *charged* weight, and assert via `ContractExecResult::gas_consumed` and actual instruction/storage-write count that the contract could not perform more real work than `gas_limit` allows — this assertion should fail, demonstrating the free extra execution.

	/// Hand over the gas metering responsibility from this meter to the executor.
	///
	/// Needs to be called when leaving a host function in order to calculate how much
	/// gas needs to be charged from the **executor**. It updates the last seen executor
	/// total value so that it is correct when `sync_from_executor` is called the next time.
	///
	/// It is important that this does **not** actually sync with the executor. That has
	/// to be done by the caller.
	pub fn sync_to_executor(&mut self, before: RefTimeLeft) -> Result<Syncable, DispatchError> {
		let ref_time_consumed = before.0.saturating_sub(self.gas_left().ref_time());
		self.engine_meter.charge_ref_time(ref_time_consumed)
	}
