### Title
Unbounded Uniswap V4 spot-price venue pricing lets a single manipulated swap drain a curveless intent pair - (File: `sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts`)

### Summary
For "curveless" trading pairs (no `bidPricePolicy`/`askPricePolicy`), the `FXFiller` intent solver prices fills using the raw Uniswap V4 pool spot price (`sqrtPriceX96` → `token0Price`/`token1Price`) instead of a manipulation-resistant TWAP. This is analogous to the xToken incident, where an oracle read from a manipulable AMM state allowed the attacker to drain pools by moving price with a single flash-loan-funded swap. The only mitigation, `checkPriceGuard`, is optional per-chain config and, when unset, leaves the pair fully unguarded.

### Finding Description
`UniswapV4FundingPlanner.computeDirectPoolPriceUsd` derives the exotic token's USD price directly from `sdkPool.token0Price`/`token1Price`, which is computed from the pool's current `sqrtPriceX96` fetched fresh via `StateView.getSlot0` on every call (`sdk/packages/simplex/src/funding/uniswapV4/UniswapV4LiquidityState.ts:139-215`, `sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts:206-275`). This is the pool's instantaneous mid, not a time-weighted average, so an attacker can move it with an ordinary swap immediately before submitting/triggering the solver's fill.

This price feeds `resolveLegRates` → `referenceRate` → `sizeOrder`/`computeLegPolicyOutput`, which determines how much output the solver pays for a given input on the curveless pair (`sdk/packages/simplex/src/strategies/fx.ts:1339-1480`). The only defense is `checkPriceGuard`, a static `referencePrice`/`maxDeviationBps` band that is optional per chain: "The two fields must be set together; omit both to leave the chain unguarded" (`docs/content/developers/evm/simplex/pricing.mdx:70-84`, `sdk/packages/simplex/src/config/filler-toml.ts:23-36`). The internal flow doc for this exact path confirms there is no size/impact adjustment and that the guard is the only defense against "a manipulated, stale, or thin pool" (`sdk/packages/simplex/docs/ai/flows/venue-pricing-uniswap-v4-funded-pairs.md:1-22`).

An unprivileged intent submitter (order source) that also controls or can influence the venue pool (e.g., via a swap in the same block, or targeting a thin/newly-configured pool before the operator sets a guard) can push the pool's mid price away from fair value, causing the solver to either:
- Sell the exotic/output token far below fair value to the attacker's counter-order (theft from the solver's inventory/vault), or
- Overpay in the reverse direction, again transferring value out of the solver. [1](#0-0) [2](#0-1) [3](#0-2) 

### Impact Explanation
This is a direct fund-theft path against the intent solver's own inventory (analogous to the xToken pool being "immediately exhausted" via oracle manipulation): a single manipulated swap against a thin or unguarded Uniswap V4 pool can be used to make the FXFiller fill an intent order at an off-market rate, draining solver-held tokens for less than fair value. Severity is Critical when `priceGuard` is unconfigured for a chain (explicitly a supported, documented configuration state), and still High even with a guard configured, since `checkPriceGuard` only bounds deviation from a static reference, not manipulation within the allowed band, and applies no execution-cost/size-impact adjustment (per the flow doc).

### Likelihood Explanation
Likelihood is Medium-High: it requires only a standard DEX swap transaction against the referenced pool (no privileged role, no consensus/relayer compromise), consistent with the "counterfeit currency"/oracle-manipulation bug class in the reference incident. It is gated by (a) the pool being thin enough to move economically and (b) whether the operator configured `referencePrice`/`maxDeviationBps` for that chain — a config the docs explicitly allow to be omitted.

### Recommendation
- Require `referencePrice`/`maxDeviationBps` (or an equivalent TWAP-based check) to be mandatory whenever `[vault.uniswapV4]` positions are configured, rather than optional.
- Replace or supplement the spot `sqrtPriceX96` read with a Uniswap V4 TWAP oracle (observation-based) for `computeDirectPoolPriceUsd`.
- Apply a size/impact-aware price rather than extending the raw mid linearly across the full quantity (`computeLegPolicyOutput`), and tighten `checkPriceGuard` to also account for pool liquidity depth relative to order size.

### Proof of Concept
1. Operator configures a curveless pair (e.g., USDC/EXOTIC) priced via `[vault.uniswapV4]` without setting `referencePrice`/`maxDeviationBps` for the target chain (an explicitly supported config per `docs/content/developers/evm/simplex/pricing.mdx`).
2. Attacker submits a large swap against the referenced Uniswap V4 pool, shifting `sqrtPriceX96` so `token0Price`/`token1Price` misrepresents fair value.
3. Attacker (or an accomplice) immediately submits/triggers an intent order on the curveless pair; `UniswapV4FundingPlanner.getExoticTokenPrice` returns the manipulated mid, `resolveLegRates`/`computeLegPolicyOutput` size the fill at that rate, and the FXFiller delivers output tokens at the distorted rate.
4. Attacker reverses their initial swap (or lets arbitrageurs restore price), realizing the spread as profit extracted from the solver's inventory. [4](#0-3)

	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}

	/**
	 * Computes the USD price of the non-stable token in a pool.
	 * Returns null if neither currency is USDC/USDT on this chain.
	 */
	private computeDirectPoolPriceUsd(
		pos: HydratedV4Position,
		sdkPool: V4Pool,
		chain: string,
	): { exoticToken: string; priceUsd: Decimal } | null {
		const usdc = this.configService.getUsdcAsset(chain).toLowerCase()
		const usdt = this.configService.getUsdtAsset(chain).toLowerCase()
		const c0 = pos.currency0.toLowerCase()
		const c1 = pos.currency1.toLowerCase()

		if (c0 === usdc || c0 === usdt) {
			// currency0 is stable → exotic is currency1
			// token1Price = "token0 per token1" = USD per exotic
			return {
				exoticToken: c1,
				priceUsd: new Decimal(sdkPool.token1Price.toFixed(18)),
			}
		}

		if (c1 === usdc || c1 === usdt) {
			// currency1 is stable → exotic is currency0
			// token0Price = "token1 per token0" = USD per exotic
			return {
				exoticToken: c0,
				priceUsd: new Decimal(sdkPool.token0Price.toFixed(18)),
			}
		}

		return null
	}

## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.
