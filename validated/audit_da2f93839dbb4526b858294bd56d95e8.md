### Title
Composite `nativeUSD × tokenUSD` Chainlink pricing in `SimplexPaymaster._tokenPrice` allows stale-feed arbitrage against the paymaster's prefunded gas - ([File: evm/src/utils/SimplexPaymaster.sol])

### Summary
`SimplexPaymaster` prices ERC-20 gas payment for every sponsored `UserOperation` by combining two *independently* staleness-checked Chainlink feeds — `nativeOracle` (native/USD) and the per-token `tokenOracle` (token/USD) — instead of a single direct native/token feed [1](#0-0) . This is the same bug class as the reported `WBTC/USD` issue: composing two separately-updated oracle legs introduces a discrepancy window that a single canonical feed would not have.

### Finding Description
`_tokenPrice` reads both feeds via `_getOraclePrice`, which only bounds each feed's own `updatedAt` against `maxOracleAge` independently: [2](#0-1) 

There is no check that the two `updatedAt` timestamps are close to each other, or that both rounds reflect the same market moment. Each feed can independently lag by up to `maxOracleAge` (configurable up to `MAX_ORACLE_AGE` = 7 days, per governance) [3](#0-2) [4](#0-3) , so the effective staleness of the *combined* ratio can be up to `2 × maxOracleAge` out of sync between the native leg and the token leg — a window that would not exist if the contract consulted a single, direct token/native (or token/USD-vs-native/USD from the same round) feed.

`_tokenPrice`'s output directly determines `prefundAmount`, the ERC-20 amount pulled from the sender to cover `maxCost` of native gas in `_prefund` (mode 0x00 via `transferFrom`, mode 0x02 via Permit2) [5](#0-4) . Any unprivileged sender constructing a `PackedUserOperation` that uses this paymaster is a reachable, unprivileged path — exactly the "bandwidth purchaser" role using the paymaster to sponsor cross-chain dispatch gas.

### Impact Explanation
If `nativeOracle` lags (e.g., native asset price has moved but the feed hasn't refreshed, yet is still within `maxOracleAge`) while `tokenOracle` (typically a stablecoin pegged near $1) is fresh, `tokenPrice = nativeUsd * 10^tokenDecimals / tokenUsd` will be computed from a stale native price. A sender can time submission of sponsored UserOps to systematically underpay the ERC-20 amount relative to the paymaster's actual native gas expenditure, draining native ETH held in the paymaster's EntryPoint deposit over repeated operations — a real transfer of value away from the protocol/treasury. This is the same class of "compose two independently-staled legs instead of one canonical feed" risk flagged in the source report, applied here to gas-fee pricing rather than lending collateral valuation.

### Likelihood Explanation
The paymaster is explicitly permissionless — any address can build a valid `UserOperation` using a registered token, and each individual charge is bounded by `maxCost`/permit size, but the exposure compounds across repeated operations during any period where the two feeds' update cadences diverge (which the docstring itself acknowledges varies significantly per chain, "BSC stablecoins ~27s, Base/Ethereum stablecoins up to 24h") [3](#0-2) . No on-chain check currently prevents combining a fresh token feed with a stale native feed (or vice versa), so likelihood is driven purely by feed update cadence mismatch, which is normal chain-to-chain behavior, not an edge case.

### Recommendation
- Require the two oracle rounds to be reasonably synchronized: track and bound `|nativeUpdatedAt - tokenUpdatedAt|` in addition to each feed's own staleness against `maxOracleAge`.
- Where a direct native/token Chainlink feed exists, prefer it over the composite ratio.
- Consider tightening `MAX_ORACLE_AGE` per deployment/token pair rather than allowing a shared, coarse global bound across both legs.

### Proof of Concept
1. Governance registers a token whose `tokenOracle` heartbeats every ~30s (e.g., a BSC-style stablecoin feed) while `nativeOracle` heartbeats up to 24h (per the contract's own documented assumption) [3](#0-2) .
2. Native asset price rises materially on-chain (e.g., via a market move) but `nativeOracle.latestRoundData()` has not yet refreshed; it remains within `maxOracleAge` so `_getOraclePrice` does not revert [6](#0-5) .
3. A sender submits a `UserOperation` through the paymaster; `_tokenPrice` computes `tokenPrice` from the stale (lower) `nativeUsd`, undercharging the ERC-20 amount relative to the true native gas cost `weiCost` that the paymaster/EntryPoint actually pays out [7](#0-6) .
4. Repeating this while the mismatch persists incrementally drains the paymaster's EntryPoint-deposited native balance relative to ERC-20 received.

    function _prefund(
        PackedUserOperation calldata userOp,
        bytes32 userOpHash,
        IERC20 token,
        uint256 tokenPrice,
        address prefunder_,
        uint256 maxCost
    )
        internal
        override
        returns (bool prefunded, uint256 prefundAmount, address prefunder, bytes memory prefundContext)
    {
        bytes calldata data = userOp.paymasterData();
        if (uint8(data[0]) != 0x02) {
            return super._prefund(userOp, userOpHash, token, tokenPrice, prefunder_, maxCost);
        }

        (, uint256 permitAmount, uint256 nonce, uint256 deadline, uint8 v, bytes32 r, bytes32 s) =
            _parsePermit2Data(data);
        prefundAmount = _erc20Cost(maxCost, userOp.maxFeePerGas(), tokenPrice);
        if (prefundAmount > permitAmount) revert InsufficientPermitAmount(permitAmount, prefundAmount);
        // Solidity's own extcodesize revert on a code-less target is not caught by try/catch.
        if (address(PERMIT2).code.length == 0) revert Permit2NotDeployed();

        // Charge the token _fetchDetails already validated as registered and active, rather
        // than re-trusting the mode byte's token field, so the external call never depends
        // on the caller-ordering of the base contract.
        address tokenAddr = address(token);
        // `prefunder_` is who the base says funds the op (userOp.sender today); use it so this
        // branch stays aligned with the mode-0 branch that forwards it to super._prefund.
        address owner = prefunder_;
        try PERMIT2.permitTransferFrom(
            ISignatureTransfer.PermitTransferFrom({
                permitted: ISignatureTransfer.TokenPermissions({token: tokenAddr, amount: permitAmount}),
                nonce: nonce,
                deadline: deadline
            }),
            ISignatureTransfer.SignatureTransferDetails({to: address(this), requestedAmount: prefundAmount}),
            owner,
            abi.encodePacked(r, s, v)
        ) {
            emit Permit2Executed(tokenAddr, owner, prefundAmount, nonce);
        } catch (bytes memory reason) {
            revert Permit2Failed(tokenAddr, reason);
        }

        return (true, prefundAmount, owner, "");
    }

    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
