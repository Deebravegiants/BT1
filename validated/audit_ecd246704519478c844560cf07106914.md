### Title
Supply-index floor resurrects wiped supplier claims and drains later deposits - (File: contracts/pool/src/interest.rs)

### Summary
When bad debt consumes the entire supply-side value, `apply_bad_debt_to_supply_index` raises the computed zero index to `SUPPLY_INDEX_FLOOR_RAW` instead of fully invalidating the outstanding supply-share epoch. Historical shares therefore retain a residual claim despite the intended 100% write-down, and a subsequent withdrawal can consume newly deposited cash. [1](#0-0) 

### Finding Description
The controller exposes permissionless `clean_bad_debt(caller, account_id)` after caller authorization. [2](#0-1)  The cleanup requires open debt and, for the public path, insolvency with collateral no greater than the dust threshold. [3](#0-2) 

During cleanup, every debt position is submitted to the pool as a borrow-side seizure, while unrelated suppliers are not removed. [4](#0-3)  The pool converts those debt shares into their ceiled RAY value, applies bad debt to the supply index, and then burns only the debt shares. [5](#0-4) 

If the bad debt is at least the market's total supplied value, `capped` equals `total_supplied_value`, `remaining` and `reduction_factor` become zero, and the mathematically wiped index is zero. [6](#0-5)  The final `max(SUPPLY_INDEX_FLOOR_RAW)` changes that complete write-down into a positive index, leaving all old scaled supply shares with a positive claim. [7](#0-6) 

A withdrawal then resolves the old position at this positive supply index, requires only sufficient pool cash, verifies that zero supply does not coexist with debt, and debits cash. [8](#0-7) [9](#0-8)  There is no post-mutation backing check that compares all remaining supplier claims with cash plus outstanding debt before payment. [9](#0-8) 

The repository's own raw-cache regression tests demonstrate the same sequence: a complete write-down clamps to the floor, leaves a nonzero stranded claim, accepts fresh cash, and lets the wiped position withdraw exactly that fresh deposit. [10](#0-9) 

### Impact Explanation
A holder of pre-wipeout supply shares can steal assets deposited after bad-debt cleanup. Because all historical scaled shares retain value at the floor, one or more wiped suppliers can withdraw up to their aggregate floor-valued residual until the pool's newly supplied cash is exhausted. [11](#0-10) 

This directly violates the intended socialization semantics: suppliers should absorb a capped loss up to their entire claim, not retain a resurrection dividend backed by unrelated later deposits. The result is theft of user funds and can leave the market's supplier liabilities greater than its assets. [12](#0-11) [13](#0-12) 

### Likelihood Explanation
The trigger is reachable through the permissionless `clean_bad_debt` path once an account is insolvent and its collateral is at or below the dust threshold. [3](#0-2)  A caller does not need to control governance or the pool contract; it only needs an authenticatable address and a qualifying insolvent account. [14](#0-13) 

The strongest exploit requires the seizable debt's ceiled value to be at least the market's total supplied value, which can occur through accrued interest or severe collateral deterioration. Any pre-cleanup supplier with stranded shares can then race subsequent depositors, and earlier suppliers cannot prevent the withdrawal once fresh reserves exist. [5](#0-4) [15](#0-14) 

### Recommendation
Do not use `max(SUPPLY_INDEX_FLOOR_RAW)` to repair a complete write-down. Track a supply-share epoch so that a capped loss of 100% invalidates every old share and initializes a separate epoch/index for future deposits. [1](#0-0) 

If epoching is not feasible, atomically settle or clear aggregate `supplied` and all corresponding controller supply positions before resetting the market; a zero index alone is unsafe because later share issuance must still have a defined divisor. [16](#0-15) 

Additionally, enforce the pool backing invariant before permitting non-liquidation withdrawals from a market touched by bad-debt cleanup. [9](#0-8)  Add an end-to-end test that calls controller `clean_bad_debt`, deposits fresh assets, and asserts that pre-cleanup supply shares resolve to zero rather than withdrawing the fresh deposit. [17](#0-16) 

### Proof of Concept
```text
1. Attacker supplies market M and owns old supply shares S_old.
2. Borrower D incurs debt in M and later becomes socializable bad debt:
   total_debt_usd > total_collateral_usd and collateral <= dust threshold.
3. Any attacker-controlled address calls:
      clean_bad_debt(caller=attacker, account_id=D)
4. For D's M borrow position, the pool computes:
      bad_debt = ceil(S_debt * borrow_index)
      total_supplied_value = supplied * supply_index
      capped = min(bad_debt, total_supplied_value)
   When bad_debt >= total_supplied_value:
      capped = total_supplied_value
      remaining = 0
      reduction_factor = 0
      computed_supply_index = 0
      stored_supply_index = max(0, SUPPLY_INDEX_FLOOR_RAW)
5. S_old is not burned, so it still unscales to:
      stranded_value = floor(S_old * SUPPLY_INDEX_FLOOR_RAW / asset_scale)
6. Victim V calls supply(...) and deposits C >= stranded_value into M.
7. Attacker calls withdraw(..., amount=i128::MAX or stranded_value).
8. Withdrawal checks cash >= stranded_value, burns attacker shares,
   debits C-backed pool cash, and transfers tokens to the attacker.
9. V's honest supply claim remains while the cash backing it has been removed.
```

#[derive(Clone, Copy, PartialEq)]
enum BadDebtGate {
    /// Permissionless: insolvent *and* collateral at or below the dust threshold.
    DustCapped,
    /// Owner-only: insolvent alone, with no cap on the collateral left behind.
    InsolventOnly,
}

/// Requires open debt and the selected insolvency gate, then cleans up the account.
fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    bad_debt::execute_bad_debt_cleanup(env, &mut cache, account_id, &account, &totals);
}
