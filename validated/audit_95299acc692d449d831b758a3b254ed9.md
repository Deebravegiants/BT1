## Title
Unbounded per-request linear scan and retry-loop over attacker-inflatable allowlist causes gateway-wide DoS - (File: `core/capabilities/vault/allow_list_based_auth.go`)

### Summary
The Vault gateway's default `AllowListBasedAuth.AuthorizeRequest` path performs an in-memory `O(N)` linear scan over *all* currently-known allowlisted requests for every single incoming Vault gateway request, and retries this scan up to 11 times with 3-second sleeps between attempts when no match is found. The size `N` of the scanned list is controlled by any linked workflow owner, who can cheaply and repeatedly call the on-chain `AllowlistRequest` function to add arbitrarily many entries. This mirrors the reported bug class ("iterate through all positions... any attacker can inflate the total number... future calls... run out of gas/DOS"): an unprivileged, low-cost action inflates a list that is then linearly scanned on every subsequent unauthenticated request, degrading (or effectively DoSing) the gateway for all users.

### Finding Description
`allowListBasedAuth.AuthorizeRequest` is the default authorizer wired into the Vault `GatewayHandler` whenever no JWT-based auth override is configured: [1](#0-0) 

For every request the gateway routes to the Vault handler, `AuthorizeRequest` calls `findAllowlistedItemWithRetry`, which fetches the *entire* in-memory allowlist and does a full linear scan (`fetchAllowlistedItem`) looking for the request's digest, retrying the whole scan up to `retryCount+1` (11) times with a 3-second sleep between attempts if no match is found: [2](#0-1) 

The list being scanned, `w.allowListedRequests`, is populated by `syncAllowlistedRequests`, which only prunes entries by expiry timestamp — never by count or per-owner cap — so it grows unboundedly with on-chain state: [3](#0-2) 

Any workflow owner who has linked ownership (a permissionless, low-cost on-chain action requiring only an ownership signature) can call `AllowlistRequest` on the `WorkflowRegistry` contract as many times as they want, each call incrementing `TotalAllowlistedRequests` and adding one more entry that the syncer will fetch and keep in memory until expiry: [4](#0-3) 

Because the request path is reachable from any caller hitting the internet-facing Gateway (`gateway.ProcessRequest` → handler → `GatewayHandler.HandleGatewayMessage` → `requestProcessor.ProcessRequest` → `authorizer.AuthorizeRequest`), and the authorization check happens *before* any request is deemed authorized, this scan-and-retry cost is paid for every incoming request — including invalid/malicious ones from unauthenticated parties — while the underlying list size is attacker-inflatable via a cheap, permissionless on-chain call. This is directly analogous to the reported `getPositionIdsByOwner()` DoS: a low-cost repeated call inflates a counter/list that a hot-path lookup function must fully scan.

### Impact Explanation
As the allowlist grows (attacker-controlled), every legitimate and illegitimate Vault gateway request pays an increasing `O(N)` cost, multiplied by up to 11 retry attempts (with 3s sleeps between them for non-matching/invalid requests) plus `O(N)` string formatting for debug logging on each attempt. A single malicious/unauthenticated actor can (a) inflate `N` cheaply and repeatedly via `AllowlistRequest`, and (b) send garbage/never-allowlisted requests that force the full 11×O(N) scan-and-30-second-sleep cycle. Concurrently doing this from multiple connections ties up gateway/Vault-handler resources and materially degrades or denies service for legitimate Vault users on the DON, matching a Medium-severity DoS analog.

### Likelihood Explanation
Reachable by any actor who can (1) link ownership (permissionless, requires only a valid signature and gas) and repeatedly call `AllowlistRequest`, and (2) send unauthenticated JSON-RPC requests to the public gateway HTTP endpoint. No special privilege is required beyond normal workflow-owner linking, making this straightforward to trigger.

### Recommendation
- Replace the linear scan with an indexed/keyed lookup (e.g., map keyed by request digest) instead of iterating the full slice on every request.
- Avoid retry-with-full-rescan semantics; instead re-check only newly synced deltas, or use a shared, incrementally-updated index structure guarded by the same mutex.
- Bound growth of the in-memory/on-chain allowlist per owner (e.g., max active allowlist entries per owner, similar to rate limiting elsewhere in the codebase) and/or cap total in-memory retained entries.
- Avoid building the full `allowedRequestsStrs` debug string list (`O(N)` per attempt) in the hot path; gate this behind a debug-log-level check or drop it.

### Proof of Concept
1. Link workflow ownership for an address on the `WorkflowRegistry` contract (permissionless given a valid signature).
2. Repeatedly call `AllowlistRequest(requestDigest, expiryTimestamp)` with unique digests to inflate `TotalAllowlistedRequests`/`allowListedRequests` to a large number (e.g., hundreds of thousands), each call being a cheap on-chain tx.
3. Send a stream of Vault JSON-RPC requests (e.g., `MethodSecretsList`) with non-matching/garbage digests to the public Gateway HTTP endpoint.
4. Observe that each request triggers `findAllowlistedItemWithRetry`, causing an `O(N)` scan repeated up to 11 times with 3-second sleeps (~30s per request) against the now-large in-memory list, exhausting gateway/Vault handler capacity and increasing latency/failure for legitimate concurrent requests.

func (r *allowListBasedAuth) findAllowlistedItemWithRetry(ctx context.Context, req jsonrpc.Request[json.RawMessage], requestDigest string, requestDigestBytes32 [32]byte) (*workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest, []string, error) {
	for attempt := 0; attempt <= r.retryCount; attempt++ {
		allowedRequests := r.workflowRegistrySyncer.GetAllowlistedRequests(ctx)
		allowedRequestsStrs := make([]string, 0, len(allowedRequests))
		for _, rr := range allowedRequests {
			allowedReqStr := fmt.Sprintf("AuthorizedOwner: %s, RequestDigest: %s, ExpiryTimestamp: %d", rr.Owner.Hex(), hex.EncodeToString(rr.RequestDigest[:]), rr.ExpiryTimestamp)
			allowedRequestsStrs = append(allowedRequestsStrs, allowedReqStr)
		}
		r.lggr.Debugw("AllowListBasedAuth loaded allowlisted requests", "method", req.Method, "requestID", req.ID, "attempt", attempt+1, "allowedRequests", allowedRequestsStrs)

		allowlistedRequest := r.fetchAllowlistedItem(allowedRequests, requestDigestBytes32)
		if allowlistedRequest != nil {
			return allowlistedRequest, allowedRequestsStrs, nil
		}
		if attempt == r.retryCount {
			return nil, allowedRequestsStrs, nil
		}

		r.lggr.Debugw("AllowListBasedAuth request digest not yet allowlisted, retrying",
			"method", req.Method,
			"requestID", req.ID,
			"digestHexStr", requestDigest,
			"attempt", attempt+1,
			"maxAttempts", r.retryCount+1,
			"retryInterval", r.retryInterval)
		if err := sleepWithContext(ctx, r.retryInterval); err != nil {
			r.lggr.Debugw("AllowListBasedAuth retry canceled", "method", req.Method, "requestID", req.ID, "error", err)
			return nil, nil, err
		}
	}

	return nil, nil, nil // unreachable: loop always returns
}

func (r *allowListBasedAuth) fetchAllowlistedItem(allowListedRequests []workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest, digest [32]byte) *workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest {
	for _, item := range allowListedRequests {
		if item.RequestDigest == digest {
			return &item
		}
	}
	return nil
}

func (w *workflowRegistry) syncAllowlistedRequests(ctx context.Context) {
	ticker := w.getTicker(defaultTickIntervalForAllowlistedRequests)
	w.lggr.Debug("starting syncAllowlistedRequests")
	for {
		select {
		case <-ctx.Done():
			w.lggr.Debug("shutting down syncAllowlistedRequests, %s", ctx.Err())
			return
		case <-ticker:
			newAllowListedRequests, totalAllowlistedRequests, head, err := w.getAllowlistedRequests(ctx, w.contractReader)
			if err != nil {
				w.lggr.Errorw("failed to call getAllowlistedRequests", "err", err)
				continue
			}
			w.allowListedMu.Lock()
			// Prune expired requests
			activeAllowlistedRequests := []workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest{}
			expiredRequestsCount := 0
			for _, request := range w.allowListedRequests {
				if int64(request.ExpiryTimestamp) > time.Now().Unix() {
					activeAllowlistedRequests = append(activeAllowlistedRequests, request)
				} else {
					expiredRequestsCount++
				}
			}

			// Add new requests
			activeAllowlistedRequests = append(activeAllowlistedRequests, newAllowListedRequests...)
			w.allowListedRequests = activeAllowlistedRequests
			w.lastSeenAllowlistedRequestsCount = totalAllowlistedRequests
			w.lggr.Debugw("synced allowlisted requests",
				"newRequestsNum", len(newAllowListedRequests),
				"expiredRequestsNum", expiredRequestsCount,
				"activeRequestsNum", len(w.allowListedRequests),
				"lastSeenOnchainRequestsNum", w.lastSeenAllowlistedRequestsCount,
				"blockHeight", head.Height,
			)
			w.allowListedMu.Unlock()
		}
	}
}
