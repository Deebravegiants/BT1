Confirmed: no admin sweep/rescue function exists to recover stranded ETH from `Hinkal`.

### Title
`prooflessDeposit` silently absorbs `msg.value` with no UTXO minted when `erc20Addresses` contains no `address(0)` entries - ([File: contracts/Hinkal.sol])

### Summary
`Hinkal.prooflessDeposit` is `payable`, but `_handleTransfersFromProoflessDeposit` (and `performProoflessDepositChecks`) never validate that `msg.value == 0` when the deduplicated `erc20Addresses` set contains no `address(0)` entry. Any ETH sent alongside an all-ERC20 proofless deposit is neither transferred out, checked, nor represented by any minted UTXO, and there is no admin sweep function to recover it, so it is permanently and irrecoverably absorbed into the contract's general ETH reserve.

### Finding Description
The claimed equality: for an all-ERC20 `erc20Addresses` (no `address(0)` entry), `msg.value` must equal `0` for value conservation, since no UTXO commitment will ever be created to represent any ETH amount.

Tracing `Hinkal.prooflessDeposit` at [1](#0-0) :
1. `hinkalHelper.performProoflessDepositChecks(...)` validates array lengths, `MAX_LEAVES_PD`, non-empty encrypted outputs, and `amounts[i] > 0` — it never inspects `msg.value` at all, as shown in `HinkalHelper.performProoflessDepositChecks` [2](#0-1) .
2. `_calcTokenChangesForProoflessDeposit` deduplicates `erc20Addresses` into `uniqueTokens` [3](#0-2) .
3. `_handleTransfersFromProoflessDeposit` loops only over `uniqueTokens` (which, in the all-ERC20 case, contains no `address(0)` entry) [4](#0-3) . The `if (erc20Address == address(0)) balanceBefore -= msg.value;` branch on line 365 is skipped entirely, and `transferERC20TokenFromOrCheckETH` is called only for `erc20Address != address(0)`, which routes to `transferERC20TokenFrom` (a plain `safeTransferFrom`) and never touches `msg.value` at all [5](#0-4) .
4. `_createProoflessDepositCommitments` creates one on-chain UTXO commitment per entry in `erc20Addresses`/`amounts` exactly as supplied by the caller — nothing here can create a UTXO for ETH unless the caller explicitly included `address(0)` in `erc20Addresses` [6](#0-5) .

Root cause: the function is unconditionally `payable`, and no code path enforces `msg.value == 0` when no ETH leaf is being deposited. The attacker's call: `prooflessDeposit(erc20Addresses=[USDC], amounts=[100], ..., {value: 1 ether})`. The ETH is accepted by the EVM (payable function), the ERC20 branch runs its balance check (`balanceAfter - balanceBefore == amount`) using only the USDC balances (unaffected by ETH), which passes, and the transaction completes successfully with no revert. The 1 ETH sent is now indistinguishable native-currency balance in `Hinkal`, backed by zero UTXOs.

Regarding the exact "future depositor absorbs it" scenario in the question: this specific sub-claim does not hold as literally stated. Because `balanceBefore` in `_handleTransfersFromProoflessDeposit` is computed fresh at call time (`getERC20OrETHBalance(address(0))` minus the *current* `msg.value`), any previously stranded ETH is already baked into `balanceBefore` for a subsequent depositor and cancels out of the `balanceAfter - balanceBefore == amount` delta check; `transferERC20TokenFromOrCheckETH` for ETH also strictly requires `msg.value == _value` (line 118-121 of `Transferer.sol`), so a second, unrelated depositor cannot short their own ETH contribution using the first depositor's strand. However, this does not negate the core issue — the first depositor's ETH remains permanently trapped in `Hinkal`'s general balance regardless, since no code path ever mints a UTXO for it or refunds it, and no sweep/rescue function exists anywhere in the audited contracts (`Transferer.sol`, `TransfererBase.sol`, `OwnerHinkal.sol`) to recover general contract ETH.

### Impact Explanation
Critical — permanent freezing of the caller's own ETH. Any unprivileged EOA who mistakenly or through a buggy integration (e.g., a front-end/relayer bug, or `HinkalWrapper.prooflessDeposit` forwarding excess `msg.value`) sends ETH along with an all-ERC20 `erc20Addresses` array loses that ETH irrecoverably: it becomes indistinguishable general reserve in `Hinkal` with no UTXO, no owner, and no withdrawal mechanism. This is repeatable per transaction and scales with how much ETH is sent each time.

### Likelihood Explanation
No special preconditions are required — this can be triggered by any single unprivileged call to `prooflessDeposit` with a non-empty ERC20-only `erc20Addresses` array and non-zero `msg.value`. It requires no proof generation, no tree state, and costs the attacker (or an accidental caller) only the stranded ETH amount. The realistic trigger is more likely a bug in a caller/integration (like `HinkalWrapper`, which forwards `ethForHinkal = msg.value - feeAmount` regardless of whether `erc20Addresses` contains ETH — see [7](#0-6) ) than intentional self-harm, but the contract itself provides no defense against it.

### Recommendation
In `_handleTransfersFromProoflessDeposit` or `prooflessDeposit`, explicitly require that `msg.value == 0` whenever `address(0)` is not present in `erc20Addresses` (equivalently, track a running `expectedEthValue` accumulated from all `amounts[i]` where `erc20Addresses[i] == address(0)`, and `require(msg.value == expectedEthValue)` before any transfers execute).

### Proof of Concept
Foundry test plan:
1. Deploy `Hinkal` with a mock USDC token and mock verifier/helper wiring as in existing test fixtures.
2. Call `hinkal.prooflessDeposit{value: 1 ether}(erc20Addresses=[usdc], amounts=[100e6], stealthAddressStructures=[...], onChainEncryptedOutputs=[bytes("x")], createBlockedUtxos=false, orderId="")` from `attacker`.
3. Assert: transaction succeeds (no revert), `address(hinkal).balance == 1 ether` after the call, and no on-chain commitment/UTXO for `address(0)` exists (only one commitment, for USDC, was inserted — check emitted commitment events / `erc20Address` field of the single `OnChainCommitment`).
4. Separately call `hinkal.prooflessDeposit{value: 1 ether}(erc20Addresses=[address(0)], amounts=[1 ether], ...)` from a second unrelated `victim2` address; assert this succeeds normally and its own `balanceBefore/balanceAfter` delta check passes using only `victim2`'s own `msg.value`, confirming the strand from step 2 is not consumed to satisfy `victim2`'s deposit (since `Transferer.transferERC20TokenFromOrCheckETH` strictly requires `msg.value == _value`).
5. Confirm there is no function in `Hinkal`, `OwnerHinkal`, `Transferer`, or `TransfererBase` callable by any role to withdraw the stranded 1 ether from step 2, proving it is permanently locked.

    function _calcTokenChangesForProoflessDeposit(
        address[] calldata erc20Addresses,
        uint256[] calldata amounts
    )
        private
        pure
        returns (TokenWithAmount[] memory uniqueTokens, uint256 uniqueCount)
    {
        uniqueTokens = new TokenWithAmount[](erc20Addresses.length);

        for (uint256 i = 0; i < erc20Addresses.length; i++) {
            bool found = false;
            for (uint256 j = 0; j < uniqueCount; j++) {
                if (uniqueTokens[j].erc20Address == erc20Addresses[i]) {
                    uniqueTokens[j].amount += amounts[i];
                    found = true;
                    break;
                }
            }
            if (!found) {
                uniqueTokens[uniqueCount] = TokenWithAmount({
                    erc20Address: erc20Addresses[i],
                    amount: amounts[i]
                });
                uniqueCount++;
            }
        }
    }

    function _handleTransfersFromProoflessDeposit(
        TokenWithAmount[] memory uniqueTokens,
        uint256 uniqueCount
    ) private {
        for (uint256 i = 0; i < uniqueCount; i++) {
            address erc20Address = uniqueTokens[i].erc20Address;
            uint256 amount = uniqueTokens[i].amount;

            uint256 balanceBefore = getERC20OrETHBalance(erc20Address);
            if (erc20Address == address(0)) balanceBefore -= msg.value;

            transferERC20TokenFromOrCheckETH(
                erc20Address,
                msg.sender,
                address(this),
                amount
            );

            uint256 balanceAfter = getERC20OrETHBalance(erc20Address);

            require(
                balanceAfter - balanceBefore == amount,
                "proofless deposit balances must be equal"
            );
        }
    }
