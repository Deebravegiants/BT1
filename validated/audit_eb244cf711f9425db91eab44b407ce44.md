## Custody Analog Found: Stale `TombStone` Enables Original Owner to Reclaim Objects Legitimately Sent to the Burn Address

### Title
Unauthorized object ownership reassignment via stale `TombStone` surviving ungated transfers — (`aptos-move/framework/aptos-framework/sources/object.move`)

### Summary
`object::burn()` performs a "soft burn" by attaching a `TombStone{original_owner}` marker to an object without changing its `owner` field or disabling `allow_ungated_transfer`. The object can therefore continue to be transferred normally through `object::transfer`/`transfer_call`/`transfer_raw` (all of which route through `transfer_raw_inner`). Unlike the `TransferRef`-based path (`transfer_with_ref`), `transfer_raw_inner` never clears a pre-existing `TombStone`. If the object is later transferred (by any subsequent, legitimate owner) to the reserved `BURN_ADDRESS`, `unburn()`'s legacy compatibility branch will match on `owner == BURN_ADDRESS` and hand the object back to the stale `original_owner` recorded from a much earlier, unrelated soft-burn — even though that original owner no longer has any custody claim.

### Finding Description
`burn()` only writes a marker resource, it does not touch ownership: [1](#0-0) 

Ordinary ungated transfers go through `transfer_raw_inner`, which mutates `ObjectCore.owner` but never inspects or removes `TombStone`: [2](#0-1) 

By contrast, the `LinearTransferRef` path explicitly clears any stale `TombStone` before transferring, precisely to prevent later reclaiming via `unburn`: [3](#0-2) 

`unburn()` contains a legacy-compatibility branch that trusts the `TombStone.original_owner` field whenever the *current* owner happens to be `BURN_ADDRESS`, regardless of how the object arrived there: [4](#0-3) 

Because `burn()` neither disables `allow_ungated_transfer` nor is a prerequisite for reaching `BURN_ADDRESS` (any owner can call `object::transfer_call(owner, object, BURN_ADDRESS)` directly, since `transfer_raw`/`verify_ungated_and_descendant` place no restriction on the destination address): [5](#0-4) 

an attacker (the original owner `A`) can:
1. `burn(A, object)` — creates `TombStone{original_owner: A}`, ownership remains `A`.
2. `object::transfer_call(A, object, B)` (or further hops `B -> C -> ...`) — ownership legitimately moves away from `A`; the stale `TombStone{original_owner: A}` is never cleared.
3. At any later point, the current legitimate owner (say `B`) sends the object to `BURN_ADDRESS` via an ordinary `transfer_call`/`transfer` (a normal way to discard/burn an asset, unrelated to `A`'s earlier soft burn).
4. `A` calls `unburn(A, object)`. Since `object_core.owner == BURN_ADDRESS`, the legacy branch fires, `original_owner_addr (A) == signer::address_of(A)` passes, and `transfer_raw_inner(object_addr, A)` restores ownership to `A`.

`A` thereby reclaims custody of an object/asset that a completely different, legitimate owner intentionally sent to the burn address, with no privilege check tying `A` to the object's current custody chain.

### Impact Explanation
This breaks the core custody invariant that "object creation, transfer, burn, extensibility, and ownership refs must preserve the intended controller." Any object type built on `aptos_framework::object` (token objects, objects holding `FungibleStore`s, NFTs, or other object-held value) that is ever soft-burned once in its history is permanently vulnerable: whichever address performed the original `burn()` retains a latent, unprivileged reclaim right that activates whenever the object is later sent to `BURN_ADDRESS` by any subsequent owner. This is theft/misdirection of custody of object-held value and undermines the "burn" semantics that later owners rely on to durably destroy/discard assets.

### Likelihood Explanation
The attack requires no special privileges beyond owning the object once and calling two public entry functions (`burn`, `transfer_call`) that are fully permissionless and part of the standard object API; the victim step (any owner sending the object to `BURN_ADDRESS`) is a normal, expected usage pattern for discarding objects, not an unusual action. No admin/governance assumption is required, and the constant `BURN_ADDRESS` is public.

### Recommendation
Clear (or invalidate) any existing `TombStone` on the object whenever ownership actually changes via `transfer_raw_inner` (mirroring the behavior already implemented in `transfer_with_ref`), so that a `TombStone`'s `original_owner` can only ever refer to the *most recent* owner who burned the object, not a stale address from a prior custody chain. Alternatively, remove the legacy `owner == BURN_ADDRESS` compatibility branch from `unburn()` entirely, or scope it strictly to the tombstone's own record without permitting reclaim once the object has been transferred away from the original burner.

### Proof of Concept
Move pseudocode illustrating the exploit sequence (using the existing test helpers in `object.move`):
```
// Step 1: A soft-burns the object (owner unchanged, TombStone{original_owner: A} created)
object::burn(A, hero);

// Step 2: A transfers the object away normally (TombStone untouched)
object::transfer_call(A, hero_address, B_address);

// Step 3: B independently discards the object by sending it to BURN_ADDRESS
object::transfer_call(B, hero_address, BURN_ADDRESS);

// Step 4: A reclaims the object that B tried to burn
object::unburn(A, hero); // succeeds: owner == BURN_ADDRESS branch, restores ownership to A
```
This diverges from the framework's own existing regression test `test_cannot_unburn_after_transfer_with_ref` [6](#0-5) , which only guards the `TransferRef`-based transfer path, leaving the ungated `transfer`/`transfer_call`/`transfer_raw` path unprotected.

    /// Allow origin owners to reclaim any objects they previous burnt.
    public entry fun unburn<T: key>(
        original_owner: &signer,
        object: Object<T>,
    ) {
        let object_addr = object.inner;
        assert!(exists<TombStone>(object_addr), error::invalid_argument(EOBJECT_NOT_BURNT));

        // The new owner of the object can always unburn it, but if it's the burn address, we go to the old functionality
        let object_core = borrow_global<ObjectCore>(object_addr);
        if (object_core.owner == signer::address_of(original_owner)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object_addr);
        } else if (object_core.owner == BURN_ADDRESS) {
            // The old functionality
            let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
            assert!(
                original_owner_addr == signer::address_of(original_owner),
                error::permission_denied(ENOT_OBJECT_OWNER)
            );
            transfer_raw_inner(object_addr, original_owner_addr);
        } else {
            abort error::permission_denied(ENOT_OBJECT_OWNER);
        };
    }
