### Title
Stale cached `Account.owner` lets a previous NFT holder retain borrow/withdraw authority after transfer - (File: contracts/controller/src/account.rs)

### Summary
The controller caches the account owner inside `Account.owner` at mint time and authorizes all spending entrypoints (`borrow`, `withdraw`, `swap_*`, `multiply`, `flash_position`, `migrate_from_blend`, `repay_debt_with_collateral`) against that cached value via `require_owner_or_delegate`. Because `position-nft` transfers do not notify the controller, transferring the NFT leaves `account.owner` pointing at the seller, so the seller — now a stranger — keeps full spending authority over the account while the new owner is partially locked out. This mirrors CVE-2019-16275's class: identity/source validation is resolved against a stale cached record rather than the live authoritative source, so a legitimate "ownership disconnect" is never honored.

### Finding Description
`create_account_with` stores `owner` into the `Account` struct once, at mint:

- `contracts/controller/src/account.rs:64-70` — `Account { owner: owner.clone(), ... }` persisted alongside the NFT mint; nothing rewrites this field on transfer.

Every privileged position path resolves authority against that cached field:

- `contracts/controller/src/account.rs:115-140` — `is_owner_or_delegate` returns `true` when `caller == owner` (the cached value), and delegate lookup is keyed by that same cached `owner`; `require_owner_or_delegate` panics otherwise.
- `contracts/controller/src/positions/debt.rs:40-57` — `process_borrow` calls `require_owner_or_delegate(env, account_id, caller, &account.owner)` then pays borrowed funds to caller-chosen `to`.
- `contracts/controller/src/positions/liquidation/mod.rs` and the strategy entrypoints use the same guard.

By contrast, owner-only maintenance paths check live NFT ownership: `require_account_owner` reads `storage::account_owner` (the NFT's current owner) rather than `account.owner` (`account.rs:143-148`). The two ownership sources therefore diverge after a transfer:

1. Alice supplies collateral and borrows on `account_id` 7, then sells/transfers the position NFT to Bob via `position-nft::transfer`.
2. `Account.owner` still equals Alice; `position-nft.owner_of(7)` is Bob.
3. Alice calls `withdraw`/`borrow` on account 7 — `caller == account.owner` passes — and drains collateral to an arbitrary `to`. Bob cannot stop it: his `remove_delegate`/`renew_account` work (live check), but he cannot out-transact Alice's cached-owner authority, and neither can he `withdraw` under the cached guard unless a resync path exists (none was found in `account.rs`, `debt.rs`, or `supply.rs`).

I could not fully verify whether `storage::get_account` re-reads the NFT owner into `account.owner` on each load; if it does, this finding collapses. The dual code paths (`account.owner` vs `storage::account_owner`) in the same file strongly suggest they are deliberately different sources, and the permissionless-entrypoints inventory only states that delegate grants go inactive on transfer — it does not claim the owner's own authority is revoked.

### Impact Explanation
Theft of user funds: a seller (or prior holder) of a position NFT retains full spending authority and can `withdraw` all collateral and `borrow` up to the LTV limit, draining the buyer's account. Also temporary freezing: the legitimate new owner cannot act through any `require_owner_or_delegate` path while the stale record stands.

### Likelihood Explanation
Reachable by any unprivileged address that ever held a position NFT: sell/gift the NFT, then exercise the retained authority. No privileged role, oracle manipulation, or flash assist is required. Medium likelihood, since it requires a position-NFT transfer to have occurred, but secondary markets/migrations make this a normal flow.

### Recommendation
Treat the NFT as the single source of truth for ownership: have `storage::get_account` (or `require_owner_or_delegate`) resolve `account.owner` from `position_nft.owner_of(account_id)` at load time, or update `account.owner` inside every guard via `storage::account_owner`. Delegate grants should be keyed under the live owner as well, consistent with the already-live `require_account_owner` check.

### Proof of Concept
1. Alice calls `supply(caller=alice, account_id=0, ...)` → account 7 minted with `account.owner = alice`.
2. Alice calls `position_nft.transfer(alice → bob, token_id=7)`.
3. Alice calls `withdraw(caller=alice, account_id=7, withdrawals=all, to=alice)`; `require_owner_or_delegate` compares `alice == account.owner` (stale) and succeeds; pool pays out Bob's collateral to Alice.
4. Expected: revert `NotAuthorized`. Actual: full withdrawal.
