### Title
Emporium runAction is reachable through a proof whose public inputs are not chain- or contract-scoped, enabling cross-chain replay and, independently, signature-less arbitrary calls from Emporium — (File: contracts/CircomDataBuilder.sol / contracts/Hinkal.sol / contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol)

### Summary
`CircomDataBuilder.formInputForCircom` routes any `transact()` call whose `externalActionId == HINKAL_EMPORIUM_ACTION_ID` and `erc20TokenAddresses.length == 0` into `formInputEmporiumMin`, which builds the SNARK public-input vector from only `emporiumMessage`, `timeStamp`, and `calldataHash` — omitting `block.chainid` and `hinkalAddress` that the normal path (`formInputNormal`/`getSignedMessageHash`) includes. Combined with `buildVerifierId` and `getHashedCalldata` also being chain-agnostic, and `rootHashHinkal`/`rootHashHinkalIndex` not being part of any hash or public input at all, the exact same Groth16 proof and calldata (aside from the freely-adjustable root fields) verifies identically on every chain that has the same verifier and the same `externalActionMap[HINKAL_EMPORIUM_ACTION_ID] → Emporium` registration.

### Finding Description
The equality that should hold but doesn't: `inputForCircom` (the values cryptographically bound by the Groth16 proof) should uniquely identify `(chainId, Hinkal contract instance)` for any action that authorizes fund-moving side effects, the way `formInputNormal` → `getSignedMessageHash` does via `chainId` and `verifyingContract`: [1](#0-0) 

For the Emporium zero-token path, this binding is dropped entirely: [2](#0-1) 

`performHinkalChecks` does pass `block.chainid` and `hinkalAddress` into `formInputForCircom`, but they are silently discarded on this branch: [3](#0-2) 

`buildVerifierId` also never uses `chainId`: [4](#0-3) 

`getHashedCalldata`/`getHashedCalldata1`/`getHashedCalldata2` (the integrity hash checked against `circomData.calldataHash`) never include `chainId`, `verifyingContract`, or `rootHashHinkal`/`rootHashHinkalIndex`: [5](#0-4) 

`rootHashExists` is a purely local, per-chain state check that is not part of the proof's public input in the Emporium-min branch, so the attacker can freely set `rootHashHinkal`/`rootHashHinkalIndex` per target chain (e.g. reuse the genesis root, which is universally valid pre-deposit) without breaking `calldataHash` or the proof: [6](#0-5) 

Dispatch to the external action is keyed only by the chain-agnostic constant `HINKAL_EMPORIUM_ACTION_ID`: [7](#0-6) [8](#0-7) 

Deployment evidence supports that Hinkal-family contracts are intentionally given identical addresses across chains via a deterministic `SAFE_SINGLETON_FACTORY` CREATE2 deployer, which is exactly the precondition needed for `circomData.externalActionData.externalAddress` (baked into the replayed calldata) to still match `externalActionMap[...]` on every target chain: [9](#0-8) 

Root cause and why guards fail:
- `verifyProof`/`buildVerifierId`: chain-agnostic, so identical on all chains for this branch.
- `rootHashExists`: real per-chain check, but decoupled from the proof and calldata hash, so trivially satisfiable per chain.
- `performHinkalChecks`'s `calldataHash` integrity check: passes because it never included chain/contract identity to begin with.
- `_externalTransact`'s `externalActionMap[...] == externalAddress` check: passes because Emporium/Hinkal addresses are deployed deterministically identical across chains.
- Result: the same `(a,b,c)` proof plus the same `CircomData` (only root fields adjusted) reaches `EmporiumUpgradeable.runAction` on every chain with an Emporium instance.

Independently compounding this, `verifyWallet` skips all authorization when `stack.signerAddress == address(0)`: [10](#0-9) 
which lets `runAction`'s stateless branch execute an arbitrary `op.endpoint.call{value: op.value}(op.callData)` from Emporium itself: [11](#0-10) 

### Impact Explanation
Attacker gains: the ability to force any Emporium instance (on any chain where the fixed `HINKAL_EMPORIUM_ACTION_ID` is registered to it) to execute attacker-chosen calls (e.g. draining held ERC20 tokens via `transfer`, or moving native ETH balance) with the exact same `(a,b,c)` proof and calldata blob, replayed unchanged across 5 live deployments. This is theft of protocol/relay-held or in-flight user funds held in Emporium, executed without any wallet owner's or prover's authorization — a Critical impact (direct theft of shielded/in-flight funds, executing calls a wallet owner never authorized). It is fully repeatable per chain and per `emporiumMessage` value (bounded only by `usedMessages` nonce reuse per chain, which is trivially avoidable by incrementing the message value).

### Likelihood Explanation
Preconditions: `HINKAL_EMPORIUM_ACTION_ID` registered to Emporium identically on each chain (near-certain, fixed protocol action), Emporium/Hinkal deployed to identical addresses across chains (supported by the `HinkalFactoryDeployer`'s use of the `SAFE_SINGLETON_FACTORY` CREATE2 pattern), and Emporium holding balance to steal. Attacker cost is limited to generating one Groth16 proof for the minimal 3-signal public input (no funds or valid nullifiers required for this branch) and paying gas per chain. Feasibility is high given the codebase's stated multi-chain design intent for Emporium; repeatable across every chain and every unused `emporiumMessage`.

### Recommendation
Bind `block.chainid` and the deployed `hinkalAddress` (and ideally the target `externalActionData.externalAddress`) into the public input for `formInputEmporiumMin` exactly as `formInputNormal` does via `getSignedMessageHash`, and include `chainId`/`verifyingContract` in `getHashedCalldata`/`calldataHash`. Also require `stack.signerAddress != address(0)` (i.e. always require and verify the EIP-712 signature) rather than allowing an unauthenticated ops path in `EmporiumUpgradeable.runAction`/`verifyWallet`.

### Proof of Concept
Foundry test plan:
1. Deploy two independent Hinkal + Emporium + verifier stacks representing chain A (`block.chainid = 1`) and chain B (`block.chainid = 42161`), each with `registerExternalAction(HINKAL_EMPORIUM_ACTION_ID, emporiumAddress)` and identical Emporium proxy address (mock via `vm.etch` at the same address, or deploy with the same CREATE2 salt/deployer nonce to mirror production behavior).
2. Fund only chain B's Emporium with an ERC20 balance.
3. Off-chain, generate one Groth16 proof `(a,b,c)` for the `MainEVMCircuitMin` circuit whose only public signals are `emporiumMessage`, `timeStamp`, `calldataHash`, with `externalActionMetadata` encoding an `EmporiumStack{signerAddress: address(0), ops:[{endpoint: token, invokeWallet:false, value:0, callData: transfer(attacker, balance)}]}`.
4. Call `Hinkal_A.transact(a,b,c,dims,circomData)` — assert it reverts or succeeds harmlessly (no funds on A).
5. Call `Hinkal_B.transact(a,b,c,dims,circomData)` (identical `a,b,c` and `circomData`, only `rootHashHinkal`/`rootHashHinkalIndex` adjusted to a root valid on chain B, e.g. `0`/pre-deposit state) — assert `verifyProof` succeeds, `_externalTransact` finds `externalActionMap[HINKAL_EMPORIUM_ACTION_ID] == emporiumAddress`, `runAction` executes the `transfer` call, and the attacker's token balance increases by Emporium B's full balance while the two `Hinkal` instances never shared any nullifier/root state.
6. Assert the equality-break directly: log `inputForCircom` computed via `formInputForCircom` for chain A vs chain B calls and show they are byte-identical despite differing `block.chainid`.

    function formInputForCircom(
        uint256 chainId,
        address verifyingContract,
        CircomData calldata circomData
    ) internal pure returns (uint256[] memory) {
        if (
            circomData.externalActionData.externalActionId ==
            HINKAL_EMPORIUM_ACTION_ID &&
            circomData.erc20TokenAddresses.length == 0
        ) {
            return formInputEmporiumMin(circomData);
        } else {
            return formInputNormal(chainId, verifyingContract, circomData);
        }
    }

    function formInputEmporiumMin(
        CircomData calldata circomData
    ) internal pure returns (uint256[] memory input) {
        input = new uint256[](circomData.publicSignalCount);

        uint16 index = 0;

        input[index++] = circomData.emporiumMessage;

        input[index++] = circomData.timeStamp;
        input[index++] = circomData.calldataHash;
    }
