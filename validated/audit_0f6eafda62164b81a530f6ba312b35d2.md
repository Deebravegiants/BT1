Based on my research, I found a genuine binding break in the OAuth callback flow that matches the report's bug class (a field trusted/acted upon without correct validation, here: the callback `shop` value used to select the host that receives the `client_secret`).

### Title
Missing shop-domain validation in OAuth callback allows attacker-controlled host to receive `client_id`/`client_secret` - ([File: lib/shopify_api/auth/oauth.rb])

### Summary
`ShopifyAPI::Auth::Oauth.validate_auth_callback` uses `auth_query.shop` directly to build the host that receives the app's `client_id` and `client_secret` when exchanging the authorization code for an access token, without ever passing it through `ShopifyAPI::Utils::ShopValidator.sanitize!`, even though this validator exists specifically for that purpose elsewhere in the codebase.

### Finding Description
In `validate_auth_callback`, the only check performed on `auth_query.shop` is that it is part of the HMAC-signed payload via `Utils::HmacValidator.validate(auth_query)`: [1](#0-0) 

The HMAC only proves the `shop`, `code`, `host`, `state`, `timestamp` tuple was signed together with the configured `api_secret_key` — it does **not** prove that `shop` is a legitimate `*.myshopify.com` (or otherwise trusted) domain. Immediately after that check, `auth_query.shop` is used unmodified both to construct the `Session` used to target the token-exchange request and to populate the request body containing the app's `client_id`/`client_secret`: [2](#0-1) 

The `Session` object's `shop` attribute is used by `Clients::HttpClient` to build the base URL (`https://#{shop}/admin/oauth`) that the outbound `access_token` POST — carrying `client_id`, `client_secret`, and the authorization `code` — is sent to. The gem does have a purpose-built safeguard for exactly this class of problem, `ShopifyAPI::Utils::ShopValidator.sanitize!`, which restricts the shop host to `TRUSTED_SHOPIFY_DOMAINS`: [3](#0-2) 

However, this validator is never invoked from `validate_auth_callback` (or anywhere in `lib/shopify_api/auth/oauth.rb`). The identity binding that should hold is: `host that is HMAC-authenticated == host that is verified to be a genuine Shopify domain`. Because `sanitize!`/`sanitize_shop_domain` is never called on `auth_query.shop`, this equality is not enforced — the code only checks that the `shop` string was HMAC-signed together with the rest of the query, not that it resolves to a `myshopify.com`-family domain.

### Impact Explanation
If a party positioned to influence the value of the `shop` query parameter delivered to the app's callback (e.g., a callback URL that a user is tricked into visiting, or any flow where the `shop` value going into `AuthQuery` is not strictly re-derived from a value already known to be a real Shopify domain) can get an arbitrary host into `auth_query.shop`, the resulting POST request — containing the app's `client_id` and `client_secret` in the body — would be sent to that attacker-controlled host instead of Shopify. This is a credential-leakage/SSRF-with-credentials condition: the app's `client_secret` would be exfiltrated to a non-Shopify host.

### Likelihood Explanation
Likelihood is constrained by the fact that `shop` is part of the HMAC-signed payload, so a fully unauthenticated attacker who has no way to obtain a validly-signed callback for an arbitrary `shop` cannot trivially trigger this. In the standard OAuth redirect flow, Shopify itself signs and sets `shop`, so under that specific call path exploitation requires a scenario where the host application passes through attacker-supplied `shop`/`hmac` pairs without additional checks. The core defect — the complete absence of `ShopValidator.sanitize!` in this code path, despite the validator existing precisely for this purpose — is nonetheless a real gap relative to the equality that should be enforced.

### Recommendation
Call `ShopifyAPI::Utils::ShopValidator.sanitize!(auth_query.shop)` (or `sanitize_shop_domain`) inside `validate_auth_callback` before using `auth_query.shop` to build the `null_session` / outbound access-token request, raising `Errors::InvalidShopError` for any shop value that does not resolve to a trusted Shopify domain — mirroring the protection `ShopValidator` already provides for other entry points.

### Proof of Concept
Not independently reproducible as a standalone unprivileged exploit within this gem alone, since the `hmac` field cryptographically binds `shop` to the rest of the query and requires the correct `api_secret_key` to forge; a concrete PoC would depend on how the host application sources `shop`/`hmac` pairs before constructing `AuthQuery`. The structural gap — `sanitize!` never being invoked in `lib/shopify_api/auth/oauth.rb` — is verifiable directly by inspecting `validate_auth_callback` [4](#0-3)  against the validator definition [5](#0-4) .

        def validate_auth_callback(cookies:, auth_query:)
          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::InvalidOauthError, "Invalid OAuth callback." unless Utils::HmacValidator.validate(auth_query)
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = cookies[SessionCookie::SESSION_COOKIE_NAME]
          raise Errors::NoSessionCookieError unless state

          raise Errors::InvalidOauthError,
            "Invalid state in OAuth callback." unless state == auth_query.state

          null_session = Auth::Session.new(shop: auth_query.shop)
          body = {
            client_id: Context.api_key,
            client_secret: Context.api_secret_key,
            code: auth_query.code,
            expiring: Context.expiring_offline_access_tokens ? 1 : 0, # Only applicable for offline tokens
          }

          client = Clients::HttpClient.new(session: null_session, base_path: "/admin/oauth")
          response = begin
            client.request(
              Clients::HttpRequest.new(
                http_method: :post,
                path: "access_token",
                body: body,
                body_type: "application/json",
              ),
            )
          rescue ShopifyAPI::Errors::HttpResponseError => e
            raise Errors::RequestAccessTokenError,
              "Cannot complete OAuth process. Received a #{e.code} error while requesting access token."
          end

          session_params = T.cast(response.body, T::Hash[String, T.untyped]).to_h
          session = Session.from(shop: auth_query.shop,
            access_token_response: Oauth::AccessTokenResponse.from_hash(session_params))

        [
          "shopify.com",

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
