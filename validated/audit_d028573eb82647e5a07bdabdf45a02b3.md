### Title
RAY-value overflow in `scaled_to_original` permanently freezes a whale-scale market once the borrow index outgrows the value ceiling - (File: `common/src/rates/scaling.rs`)

### Summary
The analog of CVE-2015-6925 — a cheap, unprivileged input that produces a disproportionate, unrecoverable denial of service — maps onto XOXNO Lending's accrual path: every user-facing verb first calls `global_sync`, which calls `accrue_step`, whose first arithmetic is `scaled_to_original(borrowed, borrow_index)`. That multiply panics with `MathOverflow` once `scaled × index` exceeds `i128::MAX`. The borrow-index ceiling (`MAX_BORROW_INDEX_RAY = 10^36`) engages only *after* that multiplication, so on a large book the value ceiling is reached first. From that block onward, `supply`, `withdraw`, `repay`, `liquidate`, `clean_bad_debt`, `flash_loan`, and `update_indexes` on that market all revert on the same panic: every verb accrues first.

### Finding Description
`scaled_to_original` is a raw `Ray::mul` with no ceiling guard [1](#0-0) . `accrue_step` invokes it on the market's total `borrowed` and `supplied` shares before computing utilization [2](#0-1) . `global_sync` runs `accrue_step` unconditionally at the head of every pool mutation, looping over yearly chunks [3](#0-2) . A single unprivileged address can reach the condition: `supply` a token amount near the admitted cap maximum (`~170 billion` whole tokens per `docs/reference/formulas.md`), then `borrow` enough to hold utilization on the steep (slope3) segment of the rate curve. The borrow index then compounds past ~170x and the next accrual panics. The repository's own stress test reproduces this end-to-end: `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` asserts `MATH_OVERFLOW` from `try_update_indexes_for` and that both `try_withdraw_raw` and `try_repay` fail with the same error [4](#0-3) . `compound_interest`'s own exponent is also an unguarded `i128` conversion that panics [5](#0-4) .

### Impact Explanation
Permanent freezing of funds and a contract unable to operate: once `borrowed_ray × borrow_index ≥ i128::MAX`, no accrual-touching operation on that (hub, token) book can ever succeed — suppliers cannot withdraw, borrowers cannot repay, liquidators cannot liquidate, bad debt cannot be cleaned or recapitalized. The index cap never engages because the panic precedes it [6](#0-5) . This is not a fail-closed oracle DoS or a budget limit: it is an irreversible arithmetic poison state installed through ordinary `supply`/`borrow` calls.

### Likelihood Explanation
Reachable by any unprivileged caller through `controller::supply` (dust-leg-free, accepts maximum-cap deposits) and `controller::borrow`. Cost is high — the attacker must supply whale-scale principal and hold high utilization while compounding accrues — and the docs disclose the numeric bound, but no code path prevents entering the state, recovers from it, or emits an alarm [7](#0-6) . An attacker could also force it cheaper by borrowing to pin utilization at the slope3 maximum on an already-large third-party book, then simply waiting; `update_indexes` is permissionless so no privileged action is needed to trigger the panic once the index crosses.

### Recommendation
Make accrual fail-soft instead of panicking: clamp `borrow_index` at `MAX_BORROW_INDEX_RAY` *before* evaluating `scaled_to_original`, or skip the utilization/reward computation when the index is saturated and pin it. Alternatively, reject `supply`/`borrow` amounts whose RAY value cannot survive accrual to the index cap (`supplied_ray` such that `supplied_ray × MAX_BORROW_INDEX_RAY` overflows), mirroring `require_cap_within_asset_domain` for caps [8](#0-7) . Emit an event when a market nears the ceiling so keepers can act before the freeze.

```rust
loop {                                            // permissionless update_indexes
    t.advance_time(YEAR_SECS);

}
// => GenericError::MathOverflow from scaled_to_original, index < cap.
// Market permanently frozen:
assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
// liquidate / clean_bad_debt / flash_loan fail identically — all accrue first.
```

```rust
/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
```
