Looking at `Plugin.Admit` in `plugin/pkg/admission/podnodeselector/admission.go`, the `labels.Conflicts()` check and the `labels.Merge()` call both operate on the exact same `pod.Spec.NodeSelector` map within a single, synchronous function invocation, with no intervening code that could mutate the map between them: [1](#0-0) 

The only transformation between the two calls is `labels.Set(pod.Spec.NodeSelector)`, a read-only type conversion (not a copy that could diverge), so `Conflicts()` and `Merge()` always see identical data — there is no "mutation window" for a benign key to be added between the check and the merge as the question's premise assumes. `labels.Conflicts` and `labels.Merge` themselves are pure, side-effect-free functions over their input maps: [2](#0-1) 

Additionally, `Admit` calls `p.Validate` at the end, which re-runs the same `Conflicts` check against the now-merged `pod.Spec.NodeSelector` and a freshly-fetched `namespaceNodeSelector`: [3](#0-2) 

Since `Merge` makes the namespace-mandated key's value win only when the pod doesn't already specify that key (and the pod's own value wins otherwise, by design — "second selector wins"), there is no scenario where an attacker can override a mandatory namespace-level key with a conflicting value while both `Conflicts()` calls and `Merge()` see a consistent snapshot. The test suite in `admission_test.go` already exercises exactly this scenario (conflicting pod vs. namespace selectors) and confirms admission is rejected: [4](#0-3) 

There is no code path supporting an intervening-mutation race as hypothesized; the premise does not hold against the actual (single-threaded, single-object-reference) implementation.

// Conflicts takes 2 maps and returns true if there a key match between
// the maps but the value doesn't match, and returns false in other cases
func Conflicts(labels1, labels2 Set) bool {
	small := labels1
	big := labels2
	if len(labels2) < len(labels1) {
		small = labels2
		big = labels1
	}

	for k, v := range small {
		if val, match := big[k]; match {
			if val != v {
				return true
			}
		}
	}

	return false
}

// Merge combines given maps, and does not check for any conflicts
// between the maps. In case of conflicts, second map (labels2) wins
func Merge(labels1, labels2 Set) Set {
	mergedMap := Set{}

	for k, v := range labels1 {
		mergedMap[k] = v
	}
	for k, v := range labels2 {
		mergedMap[k] = v
	}
	return mergedMap
}
