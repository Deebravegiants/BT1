### Title
View-role GraphQL users can read bridge outgoing authentication tokens via `bridges`/`bridge` queries - ([File: core/web/resolver/query.go])

### Summary
The GraphQL `Bridge`/`Bridges` queries in `core/web/resolver/query.go` are gated only by `authenticateUser(ctx)`, which is the lowest privilege check (any authenticated session, inherently granting "view" access), yet the returned `BridgeResolver` exposes the bridge's `OutgoingToken`, a credential used to authenticate outbound requests to the external adapter.

### Finding Description
`authenticateUser` in `core/web/resolver/auth.go` only checks that a GQL session exists; it does not check role at all, and by design "presence of user inherently provides 'view' access" [1](#0-0) . The `Bridge` and `Bridges` query resolvers use exactly this lowest-tier check before returning full `BridgeType` records [2](#0-1) .

The returned `BridgeResolver` exposes `OutgoingToken()`, which returns `r.bridge.OutgoingToken` directly — a live secret token that chainlink uses to authenticate itself to the external bridge adapter [3](#0-2) . This mirrors the underlying `BridgeType.OutgoingToken` field, which is stored and retrieved in cleartext (unlike `IncomingTokenHash`, which is salted/hashed) [4](#0-3) .

This is structurally analogous to the Frogman bug class: a read-tier ("view"/PERM_READ-equivalent) principal is able to call a query that returns a credential (`outgoingToken`) that should only be available to higher-privileged (edit/admin) users, similar to how `fm_list_managers`/`fm_whos_calling` exposed AMI manager secrets and SIP credentials to PERM_READ callers.

By contrast, the REST HTTP route for the same secret — `POST /v2/bridge_types` (bridge creation, which returns the `incomingToken`) — requires edit role [5](#0-4) , showing the intended privilege bar is higher than "view" for bridge secrets, but the GraphQL read path does not enforce it.

### Impact Explanation
Any authenticated Chainlink node Operator UI user with the lowest role (`view`) can enumerate all configured bridges and their `outgoingToken` values via the `bridges`/`bridge` GraphQL queries. This token is the credential Chainlink presents to the external bridge/adapter service, so its disclosure allows a low-privileged, otherwise read-only user to impersonate the node when talking to (or crafting requests toward) the external adapter, i.e., a form of secret/key disclosure and potential request impersonation, consistent with the "VC:H" impact category in the referenced CVE.

### Likelihood Explanation
Likelihood is high for any deployment that grants "view" role sessions to less-trusted users (a common Chainlink RBAC use case), since exploitation requires only a valid authenticated GraphQL session and a single `bridges { results { outgoingToken } }` query — no additional privilege escalation or timing is needed.

### Proof of Concept
1. Authenticate as a user with role `view` (lowest role) to obtain a GQL session cookie.
2. Send the following GraphQL query to the node's `/query` endpoint:
```graphql
query {
  bridges(limit: 100) {
    results {
      name
      url
      outgoingToken
    }
  }
}
```
3. Observe that `outgoingToken` for every configured bridge is returned, despite the caller only holding view-level access, matching the behavior of `Bridge(id)` for a specific bridge as well [2](#0-1) .

### Recommendation
Not applicable in ask-only mode; conceptually, `Bridge`/`Bridges` resolvers (or the `OutgoingToken` field itself) should require at least `authenticateUserCanEdit`/admin, or the `outgoingToken` field should be omitted/redacted for `view`-role sessions, consistent with how `IncomingToken` is only exposed on creation.

// Bridge retrieves a bridges by name.
func (r *Resolver) Bridge(ctx context.Context, args struct{ ID graphql.ID }) (*BridgePayloadResolver, error) {
	if err := authenticateUser(ctx); err != nil {
		return nil, err
	}

	name, err := bridges.ParseBridgeName(string(args.ID))
	if err != nil {
		return nil, err
	}

	bridge, err := r.App.BridgeORM().FindBridge(ctx, name)
	if err != nil {
		if errors.Is(err, sql.ErrNoRows) {
			return NewBridgePayload(bridge, err), nil
		}

		return nil, err
	}

	return NewBridgePayload(bridge, nil), nil
}

// Bridges retrieves a paginated list of bridges.
func (r *Resolver) Bridges(ctx context.Context, args struct {
	Offset *int32
	Limit  *int32
}) (*BridgesPayloadResolver, error) {
	if err := authenticateUser(ctx); err != nil {
		return nil, err
	}

	offset := pageOffset(args.Offset)
	limit := pageLimit(args.Limit)

	brdgs, count, err := r.App.BridgeORM().BridgeTypes(ctx, offset, limit)
	if err != nil {
		return nil, err
	}

	return NewBridgesPayload(brdgs, safeInt32(count)), nil
}
