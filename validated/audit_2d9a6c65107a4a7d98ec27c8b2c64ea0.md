Audit Report

## Title
Missing role restriction on `GET /v2/external_initiators` discloses initiator credentials to view-only users - (File: core/web/router.go)

## Summary
The `GET /v2/external_initiators` route is registered without any role-elevation wrapper, unlike the `POST`/`DELETE` routes for the same resource which require `auth.RequiresEditRole`. As a result, any authenticated API user with the lowest-privilege `view` role can list all configured External Initiators and receive each one's `AccessKey` and `OutgoingToken` in the JSON response.

## Finding Description
In `v2Routes`, the external initiator routes are defined as: `authv2.GET("/external_initiators", paginatedRequest(eia.Index))` with no role check, while `POST` and `DELETE` on the same path are wrapped in `auth.RequiresEditRole`, per `core/web/router.go:263-266`. The `Index` handler in `ExternalInitiatorsController.Index` (`core/web/external_initiators_controller.go:50-59`) fetches all external initiators and converts each into a `presenters.ExternalInitiatorResource` with no field redaction. That presenter type explicitly includes `AccessKey` and `OutgoingToken` as JSON fields, populated directly from the `bridges.ExternalInitiator` model in `NewExternalInitiatorResource` (`core/web/presenters/external_initiators.go:57-77`). These two fields are authentication material: `AccessKey` pairs with a secret to authenticate calls to Chainlink, and `OutgoingToken`/`OutgoingSecret` are generated as credentials the node uses when calling back into the initiator, as seen in `bridges.NewExternalInitiator` (`core/bridges/external_initiator.go:36-57`). Notably `HashedSecret` and `OutgoingSecret` are correctly excluded from this list resource, but `AccessKey` and `OutgoingToken` are not — an inconsistent and incomplete redaction. No auth middleware, role wrapper, or presenter-level filtering intercepts this for the `view` role; `auth.Authenticate` only requires a valid session/token of any role, and there is no subsequent role gate on this specific route as there is for the mutating routes on the same resource.

## Impact Explanation
This is a credential/secret exfiltration issue: an authenticated user provisioned with the minimal `view` role — intended for read-only dashboard access — can retrieve `AccessKey` and `OutgoingToken` for every configured External Initiator via a single GET request. This directly maps to the in-scope "key/secret exfiltration" impact category and represents a real least-privilege/role-segregation violation, since the same resource's write operations are correctly gated behind `edit` role.

## Likelihood Explanation
Exploitation requires only an authenticated `view`-role API token — a documented, supported privilege tier for read-only API consumers — and a single unauthenticated-role-elevation-free HTTP GET call to `/v2/external_initiators`. No race condition, timing, or additional vulnerability chaining is required, making this trivially and repeatably reproducible for any deployment that issues `view`-role tokens.

## Recommendation
Wrap `GET /v2/external_initiators` with `auth.RequiresEditRole` (or a comparable role check) to match the write operations on the same resource, or alternatively strip `AccessKey` and `OutgoingToken` from `ExternalInitiatorResource` for non-privileged roles, consistent with how `HashedSecret`/`OutgoingSecret` are already excluded.

## Proof of Concept
1. Provision an API user/token with `UserRoleView`.
2. Authenticate and issue `GET /v2/external_initiators` (routed in `core/web/router.go:264`).
3. Observe the JSON-API response includes `accessKey` and `outgoingToken` for every configured external initiator, sourced from `presenters.NewExternalInitiatorResource` (`core/web/presenters/external_initiators.go:67-77`), despite `view` being the lowest privilege role and creation/deletion of initiators on the same resource requiring `edit`. func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
```go
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}
```

```go
func NewExternalInitiatorResource(ei bridges.ExternalInitiator) ExternalInitiatorResource {
	return ExternalInitiatorResource{
		JAID:          NewJAID(strconv.FormatInt(ei.ID, 10)),
		Name:          ei.Name,
		URL:           ei.URL,
		AccessKey:     ei.AccessKey,
		OutgoingToken: ei.OutgoingToken,
		CreatedAt:     ei.CreatedAt,
		UpdatedAt:     ei.UpdatedAt,
	}
}
```

```go
// NewExternalInitiator generates an ExternalInitiator from an
// auth.Token, hashing the password for storage
func NewExternalInitiator(
	eia *auth.Token,
	eir *ExternalInitiatorRequest,
) (*ExternalInitiator, error) {
	salt := utils.NewSecret(utils.DefaultSecretSize)
	hashedSecret, err := auth.HashedSecret(eia, salt)
	if err != nil {
		return nil, pkgerrors.Wrap(err, "error hashing secret for external initiator")
	}

	return &ExternalInitiator{
		Name:           strings.ToLower(eir.Name),
		URL:            eir.URL,
		AccessKey:      eia.AccessKey,
		HashedSecret:   hashedSecret,
		Salt:           salt,
		OutgoingToken:  utils.NewSecret(utils.DefaultSecretSize),
		OutgoingSecret: utils.NewSecret(utils.DefaultSecretSize),
	}, nil
}
```
