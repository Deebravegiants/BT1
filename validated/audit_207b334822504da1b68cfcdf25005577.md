### Title
Emporium min-dimension path lets `runAction` move ETH via `op.value`/`op.callData` with zero balance-conservation checks - ([File: contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol], [File: contracts/Hinkal.sol])

### Summary
When `Hinkal.transact` is called with `circomData.erc20TokenAddresses.length == 0` and `externalActionId == HINKAL_EMPORIUM_ACTION_ID`, `EmporiumUpgradeable.runAction` still executes its full `stack.ops` loop (arbitrary `op.endpoint.call{value: op.value}(op.callData)`), but every balance-conservation loop that would normally tie moved value to `deltaAmountChanges`/`amountChanges` is skipped because it iterates over the zero-length `erc20TokenAddresses` array. This lets any ETH balance sitting in the Emporium contract be moved to an attacker-chosen endpoint with zero on-chain accounting.

### Finding Description
The claimed broken equality is: "tokens leaving an action == `-deltaAmountChanges`" - i.e., in `runAction`, `balanceChange` computed from `getBalancesForArray` before/after must reconcile with `deltaAmountChanges[i]` [1](#0-0) , and in `Hinkal.transact`, `balanceDif == amountChanges[i] + utxoAmount` [2](#0-1) .

Both of these checks are implemented as `for` loops over `circomData.erc20TokenAddresses`. When `erc20TokenAddresses.length == 0` (the min-dimension path), both loops execute zero iterations, so the equality is never evaluated at all - not "checked and found equal," but literally never checked [3](#0-2) [4](#0-3) .

Meanwhile, the `stack.ops` execution loop in `runAction` has no dependency on `erc20TokenAddresses.length` or `deltaAmountChanges.length` - it unconditionally calls `op.endpoint.call{value: op.value}(op.callData)` (stateless path) for every op in the decoded `EmporiumStack` [5](#0-4) . `verifyWallet` only performs an ECDSA check when `stack.signerAddress != address(0)`; if `signerAddress == address(0)` it returns immediately after marking the message used, skipping signature verification entirely [6](#0-5) . `payRelayFees` also degrades in this path: its main loop is over `erc20TokenAddresses` (also empty), and the flat-fee-fallback branch only reverts when `signerAddress != address(0)`, so choosing `feeStructure.flatFee == 0` avoids any relay fee obligation entirely [7](#0-6) .

The reachability gate is `onlyAllowedRecipient`, which only permits calls from addresses registered via `setAllowedRecipients`/`__ExternalActionBase_init` [8](#0-7) . Since `runAction` is invoked from `Hinkal._externalTransact` via `IExternalActionV2(...).runAction(...)` [9](#0-8) , the practical caller is the `Hinkal` contract itself (assumed whitelisted), so the attack surface is entirely through `Hinkal.transact` with min-dimension `CircomData`, exactly as described. `_externalTransact`'s own pre-loop (populating `deltaAmountChanges` and pushing funds out for negative deltas) is also a no-op for length 0 [10](#0-9) .

Given `EmporiumUpgradeable` has an unrestricted `receive() external payable {}` [11](#0-10) , any ETH that ends up resident in the contract balance (fee dust, stray sends, or unresolved balances from partially-swept multi-op flows) can be extracted by a subsequent min-dimension transact call with zero accounting and, if `flatFee == 0`, zero relay fee.

### Impact Explanation
An attacker can drain any ETH balance currently held by the `EmporiumUpgradeable` contract to an arbitrary endpoint, and can execute arbitrary external calls (`op.endpoint`/`op.callData`) that are never validated against the zero-length `amountChanges`/`deltaAmountChanges` arrays or any slippage/balance check in `Hinkal.transact`. This is theft of protocol/contract-held ETH and unauthorized call execution not constrained by the proof, matching the "High" category (theft of protocol/relay fees, executing calls a prover never authorised) at minimum. Full "Critical" classification (theft of another user's shielded/in-flight funds) would additionally require demonstrating that genuine third-party ETH persists in the Emporium contract's balance across transaction boundaries; the normal Emporium flow sweeps `balanceChange` (computed relative to that same call's `balancesBefore`) back to `Hinkal` at the end of every non-min-dimension call, so cross-transaction persistence of another user's ETH was not confirmed from the available code and would need to be demonstrated via a concrete residual-balance scenario (e.g., partial swap dust) in a PoC.

### Likelihood Explanation
The precondition is straightforward for an unprivileged attacker: craft a valid ZK proof for min-dimension `CircomData` (`erc20TokenAddresses.length == 0`) targeting `externalActionId == HINKAL_EMPORIUM_ACTION_ID`, set `EmporiumStack.signerAddress == address(0)` to skip ECDSA verification, set `feeStructure.flatFee == 0` to avoid the fallback fee revert, and include ops with `op.value > 0` targeting attacker-controlled endpoints. This is fully repeatable each time ETH is present in the Emporium contract's balance and does not require any privileged role, matching the attacker model in scope.

### Recommendation
Do not skip balance-conservation accounting based on `erc20TokenAddresses.length`. Either (a) require `erc20TokenAddresses` to include `address(0)` (ETH) whenever any `op.value > 0` is present in the decoded `EmporiumStack`, enforced on-chain before the ops loop runs, or (b) independently track the contract's ETH balance before/after the ops loop in `runAction` and revert if it decreases by more than what is accounted for by `deltaAmountChanges`, regardless of array length. Additionally, require `feeStructure.flatFee` conditions to be validated even when `erc20TokenAddresses.length == 0` and `signerAddress == address(0)`, closing the fee-bypass branch.

### Proof of Concept
Foundry test plan:
1. Deploy `EmporiumUpgradeable`, register it as `onlyAllowedRecipient` for `Hinkal`, register `Hinkal` as its allowed recipient.
2. Fund `EmporiumUpgradeable` with ETH directly via `receive()` to simulate a stray/leftover balance.
3. Build a min-dimension `CircomData` (`erc20TokenAddresses`, `amountChanges`, `slippageValues`, `onChainCreation` all length 0) with `externalActionData.externalActionId == HINKAL_EMPORIUM_ACTION_ID`, `externalActionMetadata` encoding an `EmporiumStack` with `signerAddress == address(0)`, `feeStructure.flatFee == 0`, and one op with `endpoint = attackerContract`, `value = <the ETH balance funded in step 2>`.
4. Generate a valid proof for these min dimensions (or use whatever local proof-generation harness the repo provides for min-dim circuits) and call `Hinkal.transact`.
5. Assert: (a) `Hinkal.transact` succeeds without reverting on any balance/slippage check (since the loop at `contracts/Hinkal.sol` lines 97-147 executes 0 iterations); (b) the ETH balance of `EmporiumUpgradeable` decreases by the op's `value` and the attacker's endpoint balance increases by the same amount; (c) no relay fee was paid and no `deltaAmountChanges`/`amountChanges` entry recorded this movement anywhere on-chain.

    function payRelayFees(
        CircomData calldata circomData,
        address signerAddress,
        int256[] calldata deltaAmountChanges
    ) internal {
        FeeStructure calldata feeStructure = circomData.feeStructure;

        bool foundToken = false;

        for (uint256 i = 0; i < circomData.erc20TokenAddresses.length; i++) {
            // tokens deposited into Emporium are not charged
            if (deltaAmountChanges[i] >= 0) {
                continue;
            }

            address erc20TokenAddress = circomData.erc20TokenAddresses[i];
            bool isFeeToken = erc20TokenAddress == feeStructure.feeToken;

            if (isFeeToken) {
                foundToken = true;
            }

            uint256 relayFee = 0;
            uint256 flatFee = isFeeToken ? feeStructure.flatFee : 0;

            if (signerAddress == address(0)) {
                uint256 sumAbs = uint256(-deltaAmountChanges[i]);

                EmporiumStorageVars storage $ = _getEmporiumStorage();
                relayFee = $._hinkalHelper.calculateRelayFee(
                    sumAbs,
                    flatFee,
                    feeStructure.variableRate
                );

                relayFee = flatFee;
            }

            payRelay(
                circomData.relay,
                signerAddress,
                relayFee,
                erc20TokenAddress
            );

            require(

                "Gas Token in Emporium is not found"
            );

            payRelay(
                circomData.relay,
                signerAddress,
                feeStructure.flatFee,
                feeStructure.feeToken
            );
        }
