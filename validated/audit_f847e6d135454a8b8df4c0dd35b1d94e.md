## Title
Stale/Mismatched Chainlink Price Combination in `SimplexPaymaster._tokenPrice` Allows Underpriced Gas Sponsorship — (File: `evm/src/utils/SimplexPaymaster.sol`)

### Summary
`SimplexPaymaster` converts the gas cost of a sponsored `UserOperation` into ERC-20 token units by combining two independent Chainlink price feeds — `nativeOracle` (native/USD) and `cfg.tokenOracle` (token/USD) — in `_tokenPrice()`. [1](#0-0)  Each feed's staleness is validated *independently* against `block.timestamp` via a shared `maxOracleAge` bound in `_getOraclePrice()`, but the two feeds' `updatedAt` timestamps are never cross-checked against each other. [2](#0-1)  This is the same bug class as the referenced Ion Protocol `EthXSpotOracle.getPrice` report: two prices sourced independently and combined into a single ratio without verifying they represent comparable points in time.

### Finding Description
`_tokenPrice` is reachable by any unprivileged UserOp sender through `_fetchDetails`, which is invoked during ERC-4337 paymaster validation for every sponsored operation: [3](#0-2) 

It's also exposed to solvers/relayers via the public views `getTokenPrice` and `estimateTokenCost`, and used again in `swapAndDeposit` for treasury fee recycling. [4](#0-3) [5](#0-4) 

`_getOraclePrice` only checks that each individual feed's own `updatedAt` is within `maxOracleAge` of the current block: [6](#0-5) 

`maxOracleAge` is governance-configurable up to `MAX_ORACLE_AGE = 7 days` [7](#0-6) , and the doc comment on `Params.maxOracleAge` itself notes heartbeats vary wildly per chain/asset ("BSC stablecoins ~27s, Base/Ethereum stablecoins up to 24h") [8](#0-7) . Because both `nativeOracle` and `cfg.tokenOracle` are checked against the *same* `maxOracleAge` bound rather than against each other, one feed can legitimately report a value from just now while the other reports a value up to `maxOracleAge` stale, and the ratio `nativeUsd/tokenUsd` used to price gas will silently reflect a snapshot spanning that whole window during volatile price movement — exactly the discrepancy class described in the reference report.

### Impact Explanation
If the native asset (e.g., ETH/BNB) price moves sharply while the stale token/USD leg (or vice versa) still reflects an old rate, `_tokenPrice` will under- or over-value the sponsored gas cost in token terms:
- If undervalued, users pay less ERC-20 than the true cost of the native gas the paymaster fronts to the EntryPoint, draining the paymaster's EntryPoint deposit/stake over repeated sponsored operations — a direct value-extraction/drain vector against the paymaster's treasury-controlled funds.
- If overvalued, users are overcharged relative to fair value.

This is reachable by any permissionless UserOp sender (no governance/relayer privilege required) simply by submitting operations during a period where the two feeds diverge, satisfying the "unprivileged... intent solver/bandwidth purchaser" reachability bar.

### Likelihood Explanation
Both oracle checks pass independently under normal, permitted conditions (each just needs to be within `maxOracleAge`), so no oracle malfunction or manipulation is required — only natural update-cadence divergence between two feeds sharing one staleness bound, which is explicitly acknowledged as chain-dependent in the code's own comments. [8](#0-7)  This makes the divergence window a normal, not adversarial, occurrence, especially on chains where `maxOracleAge` is configured for the more infrequently-updated leg (e.g. up to 24h on Base/Ethereum stablecoins).

### Recommendation
In `_tokenPrice` (or `_getOraclePrice`), additionally return each feed's `updatedAt` and assert `|nativeUpdatedAt - tokenUpdatedAt| <= maxSkew` for a separate, tighter skew bound, rather than only bounding each feed's absolute age against `block.timestamp` independently.

### Proof of Concept
1. Governance sets `maxOracleAge` to the chain's most permissive heartbeat (e.g. 24h for a Base/Ethereum stablecoin feed, per the code's own comment).
2. `nativeOracle` updates normally every block; `cfg.tokenOracle` (a low-volatility stablecoin feed) last updated ~23h ago — both pass `_getOraclePrice`'s individual staleness check.
3. During those 23h, the native asset price moves materially (e.g. a market shock).
4. A UserOp is submitted using the stale-relative-to-native token; `_tokenPrice` computes a ratio mixing a fresh native price with a 23h-old token price, mispricing the ERC-20 charged for sponsored gas without any check ever failing.

```text
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
```

```text
    /// @notice Estimate the token cost for a given gas amount and fee, mirroring
    ///         PaymasterERC20._erc20Cost (including its postOp gas cushion).
    function estimateTokenCost(address token, uint256 gasAmount, uint256 maxFeePerGas) external view returns (uint256) {
        TokenConfig memory cfg = tokenConfigs[token];
        if (address(cfg.tokenOracle) == address(0)) revert TokenNotRegistered(token);

        uint256 weiCost = gasAmount * maxFeePerGas + _postOpCost() * maxFeePerGas;
        return (weiCost * _tokenPrice(cfg)) / _tokenPriceDenominator();
    }
```
