### Title
Low-decimal collateral "wedge" makes an unhealthy account impossible to liquidate — every `liquidate` call reverts until the position drifts insolvent - (File: contracts/controller/src/positions/liquidation/math.rs)

### Summary
For an account whose only supply position is a collateral asset with `asset_decimals < MIN_BORROWABLE_ASSET_DECIMALS` (0–2 decimals, e.g. unit-NAV RWA tokens), the quote-repair helper `whole_unit_repayment` has a gap between its two fix-up rules. When total debt `D` sits in the narrow band `floor(U / (1 + b)) − R < D ≤ ceil((U + m) / (1 + b))`, neither rule adjusts the curve quote. If that quote backs less than one whole unit, seizure rounds down to zero and the plan is left with nothing to seize, so `liquidate` reverts with `InvalidPayments` for every possible offer — an unprivileged borrower can park an unhealthy position in this band on purpose.

### Finding Description
`normalize_repayment_plan` calls `whole_unit_repayment` only when the account is solvent (`!insolvent`) and the curve quote is below total debt (`contracts/controller/src/positions/liquidation/math.rs:188-192`). Inside `whole_unit_repayment` (math.rs:235-291):

- Rule 1 (full close): returns `total_debt` only if `unit_at_bonus >= total_debt + R` (lines 275-280).
- Rule 2 (one-unit raise): returns `unit_repayment = ceil((U + m)/(1+b))` only if `unit_repayment < total_debt` (lines 281-290).
- Otherwise it returns the unchanged curve quote (line 288).

So when `unit_at_bonus − R < D ≤ unit_repayment`, the quote is unchanged. Then in `calculate_seized_collateral`, a non-`repays_all_debt` partial leg below 3 decimals is floored to whole units (math.rs:401-416); a sub-unit quote produces `seizure_ray <= Ray::ZERO` and the leg is dropped (line 419-421). A plan with no seizure and no repayments fails validation and `liquidate` reverts with `InvalidPayments` (error 16). This is confirmed by the project's own documentation: "While `floor(U / (1 + b)) - R < D <= ceil((U + m) / (1 + b))`, neither rule 1 nor rule 2 applies. If the curve quote then backs less than one unit, every offer reverts until accrual or a price move ends that state" (docs/reference/formulas.md:305-308; docs/reference/invariants.md INV-LIQ-02 lines 433-437; skills/xoxno-lending-liquidations/SKILL.md:131-133). Harness tests reproduce the revert (`tests/test-harness/tests/controller/zero_decimal_collateral.rs:510-525`).

A borrower reaches it with only `supply` + `borrow`: supply `k ≥ 1` whole units of an admitted low-decimal asset, borrow so that after a price move (or by choosing borrow size relative to NAV) `HF < 1` and `D` lands inside the band — the band has nonzero width `≈ R + m/(1+b)`, and `D` only needs to satisfy `D ≤ unit_repayment`, which is close to `U/(1+b)`. No offer size escapes: payments are capped per leg at each leg's debt, `full_close` is false because `ideal < D`, so any offer is trimmed back to the same sub-unit `ideal` and reverts. `clean_bad_debt` cannot help either while `C > $5` or `total_debt ≤ total_collateral` (`is_socializable_bad_debt`, skills/xoxno-lending/math.md:415-417).

### Impact Explanation
All liquidation of the account is temporarily frozen while `HF < 1`. Interest keeps accruing on the frozen debt, pushing `D` upward until `C < D`, at which point the account is insolvent and the unbacked residue becomes socialized bad debt that suppliers absorb via `apply_bad_debt_to_supply_index`. The attacker converts a liquidation that should have closed near par into guaranteed bad debt, i.e., protocol insolvency plus temporary freezing of the collateral and debt settlement path.

### Likelihood Explanation
Requires a listed collateral with decimals < 3 — the codebase explicitly supports this class (RWA/NAV-style units; `liqvid_rwa_collateral.rs`, `zero_decimal_collateral.rs`) and invariant docs note such a leg must be the account's only supply position. Given such a listing, the attacker controls their own borrow amount and can time entry around price moves to land `D` in the band; liquidation bots cannot work around it because every offer size trims to the same zero-seizure plan. Medium likelihood: needs a specific listing type and band placement, but no privilege and no oracle manipulation.

### Recommendation
In `whole_unit_repayment`, close the wedge: when `unit_repayment >= total_debt` but the unchanged curve quote backs less than one whole unit, either promote the quote to `total_debt` (full close taking one unit) or fall back to seizing one whole unit at a repayment of `floor(U/(1+b))` capped at `D`. Alternatively, in `calculate_seized_collateral`, allow a sub-unit partial quote to seize one whole unit when the leg is the account's only supply position, instead of dropping the leg and reverting.

### Proof of Concept
Setup: a listed collateral with `decimals = 0`, price `U = $1,000` per unit, liquidation bonus such that `1 + b = 1.1`; single debt token with `R ≈ $0.000001`. Then `unit_at_bonus ≈ $909.09`, `m = $0.001`, `unit_repayment ≈ $909.09`. A borrower supplies 2 units (`C = $2,000`, LT = 0.5, `W = $1,000`) and borrows `D = $909.5` of stablecoin. `HF = 1000/909.5 > 1` at entry; after a small price dip to `U = $909` (`C = $1,818`, `W = $909`, `D = $909.5`): `HF < 1`, `C > D`, `unit_at_bonus ≈ $826.4 < D + R`, and `unit_repayment ≈ $826.4 < D`? — adjust so `D ≤ unit_repayment`: e.g. `U = $1,010` post-dip giving `unit_repayment ≈ $918 > D`. The curve quote `ideal < U + m` and `ideal` backs less than one unit; `whole_unit_repayment` returns it unchanged (math.rs:287-289); `calculate_seized_collateral` floors the leg to 0 units (math.rs:409-410) and drops it; `liquidate(liquidator, account, payments, SeizeMode::Transfer)` reverts `InvalidPayments` for every `payments` vector. This mirrors the existing harness tests `zdc_sub_unit_liquidation_reverts_without_charging` and `zdc_small_account_underpaid_offer_takes_no_unit`, with `D` chosen inside the wedge so the debt-sized offer reverts too.
