### Title
Clear-Text Logging of WiFi Password via nom Parse-Error Debug Output - (File: src/plans/qr_scan/wifi.rs)

### Summary
The report against `client/export.go` flags clear-text logging of sensitive credential material via `fmt.Println`/hex-encoded output. The reachable analog in `orb-core` is in the MECARD WiFi-QR-code parsing path, where a raw parse failure is logged with `{:?}` and can carry the unparsed remainder of the QR-code string — which may still include the plaintext WiFi password — into application logs.

### Finding Description
`Credentials::try_parse` calls `Self::parse(code).finish()` and, on any parse error, logs the `nom` error value directly: [1](#0-0) 

`nom`'s `Err`/`Error` types embed a reference to the remaining input slice at the point of failure. Because `Credentials::parse` interleaves password parsing with SSID/auth-type/hidden parsing inside a single loop-based combinator before validating success, a QR code such as `WIFI:P:supersecret;S:;;` (empty/invalid SSID) or any malformed-but-password-bearing MECARD string fails only at a later validation step (e.g., the SSID-required check or trailing `;`/`eof` check), while the still-unconsumed or original input carries the password field in clear text: [2](#0-1) 

The codebase clearly recognizes the password is sensitive — it wraps it in a `Password` newtype with a redacting `Debug` impl specifically "to prevent printing in plaintext": [3](#0-2) 

However, that protection only applies to the successfully-constructed `Credentials`/`Password` value. It does nothing to protect the raw `nom::Err` returned on the failure path, which is logged verbatim at `src/plans/qr_scan/wifi.rs:21` via `tracing::debug!("WiFi credentials parse error: {:?}", err)`. This mirrors the reported bug class exactly: unsanitized sensitive credential data reaching a logging sink in clear text, just triggered through a slightly-malformed input rather than a success path.

### Impact Explanation
WiFi QR codes are scanned directly by unprivileged operators/users during normal Orb operation (`qr_scan` flow), so this path is reachable without any special privilege. If the malformed QR still contains a real network password (a very plausible operator mistake — extra/missing fields, wrong escaping, bad SSID field), that password is written to the Orb's debug logs in clear text. Given Orb logs are collected and can be shipped off-device for diagnostics, this creates a realistic disclosure path for WiFi network credentials, analogous to the private-key disclosure in the original report (sensitive credential value flows into a plaintext log sink).

### Likelihood Explanation
Moderate: it requires a WiFi MECARD QR code that fails one of the parser's later validation steps (missing/invalid SSID, extra trailing bytes, duplicate fields) while still containing a real password field. This is a common class of malformed/mistyped QR codes rather than an exotic edge case, and `tracing::debug!` is gated only by log level, not by any additional redaction.

### Recommendation
- Do not log the raw `nom` error (`{:?}`) at `src/plans/qr_scan/wifi.rs:21`. Instead, log only a sanitized/generic message (e.g., error kind/parser stage) without echoing back the unparsed input.
- If the raw input must be logged for diagnostics, apply the same redaction pattern already used for `Password` (i.e., scrub any substring matching a `P:` MECARD field before logging), or restructure `Credentials::parse` to validate required fields (SSID) before/independently of parsing the password, so failures cannot carry a password-bearing remainder.
- Consider a wrapper `Debug`/`Display` for the parse error that only reports position/expected-tag information, never the raw slice content.

### Proof of Concept
1. Present a WiFi QR code with a MECARD string where the password field is populated but the entry fails final validation, e.g.:
   `WIFI:P:supersecret;S:;;` (empty SSID triggers the "ssid is actually not optional" failure at `src/network/mecard.rs:116-118`, after `password` has already been parsed from the input, and the returned `nom::Err` still references the original/remaining input containing `P:supersecret`).
2. `qr_scan` calls `Credentials::try_parse`, which hits the `Err(err)` branch and executes `tracing::debug!("WiFi credentials parse error: {:?}", err)`.
3. Inspect Orb debug logs: the plaintext WiFi password (`supersecret`) appears in the log line, despite the codebase's explicit `Password` redaction mechanism intended to prevent exactly this exposure.

    pub fn parse(input: &str) -> IResult<&str, Self> {
        let (mut input, _) = tag("WIFI:")(input)?;

        // Parses a set of fields with the following requirements:
        // 1. A field is parsed no more than once.
        // 2. Fields are parsed in arbitrary order.
        // 3. Each field is optional.
        macro_rules! parse_fields {
            ($($parse:path => $opt:ident,)*) => {
                $(let mut $opt = None;)*
                loop {
                    $(
                        if $opt.is_none() {
                            if let Ok((next_input, parsed)) = $parse(input) {
                                $opt = Some(parsed);
                                input = next_input;
                                continue;
                            }
                        }
                    )*
                    break;
                }
            };
        }
        parse_fields! {
            AuthType::parse => auth_type,
            parse_ssid => ssid,
            parse_password => password,
            parse_hidden => hidden,
        }

        let ssid = ssid.filter(|ssid| !ssid.is_empty());
        let (password, auth_type) = password
            .filter(|pwd| !pwd.is_empty())
            .map_or((None, Some(AuthType::Nopass)), |pwd| (Some(Password(pwd)), auth_type));

        // ssid is actually not optional.
        if ssid.is_none() {
            let (_, ()) = fail(input)?;
        }

        let (input, _) = tag(";")(input)?;
        let (input, _) = eof(input)?;

        let auth_type = auth_type.unwrap_or_default();
        let ssid = ssid.unwrap_or_default();
        let hidden = hidden.unwrap_or_default();
        Ok((input, Self { auth_type, ssid, password, hidden }))
    }
