Audit Report

## Title
External initiator feature-disable flag is not enforced at authentication time, only at creation time - (File: core/web/external_initiators_controller.go, core/web/auth/auth.go)

## Summary
`ExternalInitiatorsController.Create` gates creation of new external initiators behind `JobPipeline().ExternalInitiatorsEnabled()`, but `AuthenticateExternalInitiator`, which authenticates EI requests and grants `UserRoleRun`, never checks this flag. As a result, disabling the External Initiator feature does not revoke or disable already-issued EI credentials, which continue to authenticate and trigger job runs.

## Finding Description
`ExternalInitiatorsController.Create` returns `405 Method Not Allowed` if `ExternalInitiatorsEnabled()` is false [1](#0-0) . However, `AuthenticateExternalInitiator` only validates the `AccessKey`/`Secret` against the stored `ExternalInitiator` record via `store.FindExternalInitiator` and `bridges.AuthenticateExternalInitiator`, then unconditionally sets `SessionUserKey` to `UserRoleRun` — with no reference to the config flag anywhere in the function [2](#0-1) . This means the enable/disable gate is enforced only at the point of creating new EI records, not at the point where EI credentials are actually used to authenticate and gain the privileged run role.

## Impact Explanation
This decouples an admin-configured kill-switch from its actual enforcement point. If an operator disables `ExternalInitiatorsEnabled` (e.g., in response to an incident) expecting all EI-triggered job runs to stop, any previously issued EI `AccessKey`/`Secret` pairs will continue to authenticate successfully and be granted `UserRoleRun`, allowing continued unauthorized job-run triggering contrary to the operator's expressed intent. This maps to the in-scope "node API authentication or role bypass" / "unauthorized job run" impact category.

## Likelihood Explanation
The precondition is that an EI was created while the feature was enabled and the operator later disables the flag — a normal, supported operational sequence, not requiring host/database access or new privilege escalation by the caller. The caller in the exploit step already possesses valid EI credentials (issued during the enabled period) and simply continues to use them unchanged; no additional privilege is required beyond what was already granted before the flag was toggled.

## Recommendation
Re-check `App.GetConfig().JobPipeline().ExternalInitiatorsEnabled()` inside `AuthenticateExternalInitiator` (or in the `Authenticate` middleware wrapper used for EI routes) and reject authentication with `auth.ErrorAuthFailed` (or an equivalent forbidden response) when the feature is disabled, so that toggling the flag off immediately disables all existing EI credentials, not just future EI creation.

## Proof of Concept
1. Start a node with `JobPipeline.ExternalInitiatorsEnabled = true` and call `POST /v2/external_initiators` to create an EI via `ExternalInitiatorsController.Create`, capturing the returned `AccessKey`/`Secret` [3](#0-2) .
2. Reconfigure/restart the node with `JobPipeline.ExternalInitiatorsEnabled = false`.
3. Send a request to any endpoint protected by `Authenticate(..., AuthenticateExternalInitiator)` using the `X-Chainlink-EA-AccessKey`/`X-Chainlink-EA-Secret` headers captured in step 1.
4. Observe the request succeeds and is granted `SessionUserKey = &clsessions.User{Role: clsessions.UserRoleRun}` despite the feature flag being disabled, confirming the flag has no effect on already-authenticated/authorized EI sessions [4](#0-3) .

func AuthenticateExternalInitiator(c *gin.Context, store Authenticator) error {
	ctx := c.Request.Context()
	eia := &auth.Token{
		AccessKey: c.GetHeader(static.ExternalInitiatorAccessKeyHeader),
		Secret:    c.GetHeader(static.ExternalInitiatorSecretHeader),
	}

	ei, err := store.FindExternalInitiator(ctx, eia)
	if err != nil {
		if errors.Is(err, sql.ErrNoRows) {
			return auth.ErrorAuthFailed
		}

		return errors.Wrap(err, "finding external initiator")
	}

	ok, err := bridges.AuthenticateExternalInitiator(eia, ei)
	if err != nil {
		return err
	}
	if !ok {
		return auth.ErrorAuthFailed
	}

	// External initiator endpoints (wrapped with AuthenticateExternalInitiator) inherently assume the role
	// of 'run' (required to trigger job runs)
	c.Set(SessionExternalInitiatorKey, ei)
	c.Set(SessionUserKey, &clsessions.User{Role: clsessions.UserRoleRun})

	return nil
}
