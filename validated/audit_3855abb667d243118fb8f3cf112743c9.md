**Analysis:**

The premise misreads what `lhs` and `rhs` represent in `check_dispatch_type_compatibility_impl`. `lhs` is the *framework dispatcher function* — always a hardcoded, non-upgradable native declared inside the framework module itself (e.g. `dispatchable_withdraw`), constructed via `function_info::new_function_info_from_address(@aptos_framework, ...)` at the call site in `fungible_asset.move`. An unprivileged caller never supplies `lhs`; only `rhs` (the user's hook) is attacker-controlled. [1](#0-0) 

The dispatcher's own trailing `&FunctionInfo` parameter is not something the dispatch target (`rhs`) has or needs — it is the native's *own* extra parameter used only to determine which module/function to call, and it is consumed internally by the native dispatch mechanism, never forwarded to `rhs`. The slicing `lhs.param_tys()[0..lhs.param_count()-1]` intentionally drops that slot before comparing against `rhs.param_tys()`, exactly matching the documented contract: "dispatch_target should have the same signature ... except that the framework_function will have a `&FunctionInfo` in the last argument." [2](#0-1) [3](#0-2) 

Since `lhs`'s signature is fixed framework source code (`native fun dispatchable_withdraw<T: key>(store: Object<T>, amount: u64, transfer_ref: &TransferRef, function: &FunctionInfo): FungibleAsset`), its last parameter is always literally `&FunctionInfo` — there is no attacker-reachable path to make it otherwise, so "unvalidated trailing type" cannot diverge. [4](#0-3) 

Furthermore, when `features::is_function_value_dispatch_enabled()` (the modern path), dispatch doesn't even go through `check_dispatch_type_compatibility_impl` at call time — it uses `load_function_value<FuncType>`, where `FuncType` is a fully concrete, hardcoded type with no `&FunctionInfo` slot at all (e.g. `|Object<T>, u64, &TransferRef|FungibleAsset`). This resolves through `reflect::resolve`/`verify_function`, which performs strict `match_tys` on every parameter and return type independently of `check_dispatch_type_compatibility_impl`, so any real signature mismatch aborts with `FunctionIncompatibleType`. [5](#0-4) [6](#0-5) 

In the legacy path, the native `dispatchable_withdraw`/`dispatchable_deposit` pop the `&FunctionInfo` argument for module resolution and forward only the natively-already-type-checked `store`, `amount`/`fa`, `transfer_ref` values to the target via `CallFunction`; there is no "corrupted argument binding" because no extra/stale argument is ever passed to `rhs`.

Since the attacker has no ability to influence `lhs`, and the actual runtime dispatch either uses an independent exact-match verification (`load_function_value`) or never forwards the `&FunctionInfo`/trailing slot to the target, this does not cross any custody boundary or affect ownership/balance/authority state.

    fn verify_function(
        &mut self,
        module: Arc<Module>,
        func: Arc<Function>,
        expected_ty: &Type,
    ) -> PartialVMResult<Result<Box<dyn AbstractFunction>, FunctionResolutionError>> {
        use FunctionResolutionError::*;
        if !func.is_public() {
            return Ok(Err(FunctionNotAccessible));
        }
        let Type::Function {
            args,
            results,
            abilities,
        } = expected_ty
        else {
            return Ok(Err(FunctionIncompatibleType));
        };

        // A resolved function is always public (checked above) and captures no arguments, so the
        // resulting closure value has exactly the abilities of a public function value, i.e.,
        // `PUBLIC_FUNCTIONS` (copy + drop + store). Reject any expected type whose abilities are
        // not a subset of these (e.g., one requesting `key`), since no such closure value can
        // exist and returning it would let the caller treat the closure as a type it is not.
        if !abilities.is_subset(AbilitySet::PUBLIC_FUNCTIONS) {
            return Ok(Err(FunctionIncompatibleType));
        }

        let func_ref = func.as_ref();

        // Match types, inferring instantiation of function in `subst`.
        let mut subst = TypeParamMap::default();
        if !subst.match_tys(func_ref.param_tys.iter(), args.iter())
            || !subst.match_tys(func_ref.return_tys.iter(), results.iter())
        {
            return Ok(Err(FunctionIncompatibleType));
        }
