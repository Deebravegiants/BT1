**Analysis:**

The premise conflates two distinct verification concepts in the Move VM:

1. **Bytecode verification** (`is_verified()` flag) — structural/type/resource safety checking of a module's bytecode, tracked in `unmetered_get_lazily_verified_module` [1](#0-0) .
2. **Business-logic permission checks** — ordinary Move statements (e.g. `assert!` calls in a withdraw/deposit hook like `permissioned_token::withdraw`'s allowlist check) that execute as regular VM instructions once the function actually runs [2](#0-1) .

These are unrelated: whether a module's dependency-tree linking checks were performed eagerly or lazily has no bearing on whether the Move-level `assert!` statements inside the dispatch hook function execute correctly, because permission checks are ordinary bytecode instructions, not part of the bytecode verifier's job.

The lazy-loading path is a deliberate, tested design: `unmetered_get_lazily_verified_module` performs local (per-module) verification and `build_verified_module_skip_linking_checks`, deferring only cross-module *linking* checks (friend/dependency compatibility), not skipping bytecode safety verification of the module itself [3](#0-2) . This is exactly the behavior asserted by `test_dependency_tree_traversal` and related tests, which check that under lazy loading only the modules actually visited get marked verified, while unvisited ones remain unresolved until touched [4](#0-3) .

When a dispatch hook function value is actually invoked, `LazyLoader::load_function_definition` calls `metered_load_module`, which forces `unmetered_get_existing_lazily_verified_module` on that specific module before returning the function [5](#0-4) . Additionally, function-value resolution for dispatch (`resolve_function`) always calls `load_function_definition` and then explicitly type-verifies the function signature before returning a callable closure [6](#0-5) . There is no path by which a hook is invoked while its own bytecode has not been verified — lazy loading only defers verification of *other, not-yet-touched* modules in the dependency graph, not the module actually being executed.

`assert_cached_state` is explicitly a test-only helper (`#[cfg(any(test, feature = "testing"))]`) used to assert cache contents in unit tests [7](#0-6) ; it has no bearing on production custody enforcement and does not "mask" anything at runtime — production code paths never call it.

There is no demonstrated mechanism by which an attacker-controlled dispatchable FA hook could execute business-logic checks that were "never verified against permission checks" — permission checks are ordinary Move code that always executes with the caller's actual state (owner, allowlist, etc.), independent of whether the bytecode verifier had already completed transitive linking checks on the whole dependency DAG. This does not cross a custody boundary; it is a mischaracterization of the lazy-loading design.

    fn unmetered_get_lazily_verified_module(
        &self,
        module_id: &ModuleId,
    ) -> VMResult<Option<Arc<Module>>> {
        let (module, version) = match self.get_module_or_build_with(module_id, self)? {
            Some(module_and_version) => module_and_version,
            None => return Ok(None),
        };

        if module.code().is_verified() {
            return Ok(Some(module.code().verified().clone()));
        }

        let _timer = VM_TIMER.timer_with_label("unmetered_get_lazily_verified_module [cache miss]");
        let runtime_environment = self.runtime_environment();
        runtime_environment.paranoid_check_module_address_and_name(
            module.code().deserialized(),
            module_id.address(),
            module_id.name(),
        )?;
        let locally_verified_code = runtime_environment.build_locally_verified_module(
            module.code().deserialized().clone(),
            module.extension().size_in_bytes(),
            module.extension().hash(),
        )?;
        let verified_code =
            runtime_environment.build_verified_module_skip_linking_checks(locally_verified_code)?;
        let verified_module = self.insert_verified_module(
            module_id.clone(),
            verified_code,
            module.extension().clone(),
            version,
        )?;
        Ok(Some(verified_module.code().verified().clone()))
    }
