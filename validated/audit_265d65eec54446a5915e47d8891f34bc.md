### Title
Panic-inducing unchecked `copy_from_slice` on attacker-controlled `Message.from` length in HFT `on_accept` - (File: modules/pallets/hyper-fungible-token/src/module.rs)

### Summary
The `hyper-fungible-token` pallet's `on_accept` handler decodes an ABI-encoded `Message` (`from`, `to`, `amount`, `data`) from an incoming ISMP POST request body. `to` and `from` are attacker-controlled `bytes` fields with no length constraint enforced by the ABI decoder. Every other place in this file that copies such a field into a fixed 32-byte buffer (the `to` beneficiary conversion at lines 63-71, and the `from` refund conversion in `on_timeout` at lines 224-232) explicitly checks the length is 20 or 32 bytes before calling `copy_from_slice`, returning a typed error (`HftError::InvalidRecipientLength` / `InvalidSenderLength`) otherwise. The non-EVM branch of the calldata-signature path at line 177-186 does not do this: it slices `message.data` into `SubstrateCalldata`, and when no `signature` is supplied and `source.is_evm()` is false, it does `account.copy_from_slice(from_bytes)` directly into a `[0u8; 32]` buffer.

### Finding Description
`Vec<u8>`/`bytes` decoded via `Message::abi_decode` places no bound on `message.from`'s length. A caller can dispatch a cross-chain POST from a non-EVM source module registered as a valid `ContractToAsset` source, whose `Message.from` is any length other than exactly 32 bytes (e.g. 0, 1, 31, or 33+ bytes), and include a non-empty `message.data` that decodes to a `SubstrateCalldata` with `signature: None`. `Vec<u8>::copy_from_slice` panics if the source slice length does not exactly match the destination (`[0u8; 32]`), causing a runtime panic inside `on_accept`, which is invoked from the unsigned `pallet_ismp` message-handling path (`handle_unsigned` → dispatcher → module router → `on_accept`).

### Impact Explanation
A panic inside on-chain transaction/extrinsic execution triggered by attacker-controlled message content halts block execution or aborts the executing worker, which is a denial-of-service against the pallet's cross-chain message delivery path — reachable by any relayer submitting a crafted but otherwise validly-routed ISMP POST request whose target module is this pallet with `source.is_evm() == false`. This blocks legitimate message delivery for the pallet (a route/pallet unable to deliver messages), which the assignment's validation criteria treats as in-scope impact.

### Likelihood Explanation
Reaching this path requires: (1) a non-EVM `StateMachine` registered with a `ContractToAsset` mapping in `Precisions`/`ContractToAsset` storage (governance-configured, but once configured any relayer can submit the crafted request), (2) a message whose `data` decodes as valid SCALE `SubstrateCalldata` with `signature: None`, and (3) `from` of a length other than 32 bytes. All of these are attacker-controlled at the ABI-encoding layer since `Message.from` has no length assertion by Solidity ABI decoding rules. This is a config-dependent but code-reachable, deterministic panic, not a probabilistic bug.

### Recommendation
Mirror the length validation already present at lines 65-71 and 226-232: check `from_bytes.len() == 32` before `copy_from_slice`, and return `HftError::InvalidSenderLength(from_bytes.len())` (or similar) for any other length instead of panicking.

### Proof of Concept
1. Register a non-EVM `StateMachine` (e.g. a Substrate parachain) as a source with a valid `ContractToAsset` entry and `Precisions` decimals for some `local_asset_id`.
2. Craft an ABI-encoded `Message { from: bytes of length != 32 (e.g. 5 bytes), to: valid 20/32-byte recipient, amount: any, data: SCALE-encoded SubstrateCalldata { signature: None, runtime_call: <any valid call bytes> } }`.
3. Submit this as the body of a `PostRequest` from the registered non-EVM source, delivered via `pallet_ismp::handle_unsigned`/`execute` to the `hyper-fungible-token` module's `on_accept`.
4. Execution reaches `account.copy_from_slice(from_bytes)` at module.rs:184 with `from_bytes.len() != 32`, which panics, aborting extrinsic/block execution.
