**Analysis:** `StateDelta::new` computes `current.shards()[shard_id].view_layers_after(&base.shards()[shard_id])` after asserting `current.is_descendant_of(&base)` [1](#0-0) . The `LayeredMap`/`MapLayer` family construction enforces a strict parent-chain relationship — `is_descendant_of` walks up the parent pointers to confirm `base` is an actual ancestor of `current`, not merely a same-family node on a different branch [2](#0-1) . This means `StateDelta` chaining is not an operation attacker-controlled input can reorder: the `base`→`current` linkage is a monotonic layer chain built deterministically by the execution/commit pipeline (`State::update`, `try_merge`, checkpoint creation), where each new layer is spawned strictly on top of the prior one in block-execution order [3](#0-2) .

There is no code path from an unprivileged transaction, package, view function, authenticator, API, or bytecode input that lets a caller construct or interleave arbitrary `StateDelta` objects, choose their `base`/`current` pairing, or reorder the layer chain. Layer ordering is fixed by the sequential nature of block/transaction execution in the storage engine (`hot_state.rs`'s `try_merge`, `swap_view`, `apply_delta_to_base` all operate on a single monotonically advancing `committed.state`) [4](#0-3) . "Interleaving writes across multiple pending StateDeltas" as described in the question isn't achievable by any custody-relevant input — it would require internal node/executor manipulation, which is out of scope per the review bounds (this is infrastructure code enforcing invariants via `assert!`, not a Move/bytecode-reachable custody surface). No multisig-owner resource write-ordering issue follows from this layer, since Move-level writes to resources are sequenced by transaction execution order within a single `State::update` call, not by arbitrary chaining of independently-constructed `StateDelta`s.

    pub fn is_descendant_of(&self, other: &Self) -> bool {
        if !self.is_family(other) {
            return false;
        }

        // Walk up the parent chain from `self` to verify `other` is an actual ancestor,
        // not merely a same-family node on a different fork.
        let mut cur = Arc::clone(&self.inner);
        loop {
            if Arc::ptr_eq(&cur, &other.inner) {
                return true;
            }
            if cur.layer <= other.inner.layer {
                // Reached or passed the target layer without finding `other`.
                return false;
            }
            match cur.parent.upgrade() {
                Some(parent) => cur = parent,
                // Parent has been dropped — `other` is not an ancestor.
                None => return false,
            }
        }
    }
