### Title
Unbounded recursive `RuntimeCall` decoding in `pallet-hyper-fungible-token`'s `on_accept` enables stack-exhaustion DoS - (File: modules/pallets/hyper-fungible-token/src/module.rs)

### Summary
`Pallet::<T>::on_accept` (the `IsmpModule` handler invoked for every incoming HFT cross-chain transfer) decodes an attacker-controlled `substrate_data.runtime_call` byte blob with plain `T::RuntimeCall::decode`, which recurses without any depth limit, unlike the sibling `pallet-call-decompressor`, which was hardened against exactly this bug class.

### Finding Description
When a `PostRequest` is delivered to the HFT module via `IsmpModule::on_accept`, the pallet ABI-decodes the message body and, if `message.data` is non-empty, decodes optional call data: [1](#0-0) 

The resulting `substrate_data.runtime_call` bytes are then decoded directly into the chain's `RuntimeCall` enum using the unbounded `codec::Decode::decode`: [2](#0-1) 

`RuntimeCall` is a recursive type — it contains variants like `Sudo::sudo(call: Box<RuntimeCall>)`, `Utility::batch(calls: Vec<RuntimeCall>)`, `Proxy::proxy(call: Box<RuntimeCall>)`, etc. SCALE's derived `Decode` implementation recurses once per nesting level with no built-in depth guard, so an attacker can craft a payload that nests such wrapper calls thousands of times, driving `Decode::decode` to unbounded native-stack recursion and crashing the validator/collator process (stack exhaustion) exactly as in the reported `time` crate class of bug (CWE-121, unbounded recursive parser).

This exact bug class already exists — and was already fixed — elsewhere in this repository: `pallet-call-decompressor` originally decoded a compressed `RuntimeCall` with plain `Decode` and was found vulnerable to the identical nested-`Sudo`-call stack-exhaustion attack (see the regression test `decompress_stack_exhaustion_poc`). It was patched by switching to `T::RuntimeCall::decode_all_with_depth_limit(MAX_EXTRINSIC_DECODE_DEPTH_LIMIT, ...)`: [3](#0-2) [4](#0-3) 

The HFT module's `on_accept` path, however, still uses the plain, unbounded `Decode::decode` and was not updated with the same protection.

### Impact Explanation
The `on_accept` entry point is reachable by any relayer delivering a `PostRequest` whose source contract is registered in `ContractToAsset` — this is the normal, unprivileged cross-chain token-transfer delivery path (a relayed message with a valid consensus/state proof, not an admin action). Triggering the crafted nested-call payload crashes the node process handling the extrinsic (stack overflow is typically an abort, not a catchable `Result` error), which can take down collators/validators processing the message, disrupting the pallet's mint/transfer flow and, more broadly, chain liveness for the affected state machine — a genuine availability (DoS) impact matching CVSS `VA:H/SA:H` in the source advisory.

### Likelihood Explanation
Likelihood is Medium: the attacker needs a `PostRequest` accepted by `on_accept`, i.e., a source contract already mapped via `ContractToAsset` for a real HFT deployment, and must route it through `dispatch`/relay with a valid state proof for the token bridge dispatcher. This requires the HFT bridge to be live and configured, but does not require any signature (the calldata path's `else` branch derives origin purely from `message.from` and does not authenticate the caller for unsigned calldata), and no special privilege is needed to submit the crafted payload once the token leg is set up — this is comparable in reachability to the already-fixed call-decompressor bug.

### Recommendation
Replace the unbounded decode in `on_accept` with a depth-limited decode, mirroring the fix already applied in `pallet-call-decompressor`:
```rust
let runtime_call = <T as frame_system::Config>::RuntimeCall::decode_all_with_depth_limit(
    MAX_RUNTIME_CALL_DECODE_DEPTH_LIMIT,
    &mut &*substrate_data.runtime_call,
)
.map_err(HftError::RuntimeCallDecodeError)?;
```
using `codec::DecodeLimit` and a small constant depth bound consistent with the shapes of calls the HFT module is intended to dispatch.

### Proof of Concept
1. Build a deeply nested `RuntimeCall`, e.g. thousands of levels of `RuntimeCall::Sudo(pallet_sudo::Call::sudo { call: Box::new(inner) })` (same construction already used in the repo's own regression test for the analogous bug): [5](#0-4) 
2. SCALE-encode this nested call and embed it as `SubstrateCalldata.runtime_call` inside an ABI-encoded HFT `Message.data` field, with `signature = None`.
3. Construct a `PostRequest` from a source contract already registered in `ContractToAsset`, carrying this `body`, and deliver it (with a valid membership proof) via the normal ISMP relay path so it reaches `Pallet::<T>::on_accept`.
4. `T::RuntimeCall::decode` at line 189 recurses once per `Sudo` wrapper with no depth limit, exhausting the native call stack and aborting the node process handling the message — unlike the compressed-call path, which now rejects such input cleanly via `decode_all_with_depth_limit`.
