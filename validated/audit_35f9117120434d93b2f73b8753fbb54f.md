### Title
Missing reentrancy guard on Tron `IntentGatewayV2.fillOrder`/`placeOrder`/`cancelOrder` allows escrow/fee theft via a malicious beneficiary or fee-on-transfer/callback token - ([File: evm/tron/contracts/apps/IntentGatewayV2.sol])

### Summary
The Tron port of the Intent Gateway (`evm/tron/contracts/apps/IntentGatewayV2.sol`) is missing the `nonReentrant` modifier that the canonical EVM `IntentGatewayV2` (`evm/src/apps/IntentGatewayV2.sol`) applies to `fillOrder` and `cancelOrder` [1](#0-0) . The EVM version's dedicated regression tests (`evm/tests/foundry/IntrinsicIntentsReentrancyTest.sol`) document a prior fee-theft reentrancy bug that was fixed by moving `_filled[commitment] = msg.sender` to the top of the fill functions (checks-effects-interactions) plus adding the reentrancy guard [2](#0-1) . The Tron contract's `placeOrder`, `cancelOrder`, and the equivalent fill path make external native-token/ERC20 calls (`.call{value:...}`, ERC20 `transfer`/`transferFrom`) to attacker-controlled addresses (order beneficiary, dispatcher) without any `nonReentrant` protection [3](#0-2) , and `withdraw()` performs the escrow accounting decrement *after* the external transfer call in some branches [4](#0-3) .

### Finding Description
`evm/tron/contracts/apps/IntentGatewayV2.sol` is a parallel, independently maintained implementation of the Intent Gateway for the Tron EVM. Comparing it to the hardened canonical version:

- The canonical `fillOrder` and `cancelOrder` are guarded with `nonReentrant` [1](#0-0) [5](#0-4) , and `placeOrder` too [6](#0-5) .
- The Tron `placeOrder`, `cancelOrder` functions carry no such modifier at all — a `grep` for `nonReentrant`/`ReentrancyGuard` across the Tron contract returned zero matches.
- `withdraw()` in the Tron contract sends value/tokens to `beneficiary` via low-level `.call`/`IERC20.transfer` and only decrements `_orders[body.commitment][token]` *after* the transfer completes [4](#0-3) , which is the exact "interaction-before-effect" pattern that the canonical contract's regression tests were written to eliminate.
- Since the beneficiary of a same-chain fill (and the recipient of native-token refunds during `placeOrder`/`cancelOrder`) is attacker-controlled data taken directly from the `Order` struct, an attacker can supply a malicious contract as beneficiary that re-enters `withdraw`/`cancelOrder`/`fillOrder` during the native-token `.call`, before `_orders[...]`/`_filled[...]` bookkeeping is finalized, and drain escrowed input tokens, transaction fees, or dust multiple times for a single order.

### Impact Explanation
This maps directly to "concrete theft of funds" via the token bridger/intent escrow path explicitly in scope. An attacker acting as an ordinary order-placer or solver (unprivileged actor issuing a single transaction) could repeatedly withdraw the same escrowed input tokens and accumulated transaction fees from the Tron `IntentGatewayV2` contract, draining protocol escrow — directly analogous to the Galaxy Fox incident's contract-vulnerability class where a flawed contract function let an attacker extract far more value than it should have. This is a High severity finding given the loss is escrowed user funds in a live token-bridging/intent-settlement contract.

### Likelihood Explanation
Likelihood is High: no privileged role or governance action is needed — a normal user can place a same-chain order whose beneficiary is a smart-contract-controlled address, then fill it (or trigger cancellation), reentering during the native ETH/TRX `.call`. No proof forgery, consensus manipulation, or relayer collusion is required; only a single transaction from an unprivileged account touching `placeOrder`/`fillOrder`/`cancelOrder`.

### Recommendation
Port the same-chain hardening already applied to `evm/src/apps/intentsv2/*` and `evm/src/apps/IntentGatewayV2.sol` into the Tron contract:
1. Add `ReentrancyGuard`/`nonReentrant` to `placeOrder`, `fillOrder`, and `cancelOrder`.
2. Set `_filled[commitment]` and decrement `_orders[...][token]` *before* any external call (native transfer or ERC20 transfer), following strict checks-effects-interactions, mirroring the fix documented in `IntrinsicIntentsReentrancyTest.sol`.
3. Add an equivalent reentrancy regression test suite for the Tron contract.

### Proof of Concept
Conceptual PoC (mirrors the pattern in `evm/tests/foundry/IntrinsicIntentsReentrancyTest.sol`):
1. Deploy a `ReentrantBeneficiary` contract whose `receive()` calls back into `IntentGatewayV2.cancelOrder`/`withdraw`-triggering path.
2. Attacker calls `placeOrder` with `output.beneficiary` set to the malicious contract and native-token output/fees.
3. Attacker triggers the fill/cancel path; during the native `.call{value:...}` to the malicious beneficiary in `withdraw()` (`evm/tron/contracts/apps/IntentGatewayV2.sol:702-708`), the beneficiary re-enters before `_orders[body.commitment][token] -= amount` executes, allowing a second withdrawal of the same escrow before the first completes.

Note: I could not execute this against the actual Tron contract (no test harness for it was found in the indexed code), so this is a structural/code-review-based finding derived from the documented, already-fixed vulnerability in the sibling EVM contract plus direct inspection of the Tron contract's missing guard and post-transfer bookkeeping. Given index size limits, some auxiliary Tron test files may not be indexed — a Devin session with full repo access should confirm whether a Tron-specific reentrancy guard exists elsewhere (e.g., inherited from a base contract not shown here) before treating this as fully confirmed.

    function cancelOrder(Order calldata order, CancelOptions calldata options) public payable {
        bytes32 commitment = keccak256(abi.encode(order));

        // order has already been filled
        if (_filled[commitment] != address(0)) revert Filled();

        address hostAddr = host();
        bytes32 currentChain = keccak256(IDispatcher(hostAddr).host());
        bytes32 orderSource = keccak256(order.source);
        bytes32 orderDest = keccak256(order.destination);
        bool isSameChain = orderSource == orderDest;

        if (isSameChain) {
            // Same-chain: validate locally and refund immediately
            // only owner can cancel
            if (order.user != bytes32(uint256(uint160(msg.sender)))) revert Unauthorized();

            // Verify we're on the correct chain
            if (orderSource != currentChain) revert WrongChain();

            WithdrawalRequest memory body =
                WithdrawalRequest({commitment: commitment, tokens: order.inputs, beneficiary: order.user});

            withdraw(body, true);
        } else if (currentChain == orderSource) {
            // source chain: fetch storage proof from destination
            // only owner can cancel order
            if (order.user != bytes32(uint256(uint160(msg.sender)))) revert Unauthorized();

            // order has not yet expired
            if (options.height <= order.deadline) revert NotExpired();

            // Cross-chain: fetch storage proof
            uint256 inputsLen = order.inputs.length;
            for (uint256 i; i < inputsLen;) {
                // check for order existence
                if (_orders[commitment][address(uint160(uint256(order.inputs[i].token)))] == 0) revert UnknownOrder();

                unchecked {
                    ++i;
                }
            }

            bytes memory context =
                abi.encode(WithdrawalRequest({commitment: commitment, tokens: order.inputs, beneficiary: order.user}));

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(
                // contract address
                abi.encodePacked(instance(order.destination)),
                // storage slot hash
                calculateCommitmentSlotHash(commitment)
            );
            DispatchGet memory request = DispatchGet({
                dest: order.destination,
                keys: keys,
                timeout: 0,
                height: uint64(options.height),
                fee: options.relayerFee,
                context: context,
                payer: msg.sender
            });

            // dispatch storage query request
            if (msg.value > 0) {
                // there's some native tokens left to pay for request dispatch
                IDispatcher(hostAddr).dispatch{value: msg.value}(request);
            } else {
                // try to pay for dispatch with fee token
                dispatchWithFeeToken(request);
            }
        } else if (currentChain == orderDest) {
            // destination chain: dispatch RefundEscrow request to source chain
            // If order hasn't expired, only owner can cancel
            if (order.deadline >= block.number) {
                if (order.user != bytes32(uint256(uint160(msg.sender)))) revert Unauthorized();
            }

            // Mark as cancelled locally to prevent fills
            _filled[commitment] = address(uint160(uint256(order.user)));

            bytes memory body = bytes.concat(
                bytes1(uint8(RequestKind.RefundEscrow)),
                abi.encode(WithdrawalRequest({commitment: commitment, tokens: order.inputs, beneficiary: order.user}))
            );

            DispatchPost memory request = DispatchPost({
                dest: order.source,
                to: abi.encodePacked(instance(order.source)),
                body: body,
                timeout: 0,
                fee: options.relayerFee,
                payer: msg.sender
            });

            // dispatch refund request
            if (msg.value > 0) {
                IDispatcher(hostAddr).dispatch{value: msg.value}(request);
            } else {
                // try to pay for dispatch with fee token
                dispatchWithFeeToken(request);
            }
        } else {
            revert WrongChain();
        }
    }
