Audit Report

## Title
`pool` extrinsic can silently drop a coretime region while emitting `Event::Pooled` and returning success when the per-core `Workplan` bound is full - (File: substrate/frame/broker/src/dispatchable_impls.rs, function `do_pool`)

## Summary
`do_pool` calls `Self::utilize()`, which unconditionally removes the region from `Regions` (and only reinstates it for `Finality::Provisional`), then only *conditionally* records pooling bookkeeping (`Workplan`, `InstaPoolIo`, `InstaPoolContribution`) inside an `if workplan.try_push(...).is_ok()` guard. If the bounded `Workplan` entry for `(begin, core)` is already full, the function still returns `Ok(())` and unconditionally emits `Event::Pooled`, even though no bookkeeping was created and, for `Finality::Final`, the region was permanently destroyed with no way to recover it. [1](#0-0) 

## Finding Description
`do_pool` first calls `utilize`, which for any non-provisional finality unconditionally calls `Regions::<T>::remove(&region_id)` and does not reinsert the region unless `finality == Finality::Provisional`: [2](#0-1) 

Back in `do_pool`, bookkeeping (`Workplan` insertion, `InstaPoolIo` mutation, `InstaPoolContribution` insertion) is only performed inside `if workplan.try_push(...).is_ok()`. Crucially, `Self::deposit_event(Event::Pooled { region_id, duration })` sits *outside* and *after* that `if` block, so it fires regardless of whether the push succeeded, and the function unconditionally returns `Ok(())`. [3](#0-2) 

This confirms the exact bug described: for `Finality::Final`, once `utilize()` has already removed the region from storage, a failed `try_push` on the bounded `Workplan` vector leaves the region permanently gone from `Regions`, with no entry created in `Workplan`, `InstaPoolIo`, or `InstaPoolContribution`, yet `Event::Pooled` is still emitted and the extrinsic returns success (and is even fee-free via `Pays::No`). [4](#0-3) 

Notably, the sibling function `do_assign` exhibits the identical pattern — `workplan.try_push(...).is_ok()` gates only the workplan insertion, while `Event::Assigned` is deposited unconditionally afterward — confirming this is a systemic pattern in this file rather than an isolated typo, and reinforcing that the guard genuinely does not propagate failure. [5](#0-4) 

## Impact Explanation
This is a genuine broken invariant: the pallet's own event stream and `Ok(())` return value assert that pooling succeeded, while the actual storage state (`Regions`, `Workplan`, `InstaPoolContribution`, `InstaPoolIo`) shows no pooling occurred and, for `Finality::Final`, the region is irrecoverably destroyed. This is an unprivileged, signed-origin-triggerable state inconsistency causing loss of a valuable resource (a coretime region) with no compensating InstaPool credit for the payee, and it is fee-free for `Finality::Final` making it low-cost to trigger.

## Likelihood Explanation
Filling the bounded `Workplan` entry for a specific `(begin, core)` key requires enough `interlace`/`assign`/`pool` operations on mask fragments of that same slot to hit the bounded vector's capacity limit. All of `interlace`, `assign`, and `pool` are plain signed-origin extrinsics available to any account owning the relevant region/core, making this a deterministic, repeatable condition rather than a race — an account controlling a purchased core can reach this state within normal transaction flow.

## Recommendation
- Propagate a hard error from `do_pool` (e.g., a new `Error::<T>::TooManyWorkplanItems`) when `workplan.try_push` fails, instead of silently skipping bookkeeping and continuing.
- Move `Self::deposit_event(Event::Pooled { .. })` inside the successful branch only.
- Since `utilize()` already performed an irreversible `Regions::remove` before the workplan capacity is known, either check workplan capacity before calling `utilize()`, or ensure the region is reinstated/refunded when pooling cannot be completed, including for `Finality::Final`.
- Apply the same fix to `do_assign`, which has the identical unguarded-event pattern.

## Proof of Concept
1. Call `do_start_sales` and `do_purchase` to acquire a core, obtaining a `region_id` covering `CoreMask::complete()`.
2. Repeatedly call `do_interlace` to split the region into many small disjoint mask fragments, and `do_assign(..., Finality::Final)` each fragment to fill `Workplan::get((begin, core))` up to its bounded capacity.
3. Take a remaining unassigned fragment `region_x` and call `Broker::pool(signed(owner), region_x, payee, Finality::Final)`.
4. Observe: the call returns `Ok(_)` and emits `Event::Pooled { region_id: region_x, .. }`; `Regions::<Test>::get(&region_x)` is `None`; `InstaPoolContribution::<Test>::get(&region_x)` is `None`; `Workplan` does not contain the `Pool` assignment for `region_x`. A subsequent `do_claim_revenue(region_x, ...)` returns `Error::<Test>::UnknownContribution`, confirming the region's coretime value is unrecoverable despite the reported "success."

	pub(crate) fn do_pool(
		region_id: RegionId,
		maybe_check_owner: Option<T::AccountId>,
		payee: T::AccountId,
		finality: Finality,
	) -> Result<(), Error<T>> {
		if let Some((region_id, region)) = Self::utilize(region_id, maybe_check_owner, finality)? {
			let workplan_key = (region_id.begin, region_id.core);
			let mut workplan = Workplan::<T>::get(&workplan_key).unwrap_or_default();
			let duration = region.end.saturating_sub(region_id.begin);
			if workplan
				.try_push(ScheduleItem { mask: region_id.mask, assignment: CoreAssignment::Pool })
				.is_ok()
			{
				Workplan::<T>::insert(&workplan_key, &workplan);
				let size = region_id.mask.count_ones() as i32;
				InstaPoolIo::<T>::mutate(region_id.begin, |a| a.private.saturating_accrue(size));
				InstaPoolIo::<T>::mutate(region.end, |a| a.private.saturating_reduce(size));
				let record = ContributionRecord { length: duration, payee };
				InstaPoolContribution::<T>::insert(&region_id, record);
			}

			Self::deposit_event(Event::Pooled { region_id, duration });
		}
		Ok(())
	}

	pub(crate) fn utilize(
		mut region_id: RegionId,
		maybe_check_owner: Option<T::AccountId>,
		finality: Finality,
	) -> Result<Option<(RegionId, RegionRecordOf<T>)>, Error<T>> {
		let status = Status::<T>::get().ok_or(Error::<T>::Uninitialized)?;
		let region = Regions::<T>::get(&region_id).ok_or(Error::<T>::UnknownRegion)?;

		if let Some(check_owner) = maybe_check_owner {
			ensure!(Some(check_owner) == region.owner, Error::<T>::NotOwner);
		}

		Regions::<T>::remove(&region_id);

		let last_committed_timeslice = status.last_committed_timeslice;
		if region_id.begin <= last_committed_timeslice {
			let duration = region.end.saturating_sub(region_id.begin);
			region_id.begin = last_committed_timeslice + 1;
			if region_id.begin >= region.end {
				Self::deposit_event(Event::RegionDropped { region_id, duration });
				return Ok(None);
			}
		} else {
			Workplan::<T>::mutate_extant((region_id.begin, region_id.core), |p| {
				p.retain(|i| (i.mask & region_id.mask).is_void())
			});
		}
		if finality == Finality::Provisional {
			Regions::<T>::insert(&region_id, &region);
		}

		Ok(Some((region_id, region)))
	}
