Audit Report

## Title
Unauthenticated exposure of LOOP plugin discovery, metrics-proxy, and pprof-proxy endpoints via `loopRoutes` - (File: `core/web/router.go`)

## Summary
`NewRouter` mounts `loopRoutes(app, api)` directly on the top-level `api` gin group, which only applies rate-limiting and session middleware, without wrapping it in `auth.Authenticate` as is done for `debugRoutes` and the authenticated half of `sessionRoutes`. This leaves `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` reachable by any unauthenticated client that can reach the node's web port.

## Finding Description
In `core/web/router.go`, the `api` group is created with only rate limiting and a session-cookie middleware, no authentication requirement: [1](#0-0) . `loopRoutes` is called directly on this `api` group: [2](#0-1) , registering `discoveryHandler`, `pluginMetricHandler`, `pluginPPROFHandler`, and `pluginPPROFPOSTSymbolHandler` with no auth middleware.

By contrast, `debugRoutes` explicitly wraps `/debug/vars` behind `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)`: [3](#0-2) , and `sessionRoutes` splits into an unauthenticated login group and a separately authenticated destroy-session group: [4](#0-3) . No equivalent gate exists for `loopRoutes`.

The handlers themselves proxy live requests to internal LOOP plugin processes and stream results back verbatim: `pluginMetricHandler` fetches `http://<loopHostName>:<PrometheusPort>/metrics` and writes the body to the response: [5](#0-4) ; `pluginPPROFHandler` forwards to `http://<loopHostName>:<PrometheusPort>/debug/pprof/<profile>` with attacker-supplied query parameters including `seconds`, and `doRequest` streams the profiling payload back: [6](#0-5) . The comment "unlike discovery, this endpoint is internal btw the node and plugin" in the source shows the developers assumed network-level isolation as the security boundary rather than an explicit auth check, which is incorrect since the route is exposed on the same public port as GraphQL/session endpoints.

## Impact Explanation
An unauthenticated network-reachable client can enumerate LOOP plugins and their metrics targets via `GET /discovery`, pull a plugin's raw Prometheus metrics via `GET /plugins/:name/metrics` (information disclosure of internal runtime/environment data), and trigger CPU/heap/goroutine profiling of internal plugin processes via `GET /plugins/:name/debug/pprof/profile?seconds=N` (resource consumption / limited denial-of-service, with `N` controllable up to attacker's choice, tying up the plugin process for the profiling duration). This is a genuine node API authentication/authorization gap — normal Chainlink API routes require session or API-token auth, but this specific route group does not, which is an in-scope "node API authentication ... bypass" class issue.

## Likelihood Explanation
Exploitation only requires network reachability to the node's HTTP/API port (the same port serving GraphQL, sessions, and health checks) and knowledge or enumeration of a plugin name via `/discovery` — no credentials, cookies, or tokens are needed. Any deployment exposing the Chainlink web server to untrusted networks (which is the normal operating mode for a node's API/GUI port) is affected, making this readily and repeatably triggerable.

## Recommendation
Wrap `loopRoutes(app, api)` in the same authenticated sub-group pattern used by `debugRoutes`, e.g. register it under a group with `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)` (or token-based auth), or move plugin discovery/metrics/pprof-proxy handlers to a separate internal-only listener/port that is never exposed alongside the public GraphQL/session API.

## Proof of Concept
1. Run a Chainlink node with at least one LOOP plugin registered and its web API reachable.
2. Without any session cookie or `Authorization` header, issue:
   - `GET http://<node-host>:6688/discovery` → expect 200 with JSON listing plugin metrics targets.
   - `GET http://<node-host>:6688/plugins/<plugin-name>/metrics` → expect 200 with raw plugin Prometheus metrics text.
   - `GET http://<node-host>:6688/plugins/<plugin-name>/debug/pprof/profile?seconds=30` → expect 200 with a binary pprof CPU profile after ~30s, all without authentication, confirming the middleware chain in `core/web/router.go` lines 87-91 provides no auth gate for these three requests as opposed to `/debug/vars` or `DELETE /sessions` which return 401 under the same conditions.

func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/metrics", l.loopHostName, p.EnvCfg.PrometheusPort)
	req, err := http.NewRequestWithContext(gc.Request.Context(), http.MethodGet, pluginURL, nil)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)
	if err != nil {
		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q metrics", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}

func (l *LoopRegistryServer) doRequest(gc *gin.Context, method, url string, body io.Reader, timeout time.Duration, pluginName string) {
	ctx, cancel := context.WithTimeout(gc.Request.Context(), timeout)
	defer cancel()
	req, err := http.NewRequestWithContext(ctx, method, url, body)
