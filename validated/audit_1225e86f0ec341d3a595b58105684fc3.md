Audit Report

## Title
Cross-user response hijack via `MessageID` collision in the WebAPI Trigger capability handler's `savedCallbacks` map - ([File: core/services/gateway/handlers/capabilities/handler.go])

## Summary
`HandleLegacyUserMessage` in `core/services/gateway/handlers/capabilities/handler.go` stores the caller's callback in `h.savedCallbacks` keyed solely by the caller-supplied `msg.Body.MessageID`, with no check for an existing in-flight entry before overwriting it [1](#0-0) . When a DON node later responds, `handleWebAPITriggerMessage` looks the callback up purely by `MessageID` and delivers the response to whatever callback currently occupies that slot [2](#0-1) , so a second, independently-signed request that reuses the same `MessageID` before the original responder answers overwrites the first caller's callback and receives the first caller's response. The identical pattern (unbounded overwrite + lookup-by-ID-only) also exists in `core/services/gateway/handlers/handler.dummy.go` [3](#0-2) [4](#0-3) .

## Finding Description
`api.Message.Validate()`, invoked from `gateway.ProcessRequest`, checks signature well-formedness and `MessageID`/length constraints, but performs no allowlist check and no check that the `MessageID` is unique or bound to the signer [5](#0-4) . `ProcessRequest` dispatches any syntactically valid, signed message straight into `HandleLegacyUserMessage` with no session or identity binding beyond the signature-derived sender address [6](#0-5) .

`HandleLegacyUserMessage` unconditionally writes `h.savedCallbacks[msg.Body.MessageID] = &savedCallback{...}` [1](#0-0) , unlike the newer HTTP trigger handler's `setupCallback`, which explicitly rejects a colliding, in-flight `requestID` [7](#0-6) . On the node-response path, `handleWebAPITriggerMessage` looks up and deletes `savedCallbacks[msg.Body.MessageID]` and delivers whatever is found there to the caller [2](#0-1) . If User A's request occupies `savedCallbacks["X"]` while awaiting the DON's asynchronous response, an unprivileged User B who submits any independently, validly-signed message with the same `MessageID = "X"` before the node answers will overwrite the slot; when the node's response for "X" arrives, it is delivered to User B's callback instead of User A's. A code review TODO in the test file confirms the handler layer performs no sender allowlist/rate-limit validation on the incoming request [8](#0-7) , so nothing else in this call path prevents the collision.

The claim is technically accurate: I confirmed the missing duplicate-ID guard, the ID-only lookup, and the presence of an equivalent guard elsewhere (`http_trigger_handler.go`) that is not applied here.

## Impact Explanation
This is a legitimate cross-user response-routing confusion in the Gateway's legacy WebAPI-trigger path, matching the in-scope "cross-user response corruption" / "gateway request impersonation" categories. However, the actual data exposed through this specific path (`MethodWebAPITrigger`) is limited: the DON node's response for a trigger call is only `TriggerResponsePayload{Status: "ACCEPTED"}` or `{Status: "ERROR", ErrorMessage: ...}` [9](#0-8) , and the error text can include details such as the target sender/messageID when a sender-allowlist check fails [10](#0-9) . So an attacker exploiting the collision would receive another user's trigger-acceptance status/error text rather than arbitrary sensitive payload data — a genuine but low-severity information/response-confusion issue rather than fund movement or credential exposure. The same structural flaw (unbounded overwrite, no duplicate check) also exists in `handler.dummy.go`, though that handler is a minimal pass-through utility.

## Likelihood Explanation
Exploitation requires an attacker to both learn/guess a victim's chosen `MessageID` and win a race to submit a colliding, validly-signed message before the DON node responds to the original request; there is no rate limiting or allowlist enforced at the point `savedCallbacks` entries are created for either affected handler [11](#0-10) . This is repeatable since nothing detects or blocks the collision.

## Recommendation
Add a duplicate-ID guard to `HandleLegacyUserMessage` (and `HandleJSONRPCUserMessage`/`HandleLegacyUserMessage` in `handler.dummy.go`), mirroring `setupCallback`'s conflict check in `v2/http_trigger_handler.go`, so a request cannot silently overwrite another in-flight `MessageID`'s callback. Additionally consider binding the `savedCallbacks` key (or a secondary check on retrieval) to the requester's signer-derived sender address so a node response can only be routed to the callback of the same signer that originated the request.

## Proof of Concept
1. As User A, submit a validly-signed `api.Message` with `MessageID = "victim-id"`, `Method = web_api_trigger` to the Gateway; `HandleLegacyUserMessage` stores `savedCallbacks["victim-id"]` and forwards to DON nodes [12](#0-11) .
2. Before any node responds, as User B, submit an independently-signed message reusing `MessageID = "victim-id"`; this overwrites `savedCallbacks["victim-id"]` with User B's callback (no conflict check exists, unlike `setupCallback` in `v2/http_trigger_handler.go`).
3. When a DON node responds for `MessageID = "victim-id"`, `handleWebAPITriggerMessage` delivers the response (User A's trigger `ACCEPTED`/`ERROR` status) to User B's callback instead of User A's [2](#0-1) . A Go unit test can drive this directly through `handler.HandleLegacyUserMessage` twice with the same `MessageID` and differing callbacks, then invoke `HandleNodeMessage`/`handleWebAPITriggerMessage` once, asserting the second callback receives the response.

func (d *dummyHandler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback Callback) error {
	d.mu.Lock()
	d.savedCallbacks[msg.Body.MessageID] = &savedCallback{msg.Body.MessageID, callback}

	d.mu.Unlock()
	params, err := json.Marshal(msg)

		return err

		ID:      msg.Body.MessageID,
		Method:  msg.Body.Method,
		Params:  &rawParams,
	}
	for _, member := range d.donConfig.Members {
		err = errors.Join(err, don.SendToNode(ctx, member.Address, req))
	}

func (d *dummyHandler) HandleNodeMessage(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	var msg api.Message
	err := json.Unmarshal(*resp.Result, &msg)
	if err != nil {
		return err
	}
	msg.Body.MessageID = resp.ID
	err = msg.Validate()
	if err != nil {
		return err
	}
	if nodeAddr != msg.Body.Sender {
		return fmt.Errorf("node address %s does not match message sender %s", nodeAddr, msg.Body.Sender)
	}
	d.mu.Lock()
	savedCb, found := d.savedCallbacks[msg.Body.MessageID]
	delete(d.savedCallbacks, msg.Body.MessageID)
	d.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		codec := api.JSONRPCCodec{}
		return savedCb.SendResponse(UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(&msg), ErrorCode: api.NoError})
	}
	return nil

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageID) == 0 || len(m.Body.MessageID) > MessageIDMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageID, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonID) == 0 || len(m.Body.DonID) > MessageDonIDMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonID, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

func (g *gateway) ProcessRequest(ctx context.Context, rawRequest []byte, auth string) (rawResponse []byte, httpStatusCode int) {
	// decode
	jsonRequest, err := jsonrpc2.DecodeRequest[json.RawMessage](rawRequest, auth)
	if err != nil {
		return newError("", api.UserMessageParseError, err.Error())
	}
	msg, err := g.codec.DecodeJSONRequest(jsonRequest)
	if err != nil {
		return newError(jsonRequest.ID, api.UserMessageParseError, err.Error())
	}
	if len(jsonRequest.ID) > 200 {
		// Arbitrary limit to prevent abuse
		return newError(jsonRequest.ID, api.UserMessageParseError, "request ID is too long: "+strconv.Itoa(len(jsonRequest.ID))+". max is 200 characters")
	}
	isLegacyRequest := false
	var h handlers.Handler
	var handlerKey string
	if msg == nil || msg.Body.DonID == "" {
		serviceName := jsonRequest.ServiceName()
		if handler, ok := g.serviceToMultiHandler[serviceName]; ok {
			h = handler
			handlerKey = serviceName
		} else if donID, ok := g.serviceNameToDonID[serviceName]; ok {
			// Fallback to legacy service name -> DON ID mapping
			if handler, ok := g.handlers[donID]; ok {
				h = handler
				handlerKey = donID
			}
		}
		if h == nil {
			return newError(jsonRequest.ID, api.HandlerError, "Service name not found: "+serviceName)
		}
	} else {
		// Legacy request with DON ID - validate and fetch handler
		isLegacyRequest = true
		if err = msg.Validate(); err != nil {
			return newError(jsonRequest.ID, api.UserMessageParseError, err.Error())
		}
		handlerKey = msg.Body.DonID
		var ok bool
		h, ok = g.handlers[handlerKey]
		if !ok {
			return newError(jsonRequest.ID, api.UnsupportedDONIdError, "Unsupported DON ID: "+handlerKey)
		}
	}

	startTime := time.Now()
	var method string
	callback := handlerscommon.NewCallback()
	if isLegacyRequest {
		method = msg.Body.Method
		err = h.HandleLegacyUserMessage(ctx, msg, callback)
	} else {
		method = jsonRequest.Method
		err = h.HandleJSONRPCUserMessage(ctx, jsonRequest, callback)
	}
	if err != nil {
		return newError(jsonRequest.ID, api.HandlerError, err.Error())
	}
