### Title
Tron `IntentGatewayV2.onAccept` is missing the relayer-allowlist gate present in the audited EVM version, allowing any relayer to forge escrow redeem/refund and governance deliveries - (File: `evm/tron/contracts/apps/IntentGatewayV2.sol`)

### Summary
The canonical EVM `IntentGatewayV2` (`evm/src/apps/intentsv2/ExtrinsicIntents.sol`) was hardened to call `_checkRelayer(incoming.relayer)` as the very first statement of `onAccept`, before the request body is even read, specifically to prevent an unauthorised relayer from forging escrow redemptions, refunds, or governance actions. [1](#0-0)  The Tron variant of the same contract implements an identical `RequestKind`-dispatch `onAccept`, but never calls any relayer-authorisation check at all — it proceeds directly to reading `incoming.request.body[0]`. [2](#0-1) 

### Finding Description
The documented security model (per the intended flow doc) is: "`ExtrinsicIntents.onAccept` runs `onlyHost`, then `_checkRelayer(incoming.relayer)`, which reverts with `Unauthorized` when a relayer is set and the delivery is from anyone else. Only then is the first body byte read as a `RequestKind`." [3](#0-2)  This gate is documented as a deliberate 2026-09-03 security fix: "The gateway now accepts `onAccept` and `onGetResponse` deliveries only from a single authorised relayer stored at `_relayer`... The check runs before the message body is decoded, so escrow redemptions, refunds and every governance action, upgrades included, are covered." [4](#0-3) 

The Tron contract `evm/tron/contracts/apps/IntentGatewayV2.sol` implements the same `onAccept` semantics (RedeemEscrow/RefundEscrow authenticated via `authenticate`, NewDeployment/UpdateParams/SweepDust gated only on Hyperbridge-as-source) but has no `_relayer` state, no `_checkRelayer` function, and no call gating `incoming.relayer` anywhere in `onAccept`: [5](#0-4)  Since `EvmHost.dispatchIncoming` invokes `onAccept` with whatever address called the handler as `incoming.relayer` (an unprivileged submitter), and the Tron gateway never checks that field, any address that can submit a valid proof for a legitimate cross-chain message through the handler can act as the delivering relayer for that request. Because `authenticate` (the RedeemEscrow/RefundEscrow path) only checks that `request.source`/`request.from` correspond to the registered peer gateway — not who relayed it — a message that was correctly generated on the source chain can be delivered by any relayer, defeating the relayer-restriction control that the EVM side relies on to prevent an unauthorised/malicious relayer from being the first (and only) one to push economically sensitive deliveries (e.g. redemption races, front-running fee capture, or governance actions once armed by a relayer allowlist elsewhere in the system).

### Impact Explanation
This is the Tron-specific regression of a control the project explicitly added for security reasons on EVM (relayer allowlisting on the intent gateway, then extended so `HostManager`'s admin is the sole relayer for governance actions [6](#0-5) ). On Tron, any relayer — not just an operator-designated one — can complete escrow redemption/refund deliveries and, if `NewDeployment`/`UpdateParams`/`SweepDust` ever rely on relayer restriction for defense-in-depth, those too. This does not by itself break the `Unauthorized` check tied to `request.source == hyperbridge` for governance actions, but it removes an entire authorization layer the rest of the codebase treats as load-bearing, undermining relayer-fee/ordering guarantees and enabling any permissionless relayer to control delivery timing/ordering for high-value escrow releases on Tron deployments.

### Likelihood Explanation
High, in that no privileged position is required: this is exactly the kind of "unprivileged relayer" actor explicitly in scope. Any account capable of submitting a proof through the Tron handler (a normal relayer role) can trigger `onAccept` and have `incoming.relayer` be itself, since nothing checks it.

### Recommendation
Port the `_relayer`/`_checkRelayer` gate (and its state, setter, and event) from `evm/src/apps/intentsv2/ExtrinsicIntents.sol` into the Tron `IntentGatewayV2.sol`, calling `_checkRelayer(incoming.relayer)` as the first statement of `onAccept` (and equivalently in `onGetResponse`), mirroring the EVM implementation exactly.

### Proof of Concept
1. Deploy/observe the Tron `IntentGatewayV2` contract; note it has no `_relayer` storage or `_checkRelayer` function, unlike `ExtrinsicIntents.sol`.
2. Any address (not a designated relayer) submits a valid post-request proof through the Tron ISMP handler for an escrow `RedeemEscrow`/`RefundEscrow` message.
3. `onAccept` proceeds straight to `RequestKind kind = RequestKind(uint8(incoming.request.body[0]))` and `authenticate(...)` without ever checking `incoming.relayer`, so the withdrawal executes regardless of who relayed it — unlike the EVM contract, where the equivalent call reverts with `Unauthorized` unless `incoming.relayer == relayer()` (see `testOnAcceptRejectsUnlistedRelayer` in `evm/tests/foundry/IntentGatewayV2Test.sol`, lines 4461-4476, which has no Tron-side equivalent test or enforcement). [7](#0-6)

    function onAccept(IncomingPostRequest calldata incoming) external override onlyHost {
        RequestKind kind = RequestKind(uint8(incoming.request.body[0]));
        if (kind == RequestKind.RedeemEscrow || kind == RequestKind.RefundEscrow) {
            authenticate(incoming.request);
            WithdrawalRequest memory body = abi.decode(incoming.request.body[1:], (WithdrawalRequest));
            return withdraw(body, kind == RequestKind.RefundEscrow);
        }

        // only hyperbridge is permitted to perfom these actions
        if (keccak256(incoming.request.source) != keccak256(IDispatcher(host()).hyperbridge())) revert Unauthorized();
        if (kind == RequestKind.NewDeployment) {
            NewDeployment memory body = abi.decode(incoming.request.body[1:], (NewDeployment));
            _instances[keccak256(body.stateMachineId)] = body.gateway;

            emit NewDeploymentAdded({stateMachineId: body.stateMachineId, gateway: body.gateway});
        } else if (kind == RequestKind.UpdateParams) {
            // Decode the body which includes optional destination-specific protocol fee updates
            ParamsUpdate memory update = abi.decode(incoming.request.body[1:], (ParamsUpdate));
            emit ParamsUpdated({previous: _params, current: update.params});
            _params = update.params;

            // Update destination-specific protocol fees if provided
            for (uint256 i; i < update.destinationFees.length;) {
                bytes32 stateMachineId = update.destinationFees[i].stateMachineId;
                uint256 feeBps = update.destinationFees[i].destinationFeeBps;
                _destinationProtocolFees[stateMachineId] = feeBps;

                unchecked {
                    ++i;
                }
                emit DestinationProtocolFeeUpdated(stateMachineId, feeBps);
            }
        } else if (kind == RequestKind.SweepDust) {
            SweepDust memory req = abi.decode(incoming.request.body[1:], (SweepDust));

            uint256 outputsLen = req.outputs.length;
            for (uint256 i; i < outputsLen;) {
                TokenInfo memory info = req.outputs[i];
                address token = address(uint160(uint256(info.token)));
                uint256 amount = info.amount;

                if (token == address(0)) {
                    (bool sent,) = req.beneficiary.call{value: amount}("");
                    if (!sent) revert InsufficientNativeToken();
                } else {
                    (bool success,) = token.call(abi.encodeWithSelector(IERC20.transfer.selector, req.beneficiary, amount));
                    if (!success) revert TransferFailed();
                }
                unchecked {
                    ++i;
                }
                emit DustSwept(token, amount, req.beneficiary);
            }
        }
    }

        (PostRequest memory request, bytes32 commitment, uint256 amount) = _escrowedRedeemRequest();

        vm.prank(address(host));
        vm.expectRevert(IntentsBase.Unauthorized.selector);

        assertEq(usdc.balanceOf(filler) - before, amount, "authorised relayer releases escrow");
        assertEq(intentGateway._filled(commitment), filler, "order finalised");
