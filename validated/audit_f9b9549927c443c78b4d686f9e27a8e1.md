## Title
Consensus incentives reward calculation applies newly-set `cost_per_block` retroactively to the entire unpaid block span, letting a relayer capture inflated rewards from stale updates - (File: `modules/pallets/consensus-incentives/src/impls.rs`)

### Summary
`pallet-consensus-incentives` rewards a relayer for delivering a `ConsensusMessage` by multiplying the number of newly-advanced blocks by the *current* `StateMachinesCostPerBlock` rate. The rate can be changed at any time via the privileged `update_cost_per_block` extrinsic, but the change is applied immediately with no settlement of the reward owed for the span that already elapsed under the old rate. This is the same bug class as Super DCA's `setMintRate()` issue: `mintRate`/`cost_per_block` is overwritten before the pending "elapsed" interval is priced at the old rate.

### Finding Description
`calculate_reward` computes the reward strictly from the *current* rate and the block delta since the last-rewarded watermark: [1](#0-0) 

```
let blocks = latest_height.saturating_sub(baseline);
let reward = blocks_as_balance.saturating_mul(block_cost); // block_cost is CURRENT rate
```

`block_cost` here is fetched from `StateMachinesCostPerBlock` at call time inside `process_message`: [2](#0-1) 

The rate itself is mutated in-place with no prior accrual/settlement step: [3](#0-2) 

```rust
pub fn update_cost_per_block(...) -> DispatchResult {
    T::IncentivesOrigin::ensure_origin(origin)?;
    StateMachinesCostPerBlock::<T>::mutate(state_machine_id.clone(), |maybe_cost| {
        *maybe_cost = Some(cost_per_block);
    });
    ...
}
```

Because `LastRewardedHeight` is only advanced when a reward is actually paid (`process_message`, `impls.rs:70-72`), the "unpaid span" (`latest_height - baseline`) can accumulate across many blocks/consensus updates while the relayer simply withholds submitting the `ConsensusMessage`. Reward computation never splits the span by the rate that was active during each sub-interval — it always uses whatever `block_cost` is in storage the moment `on_executed` runs. An unprivileged relayer therefore controls *when* to submit a proof it already possesses, and can time submission to occur right after `cost_per_block` is raised, collecting the entire backlog of blocks at the new, higher rate instead of the rate(s) that were actually in force while those blocks were produced. This exactly mirrors the Super DCA root cause where `setMintRate()` overwrites `mintRate` before `_updateRewardIndex()` prices the elapsed interval at the old rate.

### Impact Explanation
A relayer can withhold delivery of a `ConsensusMessage` it is capable of submitting immediately, wait for governance to raise `cost_per_block` for a state machine (a routine incentive-tuning action, not malicious governance), and then submit the backlog in one batch. `calculate_reward` prices the *entire* unpaid span at the new, higher rate, draining excess funds from `T::TreasuryAccount` beyond what governance intended to pay for that historical period. This is a direct treasury drain / fund-misallocation impact, satisfying "concrete theft ... of funds" — the same class of impact the Sherlock report flags as Medium/High.

### Likelihood Explanation
The trigger requires only two ordinary, expected on-chain events: (1) a rate change via `update_cost_per_block` (a normal governance operation, not an attack) and (2) an unprivileged relayer choosing when to submit a `ConsensusMessage` it already holds. No malicious governance/admin behavior is needed — the relayer alone controls the timing that turns a routine rate increase into an overpayment. Given relayers are economically motivated to maximize their reward and already control submission timing, this is a realistic, repeatable griefing/profit vector each time the rate is adjusted upward.

### Recommendation
Settle the currently-accrued, unpaid reward at the *old* rate before applying a new `cost_per_block`, mirroring the Super-DCA fix (`_updateRewardIndex()` before rate mutation):
- In `update_cost_per_block`, before overwriting `StateMachinesCostPerBlock`, compute and pay/checkpoint the reward for the span `[LastRewardedHeight, latest_commitment_height]` at the existing rate, and advance `LastRewardedHeight` to `latest_commitment_height`.
- Alternatively, store rate-change checkpoints (height + rate) and have `calculate_reward` split the span across each rate interval so historical blocks are always priced at the rate that was active when they were produced.

### Proof of Concept
1. Governance sets `cost_per_block = 10` for `state_machine_id` via `update_cost_per_block`.
2. State machine advances 1000 blocks; the relayer already possesses a valid consensus proof covering this range but does not submit it.
3. Governance raises `cost_per_block` to `1000` via `update_cost_per_block` (a legitimate, non-malicious parameter tune).
4. The relayer now submits the consensus message. `on_executed` → `process_message` → `calculate_reward` computes `blocks = 1000`, `block_cost = 1000` (current rate), paying `1,000,000` from the treasury instead of the `10,000` that should have accrued for those blocks under the old rate.
5. `LastRewardedHeight` is advanced, permanently locking in the overpayment — see reward math at [4](#0-3) .

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}

	impl<T: Config> Pallet<T> {
		/// Update cost per block for a state machine
		#[pallet::call_index(0)]
		#[pallet::weight(T::WeightInfo::update_cost_per_block())]
		pub fn update_cost_per_block(
			origin: OriginFor<T>,
			state_machine_id: StateMachineId,
			cost_per_block: <T as pallet_ismp::Config>::Balance,
		) -> DispatchResult {
			T::IncentivesOrigin::ensure_origin(origin)?;

			StateMachinesCostPerBlock::<T>::mutate(state_machine_id.clone(), |maybe_cost| {
				*maybe_cost = Some(cost_per_block);
			});

			Self::deposit_event(Event::<T>::StateMachineCostPerBlockUpdated {
				state_machine_id,
				cost_per_block,
			});

			Ok(())
		}
