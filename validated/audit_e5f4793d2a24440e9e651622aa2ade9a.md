Audit Report

## Title
Bridge `OutgoingToken` secret is stored in plaintext and disclosed on every authenticated `GET /v2/bridge_types` / `GET /v2/bridge_types/:BridgeName` read, unlike `IncomingToken` - (File: `core/web/presenters/bridges.go`)

## Summary
The Bridge feature persists an `OutgoingToken` (the credential Chainlink presents to authenticate outbound calls to external adapters) in plaintext in the `bridges` table, and the `BridgeResource` JSON:API presenter returns it unconditionally on every `Index`/`Show` read, in contrast to `IncomingToken`, which is explicitly redacted (`omitempty`, only set at creation time). This causes a persistent secret to be disclosed to any session capable of invoking the bridge read endpoints, not just the actor who created the bridge.

## Finding Description
`BridgeType.OutgoingToken` is stored as plaintext (`db:"outgoing_token"`) with no hashing/salting, unlike the incoming token which uses `IncomingTokenHash`/`Salt`: [1](#0-0) . `BridgeResource` marks `IncomingToken` as `json:"incomingToken,omitempty"` and the constructor comment states it is "only provided when creating a Bridge," while `OutgoingToken` has plain `json:"outgoingToken"` (no omitempty) and `NewBridgeResource` always copies `b.OutgoingToken` into the resource regardless of call context: [2](#0-1) . Both `Index` and `Show` handlers in `BridgeTypesController` construct this resource straight from the DB-loaded `BridgeType` for every request, with no field-level redaction logic: [3](#0-2) . The test fixture confirms the outgoing token appears in plaintext in the JSON:API response body: [4](#0-3) .

Regarding the route-level access control gap flagged as uncertain in the original submission: examining the analogous, adjacently-registered GET routes in `core/web/router.go` shows the consistent pattern in this codebase that GET (read) endpoints on the `authv2` authenticated group are registered without any `auth.RequiresEditRole`/`RequiresAdminRole` wrapper, while only mutating verbs (POST/PUT/DELETE) are role-gated — e.g. `authv2.GET("/jobs", ...)` vs. `authv2.POST("/jobs", auth.RequiresEditRole(...))`, and `authv2.GET("/keys/"+keys.path, ...)` vs. the role-gated Create/Delete/Import/Export for the same resource: [5](#0-4) . This confirms the general design intent in this router: any authenticated session, regardless of assigned role (including the lowest `UserRoleView`), can reach GET endpoints, and only state-changing operations require elevated roles. There is no indication that bridge_types GET routes deviate from this pattern, and no role-based redaction exists in the presenter layer to compensate.

## Impact Explanation
`OutgoingToken` is a credential used to authenticate the node's outbound HTTP calls to external bridge adapters. Exposing it to any authenticated session — including lower-privileged View-role users who should only be able to observe node state, not extract adapter credentials — allows that credential to be exfiltrated and reused to impersonate the node when calling the associated external adapter. This falls under the in-scope "key/secret exfiltration" impact category: a genuine secret is disclosed via a normal, unprivileged (relative to bridge administration) authenticated read, contrary to the codebase's own established convention of write-once/redact-after-creation secret handling for `IncomingToken`.

## Likelihood Explanation
Exploitability only requires possession of any valid authenticated session against the node's core API (any role), then a single unauthenticated-relative-to-bridges `GET /v2/bridge_types` or `GET /v2/bridge_types/:BridgeName` call. No admin/edit role, no bridge ownership, and no special setup is needed beyond having a logged-in session — consistent with how every other GET endpoint in `router.go` behaves. This makes the issue readily and repeatably reproducible for any user with node API access, regardless of their assigned role tier.

## Recommendation
- Redact `OutgoingToken` from `BridgeResource` on `Index`/`Show`, mirroring the `IncomingToken` `omitempty` + create-only disclosure pattern, or mask all but a few trailing characters.
- Store `OutgoingToken` hashed/encrypted at rest analogous to `IncomingTokenHash`/`Salt`, and expose it only via a dedicated one-time reveal action gated behind `auth.RequiresEditRole`/`RequiresAdminRole`.
- If bridge secrets must remain readable for legitimate operational reasons, gate the specific fields (not just the whole route) behind an elevated role check in the controller/presenter.

## Proof of Concept
1. Authenticate as any node user with a valid session (any role, e.g., default View-level API token).
2. Send `GET /v2/bridge_types` (or `GET /v2/bridge_types/{BridgeName}` for a known bridge).
3. Observe the JSON:API response body includes the plaintext `outgoingToken` field for the bridge, as demonstrated in `core/web/presenters/bridges_test.go` (`"outgoingToken":"vjNL7X8Ea6GFJoa6PBsvK2ECzNK3b8IZ"`), reproducible via a Go test exercising `BridgeTypesController.Index`/`Show` with a low-privilege session and asserting the `outgoingToken` field is present in the response.

// Index lists Bridges, one page at a time.
func (btc *BridgeTypesController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	bridges, count, err := btc.App.BridgeORM().BridgeTypes(ctx, offset, size)

	resources := make([]presenters.BridgeResource, 0, len(bridges))
	for _, bridge := range bridges {
		resources = append(resources, *presenters.NewBridgeResource(bridge))
	}

	paginatedResponse(c, "Bridges", size, page, resources, count, err)
}

// Show returns the details of a specific Bridge.
func (btc *BridgeTypesController) Show(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	bt, err := btc.App.BridgeORM().FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}
