### Title
Missing deadline parameter in `Zap.buy` / `Zap.sell` (and permit variants) allows stale trades to be executed at a worse price - (File: `packages/contracts/src/Zap.sol`)

### Summary
`Zap.buy`, `Zap.buyWithPermit`, `Zap.sell`, and `Zap.sellWithPermit` accept only a slippage bound (`minTokensOut` / `minUsdcOut`) and no expiry/deadline parameter, so a signed-and-broadcast transaction can sit in the mempool indefinitely and later be mined against a materially different curve/LT price while still satisfying its original, now-stale slippage bound.

### Finding Description
`Zap.buy` and `Zap.sell` are the only user-facing entry points for trading on the bonding curve and post-graduation HyperSwap pool: [1](#0-0) 

Neither function (nor their `*WithPermit` counterparts) takes a `deadline` argument, and there is no timestamp/block-number check anywhere in `_buyInternal` / `_sellInternal` that would cause the call to revert once too much time has passed: [2](#0-1) [3](#0-2) 

The only economic protection is the caller-supplied `minTokensOut` / `minUsdcOut` bound, checked with `SlippageExceeded()`: [4](#0-3) [5](#0-4) 

This bound is set once, at signing time, based on the price the trader observed then. On alt.fun the relevant "price" is driven by two independently moving quantities: the bonding-curve constant-product reserves in `Router._computeBuy` / `_computeSell` (which move with every other trader's buy/sell) and the reserve asset's `exchangeRate()` from the external BounceTech LT (which can drift with leverage/funding over time, independent of any curve trade). Both are read live at execution time inside `_executeBuy` (via `Bonding.buy`/`Router.buy`) and `_sellInternal` (via `bonding_.sell` and `IBounceLeveragedToken(lt).redeem`). A `minTokensOut`/`minUsdcOut` chosen for "now" can remain technically satisfiable — just barely — after the curve and/or LT rate have moved significantly, because the bound only enforces a floor, not a bound tied to *when* the quote was taken.

Because `Zap.buy`/`Zap.sell` are plain `external` calls with standard EIP-2612 permits (`buyWithPermit`/`sellWithPermit`), a signed transaction (or a signed permit + calldata combo relayed by anyone) that a user submits with a low gas price can remain pending in the mempool for an extended period and later be included once network conditions change, executing against the then-current curve/LT state rather than the state the user intended to trade against.

### Impact Explanation
A stale, still-pending `buy`/`sell` transaction can be executed well after the user intended, against curve reserves and/or LT `exchangeRate()` that have since moved substantially. Since the only guard is the pre-signed slippage floor, the trade can still execute at a price far worse than what the user would accept if re-quoting today, causing direct economic loss to the trader — this satisfies "concrete theft ... of trader ... funds" for an unprivileged, directly reachable path (`Zap.buy`/`sell`).

### Likelihood Explanation
Likelihood is Medium: it requires either (a) a user submitting a transaction with too-low gas that later gets included as fees drop, or (b) a permit signature/relay pattern where the calldata is held and replayed later — both are realistic real-world occurrences rather than contrived attacker setups, and neither requires any privileged role, matching the reachable paths already scoped for `Zap.buy`/`sell`.

### Recommendation
Add a `deadline` parameter to `Zap.buy`, `Zap.sell`, `Zap.buyWithPermit`, and `Zap.sellWithPermit`, and revert (e.g., `TransactionExpired()`) in `_buyInternal`/`_sellInternal` if `block.timestamp > deadline`, mirroring the existing `PermitData.deadline` freshness check already used for permits.

### Proof of Concept
1. Alice calls `Zap.buy(token, usdcAmount, minTokensOut, referrer)` with `minTokensOut` computed from the current curve quote (`Router.getAmountOut`) and the LT's current `exchangeRate()`, using a low gas price.
2. The transaction sits unmined in the mempool for an extended period while the curve reserves shift from other trades and/or the LT's `exchangeRate()` drifts.
3. Once gas prices fall or the transaction is otherwise picked up, it executes: `_executeBuy` reads the now-different `Router._computeBuy` output and mints against the now-different LT rate.
4. Because `tokensOut >= minTokensOut` still technically holds (the bound was set loosely enough at signing time, or the move happened to stay just above the floor), the trade executes — [6](#0-5)  — at a price Alice never would have accepted had she re-quoted immediately before execution, with no deadline check available to abort the stale trade.

    function _buyInternal(
        address tokenAddress,
        uint256 usdcAmount,
        uint256 minTokensOut,
        address referrer
    ) internal returns (uint256 tokensOut) {
        if (usdcAmount == 0) revert InvalidInput();
        if (tokenAddress == address(0)) revert InvalidInput();
        if (usdcAmount < minUsdcAmount()) revert BelowMinAmount();
        Bonding bonding_ = _s().bonding;
        if (bonding_.creatorOf(tokenAddress) == address(0)) revert TokenNotTrading();
        if (bonding_.isGraduating(tokenAddress)) revert TokenIsGraduating();

        uint256 grossSpent;
        uint256 actualFee;
        (tokensOut, grossSpent, actualFee) = _executeBuy(tokenAddress, usdcAmount);

        if (tokensOut < minTokensOut) revert SlippageExceeded();

        if (actualFee > 0) {
            _accrueFee(tokenAddress, bonding_.creatorOf(tokenAddress), actualFee, true);
        }

        // Report the USDC actually spent, not the submitted `usdcAmount`. A
        // graduation-capped buy refunds the unused principal and fee, so the
        // two diverge there; for every other buy they're equal.
        emit Buy(tokenAddress, msg.sender, grossSpent, tokensOut);

        if (referrer != address(0) && referrer != msg.sender) {
            emit Referred(tokenAddress, msg.sender, referrer, grossSpent);
        }
    }

    function _sellInternal(
        address tokenAddress,
        uint256 tokenAmount,
        uint256 minUsdcOut
    ) internal returns (uint256 usdcOut) {
        if (tokenAmount == 0) revert InvalidInput();
        if (tokenAddress == address(0)) revert InvalidInput();
        ZapStorage storage $ = _s();
        Bonding bonding_ = $.bonding;
        if (bonding_.creatorOf(tokenAddress) == address(0)) revert TokenNotTrading();
        if (bonding_.isGraduating(tokenAddress)) revert TokenIsGraduating();

        // LT appreciation can push a curve token past the graduation threshold
        // with no buy. Selling now would drag the raised reserve back below it,
        // so graduate the token instead. The holder keeps their tokens and
        // exits on the graduated pool. Nothing is sold, so this fills `0` — only
        // take it when the caller set no floor; a positive `minUsdcOut` reverts
        // so the `usdcOut >= minUsdcOut` guarantee is never silently broken.
        if (bonding_.canGraduate(tokenAddress)) {
            if (minUsdcOut != 0) revert TokenIsGraduating();
            bonding_.triggerGraduation(tokenAddress);
            return 0;
        }

        address lt = bonding_.ltOf(tokenAddress);

        IERC20(tokenAddress).safeTransferFrom(msg.sender, address(this), tokenAmount);

        uint256 ltReceived = bonding_.isGraduated(tokenAddress)
            ? _sellOnUniswapV2(tokenAddress, lt, tokenAmount)
            : _sellOnCurve(tokenAddress, tokenAmount);

        uint256 grossUsdcEstimate = (ltReceived * IBounceLeveragedToken(lt).exchangeRate()) / 1e18;
        if (grossUsdcEstimate / 1e12 < minUsdcAmount()) revert BelowMinAmount();

        // Intentional v1 tradeoff: sells only use BounceTech's atomic
        // `redeem()` path (no `prepareRedeem` fallback/queue in Zap). If the
        // LT idle-USDC buffer is temporarily depleted, `redeem` reverts and
        // users must retry in smaller chunks after buffer replenishment.
        // Redeem into this zap (not the user) so we can deduct the fee.
        uint256 grossUsdc = IBounceLeveragedToken(lt).redeem(address(this), ltReceived, 0);

        // Symmetric with `_executeBuy`: fee charged on EVERY sell — curve
        // AND post-graduation. The `isGraduated` branch above selects the
        // venue, not the fee policy. See `_executeBuy` for the rationale.
        uint256 fee = Math.mulDiv(grossUsdc, $.sellFeeBps, BPS_DENOM, Math.Rounding.Ceil);
        usdcOut = grossUsdc - fee;

        if (usdcOut < minUsdcOut) revert SlippageExceeded();

        $.usdc.safeTransfer(msg.sender, usdcOut);

        if (fee > 0) {
            _accrueFee(tokenAddress, bonding_.creatorOf(tokenAddress), fee, false);
        }

        emit Sell(tokenAddress, msg.sender, tokenAmount, usdcOut);
    }
