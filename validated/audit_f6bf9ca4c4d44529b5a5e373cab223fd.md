## Title
Postdispatch dust-sweep in `_execute` grabs the shared `CallDispatcher`'s entire balance instead of only funds generated by the current order, allowing theft of unrelated funds resting on the dispatcher - (File: `evm/src/apps/intentsv2/IntentsBase.sol`)

### Summary
`IntentsBase._execute()`, invoked from the permissionless `fillOrder()` path whenever an order carries postdispatch calldata, sweeps the *entire current token/native balance* of the shared, stateless `CallDispatcher` contract back into the gateway as "dust" for the currently-filling order — exactly the same root-cause pattern as the referenced `GaugeCL._claimFees()` bug, which swept a contract's whole balance instead of the delta produced by the specific action being accounted for.

### Finding Description
`_execute()` dispatches the order's `output.call` through the shared `CallDispatcher`, then treats whatever tokens/ETH are left on the dispatcher afterwards as "residual dust" belonging to *this* order and sweeps 100% of it back to the gateway: [1](#0-0) 

Critically, unlike the *predispatch* flow in `placeOrder()` — which explicitly snapshots the dispatcher's/gateway's balances **before** the dispatched call and only sweeps the **delta** (`balancesBefore` / `received = after - before`) — `_execute()` performs no such snapshot around `order.output.call`: [2](#0-1) 

`CallDispatcher` is not an ephemeral, per-order contract; it is a single shared, stateless, permanently deployed contract (its address is stored once in `_params.dispatcher` and referenced/documented as the fixed `CallDispatcher` address used by `IntentGatewayV2` and also `HyperFungibleToken`/`WrappedHyperFungibleToken` for calldata execution — tokens are minted/unlocked directly to it so subsequent calls can spend them): [3](#0-2) 

Because `dispatch()` executes arbitrary calls "in its own context" and holds tokens/ETH only "temporarily," any token or ETH sitting on this shared dispatcher for *any* reason (e.g., an in-flight `HyperFungibleToken`/`WrappedHyperFungibleToken` transfer-and-swap that mints to the dispatcher before its own calls run, a partially-swept predispatch flow, slippage residue from a swap that doesn't send 100% of proceeds where expected, or even a direct token donation by anyone, since `CallDispatcher` has a permissionless `receive()` and no owner) is indistinguishable, from `_execute`'s point of view, from funds produced by the *current* order's postdispatch call. `_execute` will sweep the dispatcher's *whole* balance of every token listed in `order.output.assets` into the gateway and label it `DustCollected`, exactly as `GaugeCL._claimFees()` swept the gauge's whole balance and mislabeled unrelated staking rewards as trading fees.

### Impact Explanation
Any unrelated funds resting on the shared `CallDispatcher` (from another user's concurrent/adjacent HFT calldata delivery, an incompletely-swept predispatch leg of a different order, or funds simply sent there by any third party) can be permanently redirected into the current order's dust accounting and captured by the protocol/gateway rather than returned to their rightful owner, whenever a solver fills an order whose `output.assets` happen to include that token. This is a direct loss-of-funds vector reachable from a single permissionless `fillOrder()` transaction with attacker-chosen `output.call`/`output.assets`, mirroring the "steals staking rewards" impact of the original report (funds meant for one purpose/owner are swept and captured under a different accounting bucket).

### Likelihood Explanation
`fillOrder()` (and thus `_execute()`) is fully permissionless and callable by any solver, and `CallDispatcher` is a shared, address-fixed, stateless contract intentionally reused across `IntentGatewayV2` and the `HyperFungibleToken`/`WrappedHyperFungibleToken` calldata-execution paths, and it accepts arbitrary ERC20 transfers/ETH from anyone with no access control. An attacker only needs to (a) observe or induce a moment where the dispatcher briefly holds tokens of a type also used in someone's postdispatch `output.assets`, or (b) directly donate/park tokens on the dispatcher and then trigger/wait for a `fillOrder` with matching `output.assets`, to have those funds swept as dust. The `placeOrder` predispatch code path was already hardened with explicit before/after balance snapshots (comment: "Build sweep calls and snapshot gateway balances before the sweep"), which strongly suggests the team is aware of this exact bug class but has not applied the equivalent fix to `_execute`'s postdispatch sweep.

### Recommendation
Apply the same before/after delta-tracking pattern used in `placeOrder`'s predispatch sweep to `_execute()`: snapshot `dispatcher.balance` and `IERC20(token).balanceOf(dispatcher)` for each `output.assets[i].token` *immediately before* calling `ICallDispatcher(dispatcher).dispatch(order.output.call)`, and only sweep/emit `DustCollected` for the positive delta produced by that specific call, never the dispatcher's raw absolute balance. Consider additionally isolating dispatcher usage per-call (e.g., ephemeral minimal-proxy dispatcher instances) so unrelated flows can never share dispatcher balance state.

### Proof of Concept
Conceptual PoC (Foundry-style), analogous to the referenced report's PoC:
1. Deploy `IntentGatewayV2` with the shared `CallDispatcher` and a token `T` also used elsewhere (e.g., by a `HyperFungibleToken` calldata-execution flow that mints `T` to `CallDispatcher`).
2. Simulate residual funds on the dispatcher: `T.transfer(address(callDispatcher), 10e18)` (representing tokens left mid-flight from an unrelated HFT transfer-and-swap, or simply an attacker donation — `CallDispatcher.receive()`/ERC20 transfers have no access control).
3. Place and have a solver fill an ordinary order whose `output.call` is non-empty and whose `output.assets` includes token `T` with a small legitimate postdispatch swap amount, e.g., 0.1 `T`.
4. Call `fillOrder()`. Inside `_execute()`, after `dispatch(order.output.call)`, `IERC20(T).balanceOf(dispatcher)` now reads `10.1e18` (10e18 residual + 0.1e18 from this order's own call).
5. `_execute` sweeps the full `10.1e18` to the gateway as `DustCollected`, permanently capturing the 10e18 that belonged to the unrelated flow/owner — the same "entire-balance-swept-as-fees" pattern as `GaugeCL._claimFees()`. [1](#0-0)

    function _execute(Order calldata order, uint256 outputsLen) internal {
        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});

                ++i;
            }

contract CallDispatcher is ICallDispatcher {
    /**
     * @dev error thrown when the target is not a contract.
     */
    error NotContract(address target);

    /**
     * @dev error thrown when a call fails.
     */
    error CallFailed(address target, bytes result);

    /**
     * @dev Receive function to accept ETH transfers
     */
    receive() external payable {}

    /**
     *  @dev reverts if the target is not a contract or if any of the calls reverts.
     */
    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
