Audit Report

## Title
Bridge Adapter `OutgoingToken` disclosed to unprivileged Viewer role - (File: core/web/presenters/bridges.go)

## Summary
The `BridgeResource` presenter marshals the bridge's `OutgoingToken` field on every response without an `omitempty` guard or role-based redaction, unlike the sibling `IncomingToken` field which is explicitly restricted to bridge-creation responses. Both `GET /v2/bridge_types` (Index) and `GET /v2/bridge_types/:BridgeName` (Show) are wired without any `auth.RequiresEditRole`/`auth.RequiresAdminRole` wrapper, so any authenticated user — including one holding only the least-privileged `view` role — can retrieve this token.

## Finding Description
`BridgeResource` declares `OutgoingToken string \`json:"outgoingToken"\`` with no `omitempty`, while `IncomingToken` is explicitly commented "only provided when creating a Bridge" and marked `omitempty`: [1](#0-0) 

`NewBridgeResource` populates `OutgoingToken` directly from the stored `bridges.BridgeType.OutgoingToken` on every construction, used by both `Index` and `Show`: [2](#0-1) [3](#0-2) 

The routes are registered without a role-restricting wrapper, in contrast to `Create`/`Update`/`Destroy` which use `auth.RequiresEditRole`: [4](#0-3) 

This is corroborated by the project's own RBAC route test matrix, which explicitly sets `viewOnlyAllowed=true` for both `GET /v2/bridge_types` and `GET /v2/bridge_types/:BridgeName`, and the `TestRBAC_Routemap_ViewOnly` test that asserts a `view`-role user gets neither `401` nor `403` on these routes: [5](#0-4) [6](#0-5) 

`OutgoingToken` is generated alongside `IncomingToken` at bridge-creation time via `utils.NewSecret(24)` and persisted in the `bridges.BridgeType` model, confirming it is treated as a credential-class value at creation time, structurally identical to `IncomingToken`: [7](#0-6) 

Note: I could not find any code path in `core/services/pipeline/task.bridge.go` (the bridge task runner that performs outbound HTTP calls to the external adapter) that actually reads or sends `OutgoingToken` as an `Authorization` header or similar credential during bridge invocation — the outbound request only uses caller-supplied `Headers` param, not `OutgoingToken`: [8](#0-7) 
This means the field's current runtime security purpose (if any) is unclear from the code reachable in this index; it may be a legacy/vestigial credential field. This uncertainty does not change the fact that the field is treated as a secret at generation time (same `NewSecret(24)` origin and un-hashed storage as `IncomingToken`), and is disclosed without protection to `view`-role users, breaking the least-privilege intent evidenced by `IncomingToken`'s explicit `omitempty` restriction.

## Impact Explanation
`OutgoingToken` is generated as a 24-byte secret alongside `IncomingToken` and stored in plaintext in the `bridges` table, indicating a credential class field. Regardless of whether current EA integrations consume it as a bearer/auth token, the code's own IncomingToken pattern demonstrates an established design intent that bridge secrets should not be freely re-exposed on GET reads — this intent was not applied consistently to `OutgoingToken`. This maps to an information-disclosure (CWE-200) finding: a `view`-role user, who is meant to have read-only observability of node state, can retrieve a bridge secret intended for privileged (edit/admin) integration configuration.

## Likelihood Explanation
Likelihood is high in any deployment granting `view`-role API access to less-trusted operators — a supported configuration per the RBAC model (`admin`/`edit`/`run`/`view`). No special conditions beyond a valid `view`-role session/API token and a simple `GET /v2/bridge_types` or `GET /v2/bridge_types/:BridgeName` request are required; both routes are confirmed reachable by `view` role in the project's own test suite.

## Recommendation
Apply the same protection used for `IncomingToken`: mark `OutgoingToken` as `omitempty` and only populate it in the `Create` response, or restrict the `Index`/`Show` routes with `auth.RequiresEditRole` (or strip the field for `view`/`run` roles) so the token is only ever returned to privileged callers.

## Proof of Concept
1. As an admin, create a bridge: `POST /v2/bridge_types` with `{"name":"test","url":"http://adapter.local"}` → response includes `outgoingToken`.
2. Create a session/API token for a user with `Role: view`.
3. As that `view` user, call `GET /v2/bridge_types/test` (or `GET /v2/bridge_types`).
4. Observe the response JSON contains the same `outgoingToken` value returned at creation, confirming disclosure to a Viewer-role account — matching `TestRBAC_Routemap_ViewOnly` behavior for the `GET /v2/bridge_types` and `GET /v2/bridge_types/:BridgeName` routes.

func (btc *BridgeTypesController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	bridges, count, err := btc.App.BridgeORM().BridgeTypes(ctx, offset, size)

	resources := make([]presenters.BridgeResource, 0, len(bridges))

// Show returns the details of a specific Bridge.
func (btc *BridgeTypesController) Show(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	bt, err := btc.App.BridgeORM().FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}

	inputValues, err := CheckInputs(inputs, -1, -1, 0)
	if err != nil {
		return Result{Error: errors.Wrap(err, "task inputs")}, runInfo
	}

	var (
		name              StringParam
		requestData       MapParam
		includeInputAtKey StringParam
		cacheTTL          Uint64Param
		reqHeaders        StringSliceParam
		checkRequired     BoolParam
	)
	err = stderrors.Join(
		errors.Wrap(ResolveParam(&name, From(NonemptyString(t.Name))), "name"),
		errors.Wrap(ResolveParam(&requestData, From(VarExpr(t.RequestData, vars), JSONWithVarExprs(t.RequestData, vars, false), nil)), "requestData"),
		errors.Wrap(ResolveParam(&includeInputAtKey, From(t.IncludeInputAtKey)), "includeInputAtKey"),
		errors.Wrap(ResolveParam(&cacheTTL, From(ValidDurationInSeconds(t.CacheTTL), t.bridgeConfig.BridgeCacheTTL().Seconds())), "cacheTTL"),
		errors.Wrap(ResolveParam(&reqHeaders, From(NonemptyString(t.Headers), "[]")), "reqHeaders"),
		errors.Wrap(ResolveParam(&checkRequired, From(NonemptyString(t.CheckRequired), false)), "checkRequired"),
	)
	if err != nil {
		return Result{Error: err}, runInfo
	}

	if len(reqHeaders)%2 != 0 {
		return Result{Error: errors.Errorf("headers must have an even number of elements")}, runInfo
	}

	overtimeCtx, cancel := overtimeContext(ctx)
	defer cancel()

	bridge, err := t.getBridgeFromName(overtimeCtx, name)
	if err != nil {
		return Result{Error: err}, runInfo
	}
	url := URLParam(bridge.URL)
	lookupPayload := make(MapParam)
	maps.Copy(lookupPayload, requestData)

	requestCtx, cancel := httpRequestCtx(ctx, t, t.config)
	defer cancel()
	if bridge.UseConnectionManager {
		bridgeConnManager := t.bridgeConnManager
		start := time.Now()
		responseBytes, obsErr := bridgeConnManager.GetObservation(bridge, map[string]any(lookupPayload))
		finish := time.Now()

		statusCode := http.StatusOK
		if obsErr != nil {
			statusCode = http.StatusGatewayTimeout
		}

		elapsed := finish.Sub(start)
		promBridgeLatency.WithLabelValues(t.Name, statusCodeGroup(statusCode)).Set(elapsed.Seconds())

		if telemetryCh := GetTelemetryCh(ctx); telemetryCh != nil {
			requestDataJSON, jsonErr := json.Marshal(lookupPayload)

			}
			bt := &BridgeTelemetry{
				Name:                   t.Name,
				RequestData:            requestDataJSON,
				ResponseData:           responseBytes,
				ResponseStatusCode:     statusCode,
				RequestStartTimestamp:  start,
				RequestFinishTimestamp: finish,
				SpecID:                 t.specID,
				DotID:                  t.DotID(),

			if obsErr != nil {

				*bt.ResponseError = obsErr.Error()
			}

			bt.resolveStreamID(t, vars, lggr)

			select {
			case telemetryCh <- bt:
			default:
				lggr.Warn("bridge task: telemetry channel is full, dropping telemetry")
			}
		}

		if obsErr != nil {
			lggr.Debugw("Bridge task: connection manager request failed",
				"response", string(responseBytes),
				"url", url.String(),
				"error", obsErr,

		"requestData", string(requestDataJSON),
		"url", url.String(),
	)
