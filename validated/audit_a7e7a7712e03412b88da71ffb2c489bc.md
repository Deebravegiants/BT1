Audit Report

## Title
CORS origin bypass via unanchored suffix matching in wildcard host comparison - (File: `core/services/gateway/network/httpserver.go`)

## Summary
The Gateway user-facing HTTP server's `isAllowedOrigin` function validates wildcard CORS allowlist entries (e.g. `https://*.remix.com`) using an unanchored `strings.HasSuffix(originHost, allowedHost)` check, with no verification that the match occurs at a domain-label (dot) boundary. This lets an attacker-controlled origin such as `https://evilremix.com` satisfy an allowlist entry meant only for subdomains of `remix.com`.

## Finding Description
In `isAllowedOrigin`, when an allowlist entry's host starts with `*.`, the code strips the prefix and does a raw suffix comparison against the request's `Origin` host: `strings.HasSuffix(originHost, allowedHost)`. [1](#0-0)  This has no boundary check requiring that the character preceding the matched suffix in `originHost` be a literal `.`. So for an allowlist entry `https://*.remix.com` (`allowedHost = "remix.com"`), an origin host `evilremix.com` incorrectly matches because it merely ends with `remix.com`, despite not being a subdomain.

This function is invoked directly on the unauthenticated request path in `handleRequest`, which reads the client-supplied `Origin` header, checks it via `isAllowedOrigin`, and if allowed, echoes it back verbatim in `Access-Control-Allow-Origin`. [2](#0-1)  No other authentication, role, or scheme/port checks (which are present, but insufficient) prevent this bypass, since scheme and port checks pass independently of hostname suffix correctness. [3](#0-2) 

Existing tests only exercise true subdomains (`remix.ethereum.org` matching `*.ethereum.org`) and unrelated domains, never the "different domain sharing a suffix" case, so the bug is untested and unnoticed. [4](#0-3) 

## Impact Explanation
This is a CORS allowlist bypass (in-scope impact category). An attacker who registers a domain ending in the same characters as an operator's wildcard-allowlisted domain (e.g. `evilremix.com` vs. `*.remix.com`) can obtain `Access-Control-Allow-Origin` matching their own origin, allowing attacker-hosted JavaScript to read cross-origin Gateway responses from victims' browsers — a genuine CORS boundary violation and cross-user response exposure risk, not merely theoretical.

## Likelihood Explanation
Exploitable by any unauthenticated client that can set an arbitrary `Origin` header — no credentials, roles, or special network position required. The only precondition is that the Gateway operator has configured `CORSEnabled=true` with at least one wildcard entry (`https://*.<domain>`), which is a documented, supported configuration option exercised in the codebase's own test suite and sample configs.

## Recommendation
Enforce a domain-label boundary in the wildcard match, e.g.:
```go
if strings.HasPrefix(allowedHost, "*.") {
    allowedHost = allowedHost[2:]
    if originHost == allowedHost || strings.HasSuffix(originHost, "."+allowedHost) {
        return true
    }
}
```

## Proof of Concept
1. Start the Gateway HTTP server with `CORSEnabled=true` and `CORSAllowedOrigins=["https://*.remix.com"]`.
2. Send a POST request to the Gateway's configured path with header `Origin: https://evilremix.com`.
3. Observe the response includes `Access-Control-Allow-Origin: https://evilremix.com`, confirming `isAllowedOrigin` incorrectly returned `true` for a non-subdomain sharing only a string suffix — this can be codified as a Go unit test analogous to `TestHTTPServer_HandleRequest_CORSEnabled_FromAllowedOriginWildcards` in `core/services/gateway/network/httpserver_test.go`, asserting `evilremix.com` is rejected (it currently is not).

func (s *httpServer) handleRequest(w http.ResponseWriter, r *http.Request) {
	if s.config.CORSEnabled {
		origin := r.Header.Get("Origin")
		if s.isAllowedOrigin(origin) {
			w.Header().Set("Access-Control-Allow-Origin", origin)
			w.Header().Set("Access-Control-Allow-Methods", "GET, POST, OPTIONS")
			w.Header().Set("Access-Control-Allow-Headers", "Content-Type")
		}

		// handle preflight requests
		if r.Method == http.MethodOptions {
			w.WriteHeader(http.StatusNoContent)
			return
		}
	}
