## Title
Free unsigned `handle_unsigned` extrinsic fully executes attacker-supplied, unbounded `Vec<Message>` batches during mempool `validate_unsigned`, enabling unauthenticated memory/CPU exhaustion across every validating node - (File: modules/pallets/ismp/src/lib.rs)

### Summary
`pallet_ismp::Pallet::handle_unsigned` is a fee-less extrinsic callable by anyone with `OriginFor::None`, and its `ValidateUnsigned::validate_unsigned` implementation does not perform lightweight, bounded pre-checks before doing real work — it calls `Self::execute(messages.clone())`, which is the *same* full message-processing path used for actual block inclusion (membership-proof verification, storage-proof/trie decoding, `BTreeMap`/`Vec` construction proportional to attacker-supplied `keys`/`requests` counts). Because `validate_unsigned` runs on every peer's transaction pool as soon as the extrinsic is gossiped — not just on the node that eventually includes it in a block — a single unsigned submission with a maximally-sized `messages: Vec<Message>` (bounded only by the chain's generic max-extrinsic-length limit, not by any ISMP-specific cap) forces full proof verification and allocation work on every node in the network, repeatedly, for free.

### Finding Description
`handle_unsigned` is explicitly documented as "an unsigned extrinsic that permits anyone execute ISMP messages for free" [1](#0-0) . Its `ValidateUnsigned` implementation is deliberately "empty pre-dispatch" (no storage-modifying pre-check) but the `validate_unsigned` function itself unconditionally calls `Self::execute(messages.clone())` before returning a `ValidTransaction`: [2](#0-1) 

`execute` dispatches into `handlers::handle_incoming_message`, which for a `Request`/`Response` message performs full membership/state-proof verification over every entry in the caller-supplied batch: [3](#0-2) 

For a `Response` (GetResponse) message, each `GetRequest.keys: Vec<Vec<u8>>` is fed into `state_machine.verify_state_proof`, which for EVM/Substrate-EVM/Tendermint state machines decodes an attacker-supplied proof blob and rebuilds tries / constructs `BTreeMap`s sized by the number of keys the caller chose to include: [4](#0-3) [5](#0-4) 

Unlike the sibling `call-decompressor` pallet, which explicitly caps the *unsigned* `validate_unsigned` path with `ensure!(encoded_call_size < T::MaxCallSize::get() * ONE_MB, ...)` specifically because "the unsigned `validate_unsigned` mempool path called `decompress` directly with no bound, so a fee-less attacker could ... have a tiny zstd bomb expanded to gigabytes during transaction-pool validation" [6](#0-5) , `pallet_ismp::handle_unsigned`'s `messages: Vec<Message>` and the nested `GetRequest.keys: Vec<Vec<u8>>` / `RequestMessage.requests: Vec<PostRequest>` have no ISMP-specific size bound; only the runtime's generic max-extrinsic-length setting constrains the wire size, and there is no per-message, per-batch, or per-key count limit enforced anywhere in `handlers::request::handle` or `handlers::response::handle` before the expensive verification work runs. `GetRequest.keys` is an unbounded `Vec<Vec<u8>>` by design [7](#0-6) .

This mirrors the RaptorCast bug class: an attacker-controlled size field (`app_message_len` there; batch/`keys` length here) drives per-message memory/CPU allocation, and the entry point performing that work is reachable without the normal cost gate (fees there being bypassed via incomplete decoding; here, fees being explicitly waived by the unsigned/free design) — except here the "attacker" doesn't even need validator/staked status, only network access to gossip a transaction, which is a materially lower barrier than RaptorCast's "must be an active validator with signature authority" precondition.

### Impact Explanation
Because Substrate's transaction pool calls `validate_unsigned` on *every* node that receives the gossiped extrinsic (light and full nodes, not just the eventual block author), a single crafted submission causes full proof-verification work (trie rebuilding, `BTreeMap` construction, decoding of attacker-supplied proof bytes) to execute network-wide, for free, and can be resubmitted repeatedly with trivial variations to defeat the `provides`-tag dedup logic. Effects: sustained CPU/memory consumption on validator and RPC nodes, degraded block production and consensus participation, and potential node crashes/OOM under sustained flooding. Impact scope is a network-wide route-availability degradation ("route unable to deliver messages"), which is one of the accepted impact categories.

### Likelihood Explanation
High. The endpoint is a first-class, documented public extrinsic with `ensure_none(origin)` (no signature, no fee, no stake requirement) [8](#0-7) . No special privilege, validator status, or governance action is required — any party capable of submitting a transaction to the network can trigger this, and the cost asymmetry (near-zero cost to submit vs. full proof-verification cost imposed on every peer) makes repeated exploitation trivial. The comparable, already-acknowledged bug in `call-decompressor` (fixed with an explicit bound) demonstrates the project itself has previously recognized this exact class of "expensive work in unsigned mempool validation" as a real vulnerability.

### Recommendation
1. Enforce hard, ISMP-specific bounds on `Vec<Message>` batch size, `RequestMessage.requests`/`ResponseMessage.requests` counts, and `GetRequest.keys` length before any proof-verification work is attempted in `validate_unsigned` — analogous to `call-decompressor`'s `MaxCallSize` gate.
2. In `validate_unsigned`, perform only cheap, bounded structural/format checks (sizes, counts, obvious well-formedness) and defer full cryptographic/trie verification to `pre_dispatch`/`execute` at actual block-inclusion time, or make `pre_dispatch` reuse verification results rather than recomputing, so unauthenticated gossip cannot force full verification network-wide.
3. Add per-source-account/per-IP rate limiting or a lightweight proof-of-work/priority mechanism at the transaction-pool layer for unsigned ISMP submissions.
4. Add monitoring/alerting on abnormal `handle_unsigned` submission volume or size.

### Proof of Concept
1. Construct a single `pallet_ismp::Call::handle_unsigned { messages }` where `messages` contains one `Message::Response(ResponseMessage::Get(GetResponseMessage { requests: [...], proof, signer }))`.
2. Set `requests` to the maximum number of `GetRequest` entries that fit under the runtime's max-extrinsic-length limit, each with a large `keys: Vec<Vec<u8>>` (e.g., thousands of 52-byte EVM storage keys) and an attached `proof.proof` sized to match (a large but structurally valid — or even invalid-but-decodable — EVM/Substrate-EVM state proof blob).
3. Submit this unsigned extrinsic via RPC (`author_submitExtrinsic`) or gossip it as a peer to the network.
4. Every node's transaction pool independently calls `ValidateUnsigned::validate_unsigned`, which calls `Self::execute(messages.clone())` → `handlers::response::handle` → `state_machine.verify_state_proof(..., keys, ...)`, forcing each node to decode the proof and iterate/allocate over every key [4](#0-3) [5](#0-4) .
5. Repeat with minor content variations (e.g., differing `signer`/timestamps) to bypass the `provides`-tag pool-dedup logic and sustain the load indefinitely, at zero cost to the attacker since the call is fee-less by design.

	host: &H,
	message: Message,
) -> Result<MessageResult, anyhow::Error>

	H: IsmpHost,
{
	match message {
		Message::Consensus(consensus_message) => consensus::update_client(host, consensus_message),
		Message::FraudProof(fraud_proof) => consensus::freeze_client(host, fraud_proof),
		Message::Request(req) => request::handle(host, req),
		Message::Response(resp) => response::handle(host, resp),
		Message::Timeout(timeout) => timeout::handle(host, timeout),
	}
}

	fn verify_state_proof(
		&self,
		_host: &dyn IsmpHost,
		keys: Vec<Vec<u8>>,
		root: H256,
		proof: &Proof,
	) -> Result<BTreeMap<Vec<u8>, Option<Vec<u8>>>, Error> {
		let ismp_host_address = EvmHosts::<T>::get(&proof.height.id.state_id)
			.ok_or(SubstrateEvmError::IsmpContractNotFound)?;

		let proof: SubstrateEvmProof =
			Decode::decode(&mut &proof.proof[..]).map_err(SubstrateEvmError::ProofDecodeError)?;

		let state_root = root;

		let keys_len = keys.len();
		let mut contract_keys: BTreeMap<H160, Vec<Vec<u8>>> = BTreeMap::new();
		for key in keys {
			let address = if key.len() == 52 {
				H160::from_slice(&key[..20])
			} else if key.len() == 32 {
				ismp_host_address
			} else {
				return Err(SubstrateEvmError::InvalidKeyLength(key.len()).into());
			};
			contract_keys.entry(address).or_default().push(key);
		}

		let mut result_map = BTreeMap::new();

		for (address, keys) in contract_keys {
			let contract_info_key = contract_info_key(address);
			let trie_id = fetch_trie_id_from_main_proof::<H>(
				&proof.main_proof,
				state_root,
				&contract_info_key,
			)?;

			let child_root =
				fetch_child_root_from_main_proof::<H>(&proof.main_proof, state_root, &trie_id)?;

			let storage_proof = proof
				.storage_proof
				.get(address.as_bytes())
				.ok_or(SubstrateEvmError::StorageProofMissing(address.as_bytes().to_vec()))?;

			let storage_keys: Vec<Vec<u8>> = keys
				.iter()
				.map(|k| {
					let slot = if k.len() == 52 { &k[20..] } else { &k[..] };
					blake2_256(slot).to_vec()
				})
				.collect();

			let values = verify_child_trie_values::<H>(child_root, storage_proof, storage_keys)?;

			for (key, value) in keys.into_iter().zip(values.into_iter()) {
				result_map.insert(key, value);
			}
		}

		if result_map.len() != keys_len {
			return Err(SubstrateEvmError::MismatchedValuesAndKeys.into());
		}

		Ok(result_map)
	}
