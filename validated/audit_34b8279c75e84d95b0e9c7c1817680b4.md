### Title
`detect_fraud` unconditionally returns `Ok(false)`, permanently bypassing on-orb fraud detection and forcing `SignupReason::Normal`/`Fraud` gating to be dead code - ([File: src/plans/mod.rs])

### Summary
`MasterPlan::detect_fraud` in `src/plans/mod.rs` no longer consults any `fraud-engine::Rule`/`Pipeline` data and unconditionally returns `Ok(false)`, so `fraud_detected` in `do_signup` is always `false` regardless of the actual `biometric_pipeline::Pipeline` output. This means any signup that produces a `Some(pipeline)` (i.e., the biometric pipeline itself didn't hard-error) will always be tagged `SignupReason::Normal`, never `SignupReason::Fraud`, even if the pipeline's fraud-relevant fields (e.g. `face_identifier_fraud_checks`, occlusion errors) indicate a spoof or anomaly.

### Finding Description
In `src/plans/mod.rs`:
```
async fn detect_fraud(&mut self, orb, _debug_report, pipeline: Option<&biometric_pipeline::Pipeline>) -> Result<bool> {
    orb.set_phase("Fraud detection").await;
    let Some(_pipeline) = pipeline else {
        return Ok(false);
    };
    // FOSS: WE HAVE DELETED ALL FRAUD CHECKS
    Ok(false)
}
``` [1](#0-0) 

The caller `do_signup` computes:
```
let pipeline = Box::pin(self.biometric_pipeline(orb, debug_report, &capture)).await?;
let fraud_detected = !self.skip_fraud_checks()
    && self.detect_fraud(orb, debug_report, pipeline.as_ref()).await?;
let signup_reason = if pipeline.is_none() {
    SignupReason::Failure
} else if fraud_detected {
    SignupReason::Fraud
} else {
    SignupReason::Normal
};
``` [2](#0-1) 

Because `detect_fraud` ignores `_pipeline` entirely and always returns `Ok(false)`, `fraud_detected` can never be `true` through this path, irrespective of `self.skip_fraud_checks()`'s value. Consequently `signup_reason` can only ever be `SignupReason::Failure` (pipeline `None`) or `SignupReason::Normal` — the `SignupReason::Fraud` branch defined in `src/backend/signup_post.rs` (`SignupReason::Fraud` / `debug_report.signup_fraud()` in `report_signup_reason`) is unreachable dead code on the orb side. [3](#0-2) [4](#0-3) 

The `fraud-engine/src/dsl.rs` `Rule` type/`evaluate` function, which is designed to evaluate arithmetic/boolean expressions against serialized pipeline data to flag fraud, exists but is never invoked from this call site — it is orphaned logic. [5](#0-4) 

This matches a genuine fail-open condition: the code comment itself ("FOSS: WE HAVE DELETED ALL FRAUD CHECKS") confirms the checks were removed rather than merely misconfigured, and no other gate in `do_signup` re-derives a fraud verdict from `pipeline`'s fraud-relevant fields (e.g. `face_identifier_fraud_checks`) before enrollment.

### Impact Explanation
Any attacker who can get the biometric pipeline to succeed (`Some(pipeline)`), regardless of what fraud-relevant signals are embedded in that pipeline output, is guaranteed `signup_reason != Fraud` on the orb side. This is a liveness/fraud-detection bypass at the orb level: all on-orb single-signup and cross-signup fraud heuristics that were meant to gate `SignupReason::Fraud` (and thus block `enroll_user`) are inert. The practical effect is that `enroll_user`/`build_pcp` proceed with `SignupReason::Normal` for any pipeline that would previously have been flagged, undermining the fail-closed design intent implied by the `SignupReason::Fraud` variant and `report_signup_reason`/`debug_report.signup_fraud()` handling.

### Likelihood Explanation
No special preconditions beyond reaching the biometric pipeline stage of an attacker's own signup session (as scoped) — this is code that runs unconditionally on every non-skipped signup (`!self.skip_fraud_checks()` still evaluates true by default in most configs, but even then the inner call is a no-op). It is fully deterministic and 100% reproducible.

### Recommendation
Restore invocation of the fraud-engine `Rule::evaluate` against the actual `pipeline` data inside `detect_fraud` (or otherwise re-implement equivalent checks), and make the function fail closed on missing/errored signals (e.g., treat pipeline-absent or rule-evaluation-error cases as `Ok(true)`/fraud rather than `Ok(false)`), instead of unconditionally returning `Ok(false)`.
