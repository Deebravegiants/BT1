### Title
Crafted swap route injects an attacker-chosen contract call under the caller's auth tree, draining the caller's wallet - (File: contracts/controller/src/strategies/swap.rs)

### Summary
The Databricks JNDI bug lets a crafted parameter (krbJAASFile in the JDBC URL) turn a routine connection into arbitrary code execution. The analog in XOXNO Lending is the `swap` payload of the router strategies (`multiply`, `swap_debt`, `swap_collateral`, `repay_debt_with_collateral`): the controller passes the caller-supplied route bytes verbatim to the router, the router invokes whatever pool/token addresses the payload names with no allowlist, and any `require_auth`-triggering call that injected code makes (e.g. `token.transfer(victim, attacker, X)`) is recorded as a child of the *caller's* auth entry. If the victim signs the simulated tree — which clients typically do — the injected transfer executes and steals wallet funds far beyond the routed amount.

### Finding Description
`swap_tokens` in `contracts/controller/src/strategies/swap.rs:13-55` authorizes exactly one input transfer to the configured router (`authorize_transfer_as_current`) and then calls `router.execute_strategy(&controller, &amount_in, swap)` with attacker-controlled `swap: Bytes`. Neither the controller nor the router allowlists the venue addresses embedded in the route (documented at `docs/explanation/threat-model.md:154-165`): "the router calls the pool and token addresses its payload names and keeps no allowlist of them, so a route can put third-party code on the call stack below the caller's authorization."

The executable proof is `tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs`: a `RogueHopPool` contract named by the route calls `token.transfer(alice, attacker, WALLET_BALANCE)` during the hop; the simulation test shows the stolen transfer recorded as a child of Alice's `swap_collateral` auth entry, and the enforcing test shows the wallet drain succeeds only when the signed tree includes that child — which is exactly what a caller who signs the simulated tree provides. Venue dispatch code like `contracts/swap-aggregator/src/venues/phoenix.rs:23-25` confirms venue pool addresses come straight from the decoded hop.

### Impact Explanation
Theft of user funds: an attacker who gets a victim to execute a strategy with a poisoned route (malicious quote server, phishing UI, crafted `routeXdr`) drains arbitrary tokens from the victim's wallet — unbounded by `amount_in`, by the payload `min_out`, or by the controller's final account risk gates. The victim loses unrelated wallet balances while the swap itself appears to settle normally (fair output was even paid in the test).

### Likelihood Explanation
Reachable by any unprivileged address via `swap_collateral`/`swap_debt`/`repay_debt_with_collateral`/`multiply`. Exploitation requires social-engineering the victim into signing a route containing the malicious hop — analogous to the CVE's requirement of tricking a victim into using a crafted connection URL. The threat model itself acknowledges "the direct `execute_strategy` path has the same exposure for every swap user."

### Recommendation
Enforce a venue allowlist (or venue-kind dispatch restricted to registered pools) in the router rather than trusting payload-named addresses, so a route cannot place arbitrary contract code on the stack below the caller's auth. Short of that, clients must decode the route and reject any auth tree with children other than the single expected input transfer — as the docs prescribe but the contract does not enforce.

### Proof of Concept
`tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs` is a working PoC: `route_through_pool_stealing` builds a route naming `RogueHopPool`; `simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry` shows the rogue `transfer` nested under the caller's `swap_collateral` auth entry; `enforced_auth_moves_the_wallet_token_only_when_the_signed_tree_lists_the_rogue_transfer` shows Alice's `WALLET_BALANCE` moves to the attacker once she signs that tree.
