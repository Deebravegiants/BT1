### Title
Solver funding venue prices exotic tokens from a manipulable spot price with no size/impact term, and an explicit overfill clamp disable removes the last loss bound - ([File: sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts])

### Summary
The Simplex intent-solver's `FXFiller` prices "venue" pairs (exotic ERC-20 vs. a USD stable with no static curve) directly from the instantaneous `sqrtPriceX96` of a Uniswap V4 pool the solver holds LP in via `UniswapV4FundingPlanner.getExoticTokenPrice` → `computeDirectPoolPriceUsd`. The only defense is an optional, operator-configured static `referencePrice`/`maxDeviationBps` band (`checkPriceGuard`), which checks deviation from a fixed number, not liquidity depth or execution cost, and the code that would otherwise cap overpayment relative to the user's request (`maxOverfillBps`) has been explicitly disabled. An attacker who can move the thin pool's spot price within the configured deviation band (or on a chain with no guard configured at all) can get the solver to quote and fill at a manipulated rate, extracting value from the solver's LP-backed inventory — the same "manipulate a thin/low-liquidity pool oracle then withdraw at the skewed rate" pattern as the Float Protocol incident.

### Finding Description
`UniswapV4FundingPlanner.getExoticTokenPrice` (called by `FXFiller.getVenueUsdPrice`/`venuePriceMemo` in `sdk/packages/simplex/src/strategies/fx.ts`) selects the highest-liquidity pool position for the token and reads its price straight from `sdkPool.token0Price`/`token1Price`, i.e. the pool's current spot price: [1](#0-0) 

This is a single-block spot read with no TWAP/observation window, so it is trivially manipulable by anyone able to move the pool (e.g., a swap in the same or an adjacent transaction), exactly like the Uniswap V3 FLOAT/USDC pool cited in the external report.

The only safeguard, `checkPriceGuard`, is optional per-chain config and only compares the quote to a static number the operator set at deploy time — it explicitly does not account for depth or execution cost, as documented: [2](#0-1) [3](#0-2) 

Even where the guard is configured, an attacker only needs to move price within `maxDeviationBps` (which can be set loosely, e.g. 200 bps in the shipped example config) to profit, and any chain/pair left unguarded (the guard is optional, "omit both to leave the chain unguarded") has zero protection: [4](#0-3) 

Compounding this, the per-order overfill clamp — which previously bounded loss from a bad/manipulated price — has been intentionally disabled, so the filler now fills the full unclamped amount computed from the (potentially manipulated) rate: [5](#0-4) 

The priced amount is then funded by withdrawing real liquidity from the solver's Uniswap V4 position via `planWithdrawalForToken`/`buildRemoveLiquidityCall`, meaning a manipulated price translates directly into an on-chain transfer of the solver's escrowed LP funds to the order's beneficiary: [6](#0-5) 

### Impact Explanation
An unprivileged intent placer (order submitter) reaching the Simplex solver's venue-priced pair path can cause the solver to sell its Uniswap V4-held inventory at a manipulated rate, i.e. direct theft of solver funds — analogous to the ~350 ETH / $1.1M loss from Float Protocol's manipulated low-liquidity oracle. Because the overfill clamp is disabled by design, there is no automatic cap on how much excess the solver will pay out once a manipulated price clears (or bypasses) the optional static-reference guard. Severity is Medium-High depending on pool depth and whether `priceGuard` is configured for the affected chain/pair, matching the "Medium" severity of the source incident.

### Likelihood Explanation
Likelihood is moderate: it requires (a) a venue-priced pair (no static curve) funded from a Uniswap V4 LP position with real, exploitable liquidity depth, and (b) either no `priceGuard` configured for that chain or a configured `maxDeviationBps` wide enough to allow a profitable manipulation. Both conditions are operator/config-dependent but are explicitly supported, documented configurations (the docs show `referencePrice`/`maxDeviationBps` as optional, "omit both to leave the chain unguarded"), and the disabled overfill clamp is unconditional once any of these pairs are live.

### Recommendation
- Replace the instantaneous `sqrtPriceX96` spot price in `computeDirectPoolPriceUsd` with a manipulation-resistant TWAP (or require the price guard to be mandatory, not optional, for any venue-priced pair).
- Tighten `checkPriceGuard` to also account for pool depth/expected price impact of the specific order size, not just a static deviation band.
- Re-enable (or replace) the overfill clamp so a manipulated or stale venue quote cannot cause unbounded overpayment relative to the user's requested output; at minimum, cap total fill value from venue-priced legs independent of the quoted rate.

### Proof of Concept
1. Operator configures a venue-priced pair (`token0` = USDC, `token1` = exotic token) funded from a `[vault.uniswapV4]` LP position, either with no `priceGuard` for the destination chain, or a `maxDeviationBps` wide enough (e.g. the example config's 200 bps) to permit a profitable swing.
2. Attacker swaps against the thin Uniswap V4 pool to move `sqrtPriceX96` so that `token0Price`/`token1Price` shifts favorably (still within `maxDeviationBps` if a guard exists).
3. Attacker submits an IntentGateway order on the manipulated pair; `FXFiller.calculateProfitability` calls `venuePriceMemo → getVenueUsdPrice → getExoticTokenPrice`, which reads the manipulated spot price and passes `checkPriceGuard` (or the pair/chain has no guard at all).
4. `resolveLegRates`/`computeLegPolicyOutput` price the leg at the manipulated rate; the disabled overfill clamp (lines 678-701 of `fx.ts`) lets the unclamped `policyMaxOutput` through unchanged.
5. `planWithdrawalForToken` withdraws liquidity from the solver's real Uniswap V4 position to fund the fill, transferring solver funds to the attacker at the manipulated rate, then the attacker reverses the pool manipulation, keeping the extracted value — mirroring the Float Protocol Rari-pool exploit.

	/**
	 * Validates a live venue quote against the static reference price for the chain.
	 * Returns true (pass) when no guard is configured, or no reference exists for the
	 * chain. Returns false when the quote (token1 per USD) deviates from the reference
	 * by more than `maxDeviationBps`, in which case the order must not be filled.
	 */
	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {
			this.logger.warn(
				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
	}

## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.

```toml lineNumbers
[vault.uniswapV4]
# referencePrice is the expected cNGN per USD;
# reject if the quote is more than 2% off.
# The two go together — one without the other is rejected.
[[vault.uniswapV4.positions]]
chain           = "EVM-8453"
tokenId         = "2087350"
referencePrice  = "1575"
maxDeviationBps = 200
```
