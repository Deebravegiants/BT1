### Title
Unauthenticated `SystemInstruction::InitializeNonceAccount` allows front-running/hijacking of the nonce authority - ([File: programs/system/src/system_instruction.rs])

### Summary
`initialize_nonce_account` (invoked from `system_processor.rs` on `SystemInstruction::InitializeNonceAccount`) sets the nonce authority on any writable, `Uninitialized`-state system-owned account without requiring that account (or its owner/creator) to sign the initializing transaction. This is directly analogous to the zAuction `init()` bug: the state check (`require(!initialized)` ≈ `State::Uninitialized` match) prevents *re*-initialization, but nothing stops a third party from winning the race to be the *first* initializer.

### Finding Description
`initialize_nonce_account` only checks that the target account is writable and in `State::Uninitialized`; it does not check that any signer corresponds to the nonce account or its creator: [1](#0-0) 

The dispatcher in `system_processor.rs` likewise borrows the account and calls `initialize_nonce_account` with no signer requirement enforced on the target account itself: [2](#0-1) 

By contrast, every other mutating nonce instruction (`advance_nonce_account`, `withdraw_nonce_account`, `authorize_nonce_account`) explicitly checks `signers.contains(&data.authority)` before acting: [3](#0-2) [4](#0-3) 

`allocate`/`assign` (used to create the raw system-owned account) do require the target address to sign at creation time: [5](#0-4) 

But `InitializeNonceAccount` has no equivalent check — it is the exact "unprotected init" pattern from the report: guarded only by a `!initialized`-style state check, not by authorization.

The standard client path (`cli/src/nonce.rs::process_create_nonce_account`) bundles `CreateAccount`/`Allocate`+`Assign` and `InitializeNonceAccount` into a single atomic transaction via `create_nonce_account`/`create_nonce_account_with_seed`: [6](#0-5) 

However, nothing at the protocol/runtime level enforces this atomicity. Any user or program is free to submit a `CreateAccount`/`Allocate`+`Assign` transaction and a separate `InitializeNonceAccount` transaction. Once the account-creation transaction lands (making the account exist, funded and system-owned, in `Uninitialized` state), the account address and its lamport balance are publicly visible on-chain/in the mempool before the legitimate owner's `InitializeNonceAccount` transaction confirms. An attacker can front-run with their own `InitializeNonceAccount(attacker_pubkey)` instruction naming themselves as `nonce_authority`, paying a higher priority fee to land first.

### Impact Explanation
Once the attacker's `InitializeNonceAccount` instruction executes first, the account transitions to `State::Initialized` with the attacker as `authority`. The legitimate owner's subsequent `InitializeNonceAccount` call fails with `InstructionError::InvalidAccountData` (detectable, matching the report's stated "mitigating factor").

Critically, once the attacker controls `authority`, they can call `WithdrawNonceAccount` to drain the account's lamports (the funds the legitimate owner deposited to make the account rent-exempt), since `withdraw_nonce_account` only checks `signers.contains(&data.authority)`: [7](#0-6) 

This is a concrete value-loss path: a legitimate user's funded, system-owned account is hijacked and its lamports stolen by an unrelated party who never needed to be a signer on account creation.

### Likelihood Explanation
Exploitation requires the account-creation and initialization steps to occur as separate transactions (rather than atomically bundled, as the CLI helper does), and for the attacker to observe the intervening state and win a fee-priority race within one confirmation window. Any wallet, SDK, or program that does not follow the CLI's atomic bundling convention is exposed. This is analogous to, but narrower than, the zAuction case (no proxy pattern misuse), and the risk window is bounded to between the two transactions' confirmations — making it a real but conditional (not universal) exposure.

### Recommendation
Require that `InitializeNonceAccount` be authorized similarly to other nonce mutations — e.g., require the nonce account itself (or a designated creator/signer established at allocation time) to be a signer of the initializing transaction, closing the gap where any signer set can name themselves as `nonce_authority`. Alternatively, document/enforce (at the transaction-processing or client-library level) that `Allocate`/`Assign`/`CreateAccount` and `InitializeNonceAccount` for a given nonce account must be atomic within a single transaction.

### Proof of Concept
1. Attacker monitors for a `CreateAccount`/`Allocate`+`Assign` transaction that creates a new system-owned, zero-length-then-nonce-sized account `N` (visible once assigned/allocated, before initialization).
2. Attacker submits `SystemInstruction::InitializeNonceAccount(attacker_pubkey)` referencing account `N`, with no signature required on `N` itself — code path: [2](#0-1)  — with a higher priority fee, so it lands before the legitimate owner's own `InitializeNonceAccount(owner_pubkey)`.
3. Account `N`'s state becomes `Initialized { authority: attacker_pubkey, ... }`; legitimate owner's later `InitializeNonceAccount` call fails with `InvalidAccountData` per the `State::Initialized` branch: [8](#0-7) .
4. Attacker calls `WithdrawNonceAccount` signing as `attacker_pubkey`, draining `N`'s lamports to an address they control, per the signer check in `withdraw_nonce_account`: [9](#0-8) .

pub(crate) fn withdraw_nonce_account(
    from_account_index: IndexOfAccount,
    lamports: u64,
    to_account_index: IndexOfAccount,
    rent: &Rent,
    signers: &HashSet<Pubkey>,
    invoke_context: &InvokeContext,
    instruction_context: &InstructionContext,
) -> Result<(), InstructionError> {
    let mut from = instruction_context.try_borrow_instruction_account(from_account_index)?;
    if !from.is_writable() {
        ic_msg!(
            invoke_context,
            "Withdraw nonce account: Account {} must be writeable",
            from.get_key()
        );
        return Err(InstructionError::InvalidArgument);
    }

    let check_signer = |signer: &Pubkey| {
        if !signers.contains(signer) {
            ic_msg!(
                invoke_context,
                "Withdraw nonce account: Account {} must sign",
                signer
            );
            return Err(InstructionError::MissingRequiredSignature);
        }
        Ok(())
    };

    let state: Versions = from.get_state()?;
    match state.state() {
        State::Uninitialized => {
            if lamports > from.get_lamports() {
                ic_msg!(
                    invoke_context,
                    "Withdraw nonce account: insufficient lamports {}, need {}",
                    from.get_lamports(),
                    lamports,
                );
                return Err(InstructionError::InsufficientFunds);
            }
            check_signer(from.get_key())?;
        }
        State::Initialized(data) => {
            if lamports == from.get_lamports() {
                let durable_nonce =
                    DurableNonce::from_blockhash(&invoke_context.environment_config.blockhash);
                if data.durable_nonce == durable_nonce {
                    ic_msg!(
                        invoke_context,
                        "Withdraw nonce account: nonce can only advance once per slot"
                    );
                    return Err(SystemError::NonceBlockhashNotExpired.into());
                }
                check_signer(&data.authority)?;
                from.set_state(&Versions::new(State::Uninitialized))?;
            } else {
                let min_balance = rent.minimum_balance(from.get_data().len());
                let amount = checked_add(lamports, min_balance)?;
                if amount > from.get_lamports() {
                    ic_msg!(
                        invoke_context,
                        "Withdraw nonce account: insufficient lamports {}, need {}",
                        from.get_lamports(),
                        amount,
                    );
                    return Err(InstructionError::InsufficientFunds);
                }
                check_signer(&data.authority)?;
            }
        }
    };

    from.checked_sub_lamports(lamports)?;
    drop(from);
    let mut to = instruction_context.try_borrow_instruction_account(to_account_index)?;
    to.checked_add_lamports(lamports)?;

    Ok(())
}

pub(crate) fn initialize_nonce_account(
    account: &mut BorrowedInstructionAccount,
    nonce_authority: &Pubkey,
    rent: &Rent,
    invoke_context: &InvokeContext,
) -> Result<(), InstructionError> {
    if !account.is_writable() {
        ic_msg!(
            invoke_context,
            "Initialize nonce account: Account {} must be writeable",
            account.get_key()
        );
        return Err(InstructionError::InvalidArgument);
    }

    match account.get_state::<Versions>()?.state() {
        State::Uninitialized => {
            let min_balance = rent.minimum_balance(account.get_data().len());
            if account.get_lamports() < min_balance {
                ic_msg!(
                    invoke_context,
                    "Initialize nonce account: insufficient lamports {}, need {}",
                    account.get_lamports(),
                    min_balance
                );
                return Err(InstructionError::InsufficientFunds);
            }
            let durable_nonce =
                DurableNonce::from_blockhash(&invoke_context.environment_config.blockhash);
            let data = nonce::state::Data::new(
                *nonce_authority,
                durable_nonce,
                invoke_context
                    .environment_config
                    .blockhash_lamports_per_signature,
            );
            let state = State::Initialized(data);
            account.set_state(&Versions::new(state))
        }
        State::Initialized(_) => {
            ic_msg!(
                invoke_context,
                "Initialize nonce account: Account {} state is invalid",
                account.get_key()
            );
            Err(InstructionError::InvalidAccountData)
        }
    }
}

fn allocate(
    account: &mut BorrowedInstructionAccount,
    address: &Address,
    space: u64,
    signers: &HashSet<Pubkey>,
    invoke_context: &InvokeContext,
) -> Result<(), InstructionError> {
    if !address.is_signer(signers) {
        ic_msg!(
            invoke_context,
            "Allocate: 'to' account {:?} must sign",
            address
        );
        return Err(InstructionError::MissingRequiredSignature);
    }

    // if it looks like the `to` account is already in use, bail
    //   (note that the id check is also enforced by message_processor)
    if !account.get_data().is_empty() || !system_program::check_id(account.get_owner()) {
        ic_msg!(
            invoke_context,
            "Allocate: account {:?} already in use",
            address
        );
        return Err(SystemError::AccountAlreadyInUse.into());
    }

    if space > MAX_PERMITTED_DATA_LENGTH {
        ic_msg!(
            invoke_context,
            "Allocate: requested {}, max allowed {}",
            space,
            MAX_PERMITTED_DATA_LENGTH
        );
        return Err(SystemError::InvalidAccountDataLength.into());
    }

    account.set_data_length(space as usize)?;

    Ok(())
}
