### Title
Unchecked Success of Personal Custody Package (PCP) Tier-1/Tier-2 Uploads Leads to Signup Completing Despite Failed Biometric Data Persistence - ([File: src/plans/mod.rs])

### Summary
The `MasterPlan::build_and_upload_pcp`-style flow in `src/plans/mod.rs` checks the return value of the tier-0 PCP upload (`upload_pcp_tier_0`, which returns a `bool`/`Result<bool>` and gates the signup outcome), but the tier-1 and tier-2 uploads are dispatched by fire-and-forget message sends to the `data_uploader` agent and their eventual success/failure is never propagated back into the signup result.

### Finding Description
In `src/plans/mod.rs` (around lines 599-637), after building the PCP packages, the code calls: [1](#0-0) 

which awaits and checks the boolean result of tier-0 upload before continuing. However, for `pcp_version >= 3`, tier-1 and tier-2 packages are simply enqueued via `orb.data_uploader.enabled().unwrap().send(...)`: [2](#0-1) 

This `send` only awaits successful delivery of the message into the agent's input channel — not the outcome of the actual network upload. The real upload happens later, asynchronously, in `agents/data_uploader.rs::Agent::upload_pcp`, which retries the HTTP request against `backend::upload_personal_custody_package::request` and, on failure, simply logs an error via `tracing::error!` and increments a Datadog counter before breaking out of the retry loop — with no propagation of failure state back to the `MasterPlan` or the signup result: [3](#0-2) 

This mirrors the reported ERC20 `transfer()` bug class: the caller treats the mere act of "sending" as equivalent to "successfully transferred/persisted," and continues subsequent state transitions (marking the signup complete, informing the backend/user of success) without verifying whether the tier-1/tier-2 biometric custody data was actually stored by the backend.

### Impact Explanation
If tier-1/tier-2 PCP uploads (which carry the user's iris/face biometric keys/data for self-custody, per `personal_custody_package.rs`) silently fail due to network errors, client errors, or backend rejection, the signup flow (`MasterPlan::run` → `after_signup`) still proceeds to report the signup as completed/successful to the UI and backend. This can result in the user believing their biometric enrollment/self-custody data was persisted when it was not, a form of biometric data loss/misattribution of signup completion status — analogous to a protocol accounting for a transfer that never happened.

### Likelihood Explanation
This requires only a transient backend/network failure during tier-1/tier-2 upload (unprivileged-user reachable — this happens during a normal signup by any user), not a malicious actor, malicious node, or privileged access. The likelihood of intermittent network failures affecting an orb field device is realistic.

### Recommendation
Await and check the completion/result of tier-1 and tier-2 PCP uploads (not just successful channel enqueue) before treating the signup as fully successful. Propagate failures similarly to how `upload_pcp_tier_0`'s boolean result is handled — e.g., by returning a completion channel/future from the `data_uploader` agent for each tier, and failing the signup (or marking it for retry/flagging) if any tier upload does not confirm success.

impl Agent {
    async fn upload_pcp(&self, pcp: Pcp, id: u64) -> (u8, u64) {
        let Pcp { signup_id, user_id, data, checksum, tier } = pcp;
        tracing::info!(
            "Start uploading a personal custody package tier {tier} for signup_id={signup_id}"
        );
        let t = Instant::now();
        loop {
            let response = backend::upload_personal_custody_package::request(
                &signup_id,
                &user_id,
                checksum.as_ref(),
                &data,
                Some(tier),
                &self.config,
            )
            .await;
            match response {
                Ok(()) => {
                    dd_timing!("main.time.signup.upload_custody_images" + format!("t{}", tier), t);
                    tracing::info!(
                        "Personal custody package tier {tier} uploading completed in: {}ms",
                        t.elapsed().as_millis()
                    );
                    break;
                }
                Err(err) => {
                    tracing::error!("UPLOAD PERSONAL CUSTODY PACKAGE TIER {tier} ERROR: {err:?}");
                    dd_incr!(
                        "main.count.http.upload_custody_images.error.network_error",
                        "error_type:normal"
                    );
                    if let Some(reqwest_err) = err.downcast_ref::<reqwest::Error>() {
                        if let Some(status) = reqwest_err.status() {
                            if status.is_client_error() {
                                dd_incr!(
                                    "main.count.signup.result.failure.upload_custody_images",
                                    "type:network_error",
                                    "subtype:signup_request"
                                );
                                break;
                            }
                        }
                    }
                }
            }
        }
        (tier, id)
    }
