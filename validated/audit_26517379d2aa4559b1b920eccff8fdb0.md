Audit Report

## Title
Global, workflow-unscoped `requestID` collision in HTTP Trigger Handler allows DoS of another user's trigger requests - (File: `core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go`)

## Summary
The `httpTriggerHandler` in the Gateway's HTTP-trigger capability stores in-flight requests in a single node-wide map keyed only by the caller-supplied `requestID`, with no scoping to `workflowID` or owner. Any caller who is an authorized signer for *any* workflow (i.e., their own, freely registrable workflow) can pre-occupy an arbitrary `requestID` value, causing a completely unrelated victim's legitimate request using the same `requestID` for a different workflow to be rejected with a conflict error before ever reaching the DON.

## Finding Description
`httpTriggerHandler` keeps a single global map `callbacks map[string]savedCallback // requestID -> savedCallback` [1](#0-0) . In `HandleUserTriggerRequest`, the request pipeline runs `resolveWorkflowID` → `authorizeRequest` (JWT signature check against the target `workflowID`'s authorized keys) → `checkRateLimit` → `setupCallback` [2](#0-1) . Crucially, `setupCallback` enforces `requestID` uniqueness purely against the single global `h.callbacks` map, independent of `workflowID`:

```go
if _, found := h.callbacks[requestID]; found {
    h.handleUserError(ctx, requestID, jsonrpc.ErrConflict, ...)
    return nil, fmt.Errorf("in-flight request ID: %s", requestID)
}
``` [3](#0-2) 

The only validation on `requestID` itself is non-empty and no `/` character [4](#0-3) . `authorizeRequest` only verifies that the caller holds a valid JWT signed by a key registered as authorized *for the target `workflowID`* via `WorkflowMetadataHandler.Authorize` [5](#0-4) ; it does not tie the `requestID` namespace to that workflow in any way. Consequently, an attacker who controls (or is an authorized signer for) their *own* registered workflow — a normal, permissionless action available to any external user — passes `authorizeRequest` for their own workflow, then collides on `requestID` against the shared global map, blocking any other, unrelated workflow's request using the same ID. Node responses are also routed back purely by `resp.ID` against this same global map, confirming `requestID` is the sole disambiguator across the whole handler instance [6](#0-5) .

Existing protections (JWT signature verification, JWT replay cache, rate limiting) only guard against forging requests *for a workflow the attacker isn't authorized for* and per-workflow request flooding; none of them scope or protect the `requestID` uniqueness namespace itself, so they do not mitigate this issue.

## Impact Explanation
Any caller with authorization for at least one workflow (trivially obtained by registering their own workflow, which is a permissionless, expected platform action) can deny a specific invocation of an unrelated victim's HTTP-triggered workflow execution by pre-claiming a `requestID` the victim's client is expected to use next. The victim's genuine request is rejected with `jsonrpc.ErrConflict` and never dispatched to the DON. This is a griefing/availability (DoS) impact on individual trigger invocations across tenants, distinct from any legitimate per-workflow rate limiting or authentication control.

## Likelihood Explanation
Exploitation requires only: (1) being an authorized signer for some registered workflow (attacker's own), and (2) predicting/guessing the `requestID` value a victim's client will use (plausible for common low-entropy or sequential client-side ID schemes). No admin, operator, or host-level access is needed, and the collision check runs before any per-request accounting that would detect cross-workflow abuse.

## Recommendation
Scope the in-flight-request uniqueness check (and the `callbacks` map key) to a composite of `workflowID` (or workflow owner) plus `requestID`, so that ID collisions can only occur within the same workflow/owner's own request stream, not across unrelated callers/workflows.

## Proof of Concept
1. Attacker registers/owns Workflow A and obtains a valid JWT for it, then sends `workflows.execute` with `id = "1001"` targeting Workflow A.
2. `setupCallback` inserts `h.callbacks["1001"]` into the shared map (`core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go:419-426`).
3. Victim's client (unrelated Workflow B, using a predictable/incrementing `id` scheme) sends a legitimate `workflows.execute` request with the same `id = "1001"`.
4. Victim's request hits the same `found` check in `setupCallback`, returns `jsonrpc.ErrConflict`, and is never forwarded to the DON — reproducible via a Go unit test that calls `HandleUserTriggerRequest` twice with distinct authorized workflows but identical `req.ID`, asserting the second call returns the `in-flight request ID` error.

func (h *httpTriggerHandler) validateRequestID(ctx context.Context, requestID string, callback handlers.Callback) error {
	if requestID == "" {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "'id' field is required and cannot be empty. Use a new unique request 'id' for each request", callback)
		return errors.New("empty request ID")
	}
	// Request IDs from users must not contain "/", since this character is reserved
	// for internal node-to-node message routing (e.g., "http_action/{workflowID}/{uuid}").
	if strings.Contains(requestID, "/") {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "request ID must not contain '/'", callback)
		return errors.New("request ID must not contain '/'")
	}
	return nil
}

func (h *httpTriggerHandler) setupCallback(ctx context.Context, requestID string, callback handlers.Callback, requestStartTime time.Time, workflowID string) (<-chan struct{}, error) {
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()

	if _, found := h.callbacks[requestID]; found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrConflict, fmt.Sprintf("requestID: %s has already been used. Ensure the requestID is unique for each request.", requestID), callback)
		return nil, fmt.Errorf("in-flight request ID: %s", requestID)
	}

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}
