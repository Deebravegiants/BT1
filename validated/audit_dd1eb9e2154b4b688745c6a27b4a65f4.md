### Title
Unchecked index-scaled debt multiplication can permanently freeze a saturated market - ([File: common/src/rates/index.rs])

### Summary
Interest accrual computes `borrowed * new_borrow_index` and `supplied * supply_index` as `i128` fixed-point values and panics on `MathOverflow` when the RAY-scaled product exceeds `i128::MAX` [1](#0-0) [2](#0-1) . Because every relevant controller operation synchronizes the market before repayment, withdrawal, liquidation, or other mutations, reaching this arithmetic ceiling makes the entire market unusable [3](#0-2) [4](#0-3) .

### Finding Description
The vulnerability is the integer-overflow analog of CVE-2016-2324: attacker-controlled cumulative market size can eventually make `scaled shares * index` unrepresentable, even though every individual amount and index remains within its configured domain [5](#0-4) [6](#0-5) .

`global_sync` calls `accrue_step`, which ultimately evaluates the old and new total debt as `borrowed.mul(old_borrow_index)` and `borrowed.mul(new_borrow_index)` [7](#0-6) [2](#0-1) . `Ray::mul` delegates to `mul_div_half_up`, which panics when the exact result does not fit in `i128` [6](#0-5) [8](#0-7) .

The borrow-index ceiling does not reliably prevent this condition because `update_borrow_index` multiplies the uncapped old index and growth factor before applying `MAX_BORROW_INDEX_RAY` [9](#0-8) . A very large market can therefore cross the total-value representation limit before the index reaches its intended ceiling [10](#0-9) .

### Impact Explanation
Once `borrowed * new_borrow_index` or `supplied * supply_index` cannot fit in `i128`, forced accrual panics before the mutating operation executes [11](#0-10) [12](#0-11) .

This permanently freezes supplier withdrawals, borrower repayments, liquidations, bad-debt processing, and later index updates for the affected hub-asset market [13](#0-12) . Pool funds remain locked because the accrual failure occurs before accounting, token movement, or recovery logic can run [14](#0-13) [15](#0-14) .

### Likelihood Explanation
An unprivileged user can drive the market toward the condition through ordinary `supply`, `borrow`, and later `update_indexes`/time-triggered accrual paths; no privileged arithmetic input is required [16](#0-15) [4](#0-3) .

The exploit requires an extremely large RAY-valued position and enough index growth for the product to exceed `i128::MAX`, so it is economically constrained rather than reachable with ordinary balances [17](#0-16) [18](#0-17) . The checked-in regression test demonstrates a concrete reachable configuration: a one-billion-token, 18-decimal market at approximately 98% utilization eventually fails with `MATH_OVERFLOW`, after which both withdrawal and repayment fail [19](#0-18) .

### Recommendation
Enforce a conservative bound on scaled debt and scaled supply that guarantees `scaled * MAX_*_INDEX_RAY / RAY` remains representable, and reject supply or borrow entries before they admit a potentially overflowing market state [20](#0-19) [21](#0-20) .

Additionally, calculate the capped index transition using arithmetic that clamps before evaluating an unrepresentable intermediate, and account for interest with a widened or saturating total-value representation where economically safe [9](#0-8) [22](#0-21) . The invariant should cover both `calculate_supplier_rewards` and `update_supply_index`, since each multiplies a market total by an index [1](#0-0) [2](#0-1) .

### Proof of Concept
The repository already contains a regression test that establishes the full attack path:

```rust
let principal = BILLION * 10i128.pow(18);
t.supply_raw(BOB, "BIG18", principal);
let debt = principal / 100 * 98;
t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
t.borrow_raw(ALICE, "BIG18", debt);

loop {
    years += 1;
    t.advance_time(YEAR_SECS);
    if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
        break e;
    }
}
```

After `try_update_indexes_for` returns `MATH_OVERFLOW`, the same test shows that `withdraw` and `repay` also fail with `MATH_OVERFLOW`, while the stored borrow index remains below `MAX_BORROW_INDEX_RAY` [19](#0-18) . The documented consequence is that a billion 18-decimal whole tokens produce a `1e36` RAY amount and index growth beyond roughly 170× makes the scaled value exceed the `i128` ceiling [23](#0-22) .

pub fn update_supply_index(env: &Env, supplied: Ray, old_index: Ray, rewards_increase: Ray) -> Ray {
    if supplied == Ray::ZERO || rewards_increase == Ray::ZERO {
        return old_index;

/// Accrues borrow/supply indexes from `last_timestamp` to the cache's current time.
///
/// No-op when no time has elapsed. Splits long gaps into max-sized compound
/// windows, then sets `last_timestamp` to `current_timestamp`.
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Computes `x * y / d` rounded half up. Requires `x >= 0`, `y >= 0`, and `d > 0`; a
/// `debug_assert` checks this in debug builds. Panics with `GenericError::DivisionByZero` if
/// `d == 0`, and with `GenericError::MathOverflow` if any other precondition is violated or if
/// the result does not fit in `i128`.
pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    // The zero check runs first so debug and release builds agree on a zero
    // divisor: both surface `DivisionByZero` rather than tripping the assert.
    require_nonzero_divisor(env, d);
    debug_assert!(
        x >= 0 && y >= 0 && d > 0,
        "mul_div_half_up: non-negative x, y and positive d"
    );
    try_mul_div_half_up(env, x, y, d)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
}

/// Computes `x * y / d` rounded half up. Returns `None` if `x < 0`, `y < 0`, `d <= 0`, or the
/// result does not fit in `i128`.
pub fn try_mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> Option<i128> {
    if x < 0 || y < 0 || d <= 0 {
        return None;
    }
    let half = d / 2;

    // Fast path: the biased product fits `i128`, so the whole computation is
    // native. `x * y + half` is non-negative here, so `/` is the floor the
    // widened path would produce.
    if let Some(biased) = x
        .checked_mul(y)
        .and_then(|product| product.checked_add(half))
    {
        return Some(biased / d);
    }

    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    x256.mul(&y256)
        .add(&I256::from_i128(env, half))
        .div(&d256)
        .to_i128()
}

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
