### Title
Unauthenticated TCP livestream trigger causes unencrypted UDP transmission of raw biometric camera frames - ([File: src/agents/livestream/downstream.rs])

### Summary
The livestream agent's `Upstream::new` binds an unauthenticated TCP listener on port 9201 and, on any incoming connection, immediately instantiates `Downstream::new(addr.ip())`, which builds a GStreamer pipeline (`appsrc → nvvidconv → nvv4l2h264enc → rtph264pay → udpsink`) that streams raw camera frames (IR eye/face, RGB, thermal, depth) as H.264-over-RTP to the connecting device's IP on UDP port 9200, with no TLS/SRTP or payload encryption anywhere in the path. `Downstream::push` is the sink that feeds every rendered frame into this cleartext pipeline.

### Finding Description
`Upstream::poll_next` in `src/agents/livestream/upstream.rs` accepts any TCP connection on port 9201 with no credential, token, or key check — `Event::Connected(addr)` is emitted for every accepted socket [1](#0-0) . In `src/agents/livestream/mod.rs`, this event unconditionally creates a new `Downstream` targeting the connecting peer's IP address, with no authorization/allow-list check beyond the OS-level TCP accept [2](#0-1) . `Downstream::new` builds the GStreamer pipeline ending in `udpsink` bound to that IP on the fixed `PORT = 9200`, with no encryption element (no `srtpenc`, no DTLS, no application-layer crypto) anywhere in the chain [3](#0-2) . Every rendered UI/camera frame is then pushed through `Downstream::push`, which copies raw frame bytes into the GStreamer buffer and feeds `appsrc`, ultimately reaching the network as cleartext H.264/RTP/UDP [4](#0-3) . The rendered content includes actual sensor frames — `IrEyeFrame`, `IrFaceFrame`, `RgbFrame`, `ThermalFrame`, `DepthFrame` — passed into `gpu.update_camera_*` and rendered into the texture that `push` streams out [5](#0-4) , [6](#0-5) . Nowhere in this path is there any binding to the signup's key material, TLS/SRTP negotiation, or peer authentication — any device that can complete a TCP handshake to port 9201 determines where the unencrypted UDP video stream is subsequently sent, and any device that can observe that UDP flow (on-path or on the same LAN/broadcast segment, or via ARP/IP spoofing to redirect it) can capture the raw iris/face/depth imagery.

### Impact Explanation
This is a direct violation of the invariant that biometric secrets must only be encrypted to the scanned user's key: raw IR eye/face, RGB, and depth camera frames are transmitted as cleartext H.264/RTP over UDP with no confidentiality or integrity protection. This matches the Worldcoin/Orb bounty "biometric data disclosure" impact category — an unprivileged network-adjacent attacker can recover raw iris/face imagery of a signup subject in the clear, without needing operator access, keys, or physical tampering.

### Likelihood Explanation
Exploitability depends entirely on the `livestream` Cargo feature being compiled into the running orb-core binary and the corresponding TCP/UDP ports being reachable on the network the orb is connected to (e.g., staging/debug builds via the `stage` feature, which explicitly enables `livestream`, per `Cargo.toml`). Given that precondition (asserted in the prompt and consistent with the feature-gated design), the attack is fully reachable and repeatable: any device capable of opening a TCP connection to port 9201 unconditionally triggers a fresh unencrypted UDP video stream directed at its own IP on port 9200, and any on-path/on-LAN observer can capture that stream without any additional secret. There is no rate limiting, allow-listing, or authentication gate on either the TCP trigger or the UDP payload.

### Recommendation
Add mutual authentication (e.g., a pre-shared token or mTLS) on the TCP control channel (`Upstream`) before allowing a `Downstream` to be created, and encrypt the actual media path — either via SRTP (`srtpenc`/`srtpdec` GStreamer elements) keyed from a per-session secret established during that authenticated handshake, or by tunneling the UDP/RTP stream over a DTLS/TLS channel. Do not derive or reuse the signup's biometric key for this transport encryption; use a dedicated session key negotiated over the authenticated channel.

### Proof of Concept
Integration test plan:
1. Start `Upstream::new()` (bind to port 9201) and a mock `Downstream` sink; open a TCP connection from a test client (representing the unprivileged attacker's device) and confirm `Event::Connected` fires without any credential exchange.
2. Have the mod.rs run-loop invoke `Downstream::new(attacker_ip)` and then call `push()` with synthetic frame bytes containing a known marker pattern.
3. Bind a raw `udpsrc` listener (simulating the attacker's own passive UDP capture) on port 9200 at `attacker_ip`, run it through `rtph264depay`/`h264parse`/`avdec_h264` (mirroring `livestream-client/src/downstream.rs`), and assert that the decoded frame reproduces the known marker pattern in plaintext with no decryption step required — proving the biometric frame data is fully recoverable without any key material bound to the signup.
4. Assert failure of the invariant: no `srtpdec`/DTLS/TLS element is required to decode the stream, i.e., the pipeline succeeds even when the "attacker" client has no knowledge of any orb- or signup-specific secret.

    pub fn push(&self, frame: &[u8]) -> Result<()> {
        let mut buffer = gstreamer::Buffer::with_size(self.video_info.size())
            .expect("failed to create a new gstreamer buffer");
        {
            let buffer = buffer.get_mut().unwrap();
            let mut video_frame =
                VideoFrameRef::from_buffer_ref_writable(buffer, &self.video_info).unwrap();
            let plane_data = video_frame.plane_data_mut(0).unwrap();
            unsafe {
                ptr::copy_nonoverlapping(frame.as_ptr(), plane_data.as_mut_ptr(), frame.len());
            }
        }
        self.appsrc.push_buffer(buffer)?;
        Ok(())
    }
