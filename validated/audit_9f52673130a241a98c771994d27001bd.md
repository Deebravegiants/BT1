Confirmed key mechanism: `EvmHost.dispatchIncoming` checks `extcodesize(destination)` and silently returns without reverting if the destination has no code — so a message routed to a `to` address that doesn't have a deployed contract on the destination chain is dropped without any error, and the relayer fee held in `_requestCommitments` is never paid out or refunded automatically (it stays escrowed until a timeout message is submitted, if `timeout != 0`). ### Title
Optimistic CREATE2 peer assumption in HyperbridgeLzEndpoint causes silently dropped messages and stuck relayer fees on chains where the mirror deployment address diverges - (File: sdk/packages/lz-endpoint/contracts/HyperbridgeLzEndpoint.sol)

### Summary
`HyperbridgeLzEndpoint.send()` validates that the destination `dstEid` maps to a configured ISMP state machine, but it never validates the actual on-chain *contract* address it targets. It always sets `to: abi.encodePacked(address(this))`, optimistically assuming the same `HyperbridgeLzEndpoint` contract is deployed at the identical address on the destination chain via CREATE2, exactly as the contract's own docstring states ("Assumes the same contract address on all chains (CREATE2 deployment)"). [2](#0-1) [3](#0-2) 

### Finding Description
`setEidMapping` only records a `(lzEid → stateMachineId)` pairing set by the owner; it never records or verifies a peer *address* on the destination chain. [4](#0-3) 

When `send()` (and `quote()`) build the `DispatchPost`, the `to` field is hardcoded to `abi.encodePacked(address(this))` rather than a per-destination registered peer address: [5](#0-4) 

This mirrors the report's "optimistic peer assumption" bug class: the sender never confirms that a receiving contract actually exists at the assumed address on the destination chain before locking funds/fees and dispatching. On the destination `EvmHost`, `dispatchIncoming` resolves `to` to an address and checks `extcodesize`; if the code size is zero (no contract deployed there — e.g., the endpoint wasn't deployed to that address on that particular chain, deployer nonce/CREATE2 salt collision differs, or the destination is a chain type where CREATE2 address derivation differs), the host **silently returns** without reverting and without recording any receipt: [6](#0-5) 

Because `HyperbridgeLzEndpoint.send()` dispatches with `timeout: 0` ("no expiry"), the relayer fee escrowed in `_requestCommitments` on the destination `EvmHost` for this request can never be timed out and refunded — the request is not `dest`-source refundable via `onPostRequestTimeout` since `HyperbridgeLzEndpoint.onPostRequestTimeout` is a documented no-op: [7](#0-6) [8](#0-7) 

For any OFT/OApp routed through this endpoint, the underlying cross-chain payload (which can represent locked/burned tokens on the source OApp, per the endpoint's own docs: "Existing OFTs can point to this contract as their LayerZero endpoint") is delivered nowhere and lzReceive is never invoked, because there is no code at the target address to execute `IApp.onAccept`. The message is neither delivered nor is the underlying OApp's outbound lock ever unwound, since (with `timeout: 0`) it can never officially time out on the source chain either.

### Impact Explanation
If the operator misconfigures `setEidMapping` for a chain where the `HyperbridgeLzEndpoint` (or the intended peer OApp) has not actually been deployed at the CREATE2-predicted address (deployer key compromise necessitating a new deployer, chain without full CREATE2 support/parity, a chain-specific nonce/salt mismatch, or simply a not-yet-deployed endpoint on that chain), user funds routed through downstream OFTs are permanently unrecoverable: the source-side lock/burn happens, the message is dropped silently with no revert and no receipt on the destination, and the zero-timeout design removes the only recovery path (a timeout message) available elsewhere in the protocol. This matches "HIGH impact" from the analog report (temporary lock, or permanent loss if the team cannot deploy to the same address).

### Likelihood Explanation
Likelihood is LOW-to-MEDIUM: this requires the endpoint owner to call `setEidMapping` for a destination before actually deploying `HyperbridgeLzEndpoint` (or with a mismatched CREATE2 address) on that chain — an operational/config error rather than something an unprivileged attacker can trigger directly. However, unlike the original OmniX report (where the peer defaults are silently accepted without any admin action), here the state-machine mapping requires deliberate configuration by the operator, which somewhat lowers likelihood relative to the original finding, but the "trust CREATE2 address parity" assumption is baked into the contract's design for every configured chain, so any deployment slip reproduces the bug for all users of that route.

### Recommendation
- Store an explicit, owner-configured peer address per `dstEid`/state machine (mirroring the pattern already used correctly in `HyperFungibleToken`/`WrappedHyperFungibleToken`, which use `_supportedChains[chainId] = moduleId` and revert with `UnsupportedChain()` if unset) instead of unconditionally using `address(this)`.
- Set a non-zero `timeout` on the outbound `DispatchPost` in `send()` so that undeliverable requests become recoverable via the existing ISMP timeout/refund path (`dispatchTimeOut`), rather than being permanently unrecoverable with `timeout: 0`.
- Optionally, have `onAccept` reject/validate the `to` address on delivery in addition to source verification, so config drift is caught early rather than causing silent drops.

### Proof of Concept
1. Owner deploys `HyperbridgeLzEndpoint` at address `E` on chain A (source) via CREATE2.
2. Owner intends to also deploy the endpoint at address `E` on chain B (destination) but for any reason (different deployer nonce history, a chain that doesn't preserve CREATE2 address parity, or deployment not yet completed) the actual contract on chain B is not at address `E` (either no contract, or a different, unrelated contract).
3. Owner nonetheless calls `setEidMapping(dstEidB, stateMachineB)` on chain A's endpoint, since the mapping only requires knowing the target chain, not verifying the peer contract. [9](#0-8) 
4. A user's OFT calls `send()` on chain A's endpoint, which locks/burns tokens in the OFT and dispatches `DispatchPost{ dest: stateMachineB, to: abi.encodePacked(E), timeout: 0, ... }`. [3](#0-2) 
5. Once relayed and proven on chain B, `HandlerV2.handlePostRequests` calls `EvmHost.dispatchIncoming`, which finds `extcodesize(E) == 0` and returns silently — no `onAccept`, no revert, no receipt. [6](#0-5) 
6. Because `timeout` was `0`, the request can never be timed out on chain A, so the user's locked/burned tokens on the source OFT are never refunded and the message is never delivered — permanent loss.

    function dispatchIncoming(PostRequest memory request, address relayer) external restrict(_hostParams.handler) {
        address destination = _bytesToAddress(request.to);
        uint256 size;
        assembly {
            size := extcodesize(destination)
        }
        if (size == 0) {
            // instead of reverting the entire batch, early return here.
            return;
        }

        // replay protection
        bytes32 commitment = request.hash();
        _requestReceipts[commitment] = relayer;

        (bool success,) = address(destination)
            .call(abi.encodeWithSelector(IApp.onAccept.selector, IncomingPostRequest(request, relayer)));

        if (!success) {
            // so that it can be retried
            delete _requestReceipts[commitment];
            return;
        }
        emit PostRequestHandled({commitment: commitment, relayer: relayer});
    }

    /**
     * @notice Registers a bidirectional mapping between a LZ eid and an ISMP state machine ID.
     * @dev Pass empty `stateMachineId` to disable the EID. Re-mapping an EID clears the prior
     * state machine's reverse entry so revoked sources cannot keep impersonating the EID.
     * @param lzEid The LayerZero endpoint ID
     * @param stateMachineId The ISMP state machine identifier (e.g., StateMachine.evm(1))
     */
    function setEidMapping(uint32 lzEid, bytes calldata stateMachineId) external onlyOwner {
        if (lzEid == 0) revert InvalidEid();
        bytes memory previous = _eidToStateMachine[lzEid];
        if (previous.length != 0) {
            delete _stateMachineToEid[keccak256(previous)];
        }
        _eidToStateMachine[lzEid] = stateMachineId;
        if (stateMachineId.length != 0) {
            _stateMachineToEid[keccak256(stateMachineId)] = lzEid;
        }
    }

    function send(
        MessagingParams calldata _params,
        address /* _refundAddress */
    ) external payable override whenNotPaused returns (MessagingReceipt memory) {
        bytes memory dest = _eidToStateMachine[_params.dstEid];
        if (dest.length == 0) revert UnknownEid(_params.dstEid);

        // Track nonce
        uint64 nonce = ++_outboundNonce[msg.sender][_params.dstEid][_params.receiver];

        // Compute globally unique identifier
        bytes32 guid = keccak256(
            abi.encodePacked(nonce, _eid, bytes32(uint256(uint160(msg.sender))), _params.dstEid, _params.receiver)
        );

        // Encode the LZ message into the ISMP body
        bytes memory body = abi.encode(
            guid,
            _eid, // srcEid
            bytes32(uint256(uint160(msg.sender))), // sender
            nonce,
            _params.receiver, // receiver OApp on dest
            _params.message
        );

        DispatchPost memory request = DispatchPost({
            dest: dest,
            to: abi.encodePacked(address(this)),
            body: body,
            timeout: 0,
            fee: relayerFee(_params.dstEid),
            payer: address(this)
        });

        if (msg.value > 0) {
            IDispatcher(_host).dispatch{value: msg.value}(request);
        } else {
            // Fee tokens already transferred to this contract by OFT's _payLzToken.
            // The quoted lzTokenFee includes a buffer above the relayer fee so the
            // legacy deployed host's per-byte protocol fee can be paid out of it;
            // approve our full feeToken balance and let the host take what it needs.
            address feeToken = IDispatcher(_host).feeToken();
            IERC20(feeToken).forceApprove(_host, IERC20(feeToken).balanceOf(address(this)));
            IDispatcher(_host).dispatch(request);
        }

        return MessagingReceipt({
            guid: guid,
            nonce: nonce,
            fee: MessagingFee({nativeFee: msg.value, lzTokenFee: 0})
        });
    }
