### Title
Controller permanently strands token balances pushed outside declared strategy legs — no recovery entrypoint exists - (File: contracts/controller/src/strategies/flash_position.rs)

### Summary
The bug class is "contract holds token balances with no function to transfer them out." The XOXNO controller contract is a transient token holder in several unprivileged paths (`flash_position`, `multiply`, `swap_debt`, `swap_collateral`, `repay_debt_with_collateral`, `migrate_from_blend`, liquidation legs), yet it exposes no entrypoint that can move a token balance that is not part of the tracked per-account accounting. Any tokens that land on the controller outside the declared legs are frozen permanently.

### Finding Description
The UXD analog is the governor lacking `transferETH`; here the analogous holder is the controller. In `flash_position`, the callback pushes declared collateral to the controller, and per the documented ABI semantics, "undeclared controller balances are not credited" — tokens pushed to the controller beyond the declared collateral vector are neither credited to the account nor refundable by any entrypoint. Similarly, `migrate_from_blend` explicitly ignores pre-existing controller balances: the harness test `test_migrate_refund_ignores_preexisting_controller_balance` asserts that ETH already sitting on the controller "must remain (not used as refund or swept)". Strategy legs only measure balance *deltas* (e.g., `withdraw_and_swap_from_supply` in `contracts/controller/src/strategies/legs.rs` swaps only the measured receipt), so any residual balance has no exit path. The controller interface contains no sweep/rescue/`transfer_token` function — the only outbound flows are the pool's `transfer_out` inside withdraw accounting (`contracts/pool/src/ops/withdraw.rs:48`) and governance `execute`, which cannot move tokens held by the controller address.

### Impact Explanation
Permanent freezing of funds. A user (or a contract integrating via `flash_position`) that transfers collateral to the controller without a matching declared entry loses the tokens irrevocably: they are not credited to any account, cannot be withdrawn via `withdraw`, and there is no privileged or unprivileged function to extract them. The same applies to dust or over-payment residues left by swap strategies — all balances on the controller outside tracked accounting are locked forever.

### Likelihood Explanation
Reachable by a single unprivileged address: `flash_position(caller, account_id, ...)` with a callback that pushes tokens the position doesn't declare, or a direct `token.transfer(user -> controller)` followed by any strategy whose delta-based measurement cannot pick up the pre-existing balance. The protocol's own test suite confirms this stranded-balance state exists and is intentionally preserved, so the stuck funds are a real, reproducible state, not a theoretical one.

### Recommendation
Add a recovery path for non-tracked controller balances — e.g., a governed `AdminOperation` / controller function that transfers a specified token amount out of the controller (the analog of `transferETH`/`transferERC20`), restricted so it cannot touch balances mid-strategy (flash guard). Alternatively, in `flash_position`, credit or refund any post-callback controller balance exceeding the declared collateral instead of leaving it uncredited.

### Proof of Concept
1. Deploy controller/pool with an ETH market.
2. Mint ETH to ALICE; ALICE calls `token::Client::transfer(alice -> controller, X)` (or pushes undeclared collateral inside a `flash_position` callback).
3. Observe `token.balance(controller) == X`.
4. Attempt recovery: `controller.withdraw` fails — the tokens are not backed by any account's supply position (`execute_withdrawal` in `contracts/controller/src/positions/supply.rs:218` burns shares against tracked positions only). No other controller entrypoint moves a token balance; `get_account_positions` shows no claim. The harness test `test_migrate_refund_ignores_preexisting_controller_balance` already encodes this: a pre-existing controller balance remains on the contract untouched after `migrate_from_blend`.
5. The X tokens are permanently frozen.
