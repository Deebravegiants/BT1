### Title
Permissionless graduation can permanently brick when pinned LP amounts round to zero, freezing curve-raised funds forever - ([File: packages/contracts/src/Bonding.sol])

### Summary
`Bonding.finalizeGraduation` mints HyperSwap V2 liquidity using amounts (`tokensForLP`, `ltFromPair`) that are pinned once at phase 1 (`_enterGraduating` → `_prepareGraduationLiquidity`) and can never be recomputed or bypassed. If those pinned amounts are small enough that the resulting liquidity mint underflows (either UniswapV2's `MINIMUM_LIQUIDITY` floor or `LPLock.recordLock`'s `ZeroAmount` guard), `finalizeGraduation` reverts unconditionally on every call, permanently trapping the token in `Lifecycle.Graduating` with all curve-raised LT and the 250M reserved tokens stuck inside `Bonding` forever.

### Finding Description
Graduation is split into two phases specifically to fit HyperEVM's small-block gas ceiling, and the protocol's own invariant states that "Phase 2 must never revert under any pre-seed shape" [1](#0-0) .

`_prepareGraduationLiquidity` computes `tokensForLP` and `ltFromPair` purely from pair reserve arithmetic at the moment the threshold-crossing buy lands, and caches them in `pendingGraduation[token]`: [2](#0-1) 

These cached values are consumed verbatim by `finalizeGraduation`, with no re-pricing, no minimum-size floor check, and no fallback if the mint fails: [3](#0-2) 

The final step, `LPLock.recordLock`, itself enforces `amount == 0` reverts and is explicitly documented as a one-shot call that `finalizeGraduation` cannot skip — there is no removal or reset path for a locker, and no retry mechanism for a failed lock: [4](#0-3) 

Because `tokensForLP`/`ltFromPair` are derived from raw on-chain reserve units (not USD), and the reserve asset is an externally-priced LT whose `exchangeRate()` can be arbitrarily high, the USD graduation threshold (`graduationThresholdUsd`) can be crossed while the underlying raw LT/token amounts pinned for LP seeding are extremely small in wei terms. If `sqrt(tokensForLP * ltFromPair)` (the UniswapV2 first-mint liquidity formula used by the "no LP minted yet" fast path documented in `_seedUniswapV2Direct`) falls at or below `MINIMUM_LIQUIDITY`, the HyperSwap pair's `mint` call reverts with "INSUFFICIENT_LIQUIDITY_MINTED" every time `finalizeGraduation` is invoked, since the inputs are frozen and identical on every retry. This is structurally the same class of bug as swift-nio-http2's ALTSVC/ORIGIN issue: a specific, unhandled input shape (frame type / amount magnitude) reaches a code path that unconditionally traps, and because the condition is deterministic, every retry reproduces the crash rather than recovering.

### Impact Explanation
Once `_enterGraduating` fires, `Bonding.buy`/`sell` are frozen (`TokenIsGraduating`) and the token can never return to `Lifecycle.Curve`. If `finalizeGraduation` then reverts deterministically on this pinned-amount edge case, the token is permanently stuck in `Lifecycle.Graduating`:
- All real LT raised by the curve (`ltFromPair`) sits unrecoverably inside `Bonding` (moved there by `Router.graduate` in `_prepareGraduationLiquidity`).
- The 250M `LP_RESERVE` tokens minted for LP seeding are similarly stranded.
- Traders holding the pre-graduation token can never sell (curve is frozen) and never trade post-graduation (pair never gets LP).
This is a permanent freezing of trader and protocol funds with no on-chain recovery path, satisfying the "Medium/High/Critical" and "permanent freezing" bar.

### Likelihood Explanation
This does not require a privileged caller — it is triggered purely by the natural economics of a high-`exchangeRate` LT crossing the USD graduation threshold while raw on-chain units remain tiny, or by an attacker choosing/promoting an LT with an extreme exchange rate for their launched token and steering the curve to graduate at the smallest possible raw LT delta. Both `_enterGraduating` (via a normal buy) and `finalizeGraduation` are reachable by any unprivileged address (`triggerGraduation` is explicitly permissionless).

### Recommendation
Add a minimum-raw-unit floor check in `_prepareGraduationLiquidity` (or before caching `pendingGraduation`) ensuring `tokensForLP` and `ltFromPair` are large enough to clear `MINIMUM_LIQUIDITY` under the V2 mint formula, and/or give `finalizeGraduation` a recoverable failure path (e.g., allow re-deriving amounts from a live buffer, or an owner-gated manual rescue) rather than an unconditional, permanently-reproducing revert.

### Proof of Concept
1. Launch a token paired against an LT whose `exchangeRate()` is set very high (e.g., such that 1 wei of LT is worth far more than `graduationThresholdUsd`).
2. Perform a buy sized so that `canGraduate` becomes true via the USD leg (`realLtRaised × exchangeRate / 1e18 ≥ graduationThresholdUsd`) while `ltFromPair` in raw wei terms is minimal (a few wei).
3. `_enterGraduating` fires, computing `tokensForLP = ltFromPair * tokenReserve / assetReserve`, also minimal.
4. Call `finalizeGraduation`; the HyperSwap pair's first-mint `sqrt(tokensForLP * ltFromPair) <= MINIMUM_LIQUIDITY` underflows, `pair.mint` reverts, and every subsequent call to `finalizeGraduation` reproduces the same revert deterministically since `pendingGraduation[token]` is immutable once cached — the token, its curve-raised LT, and its 250M reserved tokens are permanently stuck.

    function finalizeGraduation(
        address tokenAddress
    ) external nonReentrant {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[tokenAddress];
        if (info.lifecycle != Lifecycle.Graduating) revert NotGraduating();

        address lt = info.ltAddress;
        PendingGraduation memory p = $.pendingGraduation[tokenAddress];

        // Anything in this contract beyond `p.ltFromPair` belongs to a
        // concurrent graduation on the same LT (Phase 1 transferred it
        // via `Router.graduate`) or to stray dust. Either way it is
        // off-limits to this graduation's deposit and sweep — see
        // `_routerDepositAndDispose` and `_sweepLTToOwner`.
        // Saturating subtract: a balance below `p.ltFromPair` shouldn't
        // be reachable in normal operation, but we keep finalize from
        // bricking on a Panic if any future code path or non-canonical
        // LT briefly violates the invariant.
        uint256 ltBalance = IERC20(lt).balanceOf(address(this));
        uint256 protectedLT = ltBalance > p.ltFromPair ? ltBalance - p.ltFromPair : 0;

        address lpPair = _ensureUniswapV2Pair(tokenAddress, lt);
        uint256 liquidity = _seedUniswapV2Direct(tokenAddress, lt, lpPair, p.tokensForLP, p.ltFromPair, protectedLT);

        _sweepLTToOwner(lt, protectedLT);

        info.lifecycle = Lifecycle.Graduated;
        $.graduatedPair[tokenAddress] = lpPair;
        delete $.pendingGraduation[tokenAddress];

        LPLock($.lpLock).recordLock(tokenAddress, lpPair, liquidity);

        emit TokenGraduated(tokenAddress, lpPair, liquidity, p.tokensForLP, p.lpBurned, p.unsoldBurned);
    }

    function recordLock(
        address token,
        address lpPair,
        uint256 amount
    ) external {
        LPLockStorage storage $ = _s();
        if (!$.isLocker[msg.sender]) revert NotAuthorized();
        if (lpPair == address(0)) revert ZeroAddress();
        if (amount == 0) revert ZeroAmount();
        // `lockedAt` is the one-shot sentinel: it is always set to a non-zero
        // timestamp on the first lock, so the guard holds for any `amount`.
        if ($.locks[token].lockedAt != 0) revert AlreadyLocked();
        if (IERC20(lpPair).balanceOf(address(this)) < amount) revert InsufficientLPBalance();
        $.locks[token] = LockInfo({lpPair: lpPair, amount: amount, lockedAt: block.timestamp});
        emit LPLocked(token, lpPair, amount);
    }
