## Title
Missing invalidation of `_requestCommitments` after GET response delivery allows duplicate `onGetTimeout` dispatch for an already-resolved GET request - (File: evm/src/core/EvmHost.sol)

### Summary
`EvmHost.dispatchIncoming(GetResponse)` pays the relayer fee and completes GET-response delivery but never deletes `_requestCommitments[commitment]`, unlike the timeout-completion path (`dispatchTimeOut`) which does delete it. Because `HandlerV2.handleGetRequestTimeouts` only guards against a missing commitment (`meta.sender == address(0)`) and never checks the source chain's own `_responseReceipts` map, any permissionless relayer can later invoke `handleGetRequestTimeouts` for a GET request whose response has already been delivered, causing `onGetTimeout()` to be dispatched a second time on the destination module for the same request.

### Finding Description
In `EvmHost.dispatchIncoming(GetResponse, address relayer)`, the response receipt is stored *before* the `onGetResponse` external call (correct CEI for replay protection of the response itself), but the outstanding *request* bookkeeping (`_requestCommitments[commitment]`) that gates the timeout path is left untouched after successful completion: [1](#0-0) 

Compare this with the timeout-completion path, `dispatchTimeOut(GetRequestTimeout, ...)`, which does delete `_requestCommitments[commitment]` for replay protection of the timeout itself: [2](#0-1) 

The permissionless entry point `HandlerV2.handleGetRequestTimeouts` only requires that `_requestCommitments[commitment]` still exists (`meta.sender != address(0)`) and a non-membership proof for `RESPONSE_RECEIPTS_STORAGE_PREFIX` on the *destination* chain at the supplied historical height; it never consults the *source* chain's `_responseReceipts` to check whether a `GetResponse` has already been delivered locally: [3](#0-2) 

By contrast, the Substrate ISMP core (`modules/ismp/core/src/handlers/timeout.rs`) explicitly guards this exact race by checking the response receipt before dispatching a GET timeout: [4](#0-3) 

This is the same bug class as the reported kernel race: a completion handler (`nvmet_bio_done`/here `dispatchIncoming(GetResponse)`) finishes and hands control to a callback (`nvmet_req_complete`/here `onGetResponse`) without first fully retiring the shared bookkeeping object (`inline_bio`/here `_requestCommitments[commitment]`), leaving a stale but still-"live" record that a second, independent completion path (re-submission of the bio/here `dispatchTimeOut(GetRequestTimeout)`) can pick up and act on again.

### Impact Explanation
A GET request can be completed twice: once via `onGetResponse` (with real state data) and again via `onGetTimeout` (as if it failed), on the *same* commitment. Any `IApp` that relies on the "exactly-once" completion invariant of ISMP GET requests (e.g. refunding an escrow on timeout, or finalizing/canceling an order via `onGetResponse` as in `IntentsBase`/`ExtrinsicIntents`) can have its state corrupted or funds released twice — the module's `onGetTimeout` handler is invoked with no way to know a legitimate response has already been processed, since the module only sees the host-provided callback and trusts the host's exactly-once guarantee. This directly threatens fund safety/consensus of any app built with the assumption enforced by the Substrate side but missing on the EVM side. Given `handleGetRequestTimeouts` is permissionless, this is reachable from a single relayed message by any relayer.

### Likelihood Explanation
Exploitability requires only: (1) a `DispatchGet` with a timeout set, (2) a legitimately delivered `GetResponse` via `handleGetResponses` (note the EVM path explicitly skips timeout re-validation — `// don't check for timeouts because it's checked on Hyperbridge`), and (3) a subsequently-submitted, still-valid non-membership proof for the destination's `RESPONSE_RECEIPTS_STORAGE_PREFIX` key at some historical height prior to when the value was actually written on the destination (or any height whose challenge period allows submission). No privileged role is required — `handleGetRequestTimeouts` is permissionless — making this Medium-to-High likelihood whenever any app's escrow/state logic depends on single-completion semantics for GET requests.

### Recommendation
Delete `_requestCommitments[commitment]` in `dispatchIncoming(GetResponse)` immediately after the response bookkeeping is finalized (mirroring what `dispatchTimeOut` already does), and/or add an explicit check in `dispatchTimeOut(GetRequestTimeout, ...)` (and/or `HandlerV2.handleGetRequestTimeouts`) that `_responseReceipts[commitment]` is empty before allowing a timeout dispatch — matching the guard already present in the Substrate `pallet-ismp` timeout handler.

### Proof of Concept
1. App dispatches a `DispatchGet` with a non-zero `timeout`; `_requestCommitments[commitment]` is stored with `meta.sender`/`fee`.
2. Hyperbridge relayer delivers the corresponding `GetResponse` via `HandlerV2.handleGetResponses` → `EvmHost.dispatchIncoming(GetResponse, relayer)`. `onGetResponse` executes successfully on the destination app, relayer fee is paid, `_responseReceipts[commitment]` is set — but `_requestCommitments[commitment]` remains populated.
3. Any relayer later submits `HandlerV2.handleGetRequestTimeouts` with `message.timeouts` containing the same `GetRequest` and a valid non-membership proof (for `RESPONSE_RECEIPTS_STORAGE_PREFIX || commitment`) taken at a destination-chain height/timestamp that satisfies `request.timeout() <= state.timestamp` and predates when the destination actually recorded the response.
4. `host.dispatchTimeOut(GetRequestTimeout(...), meta, commitment)` is accepted because `_requestCommitments[commitment].sender != address(0)`; `onGetTimeout()` fires a second time on the same app/commitment that already received `onGetResponse`.

    /**
     * @dev Dispatch an incoming GET response to source module
     * @param response - get response
     */
    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    /**
     * @dev Check the provided Get request timeouts, then dispatch to modules
     * @param host - Ismp host
     * @param message - batch get request timeouts
     */
    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
