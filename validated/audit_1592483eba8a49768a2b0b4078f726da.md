### Title
Fraud/occlusion detection results are never enforced before signing and uploading the Personal Custody Package - ([File: src/plans/mod.rs])

### Summary
`Plan::detect_fraud` in `src/plans/mod.rs` is a stub that unconditionally returns `Ok(false)` regardless of the actual biometric pipeline output, and occlusion agent failures (`occlusion::Output::Error`) are stored in `Pipeline.occlusion` but never checked by `detect_fraud` or `build_pcp` before constructing and signing the custody package. This allows a signup whose occlusion/fraud signals indicate a failed or fraudulent capture to still be tagged `SignupReason::Normal` and reach `personal_custody_package::Plan::run`, producing a cryptographically valid, uploaded custody package.

### Finding Description
The signup flow in `src/plans/mod.rs` computes `fraud_detected` from `self.detect_fraud(orb, debug_report, pipeline.as_ref())`, whose body is: [1](#0-0) 
This stub only returns `Ok(false)` unless `pipeline` itself is `None` (i.e. the whole biometric pipeline errored). It never inspects `pipeline.occlusion` or `pipeline.face_identifier_fraud_checks`.

`signup_reason` is derived directly from `fraud_detected` and whether `pipeline` is `Some`: [2](#0-1) 
Since `detect_fraud` always yields `false` when `pipeline` is `Some(..)`, any signup that successfully completes the biometric pipeline is unconditionally tagged `SignupReason::Normal`, no matter what the individual model outputs say.

Critically, the biometric pipeline itself treats `occlusion::Output::Error` as non-fatal — it is stored as `Err(error)` in the `occlusion` field but does not abort the pipeline (unlike `iris::Output::Error`, which does `return Err(Error::Iris(error))?`): [3](#0-2) 
The final `Pipeline` struct is then built successfully with `occlusion: occlusion.unwrap()` (an `Err` variant is a valid, successfully-unwrapped value here, not a panic): [4](#0-3) 

Downstream, `build_pcp` only validates `face_identifier_bundle` (image/embeddings presence and its own `error` field) and iris normalized images before constructing the package; it never inspects `pipeline.occlusion`: [5](#0-4) 
If `face_identifier_fraud_checks`/`face_identifier_bundle` also errors, `build_pcp` does catch that specific case via the bundle check, but occlusion errors (and any positive-fraud values that a face_identifier check might report through `FraudChecks`, whose only real field visible in this build is `error: Option<PyError>`) are silently ignored.

`personal_custody_package::Plan::run` then proceeds to build and sign the package using only `signup_id`, `signup_reason`, `orb_id`, `operator_id`, `timestamp`, and `qr_code` for the hash/commitment inputs — none of which encode the true occlusion/fraud verdict: [6](#0-5) 

The net effect: an attacker whose presentation attack causes the occlusion model to error out (or otherwise produces a non-fatal `Err` in a pipeline stage that isn't independently gated by `build_pcp`) still receives `SignupReason::Normal` and a fully signed, uploaded custody package, because the only real gate (`detect_fraud`) is disabled in this build (marked `// FOSS: WE HAVE DELETED ALL FRAUD CHECKS`), and no other code path uses `pipeline.occlusion` to block enrollment.

### Impact Explanation
This allows a fraudulent/presentation-attack signup to be recorded as `SignupReason::Normal` and to produce a valid signed Personal Custody Package (Hyrax commitment + hashes) that is uploaded to the backend. This corresponds to a liveness/fraud-bypass and attestation-integrity issue: the on-Orb attestation no longer reflects the true qualification/fraud verdict of the biometric pipeline, undermining the guarantee that a committed PCP represents a genuine, non-fraudulent capture.

### Likelihood Explanation
No privileged access is required. Any unprivileged user going through a normal signup with a scene/input that causes the occlusion (or other non-fatal) python-agent stage to error — while still producing a valid face_identifier bundle — will trigger this path deterministically, since `detect_fraud` is unconditionally stubbed to `false` for every signup with `Some(pipeline)`. This is fully repeatable and does not depend on timing, race conditions, or hardware tampering.

### Recommendation
Restore real fraud/occlusion checks in `detect_fraud`, and additionally have `build_pcp`/`biometric_pipeline::Plan::run` treat `occlusion::Output::Error` (and any other qualification-stage error) as blocking, not merely informational: either propagate it as a pipeline error, or check `pipeline.occlusion.is_err()` / relevant fraud signals in `detect_fraud`/`build_pcp` before proceeding to `personal_custody_package::Plan::run`. Bind the actual pass/fail verdict of each qualification stage (occlusion, face-identifier fraud checks) into the signed commitment inputs so downstream verification can detect tampering.

### Proof of Concept
Integration test plan:
1. Construct a `biometric_pipeline::Pipeline` via `Pipeline::default_with_ok()` but override `occlusion` to `Err(PyError { message: "forced error".into() })` (or drive the real `Plan::run` with a mocked `occlusion::Output::Error` message).
2. Call `Plan::detect_fraud(orb, debug_report, Some(&pipeline))` and assert it currently returns `Ok(false)` — demonstrating no gate exists.
3. Drive the full `Plan` signup handler (or directly `build_pcp` + `personal_custody_package::Plan::run`) with this pipeline and a `face_identifier_bundle` that is `Ok`, and assert (as the fix) that no `PersonalCustodyPackages` is produced / `signup_reason` is not `Normal` when `pipeline.occlusion.is_err()`.
4. Expected assertion after remediation: `build_pcp` returns `Ok(None)` (or `detect_fraud` returns `Ok(true)`) whenever `pipeline.occlusion` or `pipeline.face_identifier_fraud_checks` indicates an error/fraud signal, preventing `personal_custody_package::Plan::run` from being reached with `SignupReason::Normal`.
