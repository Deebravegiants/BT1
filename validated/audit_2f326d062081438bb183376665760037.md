### Title
Emporium relay-fee payment lets an unbound `feeStructure.feeToken`/`relay` drain a signer's `HinkalWallet` in an unauthorised token - (File: `contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol`)

### Summary
The Emporium/HinkalWallet flow lets a wallet owner (`stack.signerAddress`) authorise a batch of operations off-chain via an EIP-712 signature (`EMPORIUM_SIGNATURE_TYPEHASH`) and cap the relay fee with `stack.maxFee`. However, the signed hash never binds *which token* the fee is paid in, nor *who* receives it. Whoever assembles the surrounding `CircomData` (the party submitting `transact`) freely picks `feeStructure.feeToken`, `circomData.erc20TokenAddresses`, and `circomData.relay`, and `payRelayFees` will unconditionally pull up to `maxFee` units of that arbitrary token from the signer's `HinkalWallet` to that arbitrary relay address.

### Finding Description

It only binds `emporiumMessage`, the hashed `ops`, `maxFee`, and `deadline` — it never includes `circomData.feeStructure.feeToken`, `circomData.erc20TokenAddresses`, or `circomData.relay`.

The fee cap check only constrains the raw numeric fee, not the token: [2](#0-1) 

`payRelayFees` has a fallback branch that fires whenever `feeStructure.feeToken` is not one of the `erc20TokenAddresses` touched by the batch (`foundToken == false`), and it pays the flat fee unconditionally in `feeStructure.feeToken` to `circomData.relay`, sourced from the signer's wallet: [3](#0-2) 
This routes through `sendToRelayFromWallet` → `HinkalWallet.doSendToRelay`, which performs the actual ERC20 transfer with attacker-chosen `erc20TokenAddress`: [4](#0-3) [5](#0-4) [6](#0-5) 

This is the same class of bug as H-14: a value-bearing field (here `feeStructure.feeToken` / `circomData.relay`, analogous to the mismatched `srcToken`) is *acted upon to move real assets* but is *not part of the equality the authorizing signer actually committed to* (the EIP-712 hash). Just as H-14 let the wrong token identity be used to match/settle a cross-chain debt, here the wrong token identity can be substituted to settle a "fee" — draining whatever token the wallet actually holds, to whatever relay address the assembler of `circomData` chooses, capped only by a token-agnostic numeric `maxFee`.

### Impact Explanation
An attacker who obtains any still-valid, unused `EmporiumStack` signature (e.g. by observing it in the mempool/relay pipeline before the intended submission lands, or reusing a signature intended for a different pairing of `erc20TokenAddresses`) can wrap it in their own `CircomData`/`transact` call (using their own ZK proof over their own shielded UTXOs, since `emporiumMessage`/`calldataHash` binding is orthogonal to the wallet's fee-token binding) and set:
- `feeStructure.feeToken` = the most valuable ERC20 the victim's `HinkalWallet` holds,
- `feeStructure.flatFee` = `stack.maxFee`,
- `circomData.relay` = attacker's own address.

`payRelayFees`'s fallback branch will then transfer `maxFee` units of that token from the victim's wallet to the attacker's relay address — funds the wallet owner never intended to spend in that token, to a recipient they never authorised. This is direct, unauthorised theft of a wallet owner's assets, matching the "High/Critical: moving assets a wallet owner or prover never authorised" impact category.

### Likelihood Explanation
Exploitation only requires observing/obtaining a valid (v, r, s) `EmporiumStack` signature with a nonzero `maxFee` before its associated `emporiumMessage` nonce is consumed, and submitting a competing `transact()` call with attacker-chosen `CircomData` fields — no admin, relay-operator, or protocol privilege is needed, and no assumption about a malicious relayer operator is required (the attacker acts as an ordinary unprivileged transaction submitter exploiting the missing binding).

### Recommendation
Include `feeStructure.feeToken`, `circomData.relay`, and ideally the full `circomData.erc20TokenAddresses` set in the `EMPORIUM_SIGNATURE_TYPEHASH` payload that `stack.signerAddress` signs, so the signer's authorization equality covers exactly which token and recipient the fee can be paid to, not just a numeric cap.

### Proof of Concept
1. Victim's `HinkalWallet` holds token `X` (valuable) and signs an `EmporiumStack` (e.g., a harmless op) with `maxFee = M`, intending fees to be paid in some other token `Y` that is part of their normal `erc20TokenAddresses`.
2. Attacker intercepts the signed `(ops, v, r, s, maxFee, deadline, signerAddress)` payload before it is included on-chain.
3. Attacker calls `Hinkal.transact` with their own valid ZK proof/UTXOs, setting `circomData.erc20TokenAddresses` to exclude token `Y` (so `foundToken` is false in `payRelayFees`), `circomData.feeStructure.feeToken = X`, `circomData.feeStructure.flatFee = M`, and `circomData.relay = attacker`.
4. `EmporiumUpgradeable.runAction` → `verifyWallet` accepts the signature (none of the substituted fields are covered by it) → `payRelayFees`'s `!foundToken` branch fires → `payRelay` → `sendToRelayFromWallet` → `HinkalWallet.doSendToRelay` transfers `M` units of token `X` from the victim wallet to the attacker's `relay` address.     function payRelayFees(
```text
        CircomData calldata circomData,
        address signerAddress,
        int256[] calldata deltaAmountChanges
    ) internal {
        FeeStructure calldata feeStructure = circomData.feeStructure;

        bool foundToken = false;

        for (uint256 i = 0; i < circomData.erc20TokenAddresses.length; i++) {
            // tokens deposited into Emporium are not charged
            if (deltaAmountChanges[i] >= 0) {
                continue;
            }

            address erc20TokenAddress = circomData.erc20TokenAddresses[i];
            bool isFeeToken = erc20TokenAddress == feeStructure.feeToken;

            if (isFeeToken) {
                foundToken = true;
            }

            uint256 relayFee = 0;
            uint256 flatFee = isFeeToken ? feeStructure.flatFee : 0;

            if (signerAddress == address(0)) {
                uint256 sumAbs = uint256(-deltaAmountChanges[i]);

                EmporiumStorageVars storage $ = _getEmporiumStorage();
                relayFee = $._hinkalHelper.calculateRelayFee(
                    sumAbs,
                    flatFee,
                    feeStructure.variableRate
                );
            } else {
                relayFee = flatFee;
            }

            payRelay(
                circomData.relay,
                signerAddress,
                relayFee,
                erc20TokenAddress
            );
        }

        if (!foundToken && feeStructure.flatFee != 0) {
            require(
                signerAddress != address(0),
                "Gas Token in Emporium is not found"
            );

            payRelay(
                circomData.relay,
                signerAddress,
                feeStructure.flatFee,
                feeStructure.feeToken
            );
        }
```
