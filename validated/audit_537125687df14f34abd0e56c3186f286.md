### Title
Stale delegate grant regains account-control privileges after an NFT round-trip - (File: contracts/controller/src/storage/account.rs)

### Summary
A `DelegateGrant` is keyed only by `account_id` and stamped with the granting owner's address, with no NFT-transfer epoch or explicit reauthorization after ownership returns to that owner. After the position NFT leaves and returns to the original owner without an intervening delegate write, a formerly inactive delegate becomes authorized again and can invoke owner-or-delegate operations such as `withdraw` or `borrow`. [1](#0-0) [2](#0-1) 

### Finding Description
`is_owner_or_delegate` authorizes a non-owner whenever that caller is an active position manager and appears in `get_delegates` for the current NFT owner. [3](#0-2)  `get_delegates` loads `ControllerKey::Delegates(account_id)` and accepts the stored list whenever `grant.granted_by == owner`; it does not check when the grant was created or whether the NFT changed hands after creation. [2](#0-1) 

An NFT transfer therefore makes the previous owner's grant dormant but leaves it in persistent storage. [2](#0-1)  If the NFT later returns to that same owner, the old `granted_by` value matches the live owner again, so the stale list is read as active. The new holder can prevent this only by explicitly purging or overwriting the stale grant through `remove_delegate` or `add_delegate`; absent that write, the previous grant remains stored. [4](#0-3) 

The reachable path is:

1. Alice owns account `A` and calls `add_delegate(caller=alice, account_id=A, delegate=mallory)`, where Mallory is an already-active position manager. The stored grant is `{ granted_by: alice, delegates: [mallory] }`. [5](#0-4) 
2. Alice calls the position NFT's `transfer(from=alice, to=bob, token_id=A)`. Under Bob, `grant.granted_by == alice` no longer matches the current owner, so Mallory is inactive. [2](#0-1) 
3. Bob transfers token `A` back to Alice without calling `remove_delegate`. Bob's view of delegates is empty, and no transfer hook deletes Alice's old grant. [6](#0-5) 
4. Mallory calls an owner-or-delegate endpoint, for example `withdraw(caller=mallory, account_id=A, withdrawals=[...], to=Some(mallory))`. `require_owner_or_delegate` resolves Alice as the current NFT owner and finds Mallory in Alice's resurrected grant. [3](#0-2) 

This mirrors the report's incorrect privilege assignment pattern: authorization depends on the current owner identity, while a stale grant created under a previous ownership session is treated as if it still belongs to that session.

### Impact Explanation
The revived delegate can withdraw available collateral to a chosen recipient, borrow against the account to a chosen recipient, or execute other owner-or-delegate strategies without fresh authorization from the owner after the NFT returns. [3](#0-2) [7](#0-6)  This permits theft of the account's withdrawable collateral and borrowed assets, while the debt remains attached to the victim's account.

### Likelihood Explanation
The attack requires a prior delegate grant, the delegate remaining an active registered position manager, and the NFT leaving and later returning to the same owner without that owner or an intervening owner clearing the grant. NFT sales, marketplace settlement reversals, custody transfers, and account migrations can produce that round-trip. The grant is not reauthorized or visibly active under the intervening owner, so the revival can be unexpected when the NFT returns. [8](#0-7) 

### Recommendation
Make delegation grants ownership-session scoped. Store a last-observed NFT owner or transfer epoch in controller account state, clear `ControllerKey::Delegates(account_id)` whenever a newly observed owner differs from the stored one, or expose and persist an NFT transfer counter that is included in the grant validation. A grant should become permanently inactive on any ownership change and require the current owner to grant it again.

    to: bob,
    token_id: A,

// Mallory is inactive because granted_by == alice while owner == bob.

position_nft.transfer(
    from: bob,
    to: alice,
    token_id: A,

// Bob made no add_delegate/remove_delegate write, so the old entry remains.

controller.withdraw(
    caller: mallory,
    account_id: A,
    withdrawals: [(collateral_hub_asset, amount)],
    to: Some(mallory),
);
// owner == alice again, grant.granted_by == alice, and Mallory is listed.
// The owner-or-delegate check passes without Alice reauthorizing Mallory.

/// Returns grants stamped by `owner`, or an empty list. Ownership changes
/// invalidate a previous owner's grants without deleting them.
pub(crate) fn get_delegates(env: &Env, account_id: u64, owner: &Address) -> Vec<Address> {
    get_user::<DelegateGrant>(env, &ControllerKey::Delegates(account_id))
        .filter(|grant| grant.granted_by == *owner)
        .map(|grant| grant.delegates)
        .unwrap_or_else(|| Vec::new(env))
}

/// Stores delegates stamped by the granting owner and renews user TTL;
/// deletes the entry when the list is empty.
fn set_delegates(env: &Env, account_id: u64, owner: &Address, delegates: &Vec<Address>) {
    let key = ControllerKey::Delegates(account_id);
    if delegates.is_empty() {
        env.storage().persistent().remove(&key);
    } else {
        set_user(
            env,
            &key,
            &DelegateGrant {
                granted_by: owner.clone(),
                delegates: delegates.clone(),
            },
        );
    }
}

/// Adds a delegate, enforcing `MAX_DELEGATES`; returns false for duplicates.
/// Overwrites stale grants with a list stamped by the current owner.
pub(crate) fn add_delegate(
    env: &Env,
    account_id: u64,
    owner: &Address,
    delegate: &Address,
) -> bool {
    let mut delegates = get_delegates(env, account_id, owner);
    if delegates.contains(delegate) {
        return false;
    }
    assert_with_error!(
        env,
        delegates.len() < MAX_DELEGATES,
        GenericError::RegistryCapReached
    );
    delegates.push_back(delegate.clone());
    set_delegates(env, account_id, owner, &delegates);
    true
}

/// Accepts the owner or a registered, active manager delegated by that owner.
pub(crate) fn is_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) -> bool {
    if caller == owner {
        return true;
    }
    let active_manager =
        storage::get_position_manager(env, caller).is_some_and(|config| config.is_active);
    active_manager && storage::get_delegates(env, account_id, owner).contains(caller)
}

/// Requires the owner or a registered, active manager delegated by that owner.
pub(crate) fn require_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) {
    if is_owner_or_delegate(env, account_id, caller, owner) {
        return;

An account delegate also needs active global position-manager registration.
Its grant is stamped with the granting owner's address, not a transfer epoch:
it becomes inactive while someone else holds the NFT and can revive if the
NFT returns before an intervening owner updates delegates. Owner revocation
is immediate; global deactivation takes effect when governance executes it.
Delegates can borrow/withdraw to their chosen recipient within account gates.
Those gates do not constrain them to acting in the owner's economic interest.
