**Analysis:**

The claimed divergence is real at the code level but does not constitute an exploitable custody boundary crossing.

In `SchedulerWrapper::add_to_post_commit`, V1 calls `Scheduler::add_to_commit_queue` and unconditionally returns `Ok(())`, while V2 calls `SchedulerV2::end_commit`, which returns a `Result<(), PanicError>` [1](#0-0) .

However, `Scheduler::add_to_commit_queue` itself cannot silently fail — it uses `.expect("Pushing to the commit_queue should never fail")`, which causes a hard Rust panic (thread abort) if the bounded queue push fails, rather than a swallowed error [2](#0-1) . The queue is sized exactly to `num_txns` and each index is pushed at most once, so this failure mode is not reachable through any unprivileged transaction, package, or bytecode input — it would only occur due to an internal scheduler invariant violation (a pre-existing engineering bug), not something an attacker can trigger via transaction content.

Separately, the actual balance-mutating work (materializing committed output, e.g. `materialize_txn_commit`, and writing to `FungibleStore` balances) is driven by popping from the commit/post-commit queue and does not depend on the `Ok(())`/`Result` value returned by `add_to_post_commit` itself [3](#0-2) . The `Result` returned by `add_to_post_commit` in the caller (`txn_last_input_output.rs`) is propagated with `?` before any output is taken for post-processing, and a panic in either V1 (via `.expect()`) or V2 (via propagated `PanicError`) halts execution/falls back rather than allowing a partial write to be treated as committed [4](#0-3) .

There is no unprivileged entrypoint (transaction, package publish, view function, authenticator, API, or proof input) that can force this internal scheduler-queue failure condition, and even if it were forced, the V1 path panics rather than silently proceeding. No FA balance or ownership state is written or finalized based on the `Result`/`Ok(())` divergence described. This does not meet the custody-impact gate — it requires speculative internal invariant violations unreachable from unprivileged input, and produces no change in balance, ownership, or authority state.
