## Finding: Stale `TombStone` Survives Ordinary Object Transfers, Allowing a Prior Owner to Hijack a Burned Object from Its Current Owner

### Title
Unauthorized Object Ownership Reassignment via Stale `TombStone` on Plain Transfer Path - (File: `aptos-move/framework/aptos-framework/sources/object.move`)

### Summary
`aptos_framework::object` implements a "soft burn" mechanism: `burn()` attaches a `TombStone{original_owner}` resource to an object without changing its `owner` field, and `unburn()` lets the address recorded in `TombStone` reclaim the object once its current owner is `BURN_ADDRESS`. The `TransferRef`-based transfer path (`transfer_with_ref`) explicitly clears any stale `TombStone` before reassigning ownership, but the plain signer-based transfer path (`transfer`, `transfer_call`, `transfer_to_object`, all backed by `transfer_raw`/`transfer_raw_inner`) does **not**. This asymmetry lets a former owner who soft-burned an object *before* transferring it away later reclaim it from the burn address after the legitimate new owner intentionally destroys it — stealing the object (and any value/custody it represents, e.g. a `FungibleStore`, token, or code object) from the rightful current owner.

### Finding Description
Relevant code: [1](#0-0) 

`burn()` only asserts current ownership and attaches `TombStone{original_owner}`; it does not touch `owner` or `allow_ungated_transfer`: [2](#0-1) 

`unburn()` trusts the `TombStone.original_owner` field once the object's current owner is `BURN_ADDRESS`, and transfers the object back to that recorded address: [3](#0-2) 

The `TransferRef`-mediated transfer path is aware of this risk and explicitly removes any existing `TombStone` before reassigning ownership, with a comment confirming the intent ("we don't want the original owner to be able to reclaim by calling unburn later"): [4](#0-3) 

However, the ordinary signer-based transfer path used by `transfer`, `transfer_call`, and `transfer_to_object` goes through `transfer_raw` → `transfer_raw_inner`, which only checks `allow_ungated_transfer`/ownership and flips the `owner` field — it never inspects or clears `TombStone`: [5](#0-4) 

Because `burn()` does not disable `allow_ungated_transfer` or otherwise mark the object non-transferable, an object can be soft-burned by owner A and then transferred normally to owner B while the stale `TombStone{original_owner: A}` persists untouched.

### Impact Explanation
This breaks the object custody invariant that ownership control (including recovery/reclaim rights) must track the *current* legitimate owner, not a resource-state artifact left behind by a previous owner. Concretely:

1. A owns object `O` (which may wrap/hold a `FungibleStore`, an NFT/token object, or serve as a code object's controlling object).
2. A calls `object::burn(A, O)` — `TombStone{original_owner: A}` is attached; `O.owner` stays `A`.
3. A transfers `O` to B through the normal path (sale, marketplace, direct transfer) via `object::transfer`/`transfer_call`/`transfer_to_object`. Ownership moves to B; the stale `TombStone` is **not** cleared.
4. B, the new legitimate owner, later performs what the module documents as the standard destroy convention — transferring the object to the well-known `BURN_ADDRESS` constant via a plain `transfer` (B cannot use `burn()` again since `TombStone` already exists and would abort with `EOBJECT_ALREADY_BURNT`).
5. A calls `unburn(A, O)`. Since `O.owner == BURN_ADDRESS` and `TombStone.original_owner == A`, the assertion in `unburn` passes and `transfer_raw_inner` reassigns `O.owner` back to A.

A — who no longer has any claim to `O` — recovers an object that B legitimately owned and intentionally destroyed. Since `Object<T>` is a generic ownership primitive used to gate custody of fungible asset stores, token/NFT objects, and code objects, this is a direct unauthorized owner-reassignment / theft-of-recovery-rights bug with mainnet-relevant, asset-custody impact.

### Likelihood Explanation
The preconditions are fully within an unprivileged attacker's control: any account can call `object::burn` on an object it owns, then transfer that object away through completely ordinary, permissionless paths (marketplace sale, plain `transfer`), and the victim's own routine "burn by sending to `BURN_ADDRESS`" action (a pattern the module itself documents via the `BURN_ADDRESS` constant) is what triggers the exploit. No governance, admin, or privileged signer is required — only a two-step setup by the attacker followed by ordinary usage by the victim.

### Recommendation
Clear any existing `TombStone` on the object inside `transfer_raw_inner` (or at minimum in `transfer_raw`), mirroring the defensive logic already present in `transfer_with_ref`, so that ownership changes through any path invalidate stale burn-recovery claims:

```move
inline fun transfer_raw_inner(object: address, to: address) {
    if (exists<TombStone>(object)) {
        let TombStone { original_owner: _ } = move_from<TombStone>(object);
    };
    let object_core = borrow_global_mut<ObjectCore>(object);
    ...
}
```
Alternatively, `unburn`'s `BURN_ADDRESS` branch could additionally verify that no ownership transfer has intervened since the tombstone was created (e.g., by also comparing against the owner recorded at burn time versus the tombstone's most recent legitimate holder), but clearing the tombstone on every ownership change is the simplest fix consistent with the intent already expressed in `transfer_with_ref`.

### Proof of Concept
```move
// Assume Object<T> O initially owned by A, allow_ungated_transfer = true (default)

// Step 1: A soft-burns the object (owner stays A)
object::burn(&a_signer, o);
// TombStone{original_owner: A} now attached; O.owner == A

// Step 2: A sells/transfers O to B through a normal path
object::transfer(&a_signer, o, address_of(&b_signer));
// O.owner == B; TombStone{original_owner: A} is NOT cleared (transfer_raw_inner never touches it)

// Step 3: B, believing the object clean, destroys it via the documented burn address
object::transfer(&b_signer, o, object::burn_address()); // or equivalent literal BURN_ADDRESS
// O.owner == BURN_ADDRESS

// Step 4: A reclaims the object that B destroyed
object::unburn(&a_signer, o);
// object_core.owner == BURN_ADDRESS matches; TombStone.original_owner == A matches signer
// => transfer_raw_inner(object_addr, A) executes
// O.owner is now A again -- A has stolen back an object B legitimately owned and burned.
```

    /// Transfer to the destination address using a LinearTransferRef.
    public fun transfer_with_ref(self: LinearTransferRef, to: address) {
        assert!(!exists<Untransferable>(self.self), error::permission_denied(EOBJECT_NOT_TRANSFERRABLE));

        // Undo soft burn if present as we don't want the original owner to be able to reclaim by calling unburn later.
        if (exists<TombStone>(self.self)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(self.self);
        };

        let object = borrow_global_mut<ObjectCore>(self.self);
        assert!(
            object.owner == self.owner,
            error::permission_denied(ENOT_OBJECT_OWNER),
        );
        event::emit(
            Transfer {
                object: self.self,
                from: object.owner,
                to,
            },
        );
        object.owner = to;
    }

        object: address,

    inline fun transfer_raw_inner(object: address, to: address) {
        let object_core = borrow_global_mut<ObjectCore>(object);
        if (object_core.owner != to) {
            event::emit(
                Transfer {
                    object,
                    from: object_core.owner,
                    to,
                },
            );
            object_core.owner = to;
        };
    }

    /// Add a TombStone to the object.  The object will then be interpreted as hidden via indexers.
    /// This only works for objects directly owned and for simplicity does not apply to indirectly owned objects.
    /// Original owners can reclaim burnt objects any time in the future by calling unburn.
    /// Please use the test only [`object::burn_object_with_transfer`] for testing with previously burned objects.
    public entry fun burn<T: key>(owner: &signer, object: Object<T>) {
        let original_owner = signer::address_of(owner);
        assert!(is_owner(object, original_owner), error::permission_denied(ENOT_OBJECT_OWNER));
        let object_addr = object.inner;
        assert!(!exists<TombStone>(object_addr), EOBJECT_ALREADY_BURNT);
        move_to(&create_signer(object_addr), TombStone { original_owner });
    }

    /// Allow origin owners to reclaim any objects they previous burnt.
    public entry fun unburn<T: key>(
        original_owner: &signer,
        object: Object<T>,
    ) {
        let object_addr = object.inner;
        assert!(exists<TombStone>(object_addr), error::invalid_argument(EOBJECT_NOT_BURNT));

        // The new owner of the object can always unburn it, but if it's the burn address, we go to the old functionality
        let object_core = borrow_global<ObjectCore>(object_addr);
        if (object_core.owner == signer::address_of(original_owner)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object_addr);
        } else if (object_core.owner == BURN_ADDRESS) {
            // The old functionality
            let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
            assert!(
                original_owner_addr == signer::address_of(original_owner),
                error::permission_denied(ENOT_OBJECT_OWNER)
            );
            transfer_raw_inner(object_addr, original_owner_addr);
        } else {
            abort error::permission_denied(ENOT_OBJECT_OWNER);
        };
    }
