### Title
Unauthenticated "magic" operator QR codes let any unprivileged user trigger Orb-wide Wi-Fi and mirror-calibration resets - (File: `src/plans/mod.rs`)

### Summary
The external report's root cause is that a privileged/state-mutating action (`removeFeeder()`) executed based on a caller-supplied argument without checking that the *caller* is authorized — the function had a modifier that only validated the *target* existed, not that the *caller* held the admin role. The orb-core equivalent is `MasterPlan::handle_magic_operator_qr_code()`, which executes privileged device-reset actions triggered purely by scanned QR-code content, and is invoked **before** the operator-authorization step (`verify_operator_qr_code`) that would normally validate the scanned code against the backend.

### Finding Description
`qr_scan::operator::Data::try_parse` recognizes two "magic" QR payloads independent of normal operator QR-code parsing: `magic_action:reset_wifi_credentials` and `magic_action:reset_mirror_calibration` [1](#0-0) .

In both `scan_initial_qr_codes` and `scan_remaining_qr_codes`, the scanned operator QR code is passed to `handle_magic_operator_qr_code()` *before* `verify_operator_qr_code()` is called — and if the magic branch matches, the function returns `None` and the loop `continue`s or breaks without ever reaching the backend verification step [2](#0-1) [3](#0-2) .

`handle_magic_operator_qr_code()` itself performs no authentication or authorization check on the presenter of the QR code — it unconditionally executes `reset_mirror_calibration()` or `reset_wifi_and_ensure_network()` as soon as the regex matches the scanned text [4](#0-3) .

`reset_wifi_and_ensure_network()` calls `network::reset()`, which restores the default `wpa_supplicant.conf` and forces a reconfigure, disconnecting the Orb from its currently configured Wi-Fi network, followed by `wifi::Plan.ensure_network_connection(orb)` which re-triggers the network setup flow [5](#0-4) [6](#0-5) . `reset_mirror_calibration()` overwrites the stored calibration file and forces the Orb to recalibrate its mirror [7](#0-6) .

This is the same bug class as the reference finding: a function whose docstring/design intent implies it is operator/admin-gated (`removeFeeder`'s comment says "Allows owner to remove feeder") actually performs the privileged mutation without checking the identity of the caller — only checking the state of the target. Here, "operator QR-code scanning" is the trust boundary that is supposed to gate privileged device actions, but the magic-action branch bypasses the one authorization step (`verify_operator_qr_code`, an authenticated backend call) that distinguishes a legitimate operator from an arbitrary person holding up a piece of paper/screen to the Orb's camera.

### Impact Explanation
Any person able to present a QR code to the Orb's camera — not necessarily an authenticated operator — can force the Orb to disconnect from its configured Wi-Fi network and/or reset its mirror calibration, at will and repeatedly, during the idle/QR-scanning phase of every signup attempt. Analogous to the reference bug (removing feeders to indefinitely stall liquidations), this allows an unauthorized party to repeatedly disrupt Orb availability (denial of service against signups, forced re-provisioning of Wi-Fi, forced mirror recalibration cycles) without any operator credential, simply by re-showing the magic QR code, and the legitimate operator has no way to prevent it short of physically preventing QR presentation.

### Likelihood Explanation
High. The magic QR codes are plain, static, publicly-known strings (test file even documents them: `magic_action:reset_wifi_credentials`, `magic_action:reset_mirror_calibration`) requiring no cryptographic material, secret token, or backend round-trip to trigger, and the scanning loop actively listens for operator QR codes during idle and pre-signup phases [8](#0-7) .

### Recommendation
Move the magic-action handling to occur only after `verify_operator_qr_code()` (or an equivalent authenticated check) succeeds, so that only a backend-validated, legitimate operator identity can trigger `reset_wifi_and_ensure_network()` or `reset_mirror_calibration()`. Alternatively, require the magic action to be embedded within/signed alongside an already-verified operator QR code payload rather than being a standalone unauthenticated regex match.

### Proof of Concept
1. Power on the Orb and wait for it to enter the operator QR-code scanning phase (`scan_initial_qr_codes` / `scan_remaining_qr_codes`).
2. Present a QR code containing the literal text `magic_action:reset_wifi_credentials` to the Orb's camera.
3. `qr_scan::operator::Data::try_parse` matches `MAGIC_QR_CODE` and returns `Data::MagicResetWifi` without any backend call.
4. `handle_magic_operator_qr_code()` is invoked before `verify_operator_qr_code()`, executing `reset_wifi_and_ensure_network()`, which resets and disconnects the Orb's Wi-Fi — no operator authentication is performed at any point in this path.
5. Repeat with `magic_action:reset_mirror_calibration` to force a mirror recalibration cycle, again without authorization.

    async fn handle_magic_operator_qr_code(
        &self,
        orb: &mut Orb,
        qr_code: qr_scan::operator::Data,
    ) -> Result<Option<qr_scan::user::Data>> {
        match qr_code {
            qr_scan::operator::Data::Normal(qr_code) => {
                tracing::info!("Operator QR-code detected: {qr_code:?}");
                Ok(Some(qr_code))
            }
            qr_scan::operator::Data::MagicResetMirror => {
                tracing::info!("Magic QR-code detected: Reset Mirror");
                dd_incr!("main.count.signup.during.general.magic_qr.reset_mirror");
                let result = self.reset_mirror_calibration(orb).await;
                if let Err(err) = &result {
                    tracing::error!("Failed to reset mirror calibration: {err}");
                }
                orb.ui.magic_qr_action_completed(result.is_ok());
                Ok(None)
            }
            qr_scan::operator::Data::MagicResetWifi => {
                tracing::info!("Magic QR-code detected: Reset Wi-Fi");
                dd_incr!("main.count.signup.during.general.magic_qr.reset_wifi");
                let result = self.reset_wifi_and_ensure_network(orb).await;
                if let Err(err) = &result {
                    tracing::error!("Failed to reset wifi: {err}");
                }
                orb.ui.magic_qr_action_completed(result.is_ok());
                Ok(None)
            }
        }
    }

/// Restores the default wpa_supplicant.conf configuration file.
/// Then forces wpa_supplicant to re-read its configuration file,
/// thus disconnecting from the current network.
pub async fn reset() -> Result<()> {
    spawn_blocking(move || {
        Command::new(WPA_SUPPLICANT_INTERFACE_BIN)
            .arg("restore-default-config")
            .status()
            .wrap_err("running `wpa-supplicant-interface`")?
            .success()
            .then_some(())
            .ok_or_else(|| eyre!("`wpa-supplicant-interface` terminated unsuccessfully"))?;

        Command::new(WPA_SUPPLICANT_INTERFACE_BIN)
            .arg("reconfigure")
            .status()
            .wrap_err("running `wpa-supplicant-interface`")?
            .success()
            .then_some(())
            .ok_or_else(|| eyre!("`wpa-supplicant-interface` terminated unsuccessfully"))
    })
    .await?
}
