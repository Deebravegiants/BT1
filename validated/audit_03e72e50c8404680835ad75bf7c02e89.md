### Title
`repay_debt_with_collateral` with `close_position` reverts whenever settlement leaves residual debt, permanently blocking atomic position close — (File: contracts/controller/src/strategies/repay_debt_with_collateral.rs)

### Summary
The Tokemak bug class — a strict equality between an expected debt decrease and an actually-received amount that is reduced by fees/slippage — exists in `process_repay_debt_with_collateral`. Every leg of the flow settles with *measured* receipts (`balance_delta_since`, measured swap output, `net_settle`'s conservative overlap), yet the `close_position` flag then requires `account.borrow_positions.is_empty()`. Any shortfall of even 1 unit between the requested/quoted debt and the measured repayable amount leaves residual scaled debt and reverts the whole call with `CollateralError::CannotCloseWithRemainingDebt`, rolling back the collateral withdrawal. An unprivileged user calling `repay_debt_with_collateral(..., close_position = true)` hits this deterministically on two independent paths.

### Finding Description
`process_repay_debt_with_collateral` (contracts/controller/src/strategies/repay_debt_with_collateral.rs:30) supports two repay paths, both of which can leave dust debt:

1. **Same-market netting** (`collateral == debt`): `net_settle_collateral_against_debt` (contracts/controller/src/strategies/legs.rs:165-229) delegates to the pool's `net_settle`, which per the pool README settles `min(requested, floor(supply), ceil(debt))` and explicitly *"closes the supply and leaves one unit of debt"* when `ceil(debt)` is one unit above `floor(supply)`. Directed rounding can also "move one share at the token boundary". So even with `collateral_amount` equal to the full supply, a residual debt leg can remain.

2. **Cross-market swap**: `withdraw_and_swap_from_supply` (legs.rs:233-259) withdraws collateral to the controller, swaps only the *measured* receipt, and `repay_debt_from_controller` (legs.rs:40-81) repays only the measured swap output. Any swap fee, slippage, or fee-on-transfer haircut on the collateral withdrawal means the repaid amount is strictly less than the debt — the same shape as the Tokemak `info.debtDecrease` vs received shortfall. The pool `withdraw` leg also reports `actual_amount = gross` while transferring `gross − fee` (contracts/pool/src/ops/withdraw.rs:28-29).

Then, at lines 81-89:

```rust
if close_position {
    assert_with_error!(
        env,
        account.borrow_positions.is_empty(),
        CollateralError::CannotCloseWithRemainingDebt
    );
    execute_withdraw_all(env, &mut account, caller, &mut cache, collateral);
}
```

Any leftover scaled debt position — even a single raw unit created by `ceil(debt)` rounding or a 1-stroop swap shortfall — reverts the entire transaction after the collateral has already been burned from the supply position (all within one atomic call, so the revert also cancels the intended collateral release).

### Impact Explanation
A user attempting to fully deleverage and exit — repay all debt from collateral and withdraw remaining collateral atomically via `repay_debt_with_collateral` with `close_position = true` — finds the call reverts whenever the measured settlement is below the full debt. Because swap fees/slippage and `net_settle`'s floor-vs-ceil asymmetry make a shortfall the *normal* outcome when the caller sizes `collateral_amount` to exactly cover the debt (the natural way to build this call, since the debt accrues interest up to execution), the close path fails in precisely the cases it is used for. This is temporary freezing of funds: the collateral cannot be released via the intended atomic path and the position cannot be closed, matching the Medium severity of the source report (funds remain recoverable only by submitting different, non-closing transactions and leaving residual debt behind, or by over-paying collateral).

### Likelihood Explanation
High under normal use: any nonzero swap fee, venue slippage, or the documented `net_settle` one-unit residual triggers the assert. The caller is unprivileged (`require_owner_or_delegate`), needs only an account with collateral and debt, and the revert depends solely on in-protocol rounding/fee mechanics, not on oracle honesty or MEV. The user can work around it only by keeping `close_position = false` (leaving the position open with dust debt) or oversizing the collateral leg — i.e., the advertised close-and-exit flow is unreliable.

### Recommendation
Make `close_position` tolerant of residual dust rather than requiring a literally empty `borrow_positions` map. Options:

- After repayment, treat debt positions whose scaled amount unscale to zero asset units (below the market's dust/`clean_bad_debt` threshold) as closed, pruning them before the `is_empty` check — consistent with the protocol's existing dust-threshold cleanup semantics.
- Or, when `close_position` is set, attempt a final `net_settle`/`repay` top-up from the just-withdrawn collateral proceeds (the code already withdraws remaining collateral to `caller` via `execute_withdraw_all`), and refund the difference through `refund_controller_balance_delta`.
- At minimum, use the measured pool mutation (`PoolPositionMutation.position.scaled_amount == 0`) rather than map emptiness, so positions reduced to an unscales-to-zero remainder do not block the close.

### Proof of Concept
Conceptual trace (same-market variant, fully deterministic — no swap or oracle dependence):

1. User supplies `S` units of token T in hub H and borrows `B` units of T in the same market, such that after interest accrual `ceil(debt_value) = floor(supply_value) + 1` (attainable: borrow almost the full supply, let one accrual chunk push debt one unit above — e.g., supply 1000.0000000 T, debt 1000.0000001 T equivalent).
2. User calls `controller.repay_debt_with_collateral(caller, account_id, collateral = (H,T), collateral_amount = S_full, debt = (H,T), swap = empty, close_position = true)`.
3. `net_settle_collateral_against_debt` settles `min(S_full, floor(supply), ceil(debt)) = floor(supply)`; per `contracts/pool/README.md` the settle "closes the supply and leaves one unit of debt" — `account.borrow_positions` still contains a positive scaled debt entry for `(H,T)`.
4. The `close_position` block at repay_debt_with_collateral.rs:81-86 asserts `borrow_positions.is_empty()` → reverts with `CannotCloseWithRemainingDebt`. The withdraw-all of the user's collateral never executes; the position (and its remaining collateral allowance) stays locked.

Cross-market variant: supply token A, debt token B, request `collateral_amount` quoted to exactly cover the debt via `swap_debt`-style routing; the router's measured output (`swap_tokens` returns `balance_delta_since`, contracts/controller/src/strategies/swap.rs:75-84) is necessarily ≤ the quoted amount, so the repaid measured amount leaves residual debt and the same assert reverts.

Note: I could not fully verify whether `strategy_finalize` or LTV-refresh logic already prunes zero-value scaled debt legs before the `is_empty` check; if it does, the residual-debt condition depends on whether a 1-unit debt survives pruning. The rounding-dust argument above is based on the pool README's documented `net_settle` behavior.
