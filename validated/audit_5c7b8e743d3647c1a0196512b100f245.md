### Title
Insolvent liquidation seizes all collateral when repayment falls up to one unit per debt leg short of the collateral-backed quote — oversized "seize_all" window - (File: contracts/controller/src/positions/liquidation/math.rs)

### Summary
The ruzstd bug class — an internal length computed slightly too large so the copy overshoots its boundary — maps onto XOXNO Lending's `seize_all` margin in `normalize_repayment_plan`. On an insolvent account the liquidation plan sets `seize_all = repay_usd + one_unit_per_leg_usd >= ideal_repayment_usd`, where `ideal_repayment_usd` is the collateral-backed quote `floor(C / (1 + base))` and the slack `one_unit_per_leg_usd` is the sum of the USD value of **one whole base unit of every repaid debt leg**. When `seize_all` is set, `calculate_seized_collateral` replaces the pro-rata capped seizure with `capped_ray = actual_ray` — the *entire* held balance of every collateral leg — even though the liquidator paid up to `R` USD less than what that collateral backs at the base bonus. The debt legs' per-unit value is determined by token decimals and oracle price, not by anything the liquidation bounds, so `R` can be arbitrarily large relative to the shortfall. ### Finding Description
In `normalize_repayment_plan` (`contracts/controller/src/positions/liquidation/math.rs:209-212`):

```rust
let seize_all = insolvent
    && repay_usd > Wad::ZERO
    && repay_usd.checked_add(env, one_unit_per_leg_usd(env, &final_repayment_tokens))
        >= ideal_repayment_usd;
```

`one_unit_per_leg_usd` (math.rs:331-339) adds `Wad::from_token(env, 1, entry.feed.asset_decimals) * price_wad` for **each repayment leg** — i.e., the USD value of one indivisible base unit of each *debt* token. This value has no relation to the collateral being seized; it is a rounding-justified slack that treats "within one unit per leg of the quote" as "reached the quote".

Then in `calculate_seized_collateral` (math.rs:423-427):

```rust
let capped_ray = if repayment.seize_all {
    actual_ray
} else {
    seizure_ray.min(actual_ray)
};
```

the cap that normally limits seizure to `repay_usd * (1 + bonus)` pro-rata is dropped entirely and every collateral leg is taken whole. The documented intent (docs/reference/formulas.md:272-275) is "an insolvent account's repayment *reaches* the collateral-backed quote: that call seizes every unit" — but the code triggers seizure of everything while still up to `R` short of the quote. `R` is unbounded by the protocol: for a debt token with 2 decimals trading at $60,000 (a WBTC-like listing), one unit is $600; across the allowed multiple borrow positions, the sum of one unit per leg can reach tens of thousands of dollars. Nothing in listing couples a debt asset's unit value to this margin.

Execution then pulls only the planned (short) repayment (`apply_liquidation_repayments`, mod.rs:68-75), the leftover unpaid debt stays on the account with zero collateral, and `check_bad_debt_after_liquidation` (mod.rs:135) socializes it via supply-index write-down — so the shortfall lands on suppliers, not the liquidator.

### Impact Explanation
Theft of user funds and protocol insolvency. A liquidator pays `quote − R` and receives **all** collateral legs at their full `actual_ray`, gaining `~R * (1 + bonus)` USD more than the repayment backs; the borrower's collateral is over-seized, and the residual unpaid debt is written off against the market's supply index, harming all suppliers in that market. Both legs of the loss are real token value; no privileged role or external price manipulation is required — only an insolvent account whose debt legs are denominated in low-decimal, high-price assets.

### Likelihood Explanation
Requires: (a) a listed debt market whose single base unit has meaningful USD value (low `asset_decimals`, high price — precisely the expensive-unit configuration the docs already flag for the solvent whole-unit rule), ideally several such debt legs on one account to amplify `R`; (b) an insolvent account with `C < D`, which occurs naturally on price moves or can be constructed by the attacker on their own account and self-liquidated (`INV-LIQ-01` allows self-liquidation). The attacker then submits a `liquidate` call whose offered repayment equals `floor(C/(1+base)) − R + ε`, which the plan accepts, seizes every collateral unit, and socializes the remainder. No oracle dishonesty, reentrancy, or timing race is needed — the margin is in the planner itself.

### Recommendation
Bound the `seize_all` slack by the actual unit-rounding error of the *repayment recording* rather than one full priced unit per leg — i.e., replace `one_unit_per_leg_usd` with the sub-unit remainder each leg's ceiling-rounding could legitimately contribute (strictly less than one base unit's USD value, and only for legs whose recorded amount was ceiling-rounded), or require `repay_usd >= ideal_repayment_usd` exactly. Alternatively, cap the seized total in `calculate_seized_collateral` at `min(actual_ray, ceil(seizure_ray))` so the "seize every unit" path cannot take collateral worth more than one indivisible collateral unit above the backed quote.

```rust
/// Sums the WAD USD value of one native unit of each repayment leg.
fn one_unit_per_leg_usd(env: &Env, repaid_tokens: &Vec<RepayEntry>) -> Wad {
    let mut total = Wad::ZERO;
    for entry in repaid_tokens.iter() {
        let unit = Wad::from_token(env, 1, entry.feed.asset_decimals)
            .mul(env, Wad::from(entry.feed.price_wad));
        total = total.checked_add(env, unit);
    }
    total
}
```
