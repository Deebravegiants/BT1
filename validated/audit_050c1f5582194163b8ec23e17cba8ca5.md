### Title
Occlusion detection result (`EstimateOutput.occlusion` from `mask`/`glasses` model) is computed but never enforced before enrollment - ([File: src/plans/biometric_pipeline/mod.rs], [File: src/plans/mod.rs])

### Finding Description
The RGB-based occlusion detector in `src/agents/python/occlusion.rs` produces a boolean `occlusion` field (plus `eye_glasses_occlusion`/`face_mask_occlusion`) derived from `eye_glasses_probability`/`face_mask_probability` model scores [1](#0-0) . `biometric_pipeline::Plan::run` collects this into `Pipeline.occlusion: Result<occlusion::EstimateOutput, PyError>` [2](#0-1)  and simply propagates it, without ever comparing the boolean (or the underlying probabilities) against any threshold.

Downstream in `src/plans/mod.rs`, `biometric_pipeline()` only logs the occlusion result and records the error (if any) into the debug report: `debug_report.occlusion_error(pipeline.occlusion.clone().err()); tracing::info!("Occlusion Detection result: {:?}", pipeline.occlusion);` [3](#0-2) . The `pipeline.occlusion` value is never read again to gate the signup.

The fraud/policy gate that would normally consume this signal, `detect_fraud`, is explicitly gutted: `// FOSS: WE HAVE DELETED ALL FRAUD CHECKS` followed by `Ok(false)` unconditionally [4](#0-3) . `enroll_user()` is then called with `signup_reason` derived only from whether the pipeline itself errored, never from occlusion content [5](#0-4) , and `enroll_user.rs` contains no reference to occlusion at all (confirmed via search).

The only occlusion-related enforcement that exists anywhere in the Rust code is in `biometric_capture::Plan::update_occlusion`, which applies hysteresis to `ir_net::EstimateOutput.occlusion_30` (an IR-based center-LED reflection metric, unrelated to the RGB `occlusion.rs` glasses/mask classifier) to gate which individual IR frames are accepted as candidate captures [6](#0-5) . This only affects frame selection during capture, not the RGB face-image occlusion signal computed later in the pipeline, and it does not block the pipeline or enrollment stage from proceeding.

### Impact Explanation
Because `Pipeline.occlusion` is fully decoupled from any enforcement in `enroll_user` or `detect_fraud`, wearing glasses/a mask (at any probability, not just borderline) does not, by itself, block signup completion at the Orb-side. The signal is only ever logged and forwarded to the backend as part of the uploaded `codes` payload (`format_pipeline`, used in `signup_post::request`), meaning any occlusion enforcement is entirely dependent on backend-side logic outside this repository. Within this repo's authorization path, an occluded/degraded face is treated as compliant for local processing and proceeds through `enroll_user` to backend polling.

### Likelihood Explanation
This requires no privileged access — an attacker only needs to wear glasses or a mask during their own signup session and let the standard flow run; the "FOSS: WE HAVE DELETED ALL FRAUD CHECKS" comment shows this is a deliberate, always-on code path in this build (not a rare edge case), making it fully repeatable.

### Recommendation
Enforce `Pipeline.occlusion` (and specifically `eye_glasses_occlusion`/`face_mask_occlusion`) as a hard gate in `detect_fraud`/`enroll_user`, failing closed (treating errors or `occlusion == true` as blocking) rather than relying solely on backend-side verification that cannot be confirmed from this codebase.

### Proof of Concept
Unit test in `src/plans/mod.rs` (or a new test module): construct a `biometric_pipeline::Pipeline` via `Pipeline::default_with_ok()` but override `occlusion` to `Ok(occlusion::EstimateOutput { occlusion: true, eye_glasses_probability: 0.99, eye_glasses_occlusion: true, .. })`, then call `detect_fraud(orb, debug_report, Some(&pipeline))` and assert it currently always returns `Ok(false)` regardless of the occlusion content — demonstrating the missing enforcement. A property test could sweep `eye_glasses_probability`/`face_mask_probability` from 0.0 to 1.0 and confirm `detect_fraud`'s output is invariant to `pipeline.occlusion`, proving occlusion never influences the fraud decision returned to `signup_reason`/`enroll_user`.

    fn update_occlusion(&mut self, orb: &mut Orb, estimate: &EstimateOutput) {
        let dt = self.occlusion_center_led_timer.get_dt().unwrap_or(0.0);
        let EstimateOutput { mut occlusion_30, sharpness, .. } = *estimate;
        if occlusion_30.is_nan() || sharpness.is_nan() || sharpness < IRIS_SHARPNESS_MIN {
            occlusion_30 = THRESHOLD_OCCLUSION_30 * 1.05;
        }
        let occlusion_30_low_pass =
            self.occlusion_30_filter.add(occlusion_30, dt, OCCLUSION_CENTER_LED_LOW_PASS_FILTER_RC);
        // Apply hysteresis and a minimum pulse time.
        let occlusion_detected =
            if let Some(occlusion_indicator_on_time) = self.occlusion_indicator_on_time {
                occlusion_30_low_pass < THRESHOLD_OCCLUSION_30 * 1.025
                    || occlusion_indicator_on_time.elapsed() < OCCLUSION_INDICATOR_MIN_TIME_INTERVAL
            } else {
                occlusion_30_low_pass < THRESHOLD_OCCLUSION_30 * 0.975
            };
        if occlusion_detected {
            self.occlusion_indicator_on_time.get_or_insert_with(Instant::now);
            orb.ui.biometric_capture_occlusion(true);
        } else {
            orb.ui.biometric_capture_occlusion(false);
            self.occlusion_indicator_on_time = None;
        }
    }
