Audit Report

## Title
User Enumeration via Distinct Authentication Error Messages - ([File: core/web/sessions_controller.go])

## Summary
`SessionsController.Create` forwards the raw error returned by `AuthenticationProvider().CreateSession()` directly to the unauthenticated HTTP client via `jsonAPIError(c, http.StatusUnauthorized, err)`. Because the local, LDAP, and OIDC authenticators return distinguishable errors depending on whether the email exists versus whether the password is wrong, an unauthenticated caller can enumerate valid Chainlink node user accounts by inspecting the response body.

## Finding Description
`SessionsController.Create` calls `sc.App.AuthenticationProvider().CreateSession(ctx, sr)` and on error passes it verbatim to the client: [1](#0-0) 

`jsonAPIError` places `err.Error()` directly into the JSON response body with no redaction or generic-message substitution: [2](#0-1) 

In `localauth.orm.CreateSession`, the flow is: `FindUser` (a SQL lookup by lowercased email) runs first; if no row matches, the underlying `sql.ErrNoRows` (or similar driver error) is returned unmodified to the caller. If a user row is found, the code proceeds to a `constantTimeEmailCompare` check (largely redundant since the SQL query already filters by email) and then `CheckPasswordHash`, returning distinct errors `"Invalid email"` vs `"Invalid password"`: [3](#0-2) 

The `ldapauth` and `oidcauth` local-login fallbacks follow the identical pattern — a direct SQL lookup by email that returns the driver error verbatim if not found, then explicit `"invalid email"` vs `"invalid password"` errors once a row is found: [4](#0-3) [5](#0-4) 

Whether the exact wording for the "email not found" branch is a driver-level "no rows" error or the literal `"Invalid email"`/`"invalid email"` string, the observable fact remains: the response body content is different and deterministic depending on whether the submitted email corresponds to an existing account versus an existing account with a wrong password. No middleware, redaction layer, or generic-error normalization exists between the authenticator and `jsonAPIError` to mask this distinction. The `constantTimeEmailCompare` naming suggests an intent to mitigate timing/response leakage, but it does not address the message-content leakage this endpoint produces.

## Impact Explanation
This maps to an in-scope Chainlink node API weakness: information disclosure that assists authentication bypass/brute-force efforts against the Operator UI/API (`/sessions`). It does not directly grant unauthorized access but allows an unauthenticated attacker to confirm valid operator/admin email addresses, materially reducing the search space for credential-stuffing or brute-force attacks and leaking organizational information about provisioned accounts.

## Likelihood Explanation
`/sessions` is an unauthenticated, unprivileged, network-reachable endpoint by design (it is the login endpoint). Every request deterministically returns a distinguishable error message/body for "email not found" versus "wrong password," making the enumeration trivially automatable with no rate-limiting or generic-response mitigation observed in this code path.

## Recommendation
In `SessionsController.Create`, replace the propagated authenticator error with a single generic message (e.g., `"invalid credentials"`) for all `CreateSession` failures, logging the specific reason only server-side/audit log. Apply the same normalization inside `localauth.orm.CreateSession`, `ldapauth.localLoginFallback`, and `oidcauth.localLoginFallback` so that both "user not found" and "wrong password" paths return identical error values, preventing message-content-based account enumeration.

## Proof of Concept
1. `POST /sessions` with `{"email":"nonexistent@test.net","password":"anything"}` — HTTP 401 with a response body containing either a SQL "no rows" error or `"Invalid email"`/`"invalid email"` depending on the auth path, propagated via `jsonAPIError(c, http.StatusUnauthorized, err)`.
2. `POST /sessions` with `{"email":"<valid_admin_email>","password":"wrongpassword"}` — HTTP 401 with response body `"Invalid password"`/`"invalid password"`.
3. Comparing the two response bodies distinguishes valid from invalid emails, confirming enumeration. This can be verified with a Go integration test against `SessionsController.Create` asserting distinct response bodies for the two cases, extending the existing table-driven test at `core/web/sessions_controller_test.go` (lines 33-41) to assert on response body content rather than only `wantSession`.

```go
// jsonAPIError adds an error to the gin context and sets
// the JSON value of errors.
func jsonAPIError(c *gin.Context, statusCode int, err error) {
	_ = c.Error(err).SetType(gin.ErrorTypePublic)
	var jsonErr *models.JSONAPIErrors
	if errors.As(err, &jsonErr) {
		c.JSON(statusCode, jsonErr)
		return
	}
	c.JSON(statusCode, models.NewJSONAPIErrorsWith(err.Error()))
}
```

```go
func (o *orm) CreateSession(ctx context.Context, sr sessions.SessionRequest) (string, error) {
	user, err := o.FindUser(ctx, sr.Email)
	if err != nil {
		return "", err
	}
	lggr := o.lggr.With("user", user.Email)
	lggr.Debugw("Found user")

	// Do email and password check first to prevent extra database look up
	// for MFA tokens leaking if an account has MFA tokens or not.
	if !constantTimeEmailCompare(strings.ToLower(sr.Email), strings.ToLower(user.Email)) {
		o.auditLogger.Audit(audit.AuthLoginFailedEmail, map[string]any{"email": sr.Email})
		return "", pkgerrors.New("Invalid email")
	}

	if !utils.CheckPasswordHash(sr.Password, string(user.HashedPassword)) {
		o.auditLogger.Audit(audit.AuthLoginFailedPassword, map[string]any{"email": sr.Email})
		return "", pkgerrors.New("Invalid password")
	}
```

```go
func (l *ldapAuthenticator) localLoginFallback(ctx context.Context, sr sessions.SessionRequest) (sessions.User, error) {
	var user sessions.User
	sql := "SELECT * FROM users WHERE lower(email) = lower($1)"
	err := l.ds.GetContext(ctx, &user, sql, sr.Email)
	if err != nil {
		return user, err
	}
	if !constantTimeEmailCompare(strings.ToLower(sr.Email), strings.ToLower(user.Email)) {
		l.auditLogger.Audit(audit.AuthLoginFailedEmail, map[string]any{"email": sr.Email})
		return user, errors.New("invalid email")
	}

	if !utils.CheckPasswordHash(sr.Password, string(user.HashedPassword)) {
		l.auditLogger.Audit(audit.AuthLoginFailedPassword, map[string]any{"email": sr.Email})
		return user, errors.New("invalid password")
	}

	return user, nil
}
```
