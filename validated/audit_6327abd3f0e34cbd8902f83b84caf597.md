### Title
Fundamental/NAV-priced collateral (USTRY) ignores market depeg, letting attackers borrow against overvalued tokens - (File: contracts/price-aggregator/src/engine.rs)

### Summary
The USSD report's bug class is "a bridged/wrapped asset is priced by its underlying asset's feed, so a market depeg is invisible to the oracle." XOXNO Lending has the same shape: markets like USTRY are priced by a `Scaled` source (Reflector NAV factor × USD quote, bounded by `min_factor_wad`/`max_factor_wad` = 0.9844–1.1556 WAD) cross-checked against a RedStone feed of `nature: "Fundamental"` [1](#0-0) . Both legs report fundamental/NAV value, not the token's secondary-market price. If USTRY's issuer/bridge is impaired and the token trades at a steep discount, both oracle legs continue to agree within the 5% tolerance band and inside the sanity band, so the aggregator returns the stale NAV price and the controller values collateral at par.

### Finding Description
`Outcome::failure` in `contracts/price-aggregator/src/engine.rs:126-148` only rejects a price when it is stale, deviating between the two legs, non-positive, or outside `min_sanity_price_wad`/`max_sanity_price_wad` [2](#0-1) . For USTRY, leg 1 is `Scaled{ factor: Reflector TWAP of the fund NAV, quote: Token(USDC) }` clamped only by the factor bounds, and leg 2 is `Feed{ RedStone "USTRY", nature: Fundamental }` [3](#0-2) . Neither source reads the token's actual traded price on Aquarius/Soroswap, so no on-chain component can detect a market depeg — the same structural defect as `StableOracleWBTC` reading BTC/USD. The deviation check `within_tolerance_band` only compares the two configured legs to each other, so two honest NAV sources that both ignore the depeg pass trivially [4](#0-3) .

### Impact Explanation
Protocol insolvency. An unprivileged attacker buys depegged USTRY on the open market for far below NAV, calls `controller.supply` to post it as collateral, and calls `controller.borrow` to draw borrowable assets (USDC, XLM, etc.) sized against the inflated NAV valuation. When the position is later liquidated or bad-debt-cleaned via `clean_bad_debt`/`recapitalize`, the pool absorbs the shortfall: seized collateral is worth less than the debt written down, permanently impairing suppliers' claims. This is exactly the USSD mint-then-dump path mapped onto supply-then-borrow.

### Likelihood Explanation
Requires an actual depeg of a fundamentally-priced collateral asset (issuer default, custody/bridge failure, redemption halt) — a tail event, but the precise scenario the NAV/factor bounds cannot observe. The attack itself is a single unprivileged account performing ordinary `supply`/`borrow` calls; no privileged access, oracle manipulation, or timing is needed. Note: whether USTRY is configured as collateral-eligible with nonzero LTV in the live spoke listings was not fully verified from the indexed config; the analog is strongest for any listed collateral asset priced via `Scaled`-factor or `Fundamental` feeds.

### Recommendation
Add a market-price leg for depeggable collateral: pair the NAV/fundamental source with an on-chain liquidity source (e.g., an Aquarius pool TWAP/fair-value source of the token itself) and require agreement within tolerance, or apply a strict-price haircut when the market leg deviates downward beyond a threshold — mirroring the report's dual-oracle recommendation. Failing that, treat `Fundamental`-nature feeds as non-collateral-grade for assets whose redemption can be impaired.

### Proof of Concept
1. USTRY's issuer is impaired; market price falls to 0.50 USDC while NAV feeds still report ~1.00.
2. Attacker buys USTRY cheaply, transfers to wallet, calls `controller.supply(spoke, USTRY, amount)`.
3. Aggregator `resolve` returns ~1.00 WAD: scaled factor is inside [0.9844, 1.1556], both legs within the 10,500 bps ratio, inside the sanity band — `failure()` returns `None` [2](#0-1) .
4. Attacker calls `controller.borrow` drawing stablecoins up to the LTV-weighted (inflated) collateral value, then abandons the position.
5. Liquidation seizes USTRY worth ~50% of the debt; residual is written down via `clean_bad_debt`/supply-index write-down, socializing the loss to suppliers.

pub(crate) fn within_tolerance_band(
    env: &Env,
    anchor: i128,
    primary: i128,
    tolerance: &OracleTolerance,
) -> bool {
    let high = anchor.max(primary);
    let low = anchor.min(primary);
    let Some(upper_ratio_bps) = fp_core::try_mul_div_half_up(env, high, BPS, low) else {
        return false;
    };

    upper_ratio_bps <= i128::from(tolerance.upper_ratio_bps)
}
