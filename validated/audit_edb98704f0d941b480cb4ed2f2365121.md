### Title
Interest accrual overflows before the borrow-index cap and permanently freezes a whale market - (File: common/src/rates/simulate.rs)

### Summary
`accrue_step` unscales total debt through `scaled_to_original` before updating `borrow_index`, and `Ray::mul` panics when the resulting fixed-point value exceeds `i128::MAX`. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
Every pool mutation first calls `synced_market`, which invokes `global_sync`; `global_sync` then calls `accrue_step` for each elapsed compounding chunk. [4](#0-3) [5](#0-4)  `accrue_step` computes `borrowed * borrow_index` before `update_borrow_index` can clamp the next index to `MAX_BORROW_INDEX_RAY`. [1](#0-0) [6](#0-5)  The repository’s regression test demonstrates that a roughly billion-token market at sustained 98% utilization reaches the raw-value overflow while `borrow_index` is still below `MAX_BORROW_INDEX_RAY`, after which `update_indexes`, `withdraw`, and `repay` all revert with `MathOverflow`. [7](#0-6) 

The unprivileged path is `controller.update_indexes(caller, assets)` with the target `HubAssetKey`, followed by the same failure on user `withdraw`, `repay`, `borrow`, `liquidate`, `flash_loan`, `flash_position`, `multiply`, `swap_debt`, `swap_collateral`, `repay_debt_with_collateral`, `recapitalize`, or `claim_revenue` paths that touch the market. [8](#0-7) [9](#0-8) [4](#0-3) 

### Impact Explanation
Once `borrowed * borrow_index` exceeds `i128::MAX`, the market cannot be accrued, so repayments, withdrawals, liquidations, index updates, revenue claims, recapitalization, and further market mutations all trap before reaching their business logic. [4](#0-3) [5](#0-4) [10](#0-9)  This permanently freezes all supplier and borrower funds in that `(hub, asset)` market unless governance can upgrade or reconfigure around the state. [7](#0-6) 

### Likelihood Explanation
An unprivileged liquidity supplier and borrower can create the prerequisite market state through normal `supply` and `borrow` calls if the configured spoke caps permit an extremely large position; thereafter, only elapsed time and a permissionless `update_indexes` call are needed to trigger the overflow. [11](#0-10) [9](#0-8)  The proof test uses an 18-decimal billion-token asset and a steep but accepted 175% APR curve, and it shows the overflow occurs before the intended borrow-index ceiling engages. [12](#0-11) [13](#0-12) 

### Recommendation
Compute utilization and accrued interest through saturating or quotient-first math that cannot overflow before the index cap is applied, and cap `borrow_index` before deriving `old_total_debt`, `supplier_rewards`, and supply-index deltas. [14](#0-13) [15](#0-14)  Add a regression boundary where `borrowed * borrow_index` would exceed `i128::MAX`, then verify `update_indexes`, `withdraw`, `repay`, and liquidation remain functional after the index reaches `MAX_BORROW_INDEX_RAY`. [13](#0-12) 

### Proof of Concept
1. Configure a borrowable 18-decimal market with the stress curve `max_borrow_rate = 1.75 RAY`, `optimal_utilization = 0.75 RAY`, `max_utilization = RAY`, and `reserve_factor = 2000`. [12](#0-11) 
2. Supply `1_000_000_000 * 10^18` base units and borrow `98%` of that amount under collateral that passes the controller’s risk checks. [16](#0-15) 
3. Advance ledger time while repeatedly calling `controller.update_indexes(caller, [hub_asset])`. [11](#0-10) [17](#0-16) 
4. The accrual eventually fails with `MathOverflow` while the stored `borrow_index` remains below `MAX_BORROW_INDEX_RAY`. [18](#0-17) 
5. Subsequent `withdraw` and `repay` calls fail with the same `MathOverflow`, confirming the market-wide freeze. [19](#0-18)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();

/// Applies `interest_factor` to `old_index` to produce the new borrow index,
/// capped at `MAX_BORROW_INDEX_RAY`.
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
