### Title
Missing minimum collateral output lets a liquidation repay debt for zero collateral - ([File: contracts/controller/src/positions/liquidation/mod.rs](contracts/controller/src/positions/liquidation/mod.rs))

### Summary
`liquidate` has no caller-specified minimum collateral or acceptable exchange-rate parameter. An account can remain liquidatable while holding no collateral, and the execution path accepts a positive debt repayment with an empty seizure list.

### Finding Description
The public entrypoint accepts only `liquidator`, `account_id`, `debt_payments`, and `seize_mode`; it provides no `min_collateral`, `min_seized`, or equivalent slippage bound. [1](#0-0) 

When the target has zero-valued collateral, `calculate_seized_collateral` returns an empty seizure vector and zero unbacked repayment, so the plan retains the requested repayment instead of releasing it. [2](#0-1) 

Execution then measures and transfers the liquidator's debt tokens to the pool and applies the debt repayment before iterating over the empty seizure list. [3](#0-2)  Transfer-mode seizure application performs no payout when `seized` is empty. [4](#0-3) 

### Impact Explanation
A liquidator can permanently lose debt tokens while receiving no collateral. This can happen after signed transaction ordering changes: an earlier liquidation removes the account's remaining collateral but leaves debt outstanding, after which the later liquidation still satisfies the `health_factor < 1 WAD` gate and repays debt for an empty seizure list. [5](#0-4) 

### Likelihood Explanation
An insolvent account with residual debt and no collateral is a normal terminal state because insolvent liquidation can seize all collateral while retaining unpaid debt. [6](#0-5)  Any permissionless liquidator can reach the vulnerable path by calling `liquidate` with a positive payment for that remaining debt and `SeizeMode::Transfer`. [7](#0-6) 

### Recommendation
Add a caller-controlled minimum acceptable collateral output to `liquidate`, ideally a `Vec<(HubAssetKey, i128)>` of minimum net collateral legs or a minimum collateral USD value. Revert after seizure scaling and fee calculation if the measured liquidator payout is below that bound.

### Proof of Concept
1. An account supplies collateral and borrows another asset.
2. The collateral price falls until the account's health factor is below `1 WAD`.
3. A first liquidation uses the insolvency path and seizes all collateral while leaving part of the debt unpaid.
4. A second caller submits:
   `liquidate(liquidator, account_id, [(debt_asset, positive_amount)], SeizeMode::Transfer)`.
5. The plan still passes the health-factor check, computes an empty `seized` list because total collateral is zero, transfers `positive_amount` of debt tokens to the pool, reduces the borrower's debt, and performs no collateral transfer to the liquidator. [8](#0-7)

```rust
pub(crate) fn apply_liquidation_seizures(
    env: &Env,
    liquidator: &Address,
    account: &mut Account,
    seized: &Vec<SeizeEntry>,
    cache: &mut Context,
) {
    let mut entries: Vec<PoolWithdrawEntry> = Vec::new(env);
    for entry in seized.iter() {
        enforce_spoke_asset_flags(
            env,
            cache,
            account.spoke_id,
            &entry.hub_asset,
            FreezePolicy::SeizureLeg,
        );

        let position: AccountPosition =
            (&expect_invariant(env, account.supply_positions.get(entry.hub_asset.clone()))).into();
        entries.push_back(PoolWithdrawEntry {
            action: make_pool_action(&position, entry.amount, entry.hub_asset),
            protocol_fee: entry.protocol_fee,
        });
    }
    apply_withdraw_batch(
        env,
        account,
        liquidator,
        WithdrawKind::Liquidation,
        events::PositionAction::LiqSeize,
        &entries,
        cache,
    );
```
