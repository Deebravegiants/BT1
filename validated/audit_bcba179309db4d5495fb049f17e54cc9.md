### Title
Fraud detection is unconditionally bypassed for any completed biometric pipeline, forcing `SignupReason::Normal` regardless of fraud signals - ([File: src/plans/fraud_check.rs] and [File: src/plans/mod.rs])

### Summary
`Report::fraud_checks()` in `src/plans/fraud_check.rs` always returns an empty array (`N_FRAUD_CHECKS = 0`) with the comment "FOSS: WE HAVE DELETED ALL FRAUD CHECKS", and `MasterPlan::detect_fraud` in `src/plans/mod.rs` explicitly hardcodes `Ok(false)` whenever the biometric pipeline produced `Some(_)`. This means any signup that completes the biometric pipeline stage is unconditionally classified as non-fraudulent, regardless of any fraud-indicative signal present in the pipeline output.

### Finding Description
In `do_signup` (`src/plans/mod.rs:562-571`), the pipeline result feeds into fraud detection and the signup reason:
```
let pipeline = Box::pin(self.biometric_pipeline(orb, debug_report, &capture)).await?;
let fraud_detected = !self.skip_fraud_checks()
    && self.detect_fraud(orb, debug_report, pipeline.as_ref()).await?;
let signup_reason = if pipeline.is_none() {
    SignupReason::Failure
} else if fraud_detected {
    SignupReason::Fraud
} else {
    SignupReason::Normal
};
```
`detect_fraud` (`src/plans/mod.rs:1392-1406`) is:
```
async fn detect_fraud(...) -> Result<bool> {
    orb.set_phase("Fraud detection").await;
    let Some(_pipeline) = pipeline else {
        return Ok(false);
    };
    // FOSS: WE HAVE DELETED ALL FRAUD CHECKS
    Ok(false)
}
```
The `_pipeline` binding is discarded (underscore prefix) — no field of the `biometric_pipeline::Pipeline` (e.g. `face_identifier_fraud_checks`, `occlusion`) is inspected at all. This corroborates `src/plans/fraud_check.rs:64-134`, where `Report::fraud_checks()` returns `[]`, so `fraud_checks_strict()`, `fraud_detected()`, and `fraud_detected_with_config()` are all structurally incapable of returning `true`, and `FraudChecks::run` (`src/plans/fraud_check.rs:150-152`) simply returns an empty `Report {}` without evaluating `_pipeline` at all. This `fraud_check.rs` machinery is not even wired into `detect_fraud` in `mod.rs` — the latter shortcuts straight to `Ok(false)`.

Consequently, once `biometric_pipeline` returns `Some(pipeline)` (`src/plans/mod.rs:1290-1388`), the signup is guaranteed `fraud_detected == false` and `signup_reason = SignupReason::Normal`, which subsequently drives `enroll_user` (`src/plans/mod.rs:647-656`) and `build_pcp`/upload logic with a "normal" (non-fraud) classification, bypassing whatever downstream fraud-gated enrollment/PCP-tagging logic exists.

### Impact Explanation
This is a fail-closed invariant violation for liveness/fraud verdicts: any attacker who can get the pipeline to complete (which does not require passing any anti-spoofing/liveness/fraud heuristic, only agent-level completion without pipeline `Error`) is treated identically to a genuinely clean, fraud-free signup. This directly impacts biometric fraud/liveness bypass and inflates trust in signups that should be flagged, matching a "liveness/fraud detection bypass leading to acceptance of a non-genuine signup" class of impact.

### Likelihood Explanation
High feasibility for any unprivileged attacker running their own signup session: no special primitives (no key leakage, no operator access) are required — they only need capture + pipeline processing to complete without an internal `biometric_pipeline::Error` (timeout/agent/iris failure). This is deterministic and repeatable on every signup that reaches this stage, since the code path contains no conditional branching that could ever produce `true`.

### Recommendation
Restore real fraud check evaluation: reintroduce concrete checks in `Report::fraud_checks()` (`src/plans/fraud_check.rs`) with `N_FRAUD_CHECKS > 0`, wire `MasterPlan::detect_fraud` to actually construct/run `FraudChecks::new(pipeline).run()` and use `Report::fraud_detected()` (or `fraud_detected_with_config`) rather than hardcoding `Ok(false)`, and ensure any missing/default/deleted fraud-check outputs are treated as fraud-positive (fail-closed), consistent with the existing (but currently unused) doc comment "If fraud data are missing, we assume fraud is detected."
