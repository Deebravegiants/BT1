Audit Report

## Title
Unauthenticated, attacker-controlled `request.ID` collision enables denial-of-service on in-flight confidential-relay requests - ([File: core/services/gateway/handlers/confidentialrelay/handler.go])

## Summary
`handler.HandleJSONRPCUserMessage` in the confidential-relay gateway handler performs no authentication or authorization check before registering an in-flight request, and `newActiveRequest` deduplicates purely on the caller-supplied `req.ID` string with no binding to caller identity or request content. [1](#0-0) [2](#0-1)  Any caller who can reach this gateway/DON endpoint and submit a request with the same `ID` as another in-flight request will cause the second submission to be rejected with `"request ID already exists"`, denying that specific relay operation.

## Finding Description
The gateway's generic `ProcessRequest` dispatch in `gateway.go` routes a decoded JSON-RPC request straight to the resolved handler's `HandleJSONRPCUserMessage` with no gateway-level authentication; each handler is responsible for its own auth. [3](#0-2)  The confidential-relay handler performs only trivial ID length/emptiness checks and then immediately calls `newActiveRequest`, which locks the map and rejects if `h.activeRequests[req.ID]` is already populated — keyed solely on the raw client-supplied `req.ID`. [4](#0-3)  This is confirmed by the existing unit test, which shows a second submission with an identical `ID` is unconditionally rejected regardless of its actual content. [5](#0-4) 

By contrast, the sibling vault gateway handler requires the request to pass `GatewayVaultRequestProcessor.ProcessRequest` — which authenticates/authorizes the caller and resolves an `authorizedOwner` — before `newActiveRequest` is ever called. [6](#0-5)  The confidential-relay handler has no equivalent gate: the raw ID is trusted as-is and used as the sole lifecycle/routing key for `activeRequests`, node-response routing in `HandleNodeMessage` (keyed by `resp.ID`), and eventual response delivery. [7](#0-6) 

## Impact Explanation
Because the dedup key is neither authenticated nor bound to the semantic content of the request (`workflow_id`/`execution_id` are extracted only for logging, not for the key), an attacker who can predict or otherwise learn a legitimate caller's `request.ID` in advance can pre-register that ID at the gateway, causing the legitimate request to be rejected outright — `newActiveRequest` returns an error and `HandleJSONRPCUserMessage` propagates it without ever calling `don.SendToNode`, so the real request is never fanned out to the relay DON. [8](#0-7)  This is a targeted denial-of-service against a specific confidential-relay operation (secrets-get or capability-exec) for a workflow execution.

## Likelihood Explanation
Exploitation requires the attacker to both (a) be able to reach the gateway/DON endpoint that routes to this handler with an unauthenticated request, and (b) know or predict the victim's `request.ID` before the victim's genuine submission arrives. The gateway's dispatch layer performs no authentication before handing off to this handler, so requirement (a) is trivially met by any external caller who knows the DON/service routing — unlike the vault handler, no owner/digest check exists to filter callers. [3](#0-2)  Requirement (b) depends on how unpredictable the request IDs used by the real caller (the enclave/workflow engine) are; the codebase's own test harness demonstrates IDs can be simple deterministic strings (e.g., derived directly from execution identifiers) rather than guaranteed high-entropy random values in every code path. [9](#0-8) 

## Recommendation
Bind the in-flight request key to something the caller cannot forge on behalf of another party — e.g., require authentication/authorization before `newActiveRequest` (mirroring the vault handler's `ProcessRequest` step) and/or derive the dedup key from a hash of the full request digest (method + params + ID) rather than the raw client-supplied `ID` alone.

## Proof of Concept
1. An external, unauthenticated caller submits a `HandleJSONRPCUserMessage` request to the confidential-relay handler's gateway/DON endpoint with `ID = "req-dup"` (no credentials required, since the handler performs no auth check). [1](#0-0) 
2. When the legitimate caller's request with the same `ID` arrives, `newActiveRequest` returns `"request ID already exists: req-dup"`, and the legitimate request is never forwarded to the relay DON. [10](#0-9) 
3. This exact primitive is demonstrated by the existing unit test `TestConfidentialRelayHandler_DuplicateRequestID`. [5](#0-4)

func (h *handler) HandleJSONRPCUserMessage(ctx context.Context, req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) error {
	if req.ID == "" {
		return errors.New("request ID cannot be empty")
	}
	if len(req.ID) > 200 {
		return errors.New("request ID is too long: " + strconv.Itoa(len(req.ID)) + ". max is 200 characters")
	}

	labels := h.extractRequestLabels(req)
	l := h.requestLogger(req, labels)
	l.Debugw("handling confidential relay request", "nodes", len(h.donConfig.Members), "f", h.donConfig.F)

	ar, err := h.newActiveRequest(req, labels, callback)
	if err != nil {
		return err
	}

	return h.fanOutToNodes(ctx, l, ar)
}

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], labels requestLabels, callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID, "executionID", labels.ExecutionID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		labels:    labels,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

func (h *handler) HandleNodeMessage(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	l := logger.With(h.lggr, "method", resp.Method, "requestID", resp.ID, "nodeAddr", nodeAddr)
	l.Debugw("handling node response")

	nodeRateLimiter, ok := h.perNodeRateLimiters[nodeAddr]
	if !ok {
		return fmt.Errorf("received message from unexpected node %s", nodeAddr)
	}
	if !nodeRateLimiter.Allow(ctx) {
		l.Debugw("node is rate limited", "nodeAddr", nodeAddr)
		return nil
	}
	if !h.globalNodeRateLimiter.Allow(ctx) {
		l.Debug("global relay rate limit exceeded")
		return nil
	}

	ar := h.getActiveRequest(resp.ID)
	if ar == nil {
		l.Debugw("no pending request found for ID")
		return nil
	}

func TestConfidentialRelayHandler_DuplicateRequestID(t *testing.T) {
	t.Parallel()
	h, cb, don, _ := setupHandler(t, 4)
	don.On("SendToNode", mock.Anything, mock.Anything, mock.Anything).Return(nil)

	params := json.RawMessage(`{"workflow_id":"wf1"}`)
	req := jsonrpc.Request[json.RawMessage]{
		ID:     "req-dup",
		Method: MethodCapabilityExec,
		Params: &params,
	}

	err := h.HandleJSONRPCUserMessage(t.Context(), req, cb)
	require.NoError(t, err)

	cb2 := common.NewCallback()
	err = h.HandleJSONRPCUserMessage(t.Context(), req, cb2)
	require.ErrorContains(t, err, "request ID already exists")
}
