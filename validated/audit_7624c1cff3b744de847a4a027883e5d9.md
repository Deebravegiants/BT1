### Title
Missing `whenNotPaused` on `retryPayload` allows message delivery to bypass emergency pause - ([File: sdk/packages/lz-endpoint/contracts/HyperbridgeLzEndpoint.sol])

### Summary
`HyperbridgeLzEndpoint` gates its primary inbound-delivery path, `onAccept`, with `whenNotPaused` [1](#0-0) , and gates outbound `send` the same way [2](#0-1) . However, `retryPayload`, which performs the exact same privileged action of calling `lzReceive` on a destination OApp, has no `whenNotPaused` modifier at all.

### Finding Description
`retryPayload` is a permissionless function that re-delivers a previously-failed inbound message by calling `ILayerZeroReceiver(receiver).lzReceive(...)` directly, mirroring the delivery performed inside `onAccept`: [3](#0-2) 

The contract's owner can call `pause()`, which is intended to be an emergency stop on all cross-chain operations — the documentation states pausing stops "all operations" and both `send()` and `onAccept()` are explicitly guarded with `whenNotPaused` [4](#0-3) . But `retryPayload` (as well as `lzCompose`/`sendCompose`) omits this modifier, so even while the contract is paused, any external caller can still force delivery of a stored inbound payload to a destination OApp via `lzReceive`.

This is precisely analogous to the referenced LensHub finding: every externally-reachable state-mutating function is protected by the pause guard except one sibling function that performs the same class of action.

### Impact Explanation
If governance pauses the endpoint (e.g., because a malformed/malicious payload class was discovered, or because an OApp integration needs to be quarantined before further messages are delivered), an attacker or relayer can still call `retryPayload` to push through any payload that had been stored from a prior failed `lzReceive` attempt. This defeats the purpose of the pause and can result in unauthorized execution of OApp logic (e.g., minting, state changes) during a period explicitly meant to halt all such activity. Since `retryPayload` is permissionless and callable by anyone, this is directly reachable from a single external transaction with no privilege requirement.

### Likelihood Explanation
Likelihood is moderate: it requires (1) at least one payload to have previously failed and been stored via `onAccept`'s try/catch, and (2) the owner to have paused the contract. Both are realistic emergency-response scenarios — pausing is specifically meant for situations where a bad message/payload has been identified, which is exactly the scenario where a stored payload would already exist waiting for retry.

### Recommendation
Add `whenNotPaused` to `retryPayload` (and consider the same for `lzCompose`, since it also performs an external delivery call that should be haltable), so that pausing the endpoint fully suspends all message-delivery paths, not just the primary `onAccept` and `send` paths.

### Proof of Concept
1. OApp `X` has a payload whose `lzReceive` reverted; `onAccept` stores it in `_inboundPayloadHashes` and emits `InboundPayloadStored` [5](#0-4) .
2. Owner detects the payload/message is malicious or the OApp needs to be quarantined, and calls `pause()`.
3. Attacker calls `retryPayload(receiver, origin, guid, message)` with the matching stored hash — this succeeds because `retryPayload` has no `whenNotPaused` check, delivering the payload to the OApp despite the pause [6](#0-5) .

     * @notice Retries an inbound delivery whose OApp `lzReceive` previously reverted in {onAccept}.
     * @dev Mirrors {onAccept}'s direct call to the OApp (the adapter is the caller, so the OApp's
     * `onlyEndpoint` check still passes). Permissionless: anyone may push a stuck payload through
     * once it is executable again. On success the stored payload hash is cleared; if delivery
     * reverts again the whole call reverts and the payload remains recoverable.
     * @param receiver The destination OApp
     * @param origin The (srcEid, sender, nonce) of the stored payload
     * @param guid The original message guid
     * @param message The original message payload (must match the stored hash)
     */
    function retryPayload(
        address receiver,
        Origin calldata origin,
        bytes32 guid,
        bytes calldata message
    ) external payable {
        bytes32 stored = _inboundPayloadHashes[receiver][origin.srcEid][origin.sender][origin.nonce];
        if (stored == bytes32(0) || stored == NIL_PAYLOAD_HASH || stored != keccak256(abi.encode(guid, message))) {
            revert InvalidPayloadHash();
        }

        // Clear first; if the retry reverts, this deletion rolls back with the rest of the tx and
        // the payload remains recoverable.
        delete _inboundPayloadHashes[receiver][origin.srcEid][origin.sender][origin.nonce];

        ILayerZeroReceiver(receiver).lzReceive{value: msg.value}(origin, guid, message, msg.sender, "");
        emit InboundPayloadResolved(receiver, origin.srcEid, origin.sender, origin.nonce);
    }
