### Title
Unregistered-instance fallback to `address(this)` in `IntentGatewayV2.instance()` allows forged `RedeemEscrow`/`RefundEscrow` authentication bypass, draining escrowed funds - ([File: evm/tron/contracts/apps/IntentGatewayV2.sol])

### Summary
The Tron `IntentGatewayV2.instance()` function returns `address(this)` as a default when no gateway is registered for a given source `stateMachineId`, instead of reverting like the audited EVM `IntentsBase._instance()` does. `authenticate()` uses this function to validate that an incoming `PostRequest.from` matches the registered peer gateway for `request.source`. Because of the silent fallback, any *unregistered* source chain can be used to forge a message whose `from` field is simply set to the destination gateway's own address, and `authenticate()` will treat it as legitimate.

### Finding Description
Compare the two `instance()`/`_instance()` implementations:

Tron (vulnerable): [1](#0-0) 

EVM `intentsv2` (correct, reverts): [2](#0-1) 

`authenticate()` is used as the sole access control for `RedeemEscrow`/`RefundEscrow` in `onAccept`: [3](#0-2) 

Since `instance(request.source)` returns `address(this)` whenever `_instances[keccak256(request.source)] == 0` (i.e., the source chain has never been registered as a peer gateway via `NewDeployment`), an attacker who can dispatch a valid, proof-verified `PostRequest` from **any** state machine hyperbridge relays messages for — as long as that particular chain has not yet been configured as a known IntentGateway instance — can set `request.from` to the 20-byte encoding of the destination gateway's own address (which is public, and by the project's own design is often identical across chains via CREATE2, as referenced in the changelog). `authenticate()` then computes `module == instance(request.source)` → `address(this) == address(this)` → passes, even though the message did not actually originate from a registered peer gateway.

This is the same bug class as the NestJS advisory: a security check trusts an implicit/default value derived from unauthenticated attacker-supplied metadata (there: `Content-Type` header; here: a lookup miss silently substituted with a trusted-looking default) instead of failing closed, letting the attacker choose a payload/behavior the validator was never meant to authorize.

### Impact Explanation
Once authentication is bypassed, the attacker-crafted `WithdrawalRequest` (`commitment`, `tokens`, `beneficiary`) is passed straight to `withdraw()`, which pays out the escrowed balance for that commitment/token to an attacker-chosen `beneficiary`: [4](#0-3) 

The only remaining constraint is `_orders[body.commitment][token] != 0`, i.e., the commitment must have real escrow on the destination gateway (any active order's escrow). An attacker who can dispatch a message from any not-yet-registered state machine (which is the default state for most chains until explicitly configured) can forge `RedeemEscrow`/`RefundEscrow` requests to drain arbitrary escrowed order funds — concrete theft of user/solver funds, a High severity impact.

### Likelihood Explanation
This requires the attacker to control (or dispatch through) a state machine that Hyperbridge relays and that has simply not yet been added to `_instances` for this gateway — a very plausible situation for any chain integration prior to (or omitted from) full peer configuration, or any chain that will never be configured but is nonetheless reachable through the shared Hyperbridge network. No governance/admin compromise is required; a single crafted dispatched message with attacker-controlled `from` bytes is sufficient once routed and delivered by a relayer, matching the "single relayed proof/message" trigger threshold.

### Recommendation
Change `instance()` in `evm/tron/contracts/apps/IntentGatewayV2.sol` to revert (e.g., with `UnknownInstance`) when `_instances[keccak256(stateMachineId)] == address(0)`, mirroring `IntentsBase._instance()` in `evm/src/apps/intentsv2/IntentsBase.sol`. Remove the `address(this)` fallback entirely so authentication fails closed for unregistered source chains.

### Proof of Concept
1. Deploy/observe `IntentGatewayV2` (Tron variant) at address `G`, with real user escrow locked for `commitment = C`, token `T`, amount `A` (from a normal `placeOrder`/`fillOrder` flow).
2. Identify any state machine `S` that Hyperbridge can relay messages from but for which `_instances[keccak256(S)]` has never been set (default zero).
3. From a contract/pallet on `S`, dispatch a `PostRequest` with:
   - `source = S`
   - `from = abi.encodePacked(G)` (the destination gateway's own address)
   - `to = abi.encodePacked(G)`
   - `body = abi.encodePacked(uint8(RequestKind.RedeemEscrow), abi.encode(WithdrawalRequest({commitment: C, tokens: [TokenInfo({token: T, amount: A})], beneficiary: attackerAddress})))`
4. Relay this request through Hyperbridge to `G`'s `onAccept`. `authenticate()` computes `instance(S) == address(this)` since `S` is unregistered, matching `module = G`, so the check passes.
5. `withdraw()` transfers `A` of token `T` to `attackerAddress` and marks the order filled, even though the request never came from a legitimate registered gateway peer. [1](#0-0) [3](#0-2)

     * @dev Fetch the IntentGateway contract instance for a chain.

    function instance(bytes calldata stateMachineId) public view returns (address) {
        address gateway = _instances[keccak256(stateMachineId)];
        return gateway == address(0) ? address(this) : gateway;
    }

    /**
     * @dev Checks that the request originates from a known instance of the IntentGateway.
     */
    function authenticate(PostRequest calldata request) internal view {
        if (request.from.length != 20) revert InvalidInput();
        address module = address(bytes20(request.from));
        // IntentGateway only accepts incoming assets from itself or known instances
        if (instance(request.source) != module) revert Unauthorized();
    }
