### Title
Accrual-time `i128` overflow in `scaled_to_original` permanently freezes a high-balance market before the index cap engages — (File: common/src/rates/simulate.rs)

### Summary
The CVE class is denial of service (crash/hang of a core component). The XOXNO analog is a permanent market freeze: every pool mutation and every controller verb first runs interest accrual, and accrual's very first step multiplies scaled debt shares by the borrow index in `i128`. For a large enough scaled `borrowed` balance, `borrowed * borrow_index` overflows `i128` long before `borrow_index` reaches its `MAX_BORROW_INDEX_RAY` cap. The panic is unrecoverable: `last_timestamp` is only stamped after the loop completes, so no supply/withdraw/borrow/repay/liquidation/`update_indexes` on that market can ever succeed again.

### Finding Description
`global_sync` in `contracts/pool/src/interest.rs` runs on every market mutation and loops `accrue_chunk` until `remaining == 0`, calling `cache.mark_accrued()` only after all chunks succeed [1](#0-0) . Each chunk calls `accrue_step`, whose first operation is `scaled_to_original(env, borrowed, borrow_index)` — a `borrowed * borrow_index / RAY` checked multiply [2](#0-1) . `update_borrow_index` clamps the index at `MAX_BORROW_INDEX_RAY`, but the value multiplication overflows at roughly `i128::MAX / borrowed`, which is a far lower index than `10^36` when `borrowed` is large. The repo's own adversarial test proves the freeze: after a whale market accrues at ~98% utilization long enough for the index to cross the `i128`-value ceiling, `update_indexes`, `withdraw`, and `repay` all fail with `MathOverflow` while `borrow_index < MAX_BORROW_INDEX_RAY`, i.e., the cap "did not engage before the value overflow" and "the market is frozen: exits and repayments accrue first and hit the same panic" [3](#0-2) . Certora docs acknowledge the same trap path: "`update_supply_index` computes `supplied.mul(old_index)`, which panics with `MathOverflow` once `supplied * old_index / RAY` leaves `i128`" [4](#0-3) .

### Impact Explanation
Permanent freezing of funds and protocol insolvency-adjacent damage. Once `borrowed * borrow_index >= i128::MAX * RAY / RAY`-scale, every entrypoint touching that market — `supply`, `withdraw`, `borrow`, `repay`, `liquidate`, `clean_bad_debt`, `recapitalize`, `claim_revenue`, `update_indexes` — reverts inside `global_sync` before any state change, and since `last_timestamp` never advances, there is no path to unfreeze it. All supplier principal in the market is permanently locked, borrower collateral backing that debt cannot be liquidated through the market's own books, and accrued revenue is unclaimable.

### Likelihood Explanation
Reachable by unprivileged addresses using only `supply`/`borrow`: utilization and the index growth are functions of share balances and time, not oracle prices, so no privileged action is needed once the market is listed. An attacker (or simply organic usage) needs a large scaled `borrowed` — most feasible for a high-decimals, low-unit-price listed asset where token supply is cheap — held at sustained high utilization so the index compounds into the overflow region. The harness test demonstrates the trigger end-to-end at a 1e9·10^18-scale supply with 98% utilization on the XLM curve, crossing the cliff in a bounded number of years [5](#0-4) . The barrier is magnitude and duration rather than permission, so Medium severity.

### Recommendation
Bound the pre-cap overflow explicitly: in `update_borrow_index`/`update_supply_index` and in `accrue_step`, cap `borrow_index` (and supply-side value growth) at `i128::MAX / borrowed` (and `i128::MAX / supplied`) rather than only at `10^36`, so accrual saturates instead of panicking — matching the existing semantic "at the cap no further interest accrues". Alternatively, perform the `scaled_to_original`/`mul` in widened arithmetic (e.g., 256-bit intermediate) so the value computation cannot panic before the index cap engages. At minimum, clamp inside `accrue_step` before calling `scaled_to_original` so `mark_accrued` still runs and the market remains operable.

### Proof of Concept
1. In a listed market on an 18-decimals asset (XLM-rate curve), BOB calls `supply` with a principal of `10^9 * 10^18` units; ALICE supplies collateral in a second market and `borrow`s 98% of the BIG18 pool.
2. Anyone periodically calls `update_indexes` (permissionless) as ledger time advances; each call compounds `borrow_index` via `accrue_step`.
3. Once `borrowed * borrow_index` exceeds the `i128` range inside `scaled_to_original` — which occurs at an index far below `MAX_BORROW_INDEX_RAY` — `accrue_step` panics with `MathOverflow`, `mark_accrued` is never reached, and the timestamp never advances.
4. Every subsequent `withdraw`, `repay`, `liquidate`, or `update_indexes` on that market re-enters `global_sync` and panics identically; supplier principal and pending revenue are frozen permanently.

This is codified by the in-repo test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap`, which asserts `MathOverflow` on `update_indexes`, `withdraw`, and `repay` while `borrow_index < MAX_BORROW_INDEX_RAY` [6](#0-5) .

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
