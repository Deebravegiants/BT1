Confirmed root cause: in `extract_signer` (`modules/pallets/ismp/src/host.rs:351-359`), the `signer` bytes attached to a `RequestMessage`/`ResponseMessage` are **decoded but never cryptographically verified**. This is called from `store_request_receipt`/`store_response_receipt` (same file, lines 261-267 and 269-283), which are invoked by `handlers/request.rs::handle` (`modules/ismp/core/src/handlers/request.rs:112`) — the exact analog of DataEase's `TokenUtils.validate()` → `JWT.decode()` pattern: a `Signature` enum is decoded and its embedded public key/address is extracted via `.signer()` (`modules/utils/crypto/src/verification.rs:109-115`), but `Signature::verify()` (which actually checks the cryptographic signature, lines 35-72 of the same file) is **never called** on this path.

### Title
Unauthenticated relayer-identity field lets any submitter forge the delivery-receipt beneficiary in `pallet-ismp` - (File: `modules/pallets/ismp/src/host.rs`)

### Summary
`RequestMessage`/`ResponseMessage.signer` is decoded with `Signature::decode` and its `.signer()` (public key/address) is extracted and persisted as the "relayer who delivered this message" in `RequestReceipts`/`ResponseReceipts`, but the actual `Signature::verify()` check (ECDSA/Ed25519/Sr25519 signature-over-message verification) is never invoked in this code path. Any unsigned `handle_unsigned` submission can therefore claim to have been delivered by an arbitrary account.

### Finding Description
`extract_signer` in `modules/pallets/ismp/src/host.rs:351-359`:
```rust
fn extract_signer(signer: &[u8]) -> Result<Vec<u8>, Error> {
	if signer.len() > 32 {
		Signature::decode(&mut signer.as_ref())
			.map(|sig| sig.signer())
			.map_err(|_| Error::SignatureDecodingFailed)
	} else {
		Ok(signer.to_vec())
	}
}
```
This only SCALE-decodes the `Signature` enum and pulls out the embedded public key/address field (`Signature::signer()`, `modules/utils/crypto/src/verification.rs:109-115`). It never calls `Signature::verify(msg, ...)` (lines 35-72 of the same file), which is the function that actually checks the cryptographic signature against a message hash. `store_request_receipt`/`store_response_receipt` (`host.rs:261-283`) call `extract_signer` directly and persist the result as the relayer identity in `child_trie::RequestReceipts`/`ResponseReceipts`, which is what `handlers/request.rs::handle` (`modules/ismp/core/src/handlers/request.rs:112`) writes on every accepted `handle_unsigned` request. Since `handle_unsigned` is an unsigned extrinsic reachable by anyone (`modules/pallets/ismp/src/lib.rs:373-382`), an attacker can submit any bytes as `msg.signer` — including a `Signature::Evm`/`Sr25519`/`Ed25519` variant whose embedded public key is a *victim's* address, with a garbage/empty signature field — and it will be accepted and recorded as the delivering relayer, because the signature bytes are decoded but not checked against anything.

This is structurally identical to the DataEase bug class: the enterprise-token analog (`msg.signer`) is decoded (`JWT.decode`) to extract an identity claim (`uid`/`oid`) but the presence/format check (`TokenUtils.validate`, i.e. `signer.len() > 32`) substitutes for actual signature verification.

### Impact Explanation
`RequestReceipts[commitment]` is later read as the ground truth for "who delivered this message" by:
- `modules/pallets/relayer/src/accumulate.rs::decode_receipt_relayer` (lines 322-351), which drives relayer fee accumulation (`Fees::<T>` credits) in `accumulate()`.
- `modules/pallets/messaging-incentives/src/lib.rs::relayer_for` (lines 137-153) — note this pallet *does* call `verify_and_get_sr25519_pubkey`, i.e. it re-derives the signer safely and independently — but that only protects the reputation-mint path; the base `pallet-ismp` receipt itself is unauthenticated.
- Event `RequestResponseHandled { relayer, .. }` (`modules/ismp/core/src/handlers/request.rs:117-120`), which downstream tooling/fee accounting may trust.

Forging the receipt's relayer field lets an attacker misattribute delivery credit/fee eligibility to an arbitrary account (including one they don't control, for griefing, or one they do control for unearned fee credit) without ever proving they hold the corresponding private key.

### Likelihood Explanation
High reachability: `handle_unsigned` is callable by any unprivileged party with only a valid membership/state proof for the requests themselves (which is unrelated to `msg.signer`). Crafting a `Signature` variant with an arbitrary embedded public key/address and dummy signature bytes requires no cryptographic material.

### Recommendation
In `extract_signer` (and the `store_request_receipt`/`store_response_receipt` call sites), require `Signature::verify(&message_hash, ...)` to succeed before accepting and persisting the derived signer, mirroring what `pallet-messaging-incentives::relayer_for` already does. Reject the message (or fall back to treating it as unattributed) if verification fails, rather than trusting the decoded public key unconditionally.

### Proof of Concept
1. Construct a valid `PostRequest` batch with a legitimate membership proof (as any relayer would).
2. Set `RequestMessage.signer` to `Signature::Sr25519 { public_key: <victim_pubkey>, signature: [0u8; 64] }.encode()` (or the EVM/Ed25519 equivalent with a garbage signature).
3. Submit via `Ismp::handle_unsigned`.
4. Observe `child_trie::RequestReceipts[commitment]` and the `RequestResponseHandled` event record `<victim_pubkey>` as the delivering relayer, despite no valid signature ever being produced by the victim — confirmed by `extract_signer` never calling `.verify()`. impl Signature {
	/// verify the signature with the public key in the enum or optionally provide a public key
	/// to be used to verify the signature
	pub fn verify(
		&self,
		msg: &[u8; 32],
		public_key_op: Option<Vec<u8>>,
	) -> Result<Vec<u8>, anyhow::Error> {
		match self {
			Signature::Evm { signature, .. } => {
				if signature.len() != 65 {
					Err(anyhow!("Invalid Signature"))?
				}

				let mut sig = [0u8; 65];
				sig.copy_from_slice(&signature);
				let pub_key = sp_io::crypto::secp256k1_ecdsa_recover(&sig, msg)
					.map_err(|_| anyhow!("Signature Verification failed"))?;
				let signer = sp_io::hashing::keccak_256(&pub_key[..])[12..].to_vec();
				Ok(signer)
			},
			Signature::Sr25519 { signature, public_key } => {
				Self::verify_sr25519(signature, public_key, msg, &public_key_op)?;
				Ok(public_key_op.unwrap_or(public_key.clone()))
			},
			Signature::Ed25519 { signature, public_key, .. } => {
				let signature =
					signature.as_slice().try_into().map_err(|_| anyhow!("Invalid Signature"))?;
				let pub_key = public_key_op
					.clone()
					.unwrap_or(public_key.clone())
					.as_slice()
					.try_into()
					.map_err(|_| anyhow!("Invalid Public Key"))?;
				if !sp_io::crypto::ed25519_verify(&signature, msg, &pub_key) {
					Err(anyhow!("Signature Verification failed"))?
				}
				Ok(public_key_op.unwrap_or(public_key.clone()))
			},
		}
	}

	fn verify_sr25519(
		signature: &Vec<u8>,
		public_key: &Vec<u8>,
		msg: &[u8; 32],
		public_key_op: &Option<Vec<u8>>,
	) -> Result<[u8; 32], anyhow::Error> {
		let signature =
			signature.as_slice().try_into().map_err(|_| anyhow!("Invalid Signature"))?;

		let pub_key = public_key_op
			.clone()
			.unwrap_or(public_key.clone())
			.as_slice()
			.try_into()
			.map_err(|_| anyhow!("Invalid Public Key"))?;

		if !sp_io::crypto::sr25519_verify(&signature, msg, &pub_key) {
			return Err(anyhow!("Sr25519 signature verification failed"));
		}

		Ok(pub_key.into())
	}

	pub fn verify_and_get_sr25519_pubkey(
		&self,
		msg: &[u8; 32],
		public_key_op: Option<Vec<u8>>,
	) -> Result<[u8; 32], anyhow::Error> {
		match self {
			Signature::Sr25519 { public_key, signature } =>
				Self::verify_sr25519(signature, public_key, msg, &public_key_op),
			_ => Err(anyhow!("Signature is not of type Sr25519")),
		}
	}

	pub fn signer(&self) -> Vec<u8> {
		match self {
			Signature::Evm { address, .. } => address.clone(),
			Signature::Sr25519 { public_key, .. } => public_key.clone(),
			Signature::Ed25519 { public_key, .. } => public_key.clone(),
		}
	}

impl<T: Config> Pallet<T> {
	/// Decode a proven `RequestReceipts[commitment]` value into the delivering
	/// relayer's bytes. EVM stores the address RLP encoded, substrate stores the
	/// signer bytes or a signature to recover the signer from. Used by both fee
	/// accumulation and the outbound request delivery claim.
	pub fn decode_receipt_relayer(state_id: StateMachine, raw: &[u8]) -> Result<Vec<u8>, Error<T>> {
		match state_id {
			s if crate::is_pharos(&s) =>
				if raw.len() == 32 {
					Ok(Address::from_slice(&raw[12..]).0.to_vec())
				} else {
					Err(Error::<T>::ProofValidationError)
				},
			s if s.is_evm() => {
				use alloy_rlp::Decodable;
				Ok(Address::decode(&mut &*raw)
					.map_err(|_| Error::<T>::ProofValidationError)?
					.0
					.to_vec())
			},
			s if s.is_substrate() => {
				use codec::Decode;
				let bytes =
					<Vec<u8>>::decode(&mut &*raw).map_err(|_| Error::<T>::ProofValidationError)?;
				Ok(if bytes.len() > 32 {
					Signature::decode(&mut &*bytes)
						.map_err(|_| Error::<T>::SignatureDecodingError)?
						.signer()
				} else {
					bytes
				})
			},
			_ => Err(Error::<T>::MismatchedStateMachine),
		}
	}

	/// Recover the relayer's account from the sr25519 signature on a
	/// `Message`'s `signer` field. Returns `None` if the message has
	/// no signer (e.g. consensus messages) or the signature is bad.
	fn relayer_for(message: &Message) -> Option<T::AccountId> {
		let (signer, signed) = match message {
			Message::Request(msg) =>
				(&msg.signer, sp_io::hashing::keccak_256(&msg.requests.encode())),
			Message::Response(msg) =>
				(&msg.signer, sp_io::hashing::keccak_256(&msg.requests.encode())),
			_ => return None,
		};
		Signature::decode(&mut &signer[..])
			.ok()?
			.verify_and_get_sr25519_pubkey(&signed, None)
			.ok()
			.map(T::AccountId::from)
	}
