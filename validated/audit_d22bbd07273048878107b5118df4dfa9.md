### Title
Unhandled `ReputationAsset::mint_into` error in `process_message` allows a relayer to be paid the same block-span reward more than once, draining the treasury - ([File: modules/pallets/consensus-incentives/src/impls.rs])

### Summary
`Pallet::process_message` in `pallet-consensus-incentives` transfers the BRIDGE reward to the relayer *before* it updates the `LastRewardedHeight` watermark that prevents the same block span from being paid twice. The reputation-token mint that sits between the two steps can fail and abort the function with `?`, and the caller discards that error with `let _ =`, so the transfer is never rolled back while the watermark update never runs — exactly the same "setter error unhandled → state not persisted → double payout" shape as the Allora `RewardDelegateStake` finding.

### Finding Description
`FeeHandler::on_executed` calls the reward path once per state machine per batch and explicitly swallows any error: [1](#0-0) 

Inside `process_message`, the sequence is:
1. Transfer `reward` BRIDGE from the treasury to `relayer_account` (line 53-59).
2. Deposit `RelayerRewarded` event.
3. `T::ReputationAsset::mint_into(&relayer_account, reward)` with `.map_err(|_| Error::<T>::ReputationMintFailed)?` (line 67-68) — **this can fail and return early**.
4. Only after that succeeds does it advance `LastRewardedHeight` (the double-payment guard) at line 70-72. [2](#0-1) 

`LastRewardedHeight` is the sole mechanism preventing the same `(state_machine_id, height-span)` from being rewarded twice — the doc comment on the storage item says so explicitly: [3](#0-2) 

`calculate_reward` computes the payable span strictly from that watermark: [4](#0-3) 

If `mint_into` errors (e.g., the reputation asset is frozen, has hit `max_encoded_len`/total-issuance overflow, the account is in a `Blocked`/frozen state under `pallet-assets`, or any other `fungible::Mutate` failure condition specific to the configured `ReputationAsset`), `process_message` returns `Err(ReputationMintFailed)` *after* the treasury→relayer BRIDGE transfer already landed in storage, but *before* `LastRewardedHeight` is bumped. `on_executed` throws that error away via `let _ =`, so from the runtime's perspective the whole extrinsic still succeeds (`Ok(PostDispatchInfo { .. })` is still returned unconditionally at the end of `on_executed`), and the transfer is not reverted because it is not the outer dispatchable's own error — it was already committed inside the inner call, and nothing rolls it back once `let _` discards the failure. The next `StateMachineUpdated` batch for that same `state_machine_id` recomputes `calculate_reward` against the stale, unmoved watermark and pays out the same block span again.

### Impact Explanation
Every time the mint step fails, the treasury pays the relayer for the same block-height span more than once with no on-chain record of the double payment (the mint failure is silently discarded). This is unbounded: a relayer can repeatedly trigger the failure condition (e.g., an account state that reliably rejects `mint_into` for the reputation asset while still allowing the plain `Currency::transfer` of BRIDGE) and repeatedly re-collect the same span's reward, draining `TreasuryAccount`'s BRIDGE balance. This matches the "insolvency / drain of the reward-paying account" impact called out in the source Allora report.

### Likelihood Explanation
Reachability is via any unsigned/permissionless consensus message delivery that ends up invoking `FeeHandler::on_executed` — any relayer submitting a `Message::Consensus` is the caller of this path, which fits "an unprivileged message dispatcher/relayer" reachable in one transaction. The likelihood of actually triggering the mint failure depends on the concrete `ReputationAsset` implementation wired into the runtime (`gargantua`/`nexus`); I could not fully verify from the indexed snippets whether that asset backend has any realistic caller-triggerable failure mode (e.g., freezing, existential-deposit dust removal, or issuance caps) versus being an always-succeeding `NativeCurrency`-style asset. This is the main open uncertainty and would need to be checked against `parachain/runtimes/gargantua/src/lib.rs` / `nexus/src/lib.rs`'s `ReputationAsset` type wiring to confirm exploitability with full confidence.

### Recommendation
- Perform the `LastRewardedHeight` watermark update and any other double-payment guard **before** or atomically with the treasury transfer, or make the whole `process_message` sequence transactional so a mint failure reverts the transfer too (`#[transactional]` or restructure to update the watermark first).
- Do not silently discard the `Result` of `process_message` in `on_executed`; at minimum, if the mint fails after a successful transfer, ensure the transfer is not treated as final, or emit an event/error the runtime can surface, and audit whether `ReputationAsset::mint_into` can plausibly fail for a caller-controlled relayer account in production configuration.

### Proof of Concept
1. Configure (or find) a scenario where `T::ReputationAsset::mint_into(&relayer_account, reward)` fails for a specific `relayer_account` (e.g., an account state rejected by the pallet-assets backend used for `ReputationAsset`) while `T::Currency::transfer` (BRIDGE) to that same account still succeeds.
2. Relayer submits a `Message::Consensus` batch containing a `StateMachineUpdated` event for `state_machine_id` X with `latest_height = H1`.
3. `on_executed` → `process_message`: treasury transfers `reward` BRIDGE to the relayer, event emitted, then `mint_into` fails → function returns `Err`; `LastRewardedHeight[X]` is **not** updated; `on_executed` discards the error via `let _ =` and the extrinsic still reports success.
4. Relayer submits another batch with a `StateMachineUpdated` event for the same `state_machine_id` X at a height ≥ H1 (or even the same span, since the watermark never moved).
5. `calculate_reward` recomputes using the stale watermark and pays the **same** block span's reward again from the treasury to the relayer.
6. Repeat to drain `TreasuryAccount`.

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}
