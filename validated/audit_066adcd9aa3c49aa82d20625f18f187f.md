Audit Report

## Title
CORS wildcard-origin allowlist bypass via missing subdomain boundary check - ([File: core/services/gateway/network/httpserver.go])

## Summary
The Gateway HTTP server's `isAllowedOrigin` function strips only the `"*."` prefix from a configured wildcard allowlist entry and then performs a raw `strings.HasSuffix` comparison against the request's `Origin` host, without enforcing a `.` label boundary. As a result, any origin host that merely ends with the configured suffix (e.g. `evilexample.com` against `*.example.com`) is incorrectly treated as an allowed subdomain, bypassing the intended `CORSAllowedOrigins` allowlist restriction.

## Finding Description
In `isAllowedOrigin`, the wildcard branch is: `allowedHost = allowedHost[2:]` followed by `strings.HasSuffix(originHost, allowedHost)`. [1](#0-0)  This strips exactly the two characters `"*."`, leaving a bare domain string with no leading `.`, so the suffix check matches on raw characters rather than hostname labels — `strings.HasSuffix("evilexample.com", "example.com")` returns `true` even though `evilexample.com` is not a subdomain of `example.com`. The existing test suite only validates negative cases where the origin doesn't share the literal suffix at all (e.g. `https://ethereum.remix.org` against `*.ethereum.org`), and does not cover the boundary-bypass case (`evilethereum.org` vs `*.ethereum.org`), so the defect is untested and unguarded. [2](#0-1)  This result directly gates `Access-Control-Allow-Origin` reflection in `handleRequest`. [3](#0-2) 

## Impact Explanation
`CORSAllowedOrigins` is an explicit allowlist intended to restrict which origins may receive CORS trust from the internet-facing Gateway HTTP server. [4](#0-3)  This bug is a concrete allowlist-bypass: an operator using the documented and tested wildcard feature (`*.example.com`) unintentionally grants CORS trust to any attacker-controlled domain sharing the same suffix (`evilexample.com`, `attacker-example.com`), which is not a genuine subdomain. This falls squarely in the "allowlist bypass" impact category.

## Likelihood Explanation
Exploitation requires only that the operator use the supported, documented wildcard syntax in `CORSAllowedOrigins` — not a misconfiguration, but normal use of a built-in feature — and that an attacker register or control any domain sharing the configured suffix. No privileged access, credentials, or victim-side exploitation of another vulnerability is required; the flawed comparison is deterministic and always reachable via the `Origin` header on any HTTP request to the Gateway's request path. [5](#0-4) 

## Recommendation
Enforce a proper subdomain boundary when performing the wildcard suffix check, e.g. compare `strings.HasSuffix(originHost, "."+allowedHost) || originHost == allowedHost` after stripping `"*."`, or split hosts into labels and compare trailing label sequences exactly. Add a regression test asserting `evilexample.com` does NOT match `*.example.com`.

## Proof of Concept
Configure `CORSAllowedOrigins: ["https://*.example.com"]` and enable CORS. Send a request to the Gateway's configured HTTP path with header `Origin: https://evilexample.com`. In `isAllowedOrigin`, `allowedHost` becomes `example.com` after stripping `"*."`, and `strings.HasSuffix("evilexample.com", "example.com")` evaluates to `true`, causing `handleRequest` to set `Access-Control-Allow-Origin: https://evilexample.com`, incorrectly granting the non-subdomain origin CORS trust. [6](#0-5)

func (s *httpServer) isAllowedOrigin(origin string) bool {
	originScheme, originHost, originPort, err := s.splitURL(origin)
	if err != nil {
		s.lggr.Debug("error parsing origin URL", err)
		return false
	}
	for _, allowed := range s.config.CORSAllowedOrigins {
		// probably better to do this once when server starts and store it in a map
		// this is an easier solution so we don't have to apply more changes to the code
		// just need to be careful when specifying allowed origins in the config file
		allowedScheme, allowedHost, allowedPort, err := s.splitURL(allowed)
		if err != nil {
			s.lggr.Debug("error parsing allowed origin URL", err)
			continue
		}
		// skip if the scheme doesn't match at all
		if originScheme != allowedScheme {
			continue
		}
		// skip if the port doesn't match at all
		if originPort != allowedPort {
			continue
		}
		// check for exact host match (e.g., remix.com)
		if originHost == allowedHost {
			return true
		}
		// check for wildcard host match (e.g., *.remix.com)
		if strings.HasPrefix(allowedHost, "*.") {
			allowedHost = allowedHost[2:]
			if strings.HasSuffix(originHost, allowedHost) {
				return true
			}
		}
	}
	return false
}
