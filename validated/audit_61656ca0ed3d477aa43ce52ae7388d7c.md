### Title
Unbounded derivation-path depth allows dapp-controlled synchronous CPU-DoS via `master.derive(derivationPath)` - ([File: features/keychain/module/keychain.js])

### Summary
`throwIfInvalidKeyIdentifier` and the underlying `DerivationPath`/`assertValidDerivationPath` validators never bound the *depth* (number of path segments) of a `derivationPath`, only its per-segment syntax. A dapp/deeplink-supplied `keyId.derivationPath` with an extremely large number of segments passes all validation and is handed to `master.derive(derivationPath)`, which synchronously performs one HMAC-SHA512 + secp256k1 scalar operation per segment on the main thread, causing a long, deterministic hang proportional to path length.

### Finding Description
The call chain is `signBuffer`/`exportKey`/`getPublicKey` → `#getPrivateHDKey` → `throwIfInvalidKeyIdentifier(keyId)` → `master.derive(derivationPath)` [1](#0-0) [2](#0-1) .

`throwIfInvalidKeyIdentifier` only checks that `KeyIdentifier.validate()` succeeds and that the object is frozen [3](#0-2) . `KeyIdentifier.validate` simply re-constructs a `KeyIdentifier` from the candidate, which parses the `derivationPath` string via `DerivationPath.from` [4](#0-3) . Per-segment syntax is strictly checked with a regex (`/^(\d+)(')?$/u`), rejecting negative signs, decimals, or traversal-like tokens (e.g. `..`) deterministically [5](#0-4) . Neither `DerivationPath.from`/`DerivationPath` constructor nor `assertValidDerivationPath` impose any maximum on the *number* of segments (path depth) [6](#0-5) [7](#0-6) .

`master.derive(path)` (BIP32 `HDKey.derive`) splits the path string on `/` and synchronously iterates every entry, calling `deriveChild` (HMAC-SHA512 + EC scalar-add) for each one [8](#0-7) [9](#0-8) . There is no depth cap, so a path with a very large number of well-formed segments (e.g. `m/0/0/0/.../0` repeated hundreds of thousands of times) is fully valid per the syntax checks yet forces hundreds of thousands of sequential cryptographic operations on the calling thread.

The other exploit vectors named in the question — path-traversal-like strings (`m/0/../../0'`) and negative/overflowing numeric indices supplied as strings — are already rejected deterministically by the strict per-segment regex in `normalizeIndex`/`assertValidDerivationPath`, and BIP32/SLIP10 child derivation is a strictly forward (child-only) HMAC construction with no upward/parent traversal semantics, so no "escape to a sibling/parent account" is possible purely from path syntax. A bypass via passing a raw JS-number array instead of a string (which skips the regex in `normalizeIndex` for `typeof index === 'number'`) is also caught, because `throwIfInvalidKeyIdentifier`'s `KeyIdentifier.validate()` reconstructs the object from its already-stringified `derivationPath` property, forcing a second strict-regex parse that fails deterministically for any negative/NaN/non-integer value.

### Impact Explanation
An attacker-controlled `derivationPath` (from a dapp request, deeplink, or imported payload) reaching `exportKey`/`signBuffer`/`getPublicKey` can force `master.derive()` to perform an attacker-chosen, effectively unbounded number of synchronous elliptic-curve/HMAC operations, freezing the calling thread (wallet UI or background service) for a duration proportional to the attacker-chosen path length. This is a denial-of-service against wallet responsiveness, reachable from an unprivileged origin with no lock/approval bypass, but it does not achieve unauthorized cross-account key derivation, signing, or secret disclosure — the "escape account boundary" and negative/traversal bypass scenarios described in the question are not exploitable due to existing strict regex + round-trip revalidation.

### Likelihood Explanation
Fully attacker-controlled: any code path that lets a dapp/deeplink supply `keyId.derivationPath` verbatim (e.g. via a signing/export request) can trigger this with a single crafted string, no auth bypass or privileged state needed. Feasibility depends on whether an intermediate caller (outside `keychain.js`) already restricts `derivationPath` shape/depth before invoking `exportKey`/`signBuffer`/`getPublicKey`; if such a caller exists, this is not directly reachable, but nothing in `keychain.js`, `key-identifier.js`, or `derivation-path.js` enforces it.

### Recommendation
Add an explicit maximum depth (e.g. BIP32's practical limit is far below 255 due to `depth` being serialized as a single byte) to `DerivationPath`'s constructor/`assertValidDerivationPath`, and enforce it before `master.derive()` is invoked in `#getPrivateHDKey`.

### Proof of Concept
Unit test in `features/keychain/module/__tests__/`:
1. Create a keychain, add a seed via `addSeed`.
2. Build `derivationPath = 'm/' + Array(200000).fill('0').join('/')`.
3. Call `keychain.getPublicKey({ seedId, keyId: { derivationAlgorithm: 'BIP32', derivationPath, keyType: 'secp256k1' } })`.
4. Assert the call either throws a clear "path too deep" validation error (after fix) instead of blocking the thread for an extended, attacker-scaled duration (before fix, measure wall-clock time growing linearly with path length, demonstrating unbounded synchronous CPU cost).

function normalizeIndex(index) {

    return index

export const assertValidDerivationPath = (path, requireAllHardened = false) => {
  assert(typeof path === 'string', 'derivationPath was not a string')
  const indexes = path.split('/')
  assert(indexes.length >= 2, 'derivationPath must be at least one level deep')
  assert(indexes[0] === 'm', 'derivationPath must start with master root m')
  const indexesWithoutM = indexes.slice(1)
  assert(
    // BIPPath does not start+end check ^$ with its regex and uses exec()
    // which allows arbitrary strings to be in the path
    // This assert avoids: "m/0'somestring" to pass
    indexesWithoutM.every((index) => typeof index === 'string' && /^\d+(')?$/u.test(index)),
    `derivationPath must contain only a number and optionally a hardening character '`
  )

  assert(
    // Technically this is allowed in bip32 but defence in depth
    // against xpub + private child key leaking xpriv
    // OK: m/0'/0
    // NOT OK: m/0/0'
    !indexesWithoutM.reduce(
      ({ hardeningStillAllowed, violatedRule }, cur) => {
        if (!hardeningStillAllowed && cur.endsWith(`'`)) {
          violatedRule = true
        }

        hardeningStillAllowed = hardeningStillAllowed && cur.endsWith(`'`)
        return { hardeningStillAllowed, violatedRule }
      },
      { hardeningStillAllowed: true, violatedRule: false }
    ).violatedRule,
    `derivationPath may not contain hardened index after any unhardened indexes`
  )

  if (requireAllHardened) {
    // SLIP10 ed25519 does not support unhardened indexes
    assert(
      indexesWithoutM.every((index) => index.endsWith(`'`)),
      `derivationPath requires all hardened indexes`
    )
  }
}

  derive(path) {
    if (path === 'm' || path === 'M' || path === "m'" || path === "M'") {
      return this
    }

    const entries = path.split('/')
    let hdkey = this // eslint-disable-line unicorn/no-this-assignment
    entries.forEach(function (c, i) {
      if (i === 0) {
        assert(/^[Mm]/u.test(c), 'Path must start with "m" or "M"')
        return
      }

      const hardened = c.length > 1 && c[c.length - 1] === "'"
      let childIndex = parseInt(c, 10) // & (HARDENED_OFFSET - 1)
      assert(childIndex < HARDENED_OFFSET, 'Invalid index')
      if (hardened) childIndex += HARDENED_OFFSET

      hdkey = hdkey.deriveChild(childIndex)
    })

    return hdkey
  }

  deriveChild(index) {
    const isHardened = index >= HARDENED_OFFSET
    const indexBuffer = Buffer.alloc(4)
    indexBuffer.writeUInt32BE(index, 0)

    let data

    if (isHardened) {
      // Hardened child
      assert(this.privateKey, 'Could not derive hardened child key')

      let pk = this.privateKey
      const zb = Buffer.alloc(1)
      pk = Buffer.concat([zb, pk])

      // data = 0x00 || ser256(kpar) || ser32(index)
      data = Buffer.concat([pk, indexBuffer])
    } else {
      // Normal child
      // data = serP(point(kpar)) || ser32(index)
      //      = serP(Kpar) || ser32(index)
      data = Buffer.concat([this.publicKey, indexBuffer])
    }

    const I = hmacSync('sha512', this.chainCode, data)
    const IL = I.slice(0, 32)
    const IR = I.slice(32)

    const hd = new HDKey(this.versions)

    // Private parent key -> private child key
    if (this.privateKey) {
      // ki = parse256(IL) + kpar (mod n)
      try {
        hd.privateKey = secp256k1.privateKeyTweakAdd({
          privateKey: this.privateKey,
          tweak: IL,
          format: 'buffer',
        })
        // throw if IL >= n || (privateKey + IL) === 0
      } catch {
        // In case parse256(IL) >= n or ki == 0, one should proceed with the next value for i
        return this.deriveChild(index + 1)
      }
      // Public parent key -> public child key
    } else {
      // Ki = point(parse256(IL)) + Kpar
      //    = G*IL + Kpar
      try {
        hd.publicKey = secp256k1.publicKeyTweakAddScalar({
          publicKey: this.publicKey,
          tweak: IL,
          format: 'buffer',
        })
        // throw if IL >= n || (g**IL + publicKey) is infinity
      } catch {
        // In case parse256(IL) >= n or Ki is the point at infinity, one should proceed with the next value for i
        return this.deriveChild(index + 1)
      }
    }

    hd.chainCode = IR
    hd.depth = this.depth + 1
    hd.parentFingerprint = this.fingerprint // .readUInt32BE(0)
    hd.index = index

    return hd
  }
