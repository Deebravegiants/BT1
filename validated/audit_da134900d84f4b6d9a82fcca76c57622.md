## Analysis

The Sherlock report describes a rate-accrual bug: JUSD's borrow interest accumulator applies the *current* `borrowFeeRate` to a time span that spans a prior rate regime, instead of settling the accrual at the old rate before switching. Every rate update silently repriced already-elapsed time at the new rate, diluting/inflating the true cost.

This exact bug class reappears in `pallet-consensus-incentives`, which pays relayers a reward for delivering ISMP consensus proofs. [1](#0-0) 

`calculate_reward` computes `reward = (latest_height - baseline) * block_cost`, where `baseline` is the persisted `LastRewardedHeight` watermark [2](#0-1)  and `block_cost` is whatever `StateMachinesCostPerBlock` currently holds at call time [3](#0-2) . Just like the JUSD `tRate`, this is a single scalar applied uniformly to the *entire* unsettled span, with no per-segment pricing. `update_cost_per_block` simply overwrites the rate with no settlement step against `LastRewardedHeight` first [4](#0-3) .

The reachable trigger is permissionless: any relayer submits a `ConsensusMessage`, which flows through `FeeHandler::on_executed` → `process_message` → `calculate_reward` [5](#0-4) . A relayer fully controls *when* it submits its proof, i.e., how large the unsettled `latest_height - baseline` span grows before the reward is realized.

### Title
Stale-rate reward span lets a relayer drain the treasury by delaying proof submission across a `cost_per_block` increase - (File: modules/pallets/consensus-incentives/src/impls.rs)

### Summary
`calculate_reward` prices the entire unsettled block span (`latest_height - LastRewardedHeight` watermark) at whatever `StateMachinesCostPerBlock` happens to be *at claim time*, rather than settling accrued reward at the rate that was in effect while those blocks were relayed. This mirrors the JUSD bug where `tRate` is recomputed from a stale `lastTimeStamp` and a rate update retroactively re-prices already-elapsed time.

### Finding Description
`process_message` reads the current `block_cost` for a state machine and calls `calculate_reward`, which multiplies the full backlog span `(latest_height - baseline)` by that single rate [6](#0-5) . `baseline` only advances when a reward is actually paid out via `LastRewardedHeight::mutate` [7](#0-6) , so any relayer can simply withhold submitting consensus proofs for a state machine, allowing `latest_height` (advanced independently by `IsmpHost::latest_commitment_height`) to run far ahead of the watermark. There is no settlement/checkpoint when `update_cost_per_block` changes the rate [8](#0-7) : the old rate simply disappears and the entire backlog — including blocks that were already effectively "owed" under the previous, lower rate — is paid out at whatever rate is active when the relayer finally submits.

### Impact Explanation
Because governance is expected to periodically raise `cost_per_block` (e.g., to track market rates), a relayer that anticipates or observes an upcoming increase can strategically delay submitting proofs for a state machine, then submit right after the rate hike and collect the full deferred span (which can be large, since nothing caps `latest_height - baseline`) at the new, higher price. This drains `TreasuryAccount` funds beyond what governance intended to pay for that historical span, and also mints a matching amount of `ReputationAsset` [9](#0-8)  disproportionate to actual service rendered at the time it was rendered. This is a concrete, unbacked-payout / fund-drain scenario reachable from a single relayer-submitted consensus message.

### Likelihood Explanation
Likelihood is Medium: it requires a `cost_per_block` update to occur (a normal, expected governance operation, not an attacker-controlled event) combined with a relayer choosing to delay a claim across that update — both are realistic operational conditions rather than privileged-attacker assumptions. The relayer needs no special permission; delaying proof submission is entirely within their normal discretion, and `on_executed`/consensus message submission is a standard permissionless flow.

### Recommendation
Settle (checkpoint) the reward for the outstanding span at the *current* rate immediately whenever `update_cost_per_block` is called, updating `LastRewardedHeight` to the state machine's current committed height and crediting/reserving the reward computed at the old rate before switching to the new rate. Alternatively, record `(height, rate)` breakpoints and compute rewards as a sum over rate segments rather than a single flat multiplication across the whole unsettled span.

### Proof of Concept
1. Governance sets `StateMachinesCostPerBlock[SM] = 10` via `update_cost_per_block`.
2. State machine `SM` advances consensus commitments for 1000 blocks, but no relayer submits a `ConsensusMessage` for it, so `LastRewardedHeight[SM]` stays at the old watermark (`baseline`), while `latest_commitment_height` moves to `baseline + 1000` independently through normal state-machine updates.
3. Governance raises the rate: `update_cost_per_block(SM, 1000)` (10x), intending this to apply to *future* relaying activity.
4. A relayer now submits a single valid `ConsensusMessage` for `SM`. `on_executed` → `process_message` → `calculate_reward` computes `reward = (latest_height - baseline) * 1000 = 1000 * 1000`, i.e., the entire 1000-block backlog priced at the new rate, instead of the intended `1000 * 10` (old rate for old blocks) — a 100x overpayment funded entirely from `TreasuryAccount` [10](#0-9) .

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}

impl<T: Config> FeeHandler for Pallet<T>
where
	<T as frame_system::Config>::AccountId: From<[u8; 32]>,
{
	fn on_executed(
		messages: Vec<MessageWithWeight>,
		events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});

		if let Some(relayer_account) = maybe_relayer_account {
			// When a batch contains multiple `StateMachineUpdated` events for the
			// same `state_machine_id` (sequential consensus updates for the same
			// chain), `calculate_reward` reads the same persisted
			// `(latest_commitment_height, previous_commitment_height)` pair on
			// every iteration and pays the same block-span reward N times.
			// Collapse the per-state-machine event stream to the single highest
			// `latest_height` so each state machine receives one reward per
			// batch, sized by the actual span of its commitment advance.
			let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
			for event in events {
				if let IsmpEvent::StateMachineUpdated(update) = event {
					highest_per_state_machine
						.entry(update.state_machine_id)
						.and_modify(|h| {
							if update.latest_height > *h {
								*h = update.latest_height;
							}
						})
						.or_insert(update.latest_height);
				}
			}

			for (state_machine_id, latest_height) in highest_per_state_machine {
				let state_machine_height =
					StateMachineHeight { id: state_machine_id.clone(), height: latest_height };

				let _ = Self::process_message(
					state_machine_height,
					state_machine_id,
					relayer_account.clone().into(),
				);
			}
		}
