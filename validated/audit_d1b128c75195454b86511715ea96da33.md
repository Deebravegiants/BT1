## Analysis

The CUPID incident is a classic spot-price oracle manipulation via flash loan: the attacker temporarily distorted a pool's spot price and profited by trading against a system that trusted that spot price without protection (TWAP, deviation bound, or size/impact adjustment).

The closest analog in Hyperbridge is in the **Simplex intent solver's** Uniswap V4 venue-pricing path, which feeds prices directly into **intent order fills** on `IntentGatewayV2` (an explicitly in-scope surface).

### Title
Simplex FXFiller prices intent-order legs off an unguarded raw Uniswap V4 spot price, letting a flash-loan price manipulation extract value from solver-filled orders - (File: sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts)

### Summary
When a `[[pairs]]` entry has no bid/ask curve, `FXFiller` prices that leg entirely from a live Uniswap V4 pool's spot price (`sqrtPriceX96`), with no TWAP, no execution-size/impact adjustment, and no mandatory sanity check against a manipulated quote.

### Finding Description
`UniswapV4FundingPlanner.getExoticTokenPrice` selects the position with the largest raw pool liquidity and calls `computeDirectPoolPriceUsd`, which returns the pool's instantaneous mid price straight from `sqrtPriceX96` via `sdkPool.token0Price`/`token1Price`: [1](#0-0) 

This price is a **raw current-block spot price**: the fee tier is recorded on the position but never applied, and there is no size/impact term at all — `computeLegPolicyOutput` linearly extends this single mid price across the whole quantity being priced, as documented in the codebase's own analysis: [2](#0-1) 

The only mitigation, `checkPriceGuard`, is **optional** (`referencePrice`/`maxDeviationBps` must both be explicitly configured per chain) and checks deviation against a **static** reference rather than execution cost or a manipulation-resistant TWAP: [3](#0-2) 

Documentation confirms the guard is opt-in and leaves the chain "unguarded" when omitted: [4](#0-3) 

The unguarded venue price feeds `venuePriceMemo`/`getVenueUsdPrice`, which resolves leg rates used to size and price intent order fills for `IntentGatewayV2` orders: [5](#0-4) 

An attacker who flash-loan-manipulates the configured Uniswap V4 pool's spot price (the same bug class as the CUPID incident) can:
1. Push the pool price far from fair value within one block/transaction.
2. Submit or trigger an intent order priced against this manipulated venue quote while `checkPriceGuard` is unconfigured (default posture) or the reference itself is stale/wide.
3. Have the solver fill (or size a phantom bid) at the manipulated rate, over- or under-delivering value relative to true market price, extracting funds from the solver's escrowed/vault inventory.

### Impact Explanation
A successful manipulation directly misprices a leg of a live cross-chain intent settled through `IntentGatewayV2`/`IntrinsicIntents.sol` escrow release, letting an attacker extract solver-held funds at a manipulated rate — a concrete theft of funds via unsound price input into an in-scope fill path, matching the "concrete theft of funds" acceptance criterion.

### Likelihood Explanation
Likelihood is Medium: the guard is optional per the documented configuration model, so any deployment operating a venue-priced pair without setting `referencePrice`/`maxDeviationBps` (the documented default posture) is exposed to any attacker capable of a flash loan against the configured pool — no privileged role is required, only capital and a single transaction, consistent with the CUPID report's mechanism.

### Recommendation
Make the price guard mandatory rather than optional for venue-priced pairs, derive the reference from a manipulation-resistant TWAP (not a static hand-set value), and incorporate the pool's actual fee tier plus a size/impact term into `computeDirectPoolPriceUsd`/`computeLegPolicyOutput` instead of linearly extending a single spot mid price across the whole filled quantity.

### Proof of Concept
1. Configure a pair with `[vault.uniswapV4]` positions and no `referencePrice`/`maxDeviationBps` (the documented default, per `docs/content/developers/evm/simplex/pricing.mdx`).
2. Attacker flash-loans and swaps heavily through the configured Uniswap V4 pool to move `sqrtPriceX96` to a favorable extreme.
3. Attacker submits an intent order sized to profit from the leg using `getVenueUsdPrice` → `computeDirectPoolPriceUsd`'s now-distorted mid price.
4. Solver fills the order per `resolveLegRates`, releasing escrowed input assets at the manipulated rate.
5. Attacker reverses the flash-loan swap, restoring the pool price and pocketing the difference from the solver's inventory. [6](#0-5)

	/**
	 * Queries funding venues for `token1Address`'s USD price on a chain.
	 * Uniswap V4 is preferred; falls back to other venues. Returns null when no
	 * venue can price the token there.
	 */
	private async getVenueUsdPrice(chain: string, token1Address: string): Promise<Decimal | null> {
		if (this.fundingVenues.length === 0) return null

		// Prefer V4, fall back to others
		const v4 = this.fundingVenues.filter((v) => v.name === "UniswapV4")
		const venues = v4.length > 0 ? v4 : this.fundingVenues

		for (const venue of venues) {
			const usdPrice = await venue.getExoticTokenPrice(chain, token1Address)
			if (usdPrice?.isPositive()) return usdPrice
		}
		return null
	}

	/** Per-evaluation memo over `getVenueUsdPrice`, keyed by (chain, token1). */
	private venuePriceMemo(): (chain: string, token1Address: string) => Promise<Decimal | null> {
		const cache = new Map<string, Decimal | null>()
		return async (chain: string, token1Address: string) => {
			const key = `${chain}:${token1Address}`
			const cached = cache.get(key)
			if (cached !== undefined) return cached
			const price = await this.getVenueUsdPrice(chain, token1Address)
			cache.set(key, price)
			return price
		}
	}

	/**
	 * Validates a live venue quote against the static reference price for the chain.
	 * Returns true (pass) when no guard is configured, or no reference exists for the
	 * chain. Returns false when the quote (token1 per USD) deviates from the reference
	 * by more than `maxDeviationBps`, in which case the order must not be filled.
	 */
	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {
			this.logger.warn(
				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
	}

```text
## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.
```
