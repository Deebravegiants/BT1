## Analysis: LDAP DN/Filter Injection in Login Bind Path

The strongest reachable analog to the Traefik "unescaped user input interpolated into a structural sub-language causing an authorization bypass" bug class is in `core/sessions/ldapauth/ldap.go`, `CreateSession`. Just as Traefik interpolated untrusted `hosts[]`/`headers[].exact` values into a *rule* grammar using an escaping function meant for a different context (or no escaping at all), Chainlink's LDAP authenticator interpolates the attacker-supplied login `email` into an LDAP **Distinguished Name (DN)** string using `ldap.EscapeFilter`, which only escapes LDAP **filter** metacharacters (`\`, `*`, `(`, `)`, NUL) — not DN metacharacters (`,`, `+`, `"`, `<`, `>`, `;`, leading `#`/space, trailing space). This is the exact "escaped for the wrong grammar" root cause pattern described in the report.

### Title
LDAP Bind DN Injection via Filter-Escaped (not DN-escaped) Email in Login Path - (File: core/sessions/ldapauth/ldap.go)

### Summary
`CreateSession` builds the LDAP bind DN by concatenating the unprivileged, unauthenticated caller-supplied `sr.Email` (escaped only with `ldap.EscapeFilter`) directly into a DN string, then calls `conn.Bind(searchBaseDN, sr.Password)`.

`ldap.EscapeFilter` (from `go-ldap/ldap/v3`) only escapes filter syntax characters, not DN syntax characters. A `,` in the supplied email is passed through untouched, letting the caller append additional RDN components after the constructed `uid=<email>` fragment and change which DN the server attempts to bind against — analogous to how a backtick in a Knative host/header value terminated Traefik's rule literal and injected new rule operators. There is no length/character-class validation of `sr.Email` prior to this construction, and there is no check preventing an empty `sr.Password`, which under RFC 4513 §5.1.2 many LDAP servers process as an "unauthenticated bind" that returns success for any syntactically valid DN, independent of whether the credentials are correct.

`SessionRequest.Email`/`Password` originate from the public login HTTP endpoint and are fully attacker-controlled before any authentication has occurred — this is the unprivileged-actor entry point equivalent to Knative's `rules[].hosts[]`/`headers[].exact`.

### Impact Explanation
If the upstream LDAP server has unauthenticated binds enabled (a common default/misconfiguration, and not something this Go client verifies or defends against), an attacker can:
1. Submit a login request with a crafted `email` containing a `,`-separated DN suffix that resolves to a different (target) entry's DN, and an empty `password`.
2. `conn.Bind` returns success (unauthenticated bind), bypassing password verification entirely.
3. The code proceeds to `l.FindUser(ctx, escapedEmail)` and, on success, creates an authenticated `ldap_sessions` row and returns a valid session ID — i.e., full authentication bypass / role assumption without any valid credentials, directly comparable to the Traefik "host/header restriction bypass" that let requests reach unauthorized destinations.

### Likelihood Explanation
Reachable directly from the unauthenticated `CreateSession`/login flow with no privileges required; the escaping-mismatch defect is unconditional code, only the exploitability depends on whether the LDAP server accepts unauthenticated binds — a widely documented, common misconfiguration this client-side code does nothing to reject.

### Recommendation
- Reject empty/near-empty `sr.Password` before calling `conn.Bind` (never allow unauthenticated bind for this login path).
- Escape user-supplied values for DN construction using a proper DN-escaping routine (e.g., manually escaping `,`, `+`, `"`, `\`, `<`, `>`, `;`, leading `#`/space, trailing space), not `ldap.EscapeFilter`, or better, avoid building DNs by string concatenation and instead perform a filtered search to resolve the DN, then bind against the resolved DN only.
- Apply the same review to every other `fmt.Sprintf`-built DN/filter in `core/sessions/ldapauth/ldap.go` and `sync.go` to confirm filter-context values only ever flow into filters and DN-context values are DN-escaped.

### Proof of Concept
1. POST to the login endpoint with `email = "x,uid=admin,ou=users,dc=example,dc=com"` and `password = ""`.
2. `escapedEmail` remains `x,uid=admin,ou=users,dc=example,dc=com` (comma untouched by `EscapeFilter`).
3. `searchBaseDN` becomes `uid=x,uid=admin,ou=users,dc=example,dc=com,<UsersDN>,<BaseDN>` — a malformed/attacker-influenced DN string passed to `conn.Bind` with an empty password.
4. On an LDAP server permitting unauthenticated binds, `conn.Bind` returns `nil` (success) regardless of DN correctness, and `CreateSession` proceeds to mint a valid `ldap_sessions` entry for the attacker. [2](#0-1)

// CreateSession will forward the session request credentials to the
// LDAP server, querying for a user + role response if username and
// password match. The API call is blocking with timeout, so a sufficient timeout
// should allow the user to respond to potential MFA push notifications
func (l *ldapAuthenticator) CreateSession(ctx context.Context, sr sessions.SessionRequest) (string, error) {
	conn, err := l.ldapClient.CreateEphemeralConnection()
	if err != nil {
		return "", errors.New("unable to establish connection to LDAP server with provided URL and credentials")
	}
	defer conn.Close()

	var returnErr error

	// Attempt to LDAP Bind with user provided credentials
	escapedEmail := ldap.EscapeFilter(strings.ToLower(sr.Email))
	searchBaseDN := fmt.Sprintf("%s=%s,%s,%s", l.config.BaseUserAttr(), escapedEmail, l.config.UsersDN(), l.config.BaseDN())
	if err = conn.Bind(searchBaseDN, sr.Password); err != nil {
		l.lggr.Infof("Error binding user authentication request in LDAP Bind: %v", err)
		returnErr = errors.New("unable to log in with LDAP server. Check credentials")
	}

	// Bind was successful meaning user and credentials are present in LDAP directory
	// Reuse FindUser functionality to fetch user roles used to create ldap_session entry
	// with cached user email and role
	foundUser, err := l.FindUser(ctx, escapedEmail)
	if err != nil {
		l.lggr.Infof("Successful user login, but error querying for user groups: user: %s, error %v", escapedEmail, err)
		returnErr = errors.New("log in successful, but no assigned groups to assume role")
	}

	isLocalUser := false
	if returnErr != nil {
		// Unable to log in against LDAP server, attempt fallback local auth with credentials, case of local CLI Admin account
		// Successful local user sessions can not be managed by the upstream server and have expiration handled by the reaper sync module
		foundUser, returnErr = l.localLoginFallback(ctx, sr)
		isLocalUser = true
	}

	// If err is still populated, return
	if returnErr != nil {
		return "", returnErr
	}
