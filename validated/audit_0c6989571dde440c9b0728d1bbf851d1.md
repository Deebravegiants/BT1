### Title
Unbounded index-scaled debt valuation permanently freezes a market - (File: `common/src/rates/simulate.rs`)

### Summary
A sufficiently large and heavily borrowed market can cross the `i128` RAY-value domain before the borrow index reaches its cap. Once this happens, the mandatory accrual step always panics while converting scaled debt to its original value, leaving suppliers, borrowers, and liquidators unable to operate on the market.

### Finding Description
`accrue_step` first computes `borrowed_original` by multiplying `borrowed` by the current `borrow_index`, and similarly computes the supplied value before updating either index. [1](#0-0) 

`scaled_to_original` delegates to `Ray::mul`, which panics with `MathOverflow` if the resulting RAY value cannot fit in `i128`. [2](#0-1) [3](#0-2) [4](#0-3) 

The index ceiling in `update_borrow_index` does not prevent this failure because accrual first converts `borrowed` using the already stored index; if that product exceeds `i128`, execution never reaches the later index cap. [5](#0-4) [6](#0-5) 

`global_sync` runs this accrual for every elapsed market before the operation-specific mutation. [7](#0-6) [8](#0-7) 

The repository’s deterministic test demonstrates this exact failure: after sustained high utilization, `update_indexes` reverts with `MathOverflow`, subsequent `withdraw` and `repay` calls hit the same error, and the test states that liquidation is likewise unavailable. [9](#0-8) 

### Impact Explanation
This is a permanent market-level freeze of user funds: suppliers cannot withdraw, borrowers cannot repay, liquidators cannot liquidate, flash loans and strategy creation cannot draw from the market, and recapitalization cannot repair the book because each pool mutation accrues first. [10](#0-9) [11](#0-10) 

The committed index remains below `MAX_BORROW_INDEX_RAY`, so waiting does not let the normal cap bypass the overflow. [12](#0-11) 

An account’s other markets remain independently usable, but every position operation touching the frozen market fails; this can also permanently trap collateral on otherwise solvent accounts whose risk evaluation needs that market. [13](#0-12) 

### Likelihood Explanation
The trigger is reachable by an unprivileged account through normal `supply` and `borrow` calls, followed by the permissionless authenticated `update_indexes` entrypoint or any later mutation touching the market. [14](#0-13) [15](#0-14) 

The controller forwards `update_indexes` directly to the pool, which runs the accrual path for each requested `HubAssetKey`. [16](#0-15) [17](#0-16) [18](#0-17) 

The attack is capital- and configuration-dependent: the asset’s decimals and listed caps must admit a book large enough that `borrowed * borrow_index` approaches `i128::MAX`, and enough ledger time must pass at a sufficiently high borrow rate. [19](#0-18) 

Those preconditions do not make the bug unreachable: the harness creates an admitted 18-decimal market, supplies one billion whole tokens, borrows 98%, advances time, and reaches the overflow before the documented index ceiling. [20](#0-19) 

### Recommendation
Enforce a numeric invariant that `supplied * MAX_SUPPLY_INDEX_RAY` and `borrowed * MAX_BORROW_INDEX_RAY` remain representable throughout market admission and every supply or borrow mutation.

At minimum:

- Calculate scaled-cap admission using the maximum possible index growth, not only the current index.
- Add a pre-accrual representability check that caps or safely handles `scaled * index` before `scaled_to_original` can panic.
- If debt value exceeds the representable domain, clamp the aggregate valuation to a defined maximum and allow repayments, withdrawals, liquidation, and recapitalization to proceed under explicit accounting rules.
- Emit an alertable event when a market approaches the representability boundary.

Changing only `update_borrow_index` is insufficient because the failing multiplication happens before the index is updated. [21](#0-20) 

### Proof of Concept
The existing harness test is a direct reproduction:

1. Create an 18-decimal market with the steep `xlm_curve()` and a separate collateral market. [22](#0-21) 
2. Call `Controller::supply(caller=attacker, account_id=0, spoke_id=S, assets=[(BIG18, 1_000_000_000 * 10^18)])`.
3. Supply sufficient collateral in the second market.
4. Call `Controller::borrow(caller=attacker, account_id=A, borrows=[(BIG18, 980_000_000 * 10^18)], to=None)`. [23](#0-22) 
5. Advance ledger time and repeatedly call `Controller::update_indexes(caller=anyone, assets=[BIG18])` until the stored index makes `borrowed * borrow_index > i128::MAX`. [24](#0-23) 
6. Observe that `update_indexes`, `withdraw`, and `repay` all revert with `MathOverflow`, while `borrow_index < MAX_BORROW_INDEX_RAY`. [12](#0-11)

```rust
/// Computes `x * y / d` rounded half up. Requires `x >= 0`, `y >= 0`, and `d > 0`; a
/// `debug_assert` checks this in debug builds. Panics with `GenericError::DivisionByZero` if
/// `d == 0`, and with `GenericError::MathOverflow` if any other precondition is violated or if
/// the result does not fit in `i128`.
pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {

    );

        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
```

```rust
/// Applies `interest_factor` to `old_index` to produce the new borrow index,
/// capped at `MAX_BORROW_INDEX_RAY`.
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}
```

```rust
/// Accrues borrow/supply indexes from `last_timestamp` to the cache's current time.
///
/// No-op when no time has elapsed. Splits long gaps into max-sized compound
/// windows, then sets `last_timestamp` to `current_timestamp`.
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

```rust
        cache.borrow_index(),
```

```rust
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
