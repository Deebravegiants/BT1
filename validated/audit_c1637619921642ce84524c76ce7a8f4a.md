### Title
`Bonding.canGraduate`'s unguarded `exchangeRate()` call freezes sells (and buys) of any pre-graduation token if the reserve LT's price view reverts - (File: `packages/contracts/src/Bonding.sol`)

### Summary
`Bonding.canGraduate` calls `IBounceLeveragedToken(info.ltAddress).exchangeRate()` directly, with no try/catch or fallback, whenever a curve-stage token's pair still holds a nonzero token balance. This external view is read unconditionally on every buy and every sell of a `Lifecycle.Curve` token, so a revert on the LT side — the exact bug class flagged in the external Chainlink report (an external price source that can stop responding at will) — bricks both trade directions for that token, not just buys as the codebase's own documentation assumes.

### Finding Description
`canGraduate` at [1](#0-0)  only short-circuits via the supply trigger (`IPair(pair).tokenBalance() == 0`); otherwise it unconditionally calls `IBounceLeveragedToken(info.ltAddress).exchangeRate()` with no `try/catch`:

```
if (IPair(pair).tokenBalance() == 0) return true;
(, uint256 assetReserve) = IPair(pair).getReserves();
uint256 realLtRaised = assetReserve - _launchTimeVirtualLtReserve(token_, pair);
uint256 valueUsd = (realLtRaised * IBounceLeveragedToken(info.ltAddress).exchangeRate()) / 1e18;
```

This function is reached from three unprivileged-triggerable call sites that do not wrap it defensively:
- `Bonding._executeBuy` calls `canGraduate(tokenAddress)` at the end of every curve buy: [2](#0-1) .
- `Zap._sellInternal` calls `bonding_.canGraduate(tokenAddress)` directly before executing any sell of a curve-stage token: [3](#0-2) .
- `Bonding.triggerGraduation` also calls it: [4](#0-3) .

Additionally, `Zap._executeBuy` separately calls `Bonding.previewLtUntilGraduation`, which itself unconditionally calls the same `exchangeRate()`: [5](#0-4) , invoked at [6](#0-5) .

This directly contradicts the protocol's own stated design guarantee in `Zap.sol`, which documents that sells should always remain available even if the LT operator pauses `mint`, because "sells go through `redeem`, not `mint`": [7](#0-6) . That guarantee is broken because `_sellInternal` reads `canGraduate` — and therefore `exchangeRate()` — *before* it ever reaches `redeem`.

### Impact Explanation
If the LT's `exchangeRate()` view reverts for any reason outside alt.fun's control (BounceTech pausing the view, an internal price-source failure, or any other external gate on that call — the same risk class the external report raises for a blocked Chainlink feed), every `Zap.buy` and `Zap.sell` for that pre-graduation token reverts. Because curve trading requires no other path to exit (holders cannot sell tokens on a DEX until graduation, and `triggerGraduation`/the buy path that would push it to graduation are equally blocked), trader funds are frozen inside the curve for as long as the external view remains unavailable. This is a full denial of service on both trade directions of a launched, pre-graduation token — a stronger and more damaging effect than the mint-only DoS the codebase explicitly accepts as a v1 tradeoff.

### Likelihood Explanation
No attacker action is required — the trigger is purely a failure/pause of the external LT's `exchangeRate()` view, which alt.fun does not control. Any single unprivileged trader submitting `Zap.buy` or `Zap.sell` on a `Lifecycle.Curve` token whose pair still has `tokenBalance() != 0` will hit this path on every call, so the DoS surfaces immediately and uniformly the moment the external view starts reverting.

### Recommendation
Wrap the `exchangeRate()` read inside `canGraduate` (and the equivalent read in `previewLtUntilGraduation`) in a `try/catch`. On revert, `canGraduate` should treat the USD leg as not-yet-satisfied (return `false`) rather than propagating the revert, so that:
- `Zap.sell` can still proceed to `redeem()` (which is documented to remain available even when other LT operations are paused),
- `Zap.buy` can still execute a non-capped curve buy without depending on the USD-trigger check succeeding,
- the supply trigger and manual `triggerGraduation` retries remain the only paths gated by `exchangeRate()` succeeding.

### Proof of Concept
1. Launch a token via `Bonding.launch` and perform a normal curve buy through `Zap.buy` so the pair holds `tokenBalance() > 0` (curve not yet exhausted) and `Lifecycle.Curve`.
2. Configure (or, for the mock, simulate) the paired LT's `exchangeRate()` to revert instead of returning a value — modeling BounceTech pausing or gating that view, analogous to a blocked Chainlink feed.
3. Call `Zap.sell(tokenAddress, tokenAmount, 0)` as any holder: `_sellInternal` calls `bonding_.canGraduate(tokenAddress)` at [8](#0-7) , which calls `exchangeRate()` and reverts, so the whole sell transaction reverts before ever reaching `redeem()`.
4. Call `Zap.buy(tokenAddress, usdcAmount, 0, address(0))`: `_executeBuy` computes `previewLtUntilGraduation` (which calls `exchangeRate()`) before minting, and also calls `canGraduate` at the end of the buy — both revert, so buys are blocked too.
5. With `exchangeRate()` reverting indefinitely, the token is permanently untradeable in both directions while still pre-graduation, freezing all holders' funds in the curve.

    function canGraduate(
        address token_
    ) public view returns (bool) {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[token_];
        if (info.creator == address(0)) return false;
        if (info.lifecycle != Lifecycle.Curve) return false;

        address pair = info.pair;
        if (IPair(pair).tokenBalance() == 0) return true;

        (, uint256 assetReserve) = IPair(pair).getReserves();
        uint256 realLtRaised = assetReserve - _launchTimeVirtualLtReserve(token_, pair);
        uint256 valueUsd = (realLtRaised * IBounceLeveragedToken(info.ltAddress).exchangeRate()) / 1e18;
        return valueUsd >= $.graduationThresholdUsd;
    }

    function previewLtUntilGraduation(
        address token_
    ) external view returns (uint256) {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[token_];
        if (info.creator == address(0)) return 0;
        if (info.lifecycle != Lifecycle.Curve) return 0;

        address pair = info.pair;
        uint256 realBalance = IPair(pair).tokenBalance();
        if (realBalance == 0) return 0;

        (uint256 reserveToken, uint256 reserveAsset) = IPair(pair).getReserves();

        uint256 ltUntilThreshold = type(uint256).max;
        uint256 exchangeRate = IBounceLeveragedToken(info.ltAddress).exchangeRate();
        if (exchangeRate > 0) {
            uint256 realLtRaised = reserveAsset - _launchTimeVirtualLtReserve(token_, pair);
            uint256 thresholdRealLt = ($.graduationThresholdUsd * 1e18 + exchangeRate - 1) / exchangeRate;
            if (realLtRaised >= thresholdRealLt) return 0;
            ltUntilThreshold = thresholdRealLt - realLtRaised;
        }
