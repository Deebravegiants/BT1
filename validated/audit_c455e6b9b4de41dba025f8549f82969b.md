### Title
Unbounded LayerZero message payload lets an attacker permanently jam a shared inbound channel in `HyperbridgeLzEndpoint` - (File: `sdk/packages/lz-endpoint/contracts/HyperbridgeLzEndpoint.sol`)

### Summary
`HyperbridgeLzEndpoint.send()` accepts an arbitrary-length `_params.message` with no size cap and packs it verbatim into the ISMP request body. `onAccept()` enforces strict, LayerZero-style sequential nonce delivery per `(receiver, srcEid, sender)` channel, and it decodes/commits that nonce logic *before* any delivery outcome is known. If a message is large enough that `onAccept` can never complete within any achievable block gas limit on the destination chain, that nonce can never be committed, and — because delivery is strictly sequential — every subsequent message on that same channel is permanently blocked. This reproduces the exact "excessively large payload breaks LayerZero communication" bug class described in the external report, adapted to Hyperbridge's LZ-compatibility shim.

### Finding Description
`send()` builds the ISMP body directly from caller-supplied data with no length checks: [1](#0-0) 

On the receiving side, `onAccept()`:
1. ABI-decodes the full body (including the attacker-sized `message`) — this happens unconditionally, before any nonce bookkeeping.
2. Enforces that `nonce` must equal `expectedNonce = _inboundNonce[receiver][srcEid][sender] + 1`, and only advances `_inboundNonce` after that check passes: [2](#0-1) 

The comment at lines 375–378 shows the authors were aware of, and specifically engineered around, LayerZero's classic head-of-line-blocking failure mode by committing the nonce *before* invoking the OApp's `lzReceive` inside a `try/catch`: [3](#0-2) 

However, that mitigation only protects against `lzReceive` reverting — it does nothing if `onAccept` itself reverts or runs out of gas *before* line 382, which is exactly what an oversized `message` causes (ABI-decoding/copying a huge `bytes` payload into memory has quadratic memory-expansion cost, and downstream `lzReceive` calls forwarding that data will also need proportionally more gas).

`onAccept` is invoked by `EvmHost.dispatchIncoming` via a raw, ungated `.call()`: [4](#0-3) 

If that call runs out of gas (bounded by the destination chain's block gas limit, which no relayer can exceed), `dispatchIncoming` swallows the failure and simply leaves the request undelivered/retryable — it does not revert the whole `handlePostRequests` batch. But because the message is *unconditionally* too large to ever execute within a block, retrying is futile: the nonce commit in `onAccept` (line 382) is never reached, so `_inboundNonce[receiver][srcEid][sender]` never advances past the stuck value.

Because `_outboundNonce`/`_inboundNonce` are keyed by `msg.sender` — the calling OApp contract address, not the end user — any application built on top of this endpoint (e.g. an OFT-style token bridge) shares one nonce sequence across all of its users for a given `(receiver, srcEid)` pair. A single malicious end user who can influence the size of the `message`/payload the OApp forwards into `send()` (directly analogous to `_toAddress` in the original `OFTCore#sendFrom` report) can jam that shared channel, blocking delivery for every other user of that OApp to that destination — not just their own transactions.

### Impact Explanation
Once a nonce is unrecoverably stuck, `onAccept` will reject every future message on that `(receiver, srcEid, sender)` channel with `InvalidNonce` forever, since `expectedNonce` can never advance. This permanently freezes all subsequent cross-chain deliveries for that OApp-to-receiver route (e.g., all future token transfers through an OFT bridging via this endpoint), matching the "route unable to deliver messages" / permanent freezing-of-funds impact class. There is no `skip()`/nilify path available for a nonce that was never committed, since those recovery functions operate on already-tracked `_inboundNonce` values and stored payload hashes, neither of which get populated when `onAccept` reverts before line 382.

### Likelihood Explanation
`send()` is externally callable and payable with no payload-size restriction, and `onAccept`'s decode step runs unconditionally before nonce bookkeeping. Any address able to invoke `send()` with a sufficiently large `_params.message` (directly, or indirectly by driving an OApp that forwards user-supplied data unchecked) can trigger this deterministically and cheaply on the source chain, with the damage manifesting at delivery time on the destination chain — no privileged role or special conditions are required.

### Recommendation
Enforce a maximum payload size in `send()` before dispatching (mirroring the size guard LayerZero's own `RelayerV2` added to fix this exact issue), e.g. bound `_params.message.length` (and thus `body.length`) to a value provably deliverable within the smallest connected chain's block gas limit. Additionally, consider decoding/validating and committing the nonce in `onAccept` using a gas-bounded path (e.g., cap the amount of `message` data read before nonce advancement, or split "record nonce" from "attempt execution" so a too-large payload can be nonce-advanced and dropped/skipped rather than blocking the channel outright).

### Proof of Concept
1. Deploy/point an OFT-style OApp at `HyperbridgeLzEndpoint` as its LayerZero endpoint.
2. As a malicious user, invoke the OApp's send path (or call `HyperbridgeLzEndpoint.send()` directly) with `_params.message` sized so that decoding it plus the resulting `lzReceive` call on the destination chain cannot complete within that chain's block gas limit (e.g., several hundred KB of data).
3. A relayer submits the resulting ISMP `PostRequest` via `HandlerV2.handlePostRequests` → `EvmHost.dispatchIncoming` → `HyperbridgeLzEndpoint.onAccept`; the call always runs out of gas before reaching `_inboundNonce[...] = nonce;` (line 382), so `dispatchIncoming` leaves the request permanently undelivered.
4. Any subsequent legitimate message from the same OApp (`msg.sender`) to the same `receiver`/`srcEid` on the destination chain is assigned a higher nonce and is rejected by `if (nonce != expectedNonce) revert InvalidNonce(...)` (line 381) forever, since `expectedNonce` is frozen at the stuck value.     function onAccept(IncomingPostRequest calldata incoming) external override onlyHost whenNotPaused {
        PostRequest calldata request = incoming.request;

        // Verify source is this adapter on another chain
        if (keccak256(request.from) != keccak256(abi.encodePacked(address(this)))) revert UnknownSource();

        // Decode the LZ message from the ISMP body
        (
            bytes32 guid,
            uint32 srcEid,
            bytes32 sender,
            uint64 nonce,
            bytes32 receiver,
            bytes memory message
        ) = abi.decode(request.body, (bytes32, uint32, bytes32, uint64, bytes32, bytes));

        // Reject `expectedEid == 0` so unconfigured sources don't collide with `srcEid = 0`.
        uint32 expectedEid = _stateMachineToEid[keccak256(request.source)];
        if (expectedEid == 0 || expectedEid != srcEid) revert UnknownSource();

        // Validate and advance the nonce. The nonce is committed BEFORE (and independently of)
        // OApp execution: a reverting `lzReceive` must not roll back this write. Otherwise the
        // message would be retried forever at the same nonce and every later nonce would be
        // permanently rejected, bricking the (receiver, srcEid, sender) channel.
        address receiverAddr = address(uint160(uint256(receiver)));
        uint64 expectedNonce = _inboundNonce[receiverAddr][srcEid][sender] + 1;
        if (nonce != expectedNonce) revert InvalidNonce(expectedNonce, nonce);
        _inboundNonce[receiverAddr][srcEid][sender] = nonce;

    function dispatchIncoming(PostRequest memory request, address relayer) external restrict(_hostParams.handler) {
        address destination = _bytesToAddress(request.to);
        uint256 size;
        assembly {
            size := extcodesize(destination)
        }
        if (size == 0) {
            // instead of reverting the entire batch, early return here.
            return;
        }

        // replay protection
        bytes32 commitment = request.hash();
        _requestReceipts[commitment] = relayer;

        (bool success,) = address(destination)
            .call(abi.encodeWithSelector(IApp.onAccept.selector, IncomingPostRequest(request, relayer)));

        if (!success) {
            // so that it can be retried
            delete _requestReceipts[commitment];
            return;
        }
        emit PostRequestHandled({commitment: commitment, relayer: relayer});
    }
