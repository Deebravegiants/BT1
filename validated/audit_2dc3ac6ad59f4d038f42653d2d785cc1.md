Audit Report

## Title
Unbounded `activeRequests` map growth in the Gateway Vault handler's unauthenticated `PublicKeyGet` path enables a persistent memory-exhaustion DoS - (File: core/services/gateway/handlers/vault/handler.go)

## Summary
`HandleJSONRPCUserMessage` explicitly bypasses `requestProcessor.ProcessRequest` (the sole authorization gate in this handler) for `vaulttypes.MethodPublicKeyGet` whenever the cached public key is empty, and instead calls `h.newActiveRequest(req, callback)` directly. [1](#0-0)  `newActiveRequest` only rejects a request if its exact `req.ID` string is already present in the map — it enforces no maximum size on `h.activeRequests`. [2](#0-1)  Since `req.ID` is attacker-controlled and only length-bounded (200 chars), an attacker able to reach the gateway's HTTP endpoint during any window when the cached public key is nil can insert an unbounded number of entries into `h.activeRequests`, each surviving until the 5-second reaper (`defaultCleanUpPeriod`) expires it after `h.requestTimeout`. [3](#0-2) [4](#0-3) 

## Finding Description
This is a genuine, verified structural gap. Contrast with `core/services/gateway/handlers/common/requestcache.go`, which implements the analogous "pending request" pattern used elsewhere in the gateway and *does* enforce a hard `maxCacheSize`, rejecting new entries once the cache is full: [5](#0-4) . The vault handler's `activeRequest` map has no equivalent size check, relying purely on the time-based reaper for bounding.

The exploit precondition is that `h.getCachedPublicKey()` returns `nil`, which happens: (1) during gateway startup, since the periodic refresh ticker (`tickerVaultPublicKeyRefresh`, 1 minute) does not fire immediately on `Start()` — Go's `Ticker` only fires after the first full interval elapses, so there is a real window (up to ~1 minute) at process start where the cache is empty; and (2) any time `fetchVaultPublicKey` fails to get a quorum response from nodes (e.g., transient node unavailability), since there is no retry-with-backoff — the cache remains empty until the next 1-minute tick. During that window, every JSON-RPC POST to the gateway's user-facing endpoint with `method: vaulttypes.MethodPublicKeyGet` and a unique `id` goes straight into `activeRequests` with no authorization and no capacity limit. [6](#0-5) 

I also confirmed `defaultPublicKeyGetCacheDurationSeconds` is declared but never referenced anywhere else in the codebase — it is dead code, meaning once the cache is populated it never expires by design (contrary to what the constant name implies), which actually *narrows* the long-term exposure window to essentially "process startup / node outage" rather than a recurring 300-second cycle claimed in the report's likelihood section. This is a factual correction to the original submission: the report's claim of periodic cache-miss windows every ~300s is not supported by the code — the cache is populated once and kept indefinitely absent a code path that clears it.

I could not fully verify whether an upstream layer (e.g., a per-IP or global rate limiter in `core/services/gateway/network/httpserver.go`) throttles requests before they reach `gateway.ProcessRequest` → `HandleJSONRPCUserMessage`; the code I reviewed shows a `MaxRequestBytesLimiter` (payload size cap) and a JWT-extraction step but no visible per-connection/per-IP request-rate limiting at that layer. [7](#0-6)  This is a genuine indexing/read limitation — the full `httpserver.go` `ensureLimiters` implementation was not completely inspected, so the presence/absence of a global inbound rate limiter at the transport layer that could mitigate this remains unconfirmed.

## Impact Explanation
Within the confirmed exploit window (gateway startup before the first successful public-key fetch, or during any node-quorum outage affecting `fetchVaultPublicKey`), an unauthenticated remote client can drive unbounded heap allocation in the gateway process by sending `PublicKeyGet` requests with unique IDs faster than the 5-second reaper drains them. This maps to a legitimate in-scope DoS/resource-exhaustion impact category, consistent with the "unbounded allocation via unauthenticated request" pattern the report cites. The severity is bounded by the fact that the exposure window is transient (process startup or node-outage duration) rather than continuously exploitable in steady state, since the cache — once populated — is never invalidated.

## Likelihood Explanation
Likelihood is real but time-bound: exploitable primarily during gateway process startup (a window of up to ~1 minute before the first periodic public-key refresh fires) or during DON quorum unavailability for the public-key fetch. An attacker needs no credentials, only network access to the gateway's HTTP endpoint and the ability to generate unique 200-char-max request IDs, which is trivial. Once the cache is successfully populated, this specific path (`cachedPublicKey == nil`) is no longer reachable and the handler falls back to the synchronous cached-response path, closing the window.

## Recommendation
Add a hard cap on `h.activeRequests` size (mirroring `RequestCache`'s `maxCacheSize` pattern in `core/services/gateway/handlers/common/requestcache.go`) and reject new entries in `newActiveRequest` once the cap is reached. Additionally, consider applying a lightweight rate limiter specifically to the unauthenticated `PublicKeyGet` fast path (e.g., using the same `ratelimit.RateLimiter` infrastructure already present in the handler for node responses) so that even during the cache-miss window, the volume of concurrently pending entries is capped independent of the reaper interval.

## Proof of Concept
1. Start a gateway node with an empty vault public-key cache (fresh startup, before the first `tickerVaultPublicKeyRefresh` fire, or force node quorum failure so `fetchVaultPublicKey` cannot populate the cache).
2. From an unauthenticated client, repeatedly `POST` JSON-RPC requests to the gateway's user endpoint with `method: vaulttypes.MethodPublicKeyGet` and a fresh unique `id` on each request, at a rate exceeding what the 5-second reaper (`defaultCleanUpPeriod`) can drain.
3. Instrument/heap-profile the gateway process and observe `h.activeRequests` size grow unbounded for the duration of the cache-miss window, since `newActiveRequest` (core/services/gateway/handlers/vault/handler.go:457-472) performs no capacity check before insertion.
4. Confirm that once the cache is populated (either naturally via the 1-minute ticker or by forcing a successful `fetchVaultPublicKey`), further `PublicKeyGet` requests take the synchronous cached path and no longer grow the map — demonstrating the vulnerability is real but time-window-bound rather than perpetually exploitable.

func (h *handler) Start(_ context.Context) error {
	return h.StartOnce("VaultHandler", func() error {
		h.lggr.Debug("starting vault handler")
		if h.jwtAuth != nil {
			if err := h.jwtAuth.Start(context.Background()); err != nil {
				return fmt.Errorf("failed to start JWTBasedAuth: %w", err)
			}
		}
		go func() {
			ctx, cancel := h.stopCh.NewCtx()
			defer cancel()
			ticker := h.clock.NewTicker(defaultCleanUpPeriod)
			tickerVaultPublicKeyRefresh := h.clock.NewTicker(1 * time.Minute)
			defer ticker.Stop()
			defer tickerVaultPublicKeyRefresh.Stop()
			for {
				select {
				case <-ticker.Chan():
					h.removeExpiredRequests(ctx)
				case <-tickerVaultPublicKeyRefresh.Chan():
					// periodically, fetch vault public key, so we can cache it
					h.fetchVaultPublicKey(ctx)
				case <-h.stopCh:
					return
				}
			}
		}()
		return nil
	})
}

// removeExpiredRequests removes expired requests from the pending requests map
func (h *handler) removeExpiredRequests(ctx context.Context) {
	h.mu.RLock()
	var expiredRequests []*activeRequest
	now := h.clock.Now()
	for _, userRequest := range h.activeRequests {
		if now.Sub(userRequest.createdAt) > h.requestTimeout {
			expiredRequests = append(expiredRequests, userRequest)
		}
	}
	h.mu.RUnlock()

	for _, er := range expiredRequests {
		responses := er.copiedResponses()
		var nodeResponses strings.Builder
		for nodeKey, nodeResponse := range responses {
			_, _ = fmt.Fprintf(&nodeResponses, "%s ---::: %v               ", nodeKey, nodeResponse)
		}
		nodeResponsesStr := nodeResponses.String()
		err := h.sendResponse(ctx, er, h.errorResponse(er.req, api.RequestTimeoutError, errors.New("request expired without getting quorum of responses from nodes. Available responses: "+nodeResponsesStr), []byte(nodeResponsesStr)))
		if err != nil {
			h.lggr.Errorw("error sending response to user", "requestID", er.req.ID, "error", err)
		}
	}
}

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

func NewRequestCache[T any](timeout time.Duration, maxCacheSize uint32) RequestCache[T] {
	return &requestCache[T]{cache: make(map[globalID]*pendingRequest[T]), timeout: timeout, maxCacheSize: maxCacheSize}
}

func (c *requestCache[T]) NewRequest(lggr logger.Logger, request *api.Message, callback handlers.Callback, responseData *T) error {
	if request == nil {
		return errors.New("request is nil")
	}
	if responseData == nil {
		return errors.New("responseData is nil")
	}
	key := globalID{request.Body.Sender, request.Body.MessageID}
	c.mu.Lock()
	defer c.mu.Unlock()
	_, ok := c.cache[key]
	if ok {
		return errors.New("request already exists")
	}
	if len(c.cache) >= int(c.maxCacheSize) {
		return errors.New("request cache is full")
	}

func (s *httpServer) handleRequest(w http.ResponseWriter, r *http.Request) {
	if s.config.CORSEnabled {
		origin := r.Header.Get("Origin")
		if s.isAllowedOrigin(origin) {
			w.Header().Set("Access-Control-Allow-Origin", origin)
			w.Header().Set("Access-Control-Allow-Methods", "GET, POST, OPTIONS")
			w.Header().Set("Access-Control-Allow-Headers", "Content-Type")
		}

		// handle preflight requests
		if r.Method == http.MethodOptions {
			w.WriteHeader(http.StatusNoContent)
			return
		}
	}

	maxRequestBytes, err := s.config.MaxRequestBytesLimiter.Limit(r.Context())
	if err != nil {
		msg := "Failed to get request size limit"
		s.lggr.Errorw(msg, "err", err)
		http.Error(w, msg, http.StatusInternalServerError)
		return
	}
	source := http.MaxBytesReader(nil, r.Body, int64(maxRequestBytes))
	rawMessage, err := io.ReadAll(source)
	if err != nil {
		s.lggr.Error("error reading request", err)
		w.WriteHeader(http.StatusBadRequest)
		return
	}

	// Optionally extract jwt token from authorization header
	authHeader := r.Header.Get("Authorization")
	jwtToken := ""
	if authHeader != "" {
		jwtToken = strings.TrimPrefix(authHeader, "Bearer ")
	}

	startTime := time.Now()
	rawResponse, httpStatusCode := s.handler.ProcessRequest(r.Context(), rawMessage, jwtToken)
	duration := time.Since(startTime)
	s.hMetrics.RecordRequestDuration(r.Context(), httpStatusCode, duration)
	s.hMetrics.RecordRequestCount(r.Context(), httpStatusCode)

	w.Header().Set("Content-Type", s.config.ContentTypeHeader)
	w.WriteHeader(httpStatusCode)
	_, err = w.Write(rawResponse) //nolint:gosec // G705: response body is written with an explicit Content-Type, not rendered as HTML
	if err != nil {
		s.lggr.Error("error when writing response", err)
	}
}
