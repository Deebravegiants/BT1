### Title
Outbound HTTP header blocklist can be bypassed via header-name aliasing (underscore/dot substitution) - (File: `core/services/gateway/network/httpclient.go`)

### Summary
`httpClient.validateHeaderNames` in the gateway's outbound HTTP client enforces a security-critical header blocklist (`X-Forwarded-For`, `X-Forwarded-Host`, `X-Forwarded-Proto`, `X-Real-Ip`, `Host`, `Content-Length`, `Transfer-Encoding`, `Connection`, `Te`, `Trailer`, etc.) by doing a case-insensitive **exact string match** against the header names supplied by the workflow/node in `HTTPRequest.Headers`/`MultiHeaders`. Because the check is exact-match rather than alias-aware, a caller can substitute a non-dash separator character (e.g. `_` or `.`) inside a blocked header name to produce a still-valid HTTP token that is not in the blocklist, bypassing the check entirely while still being interpreted by many downstream servers/proxies as the trusted name.

### Finding Description
`validateHeaderNames` lower-cases both the configured blocklist and the incoming header names and does a map lookup: [1](#0-0) 

The blocklist itself explicitly exists to stop framing/spoofing attacks (`x-forwarded-for` "prevents IP spoofing", `host` "target host is set in the http client", `trailer` "blocks delayed header injection after request body", `content-length`/`transfer-encoding` guard request smuggling): [2](#0-1) 

Header names such as `X_Forwarded_For`, `X.Forwarded.For`, `Content_Length`, or `Connection.` are syntactically valid HTTP header field names (underscore and dot are legal `tchar` characters), so Go's `net/http` accepts and forwards them unmodified except for MIME canonicalization. `textproto.CanonicalMIMEHeaderKey` only re-capitalizes letters following a literal `-`; a letter following `_` or `.` is *lower-cased instead*, so `X_Forwarded_For` canonicalizes to `X_forwarded_for` — a distinct token from `X-Forwarded-For`, and therefore also distinct from every entry in `defaultBlockedHeaders`. This is exactly the aliasing mechanism described in the Traefik advisory (`X_Auth_User` surviving as an alias of `X-Auth-User`).

Because the blocklist check is a strict lower-cased equality test rather than an alias-normalizing test (as Traefik's `isAliasingHeaderName` attempts to be for its own defenses), the aliased spelling sails through `validateHeaderNames` and is then written into the outgoing request: [3](#0-2) 

This client is fed directly from JSON-RPC-carried `OutboundHTTPRequest` data that traverses the gateway's HTTP Actions handler on behalf of workflow HTTP-action capability calls — headers under caller control: [4](#0-3) 

### Impact Explanation
The blocklist is the only defense in this component against a workflow spoofing trust-sensitive or framing-sensitive headers when it makes gateway-proxied outbound HTTP calls to externally reachable, allowlisted URLs. An aliasing bypass lets a workflow:
- Spoof `X-Forwarded-For`/`X-Real-Ip`/`X-Forwarded-Host`/`X-Forwarded-Proto` (via `X_Forwarded_For`, etc.) toward any destination that normalizes underscores/dots to dashes (many reverse proxies, CGI-style backends, and app frameworks do this), defeating IP-based or origin-based trust decisions on that destination — an allowlist/authorization bypass on the receiving side.
- Inject aliased `Content-Length`/`Transfer-Encoding`/`Connection` framing headers toward a destination sitting behind a normalizing proxy, which is the classic precondition for HTTP request smuggling against shared infrastructure (potential cross-user/cross-tenant response confusion for other traffic sharing that connection/proxy).
- Inject an aliased `Host` header to redirect virtual-host routing on multi-tenant destination infrastructure that the gateway's `AllowedIPs`/`AllowedIPsCIDR` was meant to scope access to.

The severity is bounded by the fact that the destination URL is otherwise constrained by `safeurl`'s IP/scheme/port allowlist, but the header blocklist is a distinct, documented control layer that this bypass fully defeats.

### Likelihood Explanation
Reachable by any workflow/node able to issue an HTTP Action request through the gateway — no special privilege beyond normal workflow authorship is required, and the bypass requires only choosing an alternate spelling for a header name, which is trivial and requires no protocol-level trickery (unlike the Traefik trailer channel, no chunked/HTTP2 trailer manipulation is needed here — it's a pure string-matching gap).

### Recommendation
Replace the exact-match blocklist check in `validateHeaderNames` with an alias-aware check: normalize header names for comparison the way any header-consuming layer conservatively should — e.g., reject or strip any header name whose canonicalized form differs from a canonical, dash-only spelling, or reject header names containing characters other than letters, digits, and `-` when they resemble a blocked family (mirroring Traefik's own fix of checking `isAliasingHeaderName` and normalizing separators before the blocklist comparison). At minimum, expand `defaultBlockedHeaders` matching to normalize `_`/`.` to `-` before lookup.

### Proof of Concept
```go
cfg := network.HTTPClientConfig{
    AllowedIPs:   []string{"<allowlisted-target-ip>"},
    AllowedPorts: []int{80, 443},
}
client, _ := network.NewHTTPClient(cfg, lggr)

// "X-Forwarded-For" is blocked by default; the aliased spelling below is not.
_, err := client.Send(ctx, network.HTTPRequest{
    Method: "GET",
    URL:    "http://<allowlisted-target>/",
    Headers: map[string]string{
        "X_Forwarded_For": "127.0.0.1", // bypasses validateHeaderNames' exact match
    },
})
// err == nil: request is sent; a backend/proxy in front of the target that
// normalizes underscores to dashes (e.g. CGI/php-style $_SERVER, some WAFs/proxies)
// will treat this as X-Forwarded-For: 127.0.0.1, spoofing trusted origin.

// validateHeaderNames checks that none of the given header names are in the blocked list (case-insensitive).
func (c *httpClient) validateHeaderNames(names []string) error {
	blockedSet := make(map[string]struct{}, len(c.config.BlockedHeaders))
	for _, b := range c.config.BlockedHeaders {
		blockedSet[strings.ToLower(b)] = struct{}{}
	}
	for _, name := range names {
		if _, blocked := blockedSet[strings.ToLower(name)]; blocked {
			return fmt.Errorf("%w: HTTP header not allowed: %s", ErrBlockedRequest, name)
		}
	}
	return nil
}

func TestHTTPClient_ValidateHeaders(t *testing.T) {
	t.Parallel()
	lggr := logger.Test(t)

	tests := []struct {
		name           string
		blockedHeaders []string
		requestHeaders map[string]string
		expectedError  string
	}{
		{
			name:           "safe headers allowed",
			blockedHeaders: []string{"keep-alive"},
			requestHeaders: map[string]string{
				"Content-Type": "application/json",
				"User-Agent":   "test-client",
			},
			expectedError: "",
		},
		{
			name:           "blocked header - host",
			blockedHeaders: []string{"host", "keep-alive"},
			requestHeaders: map[string]string{
				"Host":         "evil.com",
				"Content-Type": "application/json",
			},
			expectedError: "HTTP header not allowed",
		},
		{
			name:           "blocked header case insensitive",
			blockedHeaders: []string{"HOST", "KEEP_ALIVE"},
			requestHeaders: map[string]string{
				"host":         "evil.com",
				"Content-Type": "application/json",
			},
			expectedError: "HTTP header not allowed",
		},
		{
			name:           "blocked header - content-length",
			blockedHeaders: []string{"content-length"},
			requestHeaders: map[string]string{
				"Content-Length": "1000000",
				"Content-Type":   "application/json",
			},
			expectedError: "HTTP header not allowed",
		},
		{
			name:           "defaults block host header",
			blockedHeaders: []string{},
			requestHeaders: map[string]string{
				"Host":         "evil.com",
				"Content-Type": "application/json",
			},
			expectedError: "HTTP header not allowed",
		},
	}

	for _, tt := range tests {
		t.Run(tt.name, func(t *testing.T) {
			config := HTTPClientConfig{
				BlockedHeaders: tt.blockedHeaders,
				AllowedIPs:     []string{"127.0.0.1"},
				AllowedPorts:   []int{80, 443},
			}

			client, err := NewHTTPClient(config, lggr)
			require.NoError(t, err)

			httpClient := client.(*httpClient)
			err = httpClient.validateHeaders(tt.requestHeaders)

			if tt.expectedError != "" {
				require.Error(t, err)
				require.Contains(t, err.Error(), tt.expectedError)
				require.ErrorIs(t, err, ErrBlockedRequest, "blocked header errors should be ErrBlockedRequest")
			} else {
				require.NoError(t, err)
			}
		})
	}
}
