### Title
Unbounded recursive SCALE decode of attacker-controlled cross-chain calldata causes stack-overflow panic in `pallet-hyper-fungible-token::on_accept` - (File: modules/pallets/hyper-fungible-token/src/module.rs)

### Summary
`pallet_hyper_fungible_token`'s `IsmpModule::on_accept` decodes the `runtime_call` bytes embedded in an incoming cross-chain message with a bare `T::RuntimeCall::decode(...)`, with no recursion-depth bound. Every other place in this codebase that decodes an attacker-supplied byte-blob into a generic `RuntimeCall` (e.g. `pallet-call-decompressor`) was hardened with `decode_all_with_depth_limit` plus a documented regression test (`decompress_stack_exhaustion_poc`) specifically because unbounded `RuntimeCall::decode` on a recursively-boxed call (e.g. `Sudo::sudo(Box<RuntimeCall>)`) can be driven arbitrarily deep by an attacker and blow the decode stack. The HFT module was not given the same treatment.

### Finding Description
`Pallet::<T>::on_accept` authenticates only that the ISMP `PostRequest.from` matches a registered source contract via `ContractToAsset::<T>::get(source, &from)`: [1](#0-0) 

The message body itself, including its optional `data` field, is fully attacker/user controlled — on the EVM side, `data` is the `SendParams.data` argument that any permissionless caller of `HyperFungibleToken.send()` supplies verbatim: [2](#0-1) 

When `message.data` is non-empty, the pallet decodes it as `SubstrateCalldata` and then decodes the embedded `runtime_call: Vec<u8>` bytes with a bare, depth-unbounded `Decode`: [3](#0-2) [4](#0-3) 

`SubstrateCalldata.runtime_call` is `Vec<u8>` (opaque bytes chosen entirely by the sender): [5](#0-4) 

Compare this to `pallet-call-decompressor`, which performs the analogous "decode attacker bytes into `T::RuntimeCall`" operation but does so through `decode_all_with_depth_limit(MAX_EXTRINSIC_DECODE_DEPTH_LIMIT, ...)`, explicitly to stop a crafted, deeply-nested `Sudo::sudo(Box::new(...))` chain from exhausting the decode stack — with a dedicated regression test proving the un-guarded version panics/fails catastrophically without the limit: [6](#0-5) [7](#0-6) 

The runtime that hosts `pallet-hyper-fungible-token` also includes `pallet_sudo` (confirmed present via `parachain/runtimes/gargantua/src/weights/pallet_sudo.rs` and its inclusion in the runtime `Call` enum), which is exactly the kind of `Box<RuntimeCall>`-recursive call needed to build an arbitrarily deep nested call for the SCALE decoder to recurse into. Because the HFT decode path uses plain `Decode` instead of `decode_all_with_depth_limit`, an attacker can send a `runtime_call` blob encoding thousands of nested `Sudo::sudo(...)` wrappers; `T::RuntimeCall::decode` will recurse once per nesting level with no cap, exhausting the executor's stack during `on_accept`.

### Impact Explanation
`on_accept` runs as part of normal ISMP message delivery (`HandlerV2`/`EvmHost` → `pallet-ismp` → `IsmpModuleCallback`), triggered by any relayed cross-chain POST from a registered HFT peer contract, and the vulnerable field (`data`/`call_data`) is populated by the original unprivileged sender, not by any privileged party. A crafted payload causes the decode routine to recurse unboundedly, which — unlike a normal `Result`-returning decode failure — manifests as a stack overflow trap during block execution of the message-delivery extrinsic. This can abort/kill the executing worker or make the specific message and any batched alongside it in the block un-processable, i.e. a message-delivery route that becomes unable to complete, denying delivery of that (and potentially other) HFT transfer(s) and repeatedly failing on retry since the same malicious message would be replayed from the commitment store. This matches the "route unable to deliver messages" acceptance criterion.

### Likelihood Explanation
High: constructing a deeply nested `RuntimeCall` (e.g., `Sudo::sudo(Box::new(Sudo::sudo(Box::new(...))))`) and SCALE-encoding it is trivial and requires no elevated permission — only a normal ERC20 transfer through `HyperFungibleToken.send()` with a crafted `data` field. The `ContractToAsset` check only authenticates that the *contract* dispatching the request is the registered HFT peer, not that the message contents are benign; the peer contract always forwards whatever `data` the calling EOA supplied.

### Recommendation
Decode `substrate_data.runtime_call` with the same bounded mechanism already used in `pallet-call-decompressor` — `T::RuntimeCall::decode_all_with_depth_limit(MAX_DEPTH, &mut &*substrate_data.runtime_call)` — and reject the message (mapping to `HftError::RuntimeCallDecodeError`) if the depth limit is exceeded, mirroring the existing hardened pattern and its regression test.

### Proof of Concept
1. On the source EVM chain, an unprivileged user builds `SubstrateCalldata { signature: None, runtime_call: <SCALE bytes of N nested `Sudo::sudo(Box::new(...System::remark(vec![])))` calls, N large enough to exceed available stack> }`, SCALE-encodes it, and passes the bytes as `SendParams.data` to `HyperFungibleToken.send()` (any nonzero `amount`, valid `to`).
2. The contract dispatches an ISMP POST whose body ABI-encodes `Message{from: msg.sender, to, amount, data}` per `_buildDispatchPost` (`sdk/packages/core/contracts/apps/HyperFungibleToken.sol:237-256`).
3. A relayer delivers the proof to the destination chain; `pallet-ismp` routes to `pallet_hyper_fungible_token::IsmpModule::on_accept`.
4. `SubstrateCalldata::decode` succeeds; `T::RuntimeCall::decode(&mut &*substrate_data.runtime_call)` (`module.rs:189`) recurses once per nested `Sudo::sudo` layer with no depth cap, causing a stack overflow during message processing instead of a controlled `Err`.

Note: I was unable to directly confirm at what block/extrinsic-execution layer (native vs. wasmtime-guarded) this stack overflow ultimately manifests, since that depends on runtime execution mode not fully visible from the indexed files; a Devin session with full build/test access would be needed to reproduce the crash empirically and measure the exact nesting depth required.

#[test]
fn decompress_stack_exhaustion_poc() {
	let mut ext = new_test_ext();
	ext.execute_with(|| {
		use crate::runtime::RuntimeCall;
		use codec::Encode;

		let inner_call = RuntimeCall::System(frame_system::Call::remark { remark: Vec::new() });

		let mut nested_calls =
			RuntimeCall::Sudo(pallet_sudo::Call::sudo { call: Box::new(inner_call) });

		for _ in 1..1000 {
			nested_calls =
				RuntimeCall::Sudo(pallet_sudo::Call::sudo { call: Box::new(nested_calls) });
		}

		let encoded = nested_calls.encode();
		let mut buffer = vec![0u8; 1000000];
		let compressed = zstd_safe::compress(&mut buffer[..], encoded.as_slice(), 3).unwrap();
		let final_compressed_call = buffer[..compressed].to_vec();

		let res = pallet_call_decompressor::Pallet::<Test>::decompress_call(
			RuntimeOrigin::none(),
			final_compressed_call.to_vec(),
			encoded.len() as u32,
		)
		.err()
		.unwrap();

		assert_eq!(
			res,
			DispatchError::Module(ModuleError {
				index: 10,
				error: [3, 0, 0, 0],
				message: Some("ErrorDecodingCall")
			})
		);
	});
}
