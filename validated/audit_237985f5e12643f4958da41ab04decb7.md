### Title
Stale delegate grants regain authorization after the position NFT returns to the granting owner - (contracts/controller/src/storage/account.rs)

### Summary
Controller delegate grants are keyed by account ID and stamped with the granting owner's address, but they are not permanently invalidated when the NFT changes owners. If an owner delegates a manager, transfers the position NFT away, and later receives the same NFT back, the old delegate automatically regains full account-control privileges. That delegate can borrow or withdraw to an arbitrary external recipient, allowing theft of user funds.

### Finding Description
`get_delegates` loads `ControllerKey::Delegates(account_id)` and accepts the stored grant whenever `grant.granted_by == owner`. Because `owner` is resolved dynamically from the current NFT owner, the grant becomes inactive while another address owns the NFT but becomes valid again if the original owner regains it. [1](#0-0) 

`is_owner_or_delegate` accepts a caller when it is an active global position manager and is present in the stored delegate list for the account's current owner. [2](#0-1) 

The NFT transfer path does not remove or tombstone `ControllerKey::Delegates(account_id)`. Account deletion removes the entry, but an ordinary NFT ownership transfer does not delete or version it. [3](#0-2) 

After regaining authority, the stale delegate can call `borrow`, which authorizes the caller through `require_owner_or_delegate` and sends pool proceeds to `to.unwrap_or(caller)`. [4](#0-3)  The delegate can likewise call `withdraw`, which pays the selected recipient after the same owner-or-delegate check. [5](#0-4) 

### Impact Explanation
This is theft of user funds. A previously approved delegate can wait until the original owner regains the NFT, then borrow against the returned collateral and receive the borrowed assets, or withdraw available collateral directly. No new authorization from the regained owner is required, even though ownership context and trust assumptions changed since the grant was created.

### Likelihood Explanation
The attacker must first receive a delegate grant from the owner and remain registered as an active position manager. The attack is then triggered by a plausible NFT lifecycle: the owner transfers the account NFT and later receives it back through sale, marketplace activity, collateral transfer, custody rotation, or another legitimate transfer. The attacker is unprivileged and only needs to submit `borrow` or `withdraw` after the return transfer.

### Recommendation
Bind delegate authority to an ownership epoch rather than only `(account_id, granted_by)`. Increment an account ownership epoch whenever the position NFT changes owners, and require delegate grants to match the current epoch. Alternatively, clear or tombstone the `Delegates` entry on every NFT ownership transfer so a stale grant can never reactivate. Grants should require explicit re-authorization after any change from the granting owner, including a later transfer back to that owner.

### Proof of Concept
1. Victim owns account NFT `account_id` with collateral and calls:
   `controller.add_delegate(victim, account_id, attacker_manager)`.
   This succeeds when `attacker_manager` is an active registered manager. [6](#0-5) 

2. Victim calls the position NFT `transfer`/`approve` flow and moves `account_id` to Buyer. Controller ownership resolution now returns Buyer, so the stale `granted_by = victim` grant is inactive.

3. Buyer later transfers the same NFT back to Victim. Controller ownership resolution again returns Victim, and `get_delegates` accepts the preserved grant because `granted_by == victim`. [1](#0-0) 

4. Attacker calls:
   `controller.borrow(attacker_manager, account_id, [(debt_asset, amount)], Some(attacker_manager))`.
   The owner-or-delegate check passes, the pool borrows against the returned collateral, and proceeds are paid to `attacker_manager`. [7](#0-6)

/// Returns grants stamped by `owner`, or an empty list. Ownership changes
/// invalidate a previous owner's grants without deleting them.
pub(crate) fn get_delegates(env: &Env, account_id: u64, owner: &Address) -> Vec<Address> {
    get_user::<DelegateGrant>(env, &ControllerKey::Delegates(account_id))
        .filter(|grant| grant.granted_by == *owner)
        .map(|grant| grant.delegates)
        .unwrap_or_else(|| Vec::new(env))

/// Accepts the owner or a registered, active manager delegated by that owner.
pub(crate) fn is_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) -> bool {
    if caller == owner {
        return true;
    }
    let active_manager =
        storage::get_position_manager(env, caller).is_some_and(|config| config.is_active);
    active_manager && storage::get_delegates(env, account_id, owner).contains(caller)
}

    set_account_delegate(env, &caller, account_id, &delegate, false);
}

/// Authenticates the NFT owner and updates delegates; grants require an active
/// manager. Emits an event only when the current owner's delegate list changes.
fn set_account_delegate(
    env: &Env,
    caller: &Address,
    account_id: u64,
    delegate: &Address,
    add: bool,
) {
    caller.require_auth();
    require_account_owner(env, account_id, caller);
    if add {
        // Reject dormant grants that could gain authority on later manager activation.
        assert_with_error!(
            env,
            storage::get_position_manager(env, delegate).is_some_and(|c| c.is_active),
            GenericError::NotAuthorized
        );

/// Borrows to `to` or the authorized owner/delegate, then checks solvency.
/// Persists supply alongside debt when the check restamps supply LTVs.
pub(crate) fn process_borrow(
    env: &Env,
    caller: &Address,
    account_id: u64,
    borrows: &Vec<HubPayment>,
    to: Option<Address>,
) {
    validation::require_authorized_caller(env, caller);

    let mut account = storage::get_account(env, account_id);
    require_owner_or_delegate(env, account_id, caller, &account.owner);

    let recipient = to.unwrap_or_else(|| caller.clone());
    let mut cache = Context::new(env);
    require_external_recipient(env, &mut cache, &recipient);
    let aggregated = payments::aggregate_positive_payments(env, borrows);

    validate_position_entry_gates(
        env,
        &account,
        &aggregated,
        &mut cache,
        AccountPositionType::Borrow,
    );
    settle_borrow(env, &mut account, &recipient, &aggregated, &mut cache);
