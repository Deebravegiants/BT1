Audit Report

## Title
Legacy gateway user-message handler never enforces the documented allowlist/rate-limit, letting any unprivileged caller broadcast trigger requests to all DON nodes - (File: core/services/gateway/handlers/capabilities/handler.go)

## Summary
`handler.HandleLegacyUserMessage` is reachable from unauthenticated external callers via `gateway.ProcessRequest`'s legacy `DonID`-based path, validates payload decoding, timestamp freshness, and method name, but contains only a `// TODO: apply allowlist and rate-limiting here` comment with no actual sender allowlist or rate-limit check before broadcasting the request to every DON member.

## Finding Description
`gateway.ProcessRequest` routes any message with a non-empty `msg.Body.DonID` into the legacy path, calling `msg.Validate()` and then `h.HandleLegacyUserMessage(ctx, msg, callback)` [1](#0-0) . `Message.Validate()` only checks field lengths/format and recovers the signer address via ECDSA signature recovery into `m.Body.Sender` — it does not check that the signer is a member of any allowlist, so any party that can generate an ECDSA keypair and sign the message passes validation [2](#0-1) .

Inside `HandleLegacyUserMessage`, after payload/timestamp checks, the code contains the explicit comment `// TODO: apply allowlist and rate-limiting here` directly followed only by a method-name check (`msg.Body.Method != MethodWebAPITrigger`) — no sender allowlist or rate limiter is invoked [3](#0-2) . The request is then saved as a callback and unconditionally broadcast to every DON member: `for _, member := range h.donConfig.Members { err = errors.Join(err, don.SendToNode(ctx, member.Address, req)) }` [4](#0-3) .

By contrast, the sibling `triggerConnectorHandler.processTrigger` path in `core/capabilities/webapi/trigger/trigger.go` does enforce a real `allowedSenders` map and a `rateLimiter.Allow(...)` check before dispatching, confirming that this class of control is both intended and implementable elsewhere in the codebase, but simply missing here [5](#0-4) . This is a legacy code path, and grep confirms no `allowedSenders`/rate-limit wiring exists anywhere in `handler.go` beyond the `nodeRateLimiter` used for *outgoing* DON→client responses, not incoming user requests.

## Impact Explanation
Any unprivileged caller who can sign an arbitrary-content message with any ECDSA key (i.e., anyone, since there is no allowlist of accepted signer addresses) can submit a `web_api_trigger` request through the Gateway's `ProcessRequest` endpoint and have it broadcast unconditionally to every node in the target DON, with no allowlist restricting which senders may trigger which workflow and no rate limiting bounding request volume. This matches an in-scope impact category of allowlist bypass / gateway request impersonation, since the code path is documented (via the TODO and via the parallel `allowedSenders` design elsewhere) to require sender-level gating but does not perform it.

## Likelihood Explanation
High. This is the default and only code path executed whenever a `DonID`-bearing legacy message reaches `gateway.ProcessRequest`, requiring nothing more than the ability to construct a validly-signed `api.Message` (any keypair works, since `Validate()` performs no allowlist check) and issue an HTTP request to the gateway's public endpoint — no special privilege or credential beyond generating a key is needed.

## Recommendation
Implement sender allowlist and rate-limiting enforcement in `HandleLegacyUserMessage` before saving the callback and broadcasting to DON members, mirroring the `allowedSenders`/`rateLimiter` pattern already present in `triggerConnectorHandler.processTrigger`, or explicitly deprecate/gate this legacy handler so it cannot serve untrusted external traffic.

## Proof of Concept
1. Configure a Gateway with a legacy DON-ID handler using `capabilities.NewHandler` (`core/services/gateway/handlers/capabilities/handler.go`).
2. Generate an arbitrary ECDSA keypair (no allowlist membership required) and use `Message.Sign` to sign a legacy `api.Message` with `Body.DonID` set, `Body.Method = "web_api_trigger"`, and a valid, fresh `webapicap.TriggerRequestPayload`.
3. POST the signed message to the Gateway's `ProcessRequest` endpoint.
4. Observe `HandleLegacyUserMessage` passes payload/timestamp/method checks (no allowlist/rate-limit check exists) and calls `don.SendToNode` for every DON member, confirming unauthenticated broadcast to the full DON.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageID) == 0 || len(m.Body.MessageID) > MessageIDMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageID, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonID) == 0 || len(m.Body.DonID) > MessageDonIDMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonID, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}
