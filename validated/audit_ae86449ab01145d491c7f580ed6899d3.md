### Title
Pool repay refunds a declared overpayment that was never received, draining pool custody - (File: contracts/pool/src/ops/repay.rs)

### Summary
`ops::repay::accounting` treats `action.amount` as funds already in pool custody and refunds the excess over outstanding debt directly out of the pool's token balance. The pool never measures what it actually received, so a caller can declare an `amount` up to the pool's whole balance against a position with no debt — the entire amount becomes "overpayment" and is transferred back to the payer out of real supplier custody.

### Finding Description
The kernel bug reads `urb->status` after `usb_hcd_giveback_urb()` consumed the urb — a stale dereference of a handed-off object. The analog is the same shape: `apply` hands the refund to `transfer_out` using a value computed from the declared `action.amount`, not from custody that was actually handed over.

`accounting` resolves `(burned, overpayment) = cache.resolve_repay(amount, position)` purely from `action.amount` and the debt book [1](#0-0) . `apply` then calls `outcome.cache.transfer_out(payer, outcome.overpayment)` with no check that `amount` was ever transferred in [2](#0-1) . The refund neither debits `cash` nor passes `require_reserves`, and `credit_cash(net_repay)` credits only the net [3](#0-2) .

The suite pins this exact behavior: `test_unfunded_repay_overpayment_refund_also_pays_out_of_custody` calls `repay` with `amount = custody_before` on a zero-debt market, `actual_amount` is 0, and the payer is refunded the full pool balance with the book untouched [4](#0-3) . In production the controller path always prefunds via measured transfer (`transfer_amount_measured` in `apply_liquidation_repayments` [5](#0-4)  and `repay_debt_from_controller` [6](#0-5) ), so the gap exists only if `pool.repay` is reachable directly — the docs describe `repay` as a payer-auth entrypoint and the test invokes `t.client().repay` with a fresh `payer`, which indicates it is not restricted to the controller.

### Impact Explanation
An unprivileged attacker calls `repay` directly on the pool with `payer = self`, a `PoolAction` whose `amount` equals the pool's full token balance, targeting a market where the referenced position has zero debt (e.g., a fresh position id). `resolve_repay` returns `overpayment = amount`, `net_repay = 0`, the `RepayRoundsToZeroShares` assert passes on the `net_repay == 0` disjunct, and `transfer_out` sends the entire custody to the attacker — theft of all supplier funds in that market, repeatable across every listed market.

### Likelihood Explanation
Single call, no flash loan, no price manipulation, no privileged key. Requires only that `pool.repay` lacks a controller-only gate and that `payer.require_auth()` is satisfiable by the attacker's own signature. The repository's own test demonstrates the drain succeeds end-to-end. Residual uncertainty: I could not fully verify `pool/src/lib.rs` auth wiring in the remaining iterations; if repay is controller-gated, the entrypoint is unreachable and severity collapses.

### Recommendation
Measure the inbound deposit inside `repay`: snapshot the pool token balance against the pre-call expectation, or require the caller to pass the measured received amount and verify `balance >= expected`. Alternatively gate `repay`/`recapitalize` to the controller address, and debit the refund from `cash` (with `require_reserves`) so an unfunded refund cannot touch supplier custody.

### Proof of Concept
Mirrors `contracts/pool/tests/flows.rs:3590`: deploy a market, seed suppliers so the pool holds `C`. Attacker calls `pool.repay(payer=attacker, PoolAction { position with zero debt, amount = C })`. Assert `token.balance(pool)` drops to 0, `token.balance(attacker)` gains `C`, `get_reserves` cash book unchanged, `actual_amount == 0` — matching `assert_unfunded_refund_drained_custody`.

```rust
#[test]
fn test_unfunded_repay_overpayment_refund_also_pays_out_of_custody() {
    let t = TestSetup::new();
    let token = token::Client::new(&t.env, &t.asset);
    let payer = Address::generate(&t.env);

    let custody_before = token.balance(&t.pool);
    let before = t.state_snapshot();
    assert_eq!(
        before.cash, custody_before,
        "fixture guard: book and custody must start in sync"
    );
    assert_eq!(before.borrowed, 0, "fixture must carry no debt");

    // Nothing transferred in, no debt to retire: the whole amount is "excess".
    let credited = t
        .client()
        .repay(&payer, &t.ract(0, custody_before))
        .get_unchecked(0)
        .actual_amount;
    assert_eq!(credited, 0, "no debt was retired, so nothing is credited");
    assert_unfunded_refund_drained_custody(&t, &payer, custody_before, &before);
}
```
