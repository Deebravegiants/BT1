### Title
`IntentGatewayV2.instance()` fallback to `address(this)` bypasses the peer-authentication access check on the Tron deployment - ([File: evm/tron/contracts/apps/IntentGatewayV2.sol])

### Summary
The Casper incident stemmed from a contract-installer bypass of access-rights checks that let an unprivileged actor gain unauthorized use of URef-gated resources. The closest reachable analog in this codebase is in the Tron variant of `IntentGatewayV2`, where the peer-authorization helper `instance()` silently falls back to `address(this)` for any state machine that has no explicitly registered deployment, instead of reverting the way the canonical EVM `IntentsBase._instance()` does. [1](#0-0) 

### Finding Description
`authenticate()` is the sole gate that decides whether an incoming ISMP `PostRequest` is trusted as coming from a legitimate peer `IntentGatewayV2` deployment on the claimed source chain: [2](#0-1) 

It calls `instance(request.source)`, which is defined as:

```solidity
function instance(bytes calldata stateMachineId) public view returns (address) {
    address gateway = _instances[keccak256(stateMachineId)];
    return gateway == address(0) ? address(this) : gateway;
}
``` [3](#0-2) 

Compare this to the canonical EVM implementation's equivalent, `IntentsBase._instance()`, which **reverts** with `UnknownInstance` when no deployment is registered for the given `stateMachineId`: [4](#0-3) 

Because the Tron `instance()` returns `address(this)` as a default instead of reverting, `authenticate()` effectively grants access-rights to *any* unregistered source chain as long as the attacker crafts `request.from = abi.encodePacked(address(thisGateway))`. This is structurally the same class of bug as the Casper incident: an access-rights check that is supposed to gate a privileged resource (here, the trust relationship between this gateway and a specific peer deployment) fails to enforce the "installer"/registration invariant and instead silently substitutes a default identity that satisfies the check.

An unprivileged relayer only needs a state machine that Hyperbridge's consensus/state-proof pipeline can verify (any chain configured on the coprocessor, even one this Tron gateway has never registered a peer for) and to submit a `PostRequest` whose `from` field is the gateway's own address. `authenticate()` (`instance(request.source) == module`) passes even though no `NewDeployment` action ever registered that chain as a trusted peer.

### Impact Explanation
`authenticate()` gates the escrow-redemption path (`RedeemEscrow`/`RefundEscrow`), which releases previously escrowed input tokens to a caller-specified beneficiary. If an unregistered/arbitrary state machine can pass `authenticate()` by spoofing `from = address(this)`, an attacker who can get a validly-proven message dispatched from any chain ISMP can verify (which does not require the victim gateway to have configured that chain as a trusted peer) can forge a `RedeemEscrow`/`RefundEscrow` request targeting escrowed funds, resulting in theft of escrowed order funds — a direct funds-loss impact matching the "High" bar (fund theft via a bypassed access-rights check on the same class as URef-gated resources in the Casper incident).

### Likelihood Explanation
Exploitation requires only a message dispatched through the normal Hyperbridge relay path from some chain with a verifiable consensus client, with a body whose first byte selects `RedeemEscrow`/`RefundEscrow` and a `from` field equal to the target gateway's own address — no admin/governance/relayer privilege is needed beyond what any ordinary relayer already has to deliver ISMP messages. This is reachable by any relayer/user who can dispatch a real cross-chain message, which matches the "single relayed proof" threat model in scope.

### Recommendation
Change `IntentGatewayV2.instance()` on Tron to match the EVM `IntentsBase._instance()` semantics: revert (e.g. with an `UnknownInstance` error) when `_instances[keccak256(stateMachineId)]` is unset, rather than defaulting to `address(this)`. This removes the implicit trust grant to arbitrary unregistered chains and forces `authenticate()` to only accept messages from chains explicitly registered via `NewDeployment`.

### Proof of Concept
1. Deploy/observe a live Tron `IntentGatewayV2` at address `G`, with escrowed funds under some `commitment` from a prior `placeOrder`.
2. Do not register any peer deployment for chain `X` (i.e., `_instances[keccak256(X)] == address(0)`).
3. From chain `X` (any chain whose consensus Hyperbridge/ISMP can verify), dispatch (or have any relayer deliver) a `PostRequest` with:
   - `source = X`
   - `from = abi.encodePacked(G)` (20 bytes, the gateway's own address)
   - `to = abi.encodePacked(G)`
   - `body = RequestKind.RedeemEscrow ++ abi.encode(WithdrawalRequest{ commitment, tokens, beneficiary: attacker })`
4. On delivery, `onAccept` calls `authenticate(request)`, which calls `instance(X)`. Since no instance is registered for `X`, `instance()` returns `address(this) == G`, matching `module == address(bytes20(request.from)) == G`. The check passes.
5. The escrowed tokens for `commitment` are released to `attacker`, even though chain `X` was never registered as a trusted peer of gateway `G`. [1](#0-0)

    function authenticate(PostRequest calldata request) internal view {
        if (request.from.length != 20) revert InvalidInput();
        address module = address(bytes20(request.from));
        // IntentGateway only accepts incoming assets from itself or known instances
        if (instance(request.source) != module) revert Unauthorized();
