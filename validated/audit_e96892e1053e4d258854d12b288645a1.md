Confirmed: `ssd::perform_async` in `src/ssd.rs` returns `None` (silently, no error propagated) whenever the SSD is not mounted, has previously failed (`STATE_FAILED` sticks permanently once any I/O error occurs), or the specific I/O call fails.

### Title
Silent read/upload failures followed by unconditional directory deletion cause permanent, unrecoverable loss of biometric identification images - (File: src/agents/image_uploader.rs)

### Summary
`upload_saved_images` in `src/agents/image_uploader.rs` reads each saved biometric PNG frame from the SSD, attempts to upload it, and unconditionally deletes the entire source directory once the loop over the images finishes — regardless of whether every individual image was actually read and successfully uploaded to the backend.

### Finding Description
The image-uploader agent processes locally stored biometric capture data (IR/RGB/thermal frames and identification images used for iris/face matching) once the Orb enters idle state: [1](#0-0) 

For each PNG path found, the code does:
```rust
let img_data = ssd::perform_async(async { fs::read(&path).await }).await;
let Some(img_data) = img_data else {
    continue;
};
```
`ssd::perform_async` silently returns `None` (no error, no exception) whenever the SSD is not mounted or has previously entered `STATE_FAILED` (which is a sticky, permanent state once a single I/O error occurs anywhere in the process): [2](#0-1) [3](#0-2) 

When `fs::read` fails, the loop simply `continue`s — the image is silently skipped, with no counter, no error log, and no accumulated failure flag. Additionally, `upload_image` (the actual backend call) always returns `Ok(())` even when the HTTP request itself fails; it only logs and increments a metric: [4](#0-3) 

After the loop over all image paths completes — irrespective of how many images were actually skipped due to read failures or failed to upload to the backend — the code unconditionally deletes the entire source directory:
```rust
ssd::perform_async(async { fs::remove_dir_all(image_dir).await }).await;
``` [5](#0-4) 

The same unconditional-cleanup pattern repeats one level up in `upload_signup_images`, which calls `upload_saved_images` multiple times plus `upload_identification_images_impl` for the identification (self-custody / iris matching) images, and then deletes the entire per-signup directory unconditionally: [6](#0-5) 

This mirrors the root cause of the referenced external report exactly: an operation (`BondNFT.distribute`) that can silently no-op under certain conditions (`totalShares == 0 || !allowedAsset`) is followed by an irreversible action (funds already pulled from `GovNFT`) that assumes the no-op path never happens, resulting in permanently stuck/lost assets with no recovery mechanism. Here, the silent no-op is "SSD read/upload failed → `continue`/log-only", and the irreversible action is "delete the only on-disk copy of the biometric data regardless."

### Impact Explanation
Once `remove_dir_all` executes, the local copy of the identification/biometric images is gone. Any image that was skipped due to a transient SSD failure (which becomes sticky/permanent for the remainder of the process once triggered — see `STATE_FAILED` in `src/ssd.rs`) or that failed to reach the backend due to a network/server error is now permanently unrecoverable — it was never uploaded, and it no longer exists locally. This is a real, concrete loss of biometric identification image data used for verification, audit and fraud-detection retention purposes, not a mere logging gap. Because a single I/O error anywhere flips SSD state to `STATE_FAILED` for the rest of the run, the effect can compound across many signups in the same upload cycle in `upload_all_signup_images`, silently discarding data for multiple users' signups. There is no code path currently that skips or defers the deletion when part of the upload failed.

### Likelihood Explanation
This does not require a malicious actor, operator, or privileged access — it triggers purely from ordinary unprivileged-user signups combined with an environmental condition (SSD wear/latency, transient I/O error, filesystem hiccup, or backend request failure), all of which are realistic operational occurrences on field-deployed hardware running for extended periods. This code path is gated behind the `internal-data-acquisition` feature per the module doc comment, so exposure depends on that build configuration, but the logic itself, once active, triggers deterministically on any read or backend failure.

### Recommendation
Track upload/read success per file within `upload_saved_images` (and across all sub-calls in `upload_signup_images` / `upload_identification_images_impl`) and only delete the local directory if all reads and all uploads for that signup succeeded. If any file failed, retain the directory (or the specific failed files) so a subsequent upload pass can retry, and surface an explicit error/metric distinguishing "some images retained for retry" from "fully uploaded and cleaned up." Additionally, make `upload_image`'s failure path propagate an `Err` (or an explicit success/failure return) instead of unconditionally returning `Ok(())`, so callers can make correct decisions about deletion.

### Proof of Concept
1. Trigger a signup with `internal-data-acquisition` enabled so identification images are saved locally by `image_notary` under `DATA_ACQUISITION_BASE_DIR/<signup_id>/identification/...`.
2. Induce a transient SSD/filesystem I/O error (e.g., momentary disk pressure, remount, or corrupted sector) while `fs::read` is called on one of the saved PNGs during the idle-state upload pass; `ssd::perform_async` sets `STATE_FAILED` and returns `None` for that read and every subsequent SSD operation in the process lifetime [7](#0-6) .
3. `upload_saved_images` hits `continue` for that (and any later) image, silently omitting it from upload, with no error surfaced to the caller [8](#0-7) .
4. After the loop finishes, `upload_saved_images` unconditionally calls `fs::remove_dir_all(image_dir)`, deleting the identification image directory including the unread/unuploaded image [5](#0-4) .
5. The biometric identification image is now permanently lost: never uploaded to the backend and no longer present on the Orb's local storage, with no retry or alert distinguishing this from a fully successful upload.

async fn upload_saved_images(
    signup_dir: &Path,
    image_dir_name: &str,
    signup_id: &SignupId,
    presigned_url_type: UrlType,
) -> Result<()> {
    let image_dir = signup_dir.join(image_dir_name);
    if !image_dir.is_dir() {
        tracing::warn!("The directory {:?} does not exist, skipping image upload", image_dir);
        return Ok(());
    }
    let mut paths = Vec::new();
    ssd::perform_async(async {
        let mut dir_reader = fs::read_dir(&image_dir).await?;
        while let Some(entry) = dir_reader.next_entry().await? {
            let path = entry.path();
            if path.extension().map_or(false, |path| path == "png") {
                paths.push(path);
            }
        }
        Ok(())
    })
    .await;
    for path in paths {
        let image_id = ImageId::from_image_path(&path)?;
        let img_data = ssd::perform_async(async { fs::read(&path).await }).await;
        let Some(img_data) = img_data else {
            continue;
        };
        upload_image(
            signup_id,
            &image_id,
            presigned_url_type,
            img_data,
            &path.display().to_string(),
            image_dir_name,
        )
        .await?;
    }
    ssd::perform_async(async { fs::remove_dir_all(image_dir).await }).await;
    Ok(())
}

pub fn perform<R, F: FnOnce() -> io::Result<R>>(f: F) -> Option<R> {
    if is_active() {
        match f() {
            Ok(value) => return Some(value),
            Err(err) => set_failed(&err),
        }
    }
    None
}

/// Asynchronous version of [`perform`].
pub async fn perform_async<R, F: Future<Output = io::Result<R>>>(f: F) -> Option<R> {
    if is_active() {
        match f.await {
            Ok(value) => return Some(value),
            Err(err) => set_failed(&err),
        }
    }
    None
}

fn set_failed(err: &io::Error) {
    let mut state = STATE.load(Ordering::Relaxed);
    loop {
        match STATE.compare_exchange_weak(state, STATE_FAILED, Ordering::Relaxed, Ordering::Relaxed)
        {
            Ok(_) => {
                tracing::error!("SSD I/O error: {:#?}", err);
                break;
            }
            Err(STATE_FAILED) => break,
            Err(new_state) => state = new_state,
        }
    }
}
