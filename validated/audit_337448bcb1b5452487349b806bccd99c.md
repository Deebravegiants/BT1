### Title
Attestation signature omits signup_id/nonce, enabling cross-signup replay - ([File: src/plans/enroll_user.rs])

### Summary
`make_signature` in `src/plans/enroll_user.rs` computes the SHA256 context signed by the secure element using only `ORB_ID`, `user_qr_code.user_id`, and the biometric pipeline's iris/mask codes and version strings; it never incorporates the `signup_id`, a capture timestamp, or any session-unique nonce. Because the function's inputs are fully attacker-influenceable/repeatable and `signup_id` is never passed into it at all, the resulting base64 signature is deterministic per `(user_id, pipeline outputs)` pair and is therefore replayable across different signups sharing those same values.

### Finding Description
`Plan::run` calls `make_signature(&user_qr_code, &p)` [1](#0-0)  — notably `self.signup_id` is never passed as an argument. `make_signature` itself builds the signed context strictly from `ORB_ID`, `user_qr_code.user_id`, and the pipeline's `ir_net_version`, `iris_version`, and each eye's `iris_code`/`mask_code`/`iris_code_version`, then signs the digest via `secure_element::sign` and base64-encodes the result [2](#0-1) . No `signup_id`, timestamp, or nonce is hashed. `signup_post::request` sends this signature as a plain "signature" multipart form field alongside the `signup_id` in the URL path, but the signature content itself carries no binding to that path parameter [3](#0-2) . Consequently, if an attacker (or environment) causes the same `(user_id, pipeline outputs)` pair to recur across two distinct signup attempts, `make_signature` will produce byte-identical signatures for both, since the function is a pure, stateless hash-and-sign over inputs that carry no session-uniqueness.

### Impact Explanation
This breaks the intended invariant that a biometric attestation is bound to one specific signup attempt. A previously captured, valid signature could be replayed against a new `signup_id`, meaning the backend receives an attestation over biometric data that is not cryptographically tied to the specific signup session presenting it. This matches an attestation-forgery/replay class of impact (signed biometric data reusable outside its intended context) rather than a full account takeover, since it depends on backend-side signup/session validation for the ultimate outcome.

### Likelihood Explanation
The precondition is that `make_signature`'s hashed inputs (`user_id` plus the six pipeline string fields) are identical across two signup attempts. This is fully within orb-core's control/observation: an attacker who controls their own `user_qr_code.user_id` (the QR they present) and who can reproduce identical pipeline output strings (e.g., by presenting an identical capture, or if the pipeline is deterministic/cacheable for the same input) triggers the deterministic replay, since `make_signature` performs no per-call randomization and does not read `signup_id`. This is directly demonstrable at the unit-test level without touching hardware, network, or backend behavior.

### Recommendation
Include the `signup_id` (and ideally a monotonic/session-unique nonce or capture timestamp) inside the SHA256 context hashed in `make_signature` before calling `secure_element::sign`, so the resulting signature is cryptographically bound to the specific signup attempt and cannot be replayed across signups.

### Proof of Concept
Unit test in `src/plans/enroll_user.rs` (or a new test module) constructing two identical `qr_scan::user::Data` and `Pipeline` values, then computing `make_signature(&user_qr_code, &pipeline)` twice (simulating two signups with distinct `SignupId`s, since `signup_id` is not even accepted as a parameter). Assert:
```
let sig_a = make_signature(&user_qr_code, &pipeline).unwrap();
let sig_b = make_signature(&user_qr_code, &pipeline).unwrap();
assert_eq!(sig_a, sig_b); // demonstrates signature is independent of signup context
```
The equality confirms the signature carries no signup-attempt-unique binding, violating the intended non-replayability invariant.

fn make_signature(user_qr_code: &qr_scan::user::Data, pipeline: &Pipeline) -> Result<String> {
    let mut ctx = Context::new(&SHA256);
    ctx.update(ORB_ID.as_str().as_bytes());
    ctx.update(user_qr_code.user_id.as_bytes());
    ctx.update(pipeline.v2.ir_net_version.as_bytes());
    ctx.update(pipeline.v2.iris_version.as_bytes());
    ctx.update(pipeline.v2.eye_left.iris_code.as_bytes());
    ctx.update(pipeline.v2.eye_left.mask_code.as_bytes());
    ctx.update(pipeline.v2.eye_left.iris_code_version.as_bytes());
    ctx.update(pipeline.v2.eye_right.iris_code.as_bytes());
    ctx.update(pipeline.v2.eye_right.mask_code.as_bytes());
    ctx.update(pipeline.v2.eye_right.iris_code_version.as_bytes());
    let signed = secure_element::sign(ctx.finish())?;
    Ok(BASE64.encode(&signed))
}
