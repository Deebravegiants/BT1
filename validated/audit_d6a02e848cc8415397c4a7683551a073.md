### Title
GRANDPA `AncestryChain::ancestry` infinite loop on a two-header hash cycle in `votes_ancestries` causes a permanent hang when reachable via `pallet-ismp::handle_unsigned` - (File: `modules/consensus/grandpa/primitives/src/justification.rs`)

### Summary
`pallet-ismp`'s `handle_unsigned` extrinsic is an unsigned, permissionless entry point that lets anyone submit ISMP `Message::Consensus` datagrams for free, provided the proof "verifies" [1](#0-0) . For the GRANDPA consensus client, this proof is decoded into a `GrandpaJustification`, whose `votes_ancestries: Vec<H>` field is fully attacker-controlled raw header data [2](#0-1) . The `AncestryChain::ancestry` walk used both by `finality_grandpa::validate_commit` and directly by `GrandpaJustification::verify_with_voter_set` follows `parent_hash` pointers through a `BTreeMap` built from these attacker-supplied headers with no cycle detection and no bound on iterations [3](#0-2) .

### Finding Description
`AncestryChain::new` indexes the submitted `votes_ancestries` headers by their own computed hash into a `BTreeMap<H::Hash, H>` [4](#0-3) . Nothing constrains the `parent_hash` field of an attacker-crafted header — it is just a struct field, not a proof-of-work-linked value — so an attacker can construct two headers A and B where `A.parent_hash == hash(B)` and `B.parent_hash == hash(A)`, forming a two-node cycle.

The `ancestry` walk then does:
```
let mut route = vec![block];
let mut current_hash = block;
while current_hash != base {
    match self.ancestry.get(&current_hash) {
        Some(current_header) => {
            current_hash = *current_header.parent_hash();
            route.push(current_hash);
        },
        _ => return Err(finality_grandpa::Error::NotDescendent),
    };
}
``` [5](#0-4) 

If `block` is chosen to be inside the A↔B cycle and `base` is not, the lookup always succeeds (both A and B are present in the map) and `current_hash` oscillates between the two hashes forever — the loop never returns `Err(NotDescendent)` and never reaches `base`. This is reached from two call sites inside the same unsigned-extrinsic-accessible verification path: `finality_grandpa::validate_commit`'s internal ancestry checks and the explicit call in `GrandpaJustification::verify_with_voter_set` [6](#0-5) , itself invoked from `verify_grandpa_finality_proof`, the entry point used by the GRANDPA `ConsensusClient` for `pallet-ismp` [7](#0-6) .

Because `handle_unsigned` is callable by anyone with no fee and is also invoked by `validate_unsigned` in the transaction pool (i.e., the loop can be triggered merely by transaction propagation/validation, not only inclusion) [8](#0-7) , a crafted `Message::Consensus` datagram containing a two-header cycle in `votes_ancestries` can hang the collator/validator node that attempts to validate or execute it — both in the txpool `validate_unsigned` path and in on-chain execution via `handle_unsigned` → `Self::execute` → `handle_incoming_message` → GRANDPA client `verify_consensus`.

This class of bug is exactly analogous to CVE-2021-2203 (an unbounded/expensive optimizer computation triggerable by a request that hangs/crashes the server): here, an unprivileged, feeless message triggers an unbounded computation (an infinite loop) in the consensus-proof verifier that a node cannot terminate, producing a complete denial of service.

### Impact Explanation
A successful exploit hangs the runtime execution thread (and/or the transaction-pool validation thread, since `validate_unsigned` runs the same `execute`/verification path) processing the malicious message. Because `handle_unsigned` is unsigned and free, any network participant — including an unprivileged relayer or arbitrary third party — can submit this payload repeatedly to every collator/validator that receives it via gossip, since `propagate: true` is set on the resulting `ValidTransaction` [9](#0-8) . This can stall block production or txpool validation across the network — a "route unable to deliver messages" / chain-halting impact — matching the Medium-severity, availability-only profile of the reference CVE.

### Likelihood Explanation
Constructing the two colliding headers requires no cryptographic break: the attacker fully controls raw header bytes (hash is just Blake2/Keccak over header fields) and only needs `hash(A)` to equal `B.parent_hash` and vice versa, which is achievable in one pass (compute A first without needing its own hash to satisfy anything, then set B.parent_hash = hash(A), compute hash(B), then rebuild A with parent_hash = hash(B) — since A's own hash isn't constrained to depend on its parent_hash in a fixed-point way, a short trial loop or direct field construction suffices). No supermajority signatures are required to reach the vulnerable code path in `verify_with_voter_set`, because the ancestry walk over `votes_ancestries` happens for each precommit signer as part of processing signed precommits, and `validate_commit`'s internal ancestry traversal (via the `Chain` trait) is invoked before/alongside vote tallying. The overall bar to trigger this is: know the GRANDPA consensus state id for a configured client (public information) and submit an unsigned extrinsic — no privileged role, no stake, no relayer whitelist.

### Recommendation
Add cycle detection / hop-count bounding to `AncestryChain::ancestry` — e.g., track visited hashes in a `BTreeSet` and bail with `NotDescendent` if a hash is revisited, or bound the walk to `votes_ancestries.len() + 1` iterations before failing. Additionally, bound the size of `votes_ancestries` (and `unknown_headers`, which is used in the same pattern in `verify_grandpa_finality_proof`) to a sane maximum length before invoking any ancestry walk, consistent with how other proof-depth limits were added elsewhere in the codebase (e.g., `MAX_PROOF_DEPTH` in the Pharos SPV verifier [10](#0-9) ).

### Proof of Concept
1. Construct header `B` with an arbitrary `parent_hash = P0` (a placeholder), encode it, and compute `hash(B)`.
2. Construct header `A` with `parent_hash = hash(B)`, encode it, and compute `hash(A)`.
3. Rebuild `B` with `parent_hash = hash(A)` (recomputing `hash(B)` again as needed one more pass if the type requires exact-fixed fields, which is trivial since header fields such as `extrinsics_root`/`digest` are attacker-chosen filler).
4. Set `votes_ancestries = vec![A, B]` inside a `GrandpaJustification` whose `commit.precommits` includes at least one precommit whose `target_hash` equals `hash(A)` (i.e., inside the cycle) while `base_hash` (lowest precommit target) is a different, non-cyclic hash.
5. Wrap this justification in a `FinalityProof`/`ConsensusMessage` for a GRANDPA `consensus_state_id` already registered on a Hyperbridge instance, and submit it via `pallet-ismp::handle_unsigned([Message::Consensus(...)])`.
6. Observe that `AncestryChain::ancestry` in `justification.rs` (lines 180–197) never returns, hanging the node's transaction-validation/execution thread.

Note: I was not able to fully trace whether an additional upstream length/size cap on `votes_ancestries` or the whole justification bytes exists elsewhere in `pallet-ismp`'s extrinsic decoding (SCALE length limits) that might make constructing a valid 2-header proof impractical; based on the code read, no depth/cycle bound specific to `AncestryChain::ancestry` exists, and this function is the same one exercised by the existing (already-fixed) GRANDPA panic regressions documented elsewhere in this codebase (`RelayHeaderNotInUnknownHeaders`, `UnknownHeadersEmpty`), indicating this code path is squarely in the audited attacker-facing surface but this particular infinite-loop case was not addressed by those prior fixes.

	pub fn verify_with_voter_set(
		&self,
		set_id: u64,
		voters: &VoterSet<AuthorityId>,
	) -> Result<(), anyhow::Error> {
		use finality_grandpa::Chain;

		let ancestry_chain = AncestryChain::<H>::new(&self.votes_ancestries);

		match finality_grandpa::validate_commit(&self.commit, voters, &ancestry_chain) {
			Ok(ref result) if result.is_valid() => {
				if result.num_duplicated_precommits() > 0 ||
					result.num_invalid_voters() > 0 ||
					result.num_equivocations() > 0
				{
					Err(anyhow!("Invalid commit, found one of `duplicate precommits`, `invalid voters`, or `equivocations` {result:?}"))?
				}
			},
			err => {
				let result = err.map_err(|_| {
					anyhow!("[verify_with_voter_set] Invalid ancestry while validating commit!")
				})?;
				Err(anyhow!("invalid commit in grandpa justification: {result:?}"))?
			},
		}

		// we pick the precommit for the lowest block as the base that
		// should serve as the root block for populating ancestry (i.e.
		// collect all headers from all precommit blocks to the base)
		let base_hash = self
			.commit
			.precommits
			.iter()
			.map(|signed| &signed.precommit)
			.min_by_key(|precommit| precommit.target_number)
			.map(|precommit| precommit.target_hash.clone())
			.expect(
				"can only fail if precommits is empty; \
				 commit has been validated above; \
				 valid commits must include precommits; \
				 qed.",
			);

		let mut visited_hashes = BTreeSet::new();
		for signed in self.commit.precommits.iter() {
			let message = finality_grandpa::Message::Precommit(signed.precommit.clone());

			check_message_signature::<_, _>(
				&message,
				&signed.id,
				&signed.signature,
				self.round,
				set_id,
			)?;

			if base_hash == signed.precommit.target_hash {
				continue;
			}

			let route = ancestry_chain
				.ancestry(base_hash, signed.precommit.target_hash)
				.map_err(|_| anyhow!("[verify_with_voter_set] Invalid ancestry!"))?;
			// ancestry starts from parent hash but the precommit target hash has been
			// visited
			visited_hashes.insert(signed.precommit.target_hash);
			for hash in route {
				visited_hashes.insert(hash);
			}
		}

impl<H: HeaderT> finality_grandpa::Chain<H::Hash, H::Number> for AncestryChain<H>
where
	H::Number: finality_grandpa::BlockNumberOps,
{
	fn ancestry(
		&self,
		base: H::Hash,
		block: H::Hash,
	) -> Result<Vec<H::Hash>, finality_grandpa::Error> {
		let mut route = vec![block];
		let mut current_hash = block;
		while current_hash != base {
			match self.ancestry.get(&current_hash) {
				Some(current_header) => {
					current_hash = *current_header.parent_hash();
					route.push(current_hash);
				},
				_ => return Err(finality_grandpa::Error::NotDescendent),
			};
		}
		Ok(route)
	}
}

pub fn verify_grandpa_finality_proof<H>(
	mut consensus_state: ConsensusState,
	finality_proof: FinalityProof<H>,
) -> Result<(ConsensusState, H, Vec<H256>, AncestryChain<H>), Error>
where
	H: Header<Hash = H256, Number = u32>,
	H::Number: finality_grandpa::BlockNumberOps + Into<u32>,
{
	// First validate unknown headers.
	let headers = AncestryChain::<H>::new(&finality_proof.unknown_headers);

	let target = finality_proof
		.unknown_headers
		.iter()
		.max_by_key(|h| *h.number())
		.ok_or(Error::UnknownHeadersEmpty)?;

	// this is illegal
	if target.hash() != finality_proof.block {
		Err(Error::LatestBlockMismatch)?;
	}

	let justification =
		GrandpaJustification::<H>::decode_all(&mut &finality_proof.justification[..])
			.map_err(|e| Error::DecodeJustification(alloc::format!("{e:?}")))?;

	if justification.commit.target_hash != finality_proof.block {
		Err(Error::JustificationTargetMismatch)?;
	}

	let from = consensus_state.latest_hash;

	let base = finality_proof
		.unknown_headers
		.iter()
		.min_by_key(|h| *h.number())
		.ok_or(Error::UnknownHeadersEmpty)?;

	if base.number() < &consensus_state.latest_height {
		headers
			.ancestry(base.hash(), consensus_state.latest_hash)
			.map_err(|_| Error::InvalidAncestry)?;
	}

	let finalized = headers.ancestry(from, target.hash()).map_err(|_| Error::InvalidAncestry)?;

	// 2. verify justification.
	justification
		.verify(consensus_state.current_set_id, &consensus_state.current_authorities)
		.map_err(|e| Error::JustificationVerify(e.to_string()))?;

	// Sets new consensus state, optionally rotating authorities
	consensus_state.latest_hash = target.hash();
	consensus_state.latest_height = (*target.number()).into();
	if let Some(scheduled_change) = find_scheduled_change::<H>(&target) {
		consensus_state.current_set_id += 1;
		consensus_state.current_authorities = scheduled_change.next_authorities;
	}

	Ok((consensus_state, target.clone(), finalized, headers))
}
