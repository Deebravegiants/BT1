### Title
Intent-solver Uniswap V4 venue pricing uses manipulable pool spot price with only a static-deviation guard, enabling profit extraction from solver liquidity - ([File: sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts])

### Summary
The JOJO report describes manipulating a thin-liquidity order book's mid-price to bias a funding-rate calculation. The reachable analog in this repo is Hyperbridge's Simplex intent-filling solver: for "venue-priced" pairs (no configured bid/ask curves) it prices cross-chain intent fills directly from a single Uniswap V4 pool's spot price, protected only by a static-reference deviation check, not by a TWAP or execution-cost model.

### Finding Description
When a pair has no configured curves and token0 is a USD stablecoin, `resolveLegRates` sources the fill rate from the venue instead of a curve: `venueUsdPrice` → `UniswapV4FundingPlanner.getExoticTokenPrice` → `computeDirectPoolPriceUsd`, which returns `sqrtPool.token0Price`/`token1Price` — the raw instantaneous pool mid derived from `sqrtPriceX96` — for whichever configured position has the largest liquidity [1](#0-0) [2](#0-1) .

The only defense against a manipulated quote is `checkPriceGuard`, which compares this live venue rate against a static `referencePrice` within `maxDeviationBps` (defaulting to unguarded if unset) — a deviation-from-a-stale-anchor check, not a check on real execution cost or a manipulation-resistant TWAP [3](#0-2) . The design writeup for this flow confirms the pool's own fee tier is never applied to the mid and there is no size/impact term: `computeLegPolicyOutput` extends the raw mid linearly across the whole priced quantity [4](#0-3) . The resolved venue rate is then used directly to size the solver's fill: `resolveLegRates` returns `venueRate = 1/venueUsd` for the leg with `priceSource: "venue"`, feeding straight into the amount-out calculation for the intent fill [5](#0-4) .

Because this is the same instantaneous AMM spot price a flash-loan/large-swap attacker can move within a single block (or hold across a couple of blocks, still inside `maxDeviationBps`), an attacker can push the pool price to the edge of the allowed deviation band before an intent targeting that pair is submitted or filled, causing the solver to quote/fill at a rate that is favorable to the attacker and unfavorable to the solver's escrowed liquidity — structurally identical to the JOJO issue where a thin order book's midPrice is steered to bias a downstream calculation used to move value.

### Impact Explanation
A successful attack lets an intent submitter extract value from the solver's on-chain liquidity (Uniswap V4 LP positions funding token deliveries) by forcing fills at a manipulated exchange rate, i.e., concrete theft of solver funds on low-liquidity "venue-priced" pairs. This affects real value transferred through the intents/solver system, which is one of the explicitly in-scope reachable surfaces (intent solver pricing/fills).

### Likelihood Explanation
Requires a pair configured with `[vault.uniswapV4]` positions and no curves (an explicitly documented, supported configuration) and a pool with liquidity thin enough that `maxDeviationBps` can be exceeded/approached via an affordable swap or flash loan. Likelihood is data/config-dependent (thin exotic-token pools are the documented target use case for this feature, e.g., cNGN), but does not require any privileged role — any actor can submit a qualifying intent after moving the target pool's spot price.

### Recommendation
Replace or supplement the raw pool spot price with a manipulation-resistant reference (e.g., a Uniswap V4 TWAP oracle over a sufficient window, or a second independent price source) before using it to size fills. Apply the pool's actual fee tier and a size/impact term proportional to trade size rather than extending the mid linearly, and tighten/enforce `maxDeviationBps` and `referencePrice` as mandatory (not optional) for all venue-priced pairs, consistent with the guard's stated purpose in `checkPriceGuard`.

### Proof of Concept
1. Configure a venue-priced pair (no `bidPricePolicy`/`askPricePolicy`) backed by a single low-liquidity Uniswap V4 position, per the documented flow [6](#0-5) .
2. Attacker swaps against the pool to move `sqrtPriceX96` such that `token0Price`/`token1Price` shifts favorably but stays within `maxDeviationBps` of the configured `referencePrice`.
3. Attacker submits (or has pending) an intent on this pair; `resolveLegRates` → `getExoticTokenPrice` → `computeDirectPoolPriceUsd` returns the manipulated spot price, `checkPriceGuard` passes since it's inside the tolerance band, and the solver fills at the skewed rate [5](#0-4) .
4. Attacker reverses/arbitrages the pool price back, keeping the value extracted from the solver's fill.

	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}

	private computeDirectPoolPriceUsd(
		pos: HydratedV4Position,
		sdkPool: V4Pool,
		chain: string,
	): { exoticToken: string; priceUsd: Decimal } | null {
		const usdc = this.configService.getUsdcAsset(chain).toLowerCase()
		const usdt = this.configService.getUsdtAsset(chain).toLowerCase()
		const c0 = pos.currency0.toLowerCase()
		const c1 = pos.currency1.toLowerCase()

		if (c0 === usdc || c0 === usdt) {
			// currency0 is stable → exotic is currency1
			// token1Price = "token0 per token1" = USD per exotic
			return {
				exoticToken: c1,
				priceUsd: new Decimal(sdkPool.token1Price.toFixed(18)),
			}
		}

		if (c1 === usdc || c1 === usdt) {
			// currency1 is stable → exotic is currency0
			// token0Price = "token1 per token0" = USD per exotic
			return {
				exoticToken: c0,
				priceUsd: new Decimal(sdkPool.token0Price.toFixed(18)),
			}
		}

		return null
	}

	private async resolveLegRates(
		orderId: string | undefined,
		leg: ResolvedLeg,
		cappedPairNotional: Decimal,
		venueUsdPrice: (chain: string, token1Address: string) => Promise<Decimal | null>,
	): Promise<LegRates | null> {
		// Explicitly configured curves always win — the venue only prices pairs
		// with no curves at all (and never same-token pairs, where a venue quote
		// would just be the asset's own USD price, not a spread).
		const curveless = !leg.pair.bidPricePolicy && !leg.pair.askPricePolicy
		if (curveless && !isSameTokenPair(leg.pair) && USD_STABLE_SYMBOLS.has(normalizeSymbol(leg.pair.token0))) {
			const venueUsd = await venueUsdPrice(leg.token1Chain, leg.token1Address)
			if (venueUsd) {
				// Guard compares the venue's token1-per-USD quote against the static reference.
				if (!this.checkPriceGuard(orderId, leg.token1Chain, new Decimal(1).div(venueUsd))) {
					return null
				}
				// A pool mid is ONE price, not a book: there is no opposite side
				// to report a round-trip margin against. The price guard above is
				// the venue-specific defense.
				const venueRate = new Decimal(1).div(venueUsd)
				return { rate: venueRate, oppositeRate: null, priceSource: "venue" }
			}
		}

		const askRate = leg.pair.askPricePolicy?.getPrice(cappedPairNotional) ?? null
		const bidRate = leg.pair.bidPricePolicy?.getPrice(cappedPairNotional) ?? null

		const rate = leg.inputIsToken0 ? askRate : bidRate
		if (!rate) {
			this.logger.debug(
				{ orderId, pair: `${leg.pair.token0}/${leg.pair.token1}`, inputIsToken0: leg.inputIsToken0 },
				"Rejecting leg: direction disabled for one-sided LP",
			)
			return null
		}
		return { rate, oppositeRate: leg.inputIsToken0 ? bidRate : askRate, priceSource: "policy" }
