### Title
Fraud detection is a permanent no-op, allowing every signup to bypass fraud checks - (File: `src/plans/mod.rs`)

### Summary
The Illuminate report describes a function (`transferFrom`) that is invoked by critical flows (`mint`/`mintWithUnderlying`) but was never actually implemented, so the calling functions could never perform their intended job even though the code compiles/executes up to that point. The orb-core analog is `detect_fraud`, which is called from the signup pipeline as the sole fraud-enforcement gate but its body has been stripped down to an unconditional `Ok(false)`, meaning the function can never report fraud regardless of the biometric pipeline results passed into it.

### Finding Description
`detect_fraud` is defined to take the completed biometric `pipeline` and orb state and to decide whether the signup should be flagged as fraudulent: [1](#0-0) 

The function signature and call site make it look like a real fraud-check gate (it takes the `pipeline` results as input and is awaited before enrollment), but the body immediately discards the pipeline and unconditionally returns `Ok(false)` — "no fraud detected" — for every single signup, with the only comment being `// FOSS: WE HAVE DELETED ALL FRAUD CHECKS`. This mirrors the `transferFrom` bug class: a function that downstream logic depends on for correct/safe operation is effectively a stub that never performs its stated function, while the surrounding code continues to treat its (meaningless) return value as authoritative.

The supporting config type confirms there are zero fraud checks wired in: [2](#0-1) 

Because `detect_fraud`'s result feeds directly into signup completion status handling (`SignupStatus::Fraud` is only ever reachable if this function returns `true`, which it structurally cannot), the fraud path in `ui_complete_signup` is dead code in this build: [3](#0-2) 

### Impact Explanation
Any user going through the signup flow — including one who fails legitimate anti-fraud heuristics that the pipeline was designed to run — will always be reported as "not fraudulent" and proceed to `enroll_user`/enrollment, since the single fraud gate in the codebase can never return `true`. This is a functional fraud/liveness-bypass condition: the enforcement mechanism exists in the call graph but is non-functional, exactly analogous to the referenced report's finding that critical functionality (`transferFrom`) is invoked but never implemented, silently defeating the intended protection while the rest of the pipeline behaves as if it works.

### Likelihood Explanation
This triggers on every single signup attempt with no attacker action required beyond going through the normal enrollment flow — the code path is unconditionally reached for any biometric pipeline result, so likelihood is effectively certain rather than probabilistic.

### Recommendation
Restore or reimplement the fraud-check logic inside `detect_fraud` so that it actually evaluates the `pipeline` results (or, if fraud checks are intentionally omitted for the FOSS build, make that limitation explicit and gate any fraud-dependent trust decisions accordingly rather than silently returning a fixed "no fraud" result that downstream code treats as a real verdict).

### Proof of Concept
1. Run any signup through the orb-core pipeline so that `biometric_pipeline::Pipeline` is produced.
2. Observe that `detect_fraud` is called with `Some(&pipeline)` at the fraud-detection phase.
3. Regardless of pipeline content, execution reaches `// FOSS: WE HAVE DELETED ALL FRAUD CHECKS` and returns `Ok(false)` unconditionally.
4. `SignupStatus::Fraud` in `ui_complete_signup` is therefore unreachable in this build, confirming fraud enforcement is fully bypassed for all signups. [4](#0-3)
