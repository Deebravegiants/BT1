### Title
Stale owner-scoped delegate grant regains account control after NFT round-trip - ([File: contracts/controller/src/storage/account.rs])

### Summary
A previously delegated position manager can regain full owner-equivalent control over an account after its position NFT leaves and returns to the granting owner, because grants are invalidated only by comparing the stored `granted_by` address with the current owner and carry no ownership epoch. [1](#0-0)  Once the original owner again owns the NFT, the stale grant passes `is_owner_or_delegate`, allowing the delegate to withdraw collateral or borrow to an arbitrary external recipient. [2](#0-1) 

### Finding Description
The controller resolves the account owner dynamically from the position NFT instead of caching it, so account authority changes when the NFT moves. [3](#0-2)  However, `ControllerKey::Delegates(account_id)` stores one `DelegateGrant` stamped only with the granting owner's address, not with an ownership epoch, transfer counter, or other transfer-aware credential. [1](#0-0) 

`is_owner_or_delegate` authorizes `caller` when it is either the current owner or an active position manager contained in the delegate list stamped by that same owner. [2](#0-1)  While a different owner holds the NFT, the old grant is inactive because `granted_by` no longer equals the current owner, but the stored list is not necessarily deleted. [1](#0-0)  If the NFT later returns to the original owner and no intervening owner called `remove_delegate` or added a replacement grant, the stale `DelegateGrant` again matches the current owner and becomes active. [4](#0-3) 

An unauthorized-by-current-owner intent is therefore enforced only partially: the check distinguishes a different current owner, but not a new ownership period belonging to the same address. [2](#0-1)  `withdraw` accepts that revived authority and sends the collateral to `to`, defaulting to the delegate when `to` is absent. [5](#0-4) 

### Impact Explanation
A stale delegate can withdraw the returned account's collateral to itself, or borrow up to the account's remaining risk limits and select itself as recipient. [6](#0-5) [7](#0-6)  This is theft of user funds and can also leave the restored owner with protocol debt created by the former delegate. [8](#0-7) 

### Likelihood Explanation
The attacker must be an active registered position manager that received a delegate grant from an earlier holder, and the NFT must return to that holder without an intervening owner purging or replacing the stale grant. [9](#0-8)  The protocol explicitly permits direct NFT transfers, so no attacker privilege or leaked key is needed to move account ownership away and back. [10](#0-9)  The sequence is realistic during sales, custody changes, collateralized transfers, marketplace settlement, or temporary transfers where the prior holder later regains the token. [11](#0-10) 

### Recommendation
Bind every delegate grant to a distinct NFT ownership epoch rather than only to an owner address. [1](#0-0)  Extend the position NFT with a monotonically increasing transfer counter or ownership generation, include that value in `DelegateGrant`, and require both `granted_by` and the current generation to match inside `is_owner_or_delegate`. [2](#0-1)  Alternatively, make every NFT transfer synchronously invalidate the account's delegate list so a grant can never survive an ownership boundary. [4](#0-3) 

### Proof of Concept
1. Alice calls `supply` and receives account `A`; governance activates manager `M`, and Alice calls `add_delegate(Alice, A, M)`. [12](#0-11) [13](#0-12) 
2. Alice transfers NFT `A` to Bob; the stored grant remains stamped by Alice, but `get_delegates(A, Bob)` returns empty because `granted_by != Bob`. [1](#0-0) 
3. Bob does not call `remove_delegate` or `add_delegate`, and later transfers NFT `A` back to Alice; `granted_by == Alice` again makes `M`'s stored grant visible. [1](#0-0) 
4. `M` calls `withdraw(caller=M, account_id=A, withdrawals=[(collateral, 0)], to=Some(M))`; `require_owner_or_delegate` accepts the revived grant, and the pool payout goes to `M`. [2](#0-1) [5](#0-4)

```rust
/// Returns grants stamped by `owner`, or an empty list. Ownership changes

pub(crate) fn get_delegates(env: &Env, account_id: u64, owner: &Address) -> Vec<Address> {
    get_user::<DelegateGrant>(env, &ControllerKey::Delegates(account_id))
        .filter(|grant| grant.granted_by == *owner)
        .map(|grant| grant.delegates)
```

```rust
/// Removes a live delegate and reports whether it changed the list.
/// Deletes stale grants but returns false, preventing those grants from
/// reactivating if the NFT returns to their original owner.
pub(crate) fn remove_delegate(
    env: &Env,
    account_id: u64,
    owner: &Address,
    delegate: &Address,
) -> bool {
    let key = ControllerKey::Delegates(account_id);
    let Some(grant) = get_user::<DelegateGrant>(env, &key) else {
        return false;
    };
    if grant.granted_by != *owner {
        env.storage().persistent().remove(&key);
        return false;
    }
    let mut delegates = grant.delegates;
    let Some(index) = delegates.first_index_of(delegate) else {
        return false;
    };
    delegates.remove(index);
    set_delegates(env, account_id, owner, &delegates);
    true
```

```rust
pub(crate) fn is_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) -> bool {
    if caller == owner {
        return true;
    }
    let active_manager =
        storage::get_position_manager(env, caller).is_some_and(|config| config.is_active);
    active_manager && storage::get_delegates(env, account_id, owner).contains(caller)
}
```

```rust
/// Requires the NFT owner to revoke manager access; renews instance TTL.
pub(crate) fn remove_delegate(env: &Env, caller: Address, account_id: u64, delegate: Address) {
    storage::renew_controller_instance(env);
    set_account_delegate(env, &caller, account_id, &delegate, false);
}

/// Authenticates the NFT owner and updates delegates; grants require an active
/// manager. Emits an event only when the current owner's delegate list changes.
fn set_account_delegate(
    env: &Env,
    caller: &Address,
    account_id: u64,
    delegate: &Address,
    add: bool,
) {
    caller.require_auth();
    require_account_owner(env, account_id, caller);
    if add {
        // Reject dormant grants that could gain authority on later manager activation.
        assert_with_error!(
            env,
            storage::get_position_manager(env, delegate).is_some_and(|c| c.is_active),
            GenericError::NotAuthorized
        );
    }

    let changed = if add {
        storage::add_delegate(env, account_id, caller, delegate)
    } else {
        storage::remove_delegate(env, account_id, caller, delegate)
    };
```
