### Title
Reward misattribution in `pallet-consensus-incentives::on_executed` lets a frontrunner steal the entire batch reward by prepending a cheap self-signed message - (File: `modules/pallets/consensus-incentives/src/impls.rs`)

### Summary
`pallet-consensus-incentives` pays the `$BRIDGE` consensus-relaying reward for **every** `StateMachineUpdated` event produced by an unsigned `handle_unsigned` batch, but it recovers the payee account from **only the first message in the batch** (`messages.get(0)`). Because `handle_unsigned` is an unsigned, permissionless extrinsic whose contents are visible in the mempool before inclusion, an attacker can copy a pending (honest) relayer's multi-message consensus batch, prepend a trivial, self-signed consensus message of their own as index 0, and resubmit it with higher priority/gas. All of the resulting `StateMachineUpdated` events - including the ones produced by the honest relayer's expensive proofs - get attributed to the attacker's account.

### Finding Description
`FeeHandler::on_executed` is invoked once per processed batch of ISMP messages with the full `Vec<MessageWithWeight>` and the full `Vec<Event>` produced by that batch [1](#0-0) .

The consensus-incentives implementation determines the relayer/payee from **only the first message**:

```rust
let maybe_relayer_account = messages.get(0).and_then(|first_message| {
    if let Message::Consensus(consensus_msg) = &first_message.message {
        let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
        Signature::decode(&mut &consensus_msg.signer[..])
            .ok()
            .and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
            .map(|pub_key| pub_key.into())
    } else {
        None::<[u8; 32]>
    }
});
``` [2](#0-1) 

It then iterates over **every** `StateMachineUpdated` event in the whole batch (collapsing per state machine to the highest height) and pays the reward for each one to that single recovered `relayer_account`, regardless of which message in the batch actually produced it:

```rust
let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
for event in events {
    if let IsmpEvent::StateMachineUpdated(update) = event {
        highest_per_state_machine...
    }
}
for (state_machine_id, latest_height) in highest_per_state_machine {
    let _ = Self::process_message(state_machine_height, state_machine_id, relayer_account.clone().into());
}
``` [3](#0-2) 

`handle_unsigned` is an unsigned (`ensure_none`) extrinsic; per-message `signer` fields inside each `ConsensusMessage` are used only for reward attribution, not for dispatch authorization, and the whole batch is publicly visible in the mempool before inclusion (mirroring the pattern used elsewhere for unsigned message batches, e.g. `state-coprocessor`'s `validate_unsigned` on a `Vec` of messages) [4](#0-3) . Reward size scales with `(LatestHeight - PreviousHeight) * CostPerBlock`, i.e. with the magnitude of the state advance carried by the *other* messages in the batch, not with the cost of the message the attacker actually supplied [5](#0-4) .

This is structurally the same bug class as the referenced Sherlock finding: a permissionless, unsigned reward-granting call processes a batch whose per-item cost and the reward-eligibility marker are decoupled, so a frontrunner can substitute a cheap element to redirect a reward that should have gone to whoever incurred the real cost.

### Impact Explanation
An attacker who monitors the mempool for pending `handle_unsigned` consensus batches (which, per Hyperbridge's own documentation, are the primary channel by which consensus relayers earn `$BRIDGE` + reputation, `Reward = (LatestHeight - PreviousHeight) * CostPerBlock`) can:
1. Copy the pending batch's `Message::Consensus` entries (public in the mempool).
2. Prepend a trivial, cheaply-constructed, self-signed `ConsensusMessage` as index 0 (e.g. a message advancing a low-cost/low-`CostPerBlock` state machine by one block, or one they already know will pass `update_client` verification cheaply).
3. Resubmit the combined batch with higher gas/priority so it lands first.

Because `on_executed` derives the sole payee from `messages[0]`, the attacker receives the entire treasury payout and reputation mint for every `StateMachineUpdated` event in the batch — including the expensive proof(s) supplied by the original relayer — while the original relayer receives nothing. This is a direct theft of relayer reward funds from the treasury and an unearned mint of the non-transferable reputation asset (which also feeds collator selection), constituting concrete economic loss and unfair protocol-influence gain.

### Likelihood Explanation
`handle_unsigned` batches are unsigned and gossip through the public mempool before inclusion, so any relayer/watcher can observe pending batches. Constructing a cheap, valid, self-signed `ConsensusMessage` to occupy index 0 requires no special privilege — the signature is verified only for reward-attribution purposes, not for dispatch authorization. Any operator running a Hyperbridge consensus-relaying node already has everything needed to perform this attack; it requires no governance or admin access and no unusual capital outlay beyond minor gas/priority bidding.

### Recommendation
Attribute the reward per-message rather than per-batch: track which `Message::Consensus` entry produced each `StateMachineUpdated` event (e.g. by having `update_client` tag its resulting events with the index or signer of the originating message) and pay the relayer recovered from that specific message's signature, not from `messages[0]` alone. Alternatively, require that all consensus messages in a single `handle_unsigned` batch share a single signer, and reject/split batches containing mixed signers before reward processing.

### Proof of Concept
1. Honest relayer `R1` observes chain `X` finalize new blocks, builds a valid, possibly expensive `ConsensusMessage` proof (`consensus_proof`) that will advance `StateMachineId(X)` from height `H` to `H+N`, signs it, and submits `handle_unsigned(origin: None, messages: [Msg_X])`. This transaction propagates through the mempool.
2. Attacker `A` observes the pending unsigned extrinsic, extracts `Msg_X`.
3. `A` builds their own trivial/cheap `ConsensusMessage` `Msg_cheap` for any state machine `Y` they can cheaply advance (or even a no-op advance they already know is valid), and signs it with their own key.
4. `A` submits `handle_unsigned(origin: None, messages: [Msg_cheap, Msg_X])` with higher priority so it lands first (or races `R1`'s transaction out via network propagation).
5. `update_client` processes both messages, producing `StateMachineUpdated` events for both `Y` and `X`.
6. `pallet_consensus_incentives::on_executed` reads `messages.get(0)` = `Msg_cheap`, recovers `A`'s account as `relayer_account`, then pays `A` the reward for **both** the `Y` advance and the expensive `X` advance (`Reward = (H+N - H) * CostPerBlock_X`), while `R1`, who did the real work of producing the `X` proof, receives nothing. `R1`'s own duplicate/original submission (if it lands separately) fails the "only advances the state" check in `update_client` since the height was already advanced, so `R1` gets no second chance at the reward. 		messages: Vec<MessageWithWeight>,
		events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});

		if let Some(relayer_account) = maybe_relayer_account {
			// When a batch contains multiple `StateMachineUpdated` events for the
			// same `state_machine_id` (sequential consensus updates for the same
			// chain), `calculate_reward` reads the same persisted
			// `(latest_commitment_height, previous_commitment_height)` pair on
			// every iteration and pays the same block-span reward N times.
			// Collapse the per-state-machine event stream to the single highest
			// `latest_height` so each state machine receives one reward per
			// batch, sized by the actual span of its commitment advance.
			let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
			for event in events {
				if let IsmpEvent::StateMachineUpdated(update) = event {
					highest_per_state_machine
						.entry(update.state_machine_id)
						.and_modify(|h| {
							if update.latest_height > *h {
								*h = update.latest_height;
							}
						})
						.or_insert(update.latest_height);
				}
			}

			for (state_machine_id, latest_height) in highest_per_state_machine {
				let state_machine_height =
					StateMachineHeight { id: state_machine_id.clone(), height: latest_height };

				let _ = Self::process_message(
					state_machine_height,
					state_machine_id,
					relayer_account.clone().into(),

/// This function handles verification of consensus messages for consensus clients
pub fn update_client<H>(host: &H, msg: ConsensusMessage) -> Result<MessageResult, anyhow::Error>
where
	H: IsmpHost,
{
	let consensus_client_id = host.consensus_client_id(msg.consensus_state_id).ok_or(
		Error::ConsensusStateIdNotRecognized { consensus_state_id: msg.consensus_state_id },
	)?;
	let consensus_client = host.consensus_client(consensus_client_id)?;
	let trusted_state = host.consensus_state(msg.consensus_state_id)?;
	host.is_consensus_client_frozen(msg.consensus_state_id)?;
	host.is_expired(msg.consensus_state_id)?;

	let (new_state, intermediate_states) = consensus_client.verify_consensus(
		host,
		msg.consensus_state_id,
		trusted_state,
		msg.consensus_proof,
	)?;
	host.store_consensus_state(msg.consensus_state_id, new_state)?;
	let timestamp = host.timestamp();
	host.store_consensus_update_time(msg.consensus_state_id, timestamp)?;
	let mut state_updates = vec![];
	for (id, mut commitment_heights) in intermediate_states {
		commitment_heights.sort_unstable_by(|a, b| a.height.cmp(&b.height));
		let previous_latest_height = host.latest_commitment_height(id)?;
		let mut last_commitment_height = None;
		for commitment_height in commitment_heights.iter() {
			let state_height = StateMachineHeight { id, height: commitment_height.height };

			// Only allow heights greater than latest height
			if previous_latest_height > commitment_height.height {
				continue;
			}

			// Skip duplicate states
			if host.state_machine_commitment(state_height).is_ok() {
				continue;
			}

			last_commitment_height = Some(state_height);
			host.store_state_machine_commitment(state_height, commitment_height.commitment)?;
			host.store_state_machine_update_time(state_height, host.timestamp())?;
		}

		if let Some(latest_height) = last_commitment_height {
			let latest_height = StateMachineHeight { id, height: latest_height.height };
			state_updates.push(Event::StateMachineUpdated(StateMachineUpdated {
				state_machine_id: id,
				latest_height: latest_height.height,
			}));
			host.store_latest_commitment_height(latest_height)?;
		}
	}

	Ok(MessageResult::ConsensusMessage(state_updates))
}
