### Title
Unbounded debt valuation overflow permanently freezes all market operations - ([File: common/src/rates/index.rs])

### Summary
A sufficiently large market can reach a state in which valuing `borrowed * borrow_index / RAY` exceeds `i128::MAX`. Because accrual runs before every pool mutation, the resulting `MathOverflow` permanently prevents repayment, withdrawal, liquidation, bad-debt cleanup, and further index updates for that market.

### Finding Description
`accrue_step` first converts scaled debt and supply to RAY-denominated values, then calls `calculate_supplier_rewards`. [1](#0-0)  `calculate_supplier_rewards` multiplies total scaled debt by both the old and new borrow indexes through `Ray::mul`. [2](#0-1)  `Ray::mul` delegates to `mul_div_half_up`, which widens only the intermediate product to `I256`; if the final debt value does not fit in `i128`, `to_i128()` returns `None` and the function panics with `GenericError::MathOverflow`. [3](#0-2) [4](#0-3) 

The borrow-index cap does not prevent this condition because the debt-value ceiling is reached before `MAX_BORROW_INDEX_RAY`. [5](#0-4)  Pool mutations load the market and run `global_sync` before applying the requested operation, so once this state is reached every subsequent state-changing path for the market hits the same overflow. [6](#0-5)  The permissionless controller `update_indexes` entrypoint invokes the same pool accrual path. [7](#0-6) 

### Impact Explanation
All supplier principal, borrower collateral backing the market, and unclaimed protocol revenue in the affected market become permanently frozen. Repayment and withdrawal both require successful accrual before their accounting logic runs; the repository’s regression test demonstrates that both operations revert with `MATH_OVERFLOW` after the debt-value ceiling is crossed. [8](#0-7)  Liquidation and bad-debt processing are also blocked because they must accrue and value the same market before mutating it.

### Likelihood Explanation
Reaching the condition requires an exceptionally large market and sustained borrowing, but no privileged action is needed after the market exists. An unprivileged liquidity provider can call `supply`, a sufficiently collateralized borrower can call `borrow`, and any account can later call `update_indexes` with the affected `HubAssetKey` to advance accrual. [9](#0-8) [7](#0-6)  The existing test establishes the reachability of the overflow before the configured borrow-index ceiling. [10](#0-9) 

### Recommendation
Track and enforce a total-debt-value bound rather than relying only on `MAX_BORROW_INDEX_RAY`. Before committing index growth, compute the prospective debt value with a non-panicking check and cap accrual while `borrowed * new_borrow_index / RAY` remains representable. Alternatively, store debt values in a wider type or introduce an explicit market-level saturation state that still permits repayments, withdrawals, liquidation, and bad-debt cleanup without executing the overflowing accrual calculation.

### Proof of Concept
The repository contains a reproduction in `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap`:

1. Supply a 1-billion-token position in an 18-decimal market and borrow 98% of it.
2. Advance ledger time in one-year increments while calling `update_indexes`.
3. Accrual eventually reaches a borrow index below `MAX_BORROW_INDEX_RAY` at which `borrowed * borrow_index / RAY` no longer fits in `i128`.
4. The next `update_indexes` call fails with `MATH_OVERFLOW`.
5. Subsequent `withdraw` and `repay` calls fail with the same error because both accrue first. [10](#0-9)

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
