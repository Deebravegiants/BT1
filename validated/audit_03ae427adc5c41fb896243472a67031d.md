Audit Report

## Title
CORS Wildcard-Suffix Bypass in Gateway User HTTP Server Allows Cross-Origin Data Theft - (File: core/services/gateway/network/httpserver.go)

## Summary
The `isAllowedOrigin` function in the Gateway's internet-facing user HTTP server matches wildcard `CORSAllowedOrigins` entries (e.g. `https://*.ethereum.org`) using a raw `strings.HasSuffix` comparison with no subdomain-boundary check. This lets any attacker-registrable domain that merely ends with the same substring (e.g. `evilethereum.org`) be treated as a valid subdomain match, causing the server to reflect that attacker origin into `Access-Control-Allow-Origin` and expose gateway JSON-RPC responses to cross-origin script.

## Finding Description
In `isAllowedOrigin` [1](#0-0) , when an allowed origin is a wildcard (`*.host`), the code strips the `*.` prefix and checks `strings.HasSuffix(originHost, allowedHost)`. This performs a plain substring-suffix test rather than validating that the origin host is either exactly `allowedHost` or ends with `"."+allowedHost`. As a result, `evilethereum.org` incorrectly satisfies `strings.HasSuffix("evilethereum.org", "ethereum.org")`.

This function is called directly from `handleRequest` [2](#0-1) , which sets `Access-Control-Allow-Origin` to the attacker-supplied `Origin` header verbatim whenever `isAllowedOrigin` returns true, with no additional boundary validation performed anywhere else in the request path. There is no other CORS library or middleware layered on top — this hand-rolled matcher is the sole gatekeeper.

The existing test suite in `httpserver_test.go` only exercises correctly-matching subdomains (`remix.ethereum.org`, `another.valid.domain.com`, `example.gov`) and a non-matching unrelated domain (`ethereum.remix.org`), but never tests a domain that shares the suffix string without a dot boundary (e.g. `evilethereum.org` vs `*.ethereum.org`), so the flaw is untested and unnoticed. The wildcard feature itself is a documented, supported configuration pattern (evidenced by the dedicated test `TestHTTPServer_HandleRequest_CORSEnabled_FromAllowedOriginWildcards`), not a misuse or misconfiguration by the operator — the bug is purely in the matching logic's implementation.

## Impact Explanation
The gateway user HTTP server is the internet-facing entry point that unprivileged clients use to submit JSON-RPC requests, with responses proxied via `gateway.ProcessRequest`. If an operator configures a wildcard subdomain entry in `CORSAllowedOrigins` (a legitimate, intended use case), an attacker who registers or controls a domain lexically ending in the same suffix can host a cross-origin page that reads back gateway JSON-RPC responses that should only be accessible to genuine subdomains. This is a concrete allowlist-bypass enabling cross-origin data disclosure of gateway response content.

## Likelihood Explanation
Exploitation requires only that the operator enable `CORSEnabled` with a wildcard entry (a supported, tested configuration) and that the attacker register any domain ending with the configured suffix (trivial and cheap, e.g. `evilethereum.org`, `notethereum.org`). No credentials, privileged access, or victim interaction beyond visiting the attacker's page while the browser sends normal fetch/XHR requests is required — the attacker's own domain and browser suffice.

## Recommendation
Fix `isAllowedOrigin` to enforce a real subdomain boundary: require `originHost == allowedHost` or `strings.HasSuffix(originHost, "."+allowedHost)` instead of a bare suffix match. Add regression tests for suffix-sharing but non-subdomain hosts (e.g. `evilethereum.org` against `*.ethereum.org`). Consider replacing the custom matcher with a vetted, well-tested host/domain parsing approach or CORS library that compares DNS labels rather than raw strings.

## Proof of Concept
1. Configure: `CORSEnabled = true`, `CORSAllowedOrigins = ["https://*.ethereum.org"]`.
2. Send a request to the gateway `/user` endpoint with header `Origin: https://evilethereum.org`.
3. Observe the server responds with `Access-Control-Allow-Origin: https://evilethereum.org` because `strings.HasSuffix("evilethereum.org", "ethereum.org")` returns `true` in `isAllowedOrigin` [3](#0-2) , confirming the bypass. This can be codified as a Go unit test analogous to `TestHTTPServer_HandleRequest_CORSEnabled_FromAllowedOriginWildcards` but asserting that `https://evilethereum.org` is (incorrectly) accepted.
