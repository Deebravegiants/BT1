Audit Report

## Title
Reentrancy stipend protection (`AllowNext`) is unreachable for any value-transferring `CALL`, defeating Solidity's `.transfer()`/`.send()` reentrancy guarantee - (File: substrate/frame/revive/src/vm/evm/instructions/contract.rs)

## Summary
In `run_call`, the match on `(value.is_zero(), gas_limit == CALL_STIPEND)` places the wildcard arm `(false, _) => AllowReentry` before the stipend-check arm `(_, true) => AllowNext`, so any non-zero `value` always resolves to `AllowReentry` regardless of `gas_limit`. This makes `AllowNext` reachable only for zero-value calls, defeating the reentrancy protection intended for real Solidity `.transfer(amount)`/`.send(amount)` calls with `amount > 0`.

## Finding Description
`run_call` computes reentrancy mode via a tuple match where the first arm `(false, _) => (true, ReentrancyProtection::AllowReentry)` matches whenever `value.is_zero()` is false (i.e., any nonzero value), independent of `gas_limit`. Only when `value.is_zero()` is true does control reach the `(_, true) => AllowNext` arm that checks `gas_limit == CALL_STIPEND`. This is confirmed by the project's own `prdoc/stable2603/pr_11227.prdoc`, which explicitly states "The zero-value case is the one detected by our `gas_limit == CALL_STIPEND` heuristic, which triggers `AllowNext`," and documents that solc emits `gas_limit = 0` (not `CALL_STIPEND`) for real non-zero `.transfer(amount)`/`.send(amount)` calls, while it only emits explicit `gas_limit = 2300` for the zero-value corner cases `.transfer(0)`/`.send(0)`. The `ReentrancyProtection::AllowNext` doc comment in `exec.rs` states the intended purpose is protecting "calls that transfer value but restrict gas so that the callee only has a stipend gas amount" — but the implementation structurally excludes the non-zero-value case from ever reaching that protection. Downstream in `exec.rs`, `AllowReentry` leaves the callee frame's `allows_reentry` flag untouched, so the callee frame remains re-entrant into the caller. [3](#0-2) [4](#0-3) 

## Impact Explanation
Any pallet-revive contract using the idiomatic Solidity pattern `payable(x).transfer(amount)` or `.send(amount)` (nonzero amount) for value transfers loses the reentrancy protection this mechanism was designed to provide, since real-world compiler output (`gas_limit = 0`, `value > 0`) falls into the `AllowReentry` arm rather than `AllowNext`. This permits reentrant callbacks into the caller mid-execution, enabling classic reentrancy-based fund-draining attacks against contracts that rely on the stipend-restriction guarantee.

## Likelihood Explanation
This is deterministic and requires no special crafting: solc's default compiled output for `.transfer(amount)`/`.send(amount)` with `amount > 0` already triggers the buggy branch. Any unprivileged user can deploy an attacker contract with a reentrant fallback and interact with any victim contract using this pattern.

## Recommendation
Restructure the match so `AllowNext` is selected whenever the call is stipend-restricted regardless of `value.is_zero()` — i.e., detect `gas_limit == 0` (implicit stipend for nonzero-value transfers) or `gas_limit == CALL_STIPEND` (explicit stipend for zero-value transfers) as the condition for `AllowNext`, and only fall back to `AllowReentry` for calls forwarding non-stipend gas amounts (e.g., `.call{value: v}("")`).

## Proof of Concept
Add a unit test directly on `run_call`'s heuristic (or an EVM fixture test alongside `evm_call_stipends_work_for_transfer_zero`): for `value != 0` and `gas_limit == 0` (the actual solc-emitted case for `.transfer(amount)`, `amount > 0`), assert the selected `ReentrancyProtection` is `AllowNext`; currently it resolves to `AllowReentry`, which is provably incorrect against the documented intent in `exec.rs`'s `AllowNext` doc comment and the `prdoc/stable2603/pr_11227.prdoc` table of solc-emitted gas values. A full end-to-end integration test can deploy a `Victim` contract that decrements balance after `.transfer()`, and an `Attacker` contract that reenters `Victim.withdraw()` from its `receive()`, demonstrating that reentrancy succeeds instead of being denied.
