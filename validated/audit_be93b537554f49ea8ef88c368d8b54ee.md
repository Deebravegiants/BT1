### Title
Arbitrary route payload can smuggle caller-authorized token transfers through `swap_collateral` - ([File: contracts/controller/src/strategies/swap.rs](contracts/controller/src/strategies/swap.rs))

### Summary

A crafted `swap: Bytes` route can direct the configured router to attacker-controlled venue code that invokes an unrelated `token.transfer(caller, attacker, amount)` beneath the caller's authorized `swap_collateral` invocation. [1](#0-0) [2](#0-1) 

The controller validates only the configured router's input spend and output receipt; it does not decode the opaque route or constrain which contracts the route can execute. [3](#0-2) [4](#0-3) 

### Finding Description

`StrategySwap` is an opaque `Bytes` value supplied by the caller and forwarded verbatim to `SwapAggregatorClient::execute_strategy`. [5](#0-4) [2](#0-1) 

`swap_collateral` accepts this value as `swap`, authorizes the account owner or delegate, withdraws the selected collateral, and calls `withdraw_and_swap_from_supply`, which reaches `swap_tokens`. [6](#0-5) [7](#0-6) 

`swap_tokens` registers one exact invoker-contract authorization for `token_in.transfer(controller, router, amount_in)`, but that controller-level authorization does not limit other calls that route-selected code places beneath the caller's root authorization. [8](#0-7) [9](#0-8) 

The repository's authorization test demonstrates that simulation records a rogue hop pool's `wallet_token.transfer(victim, attacker, amount)` as a child of the victim's `swap_collateral` entry and that signing that recorded tree permits the transfer. [10](#0-9) [11](#0-10) 

This is the lending-protocol analogue of the external report: attacker-controlled bytes are interpreted as executable routing commands, and an embedded operation can perform an action beyond the apparent swap while still producing a valid output receipt. [12](#0-11) [13](#0-12) 

### Impact Explanation

A victim can lose wallet tokens unrelated to the lending position even though `swap_collateral` settles normally, deposits the expected output collateral, and passes the controller's measured-spend, measured-output, and final-risk checks. [14](#0-13) [4](#0-3) 

The demonstrated impact is theft of user funds: the test victim's entire unrelated token balance moves to the attacker while the intended collateral swap succeeds. [15](#0-14) [16](#0-15) 

### Likelihood Explanation

The attacker needs the victim to submit an attacker-supplied route and sign the authorization tree produced by simulation, so this is not an unauthenticated direct drain. [17](#0-16) [18](#0-17) 

The attack remains plausible because the malicious transfer appears only as a nested authorization child while the top-level call remains the expected `swap_collateral` with attacker-controlled opaque `swap` bytes. [19](#0-18) [18](#0-17) 

The same opaque `swap` argument is exposed by `swap_debt` and `repay_debt_with_collateral`, so the class is not confined to `swap_collateral`. [20](#0-19) [21](#0-20) 

### Recommendation

Decode and validate route payloads in, or before, the controller boundary and reject routes containing venue, pool, token, or callback addresses outside an explicit protocol-approved allowlist. [3](#0-2) [5](#0-4) 

If arbitrary venues remain supported, require the router interface to provide an authorization manifest that declares every nested invocation before execution, and have clients reject any simulation-derived child outside that manifest. [22](#0-21) [23](#0-22) 

### Proof of Concept

1. The attacker deploys a route-compatible contract that, during its swap callback, calls `unrelated_token.transfer(victim, attacker, victim_balance)`. [24](#0-23) 
2. The attacker encodes that contract as a hop destination inside the `swap` bytes and supplies a fair `token_out` payment so the controller's positive-output check succeeds. [25](#0-24) [26](#0-25) 
3. The victim calls `swap_collateral(caller=victim, account_id, current=USDC, amount, new=ETH, swap=malicious_route)`. [19](#0-18) [27](#0-26) 
4. Simulation records the rogue token transfer as a child under the victim's `swap_collateral` authorization. [28](#0-27) 
5. If the victim signs that tree, the host accepts the nested transfer, the attacker receives the unrelated wallet balance, and the victim's collateral swap still completes successfully. [15](#0-14) [11](#0-10)

/// Authorizes, on behalf of the current contract, one `transfer(from, to, amount)`
/// call on `token_addr` made deeper in the next contract call (for example by
/// the pool). The entry allows no further sub-invocations.
pub fn authorize_transfer_as_current(
    env: &Env,
    token_addr: &Address,
    from: &Address,
    to: &Address,
    amount: i128,
) {
    let entry = InvokerContractAuthEntry::Contract(SubContractInvocation {
        context: ContractContext {
            contract: token_addr.clone(),
            fn_name: symbol_short!("transfer"),
            args: (from.clone(), to.clone(), amount).into_val(env),
        },
        sub_invocations: Vec::new(env),
    });
    env.authorize_as_current_contract(vec![env, entry]);
}

#[test]
fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
