## Title
CORS origin allowlist bypass via improper wildcard/suffix hostname matching - (File: core/services/gateway/network/httpserver.go)

## Summary
The Gateway's `isAllowedOrigin` function performs a raw `strings.HasSuffix` comparison when matching wildcard CORS allowlist entries, without enforcing a domain-label boundary. This lets an attacker-controlled hostname that merely ends with an allowed suffix (e.g., `evilremix.com` matching an allowlist entry `*.remix.com`) be treated as an authorized subdomain, causing the Gateway to reflect permissive `Access-Control-Allow-Origin` headers for an unauthorized origin.

## Finding Description
`splitURL` extracts scheme/host/port from a raw URL string using `url.Parse` and `net.SplitHostPort` [1](#0-0) . `isAllowedOrigin` then compares the incoming `Origin` header's parsed host against each configured allowed origin. For wildcard entries prefixed with `*.`, it strips the prefix and does a bare `strings.HasSuffix(originHost, allowedHost)` check with no verification that the preceding character is a `.` [2](#0-1) .

Because of this, for an allowlist entry `*.remix.com`, `allowedHost` becomes `remix.com`, and `strings.HasSuffix("evilremix.com", "remix.com")` evaluates to `true`, incorrectly classifying `evilremix.com` — an entirely different, attacker-registrable domain — as a trusted subdomain. This root cause is confirmed directly in the code with no additional boundary check present anywhere in the function.

`handleRequest` calls `isAllowedOrigin` on the raw `Origin` header from an unauthenticated caller and, if it returns true, reflects the attacker's exact `Origin` value into `Access-Control-Allow-Origin`, along with permissive `Access-Control-Allow-Methods` and `Access-Control-Allow-Headers` [3](#0-2) . No other validation intervenes before this check.

## Impact Explanation
This is a genuine CORS-allowlist bypass: it lets a browser-based attacker whose site sits on a domain merely ending in the configured suffix receive `Access-Control-Allow-Origin` reflecting their own origin, letting their page make CORS requests to the Gateway that would otherwise be blocked and read the responses. This falls under the gateway request-impersonation / cross-user response corruption impact category referenced in scope.

## Likelihood Explanation
Exploitation requires only that `CORSEnabled` is `true` and `CORSAllowedOrigins` contains a wildcard entry, both of which are legitimate, ordinary configuration options for the Gateway (confirmed present in `HTTPServerConfig` and used in sample configs) [4](#0-3) . Registering a domain that ends in the allowed suffix (e.g., `evilremix.com`) is a low-cost, unprivileged action requiring no special access to the node or network. The attacker does not need any credential or role beyond controlling a domain and serving a webpage, matching the requirement that this be triggerable by an unprivileged actor via a normal browser request.

## Recommendation
Enforce a proper subdomain boundary in the wildcard branch of `isAllowedOrigin`, e.g.:
```go
if strings.HasPrefix(allowedHost, "*.") {
    allowedHost = allowedHost[2:]
    if originHost == allowedHost || strings.HasSuffix(originHost, "."+allowedHost) {
        return true
    }
}
```

## Proof of Concept
1. Configure the Gateway with `CORSEnabled = true` and `CORSAllowedOrigins = ["https://*.remix.com"]`.
2. Send an HTTP request to the Gateway's configured path with header `Origin: https://evilremix.com`.
3. Observe that `isAllowedOrigin` returns `true` (via `strings.HasSuffix("evilremix.com", "remix.com")`), and the response includes `Access-Control-Allow-Origin: https://evilremix.com`, `Access-Control-Allow-Methods: GET, POST, OPTIONS`, and `Access-Control-Allow-Headers: Content-Type` — verifiable with a Go unit test directly invoking `isAllowedOrigin("https://evilremix.com")` against this config, or an HTTP integration test asserting the response headers for that `Origin` value.

func (s *httpServer) splitURL(rawURL string) (string, string, string, error) {
	// lowercase the URL to avoid case sensitivity issues
	parsedURL, err := url.Parse(strings.ToLower(rawURL))
	if err != nil {
		return "", "", "", fmt.Errorf("error parsing URL: %w", err)
	}

	host, port, err := net.SplitHostPort(parsedURL.Host)
	if err != nil {
		// if there's no port, the host itself is returned
		if parsedURL.Host != "" {
			return parsedURL.Scheme, parsedURL.Host, "", nil
		}
		return "", "", "", fmt.Errorf("error splitting host and port: %w", err)
	}

	return parsedURL.Scheme, host, port, nil
}
