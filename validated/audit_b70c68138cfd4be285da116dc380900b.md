### Title
`canGraduate` underflow can permanently brick buys (and sell-side graduation checks) on a curve — ([File: packages/contracts/src/Bonding.sol])

### Summary
`Bonding.canGraduate()` computes `realLtRaised = assetReserve - _launchTimeVirtualLtReserve(...)` on every single buy via `_executeBuy`. This subtraction assumes the invariant `assetReserve ≥ virtualLtReserve` always holds. If that invariant is ever violated by even 1 wei — via `Pair.swap`'s rounding ("+1" K slack) accumulating across enough buy/sell round-trips — the subtraction underflows and reverts. Because `canGraduate()` is called unconditionally at the end of every `Bonding.buy()` (and is also relied on by the sell-side graduation short-circuit described in the protocol docs), a single underflow permanently bricks all future buys (and possibly sells) for that token, exactly mirroring the M05 pattern of an unconditional subtraction/view reverting and cascading into a total functional lock.

### Finding Description
`canGraduate` reads the pair's stored reserves and subtracts the launch-time virtual LT reserve to recover the real LT raised by the curve: [1](#0-0) 

This is invoked unconditionally at the end of every buy: [2](#0-1) 

`_launchTimeVirtualLtReserve` is a fixed constant recovered from `Pair.k() / Token.TOTAL_SUPPLY()`, which is set once at `Pair.mint` and — per the protocol's own documentation — never modified by `Pair.swap` except for the small rounding slack ("Pair.swap's `+1` K slack") that the AMM math tolerates to avoid reverting legitimate swaps on integer-division rounding. The correctness of `assetReserve - virtualLtReserve` (no underflow guard, no `SafeMath`/ternary floor) depends entirely on the invariant `assetReserve ≥ virtualLtReserve` holding for every possible sequence of buys and sells, including the accumulated effect of that rounding slack over many round-trip swaps. If that invariant is ever violated by even 1 wei, `canGraduate()` reverts with an arithmetic underflow panic.

This is structurally identical to the reported Mai Fund Protocol bug: a downstream accounting function (`totalAssetValue`/`marginBalance` there, `canGraduate`/`realLtRaised` here) assumes a value can never go negative, is called from many other paths, and once the edge-case invariant breaks, every function chained to it reverts — permanently, since there is no recovery path (the pair's reserves cannot be reset, and `canGraduate` has no try/catch or fallback).

### Impact Explanation
Because `canGraduate()` is invoked inline inside `Bonding.buy()` for every purchase (`_executeBuy` → `canGraduate` → possible `_enterGraduating`), an underflow here means:
- Every subsequent `Zap.buy()` / `Bonding.buy()` call for that token reverts permanently — the curve is bricked for buyers.
- The token can never reach `canGraduate() == true` legitimately again (the check itself reverts before it can return `true`), so the token can never graduate — LP formation for that token is permanently frozen, and the 750M/250M curve/LP-reserve split can never be resolved.
- `previewLtUntilGraduation`, which performs the analogous `reserveAsset - _launchTimeVirtualLtReserve(...)` subtraction, is also exposed to the same underflow and is called by `Zap._executeBuy` on every curve buy to size the LT mint, compounding the DoS.

This satisfies "permanent freezing of trader, creator, or LP funds" — capital already deposited on the curve (LT reserve, unsold tokens held by the pair, and the 250M `lpReserve` sitting in `Bonding`) becomes permanently stranded with no buy/graduation path forward.

### Likelihood Explanation
This requires the pair's rounding slack in `Pair.swap` (documented cross-repo as the "+1 K slack" tolerance used to avoid reverting on rounding-down conversions) to accumulate unfavorably across many buy/sell round trips on the same pair until `assetReserve` dips below the fixed `virtualLtReserve` floor by at least 1 wei. This is analogous to the original report's characterization as "an edge case" that is unlikely under normal parameters but can occur under adversarial or high-volume trading conditions (many round-trip swaps deliberately engineered to walk the rounding slack in one direction), similar to how the original bug required an edge case (margin account not liquidated before going negative) that the protocol author acknowledged as low-probability but real.

### Recommendation
- Replace the unchecked subtraction in `canGraduate` and `previewLtUntilGraduation` with a saturating subtraction (`assetReserve > floor ? assetReserve - floor : 0`), matching the defensive pattern already used elsewhere in the codebase (e.g., `finalizeGraduation`'s saturating subtract for `protectedLT`, at [3](#0-2) ).
- Audit `Pair.swap`'s K-invariant check to confirm whether the rounding slack can ever let `k`/`reserve1` be pushed below the launch-time virtual floor, and if so, tighten the check to preserve the `assetReserve ≥ virtualLtReserve` invariant unconditionally.

```text
    function canGraduate(
        address token_
    ) public view returns (bool) {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[token_];
        if (info.creator == address(0)) return false;
        if (info.lifecycle != Lifecycle.Curve) return false;

        address pair = info.pair;
        if (IPair(pair).tokenBalance() == 0) return true;

        (, uint256 assetReserve) = IPair(pair).getReserves();
        uint256 realLtRaised = assetReserve - _launchTimeVirtualLtReserve(token_, pair);
        uint256 valueUsd = (realLtRaised * IBounceLeveragedToken(info.ltAddress).exchangeRate()) / 1e18;
        return valueUsd >= $.graduationThresholdUsd;
    }
```

```text
    function _executeBuy(
        address tokenHolder,
        address trader,
        uint256 amountIn,
        address tokenAddress
    ) internal returns (uint256 tokensOut, uint256 amountInUsed) {
        (amountInUsed, tokensOut) = _s().router.buy(amountIn, tokenAddress, tokenHolder);

        (uint256 newCurveSupply, uint256 newLtReserve) = _getCurveState(tokenAddress);
        emit Trade(tokenAddress, trader, true, amountInUsed, tokensOut, newCurveSupply, newLtReserve);

        if (canGraduate(tokenAddress)) {
            _enterGraduating(tokenAddress);
        }
    }
```
