The OOB-write class maps best onto a bookkeeping "write past bounds" — writing a claim beyond what's backed. A test already hints at `apply_bad_debt_to_supply_index`'s floor clamp leaving a phantom claim. Let me check reachability.### Title
Bad-debt write-down clamps `supply_index` up to `SUPPLY_INDEX_FLOOR_RAW`, reviving wiped suppliers' shares into unbacked claims that drain later deposits - (File: contracts/pool/src/interest.rs)

### Summary
The CVE is an out-of-bounds write: the decoder writes past the end of a heap buffer, corrupting state beyond what was legitimately allocated. The lending analog is a **bookkeeping out-of-bounds write**: `apply_bad_debt_to_supply_index` writes a `supply_index` that is larger than the value legitimately remaining in the market, giving share balances a claim on cash that was already written off. When a bad-debt cleanup exceeds total supplied value, the index is clamped up to `RAY/1000` instead of zeroing supplier shares, so wiped-out suppliers keep a phantom claim that is paid out of future real deposits.

### Finding Description
`apply_bad_debt_to_supply_index` computes the post-write-down index as `supply_index * (total_supplied_value - capped) / total_supplied_value`, then applies `new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW))` [1](#0-0) . When `bad_debt >= total_supplied_value`, `remaining` is zero and the correct index is zero — but the clamp writes `RAY/1000` instead. No supplier shares are burned; `supplied`, each position's `scaled_amount`, and `revenue` are untouched. Every share therefore keeps a positive floor-valued claim (`unscale_supply_floor`) that is no longer backed by anything.

Reachability is permissionless: `process_clean_bad_debt` only requires `caller.require_auth()` plus the dust-capped insolvency gate [2](#0-1) , and the same path fires inside `liquidate` via `check_bad_debt_after_liquidation` [3](#0-2) . The repo's own unit test demonstrates the full exploit shape: after a wipeout, a fresh supplier's real deposit (`mint_supply` + `credit_cash`) is drained exactly by the stranded wiped position's withdrawal (`resolve_withdrawal(i128::MAX, old_scaled)` → `gross == fresh_cash`), leaving the fresh claim unbacked [4](#0-3) .

### Impact Explanation
Theft of user funds. Any holder of supply shares in the debt market at the moment of wipeout — including the attacker, who can supply dust before triggering cleanup — retains a phantom claim payable from the pool's real `cash`. Withdrawing it (`controller.withdraw` → `pool.withdraw` → `require_reserves` passes once new cash exists) transfers tokens belonging to later depositors or other survivors to the wiped position, and the fresh supplier's claim becomes unbacked — direct loss of principal.

### Likelihood Explanation
Medium. Triggering requires a bad-debt event large enough to exceed total supplied value in that market, which is the full-wipeout tail rather than common liquidations; creating it deliberately requires the attacker's own position to go deeply insolvent (oracle price movement or long interest accrual), which is not free. However, once any organic wipeout occurs, exploitation is a race among all wiped suppliers using only `withdraw`, and the protocol's own test confirms the drain is exact. Note `docs/reference/invariants.md` INV-IDX-02 acknowledges the lower bound "can preserve an unbacked residual claim" — the residual is documented, but the documented text does not state that it is redeemable against fresh deposits, which the test shows it is.

### Recommendation
On full write-down, burn the claim instead of clamping: when `remaining` (post-write-down supplied value) would be zero or below the floor-equivalent value, zero `supplied`/`revenue` share totals via a dedicated reset path and emit an event, rather than writing an index that resurrects them. Alternatively, gate `withdraw`/`claim_revenue` payout by `require_reserves` against *backed* value only — e.g., track a per-market write-down flag that disables share redemption once the index hits `SUPPLY_INDEX_FLOOR_RAW` due to capping (`capped == total_supplied_value`).

### Proof of Concept
1. Attacker supplies dust to debt-market X and opens a separate account that borrows X against collateral.
2. The borrower goes insolvent (price move or accrual) with residual collateral below the dust threshold, and the unpaid debt exceeds total supplied value of market X.
3. Attacker calls `clean_bad_debt(account_id)` (permissionless) → pool executes `apply_bad_debt_to_supply_index`; `capped` saturates at `total_supplied_value`, `remaining = 0`, index written as `SUPPLY_INDEX_FLOOR_RAW` instead of 0. Attacker's wiped supply shares retain `unscale_supply_floor(scaled) > 0`.
4. Any user supplies fresh tokens to market X (`supply`), crediting real `cash`.
5. Attacker calls `withdraw(0)` (whole position). `resolve_withdrawal` values the phantom shares at the floor index, `require_reserves` passes against the fresh cash, and the attacker receives the new depositor's tokens while the depositor's claim remains in `supplied` — pool insolvency.

pub(crate) fn process_clean_bad_debt(env: &Env, caller: &Address, account_id: u64) {
    caller.require_auth();
    validation::require_not_flash_loaning(env);
    clean_bad_debt_standalone(env, account_id);
}

/// Admission condition for bad-debt socialization.
#[derive(Clone, Copy, PartialEq)]
enum BadDebtGate {
    /// Permissionless: insolvent *and* collateral at or below the dust threshold.
    DustCapped,
    /// Owner-only: insolvent alone, with no cap on the collateral left behind.
    InsolventOnly,
}

/// Requires open debt and the selected insolvency gate, then cleans up the account.
fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    bad_debt::execute_bad_debt_cleanup(env, &mut cache, account_id, &account, &totals);
}

/// Socializes insolvent debt when remaining collateral is at or below the dust cap.
pub(crate) fn clean_bad_debt_standalone(env: &Env, account_id: u64) {
    socialize_bad_debt(env, account_id, BadDebtGate::DustCapped);
}
