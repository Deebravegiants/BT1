## Analysis

This CVE class — validating the "new" identity in a two-sided check while trusting an unauthenticated default for the "other side" — has a direct analog in the Tron variant of `IntentGatewayV2`.

### Title
Unregistered-source default trusts `address(this)` in `authenticate()`, allowing forged cross-chain escrow withdrawal — (File: `evm/tron/contracts/apps/IntentGatewayV2.sol`)

### Summary
`IntentGatewayV2.authenticate()` on Tron checks that the `from` field of an incoming `RedeemEscrow`/`RefundEscrow` PostRequest equals `instance(request.source)` [1](#0-0) . `instance()` silently falls back to `address(this)` whenever the source chain has never been registered via a `NewDeployment` message, instead of rejecting the request [2](#0-1) . This mirrors GCDWebServer's bug of validating one path (the destination check) while leaving the other (the origin) unchecked/implicitly trusted — here the "destination" identity (`module` parsed from attacker-controlled wire data) is checked, but the "source" side of the pairing is allowed to resolve to a hardcoded trusted value (`address(this)`) instead of requiring explicit registration.

### Finding Description
`instance()`:
```solidity
function instance(bytes calldata stateMachineId) public view returns (address) {
    address gateway = _instances[keccak256(stateMachineId)];
    return gateway == address(0) ? address(this) : gateway;
}
```
returns `address(this)` for any `stateMachineId` that has not been explicitly registered by a `NewDeployment` request [3](#0-2) .

`authenticate()` then accepts the incoming request if `request.from == instance(request.source)`:
```solidity
function authenticate(PostRequest calldata request) internal view {
    if (request.from.length != 20) revert InvalidInput();
    address module = address(bytes20(request.from));
    if (instance(request.source) != module) revert Unauthorized();
}
``` [4](#0-3) 

The IntentGatewayV2 proxy is deployed with a deterministic CREATE2 salt so that its address is identical across every chain by design, and this is documented as an intentional convention: "the address depends on (impl address, salt, params, peer chain ids, relayer), all identical across chains" [5](#0-4) . Because the salt and init-code are public, and Hyperbridge's ISMP consensus layer can support a state machine (chain) that the IntentGateway team has not yet deployed a legitimate gateway on, an attacker can deploy a malicious contract at that same deterministic CREATE2 address on any such not-yet-deployed chain, then dispatch (or otherwise get delivered) a PostRequest with `source = <that new chain>` and `from = abi.encodePacked(<that address>)`.

On arrival, `authenticate()` computes `instance(source)`, finds no explicit registration, defaults to `address(this)`, and this equals `module` — the check passes even though the "source" side was never actually vetted. `withdraw()` is then invoked and unconditionally transfers the escrowed input tokens (and accrued fees) to the attacker-chosen `beneficiary` [6](#0-5) .

Note that the hardened EVM version of `IntentGatewayV2` (`evm/src/apps/IntentGatewayV2.sol` / `IntentsBase`) does **not** have this defect: its `instance()` reverts with `UnknownInstance` for an unregistered chain rather than defaulting to `address(this)`, as confirmed by the test `testAddDeploymentOverridesDefault`-style assertion "An unregistered chain reverts with `UnknownInstance`" [7](#0-6) . This shows the Tron contract's `instance()`/`authenticate()` combination is a real regression relative to the hardened implementation, not an intentional design choice.

### Impact Explanation
Any escrow deposited on a Tron-deployed `IntentGatewayV2` instance can be stolen: a forged `RedeemEscrow`/`RefundEscrow` message from any unregistered "phantom" source chain, whose `from` field equals the gateway's own address, passes `authenticate()` and unlocks the escrowed input tokens and fee balance to an attacker-controlled beneficiary. This is concrete theft of user/solver escrowed funds, reachable by an unprivileged actor able to get a single relayed ISMP request delivered (a normal, permissionless path for any state machine Hyperbridge's consensus clients support).

### Likelihood Explanation
Exploitation requires only: (1) a Hyperbridge-supported state machine that has not yet had a `NewDeployment` registered for it on the target Tron gateway (a normal, expected pre-deployment state as new chains are onboarded), and (2) the attacker deploying a contract at the deterministic CREATE2 address on that chain and dispatching one message from it. Both the CREATE2 salt and the gateway bytecode are public in this repository, making the address trivially reproducible. No privileged role, governance action, or malicious insider is required — this is directly reachable by an unprivileged relayer/message path, matching the "message dispatcher/token bridger" reachability required.

### Recommendation
Change `instance()` to revert (e.g. `UnknownInstance`) when no explicit registration exists for `stateMachineId`, mirroring the hardened `evm/src/apps/IntentGatewayV2.sol` behavior, rather than silently defaulting to `address(this)`. This removes the implicit-trust fallback and requires every peer chain to be explicitly registered via `NewDeployment` before its messages can be authenticated.

### Proof of Concept
1. Identify a Hyperbridge-supported state machine `X` for which the Tron `IntentGatewayV2` instance has no `NewDeployment` entry in `_instances`.
2. Deploy a contract on chain `X` at the same CREATE2 address as the target gateway (using the public salt/bytecode), or otherwise arrange for a PostRequest to be dispatched with `source = X` and `from = abi.encodePacked(address(thisGatewayInstance))`.
3. Craft the request body as `bytes1(RequestKind.RedeemEscrow) || abi.encode(WithdrawalRequest({commitment: <victim's order commitment>, tokens: <victim's escrowed tokens>, beneficiary: <attacker>}))`.
4. Have this request relayed to the Tron gateway via the ISMP host; `onAccept` calls `authenticate(request)` [8](#0-7) , which succeeds because `instance(X)` defaults to `address(this)`.
5. `withdraw()` transfers the victim's escrowed tokens to the attacker's beneficiary address.
