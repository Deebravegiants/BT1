### Title
Stale `feeEstimation` bypasses `validateWithdrawal` allowing withdrawal of a token that is no longer supported/whitelisted on the destination chain - (File: `packages/intents-sdk/src/sdk.ts`)

### Summary
`validateWithdrawal` (which checks token whitelisting/support on the destination chain, e.g. `TokenNotFoundInDestinationChainError`, `UnsupportedAssetIdError`, `MinWithdrawalAmountError`) is only invoked inside `_estimateWithdrawalFee`. `signAndSendWithdrawalIntent`/`createWithdrawalIntents` never re-run this check — they just build intents from the caller-supplied `feeEstimation` object.

### Finding Description
`estimateWithdrawalFee` calls `bridge.supports(...)`, computes a fee, and then calls `bridge.validateWithdrawal({...})` before returning the `FeeEstimation`: [3](#0-2) 

That returned `feeEstimation` object is designed to be passed later, separately, into `signAndSendWithdrawalIntent`: [4](#0-3) 

Inside `signAndSendWithdrawalIntent`, the code only calls `createWithdrawalIntents` (per-bridge `createWithdrawalIntents`, e.g. in `omni-bridge.ts`/`poa-bridge.ts`), pulls `quote_hash` from the fee estimation, and signs+publishes — `validateWithdrawal` is never called again: [5](#0-4) 

Per-bridge `createWithdrawalIntents` implementations (e.g. Omni Bridge, PoA Bridge, HOT Bridge) build intent primitives directly from `feeEstimation`/`withdrawalParams` and do not re-check token support: [6](#0-5) [7](#0-6) 

This is structurally analogous to the Paladin `Warden-v2` bug: a value (`feeEstimation`, analogous to the "pledge") is computed once with a validity check (`validateWithdrawal`, analogous to `minAmountRewardToken[rewardToken] == 0` check), and then reused/passed forward to trigger an action (`signAndSendWithdrawalIntent`, analogous to "extend pledge") without re-validating that the underlying asset/token is still supported. If the caller holds on to a `feeEstimation` computed while a token was still supported by e.g. PoA/Omni bridge (`getCachedSupportedTokens`/`getCachedDestinationTokenAddress`, both TTL-cached), and the token is delisted afterward, `signAndSendWithdrawalIntent` will still happily build and publish the withdrawal intent for a token that is no longer supported on the destination chain, because the validation happened only at estimation-time, not at execution-time.

### Impact Explanation
If a bridge later delists/removes support for a token (e.g., it's no longer deployed/mapped on the destination chain, or removed from PoA's supported-tokens list) between the time a `feeEstimation` was produced and the time `signAndSendWithdrawalIntent` is called with that stale estimation, the SDK will still construct and sign a withdrawal intent for that asset. This can result in funds being burned/withdrawn on NEAR via `ft_withdraw`/`mt_withdraw` intents while the destination-side leg is impossible to complete (no destination token mapping) — i.e., funds effectively stuck/lost with no automatic recovery, matching the High-impact category "a withdrawal stuck until manual intervention."

### Likelihood Explanation
Likelihood depends on the integrator's usage pattern: estimating fees and then delaying calling `signAndSendWithdrawalIntent` (e.g., user confirmation flows, batch processing, or caching estimations) is a normal integration pattern explicitly supported by the SDK's two-step API (`estimateWithdrawalFee` → `signAndSendWithdrawalIntent`). The PoA cache TTL is only 30 seconds, but nothing in `signAndSendWithdrawalIntent` bounds how long a `feeEstimation` can be reused, so any delay beyond that window (network latency, UI confirmation step, retries) creates the window described above.

### Recommendation
Re-run `bridge.validateWithdrawal(...)` (or at minimum `bridge.supports(...)`) inside `signAndSendWithdrawalIntent`/`createWithdrawalIntents` immediately before constructing intents, rather than relying solely on validation performed during the earlier `estimateWithdrawalFee` call.

### Proof of Concept
1. Call `sdk.estimateWithdrawalFee({ withdrawalParams: { assetId: 'nep141:some-token.near', ... } })`. At this point the token is supported and `validateWithdrawal` passes, returning a `feeEstimation`.
2. The bridge operator delists the token (removed from PoA's `getSupportedTokens` response, or its Omni Bridge destination-chain mapping is removed).
3. Later (after the 30s PoA cache TTL expires, or on Omni Bridge whose cache similarly can be refreshed), call `sdk.signAndSendWithdrawalIntent({ withdrawalParams, feeEstimation })` using the stale `feeEstimation` from step 1.
4. `createWithdrawalIntents` is invoked directly without calling `validateWithdrawal` again, so the withdrawal intent is built and published even though the token is no longer supported/mapped on the destination chain — see `sdk.ts:689-743` and `omni-bridge.ts:283-330`.

	protected async _estimateWithdrawalFee(args: {
		withdrawalParams: WithdrawalParams;
		quoteOptions?: QuoteOptions;
		logger?: ILogger;
	}): Promise<FeeEstimation> {
		for (const bridge of this.bridges) {
			if (await bridge.supports(args.withdrawalParams)) {
				const fee = await bridge.estimateWithdrawalFee({
					withdrawalParams: args.withdrawalParams,
					quoteOptions: args.quoteOptions,
					logger: args.logger,
				});

				if (args.withdrawalParams.feeInclusive) {
					if (args.withdrawalParams.amount <= fee.amount) {
						throw new FeeExceedsAmountError(fee, args.withdrawalParams.amount);
					}
				}
				const actualAmount = args.withdrawalParams.feeInclusive
					? args.withdrawalParams.amount - fee.amount
					: args.withdrawalParams.amount;

				await bridge.validateWithdrawal({
					assetId: args.withdrawalParams.assetId,
					amount: actualAmount,
					destinationAddress: args.withdrawalParams.destinationAddress,
					feeEstimation: fee,
					routeConfig: args.withdrawalParams.routeConfig,
					logger: args.logger,
					destinationMemo: args.withdrawalParams.destinationMemo,
					// When estimating fees before the exact amount is known, skip minimum amount validation while keeping all other validation intact.
					skipMinAmountValidation:
						args.withdrawalParams.amount === 0n &&
						args.withdrawalParams.feeInclusive === false,
				});

				return fee;
			}
		}

		throw new Error(
			`Cannot determine bridge for withdrawal = ${stringify(
				args.withdrawalParams,
			)}`,
		);
	}

	public async signAndSendWithdrawalIntent(
		args:
			| SignAndSendWithdrawalArgs<WithdrawalParams>
			| SignAndSendWithdrawalArgs<WithdrawalParams[]>,
	): Promise<IntentPublishResult> {
		let withdrawalParamsArray: WithdrawalParams[];
		let feeEstimations: FeeEstimation[];
		if (isBatchMode(args)) {
			withdrawalParamsArray = args.withdrawalParams;
			feeEstimations = args.feeEstimation;
		} else {
			withdrawalParamsArray = [args.withdrawalParams];
			feeEstimations = [args.feeEstimation];
		}

		const intentsP = zip(withdrawalParamsArray, feeEstimations).map(
			([withdrawalParams, feeEstimation]) => {
				return this.createWithdrawalIntents({
					withdrawalParams,
					feeEstimation,
					referral: args.referral ?? this.referral,
					logger: args.logger,
				});
			},
		);

		const intents = (await Promise.all(intentsP)).flat();

		const relayParamsFn: IntentRelayParamsFactory = async () => {
			const relayParams =
				args.intent?.relayParams != null
					? await args.intent?.relayParams()
					: { quoteHashes: undefined };

			const quoteHashes = relayParams.quoteHashes ?? [];

			for (const fee of feeEstimations) {
				if (fee.quote != null) {
					quoteHashes.push(fee.quote.quote_hash);
				}
			}

			return { ...relayParams, quoteHashes };
		};

		return this.signAndSendIntent({
			intents,
			signer: args.intent?.signer,
			onBeforePublishIntent: args.intent?.onBeforePublishIntent,
			relayParams: relayParamsFn,
			payload: args.intent?.payload,
			logger: args.logger,
			signedIntents: args.intent?.signedIntents,
		});
	}

	async createWithdrawalIntents(args: {
		withdrawalParams: WithdrawalParams;
		feeEstimation: FeeEstimation;
		referral?: string;
	}): Promise<IntentPrimitive[]> {
		const assetInfo = this.makeAssetInfo(
			args.withdrawalParams.assetId,
			args.withdrawalParams.routeConfig,
		);
		assert(
			assetInfo !== null,
			`Asset ${args.withdrawalParams.assetId} is not supported by Omni Bridge`,
		);
		const omniChainKind = caip2ToChainKind(assetInfo.blockchain);
		assert(
			omniChainKind !== null,
			`Chain ${assetInfo.blockchain} is not supported by Omni Bridge`,
		);

		const intents: IntentPrimitive[] = [];

		if (args.feeEstimation.quote !== null) {
			intents.push({
				intent: "token_diff",
				diff: {
					[args.feeEstimation.quote.defuse_asset_identifier_in]:
						`-${args.feeEstimation.quote.amount_in}`,
					[args.feeEstimation.quote.defuse_asset_identifier_out]:
						args.feeEstimation.quote.amount_out,
				},
				referral: args.referral,
			});
		}
		intents.push(
			...createWithdrawIntentsPrimitive(
				deriveOmniWithdrawIntentParams({
					assetId: args.withdrawalParams.assetId,
					destinationAddress: args.withdrawalParams.destinationAddress,
					actualAmount: args.withdrawalParams.amount,
					omniChainKind,
					intentsContract: this.envConfig.contractID,
					feeEstimation: args.feeEstimation,
				}),
			),
		);

		return Promise.resolve(intents);
	}
