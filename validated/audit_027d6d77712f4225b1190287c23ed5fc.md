### Title
Missing shop domain validation in `Oauth.begin_auth` / `Oauth.validate_auth_callback` allows host-validation bypass - ([File: lib/shopify_api/auth/oauth.rb])

### Summary
`ShopifyAPI::Auth::Oauth.begin_auth` and `ShopifyAPI::Auth::Oauth.validate_auth_callback` build the host that receives the OAuth authorization request (and, on callback, the app's `client_id`/`client_secret`/authorization `code`) directly from an attacker-influenceable `shop` string, without ever calling `Utils::ShopValidator.sanitize!`. Every other OAuth entry point in this gem that turns a `shop` string into a request host (`RefreshToken.refresh_access_token`, `TokenExchange.migrate_to_expiring_token`) explicitly validates it first with `ShopValidator.sanitize!`. `Oauth` is the outlier.

### Finding Description
`auth_base_uri(shop)` builds the request host as `"https://#{shop}/admin"` straight from its `shop` argument: [1](#0-0) 

This helper is used in two places:

1. `begin_auth(shop:, redirect_path:, ...)` — `shop` is a plain, unvalidated `String` parameter documented simply as "A Shopify domain name in the form `{exampleshop}.myshopify.com}`" with no enforcement. It is used to build the merchant-facing redirect URL that carries the app's `client_id`, requested `scope`, and `redirect_uri`: [2](#0-1) 

2. `validate_auth_callback(cookies:, auth_query:)` — `auth_query.shop` is used, after HMAC validation, to build the host that receives the app's `client_secret` and authorization `code` via POST: [3](#0-2) 

The HMAC check (`Utils::HmacValidator.validate(auth_query)`) only proves the query bytes were signed by a holder of `api_secret_key` — it does not assert that `shop` is a well-formed `*.myshopify.com`/trusted domain: [4](#0-3) [5](#0-4) 

By contrast, the other two flows that also derive a request host from a caller-supplied `shop` string sanitize it first: [6](#0-5) [7](#0-6) 

This is the "host validated versus the host that receives the access token or `client_secret`" binding: `ShopValidator.sanitize!`/trusted-domain checks exist elsewhere in the gem specifically to guarantee `shop == trusted_myshopify_domain` before it is turned into a request host, but `Oauth.begin_auth`/`Oauth.validate_auth_callback` skip that guarantee.

### Impact Explanation
- `begin_auth`'s `shop` parameter is not protected by any signature and, in typical real-world integrations, is taken straight from an inbound `?shop=` query parameter (this is exactly how Shopify's own documented install flow supplies it) before any OAuth signature exists. Without domain validation, an attacker can trigger the app to redirect a victim's browser to an attacker-controlled host of the attacker's choosing (`https://ATTACKER_HOST/admin/oauth/authorize?client_id=...&scope=...&redirect_uri=...&state=...`), disclosing the app's `client_id`, requested `scope`, and `redirect_uri`, and enabling forced/faked OAuth completion or phishing flows targeting the merchant.
- `validate_auth_callback` additionally sends the far more sensitive `client_secret` to `auth_base_uri(auth_query.shop)`. Because `shop` there is part of the HMAC-signed query, exploiting this specific path requires an attacker who can produce a valid HMAC (i.e., possesses `api_secret_key`), which is out of scope per the rules — so this half of the finding is not independently exploitable by an unprivileged internet user, but it demonstrates the same missing invariant that `ShopValidator` is meant to enforce everywhere a `shop` value becomes a network destination.

### Likelihood Explanation
Moderate for `begin_auth`: exploitability depends entirely on how the host application sources the `shop` value it passes in (the gem's docs do not mandate calling `ShopValidator.sanitize!` before `begin_auth`, unlike its own internal practice in `RefreshToken`/`TokenExchange`). Any host app that forwards a request's `shop` query parameter directly to `begin_auth` — a very common integration pattern — is affected.

### Recommendation
Call `Utils::ShopValidator.sanitize!(shop)` (or `sanitize_shop_domain`) at the top of both `Oauth.begin_auth` and `Oauth.validate_auth_callback`, raising `Errors::InvalidShopError` for any `shop`/`auth_query.shop` that is not a trusted Shopify domain, before it is ever used to build `auth_base_uri`. This brings `Oauth` in line with the validation already performed in `RefreshToken.refresh_access_token` and `TokenExchange.migrate_to_expiring_token`.

### Proof of Concept
```ruby
# Host app naively forwards the "shop" query param, as commonly done per Shopify's documented install flow:
# GET /login?shop=attacker.example
ShopifyAPI::Auth::Oauth.begin_auth(shop: "attacker.example", redirect_path: "/auth/callback")
# => { auth_route: "https://attacker.example/admin/oauth/authorize?client_id=...&scope=...&redirect_uri=...&state=...",
#      cookie: <state cookie> }
# The victim's browser is redirected to an attacker-controlled host carrying the app's client_id, scope, and redirect_uri,
# with no domain validation performed by the gem (contrast with RefreshToken/TokenExchange, which call
# Utils::ShopValidator.sanitize!(shop) before building the request host).
```

        def begin_auth(shop:, redirect_path:, is_online: true, scope_override: nil)
          scope = if scope_override.nil?
            ShopifyAPI::Context.scope
          elsif scope_override.is_a?(ShopifyAPI::Auth::AuthScopes)
            scope_override
          else
            ShopifyAPI::Auth::AuthScopes.new(scope_override)
          end

          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = SecureRandom.alphanumeric(NONCE_LENGTH)

          cookie = SessionCookie.new(value: state, expires: Time.now + 60)

          query = {
            client_id: ShopifyAPI::Context.api_key,
            scope: scope.to_s,
            redirect_uri: "#{ShopifyAPI::Context.host}#{redirect_path}",
            state: state,
            "grant_options[]": is_online ? "per-user" : "",
          }

          query_string = URI.encode_www_form(query)
          auth_route = auth_base_uri(shop) + "/oauth/authorize?#{query_string}"

          { auth_route: auth_route, cookie: cookie }
        end

        def validate_auth_callback(cookies:, auth_query:)
          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::InvalidOauthError, "Invalid OAuth callback." unless Utils::HmacValidator.validate(auth_query)
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = cookies[SessionCookie::SESSION_COOKIE_NAME]
          raise Errors::NoSessionCookieError unless state

          raise Errors::InvalidOauthError,
            "Invalid state in OAuth callback." unless state == auth_query.state

          null_session = Auth::Session.new(shop: auth_query.shop)
          body = {
            client_id: Context.api_key,
            client_secret: Context.api_secret_key,
            code: auth_query.code,
            expiring: Context.expiring_offline_access_tokens ? 1 : 0, # Only applicable for offline tokens
          }

          client = Clients::HttpClient.new(session: null_session, base_path: "/admin/oauth")
          response = begin
            client.request(
              Clients::HttpRequest.new(
                http_method: :post,
                path: "access_token",
                body: body,
                body_type: "application/json",
              ),
            )
          rescue ShopifyAPI::Errors::HttpResponseError => e
            raise Errors::RequestAccessTokenError,
              "Cannot complete OAuth process. Received a #{e.code} error while requesting access token."
          end

          session_params = T.cast(response.body, T::Hash[String, T.untyped]).to_h
          session = Session.from(shop: auth_query.shop,
            access_token_response: Oauth::AccessTokenResponse.from_hash(session_params))

        sig { params(shop: String).returns(String) }
        def auth_base_uri(shop)
          return "https://#{shop}/admin" unless defined?(DevServer) && shop.include?(".my.shop.dev")

          # For first-party apps in development only, we leverage DevServer to build the admin base URI
          admin_web = T.unsafe(Object.const_get("DevServer")) # rubocop:disable Sorbet/ConstantsFromStrings
            .new("admin-web")
          admin_host = admin_web.host!(nonstandard_host_prefix: "admin")
          shop_name = shop.split(".").first

          "https://#{admin_host}/store/#{shop_name}"
        end
