### Title
Missing Chainlink `minPrice`/`maxPrice` (circuit-breaker) validation lets stale extreme oracle answers mis-price gas payments and swaps - ([File: evm/src/utils/SimplexPaymaster.sol])

### Summary
`SimplexPaymaster` prices ERC-20 gas payments and its fee-recycling swaps purely from Chainlink `latestRoundData()`, checking only that the answer is positive and not stale [1](#0-0) . It never checks whether the returned `answer` sits at the aggregator's configured `minAnswer`/`maxAnswer` bounds, so during a sharp price crash or spike the feed can silently report a clamped value instead of reverting or signaling the true price, exactly like the Ubiquity `LibUbiquityPool` finding this report is based on.

### Finding Description
`_getOraclePrice` is the sole price source used to compute `tokenPrice` for every UserOperation charged through this paymaster, via `_tokenPrice` → `_fetchDetails` [2](#0-1) [3](#0-2) , and also for the minimum-output computation in `swapAndDeposit` [4](#0-3) . The minimal `AggregatorV3Interface` used only exposes `latestRoundData` and `decimals` [5](#0-4) , and `_getOraclePrice` validates only `answer <= 0` and staleness against `maxOracleAge`:

```solidity
function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
    (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();
    if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
    if (block.timestamp - updatedAt > maxOracleAge) {
        revert StaleOraclePrice(address(oracle), updatedAt);
    }
    ...
}
``` [6](#0-5) 

Chainlink aggregators enforce a `minAnswer`/`maxAnswer` band internally; when the real market price moves outside that band the aggregator keeps reporting the clamped boundary value with a fresh `updatedAt`, so neither the `answer <= 0` check nor the staleness check catches it. There is no comparison of the returned answer against the aggregator's min/max bounds anywhere in the contract.

### Impact Explanation
Any unprivileged party that submits a `PackedUserOperation` through this paymaster (mode `0x00` permit or `0x02` Permit2) is charged `tokenPrice` derived from this unchecked oracle read [7](#0-6) . If either the native/USD or token/USD feed clamps during a crash or spike:
- Solvers/users can be systematically over- or under-charged in the stablecoin relative to the true gas cost.
- `swapAndDeposit`'s `amountOutMin` is derived from the same clamped price [4](#0-3) , so accumulated stablecoin surplus can be swapped for native asset at a materially wrong (attacker-favorable, since slippage bound moves with the false price) rate, permanently misallocating treasury funds.

This directly threatens fund safety of the paymaster's treasury/deposit and of solver accounts routed through it, matching the theft/fund-misallocation bar for a Medium-severity oracle issue.

### Likelihood Explanation
This does not require any privileged action or compromised key — it triggers purely from external market conditions (a genuine sharp price move on the underlying token or native asset) combined with normal, permissionless usage of the paymaster (any bundler-submitted UserOperation, or a treasury-triggered `swapAndDeposit`). Stablecoin depegs and native-asset volatility are realistic events, and Chainlink's documented `minAnswer`/`maxAnswer` circuit breakers have triggered in production before (e.g., LUNA/UST collapse), so likelihood is non-negligible.

### Recommendation
Extend the oracle interface to also expose or read the aggregator's configured bounds (e.g., via `AggregatorV2V3Interface`'s underlying `Aggregator` contract `minAnswer()`/`maxAnswer()`, or by hard-coding conservative sanity bounds per feed in `TokenConfig`), and revert `_getOraclePrice` when `answer <= minPrice` or `answer >= maxPrice`, in addition to the existing positivity and staleness checks.

### Proof of Concept
1. Governance registers a token whose feed is a standard Chainlink aggregator with `minAnswer = X`.
2. The underlying asset's real market price crashes below `X` (e.g., a stablecoin depeg).
3. The aggregator continues returning `answer = X` with a fresh `updatedAt` (no staleness triggered).
4. `_getOraclePrice` returns `X` as if it were the true price; `_tokenPrice` and `_fetchDetails` compute `tokenPrice` off this stale-in-value-but-fresh-in-timestamp clamp.
5. A solver's UserOperation is charged based on the clamped price rather than the true crashed price, diverging materially from the intended `weiCost`-equivalent charge; alternatively, treasury calls `swapAndDeposit`, and `amountOutMin` is computed off the same clamped value, permitting a swap at a rate far from the genuine market rate.

    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
