**Analysis:**

`object::create_object_address` derives addresses as `sha3_256(bcs(creator) || seed || 0xFE)` [1](#0-0) , matching the Rust-side derivation in `types/src/account_address.rs::create_object_address` [2](#0-1) .

In `FACoin.move`, both `get_metadata()` and `assert_not_paused()` call `object::create_object_address(&@FACoin, ASSET_SYMBOL)` [3](#0-2) [4](#0-3) , where `@FACoin` is the fixed module deployment address and `ASSET_SYMBOL = b"FA"` is a compile-time constant [5](#0-4) . Neither the creator address nor the seed in this derivation is attacker-supplied at call time — both are hardcoded into the module bytecode by the deployer. There is no unprivileged transaction input flowing into these specific `create_object_address` calls at all, so the premise of "attacker-controlled ASSET_SYMBOL-equivalent seed bytes" does not apply to this code path.

Even setting that aside, for two distinct `(creator, seed)` pairs to collide at the same derived address would require finding a SHA3-256 preimage/second-preimage collision (256-bit output, 128-bit collision resistance), which is computationally infeasible and not a practical attack vector on mainnet. The `create_object_address` function itself performs no validation and simply computes a deterministic hash [6](#0-5) ; there is no code path where an unprivileged caller can force an arbitrary derived address to equal a specific pre-existing `State` resource address belonging to a different module without breaking SHA3-256.

Since no unprivileged input actually reaches the address-derivation preimage in the cited `FACoin.move` flows, and exploiting the derivation itself requires breaking a cryptographic hash function, this does not cross a real custody boundary per the review's decision standard.

pub fn create_object_address(creator: AccountAddress, seed: &[u8]) -> AccountAddress {
    let mut input = bcs::to_bytes(&creator).unwrap();
    input.extend(seed);
    input.push(Scheme::DeriveObjectAddressFromSeed as u8);
    let hash = HashValue::sha3_256_of(&input);
    AccountAddress::from_bytes(hash.as_ref()).unwrap()
}
