### Title
Unprivileged users can execute unscheduled governance self-operations and take over the protocol - ([File: contracts/governance/src/timelock/lifecycle.rs](contracts/governance/src/timelock/lifecycle.rs))

### Summary
`Governance::execute_self` resolves and applies an arbitrary `AdminOperation` without requiring that its operation hash was ever scheduled or reached its ready ledger. An attacker can execute `TransferGovOwnership` to themself, accept ownership, and then execute administrative self-operations such as replacing the controller's price aggregator.

### Finding Description
`execute_self` accepts `executor: Option<Address>` and forwards the caller-supplied `AdminOperation` directly to `lifecycle::execute_self`. Passing `None` performs no authorization or executor-role check. [1](#0-0) [2](#0-1) 

`lifecycle::execute_self` resolves the operation, invokes `prepare_execute`, marks it as executing, and immediately applies it. [3](#0-2) 

`prepare_execute` only authorizes an optional executor, hashes the supplied operation, and calls `require_operation_not_expired`; it does not check that the operation exists or that its scheduled ready ledger has arrived. [4](#0-3) 

For an unscheduled operation, `get_operation_ledger` returns a ready ledger of `0`, so `require_operation_not_expired` returns without rejecting it. [5](#0-4) 

`apply_self_op` then directly applies sensitive governance operations including `UpgradeGov`, `UpdateGovDelay`, `GrantGovRole`, `RevokeGovRole`, `TransferGovOwnership`, and `SetPriceAggregator`. [6](#0-5) 

### Impact Explanation
An attacker can submit an unscheduled `AdminOperation::TransferGovOwnership` naming themself as `new_owner`. `apply_transfer_ownership` records the attacker as pending owner. [7](#0-6) 

The attacker can then call `accept_ownership`; `ownable::accept_ownership` requires the pending owner's authorization, and `sync_owner_access_control` makes the attacker the access-control admin and grants every operational role to the attacker while revoking them from the prior owner. [8](#0-7) [9](#0-8) 

The same bypass can execute `SetPriceAggregator`, which stores a replacement aggregator and invokes the controller's owner-only `set_price_aggregator` endpoint. [10](#0-9) [11](#0-10) 

Replacing the price source can enable inflated collateral valuations and undercollateralized borrowing, allowing theft of user funds and protocol insolvency. The role takeover is a direct analog of the reported arbitrary privilege-escalation class.

### Likelihood Explanation
Any unprivileged address can call `execute_self` with `executor = None` because `authorize_executor` intentionally performs no authentication in that case. [2](#0-1) 

The attack requires no proposal, delay, proposal role, executor role, owner signature, cancellation avoidance, or account balance. For `TransferGovOwnership`, `resolve_op` only maps the caller-supplied fields to a self-operation; the owner-only proposer restriction in `propose` is not reached by the direct execution path. [12](#0-11) [13](#0-12) 

### Recommendation
Before marking the operation as executing, require `OperationState::Ready` for the hash produced from the supplied `AdminOperation` and salt. Apply the same readiness validation in `execute_self` and `execute_canceller_reset`, not only in the external `execute_operation` path.

Reject ready ledgers of `0` and `1` distinctly from valid ready operations, and add regression tests proving that `execute_self(None, TransferGovOwnership(...), arbitrary_salt)` fails when the operation was never proposed and before its sensitive delay has elapsed.

### Proof of Concept
```rust
let attacker = Address::generate(&env);
let salt = BytesN::<32>::from_array(&env, &[0xAA; 32]);

let takeover = AdminOperation::TransferGovOwnership(TransferOwnershipArgs {
    new_owner: attacker.clone(),
    live_until_ledger: env.ledger().sequence() + 1_000,
});

// No proposal or delay is required by the vulnerable path.
gov.execute_self(&None, &takeover, &salt);

// Authenticated as the pending owner, the attacker completes the transfer.
gov.accept_ownership();
```

`TransferGovOwnership` resolves to the governance contract's `transfer_ownership` function and uses the `Sensitive` delay tier when properly scheduled. [12](#0-11)  The direct execution path instead hashes the operation and applies it after only the expiry helper, so the arbitrary salt need not correspond to an existing scheduled operation. [3](#0-2) [4](#0-3) 

After takeover, the attacker has the access-control admin and all operational roles synchronized to the new owner. [9](#0-8)  The attacker can also directly execute an unscheduled `SetPriceAggregator(malicious_aggregator)` operation to redirect controller pricing before borrowing against manipulated collateral prices. [10](#0-9)
