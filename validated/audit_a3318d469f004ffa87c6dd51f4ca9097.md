The code exactly matches the claim, and there's no auth wrapper or config gate on `loopRoutes`. This is functionally the same design intent as `/discovery` and Prometheus metrics endpoints, which are commonly designed as unauthenticated scrape targets in monitoring systems (similar to `/metrics` conventions in many Prometheus-instrumented services), but the pprof endpoints going out unauthenticated is a legitimate concern since they can leak sensitive process data and enable resource exhaustion.

Audit Report

## Title
Unauthenticated exposure of internal LOOP plugin metrics and pprof/debug endpoints - (File: core/web/router.go)

## Summary
`loopRoutes`, registered in `NewRouter`, exposes `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` on the `api` group which only carries rate-limiting and session-cookie middleware, with no `auth.Authenticate(...)` wrapper, unlike `debugRoutes`, `sessionRoutes`, and `v2Routes` which explicitly require session or token authentication. [1](#0-0) [2](#0-1) 

## Finding Description
`NewRouter` builds the `api` route group protected only by a rate limiter and a cookie-session middleware (which does not itself enforce a valid/authenticated session), then registers `loopRoutes(app, api)` directly onto it. [1](#0-0)  By contrast, `debugRoutes` wraps `/debug/vars` with `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)`, `sessionRoutes` requires session auth for state-changing calls, and `v2Routes`/`authv2` requires token or session auth plus role checks for sensitive admin actions. [3](#0-2) [4](#0-3)  The `loopRoutes` handlers (`discoveryHandler`, `pluginMetricHandler`, `pluginPPROFHandler`, `pluginPPROFPOSTSymbolHandler`) perform no authentication or session/token checks themselves — they only verify the plugin name exists in the registry before proxying the request to the internal LOOP process's `/metrics` or `/debug/pprof/*` endpoints. [5](#0-4) [6](#0-5)  This is confirmed as-is in the current code with no config flag gating `loopRoutes` behind a separate internal-only listener.

## Impact Explanation
Any unauthenticated client that can reach the node's HTTP listener can enumerate registered LOOP plugins via `/discovery`, retrieve Prometheus metrics for a named plugin via `/plugins/:name/metrics`, and pull full Go `pprof` profiles (heap, goroutine, execution traces) via `/plugins/:name/debug/pprof/*profile` without any credentials. Note that `/metrics` and `/discovery` style Prometheus scrape endpoints are conventionally unauthenticated by design in many monitoring architectures (mirroring the standalone `metricRoutes` pprof group defined elsewhere in the same file, which is also unauthenticated when used), so the sensitivity of this depends on deployment network topology; however, exposing full `pprof` profiling data (which can include stack traces, memory contents, and function addresses of the internal plugin process) on the node's primary externally-reachable API surface without any auth is a legitimate information-disclosure and reconnaissance concern, and repeated CPU-profile/trace requests are also a resource-consumption vector against the plugin process.

## Likelihood Explanation
The routes are registered unconditionally within `NewRouter`, which builds the node's primary HTTP listener; there is no authentication middleware or role check applied to `loopRoutes`, so any network client that can reach the configured web server port can trigger this without credentials — high likelihood wherever the node's API port is reachable to untrusted clients.

## Recommendation
Wrap the `loopRoutes` handlers with the same `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)` pattern used by `debugRoutes`, or move plugin metrics/pprof endpoints to a separate internal-only listener/bind address not exposed on the primary API port, consistent with how `debug/pprof` is otherwise guarded in similar Go services.

## Proof of Concept
1. Start a chainlink node with at least one LOOP plugin registered (`app.GetLoopRegistry()` populated).
2. Without any session cookie or API token, issue `curl http://<node-host>:<port>/discovery` — returns the list of registered plugins and their metrics paths per `discoveryHandler`.
3. `curl http://<node-host>:<port>/plugins/<plugin-name>/metrics` — returns raw Prometheus metrics per `pluginMetricHandler`.
4. `curl http://<node-host>:<port>/plugins/<plugin-name>/debug/pprof/heap` — returns a full heap profile of the internal plugin process via `pluginPPROFHandler`, all without authentication, confirming the missing `auth.Authenticate` wrapper present on sibling route groups (`debugRoutes`, `v2Routes`).

func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/metrics", l.loopHostName, p.EnvCfg.PrometheusPort)
	req, err := http.NewRequestWithContext(gc.Request.Context(), http.MethodGet, pluginURL, nil)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)
	if err != nil {
		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q metrics", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}

func (l *LoopRegistryServer) pluginPPROFPOSTSymbolHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/symbol", l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	body, err := io.ReadAll(gc.Request.Body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error reading plugin pprof request body: %s", err))
		return
	}
	l.doRequest(gc, "POST", pluginURL, bytes.NewReader(body), timeout, pluginName)
}
