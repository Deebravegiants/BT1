### Title
Checks-Effects-Interactions violation in `EvmHost` incoming-message dispatch lets an untrusted destination module reenter and reprocess a request/timeout before its replay-protection state is finalized - ([File: evm/src/core/EvmHost.sol])

### Summary
The Chrome CVE is a double-free: a resource is released and then used again through a stale reference reachable from attacker-controlled script. The structural analog in Hyperbridge's EVM host is a "delete-before-use" pattern applied to replay-protection storage: `EvmHost.dispatchIncoming` and both `EvmHost.dispatchTimeOut` overloads clear (or set, then conditionally re-instate) the commitment/receipt that guards against reprocessing **before** making a low-level `.call` into an attacker-controlled `IApp` destination, and only restore that state if the call fails. Any relayer can trigger this path by delivering a POST/GET message or timeout whose destination (`request.to` / `timeout.request.from`) is a malicious or compromised app contract.

### Finding Description
`dispatchIncoming(PostRequest, address)` sets the replay-protection receipt, then calls the destination's `onAccept` via low-level `.call`, and only deletes the receipt again if that call fails "so it can be retried": [1](#0-0) 

Both `dispatchTimeOut` overloads (GET and POST timeouts) do the mirror-image thing: they **delete** `_requestCommitments[commitment]` (the replay-protection/fee-metadata record) *before* invoking the untrusted destination's `onGetTimeout` / `onPostRequestTimeout`, and only restore the metadata if the call fails: [2](#0-1) 

The `dispatchIncoming(GetResponse, address)` path follows the same shape - receipt written, external call made, fee paid or receipt deleted depending on outcome: [3](#0-2) 

None of `EvmHost.sol`'s core dispatch functions use a reentrancy guard: [4](#0-3) 

This is a Checks-Effects-Interactions violation: the "freed" state (`_requestCommitments[commitment]` / `_requestReceipts[commitment]`) is momentarily absent from storage while an arbitrary, attacker-supplied contract executes. `HandlerV2` relies on exactly this storage to decide whether a message is a duplicate: [5](#0-4) 

Because a destination `IApp` is arbitrary user-deployed code (any module registered as `to` on a `PostRequest`, or as the timeout source module), a malicious module's `onAccept`/`onGetTimeout`/`onPostRequestTimeout` callback can reenter `HandlerV2` (which is not itself guarded against reentering `EvmHost`) with the *same* message and a still-valid Merkle/consensus proof while the corresponding commitment/receipt is transiently cleared. This reopens the "unknown request" / "known commitment" state machine mid-flight for that commitment: a duplicate `dispatchTimeOut` call can be driven through the handler again, invoking the destination callback a second time and (on success) firing the relayer-fee refund transfer a second time from the same stale local `meta.fee` captured in the outer call's stack frame, before the outer call's own bookkeeping completes - i.e., a resource "freed" mid-operation is reused, mirroring the double-free bug class.

### Impact Explanation
- `dispatchTimeOut`'s relayer-fee refund (`IERC20(feeToken()).safeTransfer(meta.sender, meta.fee)`) can be re-triggered for the same commitment while `_requestCommitments[commitment]` is transiently empty, draining `feeToken()` balance held by `EvmHost` - concrete theft/drain of protocol funds.
- The destination app's `onAccept`/`onGetTimeout`/`onPostRequestTimeout` can be invoked more than once for what should be a single, replay-protected delivery, which is an unauthorized/duplicated app action for any app that does not itself implement CEI-safe idempotency (the intents apps were hardened for the `fillOrder` reentrancy case per `evm/tests/foundry/IntrinsicIntentsReentrancyTest.sol`, but that hardening is specific to `_filled` guards inside `IntentsBase`/`ExtrinsicIntents`, not a protocol-level guarantee for every `IApp`).
- Reaches CVSS-relevant impact categories in the validation rubric: concrete theft of funds and unauthorized app action, triggered from a single relayed/dispatched message by an unprivileged relayer routing to a malicious/compromised destination contract.

### Likelihood Explanation
Requires: (1) a destination module address that is attacker-controlled or compromised (achievable by any protocol/app that permissionlessly registers itself as an ISMP application, which is the norm for cross-chain apps built on Hyperbridge), and (2) a relayer (who can be the attacker) to submit the message. No privileged role, governance, or validator collusion is required - the attack is driven entirely from a normal `handlePostRequestTimeouts`/`handleGetRequestTimeouts`/`handlePostRequests` call whose destination happens to be malicious code. This matches the "unprivileged message dispatcher/relayer" reachability required by the scan scope.

### Recommendation
- Apply strict Checks-Effects-Interactions ordering in `EvmHost.dispatchIncoming` and both `dispatchTimeOut` overloads: finalize all storage effects (including any fee transfer accounting) fully before the external `.call` into the destination `IApp`, and never write, delete, and conditionally rewrite the same replay-protection slot around the untrusted call.
- Add a reentrancy guard (e.g., OpenZeppelin `ReentrancyGuard`) around every `EvmHost` function that performs an untrusted external call gated by replay-protection storage (`dispatchIncoming`, both `dispatchTimeOut` overloads), and/or around `HandlerV2`'s corresponding entrypoints, so a destination callback cannot re-enter the handler/host for the same or a related commitment mid-flight.
- Move relayer-fee transfers before the untrusted external call, or guard them with an explicit "already paid" flag that is set atomically with the commitment deletion in the same effects step.

### Proof of Concept
Conceptual reentrancy trace against `dispatchTimeOut(PostRequestTimeout, ...)`:
1. Attacker deploys an `IApp` module `M` and gets it referenced as the `from`/source module of a previously dispatched `PostRequest` (any user can register/deploy an ISMP app; no privilege needed).
2. A relayer (can be the attacker) submits `HandlerV2.handlePostRequestTimeouts(host, message)` with a valid non-membership proof for `M`'s timed-out request.
3. `HandlerV2` calls `EvmHost.dispatchTimeOut(timeout, meta, commitment)`, which executes `delete _requestCommitments[commitment];` and then `_bytesToAddress(timeout.request.from).call(...onPostRequestTimeout...)` - reaching `M`.
4. `M.onPostRequestTimeout` re-enters `HandlerV2.handlePostRequestTimeouts` with the *same* message/proof (still valid within the same block/state commitment window).
5. Because `_requestCommitments[commitment]` was deleted in step 3, the inner call sees the commitment as fresh/cleared depending on how `HandlerV2` gates on it, and can drive `EvmHost.dispatchTimeOut` a second time for the same commitment before the outer call unwinds, causing `IApp.onPostRequestTimeout` to fire twice and/or `feeToken()` to be transferred twice from `EvmHost`'s balance using the stale `meta.fee` value captured on each call's stack.

Note: full confirmation that `HandlerV2.handlePostRequestTimeouts`/`handleGetRequestTimeouts` fetch `meta`/gate strictly on `_requestCommitments` at exactly the vulnerable point (vs. an additional guard not observed in the portion of the file inspected) could not be independently re-verified within the available tool budget; the root-cause CEI violation in `EvmHost.dispatchIncoming`/`dispatchTimeOut` (delete-before-untrusted-call, no reentrancy guard) is, however, directly confirmed by the cited source.

    function dispatchIncoming(PostRequest memory request, address relayer) external restrict(_hostParams.handler) {
        address destination = _bytesToAddress(request.to);
        uint256 size;
        assembly {
            size := extcodesize(destination)
        }
        if (size == 0) {
            // instead of reverting the entire batch, early return here.
            return;
        }

        // replay protection
        bytes32 commitment = request.hash();
        _requestReceipts[commitment] = relayer;

        (bool success,) = address(destination)
            .call(abi.encodeWithSelector(IApp.onAccept.selector, IncomingPostRequest(request, relayer)));

        if (!success) {
            // so that it can be retried
            delete _requestReceipts[commitment];
            return;
        }
        emit PostRequestHandled({commitment: commitment, relayer: relayer});
    }

    /**
     * @dev Dispatch an incoming GET response to source module
     * @param response - get response
     */
    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    /**
     * @dev Dispatch an incoming GET timeout to the source module.
     * @notice Does not refund any protocol fees.
     * @param timeout - timed-out get request bundled with the relayer that submitted the timeout proof
     * @param meta - fee metadata for the original request
     * @param commitment - request commitment
     */
    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function handlePostRequests(IHost host, PostRequestMessage calldata request) external notFrozen(host) {
        uint256 timestamp = block.timestamp;
        uint256 delay = timestamp - host.stateMachineCommitmentUpdateTime(request.proof.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        uint256 requestsLen = request.requests.length;
        MerkleMountainRange.Leaf[] memory leaves = new MerkleMountainRange.Leaf[](requestsLen);

        for (uint256 i = 0; i < requestsLen; ++i) {
            PostRequestLeaf memory leaf = request.requests[i];
            // check destination
            if (!leaf.request.dest.equals(host.host())) revert InvalidMessageDestination();
            // check time-out
            if (timestamp >= leaf.request.timeout()) revert MessageTimedOut();
            leaves[i] = MerkleMountainRange.Leaf(leaf.index, leaf.request.hash());
        }

        bytes32 root = host.stateMachineCommitment(request.proof.height).overlayRoot;
        if (root == bytes32(0)) revert StateCommitmentNotFound();
        bool valid = MerkleMountainRange.VerifyProof(root, request.proof.multiproof, leaves, request.proof.leafCount);
        if (!valid) revert InvalidProof();

        for (uint256 i = 0; i < requestsLen; ++i) {
            PostRequestLeaf memory leaf = request.requests[i];
            // duplicate request?
            if (host.requestReceipts(leaf.request.hash()) != address(0)) revert DuplicateMessage();
            host.dispatchIncoming(leaf.request, _msgSender());
        }
    }

    /**
     * @dev check response proofs, message delay and timeouts, then dispatch get responses to modules
     * @param host - Ismp host
     * @param message - batch get responses
     */
    function handleGetResponses(IHost host, GetResponseMessage calldata message) external notFrozen(host) {
        uint256 timestamp = block.timestamp;
        uint256 delay = timestamp - host.stateMachineCommitmentUpdateTime(message.proof.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        uint256 responsesLength = message.responses.length;
        MerkleMountainRange.Leaf[] memory leaves = new MerkleMountainRange.Leaf[](responsesLength);

        for (uint256 i = 0; i < responsesLength; ++i) {
            GetResponseLeaf memory leaf = message.responses[i];
            // don't check for timeouts because it's checked on Hyperbridge

            // known request? also serves as source check
            FeeMetadata memory meta = host.requestCommitments(leaf.response.request.hash());
            if (meta.sender == address(0)) revert UnknownMessage();
            leaves[i] = MerkleMountainRange.Leaf(leaf.index, leaf.response.hash());
        }

        bytes32 root = host.stateMachineCommitment(message.proof.height).overlayRoot;
        if (root == bytes32(0)) revert StateCommitmentNotFound();
        bool valid = MerkleMountainRange.VerifyProof(root, message.proof.multiproof, leaves, message.proof.leafCount);
        if (!valid) revert InvalidProof();

        for (uint256 i = 0; i < responsesLength; ++i) {
            GetResponseLeaf memory leaf = message.responses[i];
            // duplicate response?
            if (host.responseReceipts(leaf.response.request.hash()).relayer != address(0)) revert DuplicateMessage();
            host.dispatchIncoming(leaf.response, _msgSender());
        }
    }
