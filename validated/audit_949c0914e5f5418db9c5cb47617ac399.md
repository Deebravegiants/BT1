### Title
`EvmHost.dispatchIncoming(GetResponse)` and `dispatchTimeOut` skip the extcodesize check that guards `dispatchIncoming(PostRequest)`, letting a no-code target silently "consume" delivery - (File: evm/src/core/EvmHost.sol)

### Summary
`EvmHost.dispatchIncoming(PostRequest, ...)` explicitly checks `extcodesize(destination) == 0` and early-returns *before* touching replay-protection state or making the low-level `.call`, precisely because a `.call`/`.delegatecall` to an address with no code returns `success == true` without executing any logic [1](#0-0) . The sibling functions `dispatchIncoming(GetResponse, ...)`, `dispatchTimeOut(GetRequestTimeout, ...)`, and `dispatchTimeOut(PostRequestTimeout, ...)` make the same kind of low-level `.call()` to an application address but omit this check entirely [2](#0-1) .

### Finding Description
In `dispatchIncoming(GetResponse memory response, address relayer)`, the replay-protection receipt is written *before* the call, and the call target is `_bytesToAddress(response.request.from)`, which is just whatever `msg.sender` was recorded when the original GET request was dispatched via `dispatch(DispatchGet)` — a public, permissionless function with no restriction that the caller be a persistent, non-destructible contract [3](#0-2) . If that address has no code at delivery time (e.g., an EIP-7702-delegated account such as `SolverAccount` whose delegation has been revoked, a counterfactual/CREATE2 account not yet deployed, or a self-destructed contract), the low-level `.call()` per the Solidity documentation returns `success == true` even though `onGetResponse` never executes. Because `success` is `true`, the code proceeds to keep the response receipt (no rollback), pay the relayer fee via `IERC20(feeToken()).safeTransfer(relayer, fee)`, and emit `GetRequestHandled` as if delivery succeeded [4](#0-3) . The exact same pattern (no codesize check, receipt/fee handling gated only on the low-level `success` boolean) is repeated in both `dispatchTimeOut` overloads [5](#0-4) .

This is the exact bug class from the external report: a low-level call/delegatecall silently reports success against a non-existent (no-code) account, and the caller trusts that boolean to gate irreversible state changes and fund transfers, instead of checking account existence first as the Solidity docs warn.

### Impact Explanation
Once `dispatchIncoming(GetResponse)` runs against a no-code `from`, the response commitment's receipt is permanently retained (never deleted, since the `!success` branch — which deletes it for retry — is never taken), so the message can never be redelivered even if code is later placed at that address (e.g., a fresh CREATE2 deployment or a new EIP-7702 delegation). Any application whose state transition is gated on `onGetResponse` actually executing (e.g., escrow release logic such as `ExtrinsicIntents.onGetResponse` at [6](#0-5) ) would have those funds permanently stuck, because the one message that could unlock them is marked as already delivered. Simultaneously, the relayer is paid the escrowed fee for a delivery that performed no real work — a fee-token drain that benefits the relayer at the expense of the fee payer. The same freezing/false-completion risk applies to `dispatchTimeOut` for GET and POST timeouts, where a no-code `from` causes `_requestCommitments[commitment]` to be deleted and, if a fee exists, refunded, marking the timeout as processed even though no destination logic ran.

### Likelihood Explanation
Medium. Reaching this path requires no privileged role: any account (EOA, or an EIP-7702-delegated `SolverAccount`, or a counterfactual/CREATE2 wallet) can call the permissionless `dispatch(DispatchGet)` on `EvmHost` and later have its designator/delegation revoked or its contract not yet deployed by the time a relayer submits the response/timeout proof. `EvmHost` clearly guards this exact scenario for `dispatchIncoming(PostRequest)` but not for the GET-response and timeout variants, which is an inconsistency in the same file rather than a hypothetical.

### Recommendation
Add the same `extcodesize(destination) == 0` check (mirroring `dispatchIncoming(PostRequest)`) to `dispatchIncoming(GetResponse)`, `dispatchTimeOut(GetRequestTimeout)`, and `dispatchTimeOut(PostRequestTimeout)` before writing/deleting receipts or transferring fees, so a no-code target causes an early return that preserves retryability instead of being silently treated as a successful, fee-paying delivery.

### Proof of Concept
1. An EIP-7702-delegated `SolverAccount` (or any counterfactual CREATE2 account) calls `EvmHost.dispatch(DispatchGet)`, paying `fee` in the fee token; `request.from = abi.encodePacked(msg.sender)` is recorded [7](#0-6) .
2. Before the response returns, the delegation is revoked (a standard EIP-7702 operation the EOA can perform at any time) or the CREATE2 account is never deployed, so `from` now has `extcodesize == 0`.
3. A relayer submits a valid proof for the `GetResponse`; `HandlerV2` verifies it and calls `EvmHost.dispatchIncoming(GetResponse, relayer)`.
4. Inside `dispatchIncoming`, `_bytesToAddress(from).call(...)` returns `(true, "")` because the target has no code — no revert, no `onGetResponse` execution.
5. Because `success == true`, the receipt is kept (never deleted for retry), the relayer is paid `fee` from the fee token, and `GetRequestHandled` is emitted — even though the application-level callback that was supposed to process the response never ran, and can never run again since the commitment is now marked as delivered [8](#0-7) .

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }
