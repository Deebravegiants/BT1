## Finding: Leftover swap input/output tokens permanently stuck in `LifiExternalAction`/`ExternalActionSwap`

### Title
Unaccounted leftover token balances become permanently stuck in `LifiExternalAction` after partial-fill or exact-output router calls - (File: `contracts/external-actions/swaps/LifiExternalAction.sol`, `contracts/external-actions/swaps/ExternalActionSwap.sol`)

### Summary
This is the same accounting-class bug as the Beedle report: value that legitimately lands in a contract is never accounted for by the contract's core equation, so it becomes permanently unreachable. In the Beedle case it was WETH sitting in `Staking` before `totalSupply>0`; here it is input/output token dust sitting in `LifiExternalAction`/`ExternalActionSwap` that the swap-output equation never captures and that has no sweep path.

### Finding Description
`ExternalActionSwap.swap()` transfers the full `inputAmount` into the external-action contract (via `Hinkal._externalTransact`, `contracts/Hinkal.sol:247-255`) and then calls `callRouter`, whose only accounting is the *output*-token balance diff: [1](#0-0) 

`swappedAmount` is computed purely from the delta of `outputToken` balance before/after the router call; the router is given `approveUnlimited` allowance over `inputToken`, so the router - not this contract - decides how much of `inputAmount` to actually pull: [2](#0-1) 

`swap()` never checks the `inputToken` balance before/after the call, and never sweeps any residual `inputToken` (or `outputToken` beyond what was already netted) back to `msg.sender` (the `Hinkal` contract): [3](#0-2) 

If the encoded router calldata (`circomData.externalActionData.externalActionMetadata`, fully attacker/relayer-controlled since it is just forwarded to `router.call`) triggers an "exact-output" style swap or otherwise consumes less than the full `inputAmount` that was transferred into this contract, the unconsumed remainder of `inputToken` (and any excess/refunded `outputToken` beyond the netted diff) simply remains as a balance on the `LifiExternalAction`/`ExternalActionSwap` contract. Nothing in `swap()`, `runAction()`, or `Hinkal.transact()`'s balance equation (`contracts/Hinkal.sol:97-146`) ever observes or captures this residue, because that equation only reads balances of the *Hinkal* contract, not the intermediate external-action contract. There is no `onlyOwner` sweep/rescue function in `ExternalActionSwap.sol` or `LifiExternalAction.sol` to recover it later either.

This breaks the intended equality that "every token unit that leaves a user's shielded balance is either returned to the user, paid as a fee, or converted into a new UTXO" - a portion of the user's input value silently disappears from all sides of the equation and is permanently trapped in the external-action contract.

### Impact Explanation
This is a permanent freezing of user funds: the leftover `inputToken`/`outputToken` balance is unrecoverable by the depositing user, by the protocol, or by any subsequent transaction, since the accounting is strictly diff-based per call and there is no owner-level sweep mechanism in the affected contracts. Per the rubric this qualifies as Critical ("permanent freezing of user funds").

### Likelihood Explanation
Any relayer/user who submits a `transact()` call routed through the LI.FI external action fully controls `externalActionMetadata`, i.e., the exact calldata sent to `router.call(...)`. Many DEX aggregators/routers support exact-output or multi-path fills where the amount actually pulled from the unlimited-allowance caller is less than what was pre-funded, or refund excess native/ERC20 back to the caller mid-execution. No admin/relay privilege is required to trigger the underfill; it can happen from ordinary usage of the aggregator or be deliberately crafted by any user to strand a portion of the funds (their own, or previously stranded protocol/relay-fee dust that other users indirectly leave behind).

### Recommendation
Track and account for `inputToken` balance before/after the router call in `callRouter`/`swap`, and either (a) revert if not fully consumed, or (b) fold any leftover `inputToken`/excess `outputToken` back into the returned `UTXO[]`/relay-fee accounting so it flows back through the Hinkal balance equation instead of being stranded. Additionally, add an owner-guarded but auditable rescue path is insufficient by itself since it doesn't preserve user entitlement to the funds - the real fix is closing the loop in the balance equation itself.

### Proof of Concept
1. User calls `Hinkal.transact()` with `externalActionData.externalActionId` pointing at `LifiExternalAction`, `erc20TokenAddresses = [inputToken, outputToken]`, and `amountChanges[0] = -inputAmount`.
2. `Hinkal._externalTransact` transfers the full `inputAmount` of `inputToken` to `LifiExternalAction` (`contracts/Hinkal.sol:247-255`), then calls `runAction` → `swap` → `callRouter`.
3. `externalActionMetadata` encodes a LI.FI/router call that is set up as an exact-output-style fill, consuming only `X < inputAmount` of the approved `inputToken` (the router is free to do this because `approveUnlimited` was granted, not an exact allowance).
4. `callRouter` returns `swappedAmount` based solely on the `outputToken` balance diff; the leftover `inputAmount - X` of `inputToken` remains on `LifiExternalAction`'s balance.
5. `swap()` sends only `amountToSendToHinkal` of `outputToken` back to `Hinkal`; no `inputToken` residue is ever moved back.
6. `Hinkal.transact()`'s balance equation only checks `Hinkal`'s own balance deltas and validates against the returned `utxoSet` (`contracts/Hinkal.sol:97-146`); it has no visibility into `LifiExternalAction`'s stranded `inputToken` balance, so the transaction succeeds and the leftover funds are permanently stuck with no recovery function in `ExternalActionSwap.sol`/`LifiExternalAction.sol`.

**File:** contracts/external-actions/swaps/LifiExternalAction.sol (L16-36)
```text
    function callRouter(
        address inputToken,
        uint256 inputAmount,
        address outputToken,
        bytes calldata externalActionMetadata
    ) internal override returns (uint256 swappedAmount) {
        uint256 balanceBefore = getERC20OrETHBalance(outputToken);

        if (inputToken == address(0)) {
            (bool success, ) = router.call{value: inputAmount}(
                externalActionMetadata
            );
            require(success, "LI.FI swap failed: native coin");
        } else {
            approveUnlimited(inputToken, router);
            (bool success, ) = router.call(externalActionMetadata);
            require(success, "LI.FI swap failed: erc-20 token");
        }

        swappedAmount = getERC20OrETHBalance(outputToken) - balanceBefore;
    }
```

**File:** contracts/external-actions/swaps/ExternalActionSwap.sol (L40-102)
```text
    function swap(
        CircomData calldata circomData,
        int256[] calldata deltaAmounts
    ) internal returns (UTXO[] memory utxoSet) {
        address inputToken = circomData.erc20TokenAddresses[0];
        uint256 inputAmount = uint256(-deltaAmounts[0]);

        if (inputToken == circomData.feeStructure.feeToken) {
            inputAmount -= circomData.feeStructure.flatFee;
        }

        address outputToken = circomData.erc20TokenAddresses[1];

        require(
            circomData.slippageValues[1] != 0,
            "swap output slippage floor not set"
        );

        require(
            block.timestamp <= circomData.timeStamp + SWAP_DEADLINE_WINDOW,
            "swap expired"
        );

        uint256 swappedAmount = callRouter(
            inputToken,
            inputAmount,
            outputToken,
            circomData.externalActionData.externalActionMetadata
        );

        uint256 relayFee = circomData.feeStructure.flatFee;

        uint256 hinkalFee = hinkalHelper.calculateRelayFee(
            swappedAmount,
            0,
            circomData.feeStructure.variableRate
        );

        if (circomData.feeStructure.feeToken == outputToken) {
            sendToRelay(circomData.relay, relayFee + hinkalFee, outputToken);
        } else {
            sendToRelay(
                circomData.relay,
                relayFee,
                circomData.feeStructure.feeToken
            );
            sendToRelay(circomData.relay, hinkalFee, outputToken);
        }

        uint256 totalFee = hinkalFee +
            (outputToken == circomData.feeStructure.feeToken ? relayFee : 0);
        uint256 amountToSendToHinkal = swappedAmount - totalFee;

        transferERC20TokenOrETH(outputToken, msg.sender, amountToSendToHinkal);

        utxoSet = new UTXO[](1);
        utxoSet[0] = UTXO({
            amount: amountToSendToHinkal,
            erc20Address: outputToken,
            stealthAddressStructure: circomData.stealthAddressStructure,
            timeStamp: block.timestamp
        });
    }
```
