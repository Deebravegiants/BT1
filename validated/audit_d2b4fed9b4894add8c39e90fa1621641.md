**Analysis:**

The `ForceEndEpochEvent::V1` emission is not reachable by unprivileged input. `event::emit` is called only inside `try_finalize_reconfig`, a private (non-`public`, non-`entry`) function [1](#0-0) . This function is reachable only through:

1. `try_advance_reconfig`, which is `public(friend)` restricted to the `block` module [2](#0-1) 
2. `finish_with_dkg_result` / `finish_with_chunky_dkg_result`, both private functions invoked only from the DKG/ChunkyDKG validator-transaction result-processing paths [3](#0-2) 

None of these are `entry` functions or otherwise callable by an unprivileged transaction sender. There is no public API that accepts attacker-supplied `epoch`, `dkg_incomplete`, `chunky_incomplete`, `deadline_us`, or `now_us` values and forwards them into `event::emit`. Move's event system also does not support external event injection or replay — events can only be produced by the exact bytecode path that executes `event::emit` during transaction/block execution, and `now_us`/`deadline_us` are derived from `timestamp::now_microseconds()` and `reconfiguration_state::start_time_secs()` plus the governance-configured grace period [4](#0-3) , none of which are attacker-controlled.

Additionally, even under the hypothetical that this event data could be spoofed, this would only be an off-chain indexer/wallet display issue — it does not touch any custody surface (no object ownership, FA store, multisig, or resource-account authority is read from this event on-chain). Per the review's decision standard, "cosmetic or event-level mismatch" findings that don't cross a real custody boundary are explicitly out of scope.

    fun try_finalize_reconfig(account: &signer) {
        if (!reconfiguration_state::is_in_progress()) { return };

        // Emergency watchdog: force-finalize regardless of DKG state once the
        // grace period has elapsed since reconfiguration started. Equivalent
        // to `now >= last_reconfiguration_time + epoch_interval + grace_period`,
        // since `reconfiguration_state::start_time_secs()` is set when the
        // block prologue triggers reconfig after `epoch_interval` has elapsed.
        let force_end_grace = epoch_timeout_config::force_end_grace_period_secs();
        if (force_end_grace.is_some()) {
            let now_us = timestamp::now_microseconds();
            let deadline_us = reconfiguration_state::start_time_secs() * 1_000_000
                + (*force_end_grace.borrow()) * 1_000_000;
            if (now_us >= deadline_us) {
                let dkg_incomplete = dkg::incomplete_session().is_some();
                let chunky_incomplete = chunky_dkg::incomplete_session().is_some();
                event::emit(ForceEndEpochEvent::V1 {
                    epoch: reconfiguration::current_epoch(),
                    dkg_incomplete,
                    chunky_incomplete,
                    deadline_us,
                    now_us,
                });
                finish(account);
                return
            };
        };
