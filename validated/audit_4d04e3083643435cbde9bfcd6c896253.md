### Title
Web API trigger messages lack replay protection, allowing repeated unauthorized workflow execution within the staleness window - (File: core/services/gateway/handlers/capabilities/handler.go, core/capabilities/webapi/trigger/trigger.go)

### Summary
The gateway's legacy web-api-trigger flow validates a signed `api.Message` only by checking the ECDSA signature of the message body and comparing `payload.Timestamp` against a fixed staleness window (`MaxAllowedMessageAgeSec`). There is no mechanism to mark a previously-processed signed message/timestamp as consumed, so any party who obtains a valid signed trigger message (e.g. by observing it on the wire to the internet-facing gateway HTTP endpoint) can resend the identical payload multiple times before the staleness window elapses, causing the DON to fire the workflow trigger repeatedly for the same event.

### Finding Description
`handler.HandleLegacyUserMessage` performs exactly the same category of check called out in the report: it verifies the signature is valid and checks `time.Now().Unix() - MaxAllowedMessageAgeSec <= payload.Timestamp`, but performs no idempotency/replay check tied to that signature or timestamp itself: [1](#0-0) 

The only per-message bookkeeping is `savedCallbacks[msg.Body.MessageID]`, which is used solely to route the async response back to the HTTP caller and is deleted once a response is produced — it is not a replay guard, and `MessageID` is caller-supplied and not required to be unique over time.

The message is then forwarded to the DON nodes and handled by `triggerConnectorHandler.HandleGatewayMessage` → `processTrigger`, which unconditionally re-fires the trigger channel for any workflow whose topic/sender matches, with no dedup on `payload.TriggerEventId`/`body.Sender`/timestamp: [2](#0-1) 

Because the timestamp check is the sole "freshness" gate (mirroring `block.timestamp <= liquidationSig.timestamp + upnlValidTime` in the reported bug), and nothing invalidates a signed message once it has been successfully processed, the same signed request can be resent for the entire `MaxAllowedMessageAgeSec` duration and will be re-verified and re-accepted every time.

This differs from other authentication paths in the same codebase that already implement single-use protection against exactly this class of bug — e.g. the Vault JWT flow's `RequestReplayGuard` (digest tracked with expiry, rejects on re-use) and the JWT `jti`-based replay protection in `WorkflowMetadataHandler.Authorize`: [3](#0-2) [4](#0-3) 

The legacy `web_api_trigger` message path has no equivalent guard.

### Impact Explanation
An unprivileged party who can capture a legitimately-signed trigger message (posted to the internet-facing gateway HTTP endpoint) can replay it to repeatedly re-trigger the associated workflow execution as many times as desired within the staleness window, without needing the sender's private key. Depending on the workflow, this can cause duplicate/unauthorized job runs, repeated on-chain writes or fund-moving actions triggered by the workflow, and resource exhaustion — a direct analog of the "liquidating a healthy account repeatedly" impact in the report, translated to "re-triggering a privileged workflow action repeatedly."

### Likelihood Explanation
High under attacker capability appropriate for an unprivileged network client: the gateway HTTP endpoint is internet-facing, and any observer of a single valid, signed request payload (e.g., via logs, network capture, a misbehaving relay, or simple resubmission by the original legitimate but now-untrusted caller) can trivially replay the exact bytes. No cryptographic material or role is required — only capturing one previously valid message within its ~staleness window is needed, and there is no code path that consumes/rejects a repeated timestamp+signature combination.

### Recommendation
Add a replay guard analogous to `RequestReplayGuard`/JWT `jti` tracking to the legacy web-api-trigger path: after successfully validating and accepting a trigger message, record its signature (or a digest of `MessageID`/`Sender`/`TriggerEventId`/`Timestamp`) with an expiry equal to `MaxAllowedMessageAgeSec`, and reject any subsequent request with the same digest until it naturally expires. This should be enforced either at the gateway (`handler.HandleLegacyUserMessage`) or at the DON trigger handler (`triggerConnectorHandler.HandleGatewayMessage`/`processTrigger`), consistent with how `vault.RequestReplayGuard` and the JWT `jti` cache already solve this exact problem elsewhere in the codebase.

### Proof of Concept
1. A legitimate, allowed sender signs and submits a `web_api_trigger` message to the gateway's HTTP endpoint within `MaxAllowedMessageAgeSec` of `payload.Timestamp`.
2. `handler.HandleLegacyUserMessage` validates the signature and the staleness bound, then forwards the message to the DON; `processTrigger` fires the workflow trigger channel — one legitimate execution occurs.
3. An unprivileged observer who captured the exact raw signed message body/signature resubmits the identical bytes to the gateway any number of times before `payload.Timestamp + MaxAllowedMessageAgeSec` elapses.
4. Each resubmission passes the same signature and staleness checks (nothing has changed state to invalidate it) and `processTrigger` fires the same workflow trigger again, producing duplicate/unauthorized workflow executions from a single originally-authorized signed message.

func (h *triggerConnectorHandler) processTrigger(ctx context.Context, gatewayID string, body *api.MessageBody, sender ethCommon.Address, payload webapicap.TriggerRequestPayload) error {
	// Pass on the payload with the expectation that it's in an acceptable format for the executor
	wrappedPayload, err := values.WrapMap(payload)
	if err != nil {
		return fmt.Errorf("error wrapping payload %w", err)
	}
	topics := payload.Topics

	// empty topics is error for V1
	if len(topics) == 0 {
		return errors.New("empty Workflow Topics")
	}

	h.mu.Lock()
	triggers := slices.Collect(maps.Values(h.registeredWorkflows))
	h.mu.Unlock()

	// workflows that have matched topics
	matchedWorkflows := 0
	// workflows that have matched topic and passed all checks
	fullyMatchedWorkflows := 0
	for _, trigger := range triggers {
		for _, topic := range topics {
			if trigger.allowedTopics[topic] {
				matchedWorkflows++
				if !trigger.allowedSenders[sender.String()] {
					err = fmt.Errorf("unauthorized Sender %s, messageID %s", sender.String(), body.MessageID)
					h.lggr.Debugw(err.Error())
					continue
				}
				if !trigger.rateLimiter.Allow(body.Sender) {
					err = fmt.Errorf("request rate-limited for sender %s, messageID %s", sender.String(), body.MessageID)
					continue
				}
				fullyMatchedWorkflows++
				TriggerEventID := body.Sender + payload.TriggerEventId

				// Emit trigger execution started event
				workflowExecutionID, genErr := events.GenerateExecutionID(trigger.workflowID, TriggerEventID)
				if genErr != nil {
					h.lggr.Errorw("failed to generate execution ID", "err", genErr)
					workflowExecutionID = ""
				}
				emitErr := events.EmitTriggerExecutionStarted(ctx, map[string]string{}, TriggerEventID, workflowExecutionID)
				if emitErr != nil {
					h.lggr.Errorw("failed to emit trigger execution started event", "err", emitErr)
				}

				tr := capabilities.TriggerResponse{
					Event: capabilities.TriggerEvent{
						TriggerType: TriggerType,
						ID:          TriggerEventID,
						Outputs:     wrappedPayload,
					},
				}
				trigger.chWriteMu.Lock()
				if trigger.ch == nil {
					trigger.chWriteMu.Unlock()
					return nil
				}
				select {
				case <-ctx.Done():
					trigger.chWriteMu.Unlock()
					return nil
				case trigger.ch <- tr:
					trigger.chWriteMu.Unlock()
					// Sending n topics that match a workflow with n allowedTopics, can only be triggered once.
					break
				}
			}
		}
	}
	if matchedWorkflows == 0 {
		return errors.New("no Matching Workflow Topics")
	}

	if fullyMatchedWorkflows > 0 {
		return nil
	}
	return err

// CheckAndRecord returns ErrRequestAlreadySeen if the digest was previously
// recorded and has not yet expired. Otherwise it records the digest with
// the given expiry timestamp (unix seconds, UTC).
//
// Expired entries are cleaned up on every call.
func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}
