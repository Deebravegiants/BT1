### Title
Phantom order price snapshot weights bids by live, unsnapshotted solver balance, letting a solver flash-borrow inventory to dictate the published price - (File: `sdk/packages/sdk/src/protocols/intents/phantom-aggregation.ts`)

### Summary
`aggregatePhantomBids` builds the price used by `PhantomSnapshotIntentQuoteStrategy` to quote real user intents by taking a *liquidity-weighted median* of solver bids, where each bid's weight is the solver's **current, live** on-chain balance of the leg's output token, read at the moment the aggregation runs (bid-window close) rather than a value fixed/committed at bid submission time. This is structurally the same flaw as the reported governance bug: a value that determines the weight of a vote/quote is read live instead of snapshotted, letting an actor temporarily inflate that value, dominate the outcome, then revert the inflation.

### Finding Description
`weightedMedian` in `phantom-aggregation.ts:709-724` explicitly documents that it is a **selection, not a blend**: "a solver holding over half the leg's weight sets the published price verbatim" [3](#0-2) . The weight fed into it comes from `getBalance(destUrl, chain, outputToken, solver)` inside `runAggregation`, called per quoted leg right when the bid window closes [2](#0-1) . `getBalance` defaults to `memoizedSolverBalance(yieldVaults)`, which wraps `getTotalSolverBalance` reading at `blockTags[chain]` if provided or otherwise the chain head [4](#0-3) . Nothing ties this balance read to the block at which the solver actually placed its bid; it is re-read live whenever aggregation executes.

A verified solver (one delegated to the chain's `SolverAccount`, per `isVerifiedSolverBid`) can place a bid quoting an arbitrary price, then — anytime before the aggregation actually samples the balance — temporarily acquire a large quantity of the leg's output token (flash loan, DEX swap, or transient transfer from an associated account), push its weight over 50% of the leg's total weight, and have `weightedMedian` return its own quoted price verbatim. It can then move the tokens back out immediately afterward, since nothing re-checks the balance again once the snapshot is written.

This exactly parallels the report's bug class: "increases their locked tokens... casts vote... immediately after voting, reduces back" — here, "increase balance -> get counted as majority weight -> published price set to attacker's quote -> return balance," with no commitment/snapshot of the balance at bid time.

### Impact Explanation
The resulting `PhantomOrderPriceSnapshotV2.medianPrice` is consumed directly by `PhantomSnapshotIntentQuoteStrategy.quoteSnapshot` (`sdk/packages/sdk/src/protocols/intents/quote/phantomSnapshot.ts:83-101`) to compute `amountOut`/`amountIn` for real user intents on that token pair [5](#0-4) , and feeds pool rates (`sellRate`/`buyRate`) that other consumers price against. A solver that can transiently dominate leg weight can set an arbitrarily bad price (e.g., pricing a user's swap far below fair value), directly costing users funds when they submit orders at the manipulated rate, and can also inflate its own `PoolBidder`/liquidity depth attribution downstream.

### Likelihood Explanation
Requires being a delegated solver (EIP-7702 to `SolverAccount`) capable of placing verified bids — this is the "intent solver" role explicitly in scope — and requires only a transient balance increase (flash loan/self-transfer) around the aggregation's balance read, with no additional privilege, admin, or governance action needed. This is comparable in mechanism and cost to a standard flash-loan governance attack.

### Recommendation
Pin the balance read used for bid weighting to a block at or before the bid's own submission (e.g., the block the `BidPlaced` extrinsic landed, or a block committed to inside the signed bid/userOp), rather than reading the live/head balance at aggregation time. Alternatively, require the balance to be proven/committed at bid-submission time (analogous to snapshotting voting power at proposal creation) so it cannot be inflated between bid placement and aggregation.

### Proof of Concept
1. A delegated solver submits a `place_bid` extrinsic for a phantom order quoting an extreme (unfavorable-to-user) price for a leg, with normal/low balance of the output token at that time.
2. Shortly before `PhantomBidWindowExhausted` fires (or before the indexer's `handlePhantomOrderPrices` runs `aggregatePhantomBids`), the solver flash-loans or otherwise temporarily acquires a large amount of the leg's output token on the destination chain into the address that signed the bid.
3. `aggregatePhantomBids` reads the solver's balance live (`getBalance`, defaulting to `latest` block) and computes weight far exceeding 50% of total leg weight.
4. `weightedMedian` selects the solver's quoted price verbatim as `medianPrice`, written into `PhantomOrderPriceSnapshotV2`.
5. The solver returns the borrowed/transient tokens immediately after the snapshot is taken.
6. Any user quoting through `PhantomSnapshotIntentQuoteStrategy` for that pair now receives `amountIn`/`amountOut` computed off the attacker's manipulated price rather than a fair market rate.

// lower weighted median: the smallest price whose cumulative weight reaches half of the total.
// Zero-weight quotes contribute nothing.
//
// Callers must not hand this an entry set whose weights are all zero: with nothing to weight by it
// can only pick a quote by position, and for an even-sized set that position is the upper of the
// two middles — so "the median" becomes "whoever quoted higher", settable by a solver holding no
// inventory at all. aggregatePhantomBids drops such legs instead of pricing them. The fallback
// below stays only so an unguarded caller gets a number rather than a crash; treat reaching it as
// a caller bug.
export function weightedMedian(entries: { price: bigint; weight: bigint }[]): bigint {
	const sorted = [...entries].sort((a, b) => (a.price < b.price ? -1 : a.price > b.price ? 1 : 0))
	const totalWeight = sorted.reduce((acc, e) => (e.weight > 0n ? acc + e.weight : acc), 0n)

	if (totalWeight === 0n) {
		return sorted[Math.floor(sorted.length / 2)].price
	}

	let cumulative = 0n
	for (const entry of sorted) {
		if (entry.weight <= 0n) continue
		cumulative += entry.weight
		if (cumulative * 2n >= totalWeight) return entry.price
	}
	return sorted[sorted.length - 1].price
}

export type SolverBalanceReader = (evmRpcUrl: string, chain: string, token: string, solver: string) => Promise<bigint>

// One aggregation run reads the same (chain, token, solver) balance from several places — once
// per leg the solver quoted in that token, and again in the liquidity sweep — and a bundled order
// can carry up to 128 legs. Memoizing for the life of the run collapses that to one RPC round
// trip per distinct triple, at the cost of ignoring balance changes within the run (the snapshot
// is a point-in-time read either way). Exported so a caller aggregating several orders whose bid
// windows close on the same block (one bundled order per configured chain) can share one memo
// across the runs instead of re-reading identical balances per order.
export function memoizedSolverBalance(
	yieldVaults: YieldVaultMap,
	/**
	 * Block to read each chain at, keyed by state machine id; anything absent reads the head. Block
	 * numbers are per chain, so a caller handling an event on one chain can pin that chain to the
	 * event's block while the rest of its sweep stays at the head, where the numbers would mean
	 * nothing.
	 */
	blockTags: Record<string, string> = {},
): SolverBalanceReader {
	const cache = new Map<string, Promise<bigint>>()
	return (evmRpcUrl: string, chain: string, token: string, solver: string): Promise<bigint> => {
		const key = `${chain}|${token.toLowerCase()}|${solver.toLowerCase()}`
		let pending = cache.get(key)
		if (!pending) {
			// Evict on rejection. Caching a failure would make it permanent for the memo's lifetime —
			// every retry would replay the same failed read, and a block-scoped memo would carry one
			// blip across every order closing on that block.
			pending = getTotalSolverBalance(evmRpcUrl, chain, token, solver, yieldVaults, blockTags[chain]).catch((err) => {
				cache.delete(key)
				throw err
			})
			cache.set(key, pending)
		}
		return pending
	}
