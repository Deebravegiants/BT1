### Title
Unbounded off-chain `BidCache` growth lets any account submitting `place_bid` extrinsics exhaust the intents RPC node's memory - (File: modules/pallets/intents-coprocessor/rpc/src/lib.rs)

### Summary
`BidCache` in the intents-coprocessor RPC layer stores every observed `place_bid` mempool transaction in an in-process `HashMap<H256, OrderBids>` with no cap on the number of distinct order commitments, the number of fillers per commitment, or the size of the cached `user_op` payload. Expiry only happens via a periodic TTL sweep (`remove_expired`), which does not bound the rate or volume of growth between sweeps, so an unprivileged party can drive the cache size arbitrarily high, exhausting node memory (the DoS pattern described by the rmagick advisory: unbounded resource retention under CWE-400/401).

### Finding Description
`BidCache::insert` is called from `run_bid_watcher` for every transaction pool entry that decodes as a `pallet_intents_coprocessor::Call::place_bid` extrinsic, before it is ever included in a block: [1](#0-0) 

The cache itself has no size limit on the outer `HashMap` (one entry per order `commitment`) nor on the inner `entries: Vec<BidEntry>` (one per distinct `filler`), and stores the full `user_op` bytes supplied by the caller: [2](#0-1) 

The only eviction mechanism is a periodic TTL sweep triggered by a timer tick, which drops entries whose `first_seen` is older than `ttl`: [3](#0-2) [4](#0-3) 

Because entries are only removed after they age past `ttl`, an attacker who submits `place_bid` extrinsics faster than the TTL window (or with many distinct `commitment`/`filler` pairs and large `user_op` payloads) can grow `bids` without bound during that window, and can sustain the growth indefinitely by continuously submitting fresh transactions before the TTL elapses. Nothing about `place_bid` requires the transaction to ever be included on-chain or to succeed on-chain — it only needs to be accepted into the node's transaction pool and be decodable as a `place_bid` call by `extract_bid`, which any account with the ability to sign and gossip transactions can do: [5](#0-4) 

This mirrors the reported bug class (unbounded in-memory retention leading to memory exhaustion / DoS), but here the sink is reachable from an unprivileged, unauthenticated transaction submitter rather than a local library call.

### Impact Explanation
An attacker can submit many transactions (from many keys or the same key with rapidly incrementing nonces, since acceptance into the pool — not finalization — is what triggers caching) that decode as valid `place_bid` calls with distinct commitments/fillers and large `user_op` payloads. Each is cached in unbounded structures held by the RPC-serving process, degrading and eventually crashing (OOM) the node that serves `intents_getBidsForOrder`/`intents_subscribeBids`. This is a resource-exhaustion route affecting node/relayer/filler availability for the intents pipeline, which the task scope explicitly includes ("intent solver" / dispatch-adjacent components) as a Medium severity denial-of-service.

### Likelihood Explanation
Likelihood is moderate-to-high: no special privilege, valid on-chain bid, or successful execution is required — only that the transaction pass basic extrinsic decoding and be accepted into the node's ready transaction pool as a `place_bid` call. Transaction pool acceptance criteria (fee, nonce ordering, size limits per extrinsic) constrain but do not prevent an attacker from generating a large sustained volume of distinct low-cost transactions to keep pumping the cache within any TTL window.

### Recommendation
Bound the `BidCache`: cap total tracked commitments and fillers-per-commitment (e.g., LRU eviction or a hard maximum count), and cap/reject oversized `user_op` payloads before caching. Consider deduplicating/evicting on account rather than solely on filler bytes, and evaluate whether the same account can artificially inflate the cache via nonce-cycling low-fee transactions that stay in the pool.

### Proof of Concept
1. An attacker generates N distinct signing keys (or repeatedly resubmits with different fillers/commitments), each producing a valid `pallet_intents_coprocessor::Call::place_bid { commitment, user_op }` extrinsic with a maximal-size `user_op`.
2. Attacker broadcasts these transactions so they land in the node's ready transaction pool; they do not need to be finalized or even valid on-chain, only decodable via `extract_bid`.
3. `run_bid_watcher`'s `stream.next()` branch fires for each transaction and calls `bid_cache.insert(commitment, filler, user_op)`, adding a new `HashMap` entry (new commitment) or `Vec` entry (new filler under existing commitment) each time — see [6](#0-5) .
4. Attacker sustains submission faster than `cleanup_interval`/`ttl` expiry, so `remove_expired` ( [3](#0-2) ) never catches up, and the in-memory cache grows until the RPC node exhausts available memory.

Note: I was not able to verify from the indexed portion of `modules/pallets/intents-coprocessor/src/lib.rs` whether the on-chain `place_bid` extrinsic itself enforces a `BoundedVec`/max-length constraint on `user_op` before it reaches the pool (the grep found matches but full context wasn't retrievable within the tool budget); if such a bound exists it would cap per-entry size but would not address the unbounded count of commitments/fillers, which remains the primary vector.

#[derive(Clone, Debug)]
struct BidEntry {
	filler: Vec<u8>,
	user_op: Vec<u8>,
}

#[derive(Clone, Debug)]
struct OrderBids {
	first_seen: Instant,
	entries: Vec<BidEntry>,
}

/// In-memory bid cache.
pub struct BidCache {
	bids: RwLock<HashMap<H256, OrderBids>>,
	ttl: Duration,
}

impl BidCache {
	pub fn new(ttl: Duration) -> Self {
		Self { bids: RwLock::new(HashMap::new()), ttl }
	}

	pub fn insert(
		&self,
		commitment: H256,
		filler: Vec<u8>,
		user_op: Vec<u8>,
	) -> Result<(), String> {
		let entry = BidEntry { filler: filler.clone(), user_op };

		let mut bids = self.bids.write().map_err(|e| format!("BidCache lock poisoned: {e}"))?;
		let order = bids
			.entry(commitment)
			.or_insert_with(|| OrderBids { first_seen: Instant::now(), entries: Vec::new() });
		if let Some(existing) = order.entries.iter_mut().find(|e| e.filler == filler) {
			*existing = entry;
		} else {
			order.entries.push(entry);
		}
		Ok(())
	}

	pub fn remove_expired(&self) -> Result<(), String> {
		let now = Instant::now();
		let mut bids = self.bids.write().map_err(|e| format!("BidCache lock poisoned: {e}"))?;
		bids.retain(|_commitment, order| now.duration_since(order.first_seen) < self.ttl);

pub fn extract_bid<T, Extra>(encoded: &[u8]) -> Option<(H256, Vec<u8>, Vec<u8>)>
where
	T: pallet_intents_coprocessor::Config,
	T::RuntimeCall: frame_support::traits::IsSubType<pallet_intents_coprocessor::Call<T>>
		+ DecodeWithMemTracking,
	T::AccountId: Encode + From<[u8; 32]> + DecodeWithMemTracking,
	Extra: DecodeWithMemTracking,
{
	let xt = sp_runtime::generic::UncheckedExtrinsic::<
		sp_runtime::MultiAddress<T::AccountId, ()>,
		T::RuntimeCall,
		sp_runtime::MultiSignature,
		Extra,
	>::decode(&mut &encoded[..])
	.ok()?;

	let filler = match &xt.preamble {
		sp_runtime::generic::Preamble::Signed(address, _, _) => match address {
			sp_runtime::MultiAddress::Id(id) => id.encode(),
			_ => return None,
		},
		_ => return None,
	};

	match xt.function.is_sub_type()? {
		pallet_intents_coprocessor::Call::place_bid { commitment, user_op } =>
			Some((commitment.clone(), filler, user_op.to_vec())),
		_ => None,
	}
}

pub async fn run_bid_watcher<P, Block, T, Extra>(
	pool: Arc<P>,
	bid_cache: Arc<BidCache>,
	bid_sender: broadcast::Sender<RpcBidInfo>,
	cleanup_interval: Duration,
) where
	Block: BlockT,
	P: TransactionPool<Block = Block> + 'static,
	T: pallet_intents_coprocessor::Config,
	T::RuntimeCall: frame_support::traits::IsSubType<pallet_intents_coprocessor::Call<T>>
		+ DecodeWithMemTracking,
	T::AccountId: Encode + From<[u8; 32]> + DecodeWithMemTracking,
	Extra: DecodeWithMemTracking + Send + 'static,
{
	use futures::StreamExt;

	let mut stream = pool.import_notification_stream();
	let mut timer = tokio::time::interval(cleanup_interval);

	loop {
		tokio::select! {
			Some(tx_hash) = stream.next() => {
				let tx = match pool.ready_transaction(&tx_hash) {
					Some(tx) => tx,
					None => continue,
				};

				let extrinsic_bytes = tx.data().encode();

				if let Some((commitment, filler, user_op)) = extract_bid::<T, Extra>(&extrinsic_bytes) {
					log::info!(
						target: LOG_TARGET,
						"bid in mempool for {commitment:?}",
					);
					if let Err(e) = bid_cache.insert(commitment, filler.clone(), user_op.clone()) {
						log::warn!(target: LOG_TARGET, "failed to cache bid: {e}");
						continue;
					}

					let _ = bid_sender.send(RpcBidInfo { commitment, filler, user_op });
				}
			}
			_ = timer.tick() => {
				if let Err(e) = bid_cache.remove_expired() {
					log::warn!(target: LOG_TARGET, "failed to clean bid cache: {e}");
				}
			}
		}
	}
