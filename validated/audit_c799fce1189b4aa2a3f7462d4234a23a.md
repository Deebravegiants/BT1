### Title
An account delegate can drain residual collateral to itself via `repay_debt_with_collateral(close_position = true)` - (File: contracts/controller/src/strategies/repay_debt_with_collateral.rs)

### Summary

The controller's account-guard model has two privilege tiers: the NFT owner, and a `delegate` — a governance-approved position manager the owner opted into via `add_delegate` (`contracts/controller/src/account.rs:229-275`). The shared guard `require_owner_or_delegate` (`contracts/controller/src/account.rs:130-140`) treats both as equivalent for every strategy entrypoint. That is correct for actions whose proceeds stay inside the account (`swap_debt`, `swap_collateral`, `multiply`, `migrate_from_blend`, `flash_position`), but `repay_debt_with_collateral` with `close_position = true` sends the account's remaining collateral to **the caller**, not the owner (`contracts/controller/src/lib.rs:305-309`). A delegate — a lower-privilege "shared user" — can therefore invoke an owner-appropriate payout action and receive the funds, the same class as CVE-2026-50007 where shared access was accepted for owner-only file operations.

### Finding Description

`repay_debt_with_collateral` is documented and gated as owner-or-delegate:

- The entrypoint routes to `strategies::repay_debt_with_collateral::process_repay_debt_with_collateral` with a `close_position` flag (`contracts/controller/src/lib.rs:311-333`).
- Its doc states: "`close_position` withdraws all remaining collateral to the caller, reverting with `CannotCloseWithRemainingDebt` if any debt remains. Requires owner or delegate authorization." (`contracts/controller/src/lib.rs:305-309`).
- The account guard resolves through `load_or_create_account`/`require_owner_or_delegate`, which returns early whenever `is_owner_or_delegate` is true — i.e., when `caller` is an active position manager listed in the account's delegate set (`contracts/controller/src/account.rs:115-140`).

The payout recipient is `caller`, not `account.owner`. Once the account's debts are repaid (a delegate can itself supply the repayment leg, or the account may be nearly debt-free), calling `repay_debt_with_collateral(account_id, collateral, collateral_amount, debt, swap, /*close_position*/ true)` transfers the entire residual collateral balance to the delegate's address. No owner signature is ever collected, and the NFT owner has no way to claw the funds back — `remove_delegate` only narrows future authority (`contracts/controller/src/account.rs:235-238`).

### Impact Explanation

Theft of user funds. A position manager that has been granted delegate authority on an account — a strictly weaker authorization than ownership, intended for managing position composition — can extract all remaining collateral from that account to its own address once debts are cleared. The victim owner loses the full collateral balance. This mirrors the report's shape: an authorization check (`require_owner_or_delegate`) treats lower-tier shared access as sufficient for an action that only the owner should be able to perform (receiving payouts from the account).

### Likelihood Explanation

- **Reachability:** fully reachable by any address that holds an active delegate grant plus `is_active` position-manager status — exactly the threat model delegates exist in (owners delegate to third-party managers; the manager is not trusted with custody).
- **Prerequisites:** the account must be able to reach zero remaining debt, either because debt is already low or because the delegate repays it (delegates can call `repay`/`repay_debt_with_collateral` freely). The delegate can bundle the repay-and-close in one transaction via `close_position = true`.
- **Mitigating factors:** requires the owner to have granted delegate authority first, so it is not a stranger attack; this is why it maps to a High/missing-authorization class rather than an unauthenticated theft.

### Recommendation

- Make the `close_position` payout path owner-only: either require `require_account_owner` when `close_position` is set, or pin the residual-collateral recipient to `account.owner` (read from `storage::account_owner`) instead of `caller`.
- Audit every strategy that pays out to `caller` (e.g., `refund_assets` in `flash_position`, `excess` refunds in liquidation/`recapitalize`) and ensure funds that economically belong to the account owner are sent to the owner, with `caller`-bound recipients used only for funds the caller actually supplied.

### Proof of Concept

1. Owner creates account `A`, supplies collateral, and calls `add_delegate(account_id = A, delegate = M)` where `M` is an active governance-approved position manager (`set_account_delegate` only requires the manager to be active, `contracts/controller/src/account.rs:251-258`).
2. Account `A` holds collateral and zero (or dust) debt.
3. `M` calls `repay_debt_with_collateral(caller = M, account_id = A, collateral, collateral_amount, debt, swap, close_position = true)`. `require_owner_or_delegate` passes because `M` is in `A`'s delegate set (`contracts/controller/src/account.rs:115-127`). The repay leg clears residual debt, then the close leg withdraws all remaining collateral **to `M`**.
4. `M` keeps the collateral; the owner is left with an emptied account, and `remove_delegate` cannot recover the funds.
