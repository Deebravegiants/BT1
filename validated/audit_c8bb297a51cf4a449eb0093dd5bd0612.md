### Title
Stale delegate grant reactivates after position NFT round-trip, allowing account drainage - (File: contracts/controller/src/storage/account.rs)

### Summary
A delegate grant is keyed only by `account_id` and stamped with the granting owner's address. An NFT transfer makes the grant inactive, but does not delete it; if the NFT returns to the same owner, the old delegate regains full owner-equivalent spending authority and can withdraw collateral or borrow to an arbitrary external recipient.

### Finding Description
`Controller::add_delegate` stores a `DelegateGrant` under `ControllerKey::Delegates(account_id)` with `granted_by` set to the then-current NFT owner. [1](#0-0)  `get_delegates` accepts that stored grant whenever `granted_by` equals the account's current NFT owner. [2](#0-1)  The controller resolves `account.owner` dynamically from the position NFT on every account load. [3](#0-2) 

No ownership epoch, transfer counter, or delegation generation distinguishes the original ownership period from a later ownership period by the same address. Consequently, a grant from the first ownership period becomes valid again after an NFT leaves and returns, unless the intervening owner explicitly overwrote it with `add_delegate` or purged it with `remove_delegate`. [4](#0-3) 

Once reactivated, `is_owner_or_delegate` accepts the stale delegate if it remains an active registered position manager. [5](#0-4)  Both `borrow` and `withdraw` accept a caller-selected recipient. [6](#0-5) [7](#0-6)  The only recipient restriction is that it cannot be the controller or pool, so the delegate can send proceeds to itself or another external address. [8](#0-7) 

### Impact Explanation
An old delegate can drain account value without the current owner's renewed consent. For an unlevered account, it can call `withdraw` with zero-valued legs to withdraw all collateral to itself. For a collateralized account, it can call `borrow` up to the account's risk limit and send the borrowed assets to itself, leaving the owner with the debt.

This is theft of user funds. The attacker needs only an ordinary address that is still registered as an active position manager and appears in the old grant.

### Likelihood Explanation
The exploit is conditional rather than permissionless against every account. The victim must previously delegate to the attacker's manager address, transfer the position NFT to another address, and receive the same NFT back while the manager remains active and the intervening owner does not overwrite or purge delegates.

NFT sale, escrow, temporary custody, contract wallet migration, or accidental round-trip flows can satisfy that sequence. The grant persists silently while inactive, so the victim may reasonably believe the transfer permanently revoked the old manager. Once the NFT returns, no transaction or warning is required before the delegate can act.

### Recommendation
Bind each delegate grant to a distinct ownership period, not merely to an owner address.

A robust fix is to expose an NFT ownership epoch or transfer nonce that increments on every transfer and include that epoch in `DelegateGrant`. `get_delegates` should require both `granted_by == current_owner` and `grant.epoch == current_owner_epoch`. Alternatively, add a controller ownership-synchronization hook invoked by the NFT on transfer and permanently delete `Delegates(account_id)` on every ownership change. Do not rely on intermediate owners to call `remove_delegate`.

### Proof of Concept
1. Alice owns lending `account_id` and calls `add_delegate(alice, account_id, attacker_manager)` while `attacker_manager` is an active position manager.
2. Alice transfers the position NFT for `account_id` to Bob using the position NFT's standard `transfer` or an approved `transfer_from` path.
3. Bob later transfers the same NFT back to Alice without calling `add_delegate` or `remove_delegate` on the controller.
4. The stored grant still has `granted_by == alice`; once NFT ownership resolves back to Alice, `get_delegates(account_id, alice)` returns `attacker_manager` again. [2](#0-1) 
5. The attacker calls:

```text
withdraw(
  caller = attacker_manager,
  account_id = account_id,
  withdrawals = [(victim_collateral_hub_asset, 0)],
  to = Some(attacker)
)
```

`0` selects the entire collateral position. `require_owner_or_delegate` passes through the reactivated grant, `require_external_recipient` accepts the attacker address, and the pool pays the attacker after the post-withdrawal solvency check. [7](#0-6)

/// Returns grants stamped by `owner`, or an empty list. Ownership changes
/// invalidate a previous owner's grants without deleting them.
pub(crate) fn get_delegates(env: &Env, account_id: u64, owner: &Address) -> Vec<Address> {
    get_user::<DelegateGrant>(env, &ControllerKey::Delegates(account_id))
        .filter(|grant| grant.granted_by == *owner)
        .map(|grant| grant.delegates)
        .unwrap_or_else(|| Vec::new(env))

/// Stores delegates stamped by the granting owner and renews user TTL;
/// deletes the entry when the list is empty.
fn set_delegates(env: &Env, account_id: u64, owner: &Address, delegates: &Vec<Address>) {
    let key = ControllerKey::Delegates(account_id);
    if delegates.is_empty() {
        env.storage().persistent().remove(&key);
    } else {
        set_user(
            env,
            &key,
            &DelegateGrant {
                granted_by: owner.clone(),
                delegates: delegates.clone(),
            },
        );
    }
}

/// Adds a delegate, enforcing `MAX_DELEGATES`; returns false for duplicates.
/// Overwrites stale grants with a list stamped by the current owner.
pub(crate) fn add_delegate(
    env: &Env,
    account_id: u64,
    owner: &Address,
    delegate: &Address,
) -> bool {
    let mut delegates = get_delegates(env, account_id, owner);
    if delegates.contains(delegate) {
        return false;
    }
    assert_with_error!(
        env,
        delegates.len() < MAX_DELEGATES,
        GenericError::RegistryCapReached
    );
    delegates.push_back(delegate.clone());
    set_delegates(env, account_id, owner, &delegates);
    true
}

/// Removes a live delegate and reports whether it changed the list.
/// Deletes stale grants but returns false, preventing those grants from
/// reactivating if the NFT returns to their original owner.
pub(crate) fn remove_delegate(
    env: &Env,
    account_id: u64,
    owner: &Address,
    delegate: &Address,
) -> bool {
    let key = ControllerKey::Delegates(account_id);
    let Some(grant) = get_user::<DelegateGrant>(env, &key) else {
        return false;
    };
    if grant.granted_by != *owner {
        env.storage().persistent().remove(&key);
        return false;
    }
    let mut delegates = grant.delegates;
    let Some(index) = delegates.first_index_of(delegate) else {
        return false;
    };
    delegates.remove(index);
    set_delegates(env, account_id, owner, &delegates);
    true
}

/// Accepts the owner or a registered, active manager delegated by that owner.
pub(crate) fn is_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) -> bool {
    if caller == owner {
        return true;
    }
    let active_manager =
        storage::get_position_manager(env, caller).is_some_and(|config| config.is_active);
    active_manager && storage::get_delegates(env, account_id, owner).contains(caller)
}

/// Requires the owner or a registered, active manager delegated by that owner.
pub(crate) fn require_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) {
    if is_owner_or_delegate(env, account_id, caller, owner) {
        return;
    }
    panic_with_error!(env, GenericError::NotAuthorized);
