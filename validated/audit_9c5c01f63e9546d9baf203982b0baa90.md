### Title
Permanent market freeze from unchecked RAY debt-value multiplication before the borrow-index cap - ([File: common/src/rates/index.rs])

### Summary
**Severity: Medium.** A sufficiently large market can reach a state where every state-changing operation on that market reverts with `MathOverflow`, permanently freezing supplied collateral, borrowed assets, and liquidation recovery. [1](#0-0) 

### Finding Description
Pool operations load market state and call `interest::global_sync` before executing the requested action. [2](#0-1)  Accrual calls `accrue_step`, which must compute the old and new total debt as `borrowed * borrow_index`. [3](#0-2)  Although `update_borrow_index` caps the stored borrow index at `MAX_BORROW_INDEX_RAY`, the total-debt multiplication can overflow `i128` before that cap provides protection. [4](#0-3)  The same scaled-value multiplication is exposed through `scaled_to_original`, which multiplies a scaled position by its index and propagates the overflow. [5](#0-4) 

The checked RAY multiplication panics with `MathOverflow` when the intermediate value exceeds `i128`, while the code does not clamp or recover from the oversized debt-value product. [6](#0-5)  Once the product of scaled debt and accrued borrow index crosses that boundary, accrual always fails before `last_timestamp` advances, so the same failure repeats on every subsequent operation. [7](#0-6) 

The repository’s own regression test demonstrates the condition: a one-billion-token, 18-decimal market at sustained 98% utilization eventually causes `update_indexes`, `withdraw`, and `repay` to return `MathOverflow`, while the stored borrow index remains below `MAX_BORROW_INDEX_RAY`. [8](#0-7) 

### Impact Explanation
The overflow permanently bricks the affected `(hub_id, asset)` market because every verb that must accrue first hits the same panic, including `supply`, `borrow`, `withdraw`, `repay`, `liquidate`, `clean_bad_debt`, and owner-triggered index or rate-model updates. [9](#0-8) [10](#0-9)  User collateral and pool cash remain in the contracts, but suppliers cannot withdraw and borrowers cannot repay through the normal paths. [11](#0-10)  This is a permanent freezing-of-funds impact rather than a transient revert, since no protocol path can advance or bypass the overflowing accrual once the market state crosses the boundary. [12](#0-11) 

### Likelihood Explanation
No privileged role is required to create the prerequisite state: a user can supply through `Controller::supply` and borrow through `Controller::borrow`, after which any later call to the market’s accrual path can cross the overflow boundary as time passes. [13](#0-12)  The likelihood is constrained because the demonstrated configuration requires an extremely large token supply, an 18-decimal asset, high sustained utilization, and enough collateral to support the borrow. [14](#0-13)  Those economics reduce practical exploitability, but the state transition itself is permissionless and the resulting market freeze is deterministic once reached. [15](#0-14) 

### Recommendation
Cap or saturate the scaled debt value before multiplying `borrowed` by the borrow index, rather than allowing the product to overflow `i128`. [16](#0-15)  Add a market-level invariant that `borrowed * MAX_BORROW_INDEX_RAY` and `supplied * MAX_SUPPLY_INDEX_RAY` remain representable, and enforce it during borrow and supply minting before the position or market totals are committed. [17](#0-16)  For markets already at the boundary, provide an accrual path that caps indexes and bounds the computed debt value so repayment, withdrawal, liquidation, bad-debt cleanup, and recapitalization remain executable. [18](#0-17) 

### Proof of Concept
1. Register a high-decimal market, such as an 18-decimal asset using the steep XLM-style rate curve, and configure broad enough caps for a whale-sized position. [19](#0-18) 
2. From an unprivileged account, call `Controller::supply(caller, 0, spoke_id, [(HubAssetKey { hub_id, asset }, amount)])` with a one-billion-whole-token raw amount, creating the market liquidity. [20](#0-19) 
3. Supply adequate collateral and call `Controller::borrow(caller, account_id, [(HubAssetKey { hub_id, asset }, debt)], None)` at approximately 98% utilization. [21](#0-20) 
4. Advance ledger time until `borrowed * borrow_index` exceeds the `i128` domain, then call the market’s `update_indexes` path. [22](#0-21) 
5. The call returns `MathOverflow`; subsequent `withdraw` and `repay` calls also return `MathOverflow`, demonstrating that the market cannot resume normal operation. [23](#0-22)

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:

    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);

        }

    assert_contract_error(failed, errors::MATH_OVERFLOW);

    assert!(

/// when the power of ten overflows `i128`; every `|a|` is then below that power. Returns `a`
/// unchanged when the decimal counts are equal. Panics with `GenericError::MathOverflow` if the
/// upscaling factor or the upscaled value overflows `i128`.
fn rescale(
    env: &Env,
    a: i128,
    from_decimals: u32,
    to_decimals: u32,
    round_down: impl Fn(i128, Option<i128>) -> i128,
) -> i128 {
    if from_decimals == to_decimals {
        return a;
    }
    let factor = 10i128.checked_pow(to_decimals.abs_diff(from_decimals));

    if to_decimals > from_decimals {
        factor
            .and_then(|factor| a.checked_mul(factor))
            .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
    } else {
        round_down(a, factor)
    }
}

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Socializes `bad_debt` by reducing the supply index (capped at total supply value).
///
/// Used when seizing unpaid debt: remaining supplier claims shrink pro-rata.
/// No-op when total supplied value is zero. Floors the resulting index at
/// [`SUPPLY_INDEX_FLOOR_RAW`] to avoid a zero index.
pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}

/// Mints scaled debt for `amount` of underlying and enforces max utilization.
///
/// Requires positive amount, sufficient cash reserves, and that the draw
/// leaves the liquidation buffer intact. Panics if the scaled mint rounds to
/// zero shares.
pub(crate) fn mint_debt(env: &Env, cache: &mut Cache, position: &mut Ray, amount: i128) {
    require_positive_amount(env, amount);
    cache.require_reserves(amount);
    guards::require_liquidation_buffer(env, cache, amount);

    let minted = cache.calculate_scaled_borrow(amount);

    assert_with_error!(
        env,
        minted.raw() > 0,
        GenericError::BorrowRoundsToZeroShares
    );

    *position = position.checked_add(env, minted);
    cache.mint_debt(minted);
    guards::require_utilization_below_max(env, cache);
}
