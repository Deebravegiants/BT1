### Title
Large-market accrual overflows `i128` before the borrow-index cap and permanently freezes a pool - (File: contracts/pool/src/interest.rs)

### Summary
A sufficiently large market can enter a state where every subsequent state-changing operation touching that market panics during interest accrual. `global_sync` computes utilization by unscaling the aggregate borrow and supply books before applying the new indexes; when either aggregate’s RAY value exceeds `i128::MAX`, the transaction reverts. Because withdrawal, repayment, borrowing, liquidation, and index synchronization all synchronize the market first, the overflow permanently freezes supplier funds and prevents borrowers or liquidators from operating on the market. [1](#0-0) [2](#0-1) 

### Finding Description
`global_sync` advances every accrued market through `accrue_chunk`. [3](#0-2)  During accrual, `Cache::calculate_utilization` calls `scaled_to_original` independently on `borrowed * borrow_index` and `supplied * supply_index`. [2](#0-1)  These products are evaluated before `accrue_step` can return a capped borrow index. [4](#0-3) 

An unprivileged user can create the vulnerable book through ordinary market operations: supply the vulnerable market with `supply`, establish high utilization with `borrow`, advance ledger time, and then call `update_indexes(caller, vec![hub_asset])`. After the first revert, subsequent calls to `update_indexes`, `withdraw`, `repay`, `borrow`, `liquidate`, or any other path that synchronizes the same market hit the same overflowing utilization calculation. The permissionless entrypoint itself is `update_indexes`, whose exact arguments are `caller` and `assets`. [5](#0-4) 

The harness has a concrete reproduction: an 18-decimal market holding one billion whole tokens at 98% utilization crosses the aggregate-value ceiling while the stored borrow index remains below `MAX_BORROW_INDEX_RAY`, so the intended index cap never protects it. [6](#0-5) 

### Impact Explanation
This causes permanent freezing of funds for the affected market. The reproduction confirms that after the overflow, both a one-unit supplier withdrawal and a borrower repayment fail with `MATH_OVERFLOW`; the same precondition also blocks liquidation because the market must accrue before its debt can be resolved. Suppliers cannot exit, borrowers cannot repay, liquidators cannot reduce risk, and the market cannot resume operation through an in-band recovery path. [7](#0-6) 

### Likelihood Explanation
The attack requires a very large raw book, sustained high utilization, and enough collateral for the borrow position; the demonstrated setup uses one billion whole tokens and lifted market caps. Those requirements make opportunistic triggering economically difficult, but the state is reachable through normal supply and borrow operations rather than privileged arithmetic, malformed arguments, or off-chain behavior. Once the aggregate RAY value exceeds `i128::MAX`, ordinary passage of ledger time and one permissionless `update_indexes` call turns the condition into a persistent denial of market operations. [8](#0-7) 

### Recommendation
Do not compute aggregate utilization through an unchecked `scaled * index` product when the result can exceed `i128`. Clamp or saturate utilization before unscale conversion when either scaled aggregate is large enough for the product to overflow, and ensure `accrue_step` applies the configured index ceiling before deriving aggregate token values. A checked utilization path should preserve conservative behavior—prefer saturation at maximum utilization or a capped index over reverting—so a large historical book remains repayable, withdrawable, and liquidatable. Regression coverage should assert that the demonstrated one-billion-token, 98%-utilization market remains operable after reaching the intended borrow-index ceiling. [2](#0-1) [4](#0-3) 

### Proof of Concept
The existing test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` demonstrates the sequence:

1. Configure an 18-decimal `BIG18` market and a collateral market, then lift their caps. [9](#0-8) 
2. Supply `1_000_000_000 * 10^18` base units of `BIG18` and borrow 98% of it against a large collateral position. [10](#0-9) 
3. Advance time and repeatedly call `update_indexes` for `BIG18` until the call returns `MATH_OVERFLOW`. [11](#0-10) 
4. Observe that the stored `borrow_index` remains below `MAX_BORROW_INDEX_RAY`, meaning the cap did not prevent the overflow. [12](#0-11) 
5. Attempt `withdraw` and `repay`; both fail with `MATH_OVERFLOW`, proving that user funds remain frozen after the synchronization failure. [13](#0-12)

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```

```rust
/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
