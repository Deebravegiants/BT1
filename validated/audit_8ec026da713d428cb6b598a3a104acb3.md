The analog is confirmed: NEAR's meta-transaction (NEP-366) signing scheme for `DelegateAction`/`DelegateActionV2` has the same structural flaw as the reported `ERC20Permit` bug — the signed payload has no binding to a specific chain instance, only a fixed protocol-wide discriminant.

### Title
Meta-transaction (`DelegateAction`) signatures lack chain-binding data, enabling cross-chain replay after a fork or genesis-state clone - (File: `core/primitives/src/action/delegate.rs`, `core/primitives/src/signable_message.rs`)

### Summary
`SignedDelegateAction`/`VersionedSignedDelegateAction` (NEP-366 meta-transactions) are signed off-chain by a user and later submitted on-chain by an untrusted relayer inside a `Transaction`'s `Action::Delegate`/`Action::DelegateV2`. The bytes that get hashed and signed contain no chain-specific identifier (no genesis hash, no chain id, no recent `block_hash`), only `sender_id`, `receiver_id`, `actions`, `nonce`, `max_block_height`, `public_key`, and a fixed global `MessageDiscriminant`. This mirrors the `ERC20Permit` chainID omission: if two NEAR-based chains ever share account/access-key state (a contentious hard fork, or any deployment that clones NEAR genesis/state such as a testnet reset, canary network, or appchain bootstrapped from a mainnet state dump), a signature intended for use on one chain remains valid and can be replayed by the relayer on the other chain.

### Finding Description
`DelegateAction::get_nep461_hash` / `VersionedDelegateActionPayload::get_nep461_hash` compute the signed hash as `hash(borsh(SignableMessage{discriminant, msg}))` where `msg` is the `DelegateAction`/`DelegateActionV2` struct itself: [1](#0-0) 
The struct fields signed are only `sender_id`, `receiver_id`, `actions`, `nonce`, `max_block_height`, `public_key`: [2](#0-1) 
The `MessageDiscriminant` used to domain-separate this signature scheme is a static, protocol-wide constant derived only from the NEP number (366 or 611), identical on every NEAR-based network: [3](#0-2) 
Unlike ordinary `Transaction`s, which embed a recent `block_hash` that expires after `transaction_validity_period` blocks and is thus chain-specific and short-lived, `DelegateAction` only carries `max_block_height`, an absolute height ceiling with no chain-identity binding at all: [4](#0-3) 
On execution, `validate_delegate_action_key` only checks the access key's existence, nonce ordering, and height bound — it never checks anything tying the signature to a particular chain instance: [5](#0-4) 

This is structurally the same class of bug as the reported `ERC20Permit` issue: a signature authorizing a state-changing action omits any chain-identity component, so its validity is not scoped to a single chain.

### Impact Explanation
If two NEAR-protocol chains ever come to share the same access-key/nonce state for an account — e.g., after a network hard fork/chain split, or when a new NEAR-based network (testnet reset, canary/guild network, app-specific chain) is bootstrapped from a copy of mainnet/testnet genesis or state — a `SignedDelegateAction` a user signed intending it to run only on chain A can be resubmitted verbatim by the relayer (or anyone who intercepts it, since delegate actions are unprivileged, relayer-submitted payloads) on chain B as long as the access key nonce on B hasn't advanced past the signed nonce and `max_block_height` hasn't been exceeded there. This allows unauthorized re-execution of the exact same delegated action (e.g., a token transfer/approval-style action) on the sibling chain, i.e. unauthorized state/balance change without a corresponding second authorization from the signer.

### Likelihood Explanation
This requires a chain-split or state-cloning event to create two chains with initially identical account/access-key state, which is not a routine operation. However, this is a low-difficulty issue matching the original report's severity (labeled "Difficulty: Low"): once such an event occurs, exploitation requires no privileged access — any relayer or observer holding a previously-signed `SignedDelegateAction` can immediately replay it cross-chain, since `validate_delegate_action_key` performs no chain-scoping check.

### Recommendation
Include a chain-identifying value (e.g., the genesis hash or a protocol-defined chain id) as part of the `DelegateAction`/`DelegateActionV2` struct that is signed and hashed, and validate it against the executing chain's genesis hash inside `validate_delegate_action_key` (`runtime/runtime/src/actions.rs`) before accepting the action. This closes the replay vector the same way EIP-2612 was patched by embedding `chainID` in the `permit` typed-data hash.

### Proof of Concept
1. Chain A (e.g., mainnet) and Chain B (e.g., a state-cloned/forked network) start with identical account state, including access key `nonce` for `alice.near`'s key.
2. Alice signs a `DelegateAction{sender_id: alice.near, receiver_id: ft_contract, actions: [approve/transfer-style action], nonce: N, max_block_height: H, public_key: pk}` intending it for chain A, per `DelegateAction::get_nep461_hash`: [6](#0-5) 
3. A relayer submits it on chain A inside a `Transaction` with `Action::Delegate(...)`; `validate_delegate_action_key` accepts it since nonce/height checks pass, and the action executes.
4. The same relayer (or any third party who obtained the signed payload) submits the identical `SignedDelegateAction` bytes on chain B. Because chain B's genesis/state clone gives `alice.near`'s access key the same starting nonce, and nothing in the signed hash differs between chains, `validate_delegate_action_key` on chain B also accepts it and re-executes the same action — moving/approving Alice's tokens a second time without her consent.

impl TryFrom<MessageDiscriminant> for SignableMessageType {
    type Error = ReadDiscriminantError;

    fn try_from(discriminant: MessageDiscriminant) -> Result<Self, Self::Error> {
        if discriminant.is_transaction() {
            Err(Self::Error::TransactionFound)
        } else if let Some(nep) = discriminant.on_chain_nep() {
            match nep {
                NEP_366_META_TRANSACTIONS => Ok(Self::DelegateAction),
                NEP_611_GAS_KEYS => Ok(Self::DelegateActionV2),
                _ => Err(Self::Error::UnknownOnChainNep(nep)),
            }
        } else if let Some(nep) = discriminant.off_chain_nep() {
            Err(Self::Error::UnknownOffChainNep(nep))
        } else {
            Err(Self::Error::UnknownMessageType)
        }
    }
}

impl From<SignableMessageType> for MessageDiscriminant {
    fn from(ty: SignableMessageType) -> Self {
        // unwrapping here is ok, we know the constant NEP numbers used are in range
        match ty {
            SignableMessageType::DelegateAction => {
                MessageDiscriminant::new_on_chain(NEP_366_META_TRANSACTIONS).unwrap()
            }
            SignableMessageType::DelegateActionV2 => {
                MessageDiscriminant::new_on_chain(NEP_611_GAS_KEYS).unwrap()
            }
        }
    }
}

/// Validate access key which was used for signing DelegateAction:
///
/// - Checks whether the access key is present fo given public_key and sender_id.
/// - Validates nonce and updates it if it's ok.
/// - Validates access key permissions.
fn validate_delegate_action_key(
    state_update: &mut TrieUpdate,
    apply_state: &ApplyState,
    delegate_action: VersionedDelegateActionRef<'_>,
    result: &mut ActionResult,
) -> Result<(), RuntimeError> {
    let sender_id = delegate_action.sender_id();
    let public_key = delegate_action.public_key();
    // 'sender_id' account existence must be checked by a caller
    let mut access_key = match get_access_key(state_update, sender_id, public_key)? {
        Some(access_key) => access_key,
        None => {
            result.result = Err(ActionErrorKind::DelegateActionAccessKeyError(
                InvalidAccessKeyError::AccessKeyNotFound {
                    account_id: sender_id.clone(),
                    public_key: public_key.clone().into(),
                },
            )
            .into());
            return Ok(());
        }
    };

    // A plain nonce advances the single access_key.nonce and forbids gas keys;
    // a gas key nonce advances one of the gas key's nonces selected by
    // nonce_index.
    let delegate_nonce = delegate_action.nonce();
    let (current_nonce, nonce_update) = match delegate_nonce {
        TransactionNonce::Nonce { .. } => {
            if access_key.gas_key_info().is_some() {
                result.result = Err(ActionErrorKind::DelegateActionAccessKeyError(
                    InvalidAccessKeyError::DelegateActionRequiresNonGasKey,
                )
                .into());
                return Ok(());
            }
            (access_key.nonce, DelegateNonceUpdate::AccessKey)
        }
        TransactionNonce::GasKeyNonce { nonce_index, .. } => {
            let Some(gas_key_info) = access_key.gas_key_info() else {
                result.result = Err(ActionErrorKind::DelegateActionAccessKeyError(
                    InvalidAccessKeyError::DelegateActionRequiresGasKey,
                )
                .into());
                return Ok(());
            };
            if nonce_index >= gas_key_info.num_nonces {
                result.result = Err(ActionErrorKind::DelegateActionInvalidNonceIndex {
                    nonce_index,
                    num_nonces: gas_key_info.num_nonces,
                }
                .into());
                return Ok(());
            }
            // The index is range-checked above and gas keys initialize every
            // nonce row at creation, so a missing row is inconsistent state.
            let current_nonce =
                get_gas_key_nonce(state_update, sender_id, public_key, nonce_index)?.ok_or_else(
                    || {
                        StorageError::StorageInconsistentState(format!(
                            "gas key nonce row missing for {} {} at in-range index {nonce_index} (num_nonces {})",
                            sender_id, public_key, gas_key_info.num_nonces,
                        ))
                    },
                )?;
            (current_nonce, DelegateNonceUpdate::GasKey { nonce_index })
        }
    };

    if delegate_nonce.nonce() <= current_nonce {
        result.result = Err(ActionErrorKind::DelegateActionInvalidNonce {
            delegate_nonce: delegate_nonce.nonce(),
            ak_nonce: current_nonce,
        }
        .into());
        return Ok(());
    }

    let upper_bound = apply_state.block_height
        * near_primitives::account::AccessKey::ACCESS_KEY_NONCE_RANGE_MULTIPLIER;
    if delegate_nonce.nonce() >= upper_bound {
        result.result = Err(ActionErrorKind::DelegateActionNonceTooLarge {
            delegate_nonce: delegate_nonce.nonce(),
            upper_bound,
        }
        .into());
        return Ok(());
    }
