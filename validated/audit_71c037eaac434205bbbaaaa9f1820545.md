### Title
Phantom bid weighting via a spot `balanceOf`/Uniswap V4 spot-price read lets a solver flash-inflate its median-setting weight - (File: `sdk/packages/sdk/src/protocols/intents/phantom-aggregation.ts`)

### Summary
`aggregatePhantomBids` prices every phantom-order leg by taking a `weightedMedian` of solver quotes, where each quote's weight is the solver's **spot** balance of the leg's output token (`getTotalSolverBalance`/`memoizedSolverBalance`, an `eth_call` `balanceOf`/`maxWithdraw` at `blockTag = "latest"`) plus the withdrawable amount of any declared Uniswap V4 position, itself valued from the pool's live `sqrtPriceX96`/`liquidity` (`readV4Position`, `positionAmountOfToken`). This is structurally identical to the yAxis finding: a governance/weight-determining quantity is read directly off manipulable, single-block on-chain state (a token balance and a Uniswap pool's instantaneous reserves/price) rather than a time-weighted or otherwise-hardened source.

### Finding Description
`getTotalSolverBalance` computes weight as a raw `balanceOf` call plus ERC-4626 `maxWithdraw`, read at the chain head: [1](#0-0) 

`readV4Position` additionally reads the pool's current `sqrtPriceX96` and the position's `liquidity` at `blockTag = "latest"`, which are then converted into a token amount via `positionAmountOfToken`: [2](#0-1) [3](#0-2) 

These per-leg weights feed a `weightedMedian` that is explicitly documented as a **selection, not a blend** — a solver holding over half the leg's weight sets the published price verbatim: [4](#0-3) 

The published median then flows directly into on-chain pool rates consumed for future order pricing: [5](#0-4) 

Because both inputs (`balanceOf`/`maxWithdraw` and the Uniswap V4 pool's `sqrtPriceX96`/`liquidity`) are read at a single block/`latest` tag rather than time-averaged or otherwise resistant to atomic manipulation, an attacker who is (or controls) a solver can, within one transaction/bundle prior to the snapshot's `eth_call`s: (a) transiently inflate its own ERC-20/vault balance (e.g. via a flash loan or a same-block token transfer-and-return before the read), or (b) move a Uniswap V4 pool's price/liquidity so that `positionAmountOfToken` reports an inflated withdrawable amount for a position it declares. Either manipulation increases that solver's `weight` past 50% of the leg's total weight, letting it single-handedly dictate `weightedMedian`'s output — the leg's `medianPrice` — exactly the "voting power manipulation via reserves" pattern in the yAxis report, just applied to a price-setting weight instead of a governance vote.

### Impact Explanation
The manipulated median becomes `PhantomOrderPriceSnapshotV2` (`medianPrice = lowestPrice = highestPrice`) and is renormalized into `PoolChainLiquidity`/pool `sellRate`/`buyRate` via `weightedRate`, i.e., it becomes the quoted rate other users' real intents/orders are filled against. An attacker who inflates weight to control the median can publish an arbitrarily favorable (or unfavorable, to competitors) rate for a token pair, causing mispriced fills — a form of unbacked/mispriced value transfer in the intents settlement path, reachable by any address that can submit a phantom bid.

### Likelihood Explanation
Likelihood is bounded by the difficulty of atomically manipulating a balance or a specific Uniswap V4 pool's price/liquidity within the block the RPC read lands on — feasible via flash loans or self-controlled liquidity moves against thinly-liquid pools, similar to the original yAxis scenario, but requiring the attacker to also control (or collude with) a delegated/verified solver account, since `isVerifiedSolverBid` restricts counted bids to signed solver bids. This constrains but does not eliminate the attack: a compromised or malicious-but-otherwise-legitimate solver, or one that also controls capital to move a target pool momentarily, can execute it without any privileged/admin access.

### Recommendation
Do not weight legs by a single-block spot balance or a single-block Uniswap V4 `sqrtPriceX96`/`liquidity` read. Use a TWAP-style or multi-block average for both the balance snapshot (e.g., require balance to persist across N blocks or use a checkpointed balance) and the pool price/liquidity used in `positionAmountOfToken`, or cap/discount weight contributed by any single Uniswap V4 position analogous to the existing `UNISWAP_QUOTE_HAIRCUT_BPS` price haircut, so a single atomic manipulation cannot push one bidder past the 50% threshold that lets `weightedMedian` select its price verbatim.

### Proof of Concept
1. Attacker controls (or compromises) a delegated solver account able to submit phantom bids.
2. Prior to the phantom bid window closing, attacker either (a) flash-loans/transfers a large balance of the leg's output token into the solver's wallet for the duration of the block the indexer's `eth_call getBalance`/`getTotalSolverBalance` reads at `blockTag="latest"`, or (b) executes a large swap against a thin Uniswap V4 pool backing a declared position to shift `sqrtPriceX96` right before `readV4Position`'s `getSlot0` read, inflating `positionAmountOfToken`'s output.
3. The solver's bid weight (`weights` computed in `runAggregation`, `phantom-aggregation.ts:1479-1497`) now exceeds 50% of the leg's total weight.
4. `weightedMedian` selects the attacker's quoted `price` verbatim as `medianPrice`, which is written into `PhantomOrderPriceSnapshotV2` and propagated into `PoolChainLiquidity`/pool rates used to price subsequent real orders.
5. Attacker reverses the balance/pool manipulation after the read (return the flash loan, or unwind the swap), suffering only the swap fee/flash loan fee, while having durably mispriced the pool for other users.

export async function getTotalSolverBalance(
	evmRpcUrl: string,
	chain: string,
	token: string,
	solver: string,
	yieldVaults: YieldVaultMap,
	blockTag = "latest",
): Promise<bigint> {
	const padded = solver.replace("0x", "").padStart(64, "0")
	const raw = await ethCallUint(evmRpcUrl, token, `0x70a08231${padded}`, blockTag) // balanceOf(address)
	const vaults = yieldVaults[chain]?.[token.toLowerCase()] ?? []
	const vaultBalances = await Promise.all(
		vaults.map((v) => ethCallUint(evmRpcUrl, v, `0xce96cb77${padded}`, blockTag)), // maxWithdraw(address)
	)
	return vaultBalances.reduce((acc, b) => acc + b, raw)
}
