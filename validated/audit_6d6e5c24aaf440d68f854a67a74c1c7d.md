### Title
`finalizeGraduation` can permanently revert when `tokensForLP` rounds to zero, stranding curve-raised LT and burning the LP allotment with no recovery path - ([File: packages/contracts/src/Bonding.sol])

### Summary
`Bonding._prepareGraduationLiquidity` computes `tokensForLP = (ltFromPair * tokenReserve) / assetReserve` with no floor check, and `Bonding._enterGraduating` (Phase 1) irreversibly drains `ltFromPair` via `Router.graduate` and burns `lpBurned = LP_RESERVE - tokensForLP` before Phase 2 ever runs. If `tokensForLP` rounds down to `0`, the later `finalizeGraduation` (Phase 2) call is guaranteed to revert on every attempt — via `IUniswapV2Pair.mint`'s underflow on a zero-amount first mint, a division-by-zero panic in the hostile-pre-seed rebalance math, or `LPLock.recordLock`'s explicit `ZeroAmount()` guard — leaving the token permanently stuck in `Lifecycle.Graduating` with its raised LT and burned LP allotment unrecoverable. This mirrors the reported Curve `emergencyExit` class: a downstream external-call revert defeats a supposedly-mandatory, lock-completing function, and by the time the revert is discovered, the irreversible preparatory state changes have already happened.

### Finding Description
Phase 1 (`_enterGraduating` → `_prepareGraduationLiquidity`) is inline in the threshold-crossing buy or in permissionless `triggerGraduation`, and does the following irreversibly: [1](#0-0) 

Note there is no check that `tokensForLP > 0` or `ltFromPair > 0` before draining the curve and burning `lpBurned`.

`finalizeGraduation` (Phase 2, permissionless) then consumes the cached `(tokensForLP, ltFromPair)` verbatim: [2](#0-1) 

If `tokensForLP == 0`:
- On a virgin pair (the ~99% "regime 1" path), `_seedDirectMint` transfers `0` of the token and `ltFromPair` of LT to the pair, then calls `pair.mint(lpLock)`. UniswapV2's first-mint formula is `sqrt(amount0*amount1) - MINIMUM_LIQUIDITY`; with `amount0 == 0` this reverts (`INSUFFICIENT_LIQUIDITY_MINTED`). [3](#0-2) 
- On a pre-seeded pair (regime 3), the rebalance target ratio is `targetN/targetD = ltFromPair/tokensForLP`, i.e. division by the now-zero `tokensForLP` inside `_pairRebalance`/`_noFeeSwapInput`, producing a panic revert. [4](#0-3) 
- Even in the code's own documented fallback shape (extreme pre-seed exhausting one side of the swap budget), `liquidity` resolves to `0` and is passed straight into `LPLock.recordLock`, which explicitly reverts on a zero amount rather than "recording a zero-sized lock" as the surrounding comment assumes: [5](#0-4) [6](#0-5) 

Because every one of these paths reverts deterministically on the *same* cached `(tokensForLP, ltFromPair)`, retrying `finalizeGraduation` (by the keeper or by "anyone" per its permissionless design) can never succeed. There is no code path to re-enter `Lifecycle.Curve` (`triggerGraduation` requires `Lifecycle.Curve`) and `Bonding.sell`/`Zap.sell` both revert for a non-`Curve` token, so holders cannot exit either. The token's raised LT (`ltFromPair`, already moved into `Bonding` by `Router.graduate` in Phase 1) and the burned portion of `LP_RESERVE` are permanently inert.

### Impact Explanation
This is a permanent freeze of protocol/curve funds for the affected token: the LT raised by the bonding curve is parked in `Bonding` forever (no rescue path — `Bonding` has no sweep function analogous to `_sweepLTToOwner` for the graduation's own earmark, and `protectedLT`/sweep logic is designed to protect *other* graduations, not recover a stuck one's own funds), the burned `LP_RESERVE` tokens are gone, and the token can never reach `Lifecycle.Graduated` nor return to `Lifecycle.Curve` to let holders sell. This satisfies the "permanent freezing of trader/creator/LP funds" bar.

### Likelihood Explanation
`tokensForLP` rounding to `0` requires `ltFromPair` to be extremely small relative to `assetReserve` (which is dominated by the launch-time `virtualLtReserve`) while still satisfying the $9K USD graduation threshold — i.e. a curve paired against an LT with an anomalously high `exchangeRate()` relative to its own launch-time rate. `Bonding.launch`/`Zap.createToken` place no constraint on which BounceTech LT a creator pairs with, and BounceTech LTs are leveraged tokens whose `exchangeRate()` can appreciate arbitrarily over time; a creator can freely choose to launch against an already heavily-appreciated LT. This makes the condition creator-selectable rather than requiring active price manipulation, though it depends on picking (or waiting for) an LT with a sufficiently extreme rate — a real but narrower attack surface, consistent with the Medium severity rating given to the analogous Curve report.

### Recommendation
Add an explicit floor check in `_prepareGraduationLiquidity` (or immediately after, in `_enterGraduating`) that reverts *before* draining `ltFromPair` / burning `lpBurned` if `tokensForLP == 0` (or falls below some minimum liquidity threshold), so the irreversible Phase-1 side effects never commit for a graduation that Phase 2 cannot complete. Alternatively, guarantee a non-zero floor by rounding `tokensForLP` up instead of down when `ltFromPair > 0`, and add a defensive `require(liquidity > 0)` with a clear custom error ahead of `LPLock.recordLock` in `finalizeGraduation` so any future zero-liquidity path fails loudly at Phase 1 rather than bricking Phase 2 after the fact.

### Proof of Concept
1. Creator calls `Zap.createToken` pairing a new token with a BounceTech LT that already has an extremely high `exchangeRate()` (e.g., a heavily-appreciated leveraged token), seeding with the minimum `$20` per `Zap.MIN_SEED_USDC`.
2. Because `exchangeRate()` is high, the `$20` seed converts to a tiny LT amount (`baseToLtAmount`), yet is enough for `realLtRaised * exchangeRate / 1e18 >= graduationThresholdUsd` to hold immediately — `canGraduate` returns `true` on the very first buy, firing `_enterGraduating` inline.
3. `_prepareGraduationLiquidity` computes `tokensForLP = (ltFromPair * tokenReserve) / assetReserve`, which rounds to `0` because `ltFromPair` is minuscule relative to the launch-time `virtualLtReserve` baked into `assetReserve`. Phase 1 burns `lpBurned = LP_RESERVE` and drains the tiny `ltFromPair` via `Router.graduate`.
4. Anyone calls `Bonding.finalizeGraduation(tokenAddress)`. It reverts (via `pair.mint`'s `INSUFFICIENT_LIQUIDITY_MINTED` underflow on the empty-pair path, or a division-by-zero panic / `LPLock.recordLock`'s `ZeroAmount()` on a pre-seeded pair) every time it is called, for anyone who calls it.

    function finalizeGraduation(
        address tokenAddress
    ) external nonReentrant {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[tokenAddress];
        if (info.lifecycle != Lifecycle.Graduating) revert NotGraduating();

        address lt = info.ltAddress;
        PendingGraduation memory p = $.pendingGraduation[tokenAddress];

        // Anything in this contract beyond `p.ltFromPair` belongs to a
        // concurrent graduation on the same LT (Phase 1 transferred it
        // via `Router.graduate`) or to stray dust. Either way it is
        // off-limits to this graduation's deposit and sweep — see
        // `_routerDepositAndDispose` and `_sweepLTToOwner`.
        // Saturating subtract: a balance below `p.ltFromPair` shouldn't
        // be reachable in normal operation, but we keep finalize from
        // bricking on a Panic if any future code path or non-canonical
        // LT briefly violates the invariant.
        uint256 ltBalance = IERC20(lt).balanceOf(address(this));
        uint256 protectedLT = ltBalance > p.ltFromPair ? ltBalance - p.ltFromPair : 0;

        address lpPair = _ensureUniswapV2Pair(tokenAddress, lt);
        uint256 liquidity = _seedUniswapV2Direct(tokenAddress, lt, lpPair, p.tokensForLP, p.ltFromPair, protectedLT);

        _sweepLTToOwner(lt, protectedLT);

        info.lifecycle = Lifecycle.Graduated;
        $.graduatedPair[tokenAddress] = lpPair;
        delete $.pendingGraduation[tokenAddress];

        LPLock($.lpLock).recordLock(tokenAddress, lpPair, liquidity);

        emit TokenGraduated(tokenAddress, lpPair, liquidity, p.tokensForLP, p.lpBurned, p.unsoldBurned);

    function recordLock(
        address token,
        address lpPair,
        uint256 amount
    ) external {
        LPLockStorage storage $ = _s();
        if (!$.isLocker[msg.sender]) revert NotAuthorized();
        if (lpPair == address(0)) revert ZeroAddress();
        if (amount == 0) revert ZeroAmount();
        // `lockedAt` is the one-shot sentinel: it is always set to a non-zero
        // timestamp on the first lock, so the guard holds for any `amount`.
        if ($.locks[token].lockedAt != 0) revert AlreadyLocked();
        if (IERC20(lpPair).balanceOf(address(this)) < amount) revert InsufficientLPBalance();
        $.locks[token] = LockInfo({lpPair: lpPair, amount: amount, lockedAt: block.timestamp});
        emit LPLocked(token, lpPair, amount);
    }
