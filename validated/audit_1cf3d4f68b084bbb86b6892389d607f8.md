Audit Report

## Title
`EngineMeter::charge_ref_time` never actually deducts fuel, allowing a contract to run extra Wasm instructions beyond its charged gas — (File: `substrate/frame/contracts/src/gas.rs`)

## Summary
`EngineMeter::charge_ref_time` computes `amount` to subtract from `self.fuel` but only uses `checked_sub`'s result to detect underflow via `.ok_or_else(...)?`, discarding the `Some(value)` and never assigning it back to `self.fuel`. This means `self.fuel` is never actually decremented after a chargeable host-function call, and the stale, pre-call fuel value is returned as `Syncable` and written into wasmi's real fuel counter via `__caller__.set_fuel(fuel)`, restoring headroom that should have been consumed.

## Finding Description
The code at [1](#0-0)  confirms the exact defect described in the claim:

```rust
fn charge_ref_time(&mut self, ref_time: u64) -> Result<Syncable, DispatchError> {
    let amount = ref_time
        .checked_div(T::Schedule::get().ref_time_by_fuel())
        .ok_or(Error::<T>::InvalidSchedule)?;

    self.fuel.checked_sub(amount).ok_or_else(|| Error::<T>::OutOfGas)?;
    Ok(Syncable(self.fuel))
}
```

The result of `checked_sub` is dropped, so `self.fuel` retains its pre-call value while `Syncable(self.fuel)` returns that stale (larger) value. This is invoked from `GasMeter::sync_to_executor` at [2](#0-1) , which is called by the proc-macro-generated `sync_gas_after` block that writes the returned fuel straight into wasmi via `__caller__.set_fuel(fuel)` on every host function exit, as shown in `substrate/frame/contracts/proc-macro/src/lib.rs` lines 732–748 cited in the claim. Because `GasMeter::gas_left` is correctly decremented elsewhere via `charge()` at [3](#0-2) , the pallet's own weight ledger stays consistent and will eventually detect `OutOfGas`, but wasmi's independent fuel counter — which is what actually halts pure Wasm instruction execution — is repeatedly topped back up by the host-function cost that should have been deducted, exactly as claimed.

This is a genuine logic bug reachable by any contract making ordinary calls to chargeable host functions; no privileged path, governance, or victim mistake is required.

## Impact Explanation
Each chargeable host-function call fails to deduct its own weight cost from wasmi's separate fuel counter, letting an attacker-authored contract accumulate un-deducted fuel across many host-function calls and then spend that slack executing additional real Wasm instructions before `gas_left` catches up and the call aborts with `OutOfGas`. This is a concrete metering-bypass in the SDK's own gas-accounting code (not a node/peer issue), permissionlessly triggerable by any contract, matching the claimed impact of running extra Wasm execution beyond the charged gas limit.

## Likelihood Explanation
Fully deterministic and attacker-controlled: any contract calling chargeable host functions (essentially all non-trivial contracts) hits this code path on every host-function exit via `sync_to_executor`/`charge_ref_time`. The magnitude of the discrepancy scales linearly with the number of host-function calls the attacker chooses to make, which is entirely within contract author's control.

## Recommendation
Assign the decremented value back to `self.fuel`:
```rust
self.fuel = self.fuel.checked_sub(amount).ok_or_else(|| Error::<T>::OutOfGas)?;
Ok(Syncable(self.fuel))
```

## Proof of Concept
1. Construct a `GasMeter::<Test>::new(gas_limit)`.
2. Call `sync_from_executor(engine_fuel)` to simulate entering a host function, capturing the returned `RefTimeLeft`.
3. Call `gas_meter.charge(token)` to simulate the host function's own weight cost being deducted from `gas_left`.
4. Call `sync_to_executor(before)` and observe that the returned `Syncable` fuel value equals the pre-call `self.fuel` (unchanged) rather than `self.fuel - ref_time_consumed / ref_time_by_fuel`, confirming wasmi's fuel counter gets over-topped-up on `set_fuel`.
5. At the integration level, a contract fixture that loops calling a cheap chargeable host function N times then busy-loops in pure Wasm will execute strictly more Wasm instructions than `gas_limit / ref_time_by_fuel` should permit before `OutOfGas` is raised.
