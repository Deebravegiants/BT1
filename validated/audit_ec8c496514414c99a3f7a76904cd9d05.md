## Analog Found: Unbounded Memory Allocation from Unauthenticated Header Length Field in BEEFY Consensus Codec

### Title
Unbounded array allocation from unvalidated SCALE-compact length in `Codec.DecodeHeader` before Merkle-proof authentication - (File: `evm/src/consensus/Codec.sol`)

### Summary
`Codec.DecodeHeader` reads a SCALE compact-encoded integer directly off attacker-supplied bytes and immediately uses it to size a dynamic array, with no upper bound check, mirroring the `apply_substitution`/`tar/subst.c` pattern in the JLSEC-2026-153 report where a crafted length field drives an unbounded allocation before any validation of the input's legitimacy. [1](#0-0) 

### Finding Description
`DecodeHeader` decodes the digest count via `ScaleCodec.decodeUintCompact(slice)` and allocates `Digest[] memory digests = new Digest[](length)` with no ceiling on `length` (SCALE compact mode 3 allows values up to `2^64`), and the nested `decodeDigestItem` performs the same unchecked pattern for each digest's data length via `Bytes.read(slice, length)`. [2](#0-1) [3](#0-2) 

Critically, in `EcdsaBeefy.verifyParachainHeaderProof`, `Codec.DecodeHeader(para.header)` is invoked *inside the loop, before* the Merkle multi-proof authenticity check (`MerkleMultiProof.VerifyProof(headsRoot, ...)`) that runs after the loop completes. This means the header bytes are parsed — and the unbounded allocation triggered — before the contract has any cryptographic assurance that `para.header` corresponds to a real, finalized parachain header. [4](#0-3) 

An unprivileged relayer submitting a BEEFY consensus update only needs a legitimately signed relay-chain commitment (public information, not secret) to pass `verifyMmrUpdateProof`; the `ParachainProof.parachains[i].header` bytes it pairs with that commitment are otherwise unconstrained at the point `DecodeHeader` runs. By crafting a `para.header` whose SCALE compact digest-count field encodes a very large value, the relayer forces `new Digest[](length)` to attempt a huge memory allocation, whose EVM memory-expansion gas cost grows quadratically and can be tuned to exhaust the transaction's gas, reverting the call — this is the direct Solidity analog of the OOM crash in `apply_substitution`.

### Impact Explanation
`EcdsaBeefy.verify()`/`SP1Beefy` (which shares the same `Codec.DecodeHeader` path) is the consensus-state-update entry point that the `EvmHost`/`HandlerV2` dispatch pipeline depends on to advance trusted state and admit new state commitments used for message delivery. A relayer able to reliably force out-of-gas reverts on consensus proof submissions can grief/DoS the consensus update path for a given route, preventing new parachain state commitments from being recorded and stalling message delivery through that route — satisfying the "route unable to deliver messages" impact class.

### Likelihood Explanation
Likelihood is Medium: it requires the attacker to obtain a validly signed relay-chain commitment (publicly broadcast, not privileged) and pair it with a crafted `para.header` byte string, both fully within the reach of any address that can call `verify`/dispatch a consensus update — no special privilege, governance, or off-chain compromise needed.

### Recommendation
Bound `length` in `DecodeHeader` and `decodeDigestItem` against the remaining bytes in `slice` (or an explicit maximum digest count/size) before allocating, and/or move the Merkle multi-proof authentication of `para.header` ahead of `Codec.DecodeHeader` in `verifyParachainHeaderProof` so unauthenticated header bytes are never parsed.

### Proof of Concept
1. Capture a legitimately signed BEEFY commitment/MMR proof for the current authority set (public network data).
2. Construct a `ParachainProof` whose `parachains[i].header` begins with 32+32+32 bytes of arbitrary hashes/number, followed by a SCALE compact-encoded digest-count field using mode-3 encoding to represent a very large value (e.g., approaching `2^40`+).
3. Submit this as `proof` to `EcdsaBeefy.verify(previousState, proof)` (or via the on-chain consensus-update dispatch path).
4. Execution reaches `verifyParachainHeaderProof` → `Codec.DecodeHeader(para.header)` → `new Digest[](length)`, which triggers large memory-expansion gas costs before the subsequent `MerkleMultiProof.VerifyProof` call ever executes, reverting via out-of-gas and wasting the relayer/host's expected verification flow regardless of the (never-checked) header authenticity.

        ByteSlice memory slice = ByteSlice(encoded, 0);

        bytes32 extrinsicsRoot = Bytes.toBytes32(Bytes.read(slice, 32));

        uint256 length = ScaleCodec.decodeUintCompact(slice);
        Digest[] memory digests = new Digest[](length);

        for (uint256 i = 0; i < length; i++) {
            uint8 kind = Bytes.readByte(slice);
            Digest memory digest;
            if (kind == DIGEST_ITEM_OTHER) {
                digest.isOther = true;
            } else if (kind == DIGEST_ITEM_CONSENSUS) {

                digest.preruntime = decodeDigestItem(slice);
            } else if (kind == DIGEST_ITEM_RUNTIME_ENVIRONMENT_UPDATED) {
                digest.isRuntimeEnvironmentUpdated = true;
            }

    /// @dev Decodes a SCALE-encoded digest item (4-byte consensus id + length-prefixed data).
    function decodeDigestItem(ByteSlice memory slice) internal pure returns (DigestItem memory) {
        bytes4 id = Bytes.toBytes4(read(slice, 4), 0);
        uint256 length = ScaleCodec.decodeUintCompact(slice);
        bytes memory data = Bytes.read(slice, length);
        return DigestItem(id, data);
    }
