## #Vulnerability found for this question.

### Title
Fee-on-transfer / deflationary tokens break swap and deposit accounting because output/LP amounts are computed from pre-transfer balances with no post-transfer verification - (File: `program/src/processor.rs`)

### Summary
Every unprivileged instruction that moves tokens into the pool's vaults (`process_swap_base_in`, `process_swap_base_out`, `process_swap_base_in_v2`, `process_swap_base_out_v2`, and `process_deposit`) computes the amount to be sent out to the user (or the amount of LP to mint) using vault balances read *before* the inbound transfer, and then blindly invokes `Invokers::token_transfer` with a fixed nominal amount, never re-reading the vault's balance afterward to confirm how much was actually received.

### Finding Description
In all four swap handlers the pool reserves are captured once at the top via `Calculator::calc_total_without_take_pnl_no_orderbook(amm_pc_vault.amount, amm_coin_vault.amount, &amm)` [1](#0-0) . The constant-product output `swap_amount_out` (or, in the base-out case, `swap_in_after_add_fee`) is derived purely from that reserve snapshot and the nominal `swap.amount_in`/`swap.amount_out` supplied by the caller via `Calculator::swap_token_amount_base_in` [2](#0-1) .

The program then performs the inbound transfer with the nominal amount and the outbound transfer with the previously computed amount, with no balance check in between: [3](#0-2) 

The same pattern occurs in `process_deposit`: `deduct_coin_amount`/`deduct_pc_amount` and `mint_lp_amount` are computed from the pre-transfer vault reserves, then `Invokers::token_transfer` moves the nominal `deduct_coin_amount`/`deduct_pc_amount` into the vaults, followed immediately by `Invokers::token_mint_to` minting `mint_lp_amount` LP tokens to the depositor — again without confirming the vaults actually received the nominal amount: [4](#0-3) 

`Invokers::token_transfer` itself is a thin wrapper around `spl_token::instruction::transfer` that has no before/after balance comparison: [5](#0-4) 

Because the AMM does not restrict which SPL mints can be paired in a pool (any two mints can be supplied to `Initialize2`/`process_swap*`/`process_deposit`), an attacker can create or use a pool where `coin_mint` or `pc_mint` is a fee-on-transfer/deflationary/rebasing token. When such a token is transferred, the amount credited to `amm_coin_vault`/`amm_pc_vault` is strictly less than the amount debited from the sender, yet the program's math and subsequent LP mint / counter-asset payout are based on the full nominal amount.

### Impact Explanation
- **Swap path**: `swap_amount_out` is computed assuming the vault receives the full `swap.amount_in` (or `swap_in_after_add_fee`); if the actual transferred-in amount is smaller (fee-on-transfer), the pool pays out `swap_amount_out` — calculated against reserves that were never truly deposited — draining real value from the other side of the pool relative to what was contributed. Repeated over time this permanently drains one side of the vault (real fund loss for LPs/other traders).
- **Deposit path**: `mint_lp_amount` is minted based on `deduct_coin_amount`/`deduct_pc_amount`, the nominal (not actually-received) amounts. If the deposited token has transfer fees, the depositor is credited LP tokens as if a larger amount had been deposited, resulting in unbacked LP minting and diluting/underfunding existing LPs — a form of insolvent pool accounting.

Both cases meet the "concrete theft or permanent freezing of funds / unbacked LP minting / insolvent pool accounting" bar.

### Likelihood Explanation
Reachable by any unprivileged swapper or LP in a single transaction: they only need to interact with (or create) a pool whose coin or pc mint is a fee-on-transfer/deflationary SPL token and call the standard `Swap`/`Deposit` instructions with attacker-controlled amounts. No privileged signer, off-chain component, or non-default build is required — this is a pure instruction-processing logic gap in `program/src/processor.rs`.

### Recommendation
For every token movement into a vault (`user -> amm_coin_vault` / `user -> amm_pc_vault` in swap and deposit), read the vault's SPL token balance immediately before and after invoking `Invokers::token_transfer`, and use `balance_after - balance_before` (the actually received amount) as the authoritative value driving `swap_amount_out` computation, `mint_lp_amount` computation, and any subsequent invariant/liquidity accounting, instead of trusting the caller-supplied nominal amount.

    pub fn swap_token_amount_base_in(
        amount_in: U128,
        total_pc_without_take_pnl: U128,
        total_coin_without_take_pnl: U128,
        swap_direction: SwapDirection,
    ) -> U128 {
        let amount_out;
        match swap_direction {
            SwapDirection::Coin2PC => {
                // (x + delta_x) * (y + delta_y) = x * y
                // (coin + amount_in) * (pc - amount_out) = coin * pc
                // => amount_out = pc - coin * pc / (coin + amount_in)
                // => amount_out = ((pc * coin + pc * amount_in) - coin * pc) / (coin + amount_in)
                // => amount_out =  pc * amount_in / (coin + amount_in)
                let denominator = total_coin_without_take_pnl.checked_add(amount_in).unwrap();
                amount_out = total_pc_without_take_pnl
                    .checked_mul(amount_in)
                    .unwrap()
                    .checked_div(denominator)
                    .unwrap();
            }
            SwapDirection::PC2Coin => {
                // (x + delta_x) * (y + delta_y) = x * y
                // (pc + amount_in) * (coin - amount_out) = coin * pc
                // => amount_out = coin - coin * pc / (pc + amount_in)
                // => amount_out = (coin * pc + coin * amount_in - coin * pc) / (pc + amount_in)
                // => amount_out = coin * amount_in / (pc + amount_in)
                let denominator = total_pc_without_take_pnl.checked_add(amount_in).unwrap();
                amount_out = total_coin_without_take_pnl
                    .checked_mul(amount_in)
                    .unwrap()
                    .checked_div(denominator)
                    .unwrap();
            }
        }
        return amount_out;
    }
