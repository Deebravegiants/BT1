## Title
`Hinkal::prooflessDeposit()` — Overpaid/unclaimed native ETH (`msg.value`) is never refunded or validated, permanently freezing user funds - (File: `contracts/Hinkal.sol`)

### Summary
`prooflessDeposit()` accepts `msg.value` unconditionally as a `payable` function, but the ETH is only pulled into the accounting logic if `address(0)` happens to be present in the caller-supplied `erc20Addresses` array. There is no check anywhere in the function, in `HinkalHelper.performProoflessDepositChecks()`, or in `_handleTransfersFromProoflessDeposit()` that `msg.value` equals the sum of the declared ETH amounts (or equals zero when no ETH entry exists), and there is no refund path for any leftover ETH.

### Finding Description
`prooflessDeposit()` is: [1](#0-0) 

The only place ETH is validated/consumed is `_handleTransfersFromProoflessDeposit()`, which iterates over the *unique tokens present in `erc20Addresses`*: [2](#0-1) 

and the ETH-specific branch of `transferERC20TokenFromOrCheckETH()` only fires — and only checks `msg.value == _value` — when `_contractAddress == address(0)`: [3](#0-2) 

`HinkalHelper.performProoflessDepositChecks()` validates array lengths and that `amounts[i] > 0`, but never validates `msg.value` against the ETH amounts declared, nor rejects a non-zero `msg.value` when no `address(0)` entry is present: [4](#0-3) 

Consequently:
1. If a caller invokes `prooflessDeposit()` with `erc20Addresses` containing **only ERC-20 tokens** (no `address(0)`) but attaches `msg.value > 0`, that ETH is silently accepted into `Hinkal`'s balance, no commitment/UTXO is ever created for it, and it can never be withdrawn by the depositor or anyone else (withdrawals require valid proofs/nullifiers tied to actual UTXOs, none of which exist for this stray ETH).
2. Even when `address(0)` **is** present, if the caller overpays beyond the summed ETH `amounts`, the strict `msg.value == _value` check in `transferERC20TokenFromOrCheckETH` will actually revert the whole call — so in the ETH-present case at least the transaction fails safely; but in the ETH-absent case (path 1) there is no check, no revert, and no refund, so the ETH is silently and permanently lost.
3. The same design gap propagates through `HinkalWrapper.prooflessDeposit()`, which forwards `ethForHinkal = msg.value - feeStructure.feeAmount` to `Hinkal.prooflessDeposit{value: ethForHinkal}(...)` without validating this leftover value against the declared ERC-20/ETH amounts: [5](#0-4) 

This is the direct analog of the referenced Curves finding: value received (`msg.value`) that exceeds what the accounting logic actually consumes is neither validated nor refunded — except here, because `Hinkal` is a shielded-value contract with commitments/nullifiers gating all withdrawals, the unaccounted ETH is not merely a wasted refund opportunity, it becomes **permanently unspendable/frozen** value with no corresponding leaf in the Merkle tree and no nullifier path to ever claim it.

### Impact Explanation
Any ETH sent to `prooflessDeposit()` (directly or via `HinkalWrapper`) that is not matched by an `address(0)` entry in `erc20Addresses`/`amounts` is permanently locked in the `Hinkal` contract with no UTXO/commitment created and no mechanism to withdraw it — this is a **Critical** impact per the rubric ("permanent freezing of user funds"), since the value is moved into the protocol but never counted in any balance/commitment equation and there is no admin/relay-only recovery path referenced in the reachable contracts.

### Likelihood Explanation
This is trivially reachable by any unprivileged EOA calling the public `payable` function `prooflessDeposit()` (or `HinkalWrapper.prooflessDeposit`) with a mismatched `msg.value`/`erc20Addresses` combination — no special privileges, front-running, or relayer collusion required. The only friction is that it typically requires a mistaken/miscalculated client-side call (e.g., wallet UI bug, price movement not accounted for, or leftover fee-calculation error in `HinkalWrapper._settleFee`), matching exactly the class of issue the reference report calls out.

### Recommendation
In `HinkalHelper.performProoflessDepositChecks()` (or directly in `Hinkal.prooflessDeposit()`), require that `msg.value` exactly equals the sum of all `amounts[i]` where `erc20Addresses[i] == address(0)`, and revert otherwise instead of silently accepting a mismatched value. If overpayment must be tolerated, explicitly compute and refund the excess (`msg.value - ethRequired`) to `msg.sender` at the end of `prooflessDeposit()`, analogous to `HinkalWrapper._settleFee`'s fee-only accounting but extended to cover the deposit amount itself.

### Proof of Concept
1. Attacker/user (unprivileged EOA) calls `Hinkal.prooflessDeposit()` directly with:
   - `erc20Addresses = [USDC]`, `amounts = [1000e6]` (a valid ERC-20-only deposit)
   - `msg.value = 1 ether` (arbitrary, mistaken, or miscalculated ETH amount)
2. `performProoflessDepositChecks` passes (only validates array lengths and `amounts[i] > 0`, no `msg.value` check).
3. `_calcTokenChangesForProoflessDeposit` produces `uniqueTokens = [USDC: 1000e6]` — no `address(0)` entry.
4. `_handleTransfersFromProoflessDeposit` loops only over `uniqueTokens` (USDC), pulling `1000e6` USDC from the caller via `transferERC20TokenFromOrCheckETH`; the `address(0)` ETH branch is never entered.
5. The `1 ether` sent as `msg.value` is now part of `address(this).balance` in `Hinkal`, with no commitment, no UTXO, and no nullifier ever created for it.
6. This ETH can never be recovered by the depositor (no shielded balance references it) or by anyone else (withdrawals require a valid ZK proof over an actual UTXO/nullifier set) — the funds are permanently frozen in the contract. [1](#0-0) [2](#0-1) [4](#0-3) [3](#0-2)

    function _handleTransfersFromProoflessDeposit(
        TokenWithAmount[] memory uniqueTokens,
        uint256 uniqueCount
    ) private {
        for (uint256 i = 0; i < uniqueCount; i++) {
            address erc20Address = uniqueTokens[i].erc20Address;
            uint256 amount = uniqueTokens[i].amount;

            uint256 balanceBefore = getERC20OrETHBalance(erc20Address);
            if (erc20Address == address(0)) balanceBefore -= msg.value;

            transferERC20TokenFromOrCheckETH(
                erc20Address,
                msg.sender,
                address(this),
                amount
            );

            uint256 balanceAfter = getERC20OrETHBalance(erc20Address);

            require(
                balanceAfter - balanceBefore == amount,
                "proofless deposit balances must be equal"
            );
        }
    }

        StealthAddressStructure[] calldata stealthAddressStructures,
        bytes[] calldata onChainEncryptedOutputs

            amounts.length == erc20Addresses.length &&
                amounts.length == stealthAddressStructures.length &&
                amounts.length == onChainEncryptedOutputs.length,
            "amounts length must match erc20Addresses, stealthAddressStructures, onChainEncryptedOutputs length"
        );

        require(
            erc20Addresses.length <= MAX_LEAVES_PD,
            "no more than MAX_LEAVES_PD entries allowed"
        );

        for (uint256 i = 0; i < erc20Addresses.length; i++) {
            require(
                onChainEncryptedOutputs[i].length > 0,
                "Missing encrypted output for on-chain commitment"
            );
            require(amounts[i] > 0, "Amount must be greater than zero");
        }
    }

    function prooflessDeposit(
        address[] calldata erc20Addresses,
        uint256[] calldata amounts,
        StealthAddressStructure[] calldata stealthAddressStructures,
        bytes[] calldata onChainEncryptedOutputs,
        bool createBlockedUtxos,
        ProoflessFeeStructure calldata feeStructure,
        string calldata orderId
    ) external payable {
        uint256 ethForHinkal = _settleFee(feeStructure);
        _pullAndApproveDepositTokens(erc20Addresses, amounts);
        IHinkal(hinkal).prooflessDeposit{value: ethForHinkal}(
            erc20Addresses,
            amounts,
            stealthAddressStructures,
            onChainEncryptedOutputs,
            createBlockedUtxos,
            orderId
        );
    }

    function _settleFee(
        ProoflessFeeStructure calldata feeStructure
    ) internal returns (uint256 ethForHinkal) {
        ethForHinkal = msg.value;
        if (feeStructure.feeToken == address(0)) {
            require(
                msg.value >= feeStructure.feeAmount,
                "insufficient ETH for fee"
            );
            ethForHinkal = msg.value - feeStructure.feeAmount;
            if (feeStructure.feeAmount > 0) {
                transferETH(feeStructure.feeRecipient, feeStructure.feeAmount);
            }
        } else if (feeStructure.feeAmount > 0) {
            transferERC20TokenFrom(
                feeStructure.feeToken,
                msg.sender,
                feeStructure.feeRecipient,
                feeStructure.feeAmount
            );
        }
    }
