Based on my investigation, I found a valid analog to the `UniV3OracleImpl` bug class in Hyperbridge's `IntentGatewayV2`/`IntentsBase` protocol fee override logic.

### Title
Governance cannot set a zero-fee destination override — `_destinationProtocolFees[dest] == 0` always falls back to the global `protocolFeeBps`, causing unintended fee deductions from user orders - ([File: evm/src/apps/IntentGatewayV2.sol])

### Summary
`IntentGatewayV2.placeOrder` computes the protocol fee to deduct from a user's order by first reading a destination-specific override from `_destinationProtocolFees`, and falling back to the global default whenever that override is `0`. This is structurally identical to the reported `UniV3OracleImpl._getQuoteAmount` bug: `po.fee == 0` is treated as "unset" rather than as a valid, intentionally-configured zero value, so governance can never actually configure a genuinely fee-free destination.

### Finding Description
In `_updateParams`, governance (via a Hyperbridge `Execute`/`UpdateParams` request) sets per-destination fee overrides in `_destinationProtocolFees[keccak256(chain)]`, with `0` being an entirely valid basis-points value: [1](#0-0) 

At order placement time, `placeOrder` reads this override and unconditionally treats `0` as "not configured," substituting the global `_params.protocolFeeBps`: [2](#0-1) 

This mirrors the audited pattern exactly: `_destinationProtocolFees[destinationHash]` plays the role of `po.fee`/`po.scaledOfferFactor`, and `_params.protocolFeeBps` plays the role of `$defaultFee`. Because storage has no way to distinguish "explicitly set to 0" from "never set," any governance attempt to designate a zero-fee corridor for a specific destination (e.g., a partner chain, a promotional route, or a chain where the protocol intentionally waives fees) silently reverts to charging the global default fee instead.

The Tron variant (`evm/tron/contracts/apps/IntentGatewayV2.sol`) has the identical override-application code at lines 650-660, and presumably the same read-side fallback, so the bug class is present cross-chain. [3](#0-2) 

The test suite documents this as intended "fallback" behavior rather than as a bug, confirming it is the actual shipped semantics, not a hypothetical: [4](#0-3) 

### Impact Explanation
Every user who places an order (`placeOrder`, reachable by any unprivileged account) targeting a destination that governance intended to be fee-free instead has `protocolFeeBps` (the global default, up to just under 10,000 bps / 100%) deducted from their escrowed input tokens via the `DustCollected` event path: [5](#0-4) 

This is an unexpected, unavoidable fee applied to ordinary users' funds — a direct value-loss to depositors that governance had no way to prevent through documented configuration. It does not require a malicious admin; a fully honest, well-intentioned governance action to zero out a destination's fee is silently overridden by the contract logic itself.

### Likelihood Explanation
Likelihood is high whenever governance chooses to configure a `0` bps override for any destination — a normal, foreseeable governance action given that `DestinationFee.destinationFeeBps` is validated only against the upper bound (`< 10_000`) and `0` is never rejected or treated specially: [6](#0-5) 

Any subsequent `placeOrder` call to that destination by any user then reliably incurs the unintended default fee, with no error, warning, or ability to detect the discrepancy on-chain.

### Recommendation
Introduce an explicit "is set" sentinel distinct from a valid `0` fee — e.g., store fees as `feeBps + 1` (shifting the valid range) with a companion "has-override" mapping/bitmap, or use a `mapping(bytes32 => bool)` alongside the fee mapping to record whether a destination override has ever been set, and consult that flag before falling back to `_params.protocolFeeBps`.

### Proof of Concept
1. Governance calls `UpdateParams` with `_params.protocolFeeBps = 100` (1%) and a `DestinationFee` entry for `"ARBITRUM"` with `destinationFeeBps = 0`, intending Arbitrum orders to be fee-free.
2. `_updateParams` stores `_destinationProtocolFees[keccak256("ARBITRUM")] = 0`.
3. A user calls `placeOrder` with `order.destination = "ARBITRUM"` and `order.inputs[0].amount = 1000 USDC`.
4. In `placeOrder`, `protocolFeeBps = _destinationProtocolFees[destinationHash]` reads `0`, and the `if (protocolFeeBps == 0) { protocolFeeBps = _params.protocolFeeBps; }` branch substitutes `100` bps.
5. The user's order is reduced by `1000 USDC * 100 / 10_000 = 10 USDC`, which is emitted via `DustCollected` and effectively retained by the protocol — despite governance's explicit intent to charge `0` for this destination.

    function _updateParams(ParamsUpdate memory update) internal {
        _validateParams(update.params);

        emit ParamsUpdated({previous: _params, current: update.params});
        _params = update.params;

        for (uint256 i; i < update.destinationFees.length;) {
            bytes memory chain = update.destinationFees[i].chain;
            uint256 feeBps = update.destinationFees[i].destinationFeeBps;
            if (feeBps >= 10_000) revert InvalidInput();
            _destinationProtocolFees[keccak256(chain)] = feeBps;

            unchecked {
                ++i;
            }
            emit DestinationProtocolFeeUpdated(string(chain), feeBps);
        }
    }

    function testPlaceOrderDestinationFeeWithFallback() public {
        // Test that when destination fee is not set (or is 0), it falls back to default protocol fee
        IntentGatewayV2 customGateway = _deployGatewayProxy();
        Params memory customParams = Params({
            host: address(host),
            dispatcher: address(dispatcher),
            solverSelection: false,
            surplusShareBps: 10000,
            protocolFeeBps: 100, // 1% default
            priceOracle: address(0)
        });
        customGateway.initialize(customParams, new bytes[](0), address(0));

        // Place order to destination without specific fee set
        uint256 inputAmount = 1000 * 1e6; // 1000 USDC
        uint256 expectedDefaultFee = (inputAmount * 100) / 10000; // 10 USDC (1% default)

        deal(address(usdc), user, inputAmount);

        bytes memory unknownDestination = bytes("UNKNOWN_CHAIN");

        Order memory order = Order({
            user: bytes32(0),
            source: bytes(""),
            destination: unknownDestination,
            deadline: block.timestamp + 1 hours,
            nonce: 0,
            fees: 0,
            session: address(0),
            predispatch: DispatchInfo({assets: new TokenInfo[](0), call: ""}),
            inputs: new TokenInfo[](1),
            output: PaymentInfo({beneficiary: bytes32(uint256(uint160(user))), assets: new TokenInfo[](1), call: ""})
        });

        order.inputs[0] = TokenInfo({token: bytes32(uint256(uint160(address(usdc)))), amount: inputAmount});
        order.output.assets[0] = TokenInfo({token: bytes32(uint256(uint160(address(dai)))), amount: 2000 * 1e18});

        vm.startPrank(user);
        usdc.approve(address(customGateway), inputAmount);

        vm.recordLogs();
        customGateway.placeOrder(order, bytes32(0));
        vm.stopPrank();

        // Verify DustCollected event was emitted with default fee (1%)
        Vm.Log[] memory entries = vm.getRecordedLogs();
        uint256 collectedFee = 0;

        for (uint256 i = 0; i < entries.length; i++) {
            if (entries[i].topics[0] == keccak256("DustCollected(address,uint256)")) {
                (address token, uint256 amount) = abi.decode(entries[i].data, (address, uint256));
                if (token == address(usdc)) {
                    collectedFee = amount;
                }
            }
        }

        assertEq(collectedFee, expectedDefaultFee, "Should use default protocol fee when destination fee not set");
    }
