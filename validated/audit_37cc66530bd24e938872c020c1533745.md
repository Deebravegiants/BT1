### Title
Session identity bound to an unauthenticated, predictable cookie value in non‑embedded flow - (File: lib/shopify_api/auth/oauth/session_cookie.rb, lib/shopify_api/utils/session_utils.rb)

### Summary
For non‑embedded apps (and as a fallback for embedded apps without a bearer token), `ShopifyAPI::Utils::SessionUtils.current_session_id` derives the session identity solely from the raw value of the `shopify_app_session` cookie, with no cryptographic binding (no HMAC, no signature, no encryption) tying that value to the shop/user it was originally issued for.

### Finding Description
When OAuth completes, `ShopifyAPI::Auth::Oauth.validate_auth_callback` builds a `SessionCookie` whose `value` is simply `session.id` — a plain, predictable string such as `"{shop}_{user_id}"` (online) or `"offline_{shop}"` (offline), as constructed by `jwt_session_id`/`offline_session_id` [1](#0-0) . The cookie itself carries no signature: `SessionCookie` is a plain `T::Struct` with `name`, `value`, `expires` fields and no HMAC/verification logic [2](#0-1) .

Later, `SessionUtils.current_session_id` (and its private helper `cookie_session_id`) reads this cookie value back out and returns it directly as the session identifier used by the host application to look up the stored `Session` (with its `access_token`) [3](#0-2) [4](#0-3) . No re-derivation from a signed source (e.g., the JWT `dest`/`sub` claims) occurs in this cookie fallback branch — unlike the JWT branch, which does bind the id to `payload.shop` and `payload.sub` after signature verification [5](#0-4) .

The identity-binding equality that should hold is:
`session_id_returned_by_gem == session_id_cryptographically_derived_from_a_Shopify‑signed_credential`

but for the cookie path it instead holds:
`session_id_returned_by_gem == raw_bytes_of_an_unauthenticated_client_cookie`

Because the format `"{shop}_{user_id}"` / `"offline_{shop}"` is fully predictable and shop domains (`*.myshopify.com`) are public information, any client capable of setting/editing its own cookie value (client-side script, dev tools, a compromised subdomain sharing the cookie's cookie-jar scope, etc.) can present a session id string corresponding to a *different* merchant's shop. If the host application — following this gem's documented pattern in `docs/getting_started.md` of using `current_session_id`'s return value directly as the lookup key into its session store — does so without an additional authenticated binding, the attacker's request resolves to another tenant's stored `Session`, including its `access_token`.

### Impact Explanation
This breaks the identity binding between the party proving control of a cookie and the party the session/access token actually belongs to, leading to cross-tenant access: an unprivileged party can cause the app to operate a different shop's `access_token` on their request, without ever needing that shop's `api_secret_key` or the token itself.

### Likelihood Explanation
This affects the non‑embedded OAuth flow and the embedded-app fallback-to-cookie branch, both of which are the gem's documented, first-class API surface (`current_session_id`), not a misuse of undocumented behavior. Exploitability depends on the host app's session store keying scheme following the gem's documented `session.id` format exactly as constructed here, which is likely given this is the value the gem itself hands the host application to persist and later look up.

### Recommendation
Cryptographically bind the session cookie value to the shop/user it represents (e.g., sign or encrypt the cookie value, or store only an opaque, unguessable random session identifier server-side instead of the deterministic `"{shop}_{user_id}"` string), and verify that binding in `SessionUtils.cookie_session_id` before returning it as the trusted session id.

### Proof of Concept
1. Complete OAuth for `shop-a.myshopify.com` legitimately; observe the `shopify_app_session` cookie is set to `shop-a.myshopify.com_123` (or `offline_shop-a.myshopify.com`) as constructed by `jwt_session_id`/`offline_session_id` [1](#0-0) .
2. As a client with the ability to set/modify its own `shopify_app_session` cookie, change its value to `shop-b.myshopify.com_1` (guessing/knowing a target shop's domain and a low user id, or `offline_shop-b.myshopify.com` for the offline case).
3. Call an endpoint that uses `ShopifyAPI::Utils::SessionUtils.current_session_id` [3](#0-2)  to resolve the session id, then loads the stored `Session` for that id from the host app's session repository.
4. If shop‑b's session exists in the store, the request is now serviced with shop‑b's `access_token`, without the attacker ever presenting shop‑b's credentials.

```ruby
        def current_session_id(shopify_id_token, cookies, online)
          if Context.embedded?
            if shopify_id_token
              id_token = shopify_id_token.gsub("Bearer ", "")
              session_id_from_shopify_id_token(id_token: id_token, online: online)
            else
              # falling back to session cookie
              raise Errors::CookieNotFoundError, "JWT token or Session cookie not found for app" unless
                cookies && cookies[Auth::Oauth::SessionCookie::SESSION_COOKIE_NAME]

              cookie_session_id(cookies)
            end
          else
            raise Errors::CookieNotFoundError, "Session cookie not found for app" unless
              cookies && cookies[Auth::Oauth::SessionCookie::SESSION_COOKIE_NAME]

            cookie_session_id(cookies)
          end
        end
```

```ruby
        def session_id_from_shopify_id_token(id_token:, online:)
          raise Errors::MissingJwtTokenError, "Missing Shopify ID Token" if id_token.nil? || id_token.empty?

          payload = Auth::JwtPayload.new(id_token)
          shop = payload.shop

          if online
            jwt_session_id(shop, T.must(payload.sub))
          else
            offline_session_id(shop)
          end
        end
```

```ruby
      class SessionCookie < T::Struct
        extend T::Sig

        SESSION_COOKIE_NAME = "shopify_app_session"

        const :name, String, default: SESSION_COOKIE_NAME
        const :value, String
        const :expires, T.nilable(Time)

        alias_method :eql?, :==
        sig { params(other: T.nilable(SessionCookie)).returns(T::Boolean) }
        def ==(other)
          return false unless other

          name == other.name &&
            value == other.value &&
            expires == other.expires
        end
```
