Confirmed: `CatFeeConfig` derives `#[derive(Debug, Clone)]` with plaintext `api_key` and `api_secret` fields, and `TronClient::new` logs the full struct via `log::info!(target: LOG_TARGET, "CatFee integration enabled: {:#?}", catfee_config)`.

### Title
CatFee API credentials disclosed in plaintext relayer logs - (File: tesseract/messaging/tron/src/lib.rs)

### Summary
When a TRON relayer chain is configured with CatFee (energy-purchasing) credentials, the full `CatFeeConfig` struct — including the raw `api_key` and `api_secret` — is written to the relayer's log stream via `{:#?}` formatting during client initialization.

### Finding Description
`CatFeeConfig` derives a plain `Debug` implementation with no redaction: `api_key: String` and `api_secret: String` are printed verbatim. [1](#0-0) 

`TronClient::new` constructs this config from `config.catfee_api_key` / `config.catfee_api_secret` and immediately logs it at `info` level with the `{:#?}` (pretty debug) formatter, which serializes every field including the secret: [2](#0-1) 

This is directly analogous to CVE-2021-20191: a credential intended to stay confidential is emitted through a standard, default-enabled logging path (here `log::info!`, which per `tesseract/messaging/relayer/src/logging.rs` and `tesseract/consensus/admin-relayer/src/logging.rs` defaults to `LevelFilter::INFO`, so this is not gated behind a debug-only level). [3](#0-2) 

Contrast this with the project's own established pattern elsewhere for masking secrets before display/logging (`maskSecret`/`maskToml` in the SDK's filler setup, which explicitly redacts signer keys, API keys/secrets, and URL-embedded API keys before they are shown or persisted) — the same discipline is absent here. [4](#0-3) 

### Impact Explanation
Any operator, log aggregator, monitoring pipeline, or anyone with read access to the relayer's stdout/log files (which is common for shared infra, CI logs, or centralized log shipping) can recover the CatFee `api_key`/`api_secret` in cleartext. These credentials authorize purchasing TRON bandwidth/energy on the operator's CatFee account, allowing an attacker to drain the account's balance or abuse the API quota. While this does not directly compromise the relayer's on-chain signing key, it is a real credential-confidentiality violation matching the CVE's bug class (secrets not protected from being written to logs), reachable simply by having any actor with log access.

### Likelihood Explanation
The disclosure happens unconditionally and automatically at every relayer startup whenever CatFee credentials are configured, at `info` log level (the default), requiring no attacker interaction beyond ordinary log access — high likelihood for any deployment using this feature with typical log retention/shipping.

### Recommendation
Implement a manual `Debug` impl for `CatFeeConfig` (or wrap `api_key`/`api_secret` in a redacting newtype, e.g. `SecretString`) that masks the secret fields, and avoid logging the full config with `{:#?}`; log only non-sensitive fields (e.g. `api_base`, `timeout`) similar to the masking pattern already used in `maskToml`.

### Proof of Concept
1. Configure a TRON chain with `catfee_api_key` and `catfee_api_secret` set in the relayer TOML config.
2. Start the `tesseract-relayer` binary; `TronClient::new` runs and logs at `info!` level: `"CatFee integration enabled: {:#?}"` with the full `CatFeeConfig` struct. [5](#0-4) 
3. Inspect the process's stdout/log file or any centralized log collector — the plaintext `api_key` and `api_secret` values appear in the log line, exposing the CatFee account credentials to anyone with log-read access.

export function maskToml(config: FillerConfigFile, chainLabels?: string[]): string {
	const masked: FillerConfigFile = JSON.parse(JSON.stringify(config))
	const signer = masked.simplex.signer as Record<string, string> | undefined
	if (signer) {
		for (const field of ["key", "apiToken", "apiPrivateKey"]) {
			if (signer[field]) signer[field] = maskSecret(signer[field])
		}
	}
	if (masked.simplex.substratePrivateKey) {
		masked.simplex.substratePrivateKey = maskSecret(masked.simplex.substratePrivateKey)
	}
	if (masked.binance) {
		masked.binance.apiKey = maskSecret(masked.binance.apiKey)
		masked.binance.apiSecret = maskSecret(masked.binance.apiSecret)
	}
	for (const chain of masked.chains) {
		chain.rpcUrls = chain.rpcUrls.map(maskUrlKey)
		chain.bundlerUrl = maskUrlKey(chain.bundlerUrl)
	}
	return emitFillerToml(masked, { chainComments: chainLabels })
}
