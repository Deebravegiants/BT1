### Title
Attacker-driven high-utilization market can permanently freeze all market operations - (File: contracts/pool/src/interest.rs)

### Summary
The pool’s index accrual can enter an unrecoverable arithmetic-overflow state when a sufficiently large market remains at sustained high utilization. Once the next accrual panics in `scaled_to_original`, every operation that loads and synchronizes the same market also panics, permanently freezing withdrawals, repayments, liquidations, and index updates for that market.

### Finding Description
`update_indexes` is permissionless and forwards caller-selected `HubAssetKey` values to the pool for accrual [1](#0-0) . Pool accrual loads each market cache and calls `interest::global_sync` [2](#0-1) . `global_sync` repeatedly applies `accrue_chunk` until the elapsed time reaches zero [3](#0-2) . Each chunk calls `accrue_step` with the stored scaled borrowed and supplied values and commits the resulting indexes [4](#0-3) . Utilization and position-value calculations convert scaled RAY positions back into token values through `scaled_to_original` [5](#0-4) .

The regression test demonstrates the precise failure mode: a billion-token, eighteen-decimal market at 98% utilization reaches the `i128` RAY-value ceiling before `MAX_BORROW_INDEX_RAY`, causing `MATH_OVERFLOW` on `update_indexes`; subsequent `withdraw` and `repay` calls fail with the same error [6](#0-5) .

### Impact Explanation
This is a permanent freezing of user funds and a permanent market outage. Suppliers cannot withdraw, borrowers cannot repay, liquidators cannot reduce risk, revenue accounting cannot safely accrue, and bad debt cannot be resolved through ordinary market paths because those paths perform the same failing accrual first [7](#0-6) . Other suppliers in the market inherit the freeze even if the attacker controls only the initial high-utilization position [2](#0-1) .

### Likelihood Explanation
An unprivileged whale can supply a large listed asset, create an account with sufficient collateral in another market, borrow enough of the same market to maintain very high utilization, and then let interest accrue until the scaled value exceeds the fixed-point capacity. The attacker can trigger the terminal transition directly through `update_indexes(caller, vec![HubAssetKey { hub_id, asset }])`; no privileged role, oracle manipulation, leaked key, or contract upgrade is required [1](#0-0) . The severity and practicality depend on the deployed supply/borrow caps, decimals, rate curve, and maximum-utilization configuration permitting a market to approach the required scaled-value ceiling [8](#0-7) .

### Recommendation
Add an explicit pre-accrual capacity check for `scaled_to_original` and related RAY multiplication paths. Before the next index step can overflow, clamp the borrow index at `MAX_BORROW_INDEX_RAY`, pause or isolate only the affected market in a recoverable settlement mode, and still permit repayments and collateral-preserving withdrawals. The market should also enforce supply caps below the mathematically safe `i128` ceiling for its decimals and worst-case index growth rather than relying on utilization caps alone.

### Proof of Concept
1. Create a market using an 18-decimal asset and an aggressive borrow-rate curve comparable to `xlm_curve` [9](#0-8) .
2. Supply approximately one billion whole tokens into the market [10](#0-9) .
3. From a sufficiently collateralized account, borrow approximately 98% of that market’s supply [11](#0-10) .
4. Repeatedly invoke the permissionless `update_indexes` endpoint as time advances. Eventually it fails with `MATH_OVERFLOW` before `MAX_BORROW_INDEX_RAY` is reached [12](#0-11) .
5. Attempt `withdraw` or `repay` on the same market; both still fail with `MATH_OVERFLOW`, leaving supplied funds and debt operations permanently frozen [13](#0-12) .

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```

fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
