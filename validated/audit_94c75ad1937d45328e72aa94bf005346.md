### Title
Reentrant GET-timeout delivery zeroes `_requestCommitments` fee mid-flight, causing relayer fee to be stolen/lost during `dispatchIncoming(GetResponse)` — (File: `evm/src/core/EvmHost.sol`)

### Summary
`EvmHost.dispatchIncoming(GetResponse, relayer)` reads the relayer's fee from `_requestCommitments[commitment]` **after** making an untrusted external call to the destination application's `onGetResponse` hook. That external call can reenter `HandlerV2.handleGetRequestTimeouts`, which deletes the very same `_requestCommitments[commitment]` entry and refunds it to the original payer before the outer call resumes and tries to read it. This is the same bug class as CVE-2019-15920 (a value used after the object that owned it was already invalidated by another code path executing "in between"): the fee metadata is read from storage after it has effectively been freed/mutated by a reentrant call, so the read observes stale/zeroed data instead of the value that was valid when the operation started.

### Finding Description
In `dispatchIncoming(GetResponse memory response, address relayer)`: [1](#0-0) 

the sequence is:
1. `_responseReceipts[commitment]` is set (replay guard for the response itself).
2. An **external call** is made to the attacker-influenced destination app (`response.request.from`) via `onGetResponse`.
3. Only **after** that external call returns does the function read `_requestCommitments[commitment].fee` and pay the relayer.

`HandlerV2.handleGetRequestTimeouts` is fully permissionless and reachable via ordinary reentrancy from step 2: [2](#0-1) 

It calls `host.dispatchTimeOut(GetRequestTimeout, meta, commitment)`, which for the same `commitment`: [3](#0-2) 

deletes `_requestCommitments[commitment]` and, if the destination's `onGetTimeout` callback succeeds, refunds the escrowed fee back to `meta.sender` (the original requester).

An attacker who both dispatches the GET request (as `payer`/`from`) and controls the destination app that receives `onGetResponse` can:
1. Dispatch a `GetRequest` with a fee, from a malicious contract.
2. Let the request time out on the destination height used for delivery (the non-membership proof for `handleGetRequestTimeouts` only needs to show no response receipt existed at some historical height that already elapsed the timeout — a legitimately reachable condition once enough time has passed).
3. Have a relayer submit the legitimate `GetResponse` via `handleGetResponses` → `dispatchIncoming(GetResponse, relayer)`.
4. During the `onGetResponse` callback (step 2 above), reenter `handleGetRequestTimeouts` with a valid non-membership proof for the same request, which calls `dispatchTimeOut`, deletes `_requestCommitments[commitment]`, and refunds the fee to the attacker (`meta.sender`).
5. Control flow returns to the original `dispatchIncoming(GetResponse,...)` call, which now reads `_requestCommitments[commitment].fee == 0` and pays the honest relayer nothing.

Net effect: the attacker receives their GET response (their app got the on-chain data it wanted) **and** recovers the escrowed fee via the timeout refund path, while the relayer who correctly delivered the proof is paid zero. This directly matches the rules' in-scope category of "relayer fee and reward accounting."

### Impact Explanation
This breaks the fee-for-service guarantee of the relayer incentive system: a malicious requester can consume relayer-delivered proof work for free while also recovering their escrowed fee, via a single reentrant transaction. This is a concrete theft of relayer compensation (funds that should have gone to the relayer instead return to the attacker), qualifying under "relayer fee and reward accounting" impact. It does not require any privileged role — only a self-dispatched GET request with a malicious destination contract and a cooperating relayer submitting the (legitimate) response.

### Likelihood Explanation
Medium likelihood: the attacker fully controls both endpoints of the exploit (the requesting/`from` contract and its `onGetResponse`/`onGetTimeout` callbacks), and `handleGetRequestTimeouts` is permissionless and callable reentrantly with no guard against being invoked mid-flight of another handler call on the same host. The only external dependency is timing — the request's timeout must have elapsed and a relayer must independently deliver the `GetResponse` — both of which are ordinary, expected operating conditions rather than edge cases.

### Recommendation
Read and cache `_requestCommitments[commitment]` (or capture the fee) **before** making the external call to the destination app in `dispatchIncoming(GetResponse, ...)`, following the same checks-effects-interactions pattern already used elsewhere in the file (e.g., `_responseReceipts` is set before the call). Alternatively, add a reentrancy guard shared across `dispatchIncoming`/`dispatchTimeOut` for the same commitment, or delete/lock `_requestCommitments[commitment]` before the external call so a reentrant timeout on the same commitment cannot race the fee payout.

### Proof of Concept
1. Deploy a malicious contract `M` that:
   - Calls `IDispatcher(host).dispatch(DispatchGet{ from: M, to: M, fee: F, timeout: T, ... })` to create a GET request where `M` is both `from` and effectively receives the response, and is the fee `payer`.
   - Implements `onGetResponse` to, mid-callback, call `HandlerV2.handleGetRequestTimeouts(host, timeoutMsgForSameRequest)` with a valid non-membership proof at a height where `request.timeout() <= state.timestamp` (already true once `T` has elapsed) and no response receipt existed yet at that historical height.
   - Implements `onGetTimeout` to simply return success.
2. Wait until `T` elapses.
3. A relayer observes the request has a valid response and calls `HandlerV2.handleGetResponses(host, responseMsg)`, which invokes `EvmHost.dispatchIncoming(response, relayer)`.
4. Inside `onGetResponse`, `M` reenters `handleGetRequestTimeouts`, which calls `dispatchTimeOut(GetRequestTimeout, meta, commitment)`, deleting `_requestCommitments[commitment]` and refunding fee `F` back to `M`.
5. Execution returns to `dispatchIncoming(GetResponse,...)`, which reads `_requestCommitments[commitment].fee == 0` and pays the relayer nothing, despite the relayer having delivered a valid proof.

Note: full exploitability depends on the exact timing/state-height requirements of `PolkadotTrie.VerifyProof`'s non-membership check inside `handleGetRequestTimeouts`, which I was unable to fully trace through `PolkadotTrie` internals from the indexed context; this should be verified in a live/fork test before treating the PoC as fully proven.

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
