### Title
Emporium "min" action (`erc20TokenAddresses.length == 0`) skips the balance-equation check entirely, allowing signer-authorised ops to move the Emporium contract's own ETH without any conservation proof - (File: `contracts/CircomDataBuilder.sol`, `contracts/Hinkal.sol`, `contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol`)

### Summary
This is the same bug class as the Hats report: a conditional branch that is supposed to be a harmless "special case" actually removes an equality check (there: threshold reconciliation; here: the balance-conservation equation), letting state diverge from what the protocol's invariant assumes.

### Finding Description
`CircomDataBuilder.formInputForCircom()` bifurcates on `externalActionData.externalActionId == HINKAL_EMPORIUM_ACTION_ID && erc20TokenAddresses.length == 0`, routing to `formInputEmporiumMin()`, which only feeds `emporiumMessage`, `timeStamp`, and `calldataHash` into the public-input vector — `rootHashHinkal`, `signedMessageHash`, and all UTXO/nullifier/commitment signals are dropped. [1](#0-0) 

Because `circomData.erc20TokenAddresses.length == 0` in this branch, the balance-equation loop in `Hinkal.transact()` — which normally enforces `balanceDif == amountChanges[i] + utxoAmount` — never executes at all: [2](#0-1) 

The same emptiness propagates into `EmporiumUpgradeable.runAction()`, whose own before/after balance tracking and UTXO-out creation also iterate over `circomData.erc20TokenAddresses`, so nothing is tracked or constrained there either: [3](#0-2) 

Yet `runAction()`'s "Stateless Interaction" branch still performs a direct, value-bearing external call sourced from the Emporium contract's own balance, gated only by an EIP-712 signature over the ops list (`verifyWallet`) — not by any shielded-balance/UTXO proof: [4](#0-3) [5](#0-4) 

The Emporium contract can hold its own ETH (it has a `receive()` fallback and is also the destination for `sendToRelay` when `signerAddress == address(0)`), meaning ETH belonging to the protocol/other in-flight transactions can sit in its balance between calls: [6](#0-5) [7](#0-6) 

The equality that is supposed to be maintained — "every unit of value moved by an action must be accounted for by the balance equation (`amountChanges` + UTXO deltas)" — is broken specifically because the `erc20TokenAddresses.length == 0` shortcut (analogous to the Hats faulty if/else branch that silently skipped the threshold correction) removes the very check that would have caught unaccounted value transfer.

### Impact Explanation
Any address that can produce a validly-signed `EmporiumStack` (self-signed, since the ops/signature format only requires the signer to sign their own request) can direct the Emporium contract to send `op.value` ETH from the Emporium contract's own balance to an arbitrary endpoint via `op.endpoint.call{value: op.value}(op.callData)`, with zero enforcement that this ETH corresponds to any shielded UTXO or amount the signer is entitled to withdraw. If the Emporium contract holds any residual/pooled ETH (relay fees paid via `sendToRelay` semantics, dust, or ETH left mid-flow from other users' transactions), this constitutes theft of protocol/relay funds or funds not belonging to the caller — matching the "High: theft ... of protocol/relay fees" / "unauthorised asset movement" impact category.

### Likelihood Explanation
Likelihood depends on the Emporium contract actually holding a non-zero ETH balance at the time of the call (e.g., leftover from partially-executed multi-op stacks, or fees routed through it). Given the contract explicitly exposes a `receive()` function and a fee-forwarding path that uses its own balance, some non-zero balance is plausible in normal operation, making this reachable without needing any privileged role — only a self-produced EIP-712 signature.

### Recommendation
Do not allow the `erc20TokenAddresses.length == 0` "min" Emporium path to bypass balance-equation enforcement whenever ops can move value (`op.value > 0`) from the Emporium contract's own balance. Either (a) require `erc20TokenAddresses`/`amountChanges` to always include a slot for ETH when any op has `value > 0`, so the standard balance-diff check in `Hinkal.transact()` applies, or (b) explicitly assert `address(this).balance` before/after in `EmporiumUpgradeable.runAction()` for the min-input case and revert if native ETH beyond what was supplied by the caller in the current call is spent.

### Proof of Concept
1. Attacker crafts `CircomData` with `externalActionData.externalActionId == HINKAL_EMPORIUM_ACTION_ID`, `erc20TokenAddresses = []`, and an `EmporiumStack` containing one `EmporiumOperation` with `invokeWallet = false`, `endpoint = <attacker address>`, `value = X` (X ≤ current ETH balance of the Emporium contract), `callData = ""`.
2. Attacker signs the `EMPORIUM_SIGNATURE_TYPEHASH` digest with their own key (`stack.signerAddress = attacker`), satisfying `verifyWallet`.
3. Attacker generates a proof for the "min" circuit variant — trivial since the public inputs are only `emporiumMessage`, `timeStamp`, `calldataHash`, none of which constrain fund ownership.
4. Calls `Hinkal.transact()`. `performHinkalChecks` passes (calldata hash matches), proof verifies against the reduced public-input set, and `Hinkal.transact()`'s balance-equation loop is skipped entirely because `erc20TokenAddresses.length == 0`.
5. `EmporiumUpgradeable.runAction()` executes CASE 2, sending `X` wei of the Emporium contract's own ETH balance to the attacker's address, without any check that this ETH was ever backed by a UTXO/amountChange belonging to the attacker.

        uint16 index = 0;

    function verifyWallet(
        EmporiumStack memory stack,
        CircomData calldata circomData
    ) internal {
        EmporiumStorageVars storage $ = _getEmporiumStorage();

        if ($.usedMessages[circomData.emporiumMessage]) {
            revert UsedMessage();
        }

        $.usedMessages[circomData.emporiumMessage] = true;

        if (stack.signerAddress == address(0)) {
            return;
        }

        bytes32 hashedMessage = _hashTypedDataV4(
            keccak256(
                abi.encode(
                    EMPORIUM_SIGNATURE_TYPEHASH,
                    circomData.emporiumMessage,
                    _hashEmporiumOps(stack.ops),
                    stack.maxFee,
                    stack.deadline
                )
            )
        );

        (address recoveredAddress, ECDSA.RecoverError err) = ECDSA.tryRecover(
            hashedMessage,
            stack.v,
            stack.r,
            stack.s
        );
        bool verified = err == ECDSA.RecoverError.NoError &&
            recoveredAddress == stack.signerAddress;
        if (!verified) {
            revert InvalidSignature();
        }

        if (block.timestamp > stack.deadline) {
            revert SignatureExpired();
        }

        if (circomData.feeStructure.flatFee > stack.maxFee) {
            revert FeeExceedsSignedMax();
        }
    }
