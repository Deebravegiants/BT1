### Title
Unallowlisted route venues let payload-named pool contracts execute arbitrary code inside the caller's authorization tree - (File: contracts/swap-aggregator/src/venues/mod.rs)

### Summary
The BigBlueButton CVE-2020-27605 class — a "weak sandbox" where attacker-controlled input reaches an external processor that executes with the host's privileges — maps directly onto XOXNO Lending's swap router. `execute_strategy` decodes an attacker-supplied XDR route whose `assets` registry names arbitrary pool/token addresses, and `dispatch_hop` invokes whatever contract the payload names with no venue or pool allowlist. Because the venue call executes while the sender's `execute_strategy` authorization is live, a malicious "pool" contract can request `token.transfer(victim, attacker, amount)` on any token the victim holds; the host records it as a child of the victim's signed auth tree and executes it if the victim signs the simulated tree. The payload minimum and the controller's measured-output checks do not bound the loss, which is the victim's wallet, not just the routed input.

### Finding Description
The router calls the pool and token addresses its payload names and keeps no allowlist of them; hop dispatch routes by opcode to a venue adapter that invokes the payload-supplied pool address. [1](#0-0)  The threat model documents that this "puts third-party code on the call stack below the caller's authorization" and that a transfer such code makes from the caller is "recorded by an honest simulation as a child of the caller's authorization entry, and it executes if the caller signs that tree." [2](#0-1)  The controller side offers the same reachability: `swap_tokens` authorizes one input transfer and calls `router.execute_strategy` with a caller-supplied `StrategySwap` XDR, then only checks input spend and positive measured output. [3](#0-2)  The adversarial test `rogue_hop_pool_transfer_joins_caller_auth_tree.rs` demonstrates end-to-end that a rogue pool drains the caller's unrelated wallet token when the simulated tree is signed, and that simulation itself produces the poisoned tree. [4](#0-3) 

### Impact Explanation
Theft of user funds. A victim who submits an attacker-crafted route — via `swap-aggregator::execute_strategy` directly or via `controller::swap_collateral`/`swap_debt`/`repay_debt_with_collateral`/`multiply` — signs an authorization tree whose honest simulation already contains a malicious `transfer` child, and the rogue pool then moves any of the victim's wallet tokens to the attacker. [5](#0-4)  The loss is unbounded by `min_out`, the routed amount, or final account risk gates: the sandbox escape means payload-named code acts with the caller's authority, exactly the Ghostscript analog of a converter running unsandboxed on untrusted input.

### Likelihood Explanation
Exploitation needs a victim to execute an attacker-supplied route and sign the tree the simulator returns — standard behavior for clients that trust simulation output blindly, which is the documented default flow for route construction. Reachability is fully permissionless: any address may call `execute_strategy` and all six controller strategy entrypoints. [6](#0-5)  The exposure is mitigated only client-side (decode the route and refuse extra auth children), not on-chain; the threat model assigns that duty to the client because the protocol does not enforce it. [7](#0-6)  Rated High rather than Critical because theft requires the victim to sign the poisoned tree rather than being triggerable unilaterally.

### Recommendation
Enforce venue/pool admission on-chain in the router: validate each hop's pool address against a governance-managed allowlist (or against venue-native factory/registry lookups) inside `dispatch_hop` before invoking it, mirroring the approved-pool gate already used for Blend migration. [8](#0-7)  Additionally, sandbox each venue call so no `require_auth`-bearing token invocation from the pool can attach to the sender's tree — e.g., pre-transfer hop inputs to the pool itself rather than letting pool code pull, and assert during settlement that no unauthorized sub-invocation was recorded under the sender's entry. Until then, clients must decode the route XDR and reject any simulated auth tree containing children beyond the single input transfer. [9](#0-8) 

### Proof of Concept
1. Attacker deploys a contract exposing a `swap()` function that, when invoked, calls `wallet_token.transfer(victim, attacker, victim_balance)` on any token the victim holds. [10](#0-9) 
2. Attacker encodes a `StrategySwap`/`StrategyPayload` route whose hop `pool` field indexes the attacker's contract address in the `assets` registry, with `min_out` set to a fair output so the swap appears benign in quotes.
3. Victim simulates `controller::swap_collateral(caller=victim, account_id, USDC, amount_in, ETH, route)` (or `swap-aggregator::execute_strategy` directly). Recording-mode simulation returns an auth tree containing the rogue `transfer` as a child of the victim's entry. [11](#0-10) 
4. Victim signs and submits the simulated transaction; the host authorizes the rogue transfer, the victim's wallet token moves to the attacker, and the swap still completes with fair output, passing `RouterOverspend`/`NoSwapOutput` checks. [12](#0-11)

#[test]
fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
}

#[test]
fn enforced_auth_moves_the_wallet_token_only_when_the_signed_tree_lists_the_rogue_transfer() {
    let s = Scene::new();

    // Control: a pool that touches nothing passes with the honest root-only tree.
    let benign = s.route_through_pool_stealing(0);
    s.try_swap_with_signed_tree(&benign, &[])
        .expect("the honest tree authorizes an honest route");
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);

    // Rogue pool, honest tree: the host refuses the transfer and the whole call rolls back.
    s.t.env.mock_all_auths_allowing_non_root_auth();
    let rogue = s.route_through_pool_stealing(WALLET_BALANCE);
    let usdc_before = s.t.supply_balance_raw(ALICE, "USDC");
    let refused = s
        .try_swap_with_signed_tree(&rogue, &[])
        .expect_err("a transfer outside the signed tree is unauthorized");
    std::println!("rogue transfer under the honest tree = {refused:?}");
    assert!(
        refused.is_type(ScErrorType::Auth) || refused.is_type(ScErrorType::Context),
        "expected a host auth failure, got {refused:?}"
    );
    assert!(s
        .diagnostics()
        .contains("Unauthorized function call for address"));
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);
    assert_eq!(s.wallet(&s.attacker), 0);
    assert_eq!(s.t.supply_balance_raw(ALICE, "USDC"), usdc_before);

    // Same route, with the tree that simulation returned.
    let stolen_transfer = MockAuthInvoke {
        contract: &s.wallet_token,
        fn_name: "transfer",
        args: (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        sub_invokes: &[],
    };
    s.try_swap_with_signed_tree(&rogue, core::slice::from_ref(&stolen_transfer))
        .expect("the poisoned tree authorizes the rogue transfer");
    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
}

### INV-STRAT-03 — Blend migration requires an approved pool

Blend migration requires the source Blend pool on the controller's
governance-managed approval list. Admission does not prove permanent integrity

The router's separate token whitelist selects fee placement. It does not admit
