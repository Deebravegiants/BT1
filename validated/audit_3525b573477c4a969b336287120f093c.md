### Title
Griefing DoS: a single already-delivered message can revert an entire relayer batch in `handlePostRequests`/`handleGetResponses` - (File: evm/src/core/HandlerV2.sol)

### Summary
`HandlerV2.handlePostRequests` and `handleGetResponses` verify a MMR membership proof over a whole batch of leaves computed against system state `s` (no per-item receipt yet), and only afterward, in a second loop, check each item's delivery receipt and dispatch it. If any single item in the batch is delivered by a third party between proof construction and the second loop's execution, the entire transaction reverts with `DuplicateMessage()` — exactly the "manualAllocation" pattern in the report, where a decision is computed against state `s` but executed against a later state `s'`.

### Finding Description
`handlePostRequests` [1](#0-0)  first loops over all `requestsLen` leaves to build the MMR leaf set and verify the batch proof against the stored `overlayRoot`, then in a second, separate loop calls `host.requestReceipts(leaf.request.hash())` and reverts the whole call with `DuplicateMessage()` if any single leaf was already delivered, before dispatching the rest: [2](#0-1) 

`handleGetResponses` follows the identical two-pass structure — proof verified over the full response batch, then a second loop checking `host.responseReceipts(...)` per item and reverting atomically on the first duplicate: [3](#0-2) 

Because the loop is atomic (any `revert` unwinds the whole call, and there is no `continue`/skip-if-duplicate logic as the DebtManager report recommends), an attacker only needs to get **one** of the N leaves in a relayer's pending batch delivered first (e.g., by extracting that single leaf plus its own cheap proof and front-running with a smaller `handlePostRequests`/`handleGetResponses` call, or via `batchCall`, whose semantics are the same: "any failure reverts the entire batch" [4](#0-3) ). This forces the honest relayer's larger batch to revert entirely at the `DuplicateMessage()` check, even though the MMR proof verification (the most gas-expensive step) already succeeded.

Since Tesseract batches many POST requests / GET responses into a single `handlePostRequests`/`handleGetResponses`/`batchCall` transaction for gas efficiency [5](#0-4) , and any address may call these permissionless handler entrypoints [6](#0-5) , an attacker can repeatedly and cheaply grief relayers by delivering one leaf from each observed pending batch ahead of it, causing repeated full-batch reverts.

### Impact Explanation
This is a griefing/denial-of-service on message delivery, not a fund-theft bug, but it directly harms the "route unable to deliver messages" criterion:
- The relayer wastes gas on the (expensive) MMR proof verification each time the batch reverts.
- Legitimate, undelivered messages bundled with the targeted duplicate are also blocked/delayed indefinitely as long as the attacker keeps front-running single leaves out of each rebuilt batch, since the relayer cannot know in advance which item will be "stolen" by the time its tx lands.
- At scale, this can be used to indefinitely delay delivery of time-sensitive POST requests/GET responses (e.g., before their `timeout()`), causing legitimate cross-chain messages to expire and be permanently unrelayable — a concrete "route unable to deliver messages" outcome per the validation criteria.

### Likelihood Explanation
Any observer can see pending relay batches (e.g., watching Hyperbridge's mempool/offchain queue or the relayer's submitted transactions) and race a small, cheap, single-item `handlePostRequests`/`handleGetResponses` transaction ahead of the multi-item batch. There is no cost asymmetry protection: the attacker pays gas for one cheap MMR proof against one leaf, while the victim's much larger batch (already having paid for full proof verification) reverts. This requires no special privilege — it exploits the permissionless nature of the handler, exactly analogous to the reported `manualAllocation` frontrun.

### Recommendation
Adopt the same fix pattern recommended in the source report: instead of reverting the entire batch on a stale/duplicate item, skip (continue) that specific item in the second loop and dispatch the rest:

```solidity
for (uint256 i = 0; i < requestsLen; ++i) {
    PostRequestLeaf memory leaf = request.requests[i];
    // already delivered by someone else in the interim — skip instead of reverting the whole batch
    if (host.requestReceipts(leaf.request.hash()) != address(0)) continue;
    host.dispatchIncoming(leaf.request, _msgSender());
}
```
Apply the analogous change to `handleGetResponses`. This preserves atomicity where it matters (the proof verification), while eliminating the ability for a third party to grief the rest of an otherwise-valid, proof-verified batch.

### Proof of Concept
1. Relayer R builds a `PostRequestMessage` containing leaves `L0..Ln` and a valid MMR proof for all of them (based on state `s`), and submits `handlePostRequests(host, msg)`.
2. Attacker A observes this pending transaction (mempool or off-chain queue), extracts leaf `L0`'s underlying `PostRequestLeaf`, builds/reuses a minimal valid proof for `L0` alone, and submits a cheaper `handlePostRequests` call containing only `L0`, front-running R's transaction.
3. A's transaction lands first: `host.requestReceipts(L0.hash())` becomes non-zero, and `L0` is dispatched.
4. R's transaction now executes: the proof-verification loop and MMR check succeed exactly as before (proof was constructed against unchanged consensus state `s`), but in the second loop, `host.requestReceipts(L0.hash()) != address(0)` is now true, so `handlePostRequests` reverts with `DuplicateMessage()` for the *entire* batch `L0..Ln`, even though `L1..Ln` were never delivered.
5. R has burned gas on full MMR verification for nothing, and delivery of `L1..Ln` is delayed until R rebuilds and resubmits a smaller batch — which A can repeat against the new batch. [1](#0-0)

     * @dev Process a batch of encoded handler calls in a single transaction.
     * Uses delegatecall to self so msg.sender is preserved and storage writes
     * happen in this contract's context. Atomic, any failure reverts the entire batch.
     * @param calls - array of ABI-encoded handler function calls
     */
    function batchCall(bytes[] memory calls) external {
        uint256 len = calls.length;
        for (uint256 i = 0; i < len; ++i) {
            (bool success, bytes memory returnData) = address(this).delegatecall(calls[i]);
            if (!success) revert BatchCallFailed(i, returnData);
        }
    }

    function handlePostRequests(IHost host, PostRequestMessage calldata request) external notFrozen(host) {
        uint256 timestamp = block.timestamp;
        uint256 delay = timestamp - host.stateMachineCommitmentUpdateTime(request.proof.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        uint256 requestsLen = request.requests.length;
        MerkleMountainRange.Leaf[] memory leaves = new MerkleMountainRange.Leaf[](requestsLen);

        for (uint256 i = 0; i < requestsLen; ++i) {
            PostRequestLeaf memory leaf = request.requests[i];
            // check destination
            if (!leaf.request.dest.equals(host.host())) revert InvalidMessageDestination();
            // check time-out
            if (timestamp >= leaf.request.timeout()) revert MessageTimedOut();
            leaves[i] = MerkleMountainRange.Leaf(leaf.index, leaf.request.hash());
        }

        bytes32 root = host.stateMachineCommitment(request.proof.height).overlayRoot;
        if (root == bytes32(0)) revert StateCommitmentNotFound();
        bool valid = MerkleMountainRange.VerifyProof(root, request.proof.multiproof, leaves, request.proof.leafCount);
        if (!valid) revert InvalidProof();

        for (uint256 i = 0; i < requestsLen; ++i) {
            PostRequestLeaf memory leaf = request.requests[i];
            // duplicate request?
            if (host.requestReceipts(leaf.request.hash()) != address(0)) revert DuplicateMessage();
            host.dispatchIncoming(leaf.request, _msgSender());
        }
    }

/// Build the per-message inner calldata array for an `IHandlerV2.batchCall`.
///
/// Each entry is an ABI-encoded HandlerV1 call (`handleConsensus`,
/// `handlePostRequests`) — `batchCall` delegatecalls
/// self so those selectors still dispatch correctly against HandlerV2.
async fn build_batch_inner_calls(
	client: &EvmClient,
	messages: &[Message],
) -> anyhow::Result<Vec<Bytes>> {
	let handler_addr = Address::from_slice(&client.handler().await?.0);
	let contract = HandlerV2Instance::new(handler_addr, client.signer.clone());
	let ismp_host = Address::from_slice(&client.ismp_host.0);

	let mut inner = Vec::with_capacity(messages.len());
	for msg in messages {
		let calldata = match msg {
			Message::Consensus(msg) => contract
				.handleConsensus(ismp_host, Bytes::from(msg.consensus_proof.clone()))
				.calldata()
				.clone(),

			Message::Request(msg) => {
				let (mmr_proof, leaf_indices) = decode_mmr_proof(&msg.proof.proof)?;
				let mut leaves: Vec<PostRequestLeaf> = msg
					.requests
					.iter()
					.zip(&leaf_indices)
					.map(|(post, &leaf_index)| PostRequestLeaf {
						request: post.clone().into(),
						index: AlloyU256::from(leaf_index),
					})
					.collect();
				leaves.sort_by_key(|l| l.index);
				let proof = build_solidity_proof(&mmr_proof, &msg.proof.height)?;
				contract
					.handlePostRequests(ismp_host, PostRequestMessage { proof, requests: leaves })
					.calldata()
					.clone()
			},

			Message::Response(msg) => {
				let message = build_get_response_message(msg)?;
				contract.handleGetResponses(ismp_host, message).calldata().clone()
			},

			Message::Timeout(_) =>
				return Err(anyhow!("Timeout messages are not supported by batchCall")),

			Message::FraudProof(_) =>
				return Err(anyhow!("Unexpected fraud proof message in batchCall")),
		};
		inner.push(calldata);
	}
	Ok(inner)
}
