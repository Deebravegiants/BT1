### Title
Webhook `shop` Identity Not Bound by HMAC Signature, Enabling Cross-Tenant Webhook Spoofing - (File: `lib/shopify_api/webhooks/request.rb`)

### Summary
`ShopifyAPI::Utils::HmacValidator.validate` only authenticates the raw webhook body; the `shop` domain (and `topic`/`api_version`/`webhook_id`) delivered to the app's handler are taken from unauthenticated HTTP headers that are never part of the signed payload, breaking the identity equality `shop_verified_by_hmac == shop_delivered_to_handler`.

### Finding Description
`ShopifyAPI::Webhooks::Request#to_signable_string` returns only `@raw_body`: [1](#0-0) 
while `shop`, `topic`, `api_version`, and `webhook_id` are read directly from headers with no cryptographic binding to the signature: [2](#0-1) 

`Utils::HmacValidator.validate` computes the HMAC solely over `to_signable_string` (the body) using the app's single, shop-agnostic `client_secret`: [3](#0-2) 

`Registry.process` accepts the request once this body-only HMAC passes, then forwards the **unverified** `request.shop` header straight to the app's webhook handler as the tenant identity: [4](#0-3) [5](#0-4) 

Because the same `client_secret` is used to sign webhooks for every shop that installs the app, any unprivileged merchant who installs the app on their own store legitimately receives valid `(raw_body, hmac)` pairs signed with that shared secret. That merchant can replay the exact same body+hmac while substituting the `x-shopify-shop-domain` (or `shopify-shop-domain`) header with a victim shop's domain. `HmacValidator.validate` still returns `true` (it never inspects the header), so `Registry.process` dispatches the forged request to the handler with `data.shop` set to the attacker-chosen victim domain — a cross-tenant identity binding violation: `hmac_verified_over(body)` is treated as proof of `shop`, when `shop` was never covered by the signature.

### Impact Explanation
This breaks the tenant/identity boundary the gem is supposed to enforce for webhook consumers: an attacker-controlled `shop` value reaches the app's business logic as if it were authenticated by Shopify, enabling cross-tenant data injection/confusion (e.g. an app that keys per-shop state or actions off `data.shop` from the handler can be made to act on/against a shop the attacker does not control). This matches the Critical/High "cross-tenant access" impact category defined in scope.

### Likelihood Explanation
Reachable by any unprivileged internet user who can install the target app on their own (attacker-controlled) shop — a normal, low-privilege condition, not requiring leaked `client_secret`, access tokens, or any credential beyond running their own store. No host-application misuse of the documented API is required; the gem's own `Registry.process`/`HmacValidator` accept and forward the header-derived `shop` unconditionally.

### Recommendation
Bind `shop` (and ideally `topic`, `webhook_id`) into the value verified by the HMAC, or otherwise cross-check `request.shop` against the shop associated with the specific webhook subscription/registration before dispatching to handlers, so that the value used for tenant identification cannot be forged independently of the raw body.

### Proof of Concept
1. Attacker installs the target Shopify app on `attacker-shop.myshopify.com`, a normal legitimate install.
2. Attacker's app instance receives a genuine webhook: `raw_body = B`, `x-shopify-hmac-sha256 = HMAC(client_secret, B)`, `x-shopify-shop-domain = attacker-shop.myshopify.com`.
3. Attacker replays the identical `raw_body` and `hmac` header to the app's webhook endpoint but sets `x-shopify-shop-domain: victim-shop.myshopify.com`.
4. `ShopifyAPI::Webhooks::Request.new` parses the forged headers; `HmacValidator.validate` recomputes `HMAC(client_secret, B)` — matches, returns `true` per `lib/shopify_api/utils/hmac_validator.rb` lines 26-31.
5. `Registry.process` calls the handler with `WebhookMetadata.new(shop: "victim-shop.myshopify.com", body: B, ...)` per `lib/shopify_api/webhooks/registry.rb` lines 198-199, even though this request never originated from Shopify for that shop.
