### Title
Webhook `shop-domain` header not covered by HMAC allows cross-tenant shop spoofing - (File: `lib/shopify_api/webhooks/request.rb`)

### Summary
`ShopifyAPI::Webhooks::Request` computes its HMAC over the raw request body only, but reads `topic`, `shop`, `api_version`, and `webhook_id` from HTTP headers that are never included in the signed payload. `ShopifyAPI::Webhooks::Registry.process` validates only the body HMAC and then forwards the unauthenticated `shop` header value to the app's `WebhookHandler`, breaking the intended identity binding `hmac-verified request == shop attributed to that request`.

### Finding Description
`Request#to_signable_string` returns only `@raw_body`: [1](#0-0) 

while `shop`, `topic`, `api_version`, and `webhook_id` are all pulled straight from HTTP headers with no cryptographic binding to the body or to each other: [2](#0-1) 

`Utils::HmacValidator.validate` only recomputes the HMAC over `to_signable_string` (the body) and compares it to the `hmac` header: [3](#0-2) 

`Registry.process` treats this body-only HMAC check as authorization for trusting the entire `Request`, including `request.shop`, and passes it straight into the handler's `WebhookMetadata`: [4](#0-3) [5](#0-4) 

The gem's own documentation tells integrators that `Registry.process` "will verify the request did indeed come from Shopify" and that `data.shop` is "The shop domain of the webhook" — implying it is trustworthy/authenticated — and shows it being used directly to key application-side work (e.g., `shop_domain: data.shop`): [6](#0-5) [7](#0-6) 

The identity binding that should hold is: **shop attributed to a webhook == shop that produced the HMAC-signed bytes**. Because the header carrying the shop is outside the signed byte range, this equality is not enforced by the gem. Any party that possesses one valid `(raw_body, hmac)` pair — trivially available to any merchant/developer who has installed the app on their own store and can observe their own legitimate webhook deliveries — can replay that exact body/HMAC pair to the app's public webhook endpoint while substituting an arbitrary `shopify-shop-domain` (or `x-shopify-shop-domain`) header value naming a different, victim shop. `HmacValidator.validate` still returns `true` because the body bytes and secret are unchanged, and `Registry.process` will hand the handler a `WebhookMetadata` claiming the forged victim shop, with attacker-controlled body content.

### Impact Explanation
This crosses a tenant boundary: the app is made to believe attacker-supplied data originated from a shop the attacker does not control and has no legitimate relationship to for that event. Depending on how the host app's handler uses `data.shop` (session lookup, DB writes, queued jobs keyed by shop, cache invalidation, billing/order processing, etc.), this enables cross-tenant data injection or corruption — matching the "Critical - cross-tenant access" impact category, since the gem's documented contract (`Registry.process` "verifies the request did indeed come from Shopify") is what the app author relies on to trust `data.shop`.

### Likelihood Explanation
Likelihood is meaningful but not trivial: the attacker needs at least one legitimate `(body, hmac)` pair, which they can obtain by owning any shop with the target app installed (a normal, unprivileged merchant/developer relationship) and capturing their own webhook deliveries (e.g., via a local proxy/logging in their own webhook endpoint, or via any topic whose body is attacker-influenceable, such as `products/update`, `carts/create`, etc., where they fully control the body content sent to their own endpoint). No access to `api_secret_key` or any victim credential is required — only observation of one's own legitimate traffic.

### Recommendation
Bind the identifying headers into the signed material, or independently re-verify `shop`/`topic`/`api_version` against values the app already trusts (e.g., match `shop` against the merchant record associated with the specific registered webhook subscription/handler for that path, not solely against the header). Alternatively, document explicitly and loudly that `data.shop`/`data.topic` are unauthenticated header values not covered by the HMAC, so downstream apps do not treat them as trusted, and provide an API that only exposes header fields after confirming the webhook subscription/topic pairing server-side (e.g., cross-check against the registered `path` used to route to a specific handler bound to a specific expected shop when applicable).

### Proof of Concept
```ruby

# Step 1: capture a legitimate webhook delivery to their own endpoint.
raw_body = capture_from_own_endpoint # e.g. '{"id":1,"note":"hi"}'
hmac_b64 = capture_from_own_endpoint_headers["x-shopify-hmac-sha256"] # valid for raw_body + api_secret_key

# Step 2: replay it against the public webhook endpoint, spoofing the shop header.
forged_headers = {
  "x-shopify-topic" => "products/update",
  "x-shopify-hmac-sha256" => hmac_b64,          # still valid, body unchanged
  "x-shopify-shop-domain" => "victim-shop.myshopify.com",  # forged
  "x-shopify-webhook-id" => "any",
  "x-shopify-api-version" => "2024-01",
}

request = ShopifyAPI::Webhooks::Request.new(raw_body: raw_body, headers: forged_headers)
ShopifyAPI::Webhooks::Registry.process(request)

#    handler.handle(data: WebhookMetadata(shop: "victim-shop.myshopify.com", body: attacker_controlled_body, ...))

# typed: strict
# frozen_string_literal: true

module ShopifyAPI
  module Webhooks
    class Request
      extend T::Sig
      include Utils::VerifiableQuery

      sig { override.returns(String) }
      def hmac
        Digest.hexencode(Base64.decode64(T.cast(shopify_header("hmac-sha256"), String)))
      end

      sig { returns(String) }
      def topic
        T.cast(shopify_header("topic"), String)
      end

      sig { returns(String) }
      def shop
        T.cast(shopify_header("shop-domain"), String)
      end

      sig { returns(String) }
      def api_version
        T.cast(shopify_header("api-version"), String)
      end

      sig { returns(String) }
      def webhook_id
        T.cast(shopify_header("webhook-id"), String)
      end

      sig { override.returns(String) }
      def to_signable_string
        @raw_body
      end

      sig { returns(T::Hash[String, T.untyped]) }
      def parsed_body
        JSON.parse(@raw_body)
      end

      sig { params(raw_body: String, headers: T::Hash[String, T.untyped]).void }
      def initialize(raw_body:, headers:)
        # normalize the headers by forcing lowercase, removing any prepended "http"s, and changing underscores to dashes
        headers = headers.to_h { |k, v| [k.to_s.downcase.sub("http_", "").gsub("_", "-"), v] }

        missing_headers = []
        ["topic", "hmac-sha256", "shop-domain"].each do |name|
          unless headers.key?("shopify-#{name}") || headers.key?("x-shopify-#{name}")
            missing_headers << "shopify-#{name} or x-shopify-#{name}"
          end
        end
        unless missing_headers.empty?
          raise Errors::InvalidWebhookError,
            "Missing one or more of the required HTTP headers to process webhooks: #{missing_headers}"
        end

        @headers = headers
        @raw_body = raw_body
      end

      private

      sig { params(name: String).returns(T.untyped) }
      def shopify_header(name)
        @headers["shopify-#{name}"] || @headers["x-shopify-#{name}"]
      end
    end
  end
end

          received_signature = verifiable_query.hmac

          raise Errors::InvalidWebhookError, "Invalid webhook HMAC." unless Utils::HmacValidator.validate(request)

          unless handler

## Process a Webhook

To process an http webhook, you need to listen on the route(s) you provided during the Webhook registration process, then when the route is hit construct a `ShopifyAPI::Webhooks::Request` and call `ShopifyAPI::Webhooks::Registry.process`. This will verify the request did indeed come from Shopify and then call the specified handler for that webhook. An example in Rails is shown below:

```ruby
class WebhookController < ApplicationController
  def webhook
    ShopifyAPI::Webhooks::Registry.process(
      ShopifyAPI::Webhooks::Request.new(raw_body: request.raw_post, headers: request.headers.to_h)
    )
    render json: {success: true}.to_json
  end
end
