### Title
Attacker-Sized HyperSwap V2 Pre-Seed Overwhelms the Rebalance Swap Budget in `_seedRebalancing`, Diverting Curve-Raised LT to the Owner Instead of the Graduated LP - (File: `packages/contracts/src/Bonding.sol`)

### Summary
`finalizeGraduation` seeds the post-graduation HyperSwap V2 pool via `_seedUniswapV2Direct` → `_seedRebalancing` → `_pairRebalance` → `_routerDepositAndDispose`. This flow is explicitly designed to defend against a hostile pre-seed of the (TOKEN, LT) pair by rebalancing the pool toward the curve-close ratio before depositing. However, the rebalance swap is capped at `_swapBudget`, a value derived only from **this graduation's own LT/token inventory** (`ltFromPair` / `tokensForLP`), not from the size of the attacker's pre-seeded reserves. An attacker who mints a sufficiently large, skewed pre-seed into the HyperSwap V2 pair before `finalizeGraduation` runs can make the required rebalance swap size vastly exceed this fixed budget. The swap then executes at the tiny capped amount, leaving the pool essentially at the attacker's ratio. `_routerDepositAndDispose`'s `router.addLiquidity(..., 1, 1, ...)` call then only deposits the fraction of the graduation's `(tokensForLP, ltFromPair)` matching that attacker-dominated ratio, and the leftover LT — real, curve-raised value that was meant to back the LP — is swept away to the protocol owner via `_sweepLTToOwner` instead of being deposited into the graduated pool.

### Finding Description
The dual-trigger graduation flow computes `tokensForLP` and `ltFromPair` from the curve's own state in `_prepareGraduationLiquidity` [1](#0-0) , and these amounts are meant to seed the HyperSwap V2 LP at exactly the curve-close price.

`_seedUniswapV2Direct` branches into `_seedRebalancing` whenever the HyperSwap pair already has non-zero LP supply (Regime 3 — a "mint pre-seed") [2](#0-1) . Inside `_seedRebalancing`, the rebalance swap that's supposed to correct the attacker's ratio is bounded by `maxSwap`, computed purely from the graduation's own LT or token balance: [3](#0-2) 

`_swapBudget` caps that at 99% of the graduation's own inventory [4](#0-3) , and `_noFeeSwapInput` computes the swap size needed to reach the target ratio, capped by that same `maxSwap`: [5](#0-4) 

The needed swap size `s = sqrt(reserveIn * reserveOut * targetN/targetD) - reserveIn` scales with the magnitude of the attacker-controlled `reserveIn`/`reserveOut`. If the attacker seeds the pair with reserves that are large relative to `ltFromPair`/`tokensForLP` (which for a token that just crossed the graduation threshold can be a comparatively modest, bounded amount), `s` will exceed `maxSwap` by orders of magnitude, so the capped swap barely moves the pool off the attacker's chosen ratio.

`_routerDepositAndDispose` then deposits the graduation's remaining `(tokensForLP, ltFromPair)` via `router.addLiquidity(..., 1, 1, ...)`, which is quote-based and only pulls the amount matching the *current* (still attacker-dominated) pool ratio [6](#0-5) . Whichever side is in excess of that ratio-matched amount is left in the `Bonding` contract. Token-side excess is burned (a minor loss to circulating supply); LT-side excess is real curve-raised value, and is unconditionally swept to the protocol owner at the end of `finalizeGraduation` via `_sweepLTToOwner`: [7](#0-6) 

Because the attacker's own minted LP position in the pre-seeded pair is never locked (only `Bonding`'s subsequent deposit is sent to `LPLock` via `recordLock`), the attacker can withdraw their own pre-seed capital right after `finalizeGraduation` executes, since `finalizeGraduation` is fully permissionless and callable by anyone, including the attacker themselves [8](#0-7) .

### Impact Explanation
This diverts curve-raised LT — capital that traders paid into the bonding curve and that is supposed to back the graduated liquidity pool 1:1 at the curve-close price — into the protocol owner's wallet instead. The resulting LP is seeded far below the curve-close price/ratio and with materially less liquidity than the token's holders and creator were owed, permanently harming LP depth and post-graduation trading for that token. This satisfies the "LP seeded away from the curve close price" and "unbacked token/LT payouts" acceptance criteria: the graduated pool ends up under-collateralized relative to the curve raise, while curve-raised value is misappropriated to the owner instead of the LP.

### Likelihood Explanation
The attack is fully permissionless: the HyperSwap V2 factory allows anyone to `createPair`/`mint` a (TOKEN, LT) pair for any not-yet-graduated token before phase-1 graduation even fires, since both TOKEN (buyable on the curve) and LT (mintable via BounceTech) are freely acquirable by any unprivileged wallet. The attacker's own minted LP shares are never locked, so the capital used for the skewed pre-seed is largely recoverable by withdrawing liquidity from the pair immediately after `finalizeGraduation` runs (which the attacker can call themselves). The only real cost is trading fees/slippage on the rebalance swap and on the attacker's own later withdrawal, making this a low-cost, high-payoff griefing/value-extraction path reachable purely through `Zap.createToken`/`buy` (to acquire TOKEN/LT) plus direct calls to the HyperSwap V2 factory/pair and `Bonding.finalizeGraduation` — all permissionless entry points.

### Recommendation
Size the rebalance-swap (and the fallback decision to `_seedDirectMint`) relative to the attacker's pre-seeded reserve magnitude, not only the graduation's own fixed inventory — e.g., detect when `maxSwap` is insufficient to bring the post-swap ratio within an acceptable tolerance of the target and, in that case, route through `_seedDirectMint` (which overpowers the pre-seed at the cached ratio) rather than depositing a partially-rebalanced pool via `_routerDepositAndDispose`. Alternatively, bound the acceptable pre-existing reserve size before attempting the rebalance/deposit path at all, and treat any leftover LT that would otherwise be swept to the owner as belonging to the graduation (e.g., re-route it back into the LP deposit or refund it) rather than unconditionally transferring it to the protocol owner.

### Proof of Concept
1. Token `T` launches and its curve raises a modest amount of LT (`ltFromPair`) before crossing the graduation threshold; `tokenInfo[T].lifecycle` becomes `Graduating`.
2. Before anyone calls `finalizeGraduation(T)`, attacker calls `IUniswapV2Factory.createPair(T, lt)`, acquires a large amount of `T` (via `Zap.buy` before graduation freezes trading, or by any other route) and `lt` (via BounceTech `mint`), and calls `pair.mint(attacker)` directly, seeding reserves `(reserveToken, reserveLT)` at a ratio deliberately far from `tokensForLP/ltFromPair` and sized to be `N`× larger than the graduation's own `(tokensForLP, ltFromPair)`, where `N` is large enough that `_noFeeSwapInput`'s computed `s` exceeds `maxSwap = 0.99 * ltFromPair` (or `0.99 * tokensForLP`).
3. Attacker (or anyone) calls `Bonding.finalizeGraduation(T)`. `_ensureUniswapV2Pair` returns the attacker's pre-existing pair; `_seedUniswapV2Direct` routes to `_seedRebalancing` (Regime 3); the capped rebalance swap barely shifts the pool ratio; `_routerDepositAndDispose`'s `addLiquidity(min=1,1)` deposits only the small ratio-matched fraction of `(tokensForLP, ltFromPair)`.
4. The undeposited LT remainder is swept to `owner()` via `_sweepLTToOwner`, emitting `LTRescued`, instead of backing the graduated LP.
5. Attacker calls `pair.burn` (via the V2 router or directly) to withdraw their own originally-deposited liquidity from the now-seeded pair, recovering the bulk of their capital while the token's LP remains under-seeded and skewed away from the curve-close price.

    function finalizeGraduation(
        address tokenAddress
    ) external nonReentrant {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[tokenAddress];
        if (info.lifecycle != Lifecycle.Graduating) revert NotGraduating();

        address lt = info.ltAddress;
        PendingGraduation memory p = $.pendingGraduation[tokenAddress];

        // Anything in this contract beyond `p.ltFromPair` belongs to a
        // concurrent graduation on the same LT (Phase 1 transferred it
        // via `Router.graduate`) or to stray dust. Either way it is
        // off-limits to this graduation's deposit and sweep — see
        // `_routerDepositAndDispose` and `_sweepLTToOwner`.
        // Saturating subtract: a balance below `p.ltFromPair` shouldn't
        // be reachable in normal operation, but we keep finalize from
        // bricking on a Panic if any future code path or non-canonical
        // LT briefly violates the invariant.
        uint256 ltBalance = IERC20(lt).balanceOf(address(this));
        uint256 protectedLT = ltBalance > p.ltFromPair ? ltBalance - p.ltFromPair : 0;

        address lpPair = _ensureUniswapV2Pair(tokenAddress, lt);
        uint256 liquidity = _seedUniswapV2Direct(tokenAddress, lt, lpPair, p.tokensForLP, p.ltFromPair, protectedLT);

        _sweepLTToOwner(lt, protectedLT);

        info.lifecycle = Lifecycle.Graduated;
        $.graduatedPair[tokenAddress] = lpPair;
        delete $.pendingGraduation[tokenAddress];

        LPLock($.lpLock).recordLock(tokenAddress, lpPair, liquidity);

        emit TokenGraduated(tokenAddress, lpPair, liquidity, p.tokensForLP, p.lpBurned, p.unsoldBurned);
    }

    /// @dev Send LT held by this contract above `keep` to the owner,
    ///      emitting `LTRescued`. Called at the end of
    ///      `finalizeGraduation` with `keep = protectedLT` (any escrow
    ///      that doesn't belong to this graduation), so only THIS
    ///      graduation's rebalance residue lands on the owner. No-op on
    ///      the empty-pair fast path (nothing to sweep).
    function _sweepLTToOwner(
        address lt,
        uint256 keep
    ) internal {
        uint256 bal = IERC20(lt).balanceOf(address(this));
        if (bal <= keep) return;
        uint256 amount = bal - keep;
        address recipient = owner();
        IERC20(lt).safeTransfer(recipient, amount);
        emit LTRescued(lt, recipient, amount);
    }

    function _prepareGraduationLiquidity(
        address tokenAddress
    ) internal returns (uint256 tokensForLP, uint256 ltFromPair, uint256 lpBurned, uint256 unsoldBurned) {
        address pairAddr = _s().tokenInfo[tokenAddress].pair;
        (uint256 tokenReserve, uint256 assetReserve) = IPair(pairAddr).getReserves();

        unsoldBurned = IPair(pairAddr).tokenBalance();
        if (unsoldBurned > 0) {
            Token(tokenAddress).burn(pairAddr, unsoldBurned);
        }

        ltFromPair = assetReserve - _launchTimeVirtualLtReserve(tokenAddress, pairAddr);
        if (ltFromPair > 0) {
            _s().router.graduate(tokenAddress, ltFromPair);
        }

        tokensForLP = assetReserve == 0 ? 0 : (ltFromPair * tokenReserve) / assetReserve;
        if (tokensForLP > LP_RESERVE) tokensForLP = LP_RESERVE;

        lpBurned = LP_RESERVE - tokensForLP;
        if (lpBurned > 0) {
            Token(tokenAddress).burn(address(this), lpBurned);
        }
    }

    function _routerDepositAndDispose(
        address tokenAddress,
        address lt,
        uint256 protectedLT
    ) internal returns (uint256 liquidity) {
        BondingStorage storage $ = _s();
        address routerAddr = $.uniswapV2Router;
        address lpLock_ = $.lpLock;
        uint256 remToken = IERC20(tokenAddress).balanceOf(address(this));
        // Subtract `protectedLT` (LT that doesn't belong to this graduation
        // — concurrent escrows or stray dust, snapshotted at the top of
        // `finalizeGraduation`) so the deposit allowance can never pull
        // another graduation's earmark or accidentally absorb dust into a
        // locked LP.
        uint256 ltBal = IERC20(lt).balanceOf(address(this));
        uint256 remLT = ltBal > protectedLT ? ltBal - protectedLT : 0;

        if (remToken > 0 && remLT > 0) {
            IERC20(tokenAddress).forceApprove(routerAddr, remToken);
            IERC20(lt).forceApprove(routerAddr, remLT);
            (,, liquidity) = IUniswapV2Router02(routerAddr)
                .addLiquidity(tokenAddress, lt, remToken, remLT, 1, 1, lpLock_, block.timestamp);
            IERC20(tokenAddress).forceApprove(routerAddr, 0);
            IERC20(lt).forceApprove(routerAddr, 0);
        }

        // Burn off-ratio TOKEN remainder (`Bonding` is the Token owner).
        // Hostile pre-seeds reduce circulating supply by the attacker's
        // wasted-side share, net positive for honest holders.
        uint256 leftoverToken = IERC20(tokenAddress).balanceOf(address(this));
        if (leftoverToken > 0) {
            Token(tokenAddress).burn(address(this), leftoverToken);
        }
        // LT remainder is third-party — we cannot burn it. It stays in
        // this contract until `finalizeGraduation`'s post-bookend sweeps
        // it to the owner. Honest graduations never reach this code path,
        // so the residue is zero outside attack scenarios.
    }

    function _noFeeSwapInput(
        uint256 reserveIn,
        uint256 reserveOut,
        uint256 targetN,
        uint256 targetD,
        uint256 maxSwap
    ) internal pure returns (uint256) {
        if (reserveIn == 0 || reserveOut == 0 || targetN == 0 || targetD == 0 || maxSwap == 0) {
            return 0;
        }
        uint256 product = Math.mulDiv(reserveIn * reserveOut, targetN, targetD);
        uint256 newIn = Math.sqrt(product);
        if (newIn <= reserveIn) return 0;
        uint256 s = newIn - reserveIn;
        return s > maxSwap ? maxSwap : s;
    }
