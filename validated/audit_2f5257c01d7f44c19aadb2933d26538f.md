### Title
Unvalidated swap-route pool addresses can inject unauthorized token transfers under the caller's authorization - ([File: contracts/controller/src/strategies/swap.rs])

### Summary
Controller strategy entrypoints accept caller-supplied `swap` bytes and execute them through the configured router without binding the route to trusted venue addresses. [1](#0-0)  The router's payload format treats arbitrary `assets` entries as pool addresses, and its structural validation checks only index bounds and token-chain consistency, not whether the selected pool is a legitimate or allowlisted venue. [2](#0-1)  A malicious venue can therefore run inside the victim's signed strategy call and add an unrelated token transfer to the victim's authorization tree, while still returning enough output to satisfy the router's measured-output checks. [3](#0-2) 

### Finding Description
`swap_collateral` authenticates `caller`, requires account owner or delegate authority, withdraws `amount` of `current`, and passes the caller-supplied `swap` bytes into the router path. [4](#0-3)  `swap_tokens` authorizes only the exact controller-to-router input transfer, but then passes the opaque `swap` payload to `execute_strategy`. [5](#0-4)  Its post-call checks bound only the controller's routed input spend and require a positive `token_out` balance increase; they do not constrain which contracts the route invokes or what those contracts ask the original caller to authorize. [6](#0-5) 

In the router, `Program::decode` resolves `token_in`, `token_out`, and `min_out` from caller-controlled registries, and `execute_op` turns `assets[idx_a]` into `SwapHop.pool`. [7](#0-6)  For a swap opcode, the router withdraws the calculated vault input and dispatches the hop to the payload-selected `pool`; no trusted-pool registry or address allowlist is consulted. [3](#0-2)  The Soroswap adapter invokes `get_reserves` and `swap` on that payload-selected address, while the Aquarius adapter invokes its `swap` method after authorizing the router's input transfer. [8](#0-7) [9](#0-8) 

Because the original `caller.require_auth()` authorization remains the root authorization for the transaction, token calls made by the malicious venue can be recorded as sub-invocations beneath the strategy call. [10](#0-9)  The controller's exact `authorize_transfer_as_current` entry protects only the controller's own token transfer and explicitly allows no sub-invocations, but it does not prevent a route-selected contract from requesting a separate token transfer from the original caller. [11](#0-10) 

### Impact Explanation
A victim who signs the simulated authorization tree for a malicious route can lose tokens unrelated to the lending operation, including assets that are not listed by the protocol and were never supplied as collateral. The malicious pool can return or fund a sufficient `token_out` amount so that the router's `total_min_out` check succeeds and the controller observes a positive measured output. [12](#0-11) [13](#0-12)  The injected transfer is outside the economic checks because it is neither the controller's routed input nor its measured output. [6](#0-5) 

### Likelihood Explanation
An attacker needs to cause an account owner or active delegate to submit a crafted `swap` payload through `multiply`, `swap_debt`, `swap_collateral`, or `repay_debt_with_collateral`; all four converge on the same router execution path. [14](#0-13)  This is not an unauthenticated drain of a foreign account: the victim must authorize the poisoned invocation tree. The practical risk remains material because routes are opaque serialized bytes, venue addresses come from the payload's `assets` registry, and the protocol accepts any address that satisfies the selected venue's call surface. [15](#0-14) [16](#0-15) 

### Recommendation
Validate route-selected venue addresses against a governance-controlled allowlist or a venue-specific factory/registry before dispatching a hop. At minimum, reject unrecognized pool addresses for every opcode and record the expected venue contract identity alongside the encoded route. The controller should also reject routes that produce caller-authorization children other than the expected input pull, although on-chain enforcement is preferably performed by restricting the pool addresses the router can invoke.

### Proof of Concept
1. Deploy a malicious contract exposing `get_reserves() -> (i128, i128)` and `swap(i128, i128, Address)`, so it can be selected as a Soroswap hop. Its `swap` implementation calls `token::Client::new(&env, &victim_wallet_token).transfer(&victim, &attacker, &amount)` and then transfers a positive amount of the route's `token_out` to the router.
2. Construct `StrategyPayload { amounts, assets, ops }` with `assets` containing the malicious pool, the legitimate `token_in`, and the legitimate `token_out`; encode one swap instruction whose `idx_a` selects the malicious pool.
3. Have the victim invoke `swap_collateral(caller, account_id, current, amount, new, swap)`, where `current.asset == token_in`, `new.asset == token_out`, and `swap` is the crafted payload.
4. The controller authenticates the victim and executes `swap_tokens`; the router decodes the route, dispatches to the malicious pool, and records the malicious wallet-token transfer under the victim's authorization tree. If that simulated tree is signed, the unrelated wallet token moves to the attacker while the returned output allows the strategy's positive-output and final-risk checks to pass.

    /// Validates every instruction's opcode, mode, and indices before execution begins,
    /// including the `Prev` chain, same-token swaps, and split-weight bounds.
    fn validate(&self, env: &Env, assets_len: u32, amounts_len: u32, weight_count: u32) {
        for i in 0..self.op_count {
            let record = self.raw(i);
            let Some(opcode) = Opcode::from_u8(record[field::OPCODE]) else {
                panic_with_error!(env, Error::InvalidRouteXdr);
            };
            let mode = Mode::from_u8(record[field::MODE]);
            let (idx_a, idx_b, idx_c) = (
                record[field::POOL] as u32,
                record[field::TOKEN_IN] as u32,
                record[field::TOKEN_OUT] as u32,
            );

            // `Prev` is a purely structural link: the predecessor must exist,
            // must have a single output, and that output must be this
            // instruction's input.
            if mode == Mode::Prev {
                if i == 0 {
                    panic_with_error!(env, Error::BrokenTokenChain);
                }
                let previous = self.raw(i - 1);
                let produced = match Opcode::from_u8(previous[field::OPCODE]) {
                    // A swap produces its `token_out`, a mint its share token.
                    Some(Opcode::Swap(_)) => previous[field::TOKEN_OUT],
                    Some(Opcode::Mint) => previous[field::TOKEN_IN],
                    // A burn releases every constituent at once.
                    _ => panic_with_error!(env, Error::BrokenTokenChain),
                };
                if idx_b != produced as u32 {
                    panic_with_error!(env, Error::BrokenTokenChain);
                }
            }
            match mode {
                Mode::Fixed(idx) if idx as u32 >= amounts_len => {
                    panic_with_error!(env, Error::InvalidRouteXdr)
                }
                Mode::Ppm(idx) if idx as u32 >= weight_count => {
                    panic_with_error!(env, Error::InvalidRouteXdr)
                }
                _ => {}
            }

            if idx_a >= assets_len || idx_b >= assets_len {
                panic_with_error!(env, Error::InvalidRouteXdr);
            }
            match opcode {
                Opcode::Swap(_) => {
                    if idx_c >= assets_len {
                        panic_with_error!(env, Error::InvalidRouteXdr);
                    }
                    if idx_b == idx_c {
                        panic_with_error!(env, Error::SameToken);
                    }
                }
                // Liquidity legs spend the full vault balance, so only `Mode::All` is valid.
                Opcode::Burn | Opcode::Mint => {
                    if mode != Mode::All {
                        panic_with_error!(env, Error::InvalidRouteXdr);
                    }
                    if idx_c >= amounts_len {
                        panic_with_error!(env, Error::InvalidRouteXdr);
                    }
                }
            }
        }

/// Authorizes, on behalf of the current contract, one `transfer(from, to, amount)`
/// call on `token_addr` made deeper in the next contract call (for example by
/// the pool). The entry allows no further sub-invocations.
pub fn authorize_transfer_as_current(
    env: &Env,
    token_addr: &Address,
    from: &Address,
    to: &Address,
    amount: i128,
) {
    let entry = InvokerContractAuthEntry::Contract(SubContractInvocation {
        context: ContractContext {
            contract: token_addr.clone(),
            fn_name: symbol_short!("transfer"),
            args: (from.clone(), to.clone(), amount).into_val(env),
        },
        sub_invocations: Vec::new(env),
    });
    env.authorize_as_current_contract(vec![env, entry]);
}
