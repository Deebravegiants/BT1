## Finding: Webhook `shop-domain` header is trusted without being covered by the HMAC signature

### Title
Webhook shop attribution is not bound to the HMAC signature, allowing cross-tenant webhook spoofing - (File: `lib/shopify_api/webhooks/request.rb`, `lib/shopify_api/webhooks/registry.rb`)

### Summary
`ShopifyAPI::Webhooks::Registry.process` verifies only that the raw HTTP body has a valid HMAC, but the `shop` (and `topic`, `webhook_id`, `api_version`) values that the handler receives and acts on are taken straight from unauthenticated HTTP headers that are never included in the signed payload.

### Finding Description
`ShopifyAPI::Webhooks::Request#to_signable_string` returns only the raw body: [1](#0-0) 

The `shop`, `topic`, `api_version`, and `webhook_id` accessors read directly from HTTP headers, which are attacker-controlled input on any inbound POST to the app's webhook endpoint: [2](#0-1) 

`Registry.process` validates the HMAC over the body only, then dispatches to the handler using `request.shop` taken from the header, with no cross-check that this header value is bound to the signature: [3](#0-2) 

This is the exact identity-binding gap called out by the rules: "a field acted on but not covered by the HMAC." The equality that should hold is:
`shop authenticated by HMAC == shop the handler acts on`
but in this implementation:
`shop the handler acts on = header value (never signed)` while `HMAC covers only raw_body`.

### Impact Explanation
Because the HMAC only proves the body wasn't tampered with (i.e., it was produced with the app's `api_secret_key` over that exact body), it does not prove which shop the body belongs to. An attacker who can obtain any one valid `(raw_body, hmac)` pair — e.g., from their own store's legitimate webhook delivery, from a public webhook payload sample, or by replaying a captured request — can POST that same body+HMAC to the app's webhook endpoint while setting the `x-shopify-shop-domain` (or `shopify-shop-domain`) header to a different, victim shop's domain. The `Registry.process` code will accept the HMAC (it validates against the body, which is unchanged) and hand the handler a `WebhookMetadata` claiming the event is for the victim shop. If the host application's handler uses `data.shop` to look up a stored session/access token and perform actions (e.g., updating records, triggering side effects) for that shop, the attacker achieves cross-tenant event injection/spoofing — attributing forged webhook data to an arbitrary merchant.

### Likelihood Explanation
Exploitation only requires network access to the app's public webhook endpoint and a single previously-observed valid `(body, hmac)` pair signed under the same `api_secret_key` (trivially available to the attacker if they operate any shop that installed the same app, since the app's `api_secret_key` is shared across all its installations/shops). No access token, session, or privileged credential is needed.

### Recommendation
Bind the shop (and topic/webhook_id/api_version) into the signable string, or otherwise independently verify that the `shop-domain` header matches a shop with a known, valid session/registration before dispatching to handlers, rather than trusting the header value that sits outside the HMAC-covered payload.

### Proof of Concept
1. Attacker's own shop `attacker.myshopify.com` receives (or attacker crafts and sends themselves) a legitimate webhook: body `{"id":1}"`, header `x-shopify-hmac-sha256: <valid HMAC of body under the shared api_secret_key>`, `x-shopify-shop-domain: attacker.myshopify.com`.
2. Attacker resends the identical body and HMAC header to the app's webhook endpoint, but sets `x-shopify-shop-domain: victim.myshopify.com`.
3. `ShopifyAPI::Webhooks::Registry.process` calls `Utils::HmacValidator.validate(request)`, which succeeds because the HMAC only ever covered `raw_body`, per [1](#0-0) .
4. The handler is invoked with `WebhookMetadata` where `shop == "victim.myshopify.com"`, sourced purely from the unauthenticated header, per [4](#0-3) , letting the attacker inject forged data attributed to a shop they don't control.
