### Title
i128 overflow in time-scaled index accrual permanently freezes a market - (File: common/src/rates/simulate.rs)

### Summary
Analogous to CVE-2017-15422's integer-overflow-in-date-handling class: XOXNO Lending's interest accrual multiplies a scaled `Ray` balance by a time-grown index in `i128`. Once `borrowed × borrow_index` or `supplied × supply_index` exceeds `i128::MAX`, `scaled_to_original` panics with `MathOverflow` inside `accrue_step`, which runs inside `global_sync` before every state-changing verb. The `MAX_BORROW_INDEX_RAY` cap does not prevent this because the *value* ceiling is hit before the *index* ceiling on large markets, and there is no path that skips accrual. The market — including all suppliers' principal — is frozen permanently.

### Finding Description
`accrue_step` in `common/src/rates/simulate.rs` unscales both book totals before computing utilization:

```rust
let borrowed_original = scaled_to_original(env, borrowed, borrow_index);
let supplied_original = scaled_to_original(env, supplied, supply_index);
``` [1](#0-0) 

`scaled_to_original` is `scaled.mul(env, index)`, i.e. `scaled * index / RAY` in `i128` (widening only the intermediate, with `to_i128` panicking on a result that doesn't fit). [2](#0-1) [3](#0-2) 

`update_borrow_index` multiplies-then-clamps to `MAX_BORROW_INDEX_RAY` (1e36), so the index itself is bounded — but the *product* `borrowed_scaled × borrow_index` is not. `i128::MAX ≈ 1.7e38`, so any market whose scaled book exceeds ~170 RAY-units crosses the cliff once the index grows past ~170×, well before the 1e36 index cap at steep rates. [4](#0-3) 

`global_sync` invokes `accrue_step` for every elapsed chunk, and every pool verb accrues first, so once the panic condition is reached there is no entry point that can operate on the market. [5](#0-4) 

The repo's own harness test confirms this is reachable and permanent: a 1-billion-token market at ~98% utilization on a steep curve hits `MATH_OVERFLOW` within tens of years, after which `update_indexes`, `withdraw`, and `repay` all revert, with the borrow index still below the cap. [6](#0-5) 

### Impact Explanation
Permanent freezing of funds. Once `borrowed × borrow_index` (or `supplied × supply_index`) overflows `i128`, every entrypoint that touches the market — `withdraw`, `repay`, `liquidate`, `borrow`, `supply`, `update_indexes` — reverts inside `global_sync`. Suppliers cannot exit, borrowers cannot repay or be liquidated, and the index cap never engages. All tokens held by the pool for that market are bricked.

### Likelihood Explanation
A single unprivileged address can set this up: supply a very large amount to lift the book scale (caps permitting; caps are validated only against asset decimals, not against the `i128` value ceiling times worst-case index growth), and borrow to sustain high utilization so the index compounds quickly. No admin action is needed after market listing; the trigger is simply elapsed wall-clock time plus one caller invoking `update_indexes` or any verb once the product crosses `i128::MAX`. The cost is capital-heavy and the horizon is long on realistic curves, but it is fully permissionless and irreversible — hence Medium.

### Recommendation
Bound the domain before it reaches the cliff:
- In `accrue_step`, detect `scaled × index` overflow before `scaled_to_original` and clamp the effective index (e.g. treat the market as capped at the largest index that keeps `borrowed × index` and `supplied × index` inside `i128`), mirroring how `MAX_BORROW_INDEX_RAY` already halts accrual.
- Alternatively, at listing / `supply` time, enforce a market-level cap such that `max_scaled × MAX_BORROW_INDEX_RAY` fits `i128`, shrinking `max_cap_for_decimals` by the worst-case index growth factor.
- At minimum, allow a "ceiling mode" where, upon overflow, accrual stops advancing (frozen indexes) but withdrawals and repayments still work against the last valid index, converting permanent freeze into halted-interest degradation.

### Proof of Concept
Conceptual, matching the existing harness test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` (`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321`):

1. Attacker calls controller `supply` with ~1e9 whole units of an 18-decimal asset (scaled book ≈ 1e36 RAY-units).
2. Attacker supplies collateral in a second market and calls `borrow` to push utilization to ~98% on a steep curve (`max_borrow_rate ≈ 175%` APR).
3. Time advances; anyone (or the attacker) calls `update_indexes`. Each call runs `global_sync` → `accrue_step`; `borrow_index` grows ~e^(1.75·t) per year.
4. After the index passes ~170× (a few years at that rate, decades on milder curves), `scaled_to_original(borrowed, borrow_index)` panics `MathOverflow` while `borrow_index < MAX_BORROW_INDEX_RAY`.
5. From then on, `withdraw`, `repay`, `liquidate`, and `update_indexes` on that market all revert — verified in the test at lines 348–356 — permanently locking all supplier and collateral funds routed through that market.

/// Computes `floor(x * y / d)`, rounding toward negative infinity for a negative quotient.
/// Panics with `GenericError::DivisionByZero` if `d == 0`, or with
/// `GenericError::MathOverflow` if the result does not fit in `i128`.
pub fn mul_div_floor(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    require_nonzero_divisor(env, d);
    if let Some(quotient) = x
        .checked_mul(y)
        .and_then(|product| div_floor_i128(product, d))
    {
        return quotient;
    }
    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    let nonneg = quotient_is_nonnegative(x, y, d);
    to_i128(env, &div_floor_i256(env, &x256.mul(&y256), &d256, nonneg))
}

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}
```

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
