### Title
Cross-tenant session hijacking via unauthenticated `SessionCookie` value trusted as a session identifier - (File: lib/shopify_api/utils/session_utils.rb)

### Summary
`ShopifyAPI::Utils::SessionUtils.current_session_id` derives the session identifier used to look up a merchant's stored session (and thus their access token) directly from a browser-supplied cookie, with no cryptographic binding proving that the requester is actually authenticated for that shop. This mirrors the report's bug class: a value is *acted on* (used as the tenant-identifying key) without being *covered* by any integrity check, unlike the sibling code path that derives the session id from a signed JWT.

### Finding Description
Two ways exist in this gem to resolve "which session/shop is this request for":

1. Embedded apps with a session token: `session_id_from_shopify_id_token` parses and HS256-signature-verifies a JWT via `Auth::JwtPayload.new(id_token)` before deriving `shop` from the verified `dest` claim. [1](#0-0) [2](#0-1) 

2. Non-embedded apps (or the embedded fallback when no id token is present) read the session id straight out of the `shopify_app_session` cookie with no signature, MAC, or format check at all: [3](#0-2) [4](#0-3) 

The `SessionCookie` object itself carries no HMAC or signature over its `value` field — it is a plain struct with only `name`, `value`, and `expires`: [5](#0-4) 

Session identifiers produced by this library are deterministic and predictable strings derived only from the (public) shop domain: `"offline_#{shop}"` or `"#{shop}_#{user_id}"`. [6](#0-5) 

The identity binding that should hold is: `(shop identity encoded in the session id returned by current_session_id)` == `(shop identity actually authenticated for this request)`. On the JWT branch this equality is enforced (the id is derived only after HS256 signature verification against `Context.api_secret_key`, binding it to Shopify's own signing key). On the cookie branch, the equality is not enforced at all — the returned session id is exactly whatever bytes the client sent in its own cookie, unauthenticated.

### Impact Explanation
If a host application follows the gem's documented cookie flow — using `current_session_id`/`cookie_session_id` as the lookup key into its own `SessionRepository` (as shown in the gem's own `oauth.md` example, where the cookie's `value` is set to `session.id` on completion) — then any user who can set/edit their own browser cookie for the app's domain can substitute a different, guessable session id (`offline_{othershop}.myshopify.com`) and have the host app load and act with another merchant's stored session, including that shop's access token. This is a cross-tenant access / session-fixation class issue, matching the Critical impact bar ("cross-tenant access").

### Likelihood Explanation
Session ids are deterministic and derivable from public information (the shop's `myshopify.com` domain, which is often guessable or discoverable), and nothing in the gem prevents a client from presenting an arbitrary value for this cookie since the cookie is never signed or verified server-side by this library. Exploitability ultimately also depends on how the host application uses the returned id (e.g., whether it independently re-authenticates or trusts the id blindly), which is a caveat on certainty since the gem documentation exclusively shows the id being used as a direct lookup key without further validation.

### Recommendation
Do not treat the raw cookie `value` as a trusted, tenant-authenticated identifier. Either (a) sign/MAC the cookie value (e.g., HMAC it with `Context.api_secret_key` at issuance and verify before use in `cookie_session_id`), or (b) clearly document that the cookie-based session id must never be used alone to authorize access to another shop's resources without an additional authentication check, mirroring the cryptographic binding already used on the JWT path.

### Proof of Concept
1. Complete OAuth normally as `Shop A`; the app sets cookie `shopify_app_session=offline_shop-a.myshopify.com` (per the documented flow) as shown in `docs/usage/oauth.md`.
2. As an attacker who is a legitimate/unprivileged user of the same app but a different shop (`Shop B`), replace the browser's `shopify_app_session` cookie value with the guessed/known string `offline_shop-a.myshopify.com`.
3. Call any endpoint that relies on `ShopifyAPI::Utils::SessionUtils.current_session_id`/`cookie_session_id` to resolve the session id and then loads the corresponding session from the host's `SessionRepository`. [3](#0-2) 
4. Because `cookie_session_id` performs no verification, the host app resolves and returns `Shop A`'s session (including its access token) to the attacker.

        def current_session_id(shopify_id_token, cookies, online)
          if Context.embedded?
            if shopify_id_token
              id_token = shopify_id_token.gsub("Bearer ", "")
              session_id_from_shopify_id_token(id_token: id_token, online: online)
            else
              # falling back to session cookie

              cookie_session_id(cookies)
            end

            raise Errors::CookieNotFoundError, "Session cookie not found for app" unless
              cookies && cookies[Auth::Oauth::SessionCookie::SESSION_COOKIE_NAME]

            cookie_session_id(cookies)
          end
        end

        def session_id_from_shopify_id_token(id_token:, online:)
          raise Errors::MissingJwtTokenError, "Missing Shopify ID Token" if id_token.nil? || id_token.empty?

          payload = Auth::JwtPayload.new(id_token)
          shop = payload.shop

          if online
            jwt_session_id(shop, T.must(payload.sub))
          else
            offline_session_id(shop)
          end
        end

      class SessionCookie < T::Struct
        extend T::Sig

        SESSION_COOKIE_NAME = "shopify_app_session"

        const :name, String, default: SESSION_COOKIE_NAME
        const :value, String
        const :expires, T.nilable(Time)

        alias_method :eql?, :==
        sig { params(other: T.nilable(SessionCookie)).returns(T::Boolean) }
        def ==(other)
          return false unless other

          name == other.name &&
            value == other.value &&
            expires == other.expires
        end
