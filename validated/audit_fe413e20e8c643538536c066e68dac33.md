### Title
Shared `CallDispatcher` balance is swept in full and attributed to the calling order without ownership isolation, letting a token with multiple valid addresses (or any pre-existing dispatcher balance) be stolen via `placeOrder` — (File: `evm/src/apps/IntentGatewayV2.sol`)

### Summary
`IntentGatewayV2.placeOrder`'s predispatch flow measures how much of an input token to pull from the shared `CallDispatcher` contract by reading its *raw* `balanceOf`, not a delta attributable to the current order, then transfers that whole balance into the gateway and (if it does not exceed the requested amount) credits it directly to the caller's escrowed order. This is the same root cause as the reported `NapierPool.skim` bug: computing "how much is owed to me" from an unqualified `balanceOf` read on a shared contract rather than tracking ownership per-depositor, which is unsafe whenever a token can have more than one valid contract address (e.g. TUSD-style tokens) or whenever the shared contract can otherwise end up holding tokens that are not attributable to the current caller.

### Finding Description
In the predispatch branch of `placeOrder`, the gateway builds sweep calls using the dispatcher's total balance for each input token: [1](#0-0) 

`balance = IERC20(token).balanceOf(dispatcher)` is the *entire* current balance of `token` held by the singleton `CallDispatcher` — not a value scoped to what this particular order's `predispatch.call` actually produced. That whole balance is then swept to the gateway: [2](#0-1) 

and, if the amount received does not exceed `order.inputs[i].amount`, it is credited to the order verbatim rather than reverting or requiring an exact match: [3](#0-2) 

`_params.dispatcher` is a single, persistent `CallDispatcher` instance shared by every order placed through this gateway deployment — it is not deployed per-order: [4](#0-3) 

The exact same unqualified-`balanceOf`-based sweep pattern (drain the dispatcher's full balance for a token and attribute it to `_orders[commitment][token]`) also exists in the Tron variant: [5](#0-4) 

This mirrors `NapierPool::skim`'s flaw exactly: the contract trusts `balanceOf(sharedAddress)` as ground truth for "funds belonging to me" instead of tracking a delta owned by the specific caller/order. If the underlying token has multiple valid contract addresses that share the same balance storage (the TUSD case cited in the report), or if the shared `CallDispatcher` ends up holding a balance that is not attributable to the current caller's `predispatch.call` for any other reason, that balance is swept in full and silently attributed to whichever order happens to call `placeOrder` next, with no check that it actually originated from that order's own predispatch execution.

### Impact Explanation
Any user reachable by a single `placeOrder` transaction with a non-empty `predispatch` section can have the gateway attribute tokens it does not own to their own escrowed order. Because escrow amounts (`_orders[commitment][token]`) are later paid out on fill/cancel/refund paths, an attacker who can arrange for the shared `CallDispatcher` to hold a nonzero balance of an input token that is not truly theirs (via a multi-address token alias, or any other means of populating dispatcher balance outside the current order's own deposit) can have that balance credited to their own order and ultimately withdrawn — a direct theft of funds analogous to draining a Napier pool via `skim`.

### Likelihood Explanation
Within a single, ordinary transaction the dispatcher is fully drained by the sweep (its balance goes from whatever it held to zero for the swept token), so exploitation requires a way to get token balance sitting in the singleton `CallDispatcher` contract that is not attributable to the initiating order's own predispatch deposit — most directly via a token that has multiple valid contract addresses (the exact bug class named in the report), where the balance recorded under address A is fully readable and sweepable under address B. Because the `dispatcher` address is a fixed, discoverable, shared contract used by all orders on a given gateway deployment, this is a systemic design flaw rather than an edge case, and it is reachable with nothing more than a crafted `placeOrder` call.

### Recommendation
Do not use raw `balanceOf(dispatcher)` as the sweep amount. Instead, measure only the delta produced by the current order's own `predispatch.call` (snapshot dispatcher balance immediately before dispatching the predispatch call for each input token and sweep only the increase), and revert if the dispatcher's balance decreased or is inconsistent with what this order deposited. Alternatively, require the `predispatch.call` to transfer tokens directly to a per-order or per-call escrow address rather than relying on a shared dispatcher's ambient balance.

### Proof of Concept
1. Gateway is deployed with a shared `_params.dispatcher` address, per `Params` struct used in `initialize`.
2. Suppose input token `T` is a token with two valid contract addresses `A` and `B` that reflect the same underlying balance (as with TUSD).
3. Attacker crafts an order whose `predispatch.assets`/`predispatch.call` references token address `B`, while some balance of `T` is already reflected under `CallDispatcher` via address `A` (e.g., left by an unrelated interaction, or simply because `A` and `B` share storage and any balance sent to the dispatcher under either alias is visible under both).
4. At [6](#0-5)  `IERC20(token).balanceOf(dispatcher)` returns the full shared balance regardless of which alias actually funded it, and the entire amount is swept to the gateway and credited to the attacker's order at [3](#0-2) , crediting the attacker with tokens not deposited via their own predispatch call.

contract CallDispatcher is ICallDispatcher {
    /**
     * @dev error thrown when the target is not a contract.
     */
    error NotContract(address target);

    /**
     * @dev error thrown when a call fails.
     */
    error CallFailed(address target, bytes result);

    /**
     * @dev Receive function to accept ETH transfers
     */
    receive() external payable {}

    /**
     *  @dev reverts if the target is not a contract or if any of the calls reverts.
     */
    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
