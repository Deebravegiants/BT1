Based on my investigation, alt.fun's codebase has no analog to this bug class. The reported issue is specific to JUSD's design where the owner can swap between multiple oracle adapter implementations (`JOJOOracleAdaptor`, `UniswapPriceAdaptor`, `EmergencyOracle`) that don't share a common interface, causing reverts when a secondary oracle is substituted for a failed primary one.

In alt.fun, the reserve asset for each bonding curve is a single `IBounceLeveragedToken` (LT) address fixed at launch via `Bonding.launch`'s `ltAddress` parameter, and every consumer (`Router`, `Bonding`, `Zap`) reads that LT consistently through the same `IBounceLeveragedToken` interface [1](#0-0) . There is no mechanism to swap the reserve asset or its price/exchange-rate source to an alternate implementation after launch — the docs explicitly note that if BounceTech retires an LT, "bonding curves already pointing at the old LT keep trading — `mint` / `redeem` / `exchangeRate` still work" with no swap-in of a secondary adapter [2](#0-1) .

The closest constructs that involve pluggable/allowlisted addresses — `FeeVault`'s depositor allowlist and `Bonding`'s router allowlist — use a single consistent interface (`IZap`/direct `accrue` calls) for every allowlisted entry, with no alternate-interface adapter that could be swapped in incompatibly [3](#0-2) [4](#0-3) . `Router`, `Pair`, and `IPair` are likewise used uniformly across `Bonding`, `Zap`, and the graduation flow with no alternate incompatible implementation swapped in at runtime [5](#0-4) .

Since alt.fun has no reachable, unprivileged path that hits an interface mismatch between interchangeable price/reserve-asset adapters, there is no valid analog per the stated rules (which require rejecting bugs without a real reachable path and real fund impact).

**Retired LTs.** The reserve asset is an external BounceTech LT. If BounceTech de-registers it (it redeploys a fresh LT at a new address and flips the old address's `ltExists` to `false`), bonding curves already pointing at the old LT keep trading — `mint` / `redeem` / `exchangeRate` still work — but its `exchangeRate` stops tracking the underlying, so leverage is effectively frozen. The USD trigger above then can't ripen further; the supply trigger still graduates the token, and holders can always exit via `redeem`, so no funds are stranded. `Bonding.launch` rejects new bonding curves against a retired LT (its `ltExists` gate), so only pre-existing bonding curves are affected. See root `AGENTS.md` for the full note.
