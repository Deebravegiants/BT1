### Title
Permanent market freeze from RAY value overflow during mandatory accrual - (File: common/src/rates/simulate.rs)

### Summary
An unprivileged attacker can drive a sufficiently large, highly utilized market into an unrecoverable state where `supplied * supply_index` or `borrowed * borrow_index` exceeds the `i128` RAY-value domain. Because every pool mutation synchronizes interest before executing the requested operation, subsequent `withdraw`, `repay`, `liquidate`, `clean_bad_debt`, `recapitalize`, and `update_indexes` calls revert with `MathOverflow`, permanently freezing the market's funds. [1](#0-0) [2](#0-1) 

### Finding Description
`global_sync` accrues every elapsed-time chunk before a market mutation is applied. [1](#0-0) 

Each accrual chunk first reconstructs the full current debt and supply values by calling `scaled_to_original` on the persisted scaled balances and indexes. [2](#0-1) 

`scaled_to_original` performs a checked RAY multiplication and reverts on overflow rather than saturating. [3](#0-2) [4](#0-3) 

The borrow-index ceiling does not prevent this condition: `update_borrow_index` clamps only after `scaled_to_original` has already evaluated the current value, and `update_supply_index` likewise evaluates `supplied * old_index` before calculating and clamping the new index. [5](#0-4) [6](#0-5) 

The controller exposes the state-growing path through `supply` and `borrow`, while `update_indexes` is callable by any authorized caller and forwards the selected market to the pool's accrual path. [7](#0-6) [8](#0-7) 

Once either market value product exceeds `i128::MAX`, the overflow is encountered before debt can be reduced, collateral withdrawn, bad debt written down, or the market recapitalized. [9](#0-8) [10](#0-9) 

### Impact Explanation
All token principal and accrued yield held by the affected market become permanently inaccessible because the mandatory pre-operation accrual traps before any balance-changing logic runs. [1](#0-0) [11](#0-10) 

Borrowers cannot repay, suppliers cannot withdraw, liquidators cannot reduce unhealthy debt, and recapitalization cannot restore operation because all those paths load and synchronize the same market state. [12](#0-11) [13](#0-12) 

The existing regression test demonstrates that an admitted whale-scale, high-utilization market can hit `MathOverflow` before the configured index ceiling and that both withdrawal and repayment subsequently fail with the same error. [14](#0-13) 

### Likelihood Explanation
The attack is economically expensive but does not require privileged access, leaked keys, oracle manipulation, malformed token behavior, or code upgrade. [7](#0-6) 

A single address can create or control accounts, supply a very large amount of the target asset through `supply`, provide sufficient collateral through permitted assets, borrow most of that market through `borrow`, and later invoke `update_indexes` for that market. [15](#0-14) [16](#0-15) [8](#0-7) 

The attack is bounded by listing caps, available token supply, collateral requirements, and sustained high utilization, so it is not triggerable on every market. [17](#0-16) 

### Recommendation
Make accrual overflow-safe by evaluating and saturating `borrowed * borrow_index` and `supplied * supply_index` before checked multiplication, or by storing/clamping market totals at a value domain below `i128::MAX`. [18](#0-17) [6](#0-5) 

Add an emergency accrual path that can process repayment, withdrawal, liquidation, bad-debt cleanup, or recapitalization when pre-operation valuation overflows, while preserving conservative accounting for the saturated value. [1](#0-0) 

Tighten admission-time caps so `scaled_balance * MAX_*_INDEX_RAY` remains representable for every listed market instead of only bounding asset deposits to the token-to-RAY input domain. [19](#0-18) [17](#0-16) 

### Proof of Concept
1. In a market whose caps admit the position, call `Controller::supply` to create a very large scaled supply balance, then call `Controller::borrow` to establish high utilization under normal collateral checks. [7](#0-6) [20](#0-19) 
2. Let ledger time advance and call `Controller::update_indexes(caller, [hub_asset])`; the controller forwards the market to `Pool::update_indexes`. [8](#0-7) [21](#0-20) 
3. `global_sync` calls `accrue_step`, which multiplies the persisted scaled balances by their current indexes before applying index caps. [1](#0-0) [2](#0-1) 
4. When `scaled_balance * index` exceeds `i128::MAX`, `Ray::mul` reverts with `MathOverflow`; the committed test case verifies that this occurs while `borrow_index < MAX_BORROW_INDEX_RAY`. [4](#0-3) [22](#0-21) 
5. A later `withdraw` and `repay` still invoke the same mandatory accrual and revert with `MathOverflow`, as demonstrated by the existing test. [23](#0-22)

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

```rust
pub fn update_supply_index(env: &Env, supplied: Ray, old_index: Ray, rewards_increase: Ray) -> Ray {
    if supplied == Ray::ZERO || rewards_increase == Ray::ZERO {
        return old_index;
    }

    let total_supplied_value = supplied.mul(env, old_index);

    if total_supplied_value == Ray::ZERO {
        return old_index;
    }

    let new_value = total_supplied_value.checked_add(env, rewards_increase);
    let grown = fp_core::mul_div_floor_saturating(env, new_value.raw(), RAY, supplied.raw());

    let bounded_old = old_index.raw().min(MAX_SUPPLY_INDEX_RAY);
    Ray::from(grown.min(MAX_SUPPLY_INDEX_RAY).max(bounded_old))
```

```rust
/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
