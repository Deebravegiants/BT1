### Title
Leftover input token from a partial-fill swap is left stranded and unclaimable in `ExternalActionSwap`/`LifiExternalAction` - (File: contracts/external-actions/swaps/ExternalActionSwap.sol, contracts/external-actions/swaps/LifiExternalAction.sol)

### Summary
`ExternalActionSwap.swap()` and `LifiExternalAction.callRouter()` account for the swap outcome only by measuring the **output** token balance delta of the swap contract; they never verify that the **entire input amount** transferred from `Hinkal` was actually consumed by the router. This mirrors the C4 finding on `_execBuyNftFromMarket()`, where the balance check covered only one leg (ETH) of a two-leg operation (ETH+WETH), letting leftover value go unaccounted for.

### Finding Description
In `_externalTransact()` [1](#0-0) , Hinkal transfers the full `inputAmount` (derived from the prover-committed `circomData.amountChanges`) to the external action contract (`LifiExternalAction`) **before** `runAction`/`swap()` executes.

Inside `swap()` [2](#0-1) , `inputAmount` is computed from the (proof-bound) delta and handed to `callRouter`. `LifiExternalAction.callRouter()` grants the router a (persisted) unlimited approval and executes the router call, then computes the result solely as:

```
swappedAmount = getERC20OrETHBalance(outputToken) - balanceBefore;
``` [3](#0-2) 

There is no check that the contract's `inputToken` balance actually decreased by `inputAmount`. If the router only partially consumes the approved `inputAmount` (a normal DEX-aggregator behavior — e.g. an "exact output" fill, a limit order matched at a better price, or any path that needs less than the quoted/approved amount), the unused portion of `inputToken` simply remains sitting in the `LifiExternalAction` contract.

Back in `Hinkal.transact()`, the balance-equation check is only performed on `Hinkal`'s own balances (`getBalancesForArray`), not on the external action contract's balances [4](#0-3) . Nothing in the equality that Hinkal enforces (`balanceDif == amountChanges + utxoAmount`) constrains what happens to funds once they leave `Hinkal` and are held by the external action contract — the only invariant checked there is on `Hinkal`'s balance, and from `Hinkal`'s point of view the whole `inputAmount` was properly "spent" the moment it was forwarded to `LifiExternalAction`.

This breaks the equality the report's bug-class hint calls out: **"value moved by Hinkal or an external action but not counted in the balance equation."** The leftover input token is value that left the shielded pool (debited from the user's UTXO / `amountChanges`) but was never returned as an output UTXO, and it is not tracked by the contract in any way that lets that specific depositor reclaim it. No `onlyOwner` rescue/sweep function exists in `ExternalActionBaseV2`/`ExternalActionSwap` to recover it either [5](#0-4) .

Because `externalActionMetadata` (the router call payload) is folded into `calldataHash`, which is itself a verified public input to the Groth16 proof [6](#0-5) [7](#0-6) , this is not an attacker-crafted-calldata attack and does not rely on any LI.FI router defect or malicious relayer — the root cause is Hinkal's own missing full-consumption check on the input leg, exactly analogous to the missing WETH-side check in the referenced report.

### Impact Explanation
This is a **temporary/permanent freezing of user funds** (High impact tier): the user's debited `inputAmount` (part of their shielded balance) can partially end up stuck in the `LifiExternalAction` contract with no code path to reclaim it for that user specifically. Depending on how frequently DEX routes leave unspent input (common with aggregators that support partial/optimal fills), this can recur across many swaps, and the accumulated leftover balance sits in the contract, spendable only by the owner-controlled router allowance (i.e., practically unrecoverable by the affected user).

### Likelihood Explanation
Likelihood is moderate: it depends on the router's fill behavior specified in `externalActionMetadata`, which is built off-chain by whoever generates the proof. Any swap route that does not guarantee 100% consumption of the approved `inputAmount` (e.g., aggregator quotes with built-in slippage margin on the input side, or output-exact swaps) triggers this without any malicious actor needed — it's a byproduct of normal usage, not a contrived attack, making it fairly likely to occur in production over time.

### Recommendation
In `ExternalActionSwap.swap()` / `LifiExternalAction.callRouter()`, measure the input token balance before and after the router call and require that the decrease equals `inputAmount` (or refund/forward any leftover input token back to `msg.sender`/create a UTXO for it instead of leaving it in the contract), mirroring the fix applied in the referenced report ("account for [both legs] when checking balance changes").

### Proof of Concept
1. User submits a valid Hinkal `transact()` proof for a swap: `amountChanges[0] = -100` (input token), routed through `LifiExternalAction`, with `externalActionMetadata` built to call the router requesting a swap of up to 100 input tokens for some minimum output.
2. `Hinkal._externalTransact()` transfers the full 100 input tokens to `LifiExternalAction` [1](#0-0) .
3. `LifiExternalAction.callRouter()` approves the router for 100 and calls it; the router, following normal aggregator logic (e.g., it found a route needing only 95 tokens to satisfy the output/slippage requirements of the calldata), only pulls 95 tokens via the standing approval, leaving 5 input tokens in `LifiExternalAction`.
4. `swappedAmount` is computed purely from the output-token delta, so the swap "succeeds" and an output UTXO is created for the buyer as normal [8](#0-7) .
5. The 5 leftover input tokens remain in `LifiExternalAction`'s balance indefinitely; the user's UTXO set reflects a full 100 debited with no corresponding 5-token credit, and no function exists for that user (or anyone) to reclaim exactly that 5-token remainder — it is stuck, only theoretically reachable by the contract owner or a future user's unrelated router call (which itself has no accounting for pre-existing balances).

    function swap(
        CircomData calldata circomData,
        int256[] calldata deltaAmounts
    ) internal returns (UTXO[] memory utxoSet) {
        address inputToken = circomData.erc20TokenAddresses[0];
        uint256 inputAmount = uint256(-deltaAmounts[0]);

        if (inputToken == circomData.feeStructure.feeToken) {
            inputAmount -= circomData.feeStructure.flatFee;
        }

        address outputToken = circomData.erc20TokenAddresses[1];

        require(
            circomData.slippageValues[1] != 0,
            "swap output slippage floor not set"
        );

        require(
            block.timestamp <= circomData.timeStamp + SWAP_DEADLINE_WINDOW,
            "swap expired"
        );

        uint256 swappedAmount = callRouter(
            inputToken,
            inputAmount,
            outputToken,
            circomData.externalActionData.externalActionMetadata
        );

        uint256 relayFee = circomData.feeStructure.flatFee;

        uint256 hinkalFee = hinkalHelper.calculateRelayFee(
            swappedAmount,
            0,
            circomData.feeStructure.variableRate
        );

        if (circomData.feeStructure.feeToken == outputToken) {
            sendToRelay(circomData.relay, relayFee + hinkalFee, outputToken);
        } else {
            sendToRelay(
                circomData.relay,
                relayFee,
                circomData.feeStructure.feeToken
            );
            sendToRelay(circomData.relay, hinkalFee, outputToken);
        }

        uint256 totalFee = hinkalFee +
            (outputToken == circomData.feeStructure.feeToken ? relayFee : 0);
        uint256 amountToSendToHinkal = swappedAmount - totalFee;

        transferERC20TokenOrETH(outputToken, msg.sender, amountToSendToHinkal);

        utxoSet = new UTXO[](1);
        utxoSet[0] = UTXO({
            amount: amountToSendToHinkal,
            erc20Address: outputToken,
            stealthAddressStructure: circomData.stealthAddressStructure,
            timeStamp: block.timestamp
        });

    function callRouter(
        address inputToken,
        uint256 inputAmount,
        address outputToken,
        bytes calldata externalActionMetadata
    ) internal override returns (uint256 swappedAmount) {
        uint256 balanceBefore = getERC20OrETHBalance(outputToken);

        if (inputToken == address(0)) {
            (bool success, ) = router.call{value: inputAmount}(
                externalActionMetadata
            );
            require(success, "LI.FI swap failed: native coin");
        } else {
            approveUnlimited(inputToken, router);
            (bool success, ) = router.call(externalActionMetadata);
            require(success, "LI.FI swap failed: erc-20 token");
        }

        swappedAmount = getERC20OrETHBalance(outputToken) - balanceBefore;
    }

// SPDX-License-Identifier: BUSL-1.1
pragma solidity ^0.8.17;

import {CircomData} from "../types/CircomData.sol";
import {UTXO} from "../types/UTXO.sol";
import {IExternalActionV2} from "../types/IExternalActionV2.sol";
import {OwnerHinkal} from "../OwnerHinkal.sol";

abstract contract ExternalActionBaseV2 is IExternalActionV2, OwnerHinkal {
    mapping(address => bool) internal isAllowedRecipient;

    /*
     * @dev Modifier to check if the sender is allowed to call the action
     * @dev Used to handle VolatileTokenAction and Hinkal interactions
     */
    modifier onlyAllowedRecipient() {
        require(
            isAllowedRecipient[msg.sender],
            "ExternalActionBase: sender not allowed"
        );
        _;
    }

    constructor(address[] memory _allowedRecipients) {
        for (uint i = 0; i < _allowedRecipients.length; i++) {
            isAllowedRecipient[_allowedRecipients[i]] = true;
        }
    }

    function setAllowedRecipients(
        address[] calldata recipients
    ) external onlyOwner {
        for (uint i = 0; i < recipients.length; i++) {
            require(recipients[i] != address(0), "zero address!");
            isAllowedRecipient[recipients[i]] = true;
        }
    }

    function runAction(
        CircomData calldata circomData,
        int256[] calldata deltaAmountChanges
    ) external virtual returns (UTXO[] memory utxoSet) {}
