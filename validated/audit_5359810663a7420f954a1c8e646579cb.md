## Analog Found

### Title
Stale cached LDAP role/session state is used for authorization decisions without triggering upstream revalidation, contrary to documented behavior - (`core/sessions/ldapauth/ldap.go`)

### Summary
The Sherlock report describes a pattern where a refresh/accrual step (`accrue`) is documented as required before reading current state, but the read functions never actually invoke it, so callers act on stale data. The same class of bug exists in the Chainlink node's LDAP authentication provider: `AuthorizedUserWithSession` and `FindUserByAPIToken`, which gate every authenticated HTTP/GraphQL request, read the user's role purely from local cache tables (`ldap_sessions`, `ldap_user_api_tokens`) and never trigger (nor wait on) a revalidation against the upstream LDAP directory, despite package documentation explicitly claiming otherwise.

### Finding Description
The package doc comment for `ldapauth` states: [1](#0-0) 

> "User session and roles are cached and revalidated with the upstream service at the interval defined in the local LDAP config ... This sync happens for every auth endpoint hit, and via the defined sync interval."

However, the actual per-request authorization paths never call any revalidation logic. `AuthorizedUserWithSession` (used by `AuthenticateBySession` on every session-cookie-authenticated request) simply selects the cached `user_role` from `ldap_sessions` and returns it: [2](#0-1) . Likewise `FindUserByAPIToken` reads the cached role straight from `ldap_user_api_tokens` with an explicit comment admitting "no further upstream LDAP query is performed": [3](#0-2) .

The only code path that actually re-queries the upstream LDAP server and reconciles/purges/downgrades local role state is `LDAPServerStateSyncer.Work`, which runs strictly on a background ticker (`l.run()`) at the `UpstreamSyncInterval`, or once at startup if that interval is unset — never synchronously on a request: [4](#0-3) . There is no call from the request-serving authentication code (`core/web/auth/auth.go`'s `AuthenticateBySession`/`AuthenticateByToken`, or the GraphQL equivalents) into `LDAPServerStateSyncer.Work` or any per-request LDAP re-check.

This is directly analogous to the reported issue: state that must be "accrued"/refreshed before being trusted for a privileged decision is instead read from a stale cache, and the code/documentation incorrectly implies the refresh occurs inline.

### Impact Explanation
If an operator revokes or downgrades a user's LDAP group membership (e.g., removes them from the Admin group, or deactivates the account entirely), that user's existing session cookie or long-lived API token continues to authenticate with the old, higher-privileged role until the next scheduled `UpstreamSyncInterval` fires. Since `AuthorizedUserWithSession`/`FindUserByAPIToken` are the sole authorization gates for every subsequent request on that session/token, this allows continued unauthorized use of admin/edit/run privileges by an actor whose access should have already been revoked — a concrete privilege-escalation / stale-authorization-bypass window whose length is fully attacker/operator-configuration dependent (and unbounded if `UpstreamSyncInterval` is large or misconfigured).

### Likelihood Explanation
This requires no attacker sophistication beyond already possessing a valid session cookie or API token at the moment their upstream privileges are revoked — a realistic operational scenario (offboarding, role downgrade, compromised credential revocation). The bug is deterministic: the code path guarantees the stale role is returned until the ticker-driven sync executes, so it will manifest reliably whenever LDAP-side revocation and local revalidation are not perfectly synchronized.

### Recommendation
Either update the documentation to accurately reflect that revalidation is periodic-only (removing the misleading "every auth endpoint hit" claim) and shrink the acceptable default `UpstreamSyncInterval`, or — preferably — make `AuthorizedUserWithSession` and `FindUserByAPIToken` trigger/await a synchronous (or short-TTL, rate-limited) upstream check before returning a role for authorization purposes, matching the documented "on every auth endpoint hit" behavior described in `core/sessions/ldapauth/ldap.go`.

### Proof of Concept
1. Configure the LDAP driver with `UpstreamSyncInterval` set to a large value (e.g., 24h).
2. User `alice@example.com` logs in while a member of the Admin LDAP group; `CreateSession` stores `user_role = admin` in `ldap_sessions` [5](#0-4) .
3. Operator removes `alice` from the Admin group upstream (or deactivates her account) in the LDAP directory.
4. Before the next `LDAPServerStateSyncer.Work` tick fires, `alice` continues issuing admin-role API requests using her existing session cookie; `AuthenticateBySession` → `AuthorizedUserWithSession` returns the stale cached `admin` role from `ldap_sessions` [6](#0-5) , and the request is authorized with admin privileges despite upstream revocation.

// FindUserByAPIToken retrieves a possible stored user and role from the ldap_user_api_tokens table store
func (l *ldapAuthenticator) FindUserByAPIToken(ctx context.Context, apiToken string) (sessions.User, error) {
	if !l.config.UserApiTokenEnabled() {
		return sessions.User{}, errors.New("API token is not enabled ")
	}

	// Query the ldap user API token table for given token, user role and email are cached so
	// no further upstream LDAP query is performed, sessions and tokens are synced against the upstream server
	// via the UpstreamSyncInterval config and reaper.go sync implementation
	var foundUserToken struct {
		UserEmail string
		UserRole  sessions.UserRole
		Valid     bool
	}
	err := l.ds.GetContext(ctx, &foundUserToken,
		"SELECT user_email, user_role, created_at + $2 >= now() as valid FROM ldap_user_api_tokens WHERE token_key = $1",
		apiToken, l.config.UserAPITokenDuration().Duration(),
	)
	if err != nil {
		return sessions.User{}, err
	}
	if !foundUserToken.Valid { // API Token expired, purge
		if _, execErr := l.ds.ExecContext(ctx, "DELETE FROM ldap_user_api_tokens WHERE token_key = $1", apiToken); execErr != nil {
			l.lggr.Errorf("error purging stale ldap API token session: %v", execErr)
		}
		return sessions.User{}, sessions.ErrUserSessionExpired
	}

	return sessions.User{
		Email: foundUserToken.UserEmail,
		Role:  foundUserToken.UserRole,
	}, nil
}

		return sessions.User{}, errors.New("session ID cannot be empty")
	}

	// no further upstream LDAP query is performed
	var foundSession struct {
		UserEmail string
		UserRole  sessions.UserRole
		Valid     bool
	}
	if err := l.ds.GetContext(ctx, &foundSession,
		"SELECT user_email, user_role, created_at + $2 >= now() as valid FROM ldap_sessions WHERE id = $1",
		sessionID, l.config.SessionTimeout().Duration(),
	); err != nil {
		return sessions.User{}, sessions.ErrUserSessionExpired
	}
	if !foundSession.Valid {
		// Sessions expired, purge
		if _, execErr := l.ds.ExecContext(ctx, "DELETE FROM ldap_sessions WHERE id = $1", sessionID); execErr != nil {
			l.lggr.Errorf("error purging stale ldap session: %v", execErr)
		}
		return sessions.User{}, sessions.ErrUserSessionExpired
	}
	return sessions.User{
		Email: foundSession.UserEmail,
		Role:  foundSession.UserRole,
	}, nil

func (l *LDAPServerStateSyncer) Start(ctx context.Context) error {
	// If enabled, start a background task that calls the Sync/Work function on an
	// interval without needing an auth event to trigger it
	// Use IsInstant to check 0 value to omit functionality.
	if !l.config.UpstreamSyncInterval().IsInstant() {
		l.lggr.Info("LDAP Config UpstreamSyncInterval is non-zero, sync functionality will be called on a timer, respecting the UpstreamSyncRateLimit value")
		go l.run()
	} else {
		// Ensure upstream server state is synced on startup manually if interval check not set
		l.Work(ctx)
	}
	return nil
}

func (l *LDAPServerStateSyncer) Close() error {
	close(l.stopCh)
	<-l.done
	return nil
}

func (l *LDAPServerStateSyncer) run() {
	defer close(l.done)
	ctx, cancel := l.stopCh.NewCtx()
	defer cancel()
	ticker := time.NewTicker(l.config.UpstreamSyncInterval().Duration())
	defer ticker.Stop()

	for {
		select {
		case <-ctx.Done():
			return
		case <-ticker.C:
			l.Work(ctx)
		}
	}
}
