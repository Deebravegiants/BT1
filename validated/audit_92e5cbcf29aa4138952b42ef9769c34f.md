### Title
`ShopifyAPI::Auth::Oauth.begin_auth`/`validate_auth_callback` send the app's `client_id`/`client_secret` to an unvalidated `shop` host - ([File: lib/shopify_api/auth/oauth.rb])

### Summary
`ShopifyAPI::Auth::ClientCredentials.client_credentials` and `ShopifyAPI::Auth::RefreshToken.refresh_access_token` both call `Utils::ShopValidator.sanitize!(shop)` before building a session and sending the app's `client_secret` to `https://#{shop}/admin/oauth/access_token`. [1](#0-0) [2](#0-1) 

`ShopifyAPI::Auth::Oauth.begin_auth` and `ShopifyAPI::Auth::Oauth.validate_auth_callback`, however, never call `ShopValidator` on `shop`/`auth_query.shop` before using it to build the authorization/token-exchange host. [3](#0-2) [4](#0-3) 

### Finding Description
`begin_auth` takes a `shop:` parameter directly from the caller and builds `auth_route = auth_base_uri(shop) + "/oauth/authorize?..."`, sending the app's public `client_id` to `https://#{shop}/admin/oauth/authorize` with no validation that `shop` is a real `*.myshopify.com`/trusted domain. [5](#0-4) 

More importantly, `validate_auth_callback` builds `null_session = Auth::Session.new(shop: auth_query.shop)` and uses it to POST the app's `client_id` **and `client_secret`** to `https://#{auth_query.shop}/admin/oauth/access_token`, again with no `ShopValidator.sanitize!` call on `auth_query.shop`. [6](#0-5) 

The only integrity check performed is `Utils::HmacValidator.validate(auth_query)`, which proves the `code/host/shop/state/timestamp` tuple was signed with `Context.api_secret_key` — it does not constrain `shop` to a Shopify-owned domain format. [7](#0-6) [8](#0-7) 

Every other credential-sending flow in this gem (`ClientCredentials`, `RefreshToken`, and `TokenExchange`, which derives `shop` from a JWT `dest` claim) normalizes `shop` through `Utils::ShopValidator.sanitize!` before it is used as a request host, establishing that this is the gem's own intended invariant for binding "the host receiving the `client_secret`" to "a validated Shopify domain." The Authorization Code Grant path (`oauth.rb`) breaks that invariant.

### Impact Explanation
This matches the High-impact category "SSRF with the app's credentials": if a caller (the host app, or ultimately an attacker who can influence the `shop` value passed into `begin_auth`, or who can influence what the callback echoes back and gets HMAC-signed) supplies a non-Shopify domain, the gem will send the app's `client_id` (on `begin_auth`) or `client_id` + `client_secret` (on `validate_auth_callback`) to that attacker-controlled host — an SSRF/credential-exfiltration primitive carrying the app's own OAuth credentials, exactly the pattern the other two grant flows defend against with `ShopValidator.sanitize!`.

### Likelihood Explanation
Exploitability depends on how strictly the host application already validates `shop` before calling `begin_auth`/`validate_auth_callback`. Because the rules exclude findings that "depend on the host application ignoring this gem's documented API," and the gem's own `docs/usage/oauth.md` does not clearly instruct callers to pre-sanitize `shop` themselves for the Authorization Code Grant (unlike the newer `ClientCredentials`/`RefreshToken` docs which route through `ShopValidator` internally), the missing validation is inside the gem's own trust boundary rather than purely a documented caller responsibility. I could not fully confirm from the available docs/tests whether `validate_auth_callback` is expected/documented to receive only pre-validated `shop` values, so likelihood is Medium rather than definitively High.

### Recommendation
Call `Utils::ShopValidator.sanitize!(shop)` (with the configured `myshopify_domain` if any) inside `Oauth.begin_auth` before constructing `auth_route`, and inside `Oauth.validate_auth_callback` before constructing `null_session`/`auth_base_uri(auth_query.shop)`, mirroring `ClientCredentials.client_credentials` and `RefreshToken.refresh_access_token`.

### Proof of Concept
Not independently verified end-to-end due to index limits on request/response wiring in the host application; the code-level gap is directly demonstrated by comparing:
- `client_credentials.rb:25` (`validated_shop = Utils::ShopValidator.sanitize!(shop)`) and `refresh_token.rb:24` (same pattern) — both sanitize before sending `client_secret`.
- `oauth.rb:73-81` — `null_session = Auth::Session.new(shop: auth_query.shop)` then `client.request(...)` with `client_secret` in the body, with no equivalent `ShopValidator` call anywhere in `oauth.rb`. [9](#0-8) [10](#0-9)

        def begin_auth(shop:, redirect_path:, is_online: true, scope_override: nil)
          scope = if scope_override.nil?
            ShopifyAPI::Context.scope
          elsif scope_override.is_a?(ShopifyAPI::Auth::AuthScopes)
            scope_override
          else
            ShopifyAPI::Auth::AuthScopes.new(scope_override)
          end

          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = SecureRandom.alphanumeric(NONCE_LENGTH)

          cookie = SessionCookie.new(value: state, expires: Time.now + 60)

          query = {
            client_id: ShopifyAPI::Context.api_key,
            scope: scope.to_s,
            redirect_uri: "#{ShopifyAPI::Context.host}#{redirect_path}",
            state: state,
            "grant_options[]": is_online ? "per-user" : "",
          }

          query_string = URI.encode_www_form(query)
          auth_route = auth_base_uri(shop) + "/oauth/authorize?#{query_string}"

          { auth_route: auth_route, cookie: cookie }
        end

        def validate_auth_callback(cookies:, auth_query:)
          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::InvalidOauthError, "Invalid OAuth callback." unless Utils::HmacValidator.validate(auth_query)
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = cookies[SessionCookie::SESSION_COOKIE_NAME]
          raise Errors::NoSessionCookieError unless state

          raise Errors::InvalidOauthError,
            "Invalid state in OAuth callback." unless state == auth_query.state

          null_session = Auth::Session.new(shop: auth_query.shop)
          body = {
            client_id: Context.api_key,
            client_secret: Context.api_secret_key,
            code: auth_query.code,
            expiring: Context.expiring_offline_access_tokens ? 1 : 0, # Only applicable for offline tokens
          }

          client = Clients::HttpClient.new(session: null_session, base_path: "/admin/oauth")
          response = begin
            client.request(
              Clients::HttpRequest.new(
                http_method: :post,
                path: "access_token",
                body: body,
                body_type: "application/json",
              ),
            )
          rescue ShopifyAPI::Errors::HttpResponseError => e
            raise Errors::RequestAccessTokenError,
              "Cannot complete OAuth process. Received a #{e.code} error while requesting access token."
          end

          session_params = T.cast(response.body, T::Hash[String, T.untyped]).to_h
          session = Session.from(shop: auth_query.shop,
            access_token_response: Oauth::AccessTokenResponse.from_hash(session_params))

        def auth_base_uri(shop)
          return "https://#{shop}/admin" unless defined?(DevServer) && shop.include?(".my.shop.dev")

          # For first-party apps in development only, we leverage DevServer to build the admin base URI
          admin_web = T.unsafe(Object.const_get("DevServer")) # rubocop:disable Sorbet/ConstantsFromStrings
            .new("admin-web")
          admin_host = admin_web.host!(nonstandard_host_prefix: "admin")
          shop_name = shop.split(".").first

          "https://#{admin_host}/store/#{shop_name}"
        end
