### Title
Missing owner-stamping in `handleSecretsDelete` allows cross-owner secret deletion in the Vault gateway handler - ([File: core/capabilities/vault/gw_handler.go])

### Summary
`AbstractStakingAM` authenticates by comparing a caller-supplied position owner against `msg.sender`, but `msg.sender` is actually an intermediary (`MultiCall`), so the wrong identity is checked. The Vault gateway pipeline in this repo has the analogous flaw: authorization is performed against the *transport-level* authorized owner (the address that registered an allowlisted request digest on-chain), but the object being operated on — the secret identified by `SecretIdentifier{Key, Namespace, Owner}` — is taken directly from caller-controlled request params instead of being pinned to that authorized identity for the delete path.

### Finding Description
`GatewayVaultRequestProcessor.authorizeAndStamp` authorizes the whole JSON-RPC request as a digest and returns an `AuthResult` whose `AuthorizedOwner()` reflects the address that registered (allowlisted) that specific request digest on-chain [1](#0-0) . This authorizes *who sent the request*, not *whose secret the request payload claims to target* — the two are only linked if the handler explicitly re-stamps the owner field of the payload with the authorized owner before dispatching to the `SecretsService`.

For `MethodSecretsList`, `GatewayHandler.handleSecretsList` correctly overwrites the caller-supplied owner with the cryptographically authorized one before calling the service: [2](#0-1) 

For `MethodSecretsDelete`, however, `handleSecretsDelete` unmarshals the request directly into `vaultcommon.DeleteSecretsRequest` and passes it straight to `h.secretsService.DeleteSecrets` — there is no equivalent `r.Ids[i].Owner = authResult.AuthorizedOwner()` stamping: [3](#0-2) 

`processDeleteSecretsRequest` in the request processor only validates structure and stamps the request ID prefix; it never checks or overwrites the `Owner` field embedded in each `SecretIdentifier` of `deleteReq.Ids` against `authResult.AuthorizedOwner()`: [4](#0-3) 

Because authorization is based on matching the digest of the *entire* request against an on-chain allowlist entry registered by some owner address (see `allowListBasedAuth.AuthorizeRequest`), any owner can pre-compute a `DeleteSecretsRequest` payload whose `Ids[].Owner` field references a *different* victim address, register that exact digest under their own on-chain identity, and submit it through the gateway: [5](#0-4) 

The digest check only proves "the sender is the address that registered this exact byte sequence" — it does not prove "the sender is authorized to act on the `Owner` referenced inside the payload." Since `handleSecretsDelete` never re-derives or checks `Ids[].Owner` against `authResult.AuthorizedOwner()` (unlike the list path), the delete operation is dispatched using the attacker-chosen `Owner` value, not the authenticated owner.

### Impact Explanation
An attacker who is a valid, allowlisted vault owner (i.e., any unprivileged workflow owner who can register requests via the on-chain workflow registry) can delete secrets belonging to a different owner/tenant by crafting a `DeleteSecretsRequest` whose `SecretIdentifier.Owner` fields reference the victim, allowlisting that specific request digest under their own address, then submitting it through the gateway. This results in unauthorized destruction of another tenant's confidential vault secrets — a direct cross-user authorization bypass in a security-sensitive, internet-facing capability (secret storage).

### Likelihood Explanation
Likelihood is limited by the requirement that the attacker must be able to register an allowlist entry for an arbitrary pre-computed digest via the on-chain workflow registry (which any owner participating in the CRE/Vault workflow ecosystem can do for their own workflow), and must know or guess a target `Namespace`/`Key`/`Owner` triple that exists for the victim. No signature over the semantic content (the claimed owner) beyond the raw digest is otherwise required, so once those conditions are met, exploitation requires no privilege escalation — just crafting request bytes.

### Recommendation
In `handleSecretsDelete` (and in `processDeleteSecretsRequest`/`ValidateDeleteSecretsRequest`), enforce that every `SecretIdentifier.Owner` in `DeleteSecretsRequest.Ids` equals `authResult.AuthorizedOwner()` before dispatching to `SecretsService.DeleteSecrets` — either by rejecting mismatched owners or by overwriting them the same way `handleSecretsList` stamps `r.Owner`, consistent with the documented pipeline invariant ("validates that payload owners match the authorized workflow owner") in the processor's own doc comment.

### Proof of Concept
1. Attacker (owner A) knows/derives that victim (owner B) has a secret at `Namespace="ns", Key="k"`.
2. Attacker builds `DeleteSecretsRequest{Ids: [{Key:"k", Namespace:"ns", Owner:"0xVictimB"}]}` and computes its JSON-RPC request digest.
3. Attacker calls the on-chain workflow registry as owner A to allowlist that exact digest for themselves (`WorkflowRegistryOwnerAllowlistedRequest{Owner: A, RequestDigest: digest}`).
4. Attacker submits the identical request bytes to the gateway; `allowListBasedAuth.AuthorizeRequest` matches the digest and returns `AuthResult{workflowOwner: A}` [6](#0-5) .
5. `handleSecretsDelete` unmarshals `Ids[].Owner = "0xVictimB"` unchanged and calls `secretsService.DeleteSecrets` with that request, deleting victim B's secret despite the request only ever being authorized for owner A [7](#0-6) .

func (p *GatewayVaultRequestProcessor) processDeleteSecretsRequest(
	ctx context.Context,
	req *jsonrpc.Request[json.RawMessage],
) (*AuthorizedGatewayVaultRequest, error) {
	if req.Params == nil {
		return nil, InvalidVaultParamsError{Method: req.Method, Err: errors.New("request params must not be nil")}
	}

	var deleteReq vaultcommon.DeleteSecretsRequest
	if err := json.Unmarshal(*req.Params, &deleteReq); err != nil {
		return nil, InvalidVaultParamsError{Method: req.Method, Err: err}
	}
	if p.stripOwnerPrefixForAuth {
		deleteReq.RequestId = req.ID
		if err := marshalVaultParams(req, &deleteReq); err != nil {
			return nil, InvalidVaultParamsError{Method: req.Method, Err: err}
		}
	} else {
		deleteReq.RequestId = coalesceRequestID(deleteReq.RequestId, req.ID)
	}

	if err := p.validator.ValidateDeleteSecretsRequest(ctx, &deleteReq); err != nil {
		return nil, p.validationError(req, err)
	}

	return p.authorizeAndStamp(ctx, req, func(prefixedRequestID string) error {
		deleteReq.RequestId = prefixedRequestID
		vaultutils.ApplySecretIdentifierNamespaceDefaults(deleteReq.Ids)
		return marshalVaultParams(req, &deleteReq)
	})
}

func (p *GatewayVaultRequestProcessor) authorizeAndStamp(
	ctx context.Context,
	req *jsonrpc.Request[json.RawMessage],
	stamp func(prefixedRequestID string) error,
) (*AuthorizedGatewayVaultRequest, error) {
	incomingOwner := ""
	if idx := strings.Index(req.ID, vaulttypes.RequestIDSeparator); idx != -1 {
		incomingOwner = req.ID[:idx]
	}

	p.lggr.Debugw("authorizing gateway vault request", "method", req.Method, "requestID", req.ID)
	authResult, err := p.authorizer.AuthorizeRequest(ctx, *req)
	if err != nil {
		authErr := fmt.Errorf("request not authorized: %w", err)
		p.lggr.Errorw("gateway vault request authorization failed", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "", "incomingOwner", incomingOwner, "error", authErr)
		return nil, authErr
	}

	originalRequestID := req.ID
	authorizedOwner := authResult.AuthorizedOwner()
	prefixedRequestID := authorizedOwner + vaulttypes.RequestIDSeparator + originalRequestID
	req.ID = prefixedRequestID

	if err := stamp(prefixedRequestID); err != nil {
		p.lggr.Errorw("failed to stamp authorized request params", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, fmt.Errorf("failed to stamp authorized request params: %w", err)
	}

	p.lggr.Debugw("authorized gateway vault request", "method", req.Method, "requestID", req.ID, "owner", authorizedOwner, "orgID", authResult.OrgID(), "workflowOwner", authResult.WorkflowOwner())
	return &AuthorizedGatewayVaultRequest{
		Req:        *req,
		AuthResult: authResult,
	}, nil

func (h *GatewayHandler) handleSecretsDelete(ctx context.Context, gatewayID string, req *jsonrpc.Request[json.RawMessage]) *jsonrpc.Response[json.RawMessage] {
	r := &vaultcommon.DeleteSecretsRequest{}
	if err := json.Unmarshal(*req.Params, r); err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.UserMessageParseError, err)
	}

	h.lggr.Debugw("Processing authorized delete secrets request", "request", r.String())
	resp, err := h.secretsService.DeleteSecrets(ctx, r)
	if err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.HandlerError, fmt.Errorf("failed to delete secrets: %w", err))
	}

	resultBytes, err := resp.ToJSONRPCResult()
	if err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.NodeReponseEncodingError, err)
	}

	return &jsonrpc.Response[json.RawMessage]{
		Version: jsonrpc.JsonRpcVersion,
		ID:      req.ID,
		Method:  req.Method,
		Result:  (*json.RawMessage)(&resultBytes),
	}
}

// AuthorizeRequest authorizes a request using AllowListBasedAuth.
// It does NOT check if the request method is allowed.
func (r *allowListBasedAuth) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	r.lggr.Debugw("AllowListBasedAuth authorizing request", "method", req.Method, "requestID", req.ID)
	requestDigest, err := req.Digest()
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to create digest", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, err
	}
	requestDigestBytes, err := hex.DecodeString(requestDigest)
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to decode digest", "method", req.Method, "requestID", req.ID, "requestDigest", requestDigest, "error", err)
		return nil, err
	}
	requestDigestBytes32 := [32]byte(requestDigestBytes)
	if r.workflowRegistrySyncer == nil {
		r.lggr.Errorw("AllowListBasedAuth workflowRegistrySyncer is nil", "method", req.Method, "requestID", req.ID)
		return nil, errors.New("internal error: workflowRegistrySyncer is nil")
	}
	allowlistedRequest, allowedRequestsStrs, err := r.findAllowlistedItemWithRetry(ctx, req, requestDigest, requestDigestBytes32)
	if err != nil {
		return nil, err
	}
	if allowlistedRequest == nil {
		r.lggr.Debugw("AllowListBasedAuth request digest not allowlisted",
			"method", req.Method,
			"requestID", req.ID,
			"digestHexStr", requestDigest,
			"allowedRequestsStrs", allowedRequestsStrs)
		return nil, errors.New("request not allowlisted")
	}

	if time.Now().UTC().Unix() > int64(allowlistedRequest.ExpiryTimestamp) {
		authorizedRequestStr := string(allowlistedRequest.RequestDigest[:])
		r.lggr.Debugw("AllowListBasedAuth authorization expired", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", authorizedRequestStr, "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
		return nil, errors.New("request authorization expired")
	}

	digestKey := string(allowlistedRequest.RequestDigest[:])
	r.lggr.Debugw("AllowListBasedAuth authorization succeeded", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", digestKey, "owner", allowlistedRequest.Owner.Hex(), "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
	return &AuthResult{
		workflowOwner: allowlistedRequest.Owner.Hex(),
		digest:        digestKey,
		expiresAt:     int64(allowlistedRequest.ExpiryTimestamp),
	}, nil
}
