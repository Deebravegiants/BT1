# Spot Price Manipulation of Uniswap V4 Venue Pricing Allows Draining of Simplex Solver Liquidity - (File: sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts)

### Summary
Simplex's venue-priced (curve-less) intent pairs derive the exotic token's USD price directly from the live `sqrtPriceX96` spot price of a single Uniswap V4 pool, with no TWAP or execution-cost adjustment. An unprivileged intent placer can flash-swap the referenced pool to skew its spot price, submit an intent order in the same block that gets quoted against the manipulated price, and drain solver-held LP inventory at a favorable rate — the same "spot-oracle price manipulation" bug class described in the CoFiXProtocol incident report, where reliance on a manipulable on-chain price feed let an attacker extract funds in one atomic sequence.

### Finding Description
When a `[[pairs]]` entry has no static `bidPriceCurve`/`askPriceCurve` and `token0` is a USD stablecoin, `resolveLegRates` in `sdk/packages/simplex/src/strategies/fx.ts` prices the leg from the venue instead of a curve: [1](#0-0) 

The venue quote comes from `UniswapV4FundingPlanner.getExoticTokenPrice`, which selects the most-liquid qualifying pool and reads its price straight from `computeDirectPoolPriceUsd`, itself derived from the pool's *current* `sqrtPriceX96` (no TWAP, no depth/impact adjustment): [2](#0-1) [3](#0-2) 

`UniswapV4LiquidityState.refresh` re-reads `getSlot0`/`getLiquidity` on demand right before every price query or withdrawal plan, so it always reflects the pool's instantaneous, manipulable state: [4](#0-3) 

The only defense is `checkPriceGuard`, which bounds deviation against a *static* `referencePrice`/`maxDeviationBps` — and this guard is explicitly optional per the docs ("omit both to leave the chain unguarded"): [5](#0-4) 

Even when configured, the guard only rejects quotes that drift beyond a fixed band; it does not detect a same-block flash manipulation that stays within the configured tolerance, and it performs no TWAP/oracle cross-check — confirmed by the project's own flow notes: [6](#0-5) 

Once a manipulated rate is accepted, `computeLegPolicyOutput` extends that mid price linearly across the entire quantity, and `UniswapV4FundingPlanner.planWithdrawalForToken` withdraws real LP liquidity from the solver's Uniswap V4 position to fund the fill at that price: [7](#0-6) 

### Impact Explanation
A user (unprivileged intent placer) can submit an order to `IntentGatewayV2` targeting a venue-priced (curveless) pair, having first manipulated the underlying Uniswap V4 pool's spot price with a flash swap. Simplex's solver, pricing the fill from the manipulated `sqrtPriceX96`, will withdraw disproportionately more of the exotic token from its LP position than the fair-value trade warrants, handing the attacker a profit funded by real solver-held liquidity — concrete theft of funds, directly analogous to the CoFiXProtocol spot-price manipulation exploit.

### Likelihood Explanation
The `[vault.uniswapV4]` price guard is optional by design and, even when set, only checks a static deviation band rather than any TWAP/oracle cross-check, so it does not stop within-tolerance same-block manipulation. Any chain/pair operating unguarded or with a loose `maxDeviationBps` is directly exposed, and flash-swap manipulation of a single pool's spot price is a well-understood, low-cost attack technique (the exact vector cited in the CoFiX report).

### Recommendation
Replace or supplement the raw `sqrtPriceX96` spot read with a TWAP (time-weighted average price) sourced from the pool's oracle observations, or cross-check against an independent price feed (e.g., Chainlink, as already used in `SimplexPaymaster`) before accepting a venue quote. Make the price guard mandatory for all venue-priced pairs rather than optional, and consider adding maximum per-order size limits scaled to pool depth to bound worst-case manipulation profit.

### Proof of Concept
1. Attacker identifies a Simplex-configured `[[pairs]]` entry with no `bidPriceCurve`/`askPriceCurve` (venue-priced) and either no `[vault.uniswapV4]` price guard or a loose `maxDeviationBps`.
2. Attacker flash-swaps a large amount through the referenced Uniswap V4 pool, shifting `sqrtPriceX96` far from fair value.
3. In the same block/transaction sequence, attacker submits an intent order to `IntentGatewayV2` for that pair.
4. Simplex's `FXFiller.resolveLegRates` → `UniswapV4FundingPlanner.getExoticTokenPrice` reads the manipulated spot price (no TWAP), passes any configured static-deviation guard if it's lax enough or absent, and quotes the fill at the skewed rate.
5. `planWithdrawalForToken` withdraws solver LP liquidity priced at the manipulated rate, over-crediting the attacker's fill.
6. Attacker reverses the flash swap, restoring the pool, and keeps the excess tokens extracted from the solver's inventory.

		orderId: string | undefined,
		leg: ResolvedLeg,
		cappedPairNotional: Decimal,
		venueUsdPrice: (chain: string, token1Address: string) => Promise<Decimal | null>,
	): Promise<LegRates | null> {
		// Explicitly configured curves always win — the venue only prices pairs
		// with no curves at all (and never same-token pairs, where a venue quote
		// would just be the asset's own USD price, not a spread).
		const curveless = !leg.pair.bidPricePolicy && !leg.pair.askPricePolicy
		if (curveless && !isSameTokenPair(leg.pair) && USD_STABLE_SYMBOLS.has(normalizeSymbol(leg.pair.token0))) {
			const venueUsd = await venueUsdPrice(leg.token1Chain, leg.token1Address)
			if (venueUsd) {
				// Guard compares the venue's token1-per-USD quote against the static reference.
				if (!this.checkPriceGuard(orderId, leg.token1Chain, new Decimal(1).div(venueUsd))) {
					return null
				}
				// A pool mid is ONE price, not a book: there is no opposite side
				// to report a round-trip margin against. The price guard above is
				// the venue-specific defense.
				const venueRate = new Decimal(1).div(venueUsd)
				return { rate: venueRate, oppositeRate: null, priceSource: "venue" }
			}

	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}

	private computeDirectPoolPriceUsd(
		pos: HydratedV4Position,
		sdkPool: V4Pool,
		chain: string,
	): { exoticToken: string; priceUsd: Decimal } | null {
		const usdc = this.configService.getUsdcAsset(chain).toLowerCase()
		const usdt = this.configService.getUsdtAsset(chain).toLowerCase()
		const c0 = pos.currency0.toLowerCase()
		const c1 = pos.currency1.toLowerCase()

		if (c0 === usdc || c0 === usdt) {
			// currency0 is stable → exotic is currency1
			// token1Price = "token0 per token1" = USD per exotic
			return {
				exoticToken: c1,
				priceUsd: new Decimal(sdkPool.token1Price.toFixed(18)),
			}
		}

		if (c1 === usdc || c1 === usdt) {
			// currency1 is stable → exotic is currency0
			// token0Price = "token1 per token0" = USD per exotic
			return {
				exoticToken: c0,
				priceUsd: new Decimal(sdkPool.token0Price.toFixed(18)),
			}
		}

		return null
	}

```text
## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.
```
