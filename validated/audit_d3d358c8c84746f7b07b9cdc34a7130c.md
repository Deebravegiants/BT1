### Title
Accrual overflow permanently freezes an oversized high-utilization market - (File: common/src/rates/simulate.rs)

### Summary
A market whose scaled debt or supply value approaches the `i128` ceiling can be pushed into a permanent failure state by the unprivileged `update_indexes` path. Once `scaled_to_original` overflows during accrual, every operation that syncs the market—including repayment, withdrawal, liquidation, and further index updates—reverts, leaving funds frozen absent a privileged contract upgrade.

### Finding Description
Each accrual step converts scaled supply and debt back to RAY-denominated principal through `scaled_to_original`, which performs `scaled.mul(index)`. [1](#0-0) [2](#0-1)  The multiplication is checked and raises `MathOverflow` when the resulting value cannot fit in `i128`. [3](#0-2) 

The borrow-index cap does not prevent this failure because the accrual must first compute the unscaled debt and supply values, and `update_borrow_index` caps only the index after multiplication. [4](#0-3) [5](#0-4)  Since the accrual aborts before `cache.mark_accrued()`, the stale timestamp remains and the next market operation repeats the same overflowing calculation. [6](#0-5) 

`Controller::update_indexes` is caller-authorized rather than owner-gated and directly invokes the pool accrual entrypoint. [7](#0-6) [8](#0-7)  Repayment and withdrawal also load a synced market leg before burning shares or moving cash, so neither path can bypass accrual. [9](#0-8) [10](#0-9) 

The repository already contains an end-to-end reproduction: a 1-billion-whole-token, 18-decimal market at 98% utilization reaches the RAY-value ceiling before the borrow-index cap, after which `update_indexes`, `withdraw`, and `repay` all fail with `MATH_OVERFLOW`. [11](#0-10) 

### Impact Explanation
The failed accrual freezes all accounting for the affected `(hub, token)` market. Suppliers cannot withdraw pool cash, borrowers cannot repay debt, liquidators cannot service the market, and cleanup or parameter changes cannot rescue it because those paths also accrue first. [6](#0-5) [12](#0-11) 

This is permanent freezing of user funds, not merely a transient transaction failure: the overflowing state transition cannot be committed, so the stored timestamp never advances and every subsequent operation reaches the same arithmetic boundary. [13](#0-12) 

### Likelihood Explanation
The trigger requires an exceptionally large market and sustained high utilization, so it is not reachable on every deployment. The reproduction uses an 18-decimal market with caps raised to the supported asset-domain maximum, a 1-billion-token supply, and a 0.98-billion-token borrow; those are valid runtime calls, although the listing configuration itself is governance-selected. [14](#0-13) [15](#0-14) 

For such a configured market, no privileged runtime action is needed: one funded address can call `supply`, `borrow`, and later `update_indexes` through the controller’s public authorized entrypoints. [16](#0-15) [7](#0-6) 

### Recommendation
Make accrual saturation-safe rather than letting value conversion abort the market. In particular, convert scaled values through a saturating or checked result that clamps index/state growth before `scaled * index / RAY` exceeds `i128`, and enforce the index cap before evaluating market-wide debt and supply values.

Add an explicit protocol invariant that market accrual cannot enter an unrecoverable arithmetic state, and cover the boundary with tests proving that `update_indexes`, `withdraw`, `repay`, `liquidate`, `clean_bad_debt`, and `recapitalize` remain callable at the maximum admitted index/value domain.

### Proof of Concept
The existing regression test provides the concrete sequence:

1. Configure an 18-decimal borrowable market whose cap permits a 1-billion-token position and a collateral market for the borrower. [17](#0-16) 
2. Call `Controller::supply(caller, 0, spoke_id, [(BIG18, 1_000_000_000 * 10^18)])`.
3. Supply sufficient `COL` collateral and call `Controller::borrow(caller, account_id, [(BIG18, 980_000_000 * 10^18)], None)`. [18](#0-17) 
4. Allow ledger time to elapse while utilization remains high, then call `Controller::update_indexes(caller, [BIG18])`. The call reaches `accrue_step`, where `scaled_to_original(borrowed, borrow_index)` raises `MathOverflow`. [19](#0-18) 
5. Subsequent `Controller::withdraw`, `Controller::repay`, `Controller::liquidate`, and `Controller::update_indexes` calls for `BIG18` repeat the failed accrual and revert before any state-changing recovery logic. The test explicitly demonstrates `MathOverflow` for `update_indexes`, `withdraw`, and `repay`. [20](#0-19)

```rust
/// `debug_assert` checks this in debug builds. Panics with `GenericError::DivisionByZero` if
/// `d == 0`, and with `GenericError::MathOverflow` if any other precondition is violated or if

        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
```

```rust
/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
