### Title
Global, unscoped `usedMessages` nonce lets any EOA permanently front-run/burn another user's pre-signed Emporium operation via `cancelEmporiumMessage` - ([File: contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol])

### Summary
`EmporiumUpgradeable.cancelEmporiumMessage` is meant to let a signer revoke their own pending, pre-signed off-chain Emporium message before it is executed. The EIP-712 signature it checks only proves that `msg.sender` authorized cancelling nonce `emporiumMessage` — it never proves that this nonce was reserved for or belongs to `msg.sender`. Because the `usedMessages` mapping is a single global namespace shared by every user [1](#0-0) , any unprivileged attacker can self-sign a cancellation for an arbitrary `emporiumMessage` value belonging to someone else's already-signed Emporium operation and permanently mark it as used, blocking the legitimate execution.

### Finding Description
`verifyWallet` consumes `circomData.emporiumMessage` from the shared, non-scoped mapping before any signature check for the signer-address==0 path, and generally treats the nonce space as global: [2](#0-1) 

`cancelEmporiumMessage` verifies only that `msg.sender` produced a valid signature over the `EmporiumCancel(uint256 message)` payload — it never checks that `message` corresponds to an operation actually signed by, or reserved for, `msg.sender`: [3](#0-2) 

Since any address can trivially self-sign an `EmporiumCancel` message for any `uint256 message` value with its own private key (recovering to `msg.sender`), an attacker who learns (or guesses/observes off-chain) the `emporiumMessage` nonce that Alice used in her `EmporiumSignature` (typed data she signed for a future `runAction` call) can call `cancelEmporiumMessage(aliceMessage, botV, botR, botS)` themselves. This sets `usedMessages[aliceMessage] = true` in the shared mapping, so that when Alice's (or her relay's) transaction later calls `Hinkal.transact` → `EmporiumUpgradeable.runAction` → `verifyWallet`, it hits: [4](#0-3) 
and reverts with `UsedMessage()`, permanently blocking that specific signed operation. This is the same bug class as the referenced report: a permissionless, unprivileged call claims/consumes a shared resource slot (there: a `(adapter, maturity)` pool key in `SpaceFactory`; here: a global message-nonce key in `usedMessages`) ahead of the legitimate actor, permanently breaking the legitimate actor's ability to use that pre-committed action.

### Impact Explanation
Emporium messages authorize wallet-invoking operations (`op.invokeWallet` calls through `IHinkalWallet.callHinkalWallet`, potentially moving/using shielded-derived funds and paying relay fees) [5](#0-4) . If a user signs such a message off-chain and relies on it being executable exactly once (e.g., a relay-submitted withdrawal/operation authorization), an attacker can permanently prevent that specific authorized action from ever executing by burning its nonce first. Because the compromised value is a specific pre-signed authorization tied to specific `ops`/fee terms, this results in freezing of the funds/action that message was meant to unlock until the user re-signs a brand-new message with a fresh nonce (assuming they can detect the failure and still control their signing key) — matching "temporary freezing of user funds" / unauthorized denial of a signer-authorized asset movement.

### Likelihood Explanation
Requires only knowledge of the target `emporiumMessage` nonce value (which is embedded in the calldata a relay would submit, or otherwise observable/guessable if callers use sequential or low-entropy nonces) and a trivial self-signed EIP-712 signature — no privileged role, no ability to forge someone else's key, and no complex race beyond ordinary front-running of the cancellation transaction ahead of the `runAction` transaction. This is straightforward for any EOA to execute once the target nonce is known.

### Recommendation
Scope `usedMessages` per authorized signer, e.g. `mapping(address => mapping(uint256 => bool))`, and require `cancelEmporiumMessage` to prove that `msg.sender` is the same `signerAddress` that the `EmporiumSignature` for that message was created for (or otherwise bind the nonce to the intended signer at the time it's chosen), so that a cancellation signed by an unrelated address cannot burn another user's reserved nonce.

### Proof of Concept
1. Alice signs an `EmporiumSignature` off-chain with `message = M`, intending to submit it later via a relay to `EmporiumUpgradeable.runAction`.
2. Attacker Bob observes/guesses `M` (e.g., from the relay's pending calldata, or because nonces are predictable/sequential).
3. Bob signs `EmporiumCancel(uint256 message = M)` with his own key and calls `cancelEmporiumMessage(M, v, r, s)`. The signature check passes because `recoveredAddress == msg.sender == Bob`, with no verification that `M` was ever associated with Bob.
4. `usedMessages[M]` is now `true` in the single shared mapping.
5. When Alice's transaction later reaches `Hinkal.transact` → `runAction` → `verifyWallet`, `$.usedMessages[circomData.emporiumMessage]` is `true`, and the call reverts with `UsedMessage()`, permanently blocking Alice's originally signed operation.

    /// @notice Lets a signer burn `emporiumMessage` before it's used, via a fresh signature
    /// recovering to msg.sender (so no one else can cancel it for them).
    function cancelEmporiumMessage(uint256 emporiumMessage, uint8 v, bytes32 r, bytes32 s) external {
        EmporiumStorageVars storage $ = _getEmporiumStorage();

        bytes32 hashedMessage = _hashTypedDataV4(
            keccak256(abi.encode(EMPORIUM_CANCEL_TYPEHASH, emporiumMessage))
        );

        (address recoveredAddress, ECDSA.RecoverError err) = ECDSA.tryRecover(hashedMessage, v, r, s);
        bool verified = err == ECDSA.RecoverError.NoError && recoveredAddress == msg.sender;
        if (!verified) {
            revert InvalidSignature();
        }

        $.usedMessages[emporiumMessage] = true;
    }
