### Title
Deprecated single-extension `StorageWeightReclaim` performs uncoordinated `BlockWeight` mutation, causing double/under-counting of reclaimed proof-size weight when not wrapping the full extension pipeline - ([File: cumulus/primitives/storage-weight-reclaim/src/lib.rs])

### Summary
The deprecated `allow_deprecated::StorageWeightReclaim::post_dispatch_details` directly mutates `frame_system::BlockWeight` based on its own snapshot of `post_info` without ever reading or writing the coordination storage item `frame_system::ExtrinsicWeightReclaimed`, unlike its successor `cumulus_pallet_weight_reclaim::StorageWeightReclaim`. When this legacy extension does not wrap the entire transaction-extension pipeline (i.e. is not the outermost/first element), extensions positioned between it and `frame_system::CheckWeight` in the post-dispatch execution order can further mutate `post_info.actual_weight`, causing `CheckWeight`'s independent `reclaim_weight` reduction to use a different "unspent" value than the one this extension already used, producing an under-accounted `BlockWeight`.

### Finding Description
`post_dispatch_details` at [1](#0-0)  computes `unspent = post_info.calc_unspent(info).proof_size()` and `benchmarked_weight = info.total_weight().proof_size() - unspent`, then directly `reduce`s/`accrue`s `frame_system::BlockWeight` by `storage_size_diff = |benchmarked_weight - consumed_weight|` [2](#0-1) . It never touches `frame_system::ExtrinsicWeightReclaimed` and always returns `Ok(Weight::zero())`, so it never communicates its adjustment to the rest of the pipeline.

`frame_system::CheckWeight::post_dispatch_details` separately calls `Pallet::<T>::reclaim_weight(info, post_info)` [3](#0-2) , which (per the pallet's coordination protocol demonstrated by the `extrinsic_already_refunded_more_precisely`/`extrinsic_already_refunded_less_precisely` tests) reads `ExtrinsicWeightReclaimed` to avoid re-reducing `BlockWeight` for work another extension already reclaimed, and then reduces `BlockWeight` again by `post_info.calc_unspent(info)` and records that into `ExtrinsicWeightReclaimed` [4](#0-3) .

Because the deprecated `StorageWeightReclaim` never populates `ExtrinsicWeightReclaimed`, `CheckWeight::reclaim_weight` treats it as "nothing was reclaimed yet" and applies its own full reduction based on `post_info.calc_unspent(info)` at whatever point in the pipeline it runs. If, between the deprecated extension's `post_dispatch_details` call and `CheckWeight`'s call, any other extension in the pipeline (declared such that its post_dispatch executes in between, since post_dispatch runs in reverse declaration order) further shrinks `post_info.actual_weight` via its own `post_dispatch_details` return value, `CheckWeight` will compute a larger `unspent` than the deprecated extension used. Algebraically the resulting `BlockWeight` contribution for the extrinsic becomes `consumed_weight + (unspent_at_T1 − unspent_at_T2)`; if `unspent_at_T2 > unspent_at_T1` this is strictly less than the truly measured `consumed_weight`, i.e. `BlockWeight` under-reports real PoV usage. This exactly matches the crate's own deprecation note: the extension "ignores post dispatch logic for extensions subsequent to itself" [5](#0-4) .

An unprivileged attacker does not need to control extension ordering (that is a runtime-config precondition), but given a runtime already misconfigured this way, any ordinary signed extrinsic whose dispatched call reports a lower `actual_weight` in its `PostDispatchInfo` than benchmarked (an extremely common, unprivileged pattern across FRAME pallets, e.g. calls using dynamic weight refunds) is sufficient to trigger the discrepancy — no special call is required.

### Impact Explanation
`BlockWeights::max_block`/`CheckWeight::do_prepare` gate how many extrinsics fit in a block by reading the bookkeeping `frame_system::BlockWeight` value [6](#0-5) . If that bookkeeping is systematically under-counted relative to true PoV proof-size consumption due to the uncoordinated double adjustment described above, more real resource-consuming extrinsics can be accepted into a single block than the configured `max_block` limit intends — a block weight/PoV limit bypass.

### Likelihood Explanation
This requires the documented misuse precondition: the deprecated `StorageWeightReclaim` not wrapping (not positioned as the outermost element of) the full transaction-extension pipeline, with at least one other weight-refunding extension positioned so its post-dispatch execution falls between this extension's and `CheckWeight`'s. This is a plausible runtime misconfiguration that the crate's own deprecation note explicitly warns about, and once present, is trivially and repeatably triggerable by any unprivileged user submitting ordinary extrinsics whose calls report reduced `actual_weight`.

### Recommendation
For runtimes still using the deprecated single-extension `StorageWeightReclaim`, enforce (ideally via a compile-time or `TryRuntime`/metadata check) that it is placed as the first/outermost extension in `SignedExtra`/`TxExtension`. Better, migrate to `cumulus_pallet_weight_reclaim::StorageWeightReclaim`, which wraps the whole pipeline and correctly coordinates via `frame_system::ExtrinsicWeightReclaimed`. As a stopgap, make the deprecated extension also read/write `ExtrinsicWeightReclaimed` the same way the new implementation does, so its adjustment is coordinated with `CheckWeight::reclaim_weight` regardless of pipeline position.

### Proof of Concept
Rust integration test plan (mock runtime with pipeline `[SomeWeightRefundingExtension, allow_deprecated::StorageWeightReclaim<T>, CheckWeight<T>]`, i.e. `StorageWeightReclaim` NOT first):
1. Dispatch a call with `DispatchInfo::call_weight = Weight::from_parts(100, 1000)` (proof_size benchmark 1000) whose `PostDispatchInfo.actual_weight = Some(Weight::from_parts(50, 400))`.
2. Mock the node-side proof size host function (`storage_proof_size`) to report a `consumed_weight` of, say, 300 (i.e., simulate real usage lower than the call's declared actual_weight-derived benchmark).
3. Insert a dummy extension before `StorageWeightReclaim` in the tuple whose `post_dispatch_details` further reduces `post_info.actual_weight.proof_size()` by an additional amount (e.g. 100) after `StorageWeightReclaim` has already run (simulating an extension whose post_dispatch executes between the two).
4. Record `BlockWeight::<T>::get()` before dispatch (`pre`), run the full extension pipeline's `post_dispatch`, and assert `BlockWeight::<T>::get().total().proof_size() == pre.proof_size() + consumed_weight` (300). Show that with the described misordering the actual result is strictly less than `pre + 300`, proving under-counting.

	fn post_dispatch_details(
		pre: Self::Pre,
		info: &DispatchInfoOf<T::RuntimeCall>,
		post_info: &PostDispatchInfoOf<T::RuntimeCall>,
		_len: usize,
		_result: &DispatchResult,
	) -> Result<Weight, TransactionValidityError> {
		let Some(pre_dispatch_proof_size) = pre else {
			return Ok(Weight::zero());
		};

		let Some(post_dispatch_proof_size) = get_proof_size() else {
			log::debug!(
				target: LOG_TARGET,
				"Proof recording enabled during pre-dispatch, now disabled. This should not happen."
			);
			return Ok(Weight::zero());
		};
		// Unspent weight according to the `actual_weight` from `PostDispatchInfo`
		// This unspent weight will be refunded by the `CheckWeight` extension, so we need to
		// account for that.
		let unspent = post_info.calc_unspent(info).proof_size();
		let benchmarked_weight = info.total_weight().proof_size().saturating_sub(unspent);
		let consumed_weight = post_dispatch_proof_size.saturating_sub(pre_dispatch_proof_size);

		let storage_size_diff = benchmarked_weight.abs_diff(consumed_weight as u64);

		let block_size = frame_system::BlockSize::<T>::get().unwrap_or(0);
		let node_side_pov_size = post_dispatch_proof_size.saturating_add(block_size.into());

		// This value will be reclaimed by [`frame_system::CheckWeight`], so we need to calculate
		// that in.
		frame_system::BlockWeight::<T>::mutate(|current| {
			if consumed_weight > benchmarked_weight {
				log::error!(
					target: LOG_TARGET,
					"Benchmarked storage weight smaller than consumed storage weight. extrinsic: {} benchmarked: {benchmarked_weight} consumed: {consumed_weight} unspent: {unspent}",
					frame_system::Pallet::<T>::extrinsic_index().unwrap_or(0)
				);
				current.accrue(Weight::from_parts(0, storage_size_diff), info.class)
			} else {
				log::trace!(
					target: LOG_TARGET,
					"Reclaiming storage weight. extrinsic: {} benchmarked: {benchmarked_weight} consumed: {consumed_weight} unspent: {unspent}",
					frame_system::Pallet::<T>::extrinsic_index().unwrap_or(0)
				);
				current.reduce(Weight::from_parts(0, storage_size_diff), info.class)
			}

			// If we encounter a situation where the node-side proof size is already higher than
			// what we have in the runtime bookkeeping, we add the difference to the `BlockWeight`.
			// This prevents that the proof size grows faster than the runtime proof size.
			let block_weight_proof_size = current.total().proof_size();
			let missing_from_node = node_side_pov_size.saturating_sub(block_weight_proof_size);
			if missing_from_node > 0 {
				log::debug!(
					target: LOG_TARGET,
					"Node-side PoV size higher than runtime proof size weight. node-side: {node_side_pov_size} block_size: {block_size} runtime: {block_weight_proof_size}, missing: {missing_from_node}. Setting to node-side proof size."
				);
				current.accrue(Weight::from_parts(0, missing_from_node), info.class);
			}
		});
		Ok(Weight::zero())
	}

	#[test]
	fn extrinsic_already_refunded_more_precisely() {
		new_test_ext().execute_with(|| {
			// This is half of the max block weight
			let info =
				DispatchInfo { call_weight: Weight::from_parts(512, 0), ..Default::default() };
			let post_info = PostDispatchInfo {
				actual_weight: Some(Weight::from_parts(128, 0)),
				pays_fee: Default::default(),
			};
			let prior_block_weight = Weight::from_parts(64, 0);
			let accurate_refund = Weight::from_parts(510, 0);
			let len = 0_usize;
			let base_extrinsic = block_weights().get(DispatchClass::Normal).base_extrinsic;

			// Set initial info
			BlockWeight::<Test>::mutate(|current_weight| {
				current_weight.set(Weight::zero(), DispatchClass::Mandatory);
				current_weight.set(prior_block_weight, DispatchClass::Normal);
			});

			// Validate and prepare extrinsic
			let pre = CheckWeight::<Test>(PhantomData)
				.validate_and_prepare(Some(1).into(), CALL, &info, len, 0)
				.unwrap()
				.0;

			assert_eq!(
				BlockWeight::<Test>::get().total(),
				info.total_weight() + prior_block_weight + base_extrinsic
			);

			// Refund more accurately than the benchmark
			BlockWeight::<Test>::mutate(|current_weight| {
				current_weight.reduce(accurate_refund, DispatchClass::Normal);
			});
			crate::ExtrinsicWeightReclaimed::<Test>::put(accurate_refund);

			// Do the post dispatch
			assert_ok!(CheckWeight::<Test>::post_dispatch_details(
				pre,
				&info,
				&post_info,
				len,
				&Ok(())
			));

			// Ensure the accurate refund is used
			assert_eq!(crate::ExtrinsicWeightReclaimed::<Test>::get(), accurate_refund);
			assert_eq!(
				BlockWeight::<Test>::get().total(),
				info.total_weight() - accurate_refund + prior_block_weight + base_extrinsic
			);
		})
	}
