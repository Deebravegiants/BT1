The SSRF analog here is clear in shape: the server making requests to attacker-influenced destinations maps to the router/controller invoking pool and token addresses named in caller-supplied route bytes. Let me verify the dispatch code.### Title
Unvalidated route venues let an attacker-named contract ride the caller's authorization tree and drain arbitrary wallet tokens - (File: contracts/swap-aggregator/src/execute/mod.rs, reachable via contracts/controller/src/strategies/swap.rs)

### Summary
The SSRF bug class — the application making a request to an attacker-influenced destination that its validation never actually constrained — maps directly onto XOXNO Lending's router strategies. The controller verbs `swap_collateral`, `swap_debt`, `multiply`, and `repay_debt_with_collateral` accept caller-supplied `swap: Bytes` and forward them to the router, which invokes whatever pool/token addresses the payload names. There is no venue or pool allowlist, so a route can place attacker-deployed code on the call stack *below* the caller's `require_auth` entry, and any `token.transfer(caller, attacker, amount)` that code performs is recorded as a child of the caller's signed authorization — stealing the caller's whole wallet, not just the routed input.

### Finding Description
- `Controller::swap_collateral` / `swap_debt` take a `swap: Bytes` argument from the caller and pass it untouched into `swap_tokens` (`contracts/controller/src/lib.rs:258-302`). [1](#0-0) 
- `swap_tokens` authorizes exactly one input transfer to the configured router and then calls `router.execute_strategy(&controller, &amount_in, swap)` inside the flash guard; the controller never inspects the route's destinations (`contracts/controller/src/strategies/swap.rs:33-38`). [2](#0-1) 
- The threat model states the router "calls the pool and token addresses its payload names and keeps no allowlist of them, so a route can put third-party code on the call stack below the caller's authorization," and that such a transfer "executes if the caller signs that tree" — bounding the loss by "the caller's wallet, not the routed amount" (`docs/explanation/threat-model.md:154-165`). [3](#0-2) 
- This is the direct analog of `HostCheck::isNotInternalHost` passing an unvalidated host to cURL: the "internal-host check" (allowlist of permitted destinations) does not exist, so the request-forging layer (the router executing caller-supplied XDR) connects to an arbitrary "loopback" — here, attacker-deployed contract code running inside the victim's delegated authority.

### Impact Explanation
Theft of user funds. A rogue pool contract invoked as a hop can execute `token::Client::transfer(victim, attacker, amount)` for *any* token the victim holds, as a sub-invocation of the victim's `swap_collateral` (etc.) authorization entry. The harness test proves the host records `wallet_token.transfer(alice → attacker, WALLET_BALANCE)` beneath the caller's `swap_collateral` root and the transfer succeeds when signed, draining all `77_770_000_000` units of an unlisted wallet token while the swap itself settles "fairly" (`tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs:194-227`). [4](#0-3) 

### Likelihood Explanation
An unprivileged address can deploy the rogue pool and craft the route bytes (no privilege required — routes are built off-chain and passed as XDR). Exploitation requires a victim to sign a poisoned route — e.g., served by a malicious/compromised quote source or pasted route — which is precisely the SSRF pretext (attacker controls the request destination an authorized party submits). Because the theft appears only as a sub-invocation in simulation and the swap's own min-out and the controller's risk gates still pass, the poisoned transaction is indistinguishable from an honest one until the victim inspects the auth tree — a mitigation the threat model itself pushes onto clients rather than enforcing on-chain.

### Recommendation
Constrain route destinations on-chain: maintain a governance-managed allowlist of pool/venue adapter addresses (or venue enum → registered pool mapping) in the router and reject hops naming unlisted contracts, mirroring how Blend migration already requires an approved pool (INV-STRAT-03). Alternatively/additionally, have the controller's `swap_tokens` verify — via the recorded invocation structure or a router-side guarantee — that no token transfer naming `sender`/`caller` as `from` occurs outside the single authorized input pull.

### Proof of Concept
The repository already contains a working PoC: `tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs`. `UnlistedPoolRouter::execute_strategy` invokes `route.hop_pool.swap()` — an address taken verbatim from the payload (`lines 39-47`); `RogueHopPool::swap` performs `token.transfer(victim → attacker, amount)` for a token the protocol never listed (`lines 62-71`); and the test asserts the recorded auth tree places the stolen transfer under Alice's signed `swap_collateral` root while her balance goes to zero (`lines 206-226`). Note on scope: the fix location sits in the swap-aggregator, which the rules partially exclude as "internals," but the reachable attack surface is the in-scope controller strategy verbs and the threat model itself treats unallowlisted venues as the exposure boundary, so I report it rather than reject it.

    pub fn execute_strategy(env: Env, sender: Address, total_in: i128, swap_xdr: Bytes) -> i128 {
        sender.require_auth();
        let route = RoutedSwap::from_xdr(&env, &swap_xdr).expect("route must decode");
        let router = env.current_contract_address();
        token::Client::new(&env, &route.token_in).transfer(&sender, &router, &total_in);
        let _: Val = env.invoke_contract(&route.hop_pool, &symbol_short!("swap"), vec![&env]);
        token::Client::new(&env, &route.token_out).transfer(&router, &sender, &route.min_out);
        route.min_out
    }

#[test]
fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
}
