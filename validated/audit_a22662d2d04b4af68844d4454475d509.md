### Title
Permanent market freeze: `borrowed * borrow_index` overflows i128 inside accrual before the index cap can engage - (File: common/src/rates/index.rs)

### Summary
The borrow-index cap `MAX_BORROW_INDEX_RAY` is applied to `new_index` inside `update_borrow_index`, but every interest-accrual step first computes `borrowed.mul(env, old_borrow_index)` and `borrowed.mul(env, new_borrow_index)` in `calculate_supplier_rewards`. For a market with very large scaled debt, the scaled-debt × index product overflows `i128` and panics with `GenericError::MathOverflow` while `borrow_index` is still below the cap. Since every pool verb accrues first via `global_sync`, the market then permanently reverts on supply/borrow/withdraw/repay/liquidate/`update_indexes`, freezing all supplier and borrower funds in that market. The repository's own adversarial test demonstrates this exact cliff.

### Finding Description
- `update_borrow_index` caps the index at `MAX_BORROW_INDEX_RAY`, but only after `old_index.mul(env, interest_factor)` succeeds [1](#0-0) .
- `calculate_supplier_rewards` multiplies the full scaled `borrowed` by both indexes with checked `Ray::mul`; the product overflows `i128` long before `new_index` can reach the cap, because `borrowed` is itself a RAY-scaled value [2](#0-1) .
- `accrue_step` is invoked on every state transition through `global_sync`, which chunks elapsed time into `MAX_COMPOUND_DELTA_MS` windows and runs before any supply/borrow/withdraw/repay/seize logic [3](#0-2) .
- Once `borrowed.raw() * borrow_index.raw() / RAY` exceeds `i128::MAX`, the panic is unrecoverable: nothing reduces `borrowed` or `borrow_index`, no cleanup path bypasses accrual, and even the permissionless `update_indexes`/`clean_bad_debt`/`recapitalize` entrypoints route through `global_sync`.
- This is proven in-tree: `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` shows `try_update_indexes_for`, `try_withdraw_raw`, and `try_repay` all failing with `MATH_OVERFLOW`, with `borrow_index < MAX_BORROW_INDEX_RAY` at the failure point [4](#0-3) .

### Impact Explanation
Permanent freezing of funds and denial of service for an entire market: all suppliers' deposits and all borrowers' collateral in that `(hub, token)` book become unrecoverable, and liquidations can no longer execute — satisfying both the "complete DOS" bug class of CVE-2022-21617 and the "permanent freezing of funds / contract unable to operate" acceptance criteria.

### Likelihood Explanation
Reachable by an unprivileged attacker using only `supply` and `borrow`: deposit a very large principal in a high-decimal asset, borrow to sustained high utilization on a steep rate curve, and wait for accrual to cross the `i128` product ceiling. The trigger requires whale-scale capital and sustained accrual (the test uses ~10^27 units of an 18-decimal asset at ~98% utilization over years on the XLM curve), so it is not cheap or instant — but it requires no privileges, no oracle manipulation, and no cooperation, and once crossed the freeze is irreversible. The protocol's own documented bound in `docs/reference/formulas.md` was found wrong by the in-tree test, so the cliff exists below the designed safety margin.

### Recommendation
Bound the accrual arithmetic rather than the index alone:
1. Compute `new_total_debt` via `mul_div`-style arithmetic with saturation (as `mul_div_floor_saturating` already does elsewhere), or compute `accrued_interest` as `borrowed * (new_index - old_index)` to keep intermediate products small.
2. When `borrowed * borrow_index` would exceed the representable domain, clamp `borrow_index` to `MAX_BORROW_INDEX_RAY` first and re-derive scaled debt, instead of panicking.
3. Add a fail-safe accrual bypass (e.g., a `clean_bad_debt`/`recapitalize` path that skips `global_sync` or force-caps the index) so an overflowed market remains governable.

### Proof of Concept
The existing test is the PoC. `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:320-360`: supply `BILLION * 10^18` of `BIG18`, borrow ~98% of it, advance time in yearly steps calling `update_indexes`; after a few years `try_update_indexes_for` returns `MATH_OVERFLOW`, and subsequently `try_withdraw_raw` and `try_repay` revert with the same error while `borrow_index < MAX_BORROW_INDEX_RAY` — the market is permanently frozen.

```rust
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
```

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}
```

```rust
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
```
