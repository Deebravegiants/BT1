### Title

Unbounded RAY valuation overflows during accrual and permanently freezes a market - (File: common/src/rates/simulate.rs)

### Summary

A sufficiently large market can drive `scaled * index` beyond the `i128` range during interest accrual, causing `MathOverflow` before any withdrawal, repayment, liquidation, or rescue operation can update market state. [1](#0-0) [2](#0-1) 

### Finding Description

`interest::global_sync` invokes `accrue_chunk`, which calls `accrue_step` before updating any market state. [3](#0-2) 

`accrue_step` first materializes total debt and total supply as `borrowed * borrow_index` and `supplied * supply_index` through `scaled_to_original`. [4](#0-3) 

`scaled_to_original` is a checked `Ray` multiplication, so a market whose scaled balances remain individually valid can still overflow `i128` once its index has grown sufficiently. [5](#0-4) [6](#0-5) 

The borrow-index ceiling limits only the index, not the derived total-debt or total-supply value, so the product can overflow before `MAX_BORROW_INDEX_RAY` or `MAX_SUPPLY_INDEX_RAY` is reached. [7](#0-6) [8](#0-7) 

An unprivileged caller can create the condition through `Controller::supply` and `Controller::borrow`, then advance accrual through the permissionless `update_indexes` path; `markets::update_indexes` requires caller authorization but no privileged role. [9](#0-8) [10](#0-9) 

The in-repository reproduction shows a large high-utilization market reverting with `MathOverflow`, after which both withdrawal and repayment attempt the same accrual and fail. [11](#0-10) 

### Impact Explanation

Once the next accrual would make a RAY-denominated market value exceed `i128`, the market becomes permanently unable to accrue. [1](#0-0) 

Because repayment and withdrawal run accrual before mutating positions, suppliers cannot recover cash and borrowers cannot reduce debt; the regression test explicitly demonstrates both failures. [12](#0-11) 

This permanently freezes funds already deposited in the affected market and also prevents normal liquidation or cleanup paths that depend on the same accrual sequence. [13](#0-12) 

### Likelihood Explanation

The issue requires a market near the protocol’s very large scaled-value domain and sustained interest accrual, so it is not triggerable in an arbitrary small market. [14](#0-13) 

However, it does not require privileged execution: the attacker only needs assets, a market whose configured caps admit the position, and calls to `supply`, `borrow`, and `update_indexes`. [10](#0-9) [15](#0-14) 

The consequence is a permanent freeze rather than a temporary failed transaction, because no later accrual can pass the same overflowing calculation. [16](#0-15) [17](#0-16) 

### Recommendation

Avoid materializing `scaled * index` as an unbounded `i128` during accrual. [18](#0-17) 

Compute utilization and index changes using quotient-first or widened arithmetic, and enforce a per-market index ceiling such as `i128::MAX * RAY / scaled` before applying index growth. [19](#0-18) 

At minimum, cap or saturate the accrual projection instead of reverting, so repayment, withdrawal, liquidation, and bad-debt cleanup remain executable even after a market reaches its representable-value ceiling. [20](#0-19) [21](#0-20) 

### Proof of Concept

The existing regression test builds an 18-decimal market, supplies `1_000_000_000 * 10^18` base units, borrows 98% of it, advances accrual, and observes `MathOverflow` before the index cap is reached. [22](#0-21) 

```rust
let market = HubAssetKey { hub_id, asset: big18_token };
let collateral = HubAssetKey { hub_id, asset: collateral_token };

let principal = 1_000_000_000i128 * 10i128.pow(18);
let debt = principal * 98 / 100;

let account_id = controller.supply(
    attacker.clone(),
    0,
    spoke_id,
    vec![
        &env,
        (collateral, enough_collateral),
        (market.clone(), principal),
    ],
);

controller.borrow(
    attacker.clone(),
    account_id,
    vec![&env, (market.clone(), debt)],
    Some(attacker.clone()),
);

// Advance ledger time until the next accrual would make
// supplied * supply_index or borrowed * borrow_index exceed i128::MAX.
controller.update_indexes(attacker.clone(), vec![&env, market.clone()]);

// Every subsequent state-changing path accrues first and reverts.
controller.withdraw(attacker.clone(), account_id, vec![&env, (market.clone(), 1)], None);
controller.repay(attacker, account_id, vec![&env, (market, 1)]);
```

The test then confirms that `update_indexes`, `withdraw`, and `repay` all fail with `MathOverflow`, leaving the market frozen. [23](#0-22)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);

pub fn try_mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> Option<i128> {
    if x < 0 || y < 0 || d <= 0 {
        return None;
    }
    let half = d / 2;

    // Fast path: the biased product fits `i128`, so the whole computation is
    // native. `x * y + half` is non-negative here, so `/` is the floor the
    // widened path would produce.
    if let Some(biased) = x
        .checked_mul(y)
        .and_then(|product| product.checked_add(half))
    {
        return Some(biased / d);
    }

    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    x256.mul(&y256)
        .add(&I256::from_i128(env, half))
        .div(&d256)
        .to_i128()
}

pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}

/// Grows `old_index` by distributing `rewards_increase` over the total value
/// currently supplied (`supplied * old_index`). The division rounds down.
///
/// Returns `old_index` unchanged if `supplied` or `rewards_increase` is zero,
/// or if the total supplied value is zero. Clamps the result between
/// `old_index` (itself capped at `MAX_SUPPLY_INDEX_RAY`) and
/// `MAX_SUPPLY_INDEX_RAY`, so the returned index never decreases and never
/// exceeds the cap.
pub fn update_supply_index(env: &Env, supplied: Ray, old_index: Ray, rewards_increase: Ray) -> Ray {
    if supplied == Ray::ZERO || rewards_increase == Ray::ZERO {
        return old_index;
    }

    let total_supplied_value = supplied.mul(env, old_index);

    if total_supplied_value == Ray::ZERO {
        return old_index;
    }

    let new_value = total_supplied_value.checked_add(env, rewards_increase);
    let grown = fp_core::mul_div_floor_saturating(env, new_value.raw(), RAY, supplied.raw());

    let bounded_old = old_index.raw().min(MAX_SUPPLY_INDEX_RAY);
    Ray::from(grown.min(MAX_SUPPLY_INDEX_RAY).max(bounded_old))

pub(crate) fn accounting(env: &Env, action: &PoolAction) -> RepayOutcome {
    let (mut cache, position) = ops::load_leg(env, action);
    let amount = action.amount;

    let (burned, overpayment) = cache.resolve_repay(amount, position);
    let net_repay = amount
        .checked_sub(overpayment)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));
    assert_with_error!(
        env,
        net_repay == 0 || burned.raw() > 0,
        GenericError::RepayRoundsToZeroShares
    );

    let position = position.checked_sub(env, burned);
    cache.burn_debt(burned);

    cache.credit_cash(net_repay);

    let snapshot = cache.commit();
