## Title
View-role users can read External Initiator `OutgoingToken` secrets via `GET /v2/external_initiators` - (File: core/web/router.go)

## Summary
The `/v2/external_initiators` list endpoint is registered without any role gate, while `Create` and `Destroy` on the same resource explicitly require `auth.RequiresEditRole`. This inconsistency lets an authenticated `UserRoleView` session enumerate every configured External Initiator's `OutgoingToken` (and `AccessKey`), a secret meant to be limited to higher-privileged users.

## Finding Description
In `v2Routes`, the `GET /v2/external_initiators` route is wired directly to `paginatedRequest(eia.Index)` with no role wrapper, whereas `POST` and `DELETE` for the same resource are wrapped in `auth.RequiresEditRole`: [1](#0-0) 

`RequiresEditRole` explicitly blocks `UserRoleView` and `UserRoleRun`, proving the app's RBAC model intends this resource to be edit-only, yet that check is absent from the GET route: [2](#0-1) 

`ExternalInitiatorsController.Index` builds `ExternalInitiatorResource` for every stored initiator with no additional filtering by caller role: [3](#0-2) 

`ExternalInitiatorResource` includes the raw `OutgoingToken` field, populated straight from the stored `bridges.ExternalInitiator.OutgoingToken`: [4](#0-3) 

The route-role test matrix documents this as an accepted/expected behavior, explicitly marking `GET /v2/external_initiators` as `viewOnlyAllowed: true`, in contrast to `POST`/`DELETE` for the same path which are marked `false`: [5](#0-4) 

The dedicated controller test also confirms `OutgoingToken` is present in the JSON response body returned by `Index` for an unauthenticated/any-role client (`client := app.NewHTTPClient(nil)`), and explicitly asserts `OutgoingToken` equality in the response: [6](#0-5) 

## Impact Explanation
A `UserRoleView` session — the lowest privilege tier in chainlink's RBAC, intended only for read-only/audit access — can retrieve the `OutgoingToken` (and `AccessKey`) for every configured External Initiator without being able to create or delete them. This secret is generated at initiator-creation time via `utils.NewSecret(utils.DefaultSecretSize)` and used by the node to authenticate itself to the initiator's webhook endpoint. Exposure of this token to a lower-privileged role than intended constitutes a secret-exfiltration / broken access-control bug that maps to the "key/secret exfiltration" and "node API authentication or role bypass" impact classes in scope.

## Likelihood Explanation
Exploitation requires only a valid, authenticated `UserRoleView` API session/token — a normal, supported credential tier — and a single unauthenticated-role-gated GET request. No admin/host access, social engineering, or unusual configuration is needed, making this reliably reproducible in any deployment that provisions view-only credentials (e.g., auditors, monitoring tools, dashboards).

## Recommendation
Wrap `GET /v2/external_initiators` with `auth.RequiresEditRole` (or a dedicated read-role check greater than `UserRoleView`) to match the protection level of `Create`/`Destroy`, and/or strip `OutgoingToken`/`OutgoingSecret` from the list response entirely, since operators typically only need these secrets once, at creation time.

## Proof of Concept
1. As admin, `POST /v2/external_initiators {"name":"foo","url":"http://example.com"}`; note the response's `outgoingToken`.
2. Create/obtain a session for a user provisioned with `UserRoleView`.
3. As that view-role user, call `GET /v2/external_initiators`; the JSON response includes `outgoingToken` for `foo`, confirmed by the existing test at `core/web/external_initiators_controller_test.go:63-126` and the RBAC route matrix at `core/web/auth/auth_test.go:224`, which explicitly allow this route for view-only sessions while blocking `POST`/`DELETE`.

func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}
