### Title
Unpriceable collateral leg blocks liquidation and bad-debt cleanup - ([File: contracts/controller/src/risk/totals.rs](contracts/controller/src/risk/totals.rs))

### Summary
A borrower can attach a listed Aquarius LP token as a collateral leg, then withdraw that AMM pool's liquidity below the configured `min_pool_value_wad`. Because every collateral position is priced during account-risk calculation, the resulting `InsufficientAquariusLiquidity` failure aborts liquidation and bad-debt cleanup for the entire account, even if the LP position is economically insignificant. This is a Medium-severity availability analog to CVE-2022-39408. [1](#0-0) [2](#0-1) 

### Finding Description
`supply` lets an account owner add a listed collateral asset and creates a persistent nonzero supply position. [3](#0-2)  `calculate_account_risk_totals` loads every supply and debt hub asset and fetches every distinct token price before valuing the account. [4](#0-3)  `liquidate` must call this account valuation before checking `health_factor < 1`, so one unreadable collateral price prevents even a perfectly healthy-to-underwater transition from being processed. [5](#0-4)  `clean_bad_debt` independently calls the same valuation before testing whether debt exceeds collateral and collateral is below the dust cap, so it fails on the same leg. [6](#0-5)  The Aquarius provider returns `InsufficientAquariusLiquidity` whenever `price_wad * total_shares / share_unit < min_pool_value_wad`, and production market configuration includes Aquarius LP sources with nonzero value floors. [7](#0-6) [8](#0-7) 

### Impact Explanation
The attacker can keep borrowed funds while every liquidation attempt reverts before repayment or seizure. [5](#0-4)  The same poisoned leg prevents permissionless bad-debt socialization, delaying recognition of losses and leaving suppliers exposed while the LP pool remains below the floor. [6](#0-5)  This is temporary freezing of the affected collateral and liquidation path: restoring Aquarius liquidity above the floor makes the oracle usable again. [1](#0-0) 

### Likelihood Explanation
The attack needs no privileged role: the borrower uses `supply` for the LP leg, `borrow` for the debt, and their own Aquarius LP withdrawal to push the pool's total value under `min_pool_value_wad`. [9](#0-8) [10](#0-9)  The borrower need only leave a small residual LP position on the lending account; its economic value is irrelevant because the code prices the position before considering its size. [11](#0-10)  Feasibility depends on controlling enough of the relevant Aquarius pool to drain it below its configured floor, but the attacker recovers the withdrawn underlying liquidity and only sacrifices the residual LP leg used as the blocker. [1](#0-0) 

### Recommendation
Do not let an unusable collateral price abort the entire account valuation. Treat an invalid or below-floor collateral leg as zero-valued and exclude it from pro-rata seizure while preventing it from contributing collateral, or quarantine such legs through an explicit recovery path that still permits liquidation and deterministic bad-debt handling. At minimum, add regression coverage for a nonzero Aquarius LP collateral leg whose pool is one unit below `min_pool_value_wad`. [11](#0-10) [1](#0-0) 

### Proof of Concept
1. The attacker calls `supply(attacker, 0, spoke_id, [(lp_hub_asset, residual_lp_amount)])`, then calls `borrow` to open debt against ordinary priced collateral. [9](#0-8) 
2. The attacker withdraws their remaining liquidity from the configured Aquarius pool until its computed pool value is below `min_pool_value_wad`, while leaving the residual LP token deposited as lending collateral. [1](#0-0) 
3. After the ordinary collateral loses enough value for `HF < 1`, a liquidator calls `liquidate(liquidator, account_id, [(debt_asset, amount)], SeizeMode::Transfer)`; planning invokes `calculate_account_risk_totals`, requests the LP price, receives `InsufficientAquariusLiquidity`, and reverts. [5](#0-4) [1](#0-0) 
4. A caller then invokes `clean_bad_debt(caller, account_id)`; it reaches the same all-position valuation and reverts before testing the dust-gated insolvency predicate. [6](#0-5) 
5. The existing harness demonstrates the same blocker class: a successfully supplied dust leg with a stale price makes `liquidate`, `clean_bad_debt`, and `withdraw` revert, while refreshing the price makes the identical liquidation succeed. [12](#0-11)

        &mut cache,
    );
