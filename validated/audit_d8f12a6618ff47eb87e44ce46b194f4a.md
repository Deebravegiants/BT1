### Title
Bad-debt write-down clamps `supply_index` up to `SUPPLY_INDEX_FLOOR_RAW`, leaving wiped suppliers a phantom claim that drains fresh deposits - ([File: contracts/pool/src/interest.rs])

### Summary
The bad-debt cleanup path in `contracts/pool/src/interest.rs` (`apply_bad_debt_to_supply_index`, reachable through the unprivileged `clean_bad_debt` flow) reduces the supply index by `bad_debt / supplied_shares`. When the wiped debt exceeds the total floored supply value, the subtraction would go negative — an underflow. Instead of zeroing the index (or the shares), the code clamps `supply_index` **up** to `SUPPLY_INDEX_FLOOR_RAW = RAY/1000` (`contracts/pool/README.md` documents the bound; `contracts/pool/tests/interest.rs:372-427` exercises it). Every pre-existing scaled supply position therefore retains a positive floor-valued claim even though its backing was fully written off.

### Finding Description
`backing_shortfall` and share valuation use `cache.unscale_supply_floor(cache.supplied())` against the live `supply_index` (`contracts/pool/src/guards.rs:61-66`, `contracts/pool/src/cache/scale.rs:60-67`). After a wipeout write-down:

- `supply_index` is pinned at `RAY/1000`, not `0`.
- Old holders' `scaled_amount` shares are untouched, so `unscale_supply_floor(old_scaled) > 0` — a stranded, unbacked claim.
- `resolve_withdrawal` (`common/src/rates/scaling.rs`, wired at `contracts/pool/src/cache/scale.rs:97-105`) pays that claim in real tokens, gated only by `require_reserves`/`require_liquidation_buffer` (`contracts/pool/src/guards.rs:39-47`), i.e. by whatever cash happens to be in the pool.
- `require_backed_market` runs only on `supply` (`contracts/pool/README.md:267-270`), so withdrawals after a fresh deposit are not blocked by the insolvency guard.

The in-repo test `test_raw_cache_floor_clamp_strands_claim_without_supply_guard` (`contracts/pool/tests/interest.rs:373-427`) proves the mechanics end-to-end: wiped shares unscale to a positive claim, a fresh supplier's deposit mints shares whose claim equals the deposit, and the old position's `resolve_withdrawal` + `require_reserves` + `debit_cash` sequence "drains exactly the fresh deposit," leaving `cash < fresh_claim`.

### Impact Explanation
Theft of user funds. An unprivileged holder of wiped shares (possibly the same attacker who created the bad debt via `clean_bad_debt` after an insolvent liquidation) waits for any honest user to `supply` into the written-down market, then calls `withdraw` (or sells the position NFT). The stranded claim pays out the new depositor's principal; the new depositor is left with shares the pool can no longer cover. No privileged call, oracle manipulation, or timing privilege is required beyond the bad-debt state itself.

### Likelihood Explanation
Requires a market to reach a wipeout bad-debt state (`bad_debt > supplied_claim` at `clean_bad_debt` time), which is a tail event — it needs an insolvent account whose remaining debt is cleaned while collateral is gone. But once reached, the theft is deterministic: the floor clamp guarantees a positive stranded claim, and only incidental cash-reserve checks stand between it and a payout. The pool's own test suite demonstrates the drain against raw-cache semantics; I did not fully verify whether a production guard elsewhere blocks `withdraw` in this exact state — `require_reserves` is the documented masking invariant, and it is satisfiable as soon as any deposit lands.

### Recommendation
In `apply_bad_debt_to_supply_index`, when the write-down would drive `supply_index` below `SUPPLY_INDEX_FLOOR_RAW` (i.e., bad debt ≥ floored supply value), treat it as a full wipeout: set `supply_index` to `RAY` (or `0` and zero `supplied` shares), rather than clamping up to `RAY/1000`. The clamp exists to avoid division-by-zero on subsequent mints, but preserving a non-zero index over zero backing manufactures unbacked claims. Alternatively, burn `supplied` shares alongside the clamp so `unscale_supply_floor` returns zero for wiped positions.

### Proof of Concept
```rust
// contracts/pool/tests/interest.rs — existing test demonstrating the loss
let mut cache = t.fresh_cache(PoolStateRaw {
    supplied: 1_000 * RAY, borrowed: 0, revenue: 0,
    borrow_index: RAY, supply_index: RAY, last_timestamp: 0, cash: 0,
});
apply_bad_debt_to_supply_index(&mut cache, Ray::from(5_000 * RAY));
// supply_index clamps UP to RAY/1000; old shares keep a phantom claim:
assert!(cache.unscale_supply_floor(old_scaled) > 0);

// fresh supplier deposits `fresh_cash`; old wiped holder withdraws:
let (burn, gross) = cache.resolve_withdrawal(i128::MAX, old_scaled);
cache.require_reserves(gross);   // passes — funded by the fresh deposit
cache.burn_supply(burn);
cache.debit_cash(gross);
assert_eq!(gross, fresh_cash);   // stranded claim drains the fresh deposit
assert!(cache.cash() < cache.unscale_supply_floor(fresh_scaled)); // fresh supplier shortchanged
```

Attack path: `clean_bad_debt` (unprivileged) on a wiped market → victim `supply` → attacker `withdraw`. Note: verification of the end-to-end path through the live `clean_bad_debt`/`withdraw` entrypoints (vs. the raw-cache test) was not fully completed within available iterations; the accounting primitives the test exercises are the same ones the production ops call.
