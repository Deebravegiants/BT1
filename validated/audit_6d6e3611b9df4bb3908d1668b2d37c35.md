### Title
Suppliers can front-run `clean_bad_debt`/`liquidate` to exit at the pre-write-down supply index, shifting the socialized loss onto remaining suppliers — (File: contracts/pool/src/interest.rs)

### Summary
XOXNO Lending socializes bad debt by writing down the affected market's `supply_index` inside `apply_bad_debt_to_supply_index` (`contracts/pool/src/interest.rs:73-89`), but the write-down is only applied when a permissionless `clean_bad_debt` call or a liquidation executes. Between the moment an account becomes insolvent (publicly observable via oracle prices) and the moment the write-down transaction executes, any supplier can call `withdraw` and exit at the un-written-down index. A test explicitly pins this behavior: `supplier_can_exit_ahead_of_bad_debt_writedown` (`tests/test-harness/tests/controller/bad_debt_index.rs:402-473`) shows Bob exiting whole while Carol's loss amplifies ~4x.

### Finding Description
The analog of the reported "sudden loss distribution" is the supply-index write-down in `interest::apply_bad_debt_to_supply_index`. The entire eligible debt is removed in one step: `new_supply_index = max(supply_index * remaining/total_supplied_value, SUPPLY_INDEX_FLOOR_RAW)` [1](#0-0) . The documentation confirms the index "grows on interest, falls on bad debt" [2](#0-1)  and that the loss "is written down only when a liquidation or cleanup call runs, and `backing_shortfall` counts the unrecoverable debt at face value until then" [3](#0-2) .

Permissionless `clean_bad_debt` is callable by any unprivileged address once the account's collateral is at or below the $5 dust threshold and ceil debt exceeds half-up collateral [4](#0-3) . Withdrawal is not blocked: the test notes "the liquidation buffer only guards borrow draws, and `backing_shortfall` still values Alice's uncollateralised debt at face" [5](#0-4) . Withdrawal remains callable even under global pause [6](#0-5) .

Attack path: an unprivileged supplier watches oracle prices (`get_account_positions`/`liquidatable` state is public), sees an account go insolvent in a market they supply, submits `controller::withdraw` before anyone calls `clean_bad_debt`/`liquidate`, and exits at the pre-write-down index. The same write-down is then distributed over fewer shares, concentrating the loss on passive suppliers.

### Impact Explanation
Loss that should be socialized pro-rata is instead borne disproportionately by suppliers who did not front-run — a direct transfer of value from passive suppliers to the exiting attacker. This is theft of user funds (Medium impact): each individual extraction is bounded by the attacker's share, but repeatability across every bad-debt event makes the protocol systematically unfavorable to passive suppliers.

### Likelihood Explanation
Insolvency conditions are publicly derivable from oracle prices, and `clean_bad_debt` is permissionless so there is no privileged ordering that prevents the race — the attacker only needs to sequence a `withdraw` before the cleanup transaction in the same ledger or earlier. Soroban transaction ordering makes front-running feasible whenever the insolvency is predictable. Likelihood: Medium.

### Recommendation
Either socialize the loss over time (accrue bad debt gradually into the supply index rather than in one step), or account for pending eligible bad debt at withdrawal time — e.g., value the withdrawal against a virtual index that already reflects the worst-case write-down implied by currently insolvent accounts, or gate withdrawals on the difference between the committed index and a bad-debt-adjusted index.

### Proof of Concept
The behavior is pinned by `supplier_can_exit_ahead_of_bad_debt_writedown` [7](#0-6) :

1. Bob supplies 75 ETH, Carol supplies 25 ETH; Alice borrows ETH against USDC collateral.
2. USDC price is crashed to `usd_cents(10)`, making Alice insolvent — this is public state; `t.assert_liquidatable(ALICE)` passes.
3. Scenario B: Bob calls `withdraw_all(BOB, "ETH")` before `liquidate`, recovering `>= bob_before` in full at the un-written-down index.
4. `clean_bad_debt`/liquidation then applies `apply_bad_debt_to_supply_index`, and Carol — now 100% of remaining supply — absorbs ~4x the loss she would have borne if Bob had stayed (`amplification > 3.0` assertion).

The asymmetric outcome is mechanically guaranteed: the write-down formula divides the capped loss over `total_supplied_value` at execution time [8](#0-7) , so every share that exits before execution removes itself from the denominator without reducing the loss.

```rust
pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}
```

```rust
fn supplier_can_exit_ahead_of_bad_debt_writedown() {
    // Scenario A: nobody dodges. Bob 75%, Carol 25% of the ETH supply.
    let mut a = setup();
    a.supply(BOB, "ETH", 75.0);
    a.supply(CAROL, "ETH", 25.0);
    a.supply(ALICE, "USDC", 10.0);
    a.borrow(ALICE, "ETH", 0.003);

    let carol_before_a = a.supply_balance(CAROL, "ETH");
    a.set_price("USDC", usd_cents(10));
    a.liquidate(LIQUIDATOR, ALICE, "ETH", 0.001);
    let carol_loss_a = carol_before_a - a.supply_balance(CAROL, "ETH");

    // Scenario B: identical state, but Bob withdraws before the write-down.
    let mut b = setup();
    b.supply(BOB, "ETH", 75.0);
    b.supply(CAROL, "ETH", 25.0);
    b.supply(ALICE, "USDC", 10.0);
    b.borrow(ALICE, "ETH", 0.003);

    let carol_before_b = b.supply_balance(CAROL, "ETH");
    let bob_before_b = b.supply_balance(BOB, "ETH");
    let bob_wallet_before = b.token_balance(BOB, "ETH");

    // The crash is public state. Alice is insolvent from here on, but no
    // write-down has been applied yet.
    b.set_price("USDC", usd_cents(10));
    b.assert_liquidatable(ALICE);

    // Bob exits at the un-written-down index. No gate stops him: the
    // liquidation buffer only guards borrow draws, and `backing_shortfall`
    // still values Alice's uncollateralised debt at face.
    b.withdraw_all(BOB, "ETH");
    let bob_recovered = b.token_balance(BOB, "ETH") - bob_wallet_before;

    b.liquidate(LIQUIDATOR, ALICE, "ETH", 0.001);
    let carol_loss_b = carol_before_b - b.supply_balance(CAROL, "ETH");

    assert!(
        bob_recovered >= bob_before_b,
        "Bob exits whole: supplied={:.9} recovered={:.9}",
        bob_before_b,
        bob_recovered
    );
    assert!(
        carol_loss_b > carol_loss_a,
        "dodging must push loss onto Carol: A={:.9} B={:.9}",
        carol_loss_a,
        carol_loss_b
    );

    // Carol holds 25% of supply, so passing the whole loss to her is ~4x.
    let amplification = carol_loss_b / carol_loss_a;
    assert!(
        amplification > 3.0,
        "expected ~4x concentration onto the remaining supplier, got {:.3}x \
         (A={:.9} B={:.9})",
        amplification,
        carol_loss_a,
        carol_loss_b
    );

    std::println!(
        "A4-econ dodge: bob_supplied={:.9} bob_recovered={:.9} \
         carol_loss_passive={:.9} carol_loss_after_dodge={:.9} amplification={:.3}x",
        bob_before_b,
        bob_recovered,
        carol_loss_a,
        carol_loss_b,
        amplification
    );
}
```
