## Finding

### Title
Any residual token balance left in the `EmporiumUpgradeable` contract between transactions is swept into the *next* caller's shielded output, not the original depositor's - ([File: contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol])

### Summary
`EmporiumUpgradeable.runAction` computes the amount to credit back to the calling user purely as `balancesAfter - balancesBefore` (adjusted by `deltaAmountChanges`) of the contract's own token balance at the time of the call [1](#0-0) . Whatever token balance is sitting in the Emporium contract *before* a given `runAction` call — regardless of which user's funds it actually is — becomes part of `balancesBefore` and is silently absorbed into that snapshot, but any balance that lands in the contract asynchronously between two Hinkal transactions (e.g. unswept dust from a partially-completed external op, or a reward/airdrop paid directly to the Emporium address by a third‑party protocol the ops interacted with) is captured entirely by whichever unrelated user calls `runAction` next, and paid out to *that* caller's stealth address via `handleOut` [2](#0-1) . This is the direct analog of the NFTX bug: value that legitimately belongs to a previous user (their unclaimed rewards/dust) is captured pro-rata-free by whoever transacts through the shared pool contract next.

### Finding Description
`EmporiumUpgradeable` is a shared, stateless proxy contract: any Hinkal user can route an arbitrary sequence of `EmporiumOperation` calls through it via `runAction`, and the contract computes what to return to the caller purely from its own before/after balance delta:

```solidity
uint256[] memory balancesBefore = getBalancesForArray(circomData.erc20TokenAddresses);
...
for (...) { op.endpoint.call{value: op.value}(op.callData); }
...
uint256[] memory balancesAfter = getBalancesForArray(circomData.erc20TokenAddresses);
...
int256 balanceChange = int256(balancesAfter[i]) - int256(balancesBefore[i]);
...
// the only case when balanceChange can be < 0, when there were some funds on emporium before the call
``` [3](#0-2) 

The code comment on line 141 explicitly acknowledges that pre-existing balances can sit in the Emporium contract across transactions. Because there is no per-user ledger or escrow accounting inside `EmporiumUpgradeable` — it relies solely on ambient contract balance — any token balance that arrives in the contract outside of the current `runAction` call (dust left from an earlier user's partially-executed `op.endpoint.call`, delayed reward/dividend/airdrop payouts from a protocol the Emporium previously interacted with on a prior user's behalf, etc.) is treated as `balancesBefore` for the *next* caller and gets swept out via `handleOut`, which unconditionally sends `balanceChange` to `msg.sender` (the current Hinkal contract, forwarding to the current transaction's stealth-address UTXO):

```solidity
function handleOut(...) internal returns (UTXO memory outUtxo) {
    if (balanceChange <= 0) { return outUtxo; }
    transferERC20TokenOrETH(circomData.erc20TokenAddresses[i], msg.sender, uint256(balanceChange));
    outUtxo = UTXO(uint256(balanceChange), circomData.erc20TokenAddresses[i], circomData.stealthAddressStructure, circomData.timeStamp);
}
``` [2](#0-1) 

The equality that breaks is the balance-conservation invariant enforced elsewhere in the protocol (`_internalTransact`'s "balance equation" check in `Hinkal.sol` [4](#0-3) ): value moved through an external action must be attributable to the circuit-committed public inputs of the user who owns it. Here, value that arrives in `EmporiumUpgradeable`'s balance outside of the current call's explicit `deltaAmountChanges` accounting is not tied to any prover's `calldataHash`/`signedMessageHash`/public-input vector for the rightful owner — it is opportunistically claimed by whichever unrelated user next calls `runAction` with a matching token in `erc20TokenAddresses`, exactly as an NFTX attacker opportunistically captured pro-rata rewards meant for prior long-term stakers by depositing right before `receiveRewards`.

### Impact Explanation
This allows an unprivileged EOA to steal ERC20/ETH balance that legitimately belongs to another Hinkal user (or that was destined to eventually be swept back to them), without any authorization from that user's prover or signer — a direct theft of in-flight/protocol funds routed through the shared `Emporium` contract. Per the rules, this is at least High severity ("theft ... of protocol/relay fees, temporary freezing of user funds, executing calls or moving assets a wallet owner or prover never authorised"), and can reach Critical if the swept value constitutes another user's shielded principal (not just fee/dust), since it is direct theft of shielded/in-flight user funds.

### Likelihood Explanation
Likelihood is moderate: it requires (1) some prior Emporium `op` call that leaves a token balance on the contract instead of fully returning it in the same transaction (plausible with third-party protocols that pay rewards/dividends asynchronously, rebase, or that a caller's `op.callData` does a partial claim/withdraw), and (2) a subsequent, unrelated `runAction` call listing the same ERC20 token in `circomData.erc20TokenAddresses`. Given `Emporium` is designed as a generic pass-through for arbitrary external DeFi interactions (staking, swaps, claims), such asynchronous inflows are a realistic and recurring occurrence, and any Hinkal user (or a bot watching for it) can trivially trigger a matching `runAction` call to sweep the balance.

### Recommendation
Do not rely on ambient contract balance deltas to attribute value to `msg.sender`. Either (a) require every `EmporiumOperation` sequence to leave the contract's balance for each involved token unchanged from before the call unless explicitly and provably attributable to `deltaAmountChanges` for that specific call (revert instead of paying out unexplained surplus), or (b) maintain an explicit per-user/per-token escrow ledger inside `EmporiumUpgradeable` so that any balance is only released to the depositor who is cryptographically tied to it, analogous to distributing "streamed" ownership rather than an ambient pool snapshot.

### Proof of Concept
1. User A calls `Hinkal.transact()` routing through `EmporiumUpgradeable.runAction` with an `EmporiumOperation` that interacts with an external protocol (e.g., stakes tokens, or triggers a claim) such that, due to protocol behavior (partial claim, delayed reward accrual, rounding dust), some amount of `TOKEN` is left sitting in the `EmporiumUpgradeable` contract's balance after A's transaction completes.
2. Attacker B observes (or knows in advance) that `TOKEN` balance now sits on the Emporium contract.
3. Attacker B calls `Hinkal.transact()` with a trivial/no-op `EmporiumOperation` list but includes `TOKEN` in `circomData.erc20TokenAddresses` with a zero `deltaAmountChanges` for that token.
4. Inside `runAction`, `balancesBefore[TOKEN]` already includes A's leftover balance; after B's (no-op) ops execute, `balancesAfter[TOKEN]` is unchanged, so `balanceChange = balancesBefore[TOKEN] > 0`.
5. `handleOut` sends `balanceChange` (A's leftover `TOKEN`) to `msg.sender` (Hinkal) and creates a new UTXO under B's `stealthAddressStructure`, crediting B with funds that belonged to A. [5](#0-4)

    function runAction(
        CircomData calldata circomData,
        int256[] calldata deltaAmountChanges
    ) external override onlyAllowedRecipient returns (UTXO[] memory) {
        EmporiumStack memory stack = abi.decode(
            circomData.externalActionData.externalActionMetadata,
            (EmporiumStack)
        );

        uint256[] memory balancesBefore = getBalancesForArray(
            circomData.erc20TokenAddresses
        );

        verifyWallet(stack, circomData);

        for (uint256 i = 0; i < stack.ops.length; i++) {
            EmporiumOperation memory op = stack.ops[i];

            bool success;
            bytes memory err;

            // CASE 1: Stateful Interaction
            if (op.invokeWallet && stack.signerAddress != address(0)) {
                (success, err) = IHinkalWallet(stack.signerAddress)
                    .callHinkalWallet(op.endpoint, op.callData, op.value);
            }
            // CASE 2: Stateless Interaction
            else {
                bytes4 selector = bytes4(op.callData);
                if (
                    selector == IHinkalWallet.callHinkalWallet.selector ||
                    selector == IHinkalWallet.doSendToRelay.selector
                ) {
                    revert UnauthorizedWalletCall();
                }

                (success, err) = op.endpoint.call{value: op.value}(op.callData);
            }

            if (!success) {
                revert CallFailed(err);
            }
        }

        payRelayFees(circomData, stack.signerAddress, deltaAmountChanges);

        uint256[] memory balancesAfter = getBalancesForArray(
            circomData.erc20TokenAddresses
        );

        UTXO[] memory utxoSet = new UTXO[](
            circomData.erc20TokenAddresses.length
        );

        uint256 utxoSetLength;

        for (uint256 i = 0; i < circomData.erc20TokenAddresses.length; i++) {
            int256 balanceChange = int256(balancesAfter[i]) -
                int256(balancesBefore[i]);

            if (deltaAmountChanges[i] < 0) {
                balanceChange -= deltaAmountChanges[i];
                // this equation reads: total change of emporium balance = what was moved to emporium (-deltaAmountChange) + how emporium balance changed through tx (balanceChange)
            }

            // the only case when balanceChange can be < 0, when there were some funds on emporium before the call
            if (balanceChange < 0) {
                revert BalanceChangeShouldBePositive();
            }

            UTXO memory utxoOut = handleOut(balanceChange, circomData, i);

            if (utxoOut.amount > 0) {
                utxoSet[utxoSetLength++] = utxoOut;
            }
        }

        if (utxoSetLength < circomData.erc20TokenAddresses.length) {
            utxoSet.skipLast(
                circomData.erc20TokenAddresses.length - utxoSetLength
            );
        }

        return utxoSet;
    }

    function handleOut(
        int256 balanceChange,
        CircomData calldata circomData,
        uint256 i
    ) internal returns (UTXO memory outUtxo) {
        // total change can be less than zero if there was some balance before the call -> that's why we have <=
        if (balanceChange <= 0) {
            return outUtxo;
        }

        transferERC20TokenOrETH(
            circomData.erc20TokenAddresses[i],
            msg.sender,
            uint256(balanceChange)
        );

        outUtxo = UTXO(
            uint256(balanceChange),
            circomData.erc20TokenAddresses[i],
            circomData.stealthAddressStructure,
            circomData.timeStamp
        );
    }
