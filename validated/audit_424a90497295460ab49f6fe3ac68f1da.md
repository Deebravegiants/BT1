## Analysis

The report describes a race-condition/front-running pattern: an unprivileged actor observes an outcome-determining value before it is "locked in," then acts on that foreknowledge to claim a benefit (rewards) ahead of the legitimate/expected sequence.

The closest concrete analog in this codebase is the **`Resume` endpoint** used to complete async/webhook (bridge) task callbacks, `core/web/pipeline_runs_controller.go` `Resume()`, combined with how the resume URL/taskID is constructed in `core/services/pipeline/task.bridge.go`.

### Title
Unauthenticated `/v2/resume/:runID` endpoint allows arbitrary actor to front-run the legitimate external adapter response - (File: core/web/pipeline_runs_controller.go)

### Summary
The pipeline run "Resume" callback endpoint that completes an async `BridgeTask` is registered without authentication (its own audit-log constant is literally named `UnauthedRunResumed`) and is keyed only by the task's UUID, which is embedded verbatim in the `responseURL` sent to the external adapter. [1](#0-0) [2](#0-1) 

### Finding Description
`BridgeTask.finalizeAndMarshalBridgeRequestData` builds a `responseURL` of the form `<BridgeResponseURL>/v2/resume/<t.uuid>` and sends it to the external adapter as part of the outbound bridge request when `Async == "true"`. [2](#0-1) 

The corresponding `Resume` handler accepts a `runID` (the task UUID) and a `ResumeRequest` JSON body, immediately calls `App.ResumeJobV2` with the caller-supplied result, and only afterward logs an audit event named `UnauthedRunResumed` — explicitly signaling that this route path is not gated by session/API-key/external-initiator authentication like the rest of the `/v2/jobs/...` surface. [1](#0-0) 

Because the endpoint is unauthenticated and the "secret" that gates it is only the task UUID transmitted in the response URL, any party who observes that UUID (e.g., because it traverses network intermediaries, proxies, logs, or an external adapter operator/compromised dependency) can submit a forged resume payload to `ExecuteAndInsertFinishedRun`/`ResumeRun` before the genuine external adapter callback arrives. This mirrors the reported bug class: the value that determines the outcome (here, the pipeline result) is knowable/interceptable before it is durably applied, and an unprivileged party can race to submit it first and have the node accept their version of the "result" — poisoning a downstream job pipeline run (which may feed on-chain transactions, e.g., `ETHTx` tasks) with attacker-chosen data.

### Impact Explanation
An attacker who can predict/observe the resume UUID can front-run the legitimate adapter response and inject an arbitrary result into a paused pipeline run via `ResumeJobV2`, potentially causing the node to execute downstream tasks (including on-chain transactions) driven by attacker-controlled data instead of the genuine external adapter response. This is a request-impersonation / unauthorized-run-completion issue directly matching the "front-run to claim an unauthorized outcome" bug class from the report.

### Likelihood Explanation
Likelihood depends on the resume UUID being observable/guessable by a third party (e.g., via response URL exposure in logs, external adapter compromise, or interception), which is a real but non-trivial precondition — this is why the code path is explicitly named `UnauthedRunResumed`, suggesting it is a known, accepted design tradeoff rather than an overlooked control. I could not fully verify from the index whether router-level middleware (e.g., in `core/web/router.go`) applies any additional protection specifically to this route, since the router registration for `PipelineRunsController` was only partially visible in the available search results.

### Recommendation
- Bind the resume callback to a single-use, cryptographically random token (already partially the case via UUID) that is invalidated after first use, and reject resumes for tasks not currently in a pending/async state.
- Consider requiring an additional shared secret/HMAC signature over the resume payload, generated when the async request was issued, and validated on resume, instead of relying solely on the UUID staying secret in transit.
- Ensure `ResumeJobV2` rejects resumes for a task ID that is not currently marked pending, and rate-limit/log repeated resume attempts against the same task ID for anomaly detection.

### Proof of Concept
Not independently reproducible from static analysis alone; the flow would be: (1) job with an `Async` `BridgeTask` starts, producing a `responseURL` containing the task's UUID [2](#0-1) ; (2) an unprivileged party who obtains this UUID before the real external adapter responds sends a `PATCH /v2/jobs/:ID/runs/:runID` request with forged result data; (3) `Resume` processes it via `App.ResumeJobV2` without any authentication check [3](#0-2) , completing the run with attacker-supplied data.

**Note on confidence**: This is the strongest available analog matching the report's "front-run to claim reward/outcome before legitimate resolution" pattern among reachable, unprivileged-actor-facing surfaces (node API auth/session/gateway), but I was unable to confirm within available tool budget whether `core/web/router.go` applies any additional guard specifically to the `Resume` route beyond what's shown, so treat the "no authentication" claim as based on the naming convention (`UnauthedRunResumed`) and the code path shown rather than a fully confirmed router-level audit.

```go
// Resume finishes a task and resumes the pipeline run.
// Example:
// "PATCH <application>/jobs/:ID/runs/:runID"
func (prc *PipelineRunsController) Resume(c *gin.Context) {
	taskID, err := uuid.Parse(c.Param("runID"))
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	rr := pipeline.ResumeRequest{}
	decoder := json.NewDecoder(c.Request.Body)
	err = errors.Wrap(decoder.Decode(&rr), "failed to unmarshal JSON body")
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	result, err := rr.ToResult()
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	if err := prc.App.ResumeJobV2(c.Request.Context(), taskID, result); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
	c.Status(http.StatusOK)
}
```
