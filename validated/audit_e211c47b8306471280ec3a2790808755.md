### Title
Unbounded-recursion SCALE decode of attacker-controlled `runtime_call` in `on_accept` allows stack-overflow DoS - ([File: modules/pallets/hyper-fungible-token/src/module.rs])

### Summary
`pallet-hyper-fungible-token`'s `IsmpModule::on_accept` decodes the `runtime_call` field of an incoming cross-chain `SubstrateCalldata` using plain `codec::Decode::decode`, with no recursion-depth bound, even though this exact bug class (deeply-nested `RuntimeCall` values driving SCALE decoding into unbounded recursion and crashing the node) is already known and explicitly fixed elsewhere in this codebase via `decode_all_with_depth_limit`.

### Finding Description
`Pallet::on_accept` for the HFT module decodes an ISMP `PostRequest.body` as an ABI-encoded `Message{ from, to, amount, data }`, and if `data` is non-empty, SCALE-decodes it as `SubstrateCalldata { signature: Option<Vec<u8>>, runtime_call: Vec<u8> }`, then decodes `runtime_call` into the full `T::RuntimeCall` type: [1](#0-0) [2](#0-1) 

The decode call `T::RuntimeCall::decode(&mut &*substrate_data.runtime_call)` uses the plain `Decode` trait, not `DecodeLimit::decode_all_with_depth_limit`. `RuntimeCall` is a recursively-nested enum (e.g. `Sudo(Box<RuntimeCall>)`, `Utility::batch(Vec<RuntimeCall>)`, `Proxy::proxy(Box<RuntimeCall>)`), so a maliciously crafted byte string with thousands of nested wrapper variants forces the SCALE decoder into deep recursion.

That this precise mechanism causes stack exhaustion in this codebase is proven by the existing regression test for `pallet-call-decompressor`, which builds 1000 levels of `Sudo(Sudo(...))`-nested `RuntimeCall`s and shows that decoding must go through `decode_all_with_depth_limit(MAX_EXTRINSIC_DECODE_DEPTH_LIMIT, ...)` to safely reject it instead of crashing: [3](#0-2) [4](#0-3) [5](#0-4) 

The HFT module's decode of `runtime_call` at `module.rs:189` has none of this hardening — it is a plain `Decode::decode` call reached directly from an incoming, relayer-delivered `PostRequest` to any registered `HyperFungibleToken`/`WrappedHyperFungibleToken` source contract, exactly the same "deeply nested element list drives recursive decoder into deep recursion and crash" bug class as CVE‑2016‑4078 (IEEE 802.11/CAPWAP dissector recursing on nested elements).

### Impact Explanation
Any account that can send a cross-chain HFT transfer with non-empty `data` (the "optional calldata" feature documented for `pallet-hyper-fungible-token`) fully controls the bytes fed into `T::RuntimeCall::decode`. A crafted payload encoding many nested recursive `RuntimeCall` variants can exhaust the call stack of the collator/validator processing the ISMP message, crashing the node executing `on_accept` — a denial of service against block production/state-transition for the destination parachain. This is reachable by a single relayed message from an unprivileged sender (a token bridger), matching the "route unable to deliver messages" / DoS impact class permitted by the validation rules.

### Likelihood Explanation
Likelihood is high for any deployment enabling calldata execution: constructing a deeply-nested `RuntimeCall` encoding requires no special privileges, only knowledge of the runtime's call enum layout (public), and the attack payload is cheap to construct and small in size relative to the stack damage it causes (the analogous decompressor PoC used 1000 nesting levels).

### Recommendation
Replace the plain `T::RuntimeCall::decode(&mut &*substrate_data.runtime_call)` in `on_accept` with a depth-limited decode, mirroring the fix already applied in `pallet-call-decompressor`: use `codec::DecodeLimit::decode_all_with_depth_limit` with a small explicit bound (e.g. the same `MAX_EXTRINSIC_DECODE_DEPTH_LIMIT` constant or a pallet-specific constant sized to the legitimate calldata use cases), and reject/`Err` on excess depth instead of falling through to unbounded recursive decode.

### Proof of Concept
1. Construct `inner_call = System::remark { remark: [] }`.
2. Wrap it N times (N ≈ 1000, as in the existing decompressor PoC) as `Sudo::sudo { call: Box::new(inner_call) }` repeatedly, or use any other recursively-boxed `RuntimeCall` variant available in the target runtime (`Utility::batch`, `Proxy::proxy`, etc.) to build `nested_calls`.
3. SCALE-encode `nested_calls` via `.encode()` to get `runtime_call_bytes`.
4. Build `SubstrateCalldata { signature: None, runtime_call: runtime_call_bytes }.encode()` as `data`.
5. Send an HFT cross-chain transfer (`HyperFungibleToken.send`/equivalent) with `data` set to the above bytes, targeting a beneficiary account, to a chain running `pallet-hyper-fungible-token`.
6. When the relayed `PostRequest` reaches `on_accept` and hits `T::RuntimeCall::decode(&mut &*substrate_data.runtime_call)` at `module.rs:189`, the unbounded recursive decode overflows the stack, crashing the node — directly analogous to the `decompress_stack_exhaustion_poc` regression test already present for the decompressor pallet but demonstrating that the HFT module lacks the equivalent protection.

**Note on completeness:** I was not able to fully trace whether any wrapping layer above `on_accept` (e.g. ISMP message dispatch or SCALE decode of the outer `Message` via `abi_decode`) imposes an independent recursion guard on `runtime_call` before it reaches this line; based on the code read, no such guard is visible, but a full confirmation would require running the equivalent PoC test against the HFT pallet in a live/test environment.

#[test]
fn decompress_stack_exhaustion_poc() {
	let mut ext = new_test_ext();
	ext.execute_with(|| {
		use crate::runtime::RuntimeCall;
		use codec::Encode;

		let inner_call = RuntimeCall::System(frame_system::Call::remark { remark: Vec::new() });

		let mut nested_calls =
			RuntimeCall::Sudo(pallet_sudo::Call::sudo { call: Box::new(inner_call) });

		for _ in 1..1000 {
			nested_calls =
				RuntimeCall::Sudo(pallet_sudo::Call::sudo { call: Box::new(nested_calls) });
		}

		let encoded = nested_calls.encode();
		let mut buffer = vec![0u8; 1000000];
		let compressed = zstd_safe::compress(&mut buffer[..], encoded.as_slice(), 3).unwrap();
		let final_compressed_call = buffer[..compressed].to_vec();

		let res = pallet_call_decompressor::Pallet::<Test>::decompress_call(
			RuntimeOrigin::none(),
			final_compressed_call.to_vec(),
			encoded.len() as u32,
		)
		.err()
		.unwrap();

		assert_eq!(
			res,
			DispatchError::Module(ModuleError {
				index: 10,
				error: [3, 0, 0, 0],
				message: Some("ErrorDecodingCall")
			})
		);
	});
}
