## Title
Duplicate BEEFY authority votes are not deduplicated before the supermajority threshold check, allowing a forged consensus update - (File: `evm/src/consensus/EcdsaBeefy.sol`)

### Summary
`EcdsaBeefy.verifyMmrUpdateProof` counts `relayProof.signedCommitment.votes.length` as the number of participating signatures and compares it directly against the 2/3+1 supermajority threshold, without ever checking that the `authorityIndex` values (or recovered signer addresses) are unique. The equivalent Rust verifier (`modules/consensus/beefy/verifier/src/lib.rs::verify_mmr_update_proof`) has the identical gap. This mirrors CVE-2018-14767's root cause — a message accepted with a repeated/duplicated field (there: a duplicated `To` header; here: a duplicated authority vote) that downstream code fails to validate as unique before acting on it — except here the consequence is not a crash but a **forged consensus proof acceptance**. [1](#0-0) 

### Finding Description
`verifyMmrUpdateProof` computes `sigLen = relayProof.signedCommitment.votes.length` and immediately gates on `checkParticipationThreshold(sigLen, authoritySet.len)`, i.e. `sigLen >= (2*total)/3 + 1`. It then builds one `MerkleMultiProof.Leaf` per vote using `vote.authorityIndex` as the leaf's tree index and `keccak256(ecrecover(...))` as its hash, and passes the whole array to `MerkleMultiProof.VerifyProof`. [2](#0-1) 

Nowhere in this function (or in its Rust twin, `verify_mmr_update_proof` in `modules/consensus/beefy/verifier/src/lib.rs`) is there a check that `authorityIndex` values are unique across `votes`/`signatures`. A relayer-submitted BEEFY consensus message is fully attacker-controlled data (this is exactly the unsigned, permissionless consensus-update path reachable via `HandlerV2`/`pallet-ismp`'s `handle_unsigned`). An attacker who can obtain (or has already observed) valid signatures from only a minority of the authority set (below 2/3+1) can pad `votes` with repeated `(signature, authorityIndex)` entries for the same authorities they do control, inflating `sigLen` past the threshold while never having a genuine supermajority. Whether this concretely bypasses `MerkleMultiProof.VerifyProof` depends on the external `solidity-merkle-trees` library's multiproof algorithm handling of repeated leaf indices — that library lives outside this repository and I was not able to inspect its source to confirm whether duplicate `(index, hash)` leaves are rejected or silently accepted/collapsed during proof verification. This is the one point I could not fully verify with available tools. [3](#0-2) 

By contrast, the codebase's other consensus clients explicitly guard against exactly this class of bug: the Pharos verifier rejects duplicate participant BLS keys before counting stake (`DuplicateParticipant`), and the Tendermint verifier rejects validator sets with duplicate addresses (`ensure_unique_addresses`) — showing the project is aware this bug class matters for supermajority/threshold logic, but the BEEFY ECDSA path (both Solidity and Rust) lacks the analogous check. [4](#0-3) [5](#0-4) 

### Impact Explanation
BEEFY consensus proofs are the trust root used by `EcdsaBeefy.verify` (invoked via the `ConsensusRouter`/`IConsensusV2` interface consumed by `HandlerV2`) to update `stateMachineCommitment`s that every subsequent `handlePostRequests`/`handleGetResponses` call trusts for message-inclusion proofs. If duplicate-vote padding can defeat the supermajority check, an attacker with only a minority of compromised/leaked validator signatures could force acceptance of a fabricated relay-chain finality commitment, letting them forge arbitrary parachain state commitments and subsequently deliver forged/unbacked messages (mint, state reads, etc.) through the handler — a critical, protocol-wide compromise of message integrity, matching the "unsound state commitment / forged message delivery" impact class explicitly in scope.

### Likelihood Explanation
Reaching `verifyMmrUpdateProof` requires only submitting a consensus proof through the permissionless `handle_unsigned`/`ConsensusRouter` path — no privileged role needed. The blocking uncertainty is whether the vendored `MerkleMultiProof.VerifyProof` algorithm tolerates repeated `(index, hash)` leaves; if it does not, this reduces to a defense-in-depth gap rather than an exploitable bypass. Given I could not inspect that library's source in this repo, likelihood is assessed as uncertain-but-plausible rather than confirmed.

### Recommendation
Before checking `checkParticipationThreshold`/`check_participation_threshold`, reject any `votes`/`signatures` array containing duplicate `authorityIndex` values (and/or duplicate recovered signer addresses) in both `EcdsaBeefy.sol::verifyMmrUpdateProof` and `modules/consensus/beefy/verifier/src/lib.rs::verify_mmr_update_proof`, mirroring the `DuplicateParticipant`/`ensure_unique_addresses` pattern already used by the Pharos and Tendermint verifiers.

### Proof of Concept
Conceptual (unverified against the external merkle-proof library):
1. Attacker obtains valid ECDSA signatures over a forged BEEFY `Commitment` from `k` real authorities, where `k < 2/3*total + 1`.
2. Attacker builds `RelayChainProof.signedCommitment.votes` by repeating each of the `k` signatures/`authorityIndex` pairs enough times that `votes.length >= 2/3*total + 1`.
3. Submits this as a consensus message via the permissionless handler path.
4. `checkParticipationThreshold` passes on the inflated `sigLen`.
5. If `MerkleMultiProof.VerifyProof` does not reject repeated `(index, hash)` leaves, the forged commitment is accepted, advancing `latestHeight`/authority sets with only `k` real signers.

pub fn verify_mmr_update_proof<H: Keccak256 + EcdsaRecover + Send + Sync>(
	mut trusted_state: ConsensusState,
	mmr: MmrProof,
) -> Result<(ConsensusState, H256), Error> {
	let signatures_length = mmr.signed_commitment.signatures.len();
	let latest_height = mmr.signed_commitment.commitment.block_number;

	if trusted_state.latest_beefy_height >= latest_height {
		return Err(Error::StaleHeight {
			trusted_height: trusted_state.latest_beefy_height,
			current_height: latest_height,
		});
	}

	let commitment = mmr.signed_commitment.commitment.clone();

	// Pick the authority set the commitment claims to be signed under, then judge
	// participation against that set alone.
	let authority_set = if commitment.validator_set_id == trusted_state.current_authorities.id {
		&trusted_state.current_authorities
	} else if commitment.validator_set_id == trusted_state.next_authorities.id {
		&trusted_state.next_authorities
	} else {
		return Err(Error::UnknownAuthoritySet { id: commitment.validator_set_id });
	};

	if !check_participation_threshold(signatures_length as u32, authority_set.len) {
		return Err(Error::SuperMajorityRequired);
	}

	let mmr_root_data = commitment
		.payload
		.get_raw(&MMR_ROOT_PAYLOAD_ID)
		.ok_or(Error::MmrRootHashMissing)?;

	if mmr_root_data.len() != 32 {
		return Err(Error::InvalidMmrRootHashLength { len: mmr_root_data.len() });
	}
	let mmr_root = H256::from_slice(mmr_root_data);

	let commitment_hash = H::keccak256(&commitment.encode());
	let mut authority_leaves: Vec<[u8; 32]> = Vec::new();
	let mut authority_indices = Vec::new();

	for sig in mmr.signed_commitment.signatures.iter() {
		let uncompressed = H::secp256k1_recover(&commitment_hash.0, &sig.signature)
			.map_err(|_| Error::FailedToRecoverPublicKey)?;

		let hashed_uncompressed = H::keccak256(&uncompressed);

		let mut eth_address = [0u8; 20];
		eth_address.copy_from_slice(&hashed_uncompressed.as_ref()[12..]);

		let authority_address_hash = H::keccak256(&eth_address);

		authority_leaves.push(authority_address_hash.into());
		authority_indices.push(sig.index as usize);
	}

/// Verify that all participating validators are members of the trusted validator set.
fn verify_validator_membership(
	validator_set: &ValidatorSet,
	participants: &[BlsPublicKey],
) -> Result<(), Error> {
	let deduped: alloc::collections::BTreeSet<&[u8]> =
		participants.iter().map(|k| k.as_ref()).collect();
	if deduped.len() != participants.len() {
		return Err(Error::DuplicateParticipant);
	}
	if let Some(key) = participants.iter().find(|key| !validator_set.contains(key)) {
		return Err(Error::UnknownValidator { key: key.clone() });
	}
	Ok(())
}

/// Rejects a validator set that reuses the same address twice. Each address is a
/// hash of its public key, so a duplicate signals a set that was not built honestly.
fn ensure_unique_addresses(
	validators: &[cometbft::validator::Info],
) -> Result<(), VerificationError> {
	let unique = validators.iter().map(|v| v.address).collect::<BTreeSet<_>>();
	if unique.len() != validators.len() {
		return Err(VerificationError::ValidatorSetError(
			"duplicate validator address in set".to_string(),
		));
	}
	Ok(())
}
