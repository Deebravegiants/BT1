### Title
Stale-bounded Chainlink price in SimplexPaymaster lets users pay gas with a depegging token at pre-depeg value, draining the paymaster's shared ETH reserve - ([File: evm/src/utils/SimplexPaymaster.sol])

### Summary
`SimplexPaymaster` accepts gas payment in any of several governance-registered ERC-20 tokens, converting the ETH-denominated gas cost into token units using a Chainlink `token/USD` feed [1](#0-0) . The oracle read only reverts when the feed's `updatedAt` is older than `maxOracleAge` (which can be configured up to 7 days, and the comment notes it is set "up to 24h" for Base/Ethereum stablecoins) [2](#0-1) [3](#0-2) . Exactly like the Ubiquity report's Chainlink-vs-DEX lag, a token can depeg on-market well before its feed is stale enough to revert, letting any unprivileged UserOperation sender pay gas at the pre-depeg price while the paymaster has already fronted real ETH gas out of the EntryPoint deposit.

### Finding Description
The paymaster's gas-charging price for any registered token is:
```
tokenPrice = (nativeUsd * 10^tokenDecimals * (10000 + markupBps)) / (tokenUsd * 10000)
```
computed purely from two independent Chainlink feeds with no cross-check against real-time market/DEX pricing [4](#0-3) . `_fetchDetails` (called during `_validatePaymasterUserOp`) derives the charge amount from this stale-tolerant price and `_prefund`/`super._prefund` pulls that amount of the depegging token from the sender [5](#0-4) . Meanwhile the paymaster's EntryPoint deposit — a single shared pool of native ETH funding gas for every user and every accepted token — is drawn down at the *true* gas cost in ETH by `EntryPoint`, independent of what token/price was used to reimburse the paymaster.

This is the direct analog of the Ubiquity M-2 pattern: a single, price-oracle-gated mechanism converts a devaluing "collateral" (the paying ERC-20) into a shared reserve (ETH deposit) at a stale, favorable rate. During a depeg event, users are economically incentivized to route their gas payments through the paymaster using the depegging token, since they get subsidized/cheap transaction sponsorship at the stale exchange rate, silently draining the shared ETH reserve that backs sponsorship for all users. There is no circuit breaker beyond the flat `maxOracleAge` bound, and `markupBps` (capped at 50%, but configured much lower in practice) is not a depeg-magnitude-aware safety margin — as noted in the discussion of the original report, "the maximum divergence of the market price from the oracle feed should be within the fee charged," which is not guaranteed here since `markupBps` is set independently of any live depeg risk.

### Impact Explanation
An accepted payment token depegging downward within the `maxOracleAge` window lets an attacker (or many colluding/independent users) pay gas fees at the old, higher-than-market price, extracting real ETH value from the paymaster's EntryPoint deposit for tokens now worth less than what was charged. Because remediation (deactivating the token or lowering `maxOracleAge`) requires a cross-chain Hyperbridge governance message delivered through `onAccept` [6](#0-5) , there is no fast, permissionless circuit breaker — the exploit window persists for as long as it takes governance to detect and dispatch a fix, which can meaningfully exceed the on-chain depeg duration. This is a fund-drain of the paymaster's staked ETH (a shared, cross-user reserve), fitting "concrete theft ... of funds."

### Likelihood Explanation
Any unprivileged actor able to submit an ERC-4337 `UserOperation` naming this paymaster and one of its registered tokens can trigger the mispriced charge — no special privileges are required, only ownership of the depegging token and a bundler relationship, both trivially available in a public paymaster. The likelihood scales with how many stablecoin-like tokens are registered and how wide `maxOracleAge`/`markupBps` are configured; documentation explicitly anticipates multi-day staleness windows for some chains.

### Recommendation
- Bound the acceptable price divergence with a depeg circuit breaker (e.g., reject `_getOraclePrice` reads whose deviation from a secondary reference/TWAP exceeds a threshold), not just staleness.
- Tighten `maxOracleAge` to the tightest heartbeat practical per feed rather than allowing a governance-selectable multi-day bound.
- Consider requiring `markupBps` to be set as a function of the accepted token's historical volatility/depeg risk, and add a permissionless (non-governance-gated) pause path for a single misbehaving token, so the exposure window is not tied to full cross-chain governance latency.

### Proof of Concept
1. Governance registers a stablecoin `X` with Chainlink feed `F` (`maxOracleAge` = 24h) in `SimplexPaymaster` via `RequestKind.RegisterToken` [7](#0-6) .
2. `X` depegs on-chain (e.g., drops 20% against USD on DEXes) while `F.latestRoundData().updatedAt` is still within the 24h staleness bound, so `_getOraclePrice` keeps returning the pre-depeg price [8](#0-7) .
3. An attacker submits UserOperations paying gas in `X` via mode `0x00`/`0x02`; `_tokenPrice`/`_fetchDetails` charge `X` at the stale, inflated USD value [1](#0-0) .
4. The paymaster's EntryPoint deposit pays the real ETH gas cost while receiving `X` tokens now worth materially less than that ETH, repeatable across many UserOperations until governance detects and deactivates `X` — draining the shared ETH reserve relative to its true backing value.

    function _fetchDetails(
        PackedUserOperation calldata userOp,
        bytes32 /* userOpHash */
    )
        internal
        view
        override
        returns (uint256 validationData, IERC20 token, uint256 tokenPrice)
    {
        bytes calldata data = userOp.paymasterData();
        if (data.length < 21) revert InvalidPaymasterData(data.length);

        uint8 mode = uint8(data[0]);
        if (mode != 0x00 && mode != 0x02) revert InvalidMode(mode);

        address tokenAddr = address(bytes20(data[1:21]));

        TokenConfig memory cfg = tokenConfigs[tokenAddr];
        if (address(cfg.tokenOracle) == address(0)) revert TokenNotRegistered(tokenAddr);
        if (!cfg.active) revert TokenNotActive(tokenAddr);

        tokenPrice = _tokenPrice(cfg);
        token = IERC20(tokenAddr);
        validationData = 0; // no time-range restriction

        if (mode == 0x02) {
            (,,, uint256 deadline,,,) = _parsePermit2Data(data);
            // Surfacing the permit deadline as validUntil lets bundlers drop
            // expiring ops instead of discovering it through a Permit2 revert.
            uint48 validUntil = deadline > type(uint48).max ? 0 : uint48(deadline);
            validationData = ERC4337Utils.packValidationData(true, 0, validUntil);
        }
    }

        uint256 tokenUsd = _getOraclePrice(cfg.tokenOracle, cfg.tokenOracleDecimals);

        return (nativeUsd * (10 ** cfg.tokenDecimals) * (10_000 + markupBps)) / (tokenUsd * 10_000);
    }

    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
