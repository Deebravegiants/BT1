### Title
Bad-debt socialization decision uses `liq-penalty-max` instead of the position's actual liquidation penalty, causing premature debt write-off - ([File: mainnet/contracts/market/v0-4-market.clar])

### Summary
The `liquidate` function in `mainnet/contracts/market/v0-4-market.clar` decides whether to socialize (write off) a borrower's remaining debt based on whether their *other* collateral (collateral not being liquidated in the current call) is "negligible." That negligibility check, `other-debt-repayable`, is computed using the fixed `liq-penalty-max` bonus rate, while the actual liquidation math for the position uses the graduated `liq-penalty` (which can be lower than `liq-penalty-max`). This mismatch is structurally the same class of bug as Tapioca's H-5: two related computations that should use the same rate use different ones, so the derived threshold is biased in a way that produces an incorrect (and here, exploitable) result.

### Finding Description
In `liquidate`, the position-level liquidation penalty is computed as a graduated value between `liq-penalty-min` and `liq-penalty-max` based on how far underwater the position is: [1](#0-0) [2](#0-1) 

This graduated `liq-penalty` is what's actually applied when seizing collateral for the liquidated asset: [3](#0-2) 

However, when the function checks whether the borrower has any other meaningful collateral left (to decide whether to socialize/write off the remaining debt), it substitutes `liq-penalty-max` instead of the actual `liq-penalty`: [4](#0-3) [5](#0-4) 

Since `div-bps-down other-coll-usd (+ BPS liq-penalty-max)` uses a larger divisor than `div-bps-down other-coll-usd (+ BPS liq-penalty)` would (whenever `liq-penalty-max > liq-penalty`, i.e. whenever the position isn't at the worst end of the graduated curve), the computed `other-debt-repayable` is systematically smaller than the amount of debt the borrower's other collateral could actually cover at the position's real applicable penalty. This makes `other-debt-repayable` more likely to round down to `u0`, which in turn makes `no-collateral-left` evaluate to `true` more often than it correctly should: [6](#0-5) 

When `no-collateral-left` is `true`, the contract socializes (writes off) all of the borrower's remaining debt via `fold socialize-debt-asset`, even though the borrower still holds other collateral whose value was underestimated only because of the wrong rate substitution: [7](#0-6) 

This breaks the value identity that debt socialization (bad-debt write-off, borne by lenders/the vault aggregate) should only occur when a borrower's collateral is truly exhausted: `debt written off == collateral actually unrecoverable`. Using `liq-penalty-max` in place of `liq-penalty` biases the check toward writing off debt while collateral the borrower still holds (but which is left un-seized in this call) is undervalued in the check.

### Impact Explanation
If triggered, this converts recoverable borrower debt into socialized bad debt (a loss absorbed by lenders/vault depositors) while the borrower retains other collateral of value that a correctly-computed check would have recognized as non-negligible, preventing socialization or requiring further liquidation instead. This is a protocol-insolvency-style loss transferred to depositors, matching the "protocol insolvency" / "permanent freezing of funds" impact category, since the written-off debt was collateralized value the protocol should have been able to recover.

### Likelihood Explanation
The mismatch is deterministic and independent of price manipulation — it is triggered any time a liquidator (an unprivileged actor) executes `liquidate` against a borrower with multiple collateral assets, one of which becomes fully seized on the liquidated asset (`coll-removed = 0` or the target asset being the borrower's last on that leg) while the remaining collateral value, valued at the position's real graduated penalty, would be nonzero but rounds to zero when valued at `liq-penalty-max`. The gap between `liq-penalty-min`/`liq-penalty-max` widens this window, especially in early/partial liquidation ranges where the graduated `liq-penalty` is well below `liq-penalty-max`.

### Recommendation
Use the position's actual graduated `liq-penalty` (the same value used for the primary seizure calculation) — not the fixed `liq-penalty-max` — when computing `remaining-debt-to-repay` and `other-debt-repayable`, so the "no collateral left" / socialization threshold is consistent with the rate actually governing this liquidation.
