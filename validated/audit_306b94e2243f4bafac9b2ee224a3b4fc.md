## Title
Webhook shop-domain header is not covered by HMAC, allowing cross-tenant webhook spoofing - (File: `lib/shopify_api/webhooks/request.rb`)

### Summary
`ShopifyAPI::Webhooks::Request#to_signable_string` returns only the raw request body, while `ShopifyAPI::Webhooks::Registry.process` trusts the unauthenticated `shop-domain` header as the tenant identity handed to the app's webhook handler. The HMAC check therefore verifies "this body came from Shopify with our secret" but never verifies "this body belongs to this shop," breaking the binding `hmac_verified_bytes == tenant_identity_bytes`.

### Finding Description
`Request#to_signable_string` is defined as: [1](#0-0) 
only the `@raw_body` is signed. The `shop` accessor, however, is read straight from an unauthenticated header: [2](#0-1) 

`Registry.process` validates the HMAC over the body only, then forwards `request.shop` (the header value) directly to the app's handler as the tenant identity for the delivered payload: [3](#0-2) 

and `HmacValidator.validate` / `validate_signature` compute and compare the signature only against `to_signable_string` (the body), never incorporating `shop`: [4](#0-3) 

Because the same `api_secret_key` is used to sign webhooks for every shop that installs the app, and the signature covers only the body bytes, any body+HMAC pair that was legitimately generated by Shopify for one shop (e.g., a webhook delivered to the attacker's own installed store) remains valid when replayed with an arbitrary `X-Shopify-Shop-Domain` (or `Shopify-Shop-Domain`) header pointing at a different, victim shop. `Utils::HmacValidator.validate(request)` will still return `true` because it never checks that the header-supplied shop is the one the body/HMAC was actually generated for, and `Registry.process` passes that spoofed `shop` straight to `WebhookMetadata`, i.e. `data.shop` handed to the host application's handler.

This breaks the identity binding: **the shop the HMAC was computed for ≠ the shop attributed to the payload by the gem.**

### Impact Explanation
An attacker who is a legitimate merchant of the target app (so they can trigger genuine webhook deliveries to their own shop and capture a valid `(raw_body, hmac)` pair) can replay that exact body with the HMAC unchanged but substitute the shop-domain header to name any other tenant. Any host application that trusts `WebhookMetadata#shop` from this gem (e.g., to key GDPR data-request/erasure actions, mark an app as uninstalled, update per-shop inventory/order records, etc.) can be made to act on forged data attributed to a shop the attacker does not control — a cross-tenant data-integrity/cross-tenant access issue.

### Likelihood Explanation
Medium: the attacker needs their own shop with the app installed to obtain one authentic `(raw_body, hmac)` pair (trivially available for many low-sensitivity topics), and needs to know/guess a target shop domain (public information, `*.myshopify.com`). No access token, `client_secret`, or privileged access is required — only the ability to POST an HTTP request with attacker-controlled headers to the app's public webhook endpoint.

### Recommendation
Bind the `shop` (and ideally `topic`/`webhook_id`) into the value that is HMAC-verified, or otherwise cryptographically tie the header-supplied shop to the specific delivery — e.g., verify the shop domain against the shop that's expected/registered before invoking handlers, or include the shop-domain header bytes in `to_signable_string` so a mismatched header invalidates the signature. At minimum, document that host applications must independently correlate `data.shop` against their own installation records rather than trusting it as authenticated by the HMAC check performed by this library.

### Proof of Concept
1. Install the app on shop `attacker.myshopify.com` and trigger any webhook topic (e.g., `app/uninstalled`) to capture the real HTTP request: raw body `B` and header `Shopify-Hmac-Sha256: H` (valid, computed by Shopify with the app's `client_secret`).
2. Replay the captured request to the app's public webhook endpoint, keeping `raw_body = B` and `Shopify-Hmac-Sha256 = H` unchanged, but set:
   ```
   X-Shopify-Shop-Domain: victim.myshopify.com
   X-Shopify-Topic: app/uninstalled
   ```
3. `ShopifyAPI::Webhooks::Request.new(raw_body: B, headers: forged_headers)` builds a request whose `to_signable_string` is still `B`.
4. `ShopifyAPI::Webhooks::Registry.process(request)` calls `Utils::HmacValidator.validate(request)`, which recomputes HMAC over `B` with the app's secret and matches `H`, so validation succeeds.
5. The handler receives `WebhookMetadata.new(topic: "app/uninstalled", shop: "victim.myshopify.com", ...)`, causing the host app to process an uninstall (or other tenant-scoped action) for `victim.myshopify.com`, even though that shop never sent this webhook. [5](#0-4) [3](#0-2) [6](#0-5)

      sig { params(raw_body: String, headers: T::Hash[String, T.untyped]).void }
      def initialize(raw_body:, headers:)
        # normalize the headers by forcing lowercase, removing any prepended "http"s, and changing underscores to dashes
        headers = headers.to_h { |k, v| [k.to_s.downcase.sub("http_", "").gsub("_", "-"), v] }

        missing_headers = []
        ["topic", "hmac-sha256", "shop-domain"].each do |name|
          unless headers.key?("shopify-#{name}") || headers.key?("x-shopify-#{name}")
            missing_headers << "shopify-#{name} or x-shopify-#{name}"
          end
        end
        unless missing_headers.empty?
          raise Errors::InvalidWebhookError,
            "Missing one or more of the required HTTP headers to process webhooks: #{missing_headers}"
        end

        @headers = headers
        @raw_body = raw_body
      end

# typed: strict
# frozen_string_literal: true

module ShopifyAPI
  module Utils
    module HmacValidator
      extend T::Sig

      class << self
        extend T::Sig

        sig { params(verifiable_query: VerifiableQuery).returns(T::Boolean) }
        def validate(verifiable_query)
          return false unless verifiable_query.hmac

          result = validate_signature(verifiable_query, Context.api_secret_key)
          if result || Context.old_api_secret_key.nil? || T.must(Context.old_api_secret_key).empty?
            result
          else
            validate_signature(verifiable_query, T.must(Context.old_api_secret_key))
          end
        end

        private

        sig { params(verifiable_query: VerifiableQuery, secret: String).returns(T::Boolean) }
        def validate_signature(verifiable_query, secret)
          received_signature = verifiable_query.hmac
          computed_signature = compute_signature(verifiable_query.to_signable_string, secret)
          OpenSSL.secure_compare(computed_signature, T.must(received_signature))
        end

        sig { params(signable_string: String, secret: String).returns(String) }
        def compute_signature(signable_string, secret)
          OpenSSL::HMAC.hexdigest(
            OpenSSL::Digest.new("sha256"),
            secret,
            signable_string,
          )
        end
      end
    end
  end
end
