### Title
Unvalidated `ExtendedResourceClaimStatus.ResourceClaimName` on `pods/status` lets namespace-scoped actors grant a node unauthorized `get` access to arbitrary ResourceClaims - (`plugin/pkg/auth/authorizer/node/graph.go`)

### Summary
`Graph.AddPod` wires a `claim -> pod -> node` authorization edge directly from `pod.Status.ExtendedResourceClaimStatus.ResourceClaimName` without verifying that name corresponds to a claim the scheduler actually allocated for that pod. The API-side validation of this status field (`validatePodExtendedResourceClaimStatus`) never checks `ResourceClaimName` against any spec-declared value, and the `NodeRestriction` admission check that would normally freeze this field only applies when the requester is identified as the pod's own node, not to any other RBAC principal permitted to `update` `pods/status`.

### Finding Description
`Graph.AddPod` unconditionally trusts `pod.Status.ExtendedResourceClaimStatus.ResourceClaimName` to grant the pod's bound node `get` access to a `ResourceClaim` vertex: [1](#0-0) 

Unlike `PodResourceClaimStatuses`, which is spec-anchored (`validatePodResourceClaimStatuses` checks `havePodClaim(podClaims, status.Name)` against `spec.resourceClaims`), `ExtendedResourceClaimStatus` has no corresponding spec-declared claim reference at all — it's a scheduler-synthesized field for extended-resource-to-DRA translation. `validatePodExtendedResourceClaimStatus` only validates:
- that `RequestMappings` entries reference real container names/resource-request keys in `spec.Containers`/`spec.InitContainers`, and
- that `ResourceClaimName` is a syntactically valid DNS name. [2](#0-1) 

It never checks that `ResourceClaimName` corresponds to a claim actually created for/allocated to that pod. Any pod with at least one container declaring a resource request (e.g., `cpu`) satisfies the `RequestMappings` check trivially, since the code only checks presence of the key in `c.Resources.Requests`, not that it is an extended resource.

The only other guard that could stop a non-scheduler actor from setting this field is the `NodeRestriction` admission plugin's `admitPodStatus`, which enforces `extendedResourceClaimStatusEqual(oldPod...,newPod...)` — but that function is only invoked for requests whose authenticated user is identified as the specific node hosting the pod: [3](#0-2) 

A caller who is not a node (i.e., a regular user or service account with a namespaced RBAC grant of `update` on `pods/status`) never reaches `admitPodStatus`'s equality checks at all, because `NodeRestriction` dispatches based on node identity, not generic RBAC. Therefore, such a caller can freely set `ExtendedResourceClaimStatus.ResourceClaimName` to any existing claim name in the pod's namespace, and once the informer-driven `graphPopulator.updatePod` -> `Graph.AddPod` path runs, the node hosting that pod is granted `get` on that arbitrary `ResourceClaim`, regardless of whether the claim's `status.reservedFor` even references the pod.

### Impact Explanation
This breaks the DRA node-authorization isolation invariant that a node should only ever be authorized to read `ResourceClaim` objects that are actually allocated to pods scheduled on it. An actor with only `update` permission on `pods/status` in a namespace (a plausible, minimally-privileged role, e.g., for a device-plugin/controller-style ServiceAccount) can force node authorization graph expansion, granting a node `get` access on a `ResourceClaim` belonging to an unrelated pod/tenant in the same namespace. This is an authorizer-bypass / workload-isolation-escape class issue: it undermines a scoped-least-privilege guarantee of the node authorizer without needing node/kubelet credentials.

### Likelihood Explanation
Preconditions are narrow but plausible: RBAC granting `update` on the `pods/status` subresource (namespace-scoped) is the only privilege required — no node identity, no cluster-admin. The attack sequence is a single `PATCH .../pods/{ns}/{pod}/status` with a `RequestMappings` entry that trivially matches any container's resource request key and an arbitrary `ResourceClaimName`, then simply waiting for the informer-triggered `AddPod` graph rebuild. It is fully repeatable and requires no timing races or feature-gate combinations beyond `DRAExtendedResource` being enabled.

### Recommendation
- In `validatePodExtendedResourceClaimStatus`, require that `RequestMappings` entries reference actual extended-resource names (not any arbitrary requested resource key), and, more importantly, validate that `ResourceClaimName` cannot be freely set by non-privileged callers — e.g., only allow this field to be set/changed by identities authorized as the scheduler (similar to how `NodeRestriction` is meant to prevent nodes from setting it).
- Extend `NodeRestriction`'s `admitPodStatus`-style immutability protection so that `ExtendedResourceClaimStatus` (like `spec.NodeName`) can only be set by the scheduler identity, not by arbitrary principals with `pods/status` update rights.
- In `Graph.AddPod`, before wiring the claim edge, cross-check that the referenced `ResourceClaim`'s `status.reservedFor`/allocation actually corresponds to the pod, rather than trusting the pod-status field alone.

### Proof of Concept

1. Construct `oldPod`/`newPod` where `newPod.Status.ExtendedResourceClaimStatus.ResourceClaimName = "unrelated-claim"` and `RequestMappings` references a container with a plain `cpu` resource request (no extended resource actually requested).
2. Call `ValidatePodStatusUpdate(newPod, oldPod, opts)` and assert it currently returns no errors (demonstrating the missing linkage check) — expected/fixed behavior: it should return a `field.Invalid`/`Forbidden` error unless the identity is trusted or the claim name matches a scheduler-derived value.

Integration/graph test alongside `TestNodeAuthorizerUpdateExtendedResourceClaim` in `plugin/pkg/auth/authorizer/node/node_authorizer_test.go`:
1. Simulate `graphPopulator.updatePod` with a pod whose `ExtendedResourceClaimStatus.ResourceClaimName` was set via a non-scheduler actor to a claim name unrelated to the pod's actual DRA allocation.
2. Assert that `authz.Authorize` for the pod's node against that claim currently returns `DecisionAllow` (proving the escalation), which should instead be `DecisionNoOpinion` once the fix validates the claim linkage.

// validatePodExtendedResourceClaimStatus validates the ExtendedResourceClaimStatus in a pod status.
func validatePodExtendedResourceClaimStatus(status *core.PodExtendedResourceClaimStatus, spec *core.PodSpec, fldPath *field.Path) field.ErrorList {
	if status == nil {
		return nil
	}

	containers := make(map[string]*core.Container)
	for _, c := range spec.InitContainers {
		containers[c.Name] = &c
	}
	for _, c := range spec.Containers {
		containers[c.Name] = &c
	}

	var allErrs field.ErrorList
	rmFldPath := fldPath.Child("requestMappings")
	if len(status.RequestMappings) == 0 {
		allErrs = append(allErrs, field.Required(rmFldPath, "at least one request mapping is required"))
	}
	type key struct {
		container string
		resource  string
		request   string
	}
	seen := map[key]struct{}{}
	for i, rm := range status.RequestMappings {
		idxPath := rmFldPath.Index(i)
		c, ok := containers[rm.ContainerName]
		if ok {
			if _, ok := c.Resources.Requests[core.ResourceName(rm.ResourceName)]; !ok {
				allErrs = append(allErrs, field.Invalid(idxPath.Child("resourceName"), rm.ResourceName, "must match the extended resource name of an entry in spec.initContainers.resources.requests or spec.containers.resources.requests"))
			}
		} else {
			allErrs = append(allErrs, field.Invalid(idxPath.Child("containerName"), rm.ContainerName, "must match the name of an entry in spec.initContainers.name or spec.containers.name"))
		}
		allErrs = append(allErrs, ValidateDNS1123Label(rm.RequestName, fldPath.Child("requestName"))...)
		k := key{container: rm.ContainerName, resource: rm.ResourceName, request: rm.RequestName}
		if _, ok := seen[k]; ok {
			allErrs = append(allErrs, field.Duplicate(idxPath.Child("containerName"), rm.ContainerName))
			allErrs = append(allErrs, field.Duplicate(idxPath.Child("resourceName"), rm.ResourceName))
			allErrs = append(allErrs, field.Duplicate(idxPath.Child("requestName"), rm.RequestName))
		}
		seen[k] = struct{}{}
	}
	if len(status.ResourceClaimName) == 0 {
		allErrs = append(allErrs, field.Required(fldPath.Child("resourceClaimName"), ""))
	} else {
		for _, detail := range ValidateResourceClaimName(status.ResourceClaimName, false) {
			allErrs = append(allErrs, field.Invalid(fldPath.Child("resourceClaimName"), status.ResourceClaimName, detail))
		}
	}
	return allErrs
}

// admitPodStatus allows to update the status of a pod if it is
// assigned to the current node.
func (p *Plugin) admitPodStatus(nodeName string, a admission.Attributes) error {
	switch a.GetOperation() {
	case admission.Update:
		// require an existing pod
		oldPod, ok := a.GetOldObject().(*api.Pod)
		if !ok {
			return admission.NewForbidden(a, fmt.Errorf("unexpected type %T", a.GetOldObject()))
		}
		// only allow a node to update status of a pod bound to itself
		if oldPod.Spec.NodeName != nodeName {
			return admission.NewForbidden(a, fmt.Errorf("node %q can only update pod status for pods with spec.nodeName set to itself", nodeName))
		}
		newPod, ok := a.GetObject().(*api.Pod)
		if !ok {
			return admission.NewForbidden(a, fmt.Errorf("unexpected type %T", a.GetObject()))
		}
		if !labels.Equals(oldPod.Labels, newPod.Labels) {
			return admission.NewForbidden(a, fmt.Errorf("node %q cannot update labels through pod status", nodeName))
		}
		if !resourceClaimStatusesEqual(oldPod.Status.ResourceClaimStatuses, newPod.Status.ResourceClaimStatuses) {
			return admission.NewForbidden(a, fmt.Errorf("node %q cannot update resource claim statues", nodeName))
		}
		if !extendedResourceClaimStatusEqual(oldPod.Status.ExtendedResourceClaimStatus, newPod.Status.ExtendedResourceClaimStatus) {
			return admission.NewForbidden(a, fmt.Errorf("node %q cannot update extended resource claim status", nodeName))
		}
		if !nodeAllocatableResourceClaimStatusesEqual(oldPod.Status.NodeAllocatableResourceClaimStatuses, newPod.Status.NodeAllocatableResourceClaimStatuses) {
			return admission.NewForbidden(a, fmt.Errorf("node %q cannot update node allocatable resource claim statuses", nodeName))
		}
		return nil
