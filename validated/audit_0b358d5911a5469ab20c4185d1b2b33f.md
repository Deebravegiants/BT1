### Title
Dogecoin address validation skips base58 checksum verification, allowing checksum-invalid DOGE strings to pass `validateAddress` and be embedded verbatim in a signed `WITHDRAW_TO` memo - (File: `packages/intents-sdk/src/lib/validateAddress.ts`)

### Summary
`validateDogeAddress` only checks a regex shape and never base58-decodes or verifies the double-SHA256 checksum, unlike every other base58 chain validator in the same file (`validateBtcBase58Address`, `validateLitecoinBase58Address`, `validateTronBase58Address`, `validateDashAddress`). Because `PoaBridge.validateWithdrawal` and `createWithdrawIntentPrimitive` trust `validateAddress`'s boolean result and never re-check the checksum, a checksum-invalid but regex-matching DOGE string is embedded verbatim into the signed `WITHDRAW_TO:<address>` memo.

### Finding Description
The claimed broken equality is: *`validateAddress(address, Chains.Dogecoin) === true` should imply `address` is a base58Check-valid Dogecoin address whose checksum matches `doubleSHA256(version‖hash160)[0:4]`*.

- `validateDogeAddress` implementation: [1](#0-0) 
This is a pure regex test (`/^[DA][1-9A-HJ-NP-Za-km-z]{25,33}$/`) with no `base58.decode` call and no checksum computation, in contrast to the analogous base58 validators in the same file that explicitly decode and verify the double-SHA256 checksum, e.g.: [2](#0-1) [3](#0-2) [4](#0-3) 

- `validateAddress` dispatches Dogecoin to this regex-only function: [5](#0-4) 

- `PoaBridge.validateWithdrawal` treats `validateAddress(...) === false` as the sole address-format gate before proceeding to build the withdrawal: [6](#0-5) 
Nothing downstream (`compareAddresses`, the token/minimum-amount checks, or the XRPL-specific RPC check) re-verifies a DOGE checksum — `compareAddresses` only compares the destination against the token's own origin-chain address for a different purpose.

- `createWithdrawIntentPrimitive` / `createWithdrawMemo` embed `destinationAddress` verbatim (only stripping a `bitcoincash:` prefix, irrelevant to DOGE) into the memo that becomes part of the signed intent: [7](#0-6) 

Exploit flow: an attacker (the party supplying `destinationAddress`, e.g., a counterparty/integrator-forwarded string) crafts a base58 string starting with `D` or `A`, 26-34 chars total, using only base58 alphabet characters, with an arbitrary/corrupted last checksum byte (still just needs to satisfy the regex — checksum bytes are base58-encoded too, so any character substitution within the valid charset trivially still matches the regex). This passes `validateDogeAddress`, passes `validateWithdrawal`, and is embedded verbatim into `WITHDRAW_TO:<address>` which becomes the `memo` field of the signed `ft_withdraw` intent that the user's wallet ultimately signs.

Existing guards that were checked and do **not** prevent this:
- `supports()` only checks assetId/routeConfig, not address validity.
- `FeeExceedsAmountError` / `getUnderlyingFee` are unrelated to address correctness.
- `compareAddresses` only prevents self-send to the token's own origin address; it does not validate checksum correctness of an arbitrary destination.
- The intents contract's own signature/nonce verification protects intent authenticity, not the semantic correctness of the memo string it signs.

### Impact Explanation
The signed `ft_withdraw` intent's `memo` field (`WITHDRAW_TO:<address>`) is what the POA bridge relayer parses off-chain to determine where DOGE is actually sent. If the embedded address is checksum-invalid, no real Dogecoin wallet corresponds to it, so a successful, fully-signed withdrawal results in funds that are unrecoverable — matching the Critical category ("funds delivered to a wrong address/chain/contract with no recovery"). This is repeatable per withdrawal call for any Dogecoin-denominated `nep141:doge.omft.near` withdrawal.

### Likelihood Explanation
Preconditions are minimal: any caller of `PoaBridge.validateWithdrawal`/`createWithdrawalIntents` (or the higher-level SDK withdrawal flow) with `assetId` resolving to Dogecoin and an attacker-influenced `destinationAddress` string. Constructing a regex-matching but checksum-invalid base58 string costs nothing computationally — it does not require finding a base58-decodable string with a specific structure, since the regex has no decode/length/checksum constraint at all, only character-class and length constraints. This is trivially and repeatedly exploitable by any party who can supply the `destinationAddress` value into an otherwise-normal withdrawal request.

### Recommendation
Rewrite `validateDogeAddress` to mirror `validateBtcBase58Address`/`validateLitecoinBase58Address`: base58-decode the address, confirm the decoded length is 25 bytes, validate the version byte(s) for Dogecoin mainnet (`0x1e` for P2PKH, `0x16` for P2SH), and verify the last 4 bytes equal `doubleSHA256(payload)[0:4]` before returning `true`.

### Proof of Concept
```ts
import { describe, it, expect } from "vitest";
import { base58 } from "@scure/base";
import { sha256 } from "@noble/hashes/sha2";
import { validateAddress } from "packages/intents-sdk/src/lib/validateAddress";
import { Chains } from "packages/intents-sdk/src/lib/caip2";
import { createWithdrawIntentPrimitive } from "packages/intents-sdk/src/bridges/poa-bridge/poa-bridge-utils";

it("validateAddress accepts a DOGE address with a corrupted checksum", () => {
  // Build a valid DOGE payload (version 0x1e + 20-byte hash160), then corrupt checksum byte.
  const version = 0x1e;
  const hash160 = new Uint8Array(20).fill(1);
  const payload = new Uint8Array([version, ...hash160]);
  const correctChecksum = sha256(sha256(payload)).subarray(0, 4);
  const corruptedChecksum = new Uint8Array(correctChecksum);
  corruptedChecksum[3] = (corruptedChecksum[3] + 1) % 256; // break checksum

  const bytes = new Uint8Array([...payload, ...corruptedChecksum]);
  const address = base58.encode(bytes);

  // LHS: SDK claims this is a valid Dogecoin address.
  expect(validateAddress(address, Chains.Dogecoin)).toBe(true);

  // RHS: it is NOT checksum-valid (no real wallet can control it).
  const decoded = base58.decode(address);
  const realChecksum = sha256(sha256(decoded.subarray(0, 21))).subarray(0, 4);
  expect(decoded.subarray(21, 25)).not.toEqual(realChecksum); // proves broken equality

  // Downstream: no additional checksum check before embedding into signed memo.
  const intent = createWithdrawIntentPrimitive({
    assetId: "nep141:doge.omft.near",
    destinationAddress: address,
    destinationMemo: undefined,
    amount: 1000000n,
  });
  expect(intent.memo).toBe(`WITHDRAW_TO:${address}`);
});
```

function validateBtcBase58Address(address: string): boolean {
	const decoded: Uint8Array = base58.decode(address);

	// version (1) + hash160 (20) + checksum (4) = 25 bytes
	if (decoded.length !== 25) return false;

	const version = decoded[0];
	// 0x00 = P2PKH mainnet, 0x05 = P2SH mainnet
	if (version !== 0x00 && version !== 0x05) return false;

	const payload = decoded.subarray(0, 21);
	const checksum = decoded.subarray(21, 25);
	const expectedChecksum = sha256(sha256(payload)).subarray(0, 4);

	for (let i = 0; i < 4; i++) {
		if (checksum[i] !== expectedChecksum[i]) return false;
	}
	return true;
}

function validateLitecoinBase58Address(
	address: string,
	expectedVersion: number,
): boolean {
	let decoded: Uint8Array;

	try {
		decoded = base58.decode(address);
	} catch {
		return false;
	}

	// version (1) + payload (20) + checksum (4)
	if (decoded.length !== 25) return false;

	const version = decoded[0];
	if (version !== expectedVersion) return false;

	const payload = decoded.subarray(0, 21); // version + hash160
	const checksum = decoded.subarray(21, 25);

	const hash1 = sha256(payload);
	const hash2 = sha256(hash1);
	const expectedChecksum = hash2.subarray(0, 4);

	for (let i = 0; i < 4; i++) {
		if (checksum[i] !== expectedChecksum[i]) return false;
	}

	return true;
}

export function validateDashAddress(address: string): boolean {
	try {
		const decoded: Uint8Array = base58.decode(address);

		// version (1) + payload (20) + checksum (4)
		if (decoded.length !== 25) return false;

		const version = decoded[0];
		if (
			version !== 0x4c && // P2PKH
			version !== 0x10 // P2SH
		) {
			return false;
		}

		const payload = decoded.subarray(0, 21);
		const checksum = decoded.subarray(21, 25);

		const hash1 = sha256(payload);
		const hash2 = sha256(hash1);
		const expectedChecksum = hash2.subarray(0, 4);

		for (let i = 0; i < 4; i++) {
			if (checksum[i] !== expectedChecksum[i]) return false;
		}

		return true;
	} catch {
		return false;
	}
}

export function createWithdrawIntentPrimitive(params: {
	assetId: string;
	destinationAddress: string;
	destinationMemo: string | undefined;
	amount: bigint;
}): Extract<IntentPrimitive, { intent: "ft_withdraw" }> {
	const { contractId: tokenAccountId } = utils.parseDefuseAssetId(
		params.assetId,
	);
	return {
		intent: "ft_withdraw",
		token: tokenAccountId,
		receiver_id: tokenAccountId,
		amount: params.amount.toString(),
		memo: createWithdrawMemo({
			receiverAddress: params.destinationAddress,
			xrpMemo: params.destinationMemo,
		}),
		min_gas: MIN_GAS_AMOUNT,
	};
}

function createWithdrawMemo({
	receiverAddress,
	xrpMemo,
}: {
	receiverAddress: string;
	xrpMemo: string | undefined;
}) {
	// Strip "bitcoincash:" prefix from BCH CashAddr addresses
	const normalizedAddress = receiverAddress
		.toLowerCase()
		.startsWith("bitcoincash:")
		? receiverAddress.slice("bitcoincash:".length)
		: receiverAddress;

	const memo = ["WITHDRAW_TO", normalizedAddress];

	if (xrpMemo != null && xrpMemo !== "") {
		memo.push(xrpMemo);
	}

	return memo.join(":");
}
