The Rust/Substrate implementation of the Get-timeout handler at [1](#0-0)  explicitly checks `host.response_receipt(&response).is_some()` and rejects the timeout with `Error::GetResponseAlreadyReceived` if a response was already delivered — this is the correct guard against exactly this class of race. The EVM `HandlerV2.handleGetRequestTimeouts` / `EvmHost.dispatchTimeOut(GetRequestTimeout...)` path has **no equivalent local check**, which is the vulnerability.

### Title
Missing local response-receipt check lets `handleGetRequestTimeouts` double-pay an already-answered GET request on EvmHost — (File: `evm/src/core/HandlerV2.sol`, `evm/src/core/EvmHost.sol`)

### Summary
On EVM hosts, a GET request's escrowed fee can be paid out twice: once as the relayer reward when the `GetResponse` is delivered, and again as the sender refund when a `GetRequestTimeout` is later delivered for the same commitment — because the EVM timeout path never checks the source-side `_responseReceipts` receipt that would prove the request was already answered.

### Finding Description
`EvmHost.dispatchIncoming(GetResponse memory response, address relayer)` [2](#0-1)  sets `_responseReceipts[commitment]` and, on a successful `onGetResponse` callback, pays the relayer fee out of `_requestCommitments[commitment].fee` — but it never deletes `_requestCommitments[commitment]`.

Compare this to `dispatchTimeOut(GetRequestTimeout...)` [3](#0-2) , which is annotated "replay protection" and deletes `_requestCommitments[commitment]` unconditionally before invoking the callback (restoring it only if the callback reverts).

`HandlerV2.handleGetRequestTimeouts` [4](#0-3)  only checks:
1. That `meta.sender != address(0)` (i.e., `_requestCommitments[commitment]` still exists), and
2. A Polkadot-trie **non-membership** proof for `RESPONSE_RECEIPTS_STORAGE_PREFIX + commitment` against the **destination** chain's state root at `message.height`.

It never queries the EVM host's own `_responseReceipts[commitment]` — the receipt that `dispatchIncoming(GetResponse, ...)` sets locally on this exact chain when the response was delivered. Because `_stateCommitments[stateMachineId][height]` on `EvmHost` is never pruned for old heights (only vetoed via fisherman `deleteStateMachineCommitmentInternal`), a relayer can supply a non-membership proof rooted at an *older*, still-valid `message.height` that predates when the response was actually produced/recorded, satisfying the check even though the corresponding `GetResponse` has since been delivered and its fee already paid out via `dispatchIncoming(GetResponse,...)`.

The Substrate/pallet-ismp equivalent handler explicitly guards against this: `handlers/timeout.rs` checks `host.response_receipt(&response).is_some()` and rejects with `Error::GetResponseAlreadyReceived` [1](#0-0)  before allowing the timeout to proceed. No such check (nor equivalent local receipt deletion) exists on the EVM path.

### Impact Explanation
This is a direct theft/double-payment of protocol-escrowed relayer fees: the same `FeeMetadata.fee` for a single GET request commitment can be paid out twice — once as the relayer reward on response delivery, and once again as a "refund" to the original `meta.sender` on timeout — draining the fee token (`IERC20(feeToken())`) held by `EvmHost` beyond what was actually escrowed for that request. This is reachable by any relayer/unprivileged submitter of two valid but temporally-disjoint proofs (a genuine `GetResponse` proof and a stale-height `GetRequestTimeout` non-membership proof), matching the "concrete theft of funds" bar.

### Likelihood Explanation
Medium-to-High: it requires an attacker (or any relayer) to obtain two legitimately verifiable proofs — a `GetResponse` proof at a later accepted height, and a `GetRequestTimeout` non-membership proof rooted at an earlier accepted (but not yet superseded/vetoed) `message.height` for the destination chain — both of which are within normal operational reach since `EvmHost` retains historical `_stateCommitments` entries indefinitely absent a fisherman veto. No privileged access or malicious governance/collator/node is required; a single relayed transaction pair on the source EVM chain suffices.

### Recommendation
In `EvmHost.dispatchTimeOut(GetRequestTimeout...)` (or in `HandlerV2.handleGetRequestTimeouts` before calling it), explicitly check and reject if `_responseReceipts[commitment].relayer != address(0)`, mirroring the Substrate-side `host.response_receipt(...).is_some()` guard in `handlers/timeout.rs`. Additionally consider deleting/marking `_requestCommitments[commitment]` as consumed inside `dispatchIncoming(GetResponse,...)` immediately after paying the relayer fee, so the fee metadata cannot be "reused" by a later timeout path regardless of proof height staleness.

### Proof of Concept
1. Source chain (EVM) dispatches a `GetRequest` with escrowed `fee` recorded in `_requestCommitments[commitment]`.
2. Relayer submits a valid `GetResponseMessage` via `handleGetResponses` → `EvmHost.dispatchIncoming(GetResponse,...)`: `_responseReceipts[commitment]` is set, `onGetResponse` succeeds, and `meta.fee` is paid to the relayer. `_requestCommitments[commitment]` is **not** deleted.
3. Attacker later submits a `GetTimeoutMessage` via `handleGetRequestTimeouts`, supplying a non-membership proof against an **older**, still-stored `_stateCommitments[destStateMachineId][olderHeight]` (from before the response was ever produced on the destination), satisfying `entry.value.length == 0`.
4. `meta.sender == address(0)` check passes (commitment metadata still present) → `EvmHost.dispatchTimeOut(GetRequestTimeout,...)` executes, deletes `_requestCommitments[commitment]`, calls `onGetTimeout`, and refunds `meta.fee` a second time to `meta.sender`.
5. Net effect: the protocol pays out `fee` twice for a single GET request commitment.

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;

        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
