### Title
Iris-code signature omits `signup_id` and `signup_reason` from the signed payload, enabling attestation replay and fraud-tag tampering - ([File: src/plans/enroll_user.rs])

### Summary
Analogous to the Factory.sol issue where a signature covers only generic parameters without a domain separator or nonce (enabling replay and reuse), `orb-core`'s `make_signature` function in `src/plans/enroll_user.rs` computes a secure-element signature over a fixed, narrow set of fields — Orb ID, user ID, and iris/pipeline data — but never includes the per-signup nonce (`signup_id`) or the anti-fraud tag (`signup_reason`) that are transmitted alongside it in the same request.

### Finding Description
`make_signature` builds the signed digest from only: [1](#0-0) 

```
ORB_ID + user_qr_code.user_id + pipeline.v2.{ir_net_version, iris_version} + eye_left.{iris_code, mask_code, iris_code_version} + eye_right.{...}
```

This digest is signed by the hardware secure element via `secure_element::sign` [2](#0-1) , and the resulting base64 signature, together with the **unsigned** `signup_id` (used only as a URL path parameter) and the **unsigned** `reason` form field (`NORMAL`/`FAILURE`/`FRAUD`), is submitted to the backend: [3](#0-2) 

Because `signup_id` and `signup_reason` are excluded from the signed material — exactly the "signature without domain/nonce" pattern described in the Factory.sol report — the cryptographic attestation only proves "this Orb signed this iris data for this user," not "this Orb signed this specific signup attempt with this specific fraud disposition." Any component or intermediary able to modify the outgoing multipart request after the secure-element signing step (the signing happens in a separate blocking task at `enroll_user.rs:74-88`, and the HTTP submission with the mutable `reason`/`signup_id` fields happens afterward in `signup_post::request`) can:
1. Replay the same signature under a different `signup_id` value, since the signature never binds to it.
2. Flip `SignupReason::Fraud` to `SignupReason::Normal` (or vice versa) without invalidating the signature, since `reason` is never part of the signed digest [4](#0-3) .

### Impact Explanation
The `reason` field is explicitly the mechanism by which the Orb tells the backend that "Signup was detected as a fraud attempt at the orb" [4](#0-3) . Since this tag is not covered by the cryptographic signature, the backend cannot cryptographically distinguish a genuine `NORMAL` attestation from a `FRAUD` signup whose reason tag was altered post-signing, or from a signature replayed against an unrelated `signup_id`. This is a direct fraud/liveness-enforcement bypass and attestation-forgery class of issue: the secure-element signature is supposed to be the root of trust that biometric data legitimately came from this device for this signup, but the binding is incomplete, mirroring the exact defect described in the Factory.sol report (missing domain separator / nonce / full parameter coverage in the signed payload).

### Likelihood Explanation
Exploitation requires the ability to alter the outgoing signup POST request between signature computation (`enroll_user.rs:74-88`) and transmission (`signup_post::request`), without needing the secure-element private key itself — i.e., a normal-privilege software-level tampering point rather than a physical/hardware attack, so it falls within the unprivileged-attacker scope. The likelihood is moderate: it requires local software-level request manipulation, but no elevated backend or admin credentials, no leaked secrets, and no physical hardware tampering; it exploits a straightforward, code-verifiable gap in what fields are protected by the signature.

### Recommendation
Include `signup_id` and `signup_reason` (and ideally a chain/context identifier such as the backend environment or `distributorId`) in the data hashed by `make_signature` before signing, so the secure-element signature binds the biometric attestation to the specific signup session and its fraud disposition, preventing tag tampering and cross-signup replay — following the same EIP-712-style principle recommended in the source report: sign over the complete set of security-relevant parameters, not a narrow subset.

### Proof of Concept
1. Orb performs a signup capture; `make_signature` computes and signs `SHA256(ORB_ID || user_id || iris pipeline fields)` only [1](#0-0) .
2. `Plan::run` passes this signature plus the currently-in-scope `signup_reason` (e.g., `Fraud`, set when the Orb's own on-device checks flagged the attempt) to `signup_post::request` [5](#0-4) .
3. `signup_post::request` places `reason` and `signup_id` into the multipart form unsigned [6](#0-5) .
4. Because neither field is part of the signed digest, a party able to intercept/modify this request before submission can change `reason` from `FRAUD` to `NORMAL` (or re-target the signature at a different `signup_id`) while the signature remains valid against the biometric data, defeating the fraud-tag/attestation binding.

fn make_signature(user_qr_code: &qr_scan::user::Data, pipeline: &Pipeline) -> Result<String> {
    let mut ctx = Context::new(&SHA256);
    ctx.update(ORB_ID.as_str().as_bytes());
    ctx.update(user_qr_code.user_id.as_bytes());
    ctx.update(pipeline.v2.ir_net_version.as_bytes());
    ctx.update(pipeline.v2.iris_version.as_bytes());
    ctx.update(pipeline.v2.eye_left.iris_code.as_bytes());
    ctx.update(pipeline.v2.eye_left.mask_code.as_bytes());
    ctx.update(pipeline.v2.eye_left.iris_code_version.as_bytes());
    ctx.update(pipeline.v2.eye_right.iris_code.as_bytes());
    ctx.update(pipeline.v2.eye_right.mask_code.as_bytes());
    ctx.update(pipeline.v2.eye_right.iris_code_version.as_bytes());
    let signed = secure_element::sign(ctx.finish())?;
    Ok(BASE64.encode(&signed))
}

/// Signs this buffer with Secure Element and returns the output.
#[cfg(not(test))]
pub fn sign<T: AsRef<[u8]>>(data: T) -> Result<Vec<u8>> {
    fn inner(data: &[u8]) -> Result<Vec<u8>> {
        let encoded = BASE64.encode(data);

        tracing::info!("Running orb-sign-iris-code");
        let mut command = Command::new("/usr/bin/orb-sign-iris-code");
        command.stdin(Stdio::piped());
        command.stdout(Stdio::piped());
        command.stderr(Stdio::piped());
        let mut child = command.spawn().wrap_err("running orb-sign-iris-code")?;

        let mut stdin = child.stdin.take().unwrap();
        stdin.write_all(encoded.as_bytes())?;
        drop(stdin);

        let output = child.wait_with_output().wrap_err("waiting for orb-sign-iris-code")?;
        let success = output.status.success();
        for line in String::from_utf8_lossy(&output.stderr).lines() {
            if success {
                tracing::trace!("orb-sign-iris-code {}", line);
            } else {
                tracing::error!("orb-sign-iris-code {}", line);
            }
        }
        if !success {
            if let Some(code) = output.status.code() {
                bail!("orb-sign-iris-code exited with non-zero exit code: {code}");
            } else {
                bail!("orb-sign-iris-code terminated by signal");
            }
        }
        BASE64.decode(&output.stdout).wrap_err("decoding orb-sign-iris-code output")
    }

    inner(data.as_ref())
}

/// Makes a signup request.
#[allow(clippy::too_many_arguments)]
pub async fn request(
    signature: Option<&String>,
    signup_id: &str,
    operator_qr_code: &qr_scan::user::Data,
    user_qr_code: &qr_scan::user::Data,
    s3_region: &str,
    capture: &Capture,
    pipeline: Option<&Pipeline>,
    signup_reason: SignupReason,
) -> Result<Response> {
    dd_gauge!(
        "main.gauge.signup.sharpest_iris",
        capture.eye_left.ir_net_estimate.score.to_string(),
        "side:left"
    );
    dd_gauge!(
        "main.gauge.signup.sharpest_iris",
        capture.eye_right.ir_net_estimate.score.to_string(),
        "side:right"
    );
    tracing::info!("Orb OS version: {:?}", &*ORB_OS_VERSION);
    tracing::info!("Signup reason: {:?}", signup_reason);
    let codes = pipeline.map_or(String::new(), |p| {
        serde_json::to_string_pretty(&format_pipeline(p)).expect("always a valid JSON")
    });
    let mut form = Form::new()
        .text("softwareVersion", &*ORB_OS_VERSION)
        .text("orbId", ORB_ID.as_str())
        .text("distributorId", operator_qr_code.user_id.clone())
        .text("userId", user_qr_code.user_id.clone())
        .text("region", s3_region.to_owned())
        .text("signature", signature.map_or(String::default(), Clone::clone))
        .text("codes", codes)
        .text("reason", signup_reason.to_screaming_snake_case().to_string());
    if let Some(latitude) = capture.latitude {
        form = form.text("latitude", latitude.to_string());
    }
    if let Some(longitude) = capture.longitude {
        form = form.text("longitude", longitude.to_string());
    }
    let request = super::client()?
        .post(format!("{}/api/v2/signups/{signup_id}", *SIGNUP_BACKEND_URL))
        .basic_auth(&*ORB_ID, Some(get_orb_token()?))
        .multipart(form);
