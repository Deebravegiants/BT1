### Title
Accrual-time `i128` debt-value overflow permanently freezes an entire market - (File: `common/src/rates/scaling.rs`)

### Summary
A sufficiently large scaled debt position can make the borrow-index valuation overflow before the configured borrow-index ceiling is reached, causing every subsequent accrual-dependent operation in that market to revert. This is an unprivileged, market-wide denial of service affecting repayment, withdrawal, liquidation, bad-debt cleanup, and recapitalization.

### Finding Description
`controller::update_indexes(caller, assets)` is permissionless and forwards the selected `Vec<HubAssetKey>` to the pool for accrual. [1](#0-0) 

The pool accrues each requested market through `ops::market::accrue`, which calls `interest::global_sync` before committing state. [2](#0-1) 

`global_sync` processes elapsed time in bounded chunks, but `cache.mark_accrued()` runs only after every chunk succeeds. [3](#0-2) 

Each chunk calls `accrue_step`, whose first operation converts total scaled debt into its RAY-denominated value through `scaled_to_original`. [4](#0-3) 

`scaled_to_original` performs `scaled.mul(index)`, so `scaled_debt * borrow_index` must remain representable in the `Ray`/`i128` domain. [5](#0-4) 

The overflow threshold is therefore `borrow_index > i128::MAX / borrowed_scaled`, which can be far below the nominal `10^36` borrow-index ceiling when a market has whale-scale scaled debt. [6](#0-5) 

Because the timestamp is not advanced before the panic, the same stale `last_timestamp` causes every later accrual attempt to repeat the overflowing calculation rather than making partial progress. [7](#0-6) 

All ordinary pool mutations use an interest-synced market cache through `ops::synced_market` or `ops::load_leg`, so the same arithmetic runs before the requested mutation. [8](#0-7) 

Repayment reaches that synced cache before burning debt or crediting cash. [9](#0-8) 

Withdrawal reaches it before resolving, burning, guarding, or paying out supply shares. [10](#0-9) 

Bad-debt seizure reaches it before writing down debt or reclassifying collateral shares. [11](#0-10) 

### Impact Explanation
Once the aggregate scaled debt is large enough, interest growth can push the debt valuation past `i128::MAX` even though the stored borrow index remains below `MAX_BORROW_INDEX_RAY`. [12](#0-11) 

At that point suppliers cannot withdraw and borrowers or third parties cannot repay, because both paths panic during mandatory accrual before applying the requested accounting change. [13](#0-12) [14](#0-13) 

Liquidation and bad-debt cleanup touching the market also cannot bypass the sync, because seizure calls `ops::synced_market` before performing its write-down. [15](#0-14) 

The repository's integration test demonstrates the resulting permanent market freeze: `update_indexes`, `withdraw`, and `repay` all return `MathOverflow`, while the stored borrow index remains below the nominal cap. [16](#0-15) 

This permanently freezes all user funds and debt positions in the affected `(hub_id, asset)` market unless the deployed code is changed outside the in-scope user flow. [17](#0-16) 

### Likelihood Explanation
The attack requires a market with aggregate scaled debt near the representable RAY-value limit and enough elapsed high-rate accrual for the index multiplier to cross the dynamic `i128` boundary. [18](#0-17) 

A single unprivileged address can establish the borrowing side with ordinary `supply` and `borrow` calls when market caps and collateral value permit it, and any address can later submit `update_indexes` for the market. [19](#0-18) 

No privileged caller, leaked key, oracle manipulation, malformed token, or off-chain dependency is required once such a high-utilization whale market exists. [19](#0-18) 

The extreme capitalization and multi-year accrual requirement reduce practical likelihood, but the resulting irreversible market-wide freeze supports a Medium-severity analog. [20](#0-19) 

### Recommendation
Use widened arithmetic, such as Soroban `I256`, for aggregate debt and supply valuation, utilization, and accrual deltas rather than materializing the product as `i128`. [21](#0-20) 

Alternatively, enforce an effective per-market index ceiling derived from current scaled balances, and clamp or split accrual so `borrowed_scaled * borrow_index` can never exceed the representable domain. [5](#0-4) 

Any fix should also ensure that `global_sync` cannot repeatedly retry the same overflowing state without advancing or safely bounding the market. [3](#0-2) 

### Proof of Concept
Assume an existing market accepts an 18-decimal token and has sufficient capacity and user liquidity. [22](#0-21) 

```text
// Attacker supplies sufficient collateral to their own account.
controller::supply(
    caller = attacker,
    account_id = 0,
    spoke_id = spoke_id,
    assets = [(COL_KEY, 3_000_000_000 * 10^7)],
);

// Attacker borrows almost all of a one-billion-token BIG18 market.
controller::borrow(
    caller = attacker,
    account_id = attacker_account,
    borrows = [(BIG18_KEY, 980_000_000 * 10^18)],
    to = Some(attacker),
);

// After enough accrual time for the index to exceed the dynamic i128 bound:
controller::update_indexes(
    caller = attacker,
    assets = [BIG18_KEY],
);
```

The final call re-enters `accrue_step`, overflows in `scaled_to_original`, and reverts before `last_timestamp` is updated. [23](#0-22) [7](#0-6) 

Every subsequent `withdraw`, `repay`, `liquidate`, `clean_bad_debt`, `recapitalize`, or `update_indexes` touching `BIG18_KEY` must sync the same stale market and therefore hits the same overflow. [8](#0-7) 

The existing stress test encodes this sequence with one billion 18-decimal tokens, 98% utilization, yearly accrual, and confirms `MathOverflow` on index update, withdrawal, and repayment. [24](#0-23)

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

```rust
    borrowed: Ray,
```

```rust
/// Loads a market cache and accrues interest through the current ledger time.
pub(crate) fn synced_market(env: &Env, hub_asset: &HubAssetKey) -> Cache {
    let mut cache = Cache::load(env, hub_asset);
    interest::global_sync(env, &mut cache);
    cache
}

/// Renews instance TTL, then loads and accrues the market.
pub(crate) fn renewed_market(env: &Env, hub_asset: &HubAssetKey) -> Cache {
    renew_instance(env);
    synced_market(env, hub_asset)
}

/// Validates `action.amount ≥ 0`, syncs the market, and returns (cache, scaled position).
pub(crate) fn load_leg(env: &Env, action: &PoolAction) -> (Cache, Ray) {
    require_nonneg_amount(env, action.amount);
    let cache = synced_market(env, &action.hub_asset);
    (cache, Ray::from(action.position.scaled_amount))
}
```

```rust
/// Accrues interest, resolves the repay amount into burned debt shares and
/// overpayment, burns the shares, and credits the net repay to cash without
/// transferring the overpayment refund. Panics if a positive net repay would
/// burn zero scaled shares.
pub(crate) fn accounting(env: &Env, action: &PoolAction) -> RepayOutcome {
    let (mut cache, position) = ops::load_leg(env, action);
    let amount = action.amount;

    let (burned, overpayment) = cache.resolve_repay(amount, position);
    let net_repay = amount
        .checked_sub(overpayment)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));
```

```rust
/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
