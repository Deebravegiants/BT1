### Title
Unbounded loop in GRANDPA `AncestryChain::ancestry` allows a crafted finality proof to hang node execution - (File: `modules/consensus/grandpa/primitives/src/justification.rs`)

### Summary
`pallet-ismp`'s `handle_unsigned` extrinsic is permissionless (`ensure_none`) and dispatches any submitted `Message::Consensus` for free, including GRANDPA consensus updates [1](#0-0) . For the GRANDPA client, this routes to `GrandpaConsensusClient::verify_consensus`, which decodes the attacker-supplied proof and calls `verify_parachain_headers_with_grandpa_finality_proof` / `verify_grandpa_finality_proof` [2](#0-1) . These functions build an `AncestryChain` directly from the attacker-controlled `finality_proof.unknown_headers` vector and then call `ancestry()` on it before or as part of justification verification [3](#0-2) .

### Finding Description
`AncestryChain::ancestry` walks parent hashes from `block` back to `base` using a `BTreeMap` built purely from the untrusted `unknown_headers` list, with no cycle detection or iteration bound:

```rust
fn ancestry(&self, base: H::Hash, block: H::Hash) -> Result<Vec<H::Hash>, finality_grandpa::Error> {
    let mut route = vec![block];
    let mut current_hash = block;
    while current_hash != base {
        match self.ancestry.get(&current_hash) {
            Some(current_header) => {
                current_hash = *current_header.parent_hash();
                route.push(current_hash);
            },
            _ => return Err(finality_grandpa::Error::NotDescendent),
        };
    }
    Ok(route)
}
``` [4](#0-3) 

Each header's `parent_hash` field is fully attacker-controlled (headers are only SCALE-decoded, not individually authenticated against any external chain before this call). An attacker can submit `unknown_headers` containing a set of headers whose `parent_hash` fields form a cycle that does not include `base` (e.g. header A's parent = header B's hash, header B's parent = header A's hash). Since the `BTreeMap::get` lookup for `current_hash` will always succeed (the cycle nodes are present), the `while current_hash != base` loop never terminates — it endlessly appends to `route`, growing memory without bound and consuming CPU indefinitely.

This call site is reached in `verify_grandpa_finality_proof`:
```rust
let finalized = headers.ancestry(from, target.hash()).map_err(|_| Error::InvalidAncestry)?;
``` [5](#0-4)  — reached *before* the GRANDPA justification signatures are validated in some code paths (the earlier `headers.ancestry(base.hash(), consensus_state.latest_hash)` call at line 82-86 runs even before `justification.verify(...)` at line 91-93), meaning the hang can be triggered purely from the header cycle in `unknown_headers`, without needing a cryptographically valid GRANDPA commit/justification for the target block.

This is directly analogous to the Cilium DNS proxy CWE-770 bug: a single crafted message from an untrusted, unauthenticated source (here, any address via the unsigned `handle_unsigned` extrinsic, exactly like the unauthenticated DNS response in the advisory) triggers unbounded resource consumption (CPU/memory) inside a critical dispatch path, rather than a bounded rejection.

### Impact Explanation
Because `handle_unsigned` is validated via the transaction pool's `validate_unsigned`, which itself calls `Self::execute(messages.clone())` — i.e., the same vulnerable code executes during **transaction-pool validation** on every node that receives the gossiped extrinsic, not just the block author [6](#0-5) . An infinite loop here therefore hangs transaction-pool validation on every full node that processes the extrinsic (via gossip), and if it reaches block execution/import, it hangs block execution/import — Substrate runtime execution is not gas-metered like the EVM, so nothing interrupts the loop. This can stall or crash node processes network-wide from a single unsigned, fee-less transaction, constituting a route unable to deliver messages / denial of service consistent with CWE-770, matching Medium severity per the analog advisory (network-reachable DoS with no privileged access required).

### Likelihood Explanation
High likelihood of triggerability: the attacker needs only to craft a set of `unknown_headers` (decodable `SubstrateHeader`s) with parent-hash pointers forming a cycle, wrap them in a `FinalityProof`/`ConsensusMessage::Polkadot(...)`, and submit via the permissionless, feeless `handle_unsigned` extrinsic (or the equivalent relayed consensus-message path used by tesseract relayers) — no signatures, stake, or prior state are required to reach the vulnerable loop.

### Recommendation
Bound `AncestryChain::ancestry` against re-visiting hashes (e.g., track a `visited: BTreeSet<H::Hash>` and return an error such as `NotDescendent`/a new `CyclicAncestry` error if a hash is seen twice), and/or cap the number of iterations to `self.ancestry.len()` (the ancestry map can contain at most that many distinct headers, so any walk exceeding that length is provably cyclic). Apply the same fix in the ismp-grandpa fraud-proof path (`modules/ismp/clients/grandpa/src/consensus.rs`), which uses `AncestryChain` in the same unbounded way.

### Proof of Concept
1. Construct headers `H_a` and `H_b` such that `H_a.hash() = X`, `H_a.parent_hash = Y`, `H_b.hash() = Y`, `H_b.parent_hash = X` (a 2-cycle); pick any distinct `target`/`base` hashes not in `{X, Y}`, with `target` matching a `commit.target_hash` from an otherwise-decodable `GrandpaJustification` (validity of the justification signature is not required to reach the hang for the pre-check `headers.ancestry(base.hash(), consensus_state.latest_hash)`).
2. Build a `FinalityProof { block: target_hash, justification: <encoded justification bytes>, unknown_headers: vec![H_a, H_b, ...] }` and wrap it in `ConsensusMessage::Polkadot(...)`.
3. Submit as `Message::Consensus(...)` inside `pallet_ismp::Call::handle_unsigned { messages }` as an unsigned extrinsic.
4. Observe that `verify_grandpa_finality_proof` (called from `GrandpaConsensusClient::verify_consensus`, itself invoked from both `validate_unsigned` and `execute`) enters `AncestryChain::ancestry` and never returns, hanging the calling node/thread indefinitely and growing the `route` vector without bound.

pub fn verify_grandpa_finality_proof<H>(
	mut consensus_state: ConsensusState,
	finality_proof: FinalityProof<H>,
) -> Result<(ConsensusState, H, Vec<H256>, AncestryChain<H>), Error>
where
	H: Header<Hash = H256, Number = u32>,
	H::Number: finality_grandpa::BlockNumberOps + Into<u32>,
{
	// First validate unknown headers.
	let headers = AncestryChain::<H>::new(&finality_proof.unknown_headers);

	let target = finality_proof
		.unknown_headers
		.iter()
		.max_by_key(|h| *h.number())
		.ok_or(Error::UnknownHeadersEmpty)?;

	// this is illegal
	if target.hash() != finality_proof.block {
		Err(Error::LatestBlockMismatch)?;
	}

	let justification =
		GrandpaJustification::<H>::decode_all(&mut &finality_proof.justification[..])
			.map_err(|e| Error::DecodeJustification(alloc::format!("{e:?}")))?;

	if justification.commit.target_hash != finality_proof.block {
		Err(Error::JustificationTargetMismatch)?;
	}

	let from = consensus_state.latest_hash;

	let base = finality_proof
		.unknown_headers
		.iter()
		.min_by_key(|h| *h.number())
		.ok_or(Error::UnknownHeadersEmpty)?;

	if base.number() < &consensus_state.latest_height {
		headers
			.ancestry(base.hash(), consensus_state.latest_hash)
			.map_err(|_| Error::InvalidAncestry)?;
	}

	let finalized = headers.ancestry(from, target.hash()).map_err(|_| Error::InvalidAncestry)?;
