## #Analog Found

### Title
Missing "already-responded" guard lets a relayer force a duplicate `onGetTimeout()` delivery for a GET request that has already received its `onGetResponse()` - ([File: evm/src/core/HandlerV2.sol])

### Summary
The ALSA report is about a resource being torn down by its "master" without properly synchronizing with a still-outstanding "slave" completion event, so the slave's terminal callback fires against state that should have already been finalized/removed. The Hyperbridge EVM messaging path has the same class of bug: the pallet-ismp (Substrate) implementation of the GET-request lifecycle explicitly guards against delivering a timeout after a response was already received, but the equivalent EVM `EvmHost`/`HandlerV2` path has no such guard, allowing an app to receive both a genuine `onGetResponse()` and a later, stale `onGetTimeout()` for the exact same request.

### Finding Description
On the Substrate side, `modules/ismp/core/src/handlers/timeout.rs` explicitly rejects a GET timeout if a response receipt already exists: [1](#0-0) 

This shows the protocol's own invariant: once a `GetResponse` has been delivered for a request, that request must never subsequently be timed out.

On the EVM side, `EvmHost.dispatchIncoming(GetResponse, ...)` records the response receipt but never deletes the corresponding `_requestCommitments[commitment]` entry: [2](#0-1) 

Compare this to `dispatchTimeOut(GetRequestTimeout, ...)`, which deletes `_requestCommitments[commitment]` for replay protection but performs **no check whatsoever** against `_responseReceipts[commitment]` before invoking `onGetTimeout()`: [3](#0-2) 

The permissionless caller of this path, `HandlerV2.handleGetRequestTimeouts`, only verifies:
1. the timeout timestamp has elapsed,
2. the request commitment is "known" (`meta.sender != address(0)`, which stays true forever since `dispatchIncoming(GetResponse)` never clears it),
3. a non-membership proof of the `ResponseReceipts` storage prefix **at the specific proof height `message.height`** — not against the current state. [4](#0-3) 

Because the non-membership proof is anchored to an arbitrary past height, a relayer can legitimately supply a proof from *before* the response was ever recorded, satisfying `handleGetRequestTimeouts`'s checks even though the response has since been delivered (visible via `handleGetResponses`/`dispatchIncoming(GetResponse)` on the current chain state). Since `_requestCommitments[commitment]` was never deleted when the response was delivered, `meta.sender != address(0)` still holds, and `dispatchTimeOut` proceeds to call `IApp.onGetTimeout()` on the app — even though `IApp.onGetResponse()` was already called for the same commitment.

This is the direct analog of the ALSA bug: the "master" record (`_requestCommitments`) is not torn down/synchronized at the moment the "slave" event (response delivery) completes, so a second, stale completion path (timeout) can still fire against it and reach the app's callback.

### Impact Explanation
Any `IApp` built on `HyperApp`/`IApp` that assumes a GET request resolves via exactly one of `onGetResponse()` or `onGetTimeout()` (a documented, expected invariant — see `docs/content/developers/evm/messaging/get-requests.mdx`, which describes `onGetTimeout` as being for "cleanup and state management") can be driven into an inconsistent state: e.g., an app that unlocked funds/finalized an escrow on `onGetResponse` and now also runs `onGetTimeout` cleanup/refund logic, resulting in unauthorized app state changes, double refunds, or forged/duplicate message delivery to production apps built on the SDK's `HyperApp` base contract. This is reachable by any unprivileged relayer submitting a `GetTimeoutMessage`, satisfying the "unauthorized app action" / "forged message delivery" impact category.

### Likelihood Explanation
`handleGetRequestTimeouts` is fully permissionless — any relayer can call it — and the only proof requirement is a valid non-membership proof anchored at *any* past height for which a state commitment exists and whose challenge period has elapsed. Since state commitments accumulate over time (`_stateCommitments[stateMachineId][height]`), an attacker only needs one earlier height, prior to the response being written, for which the non-membership proof is trivially constructible. No governance, admin, or malicious-node assumption is required — only a normal relayer flow with request/response/timeout timing manipulated.

### Recommendation
In `EvmHost.dispatchTimeOut(GetRequestTimeout, ...)`, add an explicit check that `_responseReceipts[commitment]` is unset before invoking `onGetTimeout()`, mirroring the Substrate-side guard in `modules/ismp/core/src/handlers/timeout.rs`. Additionally, delete/finalize `_requestCommitments[commitment]` in `dispatchIncoming(GetResponse)` once the response is successfully delivered, so a "known request" check can no longer succeed for an already-resolved request.

### Proof of Concept
1. Dispatch a `GetRequest` from an EVM chain (`EvmHost.dispatch(DispatchGet)`), producing `commitment`.
2. A consensus update makes a state commitment available at height `H1` where the destination's `ResponseReceipts` storage does not yet contain `commitment` (true for any height prior to actual delivery). Obtain and retain a non-membership proof at `H1`.
3. Deliver the GET response normally: `HandlerV2.handleGetResponses(...)` → `EvmHost.dispatchIncoming(GetResponse, relayer)`, which sets `_responseReceipts[commitment]` and calls `IApp.onGetResponse()` successfully. Note `_requestCommitments[commitment]` is left untouched (`meta.sender != address(0)`).
4. Call `HandlerV2.handleGetRequestTimeouts(host, GetTimeoutMessage{ timeouts: [request], height: H1, proof: <non-membership proof from step 2> })`.
   - `request.timeout() > state.timestamp` check passes (timeout already elapsed).
   - `meta.sender != address(0)` check passes (never cleared).
   - Non-membership proof against `H1`'s (stale) state root verifies successfully.
   - `EvmHost.dispatchTimeOut(GetRequestTimeout, meta, commitment)` executes, calling `IApp.onGetTimeout()` on the destination app — despite `onGetResponse()` having already been delivered in step 3.

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
