### Title
Emporium-min proof path leaves `rootHashHinkal` and `stealthAddressStructure` unconstrained by the ZK proof, allowing wallet actions to be authorized without cryptographic binding to the signer - ([File: contracts/CircomDataBuilder.sol])

### Summary
The Erigon bug is a case where a decoder accepts a payload whose extra bytes are never checked against the value that consensus actually commits to (trailing bytes exist but are outside the equality the protocol relies on). The structural analog here is `CircomDataBuilder.formInputEmporiumMin()`, which builds the ZK public-input vector for `Hinkal.transact()` when the external action is the Emporium action and `erc20TokenAddresses.length == 0`. Several `CircomData` fields that are otherwise part of the trust boundary (`rootHashHinkal`, the full `stealthAddressStructure`, and `getSignedMessageHash`) are silently dropped from both the public-input vector and the `calldataHash`, so the Groth16 proof no longer attests to them, yet `rootHashHinkal` is still acted on downstream by the contract.

### Finding Description
For the normal flow, `formInputNormal` → `formBasicInput` includes `rootHashHinkal`, `getSignedMessageHash(...)` (which itself binds `stealthAddressStructure`, `erc20TokenAddresses`, `amountChanges`, nullifiers/commitments and `calldataHash`), and the `stealthAddressStructure.H0x/H0y` fields directly in the public-input vector fed to `verifyProof`: [1](#0-0) 

However, when `externalActionData.externalActionId == HINKAL_EMPORIUM_ACTION_ID` and `erc20TokenAddresses.length == 0`, `formInputForCircom` dispatches to `formInputEmporiumMin`, which only sets three signals: [2](#0-1) 

This means `circomData.rootHashHinkal` and the whole `stealthAddressStructure` (`H1x`, `H1y`, `stealthAddress`, `H0x`, `H0y`) are never passed into the proof's public inputs on this path, and `getSignedMessageHash` (the only place `stealthAddressStructure` and `rootHashHinkal` are otherwise cryptographically bound) is never computed at all. Furthermore, none of these fields is included in `getHashedCalldata1`/`getHashedCalldata2`, which only cover `publicSignalCount, relay, emporiumMessage, externalActionData, slippageValues, hookData, encryptedOutputs, onChainEncryptedOutput, feeStructure, onChainCreation, originalSender, extraData`: [3](#0-2) 

Despite being unconstrained by both the proof and the calldata-integrity hash on this path, `circomData.rootHashHinkal` is still used by `Hinkal.transact()` to pass the "Root Hash Validation" check, and `circomData.stealthAddressStructure` remains part of the `CircomData` struct forwarded to `IExternalActionV2(...).runAction(circomData, ...)`, i.e. to the Emporium action / `HinkalWallet` logic: [4](#0-3) [5](#0-4) 

This breaks the intended equality "every field of `CircomData` that downstream code relies on must be bound to the proof via the public-input vector or via `calldataHash`". Here, `rootHashHinkal` (any historical root can be freely chosen, no proof tying it to the caller's actual leaves) and `stealthAddressStructure` (the value that identifies which shielded owner/signer authorized the action) are attacker-controlled and unverified in the Emporium-min branch, while the contract and the Emporium/HinkalWallet integration still treat them as authenticated.

### Impact Explanation
If `EmporiumUpgradeable`/`HinkalWallet` use `stealthAddressStructure` (or the derived `stealthAddress`) to determine which shielded owner's wallet/order the `emporiumMessage` is acting on behalf of, an attacker can submit a technically valid Groth16 proof for the Emporium-min path (no tokens, no nullifiers, no commitments are constrained on this branch) while attaching an arbitrary, proof-unbound `stealthAddressStructure`. This could let the attacker get a wallet operation executed/attributed to a shielded address they do not control and never had a matching signed proof for — i.e. "a wallet op not authorised by the prover or signer," which the scope rules classify as High impact.

### Likelihood Explanation
The root cause (the exact fields dropped from both the public-input vector and `calldataHash` on the `formInputEmporiumMin` branch) is directly confirmed in `contracts/CircomDataBuilder.sol`. However, I was not able to fully inspect `contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol` and `contracts/external-actions/emporium/HinkalWallet.sol` in this pass to confirm precisely how `stealthAddressStructure`/`emporiumMessage` are consumed to authorize a specific wallet action (e.g., whether a signature check elsewhere independently re-binds the stealth address to the message). This is required to fully confirm exploitability and should be verified before treating this as conclusively exploitable.

### Recommendation
Include `rootHashHinkal` and the full `stealthAddressStructure` (or at minimum `getSignedMessageHash`) in the public-input vector produced by `formInputEmporiumMin`, or fold these fields into `getHashedCalldata1`/`getHashedCalldata2` so that `circomData.calldataHash` cryptographically binds them, ensuring the Emporium-min path enforces the same authorization equality as `formInputNormal`.

### Proof of Concept
1. Craft a `CircomData` struct with `externalActionData.externalActionId == HINKAL_EMPORIUM_ACTION_ID`, `erc20TokenAddresses = []` (so `dimensionsCheck` requires empty `amountChanges`/`inputNullifiers`/`outCommitments`), and an arbitrary `stealthAddressStructure` and `rootHashHinkal` (any root previously inserted into the tree, from any user's deposit).
2. Generate a valid Groth16 proof for `formInputEmporiumMin`'s three signals (`emporiumMessage`, `timeStamp`, `calldataHash`); this proof does not need to correspond to the attacker's own `stealthAddressStructure`/`rootHashHinkal` since those are absent from the public input.
3. Call `Hinkal.transact()`; `performHinkalChecks` and `verifyProof` succeed because the unconstrained fields are outside `calldataHash`/`signedMessageHash`/public-input; `rootHashExists` passes because the chosen root is a real historical root (from any transaction).
4. `_externalTransact` forwards the full `circomData` (including the attacker-chosen `stealthAddressStructure`) to the Emporium/HinkalWallet action for execution — verification in `EmporiumUpgradeable.sol`/`HinkalWallet.sol` should be reviewed to confirm whether this results in an unauthorized wallet call being executed under an incorrect stealth identity.

    function formInputForCircom(
        uint256 chainId,
        address verifyingContract,
        CircomData calldata circomData
    ) internal pure returns (uint256[] memory) {
        if (
            circomData.externalActionData.externalActionId ==
            HINKAL_EMPORIUM_ACTION_ID &&
            circomData.erc20TokenAddresses.length == 0
        ) {
            return formInputEmporiumMin(circomData);
        } else {
            return formInputNormal(chainId, verifyingContract, circomData);
        }
    }

    function formInputEmporiumMin(
        CircomData calldata circomData
    ) internal pure returns (uint256[] memory input) {
        input = new uint256[](circomData.publicSignalCount);

        uint16 index = 0;

        input[index++] = circomData.emporiumMessage;

        input[index++] = circomData.timeStamp;
        input[index++] = circomData.calldataHash;
    }

    function formBasicInput(
        uint256 chainId,
        address verifyingContract,
        CircomData calldata circomData,
        uint256[] memory input,
        uint256 index,
        uint256 emporiumMessage
    ) internal pure returns (uint256[] memory) {
        // 1) First we list public inputs as in the body of the main template (not the one with exact dimensions)
        input[index++] = circomData.stealthAddressStructure.H1x;
        input[index++] = circomData.stealthAddressStructure.H1y;
        input[index++] = circomData.stealthAddressStructure.stealthAddress;
        input[index++] = emporiumMessage; // this is for Emporium message signature verification

        // 2) Then we list the private inputs as in the body of the main template
        input[index++] = circomData.rootHashHinkal;
        input[index++] = getSignedMessageHash(
            chainId,
            verifyingContract,
            circomData,
            emporiumMessage
        );

        for (uint16 i = 0; i < circomData.erc20TokenAddresses.length; i++) {
            input[index++] = uint256(
                uint160(circomData.erc20TokenAddresses[i])
            );
        }

        for (uint16 i = 0; i < circomData.amountChanges.length; i++) {
            require(
                circomData.amountChanges[i] < MAX_AMOUNT &&
                    circomData.amountChanges[i] > -1 * MAX_AMOUNT,
                "amount changed is too large"
            );

            input[index++] = circomData.amountChanges[i] >= 0
                ? uint256(circomData.amountChanges[i])
                : CIRCOM_P - uint256(-circomData.amountChanges[i]);
        }

        for (uint16 i = 0; i < circomData.inputNullifiers.length; i++) {
            for (uint16 j = 0; j < circomData.inputNullifiers[i].length; j++) {
                input[index++] = circomData.inputNullifiers[i][j];
            }
        }

        input[index++] = circomData.timeStamp;

        for (uint16 i = 0; i < circomData.outCommitments.length; i++) {
            for (uint16 j = 0; j < circomData.outCommitments[i].length; j++) {
                input[index++] = circomData.outCommitments[i][j];
            }
        }
        input[index++] = circomData.calldataHash;

        input[index++] = circomData.stealthAddressStructure.H0x;
        input[index++] = circomData.stealthAddressStructure.H0y;

        return input;
