## #Vulnerability found

### Title
Webhook `shop` (and `topic`) identity is not covered by the HMAC signature, enabling cross-tenant webhook spoofing - (File: `lib/shopify_api/webhooks/request.rb`)

### Summary
`ShopifyAPI::Webhooks::Registry.process` authenticates an inbound webhook solely by HMAC-verifying the raw request body, then hands the handler a `shop` (and `topic`) value taken from unauthenticated HTTP headers. Because those headers are never part of the signed material, an attacker who possesses *any* validly-signed `(body, hmac)` pair for the shared app secret can replay it while forging the `X-Shopify-Shop-Domain` header to impersonate a different merchant.

### Finding Description
`Webhooks::Request#to_signable_string` returns only `@raw_body`: [1](#0-0) 

`Utils::HmacValidator.validate` computes/compares the HMAC exclusively over that signable string: [2](#0-1) 

`Registry.process` treats a passing HMAC check as full authentication, then immediately trusts `request.shop` and `request.topic`, which are read straight from attacker-controlled headers, to build the metadata object handed to the app's webhook handler: [3](#0-2) [4](#0-3) 

The identity binding that should hold is:
`shop asserted by the request == shop covered by the verified signature`

but in this implementation:
`shop asserted by the request (X-Shopify-Shop-Domain header) != anything the HMAC actually signs (raw body only)`

Since the same app `client_secret` is used to sign webhooks for *every* shop that installs the app, any unprivileged attacker who installs the app on their own (attacker-controlled) shop can capture a genuine `(raw_body, hmac)` pair delivered to them for a legitimate topic, then replay that exact body+HMAC to the app's webhook endpoint with the `shop-domain` header rewritten to a victim shop. `HmacValidator.validate` still succeeds (the body/HMAC pair is genuinely valid), and `Registry.process` dispatches to the handler with `WebhookMetadata#shop` set to the victim's domain.

### Impact Explanation
This breaks the tenant boundary the gem is documented to provide via `Webhooks::Registry.process` (see `docs/usage/webhooks.md`), since host applications are expected to trust `WebhookMetadata#shop`/`#topic` as authenticated once HMAC validation passes. An attacker can inject attacker-chosen webhook payloads that are processed under a victim shop's identity — e.g., triggering `shop/redact` or `customers/redact` handling, order/customer data mutations, or any shop-scoped side effect keyed off `data.shop`, causing cross-tenant data corruption without ever needing the victim's or app's credentials.

### Likelihood Explanation
Moderate-to-high: the only prerequisite is the ability to install the app on any shop (including the attacker's own free/dev store) to obtain one legitimately-signed webhook body/HMAC pair, then send a forged HTTP POST with a spoofed `shop-domain` header to the app's public webhook endpoint. No access to `client_secret`, access tokens, or the victim's environment is required.

### Recommendation
Bind the shop (and ideally topic) identity into the verified material — e.g., have `HmacValidator`/`Webhooks::Request#to_signable_string` include the `shop-domain` (and `topic`) headers in the signed string, or independently verify that the request's shop domain corresponds to a shop with an active session/installation before dispatching to handlers, rather than trusting the header verbatim once only the body HMAC checks out.

### Proof of Concept
1. Attacker installs the target app on `attacker-shop.myshopify.com` and triggers a real event (e.g. `orders/create`), receiving a legitimate webhook POST with body `B` and header `X-Shopify-Hmac-Sha256: H` (valid HMAC over `B` using the app's shared secret).
2. Attacker sends a new POST to the app's webhook endpoint with the same raw body `B` and the same `X-Shopify-Hmac-Sha256: H`, but sets `X-Shopify-Shop-Domain: victim-shop.myshopify.com`.
3. `ShopifyAPI::Webhooks::Registry.process` calls `Utils::HmacValidator.validate`, which passes because it only hashes `@raw_body` (`lib/shopify_api/webhooks/request.rb:35-38`, `lib/shopify_api/utils/hmac_validator.rb:26-31`).
4. The handler receives `WebhookMetadata.new(topic: ..., shop: "victim-shop.myshopify.com", body: parsed(B), ...)` (`lib/shopify_api/webhooks/registry.rb:198-199`) and processes attacker-controlled data as if it originated from the victim's shop.
