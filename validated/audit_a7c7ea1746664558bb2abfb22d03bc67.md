Audit Report

## Title
Cross-user response hijacking via attacker-controlled `MessageID` colliding with a victim's in-flight legacy WebAPI trigger request - ([File: core/services/gateway/handlers/capabilities/handler.go])

## Summary
The gateway's legacy WebAPI trigger handler stores the caller's response `callback` in the shared `h.savedCallbacks` map keyed solely by the client-supplied `MessageID`, with no uniqueness or ownership check. Because the DON response is routed back purely by looking up this map with the same `MessageID`, an unprivileged attacker who submits a request using the same `MessageID` as a victim's still-pending request can overwrite the victim's saved callback and receive the victim's DON response, while the victim's own request stalls until it times out.

## Finding Description
`gateway.ProcessRequest` decodes the request and derives `msg.Body.MessageID` directly from the caller-supplied JSON-RPC `id` field (`msg.Body.MessageID = request.ID` in `JSONRPCCodec.DecodeJSONRequest`, `core/services/gateway/api/jsonrpccodec.go` L26-35), only bounding its length (`len(jsonRequest.ID) > 200`) [1](#0-0) . `msg.Validate()` checks structural properties (signature length, ID length/format) and extracts a `Sender` from the signature, but performs no allowlist or duplicate-ID check [2](#0-1) .

Inside `handler.HandleLegacyUserMessage`, the caller's `callback` is stored unconditionally into the shared map keyed by `msg.Body.MessageID`, silently overwriting any existing entry for that key; the code explicitly has a `TODO: apply allowlist and rate-limiting here` that has not been implemented [3](#0-2) .

When a DON node responds, `handleWebAPITriggerMessage` looks up and deletes the entry solely by `msg.Body.MessageID` and forwards the response to whatever callback is currently registered under that key, regardless of which caller originally owns it [4](#0-3) .

This differs from the newer `OutgoingConnectorHandler`, which explicitly rejects duplicate in-flight IDs (`"duplicate message received for ID"`), confirming that duplicate-ID protection is a recognized pattern elsewhere in the codebase but is absent in this legacy handler [5](#0-4) .

## Impact Explanation
This maps to the in-scope "cross-user response corruption" impact class: an unprivileged caller can receive another caller's DON trigger response payload, and the victim's original HTTP call to the gateway stalls until `pruneCallbacks`/`CallbackMaxAgeSec` (default 120s) expires it, returning `api.RequestTimeoutError` instead of the real response [6](#0-5) [7](#0-6) . No allowlist, rate-limiter, or per-caller binding currently prevents this, as confirmed by the unimplemented TODO in `HandleLegacyUserMessage`.

## Likelihood Explanation
Any unprivileged client that can send a legacy WebAPI trigger message to the gateway can construct an arbitrary `MessageID` (bounded only by length ≤200 and non-null-terminated), since `msg.Validate()` performs no uniqueness or allowlist check before the ID is used as the sole key. Exploitation requires the attacker to know or guess the victim's exact in-flight `MessageID` and race it before the DON node responds — a real but narrower precondition than a fully deterministic exploit, since it depends on ID predictability/observability and timing. Nonetheless, no additional authentication or per-caller binding exists at this layer to block a same-window collision, so the root cause is concretely present and exploitable given a known or guessable ID.

## Recommendation
Bind the `savedCallbacks` key to something that cannot be forged or collided across independent callers — e.g., derive the internal key from a gateway-generated nonce combined with `msg.Body.Sender` (from `msg.Validate()`'s signature-derived signer), or reject/error on a duplicate `MessageID` for an already-pending request instead of silently overwriting it, mirroring the existing `OutgoingConnectorHandler.handleSingleNodeRequest` duplicate-ID check.

## Proof of Concept
1. Victim sends a legacy WebAPI trigger request with `MessageID = "X"`; `HandleLegacyUserMessage` stores `h.savedCallbacks["X"] = victimCallback` and forwards to all DON members (`core/services/gateway/handlers/capabilities/handler.go` L411-419).
2. Before the DON responds, attacker sends their own signed legacy request reusing `MessageID = "X"`; this overwrites `h.savedCallbacks["X"] = attackerCallback`.
3. The DON node's response for `MessageID = "X"` arrives; `handleWebAPITriggerMessage` looks up `savedCallbacks["X"]`, finds the attacker's callback, and delivers the victim's response there (`core/services/gateway/handlers/capabilities/handler.go` L148-161).
4. The victim's original HTTP request blocks in `callback.Wait(ctx)` until `CallbackMaxAgeSec` elapses and returns a timeout error (`core/services/gateway/gateway.go` L281-288).
A Go integration test can simulate two concurrent `ProcessRequest` calls with identical `id` values against a mock DON connection manager to reproduce steps 1-4 deterministically.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageID) == 0 || len(m.Body.MessageID) > MessageIDMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageID, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonID) == 0 || len(m.Body.DonID) > MessageDonIDMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonID, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageID]
	delete(h.savedCallbacks, msg.Body.MessageID)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JSONRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
}
