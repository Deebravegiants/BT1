### Title
Unchecked scaled-value multiplication can permanently freeze a lending market - ([File: common/src/rates/index.rs](common/src/rates/index.rs))

### Summary
Interest accrual multiplies total scaled supply and debt by their RAY indexes without bounding the resulting position value. Once either product exceeds `i128::MAX`, every subsequent accrual reverts, freezing withdrawals, repayments, liquidations, and other operations that first synchronize the market. [1](#0-0) [2](#0-1) 

### Finding Description
`update_supply_index` calculates `supplied * old_index` through `Ray::mul`, which panics when the quotient cannot fit in `i128`. [1](#0-0) [3](#0-2)  Similarly, `calculate_supplier_rewards` computes old and new total debt as `borrowed * borrow_index`, so a sufficiently large debt book can overflow before the borrow-index ceiling is reached. [2](#0-1) 

The fixed-point implementation correctly detects overflow and raises `MathOverflow`, but the market has no recovery path that skips accrual. [4](#0-3)  `global_sync` is executed before market mutations and delegates each accrual chunk to `accrue_step`, so the overflowing total-value calculation runs on every subsequent operation. [5](#0-4)  `update_indexes` is permissionless, meaning any address can trigger the accrual that first reaches the overflow boundary. [6](#0-5) 

### Impact Explanation
A sufficiently large market at high utilization can transition from valid state into a permanently frozen state. [7](#0-6)  The existing boundary test demonstrates that `withdraw`, `repay`, and index updates all revert with `MathOverflow` after the RAY-denominated position value exceeds `i128::MAX`. [8](#0-7) 

This permanently freezes supplier principal and prevents borrowers or liquidators from settling debt, constituting permanent freezing of user funds and protocol accounting. [9](#0-8) 

### Likelihood Explanation
The trigger requires a very large token position and enough accrued interest for scaled-position value to cross the `i128` boundary. [10](#0-9)  These bounds are not enforced directly because supply caps constrain scaled shares, while the vulnerable product also includes future index growth. [11](#0-10) 

An unprivileged participant can establish the large supply and borrow positions through `supply` and `borrow`, and anyone can later invoke `update_indexes` to activate the failure once market arithmetic crosses the boundary. [12](#0-11) [13](#0-12)  The required scale makes exploitation economically demanding, but the resulting denial affects all market users rather than only the attacker.

### Recommendation
Track or bound absolute RAY position values independently of share caps before allowing supply or borrow growth. Accrual should also use saturating position-value calculations or a bounded recovery mode that permits repayment and withdrawal while blocking further interest accrual. At minimum, enforce a market-value cap strictly below the product that can overflow `scaled * index`, including future index headroom up to `MAX_BORROW_INDEX_RAY` and `MAX_SUPPLY_INDEX_RAY`. [14](#0-13) [15](#0-14) 

### Proof of Concept
The repository’s boundary test constructs a one-billion-token, 18-decimal market, supplies the principal, borrows 98% of it, and advances accrual until index synchronization fails with `MathOverflow`. [16](#0-15)  It then verifies that the borrow-index cap did not protect the market and that both withdrawal and repayment remain blocked by the same overflow. [17](#0-16)

pub fn update_supply_index(env: &Env, supplied: Ray, old_index: Ray, rewards_increase: Ray) -> Ray {
    if supplied == Ray::ZERO || rewards_increase == Ray::ZERO {
        return old_index;
    }

    let total_supplied_value = supplied.mul(env, old_index);

    if total_supplied_value == Ray::ZERO {
        return old_index;
    }

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);

fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {

    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

            years <= 40,
