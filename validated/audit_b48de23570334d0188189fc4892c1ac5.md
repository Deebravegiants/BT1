## Title
CORS origin allowlist bypass via unanchored suffix matching in Gateway HTTP server - (File: core/services/gateway/network/httpserver.go)

## Summary
The Gateway HTTP server's wildcard CORS check in `isAllowedOrigin` strips the `*.` prefix from a configured allowed origin (e.g. `*.ethereum.org` → `ethereum.org`) and then only checks `strings.HasSuffix(originHost, allowedHost)`, without requiring a `.` label boundary before the match. This lets an attacker-registered domain like `evilethereum.org` satisfy a wildcard rule intended only for subdomains of `ethereum.org`, causing the server to echo the attacker's origin into `Access-Control-Allow-Origin` and allowing cross-origin reads of gateway responses. [1](#0-0) 

## Finding Description
`isAllowedOrigin` parses both the incoming `Origin` header and each configured `CORSAllowedOrigins` entry via `splitURL`, which correctly uses `url.Parse` and `net.SplitHostPort` for scheme/host/port extraction. [2](#0-1)  After exact-match and scheme/port checks, the wildcard branch strips the `*.` prefix from `allowedHost` and performs a bare `strings.HasSuffix(originHost, allowedHost)` check with no boundary enforcement:

```go
if strings.HasPrefix(allowedHost, "*.") {
    allowedHost = allowedHost[2:]
    if strings.HasSuffix(originHost, allowedHost) {
        return true
    }
}
``` [1](#0-0) 

For an allowed entry `*.ethereum.org`, `allowedHost` becomes `ethereum.org`, and `strings.HasSuffix("evilethereum.org", "ethereum.org")` returns `true` even though `evilethereum.org` is not a subdomain of `ethereum.org`. The result flows directly into the response headers in `handleRequest`, which echoes the raw `Origin` value back as `Access-Control-Allow-Origin` whenever `isAllowedOrigin` returns true: [3](#0-2) . There is no other validation layer (no separate allowlist normalization, no host-label parsing) that would catch this — the flaw is squarely in the wildcard suffix comparison itself.

## Impact Explanation
This is a genuine CORS allowlist bypass: an operator who configures a wildcard entry such as `*.ethereum.org` to scope browser access to their own subdomains inadvertently also authorizes any domain ending in the literal bytes `ethereum.org` without a dot separator (e.g. `evilethereum.org`, `notethereum.org`). A page hosted on such an attacker-controlled domain can issue cross-origin requests to the Gateway and, because the server sets a permissive `Access-Control-Allow-Origin` matching the attacker's exact origin, read the JSON-RPC response body that Same-Origin Policy would otherwise block. This maps to the in-scope "allowlist bypass" / cross-origin response exposure impact category for the Gateway HTTP server, which is directly reachable by unauthenticated internet clients.

## Likelihood Explanation
No authentication or elevated role is required — only that the operator has enabled CORS with at least one wildcard entry, a supported and plausible configuration (the codebase's own tests exercise wildcard entries, e.g. `TestHTTPServer_HandleRequest_CORSEnabled_FromAllowedOriginWildcards` in `core/services/gateway/network/httpserver_test.go`). Registering a domain that ends in the target suffix without a preceding dot is cheap and realistic for an attacker. The victim's browser automatically sends the `Origin` header on cross-origin requests, and the attacker fully controls the origin of their own malicious page, making this a repeatable, low-effort bypass rather than a hypothetical one.

## Recommendation
Require a label boundary before the suffix match:
```go
if strings.HasPrefix(allowedHost, "*.") {
    suffix := allowedHost[2:]
    if originHost == suffix || strings.HasSuffix(originHost, "."+suffix) {
        return true
    }
}
```
This preserves legitimate subdomain matches (`remix.ethereum.org` matches `*.ethereum.org`) while rejecting suffix-colliding domains like `evilethereum.org`.

## Proof of Concept
1. Configure the Gateway HTTP server with `CORSEnabled: true` and `CORSAllowedOrigins: []string{"https://*.ethereum.org"}`.
2. Send `POST` to the configured path with header `Origin: https://evilethereum.org`.
3. Observe the response includes `Access-Control-Allow-Origin: https://evilethereum.org`, since `isAllowedOrigin` computes `originHost = "evilethereum.org"`, `allowedHost = "ethereum.org"`, and `strings.HasSuffix("evilethereum.org", "ethereum.org")` is `true`. [4](#0-3) 
4. A unit test extending the existing `TestHTTPServer_HandleRequest_CORSEnabled_FromAllowedOriginWildcards` in `core/services/gateway/network/httpserver_test.go` with the origin `https://evilethereum.org` against allowed `https://*.ethereum.org` would confirm the bypass by asserting the response header is incorrectly set.

func (s *httpServer) isAllowedOrigin(origin string) bool {
	originScheme, originHost, originPort, err := s.splitURL(origin)
	if err != nil {
		s.lggr.Debug("error parsing origin URL", err)
		return false
	}
	for _, allowed := range s.config.CORSAllowedOrigins {
		// probably better to do this once when server starts and store it in a map
		// this is an easier solution so we don't have to apply more changes to the code
		// just need to be careful when specifying allowed origins in the config file
		allowedScheme, allowedHost, allowedPort, err := s.splitURL(allowed)
		if err != nil {
			s.lggr.Debug("error parsing allowed origin URL", err)
			continue
		}
		// skip if the scheme doesn't match at all
		if originScheme != allowedScheme {
			continue
		}
		// skip if the port doesn't match at all
		if originPort != allowedPort {
			continue
		}
		// check for exact host match (e.g., remix.com)
		if originHost == allowedHost {
			return true
		}
		// check for wildcard host match (e.g., *.remix.com)
		if strings.HasPrefix(allowedHost, "*.") {
			allowedHost = allowedHost[2:]
			if strings.HasSuffix(originHost, allowedHost) {
				return true
			}
		}
	}
	return false
}
