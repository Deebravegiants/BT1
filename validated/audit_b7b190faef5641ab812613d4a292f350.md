## Title
Stale `TombStone.original_owner` allows a prior owner to reclaim an object after legitimate ownership transfer and burn - (File: `aptos-move/framework/aptos-framework/sources/object.move`)

### Summary
`object::burn()` creates a `TombStone` recording the caller as `original_owner` but does **not** transfer the object away from the caller (unlike the legacy `burn_object_with_transfer`). If the object is later transferred to a new owner through the ordinary transfer path (`transfer`/`transfer_raw`), the stale `TombStone` is never cleared. When the *new*, legitimate owner subsequently sends the object to the well-known `BURN_ADDRESS` (a normal, expected disposal action), `unburn()` grants reclaim rights to the address recorded in the stale `TombStone` — the original, no-longer-owning account — rather than to the current owner. This lets a prior owner steal back an object (and any asset it custodies, e.g. an NFT, a fungible-asset-holding object, etc.) that a later owner deliberately discarded.

### Finding Description
`burn()` only adds a `TombStone`, keeping `ObjectCore.owner` unchanged: [1](#0-0) 

Ordinary transfers (`transfer`, `transfer_call`, `transfer_raw`) go through `transfer_raw_inner`, which updates `ObjectCore.owner` but never inspects or removes an existing `TombStone`: [2](#0-1) 

Only the `TransferRef`-based path explicitly clears a pre-existing `TombStone` before changing ownership: [3](#0-2) 

`unburn()` decides who may reclaim a burnt object based purely on `ObjectCore.owner` and the (possibly stale) `TombStone.original_owner`: [4](#0-3) 

Because ordinary transfers don't clear the `TombStone`, an object can carry a `TombStone.original_owner` value that no longer corresponds to any prior legitimate custody chain by the time it is actually sent to `BURN_ADDRESS`. `unburn()`'s second branch (`object_core.owner == BURN_ADDRESS`) then authorizes the *stale* address to reclaim the object regardless of who actually sent it to the burn address.

### Impact Explanation
This breaks the object ownership/custody invariant that only the account with a legitimate, up-to-date claim (current owner or holder of a `TransferRef`/`LinearTransferRef`) can control or reclaim an object. A former owner who "soft burns" an object they intend to sell/transfer can, at any later time, reclaim that object — along with anything it holds (NFT, fungible asset store object, code object, etc.) — once the legitimate new owner discards it to `BURN_ADDRESS`, a common and expected disposal action. This is an unauthorized owner reassignment / theft of object-held value, directly affecting custody guarantees provided by `aptos_framework::object`, which underlies fungible assets, digital assets/NFTs, and other object-based custody on Aptos mainnet.

### Likelihood Explanation
Exploitation requires: (1) an attacker owns an object and calls `burn()` on it, (2) the attacker then transfers the object away via an ordinary transfer (a normal action when selling/gifting an object — the attacker does not need to reveal that they pre-burned it), and (3) the new owner independently decides to send the object to `BURN_ADDRESS` (a standard, well-documented disposal pattern in the object model). No special privileges are needed by the attacker; they only need to perform two entry-function calls on an object they legitimately (at that time) own before disposing of it. This is straightforward to set up and does not depend on any privileged role, making it a realistic and repeatable attack against any marketplace, transfer, or dead-address burn flow that trusts `unburn()`'s recovery guarantee.

### Recommendation
Clear any existing `TombStone` whenever ownership actually changes via the ordinary transfer path (`transfer_raw_inner`), the same way `transfer_with_ref` already does. Alternatively, disallow creating/keeping a stale `TombStone` across an ownership change, or have `unburn()`'s `BURN_ADDRESS` branch validate that `original_owner_addr` was indeed the immediately preceding owner (e.g., record the owner at burn-address-transfer time rather than relying on a value set arbitrarily earlier).

### Proof of Concept
```
// Alice owns NFT object O.
object::burn(&alice, O);                       // TombStone{original_owner: alice}; O.owner stays alice
object::transfer(&alice, O, bob_addr);          // ordinary transfer; O.owner = bob; TombStone NOT cleared
// Bob cannot re-burn (EOBJECT_ALREADY_BURNT), but can freely use/transfer O.
object::transfer(&bob, O, BURN_ADDRESS);        // Bob intentionally discards O; O.owner = BURN_ADDRESS
object::unburn(&alice, O);                      // branch: owner == BURN_ADDRESS
                                                 // TombStone.original_owner (alice) == caller (alice) -> passes
                                                 // transfer_raw_inner(O, alice) -> O.owner = alice
// Alice has reclaimed O despite having sold it to Bob and having no claim
// at the time Bob discarded it.
```

    /// Allow origin owners to reclaim any objects they previous burnt.
    public entry fun unburn<T: key>(
        original_owner: &signer,
        object: Object<T>,
    ) {
        let object_addr = object.inner;
        assert!(exists<TombStone>(object_addr), error::invalid_argument(EOBJECT_NOT_BURNT));

        // The new owner of the object can always unburn it, but if it's the burn address, we go to the old functionality
        let object_core = borrow_global<ObjectCore>(object_addr);
        if (object_core.owner == signer::address_of(original_owner)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object_addr);
        } else if (object_core.owner == BURN_ADDRESS) {
            // The old functionality
            let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
            assert!(
                original_owner_addr == signer::address_of(original_owner),
                error::permission_denied(ENOT_OBJECT_OWNER)
            );
            transfer_raw_inner(object_addr, original_owner_addr);
        } else {
            abort error::permission_denied(ENOT_OBJECT_OWNER);
        };
    }
