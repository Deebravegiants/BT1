Audit Report

## Title
Unauthenticated-role disclosure of External Initiator secrets via `GET /v2/external_initiators` - (File: core/web/router.go)

## Summary
The `GET /v2/external_initiators` route registers `eia.Index` with only `paginatedRequest(...)`, without any `auth.RequiresEditRole`/`RequiresRunRole`/`RequiresAdminRole` wrapper, while the sibling `POST`/`DELETE` routes for the same resource are wrapped in `auth.RequiresEditRole`. Any caller who passes the outer `authv2` group's `auth.Authenticate` (which accepts either a valid session, a valid API token, or `AuthenticateExternalInitiator`) can hit `Index` regardless of role, and the response includes each External Initiator's `AccessKey` and `OutgoingToken` in plaintext.

## Finding Description
The route table shows the asymmetry directly: [1](#0-0) 

The outer group only requires successful authentication via token, session, or (per `AuthenticateExternalInitiator`) external-initiator credentials — the latter explicitly sets the caller's role to `UserRoleRun`: [2](#0-1) 

`RequiresEditRole` explicitly excludes `UserRoleView` and `UserRoleRun`: [3](#0-2) 

Since `Index` has no role wrapper at all, a `UserRoleView` or `UserRoleRun` (including an External Initiator authenticating via `AuthenticateExternalInitiator`) principal can call it successfully, whereas `Create`/`Destroy` would reject them.

`Index` fetches all External Initiators and serializes them via `presenters.NewExternalInitiatorResource`: [4](#0-3) 

That presenter includes `AccessKey` and `OutgoingToken` in the JSON response for every record: [5](#0-4) 

`OutgoingToken` is a real secret generated at creation (`utils.NewSecret(...)`), used by the node to authenticate outbound calls to the initiator's URL: [6](#0-5) 

The write endpoints for this resource intentionally require Edit role or higher, but the read/list endpoint that discloses the same secrets has no role check — only a valid authentication method (including the low-privilege Run-role external-initiator authentication path). This is an inconsistency in role enforcement that allows a lower-privileged authenticated caller to read secrets a higher-privileged action is required to create.

## Impact Explanation
An authenticated caller with `UserRoleView`, `UserRoleRun` (or an external initiator's own credentials, which the code explicitly maps to `UserRoleRun`) can retrieve `AccessKey` and `OutgoingToken` for every configured External Initiator on the node, despite lacking the Edit role required to manage that resource. This maps to an in-scope "key/secret exfiltration" and "node API role bypass" impact category — a lower-privileged authenticated identity gains access to secrets that the write-path role gating implies should be restricted to Edit-role principals. The severity is bounded: it requires the attacker to already hold some valid node credential (session, API token, or external-initiator credential); it does not allow an entirely unauthenticated actor to read secrets.

## Likelihood Explanation
Exploitability is straightforward for anyone holding any valid authenticated identity on the node — a View-role user, a Run-role user, or an External Initiator authenticating with its own AccessKey/Secret via `AuthenticateExternalInitiator`. No special timing or race condition is needed; a single `GET` request suffices, and it is repeatable at will. The main constraint is that the attacker must already have some node-issued credential (even a low-privilege one), which is a realistic multi-tenant/multi-role node-operator scenario where View/Run credentials are handed to less-trusted consumers or where External Initiators are deployed as semi-trusted third-party callback services.

## Recommendation
Wrap the `Index` handler in the same or a comparably strict role check used for `Create`/`Destroy`, e.g. `authv2.GET("/external_initiators", auth.RequiresEditRole(paginatedRequest(eia.Index)))`, and/or remove `AccessKey`/`OutgoingToken` from `ExternalInitiatorResource`, exposing full credentials only once, at creation time, via `ExternalInitiatorAuthentication` (as is already the pattern for `Create`).

## Proof of Concept
1. Create (as an Edit/Admin user) at least one External Initiator via `POST /v2/external_initiators`, noting it stores `AccessKey`/`OutgoingToken` server-side.
2. As a separate, lower-privileged identity — e.g., a user/API token with `UserRoleView` or `UserRoleRun`, or by authenticating as the External Initiator itself using its `X-Chainlink-EA-AccessKey`/`X-Chainlink-EA-Secret` headers (`AuthenticateExternalInitiator`) — issue `GET /v2/external_initiators`.
3. Observe the JSON response includes `accessKey` and `outgoingToken` fields for every registered External Initiator (per `presenters.ExternalInitiatorResource`), even though the same identity would receive `401 Unauthorized` when calling `POST`/`DELETE /v2/external_initiators` due to `auth.RequiresEditRole`.
4. A Go handler test asserting `Index` succeeds for a `UserRoleView`/`UserRoleRun` context while `Create`/`Destroy` return 401 for the same context would confirm the inconsistency deterministically.

```go
// RequiresEditRole extracts the user object from the context, and asserts the user's role is at least
// 'edit'
func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}
```

```go
func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}
```

```go
// NewExternalInitiator generates an ExternalInitiator from an
// auth.Token, hashing the password for storage
func NewExternalInitiator(
	eia *auth.Token,
	eir *ExternalInitiatorRequest,
) (*ExternalInitiator, error) {
	salt := utils.NewSecret(utils.DefaultSecretSize)
	hashedSecret, err := auth.HashedSecret(eia, salt)
	if err != nil {
		return nil, pkgerrors.Wrap(err, "error hashing secret for external initiator")
	}

	return &ExternalInitiator{
		Name:           strings.ToLower(eir.Name),
		URL:            eir.URL,
		AccessKey:      eia.AccessKey,
		HashedSecret:   hashedSecret,
		Salt:           salt,
		OutgoingToken:  utils.NewSecret(utils.DefaultSecretSize),
		OutgoingSecret: utils.NewSecret(utils.DefaultSecretSize),
	}, nil
}
```
