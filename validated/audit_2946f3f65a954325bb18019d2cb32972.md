### Title
Missing cross-frame identity-continuity check allows biometric captures to blend two subjects' data - (File: src/plans/biometric_capture/multi_wavelength.rs, src/plans/biometric_capture/mod.rs)

### Summary
`biometric_capture::Plan::run` (and the `multi_wavelength::Plan::run` wrapper that calls it) assembles the left-eye IR/RGB frames, the right-eye IR/RGB frames, and the self-custody face frame from three independently-gated objectives, with no check that all frames originate from the same physical subject. An unprivileged party can therefore alternate two different people in front of the Orb during the capture window and produce a single `Capture` struct that blends biometric data from two distinct identities.

### Finding Description
`biometric_capture::mod.rs::Plan::run` executes objectives sequentially (`set_next_objective`, driven by `run_check`) — first for one eye side, then the other — and separately tracks the best-scoring self-custody face frame via `handle_face_identifier` [1](#0-0) . Each objective's acceptance criteria only checks IR-Net score/brightness and left/right eye side (`perceived_side`) — never whether the subject in objective N is the same as the subject in objective N-1: [2](#0-1) 

The face self-custody candidate frame is selected purely by best `FaceIdentifier` validity score across the whole capture window, independent of which side objective is active: [3](#0-2) 

`into_capture` then merges `left_ir`, `left_rgb`, `right_ir`, `right_rgb`, and `self_custody_candidate_rgb` into a single `Capture` with no identity-binding assertion between them: [4](#0-3) . `is_success`/`failure_feedback` gate only on presence of each slot, not on identity consistency: [5](#0-4) .

`multi_wavelength::Plan::run` layers on top of this same `biometric_capture::Plan`, adding 940nm/740nm frames per side keyed only by `target_left_eye`/`target_740nm`, again with no subject-continuity check, and merges them into the already-assembled (and potentially mixed-identity) `Capture`: [6](#0-5) , [7](#0-6) .

Because there is a deliberate delay between eye captures (`delay_between_eye_captures`, set in `run_check`) [8](#0-7) , and the loop simply proceeds to the next objective whenever a sharp/valid frame is found for the currently active side, a subject swap between the left-eye objective and the right-eye objective (or between eye capture and the concurrently-running face self-custody scoring) will not be detected or rejected anywhere in this code path.

### Impact Explanation
A resulting `Capture` can contain the left iris of person A and the right iris of person B (and/or a face frame from either), which would be signed and uploaded as if it were one person's biometric record. This corrupts uniqueness guarantees at the core of the Orb's identity system — matching the Immunefi impact category "biometric record blending two identities, corrupting uniqueness guarantees." Downstream signing/upload logic (outside this file) is not shown to perform any post-hoc identity-consistency verification on the assembled `Capture` before it is committed, so nothing in the code inspected here stops propagation of a mixed-identity record.

### Likelihood Explanation
Exploitation requires only physical presence in front of the Orb sensor during the capture window and coordination of the timing of a subject swap relative to the objective transition (left→right eye, or during face scoring) — no privileged access, keys, or tampering needed. The capture loop's explicit delay between eye objectives (`delay_between_eye_captures`) gives an attacker a predictable window in which to swap. This is repeatable on every signup attempt since the check (or lack thereof) is deterministic code, not a rare race condition.

### Recommendation
Add an identity-continuity check across the objectives within a single `biometric_capture::Plan` run — e.g., compare face/iris embeddings (or at minimum RGB-Net/IR-Net facial landmark consistency, gaze/pose trajectory continuity, or distance/tracking continuity from the `distance`/`mirror`/eye-tracker agents) between the left-eye, right-eye, and self-custody face frames before accepting them into a single `Capture`. If continuity cannot be established (e.g., large discontinuity in tracked position, a los-of-track event from the eye tracker, or mismatched face-identifier embedding), reset the affected slots (`left_ir`/`left_rgb`/`right_ir`/`right_rgb`/`self_custody_candidate_rgb`) and restart the corresponding objective rather than carrying over stale/mismatched data.

### Proof of Concept
Integration test plan (to be run against `biometric_capture::Plan`/`multi_wavelength::Plan::run` with a mocked `Orb`/camera/IR-Net/RGB-Net/FaceIdentifier broker):
1. Feed IR-Net/RGB-Net frame sequence for "Subject A" while `target_left_eye == true`, producing a valid sharp left iris (`left_ir`, `left_rgb` populated) and a high-score self-custody face frame from Subject A.
2. During the `delay_between_eye_captures` window (after `run_check` advances the objective to `target_left_eye == false`), swap the physical/mocked subject to "Subject B" and feed frames satisfying the right-eye objective's IR-Net/RGB-Net acceptance criteria.
3. Let `Plan::run` complete and call `into_capture`/`run_post`.
4. Assert (currently failing, demonstrating the bug): the resulting `Capture.eye_left` and `Capture.eye_right` (and/or `face_self_custody_candidate`) originate from different embeddings/identities, and that no error/rejection was raised despite mixed identities — i.e., `Output.capture` is `Some` even though frames came from two different subjects, proving the missing continuity check.

    pub(crate) async fn run_check(&mut self, orb: &mut Orb) -> Result<bool> {
        if let Some(mirror_offset) = orb.mirror_offset {
            self.mirror_offsets.push(mirror_offset);
        }
        if self.timed_out {
            tracing::info!("Biometric capture timeout");
            return Ok(true);
        }
        if !self.set_next_objective(orb).await? {
            dd_incr!("main.count.signup.during.biometric_capture.both_eye_captured");
            tracing::info!("All objectives achieved");
            orb.ui.biometric_capture_progress(1.1);
            return Ok(true);
        }
        self.valid_capture_after = Instant::now() + self.delay_between_eye_captures;
        Ok(false)
    }

    async fn perform_multi_wavelength(&mut self, orb: &mut Orb) -> Result<()> {
        orb.disable_ir_net();
        orb.disable_ir_auto_focus();
        orb.disable_eye_pid_controller();

        tracing::info!("Multi-wavelength extension: capturing 940nm");
        orb.set_ir_wavelength(IrLed::L940).await?;
        orb.set_ir_duration(1500)?;
        self.state = State::ExtraWavelength {
            timer: Box::pin(time::sleep(AUTO_EXPOSURE_WAIT_TIME)),
            target_left_eye: self.biometric_capture.target_left_eye,
            target_740nm: false,
        };
        orb.run(self).await?;

        tracing::info!("Multi-wavelength extension: capturing 740nm");
        orb.set_ir_wavelength(IrLed::L740).await?;
        orb.set_ir_duration(200)?;
        self.state = State::ExtraWavelength {
            timer: Box::pin(time::sleep(AUTO_EXPOSURE_WAIT_TIME)),
            target_left_eye: self.biometric_capture.target_left_eye,
            target_740nm: true,
        };
        orb.run(self).await?;

        orb.enable_ir_net().await?;
        orb.enable_ir_auto_focus()?;
        orb.enable_eye_pid_controller()?;
        self.state = State::Normal;
        Ok(())
    }
