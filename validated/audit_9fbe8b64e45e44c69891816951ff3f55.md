### Title
Accrued debt/supply value overflow permanently freezes a high-utilization market before the borrow-index cap engages - (File: common/src/rates/simulate.rs)

### Summary
The `detect-character-encoding` advisory is a "crash on unmatched input" class: an input domain edge produces a fatal error instead of a handled result. The analog in XOXNO Lending is the RAY-domain value ceiling in accrual: `accrue_step` calls `scaled_to_original(env, borrowed, borrow_index)` before applying the `MAX_BORROW_INDEX_RAY` clamp, so once `borrowed * borrow_index` exceeds `i128::MAX`, every accrual panics with `GenericError::MathOverflow`. Because `interest::global_sync` runs accrual first on every mutation, repay, withdraw, liquidation, and `update_indexes` all fail permanently for that market — user funds are frozen with no recovery path.

### Finding Description
`accrue_step` computes utilization from `borrowed_original`/`supplied_original` via `scaled_to_original` before calling `update_borrow_index`, which is the only place the index ceiling is enforced [1](#0-0) . The index clamp caps the *index* at `1e36` but not the *product* `scaled_shares * index`, which must fit `i128` [2](#0-1) . The widened `I256` path in `fp_core` still panics when the result does not fit `i128` [3](#0-2) . `global_sync` invokes `accrue_chunk` unconditionally on any elapsed time for every market mutation [4](#0-3) . The repo's own harness test demonstrates the freeze: after a whale market sits at ~98% utilization for a few years on the XLM rate curve, `update_indexes`, `withdraw`, and `repay` all revert with `MathOverflow` while `borrow_index < MAX_BORROW_INDEX_RAY` — the cap never engages [5](#0-4) . The docs acknowledge the gap: "valid caps and bounded indexes do not guarantee that future accrual fits. Value overflow can occur before the index ceiling and block repayment/withdrawal" [6](#0-5) .

### Impact Explanation
Permanent freezing of funds for every supplier and borrower in the affected market. Withdrawals, repayments, liquidations, and bad-debt cleanup all route through `global_sync` first, so no verb can execute once the product overflows; even positions in *other* markets of the same pool entrypoint batch are unaffected only if they don't touch the frozen market. Suppliers cannot exit, borrowers cannot repay, liquidators cannot clear the unhealthy debt — the market's cash is permanently locked in the pool contract.

### Likelihood Explanation
Reachable by unprivileged `supply`/`borrow` calls: any whale can supply a large balance (up to ~170 billion whole tokens per the token-to-RAY domain) and a borrower can drive utilization near the steep segment of the rate curve; no privileged action is needed. It requires a very large market and sustained high utilization over years at typical rates (fewer at the 200% APR cap), so likelihood is moderate-low — but it is deterministic, irreversible once crossed, and there is no alarm or circuit breaker before the cliff.

### Recommendation
Bound the exceptional condition instead of trapping: (a) in `accrue_step`, clamp `borrowed_original`/`supplied_original` via the existing `mul_div_floor_saturating` path or cap effective index growth when `borrowed * new_borrow_index` would exceed `i128::MAX`, so accrual degrades to "no further interest" rather than panicking; or (b) make `update_borrow_index` engage the cap based on the post-multiplication *value domain* of the market's outstanding scaled debt. At minimum, add an early-warning view emitting remaining headroom (`i128::MAX / index`) so integrators can force `update_indexes`/`recapitalize` before the cliff.

### Proof of Concept
`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-361` (`a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap`): supply `BILLION * 10^18` BIG18 (18 decimals), borrow 98% of it, advance time in 1-year steps calling `update_indexes`; accrual eventually reverts with `MathOverflow`, and subsequent `withdraw` and `repay` calls revert identically while `borrow_index < MAX_BORROW_INDEX_RAY`, proving the market is permanently frozen.

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
