### Title
Unauthorized theft of assets held by Emporium via unsigned CASE 2 stateless operations - (File: contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol)

### Summary
`EmporiumUpgradeable.runAction` executes CASE 2 ("stateless") operations with `op.endpoint.call(op.callData)` directly from Emporium's own context, and `verifyWallet` performs **no authorization check at all** when `stack.signerAddress == address(0)`. Combined with the "EmporiumMin" zero-token proof path (`erc20TokenAddresses.length == 0`), any unprivileged caller of `Hinkal.transact` can submit an `EmporiumStack` whose op transfers out any NFT (or other asset) currently custodied by Emporium — including an NFT that a different victim minted there in an earlier, unrelated transaction.

### Finding Description
Broken equality: `owner(tokenId) after tx == stealth address that funded/authorized the mint` is violated; instead `owner(tokenId) == attacker`.

Path:
1. A victim previously executed a CASE 2 op minting an NFT (e.g. a Uniswap V3 LP position) with `recipient = address(Emporium)`. `Transferer.onERC721Received` [1](#0-0)  unconditionally accepts custody, so `EmporiumUpgradeable` (which inherits `Transferer`) now legitimately holds `tokenId`.
2. Attacker calls `Hinkal.transact` with `externalActionData.externalAddress == Emporium` and `erc20TokenAddresses = []` (empty), which routes proof-input generation through `formInputEmporiumMin`, requiring only `emporiumMessage`, `timeStamp`, `calldataHash` as public signals [2](#0-1) . This lets the attacker generate a trivial valid proof over zero UTXOs/nullifiers, satisfying `dimensionsCheck`/`checkOnchainCreation`/`performHinkalChecks` in `HinkalHelper.sol` [3](#0-2)  without proving ownership of anything.
3. `Hinkal._externalTransact` forwards the call to `EmporiumUpgradeable.runAction` (allowed since Hinkal is a registered `onlyAllowedRecipient`) [4](#0-3) .
4. Attacker sets `stack.signerAddress = address(0)`. `verifyWallet` then returns immediately with **no signature check whatsoever** [5](#0-4) ; the only guard left is `usedMessages[emporiumMessage]`, trivially bypassed with a fresh nonce.
5. Attacker's `ops[0] = {endpoint: NFT, invokeWallet: false, value: 0, callData: safeTransferFrom(Emporium, attacker, tokenId)}` hits CASE 2, executed as `op.endpoint.call(op.callData)` [6](#0-5) . Because `msg.sender` inside that call is `address(Emporium)` itself, which is the actual owner of `tokenId`, the NFT contract authorizes the transfer.
6. No balance/slippage guard applies because `circomData.erc20TokenAddresses` is empty, so `getBalancesForArray` loops in both `Hinkal.transact` and `EmporiumUpgradeable.runAction` are no-ops for the ERC721 asset; `BalanceChangeShouldBePositive` never triggers.

Existing guards fail because: `performHinkalChecks`/`verifyProof` only attest to the attacker's own (empty) UTXO set and calldata integrity — they never bind the specific `ops[]` content to any UTXO/ownership of the target asset; `verifyWallet` skips signature verification entirely when `signerAddress == address(0)`; and the balance-diff checks in both `Hinkal.sol` and `EmporiumUpgradeable.sol` only cover tokens explicitly listed in `erc20TokenAddresses`, which the attacker can simply omit.

### Impact Explanation
Direct theft of a victim's shielded NFT/LP position (e.g., Uniswap V3 LP NFT) held in custody by Emporium, with the attacker able to redirect it to their own address. This is Critical: theft of shielded user funds/assets held in-flight by the protocol's Emporium contract. The attack is repeatable against any asset (NFT, unlisted ERC20, ETH not represented in `erc20TokenAddresses`) currently held by Emporium, for as many `tokenId`s/assets as are observable on-chain.

### Likelihood Explanation
Preconditions: Emporium must be holding the target NFT (achieved simply by any victim performing a normal CASE 2 mint-to-Emporium operation, an intended usage pattern). Attacker cost is minimal — generating a trivial zero-value ZK proof for the empty-array "EmporiumMin" path and constructing an `EmporiumStack` with `signerAddress = address(0)`. No special role, no victim cooperation, and no signature from anyone is required. This is fully feasible for any unprivileged EOA and repeatable for every asset left in Emporium's custody.

### Recommendation
Require that CASE 2 (stateless) operations either (a) mandatorily verify a `stack.signerAddress` signature tying the operation to the specific asset owner/UTXO (never allow `address(0)` to bypass signing when Emporium holds externally-custodied assets), or (b) restrict CASE 2 `endpoint`/`callData` to a allow-listed set of selectors that cannot move assets out of Emporium to arbitrary recipients, or (c) track per-asset ownership (e.g., which stealth address/commitment "owns" a given NFT held by Emporium) and enforce that only a proof over that specific commitment can authorize withdrawal of that asset.

### Proof of Concept
Hardhat fork test:
1. Deploy Hinkal, HinkalHelper, EmporiumUpgradeable, register Emporium as external action, deploy a mock/real ERC721 (e.g., Uniswap V3 `NonfungiblePositionManager` fork or a mock NFT with `mint(to, tokenId)`).
2. As "victim", call `Hinkal.transact` with `externalActionData.externalAddress = Emporium`, `EmporiumStack.ops[0] = {endpoint: NFT, invokeWallet:false, value:0, callData: mint(..., recipient=Emporium, tokenId)}`, valid trivial proof for empty `erc20TokenAddresses`. Assert `NFT.ownerOf(tokenId) == address(Emporium)`.
3. As "attacker" (different EOA, no relation to victim), call `Hinkal.transact` again with a fresh `emporiumMessage`, `stack.signerAddress = address(0)`, `ops[0] = {endpoint: NFT, invokeWallet:false, value:0, callData: safeTransferFrom(Emporium, attacker, tokenId)}`, own trivial zero-UTXO proof, `erc20TokenAddresses = []`.
4. Assert the equality breaks: before tx `NFT.ownerOf(tokenId) == address(Emporium)` (custodying victim's asset); after tx `NFT.ownerOf(tokenId) == attacker`, proving theft without any signature or proof of ownership tied to the victim's stealth address/UTXO.
