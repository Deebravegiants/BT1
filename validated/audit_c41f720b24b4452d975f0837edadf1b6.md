### Title
Underestimated relayer fee for TokenGateway teleports carrying destination calldata - ([File: sdk/packages/sdk/src/protocols/tokenGateway.ts])

### Summary
`TokenGateway.quoteNative` estimates the relayer fee for a teleport by simulating delivery of a **dummy POST request with a fixed 191-byte random body**, ignoring the actual `params.data` (destination contract calldata) that the caller intends to execute after the transfer lands. When `data` is non-empty and expensive to execute, the estimated gas — and therefore the relayer fee attached to the dispatch — is understated, exactly mirroring the GMX `estimateExecuteWithdrawalGasLimit` bug where a fixed/partial gas estimate omitted an optional, caller-controlled follow-on execution (a token swap there, an arbitrary calldata dispatch here).

### Finding Description
`quoteNative` builds relayer-fee estimates like this: [1](#0-0) 

It always estimates gas against a `dummyPostRequest` whose body is 191 bytes of **random** data — a fixed-size placeholder unrelated to the real payload: [2](#0-1) 

The actual teleport body, however, is built from `TeleportParams`, which carries an optional `data` field documented as "Destination contract calldata": [3](#0-2) 

The destination-chain execution flow for Hyperbridge's fungible-token apps (the same call-dispatch pattern the TokenGateway family follows per the on-chain docs' `call_data` field) decodes this payload and invokes `ICallDispatcher(_dispatcher).dispatch(message.data)` as an *additional* step after minting/transferring the asset: [4](#0-3) 

This is structurally identical to the GMX report: `estimateExecuteWithdrawalGasLimit` estimated gas for a base withdrawal but omitted the gas cost of an optional swap sub-operation the withdrawal could trigger, whereas here `quoteNative`'s relayer-fee estimate is built from a synthetic fixed-size body and never accounts for gas the real `data` payload's `ICallDispatcher.dispatch` execution will consume on delivery.

### Impact Explanation
A relayer fee sized below the real destination execution cost under-incentivizes relayers to deliver the message; permissionless relayers will decline to pick up (or will stall) teleports whose `data` payload is non-trivial, since the fee attached at dispatch does not cover their gas outlay. This is a funds/availability issue for the message-delivery path reachable by any unprivileged caller invoking `TokenGateway.quoteNative`/teleport with `data` set — it can strand a legitimate cross-chain transfer (with destination call) in an undeliverable state (a stuck message, later reclaimable only via timeout), which is a concrete freezing-of-funds/availability failure for the sender until the request times out and refunds.

### Likelihood Explanation
Likelihood is limited by adoption of the `data` field: it only manifests when a caller supplies non-empty destination calldata via `TeleportParams.data`, which is an explicitly supported, user-facing feature (documented in both the SDK API and the Substrate-side `TeleportParams.call_data`). Any dApp integrator building "teleport + call" flows will trigger the underestimate without any special conditions, malicious actors, or timing dependency — it is a straightforward misuse of a documented parameter combined with the SDK's fee-estimation shortcut.

### Recommendation
When `params.data` is non-empty, build the dummy/real post request used for gas estimation using the *actual* `data` payload (or a size-and-shape-matched worst-case stand-in that also triggers `ICallDispatcher.dispatch`), rather than a fixed 191-byte random blob, so `estimateGas` on the destination chain captures the true execution cost of the callback. At minimum, add a configurable gas surcharge proportional to `data.length` and document that callers supplying `data` must independently verify sufficient relayer-fee coverage.

### Proof of Concept
1. Caller invokes `tokenGateway.quoteNative({..., data: <calldata calling an expensive destination contract>})`.
2. `quoteNative` estimates gas using `dummyPostRequest` with a fixed random 191-byte body (`sdk/packages/sdk/src/protocols/tokenGateway.ts` lines 153-181), which does not exercise `ICallDispatcher.dispatch` at all.
3. The computed `relayerFee` (gas × gasPrice × 1.01) reflects only a bare transfer, not the cost of executing the supplied `data`.
4. The teleport is dispatched with this underestimated fee; relayers evaluating profitability against actual destination gas costs (transfer + `ICallDispatcher.dispatch(message.data)`) find the fee insufficient and decline delivery, leaving the request undelivered until timeout/refund.

Note: I was unable to locate the on-chain `TokenGateway.sol` contract itself in this repository's index to directly confirm its `onAccept` handling of the `data` field (only the SDK, docs, and the sibling `HyperFungibleToken*` app contracts — which implement the identical calldata-dispatch pattern — were found). This should be verified in the actual `TokenGateway.sol` deployment before treating the on-chain mechanics as fully confirmed; the estimation-code root cause in the SDK, however, is directly verified.

    function onAccept(IncomingPostRequest calldata incoming) public virtual override onlyHost whenNotPaused {
        PostRequest calldata request = incoming.request;

        bytes memory expectedSource = _supportedChains[request.source];
        if (expectedSource.length == 0) revert UnsupportedChain();
        if (keccak256(request.from) != keccak256(expectedSource)) revert UnauthorizedSource();

        Message memory message = abi.decode(request.body, (Message));
        address beneficiary = _toAddr(message.to);
        _mint(beneficiary, message.amount);

        if (message.data.length > 0) {
            ICallDispatcher(_dispatcher).dispatch(message.data);
        }

        emit Received({
            from: message.from,
            to: beneficiary,
            source: string(request.source),
            amount: message.amount
        });
    }
