### Title
Fixed-slot-count blockhash/nonce expiry window becomes wall-clock miscalibrated once slot time is reduced - (File: `runtime/src/bank.rs`, `runtime/src/slot_params.rs`, `accounts-db/src/blockhash_queue.rs`)

### Summary
`Bank::max_processing_age` and `BlockhashQueue`'s `max_age` express blockhash/nonce/durable-transaction expiry purely as a fixed number of slots (`MAX_PROCESSING_AGE`), the same "heartbeat" pattern as Renzo's fixed `MAX_TIME_WINDOW = 86400 + 60` seconds used everywhere regardless of the underlying feed's actual update cadence. Agave, however, now supports variable slot durations via slot-time-reduction feature gates (`reduce_slot_time_to_350ms/300ms/250ms/200ms`), tracked by `SlotParamsArchive`/`SlotParams` in `runtime/src/slot_params.rs`. Because the transaction-processing-age window is counted in slots rather than wall-clock time, the same fixed slot-count budget silently shrinks in real time as the network transitions to shorter slots, exactly analogous to Renzo's single "24h + 60s" window being wrong depending on the token/chain's real heartbeat.

### Finding Description
`BlockhashQueue::is_hash_valid_for_age`/`get_hash_info_if_valid` accept a `max_age` in slots and compare it against `hash_index` deltas [1](#0-0) . `Bank::max_processing_age` (a fixed `usize`, ultimately derived from `solana_clock::MAX_PROCESSING_AGE`) is used throughout transaction checking, e.g. in `check_transaction_age`/`check_age_and_compute_budget_limits` [2](#0-1) , `is_blockhash_valid` [3](#0-2) , and `get_blockhash_last_valid_block_height` (which multiplies the slot-based age budget directly into a block-height cutoff without any wall-clock scaling) [4](#0-3) .

Separately, the codebase has introduced explicit machinery acknowledging that slot duration is not constant: `SlotParams`/`SlotParamsArchive` track `ns_per_slot` transitioning through `400_000_000 -> 350_000_000 -> 300_000_000 -> 250_000_000 -> 200_000_000` ns as slot-time-reduction features activate at epoch boundaries [5](#0-4) , and `slot_range_duration_nanos` is used precisely to compute correct wall-clock durations across these transitions for other subsystems (e.g. inflation, shred limits, rewards) [6](#0-5) . However, the blockhash/nonce expiry path (`max_processing_age`, `BlockhashQueue.max_age`, `MAX_TRANSACTION_FORWARDING_DELAY`-based forwarding age adjustment in `check_transactions_with_forwarding_delay`) still uses a flat slot count with no dependency on `ns_per_slot_at_slot`/`slot_range_duration_nanos` [7](#0-6) . As `ns_per_slot` decreases from 400ms toward 200ms, the same `MAX_PROCESSING_AGE` (150 slots) budget's real-world validity window shrinks from ~60s to ~30s, without any corresponding adjustment for clients, RPC preflight ("`last_valid_block_height`"), nonce reuse safety margins, or the `MAX_TRANSACTION_FORWARDING_DELAY` slot-count constant used for forwarding-decision headroom.

### Impact Explanation
This is directly analogous to the Renzo bug class: a single hardcoded staleness/expiry parameter is applied uniformly even though the real-world cadence it is meant to bound (wall-clock time per unit) is not constant across the system's operating regimes (chains/tokens for Renzo; slot-time-reduction epochs for Agave). The practical effect in Agave is a narrowing time-budget for legitimate use (durable-nonce transactions, RPC preflight `last_valid_block_height`, forwarding to next leader) as slot time shrinks, increasing spurious `BlockhashNotFound`/nonce-expiry failures and reducing the margin `MAX_TRANSACTION_FORWARDING_DELAY` was designed to provide, rather than any direct fund loss. It is a correctness/liveness degradation in the transaction-processing-age accounting rather than a fund-safety bug, since transaction rejection (not consuming stale data as truth) is the actual failure mode — unlike Renzo where a stale price is silently accepted.

### Likelihood Explanation
Slot-time reduction features are explicitly implemented, tested (`test_reduce_slot_time_range_duration`, `test_reduce_slot_time_hashes_per_tick`) [8](#0-7) , and designed to activate progressively across epochs; once any of these gates activate on mainnet/testnet, every bank inherits the shorter `ns_per_slot` while `MAX_PROCESSING_AGE` remains unchanged. This is a certainty of divergence over time rather than a rare edge case, but I could not confirm from the indexed files whether the constant `MAX_PROCESSING_AGE` value itself is intended to be revisited as part of the slot-time-reduction feature rollout (e.g., a companion feature gate bumping it) — this file (`solana-clock` crate defining `MAX_PROCESSING_AGE`) was not available in the index, so I cannot rule out that mitigation exists elsewhere.

### Recommendation
Express blockhash/nonce/transaction-forwarding age budgets as (or make them derivable from) an approximate wall-clock target rather than a fixed slot count, using the same `SlotParamsArchive`/`ns_per_slot_at_slot`/`slot_range_duration_nanos` machinery already used elsewhere in `runtime/src/bank.rs`/`runtime/src/slot_params.rs`, so `max_processing_age`, `MAX_TRANSACTION_FORWARDING_DELAY`, and `get_blockhash_last_valid_block_height` scale with the currently effective slot duration instead of assuming the legacy 400ms/slot baseline.

### Proof of Concept
Conceptual/no dynamic PoC available from static indexing alone:
1. Activate `reduce_slot_time_to_200ms` (or any of the four slot-time-reduction feature gates) so that `SlotParamsArchive::params_at_slot` returns `SLOT_PARAMS_200MS` (`ns_per_slot = 200_000_000`) for the current slot [9](#0-8) .
2. Observe that `Bank::max_processing_age` and `BlockhashQueue::max_age` (backed by the fixed `MAX_PROCESSING_AGE` slot count) are unchanged, so `get_blockhash_last_valid_block_height`'s `block_height + max_processing_age` window [4](#0-3)  now represents half the wall-clock time it did under `LEGACY_SLOT_PARAMS` (400ms/slot).
3. Clients/RPC users relying on `last_valid_block_height` for retry/expiry timing (`rpc/src/rpc.rs` preflight logic) and durable-nonce transactions relying on `MAX_TRANSACTION_FORWARDING_DELAY` slots of buffer [10](#0-9)  experience a real-time expiry window that shrank without any protocol-level adjustment, producing elevated `TransactionError::BlockhashNotFound` rejection rates purely due to the slot-time change — the same "fixed period too short/too coarse for the actual update cadence" root cause as the Renzo finding.

    fn check_transaction_age(
        &self,

        max_age: usize,

            next_durable_nonce,
            strict_nonce_size_check,
            strict_nonce_authority_check,
        ) {
            Ok(Some(nonce_address))
        } else {
            error_counters.blockhash_not_found += 1;
            Err(TransactionError::BlockhashNotFound)
        }
    }

    /// Returns the exact wall-clock duration in nanoseconds for
    /// `start_slot..=end_slot`.
    pub(crate) fn slot_range_duration_nanos(&self, start_slot: Slot, end_slot: Slot) -> u128 {
        if start_slot > end_slot {
            return 0;
        }

        let mut cursor = start_slot;
        let mut params = self.params_at_slot(start_slot);
        let mut duration = 0u128;

        for (&effective_slot, &effective_params) in self
            .param_transitions
            .range((Excluded(start_slot), Included(end_slot)))
        {
            duration = duration.saturating_add(
                u128::from(effective_slot.saturating_sub(cursor))
                    .saturating_mul(params.ns_per_slot()),
            );
            cursor = effective_slot;
            params = effective_params;
        }

        let remaining_slots = u128::from(end_slot.saturating_sub(cursor)) + 1;
        duration.saturating_add(remaining_slots.saturating_mul(params.ns_per_slot()))
    }

#[test]
fn test_reduce_slot_time_range_duration() {
    const SLOTS_PER_EPOCH: Slot = 32;
    let bank_for_activations = |activations: &[(Pubkey, Slot)]| {
        let (mut genesis_config, _) = create_genesis_config_with_legacy_hashes(1_000_000);
        genesis_config.epoch_schedule =
            EpochSchedule::custom(SLOTS_PER_EPOCH, SLOTS_PER_EPOCH, false);
        let mut bank = Bank::new_for_tests(&genesis_config);
        let mut feature_set = FeatureSet::default();
        for (feature_id, activation_slot) in activations {
            feature_set.activate(feature_id, *activation_slot);
        }
        bank.feature_set = Arc::new(feature_set);
        bank.refresh_slot_params();
        bank
    };

    let ordered_activations = slot_time_feature_gates()
        .into_iter()
        .zip([1, 33, 65, 97])
        .map(|((feature_id, _), activation_slot)| (feature_id, activation_slot))
        .collect::<Vec<_>>();
    let bank = bank_for_activations(&ordered_activations);

    let expected_duration = [
        (SLOTS_PER_EPOCH, LEGACY_SLOT_PARAMS),
        (SLOTS_PER_EPOCH, SLOT_PARAMS_350MS),
        (SLOTS_PER_EPOCH, SLOT_PARAMS_300MS),
        (SLOTS_PER_EPOCH, SLOT_PARAMS_250MS),
        (SLOTS_PER_EPOCH, SLOT_PARAMS_200MS),
    ]
    .into_iter()
    .map(|(slots, params)| slots as f64 / params.slots_per_year())
    .sum::<f64>();

    assert_eq!(
        bank.slot_range_duration_in_years(0, SLOTS_PER_EPOCH * 5)
            .to_bits(),
        expected_duration.to_bits()
    );
    assert_eq!(
        bank.slot_range_duration_nanos(0, SLOTS_PER_EPOCH * 5 - 1),
        [
            (SLOTS_PER_EPOCH, LEGACY_SLOT_PARAMS),
            (SLOTS_PER_EPOCH, SLOT_PARAMS_350MS),
            (SLOTS_PER_EPOCH, SLOT_PARAMS_300MS),
            (SLOTS_PER_EPOCH, SLOT_PARAMS_250MS),
            (SLOTS_PER_EPOCH, SLOT_PARAMS_200MS),
        ]
        .into_iter()
        .map(|(slots, params)| u128::from(slots) * params.ns_per_slot())
        .sum::<u128>()
    );

    let [reduce_to_350ms, _, _, reduce_to_200ms] = slot_time_feature_ids();
    let bank =
        bank_for_activations(&[(reduce_to_200ms, 1), (reduce_to_350ms, SLOTS_PER_EPOCH + 1)]);
    assert_eq!(
        bank.slot_params_at_slot(SLOTS_PER_EPOCH - 1),
        LEGACY_SLOT_PARAMS
    );
    assert_eq!(bank.slot_params_at_slot(SLOTS_PER_EPOCH), SLOT_PARAMS_200MS);
    assert_eq!(
        bank.slot_params_at_slot(SLOTS_PER_EPOCH * 2),
        SLOT_PARAMS_200MS
    );
    assert_eq!(
        bank.slot_range_duration_in_years(0, SLOTS_PER_EPOCH * 3)
            .to_bits(),
        (SLOTS_PER_EPOCH as f64 / LEGACY_SLOT_PARAMS.slots_per_year()
            + (SLOTS_PER_EPOCH * 2) as f64 / SLOT_PARAMS_200MS.slots_per_year())
        .to_bits()
    );
    assert_eq!(
        bank.slot_range_duration_nanos(0, SLOTS_PER_EPOCH * 3 - 1),
        u128::from(SLOTS_PER_EPOCH) * LEGACY_SLOT_PARAMS.ns_per_slot()
            + u128::from(SLOTS_PER_EPOCH * 2) * SLOT_PARAMS_200MS.ns_per_slot()
    );
}
