**Key facts:**

`SignAndSendArgs.payload` is a documented, first-class parameter of the SDK's public API, explicitly described as a mechanism "to modify the intent payload draft before signing... to add or modify intent primitives in the payload": [1](#0-0) 

It flows directly into `IntentExecuter`'s `intentPayloadFactory`, which is invoked inside `mergeIntentPayloads` and then signed by the same `intentSigner` that the caller supplied for that exact `signAndSendIntent` invocation: [2](#0-1) [3](#0-2) [4](#0-3) 

The `payload` factory is not externally-supplied data (like `assetId`, `memo`, `nonce`, or `quoteHashes` that a counterparty or solver could inject through a request). It is a JavaScript function passed in-process by whoever calls `IntentsSDK.signAndSendIntent`/`processWithdrawal` — i.e., the integrator's own code holding the same keys/`intentSigner` that will sign the resulting payload. An "unprivileged caller" per the threat model (an ordinary user, a counterparty whose strings get forwarded, or a permissionless solver) has no channel to supply or influence this callback for someone else's SDK invocation; they can only affect it in their own calls, over their own funds, which they are entitled to sign.

The test suite in `intent-executer.test.ts` documents this as intended behavior — the factory is explicitly designed to prepend/append/override intent primitives before signing, and the resulting payload is what the signer of that same call signs (the two "appends"/"removes duplicates" tests demonstrate `intentPayloadFactory` is meant to reshape `intents`): [5](#0-4) 

This matches the exclusion rule for "deliberately misusing a documented escape hatch." The described exploit requires the *caller who owns the signer/keys* to pass a malicious factory into their own call — there is no cross-user or cross-privilege boundary crossed, and no unprivileged remote actor can reach `SignAndSendArgs.payload` for another party's transaction.

async function mergeIntentPayloads(
	defaultPayload: IntentPayload,
	intentPayloadFactory: IntentPayloadFactory,
	salt: Salt,
): Promise<IntentPayload> {
	const customPayload = await intentPayloadFactory(defaultPayload);
	const customPayloadIntents = customPayload.intents ?? [];

	const { nonce: _nonce, ...basePayload } = defaultPayload;

	return defaultIntentPayloadFactory(salt, {
		...basePayload,
		...customPayload,
		intents: Array.from(
			new Set([...customPayloadIntents, ...basePayload.intents]),
		),
	});
}
