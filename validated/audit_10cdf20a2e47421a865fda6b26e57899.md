### Title
Accrued RAY-value overflow permanently freezes a large high-utilization market - (File: common/src/rates/index.rs)

### Summary
An unprivileged borrower can leave a large market at sustained high utilization until interest accrual makes a debt or supply valuation exceed `i128`. The next permissionless `update_indexes` call panics with `MathOverflow`; because withdrawal, repayment, liquidation, and later index updates all accrue first, the same panic permanently blocks the market.

### Finding Description
The pool performs `Cache::load` and `interest::global_sync` before every mutation of an existing market, so even risk-reducing exits cannot bypass accrual [1](#0-0) . During accrual, scaled balances are converted to current values through fixed-point multiply/divide; unrepresentable results return through `to_i128` as a contract `MathOverflow` panic [2](#0-1) [3](#0-2) .

The index bounds do not bound the represented market value. The project’s own boundary documentation states that accrued position values and market totals can overflow before either index reaches its ceiling, and that this blocks repayment and withdrawal because those operations accrue first [4](#0-3) . The production regression test confirms the concrete condition: an 18-decimal market holding a billion-token book at 98% utilization eventually makes `update_indexes` fail below `MAX_BORROW_INDEX_RAY`, after which both `withdraw` and `repay` fail with `MathOverflow` [5](#0-4) .

### Impact Explanation
This permanently freezes all funds in the affected market. Suppliers cannot withdraw, borrowers cannot repay, liquidators cannot reduce unsafe debt, and `update_indexes` cannot recover the market because each path executes the same overflowing accrual first [6](#0-5) .

The attacker does not need to retain ownership of the poisoned position. Once the represented book crosses the `i128` boundary, every unrelated supplier and borrower in that market is frozen with it. This is more than fail-closed validation of a malformed request: the malformed numeric state is created by accepted supply/borrow actions and later makes all recovery actions revert.

### Likelihood Explanation
An unprivileged account can supply to an admitted market and borrow through `controller::borrow`, while anyone can advance the condition through permissionless `controller::update_indexes` [7](#0-6) . The attack requires a market whose admitted caps and collateral permit an extremely large high-utilization book, plus enough elapsed time for accrued value to exceed the representable domain; the regression test establishes that this can occur before the configured index ceiling [8](#0-7) .

The capital requirement is substantial, but the failure is deterministic once the market enters the overflowing state and does not depend on privileged access, oracle dishonesty, a malicious token, or an external service.

### Recommendation
Accrual should saturate or recover before attempting an unrepresentable total-value conversion. In particular:

- Clamp/chunk accrual before `borrowed * borrow_index` or `supplied * supply_index` can exceed `i128`.
- Treat index-ceiling saturation as a successful terminal accrual rather than allowing value overflow.
- Add an emergency debt-ceiling/write-down path that does not perform the overflowing accrual first.
- Enforce supply/borrow caps against projected post-accrual RAY values, not only current token-unit caps.
- Add regression coverage proving `repay`, `withdraw`, `liquidate`, and `update_indexes` remain callable at the market’s maximum admitted numeric boundary.

### Proof of Concept
The repository contains a concrete regression demonstrating the sequence:

1. Configure an 18-decimal market and a collateral market, with caps raised to the admitted domain boundary.
2. An unprivileged supplier deposits `1_000_000_000 * 10^18` units of `BIG18`.
3. Another unprivileged account supplies collateral and borrows `98%` of that market, creating sustained high utilization [9](#0-8) .
4. Repeatedly advance ledger time and call permissionless `update_indexes` for `BIG18` until it returns `MathOverflow` [10](#0-9) .
5. Observe that the borrow index remains below `MAX_BORROW_INDEX_RAY`, while subsequent `withdraw` and `repay` calls also fail with `MathOverflow` [6](#0-5) .

The equivalent live transaction sequence is `controller::supply` for the large asset, `controller::supply` and `controller::borrow` for the collateral-funded debt, followed by `controller::update_indexes`. No privileged action or malformed external dependency is required after the market is admitted.

```rust
pub fn mul_div_floor(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    require_nonzero_divisor(env, d);
    if let Some(quotient) = x
        .checked_mul(y)
        .and_then(|product| div_floor_i128(product, d))
    {
        return quotient;
    }
    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    let nonneg = quotient_is_nonnegative(x, y, d);
    to_i128(env, &div_floor_i256(env, &x256.mul(&y256), &d256, nonneg))
}
```

```rust
/// Converts an `I256` to `i128`, panicking with `GenericError::MathOverflow` if it does not
/// fit.
fn to_i128(env: &Env, val: &I256) -> i128 {
    val.to_i128()
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
}
```

```rust
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
