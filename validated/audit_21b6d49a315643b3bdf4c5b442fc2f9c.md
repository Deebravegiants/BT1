### Title
Permanent market freeze from RAY-value overflow before the borrow-index cap - (File: `common/src/rates/scaling.rs`)

### Summary

The interest-accrual path can permanently brick a heavily supplied and borrowed market. `accrue_step` multiplies the total scaled debt and supply by their indexes before applying any operation, while `scaled_to_original` treats an overflowing `scaled * index` product as a fatal `MathOverflow`. [1](#0-0) [2](#0-1) 

Although `update_borrow_index` caps the index at `MAX_BORROW_INDEX_RAY`, it does not cap the corresponding total position value. Consequently, a sufficiently large book can cross the `i128` RAY-value ceiling while the borrow index remains below its configured cap. [3](#0-2) [4](#0-3) 

### Finding Description

Every pool market mutation loads and synchronizes the market through `synced_market`, which invokes `interest::global_sync`. [5](#0-4) 

`global_sync` calls `accrue_step` for each elapsed chunk before the requested operation executes. [6](#0-5) 

Inside `accrue_step`, both `borrowed_original` and `supplied_original` are computed with `scaled_to_original`. [7](#0-6) 

`scaled_to_original` performs checked `scaled * index` multiplication. Once either total's RAY-denominated value exceeds `i128::MAX`, the call panics before rates, index updates, withdrawals, repayments, liquidations, or state commits can proceed. [2](#0-1) 

The borrow-index ceiling is applied only to `old_index * interest_factor`; it does not ensure that `borrowed * new_borrow_index` or `supplied * supply_index` remains representable. [3](#0-2) 

An attacker can reach this state through unprivileged controller calls:

1. `supply` a very large amount of the target asset.
2. Supply collateral in another listed market.
3. `borrow` most of the target market, creating high utilization and a large scaled debt book.
4. Repeatedly call permissionless `update_indexes` as ledger time advances until the next accrual overflows.

The controller exposes `supply`, `borrow`, and permissionless `update_indexes`, while the pool routes the latter to the same accrual routine. [8](#0-7) [9](#0-8) [10](#0-9) 

### Impact Explanation

The affected market becomes permanently unusable: `withdraw`, `repay`, `liquidate`, `clean_bad_debt`, additional `supply`, `borrow`, `claim_revenue`, and `update_indexes` all require the same pre-operation accrual and therefore encounter the same panic. [11](#0-10) [12](#0-11) 

Supplier principal and yield remain locked in the pool, borrowers cannot reduce or close debt, and liquidators cannot normalize unsafe accounts. Because `update_params` also accrues before replacing the rate model, ordinary parameter correction cannot bypass the panic. [13](#0-12) 

This is permanent freezing of user funds rather than a bounded per-call rejection: no unprivileged transaction can move the market past the overflowing accrual state.

### Likelihood Explanation

**Medium.** The attack requires an unusually large market, sufficient collateral and token liquidity, suitable admitted caps, and sustained high utilization under a steep rate curve. Those prerequisites make it expensive and market-dependent.

The condition is nevertheless reachable without privileged access, storage corruption, oracle manipulation, or leaked keys. The repository's regression test demonstrates the exact cliff: a one-billion-token, eighteen-decimal book at approximately 98% utilization eventually causes `update_indexes`, `withdraw`, and `repay` to revert with `MathOverflow` while the borrow index remains below `MAX_BORROW_INDEX_RAY`. [4](#0-3) 

### Recommendation

Bound total RAY-denominated book values rather than only bounding the indexes.

- On `supply`, `borrow`, revenue minting, and bad-debt/index updates, check that the resulting `scaled * index` and projected post-accrual values remain below a conservative `i128` bound.
- Alternatively, make accrual saturate affected derived values instead of panicking, while preventing further growth once the representable-value ceiling is reached.
- Add an explicit market-level `MAX_TOTAL_VALUE_RAY` and reject entries that could push either supplied or borrowed value beyond it.
- Add a regression test proving `update_indexes`, `withdraw`, `repay`, and liquidation remain executable when an index approaches its cap or a book approaches the value ceiling.

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");

        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"

    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
