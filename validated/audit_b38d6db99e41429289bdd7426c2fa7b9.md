## Analysis Result [1](#0-0) 

### Title
Unbounded, Fixed-Weight `GetRequestsWithProof.requests` in `pallet_state_coprocessor::handle_unsigned` Enables Uncontrolled Resource Consumption - (File: `modules/pallets/state-coprocessor/src/lib.rs`)

### Summary
`pallet_state_coprocessor::handle_unsigned` is a permissionless, unsigned extrinsic that accepts a `GetRequestsWithProof` message whose `requests: Vec<GetRequest>` field is completely unbounded, yet is declared with a fixed, size-independent weight. The same unbounded payload is fully executed twice by every node — once during `validate_unsigned` transaction-pool validation and once again at block-execution time — performing per-request state-proof verification and hashing work that scales linearly (or worse) with an attacker-controlled batch size, without any cap enforced before that work is done.

### Finding Description
`GetRequestsWithProof` carries an unbounded `Vec<GetRequest>`, and each `GetRequest` itself carries an unbounded `keys: Vec<Vec<u8>>`: [2](#0-1) 

The dispatchable `handle_unsigned` is declared with a fixed weight that does not scale with the number of requests or keys in the batch:
```rust
#[pallet::call_index(0)]
#[pallet::weight(<T as frame_system::Config>::DbWeight::get().reads_writes(1, 2))]
pub fn handle_unsigned(origin: OriginFor<T>, message: GetRequestsWithProof) -> DispatchResult {
    ensure_none(origin)?;
    Self::handle_get_requests(message).map_err(...)?;
    Ok(())
}
``` [3](#0-2) 

`Self::handle_get_requests` loops over every `GetRequest` in the batch, performing deduplication, timeout, source/dest checks, membership-proof verification of the whole batch's commitments, and then — per request — a full state-membership proof verification (`verify_state_proof`) against arbitrary `keys`, before any bandwidth or size limit is applied: [4](#0-3) 

Crucially, the `BandwidthGate::try_consume` call — the only per-app metering mechanism — is invoked *after* `verify_state_proof` has already run for that request, i.e., after the expensive cryptographic work has already been paid for in CPU time: [5](#0-4) 

Because this is an **unsigned** extrinsic, `validate_unsigned` re-executes `handle_get_requests` in full (not just a cheap signature check) as part of transaction-pool admission, before the extrinsic is even included in a block: [6](#0-5) 

This mirrors the GitLab CVE-2019-20146 bug class: an attacker-controlled, unbounded input is fully processed (uncontrolled resource consumption) by every node that touches the transaction — both in mempool validation and in block execution — while the declared/accounted `Weight` used for Substrate's block-weight-limit accounting is fixed and does not reflect the real cost. Substrate's weight system is the mechanism meant to bound per-block computation; a mismatch between declared weight and actual execution cost lets an attacker submit an unsigned call whose real CPU/verification cost vastly exceeds what the runtime "charges" for it, since the fixed weight is `reads_writes(1, 2)` regardless of batch size.

### Impact Explanation
An attacker can submit (for free, since this is an unsigned extrinsic with no signed origin or fee) a `handle_unsigned` call carrying a very large `requests` vector, each with many `keys`, forcing:
1. Every full/validating node in the network to run expensive membership/state-proof verification for the whole batch during `validate_unsigned` pool checks.
2. The same expensive verification to run again at block-execution time if the call makes it into a block, but "charged" only the fixed, negligible `reads_writes(1, 2)` weight.

This can be used to stall block production or exhaust node resources (CPU/memory) network-wide, since the block-weight accounting undercounts the actual work, allowing an attacker to pack disproportionately expensive computation into a block that appears "cheap" by weight accounting — a route/consensus-level denial of service that can render Hyperbridge unable to reliably process and deliver GET-response messages (a "route unable to deliver messages" condition per the validation criteria).

### Likelihood Explanation
High reachability: `handle_unsigned` is explicitly permissionless (`ensure_none(origin)`) and is meant to be freely submittable by any relayer with a superficially valid proof — no economic cost, no rate limiting prior to the loop, and no bound on `Vec<GetRequest>` or per-request `keys`. An attacker only needs to craft a `GetRequestsWithProof` with a large number of requests/keys that individually satisfy the cheap up-front checks (timeout, source/dest matching, dedup) so the loop proceeds into the costly `verify_state_proof` calls before failing (or even succeeding, if using previously-seen legitimate commitments/proofs is feasible, or by using still-unexpired/undelivered pending GetRequests already sitting on a source chain).

### Recommendation
- Bound `GetRequestsWithProof.requests` (and each `GetRequest.keys`) with a `BoundedVec` / explicit `MAX_REQUESTS_PER_BATCH` and `MAX_KEYS_PER_REQUEST` constant, rejecting oversized batches before any proof verification runs.
- Make the declared `#[pallet::weight(...)]` for `handle_unsigned` a function of `message.requests.len()` (and total key count) so the runtime's weight accounting reflects actual execution cost, consistent with how `pallet_ismp::handle_unsigned` computes weight via its `weight()` helper.
- Enforce the `BandwidthGate::try_consume` check (or an equivalent cheap size-based gate) up front, before invoking `verify_state_proof`, so unauthorized/over-quota apps cannot force expensive proof verification to occur at all.

### Proof of Concept
Conceptual outline (cannot be executed without live infra):
1. Construct a `GetRequestsWithProof` with e.g. 10,000+ `GetRequest`s, each carrying a large `keys: Vec<Vec<u8>>`, all sharing the same `source`/`response` state-machine heights so the batch clears the up-front metadata checks.
2. Submit this as an unsigned extrinsic (`Ismp::handle_unsigned` route via `pallet_state_coprocessor`).
3. Observe that `validate_unsigned` fully executes `handle_get_requests`, running `verify_state_proof` for every request/key in the batch — before the extrinsic is even accepted into the pool — while the eventual on-chain weight charged (if included) is the fixed `reads_writes(1, 2)`.
4. Repeated concurrent submissions of such oversized batches from multiple accounts/peers can be used to degrade block-production time across the network, since actual CPU cost is decoupled from the weight-based block-inclusion budget.

Note: I was not able to fully inspect the `weight()` helper used by the sibling `pallet_ismp::handle_unsigned` (main ISMP pallet) within the available search results, so I cannot confirm whether that specific call scales weight with message size; the state-coprocessor pallet's `handle_unsigned`, however, is conclusively fixed-weight and unbounded as shown above.

	pub fn handle_get_requests(
		GetRequestsWithProof { requests, source, response, address }: GetRequestsWithProof,
	) -> Result<(), Error> {
		// 1. Verify source proofs
		// 2. Extract fees
		// 3. Verify response proof
		// 4. insert GetResponse into mmr and request receipts
		// 5. emit Response events
		let host = <<T as Config>::IsmpHost>::default();

		// Reject duplicate requests within the batch.
		let wrapped: Vec<Request> = requests.iter().cloned().map(Request::Get).collect();
		dedup_requests::<<T as Config>::IsmpHost>(&wrapped)?;

		for req in requests.iter() {
			let full = Request::Get(req.clone());

			// Get requests time out are relative to Hyperbridge
			if full.timed_out(host.timestamp()) {
				Err(Error::RequestTimeout { meta: full.clone().into() })?
			}

			// Source of the request must match the proof
			if full.source_chain() != source.height.id.state_id {
				Err(Error::RequestProofMetadataNotValid { meta: full.clone().into() })?
			}

			// Proof must come from the requested chain
			if full.dest_chain() != response.height.id.state_id {
				Err(Error::RequestProofMetadataNotValid { meta: full.clone().into() })?
			}

			// This request has already been responded to. Mirror `handlers/response.rs:61`:
			// dedup against `response_receipt`, which the dispatch path writes for this exact
			// GetRequest hash after producing a response. The receipt also binds the response
			// commitment, so external auditors can attest "Hyperbridge produced response X for
			// request Y" from one map.
			let probe = GetResponse { get: req.clone(), values: Default::default() };
			if host.response_receipt(&probe).is_some() {
				Err(Error::DuplicateResponse { meta: (&probe).into() })?
			}
		}

		// Ensure the proof height is equal to each retrieval height specified in the Get
		// requests
		if !requests.iter().all(|get| get.height == response.height.height) {
			Err(Error::InsufficientProofHeight)?
		}

		// Verify source proof
		let source_state_machine = validate_state_machine(&host, source.height)?;
		let state_root = host.state_machine_commitment(source.height)?;

		// Verify membership proof to ensure that requests where committed on source chain
		let commitments = requests
			.iter()
			.map(|get| hash_request::<<T as Config>::IsmpHost>(&Request::Get(get.clone())))
			.collect();
		source_state_machine.verify_membership(&host, commitments, state_root, &source)?;

		// Verify response proof
		let dest_state_machine = validate_state_machine(&host, response.height)?;
		let state_root = host.state_machine_commitment(response.height)?;

		// Insert GetResponses into mmr
		let mut responses = vec![];
		// Total payload bytes across this batch, used to mint reputation to
		// the relayer named in `address`. Each response contributes its
		// abi-encoded size — the same quantity the bandwidth gate charges —
		// so the mint stays proportional to the work paid for.
		let mut total_bytes: u32 = 0;
		for req in requests {
			let values: Vec<StorageValue> = dest_state_machine
				.verify_state_proof(&host, req.keys.clone(), state_root.state_root, &response)?
				.into_iter()
				.map(|(key, value)| StorageValue { key, value })
				.collect();

			let response = GetResponse { get: req, values };

			// Meter the app's bandwidth using the full size of the
			// abi-encoded GetResponse. Charged after proof verification
			// so the value sizes are final.
			let bytes = ismp::abi::encode_get_response(&response).len() as u32;
			<T as Config>::BandwidthGate::try_consume(
				&response.get.source,
				&response.get.from,
				bytes,
			)
			.map_err(|err| Error::Custom(alloc::format!("bandwidth gate: {err}")))?;
