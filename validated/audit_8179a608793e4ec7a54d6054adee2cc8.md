### Title
Legacy `FeesOnlyTransaction` reports near-zero `loaded_accounts_data_size` after large-account reads, letting cost tracker under-charge real I/O work - ([File: svm/src/account_loader.rs])

### Finding Description
`load_transaction` (`svm/src/account_loader.rs:423-471`) calls `load_transaction_accounts`, which iterates every account key in the message, fully loads and hashes each account's data, and accumulates the real cost into `loaded_tx_data_size` via `increase_calculated_data_size` [1](#0-0) . Only after all listed accounts (which can be several large accounts, up to the 64MiB `MAX_LOADED_ACCOUNTS_DATA_SIZE_BYTES` cap or the transaction's own compute-budget-declared limit) are loaded does the function check `program_instructions_iter()` ownership and potentially return `TransactionError::InvalidProgramForExecution` [2](#0-1) .

When this trailing check fails, `load_transaction` builds `TransactionLoadResult::FeesOnly`. With `define_ltds_fee_only_semantics` **disabled**, the reported `loaded_accounts_data_size` is taken not from the accumulated `loaded_transaction_data_size` (which reflects the real bytes just read) but from `tx_details.rollback_accounts.data_size()` — i.e. just the fee payer's (and possibly nonce's) account size [3](#0-2) [4](#0-3) . This is confirmed by the existing test `fee_only_loaded_transaction_data_size`, which explicitly asserts the reported size is `0` for the `fail_program_id_transaction` case when the feature is off, versus the true accumulated size when it's on [5](#0-4) .

This near-zero value is not merely cosmetic: it is propagated as `CommittedTransaction.loaded_account_stats.loaded_accounts_data_size` [6](#0-5) , and then consumed by `get_transaction_costs`, which calls `CostModel::calculate_cost_for_executed_transaction` using `committed_tx.loaded_account_stats.loaded_accounts_data_size` as the "actual" bytes for cost purposes [7](#0-6) . That derived `TransactionCost` (including `loaded_accounts_data_size_cost`) is fed into `check_block_cost_limits`, which calls `cost_tracker.try_add` to enforce per-block and per-account cost budgets [8](#0-7) . Thus the validator performs real, potentially large, account read/deserialization work but the block-cost accounting used to gate transaction admission is charged almost nothing for it.

### Impact Explanation
An unprivileged attacker can craft an ordinary transaction that lists several existing large accounts followed by a final instruction whose program id is not a valid loader-owned account (invalid/unregistered program id). Under the legacy semantics (`define_ltds_fee_only_semantics` inactive), every such transaction:
- Forces every honest validator/leader to actually read and process all the large account data during `load_transaction_accounts` before failing on the final program-ownership check.
- Reports back a `loaded_accounts_data_size` at or near zero to the cost model, so the block-cost-tracker's `loaded_accounts_data_size_cost` component and `allocated_accounts_data_size` budget are essentially not decremented for that real work.
- Still only costs the attacker the fixed signature fee (5000 lamports/sig), unrelated to the loaded-data-size cost component.

This lets an attacker pack disproportionately more such "large-account-touching, fee-only-failing" transactions into a block than the cost model's data-size budget is meant to allow, materially underpricing real per-block validator I/O/CPU work — a spam/DoS-adjacent underpricing vector matching the "materially underpriced execution" / cost-model-gap bounty category.

### Likelihood Explanation
This requires only an ordinary signed transaction from any funded account referencing several existing large accounts and one instruction whose program id is not owned by a recognized loader — no special privileges, staking, or validator control needed. It is fully reproducible and deterministic, and is directly exercised by the existing (but currently only feature-flag-driven) test `fee_only_loaded_transaction_data_size(false)` in `svm/tests/integration_test.rs`. It is only exploitable while `define_ltds_fee_only_semantics` is not active on a given cluster (e.g., during pre-activation windows on devnet/testnet/forked clusters), which is a real, non-hypothetical precondition given the feature is still switch-gated in this codebase.

### Recommendation
Always use the accumulated `loaded_transaction_data_size` (the real bytes touched by `load_transaction_accounts`) for the `FeesOnly` path's reported `loaded_accounts_data_size`, rather than falling back to `rollback_accounts.data_size()`, regardless of `define_ltds_fee_only_semantics`. If backward-compatibility for `define_ltds_fee_only_semantics` semantics must be preserved for consensus/feature-activation reasons, ensure the feature is activated cluster-wide as soon as possible and, in the interim, ensure the legacy fallback path's returned data size is never allowed to be smaller than an upper bound reflecting the accounts actually read (e.g., clamp to `loaded_transaction_data_size` when it is known to be larger), so that cost-tracker admission control cannot be starved by this gap.

### Proof of Concept
Reuse and extend the existing integration test to assert on cost-model impact rather than only on the reported stat:

```rust
// svm/tests/integration_test.rs (extension of fee_only_loaded_transaction_data_size)
#[test]
fn fee_only_loaded_transaction_data_size_cost_gap() {
    // Build common_test_entry exactly as in fee_only_loaded_transaction_data_size,
    // with define_ltds_fee_only_semantics = false and several large accounts
    // (e.g. base_size 512..=8192) plus a valid program.

    // fail_program_id_transaction: same accounts, but final instruction targets
    // Pubkey::new_unique() (not a loader-owned program) -> InvalidProgramForExecution.
    let fail_program_id_transaction = transaction(Pubkey::new_unique(), &account_keys, None);

    // Execute and capture the FeesOnly result.
    let output = env.execute();
    let reported_size = output.processing_results[/* fail_program_id index */]
        .as_ref()
        .unwrap()
        .loaded_accounts_data_size();

    // Assert the reported size is (near) zero under legacy semantics...
    assert_eq!(reported_size, 0);

    // ...while the true bytes touched during the failed load (sum of the large
    // accounts' sizes plus base overhead) is much larger, demonstrating the gap
    // between real work performed and cost charged to the block-cost tracker.
    let true_bytes_touched = loaded_fee_payer_size + other_accounts_size; // as computed by test harness
    assert!(true_bytes_touched > reported_size + 1024,
        "cost-model gap: real bytes touched ({true_bytes_touched}) far exceeds \
         reported/charged loaded_accounts_data_size ({reported_size})");
}
```

Expected result: the assertion demonstrates that under `define_ltds_fee_only_semantics = false`, `loaded_accounts_data_size` reported (and thus fed into `CostModel::calculate_cost_for_executed_transaction` / `cost_tracker.try_add`) is `0`, while the actual bytes read by `load_transaction_accounts` for the large accounts is large and non-zero — confirming the cost-model gap described.

```rust
fn load_transaction_accounts<CB: TransactionProcessingCallback>(
    account_loader: &mut AccountLoader<CB>,
    message: &impl SVMMessage,
    loaded_fee_payer_account: LoadedTransactionAccount,
    loaded_tx_data_size: &mut LoadedTransactionDataSize,
    error_metrics: &mut TransactionErrorMetrics,
    rent: &Rent,
) -> Result<Vec<KeyedAccountSharedData>> {
    let account_keys = message.account_keys();
    let mut loaded_transaction_accounts = Vec::with_capacity(account_keys.len());
    let mut additional_loaded_accounts: AHashSet<Pubkey> = AHashSet::new();

    // Transactions pay a base fee per address lookup table.
    loaded_tx_data_size.increase_calculated_data_size(
        message
            .num_lookup_tables()
            .saturating_mul(ADDRESS_LOOKUP_TABLE_BASE_SIZE),
        error_metrics,
    )?;

    let mut collect_loaded_account =
        |account_loader: &mut AccountLoader<CB>, key: &Pubkey, loaded_account| -> Result<()> {
            let LoadedTransactionAccount {
                account,
                loaded_size,
            } = loaded_account;

            loaded_tx_data_size.increase_calculated_data_size(loaded_size, error_metrics)?;

            // This has been annotated branch-by-branch because collapsing the logic is infeasible.
            // Its purpose is to ensure programdata accounts are counted once and *only* once per
            // transaction. By checking account_keys, we never double-count a programdata account
            // that was explicitly included in the transaction. We also use a hashset to gracefully
            // handle cases that LoaderV3 presumably makes impossible, such as self-referential
            // program accounts or multiply-referenced programdata accounts, for added safety.
            //
            // If in the future LoaderV3 programs are migrated to LoaderV4, this entire code block
            // can be deleted.
            //
            // If this is a valid LoaderV3 program...
            if bpf_loader_upgradeable::check_id(account.owner())
                && let Ok(UpgradeableLoaderState::Program {
                    programdata_address,
                }) = bincode::deserialize(account.data())
            {
                // ...its programdata was not already counted and will not later be counted...
                if !account_keys.iter().any(|key| programdata_address == *key)
                    && !additional_loaded_accounts.contains(&programdata_address)
                {
                    // ...and the programdata account exists (if it doesn't, it is *not* a load failure)...
                    if let Some(programdata_account) =
                        account_loader.load_account(&programdata_address)
                    {
                        // ...count programdata toward this transaction's total size.
                        loaded_tx_data_size.increase_calculated_data_size(
                            TRANSACTION_ACCOUNT_BASE_SIZE
                                .saturating_add(programdata_account.data().len()),
                            error_metrics,
                        )?;
                        additional_loaded_accounts.insert(programdata_address);
                    }
                }
            }

            loaded_transaction_accounts.push((*key, account));

            Ok(())
        };

    // Since the fee payer is always the first account, collect it first.
    // We can use it directly because it was already loaded during validation.
    collect_loaded_account(
        account_loader,
        message.fee_payer(),
        loaded_fee_payer_account,
    )?;

    // Attempt to load and collect remaining non-fee payer accounts.
    for (account_index, account_key) in account_keys.iter().enumerate().skip(1) {
        let loaded_account =
            load_transaction_account(account_loader, message, account_key, account_index, rent)?;
        collect_loaded_account(account_loader, account_key, loaded_account)?;
    }
```

```rust
fn check_block_cost_limits<Tx: TransactionWithMeta>(
    bank: &Bank,
    tx_costs: &[Option<TransactionCost<'_, Tx>>],
) -> TransactionResult<()> {
    let mut cost_tracker = bank.write_cost_tracker().unwrap();
    for tx_cost in tx_costs.iter().flatten() {
        cost_tracker
            .try_add(tx_cost)
            .map_err(TransactionError::from)?;
    }

    Ok(())
}
```

```rust
// Get actual transaction execution costs from transaction commit results
fn get_transaction_costs<'a, Tx: TransactionWithMeta>(
    bank: &Bank,
    commit_results: &[TransactionCommitResult],
    sanitized_transactions: &'a [Tx],
) -> Vec<Option<TransactionCost<'a, Tx>>> {
    assert_eq!(sanitized_transactions.len(), commit_results.len());

    commit_results
        .iter()
        .zip(sanitized_transactions)
        .map(|(commit_result, tx)| {
            if let Ok(committed_tx) = commit_result {
                Some(CostModel::calculate_cost_for_executed_transaction(
                    tx,
                    committed_tx.executed_units,
                    committed_tx.loaded_account_stats.loaded_accounts_data_size,
                    &bank.feature_set,
                ))
            } else {
                None
            }
        })
        .collect()
}
```
