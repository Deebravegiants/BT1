### Title
Price aggregator is never set during controller initialization, leaving all price-dependent user paths non-operational until an admin action - (File: contracts/controller/src/governance.rs)

### Summary
The `Controller` constructor (`governance::init`) initializes the owner, position limits, borrow floor, and app version, and pauses the contract — but never sets the price aggregator address. Every downstream read of `ControllerKey::PriceAggregator` via `storage::get_price_aggregator` panics with `GenericError::AggregatorNotSet`, so every entrypoint that needs prices reverts for unprivileged users until the owner calls `set_price_aggregator`.

### Finding Description
The bug class is "required oracle dependency not wired during initialization."

- `Controller::__constructor` calls only `governance::init(&env, &admin)` (contracts/controller/src/lib.rs:83-85).
- `init` sets owner, position limits, min-borrow floor, app version, and pauses — there is no aggregator parameter and no aggregator write (contracts/controller/src/governance.rs:14-33).
- `storage::get_price_aggregator` reads `ControllerKey::PriceAggregator` and panics with `AggregatorNotSet` when absent (contracts/controller/src/storage/protocol.rs:60-65).
- All price reads funnel through `external::fetch_prices` / `fetch_prices_status`, which call `storage::get_price_aggregator` first (contracts/controller/src/external/price_aggregator.rs:18-34).

Unprivileged, price-dependent entrypoints reachable per scope:

- `borrow` — post-borrow solvency uses Context-cached strict prices (lib.rs:107-115).
- `withdraw` — post-withdrawal solvency check for accounts with debt; notably `withdraw` has no `#[when_not_paused]` guard (lib.rs:120-128), so it is reachable even while the contract is paused.
- `liquidate` — HF-based bonus curve requires prices; also unpausable (lib.rs:144-158).
- `update_account_threshold` — restamps LTV/threshold snapshots and enforces HF ≥ 1.05 WAD (lib.rs:386-388).
- Strategy entrypoints (`flash_position`, `multiply`, `swap_debt`, `swap_collateral`, `repay_debt_with_collateral`, `migrate_from_blend`) — all end with a solvency check that fetches prices.
- `claim_revenue` does not need prices, and `repay`/`recapitalize`/`clean_bad_debt` may succeed, but the core risk-bearing flows are dead.

### Impact Explanation
Temporary freezing of user funds and protocol insolvency exposure. With an unset aggregator, a supplier with outstanding debt cannot `withdraw`, no liquidator can `liquidate` an underwater account, and no user can `borrow` or run any strategy — all calls revert at `storage::get_price_aggregator` with `AggregatorNotSet`. Positions can enter and funds can be at risk while liquidation is impossible. Recovery requires an owner `set_price_aggregator` call, so the freeze is temporary rather than permanent, matching the source report's "partially non-operational until set" impact.

### Likelihood Explanation
This is an initialization-ordering gap rather than an attack: it materializes if the deployment sequence enables any user flow before `set_price_aggregator` is called, or if the aggregator key is ever absent (e.g., fresh deployment, or a redeployed/upgraded storage state). Because `withdraw`, `liquidate`, `repay`, and `clean_bad_debt` are not pause-gated, the window exists even while the contract is nominally paused — users can repay but cannot withdraw or be liquidated. Likelihood is moderate, consistent with a Medium.

### Recommendation
Accept the price aggregator address as a `__constructor` parameter and store it in `governance::init`, alongside the pool-creation prerequisites, so no unprivileged entrypoint can be exercised against a missing oracle. Alternatively, gate `unpause` on `ControllerKey::PriceAggregator` being set, or keep `withdraw`/`liquidate` fail-open only after aggregator configuration is confirmed. Emitting an event on `init` that records the aggregator address would also surface misconfiguration at deploy time.

### Proof of Concept
```rust
// Deploy Controller with __constructor(admin). Do NOT call set_price_aggregator.
// Setup: a supply position exists for account_id = 1 (positions can exist once
// any supply was processed while unpaused, or via a prior configuration).

// Unprivileged liquidation attempt — reverts:
controller.liquidate(
    &liquidator,
    &1u64,
    &vec![&env, (hub_asset, payment_amount)],
    &SeizeMode::Transfer,
);
// Panics: GenericError::AggregatorNotSet at
// contracts/controller/src/storage/protocol.rs:64 via
// external::fetch_prices -> storage::get_price_aggregator.

// Unprivileged withdraw attempt by the account owner — also reverts
// even though withdraw is not pause-gated:
controller.withdraw(&owner, &1u64, &vec![&env, (hub_asset, amount)], &None);
// Panics: GenericError::AggregatorNotSet during the post-withdrawal solvency check.
```

Note: I could not fully confirm within the available iterations whether `withdraw`/`liquidate` short-circuit price fetching for zero-debt or fully-dry accounts, but the revert is unconditional for any call that consults prices, which includes all borrows, all liquidations, all strategies, and withdrawals on debt-bearing accounts.
