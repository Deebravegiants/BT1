Audit Report

## Title
Unbounded growth of the JWT replay-protection cache in `WorkflowMetadataHandler` leads to memory-exhaustion DoS - ([File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go])

## Summary
`WorkflowMetadataHandler.Authorize` unconditionally records every successfully-verified JWT's `jti` into an unbounded in-memory map (`jwtReplayCache.cache`) before the HTTP trigger handler applies its rate limit. Since `authorizeRequest` executes strictly before `checkRateLimit` in `HandleUserTriggerRequest`, and the cache is only pruned once per `JWTReplayPeriodMs` (default 24h) with no size cap, an authorized signer for any registered workflow can force unbounded cache growth for up to 24 hours, unlike the sibling `RequestCache` type which enforces an explicit `maxCacheSize`.

## Finding Description
`HandleUserTriggerRequest` calls `h.authorizeRequest` (which invokes `WorkflowMetadataHandler.Authorize`) prior to `h.checkRateLimit`: [1](#0-0) 

`Authorize` verifies the JWT signature, checks replay via `isReplay`, checks the signer is in the workflow's `authorizedKeys`, and then unconditionally calls `h.jwtCache.recordUsage(claims.ID)`: [2](#0-1) 

`recordUsage` writes into the map with no size check: [3](#0-2) 

This contrasts with the sibling `requestCache` type in the gateway package, which explicitly enforces `maxCacheSize` and rejects new entries once full: [4](#0-3) 

The only pruning mechanism for `jwtReplayCache` is a ticker that runs once every `cleanupPeriod` (`JWTReplayPeriodMs`, default 24 hours, i.e. `defaultJWTReplayPeriodMs = 1000 * 60 * 60 * 24`): [5](#0-4) [6](#0-5) 

Because `jti` is a caller-controlled JWT claim only required to be unique for replay detection, and `checkRateLimit` runs only after `recordUsage` has already executed, the gateway's per-workflow trigger rate limiter does not bound how many distinct entries get inserted into `jwtCache.cache` — it only throttles what happens after insertion (trigger dispatch). No other size bound exists on this map before the next cleanup tick fires.

## Impact Explanation
Any caller who holds a signer key already authorized for at least one deployed workflow's HTTP trigger can send an arbitrary number of validly-signed, uniquely-`jti` JWTs to the gateway's trigger endpoint. Each request inserts a new entry into `jwtReplayCache.cache` regardless of the outcome of the subsequent rate-limit check, so the map can grow unbounded for up to the full `JWTReplayPeriodMs` window (24h by default), consuming gateway process memory and increasing mutex contention on `jwtCache.mu`. This is a genuine availability/DoS impact on gateway infrastructure shared by all workflows/DON members routed through it, reachable from the internet-facing HTTP trigger endpoint without any node/operator privilege — only possession of a workflow-authorized signer key is required.

## Likelihood Explanation
Moderate: exploitation requires holding a legitimate signer key registered as an authorized key for at least one workflow (i.e., being an intended caller of that workflow, not an arbitrary unauthenticated party), but no elevated node/operator/DON access is needed. Generating many distinct, validly-signed JWTs is computationally cheap once the key is held, and the lack of any cache size cap combined with the 24-hour cleanup window makes sustained abuse straightforward.

## Recommendation
Add an explicit maximum size to `jwtReplayCache` (mirroring `requestCache.maxCacheSize`) and reject or evict oldest entries when the cap is reached. Consider more frequent/incremental cleanup (e.g., per-entry TTL sweeps) independent of the full `JWTReplayPeriodMs`, and/or enforce per-signer/per-workflow insertion limits into the JWT cache ahead of, or alongside, `recordUsage`, so a single authorized caller cannot unboundedly grow the cache regardless of downstream rate limiting.

## Proof of Concept
1. Obtain/be an authorized signer for a workflow with an HTTP trigger registered on the gateway (populated via `syncMetadata`'s `authorizedKeys`).
2. Repeatedly send `workflows.execute` requests to the gateway's HTTP trigger endpoint, each with a freshly, validly ECDSA-signed JWT containing a unique `jti` claim.
3. Each request causes `Authorize` → `recordUsage(claims.ID)` to add an entry to `jwtCache.cache` before `checkRateLimit` executes.
4. Because cleanup only runs once per `JWTReplayPeriodMs` (default 24h), repeat requests at sufficient rate/volume to observe `jwtCache.cache` size (exposed via `RecordJwtCacheSize` metric) grow proportionally with request count, unconstrained by the trigger rate limiter.

```go
func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}
```

```go
func (cache *jwtReplayCache) recordUsage(jti string) {
	cache.mu.Lock()
	defer cache.mu.Unlock()

	cache.cache[jti] = time.Now()
}
```

```go
func NewRequestCache[T any](timeout time.Duration, maxCacheSize uint32) RequestCache[T] {
	return &requestCache[T]{cache: make(map[globalID]*pendingRequest[T]), timeout: timeout, maxCacheSize: maxCacheSize}
}

func (c *requestCache[T]) NewRequest(lggr logger.Logger, request *api.Message, callback handlers.Callback, responseData *T) error {
	if request == nil {
		return errors.New("request is nil")
	}
	if responseData == nil {
		return errors.New("responseData is nil")
	}
	key := globalID{request.Body.Sender, request.Body.MessageID}
	c.mu.Lock()
	defer c.mu.Unlock()
	_, ok := c.cache[key]
	if ok {
		return errors.New("request already exists")
	}
	if len(c.cache) >= int(c.maxCacheSize) {
		return errors.New("request cache is full")
	}
```
