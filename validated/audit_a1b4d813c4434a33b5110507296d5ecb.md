Audit Report

## Title
Internal error messages from the Vault secrets-service are relayed verbatim to unauthenticated gateway clients - ([File: core/capabilities/vault/gw_handler.go])

## Summary
`GatewayHandler.errorResponse` and `gatewayErrorResponse` in `core/capabilities/vault/gw_handler.go` place the raw `error.Error()` string from internal failures (key-value store errors, encryption/master-key errors, marshalling errors) directly into the `jsonrpc.WireError.Message` field of node responses sent to the gateway. Critically, the gateway-side `handler.sendSuccessResponse` in `core/services/gateway/handlers/vault/handler.go` forwards the quorum-aggregated node response — including any `resp.Error.Message` — straight to the external HTTP client via `jsonrpc.EncodeResponse(resp)`, with no equivalent to the `errorResponse` sanitization switch that exists elsewhere in the same file for gateway-originated errors (e.g., `api.NodeReponseEncodingError` case explicitly "hides the error from the user").

## Finding Description
On the node side, `errorResponse` (`core/capabilities/vault/gw_handler.go:388-410`) unconditionally sets `Message: err.Error()` and is invoked from every failure path (`handleSecretsCreate`/`Update`/`Delete`/`List`, `getMasterPublicKey`, `gatewayErrorResponse`) with raw or lightly-wrapped internal errors, not a curated user-facing string. [1](#0-0) 

That node response is sent to the gateway and handled in `handler.HandleNodeMessage` (`core/services/gateway/handlers/vault/handler.go:480-534`), which passes it through `baseAggregator.Aggregate` for either signature validation or quorum validation, then calls `sendSuccessResponse`. [2](#0-1) 

`sendSuccessResponse` encodes the aggregated response — error message included — and returns it to the user unchanged; it does not route through `h.errorResponse`'s sanitization switch (which exists in the same file and, for example, explicitly strips the error text for `api.NodeReponseEncodingError`). [3](#0-2) [4](#0-3) 

Because the vault DON nodes replicate consistent state via OCR, a request that deterministically fails on the backing store/service (e.g., hitting `MaxSecretsPerOwner`, a key-derivation failure, or a KV-store error) will very plausibly produce identical error responses across a quorum of nodes, satisfying `validateUsingQuorum` and causing the raw internal error text to be returned as the winning aggregated response. This bypasses the sanitization pattern already present in the OCR2 plugin's `userFacingError()` helper (`core/services/ocr2/plugins/vault/plugin.go:1247-1253`), which classifies errors and only surfaces `vaulttypes.UserError` text, falling back to a generic message for anything else. [5](#0-4) 

## Impact Explanation
An unauthenticated/authorized-but-untrusted external client reaching the gateway's Vault HTTP endpoint can, through the quorum-aggregation path, receive verbatim internal error text originating from the node-side `SecretsService`/key-value store rather than a sanitized message. This is an information-disclosure issue (confidentiality-only, no direct integrity/availability impact) consistent with leaking internal implementation details (storage backend error text, limiter internals) that a Vault-handling component should redact.

## Likelihood Explanation
Any client that can route a `vaulttypes.MethodSecretsCreate/Update/Delete/List` request through the gateway can attempt to trigger a deterministic backend failure (e.g., exceeding secret limits). Because vault nodes operate on replicated/consistent state, a quorum of nodes is likely to fail identically and pass `validateUsingQuorum`, causing the unsanitized error text to be relayed to the requester via `sendSuccessResponse`. This requires passing whatever authorization the request pipeline enforces up to the fan-out point, but no operator/admin privilege is needed.

## Recommendation
Add an explicit sanitization step in the gateway-side `sendSuccessResponse` (and/or in the node-side `GatewayHandler.errorResponse`/`gatewayErrorResponse`) analogous to `userFacingError()`, mapping non-user-classified errors to a fixed generic message before they are encoded and returned to the external client, while logging the raw error server-side only.

## Proof of Concept
1. Send repeated `vaulttypes.MethodSecretsCreate` requests for the same owner until `MaxSecretsPerOwner` is exceeded, causing the backing `SecretsService`/store to return a deterministic error on every vault node.
2. Observe that a quorum of nodes returns byte-identical `jsonrpc.WireError` responses containing the raw internal error string set by `GatewayHandler.errorResponse` in `core/capabilities/vault/gw_handler.go`.
3. Confirm the gateway's `validateUsingQuorum` (`core/services/gateway/handlers/vault/aggregator.go:136-186`) selects this response and `sendSuccessResponse` (`core/services/gateway/handlers/vault/handler.go:585-611`) relays it to the HTTP client unmodified — i.e., the JSON-RPC `error.message` in the HTTP response body is the raw internal error text rather than a generic sanitized message.

func (h *GatewayHandler) errorResponse(
	ctx context.Context,
	gatewayID string,
	req *jsonrpc.Request[json.RawMessage],
	errorCode api.ErrorCode,
	err error,
) *jsonrpc.Response[json.RawMessage] {
	h.requestLogger(req, gatewayID).Errorw("gateway handler error response", "errorCode", errorCode, "error", err)
	h.metrics.requestInternalError.Add(ctx, 1, metric.WithAttributes(
		attribute.String("gateway_id", gatewayID),
		attribute.String("error", errorCode.String()),
	))

	return &jsonrpc.Response[json.RawMessage]{
		Version: jsonrpc.JsonRpcVersion,
		ID:      req.ID,
		Method:  req.Method,
		Error: &jsonrpc.WireError{
			Code:    api.ToJSONRPCErrorCode(errorCode),
			Message: err.Error(),
		},
	}
}

func (h *handler) sendSuccessResponse(ctx context.Context, l logger.Logger, ar *activeRequest, resp *jsonrpc.Response[json.RawMessage]) error {
	// Strip the owner prefix from the response ID before sending it back to the user
	// This ensures compliance with JSONRPC 2.0 spec, which requires response id to match request id
	index := strings.Index(resp.ID, vaulttypes.RequestIDSeparator)
	if index != -1 {
		resp.ID = resp.ID[index+2:]
	}
	rawResponse, err := jsonrpc.EncodeResponse(resp)
	if err != nil {
		l.Errorw("failed to encode response", "error", err)
		return h.sendResponse(ctx, ar, h.errorResponse(ar.req, api.NodeReponseEncodingError, fmt.Errorf("failed to marshal response: %w", err), nil))
	}

	var errorCode api.ErrorCode
	if resp.Error != nil {
		errorCode = api.FromJSONRPCErrorCode(resp.Error.Code)
	} else {
		errorCode = api.NoError
	}

	l.Debugw("issued user callback", "errorCode", errorCode)
	successResp := gwhandlers.UserCallbackPayload{
		RawResponse: rawResponse,
		ErrorCode:   errorCode,
	}
	return h.sendResponse(ctx, ar, successResp)
}

func (h *handler) errorResponse(
	req jsonrpc.Request[json.RawMessage],
	errorCode api.ErrorCode,
	err error,
	data []byte,
) gwhandlers.UserCallbackPayload {
	switch errorCode {
	case api.FatalError:
	case api.NodeReponseEncodingError:
		h.lggr.Errorw(err.Error(), "requestID", req.ID)
		// Intentionally hide the error from the user
		err = errors.New(errorCode.String())
	case api.InvalidParamsError:
		h.lggr.Errorw("invalid params", "requestID", req.ID, "error", err.Error())
		err = errors.New("invalid params error: " + err.Error())
	case api.UnsupportedMethodError:
		h.lggr.Errorw("unsupported method", "requestID", req.ID, "method", req.Method, "error", err.Error())
		err = errors.New("unsupported method(" + req.Method + "): " + err.Error())
	case api.UserMessageParseError:
		h.lggr.Errorw("user message parse error", "requestID", req.ID, "error", err.Error())
		err = errors.New("user message parse error: " + err.Error())
	case api.NoError:
	case api.UnsupportedDONIdError:
	case api.ConflictError:
	case api.HandlerError:
	case api.LimitExceededError:
	case api.RequestTimeoutError:
	case api.StaleNodeResponseError:
		// Unused in this handler
	}

	// Strip the owner prefix from the json response ID before sending it back to the user
	// This ensures compliance with JSONRPC 2.0 spec, which requires response id to match request id
	index := strings.Index(req.ID, vaulttypes.RequestIDSeparator)
	if index != -1 {
		req.ID = req.ID[index+2:]
	}

	return gwhandlers.UserCallbackPayload{
		RawResponse: h.codec.EncodeNewErrorResponse(
			req.ID,
			api.ToJSONRPCErrorCode(errorCode),
			err.Error(),
			data,
		),
		ErrorCode: errorCode,
	}
}

func userFacingError(err error, fallback string) string {
	if vaulttypes.IsUserError(err) {
		return err.Error()
	}

	return fallback
}
