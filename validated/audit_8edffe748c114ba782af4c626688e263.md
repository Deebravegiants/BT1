### Title
`retryPayload` bypasses the pause switch, allowing forced LZ message delivery while the endpoint is paused - (File: `sdk/packages/lz-endpoint/contracts/HyperbridgeLzEndpoint.sol`)

### Summary
`HyperbridgeLzEndpoint` gates every other message-affecting entry point — `send`, `onAccept` — with `whenNotPaused`, but `retryPayload`, the permissionless function that delivers a previously failed inbound message to an OApp, has no such gate.

### Finding Description
`onAccept` decodes an inbound ISMP post request and calls `lzReceive` on the destination OApp; if that call reverts, the payload hash is stored for later retry [1](#0-0) . `onAccept` itself requires `whenNotPaused` [2](#0-1) , and `send` requires it too [3](#0-2) , following the same design used consistently across `HyperFungibleToken`, `WrappedHyperFungibleToken`, and their upgradeable variants (`send`, `onAccept`, `onPostRequestTimeout` all carry `whenNotPaused`).

`retryPayload`, however, is declared without `whenNotPaused`: [4](#0-3) 

It is explicitly documented as mirroring `onAccept`'s direct call into the OApp ("Mirrors `{onAccept}`'s direct call to the OApp ... Permissionless: anyone may push a stuck payload through"), so it performs the exact same privileged action (`ILayerZeroReceiver.lzReceive` delivery to an arbitrary OApp) that `onAccept` performs, but without the pause check that `onAccept` enforces.

`sendCompose` and `lzCompose` (queueing/executing compose messages, also part of the message-delivery surface) are likewise missing `whenNotPaused` [5](#0-4) .

### Impact Explanation
Governance pauses this contract via `pause()` specifically to stop all cross-chain send/receive activity [6](#0-5) , e.g., in response to a discovered exploit in a connected OApp, a compromised source chain, or a malformed/malicious stored payload. Because `retryPayload` is unprotected, any address can still force delivery of any previously-stored failed inbound message to its destination OApp while the contract is supposedly paused, completely defeating the purpose of the pause for messages that already failed once and are sitting in the retry queue. This can result in unauthorized app actions/state changes on connected OApps during a period governance intended to halt exactly that class of behavior.

### Likelihood Explanation
Likelihood is high in the specific scenario the pause exists for: an operator pauses the endpoint after noticing a problem with inbound deliveries (e.g., a malicious/malformed payload that should not be retried). Any single unprivileged relayer/caller can immediately invoke `retryPayload` — it takes no special permissions — to push the delivery through anyway, exactly the scenario the referenced report's transfer-lock example illustrates.

### Recommendation
Add the `whenNotPaused` modifier to `retryPayload`, and consider also adding it to `sendCompose`/`lzCompose` for consistency with the rest of the message-delivery surface, so that pausing the contract fully halts inbound message delivery, including deferred retries.

### Proof of Concept
1. Governance calls `pause()` on `HyperbridgeLzEndpoint` after learning that a previously failed inbound payload (stored via the `onAccept` catch branch) is malicious or should not be executed.
2. Because `paused == true`, a fresh `onAccept` call would revert, and `send` would revert too — but the stored payload from before the pause still exists in `_inboundPayloadHashes`.
3. Any address calls `retryPayload(receiver, origin, guid, message)` with the matching stored data [4](#0-3) ; since the function has no `whenNotPaused` check, it succeeds and calls `lzReceive` on the target OApp, delivering the message despite the pause.

    function retryPayload(
        address receiver,
        Origin calldata origin,
        bytes32 guid,
        bytes calldata message
    ) external payable {
        bytes32 stored = _inboundPayloadHashes[receiver][origin.srcEid][origin.sender][origin.nonce];
        if (stored == bytes32(0) || stored == NIL_PAYLOAD_HASH || stored != keccak256(abi.encode(guid, message))) {
            revert InvalidPayloadHash();
        }

        // Clear first; if the retry reverts, this deletion rolls back with the rest of the tx and
        // the payload remains recoverable.
        delete _inboundPayloadHashes[receiver][origin.srcEid][origin.sender][origin.nonce];

        ILayerZeroReceiver(receiver).lzReceive{value: msg.value}(origin, guid, message, msg.sender, "");
        emit InboundPayloadResolved(receiver, origin.srcEid, origin.sender, origin.nonce);
    }

     * @param _from The OApp that initiated the compose
     * @param _to The target ILayerZeroComposer
     * @param _guid The message guid
     * @param _index The compose message index
     * @param _message The composed message payload (must match the queued hash)
     * @param _extraData Additional data passed to the composer
     */
    function lzCompose(
        address _from,
        address _to,
        bytes32 _guid,
        uint16 _index,
        bytes calldata _message,
        bytes calldata _extraData
    ) external payable override {
        bytes32 key = keccak256(abi.encodePacked(_from, _to, _guid, _index));
        bytes32 expectedHash = _composeQueue[key];
        if (expectedHash == bytes32(0) || expectedHash != keccak256(_message)) revert InvalidCompose();

        delete _composeQueue[key];

        ILayerZeroComposer(_to).lzCompose{value: msg.value}(_from, _guid, _message, msg.sender, _extraData);
        emit ComposeDelivered(_from, _to, _guid, _index);
    }
