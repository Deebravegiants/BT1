### Title
Unauthenticated `intents_getBidsForOrder` RPC discloses in-flight solver `user_op` bid payloads before block inclusion, enabling bid-copying/front-running of intent fills - (File: modules/pallets/intents-coprocessor/rpc/src/lib.rs)

### Summary
The `pallet-intents-coprocessor` RPC module exposes `intents_getBidsForOrder` and `intents_subscribeBids` over the node's public JSON-RPC/websocket interface with no authentication or access control, comparable to Capgo's `get_org_members` — any caller who can reach the RPC endpoint can query or subscribe to sensitive, not-yet-finalized bid data (`filler` address and full `user_op` calldata) for any order commitment, before the winning solver's transaction is ever included in a block.

### Finding Description
`get_bids_for_order` merges two unauthenticated sources of pending bid data:
1. An in-memory `BidCache` populated straight from the transaction pool via `run_bid_watcher`, which decodes every `place_bid` extrinsic sitting in the mempool [1](#0-0) .
2. On-chain `Bids` storage plus the offchain-indexed payload, read directly through `StorageProvider`/offchain storage without any origin check [2](#0-1) .

The RPC trait registers both the query and a live subscription with no `deny_unsafe`/auth guard, unlike other node RPC modules that at least gate "unsafe" calls: [3](#0-2) . It is wired directly into the node's public RPC surface in `parachain/node/src/rpc.rs` alongside `System`/`TransactionPayment`, with no `deny_unsafe` parameter passed to `IntentsRpcHandler::new` [4](#0-3) .

Critically, the mempool path exposes bids **before they are even included in a block** — `run_bid_watcher` decodes `place_bid` extrinsics straight out of `pool.import_notification_stream()`/`ready_transaction` [5](#0-4) , and the module's own doc comment confirms the design intent is "sub-second bid discovery" [1](#0-0) . `place_bid` itself only requires `ensure_signed`, imposing no restriction on who may query or copy bid content once observed [6](#0-5) .

### Impact Explanation
This is directly reachable by any unprivileged intent solver ("bandwidth purchaser"/filler) or arbitrary network participant able to open an RPC/WebSocket connection to a Hyperbridge collator/full node — no privileged role is required, matching the "unauthenticated actor with only public access" pattern in the Capgo report. Because a solver's full `user_op` (the signed UserOperation encoding output tokens, amounts, and fill strategy) is disclosed the instant it hits any node's mempool, a competing solver can:
- Observe a legitimate filler's bid via `intents_subscribeBids`/`intents_getBidsForOrder` before it is finalized.
- Submit its own `place_bid` with a marginally better price (undercutting by the minimum increment) to win the intent-order auction that the honest solver discovered, priced, and was first to bid on.

This constitutes theft of the fill opportunity/fee that would otherwise accrue to the originating solver — i.e., a route by which economic value that would have gone to one bidder is redirected to another purely via a public data-disclosure primitive, mirroring the "unauthenticated enumeration of sensitive data via public RPC" bug class from the CVE, applied to the intents-escrow/bid subsystem explicitly in-scope for this analysis. It does not directly enable an unbacked mint or forged message delivery, so I rate it Medium.

### Likelihood Explanation
High likelihood of exploitation: the RPC method and subscription are unauthenticated by construction (no `deny_unsafe` guard, no capability check), require only a standard JSON-RPC client, and the bid data is generated automatically for every `place_bid` transaction — an attacker needs no special access, only a connection to any Hyperbridge full node exposing default RPC ports (mempool visibility is described as an intentional design goal, increasing the certainty this path is live in production deployments).

### Recommendation
- Rate-limit and/or require an allow-listed/rotating API key for `intents_getBidsForOrder` and `intents_subscribeBids`, or restrict them behind `deny_unsafe`/authenticated RPC namespaces the way privileged Substrate RPC calls typically are.
- Consider redacting or encrypting `user_op` payloads in the mempool-sourced `BidCache` until the bid is finalized/selected, exposing only enough metadata (e.g., commitment + price) for legitimate bid discovery without leaking full execution calldata that a copier can resubmit verbatim.
- Add a minimum bid-improvement delta or commit-reveal scheme for `place_bid` so that observing a competitor's bid does not trivially allow undercutting it by an arbitrarily small amount.

### Proof of Concept
1. Attacker connects to any Hyperbridge parachain node's public RPC endpoint (no credentials needed) and calls `intents_subscribeBids` (optionally filtered by `commitment`), per the trait defined at [7](#0-6) .
2. A legitimate solver submits `place_bid(commitment, user_op)` for an order it has priced competitively; the extrinsic enters the mempool.
3. `run_bid_watcher` immediately decodes the extrinsic via `extract_bid` and pushes `RpcBidInfo { commitment, filler, user_op }` to all subscribers before the block containing it is even produced [8](#0-7) .
4. The attacker decodes `user_op`, extracts the offered outputs, and submits its own `place_bid` with a marginally improved output/lower fee for the same `commitment`.
5. When the order's bid-selection logic runs (client-side `sortBids`/`selectAndExecuteBest`, e.g. [9](#0-8) ), the attacker's copied/undercut bid is selected instead of the original solver's, diverting the fill and its associated fee to the attacker.

Note: I was unable to fully trace the exact bid-comparison/selection algorithm inside the on-chain pallet (only the SDK-side sorting logic was found), so the precise minimum-undercut economics and whether an on-chain tie-break exists could not be fully confirmed from the indexed files — a Devin session with full repo access would be needed to verify the exact `sortBids`/on-chain settlement comparator logic.

	fn get_bids_for_order(&self, commitment: H256) -> RpcResult<Vec<RpcBidInfo>> {
		// Get mempool bids from in-memory cache
		let mut bids =
			self.bid_cache.get_bids(&commitment).map_err(runtime_error_into_rpc_error)?;

		// Query on-chain bids via StorageProvider and read bid data from offchain storage.
		let best_hash = self.client.info().best_hash;
		let prefix = bids_storage_prefix(&commitment);
		let prefix_key = sp_core::storage::StorageKey(prefix.clone());

		let keys = self
			.client
			.storage_keys(best_hash, Some(&prefix_key), None)
			.map_err(runtime_error_into_rpc_error)?;

		const MAX_ON_CHAIN_BIDS: usize = 30;

		for key in keys.take(MAX_ON_CHAIN_BIDS) {
			// Key layout after prefix: blake2_128(filler) ++ filler_encoded
			let filler_start = prefix.len() + 16;
			if key.0.len() > filler_start {
				let filler_encoded = &key.0[filler_start..];

				let offchain_key =
					pallet_intents_coprocessor::offchain_bid_key_raw(&commitment, filler_encoded);

				if let Some(data) = self.offchain_storage.get(STORAGE_PREFIX, &offchain_key) {
					// Bid encoding: filler.encode() ++ user_op.encode()
					if data.len() > filler_encoded.len() {
						if let Ok(user_op) = Vec::<u8>::decode(&mut &data[filler_encoded.len()..]) {
							bids.insert(RpcBidInfo {
								commitment,
								filler: filler_encoded.to_vec(),
								user_op,
							});
						}
					}
				}
			}
		}

		Ok(bids.into_iter().collect())

		#[pallet::call_index(0)]
		#[pallet::weight(T::WeightInfo::place_bid())]
		pub fn place_bid(
			origin: OriginFor<T>,
			commitment: H256,
			user_op: BoundedVec<u8, ConstU32<1_048_576>>,
		) -> DispatchResult {
			let filler = ensure_signed(origin)?;

			// Validate user_op is not empty
			ensure!(!user_op.is_empty(), Error::<T>::InvalidUserOp);

			// Phantom orders have stricter rules: one bid per filler, no updates, and only
			// within the configured acceptance window after the order was registered. Every
			// chain's active order is checked, not just the most recently generated one.
			if let Some(active) = CurrentPhantomOrder::<T>::get() {
				if let Some((_, info)) = active.iter().find(|(c, _)| *c == commitment) {
					let window: BlockNumberFor<T> = Self::phantom_bid_window().into();
					ensure!(
						frame_system::Pallet::<T>::block_number() <= info.created_at_block + window,
						Error::<T>::PhantomOrderBidWindowClosed
					);
					ensure!(
						!Bids::<T>::contains_key(&commitment, &filler),
						Error::<T>::DuplicatePhantomBid
					);
				}
			}

			// If a bid already exists, unreserve the old deposit first
			if let Some(old_deposit) = Bids::<T>::get(&commitment, &filler) {
				<T as Config>::Currency::unreserve(&filler, old_deposit);
			}

			let deposit = Self::storage_deposit_fee();

			// Reserve the new deposit
			<T as Config>::Currency::reserve(&filler, deposit)
				.map_err(|_| Error::<T>::InsufficientBalance)?;

			// Store the bid in offchain storage
			let bid = Bid { filler: filler.clone(), user_op: user_op.to_vec() };
			let offchain_key = Self::offchain_bid_key(&commitment, &filler);
			offchain_index::set(&offchain_key, &bid.encode());

			// Store deposit amount in onchain storage for discoverability and accurate refunds
			Bids::<T>::insert(&commitment, &filler, deposit);

			Self::deposit_event(Event::BidPlaced { filler, commitment, deposit });

			Ok(())
		}
