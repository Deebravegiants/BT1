## Finding: Stale `TombStone.original_owner` Survives Ungated Transfers, Enabling Object Hijack via BURN_ADDRESS

### Title
Object soft-burn `TombStone` is not cleared on ungated transfers, allowing a prior owner to reclaim an object away from its legitimate current owner - (File: `aptos-move/framework/aptos-framework/sources/object.move`)

### Summary
Aptos's `object` module implements a "soft burn" mechanism (`TombStone`) that records the `original_owner` of an object when it is marked as burnt. This record is only cleared when ownership is later changed via `transfer_with_ref` (a privileged `TransferRef`-gated transfer). It is **not** cleared by the normal, unprivileged ungated-transfer path (`transfer`, `transfer_call`, `transfer_raw`, `transfer_to_object`). Any current owner of an object can therefore plant a stale `TombStone{original_owner: self}` on it, then transfer the object away through ordinary means. If that object is ever later sent to the well-known `BURN_ADDRESS` (a pattern the module itself defines and that many apps use as a "destroy this object" convention), the original planting owner - not the actual sender who intended to burn it - can reclaim the object via `unburn`.

### Finding Description
`object::burn` (soft burn) only checks current ownership and the absence of an existing tombstone before attaching a `TombStone`; it does not disable transfers: [1](#0-0) 

Normal ungated transfers (`transfer`, `transfer_call`, `transfer_raw`) go through `transfer_raw_inner`, which only updates `owner` and emits an event - it never inspects or removes an existing `TombStone`: [2](#0-1) 

Only the privileged, `TransferRef`-derived `transfer_with_ref` path clears a stale tombstone, and the code comment even acknowledges the reason: to prevent exactly this kind of stale-reclaim: [3](#0-2) 

`unburn` then allows reclaim either by the *current* owner (harmless no-op cleanup) or - critically - by the tombstone's recorded `original_owner` whenever the object's *current* owner happens to be `BURN_ADDRESS`: [4](#0-3) 

`BURN_ADDRESS` is a fixed, documented constant (`0xff…ff`) that the module itself uses as the canonical "burn" destination (and which the now test-only `burn_object_with_transfer` used to send objects to): [5](#0-4) [6](#0-5) 

**Attack path:**
1. Attacker owns object `O` (e.g., a token-v2 NFT, or any object wrapping value such as a fungible store) with `allow_ungated_transfer = true` (the default).
2. Attacker calls `object::burn(attacker, O)`. This creates `TombStone{original_owner: attacker}` while `O.owner` stays `attacker`. No transfer restriction is applied.
3. Attacker transfers `O` normally (sale, gift, marketplace trade, etc.) via `object::transfer`/`transfer_call` to Victim. `transfer_raw_inner` updates `owner = Victim` but leaves the stale `TombStone{original_owner: attacker}` in place.
4. At some later point, Victim (or any application Victim uses) sends `O` to `BURN_ADDRESS` - a documented, intentional "destroy this object" idiom in the object model - via an ordinary `object::transfer_call(victim, O, BURN_ADDRESS)`.
5. Attacker calls `object::unburn(attacker, O)`. Since `O.owner == BURN_ADDRESS` and `TombStone.original_owner == attacker`, the check passes and `O` is transferred back to **Attacker**, not to Victim who performed the burn.

The custody invariant broken: object ownership/control metadata (`TombStone.original_owner`) must not outlive a legitimate change of controller through the standard transfer path; only privileged code paths should be able to grant "reclaim" rights, and reclaim rights must always track the *actual* party who most recently sent the object to the burn state, not a stale value planted by an unrelated prior owner.

### Impact Explanation
This breaks object ownership control: an unprivileged, prior owner can pre-poison any object they control so that, at a time entirely of their choosing, when that object is later legitimately burned/destroyed by a subsequent (unrelated) owner, the value is redirected back to the attacker instead of being permanently locked/burned as the actual owner intended. This is a direct owner-reassignment vulnerability affecting any object-held value (NFTs, primary/secondary fungible-asset stores owned by objects, resource-account-controlled objects, etc.), satisfying "unauthorized takeover... owner reassignment... tied to live assets" and "theft of object-held value" in the Custody Impact Gate.

### Likelihood Explanation
The precondition (object sent to `BURN_ADDRESS`) requires the *current* owner (or an app acting on their behalf) to voluntarily transfer to that specific address - this is a real, common on-chain idiom for "destroying" transferable objects since arbitrary objects generally cannot be deleted (no `DeleteRef` in circulation) and `BURN_ADDRESS` is the framework's own documented mechanism for this. The exploit itself requires no privilege beyond owning the object once (step 1-3), and the attacker does not need to control when/if the victim burns it - it is a "plant and wait" attack that works passively against any downstream owner in the transfer chain who eventually uses the canonical burn pattern.

### Recommendation
- Clear any existing `TombStone` in `transfer_raw_inner` (or in `transfer_raw`/`transfer_call`) whenever the ungated-transfer path changes ownership, mirroring the behavior already implemented in `transfer_with_ref`.
- Alternatively/additionally, disallow `burn` from leaving the object transferable at all (e.g., force `disable_ungated_transfer` semantics as part of `burn`), so a soft-burnt object cannot silently change hands without going through a controlled path that clears the tombstone.

### Proof of Concept
```move
#[test(attacker = @0xA11CE, victim = @0xB0B)]
fun test_tombstone_hijack(attacker: &signer, victim: &signer) {
    // 1. Attacker creates and owns an object.
    let ctor = object::create_object(signer::address_of(attacker));
    let obj: object::Object<object::ObjectCore> = object::object_from_constructor_ref(&ctor);

    // 2. Attacker soft-burns it (TombStone{original_owner: attacker}), ownership unchanged.
    object::burn(attacker, obj);

    // 3. Attacker sells/transfers the object normally to Victim.
    //    transfer_raw_inner does NOT clear the stale TombStone.
    object::transfer(attacker, obj, signer::address_of(victim));
    assert!(object::owner(obj) == signer::address_of(victim), 0);

    // 4. Victim later "burns" the object the normal way, sending it to BURN_ADDRESS.
    object::transfer_call(victim, object::object_address(&obj), @0xffffffffffffffffffffffffffffffffffffffffffffffffffffffffffffffff);

    // 5. Attacker reclaims the object out from under the intended burn.
    object::unburn(attacker, obj);
    assert!(object::owner(obj) == signer::address_of(attacker), 1); // Attacker now owns Victim's "burned" object.
}
```

    public fun transfer_with_ref(self: LinearTransferRef, to: address) {

        // Undo soft burn if present as we don't want the original owner to be able to reclaim by calling unburn later.
        if (exists<TombStone>(self.self)) {

        );

                from: object.owner,
                to,
            },
        );

        if (object_core.owner != to) {
            event::emit(
                Transfer {
                    object,
                    from: object_core.owner,
                    to,
                },

            object_core.owner = to;

    /// Allow origin owners to reclaim any objects they previous burnt.
    public entry fun unburn<T: key>(
        original_owner: &signer,
        object: Object<T>,
    ) {
        let object_addr = object.inner;
        assert!(exists<TombStone>(object_addr), error::invalid_argument(EOBJECT_NOT_BURNT));

        // The new owner of the object can always unburn it, but if it's the burn address, we go to the old functionality
        let object_core = borrow_global<ObjectCore>(object_addr);
        if (object_core.owner == signer::address_of(original_owner)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object_addr);
        } else if (object_core.owner == BURN_ADDRESS) {
            // The old functionality
            let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
            assert!(
                original_owner_addr == signer::address_of(original_owner),
                error::permission_denied(ENOT_OBJECT_OWNER)
            );
            transfer_raw_inner(object_addr, original_owner_addr);
        } else {
            abort error::permission_denied(ENOT_OBJECT_OWNER);
        };
    }
