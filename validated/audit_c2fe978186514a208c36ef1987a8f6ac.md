### Title
Bad-debt wipeout preserves floor-index supply claims that can drain later deposits - (`contracts/pool/src/interest.rs`)

### Summary
High severity: bad-debt socialization can reduce a market’s supply index to `SUPPLY_INDEX_FLOOR_RAW` while leaving all scaled supply shares outstanding, resurrecting otherwise wiped-out positions as positive claims against future cash. [1](#0-0) 

### Finding Description
`seize_positions` handles a bad-debt leg by converting the position’s scaled debt to RAY, socializing it through `apply_bad_debt_to_supply_index`, and then burning only the debt shares. [2](#0-1) 

`apply_bad_debt_to_supply_index` caps the write-down at the current total supplied value, computes the reduced index, and then clamps it to `SUPPLY_INDEX_FLOOR_RAW`, but it never burns or otherwise invalidates the corresponding `supplied` shares. [1](#0-0) 

This is inconsistent when `bad_debt >= total_supplied_value`: economically every supplier claim should be fully consumed, yet every old scaled share remains claimable at `index = RAY / 1000`. [3](#0-2) 

Withdrawals then convert those stale scaled shares with the floored index, pass the reserve check when new cash exists, burn the shares, and debit pool cash. [4](#0-3) 

The controller reaches this path through permissionless `clean_bad_debt`, which requires outstanding debt, `total_debt > total_collateral`, and collateral at or below `BAD_DEBT_USD_THRESHOLD`. [5](#0-4) [6](#0-5) 

### Impact Explanation
An attacker who holds supply shares in the debt market before the wipeout retains a positive residual claim after `clean_bad_debt`. When a victim later supplies that asset, the attacker can withdraw the stale claim and receive the victim’s newly deposited cash, leaving the victim’s honest claim under-backed or unpaid. [7](#0-6) [8](#0-7) 

The in-repo test demonstrates the exact failure mode: a `2_000_000` bad-debt write-down against `1_000_000` scaled supply clamps the index to the floor, leaves a stranded claim, and that claim drains exactly a later deposit of equal size. [8](#0-7) 

### Likelihood Explanation
The trigger is permissionless once an account becomes insolvent with dust-sized collateral, either directly through `clean_bad_debt` or automatically after a liquidation leaves socializable bad debt. [5](#0-4) [9](#0-8) 

An unprivileged attacker can control the bad-debt account through ordinary `supply` and `borrow` calls and separately hold survivor supply shares in the borrowed market. [10](#0-9) 

No privileged call, oracle dishonesty, leaked key, or malformed token behavior is required; ordinary adverse price movement and debt-index accrual can create the insolvency, while the cleanup itself creates the inconsistent share/index state. [11](#0-10) 

### Recommendation
Do not clamp the supply index to a positive floor while retaining pre-write-down scaled shares as live claims. For a full or floor-crossing write-down, explicitly invalidate the old share epoch or synchronously clear all affected claims, then reset the market index for new deposits under a new epoch. At minimum, block new supply and withdrawals until old positions are migrated or written off consistently, and add an end-to-end regression test proving that a post-wipeout survivor cannot withdraw a later depositor’s cash. [1](#0-0) 

### Proof of Concept
1. Attacker B calls `supply(caller=B, account_id=0, spoke_id, [(X, S)])`, receiving scaled supply shares in market `X`. [12](#0-11) 

2. Attacker A calls `supply` for collateral `C`, then `borrow(caller=A, account_id=A, [(X, D)], Some(A))`. [13](#0-12) 

3. After `A` becomes insolvent and its remaining collateral is at most the dust threshold, anyone calls `clean_bad_debt(caller, A)`. [5](#0-4) 

4. `execute_bad_debt_cleanup` emits a borrow-side `PoolSeizeEntry`; the pool computes `bad_debt = scaled_debt * borrow_index`, calls `apply_bad_debt_to_supply_index`, and burns the debt. [14](#0-13) [2](#0-1) 

5. If `bad_debt` is at least the market’s supplied value, the index is clamped to `SUPPLY_INDEX_FLOOR_RAW` instead of zeroing B’s claim. [3](#0-2) 

6. Victim V calls `supply` for `C` units of `X`, increasing cash and minting shares at the floored index. [15](#0-14) 

7. B calls `withdraw(caller=B, account_id=B, [(X, 0)], Some(B))`; zero is converted to the withdraw-all sentinel, the stale shares resolve to a positive payout, and the pool transfers V’s deposited cash to B. [16](#0-15) [4](#0-3)

pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));

enum BadDebtGate {
    /// Permissionless: insolvent *and* collateral at or below the dust threshold.
    DustCapped,
    /// Owner-only: insolvent alone, with no cap on the collateral left behind.
    InsolventOnly,

/// Requires open debt and the selected insolvency gate, then cleans up the account.
fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    bad_debt::execute_bad_debt_cleanup(env, &mut cache, account_id, &account, &totals);

/// Checks supply entry gates and credits measured pool receipts.
pub(crate) fn process_deposit(
    env: &Env,
    caller: &Address,
    account: &mut Account,
    aggregated: &AggregatedPayments,
    cache: &mut Context,
) {
    validate_position_entry_gates(
        env,
        account,
        aggregated,
        cache,
        AccountPositionType::Deposit,
    );
    let pool_addr = cache.cached_pool_address();
    let mut entries: Vec<PoolSupplyEntry> = Vec::new(env);
    for (hub_asset, amount_in) in aggregated.iter() {
        let asset_config: AssetConfig = cache.require_spoke_asset(account.spoke_id, &hub_asset);
        let received = payments::transfer_amount_measured(
            env,
            &hub_asset.asset,
            caller,
            &pool_addr,
            amount_in,
            GenericError::AmountMustBePositive,
        );
        let position = account.get_or_create_supply_position(&hub_asset, &asset_config);
        entries.push_back(PoolSupplyEntry {
            action: make_pool_action(&position, received, hub_asset.clone()),
        });
    }

    let results = pool_supply_call(env, &pool_addr, &entries);
    for_each_leg(env, &entries, &results, |entry, result| {
        merge_supply_leg(env, account, &entry.action, &result, cache);
    });
