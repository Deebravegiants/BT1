No vulnerability found for this question.

**Reasoning:**

`reconfiguration_with_dkg::try_start()` is `public(friend)`, restricted to friends `aptos_framework::block` and `aptos_framework::aptos_governance` [1](#0-0) . It is only invoked from `block::block_prologue_ext`, which is called by the VM signer during block prologue (validator/consensus-driven, not an unprivileged transaction), or from `aptos_governance::reconfigure`, which itself requires `system_addresses::assert_aptos_framework` [2](#0-1) [3](#0-2) . There is no unprivileged entrypoint that lets an attacker seed or manipulate `chunky_dkg::incomplete_session()` state; that state is only mutated by `chunky_dkg::start`/`finish`, both `public(friend)` to `reconfiguration_with_dkg` [4](#0-3) , which in turn are only driven by validator consensus transactions through the DKG protocol.

Even granting the described call ordering, the effect described — `try_clear_incomplete_session` dropping a stale chunky session inside `try_start()` — is an intentional recovery mechanism documented in the code comment ("drop any stale chunky session so finish_with_dkg_result can proceed... recovery from a stall") [5](#0-4) . Clearing an incomplete session only discards an *unfinished* chunky DKG attempt; it does not touch `decryption`'s already-buffered or committed keys, which are only set via `decryption::set_for_next_epoch` inside `finish_with_chunky_dkg_result` after `chunky_dkg::finish` succeeds [6](#0-5) , and applied only at legitimate epoch finalization via `decryption::on_new_epoch` inside `finish()` [7](#0-6) . Worst case here is a restarted/stalled DKG round (availability), not a change in who holds or can decrypt/derive the multisig key — no ownership, mint/burn, freeze, or transfer authority is affected. This falls outside the required custody impact gate (no unprivileged entrypoint, no asset/ownership control change), and DoS/availability issues are explicitly excluded from scope.

    public(friend) fun start(
        dealer_epoch: u64,
        chunky_dkg_config: ChunkyDKGConfig,
        dealer_validator_set: vector<ValidatorConsensusInfo>,
        target_validator_set: vector<ValidatorConsensusInfo>
    ) acquires ChunkyDKGState {
        if (is_session_started(dealer_epoch)) { return };
        let chunky_dkg_state = borrow_global_mut<ChunkyDKGState>(@aptos_framework);
        let new_session_metadata = ChunkyDKGSessionMetadata {
            dealer_epoch,
            chunky_dkg_config,
            dealer_validator_set,
            target_validator_set
        };
        let start_time_us = timestamp::now_microseconds();
        chunky_dkg_state.in_progress = std::option::some(
            ChunkyDKGSessionState {
                metadata: new_session_metadata,
                start_time_us,
                aggregated_subtranscript: vector[]
            }
        );

        emit(
            ChunkyDKGStartEvent { start_time_us, session_metadata: new_session_metadata }
        );
    }

    /// Put a transcript into the currently incomplete Chunky DKG session, then mark it completed.
    ///
    /// Abort if Chunky DKG is not in progress.
    public(friend) fun finish(aggregated_subtranscript: vector<u8>) acquires ChunkyDKGState {
        let chunky_dkg_state = borrow_global_mut<ChunkyDKGState>(@aptos_framework);
        assert!(
            chunky_dkg_state.in_progress.is_some(),
            error::invalid_state(ECHUNKY_DKG_NOT_IN_PROGRESS)
        );
        let session = chunky_dkg_state.in_progress.extract();
        session.aggregated_subtranscript = aggregated_subtranscript;
        chunky_dkg_state.last_completed = option::some(session);
        chunky_dkg_state.in_progress = option::none();
    }
