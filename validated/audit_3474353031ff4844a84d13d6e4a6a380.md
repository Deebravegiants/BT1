### Title
Suppliers can exit before `seize_positions` books the bad-debt supply-index write-down, shifting the entire socialized loss onto remaining suppliers — (File: contracts/pool/src/ops/seize.rs)

### Summary
Bad-debt losses in XOXNO Lending are booked lazily: they only hit a market's `supply_index` when `clean_bad_debt`, `force_socialize_bad_debt`, or the post-liquidation hook calls `seize_positions` → `apply_bad_debt_to_supply_index` [1](#0-0) . Because `withdraw` only accrues interest (`synced_market` → `global_sync`) and never checks for pending socializable debt [2](#0-1) , any supplier can withdraw at the pre-write-down index once a cleanup is imminent and observable, escaping their pro-rata share of the loss — the same class as front-running `updateDebtReporting` with a subset of destinations.

### Finding Description
The Tokemak bug let a user choose which destinations to report, exiting before the loss leg was accounted. Here the loss leg is inherently deferred rather than user-selected, but the exploitable window is the same and is reachable by an unprivileged address:

1. A borrower account becomes insolvent (`total_debt > total_collateral`, per `is_socializable_bad_debt` / `BadDebtGate::InsolventOnly`) [3](#0-2) .
2. Cleanup becomes callable: `clean_bad_debt` permissionlessly when collateral ≤ $5 [4](#0-3) , or `force_socialize_bad_debt` via governance — which is publicly scheduled on the timelock's Sensitive tier, giving suppliers a predictable, delayed execution window [5](#0-4) .
3. Only at cleanup does `apply` reduce the debt market's `supply_index` by `min(bad_debt, total_supply)` [6](#0-5) .
4. Before that executes, a supplier calls `controller.withdraw` → `pool.withdraw`; `accounting` resolves the payout against the *un-written-down* `supply_index` and transfers real cash out [7](#0-6) .
5. When cleanup lands, `total_supply` has shrunk by the exiting shares, so the same debt write-down falls entirely on the suppliers who stayed. With `reduction = (total_supply − bad_debt)/total_supply` [8](#0-7) , each early exit increases the per-share loss of the remainder; if enough exit, the index clamps at `RAY/1000`, stranding claims and forcing `PoolInsolvent`/recapitalization [9](#0-8) .

The write-down also only triggers inside `seize_positions`; no withdrawal or borrow path marks an insolvent account pending cleanup, so nothing blocks the exit leg.

### Impact Explanation
Early withdrawers are paid face value for shares that are economically impaired, draining `cash` ahead of the loss booking. Remaining suppliers absorb a larger per-share write-down, can be left with unbacked claims at the index floor, and the market can require external `recapitalize` donations to restore backing — theft/redistribution of user funds, matching the original report's "attacker exits at profit, later withdrawers suffer more loss" shape.

### Likelihood Explanation
Requires an account reaching `D > C` (a real market event — the test suite constructs these routinely) and an exit window. The window is guaranteed, not opportunistic: `force_socialize_bad_debt` passes through a governance timelock delay that is publicly inspectable, and even the permissionless `clean_bad_debt` path requires someone to submit the transaction, which mempool watchers can front-run. Any supplier of the affected market can execute it with ordinary `withdraw`, which is not blocked by pause, listing flags, or the dust gate.

### Recommendation
Bind loss booking to withdrawal, or remove the observability gap: (a) when `check_bad_debt_after_liquidation`/risk computation detects `is_socializable_bad_debt`, socialize immediately in the same transaction rather than waiting for a separate cleanup call (the post-liquidation hook already does this — extend it so a withdrawal touching a market with a known-insolvent account cannot precede the write-down); (b) at minimum, have `controller.withdraw`/`pool.withdraw` consult a pending-bad-debt flag per market and apply or trigger cleanup first. Note this is a partially documented design choice (ADR-0012/ADR-0021 describe the deferred write-down and floor shortfall), which may reduce severity on review.

### Proof of Concept
Setup mirrors `tests/test-harness/tests/controller/bad_debt_index.rs::test_force_socialize_leaves_an_untouched_market_bit_identical` [10](#0-9) :

```rust
// ETH market: BOB supplies 50 ETH, ATTACKER supplies 50 ETH.
// ALICE supplies USDC collateral, borrows ETH.
t.supply(BOB, "ETH", 50.0);
t.supply(ATTACKER, "ETH", 50.0);
t.supply(ALICE, "USDC", 200_000.0);
t.borrow(ALICE, "ETH", 10.0);

// Crash USDC -> ALICE insolvent (D > C). Governance proposes
// ForceSocializeBadDebt(alice_id); it sits in the timelock delay.
t.set_price("USDC", usd_cents(1));

// ATTACKER front-runs the scheduled execution:
let attacker_before = t.supply_balance(ATTACKER, "ETH");
t.withdraw_all(ATTACKER, "ETH"); // pays out at pre-write-down supply_index

// Execute force_socialize_bad_debt: write-down now lands on BOB alone.
t.force_socialize_bad_debt_by_id(alice_id);

// ATTACKER received ~50 ETH worth; BOB's claim absorbs the full 10 ETH debt
// (plus the collateral reclassified to revenue), i.e. BOB's per-share loss is
// roughly double the pro-rata share he would have borne if ATTACKER had stayed.
let bob_loss = bob_before - t.supply_balance(BOB, "ETH");
assert!(bob_loss > alice_debt_value * bob_before / supplied_value_before_incl_attacker);
```

For the permissionless variant, replace the governance step with collateral ≤ $5 and have ATTACKER submit `withdraw` immediately before the keeper's `clean_bad_debt` transaction.

fn test_force_socialize_leaves_an_untouched_market_bit_identical() {
    let mut t = LendingTest::new()
        .three_asset_usdc_eth_wbtc()
        .with_dust_disabled_all_markets()
        .build();

    t.supply(BOB, "ETH", 100.0);
    t.supply(CAROL, "WBTC", 2.0);
    t.supply(DAVE, "USDC", 200_000.0);
    t.borrow(DAVE, "WBTC", 1.0);

    t.advance_and_sync(days(90));

    t.supply(ALICE, "USDC", 100.0);
    t.borrow(ALICE, "ETH", 0.02);

    let wbtc_before = market_state(&t, "WBTC");
    let (eth_si_before, _) = get_indexes(&t, "ETH");

    t.set_price("USDC", usd_cents(30));
    let account_id = t.resolve_account_id(ALICE);
    t.force_socialize_bad_debt_by_id(account_id);

    let (eth_si_after, _) = get_indexes(&t, "ETH");
    let wbtc_after = market_state(&t, "WBTC");

    assert!(
        eth_si_after < eth_si_before,
        "force-socialize must write down ETH: before={eth_si_before} after={eth_si_after}"
    );
    assert_market_state_unchanged("WBTC", &wbtc_before, &wbtc_after);
}
