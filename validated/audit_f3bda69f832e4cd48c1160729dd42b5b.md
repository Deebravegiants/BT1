### Title
High-utilization whale market permanently freezes on accrual overflow - (File: common/src/rates/scaling.rs)

### Summary

A sufficiently large market whose debt remains highly utilized can grow its borrow index until merely unscaling the stored scaled balances overflows `i128`. Because every market mutation performs interest accrual before applying the requested operation, the resulting `MathOverflow` traps `update_indexes` and subsequently all supply, borrow, withdrawal, repayment, liquidation, and bad-debt actions for that market.

### Finding Description

`global_sync` unconditionally runs `accrue_step` for each elapsed period before a pool mutation proceeds. `accrue_step` first converts scaled debt and scaled supply into original values through `scaled_to_original`, which uses the non-saturating `Ray::mul` path. That multiplication widens intermediate arithmetic but still panics with `MathOverflow` when the final value does not fit in `i128`.

The borrow index is capped at `MAX_BORROW_INDEX_RAY`, but the cap is applied only after multiplying the old index by the interest factor. More importantly, it does not bound `borrowed_scaled * borrow_index`, which is the product used by `scaled_to_original`. Once the scaled debt is large enough, the index can remain below its configured ceiling while the reconstructed debt value already exceeds `i128::MAX`.

The in-repo integration test demonstrates this exact condition: a large 18-decimal market at sustained high utilization eventually makes `update_indexes` fail with `MathOverflow`; after that, both withdrawal and repayment fail for the same reason because they accrue first.

Relevant flow:

- Public controller entrypoints include `supply`, `borrow`, `withdraw`, `repay`, and `liquidate`. [1](#0-0) 
- Each pool mutation obtains an interest-synced market through `synced_market`. [2](#0-1) 
- `global_sync` accrues every elapsed chunk before the requested operation. [3](#0-2) 
- Each step calls `scaled_to_original` for debt and supply. [4](#0-3) 
- `scaled_to_original` calls non-saturating multiplication. [5](#0-4) 
- `Ray::mul` delegates to `mul_div_half_up`. [6](#0-5) 
- `mul_div_half_up` panics when the result cannot fit in `i128`. [7](#0-6) 

### Impact Explanation

This can permanently freeze user funds in the affected market. Suppliers cannot withdraw, borrowers cannot repay, liquidators cannot liquidate, and bad-debt cleanup cannot complete because each path reaches the same accrual calculation before it can reduce either scaled balance.

The failure is not merely transient congestion or a temporary liquidity shortage. Once `borrowed_scaled * borrow_index` or `supplied_scaled * supply_index` exceeds the representable range, every later accrual recomputes the overflowing product and traps again. The index ceilings do not prevent this: `MAX_BORROW_INDEX_RAY` bounds only the index, not the index times an arbitrarily large scaled position. [8](#0-7) [9](#0-8) 

### Likelihood Explanation

The trigger requires a very large market balance and sustained positive interest accrual. It cannot be induced by a single dust-sized position, and configured supply or borrow caps can move the required amount beyond practical reach.

However, the path is reachable by unprivileged protocol actions where token supply and market limits permit it: an attacker can supply the debt asset through `supply`, obtain the corresponding position through a sufficiently collateralized account, and borrow through `borrow`. Thereafter, any caller can attempt `update_indexes` or any user can attempt an operation on that market; the arithmetic condition persists even if the attacker stops participating. The checked-in reproduction reaches the cliff below the index cap and confirms that both withdrawal and repayment remain blocked. [10](#0-9) 

### Recommendation

Make accrual overflow-safe at the point where scaled balances are converted to value. In particular:

- Use a saturating or explicit bound-aware `scaled_to_original` calculation for utilization and accrual.
- Enforce a market-level invariant on `scaled_amount * index`, not only on `index` itself.
- Bound scaled supply and debt minting so subsequent unscaling cannot exceed `i128`.
- If saturation is used for utilization, ensure debt valuation and liquidation paths still use conservative arithmetic rather than treating a saturated result as exact.
- Add a regression test proving that `update_indexes`, `withdraw`, `repay`, and liquidation remain executable at the maximum admitted scaled-position/index product.

### Proof of Concept

The repository already contains a direct reproduction in `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap`:

1. Create an 18-decimal debt market and a collateral market.
2. Supply approximately one billion whole debt tokens to create scaled supply near the `i128` value boundary.
3. Borrow approximately 98% of that supply through a sufficiently collateralized account.
4. Advance ledger time until the borrow index grows enough that `borrowed_scaled * borrow_index` no longer fits in `i128`.
5. Call `update_indexes`; `accrue_step` reaches `scaled_to_original` and panics with `MathOverflow`.
6. Call `withdraw` or `repay`; both calls perform `global_sync` first and fail with the same error.

The test records that the borrow index remains below `MAX_BORROW_INDEX_RAY`, proving that the index ceiling does not protect the value multiplication, and verifies the frozen withdrawal and repayment paths. [11](#0-10)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();

/// Computes `x * y / d` rounded half up. Requires `x >= 0`, `y >= 0`, and `d > 0`; a
/// `debug_assert` checks this in debug builds. Panics with `GenericError::DivisionByZero` if
/// `d == 0`, and with `GenericError::MathOverflow` if any other precondition is violated or if
/// the result does not fit in `i128`.
pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    // The zero check runs first so debug and release builds agree on a zero
    // divisor: both surface `DivisionByZero` rather than tripping the assert.
    require_nonzero_divisor(env, d);
    debug_assert!(
        x >= 0 && y >= 0 && d > 0,
        "mul_div_half_up: non-negative x, y and positive d"
    );
    try_mul_div_half_up(env, x, y, d)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
}

/// Applies `interest_factor` to `old_index` to produce the new borrow index,
/// capped at `MAX_BORROW_INDEX_RAY`.
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
