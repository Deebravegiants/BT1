## Title
Missing slippage protection in `SwapFirstAssetTrader::refund_weight` allows sandwiching of XCM fee-swap refunds - (File: `cumulus/primitives/utility/src/lib.rs`)

## Summary
`SwapFirstAssetTrader::refund_weight` calls `SwapCredit::swap_exact_tokens_for_tokens(vec![Target::get(), refund_swap_asset], refund, None)` with `amount_out_min` hard-coded to `None`, disabling `pallet_asset_conversion`'s only slippage-protection mechanism for that swap. [1](#0-0)  By contrast, `buy_weight` swaps via `swap_tokens_for_exact_tokens` where the output amount (`fee`) is fixed exactly, so slippage there is bounded by construction. [2](#0-1) 

## Finding Description
`pallet_asset_conversion::do_swap_exact_tokens_for_tokens` only checks `amount_out >= amount_out_min` when `amount_out_min` is `Some`; when `None`, the check is skipped entirely and the swap executes at whatever price the constant-product pool yields at execution time. [3](#0-2)  `SwapFirstAssetTrader::refund_weight` extracts the unused fee amount from `total_fee` and swaps it back to the originally-supplied asset via this exact-input path, passing `None` unconditionally, so the refund can be paid out at an arbitrarily poor price if the pool is manipulated within the same block (e.g., by whoever controls extrinsic ordering, most plausibly the block author/collator, or a racing transaction). [4](#0-3) 

Confirmed: `SwapFirstAssetTrader` is wired into a real, non-mock production runtime as an `XcmConfig::Trader`, using `crate::AssetConversion` as `SwapCredit` in `cumulus/parachains/runtimes/assets/asset-hub-westend/src/xcm_config.rs`, verified directly in this codebase. [5](#0-4)  This confirms the code path is reachable in production configuration, not merely a mocked/test-only helper — this portion of the claim is verified true.

## Impact Explanation
Whenever an XCM message pays fees through `SwapFirstAssetTrader` in a non-`Target` asset and the bought weight exceeds actual consumption (a routine, expected occurrence since `BuyExecution` typically over-provisions), `refund_weight` performs an unbounded-price swap back to the sender's asset. If the pool price is moved adversely just before this swap executes (and optionally reversed afterward), the XCM sender receives less refunded value than fair market price, with the difference captured by the price-manipulating party. This is a genuine, concrete value-transfer bug from an unprivileged protocol user to whoever can influence intra-block extrinsic ordering, consistent with the reference `buy_weight`/`refund_weight` code shown.

## Likelihood Explanation
Exploitation requires the ability to influence extrinsic ordering within the same block relative to the victim's XCM-executing extrinsic — realistically a collator/block author (a "semi-privileged" but non-governance, permissionless-in-principle role in many parachains), or a user racing transaction submission for favorable ordering. This is a weaker precondition than direct privilege escalation, but stronger than "any ordinary user acting alone with a single transaction," since the manipulator must also supply capital to move the pool and, ideally, reverse the position afterward. The magnitude of extractable value is bounded by the size of the refund itself (unused weight fee), which is typically small relative to a transaction's total fee, limiting per-instance profit but the pattern is repeatable across every fee-swap refund.

## Recommendation
Do not pass `None` for `amount_out_min` in `SwapFirstAssetTrader::refund_weight`. Compute an acceptable minimum via `QuotePrice::quote_price_exact_tokens_for_tokens` (or a similarly available quoting mechanism) with a configurable slippage tolerance, and pass `Some(min_amount)` to `swap_exact_tokens_for_tokens`, mirroring the implicit protection already present on the `buy_weight` path. If a safe minimum cannot be computed, prefer holding the excess in the `Target` asset (skipping the refund swap) over refunding at an unbounded price.

## Proof of Concept
1. Deploy/observe a runtime with `SwapFirstAssetTrader` configured as `cumulus_primitives_utility::SwapFirstAssetTrader<WestendLocation, crate::AssetConversion, WeightToFee, ...>` in `XcmConfig::Trader`, backed by a `pallet_asset_conversion` pool between `Target` and another asset with modest liquidity (matches asset-hub-westend's actual configuration).
2. A user sends an XCM message with `BuyExecution` paid in the non-`Target` asset, over-provisioning weight relative to actual consumption.
3. `buy_weight` executes `swap_tokens_for_exact_tokens` for the exact `fee` (bounded by construction).
4. Before/interleaved with the same extrinsic's `refund_weight` call, an actor with ordering control (e.g., block author) inserts a large swap/liquidity operation shifting the `Target -> refund_swap_asset` price unfavorably.
5. `refund_weight` executes `swap_exact_tokens_for_tokens(vec![Target::get(), refund_swap_asset], refund, None)`; because `amount_out_min` is `None`, `do_swap_exact_tokens_for_tokens`'s `ProvidedMinimumNotSufficientForSwap` check is skipped and the swap succeeds at the manipulated price.
6. The refund credited to the user is measurably lower than a pre-manipulation quote would have implied — reproducible as a unit test in `cumulus/primitives/utility/src/tests/swap_first.rs`-style mock environment by manipulating pool reserves between the `buy_weight` and `refund_weight` calls and asserting the refunded amount against a slippage-free baseline.

	fn refund_weight(&mut self, weight: Weight, _context: &XcmContext) -> Option<AssetsInHolding> {
		log::trace!(
			target: "xcm::weight",
			"SwapFirstAssetTrader::refund_weight weight: {:?}, self.total_fee: {:?}",
			weight,
			self.total_fee,
		);
		if weight.is_zero() || self.total_fee.peek().is_zero() {
			// noting to refund.
			return None;
		}
		let refund_asset = if let Some(asset) = &self.last_fee_asset {
			// create an initial zero refund in the asset used in the last `buy_weight`.
			(asset.clone(), Fungible(0)).into()
		} else {
			return None;
		};
		let refund_amount = WeightToFee::weight_to_fee(&weight);
		if refund_amount >= self.total_fee.peek() {
			// not enough was paid to refund the `weight`.
			return None;
		}

		let refund_swap_asset = FungiblesAssetMatcher::matches_fungibles(&refund_asset)
			.map(|(a, _)| a.into())
			.ok()?;

		let refund = self.total_fee.extract(refund_amount);
		let refund = match SwapCredit::swap_exact_tokens_for_tokens(
			vec![Target::get(), refund_swap_asset],
			refund,
			None,
		) {
			Ok(refund_in_target) => refund_in_target,
			Err((refund, _)) => {
				// return an attempted refund back to the `total_fee`.
				let _ = self.total_fee.subsume(refund).map_err(|refund| {
					// error may occur if `total_fee.asset` differs from `refund.asset`, which does
					// not apply in this context.
					defensive!(
						"`total_fee.asset` must be equal to `refund.asset`",
						(self.total_fee.asset(), refund.asset())
					);
				});
				return None;
			},
		};

		let refund = AssetsInHolding::new_from_fungible_credit(refund_asset.id, Box::new(refund));
		Some(refund)
	}
