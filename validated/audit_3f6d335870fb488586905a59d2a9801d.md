## Finding: Stale `TombStone.original_owner` in `object.move` allows a former owner to hijack an object away from a legitimate later owner via `unburn`

### Title
Unauthorized object ownership reassignment via stale `TombStone` after ordinary `transfer` — ([File: aptos-move/framework/aptos-framework/sources/object.move])

### Summary
`object::burn` marks an object as "soft burnt" by attaching a `TombStone{original_owner}` resource without changing `ObjectCore.owner`. The `TombStone` is only cleared in `unburn()` or in `transfer_with_ref()` (the privileged `LinearTransferRef` path). The ordinary, unprivileged `object::transfer` / `transfer_raw` / `transfer_call` path (`transfer_raw_inner`) changes `ObjectCore.owner` but never clears an existing `TombStone`. As a result, a **stale** `original_owner` recorded by a past owner survives arbitrary subsequent ownership changes and can be redeemed later, letting a former owner reclaim (steal) an object that a *different, legitimate* later owner sent to the burn address.

### Finding Description
- `burn<T>` records `TombStone { original_owner }` for the caller while leaving `ObjectCore.owner` unchanged: [1](#0-0) 
- `transfer_raw_inner`, used by the public, unprivileged `transfer`/`transfer_raw`/`transfer_call` entrypoints, only updates `object_core.owner`; it does **not** check for or clear any existing `TombStone`: [2](#0-1) 
- In contrast, the privileged `transfer_with_ref` (requires a `TransferRef`/`LinearTransferRef`) explicitly clears a stale `TombStone` before transferring, specifically to prevent this kind of stale-reclaim: [3](#0-2) 
- `unburn<T>` trusts the `TombStone.original_owner` field whenever the object's current owner happens to be `BURN_ADDRESS`, without verifying that the object has not changed hands (via ordinary transfer) since that `TombStone` was created: [4](#0-3) 

Exploit path:
1. Owner `A` calls `object::burn(A, obj)` → `TombStone{original_owner: A}` is created; `A` remains the owner (soft burn).
2. `A` transfers `obj` normally to `C` via `object::transfer`/`transfer_raw` (a completely ordinary, unprivileged operation) → `ObjectCore.owner = C`, but the stale `TombStone{original_owner: A}` is **not** cleared.
3. `C`, the legitimate current owner, later decides to permanently destroy the object by sending it to `BURN_ADDRESS` via an ordinary `object::transfer(C, obj, BURN_ADDRESS)` (a normal, expected way to "hard burn" an object).
4. `A` (who no longer owns the object and has no current relationship to it) calls `unburn(A, obj)`. Since `ObjectCore.owner == BURN_ADDRESS` and the stale `TombStone.original_owner == A`, the assert passes and `transfer_raw_inner(obj, A)` restores ownership to `A`.

`A` thereby reclaims an object/asset that legitimately belonged to, and was intentionally destroyed by, `C`. This breaks the custody invariant that "burn = irrecoverable" and that ownership refs/ownership transfer must preserve the intended controller — instead an unrelated, unprivileged past owner regains control.

### Impact Explanation
This is a custody-grade ownership-control break: an unprivileged, unrelated address (`A`) can reassign to itself the ownership of an object that a different, legitimate owner (`C`) explicitly and permanently destroyed. Any object-held value (token objects, NFTs, or fungible-asset-holding objects transferred with plain `object::transfer`) is at risk if the object was ever soft-burnt earlier in its history by any past owner. This is a theft/unauthorized owner-reassignment scenario and also undermines the guarantee that sending an object to `BURN_ADDRESS` is a genuine, irrecoverable destruction — a stale claimant can resurrect it instead.

### Likelihood Explanation
The unprivileged path (`object::transfer`) is the default/most common way objects change hands (used pervasively by NFT/token-object modules and other object-holding flows), whereas `transfer_with_ref` is only used in specific privileged/controlled flows (e.g., primary fungible store internals). Any object that has at some point been soft-burnt by `object::burn` and later transferred normally carries this latent, exploitable stale state. No special privileges are required by the attacker (`A`) — they only need to have been a past owner who called `burn` once, then transferred the object away normally.

### Recommendation
Clear (or invalidate) any existing `TombStone` whenever ownership changes through the ordinary `transfer_raw_inner` path (mirroring what `transfer_with_ref` already does), or bind `TombStone` validity to the specific owner-at-burn-time such that any subsequent ownership change (through any path) invalidates the stale claim. Alternatively, have `unburn`'s `BURN_ADDRESS` branch additionally verify that no intervening ordinary ownership change occurred since the `TombStone` was recorded (e.g., by tracking the owner at burn time and requiring it match the owner immediately prior to the burn-address transfer).

### Proof of Concept
```
// Pseudocode using object.move public API
object::burn(A, obj);                       // TombStone{original_owner: A}, owner still A
object::transfer(A, obj, C_addr);           // owner = C, TombStone NOT cleared (bug)
// ... time passes, C uses the object normally ...
object::transfer(C, obj, BURN_ADDRESS);     // C intentionally & legitimately burns obj
object::unburn(A, obj);                     // succeeds! owner reset to A, stealing it from C's burn
```
This mirrors the existing test `test_cannot_unburn_after_transfer_with_ref` [5](#0-4) , which confirms that only the `transfer_with_ref` path is guarded against stale reclaim — there is no equivalent test/guard for the ordinary `transfer` path, confirming the gap.

                to,

    /// Allow origin owners to reclaim any objects they previous burnt.
    public entry fun unburn<T: key>(
        original_owner: &signer,
        object: Object<T>,
    ) {
        let object_addr = object.inner;
        assert!(exists<TombStone>(object_addr), error::invalid_argument(EOBJECT_NOT_BURNT));

        // The new owner of the object can always unburn it, but if it's the burn address, we go to the old functionality
        let object_core = borrow_global<ObjectCore>(object_addr);
        if (object_core.owner == signer::address_of(original_owner)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object_addr);
        } else if (object_core.owner == BURN_ADDRESS) {
            // The old functionality
            let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
            assert!(
                original_owner_addr == signer::address_of(original_owner),
                error::permission_denied(ENOT_OBJECT_OWNER)
            );
            transfer_raw_inner(object_addr, original_owner_addr);
        } else {
            abort error::permission_denied(ENOT_OBJECT_OWNER);
        };
    }
