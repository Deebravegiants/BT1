### Title
Dropped liquidation seizure legs keep their backing repayment — skipped collateral is not added to `unseized_usd` - (File: contracts/controller/src/positions/liquidation/math.rs)

### Summary
`calculate_seized_collateral` allocates the total seizure (`repay_usd * (1 + bonus)`) pro-rata across collateral legs and returns `unseized_usd`, the repayment USD that ended up backed by no seizure so the caller can release it via `release_unbacked_repayment`. The only path that credits `unseized_usd` is the sub-3-decimal whole-unit floor at lines 409-415. Three other skip paths — `seizure_ray <= 0`, `capped_ray <= 0`, `seized_scaled <= 0`, and `capped_amount <= 0` (lines 419, 428, 456, 465) — silently `continue` without crediting `unseized_usd`, so the repayment that nominally backed that leg's seizure stays in `repay_usd` and is pulled from the liquidator without any collateral being seized for it.

### Finding Description
In `calculate_seized_collateral` (`contracts/controller/src/positions/liquidation/math.rs:363-505`), each supply leg computes `seizure_for_asset_usd`, converts it to `seizure_ray`, then runs several guards:

```rust
if seizure_ray <= Ray::ZERO { continue; }            // line 419
...
if capped_ray <= Ray::ZERO { continue; }             // line 428
...
if seized_scaled <= Ray::ZERO { continue; }          // line 456
...
if capped_amount <= 0 { continue; }                  // line 465
```

Compare with the whole-unit path, which does account for the dropped value:

```rust
let whole_usd = seizure_ray.to_wad(env).mul(env, feed.price);
if seizure_for_asset_usd > whole_usd {
    unseized_usd = unseized_usd
        .checked_add(env, seizure_for_asset_usd.checked_sub(env, whole_usd));
}
```

The `continue` paths perform no equivalent accounting. A leg whose pro-rata seizure is positive in USD terms but rounds to zero scaled shares (`capped_ray.div_floor(supply_index) == 0`, line 450) or zero token units (`capped_ray.to_asset_floor(...) == 0`, line 463) is dropped entirely, yet `seizure_for_asset_usd` for that leg is never added to `unseized_usd`. The returned `unseized_usd` (floored by `one_plus_bonus` at line 504) is therefore understated, `release_unbacked_repayment` (lines 509-527) releases too little, and `repay_usd` keeps repayment that no seizure backs. `LiquidationPlan::validate` (lines 54-69) only checks entry bounds and that recorded repayments sum to `repay_usd` — it does not check that kept repayment is collateral-backed, so the inconsistency passes validation.

This is the same bug class as the Derby finding: an accounting quantity (`unseized_usd` ↔ `savedTotalUnderlying`) that must track skipped legs only records one of several skip conditions, so state implies value moved that never did.

### Impact Explanation
A liquidator calling `liquidate` (unprivileged) has debt-token payments pulled per the plan's `repaid` entries, but receives only the `seized` entries. For every collateral leg silently dropped by the guards above, the liquidator repays debt with zero collateral in return — a direct loss of the repayment tokens for that leg's share of `repay_usd * (1 + bonus)`. On a victim account with several small or low-decimal collateral positions (e.g., a dominant large leg plus dust legs, or legs where `supply_index` growth pushes `scaled` seizure below 1 share), an attacker-liquidator cannot profit, but any ordinary liquidator is overcharged; equivalently, the borrower is relieved of debt without surrendering the corresponding collateral, which socializes the loss into the pool as under-seized collateral backing repaid debt is fine for the pool but the liquidator's funds are taken with no compensation — theft of funds from the liquidator.

### Likelihood Explanation
Reachable by any unprivileged liquidator on any account with more than one collateral leg where a minor leg's pro-rata seizure rounds to zero: `capped_ray < supply_index` (producing `seized_scaled == 0`) requires only that the leg's share of the seizure be below one share at a grown index, or below one token unit for `capped_amount == 0`. Dust collateral positions and mature supply indexes make this routine rather than exotic. The loss scales with the dropped leg's pro-rata share — bounded per call by the smaller collateral legs — consistent with Medium severity.

### Recommendation
In each skip path inside `calculate_seized_collateral`, credit the dropped seizure value to `unseized_usd` before `continue`, mirroring the whole-unit block:

```rust
if seized_scaled <= Ray::ZERO || capped_amount <= 0 {
    unseized_usd = unseized_usd.checked_add(env, seizure_for_asset_usd);
    continue;
}
```

(Apply the same credit for the `seizure_ray <= 0` / `capped_ray <= 0` early skips if those legs were allocated a positive `seizure_for_asset_usd`.) Alternatively, compute `unseized_usd` at the end as `total_seizure_usd` minus the sum of the USD actually pushed into `seized`, which structurally cannot diverge from the kept repayment.

### Proof of Concept
1. Borrower holds collateral legs A (large) and B (small, or high `supply_index`), with debt making the account liquidatable.
2. Liquidator calls `liquidate` offering a partial repayment sized so B's pro-rata `seizure_for_asset_usd` converts to `capped_ray > 0` but `capped_ray.div_floor(supply_index) == 0` (or `to_asset_floor == 0`).
3. `calculate_seized_collateral` hits the `seized_scaled <= 0`/`capped_amount <= 0` `continue` for B without adding `seizure_for_asset_usd` to `unseized_usd`.
4. `release_unbacked_repayment` receives an understated `excess_usd`, so `repaid` keeps B's share; the liquidator's full merged payment is pulled while `seized` contains only leg A.
5. Net effect: liquidator repays `repay_usd` including B's allocation but receives no B collateral — the missing `unseized_usd / (1 + bonus)` repayment is lost.

Caveat: I did not have remaining iterations to read `liquidation/apply.rs` to confirm the exact plumbing of `unseized_usd` into `release_unbacked_repayment` and whether `scale_seizures_to_received` or the measured-receipt path compensates post-transfer; the accounting gap itself in `calculate_seized_collateral` is confirmed by inspection, and `LiquidationPlan::validate` does not guard it.
