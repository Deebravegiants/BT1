### Title
Cross-Tenant Session Hijack via Predictable, Unsigned Offline Session Cookie - (File: `lib/shopify_api/utils/session_utils.rb`)

### Summary
For non-embedded apps (and as a fallback for embedded apps), `ShopifyAPI::Utils::SessionUtils.current_session_id` derives the active session identity entirely from the raw value of the `shopify_app_session` cookie, with no cryptographic binding to the requester. Because the library also generates offline session IDs using a fully deterministic, public formula (`"offline_#{shop}"`), any unauthenticated internet user who knows (or guesses) a target store's `.myshopify.com` domain can set that exact string as their own cookie value and have the host application resolve and use the victim shop's persisted `Session` (including its `access_token`) on their behalf.

### Finding Description
The identity binding that should hold is:
```
session_id_presented_in_cookie == session_id_that_only_the_authenticated_owner_of_that_shop_could_produce
```
This gem breaks that equality by constructing the session cookie value from a deterministic, non-secret formula and then trusting it verbatim as the session lookup key, with no signature or server-side nonce tying it to the browser that completed OAuth.

- The offline session ID is computed with no randomness or secret material: [1](#0-0) 

- The identical deterministic ID is also what `Session.from` assigns as the session's primary `id` after OAuth completes for offline access: [2](#0-1) 

- After OAuth, the library hands this same value back to the host app to store as a plain cookie, with no mention of signing/HMAC-protecting it — only `secure`/`http_only` flags are recommended: [3](#0-2) [4](#0-3) 

- Crucially, `SessionUtils.current_session_id`/`cookie_session_id` performs **zero validation** of the cookie's contents — it returns whatever the client sent, unauthenticated, as the session key to be looked up in the host app's session store: [5](#0-4) [6](#0-5) 

The `SessionCookie` object itself has no signature field, no HMAC, and no expiry enforcement tied to a nonce — it is a bare struct of `name`, `value`, `expires`: [7](#0-6) 

Because `shop` is public information (every merchant's `*.myshopify.com` handle is exposed in checkout URLs, storefront links, admin URLs, etc.), the resulting session ID `"offline_<shop>.myshopify.com"` is fully guessable by anyone, without ever completing OAuth or possessing any credential. If the host application (per the gem's own documented pattern) blindly forwards the value returned by `SessionUtils.current_session_id` into a session-store lookup, the attacker's forged cookie will resolve to the real, persisted `ShopifyAPI::Auth::Session` for the victim shop — including its live `access_token`.

### Impact Explanation
This breaks the shop-authenticated vs. shop-stored-as-session-key binding described in the vulnerability class rules, resulting in cross-tenant access: an unprivileged internet user can retrieve and use another merchant's offline access token by simply presenting a guessed cookie value, with no interaction with Shopify's OAuth flow, no secret, and no privileged access. This matches the "Critical - cross-tenant access" impact category, since the attacker ends up operating with another tenant's live access token.

### Likelihood Explanation
Likelihood is high for any app following the gem's documented non-embedded/cookie flow exactly as shown in `docs/usage/oauth.md`: the flow explicitly stores `session.id` (which for offline sessions is `"offline_#{shop}"`) as the cookie value with no additional signing step suggested by the library or its documentation. An attacker only needs the target's `.myshopify.com` handle, which is trivially discoverable (it's shown to public site visitors in numerous contexts). No rate limiting, secret, or privileged credential is required to exploit this once a host app follows the documented pattern.

### Recommendation
- Do not use a predictable, deterministic value (`"offline_#{shop}"` or `"#{shop}_#{user_id}"`) as the bare cookie value trusted for session lookup.
- Have `SessionCookie` carry (or the gem itself compute) an HMAC/signature over the session id using `Context.api_secret_key`, and verify that signature inside `SessionUtils.cookie_session_id`/`current_session_id` before returning the ID to the caller.
- Alternatively, mint a random, unguessable session token distinct from the storage key, and never expose the raw storage key ( `"offline_#{shop}"`) as attacker-settable client state.

### Proof of Concept
1. App follows the documented non-embedded OAuth flow in `docs/usage/oauth.md` (lines 241–275), storing `auth_result[:cookie].value` (== `session.id`, e.g. `"offline_victim-shop.myshopify.com"`) as a plain, non-signed cookie named `shopify_app_session`.
2. Attacker (never having gone through OAuth for `victim-shop.myshopify.com`) sends a request to the host app with:
   ```
   Cookie: shopify_app_session=offline_victim-shop.myshopify.com
   ```
3. Host app calls `ShopifyAPI::Utils::SessionUtils.current_session_id(nil, cookies, false)`, which — per `lib/shopify_api/utils/session_utils.rb` lines 19-37 — returns `cookie_session_id(cookies)`, i.e., the attacker-supplied string, unmodified and unverified.
4. Host app looks up `MyApp::SessionRepository.load_session("offline_victim-shop.myshopify.com")`, retrieves the genuine `Session` object (with the real access token) persisted during the victim's legitimate OAuth completion, and uses it to serve the attacker's request — granting the attacker access to `victim-shop`'s data via its own access token. [8](#0-7)

# typed: strict
# frozen_string_literal: true

module ShopifyAPI
  module Utils
    class SessionUtils
      extend T::Sig

      class << self
        extend T::Sig

        sig do
          params(
            shopify_id_token: T.nilable(String),
            cookies: T.nilable(T::Hash[String, String]),
            online: T::Boolean,
          ).returns(T.nilable(String))
        end
        def current_session_id(shopify_id_token, cookies, online)
          if Context.embedded?
            if shopify_id_token
              id_token = shopify_id_token.gsub("Bearer ", "")
              session_id_from_shopify_id_token(id_token: id_token, online: online)
            else
              # falling back to session cookie
              raise Errors::CookieNotFoundError, "JWT token or Session cookie not found for app" unless
                cookies && cookies[Auth::Oauth::SessionCookie::SESSION_COOKIE_NAME]

              cookie_session_id(cookies)
            end
          else
            raise Errors::CookieNotFoundError, "Session cookie not found for app" unless
              cookies && cookies[Auth::Oauth::SessionCookie::SESSION_COOKIE_NAME]

            cookie_session_id(cookies)
          end
        end

        sig do
          params(
            id_token: T.nilable(String),
            online: T::Boolean,
          ).returns(String)
        end
        def session_id_from_shopify_id_token(id_token:, online:)
          raise Errors::MissingJwtTokenError, "Missing Shopify ID Token" if id_token.nil? || id_token.empty?

          payload = Auth::JwtPayload.new(id_token)
          shop = payload.shop

          if online
            jwt_session_id(shop, T.must(payload.sub))
          else
            offline_session_id(shop)
          end
        end

        sig { params(shop: String, user_id: String).returns(String) }
        def jwt_session_id(shop, user_id)
          "#{shop}_#{user_id}"
        end

        sig { params(shop: String).returns(String) }
        def offline_session_id(shop)
          "offline_#{shop}"
        end

        sig { params(cookies: T::Hash[String, String]).returns(T.nilable(String)) }
        def cookie_session_id(cookies)
          cookies[Auth::Oauth::SessionCookie::SESSION_COOKIE_NAME]
        end
      end
    end
  end
end
