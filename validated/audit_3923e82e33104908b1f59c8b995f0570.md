### Title
Predictable, Unsigned Session Cookie Value Enables Cross-Tenant Session Hijacking - (`lib/shopify_api/utils/session_utils.rb`)

### Summary
For non-embedded apps (and as a fallback for embedded apps), `ShopifyAPI::Utils::SessionUtils.current_session_id` resolves the caller's session purely from the raw value of the `shopify_app_session` cookie, with no cryptographic binding tying that value to the browser that actually completed OAuth for a given shop. Because the session ID format is fully deterministic and derived from public information (`"offline_#{shop}"` or `"#{shop}_#{user_id}"`), any user of the host application can set this value themselves and cause the host app to look up and act on a different shop's stored session/access token.

### Finding Description
Two session-resolution paths exist in `ShopifyAPI::Utils::SessionUtils`:

1. **JWT path** (`session_id_from_shopify_id_token`): the session ID is derived from a Shopify-signed session token, verified via `Auth::JwtPayload.new(id_token)` which checks the HS256 signature against `Context.api_secret_key` [1](#0-0) . Here the `shop`/`sub` values used to build the session ID are cryptographically bound to Shopify's signature.

2. **Cookie path** (`cookie_session_id`): the session ID is read verbatim from client-supplied cookies with no signature check at all: [2](#0-1) 

`current_session_id` falls back to this cookie path for non-embedded apps unconditionally, and for embedded apps whenever no `shopify_id_token`/`Authorization` header is present: [3](#0-2) 

The cookie's value is originally set by the gem itself during `Oauth.validate_auth_callback` to `session.id`: [4](#0-3) 

and `session.id` is constructed deterministically from public data — the shop's `myshopify.com` domain and, for online sessions, the associated user id: [5](#0-4) [6](#0-5) 

The identity binding that is broken can be stated as an equality that should hold but doesn't:

`cookie_session_id(cookies)` (client-controlled, unsigned bytes) is treated by the host application as equivalent to `an ID cryptographically issued to this specific browser via a completed OAuth flow`. Since the cookie carries no HMAC/signature (unlike the JWT path, and unlike the OAuth callback's `AuthQuery`, which is HMAC-verified via `Utils::HmacValidator.validate` before its `shop` value is trusted [7](#0-6) ), any user of the app can substitute the value of their own `shopify_app_session` cookie for a session ID belonging to another shop (`offline_othershop.myshopify.com`) or another user (`shop.myshopify.com_<guessable-user-id>`), and the gem will happily hand that string back to the host application as "the current session id" to be looked up in session storage.

### Impact Explanation
If the host application uses the value returned by `current_session_id`/`cookie_session_id` to fetch a stored `Session` (containing another merchant's live access token) without any additional authentication check, an attacker gains cross-tenant access to another shop's Shopify Admin API access token merely by guessing or knowing another shop's `myshopify.com` handle (which is often public/discoverable) and setting their own cookie accordingly. This falls under the accepted High-impact category of session fixation / identity binding bypass via an unauthenticated, predictable session identifier.

### Likelihood Explanation
The session ID format (`offline_#{shop}` or `#{shop}_#{user_id}`) is fully deterministic and shop domains are typically public (visible in storefront URLs, app listing pages, etc.), and online-session user ids are small sequential integers, making them enumerable. No credential, token, or `api_secret_key` knowledge is required to construct a guessed session ID — only the ability to set one's own browser cookie, which any unauthenticated/low-privilege user of the app can do. This is a direct consequence of the gem's own `cookie_session_id` implementation returning raw, unverified cookie bytes as an authoritative session identifier.

### Recommendation
Do not use raw, deterministic session IDs as the sole lookup key trusted from a client-controlled cookie. Either:
- Store an opaque, cryptographically random value in the cookie (decoupled from the deterministic `shop`/`user_id`-derived `Session#id`), and map that random value to the real session server-side, or
- Sign/HMAC the cookie value with `Context.api_secret_key` (similar to `Utils::HmacValidator`) so that `cookie_session_id` can verify the cookie was actually issued by this app for this browser before returning it, rejecting any cookie whose signature does not validate.

### Proof of Concept
1. Attacker visits the non-embedded app as any unauthenticated user (or a merchant who installed the app for their own shop).
2. Attacker knows or guesses `victim-shop.myshopify.com` (a public domain) and, for offline sessions, sets their `shopify_app_session` cookie to `offline_victim-shop.myshopify.com`.
3. The app calls `ShopifyAPI::Utils::SessionUtils.current_session_id(nil, cookies, false)`, which returns `cookie_session_id(cookies)` unchanged — the attacker-supplied string — with no verification: [8](#0-7) 
4. If the host app's session repository has a stored `Session` under that exact ID (which it will, since IDs are deterministic), the attacker's requests are now serviced using `victim-shop`'s real Shopify access token, resulting in cross-tenant API access.

        def current_session_id(shopify_id_token, cookies, online)
          if Context.embedded?
            if shopify_id_token
              id_token = shopify_id_token.gsub("Bearer ", "")
              session_id_from_shopify_id_token(id_token: id_token, online: online)
            else
              # falling back to session cookie
              raise Errors::CookieNotFoundError, "JWT token or Session cookie not found for app" unless
                cookies && cookies[Auth::Oauth::SessionCookie::SESSION_COOKIE_NAME]

              cookie_session_id(cookies)
            end
          else
            raise Errors::CookieNotFoundError, "Session cookie not found for app" unless
              cookies && cookies[Auth::Oauth::SessionCookie::SESSION_COOKIE_NAME]

            cookie_session_id(cookies)
          end
        end
