### Title
Uncaught `SecurityError` from tainted-canvas `getImageData` in `getIconData` load handler causes permanently pending Promise, hanging the RPC bridge - ([File: libraries/browser-extension-rpc/src/metadata.js])

### Summary
In `getIconData`, the `'load'` event handler performs `ctx.drawImage`/`ctx.getImageData` with no try/catch, while the only defined failure path is `img.onerror = () => resolve(null)`. When the icon image loads successfully but the canvas becomes "tainted" (e.g., the attacker's own icon server omits CORS headers while `img.crossOrigin = 'anonymous'` is set), `getImageData` throws a `SecurityError` synchronously inside the `load` listener. This exception is neither caught nor triggers `onerror`, so the `Promise` returned by `getIconData` never resolves or rejects - it hangs forever.

### Finding Description
`getIconData` sets `img.crossOrigin = 'anonymous'` and loads `href`, which is attacker-controlled via `getIcon()`'s selection of `<link rel="icon">` tags or `favicon.ico` on the dapp's own origin [1](#0-0) . On `'load'`, the code draws the image to a canvas and calls `ctx.getImageData(...)` without any error handling [2](#0-1) . If the image resource is served without `Access-Control-Allow-Origin`, the browser still fires `'load'` (the image displays fine) but marks the canvas as tainted; any subsequent `getImageData` call throws a `SecurityError` DOMException. That throw happens inside the `'load'` event listener callback - it is an uncaught synchronous exception in an event handler, not a promise rejection propagated to the `new Promise((resolve) => {...})` executor, so `resolve` is never called and the `onerror` fallback (`resolve(null)`) is never reached either. The only defined error path (`img.onerror`) covers network failures (404s, malformed bytes causing decode failure) but not this post-load throw, confirming the safety net is incomplete for this specific attacker-inducible mode.

This function is awaited from `content.js`'s module-level `metadata` promise (`const icon = await getIcon()`), and every incoming RPC message handler does `const senderMetadata = await metadata` before processing [3](#0-2) . If `metadata` never resolves, every RPC message in that tab's content script (`transport.on('data', ...)`) stalls indefinitely waiting on `await metadata`, freezing the RPC bridge for the page.

### Impact Explanation
A malicious dapp fully controls this: it just needs its own favicon endpoint to omit CORS headers (trivial, default server behavior) while the `<link rel="icon">`/`favicon.ico` still loads normally. This causes the extension's content-script RPC bridge (`createRPCProxy` in `content.js`) to permanently stall on `await metadata`, blocking all subsequent wallet<->dapp RPC traffic for that tab. This is a denial-of-service / RPC-liveness bug rather than a direct signing/auth bypass; it matches a "stalled RPC channel" impact category, and the scoped question's hypothesis that this could be leveraged to desynchronize consent-flow timing is plausible but not independently demonstrated in this file - the concrete, provable impact here is the permanent hang itself.

### Likelihood Explanation
Feasibility is high and fully attacker-controlled: the attacker just needs to host a normal favicon without CORS headers on their own dapp page (default for essentially all web servers), requiring no privileged state, no social engineering beyond a user visiting the malicious page, and no cooperation from Exodus infrastructure. It is deterministic/repeatable on every page load once the response lacks CORS headers.

### Recommendation
Wrap the `'load'` handler body in `try { ... } catch { resolve(null) }` so any post-load failure (tainted canvas `SecurityError`, zero-dimension image causing invalid `getImageData` bounds, etc.) also resolves to `null` instead of throwing uncaught inside the event listener:
```js
img.addEventListener('load', () => {
  try {
    // existing drawImage/getImageData/resolve logic
  } catch {
    resolve(null)
  }
})
```
Additionally consider adding a bounded timeout around `getIconData`/`getIcon()` in `content.js` so a hang in image processing cannot indefinitely block `await metadata` and the RPC message pipeline.

### Proof of Concept
Unit test plan for `getIconData` (jsdom/mock `Image`/`document.createElement('canvas')`):
1. Mock `Image` so `crossOrigin='anonymous'` is set, and on `src` assignment, synchronously/asynchronously dispatch `'load'`.
2. Mock `document.createElement('canvas').getContext('2d').getImageData` to throw `new DOMException('tainted canvas', 'SecurityError')` (simulating a cross-origin response without CORS headers).
3. Call `getIconData(href)` and assert with `Promise.race([getIconData(href), timeout(500)])` that the promise settles (resolves to `null` after fix, or currently times out/hangs, proving the bug).
4. Table-driven cases: `{network error}` -> resolves `null` (passes today); `{corrupt PNG bytes}` -> `'error'` fires, resolves `null` (passes today); `{tainted-canvas valid decode}` -> currently never settles (fails/hangs, demonstrating the bug); `{zero-dimension image}` -> `getIconDimensions` divides by `image.height` producing `NaN`/`Infinity` width/height passed to `getImageData`, which throws `IndexSizeError`, also hanging today.

const getIconData = (href) => {
  const img = new Image()

  img.crossOrigin = 'anonymous'
  img.src = href

  return new Promise((resolve) => {
    img.addEventListener('load', () => {
      const canvas = document.createElement('canvas')
      const ctx = canvas.getContext('2d')
      const dimensions = getIconDimensions(img, ICON_MAX_SIZE)

      const width = dimensions.width
      const height = dimensions.height

      canvas.width = width
      canvas.height = height

      ctx.drawImage(img, dimensions.dx, dimensions.dy, dimensions.dWidth, dimensions.dHeight)

      const { data } = ctx.getImageData(0, 0, width, height)

      resolve({ width, height, data: base64(data) })
    })

    // If can't compute, enable connecting dapp without icon. UI will render empty state
    img.onerror = () => resolve(null) // eslint-disable-line unicorn/prefer-add-event-listener
  })
}

export const getIcon = async () => {
  const icons = document.querySelectorAll('head > link[rel~="icon"]')
  const sortedIcons = [...icons].sort((a, b) => getIconSize(b) - getIconSize(a))
  const href = sortedIcons[0]?.href || `${document.location.origin}/favicon.ico`

  return getIconData(href)
}

  if (typeof extensionName !== 'string' || typeof channelName !== 'string') {
    throw new TypeError(`Unable to create RPC because channelName or extensionName are missing`)
  }

  const channel = channels[channelName]
  const transport = createWindowRpcTransport({
    name: `${extensionName}-${channelName}`,
    target: `${extensionName}-${channelName}-window`,
  })

  transport.on('data', async (event) => {
    const isResponse = !JSON.parse(event).method
    const senderMetadata = await metadata
    const options = { senderMetadata }

    if (isResponse) {
      channel.sendMessage(event, options)
    } else {
      channel.call(event, options).then(transport.write)
    }
  })
