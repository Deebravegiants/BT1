### Title
Relay flat fee is silently bypassed when `feeStructure.feeToken` matches none of the withdrawal tokens - (File: `contracts/Hinkal.sol`)

### Summary
`Hinkal.transact` lets a proof author choose an arbitrary `feeStructure.feeToken` value that is never checked against the tokens actually being withdrawn (`circomData.erc20TokenAddresses`). If it doesn't match any withdrawal token, the contract silently treats the flat relay fee as `0` for every token instead of rejecting the mismatch, exactly mirroring the charta `registerRepayment` pattern of "accept the parameter and quietly skip the effect" instead of reverting.

### Finding Description
In `_internalTransact`, for every withdrawn token the flat fee is computed as: [1](#0-0) 
```
if (circomData.relay != address(0)) {
    uint256 flatFee = circomData.feeStructure.feeToken ==
        circomData.erc20TokenAddresses[i]
        ? circomData.feeStructure.flatFee
        : 0;
    ...
```
There is no requirement anywhere that `feeStructure.feeToken` be equal to at least one element of `circomData.erc20TokenAddresses`. `feeStructure` and `erc20TokenAddresses` are both bound into the same signed payload (`getHashedCalldata2` / `getSignedMessageHash`) generated by the transaction's own author [2](#0-1) [3](#0-2) , so an unprivileged user constructing their own proof can freely pick a `feeStructure.feeToken` that is guaranteed to differ from every entry of `erc20TokenAddresses` for the withdrawal they intend to make. The `variableRate` portion of the fee is still charged (`recipientAmount`/`relayFee` computation does not depend on `flatFee` being non‑zero), but the flat component is unconditionally dropped to `0` for that withdrawal, and the contract still proceeds and marks `hasPaidToRelay = true` as long as `relayFee > 0` from the variable-rate cut [4](#0-3) . There is no revert path analogous to what the charta fix added (reject the whole call when the "designated" token is not part of the operation); the contract simply accepts the mismatch and continues.

### Impact Explanation
This lets a user unilaterally reduce/eliminate the flat portion of the relay fee that the relay is entitled to for servicing a withdrawal, by simply choosing `feeStructure.feeToken` to be an address outside the token set they are withdrawing. This is a theft/permanent underpayment of protocol/relay fees, matching the "theft or permanent freezing of protocol/relay fees" High-impact category.

### Likelihood Explanation
Likelihood is limited by the fact that the relay chooses whether to submit/process a given signed `circomData`, so a relay that independently verifies the fee terms before broadcasting can refuse non-compliant requests off-chain. However, nothing on-chain enforces the invariant, so any relay implementation that trusts the on-chain fee enforcement (rather than re-deriving expected fees off-chain) is silently underpaid, and any user submitting their own signed data directly can always avoid the flat fee.

### Recommendation
Require that `feeStructure.feeToken` (when `flatFee > 0` and `relay != address(0)`) is present among `circomData.erc20TokenAddresses`, and revert the whole `transact` call if it is not — mirroring the charta fix of rejecting mismatched tokens outright instead of silently zeroing the effect.

### Proof of Concept
1. User constructs a withdrawal `circomData` with `erc20TokenAddresses = [USDC]`, `amountChanges[0] < 0` (withdraw), `relay = <relayAddress>`.
2. User sets `feeStructure = { feeToken: DAI, flatFee: X, variableRate: Y }` (DAI not in `erc20TokenAddresses`).
3. User generates a valid proof over this `circomData` (feeStructure and erc20TokenAddresses are both committed via `getSignedMessageHash`/`calldataHash`, so the proof is self-consistent and valid).
4. On `transact`, in `_internalTransact`, for `i = 0` (`USDC`), `flatFee` evaluates to `0` because `feeStructure.feeToken (DAI) != erc20TokenAddresses[0] (USDC)`; only the variable-rate cut is deducted, and the call succeeds without any revert. [5](#0-4)

```text
    function _internalTransact(CircomData calldata circomData) private {
        bool hasPaidToRelay = false;
        for (uint64 i = 0; i < circomData.erc20TokenAddresses.length; i++) {
            int256 deltaAmountChange = _calculateDeltaAmount(circomData, i);

            if (deltaAmountChange > 0) {
                require(
                    circomData.externalActionData.externalAddress == msg.sender,
                    "Deposit should come from the sender"
                );
                transferERC20TokenFromOrCheckETH(
                    circomData.erc20TokenAddresses[i],
                    circomData.externalActionData.externalAddress,
                    address(this),
                    uint256(circomData.amountChanges[i])
                );
            } else {
                uint256 sumAbs = uint256(-deltaAmountChange);
                uint256 relayFee = 0;
                if (circomData.relay != address(0)) {
                    uint256 flatFee = circomData.feeStructure.feeToken ==
                        circomData.erc20TokenAddresses[i]
                        ? circomData.feeStructure.flatFee
                        : 0;

                    require(
                        sumAbs >= flatFee,
                        "Relay Fee is over withdraw amount"
                    );

                    uint256 recipientAmount = ((10000 -
                        circomData.feeStructure.variableRate) *
                        (sumAbs - flatFee)) / 10000;

                    relayFee = sumAbs - recipientAmount;

                    if (relayFee > 0) {
                        transferERC20TokenOrETH(
                            circomData.erc20TokenAddresses[i],
                            circomData.relay,
                            relayFee
                        );
                    }
                    hasPaidToRelay = true;
                }
                if (sumAbs - relayFee > 0) {
                    transferERC20TokenOrETH(
                        circomData.erc20TokenAddresses[i],
                        circomData.externalActionData.externalAddress,
                        sumAbs - relayFee
                    );
                }
            }
        }
        require(
            circomData.relay == address(0) || hasPaidToRelay,
            "relay not paid"
        );
    }
```
