### Title
Secure-element signature in `make_signature` omits `signup_id`/nonce, enabling attestation replay across distinct signups - ([File: src/plans/enroll_user.rs])

### Summary
`make_signature` (src/plans/enroll_user.rs:290-304) builds the SHA-256 digest signed by the secure element from `ORB_ID`, `user_qr_code.user_id`, `pipeline.v2.ir_net_version`/`iris_version`, and both eyes' `iris_code`/`mask_code`/`iris_code_version`. It never mixes in `self.signup_id`, a timestamp, or a nonce, even though `signup_id` is generated per signup session and passed separately into `signup_post::request` alongside the signature.

### Finding Description
`Plan::run` computes the signature once via `make_signature(&user_qr_code, &pipeline)` (src/plans/enroll_user.rs:74-88) and then sends it together with `signup_id` as independent fields to the backend through `signup_post::request` (src/plans/enroll_user.rs:90-102). Because `signup_id` never enters the hashed digest at src/plans/enroll_user.rs:292-301, the resulting secure-element signature is a pure function of `(ORB_ID, user_id, iris_version, iris/mask codes)` and is therefore identical for any two signup attempts that reuse the same `user_id` and produce the same iris/mask codes, regardless of which `signup_id` they are eventually submitted under. Since the signature and the `signup_id` are transmitted as separate, independently-controllable fields in the same request, nothing in this code path cryptographically binds a given attestation to the specific signup transaction it was produced for.

### Impact Explanation
The secure-element signature is meant to attest "this Orb's secure element vouches for this specific iris capture," and the backend presumably relies on that attestation being unique per signup for auditing/fraud analysis. Because `signup_id` is not part of the signed digest, a previously observed valid `(signature, iris_code, mask_code, user_id)` tuple can be re-submitted under a different `signup_id`, and the signature check alone cannot distinguish the two signups. This breaks the uniqueness/non-replayability guarantee of the attestation and could let a second, distinct signup session inherit an attestation that was actually produced for a different signup event.

### Likelihood Explanation
Exploitation requires the attacker to obtain two signup attempts that yield bit-identical `iris_code`/`mask_code` values under the same `user_id` (e.g., via a replayed/recorded capture), which is a strong precondition given normal iris-code capture noise and any existing liveness/uniqueness checks elsewhere in the pipeline. Given that precondition, however, reproducing an identical signature across two different `signup_id`s is deterministic and trivially repeatable, since `make_signature` performs no session-specific mixing at all.

### Recommendation
Include `signup_id` (and ideally a timestamp or per-session nonce) in the digest hashed by `make_signature` before calling `secure_element::sign`, so that the signature cryptographically binds to the specific signup session and cannot be replayed across different `signup_id`s.

### Proof of Concept
Unit test in `src/plans/enroll_user.rs`:
1. Construct a `qr_scan::user::Data` with a fixed `user_id` and a `Pipeline` with fixed `iris_code`/`mask_code`/version fields for both eyes.
2. Call `make_signature(&user_qr_code, &pipeline)` twice, simulating two different `Plan` instances with distinct `signup_id`s (e.g., different `SignupId::default()` values).
3. Assert the two resulting base64 signature strings are equal (`assert_eq!(sig_a, sig_b)`), demonstrating that the signature does not vary with `signup_id` and can be replayed unchanged across independent signups. [1](#0-0) [2](#0-1)

fn make_signature(user_qr_code: &qr_scan::user::Data, pipeline: &Pipeline) -> Result<String> {
    let mut ctx = Context::new(&SHA256);
    ctx.update(ORB_ID.as_str().as_bytes());
    ctx.update(user_qr_code.user_id.as_bytes());
    ctx.update(pipeline.v2.ir_net_version.as_bytes());
    ctx.update(pipeline.v2.iris_version.as_bytes());
    ctx.update(pipeline.v2.eye_left.iris_code.as_bytes());
    ctx.update(pipeline.v2.eye_left.mask_code.as_bytes());
    ctx.update(pipeline.v2.eye_left.iris_code_version.as_bytes());
    ctx.update(pipeline.v2.eye_right.iris_code.as_bytes());
    ctx.update(pipeline.v2.eye_right.mask_code.as_bytes());
    ctx.update(pipeline.v2.eye_right.iris_code_version.as_bytes());
    let signed = secure_element::sign(ctx.finish())?;
    Ok(BASE64.encode(&signed))
}
