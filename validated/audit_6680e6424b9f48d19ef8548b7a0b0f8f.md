### Title
Missing source-identity verification when handling `RequestState` messages allows state disclosure to unverified relay peers - ([File: orb-relay-client/src/client.rs])

### Summary
In the Orb⇄App relay client used for self-serve signup IPC, incoming messages are normally validated against the expected paired peer (`src.id == self.config.dst_id`) before being processed. However, when the incoming payload matches `self_serve::app::v1::RequestState`, this source-identity check is completely bypassed: the client immediately re-sends its `last_message` to the sender without verifying that `src.id` belongs to the registered/paired peer for this session.

### Finding Description
The `PollerAgent::main_loop` function branches on the type of the received payload before applying the peer-identity check: [1](#0-0) 

```rust
if self_serve::app::v1::RequestState::matches(&payload).is_some() {
    sender_tx.send(self.last_message.clone()).await...
} else if src.id != self.config.dst_id {
    tracing::error!("Skipping received message from unexpected source: ...");
} else {
    self.handle_message(...).await?;
}
```

For every other message type, the code validates that `src.id` equals `self.config.dst_id` (the entity that was registered as this session's counterpart when the client was constructed via `Client::new_as_orb` / `Client::new_as_app`) [2](#0-1) . This is the exact analog of `s.vaults[c.lienRequest.strategy.vault]` in the reported bug — a caller-influenced identifier (`src.id`) that must be checked against the set of trusted/registered peers before the code performs a privileged action on its behalf.

For `RequestState`, this check is skipped entirely: any entity able to deliver a `RequestState`-typed payload to this session (regardless of its `src.id`) causes the client to unconditionally resend `self.last_message` — the last protocol message it sent to its legitimate peer (e.g. `AnnounceOrbId`, `SignupEnded`, `CaptureStarted`, `AgeVerificationRequiredFromOperator`, etc., see `IntoPayload` impls) [3](#0-2) .

This client is used during the self-serve signup flow to synchronize Orb/App signup state over the relay [4](#0-3) , so the "IPC" boundary here is the orb-relay channel used for signup state exchange between the Orb and an unprivileged user's App, matching the allowed "agent-IPC trust boundary" bug class.

### Impact Explanation
An unregistered/unverified relay entity that manages to have a `RequestState` payload routed to an Orb's or App's session obtains an unauthenticated echo of that session's last signup-state message, bypassing the same-peer validation that protects every other message type. Depending on relay-server routing guarantees, this can leak signup/session state (e.g. capture state, orb-id announcement, age-verification prompts) to an entity that was never validated as the paired counterpart for that session — a cross-signup state disclosure analogous to the unregistered-vault fund drain in the original report, where an unchecked caller-supplied identifier let an unauthorized party trigger privileged behavior meant only for a registered/paired counterpart.

### Likelihood Explanation
The bypass is unconditional and requires no special relay privileges — merely sending (or getting routed) a payload matching the `self_serve::app::v1::RequestState` type-URL triggers the response, with `src.id` never inspected in that branch. This is a straightforward oversight in an otherwise-consistent validation pattern applied to all other message types.

### Recommendation
Apply the same `src.id != self.config.dst_id` check before handling `RequestState`, so that only the registered/paired peer for the session can trigger a resend of `last_message`:

```rust
if src.id != self.config.dst_id {
    tracing::error!("Skipping received message from unexpected source: {:?}", src.id);
} else if self_serve::app::v1::RequestState::matches(&payload).is_some() {
    sender_tx.send(self.last_message.clone()).await...
} else {
    self.handle_message(...).await?;
}
```

### Proof of Concept
1. Establish a relay connection as an arbitrary entity (any `src_id`) capable of having a payload delivered to a target Orb/App session.
2. Craft and send a payload matching `self_serve::app::v1::RequestState` (via `unpack_any::<self_serve::app::v1::W>` type URL) with `src.id` set to any value other than the session's registered peer id.
3. Observe in `orb-relay-client/src/client.rs` (lines 436-440) that the check `src.id != self.config.dst_id` is never evaluated for this payload type, and the target immediately replies with `self.last_message`, disclosing the last signup-state message to the unverified sender.
