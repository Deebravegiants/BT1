### Title
Unbounded interest-value accrual permanently freezes a high-utilization market - (File: contracts/pool/src/cache/scale.rs)

### Summary
A market with extremely large supplied and borrowed balances can drive the scaled-to-asset index conversion past `i128` before the configured borrow-index ceiling is reached. After that point, every market operation that first accrues interest—including `update_indexes`, `repay`, `withdraw`, `borrow`, `liquidate`, and flash paths—reverts on `MathOverflow`, permanently freezing the market’s funds. [1](#0-0) 

### Finding Description
The pool scales balances between share-space and asset-space using `scaled_to_original` during interest accrual. The conversion uses checked fixed-point multiplication and panics with `GenericError::MathOverflow` when the result no longer fits in `i128`. [2](#0-1) 

The protocol test demonstrates that a sufficiently large 18-decimal market at sustained 98% utilization reaches the value ceiling before `MAX_BORROW_INDEX_RAY` engages. [3](#0-2) 

Once the next accrual overflows, `update_indexes` fails with `MathOverflow`. Because the same accrual precedes exits and repayments, subsequent `withdraw` and `repay` calls also fail with `MathOverflow`. [4](#0-3) 

### Impact Explanation
The affected market cannot process further accrual-dependent operations, leaving suppliers unable to withdraw and borrowers unable to repay through the normal controller entrypoints. This is permanent freezing of user funds unless governance replaces the implementation or otherwise changes the contract state. [5](#0-4) 

### Likelihood Explanation
The trigger requires a very large market and sustained high utilization, so it is not reachable on an ordinary market without substantial capital and accumulated interest. However, it is reachable by unprivileged protocol actions: an account owner supplies collateral and borrows, and any caller can invoke `controller::update_indexes` to advance accrual once the overflow condition exists. [6](#0-5) 

### Recommendation
Make `scaled_to_original` and the accrual path saturate or explicitly clamp before the computed asset value can exceed `i128`, rather than allowing a checked-conversion panic. Alternatively, enforce a lower market/index bound that is guaranteed to occur before the largest possible scaled balance multiplied by the index reaches the `i128` limit, and add regression coverage proving post-cap `update_indexes`, `repay`, and `withdraw` remain executable. [7](#0-6) 

### Proof of Concept
1. Create an 18-decimal market with the steep interest-rate curve and remove or lift the practical utilization/cap constraints used by the test.
2. Supply `1_000_000_000 * 10^18` units of the market asset.
3. Supply enough separate collateral to borrow `98%` of that asset.
4. Repeatedly advance the ledger timestamp and call `controller::update_indexes` with the market’s `HubAssetKey`.
5. Observe `update_indexes` revert with `MathOverflow` while the stored borrow index is still below `MAX_BORROW_INDEX_RAY`.
6. Call `controller::withdraw` for the supplier and `controller::repay` for the borrower; both revert with `MathOverflow` because they accrue the market before applying their requested action. [8](#0-7)

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);

/// Computes `floor(x * y / d)`, rounding toward negative infinity for a negative quotient.
/// Panics with `GenericError::DivisionByZero` if `d == 0`, or with
/// `GenericError::MathOverflow` if the result does not fit in `i128`.
pub fn mul_div_floor(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    require_nonzero_divisor(env, d);
    if let Some(quotient) = x
        .checked_mul(y)
        .and_then(|product| div_floor_i128(product, d))
    {
        return quotient;
    }
    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    let nonneg = quotient_is_nonnegative(x, y, d);
    to_i128(env, &div_floor_i256(env, &x256.mul(&y256), &d256, nonneg))
}
