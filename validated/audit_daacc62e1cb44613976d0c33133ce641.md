Audit Report

## Title
CORS wildcard-origin allowlist bypass via missing domain-boundary check in Gateway HTTP server - (File: core/services/gateway/network/httpserver.go)

## Summary
The Gateway HTTP server's `isAllowedOrigin` function implements wildcard CORS origin matching using a raw `strings.HasSuffix` comparison without enforcing a domain boundary, so any attacker-registered domain that merely ends with the configured allowed suffix (e.g. `evilchain.link` for a `*.chain.link` allowlist entry) is incorrectly treated as an allowed origin. This is confirmed directly in the code at [1](#0-0)  and is invoked on every request through `handleRequest` using the unprivileged, attacker-controlled `Origin` header at [2](#0-1) .

## Finding Description
`isAllowedOrigin` splits the incoming `Origin` header and each configured allowed origin into scheme/host/port via `splitURL` [3](#0-2) . For wildcard entries prefixed with `*.`, it strips the prefix and performs `strings.HasSuffix(originHost, allowedHost)` [4](#0-3) . Because `HasSuffix` is a pure string-suffix check with no `.`-boundary enforcement, `strings.HasSuffix("evilchain.link", "chain.link")` returns `true`, incorrectly matching an unrelated domain. This function is called directly from `handleRequest`, which reflects the attacker-supplied `Origin` value into `Access-Control-Allow-Origin` when the check passes, with no other origin-boundary validation elsewhere in the code path [2](#0-1) . The existing test suite only validates true-positive subdomain matches (e.g. `remix.ethereum.org`, `another.valid.domain.com`, `example.gov`) and does not test the boundary-bypass case, so the flaw is unguarded by tests [5](#0-4) .

## Impact Explanation
When an operator configures a wildcard `CORSAllowedOrigins` entry (a supported, documented configuration), an attacker who registers any domain ending in the same character sequence as the configured suffix will have their origin accepted by the Gateway's CORS policy, and the server reflects that origin into `Access-Control-Allow-Origin`. This is a concrete allowlist-bypass condition matching the CORS-origin allowlist logic in `isAllowedOrigin`.

## Likelihood Explanation
Exploitation requires: (1) the operator to enable CORS with a wildcard entry in `CORSAllowedOrigins` — a normal, supported configuration, not a misconfiguration in the security sense; and (2) the attacker to control any domain name ending in the same suffix string, which is trivially achievable via public domain registration. No network position, host access, or privileged credentials are needed — only a normal HTTP request with a crafted `Origin` header, which is exactly what `handleRequest` processes for every unprivileged client request.

## Recommendation
Fix `isAllowedOrigin` to enforce a proper domain boundary in the wildcard branch, e.g., require `originHost == allowedHost || strings.HasSuffix(originHost, "."+allowedHost)` instead of the raw `strings.HasSuffix(originHost, allowedHost)` check, so `evilchain.link` is correctly rejected against a `*.chain.link` allowlist entry.

## Proof of Concept
1. Configure the Gateway HTTP server with `CORSEnabled: true` and `CORSAllowedOrigins: []string{"https://*.chain.link"}`.
2. Send a POST request to the Gateway's configured path with header `Origin: https://evilchain.link`.
3. Observe that `isAllowedOrigin` returns `true` (via `strings.HasSuffix("evilchain.link", "chain.link")`), and the response includes `Access-Control-Allow-Origin: https://evilchain.link`.
4. This can be verified as a Go unit test analogous to `TestHTTPServer_HandleRequest_CORSEnabled_FromAllowedOriginWildcards` in `core/services/gateway/network/httpserver_test.go`, but asserting the origin `https://evilchain.link` against allowed origin `https://*.chain.link` and confirming the (incorrect) `Access-Control-Allow-Origin` reflection.

```go
func (s *httpServer) isAllowedOrigin(origin string) bool {
	originScheme, originHost, originPort, err := s.splitURL(origin)
	if err != nil {
		s.lggr.Debug("error parsing origin URL", err)
		return false
	}
	for _, allowed := range s.config.CORSAllowedOrigins {
		// probably better to do this once when server starts and store it in a map
		// this is an easier solution so we don't have to apply more changes to the code
		// just need to be careful when specifying allowed origins in the config file
		allowedScheme, allowedHost, allowedPort, err := s.splitURL(allowed)
		if err != nil {
			s.lggr.Debug("error parsing allowed origin URL", err)
			continue
		}
```

```go
func (s *httpServer) handleRequest(w http.ResponseWriter, r *http.Request) {
	if s.config.CORSEnabled {
		origin := r.Header.Get("Origin")
		if s.isAllowedOrigin(origin) {
			w.Header().Set("Access-Control-Allow-Origin", origin)
			w.Header().Set("Access-Control-Allow-Methods", "GET, POST, OPTIONS")
			w.Header().Set("Access-Control-Allow-Headers", "Content-Type")
		}
```

```go
func TestHTTPServer_HandleRequest_CORSEnabled_FromAllowedOriginWildcards(t *testing.T) {
	t.Parallel()
	_, handler, url := startNewServer(t, 100_000, 100_000, true,
		[]string{"https://*.ethereum.org", "https://*.valid.domain.com", "http://*.gov"})

	handler.On("ProcessRequest", mock.Anything, mock.Anything, mock.Anything).Return([]byte("response"), 200)

	origin := "https://remix.ethereum.org"
	resp, respBytes := sendRequest(t, url, []byte("0123456789"), http.MethodPost, &origin) //nolint:bodyclose // sendRequest closes the body
	require.Equal(t, http.StatusOK, resp.StatusCode)
	require.Equal(t, []byte("response"), respBytes)
	require.Equal(t, origin, resp.Header.Get("Access-Control-Allow-Origin"))
	require.Equal(t, "GET, POST, OPTIONS", resp.Header.Get("Access-Control-Allow-Methods"))
	require.Equal(t, "Content-Type", resp.Header.Get("Access-Control-Allow-Headers"))

	handler.On("ProcessRequest", mock.Anything, mock.Anything, mock.Anything).Return([]byte("response"), 200)

	origin = "https://another.valid.domain.com"
	resp, respBytes = sendRequest(t, url, []byte("0123456789"), http.MethodPost, &origin) //nolint:bodyclose // sendRequest closes the body
	require.Equal(t, http.StatusOK, resp.StatusCode)
	require.Equal(t, []byte("response"), respBytes)
	require.Equal(t, origin, resp.Header.Get("Access-Control-Allow-Origin"))
	require.Equal(t, "GET, POST, OPTIONS", resp.Header.Get("Access-Control-Allow-Methods"))
	require.Equal(t, "Content-Type", resp.Header.Get("Access-Control-Allow-Headers"))

	handler.On("ProcessRequest", mock.Anything, mock.Anything, mock.Anything).Return([]byte("response"), 200)

	origin = "http://example.gov"

	require.Equal(t, http.StatusOK, resp.StatusCode)

	require.Equal(t, origin, resp.Header.Get("Access-Control-Allow-Origin"))
	require.Equal(t, "GET, POST, OPTIONS", resp.Header.Get("Access-Control-Allow-Methods"))
	require.Equal(t, "Content-Type", resp.Header.Get("Access-Control-Allow-Headers"))
}
```
