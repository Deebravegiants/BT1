## Title
Unbounded, fee-free computational cost in `pallet_ismp::handle_unsigned` mempool validation via oversized/heavy message batches (GRANDPA `unknown_headers`, etc.) — (File: `modules/pallets/ismp/src/lib.rs`)

### Summary
`pallet-ismp`'s `handle_unsigned` extrinsic is dispatched with `ensure_none` (anyone, no signature, no fee) and is fully executed inside `validate_unsigned` before ever reaching a block, using a **static, content-independent weight**. Several message payloads it accepts — most notably GRANDPA `FinalityProof::unknown_headers: Vec<H>` — carry **no explicit bound** on their size, unlike the analogous BSC path which caps `epoch_header_ancestry` at `BoundedVec<CodecHeader, ConstU32<1000>>`. This lets an unauthenticated relayer submit maximal-size, computation-heavy `handle_unsigned` extrinsics for free, and have every full node's transaction pool re-execute the full verification path (header decoding, hashing, `AncestryChain` construction/walk, justification checks) on every such submission before rejecting it — a cost mismatch analogous to CVE-2020-0602's "improper handling of a web request causing DoS."

### Finding Description
- `handle_unsigned` is declared with a fixed weight regardless of payload size or content: [1](#0-0) 
```
/// Static weights because these should get overridden by the FeeHandler
fn weight() -> Weight {
	Weight::from_parts(300_000_000, 0)
}
```
- It is dispatched as `Unsigned`/`ensure_none`, i.e. free, spam-resistant only by virtue of the mempool re-running full validation: [2](#0-1) 
- `validate_unsigned` does not just check shape — it **fully executes** `Self::execute(messages.clone())` for every candidate extrinsic before it can be rejected, meaning the entire cost of processing (including cryptographic verification, header hashing, and any embedded proof walking) is paid by every full node validating the transaction pool, not just the block author: [3](#0-2) 
- One of the accepted `Message::Consensus` payloads routes to the GRANDPA consensus client, whose `FinalityProof.unknown_headers` field is an **unbounded** `Vec<H>` (contrast with BSC's `BoundedVec<..., ConstU32<1000>>`): [4](#0-3) [5](#0-4) 
- Verification builds a `BTreeMap` over every header (hashing each one) and then, for every precommit in the justification, walks a parent-hash chain back to the base block: [6](#0-5) 
- This same unbounded vector is decoded and hashed again during `verify_grandpa_finality_proof`/`verify_parachain_headers_with_grandpa_finality_proof`, each of which is reachable straight from `handle_unsigned`: [7](#0-6) 

Because `weight()` is a flat constant independent of `messages.len()` or the size of any embedded consensus proof, and the call is fee-free, the protocol has no mechanism to make the submitter pay proportionally for large, expensive-but-ultimately-invalid batches. An attacker can pack a `handle_unsigned` extrinsic up to the maximum allowed extrinsic/block size with a GRANDPA consensus message carrying thousands of synthetic headers (or with other Message variants carrying maximal proof arrays), and repeatedly resubmit variants of it (unsigned transactions have no nonce, so many near-duplicate payloads can be crafted) to force disproportionate CPU/memory work onto every collator/full node performing pool validation, without ever paying for it.

### Impact Explanation
This is a network-wide resource-exhaustion / block-production-degradation vector reachable by any unprivileged actor who can submit an unsigned extrinsic to the Hyperbridge parachain's tx pool — exactly the class of actor this scan is scoped to (an unprivileged message dispatcher/relayer). Sustained abuse could slow down or stall consensus-message and request/response processing across the ISMP host, i.e. a route becoming unable to deliver messages in a timely manner, which is one of the explicitly accepted impacts for this scan.

### Likelihood Explanation
Medium. The attack requires no privileged access, no valid proof, and no fee — only the ability to submit an unsigned extrinsic (`Ismp::handle_unsigned`) with a large `Message::Consensus` GRANDPA payload (or other unbounded/underpriced payload) up to the chain's extrinsic size limit. The barrier is the maximum extrinsic/block size configured in the runtime, which still allows a substantial number of headers/proof items to be packed into a single call, and the attack can be repeated cheaply since it's fee-free.

### Recommendation
- Bound `FinalityProof::unknown_headers` (and any other unbounded `Vec<H>`/proof-array fields reachable via `handle_unsigned`) with an explicit `BoundedVec<_, ConstU32<N>>`, mirroring the cap already applied to BSC's `epoch_header_ancestry`.
- Make `handle_unsigned`'s declared weight (and/or its `FeeHandler`-driven post-dispatch weight) scale with the actual size of the submitted `messages` (number of messages, number of headers/leaves/proof items), rather than using a flat constant, so oversized batches are weighted (and therefore rate-limited/priced) proportionally to the work they cause validating nodes to perform.
- Consider cheap, pre-execution shape/size validation (bounds on header counts, proof array lengths) that runs before `Self::execute()` is invoked in `validate_unsigned`, so grossly oversized submissions are rejected without paying the full verification cost.

### Proof of Concept
Not independently reproduced (no test-harness access in this pass); the mechanism is demonstrated structurally:
1. Construct a `Message::Consensus(ConsensusMessage)` whose GRANDPA `FinalityProof.unknown_headers` contains the maximum number of minimal `SubstrateHeader`s that fit under the runtime's extrinsic/block size limit.
2. Submit it as `Ismp::handle_unsigned([message])` via an unsigned transaction (as done by `subxt::dynamic::tx("Ismp", "handle_unsigned", ...)` in the existing test/relayer code paths, e.g. `parachain/simtests/src/pallet_ismp.rs:282-290` and `tesseract/messaging/substrate/src/provider.rs:846-851`).
3. Because `validate_unsigned` calls `Self::execute(messages.clone())` before any weight-based rejection, every node's pool pays for hashing/decoding all headers and walking `AncestryChain::ancestry` per precommit, regardless of whether the extrinsic is ultimately accepted or rejected as invalid.
4. Repeat with fresh nonce-less variants (no fee, no nonce collision needed across distinct payload bytes) to sustain load.

**Note on uncertainty:** I was unable to fully verify, within the available tool-call budget, whether `pallet_ismp`'s `FeeHandler` (`modules/pallets/ismp/src/fee_handler.rs`) recomputes and enforces a size-proportional `actual_weight`/fee post-dispatch in a way that could mitigate this (the doc comment "Static weights because these should get overridden by the FeeHandler" suggests such a mechanism might exist for *signed* fee-charging paths, but `handle_unsigned`'s own return value `Ok(().into())` does not set `actual_weight`, and unsigned calls are `Pays::No` by design). This should be confirmed before treating the recommendation as final — if a working post-dispatch weight-correction mechanism does exist and is applied at the `validate_unsigned` stage (not just at inclusion time), the severity of this finding would be reduced.

impl<H: HeaderT> AncestryChain<H> {
	/// Initialize the ancestry chain given a set of relay chain headers.
	pub fn new(ancestry: &[H]) -> AncestryChain<H> {
		let ancestry: BTreeMap<_, _> = ancestry.iter().cloned().map(|h: H| (h.hash(), h)).collect();

		AncestryChain { ancestry }
	}

	/// Fetch a header from the ancestry chain, given it's hash. Returns [`None`] if it doesn't
	/// exist.
	pub fn header(&self, hash: &H::Hash) -> Option<&H> {
		self.ancestry.get(hash)
	}
}

impl<H: HeaderT> finality_grandpa::Chain<H::Hash, H::Number> for AncestryChain<H>
where
	H::Number: finality_grandpa::BlockNumberOps,
{
	fn ancestry(
		&self,
		base: H::Hash,
		block: H::Hash,
	) -> Result<Vec<H::Hash>, finality_grandpa::Error> {
		let mut route = vec![block];
		let mut current_hash = block;
		while current_hash != base {
			match self.ancestry.get(&current_hash) {
				Some(current_header) => {
					current_hash = *current_header.parent_hash();
					route.push(current_hash);
				},
				_ => return Err(finality_grandpa::Error::NotDescendent),
			};
		}
		Ok(route)
	}
