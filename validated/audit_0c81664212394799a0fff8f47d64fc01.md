Audit Report

## Title
Unauthenticated LOOP Plugin Discovery/Metrics/PPROF Endpoints Bypass Node Authentication Layer - (File: core/web/router.go)

## Summary
`NewRouter` in `core/web/router.go` mounts `loopRoutes` directly on the unauthenticated `api` group, unlike `debugRoutes` (wrapped in `auth.Authenticate(..., auth.AuthenticateBySession)`) and `metricRoutes` (only ever mounted inside `authv2`, gated by token/session auth). This exposes `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` to any unauthenticated remote client that can reach the node's HTTP API port.

## Finding Description
`NewRouter` builds the `api` group with only CORS/rate-limit/session-cookie middleware and no authentication requirement: [1](#0-0) 

`debugRoutes` explicitly wraps `/debug/vars` in session authentication: [2](#0-1) 

`metricRoutes` (the node's own pprof handlers) is defined but is only ever invoked inside the `authv2` group, gated by `auth.Authenticate(..., auth.AuthenticateByToken, auth.AuthenticateBySession)`: [3](#0-2) [4](#0-3) 

By contrast, `loopRoutes` — which forwards to `pluginMetricHandler`, `pluginPPROFHandler`, and `pluginPPROFPOSTSymbolHandler` (the equivalent debug/pprof surface for LOOP plugins) — is registered directly on the bare `api` group with zero auth middleware: [5](#0-4) [6](#0-5) 

I verified the handler implementations in `core/web/loop_registry.go`. `pluginPPROFHandler`/`pluginPPROFPOSTSymbolHandler` forward the caller's request (including arbitrary `debug`, `gc`, and `seconds` query parameters) to `http://<loopHostName>:<PrometheusPort>/debug/pprof/<profile>` for whichever plugin is requested, with no authentication check anywhere in the handler chain: [7](#0-6) [8](#0-7) 

`discoveryHandler` similarly returns the full list of registered plugin names and Prometheus scrape targets/hostnames with no auth check: [9](#0-8) 

This confirms the root cause: the session/rate-limit-only `api` group carries no authentication by default, and each sub-route builder is individually responsible for opting into `auth.Authenticate`. `loopRoutes` is the one route group in `NewRouter` that never opts in, unlike its functionally analogous sibling `metricRoutes`.

## Impact Explanation
An unauthenticated remote client that can reach the node's HTTP listener can:
- Enumerate all registered LOOP plugins and their metrics scrape endpoints via `/discovery`.
- Pull live metrics via `/plugins/:name/metrics`.
- Pull CPU/heap/goroutine/mutex/block profiles and full stack traces via `/plugins/:name/debug/pprof/*`, including expensive, long-running profile captures (`profile?seconds=N`), which can also be used to degrade availability of the plugin process.

This is an authentication bypass on a debug/introspection surface that the codebase's own design intends to be gated (as evidenced by `debugRoutes` and `metricRoutes` both requiring authentication for equivalent functionality). This maps to the in-scope "node API authentication bypass" impact category and can lead to sensitive information disclosure (plugin internals, potential in-memory secrets) and node/plugin availability degradation.

## Likelihood Explanation
Likelihood is high wherever the node's HTTP API port is reachable by anyone other than the operator, which is the same listener serving both the public and `/v2` authenticated routes. No credentials or special network position are required — a single unauthenticated GET/POST is sufficient, and the request is trivially repeatable. The only precondition is that one or more LOOP plugins are registered, which is standard for OCR2/plugin-based job types.

## Recommendation
Wrap `loopRoutes` in the same authentication middleware pattern used by `debugRoutes`/`metricRoutes` — e.g., mount it inside `authv2` or a dedicated group gated by `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)`, instead of passing the bare `api` group into `loopRoutes` at line 91 of `core/web/router.go`. Add a regression test in the `auth_test.go` RBAC suite asserting `/discovery`, `/plugins/:name/metrics`, and `/plugins/:name/debug/pprof/*` return 401/403 for unauthenticated callers.

## Proof of Concept
Against a running node with at least one LOOP plugin registered, send requests with no `Authorization` header and no session cookie:
```
curl -s -o /dev/null -w "%{http_code}\n" http://NODE_HOST:6688/discovery
curl -s -o /dev/null -w "%{http_code}\n" http://NODE_HOST:6688/plugins/<plugin-name>/metrics
curl -s -o /dev/null -w "%{http_code}\n" "http://NODE_HOST:6688/plugins/<plugin-name>/debug/pprof/goroutine?debug=2"
```
Expected on the current code: HTTP 200 with discovery/metrics/pprof data, contrasted with `http://NODE_HOST:6688/v2/...pprof...` (via `metricRoutes`/`authv2`) which returns 401 without a valid token/session. A Go integration test can be written using `gin.CreateTestContext` plus `NewRouter` to assert the same, or extending the `routesRolesMap` table in `core/web/auth/auth_test.go` with the `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*` paths.

```go
// discoveryHandler implements service discovery of prom endpoints for LOOPs in the registry
func (l *LoopRegistryServer) discoveryHandler(w http.ResponseWriter, req *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	groups := make([]*targetgroup.Group, 0, 1+len(l.registry.List()))

	// add node metrics to service discovery
	groups = append(groups, pluginGroup(l.discoveryHostName, l.exposedPromPort, "/metrics"))

	// add all the plugins
	for _, registeredPlugin := range l.registry.List() {
		group := pluginGroup(l.discoveryHostName, l.exposedPromPort, pluginMetricPath(registeredPlugin.Name))
		group.Labels[LabelMetaPluginName] = model.LabelValue(registeredPlugin.Name)
		groups = append(groups, group)
	}

	b, err := l.jsonMarshalFn(groups)
	if err != nil {
		w.WriteHeader(http.StatusInternalServerError)
		_, err = w.Write([]byte(err.Error()))
		if err != nil {
			l.logger.Error(err)
		}
		return
	}
	_, err = w.Write(b)
	if err != nil {
		w.WriteHeader(http.StatusInternalServerError)
		l.logger.Error(err)
	}
}
```

```go
func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
```

```go
func (l *LoopRegistryServer) pluginPPROFPOSTSymbolHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/symbol", l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	body, err := io.ReadAll(gc.Request.Body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error reading plugin pprof request body: %s", err))
		return
	}
	l.doRequest(gc, "POST", pluginURL, bytes.NewReader(body), timeout, pluginName)
}
```
