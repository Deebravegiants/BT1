### Title
Anyone can permanently cancel any pending `emporiumMessage`, freezing a victim's signed intent - ([File: contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol])

### Summary
`cancelEmporiumMessage` only checks that the ECDSA signature it receives recovers to `msg.sender`, but never checks that `msg.sender` (or the recovered address) is the actual `stack.signerAddress` who created the pending `EmporiumStack` for that `emporiumMessage`. Since any EOA can trivially self-sign an `EmporiumCancel(message)` payload for an arbitrary `message` id with their own key, any unprivileged attacker can mark any not-yet-used `emporiumMessage` as `usedMessages[...] = true`, permanently blocking the victim's legitimately signed `EmporiumStack` from ever being executed via `runAction`/`verifyWallet`.

### Finding Description
The broken equality: "the party allowed to cancel `emporiumMessage = M`" should equal "the original `stack.signerAddress` who signed the `EmporiumStack` for `M`" — but the code only enforces "recoveredAddress == msg.sender" [1](#0-0) .

`cancelEmporiumMessage` builds an EIP-712 hash over `EMPORIUM_CANCEL_TYPEHASH` and the caller-supplied `emporiumMessage`, recovers the signer from `(v, r, s)`, and requires only that the recovered address equals `msg.sender` [2](#0-1) . Because the attacker is free to sign this payload with their own private key for any `emporiumMessage` value of their choosing, this check is always trivially satisfiable by the attacker regardless of who actually owns that message id — there is no stored mapping from `emporiumMessage` to the signer who created the corresponding `EmporiumStack`, and no cross-check against `stack.signerAddress` from `verifyWallet` [3](#0-2) . The comment above the function ("via a fresh signature recovering to msg.sender (so no one else can cancel it for them)") reflects a design misunderstanding: it prevents someone from cancelling *using the victim's signature*, but does nothing to stop anyone from cancelling *using their own signature* over the victim's message id.

Once `cancelEmporiumMessage(M, ...)` succeeds, `$.usedMessages[M] = true` is set unconditionally [4](#0-3) . Subsequently, when the victim's transaction reaches `verifyWallet` for the same `emporiumMessage`, it reverts with `UsedMessage` because `$.usedMessages[circomData.emporiumMessage]` is already `true` [5](#0-4) .

Exploit flow: victim signs an `EmporiumStack` targeting `emporiumMessage = M` (observable once the transaction is broadcast/dropped, or if ids are predictable/sequential). Attacker calls `cancelEmporiumMessage(M, v_a, r_a, s_a)` where `(v_a, r_a, s_a)` is the attacker's own valid signature over `EMPORIUM_CANCEL_TYPEHASH(M)` — this recovers to the attacker's own address, matching `msg.sender` (the attacker), and the check passes. `usedMessages[M]` becomes `true`. The victim's genuine `runAction` call with `emporiumMessage = M` now always reverts with `UsedMessage`.

### Impact Explanation
This lets any unprivileged attacker deny/cancel any other user's pending Emporium action by front-running with a trivially self-signed cancellation, at near-zero cost (one transaction, no funds at risk). The direct on-chain consequence is denial of the specific signed intent (`EmporiumStack`) for message id `M`; the victim cannot resubmit under the same `M`. However, whether this rises to **Critical: permanent freezing of user funds** depends on whether the victim's underlying shielded UTXO/nullifiers are irrecoverably tied to that specific `emporiumMessage`, or whether the victim can simply regenerate a new proof with a fresh `emporiumMessage` value and resubmit (in which case this is a repeatable but not permanent DoS/griefing vector). The available context does not conclusively establish that `emporiumMessage` is bound to nullifiers in a way that prevents regeneration — this determination requires inspecting how `emporiumMessage`/`messageSeed` is derived and constrained in the circuit (`circuits/MainEVMCircuit.circom`) and in `contracts/CircomDataBuilder.sol`, which the available index did not return full contents for.

### Likelihood Explanation
The attack is cheap and requires no special preconditions beyond knowing/guessing a pending `emporiumMessage` value that has a signed-but-unsubmitted `EmporiumStack`. It is fully repeatable against any number of victims and any number of message ids, since the attacker signs their own arbitrary payload each time.

### Recommendation
`cancelEmporiumMessage` must bind cancellation authority to the actual creator of the message id, not to an arbitrary self-signature. Concrete fix: persist the `signerAddress` associated with each `emporiumMessage` at the time the `EmporiumStack` is first signed/observed (or require the cancel call to include the full `EmporiumStack`/its `signerAddress` and verify that `recoveredAddress == stack.signerAddress` using the same `EMPORIUM_SIGNATURE_TYPEHASH` domain, not a separate cancel-only hash that anyone can self-satisfy). At minimum, require that the caller prove control of the specific `stack.signerAddress` tied to `emporiumMessage` (e.g., by having the cancel signature be produced under the *same* signer key that would have signed the original stack, and validating against a stored/committed signer address rather than an unconstrained `msg.sender`).

### Proof of Concept
Foundry test plan:
1. Deploy `EmporiumUpgradeable`, initialize with helper/owner.
2. Victim (`vk`) constructs an `EmporiumStack` with `signerAddress = victim`, valid `ops`, `maxFee`, `deadline`, and signs `EMPORIUM_SIGNATURE_TYPEHASH` for `emporiumMessage = M` — do NOT submit yet.
3. Attacker (`atk`, unrelated key) calls `cancelEmporiumMessage(M, v_atk, r_atk, s_atk)` where `(v_atk, r_atk, s_atk)` is `atk`'s own signature over `EMPORIUM_CANCEL_TYPEHASH(M)` computed via `_hashTypedDataV4`.
4. Assert the call succeeds (no revert) and `usedMessages[M] == true` (read via a test-only getter or storage slot).
5. Victim then calls `runAction`/triggers `verifyWallet` with `circomData.emporiumMessage = M` and their valid stack; assert it reverts with `UsedMessage()`.
6. This proves an unrelated third party permanently blocked the victim's signed, not-yet-executed intent for message id `M`, with the equality "canceller == original signer" broken (attacker ≠ victim, yet cancellation succeeds).

```text
    function cancelEmporiumMessage(uint256 emporiumMessage, uint8 v, bytes32 r, bytes32 s) external {
        EmporiumStorageVars storage $ = _getEmporiumStorage();

        bytes32 hashedMessage = _hashTypedDataV4(
            keccak256(abi.encode(EMPORIUM_CANCEL_TYPEHASH, emporiumMessage))
        );

        (address recoveredAddress, ECDSA.RecoverError err) = ECDSA.tryRecover(hashedMessage, v, r, s);
        bool verified = err == ECDSA.RecoverError.NoError && recoveredAddress == msg.sender;
        if (!verified) {
            revert InvalidSignature();
        }

        $.usedMessages[emporiumMessage] = true;
    }
```
