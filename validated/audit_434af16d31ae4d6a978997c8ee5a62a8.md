## Finding [1](#0-0) 

### Title
Unauthorized `transferFrom` of a third party's approved tokens via `DepositOnChainUtxosExternalAction` — (File: `contracts/external-actions/DepositOnChainUtxosExternalAction.sol`)

### Summary
`DepositOnChainUtxosExternalAction.runAction` pulls ERC20 tokens from `circomData.originalSender` using `transferERC20TokenFrom`, but nothing in the call path requires `circomData.originalSender == msg.sender` of the top-level `Hinkal.transact()` call. Any address that has approved this external-action contract to spend its tokens (the intended flow for legitimately creating on-chain UTXOs) can have its tokens pulled by an unrelated, unprivileged caller who simply submits a self-crafted (zero-value) proof referencing the victim's address as `originalSender`.

### Finding Description
In `_internalTransact`, deposits explicitly enforce that the depositing address matches the caller: [2](#0-1) 
```
require(
    circomData.externalActionData.externalAddress == msg.sender,
    "Deposit should come from the sender"
);
transferERC20TokenFromOrCheckETH(...);
```

However, the external-action path (`_externalTransact`) has no equivalent restriction. It simply checks that the external action ID/address is a registered one: [3](#0-2) 

`DepositOnChainUtxosExternalAction.runAction` then pulls tokens directly from `circomData.originalSender`: [4](#0-3) 
```
address userAddress = circomData.originalSender;
require(userAddress != address(0), ...);
...
require(deltaAmounts[i] == 0, ...);
...
transferERC20TokenFrom(tokenAddress, userAddress, msg.sender, tokenTotal);
```

`circomData.originalSender` is fully caller-controlled: it is hashed into `calldataHash`/`getSignedMessageHash` inside `CircomDataBuilder.sol` [5](#0-4) , but that hash is only checked for internal consistency with the caller's own ZK proof/nullifiers — it does not bind `originalSender` to the transaction sender (`msg.sender` of `Hinkal.transact()`), nor to the holder of the nullifying private key. Any unprivileged EOA can generate a proof over its own (even zero-value) nullifiers/UTXOs while freely setting `originalSender` to an arbitrary victim address, then invoke `Hinkal.transact()` targeting the `DepositOnChainUtxosExternalAction`. Because `deltaAmounts[i]` is required to be `0` (bypassing the "deposit should come from sender" style check that only exists in `_internalTransact`), the flow proceeds straight to `transferERC20TokenFrom(tokenAddress, victim, action-contract, amount)`.

This breaks the balance/authorization equality the protocol otherwise enforces: value is moved out of a third party's wallet by a `transferFrom` that was never authorized by that wallet's owner as `msg.sender`, nor tied to the prover's own nullifying key — an unauthorized wallet operation as described in the accepted bug class. Any user who has previously approved `DepositOnChainUtxosExternalAction` (as intended, to create their own on-chain UTXOs) is exposed: an attacker can trigger the pull on the victim's behalf, redirecting the resulting on-chain UTXOs to a stealth address chosen entirely by the attacker (`circomData.stealthAddressStructure`).

### Impact Explanation
Direct theft of a victim's approved ERC20 balance: an unprivileged attacker can drain any allowance a user has granted to `DepositOnChainUtxosExternalAction`, with the resulting UTXO commitments controlled by the attacker's own stealth address/public key. This is Critical — direct theft of user funds — matching the rules' Critical impact tier.

### Likelihood Explanation
The precondition (a victim having approved `DepositOnChainUtxosExternalAction` to spend ERC20 tokens) is exactly the state the contract is designed to create as part of normal, legitimate use of on-chain UTXO deposits. Once approved, the attack requires only a self-generated proof over the attacker's own (possibly zero) nullifiers, with `deltaAmounts` set to zero and `originalSender` set to the victim — fully within reach of any EOA with no special privileges.

### Recommendation
Enforce that `circomData.originalSender == msg.sender` (the caller of `Hinkal.transact()`) whenever `DepositOnChainUtxosExternalAction` (or any external action that performs a `transferFrom` from `originalSender`) is invoked, mirroring the check already present in `_internalTransact` (`Hinkal.sol:178-181`). Alternatively, require the ZK proof to bind `originalSender` to `msg.sender` as part of the verified public inputs, not merely as an opaque hashed field.

### Proof of Concept
1. Victim approves `DepositOnChainUtxosExternalAction` to spend `N` tokens (as part of normal deposit flow, e.g. by calling it directly once).
2. Attacker (any unprivileged EOA) constructs a valid Hinkal proof using the attacker's own (or dummy zero-amount) nullifiers/UTXOs, setting:
   - `erc20TokenAddresses = [tokenAddress]`, `amountChanges = [0]`
   - `externalActionData.externalActionId` = the ID registered for `DepositOnChainUtxosExternalAction`
   - `circomData.originalSender = victimAddress`
   - `externalActionData.externalActionMetadata` encoding `utxoAmounts` summing to `N`
   - `stealthAddressStructure` pointing to attacker's own stealth key.
3. Attacker calls `Hinkal.transact(circomData)`.
4. `_externalTransact` → `DepositOnChainUtxosExternalAction.runAction` executes `transferERC20TokenFrom(tokenAddress, victimAddress, action-contract, N)`, pulling the victim's tokens.
5. New on-chain UTXO commitments worth `N` are created under the attacker's stealth address, completing the theft.

    function runAction(
        CircomData calldata circomData,
        int256[] calldata deltaAmounts
    ) external override onlyAllowedRecipient returns (UTXO[] memory utxoSet) {
        uint256 tokenCount = circomData.erc20TokenAddresses.length;
        require(
            tokenCount > 0 && deltaAmounts.length == tokenCount,
            "DepositOnChainUtxosExternalAction: token count mismatch"
        );

        address userAddress = circomData.originalSender;
        require(
            userAddress != address(0),
            "DepositOnChainUtxosExternalAction: Invalid originalSender"
        );

        uint256[][] memory utxoAmounts = abi.decode(
            circomData.externalActionData.externalActionMetadata,
            (uint256[][])
        );
        require(
            utxoAmounts.length == tokenCount,
            "DepositOnChainUtxosExternalAction: metadata length mismatch"
        );

        utxoSet = new UTXO[](countUtxos(utxoAmounts));

        uint256 utxoIndex = 0;
        for (uint256 i = 0; i < tokenCount; i++) {
            require(
                deltaAmounts[i] == 0,
                "DepositOnChainUtxosExternalAction: Delta amount must be zero"
            );

            address tokenAddress = circomData.erc20TokenAddresses[i];
            uint256 tokenTotal = 0;

            for (uint256 j = 0; j < utxoAmounts[i].length; j++) {
                uint256 amount = utxoAmounts[i][j];
                require(
                    amount > 0,
                    "DepositOnChainUtxosExternalAction: UTXO amount must be positive"
                );
                tokenTotal += amount;

                utxoSet[utxoIndex] = UTXO({
                    amount: amount,
                    erc20Address: tokenAddress,
                    stealthAddressStructure: circomData.stealthAddressStructure,
                    timeStamp: circomData.timeStamp + utxoIndex
                });
                utxoIndex++;
            }

            if (tokenAddress != address(0) && tokenTotal > 0) {
                transferERC20TokenFrom(
                    tokenAddress,
                    userAddress,
                    msg.sender,
                    tokenTotal
                );
            }
        }

        emit BlockedUtxosCreated();
    }

        );

        int256[] memory deltaAmountChanges = new int256[](
            circomData.erc20TokenAddresses.length
        );
        for (uint256 i = 0; i < circomData.erc20TokenAddresses.length; i++) {
            deltaAmountChanges[i] = _calculateDeltaAmount(circomData, i);

                    circomData.erc20TokenAddresses[i],
                    circomData.externalActionData.externalAddress,
                    uint256(-deltaAmountChanges[i])
                );
            }
        }

            IExternalActionV2(circomData.externalActionData.externalAddress)
