## Title
Webhook `shop` identity is not bound to the HMAC signature, enabling cross-tenant webhook spoofing - (File: `lib/shopify_api/webhooks/request.rb`)

### Summary
`ShopifyAPI::Webhooks::Request` derives the `shop` (and `topic`, `webhook_id`, `api_version`) attributes straight from unauthenticated HTTP headers, while the HMAC signature that `Registry.process` verifies is computed **only over the raw request body**. This is the exact "field acted on but not covered by the HMAC" pattern from the referenced report: the treasury's `getLoan`/`withdrawReserves` shared one approval mapping without differentiating the caller's intent, here the webhook pipeline shares one HMAC check without differentiating (or binding) the `shop` identity that downstream handler code trusts.

### Finding Description
`Request#to_signable_string` returns only `@raw_body`: [1](#0-0) 

Yet `Request#shop` is read straight from the `shop-domain` header without any cryptographic binding: [2](#0-1) 

`HmacValidator.validate` computes the signature purely from `verifiable_query.to_signable_string` (the body) and compares it against the `hmac` header: [3](#0-2) 

`Registry.process` uses this validation result to gate handler execution, then forwards the *unauthenticated* `request.shop` value into `WebhookMetadata`, which is exactly what host applications use to key/scope data to a specific merchant: [4](#0-3) 

The equality the code implicitly assumes is:

`hmac-verified bytes (raw_body) == identity bytes acted upon (shop header used for tenant scoping)`

This equality is false. The signature only proves the body was produced by a holder of `api_secret_key`; it says nothing about which shop that body belongs to. An attacker who has legitimately received one webhook (body, hmac) pair from Shopify — for example by installing the app on their own store — can replay that same body/hmac pair to the app's webhook endpoint while substituting the `shop-domain` header for a victim shop. The HMAC check still passes because the header is not part of the signed material, and the handler receives `data.shop` claiming to be the victim tenant.

### Impact Explanation
This breaks the tenant-authentication boundary the whole HMAC verification step exists to provide (Critical — cross-tenant access): the app's handler code is designed to trust `WebhookMetadata#shop` as an authenticated statement of which merchant the event belongs to, but that value can be forged independently of the signature check that is supposed to authenticate it.

### Likelihood Explanation
Any internet user can install the target app on a store they control (a normal, unprivileged action) and thereby obtain at least one genuine `(raw_body, hmac)` pair for a webhook topic they can trigger (e.g. `app/uninstalled`, `orders/create`). They can then replay that untouched body+hmac to the app's public webhook endpoint with an arbitrary `shop-domain` header value, since `Registry.process` never re-derives or cross-checks `shop` against anything covered by the signature.

### Recommendation
Include the `shop` domain (and ideally `topic`) in the signable material verified by the HMAC, or independently validate the `shop-domain` header against a known/installed-shop list (with `ShopValidator`) before trusting it, and reject processing if `shop` was not part of the authenticated payload.

### Proof of Concept
1. Attacker installs the target app on `attacker.myshopify.com`, triggering a genuine webhook delivery with body `B` and header `x-shopify-hmac-sha256: H` (valid for `B`).
2. Attacker replays a POST to the app's webhook endpoint with the same body `B`, same `x-shopify-hmac-sha256: H`, but sets `x-shopify-shop-domain: victim.myshopify.com`.
3. `ShopifyAPI::Utils::HmacValidator.validate` recomputes HMAC over `B` only, matches `H`, and returns `true` — see `lib/shopify_api/utils/hmac_validator.rb:26-31` and `lib/shopify_api/webhooks/request.rb:35-38`.
4. `ShopifyAPI::Webhooks::Registry.process` proceeds and calls the topic handler with `WebhookMetadata.new(..., shop: "victim.myshopify.com", ...)`, even though the request never originated from Shopify for that shop — see `lib/shopify_api/webhooks/registry.rb:188-200`.

        def validate_signature(verifiable_query, secret)
          received_signature = verifiable_query.hmac
          computed_signature = compute_signature(verifiable_query.to_signable_string, secret)
          OpenSSL.secure_compare(computed_signature, T.must(received_signature))
        end
