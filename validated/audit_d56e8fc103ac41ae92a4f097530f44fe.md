### Title
Meta-transaction (`DelegateAction`) front-running griefs relayers by consuming the sender's nonce before the relayer's transaction executes - (File: `runtime/runtime/src/actions.rs`)

### Summary
NEAR's meta-transaction feature (NEP-366) lets a user (`sender_id`) sign a `DelegateAction` off-chain and hand it to a relayer, who wraps it in a transaction and pays gas/deposit costs on the user's behalf. The `SignedDelegateAction` is a self-contained, replayable payload: any account can wrap the same bytes in its own transaction and submit it as the "relayer." Because validation only checks that the delegate nonce is greater than the current access-key nonce, whoever gets their wrapping transaction included first consumes the nonce, causing every other holder of the same `SignedDelegateAction` (including the intended relayer) to fail with `DelegateActionInvalidNonce`, after already having paid the SEND-side gas/fees for the outer transaction. This is the exact "permit + external call" griefing pattern from the report, translated to nearcore's meta-transaction primitive: a publicly-known, signature-authorized payload can be frontrun by a third party to invalidate/grief the intended executor's transaction.

### Finding Description
A `DelegateAction`/`SignedDelegateAction` is signed once by the sender and is valid for use by any relayer that wraps it in a transaction, similar to an ERC-20 `permit`: [1](#0-0) . Signature verification only checks that the `DelegateAction` was signed by the sender's key; it does not bind the action to a specific relayer/signer of the outer transaction: [2](#0-1) .

On execution, `apply_delegate_action` verifies the signature and then calls `validate_delegate_action_key`, which only requires `delegate_nonce > current_nonce` on the sender's access key, then advances the nonce: [3](#0-2) [4](#0-3) . Whichever transaction wrapping this `SignedDelegateAction` lands on-chain first advances the nonce; any subsequent transaction wrapping the identical `SignedDelegateAction` (from the original relayer or otherwise) fails with `DelegateActionInvalidNonce`: [5](#0-4) .

Critically, the relayer/signer of the outer transaction already pays the SEND-side costs for wrapping the delegate action before this nonce check runs, and per the documented economics, "Relayer prepaid all fees and all things required by actions... Relayer should verify DelegateAction before submitting it": [6](#0-5) . The wasted gas is borne by whichever party's transaction executes and fails the nonce check — for the legitimate relayer this is a pure griefing loss with no compensation, mirroring the report's "check allowance before `transfer()`" scenario where a front-run permit causes the dependent call to revert after the caller already committed resources.

This is exploitable because `SignedDelegateAction` bytes are necessarily exposed before final inclusion (e.g., visible in the relayer's outbound transaction once gossiped to the network, or leaked via any off-chain channel used to hand it to the relayer), just as permit signatures are exposed in the mempool before their consuming transaction confirms.

### Impact Explanation
Impact is low/no direct fund loss to the sender (`sender_id`), consistent with the original report's rating: no attacker gains funds, and the sender can simply sign a new `DelegateAction` with a fresh nonce. However, it griefs the relayer, who bears the wasted SEND-side gas cost for a transaction that fails execution once the nonce is consumed by the frontrunning transaction, and it disrupts the meta-transaction guarantee that the relayer's submission will execute the intended action.

### Likelihood Explanation
Likelihood is high in the same sense as the original finding: exploitation requires no special privilege — any account can observe a broadcast transaction containing a `SignedDelegateAction` and, before it is included, submit its own transaction wrapping the identical bytes with a higher priority/gas price, or simply resubmit as soon as it becomes visible. No signature forgery or privileged access is needed, only visibility of the already-signed payload prior to inclusion, which is inherent to how transactions propagate before finality.

### Recommendation
- Bind the `DelegateAction` to a specific authorized relayer (e.g., include an expected relayer/signer account id or public key in the signed payload) so only that party's wrapping transaction is accepted, similar to how ERC-20 `permit` griefing is mitigated by pre-checking allowance/binding execution context.
- Alternatively/additionally, document and mitigate at the relayer-service level: relayers should treat delegate-action submission as an atomic "claim" operation (e.g., using their own reserved nonce range or holding the payload privately until final inclusion) rather than relying solely on protocol-level nonce checks, and should be prepared for the fact that the SEND-side cost paid on an ultimately-reverted `DelegateActionInvalidNonce` result is not refunded.
- Consider making the nonce check idempotent-safe for the legitimate relayer, e.g. by exposing an execution mode where a stale nonce due to legitimate execution (not malicious replay) does not burn the relayer's send-side gas, though this requires careful protocol-level design to avoid new replay issues.

### Proof of Concept
1. Alice signs a `DelegateAction { sender_id: alice, receiver_id: bob, nonce: N, actions: [...] }` and sends `SignedDelegateAction` bytes to Relayer R off-chain.
2. R constructs and broadcasts `Transaction { signer_id: R, actions: [Action::Delegate(signed_delegate_action)] }`.
3. Attacker M observes the broadcast transaction (or otherwise obtains the same `SignedDelegateAction` bytes) before it is included in a block, and submits its own `Transaction { signer_id: M, actions: [Action::Delegate(signed_delegate_action)] }` with a higher gas price so it is included first.
4. M's transaction is included: `apply_delegate_action` verifies the (unchanged) signature, passes `validate_delegate_action_key`, and bumps Alice's access-key nonce to `N`, per [7](#0-6) .
5. R's transaction, submitted with the same delegate nonce `N`, now fails at `validate_delegate_action_key` with `ActionErrorKind::DelegateActionInvalidNonce { delegate_nonce: N, ak_nonce: N }`, per [8](#0-7) , after R has already paid the outer transaction's SEND-side gas costs, matching the test coverage of this exact code path at [9](#0-8) .

pub(crate) fn apply_delegate_action(
    state_update: &mut TrieUpdate,
    apply_state: &ApplyState,
    action_receipt: &VersionedActionReceipt,
    sender_id: &AccountId,
    signed_delegate_action: VersionedSignedDelegateActionRef<'_>,
    result: &mut ActionResult,
) -> Result<(), RuntimeError> {
    // The inner delegate signature is verified below, here on the receiver shard.
    // Meter its verification compute against this shard's `compute_limit`; the gas
    // for it was already burnt at tx conversion on the signer shard. Without the
    // fix the compute is instead mis-charged on the signer shard (which never runs
    // this verify), letting the work escape the receiver shard's budget. See
    // `signature_verification_cost`.
    if apply_state.config.wasm_config.fix_ml_dsa_cost_charging {
        let verify_compute = delegate_signature_verification_compute(
            &apply_state.config.fees,
            signed_delegate_action.delegate_action().public_key(),
        );
        result.compute_usage = safe_add_compute(result.compute_usage, verify_compute)?;
    }
    if !signed_delegate_action.verify() {
        result.result = Err(ActionErrorKind::DelegateActionInvalidSignature.into());
        return Ok(());
    }
    let delegate_action = signed_delegate_action.delegate_action();
    if apply_state.block_height > delegate_action.max_block_height() {
        result.result = Err(ActionErrorKind::DelegateActionExpired.into());
        return Ok(());
    }
    if delegate_action.sender_id().as_str() != sender_id.as_str() {
        result.result = Err(ActionErrorKind::DelegateActionSenderDoesNotMatchTxReceiver {
            sender_id: delegate_action.sender_id().clone(),
            receiver_id: sender_id.clone(),
        }
        .into());
        return Ok(());
    }

    validate_delegate_action_key(state_update, apply_state, delegate_action, result)?;

    // A plain nonce advances the single access_key.nonce and forbids gas keys;
    // a gas key nonce advances one of the gas key's nonces selected by
    // nonce_index.
    let delegate_nonce = delegate_action.nonce();
    let (current_nonce, nonce_update) = match delegate_nonce {
        TransactionNonce::Nonce { .. } => {
            if access_key.gas_key_info().is_some() {
                result.result = Err(ActionErrorKind::DelegateActionAccessKeyError(
                    InvalidAccessKeyError::DelegateActionRequiresNonGasKey,
                )
                .into());
                return Ok(());
            }
            (access_key.nonce, DelegateNonceUpdate::AccessKey)
        }
        TransactionNonce::GasKeyNonce { nonce_index, .. } => {
            let Some(gas_key_info) = access_key.gas_key_info() else {
                result.result = Err(ActionErrorKind::DelegateActionAccessKeyError(
                    InvalidAccessKeyError::DelegateActionRequiresGasKey,
                )
                .into());
                return Ok(());
            };
            if nonce_index >= gas_key_info.num_nonces {
                result.result = Err(ActionErrorKind::DelegateActionInvalidNonceIndex {
                    nonce_index,
                    num_nonces: gas_key_info.num_nonces,
                }
                .into());
                return Ok(());
            }
            // The index is range-checked above and gas keys initialize every
            // nonce row at creation, so a missing row is inconsistent state.
            let current_nonce =
                get_gas_key_nonce(state_update, sender_id, public_key, nonce_index)?.ok_or_else(
                    || {
                        StorageError::StorageInconsistentState(format!(
                            "gas key nonce row missing for {} {} at in-range index {nonce_index} (num_nonces {})",
                            sender_id, public_key, gas_key_info.num_nonces,
                        ))
                    },
                )?;
            (current_nonce, DelegateNonceUpdate::GasKey { nonce_index })
        }
    };

    if delegate_nonce.nonce() <= current_nonce {
        result.result = Err(ActionErrorKind::DelegateActionInvalidNonce {
            delegate_nonce: delegate_nonce.nonce(),
            ak_nonce: current_nonce,
        }
        .into());
        return Ok(());
    }
