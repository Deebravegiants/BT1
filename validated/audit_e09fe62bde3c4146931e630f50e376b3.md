### Title
Unauthenticated gateway user can overwrite another in-flight request's callback in the legacy WebAPI trigger handler, causing cross-user response delivery - (File: `core/services/gateway/handlers/capabilities/handler.go`)

### Summary
`handler.HandleLegacyUserMessage` stores every incoming user request in a shared map keyed solely by the caller-supplied `msg.Body.MessageID`, with no check that the ID is unique or "owned" by the current caller, before fanning the request out to all DON nodes. This mirrors the root cause of the reported `CollateralManager.commitCollateral` bug: a caller-controlled identifier is used to write into a shared, unauthenticated collection without any ownership/uniqueness validation, and a later, unrelated process (the DON node's asynchronous response) consumes whatever is currently stored at that key.

### Finding Description
`HandleLegacyUserMessage` unconditionally writes to the handler's shared `savedCallbacks` map using the attacker-controlled `msg.Body.MessageID` as the key, without checking whether an entry already exists for that ID: [1](#0-0) 

There is no ownership or uniqueness enforcement analogous to `_checkBalance`/access control in the reported bug — any caller reaching this handler (this is the "legacy" JSON-RPC path that predates the newer per-request-ID conflict check) can supply an arbitrary `MessageID`. If that ID happens to collide with another caller's still in-flight request, the second write silently overwrites the first caller's `savedCallback` entry.

When the DON node eventually responds, the response's `MessageID` (the *original* caller's ID) is used to look up and deliver the callback: [2](#0-1) 

Because the map entry was overwritten, the original caller's DON response is now delivered to the attacker's `callback` object instead of the legitimate caller — a direct cross-user response confusion, and the original caller receives no response at all (functionally denied) unless it happens to retry.

By contrast, the newer v2 handler explicitly guards against this exact class of bug by checking for an existing entry before storing a new callback and rejecting the request with a conflict error: [3](#0-2) 

This confirms the legacy handler's behavior is a real gap rather than intended design — the same protection exists elsewhere in the codebase but is missing here.

### Impact Explanation
An attacker who can reach the legacy WebAPI trigger gateway path can:
- Deny another user's response delivery by causing their `savedCallback` entry to be silently replaced.
- Receive another user's DON response payload (potentially containing another workflow's sensitive trigger result) by colliding `MessageID`s, achieving cross-user response confusion — one of the explicitly accepted vulnerability classes.

This does not require any special privilege beyond being able to send a message through the gateway's legacy user-message path, matching the "unprivileged actor" requirement, and is a genuine authorization/ownership gap in shared per-ID state (directly analogous to the missing ownership check in `commitCollateral`).

### Likelihood Explanation
Likelihood is moderate: it requires the attacker to guess or intentionally choose a `MessageID` matching a legitimate in-flight request from another user while that request is still awaiting a DON response. Since `MessageID` is fully attacker-controlled and there is no server-side uniqueness/randomness enforcement, a malicious client could deliberately probe or flood with predictable/sequential/observed IDs (e.g., IDs may be predictable if clients use simple counters, or an attacker could simply race many requests with the same ID) to increase the collision window, similar to how the audited `commitCollateral` finding also relies on the attacker choosing values (token address/amount) that satisfy weak validation.

### Recommendation
In `HandleLegacyUserMessage`, before writing to `h.savedCallbacks`, check for an existing entry keyed by `msg.Body.MessageID` (mirroring the conflict check already implemented in `httpTriggerHandler.setupCallback`) and reject the request (or use a server-generated/composite key incorporating a caller-bound nonce or connection identity) instead of trusting the caller-supplied ID as the sole map key.

### Proof of Concept
1. Client A sends a legacy WebAPI trigger message with `MessageID = "X"`, which is stored in `h.savedCallbacks["X"]` and forwarded to all DON nodes.
2. Before any DON node responds, Client B (attacker) sends its own legacy WebAPI trigger message also using `MessageID = "X"`. This overwrites `h.savedCallbacks["X"]` with B's callback (no conflict check exists in `HandleLegacyUserMessage`, unlike the v2 handler's `setupCallback`).
3. A DON node responds to the original request with `MessageID = "X"`. `handleWebAPITriggerMessage` looks up `h.savedCallbacks["X"]`, finds B's callback, deletes the entry, and delivers Client A's response to Client B.
4. Client A never receives a response (denied), and Client B receives Client A's response data (cross-user confusion).

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageID]
	delete(h.savedCallbacks, msg.Body.MessageID)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JSONRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil

func (h *httpTriggerHandler) setupCallback(ctx context.Context, requestID string, callback handlers.Callback, requestStartTime time.Time, workflowID string) (<-chan struct{}, error) {
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()

	if _, found := h.callbacks[requestID]; found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrConflict, fmt.Sprintf("requestID: %s has already been used. Ensure the requestID is unique for each request.", requestID), callback)
		return nil, fmt.Errorf("in-flight request ID: %s", requestID)
	}
