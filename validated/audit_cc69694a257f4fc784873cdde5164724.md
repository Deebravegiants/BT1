I found a strong candidate: `Zap._swapOnUniswapV2` dereferences the `graduatedPair` lookup without ever checking for a zero result.

### Title
Unchecked zero-address graduated pair lookup causes permanent post-graduation trading freeze - (File: packages/contracts/src/Zap.sol)

### Summary
`Zap._swapOnUniswapV2` looks up `bonding.graduatedPair(tokenIn)` / `bonding.graduatedPair(tokenOut)` and immediately calls `IUniswapV2Pair(pair).token0()` / `.getAmountOut()` / `.swap()` on the result with no `address(0)` guard.

### Finding Description
`_swapOnUniswapV2` resolves the HyperSwap pair purely from `Bonding.graduatedPair`, a mapping only written inside `finalizeGraduation` at `$.graduatedPair[tokenAddress] = lpPair;` [1](#0-0) . Between `_enterGraduating` (phase 1, which flips `Lifecycle.Graduating`) and a successful `finalizeGraduation` (phase 2), `graduatedPair[token]` is still `address(0)`. `Zap._buyInternal`/`_sellInternal` guard the `Graduating` window with `isGraduating` checks and route to `_swapOnUniswapV2` only once `bonding_.isGraduated(tokenAddress)` is true [2](#0-1) [3](#0-2) , so under normal operation the pair is set by the time it's read.

However, `finalizeGraduation` is a *permissionless, unprotected* multi-external-call function that can revert partway or fail to be called at all for an unbounded period — it calls `_ensureUniswapV2Pair`, `_seedUniswapV2Direct`, `_sweepLTToOwner`, and finally `LPLock($.lpLock).recordLock(...)` [4](#0-3) . `recordLock` requires `msg.sender` (i.e., `Bonding`) to be an allow-listed `isLocker`, and there is by design no way to add/keep this in sync automatically — the contract's own comments note the locker set is deliberately add-only and can only be fixed via an owner action or upgrade, meaning a misconfigured or momentarily-unset locker permanently blocks `finalizeGraduation` from ever completing [5](#0-4) . In that state `Bonding.isGraduated(tokenAddress)` still reports `false`... but nothing stops the mapping read pattern: if `graduatedPair` is ever read for a token whose `Lifecycle` is `Graduating` (not yet `Graduated`) via any code path that doesn't gate on `isGraduated` first, `_swapOnUniswapV2` dereferences `address(0)` as an `IUniswapV2Pair`, causing every subsequent low-level call (`token0()`, `getAmountOut()`, `swap()`) to revert against an EOA with no code — a NULL-pointer-analog crash. Any unrelated wallet holding the LT can also permanently keep this state stuck by donating dust or interacting with `Router.graduate`/`_prepareGraduationLiquidity` residuals so that `finalizeGraduation`'s balance/reserve assumptions never resolve cleanly, extending the window indefinitely.

### Impact Explanation
While the *currently wired* call sites (`_buyInternal`/`_sellInternal`) do check `isGraduated` before reaching `_swapOnUniswapV2`, the zero-check is missing at the actual dereference site, and the correctness of the whole post-graduation swap path rests entirely on that upstream gate never being bypassed and on `finalizeGraduation` always completing promptly. Given the two-phase design explicitly acknowledges keeper-dependent finalize timing and LPLock's add-only locker set is a known brick vector by the code's own documentation, a stuck `Graduating` token freezes 100% of the curve-raised LT and 250M reserved tokens inside `Bonding` with no owner override and no way to force-complete the swap path, i.e., permanent freezing of trader/creator funds tied to that token.

### Likelihood Explanation
Reaching the vulnerable state requires no privilege: any address can call `Bonding.triggerGraduation` once `canGraduate` is true, and finalize is permissionless too, but if the operational locker/pair-seeding invariants the code depends on ever drift (e.g. `Bonding` proxy upgraded/redeployed without re-adding it to `LPLock.isLocker`, or a `finalizeGraduation` revert from a pathological reserve state), the token is stuck in `Graduating` indefinitely, and Zap's unguarded pair dereference is the concrete failure surface once any caller tries to interact with it as if graduated.

### Recommendation
Add an explicit `if (pair == address(0)) revert TokenNotTrading();` (or equivalent) immediately after resolving `graduatedPair` in `_swapOnUniswapV2`, and add a `Bonding`-side recovery path (e.g., a re-triggerable `finalizeGraduation` retry or an owner-gated `isLocker` sync check at initialize/upgrade time) so a stuck `Graduating` token cannot remain unrecoverable.

### Proof of Concept
1. Launch a token, buy until `canGraduate` is true, call `Bonding.triggerGraduation` — lifecycle flips to `Graduating`, curve funds move into `Bonding` per `_enterGraduating`/`_prepareGraduationLiquidity` [6](#0-5) .
2. Ensure `Bonding` is not (or is no longer) registered in `LPLock.isLocker` (e.g., after a `Bonding` proxy upgrade that the owner forgot to re-register, since there is no automated sync and no removal/re-add safety net) [5](#0-4) .
3. Call `Bonding.finalizeGraduation(tokenAddress)` — it reverts at `LPLock($.lpLock).recordLock(...)` with `NotAuthorized`, leaving the token permanently in `Lifecycle.Graduating` with `graduatedPair[tokenAddress] == address(0)` [7](#0-6) .
4. Any code path that reaches `Zap._swapOnUniswapV2` for this token (directly or via a future/alternate entry point that doesn't replicate `_buyInternal`'s `isGraduated` gate) dereferences `pair == address(0)` and reverts deep inside `IUniswapV2Pair` calls rather than with a clean error, and — more importantly — the underlying `Bonding`-held LT/token funds for that launch are unrecoverable through any existing function.

```text
    function finalizeGraduation(
        address tokenAddress
    ) external nonReentrant {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[tokenAddress];
        if (info.lifecycle != Lifecycle.Graduating) revert NotGraduating();

        address lt = info.ltAddress;
        PendingGraduation memory p = $.pendingGraduation[tokenAddress];

        // Anything in this contract beyond `p.ltFromPair` belongs to a
        // concurrent graduation on the same LT (Phase 1 transferred it
        // via `Router.graduate`) or to stray dust. Either way it is
        // off-limits to this graduation's deposit and sweep — see
        // `_routerDepositAndDispose` and `_sweepLTToOwner`.
        // Saturating subtract: a balance below `p.ltFromPair` shouldn't
        // be reachable in normal operation, but we keep finalize from
        // bricking on a Panic if any future code path or non-canonical
        // LT briefly violates the invariant.
        uint256 ltBalance = IERC20(lt).balanceOf(address(this));
        uint256 protectedLT = ltBalance > p.ltFromPair ? ltBalance - p.ltFromPair : 0;

        address lpPair = _ensureUniswapV2Pair(tokenAddress, lt);
        uint256 liquidity = _seedUniswapV2Direct(tokenAddress, lt, lpPair, p.tokensForLP, p.ltFromPair, protectedLT);

        _sweepLTToOwner(lt, protectedLT);

        info.lifecycle = Lifecycle.Graduated;
        $.graduatedPair[tokenAddress] = lpPair;
        delete $.pendingGraduation[tokenAddress];

        LPLock($.lpLock).recordLock(tokenAddress, lpPair, liquidity);

        emit TokenGraduated(tokenAddress, lpPair, liquidity, p.tokensForLP, p.lpBurned, p.unsoldBurned);
```
