Audit Report

## Title
Gateway forwards legacy web-API-trigger messages to all DON nodes with no allowlist/authorization check - ([File: core/services/gateway/handlers/capabilities/handler.go])

## Summary
`handler.HandleLegacyUserMessage` validates only payload decodability, timestamp freshness, and method name before registering a callback and broadcasting the raw request to every node in the DON via `don.SendToNode`. No sender/topic allowlist or rate-limit check is performed anywhere in this path, despite an explicit `// TODO: apply allowlist and rate-limiting here` comment marking the gap.

## Finding Description
`HandleLegacyUserMessage` is reached from `gateway.ProcessRequest` for any request that includes a `DonID` (the "legacy request" branch): the request only goes through `msg.Validate()`, which checks structural fields and signature format and recovers `m.Body.Sender` from the signature, but performs no comparison of that sender against a per-DON/per-topic allowlist. [1](#0-0) [2](#0-1) 

Inside `HandleLegacyUserMessage`, after decoding the payload, checking `payload.Timestamp` for staleness, and checking `msg.Body.Method == MethodWebAPITrigger`, the handler immediately builds a request via `common.ValidatedRequestFromMessage(msg)`, stores a callback in `h.savedCallbacks`, and fans the request out to every DON member with `don.SendToNode`. [3](#0-2) 

The TODO comment directly above the method check documents the acknowledged gap. [4](#0-3) 

This is corroborated by the handler's own test suite, which contains a comment acknowledging the same unresolved gap rather than a passing regression test proving allowlist enforcement: `// TODO: Validate Senders and rate limit check, pending question in trigger about where senders and rate limits are validated`. [5](#0-4) 

By contrast, the sibling `webapiTrigger`/`processTrigger` capability-trigger code (a different, node-side component that processes the same `MethodWebAPITrigger` payload once it reaches the workflow DON node) does enforce `allowedSenders` and per-sender rate limiting. [6](#0-5)  The newer v2 HTTP capability gateway handler explicitly refuses legacy messages altogether (`return errors.New("HTTP capability gateway handler does not support legacy messages")`), confirming this legacy code path in `handler.go` remains a live, unguarded fallback for DONs still configured to use it. [7](#0-6) 

## Impact Explanation
Any client able to reach the gateway's user-facing HTTP endpoint and produce a validly-signed (but not necessarily authorized) message with `Method = "web_api_trigger"`, a fresh timestamp, and a valid `TriggerRequestPayload` can force the gateway to broadcast that request to every node in the configured DON and register a pending callback entry, without any check that the sender is a permitted/allowlisted party. This maps to the "gateway request impersonation / allowlist bypass" impact class: it lets a caller who signed the message (but is not on any topic/sender allowlist) consume DON node resources and gateway callback-table capacity (`h.savedCallbacks`, bounded only by `MaxSavedCallbacks`/pruning) on every DON node simultaneously.

## Likelihood Explanation
Likelihood is high for any deployment still routing traffic through this legacy handler: constructing a valid message requires only a signing key (which callers of a public trigger endpoint are expected to have, since `msg.Sign`/`msg.Validate` is the only credential-like check performed) and a fresh timestamp — no allowlist bypass technique is needed because no allowlist check exists on this path at all. The gap is explicitly flagged in both the implementation TODO and the test file's TODO comment, indicating it was never wired up.

## Recommendation
Implement the allowlist and rate-limiting check called out by the TODO in `HandleLegacyUserMessage`, mirroring `core/capabilities/webapi/trigger/trigger.go`'s per-sender allowlist and rate limiter, before constructing/forwarding `req` to DON members. Reject the message with an appropriate error response before touching `h.savedCallbacks` or calling `don.SendToNode` if the sender/topic is not allowlisted or exceeds rate limits.

## Proof of Concept
1. Sign a well-formed `api.Message` with `Body.Method = "web_api_trigger"`, `Body.DonID` set to a configured legacy DON, and a `TriggerRequestPayload` with a fresh `Timestamp`, using any private key (as done in the test helper `triggerRequest` in `handler_test.go`). [8](#0-7) 
2. Submit it to the gateway's `ProcessRequest` entry point (the public HTTP endpoint) for a DON that uses `capabilities.handler` (legacy path).
3. Observe that `msg.Validate()` succeeds (it only checks structure/signature format, not sender authorization), `HandleLegacyUserMessage` passes the staleness/method checks, and `don.SendToNode` is invoked for every DON member regardless of whether the signing key belongs to an allowlisted sender — as shown by the existing "happy case" test exercising exactly this flow with no sender-authorization gate. [9](#0-8)

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageID) == 0 || len(m.Body.MessageID) > MessageIDMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageID, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonID) == 0 || len(m.Body.DonID) > MessageDonIDMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonID, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

func triggerRequest(t *testing.T, key *ecdsa.PrivateKey, topics []string, methodName, timestamp, payload string) *api.Message {
