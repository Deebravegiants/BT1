### Title
`retryPayload` in HyperbridgeLzEndpoint is not gated by `whenNotPaused`, allowing message delivery while the endpoint is paused - (File: sdk/packages/lz-endpoint/contracts/HyperbridgeLzEndpoint.sol)

### Summary
`HyperbridgeLzEndpoint` mirrors the exact structural flaw described in the external report: the primary inbound entrypoint `onAccept` enforces `whenNotPaused`, but the associated retry function that re-executes a previously stored/failed inbound payload does not carry the same modifier, so pausing the contract does not actually stop delivery of messages once they have already been recorded as failed.

### Finding Description
`onAccept` decodes an incoming ISMP `PostRequest` from the LayerZero bridge and attempts to deliver it directly to the destination OApp via `ILayerZeroReceiver.lzReceive`. It is annotated `onlyHost whenNotPaused`, meaning it can only run while the endpoint is not paused. [4](#0-3) 

If the OApp's `lzReceive` call reverts, `onAccept` does not revert as a whole — instead it stores the failed payload's hash in `_inboundPayloadHashes` so it can be retried later, exactly analogous to `failedMessages` in the report's `OmnichainGovernanceExecutor`: [5](#0-4) 

`retryPayload` is the function that later replays this stored payload by calling `lzReceive` on the receiver directly. It carries no `whenNotPaused` modifier — only a payload-hash-integrity check: [3](#0-2) 

This is the identical bug class from the report: the "front door" (`onAccept`/`_blockingLzReceive`) is paused, but the "back door" replay path (`retryPayload`/`retryMessage`) that re-delivers a previously failed message is left unguarded, letting message delivery proceed even while the contract is supposedly paused.

### Impact Explanation
An unprivileged actor (any relayer submitting the ISMP `PostRequest`, or anyone calling `retryPayload`, since it is explicitly documented as "Permissionless: anyone may push a stuck payload through") can force delivery of a cross-chain LayerZero message to an arbitrary destination OApp even after the endpoint's owner has paused the contract to halt operations (e.g., during an incident response). Since `retryPayload` directly invokes `ILayerZeroReceiver(receiver).lzReceive(...)` on the destination OApp with attacker-controlled `msg.value` and the originally stored payload, this defeats the security guarantee that pausing halts all inbound message processing, potentially allowing minting, state changes, or other OApp-level actions to occur during a period the operator explicitly intended to freeze.

### Likelihood Explanation
High likelihood: no special privileges or timing constraints are required. An attacker only needs a message to first fail delivery (many ways to force a revert in a destination OApp's `lzReceive`, or simply wait for organic failures) and then call the permissionless `retryPayload` after the owner pauses the endpoint. This exactly reproduces the two-step "queue failure then retry-while-paused" pattern validated in the original report.

### Recommendation
Add the `whenNotPaused` modifier to `retryPayload` (and consider whether `clear`, `skip`, `nilify`, and `burn` should also respect the pause state, since they mutate the same inbound delivery state machine), consistent with the modifier applied to `onAccept`.

### Proof of Concept
1. Endpoint owner calls `pause()`.
2. Attacker triggers a payload that was stored via `_inboundPayloadHashes` prior to the pause (either from an organically failed delivery, or one deliberately caused by making the destination OApp revert during `lzReceive`).
3. Attacker calls `retryPayload(receiver, origin, guid, message)`.
4. Since `retryPayload` has no `whenNotPaused` check, it succeeds and calls `ILayerZeroReceiver(receiver).lzReceive(...)` on the destination OApp, delivering the message despite the endpoint being paused.

    function retryPayload(
        address receiver,
        Origin calldata origin,
        bytes32 guid,
        bytes calldata message
    ) external payable {
        bytes32 stored = _inboundPayloadHashes[receiver][origin.srcEid][origin.sender][origin.nonce];
        if (stored == bytes32(0) || stored == NIL_PAYLOAD_HASH || stored != keccak256(abi.encode(guid, message))) {
            revert InvalidPayloadHash();
        }

        // Clear first; if the retry reverts, this deletion rolls back with the rest of the tx and
        // the payload remains recoverable.
        delete _inboundPayloadHashes[receiver][origin.srcEid][origin.sender][origin.nonce];

        ILayerZeroReceiver(receiver).lzReceive{value: msg.value}(origin, guid, message, msg.sender, "");
        emit InboundPayloadResolved(receiver, origin.srcEid, origin.sender, origin.nonce);
    }
