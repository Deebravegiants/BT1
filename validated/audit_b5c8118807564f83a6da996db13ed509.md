### Title
Unbounded-depth `RuntimeCall` decode in `pallet-hyper-fungible-token`'s `on_accept` allows stack-exhaustion DoS from a relayed cross-chain message - ([File: modules/pallets/hyper-fungible-token/src/module.rs])

### Summary
`pallet-hyper-fungible-token`'s ISMP `on_accept` handler decodes attacker-controlled calldata carried inside a relayed cross-chain token message using plain `Decode::decode`, with no recursion-depth bound. This is analogous to CVE‑2018‑20103 (HAProxy `dns.c`): both cases decode an attacker-supplied, self-referential/nested structure without limiting recursion depth, driving the decoder into deep/unbounded recursion and exhausting the call stack.

### Finding Description
`on_accept` in `modules/pallets/hyper-fungible-token/src/module.rs` processes a `PostRequest` delivered by any relayer for a registered ERC20↔asset bridge contract pair. After minting/transferring tokens, if `message.data` is non-empty it decodes it as `SubstrateCalldata`, then decodes the embedded runtime call unconditionally with: [1](#0-0) 

```rust
let runtime_call = T::RuntimeCall::decode(&mut &*substrate_data.runtime_call)
    .map_err(HftError::RuntimeCallDecodeError)?;
```

This uses the standard `parity-scale-codec` `Decode::decode`, which has **no** recursion-depth limit. `RuntimeCall` is a large enum that (in production runtimes) includes call variants boxing other `RuntimeCall`s (e.g. `pallet_sudo::Call::sudo { call: Box<RuntimeCall> }`, and other nested-call pallets such as `Utility::batch`/`as_derivative`). By nesting such calls thousands of times, an attacker can craft `substrate_data.runtime_call` bytes whose SCALE decoding recurses thousands of levels deep, exhausting the executing thread's stack.

The codebase is demonstrably aware of exactly this bug class and has already fixed it in a sibling path: `pallet-call-decompressor`'s `decode_and_execute` and `validate_unsigned` both switched from plain `decode` to `decode_all_with_depth_limit(MAX_EXTRINSIC_DECODE_DEPTH_LIMIT, ...)`, with an explicit regression test (`decompress_stack_exhaustion_poc`) proving that a 1000-deep `Sudo(Sudo(...))` payload is safely rejected: [2](#0-1) 

```rust
let runtime_call = <T as frame_system::Config>::RuntimeCall::decode_all_with_depth_limit(
    MAX_EXTRINSIC_DECODE_DEPTH_LIMIT,
    &mut &call_bytes[..],
)
.map_err(|_| Error::<T>::ErrorDecodingCall)?;
``` [3](#0-2) 

The `hyper-fungible-token` module never received this hardening: its `T::RuntimeCall::decode(...)` call at line 189 remains unbounded, even though its input (`message.data`) is fully attacker-controlled — it arrives from the ISMP `PostRequest.body`, ABI-decoded into `Message` and passed straight through, with the only gating being knowledge of a registered `(source, from)` contract pair, not a trust relationship on payload contents: [4](#0-3) [5](#0-4) 

### Impact Explanation
This handler runs inside `pallet-ismp`'s message-dispatch execution (`IsmpModule::on_accept`), which is invoked whenever a relayer submits a proof-backed `PostRequest` targeting the HFT module — i.e. reachable from a single relayed cross-chain message with no special privilege beyond running a relayer. A crafted deeply nested `RuntimeCall` in `data` can crash/exhaust the stack of the executing validator/collator node during block execution or transaction-pool validation, a denial-of-service against message delivery for the whole chain (comparable in class/severity to the referenced CVE — "resulting in stack exhaustion").

### Likelihood Explanation
Likelihood is High: the attacker only needs (1) a registered `ContractToAsset` mapping for some `(source, from)` pair — which is a normal, already-live bridging configuration, not privileged access — and (2) the ability to submit an ISMP `PostRequest` with an accompanying valid consensus proof, which is exactly the job of any unprivileged relayer. No signature or governance approval over the `data` payload is required; only the mint/transfer path is separately validated, not the optional calldata contents before decode.

### Recommendation
Replace the unbounded `T::RuntimeCall::decode(...)` call in `on_accept` with `T::RuntimeCall::decode_all_with_depth_limit(MAX_DEPTH, ...)`, mirroring the fix already applied in `pallet-call-decompressor`, and add a regression test analogous to `decompress_stack_exhaustion_poc` that submits a deeply nested boxed-call payload through `on_accept` and asserts it errors out (`RuntimeCallDecodeError`) rather than overflowing the stack.

### Proof of Concept
1. Register `ContractToAsset` for a `(source, from)` pair as in normal deployment.
2. Build a `RuntimeCall` value nested ~1000 levels deep, e.g. `Sudo(sudo{call: Box::new(Sudo(sudo{call: Box::new(...)}))})` (as done in `decompress_stack_exhaustion_poc`), `.encode()` it.
3. Construct an ABI-encoded `Message` whose `data` field is `SubstrateCalldata{ signature: None, runtime_call: <bytes from step 2> }.encode()`.
4. Submit this as the `body` of an ISMP `PostRequest` (with a valid consensus/state proof) targeting the HFT module for the registered contract pair.
5. When `Pallet::on_accept` reaches `T::RuntimeCall::decode(&mut &*substrate_data.runtime_call)` at line 189, the unbounded decode recursion exhausts the stack, crashing/DoS-ing the node processing the message — analogous to the DNS-pointer-recursion stack exhaustion in CVE‑2018‑20103.

#[test]
fn decompress_stack_exhaustion_poc() {
	let mut ext = new_test_ext();
	ext.execute_with(|| {
		use crate::runtime::RuntimeCall;
		use codec::Encode;

		let inner_call = RuntimeCall::System(frame_system::Call::remark { remark: Vec::new() });

		let mut nested_calls =
			RuntimeCall::Sudo(pallet_sudo::Call::sudo { call: Box::new(inner_call) });

		for _ in 1..1000 {
			nested_calls =
				RuntimeCall::Sudo(pallet_sudo::Call::sudo { call: Box::new(nested_calls) });
		}

		let encoded = nested_calls.encode();
		let mut buffer = vec![0u8; 1000000];
		let compressed = zstd_safe::compress(&mut buffer[..], encoded.as_slice(), 3).unwrap();
		let final_compressed_call = buffer[..compressed].to_vec();

		let res = pallet_call_decompressor::Pallet::<Test>::decompress_call(
			RuntimeOrigin::none(),
			final_compressed_call.to_vec(),
			encoded.len() as u32,
		)
		.err()
		.unwrap();

		assert_eq!(
			res,
			DispatchError::Module(ModuleError {
				index: 10,
				error: [3, 0, 0, 0],
				message: Some("ErrorDecodingCall")
			})
		);
	});
}
