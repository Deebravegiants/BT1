### Title
Consensus relayer rewards use the current `StateMachinesCostPerBlock` rate for the entire backlog instead of the rate that was active during each rewarded block - (File: `modules/pallets/consensus-incentives/src/impls.rs`)

### Summary
`pallet-consensus-incentives::calculate_reward` computes a relayer's consensus-delivery reward as `(latest_height - baseline) * block_cost`, where `block_cost` is whatever value is *currently* stored in `StateMachinesCostPerBlock` at the time the reward is paid. It never checks what the per-block cost was *during* each of the blocks being rewarded. This is the same root-cause pattern as the Babylon report: a per-period accounting value (historical stake / historical cost) is replaced by a single "current" snapshot applied retroactively across an entire span that may straddle multiple different historical values.

### Finding Description
`calculate_reward` in [1](#0-0)  derives the block span to reward as `latest_height - baseline`, where `baseline` is the `LastRewardedHeight` watermark (or `previous_commitment_height` on first reward), and multiplies that span by the single `block_cost` value passed in from `process_message`. That `block_cost` is read fresh from `StateMachinesCostPerBlock::<T>::get(state_machine_id)` in [2](#0-1)  at the moment the message is processed — i.e., the rate that is live *now*, not the rate(s) that were live for each of the blocks in `[baseline, latest_height]`.

`StateMachinesCostPerBlock` is a plain `StorageMap` with no historical/versioned entries, updated in-place by `update_cost_per_block`: [3](#0-2) . There is no tracking of when a rate change took effect relative to the height watermark, so any reward calculated after a rate change is priced entirely at the new rate for the whole backlog, including blocks that accrued under the old rate.

Crucially, the size of the backlog (`latest_height - baseline`) is influenced by when a relayer chooses to submit consensus proofs — `process_message`/`on_executed` is only invoked when a relayer submits a `Message::Consensus` batch that is executed via `FeeHandler::on_executed` [4](#0-3) . A relayer (an unprivileged, permissionless participant) fully controls the timing of submission for a given state machine, and can therefore withhold consensus proofs to build up an unrewarded backlog, then submit right after governance raises `cost_per_block`, collecting the new, higher per-block rate for blocks that historically only warranted the old, lower rate.

### Impact Explanation
This misprices relayer rewards paid out of the treasury (`T::TreasuryAccount`) via a direct `Currency::transfer` in `process_message` [5](#0-4) . Any relayer can extract more BRIDGE from the treasury than the protocol intended for a given historical block range simply by timing their proof submission around a `cost_per_block` update, resulting in treasury fund drain disproportionate to actual consensus-relay work performed for those blocks. This is a Medium-severity fund-misallocation/drain issue reachable by any permissionless relayer submitting a consensus message — no privileged role is required to trigger the mispricing (only the pre-existing, expected governance action of updating the rate, which is a normal operational event, not an attack).

### Likelihood Explanation
Rate changes to `StateMachinesCostPerBlock` are a normal, expected governance operation (e.g., adjusting for gas-price or BEEFY-proof-cost changes). Any relayer monitoring on-chain events can trivially detect an upcoming or just-landed rate increase and delay/batch their consensus-message submission to maximize the backlog rewarded at the new rate, or conversely rush submission before a decrease. Since relayers already control submission cadence as part of normal operation, exploiting this requires no special access — just ordinary transaction submission timing.

### Recommendation
Track the effective `cost_per_block` per block height (e.g., a versioned/historical map of `(state_machine_id, height) -> cost_per_block`, or checkpoint the rate at each `LastRewardedHeight` update) so `calculate_reward` integrates the reward across the piecewise-constant rate history between `baseline` and `latest_height` instead of applying the single current rate to the whole span.

### Proof of Concept
1. Governance sets `StateMachinesCostPerBlock[X] = 1` via `update_cost_per_block` [6](#0-5) .
2. A relayer withholds consensus proofs for state machine `X` for 10,000 blocks (no `on_executed` call happens, so `LastRewardedHeight[X]` stays at the old watermark).
3. Governance raises `StateMachinesCostPerBlock[X] = 100` to reflect new operating costs going forward.
4. The relayer immediately submits a consensus message covering all 10,000 backlogged blocks. `process_message` reads the *current* rate (100) and calls `calculate_reward`, which computes `reward = 10,000 * 100`, instead of the intended `10,000 * 1` (or a mixed calculation reflecting when the rate changed) [7](#0-6) .
5. The relayer receives ~100x the treasury payout that the historical blocks warranted, and `LastRewardedHeight` advances so the overpayment can never be "corrected" retroactively.

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}

impl<T: Config> FeeHandler for Pallet<T>
where
	<T as frame_system::Config>::AccountId: From<[u8; 32]>,
{
	fn on_executed(
		messages: Vec<MessageWithWeight>,
		events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});

		if let Some(relayer_account) = maybe_relayer_account {
			// When a batch contains multiple `StateMachineUpdated` events for the
			// same `state_machine_id` (sequential consensus updates for the same
			// chain), `calculate_reward` reads the same persisted
			// `(latest_commitment_height, previous_commitment_height)` pair on
			// every iteration and pays the same block-span reward N times.
			// Collapse the per-state-machine event stream to the single highest
			// `latest_height` so each state machine receives one reward per
			// batch, sized by the actual span of its commitment advance.
			let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
			for event in events {
				if let IsmpEvent::StateMachineUpdated(update) = event {
					highest_per_state_machine
						.entry(update.state_machine_id)
						.and_modify(|h| {
							if update.latest_height > *h {
								*h = update.latest_height;
							}
						})
						.or_insert(update.latest_height);
				}
			}

			for (state_machine_id, latest_height) in highest_per_state_machine {
				let state_machine_height =
					StateMachineHeight { id: state_machine_id.clone(), height: latest_height };

				let _ = Self::process_message(
					state_machine_height,
					state_machine_id,
					relayer_account.clone().into(),
				);
			}
		}

	impl<T: Config> Pallet<T> {
		/// Update cost per block for a state machine
		#[pallet::call_index(0)]
		#[pallet::weight(T::WeightInfo::update_cost_per_block())]
		pub fn update_cost_per_block(
			origin: OriginFor<T>,
			state_machine_id: StateMachineId,
			cost_per_block: <T as pallet_ismp::Config>::Balance,
		) -> DispatchResult {

			StateMachinesCostPerBlock::<T>::mutate(state_machine_id.clone(), |maybe_cost| {

				state_machine_id,
				cost_per_block,
			});
