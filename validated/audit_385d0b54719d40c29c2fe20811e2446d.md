### Title
`flash_position` mints the same leveraged debt as `multiply` but hardcodes `charge_fee = false`, letting any user open fee-free leveraged positions and bypass the strategy origination fee - (File: contracts/controller/src/strategies/flash_position.rs)

### Summary
The controller exposes two entrypoints that achieve the same economic result — minting pool debt against freshly supplied collateral. `multiply` charges the market's `flashloan_fee` on the borrowed amount, while `flash_position` passes `charge_fee = false` to the same pool strategy op and emits `fee: 0`. An unprivileged user with their own receiver contract can replicate any `multiply` open through `flash_position` and never pay the origination fee, permanently diverting protocol revenue.

### Finding Description
`pool::ops::strategy::accounting` computes the strategy fee only when the controller passes `charge_fee = true`, applying `flashloan_fee` bps on `action.amount` and booking it via `interest::add_protocol_revenue`. The `charge_fee` flag is chosen by the controller strategy wrapper, not by the pool. `multiply` calls `borrow_into_controller(..., debt, debt_to_flash_loan, true, PositionAction::Multiply, ...)`, so it charges the fee. `flash_position` calls `borrow_into_controller(..., debt, amount, false, PositionAction::FlashPos, ...)` and publishes `FlashPositionEvent { fee: 0 }`. Both flows end in `strategy_finalize`, which runs the identical risk checks, and `require_flash_position_still_open` enforces positive debt plus non-empty supply — exactly the shape `multiply` produces after `process_deposit`. The only functional difference is who performs the debt→collateral swap: `multiply` does it inside via the router, while `flash_position` delegates to the caller's `execute_flash_position` receiver and measures collateral receipts via `collect_collateral_deposits` balance deltas. A user-supplied receiver that performs the same swap on Aquarius/Soroswap and returns the collateral tokens reproduces the multiply outcome with zero fee.

### Impact Explanation
Every leveraged open, extend, or re-lever can be routed through `flash_position` instead of `multiply`, so the `flashloan_fee` origination revenue on strategy debt is fully avoidable at the attacker's option. On markets with a nonzero `flashloan_fee` (up to `MAX_FLASHLOAN_FEE_BPS`), all such fee revenue is lost — a direct theft of yield that would otherwise accrue to protocol revenue shares in `interest::add_protocol_revenue`. No collateral shortcut exists: the evader must still post sufficient collateral and pass `strategy_finalize` risk checks, so the loss is confined to revenue, matching a Medium severity.

### Likelihood Explanation
Reachable by any unprivileged address: `flash_position` only requires `require_authorized_caller`, `amount > 0`, a `Multiply`/`Long`/`Short` mode, a wasm receiver distinct from controller and pool, and `is_flashloanable` on the debt market — the same flag `multiply` relies on for its fee-bearing borrow. The attacker deploys a trivial receiver implementing `execute_flash_position` that swaps the forwarded debt tokens and returns collateral to the controller; the measured-receipt deposit logic (`collect_collateral_deposits` requiring `delta >= min_amount`) is satisfied exactly as it would be for a genuine user. The bypass costs nothing extra versus `multiply` and can be repeated on every leveraged operation.

### Recommendation
Charge the strategy fee symmetrically: pass `charge_fee = true` in `flash_position`'s `borrow_into_controller` call (or compute the fee inside the pool unconditionally for debt-minting strategy ops), and include the withheld fee in the `FlashPositionEvent` and in the `execute_flash_position` callback's fee argument instead of the hardcoded `0i128`/`fee: 0`. Alternatively, if a fee-free flash path is intended, gate `flash_position` to operations that cannot substitute for `multiply` (e.g., require the receiver to be the configured router) so the fee-bearing path cannot be routed around.

### Proof of Concept
1. Admin configures market XLM with `flashloan_fee = F > 0` and `is_flashloanable = true`; USDC market listed for collateral.
2. Attacker deploys a wasm receiver `R` implementing `execute_flash_position(initiator, account_id, asset, amount, fee, amount_received, controller, data)`: it swaps the received XLM for USDC on Soroswap and transfers the USDC to the controller.
3. Attacker calls `controller.flash_position(account_id: 0, spoke_id, mode: Multiply, debt: XLM key, amount: A, receiver: R, data, collaterals: [(USDC key, min_out)], refund_assets: [])`.
4. Controller mints `A` XLM debt via `pool.create_strategy(..., charge_fee=false)` — pool books zero fee, forwards `A` (not `A - fee`) to `R`; `R` returns `>= min_out` USDC, which is deposited; `strategy_finalize` passes since collateral covers debt.
5. Compare to the equivalent `multiply(..., debt_to_flash_loan: A, ...)`: pool would withhold `fee = A * F / BPS` as revenue and forward only `A - fee`. The attacker obtained the identical leveraged account while paying zero fee; `snapshot_revenue("XLM")` shows no increase.
