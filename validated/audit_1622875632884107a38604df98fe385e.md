Audit Report

## Title
CORS wildcard-origin allowlist bypass via unanchored suffix match - ([File: core/services/gateway/network/httpserver.go])

## Summary
`isAllowedOrigin` in `core/services/gateway/network/httpserver.go` handles wildcard CORS allowlist entries (`*.domain.com`) by stripping the `*.` prefix and checking `strings.HasSuffix(originHost, allowedHost)` without any domain-boundary anchor. As a result, an attacker-controlled origin such as `evilethereum.org` is treated as allowed against a wildcard rule of `*.ethereum.org`, even though it is not a subdomain of `ethereum.org`.

## Finding Description
The relevant code is: [1](#0-0)  This performs a raw substring suffix comparison with no requirement that the matched suffix be preceded by a `.` separator or that `originHost` equal the allowed domain. Consequently `strings.HasSuffix("evilethereum.org", "ethereum.org")` returns `true`, incorrectly matching an unrelated registrable domain as if it were a genuine subdomain.

This function is called directly from the request-handling entry point of the gateway's internet-facing HTTP server: [2](#0-1)  This handler is registered for the configured request path and served to any client that can reach the gateway's HTTP port, with no authentication required before the CORS check runs (the JWT/Authorization header is extracted afterward and is optional): [3](#0-2)  and [4](#0-3) 

The existing exact-match check (`originHost == allowedHost`) does not prevent the flawed wildcard branch from being reached, since it only short-circuits on exact matches. The existing test suite covers a different negative case (`ethereum.remix.org`, which legitimately does not end with `ethereum.org`) but does not test the "prefix concatenation" bypass case (`evilethereum.org`, which does end with the raw substring `ethereum.org`).

## Impact Explanation
If an operator configures a wildcard CORS entry (e.g., `https://*.ethereum.org`), intending to trust only genuine subdomains, the missing boundary check allows any domain that happens to end with that string (e.g., `evilethereum.org`) to be reflected into `Access-Control-Allow-Origin`. This lets an unrelated, attacker-controlled website read cross-origin responses from the gateway's user-facing API, breaking the intended origin isolation for JSON-RPC-style gateway requests. This maps to the in-scope "allowlist bypass" / "cross-user response corruption" impact category for the gateway.

## Likelihood Explanation
The bug is triggerable by any unprivileged client that can send an HTTP request with a crafted `Origin` header to the gateway, requiring no special credentials, roles, or host access — only that the operator has configured a wildcard `CORSAllowedOrigins` entry (a supported, documented configuration option) and that the attacker controls/registers a domain with the matching suffix. This is a realistic, low-effort, repeatable exploitation path.

## Recommendation
Anchor the wildcard suffix match to a real label boundary so that `originHost` must equal the allowed domain or end with `.` + the allowed domain, e.g.:
```go
if strings.HasPrefix(allowedHost, "*.") {
    suffix := allowedHost[1:] // ".ethereum.org"
    if originHost == suffix[1:] || strings.HasSuffix(originHost, suffix) {
        return true
    }
}
```
Add a regression test asserting `https://evilethereum.org` is rejected against an allowlist entry of `https://*.ethereum.org`.

## Proof of Concept
1. Configure the gateway HTTP server with `CORSEnabled = true` and `CORSAllowedOrigins = ["https://*.ethereum.org"]`.
2. Send an HTTP request to the gateway's configured path with header `Origin: https://evilethereum.org`.
3. Observe the response includes `Access-Control-Allow-Origin: https://evilethereum.org`, since `isAllowedOrigin` returns `true` via `strings.HasSuffix("evilethereum.org", "ethereum.org")`.
4. This can be codified as a Go unit test analogous to `TestHTTPServer_HandleRequest_CORSEnabled_FromNotAllowedOriginWildcards` in `core/services/gateway/network/httpserver_test.go`, but asserting the opposite (rejection) for origin `https://evilethereum.org` — the test would currently fail, confirming the bypass.
