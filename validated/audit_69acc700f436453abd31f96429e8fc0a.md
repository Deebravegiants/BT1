### Title
Route payloads can hide arbitrary sub-invocations under the caller's signed auth tree, draining the caller's wallet beyond the routed amount - (File: contracts/controller/src/strategies/swap.rs)

### Summary
The controller's strategy entrypoints (`multiply`, `swap_debt`, `swap_collateral`, `repay_debt_with_collateral`) accept an opaque, user-supplied route `Bytes` payload and invoke the configured router while the caller's authorization entry is on the stack. The controller only constrains its *own* single input-transfer grant; it does not and cannot constrain what the route's venues do with the *caller's* `require_auth` tree. A route that names attacker-deployed pool code causes that code to run as a descendant of the caller's root authorization, so any `token.transfer(caller, attacker, amount)` it issues is recorded by simulation as a child of the caller's entry and executes once the caller signs the returned tree. This mirrors the report's shape: an unauthenticated remote attacker supplies a malicious payload that a victim is induced to load/sign (human interaction), yielding unauthorized access to assets far beyond what the operation nominally moves.

### Finding Description
- `swap_tokens` snapshots balances, authorizes exactly one `token_in.transfer(controller, router, amount_in)` for the *controller's* funds, then calls `router.execute_strategy(&controller, &amount_in, swap)` inside `with_flash_guard`, with `swap` being raw caller-controlled bytes whose internal route it never parses [1](#0-0) .
- The post-conditions check only the controller's input spend and output receipt (`RouterOverspend`, `NoSwapOutput`) and refund the controller-held leftover to the caller — nothing bounds transfers out of the caller's own wallet [2](#0-1) .
- The threat model itself documents that the router keeps no allowlist of pools/tokens, so "a route can put third-party code on the call stack below the caller's authorization," and the resulting caller-side `transfer` "executes if the caller signs that tree," with the loss bounded by "the caller's wallet, not the routed amount" [3](#0-2) .
- The harness test proves both halves: a rogue pool calling `token.transfer(victim, attacker, WALLET_BALANCE)` is recorded as a sub-invocation of the caller's `swap_collateral` auth entry during simulation, and in enforcing mode the same call succeeds — and empties an unrelated, never-listed wallet token — when the victim signs the poisoned tree [4](#0-3) [5](#0-4) .

### Impact Explanation
Theft of user funds. Unlike ordinary route-quality loss (bounded by the routed amount and payload minimum), the malicious hop transfers arbitrary amounts of arbitrary tokens the victim holds — including assets the protocol never lists — directly to the attacker. The test demonstrates draining the full `WALLET_BALANCE` (77,770 units) of an unrelated token while the victim signed for a 5,000 USDC `swap_collateral` [6](#0-5) [7](#0-6) . The same exposure applies to every strategy entrypoint that forwards a route and to direct `execute_strategy` callers [8](#0-7) .

### Likelihood Explanation
Requires victim interaction — the victim must submit a transaction built on an attacker-supplied route payload and sign the resulting authorization tree — matching the report's `UI:R` / unauthenticated-remote profile. The vector is realistic because route bytes are opaque XDR produced by an external quote service; a compromised or malicious route source (or phishing-style payload substitution) can embed the attacker's pool in any hop. No protocol privilege, leaked key, or oracle manipulation is needed; the attacker only deploys a contract and gets its address into a route. Mitigating factor: an honest client that decodes the simulated auth tree and rejects unexpected child invocations blocks the theft — but the protocol places that burden entirely on integrators [9](#0-8) . Medium.

### Recommendation
- Enforce a venue/pool allowlist for route hops at the router level (or pass the controller a decoded route manifest and verify each hop target), so arbitrary third-party code cannot execute below the caller's auth.
- Alternatively, have the router execute hops from its own reentrant-safe sub-context that cannot reach the caller's `require_auth` — e.g., require venues to pull funds only from the router, never `transfer` from `sender`.
- Client-side: document and enforce decoding the simulated `SorobanAuthorizationEntry` tree; reject any tree containing child invocations other than the expected single controller-side input transfer [9](#0-8) .

### Proof of Concept
Provided in-repo at `tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs`:
1. Victim Alice supplies 10,000 USDC (debt-free) and holds 77,770 units of an unlisted `wallet_token` [10](#0-9) .
2. Attacker deploys `RogueHopPool` whose `swap()` calls `token.transfer(victim, attacker, WALLET_BALANCE)` [11](#0-10) .
3. A route naming that pool is built and passed to `controller.swap_collateral(alice, account_id, USDC, 5000e7, ETH, route)` [12](#0-11) .
4. Simulation records the theft transfer as a child of Alice's `swap_collateral` auth entry; with a root-only signed tree the host rejects it, but with the simulated (poisoned) tree signed, the call succeeds: Alice's wallet token goes to zero, the attacker receives the full balance, and Alice still gets a "fair" swap output — so nothing in the controller's measured-settlement checks fires [13](#0-12) .

#[test]
fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
}

#[test]
fn enforced_auth_moves_the_wallet_token_only_when_the_signed_tree_lists_the_rogue_transfer() {
    let s = Scene::new();

    // Control: a pool that touches nothing passes with the honest root-only tree.
    let benign = s.route_through_pool_stealing(0);
    s.try_swap_with_signed_tree(&benign, &[])
        .expect("the honest tree authorizes an honest route");
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);

    // Rogue pool, honest tree: the host refuses the transfer and the whole call rolls back.
    s.t.env.mock_all_auths_allowing_non_root_auth();
    let rogue = s.route_through_pool_stealing(WALLET_BALANCE);
    let usdc_before = s.t.supply_balance_raw(ALICE, "USDC");
    let refused = s
        .try_swap_with_signed_tree(&rogue, &[])
        .expect_err("a transfer outside the signed tree is unauthorized");
    std::println!("rogue transfer under the honest tree = {refused:?}");
    assert!(
        refused.is_type(ScErrorType::Auth) || refused.is_type(ScErrorType::Context),
        "expected a host auth failure, got {refused:?}"
    );
    assert!(s
        .diagnostics()
        .contains("Unauthorized function call for address"));
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);
    assert_eq!(s.wallet(&s.attacker), 0);
    assert_eq!(s.t.supply_balance_raw(ALICE, "USDC"), usdc_before);

    // Same route, with the tree that simulation returned.
    let stolen_transfer = MockAuthInvoke {
        contract: &s.wallet_token,
        fn_name: "transfer",
        args: (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        sub_invokes: &[],
    };
    s.try_swap_with_signed_tree(&rogue, core::slice::from_ref(&stolen_transfer))
        .expect("the poisoned tree authorizes the rogue transfer");
    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
