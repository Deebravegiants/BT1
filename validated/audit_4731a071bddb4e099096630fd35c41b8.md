### Title
JWT Replay-Protection Check-Then-Act Race Allows Token Reuse - ([File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go])

### Summary
The `Authorize` method of `WorkflowMetadataHandler` checks whether a JWT `jti` has already been used (`isReplay`) and, only after validating signer/authorization, records that `jti` as used (`recordUsage`). These two operations acquire the cache's mutex independently rather than atomically, so two concurrent HTTP trigger requests carrying the same signed JWT can both pass the `isReplay` check before either calls `recordUsage`, allowing the same signed authorization token to be used to trigger a workflow execution more than once. This is the same class of bug as the Fei Rari exploit: the "effect" (marking state as consumed) is decoupled from the "check" (validating the state hasn't been consumed yet), leaving a window where a second reentrant/concurrent caller sees stale state and bypasses the guard.

### Finding Description
`Authorize` is invoked from the internet-facing HTTP Trigger Handler on every unprivileged, external client request that hits the gateway's HTTP trigger path (`httpTriggerHandler.authorizeRequest` → `WorkflowMetadataHandler.Authorize`): [1](#0-0) 

Inside `Authorize`, the check and the corresponding write to the replay cache are two separate, non-atomic critical sections: [2](#0-1) 

`isReplay` takes an `RLock`, reads, and releases: [3](#0-2) 

`recordUsage` is only called afterward, at the very end of `Authorize`, and takes its own separate `Lock`: [4](#0-3) 

Between these two lock acquisitions, `Authorize` performs additional work (JWT signature verification already happened before the check, but signer/authorized-key lookup happens between the check and the record). This gap is a classic TOCTOU (check-then-act) window: if two requests bearing the identical JWT (same `jti`) arrive concurrently, both can execute `h.jwtCache.isReplay(claims.ID)` and observe `exists == false` before either has called `recordUsage`, so both are treated as valid, non-replayed authorizations. Each successful `Authorize` call leads to a full workflow trigger being dispatched to the DON via `sendWithRetries`.

This directly parallels the Fei Rari root cause: Compound's `borrow()` transferred funds (effect) before recording the debt (state update), and a reentrant call exploited the gap between the transfer and the record. Here, the "effect" of authorization (permitting the request to proceed to node dispatch) happens before the corresponding replay-protection state (`recordUsage`) is committed, and concurrent requests are the "reentrant" vector instead of a Solidity fallback call.

### Impact Explanation
An external, unprivileged caller who has legitimately obtained one valid signed JWT for a workflow trigger can replay it concurrently to trigger the same workflow execution multiple times before the replay cache is updated. This defeats the intended one-time-use guarantee of `jti`-based replay protection at the gateway's internet-facing trigger endpoint, potentially causing duplicate/unauthorized workflow executions (a form of authorization bypass / unauthorized job run), and can be used to amplify rate-limit or resource consumption before `checkRateLimit` is applied downstream, since `authorizeRequest` runs before `checkRateLimit` in `HandleUserTriggerRequest`. [5](#0-4) 

### Likelihood Explanation
Likelihood is moderate: exploiting the race requires sending multiple copies of the same signed JWT/request in near-simultaneous fashion (easy for a normal HTTP client — no special network position, node compromise, or privileged access needed) and winning a narrow but real timing window between `isReplay` and `recordUsage`. It is directly reachable by any unprivileged client capable of calling the HTTP trigger endpoint with a previously obtained valid JWT.

### Recommendation
Make the check-and-record operation atomic under a single critical section (e.g., a `checkAndRecord(jti string) bool` method that holds the write lock for the entire "read cache, if absent insert, return whether it was already present" sequence), so no two concurrent callers can both observe an unused `jti`. This mirrors the checks-effects-interaction fix pattern: the "effect" (marking the token consumed) must complete atomically with the "check" (verifying it wasn't consumed) before any authorization decision is returned to the caller.

### Proof of Concept
1. Obtain one valid signed JWT (`jti = X`) for triggering workflow `W`, satisfying signer/authorized-key requirements.
2. Fire two (or more) concurrent `workflows.execute` requests to the gateway's HTTP trigger endpoint using the exact same JWT.
3. Both goroutines executing `WorkflowMetadataHandler.Authorize` call `h.jwtCache.isReplay(claims.ID)` before either has reached `h.jwtCache.recordUsage(claims.ID)` at the end of the function; both observe `isReplay == false`.
4. Both requests pass authorization and proceed through `checkRateLimit` and `sendWithRetries`, resulting in two workflow executions triggered from a single-use JWT — demonstrating the replay-protection bypass.

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}

func (cache *jwtReplayCache) isReplay(jti string) bool {
	cache.mu.RLock()
	defer cache.mu.RUnlock()

	_, exists := cache.cache[jti]
	return exists
}

func (cache *jwtReplayCache) recordUsage(jti string) {
	cache.mu.Lock()
	defer cache.mu.Unlock()

	cache.cache[jti] = time.Now()
}
