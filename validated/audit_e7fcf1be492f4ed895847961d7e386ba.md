### Title
Unauthenticated `CallDispatcher.dispatch()` allows theft of any token balance the shared dispatcher singleton holds - ([File: evm/src/utils/CallDispatcher.sol])

### Summary
`CallDispatcher.dispatch()` is a public, unauthenticated entry point that executes arbitrary attacker-supplied `Call[]` with the `CallDispatcher` contract itself as `msg.sender`. `CallDispatcher` is a single shared singleton used by `IntentGatewayV2`, `HyperFungibleToken`, `WrappedHyperFungibleToken` and their upgradeable variants to run "untrusted" predispatch/postdispatch calldata attached to cross-chain orders and token messages. Any residual token or native balance left on this contract — whether from partial sweeps, unlisted reward/LP tokens returned by a DEX swap, or any other edge case not covered by the caller's post-hoc sweep logic — can be drained by any unprivileged address in an ordinary follow-up transaction, because nothing restricts who may call `dispatch()`.

### Finding Description
`CallDispatcher.dispatch()` has no caller restriction whatsoever: [1](#0-0) 

It decodes an ABI-encoded `Call[]` and, for each entry, performs `to.call{value: call.value}(call.data)` with `CallDispatcher` as the caller, only checking that `to` has code. The interface comment itself acknowledges the contract dispatches "untrusted call(s)": [2](#0-1) 

The intended safety model is that funds only ever sit on `CallDispatcher` transiently, within a single atomic transaction, between the caller transferring assets in and immediately sweeping the resulting balance back out via a second `dispatch()` call, e.g. in `IntentsBase._execute`: [3](#0-2) 

and in `IntentGatewayV2`'s predispatch flow: [4](#0-3) 

as well as the HFT apps' `onAccept`, which forwards arbitrary `message.data` straight to `CallDispatcher.dispatch()` after minting/transferring funds to the recipient: [5](#0-4) 

The sweep logic in every one of these callers is scoped only to the *known* set of tokens (`order.inputs`/`order.output.assets`, or the recipient/native balance) — it is not an exhaustive "sweep whatever is on the dispatcher" pass. If the attacker-, solver-, or order-creator-supplied predispatch/postdispatch calldata causes the dispatcher to end up holding *any* token that isn't in that enumerated list (a swap-router reward token, dust from a multi-hop route, a stuck approval-triggered transfer, or simply a call that reverts partway leaving assets un-swept in a way that doesn't propagate the revert), that balance remains on the shared singleton after the transaction completes. Because `dispatch()` has no access control and the docs themselves warn that "the dispatcher contract holds tokens temporarily during execution," any unprivileged address can, in a completely separate later transaction, call `CallDispatcher.dispatch()` directly with `Call({to: token, value: 0, data: abi.encodeWithSelector(IERC20.transfer.selector, attacker, balance)})` (or, for native ETH, `Call({to: attackerContract, value: address(dispatcher).balance, data: ""})`) and pull out that balance, since the call executes with `CallDispatcher` as `msg.sender`.

### Impact Explanation
Any token or ETH balance left on the shared `CallDispatcher` — even if only transiently by design — is permanently exposed to theft by an arbitrary unprivileged third party, not just the party whose transaction produced it. This directly matches the "concrete theft ... of funds" bar: the dispatcher is reachable from `IntentGatewayV2` (intent solver/order flow), `HyperFungibleToken`/`WrappedHyperFungibleToken` (token bridge flow), across multiple EVM deployments (including the Tron variant), so the surface for accidental residual balances is broad and the exploit itself requires nothing but a single call to a public function.

### Likelihood Explanation
Exploiting an *existing* residual balance requires only a single unprivileged transaction (no signatures, no proofs, no special role) — the barrier is solely whether any balance is ever left behind, which depends on the diversity of tokens/side effects returned by arbitrary predispatch/postdispatch DeFi calls (reward tokens, dust from swaps, partial executions) across all deployments that route through this singleton `CallDispatcher`.

### Recommendation
Restrict `CallDispatcher.dispatch()` to a known, authorized caller set (e.g. an `onlyAuthorizedCaller` allowlist of the `IntentGatewayV2` and HFT app addresses configured to use it), or make the dispatcher non-shared/ephemeral (deploy per-call via a minimal proxy that self-destructs or is single-use), so that no unprivileged address can invoke arbitrary calls against a contract that may transiently or accidentally hold value.

### Proof of Concept
1. A predispatch/postdispatch `Call[]` (supplied by an order creator, solver, or via HFT `message.data`) routes through a DEX/DeFi call that returns an incidental token not enumerated in `order.inputs`/`order.output.assets` (e.g., a reward token, or leftover dust from a multi-hop swap), or a call partially completes leaving assets unswept.
2. `CallDispatcher` now holds a balance of that token that the caller's sweep logic (scoped only to the known asset list) does not collect.
3. Any unprivileged address submits a standalone transaction calling `CallDispatcher.dispatch(abi.encode([Call({to: leftoverToken, value: 0, data: abi.encodeWithSelector(IERC20.transfer.selector, attacker, IERC20(leftoverToken).balanceOf(dispatcher))})]))`.
4. `CallDispatcher.dispatch` executes the call with itself as `msg.sender`, transferring the leftover balance to the attacker — no authorization check prevents this.

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }

        PostRequest calldata request = incoming.request;

        if (expectedSource.length == 0) revert UnsupportedChain();
        if (keccak256(request.from) != keccak256(expectedSource)) revert UnauthorizedSource();

            to: beneficiary,
