### Title
Sustained high-utilization accrual overflows the RAY value ceiling and permanently freezes a market — no bound on index growth before `scaled_to_original` panics - ([File: contracts/pool/src/interest.rs](contracts/pool/src/interest.rs))

### Summary
Analogous to the psd-tools report's "no upper-bound validation before allocation / unguarded expansion" class (CWE-190/CWE-789): `global_sync` compounds `borrow_index`/`supply_index` with no ceiling that engages before the `i128` value ceiling, so a large, highly-utilized market eventually panics inside `scaled_to_original` on every subsequent accrual. Since every pool verb accrues first, the market becomes permanently frozen — no repay, withdraw, or liquidation ever succeeds again.

### Finding Description
`global_sync` in `contracts/pool/src/interest.rs` chunks elapsed time by `MAX_COMPOUND_DELTA_MS` and calls `accrue_chunk`, which multiplies the indexes via `accrue_step` (`common/src/rates`) and writes them back with `set_borrow_index`/`set_supply_index` [1](#0-0) . The fixed-point engine (`common/src/math/fp_core.rs`, `common/src/math/fp.rs`) panics with `GenericError::MathOverflow` whenever `scaled × index` exceeds `i128::MAX` [2](#0-1) . The documented `MAX_BORROW_INDEX_RAY` cap never engages because the *value* ceiling (`scaled_to_original` on the total scaled book) overflows first — exactly the "dimension/range not validated before it drives the computation" gap from the advisory.

The test harness proves it end-to-end: a 18-decimal market with ~1e9 whole tokens of principal at ~98% utilization on the XLM rate curve panics inside `scaled_to_original` during `update_indexes` once the index grows past ~170x, and afterwards `withdraw` and `repay` both revert with `MATH_OVERFLOW` [3](#0-2) . There is no recovery path: `clean_bad_debt`/`liquidate`/`recapitalize` all accrue first, so no unprivileged or privileged verb can unfreeze the book.

### Impact Explanation
Permanent freezing of all supplier and borrower funds in the affected market, and protocol insolvency for outstanding debt that can never be repaid or liquidated. Every accounting operation on that market's book reverts forever once the cliff is crossed.

### Likelihood Explanation
Requires a very large market (whale-scale supply at high decimals) and sustained near-100% utilization for the index to compound ~170x, which the harness shows is reachable on the steep segment of a listed rate curve. An unprivileged attacker can create the precondition cheaply by supplying and borrowing the same market at high utilization (`supply` then `borrow`), but the cliff itself takes extended wall-clock accrual; it cannot be triggered instantly. Reachability is real (caps lifted in the test mirror lifted supply caps), but the horizon and capital requirements put this at Medium.

### Recommendation
Validate index growth against a hard bound *before* the value overflow: clamp `borrow_index`/`supply_index` at a cap chosen so `scaled × index` always fits `i128` for the maximum listable book size, and convert the accrual panic into a bounded terminal state (e.g., stop accrual at the cap and mark the market frozen-in-place) so repay/withdraw/liquidate remain callable against the last-good index instead of reverting. Alternatively, perform accrual arithmetic in `I256` and saturate the stored index rather than panicking.

### Proof of Concept
Unprivileged path (mirrors `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap`):

1. `controller.supply(BOB, hub, BIG18_token, 1e9 * 10^18)` — whales or an attacker with capital seeds a giant 18-decimal market; total scaled supply is ~1e36 ray-units, ~170x below `i128::MAX`.
2. `controller.borrow(ALICE, hub, BIG18_token, ~98% of supply)` against a collateral position — utilization pinned on the steep segment of the interest curve, so the borrow rate compounds hard.
3. Anyone calls `controller.update_indexes([BIG18])` periodically. Each call runs `global_sync` → `accrue_chunk` → `accrue_step`, multiplying `borrow_index`/`supply_index` upward with no effective cap [4](#0-3) .
4. Once `scaled_supply × supply_index` (or the borrow side) exceeds `i128::MAX`, `scaled_to_original` inside the accrual panics with `MathOverflow` [2](#0-1) . From then on, `withdraw`, `repay`, `borrow`, `liquidate`, `clean_bad_debt`, and `claim_revenue` on that market all revert at the accrual pre-step — permanently. Confirmed by the harness assertions that `try_withdraw_raw` and `try_repay` both fail with `MATH_OVERFLOW` after the cliff [5](#0-4) .

Uncertainty note: I verified the freeze mechanics and the harness test but did not read `common/src/rates/index.rs` `accrue_step` directly, so the exact cap-ordering claim ("value ceiling before index cap") relies on the test's documented assertion rather than a line-level read of the cap check.

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}
```

```rust
pub fn mul_div_floor(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    require_nonzero_divisor(env, d);
    if let Some(quotient) = x
        .checked_mul(y)
        .and_then(|product| div_floor_i128(product, d))
    {
        return quotient;
    }
    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    let nonneg = quotient_is_nonnegative(x, y, d);
```

```rust
/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
```
