### Title
Unchecked UTF-8 deserialization of untrusted cross-chain message body in `pallet-ismp-demo`'s `on_accept` - (File: modules/pallets/demo/src/lib.rs)

### Summary
`ismp-demo`'s `IsmpModuleCallback::on_accept` converts the raw bytes of an incoming ISMP `PostRequest` body into a `String` using `unsafe { String::from_utf8_unchecked(request.body) }` whenever the source chain is `StateMachine::Evm(_)`. `request.body` is attacker-controlled bytes carried in a relayed cross-chain message and is never validated as UTF-8 before this unsafe conversion. [1](#0-0) 

### Finding Description
`String::from_utf8_unchecked` is documented by Rust as producing undefined behavior if the input is not valid UTF-8, because it constructs a `String` — a type whose entire safety contract (used throughout the standard library and any consumer, including `Event::Request { data: String, .. }`) assumes it can only ever hold valid UTF-8. Any downstream code that treats this `String` as trusted UTF-8 (formatting, slicing at char boundaries, JSON/SCALE re-encoding, RPC serialization) inherits the corrupted invariant, which is the same fundamental bug class as the FontForge CVE: deserializing untrusted bytes into a strongly-typed structure without validating the wire format the type's safety guarantees depend on. This is directly reachable by any unprivileged relayer or message dispatcher: `on_accept` is called from the ISMP dispatch pipeline (`pallet_ismp::Pallet::execute` → `Router::dispatch` → module callback) whenever an `Evm(_)` state machine's `PostRequest` is delivered to this module id, and `request.body` is fully attacker-supplied (the sender on the EVM side controls the raw bytes dispatched to Hyperbridge). [2](#0-1) 

By contrast, every other decode path found in the codebase (`codec::Decode`, `serde::Deserialize`, `String::from_utf8`) surfaces a typed error on malformed input rather than invoking undefined behavior, and the project has explicit regression tests guarding against exactly this class of "untrusted bytes -> panic/UB at the deserialization boundary" bug (see `modules/utils/serde/src/lib.rs` comments about a production crash from unchecked fixed-length copies, and `modules/trees/ethereum/src/tests.rs` regression test for an RLP decode panic on adversarial proof nodes). [3](#0-2) [4](#0-3) 

### Impact Explanation
In a Substrate/WASM runtime, `String::from_utf8_unchecked` on invalid UTF-8 is technically instantaneous UB rather than a classic native memory-corruption RCE as in FontForge's C/C++ context; however, the invariant violation propagates a `String` guaranteed-invalid-UTF-8 value into runtime state (deposited as an event, `Event::Request { data, .. }`). Any consumer of that event or subsequent runtime logic that relies on the type's UTF-8 guarantee (string slicing, `.as_bytes()` re-interpretation assumptions, external tooling parsing chain events, potential future logic gating on the string) can misbehave unpredictably, and compiler optimizations are permitted to exploit the broken invariant in ways that produce further undefined behavior in the same or nearby code (miscompilation, corrupted control flow) — the same class of "deserialization of untrusted data" flaw cited by the external report, just realized as UB in a memory-safe language rather than classic heap corruption. This is an "unsound state"/unauthorized-behavior class finding on a directly attacker-reachable dispatch path from any Evm-side sender relaying a message into this module.

### Likelihood Explanation
High likelihood of triggering: any account on any tracked EVM chain can dispatch an arbitrary-bytes `PostRequest` addressed to this pallet's module id, and simply sending non-UTF-8 bytes (e.g. a lone continuation byte `0x80`) triggers the unchecked path with no additional preconditions, signatures, or privileges required beyond a normal ISMP message delivery.

### Recommendation
Replace `unsafe { String::from_utf8_unchecked(request.body) }` with `String::from_utf8(request.body).map_err(|_| IsmpError::Custom("Invalid utf8 in request body".into()))?`, matching the fallible-decode pattern already used elsewhere in this same function for `Payload::decode` and elsewhere in the codebase (e.g. `modules/ismp/core/src/host.rs`'s `String::from_utf8(...).unwrap_or(...)` fallback pattern). If this module is intended purely as a demo/example (not part of a production runtime), it should not be wired into any production parachain runtime's ISMP router at all; confirm whether `gargantua`/`nexus` runtimes route live `Evm(_)` traffic to this module id and, if so, treat the fix as required rather than optional.

### Proof of Concept
1. An EVM-side application (or any account capable of dispatching an ISMP `POST` request to Hyperbridge) constructs and relays a `PostRequest` with `source = StateMachine::Evm(<any tracked chain id>)`, `to` = this demo module's registered module id (`ModuleId::Pallet(PalletId(*b"ismp-ast"))`), and `body = vec![0x80]` (a lone UTF-8 continuation byte, invalid on its own).
2. Once the request is relayed and proof-verified, `pallet_ismp` dispatches it to `IsmpModuleCallback::on_accept`.
3. Because `source_chain` matches `StateMachine::Evm(_)`, execution reaches `unsafe { String::from_utf8_unchecked(request.body) }` with `request.body == vec![0x80]`, constructing a `String` that violates Rust's UTF-8 invariant — undefined behavior, reachable purely from an unprivileged cross-chain message. impl<T: Config> IsmpModule for IsmpModuleCallback<T> {
	fn on_accept(&self, request: PostRequest) -> Result<Weight, anyhow::Error> {
		let source_chain = request.source;

		match source_chain {
			StateMachine::Evm(_) => Pallet::<T>::deposit_event(Event::Request {
				source: source_chain,
				data: unsafe { String::from_utf8_unchecked(request.body) },
			}),
			StateMachine::Polkadot(_) | StateMachine::Kusama(_) => {
				let payload =
					<Payload<T::AccountId, <T as Config>::Balance> as codec::Decode>::decode(
						&mut &*request.body,
					)
					.map_err(|_| IsmpError::Custom("Failed to decode request data".to_string()))?;
				<T::NativeCurrency as Mutate<T::AccountId>>::mint_into(
					&payload.to,
					payload.amount.into(),
				)
				.map_err(|_| IsmpError::Custom("Failed to mint funds".to_string()))?;
				Pallet::<T>::deposit_event(Event::<T>::BalanceReceived {
					from: payload.from,
					to: payload.to,
					amount: payload.amount,
					source_chain,
				});
			},
			source => Err(IsmpError::Custom(format!("Unsupported source {source:?}")))?,
		}

		Ok(weight())
	}
