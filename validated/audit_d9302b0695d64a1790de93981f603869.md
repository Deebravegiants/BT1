Audit Report

## Title
Missing role-based permission check on `GET /v2/external_initiators` allows low-privileged users to enumerate External Initiator access keys - ([File: core/web/router.go])

## Summary
The `GET /v2/external_initiators` route is registered with only generic authentication (`auth.Authenticate`), lacking the `auth.RequiresEditRole`/`auth.RequiresAdminRole` wrapper applied to the sibling `POST`/`DELETE` routes on the same resource. Any authenticated user, including one with the lowest-privilege `UserRoleView` role, can call this endpoint and receive a full listing of configured external initiators' `AccessKey` and `OutgoingToken` values.

## Finding Description
In `v2Routes` (`core/web/router.go`), the External Initiators routes are:
```go
eia := ExternalInitiatorsController{app}
authv2.GET("/external_initiators", paginatedRequest(eia.Index))
authv2.POST("/external_initiators", auth.RequiresEditRole(eia.Create))
authv2.DELETE("/external_initiators/:Name", auth.RequiresEditRole(eia.Destroy))
``` [1](#0-0) 

The `GET` handler only inherits the `authv2` group's base authentication middleware (`auth.AuthenticateByToken`/`auth.AuthenticateBySession`), which verifies the caller has *some* valid session/token but performs no role check: [2](#0-1) 

`ExternalInitiatorsController.Index` returns all initiators via `presenters.NewExternalInitiatorResource`, which includes the plaintext `AccessKey` and `OutgoingToken` fields sourced directly from the ORM without redaction: [3](#0-2) 

This is inconsistent with the established pattern elsewhere in the router where mutating or sensitive actions are gated behind `RequiresEditRole`/`RequiresAdminRole` (e.g., VRF keys, jobs), and specifically inconsistent within this same resource, where `POST`/`DELETE` require edit role but `GET` (the one that discloses secrets) does not.

## Impact Explanation
`AccessKey` is a credential component used in `AuthenticateExternalInitiator` to authenticate External Initiator callback requests against the node. Exposing valid `AccessKey`/`OutgoingToken` values to a `UserRoleView` account — a role explicitly meant to be restricted from edit/admin-level operations — constitutes an authorization boundary violation and unauthorized disclosure of node integration credentials, falling within the "key/secret exfiltration" and "node API authentication/role bypass" impact categories relevant to Chainlink's bounty scope.

## Likelihood Explanation
This is straightforward to trigger for any deployment supporting multiple RBAC roles (a documented, standard feature: `UserRoleView`, `UserRoleRun`, `UserRoleEdit`, `UserRoleAdmin`). Any account provisioned with only `view` access (e.g., a read-only monitoring/dashboard credential) — a supported, unprivileged configuration — can call this endpoint with a valid session/API token and receive the full initiator listing, with no additional privilege escalation required.

## Recommendation
Wrap the route with a role check consistent with the resource's other endpoints:
```go
authv2.GET("/external_initiators", auth.RequiresEditRole(paginatedRequest(eia.Index)))
```
Additionally, consider redacting `AccessKey`/`OutgoingToken` from list responses, mirroring how `Secret`/`OutgoingSecret` are already excluded from `ExternalInitiatorResource`.

## Proof of Concept
1. Provision a user with `UserRoleView` via `POST /v2/users` (admin-only setup step, but the resulting account is unprivileged).
2. Authenticate as that view-only user (`POST /sessions` or API token).
3. Call `GET /v2/external_initiators` using the view-only session/token: the request succeeds because no role check exists on this route, and the response includes each initiator's `accessKey` and `outgoingToken` fields, as confirmed by the existing controller test asserting these fields are populated in `Index` responses (`core/web/external_initiators_controller_test.go` lines 104-109).

func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}
