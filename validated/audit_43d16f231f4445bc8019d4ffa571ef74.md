### Title
Hardcoded `BAD_DEBT_USD_THRESHOLD` permanently blocks cleanup of mid-sized bad debt - (File: contracts/controller/src/constants.rs)

### Summary
The bad-debt dust threshold is a compile-time constant fixed at `DEFAULT_MIN_BORROW_COLLATERAL_USD_WAD` (5 USD in wad) in `contracts/controller/src/constants.rs:3`, re-exported from `common/src/constants/shared.rs:43`. Like the Kyber report's constructor-fixed `feeAmountTickDistances`, this value is baked into the binary for every market, hub, and spoke — governance cannot retune it — and it gates `clean_bad_debt`, the only non-donation path for writing down defaulted debt.

### Finding Description
The pool writes down bad debt via `clean_bad_debt` only when the position's remaining debt is below `BAD_DEBT_USD_THRESHOLD`. Above the threshold the call reverts, and `liquidate` cannot help either: liquidation seizes collateral pro-rata, and a position that has already been fully seized has no collateral legs to take. The only remaining path is `recapitalize`, which requires a caller to donate real tokens without minting shares — economically a gift, so no rational unprivileged actor performs it.

Because the threshold is hardcoded rather than a per-market or per-spoke parameter (contrast with `set_spoke_liquidation_curve` in `contracts/controller/src/config/spoke.rs:52` and per-market `write_rate_model` in `contracts/pool/src/storage.rs:72`, which are adjustable), any bad debt larger than 5 USD sits permanently inside `total_debt` in `PoolStateRaw`. The borrow index keeps accruing on debt that can never be repaid, and the supply side's claim on the physical pool balance is permanently impaired.

### Impact Explanation
Protocol insolvency / permanent freezing of supplier funds. Each stuck bad-debt position leaves the market's accounting debt exceeding the real token balance forever; last-out suppliers cannot withdraw fully. Unlike the Kyber original (mere brittleness), here the fixed constant directly disables the cleanup entrypoint for a reachable state, converting a design limitation into an uncapped, permanent loss accumulator.

### Likelihood Explanation
A single unprivileged address can create the state: supply minimum collateral in a spoke market, borrow near the LTV limit, then move the Aquarius constant-product price of the collateral downward with its own trades (an allowed venue), letting the position go underwater. Liquidation seizes all remaining collateral; leftover debt above 5 USD cannot be cleaned. Repeated across positions, the unrecoverable debt grows without bound and no parameter change can ever re-enable cleanup for the existing configuration.

### Recommendation
Make the bad-debt threshold a configurable per-market or protocol parameter (stored alongside `MarketParamsRaw` or spoke config) with bounds, and emit an event on change, mirroring `set_spoke_liquidation_curve`. Alternatively, let `clean_bad_debt` write down bad debt of any size when the position has zero remaining collateral, reserving the threshold only for positions that still hold dust collateral.

### Proof of Concept
1. Governance lists a market; attacker calls `supply` (collateral C), then `borrow` amount D such that `min_borrow_collateral_usd` is satisfied.
2. Attacker executes its own sells on the Aquarius pool underlying the collateral's price leg, moving the strict price down within the dual-leg tolerance so the position's HF drops below 1.
3. Attacker (or anyone) calls `liquidate`; the plan seizes all whole-unit collateral legs. Remaining debt `D' = D + accrued - seized_value` where `D' > 5 USD` (`BAD_DEBT_USD_THRESHOLD` at `contracts/controller/src/constants.rs:3`).
4. Any caller invokes `clean_bad_debt`; it reverts because `D'` exceeds the fixed threshold. `liquidate` finds no collateral legs. Debt `D'` remains in `total_debt` permanently, and suppliers' share value is permanently diluted by `D'` plus its future accrued interest.

Caveat: I verified the constant definition and the configurability contrast, but could not fully re-verify within this session the exact revert condition inside `clean_bad_debt` and the liquidation leg-skip rule; if cleanup uses a different bound (e.g., "below threshold" vs. "below-or-equal") or recapitalize mints value another way, the severity may shift, though the hardcoded-parameter structure stands.
