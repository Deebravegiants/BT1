## Title
Missing Authentication on LOOP Plugin Debug/Metrics/pprof Endpoints Exposes Internal Diagnostics and Runtime Profiling to Any Unauthenticated Client - (File: core/web/router.go)

## Summary
`loopRoutes` is registered on the base `api` gin group in `NewRouter` [1](#0-0)  which only applies rate-limiting and session middleware [2](#0-1) , with no `auth.Authenticate(...)` wrapper, unlike `debugRoutes` [3](#0-2)  and the equivalent core `metricRoutes`/pprof handlers, which are only exposed inside the token/session-authenticated `authv2` group [4](#0-3) . This lets any client that can reach the node's operator HTTP port hit `/discovery`, `/plugins/:name/metrics`, and `/plugins/:name/debug/pprof/*` without credentials.

## Finding Description
`loopRoutes(app, api)` registers four handlers directly on the unauthenticated `api` group: [5](#0-4) 
- `discoveryHandler` enumerates all registered LOOP plugin names and internal Prometheus scrape targets [6](#0-5) 
- `pluginMetricHandler` proxies to the internal plugin's `/metrics` endpoint [7](#0-6) 
- `pluginPPROFHandler` proxies arbitrary `net/http/pprof` sub-paths (heap, goroutine, profile with attacker-controlled `seconds`, trace, etc.) to the internal plugin process [8](#0-7) 
- `pluginPPROFPOSTSymbolHandler` forwards an attacker-supplied POST body to the plugin's `/debug/pprof/symbol` [9](#0-8) 

By contrast, the functionally identical core-process pprof routes are gated behind `authv2`, which requires `auth.Authenticate(..., auth.AuthenticateByToken, auth.AuthenticateBySession)` [10](#0-9) [4](#0-3) . No equivalent check exists anywhere in `loopRoutes` or in `LoopRegistryServer`'s handlers, and no other middleware in the `api` group (rate limiter, session cookie middleware) enforces authentication — `sessions.Sessions` alone does not reject unauthenticated requests, it only makes a session available for handlers that explicitly check it (as `debugRoutes` and `authv2` do, but `loopRoutes` does not).

## Impact Explanation
An unauthenticated client reaching the node's operator HTTP port can enumerate LOOP plugin names/hosts, pull plugin Prometheus metrics, and trigger/retrieve `pprof` heap, goroutine, and CPU-profile dumps from the internal plugin process, plus submit arbitrary POST bodies to `/debug/pprof/symbol`. This is an information-disclosure path (CWE-306, missing authentication for a critical function) that could expose internal plugin runtime state, and the attacker-controlled `seconds` parameter on CPU profiling is a resource-consumption vector against the plugin process. This is a genuine parity gap with the authenticated core `pprof` routes in the same file.

## Likelihood Explanation
No credentials, tokens, or session cookies are required — only network reachability to the same HTTP port that serves the rest of the `/v2/*` API. The routes are unconditionally registered in `NewRouter` whenever the application builds its router, so this is always active for any deployment using LOOP plugins.

## Recommendation
Wrap `loopRoutes`'s router group with the same `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)` middleware applied to `authv2`/`debugRoutes`, and consider role restriction (`auth.RequiresAdminRole`) for the pprof/metrics/discovery handlers, consistent with how `metricRoutes` is protected under `authv2`.

## Proof of Concept
Against a running node with LOOP plugins configured, issue with no cookies/tokens:
```
GET /discovery
GET /plugins/<plugin-name>/metrics
GET /plugins/<plugin-name>/debug/pprof/heap
GET /plugins/<plugin-name>/debug/pprof/profile?seconds=60
POST /plugins/<plugin-name>/debug/pprof/symbol
```
All succeed and return plugin-internal data because `loopRoutes(app, api)` in `core/web/router.go` is registered on the `api` group without any `auth.Authenticate` middleware, unlike the comparable authenticated `metricRoutes` under `authv2`.

// discoveryHandler implements service discovery of prom endpoints for LOOPs in the registry
func (l *LoopRegistryServer) discoveryHandler(w http.ResponseWriter, req *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	groups := make([]*targetgroup.Group, 0, 1+len(l.registry.List()))

	// add node metrics to service discovery
	groups = append(groups, pluginGroup(l.discoveryHostName, l.exposedPromPort, "/metrics"))

	// add all the plugins
	for _, registeredPlugin := range l.registry.List() {
		group := pluginGroup(l.discoveryHostName, l.exposedPromPort, pluginMetricPath(registeredPlugin.Name))
		group.Labels[LabelMetaPluginName] = model.LabelValue(registeredPlugin.Name)
		groups = append(groups, group)
	}

	body, err := io.ReadAll(gc.Request.Body)

	}
