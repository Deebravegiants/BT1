### Title
JWT replay-protection check-then-record race allows replay of a workflow-trigger JWT - ([File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go])

### Summary
The `H-1` report describes a class of bug where a shared/global piece of state is *read* to make an authorization/accounting decision before the corresponding *write* that should invalidate/consume that state has happened, letting an unprivileged actor exploit the stale read to get a benefit they should not have received (claiming reward on tokens that were "about to be" frozen). The same check-then-act pattern, without atomicity between the check and the record, exists in Chainlink's gateway JWT replay-protection cache used to authorize inbound HTTP-trigger workflow requests from unprivileged external callers.

### Finding Description
`WorkflowMetadataHandler.Authorize` is the entry point that authenticates an inbound HTTP trigger request via a signed JWT before dispatching it to workflow DON nodes: [1](#0-0) 

The replay defense is implemented as two separate, independently-locked operations on `jwtReplayCache`:
- `isReplay(jti)` takes an `RLock`, checks membership, and releases the lock.
- `recordUsage(jti)` is called *after* the rest of the authorization logic (workflow lookup, signer lookup) succeeds, taking a separate `Lock` to insert the jti. [2](#0-1) 

Because `isReplay` and `recordUsage` are not executed atomically as a single critical section — the check happens, then (after other work) the record happens — two concurrent `Authorize` calls carrying the exact same JWT (`jti`) can both pass the `isReplay` check before either call reaches `recordUsage`. This is structurally identical to the reported bug class: a shared piece of state (the "already used" set / the "current total staked") is read for a decision, and only afterward is the mutation applied that should have made the second read see a different (correct) value. In the audited contract, the fix was to reorder the read to occur *after* the update; here, the analogous fix is to make the check-and-record atomic (e.g., a single locked "check-and-insert" operation, as is correctly done elsewhere in the same codebase by `RequestReplayGuard.CheckAndRecord` in `core/capabilities/vault/request_replay_guard.go`, which combines the existence check and insertion inside one `Lock`/`Unlock`). [3](#0-2) 

### Impact Explanation
A JWT is meant to be single-use for a given workflow trigger; the JWT itself functions as the caller's proof of authorization to trigger execution of a specific workflow with fixed parameters (digest-bound). If the same signed JWT can be successfully authorized twice (or more) via a race, an unprivileged external caller can cause duplicate/unauthorized workflow execution requests to be dispatched to the DON nodes using a single credential that was intended to be consumed exactly once. This is a concrete authentication/replay-bypass with real effect: unauthorized additional job/workflow runs beyond what the caller's single signed authorization should permit.

### Likelihood Explanation
Exploitation requires only that an external, unauthenticated-beyond-JWT caller send the same signed request (same `jti`) concurrently (e.g., two near-simultaneous HTTP calls). No privileged access, no node compromise, and no special network position are needed — it is reachable purely from the internet-facing gateway HTTP trigger path. The race window is small but real, and unprivileged callers fully control the timing of their own requests, making the race trivially triggerable by the caller.

### Recommendation
Merge `isReplay` and `recordUsage` into a single atomic "check-and-record" operation performed under one lock, mirroring the pattern already used in `RequestReplayGuard.CheckAndRecord`. Concretely, in `jwtReplayCache`, add a method such as `checkAndRecord(jti string) bool` that takes the write lock once, checks for existence, and if absent inserts the jti before returning — and call it from `Authorize` instead of the separate `isReplay`/`recordUsage` calls, ensuring the accept-decision and the state mutation happen as one indivisible step, analogous to correcting `Comptroller._accrueRewards` to read `globalTotalStaked` only after the frozen-amount state has been finalized.

### Proof of Concept
1. Craft one valid signed JWT `token` for a request `req` with `jti = X` for an authorized workflow/signer.
2. Fire two concurrent calls: `handler.Authorize(workflowID, token, &req)` from goroutine A and goroutine B.
3. Both goroutines execute `h.jwtCache.isReplay(claims.ID)` (line 87) before either reaches `h.jwtCache.recordUsage(claims.ID)` (line 105); both see `exists == false` and proceed past the replay guard, passing the subsequent signer/workflow checks and returning success for both — i.e., the single-use JWT is accepted twice. func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}

func (cache *jwtReplayCache) isReplay(jti string) bool {
	cache.mu.RLock()
	defer cache.mu.RUnlock()

	_, exists := cache.cache[jti]
	return exists
}

func (cache *jwtReplayCache) recordUsage(jti string) {
	cache.mu.Lock()
	defer cache.mu.Unlock()

	cache.cache[jti] = time.Now()
}

func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}
