## Title
Gateway CORS wildcard-origin allowlist bypass via unanchored suffix match - (File: `core/services/gateway/network/httpserver.go`)

## Summary
The Chainlink Gateway's `isAllowedOrigin` function implements wildcard CORS matching (e.g., `*.remix.com`) by stripping the `*.` prefix and calling `strings.HasSuffix(originHost, allowedHost)` without verifying a literal `.` label boundary precedes the match. As a result, any origin hostname that merely ends with the configured suffix string — not just true subdomains — is treated as allowed, letting an attacker who registers a look-alike domain (e.g., `evilremix.com` against a `*.remix.com` rule) bypass the intended CORS allowlist.

## Finding Description
`isAllowedOrigin` in [1](#0-0)  loops over `s.config.CORSAllowedOrigins`, and for wildcard entries strips the `*.` prefix then checks `strings.HasSuffix(originHost, allowedHost)`: [2](#0-1) 

Given a configured entry `*.remix.com`, `allowedHost` becomes `remix.com`, and `strings.HasSuffix("evilremix.com", "remix.com")` returns `true` even though `evilremix.com` is not a subdomain of `remix.com` — there is no check that the character preceding the matched suffix is a `.`. This is the same root-cause class as CVE-2024-52289: a check intended to enforce a domain/subdomain boundary is implemented as a bare, unanchored string operation.

This function is called directly from `handleRequest`, the entry point for every inbound HTTP request to the Gateway server: [3](#0-2) 
If `isAllowedOrigin` returns `true`, the raw, attacker-controlled `Origin` header value is reflected verbatim into `Access-Control-Allow-Origin`, along with permissive `Access-Control-Allow-Methods` and `Access-Control-Allow-Headers`. No authentication, role, or credential is required to trigger this — an unprivileged external client can freely set the `Origin` header on any request to the Gateway's public HTTP endpoint. There is no other validation layer between `handleRequest` and this function that would catch the boundary issue; the only prior checks are exact scheme/port/full-host matching, which do not apply to the wildcard branch.

## Impact Explanation
Operators who configure a wildcard CORS entry such as `*.mycompany.com`, intending to scope trusted origins to their own subdomains, are exposed to an allowlist bypass: an attacker-registered domain ending in the same substring (e.g., `evilmycompany.com`) is treated as trusted. This lets an attacker's web page induce a victim's browser (which holds credentials/session context for the Gateway) to make cross-origin requests to the Gateway that the server will label as CORS-permitted, and the attacker's origin can then read the JSON response contents. This maps to the in-scope "gateway request impersonation / cross-origin allowlist bypass" impact category, since it undermines the operator's intended trust boundary for the Gateway's public HTTP interface.

## Likelihood Explanation
The attack requires only that the operator has configured at least one wildcard entry in `CORSAllowedOrigins` (a supported, documented configuration pattern shown in `core/scripts/gateway/sample_config.toml`) and that the attacker registers a domain sharing the trailing substring — no special TLD control, no privileged access to Chainlink infrastructure, and no code path beyond a normal HTTP request with a crafted `Origin` header. The existing test suite in `httpserver_test.go` even demonstrates the wildcard-matching logic is actively exercised and expected to reject non-subdomain origins that don't share the suffix, but does not cover the "shares suffix without dot boundary" case, confirming the gap is untested and unnoticed.

## Recommendation
Anchor the wildcard suffix match to a label boundary: replace
```go
if strings.HasSuffix(originHost, allowedHost) {
```
with
```go
if originHost == allowedHost || strings.HasSuffix(originHost, "."+allowedHost) {
```
so that `evilmycompany.com` is rejected while `sub.mycompany.com` and `mycompany.com` are still accepted. Add regression tests analogous to `TestHTTPServer_HandleRequest_CORSEnabled_FromNotAllowedOriginWildcards` in [4](#0-3)  that assert rejection of a hostname sharing only a trailing substring without a preceding dot (e.g., `evilremix.com` against `*.remix.com`).

## Proof of Concept
1. Start the Gateway HTTP server with config `CORSEnabled = true` and `CORSAllowedOrigins = ["https://*.remix.com"]`.
2. Send an HTTP request to the Gateway endpoint with header `Origin: https://evilremix.com`.
3. Observe the response contains `Access-Control-Allow-Origin: https://evilremix.com`, `Access-Control-Allow-Methods: GET, POST, OPTIONS`, and `Access-Control-Allow-Headers: Content-Type`, despite `evilremix.com` not being a subdomain of `remix.com`.
4. As a Go unit test analog, add a case to `TestHTTPServer_HandleRequest_CORSEnabled_FromNotAllowedOriginWildcards` (or a new test) using `startNewServer` with allowed origins `[]string{"https://*.remix.com"}` and origin `"https://evilremix.com"`, then assert that `resp.Header.Get("Access-Control-Allow-Origin")` is non-empty, demonstrating the bypass — this would currently fail the intended-secure expectation, confirming the vulnerability.

func (s *httpServer) isAllowedOrigin(origin string) bool {
	originScheme, originHost, originPort, err := s.splitURL(origin)
	if err != nil {
		s.lggr.Debug("error parsing origin URL", err)
		return false
	}
	for _, allowed := range s.config.CORSAllowedOrigins {
		// probably better to do this once when server starts and store it in a map
		// this is an easier solution so we don't have to apply more changes to the code
		// just need to be careful when specifying allowed origins in the config file
		allowedScheme, allowedHost, allowedPort, err := s.splitURL(allowed)
		if err != nil {
			s.lggr.Debug("error parsing allowed origin URL", err)
			continue
		}
		// skip if the scheme doesn't match at all
		if originScheme != allowedScheme {
			continue
		}
		// skip if the port doesn't match at all
		if originPort != allowedPort {
			continue
		}
		// check for exact host match (e.g., remix.com)
		if originHost == allowedHost {
			return true
		}
		// check for wildcard host match (e.g., *.remix.com)
		if strings.HasPrefix(allowedHost, "*.") {
			allowedHost = allowedHost[2:]
			if strings.HasSuffix(originHost, allowedHost) {
				return true
			}
		}
	}
	return false
}
