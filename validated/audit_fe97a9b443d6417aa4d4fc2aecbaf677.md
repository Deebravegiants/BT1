### Title
Consensus relayers incentivised to withhold `ConsensusMessage` submission and front-run to capture unbounded block-span rewards - (File: `modules/pallets/consensus-incentives/src/impls.rs`)

### Summary
`pallet-consensus-incentives` pays whoever submits a `ConsensusMessage` a reward proportional to `(latest_height - LastRewardedHeight) * cost_per_block`. Because the reward keeps growing the longer no one submits, and submission is a permissionless, unsigned extrinsic (`pallet_ismp::Pallet::handle_unsigned` called with `RuntimeOrigin::none()`), relayers are incentivised to withhold a valid, freely-obtainable consensus proof rather than submit it immediately, waiting for the reward to accumulate, then racing/front-running each other once one submits.

### Finding Description
`Pallet::process_message` calculates the reward as: [1](#0-0) 

`blocks = latest_height - baseline` where `baseline` is `LastRewardedHeight` (or `previous_commitment_height` before the first payout), and `reward = blocks * cost_per_block` with **no cap**. This mirrors the Cooler `Clearinghouse.claimDefaulted` bug class: a reward that scales linearly with elapsed/unrewarded time (here, unrewarded block-span) rather than being paid promptly and flatly.

The relayer identity that receives the reward is recovered from the signature embedded in the `ConsensusMessage` itself: [2](#0-1) 

Submission of this message happens via `pallet_ismp::Pallet::handle_unsigned`, dispatched with `RuntimeOrigin::none()` — confirmed by the pallet's own test harness: [3](#0-2) 

As the docs state, the underlying consensus proofs "can be generated by anyone, as they are freely provided by its connected chains" [4](#0-3) . Because submission is permissionless and the proof itself is freely obtainable off-chain, any actor who could submit a valid `ConsensusMessage` (advancing `latest_height`) is not compelled to submit it promptly. Since reward grows monotonically and unboundedly with every additional block that passes without a submission, the dominant strategy is to withhold submission (letting `latest_height - LastRewardedHeight` grow), and only submit — or watch the mempool and front-run someone else's submission — once the accrued reward is large enough to be worth the gas/priority-fee competition. This directly parallels the reported Cooler `claimDefaulted` issue: a mechanism meant to reward prompt liveness-critical action instead rewards delay, and precipitates a front-running race when the reward becomes large enough to contest.

### Impact Explanation
This breaks the intended incentive of `pallet-consensus-incentives`: consensus updates for connected chains are meant to be relayed promptly to keep `IsmpHost`'s cross-chain view current, which other core message-delivery paths (timeouts, requests, responses) all depend on via `state_machine_commitment`/`latest_commitment_height`. If relayers collude or a single dominant relayer withholds submission to maximize its own payout, consensus updates for a given `StateMachineId` are delayed indefinitely, which delays or blocks all dependent cross-chain request/response/timeout processing for that chain (a route unable to deliver messages promptly) while draining a disproportionate amount of treasury funds (`TreasuryAccount`) per submission (unbacked/excessive reward extraction) once finally submitted.

### Likelihood Explanation
Likelihood is Medium-High: the consensus proof is freely available off-chain (no special access), the reward-calculation and transfer logic contain no per-submission cap or decay, and the submitting extrinsic is unsigned/permissionless so any holder of a valid proof + relayer signature can claim it — including watching the public mempool and front-running a soon-to-land submission from another relayer.

### Recommendation
Cap the maximum reward payable per submission (independent of elapsed block span), or decouple payout timing from proof arrival by requiring/incentivizing prompt submission (e.g., decaying reward the longer a submission is delayed instead of growing), similar to recommendations in the referenced report to have the protocol itself trigger payment rather than relying purely on external submitter incentives that reward delay.

### Proof of Concept
1. Governance sets `StateMachinesCostPerBlock[state_machine_id] = cost_per_block` via `update_cost_per_block` [5](#0-4) .
2. A relayer obtains a valid consensus proof for `state_machine_id` early (proofs are freely available) but does not submit it.
3. Blocks continue to advance on the remote chain; each additional block increases the eventual reward by exactly `cost_per_block`, unbounded.
4. Once the accrued `blocks * cost_per_block` is large, the relayer (or a competing relayer who detects the pending, unsubmitted advance) submits `handle_unsigned([ConsensusMessage{..}])` via `RuntimeOrigin::none()`. `process_message`/`calculate_reward` computes and pays the full unbounded span reward to whichever signer's message lands first [6](#0-5) , incentivizing gas/priority-fee front-running races among relayers who all saw the same withheld opportunity.

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}
