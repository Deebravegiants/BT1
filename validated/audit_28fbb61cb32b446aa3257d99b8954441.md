## Title
CallDispatcher.dispatch() is callable by anyone with a fully caller-controlled target, allowing theft of any funds transiently or persistently held by the shared dispatcher - (File: evm/src/utils/CallDispatcher.sol)

### Summary
`CallDispatcher.dispatch()` has no access control and lets any caller supply an arbitrary `Call[]` array (`to`, `value`, `data`) that is executed with the `CallDispatcher` itself as `msg.sender`. This is the same trust-boundary defect as `UniProxy.depositSwap`'s `_router` parameter: a contract that can hold assets exposes a function whose "target"/router is entirely determined by an unprivileged caller, so any funds sitting on that contract can be routed away by whoever calls it first.

### Finding Description
`CallDispatcher` is a shared, protocol-wide utility contract used by `HyperFungibleTokenUpgradeable`, `WrappedHyperFungibleToken`, and `IntentGatewayV2` to execute arbitrary post-mint/post-fill/pre-escrow calldata on behalf of users (swap-then-escrow, transfer-and-swap, fill-then-act patterns): [1](#0-0) 

The `dispatch` function has no `onlyGateway`/`onlyOwner`/allow-list restriction whatsoever — it is `external` and callable by any address: [2](#0-1) 

`CallDispatcher` also accepts arbitrary native ETH via an unrestricted `receive()`: [3](#0-2) 

The gateways transfer assets to this shared dispatcher and then invoke `dispatch()` on it as separate statements. In `IntentGatewayV2.placeOrder`, predispatch assets (native or ERC20) are pushed to `dispatcher` before `dispatch()` executes the user-supplied calldata: [4](#0-3) 

Similarly, `HyperFungibleTokenUpgradeable.onAccept` and `WrappedHyperFungibleTokenUpgradeable.onAccept` mint/unlock tokens to the caller-specified `to` address (which, per the documented pattern, is routinely set to `CALL_DISPATCHER` so the swap calldata can spend the funds) and only afterward hand off to `ICallDispatcher(_dispatcher).dispatch(message.data)`: [5](#0-4) 

The documentation itself confirms the dispatcher is expected to hold funds mid-flight and even warns about it: "Token approvals in the `Call[]` should use exact amounts rather than unlimited allowances, since the dispatcher contract holds tokens temporarily during execution," and explicitly instructs integrators to mint tokens directly to `CALL_DISPATCHER` before it processes calldata.

Because `dispatch()` is unauthenticated, any account — including an unrelated relayer, solver, or ordinary EOA — can call `CallDispatcher.dispatch()` directly at any time with a `Call[]` of its own choosing. Any ERC20/native balance that is momentarily or persistently resident on the shared `CallDispatcher` (e.g., tokens minted to it by a token-bridge message whose attached `data` is empty or fails to fully consume the balance, dust left after an interrupted/partial sweep, or stray ETH sent to its `receive()`) can be swept out by an attacker's own `dispatch()` call before the legitimate app-driven sweep runs — exactly the "router determined by an unprivileged caller can steal funds stuck in the contract" pattern from the reported `UniProxy.depositSwap` bug.

### Impact Explanation
`CallDispatcher` is shared infrastructure across `HyperFungibleTokenUpgradeable`, `WrappedHyperFungibleTokenUpgradeable`, and `IntentGatewayV2` — a token bridge and an intent-escrow gateway, both explicitly in-scope reachable paths. Any ERC20 or native token balance that ends up sitting on the dispatcher (by design in the mint-to-dispatcher pattern, or due to incomplete sweeps/rounding dust) can be permanently stolen by an unprivileged third party calling `dispatch()` directly, since the target contract and calldata of the executed call are fully attacker-controlled with no ownership/whitelist check on the caller of `dispatch()` itself. This is concrete theft of funds routed through, or resting on, a core cross-chain messaging/token-bridge component.

### Likelihood Explanation
Likelihood is high given normal, documented usage: the SDK/docs instruct integrators to mint bridged tokens directly to the `CallDispatcher` address so that attached calldata can spend them. Any transaction where the attached calldata does not fully drain the dispatcher's balance in the same transaction (empty `data`, a swap that returns less input consumed than expected, or partial-fill dust) leaves an exploitable window between transactions during which any address can call `dispatch()` unauthenticated and redirect the balance to itself.

### Recommendation
Restrict `CallDispatcher.dispatch()` to a fixed set of authorized callers (e.g., an immutable/owner-set allow-list of gateway contracts configured at deployment, analogous to removing the caller-supplied `_router` and using a storage variable set in the constructor). Alternatively, make `CallDispatcher` per-app/non-shared, or require that it never retain a balance across transaction boundaries by enforcing atomic sweep-to-zero checks at the end of every `dispatch()` call.

### Proof of Concept
1. A relayer delivers an ISMP POST to `HyperFungibleTokenUpgradeable.onAccept` (or `WrappedHyperFungibleTokenUpgradeable.onAccept`) where `message.to` is set to the shared `CallDispatcher` address (the documented "mint to dispatcher then swap" pattern) but `message.data` is empty, zero-length calldata, or crafted so that only part of the minted balance is consumed by the intended calls.
2. Tokens are minted/unlocked directly to `CallDispatcher`, and since `message.data.length == 0` no `dispatch()` call occurs in that transaction, or a partial-consumption calldata leaves residual balance on `CallDispatcher` after its own dispatch call completes.
3. An attacker, in a separate transaction, calls `CallDispatcher.dispatch(abi.encode([Call({to: token, value: 0, data: abi.encodeWithSelector(IERC20.transfer.selector, attacker, balance)})]))` directly — this succeeds because `dispatch()` has no caller restriction — draining the resident balance to the attacker's address.

```text
contract CallDispatcher is ICallDispatcher {
    /**
     * @dev error thrown when the target is not a contract.
     */
    error NotContract(address target);

    /**
     * @dev error thrown when a call fails.
     */
    error CallFailed(address target, bytes result);

    /**
     * @dev Receive function to accept ETH transfers
     */
    receive() external payable {}

    /**
     *  @dev reverts if the target is not a contract or if any of the calls reverts.
     */
    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
```
