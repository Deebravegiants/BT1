Audit Report

## Title
Missing allowlist/rate-limiting on Gateway `HandleLegacyUserMessage` allows unbounded fan-out of unprivileged user requests to all DON nodes - (File: core/services/gateway/handlers/capabilities/handler.go)

## Summary
`HandleLegacyUserMessage` accepts `web_api_trigger` messages from any sender capable of producing a validly-signed, non-stale message, but the allowlist/rate-limit enforcement is left as an unimplemented `// TODO` comment before the message is stored in the shared `savedCallbacks` map and forwarded to every DON member. This allows an unprivileged actor to repeatedly flood the gateway with unique `MessageID`s, exhausting the bounded `savedCallbacks` cache (evicting legitimate pending callbacks) and multiplying request load onto every node in the DON with no economic or authorization cost.

## Finding Description
In `core/services/gateway/handlers/capabilities/handler.go`, `HandleLegacyUserMessage` decodes the payload and checks message staleness, but the code explicitly defers sender allowlisting and rate limiting via `// TODO: apply allowlist and rate-limiting here` (line 384), then proceeds directly to method validation, callback storage, and DON-wide fan-out (lines 411-420). The `nodeRateLimiter` field on `handler` only guards the reverse direction — outgoing HTTP calls from gateway to external endpoints triggered by node responses in `handleWebAPIOutgoingMessage` — not inbound user requests. The only mitigation for unbounded `savedCallbacks` growth is `pruneCallbacks`, a periodic job (default every 30s) that evicts entries only after `MaxSavedCallbacks` (default 20000) is exceeded, trimming to half that size — a reactive cap, not a preventive control tied to sender identity. The handler's own test file documents this gap with an explicit unresolved TODO for sender/rate-limit validation.

## Impact Explanation
This is a Medium-severity denial-of-service: an unprivileged, non-allowlisted sender can flood the shared `savedCallbacks` map and force `don.SendToNode` calls to every DON member on each request, degrading or denying the `web_api_trigger` capability for legitimate users (whose callbacks can be prematurely evicted) and multiplying unwanted load across all workflow nodes in the DON.

## Likelihood Explanation
High reachability and low attacker cost: `HandleLegacyUserMessage` is reachable directly by any external client that can produce a validly-signed, non-stale message (signature/staleness checks require no allowlist membership or payment), and repeating this with unique `MessageID`s is trivial and cheap to automate.

## Recommendation
Implement the sender allowlist and rate-limiting check at the `// TODO` in `HandleLegacyUserMessage`, before storing the callback and fanning out to `h.donConfig.Members`: validate `msg.Body.Sender` against a configured allowlist for the DON/trigger, and apply a per-sender (and/or global) rate limiter analogous to the existing `ratelimit.RateLimiter` pattern used for `nodeRateLimiter`, or reuse the `allowedSenders`/`rateLimiter` machinery already present in the trigger-side webapi code.

## Proof of Concept
Extend `core/services/gateway/handlers/capabilities/handler_test.go` with a test that issues repeated `HandleLegacyUserMessage` calls using distinct `MessageID`s from a single non-allowlisted sender key, and assert that (a) all requests succeed and are fanned out to all `donConfig.Members`, and (b) `savedCallbacks` grows without any per-sender throttling until `pruneCallbacks`/`MaxSavedCallbacks` kicks in — demonstrating no allowlist or rate limit is applied prior to that point.

func (h *handler) pruneCallbacks() {
	h.mu.Lock()
	defer h.mu.Unlock()

	// First, remove expired callbacks.
	maxAge := time.Duration(h.config.CallbackMaxAgeSec) * time.Second
	now := time.Now()
	var expired int
	for id, cb := range h.savedCallbacks {
		if now.Sub(cb.createdAt) > maxAge {
			delete(h.savedCallbacks, id)
			expired++
		}
	}

	// If there are still too many callbacks, sort them by creation time and remove the oldest ones.
	maxSize := h.config.MaxSavedCallbacks
	var evicted int
	if len(h.savedCallbacks) > maxSize {
		type entry struct {
			id        string
			createdAt time.Time
		}
		entries := make([]entry, 0, len(h.savedCallbacks))
		for id, cb := range h.savedCallbacks {
			entries = append(entries, entry{id, cb.createdAt})
		}
		sort.Slice(entries, func(i, j int) bool {
			return entries[i].createdAt.Before(entries[j].createdAt)
		})
		// Trim to maxSize/2 to avoid sorting the list too frequently.
		for _, e := range entries[:len(entries)-maxSize/2] {
			delete(h.savedCallbacks, e.id)
			evicted++
		}
	}

	if expired > 0 || evicted > 0 {
		h.lggr.Infow("Pruned savedCallbacks", "expired", expired, "evicted", evicted, "remaining", len(h.savedCallbacks))
	}
