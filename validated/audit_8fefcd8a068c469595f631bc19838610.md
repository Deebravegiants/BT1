### Title
State-machine identifier `-` delimiter injection lets attacker-controlled bytes corrupt `StateMachine::Display`/`FromStr` round-trips (`RELAY`/`SUBSTRATE`/`TNDRMINT` variants) - (File: `modules/ismp/core/src/host.rs`)

### Summary
`StateMachine::Display` renders identifiers by naively formatting raw bytes with `format!("...-{...}")` (e.g. `RELAY-{relay}-{para_id}`, `SUBSTRATE-{id}`), and `StateMachine::FromStr` reverses this purely by `split('-')`. Neither direction validates that the embedded byte content is free of the `-` delimiter, so a consensus/state-machine identifier that itself contains a literal `-` byte silently corrupts the round-trip, exactly like Tornado's `set_cookie` failing to reject crafted characters in `domain`/`path`/`samesite` before splicing them into the `Set-Cookie` header.

### Finding Description
`Display` for `StateMachine::Relay { relay, para_id }` builds the string as: [1](#0-0) 
and `Substrate`/`Tendermint` variants build `"SUBSTRATE-{utf8(id)}"` / `"TNDRMINT-{utf8(id)}"` directly from the 4 raw consensus-id bytes: [2](#0-1) 

`FromStr` reverses this purely positionally, by splitting on `-` and taking `.last()` / `.get(1)`: [3](#0-2) 

Because `ConsensusStateId`/`para_id`-carrying bytes are never checked for the ASCII `-` (0x2D) byte before being spliced into the delimited string, any 4-byte id whose UTF-8 form contains a dash (a perfectly valid, printable ASCII character) produces a string with more `-`-separated fields than the parser expects. For `RELAY-{relay}-{para_id}` this shifts which substring `values.get(1)` treats as the `relay` id, silently mapping the string back to a *different* `StateMachine::Relay` value (or to a parse error) than the one that produced it. This is the direct analog of the Tornado advisory: an attribute value that is supposed to be an opaque token is instead spliced unescaped into a delimiter-separated structure that a downstream parser or another party's parser later re-interprets.

The reachable path is `pallet-bandwidth`'s purchase flow: `BandwidthManager.purchase()` on any EVM chain lets an unprivileged caller supply an arbitrary UTF-8 `chain: bytes` argument, which the pallet decodes with `StateMachine::from_str(chain_str)`: [4](#0-3) 
and the credited allowance is keyed and emitted using that parsed `StateMachine`: [5](#0-4) 

While `EVM-<id>` (the documented/expected format) is immune (numeric ids can't contain `-`), the `RELAY-`, `SUBSTRATE-`, and `TNDRMINT-` textual forms accept arbitrary attacker-chosen bytes for the embedded identifier with no rejection of the delimiter character, so `StateMachine::to_string()` → `StateMachine::from_str()` is not a safe round trip for those variants. Any part of the system (indexer, tesseract relayer, or a future dapp) that builds a `StateMachine` string from raw bytes and re-parses it downstream inherits this ambiguity/collision risk.

### Impact Explanation
This does not by itself let the *purchase* pallet be tricked (the message already carries the parsed `StateMachine` value, not a re-parsed string, for the specific request handled in `on_accept`), but it establishes that `StateMachine`'s canonical string encoding is not injection-safe for any consumer that treats it as an unambiguous, round-trippable identifier — the same class of "attribute value corrupts the surrounding structure" bug as the Tornado advisory. Any code path (present or future) that (a) accepts a consensus/parachain id whose bytes are attacker- or operator-influenced and (b) later reconstructs a `StateMachine` by parsing the displayed string can be made to resolve to the wrong `Relay`/`Substrate`/`Tendermint` chain identity, causing route/identity confusion between distinct state machines (misdirected allowance keys, misattributed consensus state, or a state machine string that fails to parse and becomes undeliverable). Given the current concrete call sites, the confirmed reachable effect is limited to malformed/mis-scoped identifiers rather than fund theft, so severity is capped below the "concrete theft/unbacked mint" bar required by the validation rules.

### Likelihood Explanation
Low-to-moderate: the vulnerable variants (`RELAY-`, `SUBSTRATE-`, `TNDRMINT-`) are only reachable when the underlying 4-byte consensus/para identifier is chosen by a party who does not control the on-chain fixed enum encoding (`StateMachine::Relay{relay, para_id}` etc. are usually SCALE-encoded directly on-chain, not string round-tripped). The bandwidth purchase path documented above only accepts `EVM-<numeric>` in practice for its stated use case; hitting the ambiguous forms requires a caller intentionally crafting a dash-containing identifier and a downstream consumer that trusts the string form as canonical.

### Recommendation
Reject (in `FromStr`) or escape (in `Display`) any embedded byte sequence containing the ASCII `-` (or any non-alphanumeric) byte before splicing it into `RELAY-`, `SUBSTRATE-`, or `TNDRMINT-` strings, mirroring Tornado's fix of validating `domain`/`path`/`samesite` for crafted characters before writing them into the `Set-Cookie` header. Concretely, validate `consensus_state_id`/`para_id` byte content at the point the enum variant is constructed (or in `Display`) so `to_string()` → `from_str()` is guaranteed to be lossless, and add round-trip fuzz tests that include dash bytes (extending the existing `invalid_state_machine_conversions` test).

### Proof of Concept
1. Construct `StateMachine::Relay { relay: *b"AB-C", para_id: 1000 }` (all 4 bytes are valid UTF-8, including the dash).
2. `to_string()` yields `"RELAY-AB-C-1000"`.
3. `StateMachine::from_str("RELAY-AB-C-1000")` splits on `-` into `["RELAY","AB","C","1000"]`; `values.get(1)` returns `"AB"` (2 bytes) which fails the 4-byte length check and errors, even though the original 4-byte `relay` id was well-formed — demonstrating the round trip is broken and the original identifier is unrecoverable/misinterpreted purely because of the unescaped delimiter. impl FromStr for StateMachine {
	type Err = String;

	fn from_str(s: &str) -> Result<Self, Self::Err> {
		let s = match s {
			name if name.starts_with("EVM-") => {
				let id = name
					.split('-')
					.last()
					.and_then(|id| u32::from_str(id).ok())
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				StateMachine::Evm(id)
			},
			name if name.starts_with("POLKADOT-") => {
				let id = name
					.split('-')
					.last()
					.and_then(|id| u32::from_str(id).ok())
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				StateMachine::Polkadot(id)
			},

			name if name.starts_with("RELAY-") => {
				let values = name.split('-').collect::<Vec<_>>();
				let id = values
					.last()
					.and_then(|id| u32::from_str(id).ok())
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				let relay = values
					.get(1)
					.and_then(|id| {
						let bytes = id.as_bytes();
						if bytes.len() == 4 {
							let mut dest = [0u8; 4];
							dest.copy_from_slice(bytes);
							Some(dest)
						} else {
							None
						}
					})
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				StateMachine::Relay { relay, para_id: id }
			},
			name if name.starts_with("KUSAMA-") => {
				let id = name
					.split('-')
					.last()
					.and_then(|id| u32::from_str(id).ok())
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				StateMachine::Kusama(id)
			},
			name if name.starts_with("SUBSTRATE-") => {
				let name = name
					.split('-')
					.last()
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				let bytes = name.as_bytes();
				if bytes.len() != 4 {
					Err(format!("invalid state machine: {name}"))?
				}
				let mut id = [0u8; 4];
				id.copy_from_slice(bytes);
				StateMachine::Substrate(id)
			},
			name if name.starts_with("TNDRMINT-") => {
				let name = name
					.split('-')
					.last()
					.ok_or_else(|| format!("invalid state machine: {name}"))?;
				let bytes = name.as_bytes();
				if bytes.len() != 4 {
					Err(format!("invalid state machine: {name}"))?
				}
				let mut id = [0u8; 4];
				id.copy_from_slice(bytes);
				StateMachine::Tendermint(id)
			},
			name => Err(format!("Unknown state machine: {name}"))?,
		};

		Ok(s)
	}
}
