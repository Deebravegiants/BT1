### Title
`CallDispatcher` accepts ETH via an unrestricted `receive()` but has no rescue/withdraw function, permanently locking any stray or leftover native token balance - (File: `evm/src/utils/CallDispatcher.sol`)

### Summary
`CallDispatcher` is a shared, ownerless utility contract used by `IntentGatewayV2` to forward native-token payouts to untrusted call targets during order fills/settlement. Like `FootiumPrizeDistributor`, it implements an unconditional `receive() external payable {}` but exposes no function anywhere in the contract to withdraw or sweep its own native-token balance.

### Finding Description
`CallDispatcher.sol` declares: [1](#0-0) 

and its only other function, `dispatch`, forwards the contract's *own* balance to whatever `to`/`value`/`data` triplets are encoded in the caller-supplied `Call[]` array: [2](#0-1) 

`dispatch` is not `payable` and only ever moves out exactly the amounts named in the supplied calls; it never reconciles or sweeps the contract's residual balance. Because `receive()` has no access control, this contract's address can be sent native tokens directly by anyone, and because `dispatch()` is fully controlled by whichever caller supplies the `Call[]` payload (from `IntentsBase`/`ExtrinsicIntents` in `evm/src/apps/intentsv2/IntentsBase.sol`), any balance not explicitly re-routed by a subsequent `dispatch()` call (rounding dust, direct/accidental transfers, or a call batch that undersends relative to the balance held) has no code path to ever leave the contract again. There is no owner, no `Ownable`, and no rescue/skim function defined anywhere in `CallDispatcher.sol`.

This mirrors the reported `FootiumPrizeDistributor` bug class exactly: an unrestricted `receive()` combined with the total absence of any generic withdrawal mechanism for the native token the contract is designed to hold and forward.

### Impact Explanation
Because `CallDispatcher` is used within the `IntentGatewayV2` order-fill flow to move escrowed native-token proceeds to fill targets (per the comment "receiving swept balances from the CallDispatcher" in `evm/src/apps/IntentGatewayV2.sol:77-82`), any native-token dust that accumulates in it (from direct sends, rounding, or partially-matched dispatch batches) is permanently and irrecoverably frozen — no admin, governance, or user action can ever retrieve it, since the contract has no privileged role and no sweep entry point.

### Likelihood Explanation
Likelihood is limited to accidental or edge-case native-token transfers to the `CallDispatcher` address (direct sends by users/scripts, or dust left behind by imperfect `Call[]` batches), the same low-but-nonzero likelihood pattern as the original report. It does not require any privileged action and is reachable by any unprivileged party who can send a transaction to the contract's address.

### Recommendation
Add a permissioned (or at minimum, non-discriminatory) rescue/skim function to `CallDispatcher` that allows recovering any native-token balance not currently earmarked by an in-flight `dispatch()` call, e.g., an owner-gated `rescue(address to, uint256 amount)` or a `sweep()` that forwards `address(this).balance` to a configured beneficiary.

### Proof of Concept
1. Any address sends ETH directly to the deployed `CallDispatcher` contract (its `receive()` at `evm/src/utils/CallDispatcher.sol:39` accepts it unconditionally).
2. No function in the contract — `dispatch` included — provides a path to withdraw this balance back out; `dispatch` only moves amounts explicitly specified in caller-supplied `Call[]` structs.
3. The sent ETH remains locked in the contract indefinitely, with no rescue mechanism ever added.

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
