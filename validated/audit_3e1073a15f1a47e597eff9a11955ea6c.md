## Title
Pausing cross-chain operations blocks timeout refunds, freezing burned tokens - (File: `sdk/packages/core/contracts/apps/HyperFungibleToken.sol`, `HyperFungibleTokenUpgradeable.sol`, `WrappedHyperFungibleToken.sol`, `WrappedHyperFungibleTokenUpgradeable.sol`)

### Summary
`HyperFungibleToken` and its sibling contracts (`HyperFungibleTokenUpgradeable`, `WrappedHyperFungibleToken`, `WrappedHyperFungibleTokenUpgradeable`) gate `onPostRequestTimeout()` — the callback that refunds a user's burned/escrowed tokens when a cross-chain `send()` times out — behind the same `whenNotPaused` modifier used to gate inbound deposits (`onAccept`). This is the same anti-pattern described in the external `LpToken` report: a pause switch intended to stop risky *inflows* is also applied to the *refund/withdrawal* path, letting the owner (or an emergency pause triggered while a security incident is being investigated) block users from recovering funds they already burned.

### Finding Description
`send()` burns the caller's tokens and dispatches a POST request cross-chain [1](#0-0) . If that request times out, `EvmHost.dispatchTimeOut` invokes the app's `onPostRequestTimeout()` to re-mint the burned tokens back to the sender [2](#0-1) . Both `onAccept` (inbound mint on delivery) and `onPostRequestTimeout` (refund mint on timeout) are marked `whenNotPaused` in every fungible-token app variant: [3](#0-2) [4](#0-3) [5](#0-4) [6](#0-5) .

The contract is `Pausable`, and `pause()`/`unpause()` are owner-gated [7](#0-6) . Documentation confirms the intent is to pause "all cross-chain operations (send and receive)" as a single unit [8](#0-7) , mirroring exactly the design flaw flagged in the external report — deposit-side and withdrawal-side controls sharing one switch.

While `EvmHost.dispatchTimeOut` does restore the request commitment on a failed callback so the timeout can be *retried* later [9](#0-8) , this only mitigates permanent loss — it does not remove the DoS: for the entire duration the contract is paused, any user whose `send()` times out cannot recover their already-burned tokens through `onPostRequestTimeout`, even though the pause was intended only to stop new/suspicious inbound mints via `onAccept`.

### Impact Explanation
A paused `HyperFungibleToken`/`WrappedHyperFungibleToken` deployment denies legitimate users access to funds they already burned on the source chain while a cross-chain transfer is timing out. Because the same pause flag also blocks `transfer`/`transferFrom` [10](#0-9) , users lose all liquidity/recovery options for the token during the pause window. This is a Medium-severity denial-of-service on user funds recovery, directly analogous to the reported `LpToken` withdrawal DoS.

### Likelihood Explanation
Pausing is a normal incident-response action expected to be used whenever a security concern (e.g., a compromised peer chain module, a bridge exploit elsewhere) is detected — precisely the scenario in which users are also likely to have in-flight `send()` requests timing out. The owner does not need to act maliciously; using `pause()` as documented ("pause all cross-chain operations") is sufficient to trigger the freeze.

### Recommendation
Do not gate `onPostRequestTimeout()` (and, by analogy, any other refund/recovery callback) with `whenNotPaused`. Reserve the pause modifier for inbound mint paths (`onAccept`) and outbound `send()`, so that once tokens are already burned/escrowed, users can always reclaim them via the timeout path regardless of pause state.

### Proof of Concept
1. Owner calls `pause()` on `HyperFungibleTokenUpgradeable` in response to a suspected issue [11](#0-10) .
2. A user's earlier `send()` call had burned tokens and dispatched a POST request that subsequently times out (e.g., destination chain congestion) [1](#0-0) .
3. A relayer (or the user) submits the timeout proof via `HandlerV2.handlePostRequestTimeouts`, which calls `EvmHost.dispatchTimeOut` → `onPostRequestTimeout` [12](#0-11) [2](#0-1) .
4. `onPostRequestTimeout` reverts because of `whenNotPaused` [13](#0-12) ; the user's burned tokens remain unrefunded for as long as the pause is active, and any direct token transfers are also blocked in the interim.

    function dispatchTimeOut(
        PostRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onPostRequestTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit PostRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

        HyperFungibleToken.Message memory message = abi.decode(incoming.request.body, (HyperFungibleToken.Message));
        address refundee = _toAddr(message.from);

        if (_isWeth) {
            // Try a native-ETH push first; if the refundee cannot accept native value
            // (e.g. the caller used the ERC-20 deposit path in `send()` from a
            // non-payable contract), re-wrap the withdrawn ETH and deliver the
            // underlying WETH as an ERC-20 transfer so the timeout still settles and
            // funds are not permanently locked.

            if (!sent) {
                IWETH(_underlying).deposit{value: message.amount}();
                IERC20(_underlying).safeTransfer(refundee, message.amount);
            }
        } else {
            IERC20(_underlying).safeTransfer(refundee, message.amount);
        }

        emit Refunded({to: refundee, amount: message.amount});
    }

    function handlePostRequestTimeouts(IHost host, PostRequestTimeoutMessage calldata message)
        external
        notFrozen(host)
    {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            PostRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            // known request? also serves as source check
            bytes32 requestCommitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(requestCommitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(REQUEST_RECEIPTS_STORAGE_PREFIX, requestCommitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(PostRequestTimeout(request, _msgSender()), meta, requestCommitment);
        }
    }
