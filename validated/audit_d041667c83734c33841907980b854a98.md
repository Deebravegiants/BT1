### Title
Centralized fetchPrice fallback in fee-token/native conversion can deny cross-chain intent order placement - ([File: sdk/packages/sdk/src/protocols/intents/utils.ts])

### Summary
The intents SDK's `convertFeeTokenToWei` and `convertGasToFeeToken` helpers fall back to a centralized external price API (`fetchPrice`) whenever the on-chain Uniswap V2 quote fails or returns zero. This is structurally identical to the reported ZecWallet bug: a single external price source (there, coinmarketcap.com; here, the `fetchPrice` provider) feeding a division that is used to compute the amount attached to a cross-chain dispatch. If that price source is unavailable, rate-limited, or returns `0`, the downstream `Decimal.dividedBy()` call either throws or yields a nonsensical value, breaking fee/native-value computation for any order or teleport that must fall back off the on-chain swap path.

### Finding Description
`convertFeeTokenToWei` first attempts an on-chain Uniswap V2 quote; on failure or a zero `amountOut` it falls back to:
```
const nativeTokenPriceUsd = await fetchPrice(nativeCurrency?.symbol, chainId)
const feeTokenAmountUsd = feeTokenAmountInToken.times(new Decimal(1))
const nativeAmount = feeTokenAmountUsd.dividedBy(nativeTokenPriceUsd)
``` [1](#0-0) 

`fetchPrice` is a single, centralized off-chain price provider (the same architectural role coinmarketcap.com plays in the ZecWallet report). If it returns `0` (temporary outage, malformed response, unlisted symbol, or a DNS/availability attack against the provider), `Decimal.dividedBy(0)` on a non-zero dividend produces an unusable result (Decimal.js throws a `DivisionByZero` error rather than silently returning `Infinity`), propagating an unhandled exception out of `convertFeeTokenToWei`/`convertGasToFeeToken`.

This same fallback pattern is reused by `convertGasToFeeToken` for computing `totalGasInFeeToken` and `relayerFeeInSourceFeeToken`, values consumed directly by `GasEstimator.estimateFillOrder` and `IntentGateway.quoteOrderFees`, which are the fee/quote paths solvers and end-users rely on to size the `nativeValue`/`fees` attached to `placeOrder` / cross-chain dispatch transactions: [2](#0-1) [3](#0-2) 

`IntentGateway.quoteOrderFees` does defend against a zero *gas* estimate ("Gas estimation failed"), but that guard only checks `estimate.totalGasCostWei === 0n || estimate.totalGasInFeeToken === 0n`; it does not protect against the underlying `fetchPrice` call throwing before those values are even produced, nor against a wrong (but non-zero) price silently corrupting `nativeAmount`/`totalGasInFeeToken`.

### Impact Explanation
Because these helpers are the fallback path exercised whenever the primary on-chain Uniswap V2 quote fails (thin liquidity, missing pair, reverting router — explicitly anticipated by the code's own comments), any chain/token pair without deep Uniswap V2 liquidity is entirely dependent on the centralized `fetchPrice` provider for fee/native-value computation. An outage or zero/garbage response from that provider denies the ability to compute a valid fee or native value for placing an order or teleport on that route — i.e., "a route unable to deliver messages," mirroring the original report's "mobile wallets unable to send funds" impact, but at the scale of every user/solver relying on the SDK for that chain pair rather than a single device.

### Likelihood Explanation
Likelihood is moderate: it requires either (a) the paired Uniswap V2 pool for the relevant fee-token/WETH leg to be unavailable/thin (which the code's own comments acknowledge as an expected occurrence, not an edge case) and (b) the external `fetchPrice` provider to be down, rate-limited, or serving a stale/zero price at the same time. Both conditions are realistically triggerable without any privileged access — an attacker only needs to target the price provider's availability (as in the original coinmarketcap DoS scenario) during periods when the DEX-based fallback is already unusable for a given chain/token.

### Recommendation
- Validate `fetchPrice`'s return value is strictly positive and finite before using it as a divisor; treat `0`/`NaN`/missing as an explicit, caught error rather than letting a `Decimal` division-by-zero exception propagate uncaught.
- Do not rely on a single centralized off-chain price source as the sole fallback for fee/native-value computation; support multiple independent price sources or an on-chain oracle (e.g., Chainlink, similar to `SimplexPaymaster._getOraclePrice`, which already validates staleness/positivity) as the fallback instead of a single web API.
- Extend the existing "Gas estimation failed" guard in `IntentGateway.quoteOrderFees` to also cover failures thrown out of `convertFeeTokenToWei`/`convertGasToFeeToken`, surfacing a clear, catchable error to callers rather than an unhandled Decimal exception.

### Proof of Concept
1. Target a chain/fee-token pair where the on-chain Uniswap V2 pool for `feeToken -> WETH` has no liquidity or reverts (already an anticipated case per the code comments in `gas_oracle.rs`/`utils.ts`).
2. Cause the `fetchPrice` provider (external HTTP price API) to become unavailable or return a `0`/malformed price for the requested native-currency symbol — e.g., via a DoS against the provider, analogous to the original report's DNS-hijack/DoS against coinmarketcap.com.
3. Any SDK caller (solver via `GasEstimator.estimateFillOrder`, or an end-user via `IntentGateway.quoteOrderFees` / `TokenGateway.quoteNative`) invoking `convertFeeTokenToWei` on that route now hits `feeTokenAmountUsd.dividedBy(0)`, throwing an unhandled `Decimal` division-by-zero error and aborting fee computation — preventing the order/teleport from being quoted or dispatched on that route until the external price provider recovers. export async function convertFeeTokenToWei(
	ctx: IntentGatewayContext,
	feeTokenAmount: bigint,
	feeTokenIn: "source" | "dest",
	evmChainID: string,
): Promise<bigint> {
	// Testnet gas is treated as effectively free upstream, so the wei-equivalent
	// is negligible too; this also avoids the CoinGecko fallback that rate-limits CI.
	if (TESTNET_CHAINS.has(evmChainID)) return 1n

	const chain = ctx[feeTokenIn]
	const client = chain.client
	const wethAddr = chain.configService.getWrappedNativeAssetWithDecimals(evmChainID).asset
	const feeToken = await getFeeToken(ctx, evmChainID, chain)

	try {
		const { amountOut } = await ctx.swap.findBestProtocolWithAmountIn(
			client,
			feeToken.address,
			wethAddr,
			feeTokenAmount,
			evmChainID,
			{ selectedProtocol: "v2" },
		)
		if (amountOut === 0n) {
			throw new Error()
		}
		return amountOut
	} catch {
		const nativeCurrency = client.chain?.nativeCurrency
		const chainId = Number.parseInt(evmChainID.split("-")[1])
		const feeTokenAmountInToken = new Decimal(formatUnits(feeTokenAmount, feeToken.decimals))
		const nativeTokenPriceUsd = await fetchPrice(nativeCurrency?.symbol, chainId)
		const feeTokenAmountUsd = feeTokenAmountInToken.times(new Decimal(1))
		const nativeAmount = feeTokenAmountUsd.dividedBy(nativeTokenPriceUsd)
		return parseUnits(nativeAmount.toFixed(nativeCurrency?.decimals ?? 18), nativeCurrency?.decimals ?? 18)
	}

	async quoteOrderFees(
		order: Order,
		options?: { maxPriorityFeePerGasBumpPercent?: number; maxFeePerGasBumpPercent?: number },
	): Promise<OrderFeesQuote> {
		const isSameChain = this.source.config.stateMachineId === this.dest.config.stateMachineId
		const orderFeeGasPriceBumpPercent = resolveOrderFeeGasPriceBump(this.source.config.stateMachineId, isSameChain)
		const estimate = await this.gasEstimator.estimateFillOrder(
			{
				order,
				maxPriorityFeePerGasBumpPercent: options?.maxPriorityFeePerGasBumpPercent,
				maxFeePerGasBumpPercent: options?.maxFeePerGasBumpPercent,
			},
			{ orderFeeGasPriceBumpPercent },
		)

		if (estimate.totalGasCostWei === 0n || estimate.totalGasInFeeToken === 0n) {
			throw new Error("Gas estimation failed")
		}

		// Same-chain fills need a larger solver fee margin. Cross-chain orders
		// attach (fill gas + the settlement relayer fee, the SAME gas budget a
		// solver's requirement is sized against) with a 5% buffer over the WHOLE
		// sum: the solver's requirement carries no padding of its own, so the
		// buffer must cover the relayer component too — a buffer on fill gas
		// alone is dwarfed whenever the source chain is expensive and the
		// destination cheap (relayer fee >> fill gas), and every SDK-placed
		// order would come up short and be refused.
		const fees = isSameChain
			? estimate.totalGasInFeeToken * 2n
			: ((estimate.totalGasInFeeToken + estimate.relayerFeeInSourceFeeToken) * 105n) / 100n

		const { address: feeToken } = await this.source.getFeeTokenWithDecimals()

		return {
			fees,
			nativeValue: estimate.totalGasCostWei + (estimate.totalGasCostWei * 2n) / 100n,
			feeToken,
			estimate,
		}
