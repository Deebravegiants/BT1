### Title
Arbitrary swap-route code can append unauthorized wallet token transfers to a signed controller authorization tree - (File: contracts/controller/src/strategies/swap.rs)

### Summary

Router-backed strategy entrypoints accept caller-controlled opaque `swap` bytes and execute them while the account owner’s root `require_auth` remains active. Although the controller authorizes only one exact input-token transfer to the configured router, a route can place attacker-controlled pool or token code beneath that authorization tree, where it can request an unrelated token transfer from the caller. If simulation records that child transfer and the caller signs the returned authorization tree, the unrelated wallet tokens are transferred to the attacker while the lending strategy still satisfies its measured-output and account-risk checks. [1](#0-0) [2](#0-1) 

### Finding Description

`swap_collateral` authenticates `caller`, requires the caller to be the account owner or an active delegate, and forwards the caller-controlled `swap` payload into `withdraw_and_swap_from_supply`. [3](#0-2) 

The equivalent router boundary is also reachable through `swap_debt(caller, account_id, existing_debt, amount, new_debt, swap)` and `repay_debt_with_collateral(caller, account_id, collateral, collateral_amount, debt, swap, close_position)`. [4](#0-3) [5](#0-4) 

The shared swap helper snapshots the controller’s input and output balances, authorizes one transfer of exactly `amount_in` to the configured router, invokes `execute_strategy`, rejects overspending, refunds unused input, and requires positive measured output. [1](#0-0) 

Those checks bound only movement of the controller-held swap input and output; they do not prevent route-selected code below the caller’s authorization from requesting another token transfer from the caller’s wallet. [6](#0-5) 

The harness demonstrates that a malicious hop pool can call `token.transfer(victim, attacker, amount)` while the route executes, that Soroban simulation records that transfer as a child of the victim’s `swap_collateral` authorization, and that signing the recorded tree transfers the victim’s unrelated wallet balance. [7](#0-6) [8](#0-7) 

### Impact Explanation

A victim can lose wallet assets that are not listed by XOXNO Lending, were not supplied as collateral, and are not part of the swap amount. The proof uses an unrelated token balance of `77_770_000_000` and ends with the victim balance at zero and the attacker balance equal to that full amount. [9](#0-8) [10](#0-9) 

The lending operation itself can remain valid because the malicious route still pays the requested output and the controller’s post-operation accounting only verifies controller balance deltas and final account risk. [11](#0-10) [12](#0-11) 

### Likelihood Explanation

Exploitation requires the victim to submit a malicious route and sign the authorization tree returned by simulation, so it is not a fully unauthenticated theft path. The practical risk is that the attacker controls opaque `swap` bytes and route-selected contract addresses while the wallet’s authorization tree can include a nested transfer that is unrelated to the lending operation. [13](#0-12) [2](#0-1) 

A caller cannot target a foreign account because `process_swap_collateral` separately enforces `require_owner_or_delegate`, but an attacker can distribute the malicious route to victims who each operate on their own account. [14](#0-13) 

The enforced-auth test confirms the attack succeeds only when the signed tree contains the rogue transfer; therefore, client-side authorization inspection mitigates users who fully decode and verify the tree, but the protocol still exposes a dangerous opaque-route trust boundary. [15](#0-14) 

### Recommendation

Restrict swap routes to governance-reviewed venue and pool addresses, or otherwise introduce a route allowlist that prevents arbitrary contract addresses from executing beneath the caller’s authorization. For routes that must remain flexible, the API should expose a decoded, canonical list of every contract invocation and token transfer before signing, and clients should reject any authorization tree containing children other than the expected controller-authorized input transfer. The controller or router should additionally bind the signed strategy payload to a declared venue/pool registry so a payload cannot silently introduce unrelated token contracts or recipient addresses. [16](#0-15) [2](#0-1) 

### Proof of Concept

1. Deploy a malicious hop contract whose swap function calls `token::Client::transfer(victim, attacker, wallet_balance)` for an unrelated token held by the victim. [7](#0-6) 
2. Give the victim a funded lending account and an unrelated wallet-token balance, then construct `swap_collateral(alice, account_id, usdc_key, 50_000_000_000, eth_key, route)` where `route` names the malicious hop contract but still returns the expected ETH output. [17](#0-16) 
3. Simulate the call; the recorded authorization for Alice contains the `swap_collateral` root and a child `wallet_token.transfer(alice, attacker, wallet_balance)`. [18](#0-17) 
4. Submit the call with that signed authorization tree; the swap deposits the fair ETH output into Alice’s position while Alice’s unrelated wallet-token balance moves to the attacker. [10](#0-9) 
5. The enforced-auth test isolates the authorization failure mode: the same malicious route fails with an unsigned tree and succeeds once the rogue transfer is present in the signed tree. [19](#0-18)

#[test]
fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
}

#[test]
fn enforced_auth_moves_the_wallet_token_only_when_the_signed_tree_lists_the_rogue_transfer() {
    let s = Scene::new();

    // Control: a pool that touches nothing passes with the honest root-only tree.
    let benign = s.route_through_pool_stealing(0);
    s.try_swap_with_signed_tree(&benign, &[])
        .expect("the honest tree authorizes an honest route");
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);

    // Rogue pool, honest tree: the host refuses the transfer and the whole call rolls back.
    s.t.env.mock_all_auths_allowing_non_root_auth();
    let rogue = s.route_through_pool_stealing(WALLET_BALANCE);
    let usdc_before = s.t.supply_balance_raw(ALICE, "USDC");
    let refused = s
        .try_swap_with_signed_tree(&rogue, &[])
        .expect_err("a transfer outside the signed tree is unauthorized");
    std::println!("rogue transfer under the honest tree = {refused:?}");
    assert!(
        refused.is_type(ScErrorType::Auth) || refused.is_type(ScErrorType::Context),
        "expected a host auth failure, got {refused:?}"
    );
    assert!(s
        .diagnostics()
        .contains("Unauthorized function call for address"));
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);
    assert_eq!(s.wallet(&s.attacker), 0);
    assert_eq!(s.t.supply_balance_raw(ALICE, "USDC"), usdc_before);

    // Same route, with the tree that simulation returned.
    let stolen_transfer = MockAuthInvoke {
        contract: &s.wallet_token,
        fn_name: "transfer",
        args: (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        sub_invokes: &[],
    };
    s.try_swap_with_signed_tree(&rogue, core::slice::from_ref(&stolen_transfer))
        .expect("the poisoned tree authorizes the rogue transfer");
    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);

/// Requires debt coverage by LTV-weighted collateral, health factor >= 1, and
/// the configured collateral floor. Debt-free accounts skip all three checks.
pub(crate) fn require_post_pool_risk_gates(env: &Env, cache: &mut Context, account: &Account) {
    if account.debt_free() {
        return;
    }

    let totals = risk::calculate_account_risk_totals(
        env,
        cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    assert_with_error!(
        env,
        totals.ltv_collateral >= totals.total_debt,
        CollateralError::InsufficientCollateral
    );

    spec_hooks::solvency_gate_checked(account);

    assert_with_error!(
        env,
        totals.health_factor >= Wad::ONE,
        CollateralError::InsufficientCollateral
    );

    let floor = storage::get_min_borrow_collateral_usd_wad(env);
    if floor != 0 && totals.ltv_collateral.raw() < floor {
        panic_with_error!(env, CollateralError::MinBorrowCollateralNotMet);
    }

    require_whole_unit_collateral_floor(env, cache, account);
}
