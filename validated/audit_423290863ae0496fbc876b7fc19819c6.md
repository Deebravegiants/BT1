### Title
Legacy WebAPI Trigger Gateway Path Dispatches Unauthenticated Workflow Triggers to All DON Nodes Without Allowlist Check - (File: core/services/gateway/handlers/capabilities/handler.go)

### Summary
The Yggdrasil CVE (CVE-2025-3931) is a "missing authorization on a message-dispatch path that fans out a privileged action to worker processes" bug class. Chainlink's Gateway has a directly analogous pattern in the legacy WebAPI trigger path: `handler.HandleLegacyUserMessage` accepts any correctly self-signed message and unconditionally forwards it as a trigger request to every node in the DON, with an explicit `// TODO: apply allowlist and rate-limiting here` marking the missing authorization check.

### Finding Description
`gateway.ProcessRequest` routes internet-facing HTTP requests lacking a DON-scoped JSON-RPC service name to the legacy path when `msg.Body.DonID != ""`, calling `msg.Validate()` and then `h.HandleLegacyUserMessage(ctx, msg, callback)`. [1](#0-0) 

`Message.Validate()` only checks field-length constraints and recovers a signer address from the message signature — it does not check that signer against any allowlist. Since anyone can generate an ECDSA keypair and self-sign a message, this "validation" authenticates *a* sender, not an *authorized* sender. [2](#0-1) 

`HandleLegacyUserMessage` then dispatches the request to every member of the DON with only a stale-timestamp and method-name check — the allowlist/rate-limit gap is called out directly in the code: [3](#0-2) 

This is the same bug class as the Yggdrasil advisory: a broker-style dispatch entry point (`don.SendToNode` fan-out to all DON members) that forwards a caller-controlled request to privileged worker processes (capability/workflow nodes) without checking whether the caller is authorized to invoke that action.

By contrast, the newer v2 HTTP trigger path performs a real authorization check before dispatch, via `workflowMetadataHandler.Authorize(workflowID, req.Auth, req)`: [4](#0-3) 

confirming that the legacy path's lack of an equivalent check is a regression/gap rather than an intentional design choice.

### Impact Explanation
An unprivileged, unauthenticated internet client can submit a self-signed `MethodWebAPITrigger` legacy message to the Gateway's HTTP endpoint. The Gateway will forward this request to **every node** of the target DON as a trigger invocation, without verifying that the caller is the workflow owner, has been allowlisted, or is otherwise entitled to trigger that workflow. This can result in unauthorized job/workflow execution across the entire DON — matching the "unauthorized job run" impact category — and can be used to flood/DOS the DON's nodes since no per-sender rate limiting or allowlist gate exists on this path either (the `TODO` covers both).

### Likelihood Explanation
High. The legacy handler is reachable directly from the internet-facing Gateway HTTP endpoint; the only barrier is a syntactically valid signature over an arbitrary payload, which any caller can produce with a throwaway keypair. No workflow-ownership or DON-membership check gates the dispatch.

### Recommendation
Add allowlist/authorization enforcement (and rate limiting) to `HandleLegacyUserMessage` equivalent to the check already performed in the v2 path (`workflowMetadataHandler.Authorize`), verifying that `msg.Body.Sender` (recovered signer) is authorized for the target workflow/DON before calling `don.SendToNode`. Alternatively, deprecate/disable the legacy path in production Gateway deployments if it is no longer required, since a hardened v2 equivalent already exists.

### Proof of Concept
1. Generate an arbitrary ECDSA keypair (no registration required).
2. Construct an `api.Message` with `Body.Method = "web_api_trigger"`, a valid `Body.DonID`, a fresh `Body.MessageID`, and a `TriggerRequestPayload` with `Timestamp = now`.
3. Sign it with the throwaway key via `Message.Sign`.
4. POST the encoded JSON-RPC legacy request to the Gateway's HTTP endpoint (`gateway.ProcessRequest`).
5. Observe that `msg.Validate()` succeeds (valid signature format/length) and `HandleLegacyUserMessage` forwards the trigger request to every member node of the target DON via `don.SendToNode`, with no check that the throwaway key's address is an authorized workflow owner.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageID) == 0 || len(m.Body.MessageID) > MessageIDMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageID, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonID) == 0 || len(m.Body.DonID) > MessageDonIDMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonID, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

func (h *httpTriggerHandler) authorizeRequest(ctx context.Context, workflowID string, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback) (*gateway_common.AuthorizedKey, error) {
	h.lggr.Debugw("authorizing request", "workflowID", workflowID, "requestID", req.ID)
	key, err := h.workflowMetadataHandler.Authorize(workflowID, req.Auth, req)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInvalidRequest, "Auth failure: "+err.Error(), callback)
		return nil, errors.Join(errors.New("auth failure"), err)
	}
	return key, nil
}
