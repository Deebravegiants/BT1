The reported bug class is specific to `RedstoneCoreOracle`'s price-caching mechanism, where a cached price (`cachedPrice`/`cacheUpdatedAt`) can be overwritten by a signed price with an *older* observation timestamp than the one currently cached, because the contract compares against `block.timestamp` rather than the previous price's own timestamp.

alt.fun's contracts have no equivalent caching layer for the LT exchange rate. `Bonding.canGraduate` and `previewLtUntilGraduation` call `IBounceLeveragedToken(info.ltAddress).exchangeRate()` live on every invocation [1](#0-0) [2](#0-1) , and `Zap._executeBuy` likewise reads `baseToLtAmount`/`ltToBaseAmount` fresh on the current LT state rather than a stored, staleness-gated cache [3](#0-2) . There is no `cachedPrice`/`cacheUpdatedAt`-style state anywhere in `packages/contracts/src` — confirmed by grep across the source tree, which only turns up two unrelated hits in `Bonding.sol` (its own docstring comments, not any oracle-caching code). Since there is no persisted "last observed price" that a newer-but-actually-older signed timestamp could displace, the root-cause mechanism of the report (accepting a stale-relative-to-current-cache price because the comparison is against `block.timestamp` instead of the cached observation timestamp) has no reachable analog in this codebase's bonding-curve/graduation/exchange-rate logic.
