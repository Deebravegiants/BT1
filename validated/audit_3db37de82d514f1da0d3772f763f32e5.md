### Title
Uncontrolled Resource Consumption via unbounded, fee-free consensus proof verification in `pallet_ismp::handle_unsigned` - (File: modules/pallets/ismp/src/lib.rs)

### Summary
The Tendermint CVE describes a client that performs expensive processing (gzip decompression) on attacker-controlled data before any size/cost bound is enforced. Hyperbridge's `pallet-ismp` has an analogous pattern: `handle_unsigned` is dispatched as an **unsigned, fee-free** extrinsic, and its `ValidateUnsigned::validate_unsigned` hook runs the *entire* consensus/message verification pipeline (`Self::execute(messages.clone())`) on every node's transaction-pool validation path, before any weight/fee is charged and with no explicit cap on the number of messages or the size of embedded consensus proofs (e.g. Tendermint validator sets, BSC epoch validator lists).

### Finding Description
`validate_unsigned` for `pallet_ismp::Call::handle_unsigned` calls `Self::execute(messages.clone())` directly to determine transaction validity: [1](#0-0) 

`execute` iterates every message and invokes `handle_incoming_message`, which for `Message::Consensus` performs full light-client verification (signature checks over the entire validator/signer set) via `ConsensusClient::verify_consensus`: [2](#0-1) 

For the Tendermint consensus client, this path decodes an attacker-supplied `TendermintConsensusUpdate` and runs `verify_header_update`, which validates a `Vec<Validator>`/commit-signature set of unbounded size (no `MAX_VALIDATORS`-style cap exists in `modules/consensus/tendermint/**`, unlike the Pharos verifier which explicitly enforces `MAX_VALIDATORS`): [3](#0-2) [4](#0-3) 

By contrast, the `pallet-call-decompressor` had this exact class of bug and it was explicitly fixed: `validate_unsigned` there now enforces a size gate (`ensure!(encoded_call_size < T::MaxCallSize::get() * ONE_MB, ...)`) at the single choke point *before* any expansion/decoding work, specifically because "the unsigned `validate_unsigned` mempool path called `decompress` directly with no bound, so a fee-less attacker could ... have a tiny zstd 'bomb' expanded to gigabytes during transaction-pool validation, before any size check": [5](#0-4) 

`pallet-ismp`'s own `handle_unsigned` has no equivalent gate: there is no limit on `messages: Vec<Message>` length, and no limit on the number of validators/signatures a single embedded consensus proof can carry (the only implicit bound is the runtime's generic max-extrinsic-length, which still permits many thousands of small validator entries to be packed into one extrinsic). [6](#0-5) 

### Impact Explanation
Because `handle_unsigned` messages are unsigned and fee-free by design ("execute the provided batch of ISMP messages for free"), and because the transaction-pool validity check performs the *same* full cryptographic verification work as actual dispatch, an attacker can flood the network with maximal-size extrinsics packed with worst-case validator/signature counts (or many `Message::Consensus` entries in one batch). Every full node that receives the gossiped transaction must perform this expensive signature verification during mempool validation for free, repeatedly, before the transaction is even included in a block — this is uncontrolled resource consumption (CWE-400) that can degrade or deny relayer/mempool availability across the network, directly mirroring the CVE's root cause (expensive decode/processing performed before any resource-cost bound).

### Likelihood Explanation
`handle_unsigned` is explicitly designed to be reachable by any unprivileged relayer/party without a fee — this is the pallet's intended free-message-delivery mechanism, so the attack requires no special privilege. The only friction is the runtime's overall extrinsic-length limit and transaction-pool longevity/priority rules, neither of which cap the computational cost of the consensus proof itself.

### Recommendation
Add an explicit bound (mirroring the fix already applied in `pallet-call-decompressor`) at the `validate_unsigned` choke point for `pallet_ismp::Call::handle_unsigned`:
- Cap `messages.len()` per batch.
- Cap the number of validators/signatures accepted inside a single consensus proof for each supported consensus client (Tendermint, BSC, etc.), similar to Pharos's `MAX_VALIDATORS` check, and reject oversized proofs before invoking `verify_consensus`.

### Proof of Concept
Not verifiable without a live network/runtime to measure actual CPU cost per validator entry; this analysis is based on static code review only (no PoC executed). The reachable path is confirmed statically: `handle_unsigned` → `validate_unsigned` → `Self::execute` → `handle_incoming_message` → `TendermintClient::verify_consensus` → `verify_header_update`, with no size gate at any point in that chain, contrasted with the explicit gate present in the analogous `pallet-call-decompressor` fix.

	pub fn execute(messages: Vec<Message>) -> Result<Vec<events::Event>, Error<T>> {
		let host = Pallet::<T>::default();

		let message_results = messages
			.iter()
			.map(|msg| handle_incoming_message(&host, msg.clone()))
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

pub fn verify_header_update(
	trusted_state: TrustedState,
	consensus_proof: ConsensusProof,
	current_time: u64,
) -> Result<UpdatedTrustedState, VerificationError> {
	consensus_proof.validate().map_err(|e| VerificationError::Invalid(e))?;

	let chain_id = Id::try_from(trusted_state.chain_id.clone())
		.map_err(|e| VerificationError::Invalid(e.to_string()))?;
	let height = Height::try_from(trusted_state.height)
		.map_err(|e| VerificationError::Invalid(e.to_string()))?;
	let timestamp = Timestamp { seconds: trusted_state.timestamp as i64, nanos: 0 };
	let time = Time::try_from(timestamp).map_err(|e| VerificationError::Invalid(e.to_string()))?;
	let next_validators = ValidatorSet::new(trusted_state.next_validators.clone(), None);
	let next_validators_hash = Hash::Sha256(trusted_state.next_validators_hash);

	let tendermint_trusted_state = TrustedBlockState {
		chain_id: &chain_id,
		header_time: time,
		height,
		next_validators: &next_validators,
		next_validators_hash,
	};

	let validators = extract_validators(&trusted_state, &consensus_proof)?;
	let next_validators = consensus_proof
		.next_validators
		.as_ref()
		.map(|validators| ValidatorSet::new(validators.clone(), None));

	let untrusted_block_state = UntrustedBlockState {
		signed_header: &consensus_proof.signed_header,
		validators: &validators,
		next_validators: next_validators.as_ref(),
	};

	let verifier_options = convert_verification_options(
		&trusted_state.verification_options,
		trusted_state.trusting_period_duration(),
	)?;
	let now = convert_timestamp(current_time)?;

	let verifier = SpIoVerifier::default();
	let result = verifier.verify_update_header(
		untrusted_block_state,
		tendermint_trusted_state,
		&verifier_options,
		now,
	);

	pub fn decompress(
		compressed_bytes: Vec<u8>,
		encoded_call_size: u32,
	) -> Result<Vec<u8>, DispatchError> {
		// Bound the claimed decompressed size against the configured maximum here,
		// at the single choke point every caller flows through. Previously this
		// gate lived only in `decompress_call` (the dispatch path); the unsigned
		// `validate_unsigned` mempool path called `decompress` directly with no
		// bound, so a fee-less attacker could claim `encoded_call_size = u32::MAX`
		// and have a tiny zstd "bomb" expanded to gigabytes during transaction-pool
		// validation, before any size check. Enforcing it here protects both paths.
		ensure!(encoded_call_size < T::MaxCallSize::get() * ONE_MB, Error::<T>::CallSizeOutOfBound);

		let mut decoder = StreamingDecoder::new(compressed_bytes.as_slice())
			.map_err(|_| Error::<T>::DecompressionFailed)?;

		let claimed = encoded_call_size as usize;
		let mut result = Vec::new();
		let mut chunk = vec![0u8; 4096];

		loop {
			let n = decoder.read(&mut chunk).map_err(|_| Error::<T>::DecompressionFailed)?;
			if n == 0 {
				break;
			}
			if result.len() + n > claimed {
				return Err(Error::<T>::DecompressionFailed.into());
			}
			result.extend_from_slice(&chunk[..n]);
		}

		ensure!(result.len() == claimed, Error::<T>::DecompressionFailed);

		Ok(result)
	}
