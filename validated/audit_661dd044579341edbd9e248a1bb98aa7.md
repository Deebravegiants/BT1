### Title
Permissionless `force_socialize_bad_debt` crystallizes a permanent supplier write-down the instant debt exceeds collateral - (File: contracts/controller/src/positions/liquidation/mod.rs)

### Summary
The bug class of the reference report is an unsynchronized read of a shared value that can change under the reader. The analog here is an unsynchronized *act* on shared state: `process_force_socialize_bad_debt` lets any address force-inspect an account's debt-vs-collateral snapshot and permanently socialize the deficit into the supply index, with no authorization and no dust bound.

### Finding Description
`socialize_bad_debt` defines two admission gates: `DustCapped` (permissionless, used by `clean_bad_debt`) and `InsolventOnly`, documented as "Owner-only: insolvent alone, with no cap on the collateral left behind" (`mod.rs:203-209`). However, `process_force_socialize_bad_debt` performs only `require_not_flash_loaning` and then calls `socialize_bad_debt(env, account_id, BadDebtGate::InsolventOnly)` — there is no `require_auth`, no owner check, and no delegate check anywhere in the function (`mod.rs:245-248`). Any address can therefore invoke the owner-only gate on any account.

Unlike `clean_bad_debt` — which additionally requires remaining collateral to be at or below the dust threshold via `is_socializable_bad_debt` (`mod.rs:230-232`) — the `InsolventOnly` gate admits any account the moment `total_debt > total_collateral`, regardless of how much collateral remains. `bad_debt::execute_bad_debt_cleanup` then writes the deficit down into the market's supply index, imposing a permanent loss on every supplier of that hub/asset market.

### Impact Explanation
An unprivileged caller can snapshot an account at a moment when prices (read fresh through the `Context`-cached strict price path) transiently make it insolvent — e.g., a liquidation partially executed, or an intra-block price dip within the sanity band — and force the write-down immediately. The socialization is irreversible: supplier share value is reduced permanently, even if collateral prices recover in the next ledger. Remaining collateral (which could later cover the debt again) is released/socialized against the debt now. This is a permanent loss of supplier funds / premature realization of protocol insolvency, triggered by an address with no stake in the account, bypassing the dust cap that was explicitly designed as the permissionless safety bound.

### Likelihood Explanation
Reachability requires only a signed caller and an account that is instantaneously insolvent — a condition that occurs routinely around liquidations and during volatile price updates. The test harness confirms the endpoint is called with no caller argument at all (`tests/test-harness/src/keeper.rs:42-44`), consistent with the missing authorization. No timing race is needed on-chain; a single transaction suffices.

### Recommendation
Enforce the documented "Owner-only" semantics: require `require_owner_or_delegate(env, account_id, caller, &account.owner)` (or `account.owner.require_auth()`) inside `process_force_socialize_bad_debt` before invoking `socialize_bad_debt` with `BadDebtGate::InsolventOnly`. Alternatively, if the intent is permissionless uncapped socialization, correct the `BadDebtGate` documentation and add an integration test asserting that behavior — but the dust cap exists precisely to prevent outsiders from crystallizing large write-downs, so owner-gating is the safer fix.

### Proof of Concept
1. Alice supplies USDC and borrows ETH; Bob supplies USDC (the market that will absorb the loss).
2. A partial liquidation or a within-band downward price move leaves Alice's account with `total_debt > total_collateral` but substantial remaining collateral (well above the dust threshold), so `clean_bad_debt` correctly rejects it.
3. Carol (unrelated attacker) calls `controller.force_socialize_bad_debt(alice_account_id)`. No auth on Alice's owner is required — only the flash-loan guard is checked.
4. `execute_bad_debt_cleanup` writes the full deficit into the USDC supply index; Bob's and all other suppliers' shares are permanently devalued, and Alice's remaining collateral is consumed — outcomes that would have been avoided had the price recovered or normal liquidation completed first. /// Admission condition for bad-debt socialization.
#[derive(Clone, Copy, PartialEq)]
enum BadDebtGate {
    /// Permissionless: insolvent *and* collateral at or below the dust threshold.
    DustCapped,
    /// Owner-only: insolvent alone, with no cap on the collateral left behind.
    InsolventOnly,
}

/// Requires open debt and the selected insolvency gate, then cleans up the account.
fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    bad_debt::execute_bad_debt_cleanup(env, &mut cache, account_id, &account, &totals);
}

/// Socializes insolvent debt when remaining collateral is at or below the dust cap.
pub(crate) fn clean_bad_debt_standalone(env: &Env, account_id: u64) {
    socialize_bad_debt(env, account_id, BadDebtGate::DustCapped);
}

/// Socializes debt exceeding collateral without a dust cap, outside flash loans.
pub(crate) fn process_force_socialize_bad_debt(env: &Env, account_id: u64) {
    validation::require_not_flash_loaning(env);
    socialize_bad_debt(env, account_id, BadDebtGate::InsolventOnly);
