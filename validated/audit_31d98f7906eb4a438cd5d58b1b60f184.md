Analog confirmed. `SimplexPaymaster.sol` is deployed on Arbitrum mainnet and prices gas sponsorship purely from Chainlink `latestRoundData()`, with no check of the Arbitrum L2 sequencer uptime feed.

### Title
Missing Arbitrum sequencer-uptime check in `SimplexPaymaster._getOraclePrice` allows stale/wrong Chainlink prices to mis-price gas sponsorship - (File: evm/src/utils/SimplexPaymaster.sol)

### Summary
`SimplexPaymaster` is a permissionless ERC-4337 paymaster deployed on Arbitrum mainnet (`SimplexPaymaster: 0x7281Bccb4f0BCE44F3B8542d1fC5e51c2F5fC08C`) that converts gas cost to ERC-20 stablecoin amount using two Chainlink `AggregatorV3Interface` feeds (native/USD and token/USD). [1](#0-0) 
Its `_getOraclePrice` helper only validates that the answer is positive and not older than `maxOracleAge`; it never checks the Arbitrum L2 sequencer uptime feed, contrary to Chainlink's recommendation for L2 price consumers.

### Finding Description
`_getOraclePrice` reads `latestRoundData()` and reverts only on a non-positive answer or on staleness measured against `block.timestamp`: [2](#0-1) 
`_tokenPrice` calls this twice (native oracle and token oracle) to build the price used both for validation-time pricing (`fetchDetails`/`validate`, via `PaymasterERC20`) and for `getTokenPrice`/`estimateTokenCost`: [3](#0-2) 
No `AggregatorV2V3Interface`/`FlagsInterface` or the canonical `0xFdB631F5EE196F0ed6FAa767959853A9F217697D` Arbitrum Sequencer Uptime Feed is referenced anywhere in the contract, the deployment script, or the fork tests: [4](#0-3) 
When Arbitrum's sequencer is down, transactions still land once the sequencer restarts or via the L1 delayed inbox, but the Chainlink feed's `updatedAt` can remain within `maxOracleAge`'s window while the underlying price is no longer being refreshed at the intended heartbeat, or a stale round can be replayed once the sequencer restarts. `_getOraclePrice`'s check does not distinguish "fresh because the sequencer is healthy" from "fresh because the check itself is measured against an L2 clock that was not advancing reliably," so a stale/incorrect price can pass validation.

### Impact Explanation
This price feeds directly into how many ERC-20 stablecoin units a solver or user is charged for gas via `_tokenPrice`, consumed by `fetchDetails`/`validate`/`_postOp` in the ERC-4337 flow, and is also the price solvers rely on when submitting intent-fill bids that use Simplex for gas sponsorship (`prepareBidUserOp` → `buildPaymasterAndData`): [5](#0-4) 
A stale/incorrect price during an Arbitrum sequencer outage can under-charge the token amount relative to the real gas cost the paymaster pays out of its EntryPoint deposit — a direct loss of paymaster treasury funds to whoever submits an operation during the mispriced window — or over-charge users, forcing them to pay a distorted amount. Because `SimplexPaymaster` is permissionless (any UserOperation sender can trigger pricing) and holds a shared EntryPoint deposit funding all sponsored operations, this is a fund-drain vector on the paymaster's deposit reachable by any unprivileged actor, including an intent solver.

### Likelihood Explanation
Requires an Arbitrum sequencer outage or a delayed-inbox/replay window coincident with stale Chainlink data — an infrequent but real, externally-triggerable condition (has occurred historically on Arbitrum). During such a window, any unprivileged sender (including solvers pursuing intents) can submit a `PackedUserOperation` priced off the stale feed with no additional privilege required, so likelihood is low-to-medium and impact is concrete fund loss, consistent with a Medium-severity finding.

### Recommendation
Add an Arbitrum Sequencer Uptime Feed check to `_getOraclePrice` (or to `_tokenPrice`), following Chainlink's L2 guidance: read `latestRoundData()` from the sequencer uptime feed, revert if `answer == 1` (down) or if `block.timestamp - startedAt` is within a grace period (e.g. 1 hour) after the sequencer came back up, before trusting `nativeOracle`/`tokenOracle` data. Make the sequencer feed address a governance-configurable parameter (empty/zero on chains without one, e.g. BSC) analogous to `nativeOracle`/`tokenConfigs`.

### Proof of Concept
1. Arbitrum sequencer goes down; L2 block production and Chainlink OCR reporting on Arbitrum stall or become unreliable, while some cached round's `updatedAt` still satisfies `block.timestamp - updatedAt <= maxOracleAge` (or the L2 clock itself is not advancing during the outage window, masking real staleness).
2. Once transactions can land again (sequencer restart or forced-inclusion via the L1 delayed inbox), a solver or user submits a `PackedUserOperation` with `SimplexPaymaster` as paymaster.
3. `fetchDetails`/`validate` call `_tokenPrice` → `_getOraclePrice`, which reads the same stale/incorrect round and returns a price that no longer reflects the true native/token exchange rate. [6](#0-5) 
4. `PaymasterERC20`'s `_postOp` charges the sender the mispriced token amount while the paymaster's EntryPoint deposit pays the real ETH gas cost, letting an attacker who times operations to this window extract value from the shared deposit or the treasury markup.

    function _tokenPrice(TokenConfig memory cfg) internal view returns (uint256) {
        uint256 nativeUsd = _getOraclePrice(nativeOracle, nativeOracleDecimals);
        uint256 tokenUsd = _getOraclePrice(cfg.tokenOracle, cfg.tokenOracleDecimals);

        return (nativeUsd * (10 ** cfg.tokenDecimals) * (10_000 + markupBps)) / (tokenUsd * 10_000);
    }

    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
