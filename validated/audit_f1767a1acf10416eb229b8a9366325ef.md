### Title
Unbounded RAY debt-value multiplication permanently freezes an oversized market - ([File: common/src/rates/index.rs])

### Summary
`calculate_supplier_rewards` multiplies total scaled debt by both the old and new borrow indexes using `Ray::mul`. If `borrowed * borrow_index / RAY` exceeds `i128::MAX`, the checked multiplication panics with `MathOverflow` before the borrow-index cap can protect the market. Because every market operation accrues interest first, all repayments, withdrawals, liquidations, and subsequent index updates on that market remain bricked.

### Finding Description
`global_sync` calls `accrue_chunk` for each elapsed interval before any requested pool mutation proceeds. `accrue_chunk` delegates the arithmetic to `accrue_step`, which computes `calculate_supplier_rewards(borrowed, new_borrow_index, old_borrow_index)`. [1](#0-0) [2](#0-1) 

Inside `calculate_supplier_rewards`, both `borrowed.mul(old_borrow_index)` and `borrowed.mul(new_borrow_index)` must fit in `i128`. Once scaled debt is approximately `1e36` RAY, an index above roughly `170 * RAY` makes this multiplication unrepresentable and reverts. The fixed `MAX_BORROW_INDEX_RAY` is `1e9 * RAY`, so it cannot prevent this smaller, debt-dependent ceiling. [3](#0-2) [4](#0-3) 

This is reachable through the permissionless controller `borrow`, `repay`, `withdraw`, `liquidate`, and `update_indexes` surfaces; the corresponding pool entrypoints execute `global_sync` before mutating state. [5](#0-4) [6](#0-5) [7](#0-6) 

The repository already contains a deterministic demonstration: a one-billion-token, 18-decimal market at 98% utilization eventually causes `update_indexes` to fail with `MathOverflow`; the same panic then rejects both withdrawal and repayment while `borrow_index` remains below its configured cap. [8](#0-7) 

### Impact Explanation
This permanently freezes the affected market. Suppliers cannot withdraw, borrowers cannot repay, liquidators cannot clear the account, and keepers cannot advance the indexes because each path repeats the same overflowing accrual before reaching its recovery or exit logic. Since the panic is atomic, no later call can move the market past the overflowing state.

The affected funds are not merely temporarily unavailable: debt shares and index state never decrease, so every future accrual attempts the same unrepresentable multiplication. Direct token transfers to the pool do not repair the scaled-debt arithmetic.

### Likelihood Explanation
The trigger requires an exceptionally large market balance, sustained high utilization, and enough elapsed accrual for the index to exceed the market-specific `i128 / borrowed` ceiling. A single unprivileged borrower can create the final condition by borrowing most of an already-funded market and later invoking `update_indexes`; no privileged call, oracle manipulation, leaked key, or malformed dependency is needed.

The economic prerequisite substantially lowers practical likelihood, but the affected code path is reachable with otherwise valid governance-listed parameters and ordinary user calls.

### Recommendation
Enforce a dynamic representability bound before multiplying market totals by an index. For a nonzero `borrowed` balance, derive the largest safe index as `min(MAX_BORROW_INDEX_RAY, floor(i128::MAX / borrowed))` and clamp accrual at that bound before `calculate_supplier_rewards` is called. Apply the equivalent bound to supplied-value calculations, or use a wider internal representation for totals and only downscale results after proving they fit `i128`.

Prefer stopping borrower interest at the dynamic ceiling over panicking: a capped index preserves repayment, withdrawal, liquidation, and bad-debt cleanup paths. Add regression coverage for a market whose scaled debt is large enough that `borrowed * next_index` would overflow.

### Proof of Concept
1. Governance lists an 18-decimal asset and a separate collateral market with permissive caps and utilization.
2. Victim suppliers deposit `1_000_000_000 * 10^18` base units of the 18-decimal asset, producing approximately `1e36` scaled RAY supply.
3. An attacker supplies sufficient collateral and calls:
   ```rust
   controller.borrow(
       attacker,
       account_id,
       vec![env, (target_hub_asset, 980_000_000 * 10i128.pow(18))],
       None,
   );
   ```
4. Time advances while the market remains near high utilization. Once `borrow_index` exceeds approximately `170 * RAY`, call:
   ```rust
   controller.update_indexes(vec![env, target_hub_asset]);
   ```
5. The call reaches `calculate_supplier_rewards`, where `borrowed.mul(new_borrow_index)` exceeds `i128::MAX` and raises `MathOverflow`.
6. Subsequent `repay`, `withdraw`, `liquidate`, and `update_indexes` calls repeat accrual and fail identically, permanently freezing the market.

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
