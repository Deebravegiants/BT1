Audit Report

## Title
LDAP Authentication Bypass via Unauthenticated (Empty-Password) Simple Bind - (File: `core/sessions/ldapauth/ldap.go`)

## Summary
`ldapAuthenticator.CreateSession` and `ldapAuthenticator.TestPassword` in `core/sessions/ldapauth/ldap.go` pass the attacker-controlled `SessionRequest.Password` (or `password` parameter) directly to `conn.Bind()` with no check that it is non-empty. [1](#0-0) [2](#0-1)  Per RFC 4513 §5.1.2, a simple bind with a zero-length password is defined as an "unauthenticated bind," which many LDAP servers report as success without validating the identity, and chainlink treats any `err == nil` from `Bind` as a fully authenticated login.

## Finding Description
`CreateSession` is reachable from the unauthenticated `/sessions` login endpoint, which binds the raw JSON body (including an empty-string `password`) into `sessions.SessionRequest` via `ShouldBindJSON` with no non-empty validation. [3](#0-2)  It then calls `AuthenticationProvider().CreateSession(ctx, sr)`, which for LDAP-configured nodes routes to `ldapAuthenticator.CreateSession`. That function builds the bind DN from the attacker-supplied, lower-cased, filter-escaped email and calls `conn.Bind(searchBaseDN, sr.Password)` without ever checking `sr.Password != ""`. [4](#0-3)  If the bind returns `err == nil`, the code proceeds to call `l.FindUser`, obtains the target user's mapped role, and inserts a new row into `ldap_sessions`, returning a valid session ID/cookie for that user's role. [5](#0-4)  The identical unguarded pattern exists in `TestPassword`. [6](#0-5)  `CreateEphemeralConnection` (in `core/sessions/ldapauth/client.go`) only performs the node's own service-account bind for search purposes and does nothing to constrain how the later per-user `Bind` call behaves with an empty password. [7](#0-6)  No password-complexity or non-empty check (`core/utils/password.go`) is invoked anywhere on this login path — that check is only used on password creation/change flows. This confirms the reported root cause: the application-layer code contains no defense-in-depth rejection of empty passwords before delegating trust entirely to the directory server's bind semantics.

## Impact Explanation
If the configured upstream LDAP/AD directory permits unauthenticated binds for the target DN (the RFC-default behavior absent explicit hardening), an attacker who knows or guesses a valid account email (e.g., an admin's) can obtain a fully authenticated chainlink session with that user's mapped RBAC role — a genuine node API authentication/role bypass, matching an in-scope Chainlink impact class. This is a full authentication bypass reachable directly from the public `/sessions` endpoint with no privileged access required. However, the actual bypass is only realized if the upstream directory server treats the zero-length-password bind as success; this depends on external directory-server bind policy that chainlink does not control, though the application itself provides no independent safeguard.

## Likelihood Explanation
An unprivileged remote attacker can trigger the vulnerable code path with a single unauthenticated HTTP POST to `/sessions` supplying any candidate email and an empty password string — no credentials, roles, or prior access are required to reach `ldapAuthenticator.CreateSession`. Exploitation success is gated on the upstream directory's bind configuration (many real-world OpenLDAP/AD deployments still allow unauthenticated binds unless explicitly hardened), making likelihood realistic but conditional and not fully within chainlink's control. The missing empty-password guard is nonetheless a concrete, reviewable, and fixable code defect independent of that external factor.

## Recommendation
Add an explicit rejection of empty (or whitespace-only) passwords at the top of both `ldapAuthenticator.CreateSession` and `ldapAuthenticator.TestPassword` in `core/sessions/ldapauth/ldap.go`, before any call to `conn.Bind`, e.g.:
```go
if strings.TrimSpace(sr.Password) == "" {
    return "", errors.New("password must not be empty")
}
```
This removes reliance on the upstream directory server's anonymous/unauthenticated bind policy and closes the RFC 4513 unauthenticated-bind class of bypass regardless of server configuration.

## Proof of Concept
1. Configure a chainlink node with LDAP auth (`ldapAuthenticator`) pointed at a directory that permits unauthenticated binds for the relevant DN.
2. Send `POST /sessions` with body `{"email": "admin@example.com", "password": ""}`.
3. `ldapAuthenticator.CreateSession` calls `conn.Bind("<baseUserAttr>=admin@example.com,<usersDN>,<baseDN>", "")`.
4. If the directory returns `err == nil` (unauthenticated bind success), the code proceeds to `FindUser`, inserts an `ldap_sessions` row, and returns a valid session ID — granting the caller the admin's mapped role without knowledge of the real password.
5. A Go unit test can mock `LDAPConn.Bind` to return `nil` for an empty-password call and assert that `CreateSession` currently returns a valid session ID, demonstrating the missing guard.

func (l *ldapAuthenticator) CreateSession(ctx context.Context, sr sessions.SessionRequest) (string, error) {
	conn, err := l.ldapClient.CreateEphemeralConnection()
	if err != nil {
		return "", errors.New("unable to establish connection to LDAP server with provided URL and credentials")
	}
	defer conn.Close()

	var returnErr error

	// Attempt to LDAP Bind with user provided credentials
	escapedEmail := ldap.EscapeFilter(strings.ToLower(sr.Email))
	searchBaseDN := fmt.Sprintf("%s=%s,%s,%s", l.config.BaseUserAttr(), escapedEmail, l.config.UsersDN(), l.config.BaseDN())
	if err = conn.Bind(searchBaseDN, sr.Password); err != nil {
		l.lggr.Infof("Error binding user authentication request in LDAP Bind: %v", err)
		returnErr = errors.New("unable to log in with LDAP server. Check credentials")
	}

// CreateEphemeralConnection returns a valid, active LDAP connection for upstream Search and Bind queries
func (l *ldapClient) CreateEphemeralConnection() (LDAPConn, error) {
	conn, err := ldap.DialURL(l.config.ServerAddress())
	if err != nil {
		return nil, fmt.Errorf("failed to Dial LDAP Server: %w", err)
	}
	// Root level root user auth with credentials provided from config
	bindStr := l.config.BaseUserAttr() + "=" + l.config.ReadOnlyUserLogin() + "," + l.config.BaseDN()
	if err := conn.Bind(bindStr, l.config.ReadOnlyUserPass()); err != nil {
		return nil, fmt.Errorf("unable to login as initial root LDAP user: %w", err)
	}
	return conn, nil
}
