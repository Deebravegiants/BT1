### Title
Unchecked U128→u64 Truncation in `swap_in_after_add_fee` Allows Pool Drain via `SwapBaseOut` / `SwapBaseOutV2` - ([File: program/src/processor.rs])

### Summary
`process_swap_base_out` and `process_swap_base_out_v2` compute the required input amount (`swap_in_after_add_fee`) as a `U128` value and then downcast it to `u64` with `.as_u64()` without any bounds check. `U128`/`U256` in this codebase are custom types created via `uint::construct_uint!`, whose `as_u64()` method silently truncates to the low 64 bits instead of panicking or erroring on overflow — the exact "unguarded downcast" bug class described in the reference report (`uint112(shares)` in DODO's GSP), just applied to `U128 -> u64` instead of `uint256 -> uint112`.

### Finding Description
In `process_swap_base_out`: [1](#0-0) 

```rust
let swap_in_before_add_fee = Calculator::swap_token_amount_base_out(
    swap.amount_out.into(),
    total_pc_without_take_pnl.into(),
    total_coin_without_take_pnl.into(),
    swap_direction,
);
let swap_in_after_add_fee = swap_in_before_add_fee
    .checked_mul(amm.fees.swap_fee_denominator.into())
    .unwrap()
    .checked_ceil_div(...)
    .unwrap()
    .as_u64();
```

`Calculator::swap_token_amount_base_out` (in `program/src/math.rs`) computes, for `Coin2PC`:
`swap_in_before_add_fee = coin * amount_out / (pc - amount_out)` (ceil-div), all in `U128` arithmetic: [2](#0-1) 

Because `coin` (`total_coin_without_take_pnl`), `amount_out`, and `pc` are all `u64`, and `U128::MAX` (~3.4e38) is far larger than the maximum possible numerator (`u64::MAX * u64::MAX` ≈ 3.4e38), all `checked_mul`/`checked_ceil_div` calls succeed (no panic) even when the mathematical result vastly exceeds `u64::MAX` (~1.8e19). The subsequent `.as_u64()` call then truncates this oversized `U128` result to its low 64 bits with no error — the resulting `swap_in_after_add_fee` becomes an arbitrary, attacker-influenceable small value rather than the true required input.

Crucially, the check that would normally bound `amount_out` away from the pool's reserve — `if swap.amount_out >= total_pc_without_take_pnl { return Err(...) }` — is only performed *after* `swap_in_after_add_fee` has already been computed and used for the slippage/funds checks: [3](#0-2) 

This lets an attacker choose `swap.amount_out = total_pc_without_take_pnl - 1` (still passing the final check while making the division denominator `pc - amount_out = 1`), which maximizes `swap_in_before_add_fee ≈ coin * amount_out`, comfortably overflowing `u64` while remaining within `U128` bounds, so the arithmetic never panics — it just truncates silently at the final `.as_u64()`.

`process_swap_base_out_v2` contains the identical pattern: [4](#0-3) 

### Impact Explanation
By choosing `amount_out` to make the true (untruncated) required input overflow `u64`, an attacker can make `swap_in_after_add_fee` collapse to an arbitrarily small, attacker-controllable `u64` value (via brute-forcing/selecting `amount_out` so the low 64 bits of the true U128 result land at a value ≤ `user_source.amount` and ≤ `swap.max_amount_in`), while still receiving `swap.amount_out` — an amount close to the entire pool reserve of the output token — via `Invokers::token_transfer_with_authority`. This is a direct, permissionless drain of pool/LP funds: the attacker pays a negligible input while the AMM's vault pays out almost its full balance of the other token, producing an insolvent pool and permanent loss of LP/user funds.

### Likelihood Explanation
This is reachable by any unprivileged user in a single transaction to the permissionless `SwapBaseOut`/`SwapBaseOutV2` instructions, using fully attacker-chosen `amount_out` and standard token accounts — no privileged signer, no off-chain component, and no reliance on validator or SPL-token-program bugs. The only requirement is picking `amount_out` close to (but below) the pool's current reserve of the requested token, which is public, on-chain state readable at transaction-build time.

### Recommendation
Replace the raw `.as_u64()` downcast with a checked conversion (e.g., `Calculator::to_u64` which uses `try_into` and returns `AmmError::ConversionFailure` on overflow) for `swap_in_after_add_fee` in both `process_swap_base_out` and `process_swap_base_out_v2`. Additionally, move the `swap.amount_out >= total_pc_without_take_pnl` / `total_coin_without_take_pnl` bounds check to occur *before* computing `swap_in_before_add_fee`/`swap_in_after_add_fee`, so the denominator can never be driven arbitrarily close to zero.

### Proof of Concept
1. Attacker reads current `amm_pc_vault.amount` / `amm_coin_vault.amount` to derive `total_pc_without_take_pnl` and `total_coin_without_take_pnl`.
2. Attacker submits `SwapBaseOut` (or `SwapBaseOutV2`) with `swap_direction = Coin2PC` and `amount_out = total_pc_without_take_pnl - 1`.
3. `swap_token_amount_base_out` computes `swap_in_before_add_fee = total_coin_without_take_pnl * amount_out / 1`, a value on the order of `u64::MAX^2`, which fits in `U128` (so `checked_mul`/`checked_ceil_div` never panic).
4. `swap_in_after_add_fee = swap_in_before_add_fee * swap_fee_denominator / (swap_fee_denominator - swap_fee_numerator)` remains far larger than `u64::MAX`, and `.as_u64()` truncates it to an attacker-predictable small `u64`.
5. The truncated `swap_in_after_add_fee` passes the `user_source.amount < swap_in_after_add_fee` and `swap.max_amount_in < swap_in_after_add_fee` checks trivially (attacker sets `max_amount_in` accordingly), and the final `swap.amount_out >= total_pc_without_take_pnl` check passes since `amount_out = total_pc_without_take_pnl - 1`.
6. The program transfers only the tiny truncated `swap_in_after_add_fee` from the attacker into `amm_coin_vault`, then transfers `swap.amount_out` (≈ the entire pc reserve) from `amm_pc_vault` to the attacker, draining the pool.

```rust
    pub fn swap_token_amount_base_out(
        amount_out: U128,
        total_pc_without_take_pnl: U128,
        total_coin_without_take_pnl: U128,
        swap_direction: SwapDirection,
    ) -> U128 {
        let amount_in;
        match swap_direction {
            SwapDirection::Coin2PC => {
                // (x + delta_x) * (y + delta_y) = x * y
                // (coin + amount_in) * (pc - amount_out) = coin * pc
                // => amount_in = coin * pc / (pc - amount_out) - coin
                // => amount_in = (coin * pc - pc * coin + amount_out * coin) / (pc - amount_out)
                // => amount_in = (amount_out * coin) / (pc - amount_out)
                let denominator = total_pc_without_take_pnl.checked_sub(amount_out).unwrap();
                amount_in = total_coin_without_take_pnl
                    .checked_mul(amount_out)
                    .unwrap()
                    .checked_ceil_div(denominator)
                    .unwrap()
            }
```
