### Title
`swap_debt`/`swap_collateral` validate the wrong hub's active flag, allowing entry into a disabled hub — (File: contracts/controller/src/strategies/swap_debt.rs)

### Summary
The eZ Publish advisory is a "disabled module still reachable" bug: a view turned off in `site.ini` was still served when accessed by direct URL. The lending analog is an administrative disable (hub deactivation) that a user can route around because a strategy entrypoint validates the *source* leg's hub instead of the *destination* leg's hub. `process_swap_debt` calls `config::require_hub_active(env, existing_debt.hub_id)` while the new risk exposure is opened in `new_debt`, which may live in a different hub.

### Finding Description
Both strategy flows support cross-hub legs ("Matching assets across hubs pass through"), so `existing_debt.hub_id` and `new_debt.hub_id` can differ.

In `contracts/controller/src/strategies/swap_debt.rs:44`:

```rust
config::require_hub_active(env, existing_debt.hub_id);
```

This checks the hub of the debt being *repaid*, not the hub where the *new* borrow is opened via `borrow_into_controller` (line 55–63). If governance deactivates hub B but its spoke listings were left with `paused=false, frozen=false` (ADR-0007/ADR-0008 make hub deactivation and listing flags independent controls), an attacker can submit `swap_debt(account_id, existing_debt_in_active_hub_A, new_debt_in_inactive_hub_B, ...)` and create fresh borrow exposure inside the administratively disabled hub. The entry listing flags on `new_debt` may pass because per-listing `paused`/`frozen` were never set — hub inactivity was intended to be the gate.

The symmetric shape exists in `process_swap_collateral` (`contracts/controller/src/strategies/swap_collateral.rs:43`), which checks `current.hub_id` while the new collateral is deposited into `new` via `supply::process_deposit` (line 68). Here `require_can_supply` is explicitly invoked on `new` (line 50), which covers listing flags; whether it also re-checks hub active status is not visible in the indexed snippet — if it does not, the same bypass applies to new supply into a disabled hub.

### Impact Explanation
A disabled hub is an administrative "module off" control. An unprivileged account owner (or delegate) can continue to originate borrows against it, draining liquidity from a pool that governance intended to freeze, and can keep accruing/leveraging exposure while the disable is in effect. Depending on why the hub was deactivated (e.g., oracle or asset problem), this can produce bad debt or stealable liquidity rather than mere information disclosure.

### Likelihood Explanation
Reachable by any account owner/delegate through `swap_debt` with a cross-hub `new_debt` argument. Preconditions: the target hub is inactive while its spoke listing flags remain permissive — a plausible state since flag tightening and hub deactivation are separate admin operations per ADR-0007/ADR-0008. The single residual uncertainty is whether `borrow_into_controller`/`require_can_borrow` re-checks `require_hub_active` internally; the deliberate placement of `require_hub_active` at the top of the strategy functions suggests it is not redundant, and it is applied to the wrong key.

### Recommendation
Check `require_hub_active` on both legs: in `process_swap_debt` validate `new_debt.hub_id` (the hub receiving new exposure), and in `process_swap_collateral` validate `new.hub_id`. Alternatively, enforce `require_hub_active` inside `borrow_into_controller`/`process_deposit` so every entry leg is gated regardless of caller path.

### Proof of Concept
1. Hubs A (active) and B (inactive via admin deactivation) both list assets; B's spoke listing flags remain `paused=false, frozen=false`.
2. Attacker holds debt in hub A and calls `Controller.swap_debt` with `existing_debt = hub-A asset`, `new_debt = hub-B asset`, `new_debt_amount > 0`, plus a swap route (or same-asset passthrough across hubs).
3. `require_hub_active(existing_debt.hub_id)` passes; `borrow_into_controller` opens new hub-B debt; `repay_debt_from_controller` retires the hub-A debt.
4. Result: fresh borrow exposure inside a hub governance had disabled — the "disabled view" is still serving requests.
