### Title
Unauthenticated "magic" QR-codes let anyone repeatedly force a Wi-Fi/network reset (DoS) before operator authorization is checked - (File: `src/plans/mod.rs`)

### Summary
`src/plans/qr_scan/operator.rs` parses any scanned code matching `magic_action:<action>` into `Data::MagicResetWifi` / `Data::MagicResetMirror` regardless of who presents it. `src/plans/mod.rs::handle_magic_operator_qr_code` executes the privileged reset action (`reset_wifi_and_ensure_network` / `reset_mirror_calibration`) immediately, and only afterwards would the flow call `verify_operator_qr_code` to check the scanned operator against the backend. Because the magic-action branch returns `None` before ever reaching the operator-validation call, **no authorization check is performed** — any person who shows the orb camera a piece of paper with `magic_action:reset_wifi_credentials` can trigger the reset, repeatedly, forever.

### Finding Description
The operator QR-code parsing logic treats "magic" codes as a special, unauthenticated command channel: [1](#0-0) 

The dispatch loop calls `scan_operator_qr_code` → `handle_magic_operator_qr_code` and only calls `verify_operator_qr_code` (the actual backend authorization check that determines whether the scanned code belongs to a valid, registered operator) for the `Normal` variant, after the magic-action branches have already `continue`d/returned: [2](#0-1) [3](#0-2) 

The handler that actually performs the privileged action runs unconditionally on any scanned magic code, with zero authentication of the presenter: [4](#0-3) 

The action itself tears down the orb's network connection and blocks until a new connection is negotiated: [5](#0-4) 

This is structurally the same bug class as the reported `handleReallocation` DoS: a component that is supposed to be gated behind an authorization check (there: `SWAP_CALLER_ROLE` verification before the privileged call; here: backend operator validation via `verify_operator_qr_code` before privileged action) can instead be triggered directly by an unprivileged party through a side-channel input (there: `Executor.swapAndExecute` with arbitrary calldata; here: a QR code with `magic_action:...` text), and the action can be repeated indefinitely to keep the system unavailable.

### Impact Explanation
Any bystander (no operator credentials, no signup token, no association with the orb operator) can hold up a printed/displayed QR code encoding `magic_action:reset_wifi_credentials` to the orb's camera during idle/operator-scan phase and force the device to reset and re-negotiate its network connection via `network::reset()` + `wifi::Plan.ensure_network_connection`. Because there is no rate limiting, cooldown, or authorization gate on this path, the attacker can repeat this scan continuously, keeping the orb perpetually re-establishing network connectivity and unable to reliably process legitimate signups — a repeatable, self-service denial of service, matching the "Anyone can DOS ... over and over" impact class from the report. `magic_action:reset_mirror_calibration` similarly allows an unauthenticated party to force recalibration of the movable mirror mechanism at will, disrupting biometric capture operations.

### Likelihood Explanation
Likelihood is high: the trigger requires only physical presence in front of the orb's camera with an arbitrary printed/displayed QR code — no valid operator ID, no backend credentials, and no prior state are needed. The regex-based magic action parser accepts any string matching `magic_action:[\w]+` and dispatches straight to the privileged handler before any backend validation occurs.

### Recommendation
Move the magic-action dispatch after (or gate it behind) the same operator-authorization check (`verify_operator_qr_code`) used for normal operator QR-codes, so only a code presented by a validated/authorized operator can trigger `reset_wifi_and_ensure_network` or `reset_mirror_calibration`. Additionally, consider adding rate-limiting/cooldown on these destructive magic actions independent of authorization, since even legitimate operators should not be able to trigger unlimited resets in rapid succession.

### Proof of Concept
1. Print/display a QR code containing the literal text `magic_action:reset_wifi_credentials`.
2. Present it to the orb's camera during the operator QR-code scanning phase (idle screen / `scan_initial_qr_codes` / `scan_remaining_qr_codes`).
3. Observe `handle_magic_operator_qr_code` matches `Data::MagicResetWifi` (per the parser in `src/plans/qr_scan/operator.rs`) and calls `reset_wifi_and_ensure_network`, tearing down and re-establishing the orb's network connection — with no check that the presenter is a registered operator.
4. Repeat the scan indefinitely to keep the orb continuously resetting its network connectivity, denying normal signup operation.

/// Operator QR-code data.
#[derive(Clone, Debug)]
pub enum Data {
    /// Normal Operator QR-code.
    Normal(user::Data),
    /// Action to reconfigure WiFi.
    MagicResetWifi,
    /// Action to reset mirror calibration.
    MagicResetMirror,
}

impl Schema for Data {
    fn ui() -> ui::QrScanSchema {
        ui::QrScanSchema::Operator
    }

    fn try_parse(code: &str) -> Option<Self> {
        let normal = user::Data::try_parse(code)
            .filter(
                |d| if d.signup_extension() { d.signup_extension_config.is_some() } else { true },
            )
            .map(Data::Normal);
        if normal.is_some() {
            return normal;
        }
        if let Some(captures) = MAGIC_QR_CODE.captures(code) {
            return match captures
                .name("magic_action")
                .expect("magic_action group must be present")
                .as_str()
            {
                "reset_wifi_credentials" => Some(Data::MagicResetWifi),
                "reset_mirror_calibration" => Some(Data::MagicResetMirror),
                _ => None,
            };
        }
        None
    }

    async fn handle_magic_operator_qr_code(
        &self,
        orb: &mut Orb,
        qr_code: qr_scan::operator::Data,
    ) -> Result<Option<qr_scan::user::Data>> {
        match qr_code {
            qr_scan::operator::Data::Normal(qr_code) => {
                tracing::info!("Operator QR-code detected: {qr_code:?}");
                Ok(Some(qr_code))
            }
            qr_scan::operator::Data::MagicResetMirror => {
                tracing::info!("Magic QR-code detected: Reset Mirror");
                dd_incr!("main.count.signup.during.general.magic_qr.reset_mirror");
                let result = self.reset_mirror_calibration(orb).await;
                if let Err(err) = &result {
                    tracing::error!("Failed to reset mirror calibration: {err}");
                }
                orb.ui.magic_qr_action_completed(result.is_ok());
                Ok(None)
            }
            qr_scan::operator::Data::MagicResetWifi => {
                tracing::info!("Magic QR-code detected: Reset Wi-Fi");
                dd_incr!("main.count.signup.during.general.magic_qr.reset_wifi");
                let result = self.reset_wifi_and_ensure_network(orb).await;
                if let Err(err) = &result {
                    tracing::error!("Failed to reset wifi: {err}");
                }
                orb.ui.magic_qr_action_completed(result.is_ok());
                Ok(None)
            }
        }
    }
