### Title
Whole-unit ceil rounding over-seizes low-decimal collateral on full-debt liquidation - (File: contracts/controller/src/positions/liquidation/math.rs)

### Summary
For collateral assets with `asset_decimals < MIN_BORROWABLE_ASSET_DECIMALS` (0–2 decimals), `calculate_seized_collateral` rounds the planned seizure **up** to a whole token unit whenever the repayment plan covers all debt (`repayment.repays_all_debt`). Rescaling a RAY value to a 0-decimal asset divides by `10^27`, so any non-zero planned seizure rounds up to a full token — the same defect class as the reported `mulDivRoundingUp(..., 1e18)` where a huge divisor inflates the ceil to a whole unit of collateral.

### Finding Description
In `calculate_seized_collateral`, `seizure_ray` is sized from `repay_usd * (1 + bonus)` — the exact USD value the seized collateral should be worth [1](#0-0) . For low-decimal collateral on a full-debt repayment plan, the code then applies `seizure_ray.to_asset_ceil(env, feed.asset_decimals)` and converts the whole-unit count back to RAY, capped only at the held balance [2](#0-1) . `to_asset_ceil` computes `ceil(ray / 10^(27-d))`; at `d = 0` the divisor is `10^27`, so a seizure of e.g. `0.001` whole tokens rounds up to `1` whole token — an excess of up to `10^(27-d) - 1` RAY units, i.e. almost one entire token. The inflated `seizure_ray` then becomes `capped_ray` (only bounded by `actual_ray`) and is converted to seized supply shares/payout for the liquidator [3](#0-2) . The liquidator is credited `repay_usd * (1 + bonus)` worth of principal-plus-bonus semantics, but physically receives the whole-unit-rounded collateral, which can be worth materially more.

### Impact Explanation
Theft of user collateral. For a listed asset with 0 decimals priced at, say, \$200/whole token, a liquidator repaying the account's full debt can be credited a seizure whose planned value is far below one token, yet walks away with a whole token worth ~\$200 beyond `repay * (1 + bonus)`. The loss is borne by the liquidated account's collateral positions. The excess is unbounded by the bonus and scales with token unit price, per low-decimal collateral leg.

### Likelihood Explanation
Reachable by any unprivileged liquidator via `liquidate`: offering payments covering every debt leg sets `repays_all_debt`, which selects the `to_asset_ceil` branch. Requires a listed collateral asset with `asset_decimals < MIN_BORROWABLE_ASSET_DECIMALS` whose whole unit has meaningful USD value, and an unhealthy account holding such collateral — plausible configurations since `MIN_ASSET_DECIMALS = 0`. Severity: Medium (bounded by one whole unit per leg, conditional on valuable sub-3-decimal collateral being listed).

### Recommendation
Cap the whole-unit seizure by the USD-valued amount: after `to_asset_ceil`, clamp `seizure_ray` to `Ray::from_asset(env, seizure_amount_wad.to_asset-equivalent...)` — concretely, bound the rounded-up seizure so its USD value does not exceed `seizure_for_asset_usd` plus the smallest representable unit, or revert/omit the leg when the ceil exceeds the proportional value by more than one unit of bonus headroom. Alternatively, only permit whole-unit rounding when the rounded token's USD value is within the bonus of the planned seizure.

### Proof of Concept
1. Asset `X` is listed with `asset_decimals = 0`, price \$200 (WAD `200e18`), some supply index.
2. Victim account holds `0.5` tokens of `X` collateral (e.g. `actual_ray = 0.5e27`) and small debt in another asset; HF < 1.
3. Liquidator calls `liquidate` with payments covering all debt → `repays_all_debt = true`.
4. Pro-rata math computes `seizure_ray` for the `X` leg ≈ `repay_usd*(1+bonus)/200 * 1e27`, say `0.05e27` (\$10 planned seizure).
5. `to_asset_ceil(env, 0)` → `ceil(0.05e27 / 1e27) = 1` whole unit; `seizure_ray = 1e27`, capped only at `actual_ray` — but actual is `0.5e27`, so `capped_ray = 0.5e27` (full position seized despite plan of \$10).
6. Liquidator receives `0.5` whole `X` (~\$100) for ~\$10 of repayment value: ~\$90 of victim collateral over-seized, far above the liquidation bonus.
