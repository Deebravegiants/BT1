### Title
Fraud detection is hardcoded to never trigger regardless of pipeline output - ([File: src/plans/fraud_check.rs])

### Summary
The Fraud Check Engine has been reduced to zero actual checks: `N_FRAUD_CHECKS` is set to `0` and `Report::fraud_checks()` unconditionally returns an empty array, so `Report::fraud_detected()` and `fraud_detected_with_config()` always evaluate to `false` no matter what biometric data (occlusion, multiple faces, underaged, etc.) was captured. `FraudChecks::run()` also ignores the actual `biometric_pipeline::Pipeline` argument entirely and returns an empty `Report {}`.

### Finding Description
`FraudChecks::new` takes a reference to the `biometric_pipeline::Pipeline` but stores nothing from it (`PhantomData` only), and `FraudChecks::run` returns `Report {}` unconditionally without inspecting the pipeline at all: [1](#0-0) 

`Report::fraud_checks()` is hardcoded to return an empty array because `N_FRAUD_CHECKS` is set to `0`, explicitly annotated as "manually deleted all fraud checks": [2](#0-1) [3](#0-2) 

Consequently, `fraud_detected()` iterates over an empty array with `.any(...)`, which by definition of `Iterator::any` on an empty iterator returns `false` unconditionally: [4](#0-3) 

This means any caller in `MasterPlan::detect_fraud` (`src/plans/mod.rs`) that constructs `FraudChecks::new(&pipeline)` and calls `.run()` followed by `.fraud_detected()` will always get `false`, independent of whether the underlying `biometric_pipeline::Pipeline` contains `occlusion = Err(_)`, `face_identifier_fraud_checks = Err(_)`, multi-face detections, or underage indicators. There is no code path in `fraud_check.rs` that reads the pipeline's fields to populate `fraud_checks()`, so no combination of pipeline outputs can make `fraud_detected` return `true`.

### Impact Explanation
This is a fail-open bypass of biometric fraud enforcement: signups with occluded faces, multiple faces in frame, or underaged subjects will never be flagged as fraudulent by this engine, regardless of scene contents at capture time. This violates the fail-closed design intent implied by `fraud_checks_strict` ("If fraud data are missing, we assume fraud is detected") — that safety net is moot because there are zero checks to begin with. Matches Worldcoin/Orb bounty category of liveness/fraud bypass leading to unauthorized/fraudulent signup enrollment.

### Likelihood Explanation
This requires no privileged access — it is the default, unconditional behavior of the fraud engine for every signup, since `N_FRAUD_CHECKS = 0` and `run()` ignores its input. It is 100% reproducible for any attacker-controlled scene (occluded face, multiple faces, underaged subject) presented to the cameras during a normal signup session.

### Recommendation
Restore actual fraud-check implementations that inspect the `biometric_pipeline::Pipeline` fields (occlusion, multi-face, age estimation, etc.) and populate `Report::fraud_checks()` accordingly instead of returning an empty array; ensure `FraudChecks::run()` reads its `_pipeline` argument rather than discarding it via `PhantomData`.
