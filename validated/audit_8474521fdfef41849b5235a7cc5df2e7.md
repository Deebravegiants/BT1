### Title
Shared, unpartitioned custody in `EmporiumUpgradeable.runAction` "stateless" path allows any user to steal a prior user's stateful external-protocol position - (`contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol`)

### Summary
`EmporiumUpgradeable` is a single, shared contract address used by every Hinkal user to route arbitrary `op.endpoint.call{value: op.value}(op.callData)` interactions (the "Stateless Interaction" branch, reachable when `op.invokeWallet == false` or `stack.signerAddress == address(0)`). Replay protection is enforced only per `circomData.emporiumMessage` via `EmporiumStorageVars.usedMessages`, with no linkage between a message and the specific assets/positions it is entitled to withdraw from Emporium or from any external protocol Emporium interacted with on a caller's behalf.

### Finding Description
The equality the design implicitly assumes is:

`assets/positions held under Emporium's address after user A's runAction == assets attributable exclusively to user A's emporiumMessage/UTXOs`

This is false. Consider:

1. Victim (or any user) calls `transact()` → Hinkal core → `EmporiumUpgradeable.runAction` with an `EmporiumStack` op where `invokeWallet == false` (Case 2, "Stateless Interaction", `contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol:97-113`). This path requires **no signature at all** — `verifyWallet` returns immediately once `stack.signerAddress == address(0)` after marking the message used (`contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol:314-316`). The only gate is `onlyAllowedRecipient`, which merely checks `msg.sender` is the whitelisted Hinkal core contract (`contracts/external-actions/ExternalActionBaseUpgradeable.sol:39-46`) — it does not tie the call to any specific user identity or asset.
2. `op.endpoint` and `op.callData` are attacker/user-controlled data embedded in `circomData.externalActionData.externalActionMetadata`, decoded with no restriction that the target protocol be a genuinely atomic/stateless interaction (e.g., nothing stops calling `deposit()`/`stake()` on a lending or staking protocol that records a position keyed by `msg.sender == address(Emporium)`).
3. Emporium's own accounting only diffs `getBalancesForArray` before/after the call for the exact `circomData.erc20TokenAddresses` listed in that transaction (`contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol:85-88, 122-151`). If the external protocol leaves a position (LP receipt, internal ledger entry, collateral record) rather than immediately returning tokens, that position sits under Emporium's shared address, permanently and un-partitioned.
4. Attacker (a different, unrelated, unprivileged account) then submits their own `transact()` with a brand-new, self-authorized `emporiumMessage` (accepted because `usedMessages` only rejects exact message reuse, not asset overlap) whose `op.endpoint.call` invokes the same external protocol's withdraw/redeem function. Since that protocol only knows `msg.sender == Emporium`, it releases the previously-deposited value into Emporium's balance during the attacker's own atomic call. `handleOut` then sweeps `balancesAfter - balancesBefore` for that token straight to `msg.sender` (Hinkal core, ultimately attacker's stealth UTXO) via `transferERC20TokenOrETH` (`contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol:162-184`), crediting the victim's funds to the attacker.

Existing guards do not prevent this: `usedMessages` is per-message not per-asset/position (`contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol:308-312`); `verifyWallet`'s signature check is entirely skipped for `signerAddress == address(0)`; and the only architectural mitigation the code provides — routing genuinely stateful interactions through a per-user-signed `HinkalWallet` (Case 1, `contracts/external-actions/emporium/HinkalWallet.sol`) — is optional and not enforced at the contract level for Case 2 calls.

### Impact Explanation
Direct theft of shielded/in-flight user funds: any value a user leaves parked in a stateful external protocol via the Emporium "stateless" path becomes claimable by any subsequent unprivileged caller who targets the same protocol/endpoint, matching the Critical severity bar (direct theft of shielded funds). This is repeatable for every stateful external integration reachable through `op.endpoint.call` and for every victim who leaves a redeemable position.

### Likelihood Explanation
Preconditions: a victim (or the standard SDK/relay flow) must perform a Case 2 (`invokeWallet=false`) external action against a protocol that does not fully round-trip funds back into an ERC20/ETH balance within the same call (i.e., any protocol with persistent, address-keyed state — staking, lending, LP positions). No admin/relay privilege or victim's key material is required by the attacker; the attacker only needs to know the vulnerable external protocol/endpoint and submit their own independently valid, self-signed proof/message. Cost is a single ordinary `transact()` call.

### Recommendation
Enforce that Case 2 ("Stateless Interaction") calls cannot leave any residual, protocol-tracked position keyed to Emporium's address — e.g., by requiring the full set of tokens/assets touched by `op.endpoint` to be declared and swept, or by disallowing use of the unsigned/no-wallet path for any external protocol identified as stateful. Alternatively, require all external interactions to go exclusively through per-user `HinkalWallet` instances (Case 1, signature-gated) so state at third-party protocols is always keyed to a distinct, victim-controlled address rather than the shared `Emporium` address.

### Proof of Concept
Foundry test plan:
1. Deploy `EmporiumUpgradeable`, a mock "stateful" protocol (e.g., `MockLending` with `deposit()`/`withdraw()` keyed by `msg.sender`), and a Hinkal core stub granted `onlyAllowedRecipient`.
2. As "victim", call `runAction` with `EmporiumStack{ops:[{endpoint: mockLending, invokeWallet:false, callData: deposit(amount)}], signerAddress: address(0)}` and a fresh `emporiumMessage_A`; assert `usedMessages[emporiumMessage_A] == true` and `mockLending.balanceOf(address(emporium)) == amount`.
3. As "attacker" (different EOA, unrelated proof/UTXOs), call `runAction` with a new `emporiumMessage_B`, `op.endpoint = mockLending`, `callData = withdraw(amount)`, `erc20TokenAddresses = [underlyingToken]`.
4. Assert: attacker's resulting `UTXO`/`transferERC20TokenOrETH` receives `amount` of `underlyingToken`, while `usedMessages` shows both `emporiumMessage_A` and `emporiumMessage_B` as independently valid/used — demonstrating there is no mapping tying the victim's deposited asset to `emporiumMessage_A` exclusively, proving the equality `assets held after victim's tx == assets attributable to victim's message` is false.     function runAction(
        CircomData calldata circomData,
        int256[] calldata deltaAmountChanges
    ) external override onlyAllowedRecipient returns (UTXO[] memory) {
        EmporiumStack memory stack = abi.decode(
            circomData.externalActionData.externalActionMetadata,
            (EmporiumStack)
        );

        uint256[] memory balancesBefore = getBalancesForArray(
            circomData.erc20TokenAddresses
        );

        verifyWallet(stack, circomData);

        for (uint256 i = 0; i < stack.ops.length; i++) {
            EmporiumOperation memory op = stack.ops[i];

            bool success;
            bytes memory err;

            // CASE 1: Stateful Interaction
            if (op.invokeWallet && stack.signerAddress != address(0)) {
                (success, err) = IHinkalWallet(stack.signerAddress)
                    .callHinkalWallet(op.endpoint, op.callData, op.value);
            }
            // CASE 2: Stateless Interaction
            else {
                bytes4 selector = bytes4(op.callData);
                if (
                    selector == IHinkalWallet.callHinkalWallet.selector ||
                    selector == IHinkalWallet.doSendToRelay.selector
                ) {
                    revert UnauthorizedWalletCall();
                }

                (success, err) = op.endpoint.call{value: op.value}(op.callData);
            }

            if (!success) {
                revert CallFailed(err);
            }
        }

        payRelayFees(circomData, stack.signerAddress, deltaAmountChanges);

        uint256[] memory balancesAfter = getBalancesForArray(
            circomData.erc20TokenAddresses
        );

        UTXO[] memory utxoSet = new UTXO[](
            circomData.erc20TokenAddresses.length
        );

        uint256 utxoSetLength;

        for (uint256 i = 0; i < circomData.erc20TokenAddresses.length; i++) {
            int256 balanceChange = int256(balancesAfter[i]) -
                int256(balancesBefore[i]);

            if (deltaAmountChanges[i] < 0) {
                balanceChange -= deltaAmountChanges[i];
                // this equation reads: total change of emporium balance = what was moved to emporium (-deltaAmountChange) + how emporium balance changed through tx (balanceChange)
            }

            // the only case when balanceChange can be < 0, when there were some funds on emporium before the call
            if (balanceChange < 0) {
                revert BalanceChangeShouldBePositive();
            }

            UTXO memory utxoOut = handleOut(balanceChange, circomData, i);

            if (utxoOut.amount > 0) {
                utxoSet[utxoSetLength++] = utxoOut;
            }
        }

        if (utxoSetLength < circomData.erc20TokenAddresses.length) {
            utxoSet.skipLast(
                circomData.erc20TokenAddresses.length - utxoSetLength
            );
        }

        return utxoSet;
    }

    function verifyWallet(
        EmporiumStack memory stack,
        CircomData calldata circomData
    ) internal {
        EmporiumStorageVars storage $ = _getEmporiumStorage();

        if ($.usedMessages[circomData.emporiumMessage]) {
            revert UsedMessage();
        }

        $.usedMessages[circomData.emporiumMessage] = true;

        if (stack.signerAddress == address(0)) {
            return;
        }

        bytes32 hashedMessage = _hashTypedDataV4(
            keccak256(
                abi.encode(
                    EMPORIUM_SIGNATURE_TYPEHASH,
                    circomData.emporiumMessage,
                    _hashEmporiumOps(stack.ops),
                    stack.maxFee,
                    stack.deadline
                )
            )
        );

        (address recoveredAddress, ECDSA.RecoverError err) = ECDSA.tryRecover(
            hashedMessage,
            stack.v,
            stack.r,
            stack.s
        );
        bool verified = err == ECDSA.RecoverError.NoError &&
            recoveredAddress == stack.signerAddress;
        if (!verified) {
            revert InvalidSignature();
        }

        if (block.timestamp > stack.deadline) {
            revert SignatureExpired();
        }

        if (circomData.feeStructure.flatFee > stack.maxFee) {
            revert FeeExceedsSignedMax();
        }
    }

pragma solidity ^0.8.17;

import {ECDSA} from "@openzeppelin/contracts/utils/cryptography/ECDSA.sol";
import {IERC165} from "@openzeppelin/contracts/interfaces/IERC165.sol";

import {Transferer} from "../../Transferer.sol";
import {IHinkalWallet} from "../../types/IHinkalWallet.sol";

contract HinkalWallet is Transferer, IHinkalWallet {
    address public immutable emporium;

    event EthReceivedOnWallet(address indexed sender, uint256 amount);

    error NotAllowedToCallWallet();

    constructor(address _emporium) {
        emporium = _emporium;
    }

    modifier onlyEmporium() {
        if (msg.sender != emporium) {
            revert NotAllowedToCallWallet();
        }
        _;
    }

    function callHinkalWallet(
        address endpoint,
        bytes calldata data,
        uint value
    ) external onlyEmporium returns (bool success, bytes memory err) {
        (success, err) = endpoint.call{value: value}(data);
    }
