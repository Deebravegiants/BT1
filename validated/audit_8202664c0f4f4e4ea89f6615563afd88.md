### Title
`EvmHost.dispatch()` prices native-fee swaps from a single-block, unprotected AMM spot price — ([File: evm/src/core/EvmHost.sol])

### Summary
`EvmHost.dispatch(DispatchPost)` lets any caller pay Hyperbridge's relayer fee in native token by having the Host swap `msg.value` ETH for `post.fee` units of `feeToken()` through the configured router (`_hostParams.uniswapV2`), via `swapETHForExactTokens`. The price paid is read live from whatever AMM pool the router points to — Uniswap V2 (`getReserves`), or, per the `UniV3UniswapV2Wrapper`/`UniV4UniswapV2Wrapper`, a V3/V4 pool queried with `sqrtPriceLimitX96: 0` (no price bound). None of these paths apply a TWAP or a caller-supplied slippage bound; the exact-output amount is derived from whatever the pool's reserves/tick are in that same block. [1](#0-0) 

### Finding Description
`dispatch()` unconditionally trusts the configured router's live price:

```solidity
function dispatch(DispatchPost memory post) external payable notFrozen returns (bytes32 commitment) {
    if (msg.value > 0) {
        address[] memory path = new address[](2);
        address uniswapV2 = _hostParams.uniswapV2;
        path[0] = IUniswapV2Router02(uniswapV2).WETH();
        path[1] = feeToken();
        IUniswapV2Router02(uniswapV2).swapETHForExactTokens{value: msg.value}(
            post.fee, path, address(this), block.timestamp
        );
    }
    ...
``` [1](#0-0) 

`HyperApp.quote()`, the client-side helper that estimates the native cost, has the same single-block dependency:

```solidity
function quote(DispatchPost memory request) public returns (uint256) {
    address _host = host();
    address _uniswap = IDispatcher(_host).uniswapV2Router();
    address[] memory path = new address[](2);
    path[0] = IUniswapV2Router02(_uniswap).WETH();
    path[1] = IDispatcher(_host).feeToken();
    return IUniswapV2Router02(_uniswap).getAmountsIn(request.fee, path)[0];
}
``` [2](#0-1) 

Where the Host's `uniswapV2` is a `UniV3UniswapV2Wrapper`/`UniV4UniswapV2Wrapper`, the "V2-compatible" quote is not a passive view read but an actual on-chain swap executed with `sqrtPriceLimitX96: 0` — i.e. no protection against the current tick being far from a fair price:

```solidity
IV3SwapRouter.ExactInputSingleParams memory params = IV3SwapRouter.ExactInputSingleParams({
    tokenIn: token,
    tokenOut: weth,
    fee: _params.maxFee,
    recipient: address(this),
    amountIn: amountIn,
    amountOutMinimum: amountOutMin,
    sqrtPriceLimitX96: 0
});
``` [3](#0-2) 

This is the same bug class as the referenced AIZPT exploit: a protocol-controlled monetary calculation is derived from a single-transaction, manipulable AMM state instead of a resistant price source (TWAP/oracle), and is invoked atomically alongside a flash loan. Here, an attacker can, within one transaction: (1) flash-loan and trade against the configured pool to crash the price of `feeToken()` relative to native ETH, (2) call `EvmHost.dispatch{value: <tiny amount>}(post)` with a large `post.fee`, so `swapETHForExactTokens` (or the V3/V4 exact-input swap) fills the Host's fee-token requirement out of the now-distorted pool for far less ETH than the token is really worth, and (3) reverse the manipulation and repay the flash loan, pocketing the difference extracted from the pool's liquidity while `EvmHost` records the full `post.fee` as paid and dispatches the message. This can be repeated in a loop (bounded only by the pool's depth) to drain the value backing the fee-token pool that Hyperbridge's own native-fee payment path depends on, and the resulting under-priced dispatches still register the requested fee in `_requestCommitments`, later refundable to `post.payer` on timeout.

### Impact Explanation
Any unprivileged account reachable path — a single `dispatch()` call with `msg.value` — lets an attacker atomically manipulate the price the Host relies on to compute how much native currency backs a relayer fee, extracting value from the configured AMM pool (which is part of the protocol's fee infrastructure) at attacker-chosen, manipulated rates, and can repeat this to drain that pool's liquidity. This is a concrete "wrong price calculation" causing fund loss reachable from a single dispatched transaction, matching the required "concrete theft ... via unsound state commitment" bar because the fee accounting recorded by `EvmHost` (`_requestCommitments[commitment].fee`) does not reflect real economic value paid.

### Likelihood Explanation
High: no privileged role is required, no TWAP/slippage protections exist in `dispatch()`, `HyperApp.quote()`, or the V3/V4 wrapper swaps, and flash loans against public DEX pools are a standard, cheaply repeatable primitive (as demonstrated by the referenced AIZPT PancakeV3 flash-based exploit).

### Recommendation
Replace the single-block spot-price swap with a slippage-bounded and/or TWAP-derived quote: require callers to supply a `maxNativeIn` / `minFeeTokenOut` bound checked against a time-weighted price, or route native payments through a price oracle resistant to single-transaction manipulation before executing `swapETHForExactTokens`/`exactInputSingle`. At minimum, add a `amountInMax` parameter to `dispatch()` bounded by an off-chain-computed acceptable price and revert if the swap would exceed it.

### Proof of Concept
Analogous to the referenced report: an attacker contract takes a flash loan on the pool feeding `_hostParams.uniswapV2` (or the V3/V4 wrapper's underlying pool), swaps to skew the `WETH/feeToken` price, calls `EvmHost.dispatch{value: X}(post)` with `post.fee` set to drain a meaningful amount of `feeToken` for `X` far below its market value, then reverses the price skew and repays the flash loan within the same transaction — exactly the "flash loan + manipulate on-chain price used by protocol swap" pattern in `AIZPTToken_exp.sol`, applied to `EvmHost.dispatch`'s unprotected `swapETHForExactTokens`/`exactInputSingle` call.
