### Title
Reachable arithmetic-underflow panic in `swap_token_amount_base_out` allows any user to abort `SwapBaseOut`/`SwapBaseOut2` transactions - (File: program/src/math.rs, program/src/processor.rs)

### Summary
`Calculator::swap_token_amount_base_out` performs `total_pc_without_take_pnl.checked_sub(amount_out).unwrap()` (Coin2PC branch) or `total_coin_without_take_pnl.checked_sub(amount_out).unwrap()` (PC2Coin branch) as part of computing the swap input amount for base-out swaps. Both call sites (`process_swap_base_out` and `process_swap_base_out2`) invoke this function with the attacker-supplied `swap.amount_out` *before* performing the bounds check `if swap.amount_out >= total_pc_without_take_pnl { return Err(...) }` that would normally reject an out-of-range value.

### Finding Description [1](#0-0) 
computes `denominator = total_pc_without_take_pnl.checked_sub(amount_out).unwrap()` (or the coin equivalent for `PC2Coin`). `checked_sub` returns `None` whenever `amount_out >= total_pc_without_take_pnl`, and the immediate `.unwrap()` converts that into a panic instead of a graceful `AmmError`.

In `process_swap_base_out`, the vulnerable call happens at [2](#0-1) 
which is reached before the corresponding guard [3](#0-2) 
is ever evaluated. The identical ordering bug exists in `process_swap_base_out2`, where the vulnerable call is at [4](#0-3) 
and the guard is at [5](#0-4) 
.

Since `swap.amount_out` is deserialized directly from instruction data (`SwapInstructionBaseOut`), and the pool's `total_pc_without_take_pnl`/`total_coin_without_take_pnl` are computed from vault balances that are visible on-chain, any unprivileged party can craft a single transaction (using their own arbitrary `amount_out` value, no privileged signer required) that deterministically panics the on-chain program at the `unwrap()` call — the reachable-assertion/abort pattern that is the same bug class as CVE-2017-13751's `calcstepsizes()` abort.

### Impact Explanation
On Solana, a panic inside a BPF program aborts only the invoking transaction (the runtime traps it and returns a failed transaction), it does not crash the validator. Consequently this class of bug degrades to a griefing/DoS vector: an attacker can force the AMM's `SwapBaseOut`/`SwapBaseOut2` instructions to always fail for a given attacker-chosen `amount_out`, but they cannot use it to steal funds, mint unbacked LP, or corrupt AmmInfo/TargetOrders state, because the panic aborts before any token transfer or state mutation occurs. Legitimate users are not blocked from calling the instruction with valid, in-range `amount_out` values — the impact is limited to the attacker's own poorly-formed request failing (with a panic/log noise) instead of returning the intended `InsufficientFunds` error.

### Likelihood Explanation
Trivial to trigger — a single transaction with `amount_out >= total_pc_without_take_pnl` (or the coin equivalent) is sufficient, requiring only default-signer permissions and no special account state.

### Recommendation
Reorder the checks so that the `swap.amount_out >= total_pc_without_take_pnl` / `total_coin_without_take_pnl` bounds validation happens *before* calling `Calculator::swap_token_amount_base_out`, and/or change `swap_token_amount_base_out`'s internal `checked_sub(...).unwrap()` calls to propagate a proper `AmmError` (e.g. via `ok_or(AmmError::CheckedSubOverflow)?`) instead of panicking.

### Proof of Concept
1. Create/observe an AMM pool where `total_pc_without_take_pnl = P` (readable from the on-chain vault balance).
2. Submit a `SwapBaseOut` (or `SwapBaseOut2`) instruction with `swap_direction = Coin2PC` and `amount_out = P` (or any value `>= P`), with any account matching the mint requirements (no special privileges needed).
3. Execution reaches `program/src/math.rs:341` (`total_pc_without_take_pnl.checked_sub(amount_out).unwrap()`), `checked_sub` returns `None`, `.unwrap()` panics, and the transaction aborts with a runtime panic instead of the intended `AmmError::InsufficientFunds`.

Given that Solana traps the panic at the transaction boundary rather than propagating any broader system compromise, this qualifies as a low-severity logic/ordering defect rather than a High-severity concrete-theft or fund-freezing vulnerability as required by the validation criteria in this scan.

    pub fn swap_token_amount_base_out(
        amount_out: U128,
        total_pc_without_take_pnl: U128,
        total_coin_without_take_pnl: U128,
        swap_direction: SwapDirection,
    ) -> U128 {
        let amount_in;
        match swap_direction {
            SwapDirection::Coin2PC => {
                // (x + delta_x) * (y + delta_y) = x * y
                // (coin + amount_in) * (pc - amount_out) = coin * pc
                // => amount_in = coin * pc / (pc - amount_out) - coin
                // => amount_in = (coin * pc - pc * coin + amount_out * coin) / (pc - amount_out)
                // => amount_in = (amount_out * coin) / (pc - amount_out)
                let denominator = total_pc_without_take_pnl.checked_sub(amount_out).unwrap();
                amount_in = total_coin_without_take_pnl
                    .checked_mul(amount_out)
                    .unwrap()
                    .checked_ceil_div(denominator)
                    .unwrap()
            }
            SwapDirection::PC2Coin => {
                // (x + delta_x) * (y + delta_y) = x * y
                // (pc + amount_in) * (coin - amount_out) = coin * pc
                // => amount_out = coin - coin * pc / (pc + amount_in)
                // => amount_out = (coin * pc + coin * amount_in - coin * pc) / (pc + amount_in)
                // => amount_out = coin * amount_in / (pc + amount_in)

                // => amount_in = coin * pc / (coin - amount_out) - pc
                // => amount_in = (coin * pc - pc * coin + pc * amount_out) / (coin - amount_out)
                // => amount_in = (pc * amount_out) / (coin - amount_out)
                let denominator = total_coin_without_take_pnl.checked_sub(amount_out).unwrap();
                amount_in = total_pc_without_take_pnl
                    .checked_mul(amount_out)
                    .unwrap()
                    .checked_ceil_div(denominator)
                    .unwrap()
            }
        }
        return amount_in;
    }
