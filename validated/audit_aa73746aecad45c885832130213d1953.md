## Finding

The Chainlink Gateway's CORS origin-matching logic in `core/services/gateway/network/httpserver.go` reimplements wildcard subdomain matching using a plain `strings.HasSuffix` check without validating a dot boundary, reproducing the exact bug class described in GHSA-869c-j7wc-8jqv/CVE-2019-25211 (Gin CORS mishandling wildcard-terminated origins, e.g. `example.community` matching an `example.com` rule). [1](#0-0) 

### Title
CORS wildcard-origin allowlist bypass via unanchored suffix match in Gateway HTTP server - (File: core/services/gateway/network/httpserver.go)

### Summary
`isAllowedOrigin` strips the `*.` prefix from a configured wildcard rule (e.g. `https://*.ethereum.org` → `ethereum.org`) and then checks `strings.HasSuffix(originHost, allowedHost)` with no dot-boundary check, so any host string that merely *ends with* the allowed suffix satisfies the rule, not just proper subdomains. [2](#0-1) 

### Finding Description
The Gateway HTTP server (`core/services/gateway/network/httpserver.go`) is an internet-facing component whose `handleRequest` sets CORS response headers based on `isAllowedOrigin`: [3](#0-2) 

`isAllowedOrigin` splits scheme/host/port for both the request `Origin` header and each configured allowed origin, then for wildcard entries strips the leading `*.` and does a bare suffix comparison:

```go
if strings.HasPrefix(allowedHost, "*.") {
    allowedHost = allowedHost[2:]
    if strings.HasSuffix(originHost, allowedHost) {
        return true
    }
}
```

For an operator-configured rule such as `https://*.ethereum.org`, `allowedHost` becomes `"ethereum.org"`. Because `HasSuffix` has no requirement that the character preceding the match be a `.` (or that it be a full label boundary), any origin host that ends with the literal string `ethereum.org` — including `fakeethereum.org`, `notethereum.org`, or `attacker-ethereum.org` — is treated as allowed. This is the identical flaw class as the referenced Gin/gin-contrib/cors advisory, where `parseWildcardRules` allowed `https://example.community` to satisfy a rule meant to permit only `https://example.com`.

### Impact Explanation
An attacker who registers or controls a domain that merely ends with an operator's intended allowed suffix (e.g. `evilethereum.org` when the operator intended to scope access to `*.ethereum.org`) can host a page there and have the Gateway's CORS check treat it as an allowed cross-origin caller. The server reflects the attacker's `Origin` value into `Access-Control-Allow-Origin` and grants `Access-Control-Allow-Methods`/`Access-Control-Allow-Headers`, letting browser-based JavaScript on the attacker's page make cross-origin requests to the Gateway endpoint and read the JSON responses that would otherwise be same-origin-protected. This is a concrete allowlist bypass on an unprivileged, internet-facing path — the Gateway is designed to accept requests from external callers (e.g., DON/Functions clients) — matching the rules' acceptance criteria for "allowlist... bypass" on the "internet-facing gateway."

### Likelihood Explanation
Exploitation only requires the operator to configure any wildcard entry in `CORSAllowedOrigins` (a documented, supported configuration pattern per the test suite itself, e.g. `https://*.ethereum.org`) and an attacker registering a domain with a matching suffix — no privileged access or network position is required, and the check is purely string-based with no anchoring. [4](#0-3) 

### Recommendation
Anchor the wildcard suffix match to a label boundary, e.g. require that either `originHost == allowedHost` or `originHost` ends with `"."+allowedHost`, instead of a bare `strings.HasSuffix` comparison, mirroring the fix applied upstream in `gin-contrib/cors` v1.6.0.

### Proof of Concept
1. Configure the Gateway with `CORSAllowedOrigins = ["https://*.ethereum.org"]` and `CORSEnabled = true` (mirrors the pattern used in `TestHTTPServer_HandleRequest_CORSEnabled_FromAllowedOriginWildcards`).
2. From a browser page hosted at `https://fakeethereum.org` (an attacker-controlled domain not intended to be permitted), send a request to the Gateway endpoint with header `Origin: https://fakeethereum.org`.
3. Observe the server responds with `Access-Control-Allow-Origin: https://fakeethereum.org` because `strings.HasSuffix("fakeethereum.org", "ethereum.org")` evaluates true, even though `fakeethereum.org` is not a subdomain of `ethereum.org`. [1](#0-0)

func (s *httpServer) isAllowedOrigin(origin string) bool {
	originScheme, originHost, originPort, err := s.splitURL(origin)
	if err != nil {
		s.lggr.Debug("error parsing origin URL", err)
		return false
	}
	for _, allowed := range s.config.CORSAllowedOrigins {
		// probably better to do this once when server starts and store it in a map
		// this is an easier solution so we don't have to apply more changes to the code
		// just need to be careful when specifying allowed origins in the config file
		allowedScheme, allowedHost, allowedPort, err := s.splitURL(allowed)
		if err != nil {
			s.lggr.Debug("error parsing allowed origin URL", err)
			continue
		}
		// skip if the scheme doesn't match at all
		if originScheme != allowedScheme {
			continue
		}
		// skip if the port doesn't match at all
		if originPort != allowedPort {
			continue
		}
		// check for exact host match (e.g., remix.com)
		if originHost == allowedHost {
			return true
		}
		// check for wildcard host match (e.g., *.remix.com)
		if strings.HasPrefix(allowedHost, "*.") {
			allowedHost = allowedHost[2:]
			if strings.HasSuffix(originHost, allowedHost) {
				return true
			}
		}
	}
	return false
}

func (s *httpServer) handleRequest(w http.ResponseWriter, r *http.Request) {
	if s.config.CORSEnabled {
		origin := r.Header.Get("Origin")
		if s.isAllowedOrigin(origin) {
			w.Header().Set("Access-Control-Allow-Origin", origin)
			w.Header().Set("Access-Control-Allow-Methods", "GET, POST, OPTIONS")
			w.Header().Set("Access-Control-Allow-Headers", "Content-Type")
		}

		// handle preflight requests
		if r.Method == http.MethodOptions {
			w.WriteHeader(http.StatusNoContent)
			return
		}
	}
