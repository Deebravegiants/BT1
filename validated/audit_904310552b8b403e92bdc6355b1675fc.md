### Title
Insolvency shield via induced Aquarius LP price outage bricks liquidation and bad-debt cleanup - (File: contracts/price-aggregator/src/providers/aquarius.rs)

### Summary
The MySQL bug class is a low-privilege network attacker causing a repeatable denial of service on a core server function. The XOXNO Lending analog: an unprivileged borrower adds a dust supply leg of an Aquarius-LP-priced collateral, then — acting as the pool's liquidity provider — withdraws pool value below `min_pool_value_wad`. The Aquarius provider then fails closed (`InsufficientAquariusLiquidity`), the strict price cache panics (`OracleNotConfigured`), and every valuation-dependent path that must price the dust leg — `liquidate`, `clean_bad_debt`, and governed force-socialization — reverts. The account can never be liquidated or cleaned while the outage persists, converting a DoS primitive into permanent bad debt.

### Finding Description
`aquarius::read` computes the fair LP price and then enforces a pool-value floor:

- `contracts/price-aggregator/src/providers/aquarius.rs:118-122`: `pool_value_wad` is derived from `price_wad * total_shares / share_unit`; if `pool_value_wad < lp.min_pool_value_wad` the read returns `Err(OracleError::InsufficientAquariusLiquidity)`, producing no observation.

On the controller side all prices are strict:

- `Context::fetch_prices` only caches feeds the aggregator returns (`contracts/controller/src/context.rs:142-151`); a missing entry is never populated.
- `Context::cached_price` panics with `OracleError::OracleNotConfigured` when the cache has no entry (`context.rs:154-159`).
- `build_liquidation_plan` calls `risk::calculate_account_risk_totals` over **all** `supply_positions` and `borrow_positions` (`contracts/controller/src/positions/liquidation/plan.rs:34-39`), so a single unpriceable dust leg aborts the entire pro-rata plan. Seizure legs are forced across every collateral leg, and the same pricing loop is reached by `clean_bad_debt`/recapitalization flows.

Root cause: the valuation of the account is fail-closed over the conjunction of all legs, while the availability of an Aquarius LP leg's price is externally manipulable by any LP who can push pool value under the configured floor. An LP who supplies dust collateral and holds sufficient pool shares can toggle the leg's price on (borrow against other collateral) and off (withdraw liquidity to drop `pool_value_wad` below `min_pool_value_wad`) at will. Threat-model `DoS.1` (`docs/explanation/threat-model.md:364`) describes exactly this shape, confirming the code path exists as analyzed rather than the documentation constituting a fix.

### Impact Explanation
An insolvent account protected by one unpriceable dust leg cannot be liquidated, and cannot be cleaned up by `clean_bad_debt` or force-socialization either, because all of these paths price the full position set. While the outage holds, interest accrues on the bad debt; when the attacker finally lets the leg reprice (or the account's other collateral fully erodes), the protocol is left with socializable bad debt charged against suppliers via supply-index write-downs. Accepted impact: protocol insolvency and temporary-to-permanent freezing of liquidation/cleanup.

### Likelihood Explanation
Requires (a) an Aquarius LP token listed as collateral with `min_pool_value_wad` configured (mainnet `configs/mainnet/markets.json` contains multiple Aquarius-sourced markets), and (b) the attacker holding enough LP shares that their withdrawal moves pool value across the floor — realistic for thin or attacker-dominated pools, and exactly the scenario the floor was designed for (it treats small pools as untrusted). Cost is bounded by the dust collateral plus foregone LP position; no privileged role needed — `supply` accepts third-party top-ups and any listed asset, and Aquarius `withdraw_liquidity` is permissionless. Both triggers are single-user reachable, matching the PR:L severity of the original CVE.

### Recommendation
- Decouple leg pricing so a single failed feed cannot abort a whole-account operation: e.g., treat unpriceable supply legs as zero-valued collateral in `calculate_account_risk_totals` (conservative for HF, still lets seizure of priced legs proceed), or skip unpriceable legs in the seizure plan rather than aborting.
- Alternatively, make `clean_bad_debt`/force-socialization tolerate a missing price for supply legs being written down (they are forfeited anyway; pricing them is unnecessary).
- Review `min_pool_value_wad` per market so an attacker cannot cross it with a routine withdrawal; consider time-averaged pool value instead of instantaneous reserves.

### Proof of Concept
1. Governance lists Aquarius LP token `LP-X` as collateral in spoke S, source `AquariusLpSource { pool: P, min_pool_value_wad: M, ... }`.
2. Attacker deposits meaningful liquidity into Aquarius pool `P` (permissionless), making them a large LP holder.
3. Attacker calls `controller.supply` to create a dust `LP-X` supply leg on their account, then supplies other collateral and calls `borrow`, establishing a healthy position.
4. Market moves (or attacker sandwitches prices within bands) so HF < 1; before liquidators act, attacker calls `P.withdraw_liquidity` to pull reserves down until `price_wad * total_shares / share_unit < M`.
5. Every subsequent `liquidate(liquidator, account, ...)` reverts: `aquarius::read` → `InsufficientAquariusLiquidity` → no observation cached → `cached_price(LP-X)` panics `OracleNotConfigured` inside `calculate_account_risk_totals`. `clean_bad_debt` fails the same way.
6. Debt accrues unliquidated until the attacker re-adds liquidity; by then remaining collateral may not cover the debt → socialized loss via supply-index write-down.
