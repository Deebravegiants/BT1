This confirms the analog. The bug class maps cleanly onto `pallet-consensus-incentives`: the reward watermark `LastRewardedHeight` is only advanced when the computed reward is non-zero, exactly mirroring the Deli-Swap `IncentiveGauge` bug where `_updatePoolByPid()` (its own "watermark" update) is skipped whenever the rate/reward comes out to zero.

### Title
Stale `LastRewardedHeight` watermark when `cost_per_block` is zero or unset causes treasury overpayment on re-enable - (File: `modules/pallets/consensus-incentives/src/impls.rs`)

### Summary
`Pallet::process_message` only advances the `LastRewardedHeight` watermark for a state machine when the computed `reward` is non-zero, and does nothing at all when `StateMachinesCostPerBlock` has no entry for that state machine. Any consensus updates delivered while the reward rate is `0` (governance sets `cost_per_block = 0`, or removes the entry via `remove_incentives`) advance the chain's `latest_commitment_height` without ever moving the watermark forward. When governance later re-enables a positive `cost_per_block`, `calculate_reward` computes `blocks = latest_height - baseline` using the old, stale watermark, so the relayer is paid for the entire span of blocks that elapsed during the "free" (zero-cost) period — funds that were never supposed to be paid.

### Finding Description [1](#0-0) 

`process_message` reads `block_cost` for the state machine and, only `if let Some(block_cost)`, computes `reward`. If `reward.is_zero()` it returns `Ok(())` immediately, *before* the `LastRewardedHeight::<T>::mutate(...)` call that advances the watermark:

```rust
if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
    let reward = Self::calculate_reward(&state_machine_id, block_cost)?;
    if reward.is_zero() {
        return Ok(());
    }
    ...
    LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
        *watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
    });
}
``` [2](#0-1) 

`calculate_reward` derives the payable span purely from the persisted watermark:

```rust
let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);
let blocks = latest_height.saturating_sub(baseline);
let reward = blocks_as_balance.saturating_mul(block_cost);
```

This is structurally identical to the Deli-Swap `IncentiveGauge._upsertIncentive()` bug: there, `_updatePoolByPid()` (which advances `lastUpdated`) is skipped whenever `info.rewardRate == 0`, so a later non-zero-rate accrual reads a stale `lastUpdated` and mis-prices the elapsed interval. Here, the `LastRewardedHeight` watermark plays the exact same role as `lastUpdated`, `cost_per_block == 0` (or the entry being entirely absent) plays the role of `rewardRate == 0`, and the watermark-advance is likewise gated behind the "reward is non-zero" branch.

Concretely:
1. Governance calls `remove_incentives` or `update_cost_per_block(..., 0)` for a state machine, so `StateMachinesCostPerBlock::get` returns `None`/`0`. [3](#0-2) 
2. Consensus updates for that state machine continue to advance `latest_commitment_height` on the IsmpHost via the normal handler pipeline; `on_executed`/`process_message` run each time but never touch `LastRewardedHeight` because the `if let Some(block_cost)` branch is skipped (or `reward.is_zero()` returns early). The watermark is frozen at whatever height it last held.
3. Governance later re-enables incentives with `update_cost_per_block(..., cost_per_block > 0)`.
4. The next `StateMachineUpdated` event triggers `process_message` → `calculate_reward`, which computes `blocks = latest_height - baseline` using the frozen, stale `baseline`. This span now includes every block that advanced while incentives were off/zero, none of which should be compensated.
5. `T::Currency::transfer` pays the relayer `blocks_as_balance.saturating_mul(block_cost)` out of `T::TreasuryAccount`, which can be an arbitrarily large, unbounded amount depending on how long incentives were disabled and how far the chain advanced in the interim.

### Impact Explanation
This causes uncompensated/unbounded treasury drain: a single relayer submission after a dormant or zero-cost period can withdraw treasury funds sized to the entire un-rewarded block span, not just the blocks actually delivered under the active incentive. Because `saturating_mul` is used and the span can be large (months of blocks at high-throughput chains), this is a concrete loss-of-funds vector for the treasury, satisfying the "concrete theft ... of funds" bar. It is directly reachable by any relayer submitting a normal, valid consensus message once governance re-enables `cost_per_block` — no malicious governance action is required, since disabling/enabling `cost_per_block` is a legitimate, expected governance operation and the bug fires on the very next honest relayer submission afterward.

### Likelihood Explanation
Toggling `cost_per_block` (via `remove_incentives` or setting it to `0` and later back to a positive value) is a normal governance lever explicitly exposed by the pallet (`update_cost_per_block`, `remove_incentives`), not an adversarial action. Any relayer that then submits the next valid `StateMachineUpdated` consensus proof automatically triggers the overpayment — this requires no special positioning, timing race, or privileged access, making the likelihood high whenever an operator pauses and resumes incentives for a state machine, which the pallet's own API anticipates as routine.

### Recommendation
Advance `LastRewardedHeight` to the state machine's current height whenever the height is observed, regardless of whether a reward is currently configured or computes to zero — mirroring the report's fix of calling `_updatePoolByPid()` unconditionally. Concretely, move the watermark update outside the `if let Some(block_cost)` and outside the `reward.is_zero()` early return, e.g. always set `LastRewardedHeight` to `latest_height` (or `state_machine_height.height`) after reading it in `process_message`, before or regardless of computing/paying `reward`. This ensures a later re-enable of `cost_per_block` only ever prices the blocks that occurred while the incentive was actually active.

### Proof of Concept
1. Set `StateMachinesCostPerBlock[SM] = 100` and drive the chain to height `1000` via `StateMachineUpdated`; `on_executed` pays `100 * (1000 - baseline)` and sets `LastRewardedHeight[SM] = 1000`.
2. Governance calls `remove_incentives(SM)` (or `update_cost_per_block(SM, 0)`).
3. The state machine's consensus continues to advance for a long interval — e.g. to height `1,000,000` — via ordinary `StateMachineUpdated` events; each call into `process_message` skips the `LastRewardedHeight` update because `StateMachinesCostPerBlock::get` is `None`/reward is `0` [4](#0-3) .
4. Governance calls `update_cost_per_block(SM, 100)` again.
5. Any relayer submits the next valid consensus message advancing the height by even 1 block (to `1,000,001`). `calculate_reward` computes `baseline = LastRewardedHeight = 1000`, `blocks = 1,000,001 - 1000 = 999,001`, and pays `100 * 999,001` from the treasury to that single relayer for one submitted proof — vastly more than the single block actually delivered under active incentives.

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,

			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});

	}

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}
