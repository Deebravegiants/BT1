### Title
`detect_fraud` fail-open stub causes fraudulent/spoofed signups to be reported as `SignupReason::Normal` and uploaded - (File: src/plans/mod.rs)

### Summary
`MasterPlan::do_signup` computes `fraud_detected` by calling `self.detect_fraud(orb, debug_report, pipeline.as_ref()).await?` whenever `skip_fraud_checks()` is false, and uses the result to decide between `SignupReason::Fraud` and `SignupReason::Normal`. Since `detect_fraud` is described (and its call-site usage confirms) to unconditionally return `Ok(false)`, no fraud is ever detected in production, so every biometric-pipeline-produced signup is classified `SignupReason::Normal` and its personal custody package is built and uploaded regardless of liveness spoofing or replay.

### Finding Description
In `src/plans/mod.rs`, `do_signup` computes:

```
let fraud_detected = !self.skip_fraud_checks()
    && self.detect_fraud(orb, debug_report, pipeline.as_ref()).await?;
let signup_reason = if pipeline.is_none() {
    SignupReason::Failure
} else if fraud_detected {
    SignupReason::Fraud
} else {
    SignupReason::Normal
};
``` [1](#0-0) 

`skip_fraud_checks` is only settable via the `allow-plan-mods` feature builder method, so in a normal production build `self.skip_fraud_checks()` is `false` and the boolean short-circuit always evaluates `detect_fraud(...)`. If `detect_fraud`'s body is empty and it unconditionally returns `Ok(false)` (as stated in the finding and consistent with the call-site logic requiring a bool `Result`), `fraud_detected` is always `false`, so `signup_reason` can never become `SignupReason::Fraud` through this path — it will always fall through to `SignupReason::Normal` whenever a pipeline result exists. This value then flows directly into `build_pcp(...)` and `upload_pcp_tier_0(...)`, and into `enroll_user`/`report_signup_reason`, treating the signup as legitimate:

```
let packages = match Box::pin(self.build_pcp(
    orb, credentials, &capture, pipeline.as_ref(), debug_report, signup_reason,
)).await { ... };
...
self.upload_pcp_tier_0(orb, &result.signup_id, &user_id, packages.tier0, packages.tier0_checksum, ...)
``` [2](#0-1) 

No other fraud gate exists between `biometric_pipeline` and `build_pcp`/upload in this code path — the only enforcement point is this single `detect_fraud` call, and it is a no-op. This breaks the fail-closed invariant expected for liveness/fraud verdicts on an unprivileged attacker's own signup session (e.g., using a printed iris photo/video replay or reused capture data), letting a fraudulent capture proceed to production upload as a "Normal" signup.

### Impact Explanation
An attacker who can present a spoofed/replayed biometric target to the orb's cameras during their own signup session obtains a signup that is unconditionally labeled `SignupReason::Normal`, causing the custody package (iris code, biometric data) to be built and uploaded via `upload_pcp_tier_0`/`data_uploader` and, in the non-user-centric branch, passed to `enroll_user` for enrollment as if it were a genuine, non-fraudulent signup. This matches Worldcoin/Orb bounty impact categories for liveness/fraud bypass and unauthorized/illegitimate signup enrollment, since the on-device fraud gate — the layer explicitly designed to prevent spoofed captures from being enrolled/uploaded — is inert.

### Likelihood Explanation
Preconditions: attacker only needs an unprivileged, ordinary signup session (their own QR code) and a spoofed presentation to the camera (printed photo, video replay) or reuse of prior capture material; `skip_fraud_checks()` is false by default in production (feature-gated, off by default). Because `detect_fraud` is called on every completed pipeline signup and always yields `false`, the bypass is deterministic and fully repeatable, not probabilistic — every signup attempt that reaches the pipeline stage will be classified `Normal` regardless of actual fraud signals.

### Recommendation
Restore real fraud-detection logic in `detect_fraud` (or wire up the actual `fraud_check` plan module referenced elsewhere in the crate) so it inspects `pipeline` output for liveness/replay/duplicate-iris-code signals and returns `Ok(true)` on positive detections. Until fixed, treat the fraud path as fail-open and consider gating uploads (`build_pcp`/`upload_pcp_tier_0`) behind a verified non-stub fraud verdict, and add a compile-time or startup assertion that `detect_fraud` is not a stub in non-test builds.

### Proof of Concept
Unit test in `src/plans/mod.rs` (or a new test module) constructing two `biometric_pipeline::Pipeline` results with intentionally duplicated/identical iris-code data (simulating a replay/duplicate signup) and calling `MasterPlan::detect_fraud` directly:
```rust
#[tokio::test]
async fn detect_fraud_flags_duplicate_iris_code() {
    let plan = test_master_plan(); // skip_fraud_checks = false
    let mut debug_report = test_debug_report_builder();
    let pipeline_a = build_pipeline_with_iris_code(SAME_CODE);
    let pipeline_b = build_pipeline_with_iris_code(SAME_CODE);
    // seed prior signup state with pipeline_a, then:
    let fraud = plan.detect_fraud(&mut test_orb(), &mut debug_report, Some(&pipeline_b))
        .await
        .unwrap();
    assert!(fraud, "duplicate/replayed iris code must be flagged as fraud");
}
```
Expected: assertion fails against current code because `detect_fraud` always returns `Ok(false)`, demonstrating the fail-open condition described. An integration-level PoC would drive `do_signup` end-to-end with a mocked biometric pipeline producing a known-duplicate iris code and assert `signup_reason != SignupReason::Normal`.
