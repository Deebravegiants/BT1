### Title
Contract loading/compilation gas charge occurs after the expensive load, not before it — free/underpriced work on `FunctionCall` when `fix_contract_loading_cost` is unset - ([File: runtime/near-vm-runner/src/wasmtime_runner/mod.rs])

### Summary
On the current stable protocol version used by this codebase, the WASM contract "loading fee" that is supposed to pay for compiling/deserializing/linking/instantiating a contract is charged **after** that expensive work has already been performed, not before, mirroring exactly the reported EVM pattern: unpriced/uncharged work happens ahead of the gas check meant to price it.

### Finding Description
`WasmtimeVM::with_compiled_and_loaded` performs contract cache lookup, and on a cache miss, full compilation (`compile_and_cache`), `Module::deserialize`, export resolution, `Linker::instantiate_pre`, are executed before any gas is charged for loading. [1](#0-0) 

Only after all of that work completes does the caller invoke `before_loading_executable`/`after_loading_executable`, which is where the loading-fee gas check (`add_contract_loading_fee`) actually happens: [2](#0-1) 

The gas-check function itself makes the ordering explicit via the `fix_contract_loading_cost` config flag: when it is `false` (the default on the current stable protocol version, per the spec), the loading fee is charged in `after_loading_executable`, i.e. strictly after the compile/load work, rather than `before_loading_executable` (pre-charge): [3](#0-2) 

The spec documentation for this codebase confirms `fix_contract_loading_cost` is `false` on the active stable protocol version (2.13.0 / PV 86), with the pre-charge fix gated to a nightly-only protocol feature that is not active: "On 2.13.0 mainnet `fix_contract_loading_cost` is `false` (the fix is nightly-only, PV 129), so the loading fee is charged post-load." [4](#0-3) 

This is the direct structural analog of the EVM report: "gas checks should be done as soon as possible to avoid unnecessary work... if there were an error in these prior checks, it wouldn't cost the caller anything." Here, the "prior operation" is compilation/deserialization/linking/instantiation (CPU-bound, non-trivial work for large contracts), and the "gas check" is the loading-fee charge that is meant to make the caller pay for that exact work.

### Impact Explanation
An attacker can submit a `FunctionCall` action with a low `prepaid_gas` value against a large, not-yet-cached (or evicted-from-cache) contract. The validator/runtime must fully compile, deserialize, link, and instantiate the module *before* discovering (via `add_contract_loading_fee`) that the attached gas was insufficient to pay for that work, at which point the call aborts as `GasExceeded`/`HostError` — a graceful, gas-bearing outcome, but one whose loading-fee charge does not reflect the compile/link/instantiate cost actually incurred if the transaction fails for gas reasons before or at that late charge point. This is an underpriced/uncharged-CPU-work pattern reachable by any unprivileged account via ordinary `FunctionCall` receipts. Because compiled artifacts are cached (`AnyCache`/on-disk LRU), the practical severity is bounded by cache hit rates and eviction behavior, but cache misses (new/large/varied contracts, or cache pressure causing eviction) let this be repeated. This matches the "free or underpriced execution" impact category.

### Likelihood Explanation
This is not a hypothetical or contrived path — it is the default, always-active ordering on the current stable protocol version (`fix_contract_loading_cost == false`), reachable through the standard `FunctionCall` action path used by every contract call. No malicious validator/peer or privileged access is required; any account submitting a transaction that calls an under-provisioned `FunctionCall` against a large/uncached contract exercises this path. The codebase's own protocol-model documentation flags this exact ordering issue and the pending (but not yet activated) fix, corroborating that the underpricing window is real and currently live on stable. [5](#0-4) 

### Recommendation
Charge (or reserve) the loading fee based on the contract's known code length before performing compilation/deserialization/linking/instantiation, i.e., make `before_loading_executable`'s pre-charge path (`config.fix_contract_loading_cost == true`) the unconditional default rather than gating it behind a not-yet-activated protocol feature, so that a caller with insufficient gas is rejected before the runtime performs the expensive load/link/instantiate work. [6](#0-5) 

### Proof of Concept
1. Deploy a large WASM contract (near `max_contract_size`) to a fresh account so its compiled artifact is not yet cached (or ensure cache eviction by deploying enough distinct large contracts to exceed the on-disk/in-memory cache size).
2. Submit a `FunctionCall` action targeting that contract with `prepaid_gas` set just above the minimum required to build the receipt but below what `contract_loading_base + contract_loading_bytes * code_len` would require.
3. Observe that the runtime performs full cache-miss compilation, `Module::deserialize`, `Linker::instantiate_pre` (`runtime/near-vm-runner/src/wasmtime_runner/mod.rs:704-801`) before the loading-fee gas check in `after_loading_executable` (`runtime/near-vm-runner/src/logic/gas_counter.rs:259-272`) rejects the call with `GasExceeded`.
4. Repeat with varied contracts/cache-eviction pressure to induce repeated cache misses, each incurring full compile/link/instantiate cost that is not fully recouped by the (correctly sized, but too-late) loading-fee charge when the call is rejected for insufficient gas.

Note: I was not able to fully trace the on-disk/in-memory cache eviction thresholds or exact `LimitConfig::max_contract_size` value in this pass, nor precisely quantify how much CPU work occurs before vs. after the fee charge relative to typical block gas limits; a background Devin session with full repo/build access would be needed to benchmark actual exploitability bounds.

    /// VM independent setup before loading the executable.
    ///
    /// Does VM independent checks that happen after the instantiation of
    /// VMLogic but before loading the executable. This includes pre-charging gas
    /// costs for loading the executable, which depends on the size of the WASM code.
    #[cfg(feature = "wasmtime_vm")]
    pub(crate) fn before_loading_executable(
        &mut self,
        config: &near_parameters::vm::Config,
        method_name: &str,
        wasm_code_bytes: u64,
    ) -> std::result::Result<(), super::errors::FunctionCallError> {
        if method_name.is_empty() {
            let error = super::errors::FunctionCallError::MethodResolveError(
                super::errors::MethodResolveError::MethodEmptyName,
            );
            return Err(error);
        }
        if config.fix_contract_loading_cost {
            if self.add_contract_loading_fee(wasm_code_bytes).is_err() {
                let error =
                    super::errors::FunctionCallError::HostError(super::HostError::GasExceeded);
                return Err(error);
            }
        }
        Ok(())
    }

    /// Legacy code to preserve old gas charging behaviour in old protocol versions.
    #[cfg(feature = "wasmtime_vm")]
    pub(crate) fn after_loading_executable(
        &mut self,
        config: &near_parameters::vm::Config,
        wasm_code_bytes: u64,
    ) -> std::result::Result<(), super::errors::FunctionCallError> {
        if !config.fix_contract_loading_cost {
            if self.add_contract_loading_fee(wasm_code_bytes).is_err() {
                return Err(super::errors::FunctionCallError::HostError(
                    super::HostError::GasExceeded,
                ));
            }
        }
        Ok(())
    }

`WasmtimeVM::with_compiled_and_loaded` (`runtime/near-vm-runner/src/wasmtime_runner/mod.rs:683`) resolves the compiled artifact through a two-level cache (see §7), then charges the loading fee. Ordering (load-bearing):
1. Look up `ContractCacheKey` in the in-memory `AnyCache`, then the on-disk cache; on a miss, fetch code via `Contract::get_code` and `compile_and_cache` (`:606`); a compile failure is stored/returned as `CompiledContract::CompileModuleError` (`mod.rs:723`).
2. `deserialize` the module, resolve the `memory` export (missing ⇒ `LinkError`), build a `Linker`, `link` host functions (`mod.rs:1127`), and `instantiate_pre`.
3. `before_loading_executable` (`gas_counter.rs:236`): reject empty `method_name` (`MethodResolveError::MethodEmptyName`); if `fix_contract_loading_cost` is set, pre-charge `add_contract_loading_fee` (`contract_loading_base` + `contract_loading_bytes * code_len`, `gas_counter.rs:225`) — on OOG return `HostError::GasExceeded` as an abort.
4. `after_loading_executable` (`gas_counter.rs:260`): if `fix_contract_loading_cost` is **not** set, charge the loading fee *after* loading instead (legacy ordering). On 2.13.0 mainnet `fix_contract_loading_cost` is `false` (the fix is nightly-only, PV 129), so the loading fee is charged post-load.
