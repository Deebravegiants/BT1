### Title
Bad-debt wipeout leaves stranded supply claims that drain the next fresh deposit - (File: contracts/pool/src/interest.rs)

### Summary
The Wallos bug class — an unauthenticated path whose only real guard is "the store is empty" — maps onto `apply_bad_debt_to_supply_index` in the pool. When socialized bad debt equals or exceeds total supplied value, the supply index is clamped UP to `SUPPLY_INDEX_FLOOR_RAW` (`RAY/1000`) instead of zeroing/burning supplier shares. Every surviving supplier thereby keeps a residual claim. While `cash == 0` the claim is masked by `require_reserves`; the moment any user makes a fresh deposit, a wiped-out supplier can `withdraw` and pay themselves entirely out of the victim's cash.

### Finding Description
`apply_bad_debt_to_supply_index` (contracts/pool/src/interest.rs:73-89) reduces `supply_index` pro-rata by `capped = min(bad_debt, total_supplied_value)`, then floors the result at `SUPPLY_INDEX_FLOOR_RAW`. When `bad_debt >= total_supplied_value`, `remaining` is zero but the index is still set to `RAY/1000`, so `unscale_supply_floor(supplied) > 0` for every pre-existing share — a phantom claim backed by nothing.

The only thing preventing payout is `cache.require_reserves(net_transfer)` in `gate_and_debit` (contracts/pool/src/ops/withdraw.rs:111-118), i.e., the check passes only because `cash == 0`. There is no guard distinguishing real claims from post-wipeout residuals. The in-repo test `test_raw_cache_seizure_residual_would_drain_fresh_cash_without_supply_guard` (contracts/pool/tests/interest.rs:431-495) proves the exploit end-to-end on the real `Cache`: after the clamp, a fresh deposit is minted honest shares, the stranded holder calls `resolve_withdrawal(i128::MAX, ...)`, `require_reserves` passes against the fresh cash, and `gross == deposit` — the wiped position extracts exactly the new depositor's funds.

Reachable path for a single unprivileged address:
1. Attacker holds supply shares in a market that later suffers a wipeout: bad debt ≥ total supplied value via `clean_bad_debt` / liquidation `execute_bad_debt_cleanup` (permissionless once debt > collateral and collateral ≤ $5).
2. Wait for a victim `supply` into the same market (or a `recapitalize`).
3. Attacker calls `controller.withdraw(caller, account_id, [(hub_asset, i128::MAX)], to)` — `apply` → `accounting` → `gate_and_debit` pays out the stranded claim from the victim's cash. No auth beyond owning the wiped account; no HF check is needed for withdraw.

### Impact Explanation
Theft of user funds / permanent loss for fresh depositors: any tokens supplied to a previously wiped market can be immediately drained by legacy share holders whose positions were already written down to the floor. Repeatable per deposit until `recapitalize` or withdrawals exhaust the phantom claims.

### Likelihood Explanation
Requires a full-wipeout bad-debt event (unpaid debt ≥ total supplied value) in a market that subsequently attracts new deposits — uncommon but realistic after a catastrophic collateral crash leaving dust-collateral insolvent accounts. Medium severity: conditional on a severe loss event, but deterministic theft once it occurs.

### Recommendation
On wipeout, burn or zero the surviving scaled supply (e.g., convert the residual floor claim to zero by tracking a wipeout flag/generation, or mint fresh-epoch shares) rather than clamping the index up to a nonzero floor. Alternatively, gate `withdraw`/`resolve_withdrawal` so claims created before a floor-clamp cannot draw on cash credited after it, and have `recapitalize` retire stranded shares before accepting fresh backing.

### Proof of Concept
Already encoded in the production test suite: `contracts/pool/tests/interest.rs` lines 431-495 (`test_raw_cache_seizure_residual_would_drain_fresh_cash_without_supply_guard`) and the equivalent scenario at lines 340-368. Key steps on the live `Cache`:

```rust
// state: supplied = borrowed = 1000*RAY, indexes = RAY, cash = 0
let bad_debt = cache.unscale_borrow_ceil_ray(borrow_scaled);
apply_bad_debt_to_supply_index(&mut cache, bad_debt);   // index -> RAY/1000 floor
cache.burn_debt(borrow_scaled);
let alice_stranded = cache.unscale_supply_floor(alice_scaled); // > 0

// victim deposits `alice_stranded` fresh cash
let bob_scaled = cache.calculate_scaled_supply(deposit);
cache.mint_supply(bob_scaled);
cache.credit_cash(deposit);

// attacker withdraws: gross == victim's deposit
let (burn, gross) = cache.resolve_withdrawal(i128::MAX, alice_scaled);
cache.require_reserves(gross);   // passes only because fresh cash exists
cache.burn_supply(burn);
cache.debit_cash(gross);         // cash < bob_claim: victim's funds lost
```

Relevant code: `apply_bad_debt_to_supply_index` at `contracts/pool/src/interest.rs:73-89`; withdraw gate at `contracts/pool/src/ops/withdraw.rs:111-118`.
