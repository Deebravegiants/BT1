### Title
SimplexPaymaster uses a single global `maxOracleAge` staleness threshold for all Chainlink price feeds regardless of each feed's actual heartbeat, allowing stale prices to be accepted as valid - ([File: evm/src/utils/SimplexPaymaster.sol])

### Summary
`SimplexPaymaster` prices ERC-20 gas payments using two independent Chainlink feeds — a single native/USD oracle shared by all tokens, and a per-token token/USD oracle — but validates staleness for *both* against one contract-wide `maxOracleAge` value, exactly the bug class described in the Sherlock report: a constant staleness threshold applied uniformly to feeds that have materially different real-world heartbeats.

### Finding Description
`_getOraclePrice` is the sole staleness check for every price read in the contract, and it compares `block.timestamp - updatedAt` against the single stored `maxOracleAge`: [1](#0-0) 

That single value is used for both the `nativeOracle` and every registered token's `tokenOracle` inside `_tokenPrice`: [2](#0-1) 

The contract's own documentation acknowledges that Chainlink heartbeats differ drastically per chain/asset ("BSC stablecoins ~27s, Base/Ethereum stablecoins up to 24h"), yet only one governance-settable ceiling (`MAX_ORACLE_AGE = 7 days`) bounds a single `maxOracleAge` field shared across every oracle: [3](#0-2) [4](#0-3) 

`RegisterToken` lets governance add any ERC-20 with any Chainlink feed, but `_registerToken` stores no per-token staleness bound at all — only the oracle address and decimals: [5](#0-4) 

Because `maxOracleAge` must be sized loosely enough to tolerate the slowest-heartbeat feed registered (e.g., a 24h-heartbeat stablecoin feed), a fast-heartbeat feed (e.g., BSC's ~27s stablecoin feed, or any native-asset feed with a short heartbeat) can go stale for a long time — up to `maxOracleAge` — while `_getOraclePrice` still reports it as fresh. This is the direct analog of the Sherlock M-6 finding: a constant threshold that is correct for some feeds is dangerously loose for others sharing the same check.

### Impact Explanation
Any address can trigger this pricing path by submitting an ERC-4337 `PackedUserOperation` through the EntryPoint using `SimplexPaymaster` as paymaster (mode 0x00 permit or mode 0x02 Permit2) — this is fully permissionless, unprivileged bandwidth-purchaser-style access, matching Hyperbridge's in-scope reachable surfaces. `_prefund`/`_erc20Cost` computed from `_tokenPrice` determines how many ERC-20 tokens are pulled to cover `maxCost` of gas: [6](#0-5) 

If the native-asset feed or the token feed has gone stale (feed frozen/underlying market halted) for longer than its real heartbeat but shorter than the shared `maxOracleAge`, the paymaster keeps charging users at a wrong (stale) native/token exchange rate. Depending on price direction this either:
- undercharges users relative to the true market rate, directly draining the paymaster's treasury/surplus (a value-extraction/theft vector reachable by any UserOp sender who is aware the feed has diverged), or
- overcharges users, taking excess funds from their signed permit allowance.

Both are concrete fund-impact outcomes stemming from unsound price validation, not merely a low-severity inconvenience.

### Likelihood Explanation
Likelihood is moderate: it requires (a) governance to register a token whose Chainlink feed has a materially shorter heartbeat than `maxOracleAge`, or the shared native oracle's real heartbeat to be shorter than the configured `maxOracleAge`, and (b) that feed to actually stop updating (a real-world Chainlink degradation/outage, which has occurred historically for various feeds) while still within the loose global window. No malicious admin action is required — the existing governance-set `maxOracleAge` combined with normal token onboarding is sufficient to create the exposure, and any user can then submit ordinary UserOps to exploit the mispricing during the stale window.

### Recommendation
Store a per-oracle staleness bound instead of one contract-wide `maxOracleAge`: add a `maxAge` field to `TokenConfig` (and a dedicated bound for `nativeOracle`), validated against each feed's real heartbeat at `RegisterToken`/`UpdateParams` time, and check `_getOraclePrice` against the oracle-specific bound rather than the shared constant/param.

### Proof of Concept
1. Governance registers `TokenA` with a Chainlink feed whose real heartbeat is 27 seconds (e.g., a fast BSC stablecoin feed) alongside `nativeOracle`/other tokens needing a looser bound, and sets `maxOracleAge` to, say, 3600s to accommodate a slower feed elsewhere.
2. `TokenA`'s feed stops updating for 1800 seconds due to a market/keeper issue — far beyond its 27s heartbeat but well inside the shared 3600s `maxOracleAge`.
3. A user submits a UserOperation with mode 0x00/0x02 `paymasterData` naming `TokenA`; `_prefund` → `_tokenPrice` → `_getOraclePrice` reads `TokenA`'s stale `latestRoundData()` and, since `block.timestamp - updatedAt (1800) <= maxOracleAge (3600)`, treats it as valid: [1](#0-0) 
4. Gas cost is computed and pulled from the user (or credited against the treasury) using the stale, mispriced rate, resulting in an incorrect token amount transferred relative to the true current market price.

    function _registerToken(address token, AggregatorV3Interface oracle) internal {
        if (token == address(0) || address(oracle) == address(0)) revert ZeroAddress();

        bool isNew = !tokenConfigs[token].active && address(tokenConfigs[token].tokenOracle) == address(0);

        tokenConfigs[token] = TokenConfig({
            tokenOracle: oracle,
            tokenOracleDecimals: oracle.decimals(),
            tokenDecimals: IERC20Metadata(token).decimals(),
            active: true
        });

        if (isNew) {
            registeredTokens.push(token);
        }

        emit TokenRegistered(token, address(oracle));
    }

    function _prefund(
        PackedUserOperation calldata userOp,
        bytes32 userOpHash,
        IERC20 token,
        uint256 tokenPrice,
        address prefunder_,
        uint256 maxCost
    )
        internal
        override
        returns (bool prefunded, uint256 prefundAmount, address prefunder, bytes memory prefundContext)
    {
        bytes calldata data = userOp.paymasterData();
        if (uint8(data[0]) != 0x02) {
            return super._prefund(userOp, userOpHash, token, tokenPrice, prefunder_, maxCost);
        }

        (, uint256 permitAmount, uint256 nonce, uint256 deadline, uint8 v, bytes32 r, bytes32 s) =
            _parsePermit2Data(data);
        prefundAmount = _erc20Cost(maxCost, userOp.maxFeePerGas(), tokenPrice);
        if (prefundAmount > permitAmount) revert InsufficientPermitAmount(permitAmount, prefundAmount);
        // Solidity's own extcodesize revert on a code-less target is not caught by try/catch.
        if (address(PERMIT2).code.length == 0) revert Permit2NotDeployed();

        // Charge the token _fetchDetails already validated as registered and active, rather
        // than re-trusting the mode byte's token field, so the external call never depends
        // on the caller-ordering of the base contract.
        address tokenAddr = address(token);
        // `prefunder_` is who the base says funds the op (userOp.sender today); use it so this
        // branch stays aligned with the mode-0 branch that forwards it to super._prefund.
        address owner = prefunder_;
        try PERMIT2.permitTransferFrom(
            ISignatureTransfer.PermitTransferFrom({
                permitted: ISignatureTransfer.TokenPermissions({token: tokenAddr, amount: permitAmount}),
                nonce: nonce,
                deadline: deadline
            }),
            ISignatureTransfer.SignatureTransferDetails({to: address(this), requestedAmount: prefundAmount}),
            owner,
            abi.encodePacked(r, s, v)
        ) {
            emit Permit2Executed(tokenAddr, owner, prefundAmount, nonce);
        } catch (bytes memory reason) {
            revert Permit2Failed(tokenAddr, reason);
        }

        return (true, prefundAmount, owner, "");
    }

    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
