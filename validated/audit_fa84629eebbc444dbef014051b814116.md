## Title
Self-Transfer of an Object Creates a Self-Owned Object Address, Permanently Locking the Object and All Held Assets - (File: `aptos-move/framework/aptos-framework/sources/object.move`)

### Summary
`object::transfer_raw` / `transfer` / `transfer_call` set `ObjectCore.owner` to an arbitrary `to` address without ever checking that `to` is different from the object's own address [1](#0-0) . A legitimate owner can call `transfer_call(owner, object_addr, object_addr)` (transfer the object to itself), which passes `verify_ungated_and_descendant` trivially (the check only verifies the *caller* is/derives authority over the current owner, not anything about `to`) [2](#0-1)  and then sets `object_core.owner = to`, making the object own itself.

### Finding Description
`transfer_raw` performs the authority check via `verify_ungated_and_descendant(owner_address, object)`, which walks the ownership chain of `object` and asserts that `owner_address` is reached within `MAXIMUM_OBJECT_NESTING` hops [2](#0-1) . This check only validates that the caller controls the object; it never inspects the destination address `to`. `transfer_raw_inner` then unconditionally writes `object_core.owner = to` [3](#0-2) .

If a rightful owner calls `object::transfer_call(owner, object_addr, object_addr)` (or `transfer`/`transfer_to_object` with `to == object.inner`), the resulting `ObjectCore.owner` field is set to the object's own address. Because an object address has no corresponding private key/signer that the VM will natively produce as a transaction sender, the object becomes uncontrollable through the normal transfer/ownership-authority path — no external signer can ever again satisfy `owner_address == object.owner` in `verify_ungated_and_descendant`/`is_owner`.

Additionally, `root_owner()` has no cycle/nesting protection at all — unlike `owns()` and `verify_ungated_and_descendant()`, which both guard iteration with `MAXIMUM_OBJECT_NESTING` [4](#0-3) , `root_owner` loops `while (is_object(obj_owner)) { obj_owner = ...owner() }` with no bound [5](#0-4) . A self-owned object (owner == own address) causes this function to loop forever until it exhausts gas, and any code path depending on `root_owner` (e.g., royalty/collection resolution logic in token modules) for such an object will always abort.

This is the direct custody analog to the external `RewardsMath` bug: a "self-pointing" state update (there, `linkedListTPSS[x] = x`; here, `ObjectCore.owner = self`) silently corrupts a control-flow invariant (linked-list validity / ownership validity) because no guard rejects the degenerate self-referential value.

### Impact Explanation
Once `ObjectCore.owner` at address `X` equals `X` itself:
- No signer can ever again pass the `owner_address == object.owner` check used by `transfer`, `burn` (`is_owner` check) [6](#0-5) , `TransferRef` generation (`generate_linear_transfer_ref` reads `owner`) [7](#0-6) , or any fungible-asset/token-object operation gated by `object::owns`/`object::owner` (e.g. `fungible_asset::withdraw_sanity_check`, `upgrade_store_to_concurrent`'s `object::owns` check) [8](#0-7) .
- Any `FungibleStore`, token, or other resource held at or under that object address becomes **permanently non-transferable and non-recoverable** — a direct "permanent lock or non-recoverable loss of object-held value," which is explicitly in scope of the custody impact gate.
- `root_owner()` becomes an unbounded loop for that object, causing gas-exhaustion aborts wherever it (or code depending on it) is invoked.

This is a high-severity, unprivileged, user-triggerable (even if only against the caller's own object) bug because it can permanently strand real value (APT via `FungibleStore`, NFTs/token objects, etc.) with no governance or admin recovery path, since `TransferRef`/`ExtendRef` capabilities also route through the same broken `owner` field semantics for ungated flows, and no owner-derived signer for the self-owned object can ever be produced through the normal object framework.

### Likelihood Explanation
Likelihood is high for the "self-lock" scenario: any object owner (mistakenly, via a buggy dApp/integration passing the object's own address as `to`, or an attacker tricking a victim into signing such a transfer) can trigger it with one transaction and no special privileges. It requires no timing race and no economic cost beyond gas. The `root_owner` DoS is a natural side-effect that also fires whenever any code queries the root owner of the now-self-owned object.

### Recommendation
1. In `transfer_raw` (and by extension `transfer`, `transfer_call`, `transfer_to_object`, `transfer_with_ref`), explicitly reject `to == object` (self-transfer to own address) with an assertion, e.g. `assert!(object != to, error::invalid_argument(ECANNOT_TRANSFER_TO_SELF));`.
2. Add the same nesting/cycle bound used in `owns`/`verify_ungated_and_descendant` to `root_owner`, so that any pre-existing or newly formed cyclic ownership graph cannot cause unbounded loops/gas exhaustion.
3. Consider validating on every ownership write that the new owner graph, walked to `MAXIMUM_OBJECT_NESTING` depth, does not point back to `object` itself, closing off multi-hop self-referential cycles (e.g., A owned by B, then B transferred into A).

### Proof of Concept
```move
// Pseudocode illustrating the self-lock
let (creator_ref, obj) = object::create_object(signer::address_of(owner));
let obj_addr = object::object_address(&obj);
// owner is the legitimate current owner of obj (obj.owner == address_of(owner))
object::transfer_call(owner, obj_addr, obj_addr); // to == object itself
// Now: ObjectCore.owner at obj_addr == obj_addr
// Any future call requiring object::owns(obj, some_signer) or object::is_owner(obj, some_signer)
// will fail for every possible signer, since no signer address can equal obj_addr through
// normal transaction submission.
// object::root_owner(obj) now loops forever (is_object(obj_addr) is always true, owner is always obj_addr).
```

Note: I was unable to fully verify within the available tool budget whether any framework-level guard (e.g., in the VM's session/transaction validation layer, outside `object.move`) independently prevents an object address from being submitted or resolved as `to` in these entry functions; the plan above is scoped strictly to the Move-level logic in `object.move`, which contains no such check.

        let object_core = borrow_global_mut<ObjectCore>(object);
        if (object_core.owner != to) {
            event::emit(
                Transfer {
                    object,
                    from: object_core.owner,
                    to,
                },
            );
            object_core.owner = to;
        };

    fun verify_ungated_and_descendant(owner: address, destination: address) {
        let current_address = destination;
        assert!(
            exists<ObjectCore>(current_address),
            error::not_found(EOBJECT_DOES_NOT_EXIST),
        );

        let object = borrow_global<ObjectCore>(current_address);
        assert!(
            object.allow_ungated_transfer,
            error::permission_denied(ENO_UNGATED_TRANSFERS),
        );

        let current_address = object.owner;
        let count = 0;
        while (owner != current_address) {
            count += 1;
            assert!(count < MAXIMUM_OBJECT_NESTING, error::out_of_range(EMAXIMUM_NESTING));
            // At this point, the first object exists and so the more likely case is that the
            // object's owner is not an object. So we return a more sensible error.
            assert!(
                exists<ObjectCore>(current_address),
                error::permission_denied(ENOT_OBJECT_OWNER),
            );
            let object = borrow_global<ObjectCore>(current_address);
            assert!(
                object.allow_ungated_transfer,
                error::permission_denied(ENO_UNGATED_TRANSFERS),
            );
            current_address = object.owner;
        };
    }

    public fun owns<T: key>(object: Object<T>, owner: address): bool {
        let current_address = object.object_address();

        assert!(
            exists<ObjectCore>(current_address),
            error::not_found(EOBJECT_DOES_NOT_EXIST),
        );

        if (current_address == owner) {
            return true
        };

        let object = borrow_global<ObjectCore>(current_address);
        let current_address = object.owner;

        let count = 0;
        while (owner != current_address) {
            count += 1;
            assert!(count < MAXIMUM_OBJECT_NESTING, error::out_of_range(EMAXIMUM_NESTING));
            if (!exists<ObjectCore>(current_address)) {
                return false
            };

            let object = borrow_global<ObjectCore>(current_address);
            current_address = object.owner;
        };
        true
    }
