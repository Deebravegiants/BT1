### Title
Uniswap V4 venue pricing uses manipulable spot price (`slot0`), not a TWAP, to price and fill intent orders - ([File: sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts])

### Summary
The `FXFiller` reference solver (`sdk/packages/simplex`) prices "venue-priced" trading pairs (pairs with no static bid/ask curve) directly from a Uniswap V4 pool's current spot price, exactly the bug class described in the report: reading `sqrtPriceX96`/tick from `slot0` instead of a time-weighted average. This price feeds order pricing and fills, and the only defense is an *optional* static reference-price guard that operators are explicitly told they may leave unset.

### Finding Description
`UniswapV4FundingPlanner.getExoticTokenPrice` and `computeDirectPoolPriceUsd` derive the USD price of the non-stable leg token straight from the pool's live `sqrtPrice`/tick, via the SDK `V4Pool.token0Price`/`token1Price`: [1](#0-0) 
This state is refreshed from `StateView.getSlot0` (the pool's instantaneous `sqrtPriceX96`/`tick`), i.e. a spot price, not any cumulative/TWAP observation: [2](#0-1) 

This spot price is consumed by the `FXFiller` strategy through `getVenueUsdPrice`/`venuePriceMemo`, which is used both to compute a leg's reference rate for order acceptance/sizing and as the actual pricing source for venue-priced legs when no static curve exists: [3](#0-2) [4](#0-3) 

The maintainers' own flow documentation confirms the price is the "raw pool mid" derived from `sqrtPriceX96` with no size/impact adjustment, and that `checkPriceGuard` is the *only* defense on this path: [5](#0-4) 

Crucially, that guard is optional per chain, and the documentation explicitly instructs operators that omitting both `referencePrice` and `maxDeviationBps` leaves the chain "unguarded": [6](#0-5) 
The guard implementation itself only rejects a quote when a guard is configured for that chain; absent a guard it always passes: [7](#0-6) 

This is functionally identical to the reported `USSDRebalancer.getOwnValuation` bug: a DeFi-facing valuation function reads a Uniswap pool's instantaneous `sqrtPriceX96` and treats it as ground truth, with no TWAP or manipulation-resistant oracle backing the automated economic decision (rebalance / order-fill) it drives.

### Impact Explanation
An intent order routed to a venue-priced (curve-less) pair is priced by whatever the Uniswap V4 pool's spot price says at evaluation/fill time. An attacker who can move that pool's spot price within a single transaction (flash-swap/flash-loan against the same pool or a correlated one, since there is no size/impact term applied either) can:
1. Skew the pool's `sqrtPriceX96` to make the exotic token appear artificially cheap or expensive.
2. Submit (or have pending) an IntentGateway order that the `FXFiller` will price/fill against that manipulated venue price via `getExoticTokenPrice`/`computeDirectPoolPriceUsd`.
3. Extract value from the solver's own inventory at the manipulated rate, then reverse the pool manipulation, realizing profit at the solver's expense — a direct theft-of-funds vector for any operator running the reference filler with venue pricing enabled and no (or a loosely-configured) price guard.

Because `checkPriceGuard` is optional and disabled by default absent explicit configuration, deployments that follow the documented minimal setup (curve-less pair + Uniswap V4 position, no `referencePrice`/`maxDeviationBps`) have no protection at all against this class of attack.

### Likelihood Explanation
Likelihood is high for any solver operator who configures a venue-priced pair without the optional guard, which the documentation presents as a valid, supported configuration ("omit both to leave the chain unguarded"). Even with the guard configured, it only checks deviation from a static reference and not execution cost/size, and the underlying spot price used to compute the "current" quote and enforce the deviation check is itself the manipulated value at read-time — so a sufficiently well-funded manipulation within the guard's `maxDeviationBps` tolerance still succeeds. Triggering the attack requires only a single flash-loan-funded swap plus a normally-submitted intent order, both of which are actions available to any unprivileged user/solver interacting with the public IntentGateway/Uniswap pool.

### Recommendation
Replace the spot-price read (`getSlot0`) used in `UniswapV4FundingPlanner`/`UniswapV4LiquidityState` with a TWAP derived from the pool's cumulative tick/price observations (or an external, manipulation-resistant oracle) before it is used to price or size any order. If spot price must be retained for UX/latency reasons, make the price guard (`referencePrice`/`maxDeviationBps`) mandatory rather than optional for every venue-priced pair, and additionally bound the deviation check against a short TWAP window rather than a single-block spot read, so a same-block/same-transaction manipulation cannot pass the guard.

### Proof of Concept
1. Configure an `FXFiller` with a curve-less pair (e.g. `USDC/EXOTIC`) backed by a `[vault.uniswapV4]` position, per the documented minimal setup, and without setting `referencePrice`/`maxDeviationBps` (a supported, documented configuration) — see `docs/content/developers/evm/simplex/pricing.mdx` lines 48-66.
2. Attacker flash-loans funds and performs a large swap against the same Uniswap V4 pool used by the position, moving `slot0.sqrtPriceX96` far from the pool's fair value.
3. In the same block (or immediately after), attacker submits an IntentGateway order whose leg matches this pair; when the filler evaluates/fills it, `UniswapV4FundingPlanner.getExoticTokenPrice` → `computeDirectPoolPriceUsd` reads the manipulated `slot0` price (`sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts:246-272`), and `FXFiller.getVenueUsdPrice`/venue rate resolution prices the fill off that skewed quote (`sdk/packages/simplex/src/strategies/fx.ts:390-420`, `1339-1364`).
4. The filler fills the order at the manipulated rate, transferring more value than intended from its inventory to the attacker.
5. Attacker reverses the initial swap (repays the flash loan) and nets the difference — analogous to steps 2-7 of the original report's attack narrative, but against the Uniswap V4-backed intent-solver pricing path instead of `USSDRebalancer`.

	/**
	 * Queries funding venues for `token1Address`'s USD price on a chain.
	 * Uniswap V4 is preferred; falls back to other venues. Returns null when no
	 * venue can price the token there.
	 */
	private async getVenueUsdPrice(chain: string, token1Address: string): Promise<Decimal | null> {
		if (this.fundingVenues.length === 0) return null

		// Prefer V4, fall back to others
		const v4 = this.fundingVenues.filter((v) => v.name === "UniswapV4")
		const venues = v4.length > 0 ? v4 : this.fundingVenues

		for (const venue of venues) {
			const usdPrice = await venue.getExoticTokenPrice(chain, token1Address)
			if (usdPrice?.isPositive()) return usdPrice
		}
		return null
	}

	/** Per-evaluation memo over `getVenueUsdPrice`, keyed by (chain, token1). */
	private venuePriceMemo(): (chain: string, token1Address: string) => Promise<Decimal | null> {
		const cache = new Map<string, Decimal | null>()
		return async (chain: string, token1Address: string) => {
			const key = `${chain}:${token1Address}`
			const cached = cache.get(key)
			if (cached !== undefined) return cached
			const price = await this.getVenueUsdPrice(chain, token1Address)
			cache.set(key, price)
			return price
		}
	}

	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {
			this.logger.warn(
				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
	}

	/**
	 * Minimum-size reference rate (token1 per token0) for a leg's pair: the
	 * bid curve at 0 (the side token1-input legs trade at), falling back to the
	 * ask curve, then the live venue quote for venue-priced pairs.
	 */
	private async referenceRate(
		leg: ResolvedLeg,
		venueUsdPrice: (chain: string, token1Address: string) => Promise<Decimal | null>,
	): Promise<Decimal | null> {
		const policy = leg.pair.bidPricePolicy ?? leg.pair.askPricePolicy
		if (policy) {
			const rate = policy.getPrice(new Decimal(0))
			return rate.gt(0) ? rate : null
		}
		// Venue-priced pair: token0 is USD-stable (constructor invariant), so the
		// venue's USD-per-token1 quote inverts straight into token1-per-token0.
		const venueUsd = await venueUsdPrice(leg.token1Chain, leg.token1Address)
		if (!venueUsd) return null
		const venueRate = new Decimal(1).div(venueUsd)
		// Same guard as trade pricing: this rate sizes the order's USD notional
		// for confirmation depth, and a manipulated pool understating the value
		// would shrink the reorg protection — the exact attack the guard exists
		// to stop. Refusing to size skips the order, consistent with pricing.
		if (!this.checkPriceGuard(undefined, leg.token1Chain, venueRate)) return null
		return venueRate
	}

```text
## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.

```toml lineNumbers
[vault.uniswapV4]
# referencePrice is the expected cNGN per USD;
# reject if the quote is more than 2% off.
# The two go together — one without the other is rejected.
[[vault.uniswapV4.positions]]
chain           = "EVM-8453"
tokenId         = "2087350"
referencePrice  = "1575"
maxDeviationBps = 200
```
