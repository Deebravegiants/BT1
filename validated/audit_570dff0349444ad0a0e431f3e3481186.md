Audit Report

## Title
Unbounded, unauthenticated pending-request map growth causes gateway DoS - (File: `core/services/gateway/handlers/confidentialrelay/handler.go`)

## Summary
The Confidential Relay gateway handler's `HandleJSONRPCUserMessage` is the entry point for arbitrary, unauthenticated external HTTP callers reaching the Gateway's public endpoint, and it accepts every syntactically valid request (only requiring a unique, ≤200-char ID) and unconditionally inserts it into the in-memory `activeRequests` map before any authorization, allowlist check, or per-caller rate limiting. [1](#0-0)  Because there is no cap on the number of concurrently pending requests and no inbound throttle ahead of this allocation, a networked attacker can grow the map (plus its associated mutexes, response maps, and per-request fan-out goroutines) faster than the timeout/cleanup ticker can reclaim them, exhausting gateway memory/goroutines.

## Finding Description
`gateway.ProcessRequest` is the HTTP-facing decode/dispatch path: it decodes any raw JSON-RPC payload, resolves a handler by service name, and — for non-legacy requests — calls `h.HandleJSONRPCUserMessage(ctx, jsonRequest, callback)` directly, with no authentication or allowlist gate at this layer beyond an ID-length check. [2](#0-1)  The underlying `httpServer.handleRequest` only bounds the raw request body size via `MaxRequestBytesLimiter`; it extracts an optional bearer token but performs no authentication decision itself before calling `ProcessRequest`. [3](#0-2) 

In `confidentialrelay/handler.go`, `HandleJSONRPCUserMessage` performs only an empty/length check on `req.ID`, then calls `newActiveRequest` and fans the request out to every DON member — with no call into any authorization/allowlist component and no rate limiter gating the incoming user request. [1](#0-0)  `newActiveRequest` only rejects a request if the exact same string ID is already pending; it enforces no maximum on the total number of concurrently pending requests. [4](#0-3)  This contrasts with `common.requestCache.NewRequest`, which explicitly bounds its cache via `maxCacheSize` and rejects new entries once full. [5](#0-4) 

The `globalNodeRateLimiter` and `perNodeRateLimiters` that do exist on this handler are wired only into `HandleNodeMessage`, which gates *node responses* coming back from the DON, not the initial user-submitted request that allocates the map entry. [6](#0-5)  Each accepted request stays resident (map entry, `sync.Mutex`, `responses` map, and per-request `errgroup.Group` fan-out goroutines to every DON member) until `requestTimeout` elapses (default 30s) and the 1-second cleanup ticker sweeps it. [7](#0-6) [8](#0-7) [9](#0-8) 

The vault handler in the same gateway process demonstrates the expected pattern by design: it gates `newActiveRequest` behind `h.requestProcessor.ProcessRequest` authorization before doing real work. [10](#0-9)  The confidential relay handler has no equivalent gate.

## Impact Explanation
An unauthenticated client of the Gateway's public HTTP endpoint can submit a sustained flood of confidential-relay requests, each with a unique ID, causing `activeRequests` and its fan-out goroutines to grow without any structural bound for up to the `requestTimeout` window. This can exhaust gateway process memory/goroutines, degrading or crashing the Gateway component that also serves other DON traffic (vault, capabilities) sharing the same HTTP server process — an in-scope denial-of-service impact against the Gateway's availability.

## Likelihood Explanation
High for any networked attacker with basic HTTP access to the Gateway's confidential-relay-configured endpoint: no authentication token, allowlist membership, or per-caller quota gates `HandleJSONRPCUserMessage`; only a syntactically valid JSON-RPC envelope with a unique ID (≤200 chars) is required to reach `newActiveRequest`.

## Recommendation
Bound the number of concurrently pending `activeRequests` (mirroring `common.requestCache`'s `maxCacheSize`) and/or apply a per-caller/global inbound rate limiter in `HandleJSONRPCUserMessage` before `newActiveRequest` is invoked, consistent with how the vault handler gates real work behind `requestProcessor.ProcessRequest` authorization.

## Proof of Concept
1. From an unauthenticated client, repeatedly POST JSON-RPC requests to the Gateway's confidential-relay endpoint with method `secretsGet` or `capabilityExec`, each with a freshly generated unique `id` (up to 200 chars), and no `Authorization` header.
2. Send requests at a rate exceeding what the 30-second default `requestTimeout`/1-second cleanup ticker can drain (e.g., hundreds/sec).
3. Instrument or observe `handler.activeRequests` size and goroutine counts on the Gateway process growing unbounded over the sustained flood, with no rejection due to a request-count cap or inbound rate limit, since none exists in `HandleJSONRPCUserMessage`/`newActiveRequest`.

					return

func (h *handler) removeExpiredRequests(ctx context.Context) {
	h.mu.RLock()
	var expiredRequests []*activeRequest
	now := h.clock.Now()
	for _, userRequest := range h.activeRequests {
		if now.Sub(userRequest.createdAt) > h.requestTimeout {
			expiredRequests = append(expiredRequests, userRequest)
		}
	}
	h.mu.RUnlock()

func (h *handler) HandleJSONRPCUserMessage(ctx context.Context, req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) error {
	if req.ID == "" {
		return errors.New("request ID cannot be empty")
	}
	if len(req.ID) > 200 {
		return errors.New("request ID is too long: " + strconv.Itoa(len(req.ID)) + ". max is 200 characters")
	}

	labels := h.extractRequestLabels(req)
	l := h.requestLogger(req, labels)
	l.Debugw("handling confidential relay request", "nodes", len(h.donConfig.Members), "f", h.donConfig.F)

	ar, err := h.newActiveRequest(req, labels, callback)
	if err != nil {
		return err
	}

	return h.fanOutToNodes(ctx, l, ar)
}

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], labels requestLabels, callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID, "executionID", labels.ExecutionID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		labels:    labels,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

func (h *handler) HandleNodeMessage(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	l := logger.With(h.lggr, "method", resp.Method, "requestID", resp.ID, "nodeAddr", nodeAddr)
	l.Debugw("handling node response")

	nodeRateLimiter, ok := h.perNodeRateLimiters[nodeAddr]
	if !ok {
		return fmt.Errorf("received message from unexpected node %s", nodeAddr)
	}
	if !nodeRateLimiter.Allow(ctx) {
		l.Debugw("node is rate limited", "nodeAddr", nodeAddr)
		return nil
	}
	if !h.globalNodeRateLimiter.Allow(ctx) {
		l.Debug("global relay rate limit exceeded")
		return nil
	}

func (c *requestCache[T]) NewRequest(lggr logger.Logger, request *api.Message, callback handlers.Callback, responseData *T) error {
	if request == nil {
		return errors.New("request is nil")
	}
	if responseData == nil {
		return errors.New("responseData is nil")
	}
	key := globalID{request.Body.Sender, request.Body.MessageID}
	c.mu.Lock()
	defer c.mu.Unlock()
	_, ok := c.cache[key]
	if ok {
		return errors.New("request already exists")
	}
	if len(c.cache) >= int(c.maxCacheSize) {
		return errors.New("request cache is full")
	}
