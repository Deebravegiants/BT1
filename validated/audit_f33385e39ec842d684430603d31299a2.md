### Title
Whale-scale position at sustained high utilization permanently freezes a market via i128 RAY-value overflow in accrual - (File: contracts/pool/src/interest.rs)

### Summary
CVE-2020-14794 is an optimizer crash that yields a repeatable, complete DoS of the server. The XOXNO Lending analog is a repeatable arithmetic crash inside the interest-accrual step: once a market's scaled book value grows past the `i128` RAY domain, `accrue_step` panics with `MathOverflow` inside `scaled_to_original`. Because `global_sync` runs before every mutation of that market, the panic is permanent and bricks every exit path.

### Finding Description
Every pool entrypoint loads the cache and calls `interest::global_sync`, which loops over `accrue_chunk` → `accrue_step` [1](#0-0) . `accrue_step` computes `scaled_to_original(env, borrowed, borrow_index)` and `scaled_to_original(env, supplied, supply_index)`, i.e. `scaled.mul(index)` [2](#0-1) , a checked RAY multiply that panics with `GenericError::MathOverflow` when `shares * index` exceeds `i128::MAX` (~1.7e38 raw) [3](#0-2) .

The admitted book can reach that domain: caps accept up to `max_cap_for_decimals(d) = i128::MAX / 10^(27-d)` ≈ 170 billion whole tokens [4](#0-3) , so `supplied`/`borrowed` can legitimately sit near `i128::MAX / index`. The borrow index then compounds up to `MAX_BORROW_RATE_RAY` (200% APR) while utilization stays high, and the index cap `MAX_BORROW_INDEX_RAY` (1e9×) never engages first — the value multiply overflows at index ≈170× [5](#0-4) .

Once the panic condition holds it is self-sustaining: `borrow_index` is monotone, `supplied` only grows through revenue minting, and the only writer that could lower `supply_index` (`apply_bad_debt_to_supply_index`) is itself reached only through paths that accrue first. So `update_indexes`, `supply`, `borrow`, `withdraw`, `repay`, `seize_positions`, `flash_loan`, revenue claims — every verb on that (hub, token) book reverts forever with `MathOverflow` [6](#0-5) .

The harness reproduces this exactly: `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` shows `update_indexes`, `withdraw` and `repay` all failing with `MATH_OVERFLOW` once the cliff is crossed [7](#0-6) .

### Impact Explanation
Permanent freezing of funds for every supplier and borrower in the affected market book — the protocol cannot repay debt, release collateral, liquidate, or pay out deposits, matching the "complete DOS" impact class of the CVE, lifted to fund loss since the market shares one physical pool balance per hub token.

### Likelihood Explanation
Reachable by unprivileged addresses (`supply` + `borrow` + time, or a whale deposit plus ordinary borrowing), but requires a book value near the RAY-domain ceiling — feasible mainly for high-supply/high-decimal tokens listed with caps near the admitted maximum — and sustained utilization near the steep part of the rate curve for enough compounding chunks. No privileged action needed, but substantial capital and time are required. Medium.

### Recommendation
Track the debt/supply RAY value against a headroom bound (e.g. `i128::MAX / MAX_BORROW_INDEX_RAY` worth of index growth, or an explicit `max_ray_value` per market) and gate `supply`/`borrow` entry so `supplied * supply_index` and `borrowed * borrow_index` can never exceed `i128::MAX` at the index ceiling; alternatively saturate `scaled_to_original` inside accrual (as `calculate_scaled_cap` already does for caps) so a value overflow degrades to a rate/zero-accrual state instead of an unrecoverable panic [8](#0-7) .

### Proof of Concept
See `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs::a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` [9](#0-8) : supply ~1e9 whole 18-decimal tokens, borrow ~98% of it against collateral on the XLM stress curve (`max_borrow_rate` 175%), advance time until `try_update_indexes_for(&["BIG18"])` returns `MATH_OVERFLOW`, then observe `try_withdraw_raw` and `try_repay` failing with the same error while `borrow_index < MAX_BORROW_INDEX_RAY` — the market is frozen before any index bound engages.

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}
```

```rust
/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
}
```
