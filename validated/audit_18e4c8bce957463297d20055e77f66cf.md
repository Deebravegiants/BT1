[1](#0-0) ### Title
RAY debt-value overflow during mandatory accrual freezes a market - (File: common/src/rates/simulate.rs)

### Summary
A sufficiently large debt book can make `borrowed * borrow_index / RAY` exceed `i128`. Because every pool mutation synchronizes interest before operating, the first accrual crossing that boundary reverts without advancing `last_timestamp`, after which repayment, withdrawal, liquidation, bad-debt cleanup, revenue claims, and recapitalization repeatedly fail for that market. [2](#0-1) [3](#0-2) 

### Finding Description
`Controller::update_indexes` is permissionless and forwards the selected markets to the owner-gated pool accrual entrypoint. [1](#0-0) [4](#0-3) 

Pool accrual loads each market and calls `global_sync`; `global_sync` calls `accrue_step` for every elapsed chunk and only marks the market accrued after all chunks complete. [5](#0-4) [6](#0-5) 

`accrue_step` converts scaled debt and supply into RAY-denominated values before calculating the new rate and rewards, while `calculate_supplier_rewards` separately multiplies the debt shares by both the old and new borrow indexes. [7](#0-6) [8](#0-7) 

Those multiplications use `Ray::mul`, which calls `mul_div_half_up`; its widened `I256` path protects the intermediate product but still panics with `MathOverflow` when the final quotient cannot fit in `i128`. [9](#0-8) [10](#0-9) 

The protocol caps the index but does not maintain the stronger invariant that scaled debt or scaled supply multiplied by the index remains representable. A transaction that crosses that value domain therefore reverts before `mark_accrued` or `commit`, leaving the stale timestamp and oversized scaled balances intact for every later attempt. [11](#0-10) [12](#0-11) 

### Impact Explanation
Once the boundary is crossed, suppliers cannot withdraw, borrowers cannot repay, liquidators cannot execute seizure, and bad-debt cleanup cannot socialize the position because those flows all load a synchronized market or invoke an account path that reaches it. [13](#0-12) [14](#0-13) [15](#0-14) 

`recapitalize` is also unusable as an unprivileged recovery path because it calls `renewed_market`, which performs the same accrual before calculating the backing shortfall. [16](#0-15) 

This freezes the underlying held by the affected market and leaves the contract unable to operate on that market under the current code; other markets remain isolated by the hub/asset state model.

### Likelihood Explanation
The attack requires a market whose configured caps and token supply permit scaled balances large enough that index growth pushes the position value outside the RAY `i128` domain, plus enough elapsed accrual for the index to reach that point. A single unprivileged address can create both the liquidity-supplying account and a collateral-backed borrowing account, so no privileged role, leaked key, oracle manipulation, or third-party failure is required.

Likelihood is limited by the required market size and configuration, but the impact is market-wide and the deterministic harness demonstrates that an admitted 18-decimal market can reach the boundary below the borrow-index cap. [17](#0-16) [18](#0-17) 

### Recommendation
Enforce a value-domain invariant whenever minting supply, debt, or revenue shares:

```text
scaled <= floor(i128::MAX * RAY / MAX_INDEX_RAY)
```

For the current `MAX_BORROW_INDEX_RAY` and `MAX_SUPPLY_INDEX_RAY`, this bounds scaled balances so their value remains representable even at the index ceiling. Enforce it in `mint_supply`, `mint_debt`, and revenue-share accrual, and include the accumulated `supplied + revenue` total rather than only the caller's new leg. Alternatively, refactor market valuation and accrual to use a representation that can safely handle the maximum admitted scaled balance at the maximum index.

### Proof of Concept
A transaction sequence for a permitted 18-decimal debt market is:

```rust
let debt_asset = HubAssetKey { hub_id, asset: debt_token };
let collateral_asset = HubAssetKey { hub_id, asset: collateral_token };

// One caller owns both accounts.
let liquidity_account = controller.supply(
    attacker,
    0,
    spoke_id,
    vec![(debt_asset, 1_000_000_000 * 10i128.pow(18))],
);

let borrower_account = controller.supply(
    attacker,
    0,
    spoke_id,
    vec![(collateral_asset, sufficient_collateral)],
);

controller.borrow(
    attacker,
    borrower_account,
    vec![(debt_asset, 980_000_000 * 10i128.pow(18))],
    Some(attacker),
);

// After elapsed accrual pushes borrowed * borrow_index / RAY over i128::MAX:
controller.update_indexes(attacker, vec![debt_asset]); // MathOverflow

// Each subsequent recovery path accrues first and reverts:
controller.repay(attacker, borrower_account, vec![(debt_asset, 1)]);
controller.withdraw(attacker, liquidity_account, vec![(debt_asset, 1)], None);
controller.liquidate(attacker, borrower_account, vec![(debt_asset, 1)], SeizeMode::Transfer);
controller.clean_bad_debt(attacker, borrower_account);
controller.recapitalize(attacker, debt_asset, recapitalization_amount);
```

The checked-in scenario creates an 18-decimal market, supplies `1_000_000_000` whole units, borrows 98% of it, observes `MathOverflow` before the index cap, and confirms both withdrawal and repayment remain frozen. [17](#0-16) [19](#0-18)

```rust
/// Computes `x * y / d` rounded half up. Returns `None` if `x < 0`, `y < 0`, `d <= 0`, or the
/// result does not fit in `i128`.
pub fn try_mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> Option<i128> {
    if x < 0 || y < 0 || d <= 0 {
        return None;
    }
    let half = d / 2;

    // Fast path: the biased product fits `i128`, so the whole computation is
    // native. `x * y + half` is non-negative here, so `/` is the floor the
    // widened path would produce.
    if let Some(biased) = x
        .checked_mul(y)
        .and_then(|product| product.checked_add(half))
    {
        return Some(biased / d);
    }

    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    x256.mul(&y256)
        .add(&I256::from_i128(env, half))
        .div(&d256)
        .to_i128()
}
```

```rust
pub(crate) fn accounting(env: &Env, action: &PoolAction) -> RepayOutcome {
    let (mut cache, position) = ops::load_leg(env, action);
    let amount = action.amount;

    let (burned, overpayment) = cache.resolve_repay(amount, position);
    let net_repay = amount
        .checked_sub(overpayment)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));

        env,
        net_repay == 0 || burned.raw() > 0,
        GenericError::RepayRoundsToZeroShares
    );

    let position = position.checked_sub(env, burned);
    cache.burn_debt(burned);

    cache.credit_cash(net_repay);
```
