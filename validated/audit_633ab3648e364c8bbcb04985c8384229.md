### Title
Local biometric image data is deleted after unconfirmed/failed uploads because `upload_image` swallows failures - (File: `src/agents/image_uploader.rs`)

### Summary
`upload_saved_images` in `src/agents/image_uploader.rs` iterates every locally-saved biometric image (IR, RGB, face, thermal, identification images) and calls `upload_image` for each file, then unconditionally deletes the entire directory of raw biometric images via `fs::remove_dir_all(image_dir)` once the loop over all files completes. [1](#0-0) 

### Finding Description
`upload_image` performs the network request but never propagates the outcome to its caller — on failure it only logs and increments a metric, always returning `Ok(())`: [2](#0-1) 

Because the per-image success/failure state is discarded ("not communicated back to the calling function", mirroring the reported bug class), `upload_saved_images` cannot tell whether all, some, or none of the images were actually uploaded to the backend. It nonetheless proceeds to delete the entire local image directory unconditionally right after the loop finishes: [1](#0-0) 

This function is used for every category of raw biometric imagery collected during a signup — IR camera, RGB camera, IR face, thermal, and identification images — and is invoked from `upload_signup_images` and `upload_identification_images_impl`, both of which are reached from the idle-state/fraud-detection upload flow (`upload_all_signup_images`): [3](#0-2) [4](#0-3) [5](#0-4) 

The overall signup directory is similarly deleted unconditionally at the end of `upload_signup_images`, compounding the issue at a coarser granularity. [6](#0-5) 

### Impact Explanation
If the backend upload fails (network error, backend 5xx, timeout, etc.) for one or more images in a signup — including fraud-detection-relevant biometric imagery (IR/RGB/thermal/identification images) — the Orb still deletes its only local copy of that data. Since the backend never received the data and the device has irrecoverably wiped its local copy, this results in permanent, silent loss of biometric evidentiary data. This directly undermines any downstream fraud/liveness review, dispute resolution, or audit process that relies on this imagery being retrievable, since there is no persisted record that the upload failed nor any retry after the fact — the code path already moved past this signup's data by the time it discovers the failure was silently absorbed.

### Likelihood Explanation
This runs on every idle-state/fraud-detection upload cycle for every signup captured with `internal-data-acquisition` enabled, and network failures (temporary connectivity loss, backend errors) are a realistic condition in field-deployed hardware, making the deletion of unconfirmed data a routine occurrence rather than an edge case.

### Recommendation
Change `upload_image` to propagate the `Result` of the network request instead of unconditionally returning `Ok(())`. In `upload_saved_images`, track per-file upload success and only delete files (or the parent directory) once every file in that directory has been confirmed uploaded; otherwise retain the failed files for retry on a future upload cycle, and only remove the individually confirmed files rather than doing an all-or-nothing directory removal.

### Proof of Concept
1. Trigger a signup so images are saved under `DATA_ACQUISITION_BASE_DIR/<signup_id>/...`.
2. Enter idle state so `upload_all_signup_images` → `upload_signup_images` → `upload_saved_images` runs.
3. Simulate a backend upload failure (e.g., network error or 5xx) for one of the PNG files in the loop at `src/agents/image_uploader.rs:127-142`.
4. Observe `upload_image` logs the error but returns `Ok(())`, so the loop continues normally, and `fs::remove_dir_all(image_dir)` at line 143 executes regardless, permanently deleting the image that was never actually uploaded.

async fn upload_image(
    signup_id: &SignupId,
    image_id: &ImageId,
    presigned_url_type: UrlType,
    img_data: Vec<u8>,
    log_image_path: &str,
    dd_image_tag: &str,
) -> Result<()> {
    tracing::info!("Uploading image: {log_image_path}");
    let t = Instant::now();
    let response =
        upload_image::request(signup_id, image_id, presigned_url_type, img_data, dd_image_tag)
            .await;
    dd_timing!("main.time.data_acquisition.upload" + format!("{}.full", dd_image_tag), t);
    match response {
        Ok(()) => {
            dd_incr!("main.count.data_acquisition.upload.success" + format!("{}", dd_image_tag));
        }
        Err(e) => {
            dd_incr!("main.count.data_acquisition.upload.error" + format!("{}", dd_image_tag));
            tracing::error!("Uploading image {log_image_path} failed: {e}");
        }
    }
    Ok(())
}
