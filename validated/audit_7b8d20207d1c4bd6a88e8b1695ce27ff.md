Audit Report

## Title
Unsynchronized map read in `WorkflowMetadataHandler.Authorize` races with locked map write in `syncMetadata`, crashing the Gateway process - ([File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go])

## Summary
`Authorize()` reads `h.authorizedKeys[workflowID]` at line 92 without acquiring `h.mu`, while `syncMetadata()` reassigns `h.authorizedKeys` (and related maps) wholesale under `h.mu.Lock()` at line 178. This is a genuine, reachable data race in Go's map implementation, which is not merely undefined behavior but produces a fatal, unrecoverable process crash (`fatal error: concurrent map read and map write`) when triggered concurrently.

## Finding Description
`Authorize` is invoked on every user-triggered HTTP request via `httpTriggerHandler.authorizeRequest` → `h.workflowMetadataHandler.Authorize(workflowID, req.Auth, req)`, which is itself called from `HandleUserTriggerRequest`, the entry point for unprivileged/authenticated client trigger requests. [1](#0-0) [2](#0-1) 

Inside `Authorize`, the map read at line 92 (`keys, exists := h.authorizedKeys[workflowID]`) has no `h.mu.RLock()`, unlike every other accessor of the same struct's protected fields (`WorkflowShards`, `GetWorkflowID`, `GetWorkflowReference`), which correctly acquire `h.mu.RLock()`/`RUnlock()`. [3](#0-2) [4](#0-3) [5](#0-4) 

Meanwhile, `syncMetadata`, run periodically via `h.runTicker(time.Duration(h.config.MetadataAggregationIntervalMs)*time.Millisecond, h.syncMetadata)`, replaces `h.authorizedKeys` (and `h.workflowRefToID`, `h.workflowIDToRef`, `h.workflowShards`) as a full map-header write while holding `h.mu.Lock()`. [6](#0-5) [7](#0-6) 

Go's runtime map implementation actively detects concurrent read/write access to the same map via internal write-in-progress flags, and when it does so, it calls `fatal()`, which terminates the process immediately — this cannot be caught by `recover()` or any HTTP middleware. Since `Authorize`'s read is genuinely unguarded while `syncMetadata`'s write is a real full reassignment under `Lock()`, this is a true, exploitable Go-level data race, not a hypothetical concern.

## Impact Explanation
Any request that lands on `Authorize` while `syncMetadata` is mid-reassignment of `h.authorizedKeys` can trigger Go's concurrent map access fatal error, crashing the entire Gateway process. This causes a complete availability loss for all Gateway-served traffic (HTTP triggers, vault, confidential relay, and other capability handlers) until the process is restarted, matching an Availability-only impact category.

## Likelihood Explanation
`Authorize` executes on the hot path for every `HandleUserTriggerRequest` call, and `syncMetadata` fires unconditionally on a fixed interval regardless of traffic, as confirmed by the ticker registration. An attacker capable of sending even a modest, sustained stream of HTTP trigger requests (valid or invalid signer, since the map lookup occurs either way, before the auth-failure branch) can reliably widen and hit this race window without any special privilege — this only requires the same access level as normal workflow-trigger callers.

## Recommendation
Add `h.mu.RLock()` / `defer h.mu.RUnlock()` around the `h.authorizedKeys[workflowID]` lookup in `Authorize()`, matching the locking discipline already used in `WorkflowShards`, `GetWorkflowID`, and `GetWorkflowReference`. Audit `WorkflowMetadataHandler` for any other unguarded field accesses that could race with `syncMetadata`'s locked writes.

## Proof of Concept
1. Build/run the Gateway with a `WorkflowMetadataHandler` configured with a short `MetadataAggregationIntervalMs` (e.g., 10ms) and at least one shard aggregator continuously reporting metadata so `syncMetadata` performs real map reassignments each tick.
2. Drive concurrent `HandleUserTriggerRequest` calls (each invoking `Authorize` via `authorizeRequest`) in a tight loop from a Go test or load-testing client against a live/valid `workflowID`.
3. Run with `go test -race` or under normal execution with `GODEBUG` map checks; observe `fatal error: concurrent map read and map write` and process exit in the Gateway logs, confirming the crash. A Go unit test that calls `h.Authorize(...)` in one goroutine in a tight loop while calling `h.syncMetadata(ctx)` in another goroutine in a tight loop (using the exported/package-internal API directly) will reproduce the fatal error deterministically within a few iterations under `-race` or even without it, since this is a hard runtime failure, not just a race detector finding.

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}

func (h *WorkflowMetadataHandler) GetWorkflowID(workflowOwner, workflowName, workflowTag string) (string, bool) {
	h.mu.RLock()
	defer h.mu.RUnlock()
	workflowRef := workflowReference{
		workflowOwner: workflowOwner,
		workflowName:  workflowName,
		workflowTag:   workflowTag,
	}
	workflowID, exists := h.workflowRefToID[workflowRef]
	if !exists {
		return "", false
	}
	return workflowID, true
}

func (h *WorkflowMetadataHandler) GetWorkflowReference(workflowID string) (workflowReference, bool) {
	h.mu.RLock()
	defer h.mu.RUnlock()
	workflowRef, exists := h.workflowIDToRef[workflowID]
	return workflowRef, exists
}
