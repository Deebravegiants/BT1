### Title
Omni Bridge hidden native fee for `prefundedNativeFeeTokens`: `feeEstimation.amount` reports 0 while a `storage_deposit` intent still debits `nativeFee` from the user - ([File: packages/intents-sdk/src/bridges/omni-bridge/omni-bridge.ts])

### Summary
When a withdrawn asset is listed in `bridgeConfigs[OmniBridge].prefundedNativeFeeTokens`, `estimateWithdrawalFee` skips the fee-quote conversion and returns `amount: 0n` while still recording a non-zero `relayerFee` in `underlyingFees`. That non-zero `relayerFee` (`nativeFee`) is later used by `deriveOmniWithdrawIntentParams`/`createWithdrawIntentsPrimitive` to add a `storage_deposit` intent that moves `nativeFee` out of the user's wrap.near balance, so the amount actually debited from the user exceeds the displayed `feeEstimation.amount`.

### Finding Description
The claimed invariant is: `feeEstimation.amount == total value leaving the user's balance beyond amount, across all assets`.

In `estimateWithdrawalFee` (packages/intents-sdk/src/bridges/omni-bridge/omni-bridge.ts:590-632):
- `totalAmountToQuote = fee.native_token_fee (+ storageDepositFee)` is computed from the live Omni Bridge API response.
- Unlike `FEE_SUBSIDIZED_TOKENS`, which explicitly zeroes `fee.native_token_fee` at line 581-583, tokens in `prefundedNativeFeeTokens` do **not** have `fee.native_token_fee` zeroed. `underlyingFees.relayerFee = fee.native_token_fee` therefore stays at its real, non-zero API value (line 585-586).
- The quote/swap step that would normally convert `totalAmountToQuote` (in wrap.near) into `amount` denominated in the withdrawn asset is skipped for `prefundedNativeFeeTokens` (line 616-621: `!this.bridgeConfig.prefundedNativeFeeTokens.includes(...)`), leaving `amount = 0n` for the returned `FeeEstimation`.
- So `feeEstimation.amount === 0n` even though `feeEstimation.underlyingFees[OmniBridge].relayerFee > 0n`.

Downstream, `createWithdrawalIntents` calls `deriveOmniWithdrawIntentParams` (omni-withdraw-params.ts:66-153), which reads `nativeFee = getUnderlyingFee(feeEstimation, OmniBridge, "relayerFee")` — this is the non-zeroed value from the API. Since `nativeFee > 0n`, `storageDepositAccountId` is computed (not `null`), and `createWithdrawIntentsPrimitive` (omni-bridge-utils.ts:56-63) pushes a `storage_deposit` intent:
```
{ deposit_for_account_id: storageDepositAccountId, amount: nativeFee.toString(), contract_id: OMNI_BRIDGE_CONTRACT, intent: "storage_deposit" }
```
This intent is signed as part of the same withdrawal batch signed by the withdrawing user, and it debits `nativeFee` from the user's wrap.near balance in intents.near — a value the user was never shown, because `feeEstimation.amount` reported 0.

With `feeInclusive: true`, the SDK computes `actualAmount = withdrawalParams.amount - feeEstimation.amount`. Because `feeEstimation.amount` is 0, `actualAmount` equals the full requested amount, and the user believes no fee is charged — yet `nativeFee` wrap.near is still silently removed via the `storage_deposit` intent.

This differs materially from the genuinely fee-free path (`FEE_SUBSIDIZED_TOKENS`), where `fee.native_token_fee` is forced to `0n`, making `nativeFee` in `deriveOmniWithdrawIntentParams` also `0n`, so no `storage_deposit` intent is generated at all and the equality holds. For `prefundedNativeFeeTokens` this zeroing never happens — only the quote step is skipped, not the fee itself — so the two branches (subsidized vs. prefunded) diverge in outcome despite superficially similar naming/intent ("fee is covered, so no cost to display").

None of the existing guards catch this: `validateWithdrawal` explicitly allows `feeEstimation.amount == 0n` for both `isFeeSubsidized` and `isPrefundedWithdrawal` tokens (line 341-349), and the later relayer-fee assertion (line 440-455) is unaware of the `amount` vs `relayerFee` mismatch — it only asserts `relayerFee > 0` for non-UTXO/non-subsidized withdrawals, which is satisfied here and does not fail.

### Impact Explanation
The withdrawing user signs and submits an intent batch that debits `nativeFee` (real wrap.near value from the live API, potentially several cents to dollars depending on gas conditions) from their intents balance via the `storage_deposit` intent, while the SDK's `estimateWithdrawalFee`/`feeEstimation.amount` told them (and any integrator UI built on it) the fee was `0`. This is a fee overcharge relative to the displayed estimate — funds leave the user's balance that the displayed fee said would not be taken. This is repeatable on every withdrawal of a `prefundedNativeFeeTokens`-configured asset as long as the live Omni Bridge fee API returns `native_token_fee > 0`. This matches the "fee overcharge" High-impact category in scope.

### Likelihood Explanation
Requires only: (1) an integrator sets `bridgeConfigs[OmniBridge].prefundedNativeFeeTokens` to include a real asset (an integrator-controlled config, not attacker-controlled, but the affected party is the ordinary user of that integrator), and (2) the Omni Bridge fee API returns a non-zero `native_token_fee` for that asset/destination pair, which is the normal case for most non-UTXO destination chains. No special attacker action is needed beyond calling `estimateWithdrawalFee`/`processWithdrawal` with `feeInclusive: true` as any normal user would. This is deterministic and repeatable per withdrawal.

### Recommendation
For `prefundedNativeFeeTokens`, either:
1. Zero out `fee.native_token_fee` (and any `storageDepositFee`) the same way `FEE_SUBSIDIZED_TOKENS` does, so `nativeFee` is genuinely `0` end-to-end and no `storage_deposit` intent is created; or
2. If the relayer fee is real and must still be paid via `storage_deposit` from the user's wrap.near, do not skip reporting it in `feeEstimation.amount` — report `nativeFee` (denominated appropriately) so `feeEstimation.amount` reflects the true total value leaving the user's balance, and use the "skip quote" optimization only to avoid an unnecessary token-to-wrap.near swap, not to hide the fee amount from the caller.

### Proof of Concept

it("prefundedNativeFeeTokens: feeEstimation.amount must equal nativeFee actually debited", async () => {
  const assetId = "nep141:aptos.omft.near";
  vi.spyOn(bridge["omniBridgeAPI"], "getFee").mockResolvedValue({
    native_token_fee: 1_000_000_000_000_000_000n, // 1 NEAR, realistic non-zero fee
    gas_fee: null,
    protocol_fee: null,
    min_amount: null,
    insufficient_utxo: false,
  } as any);
  // storage already sufficient so storageDepositFee = 0
  vi.spyOn(bridge as any, "getCachedStorageDepositValue").mockResolvedValue([0n, 0n]);

  const bridgeWithConfig = new OmniBridge({
    envConfig, nearProvider,
    bridgeConfig: { prefundedNativeFeeTokens: [assetId] },
  });

  const feeEstimation = await bridgeWithConfig.estimateWithdrawalFee({
    withdrawalParams: { assetId, destinationAddress: "0xabc", amount: 100n },
  });

  // LHS of invariant: displayed fee
  expect(feeEstimation.amount).toBe(0n); // BUG: displayed as free

  const intents = await bridgeWithConfig.createWithdrawalIntents({
    withdrawalParams: { assetId, amount: 100n, destinationAddress: "0xabc", feeInclusive: true },
    feeEstimation,
  });

  const storageDepositIntent = intents.find((i) => i.intent === "storage_deposit");
  // RHS of invariant: actual value leaving user's balance
  expect(storageDepositIntent).toBeDefined();
  expect(storageDepositIntent!.amount).toBe("1000000000000000000"); // nativeFee > 0, contradicts feeEstimation.amount === 0n
});

export function createWithdrawIntentsPrimitive({
	tokenAccountId,
	recipient,
	msg,
	externalId,
	storageDepositAccountId,
	amount,
	nativeFee,
	storageDepositAmount,
}: OmniWithdrawIntentParams): (IntentStorageDeposit | IntentFtWithdraw)[] {
	const ftWithdrawPayload: {
		recipient: OmniAddress;
		fee: string;
		native_token_fee: string;
		external_id: string;
		msg?: string;
	} = {
		recipient,
		fee: "0",
		native_token_fee: nativeFee.toString(),
		external_id: externalId,
	};
	if (msg !== "") {
		ftWithdrawPayload.msg = msg;
	}

	const intents: (IntentStorageDeposit | IntentFtWithdraw)[] = [];
	if (storageDepositAccountId !== null) {
		intents.push({
			deposit_for_account_id: storageDepositAccountId,
			amount: nativeFee.toString(),
			contract_id: OMNI_BRIDGE_CONTRACT,
			intent: "storage_deposit",
		});
	}
	intents.push({
		intent: "ft_withdraw",
		token: tokenAccountId,
		receiver_id: OMNI_BRIDGE_CONTRACT,
		amount: amount.toString(),
		storage_deposit:
			storageDepositAmount > 0n ? storageDepositAmount.toString() : undefined,
		msg: JSON.stringify(ftWithdrawPayload),
		min_gas: MIN_GAS_AMOUNT,
	});

	return intents;
}
