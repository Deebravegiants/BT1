### Title
Webhook `shop`/`topic` identity is not covered by the HMAC signature, allowing cross-tenant webhook spoofing - (File: `lib/shopify_api/webhooks/request.rb`)

### Summary
`ShopifyAPI::Webhooks::Registry.process` authenticates a webhook solely by validating the HMAC over the raw request body, then dispatches the handler using the `shop`, `topic`, `api_version`, and `webhook_id` values taken directly from HTTP headers — none of which are covered by the signature.

### Finding Description
`Webhooks::Request#to_signable_string` returns only `@raw_body`: [1](#0-0) . The `shop`, `topic`, `api_version`, and `webhook_id` accessors all read from unauthenticated headers instead: [2](#0-1) .

`Utils::HmacValidator.validate` computes the HMAC exclusively over `verifiable_query.to_signable_string` (the body) and compares it to the `hmac` header: [3](#0-2) .

`Registry.process` uses this validation result to authorize the request, then builds `WebhookMetadata` — including `shop` and `topic` — straight from the unverified header values on the same `request` object: [4](#0-3) . `WebhookMetadata` is a plain struct with no additional verification of its `shop`/`topic` fields: [5](#0-4) .

The identity binding that should hold is: `bytes_verified_by_HMAC == bytes_that_determine_the_tenant`. In this code, `bytes_verified_by_HMAC = raw_body` while `bytes_that_determine_the_tenant = headers("shop-domain", "topic", ...)`. These are disjoint, so a valid HMAC over a given body says nothing about which shop or topic the request claims to represent.

### Impact Explanation
Any entity capable of installing the app on a shop they control (an unprivileged internet user — installing a Shopify app on a free/dev store requires no special privilege) can receive a genuinely Shopify-signed webhook (body + valid HMAC, since the app's `api_secret_key` is shared across all installs of the app). That attacker can then replay the exact same `raw_body`/`hmac` pair directly to the app's public webhook endpoint while substituting the `x-shopify-shop-domain` and/or `x-shopify-topic` headers to name a victim shop/topic. `Registry.process` will accept the HMAC (it only checks the body) and hand the handler a `WebhookMetadata` claiming to be from the victim shop. If the host application trusts `data.shop` to select per-tenant credentials/state (the documented and expected usage pattern for this gem, e.g., looking up a session or deleting shop data on `app/uninstalled`), this is a cross-tenant identity spoof: an attacker impersonates a different shop's webhook stream using their own valid credential material.

### Likelihood Explanation
Requires only: (1) installing the app on any store the attacker controls (no special privilege), (2) capturing one legitimate webhook delivery (body+HMAC) from that install, and (3) POSTing it to the public webhook endpoint with modified `shop`/`topic` headers. No access to `api_secret_key`, access tokens, or the victim's credentials is needed.

### Recommendation
Bind the identity fields into the signed material, or otherwise cryptographically tie `shop`/`topic` to the verified payload before trusting them — e.g., include the relevant headers in `to_signable_string`, or require the host application to independently confirm `shop` corresponds to a shop with an active, matching session before acting on `WebhookMetadata`. At minimum, document that `WebhookMetadata#shop`/`#topic` are unauthenticated and must not be trusted for authorization decisions without an independent tenant check.

### Proof of Concept
1. Install the target app on shop `attacker.myshopify.com` (any free/dev store).
2. Trigger a webhook (e.g., `app/uninstalled`) and capture the raw POST: `raw_body` and `x-shopify-hmac-sha256` header — this HMAC is valid because it's signed with the app's shared `api_secret_key`.
3. Replay the identical `raw_body` + `hmac` header to the same endpoint, but set `x-shopify-shop-domain: victim-shop.myshopify.com` (and optionally a different `x-shopify-topic`).
4. `Utils::HmacValidator.validate` succeeds (it only checks `raw_body` against the secret) per `lib/shopify_api/utils/hmac_validator.rb`; `Registry.process` dispatches the handler with `WebhookMetadata(shop: "victim-shop.myshopify.com", topic: ...)` per `lib/shopify_api/webhooks/registry.rb:188-199`, even though Shopify never sent a webhook for `victim-shop.myshopify.com` with that content.
