## Title
Creator fee balances become permanently frozen if the creator address is blacklisted by USDC, with no admin recovery path - (`packages/contracts/src/FeeVault.sol`)

### Summary
`FeeVault.claim()` pays out `creatorBalance[msg.sender]` directly to `msg.sender`, and `creatorBalance` is keyed purely by the creator address recorded at fee-accrual time [1](#0-0) . If that address is later blacklisted by USDC (the real, external stablecoin used for all fees per `docs/contracts-scope.md`), `usdc.safeTransfer(msg.sender, amount)` reverts on every call and the accrued balance can never be withdrawn. Unlike `FeeVault.setFeeTo()`, which lets the owner redirect the protocol-fee recipient independently of `claimProtocol()`, there is no analogous mechanism to redirect or rescue an individual creator's already-accrued `creatorBalance`.

### Finding Description
Fees accrue into `FeeVault` via `accrue()`, called by `Zap` on every buy/sell, crediting `creatorBalance[creator]` where `creator` is read from `Bonding.tokenInfo(token).creator` at the time of the trade [2](#0-1) . `Bonding.transferCreator()` lets a creator rotate the *future* fee-attribution address for a token [3](#0-2) , but it only updates `TokenInfo.creator` inside `Bonding` — it has no effect on the FeeVault's `creatorBalance` mapping, which is keyed by the historical creator address that already earned fees.

`claim()` is unconditionally hard-wired to `msg.sender`:
```solidity
function claim() external nonReentrant returns (uint256 amount) {
    FeeVaultStorage storage $ = _s();
    amount = $.creatorBalance[msg.sender];
    if (amount == 0) revert NothingToClaim();
    $.creatorBalance[msg.sender] = 0;
    $.totalAccruedCreator -= amount;
    $.usdc.safeTransfer(msg.sender, amount);
    emit CreatorFeesClaimed(msg.sender, amount);
}
``` [1](#0-0) 

If the current holder of a `creatorBalance` entry is put on the USDC blacklist (a real, well-documented USDC feature, per the analog external report), `safeTransfer` to that address will always revert, so `claim()` will always revert for that address. There is no `onlyOwner` override, no "claim on behalf of" function, and no way to migrate an already-accrued `creatorBalance[oldCreator]` to a new address — `transferCreator` only redirects future accrual, not the stuck historical balance. Compare this to `setFeeTo()`, which explicitly documents and supports redirecting the protocol-fee recipient *before* the funds are pulled [4](#0-3)  — no equivalent exists for creator balances.

### Impact Explanation
Any creator whose wallet later becomes blacklisted by USDC permanently loses access to their entire pooled `creatorBalance` across every token they've launched. Because `accrue()` keeps crediting the same address on every subsequent buy/sell of that creator's token(s) (attribution doesn't change unless `transferCreator` is called *before* accrual, and even then only future accrual moves), more funds can continue accumulating under a now-unreachable balance. This is a concrete, permanent freezing of creator funds inside the in-scope `FeeVault.sol`, matching the "Medium" impact bar (permanent freezing of creator funds, no recovery path).

### Likelihood Explanation
Reaching this state requires no privileged action — any creator address can be independently blacklisted by USDC's centralized issuer (Circle) at any time, for reasons entirely outside the protocol's control (e.g., sanctions, flagged addresses, mixer interaction). Given `alt.fun` is fully permissionless (`Zap.createToken`/`buy`/`sell` are open to anyone), any address, including one later blacklisted, can become a token creator and accrue fees beforehand. This mirrors the real-world precedent cited in the external report and is a foreseeable, non-contrived scenario for a protocol denominated in USDC.

### Recommendation
Decouple the balance's identity from the payout recipient, mirroring the `setFeeTo()` pattern used for the protocol fee: add an owner-gated (or creator-signed) function to reassign `creatorBalance[oldCreator]` to a new address, or allow claiming to an explicit `to` argument analogous to how `setFeeTo` lets the protocol redirect claims ahead of blacklisting. At minimum, expose an admin path to migrate a stuck balance to a creator-designated alternate address so funds are not stranded indefinitely.

### Proof of Concept
1. Creator `C` launches a token via `Zap.createToken`, accrues `creatorBalance[C] = X` USDC across trades routed through `Zap.buy`/`Zap.sell` → `FeeVault.accrue` [2](#0-1) .
2. USDC's issuer blacklists address `C` (independent of the protocol).
3. `C` calls `FeeVault.claim()`; `usdc.safeTransfer(C, X)` reverts because `C` is blacklisted, so the whole `claim()` call reverts [1](#0-0) .
4. `C` calls `Bonding.transferCreator(token, D)` to attribute future fees to a fresh address `D` [3](#0-2)  — this does not move the existing `creatorBalance[C] = X` in `FeeVault`, which remains permanently locked since no function can redirect it away from `C`.

    function accrue(
        address token,
        address creator,
        uint256 creatorAmount,
        uint256 protocolAmount,
        bool isBuy
    ) external onlyDepositor {
        FeeVaultStorage storage $ = _s();
        if (creatorAmount > 0) {
            if (creator == address(0)) revert ZeroAddress();
            $.creatorBalance[creator] += creatorAmount;
            $.totalAccruedCreator += creatorAmount;
            $.lifetimeCreatorEarned[creator] += creatorAmount;
        }
        if (protocolAmount > 0) {
            $.protocolBalance += protocolAmount;
            $.lifetimeProtocolEarned += protocolAmount;
        }
        if ($.usdc.balanceOf(address(this)) < $.totalAccruedCreator + $.protocolBalance) {
            revert UnderfundedAccrual();
        }
        emit FeeAccrued(token, creator, creatorAmount, protocolAmount, isBuy);
    }

    /// @dev Protocol fees are pooled and paid to whoever is `feeTo` at claim
    ///      time, so rotating here redirects the entire outstanding

    ///      `claimProtocol()` (and `sweepDonations()`) first to settle the

    function setFeeTo(
        address feeTo_
    ) external onlyOwner {
        if (feeTo_ == address(0)) revert ZeroAddress();
        FeeVaultStorage storage $ = _s();
        address old = $.feeTo;
        $.feeTo = feeTo_;

        if (msg.sender != info.creator) revert NotCreator();
