### Title
Sub-3-decimal collateral legs enter a dead zone where every liquidation offer reverts while debt keeps accruing — (File: contracts/controller/src/positions/liquidation/math.rs)

### Summary
The external report's bug class is a liquidation window that is too narrow: the state space between "liquidatable" and "underwater" is so thin that the protocol accumulates bad debt before liquidators can act. XOXNO Lending has a strictly worse analog of the same class on collateral assets listed with fewer than `MIN_BORROWABLE_ASSET_DECIMALS` (3) decimals: between the two whole-unit liquidation rules there is a debt interval where **no** liquidation offer is accepted at all. Every `liquidate` call reverts with `InvalidPayments`, while borrow interest keeps accruing on the position and pushes it toward insolvency. The liquidation window is not narrow — it is zero.

### Finding Description
Liquidation is permissionless through `liquidate`, gated on `health_factor < 1 WAD` where `HF = floor(weighted_collateral * WAD / total_debt)` (`docs/reference/formulas.md:194-199`). For a collateral asset below 3 decimals, seizure legs only move in whole token units: a full close rounds the leg up to the held balance, a partial rounds it down and trims the repayment accordingly (`formulas.md:266-270`, `math.md:387`).

The planning logic has two rules for such a leg — (rule 1) a full-debt repayment seizes the rounded-up whole-unit balance, and (rule 2) a partial repayment seizes whole units backed by `floor(U / (1 + b))`. The reference documentation explicitly states the gap:

> While `floor(U / (1 + b)) - R < D <= ceil((U + m) / (1 + b))`, neither rule 1 nor rule 2 applies. If the curve quote then backs less than one unit, every offer reverts until accrual or a price move ends that state. (`docs/reference/formulas.md:305-308`)

Concretely: for a debt `D` in that interval and a curve quote `ideal` that backs less than one whole unit of collateral, the partial-seizure path rounds the kept seizure to zero units, the trimmed repayment becomes zero, and the plan is left with no seizure leg. A plan with no remaining leg reverts in `liquidate` with `InvalidPayments` (16) (`formulas.md:260-262`, `math.md:387`). No input from the liquidator changes this — offering more debt payment does not help, because a partial payment above the quote is trimmed to `ideal`, and offering the full debt is refused by rule boundaries that require `D <= floor(U/(1+b)) - R` for the round-up path.

The state is only exited by (a) interest accrual pushing `D` above the interval's upper edge — i.e., the position becoming *more* underwater — or (b) an oracle price move. An unprivileged liquidator cannot un-stick it.

### Impact Explanation
While the account sits in the dead zone, liquidation is impossible, yet debt grows via millisecond-chunked interest accrual. The position can cross into insolvency (`C < D`) during the window, converting a solvent-but-unhealthy account into socialized bad debt handled by `clean_bad_debt` / supply-index write-down (`curve.rs:25-27`, `is_socializable_bad_debt`). This is exactly the external report's bad-debt-from-insufficient-liquidation-window outcome, realized as a temporary freezing of the liquidation mechanism with protocol-insolvency consequences for lenders whose supply claims are written down.

### Likelihood Explanation
Requires a spoke listing a collateral asset with fewer than 3 decimals (permitted: `MIN_ASSET_DECIMALS = 0`; only borrowable assets need ≥3, `shared.rs:20-27`) and an account whose only supply leg is that asset holding ≥ `MIN_WHOLE_UNIT_COLLATERAL` = 2 units. The dead-zone width is one whole token unit divided by `1 + bonus` — for a low-decimals, high-unit-value token (e.g., a 0- or 2-decimal RWA/tokenized asset) this is a USD-meaningful interval, and a position drifting down through HF < 1 lands in it whenever the curve quote happens to back less than one unit. No privileged action is needed to reach or exploit the state; any liquidator calling `liquidate` simply fails.

### Recommendation
Close the gap between the two whole-unit rules. Options: when the curve quote backs less than one whole unit on a sub-3-decimal leg, promote the quote to the amount that backs exactly one unit (bounded by the debt and the HF-preserving cap), or allow the round-up full-close rule to fire whenever the partial rule yields zero units and the single unit's value covers the trimmed repayment at the capped bonus. At minimum, `get_liquidation_estimate` should surface the dead zone and the repayment should be promotable to full debt (analogous to the existing `< $5` dust-debt promotion at `curve.rs:133-135`) so a liquidator can always close the position.

### Proof of Concept
1. Governance lists token `T` with 2 decimals as collateral (allowed; only borrowable markets require ≥3 decimals), liquidation threshold `LT`, bonus `b0`.
2. Borrower supplies `k` whole units of `T` (unit value `U`), borrows a 3+-decimal asset up to the LTV limit, satisfying `ltv_collateral >= total_debt` and `HF >= 1` at open.
3. `T` price drifts down (or debt accrues) so `HF < 1` and `D` lands in `floor(U/(1+b)) - R < D <= ceil((U+m)/(1+b))`, with the target-HF quote backing less than one whole unit — e.g., `ideal * (1 + b) < U`.
4. Any liquidator calls `liquidate(account, debt_payments, SeizeMode::Transfer)`. The partial rule keeps 0 units → no seizure leg → revert `InvalidPayments`. Offering the full `D` also fails because the round-up rule requires `D` below the interval.
5. Debt continues accruing; once `D` exceeds the interval or `C < D`, the residue becomes bad debt written down via `clean_bad_debt`/`recapitalize` at suppliers' expense. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4)
