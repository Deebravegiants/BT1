## Title
Uniswap V4 spot-price venue pricing lacks TWAP/oracle protection, letting a flash-loan price manipulation drain the Simplex solver's inventory - ([File: sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts])

## Summary
Simplex's `FXFiller` prices curve-less "venue" trading pairs directly off a Uniswap V4 pool's instantaneous spot price (`sqrtPriceX96`) with no TWAP, and the only mitigation — a static `referencePrice`/`maxDeviationBps` guard — is optional and, even when configured, is a crude deviation check rather than a manipulation-resistant price feed. An attacker can flash-loan-swap the referenced pool to move its spot price, then submit (or cause to be filled) an intent order through `IntentGatewayV2` that the solver fills against the manipulated rate, extracting solver-held liquidity — the same bug class as the Float Protocol incident (flash-loan manipulation of a Uniswap V3 `slot0` spot price mispricing LP shares).

## Finding Description
When a trading pair has no static bid/ask curves and `token0` is a USD stable, `FXFiller.resolveLegRates` prices the leg entirely from the live pool quote: [1](#0-0) 

That quote comes from `UniswapV4FundingPlanner.getExoticTokenPrice` → `computeDirectPoolPriceUsd`, which returns the **raw pool mid** derived straight from `sqrtPriceX96` with no size/impact term and no averaging window: [2](#0-1) 

The underlying state is refreshed by reading `slot0`/`getLiquidity` at the current block — an instantaneous read, not a TWAP: [3](#0-2) 

The only defense against a manipulated quote is `checkPriceGuard`, which compares the live quote to a **static, operator-configured** `referencePrice` within `maxDeviationBps`: [4](#0-3) 

This guard is explicitly optional — a chain without both fields configured is "unguarded": [5](#0-4) 

And project-internal documentation independently confirms this is the only defense on the path and that it checks deviation from a stale reference, not execution cost: [6](#0-5) 

Compounding this, the per-leg overfill clamp that used to bound loss from exactly this scenario has been intentionally disabled, with the code comment acknowledging the removed protection applied to "a bug / stale cache / manipulated venue price": [7](#0-6) 

An attacker who flash-loan-swaps the referenced Uniswap V4 pool can move the spot price either (a) past what any configured `maxDeviationBps` still permits, or (b) trivially, if the operator left the chain unguarded (the documented default posture), and then submit an intent order via `IntentGatewayV2` sized to be filled by the solver at the manipulated rate. Because the overfill clamp is disabled, the solver pays out the full curve-derived amount with no cap, directly analogous to Float Protocol's attacker repeatedly depositing/withdrawing at an inflated Uniswap-derived share price.

## Impact Explanation
A successful attack extracts value directly from the solver's on-chain inventory (wallet balance plus Uniswap V4 LP withdrawals) at a price divorced from the pool's true, unmanipulated market rate. This is concrete theft of solver funds reachable by any unprivileged intent creator/attacker who can (1) flash-loan swap the configured pool and (2) submit a matching intent order — no privileged role required. Given the removal of the overfill ceiling, losses are bounded only by the solver's available inventory for that pair/chain, not by any per-order cap.

## Likelihood Explanation
Likelihood is Medium: exploitation requires (a) the operator running a curve-less, venue-priced pair funded by a Uniswap V4 LP position, and (b) that pool having exploitable liquidity depth relative to a flash loan. Where `referencePrice`/`maxDeviationBps` is omitted (the documented default), there is no barrier at all beyond the attacker's flash-loan capital. Where it is configured, the static reference still permits manipulation up to `maxDeviationBps`, and the guard does not account for the swap fee/slippage the solver itself would incur sourcing inventory from the same pool, so a "guarded" chain is still exposed within the configured band.

## Recommendation
- Replace the raw `sqrtPriceX96` mid used in `computeDirectPoolPriceUsd` with a manipulation-resistant price (e.g., a TWAP over a meaningful window, or a validated external oracle) before using it to price fills.
- Re-enable and enforce the per-leg overfill ceiling (`maxOverfillBps`) for venue-priced legs rather than warn-only, restoring a hard loss bound against a manipulated/stale venue price.
- Make the `referencePrice`/`maxDeviationBps` guard mandatory (not optional) for any venue-priced pair, and periodically refresh the reference from an independent source rather than a fixed operator-set constant, so the band tracks the true market instead of drifting stale.
- Consider incorporating swap-cost/impact into the venue price so the guard also bounds the solver's realized execution cost, not just the raw quote deviation.

## Proof of Concept
1. Operator configures a curve-less pair (e.g. `USDC/CNGN`) priced via `[vault.uniswapV4]` with no `referencePrice`/`maxDeviationBps` (an explicitly supported, documented configuration — see `docs/content/developers/evm/simplex/pricing.mdx` lines 64-66), or with a guard whose band is wide enough to tolerate the intended price move.
2. Attacker takes a flash loan and performs a large swap against the referenced Uniswap V4 pool, moving `slot0`/`sqrtPriceX96` far from the pool's pre-attack (fair) price.
3. Within the same or a subsequent block (before arbitrageurs correct the pool), attacker submits an `IntentGatewayV2` order whose input/output amounts are set to be attractive at the now-manipulated rate.
4. `FXFiller.calculateProfitability` → `resolveLegRates` → `getVenueUsdPrice` reads the manipulated `sqrtPriceX96`; `checkPriceGuard` passes (guard absent or band wide enough); `computeLegPolicyOutput` computes a payout at the manipulated rate with no overfill ceiling enforced (per `sdk/packages/simplex/src/strategies/fx.ts` lines 678-685).
5. The solver fills the order, paying out from wallet balance and/or Uniswap V4 LP withdrawal at the manipulated rate; attacker repays the flash loan and repeats until the pair's inventory or `maxOrderSize` limits the extraction.

```typescript
	 * Validates a live venue quote against the static reference price for the chain.
	 * Returns true (pass) when no guard is configured, or no reference exists for the
	 * chain. Returns false when the quote (token1 per USD) deviates from the reference
	 * by more than `maxDeviationBps`, in which case the order must not be filled.
	 */
	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {
			this.logger.warn(
				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
	}
```

```typescript
	private computeDirectPoolPriceUsd(
		pos: HydratedV4Position,
		sdkPool: V4Pool,

		const usdc = this.configService.getUsdcAsset(chain).toLowerCase()
		const usdt = this.configService.getUsdtAsset(chain).toLowerCase()
		const c0 = pos.currency0.toLowerCase()

			// currency0 is stable → exotic is currency1
			// token1Price = "token0 per token1" = USD per exotic
			return {
				exoticToken: c1,
				priceUsd: new Decimal(sdkPool.token1Price.toFixed(18)),
			}
		}

		if (c1 === usdc || c1 === usdt) {
			// currency1 is stable → exotic is currency0
			// token0Price = "token1 per token0" = USD per exotic
			return {
				exoticToken: c0,
				priceUsd: new Decimal(sdkPool.token0Price.toFixed(18)),
			}
		}

		return null
	}
```

**File:** docs/content/developers/evm/simplex/pricing.mdx (L68-72)
```text
## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.
```
