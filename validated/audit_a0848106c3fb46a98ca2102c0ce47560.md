Audit Report

## Title
Cross-workflow HTTP response cache poisoning due to `WorkflowID` being excluded from cache key - (File: core/services/gateway/handlers/capabilities/v2/response_cache.go)

## Summary
The gateway's `responseCache` caches outbound HTTP Action responses keyed solely by `gateway.OutboundHTTPRequest.Hash()`, which per the in-repo comment and the accompanying test suite is computed from method, URL, headers, body, and `WorkflowOwner` — but explicitly excludes `WorkflowID` [1](#0-0) . This contradicts the package's documented "Workflow Isolation" guarantee and allows two different workflows belonging to the same owner to receive each other's cached HTTP responses.

## Finding Description
`Fetch` and `Set` both use `req.Hash()` as the sole cache map key [2](#0-1) [3](#0-2) . The in-repo test suite directly proves the omission: two requests differing only in `WorkflowID` produce identical hashes, while two requests sharing the same `WorkflowOwner` also collide as expected [4](#0-3) . The consuming code path, `makeOutgoingRequest`, unmarshals an `OutboundHTTPRequest` (whose fields, including `CacheSettings`, `WorkflowID` and request shape, are supplied by the workflow itself) and calls `h.responseCache.Fetch`/`Set` directly, with no additional per-workflow scoping applied anywhere in `http_handler.go` [5](#0-4) . No code in this cache path adds `WorkflowID` to the key or otherwise isolates entries per-workflow, so the "Workflow Isolation" claim in the design doc is not actually enforced at the workflow level — only at the owner level (via `WorkflowOwner` inclusion in the hash).

## Impact Explanation
This is intra-owner, cross-workflow cache/response reuse: a workflow response cached by one of an owner's workflows can be served to a different workflow run by the same owner that happens to construct an identical method/URL/headers/body request, bypassing a fresh fetch and violating the documented per-workflow isolation guarantee. This maps to the in-scope "cross-user/cross-tenant response corruption" impact class in a weaker form (same owner, different workflow contexts rather than different owners), since `WorkflowOwner` is still included in the hash and correctly prevents cross-owner leakage. The severity is bounded by the fact that isolation failure occurs only within a single owner's own workflows, not across distinct tenants/owners.

## Likelihood Explanation
Triggering this only requires an owner operating two workflows that issue functionally identical HTTP Action requests with `CacheSettings.MaxAgeMs > 0` and `Store: true` — both fields are workflow-controlled inputs on `OutboundHTTPRequest`, requiring no operator/admin access, just normal workflow-authoring capability [6](#0-5) . This is deterministically reproducible via the existing test pattern.

## Recommendation
Include `WorkflowID` (or an execution-scoped identifier) in the value hashed for the cache key, or explicitly redefine/document the cache as owner-scoped (not workflow-scoped) and update the README's "Workflow Isolation" claim accordingly. Add/adjust the regression test to assert `WorkflowID` does affect the hash if per-workflow isolation is the intended guarantee, since the current test (`TestRequestHash`, subtest "having different workflowID results in same Hash") asserts the opposite [7](#0-6) .

## Proof of Concept
1. Owner `0xABC` registers Workflow A (`WorkflowID = "wf-1"`) which issues `GET https://victim.example/data` with `CacheSettings{MaxAgeMs: 600000, Store: true}`; gateway calls `Fetch`, caches the result under `req.Hash()` [8](#0-7) .
2. Owner `0xABC` also runs Workflow B (`WorkflowID = "wf-2"`) which issues an identical-shape request; per `TestRequestHash`'s "having different workflowID results in same Hash" assertion, this computes the same cache key [7](#0-6) .
3. `Fetch` returns Workflow A's cached response to Workflow B without a fresh HTTP call, demonstrating the workflow-isolation failure documented as unintended in the package design.

func (rc *responseCache) Fetch(ctx context.Context, req gateway.OutboundHTTPRequest, fetchFn func() gateway.OutboundHTTPResponse, storeOnFetch bool) gateway.OutboundHTTPResponse {
	cacheKey := req.Hash()
	cacheMaxAge := time.Duration(req.CacheSettings.MaxAgeMs) * time.Millisecond

	// Fast path: check cache without singleflight overhead.
	rc.cacheMu.RLock()
	cachedResp, exists := rc.cache[cacheKey]
	rc.cacheMu.RUnlock()
	if exists && cachedResp.storedAt.Add(cacheMaxAge).After(time.Now()) {
		rc.metrics.IncrementCacheHitCount(ctx, rc.lggr)
		return cachedResp.response
	}

	// Slow path: singleflight deduplicates concurrent fetches per key.
	// Cache check + store happen inside the flight so the key isn't released
	// until the result is cached, closing the race window between singleflight
	// completion and cache write.
	result, _, _ := rc.flight.Do(cacheKey, func() (any, error) {
		// Re-check cache: a previous flight may have just stored the result.
		rc.cacheMu.RLock()
		cachedResp, exists := rc.cache[cacheKey]
		rc.cacheMu.RUnlock()
		if exists && cachedResp.storedAt.Add(cacheMaxAge).After(time.Now()) {
			rc.metrics.IncrementCacheHitCount(ctx, rc.lggr)
			return cachedResp.response, nil
		}

		response := fetchFn()

		if storeOnFetch && isCacheableStatusCode(response.StatusCode) {
			rc.cacheMu.Lock()
			rc.cache[cacheKey] = &cachedResponse{
				response: response,
				storedAt: time.Now(),
			}
			rc.cacheMu.Unlock()
		}

		return response, nil
	})

	return result.(gateway.OutboundHTTPResponse)

func (rc *responseCache) Set(req gateway.OutboundHTTPRequest, response gateway.OutboundHTTPResponse) {
	rc.cacheMu.Lock()
	defer rc.cacheMu.Unlock()
	if isCacheableStatusCode(response.StatusCode) && rc.isExpiredOrNotCached(req) {
		rc.cache[req.Hash()] = &cachedResponse{
			response: response,
			storedAt: time.Now(),
		}
	}
}

type ResponseCache interface {
	// Set caches a response if it is cacheable (2xx or 4xx status codes) and the cache is empty or expired for the given request.
	Set(req gateway_common.OutboundHTTPRequest, response gateway_common.OutboundHTTPResponse)

	// Fetch retrieves a response from the cache if it exists and the age of cached response is less than the max age of the request.
	// If the cached response is expired or not cached, it fetches a new response from the fetchFn.
	// The response is cached if it is cacheable and storeOnFetch is true.
	Fetch(ctx context.Context, req gateway_common.OutboundHTTPRequest, fetchFn func() gateway_common.OutboundHTTPResponse, storeOnFetch bool) gateway_common.OutboundHTTPResponse

	// DeleteExpired removes all cached responses that have exceeded their TTL (Time To Live).
	DeleteExpired(ctx context.Context) int
}
