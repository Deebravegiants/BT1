### Title
Empty `keys` in a `GetRequest` lets a relayer skip state-proof verification entirely and permanently finalize a forged response - ([File: modules/ismp/core/src/handlers/response.rs])

### Summary
The state-machine `verify_state_proof` implementations (EVM, Substrate-EVM, Pharos, Tendermint) only perform trie/merkle verification inside a `for key in keys { ... }` loop. When the `GetRequest.keys` list is empty, the loop body never executes, so the function returns `Ok(<empty map>)` without ever touching the state root, without decoding a real trie proof against it, and without any cryptographic binding between the claimed `proof.proof` bytes and the consensus-verified `StateCommitment`. This mirrors the OpenSSL AES-SIV/AES-GCM-SIV bug class exactly: the "tag"/verification step is computed only when the update function is invoked with non-empty data; when the caller supplies "empty ciphertext" (here, an empty `keys` vector) the authenticity check is skipped and any garbage input is accepted as verified.

### Finding Description
`verify_state_proof` in `modules/ismp/state-machines/evm/src/lib.rs` (lines 149-261) groups `keys` into `contract_to_keys`, and only calls `get_values_from_proof` (the actual trie verification against `root`) for the accumulated per-contract entries: [1](#0-0) 

If `keys` is `vec![]`, `contract_to_keys` is empty, the correspondence checks (`.all(...)` over an empty iterator, and `.any(...)` over `evm_state_proof.storage_proof.keys()`) are vacuously satisfied as long as the attacker submits an `EvmStateProof` with empty `storage_proof`/`contract_proof`, and the function returns `Ok(BTreeMap::new())` — `root` (the `StateCommitment.state_root`) is never dereferenced by any cryptographic check.

The same structural pattern (loop-only verification, vacuous pass on empty input) repeats in the sibling state machines: [2](#0-1) [3](#0-2) 

This function is invoked directly from the permissionless response handler with `keys = request.keys.clone()`, where `request` is the original `GetRequest` object supplied by the relayer's `ResponseMessage`: [4](#0-3) 

Note that this handler validates the batch is non-empty (`msg.requests.is_empty()`) and validates that the *request* itself is a genuine, previously-dispatched, un-timed-out `GetRequest` matching the claimed `proof.height`, but it never validates that `request.keys` is non-empty before trusting the "verified" result of `verify_state_proof`. The identical pattern exists in the permissionless `pallet-state-coprocessor::handle_get_requests`: [5](#0-4) 

Because `GetRequest.keys` is chosen by the *source* application at dispatch time and is not required to be non-empty anywhere in the dispatcher path I was able to inspect, a relayer processing any `GetRequest` dispatched with an empty (or later reduced to empty via decode/serialization edge cases) `keys` array can submit a `ResponseMessage`/`GetRequestsWithProof` whose `proof.proof` bytes are arbitrary garbage — as long as they merely decode into the expected wire format with empty proof containers. `verify_state_proof` will report success without checking any actual state commitment, and the handler will proceed to call `host.store_response_receipt(...)` and dispatch `on_response` to the destination module, permanently marking that request as answered.

### Impact Explanation
This is a forged-message-delivery / route-freezing bug reachable by any unprivileged relayer submitting an unsigned `handle_unsigned` extrinsic (or the coprocessor's equivalent unsigned call):
- A relayer can force-finalize a `GetRequest` with an empty `keys` list using a fabricated proof that was never checked against any real consensus-verified state root, permanently consuming the request's response-receipt slot (`store_response_receipt`) and blocking the real answer from ever being delivered — a permanent freeze of that message route for the target request.
- In `pallet-state-coprocessor::handle_get_requests`, the same skip lets a relayer trigger `BandwidthGate::try_consume` and reputation-minting (`ReputationMinted`) accounting for a "response" whose authenticity was never verified, corrupting the fee/reward accounting for bandwidth purchasers.
- The severity is capped by the fact that this requires a `GetRequest` with an empty `keys` field to exist (source-application controlled), so it is not universally exploitable against arbitrary in-flight requests, matching the CVSS "AC:H" qualifier in the referenced advisory (the analogous condition there requires the caller to skip the ciphertext-update call).

### Likelihood Explanation
Likelihood is Medium: exploitation requires a `GetRequest` in flight whose `keys` field is empty. Nothing in the dispatcher, wire format, or handler enforces `keys.len() > 0`, so any application (including test/demo pallets, or a maliciously crafted GET dispatch from an app that doesn't defensively check) can create such a request, after which any permissionless relayer can exploit the gap with a garbage proof. No special privilege, consensus corruption, or cryptographic break is required — only a correctly-shaped but semantically empty state proof payload.

### Recommendation
In `verify_state_proof` (EVM, Substrate-EVM, Pharos, Tendermint implementations) and in the response/coprocessor handlers, explicitly reject requests whose `keys` (or `commitments`) argument is empty, or otherwise require that the number of verified entries be bound to a non-zero, caller-supplied expectation independent of the proof's own (attacker-controlled) container sizes — mirroring the fix pattern for the referenced CVE, where the authentication tag must always be (re)computed/verified regardless of whether the update path executed zero times.

### Proof of Concept
1. An application on state machine `A` dispatches a `GetRequest` with `keys: vec![]` (nothing in the dispatch path rejects this).
2. Before timeout, a relayer submits `pallet_ismp::Call::handle_unsigned` with a `Message::Response(ResponseMessage { requests: vec![that_get_request], proof, signer })` where `proof.proof` is a minimal encoding of `EvmStateProof { contract_proof: vec![], storage_proof: BTreeMap::new() }` (or the Substrate/Pharos equivalent empty containers) — bytes not derived from, or bound to, the real `state.state_root`.
3. `response.rs::handle` calls `state_machine.verify_state_proof(host, vec![], state.state_root, &proof)`, which decodes the proof successfully, finds no keys to check, and returns `Ok(BTreeMap::new())` without ever verifying `proof.proof` against `state.state_root`.
4. The handler proceeds to `store_response_receipt` and dispatch `on_response(GetResponse { get: request, values: vec![] })`, permanently marking the request as answered with a response whose "proof" was never cryptographically checked — corresponding to the OpenSSL PoC of empty AAD/ciphertext with an unrecomputed all-zero tag passing `EVP_DecryptFinal_ex`.

pub fn verify_state_proof<H: Keccak256 + Send + Sync>(
	keys: Vec<Vec<u8>>,
	root: H256,
	proof: &Proof,
	ismp_address: H160,
) -> Result<BTreeMap<Vec<u8>, Option<Vec<u8>>>, Error> {
	// Reject repeats before doing any work at all. They are already an error — repeats collapse
	// in the map returned below, so the caller's key-count check fails — but reaching that
	// check means every repeat has been verified first, and for account queries that is a
	// clone of the whole contract proof each time.
	let mut seen_keys = BTreeSet::new();
	for key in &keys {
		if !seen_keys.insert(key.as_slice()) {
			return Err(EvmStateMachineError::DuplicateKey.into());
		}
	}

	let evm_state_proof = decode_evm_state_proof(proof)?;
	let mut map = BTreeMap::new();
	let mut contract_to_keys = BTreeMap::new();
	let mut contract_account_queries = Vec::new();

	// Group keys by the contract address they belong to
	for key in keys {
		// For keys that are 52 bytes we expect the first 20 bytes to be the contract address and
		// the last 32 bytes the slot hash.
		// For keys that are 20 bytes we expect that to the
		// contract or account address.
		// For keys that are 32 bytes we expect that to be a slothash in
		// the Ismp EVM host
		let contract_address = if key.len() == 52 {
			H160::from_slice(&key[..20])
		} else if key.len() == 32 {
			ismp_address
		} else if key.len() == 20 {
			contract_account_queries.push(H160::from_slice(&key));
			continue;
		} else {
			return Err(EvmStateMachineError::UnsupportedKeyLength.into());
		};
		let entry = contract_to_keys.entry(contract_address.0.to_vec()).or_insert(vec![]);

		let slot_hash = if key.len() == 52 {
			H::keccak256(&key[20..]).0.to_vec()
		} else {
			H::keccak256(&key).0.to_vec()
		};

		entry.push((key, slot_hash));
	}

	// The storage proof must correspond exactly to the contracts a key was requested from:
	// every one covered, and nothing else. Both directions are settled here, before a single
	// entry is resolved — resolving one clones the whole contract proof and rebuilds its trie,
	// so checking as we go would let a proof padded with unrequested accounts do that work
	// before being rejected, and would make which error surfaces depend on map ordering.
	// The honest prover already emits exactly this set, deriving its map from the requested
	// keys, so nothing legitimate is turned away.
	let result = contract_to_keys
		.clone()
		.into_keys()
		.all(|contract| evm_state_proof.storage_proof.contains_key(&contract));
	if !result {
		return Err(EvmStateMachineError::IncompleteStorageProof.into());
	}

	if evm_state_proof
		.storage_proof
		.keys()
		.any(|contract| !contract_to_keys.contains_key(contract))
	{
		return Err(EvmStateMachineError::UnrequestedContractProof.into());
	}

		proof: &Proof,

			.ok_or(SubstrateEvmError::IsmpContractNotFound)?;

		let proof: SubstrateEvmProof =
			Decode::decode(&mut &proof.proof[..]).map_err(SubstrateEvmError::ProofDecodeError)?;

		let state_root = root;

		let keys_len = keys.len();
		let mut contract_keys: BTreeMap<H160, Vec<Vec<u8>>> = BTreeMap::new();
		for key in keys {
			let address = if key.len() == 52 {
				H160::from_slice(&key[..20])
			} else if key.len() == 32 {
				ismp_host_address
			} else {
				return Err(SubstrateEvmError::InvalidKeyLength(key.len()).into());
			};
			contract_keys.entry(address).or_default().push(key);
		}

		let mut result_map = BTreeMap::new();

		for (address, keys) in contract_keys {
			let contract_info_key = contract_info_key(address);
			let trie_id = fetch_trie_id_from_main_proof::<H>(
				&proof.main_proof,
				state_root,
				&contract_info_key,
			)?;

			let child_root =
				fetch_child_root_from_main_proof::<H>(&proof.main_proof, state_root, &trie_id)?;

			let storage_proof = proof
				.storage_proof
				.get(address.as_bytes())
				.ok_or(SubstrateEvmError::StorageProofMissing(address.as_bytes().to_vec()))?;

			let storage_keys: Vec<Vec<u8>> = keys
				.iter()
				.map(|k| {
					let slot = if k.len() == 52 { &k[20..] } else { &k[..] };
					blake2_256(slot).to_vec()

				.collect();

				result_map.insert(key, value);
			}
		}

			return Err(SubstrateEvmError::MismatchedValuesAndKeys.into());

pub fn verify_state_proof<H: Keccak256 + Send + Sync>(
	keys: Vec<Vec<u8>>,
	root: H256,
	proof: &Proof,
	ismp_address: H160,
) -> Result<BTreeMap<Vec<u8>, Option<Vec<u8>>>, Error> {
	let pharos_proof = decode_pharos_state_proof(proof)?;

	let state_root = root;

	// Pharos uses a flat trie — storage proofs verify directly against state_root.
	let mut map = BTreeMap::new();

	for key in keys {
		let (contract_addr, slot_hash) = if key.len() == 52 {
			// First 20 bytes = contract address, last 32 = slot hash
			let addr = H160::from_slice(&key[..20]);
			(addr, key[20..].to_vec())
		} else if key.len() == 32 {
			// Direct slot hash for the ISMP host contract
			(ismp_address, key.clone())
		} else if key.len() == 20 {
			// Account query which verifies account proof and return raw account value
			let address: [u8; 20] = key
				.clone()
				.try_into()
				.map_err(|e: Vec<u8>| PharosStateMachineError::InvalidAddressLength(e.len()))?;
			let account_data = pharos_proof
				.account_proofs
				.get(&key)
				.ok_or(PharosStateMachineError::MissingAccountProof)?;

			spv::verify_proof(
				&account_data.proof_nodes,
				&address,
				&account_data.raw_value,
				&state_root.0,
			)
			.map_err(|e| PharosStateMachineError::SpvVerificationFailed(alloc::format!("{e:?}")))?;

			map.insert(key, Some(account_data.raw_value.clone()));
			continue;
		} else {
			return Err(PharosStateMachineError::UnsupportedKeyLength.into());
		};

		let contract_address: [u8; 20] = contract_addr.0;

		let slot_key: [u8; 32] = slot_hash
			.clone()
			.try_into()
			.map_err(|e: Vec<u8>| PharosStateMachineError::InvalidSlotHashLength(e.len()))?;

		// Check if this is a non-existence proof
		if let Some(non_existence) = pharos_proof.non_existence_proofs.get(slot_key.as_slice()) {
			spv::verify_non_existence_proof(
				&non_existence.proof_nodes,
				&spv::build_storage_key(&contract_address, &slot_key),
				&state_root.0,
				&non_existence.sibling_proofs,
			)
			.map_err(|e| PharosStateMachineError::SpvVerificationFailed(alloc::format!("{e:?}")))?;
			map.insert(key, None);
			continue;
		}

		// Otherwise verify existence proof
		let storage_proof_nodes = pharos_proof
			.storage_proof
			.get(slot_key.as_slice())
			.ok_or(PharosStateMachineError::MissingStorageProof)?;

		let storage_value = pharos_proof
			.storage_values
			.get(&slot_hash)
			.ok_or(PharosStateMachineError::MissingStorageValue)?;

		// Pad value to 32 bytes for proof verification
		let mut padded_value = [0u8; 32];
		if storage_value.len() <= 32 {
			padded_value[32 - storage_value.len()..].copy_from_slice(storage_value);
		} else {
			return Err(PharosStateMachineError::StorageValueTooLarge.into());
		}

		spv::verify_proof(
			storage_proof_nodes,
			&spv::build_storage_key(&contract_address, &slot_key),
			&padded_value,
			&state_root.0,
		)
		.map_err(|e| PharosStateMachineError::SpvVerificationFailed(alloc::format!("{e:?}")))?;

		map.insert(key, Some(storage_value.clone()));
	}

	Ok(map)
}
