### Title
BidManager treats USDC/USDT as fixed $1 stablecoins with no depeg check when ranking solver bids - ([File: sdk/packages/sdk/src/protocols/intents/BidManager.ts])

### Summary
`BidManager.sortAllStables` (and `isStableToken`/`computeStablesUsdValue`) prices every "stable" output token at a hardcoded $1 when ranking competing solver bids for an intent order, exactly mirroring the Salty `PriceAggregator` bug class of trusting a fixed/assumed price for an asset without accounting for real-world depegging.

### Finding Description
When an order has multiple output assets and all of them are classified as stablecoins (USDC/USDT), `BidManager.sortBids` routes to `sortAllStables`, which calls `computeStablesUsdValue` to sum "normalised USD values (treating each stable as $1)" for both the required order outputs and every competing bid's outputs: [1](#0-0) 

This is the exact analog of the Salty finding: instead of consulting a live price feed for the actual traded token (WBTC), the code assumes a fixed 1:1 parity for the asset class (stablecoin ⇒ $1) and never checks whether that peg currently holds. `sortBids` decides which path to use purely from `isStableToken`: [2](#0-1) 

### Impact Explanation
`selectAndExecuteBest`/`selectBid` use `sortBids`'s ranking to decide which solver's `PackedUserOperation` gets simulated and executed to fill a real, on-chain, funded intent order: [3](#0-2) 

If any of the "stable" output tokens depegs (e.g., a USDC/USDT market stress event, similar in kind to the WBTC depeg cited in the original report), a malicious or opportunistic intent solver can submit a bid denominated in the depegged token. Because `computeStablesUsdValue` values it at a fixed $1 regardless of its real market price, that bid can appear as (or tie for) the top-ranked, most valuable bid and get selected/executed ahead of bids offering genuinely full-value tokens — the user (order placer) then receives depegged, lower-value tokens while the solver's bid is scored as if it were full value. This is a direct instance of "easier to manipulate the aggregated/assumed price in case of depegging," leading to the user receiving less real value than believed, i.e., value extraction from unprivileged users placing intents.

### Likelihood Explanation
Reachability is high: any user placing a multi-stable-output order and any unprivileged solver submitting a bid can trigger this path with zero special privileges — it runs on every `selectAndExecuteBest`/`selectBid` call whose order outputs are all recognized stables. The precondition (a real depeg event in USDC/USDT) is externally driven and has historically occurred (e.g., USDC's 2023 SVB-related depeg to ~$0.88), matching the "real-life depegging event" precedent cited in the original Salty report for WBTC.

### Recommendation
Do not hardcode a $1 valuation for "stable" tokens. Either (a) source a live price for each stable output token via a Chainlink feed (or equivalent oracle) and apply the same DEX/oracle price-guard logic already used in `sortMixedOutputs`/`computeOutputsUsdValue`, or (b) always fall back to `sortMixedOutputs`'s on-chain DEX-quote path for stable tokens too, rather than skipping pricing verification for the "all stables" case. At minimum, apply a sanity bound (e.g., reject/flag any stable priced far from $1 on-chain) before trusting the $1 assumption.

### Proof of Concept
1. An order is placed with two output legs, both tokens matching `isStableToken` (USDC and USDT) via `IntentGateway`/`BidManager`.
2. Two solvers submit competing bids: Solver A offers legitimate, fully-pegged USDC; Solver B offers a stablecoin that has depegged (market price ≈ $0.85) but is still classified by `isStableToken` as a stable.
3. `sortBids` detects `allStables === true` and calls `sortAllStables`, which values both bids' outputs at $1 per unit via `computeStablesUsdValue`.
4. Solver B's bid, despite being worth materially less in real USD terms, scores equal to or higher than Solver A's bid if it offers a nominally larger token amount, and gets selected by `selectAndExecuteBest`/`execute()`.
5. The user's order is filled with depegged tokens while the SDK reported it as the best (highest-USD) available bid — a direct value-loss for the order placer, mirroring the Salty PriceAggregator's mispricing of WBTC as BTC in the referenced report.

	async sortBids(order: Order, bids: Bid[]): Promise<Bid[]> {
		const outputs = order.output.assets

		if (outputs.length <= 1) {
			console.log(`[BidManager] Using single-output sorting (1 output asset)`)
			return this.sortSingleOutput(bids, outputs[0])
		}

		const chainId = this.ctx.dest.config.stateMachineId
		const allStables = outputs.every((o) => this.isStableToken(bytes32ToBytes20(o.token), chainId))

		if (allStables) {
			console.log(`[BidManager] Using all-stables sorting (${outputs.length} stable output assets)`)
			return this.sortAllStables(bids, outputs, chainId)
		}

		console.log(`[BidManager] Using mixed-output sorting (${outputs.length} output assets, some non-stable)`)
		return this.sortMixedOutputs(bids, outputs, chainId)
	}

	/**
	 * Case B: all outputs are USDC/USDT.
	 * Sum normalised USD values (treating each stable as $1) and sort descending.
	 * Partial fill bids are allowed.
	 */
	private sortAllStables(bids: Bid[], orderOutputs: TokenInfo[], chainId: string): Bid[] {
		const requiredUsd = this.computeStablesUsdValue(orderOutputs, chainId)
		console.log(`[BidManager] sortAllStables: required USD value=${requiredUsd.toString()}`)

		const validBids: { bid: Bid; usdValue: Decimal }[] = []

		for (const bid of bids) {
			const bidUsd = this.computeStablesUsdValue(bid.outputs, chainId)

			if (bidUsd === null) {
				console.warn(`[BidManager] Bid from solver=${bid.solverAddress} REJECTED: unable to compute USD value`)
				continue
			}

			if (bidUsd.lt(requiredUsd)) {
				console.log(
					`[BidManager] Bid from solver=${bid.solverAddress}: partial fill candidate ` +
						`(bid=${bidUsd.toString()}, required=${requiredUsd.toString()}, ` +
						`covers=${bidUsd.div(requiredUsd).mul(100).toFixed(2)}%)`,
				)
			} else {
				console.log(`[BidManager] Bid from solver=${bid.solverAddress} ACCEPTED: USD value=${bidUsd.toString()}`)
			}

			validBids.push({ bid, usdValue: bidUsd })
		}

		validBids.sort((a, b) => b.usdValue.comparedTo(a.usdValue))
		return validBids.map(({ bid }) => bid)
	}
