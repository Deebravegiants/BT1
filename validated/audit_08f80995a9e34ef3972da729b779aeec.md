Audit Report

## Title
Unauthenticated request-ID collision allows front-running griefing of legitimate relay requests - (File: `core/services/gateway/handlers/confidentialrelay/handler.go`)

## Summary
`HandleJSONRPCUserMessage` in the confidential relay gateway handler accepts a JSON-RPC request from any HTTP caller and immediately registers it into the shared `activeRequests` map keyed solely by the caller-supplied `req.ID`, with no authentication or authorization step preceding this write [1](#0-0) . Because the existence check and insert (`newActiveRequest`) happen unconditionally before any signature/attestation verification at the gateway layer, an unauthenticated attacker who submits a request with the same `ID` first causes any later legitimate request bearing that same ID to be rejected with `"request ID already exists"` [2](#0-1) .

## Finding Description
`HandleJSONRPCUserMessage` performs only ID emptiness/length checks before calling `newActiveRequest`, which does a lock-guarded existence check on `h.activeRequests[req.ID]` and returns an error if occupied, otherwise inserting the caller's entry [3](#0-2) . There is no `AuthorizeRequest`/allowlist call anywhere in this method, unlike the vault handler's pipeline, where the equivalent `newActiveRequest` call is only reached after `h.requestProcessor.ProcessRequest` authorizes the caller and rewrites `req.ID` to an owner-prefixed ID (`authorizedOwner + separator + originalRequestID`) [4](#0-3) [5](#0-4) . This owner-prefixing scopes vault ID collisions to the same authenticated owner; the confidential relay handler has no such scoping.

This gap is confirmed directly by the test `TestConfidentialRelayHandler_DuplicateRequestID`, which submits two requests with identical `ID` through `HandleJSONRPCUserMessage` and shows the second fails with `"request ID already exists"` [6](#0-5) . The gateway's `ProcessRequest`, which is the single entry point for both the vault and confidential-relay handlers, routes any decoded JSON-RPC request straight into `h.HandleJSONRPCUserMessage` with no caller-identity check performed by the gateway itself [7](#0-6) . The `requestLabels`/`extractRequestLabels` comment explicitly documents that the gateway "does not otherwise interpret params" and stays a "dumb relay," consistent with the actual per-request authorization (attestation + Workflow-DON quorum check) being performed later, node-side, in `core/capabilities/confidentialrelay/handler.go`'s `handleCapabilityExecute`/`handleSecretsGet` rather than at the gateway [8](#0-7) [9](#0-8) .

## Impact Explanation
An unauthenticated network client reaching the gateway's user-facing HTTP endpoint can deny service to a specific legitimate confidential-relay request (`MethodCapabilityExec`/`MethodSecretsGet`) by pre-registering the same `req.ID` before the legitimate caller's request arrives. Because this check occurs strictly before any attestation or workflow-owner verification at the gateway, no privileged access is required to trigger it, and the victim's genuine request errors out immediately with `"request ID already exists"` rather than being serviced by the relay DON. This is a griefing/DoS of a targeted request rather than key or fund compromise: it does not by itself leak secrets, bypass authorization for capability results, or corrupt another user's response content, since the actual authorization/attestation of the relayed content still happens node-side and rejects unauthenticated/forged payloads there.

## Likelihood Explanation
Exploitability depends on the attacker being able to predict or observe a specific victim's `req.ID` before it is submitted, since the gateway's HTTP endpoint is reachable by any unauthenticated client and performs no pre-registration identity check. The severity of this finding is bounded by that predictability requirement and by the fact that it only griefs a single targeted request per guessed ID (each attempt requires knowing/guessing another specific ID), rather than enabling broad service disruption, secret exfiltration, or unauthorized fund movement.

## Recommendation
Namespace `activeRequests` (or otherwise scope the collision check) by an authenticated caller identity, or require minimal request authentication/attestation-binding before performing the existence check and insert into shared state, mirroring the vault pipeline's authorize-then-prefix approach so an unauthenticated caller cannot occupy another party's request-ID slot.

## Proof of Concept
1. Send a `MethodCapabilityExec` JSON-RPC request to the gateway's public HTTP endpoint with `ID` set to a value the victim will use, and arbitrary/garbage params, before the victim's real request arrives.
2. `newActiveRequest` inserts the attacker's entry into `h.activeRequests[req.ID]`.
3. When the victim's legitimate request with the same ID arrives, `newActiveRequest` returns `"request ID already exists: " + req.ID"`, and `HandleJSONRPCUserMessage` returns this error immediately, denying the victim's request — reproduced directly by `TestConfidentialRelayHandler_DuplicateRequestID`.

func (h *handler) HandleJSONRPCUserMessage(ctx context.Context, req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) error {
	if req.ID == "" {
		return errors.New("request ID cannot be empty")
	}
	if len(req.ID) > 200 {
		return errors.New("request ID is too long: " + strconv.Itoa(len(req.ID)) + ". max is 200 characters")
	}

	labels := h.extractRequestLabels(req)
	l := h.requestLogger(req, labels)
	l.Debugw("handling confidential relay request", "nodes", len(h.donConfig.Members), "f", h.donConfig.F)

	ar, err := h.newActiveRequest(req, labels, callback)
	if err != nil {
		return err
	}

	return h.fanOutToNodes(ctx, l, ar)
}

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], labels requestLabels, callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID, "executionID", labels.ExecutionID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		labels:    labels,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

func TestConfidentialRelayHandler_DuplicateRequestID(t *testing.T) {
	t.Parallel()
	h, cb, don, _ := setupHandler(t, 4)
	don.On("SendToNode", mock.Anything, mock.Anything, mock.Anything).Return(nil)

	params := json.RawMessage(`{"workflow_id":"wf1"}`)
	req := jsonrpc.Request[json.RawMessage]{
		ID:     "req-dup",
		Method: MethodCapabilityExec,
		Params: &params,
	}

	err := h.HandleJSONRPCUserMessage(t.Context(), req, cb)
	require.NoError(t, err)

	cb2 := common.NewCallback()
	err = h.HandleJSONRPCUserMessage(t.Context(), req, cb2)
	require.ErrorContains(t, err, "request ID already exists")
