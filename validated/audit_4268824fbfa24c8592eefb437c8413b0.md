### Title
Creator fee claims in `FeeVault.claim()` are restricted to `msg.sender`, permanently freezing accrued fees for contract-creator addresses that cannot self-call - ([File: packages/contracts/src/FeeVault.sol])

### Summary
`FeeVault.claim()` only pays out the `creatorBalance[msg.sender]` and provides no mechanism for a third party to claim on behalf of another address, unlike `claimProtocol()` which is explicitly permissionless [1](#0-0) . Since `Bonding` allows a token's `creator` to be any address, including an arbitrary contract that never calls `Zap.createToken`/`Bonding.launch` and simply receives fee attribution via `transferCreator`, a creator that is a contract without built-in `claim()`/`transferCreator()` call logic can never retrieve its accrued USDC fees.

### Finding Description
Creator attribution is set at launch and can be reassigned via `Bonding.transferCreator`, which is itself restricted to `msg.sender == info.creator` [2](#0-1) . Fees accrue into `FeeVault.creatorBalance[creator]` through `accrue()`, called by `Zap` on every buy/sell [3](#0-2) . The only way to retrieve that balance is `FeeVault.claim()`, which hardcodes `msg.sender` as both the balance key and the transfer recipient:
```solidity
function claim() external nonReentrant returns (uint256 amount) {
    amount = $.creatorBalance[msg.sender];
    ...
    $.usdc.safeTransfer(msg.sender, amount);
}
``` [4](#0-3) 

There is no "claim on behalf of" variant, and no way for the FeeVault owner or anyone else to redirect a stuck creator's balance to a reachable address. Both the entry point that could redirect attribution (`transferCreator`) and the exit point that pays it out (`claim`) require the exact `creator` address itself to originate the call. If the `creator` address recorded in `Bonding.tokenInfo` is a smart contract that has no function calling `claim()`/`transferCreator()` (e.g., a vault, a multisig lacking an arbitrary-call function, a contract deployed by a factory pattern, or simply a contract whose owner never anticipated needing to call an external unrelated contract), the fees accrued to that creator are permanently unreachable — this mirrors the reported analog where `TrufMigrator.migrate()` only allows `msg.sender` to claim for itself, stranding contract-held balances.

Contrast this with `claimProtocol()`, which the codebase's own documentation explicitly designed to be permissionless specifically because "anyone can trigger the payout, but funds always go to the admin-set address" [5](#0-4) . No equivalent design decision was made for creator claims, leaving an asymmetric trust/reachability model for the two claimant classes.

### Impact Explanation
Any creator address that is a smart contract without call-forwarding logic permanently loses access to its accrued 0.25% creator fee share on every buy/sell of its token. Because `FeeVault` fully backs `creatorBalance` 1:1 in USDC (enforced by the `UnderfundedAccrual` check in `accrue()`), the funds are not lost from the vault's accounting but are permanently frozen — capital that can never be extracted by the creator or redirected by anyone else, satisfying "permanent freezing of ... creator ... funds."

### Likelihood Explanation
Reaching this requires only an ordinary, permissionless action: launching a token (or being assigned creator via `transferCreator`) with a creator address that is a contract lacking a generic `call`/`execute` primitive. This is a realistic and common occurrence — automated launcher bots, vesting contracts, or DAOs frequently use minimal proxy/contract wallets that were never designed to originate arbitrary external calls to `FeeVault.claim()`.

### Recommendation
Add a permissionless or delegated claim path analogous to `claimProtocol()`'s design, e.g. `claimFor(address creator)` that pays out `creatorBalance[creator]` to `creator` regardless of caller (safe, since funds always go to the balance owner, not the caller), mirroring the permissionless-but-fixed-recipient pattern already used for `claimProtocol()` and `sweepDonations()`.

### Proof of Concept
1. Deploy a minimal contract `CreatorWallet` with no fallback/execute function, i.e. it cannot call arbitrary external contracts.
2. Have `CreatorWallet` (or an EOA that later calls `Bonding.transferCreator(token, address(CreatorWallet))`) become `info.creator` for a launched token.
3. Trigger buys/sells through `Zap`, causing `FeeVault.accrue()` to credit `creatorBalance[address(CreatorWallet)]`.
4. Attempt `FeeVault.claim()` — it can only be called successfully by `msg.sender == address(CreatorWallet)`; since `CreatorWallet` has no logic to invoke it, and `transferCreator` likewise requires `msg.sender == info.creator`, the balance in `FeeVault` is permanently unreachable by any party.

    function accrue(
        address token,
        address creator,
        uint256 creatorAmount,
        uint256 protocolAmount,
        bool isBuy
    ) external onlyDepositor {
        FeeVaultStorage storage $ = _s();
        if (creatorAmount > 0) {
            if (creator == address(0)) revert ZeroAddress();
            $.creatorBalance[creator] += creatorAmount;
            $.totalAccruedCreator += creatorAmount;
            $.lifetimeCreatorEarned[creator] += creatorAmount;
        }
        if (protocolAmount > 0) {
            $.protocolBalance += protocolAmount;
            $.lifetimeProtocolEarned += protocolAmount;
        }
        if ($.usdc.balanceOf(address(this)) < $.totalAccruedCreator + $.protocolBalance) {
            revert UnderfundedAccrual();
        }
        emit FeeAccrued(token, creator, creatorAmount, protocolAmount, isBuy);
    }

    function claim() external nonReentrant returns (uint256 amount) {
        FeeVaultStorage storage $ = _s();
        amount = $.creatorBalance[msg.sender];
        if (amount == 0) revert NothingToClaim();
        $.creatorBalance[msg.sender] = 0;
        $.totalAccruedCreator -= amount;
        $.usdc.safeTransfer(msg.sender, amount);
        emit CreatorFeesClaimed(msg.sender, amount);
    }

    function claimProtocol() external nonReentrant returns (uint256 amount) {
        FeeVaultStorage storage $ = _s();
        amount = $.protocolBalance;
        if (amount == 0) revert NothingToClaim();
        $.protocolBalance = 0;
        address feeTo_ = $.feeTo;
        $.usdc.safeTransfer(feeTo_, amount);
        emit ProtocolFeesClaimed(feeTo_, amount);
    }

        address tokenAddress,
        address newCreator

        if (newCreator == address(0)) revert ZeroAddress();
        TokenInfo storage info = _s().tokenInfo[tokenAddress];
        if (msg.sender != info.creator) revert NotCreator();
        if (newCreator == info.creator) revert InvalidInput();
