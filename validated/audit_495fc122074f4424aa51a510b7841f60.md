### Title
`validateDogeAddress` accepts base58-format strings with no checksum verification, allowing withdrawal to an unspendable Dogecoin address - ([File: packages/intents-sdk/src/lib/validateAddress.ts])

### Summary
`validateDogeAddress` in `packages/intents-sdk/src/lib/validateAddress.ts` only checks the address against a regex shape (`/^[DA][1-9A-HJ-NP-Za-km-z]{25,33}$/`) and never decodes/verifies the base58Check checksum, unlike the sibling implementations for Bitcoin, Litecoin, and Dash in the same file which decode the base58 payload and verify the double-SHA256 checksum bytes. This lets a caller pass a `destinationAddress` that merely "looks like" a Dogecoin address (correct prefix/charset/length) but has a corrupted or fabricated checksum, and `validateAddress(address, Chains.Dogecoin)` returns `true` for it.

### Finding Description
The broken equality is: *`validateAddress(address, Chains.Dogecoin) === true` should imply `address` is a real, checksum-valid, spendable Dogecoin address* — but the code only guarantees regex-shape validity, not checksum validity.

Code path:
- `validateAddress(address, Chains.Dogecoin)` dispatches to `validateDogeAddress(address)` [1](#0-0) .
- `validateDogeAddress` is purely a regex test with no base58 decode or checksum verification: [2](#0-1) .
- Contrast with `validateLitecoinBase58Address` and `validateDashAddress`, which decode via `base58.decode`, check the byte length is 25 (version + 20-byte hash + 4-byte checksum), verify the version byte, and compare the last 4 bytes against `sha256(sha256(payload))`: [3](#0-2) [4](#0-3) .
- In `PoaBridge.validateWithdrawal`, `validateAddress` is the sole address-format gate before proceeding to build the withdrawal intent: [5](#0-4) .
- `createWithdrawIntentPrimitive` in `poa-bridge-utils.ts` embeds `destinationAddress` verbatim (only lower-casing for a `bitcoincash:` prefix strip, irrelevant to Doge) into the `WITHDRAW_TO:<address>` memo with no further validation: [6](#0-5) .

Attacker input: any 26–34 character string starting with `D` or `A`, using only base58 characters, e.g. take a valid address `D86DwJpYsyV7nTP2ib5qdwGsb2Tj7LgzPP` and flip one interior character to `D86DwJpYsyV7nTP2ib5qdwGsb2Tj7LgzPQ`. The regex still matches (shape/length/charset unaffected), so `validateAddress` returns `true`, but the base58Check checksum no longer matches and no such spendable Dogecoin address exists on-chain.

Existing guards do not catch this: `validateWithdrawal`'s only address check is `validateAddress`, `compareAddresses` only guards against the address matching the token's own origin-chain address, and there is no other checksum verification anywhere in the withdrawal path for Dogecoin.

### Impact Explanation
A caller (the SDK integrator or an end user constructing withdrawal params) can have their own funds routed to a memo string that decodes to no valid Dogecoin script — the PoA bridge relayer, seeing an unspendable/invalid destination in the `WITHDRAW_TO` memo, cannot deliver the funds to any real address the user controls. This is the "funds delivered to a wrong address/chain/contract with no recovery" Critical category, but note the funds are the caller's own (the question explicitly scopes this as "user's own funds"), and it requires the caller (or an integrator forwarding externally-supplied strings) to submit a corrupted string in the first place — the SDK's validation, which is supposed to be a safety net, silently fails to catch it. It is repeatable for every Doge withdrawal call.

### Likelihood Explanation
Preconditions: caller must supply a `destinationAddress` for `Chains.Dogecoin`/`nep141:doge.omft.near` that matches the regex shape but has an invalid base58Check checksum (e.g., due to a typo, a copy-paste error, or a malicious counterparty feeding a corrupted string to an integrator who does not do their own checksum validation). Attacker cost is trivial — flip one character in a valid-looking string. Feasibility is high since regex-only validation is easy to satisfy; likelihood of accidental occurrence (typos) is realistic, and it is straightforward to construct deliberately in a proof of concept.

### Recommendation
Implement full base58Check decoding and double-SHA256 checksum verification for Dogecoin addresses, mirroring the existing pattern used for Litecoin (`validateLitecoinBase58Address`) and Dash (`validateDashAddress`): decode the address, verify total length is 25 bytes, verify the version byte matches Dogecoin's P2PKH (`0x1E`) or P2SH (`0x16`) prefixes, and verify the last 4 bytes equal `sha256(sha256(version+hash160))[0:4]`.

function validateLitecoinBase58Address(
	address: string,
	expectedVersion: number,
): boolean {
	let decoded: Uint8Array;

	try {
		decoded = base58.decode(address);
	} catch {
		return false;
	}

	// version (1) + payload (20) + checksum (4)
	if (decoded.length !== 25) return false;

	const version = decoded[0];
	if (version !== expectedVersion) return false;

	const payload = decoded.subarray(0, 21); // version + hash160
	const checksum = decoded.subarray(21, 25);

	const hash1 = sha256(payload);
	const hash2 = sha256(hash1);
	const expectedChecksum = hash2.subarray(0, 4);

	for (let i = 0; i < 4; i++) {
		if (checksum[i] !== expectedChecksum[i]) return false;
	}

	return true;
}

export function validateDashAddress(address: string): boolean {
	try {
		const decoded: Uint8Array = base58.decode(address);

		// version (1) + payload (20) + checksum (4)
		if (decoded.length !== 25) return false;

		const version = decoded[0];
		if (
			version !== 0x4c && // P2PKH
			version !== 0x10 // P2SH
		) {
			return false;
		}

		const payload = decoded.subarray(0, 21);
		const checksum = decoded.subarray(21, 25);

		const hash1 = sha256(payload);
		const hash2 = sha256(hash1);
		const expectedChecksum = hash2.subarray(0, 4);

		for (let i = 0; i < 4; i++) {
			if (checksum[i] !== expectedChecksum[i]) return false;
		}

		return true;
	} catch {
		return false;
	}
}

export function createWithdrawIntentPrimitive(params: {
	assetId: string;
	destinationAddress: string;
	destinationMemo: string | undefined;
	amount: bigint;
}): Extract<IntentPrimitive, { intent: "ft_withdraw" }> {
	const { contractId: tokenAccountId } = utils.parseDefuseAssetId(
		params.assetId,
	);
	return {
		intent: "ft_withdraw",
		token: tokenAccountId,
		receiver_id: tokenAccountId,
		amount: params.amount.toString(),
		memo: createWithdrawMemo({
			receiverAddress: params.destinationAddress,
			xrpMemo: params.destinationMemo,
		}),
		min_gas: MIN_GAS_AMOUNT,
	};
}

function createWithdrawMemo({
	receiverAddress,
	xrpMemo,
}: {
	receiverAddress: string;
	xrpMemo: string | undefined;
}) {
	// Strip "bitcoincash:" prefix from BCH CashAddr addresses
	const normalizedAddress = receiverAddress
		.toLowerCase()
		.startsWith("bitcoincash:")
		? receiverAddress.slice("bitcoincash:".length)
		: receiverAddress;

	const memo = ["WITHDRAW_TO", normalizedAddress];

	if (xrpMemo != null && xrpMemo !== "") {
		memo.push(xrpMemo);
	}

	return memo.join(":");
}
