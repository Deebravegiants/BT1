## Title
Unauthenticated access to LOOP plugin pprof/metrics proxy endpoints allows unprivileged remote profiling, plugin-topology disclosure, and DoS - ([File: core/web/router.go])

## Summary
`loopRoutes` registers `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` directly on the top-level unauthenticated `api` router group, with no `auth.Authenticate` wrapper, unlike the functionally comparable `debugRoutes` group which explicitly requires session authentication for its `/debug/vars` endpoint. This lets any network client that can reach the node's HTTP API enumerate LOOP plugin topology and trigger expensive, attacker-controlled-duration pprof profiling operations against internal plugin processes without any credentials.

## Finding Description
`loopRoutes` is mounted on the `api` group, which itself only has rate-limiting and cookie-session middleware applied (no auth check): [1](#0-0) 

The route registrations for the loop plugin proxy handlers carry no authentication middleware: [2](#0-1) 

By contrast, `debugRoutes`, which exposes a comparable capability (`/debug/vars`), is explicitly wrapped with `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)`: [3](#0-2) 

The handler `pluginPPROFHandler` forwards the client-supplied `profile` path segment and query parameters straight to an internal plugin's `/debug/pprof/*` endpoint and returns the raw response: [4](#0-3) 

`pprofURLVals` parses the `seconds` query parameter directly from the unauthenticated request and uses it, unbounded, to compute the request timeout that gates how long the CPU-profile capture runs: [5](#0-4) 

`pluginMetricHandler` and `discoveryHandler` similarly require no credential and disclose plugin names/labels and forward metrics requests: [6](#0-5) [7](#0-6) 

The broken security assumption is that all sensitive introspection/debug endpoints in this router are gated by `auth.Authenticate` as `debugRoutes` demonstrates is the intended pattern in this exact file — but `loopRoutes` was registered without it, an inconsistency directly visible in the router wiring at line 87–91.

## Impact Explanation
An unauthenticated network client reaching the node's WebServer HTTP port can:
- Enumerate registered LOOP plugins and internal topology/labels via `/discovery` and `/plugins/:name/metrics`.
- Trigger CPU/goroutine/heap profiling on internal plugin processes via `/plugins/:name/debug/pprof/*`, with an attacker-controlled `seconds` parameter influencing the duration of the operation, creating a resource-exhaustion/availability risk on the plugin process.
- This is an authentication-bypass-class issue (missing auth middleware on a sensitive route family), falling under the in-scope "node API authentication or role bypass" impact category, with an information-disclosure and availability angle rather than fund loss or key exfiltration.

## Likelihood Explanation
Likelihood is high for any deployment where the node's WebServer HTTP port is reachable from an untrusted network segment, since no credentials, session cookie, or API token are required to invoke any of these four routes — a plain unauthenticated GET/POST is sufficient. The exploit requires no privileged starting point and is trivially repeatable/scriptable.

## Recommendation
Wrap `loopRoutes` registration with the same `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)` (or token-based) middleware used for `debugRoutes`/`v2Routes`, and consider gating profiling behind `auth.RequiresAdminRole` given its operational sensitivity. Additionally, validate/bound the `seconds` parameter and consider rate-limiting this route group distinctly.

## Proof of Concept
```

curl -s "http://<node-host>:6688/plugins/<plugin-name>/metrics"
```

```go
func (l *LoopRegistryServer) discoveryHandler(w http.ResponseWriter, req *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	groups := make([]*targetgroup.Group, 0, 1+len(l.registry.List()))

	// add node metrics to service discovery
	groups = append(groups, pluginGroup(l.discoveryHostName, l.exposedPromPort, "/metrics"))

	// add all the plugins
	for _, registeredPlugin := range l.registry.List() {
		group := pluginGroup(l.discoveryHostName, l.exposedPromPort, pluginMetricPath(registeredPlugin.Name))
		group.Labels[LabelMetaPluginName] = model.LabelValue(registeredPlugin.Name)
		groups = append(groups, group)
	}

	b, err := l.jsonMarshalFn(groups)
	if err != nil {
		w.WriteHeader(http.StatusInternalServerError)
		_, err = w.Write([]byte(err.Error()))
		if err != nil {
			l.logger.Error(err)
		}
		return
	}
	_, err = w.Write(b)
	if err != nil {
		w.WriteHeader(http.StatusInternalServerError)
		l.logger.Error(err)
	}
}
```

```go
const PPROFOverheadSeconds = 30

func pprofURLVals(gc *gin.Context) (urlVals url.Values, timeout time.Duration) {
	urlVals = make(url.Values)
	if db, ok := gc.GetQuery("debug"); ok {
		urlVals.Set("debug", db)
	}
	if gc, ok := gc.GetQuery("gc"); ok {
		urlVals.Set("gc", gc)
	}
	timeout = PPROFOverheadSeconds * time.Second
	if sec, ok := gc.GetQuery("seconds"); ok {
		urlVals.Set("seconds", sec)
		if i, err := strconv.Atoi(sec); err == nil {
			timeout = time.Duration(i+PPROFOverheadSeconds) * time.Second
		}
	}
	return urlVals, timeout
}
```
