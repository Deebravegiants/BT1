Audit Report

## Title
LDAP DN injection via unescaped `email` field in bind/search DN construction - ([File: core/sessions/ldapauth/ldap.go])

## Summary
`SessionsController.Create` in `core/web/sessions_controller.go` accepts an unauthenticated JSON login request and binds the raw body into `clsessions.SessionRequest{Email, Password}` before forwarding it to `AuthenticationProvider().CreateSession(ctx, sr)`. [1](#0-0) [2](#0-1)  When LDAP auth is configured, `ldapAuthenticator.CreateSession` and `TestPassword` build the LDAP bind DN with `fmt.Sprintf` using `ldap.EscapeFilter(strings.ToLower(sr.Email))`, which only escapes RFC 4515 filter metacharacters (`(`, `)`, `*`, `\`, NUL) and not RFC 4514 DN metacharacters such as `,`, `+`, `"`, `<`, `>`, `;`, `=`. [3](#0-2) [4](#0-3) 

## Finding Description
The `Email` field flows unauthenticated and unvalidated from the HTTP request body into a raw DN string that is passed directly to `conn.Bind()`. Because `escapedEmail` is only filter-escaped, DN-structural characters (most notably `,`) survive into the final `searchBaseDN := fmt.Sprintf("%s=%s,%s,%s", l.config.BaseUserAttr(), escapedEmail, l.config.UsersDN(), l.config.BaseDN())` string, meaning a crafted email can inject additional RDN components and change the DN structure actually presented to the LDAP bind call rather than being treated as an inert filter/attribute value. No other layer (gin binding, `ShouldBindJSON`, or the authenticator) performs DN-specific escaping or validation before this call. [5](#0-4) [6](#0-5) 

## Impact Explanation
This affects an internet-facing, pre-authentication endpoint (`POST /sessions`), which is unauthenticated by design. On nodes where `WebServer.AuthenticationMethod = 'ldap'` is enabled, an attacker-controlled email value can alter the bind DN structure sent to the upstream LDAP directory, which is the root cause class behind DN-confusion bugs like CVE-2020-27840. Actual authentication bypass still requires the attacker to also supply a valid password for whatever DN results from the injection, which constrains real-world exploitability, but the underlying escaping defect is real and maps to the "node API authentication bypass" impact category since it corrupts the security-relevant DN construction used for authentication decisions. [7](#0-6) 

## Likelihood Explanation
The vulnerable code path is reachable pre-authentication by any network client capable of reaching `/sessions`, with no credential or role required to trigger the flawed DN construction itself. [8](#0-7)  Exploitability is gated behind the opt-in `WebServer.AuthenticationMethod = 'ldap'` configuration (not default), which limits blast radius but does not make the code path itself hypothetical — it is unconditionally reachable pre-auth on any node running with that configuration. [9](#0-8) 

## Recommendation
Replace `ldap.EscapeFilter` with proper RFC 4514 DN escaping (escaping `,`, `+`, `"`, `\`, `<`, `>`, `;`, `=`, and leading/trailing spaces) wherever a value is inserted into a DN string via `fmt.Sprintf`, specifically in `CreateSession` and `TestPassword` in `core/sessions/ldapauth/ldap.go`. Keep `EscapeFilter` only for values used in actual LDAP search filter contexts (e.g., `filterQuery`). [10](#0-9) [11](#0-10) 

## Proof of Concept
1. Configure a node with `WebServer.AuthenticationMethod = 'ldap'` and set `WebServer.LDAP.BaseDN`, `BaseUserAttr`, `UsersDN` per `docs/CONFIG.md`. [9](#0-8) 
2. `POST /sessions` with a JSON body `{"email": "x,ou=OtherOU,dc=custom,dc=example,dc=com", "password": "..."}`.
3. Observe that `searchBaseDN` in `CreateSession`/`TestPassword` is constructed with the injected comma-delimited DN suffix intact rather than being escaped, altering the DN structure passed to `conn.Bind()` instead of being treated as a single literal `uid` value. [5](#0-4)

func (l *ldapAuthenticator) CreateSession(ctx context.Context, sr sessions.SessionRequest) (string, error) {
	conn, err := l.ldapClient.CreateEphemeralConnection()
	if err != nil {
		return "", errors.New("unable to establish connection to LDAP server with provided URL and credentials")
	}
	defer conn.Close()

	var returnErr error

	// Attempt to LDAP Bind with user provided credentials
	escapedEmail := ldap.EscapeFilter(strings.ToLower(sr.Email))
	searchBaseDN := fmt.Sprintf("%s=%s,%s,%s", l.config.BaseUserAttr(), escapedEmail, l.config.UsersDN(), l.config.BaseDN())
	if err = conn.Bind(searchBaseDN, sr.Password); err != nil {
		l.lggr.Infof("Error binding user authentication request in LDAP Bind: %v", err)
		returnErr = errors.New("unable to log in with LDAP server. Check credentials")
	}
