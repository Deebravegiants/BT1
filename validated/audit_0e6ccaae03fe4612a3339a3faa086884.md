Audit Report

## Title
CORS wildcard-origin allowlist bypass via unbounded suffix match in `isAllowedOrigin` - ([File: core/services/gateway/network/httpserver.go])

## Summary
`isAllowedOrigin` in `core/services/gateway/network/httpserver.go` implements wildcard CORS-origin matching (`*.domain.com`) using a raw `strings.HasSuffix` check with no domain-boundary enforcement, so any origin host string that merely ends with the configured suffix (e.g., `evilremix.com` matching `*.remix.com`) is incorrectly treated as an allowed origin. This is directly reachable by any unauthenticated client via the `Origin` header on the internet-facing gateway HTTP endpoint.

## Finding Description
The wildcard-matching branch of `isAllowedOrigin` [1](#0-0)  strips the `*.` prefix from the configured allowed host and then checks `strings.HasSuffix(originHost, allowedHost)` with no requirement that the preceding character be a `.` boundary. This means `strings.HasSuffix("evilremix.com", "remix.com")` returns `true`, incorrectly matching a sibling/lookalike domain rather than a genuine subdomain.

The result feeds directly into `handleRequest`, which reflects the attacker-supplied `Origin` value into `Access-Control-Allow-Origin` when `isAllowedOrigin` returns true [2](#0-1) . There is no other boundary check, allowlist normalization, or additional validation anywhere in this path — the exact/scheme/port checks preceding the wildcard branch do not mitigate the suffix issue [3](#0-2) .

This requires no credentials, no admin access, and no host access — an unauthenticated browser client can simply send a normal cross-origin request with a crafted `Origin` header to the gateway's HTTP endpoint. The precondition is that the operator has configured a wildcard entry in `CORSAllowedOrigins`, which is a documented, ordinary configuration option (not a misconfiguration/mistake) [4](#0-3) .

## Impact Explanation
An attacker who registers a domain ending in the configured suffix (e.g., `evilremix.com` when `*.remix.com` is allowlisted) is granted CORS trust equivalent to a genuine subdomain of the trusted domain. This lets pages on the attacker's domain issue cross-origin requests to the gateway and read the responses via the browser's fetch/XHR, which is a genuine cross-origin allowlist bypass and falls into the "allowlist bypass" / "cross-user response corruption" impact category for the gateway's internet-facing HTTP endpoint.

## Likelihood Explanation
Exploitability requires only that the operator use a wildcard `CORSAllowedOrigins` entry — a normal, supported feature (not requiring any special privilege from the attacker) — and that the attacker register a domain string ending with the same suffix. No victim credential compromise, no server-side access, and no special role are needed; the flawed comparison is purely a client-triggerable header-matching bug in code the gateway executes on every incoming request.

## Recommendation
Enforce a domain boundary when matching wildcard suffixes, for example:
```go
if strings.HasPrefix(allowedHost, "*.") {
    base := allowedHost[2:]
    if originHost == base || strings.HasSuffix(originHost, "."+base) {
        return true
    }
}
```
This ensures `originHost` must equal the base domain or be a true subdomain (preceded by a literal `.`), preventing sibling/lookalike domains such as `evilremix.com` from matching `*.remix.com`.

## Proof of Concept
1. Configure the gateway with `CORSAllowedOrigins = ["https://*.remix.com"]` and `CORSEnabled = true`.
2. Send an HTTP request to the gateway's configured `Path` endpoint with header `Origin: https://evilremix.com`.
3. Observe that `isAllowedOrigin` returns `true` because `strings.HasSuffix("evilremix.com", "remix.com")` is `true`, and the response includes `Access-Control-Allow-Origin: https://evilremix.com`.
4. A Go unit test calling `httpServer.isAllowedOrigin("https://evilremix.com")` with `CORSAllowedOrigins: []string{"https://*.remix.com"}` configured demonstrates the bypass returns `true` instead of the expected `false`.

```go
func (s *httpServer) isAllowedOrigin(origin string) bool {
	originScheme, originHost, originPort, err := s.splitURL(origin)
	if err != nil {
		s.lggr.Debug("error parsing origin URL", err)
		return false
	}
	for _, allowed := range s.config.CORSAllowedOrigins {
		// probably better to do this once when server starts and store it in a map
		// this is an easier solution so we don't have to apply more changes to the code
		// just need to be careful when specifying allowed origins in the config file
		allowedScheme, allowedHost, allowedPort, err := s.splitURL(allowed)
		if err != nil {
			s.lggr.Debug("error parsing allowed origin URL", err)
			continue
		}
		// skip if the scheme doesn't match at all
		if originScheme != allowedScheme {
			continue
		}
		// skip if the port doesn't match at all
		if originPort != allowedPort {
			continue
		}
		// check for exact host match (e.g., remix.com)
		if originHost == allowedHost {
			return true
		}
		// check for wildcard host match (e.g., *.remix.com)
		if strings.HasPrefix(allowedHost, "*.") {
			allowedHost = allowedHost[2:]
			if strings.HasSuffix(originHost, allowedHost) {
				return true
			}
		}
	}
	return false
}
```
