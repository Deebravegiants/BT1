Audit Report

## Title
Nil-pointer dereference on unauthenticated gateway request via missing "params" field in `JSONRPCCodec.DecodeJSONRequest` - (File: `core/services/gateway/api/jsonrpccodec.go`)

## Summary
`JSONRPCCodec.DecodeJSONRequest` dereferences `request.Params` (`*json.RawMessage`) via `json.Unmarshal(*request.Params, &msg)` without a nil check. [1](#0-0)  Because JSON-RPC `params` is optional, a request that omits it entirely reaches this line unmodified through `gateway.ProcessRequest`, which calls `g.codec.DecodeJSONRequest(jsonRequest)` immediately after `jsonrpc2.DecodeRequest` and before any DON/handler-specific validation. [2](#0-1)  This causes a panic on otherwise well-formed, unauthenticated input.

## Finding Description
`gateway.ProcessRequest` is the entry point invoked for every inbound HTTP request by `httpServer.handleRequest`, which reads the raw body and passes it straight to `s.handler.ProcessRequest(r.Context(), rawMessage, jwtToken)` with no prior validation of the JSON-RPC payload shape. [3](#0-2)  `ProcessRequest` decodes the raw bytes via `jsonrpc2.DecodeRequest`, then unconditionally calls `g.codec.DecodeJSONRequest(jsonRequest)`, and only afterward branches into DON-ID/service-name handling. [4](#0-3)  `DecodeJSONRequest` dereferences `request.Params` without checking for `nil`, unlike sibling helpers in the same codebase, e.g. `ValidatedMessageFromReq`, `processUpdateSecretsRequest`/`processDeleteSecretsRequest` in the vault gateway processor, and `httpTriggerHandler.validatedTriggerRequest`, all of which explicitly guard `if req.Params == nil { ... }` before dereferencing. [5](#0-4) [6](#0-5) [7](#0-6)  This confirms the nil-check pattern is a recognized, established requirement in this codebase that was simply omitted from `DecodeJSONRequest`. The existing test suite's `"missing params"` case only exercises `DecodeRawRequest` and asserts an error is returned, but does not actually catch the panic since `jsonrpc2.DecodeRequest` (called first inside `DecodeRawRequest`) likely already errors on other malformed cases in that table — the "missing params" test would panic rather than return a normal error, meaning this exact regression is not covered by the existing test. [8](#0-7) 

Regarding the impact severity, Go's standard `net/http` server recovers panics per-connection inside its internal request-serving goroutine by default (this is standard library behavior, not custom code in this repo). This means a panic here would typically abort only the single offending connection/request (client receives a broken/reset connection, no valid response), rather than crashing the entire gateway process for all users. No custom panic-recovery middleware was found in `httpServer.handleRequest`. [9](#0-8) 

## Impact Explanation
This is a genuine, unauthenticated missing-input-validation bug that causes an unhandled panic instead of a controlled `UserMessageParseError` JSON-RPC response. The realistic impact is degraded/broken availability of the specific offending connection (dropped connection, no valid response returned to the caller) plus log noise from repeated panics, rather than the full gateway process crash suggested by the report's CVE comparison — Go's net/http server isolates and recovers panics per request/connection by default. This is a legitimate availability/robustness bug but does not clearly rise to a full-service denial-of-service impacting all DONs/nodes as framed in the original claim.

## Likelihood Explanation
High reachability: any unauthenticated client can send `{"jsonrpc":"2.0","id":"abc","method":"upload"}` (no `params`) directly to the gateway's public HTTP endpoint, with no valid DON ID, auth token, or handler-specific setup required, and the vulnerable code executes unconditionally before any DON/service routing logic.

## Recommendation
Add a nil-check on `request.Params` in `DecodeJSONRequest`, mirroring the existing pattern in `ValidatedMessageFromReq`, `GatewayVaultRequestProcessor`, and `httpTriggerHandler`:
```go
func (*JSONRPCCodec) DecodeJSONRequest(request jsonrpc2.Request[json.RawMessage]) (*Message, error) {
	if request.Params == nil {
		return nil, errors.New("missing params attribute")
	}
	var msg Message
	err := json.Unmarshal(*request.Params, &msg)
	...
```
Additionally, consider adding defensive panic-recovery middleware in `httpServer.handleRequest` to guarantee well-formed JSON-RPC error responses are always returned even for unforeseen edge cases.

## Proof of Concept
1. Start the gateway with a valid service/DON configuration exposing the public user HTTP endpoint.
2. Send: `POST /` with body `{"jsonrpc":"2.0","id":"abc","method":"upload"}` and no `Authorization` header.
3. Observe: `jsonrpc2.DecodeRequest` succeeds (params is optional), `jsonRequest.Params == nil`, and `g.codec.DecodeJSONRequest(jsonRequest)` panics at `json.Unmarshal(*request.Params, &msg)`.
4. Go unit test equivalent: call `api.JSONRPCCodec{}.DecodeJSONRequest(jsonrpc2.Request[json.RawMessage]{ID: "abc", Method: "upload", Params: nil})` directly and observe a panic instead of a returned `error`.

func (s *httpServer) handleRequest(w http.ResponseWriter, r *http.Request) {
	if s.config.CORSEnabled {
		origin := r.Header.Get("Origin")
		if s.isAllowedOrigin(origin) {
			w.Header().Set("Access-Control-Allow-Origin", origin)
			w.Header().Set("Access-Control-Allow-Methods", "GET, POST, OPTIONS")
			w.Header().Set("Access-Control-Allow-Headers", "Content-Type")
		}

		// handle preflight requests
		if r.Method == http.MethodOptions {
			w.WriteHeader(http.StatusNoContent)
			return
		}
	}

	maxRequestBytes, err := s.config.MaxRequestBytesLimiter.Limit(r.Context())
	if err != nil {
		msg := "Failed to get request size limit"
		s.lggr.Errorw(msg, "err", err)
		http.Error(w, msg, http.StatusInternalServerError)
		return
	}
	source := http.MaxBytesReader(nil, r.Body, int64(maxRequestBytes))
	rawMessage, err := io.ReadAll(source)
	if err != nil {
		s.lggr.Error("error reading request", err)
		w.WriteHeader(http.StatusBadRequest)
		return
	}

	// Optionally extract jwt token from authorization header
	authHeader := r.Header.Get("Authorization")
	jwtToken := ""
	if authHeader != "" {
		jwtToken = strings.TrimPrefix(authHeader, "Bearer ")
	}

	startTime := time.Now()
	rawResponse, httpStatusCode := s.handler.ProcessRequest(r.Context(), rawMessage, jwtToken)
	duration := time.Since(startTime)
	s.hMetrics.RecordRequestDuration(r.Context(), httpStatusCode, duration)
	s.hMetrics.RecordRequestCount(r.Context(), httpStatusCode)

	w.Header().Set("Content-Type", s.config.ContentTypeHeader)
	w.WriteHeader(httpStatusCode)
	_, err = w.Write(rawResponse) //nolint:gosec // G705: response body is written with an explicit Content-Type, not rendered as HTML
	if err != nil {
		s.lggr.Error("error when writing response", err)
	}
}
