### Title
Unmanipulation-resistant Uniswap V4 spot price used as execution-price oracle for cross-asset intent fills, with no size/impact term and manipulation-blind deviation guard - ([File: sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts])

### Summary
Simplex's FX solver strategy prices curveless cross-asset pairs directly off a Uniswap V4 pool's instantaneous `sqrtPriceX96` (spot mid-price), the same class of bug as the Mirror Protocol incident — a synthetic-asset/AMM price oracle that can be pushed away from the fair market price and then consumed by a downstream settlement path before it corrects. This is reachable purely by an unprivileged party who places (or engineers the timing of) an intent order on `IntentGatewayV2`; the solver evaluates and fills the order using the manipulated pool read.

### Finding Description
`UniswapV4FundingPlanner.getExoticTokenPrice` selects the position with the largest pool liquidity and calls `computeDirectPoolPriceUsd`, which returns `sdkPool.token0Price`/`token1Price` derived straight from the pool's current `sqrtPriceX96` read via `getSlot0`: [1](#0-0) [2](#0-1) 

This raw pool mid is consumed as the pricing rate for a whole curveless pair in `FXFiller.resolveLegRates`, which only compares it to a static `checkPriceGuard` deviation and otherwise trusts it verbatim to size the entire order — no TWAP, no size/impact adjustment, and the pool's own fee tier is never applied to the quoted rate: [3](#0-2) 

The project's own internal documentation confirms this is a known, accepted risk surface rather than a hardened path: [4](#0-3) 

The only mitigation is `checkPriceGuard`, which rejects a quote only if it drifts more than a static, operator-configured `maxDeviationBps` from a hardcoded `referencePrice` — and both fields are optional ("omit both to leave the chain unguarded"): [5](#0-4) 

This mirrors the Mirror Protocol bug class precisely: a price used to value/settle assets is sourced from a single, on-chain, thinly-checked feed (an AMM spot price instead of Chainlink/Band) that an attacker can move within a single transaction (flash loan / large directional swap against the chosen pool) immediately before submitting an intent order sized against that skewed rate, and the guard band (when configured) only bounds deviation from a static reference, not the manipulation itself or the execution cost of unwinding a large trade through that same shallow pool.

### Impact Explanation
Because `computeLegPolicyOutput` linearly extends the manipulated mid price across the entire priced quantity with no size-impact discount, and because the same pool the solver reads from is also the pool the solver later swaps through to source inventory (`swapAndDeposit`-style recycling and V4 LP withdrawal), an attacker who transiently skews the pool price can force the solver to (a) quote/fill an intent order at an off-market rate, directly transferring value from solver inventory to the attacker, and/or (b) drain solver liquidity through non-market executions. This is a direct funds-loss vector against solver-held inventory reachable from a fully unprivileged actor placing an order — squarely the "concrete theft" bar required.

### Likelihood Explanation
Likelihood is high wherever an operator configures a curveless, Uniswap-V4-funded pair without setting `referencePrice`/`maxDeviationBps` (explicitly permitted by design: "omit both to leave the chain unguarded"), or where the configured deviation band is wide enough to admit a profitable single-block manipulation relative to the pool's liquidity depth. Even with the guard configured, it only bounds against a static reference and does not account for trade size versus pool depth, so a sufficiently thin/liquidity-light pool remains exploitable within the allowed band. Placing an intent order is a fully permissionless, single-transaction action, and pool manipulation via flash swap requires no special privilege.

### Recommendation
Replace or supplement the raw `sqrtPriceX96` spot read with a manipulation-resistant price source for any pair used to size solver-committed fills: a time-weighted average price (TWAP) over multiple blocks, a Chainlink/oracle cross-check (as already used elsewhere in the codebase, e.g. `SimplexPaymaster._getOraclePrice`), and/or an execution-cost-aware quote (simulate the actual swap size against pool depth rather than assuming the mid price holds across the whole notional). Make `referencePrice`/`maxDeviationBps` mandatory (not optional) for any pair with no static curve, and size the deviation bound relative to trade size and pool liquidity rather than a single static percentage.

### Proof of Concept
1. Operator configures a curveless USDC/EXOTIC pair funded by a single Uniswap V4 position, per `docs/content/developers/evm/simplex/pricing.mdx`, without setting `referencePrice`/`maxDeviationBps` (an explicitly supported configuration).
2. Attacker executes a large one-sided swap against that V4 pool (flash-loan funded) to push `sqrtPriceX96` far from fair value.
3. Attacker immediately places an `IntentGatewayV2.placeOrder` intent sized to exploit the skewed rate.
4. `FXFiller.resolveLegRates` → `UniswapV4FundingPlanner.getExoticTokenPrice` → `computeDirectPoolPriceUsd` reads the still-skewed pool mid (no TWAP), `checkPriceGuard` passes because no reference/deviation bound is configured (or the drift is inside the configured band), and `computeLegPolicyOutput` extends that skewed mid linearly across the full order notional.
5. Solver fills the order at the off-market rate, transferring inventory to the attacker at a loss; attacker reverses the pool manipulation in the same or a later transaction, realizing profit at the solver's expense.

	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}

	private computeDirectPoolPriceUsd(
		pos: HydratedV4Position,
		sdkPool: V4Pool,
		chain: string,
	): { exoticToken: string; priceUsd: Decimal } | null {
		const usdc = this.configService.getUsdcAsset(chain).toLowerCase()
		const usdt = this.configService.getUsdtAsset(chain).toLowerCase()
		const c0 = pos.currency0.toLowerCase()
		const c1 = pos.currency1.toLowerCase()

		if (c0 === usdc || c0 === usdt) {
			// currency0 is stable → exotic is currency1
			// token1Price = "token0 per token1" = USD per exotic
			return {
				exoticToken: c1,
				priceUsd: new Decimal(sdkPool.token1Price.toFixed(18)),
			}
		}

		if (c1 === usdc || c1 === usdt) {
			// currency1 is stable → exotic is currency0
			// token0Price = "token1 per token0" = USD per exotic
			return {
				exoticToken: c0,
				priceUsd: new Decimal(sdkPool.token0Price.toFixed(18)),
			}
		}

		return null
	}

## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.

```toml lineNumbers
[vault.uniswapV4]
# referencePrice is the expected cNGN per USD;
# reject if the quote is more than 2% off.
# The two go together — one without the other is rejected.
[[vault.uniswapV4.positions]]
chain           = "EVM-8453"
tokenId         = "2087350"
referencePrice  = "1575"
maxDeviationBps = 200
```
