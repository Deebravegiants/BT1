### Title
Unguarded underflow in `assetReserve - virtualLtReserve` bricks graduation checks and the buy path - ([File: packages/contracts/src/Bonding.sol])

### Summary
`Bonding.canGraduate()` and `Bonding.previewLtUntilGraduation()` both compute the curve's real raised LT as a raw subtraction, `assetReserve - _launchTimeVirtualLtReserve(token_, pair)`, with no guard against the subtrahend exceeding the minuend. This is the same bug class as the Centrifuge NAV fix (#815): a derived "old value" (here, the recovered launch-time virtual LT reserve) is subtracted from a live stored value without clamping, on the unstated assumption that the stored value can never dip below it. [1](#0-0) [2](#0-1) 

### Finding Description
`_launchTimeVirtualLtReserve` recovers the launch-time virtual LT reserve `V` as `Pair.k() / Token.TOTAL_SUPPLY()`, an identity that holds exactly only when the pair's stored `tokenReserve` equals its launch-time value `S = TOTAL_SUPPLY`: [3](#0-2) 

`Pair.swap` does not enforce the constant-product invariant exactly; it accepts any post-swap state that satisfies a `+1`-slacked floor check: [4](#0-3) 

Because the check is `(newTokenReserve + 1) * (newAssetReserve + 1) >= k` rather than `newTokenReserve * newAssetReserve >= k`, the pool is allowed to settle at a state where the *unslacked* product `newTokenReserve * newAssetReserve` is strictly below `k`. When a trader drives `tokenReserve` back up to its maximum, `S` (by buying tokens off the curve and then selling all of them back — reachable because sold tokens can never exceed the curve's real balance and hence never exceed `S` on the buy-side, per the codebase's own `test_inv_virtualReserveAlwaysExceedsRealBalance` invariant), the resulting `assetReserve` can round down to a value below the true `V = k / S` by an integer amount permitted by the slack. At that point, `_launchTimeVirtualLtReserve` still returns exactly `V` (it's a pure `k/TOTAL_SUPPLY` division, unaffected by the live reserve rounding), while the live `assetReserve` is now `< V`.

Both `canGraduate` (line 692) and `previewLtUntilGraduation` (line 722) perform `assetReserve - V` unconditionally and will revert with a Solidity 0.8 arithmetic-underflow panic in that state. Notably, the codebase already recognizes and guards the *symmetric* condition on the supply leg — `previewLtUntilGraduation` explicitly checks `if (realBalance >= reserveToken) return ltUntilThreshold;` before doing `reserveToken - realBalance` — but applies no equivalent guard to the USD-leg subtraction just a few lines above it: [5](#0-4) 

Per the project's own documentation, `canGraduate()` is invoked inline at the end of every buy inside `Bonding._executeBuy`: [6](#0-5) 

so once the pair reaches this boundary state, every subsequent buy transaction on that curve reverts inside `canGraduate`, and `previewLtUntilGraduation` (used by the frontend/Zap to size buys) reverts as well. Sells do not recover the state — a sell only pushes `tokenReserve` further up and `assetReserve` further down relative to `V`, so once triggered the underflow does not self-heal via further trading on the curve.

### Impact Explanation
This denies further buys (and quote previews) on the affected bonding curve — an unprivileged trader can no longer acquire the token, and the curve can never reach graduation via the buy path (the very check that would flip it to `Graduating` is what reverts). This is a permanent freeze of the trading path for that token's curve, affecting all future traders and stalling the creator's token indefinitely, until/unless a privileged intervention (e.g., contract upgrade) is made. It does not directly steal funds, but it can permanently lock a token in a non-graduating, non-tradeable state — a liveness/availability failure of the bonding-curve product for that token.

### Likelihood Explanation
Reaching the boundary condition requires a trader (or sequence of traders) to buy the entire real, sellable balance of the pair and then sell it all back, driving stored `tokenReserve` to exactly its launch-time maximum `S`. This is reachable by any account with no special privileges — it only requires ordinary `Bonding.buy`/`Bonding.sell` calls (or the `Zap` equivalents) sized to fully round-trip the curve. The magnitude of the underflow enabled by the `+1` K-floor slack is small (bounded to a handful of wei given `S` is on the order of `1e27`), so it is a narrow, precisely-timed edge case rather than something that occurs from ordinary trading, but it is deterministically constructible by a motivated attacker who controls both the buy and the matching full sell-back in the same or adjacent transactions.

### Recommendation
Mirror the pattern the codebase already uses for the supply leg: clamp the USD-leg subtraction instead of doing it unconditionally, e.g.
```solidity
uint256 virtualLt = _launchTimeVirtualLtReserve(token_, pair);
uint256 realLtRaised = assetReserve > virtualLt ? assetReserve - virtualLt : 0;
```
in both `canGraduate` (Bonding.sol:692) and `previewLtUntilGraduation` (Bonding.sol:722), so a rounding-induced dip below the recovered virtual reserve degrades gracefully (treated as "nothing raised yet") instead of reverting the entire buy/preview path.

### Proof of Concept
1. Launch a token normally via `Bonding.launch`, giving pair state `tokenReserve = S = TOTAL_SUPPLY`, `assetReserve = V`, `k = S * V` [7](#0-6) .
2. Trader calls `Bonding.buy` (routed through `Router.buy` → `Pair.swap`) to purchase real tokens off the curve, reducing stored `tokenReserve` below `S` and increasing `assetReserve` above `V`.
3. The same trader calls `Bonding.sell` for the exact tokens just purchased, routed through `Router.sell` → `Pair.swap`, driving `tokenReserve` back up to `S` and `assetReserve` back down toward `V`. Because `Pair.swap`'s floor check only enforces `(tokenReserve+1)*(assetReserve+1) >= k` [8](#0-7) , the accepted `assetReserve` can land at `V - n` for a small `n > 0` instead of exactly `V`.
4. The next unprivileged trader's `Bonding.buy` call reaches `_executeBuy`'s inline `canGraduate(token)` check, which computes `assetReserve - _launchTimeVirtualLtReserve(...)` = `(V - n) - V`, underflowing and reverting the entire buy transaction with a panic [9](#0-8) .
5. All subsequent buys and `previewLtUntilGraduation` calls on this curve revert identically, permanently freezing the buy side of the bonding curve for that token.
