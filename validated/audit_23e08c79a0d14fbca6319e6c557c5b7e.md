I have two iterations left — let me confirm the mechanics of the whole-unit liquidation dead-band and permissionless `repay`.### Title
Permissionless `repay` pins an underwater account inside the whole-unit liquidation dead-band, indefinitely reverting `liquidate` - (File: contracts/controller/src/positions/liquidation/math.rs)

### Summary
`whole_unit_repayment` leaves a solvent account whose only supply leg is a sub-3-decimal token inside a debt interval where neither the full-close promotion nor the one-unit raise applies. In that interval every `liquidate` offer reverts with `InvalidPayments` because the unchanged curve quote backs less than one whole collateral unit and a plan with no seizure is rejected. The protocol documents that accrual or a price move ends this state — but `repay` is callable by any address on any account, so anyone (a griefer, or the borrower itself) can repay dust whenever interest pushes the debt out of the band, keeping the account unliquidatable for as long as they keep paying. [1](#0-0) [2](#0-1) 

### Finding Description
For a solvent account (`total_collateral >= total_debt`) whose single supply position has `asset_decimals < MIN_BORROWABLE_ASSET_DECIMALS` and holds at least one whole unit, `whole_unit_repayment` computes:

- `unit_at_bonus = floor(U / (1 + b))` and `full_close_ceiling = D + R`. If `unit_at_bonus >= D + R` the quote becomes `D` (rule 1, full close). [3](#0-2) 
- `unit_repayment = ceil((U + U/1e6) / (1 + b))`. If `unit_repayment >= D` the quote is returned unchanged (rule 2 not applicable); only when `unit_repayment < D` is the quote raised. [4](#0-3) 

The dead-band is therefore `unit_at_bonus - R < D <= unit_repayment`, reachable only when the curve quote itself backs less than one unit (`quote * (1+b) < U + margin`). Inside it, `normalize_repayment_plan` keeps `ideal_repayment_usd = quote_usd`, so any offer at or above the quote is trimmed back to a repayment that seizes zero whole units; a plan with no payable seizure reverts with `InvalidPayments` (16). [5](#0-4) [6](#0-5) 

`repay(caller, account_id, payments)` requires only `caller.require_auth()` and is explicitly permissionless — anyone may repay any account's debt. Interest accrual monotonically grows `D`; once `D` exceeds `unit_repayment` the band exits and liquidation succeeds. An attacker calls `repay` with a payment equal to the excess over the band interior, dropping `D` back into `unit_at_bonus - R < D <= unit_repayment`. Repeating this on each accrual boundary keeps `liquidate` reverting indefinitely at a per-interval cost of only the accrued interest over the band's width. The borrower can do this to their own account to dodge liquidation while still underwater; a third party can do it to a victim's account, since repayment of another account is allowed. [7](#0-6) [8](#0-7) 

### Impact Explanation
An account with `HF < 1` is made permanently unliquidatable while it remains solvent, for as long as the attacker funds the maintenance repays. Liquidation is the only permissionless mechanism that shrinks such an account before insolvency — `clean_bad_debt` additionally requires `total_collateral <= 5 WAD`, which an account holding a valuable whole-unit collateral (the band exists precisely when one unit is worth more than the debt) violates, so the debt cannot be socialized either. During the freeze, debt keeps accruing against a fixed whole-unit-collateral book, converting a recoverable underwater position into deeper insolvency and eventual supply-index write-down borne by suppliers. This is a temporary freezing of funds / availability loss of the liquidation path reachable by a single unprivileged address. [9](#0-8) [10](#0-9) 

### Likelihood Explanation
Requires a listed sub-3-decimal asset (admitted design: whole-unit seizure is intentional), an underwater account whose only supply is that asset, and a debt positioned near the band. The attacker path is a single `repay` call per accrual interval — permissionless, cheap (the band width is `unit_repayment - (unit_at_bonus - R)`, typically a fraction of one debt unit), and needs no flash loan, oracle manipulation, or privileged role. The freeze self-terminates only if the attacker stops paying or the debt-to-collateral ratio crosses into insolvency, at which point the insolvency branch bypasses the whole-unit logic — but by then the protocol's recovery is strictly worse than a timely liquidation. Medium likelihood: it needs a somewhat exotic position shape, but no coordination or capital beyond interest-rate-sized repays.

### Recommendation
Close the band in `whole_unit_repayment` rather than documenting around it: when `unit_at_bonus < D + R` and `unit_repayment >= D`, promote the quote to `D` (full close) instead of returning the unraised curve quote — a full close repays the whole debt and rounds the leg up to one unit, which is strictly better for the protocol than a permanent revert. Alternatively, add a permissionless fallback in `build_liquidation_plan` (e.g., when the normalized plan would seize nothing on a solvent whole-unit-leg account, accept any offer covering `unit_repayment` by pulling the difference) so the band cannot be held open by dust repays. At minimum, restrict or rate-limit third-party `repay` adjustments that re-enter the band, though the code-level fix (closing the band) is cleaner and removes the invariant exception documented in INV-LIQ-02. [11](#0-10) 

### Proof of Concept
1. List collateral `LOW3` (e.g., a 0-decimal or 2-decimal token priced so one unit `U` is worth hundreds of USD).
2. Borrower supplies `k` units of `LOW3` as the account's only supply position and borrows debt token `D` such that `HF < 1` and `D` lands in `floor(U/(1+b)) - R < D <= ceil((U + U/1e6)/(1+b))`. Per `whole_unit_repayment`, rule 1 fails (`unit_at_bonus < D + R`) and rule 2 fails (`unit_repayment >= D`), so `quote_usd` is returned unchanged and backs less than one unit.
3. Any `liquidate(liquidator, account_id, payments, SeizeMode::Transfer)` reverts with `InvalidPayments`: offers ≥ the quote are trimmed to a sub-one-unit seizure; smaller offers seize nothing. [12](#0-11) 
4. Interest accrual grows `D` past `unit_repayment`. Attacker calls `repay(attacker, account_id, [(debt_key, D - d_inband)])` — permissionless per the controller README — restoring the band. Repeat indefinitely.
5. Result: `liquidate` reverts on every offer and `clean_bad_debt` reverts with `CannotCleanBadDebt` because collateral `> $5`, while the account stays `HF < 1` and debt compounds.
