### Title
Self-custody face binding accepts a single best-scoring instantaneous frame, with no continuity/fraud enforcement across the capture session, enabling identity-mismatched (misattributed) signups - (File: `src/plans/biometric_capture/mod.rs`)

### Summary
The Velodrome `Gauge.sol` bug class is: a boolean/state "checkpoint" that is supposed to represent *sustained* compliance over an interval is instead overwritten by a single instantaneous value, letting an attacker satisfy the check for a moment right before/after the reward-relevant checkpoint while never actually maintaining the intended condition. The orb-core analog is in the biometric-capture identity binding: the frame used to bind the enrolled user's face ("self-custody candidate", later baked into the Personal Custody Package as the enrolled identity photo/key material) is not required to be consistent with the person whose iris is captured for the whole session — it is simply the single highest-scoring frame ever seen, and it is only strictly *required* during the last objective of the capture. Combined with the fact this FOSS build has no fraud/liveness cross-checks at all, this creates a gap analogous to the "vote right before claiming" bug: momentary compliance overwrites/decides the persisted checkpoint used for enrollment identity.

### Finding Description
In `src/plans/biometric_capture/mod.rs`, `handle_face_identifier` maintains `self.self_custody_candidate_rgb` as a single mutable "best so far" checkpoint: [1](#0-0) 

Every time a new RGB frame is deemed `is_valid` by the (stubbed) face identifier and scores higher than the previously stored frame, it **overwrites** the checkpoint — there is no requirement that this frame be consistent with the identity captured across the rest of the session (irises, other RGB frames). The only gating condition for finishing capture is: [2](#0-1) 

This shows the self-custody frame requirement is only strictly enforced once, at completion of the *last* objective — i.e., the checkpoint only needs to be true momentarily, at the very end, exactly like `cp0.voted` in the original report needed to be true only at the instant of `earned()`/checkpoint evaluation.

This frame is then propagated unchanged into the biometric pipeline and eventually into the Personal Custody Package identity material: [3](#0-2) [4](#0-3) 

Normally, one might expect a fraud/liveness engine to cross-validate that the face used for `face_left`, `face_right`, and `face_self_custody_candidate` (as well as the iris frames) belong to the same continuously-present person. However, in this codebase all fraud checks have been deleted: [5](#0-4) [6](#0-5) 

and the face identifier's own `is_valid`/`estimate` are also stub implementations that always accept: [7](#0-6) 

The combination means: (1) the identity-binding checkpoint is a single overwritable "best score" snapshot rather than a sustained continuity guarantee, and (2) nothing downstream verifies that the winning snapshot is consistent with the rest of the session. An unprivileged user undergoing signup could present a different face for most of the capture (e.g., to game duress/liveness cues, or swap identities mid-session with a colluding second party) and only need the "true" identity's face to appear for a fleeting, high-scoring frame near the end of the last objective to have it become the persisted self-custody identity checkpoint — mirroring the original report's "vote right before claim, reset right after" trick.

### Impact Explanation
If the self-custody candidate frame does not need to represent the same person throughout the whole biometric capture, the Orb can bind a signup's cryptographic identity/custody material to a face that is inconsistent with the actual iris owner captured during the session. This is a misattributed-signup / cross-signup identity-binding integrity issue: the enrolled "photo of record" used in the Personal Custody Package can be decoupled from the person whose iris biometric was actually scanned, undermining identity binding guarantees the system is meant to provide.

### Likelihood Explanation
The checkpoint-overwrite mechanic is unconditional and reachable by any unprivileged user going through the standard signup flow — no special privileges, hardware access, or operator collusion beyond normal user behavior during their own signup is required. Given fraud checks and face-identifier validation are fully stubbed (`N_FRAUD_CHECKS = 0`, `is_valid` always returns `true`), there is no compensating control preventing exploitation in this build.

### Recommendation
- Require the self-custody candidate frame's validity/consistency to be verified continuously (or via multiple samples across the whole capture window), rather than allowing a single late, high-scoring frame to overwrite the checkpoint.
- Add an explicit cross-check between `face_left`, `face_right`, `face_self_custody_candidate`, and the iris frames to ensure they represent the same person before finalizing capture (analogous to creating a new checkpoint on every relevant state change instead of overwriting the last one, as recommended in the original report).
- Re-introduce/restore fraud and liveness enforcement rather than leaving `detect_fraud` and `face_identifier::is_valid` as unconditional pass-through stubs, at least gating identity-binding-sensitive code paths.

### Proof of Concept
1. Start a signup; during earlier `Objective`s (non-last), present a face/iris belonging to user A while the code only requires matching IR sharpness/score thresholds (`handle_ir_net`, `handle_rgb_net`) with no identity continuity check. [8](#0-7) 
2. During the last `Objective`, briefly present user B's face; because `is_valid` is a stub that always returns `is_valid: Some(true)`, any single high-scoring frame will overwrite `self.self_custody_candidate_rgb` in `handle_face_identifier`. [7](#0-6) 
3. `poll_extra` only requires `self.self_custody_candidate_rgb.is_some()` at the final objective to complete capture, accepting the momentary swap as the finalized checkpoint used downstream in the Personal Custody Package. [2](#0-1)

    fn handle_ir_net(
        &mut self,
        orb: &mut Orb,
        output: port::Output<ir_net::Model>,
        frame: Option<camera::ir::Frame>,
    ) -> Result<BrokerFlow> {
        match output.value {
            ir_net::Output::Estimate(estimate) => {
                self.update_occlusion(orb, &estimate);
                if let Some(perceived_side) = estimate.perceived_side {
                    if perceived_side != i32::from(!self.target_left_eye) {
                        tracing::debug!("Skipping frame due to target and perceived side mismatch");
                        return Ok(BrokerFlow::Continue);
                    }
                } else {
                    tracing::debug!("IRNet perceived_side=None, skipping frame");
                    return Ok(BrokerFlow::Continue);
                }

                self.update_ux(orb, estimate.sharpness);

                let frame = frame.expect("frame must be set for an estimate output");
                let valid_capture = estimate.score >= IRIS_SCORE_MIN
                    && (!orb.ir_auto_exposure.is_enabled()
                        || IRIS_BRIGHTNESS_RANGE.contains(&frame.mean()))
                    && self.valid_capture_after <= Instant::now();

                if valid_capture {
                    let slot =
                        if self.target_left_eye { &mut self.left_ir } else { &mut self.right_ir };
                    if slot.is_none() {
                        dd_incr!(
                            "main.count.signup.during.biometric_capture.\
                             first_side_sharp_iris_detected",
                            &format!(
                                "side:{}",
                                if self.target_left_eye { "left" } else { "right" }
                            )
                        );
                    }
                    tracing::debug!("Found sharp iris: {}", estimate.score);
                    *slot = Some(FrameInfoIr::new(estimate, frame));
                }
            }
            ir_net::Output::Version(_) => {}
            ir_net::Output::Error => {
                tracing::error!("IR-Net failed during biometric capture phase");
            }
            ir_net::Output::Warmup => unreachable!("IR-Net::Warmup not part biometric capture"),
        }
        Ok(BrokerFlow::Continue)
    }

    fn handle_rgb_net(
        &mut self,
        _orb: &mut Orb,
        output: port::Output<rgb_net::Model>,
        frame: Option<camera::rgb::Frame>,
    ) -> Result<BrokerFlow> {
        if let rgb_net::Output::Estimate(estimate) = output.value {
            if let Some(prediction) = estimate.primary() {
                if prediction.bbox.coordinates.is_correct() {
                    let frame = frame.expect("frame must be set for an estimate output");
                    let slot =
                        if self.target_left_eye { &mut self.left_rgb } else { &mut self.right_rgb };
                    *slot = Some(FrameInfoRgb::new(estimate, frame));
                }
            }
        }
        Ok(BrokerFlow::Continue)
    }
