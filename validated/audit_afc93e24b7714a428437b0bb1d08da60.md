### Title
Stale (never-invalidated) `_requestCommitments` entry lets an already-delivered Post/Get request be timed out with an old destination-state proof, causing double fee payout and forged `onTimeout` delivery after `onAccept`/`onGetResponse` already ran - (File: `evm/src/core/EvmHost.sol`)

### Summary
`EvmHost.dispatchIncoming` (for both `PostRequest` and `GetResponse`) never clears `_requestCommitments[commitment]` on the *success* path after a message is delivered to the destination app. `HandlerV2.handlePostRequestTimeouts` / `handleGetRequestTimeouts` accept a non-membership proof against *any* previously-committed height of the counterparty chain, not necessarily the latest one. Because Hyperbridge retains old `_stateCommitments` entries indefinitely (they are only removed on an explicit veto, see `deleteStateMachineCommitmentInternal`, `evm/src/core/EvmHost.sol:704-732`), a relayer can first deliver the request/response normally, then submit a timeout proof rooted at an *earlier* committed height of the counterparty chain — from before the receipt existed — and pass the non-membership check even though the message was actually delivered.

### Finding Description
- `dispatchIncoming(PostRequest, relayer)` sets `_requestReceipts[commitment]` and calls `IApp.onAccept`; on success it never touches `_requestCommitments`, only deleting the receipt on failure: [1](#0-0) 
- `dispatchIncoming(GetResponse, relayer)` similarly sets `_responseReceipts[commitment]`, calls `onGetResponse`, and on success pays the relayer fee straight from `_requestCommitments[commitment].fee` without ever deleting that commitment: [2](#0-1) 
- `dispatchTimeOut` (both overloads) is the only place that clears `_requestCommitments`, but it is reachable independently, from `HandlerV2.handlePostRequestTimeouts` / `handleGetRequestTimeouts`, and unconditionally refunds `meta.fee` to `meta.sender` once the module's `onPostRequestTimeout`/`onGetTimeout` call succeeds: [3](#0-2) 
- The timeout handlers verify only a non-membership proof of the receipt at the caller-supplied `message.height`, with no check that this height is the *latest* known height or postdates the actual delivery: [4](#0-3) [5](#0-4) 
- Old state commitments are retained in storage indefinitely (kept for challenge-period bookkeeping), so a stale, pre-delivery height remains provable long after a later height already contains the receipt: [6](#0-5) 

Combining these: a relayer (or colluding pair of relayers/apps) can (1) deliver the Post request / Get response through the normal path, collecting the relayer fee where applicable and letting the destination app run `onAccept`/`onGetResponse`, then (2) submit a `PostRequestTimeoutMessage`/`GetTimeoutMessage` whose `message.height` corresponds to an earlier, still-stored state commitment of the counterparty chain from before the receipt existed. The non-membership proof against that stale height passes, `host.requestCommitments(...)` still returns non-zero `meta` (never cleared), and `dispatchTimeOut` proceeds to invoke `onPostRequestTimeout`/`onGetTimeout` on the app and pay out `meta.fee` again to `meta.sender`.

### Impact Explanation
This is directly analogous to the CVE's root cause: an object (`_requestCommitments[commitment]`) that should have been invalidated ("freed") once consumed by the success path is instead left live, and a second, unrelated code path (timeout dispatch) later dereferences/acts on that stale reference as if it were still pending. The consequences on Hyperbridge are concrete fund loss and protocol-state corruption:
- Double payment of the protocol fee (once as relayer reward on delivery, once as sender refund on the bogus timeout) — direct theft of escrowed fee-token funds from `EvmHost`.
- Forged/duplicate message delivery: an app that already executed `onAccept`/`onGetResponse` (e.g., minted tokens, released escrow, filled an intent) subsequently receives an inconsistent `onPostRequestTimeout`/`onGetTimeout` call, which many apps (e.g., `ExtrinsicIntents`) treat as "delivery never happened" and may refund/re-credit — enabling unbacked mint or double-spend of bridged value at the application layer.

### Likelihood Explanation
Any unprivileged relayer that already legitimately delivered a request/response can trigger this by simply also submitting a timeout message for the same commitment, choosing an older (still-stored, still-provable) `message.height` from before the receipt was written on the counterparty chain. No governance, admin, or consensus compromise is required — only a normal relayed proof plus control over which historical height is cited, both of which are attacker-controlled inputs to `HandlerV2`.

### Recommendation
- Clear `_requestCommitments[commitment]` on the success path of `dispatchIncoming` (for both `PostRequest` and `GetResponse`) once the message has been durably delivered, the same way `dispatchTimeOut` clears it — so a later timeout for the same commitment fails the `meta.sender == address(0)` check.
- Additionally/alternatively, require that the state height cited in `handlePostRequestTimeouts`/`handleGetRequestTimeouts` be at or after the `latestStateMachineHeight` (or otherwise monotonic per state machine), rejecting non-membership proofs rooted in superseded, stale heights.

### Proof of Concept
1. Relayer R submits a valid `PostRequestMessage` (or `GetResponseMessage`) via `HandlerV2.handlePostRequests`; `EvmHost.dispatchIncoming` runs `onAccept` successfully and sets the receipt, leaving `_requestCommitments[commitment]` untouched (`evm/src/core/EvmHost.sol:805-818`).
2. R waits for the request's timeout timestamp to pass on the source-chain clock, then crafts a `PostRequestTimeoutMessage` whose `message.height` points to a state commitment of the destination chain from *before* step 1's receipt was written (this old commitment is still stored per `evm/src/core/EvmHost.sol:701-732`).
3. R calls `HandlerV2.handlePostRequestTimeouts`; the non-membership proof against the stale height succeeds (`evm/src/core/HandlerV2.sol:277-284`), `host.requestCommitments(...)` still returns the original `meta` (never deleted), and `EvmHost.dispatchTimeOut` runs `onPostRequestTimeout` on the destination-turned-source app and refunds `meta.fee` to `meta.sender` (`evm/src/core/EvmHost.sol:885-900`), even though the request was already delivered and processed in step 1.

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function handlePostRequestTimeouts(IHost host, PostRequestTimeoutMessage calldata message)
        external
        notFrozen(host)
    {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            PostRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            // known request? also serves as source check
            bytes32 requestCommitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(requestCommitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(REQUEST_RECEIPTS_STORAGE_PREFIX, requestCommitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(PostRequestTimeout(request, _msgSender()), meta, requestCommitment);
        }
    }
