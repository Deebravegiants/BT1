### Title
Pool `repay` overpayment refund pays declared-excess out of real custody without verifying an inbound transfer — ([File: contracts/pool/src/ops/repay.rs](contracts/pool/src/ops/repay.rs))

### Summary
The 1inch exploit class — a crafted numeric input in a code path that turns a declared value into a real payout — maps onto the pool's repay leg. `ops::repay::accounting` computes `overpayment = amount - current_debt` purely from the *declared* `action.amount` and then `apply` transfers that overpayment to `payer` via `transfer_out`, which never debits accounting cash and never calls `require_reserves`. When the market has no debt (or the declared amount exceeds debt), the entire declared amount is refunded out of the pool's real token custody, paying an attacker funds that belong to suppliers — an unprivileged drain reachable via the `repay` entrypoint with an attacker-chosen `PoolAction`.

### Finding Description
In `contracts/pool/src/ops/repay.rs`, `accounting` resolves the repay against the position's debt: [1](#0-0) 

`resolve_repay` takes the full-close branch when `current_debt_ceil` is zero or `amount` exceeds the debt, so `overpayment` becomes `amount - debt`. `apply` then pays it: [2](#0-1) 

`transfer_out` validates only nonnegativity — it skips `require_reserves` and does not debit `cash`: [3](#0-2) 

The in-repo regression test documents the drain concretely: with zero debt and nothing transferred in, `repay` refunds the entire declared amount out of custody, and the comment notes the same gap exists in `ops::recapitalize`: [4](#0-3) 

Analog to 1inch: the attacker controls a numeric field (`action.amount`, analogous to the forged `interactionLength`), the code subtracts a trusted quantity (`current_debt`) from it without checking that the corresponding value ever arrived, and the difference is paid out of pooled user funds. Only `net_repay` is credited to cash; the refund is pure payout.

### Impact Explanation
Theft of user funds: an attacker submits `repay` with a `PoolAction` amount up to the market's real token balance against a market with no debt (or any debt < declared amount), receiving `amount - debt` tokens transferred from the pool's custody to `payer`. Custody leaves while the cash book is untouched, draining supplier funds and/or rendering the pool unable to honor withdrawals. Per the test, a debt-free market makes the whole declared amount payable, bounded only by real custody.

### Likelihood Explanation
Likelihood depends on authorization at the pool boundary: the test calls `client().repay(&payer, &action)` directly, which suggests the leg either lacks a controller-only check or the harness mocks auth — this is the aspect I could not fully verify within the indexed context (pool `lib.rs` entrypoint auth checks were not shown). If `repay` is controller-gated, reachability reduces to whether any unprivileged controller endpoint can drive a pool repay where `overpayment` exceeds what was actually transferred in — `repay_debt_from_controller` prefunds and measures, but plain user `repay` pulls the caller's tokens first, so the controller-mediated paths appear funded. The primary exposure is the unguarded direct `repay` leg paying declared-excess from custody.

### Recommendation
Verify inbound funding before refunding: either require controller auth on `repay`/`recapitalize` and assert the pool's measured balance delta covers `amount`, or debit `cash` (subject to `require_reserves`) in `transfer_out` for refunds, so an unfunded declared amount cannot convert bookkeeping dust into a real payout. Mirror the fix in `ops::recapitalize::apply`, which the test documents as sharing the same refund gap.

### Proof of Concept
As pinned by `test_unfunded_repay_overpayment_refund_also_pays_out_of_custody` (`contracts/pool/tests/flows.rs:3589-3611`):

1. Market has custody `C` and `borrowed = 0`.
2. Attacker calls `repay(payer = attacker, PoolAction{ hub_asset, amount = C, ... })`.
3. `resolve_repay` returns `overpayment = C`, `net_repay = 0`; the `RepayRoundsToZeroShares` assert passes on its `net_repay == 0` branch.
4. `transfer_out(attacker, C)` moves the entire custody balance to the attacker; `cash` is unchanged.

Uncertainty note: whether this leg is reachable without controller auth could not be confirmed from the indexed snippets; if auth-gated, the residual analog is any controller path that lets a caller inflate `amount` beyond measured funds received.

```rust
pub(crate) fn accounting(env: &Env, action: &PoolAction) -> RepayOutcome {
    let (mut cache, position) = ops::load_leg(env, action);
    let amount = action.amount;

    let (burned, overpayment) = cache.resolve_repay(amount, position);
    let net_repay = amount
        .checked_sub(overpayment)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));
    assert_with_error!(
        env,
        net_repay == 0 || burned.raw() > 0,
        GenericError::RepayRoundsToZeroShares
    );

    let position = position.checked_sub(env, burned);
    cache.burn_debt(burned);

    cache.credit_cash(net_repay);
```

```rust
#[test]
fn test_unfunded_repay_overpayment_refund_also_pays_out_of_custody() {
    let t = TestSetup::new();
    let token = token::Client::new(&t.env, &t.asset);
    let payer = Address::generate(&t.env);

    let custody_before = token.balance(&t.pool);
    let before = t.state_snapshot();
    assert_eq!(
        before.cash, custody_before,
        "fixture guard: book and custody must start in sync"
    );
    assert_eq!(before.borrowed, 0, "fixture must carry no debt");

    // Nothing transferred in, no debt to retire: the whole amount is "excess".
    let credited = t
        .client()
        .repay(&payer, &t.ract(0, custody_before))
        .get_unchecked(0)
        .actual_amount;
    assert_eq!(credited, 0, "no debt was retired, so nothing is credited");
    assert_unfunded_refund_drained_custody(&t, &payer, custody_before, &before);
}
```
