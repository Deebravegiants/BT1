### Title
Mega Agent Python process agents lack a deterministic-crash exit strategy, enabling a repeatable panic/crash loop from attacker-supplied biometric image data - ([File: src/agents/python/mod.rs])

### Summary
Kakarot's `execute_starknet_call` bug class is "an unprivileged caller can supply input that makes a downstream component panic, and the panic is not gracefully isolated, so it breaks the surrounding system instead of returning a recoverable error." The same structural pattern exists in `orb-core`'s agent-IPC trust boundary: the Python ML agents (`MegaAgentOne`/`MegaAgentTwo`), which process the RGB/IR biometric images of the unprivileged person being scanned, run as `agentwire` process-based agents but do not override `exit_strategy()`. This means a deterministic crash triggered by a single crafted image is retried against the freshly-restarted process forever, because the default `ExitStrategy` is `Retry`, which explicitly replays "the latest input."

### Finding Description
`agentwire::agent::Process::exit_strategy` decides what happens when an agent's OS process dies (panic, segfault, uncaught exception, etc.): [1](#0-0) 

The broker loop that manages the child process explicitly re-feeds the same recovered input on `ExitStrategy::Retry` (the `#[default]`): [2](#0-1) 

`MegaAgentOne` (and analogously `MegaAgentTwo`) implements `agentwire::agent::Process` without overriding `exit_strategy`, so it inherits `ExitStrategy::Retry` by default: [3](#0-2) 

These agents run the biometric image pipeline (IR-Net, Iris, Occlusion, RGB-Net, Face Identifier), feeding frames derived directly from the unprivileged person undergoing signup into a Python subprocess loop that exits the whole process on any error: [4](#0-3) 

By contrast, the `qr_code::Agent`, whose decoding path also can panic on malformed/attacker-influenced frame data (`RgbImage::from_vec(...).expect(...)`), explicitly overrides `exit_strategy` to `Restart` (which clears `recovered_inputs` instead of retrying them), precisely because "crashes are deterministic for this agent" and retrying a poisoned input would create an infinite crash loop: [5](#0-4) [6](#0-5) 

This comment demonstrates the developers are aware that the `Retry`-on-crash default is unsafe for any agent whose crash can be made deterministic by attacker-controlled input, yet the mega-agent Python processes - which handle the actual biometric ML inference over user-supplied iris/face imagery - do not carry the same safeguard.

### Impact Explanation
If a person presenting themselves for signup (an unprivileged party with only physical access to the camera, no software privilege) can produce an eye/face image (via unusual anatomy, an adversarial image displayed on a screen, spoofing artifact, or other edge case) that deterministically crashes the Python model process (segfault in native TensorRT/CUDA code, or unhandled exception at a Rust `unwrap()`/`extract()` boundary such as in `ir_net::extract`), the process dies, and the default `ExitStrategy::Retry` causes `spawn_process_impl` to restart the process and immediately resubmit the exact same crashing frame. Because the crash is deterministic, this repeats indefinitely, permanently breaking the biometric pipeline (IR-Net/Iris/Occlusion/RGB-Net/Face-Identifier) for that Orb until an operator manually intervenes (equivalent to bricking every subsequent signup attempt), mirroring the "any transaction containing a call to a reverting contract... bricks the flow" impact described in the source finding, translated to availability of the signup/identity pipeline rather than an RPC revert.

### Likelihood Explanation
The pipeline receives raw camera imagery of an untrusted, unprivileged party during every normal signup, so the input surface is directly reachable without any special access. Deterministic crashes from unusual/malformed image content are a realistic class of bug in native ML inference code, and the codebase's own defensive comment in `qr_code.rs` acknowledges this exact failure mode is plausible for camera/QR-derived agents - yet the same protection was not applied to the mega-agent Python processes that handle biometric data.

### Recommendation
Override `exit_strategy` for `MegaAgentOne`/`MegaAgentTwo` (and any other process agent consuming untrusted/unprivileged-user-derived data) to avoid retrying the same input after a crash - e.g., use `ExitStrategy::Restart` (clear `recovered_inputs`) or `ExitStrategy::Close` combined with defensive validation/`catch_unwind` around per-frame inference, so a single crafted image cannot create a persistent denial-of-service loop against the biometric pipeline.

### Proof of Concept
Conceptual reproduction path:
1. Present to the camera an image which the IR-Net/Iris/Occlusion Python model or its Rust extraction code (`extract()` in `src/agents/python/ir_net.rs`) cannot handle without crashing (e.g., a value that trips a native library assertion/segfault, or a missing dict key causing `estimation.get_item(...)?` to propagate an error that isn't distinguishable from a fatal case, or a genuine Rust panic elsewhere in the pipeline).
2. `run_python_process` in `src/agents/python/mod.rs` line 166 propagates the error via `break Err(err)`, terminating the process with a non-zero/abnormal exit status.
3. `spawn_process_impl` in `agentwire/src/agent/process.rs` observes the exit, calls `MegaAgentOne::exit_strategy` (unoverridden default `Retry`), and re-injects the same recovered frame into the newly spawned process.
4. The new process crashes again on the same input, looping indefinitely and blocking all subsequent signups relying on that mega agent.

pub enum ExitStrategy {
    /// Close the port without restarting the agent.
    Close,
    /// Keep the port open and restart the agent.
    Restart,
    /// Keep the port open, restart the agent, and retry the latest input.
    #[default]
    Retry,
}
