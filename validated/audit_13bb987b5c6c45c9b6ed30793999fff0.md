Audit Report

## Title
`dissolve` permanently burns any balance transferred directly into the crowdloan pot rather than returning it - (File: polkadot/runtime/common/src/crowdloan/mod.rs)

## Summary
`Pallet::dissolve` checks only the in-storage `fund.raised.is_zero()` bookkeeping value, not the pot account's actual free balance, before calling `CurrencyOf::<T>::make_free_balance_be(&pot, Zero::zero())`. Since the pot is a normal, unfiltered `AccountId` derived from `PalletId` + fund index, anyone can transfer arbitrary funds into it, and those funds are unconditionally burned (not returned to anyone) the next time `dissolve` is called.

## Finding Description
`dissolve` computes `can_dissolve = permitted && fund.raised.is_zero()` [3](#0-2)  and then unconditionally burns the pot's entire free balance via `make_free_balance_be(&pot, Zero::zero())` [4](#0-3) . `fund.raised` is maintained independently, decremented only in `withdraw` and `refund` when contributions are paid out [5](#0-4) [6](#0-5) , and is never reconciled against the pot's actual live balance inside `dissolve`. By contrast, `withdraw` and `refund` both call `Self::ensure_crowdloan_ended(now, &fund_account, &fund)` before touching the pot [7](#0-6) [8](#0-7) , which does check the pot's real balance versus `fund.raised`; `dissolve` has no such check. Because the pot account is a plain transferable account, any unprivileged user can send balance to it via a standard `transfer_allow_death`/`transfer_keep_alive` call, and this deposit will not update `fund.raised`. The only gating on `dissolve` is `ensure_signed` plus `who == fund.depositor || now >= fund.end`, both trivially satisfiable in normal end-of-crowdloan conditions.

## Impact Explanation
Any funds sent to the pot account outside the normal contribution flow are permanently and irreversibly destroyed when `dissolve` executes, with no compensation to the sender, the depositor, or any contributor. This is a genuine unrestricted-burn bug: the destroyed amount is not tied to any accounting invariant, and there is no recovery mechanism for stray balance in the pot. The impact is concrete (a `make_free_balance_be` call to zero on pallet-balances effects real issuance destruction) though the class of loss is narrow — it is triggered by a transfer into a semi-obscure derived account, and the loss falls either on whoever sent to the pot mistakenly, or is deliberately inflicted by an attacker donating/burning their own funds or third-party stray balance with no recovery path.

## Likelihood Explanation
The precondition (`fund.raised == 0` at dissolve time, i.e., an unsuccessful/fully-refunded crowdloan) is a normal state reached at the end of many crowdloans. No special timing, governance, or privileged path is required — an unprivileged account can transfer to the pot at any time before `dissolve` is called, and `dissolve` itself is callable by the depositor (always) or anyone after `fund.end`. This makes the bug reliably reproducible via ordinary extrinsics.

## Recommendation
In `dissolve`, before burning, verify the pot's actual free/total balance is zero (or equal to any residual expected amount), and either reject dissolution if nonzero balance remains, or sweep any leftover balance back to the depositor/treasury instead of silently destroying it via `make_free_balance_be`. Consider reusing `ensure_crowdloan_ended`-style balance reconciliation logic in `dissolve` to detect and safely handle any balance/`fund.raised` mismatch, emitting an event rather than silently burning value.

## Proof of Concept
1. Create a crowdloan fund via `Crowdloan::create`; let it reach a state where `fund.raised == 0` (no contributions, or after full `refund`).
2. From an unrelated signed account `attacker`, call `Balances::transfer_allow_death(attacker, pot_account, DUST)` where `pot_account = Crowdloan::fund_account_id(fund.fund_index)`.
3. Record `Balances::total_issuance()` before dissolve.
4. Call `Crowdloan::dissolve(depositor_or_any_signed_after_end, index)`.
5. Assert: `Balances::free_balance(&pot_account) == 0`; `total_issuance` decreased by exactly `DUST`; `attacker`'s balance is not refunded — confirming the transferred dust was permanently burned rather than returned.

		pub fn dissolve(origin: OriginFor<T>, #[pallet::compact] index: ParaId) -> DispatchResult {
			let who = ensure_signed(origin)?;

			let fund = Funds::<T>::get(index).ok_or(Error::<T>::InvalidParaId)?;
			let pot = Self::fund_account_id(fund.fund_index);
			let now = frame_system::Pallet::<T>::block_number();

			// Only allow dissolution when the raised funds goes to zero,
			// and the caller is the fund creator or we are past the end date.
			let permitted = who == fund.depositor || now >= fund.end;
			let can_dissolve = permitted && fund.raised.is_zero();
			ensure!(can_dissolve, Error::<T>::NotReadyToDissolve);

			// Assuming state is not corrupted, the child trie should already be cleaned up
			// and all funds in the crowdloan account have been returned. If not, governance
			// can take care of that.
			debug_assert!(Self::contribution_iterator(fund.fund_index).count().is_zero());

			// Crowdloan over, burn all funds.
			let _imba = CurrencyOf::<T>::make_free_balance_be(&pot, Zero::zero());
			let _ = frame_system::Pallet::<T>::dec_providers(&pot).defensive();

			CurrencyOf::<T>::unreserve(&fund.depositor, fund.deposit);
			Funds::<T>::remove(index);
			Self::deposit_event(Event::<T>::Dissolved { para_id: index });
			Ok(())
		}
