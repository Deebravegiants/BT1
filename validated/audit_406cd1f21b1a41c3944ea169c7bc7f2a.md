### Title
Fraud/duplicate-signup detection is unconditionally disabled (`N_FRAUD_CHECKS=0`), allowing every capture — including fraudulent ones — to be treated as `SignupReason::Normal` - ([File: src/plans/fraud_check.rs])

### Summary
The Fraud Check Engine has been stripped down so that `N_FRAUD_CHECKS` is hard-coded to `0`, making `Report::fraud_checks()`, `fraud_checks_strict()`, and ultimately `Report::fraud_detected()` / `fraud_detected_with_config()` always operate over empty arrays. As a result `fraud_detected()` always returns `false` and `FraudChecks::run()` always produces an empty, fraud-free `Report {}` regardless of what the `biometric_pipeline::Pipeline` actually observed. Any downstream caller that gates `SignupReason` or capture acceptance on these fraud results will unconditionally treat the signup as non-fraudulent.

### Finding Description
`FraudChecks::new` takes a `&biometric_pipeline::Pipeline` but stores it only as `PhantomData` — the pipeline data is never inspected: [1](#0-0) . `Report::fraud_checks()` and `enabled_checks_from_config()` both return `[]` because the const array size `N_FRAUD_CHECKS` is `0` [2](#0-1) [3](#0-2) . Consequently `fraud_detected()` iterates over an empty slice and its `.any(...)` trivially returns `false` [4](#0-3) , and `fraud_detected_with_config` similarly returns `(false, [])` for any input [5](#0-4) . No signal produced by the biometric pipeline (duplicate iris code, spoofed capture, liveness anomaly, etc.) can ever propagate into a non-`false` fraud verdict, because the check surface has been deleted entirely (the comment explicitly states: "FOSS: This is set to 0 because we manually deleted all fraud checks"). Any code path (e.g. signup finalization logic that decides `SignupReason::Normal` vs a fraud-based reason) that relies on this `Report`/`FraudChecks` output is fail-open by construction, not fail-closed.

### Impact Explanation
Because fraud/duplicate detection is architecturally a no-op in this build, an attacker performing their own signup session with a manipulated or duplicate capture (contact lenses, screen replay, duplicate iris presented in different session, etc.) cannot be flagged by this component — it will always report "no fraud" and the associated feedback/report metadata will always be empty. This directly weakens the liveness/fraud-detection control that is supposed to prevent duplicate/fraudulent identities from being signed and packaged as genuine signups, corresponding to a "liveness/fraud bypass" impact category.

### Likelihood Explanation
This is unconditional and requires no special attacker capability — it is the default behavior for every signup processed by this build, since `N_FRAUD_CHECKS` is a compile-time constant of `0`. Any unprivileged attacker who can present a manipulated capture to the cameras during their own signup session automatically benefits from this fail-open behavior; no bypass technique is even necessary.

### Recommendation
Restore actual fraud-check implementations (do not ship `N_FRAUD_CHECKS = 0`) or, if this is intentionally a reduced/FOSS build, ensure that any signup-authorization / `SignupReason` decision that depends on `Report::fraud_detected()` does not treat "no configured checks" as equivalent to "verified non-fraudulent," and instead fails closed (blocks signup / escalates) when no fraud-detection checks are active.

### Proof of Concept
Unit test in `src/plans/fraud_check.rs`:
```rust
#[test]
fn fraud_detected_always_false_even_for_obviously_fraudulent_pipeline() {
    // Construct a Pipeline that would represent an obviously fraudulent/duplicate capture
    // (e.g., known-duplicate iris code, replay artifacts, etc.)
    let pipeline = build_fraudulent_pipeline_fixture();
    let mut checks = FraudChecks::new(&pipeline);
    let report = checks.run();
    assert!(!report.fraud_detected(), "expected fraud_detected() to reflect pipeline signal, but it is always false");
    let config = BackendConfig::default();
    let (detected, feedback) = report.fraud_detected_with_config(&config);
    assert!(!detected && feedback.is_empty(), "fraud_detected_with_config never reports fraud regardless of input");
}
```
This demonstrates that regardless of the content of `pipeline`, `Report`/`FraudChecks` cannot produce a fraud signal, confirming the fail-open design at this call site.

    #[must_use]
    pub fn fraud_detected_with_config(
        &self,
        config: &BackendConfig,
    ) -> (bool, Vec<PipelineFailureFeedbackMessage>) {
        let enabled_checks = Self::enabled_checks_from_config(config);
        let fraud_results = self.fraud_checks_strict();
        let feedback_msgs = Self::feedback_messages();

        let feedback: Vec<PipelineFailureFeedbackMessage> = enabled_checks
            .iter()
            .zip(fraud_results.iter())
            .zip(feedback_msgs.iter())
            .filter_map(
                |((&enabled, &result), feedback_msg)| {
                    if enabled && result { feedback_msg.clone() } else { None }
                },
            )
            .collect();

        (!feedback.is_empty(), feedback)
    }
