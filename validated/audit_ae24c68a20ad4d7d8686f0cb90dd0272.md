Confirmed: `create_signer` is a `public(friend)` native restricted to a fixed allowlist of framework modules [1](#0-0) . A normal user who owns an object but does not hold its `ExtendRef`/`ConstructorRef` has no way to ever produce a `signer` for that object's own address.

### Title
Object self-ownership via unchecked `to` address in `object::transfer_raw`/`transfer_with_ref` permanently locks object-held assets - (File: `aptos-move/framework/aptos-framework/sources/object.move`)

### Summary
`object::transfer_raw_inner` and `object::transfer_with_ref` write the caller-supplied destination address into `ObjectCore.owner` without checking that the destination differs from the object's own address. This is the same unbounded/unchecked "path" class of bug as the reported issue: the ownership "path" (chain from asset to its ultimate controlling account) is never validated for a degenerate case, allowing a `path` of length zero (self-reference) to be written into the record without control.

### Finding Description
Ownership transfer in the Object model is implemented as: [2](#0-1) 

`transfer_raw` only verifies that the calling signer is an ungated ancestor of `object` via `verify_ungated_and_descendant(owner_address, object)` [3](#0-2) . It never checks `to != object`. `transfer_raw_inner` then unconditionally sets `object_core.owner = to` [4](#0-3) .

The same missing check exists in the capability-based path, `transfer_with_ref`, which only validates that `self.owner == object.owner` at ref-generation time, not that `to != self.self`: [5](#0-4) 

If a caller (the legitimate current owner, or any downstream contract that forwards a user-controlled `to` argument into `object::transfer`/`transfer_call`/`transfer_with_ref`) supplies `to == object_address`, `ObjectCore.owner` becomes the object's own address. From that point on:
- `is_owner<T>(object, owner)` can never be satisfied by any real account signer, because the only way to get a `signer` matching that address is the framework-internal, allowlisted `create_signer` native [1](#0-0) , which ordinary object owners do not possess unless they separately retained the object's `ExtendRef`.
- `owns`/`root_owner`, which walk the ownership chain, also lose their termination guarantee: `owns` is bounded by `MAXIMUM_OBJECT_NESTING` and will simply revert with `EMAXIMUM_NESTING` [6](#0-5) , while `root_owner` has **no bound at all** and will loop indefinitely on a self-owned object because `is_object(obj_owner)` stays true forever [7](#0-6) . Note the spec/doc comments explicitly call out depth-8 bounding for `verify_ungated_and_descendant` and `owns` [8](#0-7)  but `root_owner` was never given the same treatment.
- `transfer`, `transfer_raw`, `burn` (which requires `is_owner`) can never again succeed for this object because no future caller can satisfy the owner-signer requirement [9](#0-8) .

### Impact Explanation
Any fungible-asset primary/secondary store, token, or arbitrary resource held inside a named/derived object can be permanently and irrecoverably locked by simply transferring the object to its own address, either directly by the owner or via any intermediary contract that forwards attacker-influenced `to` parameters to `object::transfer`/`transfer_call`/`transfer_with_ref` (e.g., marketplace, escrow, or vault flows that resolve `to` dynamically). This satisfies the "Permanent lock or non-recoverable loss of object-held … value" custody-impact category, and additionally the `root_owner` unbounded loop provides an unrecoverable-availability vector for any protocol logic that calls `root_owner` on such an object.

### Likelihood Explanation
The action requires no special privilege beyond normal object-transfer authority (owner, or `LinearTransferRef` holder), and the destination address is a plain `address` argument with no validation anywhere in the transfer call chain. Any composed protocol that lets a user (even indirectly) choose or influence the recipient of an object transfer is exposed. Likelihood is high for any code built on top of `object::transfer*`/`transfer_with_ref` that doesn't itself add a `to != object_address` check, since the framework provides no such guard centrally.

### Recommendation
Add an explicit check `assert!(to != object, error::invalid_argument(ECANNOT_TRANSFER_TO_SELF));` in `transfer_raw_inner` (used by `transfer_raw`/`transfer`/`transfer_call`) and the equivalent check `assert!(to != self.self, ...)` in `transfer_with_ref`. Also bound `root_owner`'s traversal by `MAXIMUM_OBJECT_NESTING` (as already done for `owns` and `verify_ungated_and_descendant`) to eliminate the unbounded-loop path independent of the self-transfer fix.

```move
// Move funds/NFT into the object as normal custody flow ...

// Self-transfer: no check prevents to == obj_addr
object::transfer_call(&owner, obj_addr, obj_addr);

// From here on:
// - object::is_owner(obj, owner_addr) == false forever
// - object::burn(&owner, obj) aborts with ENOT_OBJECT_OWNER forever
// - object::transfer(&owner, obj, anyone) aborts with ENOT_OBJECT_OWNER forever
//   (verify_ungated_and_descendant requires owner==current_address up the chain,
//    but current_address is now obj_addr itself, unreachable by any signer)
// - object::root_owner(obj) loops indefinitely (is_object(obj_addr) is always true)
```

```text
    fun verify_ungated_and_descendant(owner: address, destination: address) {
        let current_address = destination;
        assert!(
            exists<ObjectCore>(current_address),
            error::not_found(EOBJECT_DOES_NOT_EXIST),
        );

        let object = borrow_global<ObjectCore>(current_address);
        assert!(
            object.allow_ungated_transfer,
            error::permission_denied(ENO_UNGATED_TRANSFERS),
        );

        let current_address = object.owner;
        let count = 0;
        while (owner != current_address) {
            count += 1;
            assert!(count < MAXIMUM_OBJECT_NESTING, error::out_of_range(EMAXIMUM_NESTING));
            // At this point, the first object exists and so the more likely case is that the
            // object's owner is not an object. So we return a more sensible error.
            assert!(
                exists<ObjectCore>(current_address),
                error::permission_denied(ENOT_OBJECT_OWNER),
            );
            let object = borrow_global<ObjectCore>(current_address);
            assert!(
                object.allow_ungated_transfer,
                error::permission_denied(ENO_UNGATED_TRANSFERS),
            );
            current_address = object.owner;
        };
    }
```

```text
    public fun owns<T: key>(object: Object<T>, owner: address): bool {
        let current_address = object.object_address();

        assert!(
            exists<ObjectCore>(current_address),
            error::not_found(EOBJECT_DOES_NOT_EXIST),
        );

        if (current_address == owner) {
            return true
        };

        let object = borrow_global<ObjectCore>(current_address);
        let current_address = object.owner;

        let count = 0;
        while (owner != current_address) {
            count += 1;
            assert!(count < MAXIMUM_OBJECT_NESTING, error::out_of_range(EMAXIMUM_NESTING));
            if (!exists<ObjectCore>(current_address)) {
                return false
            };

            let object = borrow_global<ObjectCore>(current_address);
            current_address = object.owner;
        };
        true
    }
```
