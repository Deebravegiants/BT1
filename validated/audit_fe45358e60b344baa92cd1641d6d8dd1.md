The core issue is a missing increment of a nonce, which allows for replayability of a state-changing operation.

In the `powHSM` codebase, the `signer_authorization` module in `firmware/src/ledger/ui/src/signer_authorization.c` handles the authorization of RSK signer binaries. This module manages the installation, verification, and execution authorization of signers, and it uses a state machine to track the process. The `do_authorize_signer` function processes various operation codes, including `OP_SIGAUT_SIGN` . When `OP_SIGAUT_SIGN` is called, it verifies signatures from multiple authorizers and, if a threshold is met, writes the new authorized signer version and iteration to non-volatile memory (NVM) .

The `signer_authorization` module does not appear to implement a nonce or similar mechanism to prevent replay attacks for the `OP_SIGAUT_SIGN` operation. If an attacker intercepts a valid `OP_SIGAUT_SIGN` command and its associated signatures, they could potentially replay this command to re-authorize an older or specific signer version, even if a newer version has been installed. This is analogous to the `CloudRecoveryModule` issue where the lack of nonce increment allows replaying recovery processes.

### Title
Replay Attack on Signer Authorization - ()

### Summary
The `signer_authorization` module in `powHSM` does not increment a nonce or similar counter after successfully authorizing a new signer version. This omission allows an attacker to replay a previously valid `OP_SIGAUT_SIGN` command, potentially forcing the device to revert to an older, authorized signer version.

### Finding Description
The `do_authorize_signer` function, specifically when handling the `OP_SIGAUT_SIGN` operation, updates the `N_current_signer_status` in NVM with a new signer hash and iteration after verifying a sufficient number of signatures . However, there is no mechanism, such as a nonce or a monotonically increasing counter, that is incremented or checked to prevent the re-submission of the same valid authorization command. This means that if an attacker captures a valid `OP_SIGAUT_SIGN` APDU and its corresponding signatures, they can resend it at a later time.

### Impact Explanation
An attacker could replay a captured `OP_SIGAUT_SIGN` command to force the `powHSM` device to load an older, potentially vulnerable, or undesired signer binary. This could lead to a downgrade attack, where the security improvements of newer signer versions are bypassed. If the private key for the original authorization is lost, or if a new signer is authorized to revoke a compromised one, replaying an old authorization could re-enable the compromised signer, leading to unauthorized signing or other malicious activities.

### Likelihood Explanation
The likelihood is moderate. An attacker would need to intercept a valid `OP_SIGAUT_SIGN` command and its associated signatures. Given that these commands are part of the device's update mechanism, they are not frequently executed, but their compromise could have significant consequences. The lack of a nonce makes the replay straightforward once the necessary data is obtained.

### Recommendation
Implement a nonce or a monotonically increasing counter for signer authorization commands. This counter should be part of the message signed by the authorizers and stored in NVM alongside the `N_current_signer_status`. Each time a signer authorization is successfully processed, this nonce should be incremented. Any incoming `OP_SIGAUT_SIGN` command should include a nonce that is strictly greater than the last recorded nonce for that signer.

### Proof of Concept
1. An authorized party sends an `OP_SIGAUT_SIGN` command to authorize `SignerA` with `iteration_X`. The command includes the hash of `SignerA` and `iteration_X`, along with valid signatures from the required number of authorizers. 
2. The `powHSM` device verifies the signatures and updates `N_current_signer_status` to `SignerA` and `iteration_X`. 
3. Later, a new `SignerB` with `iteration_Y` is authorized through the same process, updating `N_current_signer_status`.
4. An attacker, who previously intercepted the `OP_SIGAUT_SIGN` command for `SignerA` and `iteration_X`, replays this exact command to the `powHSM` device.
5. Since there is no nonce check, the device re-verifies the valid signatures for `SignerA` and `iteration_X` and overwrites `N_current_signer_status` with the older `SignerA` and `iteration_X`, effectively downgrading the authorized signer.
