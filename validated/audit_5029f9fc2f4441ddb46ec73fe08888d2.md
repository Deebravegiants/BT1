# Title
Stale-Proof Race in `dispatchTimeOut(GetRequestTimeout)` Enables Double Payment of Relayer Fee — (`evm/src/core/EvmHost.sol`)

### Summary
The EVM `EvmHost` fee-settlement paths for `GetRequest`s are guarded by a non-membership proof checked against a historical, previously-committed state root, but the actual state-mutating function (`dispatchTimeOut` for `GetRequestTimeout`) never re-checks the host's own live receipt state before paying out. This mirrors the CVE-2023-0128 bug class (acting on a resource whose lifecycle state changed since it was last validated) — here, using stale validation data to authorize consumption of a fee escrow that may already have been consumed by a concurrent, valid response delivery.

### Finding Description
`EvmHost.dispatchIncoming(GetResponse, relayer)` pays the relayer fee out of `_requestCommitments[commitment].fee` on a successful `onGetResponse` delivery, but crucially never deletes `_requestCommitments[commitment]`: [1](#0-0) 

Separately, `EvmHost.dispatchTimeOut(GetRequestTimeout, meta, commitment)` unconditionally deletes `_requestCommitments[commitment]` and refunds the same fee back to the original sender, with no check of the host's own `_responseReceipts[commitment]` before doing so: [2](#0-1) 

The only gate preventing a duplicate timeout is `HandlerV2.handleGetRequestTimeouts`, which verifies a non-membership proof of the `ResponseReceipts` trie key against a **historical** `state.stateRoot` fetched via `host.stateMachineCommitment(message.height)`: [3](#0-2) 

Because this proof is checked against a state root committed at `message.height` (a snapshot taken before the transaction executes) rather than the host's live storage, it can be satisfied even if a `GetResponse` was legitimately delivered *after* that snapshot but *before* the timeout call executes. Once `dispatchTimeOut` runs, it performs no live re-check of `_responseReceipts[commitment]`, so it will refund the fee a second time to `meta.sender` even though the relayer was already paid via `dispatchIncoming(GetResponse, ...)`.

This is precisely the class of bug the Rust `pallet-ismp` handlers were hardened against — note the explicit "re-check right before dispatch" comments added to close exactly this kind of race (a prior request/response in the same batch, or a re-entrant call, changing receipt state between the up-front proof-verification pass and the actual dispatch): [4](#0-3) [5](#0-4) 

The EVM `EvmHost`/`HandlerV2` implementation lacks the equivalent live-state guard for the `GetRequestTimeout` path.

### Impact Explanation
An unprivileged relayer can construct a valid `GetResponseMessage` (paying itself the fee) and a valid `GetTimeoutMessage` for the same `GetRequest`, using a stale state-root snapshot that predates the response delivery, to trigger `dispatchTimeOut` and drain the fee token a second time from `EvmHost`. This is a direct theft-of-funds / unbacked double payment out of protocol-held escrow, reachable from a single relayed proof submission — matching the "relayer fee and reward accounting" and "forged message delivery" impact categories in scope.

### Likelihood Explanation
Exploitation only requires: (1) submitting a normal `handleGetResponses` call and (2) submitting a `handleGetRequestTimeouts` call using a state-root snapshot taken prior to the response's delivery but still satisfying the "not yet timed out"/challenge-period checks. Both are ordinary relayer-accessible entry points (`HandlerV2.handleGetResponses`, `HandlerV2.handleGetRequestTimeouts`), requiring no privileged role — only careful timing/ordering of two otherwise-legitimate proofs.

### Recommendation
In `EvmHost.dispatchTimeOut(GetRequestTimeout, ...)`, re-check `_responseReceipts[commitment]` is unset (live storage, not a historical proof) immediately before deleting the commitment and issuing the refund, mirroring the "re-check right before dispatch" pattern already used in `modules/ismp/core/src/handlers/timeout.rs` and `response.rs`. Reject the timeout if a response receipt already exists.

### Proof of Concept
1. Relayer submits `HandlerV2.handleGetResponses(host, msg)` for `GetRequest` R at time T2, delivering the response and collecting `_requestCommitments[R].fee` via `dispatchIncoming(GetResponse, relayer)` (`EvmHost.sol:824-847`).
2. Relayer separately obtains (or had pre-obtained) a non-membership proof of `ResponseReceipts[R]` against a state root committed at height T1 < T2 (before the response existed).
3. Relayer submits `HandlerV2.handleGetRequestTimeouts(host, msg)` with that stale proof; `entry.value.length == 0` check passes because at T1 no receipt existed (`HandlerV2.sol:308-319`).
4. `EvmHost.dispatchTimeOut(GetRequestTimeout, meta, R)` executes unconditionally, refunding `meta.fee` a second time to `meta.sender` (`EvmHost.sol:856-877`), resulting in the fee being paid out twice from the same escrowed commitment.

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
