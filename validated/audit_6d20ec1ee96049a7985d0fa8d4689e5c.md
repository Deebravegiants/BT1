Audit Report

## Title
Login Endpoint Leaks Distinct Auth-Failure Errors, Enabling Username Enumeration - (File: core/web/sessions_controller.go)

## Summary
`SessionsController.Create` forwards the raw error from `AuthenticationProvider().CreateSession` directly to `jsonAPIError`, which serializes `err.Error()` verbatim into the HTTP response body. Because the underlying auth implementations (`localauth`, `ldapauth`, `oidcauth`) return distinguishable error strings depending on whether the failure was due to an unknown email versus an incorrect password, an unauthenticated caller to `POST /sessions` can enumerate valid user emails on the node.

## Finding Description
`SessionsController.Create` calls `sc.App.AuthenticationProvider().CreateSession(ctx, sr)` and on failure passes the raw error straight to `jsonAPIError(c, http.StatusUnauthorized, err)`: [1](#0-0) . `jsonAPIError` then serializes `err.Error()` directly into the JSON response without normalization: [2](#0-1) .

In `localauth`'s `CreateSession`, `FindUser` looks up the user by email; if no matching row exists, the raw error (e.g. a `sql.ErrNoRows`-derived message) is returned immediately: [3](#0-2) . If the email is found but the password check fails, the distinct string `"Invalid password"` is returned: [4](#0-3) . The `"Invalid email"` branch that immediately follows the lookup is effectively unreachable in normal operation, since `findUser` already filters rows by (case-insensitive) email match, so `constantTimeEmailCompare` will not fail after a successful lookup: [5](#0-4) . The same structure is repeated in `ldapauth.localLoginFallback` and `oidcauth.localLoginFallback`: [6](#0-5) [7](#0-6) .

The net effect is that the response text differs measurably between "email not found" (raw DB/lookup error) and "email found, wrong password" (`"Invalid password"`), regardless of whether the literal string is exactly `"Invalid email"` as claimed. No middleware in the `/sessions` path normalizes or genericizes these messages before they reach the client.

## Impact Explanation
This allows an unauthenticated attacker to distinguish whether a submitted email corresponds to an existing node user account by observing the differing error text returned from `POST /sessions`. This is a username-enumeration information disclosure that facilitates targeted credential-stuffing/brute-force attacks against valid accounts, but it does not by itself bypass authentication or grant access — it is a lower-severity, auth-adjacent information disclosure rather than a direct authentication/role bypass.

## Likelihood Explanation
The `/sessions` endpoint is reachable pre-authentication by any client that can reach the node's API, and exploitation only requires submitting email/password pairs and observing the response body — no special privileges or preconditions are needed, making this trivially reproducible.

## Recommendation
Return a single generic error (e.g., "invalid credentials") from `SessionsController.Create` for all `CreateSession` failure paths, and avoid propagating internal error strings (including raw DB "no rows" errors) from `AuthenticationProvider().CreateSession` verbatim to the HTTP client. Remove or guard the effectively-dead `"Invalid email"` branches so failure paths are consistent, and consider constant-time/uniform response behavior across "no such user" and "wrong password" cases.

## Proof of Concept
1. `POST /sessions` with `{"email":"nonexistent@example.com","password":"anything"}` → response body contains the raw lookup error text (e.g., derived from `sql.ErrNoRows`), per `core/sessions/localauth/orm.go:145-148`.
2. `POST /sessions` with `{"email":"<a known valid email>","password":"wrongpassword"}` → response body contains `"Invalid password"`, per `core/sessions/localauth/orm.go:159-162`.
3. Comparing the two distinct response bodies lets an unauthenticated caller determine whether a given email is a registered account.

func jsonAPIError(c *gin.Context, statusCode int, err error) {
	_ = c.Error(err).SetType(gin.ErrorTypePublic)
	var jsonErr *models.JSONAPIErrors
	if errors.As(err, &jsonErr) {
		c.JSON(statusCode, jsonErr)
		return
	}
	c.JSON(statusCode, models.NewJSONAPIErrorsWith(err.Error()))
}

func (l *ldapAuthenticator) localLoginFallback(ctx context.Context, sr sessions.SessionRequest) (sessions.User, error) {
	var user sessions.User
	sql := "SELECT * FROM users WHERE lower(email) = lower($1)"
	err := l.ds.GetContext(ctx, &user, sql, sr.Email)
	if err != nil {
		return user, err
	}
	if !constantTimeEmailCompare(strings.ToLower(sr.Email), strings.ToLower(user.Email)) {
		l.auditLogger.Audit(audit.AuthLoginFailedEmail, map[string]any{"email": sr.Email})
		return user, errors.New("invalid email")
	}

		l.auditLogger.Audit(audit.AuthLoginFailedPassword, map[string]any{"email": sr.Email})
		return user, errors.New("invalid password")
	}
