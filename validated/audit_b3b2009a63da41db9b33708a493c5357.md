### Title
Attacker-controlled `amount_out` causes division-by-zero panic in `swap_token_amount_base_out` before the insufficient-funds guard is checked - (File: `program/src/math.rs`, `program/src/processor.rs`)

### Summary
`process_swap_base_out` and `process_swap_base_out_v2` compute the required input amount by calling `Calculator::swap_token_amount_base_out` using the attacker-supplied `swap.amount_out` *before* validating that `amount_out` is less than the pool's available reserve. When `amount_out` equals the pool's total reserve for the requested side exactly, the internal subtraction used as a division denominator becomes zero, causing a panic (division by zero) that aborts the transaction.

### Finding Description
`Calculator::swap_token_amount_base_out` in [5](#0-4)  computes:
```
let denominator = total_pc_without_take_pnl.checked_sub(amount_out).unwrap(); // Coin2PC
amount_in = total_coin_without_take_pnl.checked_mul(amount_out).unwrap().checked_ceil_div(denominator).unwrap();
```
(and the symmetric PC2Coin branch using `total_coin_without_take_pnl`). `checked_ceil_div` (for `U128`) is implemented as [6](#0-5)  which itself calls `self.checked_div(rhs)?`; when `rhs == 0` this returns `None`, and the caller's trailing `.unwrap()` on that `None` triggers a Rust panic.

In both `process_swap_base_out` ( [1](#0-0) ) and `process_swap_base_out_v2` ( [2](#0-1) ), this division happens immediately after computing `total_pc_without_take_pnl`/`total_coin_without_take_pnl` from the live vault balances, and *before* the check that would reject `amount_out >= total_pc_without_take_pnl` (Coin2PC) or `>= total_coin_without_take_pnl` (PC2Coin), which only occurs later at [3](#0-2)  / [4](#0-3) . Since `swap.amount_out` is fully attacker-controlled instruction data (from `SwapInstructionBaseOut`), a swapper can set it exactly equal to the current pool reserve of the output token to force `denominator == 0`, triggering the unhandled `None.unwrap()` panic deep inside the math routine, rather than the intended graceful `InsufficientFunds` error.

### Impact Explanation
This is a reachable panic condition in a core, unprivileged swap instruction, matching the CVE-2016-10266 bug class (a crafted/attacker-chosen input driving an unguarded denominator to zero and crashing the program instead of returning a graceful error). While a single reverted transaction is not itself catastrophic (Solana runtime aborts and rolls back state on panic, so no funds are stolen directly), it demonstrates that swap-input validation is ordered incorrectly relative to the math, meaning the program can be driven to panic paths instead of returning a controlled `AmmError`. This is a real defect in the swap accounting/validation flow of a fund-custody program and represents a denial-of-service / reliability defect at the on-chain math layer that should be fixed by validating amounts before performing unchecked division.

### Likelihood Explanation
High reachability: any unprivileged user can submit a `SwapBaseOut`/`SwapBaseOutV2` instruction with a self-chosen `amount_out` value equal to the current pool reserve, which is readable from the vault account state at transaction-build time (or can simply be targeted at low-liquidity pools where guessing/near-draining is straightforward). No special privileges, signer keys, or non-default builds are required.

### Recommendation
Move the `amount_out >= total_pc_without_take_pnl` / `amount_out >= total_coin_without_take_pnl` checks to occur *before* calling `Calculator::swap_token_amount_base_out`, and additionally make `swap_token_amount_base_out` / `checked_ceil_div` return a proper `Result`/`Option` and propagate a defined `AmmError` (e.g., `AmmError::InsufficientFunds` or a new `CalculationExRateFailure`) instead of relying on `.unwrap()` panics when the denominator is zero.

### Proof of Concept
1. Attacker queries the current `amm_pc_vault`/`amm_coin_vault` balances to learn `total_pc_without_take_pnl` (for Coin2PC direction).
2. Attacker submits a `SwapBaseOut` (or `SwapBaseOutV2`) instruction with `swap.amount_out` set exactly equal to `total_pc_without_take_pnl`.
3. Inside `process_swap_base_out`, `Calculator::swap_token_amount_base_out` computes `denominator = total_pc_without_take_pnl.checked_sub(amount_out).unwrap() == 0`.
4. `checked_ceil_div(0)` returns `None` (via `checked_div` returning `None` for zero divisor), and the subsequent `.unwrap()` in `program/src/math.rs` line 346 panics, aborting the transaction with a runtime panic instead of the intended `AmmError::InsufficientFunds`.

    pub fn swap_token_amount_base_out(
        amount_out: U128,
        total_pc_without_take_pnl: U128,
        total_coin_without_take_pnl: U128,
        swap_direction: SwapDirection,
    ) -> U128 {
        let amount_in;
        match swap_direction {
            SwapDirection::Coin2PC => {
                // (x + delta_x) * (y + delta_y) = x * y
                // (coin + amount_in) * (pc - amount_out) = coin * pc
                // => amount_in = coin * pc / (pc - amount_out) - coin
                // => amount_in = (coin * pc - pc * coin + amount_out * coin) / (pc - amount_out)
                // => amount_in = (amount_out * coin) / (pc - amount_out)
                let denominator = total_pc_without_take_pnl.checked_sub(amount_out).unwrap();
                amount_in = total_coin_without_take_pnl
                    .checked_mul(amount_out)
                    .unwrap()
                    .checked_ceil_div(denominator)
                    .unwrap()
            }
            SwapDirection::PC2Coin => {
                // (x + delta_x) * (y + delta_y) = x * y
                // (pc + amount_in) * (coin - amount_out) = coin * pc
                // => amount_out = coin - coin * pc / (pc + amount_in)
                // => amount_out = (coin * pc + coin * amount_in - coin * pc) / (pc + amount_in)
                // => amount_out = coin * amount_in / (pc + amount_in)

                // => amount_in = coin * pc / (coin - amount_out) - pc
                // => amount_in = (coin * pc - pc * coin + pc * amount_out) / (coin - amount_out)
                // => amount_in = (pc * amount_out) / (coin - amount_out)
                let denominator = total_coin_without_take_pnl.checked_sub(amount_out).unwrap();
                amount_in = total_pc_without_take_pnl
                    .checked_mul(amount_out)
                    .unwrap()
                    .checked_ceil_div(denominator)
                    .unwrap()
            }
        }
        return amount_in;
    }

impl CheckedCeilDiv for U128 {
    fn checked_ceil_div(&self, rhs: Self) -> Option<Self> {
        let mut quotient = self.checked_div(rhs)?;
        let remainder = self.checked_rem(rhs)?;
        if remainder != U128::zero() {
            quotient = quotient.checked_add(U128::one())?;
        }
        Some(quotient)
    }
