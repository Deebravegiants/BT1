### Title
Missing Arbitrum L2 sequencer-uptime check in `SimplexPaymaster` Chainlink oracle reads allows mispriced gas prefunds and swaps during sequencer downtime - ([File: evm/src/utils/SimplexPaymaster.sol])

### Summary
`SimplexPaymaster._getOraclePrice()` fetches Chainlink `latestRoundData()` and only validates a positive answer and a staleness bound (`block.timestamp - updatedAt <= maxOracleAge`, up to 7 days per `MAX_ORACLE_AGE`). It never checks the Arbitrum L2 sequencer-uptime feed, even though the paymaster is deployed on Arbitrum. This is the same bug class as Sherlock M-4 (missing Chainlink `sequencerUptimeFeed` check on Arbitrum's `GLPOracle`).

### Finding Description
`_getOraclePrice` at [1](#0-0)  reads `oracle.latestRoundData()` and reverts only on `answer <= 0` or `block.timestamp - updatedAt > maxOracleAge`. There is no call to an `AggregatorV3Interface` sequencer-uptime feed (e.g. `0xFdB631F5EE196F0ed6FAa767959853A9F217697D` on Arbitrum) nor any grace-period check as recommended by Chainlink's L2 sequencer-feed example.

This price is consumed in two unprivileged, attacker-reachable paths:
- `_tokenPrice()` → used by `_fetchDetails()` and `_prefund()` on every sponsored `UserOperation` submitted by any solver/user through the permissionless paymaster (mode `0x00` permit and mode `0x02` Permit2), see [2](#0-1)  and [3](#0-2) .
- `swapAndDeposit()`, which derives `amountOutMin` from the same oracle pair to bound a Uniswap V2 swap of the paymaster's accrued stablecoins into native gas, see [4](#0-3) .

`maxOracleAge` can be governance-configured up to `MAX_ORACLE_AGE = 7 days` [5](#0-4) , and documented deployments include Arbitrum: "live on Ethereum, Arbitrum, Base, Polygon and BSC" [6](#0-5) , and `SimplexPaymasterStakeLockForkTest.t.sol` explicitly forks a live Arbitrum-style deployment context alongside Ethereum/BSC [7](#0-6) . During an Arbitrum sequencer outage, the L1-anchored Chainlink feed's `updatedAt` can stop advancing while `block.timestamp` (as observed once the sequencer resumes, or via any L1↔L2 timestamp skew during the outage) still satisfies the staleness bound, letting a stale native/USD or token/USD ratio be treated as fresh.

### Impact Explanation
A mispriced `nativeUsd`/`tokenUsd` ratio directly changes `tokenPrice` and therefore `prefundAmount` pulled from a solver's wallet (via `transferFrom` or `Permit2.permitTransferFrom`) for every sponsored UserOperation, and the `amountOutMin` floor in `swapAndDeposit`. An attacker who can predict or race the stale-vs-true price divergence during/after a sequencer outage can either underpay for sponsored gas (draining the paymaster's stablecoin/native reserves funded by other users and the protocol treasury) or force `swapAndDeposit` to execute at a worse rate, directly costing protocol funds. This is a concrete loss of funds for the paymaster/treasury, matching Medium severity.

### Likelihood Explanation
Exploitation requires an Arbitrum sequencer downtime event, which is an infrequent but real, externally-triggered condition (not attacker-controlled), consistent with the original Sherlock finding's Medium rating. Once it occurs, exploitation only requires calling `_fetchDetails`/`_prefund` (submitting a normal sponsored UserOp) — no privileged role is needed.

### Recommendation
Add an Arbitrum sequencer-uptime `AggregatorV3Interface` (e.g. Chainlink's `0xFdB631F5EE196F0ed6FAa767959853A9F217697D`) check inside `_getOraclePrice()`, following Chainlink's documented pattern: revert if `answer == 1` (sequencer down) and enforce a grace period (e.g. 1 hour) after `startedAt` before trusting price feeds again, in addition to the existing staleness and positivity checks.

### Proof of Concept
1. Arbitrum sequencer goes offline; the `nativeOracle`/token `AggregatorV3Interface` feeds stop receiving new rounds, freezing `answer`/`updatedAt` at pre-outage values.
2. While `block.timestamp - updatedAt` remains `<= maxOracleAge` (up to 7 days, or the operator-configured value), any user submits a sponsored UserOperation through `SimplexPaymaster` (mode `0x00` or `0x02`).
3. `_fetchDetails` → `_tokenPrice` → `_getOraclePrice` returns the frozen price without any sequencer-liveness check, computing `prefundAmount` from a price that no longer reflects the true market rate at resumption.
4. `_prefund` executes the transfer/Permit2 pull at the mispriced `tokenPrice`, letting the solver pay less than the current fair cost (or, symmetrically, letting `swapAndDeposit` execute a swap at a stale `amountOutMin` favorable to an outside actor), draining paymaster reserves over repeated operations.

    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
