### Title
Permanent market freeze via `i128` ray-value overflow in accrual (`scaled_to_original` panics before the borrow-index cap engages) - (File: common/src/rates/scaling.rs)

### Summary
The MySQL CVE is an integer-overflow pre-auth DoS. The analog in XOXNO Lending is an `i128` overflow in the RAY-domain valuation inside `accrue_step`: once `borrowed * borrow_index` no longer fits in `i128`, `scaled_to_original` panics with `MathOverflow` on every subsequent accrual. Since every mutating entrypoint on a market accrues first, the entire (hub, token) book freezes permanently — no repay, withdraw, liquidate, or flash loan can ever execute again on that market, and all suppliers' funds are locked forever. The borrow-index ceiling (`MAX_BORROW_INDEX_RAY = 10^36`) does not protect against this because for a whale-scale market the value ceiling (`i128::MAX` ≈ 1.7e38) is hit at an index of only ~170x, long before the 10^9x index cap.

### Finding Description
`accrue_step` — the single accrual implementation used by the mutating `interest::global_sync` path and by `simulate_update_indexes` — calls `scaled_to_original` twice per step to value `borrowed` and `supplied` in RAY terms ( [1](#0-0) ). `scaled_to_original` is `scaled.mul(index)` ( [2](#0-1) ), which goes through `mul_div_half_up`: the `I256` intermediate is exact, but the final `.to_i128()` returns `None` once the quotient exceeds `i128::MAX`, surfacing as `GenericError::MathOverflow` ( [3](#0-2) ). `calculate_supplier_rewards` additionally computes `borrowed * new_borrow_index` per step, hitting the same wall.

The docs themselves define the cliff: the RAY value of a position must fit `i128`, and "value overflow can occur before the index ceiling and block repayment/withdrawal because those operations accrue first" ( [4](#0-3) ). The dedicated test proves it end-to-end: a 1-billion-whole-token 18-decimals market at ~98% utilization on the steep XLM curve panics inside `scaled_to_original` after a few years of accrual, after which `withdraw` and `repay` revert with `MATH_OVERFLOW` forever, with `borrow_index < MAX_BORROW_INDEX_RAY` ( [5](#0-4) ).

Attack path for a single unprivileged address: `controller.supply` a very large amount of a high-decimals listed asset (caps admit up to ~170 billion whole tokens per market, and an attacker holding or controlling a listed 18-decimal token can do this at low real cost), take the book to near-max utilization via `controller.borrow` against collateral in another spoke, then call the permissionless `update_indexes` (or simply let time pass) until `borrowed * borrow_index` crosses `i128::MAX`. From that block onward every verb on the market — including `liquidate` and `clean_bad_debt` — reverts in `global_sync`.

### Impact Explanation
Permanent freezing of funds: all suppliers' tokens in the affected market are unrecoverable, borrowers cannot repay or be liquidated, and the pool's physical token balance for that market is stranded. Unlike a fail-closed pause, nothing can ever unfreeze the book because the panic happens inside the mandatory accrual preamble shared by every entrypoint.

### Likelihood Explanation
Medium-low. It requires a whale-scale position (on the order of 10^9 whole tokens) at sustained high utilization on a steep rate curve, and the overflow only materializes after the index grows ~170x — years of compounding, or less on aggressively configured markets. No privilege is needed: `update_indexes` is permissionless and the attacker controls both the supply side and (via collateral elsewhere) the utilization. The cost is the attacker's own locked capital, but griefing is asymmetrical when other suppliers' funds are trapped alongside it.

### Recommendation
Bound the accrual so it cannot revert: saturate the market valuation used for utilization/reward computation (as `mul_div_floor_saturating` already does for `update_supply_index` and `protocol_fee_shares`, and `calculate_scaled_cap` does for caps), or clamp `borrowed`/`supplied` RAY inputs to `i128::MAX / index` before valuation, or stop accruing once a market's ray value nears the ceiling and emit an alarm so positions can still exit against the last valid index. At minimum, decouple position exits (withdraw/repay/liquidate) from the panicking market-total valuation so individual positions remain operable.

### Proof of Concept
The committed test is the PoC — `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs::a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap`:

```rust
// Supply 1e9 whole tokens of an 18-decimals asset; borrow ~98% of it.
t.supply_raw(BOB, "BIG18", BILLION * 10i128.pow(18));
t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
t.borrow_raw(ALICE, "BIG18", principal / 100 * 98);

// Advance time; permissionless update_indexes eventually panics.
loop {
    t.advance_time(YEAR_SECS);
    if let Err(e) = t.try_update_indexes_for(&["BIG18"]) { break e; }
}
assert_contract_error(failed, errors::MATH_OVERFLOW);

// Market permanently frozen: exits and repayments accrue first, same panic.
assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
assert!(book(&t, "BIG18").borrow_index < MAX_BORROW_INDEX_RAY);
```

```rust
/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
