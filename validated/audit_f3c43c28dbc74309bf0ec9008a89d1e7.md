### Title
Permanent freeze of curve-raised LT and 250M tokens when the push-transfer to the HyperSwap pair in `finalizeGraduation` reverts - (File: packages/contracts/src/Bonding.sol)

### Summary
`Bonding.finalizeGraduation` is the sole, one-shot, permissionless exit from `Lifecycle.Graduating`. It pushes the curve-raised LT reserve asset and the LP-bound token allocation directly to the HyperSwap V2 pair via `IERC20.safeTransfer`/`forceApprove`+`addLiquidity` (in `_seedDirectMint`, `_pairRebalance`, `_routerDepositAndDispose`), then calls the one-shot `LPLock.recordLock`. There is no pull-pattern fallback analogous to Moloch's proposal path: if any of these push transfers of the LT (a live, externally-controlled BounceTech Leveraged Token) revert, the token is permanently stuck in `Lifecycle.Graduating` with all curve-raised LT and up to `LP_RESERVE` (250M) tokens locked in `Bonding` forever, with `buy`/`sell` both blocked (`TokenIsGraduating`).

### Finding Description
Once `_enterGraduating` runs (triggered permissionlessly by `Bonding.triggerGraduation` or inline on a threshold-crossing buy, see [1](#0-0) ), the token's `lifecycle` is irreversibly set to `Graduating` and the only way forward is `finalizeGraduation`: [2](#0-1) 

Inside phase 2, `_seedUniswapV2Direct` dispatches to one of three regimes, all of which move LT (and TOKEN) by direct `safeTransfer`/router-pulled `addLiquidity` into the HyperSwap pair: [3](#0-2) [4](#0-3) [5](#0-4) 

None of these transfers are wrapped in a try/catch or have any alternative code path. The reserve asset is explicitly documented as an external, live BounceTech LT read via `exchangeRate()`/`minTransactionSize()` etc., not a simple vanilla ERC20 — see the contract-level natspec: [6](#0-5) . If that LT ever reverts a transfer targeting the `Bonding` contract, the pair, or the router (e.g. a pause, an AUM/mint-floor gate reverting a subsequent internal `redeem`, or any other externally-triggered transfer restriction on the live LT contract), every call to `finalizeGraduation` for that token reverts identically every time — there is no retry-with-different-amount, no pull-claim fallback, and no owner rescue path once `Lifecycle.Graduating` is entered.

This is compounded by `LPLock.recordLock`, which the contract's own comments flag as a one-shot, non-revocable dependency: [7](#0-6) [8](#0-7) 

Any revert in that final call (e.g. `InsufficientLPBalance` from an LT-side shortfall bleeding into the LP mint) equally bricks the whole graduation permanently, since `finalizeGraduation` cannot skip it (as the codebase's own comment on `isLocker` acknowledges: "would brick every in-flight `Bonding.finalizeGraduation`").

This is the same bug class as the referenced Moloch.sol report: a push-pattern token transfer inside a mandatory finalization step, with no pull-pattern fallback, where a transfer that can be blocked (by the external asset, analogous to a USDC blacklist) makes the finalization step permanently unexecutable — except here the blocked party isn't a proposer being refunded, it's the entire curve-raised treasury (LT) and 250M reserved tokens for every trader/holder of that token.

### Impact Explanation
If the push-transfer of LT reverts during `finalizeGraduation`, the affected token permanently freezes in `Lifecycle.Graduating`:
- All LT raised on the curve for that token (up to the graduation threshold, minimum `VIRTUAL_LIQUIDITY_USD` worth, i.e. real capital contributed by every buyer) is stuck in `Bonding` with no withdrawal path.
- Up to `LP_RESERVE` = 250,000,000 tokens allocated for LP are stuck and can never be minted into a pair or distributed.
- `buy`/`sell` on the curve are permanently blocked for that token (`TokenIsGraduating` revert in both functions), so holders cannot exit their position at all — this is a total, permanent freeze of trader funds for that token, not merely a stuck single proposal as in the Moloch case.
- There is no admin/owner rescue function reachable once `Lifecycle.Graduating` is set (verified: no such function exists in `Bonding.sol`).

This satisfies the "permanent freezing of trader, creator or LP funds" impact bar.

### Likelihood Explanation
Reachable by an unprivileged party: `triggerGraduation(tokenAddress)` is fully permissionless ( [9](#0-8) ), and any trader's ordinary `buy` can also cross the graduation threshold inline via `_executeBuy`. Once triggered, `finalizeGraduation` is likewise permissionless and can be called by anyone/anytime — but if the underlying LT transfer path is (even transiently) blocked, every call reverts identically. Likelihood therefore hinges entirely on whether the specific BounceTech LT deployed as a token's reserve asset can, under any operator/owner action or protocol-level condition on the live LT contract, revert a `transfer`/`transferFrom` of itself to/from `Bonding`, the HyperSwap pair, or the router. Since alt.fun is explicitly designed around arbitrary permissionless LTs (`Factory.ltExists` is the only launch-time gate — see [10](#0-9) ), and BounceTech LTs are rebasing tokens with owner-controlled parameters (mint floors, pausability being standard for such leveraged-token designs), this is a realistic operational condition rather than a purely theoretical one. I was not able to inspect the BounceTech LT's own source in this pass to confirm it exposes a pause/blacklist primitive; per the rules, bugs *inside* the LT itself are out of scope — the vulnerability here is `Bonding`'s reliance on an unconditional push-transfer with no pull/rescue fallback for a reserve asset it does not control.

### Recommendation
Add a pull-pattern (or at minimum an owner/permissionless rescue) fallback to `finalizeGraduation`'s LT/token movements, mirroring the fix recommended for Moloch: instead of unconditionally pushing LT into the pair inside `_seedDirectMint`/`_pairRebalance`/`_routerDepositAndDispose`, wrap the external LT transfer(s) so that a revert degrades to an escrow-and-claim model (e.g., record the amount owed and let the pair/LPLock/keeper "pull" it later, or let the owner sweep and re-attempt graduation with a substitute mechanism) rather than leaving the token wedged in `Lifecycle.Graduating` with no forward path.

### Proof of Concept
1. A creator launches a token via `Zap.createToken` pairing with a permissionless BounceTech LT (`Bonding.launch` only checks `IBounceFactory.ltExists`, not any transfer-safety property of the LT).
2. Traders buy on the curve until `canGraduate` is true (USD threshold or full sellout), or anyone calls `Bonding.triggerGraduation(tokenAddress)` once `canGraduate` is true — this fires `_enterGraduating`, setting `Lifecycle.Graduating` and caching `(tokensForLP, ltFromPair)`.
3. Before `finalizeGraduation` is called, an owner/operator-controlled property of the LT contract (e.g. a pause, denylist, or mint/redeem floor triggered internally during transfer bookkeeping) causes `IERC20(lt).transfer`/`transferFrom` calls that touch `Bonding`, the pair, or the router to revert.
4. Any caller invokes `Bonding.finalizeGraduation(tokenAddress)`. Execution reaches `_seedUniswapV2Direct` → `_seedDirectMint`/`_pairRebalance`/`_routerDepositAndDispose`, whose `IERC20(lt).safeTransfer(pair, ...)` or `forceApprove`+`addLiquidity` call reverts.
5. The transaction reverts entirely; `Lifecycle` remains `Graduating`. Every subsequent call to `finalizeGraduation` for this token reverts identically (deterministic input), and `buy`/`sell` remain permanently blocked with `TokenIsGraduating`. The curve-raised LT and the up-to-250M reserved tokens are permanently stuck in `Bonding` with no recovery function available.

    function finalizeGraduation(
        address tokenAddress
    ) external nonReentrant {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[tokenAddress];
        if (info.lifecycle != Lifecycle.Graduating) revert NotGraduating();

        address lt = info.ltAddress;
        PendingGraduation memory p = $.pendingGraduation[tokenAddress];

        // Anything in this contract beyond `p.ltFromPair` belongs to a
        // concurrent graduation on the same LT (Phase 1 transferred it
        // via `Router.graduate`) or to stray dust. Either way it is
        // off-limits to this graduation's deposit and sweep — see
        // `_routerDepositAndDispose` and `_sweepLTToOwner`.
        // Saturating subtract: a balance below `p.ltFromPair` shouldn't
        // be reachable in normal operation, but we keep finalize from
        // bricking on a Panic if any future code path or non-canonical
        // LT briefly violates the invariant.
        uint256 ltBalance = IERC20(lt).balanceOf(address(this));
        uint256 protectedLT = ltBalance > p.ltFromPair ? ltBalance - p.ltFromPair : 0;

        address lpPair = _ensureUniswapV2Pair(tokenAddress, lt);
        uint256 liquidity = _seedUniswapV2Direct(tokenAddress, lt, lpPair, p.tokensForLP, p.ltFromPair, protectedLT);

        _sweepLTToOwner(lt, protectedLT);

        info.lifecycle = Lifecycle.Graduated;
        $.graduatedPair[tokenAddress] = lpPair;
        delete $.pendingGraduation[tokenAddress];

        LPLock($.lpLock).recordLock(tokenAddress, lpPair, liquidity);

        emit TokenGraduated(tokenAddress, lpPair, liquidity, p.tokensForLP, p.lpBurned, p.unsoldBurned);
    }

    function _pairRebalance(
        RebalanceParams memory p
    ) internal returns (bool) {
        uint256 s = _noFeeSwapInput(p.reserveIn, p.reserveOut, p.targetN, p.targetD, p.maxSwap);
        if (s == 0) return false;

        // Quote from the pair so the output tracks its live fee; a value
        // derived from a stale fee rate would trip the pair's K-check.
        uint256 expectedOut = IUniswapV2Pair(p.pair).getAmountOut(s, p.tokenIn);
        if (expectedOut == 0) return false;

        IERC20(p.tokenIn).safeTransfer(p.pair, s);
        (uint256 amount0Out, uint256 amount1Out) = p.tokenInIs0 ? (uint256(0), expectedOut) : (expectedOut, uint256(0));
        IUniswapV2Pair(p.pair).swap(amount0Out, amount1Out, address(this), new bytes(0));
        return true;
    }

    function _routerDepositAndDispose(
        address tokenAddress,
        address lt,
        uint256 protectedLT
    ) internal returns (uint256 liquidity) {
        BondingStorage storage $ = _s();

        uint256 remToken = IERC20(tokenAddress).balanceOf(address(this));

    /// @notice Record an LP lock. LP tokens must already sit at this address.
    function recordLock(
        address token,
        address lpPair,
        uint256 amount
    ) external {
        LPLockStorage storage $ = _s();
        if (!$.isLocker[msg.sender]) revert NotAuthorized();
        if (lpPair == address(0)) revert ZeroAddress();
        if (amount == 0) revert ZeroAmount();
        // `lockedAt` is the one-shot sentinel: it is always set to a non-zero
        // timestamp on the first lock, so the guard holds for any `amount`.
        if ($.locks[token].lockedAt != 0) revert AlreadyLocked();
        if (IERC20(lpPair).balanceOf(address(this)) < amount) revert InsufficientLPBalance();
        $.locks[token] = LockInfo({lpPair: lpPair, amount: amount, lockedAt: block.timestamp});
        emit LPLocked(token, lpPair, amount);
    }
