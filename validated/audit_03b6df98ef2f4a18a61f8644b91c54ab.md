### Title
`signAndSendWithdrawalIntent` pushes quote hashes for fee estimations whose withdrawals were dropped by `zip` truncation - ([File: packages/intents-sdk/src/sdk.ts])

### Summary
In `IntentsSDK.signAndSendWithdrawalIntent`, the intents array is built via `zip(withdrawalParamsArray, feeEstimations)`, which truncates to the shorter of the two arrays, but `relayParamsFn` separately iterates the full, untruncated `feeEstimations` array to populate `quoteHashes`. When a caller supplies more fee estimations than withdrawal params, extra quote hashes are submitted to the relayer even though no signed intent consumed them.

### Finding Description
The equality that must hold is: `quoteHashes submitted to intentRelayer.publishIntents` == `set of quote_hash values actually referenced by the signed intents`.

The intents are built with:
```
const intentsP = zip(withdrawalParamsArray, feeEstimations).map(([withdrawalParams, feeEstimation]) => { ... });
``` [1](#0-0) 

`zip` (in `lib/array.ts`) pairs elements up to the length of the shorter array, so any `feeEstimations` entries beyond `withdrawalParamsArray.length` are silently dropped from intent construction.

However, `relayParamsFn` computes `quoteHashes` independently by iterating the entire `feeEstimations` array, not the zipped/truncated pairs:
```
for (const fee of feeEstimations) {
    if (fee.quote != null) {
        quoteHashes.push(fee.quote.quote_hash);
    }
}
``` [2](#0-1) 

Because this loop is over `feeEstimations` (full array) rather than over the pairs actually consumed to build `intents`, any extra fee estimation appended by the caller beyond `withdrawalParamsArray.length` still contributes its `quote.quote_hash` to `quoteHashes`, which is passed to `intentRelayer.publishIntents` alongside `intents` that never referenced that quote. There is no `assert` or length-equality check between `withdrawalParamsArray.length` and `feeEstimations.length` anywhere in this function (lines 689-743) that would catch this mismatch before either loop runs.

Attacker/caller input: `signAndSendWithdrawalIntent({ withdrawalParams: [w0], feeEstimation: [f0, f1_unused] })`. The zip-based intents-builder only produces intents for `(w0, f0)`; `f1_unused` is dropped from intent construction but not from the quote-hash loop.

### Impact Explanation
The relayer/solver-relay is told a quote hash (`f1_unused.quote.quote_hash`) was consumed as part of this publish call, even though no intent in the batch references or spends it. This can cause a legitimate, unrelated solver quote to be marked as consumed/relayed for a transaction it was never part of, misreporting quote consumption to the solver/relay layer. This matches the "fee error" / manipulation-adjacent category, though the direct funds-movement impact depends on how the solver-relay backend treats `quoteHashes` (e.g., whether it uses this to release solver liquidity or settle a quote). Within the SDK itself, this is a real divergence between signed intents and reported consumed quotes, repeatable on every call where a caller supplies mismatched-length arrays.

### Likelihood Explanation
Preconditions: caller (an integrator or any caller of the public `signAndSendWithdrawalIntent` batch API) must supply `feeEstimation.length > withdrawalParams.length`. This requires no special privilege — it's a normal call to a public SDK method with a malformed/mismatched batch, which is plausible either from an integrator bug or from a caller intentionally exploiting the mismatch to mark an unrelated quote as consumed. No on-chain state or route condition is required beyond having a valid extra quote hash. Highly feasible and trivially repeatable each call.

### Recommendation
Compute `quoteHashes` from the same zipped/truncated pairs used to build `intents`, not from the raw `feeEstimations` array — e.g., zip `withdrawalParamsArray` and `feeEstimations` once, reuse the truncated pairs for both intent construction and quote-hash collection, or explicitly assert `withdrawalParamsArray.length === feeEstimations.length` before proceeding.

### Proof of Concept
Vitest test plan:
1. Mock `intentRelayer.publishIntents` (or `publishIntent`) to capture its call arguments.
2. Call `intentsSDK.signAndSendWithdrawalIntent({ withdrawalParams: [w0], feeEstimation: [f0, f1_unused], intent: { signer: mockSigner } })` where `f0.quote.quote_hash = "hash_used"` and `f1_unused.quote.quote_hash = "hash_unused"`.
3. Assert that the `intents` array passed to `signAndSendIntent`/built from `zip` contains no diff/withdraw intent referencing `f1_unused` (only one withdrawal's intents, derived from `w0`/`f0`).
4. Assert that `publishIntents` was called with `quoteHashes` containing both `"hash_used"` and `"hash_unused"` — i.e., `quoteHashes.includes("hash_unused")` is `true` while no signed intent references it, demonstrating the broken equality.
