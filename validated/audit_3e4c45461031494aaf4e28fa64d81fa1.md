### Title
IntentGatewayV2 (Tron) `onAccept` omits the authorised-relayer gate present in the canonical EVM contract - ([File: evm/tron/contracts/apps/IntentGatewayV2.sol])

### Summary
The Tron variant of `IntentGatewayV2` never checks `incoming.relayer` before executing `RedeemEscrow`, `RefundEscrow`, `NewDeployment`, `UpdateParams`, or `SweepDust`, whereas the canonical EVM `IntentGatewayV2`/`ExtrinsicIntents` gates every one of these callbacks behind `_checkRelayer`. This is the same class of bug as the reported appchain-registry issue: a privilege/authorization check was added to one implementation and never mirrored to the structurally-identical sibling implementation.

### Finding Description
The canonical EVM gateway enforces a single authorised relayer for all `onAccept`/`onGetResponse` deliveries: [1](#0-0) 

and this gate is documented as the specific defense against a forged/compromised handler that could otherwise report an arbitrary relayer to authorize escrow redemption, governance upgrades, and parameter changes: [2](#0-1) 

The Tron implementation of the same contract, `evm/tron/contracts/apps/IntentGatewayV2.sol`, has no `_relayer` field, no `_checkRelayer`, and its `onAccept` never inspects `incoming.relayer` at all before dispatching `RedeemEscrow`/`RefundEscrow` (via `authenticate` + `withdraw`) or governance actions (`NewDeployment`, `UpdateParams`, `SweepDust`): [3](#0-2) 

Compare this to the constructor and state of the same contract, which carries only a one-shot `_admin` used solely by `setParams`, with nothing analogous to the relayer allowlist: [4](#0-3) [5](#0-4) 

### Impact Explanation
On the canonical EVM deployment, the relayer allowlist is the last line of defense if the host's handler is ever swapped for a malicious one (e.g., through a forged `SetHostParam` governance message under a compromised consensus client) — the `HostManagerTest.testForgedHandlerSwapIsRefused` scenario shows the attack this defends against. The Tron `IntentGatewayV2` has no equivalent gate, so the same class of attack (a subverted handler reporting an attacker-controlled relayer/sender) would let escrow funds be redeemed to an attacker-chosen beneficiary and governance-only actions (`NewDeployment`, `UpdateParams`, `SweepDust`) be applied without the relayer allowlist protection that the rest of the protocol relies on. This is medium/high severity because it can lead to theft of escrowed intent funds and unauthorized app configuration changes on the affected chain.

### Likelihood Explanation
Reaching this requires the same precondition the EVM relayer-gate decision docs describe (a forged/compromised handler or an equivalent host-parameter attack), so it is not trivially triggerable by an ordinary user in the current design, but it is directly reachable by any relayer once that precondition is met — exactly the scenario the EVM codebase already treats as a real, tested threat model. The Tron contract, being deployed as an independent, non-upgradeable-by-proxy copy of the same business logic, silently lacks the mitigation applied everywhere else in the codebase, mirroring the "partial fix" pattern from the reported bug.

### Recommendation
Port the `_relayer` / `setRelayer` / `_checkRelayer` gate (or equivalent) from `evm/src/apps/intentsv2/ExtrinsicIntents.sol` into `evm/tron/contracts/apps/IntentGatewayV2.sol`, and require `onAccept`/`onGetResponse` to validate `incoming.relayer` against the authorised relayer before decoding or acting on the request body, consistent with the canonical EVM implementation.

### Proof of Concept
1. Assume the Tron host's handler is compromised/forged (the same precondition documented for `testForgedHandlerSwapIsRefused` on the EVM side).
2. The attacker crafts/relays a `PostRequest` with `RequestKind.RedeemEscrow` (or a governance kind such as `UpdateParams`/`NewDeployment`) whose source/from passes `authenticate`.
3. The forged handler calls `onAccept` with an arbitrary `incoming.relayer` value; since Tron's `onAccept` never checks this field (unlike `ExtrinsicIntents._checkRelayer` in `evm/src/apps/intentsv2/ExtrinsicIntents.sol:75-78`), the withdrawal or governance mutation executes immediately, redeeming escrowed funds to an attacker-controlled `beneficiary` or applying unauthorized parameter changes.

     * @dev Once a relayer is set, rejects deliveries from anyone else before the body is read. The

    function _checkRelayer(address relayer) internal view {
        address authorised = _relayer;
        if (authorised != address(0) && relayer != authorised) revert Unauthorized();
    }

    function onAccept(IncomingPostRequest calldata incoming) external override onlyHost {
        RequestKind kind = RequestKind(uint8(incoming.request.body[0]));
        if (kind == RequestKind.RedeemEscrow || kind == RequestKind.RefundEscrow) {
            authenticate(incoming.request);
            WithdrawalRequest memory body = abi.decode(incoming.request.body[1:], (WithdrawalRequest));
            return withdraw(body, kind == RequestKind.RefundEscrow);
        }

        // only hyperbridge is permitted to perfom these actions
        if (keccak256(incoming.request.source) != keccak256(IDispatcher(host()).hyperbridge())) revert Unauthorized();
        if (kind == RequestKind.NewDeployment) {
            NewDeployment memory body = abi.decode(incoming.request.body[1:], (NewDeployment));
            _instances[keccak256(body.stateMachineId)] = body.gateway;

            emit NewDeploymentAdded({stateMachineId: body.stateMachineId, gateway: body.gateway});
        } else if (kind == RequestKind.UpdateParams) {
            // Decode the body which includes optional destination-specific protocol fee updates
            ParamsUpdate memory update = abi.decode(incoming.request.body[1:], (ParamsUpdate));
            emit ParamsUpdated({previous: _params, current: update.params});
            _params = update.params;

            // Update destination-specific protocol fees if provided
            for (uint256 i; i < update.destinationFees.length;) {
                bytes32 stateMachineId = update.destinationFees[i].stateMachineId;
                uint256 feeBps = update.destinationFees[i].destinationFeeBps;
                _destinationProtocolFees[stateMachineId] = feeBps;

                unchecked {
                    ++i;
                }
                emit DestinationProtocolFeeUpdated(stateMachineId, feeBps);
            }
        } else if (kind == RequestKind.SweepDust) {
            SweepDust memory req = abi.decode(incoming.request.body[1:], (SweepDust));

            uint256 outputsLen = req.outputs.length;
            for (uint256 i; i < outputsLen;) {
                TokenInfo memory info = req.outputs[i];
                address token = address(uint160(uint256(info.token)));
                uint256 amount = info.amount;

                if (token == address(0)) {
                    (bool sent,) = req.beneficiary.call{value: amount}("");
                    if (!sent) revert InsufficientNativeToken();
                } else {
                    (bool success,) = token.call(abi.encodeWithSelector(IERC20.transfer.selector, req.beneficiary, amount));
                    if (!success) revert TransferFailed();
                }
                unchecked {
                    ++i;
                }
                emit DustSwept(token, amount, req.beneficiary);
            }
        }
    }
