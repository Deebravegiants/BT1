## Title
Unauthenticated `/v2/resume/:runID` endpoint allows anyone possessing a task/run UUID to inject arbitrary results into a paused pipeline run - (File: `core/web/router.go`, `core/web/pipeline_runs_controller.go`)

### Summary
The Sherlock report describes a Vyper `Vault.migrate()` function that lacks any `msg.sender` check, letting an unprivileged actor trigger a privileged, state-changing action (and front-run the admin's `deactivate_migration`). The reachable Chainlink analog is the node's `PATCH /v2/resume/:runID` HTTP route, which is mounted in the **unauthenticated** route group and performs a privileged, state-changing action (injecting a result/error into a suspended pipeline run and resuming it) without any authentication or authorization check on the caller.

### Finding Description
In `core/web/router.go`, the resume route is deliberately registered on the unauthenticated group, bypassing every other auth method (`AuthenticateByToken`, `AuthenticateBySession`, external-initiator auth) that gate all other `/v2/*` endpoints: [1](#0-0) 

The handler itself, `PipelineRunsController.Resume`, performs zero access-control checks — it parses the caller-supplied `runID` (a UUID) directly out of the URL, decodes an arbitrary JSON body into a `pipeline.ResumeRequest`, and calls `App.ResumeJobV2` to inject that attacker-controlled value/error into the paused pipeline run, unconditionally advancing the run: [2](#0-1) 

The only nod to this being a known unauthenticated action is that it is specifically tagged with an `UnauthedRunResumed` audit event, which is defined alongside other authenticated audit events: [3](#0-2) 

Under the hood, `ResumeRun`/`UpdateTaskRunResult` writes the caller-supplied value/error directly as the task's result and, if the run is otherwise ready, restarts pipeline execution from that point: [4](#0-3) 

This mirrors the report's root cause precisely: a state-mutating operation (`migrate()` / `Resume()`) that any caller can invoke because the code path contains no `msg.sender`/authentication check, relying solely on knowledge of an opaque identifier (the `migration_admin` check is simply absent in the Vyper contract; here, authentication is structurally skipped by routing the endpoint into the unauthenticated group).

### Impact Explanation
Whoever can reach the node's HTTP interface and knows or obtains a suspended run's `runID`/`taskID` UUID can supply arbitrary result data (or an error) into an in-flight pipeline run and force it to resume with attacker-chosen data. Since pipeline runs commonly drive external-adapter-fed values that ultimately feed on-chain transactions/reports, forging the resumed value can corrupt job outputs. This is not equivalent to the external-initiator flow, which requires a hashed secret to authenticate — the resume path has no secret verification whatsoever, only reliance on the UUID being unguessable.

### Likelihood Explanation
Exploitation requires knowledge of the task/run UUID, which is not directly exposed to unauthenticated third parties in the default flow (it is normally only known to the external adapter chosen to callback). However, unlike the external-initiator callback mechanism (which cryptographically hashes a shared secret), this endpoint performs **no verification at all** — if the UUID is logged, cached, proxied through an intermediary, or otherwise disclosed (e.g., via bridge adapter response logs, HTTP proxies, browser history, or a compromised adapter), any party can permanently hijack the run. The complete absence of an authentication layer (versus a defense-in-depth secret check) elevates likelihood beyond "requires insider access."

### Recommendation
Add an authentication/authorization mechanism to the resume endpoint, e.g., require a signed/HMAC'd callback token tied to the specific task (verified server-side) instead of relying purely on UUID secrecy, or move the endpoint behind the existing external-initiator/API-token authentication used elsewhere in `core/web/auth/auth.go`, so that resuming a run requires proof of authorization from the entity that suspended it.

### Proof of Concept
1. Create/observe a job whose pipeline suspends on an async task, obtaining its `taskID` (e.g., via a leaked bridge/external-adapter callback log).
2. As an unauthenticated third party, send `PATCH /v2/resume/<taskID>` with an attacker-chosen JSON body (`{"value": ..., "error": ...}`).
3. Observe that `PipelineRunsController.Resume` accepts the request without any auth check [5](#0-4)  and the pipeline resumes using the attacker-supplied data via `ResumeJobV2`/`ResumeRun` [4](#0-3) .

```go
// Resume finishes a task and resumes the pipeline run.
// Example:
// "PATCH <application>/jobs/:ID/runs/:runID"
func (prc *PipelineRunsController) Resume(c *gin.Context) {
	taskID, err := uuid.Parse(c.Param("runID"))
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	rr := pipeline.ResumeRequest{}
	decoder := json.NewDecoder(c.Request.Body)
	err = errors.Wrap(decoder.Decode(&rr), "failed to unmarshal JSON body")
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	result, err := rr.ToResult()
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	if err := prc.App.ResumeJobV2(c.Request.Context(), taskID, result); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
	c.Status(http.StatusOK)
}
```

```go
func (r *runner) ResumeRun(ctx context.Context, taskID uuid.UUID, value any, err error) error {
	run, start, err := r.orm.UpdateTaskRunResult(ctx, taskID, Result{
		Value: value,
		Error: err,
	})
	if err != nil {
		return fmt.Errorf("failed to update task run result: %w", err)
	}

	// TODO: Should probably replace this with a listener to update events
	// which allows to pass in a transactionalised database to this function
	if start {
		// start the runner again
		go func() {
			ctx, cancel := r.chStop.NewCtx()
			defer cancel()
			if _, err := r.Run(ctx, &run, false, nil); err != nil {
				r.lggr.Errorw("Resume run failure", "err", err)
			}
			r.lggr.Debug("Resume run success")
		}()
	}
	return nil
}
```
