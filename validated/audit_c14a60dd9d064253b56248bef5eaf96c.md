## Analysis

The reported bug pattern is: a function reads/caches a config parameter used to gate a time-based authorization check, but that cached parameter is never refreshed even though the backend can push updated config values asynchronously — mirroring `FraxlendPair.changeFee()` applying a stale rate to a window it shouldn't cover.

In `orb-core`, `MasterPlan::run` destructures `operator_qr_expiration_time` from the shared config exactly once, before entering its main `loop` that drives every signup for the remainder of the orb's operating session [1](#0-0) . This single cached value is then passed unchanged into `scan_initial_qr_codes` on every iteration of the loop [2](#0-1)  and into `idle_wait_for_signup_request` [3](#0-2) , which uses it to decide whether a previously-scanned operator QR code is still valid to reuse for a new signup [4](#0-3) .

Meanwhile, the backend config is refreshed independently and asynchronously in the background via `Observer::config_update`, which downloads new config on an interval and stores it into the shared `Arc<Mutex<Config>>` [5](#0-4) , polled on `CONFIG_UPDATE_INTERVAL` [6](#0-5) . Because `MasterPlan::run` never re-reads `operator_qr_expiration_time` after its initial destructuring, any backend-side reduction of this value (e.g., to invalidate an operator QR code sooner after a suspected leak) will not take effect for the remainder of the orb's run — the master loop keeps treating the old QR code as valid under the stale, longer expiration window it captured at start-up. This is a direct architectural analog to the Fraxlend `changeFee()` bug: a security-relevant parameter change is silently ignored for already-in-flight state evaluation (here, operator QR / identity binding validity) instead of being applied immediately.

By contrast, `do_signup` re-derives the config fresh at the top of each call [7](#0-6) , so this staleness is specific to the outer idle/signup loop's operator-QR reuse path, not the whole codebase.

### Title
Stale cached `operator_qr_expiration_time` allows continued signups under an operator QR code that the backend has since deauthorized - (File: `src/plans/mod.rs`)

### Summary
`MasterPlan::run` reads `operator_qr_expiration_time` from the shared, mutable `Config` exactly once before entering its main signup loop, then reuses this stale value for the lifetime of the orb-core process to decide whether a cached operator QR code / operator identity binding is still valid for starting new signups.

### Finding Description
`operator_qr_expiration_time` governs how long a previously-scanned operator QR code (and the location/authorization data derived from it) may be reused without re-scanning [8](#0-7) . `MasterPlan::run` captures this value from `orb.config.lock().await` once, outside its `loop {}` [1](#0-0) , and this same value is used across every subsequent signup cycle to gate whether the cached operator QR data is expired in `scan_initial_qr_codes` [4](#0-3)  and `idle_wait_for_signup_request` [9](#0-8) .

The backend can independently update this value at any time via `Config::download`, which is fetched periodically in the background by `Observer::config_update` and swapped into the shared `Arc<Mutex<Config>>` [5](#0-4) . Because `MasterPlan::run` never re-reads the config for this specific value after start-up, a backend-issued reduction of `operator_qr_expiration_time` (for example, to shorten the reuse window after an operator QR code is suspected compromised or shared) has no effect on the already-running orb-core process — the stale, longer expiration continues to be enforced for as long as the process runs.

### Impact Explanation
If the backend narrows `operator_qr_expiration_time` as a corrective/security measure, an orb that has already cached an operator QR code will keep honoring the old, wider expiration window and continue accepting new user signups bound to that operator identity beyond the intended cutoff. This is an unauthorized-signup / misattributed-identity-binding condition: signups proceed under an operator authorization that the backend intended to have already lapsed.

### Likelihood Explanation
This triggers deterministically whenever the backend changes `operator_qr_expiration_time` while an orb-core process with `self_serve` idle-scanning active is already running with a cached operator QR code; no attacker action beyond normal reuse of a previously valid operator QR code is required, and the orb-core master loop can run unattended for extended periods between full restarts.

### Recommendation
Re-fetch `operator_qr_expiration_time` (and ideally all other per-loop-iteration config fields) from `orb.config.lock().await` at the top of each loop iteration in `MasterPlan::run`, rather than caching it once before the loop, so that backend-pushed config changes are honored for the next expiration check instead of only after a process restart.

### Proof of Concept
1. Start `orb-core` in self-serve mode; `MasterPlan::run` caches `operator_qr_expiration_time = 23h` from the initial config read.
2. An operator QR code is scanned and cached with a timestamp `T0`.
3. At `T0 + 1h`, the backend pushes a config update reducing `operator_qr_expiration_time` to `30m`, intending to invalidate the cached operator QR immediately (e.g., due to a suspected leak).
4. `Observer::config_update` downloads this new config into the shared `Arc<Mutex<Config>>`, but `MasterPlan::run`'s local `operator_qr_expiration_time` variable still holds `23h`.
5. `scan_initial_qr_codes`/`idle_wait_for_signup_request` continue to treat the cached operator QR as valid (`elapsed < 23h`) and allow further user signups to proceed under it, even though the backend's updated policy intended it to be expired after `30m`.

    async fn idle_wait_for_signup_request(
        &mut self,
        orb: &mut Orb,
        qr_codes: &QrCodes,
        self_serve: bool,
        self_serve_button: bool,
        operator_qr_expiration_time: Duration,
    ) -> Result<Option<QrCodes>> {
        // We currently support 4 scenarios:
        // 1. Internal testing with a biometric input file.
        // 2. Self-serve mode that always scans for a user QR code.
        // 3. Self-serve mode that expects a button press to ask for a user QR code.
        // 4. Normal mode that expects a button press to ask for an operator QR code and then a user QR code.
        //
        // Scenarios 3 and 4 are handled by the same code path in the following last else-statement.
        let ui_idle_delay = self.ui_idle_delay.take();
        let qr_codes = if self.oneshot || self.has_biometric_input() {
            qr_codes.clone()
        } else if self_serve && !self_serve_button {
            orb.set_phase("User QR-code idle scanning").await;
            let QrCodes::Operator { operator_data } = &qr_codes else {
                panic!("operator QR code needs to be scanned beforehand in self-serve mode");
            };
            let Some((user_qr_code, user_data, user_qr_code_string)) = self
                .idle_scan_user_qr_code(
                    orb,
                    operator_data,
                    operator_qr_expiration_time,
                    ui_idle_delay,
                )
                .await?
            else {
                return Ok(None);
            };
            qr_codes.with_user_qr_code(user_qr_code, user_data, user_qr_code_string)
        } else {
            orb.set_phase("Idle waiting for button press").await;
            self.idle_wait_for_button_press(orb, ui_idle_delay).await?;
            orb.ui.signup_start_operator();
            qr_codes.clone()
        };
        Ok(Some(qr_codes))
    }

    fn config_update(&mut self, observer: &mut Observer) -> Result<()> {
        if self.before_config_update()? {
            match observer.config_update.as_mut().map(future::FutureExt::now_or_never) {
                Some(None) => return Ok(()),
                Some(Some(result)) => result??,
                None => {}
            }
            let config = Arc::clone(&observer.config);
            let ui = observer.ui.clone();
            observer.config_update = Some(tokio::spawn(async move {
                if let Ok(new_config) = Config::download().await {
                    *config.lock().await = new_config;
                    config.lock().await.propagate_to_ui(ui.as_ref());
                }
                Ok(())
            }));
        }
        Ok(())
    }
