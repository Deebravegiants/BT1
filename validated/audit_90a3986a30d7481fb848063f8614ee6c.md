### Title
`instance()` fallback to `address(this)` for unregistered chains lets a same-address deployment on any un-onboarded state machine authenticate as a trusted `IntentGatewayV2` peer, enabling forged escrow redemption/refund - (File: `evm/tron/contracts/apps/IntentGatewayV2.sol`)

### Summary
The Tron `IntentGatewayV2` diverges from the canonical EVM implementation's `instance()`/`authenticate()` pattern. Instead of reverting when a state machine has no registered peer gateway, `instance()` silently falls back to `address(this)`, and `authenticate()` accepts any incoming `PostRequest` whose `from` field equals that fallback value — exactly the same bug class as the external report: a sentinel/default value (`address(0)` for "unregistered") collides with a value (`address(this)`) that the guard treats as legitimate, so the "not registered" guard is bypassed.

### Finding Description
`instance()` in the Tron gateway:
```solidity
function instance(bytes calldata stateMachineId) public view returns (address) {
    address gateway = _instances[keccak256(stateMachineId)];
    return gateway == address(0) ? address(this) : gateway;
}
``` [1](#0-0) 

and `authenticate()`:
```solidity
function authenticate(PostRequest calldata request) internal view {
    if (request.from.length != 20) revert InvalidInput();
    address module = address(bytes20(request.from));
    if (instance(request.source) != module) revert Unauthorized();
}
``` [2](#0-1) 

For any `request.source` state machine that has never been explicitly registered via a governance `NewDeployment` message (i.e. `_instances[keccak256(stateMachineId)] == address(0)`), `instance()` returns `address(this)` instead of reverting. `authenticate()` then accepts the request as long as `request.from` equals the gateway's own address. `onAccept` routes `RedeemEscrow`/`RefundEscrow` requests straight through `authenticate()` into `withdraw()`, which transfers out whatever tokens the `WithdrawalRequest` body names:
```solidity
if (kind == RequestKind.RedeemEscrow || kind == RequestKind.RefundEscrow) {
    authenticate(incoming.request);
    WithdrawalRequest memory body = abi.decode(incoming.request.body[1:], (WithdrawalRequest));
    return withdraw(body, kind == RequestKind.RefundEscrow);
}
``` [3](#0-2) 

Because `IntentGatewayV2` contracts are deployed deterministically at the same address across EVM-compatible chains, `request.from` naturally equals `address(this)` for the intended, legitimately-registered peers too — but the fallback makes this collision apply to *every* state machine that has simply not yet gone through the `NewDeployment` governance flow. Any chain connected to Hyperbridge (or reachable via a relayed/proven ISMP message) whose state machine ID is not yet present in `_instances` will authenticate successfully if a contract at the gateway's deterministic address dispatches a `PostRequest` from it — draining `_orders[commitment][token]` escrow to an attacker-controlled beneficiary via `withdraw()`.

This is directly analogous to the `PolicyProposals` bug: the guard (`registerProposal`/`refund` checking for already-registered/eligible proposals; here, `authenticate` checking for a known peer) does not correctly special-case the "not yet set" sentinel (`address(0)` in both cases), and the fallback behavior (`address(this)`) unintentionally satisfies the guard.

For comparison, the canonical EVM version (`evm/src/apps/intentsv2/IntentsBase.sol`) defines an explicit `UnknownInstance` error precisely to revert instead of silently falling back for unregistered chains [4](#0-3) , and the corresponding test suite confirms `instance()` reverts for unregistered state machine IDs [5](#0-4) . The Tron contract's silent `address(this)` fallback is the deviation that reintroduces the zero-value/sentinel bypass.

### Impact Explanation
A successful forgery lets an attacker drain all cross-chain escrowed tokens (`_orders[commitment][token]`) and accumulated transaction fees held by the Tron `IntentGatewayV2` contract, by fabricating `RedeemEscrow`/`RefundEscrow` requests from any not-yet-onboarded (but Hyperbridge-connected) state machine, directing funds to an arbitrary beneficiary. This is concrete theft of escrowed user/solver funds — Critical severity under the "concrete theft ... of funds" acceptance criterion.

### Likelihood Explanation
Exploitation requires the attacker to get a genuine ISMP `PostRequest` delivered and proven (through the host's consensus verification) with `source` set to a state machine identifier that the Tron gateway has not yet registered via `NewDeployment`, and `from` matching the gateway's deterministic address. Any newly connected chain, testnet, or a chain intentionally left unregistered (since governance registration lags behind Hyperbridge's chain onboarding) provides this window. Because gateway deployments intentionally share the same address across chains for legitimate reasons, an attacker only needs control of an app/contract at that same address on some other Hyperbridge-supported chain (achievable via CREATE2 with the same salt/bytecode, a standard, permissionless step) to produce a matching `from`.

### Recommendation
Make `instance()` revert (or otherwise fail closed) for unregistered state machine IDs instead of returning `address(this)`, mirroring `IntentsBase.UnknownInstance` in the canonical EVM implementation, so `authenticate()` only accepts requests from explicitly governance-registered peer gateways.

### Proof of Concept
1. Confirm `_instances[keccak256("NEW_CHAIN")] == address(0)` (never registered via `NewDeployment` on the Tron `IntentGatewayV2`).
2. Deploy an identical-address `IntentGatewayV2`/dispatcher-controlled contract on any Hyperbridge-connected chain identified as `"NEW_CHAIN"`, using the same CREATE2 salt/bytecode as the legitimate deterministic deployment.
3. From that contract, dispatch an ISMP `PostRequest` with `source = "NEW_CHAIN"`, `from = abi.encodePacked(address(this))` (which equals the Tron gateway's address), `to = abi.encodePacked(tronGatewayAddress)`, and `body = bytes.concat(bytes1(uint8(RequestKind.RedeemEscrow)), abi.encode(WithdrawalRequest({commitment: <existing escrowed commitment>, tokens: <escrowed tokens>, beneficiary: <attacker address>})))`.
4. Once the relayer proves and delivers this request, the Tron host calls `onAccept`, `authenticate()` computes `instance("NEW_CHAIN") == address(this) == module` (since `from` == gateway address) and passes.
5. `withdraw()` releases the escrowed tokens to the attacker-controlled beneficiary, confirmed via `_orders[commitment][token]` being zeroed and the beneficiary's balance increasing — matching the `testInstance`/`testOnAcceptNewDeployment` control-flow shown in `IntentGatewayV2Test.sol` but bypassing the intended `NewDeployment` registration step entirely.
