## Analysis

The Sherlock report describes replaying another party's submission values to claim rewards without doing the underlying work. The equivalent construct in this Hyperbridge codebase is `pallet-beefy-consensus-proofs`, which pays provers a treasury reward (`ProofReward`) plus a 1:1 reputation-asset mint for submitting a BEEFY consensus proof that advances Hyperbridge's view of the coprocessor parachain.

For SP1 proofs the pallet explicitly defends against exactly this "steal someone else's submitted proof" attack: the SP1 proof commits a prover-chosen nonce into its public values, and `do_submit_proof` requires that nonce to equal the extrinsic signer, rejecting a copied proof submitted by anyone other than the account that generated it [1](#0-0) . This is explicitly documented as "the anti-theft gate" preventing proofs from being "stolen from the mempool" [2](#0-1) .

However, the `PROOF_TYPE_NAIVE` branch sets `account = None` and applies none of this binding [3](#0-2) . `settle_first_proof` still pays the full position-0 reward to whichever account is the extrinsic `submitter`, regardless of proof type [4](#0-3) , and `pay_position_reward` transfers `ProofReward` from the treasury and mints reputation tokens to that `submitter` [5](#0-4) .

### Title
Naive BEEFY consensus proofs lack prover-binding, allowing mempool theft of treasury rewards - (File: `modules/pallets/beefy-consensus-proofs/src/lib.rs`)

### Summary
`submit_proof` accepts two proof kinds, `PROOF_TYPE_SP1` and `PROOF_TYPE_NAIVE`. SP1 proofs are cryptographically bound to their submitting account via a committed nonce check, explicitly to prevent a proof from being copied out of the mempool and claimed by a different account. `PROOF_TYPE_NAIVE` proofs receive no such binding (`account = None`), yet are paid the identical treasury reward and reputation mint as a bound SP1 proof, keyed only by the extrinsic's signer.

### Finding Description
`do_submit_proof` decodes the proof type and, only for `PROOF_TYPE_SP1`, enforces `submitter.encode() == nonce`, rejecting the call with `UnauthorizedProof` on mismatch [3](#0-2) . For `PROOF_TYPE_NAIVE` no such check exists — `account` is simply `None`.

The naive proof bytes themselves (an ECDSA/BEEFY multi-signature justification, decoded via `ismp_abi::ecdsa_beefy::BeefyConsensusProof`) are self-verifying data collected from the relay chain; they contain no reference to whoever assembled/submitted them [6](#0-5) . Once a legitimate prover broadcasts a `submit_proof(naive_proof_bytes)` extrinsic, those bytes are visible in the public transaction pool before inclusion. Any other account can copy the exact same `proof` bytes into their own `submit_proof` call and, if included first (e.g. via higher tip/fee, faster propagation, or validator collusion), pass `verify_and_apply` identically — the check only validates the proof's cryptographic content and its height against the last-applied state, not who submitted it.

`settle_first_proof` then pays `pay_position_reward(&submitter, 0)` to whichever account's extrinsic actually landed on-chain [7](#0-6) , transferring the full `ProofReward` from the treasury and minting reputation to that copier — not to the account that actually monitored the relay chain and produced the justification.

### Impact Explanation
This lets an unprivileged attacker who does no consensus-following/proof-production work at all systematically front-run the mempool and redirect every `ProofReward` treasury payout (plus the associated reputation-asset mint) for naive proofs to themselves. This is a direct theft of treasury funds and an unearned inflation of the reputation asset, and it also destroys the economic incentive for honest naive-proof provers to keep Hyperbridge's BEEFY consensus state current, since their work can always be appropriated by a faster/better-connected copier. Given naive proofs are also what keeps Hyperbridge's coprocessor state machine height advancing (gating request/response delivery finality), sustained griefing of honest provers can also degrade the freshness of consensus updates.

### Likelihood Explanation
Any node with mempool visibility (a validator, a bot running on public RPC, or a colluding relayer) can trivially observe pending `submit_proof` calls carrying `PROOF_TYPE_NAIVE`, copy the `proof` bytes verbatim, and resubmit under their own account with a higher priority/fee. No special permissions or capital are required — this is a pure MEV/front-running attack enabled by the missing binding that the SP1 path already implements for exactly this reason.

### Recommendation
Bind naive proofs to their submitter the same way SP1 proofs are bound, e.g. by requiring/deriving a submitter-specific value from the proof (if the format allows embedding one), or by disallowing/deprioritizing naive proofs for reward purposes and reserving `ProofReward` payouts for provably-bound proof types, or by having `pallet-ismp`/the transaction pool assign priority based on original broadcaster in a way that cannot be fully replicated by a copier. At minimum, treat `PROOF_TYPE_NAIVE` submissions the same as SP1 for anti-theft purposes rather than exempting them.

### Proof of Concept
1. Honest prover P constructs a valid naive BEEFY proof and submits `submit_proof(naive_proof_bytes)` from account A.
2. Attacker M observes the pending extrinsic in the public mempool, extracts `naive_proof_bytes`, and submits `submit_proof(naive_proof_bytes)` from account M with a higher fee/tip.
3. M's extrinsic is included first. `verify_and_apply` succeeds (the proof is cryptographically valid regardless of submitter) [8](#0-7) .
4. `settle_first_proof` pays the full `ProofReward` and mints reputation to M [7](#0-6) .
5. P's original extrinsic, submitted second, now fails `verify_and_apply`'s height check (`latest_height <= prev_height` → `StaleProof`) since state has already advanced, and since it's a naive proof it does not route to the uncle path (`settle_uncle_proof` is SP1-only) [9](#0-8) , so P receives nothing despite doing all the actual work.

//! ## Prover-bound proofs & deduplication
//!
//! Each SP1 proof commits a prover-chosen nonce into its public values, and the pallet
//! requires that nonce to equal the extrinsic signer (the reward payee). This binds a proof
//! to its submitter: a copied proof verifies cryptographically but cannot be claimed by a

//! account is rewarded at most once per height. Because the nonce is committed (not derived
//! from the proof bytes), Groth16 re-randomization or re-proving cannot mint extra reward

			// For SP1 proofs, decode the committed nonce and require it to equal the extrinsic
			// signer. The nonce is committed into the proof's public values, so it can only be
			// changed by re-running the SP1 program — a copied proof verifies cryptographically
			// but is bound to the *original* prover's account, so a different signer cannot claim
			// it. This is the anti-theft gate and also the dedup key: see [`AcceptedProvers`].
			//
			// Binding to the committed nonce also makes dedup robust without canonical
			// re-encoding: Groth16 re-randomization (or re-proving) yields different proof bytes
			// for the same statement, but all of them carry the same committed nonce, so they
			// collapse to a single per-account slot regardless of trailing padding or alternate
			// encodings.
			let account = match proof_type {
				types::PROOF_TYPE_SP1 => {
					let p =
						<ismp_abi::sp1_beefy::SP1Beefy::SP1BeefyProof as SolType>::abi_decode_params(
							&proof[1..],
						)
						.map_err(|_| Error::<T>::AbiDecodeFailed)?;
					let nonce = H256(p.nonce.0);
					// `T::AccountId` is `AccountId32` in hyperbridge runtimes, which SCALE-encodes
					// to its 32 raw bytes; compare those against the committed nonce.
					if submitter.encode().as_slice() != nonce.as_bytes() {
						Err(Error::<T>::UnauthorizedProof)?
					}
					Some(nonce)
				},
				types::PROOF_TYPE_NAIVE => None,
				_ => Err(Error::<T>::UnknownProofType)?,
			};

			// Read the pre-proof consensus state before `verify_and_apply` mutates it.
			// Used to seed `ProofContext` for the first-proof path.
			let host = pallet_ismp::Pallet::<T>::default();
			let prev_state_bytes = host
				.consensus_state(ismp_beefy::BEEFY_CONSENSUS_ID)
				.map_err(|_| Error::<T>::NotInitialized)?;

			match Self::verify_and_apply(&proof) {
				Ok(outcome) => Self::settle_first_proof(
					submitter,
					proof,
					account,
					proof_type,
					prev_state_bytes,
					outcome,
				),
				// `verify_and_apply` returns `StaleProof` for SP1 proofs whose
				// `block_number <= prev.latest_beefy_height` via the upfront height check,
				// which is exactly the legitimate-uncle case. Other failures (corrupt
				// bytes, bad signatures, wrong vkey) propagate so the submitter pays the
				// fee instead of paying for a wasted second SP1 verification.
				Err(Error::<T>::StaleProof) if proof_type == types::PROOF_TYPE_SP1 => {
					// SP1 always yields `Some(account)` above.
					let account = account.ok_or(Error::<T>::UnknownProofType)?;
					Self::settle_uncle_proof(submitter, proof, account)
				},
				Err(e) => Err(e.into()),
			}

		pub fn settle_first_proof(
			submitter: T::AccountId,
			proof: Vec<u8>,
			account: Option<H256>,
			proof_type: u8,
			prev_state_bytes: Vec<u8>,
			outcome: VerifyOutcome,
		) -> DispatchResultWithPostInfo {
			if outcome.has_new_messages {
				LastRewardedDispatchRoot::<T>::put(outcome.child_trie_root);
			}

			// Record uncle metadata for SP1 proofs only. Naive proofs are ineligible.
			//
			// A rotation may land on a height a messaging proof already filled, and the slots
			// are bounded, so this can fail. Uncle bookkeeping only decides who gets paid,
			// while the caller has already applied the authority-set rotation, so a hard error
			// here would roll that rotation back. The mandatory justification is the only one
			// obtainable for that session, so every retry would fail identically and the
			// consensus state would sit on the old set forever. Log and carry on instead.
			// Skipping the record cannot mint a second reward: `ProverCount` is already at the
			// cap, so `settle_uncle_proof` rejects on position before it reads `AcceptedProvers`.
			if proof_type == types::PROOF_TYPE_SP1 {
				let account = account.ok_or(Error::<T>::UnknownProofType)?;
				if let Err(e) =
					Self::record_uncle_metadata(outcome.latest_height, prev_state_bytes, account)
				{
					log::warn!(
						target: "ismp",
						"[beefy-consensus-proofs] uncle metadata skipped at height {}: {e:?}",
						outcome.latest_height,
					);
				}
			}

			// Same reasoning as the uncle bookkeeping above: the caller has already applied the
			// authority-set rotation, so a hard error here rolls it back, and since the mandatory
			// justification is the only one obtainable for that session every retry fails
			// identically until someone tops the treasury up — leaving the consensus state on the
			// old set in the meantime. A missed reward is the cheaper loss, so log and carry on.
			// Messaging proofs keep the hard error: reverting one is recoverable, because the work
			// is re-attempted by the next proof once the treasury can pay.
			let reward_paid = match Self::pay_position_reward(&submitter, 0) {
				Ok(reward) => reward,
				Err(e) if outcome.rotated => {
					log::warn!(
						target: "ismp",
						"[beefy-consensus-proofs] reward skipped for rotation to set {}: {e:?}",
						outcome.current_set_id,
					);
					BalanceOf::<T>::default()
				},
				Err(e) => Err(e)?,
			};

		fn pay_position_reward(
			submitter: &T::AccountId,
			position: u32,
		) -> Result<BalanceOf<T>, Error<T>> {
			let zero = BalanceOf::<T>::default();
			let base = ProofReward::<T>::get();
			if base == zero {
				return Ok(zero);
			}

			let reward = Self::position_reward(base, position);
			if reward == zero {
				return Ok(zero);
			}

			let treasury: T::AccountId =
				<T as Config>::TreasuryPalletId::get().into_account_truncating();
			<T as Config>::Currency::transfer(&treasury, submitter, reward, Preservation::Preserve)
				.map_err(|e| {
					log::warn!(
						target: "ismp",
						"[beefy-consensus-proofs] treasury reward transfer failed: {e:?}",
					);
					Error::<T>::RewardTransferFailed
				})?;

			if let Err(e) = T::ReputationAsset::mint_into(submitter, reward) {
				log::warn!(
					target: "ismp",
					"[beefy-consensus-proofs] reputation mint failed: {e:?}",
				);
			}

			Ok(reward)
		}
