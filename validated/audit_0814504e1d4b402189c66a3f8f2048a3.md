## Finding

Chainlink's gateway internet-facing HTTP server implements a weak, string-suffix-based CORS origin allowlist check that can be bypassed by an unprivileged, unauthenticated web client — directly analogous to the GHSA-c2w2-prh8-qm98 "weak host validation → host confusion" bug class.

### Title
CORS Origin Allowlist Bypass via Unanchored Suffix Matching in Gateway Wildcard Origin Check - (File: core/services/gateway/network/httpserver.go)

### Summary
The gateway's public HTTP server validates the `Origin` header against a configured allowlist (`CORSAllowedOrigins`) in `isAllowedOrigin`. For wildcard entries such as `*.ethereum.org`, the code strips the `*.` prefix and then checks `strings.HasSuffix(originHost, allowedHost)` with no boundary check that the character preceding the matched suffix is a `.`. Just as the psr7 advisory shows that failing to properly validate/anchor host components lets an attacker-supplied host be misinterpreted as trusted, this code lets an attacker register or control a domain like `evilethereum.org` that is not a subdomain of `ethereum.org` but still satisfies the suffix check, since `"evilethereum.org"` ends with `"ethereum.org"` with no dot separating them. [1](#0-0) 

### Finding Description
`isAllowedOrigin` parses the untrusted `Origin` header via `splitURL`, which uses `url.Parse` plus `net.SplitHostPort`. [2](#0-1) 
For each configured allowed origin, if it starts with `*.`, the wildcard prefix is stripped and the remaining string is compared using `strings.HasSuffix` against the request's `Origin` host — with no requirement that a `.` immediately precede the matched suffix in `originHost`: [1](#0-0) 
This is called directly from the request handling path on every incoming HTTP request to the gateway's user-facing server, keyed off the client-supplied `Origin` header: [3](#0-2) 

Given `CORSAllowedOrigins = ["https://*.ethereum.org"]`, the allowed host after `*.` stripping is `ethereum.org`. An attacker who controls (or registers) a domain such as `https://evilethereum.org` (no dot before `ethereum.org`) sends this as their `Origin` header. `originHost == "evilethereum.org"` satisfies `strings.HasSuffix("evilethereum.org", "ethereum.org")`, so the check incorrectly returns `true`, and the server responds with `Access-Control-Allow-Origin: https://evilethereum.org`, treating an unrelated, attacker-controlled origin as trusted.

### Impact Explanation
This weak suffix-based host validation causes CORS to trust an origin that is not actually a subdomain of the intended allowlisted domain — a cross-origin trust-boundary bypass exactly matching CWE-20 "Improper Input Validation" flagged in the advisory. Any browser-based client on the attacker's look-alike domain can then make credentialed cross-origin requests to the gateway and read responses that should be scoped to the legitimately allowlisted origins, enabling cross-user response confusion/disclosure for whatever the gateway's user-facing HTTP API exposes (e.g., workflow trigger responses, job results) to any browser session that reaches the gateway with cookies/credentials attached.

### Likelihood Explanation
Exploitation only requires an unprivileged actor to register or control a domain sharing the vulnerable suffix (no dot boundary enforced) and to send a normal cross-origin browser request with a crafted `Origin` header — no authentication or node-level privileges are needed. This is reachable purely from the internet-facing gateway HTTP endpoint.

### Recommendation
Fix the wildcard match in `isAllowedOrigin` to require a `.` boundary before the matched suffix (i.e., check that `originHost == allowedHost` or `strings.HasSuffix(originHost, "."+allowedHost)`), so `evilethereum.org` cannot satisfy an allowlist entry for `*.ethereum.org`.

### Proof of Concept
1. Configure the gateway with `CORSAllowedOrigins = ["https://*.ethereum.org"]`.
2. Send a request to the gateway's HTTP endpoint with header `Origin: https://evilethereum.org`.
3. Observe the response includes `Access-Control-Allow-Origin: https://evilethereum.org` (as shown by the flow in [4](#0-3) ), confirming the untrusted origin is incorrectly allowed.

func (s *httpServer) splitURL(rawURL string) (string, string, string, error) {
	// lowercase the URL to avoid case sensitivity issues
	parsedURL, err := url.Parse(strings.ToLower(rawURL))
	if err != nil {
		return "", "", "", fmt.Errorf("error parsing URL: %w", err)
	}

	host, port, err := net.SplitHostPort(parsedURL.Host)
	if err != nil {
		// if there's no port, the host itself is returned
		if parsedURL.Host != "" {
			return parsedURL.Scheme, parsedURL.Host, "", nil
		}
		return "", "", "", fmt.Errorf("error splitting host and port: %w", err)
	}

	return parsedURL.Scheme, host, port, nil
}
