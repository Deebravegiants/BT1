### Title
Wildcard CORS `Access-Control-Allow-Origin` allowlist matching lacks a domain-boundary check, allowing attacker-controlled origins to receive credentialed gateway responses - ([File: core/services/gateway/network/httpserver.go])

### Summary
The gateway's HTTP server implements a CORS allowlist for cross-origin requests. When an allowed origin entry uses a wildcard subdomain form (e.g. `https://*.ethereum.org`), the matching logic strips the `*.` prefix and then checks whether the request's `Origin` header host merely ends with the resulting suffix — without requiring a `.` boundary. This lets an attacker register a domain like `evil-ethereum.org` (which is *not* a subdomain of `ethereum.org`) and still have it match the wildcard rule, causing the gateway to reflect that origin in `Access-Control-Allow-Origin` and permit the browser to read the response cross-origin, analogous to the reported bug class where an internet-facing message endpoint fails to correctly validate the origin of the requester before exposing sensitive response data.

### Finding Description
`isAllowedOrigin` in `core/services/gateway/network/httpserver.go` performs the allowlist check: [1](#0-0) 

For non-wildcard entries it requires an exact host match. For wildcard entries (`*.host`), it strips the `*.` prefix and then does:
```go
allowedHost = allowedHost[2:]
if strings.HasSuffix(originHost, allowedHost) {
    return true
}
```
`strings.HasSuffix` performs a raw string-suffix comparison with no requirement that the character immediately preceding the matched suffix be a `.` (domain label boundary). This means any origin host that simply ends with the configured suffix — not just true subdomains — will pass the check. For example, if the operator configures `CORSAllowedOrigins = ["https://*.ethereum.org"]` intending to allow only actual subdomains of `ethereum.org` (e.g. `remix.ethereum.org`), an attacker-registered domain such as `https://evil-ethereum.org` or `https://notethereum.org` also satisfies `HasSuffix(originHost, "ethereum.org")` and is treated as allowed.

This check feeds directly into `handleRequest`, which reflects the (attacker-supplied) `Origin` header value back in `Access-Control-Allow-Origin` when `isAllowedOrigin` returns true: [2](#0-1) 

This is a real, internet-facing gateway component (`httpServer.handleRequest`), reachable by any unauthenticated browser client that can trigger a cross-origin request, matching the "internet-facing gateway (message envelopes, allowlist/subscriptions, handlers, caches)" scope. The root cause — an allowlist/origin-matching function that fails to properly bound-check the origin before granting cross-origin trust — is directly analogous to CVE-2022-25146's root cause (a Remote-App message handler that failed to verify the origin of incoming messages before treating them as trusted, enabling exfiltration of sensitive data via a mismatched/attacker-controlled origin).

### Impact Explanation
If an operator configures a wildcard CORS entry (a documented, supported configuration pattern per the existing test suite, e.g. `https://*.ethereum.org`, `https://*.valid.domain.com`), any attacker who registers a similarly-suffixed domain (`evil-ethereum.org`, `xethereum.org`, etc.) can host a malicious webpage that issues cross-origin requests to the gateway HTTP endpoint. The browser will honor the reflected `Access-Control-Allow-Origin` header and allow the attacker's page to read the gateway's response body, which can include sensitive data such as JSON-RPC responses to node/gateway operations. This is a concrete cross-origin response exposure / allowlist-bypass condition reachable from an unprivileged web client.

### Likelihood Explanation
Exploitability depends on the deployment using a wildcard entry in `CORSAllowedOrigins` (a supported feature, evidenced by `TestHTTPServer_HandleRequest_CORSEnabled_FromAllowedOriginWildcards` in `core/services/gateway/network/httpserver_test.go`). Registering a domain that satisfies the suffix condition but is not a genuine subdomain (e.g. buying `evil-ethereum.org` when `*.ethereum.org` is allowlisted) is trivial and requires no privileged access — only a domain registration and a malicious webpage, making this a low-effort, unprivileged-actor attack once a wildcard entry is configured.

### Recommendation
Fix the wildcard suffix check in `isAllowedOrigin` to require a domain-label boundary, e.g. compare against `"."+allowedHost` as the suffix (after stripping the `*.` prefix), so that only genuine subdomains match:
```go
if strings.HasSuffix(originHost, "."+allowedHost) || originHost == allowedHost {
    return true
}
```
Additionally, add explicit negative test cases (e.g. `evil-ethereum.org` should NOT match `*.ethereum.org`) alongside the existing positive wildcard tests in `core/services/gateway/network/httpserver_test.go`.

### Proof of Concept
1. Operator configures the gateway with `CORSEnabled = true` and `CORSAllowedOrigins = ["https://*.ethereum.org"]`.
2. Attacker registers `https://evil-ethereum.org` and serves a page there that performs a `fetch()`/XHR request to the gateway's HTTP endpoint with `Origin: https://evil-ethereum.org`.
3. `isAllowedOrigin` computes `allowedHost = "ethereum.org"` (after stripping `*.`) and checks `strings.HasSuffix("evil-ethereum.org", "ethereum.org")`, which returns `true`.
4. `handleRequest` sets `Access-Control-Allow-Origin: https://evil-ethereum.org` on the response, and the browser permits the attacker's script to read the gateway's response body — despite `evil-ethereum.org` not being an intended subdomain of `ethereum.org`. [3](#0-2)

func (s *httpServer) isAllowedOrigin(origin string) bool {
	originScheme, originHost, originPort, err := s.splitURL(origin)
	if err != nil {
		s.lggr.Debug("error parsing origin URL", err)
		return false
	}
	for _, allowed := range s.config.CORSAllowedOrigins {
		// probably better to do this once when server starts and store it in a map
		// this is an easier solution so we don't have to apply more changes to the code
		// just need to be careful when specifying allowed origins in the config file
		allowedScheme, allowedHost, allowedPort, err := s.splitURL(allowed)
		if err != nil {
			s.lggr.Debug("error parsing allowed origin URL", err)
			continue
		}
		// skip if the scheme doesn't match at all
		if originScheme != allowedScheme {
			continue
		}
		// skip if the port doesn't match at all
		if originPort != allowedPort {
			continue
		}
		// check for exact host match (e.g., remix.com)
		if originHost == allowedHost {
			return true
		}
		// check for wildcard host match (e.g., *.remix.com)
		if strings.HasPrefix(allowedHost, "*.") {
			allowedHost = allowedHost[2:]
			if strings.HasSuffix(originHost, allowedHost) {
				return true
			}
		}
	}
	return false
}

func (s *httpServer) handleRequest(w http.ResponseWriter, r *http.Request) {
	if s.config.CORSEnabled {
		origin := r.Header.Get("Origin")
		if s.isAllowedOrigin(origin) {
			w.Header().Set("Access-Control-Allow-Origin", origin)
			w.Header().Set("Access-Control-Allow-Methods", "GET, POST, OPTIONS")
			w.Header().Set("Access-Control-Allow-Headers", "Content-Type")
		}

		// handle preflight requests
		if r.Method == http.MethodOptions {
			w.WriteHeader(http.StatusNoContent)
			return
		}
	}
