### Title
Magic operator QR codes (`reset_wifi_credentials`, `reset_mirror_calibration`) execute before backend operator authentication, letting any unprivileged bystander halt the Orb - (File: src/plans/mod.rs)

### Summary
The Orb accepts special "magic" operator QR codes (`magic_action:reset_wifi_credentials`, `magic_action:reset_mirror_calibration`) that trigger privileged, disruptive hardware/network actions. These actions are dispatched by `handle_magic_operator_qr_code` *before* the scanned QR code is verified against the backend as belonging to a legitimate operator via `verify_operator_qr_code`. This mirrors the reported bug class where a critical, protocol-halting action was gated by an insufficiently strong permission check (`onlyStrategist`) instead of the highest trust tier (`onlyGovernance`): here the equivalent of "governance-level" verification (backend operator authentication) is completely skipped for a functionally equivalent, disruption-causing action.

### Finding Description
`qr_scan::operator::Data::try_parse` locally regex-matches the string `magic_action:reset_wifi_credentials` or `magic_action:reset_mirror_calibration` with no cryptographic signature, secret, or backend check required: [1](#0-0) 

In both `scan_initial_qr_codes` and `scan_remaining_qr_codes`, the flow is:
1. `scan_operator_qr_code` reads and parses the raw QR contents (any camera-visible text/QR image — fully attacker-controlled, no operator credential required).
2. `handle_magic_operator_qr_code` is called with the parsed data **immediately**, and for the `MagicResetWifi` / `MagicResetMirror` variants it performs the action right away.
3. `verify_operator_qr_code` (the actual backend authentication check that confirms this is a legitimate registered operator) is only invoked afterward, and only for the `Normal` variant. [2](#0-1) [3](#0-2) [4](#0-3) 

The actions themselves are privileged, hardware-affecting operations: [5](#0-4) 

`reset_wifi_and_ensure_network` calls `network::reset()` which discards the Orb's WiFi configuration and forces reconnection, and `reset_mirror_calibration` wipes the stored mirror calibration and forces a live recalibration cycle. Neither of these requires any proof that the QR code presenter is an authorized operator — the backend `operator_status::request` call (the equivalent of "governance-level" authorization in the analog bug) is entirely bypassed for these two code paths.

### Impact Explanation
Any unprivileged person within camera range of an idle Orb (e.g., in a public kiosk deployment, exactly the threat model where operator QR scanning happens continuously while waiting for a signup) can print/display a QR code encoding `magic_action:reset_wifi_credentials` and force the device to drop its network configuration, or `magic_action:reset_mirror_calibration` to force a hardware recalibration cycle. Repeated or well-timed triggering causes denial of service: loss of connectivity (blocking all future signups until a technician re-provisions WiFi) or repeated mirror recalibration cycles that disrupt/halt normal operator/signup flow — directly analogous to the reported protocol-halting impact, except here caused by a fully unauthenticated, unprivileged actor instead of even a semi-trusted role.

### Likelihood Explanation
High. No secret, credential, or backend round-trip is needed — a printed QR code is sufficient, and the vulnerable code path (`scan_operator_qr_code` → `handle_magic_operator_qr_code`) runs during normal idle QR scanning, which is exposed to the public in kiosk/self-serve deployments and to anyone who can approach an operator-attended Orb before the operator scans their real badge.

### Recommendation
Move the magic-action dispatch after backend authentication, or require validating the magic QR code against the backend (e.g., extend `verify_operator_qr_code`/`operator_status::request` to also authorize magic actions) before calling `reset_wifi_and_ensure_network` / `reset_mirror_calibration`. At minimum, gate these actions behind the same operator-verification check used for `Data::Normal`, mirroring the recommended fix in the original report (elevate the check to the highest verified trust tier rather than none/lowest).

### Proof of Concept
1. Generate a QR code containing the literal text `magic_action:reset_wifi_credentials` (matches `MAGIC_QR_CODE` regex in `src/plans/qr_scan/operator.rs`).
2. Present it to an idle Orb during operator QR-code scanning (`scan_operator_qr_code` in `src/plans/mod.rs`).
3. Observe that `handle_magic_operator_qr_code` immediately invokes `reset_wifi_and_ensure_network` — before any call to `verify_operator_qr_code`/backend `operator_status::request` — dropping the Orb's WiFi and forcing reconnection without any operator authentication having occurred.
4. Repeat with `magic_action:reset_mirror_calibration` to force an unauthenticated hardware recalibration cycle via `reset_mirror_calibration`.

        None

    /// Resets the mirror calibration.
    pub async fn reset_mirror_calibration(&self, orb: &mut Orb) -> Result<()> {
        let calibration: Calibration = (&*orb.config.lock().await).into();
        calibration.store(CALIBRATION_FILE_PATH).await?;
        orb.enable_mirror()?;
        orb.recalibrate(calibration).await?;
        orb.disable_mirror();
        Ok(())
    }

    /// Resets the network and requests a new one.
    pub async fn reset_wifi_and_ensure_network(&self, orb: &mut Orb) -> Result<()> {
        network::reset().await?;
        wifi::Plan.ensure_network_connection(orb).await?;
        orb.reset_rgb_camera().await?;
        Ok(())
    }

    async fn handle_magic_operator_qr_code(
        &self,
        orb: &mut Orb,
        qr_code: qr_scan::operator::Data,
    ) -> Result<Option<qr_scan::user::Data>> {
        match qr_code {
            qr_scan::operator::Data::Normal(qr_code) => {
                tracing::info!("Operator QR-code detected: {qr_code:?}");
                Ok(Some(qr_code))
            }
            qr_scan::operator::Data::MagicResetMirror => {
                tracing::info!("Magic QR-code detected: Reset Mirror");
                dd_incr!("main.count.signup.during.general.magic_qr.reset_mirror");
                let result = self.reset_mirror_calibration(orb).await;
                if let Err(err) = &result {
                    tracing::error!("Failed to reset mirror calibration: {err}");
                }
                orb.ui.magic_qr_action_completed(result.is_ok());
                Ok(None)
            }
            qr_scan::operator::Data::MagicResetWifi => {
                tracing::info!("Magic QR-code detected: Reset Wi-Fi");
                dd_incr!("main.count.signup.during.general.magic_qr.reset_wifi");
                let result = self.reset_wifi_and_ensure_network(orb).await;
                if let Err(err) = &result {
                    tracing::error!("Failed to reset wifi: {err}");
                }
                orb.ui.magic_qr_action_completed(result.is_ok());
                Ok(None)
            }
        }
    }
