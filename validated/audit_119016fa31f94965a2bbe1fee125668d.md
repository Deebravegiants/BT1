## Analysis

The auction report's bug class is: **a time-bounded window that is meant to eventually close is instead continuously pushed forward by repeated unprivileged actions, because the extension logic checks only "time since last action" and never enforces an absolute cap from the original start.**

The closest reachable analog in `AYontt/chainlink--012` is the local-auth session lifetime: `SessionTimeout` (15m idle timeout) and `SessionReaperExpiration` (240h — documented as "how long an API session lasts before expiring and requiring a new login") are supposed to bound how long a session can remain valid. In practice, the reaper only evaluates `last_used`, and `last_used` is refreshed on **every** authenticated request, so an actively-used session never reaches the reaper's deletion threshold — there is no check against `created_at`/session-start time.

### Title
Session lifetime can be extended indefinitely via `last_used` refresh, defeating the documented mandatory re-authentication cap - ([File: core/sessions/localauth/orm.go])

### Summary
`WebServer.SessionReaperExpiration` is documented as the point at which an API session "expires and requires a new login," implying an absolute lifetime cap independent of activity [1](#0-0) . However, `AuthorizedUserWithSession` validates and refreshes the session purely against `last_used`, and every successful authenticated request calls `updateSessionLastUsed`, resetting the clock [2](#0-1) . The reaper that is supposed to enforce the hard cap only deletes rows where `last_used < before`, and never compares against the session's `created_at` [3](#0-2) .

### Finding Description
`findValidSession` treats a session as valid as long as `last_used + sessionDuration >= now()` [4](#0-3) . `AuthorizedUserWithSession` then unconditionally bumps `last_used = now()` on every successful call [5](#0-4) , exactly mirroring the auction contract's pattern of extending its own deadline on every "bid" placed near expiry, with no cap on how many times this can happen.

The `sessionReaper.Work` function is the intended backstop that should force re-authentication after `SessionReaperExpiration` (240h by default) has elapsed, per its own documentation [6](#0-5) . But its deletion query is solely based on `last_used`: `DELETE FROM sessions WHERE last_used < $1` [7](#0-6) . It never checks `created_at`, so as long as the session cookie/token is used at least once per `SessionTimeout` window, it is refreshed and the reaper's threshold check against `last_used` is perpetually defeated — the session lives forever, exactly like the auction end being pushed back by 15 minutes on every qualifying bid with no cap.

### Impact Explanation
This undermines an explicitly documented security control ("requiring a new login" after `SessionReaperExpiration`). If a session cookie is stolen (e.g. XSS, log leakage, shared machine) and the attacker (or a background script) issues periodic requests, the compromised session never expires and is never forced to re-authenticate, regardless of how much wall-clock time passes. This is a Medium-severity logic flaw analogous to the reported unbounded-postponement bug: an unprivileged holder of a valid token can indefinitely extend a resource's validity window that was designed to have a hard upper bound.

### Likelihood Explanation
Exploitation only requires possession of a valid session ID and the ability to issue a request more often than every `SessionTimeout` interval (default 15 minutes) — trivially automatable, and requires no special privilege beyond what is needed to use the session in the first place.

### Recommendation
Enforce an absolute session lifetime cap independent of activity: track `created_at` and reject/reap sessions where `now() - created_at > SessionReaperExpiration`, in addition to (not instead of) the idle-based `SessionTimeout` check, so continuous activity cannot indefinitely postpone forced re-authentication. Apply the same fix consistently across `localauth`, `ldapauth`, and `oidcauth` reapers, all of which follow the same `last_used`-only pattern [8](#0-7) .

### Proof of Concept
1. Log in via `POST /sessions` to obtain a session cookie [9](#0-8) .
2. Every ~14 minutes (under the default 15m `SessionTimeout`), issue any authenticated API request using that session cookie.
3. Each such request calls `AuthorizedUserWithSession` → `updateSessionLastUsed`, resetting `last_used` [5](#0-4) .
4. Wait beyond the documented `SessionReaperExpiration` (240h/10 days) while continuing step 2 — the session is never reaped because `deleteStaleSessions` only checks `last_used` [7](#0-6) , which never grows stale under this polling.
5. The session remains valid indefinitely, contradicting the documented guarantee that it "expires...requiring a new login."

// findValidSession finds an unexpired session by its ID and returns the associated email.
func (o *orm) findValidSession(ctx context.Context, sessionID string) (email string, err error) {
	if err := o.ds.GetContext(ctx, &email, "SELECT email FROM sessions WHERE id = $1 AND last_used + $2 >= now() FOR UPDATE", sessionID, o.sessionDuration); err != nil {
		o.lggr.Infof("query result: %v", email)
		return email, pkgerrors.Wrap(err, "no matching user for provided session token")
	}
	return email, nil
}

// updateSessionLastUsed updates a session by its ID and sets the LastUsed field to now().
func (o *orm) updateSessionLastUsed(ctx context.Context, sessionID string) error {
	_, err := o.ds.ExecContext(ctx, "UPDATE sessions SET last_used = now() WHERE id = $1", sessionID)
	return err
}

func (o *orm) AuthorizedUserWithSession(ctx context.Context, sessionID string) (user sessions.User, err error) {
	if len(sessionID) == 0 {
		return sessions.User{}, sessions.ErrEmptySessionID
	}

	email, err := o.findValidSession(ctx, sessionID)
	if err != nil {
		return sessions.User{}, sessions.ErrUserSessionExpired
	}

	user, err = o.findUser(ctx, email)
	if err != nil {
		return sessions.User{}, sessions.ErrUserSessionExpired
	}

	if err := o.updateSessionLastUsed(ctx, sessionID); err != nil {
		return sessions.User{}, err
	}

	return user, nil
}

	session := sessions.Default(c)
	var sr clsessions.SessionRequest
	if err := c.ShouldBindJSON(&sr); err != nil {
		jsonAPIError(c, http.StatusBadRequest, fmt.Errorf("error binding json %w", err))
		return
	}

	// Does this user have 2FA enabled?
	userWebAuthnTokens, err := sc.App.AuthenticationProvider().GetUserWebAuthn(ctx, sr.Email)

		sc.App.GetLogger().Errorf("Error loading user WebAuthn data: %s", err)
		jsonAPIError(c, http.StatusInternalServerError, errors.New("internal Server Error"))
		return
	}

	// If the user has registered MFA tokens, then populate our session store and context
	// required for successful WebAuthn authentication
	if len(userWebAuthnTokens) > 0 {
		sr.SessionStore = sc.sessions
		sr.WebAuthnConfig = sc.App.GetWebAuthnConfiguration()
	}

	sid, err := sc.App.AuthenticationProvider().CreateSession(ctx, sr)

		jsonAPIError(c, http.StatusUnauthorized, err)
		return
	}

		return
	}

	jsonAPIResponse(c, Session{Authenticated: true}, "session")
