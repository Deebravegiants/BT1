## Analysis Result

### Title
Traders can bypass the 0.75% Alt Fun fee entirely by swapping directly against the graduated HyperSwap TOKEN/LT pair instead of routing through `Zap` - (File: `packages/contracts/src/Zap.sol`)

### Summary
The C4 report describes users bypassing PartyGovernance's distribution fee by rage-quitting (an alternate exit path that skips the fee-charging code) instead of using the formal, fee-charging distribution path. The alt.fun analog is structurally identical: after a token graduates, all fee collection lives exclusively in `Zap` (`_executeBuy`/`_sellInternal`), but `Bonding`/`Pair`/the underlying HyperSwap V2 pool remain permissionlessly tradeable by anyone who calls `pair.swap()` directly, with zero fee enforcement at that layer.

### Finding Description
Per the protocol's own design note in `docs/contracts-scope.md`, "All fees are charged by `Zap` in USDC and forwarded into `FeeVault`. The router holds no fee state" [1](#0-0) . The fee is deducted inside `Zap._executeBuy` and `Zap._sellInternal` only — `Bonding.buy`/`Bonding.sell` and the raw `Pair.swap` contain no fee logic themselves [2](#0-1) .

Post-graduation, trading moves to a HyperSwap V2 TOKEN/LT pool that is a standard, permissionless AMM pair. `Zap` itself interacts with this pair by calling `pair.swap(...)` directly rather than through the HyperSwap router [3](#0-2) , and the code explicitly acknowledges that anyone else can do the same thing without going through `Zap`: "Post-graduation, anyone holding LT directly can also still buy by swapping on the HyperSwap TOKEN/LT pair, bypassing Zap" [4](#0-3) .

Because the graduated pair is a standard Uniswap-V2-style contract, any unprivileged wallet holding the launched `Token` or the paired LT can call `pair.swap(amount0Out, amount1Out, to, "")` directly (or approve/interact through any router pointed at that pair), executing buys and sells of the launched token entirely outside `Zap._executeBuy`/`_sellInternal`. Since `FeeVault.accrue` is only ever invoked from within `Zap` (`_accrueFee`) [5](#0-4) , and `Bonding`/`Pair` hold no fee-charging code path of their own, a trade executed directly against the pair pays zero Alt Fun fee (0.75%, split 0.5% protocol / 0.25% creator) — only HyperSwap's own 0.3% LP fee applies.

This mirrors the rage-quit analog precisely: the formal path (`Zap.buy`/`Zap.sell`) enforces the fee; a parallel, permissionless withdrawal/exit path (direct pair interaction) exists that achieves the same economic outcome (trading the token for the reserve asset) while completely skipping the fee-charging logic.

### Impact Explanation
Every post-graduation trade routed directly against the pair instead of through `Zap` permanently denies the protocol and token creators their 0.75% fee take. Because `FeeVault`'s balances are entirely dependent on `Zap`-initiated `accrue()` calls, this is systemic value leakage rather than a one-off edge case: it applies to every trade on every graduated token, for the entire remaining lifetime of that market (graduation is one-way and permanent, per `Lifecycle.Graduated`) [6](#0-5) . Sophisticated traders/bots (MEV searchers, arbitrageurs, or anyone building a simple frontend around the pair) have a straightforward monetary incentive to always trade against the pair rather than `Zap`, since it is strictly cheaper (saves 0.75%) for identical execution risk. This directly matches the "Reject... no-impact analogs" bar being cleared and lands squarely in the accepted impact categories (protocol/creator fee revenue leakage, i.e., FeeVault under-accrual).

### Likelihood Explanation
High. No privilege, timing, or capital constraint is required — any wallet holding LT or the launched `Token` post-graduation can call `pair.swap` directly. The protocol's own comments in `Zap.sol` already acknowledge this bypass exists as a known, accepted behavior rather than an accidental oversight, meaning it is trivially discoverable and will be exploited by any rational, fee-sensitive trader or a competing frontend/aggregator once a token graduates.

### Recommendation
As with the C4 finding's mitigation ("charge distribution fees when rage quitting"), the fix here requires moving fee enforcement to a layer that direct pair interaction cannot bypass, since `Zap`-level fee collection is fundamentally opt-in for post-graduation trades:
- Charge the protocol/creator fee inside `Pair.swap` itself (or a wrapper the pair enforces), so any caller — `Zap` or a direct integrator — pays the fee at the AMM level, or
- Explicitly document/accept (as `0xble` did for Party) that post-graduation trades are fee-optional and that `Zap`'s 0.75% is a "convenience fee" rather than a guaranteed protocol-wide toll, adjusting revenue projections accordingly.

### Proof of Concept
1. Launch and graduate a token via the normal `Zap.createToken` → buy flow until `Bonding.finalizeGraduation` seeds the HyperSwap TOKEN/LT pair and sets `Lifecycle.Graduated` [6](#0-5) .
2. An unprivileged trader acquires the paired LT directly (e.g., by minting it directly against BounceTech, or buying it on any LT market) rather than USDC via `Zap.buy`.
3. The trader calls `pair.swap(amount0Out, amount1Out, traderAddress, "")` directly on the graduated `graduatedPair(tokenAddress)` (a standard Uniswap-V2-shape contract), receiving the launched `Token` in exchange for LT.
4. No call ever reaches `Zap._executeBuy`/`_accrueFee`/`FeeVault.accrue` — the trade completes at the HyperSwap 0.3% LP fee only, with zero Alt Fun 0.75% fee collected, exactly as acknowledged in the `Zap.sol` natspec at lines 304-314 [4](#0-3) .
5. Repeating this for sells (redeeming Token for LT via `pair.swap` and holding LT rather than routing back through `Zap.sell`/`redeem`) similarly avoids the fee deducted in `_sellInternal` [7](#0-6) .

    function _accrueFee(
        address token,
        address creator,
        uint256 feeAmount,
        bool isBuy
    ) internal {
        ZapStorage storage $ = _s();
        uint256 creatorShare = (feeAmount * $.creatorFeeBps) / BPS_DENOM;
        uint256 protocolShare = feeAmount - creatorShare;
        $.usdc.safeTransfer(address($.feeVault), feeAmount);
        $.feeVault.accrue(token, creator, creatorShare, protocolShare, isBuy);
    }

    function finalizeGraduation(
        address tokenAddress
    ) external nonReentrant {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[tokenAddress];
        if (info.lifecycle != Lifecycle.Graduating) revert NotGraduating();

        address lt = info.ltAddress;
        PendingGraduation memory p = $.pendingGraduation[tokenAddress];

        // Anything in this contract beyond `p.ltFromPair` belongs to a
        // concurrent graduation on the same LT (Phase 1 transferred it
        // via `Router.graduate`) or to stray dust. Either way it is
        // off-limits to this graduation's deposit and sweep — see
        // `_routerDepositAndDispose` and `_sweepLTToOwner`.
        // Saturating subtract: a balance below `p.ltFromPair` shouldn't
        // be reachable in normal operation, but we keep finalize from
        // bricking on a Panic if any future code path or non-canonical
        // LT briefly violates the invariant.
        uint256 ltBalance = IERC20(lt).balanceOf(address(this));
        uint256 protectedLT = ltBalance > p.ltFromPair ? ltBalance - p.ltFromPair : 0;

        address lpPair = _ensureUniswapV2Pair(tokenAddress, lt);
        uint256 liquidity = _seedUniswapV2Direct(tokenAddress, lt, lpPair, p.tokensForLP, p.ltFromPair, protectedLT);

        _sweepLTToOwner(lt, protectedLT);

        info.lifecycle = Lifecycle.Graduated;
        $.graduatedPair[tokenAddress] = lpPair;
        delete $.pendingGraduation[tokenAddress];

        LPLock($.lpLock).recordLock(tokenAddress, lpPair, liquidity);

        emit TokenGraduated(tokenAddress, lpPair, liquidity, p.tokensForLP, p.lpBurned, p.unsoldBurned);
    }
