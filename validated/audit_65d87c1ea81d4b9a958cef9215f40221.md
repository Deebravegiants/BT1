### Title
Presentation-attack acceptance in `handle_rgb_net` due to geometry-only accept criterion and disabled fraud/liveness checks - (File: `src/plans/biometric_capture/mirror_sweep.rs`, `src/plans/biometric_capture/mod.rs`, `src/plans/mod.rs`)

### Summary
`mirror_sweep::Plan::handle_rgb_net` delegates directly to `biometric_capture::Plan::handle_rgb_net`, whose only acceptance test on an RGB-Net prediction is `prediction.bbox.coordinates.is_correct()` — a bounding-box geometry sanity check, not a liveness signal. Downstream, the plan-level fraud/liveness gate `detect_fraud` in `src/plans/mod.rs` is hard-coded to return `false` (comment: "FOSS: WE HAVE DELETED ALL FRAUD CHECKS"), and `FraudChecks::run` in `src/plans/fraud_check.rs` returns an empty `Report {}`.

### Finding Description
`mirror_sweep::Plan::handle_rgb_net` forwards every RGB-Net output unchanged to the base capture plan: [1](#0-0) 

The base implementation only stores a frame as a valid capture slot if the predicted face bbox passes a coordinate-correctness check — no texture, depth, pupillary response, or temporal-consistency liveness signal is required: [2](#0-1) 

This captured frame flows into `biometric_pipeline::Plan` and then into fraud detection in `src/plans/mod.rs`. However, `detect_fraud` — the single choke point meant to reject artifacts/spoofs after the pipeline runs — is stubbed to always return `false`: [3](#0-2) 

And the standalone `FraudChecks` plan used elsewhere is likewise a no-op, always returning an empty report: [4](#0-3) 

Because the accept criterion in `handle_rgb_net` is purely geometric (bbox shape/position), and the only downstream fraud/liveness gate is disabled in this codebase, a physical artifact (high-resolution print or IR-matched display) that produces a correctly-shaped face bounding box and passing IR iris score (`IRIS_SCORE_MIN`, brightness range in `handle_ir_net`, also just signal-quality thresholds) will be accepted as a live subject all the way through to enrollment.

### Impact Explanation
This allows enrollment or verification of a non-live subject using a printed/displayed artifact, i.e., identity spoofing / biometric liveness bypass, matching the Worldcoin/Orb bounty impact category of "enrollment/verification of a non-live subject."

### Likelihood Explanation
Preconditions are minimal and fully attacker-controlled: physical presentation of an artifact in front of Orb cameras during a self-initiated signup session, no privileged access needed. Feasibility depends on producing an artifact whose RGB bbox estimate is geometrically valid and whose IR reflectance/sharpness passes `IRIS_SCORE_MIN`/brightness thresholds — reproducible with commodity print/display + IR filtering, and repeatable across attempts since the check is purely threshold-based and stateless per frame.

### Recommendation
Reintroduce an actual liveness/fraud check as a gating condition before accepting `handle_rgb_net`/`handle_ir_net` captures or before enrollment: implement `detect_fraud` and `FraudChecks::run` with real anti-spoofing signals (e.g., pupil dynamics, specular reflection consistency, depth/thermal cross-checks, or an ML-based presentation-attack-detection model) rather than stubs that unconditionally return no-fraud.

### Proof of Concept
Integration test plan:
1. Construct a synthetic `rgb_net::Output::Estimate` with a `prediction.bbox.coordinates` that satisfies `is_correct()` and IR frame estimate with `score >= IRIS_SCORE_MIN` and mean within `IRIS_BRIGHTNESS_RANGE`, simulating an artifact-derived frame (no liveness signal present, e.g., zero motion/pupil response encoded).
2. Feed these through `biometric_capture::Plan::handle_rgb_net`/`handle_ir_net` (as invoked via `mirror_sweep::Plan::handle_rgb_net`) and assert the frame is stored into `left_rgb`/`right_rgb`/`left_ir`/`right_ir` slots (`Some(FrameInfo...)`).
3. Continue the pipeline through `biometric_pipeline::Plan::run` and `Plan::detect_fraud` in `src/plans/mod.rs`; assert `detect_fraud` always returns `Ok(false)` regardless of pipeline content, confirming no rejection occurs.
4. Expected (failing) assertion for security: `detect_fraud` or `handle_rgb_net`/`handle_ir_net` should reject frames lacking a liveness signal; current code accepts them, demonstrating the bypass.

    fn handle_rgb_net(
        &mut self,
        _orb: &mut Orb,
        output: port::Output<rgb_net::Model>,
        frame: Option<camera::rgb::Frame>,
    ) -> Result<BrokerFlow> {
        if let rgb_net::Output::Estimate(estimate) = output.value {
            if let Some(prediction) = estimate.primary() {
                if prediction.bbox.coordinates.is_correct() {
                    let frame = frame.expect("frame must be set for an estimate output");
                    let slot =
                        if self.target_left_eye { &mut self.left_rgb } else { &mut self.right_rgb };
                    *slot = Some(FrameInfoRgb::new(estimate, frame));
                }
            }
        }
        Ok(BrokerFlow::Continue)
    }
