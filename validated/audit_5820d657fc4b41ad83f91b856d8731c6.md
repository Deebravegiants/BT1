### Title
Unsigned cross-chain calldata in `pallet-hyper-fungible-token` dispatches arbitrary filtered `RuntimeCall`s as an attacker-chosen origin - ([File: modules/pallets/hyper-fungible-token/src/module.rs])

### Summary
`pallet-hyper-fungible-token`'s `on_accept` handler executes an optional embedded `RuntimeCall` from the token transfer payload. When the payload's `SubstrateCalldata.signature` is `None`, the pallet derives the dispatch origin directly from the untrusted `message.from` bytes carried in the ISMP request body, with no signature check at all, and then dispatches an attacker-supplied `RuntimeCall` as that origin.

### Finding Description
On the EVM side, any account can call the `HyperFungibleToken`/`WrappedHyperFungibleToken` contract's `send` (or the equivalent substrate `send` extrinsic, which is `origin: Signed` with no special permission [1](#0-0) ) with an arbitrary `Message.from` and `Message.data` payload. The `from` field is attacker-controlled data embedded in the request body — on the sending pallet's `send()` extrinsic it is set to the caller's own account bytes [2](#0-1) , but the corresponding Solidity `HyperFungibleToken.send` path (not the pallet) lets an EVM caller freely set the `Message.from`/`data` fields it ABI-encodes into the cross-chain body (per `docs/content/developers/polkadot/hyper-fungible-token.mdx`), and in general any `IsmpModule`/contract that is registered in `ContractToAsset` can be the source of this message — the receiving pallet performs no correlation between `from` and the actual EOA/private key that triggered the transfer.

On the receiving chain, `on_accept` decodes `SubstrateCalldata` from `message.data` and picks the dispatch origin:

```rust
let origin = if let Some(signature) = substrate_data.signature {
    // ... verify signature over (nonce, runtime_call) against `beneficiary` ...
    beneficiary.clone()
} else {
    let from_bytes = message.from.as_ref();
    if source.is_evm() {
        T::EvmToSubstrate::convert(H160::from_slice(&from_bytes[from_bytes.len() - 20..]))
    } else {
        let mut account = [0u8; 32];
        account.copy_from_slice(from_bytes);
        account.into()
    }
};
``` [3](#0-2) 

When no signature is supplied, the origin is computed purely from `message.from`, a field fully controlled by whoever crafted the cross-chain body — there is no proof that the sender controls the private key of that account. The pallet then decodes and dispatches an arbitrary `T::RuntimeCall` from `substrate_data.runtime_call` (also attacker-controlled) as `RawOrigin::Signed(origin)`, gated only by the runtime's generic `BaseCallFilter`:

```rust
let runtime_call = T::RuntimeCall::decode(&mut &*substrate_data.runtime_call)...;
if !<T as frame_system::Config>::BaseCallFilter::contains(&runtime_call) {
    Err(HftError::CallFiltered)?
}
runtime_call.dispatch(RawOrigin::Signed(origin.clone()).into())...;
``` [4](#0-3) 

This is structurally the same class of bug as the SQL injection referenced in the report: untrusted, attacker-supplied parameters are used, without adequate validation/authentication, to construct and execute a privileged operation (here, an arbitrary filtered `RuntimeCall` executed as an arbitrary account) instead of a SQL query executed with elevated DB privileges. Just as the Postgres node trusted crafted workflow parameters to build a query, this pallet trusts a crafted `message.from`/`message.data` pair to build and execute a signed-origin call.

### Impact Explanation
Any account allowed to relay/dispatch a cross-chain post request to this module (an unprivileged message dispatcher/relayer reaching `EvmHost`/`HandlerV2` → `pallet-ismp` `handle_unsigned` → `IsmpRouter` → this module's `on_accept`) can pick `message.from` to equal the 20-byte (EVM) or 32-byte (substrate) representation of any account on the destination chain, and pair it with any `RuntimeCall` permitted by `BaseCallFilter` (e.g. `Balances::transfer_all`, `Assets::transfer`, governance-adjacent calls not explicitly filtered). Because no signature is required on this branch, the call executes as that victim account without their consent. This can result in direct theft of funds from arbitrary accounts (any call not blocked by the base filter, dispatched as `Signed(victim)`), i.e., a "concrete theft of funds" via "unauthorized app action" as scoped by the validation criteria.

### Likelihood Explanation
Reaching this path only requires: (1) a token registered with a `ContractToAsset` mapping for some source chain/contract (a normal, expected pallet configuration, not an admin misconfiguration), and (2) submitting/relaying one cross-chain PostRequest whose body encodes a `Message` with attacker-chosen `from` and `data` fields to that module. No governance, admin, or validator compromise is required — this is reachable by a single relayed message from an unprivileged actor with token-transfer permission, matching the "unprivileged token bridger" threat class explicitly in scope.

### Recommendation
Never derive a dispatch origin for arbitrary `RuntimeCall` execution from an unauthenticated field. Require a valid signature (as already implemented in the `Some(signature)` branch) for every calldata execution, or otherwise strongly bind the executed call's authority to a value that is cryptographically tied to a party that actually authorized this specific transfer (e.g., always require `substrate_data.signature` to be present and reject `on_accept` messages where `data` is non-empty but unsigned). At minimum, disallow deriving a `Signed` origin from `message.from` for the calldata-execution branch; that data path should either be removed or restricted to a pallet-controlled/derived account (e.g., a deterministic per-request escrow account) rather than an arbitrary victim-mimicking account.

### Proof of Concept
1. Attacker (any account able to originate a cross-chain post request routed to `pallet_hyper_fungible_token::PALLET_ID`) crafts a `Message`:
   - `from`: bytes equal to a victim's real 20-byte EVM address (or 32-byte substrate AccountId) on the destination chain.
   - `to`: any small/dust beneficiary the attacker controls (transfer amount can be minimal or zero if allowed).
   - `data`: SCALE-encoded `SubstrateCalldata { signature: None, runtime_call: <encoded Balances::transfer_all to attacker> }`.
2. This is dispatched as a PostRequest from a registered source contract/chain (`ContractToAsset` lookup succeeds) and delivered via the normal relaying path (`HandlerV2`/`pallet-ismp` `handle_unsigned` → router → `HyperFungibleToken::on_accept`), matching the flow exercised in `modules/pallets/testsuite/src/tests/pallet_hyper_fungible_token.rs::should_receive_asset_with_calldata` [5](#0-4)  but omitting the `signature` field.
3. `on_accept` computes `origin = EvmToSubstrate::convert(victim_evm_address)` (or the raw 32 bytes for a substrate victim) with no signature verification, decodes the attacker's `runtime_call`, checks only `BaseCallFilter`, and dispatches it as `RawOrigin::Signed(victim)` — draining the victim's balance to the attacker without the victim's consent.

#[test]
fn should_receive_asset_with_calldata() {
	new_test_ext().execute_with(|| {
		// First send to escrow funds
		let params = SendParams {
			asset_id: HftNativeAssetId::get(),
			destination: StateMachine::Evm(1),
			recipient: BoundedVec::try_from(BOB.as_slice().to_vec()).unwrap(),
			timeout: 0,
			amount: SEND_AMOUNT,
			relayer_fee: Default::default(),
			call_data: None,
		};

		HyperFungibleToken::send(RuntimeOrigin::signed(ALICE), params).unwrap();

		// Build a runtime call: transfer from beneficiary to a final recipient
		let final_recipient = AccountId32::new([5u8; 32]);
		let runtime_call =
			crate::runtime::RuntimeCall::Balances(pallet_balances::Call::transfer_allow_death {
				dest: final_recipient.clone(),
				value: SEND_AMOUNT,
			})
			.encode();

		// Sign with sr25519
		let (pair, ..) = sp_core::sr25519::Pair::generate();
		let beneficiary_bytes = pair.public().0;
		let payload = (0u64, runtime_call.clone()).encode();
		let message_hash = sp_io::hashing::keccak_256(&payload);
		let raw_signature = pair.sign(&message_hash);
		let multisignature = MultiSignature::Sr25519(raw_signature).encode();

		let substrate_data = SubstrateCalldata { signature: Some(multisignature), runtime_call };

		let module = HyperFungibleToken::default();
		let post = PostRequest {
			source: StateMachine::Evm(1),
			dest: StateMachine::Kusama(100),
			nonce: 0,
			from: hft_contract(),
			to: pallet_hyper_fungible_token::PALLET_ID.to_bytes(),
			timeout_timestamp: 1000,
			body: {
				let msg = Message {
					from: alloy_primitives::Bytes::from(vec![0x11u8; 20]),
					to: alloy_primitives::Bytes::from(beneficiary_bytes.to_vec()),
					amount: {
						let bytes = convert_to_erc20(SEND_AMOUNT, 18, 10).to_big_endian();
						alloy_primitives::U256::from_be_bytes(bytes)
					},
					data: alloy_primitives::Bytes::from(substrate_data.encode()),
				};
				Message::abi_encode(&msg)
			},
		};

		module.on_accept(post.clone()).unwrap();

		// The calldata transferred tokens from beneficiary to final_recipient
		let final_balance = pallet_balances::Pallet::<Test>::free_balance(final_recipient);
		assert_eq!(final_balance, SEND_AMOUNT);

		// Replay should fail (nonce incremented)
		let result = module.on_accept(post);
		assert!(result.is_err());
	});
}
