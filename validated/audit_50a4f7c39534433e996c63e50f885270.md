Audit Report

## Title
Staking-async reward payout permanently lost on transfer failure due to claim status being finalized before the transfer - (File: substrate/frame/staking-async/src/pallet/impls.rs)

## Summary
In `pallet-staking-async`, `do_payout_stakers_by_page` calls `Eras::<T>::set_rewards_as_claimed(era, &stash, page)` before performing the actual reward transfers via `payout_from_provider`/`make_payout_from_provider`. If a per-account transfer fails (e.g., because the resulting destination balance would fall below the Existential Deposit), the error is only logged and the function returns `None`, permanently forfeiting that reward with no retry path since the page is already marked claimed. [1](#0-0) 

## Finding Description
`do_payout_stakers_by_page` finalizes claim status early: `Eras::<T>::set_rewards_as_claimed(era, &stash, page)` executes right after the "already claimed" check and well before any transfer is attempted. [2](#0-1) 

Subsequently, `payout_from_provider` iterates the validator and each nominator in `exposure.others()`, computing `nominator_reward` as `Perbill::from_rational(nominator.value, total_nominator_stake).mul_floor(total_nominator_payout)` — an amount that can be arbitrarily small for low-stake nominators. [3](#0-2) 

`make_payout_from_provider` performs the transfer via `T::Currency::transfer(&staker_rewards_pot, &payout_account, amount, Preservation::Expendable)`. If this fails, the error is only logged, and the function returns `None` with no retry or alternate credit path. [4](#0-3) 

The underlying deposit check in `pallet-balances`' `can_deposit` returns `DepositConsequence::BelowMinimum` whenever a deposit would leave a destination account's free balance below `T::ExistentialDeposit`, causing the transfer to fail for any account with zero/near-zero existing balance receiving a sub-ED reward. [5](#0-4) 

I confirmed this `can_deposit` check is invoked from the fungibles `transfer` default implementation (`Self::can_deposit(...).into_result()?` prior to any balance mutation), matching the failure semantics described in the report. [6](#0-5) 

One caveat: I was unable to fully verify within the available iterations whether `T::Currency` in the staking-async pallet config resolves to the singular `fungible::Mutate` trait (in `substrate/frame/support/src/traits/tokens/fungible/regular.rs`) or the plural `fungibles::Mutate` trait cited in the report, and whether there is a blanket impl bridging balances' `fungible::Inspect`/`Mutate` implementation to the cited `can_deposit`/`transfer` code path. However, `pallet-balances` implements the `fungible` (singular) trait directly via `impl_fungible.rs`, including its own `can_deposit` with identical `BelowMinimum` semantics, and the singular `fungible::Mutate::transfer` default implementation performs the analogous "check-then-move" pattern found in the plural trait file. This does not change the conclusion: the same ED-driven transfer failure applies regardless of which trait variant is used.

The core defect — marking claim state before performing transfers, with silent forfeiture on transfer failure — is verified directly in the staking-async code with no guard preventing loss.

## Impact Explanation
A legitimate, unprivileged nominator's reward for a page/era can be permanently and unrecoverably lost: it is not returned to the reward pot, not retried, and not credited elsewhere, and the page can never be reprocessed because `is_rewards_claimed` will return true for it. This is a direct loss-of-funds bug affecting the correctness of the staking reward accounting.

## Likelihood Explanation
This is realistically triggerable without any privileged role: any pool with a nominator holding a very small stake relative to total page exposure, or a fresh/dust nominator account with a zero balance, will receive a reward share below the Existential Deposit whenever the proportional payout is small — a routine occurrence in pools with many nominators or highly skewed stake distributions.

## Recommendation
Perform all transfers before finalizing the page's claimed status, or on transfer failure route the failed amount to a recoverable location (e.g., re-credit the reward pot or a per-account "pending rewards" storage item) instead of only logging and discarding it, so the payout can be retried or reclaimed.

## Proof of Concept
1. Set up a validator with two nominators for a given era/page: nominator A with a large stake, nominator B with a very small stake and zero existing free balance.
2. Fund the era's reward pot as usual via `ErasSumWeightedPoints`/incentive budget.
3. Call `payout_stakers(origin, validator_stash, era)`. Inside `do_payout_stakers_by_page`, `Eras::<T>::set_rewards_as_claimed(era, &stash, page)` executes (`substrate/frame/staking-async/src/pallet/impls.rs:386`) before any transfer.
4. `payout_from_provider` computes nominator B's `nominator_reward` below `ExistentialDeposit` (`substrate/frame/staking-async/src/pallet/impls.rs:500-501`).
5. `make_payout_from_provider`'s `T::Currency::transfer(...)` fails due to `can_deposit` returning `BelowMinimum` (`substrate/frame/balances/src/impl_fungible.rs:90`); the error is logged and `None` returned (`substrate/frame/staking-async/src/pallet/impls.rs:602-616`).
6. No `Rewarded` event is emitted for nominator B, and no funds are credited anywhere.
7. Because the page was already marked claimed in step 3, re-invoking `payout_stakers`/`payout_stakers_by_page` for this era/page returns `AlreadyClaimed` (`substrate/frame/staking-async/src/pallet/impls.rs:381-384`) — nominator B's reward is permanently lost. A unit test asserting nominator B's free balance remains zero and total issuance/pot balance reflects the undistributed amount after this sequence would confirm the bug.

	fn payout_from_provider(
		era: EraIndex,
		stash: &T::AccountId,
		validator_payout: BalanceOf<T>,
		exposure: &crate::PagedExposure<T::AccountId, BalanceOf<T>>,
		overview_own: BalanceOf<T>,
		total_nominator_payout: BalanceOf<T>,
	) -> u32 {
		let mut nominator_payout_count: u32 = 0;

		if let Some((amount, dest)) = Self::make_payout_from_provider(era, stash, validator_payout)
		{
			Self::deposit_event(Event::<T>::Rewarded { stash: stash.clone(), dest, amount });
		}

		let total_nominator_stake = exposure.total().saturating_sub(overview_own);
		for nominator in exposure.others().iter() {
			let nominator_exposure_part =
				Perbill::from_rational(nominator.value, total_nominator_stake);
			let nominator_reward: BalanceOf<T> =
				nominator_exposure_part.mul_floor(total_nominator_payout);

			if let Some((amount, dest)) =
				Self::make_payout_from_provider(era, &nominator.who, nominator_reward)
			{
				nominator_payout_count.saturating_inc();
				Self::deposit_event(Event::<T>::Rewarded {
					stash: nominator.who.clone(),
					dest,
					amount,
				});
			}
		}

		nominator_payout_count
	}

	fn can_deposit(
		who: &T::AccountId,
		amount: Self::Balance,
		provenance: Provenance,
	) -> DepositConsequence {
		if amount.is_zero() {
			return DepositConsequence::Success;
		}

		if provenance == Minted && TotalIssuance::<T, I>::get().checked_add(&amount).is_none() {
			return DepositConsequence::Overflow;
		}

		let account = Self::account(who);
		let new_free = match account.free.checked_add(&amount) {
			None => return DepositConsequence::Overflow,
			Some(x) if x < T::ExistentialDeposit::get() => return DepositConsequence::BelowMinimum,
			Some(x) => x,
		};
