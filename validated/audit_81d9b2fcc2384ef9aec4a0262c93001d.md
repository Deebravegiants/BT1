This lets a relayer/caller swap it without invalidating the proof or signature.

### Title
Unconstrained `rootHashHinkalIndex` allows stale/arbitrary root-index substitution outside the proof and signature binding - (File: contracts/CircomDataBuilder.sol)

### Summary
`CircomData.rootHashHinkalIndex` [1](#0-0)  is consumed directly by `Hinkal.transact` to validate the Merkle root: `rootHashExists(circomData.rootHashHinkal, circomData.rootHashHinkalIndex)` [2](#0-1) . However, this field is never hashed into `calldataHash` (`getHashedCalldata1`/`getHashedCalldata2`) [3](#0-2) , never included in `getSignedMessageHash` [4](#0-3) , and never placed into the public-input array returned by `formBasicInput`/`formInputEmporiumMin` that is fed to the Groth16 verifier [5](#0-4) . Only `circomData.rootHashHinkal` (the root value itself) is bound by those equalities — the index used to look it up in the historical-root window is not.

### Finding Description
The verification flow in `Hinkal.transact` is:
1. `hinkalHelper.performHinkalChecks` recomputes `calldataHash` from a fixed subset of `CircomData` fields and checks it against `circomData.calldataHash` [6](#0-5) , then builds the circuit's public inputs via `formInputForCircom`.
2. The Groth16 proof is verified against those public inputs [7](#0-6) .
3. Separately, root validity is checked with `rootHashExists(circomData.rootHashHinkal, circomData.rootHashHinkalIndex)` [8](#0-7) .

The prover signs and proves over `rootHashHinkal` (via `getSignedMessageHash` and the public-input array), but never over `rootHashHinkalIndex`. Since `rootHashHinkalIndex` is not part of any hash/signature/public-input equality, an unprivileged party who submits the transaction (the relayer, or any EOA broadcasting a proof they've obtained/observed) can freely choose any `rootHashHinkalIndex` value as long as `rootHashExists` accepts the pair — i.e., they can target whichever historical root-slot in the rolling root window still matches `circomData.rootHashHinkal`, independent of which root/index the user actually intended or proved membership against off-chain. This breaks the intended equality that the (root, index) pair used for on-chain acceptance must be the exact one the circuit/signature committed to.

### Impact Explanation
This does not by itself let an attacker forge a Merkle-membership proof — `calcTransactionRootHash` in the circuit still constrains `rootHashHinkal` itself via `rootHashHinkal` being part of `getSignedMessageHash`/public inputs, and the circuit checks `inCommitmentSiblings` against `rootHashHinkal` at proof time. The concrete on-chain risk is that `rootHashHinkalIndex` is an unconstrained hint into the root-history window; because it's excluded from every integrity/authorization equality, any party relaying the transaction can substitute an index pointing to a stale but still-cached root slot, decoupling the "index" (freshness/slot claim) from what the user's proof/signature actually attested to. Given the report's rules, this is a genuine equality break — a `CircomData` field acted on by privileged on-chain logic (`rootHashExists` gating fund movement) but outside `calldataHash`/`signedMessageHash`/the public-input vector — though without access to `rootHashExists`'s exact window semantics (`Merkle.sol`, not in the indexed context), it cannot be confirmed as directly enabling double-spend or fund theft versus a benign lookup optimization. This should be scoped High pending confirmation of `rootHashExists`'s implementation.

### Likelihood Explanation
Any relayer or non-owner party responsible for submitting `circomData` and the proof can trivially manipulate `rootHashHinkalIndex` since it costs nothing and is not checked by any hash equality — this requires no special privilege, only that the party controls calldata construction (which relayers/front-ends already do for every unprivileged Hinkal transaction).

### Recommendation
Include `rootHashHinkalIndex` in `getHashedCalldata1`/`getHashedCalldata2` (or `getSignedMessageHash`) in `contracts/CircomDataBuilder.sol` so that it is bound by `calldataHash`/`signedMessageHash` integrity checks in `HinkalHelper.performHinkalChecks`, matching the treatment already given to `rootHashHinkal`.

### Proof of Concept
Not independently reproducible from the indexed contracts alone because `rootHashExists`'s window/lookup logic lives in `Merkle.sol`, which was not returned by the available searches; the analog is based on the confirmed absence of `rootHashHinkalIndex` from `getHashedCalldata1/2`, `getSignedMessageHash`, and `formBasicInput`/`formInputEmporiumMin` in `contracts/CircomDataBuilder.sol`, contrasted with its direct use in `Hinkal.transact`'s root-validity gate. Due to index size limits, `Merkle.sol`'s `rootHashExists` implementation was not available in this pass — starting a Devin session would allow full inspection of that function to determine whether the unconstrained index enables any exploitable root-window manipulation beyond the equality-break already demonstrated.

    function getSignedMessageHash(
        uint256 chainId,
        address verifyingContract,
        CircomData calldata circomData,
        uint256 emporiumMessage
    ) internal pure returns (uint256) {
        // split into two encode calls to avoid "stack too deep"
        uint256 hash1 = uint256(
            keccak256(
                abi.encode(
                    chainId,
                    verifyingContract,
                    circomData.rootHashHinkal,
                    _encodeTokenAddresses(circomData.erc20TokenAddresses),
                    _encodeAmountChanges(circomData.amountChanges),
                    circomData.timeStamp,
                    _flatUint256Matrix(circomData.inputNullifiers),
                    _flatUint256Matrix(circomData.outCommitments),
                    circomData.calldataHash,
                    emporiumMessage
                )
            )
        );
        uint256 hash2 = uint256(
            keccak256(
                abi.encode(
                    circomData.stealthAddressStructure.H1x,
                    circomData.stealthAddressStructure.H1y,
                    circomData.stealthAddressStructure.H0x,
                    circomData.stealthAddressStructure.H0y
                )
            )
        );
        return
            uint256(keccak256(abi.encode(hash1, hash2))) % CIRCOM_P;
    }

    function formBasicInput(
        uint256 chainId,
        address verifyingContract,
        CircomData calldata circomData,
        uint256[] memory input,
        uint256 index,
        uint256 emporiumMessage
    ) internal pure returns (uint256[] memory) {
        // 1) First we list public inputs as in the body of the main template (not the one with exact dimensions)
        input[index++] = circomData.stealthAddressStructure.H1x;
        input[index++] = circomData.stealthAddressStructure.H1y;
        input[index++] = circomData.stealthAddressStructure.stealthAddress;
        input[index++] = emporiumMessage; // this is for Emporium message signature verification

        // 2) Then we list the private inputs as in the body of the main template
        input[index++] = circomData.rootHashHinkal;
        input[index++] = getSignedMessageHash(
            chainId,
            verifyingContract,
            circomData,
            emporiumMessage
        );

        for (uint16 i = 0; i < circomData.erc20TokenAddresses.length; i++) {
            input[index++] = uint256(
                uint160(circomData.erc20TokenAddresses[i])
            );
        }

        for (uint16 i = 0; i < circomData.amountChanges.length; i++) {
            require(
                circomData.amountChanges[i] < MAX_AMOUNT &&
                    circomData.amountChanges[i] > -1 * MAX_AMOUNT,
                "amount changed is too large"
            );

            input[index++] = circomData.amountChanges[i] >= 0
                ? uint256(circomData.amountChanges[i])
                : CIRCOM_P - uint256(-circomData.amountChanges[i]);
        }

        for (uint16 i = 0; i < circomData.inputNullifiers.length; i++) {
            for (uint16 j = 0; j < circomData.inputNullifiers[i].length; j++) {
                input[index++] = circomData.inputNullifiers[i][j];
            }
        }

        input[index++] = circomData.timeStamp;

        for (uint16 i = 0; i < circomData.outCommitments.length; i++) {
            for (uint16 j = 0; j < circomData.outCommitments[i].length; j++) {
                input[index++] = circomData.outCommitments[i][j];
            }
        }
        input[index++] = circomData.calldataHash;

        input[index++] = circomData.stealthAddressStructure.H0x;
        input[index++] = circomData.stealthAddressStructure.H0y;

        return input;
    }
