## Title
`CallDispatcher.dispatch` has no caller authorization, letting any unprivileged address drain whatever balance the shared dispatcher is custodying — (File: `evm/src/utils/CallDispatcher.sol`)

### Summary
The CVE analog describes Ruby's `Shell#[]`/`Shell#test` treating an untrusted "command" argument as implicitly trusted, letting any caller who controls that argument execute arbitrary methods. `CallDispatcher.dispatch(bytes memory encoded)` has the same defect: it decodes an attacker-supplied `Call[]` and executes each entry (`to.call{value: call.value}(call.data)`) with the `CallDispatcher` itself as `msg.sender`, with **no restriction on who may call `dispatch`** — no `onlyOwner`, no allow-listed caller, no reentrancy guard. [1](#0-0) 

### Finding Description
`CallDispatcher` is a single shared, stateful contract deployed once and referenced by address in `Params.dispatcher` across `IntentGatewayV2`, `HyperFungibleToken`, and `WrappedHyperFungibleToken` (and their upgradeable/Tron variants), all of which move real user funds into it before invoking `dispatch`. [2](#0-1) 

Two flows custody assets in the dispatcher and rely on the *caller* (gateway) sweeping them back afterward, but only for the token set the caller already knows about:

- Predispatch: `IntentGatewayV2.placeOrder` transfers `order.predispatch.assets` to `dispatcher`, calls `dispatch(order.predispatch.call)` with attacker/order-creator supplied calldata, then sweeps back only the tokens listed in `order.inputs`. [3](#0-2) 

- Postdispatch: `IntentsBase._execute` calls `dispatch(order.output.call)` and then sweeps back only tokens listed in `order.output.assets`. [4](#0-3) 

Any token that the predispatch/postdispatch calldata's DEX/DeFi interaction produces or leaves behind (intermediate swap-path tokens, reward tokens, slippage remainder, or native ETH sent to the dispatcher's public `receive()`) that is **not** one of the explicitly enumerated `order.inputs`/`order.output.assets` is never swept and sits in `CallDispatcher`'s balance. Because `dispatch()` is fully public and unauthenticated, any unprivileged address can then call it directly with a `Call` targeting that ERC20's `transfer`/`approve`/`transferFrom` (or ETH to a contract it controls), executing with `msg.sender == CallDispatcher`, and walk off with that balance — funds that ultimately trace back to a legitimate user's escrow or a token-transfer message. [1](#0-0) [5](#0-4) 

The `WrappedHyperFungibleToken`/`HyperFungibleToken` apps route inbound cross-chain calldata through the same shared dispatcher, so unswept balances from a token-bridge delivery are equally exposed: [6](#0-5) 

### Impact Explanation
Any value the `CallDispatcher` ends up holding outside the narrow set of tokens the calling app's sweep loop enumerates is permanently and immediately stealable by any address on-chain, with no relayer, governance, or privileged role required — a single unprivileged transaction (`CallDispatcher.dispatch(...)`) suffices. Given the dispatcher is a shared singleton across the intents system and the token-bridge apps, this is a theft-of-funds primitive reachable from ordinary DeFi-composed order fulfillment (swap slippage, multi-hop routing, reward claims) or any accidental/incidental transfer to the dispatcher's `receive()`.

### Likelihood Explanation
Likelihood depends on the dispatcher actually holding a non-zero, non-enumerated balance at some point — which is a realistic, not hypothetical, occurrence any time predispatch/postdispatch calldata performs a swap with slippage, claims rewards, or interacts with a DEX router that leaves intermediate-token dust, since only the tokens explicitly named in `order.inputs`/`order.output.assets` are swept back. Because `dispatch()` itself has zero access control, exploitation requires no special timing or race — the attacker can call it in any block once such a balance exists (a public mempool watcher/monitoring bot can trigger this trivially and permissionlessly).

### Recommendation
Restrict `CallDispatcher.dispatch` to authorized callers only (e.g., an `onlyAuthorized` allow-list of the gateway/app contracts that are meant to use it, or make the dispatcher a non-shared, per-call ephemeral proxy so it never persists balance between calls), and/or have it sweep its *entire* balance for any token touched by `call.data`, not just the caller-enumerated set, before returning control.

### Proof of Concept
1. A postdispatch order routes output assets through a DEX with `order.output.call`, and the swap leaves a small remainder of an intermediate token (e.g., WETH) in `CallDispatcher` that is not part of `order.output.assets`.
2. `IntentsBase._execute`'s sweep loop only checks `order.output.assets`, so the WETH remainder is never swept and stays in `CallDispatcher`'s balance. [7](#0-6) 
3. Any external address calls `CallDispatcher.dispatch(abi.encode([Call({to: address(WETH), value: 0, data: abi.encodeWithSelector(IERC20.transfer.selector, attacker, wethBalance)})]))` — this passes the `extcodesize` check (WETH is a contract) and succeeds because `dispatch` has no `msg.sender` restriction. [8](#0-7) 
4. The attacker now holds the WETH that should have belonged to the protocol/beneficiary, with no signature, relayer authorization, or governance action needed.

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }

        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            } else {
                uint256 balance = IERC20(token).balanceOf(dispatcher);
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            }

            unchecked {
                ++i;
            }
        }

                }
