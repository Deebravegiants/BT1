## Title
Denial of Service via unbounded GRANDPA ancestry-walk in unsigned finality/fraud proofs - (File: `modules/consensus/grandpa/primitives/src/justification.rs`)

### Summary
`pallet-ismp`'s `handle_unsigned` extrinsic accepts arbitrary GRANDPA `ConsensusMessage` / `FraudProofMessage` payloads from any unauthenticated submitter (no signature, no fee) [1](#0-0) . Before such a transaction is even accepted into the transaction pool, `ValidateUnsigned::validate_unsigned` fully executes the message — including complete GRANDPA justification verification — on every node that receives the transaction over the network [2](#0-1) . The GRANDPA verifier builds an `AncestryChain` from the attacker-supplied `unknown_headers` list and then, for every precommit in the justification, walks the chain node-by-node from the precommit's target back to the base block via `AncestryChain::ancestry` [3](#0-2) . Neither `unknown_headers` nor `precommits` is size-bounded before this walk runs, so a single crafted, unsigned message can force every full node's mempool-validation worker to perform an unbounded number of hash-map traversals — closely mirroring the SAML-endpoint pattern of one unauthenticated request driving disproportionate CPU work and worker-thread starvation.

### Finding Description
`handle_unsigned` is deliberately free/unsigned so relayers can submit ISMP messages without cost [4](#0-3) . To keep this from being a spam vector, the pallet relies entirely on `ValidateUnsigned::validate_unsigned` rejecting invalid submissions — but that validation function itself calls `Self::execute(messages.clone())`, i.e. it performs the *full* cryptographic verification of the message before deciding whether to admit it to the pool [2](#0-1) . This means the expensive verification work is paid by **every peer node in the network** during transaction-pool gossip/validation, not just a block author, since `validate_unsigned` runs on every node that receives the extrinsic.

For a GRANDPA `ConsensusMessage`, this ultimately calls `verify_grandpa_finality_proof`, which:
1. Builds `AncestryChain::new(&finality_proof.unknown_headers)` — a `BTreeMap` over every header the attacker supplies, with no upper bound on `unknown_headers.len()` [5](#0-4) .
2. Decodes and verifies the `GrandpaJustification`, which for each of its `precommits`, calls `ancestry_chain.ancestry(base_hash, signed.precommit.target_hash)` [3](#0-2) .

`AncestryChain::ancestry` walks parent-hash pointers one link at a time until it reaches `base`, and is O(chain length) per call [6](#0-5) . Because it's invoked once per precommit, and precommit count is attacker-influenced (a malformed/duplicated set only fails validation *after* signature checks and ancestry walks have already run), the overall verification cost scales as O(precommits × unknown_headers), both of which are supplied in the same unsigned, un-metered payload with no explicit cap in `FinalityProof`/`GrandpaJustification`/`ConsensusMessage` encoding [7](#0-6) . The same unbounded pattern additionally runs twice per call in `verify_fraud_proof`, which decodes and processes two independent `FinalityProof` payloads before any cheap sanity checks such as block-hash comparison could short-circuit the expensive path [7](#0-6) .

### Impact Explanation
Because `validate_unsigned` runs on every full/collator node's mempool validation path — before the extrinsic is charged any fee or even guaranteed to be included — an attacker can broadcast a stream of oversized, syntactically-valid-but-cryptographically-doomed GRANDPA messages (large `unknown_headers` chains, many precommits) to consume CPU on every node in the network simultaneously. This matches CWE-1286/algorithmic-complexity DoS: a single crafted, unauthenticated payload forces disproportionate CPU work network-wide, potentially causing block production stalls and network-wide unavailability of the relay/messaging path — the same "no impact on confidentiality/integrity, but High availability impact" profile as the referenced Keycloak SAML CVE.

### Likelihood Explanation
`handle_unsigned` is explicitly designed to be reachable by anyone without a signature or fee [8](#0-7) , satisfying the "unprivileged message dispatcher/relayer" reachability bar. The only mitigations mentioned in docs ("transaction pool validity checks filter malformed messages") are exactly the code path (`validate_unsigned`) that performs the expensive, unbounded work being described here, so the stated mitigation is itself the attack surface.

### Recommendation
Bound `unknown_headers.len()` and `precommits.len()` (and the equivalent for the fraud-proof path) to a small multiple of the known/expected authority-set size before running any ancestry walk or signature verification, and reject oversized `FinalityProof`/`GrandpaJustification` payloads immediately in `validate_unsigned`, prior to any BTreeMap construction or ancestry traversal.

### Proof of Concept
1. Construct a `ConsensusMessage` targeting the GRANDPA consensus state whose `consensus_proof` encodes a `FinalityProof` with a very large `unknown_headers` chain (e.g., tens of thousands of synthetic linked headers, sized to fit within the extrinsic/block-length limit) and a `justification` with many precommits, each targeting a different point along that chain.
2. Wrap it in `pallet_ismp::Call::handle_unsigned { messages: vec![Message::Consensus(...)] }` and broadcast it unsigned, as tests already do for legitimate messages [9](#0-8) .
3. Every node that receives the gossiped extrinsic invokes `ValidateUnsigned::validate_unsigned` → `Self::execute` → `verify_grandpa_finality_proof` → `AncestryChain::ancestry` in a loop over all precommits, each walking a large chain, before ultimately rejecting the message as invalid — burning CPU on every peer for a message that costs the attacker nothing and never lands on-chain.

	fn ancestry(
		&self,
		base: H::Hash,
		block: H::Hash,
	) -> Result<Vec<H::Hash>, finality_grandpa::Error> {
		let mut route = vec![block];
		let mut current_hash = block;
		while current_hash != base {
			match self.ancestry.get(&current_hash) {
				Some(current_header) => {
					current_hash = *current_header.parent_hash();
					route.push(current_hash);
				},
				_ => return Err(finality_grandpa::Error::NotDescendent),
			};
		}
		Ok(route)
	}

	fn verify_fraud_proof(
		&self,
		_host: &dyn IsmpHost,
		trusted_consensus_state: Vec<u8>,
		proof_1: Vec<u8>,
		proof_2: Vec<u8>,
	) -> Result<(), Error> {
		// decode the consensus state
		let consensus_state: ConsensusState =
			codec::Decode::decode(&mut &trusted_consensus_state[..])
				.map_err(|e| GrandpaError::DecodeConsensusState(format!("{e:?}")))?;

		let first_proof: FinalityProof<SubstrateHeader> = codec::Decode::decode(&mut &proof_1[..])
			.map_err(|e| GrandpaError::DecodeFinalityProof(format!("{e:?}")))?;

		let second_proof: FinalityProof<SubstrateHeader> = codec::Decode::decode(&mut &proof_2[..])
			.map_err(|e| GrandpaError::DecodeFinalityProof(format!("{e:?}")))?;

		if first_proof.block == second_proof.block {
			return Err(GrandpaError::FraudProofsSameBlock.into());
		}

		let first_headers = AncestryChain::<SubstrateHeader>::new(&first_proof.unknown_headers);
		let first_target = first_proof
			.unknown_headers
			.iter()
			.max_by_key(|h| *h.number())
			.ok_or(GrandpaError::UnknownHeadersEmpty)?;

		let second_headers = AncestryChain::<SubstrateHeader>::new(&second_proof.unknown_headers);
		let second_target = second_proof
			.unknown_headers
			.iter()
			.max_by_key(|h| *h.number())
			.ok_or(GrandpaError::UnknownHeadersEmpty)?;

		if first_target.hash() != first_proof.block || second_target.hash() != second_proof.block {
			return Err(GrandpaError::FraudProofsDifferentChain.into());
		}

		let first_base = first_proof
			.unknown_headers
			.iter()
			.min_by_key(|h| *h.number())
			.ok_or(GrandpaError::UnknownHeadersEmpty)?;
		let first_chain = first_headers
			.ancestry(first_base.hash(), first_target.hash())
			.map_err(|_| GrandpaError::InvalidAncestry)?;

		let second_base = second_proof
			.unknown_headers
			.iter()
			.min_by_key(|h| *h.number())
			.ok_or(GrandpaError::UnknownHeadersEmpty)?;
		let second_chain = second_headers
			.ancestry(second_base.hash(), second_target.hash())
			.map_err(|_| GrandpaError::InvalidAncestry)?;

## Transaction fees

Pallet ISMP uses unsigned transactions for executing cross-chain messages. This means all cross-chain messages received are executed for free as unsigned transactions. The upside to this is that it cannot be exploited as a spam vector, since the transaction pool will check if the submitted extrinsics are valid before they are included in the pool. This validity check ensures that the transaction can be successfully executed and contains valid proofs. Malformed messages or those with invalid proofs are filtered out by the transaction pool validation logic preventing unnecessary processing and potential network congestion.
