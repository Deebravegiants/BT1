### Title
Pool refunds unverified "excess" payments out of real custody, letting any caller drain reserves - ([File: contracts/pool/src/ops/recapitalize.rs], [File: contracts/pool/src/ops/repay.rs])

### Summary
Analogous to the esp page-frag leak — where a resource acquired earlier is released unconditionally on a failure path — the pool releases custody unconditionally on a "refund" path whose precondition (the inbound funding) was never verified. `recapitalize::apply` and `repay::apply` refund `amount - applied` / `amount - net_repay` derived purely from the *declared* `amount`, not from any measured receipt. When the pool is invoked directly (bypassing the controller's `transfer_amount_measured` prefunding), the entire declared amount is refunded out of real reserves while no tokens ever arrive.

### Finding Description
`ops::recapitalize::accounting` computes `applied = min(amount, backing_shortfall)` and `refund = amount - applied`, then `apply` calls `cache.transfer_out(&payer, refund)` with no check that `amount` was actually deposited [1](#0-0) . The doc comment explicitly assumes "The controller transfers `amount` into the pool before this call" — trust in the caller's prefunding, not measured receipt.

The same shape exists in `ops::repay::accounting`: `resolve_repay` splits the declared `amount` into `net_repay` and `overpayment`, then `apply` refunds `overpayment` to the payer [2](#0-1) . For a market with zero debt, `current_debt_ceil` is zero, the full-close branch makes `net_repay == 0`, the `RepayRoundsToZeroShares` assert passes on its `net_repay == 0` disjunct, and the whole declared amount becomes an unfunded refund.

The test suite already demonstrates both: `test_unfunded_repay_overpayment_refund_also_pays_out_of_custody` calls `client().repay(&payer, &ract(0, custody_before))` directly against the pool and asserts the payer receives the full declared amount and pool custody goes to zero while the cash book is unchanged [3](#0-2) . The controller path is safe only because `settle_repay` and `recapitalize` measure the inbound transfer first via `payments::transfer_amount_measured` [4](#0-3) [5](#0-4) .

### Impact Explanation
Theft of user funds / protocol insolvency: an unprivileged address that can call the pool's `repay` or `recapitalize` entrypoint directly (as the tests do) declares a large `amount`, triggers the refund branch, and receives existing pool custody without depositing anything. Worse, `cash` is not debited by the refund (`transfer_out` moves custody but the book is committed with the book-keeping untouched), so the market keeps reporting drained funds as present — subsequent `withdraw`/`borrow` calls pass `require_reserves` against phantom cash and fail inside the SAC transfer, permanently freezing remaining user funds.

### Likelihood Explanation
Requires only that the pool entrypoints be directly callable — the fixture tests confirm no controller-only gate rejects the call, and the rules explicitly allow "direct token transfers to the pool or controller." A single transaction with attacker-chosen `amount` up to pool custody suffices; no oracle manipulation, timing, or privileged role needed.

### Recommendation
Measure inbound receipts inside the pool (balance-delta before/after, as the controller already does in `transfer_amount_measured` / `claim_revenue_for_asset`), or gate `repay`/`recapitalize` to the controller address, or debit `cash` by the refund and require reserves before `transfer_out`. The refund must never exceed funds verifiably received in the same transaction.

### Proof of Concept
```rust
// Attacker calls the pool directly with a debt-free market:
let declared = pool_custody; // e.g. full USDC balance held by pool
pool_client.repay(&attacker, &vec![env, (hub_asset, declared)]);
// net_repay == 0, overpayment == declared
// transfer_out(attacker, declared) pays real custody; cash book unchanged
// pool now insolvent: suppliers cannot withdraw
```
This mirrors `test_unfunded_repay_overpayment_refund_also_pays_out_of_custody` in `contracts/pool/tests/flows.rs`, which asserts `token.balance(&t.pool) == 0` and `after.cash == before.cash` after the call.

pub(crate) fn accounting(
    env: &Env,
    hub_asset: HubAssetKey,
    amount: i128,
) -> RecapitalizationOutcome {
    require_nonneg_amount(env, amount);
    let mut cache = ops::renewed_market(env, &hub_asset);

    let applied = amount.min(guards::backing_shortfall(&cache));
    let refund = amount
        .checked_sub(applied)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));

    cache.credit_cash(applied);
    cache.commit();
```

pub(crate) fn apply(
    env: &Env,
    payer: &Address,
    action: &PoolAction,

    let outcome = accounting(env, action);

    outcome.cache.transfer_out(payer, outcome.overpayment);
    (outcome.mutation, outcome.snapshot)
}

/// Accrues interest, resolves the repay amount into burned debt shares and
/// overpayment, burns the shares, and credits the net repay to cash without
/// transferring the overpayment refund. Panics if a positive net repay would
/// burn zero scaled shares.
pub(crate) fn accounting(env: &Env, action: &PoolAction) -> RepayOutcome {
    let (mut cache, position) = ops::load_leg(env, action);
    let amount = action.amount;

    let (burned, overpayment) = cache.resolve_repay(amount, position);
    let net_repay = amount
        .checked_sub(overpayment)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));
    assert_with_error!(
        env,
        net_repay == 0 || burned.raw() > 0,
        GenericError::RepayRoundsToZeroShares
    );
```

#[test]
fn test_unfunded_repay_overpayment_refund_also_pays_out_of_custody() {
    let t = TestSetup::new();
    let token = token::Client::new(&t.env, &t.asset);
    let payer = Address::generate(&t.env);

    let custody_before = token.balance(&t.pool);
    let before = t.state_snapshot();
    assert_eq!(
        before.cash, custody_before,
        "fixture guard: book and custody must start in sync"
    );
    assert_eq!(before.borrowed, 0, "fixture must carry no debt");

    // Nothing transferred in, no debt to retire: the whole amount is "excess".
    let credited = t
        .client()
        .repay(&payer, &t.ract(0, custody_before))
        .get_unchecked(0)
        .actual_amount;
    assert_eq!(credited, 0, "no debt was retired, so nothing is credited");
    assert_unfunded_refund_drained_custody(&t, &payer, custody_before, &before);
}
