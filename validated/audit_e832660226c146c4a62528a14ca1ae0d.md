### Title
Unbounded Array Allocation from Untrusted SCALE Compact Length in `Codec.DecodeHeader` Before Proof Authentication - (File: evm/src/consensus/Codec.sol)

### Summary
`Codec.DecodeHeader` allocates a `Digest[]` array sized directly from an attacker-influenced SCALE compact-encoded length field read out of raw header bytes, and this decode is executed **before** the header bytes are authenticated against the BEEFY MMR parachain-heads root. This mirrors the CVE-2021-36155 bug class (allocating memory/array size from an untrusted length prefix before validating the underlying payload), reachable by any relayer submitting a BEEFY consensus proof to `EcdsaBeefy.verify`.

### Finding Description
`Codec.DecodeHeader` reads a SCALE compact-encoded digest count and immediately allocates a memory array of that size: [1](#0-0) 

This function is invoked from `verifyParachainHeaderProof` for every entry in `proof.parachains`, and critically the decode happens **before** the merkle-multiproof membership check (`MerkleMultiProof.VerifyProof`) that would authenticate `para.header` against the BEEFY-anchored `headsRoot`: [2](#0-1) 

Because `ParachainProof` (which carries the raw `para.header` bytes) is ABI-decoded straight from the calldata passed to `verify()`, and the header content itself is not checked until *after* `DecodeHeader` already ran, the `length` value driving `new Digest[](length)` is fully attacker/relayer-controlled at the point of allocation: [3](#0-2) 

### Impact Explanation
A relayer can submit a genuinely valid `RelayChainProof` (which passes the supermajority signature/authority check in `verifyMmrUpdateProof`) paired with an arbitrary, unauthenticated `ParachainProof.parachains[i].header` whose digest-count compact integer is crafted to be extremely large. `DecodeHeader` will attempt to allocate a `Digest[]` of that size and then loop over it, exhausting gas and reverting the entire `verify()` call — including the legitimate consensus/MMR-root update and every other (legitimate) parachain header batched in the same call. Because Hyperbridge batches multiple parachains' state commitments in a single BEEFY consensus update, this lets a single malformed/malicious header entry deny the consensus update — and therefore block ISMP message delivery — for all other parachains bundled in that update, until callers learn to exclude the offending state machine. This satisfies the "route unable to deliver messages" impact criterion.

### Likelihood Explanation
`EcdsaBeefy.verify` is a `pure`/permissionless entry point reachable by any relayer submitting a consensus update; no privileged role is required to control the `ParachainProof` argument, only a previously-valid `RelayChainProof` (which is public, replayable relay-chain data). Crafting a header with an oversized SCALE compact digest-count is trivial and requires no cryptographic break — only that the array allocation and loop occur before the merkle-inclusion check.

### Recommendation
Reorder validation so header bytes are hash-committed and merkle-verified against `headsRoot` **before** `Codec.DecodeHeader` is invoked on their content, or impose a strict upper bound on the decoded digest `length` (reject/revert immediately if it exceeds a small sane maximum, e.g. a few dozen digests) prior to allocating `Digest[]`, mirroring the bound already added in `pallet-call-decompressor::decompress` for the analogous zstd-bomb issue.

### Proof of Concept
1. Obtain any genuine `RelayChainProof` (public relay-chain data) that satisfies `verifyMmrUpdateProof`.
2. Construct a `ParachainProof.parachains[0].header` byte string that is well-formed only up to the digest-count field, encoding an extremely large SCALE compact value (e.g. mode-3 encoding of a near-`u64::MAX` value) as the digest count, with insufficient trailing bytes to actually satisfy that many digests.
3. Call `EcdsaBeefy.verify(previousState, abi.encode(relay, parachainProofWithMaliciousHeader))`.
4. Execution reaches `Codec.DecodeHeader`, attempts `new Digest[](hugeLength)`, and the call reverts on out-of-gas before the merkle-inclusion check in `verifyParachainHeaderProof` ever runs against the malicious header — causing the whole batched update (including any legitimate parachains in the same call) to fail.

    // @dev Verifies that some parachain header has been finalized, given the current trusted consensus state.
    function verifyParachainHeaderProof(bytes32 headsRoot, ParachainProof memory proof)
        internal
        pure
        returns (IntermediateState[] memory)
    {
        uint256 len = proof.parachains.length;
        MerkleMultiProof.Leaf[] memory leaves = new MerkleMultiProof.Leaf[](len);
        IntermediateState[] memory intermediates = new IntermediateState[](len);

        for (uint256 i = 0; i < len; i++) {
            Parachain memory para = proof.parachains[i];
            Header memory header = Codec.DecodeHeader(para.header);
            if (header.number == 0) revert IllegalGenesisBlock();

            leaves[i] = MerkleMultiProof.Leaf(
                para.index,
                keccak256(bytes.concat(ScaleCodec.encode32(uint32(para.id)), ScaleCodec.encodeBytes(para.header)))
            );

            StateCommitment memory commitment = header.stateCommitment();
            intermediates[i] =
                IntermediateState({stateMachineId: para.id, height: header.number, commitment: commitment});
        }

        if (len > 0) {
            bool valid = MerkleMultiProof.VerifyProof(headsRoot, proof.proof, leaves, proof.leafCount);
            if (!valid) revert InvalidMmrProof();
        }

        return intermediates;
    }
