### Title
Login brute-force rate limiter is process-local in-memory state, not shared across instances and reset on restart - (File: core/web/router.go)

### Summary
The `/sessions` login endpoint (unauthenticated, credential-guessing surface) is protected only by an in-process `ulule/limiter` counter backed by `memory.NewStore()`, instantiated fresh per process with no persistence or cross-instance coordination.

### Finding Description
`NewRouter` builds the rate limiter via the `rateLimiter` helper, which always constructs an in-memory store: [1](#0-0) 

`sessionRoutes` applies this in-memory limiter specifically to the unauthenticated `POST /sessions` login endpoint, gated only by `rl.Unauthenticated()` / `rl.UnauthenticatedPeriod()` (default 5 attempts per 20s): [2](#0-1) 

The actual credential check happens in `orm.CreateSession` (local auth) or the LDAP/OIDC equivalents, which compare password hashes and can also leak MFA-presence info via error paths: [3](#0-2) 

Because the counter lives only in a Go process's memory (`limiter/v3/drivers/store/memory`), it has the same structural weakness as the reported analog (`TOTPRateLimiter` using an in-memory `defaultdict`/class variable):
- State is per-process; any horizontally scaled or restarted Chainlink node instance (e.g., behind a load balancer, in a Kubernetes deployment with multiple replicas, or during a simple process restart/redeploy) resets or fragments the attempt counters.
- An attacker distributing requests across multiple node replicas (common in production HA/multi-replica deployments of Chainlink nodes) or triggering/waiting for a restart gets an effectively unlimited number of unthrottled password-guessing attempts against `/sessions`.

### Impact Explanation
This weakens brute-force protection on the primary node-operator authentication endpoint. Successful credential guessing grants a session cookie with the victim user's role (Admin/Edit/Run), enabling job creation, bridge configuration, fund-moving transfer endpoints (`/v2/transfers*`), and other privileged actions gated by `auth.RequiresAdminRole` / `auth.RequiresEditRole`. This is a rate-limiting/brute-force weakness rather than a full bypass — actual compromise still requires guessing a valid password, but the intended throttle is unreliable in any multi-instance or frequently-restarted deployment.

### Likelihood Explanation
Exploitability depends on deployment: a single, long-lived node instance provides real throttling. However, any deployment running multiple `chainlink` node processes (load-balanced replicas) or subject to restarts/redeploys (common in containerized/production environments) allows the limiter to be trivially reset or bypassed by an unprivileged network client without any special access.

### Recommendation
Back the login/session rate limiter with a shared, durable store (e.g., the node's Postgres database or Redis) instead of `ulule/limiter/v3/drivers/store/memory`, so attempt counts are shared across all node replicas and survive restarts. At minimum, persist failed-login counters/lockouts per email/IP in the database, mirroring the audit log entries already emitted (`audit.AuthLoginFailedPassword`, `audit.AuthLoginFailedEmail`).

### Proof of Concept
1. Deploy two replicas of the same Chainlink node behind a load balancer (or restart the node process between attempts).
2. Send `POST /sessions` with `{"email":"target@node.com","password":"guess1"}` five times to replica A — the 6th request is throttled with `429` (matching `TestSessions_RateLimited` behavior) [4](#0-3) .
3. Send the 6th (and further) guesses to replica B, or restart the node process and resend — the in-memory counter on the new process/replica is empty, so requests are again accepted and return `401` instead of `429`, allowing continued unthrottled password guessing.

func sessionRoutes(app chainlink.Application, r *gin.RouterGroup) {
	config := app.GetConfig()
	rl := config.WebServer().RateLimit()
	unauth := r.Group("/", rateLimiter(
		rl.UnauthenticatedPeriod(),
		rl.Unauthenticated(),
	))
	sc := NewSessionsController(app)
	unauth.POST("/sessions", sc.Create)
	auth := r.Group("/", auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession))
	auth.DELETE("/sessions", sc.Destroy)
}

func (o *orm) CreateSession(ctx context.Context, sr sessions.SessionRequest) (string, error) {
	user, err := o.FindUser(ctx, sr.Email)
	if err != nil {
		return "", err
	}
	lggr := o.lggr.With("user", user.Email)
	lggr.Debugw("Found user")

	// Do email and password check first to prevent extra database look up
	// for MFA tokens leaking if an account has MFA tokens or not.
	if !constantTimeEmailCompare(strings.ToLower(sr.Email), strings.ToLower(user.Email)) {
		o.auditLogger.Audit(audit.AuthLoginFailedEmail, map[string]any{"email": sr.Email})
		return "", pkgerrors.New("Invalid email")
	}

	if !utils.CheckPasswordHash(sr.Password, string(user.HashedPassword)) {
		o.auditLogger.Audit(audit.AuthLoginFailedPassword, map[string]any{"email": sr.Email})
		return "", pkgerrors.New("Invalid password")
	}
