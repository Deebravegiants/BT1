### Title
Unbounded-depth SCALE decode of attacker-controlled `runtime_call` in `pallet-hyper-fungible-token::on_accept` allows a crafted cross-chain message to panic delivery and permanently block that message's route - (File: `modules/pallets/hyper-fungible-token/src/module.rs`)

### Summary
`pallet-hyper-fungible-token`'s `on_accept` decodes the `runtime_call` field of an incoming cross-chain `Message.data` payload with a plain, depth-unbounded `Decode::decode` call, instead of the depth-limited decoder used everywhere else in the codebase for exactly this kind of untrusted, attacker-supplied encoded call. [1](#0-0)  The sibling pallet `pallet-call-decompressor` was patched specifically because unbounded decoding of a deeply-nested `RuntimeCall` (e.g. `Sudo(Sudo(Sudo(...)))`) causes stack exhaustion during decode, and now enforces `MAX_EXTRINSIC_DECODE_DEPTH_LIMIT` via `decode_all_with_depth_limit`. [2](#0-1) [3](#0-2)  HFT's `on_accept` never received the equivalent fix.

### Finding Description
`SendParams.call_data` lets any unprivileged sender attach arbitrary bytes to a cross-chain token transfer; these bytes are ABI-encoded into `Message.data` and delivered unmodified to the destination chain. [4](#0-3)  On delivery, `IsmpModule::on_accept` parses this into `SubstrateCalldata` and decodes its `runtime_call` field with a bare `Decode::decode`, with no recursion-depth limit, before the `BaseCallFilter` check is ever reached:

```rust
let runtime_call = T::RuntimeCall::decode(&mut &*substrate_data.runtime_call)
    .map_err(HftError::RuntimeCallDecodeError)?;
if !<T as frame_system::Config>::BaseCallFilter::contains(&runtime_call) {
    Err(HftError::CallFiltered)?
}
``` [5](#0-4) 

This is the same bug class the project itself has already identified and fixed once, in `pallet-call-decompressor`: an attacker can encode a deeply nested `RuntimeCall` (e.g. hundreds of levels of `Sudo(Sudo(...))`) whose SCALE decode recurses once per nesting level, exhausting the executor's stack before any filter or validation logic runs. `pallet-call-decompressor::decode_and_execute` had exactly this vulnerability and was fixed by switching to `decode_all_with_depth_limit(MAX_EXTRINSIC_DECODE_DEPTH_LIMIT, ...)`, with a regression test (`decompress_stack_exhaustion_poc`) that specifically builds 1000 nested `Sudo` calls to prove the depth limit now rejects them cleanly. [6](#0-5)  `pallet-hyper-fungible-token::module.rs` never received this fix and still performs the unbounded decode on data supplied by the message sender across the bridge.

Unlike `pallet-call-decompressor`'s `decompress_call`, which is a permissionless *unsigned* extrinsic gated only by size and depth checks, HFT's path is reached through the fully-authenticated ISMP delivery pipeline (`on_accept` is invoked only after consensus/state-proof verification of the POST request), but the *content* of `message.data` is entirely attacker/sender-controlled and unauthenticated at decode time — the signature check on `SubstrateCalldata` only covers the case where a `signature` is present, and even then the signature is verified only after the vulnerable decode has already run in the no-signature branch, and in all cases the crash happens before dispatch, inside decode itself.

### Impact Explanation
A single cross-chain `send` call with a crafted `call_data` payload reaches `on_accept` on the destination chain and triggers stack exhaustion during `Decode::decode` before the `BaseCallFilter` gate or the eventual dispatch/authorization check ever executes. Any relayer that submits this specific request will have the extrinsic abort in an uncontrolled way rather than return a handled `Err`; because the message can never be successfully decoded, it can never be delivered, and — depending on runtime executor behavior — repeated delivery attempts of the same request can degrade or halt block execution for that state machine. This falls under "a route unable to deliver messages": the specific message commitment becomes permanently stuck (neither cleanly accepted nor cleanly failing to a recoverable error), which can also block the timeout/refund path for the same request if the same code path is exercised, effectively freezing the sender's escrowed/burned funds tied to that message.

### Likelihood Explanation
High reachability: any account can call the permissionless `send` extrinsic with an arbitrary `call_data` byte string; no special privilege, governance, or admin permission is required. [7](#0-6)  Building a deeply nested `RuntimeCall` encoding is trivial and requires no cryptographic break — it is the exact same construction the project's own `decompress_stack_exhaustion_poc` test uses against the sibling pallet.

### Recommendation
Replace the plain `T::RuntimeCall::decode(&mut &*substrate_data.runtime_call)` call in `on_accept` with `T::RuntimeCall::decode_all_with_depth_limit(MAX_EXTRINSIC_DECODE_DEPTH_LIMIT, &mut &*substrate_data.runtime_call)`, mirroring the fix already applied in `pallet-call-decompressor`, and add a regression test analogous to `decompress_stack_exhaustion_poc` that submits a deeply nested `Sudo(...)` payload through `on_accept` and asserts a clean, bounded error instead of an uncontrolled abort.

### Proof of Concept
1. Build `inner = RuntimeCall::System(frame_system::Call::remark { remark: vec![] })`.
2. Loop ~1000 times: `inner = RuntimeCall::Sudo(pallet_sudo::Call::sudo { call: Box::new(inner) })` (or any recursive call variant reachable in the destination runtime's `RuntimeCall`).
3. SCALE-encode `inner` to get `runtime_call_bytes`.
4. Construct `SubstrateCalldata { signature: None, runtime_call: runtime_call_bytes }`, SCALE-encode it to get `data`.
5. From the source chain, call `HyperFungibleToken::send` (or the EVM `HyperFungibleToken.send`) with `call_data = data` targeting the destination chain/asset.
6. When the destination `pallet-hyper-fungible-token::on_accept` processes the delivered `PostRequest`, it reaches `T::RuntimeCall::decode(&mut &*substrate_data.runtime_call)` on the crafted bytes, reproducing the same stack-exhaustion condition demonstrated by `decompress_stack_exhaustion_poc` in `modules/pallets/testsuite/src/tests/pallet_call_decompressor.rs:313-352`, but with no depth-limit guard in front of it.

#[test]
fn decompress_stack_exhaustion_poc() {
	let mut ext = new_test_ext();
	ext.execute_with(|| {
		use crate::runtime::RuntimeCall;
		use codec::Encode;

		let inner_call = RuntimeCall::System(frame_system::Call::remark { remark: Vec::new() });

		let mut nested_calls =
			RuntimeCall::Sudo(pallet_sudo::Call::sudo { call: Box::new(inner_call) });

		for _ in 1..1000 {
			nested_calls =
				RuntimeCall::Sudo(pallet_sudo::Call::sudo { call: Box::new(nested_calls) });
		}

		let encoded = nested_calls.encode();
		let mut buffer = vec![0u8; 1000000];
		let compressed = zstd_safe::compress(&mut buffer[..], encoded.as_slice(), 3).unwrap();
		let final_compressed_call = buffer[..compressed].to_vec();

		let res = pallet_call_decompressor::Pallet::<Test>::decompress_call(
			RuntimeOrigin::none(),
			final_compressed_call.to_vec(),
			encoded.len() as u32,
		)
		.err()
		.unwrap();

		assert_eq!(
			res,
			DispatchError::Module(ModuleError {
				index: 10,
				error: [3, 0, 0, 0],
				message: Some("ErrorDecodingCall")
			})
		);
	});
}

## Sending Tokens Cross-Chain

To make a cross-chain transfer, dispatch the `send` extrinsic:

```rust lineNumbers
pub struct SendParams<AssetId, Balance> {
    /// Local asset ID
    pub asset_id: AssetId,
    /// Destination state machine
    pub destination: StateMachine,
    /// Recipient account on the destination chain (up to 32 bytes)
    pub recipient: BoundedVec<u8, ConstU32<32>>,
    /// Amount to send (in local denomination)
    pub amount: Balance,
    /// Request timeout in seconds
    pub timeout: u64,
    /// Relayer fee
    pub relayer_fee: Balance,
    /// Optional calldata to execute on the destination chain
    pub call_data: Option<Vec<u8>>,
}
```

| Parameter | Description |
|-----------|-------------|
| `asset_id` | The local asset ID for the asset to transfer. |
| `destination` | The destination chain. |
| `recipient` | The beneficiary account on the destination. For EVM chains, use the 20-byte address. For substrate chains, use the 32-byte AccountId. |
| `amount` | The amount to transfer in local denomination. Automatically converted to the destination chain's precision. |
| `timeout` | Request timeout in seconds. |
| `relayer_fee` | Fee paid to relayers for delivering the request. |
| `call_data` | Optional SCALE-encoded `SubstrateCalldata` to execute on the destination chain after the transfer. |
