### Title
Unauthenticated LOOP plugin pprof/metrics proxy endpoints allow local disruption and information disclosure - (File: core/web/router.go)

### Summary
Chainlink core exposes LOOP-plugin diagnostic endpoints (`/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*`, `/plugins/:name/debug/pprof/symbol`) via `loopRoutes` registered directly on the top-level `api` group, which only carries rate-limiting and session middleware — no authentication is applied, unlike the equivalent core-node `metricRoutes(authv2)` registration which is explicitly gated behind session/token auth.

### Finding Description
In `core/web/router.go`, `NewRouter` builds an `api` group with only `sessions.Sessions(...)` and rate limiting (`core/web/router.go:78-91`), and calls `loopRoutes(app, api)` directly on it: [1](#0-0) 
Compare this to the core node's own pprof/expvar debug endpoints, which are deliberately wrapped in `auth.Authenticate(...)`: [2](#0-1) 
and again reiterated as "Debug routes accessible via authentication" inside the authenticated `authv2` group: [3](#0-2) 

However, `loopRoutes` itself applies no `auth.Authenticate` middleware at all: [4](#0-3) 

The handlers backing these routes, in `core/web/loop_registry.go`, proxy requests straight through to each LOOP plugin's internal pprof/metrics HTTP server without any authorization check: [5](#0-4) [6](#0-5) 

This is structurally analogous to the reported Cilium/Envoy bug class: a diagnostic/admin-style interface (pprof full profile/trace, heap dumps, and metrics) that should require privilege is instead reachable by any client able to reach the node's HTTP listener, because the intended authentication wrapper (present for the core node's own `/debug/*` and `metricRoutes`) was never applied to the parallel LOOP-plugin proxy routes.

### Impact Explanation
- **Information disclosure**: `pprof` heap/goroutine/trace dumps and Prometheus `/metrics` output from LOOP plugins (e.g., relayer/median/OCR plugins) can leak internal state, in-memory data, and operational details to any unauthenticated caller with network access to the node's web server.
- **Disruption**: `pprof/profile` and `/trace` accept a `seconds` query parameter (`pprofURLVals`, `core/web/loop_registry.go:132-148`) that is forwarded to the plugin's pprof server and can be used to tie up plugin resources for extended windows; combined with lack of rate limiting/auth this is an easy DoS vector against LOOP plugins, mirroring the Envoy admin-socket "terminate/disrupt" impact category from the analog report.
- This matches the CVSS profile of the analog (`AV:L/PR:N` characteristics translated to "any client reaching the node's web server, no privilege required").

### Likelihood Explanation
Reaching these endpoints requires only network access to the Chainlink node's web server port and knowledge of/enumeration of plugin names (which can also be enumerated via the unauthenticated `/discovery` endpoint itself, which lists all registered plugins and their metrics paths — `core/web/loop_registry.go:53-81`). No credentials, tokens, or session cookies are needed. This makes the path trivially reachable whenever LOOP plugins are deployed and the node's web server is exposed (even to an internal/adjacent network), which is a common deployment pattern.

### Recommendation
Wrap `loopRoutes` registration with the same `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)` (or token) middleware used for `debugRoutes`/`metricRoutes`, or move it into the authenticated `authv2`/`api`-with-auth group so that `/discovery`, `/plugins/:name/metrics`, and `/plugins/:name/debug/pprof/*` all require an authenticated session/API token, consistent with the core node's own debug endpoints.

### Proof of Concept
Given a running node with a LOOP plugin registered (e.g., name `median`), an unauthenticated request:
```
curl http://<node-host>:6688/discovery
curl http://<node-host>:6688/plugins/median/metrics
curl "http://<node-host>:6688/plugins/median/debug/pprof/profile?seconds=30"
```
succeeds without any `Authorization`/session cookie, because `loopRoutes(app, api)` in `core/web/router.go:91` is not gated by `auth.Authenticate`, unlike the equivalent `metricRoutes(authv2)` call at `core/web/router.go:446`.

func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/metrics", l.loopHostName, p.EnvCfg.PrometheusPort)
	req, err := http.NewRequestWithContext(gc.Request.Context(), http.MethodGet, pluginURL, nil)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)
	if err != nil {
		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q metrics", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
