### Title
Unbounded, TTL-only in-memory bid cache lets a mempool-only `place_bid` flood exhaust intents-coprocessor RPC node memory — (File: modules/pallets/intents-coprocessor/rpc/src/lib.rs)

### Summary
The QEMU CVE is a memory-leak DoS: repeated, cheap "unplug" operations by a local actor cause unbounded host memory growth until the process crashes. The closest reachable analog in Hyperbridge is `BidCache` in `modules/pallets/intents-coprocessor/rpc/src/lib.rs`, which any unprivileged intent bidder/filler can grow without bound by repeatedly broadcasting `place_bid` transactions into the local node's transaction pool — before those transactions are ever included in a block.

### Finding Description
`run_bid_watcher` subscribes to the transaction pool's `import_notification_stream` and, for every transaction that becomes "ready" in the pool, decodes it and calls `bid_cache.insert(commitment, filler, user_op)` [1](#0-0) . `BidCache::insert` stores an entry in a `HashMap<H256, OrderBids>` keyed by order commitment, with each `OrderBids` holding a `Vec<BidEntry>` (arbitrary `filler` and `user_op` byte vectors) [2](#0-1) .

The only eviction path is a periodic, TTL-based sweep (`remove_expired`) driven by a fixed `cleanup_interval` timer, which purges an entire order's bids only once `now - first_seen >= ttl` [3](#0-2) [4](#0-3) . There is no cap on:
- the number of distinct order commitments tracked,
- the number of distinct fillers (bid entries) per commitment, or
- the size of the `user_op` payload per bid.

Critically, entry into the cache is gated only by a transaction reaching the "ready" state in the local mempool, not by block inclusion, finality, or even eventual validity of the underlying intent. Any account able to submit a signed `place_bid` extrinsic that passes pool admission (nonce/signature/fee-affordability checks) triggers a cache insertion, regardless of whether the transaction is later dropped, replaced, or never mined. An attacker (a bidder/filler — one of the explicitly in-scope unprivileged roles) can therefore submit a sustained stream of distinct `place_bid` transactions (varying commitment and/or filler address, each with a sizeable `user_op`) faster than the TTL sweep interval reclaims them, growing the `HashMap` and its `Vec<BidEntry>` payloads without bound until the RPC/full node process exhausts memory and crashes — the direct analog of the QEMU `wdt_i6300esb` unplug-loop memory leak causing host memory consumption and process crash.

### Impact Explanation
This targets availability of a node process that serves the intents subsystem's `intents_getBidsForOrder`/`intents_subscribeBids` RPCs and mempool-bid propagation used by solvers to discover competing bids in sub-second time. A memory-exhaustion crash of this process is a denial of service against bid discovery for the intents/order-filling pipeline — solvers relying on this fast path lose visibility into mempool bids, degrading price competition and fill routing (a route unable to deliver/serve messages in the intents flow), and repeated crashes/restarts constitute an availability-impacting DoS on infrastructure any unprivileged participant can reach without needing transactions to ever be mined.

### Likelihood Explanation
Reachability is straightforward: the trigger is simply getting transactions accepted into a node's ready tx pool, which any account with enough balance to pass fee-affordability checks (or even zero-cost calls, depending on runtime fee config) can do repeatedly. No governance, admin, or special role is required — this is exactly the kind of action an ordinary intent bidder performs. The severity is bounded by tx-pool admission costs and pool size limits imposed by the node's transaction-pool configuration, and cache entries are eventually reclaimed on the TTL boundary, so the attack requires a sustained flood outrunning the cleanup interval rather than a single cheap call. This keeps likelihood at Medium rather than High/Critical.

### Recommendation
Bound the `BidCache` independent of time-based expiry: cap total tracked commitments and bids-per-commitment (evicting oldest/least-relevant on overflow), cap `user_op`/`filler` byte lengths accepted into the cache, and/or require the underlying `place_bid` extrinsic itself to enforce a `BoundedVec` size limit and a pool-slot cost that scales with cache pressure. Consider inserting into the cache only after the transaction has been included/finalized (or after a stricter pre-validation), rather than purely on tx-pool "ready" notification, to remove the free/never-mined amplification vector.

### Proof of Concept
1. Run a Hyperbridge parachain node exposing the intents-coprocessor RPC (`run_bid_watcher` wired in `parachain/node/src/service.rs`).
2. From N distinct signer accounts (funded minimally to pass pool fee checks), submit `place_bid(commitment, user_op)` extrinsics continuously, using unique or rotating `commitment`/`filler` values and maximally-sized `user_op` payloads, at a rate exceeding `cleanup_interval` × TTL reclamation throughput.
3. Observe `import_notification_stream` firing for each pool-admitted transaction and `bid_cache.insert` growing the `HashMap`/`Vec<BidEntry>` set in `modules/pallets/intents-coprocessor/rpc/src/lib.rs` [1](#0-0)  regardless of whether these transactions are later included in a block.
4. Monitor the node process RSS climbing unbounded until OOM/crash, confirming no cap exists on cache size or entry payload length in `BidCache` [5](#0-4) .

struct BidEntry {
	filler: Vec<u8>,
	user_op: Vec<u8>,

#[derive(Clone, Debug)]
struct OrderBids {
	first_seen: Instant,
	entries: Vec<BidEntry>,
}

/// In-memory bid cache.
pub struct BidCache {
	bids: RwLock<HashMap<H256, OrderBids>>,
	ttl: Duration,
}

impl BidCache {
	pub fn new(ttl: Duration) -> Self {
		Self { bids: RwLock::new(HashMap::new()), ttl }
	}

	pub fn insert(
		&self,
		commitment: H256,
		filler: Vec<u8>,
		user_op: Vec<u8>,
	) -> Result<(), String> {
		let entry = BidEntry { filler: filler.clone(), user_op };

		let mut bids = self.bids.write().map_err(|e| format!("BidCache lock poisoned: {e}"))?;
		let order = bids
			.entry(commitment)
			.or_insert_with(|| OrderBids { first_seen: Instant::now(), entries: Vec::new() });
		if let Some(existing) = order.entries.iter_mut().find(|e| e.filler == filler) {
			*existing = entry;
		} else {
			order.entries.push(entry);
		}
		Ok(())
	}

	pub fn remove_expired(&self) -> Result<(), String> {
		let now = Instant::now();
		let mut bids = self.bids.write().map_err(|e| format!("BidCache lock poisoned: {e}"))?;
		bids.retain(|_commitment, order| now.duration_since(order.first_seen) < self.ttl);

	}
