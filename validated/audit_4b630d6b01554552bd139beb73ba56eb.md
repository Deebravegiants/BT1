### Title
Webhook shop/topic identity spoofing via unauthenticated headers - (File: lib/shopify_api/webhooks/request.rb)

### Summary
The webhook HMAC only authenticates the raw request body; it does not bind the `shop-domain`, `topic`, `webhook-id`, or `api-version` headers used to route and identify the tenant for the webhook.

### Finding Description
`HmacValidator.validate` computes the signature over `verifiable_query.to_signable_string`, and for `Webhooks::Request` that method returns only `@raw_body` [1](#0-0) [4](#0-3) . Meanwhile `shop`, `topic`, `webhook_id`, and `api_version` are all pulled directly from HTTP headers via `shopify_header`, with no cryptographic linkage to the body or to each other [2](#0-1) . `Registry.process` validates only the HMAC before dispatching `WebhookMetadata.new(topic: request.topic, shop: request.shop, body: request.parsed_body, ...)` to the app's registered handler [3](#0-2) .

Since Shopify webhooks for a given app are all signed with the same app-level `api_secret_key` (not a per-shop secret), any body+HMAC pair that is valid for one shop's webhook delivery is also a byte-for-byte valid signature for that same body sent with **different** `shop-domain`/`topic`/`webhook-id` headers. This breaks the intended binding: `HMAC-authenticated bytes (body)` == `identity used to act (shop header)`. Before the attacker's replay, the body was authenticated *and* correctly attributed to the originating shop; after replaying the identical body with a substituted `shop-domain` header, the body is still authenticated (HMAC passes) but is now falsely attributed to an arbitrary shop of the attacker's choosing.

### Impact Explanation
A merchant who has installed the app on their own store can capture a legitimately Shopify-signed webhook payload/HMAC (e.g. from an event they trigger themselves) and resend it to the app's webhook endpoint with a forged `x-shopify-shop-domain` header pointing at a victim tenant, and/or a forged `x-shopify-topic` header to trigger a different handler than the one that produced the body. Because `Registry.process` only checks the HMAC over the body, this passes validation, and the handler executes for the impersonated shop and/or the impersonated topic. If handlers key off `WebhookMetadata#shop` to look up/act on shop-specific records (the documented usage pattern), this results in cross-tenant data corruption or disclosure — a Critical-class impact.

### Likelihood Explanation
Exploitation requires only that the attacker control one legitimate app installation (their own store) to obtain a validly-signed webhook body, then freely alter unauthenticated headers on replay to any endpoint reachable from the internet. No access token, `client_secret`, or privileged account is required — only a standard merchant relationship with the app, satisfying the "unprivileged internet user" threat model.

### Recommendation
Include the routing/identity fields (`shop-domain`, `topic`, and ideally `webhook-id`) in the signable string that is HMAC-verified, or otherwise cryptographically bind them to the body (e.g., re-derive/validate `shop` against a value embedded in the verified body, or maintain a per-shop webhook secret). At minimum, cross-check the `shop-domain` header against an expected/registered shop before invoking handlers.

### Proof of Concept
1. App merchant M installs the app on `m.myshopify.com` and triggers an event (e.g., `orders/create`) so Shopify sends a legitimately HMAC-signed webhook with body `B` and headers `shop-domain: m.myshopify.com`, `topic: orders/create`.
2. M records `B` and the `X-Shopify-Hmac-Sha256` value.
3. M sends a POST to the app's webhook endpoint with body `B` unchanged, `X-Shopify-Hmac-Sha256` unchanged, but `shop-domain: victim.myshopify.com`.
4. `Utils::HmacValidator.validate` recomputes HMAC over `B` only, matches, and returns `true` [5](#0-4) .
5. `Registry.process` invokes the `orders/create` handler with `shop: "victim.myshopify.com"` [6](#0-5) , causing the app to act on/attribute data to `victim.myshopify.com` using attacker-supplied body content.
