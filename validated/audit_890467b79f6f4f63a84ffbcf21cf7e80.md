### Title
Bad-debt index floor preserves wiped supply shares and drains later deposits - (File: contracts/pool/src/interest.rs)

### Summary
When bad debt equals or exceeds total supplied value, `apply_bad_debt_to_supply_index` computes a zero residual index but clamps it back to `SUPPLY_INDEX_FLOOR_RAW`, leaving every pre-wipe scaled supply position with a nonzero claim. [1](#0-0)  An attacker who keeps an unrelated supply position can permissionlessly trigger the cleanup and later withdraw that phantom claim against a new depositor’s cash. [2](#0-1) [3](#0-2) 

### Finding Description
`apply_bad_debt_to_supply_index` caps `bad_debt` at `total_supplied_value`, so a full wipeout makes `remaining` zero and `new_supply_index` zero, but the final `.max(SUPPLY_INDEX_FLOOR_RAW)` stores a nonzero index instead. [4](#0-3)  The stored `supplied` share total and all controller-side scaled positions remain unchanged, so they are revived at approximately 0.1% of their original value whenever fresh liquidity arrives. [5](#0-4) [6](#0-5) 

The permissionless cleanup path builds deposit-seizure and borrow-seizure entries for the insolvent account and sends them to the pool. [7](#0-6)  On the borrow side, the pool unscales the debt, calls `apply_bad_debt_to_supply_index`, and burns the debt, but it does not burn unrelated suppliers’ shares or otherwise mark them as wiped. [8](#0-7) 

A later withdrawal resolves the stale scaled position against the floored supply index, checks only that the pool has enough cash for that withdrawal, and then debits cash. [9](#0-8) [10](#0-9)  The codebase’s own regression-style test demonstrates this exact sequence: a wiped survivor retains a stranded claim, a fresh deposit credits cash, and the survivor withdraws the entire fresh deposit while the fresh supplier remains under-backed. [11](#0-10) 

### Impact Explanation
This is theft of user funds and creates protocol insolvency in the affected market. [12](#0-11)  After a full supply write-down, an old supplier can redeem shares that should represent zero against tokens deposited by later suppliers, leaving the later suppliers’ booked claims larger than the remaining cash. [13](#0-12) 

The extractable amount is bounded by the residual value of pre-wipe shares at the supply-index floor, but can be substantial because every pre-wipe supplier retains that residual claim. [14](#0-13) [15](#0-14) 

### Likelihood Explanation
The attacker must first hold supply shares in the borrowed market and then cause or wait for an account whose debt in that market reaches the full-write-down condition while its remaining collateral is at or below the dust threshold. [16](#0-15) [17](#0-16)  This requires a severe bad-debt event, but triggering the cleanup itself is permissionless and requires only caller authorization. [2](#0-1) [3](#0-2) 

The attacker does not need privileged access, storage manipulation, oracle misbehavior, or control of the victim deposit; they only need to be among the pre-wipe suppliers and execute a normal withdrawal afterward. [18](#0-17) [19](#0-18) 

### Recommendation
Do not clamp a fully wiped supply index back to a nonzero value while retaining pre-wipe share balances. [4](#0-3)  On `remaining == 0`, either zero the market’s scaled supply and revenue and make all pre-wipe positions unredeemable, or introduce a write-down epoch/share generation so newly minted supply cannot be claimed by pre-wipe positions. [5](#0-4) [9](#0-8)  Add an end-to-end controller test covering `clean_bad_debt`, a surviving third-party supplier, a fresh deposit, and withdrawal of the old position. [20](#0-19) 

### Proof of Concept
```text
// Precondition: listed markets D (debt asset) and C (collateral asset)
// exist on the same spoke, and market D initially has total supplied S.

1. Attacker calls:
   supply(attacker, 0, spoke_id, [(D, attacker_supply)])
   -> account_A with scaled supply S_A.

2. Attacker calls:
   supply(attacker, 0, spoke_id, [(C, collateral)])
   -> account_B.

3. Attacker calls:
   borrow(attacker, account_B, [(D, borrowed_amount)], Some(attacker))
   where borrowed_amount is close to the available D liquidity.

4. After C's value falls until account_B's collateral is <= the bad-debt
   dust threshold and D debt >= the D market's supplied value, attacker calls:
   clean_bad_debt(attacker, account_B)

   The borrow-seize leg calls apply_bad_debt_to_supply_index and stores
   SUPPLY_INDEX_FLOOR_RAW, while attacker's unrelated S_A shares remain.

5. Victim calls:
   supply(victim, 0, spoke_id, [(D, stranded_claim)])

6. Attacker calls:
   withdraw(attacker, account_A, [(D, 0)], Some(attacker))

   `0` maps to the withdraw-all sentinel, the pool resolves S_A at the
   nonzero floor index, and the victim's cash is transferred to attacker.
```
The controller accepts zero as a full withdrawal and forwards the withdraw-all sentinel to the pool. [18](#0-17) [19](#0-18)  The existing test `test_raw_cache_seizure_residual_would_drain_fresh_cash_without_supply_guard` demonstrates the same state transition and ends with the fresh supplier’s claim exceeding remaining cash. [21](#0-20)

```rust
pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
```

```rust
fn test_raw_cache_seizure_residual_would_drain_fresh_cash_without_supply_guard() {
    let t = TestSetup::new();
    t.as_contract(|| {
        let alice_scaled_raw = 1_000 * RAY;
        let borrowed_scaled_raw = 1_000 * RAY;
        let mut cache = t.fresh_cache(PoolStateRaw {
            supplied: alice_scaled_raw,
            borrowed: borrowed_scaled_raw,
            revenue: 0,
            borrow_index: RAY,
            supply_index: RAY,
            last_timestamp: 0,
            cash: 0,
        });
        let alice_scaled = Ray::from(alice_scaled_raw);
        let borrow_scaled = Ray::from(borrowed_scaled_raw);

        let bad_debt = cache.unscale_borrow_ceil_ray(borrow_scaled);
        apply_bad_debt_to_supply_index(&mut cache, bad_debt);
        cache.burn_debt(borrow_scaled);

        assert_eq!(
            cache.supply_index().raw(),
            SUPPLY_INDEX_FLOOR_RAW,
            "seize wipeout clamps supply_index UP to RAY/1000, leaving unburned shares a residual"
        );

        let alice_stranded = cache.unscale_supply_floor(alice_scaled);
        assert!(alice_stranded > 0, "wiped survivor keeps a stranded claim");
        assert_eq!(
            cache.cash(),
            0,
            "empty market: claim masked by require_reserves"
        );

        let deposit = alice_stranded;
        let bob_scaled = cache.calculate_scaled_supply(deposit);
        cache.mint_supply(bob_scaled);
        cache.credit_cash(deposit);

        let total_owed = cache.unscale_supply_floor(cache.supplied());
        assert!(
            total_owed > cache.cash(),
            "post-deposit books insolvent: owed {} > cash {}",
            total_owed,
            cache.cash()
        );

        let (burn, gross) = cache.resolve_withdrawal(i128::MAX, alice_scaled);
        cache.require_reserves(gross);
        cache.burn_supply(burn);
        cache.debit_cash(gross);

        assert!(gross > 0, "wiped position pays out real cash");
        assert_eq!(gross, deposit, "Alice extracts exactly Bob's fresh deposit");

        let bob_claim = cache.unscale_supply_floor(bob_scaled);
        assert!(
            cache.cash() < bob_claim,
            "cash {} cannot cover Bob's honest claim {}: fresh depositor lost funds",
            cache.cash(),
            bob_claim
        );
```
