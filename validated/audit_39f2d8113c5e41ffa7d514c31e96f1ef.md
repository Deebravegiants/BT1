### Title
Token Exchange accepts non-admin session tokens without validating the `iss` claim, allowing scope escalation - (File: `lib/shopify_api/auth/token_exchange.rb`)

### Summary
`ShopifyAPI::Auth::TokenExchange.exchange_token` derives the target shop purely from the session token's `dest` claim and only checks that the token's `aud` claim matches the configured API key. It never verifies that the token's `iss` claim marks it as an *admin* session token before using it to request a privileged (online or offline) admin access token via the token-exchange grant.

### Finding Description
`JwtPayload` exposes an `admin_session_token?` helper that checks whether `iss` ends with `/admin`, and this helper is deliberately used to gate `shopify_user_id`: [1](#0-0) [2](#0-1) 

The test suite confirms that the very same `JwtPayload` class and secret are used to mint and validate **both** admin session tokens (`iss: ".../admin"`) and non-admin tokens such as checkout UI extension session tokens (`iss: ".../checkouts"`): [3](#0-2) [4](#0-3) 

`JwtPayload#initialize` only enforces `aud == Context.api_key`; it never checks `iss` at construction time: [5](#0-4) 

`TokenExchange.exchange_token` takes an arbitrary `session_token`, builds a `JwtPayload` from it, and unconditionally trusts `jwt_payload.shop` (the `dest` claim) as the shop to exchange a privileged admin access token for — it never calls `admin_session_token?` or otherwise validates `iss`: [6](#0-5) 

The identity binding that should hold is:
`token.iss == "https://{shop}/admin"` (i.e., "this is an admin session token") **==** "the token is eligible to be exchanged for an admin access token".

Because the gem never checks the left-hand side, any correctly-signed session token issued for a *different, lower-privileged surface* (e.g., a checkout UI extension token, which is signed with the same `api_secret_key`/`api_key` pair and thus passes the `aud` check) is treated identically to an admin session token. The library will happily forward it to Shopify's `/admin/oauth/access_token` token-exchange endpoint together with the app's `client_secret`, requesting an **online or offline admin access token** for the shop named in `dest`.

Contrast this with the other OAuth flows in the same file, which explicitly sanitize/validate the shop before using it in the same code path: [7](#0-6) [8](#0-7) 

`exchange_token` has no equivalent guard for the *type* of the presented token, only for the shop string format.

### Impact Explanation
If a lower-privilege, buyer-facing session token (such as a checkout UI extension id-token, which is exposed to script running in a buyer's browser context and is not intended to grant Admin API access) is captured or replayed by an unprivileged party and submitted to a host app's endpoint that calls `TokenExchange.exchange_token`, the gem will exchange it for an Admin API access token scoped to the shop, without ever having verified the token was actually minted for the Admin surface. This is a scope/privilege check that answers permissively — a token confusion / privilege-escalation vector that can result in issuance of a merchant-scoped admin access token to a party who only ever held a buyer-scoped token. This falls under "scope or expiry check bypass" (High).

### Likelihood Explanation
Exploitability depends on an attacker being able to obtain a valid, non-expired session token that was not intended for admin use (e.g., a checkout UI extension token) and getting it fed into a host application's token-exchange endpoint. The gem itself places no barrier in the way of this once such a token is presented — the only gate (`aud == api_key`) is trivially satisfied by any token type issued for the same app.

### Recommendation
In `TokenExchange.exchange_token`, require `jwt_payload` to satisfy `admin_session_token?` (or an equivalent explicit `iss` check) before proceeding, raising `ShopifyAPI::Errors::InvalidJwtTokenError` otherwise — mirroring how `admin_session_token?` already gates `shopify_user_id` in `JwtPayload`.

### Proof of Concept
1. Mint a valid, correctly-signed session token with `iss: "https://shop.myshopify.io/checkouts"`, `aud: <app api_key>`, `dest: "https://shop.myshopify.io"` (as in `test_decode_jwt_payload_coming_from_checkout_ui_extension`, `lib/shopify_api/auth/jwt_payload.rb`/`test/auth/jwt_payload_test.rb:154-174`).
2. Call `ShopifyAPI::Auth::TokenExchange.exchange_token(session_token: checkout_token, requested_token_type: RequestedTokenType::OFFLINE_ACCESS_TOKEN)`.
3. Observe that `exchange_token` proceeds (`lib/shopify_api/auth/token_exchange.rb:29-65`) — no exception is raised for the non-admin `iss`, and the gem sends `client_id`, `client_secret`, and the checkout token as `subject_token` to `/admin/oauth/access_token`, requesting an admin-scoped access token.

        def exchange_token(session_token:, requested_token_type:, shop: nil)
          unless ShopifyAPI::Context.setup?
            raise ShopifyAPI::Errors::ContextNotSetupError,
              "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise ShopifyAPI::Errors::UnsupportedOauthError,
            "Cannot perform OAuth Token Exchange for private apps." if ShopifyAPI::Context.private?
          raise ShopifyAPI::Errors::UnsupportedOauthError,
            "Cannot perform OAuth Token Exchange for non embedded apps." unless ShopifyAPI::Context.embedded?

          # Validate the session token and use the shop from the token's `dest` claim
          jwt_payload = ShopifyAPI::Auth::JwtPayload.new(session_token)
          dest_shop = jwt_payload.shop

          if shop
            ShopifyAPI::Logger.deprecated(
              "The `shop` parameter for `exchange_token` is deprecated and will be removed in v17. " \
                "The shop is now always taken from the session token's `dest` claim.",
              "17.0.0",
            )
          end

          shop_session = ShopifyAPI::Auth::Session.new(shop: dest_shop)
          body = {
            client_id: ShopifyAPI::Context.api_key,
            client_secret: ShopifyAPI::Context.api_secret_key,
            grant_type: TOKEN_EXCHANGE_GRANT_TYPE,
            subject_token: session_token,
            subject_token_type: ID_TOKEN_TYPE,
            requested_token_type: requested_token_type.serialize,
          }

          if requested_token_type == RequestedTokenType::OFFLINE_ACCESS_TOKEN
            body.merge!({ expiring: ShopifyAPI::Context.expiring_offline_access_tokens ? 1 : 0 })
          end

          client = Clients::HttpClient.new(session: shop_session, base_path: "/admin/oauth")
