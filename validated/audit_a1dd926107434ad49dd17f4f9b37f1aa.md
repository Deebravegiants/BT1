Audit Report

## Title
Unauthenticated exposure of LOOP plugin `pprof` debug/profiling and metrics proxy endpoints - (File: `core/web/router.go`, `core/web/loop_registry.go`)

## Summary
`loopRoutes` registers `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` on the top-level `api` router group in `NewRouter`, which is protected only by rate-limiting and session middleware — no `auth.Authenticate(...)` wrapper is applied, unlike every other sensitive route family registered in the same function (`debugRoutes`, `v2Routes`'s `authv2` group, and `metricRoutes` which is only mounted inside `authv2`). This allows any unauthenticated network client that can reach the node's HTTP listener to pull full Go `pprof` profiles (heap, goroutine, trace, CPU profile) from any registered LOOP plugin process.

## Finding Description
In `core/web/router.go`, the `api` group is created with only rate limiting and session middleware: [1](#0-0) . `loopRoutes(app, api)` is then called directly on this unauthenticated group alongside `debugRoutes`, `healthRoutes`, `sessionRoutes`, and `v2Routes`: [2](#0-1) .

Comparing to sibling route registrations in the same file: `debugRoutes` explicitly requires session authentication via `auth.Authenticate(...)` before exposing `/debug/vars`: [3](#0-2) . Similarly, the raw `pprof.*` handlers in `metricRoutes` are only ever mounted on the authenticated `authv2` group: [4](#0-3) .

`loopRoutes`, in contrast, registers the pprof-proxying and metrics-proxying handlers directly on `api` with zero auth wrapper: [5](#0-4) .

The handlers in `core/web/loop_registry.go` forward the incoming request to an internal plugin's pprof/metrics HTTP server based solely on the `:name` path parameter (a plugin name such as `median`, `solana`, `starknet`), with no additional authorization check: `pluginMetricHandler` [6](#0-5) , and `pluginPPROFHandler` [7](#0-6) . The code comments even acknowledge these are meant to be internal ("unlike discovery, this endpoint is internal btw the node and plugin"), confirming the developer's intent diverges from the actual (missing) access control.

This is a genuine broken-access-control bug: a debug/introspection surface capable of returning full Go runtime heap/goroutine/CPU profile data is reachable by any unauthenticated actor because it was wired into the router outside of the authentication middleware chain (`auth.Authenticate`) that protects every comparable sensitive route in the same file.

## Impact Explanation
An unauthenticated network client that can reach the node's web server can pull full `pprof` profiles (`heap`, `goroutine`, `trace`, arbitrary `debug=N`/`seconds=N` CPU profiles) and Prometheus metrics from any registered LOOP plugin process without credentials. Heap/goroutine dumps can contain sensitive in-process data handled by the plugin (e.g., key material, secrets, connection strings), constituting an information-disclosure impact, and repeated CPU-profile/trace requests could be used to degrade plugin availability. This maps to an in-scope "key/secret exfiltration" / node API authentication bypass impact category, though the actual presence of secrets in any given profile is not guaranteed (weaker than a deterministic secret leak).

## Likelihood Explanation
Any client able to reach the node's HTTP listener can enumerate registered plugin names (a small, discoverable/guessable set) and issue `GET /plugins/<name>/debug/pprof/heap` or similar with no credentials, since the route sits entirely outside the authenticated route groups (`api.Group("/debug", auth.Authenticate(...))`, `authv2`). This is directly and repeatably triggerable by an unprivileged actor with no operator/admin access required.

## Recommendation
Wrap the pprof-proxying routes (`/plugins/:name/debug/pprof/*profile`, `/plugins/:name/debug/pprof/symbol`) — and ideally `/plugins/:name/metrics` — in the same `auth.Authenticate(...)` middleware used by `debugRoutes`/`authv2`, reserving unauthenticated access only to the coarse `/discovery` endpoint if it must remain scrapeable by external Prometheus without credentials (or gate it via network-level controls instead).

## Proof of Concept
1. Start a chainlink node with a LOOP plugin registered (e.g. `median`, `solana`), per `plugins.LoopRegistry` wiring in `core/services/chainlink`.
2. As an unauthenticated client (no session cookie, no API token), issue: `curl http://<node-host>:6688/plugins/median/debug/pprof/heap?debug=1`.
3. Observe the handler chain `loopRoutes` (`core/web/router.go:230-236`) → `pluginPPROFHandler` (`core/web/loop_registry.go:150-166`) returns the full heap profile of the plugin process with HTTP 200 and no authentication challenge, in contrast to `curl http://<node-host>:6688/debug/vars`, which requires a valid session per `debugRoutes` (`core/web/router.go:180-183`).

```go
func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/metrics", l.loopHostName, p.EnvCfg.PrometheusPort)
	req, err := http.NewRequestWithContext(gc.Request.Context(), http.MethodGet, pluginURL, nil)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)
	if err != nil {
		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q metrics", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}
```

```go
func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
```
