## Title
Manipulable Uniswap V4 spot price used to size intent fills — flash-loan price manipulation drains solver liquidity ([File: sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts])

### Summary
The Sherlock report flags `CurveV1StableEthOracle.getPriceInEth` for pricing an LP token off a single-block, un-TWAP'd read of underlying pool state, letting a flash loan skew the derived price and extract value. The Simplex intent-filler component of this repo has the same bug class: `UniswapV4FundingPlanner.getExoticTokenPrice` / `computeDirectPoolPriceUsd` price a cross-chain intent fill directly off the live `sqrtPriceX96` of a Uniswap V4 pool — an instantaneous spot price with no TWAP, and the only mitigation (`checkPriceGuard`) is optional and left disabled by default.

### Finding Description
`computeDirectPoolPriceUsd` derives the USD price of the "exotic" token straight from `sdkPool.token0Price`/`token1Price`, which is computed from the pool's current `sqrtPriceX96`: [1](#0-0) 

This spot price is what `getExoticTokenPrice` returns, selecting the highest-liquidity pool's instantaneous quote (still just a spot value, not time-weighted): [2](#0-1) 

That price feeds `resolveLegRates` in `FXFiller`, which inverts it into the leg's exchange rate and uses it to size the fill amount for an incoming Hyperbridge intent order: [3](#0-2) 

The only defense is `checkPriceGuard`, which compares the live venue quote against a static `referencePrice`/`maxDeviationBps` — and this guard is explicitly optional, "omit both to leave the chain unguarded": [4](#0-3) [5](#0-4) 

Even when configured, the guard only bounds deviation from a fixed reference and is checked against the same manipulable live pool read used for pricing — it does not use a TWAP, so an attacker can push the price anywhere inside the configured band (or fully unconstrained when unguarded) via a flash loan against the V4 pool immediately before the solver quotes/fills the order.

### Impact Explanation
An attacker who flash-loan-manipulates the Uniswap V4 pool referenced by `[vault.uniswapV4]` can force the Simplex solver to size a cross-chain intent fill at a distorted rate. Because the solver funds fills by withdrawing liquidity from its own V4 positions (`planWithdrawalForToken` / `buildRemoveLiquidityCall`), a mispriced fill directly transfers excess value from the solver's LP inventory to the attacker's counter-order, a concrete theft of solver-held funds backing Hyperbridge intent fulfillment. This is High severity: it is a direct, fund-draining oracle manipulation on a component that custodies liquidity used to fill user intents.

### Likelihood Explanation
Likelihood is high for chains/pairs configured under `[vault.uniswapV4]` without `referencePrice`/`maxDeviationBps` (guard is optional and clearly documented as "unguarded" without it), and non-trivial even when guarded since the guard band itself is checked against the same spot read and only bounds — not eliminates — the achievable skew. Triggering it only requires submitting an intent order timed with a flash-loan swap against the referenced pool, both of which are actions available to an ordinary, unprivileged intent submitter.

### Recommendation
Replace the instantaneous `sqrtPriceX96`-derived spot price in `computeDirectPoolPriceUsd` with a TWAP (e.g., Uniswap V4 pool observations) or require the `referencePrice`/`maxDeviationBps` guard to be mandatory (not optional) for every `[vault.uniswapV4]` position, and tighten `maxDeviationBps` defaults so a single-block manipulation cannot pass even when configured.

### Proof of Concept
1. Attacker identifies a `[vault.uniswapV4]` pair configured without `referencePrice`/`maxDeviationBps` (unguarded per the docs) or with a wide `maxDeviationBps`.
2. Attacker flash-loans a large amount of the pool's stable/exotic token and swaps to move `sqrtPriceX96` far from the true market price.
3. In the same block/transaction window, attacker submits a Hyperbridge intent order sized to be filled from that same pool's exotic-token leg.
4. `FXFiller.resolveLegRates` → `UniswapV4FundingPlanner.getExoticTokenPrice` reads the manipulated spot price, `checkPriceGuard` passes (absent or within the wide band), and the solver withdraws liquidity via `planWithdrawalForToken` to fund the fill at the skewed rate.
5. Attacker repays the flash loan, unwinding the price, and keeps the excess tokens extracted from the solver's position. [6](#0-5)

```typescript
	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}
```

```typescript
	/**
	 * Validates a live venue quote against the static reference price for the chain.
	 * Returns true (pass) when no guard is configured, or no reference exists for the
	 * chain. Returns false when the quote (token1 per USD) deviates from the reference
	 * by more than `maxDeviationBps`, in which case the order must not be filled.
	 */
	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {
			this.logger.warn(
				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
	}
```

```text
## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.
```
