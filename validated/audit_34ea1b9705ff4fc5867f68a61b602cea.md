Audit Report

## Title
Plaintext passwords leaked in Debug-level HTTP request logs for GraphQL mutations due to non-recursive JSON redaction - (File: `core/web/router.go`)

## Summary
The `loggerFunc` middleware, registered globally via `engine.Use()` and thus wrapping the `/query` GraphQL endpoint, logs the sanitized request body at Debug level using `readSanitizedJSON`. That function only redacts top-level JSON keys against a `password`-related blacklist, but GraphQL requests nest sensitive fields (`password`, `oldPassword`, `newPassword`) inside a `variables` object, so they bypass redaction and are written to logs in plaintext.

## Finding Description
`loggerFunc` reads the full request body and, after the handler runs, logs it via `readBody` → `readSanitizedJSON` at `core/web/router.go` lines 556-562 and 588-606. `readSanitizedJSON` unmarshals into a flat `map[string]any` and only checks top-level keys against `isBlacklisted` (lines 608-629, 652-658). For a GraphQL request body such as `{"query": "...", "variables": {"input": {"password": "..."}}}` (matching `CreateAPITokenInput.password` and `UpdatePasswordInput.oldPassword`/`newPassword` in the schema), the only top-level keys are `query` and `variables` — neither is blacklisted — so the entire `variables` subtree, including plaintext passwords, is serialized unredacted into the Debug log line. This is confirmed directly in the code: the `for k, v := range dst` loop in `readSanitizedJSON` never recurses into nested maps. [1](#0-0) [2](#0-1) [3](#0-2) 

The `/query` route requires `auth.AuthenticateGQL`, but `loggerFunc` is registered as global middleware and executes for every request (successful or not) regardless of the auth outcome, so the vulnerability is triggered by any client that can reach the route with a body — the redaction gap exists independent of authentication success. [4](#0-3) 

## Impact Explanation
This is a genuine CWE-532 sensitive-data-in-logs issue: an authenticated user calling `updateUserPassword` or `createAPIToken` (or any mutation with nested sensitive fields) causes their plaintext password/secret to be written to the node's own log stream. If those logs are aggregated, shipped to a SIEM, or otherwise accessible to anyone other than the exact end user (ops teams, log aggregation services, etc.), this results in confidentiality-only credential disclosure. It does not by itself cause authentication bypass, fund movement, or job-run manipulation — the impact is limited to log-based credential exposure.

## Likelihood Explanation
Exploitation requires:
1. Debug-level logging enabled on the node (not the out-of-the-box default level, which is `info`),
2. An authenticated user issuing a `createAPIToken` or `updateUserPassword` mutation (their own credentials, or an admin issuing on behalf of another via `authv2.PATCH("/user/password", uc.UpdatePassword)` — this REST route is separate but the GraphQL mutation path is the one under discussion),
3. An observer having access to the node's logs (not something an external unprivileged network attacker can obtain directly).

The vulnerable code path is real and reproducible by inspection of `router.go`, but the actual confidentiality leak only self-discloses the acting user's own password to whoever has log access — it is not a mechanism for one unprivileged user to exfiltrate another user's secret. This weakens the severity relative to the claim's framing, since the "victim" and the "log accessor" are typically the same operational trust boundary (node operator/admin who already has infrastructure access), and Debug logging is not a default production configuration.

## Recommendation
Make `readSanitizedJSON`'s redaction recursive over nested JSON objects/arrays so keys under `variables.input.*` are checked, or special-case GraphQL body sanitization to strip/redact sensitive nested fields before logging. Alternatively, suppress body logging for the `/query` route entirely.

## Proof of Concept
1. Set `Log.Level = 'debug'` in node config.
2. As an authenticated user, `POST /query` with body:
```json
{"query": "mutation UpdateUserPassword($input: UpdatePasswordInput!) { updateUserPassword(input: $input) { ... } }", "variables": {"input": {"oldPassword": "CurrentPlainText123", "newPassword": "NewPlainText456"}}}
```
3. Inspect node logs — the Debug log line's `"body"` field contains the full `variables` object with `oldPassword`/`newPassword` in plaintext, confirmed by tracing `readSanitizedJSON`'s non-recursive top-level-only redaction logic. [5](#0-4)

func readSanitizedJSON(buf *bytes.Buffer) (string, error) {
	var dst map[string]any
	err := json.Unmarshal(buf.Bytes(), &dst)
	if err != nil {
		return "", err
	}

	cleaned := map[string]any{}
	for k, v := range dst {
		if isBlacklisted(k) {
			cleaned[k] = "*REDACTED*"
			continue
		}
		cleaned[k] = v
	}

	b, err := json.Marshal(cleaned)
	if err != nil {
		return "", err
	}
	return string(b), err
}

func redact(values url.Values) string {
	cleaned := url.Values{}
	for k, v := range values {
		if isBlacklisted(k) {
			cleaned[k] = []string{"REDACTED"}
			continue
		}
		cleaned[k] = v
	}
	return cleaned.Encode()
}

// NOTE: keys must be in lowercase for case insensitive match
var blacklist = map[string]struct{}{
	"password":             {},
	"newpassword":          {},
	"oldpassword":          {},
	"current_password":     {},
	"new_account_password": {},
}

func isBlacklisted(k string) bool {
	lk := strings.ToLower(k)
	if _, ok := blacklist[lk]; ok || strings.Contains(lk, "password") {
		return true
	}
	return false
}
