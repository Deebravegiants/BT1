### Title
Unchecked `assetReserve - virtualLtReserve` subtraction in `canGraduate` can underflow and permanently brick a token's curve - ([File: packages/contracts/src/Bonding.sol])

### Summary
`Bonding.canGraduate` (and every function that calls it — `buy`, `sell`, `triggerGraduation`, `previewLtUntilGraduation`) computes `realLtRaised = assetReserve - _launchTimeVirtualLtReserve(token_, pair)` with a bare Solidity `-` and no bounds check [1](#0-0) . The subtrahend, the launch-time virtual LT reserve, is recovered as an immutable constant `Pair.k() / TOTAL_SUPPLY` and never changes for the life of the pair [2](#0-1) . The minuend, `assetReserve`, is *not* pinned — it is live, mutable `Pair` state that any unprivileged trader moves on every `buy()`/`sell()` via `Router._computeBuy`/`_computeSell`, both of which use floor-division and are only bounded by `Pair.swap`'s deliberately loosened `(tokenReserve+1)*(assetReserve+1) >= k` check [3](#0-2) . This `+1` slack is explicitly acknowledged by the maintainers as intentional rounding tolerance in `Router` and `Pair`, but the code never re-derives the resulting worst case against `canGraduate`'s implicit invariant that `assetReserve` never drops below the fixed virtual seed.

### Finding Description
The curve's product `k = tokenReserve_init * assetReserve_init` is fixed once at `Pair.mint` and never recomputed [4](#0-3) . `tokenReserve` can never exceed its initial value `TOTAL_SUPPLY` because only previously-sold tokens can be sold back into the pair [5](#0-4) . Given that ceiling on `tokenReserve`, the `+1`-slackened invariant in `Pair.swap` mathematically permits `assetReserve` to legitimately settle strictly below `virtualLtReserve` (i.e. below the value `_launchTimeVirtualLtReserve` will later recompute) once `tokenReserve` is pushed near its ceiling — the invariant only guarantees `(tokenReserve+1)*(assetReserve+1) >= k`, not `assetReserve >= assetReserve_init` [6](#0-5) . `Router._computeBuy` and `_computeSell` both round via floor division in ways that are not guaranteed to cancel exactly across an arbitrary sequence of unequal-sized buy/sell round-trips (only an exact-match round trip cancels cleanly, since `k` is exactly divisible by the original `tokenReserve`) [7](#0-6) . An unprivileged trader fully controls the amounts and ordering of `buy()`/`sell()` calls (via `Zap`/`Bonding.buy`/`Bonding.sell`), and can therefore drive `assetReserve` to a value 1+ wei below the immutable `virtualLtReserve` through a sequence of asymmetric-sized trades that each individually satisfy `Pair.swap`'s `+1`-slackened check. Once that happens, `_launchTimeVirtualLtReserve(...)` (still `Pair.k()/TOTAL_SUPPLY`, unaffected by trading) exceeds the live `assetReserve`, and `canGraduate`'s subtraction underflows, reverting.

Because `canGraduate` is called unconditionally:
- inside every `buy()` at the end of `_executeBuy` [8](#0-7) ,
- inside every `sell()` to gate the "must-graduate" check [9](#0-8) ,
- inside `triggerGraduation` [10](#0-9) , and
- inside `previewLtUntilGraduation`'s analog arithmetic [11](#0-10) ,

the underflow reverts every entry point that touches the token while it is still `Lifecycle.Curve`. There is no recovery: `triggerGraduation` (the only permissionless path into graduation) reverts the same way, so the token can never reach `Lifecycle.Graduating`/`finalizeGraduation`, and the real LT and tokens already escrowed in the `Pair` become permanently unreachable.

### Impact Explanation
This is a permanent freeze of funds: all real LT raised by the curve and all unsold curve tokens sit in the `Pair` contract with no path to `sell()`, `buy()`, or `triggerGraduation()` once the underflow state is reached — every one of those calls reverts identically. Traders lose access to their LT/token positions on that curve, the creator's token can never graduate to the HyperSwap V2 LP, and there is no admin recovery function for a `Pair` (only `Bonding`'s owner-only setters, none of which touch a live `Pair`'s reserves). This matches the "permanent freezing of trader/creator funds" impact bar in the validation rules.

### Likelihood Explanation
The attack is reachable purely through the standard permissionless `Zap.buy`/`Zap.sell` → `Bonding.buy`/`Bonding.sell` → `Router._computeBuy`/`_computeSell` path available to any unprivileged wallet; no privileged role, upgrade, or off-chain component is required. The rounding drift per trade is small (bounded by the `+1` slack), so reaching a full 1-wei (18-dp) deficit against `virtualLtReserve` likely requires a deliberately crafted, possibly lengthy sequence of asymmetric buy/sell pairs chosen to avoid the exact-cancellation case demonstrated for a matched round-trip. This raises the operational cost/complexity relative to a one-shot exploit, but it remains executable by a single address with no special privileges, bounded only by gas and LT minimum-transaction-size (`minTransactionSize()`) constraints on trade sizing — it is a real reachable griefing/DoS vector, not merely theoretical, since the code's own invariant (`Pair.swap`'s `+1` slack) explicitly permits the underlying state to occur.

### Recommendation
Guard the subtraction in `canGraduate`, `previewLtUntilGraduation`, and `_prepareGraduationLiquidity` so that `assetReserve < _launchTimeVirtualLtReserve(...)` is treated as `realLtRaised = 0` instead of underflowing (e.g., via a saturating subtraction, mirroring the existing saturating-subtract pattern already used for `protectedLT` in `finalizeGraduation` [12](#0-11) ). Additionally, consider tightening `Pair.swap`'s K-invariant slack or re-deriving `virtualLtReserve` bounds so that no legitimate sequence of trades can push `assetReserve` below the immutable seed value in the first place.

### Proof of Concept
1. Creator calls `launch()`/seed buy through `Zap`, establishing `Pair` with `tokenReserve_init = TOTAL_SUPPLY`, `assetReserve_init = virtualLtReserve`, `k = TOTAL_SUPPLY * virtualLtReserve` (fixed forever) [13](#0-12) .
2. An unprivileged attacker repeatedly calls `Zap.buy` then `Zap.sell` (or the equivalent `Bonding.buy`/`sell`) with deliberately chosen, unequal-sized amounts across multiple round trips (not a single exact buy-then-sell-the-same-amount, which cancels exactly) — each call is only checked against `Pair.swap`'s `(tokenReserve+1)*(assetReserve+1) >= k` invariant [6](#0-5) , so each individual call succeeds.
3. Accumulating the floor-division rounding asymmetry from `Router._computeBuy`/`_computeSell` across enough round trips drives the live `assetReserve` to a value strictly below the fixed `virtualLtReserve` (permitted headroom shown by the invariant bound `assetReserve ≥ k/(tokenReserve+1) - 1`, which falls below `assetReserve_init` once `tokenReserve` approaches `TOTAL_SUPPLY`).
4. Any subsequent call to `buy()`, `sell()`, `triggerGraduation()`, or `previewLtUntilGraduation()` for that token now underflows in `assetReserve - _launchTimeVirtualLtReserve(...)` and reverts, permanently freezing the token's curve and all LT/tokens held in the `Pair`.

    function previewLtUntilGraduation(
        address token_
    ) external view returns (uint256) {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[token_];
        if (info.creator == address(0)) return 0;
        if (info.lifecycle != Lifecycle.Curve) return 0;

        address pair = info.pair;
        uint256 realBalance = IPair(pair).tokenBalance();
        if (realBalance == 0) return 0;

        (uint256 reserveToken, uint256 reserveAsset) = IPair(pair).getReserves();

        uint256 ltUntilThreshold = type(uint256).max;
        uint256 exchangeRate = IBounceLeveragedToken(info.ltAddress).exchangeRate();
        if (exchangeRate > 0) {
            uint256 realLtRaised = reserveAsset - _launchTimeVirtualLtReserve(token_, pair);
            uint256 thresholdRealLt = ($.graduationThresholdUsd * 1e18 + exchangeRate - 1) / exchangeRate;
            if (realLtRaised >= thresholdRealLt) return 0;
            ltUntilThreshold = thresholdRealLt - realLtRaised;
        }

        // Donation-inflated `realBalance`: supply trigger unreachable, defer to USD leg.
        if (realBalance >= reserveToken) return ltUntilThreshold;

        uint256 cappedReserveToken = reserveToken - realBalance;
        uint256 cappedReserveAsset = (IPair(pair).k() + cappedReserveToken - 1) / cappedReserveToken;
        uint256 ltUntilSupply = cappedReserveAsset - reserveAsset;

        return ltUntilSupply < ltUntilThreshold ? ltUntilSupply : ltUntilThreshold;
    }

    function _computeBuy(
        address pairAddr,
        uint256 amountIn
    ) internal view returns (uint256 amountInUsed, uint256 tokensOut) {
        IPair pair = IPair(pairAddr);
        (uint256 reserveToken, uint256 reserveAsset) = pair.getReserves();
        uint256 k = pair.k();

        amountInUsed = amountIn;

        uint256 newReserveAsset = reserveAsset + amountInUsed;
        tokensOut = reserveToken - (k / newReserveAsset);

        uint256 realBalance = pair.tokenBalance();
        if (tokensOut > realBalance) {
            tokensOut = realBalance;
            uint256 cappedReserveToken = reserveToken - tokensOut;
            if (cappedReserveToken == 0) revert OverflowCapDegenerate();
            uint256 cappedReserveAsset = (k + cappedReserveToken - 1) / cappedReserveToken;
            amountInUsed = cappedReserveAsset - reserveAsset;
        }
    }

    /// @notice Tokens in → LT out.
    function sell(
        uint256 amountIn,
        address token,
        address to
    ) external onlyRole(BONDING_ROLE) returns (uint256 tokensIn, uint256 assetOut) {
        if (amountIn == 0) revert ZeroAmount();

        address asset = assetTokenFor(token);
        address pairAddr = factory.getPair(token, asset);
        if (pairAddr == address(0)) revert PairNotFound();
        tokensIn = amountIn;

        IERC20(token).safeTransferFrom(to, pairAddr, amountIn);

        assetOut = _computeSell(pairAddr, amountIn);

        IPair(pairAddr).transferAsset(to, assetOut);

        IPair(pairAddr).swap(amountIn, 0, 0, assetOut);
    }

    function _computeSell(
        address pairAddr,
        uint256 amountIn
    ) internal view returns (uint256 assetOut) {
        IPair pair = IPair(pairAddr);
        (uint256 reserveToken, uint256 reserveAsset) = pair.getReserves();
        uint256 k = pair.k();

        uint256 newReserveToken = reserveToken + amountIn;
        assetOut = reserveAsset - (k / newReserveToken);
    }
