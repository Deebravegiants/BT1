Audit Report

## Title
Missing role check on `GET /v2/external_initiators` exposes all External Initiator `AccessKey`/`OutgoingToken` credentials to any authenticated view-only user - (File: core/web/router.go)

## Summary
The `GET /v2/external_initiators` route is registered without any role wrapper, unlike the sibling `POST`/`DELETE` routes for the same resource which require `auth.RequiresEditRole`. `Index` serializes every stored `ExternalInitiator` row—including `AccessKey` and `OutgoingToken`—via `presenters.NewExternalInitiatorResource`, so any authenticated user with the lowest `view` role can retrieve these credentials for all configured external initiators.

## Finding Description
In `core/web/router.go`, the route registration is: [1](#0-0) 

`authv2.GET("/external_initiators", paginatedRequest(eia.Index))` has no `auth.RequiresEditRole`/`auth.RequiresAdminRole` wrapper, while the `POST` and `DELETE` routes for the same resource do. `ExternalInitiatorsController.Index` fetches all rows from `BridgeORM().ExternalInitiators` and converts them with `presenters.NewExternalInitiatorResource`: [2](#0-1) 

That presenter includes the raw `AccessKey` and `OutgoingToken` fields in the JSON response: [3](#0-2) 

The project's own RBAC contract test explicitly documents this: `GET /v2/external_initiators` is marked `viewOnlyAllowed: true`, while `POST`/`DELETE` on the same path are `false`/`false`: [4](#0-3) 

This confirms the code behaves exactly as claimed on the current codebase: no middleware, role wrapper, or field redaction restricts or filters this response for lower-privileged callers, and the test suite treats this open access as expected/passing behavior rather than flagging it as a bug.

## Impact Explanation
A `view`-role user (or any authenticated actor holding only view privileges) can retrieve `AccessKey` and `OutgoingToken` for every External Initiator on the node without needing edit/admin rights. `AccessKey` is part of the inbound authentication scheme for job runs, and `OutgoingToken` is one of the node's outbound secrets used when POSTing results back to third-party endpoints. This is a legitimate cross-role secret disclosure: a privilege boundary that is explicitly enforced on the create/delete side of the same resource is absent on the read side, letting a lower-privileged principal read data intended to be limited to edit/admin users. This maps to the in-scope "key/secret exfiltration" impact category.

## Likelihood Explanation
High feasibility for any actor already holding valid `view`-role credentials: a single unauthenticated-role-free `GET` request against a standard, unauthenticated-by-role endpoint returns the sensitive fields. No race conditions, no elevated privileges, no host/database access required — only a valid low-privilege API key or session, which the RBAC test matrix confirms is sufficient (`viewOnlyAllowed: true`).

## Recommendation
Wrap `GET /v2/external_initiators` with `auth.RequiresEditRole` (matching `POST`/`DELETE` on the same resource), or strip `AccessKey`/`OutgoingToken` from the `Index`/`ExternalInitiatorResource` payload entirely (as is already done for the `Secret`, which is hashed and excluded), returning only non-sensitive fields (`Name`, `URL`, timestamps) regardless of caller role.

## Proof of Concept
1. As an `edit`/`admin` user, create an External Initiator via `POST /v2/external_initiators {"name":"foo","url":"http://x"}`; note the returned `AccessKey`/`OutgoingToken` from `ExternalInitiatorAuthentication`.
2. Authenticate as a user holding only the `view` role.
3. Call `GET /v2/external_initiators` with the view-role session/API token.
4. Observe the JSON response includes `accessKey` and `outgoingToken` for the initiator created in step 1, confirmed by `TestExternalInitiatorsController_Index` (`core/web/external_initiators_controller_test.go` L104-109) asserting these fields are present, and by the RBAC matrix entry `{"GET", "/v2/external_initiators", true, true, true}` in `core/web/auth/auth_test.go` (L224) which is exercised by the router's RBAC test loop.

func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}
```

type ExternalInitiatorResource struct {
	JAID
	Name          string         `json:"name"`
	URL           *models.WebURL `json:"url"`
	AccessKey     string         `json:"accessKey"`
	OutgoingToken string         `json:"outgoingToken"`
	CreatedAt     time.Time      `json:"createdAt"`
	UpdatedAt     time.Time      `json:"updatedAt"`
}

func NewExternalInitiatorResource(ei bridges.ExternalInitiator) ExternalInitiatorResource {
	return ExternalInitiatorResource{
		JAID:          NewJAID(strconv.FormatInt(ei.ID, 10)),
		Name:          ei.Name,
		URL:           ei.URL,
		AccessKey:     ei.AccessKey,
		OutgoingToken: ei.OutgoingToken,
		CreatedAt:     ei.CreatedAt,
		UpdatedAt:     ei.UpdatedAt,
	}
}
```
