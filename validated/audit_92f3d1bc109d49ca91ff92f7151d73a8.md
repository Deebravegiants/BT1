Audit Report

## Title
Missing allowlist/authorization check lets any client trigger workflow execution via the legacy Web API gateway path - (File: `core/services/gateway/handlers/capabilities/handler.go`)

## Summary
`HandleLegacyUserMessage` in the capabilities gateway handler validates message structure, signature well-formedness, and staleness, but never checks the extracted signer (`msg.Body.Sender`) against any allowlist before broadcasting a `web_api_trigger` request to every member node of the target DON. This is explicitly marked with a `// TODO: apply allowlist and rate-limiting here` comment left directly above the dispatch logic.

## Finding Description
The flow is `gateway.ProcessRequest` → `HandleLegacyUserMessage` for any message with a non-empty `Body.DonID`, as confirmed by `isLegacyRequest` routing in [1](#0-0) . Inside `HandleLegacyUserMessage`, the checks performed are: payload decoding, non-zero timestamp, and message-age freshness, followed immediately by the acknowledged gap and method check: [2](#0-1) . The request is then converted and sent to every configured DON member with no further gating: [3](#0-2) .

Critically, `msg.Validate()` (called earlier in `gateway.ProcessRequest`, [4](#0-3) ) only verifies signature format and recovers the signer's address into `msg.Body.Sender` — it does not check that the signer is a permitted/allowlisted workflow owner: [5](#0-4) . Anyone with an arbitrary ECDSA keypair can self-sign a well-formed message; the signature only proves internal consistency, not authorization. This is confirmed to differ from the `vault` handler's pattern, where every privileged method must pass `requestProcessor.ProcessRequest` (backed by an `Authorizer`) before any DON interaction: [6](#0-5) .

## Impact Explanation
An unauthenticated/unprivileged network client that can reach the gateway's user-facing HTTP endpoint can force `web_api_trigger` dispatch to every node of a target DON without being a legitimate workflow owner. This maps to the in-scope "gateway request impersonation" / "unauthorized job run" impact classes — an attacker can spoof/impersonate a trigger to fan out arbitrary trigger payloads to all DON members, potentially causing unauthorized workflow execution attempts and DoS-style resource consumption across the DON's nodes.

## Likelihood Explanation
The vulnerable path requires only network access to the gateway's user HTTP port and the ability to construct a signed `api.Message` with any keypair (self-generated, not privileged) — no credentials, DON membership, or prior authorization state is required. The `TODO` comment in the shipped code is direct evidence the control was never implemented, making this straightforward and repeatable to trigger.

## Recommendation
Add an allowlist/authorization check in `HandleLegacyUserMessage` before the DON broadcast loop — verify `msg.Body.Sender` against the DON's configured owner/workflow allowlist (mirroring the `Authorizer`/`allowListBasedAuth` pattern used in `core/services/gateway/handlers/vault/handler.go`) and reject/rate-limit unauthorized senders prior to calling `don.SendToNode`.

## Proof of Concept
1. Generate an arbitrary ECDSA keypair (no special privileges needed) and sign an `api.Message` with `Body.Method = "web_api_trigger"`, a valid `TriggerRequestPayload.Timestamp` within `MaxAllowedMessageAgeSec`, and `Body.DonID` set to a target DON ID configured on the gateway.
2. POST the JSON-RPC-wrapped message to the gateway's user HTTP endpoint so it reaches `gateway.ProcessRequest`, which routes it via `isLegacyRequest` to `HandleLegacyUserMessage` (`core/services/gateway/gateway.go:253-272`).
3. Observe that `HandleLegacyUserMessage` performs no check of the signer/sender against any allowlist and calls `don.SendToNode` for every member of `h.donConfig.Members` (`core/services/gateway/handlers/capabilities/handler.go:416-420`), confirming the trigger is broadcast DON-wide despite the caller never being verified as an authorized workflow owner.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageID) == 0 || len(m.Body.MessageID) > MessageIDMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageID, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonID) == 0 || len(m.Body.DonID) > MessageDonIDMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonID, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}
