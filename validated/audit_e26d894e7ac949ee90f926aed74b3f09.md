Invalid vulnerability report — `validateOverhead` overhead/RuntimeClass consistency is enforced by a separate admission plugin, not the field validator - ([File: pkg/apis/core/validation/validation.go])

### Summary
The premise that `validateOverhead` in `pkg/apis/core/validation/validation.go` is the "sole gate" for overhead consistency with a RuntimeClass is incorrect. The actual cross-referential consistency check between `pod.Spec.Overhead` and `RuntimeClass.Overhead` is performed by the dedicated `RuntimeClass` admission plugin (`plugin/pkg/admission/runtimeclass/admission.go`), which runs on every pod create and explicitly rejects mismatches.

### Finding Description
The generic field validator `validateOverhead` referenced in the question only checks that quantities in `spec.overhead` are well-formed resource quantities — it is not meant to, and does not need to, cross-reference the RuntimeClass object, since resource-quantity syntactic validation is orthogonal to cross-object consistency. The actual consistency enforcement lives in `plugin/pkg/admission/runtimeclass/admission.go`, where the `RuntimeClass` admission plugin performs both mutation (`setOverhead`) and validation (`Validate` -> local `validateOverhead`) steps:

- On `Admit`, `setOverhead` looks up the referenced `RuntimeClass` via `prepareObjects`, converts its `Overhead` to internal form, and rejects the pod if `pod.Spec.Overhead` is already set and does not match the RuntimeClass's declared overhead: [1](#0-0) 
- On `Validate`, the plugin's own `validateOverhead` function re-asserts that if a RuntimeClass with an `Overhead` is set, `pod.Spec.Overhead` must exactly equal it via `apiequality.Semantic.DeepEqual`, and if no RuntimeClass Overhead is defined but the pod has one set, the pod is rejected too: [2](#0-1) 

This means an attacker who creates a pod with `runtimeClassName` set and a manually forged `overhead` (e.g., zero or understated) that doesn't match the actual RuntimeClass's overhead is rejected by this admission plugin before the object is persisted — regardless of what the type-level `validateOverhead` in `pkg/apis/core/validation/validation.go` does or doesn't check. This behavior is directly covered by existing tests: `TestSetOverhead` (`plugin/pkg/admission/runtimeclass/admission_test.go:82-169`) and `TestValidateOverhead` (`plugin/pkg/admission/runtimeclass/admission_test.go:508-589`), which include explicit "Non-matching Overheads" cases that expect `expectError: true`. [3](#0-2) [4](#0-3) [5](#0-4) 

Additionally, the API documentation on the `Overhead` field itself states that when the RuntimeClass admission controller is enabled, "Pod create requests" with overhead already set are rejected outright by that controller: [6](#0-5) 

The user's proof idea ("integration test asserting RuntimeClass admission plugin (not just validateOverhead) enforces overhead consistency, and that validateOverhead alone is not the sole gate") is actually already satisfied by the existing code and tests — there is no gap. `validateOverhead` in the core validation package was never intended to be the sole gate; the RuntimeClass admission plugin is the documented and tested enforcement point.

### Impact Explanation
No exploitable impact exists. The described attack path (setting mismatched/zero overhead to evade ResourceQuota) is blocked at admission time by the RuntimeClass admission plugin before the pod is ever persisted or counted against quota.

### Likelihood Explanation
Not applicable — the described bypass path does not exist given the RuntimeClass admission plugin's enforcement. This assumes the plugin is enabled, which is the default/standard configuration for clusters using RuntimeClass with Overhead; if an operator disables this admission plugin, that would be a misconfiguration issue explicitly out of scope per the rules.

func setOverhead(a admission.Attributes, pod *api.Pod, runtimeClass *nodev1.RuntimeClass) (err error) {
	if runtimeClass == nil || runtimeClass.Overhead == nil {
		return nil
	}

	// convert to internal type and assign to pod's Overhead
	nodeOverhead := &node.Overhead{}
	if err = apinodev1.Convert_v1_Overhead_To_node_Overhead(runtimeClass.Overhead, nodeOverhead, nil); err != nil {
		return err
	}

	// reject pod if Overhead is already set that differs from what is defined in RuntimeClass
	if len(pod.Spec.Overhead) > 0 && !apiequality.Semantic.DeepEqual(nodeOverhead.PodFixed, pod.Spec.Overhead) {
		return admission.NewForbidden(a, fmt.Errorf("pod rejected: Pod's Overhead doesn't match RuntimeClass's defined Overhead"))
	}

	pod.Spec.Overhead = nodeOverhead.PodFixed

	return nil

func validateOverhead(a admission.Attributes, pod *api.Pod, runtimeClass *nodev1.RuntimeClass) (err error) {
	if runtimeClass != nil && runtimeClass.Overhead != nil {
		// If the Overhead set doesn't match what is provided in the RuntimeClass definition, reject the pod
		nodeOverhead := &node.Overhead{}
		if err := apinodev1.Convert_v1_Overhead_To_node_Overhead(runtimeClass.Overhead, nodeOverhead, nil); err != nil {
			return err
		}
		if !apiequality.Semantic.DeepEqual(nodeOverhead.PodFixed, pod.Spec.Overhead) {
			return admission.NewForbidden(a, fmt.Errorf("pod rejected: Pod's Overhead doesn't match RuntimeClass's defined Overhead"))
		}
	} else {
		// If RuntimeClass with Overhead is not defined but an Overhead is set for pod, reject the pod
		if pod.Spec.Overhead != nil {
			return admission.NewForbidden(a, fmt.Errorf("pod rejected: Pod Overhead set without corresponding RuntimeClass defined Overhead"))
		}
	}

	return nil
}
