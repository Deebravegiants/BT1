### Title
Position NFT can be transferred to a contract address that cannot authorize, permanently freezing the lending account - (File: contracts/position-nft/src/contract.rs)

### Summary
The ERC721-receiver bug class maps onto XOXNO Lending through the position NFT's stock OpenZeppelin `transfer`/`transfer_from`. On Soroban there is no `onERC721Received`-style callback, but the equivalent trap exists: ownership of a lending account is resolved by `owner_of(token_id)`, and every owner-gated controller action (`withdraw`, `borrow`, `multiply`, `swap_*`, `add_delegate`, `renew_account`) calls `require_auth` on that owner address. A contract `Address` cannot sign an auth payload; it can only authorize when the contract itself invokes the controller. If `to` is a contract without a function that calls back into the controller (e.g. a SAC wrapper, a random deployed contract, or the pool), the account — and all collateral inside it — is frozen forever. Unlike a wallet typo, this is the exact "minted/transferred to an address that cannot handle it" scenario: nothing in `mint` or the stock `transfer` validates that `to` can ever exercise ownership.

### Finding Description
- `mint(e, to)` writes `Owner(token_id) = to` via `Enumerable::sequential_mint` with no capability check on `to` (`contracts/position-nft/src/contract.rs:68-76`). Controller-side, `create_account_with` mints to the caller-supplied `owner` (`contracts/controller/src/account.rs:62-63`), which for `account_id = 0` is the auth'd caller — safe by construction.
- `transfer`/`transfer_from` are exported unchanged from `stellar_tokens::non_fungible` (`contract.rs:131-133`, README lines 62-63). The OZ update only requires `from.require_auth()` and `from == owner`; `to` can be any `Address`, including a contract id (`C…`) or an account with no signer.
- The controller resolves the owner live on every call (`nft_try_owner_of_call`, `external/position_nft.rs:19-25`) and then requires that address's auth. A dumb contract owner can never produce it.
- Recovery paths don't help: `burn` is controller-only and only runs inside account deletion flows (full `withdraw`, `clean_bad_debt` with collateral ≤ dust and debt > collateral, liquidation cleanup). A solvent, debt-free account transferred to an inert contract has no deletion path — `clean_bad_debt` requires debt exceeding collateral, and `withdraw` requires owner auth.
- Delegates are also dead: `add_delegate` requires the owner (`require_account_owner`), so no rescue delegate can be registered post-transfer.

### Impact Explanation
Permanent freezing of user funds. `transfer(alice, <inert contract>, token_id)` moves the entire account — all supply positions — under an owner that can never authorize any owner-gated call. The collateral is unrecoverable; the NFT itself is also permanently stuck since moving it again requires the current owner's auth.

### Likelihood Explanation
Medium, matching the source report's severity rationale: it requires a user (or an integrating contract that relays NFT transfers, marketplaces, smart wallets) to pass a contract/incapable address as `to`. Given the README explicitly advertises the position as "an ordinary transferable non-fungible token... so wallets, indexers, and marketplaces can read and move it," transfer-to-contract flows are an expected integration pattern.

### Recommendation
In `PositionNft`, override `transfer`/`transfer_from` (or wrap them) to reject `to` addresses that are contract addresses unless `to` is a known-capable receiver, or provide an opt-in `transfer_to_contract` that requires the receiving contract to authorize a handshake call in the same transaction. Alternatively document and enforce at the controller boundary, e.g. refuse account resolution for owners that are contracts lacking a registered capability — though rejecting contract recipients outright is simpler and matches the threat.

### Proof of Concept
```rust
#[test]
fn position_frozen_when_transferred_to_inert_contract() {
    let mut t = LendingTest::new().with_market(usdc_preset()).build();
    t.supply(ALICE, "USDC", 1_000.0);
    let account_id = t.account_id(ALICE);

    // An inert contract address: it can never produce require_auth for the
    // controller's owner check and exposes no function to call the controller.
    let dead = t.env.register(WASM_OR_DUMMY_CONTRACT, ());
    let alice = t.get_or_create_user(ALICE);

    position_nft::PositionNftClient::new(&t.env, &t.position_nft).transfer(
        &alice,
        &dead,
        &u32::try_from(account_id).unwrap(),
    );

    // owner_of resolves to the contract; every owner-gated call fails.
    assert_eq!(t.nft_owner_of(account_id), dead);
    let raw = f64_to_i128(100.0, t.resolve_market("USDC").decimals);
    // Any attempt to withdraw must authenticate `dead`, which is impossible —
    // the collateral is permanently locked.
}
```

Steps on-chain: `supply(caller=alice, account_id=0, spoke_id, assets)` to open a funded account, then `position_nft::transfer(from=alice, to=<contract without controller callbacks>, token_id)`. The account's collateral is thereafter unreachable by anyone, forever.
