### Title
Missing/archived `SpokeUsage` row is silently treated as zero, disabling spoke supply/borrow caps — (File: contracts/controller/src/spoke_usage.rs)

### Summary
The bug class behind CVE-2021-36513 — an uninitialized/absent value being consumed as meaningful data — maps onto `SpokeUsageContext`. The spoke usage book (`SpokeUsageRaw` per `(spoke_id, HubAssetKey)`) is the per-spoke cap accounting for scaled supply and debt. `apply_entry` treats an absent persistent row as `Default` (all zeros) and `apply_exit` silently returns when the row is absent. If the usage row is ever absent while scaled positions still exist — most realistically after TTL archival eviction of the persistent `ControllerKey::SpokeUsage` entry, which is only renewed when a leg touches that market — subsequent cap checks count only the caller's new delta against a zero baseline, so `supply_cap`/`borrow_cap` are silently bypassed.

### Finding Description
- `apply_entry` loads usage with `load_usage_row(hub_asset).unwrap_or_default()` and only enforces `side.scaled(usage) + delta <= cap_scaled` — an absent row means the cap is checked against the single new delta alone. [1](#0-0) 
- `apply_exit` is an explicit no-op on a missing row: `let Some(mut usage) = self.load_usage_row(hub_asset) else { return; }`. It neither restores consistency nor fails, so divergence between the usage book and the real scaled positions is silently absorbed. [2](#0-1) 
- `set_spoke_usage` deletes the row entirely when both sides reach zero, normalizing "absent = zero" — which is correct only if scaled positions are also zero. [3](#0-2) 
- The row lives in persistent storage behind `get_shared`, which renews the shared TTL only when the key is read or written. Account position keys use a separate user-TTL renewal (`renew_user_key` / `TTL_BUMP_USER`), so an account can stay live while the market's usage row archives if no supply/borrow/withdraw/repay/liquidation leg touches that `(spoke, asset)` pair within the shared TTL window. [4](#0-3) 
- The codebase itself acknowledges the asymmetry: the Certora rule `usage_exit_without_usage_row_is_a_noop` documents that `apply_exit` on an absent row "leaves usage at the zero row instead of tracking the position down," and the harness test comments that the no-op "cannot detect a share writer that skips `apply_leg_usage`." [5](#0-4) 
- Cap enforcement converts the configured asset-unit cap via `calculate_scaled_cap` and asserts `next_scaled <= cap_scaled`. With usage reset to zero, the only thing checked is the attacker's delta, so the cap is enforced per-transaction rather than per-market. [6](#0-5) 

### Impact Explanation
`borrow_cap`/`supply_cap` are the protocol's configured exposure limits per spoke market. Once the usage row is absent, an unprivileged borrower can repeatedly `borrow` (or supply) with each entry seeing `usage == 0`, accumulating real scaled debt far beyond the cap. Since caps exist to bound market exposure, bypassing them enables over-borrowing beyond intended limits — draining pool liquidity in that asset beyond the configured risk envelope, contributing to protocol insolvency if positions turn bad. The understated `borrowed_scaled_ray` also means the cap remains bypassable for subsequent users until usage is rebuilt.

### Likelihood Explanation
Medium. The trigger requires the persistent usage row to be absent while positions exist — the natural path is archival eviction after the shared TTL lapses on an inactive market while account keys persist (they renew on separate TTLs and on account-level touches). No privilege is needed to exploit the state once it exists; entrypoints `supply`, `borrow`, `multiply`, `flash_position`, etc., all route through `apply_leg_usage`. A secondary contributing factor: because exits no-op on a missing row rather than failing, there is no early warning that the book has diverged. Uncertainty: whether `update_indexes` or another routine renewal touches `SpokeUsage` often enough to make eviction unreachable in practice; I could not verify renewal cadence across all entrypoints within the available iterations.

### Recommendation
- Make `apply_exit` fail loudly (e.g., `InternalError`) when the row is absent, so a missing usage book halts exits instead of silently passing, matching the "absent ≠ zero" semantics already asserted for zero-row underflow.
- Alternatively, on `apply_entry`/`apply_exit`, detect a missing row with nonzero expected exposure and require a restore/rebuild path, or derive caps from pool-side totals rather than the evictable spoke row.
- Ensure the `SpokeUsage` TTL is renewed on every account-level touch for that market (e.g., inside `update_indexes`/`get_market_index` reads) so the row cannot archive while positions referencing it remain live.

### Proof of Concept
1. Alice supplies asset X in spoke S and Bob borrows X up to `borrow_cap`. `SpokeUsage(S, X)` is written with `borrowed_scaled_ray = cap_scaled`.
2. The market pair goes untouched until the persistent `SpokeUsage` entry archives, while Alice's/Bob's account keys remain live under the user TTL.
3. Carol (attacker) calls `withdraw`/`repay` dust on her own position in that market — `apply_exit` hits the missing row and silently no-ops instead of tracking the book down.
4. Carol then calls `borrow(account_id, [(X, cap - ε)])` repeatedly (fresh accounts via `position-nft`, or `multiply`). Each `apply_entry` computes `0 + delta <= cap_scaled` and passes; each persists `borrowed_scaled_ray = delta`, keeping the stored book near zero while pool-side `borrowed` grows without bound.
5. Result: aggregate borrows in spoke S exceed `borrow_cap` by an arbitrary multiple, bounded only by pool cash.

    pub(crate) fn apply_exit(
        &mut self,
        side: UsageSide,
        hub_asset: &HubAssetKey,
        delta_scaled: Ray,
    ) {
        if delta_scaled == Ray::ZERO {
            return;
        }
        let Some(mut usage) = self.load_usage_row(hub_asset) else {
            return;
        };
        let next = side
            .scaled(&usage)
            .checked_sub(delta_scaled.raw())
            .unwrap_or_else(|| panic_with_error!(&self.env, GenericError::MathOverflow));

        assert_with_error!(&self.env, next >= 0, GenericError::InternalError);
        side.set_scaled(&mut usage, next);
        self.usage.set(hub_asset.clone(), usage);
    }

/// Stores usage and renews shared TTL; deletes the row when both sides are zero.
pub(crate) fn set_spoke_usage(
    env: &Env,
    spoke_id: u32,
    hub_asset: &HubAssetKey,
    usage: &SpokeUsageRaw,
) {
    let key = ControllerKey::SpokeUsage(spoke_id, hub_asset.clone());

    if usage.supplied_scaled_ray == 0 && usage.borrowed_scaled_ray == 0 {
        env.storage().persistent().remove(&key);
    } else {
        set_shared(env, &key, usage);
    }
}
