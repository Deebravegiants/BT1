### Title
Outgoing POST/GET dispatch never validates that the destination `StateMachine` is a supported/whitelisted chain, allowing fee-escrowing requests to a capability-less destination that can never be delivered - (File: `modules/pallets/ismp/src/impls.rs`)

### Summary
`Pallet::<T>::dispatch_request` (the function that actually persists an outgoing request and its commitment) performs no check that `request.dest_chain()` corresponds to a state machine that has a registered `ConsensusClient`/`StateMachineClient` capable of producing state proofs for it. The higher-level `IsmpDispatcher::dispatch_request` in `modules/pallets/ismp/src/dispatcher.rs` collects the relayer fee first (`T::Currency::transfer(...)`) and then unconditionally builds the `Request` and calls `Pallet::<T>::dispatch_request`, with zero destination-capability validation in between.

### Finding Description
This mirrors the ONOS/CVE-2022-29605 bug class: a message (there, IPv6 flow rules; here, a cross-chain `Request`) is dispatched to a destination without checking whether that destination actually has the capability to receive/verify it. In Hyperbridge:

- `dispatch_request` in [1](#0-0)  collects the relayer fee via `T::Currency::transfer` and constructs the `Request::Post`/`Request::Get` using whatever `dest: StateMachine` the caller supplied in `DispatchPost`/`DispatchGet`, with no lookup against `host.consensus_client_id(...)` or any registered `ConsensusClient::state_machine(id)` capability check.
- The commitment is then persisted unconditionally in `Pallet::<T>::dispatch_request` at [2](#0-1) , which only checks for duplicate commitments, never for a valid/known destination.
- The *inbound*/verification path does correctly reject unsupported/unregistered state machines — e.g. `ConsensusClient::state_machine` implementations return `UnsupportedStateMachine`/`UnregisteredParachain` errors (see `BeefyConsensusClient::state_machine` [3](#0-2) , `BscConsensusClient::state_machine` [4](#0-3) , `SyncCommitteeConsensusClient::state_machine` [5](#0-4) ) and `validate_state_machine` in the handler path enforces this before accepting incoming messages/proofs [6](#0-5) .
- But this capability check exists only on the *receiving/relaying* side of an already-produced consensus proof — it is never consulted at the point of *outgoing* dispatch. A caller (any unprivileged user via `dispatch_to_evm`, `get_request`, or the low-level `IsmpDispatcher`) can freely target a `StateMachine` value for which no consensus client/relayer route exists, e.g. an EVM chain id nobody tracks, or a parachain id not registered with any consensus client.

### Impact Explanation
A user's relayer fee is escrowed (`T::Currency::transfer(&fee.payer, &RELAYER_FEE_ACCOUNT..., fee.fee, ...)`) and the request commitment is durably stored the moment `dispatch_request` succeeds, before any relayer ever attempts delivery. If the destination lacks a capable consensus client / relayer route, the request can never be delivered nor could a valid consensus/state proof ever be produced for a timeout on it either (timeouts also require a valid consensus proof through `validate_state_machine`). This can permanently strand escrowed relayer fees and leave the request commitment un-resolvable — i.e., a route unable to deliver messages and a form of fund freezing, matching the "Improper handling of the difference in capabilities...misleading to a network operator" bug class from the CVE, except here it directly risks locked relayer-fee funds rather than merely a misleading network state.

### Likelihood Explanation
Any unprivileged extrinsic caller can trigger this simply by supplying an arbitrary/unsupported `StateMachine` value as `dest` in `DispatchPost`/`DispatchGet` (via `dispatch_to_evm`, `get_request`, or direct `IsmpDispatcher::dispatch_request` calls) — no special privileges are required, and the fee-collection and commitment-storage logic proceed unconditionally.

### Recommendation
Before collecting fees and persisting the commitment in `dispatch_request` (`modules/pallets/ismp/src/dispatcher.rs` / `modules/pallets/ismp/src/impls.rs`), validate that `request.dest_chain()` maps to a registered `ConsensusClient` capable of returning a `StateMachineClient` for it (i.e., call the equivalent of `host.consensus_client_id(...)`/iterate `host.consensus_clients()` and confirm at least one client's `state_machine(dest)` succeeds), and reject the dispatch (refunding/never charging the fee) if no such client exists.

### Proof of Concept
1. Deploy/runtime-configure `pallet-ismp` with only a subset of consensus clients registered (e.g. only BSC's `BscConsensusClient` tracking `BSC_CHAIN_ID`).
2. Call `dispatch_to_evm` (or any extrinsic backed by `IsmpDispatcher::dispatch_request`) with `dest: StateMachine::Evm(999999)` — a chain id no consensus client tracks — and a non-zero `fee`.
3. Observe: `T::Currency::transfer` succeeds, escrowing the fee; `Pallet::<T>::dispatch_request` stores the commitment and emits `Event::Request` — with no error, despite no consensus client existing that can ever produce a state/consensus proof enabling delivery or a valid timeout for `StateMachine::Evm(999999)`.
4. The request commitment remains permanently pending and the escrowed fee is unrecoverable through the normal delivery/timeout flow.

	fn dispatch_request(
		&self,
		request: DispatchRequest,
		fee: FeeMetadata<T>,
	) -> Result<H256, anyhow::Error> {
		// collect payment for the request
		if fee.fee != Zero::zero() {
			T::Currency::transfer(
				&fee.payer,
				&RELAYER_FEE_ACCOUNT.into_account_truncating(),
				fee.fee,
				Preservation::Expendable,
			)
			.map_err(|err| IsmpError::Custom(format!("Error withdrawing request fees: {err:?}")))?;
		}

		let request = match request {
			DispatchRequest::Get(dispatch_get) => {
				let get = GetRequest {
					source: self.host_state_machine(),
					dest: dispatch_get.dest,
					nonce: self.next_nonce(),
					from: dispatch_get.from,
					keys: dispatch_get.keys,
					height: dispatch_get.height,
					context: dispatch_get.context,
					timeout_timestamp: if dispatch_get.timeout == 0 {
						0
					} else {
						<T::TimestampProvider as UnixTime>::now()
							.as_secs()
							.saturating_add(dispatch_get.timeout)
					},
				};
				Request::Get(get)
			},
			DispatchRequest::Post(dispatch_post) => {
				let post = PostRequest {
					source: self.host_state_machine(),
					dest: dispatch_post.dest,
					nonce: self.next_nonce(),
					from: dispatch_post.from,
					to: dispatch_post.to,
					timeout_timestamp: if dispatch_post.timeout == 0 {
						0
					} else {
						<T::TimestampProvider as UnixTime>::now()
							.as_secs()
							.saturating_add(dispatch_post.timeout)
					},
					body: dispatch_post.body,
				};
				Request::Post(post)
			},
		};

		let commitment = Pallet::<T>::dispatch_request(request, fee)?;

		Ok(commitment)
	}

	pub fn dispatch_request(request: Request, meta: FeeMetadata<T>) -> Result<H256, ismp::Error> {
		let commitment = hash_request::<Pallet<T>>(&request);

		if RequestCommitments::<T>::contains_key(commitment) {
			Err(ismp::Error::Custom("Duplicate request".to_string()))?
		}

		let (dest_chain, source_chain, nonce) =
			(request.dest_chain(), request.source_chain(), request.nonce());
		let leaf_index_and_pos = T::OffchainDB::push(Leaf::Request(request));
		// Deposit Event
		Pallet::<T>::deposit_event(Event::Request {
			request_nonce: nonce,
			source_chain,
			dest_chain,
			commitment,
		});

		RequestCommitments::<T>::insert(
			commitment,
			RequestMetadata {
				offchain: LeafIndexAndPos {
					leaf_index: leaf_index_and_pos.index,
					pos: leaf_index_and_pos.position,
				},
				fee: meta,
				claimed: false,
			},
		);

		Ok(commitment)
	}

	fn state_machine(&self, id: StateMachine) -> Result<Box<dyn StateMachineClient>, Error> {
		// On the coprocessor the BEEFY client only seeds the coprocessor's own state machine
		// commitment; it must never be used to verify state proofs for incoming messages.
		let host = H::default();
		if Some(host.host_state_machine()) == host.allowed_proxy() {
			Err(BeefyError::HostStateMachineIsCoprocessor)?
		}

		let para_id = match id {
			StateMachine::Polkadot(id) | StateMachine::Kusama(id) => id,
			_ => Err(BeefyError::UnsupportedStateMachine(id))?,
		};

		if !C::is_parachain_tracked(para_id) {
			Err(BeefyError::UnregisteredParachain(para_id))?
		}

		Ok(Box::new(S::from(id)))
	}

pub fn validate_state_machine<H>(
	host: &H,
	proof_height: StateMachineHeight,
) -> Result<Box<dyn StateMachineClient>, Error>
where
	H: IsmpHost,
{
	// Ensure consensus client is not frozen
	let consensus_client_id = host.consensus_client_id(proof_height.id.consensus_state_id).ok_or(
		Error::ConsensusStateIdNotRecognized {
			consensus_state_id: proof_height.id.consensus_state_id,
		},
	)?;
	let consensus_client = host.consensus_client(consensus_client_id)?;
	// Ensure client is not frozen
	host.is_consensus_client_frozen(proof_height.id.consensus_state_id)?;

	// Ensure delay period has elapsed
	if !verify_delay_passed(host, &proof_height)? {
		return Err(Error::ChallengePeriodNotElapsed {
			state_machine_id: proof_height.id,
			current_time: host.timestamp(),
			update_time: host.state_machine_update_time(proof_height)?,
		});
	}

	consensus_client.state_machine(proof_height.id.state_id)
}
