### Title
Predispatch call in `IntentGatewayV2.placeOrder` can strand secondary/unlisted tokens returned by external protocols in the `CallDispatcher`, permanently locking user funds - (File: evm/src/apps/IntentGatewayV2.sol)

### Summary
The vBNT bug pattern — a deposit action into an external protocol that returns *two* distinct tokens, while the calling contract only accounts for and forwards one of them — has a structural analog in `IntentGatewayV2.placeOrder`'s predispatch flow. When an order's `predispatch.call` executes arbitrary logic against an external DeFi protocol (e.g. unstaking LP positions, unwinding a lending position, or claiming a position that yields both a principal token and a secondary/reward/governance token), the gateway only sweeps back the token addresses explicitly declared in `order.inputs`. Any other token type the external protocol returns to the `CallDispatcher` as part of that same interaction is never swept, never accounted for, and has no owner-only or protocol-level recovery mechanism.

### Finding Description
`placeOrder` executes the user-supplied `order.predispatch.call` through the shared `CallDispatcher` contract, then builds `transferCalls` to sweep back **only the tokens listed in `order.inputs`**: [1](#0-0) 

The predispatch mechanism is explicitly documented as supporting composable actions such as "unwrapping LP tokens" before escrowing the resulting balances: [2](#0-1) 

If the external protocol invoked by `order.predispatch.call` returns more than one token type for a single position-unwind action (exactly the vBNT scenario: depositing/withdrawing from a protocol yields both a primary asset and a secondary governance/debt/reward token), only the token(s) enumerated in `order.inputs` are swept from the `CallDispatcher` back to the gateway: [3](#0-2) 

The `CallDispatcher` itself is a generic, permissionless call relay with no sweep, rescue, or admin-recovery function — it only exposes `dispatch()` and a `receive()`: [4](#0-3) 

Any token balance left on the `CallDispatcher` after the sweep (i.e., a token type not listed in `order.inputs`) is not tracked anywhere in `_orders`, not emitted as `DustCollected`, and not recoverable by the user who placed the order, by the solver, or by governance through any function visible in `IntentsBase`/`IntentGatewayV2`. This mirrors the vBNT root cause: an aggregation step that interacts with an external protocol returning multiple asset types, where only one is accounted for and the other becomes permanently stuck.

### Impact Explanation
Funds (the secondary token returned by the external protocol call, e.g., a reward, debt, or governance token component of an unstaking/unwind action) become permanently locked in the shared `CallDispatcher` contract, with no code path to withdraw them. Because `CallDispatcher` is a shared, protocol-wide utility contract (not a per-order or per-user escrow), tokens accumulate there indefinitely across all users who structure predispatch calls this way. This satisfies "permanent freezing of funds" for any user whose predispatch interaction returns a secondary asset the order didn't declare as an input.

### Likelihood Explanation
This is reachable by any unprivileged user submitting a single `placeOrder` transaction with a crafted `predispatch.call`/`predispatch.assets` pair targeting a legitimate external DeFi protocol whose unstake/withdraw/redeem functions return more than one asset (a common pattern: LP unstaking returning both underlying LP-adjacent assets and reward/governance tokens, akin to Bancor's bnBNT + vBNT). No malicious governance, admin, or relayer involvement is required — the loss is triggered purely by normal composable usage of the documented predispatch feature.

### Recommendation
After executing `order.predispatch.call` and sweeping the declared `order.inputs` tokens, snapshot and sweep (or explicitly document/require) that the predispatch call's target protocol returns exactly the token set declared in `order.inputs`. Add either: (a) a generic post-call balance diff/sweep across a broader declared token list (including secondary/reward tokens) so nothing is left behind, or (b) a permissioned rescue/sweep function on `CallDispatcher` (or a per-order dust recovery path in `IntentGatewayV2`) allowing the order's `user` to reclaim any residual token balances left on the dispatcher attributable to their `predispatch.call`.

### Proof of Concept
Conceptual PoC (cannot be fully executed without a live external protocol integration, but the vulnerable code path is directly traceable):
1. User calls `placeOrder` with `order.predispatch.assets` = [LP token], `order.predispatch.call` = calldata to unstake/withdraw from an external protocol whose withdraw function pays out both the primary underlying token and a secondary token (e.g., a governance/vBNT-equivalent token) to the `CallDispatcher`.
2. `order.inputs` only lists the primary underlying token.
3. `ICallDispatcher(dispatcher).dispatch(order.predispatch.call)` executes the withdrawal; both tokens land on `dispatcher`. [5](#0-4) 
4. The sweep loop (`transferCalls`) is built strictly from `order.inputs`, so only the primary token is transferred back to `IntentGatewayV2`; the secondary token balance remains on `dispatcher` untouched. [6](#0-5) 
5. `CallDispatcher` has no function other than `dispatch()` to move out arbitrary token balances by any account, so the secondary token is now permanently stranded. [7](#0-6) 

**Uncertainty**: This finding is based on the identified code structure and documented intended use ("unwrapping LP tokens") rather than a confirmed exploit against a specific named external protocol in-repo; no test in the indexed codebase exercises a multi-token-return predispatch scenario, so likelihood/exploitability should be validated against the actual external protocols the predispatch feature is expected to integrate with.

contract CallDispatcher is ICallDispatcher {
    /**
     * @dev error thrown when the target is not a contract.
     */
    error NotContract(address target);

    /**
     * @dev error thrown when a call fails.
     */
    error CallFailed(address target, bytes result);

    /**
     * @dev Receive function to accept ETH transfers
     */
    receive() external payable {}

    /**
     *  @dev reverts if the target is not a contract or if any of the calls reverts.
     */
    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
}
