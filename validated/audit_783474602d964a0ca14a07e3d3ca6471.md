### Title
Chainlink oracle DoS in `SimplexPaymaster._getOraclePrice` blocks gas sponsorship for Hyperbridge dispatch transactions - (File: `evm/src/utils/SimplexPaymaster.sol`)

### Summary
`SimplexPaymaster` is a permissionless ERC-4337 paymaster that sponsors gas for UserOps (including ones that call into Hyperbridge, e.g. `IDispatcher` dispatch calls) in exchange for stablecoins, pricing everything through two Chainlink feeds queried in `_getOraclePrice`. That function calls `oracle.latestRoundData()` directly with no try/catch and no non-Chainlink fallback, so if Chainlink's multisig blocks access to either the native/USD or a token/USD feed, every call reverts unconditionally, unconditionally denying the paymaster service to all users of that token.

### Finding Description
`_getOraclePrice` reads `latestRoundData()` unconditionally: [1](#0-0) 

This is invoked from `_tokenPrice`, which is in turn invoked from `fetchDetails` (called during `validatePaymasterUserOp` for every UserOp using this paymaster), `getTokenPrice`, `estimateTokenCost`, and `swapAndDeposit`: [2](#0-1) [3](#0-2) 

None of these call sites wrap the oracle call in a try/catch, matching the exact bug class in the report: as documented in OpenZeppelin's price-oracle guidance referenced by the report, Chainlink's feed-access multisig can block `latestRoundData()` at will, causing it to revert. Because `_getOraclePrice` is called unconditionally on the validation hot path (`fetchDetails` → `validatePaymasterUserOp`), a single blocked feed makes every UserOp priced in that token permanently unvalidatable through this paymaster.

The only recovery path is governance re-registering the token with a different oracle via `_registerToken` (an `onAccept` governance request gated to a single relayer and originating from Hyperbridge itself): [4](#0-3) 

This requires an off-chain governance round-trip through the Hyperbridge messaging pipeline before the paymaster can serve UserOps again, so the denial of service is not self-healing.

### Impact Explanation
`SimplexPaymaster` sponsors ERC-4337 UserOps that end users rely on to submit Hyperbridge transactions without holding native gas — a "bandwidth purchaser" style role. If Chainlink blocks the `nativeOracle` feed or any registered `tokenOracle`, `validatePaymasterUserOp` reverts for every affected UserOp, so bundlers cannot include them and the sponsored route to submit Hyperbridge messages becomes unusable for all users of that token until governance intervenes (a relayer-gated, cross-chain `onAccept` request) to re-register a working oracle. This is a route-availability denial of service on funds/gas sponsorship, not merely a single-user revert.

### Likelihood Explanation
Likelihood is bounded by the operational likelihood of a Chainlink feed being paused/blocked by its multisig, which is a documented and previously-observed occurrence for Chainlink aggregators, rather than requiring any attacker action — any single blocked feed immediately and deterministically halts sponsorship for the affected token with no attacker cost.

### Recommendation
Wrap the `latestRoundData()` (and `decimals()`) calls in `_getOraclePrice`/`_registerToken`/`_setParams` in try/catch blocks. On failure (or on a stale/invalid answer), fall back to a secondary price source, a cached last-good price with a defined staleness bound, or gracefully mark the affected token inactive (rather than reverting every validation) so other tokens/paths remain usable while governance restores the feed.

### Proof of Concept
1. Governance registers token `T` with Chainlink oracle `O` via `RequestKind.RegisterToken` (`_registerToken`).
2. Chainlink's feed-access multisig blocks reads on `O`, causing `O.latestRoundData()` to revert (as documented behavior of Chainlink aggregator access control).
3. Any user submits a UserOp with `paymasterData` selecting mode 0x00/0x02 and token `T`.
4. The EntryPoint calls `validatePaymasterUserOp` → `fetchDetails` → `_tokenPrice` → `_getOraclePrice(cfg.tokenOracle, ...)`, which reverts because `latestRoundData()` reverts.
5. The UserOp fails validation (`AA33`), and every other UserOp using token `T` through this paymaster fails identically until Hyperbridge governance delivers a `RegisterToken`/`UpdateParams` request pointing to a working oracle.

```text
    /// @dev Registers or updates a supported ERC-20 token with its token/USD feed.
    ///      Re-registering is also the recovery path for a misbehaving oracle.
    function _registerToken(address token, AggregatorV3Interface oracle) internal {
        if (token == address(0) || address(oracle) == address(0)) revert ZeroAddress();

        bool isNew = !tokenConfigs[token].active && address(tokenConfigs[token].tokenOracle) == address(0);

        tokenConfigs[token] = TokenConfig({
            tokenOracle: oracle,
            tokenOracleDecimals: oracle.decimals(),
            tokenDecimals: IERC20Metadata(token).decimals(),
            active: true
        });

        if (isNew) {
            registeredTokens.push(token);
        }

        emit TokenRegistered(token, address(oracle));
    }
```

```text
    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
```
