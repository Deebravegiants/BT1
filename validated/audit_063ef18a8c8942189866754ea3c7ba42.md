### Title
Unchecked mint `decimals` in `Initialize2` permanently panics `normalize_decimal_v2`/`restore_decimal`, freezing pool funds - (File: program/src/processor.rs)

### Summary
`process_initialize2` stores `coin_mint.decimals` and `pc_mint.decimals` into `AmmInfo` without validating their range. [1](#0-0) 
These decimals are then fed as `native_decimal` into `Calculator::normalize_decimal_v2` / `restore_decimal` / `normalize_decimal`, which compute `U128::from(10).checked_pow(native_decimal.into()).unwrap()`. [2](#0-1) 
`U128` is a 128-bit integer (max ≈ 3.4×10^38 ≈ 10^38.5). SPL Token `Mint::decimals` is a `u8` field that the mint creator can set to any value up to 255, so a mint with `decimals > 38` makes `checked_pow` return `None`, and the following `.unwrap()` panics. This is analogous to the reported PaddlePaddle bug class: an unchecked, attacker-controlled "size" parameter (decimals) is used to derive an internal computation with no bounds check, producing a crash reachable from a single transaction.

### Finding Description
`process_initialize2` is invoked by an unprivileged pool creator supplying arbitrary `amm_coin_mint_info` / `amm_pc_mint_info` accounts. The only checks performed are that the two mints differ and that they successfully unpack as SPL mints; there is no upper bound placed on `decimals`. [3](#0-2) [4](#0-3) 

The unchecked decimals are persisted into the pool state via `amm.initialize(...)`: [1](#0-0) 

`Calculator::normalize_decimal_v2`, `normalize_decimal`, and `restore_decimal` all call `U128::from(10).checked_pow(native_decimal.into()).unwrap()`, which panics whenever `native_decimal > 38`: [5](#0-4) 

These functions are invoked on essentially every subsequent instruction that touches the pool — `process_deposit`, `process_withdraw`, `process_swap_base_in`/`_v2`, `process_swap_base_out`/`_v2`, `process_withdrawpnl`, and `calc_take_pnl` — using `amm.pc_decimals`/`amm.coin_decimals` read from the now-permanently-stored `AmmInfo`: [6](#0-5) [7](#0-6) [8](#0-7) 

Because `coin_decimals`/`pc_decimals` are fixed at pool creation and never revalidated or corrected, once a pool is initialized with a mint whose `decimals > 38`, every future `Deposit`, `Withdraw`, `SwapBaseIn(V2)`, `SwapBaseOut(V2)`, and `WithdrawPnl` call on that pool will panic and abort, since they all reach `normalize_decimal_v2`/`restore_decimal` before performing any transfer.

### Impact Explanation
Any liquidity deposited into such a pool (by the creator or by other unaware LPs who deposit before noticing the pool is unusable) becomes permanently unwithdrawable: `process_withdraw` panics before ever calling `Invokers::token_transfer`, and `process_deposit`/swap instructions likewise panic, so the pool is bricked forever with no admin recovery path in the AMM instruction set. This is a permanent freezing of user/LP funds, satisfying the High-severity impact bar (analogous to the "denial of service, or even more damage" impact of the PaddlePaddle CVE).

### Likelihood Explanation
Trivially reachable: any unprivileged actor can create an SPL mint with `decimals` set arbitrarily (e.g., 200) using the standard `spl_token::instruction::initialize_mint` and then submit a single `Initialize2` transaction using that mint as `coin_mint` or `pc_mint`. No privileged signer, validator collusion, or off-chain component is required — this fits squarely in the in-scope "Initialize2, attacker-chosen accounts and data" path.

### Recommendation
In `process_initialize2`, validate `coin_mint.decimals` and `pc_mint.decimals` against a safe maximum (e.g., ensure `native_decimal <= 19`, matching realistic token decimal ranges and leaving headroom under `sys_decimal_value` multiplication) before calling `amm.initialize(...)`, rejecting the instruction with an explicit `AmmError` if exceeded. Additionally, harden `Calculator::normalize_decimal`/`normalize_decimal_v2`/`restore_decimal` to return a `Result`/checked error instead of `unwrap()`-ing `checked_pow`, so a malformed/legacy pool state cannot panic the program.

### Proof of Concept
1. Attacker creates a new SPL mint `M` via `spl_token::instruction::initialize_mint(..., decimals = 200)`.
2. Attacker calls `initialize2` (program/src/instruction.rs:664) with `amm_coin_mint = M` (or `amm_pc_mint = M`), a normal counterpart mint, and self-funded initial liquidity amounts.
3. `process_initialize2` succeeds; `amm.coin_decimals` (or `pc_decimals`) is stored as `200`.
4. Any subsequent `Deposit`, `Withdraw`, `SwapBaseIn/Out(V2)`, or `WithdrawPnl` on this pool calls `Calculator::normalize_decimal_v2`/`restore_decimal` with `native_decimal = 200`, causing `U128::from(10).checked_pow(200.into())` to return `None` and the `.unwrap()` to panic, aborting every such transaction permanently.
5. Any tokens already deposited into the coin/pc vaults or minted as LP for this pool can never be withdrawn again through the program's instructions.

    pub fn normalize_decimal(val: u64, native_decimal: u64, sys_decimal_value: u64) -> u64 {
        // e.g., amm.sys_decimal_value is 10**6, native_decimal is 10**9, price is 1.23, this function will convert (1.23*10**9) -> (1.23*10**6)
        //let ret:u64 = val.checked_mul(amm.sys_decimal_value).unwrap().checked_div((10 as u64).pow(native_decimal.into())).unwrap();
        let ret_mut = (U128::from(val))
            .checked_mul(sys_decimal_value.into())
            .unwrap();
        let ret = Self::to_u64(
            ret_mut
                .checked_div(U128::from(10).checked_pow(native_decimal.into()).unwrap())
                .unwrap()
                .as_u128(),
        )
        .unwrap();
        ret
    }

    pub fn restore_decimal(val: U128, native_decimal: u64, sys_decimal_value: u64) -> U128 {
        // e.g., amm.sys_decimal_value is 10**6, native_decimal is 10**9, price is 1.23, this function will convert (1.23*10**6) -> (1.23*10**9)
        // let ret:u64 = val.checked_mul((10 as u64).pow(native_decimal.into())).unwrap().checked_div(amm.sys_decimal_value).unwrap();
        let ret_mut = val
            .checked_mul(U128::from(10).checked_pow(native_decimal.into()).unwrap())
            .unwrap();
        let ret = ret_mut.checked_div(sys_decimal_value.into()).unwrap();

    }
