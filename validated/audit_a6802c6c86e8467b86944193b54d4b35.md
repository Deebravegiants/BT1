### Title
Out-of-bounds/short read in `HeaderImpl.stateCommitment` ISMP consensus-digest parsing lets a malformed parachain header be accepted with a truncated/zero `overlayRoot`/`stateRoot` - ([File: evm/src/consensus/Types.sol])

### Summary
`HeaderImpl.stateCommitment()` (called from `SP1Beefy.verifyConsensus` and equivalently in the Rust BEEFY/GRANDPA verifiers) extracts the ISMP MMR root and child-trie root from a header's `ISMP` consensus digest by slicing fixed 32-byte windows out of `self.digests[j].consensus.data` without validating that the digest payload is actually ≥64 bytes:

```solidity
mmrRoot = Bytes.toBytes32(Bytes.substr(self.digests[j].consensus.data, 0, 32));
childTrieRoot = Bytes.toBytes32(Bytes.substr(self.digests[j].consensus.data, 32));
``` [1](#0-0) 

The header itself (`Header.digests`) is decoded by `Codec.DecodeHeader`/`decodeDigestItem`, which allow a `DIGEST_ITEM_CONSENSUS` entry with `consensusId == ISMP_CONSENSUS_ID` ("ISMP") but an arbitrary, attacker-controlled `data` length (including 0 or a length between 1 and 63 bytes) — SCALE length-prefixed and bounds-checked only against the *encoded header buffer*, not against the semantic 64-byte requirement of an `ConsensusDigest{mmr_root, child_trie_root}` payload:

```solidity
function decodeDigestItem(ByteSlice memory slice) internal pure returns (DigestItem memory) {
    bytes4 id = Bytes.toBytes4(read(slice, 4), 0);
    uint256 length = ScaleCodec.decodeUintCompact(slice);
    bytes memory data = Bytes.read(slice, length);
    return DigestItem(id, data);
}
``` [2](#0-1) 

### Finding Description
`Bytes.substr(data, offset, len)`/`Bytes.substr(data, offset)` (from the imported `@polytope-labs/solidity-merkle-trees` library) is a raw-memory slice helper. When `data.length < 64` (e.g. an attacker crafts a parachain header whose "ISMP" consensus digest carries 0, 16, or 32 bytes of payload instead of the expected 64), calling `Bytes.substr(data, 32)` or `Bytes.substr(data, 0, 32)` reads past the end of the `data` buffer in memory — this is the direct analog of CVE-2017-14501's `parse_file_info` reading fields from an ISO9660 record without checking the actual record length against the expected fixed-size fields, causing an out-of-bounds read of adjacent memory that gets reinterpreted as valid header/field data.

Reachability: this code path is hit whenever anyone submits a `SP1Beefy.verify(previousState, proof)` transaction (permissionless — `IHandlerV2.handleConsensus`/any relayer can call it) with `proof.headers` containing a parachain header whose ISMP digest was truncated. The SP1 proof cryptographically proves inclusion of the header's *hash* in the MMR and inclusion of `digest.data` in the SP1 public inputs via `keccak256`, but it does not constrain `digest.data.length == 64`; a header that a malicious/compromised parachain collator or a bug in a downstream chain's runtime produces with a short ISMP digest would still hash-check correctly while `stateCommitment()` walks off the end of the buffer.

Because Solidity `bytes memory` slicing via raw pointer arithmetic (as used by these merkle-tree/byte utility libraries) does not automatically revert on an out-of-bounds read the way a `require`-guarded ABI decode would, the result is that garbage/adjacent-memory bytes get interpreted as `overlayRoot`/`stateRoot`, i.e., an unsound state commitment is recorded for the corresponding `IntermediateState`.

### Impact Explanation
An intermediate state (`overlayRoot`/`stateRoot`) computed from out-of-bounds memory is a forged/undefined state commitment. Downstream, `HandlerV2.handlePostRequests`/`handleGetResponses` use these state commitments to verify membership/non-membership proofs of ISMP messages (`MerkleMountainRange`/`PolkadotTrie` proofs against `state.overlayRoot`). An attacker who can influence the garbage bytes landed in memory (heap-grooming via calldata layout, a realistic technique for memory-corruption-class bugs in EVM contracts) could cause the host to accept a forged root, enabling unauthorized/forged message delivery or unsound state commitment acceptance — a "forged message delivery / unsound state commitment" impact as required by the validation criteria.

### Likelihood Explanation
Medium: triggering it requires getting a parachain header with an ISMP consensus digest shorter than 64 bytes into a header set that a relayer submits to `SP1Beefy.verify`/`EcdsaBeefy.verify`. Because SP1/BEEFY only prove the header's hash and the digest bytes verbatim (not their semantic length), a malicious or bugged parachain (or one that a Hyperbridge governance/BEEFY-tracked chain misconfigures its ISMP digest emission on) can produce such a header, and any permissionless relayer can then submit it through the normal consensus-message flow. No special privilege beyond "submit a consensus proof/relay a header" — squarely in the unprivileged-relayer reachable set required by scope.

### Recommendation
In `HeaderImpl.stateCommitment` (and the analogous Rust `ConsensusDigest::decode` paths), require `self.digests[j].consensus.data.length == 64` (or the exact expected size) before slicing, and revert with a clear error (e.g. `InvalidConsensusDigestLength`) otherwise. Prefer using a bounds-checked ABI-style decode (`abi.decode(data, (bytes32, bytes32))`) over raw `Bytes.substr` pointer slicing for fixed-size struct extraction from untrusted digest payloads.

### Proof of Concept
1. Construct a substrate/parachain header whose digest list includes a `DigestItem::Consensus(ISMP_ID, data)` entry where `data.len() < 64` (e.g. `data = vec![0u8; 16]`).
2. SCALE-encode this header and include it as one of `SP1BeefyProof.headers[i].header` in a valid SP1 proof (the SP1 circuit only commits to `keccak256(header)`/`keccak256(data)` equality, not to `data.len()`).
3. Submit via `HandlerV2.handleConsensus(host, proof)` → `SP1Beefy.verify` → `verifyConsensus` → `Codec.DecodeHeader` (succeeds because `decodeDigestItem`'s bounds check is against the encoded header buffer, not against 64) → `header.stateCommitment()` calls `Bytes.substr(data, 32)` on a 16-byte `data`, reading out of bounds.
4. Observe the resulting `IntermediateState.commitment.overlayRoot/stateRoot` reflect out-of-bounds memory content rather than a revert, and that this commitment is persisted via `IConsensusV2.verify`'s returned `intermediates`.

Note: I was unable to directly inspect the implementation of `Bytes.substr`/`Bytes.toBytes32` from the imported `@polytope-labs/solidity-merkle-trees` package within this index (it is an external dependency, not fully indexed here), so the exact low-level memory-safety behavior of `Bytes.substr` when `offset+len > data.length` could not be fully confirmed from source in this session — a Devin session with full filesystem/dependency access should verify the library's exact bounds-checking behavior to confirm whether it reverts, silently truncates, or performs a true OOB read, and adjust the finding's certainty/impact accordingly.
