### Title
Attacker-seeded HyperSwap V2 pool ratio can force a `Math.mulDiv` overflow revert in `_noFeeSwapInput`, permanently bricking `finalizeGraduation` - ([File: packages/contracts/src/Bonding.sol])

### Summary
The OpenLDAP report describes an assertion failure triggered by adversarial input to a validation routine (`saslAuthzTo`), causing `slapd` to crash — a permanent denial of service. Alt.fun has a structurally identical class of bug in its graduation LP-seeding math: `Bonding._noFeeSwapInput`, called from the permissionless `finalizeGraduation` path, performs a `Math.mulDiv` whose final result is only "assumed" to fit in `uint256` — the contract's own natspec admits that "constructed adversarial inputs that violate this would revert." An unprivileged attacker who pre-seeds the HyperSwap V2 `TOKEN/LT` pair with an extreme reserve ratio before a token graduates can force exactly that overflow revert, permanently bricking `finalizeGraduation` for that token with all curve-raised LT and 250M reserved tokens stranded in `Bonding` forever.

### Finding Description
`_prepareGraduationLiquidity` caches `tokensForLP` (up to `LP_RESERVE` = 250,000,000e18) and `ltFromPair` (the real LT raised by the curve, which can be made arbitrarily small relative to `tokensForLP` because the curve's USD threshold is denominated via a permissionless, externally-controlled LT `exchangeRate()`) at phase 1: [1](#0-0) 

At phase 2, `finalizeGraduation` calls `_seedUniswapV2Direct` → `_seedRebalancing`, which — whenever the HyperSwap V2 pair already has non-zero `totalSupply` (i.e. someone minted LP against it, "Regime 3") — computes a rebalancing swap via `_pairRebalance` → `_noFeeSwapInput`: [2](#0-1) [3](#0-2) 

```solidity

    uint256 reserveOut,
    uint256 targetN,
    uint256 targetD,
    uint256 maxSwap

    if (reserveIn == 0 || reserveOut == 0 || targetN == 0 || targetD == 0 || maxSwap == 0) {
        return 0;
    }
    uint256 product = Math.mulDiv(reserveIn * reserveOut, targetN, targetD);
    uint256 newIn = Math.sqrt(product);
    ...
}
``` [4](#0-3) 

`Math.mulDiv` computes `reserveIn * reserveOut * targetN / targetD` in 512-bit space, but OpenZeppelin's `Math.mulDiv` **reverts if the final quotient does not fit in 256 bits** — this is exactly the kind of "assertion" the contract's own comment warns about: [5](#0-4) 

`reserveIn`/`reserveOut` come from the HyperSwap V2 pair's `uint112` reserves (attacker-controlled — the attacker permissionlessly creates the pair via the standard `IUniswapV2Factory.createPair` and self-funds a `mint()` against it before graduation, exactly the pre-seeding vector this scan explicitly treats as in-scope). `targetN`/`targetD` are `ltFromPair`/`tokensForLP` (or their inverse), which the attacker can also skew heavily: because `ltFromPair` is real LT raised (denominated via an externally-controlled leveraged-token `exchangeRate()`), it can be driven very small relative to `tokensForLP` (up to 2.5e26) for a token whose curve just crossed the USD graduation threshold with a high-exchange-rate LT. With `reserveIn`/`reserveOut` chosen near `uint112.max` (~5.19e33 each) and `targetN/targetD` skewed by many orders of magnitude, `reserveIn * reserveOut * targetN / targetD` overflows `uint256` (~1.16e77), and `Math.mulDiv` reverts unconditionally, regardless of `maxSwap`.

### Impact Explanation
Once `_enterGraduating` has run, the token is permanently stuck in `Lifecycle.Graduating` — there is no code path back to `Curve` and no admin override to bypass `_seedRebalancing`. If `_noFeeSwapInput` always reverts for the attacker-crafted pool state, `finalizeGraduation` can never succeed: [6](#0-5) 

The consequence is a permanent freeze of:
- the curve-raised LT already moved into `Bonding` via `Router.graduate` in phase 1 (`ltFromPair`),
- the up to 250,000,000e18 `tokensForLP` reserved for the LP,
- every trader's ability to ever trade or exit the token (trading is frozen the instant `Lifecycle.Graduating` is entered, and it can never reach `Graduated`),
- the LP lock, which never records anything for this token.

This matches the Validate criterion of "permanent freezing of trader, creator, or LP funds," directly analogous to the OpenLDAP bug class (adversarial input hitting an internal assertion → permanent denial of service), just with financial consequences instead of a crashed daemon.

### Likelihood Explanation
- `finalizeGraduation` is explicitly permissionless (called by anyone/keeper).
- HyperSwap V2's factory `createPair`/`mint` are standard permissionless functions; nothing in `Bonding` prevents an attacker from creating the `TOKEN/LT` pair and seeding an extreme ratio before the curve token graduates.
- The `DIRECT_MINT_PRESEED_BPS` guard only diverts *small* pre-seeds to the safe direct-mint fallback; the attacker deliberately stays above that band while making the ratio extreme enough to overflow `Math.mulDiv`, which is achievable given the wide dynamic range between `uint112`-scale reserves and the `tokensForLP`/`ltFromPair` ratio (which can differ by many orders of magnitude for graduations funded by a high-`exchangeRate` LT).
- No test/fuzz coverage is evident for this overflow boundary; the natspec on `_noFeeSwapInput` itself flags it as a known, unmitigated risk ("Constructed adversarial inputs ... would revert").

### Recommendation
- Bound the `Math.mulDiv` inputs before calling it in `_noFeeSwapInput` — e.g., detect when `targetN/targetD` combined with `reserveIn*reserveOut` would overflow and clamp/scale down proportionally rather than reverting, or perform the computation in a way that degrades gracefully (falling back to `_seedDirectMint`, exactly as already done for the `expectedOut == 0` / dust case).
- Alternatively, cap the attacker-controllable skew: sanity-check the V2 pool's pre-existing reserve ratio against `tokensForLP`/`ltFromPair` before attempting the rebalance swap, and route to `_seedDirectMint` whenever the projected `mulDiv` operands exceed a safe pre-computed bound.
- Add a regression test that pre-seeds a HyperSwap V2 pair with `uint112`-max-scale reserves and a graduation with a large `tokensForLP`/`ltFromPair` skew, asserting `finalizeGraduation` still succeeds (falls back to direct mint) instead of reverting.

### Proof of Concept
1. Launch (or wait for) a token `T` paired with LT `L` whose `exchangeRate()` is high enough that a small amount of raised LT (`ltFromPair`) crosses the $9,000 USD graduation threshold, while `tokensForLP` is near its `LP_RESERVE` cap (2.5e26) — i.e., a large `tokensForLP / ltFromPair` skew.
2. Before `T` graduates, attacker calls `IUniswapV2Factory(uniswapV2Factory).createPair(T, L)`, then directly transfers self-funded `T` and `L` amounts near `uint112.max` into the pair and calls `pair.mint(attacker)`, baking in an extreme reserve ratio (Regime 3 "mint pre-seed").
3. Buy/sell activity (or `triggerGraduation`) pushes `T` past the graduation threshold; `_enterGraduating` fires, caching `(tokensForLP, ltFromPair)` and moving `ltFromPair` LT into `Bonding` via `Router.graduate`.
4. Anyone calls `finalizeGraduation(T)`. Execution reaches `_seedRebalancing` → `_pairRebalance` → `_noFeeSwapInput`, where `Math.mulDiv(reserveIn * reserveOut, targetN, targetD)` overflows `uint256` and reverts.
5. `finalizeGraduation(T)` reverts on every subsequent call (the pre-seeded pair state and cached `PendingGraduation` values are unchanged), permanently freezing `T` in `Lifecycle.Graduating` along with its escrowed LT and reserved tokens.

    function finalizeGraduation(
        address tokenAddress
    ) external nonReentrant {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[tokenAddress];
        if (info.lifecycle != Lifecycle.Graduating) revert NotGraduating();

        address lt = info.ltAddress;
        PendingGraduation memory p = $.pendingGraduation[tokenAddress];

        // Anything in this contract beyond `p.ltFromPair` belongs to a
        // concurrent graduation on the same LT (Phase 1 transferred it
        // via `Router.graduate`) or to stray dust. Either way it is
        // off-limits to this graduation's deposit and sweep — see
        // `_routerDepositAndDispose` and `_sweepLTToOwner`.
        // Saturating subtract: a balance below `p.ltFromPair` shouldn't
        // be reachable in normal operation, but we keep finalize from
        // bricking on a Panic if any future code path or non-canonical
        // LT briefly violates the invariant.
        uint256 ltBalance = IERC20(lt).balanceOf(address(this));
        uint256 protectedLT = ltBalance > p.ltFromPair ? ltBalance - p.ltFromPair : 0;

        address lpPair = _ensureUniswapV2Pair(tokenAddress, lt);
        uint256 liquidity = _seedUniswapV2Direct(tokenAddress, lt, lpPair, p.tokensForLP, p.ltFromPair, protectedLT);

        _sweepLTToOwner(lt, protectedLT);

        info.lifecycle = Lifecycle.Graduated;
        $.graduatedPair[tokenAddress] = lpPair;
        delete $.pendingGraduation[tokenAddress];

        LPLock($.lpLock).recordLock(tokenAddress, lpPair, liquidity);

        emit TokenGraduated(tokenAddress, lpPair, liquidity, p.tokensForLP, p.lpBurned, p.unsoldBurned);
    }

    function _prepareGraduationLiquidity(
        address tokenAddress
    ) internal returns (uint256 tokensForLP, uint256 ltFromPair, uint256 lpBurned, uint256 unsoldBurned) {
        address pairAddr = _s().tokenInfo[tokenAddress].pair;
        (uint256 tokenReserve, uint256 assetReserve) = IPair(pairAddr).getReserves();

        unsoldBurned = IPair(pairAddr).tokenBalance();
        if (unsoldBurned > 0) {
            Token(tokenAddress).burn(pairAddr, unsoldBurned);
        }

        ltFromPair = assetReserve - _launchTimeVirtualLtReserve(tokenAddress, pairAddr);
        if (ltFromPair > 0) {
            _s().router.graduate(tokenAddress, ltFromPair);
        }

        tokensForLP = assetReserve == 0 ? 0 : (ltFromPair * tokenReserve) / assetReserve;
        if (tokensForLP > LP_RESERVE) tokensForLP = LP_RESERVE;

        lpBurned = LP_RESERVE - tokensForLP;
        if (lpBurned > 0) {
            Token(tokenAddress).burn(address(this), lpBurned);
        }
    }

    function _seedRebalancing(
        address tokenAddress,
        address lt,
        address pair,
        uint256 tokensForLP,
        uint256 ltFromPair,
        uint256 protectedLT
    ) internal returns (uint256 liquidity) {
        (uint112 r0, uint112 r1,) = IUniswapV2Pair(pair).getReserves();
        bool tokenIs0 = IUniswapV2Pair(pair).token0() == tokenAddress;
        (uint256 reserveToken, uint256 reserveLT) = tokenIs0 ? (uint256(r0), uint256(r1)) : (uint256(r1), uint256(r0));

        // Below the band on BOTH sides, overpower the pre-seed with a direct
        // mint at the cached ratio: the rebalance swap is too coarse to reach
        // the ratio against such small reserves, and the pre-existing LP's
        // claim on the deposit stays bounded by `DIRECT_MINT_PRESEED_BPS`. A
        // side that is large relative to its LP target still takes the
        // rebalance path so it isn't donated under the empty-mint `min()`.
        if (
            reserveToken * BPS_DENOM <= tokensForLP * DIRECT_MINT_PRESEED_BPS
                && reserveLT * BPS_DENOM <= ltFromPair * DIRECT_MINT_PRESEED_BPS
        ) {
            return _seedDirectMint(tokenAddress, lt, pair, tokensForLP, ltFromPair);
        }

        // Budget reads `balanceOf(this)` rather than `tokensForLP` /
        // `ltFromPair` so any skim donation contributes to the rebalance
        // and not only to `_routerDepositAndDispose`'s deposit.
        // Direction: pool TOKEN-rich vs target ⇒ swap LT in (TOKEN out).
        // Pool LT-rich ⇒ swap TOKEN in (LT out). Bounded by uint112 reserves
        // and curve-close-shape targets, both products fit in uint256.
        // When `_pairRebalance` returns false the seed is too small for any
        // swap to move the ratio (its fee-charging quote rounds to zero), so
        // the reserves are negligible against this graduation's inventory:
        // overpower them with a direct mint at the cached ratio rather than
        // letting the router deposit at the attacker's ratio. A swap that
        // does fire leaves the pool ≈ at target for the router deposit.
        if (reserveToken * ltFromPair > reserveLT * tokensForLP) {
            // Pool TOKEN-rich. tokenIn = lt, tokenOut = tokenAddress.
            // tokenInIs0 = (lt is token0) = !tokenIs0.
            if (!_pairRebalance(
                    RebalanceParams({
                        pair: pair,
                        tokenIn: lt,
                        tokenInIs0: !tokenIs0,
                        reserveIn: reserveLT,
                        reserveOut: reserveToken,
                        targetN: ltFromPair,
                        targetD: tokensForLP,
                        maxSwap: _swapBudget(_ltSwapInventory(lt, protectedLT))
                    })
                )) {
                return _seedDirectMint(tokenAddress, lt, pair, tokensForLP, ltFromPair);
            }
        } else if (reserveToken * ltFromPair < reserveLT * tokensForLP) {
            // Pool LT-rich. tokenIn = tokenAddress, tokenInIs0 = tokenIs0.
            if (!_pairRebalance(
                    RebalanceParams({
                        pair: pair,
                        tokenIn: tokenAddress,
                        tokenInIs0: tokenIs0,
                        reserveIn: reserveToken,
                        reserveOut: reserveLT,
                        targetN: tokensForLP,
                        targetD: ltFromPair,
                        maxSwap: _swapBudget(IERC20(tokenAddress).balanceOf(address(this)))
                    })
                )) {
                return _seedDirectMint(tokenAddress, lt, pair, tokensForLP, ltFromPair);
            }
        }
        // else: pool already at curve-close ratio (rare — e.g. attacker
        // pre-seeded at exactly target). Skip swap, deposit directly.

        return _routerDepositAndDispose(tokenAddress, lt, protectedLT);
    }

    function _pairRebalance(
        RebalanceParams memory p
    ) internal returns (bool) {
        uint256 s = _noFeeSwapInput(p.reserveIn, p.reserveOut, p.targetN, p.targetD, p.maxSwap);
        if (s == 0) return false;

        // Quote from the pair so the output tracks its live fee; a value
        // derived from a stale fee rate would trip the pair's K-check.
        uint256 expectedOut = IUniswapV2Pair(p.pair).getAmountOut(s, p.tokenIn);
        if (expectedOut == 0) return false;

        IERC20(p.tokenIn).safeTransfer(p.pair, s);
        (uint256 amount0Out, uint256 amount1Out) = p.tokenInIs0 ? (uint256(0), expectedOut) : (expectedOut, uint256(0));
        IUniswapV2Pair(p.pair).swap(amount0Out, amount1Out, address(this), new bytes(0));
        return true;
    }

    function _noFeeSwapInput(
        uint256 reserveIn,
        uint256 reserveOut,
        uint256 targetN,
        uint256 targetD,
        uint256 maxSwap
    ) internal pure returns (uint256) {
        if (reserveIn == 0 || reserveOut == 0 || targetN == 0 || targetD == 0 || maxSwap == 0) {
            return 0;
        }
        uint256 product = Math.mulDiv(reserveIn * reserveOut, targetN, targetD);
        uint256 newIn = Math.sqrt(product);
        if (newIn <= reserveIn) return 0;
        uint256 s = newIn - reserveIn;
        return s > maxSwap ? maxSwap : s;
    }
