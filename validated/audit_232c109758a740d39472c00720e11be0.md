## Analog Found: Improper Authorization via Unsafe Default in `IntentGatewayV2.instance()` (Tron)

### Title
Cross-chain module impersonation via `instance()` fallback to `address(this)` allows unauthorized escrow redemption/refund - ([File: evm/tron/contracts/apps/IntentGatewayV2.sol])

### Summary
The Tron variant of `IntentGatewayV2` authenticates incoming cross-chain `RedeemEscrow`/`RefundEscrow` requests by comparing the request's claimed sender (`request.from`) against `instance(request.source)`. Unlike the canonical EVM implementation, this `instance()` getter silently falls back to `address(this)` — the gateway's own address — whenever no gateway is registered for the source state machine, instead of reverting. This turns an "unknown peer" case into an implicit trust anchor: any counterparty on a state machine that Hyperbridge recognizes but for which this gateway has no registered instance can forge `request.from == address(this)` and pass authentication, exactly as GitLab Pages let a token minted for one context be accepted by another because the validation was not properly scoped to the specific resource.

### Finding Description
Compare the two implementations:

- Canonical EVM (`evm/src/apps/intentsv2/IntentsBase.sol`, `_instance`): reverts with `UnknownInstance` when no gateway is registered for a `stateMachineId`. [1](#0-0) 

- Tron variant (`evm/tron/contracts/apps/IntentGatewayV2.sol`, `instance`): returns `address(this)` when unregistered, and `authenticate` uses this value directly: [2](#0-1) 

`onAccept` dispatches `RedeemEscrow`/`RefundEscrow` bodies straight into `authenticate()` then `withdraw()`, with no additional sender check: [3](#0-2) 

`withdraw()` releases whatever tokens are escrowed under the supplied commitment to the `beneficiary` named in the (attacker-supplied) `WithdrawalRequest` body, with the only guard being that the commitment has non-zero escrow: [4](#0-3) 

Because IntentGatewayV2 contracts are deployed deterministically via CREATE2 to preserve identical addresses across chains (documented rationale in `IntentsBase._blockNumber`'s neighboring comment about "preserving the deterministic CREATE2 deployment addresses"), the Tron gateway's own address is very likely to coincide with, or be freely chosen to coincide with, a contract address on any state machine that Hyperbridge supports for consensus/proof verification but for which this Tron gateway has not yet had a `NewDeployment` registered (a normal transient state, or a chain intentionally never given a Tron-side peer). An attacker who deploys (or already owns) a contract at that address on such a chain, then dispatches a genuine ISMP `PostRequest` from it with `from = <that address>` and a `RedeemEscrow`/`RefundEscrow` body naming an arbitrary escrowed `commitment` and their own `beneficiary`, satisfies `authenticate()` because `instance(request.source)` resolves to `address(this)` — matching `module` — purely due to the absent registration, not any legitimate trust relationship.

### Impact Explanation
This is a concrete theft-of-funds vector: any user's escrowed order inputs on the Tron `IntentGatewayV2` can be redeemed or refunded to an attacker-chosen beneficiary by forging a cross-chain message from an unregistered/attacker-controlled source chain identity, bypassing the intended "known instance" authorization gate entirely. This directly parallels the CVE's bug class — an authorization credential/context validated too loosely, letting it be reused in a scope it was never issued for.

### Likelihood Explanation
Reachable by any unprivileged actor able to dispatch a POST request through ISMP from a chain/state-machine that Hyperbridge tracks consensus for but that has no registered `IntentGatewayV2` peer on Tron — a state that exists by default for every newly-supported or Tron-unpaired chain until governance explicitly calls `NewDeployment`. No admin, governance, or relayer collusion is required beyond normal permissionless message delivery.

### Recommendation
Change `instance()` in `evm/tron/contracts/apps/IntentGatewayV2.sol` to revert (e.g. with `UnknownInstance`) when no gateway is registered for the given `stateMachineId`, matching the canonical `IntentsBase._instance()` behavior, so `authenticate()` can never treat an unconfigured source chain as implicitly trusted.

### Proof of Concept
1. Identify a state machine ID `S` supported by Hyperbridge for consensus verification, for which `_instances[keccak256(S)]` is unset on the Tron `IntentGatewayV2` (fresh chain, or a chain never paired with the Tron deployment).
2. On chain `S`, deploy/own a contract at address `A` such that `A == address(TronIntentGatewayV2)` (feasible via CREATE2 given the deterministic-deployment design, or trivially if `S` is a chain the attacker fully controls addressing on).
3. From `A`, dispatch a legitimate ISMP `PostRequest` to the Tron gateway with `from = A`, body = `[RedeemEscrow] ++ abi.encode(WithdrawalRequest{commitment: <victim's escrowed order commitment>, tokens: <victim's escrowed tokens>, beneficiary: <attacker address>})`.
4. Relay the message; `HandlerV2`/`EvmHost.dispatchIncoming` calls `onAccept`, which calls `authenticate()`: `instance(S)` returns `address(this)` (unregistered fallback) `== module (A)` → passes.
5. `withdraw()` transfers the victim's escrowed tokens to the attacker's beneficiary address.

     * @dev Fetch the IntentGateway contract instance for a chain.

    function instance(bytes calldata stateMachineId) public view returns (address) {
        address gateway = _instances[keccak256(stateMachineId)];
        return gateway == address(0) ? address(this) : gateway;
    }

    /**
     * @dev Checks that the request originates from a known instance of the IntentGateway.
     */
    function authenticate(PostRequest calldata request) internal view {
        if (request.from.length != 20) revert InvalidInput();
        address module = address(bytes20(request.from));
        // IntentGateway only accepts incoming assets from itself or known instances
        if (instance(request.source) != module) revert Unauthorized();
    }
