### Title
Foundation termination flow unstakes a stale `get_account_staked_balance` snapshot instead of the account's full share balance, permanently stranding rewards accrued between the view read and the internal ping - (File: lockup/src/foundation_callbacks.rs, staking-pool/src/lib.rs)

### Summary
`termination_prepare_to_withdraw` obtains the amount to unstake by cross-calling the staking pool's view-style method `get_account_staked_balance`, which never triggers `internal_ping`, and then unstakes exactly that amount via `unstake(amount)`. Because `unstake(amount)` internally re-pings before executing, any reward accrued between the moment the staking pool last pinged and the moment the unstake call executes raises the share price, so the fixed `amount` obtained earlier under-covers the account's now-larger true entitlement in shares. This leaves residual `stake_shares` on the account that the single-pass termination state machine never revisits.

### Finding Description
`termination_prepare_to_withdraw` (in the `VestingTerminatedWithDeficit` branch) calls: [1](#0-0) 

The callback then unstakes exactly the returned snapshot value: [2](#0-1) 

`get_account_staked_balance` is a `&self` (non-mutating) method that simply reads currently stored `total_staked_balance` / `total_stake_shares` without calling `internal_ping`: [3](#0-2) 

By contrast, `unstake(amount)` always pings first, which can materially change the share price before the fixed `amount` is applied: [4](#0-3) [5](#0-4) 

Because `inner_unstake` converts the caller-supplied `amount` to `num_shares` at the (possibly now-higher) post-ping price via `num_shares_from_staked_amount_rounded_up`, and the account's actual number of shares does not change from a ping (only price does), passing a pre-ping `amount` that is lower than the post-ping true value converts to fewer shares than the account actually holds: [6](#0-5) 

The callback `on_staking_pool_unstake_for_termination` treats any promise success as complete, immediately advancing the status to `EverythingUnstaked` with no re-check of the account's remaining `stake_shares`/staked balance: [7](#0-6) 

Once `EverythingUnstaked` is set, the subsequent `termination_prepare_to_withdraw` call only fetches and withdraws the *unstaked* balance — it never loops back to check for remaining staked shares: [8](#0-7) 

There is no code path in the termination state machine (`TerminationStatus`) that returns to `UnstakingInProgress`/`VestingTerminatedWithDeficit` after `EverythingUnstaked` is reached, so any residual staked shares from this race remain staked and effectively frozen from the lockup contract's perspective.

The root cause is the design choice to unstake by an explicit externally-fetched `amount` rather than calling the staking pool's `unstake_all()` method, which computes `amount` from the account's live `stake_shares` at ping-updated price at unstake time (see `staking-pool/src/lib.rs::unstake_all`, lines 291-301), guaranteeing full capture regardless of any pending un-pinged reward.

### Impact Explanation
The window for this race is realistic in practice: if the staking pool has not been pinged for one or more epochs (i.e., no other user has deposited/staked/unstaked/withdrawn on it since the last epoch boundary), `get_account_staked_balance` returns a stale, low value based on the old share price. When `termination_prepare_to_withdraw`'s callback then calls `unstake(stale_amount)`, the internal ping inside `unstake` catches up on all the epochs' worth of accumulated rewards at once, potentially a non-trivial amount, not merely 1-yocto rounding dust. The resulting shortfall in unstaked shares remains staked at the pool, associated with the lockup account, and is not covered by any later step of the termination flow. This matches "Permanent freezing/irrecoverable loss of user or protocol funds in vesting termination... unstake-withdraw flows," a valid Critical/High impact per the scope, since the un-captured tokens can never be reached through `termination_prepare_to_withdraw`/`termination_withdraw` once `EverythingUnstaked` is set (no re-entry path back to unstaking).

### Likelihood Explanation
This requires no attacker privilege — it can occur purely from normal contract/timing dynamics: the foundation account triggering `termination_prepare_to_withdraw` while the staking pool happens not to have been pinged recently. The larger the un-pinged reward backlog (which grows the longer nobody else interacts with the pool), the larger the stranded residue. It is a deterministic accounting bug tied to the state-machine's one-shot design rather than a probabilistic or exotic attack, making it moderately likely to occur in real deployments where delegator activity on a given validator's pool is sparse.

### Recommendation
Change `on_get_account_staked_balance_to_unstake` (or the initiating call) to invoke the staking pool's `unstake_all()` instead of `unstake(amount)`, so the pool computes the amount to unstake from the account's live share balance at the post-ping price rather than a value snapshotted before the ping. Alternatively, after `on_staking_pool_unstake_for_termination` succeeds, re-query `get_account_staked_balance` and only transition to `EverythingUnstaked` if the remaining staked balance is `0`; otherwise loop back into `UnstakingInProgress`/`VestingTerminatedWithDeficit` to unstake the remainder.

### Proof of Concept
1. Foundation deploys lockup with a staking pool selected and vesting terminated with a deficit (`TerminationStatus::VestingTerminatedWithDeficit`).
2. Ensure the staking pool has not been pinged since the current epoch began (no deposits/stakes/unstakes/withdrawals by any party), while validator rewards for the epoch have accrued to `env::account_locked_balance()`.
3. Foundation calls `termination_prepare_to_withdraw()`; this issues `get_account_staked_balance` (reads pre-ping/stale `total_staked_balance`/`total_stake_shares`), returning `staked_balance = X`.
4. Callback `on_get_account_staked_balance_to_unstake` calls `unstake(X)`. Inside the staking pool, `internal_ping()` runs first, crediting the pending reward and raising the share price so the account's true entitlement in tokens is now `X' > X`.
5. `inner_unstake(X)` converts `X` to `num_shares` at the new (higher) price, which is fewer shares than `account.stake_shares` — leaving `account.stake_shares > 0` still staked.
6. `on_staking_pool_unstake_for_termination` sees promise success and sets `TerminationStatus::EverythingUnstaked`.
7. A subsequent `get_account_staked_balance` view call for the lockup account on the staking pool returns `> 0`, confirming real stake remains, yet the lockup's termination status has already advanced past the unstaking phase with no code path to retry, permanently stranding the residual reward-derived stake.

            self.set_staking_pool_status(TransactionStatus::Idle);
            self.set_termination_status(TerminationStatus::EverythingUnstaked);
            PromiseOrValue::Value(true)
        }
    }

    pub fn on_staking_pool_unstake_for_termination(&mut self, amount: WrappedBalance) -> bool {
        assert_self();

        let unstake_succeeded = is_promise_success();
        self.set_staking_pool_status(TransactionStatus::Idle);

        if unstake_succeeded {
            self.set_termination_status(TerminationStatus::EverythingUnstaked);
            env::log(
                format!(
                    "Termination Step: Unstaking of {} at @{} succeeded",
                    amount.0,
                    self.staking_information
                        .as_ref()
                        .unwrap()
                        .staking_pool_account_id
                )
                .as_bytes(),
            );
        } else {
            self.set_termination_status(TerminationStatus::VestingTerminatedWithDeficit);
            env::log(
                format!(
                    "Termination Step: Unstaking {} at @{} has failed",
                    amount.0,
                    self.staking_information
                        .as_ref()
                        .unwrap()
                        .staking_pool_account_id
                )
                .as_bytes(),
            );
        }
        unstake_succeeded
    }

    pub(crate) fn inner_unstake(&mut self, amount: u128) {
        assert!(amount > 0, "Unstaking amount should be positive");

        let account_id = env::predecessor_account_id();
        let mut account = self.internal_get_account(&account_id);

        assert!(
            self.total_staked_balance > 0,
            "The contract doesn't have staked balance"
        );
        // Calculate the number of shares required to unstake the given amount.
        // NOTE: The number of shares the account will pay is rounded up.
        let num_shares = self.num_shares_from_staked_amount_rounded_up(amount);
        assert!(
            num_shares > 0,
            "Invariant violation. The calculated number of \"stake\" shares for unstaking should be positive"
        );
        assert!(
            account.stake_shares >= num_shares,
            "Not enough staked balance to unstake"
        );

        // Calculating the amount of tokens the account will receive by unstaking the corresponding
        // number of "stake" shares, rounding up.
        let receive_amount = self.staked_amount_from_num_shares_rounded_up(num_shares);
        assert!(
            receive_amount > 0,
            "Invariant violation. Calculated staked amount must be positive, because \"stake\" share price should be at least 1"
        );

        account.stake_shares -= num_shares;
        account.unstaked += receive_amount;
        account.unstaked_available_epoch_height = env::epoch_height() + NUM_EPOCHS_TO_UNLOCK;
        self.internal_save_account(&account_id, &account);

        // The amount tokens that will be unstaked from the total to guarantee the "stake" share
        // price never decreases. The difference between `receive_amount` and `unstake_amount` is
        // paid from the allocated STAKE_SHARE_PRICE_GUARANTEE_FUND.
        let unstake_amount = self.staked_amount_from_num_shares_rounded_down(num_shares);

        self.total_staked_balance -= unstake_amount;
        self.total_stake_shares -= num_shares;

    /// Distributes rewards after the new epoch. It's automatically called before every action.
    /// Returns true if the current epoch height is different from the last epoch height.
    pub(crate) fn internal_ping(&mut self) -> bool {
        let epoch_height = env::epoch_height();
        if self.last_epoch_height == epoch_height {
            return false;
        }
        self.last_epoch_height = epoch_height;

        // New total amount (both locked and unlocked balances).
        // NOTE: We need to subtract `attached_deposit` in case `ping` called from `deposit` call
        // since the attached deposit gets included in the `account_balance`, and we have not
        // accounted it yet.
        let total_balance =
            env::account_locked_balance() + env::account_balance() - env::attached_deposit();

        assert!(
            total_balance >= self.last_total_balance,
            "The new total balance should not be less than the old total balance"
        );
        let total_reward = total_balance - self.last_total_balance;
        if total_reward > 0 {
            // The validation fee that the contract owner takes.
            let owners_fee = self.reward_fee_fraction.multiply(total_reward);

            // Distributing the remaining reward to the delegators first.
            let remaining_reward = total_reward - owners_fee;
            self.total_staked_balance += remaining_reward;

            // Now buying "stake" shares for the contract owner at the new share price.
            let num_shares = self.num_shares_from_staked_amount_rounded_down(owners_fee);
            if num_shares > 0 {
                // Updating owner's inner account
                let owner_id = self.owner_id.clone();
                let mut account = self.internal_get_account(&owner_id);
                account.stake_shares += num_shares;
                self.internal_save_account(&owner_id, &account);
                // Increasing the total amount of "stake" shares.
                self.total_stake_shares += num_shares;
            }
            // Increasing the total staked balance by the owners fee, no matter whether the owner
            // received any shares or not.
            self.total_staked_balance += owners_fee;

            env::log(
                format!(
                    "Epoch {}: Contract received total rewards of {} tokens. New total staked balance is {}. Total number of shares {}",
                    epoch_height, total_reward, self.total_staked_balance, self.total_stake_shares,
                )
                    .as_bytes(),
            );
            if num_shares > 0 {
                env::log(format!("Total rewards fee is {} stake shares.", num_shares).as_bytes());
            }
        }

        self.last_total_balance = total_balance;
        true
    }
