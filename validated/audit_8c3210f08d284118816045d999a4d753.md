### Title
Bad-debt wipeout floors supply index at `SUPPLY_INDEX_FLOOR_RAW`, leaving wiped suppliers a phantom claim that drains later deposits - (File: contracts/pool/src/interest.rs)

### Summary
The analog of CVE-2026-58469 is a "walk-past-the-start" failure on a value-reduction path: `apply_bad_debt_to_supply_index` is supposed to drive supplier value to zero when bad debt consumes the entire pool, but it caps the reduction and then clamps the resulting supply index up to `SUPPLY_INDEX_FLOOR_RAW`. Like the Metalink trim loop that only misbehaves on the degenerate all-whitespace input, this only misbehaves on the degenerate full-wipeout input: instead of reaching zero, the index stops short, leaving every pre-wipeout supply share with a nonzero residual claim that is paid out of future depositors' cash.

### Finding Description
`apply_bad_debt_to_supply_index` computes `remaining = total_supplied_value - min(bad_debt, total_supplied_value)` and multiplies the supply index by `remaining / total_supplied_value`. When `bad_debt >= total_supplied_value`, `remaining` is zero and `new_supply_index` is zero — but the result is then clamped with `.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW))`, so the index lands at roughly `RAY/1000` rather than zero. [1](#0-0) 

Because positions store raw scaled shares (`scaled_amount`), every wiped supplier retains `scaled_amount * SUPPLY_INDEX_FLOOR_RAW` of claim value. `supplied` itself is not reduced, so the aggregate claim across all old shares equals roughly 0.1% of the pre-wipeout supplied value — real, withdrawable value with no backing. `resolve_withdrawal` + `require_reserves` only check that gross payout ≤ current cash, so once any new deposit lands, old shares withdraw against it. The repository's own test demonstrates this exactly: `test_raw_cache_floor_clamp_strands_claim_without_supply_guard` seeds a wipeout, deposits `fresh_cash == stranded` from a fresh supplier, then shows `resolve_withdrawal(i128::MAX, old_scaled)` paying `gross == fresh_cash` to the wiped position, leaving the fresh depositor undercollateralized. [2](#0-1) 

Reachability: `clean_bad_debt` on the controller is a permissionless entrypoint (listed in `scripts/permissionless_entrypoints.txt`), and liquidation (`SeizeMode::Credit` / `apply_liquidation_share_credit`) funnels unpaid debt into the same pool-side write-down. An unprivileged actor only needs a position whose debt exceeds recoverable collateral — creatable with a volatile collateral asset or by riding price movement — then calls `clean_bad_debt`/liquidation legs until `bad_debt` reaches `total_supplied_value`.

### Impact Explanation
Theft of user funds. After a full wipeout, the first new suppliers' deposits are claimable by old wiped shares up to ~0.1% of the pre-wipeout supplied value in aggregate (bounded by cash present). Since `supplied` is unchanged and the index is nonzero, `get_supplied_amount`-style views also misreport wiped positions as solvent, inviting further deposits into the insolvent book.

### Likelihood Explanation
Requires a market to reach `bad_debt >= total_supplied_value`, i.e., total wipeout — an extreme but reachable state via a severe price crash or an illiquid spoke asset, with `clean_bad_debt` callable by anyone. Once reached, the payout is deterministic (no race): whoever supplies next is drained by whichever wiped holder withdraws first. Medium likelihood, bounded magnitude (0.1% of wiped supply) → Medium severity.

### Recommendation
On `remaining == Ray::ZERO`, either zero all supply shares consistently (write `supplied = 0`, `revenue = 0`, and accept/handle index zero at the `div_floor`/`div_ceil` scaling sites in `common/src/rates/scaling.rs:37-67`), or proportionally burn scaled shares so that `supplied * floor_index` reflects only intentionally preserved value. At minimum, reduce `supplied` by the wiped fraction inside `apply_bad_debt_to_supply_index` so residual claims cannot exceed actual remaining value.

### Proof of Concept
Mirror `test_raw_cache_floor_clamp_strands_claim_without_supply_guard` end-to-end:
1. Supplier A supplies `S` units; borrower opens debt, collateral collapses.
2. Keeper/anyone calls `liquidate` then `clean_bad_debt` until `apply_bad_debt_to_supply_index` runs with `bad_debt >= supplied * supply_index`; index clamps to `SUPPLY_INDEX_FLOOR_RAW`, `supplied` untouched.
3. Supplier B deposits `D = S_old_scaled * SUPPLY_INDEX_FLOOR_RAW` units.
4. A calls `withdraw(0)` (sentinel for full withdrawal); `resolve_withdrawal` unscale-floors the old shares at the floored index and `require_reserves` passes against B's cash. A receives `D`; B's claim `D` can no longer be covered by pool cash.

Caveat: the floor clamp is an explicitly documented design choice ("to avoid a zero index"), so this may be a known accepted trade-off; if so, it should be rejected under the documented-ADR exclusion. I was unable to fully verify whether `clean_bad_debt` zeroes `supplied` elsewhere in the same commit — the pool test above strongly suggests it does not.

pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}

#[test]
fn test_raw_cache_floor_clamp_strands_claim_without_supply_guard() {
    let t = TestSetup::new();
    t.as_contract(|| {
        let old_scaled_raw = 1_000 * RAY;
        let mut cache = t.fresh_cache(PoolStateRaw {
            supplied: old_scaled_raw,
            borrowed: 0,
            revenue: 0,
            borrow_index: RAY,
            supply_index: RAY,
            last_timestamp: 0,
            cash: 0,
        });
        let old_scaled = Ray::from(old_scaled_raw);

        apply_bad_debt_to_supply_index(&mut cache, Ray::from(5_000 * RAY));
        assert_eq!(
            cache.supply_index().raw(),
            SUPPLY_INDEX_FLOOR_RAW,
            "wipeout clamps supply_index UP to RAY/1000 instead of resetting shares to 0",
        );

        let stranded = cache.unscale_supply_floor(old_scaled);
        assert!(stranded > 0, "floor clamp leaves S_old a phantom claim");
        assert_eq!(
            cache.cash(),
            0,
            "no cash yet: invariant only masked by require_reserves"
        );

        let fresh_cash = stranded;
        let fresh_scaled = cache.calculate_scaled_supply(fresh_cash);
        cache.mint_supply(fresh_scaled);
        cache.credit_cash(fresh_cash);

        let fresh_claim = cache.unscale_supply_floor(fresh_scaled);
        assert_eq!(
            fresh_claim, fresh_cash,
            "fresh supplier's claim equals deposit"
        );

        let (burn, gross) = cache.resolve_withdrawal(i128::MAX, old_scaled);
        cache.require_reserves(gross);
        cache.burn_supply(burn);
        cache.debit_cash(gross);

        assert!(gross > 0, "stranded wiped position pays out real tokens");
        assert_eq!(gross, fresh_cash, "S_old drains exactly the fresh deposit");
        assert!(
            cache.cash() < fresh_claim,
            "pool cash ({}) can no longer cover fresh supplier claim ({}): funds lost",
            cache.cash(),
            fresh_claim,
        );
    });
}
