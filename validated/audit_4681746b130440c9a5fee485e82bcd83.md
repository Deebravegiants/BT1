## Finding

### Title
Unauthenticated pipeline run resume endpoint allows result/error injection and job-state hijacking — (File: `core/web/router.go`, `core/web/pipeline_runs_controller.go`)

### Summary
The external report highlights that `restartDca` lets an unprivileged caller mutate sensitive, trust-bearing state (`isGelatoWatching`, `taskId`) with no ownership or state-consistency checks, effectively letting anyone hijack or corrupt another user's DCA. The chainlink analog is `PipelineRunsController.Resume`, mounted on the completely unauthenticated route group and lacking any check that the caller is the legitimate party (e.g., an external adapter/bridge) that is supposed to supply the async task result.

### Finding Description
`PipelineRunsController.Resume` is registered with **no authentication middleware at all**: [1](#0-0) 

```go
func v2Routes(app chainlink.Application, r *gin.RouterGroup) {
	unauthedv2 := r.Group("/v2")

	prc := PipelineRunsController{app}
	psec := PipelineJobSpecErrorsController{app}
	unauthedv2.PATCH("/resume/:runID", prc.Resume)
```

Compare this with every other write-capable route, which is wrapped in `auth.Authenticate(...)` with session/token/external-initiator checks and role gating (`auth.RequiresRunRole`, `auth.RequiresEditRole`, etc.), as seen throughout the rest of `v2Routes` [2](#0-1) .

The handler itself only validates that `runID` parses as a UUID and that the JSON body decodes; it performs no ownership, ACL, or provenance check on the caller before mutating pipeline state: [3](#0-2) 

This flows into `Application.ResumeJobV2` → `runner.ResumeRun` → `orm.UpdateTaskRunResult`: [4](#0-3) 

The ORM update itself only checks that the *run* (not the specific task run) is in `running`/`suspended` state — it does not check that the specific `pipeline_task_runs` row is still pending (`finished_at IS NULL`) before overwriting its output/error: [5](#0-4) 

This mirrors the `restartDca` defect pattern precisely: the code that mutates trust-sensitive execution state (a task's result, which can drive an `ETHTx` task or other side-effecting pipeline stages) omits the validation step that would normally be enforced by the "create" path — here, the authenticated `AuthenticateExternalInitiator` / access-key+secret flow used elsewhere in the codebase: [6](#0-5) 

Unlike that flow, which does a constant-time comparison of an access key + hashed secret pair, the resume endpoint's only "secret" is the task UUID itself, and there is no additional signature/HMAC/ownership binding checked at the HTTP layer.

### Impact Explanation
Any unauthenticated network client that obtains or guesses a valid task run UUID can:
- Inject arbitrary `value`/`error` results into a pending pipeline task run for any job on the node, impersonating the legitimate external adapter/bridge that was supposed to supply that result.
- Re-post to the same `runID` to overwrite an already-completed task run's output/error while the enclosing run is still `running`/`suspended` for other branches, since the update query is not scoped to `finished_at IS NULL` on that specific task row.
- Because pipeline tasks feed data into downstream tasks (including fund-moving `ETHTx` tasks), a spoofed result can corrupt job outputs or induce unintended downstream execution paths, analogous to how `restartDca`'s missing checks let an attacker silently disable/redirect a victim's DCA task.

### Likelihood Explanation
The endpoint requires no authentication whatsoever — it is registered on the `unauthedv2` group, unlike every comparable state-mutating route. The only barrier is guessing/obtaining a UUID `runID`. These UUIDs can leak through logs, monitoring dashboards, external-adapter integration configs, or other channels not designed to be treated as bearer secrets equivalent to the access-key/secret pairs used elsewhere in the codebase for the same trust boundary (external initiators).

### Recommendation
1. Short term: require the caller to authenticate as the specific external initiator/bridge that owns the pending task (or bind an HMAC/shared-secret per task run) before `Resume` is allowed to mutate task state, mirroring `AuthenticateExternalInitiator`'s constant-time secret comparison.
2. Add a `finished_at IS NULL` (or equivalent "still pending") condition to the `UpdateTaskRunResult` query scoped to the specific task run, not just the run's overall state, to prevent re-injection/overwrite of already-completed task results.
3. Long term: document and test the intended trust model for `/v2/resume/:runID`, and add unit/integration tests (as recommended in the referenced report) covering unauthorized/duplicate resume attempts.

### Proof of Concept
```
# Attacker obtains/guesses a pending task run UUID (e.g., leaked via logs or external-adapter config)
curl -X PATCH http://node:6688/v2/resume/<taskID> \
  -H 'Content-Type: application/json' \
  -d '{"value": "9999999"}'
# No authentication header required — request succeeds if the run is still running/suspended,
# injecting an attacker-controlled value into the pipeline task, potentially feeding
# a downstream ETHTx or other side-effecting task.
``` [7](#0-6)

func (prc *PipelineRunsController) Resume(c *gin.Context) {
	taskID, err := uuid.Parse(c.Param("runID"))
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	rr := pipeline.ResumeRequest{}
	decoder := json.NewDecoder(c.Request.Body)
	err = errors.Wrap(decoder.Decode(&rr), "failed to unmarshal JSON body")
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	result, err := rr.ToResult()
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	if err := prc.App.ResumeJobV2(c.Request.Context(), taskID, result); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
	c.Status(http.StatusOK)
}

func (r *runner) ResumeRun(ctx context.Context, taskID uuid.UUID, value any, err error) error {
	run, start, err := r.orm.UpdateTaskRunResult(ctx, taskID, Result{
		Value: value,
		Error: err,
	})
	if err != nil {
		return fmt.Errorf("failed to update task run result: %w", err)
	}

	// TODO: Should probably replace this with a listener to update events
	// which allows to pass in a transactionalised database to this function
	if start {
		// start the runner again
		go func() {
			ctx, cancel := r.chStop.NewCtx()
			defer cancel()
			if _, err := r.Run(ctx, &run, false, nil); err != nil {
				r.lggr.Errorw("Resume run failure", "err", err)
			}
			r.lggr.Debug("Resume run success")
		}()
	}
	return nil
}

	if result.OutputDB().Valid && result.ErrorDB().Valid {
		panic("run result must specify either output or error, not both")
	}
	err = o.transact(ctx, func(tx *orm) error {
		sql := `
		SELECT pipeline_runs.*, pipeline_specs.dot_dag_source "pipeline_spec.dot_dag_source", job_pipeline_specs.job_id "job_id"
		FROM pipeline_runs
		JOIN pipeline_task_runs ON (pipeline_task_runs.pipeline_run_id = pipeline_runs.id)
		JOIN pipeline_specs ON (pipeline_specs.id = pipeline_runs.pipeline_spec_id)
		JOIN job_pipeline_specs ON (job_pipeline_specs.pipeline_spec_id = pipeline_specs.id)
		WHERE pipeline_task_runs.id = $1 AND pipeline_runs.state in ('running', 'suspended')
		FOR UPDATE`

			return fmt.Errorf("failed to find pipeline run for task ID %s: %w", taskID.String(), err)

// Implements authMethod
func AuthenticateExternalInitiator(c *gin.Context, store Authenticator) error {
	ctx := c.Request.Context()
	eia := &auth.Token{
		AccessKey: c.GetHeader(static.ExternalInitiatorAccessKeyHeader),
		Secret:    c.GetHeader(static.ExternalInitiatorSecretHeader),
	}

	ei, err := store.FindExternalInitiator(ctx, eia)
	if err != nil {
		if errors.Is(err, sql.ErrNoRows) {
			return auth.ErrorAuthFailed
		}

		return errors.Wrap(err, "finding external initiator")
	}

	ok, err := bridges.AuthenticateExternalInitiator(eia, ei)
	if err != nil {
		return err
	}
	if !ok {
		return auth.ErrorAuthFailed
	}

	// External initiator endpoints (wrapped with AuthenticateExternalInitiator) inherently assume the role
	// of 'run' (required to trigger job runs)
	c.Set(SessionExternalInitiatorKey, ei)
	c.Set(SessionUserKey, &clsessions.User{Role: clsessions.UserRoleRun})

	return nil
}
