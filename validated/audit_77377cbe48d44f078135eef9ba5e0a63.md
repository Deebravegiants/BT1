### Title
Webhook shop-domain header is not covered by the HMAC signature, enabling cross-tenant webhook spoofing - (File: `lib/shopify_api/webhooks/request.rb`)

### Summary
`ShopifyAPI::Webhooks::Registry.process` authenticates a webhook solely by validating the HMAC over the raw request body, but the `shop` (and `topic`, `webhook_id`, `api_version`) values that the handler consumes to identify the tenant are taken from unauthenticated headers that are never part of the signed payload.

### Finding Description
`ShopifyAPI::Webhooks::Request#to_signable_string` returns only `@raw_body`: [1](#0-0) 
while `#shop`, `#topic`, `#webhook_id`, and `#api_version` are all read straight from HTTP headers with no cryptographic binding to the body: [2](#0-1) 

`Registry.process` verifies the HMAC and then immediately hands `request.shop` (an unauthenticated header value) to the app's handler as the tenant identity: [3](#0-2) 

Because a single per-app `client_secret`/`api_secret_key` is used to sign webhooks for *every* shop that installs the app (not a per-shop secret), any shop where the app is installed can obtain validly-signed `(body, hmac)` pairs from Shopify for its own legitimate webhook traffic. The equality that should hold is:

`shop authenticated by the HMAC == shop delivered to the handler as WebhookMetadata#shop`

but instead the code only enforces `body authenticated by the HMAC == raw body`, and separately trusts whatever `x-shopify-shop-domain` header value the caller sends, with no check that it matches the shop the payload was actually generated for.

### Impact Explanation
An attacker who controls their own shop with the app installed can capture a legitimately-signed webhook body/HMAC pair from their own store, then replay it to the app's webhook endpoint while substituting the `X-Shopify-Shop-Domain` (or `Shopify-Shop-Domain`) header with a victim shop's domain. `Utils::HmacValidator.validate` still succeeds because it only checks the body against the shared app secret; `Registry.process` then dispatches to the handler with `shop: <victim shop>` and attacker-controlled `body`. Any host application that uses `WebhookMetadata#shop` to look up sessions/tokens or to scope database writes for that shop will process attacker-supplied data under the victim's tenant identity — a cross-tenant confusion/injection primitive.

### Likelihood Explanation
Any merchant/developer who can install the app on a store they control (a routine, unprivileged action for any Shopify developer) can obtain valid `(body, hmac)` pairs for that shop, then simply resend the HTTP request with a different `shop-domain` header value to any other shop's webhook endpoint on the same app. No secret key, session token, or elevated privilege is required beyond installing the app on one's own shop.

### Recommendation
Include `shop` (and ideally `topic`/`webhook_id`) inside the signed content, or otherwise cryptographically bind the header-derived shop to the specific installation/session the webhook endpoint expects, e.g., by validating `request.shop` against the shop associated with the resolved `webhook_id`/subscription via a follow-up Admin API check, or by not trusting the `shop-domain` header at all for authorization decisions unless it is independently verified against Shopify's recorded webhook subscription for that ID.

### Proof of Concept
```ruby
# 1. Attacker installs the app on their own shop "attacker.myshopify.com"
#    and captures a real webhook delivery, e.g. for topic "orders/create":
raw_body = '{"id": 1, "malicious": "payload"}'
hmac = OpenSSL::HMAC.digest(OpenSSL::Digest.new("sha256"), APP_SECRET, raw_body)
# (This hmac is valid because the same app secret signs webhooks for all shops.)

# 2. Attacker replays the same body+hmac to the app's webhook endpoint,
#    but swaps the shop-domain header to the victim's shop:
headers = {
  "x-shopify-topic" => "orders/create",
  "x-shopify-hmac-sha256" => Base64.encode64(hmac),
  "x-shopify-shop-domain" => "victim-shop.myshopify.com", # forged
  "x-shopify-webhook-id" => "any-id",
  "x-shopify-api-version" => "2024-01",
}

request = ShopifyAPI::Webhooks::Request.new(raw_body: raw_body, headers: headers)
ShopifyAPI::Webhooks::Registry.process(request)
# HmacValidator.validate(request) => true, because only raw_body is signed.
# Handler is invoked with WebhookMetadata(shop: "victim-shop.myshopify.com", body: attacker-controlled)
```
