Audit Report

## Title
Unprivileged `view`-role users can list External Initiator `AccessKey`/`OutgoingToken` credentials via `GET /v2/external_initiators` - (File: core/web/router.go)

## Summary
`GET /v2/external_initiators` is registered with only the base `Authenticate` middleware (session or API token, any role), while the sibling `POST`/`DELETE` routes are wrapped in `auth.RequiresEditRole`. The `Index` handler returns `presenters.ExternalInitiatorResource`, which includes each initiator's `AccessKey` and `OutgoingToken` fields unconditionally, so a low-privilege `view`-role user can enumerate these credential values.

## Finding Description
In `v2Routes`, `authv2.GET("/external_initiators", paginatedRequest(eia.Index))` has no role wrapper, whereas `authv2.POST("/external_initiators", auth.RequiresEditRole(eia.Create))` and the `DELETE` route do [1](#0-0) . The outer group `authv2` only requires `auth.Authenticate` via session or API token, which succeeds for any authenticated role including `UserRoleView` [5](#0-4) . `ExternalInitiatorsController.Index` fetches all rows from `BridgeORM().ExternalInitiators` and maps each to `presenters.NewExternalInitiatorResource` without any filtering by caller identity or role [2](#0-1) . That resource struct serializes `AccessKey` and `OutgoingToken` directly from the `bridges.ExternalInitiator` model [3](#0-2) . `auth.RequiresRunRole`/`RequiresEditRole` explicitly demonstrate the role hierarchy (`view` < `run` < `edit`/`admin`) and that `view` is rejected by both stricter gates [4](#0-3) , confirming the `Index` route is reachable by `view` precisely because it lacks any such wrapper.

## Impact Explanation
`AccessKey`/`Secret` pairs authenticate external initiator calls to `POST /v2/jobs/:ID/runs`, granting the caller an implicit `run` role via `AuthenticateExternalInitiator` [6](#0-5) ; `OutgoingToken`/`OutgoingSecret` are secrets the node uses to authenticate itself outward to the initiator's callback URL. Exposing `AccessKey` and `OutgoingToken` to a `view`-role principal is a real secret/credential disclosure that breaks the intended privilege separation between `view` (read-only dashboard) and `edit`/`run` roles, falling under the in-scope "key/secret exfiltration" and "node API role bypass" categories.

## Likelihood Explanation
The exploit requires only a valid `view`-role session cookie or API key/secret pair (the lowest privilege tier a node operator can provision) and a single unauthenticated-parameter `GET` request; it is deterministic and repeatable with no timing, race, or additional interaction needed.

## Recommendation
Wrap `authv2.GET("/external_initiators", ...)` in `auth.RequiresEditRole` (or at minimum `RequiresRunRole`) to match the write endpoints, and/or remove `AccessKey`/`OutgoingToken` from the list resource, mirroring how bridge `IncomingToken` is only exposed at creation time and not on `Index`/`Show`.

## Proof of Concept
1. As an admin, create an external initiator via `POST /v2/external_initiators` (captures `AccessKey`/`OutgoingToken`).
2. Create a second user with role `view` (`clsessions.UserRoleView`) and obtain a session cookie or API key/secret for that user.
3. As the `view` user, call `GET /v2/external_initiators`.
4. Observe the JSON response's `externalInitiators` array contains `accessKey` and `outgoingToken` for the initiator created in step 1, despite the `view` role being rejected by `auth.RequiresRunRole`/`RequiresEditRole` on every other mutating route — confirmed by the route table [1](#0-0)  and resource definition [7](#0-6) .

func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))

	}

// AuthenticateExternalInitiator compares an auth against an initiator and

func AuthenticateExternalInitiator(eia *auth.Token, ea *ExternalInitiator) (bool, error) {
	hashedSecret, err := auth.HashedSecret(eia, ea.Salt)
	if err != nil {
		return false, err
	}
	return subtle.ConstantTimeCompare([]byte(hashedSecret), []byte(ea.HashedSecret)) == 1, nil
}
