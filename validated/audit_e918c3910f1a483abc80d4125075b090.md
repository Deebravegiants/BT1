### Title
`DepositOnChainUtxosExternalAction.runAction()` pulls tokens using an unverified `circomData.originalSender` field, not msg.sender - ([File: contracts/external-actions/DepositOnChainUtxosExternalAction.sol])

### Summary
`DepositOnChainUtxosExternalAction.runAction()` transfers ERC20 tokens away from `circomData.originalSender` using `transferERC20TokenFrom`, but `originalSender` is a plain calldata field that is neither checked against `msg.sender`/`tx.origin` nor included in the circuit's `signedMessageHash`/public-input vector [1](#0-0) . Anyone who submits calldata to `Hinkal` can set this field to any address, and the token movement is authorised only by the pre-existing ERC20 `approve` a victim previously granted to the Hinkal contracts, not by any signature that the circuit or an off-chain relayer verifies.

### Finding Description
In `Hinkal.sol`'s normal internal deposit path, the protocol explicitly enforces that the depositing address equals the transaction sender: `require(circomData.externalActionData.externalAddress == msg.sender, "Deposit should come from the sender")` [2](#0-1) . This equality is the mechanism that ties any `transferFrom`-based fund movement to the actual caller/authoriser.

`DepositOnChainUtxosExternalAction.runAction()` breaks this equality. It reads `userAddress = circomData.originalSender` directly from calldata and immediately performs `transferERC20TokenFrom(tokenAddress, userAddress, msg.sender, tokenTotal)` with no check that `userAddress == msg.sender` (the outer transaction caller) or any other check binding it to a signer [3](#0-2) .

Confirming that this field is unconstrained by the ZK proof: `getSignedMessageHash`/`formBasicInput` in `CircomDataBuilder.sol`, which build the circuit's public-input/signed-message vector, hash `rootHashHinkal`, token addresses, `amountChanges`, `timeStamp`, nullifiers, `outCommitments`, `calldataHash`, and the stealth-address fields — `originalSender` is absent from this list [4](#0-3) [5](#0-4) . So the EdDSA signature verified inside `MainEVMCircuit` (`SignatureVerifier`, over `signedMessageHash`) never commits to whose tokens are being pulled [6](#0-5) .

This exactly mirrors the reported bug class: a value-bearing field (`priceSig.timestamp` in the original report; `circomData.originalSender` here) is used to move value/assets but is not properly constrained by the equality (signature/public-input) that is supposed to authorise the action, letting an unprivileged party choose it maliciously.

### Impact Explanation
Any address that has ever granted ERC20 allowance to the Hinkal/external-action contracts (a normal step for using the protocol's deposit flow) is at risk: any other unprivileged caller can submit a transaction to `Hinkal` that routes through `DepositOnChainUtxosExternalAction` with `circomData.originalSender` set to the victim's address and `stealthAddressStructure` set to the attacker's own stealth address. The victim's approved tokens are pulled via `transferFrom` and minted into a shielded UTXO fully controlled by the attacker, resulting in direct theft of the victim's funds. This is a Critical impact: direct theft of user funds via an unauthorised `transferFrom` that the wallet owner never approved for this specific transaction.

### Likelihood Explanation
Likelihood depends on the victim having outstanding ERC20 allowance to the relevant contract, which is a common state for active users of an approve-then-deposit protocol (and can also occur via `approve(..., type(uint256).max)`, a widespread wallet/dApp pattern). No privileged role, admin key, or relayer collusion is required — any EOA can call the public `transact` entrypoint with attacker-chosen `CircomData` routed to this external action. The only gate is `onlyAllowedRecipient`, which restricts which *external action contract* can be invoked, not who supplies `originalSender` within it.

### Recommendation
Constrain `circomData.originalSender` the same way normal deposits are constrained in `Hinkal.sol`: require `circomData.originalSender == msg.sender` (or the true outer caller, propagated through the external-action dispatch) before calling `transferERC20TokenFrom`. Alternatively, remove reliance on a freely-chosen `originalSender` and require the token source to be committed inside `signedMessageHash`/the public-input vector so the EdDSA-signing party explicitly authorises the specific depositor address.

### Proof of Concept
1. Victim `V` approves the Hinkal external-action contract (or Hinkal itself) for `X` tokens, as required by normal protocol usage.
2. Attacker `A` crafts `CircomData` with `originalSender = V`, `stealthAddressStructure` pointing to `A`'s own shielded stealth address, `erc20TokenAddresses = [tokenX]`, and appropriate `deltaAmounts[i] == 0` per the function's requirement [7](#0-6) , and an `externalActionData.externalActionMetadata` encoding `utxoAmounts` up to `X`.
3. `A` calls `Hinkal`'s external-transact entrypoint, which dispatches to `DepositOnChainUtxosExternalAction.runAction()`.
4. `transferERC20TokenFrom(tokenX, V, msg.sender, X)` executes successfully using `V`'s pre-existing allowance [8](#0-7) .
5. A new UTXO for amount `X` is created under `A`'s stealth address and inserted into the shielded pool, giving `A` spendable shielded value backed by `V`'s stolen tokens.

    function getSignedMessageHash(
        uint256 chainId,
        address verifyingContract,
        CircomData calldata circomData,
        uint256 emporiumMessage
    ) internal pure returns (uint256) {
        // split into two encode calls to avoid "stack too deep"
        uint256 hash1 = uint256(
            keccak256(
                abi.encode(
                    chainId,
                    verifyingContract,
                    circomData.rootHashHinkal,
                    _encodeTokenAddresses(circomData.erc20TokenAddresses),
                    _encodeAmountChanges(circomData.amountChanges),
                    circomData.timeStamp,
                    _flatUint256Matrix(circomData.inputNullifiers),
                    _flatUint256Matrix(circomData.outCommitments),
                    circomData.calldataHash,
                    emporiumMessage
                )
            )
        );
        uint256 hash2 = uint256(
            keccak256(
                abi.encode(
                    circomData.stealthAddressStructure.H1x,
                    circomData.stealthAddressStructure.H1y,
                    circomData.stealthAddressStructure.H0x,
                    circomData.stealthAddressStructure.H0y
                )
            )
        );
        return
            uint256(keccak256(abi.encode(hash1, hash2))) % CIRCOM_P;
    }

    function formBasicInput(
        uint256 chainId,
        address verifyingContract,
        CircomData calldata circomData,
        uint256[] memory input,
        uint256 index,
        uint256 emporiumMessage
    ) internal pure returns (uint256[] memory) {
        // 1) First we list public inputs as in the body of the main template (not the one with exact dimensions)
        input[index++] = circomData.stealthAddressStructure.H1x;
        input[index++] = circomData.stealthAddressStructure.H1y;
        input[index++] = circomData.stealthAddressStructure.stealthAddress;
        input[index++] = emporiumMessage; // this is for Emporium message signature verification

        // 2) Then we list the private inputs as in the body of the main template
        input[index++] = circomData.rootHashHinkal;
        input[index++] = getSignedMessageHash(
            chainId,
            verifyingContract,
            circomData,
            emporiumMessage
        );

        for (uint16 i = 0; i < circomData.erc20TokenAddresses.length; i++) {
            input[index++] = uint256(
                uint160(circomData.erc20TokenAddresses[i])
            );
        }

        for (uint16 i = 0; i < circomData.amountChanges.length; i++) {
            require(
                circomData.amountChanges[i] < MAX_AMOUNT &&
                    circomData.amountChanges[i] > -1 * MAX_AMOUNT,
                "amount changed is too large"
            );

            input[index++] = circomData.amountChanges[i] >= 0
                ? uint256(circomData.amountChanges[i])
                : CIRCOM_P - uint256(-circomData.amountChanges[i]);
        }

        for (uint16 i = 0; i < circomData.inputNullifiers.length; i++) {
            for (uint16 j = 0; j < circomData.inputNullifiers[i].length; j++) {
                input[index++] = circomData.inputNullifiers[i][j];
            }
        }

        input[index++] = circomData.timeStamp;

        for (uint16 i = 0; i < circomData.outCommitments.length; i++) {
            for (uint16 j = 0; j < circomData.outCommitments[i].length; j++) {
                input[index++] = circomData.outCommitments[i][j];
            }
        }
        input[index++] = circomData.calldataHash;

        input[index++] = circomData.stealthAddressStructure.H0x;
        input[index++] = circomData.stealthAddressStructure.H0y;
