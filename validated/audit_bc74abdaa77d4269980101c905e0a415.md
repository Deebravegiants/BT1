### Title
Missing Cache-Control/Vary headers on session and authenticated API responses enable session hijack via proxy/CDN cache poisoning - (File: core/web/router.go, core/web/sessions_controller.go, core/web/helpers.go)

### Summary
The Chainlink node's Gin-based HTTP server never sets `Cache-Control: no-store`, `Pragma: no-cache`, or `Vary: Cookie` on any response, including the `POST /sessions` login endpoint that issues the `clsession` auth cookie and all `session`/API-token authenticated GET endpoints under `/v2/*`. When the node is deployed behind a shared/reverse-proxy cache (a common production topology for TLS termination and load balancing, explicitly supported via `WebServer.TLS`/`ListenIP` config), an intermediate cache with default caching heuristics can store these session-bound responses and later replay them to a different, unprivileged client requesting the same path — leaking session state or authenticated data across users, exactly analogous to the Manyfold advisory.

### Finding Description
The router is built once in `NewRouter` [1](#0-0) , applying global middleware (`otelgin`, request-size limiter, logger, CORS, `secureMiddleware`, `helmet.Default()`) but none of these set cache-control headers; `helmet.Default()` only sets `X-Content-Type-Options`, `X-DNS-Prefetch-Control`, `X-Frame-Options`, HSTS, `X-Download-Options`, and `X-Xss-Protection`, as verified by the test asserting the exact header set [2](#0-1) .

The session cookie is created and returned in `SessionsController.Create`, which sets the `clsession` cookie via `saveSessionID`/`session.Save()` and responds with `jsonAPIResponse` — again with no explicit cache directive [3](#0-2) . All JSON API responses funnel through `jsonAPIResponse`/`jsonAPIResponseWithStatus`/`jsonAPIError` in `core/web/helpers.go`, none of which set `Cache-Control` [4](#0-3) .

Authenticated GET endpoints reachable by a logged-in but otherwise unprivileged user (e.g., `chains`, `nodes`, `/v2/ping`, `/debug/vars`) are wired via `auth.Authenticate(... auth.AuthenticateBySession)` in `sessionRoutes`/`v2Routes`/`debugRoutes` [5](#0-4) [6](#0-5) , and the session lookup itself reads the session cookie via `sessions.Default(c)` in `AuthenticateBySession` [7](#0-6) . Because responses to these session-authenticated GET requests carry no `Vary: Cookie` / `Cache-Control: private, no-store`, a caching intermediary that keys solely on method+URL (ignoring the `Cookie` header, which is the default for many caches unless explicitly told to vary) will store the first user's authenticated response and serve it to subsequent requesters for the same URL — including unauthenticated or differently-authenticated clients — without re-checking the session.

### Impact Explanation
An attacker (unprivileged, unauthenticated network client) requesting the same cached path shortly after a legitimate user could receive that user's cached authenticated response body, and in cache-poisoning scenarios involving `Set-Cookie` propagation, potentially the victim's session cookie/value if the login response itself is cacheable under proxy misconfiguration. This yields cross-user response confusion and possible session hijack, satisfying the CIA impact pattern (`C:H/I:H`) described in the CVE. Impact is amplified for any deployment fronted by shared caches (CDN/reverse proxy), which the codebase's TLS/`ListenIP` configuration options implicitly anticipate.

### Likelihood Explanation
Likelihood is Medium: it requires (a) the node being deployed behind a caching proxy that doesn't already force `no-store` (this is an operator/infra choice, not enforced by the app), and (b) user interaction (`UI:R` per the CVSS vector) such as a victim visiting/being routed through the shared cache path around the same time as the attacker's request. The root cause — absence of explicit cache-control headers at the application layer — is fully within the node's own HTTP layer and unconditionally reachable by any unprivileged client hitting any authenticated endpoint through a caching proxy.

### Recommendation
Add global middleware in `NewRouter` (applied before/alongside `helmet.Default()`) that sets `Cache-Control: no-store, private`, `Pragma: no-cache`, and `Vary: Cookie` on all API responses (`/sessions`, `/v2/*`, `/query`, `/debug/*`), so intermediate caches never store authenticated or session-establishing responses. Static asset routes (`guiAssetRoutes`) can retain their own caching policy since they don't carry session state.

### Proof of Concept
1. Deploy the Chainlink node's web server behind a caching reverse proxy configured with typical defaults (cache keyed on URL, not headers).
2. Victim logs in via `POST /sessions`, then issues `GET /v2/chains` (or `/v2/ping`) with their session cookie; the proxy caches the response since no `Cache-Control`/`Vary: Cookie` header instructs otherwise.
3. Attacker, unauthenticated, requests `GET /v2/chains` on the same proxy; the cache serves the victim's stored authenticated response, disclosing victim-scoped data without ever presenting a valid session cookie — demonstrating the missing-header caching gap identified in `core/web/router.go` and `core/web/helpers.go`.

	engine := gin.New()

	engine.Use(
		otelgin.Middleware("chainlink-web-routes",

		cors,

	)
	if prometheus != nil {
		engine.Use(prometheus.Instrument())
	}

func (sc *SessionsController) Create(c *gin.Context) {
	defer sc.App.WakeSessionReaper()
	ctx := c.Request.Context()
	sc.App.GetLogger().Debugf("TRACE: Starting Session Creation")

	session := sessions.Default(c)
	var sr clsessions.SessionRequest
	if err := c.ShouldBindJSON(&sr); err != nil {
		jsonAPIError(c, http.StatusBadRequest, fmt.Errorf("error binding json %w", err))
		return
	}

	// Does this user have 2FA enabled?
	userWebAuthnTokens, err := sc.App.AuthenticationProvider().GetUserWebAuthn(ctx, sr.Email)
	if err != nil {
		sc.App.GetLogger().Errorf("Error loading user WebAuthn data: %s", err)
		jsonAPIError(c, http.StatusInternalServerError, errors.New("internal Server Error"))
		return
	}

	// If the user has registered MFA tokens, then populate our session store and context
	// required for successful WebAuthn authentication
	if len(userWebAuthnTokens) > 0 {
		sr.SessionStore = sc.sessions
		sr.WebAuthnConfig = sc.App.GetWebAuthnConfiguration()
	}

	sid, err := sc.App.AuthenticationProvider().CreateSession(ctx, sr)
	if err != nil {
		jsonAPIError(c, http.StatusUnauthorized, err)
		return
	}

	if err := saveSessionID(session, sid); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, errors.Join(errors.New("unable to save session id"), err))
		return
	}

	jsonAPIResponse(c, Session{Authenticated: true}, "session")
}

func jsonAPIError(c *gin.Context, statusCode int, err error) {
	_ = c.Error(err).SetType(gin.ErrorTypePublic)
	var jsonErr *models.JSONAPIErrors
	if errors.As(err, &jsonErr) {
		c.JSON(statusCode, jsonErr)
		return
	}
	c.JSON(statusCode, models.NewJSONAPIErrorsWith(err.Error()))
}

func paginatedResponse(
	c *gin.Context,
	name string,
	size int,
	page int,
	resource any,
	count int,
	err error,
) {
	if errors.Is(err, sql.ErrNoRows) {
		err = nil
	}

	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, fmt.Errorf("error getting paged %s: %w", name, err))
	} else if buffer, err := NewPaginatedResponse(*c.Request.URL, size, page, count, resource); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, fmt.Errorf("failed to marshal document: %w", err))
	} else {
		c.Data(http.StatusOK, MediaType, buffer)
	}
}

func paginatedRequest(action func(*gin.Context, int, int, int)) func(*gin.Context) {
	return func(c *gin.Context) {
		size, page, offset, err := ParsePaginatedRequest(c.Query("size"), c.Query("page"))
		if err != nil {
			jsonAPIError(c, http.StatusUnprocessableEntity, err)
			return
		}
		action(c, size, page, offset)
	}
}

func jsonAPIResponseWithStatus(c *gin.Context, resource any, name string, status int) {
	json, err := jsonapi.Marshal(resource)
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, fmt.Errorf("failed to marshal %s using jsonapi: %w", name, err))
	} else {
		c.Data(status, MediaType, json)
	}
}

func jsonAPIResponse(c *gin.Context, resource any, name string) {
	jsonAPIResponseWithStatus(c, resource, name, http.StatusOK)
}

func AuthenticateBySession(c *gin.Context, authr Authenticator) error {
	ctx := c.Request.Context()
	session := sessions.Default(c)
	sessionID, ok := session.Get(SessionIDKey).(string)
	if !ok {
		return auth.ErrorAuthFailed
	}

	user, err := authr.AuthorizedUserWithSession(ctx, sessionID)
	if err != nil {
		return err
	}

	c.Set(SessionUserKey, &user)

	return nil
}
