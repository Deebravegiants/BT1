### Title
Unauthenticated Magic QR-Codes Bypass Operator Authorization to Trigger Privileged Orb Actions - (File: `src/plans/mod.rs`)

### Summary
The Orb's signup flow is designed so that privileged, operator-only actions (resetting Wi-Fi credentials, resetting mirror calibration) are supposed to be gated behind backend verification of a valid operator/distributor QR-code. However, the code path for "magic" QR-codes executes these privileged actions *before* that verification ever runs, allowing anyone who can present a crafted QR-code to the Orb's camera to trigger them without any authentication.

### Finding Description
`MasterPlan::scan_initial_qr_codes` and `MasterPlan::scan_remaining_qr_codes` both scan a QR-code and parse it as `qr_scan::operator::Data`, then immediately call `handle_magic_operator_qr_code` *before* calling `verify_operator_qr_code` (which is the function that actually authenticates the operator against the backend, via `backend::operator_status::request`): [1](#0-0) [2](#0-1) 

`handle_magic_operator_qr_code` executes privileged system actions directly for the `MagicResetMirror` and `MagicResetWifi` variants, with no backend authorization check at all: [3](#0-2) 

The parsing logic in `qr_scan::operator::Data::try_parse` recognizes any string of the form `magic_action:reset_wifi_credentials` or `magic_action:reset_mirror_calibration` as valid `Data::MagicResetWifi` / `Data::MagicResetMirror` values — no signature, credential, or backend round-trip is required to produce a value that is accepted by `handle_magic_operator_qr_code`: [4](#0-3) 

By contrast, the normal operator path (`Data::Normal`) is only allowed to proceed to signup after `verify_operator_qr_code` confirms via a backend request (`backend::operator_status::request`, which validates the operator/distributor ID and requires `basic_auth` with the Orb's token) that the presented ID is a legitimate, backend-registered operator: [5](#0-4) 

Because `handle_magic_operator_qr_code` is invoked prior to this verification step, the "magic" branch completely skips the intended access-control boundary — it was clearly meant to be an operator-only maintenance action (per the naming and the surrounding logic that authenticates `Normal` operator codes), but due to the call ordering, it is reachable by anyone who can show the Orb a QR code containing this exact string, with no operator credential required.

The two triggered actions:
- `reset_mirror_calibration` — wipes/resets the Orb's mirror calibration state.
- `reset_wifi_and_ensure_network` — calls `network::reset()` (which restores the default `wpa_supplicant` config and forces a `wpa_cli` reconfigure, dropping the current WiFi connection), then re-prompts for a new WiFi-credentials QR-code via `qr_scan::Plan::<mecard::Credentials>`: [6](#0-5) [7](#0-6) [8](#0-7) 

### Impact Explanation
Any unprivileged party who can present a QR code to the Orb's camera (e.g., during the normal operator-QR-scan step of the signup flow, without possessing any valid operator/distributor identity) can:
1. Force the Orb off its current WiFi network and drive it to re-prompt for new WiFi credentials via `wifi::Plan::ensure_network_connection`, then supply an attacker-controlled `WIFI:` MECARD QR-code to join the Orb to an attacker-controlled network — enabling network-position attacks against all subsequent backend traffic from the device, undermining the trust boundary the operator-authentication step was designed to protect.
2. Force a mirror-calibration reset at will, degrading or corrupting the biometric capture pipeline that immediately follows in the signup flow, since `do_signup` proceeds to biometric capture right after this same QR-scanning stage.

This is a genuine authorization-boundary bypass: the code clearly intends operator actions to require backend-verified operator identity (as demonstrated by the `Normal` variant's mandatory `verify_operator_qr_code` call), but the "magic" actions execute unconditionally before that check, exactly matching the reported bug class of "functions designed to be access-controlled but reachable via an un-overridden/unchecked path."

### Likelihood Explanation
High. No special privileges, hardware access, or insider position are required — only the ability to present a static, publicly-derivable string (`magic_action:reset_wifi_credentials` or `magic_action:reset_mirror_calibration`) as a QR-code to the Orb's camera during the standard operator-scan phase, which is reachable in the normal signup flow.

### Recommendation
Move the `handle_magic_operator_qr_code` magic-action branches to execute only after `verify_operator_qr_code` succeeds (i.e., only allow `MagicResetWifi`/`MagicResetMirror` execution for QR-code holders who have been confirmed as legitimate operators by the backend), or otherwise require an equivalent authenticated/signed payload for magic actions before performing `network::reset()` or `reset_mirror_calibration`.

### Proof of Concept
1. Generate a QR-code encoding the literal string `magic_action:reset_wifi_credentials`.
2. Present it to the Orb's camera during the operator QR-code scan phase of the idle/signup loop (`scan_initial_qr_codes` or `scan_remaining_qr_codes`).
3. Observe that `qr_scan::operator::Data::try_parse` returns `Data::MagicResetWifi` and `handle_magic_operator_qr_code` is invoked and executes `reset_wifi_and_ensure_network` — with `verify_operator_qr_code` never having been called — dropping the Orb's WiFi connection and prompting for new WiFi credentials, with no backend operator-authentication performed at any point in this path: [9](#0-8)

    async fn handle_magic_operator_qr_code(
        &self,
        orb: &mut Orb,
        qr_code: qr_scan::operator::Data,
    ) -> Result<Option<qr_scan::user::Data>> {
        match qr_code {
            qr_scan::operator::Data::Normal(qr_code) => {
                tracing::info!("Operator QR-code detected: {qr_code:?}");
                Ok(Some(qr_code))
            }
            qr_scan::operator::Data::MagicResetMirror => {
                tracing::info!("Magic QR-code detected: Reset Mirror");
                dd_incr!("main.count.signup.during.general.magic_qr.reset_mirror");
                let result = self.reset_mirror_calibration(orb).await;
                if let Err(err) = &result {
                    tracing::error!("Failed to reset mirror calibration: {err}");
                }
                orb.ui.magic_qr_action_completed(result.is_ok());
                Ok(None)
            }
            qr_scan::operator::Data::MagicResetWifi => {
                tracing::info!("Magic QR-code detected: Reset Wi-Fi");
                dd_incr!("main.count.signup.during.general.magic_qr.reset_wifi");
                let result = self.reset_wifi_and_ensure_network(orb).await;
                if let Err(err) = &result {
                    tracing::error!("Failed to reset wifi: {err}");
                }
                orb.ui.magic_qr_action_completed(result.is_ok());
                Ok(None)
            }
        }
    }

/// Makes a validation request.
pub async fn request(qr_code: &qr_scan::user::Data) -> Result<Status> {
    let request = super::client()?
        .get(format!(
            "{}/api/v1/distributor/{}/orb/{}/status",
            *SIGNUP_BACKEND_URL, qr_code.user_id, *ORB_ID
        ))
        .basic_auth(&*ORB_ID, Some(get_orb_token()?));
    let status: Status = match request.send().await?.error_for_status() {
        Ok(response) => response.json().await?,
        Err(err) => {
            tracing::error!("Received error response {err:?}");
            return Err(err.into());
        }
    };
    if !status.valid {
        tracing::info!(
            "Operator QR-code invalid: {qr_code:?}, reason: {:?}",
            status.reason.as_deref().unwrap_or("<empty>")
        );
        return Ok(status);
    }
