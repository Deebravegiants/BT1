### Title
`pallet-consensus-incentives`: `update_cost_per_block` changes the reward rate without settling pending rewards, allowing relayers to retroactively claim backlog blocks at the new rate - (File: `modules/pallets/consensus-incentives/src/lib.rs`)

### Summary
`pallet-consensus-incentives` pays relayers `(latest_height - LastRewardedHeight) * cost_per_block` whenever a `ConsensusMessage` is processed. `cost_per_block` can be updated at any time via `update_cost_per_block`, but the pallet never "closes the books" on the un-rewarded block span before applying the new rate — exactly the `totalAllocPoint`-without-`massUpdatePools()` bug class from the referenced Aura/ConvexMasterChef finding, applied to a per-block reward-rate variable instead of a pool-allocation weight.

### Finding Description
`calculate_reward` computes the reward using whatever `cost_per_block` is currently stored, multiplied by the *entire* unpaid block span since `LastRewardedHeight`: [1](#0-0) 

`update_cost_per_block` simply overwrites `StateMachinesCostPerBlock` for a state machine with no interaction with `LastRewardedHeight` or any "pay out pending blocks at the old rate first" step: [2](#0-1) 

Because the reward for the *whole* unpaid span (`latest_height - LastRewardedHeight`) is always computed with the rate in effect **at the time of delivery**, not the rate(s) that were actually in effect while those blocks were produced, any backlog of un-rewarded blocks that accumulates while `cost_per_block` is low gets paid out at whatever rate is active when the relayer finally submits the `ConsensusMessage`. This is structurally identical to the ConvexMasterChef bug: `totalAllocPoint`/`cost_per_block` is a rate-defining variable that is mutated without first accruing/settling the pending reward under the old rate, so the whole reward calculation becomes stale-rate-inconsistent.

### Impact Explanation
A relayer (an unprivileged, permissionless actor — anyone can run a consensus relayer and submit `ConsensusMessage`s) can withhold delivery of a consensus proof for a state machine while a large backlog of un-rewarded blocks accumulates (e.g. `LastRewardedHeight` far behind `latest_commitment_height`, or simply by observing that a chain hasn't had incentives configured/updated recently). Once governance raises `cost_per_block` for legitimate reasons (e.g. gas costs increased on that chain), the relayer immediately submits the queued proof and is paid the *entire* backlog span at the new, higher rate rather than only the newly produced blocks. `T::Currency::transfer` moves real `$BRIDGE` out of the treasury account for this inflated amount, and an equal amount of non-transferable `ReputationAsset` is minted: [3](#0-2) 

This is a direct drain of the treasury (theft of protocol funds) beyond what governance intended when setting the new rate, and simultaneously an unbacked/over-mint of `ReputationAsset` (which feeds directly into collator selection, per the pallet's documented purpose), giving the exploiting relayer disproportionate influence toward becoming a block-producing collator.

### Likelihood Explanation
Likelihood is moderate-to-high: `cost_per_block` updates are a normal, expected governance operation (the pallet's whole purpose is to let governance tune the reward per state machine), and any relayer can trivially observe on-chain when `LastRewardedHeight` lags `latest_commitment_height` for a given state machine and simply time their proof submission to follow a rate increase. No special privileges, race conditions, or non-standard tooling are required — only patience and public chain-state observation.

### Recommendation
Before applying a new `cost_per_block`, settle the currently-accrued-but-unpaid span at the old rate (i.e., snapshot/pay out the pending reward, or otherwise segment reward calculation by the rate that was active during each sub-range of blocks), mirroring the `massUpdatePools()`-before-`totalAllocPoint`-change fix recommended in the referenced report. At minimum, `update_cost_per_block` should record a rate-change checkpoint so `calculate_reward` can split the `[baseline, latest_height]` span into pre-change and post-change segments and price each segment with its respective rate.

### Proof of Concept
1. Governance sets `cost_per_block(state_machine_id) = 1` via `update_cost_per_block`.
2. No relayer submits a `ConsensusMessage` for this chain for a long period; the chain's `latest_commitment_height` advances far past `LastRewardedHeight` (a large backlog accrues, priced cheaply).
3. Governance later raises `cost_per_block(state_machine_id) = 1000` (e.g., due to rising gas costs on that external chain).
4. A relayer immediately submits a `ConsensusMessage` proving the same backlog span that had accumulated under the `cost_per_block = 1` regime.
5. `calculate_reward` computes `reward = (latest_height - LastRewardedHeight) * 1000`, paying the relayer as if every backlogged block had always cost `1000`, draining the treasury for the inflated difference and minting an equally inflated `ReputationAsset` amount — see the reward math in `calculate_reward` [4](#0-3)  and the transfer/mint in `process_message` [5](#0-4) .

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}

	#[pallet::call]
	impl<T: Config> Pallet<T> {
		/// Update cost per block for a state machine
		#[pallet::call_index(0)]
		#[pallet::weight(T::WeightInfo::update_cost_per_block())]
		pub fn update_cost_per_block(
			origin: OriginFor<T>,
			state_machine_id: StateMachineId,
			cost_per_block: <T as pallet_ismp::Config>::Balance,
		) -> DispatchResult {
			T::IncentivesOrigin::ensure_origin(origin)?;

			StateMachinesCostPerBlock::<T>::mutate(state_machine_id.clone(), |maybe_cost| {
				*maybe_cost = Some(cost_per_block);
			});

			Self::deposit_event(Event::<T>::StateMachineCostPerBlockUpdated {
				state_machine_id,
				cost_per_block,
			});

			Ok(())
		}
