## Custody Analog Found

### Title
Stale `TombStone.original_owner` in `object::burn`/`unburn` lets a former owner reclaim an object after it has passed to a new owner and been sent to the burn address - ([File: aptos-move/framework/aptos-framework/sources/object.move])

### Summary
The bug-class in the Sherlock report is: a boolean/state flag (`_isLiquidation`) set during one operation is never cleared when the underlying position changes hands, so a later, unrelated holder inherits stale state that benefits the wrong party. The Aptos-native analog is `TombStone.original_owner` in `object.move`: it is set once by `burn()` and never updated or invalidated by ordinary ownership-changing calls (`transfer`, `transfer_raw`, `transfer_to_object`), so `unburn()` can later hand the object to a stale, no-longer-authorized address.

### Finding Description
`object::burn` only asserts current ownership and writes a `TombStone{ original_owner }` resource; it does **not** touch `ObjectCore.owner` or disable transfers: [1](#0-0) 

Ordinary transfers (`transfer`, `transfer_raw`, `transfer_to_object`) route through `transfer_raw_inner`, which only updates `ObjectCore.owner` and emits an event - it never inspects or clears `TombStone`: [2](#0-1) 

By contrast, the `TransferRef`-based `transfer_with_ref` path explicitly *does* clear a stale `TombStone` before changing owner, showing the framework authors were aware this cleanup is required for correctness: [3](#0-2) 

`unburn` then trusts the (possibly stale) `TombStone.original_owner` field whenever the object's current owner is `BURN_ADDRESS`: [4](#0-3) 

Because plain ownership transfer (`transfer_raw_inner`) never clears or refreshes `TombStone`, the invariant "`TombStone.original_owner` == the owner who most recently sent the object to `BURN_ADDRESS`" can be broken:

1. Owner `O` owns object `X` (no `TombStone`).
2. `O` calls `object::burn(O, X)` → `TombStone{original_owner: O}` is created; `X.owner` remains `O` (burn is a "soft burn", it does not move the object).
3. `O` calls a plain `object::transfer(O, X, N)` (ungated transfer is allowed by default and is unaffected by the existing `TombStone`) → `X.owner` becomes `N`. The stale `TombStone{original_owner: O}` is **not** cleared, because `transfer_raw_inner` never touches it. Note `N` cannot call `object::burn(N, X)` to "correctly" re-tag it, since `burn()` asserts `!exists<TombStone>` and aborts.
4. `N`, the legitimate current owner, later sends the object to the canonical burn address with a plain transfer: `object::transfer(N, X, BURN_ADDRESS)` → `X.owner = BURN_ADDRESS`. The stale `TombStone{original_owner: O}` is still present, untouched.
5. `O` (no longer the legitimate owner since step 3) calls `object::unburn(O, X)`. `TombStone` exists, `X.owner == BURN_ADDRESS`, and `original_owner_addr (O) == signer::address_of(O)` passes the check, so `transfer_raw_inner(X, O)` runs and ownership is reassigned back to `O`.

`O` has reclaimed custody of an object that had been legitimately transferred away to `N` and then burned by `N` - an unprivileged, unauthorized owner reassignment driven entirely by leftover state that should have been invalidated at step 3.

### Impact Explanation
This is a direct custody violation: object ownership (and by extension any value the object represents - an NFT, or a non-primary `FungibleStore` object holding fungible-asset balance, since `create_store` produces ordinary transferable objects unless explicitly marked untransferable) can be redirected to a party with no legitimate claim, at the expense of whoever was the actual last owner before the object reached `BURN_ADDRESS`. This satisfies the custody gate's "theft ... or owner reassignment of ... token objects, or other object-held value" and "Object creation, transfer, burn ... must preserve the intended controller."

### Likelihood Explanation
Requires: (a) the object supports ungated transfer (default `true` for freshly created objects), (b) a prior owner has at some point called `object::burn` on it without later `unburn`-ing before transferring it onward, and (c) a subsequent owner independently sends the object to `BURN_ADDRESS` via a plain transfer (a plausible action since `object::burn` itself would abort for them due to the pre-existing `TombStone`, and sending to a well-known burn address via plain transfer is a common cross-chain convention). This is a moderate-likelihood, high-impact logic bug reachable purely through public entry functions with no privileged assumptions.

### Recommendation
- Clear (`move_from`) any existing `TombStone` inside `transfer_raw_inner` whenever ownership changes, mirroring the cleanup already performed in `transfer_with_ref`.
- Alternatively/additionally, have `unburn`'s `BURN_ADDRESS` branch verify that `TombStone.original_owner` corresponds to the immediately preceding owner as tracked at the time the object last reached `BURN_ADDRESS`, not an owner recorded arbitrarily earlier in the object's history.

### Proof of Concept
```
// O owns X
object::burn(O, X);                       // TombStone{original_owner: O} created, X.owner == O
object::transfer(O, X, N);                // X.owner == N; TombStone NOT cleared (transfer_raw_inner ignores it)
object::transfer(N, X, BURN_ADDRESS);     // X.owner == BURN_ADDRESS; TombStone still {original_owner: O}
object::unburn(O, X);                     // passes: X.owner == BURN_ADDRESS && original_owner == O
                                           // => X.owner reset to O, bypassing N's rights entirely
```

Note: I was not able to fully trace every downstream module (e.g., digital-asset/token_v2 burn wrappers, marketplace contracts) that might call `object::burn`/plain `transfer` in this exact sequence within this indexed snapshot, so real-world reachability through a specific dApp's burn flow should be verified in a full checkout of the repo before treating this as confirmed-exploitable end-to-end.

```text
        let original_owner = signer::address_of(owner);
        assert!(is_owner(object, original_owner), error::permission_denied(ENOT_OBJECT_OWNER));
        let object_addr = object.inner;
        assert!(!exists<TombStone>(object_addr), EOBJECT_ALREADY_BURNT);
```

```text
    /// Allow origin owners to reclaim any objects they previous burnt.
    public entry fun unburn<T: key>(
        original_owner: &signer,
        object: Object<T>,
    ) {
        let object_addr = object.inner;
        assert!(exists<TombStone>(object_addr), error::invalid_argument(EOBJECT_NOT_BURNT));

        // The new owner of the object can always unburn it, but if it's the burn address, we go to the old functionality
        let object_core = borrow_global<ObjectCore>(object_addr);
        if (object_core.owner == signer::address_of(original_owner)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object_addr);
        } else if (object_core.owner == BURN_ADDRESS) {
            // The old functionality
            let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
            assert!(
                original_owner_addr == signer::address_of(original_owner),
                error::permission_denied(ENOT_OBJECT_OWNER)
            );
            transfer_raw_inner(object_addr, original_owner_addr);
        } else {
            abort error::permission_denied(ENOT_OBJECT_OWNER);
        };
    }
```
