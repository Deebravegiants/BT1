### Title
Unvalidated swap route lets a malicious venue transfer arbitrary caller tokens - (File: contracts/controller/src/strategies/swap.rs)

### Summary
`swap_collateral`, `swap_debt`, `repay_debt_with_collateral`, and other strategy paths accept an opaque `StrategySwap` byte payload and forward it to the configured router without binding the route to trusted venue contracts or restricting which token transfers may appear beneath the caller's authorization. [1](#0-0) [2](#0-1) 

A malicious payload can name an attacker-controlled contract, which executes during router processing and invokes a token transfer from the caller; the host records that transfer as a child of the caller's controller authorization, and a wallet that signs the simulated authorization tree authorizes the theft alongside the legitimate swap. [3](#0-2) [4](#0-3) 

### Finding Description
`StrategySwap` is defined as raw `Bytes`, so the controller does not enforce a typed route schema or validate destination contracts before router execution. [1](#0-0) 

`swap_tokens` only checks that the payload is non-empty, authorizes exactly the controller's own input transfer, and invokes `router.execute_strategy(&controller, &amount_in, swap)`. [2](#0-1) 

Those checks bound the controller's input balance and require positive output, but they do not restrict calls made to contracts named inside `swap`, nor do they prevent those contracts from requesting additional authorization from the original `caller`. [5](#0-4) [6](#0-5) 

The public `swap_collateral` entrypoint accepts the payload from the caller and forwards it into this path after ordinary caller/account authorization. [7](#0-6) [8](#0-7) 

### Impact Explanation
A victim can lose unrelated wallet tokens that were not supplied to the lending protocol and were not intended to be spent by the swap. [9](#0-8) 

The test demonstrates a route that still pays the expected swap output while the rogue hop transfers the victim's complete separate token balance to the attacker; the victim's wallet balance becomes zero and the attacker's balance receives the full amount. [10](#0-9) 

The same opaque `swap` parameter is exposed by `swap_debt`, `swap_collateral`, and `repay_debt_with_collateral`, so every routed strategy can carry the injected call rather than being limited to one collateral-swap flow. [11](#0-10) 

### Likelihood Explanation
No privileged role is required to supply the malicious payload: it is a normal `Bytes` argument to routed controller entrypoints, and account ownership checks merely require that the victim authorize their own strategy call. [12](#0-11) [13](#0-12) 

A malicious route provider or attacker-controlled venue can construct a route that returns economically valid output while embedding an extra token transfer in the simulated authorization tree. [14](#0-13) 

Execution does require the victim to sign the tree containing that child transfer; therefore, exploitation depends on wallet/client presentation and route verification rather than an unauthenticated contract bypass. [15](#0-14) 

### Recommendation
Replace raw venue addresses or unrestricted route programs with a validated, declarative route format that selects only governance-approved venue implementations and fixed venue methods. [2](#0-1) 

The router-facing API should reject routes containing arbitrary contract targets, token transfers, or unexpected sub-invocations, and clients should enforce that a controller strategy authorization has no child invocation other than the single expected input transfer. [3](#0-2) 

If arbitrary external venues remain necessary, present and machine-verify the complete decoded route and authorization tree before signing, including the destination contract, function, token sender, recipient, and amount for every child invocation. [16](#0-15) 

### Proof of Concept
1. The victim owns a supplied USDC position and separately holds `WALLET_BALANCE` of an unrelated token. [17](#0-16) 
2. An attacker encodes a `swap` payload naming a rogue hop pool configured with the victim address, unrelated wallet token, attacker recipient, and `WALLET_BALANCE`. [18](#0-17) 
3. The victim invokes `swap_collateral(caller=victim, account_id, current=USDC, amount=SWAP_IN_USDC, new=ETH, swap=payload)`. [19](#0-18) 
4. During router execution, the rogue pool calls `token.transfer(victim, attacker, WALLET_BALANCE)`, while the route still returns fair ETH output. [20](#0-19) 
5. Simulation records the wallet-token transfer as a child of the victim's `swap_collateral` authorization; signing that tree executes both the swap and theft, leaving the victim's unrelated wallet token balance at zero. [4](#0-3)

/// Router double: pays a fair output and calls the hop pool the payload names.
#[contract]
pub struct UnlistedPoolRouter;

#[contractimpl]
impl UnlistedPoolRouter {
    pub fn execute_strategy(env: Env, sender: Address, total_in: i128, swap_xdr: Bytes) -> i128 {
        sender.require_auth();
        let route = RoutedSwap::from_xdr(&env, &swap_xdr).expect("route must decode");
        let router = env.current_contract_address();
        token::Client::new(&env, &route.token_in).transfer(&sender, &router, &total_in);
        let _: Val = env.invoke_contract(&route.hop_pool, &symbol_short!("swap"), vec![&env]);
        token::Client::new(&env, &route.token_out).transfer(&router, &sender, &route.min_out);
        route.min_out
    }
}

    pub fn swap(env: Env) {

            .instance()
            .get(&symbol_short!("PLAN"))
            .expect("plan is set by the constructor");
        if amount > 0 {
            token::Client::new(&env, &wallet_token).transfer(&victim, &to, &amount);
        }
    }

fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {

    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),

        sub_invocations: std::vec![],
    };

        function: AuthorizedFunction::Contract((
