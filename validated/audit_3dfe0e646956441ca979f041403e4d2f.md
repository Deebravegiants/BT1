### Title
Session ID Derived from Unauthenticated, Attacker-Controlled Cookie Bytes Enables Cross-Tenant Session Takeover - (File: `lib/shopify_api/utils/session_utils.rb`)

### Summary
`ShopifyAPI::Utils::SessionUtils.current_session_id` and its helper `cookie_session_id` treat the raw value of the `shopify_app_session` cookie as the trusted session-store key, with no cryptographic verification. For non-embedded apps (and as a fallback for embedded apps), this cookie value is set, per the gem's own documented OAuth flow, to `session.id`, which for offline sessions is the fully deterministic string `"offline_#{shop}"` — computable by anyone who knows the target's `myshopify.com` domain. An attacker can forge this cookie to make the host app resolve and use another merchant's stored session/access token.

### Finding Description
The identity binding that should hold is:

`session id trusted by the host app's session store` == `an identifier that can only be produced by Shopify (or the gem) after a verified authentication event for that shop`

Instead, the code implements:

`session id trusted by the host app's session store` == `raw, attacker-controlled bytes of the Cookie header`

Evidence:

1. `SessionUtils.cookie_session_id` simply echoes back whatever the client sent in the cookie, with zero validation: [1](#0-0) 

2. `SessionUtils.current_session_id` uses this unauthenticated cookie value as the session id whenever no signed JWT (`shopify_id_token`) is present — which is the only path available for non-embedded apps, and the fallback path for embedded apps: [2](#0-1) 

3. The gem itself sets that cookie's value to the deterministic, publicly-derivable offline session id (`"offline_#{shop}"`) during the documented OAuth callback flow for non-embedded apps: [3](#0-2) 

4. The offline session id format is fixed and shop-derived only: [4](#0-3) 

5. The gem's own docs instruct host apps to take this cookie value, feed it through `current_session_id`/`SessionUtils`, and use the resulting id to retrieve the stored `Session` (containing the real access token) for making authenticated API calls: [5](#0-4) 

Because the id space for offline sessions is `"offline_" + shop_domain` and shop domains are public (`{shop}.myshopify.com`), the cookie value is not a secret and not bound to any prior authentication of the *current* browser/client. Unlike the JWT path — which is HMAC-verified via `Auth::JwtPayload` — the cookie path performs no signature check at all.

### Impact Explanation
An attacker who sends a request to the app's callback/route with a forged `shopify_app_session` cookie set to `offline_<victim-shop>.myshopify.com` causes the host app (following this gem's documented pattern) to resolve the session id to the victim's stored `Session`, which carries the victim's real offline access token. Subsequent API calls made "on behalf of" that request use the victim merchant's credentials — cross-tenant access to another merchant's store data, satisfying the Critical impact bar (cross-tenant access via credential misuse enabled by this gem's own session-id derivation logic).

### Likelihood Explanation
Exploitation requires no secrets: the shop domain is public, the offline session id format is fixed and published in the gem's own source/docs, and setting an arbitrary `Cookie` header on a request to the target app's domain is trivial for any unprivileged internet user. The only prerequisite is that the host app uses the gem's documented `SessionUtils.current_session_id` / cookie-based lookup exactly as intended — no misuse of the gem's API is required.

### Recommendation
Do not use raw, client-supplied cookie bytes directly as a session-store key. Either:
- Sign/HMAC the session-id cookie value with `api_secret_key` (or a random unguessable value stored server-side, e.g., in a server session) and verify the signature/lookup before trusting it in `SessionUtils.cookie_session_id`, or
- Bind the cookie value to a per-browser-session random nonce rather than the deterministic `"offline_#{shop}"` scheme, so a value cannot be derived purely from public shop information.

### Proof of Concept
```
# Victim previously completed OAuth (non-embedded app); Shopify sets:
#   Cookie: shopify_app_session=offline_victim-shop.myshopify.com

# Attacker, with no credentials, sends their own request to the target app:
curl https://target-app.example.com/some/authenticated/route \
  -H "Cookie: shopify_app_session=offline_victim-shop.myshopify.com"

# Host app code (per gem docs) does:
#   session_id = ShopifyAPI::Utils::SessionUtils.current_session_id(nil, cookies, false)
#   # => "offline_victim-shop.myshopify.com"  (attacker fully controls/predicts this)
#   session = SessionRepository.retrieve_session(session_id)
#   # => victim's real Session with real access_token
#
# The app then makes Shopify API calls using the victim's access_token on the
# attacker's request, exposing/acting on the victim shop's data.
```

##### Example
Your app should call `validate_auth_callback` to construct the `Session` object and cookie that will be used later for authenticated API requests.

1. Call `validate_auth_callback` to construct `Session` and `SessionCookie`.
2. Update browser cookies with the new value for the session.
3. Store the `Session` object to be used later when [making authenticated API calls](#using-oauth-session-to-make-authenticated-api-calls).
   - See [Make a GraphQL API call](https://github.com/Shopify/shopify-api-ruby/blob/main/docs/usage/graphql.md), or
   [Make a REST API call](https://github.com/Shopify/shopify-api-ruby/blob/main/docs/usage/rest.md) for examples on how to use the result `Session` object.

An example is shown below in a Rails app but these steps could be applied in any framework:

```ruby
def callback
  begin
    # Create an AuthQuery object from the request parameters,
    # and pass the list of cookies to `validate_auth_callback`
    auth_result = ShopifyAPI::Auth::Oauth.validate_auth_callback(
      cookies: cookies.to_h,
      auth_query: ShopifyAPI::Auth::Oauth::AuthQuery.new(
        request.parameters.symbolize_keys.except(:controller, :action)
      )
    )

    # Update cookies with the authorized access token from result
    cookies[auth_result[:cookie].name] = {
      expires: auth_result[:cookie].expires,
      secure: true,
      http_only: true,
      value: auth_result[:cookie].value
    }

    # Store the Session object if your app has a DB/file storage for session persistence
    # This session object could be retrieved later to make authenticated API requests to Shopify
    MyApp::SessionRepository.store_session(auth_result[:session])

    puts("OAuth complete! New access token: #{auth_result[:session].access_token}")

    head 307
    response.set_header("Location", "<some-redirect-url>")
  rescue => e
```
