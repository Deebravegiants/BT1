### Title
Unvalidated route pool addresses let malicious code join the caller’s authorization tree and steal unrelated wallet tokens - (File: contracts/controller/src/strategies/swap.rs)

### Summary
Controller strategies accept caller-supplied `swap` bytes and invoke the configured router without constraining the pool contracts reachable through that route. A malicious route pool can call `token.transfer(victim, attacker, amount)` while the victim’s `swap_collateral`, `swap_debt`, `repay_debt_with_collateral`, or `multiply` authorization is active; simulation records that transfer as a child of the victim’s authorization entry, and submitting the recorded tree authorizes it. This permits theft of unrelated wallet assets outside the lending position and outside the controller’s measured input/output checks. [1](#0-0) [2](#0-1) 

### Finding Description
`swap_collateral` authenticates `caller`, verifies account ownership or delegation, and passes its opaque `swap` argument into `withdraw_and_swap_from_supply`. [3](#0-2)  `swap_tokens` then authorizes only the intended `token_in.transfer(controller, router, amount_in)` before invoking `router.execute_strategy(controller, amount_in, swap)`. [4](#0-3)  That authorization protects the controller’s input leg, but it does not constrain other calls that route-selected code makes under the original caller’s top-level authorization. [5](#0-4) 

The route format places pool and token addresses in an attacker-controlled `assets` registry, and each swap instruction resolves its `pool` from that registry. [6](#0-5)  Program validation checks only registry bounds, token-chain structure, opcode values, and split weights; it does not authenticate or allowlist the resolved pool address. [7](#0-6)  The venue dispatcher then invokes the selected pool through its venue adapter, and the Soroswap adapter calls both `get_reserves` and `swap` on that attacker-selected contract. [8](#0-7) 

The regression test demonstrates the escaping call: a pool supplied by route data calls `token.transfer(alice, attacker, WALLET_BALANCE)` for a token that is neither the swap input nor output. [9](#0-8)  Simulation records the unauthorized wallet transfer as a child of Alice’s `swap_collateral` invocation, the transaction succeeds when Alice signs that recorded tree, and Alice’s unrelated token balance moves to the attacker. [2](#0-1) [10](#0-9) 

### Impact Explanation
This is theft of user funds. The stolen asset need not be deposited in the protocol, listed as collateral, included in route accounting, or bounded by `amount_in`; it only needs to be spendable by the signing address. [11](#0-10)  The controller’s post-router checks measure only `token_in` and `token_out` at the controller, so they cannot detect a transfer of a third token directly from the caller to the attacker. [12](#0-11) 

### Likelihood Explanation
The attacker needs no protocol role and can deploy the malicious pool contract, but the victim must submit a poisoned route and sign the authorization tree containing the extra transfer. [13](#0-12)  This is realistic when route bytes originate from a compromised or malicious quoting interface and the user does not independently decode every nested authorization. [14](#0-13)  The same boundary is reachable through every public strategy that accepts `swap: Bytes`, including `multiply`, `swap_debt`, `swap_collateral`, and `repay_debt_with_collateral`. [15](#0-14) 

### Recommendation
Do not let route bytes select arbitrary executable pool addresses. Bind each venue opcode to governance-approved venue contracts or maintain an on-chain pool allowlist, and reject unknown pool addresses before invocation. [16](#0-15)  In addition, surface the complete authorization tree for every strategy signature and reject any tree whose nested calls are not the explicitly expected token transfers. [17](#0-16) 

### Proof of Concept
1. Deploy a malicious `RogueHopPool` whose `swap` method calls `token::Client::transfer(victim, attacker, victim_balance)` on an unrelated token held by the victim. [9](#0-8) 
2. Encode a `swap_collateral(caller=victim, account_id, current=USDC market, amount=50_000_000_000, new=ETH market, swap=malicious_route)` request whose route names that contract as the Soroswap pool while still returning enough `ETH` to satisfy output accounting. [18](#0-17) [19](#0-18) 
3. Simulate the transaction; Soroban records `token.transfer(victim, attacker, WALLET_BALANCE)` as a child invocation beneath the victim’s controller authorization. [20](#0-19) 
4. Have the victim sign the recorded tree and submit. The malicious transfer executes: the victim’s unrelated token balance becomes zero and the attacker receives `WALLET_BALANCE`, while the collateral swap itself also completes. [21](#0-20)

    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
}

fn enforced_auth_moves_the_wallet_token_only_when_the_signed_tree_lists_the_rogue_transfer() {
    let s = Scene::new();

    // Control: a pool that touches nothing passes with the honest root-only tree.
    let benign = s.route_through_pool_stealing(0);
    s.try_swap_with_signed_tree(&benign, &[])
        .expect("the honest tree authorizes an honest route");
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);

    // Rogue pool, honest tree: the host refuses the transfer and the whole call rolls back.
    s.t.env.mock_all_auths_allowing_non_root_auth();
    let rogue = s.route_through_pool_stealing(WALLET_BALANCE);
    let usdc_before = s.t.supply_balance_raw(ALICE, "USDC");
    let refused = s
        .try_swap_with_signed_tree(&rogue, &[])
        .expect_err("a transfer outside the signed tree is unauthorized");
    std::println!("rogue transfer under the honest tree = {refused:?}");
    assert!(
        refused.is_type(ScErrorType::Auth) || refused.is_type(ScErrorType::Context),
        "expected a host auth failure, got {refused:?}"
    );
    assert!(s
        .diagnostics()
        .contains("Unauthorized function call for address"));
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);

        args: (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),

    s.try_swap_with_signed_tree(&rogue, core::slice::from_ref(&stolen_transfer))

    /// Validates every instruction's opcode, mode, and indices before execution begins,
    /// including the `Prev` chain, same-token swaps, and split-weight bounds.
    fn validate(&self, env: &Env, assets_len: u32, amounts_len: u32, weight_count: u32) {
        for i in 0..self.op_count {
            let record = self.raw(i);
            let Some(opcode) = Opcode::from_u8(record[field::OPCODE]) else {
                panic_with_error!(env, Error::InvalidRouteXdr);
            };
            let mode = Mode::from_u8(record[field::MODE]);
            let (idx_a, idx_b, idx_c) = (
                record[field::POOL] as u32,
                record[field::TOKEN_IN] as u32,
                record[field::TOKEN_OUT] as u32,
            );

            // `Prev` is a purely structural link: the predecessor must exist,
            // must have a single output, and that output must be this
            // instruction's input.
            if mode == Mode::Prev {
                if i == 0 {
                    panic_with_error!(env, Error::BrokenTokenChain);
                }
                let previous = self.raw(i - 1);
                let produced = match Opcode::from_u8(previous[field::OPCODE]) {
                    // A swap produces its `token_out`, a mint its share token.
                    Some(Opcode::Swap(_)) => previous[field::TOKEN_OUT],
                    Some(Opcode::Mint) => previous[field::TOKEN_IN],
                    // A burn releases every constituent at once.
                    _ => panic_with_error!(env, Error::BrokenTokenChain),
                };
                if idx_b != produced as u32 {
                    panic_with_error!(env, Error::BrokenTokenChain);
                }
            }
            match mode {
                Mode::Fixed(idx) if idx as u32 >= amounts_len => {
                    panic_with_error!(env, Error::InvalidRouteXdr)
                }
                Mode::Ppm(idx) if idx as u32 >= weight_count => {
                    panic_with_error!(env, Error::InvalidRouteXdr)
                }
                _ => {}
            }

            if idx_a >= assets_len || idx_b >= assets_len {
                panic_with_error!(env, Error::InvalidRouteXdr);
            }
            match opcode {
                Opcode::Swap(_) => {
                    if idx_c >= assets_len {
                        panic_with_error!(env, Error::InvalidRouteXdr);
                    }
                    if idx_b == idx_c {
                        panic_with_error!(env, Error::SameToken);
                    }
                }
                // Liquidity legs spend the full vault balance, so only `Mode::All` is valid.
                Opcode::Burn | Opcode::Mint => {
                    if mode != Mode::All {
                        panic_with_error!(env, Error::InvalidRouteXdr);
                    }
                    if idx_c >= amounts_len {
                        panic_with_error!(env, Error::InvalidRouteXdr);
                    }
                }
            }
