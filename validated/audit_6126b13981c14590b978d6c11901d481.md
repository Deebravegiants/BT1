### Title
Free, unauthenticated `pallet-ismp::handle_unsigned` performs full consensus/proof verification (SCALE decode, ABI decode, cryptographic light-client verification) during transaction-pool `validate_unsigned` before any cheap size/shape check — a fee-less CPU/memory amplification DoS reachable by any network peer - (File: modules/pallets/ismp/src/lib.rs)

### Summary
`pallet-ismp`'s `handle_unsigned` extrinsic is dispatched with `ensure_none` (no signer, no fee) and its `ValidateUnsigned::validate_unsigned` implementation immediately calls `Self::execute(messages.clone())`, which runs the *entire* ISMP message-handling pipeline — SCALE decoding of nested proof structures, ABI decoding for SP1/BEEFY proofs, and full cryptographic light-client verification (BEEFY MMR/authority-multiproof, SP1 zk verification, Tendermint header/signature verification, Substrate/EVM state-trie proof walking) — for every gossiped candidate transaction, on every node in the network, before the extrinsic is accepted or rejected. There is no upfront, cheap bound on proof size or a lightweight shape check analogous to CoreDNS's missing pre-decode size guard on the DoH GET path.

### Finding Description
`handle_unsigned` is registered as `Unsigned` origin, so any peer can construct and gossip a `Message::Consensus`, `Message::Request`, `Message::Response`, `Message::FraudProof`, or `Message::Timeout` datagram containing an arbitrarily large/adversarial byte blob in `consensus_proof: Vec<u8>` or `proof: Vec<u8>` fields, with no fee attached: [1](#0-0) [2](#0-1) 

`validate_unsigned` unconditionally calls `Self::execute(messages.clone())` before returning any verdict: [3](#0-2) 

`execute` calls `handle_incoming_message` for every message in the batch, dispatching straight into the consensus/state-machine handlers: [4](#0-3) 

For a `Consensus` message this reaches `verify_consensus` on the configured client (e.g. Tendermint/Polygon), which unconditionally SCALE-decodes the proof and trusted state, converts to native form, and then runs full cryptographic light-client verification (Merkle/authority set/threshold checks) — all before any acceptance decision: [5](#0-4) [6](#0-5) 

For BEEFY/SP1-style proofs routed through `pallet-beefy-consensus-proofs`, `verify_and_apply` performs SCALE + ABI decode (`abi_decode_params`) of large structured payloads (headers, MMR proofs, signatures) before verification: [7](#0-6) 

Crucially, this pallet's own analog — `pallet_call_decompressor` — was already hardened against exactly this bug class: its comments explicitly describe the same DoH-style pre-validation-amplification bug (a "zstd bomb" through `validate_unsigned`) and fix it by adding a cheap `ensure!(encoded_call_size < T::MaxCallSize::get() * ONE_MB, ...)` gate *before* any expensive decompression/decoding work in the unsigned mempool path: [8](#0-7) 

`pallet-ismp::handle_unsigned` has no equivalent — `messages: Vec<Message>` is unbounded (no `MaxCallSize`/`BoundedVec` gate, no cheap proof-length or proof-type pre-check) before `execute()` triggers full decode-and-verify. `pallet-beefy-consensus-proofs::submit_proof` is signed and fee-bearing with a `BoundedVec<u8, MaxProofSize>`, so it is not exposed to this fee-less amplification, but `pallet-ismp::handle_unsigned` (and `pallet-state-coprocessor::handle_unsigned`, which similarly calls `handle_get_requests` unconditionally in `validate_unsigned`) are: [9](#0-8) 

This mirrors the CoreDNS root cause precisely: an unauthenticated, fee-less caller can trigger expensive parsing/decoding/cryptographic work that is only rejected *after* the costly work has been performed, and — unlike CoreDNS's single-node HTTP request — the ISMP unsigned extrinsic is additionally re-validated by *every peer* that receives it via transaction-pool gossip (each node independently calls `validate_unsigned` on the same candidate transaction), multiplying the amplification across the whole validator/full-node set.

### Impact Explanation
This is a network-wide, fee-less denial-of-service vector against Hyperbridge parachain nodes:
- Attackers can flood the network with malformed/oversized `handle_unsigned` (and `pallet-state-coprocessor::handle_unsigned`) candidates that always fail verification but force every receiving node to run full SCALE/ABI decode plus expensive cryptographic light-client verification (BEEFY MMR verification, SP1/Tendermint signature and voting-power checks, trie proof walks) during mempool validation.
- Because this happens in `validate_unsigned`, which every full node/collator runs on every gossiped candidate before dispatch, the attack degrades throughput and responsiveness network-wide, elevates CPU/memory/GC pressure, and can starve legitimate relayer messages from being validated and included in blocks in a timely manner — a route-unable-to-deliver-messages condition matching High severity under CWE-400.
- No stake, deposit or fee is required since the calls are unsigned/free, making the attack essentially costless to mount repeatedly.

### Likelihood Explanation
High. The extrinsic is explicitly designed to be free and permissionless ("This allows users execute ISMP datagrams for free. Use with caution."), reachable by any relayer, dispatcher, or arbitrary network peer without any deposit, stake, or prior state. Constructing a plausible-looking but ultimately-invalid `Message::Consensus`/`Message::Request` with a large proof blob requires no special access and can be automated trivially, exactly analogous to the CoreDNS PoC's oversized `dns=` parameter.

### Recommendation
Add a cheap, pre-decode bound before any expensive work in `pallet-ismp::validate_unsigned`/`execute` and in `pallet-state-coprocessor::validate_unsigned`, mirroring the fix already applied in `pallet_call_decompressor::decompress`:
1. Enforce a configurable maximum total encoded size for `messages: Vec<Message>` (and per-message maximum for `consensus_proof`/`proof` byte fields) via a `Get<u32>`-style bound checked immediately in `validate_unsigned`, before calling `Self::execute`.
2. Reject batches/messages whose proof field exceeds the bound with a cheap length check prior to `Decode::decode`/`abi_decode_params` and prior to invoking any consensus-client `verify_consensus`/`verify_fraud_proof`.
3. Apply the same reasoning to `pallet-state-coprocessor::handle_unsigned`, which likewise calls `handle_get_requests` unconditionally inside `validate_unsigned`.
4. Consider consuming (or otherwise rate-limiting/priced-in) mempool-validation weight/reputation for repeatedly-invalid unsigned submissions from the same peer, since unsigned extrinsics are unmetered and gossiped to the whole network.

### Proof of Concept
Conceptual analog of the CoreDNS PoC (no code execution performed; reachability confirmed via source review):
1. Craft an unsigned extrinsic calling `Ismp::handle_unsigned` with `messages = [Message::Consensus(ConsensusMessage { consensus_proof: <large adversarial byte blob near the network's max extrinsic size>, consensus_state_id: <a real configured client id, e.g. Tendermint/BEEFY>, signer: vec![] })]`.
2. Gossip this extrinsic to the network via `author_submitExtrinsic`/p2p transaction gossip.
3. Every receiving node's transaction pool calls `ValidateUnsigned::validate_unsigned`, which calls `Pallet::<T>::execute(messages.clone())` → `handle_incoming_message` → the target consensus client's `verify_consensus`, which SCALE-decodes the full blob and attempts full cryptographic light-client verification before ultimately failing and returning `InvalidTransaction::BadProof`.
4. Repeating this at scale (many such extrinsics with distinct nonces/content so they are not deduplicated by `provides` tags) forces sustained CPU/allocation/GC load on every node validating the mempool, at zero cost to the attacker, since the calls are unsigned and never included/paid for.

	/// Execute the provided ISMP datagrams, this will short circuit if any messages are invalid.
	/// This also charges fee on valid message delivery
	pub fn execute(messages: Vec<Message>) -> Result<Vec<events::Event>, Error<T>> {
		let host = Pallet::<T>::default();

			.iter()
			.map(|msg| handle_incoming_message(&host, msg.clone()))

				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

/// This function serves as an entry point to handle the message types provided by the ISMP protocol
pub fn handle_incoming_message<H>(
	host: &H,
	message: Message,
) -> Result<MessageResult, anyhow::Error>
where
	H: IsmpHost,
{
	match message {
		Message::Consensus(consensus_message) => consensus::update_client(host, consensus_message),
		Message::FraudProof(fraud_proof) => consensus::freeze_client(host, fraud_proof),
		Message::Request(req) => request::handle(host, req),
		Message::Response(resp) => response::handle(host, resp),
		Message::Timeout(timeout) => timeout::handle(host, timeout),
	}
}

/// Main verification function for header updates
pub fn verify_header_update(
	trusted_state: TrustedState,
	consensus_proof: ConsensusProof,
	current_time: u64,
) -> Result<UpdatedTrustedState, VerificationError> {
	consensus_proof.validate().map_err(|e| VerificationError::Invalid(e))?;

	let chain_id = Id::try_from(trusted_state.chain_id.clone())
		.map_err(|e| VerificationError::Invalid(e.to_string()))?;
	let height = Height::try_from(trusted_state.height)
		.map_err(|e| VerificationError::Invalid(e.to_string()))?;
	let timestamp = Timestamp { seconds: trusted_state.timestamp as i64, nanos: 0 };
	let time = Time::try_from(timestamp).map_err(|e| VerificationError::Invalid(e.to_string()))?;
	let next_validators = ValidatorSet::new(trusted_state.next_validators.clone(), None);
	let next_validators_hash = Hash::Sha256(trusted_state.next_validators_hash);

	let tendermint_trusted_state = TrustedBlockState {
		chain_id: &chain_id,
		header_time: time,
		height,
		next_validators: &next_validators,
		next_validators_hash,
	};

	let validators = extract_validators(&trusted_state, &consensus_proof)?;
	let next_validators = consensus_proof
		.next_validators
		.as_ref()
		.map(|validators| ValidatorSet::new(validators.clone(), None));

	let untrusted_block_state = UntrustedBlockState {
		signed_header: &consensus_proof.signed_header,
		validators: &validators,
		next_validators: next_validators.as_ref(),
	};

	let verifier_options = convert_verification_options(
		&trusted_state.verification_options,
		trusted_state.trusting_period_duration(),
	)?;
	let now = convert_timestamp(current_time)?;

	let verifier = SpIoVerifier::default();
	let result = verifier.verify_update_header(
		untrusted_block_state,
		tendermint_trusted_state,
		&verifier_options,
		now,
	);

	match result {
		Verdict::Success => {
			let updated_state = create_updated_trusted_state(&trusted_state, &consensus_proof)?;
			Ok(updated_state)
		},
		Verdict::NotEnoughTrust(tally) =>
			Err(VerificationError::NotEnoughTrust(format!("Voting power tally: {}", tally))),
		Verdict::Invalid(detail) => Err(VerificationError::Invalid(format!("{:?}", detail))),
	}
