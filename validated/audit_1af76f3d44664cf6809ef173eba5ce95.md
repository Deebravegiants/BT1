### Title
Cached `signature_details` frozen at static (pre-ALT) sanitization causes under-counting of precompile signature-verification fee/cost when a `program_id_index` resolves to a precompile only after address-lookup-table resolution - ([File: runtime-transaction/src/runtime_transaction.rs])

### Summary
`RuntimeTransaction<T>::num_ed25519_signatures`/`num_secp256k1_signatures`/`num_secp256r1_signatures` always read from `self.meta.signature_details`, a snapshot computed once when the transaction is first turned into a `RuntimeTransaction<SanitizedVersionedTransaction>` (statically, before address-lookup-table resolution). That same `meta` is carried over unchanged into `RuntimeTransaction<SanitizedTransaction>` after dynamic (ALT) loading, while `num_write_locks`, `recent_blockhash`, and `instructions_iter`/`program_instructions_iter` on the fully-loaded type correctly delegate live to the resolved `self.transaction`. If a `program_id_index` in an instruction points into the address-lookup-table region (i.e. beyond `static_account_keys()`), it cannot be resolved to a program id at the static stage and is therefore skipped when building `precompile_signature_details`; if that ALT entry resolves to `secp256k1_program`/`ed25519_program`/`secp256r1_program` once the addresses are loaded, the corresponding signature count is silently missing from the cached `meta.signature_details` even though the fully-resolved transaction (used at execution time) correctly executes it as a precompile.

### Finding Description
- The static constructor `RuntimeTransaction<SanitizedVersionedTransaction>::try_from` builds `InstructionMeta`/`signature_details` from `sanitized_versioned_tx.get_message().program_instructions_iter()` [1](#0-0) . At this stage the message has not had its address-lookup-table entries resolved, so `program_instructions_iter()` can only resolve `program_id` for instructions whose `program_id_index` falls inside `static_account_keys()`; an index that falls in the ALT-loaded region cannot be resolved to a `Pubkey` yet (this pattern is confirmed by a sibling helper that filters via `static_account_keys().get(ix.program_id_index as usize)`, dropping any instruction whose index exceeds the static key list) [2](#0-1) .
- `RuntimeTransaction<SanitizedTransaction>::try_from` (the "dynamic load" step) re-uses the previously computed `meta` verbatim after performing ALT resolution via `SanitizedTransaction::try_new` — it never recomputes `signature_details` against the newly resolved account keys [3](#0-2) .
- `SVMStaticMessage` for `RuntimeTransaction<T>` overrides `num_ed25519_signatures`/`num_secp256k1_signatures`/`num_secp256r1_signatures` to read from `self.meta.signature_details` (the frozen snapshot), while `num_write_locks`, `recent_blockhash`, `instructions_iter`, and `program_instructions_iter` all delegate live to `self.transaction` [4](#0-3) .
- The independent, stateless helper `get_precompile_signature_details` classifies `program_id`/`program_id_index` pairs by comparing against `secp256k1_program::ID`, `ed25519_program::ID`, `secp256r1_program::ID` [5](#0-4) , confirming that classification is purely a function of the resolved `program_id` at the time it is computed — i.e. it is sensitive to whether resolution has happened yet.
- At actual execution time, `InvokeContext::process_message` iterates `message.program_instructions_iter()` on the fully resolved message and calls `self.is_precompile(program_id)` to decide whether to run precompile verification [6](#0-5) ; this uses the correct, resolved `program_id`, so the precompile is actually executed/verified. Only the *accounting* value (`meta.signature_details`) used elsewhere for signature-verification cost/fee purposes is stale.
- No sanitization check re-derives or validates `signature_details` after ALT resolution; the field is simply propagated unchanged.

### Impact Explanation
`num_ed25519_signatures`/`num_secp256k1_signatures`/`num_secp256r1_signatures` feed into signature-verification fee and cost-model calculations (e.g. `forwarding_stage.rs`'s `signature_details().total_signatures()` multiplied by `lamports_per_signature` for prioritization/fee estimation) [7](#0-6) . If an attacker constructs a transaction whose precompile-invoking instruction's `program_id_index` only resolves to a precompile program id after ALT loading, the count contributed by that instruction is absent from the frozen `meta.signature_details`, while the instruction is nonetheless executed as a real precompile at runtime. This yields under-charged signature-verification fee/cost relative to the actual resolved account keys and work performed — a materially underpriced execution / fee-undercharging condition (cost-model / fee-accounting bounty category), not a signature-verification bypass (the precompile itself is still verified correctly at execution time using the live-resolved `program_instructions_iter`).

### Likelihood Explanation
Preconditions are attacker-controlled and require no privileged access: the attacker only needs to (1) create/extend an address lookup table so that one of its slots holds `secp256k1_program::ID`, `ed25519_program::ID`, or `secp256r1_program::ID`, and (2) submit a v0 transaction whose instruction's `program_id_index` references that ALT slot (an index beyond `static_account_keys().len()`). This is fully reachable via the public `try_create` path (`RuntimeTransaction::try_create` → static `try_from` → dynamic `try_from`) used for every incoming transaction, making the condition easily and repeatably triggerable by any normal user.

### Recommendation
Recompute (or re-validate) `signature_details`/`precompile_signature_details` for `RuntimeTransaction<SanitizedTransaction>` (and the `ResolvedTransactionView` dynamic path) using the fully resolved `program_instructions_iter()` after ALT resolution, instead of reusing the static-stage `meta` unchanged in `RuntimeTransaction<SanitizedTransaction>::try_from`.

### Proof of Concept
Rust integration test plan in `runtime-transaction/src/runtime_transaction/sdk_transactions.rs` tests module:
1. Build a `VersionedTransaction` (v0) with a static account list that does not include any precompile id, and one instruction whose `program_id_index` points to index `static_account_keys().len()` (i.e., the first ALT-loaded slot), with instruction data `[N]` (claiming `N` signatures).
2. Register an address lookup table (mock `AddressLoader`) that resolves that slot to `solana_sdk_ids::ed25519_program::ID`.
3. Call `RuntimeTransaction::<SanitizedVersionedTransaction>::try_from(...)` and assert `meta.signature_details.num_ed25519_instruction_signatures() == 0` (missed at static stage).
4. Call `RuntimeTransaction::<SanitizedTransaction>::try_from(statically_loaded_runtime_tx, mock_address_loader, ...)` to perform dynamic/ALT loading, then call `.num_ed25519_signatures()` on the result and assert it is still `0`.
5. Independently call `get_precompile_signature_details(resolved_tx.program_instructions_iter())` on the fully resolved transaction and assert `num_ed25519_instruction_signatures == N`.
6. Assert the mismatch: `resolved_tx.num_ed25519_signatures() != get_precompile_signature_details(resolved_tx.program_instructions_iter()).num_ed25519_instruction_signatures`, demonstrating the stale/incorrect cached value used for fee/cost purposes versus the true resolved classification.

pub fn get_precompile_signature_details<'a>(
    instructions: impl Iterator<Item = (&'a Pubkey, SVMInstruction<'a>)>,

    let mut builder = PrecompileSignatureDetailsBuilder::default();

struct SignatureDetailsFilter {
    // array of slots for all possible u8 program_id_index values,
    // each slot indicates if a program_id_index has not been checked, or is
    // already checked with result that can be reused.
    flags: [Option<ProgramIdStatus>; FILTER_SIZE],
}

impl SignatureDetailsFilter {
    #[inline]
    fn new() -> Self {
        Self {
            flags: [None; FILTER_SIZE],
        }
    }

    #[inline]
    fn is_signature(&mut self, index: u8, program_id: &Pubkey) -> ProgramIdStatus {
        let flag = &mut self.flags[usize::from(index)];
        match flag {
            Some(status) => *status,
            None => {
                *flag = Some(Self::check_program_id(program_id));
                *flag.as_ref().unwrap()
            }
        }
    }

    #[inline]
    fn check_program_id(program_id: &Pubkey) -> ProgramIdStatus {
        if program_id == &solana_sdk_ids::secp256k1_program::ID {
            ProgramIdStatus::Secp256k1
        } else if program_id == &solana_sdk_ids::ed25519_program::ID {
            ProgramIdStatus::Ed25519
        } else if program_id == &solana_sdk_ids::secp256r1_program::ID {
            ProgramIdStatus::Secp256r1
        } else {
            ProgramIdStatus::NotSignature
        }
    }
