### Title
Get-request relayer fee is never cleared after successful `GetResponse` delivery, allowing a later `dispatchTimeOut(GetRequestTimeout)` on a stale (but still-retained) state height to pay the fee a second time - (File: `evm/src/core/EvmHost.sol`)

### Summary
This is the closest reachable analog to a "stale reference reused after being logically freed" bug class (the blockchain-native equivalent of use-after-free): `EvmHost.dispatchIncoming(GetResponse, relayer)` reads and pays out `_requestCommitments[commitment].fee` on success but never deletes the `_requestCommitments[commitment]` entry afterward [1](#0-0) . The same `commitment` key can later be consumed again by `dispatchTimeOut(GetRequestTimeout, ...)`, which independently checks `meta.sender == address(0)` via `host.requestCommitments(commitment)` before paying out the fee a second time [2](#0-1) .

### Finding Description
On the GET-request source chain, `dispatch(DispatchGet)` writes `_requestCommitments[commitment] = FeeMetadata({sender, fee})` [3](#0-2) . When the response is later delivered via `dispatchIncoming(GetResponse, relayer)`, on success the code pays `fee` to the relayer but leaves `_requestCommitments[commitment]` fully intact - contrast this with the two `dispatchTimeOut` overloads, which explicitly `delete _requestCommitments[commitment]` before the callback (restoring only on failure) specifically "for replay protection" [1](#0-0) [4](#0-3) .

`HandlerV2.handleGetRequestTimeouts` independently authorizes payout based solely on: (1) `meta.sender != address(0)` (i.e., `_requestCommitments[commitment]` still populated) and (2) a non-membership proof that the destination's response-receipt slot was empty *at the proven historical height* [2](#0-1) . Because pallet-ismp retains a bounded FIFO window of past state-machine heights per chain (`StateMachineCommitmentCap`/`MAX_STATE_MACHINE_COMMITMENTS`), a state height captured *before* the destination actually wrote its response receipt remains provable for as long as it sits in that window [5](#0-4) . If a relayer already delivered the `GetResponse` (fee #1 paid, `_requestCommitments` untouched) and the request's `timeout()` had already elapsed relative to that older proven height's timestamp, a second party can submit `handleGetRequestTimeouts` against that stale height, pass the non-membership check (destination hadn't recorded the response *at that height*), and trigger `dispatchTimeOut(GetRequestTimeout, meta, commitment)` — paying the same escrowed fee out a second time to `meta.sender` before finally deleting the commitment.

### Impact Explanation
This is a real-fund-loss / unbacked-payout bug: the protocol's escrowed relayer fee for a single GET request could be paid out twice (once via the response path to the relayer, once via the timeout path to the payer), draining the fee token balance of `EvmHost` by an amount not backed by any corresponding dispatch. This matches the "concrete theft" and "relayer fee accounting" categories called out as in-scope.

### Likelihood Explanation
I was **not able to fully verify** the timing precondition given the tool-call budget: it requires (a) the destination's timeout-elapsed timestamp for the request to be reachable at a height *older* than the height where the response was actually recorded, and (b) that older height still being within the source chain's retained commitment window (bounded by `StateMachineCommitmentCap`) when the timeout message is submitted. Whether these two conditions can coexist in practice (destination processing latency vs. challenge-period/eviction-window sizing) needs confirmation by tracing `handleGetResponses`'s proof-height requirements against `handleGetRequestTimeouts`'s height selection, and by checking whether any other guard (e.g., a duplicate-payout check I did not find) exists elsewhere in `EvmHost.sol` around `_requestCommitments`. Given this, treat likelihood as **uncertain/Medium** pending that verification, rather than confirmed exploitable.

### Recommendation
Delete `_requestCommitments[commitment]` in `dispatchIncoming(GetResponse, relayer)` immediately after the fee is successfully paid (mirroring the pattern already used in both `dispatchTimeOut` overloads), so that a subsequent `handleGetRequestTimeouts` submission for the same commitment fails the `meta.sender == address(0)` check regardless of which historical height is proven against.

### Proof of Concept
Conceptual sequence (needs confirmation against actual timing/eviction parameters):
1. User dispatches a `GetRequest` with a fee via `EvmHost.dispatch(DispatchGet)`, escrowing `fee` under `_requestCommitments[commitment]`.
2. Relayer submits a valid `GetResponse` via `HandlerV2.handleGetResponses` → `EvmHost.dispatchIncoming(GetResponse, relayer)`; the callback succeeds, `fee` is paid to `relayer`, but `_requestCommitments[commitment]` is left populated.
3. A second relayer (or the same one) obtains a non-membership proof of the destination's response-receipt slot at a height that predates the destination's actual response write, but whose timestamp is already past `request.timeout()`, and that height is still retained in `BoundedStateCommitments`.
4. That relayer submits `HandlerV2.handleGetRequestTimeouts` with this stale height/proof; `meta.sender != 0` still holds, the non-membership check passes against the stale root, and `EvmHost.dispatchTimeOut(GetRequestTimeout, meta, commitment)` pays `meta.fee` a second time before finally clearing `_requestCommitments[commitment]`.     function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }

		/// Number of state commitments retained for `id`: the
		/// [`StateMachineCommitmentCap`] override if set, otherwise
		/// [`MAX_STATE_MACHINE_COMMITMENTS`].
		pub fn state_machine_commitment_cap(id: StateMachineId) -> u32 {
			StateMachineCommitmentCap::<T>::get(id).unwrap_or(MAX_STATE_MACHINE_COMMITMENTS)
		}

		/// Insert a state commitment into the bounded map. ISMP does not allow
		/// duplicate state updates so we don't have an overwrite path.
		///
		/// Appends the height to the per-chain [`StateCommitmentQueue`] and, once
		/// the chain's cap is exceeded, evicts oldest-first from the queue head.
		/// Evictions are limited to [`MAX_COMMITMENT_EVICTIONS_PER_INSERT`] per
		/// call so a lowered cap drains over many insertions rather than in one.
		pub fn insert_bounded_state_commitment(
			height: StateMachineHeight,
			commitment: StateCommitment,
		) {
			let cap = Self::state_machine_commitment_cap(height.id).max(1) as u64;
			let mut state = CommitmentQueueStates::<T>::get(height.id);

			StateCommitmentQueue::<T>::insert(height.id, state.tail, height.height);
			state.tail += 1;

			let excess = (state.tail - state.head)
				.saturating_sub(cap)
				.min(MAX_COMMITMENT_EVICTIONS_PER_INSERT as u64);
			for _ in 0..excess {
				if let Some(old) = StateCommitmentQueue::<T>::take(height.id, state.head) {
					BoundedStateCommitments::<T>::remove(height.id, old);
					BoundedStateMachineUpdateTime::<T>::remove(height.id, old);
				}
				state.head += 1;
			}

			CommitmentQueueStates::<T>::insert(height.id, state);
			BoundedStateCommitments::<T>::insert(height.id, height.height, commitment);
		}
