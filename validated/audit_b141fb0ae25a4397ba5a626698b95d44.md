### Title
Stale Role/Permission Authorization via Locally-Cached LDAP Sessions and API Tokens - ([File: core/sessions/ldapauth/ldap.go])

### Summary
The LDAP authentication provider caches a user's role at session/token creation time in local `ldap_sessions` and `ldap_user_api_tokens` tables. Authorization decisions (`AuthorizedUserWithSession`, `FindUserByAPIToken`) are made entirely against this local cache and never re-validate against the upstream LDAP directory. The cache is only refreshed by a periodic background job (`LDAPServerStateSyncer.Work`) gated by `UpstreamSyncInterval`/`UpstreamSyncRateLimit`. This is structurally the same bug class as CVE-2020-13284 ("API Authorization Using Outdated CI Job Token"): an authorization credential continues to carry an outdated/no-longer-valid permission level until an out-of-band revalidation happens.

### Finding Description
`AuthorizedUserWithSession` reads the role directly from the `ldap_sessions` row rather than the live LDAP group membership: [1](#0-0) 

Likewise `FindUserByAPIToken` reads the role from the `ldap_user_api_tokens` row: [2](#0-1) 

Both explicitly document that "no further upstream LDAP query is performed" and that reconciliation only happens "via the UpstreamSyncInterval config and reaper.go sync implementation" — i.e., the cached role is trusted for authorization purposes between syncs.

The only mechanism that reconciles a demoted/removed user's cached role with the authoritative upstream state is `LDAPServerStateSyncer.Work`, which runs on a timer (`UpstreamSyncInterval`) and is additionally throttled by `UpstreamSyncRateLimit`: [3](#0-2) [4](#0-3) 

This sync job is also the only thing that purges sessions/tokens for users who lost all group membership: [5](#0-4) 

Contrast this with the local-auth provider, whose `AuthorizedUserWithSession`/`FindUserByAPIToken` re-query the live `users` table row on every request, so role changes (`UpdateRole`) take effect immediately and even purge the user's session: [6](#0-5) 

The OIDC provider has the identical caching pattern as LDAP (role cached at session/token creation, reconciled only by its own periodic reaper/sync): [7](#0-6) [8](#0-7) 

The web authentication middleware unconditionally trusts whatever role is returned by these `Authenticator` methods for authorization decisions elsewhere in the app (GraphQL resolvers, REST controllers): [9](#0-8) [10](#0-9) 

### Impact Explanation
If an operator revokes or demotes a user's privileges in the upstream LDAP/OIDC identity source (e.g., removing them from the `admin` group after a compromise, offboarding, or policy change), the user's already-issued session cookie or API token continues to authenticate with the **old, higher-privileged role** for up to a full `UpstreamSyncInterval` (further delayed by `UpstreamSyncRateLimit`). During this window the user (who is an "unprivileged" actor from the standpoint of the just-applied revocation) retains admin/edit-level access to node operations — user management, job/bridge management, keys, etc. — even though the source of truth says they should no longer have it. This is a concrete authorization bypass / stale-permission window, directly analogous to the outdated CI job token being usable past its intended validity in the reported CVE.

### Likelihood Explanation
Likelihood is moderate to high in any deployment that enables LDAP or OIDC authentication (a supported, documented production configuration) rather than local auth. The exposure window is deterministic and configuration-controlled (`UpstreamSyncInterval`), meaning any deployment with a non-trivial sync interval (which is expected to reduce load on the identity server) has a predictable and potentially long window during which revoked/demoted access remains valid. No attacker-controlled trickery is required — this triggers on any legitimate role/group change performed by an admin who reasonably expects immediate effect.

### Recommendation
- For security-sensitive operations (or at minimum role/permission checks), avoid relying solely on the locally cached `user_role` value; consider a lightweight on-demand verification path or a much lower default `UpstreamSyncInterval`/documentation call-out that revocation is not immediate.
- Provide an explicit "force sync" / "revoke session" admin action that can be triggered synchronously when access is intentionally revoked, rather than waiting for the timer.
- Document prominently (in `UpstreamSyncInterval`/`UserAPITokenDuration` config docs) that role downgrades in the upstream directory are not immediately enforced, so operators can set an appropriately short interval for their risk tolerance.
- Consider purging sessions/tokens proactively whenever a downgrade is detected rather than only purging fully-removed users, matching local-auth's immediate session purge on `UpdateRole`.

### Proof of Concept
1. Configure the node with `LDAPAuth` (or `OIDCAuth`) and a non-zero `UpstreamSyncInterval` (e.g., 15m), per `core/config/docs/core.toml`.
2. As an LDAP-admin-group user, log in to create a session (`CreateSession` in `core/sessions/ldapauth/ldap.go:396-457`) or issue an API token (`SetAuthToken` in `core/sessions/ldapauth/ldap.go:544-592`); the resulting `ldap_sessions`/`ldap_user_api_tokens` row caches `user_role = admin`.
3. An operator removes the user from the admin group in the upstream LDAP directory (immediate revocation intended).
4. Before the next `LDAPServerStateSyncer.Work` tick fires, replay the original session cookie or API token against the node's REST/GraphQL API.
5. Observe that `AuthorizedUserWithSession`/`FindUserByAPIToken` (`core/sessions/ldapauth/ldap.go:204-236, 342-373`) still return `Role: admin`, and admin-only endpoints (e.g., user management, `UserController.UpdateRole`/`Delete`) remain accessible until the sync job runs.

Note: I was unable to determine the exact default value shipped for `UpstreamSyncInterval` from the index (searches returned only file/line-count matches without the actual default string), so the concrete default exposure window could not be confirmed from available context — this would need to be checked directly in `core/config/docs/core.toml` in a full session to quantify the real-world window size.

// FindUserByAPIToken retrieves a possible stored user and role from the ldap_user_api_tokens table store
func (l *ldapAuthenticator) FindUserByAPIToken(ctx context.Context, apiToken string) (sessions.User, error) {
	if !l.config.UserApiTokenEnabled() {
		return sessions.User{}, errors.New("API token is not enabled ")
	}

	// Query the ldap user API token table for given token, user role and email are cached so
	// no further upstream LDAP query is performed, sessions and tokens are synced against the upstream server
	// via the UpstreamSyncInterval config and reaper.go sync implementation
	var foundUserToken struct {
		UserEmail string
		UserRole  sessions.UserRole
		Valid     bool
	}
	err := l.ds.GetContext(ctx, &foundUserToken,
		"SELECT user_email, user_role, created_at + $2 >= now() as valid FROM ldap_user_api_tokens WHERE token_key = $1",
		apiToken, l.config.UserAPITokenDuration().Duration(),
	)
	if err != nil {
		return sessions.User{}, err
	}
	if !foundUserToken.Valid { // API Token expired, purge
		if _, execErr := l.ds.ExecContext(ctx, "DELETE FROM ldap_user_api_tokens WHERE token_key = $1", apiToken); execErr != nil {
			l.lggr.Errorf("error purging stale ldap API token session: %v", execErr)
		}
		return sessions.User{}, sessions.ErrUserSessionExpired
	}

	return sessions.User{
		Email: foundUserToken.UserEmail,
		Role:  foundUserToken.UserRole,
	}, nil
}

func (l *LDAPServerStateSyncer) Work(ctx context.Context) {
	// Purge expired ldap_sessions and ldap_user_api_tokens
	recordCreationStaleThreshold := l.config.SessionTimeout().Before(time.Now())
	err := l.deleteStaleSessions(ctx, recordCreationStaleThreshold)
	if err != nil {
		l.lggr.Error("unable to expire local LDAP sessions: ", err)
	}
	recordCreationStaleThreshold = l.config.UserAPITokenDuration().Before(time.Now())
	err = l.deleteStaleAPITokens(ctx, recordCreationStaleThreshold)
	if err != nil {
		l.lggr.Error("unable to expire user API tokens: ", err)
	}

	// Optional rate limiting check to limit the amount of upstream LDAP server queries performed
	if !l.config.UpstreamSyncRateLimit().IsInstant() {
		if !time.Now().After(l.nextSyncTime) {
			return
		}

		// Enough time has elapsed to sync again, store the time for when next sync is allowed and begin sync
		l.nextSyncTime = time.Now().Add(l.config.UpstreamSyncRateLimit().Duration())
	}

	l.lggr.Info("Begin Upstream LDAP provider state sync after checking time against config UpstreamSyncInterval and UpstreamSyncRateLimit")

// UpdateRole overwrites role field of the user specified by email.
func (o *orm) UpdateRole(ctx context.Context, email, newRole string) (sessions.User, error) {
	var userToEdit sessions.User

	if newRole == "" {
		return userToEdit, pkgerrors.New("user role must be specified")
	}

	err := sqlutil.TransactDataSource(ctx, o.ds, nil, func(tx sqlutil.DataSource) error {
		// First, attempt to load specified user by email
		if err := tx.GetContext(ctx, &userToEdit, "SELECT * FROM users WHERE lower(email) = lower($1)", email); err != nil {
			return pkgerrors.New("no matching user for provided email")
		}

		// Patch validated role
		userRole, err := sessions.GetUserRole(newRole)
		if err != nil {
			return err
		}
		userToEdit.Role = userRole

		_, err = tx.ExecContext(ctx, "DELETE FROM sessions WHERE email = lower($1)", email)
		if err != nil {
			o.lggr.Errorw("Failed to purge user sessions for UpdateRole", "err", err)
			return pkgerrors.New("error updating API user")
		}

		sql := "UPDATE users SET role = $1, updated_at = now() WHERE lower(email) = lower($2) RETURNING *"
		if err := tx.GetContext(ctx, &userToEdit, sql, userToEdit.Role, email); err != nil {
			o.lggr.Errorw("Error updating API user", "err", err)
			return pkgerrors.New("error updating API user")
		}

		return nil
	})

	return userToEdit, err
}

func AuthenticateBySession(c *gin.Context, authr Authenticator) error {
	ctx := c.Request.Context()
	session := sessions.Default(c)
	sessionID, ok := session.Get(SessionIDKey).(string)
	if !ok {
		return auth.ErrorAuthFailed
	}

		return err
	}
