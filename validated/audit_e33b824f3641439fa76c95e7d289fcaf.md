### Title
`calc_take_pnl` assumes the swap invariant (k) never decreases below the recorded PnL baseline, causing `Deposit`/`Withdraw` to permanently revert (frozen LP funds) - (File: `program/src/processor.rs`)

### Summary
`Processor::calc_take_pnl` recomputes the AMM's k-invariant from the *current* vault balances (`total_pc_without_take_pnl * total_coin_without_take_pnl`) and compares it against a previously stored baseline (`target.calc_pnl_x * target.calc_pnl_y`). The function hard-codes the assumption that current k is always `>=` the stored baseline; if it ever is not, the function unconditionally returns `AmmError::CalcPnlError`, which propagates up and reverts the entire `Deposit`/`Withdraw`/`WithdrawPnl` instruction. This mirrors the INIT Capital `POS_MANAGER` bug class: a value that is implicitly assumed to be monotonically non-decreasing between calls, but is not guaranteed to be so, causes downstream calls to permanently revert. [1](#0-0) 

### Finding Description
`calc_take_pnl` is invoked from `process_deposit`, `process_withdraw`, and `process_withdrawpnl` every time liquidity changes: [2](#0-1) [3](#0-2) 

Inside it, the guard is:

```rust
if pool_pc_amount.checked_mul(pool_coin_amount).unwrap()
    >= (calc_pc_amount).checked_mul(calc_coin_amount).unwrap()
{
    ... // compute delta_x/delta_y, update need_take_pnl_*, ok
} else {
    return Err(AmmError::CalcPnlError.into());
}
``` [4](#0-3) 

`target.calc_pnl_x`/`target.calc_pnl_y` are only updated inside `process_deposit`/`process_withdraw`/`process_withdrawpnl` themselves, each time going through decimal normalization (`normalize_decimal_v2`) and de-normalization (`restore_decimal`) between the raw token amounts and the internal fixed-point `sys_decimal_value` representation: [5](#0-4) [6](#0-5) 

Because these conversions round (floor/ceiling) at each step, and because `calc_pnl_x`/`calc_pnl_y` and the vault-derived `total_pc_without_take_pnl`/`total_coin_without_take_pnl` are each updated via *different* rounding paths (one subtracts a `restore_decimal(normalize_decimal_v2(...))` round-trip, the other subtracts a raw token amount), repeated deposit/withdraw cycles can cause the recorded baseline `calc_pnl_x * calc_pnl_y` to drift above the actual current pool invariant `total_pc_without_take_pnl * total_coin_without_take_pnl`. The developers were clearly aware rounding drift is a risk here — there is a dedicated regression test, `test_calc_pnl_precision`, exercising exactly this multi-withdraw rounding scenario: [7](#0-6) 

Once the recorded baseline exceeds the actual invariant (whether via rounding drift accumulated over many small deposits/withdrawals, or an attacker deliberately performing a sequence of dust-sized withdrawals designed to maximize rounding loss in one direction), **every subsequent call to `calc_take_pnl` reverts unconditionally** with `AmmError::CalcPnlError`, since nothing in the codebase ever resets or repairs `calc_pnl_x`/`calc_pnl_y` from outside these three permissioned code paths.

### Impact Explanation
Since `calc_take_pnl` is called unconditionally in `process_deposit` and (except when the pool has been placed into the privileged `WithdrawOnly` status) in `process_withdraw`, a single occurrence of this drift permanently blocks:
- All further `Deposit` calls (LP funds cannot grow / new deposits DoS'd).
- All further `Withdraw` calls (LP holders cannot redeem their LP tokens for underlying coin/pc) unless the AMM owner intervenes via a privileged `SetParams`/status-change instruction to force `WithdrawOnly` (bypassing `calc_take_pnl` for withdraw only — deposits remain permanently frozen, and if the owner never intervenes, both remain frozen).
- `WithdrawPnl` (the protocol's own PnL collection) is likewise permanently DoS'd.

This is a permanent freezing of LP/user funds without any recovery path reachable by an unprivileged actor, matching the class of impact called out in the source report (blocking of protected operations due to a broken monotonicity assumption).

### Likelihood Explanation
The condition can be reached purely through unprivileged, permissionless instructions (`Deposit`/`Withdraw`) with attacker-chosen amounts — no special accounts or signer privileges are required. Because the rounding behavior of `normalize_decimal_v2`/`restore_decimal` is deterministic and depends only on the coin/pc decimals and chosen amounts, an attacker can craft a sequence of small deposit/withdraw operations designed to maximize the divergence between the vault-based invariant and the recorded `calc_pnl_x`/`calc_pnl_y` baseline in a single transaction or a short sequence of transactions, rather than relying on incidental drift over time. This makes deliberate exploitation plausible, though the exact amounts needed to trigger the failing inequality depend on the specific pool's `pc_decimals`/`coin_decimals`/`sys_decimal_value` and would need to be empirically derived (I could not fully verify the exact numeric drift bound with the available tooling; a background Devin/foundry-equivalent test run against the actual `Calculator::normalize_decimal_v2`/`restore_decimal` implementations would be needed to construct a concrete numeric PoC).

### Recommendation
Do not treat `pool_pc_amount * pool_coin_amount < calc_pc_amount * calc_coin_amount` as an unrecoverable error. Instead:
1. When the current invariant is below the recorded baseline, skip PnL extraction for that call (treat `delta_x = delta_y = 0`) and either leave `calc_pnl_x`/`calc_pnl_y` unchanged or clamp them down to the current invariant, rather than returning `AmmError::CalcPnlError` and reverting the whole `Deposit`/`Withdraw` instruction.
2. Ensure `calc_pnl_x`/`calc_pnl_y` updates in `process_deposit`/`process_withdraw` use the exact same rounding path as the vault-balance-derived totals so that the two figures cannot diverge due to independent rounding.

### Proof of Concept
The repository's own unit test demonstrates the mechanics of the drift (rounding through `normalize_decimal_v2`/`restore_decimal` across successive withdraw cycles updating `target.calc_pnl_x`/`calc_pnl_y` independently of `total_pc_without_take_pnl`/`total_coin_without_take_pnl`): [8](#0-7) 

To turn this into a full on-chain PoC, a background engineer should:
1. Write a Foundry/Solana-program-test harness that calls `Initialize2`, then repeatedly calls `Deposit`/`Withdraw` with amounts chosen to maximize floor/ceiling rounding divergence between `calc_pnl_x`/`calc_pnl_y` and `total_pc_without_take_pnl`/`total_coin_without_take_pnl` (varying `pc_decimals`/`coin_decimals` combinations, since `normalize_decimal_v2`/`restore_decimal` round differently depending on decimal deltas).
2. Confirm that a subsequent `Deposit` or `Withdraw` call reverts with `AmmError::CalcPnlError` at [9](#0-8)  even though no legitimate loss of LP-backing funds occurred, demonstrating the pool becomes permanently un-depositable/un-withdrawable for unprivileged users.

    pub fn calc_take_pnl(
        target: &TargetOrders,
        amm: &mut AmmInfo,
        total_pc_without_take_pnl: &mut u64,
        total_coin_without_take_pnl: &mut u64,
        x1: U256,
        y1: U256,
    ) -> Result<(u128, u128), ProgramError> {
        // calc pnl
        let mut delta_x: u128;
        let mut delta_y: u128;
        let calc_pc_amount = Calculator::restore_decimal(
            target.calc_pnl_x.into(),
            amm.pc_decimals,
            amm.sys_decimal_value,
        );
        let calc_coin_amount = Calculator::restore_decimal(
            target.calc_pnl_y.into(),
            amm.coin_decimals,
            amm.sys_decimal_value,
        );
        let pool_pc_amount = U128::from(*total_pc_without_take_pnl);
        let pool_coin_amount = U128::from(*total_coin_without_take_pnl);
        if pool_pc_amount.checked_mul(pool_coin_amount).unwrap()
            >= (calc_pc_amount).checked_mul(calc_coin_amount).unwrap()
        {
            // last k is
            // let last_k: u128 = (target.calc_pnl_x as u128).checked_mul(target.calc_pnl_y as u128).unwrap();
            // current k is
            // let current_k: u128 = (x1 as u128).checked_mul(y1 as u128).unwrap();
            // current p is
            // let current_p: u128 = (x1 as u128).checked_div(y1 as u128).unwrap();
            let x2_power = Calculator::calc_x_power(
                target.calc_pnl_x.into(),
                target.calc_pnl_y.into(),
                x1,
                y1,
            );
            // let x2 = Calculator::sqrt(x2_power).unwrap();
            let x2 = x2_power.integer_sqrt();
            // msg!(arrform!(LOG_SIZE, "calc_take_pnl x2_power:{}, x2:{}", x2_power, x2).as_str());
            let y2 = x2.checked_mul(y1).unwrap().checked_div(x1).unwrap();
            // msg!(arrform!(LOG_SIZE, "calc_take_pnl y2:{}", y2).as_str());

            // transfer to token_coin_pnl and token_pc_pnl
            // (x1 -x2) * pnl / sys_decimal_value
            let diff_x = U128::from(x1.checked_sub(x2).unwrap().as_u128());
            let diff_y = U128::from(y1.checked_sub(y2).unwrap().as_u128());
            delta_x = diff_x
                .checked_mul(amm.fees.pnl_numerator.into())
                .unwrap()
                .checked_div(amm.fees.pnl_denominator.into())
                .unwrap()
                .as_u128();
            delta_y = diff_y
                .checked_mul(amm.fees.pnl_numerator.into())
                .unwrap()
                .checked_div(amm.fees.pnl_denominator.into())
                .unwrap()
                .as_u128();

            let diff_pc_pnl_amount =
                Calculator::restore_decimal(diff_x, amm.pc_decimals, amm.sys_decimal_value);
            let diff_coin_pnl_amount =
                Calculator::restore_decimal(diff_y, amm.coin_decimals, amm.sys_decimal_value);
            let pc_pnl_amount = diff_pc_pnl_amount
                .checked_mul(amm.fees.pnl_numerator.into())
                .unwrap()
                .checked_div(amm.fees.pnl_denominator.into())
                .unwrap()
                .as_u64();
            let coin_pnl_amount = diff_coin_pnl_amount
                .checked_mul(amm.fees.pnl_numerator.into())
                .unwrap()
                .checked_div(amm.fees.pnl_denominator.into())
                .unwrap()
                .as_u64();
            if pc_pnl_amount != 0 && coin_pnl_amount != 0 {
                amm.state_data.need_take_pnl_pc = amm
                    .state_data
                    .need_take_pnl_pc
                    .checked_add(pc_pnl_amount)
                    .unwrap();
                amm.state_data.need_take_pnl_coin = amm
                    .state_data
                    .need_take_pnl_coin
                    .checked_add(coin_pnl_amount)
                    .unwrap();

                // step3: update total_coin and total_pc without pnl
                *total_pc_without_take_pnl = (*total_pc_without_take_pnl)
                    .checked_sub(pc_pnl_amount)
                    .unwrap();
                *total_coin_without_take_pnl = (*total_coin_without_take_pnl)
                    .checked_sub(coin_pnl_amount)
                    .unwrap();
            } else {
                delta_x = 0;
                delta_y = 0;
            }
        } else {
            msg!(arrform!(
                LOG_SIZE,
                "calc_take_pnl error x:{}, y:{}, calc_pnl_x:{}, calc_pnl_y:{}",
                x1,
                y1,
                identity(target.calc_pnl_x),
                identity(target.calc_pnl_y)
            )
            .as_str());
            return Err(AmmError::CalcPnlError.into());
