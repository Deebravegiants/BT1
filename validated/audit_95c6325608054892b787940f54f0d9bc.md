**Reasoning:**

`ShardedJmtMerkleDb::get_state_snapshot_version_before` is a storage-layer helper used only to find the latest version whose top-level (non-sharded) JMT root has actually been persisted in the metadata DB, falling back to the previous version when the top-level root write for a version is missing (e.g., a crash between the parallel shard writes and the subsequent `commit_top_levels` call in `commit`). [1](#0-0) 

Within a single `commit(version, ...)` call, all 16 shard batches for that version are written first, then the top-level batch is written for that same version — a debit and its corresponding credit (both part of one transaction, hence one `version`) are always written together across shards before that version's top level is committed. [2](#0-1) 

The recursive fallback only triggers when the top-level root node for a version is absent from the metadata DB, and it walks strictly backward to older versions — it never returns a version whose top-level root doesn't exist, and it never mixes debit-shard data from version N with credit-shard data from version N-1. Any tree traversal against the returned (fully-committed) version reads nodes filtered by `node_key.version() <= reported_version`, so partially-written shard data belonging to a later, not-yet-finalized version is simply invisible/orphaned — it cannot be picked up by JMT traversal at the reported snapshot version, so there is no possibility of a state reconstruction that includes a withdrawal without its corresponding deposit or vice versa.

Additionally, this code path is only exercised in local node crash-recovery / restore scenarios (mid-write crash between shard commits and top-level commit, or during `commit_no_progress` used by fast-sync's `TreeWriter::write_node_batch`), not through any unprivileged transaction, package, view, authenticator, API, bytecode, or proof input. There is no entrypoint by which an ordinary transaction sender can control the timing/ordering of `commit_top_levels` versus shard writes relative to this recursive lookup. This falls outside the required unprivileged-input custody boundary and is excluded as node-local storage/crash-recovery behavior rather than a custody-affecting bug in asset ownership, transfer, minting, freezing, or supply accounting.

    pub(crate) fn commit(
        &self,
        version: Version,
        top_levels_batch: impl IntoRawBatch,
        batches_for_shards: Vec<impl IntoRawBatch + Send>,
    ) -> Result<()> {
        ensure!(
            batches_for_shards.len() == NUM_STATE_SHARDS,
            "Shard count mismatch."
        );
        THREAD_MANAGER.get_io_pool().install(|| {
            batches_for_shards
                .into_par_iter()
                .enumerate()
                .for_each(|(shard_id, batch)| {
                    self.db_shard(shard_id)
                        .write_schemas(batch)
                        .unwrap_or_else(|err| {
                            panic!("Failed to commit state merkle shard {shard_id}: {err}")
                        });
                })
        });

        self.commit_top_levels(version, top_levels_batch)?;

        if let Some(lru_cache) = self.lru_cache.as_ref() {
            self.version_caches
                .iter()
                .for_each(|(_, cache)| cache.maybe_evict_version(lru_cache));
        }

        Ok(())
    }

    pub fn get_state_snapshot_version_before(
        &self,
        next_version: Version,
    ) -> Result<Option<Version>> {
        if next_version > 0 {
            let max_possible_version = next_version - 1;
            let mut iter = self.metadata_db().rev_iter::<JellyfishMerkleNodeSchema>()?;
            iter.seek_for_prev(&NodeKey::new_empty_path(max_possible_version))?;
            if let Some((key, _node)) = iter.next().transpose()? {
                let version = key.version();
                if self
                    .metadata_db()
                    .get::<JellyfishMerkleNodeSchema>(&NodeKey::new_empty_path(version))?
                    .is_some()
                {
                    return Ok(Some(version));
                }
                // Since we split state merkle commit into multiple batches, it's possible that
                // the root is not committed yet. In this case we need to look at the previous
                // root.
                return self.get_state_snapshot_version_before(version);
            }
        }
        // No version before genesis.
        Ok(None)
    }
