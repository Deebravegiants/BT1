### Title
Webhook `shop-domain` header is not covered by the HMAC signature, allowing cross-tenant webhook spoofing - (`lib/shopify_api/webhooks/request.rb`)

### Summary
`ShopifyAPI::Webhooks::Request` derives the HMAC-signed content solely from the raw request body, while the `shop` (tenant identifier) is read from an unauthenticated HTTP header. `Registry.process` validates only the body's HMAC and then hands the header-derived `shop` value to the app's webhook handler as the trusted tenant key. Any unprivileged actor who can get one genuine, Shopify-signed webhook delivered to their own store (e.g. by installing the app on a free/dev store they control) can replay that exact body+HMAC pair to the app's webhook endpoint while substituting an arbitrary victim `shop-domain` header, and the gem will accept it as authentic for that victim shop.

### Finding Description
The equality the gem is supposed to enforce is:
`shop authenticated by Shopify's signature == shop used by the app as the tenant/session key`

Instead:
- `Request#to_signable_string` returns only `@raw_body`: [1](#0-0) 
- `Request#shop` is read straight from an HTTP header with no cryptographic binding to the body: [2](#0-1) 
- `HmacValidator.validate` recomputes and compares the signature purely over `to_signable_string` (i.e., the body), never touching the shop header: [3](#0-2) 
- `Registry.process` validates the HMAC and then forwards `request.shop` (the unauthenticated header value) to the handler as the trusted tenant identity: [4](#0-3) 

Because the shop-domain header sits outside the signed material, two different values of `shop` can be attached to the exact same signed body without invalidating the HMAC. Any request whose body is byte-identical to a previously-received, genuinely-signed webhook will pass `HmacValidator.validate` regardless of which shop's domain is claimed in the header.

### Impact Explanation
An attacker who installs the target app on a store they control (a normal, unprivileged action available to any internet user for public/dev-store apps) will receive genuinely Shopify-signed webhooks for events on their own store. By capturing the raw body and its valid `X-Shopify-Hmac-Sha256` value and replaying them directly to the app's webhook endpoint with the `X-Shopify-Shop-Domain` header rewritten to a victim shop, the attacker can make the app process attacker-controlled webhook content (e.g. `app/uninstalled`, `customers/redact`, GDPR/data payloads, or any topic with attacker-influenced fields) as if it originated from the victim tenant. Depending on how the host app keys session lookup/state changes off `WebhookMetadata#shop`, this can trigger cross-tenant actions such as deleting or corrupting another merchant's stored session/data, satisfying the "cross-tenant access" Critical impact bucket defined in scope.

### Likelihood Explanation
Likelihood is high for any app that (a) exposes a public webhook endpoint using this gem's `Registry.process`/`Request` classes as documented, and (b) allows installation on attacker-controlled stores (standard for any public Shopify app or free dev store). No secrets, tokens, or privileged access are required — only the ability to install the app once and observe one delivered webhook.

### Recommendation
Bind the shop identity into the material that is HMAC-verified, or otherwise cryptographically tie the `shop-domain` header to the signed body (e.g., include the header in `to_signable_string`, or cross-check `request.shop` against the shop encoded in the payload / a per-shop registered webhook secret) before trusting `request.shop` as the tenant key in `WebhookMetadata`.

### Proof of Concept
1. Install the vulnerable app on attacker-owned shop `attacker.myshopify.com`; trigger any webhook topic the app subscribes to (e.g., `app/uninstalled`).
2. Capture the raw POST body and the `X-Shopify-Hmac-Sha256` header Shopify sent — this HMAC is valid because it is computed only over the body using the app's shared secret.
3. Replay this exact body and HMAC header to the app's public webhook endpoint, but set `X-Shopify-Shop-Domain: victim.myshopify.com`.
4. `ShopifyAPI::Utils::HmacValidator.validate` succeeds (body matches signature), `ShopifyAPI::Webhooks::Registry.process` invokes the app's handler with `WebhookMetadata#shop == "victim.myshopify.com"`, even though nothing about the request was authenticated as coming from `victim.myshopify.com`.
