### Title
Biometric identifiers (iris codes, mask codes, normalized iris images, face embeddings) remain unencrypted in process memory throughout the signup pipeline - (File: src/plans/biometric_pipeline/mod.rs, src/plans/personal_custody_package.rs, src/agents/python/iris/mod.rs)

### Summary
Analogous to the reported mnemonic-phrase-in-memory issue, orb-core holds highly sensitive, irrevocable biometric identifiers — iris codes, iris mask codes, iris code MPC shares, and normalized iris images — as plaintext `String`/`Vec<u8>` fields in ordinary heap-allocated structs for the entire duration of a signup, from capture through personal-custody-package (PCP) construction. Encryption is applied only at the very last step, immediately before upload, meaning the plaintext biometric data is exposed in process memory for an extended window with no in-memory protection (no `zeroize`, no secure/locked memory, no early wipe of intermediate buffers).

### Finding Description
The iris pipeline agent produces `EstimateOutput` containing plaintext `iris_code`, `mask_code`, `iris_code_shares`, `mask_code_shares`, and `NormalizedIris` images [1](#0-0) . This output is copied unchanged into `EyePipeline` inside the biometric pipeline plan [2](#0-1) , and further propagated into `personal_custody_package::Pipeline` and `Credentials`, which store the same values as plain `String`/`Vec<u8>` [3](#0-2) .

These plaintext structures persist across multiple async task boundaries (`orb.ui.biometric_pipeline_success()`, `debug_report` population, `dd_incr!` logging, JSON serialization for debug/self-serve flows) before `Package::build()` is invoked. Only inside `build()` are the iris/normalized-iris/face tar archives passed through `encrypt(...)` — right before being packaged for upload [4](#0-3) . Prior to that call, the iris codes, mask codes, MPC shares, and normalized iris images sit unencrypted in memory, and none of the intermediate containers (`EyePipeline`, `biometric_pipeline::Pipeline`, `personal_custody_package::Pipeline`, `Credentials`) implement zeroization or secure-memory handling; standard Rust `Drop` for `String`/`Vec<u8>` does not wipe memory contents.

Additionally, under the `allow-plan-mods` feature, the fully-decoded iris codes are written out to `codes.json` on disk in plaintext for debugging purposes [5](#0-4) , and the `log-iris-data` feature logs raw iris code/mask code contents via `tracing::info!` [6](#0-5) , further widening the exposure surface for the same unencrypted in-memory biometric secrets. There is no `zeroize`/`Zeroizing` usage anywhere in orb-core's own source (only present transitively via dependencies), confirming no deliberate memory-scrubbing of these buffers is performed once they're no longer needed.

### Impact Explanation
Iris codes and normalized iris images are permanent, non-revocable biometric identifiers analogous to the wallet mnemonic — anyone extracting them from an Orb's memory (e.g. via a memory dump, debugger, core dump on crash, or a compromised co-located process) can impersonate or link the user's biometric identity outside the intended cryptographic protections that the Personal Custody Package (PCP) is designed to enforce. This is analogous to "biometric data disclosure," an explicitly accepted high-impact category for this analysis.

### Likelihood Explanation
An attacker needs local access to the Orb's process memory (e.g., through a coredump, an unrelated debugging/administrative interface, or a bug enabling arbitrary memory read) during the multi-step window between biometric capture and final PCP encryption in `Package::build()`. The window spans multiple async steps and feature-gated debug paths (`allow-plan-mods`, `log-iris-data`) which further increase the plaintext data's exposure surface and duration.

### Recommendation
- Wrap iris codes, mask codes, MPC shares, and normalized iris image buffers in a zeroizing container (e.g., `zeroize::Zeroizing`) from the moment they are produced by the iris agent through to their encryption in `Package::build()`.
- Reduce the lifetime of plaintext biometric buffers by encrypting immediately after capture/estimation rather than deferring encryption to the final PCP-build step.
- Gate or remove the `allow-plan-mods` plaintext `codes.json` dump and the `log-iris-data` plaintext logging path from any build that could run in production-adjacent environments.
- Avoid `Clone`-ing plaintext iris/mask code structures into `debug_report` unless strictly required, and zeroize any cloned copies once consumed.

### Proof of Concept
1. Start a signup; the iris agent returns `EstimateOutput { iris_code, mask_code, iris_code_shares, mask_code_shares, normalized_image, .. }` in plaintext [7](#0-6) .
2. These values flow unencrypted into `EyePipeline` and then `personal_custody_package::Pipeline`/`Credentials` [8](#0-7) , [9](#0-8) .
3. During this interval, dumping the orb-core process's heap (e.g. via `gcore`, a crash handler, or a debugger attached locally) would expose the raw iris code, mask code, MPC shares, and normalized iris pixel data in plaintext, since encryption only happens later at `Package::build()` [10](#0-9) .
4. With `allow-plan-mods` enabled, the same plaintext codes are additionally written to `codes.json` on disk [5](#0-4) .

impl Package<'_> {
    fn build(&self) -> Result<(Vec<u8>, Vec<u8>, Vec<u8>)> {
        let Self { ts, ref credentials, .. } = *self;
        let Credentials {
            backend_iris_public_key,
            backend_normalized_iris_public_key,
            backend_face_public_key,
            backend_tier2_public_key,
            self_custody_user_public_key,
            pcp_version,
            ..
        } = credentials;
        let mut hashes = BTreeMap::new();
        let mut tier0 = tar::Builder::new(Vec::new());
        let mut tier1 = tar::Builder::new(Vec::new());
        let mut tier2 = tar::Builder::new(Vec::new());

        let mut iris_tar = self.make_iris_tar(&mut hashes)?;
        iris_tar = encrypt(iris_tar, backend_iris_public_key);

        let mut normalized_iris_tar = self.make_normalized_iris_tar(&mut hashes)?;
        normalized_iris_tar = encrypt(normalized_iris_tar, backend_normalized_iris_public_key);

        let mut face_tar = self.make_face_tar(&mut hashes)?;
        face_tar = encrypt(face_tar, backend_face_public_key);

        let backend_keys_json = self.make_backend_keys_json(&mut hashes)?;

        if *pcp_version >= 3 {
            tar_append(&mut tier1, ts, "iris.tar", iris_tar)?;
            tar_append(&mut tier1, ts, "normalized_iris.tar", normalized_iris_tar)?;
            tar_append(&mut tier1, ts, "face.tar", face_tar)?;
            self.make_tier2(&mut tier2)?;
        } else {
            tar_append(&mut tier0, ts, "iris.tar", iris_tar)?;
            tar_append(&mut tier0, ts, "normalized_iris.tar", normalized_iris_tar)?;
            tar_append(&mut tier0, ts, "face.tar", face_tar)?;
        }

        let tier1_compressed = compress(tier1.into_inner()?, ts, "tier1.tar.gz")?;
        let tier1_encrypted = encrypt(tier1_compressed, self_custody_user_public_key);
        let tier2_compressed = compress(tier2.into_inner()?, ts, "tier2.tar.gz")?;
        let tier2_single_encrypted = backend_tier2_public_key
            .map(|backend_tier2_public_key| encrypt(tier2_compressed, &backend_tier2_public_key))
            .unwrap_or_default();
        let tier2_encrypted = encrypt(tier2_single_encrypted, self_custody_user_public_key);
