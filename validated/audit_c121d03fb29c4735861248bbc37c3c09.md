### Title
Unaccounted native-ETH balance change in `EmporiumUpgradeable.runAction` allows draining contract's ETH via signature-less "stateless" ops - (File: `contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol`)

### Summary
`EmporiumUpgradeable.runAction` only verifies that the contract's balance did not decrease for the tokens listed in `circomData.erc20TokenAddresses`. Because that array is chosen by the caller (as part of the proven `circomData`), an attacker can simply omit `address(0)` (native ETH) from it while still executing an `EmporiumOperation` with `op.value > 0` in the signature-free "stateless" branch, sending out ETH that the contract holds (e.g. accumulated relay fees, dust from prior `receive()` calls) without that outflow ever appearing in the balance-change equality check.

### Finding Description
`runAction` computes `balancesBefore`/`balancesAfter` strictly over `circomData.erc20TokenAddresses`: [1](#0-0) [2](#0-1) 

For each op in the stack, when `invokeWallet` is false or `signerAddress == address(0)`, the "stateless" branch performs an arbitrary low-level call with attacker-controlled native value straight from the Emporium contract's own balance, with no per-op signature check tied to that value beyond the overall EIP-712 signature (which itself is skipped entirely when `signerAddress == address(0)`): [3](#0-2) [4](#0-3) 

The only economic safety net is the post-call check that `balanceChange >= 0` for each entry actually present in `circomData.erc20TokenAddresses`: [5](#0-4) 

`getERC20OrETHBalance(address(0))` returns `address(this).balance`, i.e. the *entire* contract ETH balance, not just the amount attributable to the current caller: [6](#0-5) 

Since the `erc20TokenAddresses` array is supplied by the caller and used verbatim to select which balances get checked, an attacker can construct a `CircomData`/`EmporiumStack` where:
- `erc20TokenAddresses` lists only an unrelated ERC-20 (or is otherwise crafted to exclude `address(0)`),
- `stack.signerAddress == address(0)` so `verifyWallet` returns immediately without any signature check on `stack.ops`,
- one `EmporiumOperation` has `invokeWallet == false`, an attacker-controlled `endpoint`, and `value` equal to the contract's current ETH balance.

The loop then executes `op.endpoint.call{value: op.value}(op.callData)`, draining the contract's ETH to the attacker's address, and because `address(0)` is absent from `erc20TokenAddresses`, this ETH outflow is never included in the `balancesBefore`/`balancesAfter` comparison, so the `BalanceChangeShouldBePositive` guard never fires. This breaks the balance equality the function relies on ("total change of emporium balance = what was moved to emporium + how emporium balance changed through tx") because the equation simply omits the ETH leg entirely when the token isn't in the array.

The ETH sitting in `EmporiumUpgradeable` (which has a permissive `receive() external payable {}`) originates from relay-fee payments (`sendToRelay`/`payRelayFees`) and any dust left from prior operations - i.e., protocol/relay funds, not funds the calling UTXO owner has proven ownership of.

### Impact Explanation
This is theft of protocol/relay ETH funds held by the `EmporiumUpgradeable` contract, executed via a call that was never authorized by any signer for that value (the EIP-712 signature check is skipped for `signerAddress == address(0)`, and even when present, it only binds the ops the *first* time - the balance check that should catch unaccounted value movement is bypassed by omitting the token from the checked array). This matches "theft ... of protocol/relay fees" and "executing calls or moving assets ... never authorised" (High impact).

### Likelihood Explanation
Reachable by any user who can submit a valid Hinkal proof with `externalActionData` targeting the Emporium external action, since `erc20TokenAddresses` and the encoded `EmporiumStack` (including `op.value`, `op.endpoint`, and `signerAddress = address(0)`) are attacker-chosen inputs to `runAction`, and `onlyAllowedRecipient` only checks `msg.sender == Hinkal`, not the caller's proof content. The prerequisite is that the Emporium contract holds a nonzero ETH balance (from relay fees or dust), which accumulates naturally over normal protocol operation via `receive() external payable {}` and `sendToRelay`.

### Recommendation
- Do not rely on the caller-supplied `erc20TokenAddresses` array to decide which balances are checked for safety; always include `address(0)` in the before/after balance snapshot for `runAction`, or independently track and require that any ETH sent out via `op.value` in the ops loop is deducted from a tracked/whitelisted balance.
- Require a valid signer/signature for any op carrying nonzero `value`, rather than allowing `signerAddress == address(0)` to skip verification entirely.
- Consider enforcing that `circomData.erc20TokenAddresses` must be a superset of all tokens (including native ETH) referenced by `stack.ops[].value`.

### Proof of Concept
1. Ensure `EmporiumUpgradeable` holds ETH (normal state, accumulated via `receive()`/relay-fee flows) - call this balance `B`.
2. Attacker submits a valid Hinkal `transact()` proof whose `circomData.externalActionData` targets the Emporium action, with `circomData.erc20TokenAddresses` containing only an arbitrary ERC-20 token (not `address(0)`) and near-zero/self-consistent `amountChanges` for that token so the proof and other Hinkal-level checks pass.
3. `externalActionMetadata` decodes to an `EmporiumStack` with `signerAddress = address(0)` and a single `EmporiumOperation{ endpoint: attackerContract, invokeWallet: false, value: B, callData: "" }`.
4. In `runAction`: `verifyWallet` returns immediately (no signature check because `signerAddress == address(0)`); the loop executes `attackerContract.call{value: B}("")`, draining all ETH from `EmporiumUpgradeable` to the attacker.
5. `balancesBefore`/`balancesAfter` are computed only over the single ERC-20 token in `erc20TokenAddresses`; the ETH balance change is never checked, so `BalanceChangeShouldBePositive` never reverts. [7](#0-6)

    function runAction(
        CircomData calldata circomData,
        int256[] calldata deltaAmountChanges
    ) external override onlyAllowedRecipient returns (UTXO[] memory) {
        EmporiumStack memory stack = abi.decode(
            circomData.externalActionData.externalActionMetadata,
            (EmporiumStack)
        );

        uint256[] memory balancesBefore = getBalancesForArray(
            circomData.erc20TokenAddresses
        );

        verifyWallet(stack, circomData);

        for (uint256 i = 0; i < stack.ops.length; i++) {
            EmporiumOperation memory op = stack.ops[i];

            bool success;
            bytes memory err;

            // CASE 1: Stateful Interaction
            if (op.invokeWallet && stack.signerAddress != address(0)) {
                (success, err) = IHinkalWallet(stack.signerAddress)
                    .callHinkalWallet(op.endpoint, op.callData, op.value);
            }
            // CASE 2: Stateless Interaction
            else {
                bytes4 selector = bytes4(op.callData);
                if (
                    selector == IHinkalWallet.callHinkalWallet.selector ||
                    selector == IHinkalWallet.doSendToRelay.selector
                ) {
                    revert UnauthorizedWalletCall();
                }

                (success, err) = op.endpoint.call{value: op.value}(op.callData);
            }

            if (!success) {
                revert CallFailed(err);
            }
        }

        payRelayFees(circomData, stack.signerAddress, deltaAmountChanges);

        uint256[] memory balancesAfter = getBalancesForArray(
            circomData.erc20TokenAddresses
        );

        UTXO[] memory utxoSet = new UTXO[](
            circomData.erc20TokenAddresses.length
        );

        uint256 utxoSetLength;

        for (uint256 i = 0; i < circomData.erc20TokenAddresses.length; i++) {
            int256 balanceChange = int256(balancesAfter[i]) -
                int256(balancesBefore[i]);

            if (deltaAmountChanges[i] < 0) {
                balanceChange -= deltaAmountChanges[i];
                // this equation reads: total change of emporium balance = what was moved to emporium (-deltaAmountChange) + how emporium balance changed through tx (balanceChange)
            }

            // the only case when balanceChange can be < 0, when there were some funds on emporium before the call
            if (balanceChange < 0) {
                revert BalanceChangeShouldBePositive();
            }

            UTXO memory utxoOut = handleOut(balanceChange, circomData, i);

            if (utxoOut.amount > 0) {
                utxoSet[utxoSetLength++] = utxoOut;
            }
        }

        if (utxoSetLength < circomData.erc20TokenAddresses.length) {
            utxoSet.skipLast(
                circomData.erc20TokenAddresses.length - utxoSetLength
            );
        }

        return utxoSet;
    }

    function getERC20OrETHBalance(
        address _erc20TokenAddress
    ) internal view returns (uint256) {
        if (_erc20TokenAddress == address(0)) {
            return address(this).balance;
        } else {
            IERC20 outToken = IERC20(_erc20TokenAddress);
            return outToken.balanceOf(address(this));
        }
    }
