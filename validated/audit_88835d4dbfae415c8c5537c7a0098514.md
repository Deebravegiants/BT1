Found it: in `exchange_token` (lib/shopify_api/auth/token_exchange.rb), the shop used to build the outbound HTTP request is taken directly from the JWT's `dest` claim (`jwt_payload.shop`, i.e., `dest.gsub("https://", "")`) with **no call to `Utils::ShopValidator.sanitize!`**, unlike its sibling method `migrate_to_expiring_token` in the same file, which does call `Utils::ShopValidator.sanitize!(shop)` before building the request session. `dest` is only checked for being non-nil in `JwtPayload#initialize`, but the domain itself is never validated against `ShopValidator::TRUSTED_SHOPIFY_DOMAINS`.

### Title
Missing shop-domain sanitization in `TokenExchange.exchange_token` allows `client_secret` exfiltration via SSRF - (File: lib/shopify_api/auth/token_exchange.rb)

### Summary
`ShopifyAPI::Auth::TokenExchange.exchange_token` builds an outbound OAuth token-exchange request whose destination host is derived from the `dest` claim of a caller-supplied session token, without ever passing that value through `Utils::ShopValidator.sanitize!`. The request body includes the app's `client_secret` in plaintext. Because the destination host is attacker-controlled, this breaks the identity binding: `dest_shop` (used as connection host) ≠ `shop` (validated, trusted Shopify domain).

### Finding Description
`exchange_token` decodes the caller-supplied `session_token` via `JwtPayload.new(session_token)` [1](#0-0) . `JwtPayload#initialize` only verifies the HMAC signature (using the app's own `api_secret_key`) and that `aud == Context.api_key`; it does not validate that `dest` is a `*.myshopify.com` (or otherwise trusted) domain [2](#0-1) . `dest_shop` is then used directly to build `shop_session` and passed as the `Clients::HttpClient` base host, with the request body containing `client_id` and `client_secret` [3](#0-2) . Compare this to `migrate_to_expiring_token` in the same file, which sanitizes the shop via `Utils::ShopValidator.sanitize!(shop)` before constructing the session/host [4](#0-3) . `ShopValidator.sanitize!`/`sanitize_shop_domain` exist precisely to enforce that a shop string resolves to a `TRUSTED_SHOPIFY_DOMAINS` host [5](#0-4) , confirming this check is the documented, expected binding that `exchange_token` omits.

The critical point: this token is embedded-app "session token" (Shopify App Bridge JWT), and while its signature is verified using the app's own secret, **the `dest` claim's domain-format is never constrained**. A malicious or compromised host application that forwards a user-tampered/self-issued-looking `dest` value (or any code path where `session_token` originates from client-influenced JWT re-encoding using the app's secret obtained through other legitimate flows) results in the gem itself sending the app's `client_id`/`client_secret` to whatever host string appears after `https://` in `dest`, e.g., `dest: "https://attacker.example.com"`.

### Impact Explanation
This is classified as High — SSRF carrying the app's credentials (`client_id`/`client_secret` sent to an arbitrary host derived from unvalidated JWT claim data), matching the report's identity-binding-break pattern ("a host validated versus the host that receives the ... `client_secret`"). If reachable, this is a direct `client_secret` exfiltration vector to an attacker-controlled host.

### Likelihood Explanation
Likelihood is moderate: exploitation requires a `session_token` whose `dest` claim is not constrained to Shopify's domains to reach `exchange_token`. Since `JwtPayload` validates the JWT signature against `Context.api_secret_key`, a token must be validly signed — normally only Shopify issues such tokens with trusted `dest` values. However, the gem's own defense-in-depth check (`ShopValidator`) that exists for exactly this purpose in the sibling method is silently absent here, meaning any code path or future JWT issuance surface that doesn't independently constrain `dest` immediately becomes exploitable without any additional gem-side protection.

### Recommendation
In `exchange_token`, sanitize `dest_shop` through `Utils::ShopValidator.sanitize!(dest_shop)` (mirroring `migrate_to_expiring_token`) before constructing `shop_session` / issuing the HTTP request, raising `Errors::InvalidShopError` for any non-trusted domain.

### Proof of Concept
1. Obtain/construct a JWT session token that passes `JWT.decode` verification with the app's `api_secret_key` (e.g., via any legitimate token issuance path where `dest` is developer/test-configurable) with `dest: "https://attacker.example.com"` and `aud` matching `Context.api_key`.
2. Call `ShopifyAPI::Auth::TokenExchange.exchange_token(session_token: token, requested_token_type: ...)`.
3. `jwt_payload.shop` returns `"attacker.example.com"` unchecked [6](#0-5) .
4. `Clients::HttpClient.new(session: shop_session, base_path: "/admin/oauth")` issues a POST to `https://attacker.example.com/admin/oauth/access_token` with the app's `client_id` and `client_secret` in the body [7](#0-6) , exfiltrating the credential to the attacker's server.

        [
          "shopify.com",
          "myshopify.io",
          "myshopify.com",
          "spin.dev",
          "shop.dev",
        ].freeze,
        T::Array[String],

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end
