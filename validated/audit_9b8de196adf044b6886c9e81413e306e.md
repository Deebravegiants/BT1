**Analysis:**

The premise fails at the construction step. `module_write_set` in `UserSessionChangeSet` is populated exclusively by `convert_modules_into_write_ops`, which iterates only over `verified_module_bundle` (compiled module bytecode) and inserts entries keyed by `StateKey::module_id(&module_id)` [1](#0-0) . The resulting `ModuleWriteSet` map only ever contains module-code state keys [2](#0-1) .

Conversely, `change_set` (a `VMChangeSet`) holds `resource_write_set` entries for ordinary Move resources, including fungible asset primary stores, which are keyed via resource access paths, not module IDs [3](#0-2) . Module state keys are distinguished at the storage layer by `StateKeyInner::AccessPath` with `try_get_module_id()` succeeding, which is structurally distinct from a resource access path used for an FA store [4](#0-3) .

There is no unprivileged path that lets a fungible-asset primary-store write land in `module_write_set`: that structure is only ever built by staging and verifying an actual module bundle through `StagingModuleStorage`, subject to compatibility/cycle checks [5](#0-4) , not from arbitrary resource writes. Because the two write sets operate on structurally disjoint `StateKey` domains, `write_set_size_iter`'s `chain` in `session_change_sets.rs` (lines 47-51) [6](#0-5)  cannot in practice yield duplicate/overlapping keys between the two component iterators.

Even setting that aside, `check_change_set` only accumulates a byte total against `max_bytes_all_write_ops_per_transaction` to enforce a gas/storage limit [7](#0-6) ; it does not influence which `WriteOp` values are actually applied to state. A miscounted byte total would at most cause an incorrect accept/reject decision on the transaction as a whole — it cannot alter the materialized value of the FA store itself, since the write ops committed to storage come from the underlying `resource_write_set`/`ModuleWriteSet` maps, not from this size-accounting pass. This fails the custody impact gate, which requires the wrong balance/owner/authority to actually change, not a cosmetic or limit-check miscalculation.
