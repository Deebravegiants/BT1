### Title
Venue-priced Uniswap V4 pairs value fills off a manipulable `slot0`/`sqrtPriceX96` spot price with an optional, default-off deviation guard - ([File: sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts])

### Summary
Simplex's `UniswapV4FundingPlanner` prices "curveless" cross-asset pairs directly from a Uniswap V4 pool's current `sqrtPriceX96`/tick (`slot0`), exactly the class of oracle read flagged in the referenced report (`USSDRebalancer.getOwnValuation()` reading `slot0`). The only defense against a manipulated, thin, or stale pool is `checkPriceGuard`, which is **optional** and defaults to "pass every quote" when a chain has no configured `referencePrice`/`maxDeviationBps`.

### Finding Description
`UniswapV4LiquidityState.refresh()` fetches the pool's spot price/tick via `StateView.getSlot0()` [1](#0-0)  and rebuilds an SDK `V4Pool` object directly from that instantaneous `sqrtPriceX96`/`tick`, with no time-weighting whatsoever [2](#0-1) .

`UniswapV4FundingPlanner.getExoticTokenPrice`/`computeDirectPoolPriceUsd` then derives the USD price of the exotic token straight from `sdkPool.token0Price`/`token1Price` — i.e. the raw pool mid computed from that same spot `sqrtPriceX96` — with no TWAP, no fee-tier adjustment, and no size/impact term [3](#0-2) .

This price feeds `FXFiller.resolveLegRates`, which uses it as the fill rate for the leg whenever the pair is curveless and `token0` is a USD stable — the only check performed is `checkPriceGuard` [4](#0-3) . That guard is itself optional: it returns `true` (pass) unconditionally when no `priceGuard` entry exists for the chain, i.e. when `referencePrice`/`maxDeviationBps` were never configured [5](#0-4) . The project's own documentation confirms the guard is opt-in and the pool path is otherwise unguarded: *"Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote... The two fields must be set together; omit both to leave the chain unguarded."* [6](#0-5)  and an internal design note records that the derived mid ignores the pool's own fee tier and has no size/impact term at all [7](#0-6) .

The root cause mirrors the referenced report precisely: a price is derived from a single-block, single-transaction-manipulable AMM spot read (`slot0`/`sqrtPriceX96`) rather than a TWAP, and the only mitigation is a manually configured, non-mandatory deviation band.

### Impact Explanation
Any unprivileged actor able to move a configured pool's spot price within the same block (a flash-swap or a large one-sided swap immediately ahead of the solver's fill) directly controls the USD rate `FXFiller` uses to size and price the leg of an incoming intent order on any chain where `priceGuard` was not configured for that position (the default/unguarded state the docs explicitly describe). Since the pool mid is applied linearly across the whole notional with no fee/impact correction, a manipulated quote lets an attacker submit an order that the solver fills at an economically distorted rate — the solver either overpays in the exotic token (direct value drain from solver-held funds) or, on the reverse leg, a user is short-changed. This is the same "unauthorized/incorrect valuation leading to financial loss" impact class as the referenced USSD finding, just realized against solver-held liquidity instead of protocol reserves.

### Likelihood Explanation
Likelihood is real but conditioned on operator configuration: exploitation requires (a) a venue-priced (curveless) pair configured under `[vault.uniswapV4]`, and (b) that chain's position lacking `referencePrice`/`maxDeviationBps` — a state the documentation itself calls out as the default/"unguarded" outcome of `[vault.uniswapV4]` positions without the optional fields. Any operator who follows the minimal example in the docs (`pricing.mdx` lines 48-62, which omits the guard) ships in this exposed configuration. Manipulating a single pool's spot price for one block via a flash swap is a standard, low-cost, permissionless action requiring no privileged role.

### Recommendation
- Make the price guard (`referencePrice`/`maxDeviationBps`) mandatory whenever a chain has no bid/ask curves and relies purely on pool pricing, rather than optional-with-silent-pass-through.
- Replace or supplement the spot `slot0` read with a TWAP (e.g., Uniswap V4's truncated oracle/observations, or an external attested price) for `computeDirectPoolPriceUsd`.
- Apply the pool's fee tier and a size/impact term to the derived mid instead of extending the raw mid linearly across the full notional, closing the "swap-through-own-pool pays a fee it never quoted against" gap noted in `venue-pricing-uniswap-v4-funded-pairs.md`.

### Proof of Concept
1. Operator deploys `FXFiller` with a curveless `[[pairs]]` entry (`token0 = "USDC"`, `token1 = "CNGN"`) and a `[vault.uniswapV4]` position but omits `referencePrice`/`maxDeviationBps`, matching the documented minimal example.
2. Attacker executes a large one-sided swap against the configured Uniswap V4 pool in the block immediately preceding order submission, shifting `sqrtPriceX96` far from the pool's true equilibrium.
3. Attacker (or an accomplice) submits an intent order on the affected pair. `FXFiller.resolveLegRates` → `getVenueUsdPrice` → `UniswapV4FundingPlanner.getExoticTokenPrice` reads the manipulated `slot0` via `UniswapV4LiquidityState.refresh()` and returns the distorted mid; `checkPriceGuard` passes trivially because no guard is configured for the chain.
4. The solver fills the order at the distorted rate, transferring value out of its own Uniswap V4 position/wallet at a loss, after which the attacker reverses the price-moving swap, retaining the profit extracted from the solver.

```typescript
	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}

	/**
	 * Computes the USD price of the non-stable token in a pool.
	 * Returns null if neither currency is USDC/USDT on this chain.
	 */
	private computeDirectPoolPriceUsd(
		pos: HydratedV4Position,
		sdkPool: V4Pool,
		chain: string,
	): { exoticToken: string; priceUsd: Decimal } | null {
		const usdc = this.configService.getUsdcAsset(chain).toLowerCase()
		const usdt = this.configService.getUsdtAsset(chain).toLowerCase()
		const c0 = pos.currency0.toLowerCase()
		const c1 = pos.currency1.toLowerCase()

		if (c0 === usdc || c0 === usdt) {
			// currency0 is stable → exotic is currency1
			// token1Price = "token0 per token1" = USD per exotic
			return {
				exoticToken: c1,
				priceUsd: new Decimal(sdkPool.token1Price.toFixed(18)),
			}
		}

		if (c1 === usdc || c1 === usdt) {
			// currency1 is stable → exotic is currency0
			// token0Price = "token1 per token0" = USD per exotic
			return {
				exoticToken: c0,
				priceUsd: new Decimal(sdkPool.token0Price.toFixed(18)),
			}
		}

		return null
	}
```

```typescript
	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {
			this.logger.warn(
				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
	}
```

```typescript
		cappedPairNotional: Decimal,

		// with no curves at all (and never same-token pairs, where a venue quote
		// would just be the asset's own USD price, not a spread).
		const curveless = !leg.pair.bidPricePolicy && !leg.pair.askPricePolicy
		if (curveless && !isSameTokenPair(leg.pair) && USD_STABLE_SYMBOLS.has(normalizeSymbol(leg.pair.token0))) {

				// the venue-specific defense.
```

```text
## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.
```
