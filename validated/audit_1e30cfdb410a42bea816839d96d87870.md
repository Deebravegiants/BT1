### Title
Webhook shop-domain identity is not covered by HMAC verification, enabling cross-tenant webhook spoofing - (File: `lib/shopify_api/webhooks/request.rb`, `lib/shopify_api/webhooks/registry.rb`)

### Summary
`ShopifyAPI::Webhooks::Registry.process` authenticates an inbound webhook solely by validating the HMAC over the raw request body, then hands the *unauthenticated* `shop` header straight to the host application's handler as the tenant identity. Because the HMAC signature never covers the `shop` field, any party capable of producing one valid `(raw_body, hmac)` pair for *their own* shop can replay that pair to the webhook endpoint with an arbitrary `X-Shopify-Shop-Domain` header and have the library treat the payload as belonging to a different tenant.

### Finding Description
`Webhooks::Request#to_signable_string` returns only `@raw_body`: [1](#0-0) 

and `shop` is read from a separate, unsigned header: [2](#0-1) 

`HmacValidator.validate` therefore only proves that `@raw_body` was HMAC'd with the app's `api_secret_key` — it says nothing about which shop the body belongs to: [3](#0-2) 

`Registry.process` performs exactly that check and then forwards `request.shop` — never cross-checked against the signed content — directly to the app's webhook handler as the authoritative tenant identifier: [4](#0-3) 

This breaks the identity binding `authenticated(body) == shop_the_handler_acts_on`. The equality that should hold is:
`shop_bound_by_hmac == shop_used_for_tenant_routing`
but instead the library computes `shop_bound_by_hmac == ∅` (no shop is signed) while `shop_used_for_tenant_routing == request.shop` (an attacker-controlled header).

### Impact Explanation
An unprivileged internet user who has any legitimate access to the app (e.g., installs it on their own free/dev Shopify store) can trigger genuine webhook deliveries for their own store, capture the resulting `(raw_body, hmac)` pair, and replay it directly to the app's public webhook endpoint with a forged `X-Shopify-Shop-Domain`/`x-shopify-shop-domain` header naming a victim shop. `HmacValidator.validate` still returns `true` (it only checks the body), and `Registry.process` passes the forged shop into `WebhookMetadata`, which most host applications use to key writes/updates into per-tenant storage (orders, inventory, customer data, etc.) keyed by shop. This yields cross-tenant data injection/corruption attributed to a victim merchant's session — a cross-tenant access impact.

### Likelihood Explanation
Likelihood is high for any app that exposes its webhook endpoint publicly (as required by Shopify) and that trusts `WebhookMetadata#shop` for tenant routing, which is the documented and expected usage pattern shown in this gem's own test suite (`data.shop` used directly). No secrets, tokens, or privileged access are required — only the ability to install the app on any shop (including a free attacker-owned store) to obtain one valid signed body.

### Recommendation
Include the shop (and ideally topic/webhook-id) in the signable content used for HMAC validation, or explicitly cross-check `request.shop` against a shop known to have a stored/active session for this app before invoking the handler, rather than trusting the header purely because the body's HMAC validated.

### Proof of Concept
1. Attacker installs the target app on their own Shopify dev store `attacker.myshopify.com` and triggers a webhook (e.g., `orders/create`) that the app registers for.
2. Attacker captures the raw POST body and the `X-Shopify-Hmac-Sha256` header from that genuine delivery.
3. Attacker sends a new HTTP request directly to the app's public webhook URL, reusing the captured body and HMAC header unchanged, but sets `X-Shopify-Shop-Domain: victim-shop.myshopify.com`.
4. `ShopifyAPI::Webhooks::Request.new` parses the forged headers; `HmacValidator.validate` succeeds because it only checks `raw_body` against the HMAC.
5. `Registry.process` invokes the app's handler with `WebhookMetadata#shop == "victim-shop.myshopify.com"`, causing the host app to process attacker-supplied order/product data as if it belonged to the victim shop.
