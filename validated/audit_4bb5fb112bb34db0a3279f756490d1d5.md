### Title
Bad-debt socialization writes down the liquidity index using a stale (un-accrued) index/lindex snapshot, permanently destroying supplier interest - (File: `mainnet/contracts/vault/v0-vault-stx.clar`, similarly all `v0-vault-*.clar` and `local-testing/contracts/vault/vault-*.clar`)

### Summary
`socialize-debt` in every vault contract reads `index` and `lindex` directly from storage and uses them to compute the debt write-down and the new `lindex`, without first calling `accrue()` to bring those values up to date. `market.clar`'s `socialize-debt-asset` calls `vault-socialize-debt` (which invokes this unaccrued `socialize-debt`) and only calls `vault-accrue` *afterwards*, by which time `principal-scaled` has already been reduced. This causes interest that legitimately accrued to suppliers between the last accrual and the socialization event to be permanently lost, in the same pattern as the Zest analog of finding M-06 (a state transition that snapshots/writes-down an accumulator without first calling the update/accrual routine).

### Finding Description
Each vault's `socialize-debt` function [1](#0-0)  reads `idx` (`var-get index`) and `current-lindex` (`var-get lindex`) directly, computes `debt-reduction` and `old-total-assets` from these stale values, and writes a new `lindex` — all without calling `accrue`. Critically, it never updates `last-update`.

`market.clar`'s `socialize-debt-asset` helper [2](#0-1)  calls `vault-socialize-debt` first, and only refreshes the accrual cache with `vault-accrue` *after* the write-down has already mutated `principal-scaled`, `total-borrowed`, and `lindex`.

Because `last-update` was never advanced by `socialize-debt`, the subsequent `vault-accrue` call computes interest for the entire elapsed period (`stacks-block-time - last-update`) using the *post-write-down* (reduced) `principal-scaled`, instead of the correct (larger) pre-write-down principal that was actually outstanding for that period. Interest that legitimately accrued on the full principal between the last accrual and the moment of default is never credited to `lindex`/suppliers.

This is functionally identical to the M-06 report's root cause: a function that snapshots/writes an accumulator (`lastAccumulatedETHPerFreeFloatingShare` there; `lindex`/`index` here) into a "final" state without first calling the routine (`updateAccruedETHPerShares` there; `accrue` here) that would bring the accumulator current. In both cases, the omission causes legitimate reward/interest to be permanently under-recorded for good-faith unprivileged participants (Syndicate stakers there, vault suppliers here).

### Impact Explanation
Suppliers' liquidity index (`lindex`), which determines the redemption value of their zTokens, permanently fails to capture interest that was earned on the defaulted borrower's principal prior to the write-down. This is a loss of unclaimed yield for all zToken holders of that vault — value that should have accrued to the pooled supply-side interest never materializes and cannot be recovered by any subsequent transaction, since the accrual clock only measures forward from `last-update` using the already-reduced principal. Per the impact criteria, permanent loss of unclaimed yield for legitimate suppliers qualifies as High impact.

### Likelihood Explanation
This triggers on every bad-debt socialization event that is not preceded, within the same block, by a `vault-accrue` call on that asset via `accrue-and-cache` for an unrelated operation (deposit/borrow/repay/etc. touching the same vault in the same block). Since `socialize-debt-asset` unconditionally calls `vault-socialize-debt` before `vault-accrue`, the bug is deterministic for any bad-debt event that occurs when there is unaccrued interest pending (i.e., any time has elapsed since the vault's last accrual) — a very common condition in production, since accrual is lazy/on-demand rather than per-block.

### Recommendation
In `socialize-debt-asset` (`market.clar`), call `vault-accrue`/`accrue-and-cache` for the asset **before** invoking `vault-socialize-debt`, so `index`/`lindex` are current when the write-down proportion is computed, and `last-update` is advanced to the current timestamp prior to reducing `principal-scaled`. Equivalently, have the vault's `socialize-debt` internally call `accrue()` as its first step (mirroring the pattern used by `set-fee-reserve`, `set-points-util`, etc., which already do `(try! (accrue))` before mutating state) so the write-down is always computed against up-to-date indices.

### Proof of Concept
1. At time T0, vault has `principal-scaled = P`, `index = I0`, `lindex = L0`, `last-update = T0`, and total supplier value backed by `L0`.
2. No further vault interaction occurs (no deposit/borrow/repay/liquidate on other assets that would call `accrue-and-cache` for this vault) until T1, where a borrower default is discovered and `market.clar`'s bad-debt socialization flow is invoked for scaled amount `A` on this asset.
3. `socialize-debt-asset` calls `vault-socialize-debt(A)`, which runs `socialize-debt` [3](#0-2)  using the stale `idx = I0` and `lindex = L0` (not the true index `I1` that should apply at T1, since interest accrued between T0 and T1 is unrealized). `principal-scaled` is reduced to `P - A` but `last-update` remains `T0`.
4. `socialize-debt-asset` then calls `vault-accrue`, which computes `next-index` from `interest-rate() * (T1 - T0)` applied against the now-reduced `principal-scaled = P - A`, instead of the original `P` that was actually outstanding for the full T0→T1 interval.
5. Result: the interest portion attributable to `A` of principal for the interval [T0, T1] is never accrued into `lindex`/`index`/treasury; it silently disappears rather than being credited to suppliers (or even socialized as bad debt itself), permanently reducing the redemption value suppliers should have received.

Note: full verification that no other transaction in the same block triggers `accrue-and-cache` for this asset before the socialization call was not exhaustively traced across every code path (e.g., all callers of the batch/liquidation flow that leads into `socialize-debt-asset`); however, the core mechanism — `socialize-debt` never calling `accrue`, and `vault-accrue` being invoked only after the principal reduction — is directly confirmed in the cited code.

(define-public (socialize-debt (scaled-amount uint))
  (let ((scaled-principal (var-get principal-scaled))
        (borrowed (var-get total-borrowed))
        (idx (var-get index))
        (current-assets (var-get assets))
        (current-lindex (var-get lindex))
        (old-total-assets (total-assets))
        (debt-reduction (mul-div-down scaled-amount idx INDEX-PRECISION))
        (principal-reduction (if (> scaled-principal u0)
                                (mul-div-down scaled-amount borrowed scaled-principal)
                                u0))
        ;; Write down lindex proportionally to loss in total-assets
        (new-lindex (if (and (> old-total-assets u0) (> old-total-assets debt-reduction))
                       (mul-div-down current-lindex (- old-total-assets debt-reduction) old-total-assets)
                       u0)))

    (try! (check-caller-auth))
    (asserts! (> scaled-amount u0) ERR-AMOUNT-ZERO)

    (var-set lindex new-lindex)
    (var-set principal-scaled (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0))
    (var-set total-borrowed (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0))
    (var-set assets (if (> current-assets principal-reduction) (- current-assets principal-reduction) u0))

    (print {
      action: "socialize-debt",
      caller: contract-caller,
      data: {
        scaled-amount: scaled-amount,
        debt-reduction: debt-reduction,
        principal-reduction: principal-reduction,
        old-lindex: current-lindex,
        new-lindex: new-lindex,
        old-total-assets: old-total-assets,
        principal-scaled: (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0),
        total-borrowed: (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0),
        index: idx
      }
    })

    (ok true)))

(define-private (socialize-debt-asset
                (debt-entry { aid: uint, scaled: uint })
                (acc { borrower: principal, success: bool }))
  ;; Early return if previous socialization failed
  (if (not (get success acc))
      acc
      (let ((borrower (get borrower acc))
            (failed-status { borrower: borrower, success: false })
            (asset-id (get aid debt-entry))
            (scaled-debt (get scaled debt-entry)))

            ;; Socialize in vault - pass scaled directly to avoid rounding
            (unwrap! (vault-socialize-debt asset-id scaled-debt) failed-status)
            ;; Refresh cache with new indexes post-write-down (lindex decreased)
            (map-set index-cache
                     { timestamp: stacks-block-time, aid: asset-id }
                     (unwrap! (vault-accrue asset-id) failed-status))
            ;; Remove from obligation
            (unwrap! (contract-call? .v0-market-vault
                                      debt-remove-scaled
                                      borrower
                                      scaled-debt
                                      asset-id) failed-status)
          acc)
        ))
