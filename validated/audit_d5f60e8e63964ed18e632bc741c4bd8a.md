### Title
Permanent market freeze: unchecked i128 overflow in interest accrual bricks all exits once `borrowed × borrow_index` exceeds the RAY domain — (File: contracts/pool/src/interest.rs)

### Summary
Analog of CVE-2016-7054: a data path that is safe for small inputs crashes permanently once a value crosses an internal size limit. Every state-changing pool entrypoint (`supply`, `borrow`, `withdraw`, `repay`, `seize_positions`, `flash_loan`, `create_strategy`, `recapitalize`, `claim_revenue`) begins with `Cache::load` → `interest::global_sync`, which calls `accrue_step` to compute the interest on the whole `borrowed` share pool. That step values debt as `scaled_to_original(borrowed, borrow_index)` via `Ray::mul` → `mul_div_half_up`, which panics with `MathOverflow` (33) when the product does not fit `i128`. The overflow bound is a property of the market total, not of any single call, so once crossed no transaction can ever accrue the market again — the panic is not recoverable because `last_timestamp` is never advanced (`mark_accrued` runs only after the loop completes) and the index cap (`MAX_BORROW_INDEX_RAY` = 10^36) is applied per chunk inside `accrue_step`, i.e. after the overflowing multiplication.

### Finding Description
- `contracts/pool/src/interest.rs:20-33` `global_sync` loops `accrue_chunk` for all elapsed time before any mutation, and `accrue_chunk` (lines 39-53) unconditionally evaluates `accrue_step` over `cache.borrowed()` and `cache.borrow_index()`. [1](#0-0) 
- `accrue_step` (common/src/rates) computes `scaled_to_original` on the aggregate `borrowed`; `common/src/rates/scaling.rs:14-16` maps that to `Ray::mul`, which panics `MathOverflow` on an unrepresentable `i128` result (`common/src/math/fp.rs:50-52`, `docs/reference/errors.md:31`). [2](#0-1) 
- `docs/reference/formulas.md:426-437` confirms the gap: caps bound only the *admitted* token amount (`i128::MAX / 10^(27-d)` ≈ 170 billion whole tokens), while accrued market value can independently exceed `i128` before the index ceiling engages, at which point "repayment/withdrawal ... accrue first" and block. [3](#0-2) 
- The in-repo harness test `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-361` demonstrates the failure end-to-end: a large 18-decimal market at ~98% utilization compounds until `update_indexes`, `withdraw`, and `repay` all revert with `MathOverflow` while `borrow_index < MAX_BORROW_INDEX_RAY`. [4](#0-3) 
- Reachability is fully unprivileged: `controller::supply`/`borrow` grow `borrowed`, `controller::update_indexes` is declared permissionless keeper maintenance (`scripts/permissionless_entrypoints.txt:74`), and time does the rest. [5](#0-4) 

### Impact Explanation
Permanent freezing of funds for every supplier and borrower of that hub asset: `withdraw`, `repay`, `liquidate` (which routes through pool `repay`/`withdraw` and `seize_positions`), `clean_bad_debt`, and even governance `recapitalize`/`claim_revenue` all enter through `global_sync` and hit the same panic. Supplied cash and outstanding debt in the pool become unrecoverable; the market cannot be unwound because the only accrual path is the one that overflows.

### Likelihood Explanation
Requires a very large market (order of 10^11 whole tokens at 18 decimals, smaller at fewer effective bits once the index has grown) sustained at high utilization for multiple compound windows — capital-intensive and slow, but it needs no privilege, no oracle manipulation, and no admin mistake; ordinary whale supply plus near-max utilization on a steep rate curve suffices, and nothing in the entry path detects or caps the approach (no ceiling alarm exists, per the docs).

### Recommendation
Make accrual fail-safe instead of all-or-nothing: e.g. clamp the borrow index inside `accrue_chunk` to the largest index whose `scaled_to_original(borrowed, index)` still fits `i128` (binary-search or analytic bound), saturate interest at that point like the existing `MAX_BORROW_INDEX_RAY` cap does, or compute debt interest with `I256` intermediates and saturate the booked values. At minimum, gate `supply`/`borrow` growth so `borrowed × MAX_BORROW_INDEX_RAY` provably stays within `i128`, turning the cliff into a cap rejection rather than a permanent trap.

### Proof of Concept
Already encoded as an in-repo regression scenario in `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-361`: supply `10^9 × 10^18` of an 18-decimal asset, borrow ~98% of it on the steep XLM curve with `max_utilization` disabled, then advance time in one-year steps calling the permissionless `update_indexes`. Within the tested horizon `try_update_indexes_for` returns `MathOverflow`; afterwards `try_withdraw_raw(BOB, "BIG18", 1)` and `try_repay(ALICE, "BIG18", 1.0)` both revert with `MathOverflow`, while `borrow_index` remains below `MAX_BORROW_INDEX_RAY` — proving the cap cannot rescue the market and all funds are frozen.

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}

fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
}
