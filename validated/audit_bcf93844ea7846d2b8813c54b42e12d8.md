### Title
Uniswap V4 venue pricing derives the exotic-token USD rate directly from live pool `slot0`/`sqrtPriceX96`, making Simplex FXFiller fills manipulable with a flash-loan swap - (File: sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts)

### Summary
`UniswapV4FundingPlanner.getExoticTokenPrice` / `computeDirectPoolPriceUsd`, used by the Simplex `FXFiller` intent solver to price "venue" (curveless) pairs, derives the exotic token's USD price straight from the Uniswap V4 pool's current spot price (`sqrtPriceX96` read via `slot0`/`StateView.getSlot0`). This is the same bug class as the referenced report: a spot price read from a single block is used, with no TWAP, so it is directly manipulable by a flash-loan swap against thin pool liquidity immediately before an order is quoted/filled.

### Finding Description
When a Simplex trading pair has no bid/ask curve configured (curveless "venue" pricing), `resolveLegRates` prices the exotic leg through `venuePriceMemo()` → `getVenueUsdPrice()` → `UniswapV4FundingPlanner.getExoticTokenPrice()`: [1](#0-0) 

`getExoticTokenPrice` picks the pool position with the highest liquidity and prices it through `computeDirectPoolPriceUsd`, which reads the raw `token0Price`/`token1Price` off the SDK `Pool` object — values derived directly from the pool's current `sqrtPriceX96`: [2](#0-1) 

The `sqrtPriceX96` itself is a single, un-TWAP'd spot read of `slot0` (via `StateView.getSlot0`) performed immediately before pricing/planning, refreshed synchronously right before use: [3](#0-2) 

This is explicitly acknowledged in the project's own documentation of the flow: the pool's raw mid, with no size/impact term, is the price used, and it is trusted directly: [4](#0-3) [5](#0-4) 

The only defense is an *optional* `checkPriceGuard`, which compares the live venue quote against a static `referencePrice` within `maxDeviationBps`: [6](#0-5) 

This guard must be explicitly configured per chain/position (`referencePrice` + `maxDeviationBps` set together), and is otherwise absent entirely: [7](#0-6) 

Even when configured, the guard only rejects quotes that deviate from a *static* reference by more than a fixed bps band — an attacker can still manipulate the spot price within that band (or, more directly, on any unguarded chain/pair) to shift the effective fill price in their favor for the exact transaction that fills the order, since the price is re-read live at fill time from the same pool the attacker just swapped against.

### Impact Explanation
An unprivileged user places a cross-chain intent (order) that a Simplex solver fills against a curveless, Uniswap V4 venue-priced pair. By flash-loan-swapping through the referenced (and possibly thin) V4 pool immediately before/around the fill transaction, an attacker can skew `sqrtPriceX96` and thus the USD price the solver uses to size its payout for that leg. Because `computeLegPolicyOutput` linearly extends this manipulated mid price across the entire quantity with no size/impact adjustment, the solver can be made to release more of the exotic (or stable) token than the pool's true depth-adjusted value warrants — a direct loss of solver funds analogous to the original USSD rebalancer manipulation causing a mispriced collateral/valuation action.

### Likelihood Explanation
Likelihood depends on operator configuration: if a `[vault.uniswapV4]` position has no `referencePrice`/`maxDeviationBps` guard set, the pricing path is fully unguarded and manipulation is trivial for any attacker capable of a flash loan against the referenced pool. Even guarded pools remain exposed within the configured deviation band, and are exposed to stale reference drift over time. Pool-based venue pricing is an explicitly documented, first-class feature (not a hidden edge case), so any solver operator who configures a low-liquidity Uniswap V4 position for an exotic asset is at risk.

### Recommendation
Do not price fills solely from `slot0`'s instantaneous `sqrtPriceX96`. Use a time-weighted average price (TWAP) derived from the pool's oracle observations (or an external oracle) for `computeDirectPoolPriceUsd`, and/or make the `referencePrice`/`maxDeviationBps` price guard mandatory (not optional) for every Uniswap V4-funded venue pair, with the reference kept fresh via a trusted external feed rather than a static config value.

### Proof of Concept
1. Configure an FXFiller pair with no bid/ask curve (`[vault.uniswapV4]` venue pricing) for a low-liquidity exotic/USD Uniswap V4 pool, and do not set `referencePrice`/`maxDeviationBps` (allowed per `docs/content/developers/evm/simplex/pricing.mdx` lines 64-66, "omit both to leave the chain unguarded").
2. Attacker takes a flash loan and swaps a large amount through the referenced V4 pool, shifting `sqrtPriceX96` far from its pre-swap value.
3. Attacker (or an accomplice) submits/triggers an intent order priced against that pair; `resolveLegRates` → `getVenueUsdPrice` → `UniswapV4FundingPlanner.getExoticTokenPrice` re-reads the manipulated `slot0` at fill time (`UniswapV4LiquidityState.refresh`, lines 139-170) and returns the skewed price.
4. `computeLegPolicyOutput` linearly extends this skewed mid across the whole leg notional, causing the solver to release an incorrect (attacker-favorable) amount of tokens.
5. Attacker reverses the flash-loan swap in the same transaction bundle, keeping the pool price restored and pocketing the mispriced solver payout, net of flash-loan and swap fees.

	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}

	private computeDirectPoolPriceUsd(
		pos: HydratedV4Position,
		sdkPool: V4Pool,
		chain: string,
	): { exoticToken: string; priceUsd: Decimal } | null {
		const usdc = this.configService.getUsdcAsset(chain).toLowerCase()
		const usdt = this.configService.getUsdtAsset(chain).toLowerCase()
		const c0 = pos.currency0.toLowerCase()
		const c1 = pos.currency1.toLowerCase()

		if (c0 === usdc || c0 === usdt) {
			// currency0 is stable → exotic is currency1
			// token1Price = "token0 per token1" = USD per exotic
			return {
				exoticToken: c1,
				priceUsd: new Decimal(sdkPool.token1Price.toFixed(18)),
			}
		}

		if (c1 === usdc || c1 === usdt) {
			// currency1 is stable → exotic is currency0
			// token0Price = "token1 per token0" = USD per exotic
			return {
				exoticToken: c0,
				priceUsd: new Decimal(sdkPool.token0Price.toFixed(18)),
			}
		}

		return null
	}

## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.

```toml lineNumbers
[vault.uniswapV4]
# referencePrice is the expected cNGN per USD;
# reject if the quote is more than 2% off.
# The two go together — one without the other is rejected.
[[vault.uniswapV4.positions]]
chain           = "EVM-8453"
tokenId         = "2087350"
referencePrice  = "1575"
maxDeviationBps = 200

	/**
	 * Validates a live venue quote against the static reference price for the chain.
	 * Returns true (pass) when no guard is configured, or no reference exists for the
	 * chain. Returns false when the quote (token1 per USD) deviates from the reference
	 * by more than `maxDeviationBps`, in which case the order must not be filled.
	 */
	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {
			this.logger.warn(
				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
	}
