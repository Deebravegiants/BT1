Audit Report

## Title
Unauthenticated `requestID` collision allows censorship of a specific confidential-relay request — (File: `core/services/gateway/handlers/confidentialrelay/handler.go`)

## Summary
The `confidentialrelay` gateway handler's `HandleJSONRPCUserMessage` registers in-flight requests keyed solely on the caller-supplied `req.ID` string via `newActiveRequest`, before any authorization, attestation, or owner-binding occurs. Because dedup happens at the gateway entry point — prior to and independent of the downstream node-side `verifyWorkflowAuthorization`/attestation checks in `core/capabilities/confidentialrelay/handler.go` — any unauthenticated caller who submits a request with a given `req.ID` first occupies that slot and causes the legitimate submitter's request with the same ID to be rejected outright.

## Finding Description
`HandleJSONRPCUserMessage` calls `h.newActiveRequest(req, labels, callback)` immediately, which takes a lock and checks `h.activeRequests[req.ID] != nil` before returning an error if occupied: [1](#0-0) . The map is keyed verbatim on `req.ID`, with no owner/identity prefix: [2](#0-1) .

This is confirmed by `TestConfidentialRelayHandler_DuplicateRequestID`, which shows a second request with an identical ID fails with `"request ID already exists"` regardless of caller identity: [3](#0-2) .

Critically, the gateway's public HTTP entrypoint (`gateway.ProcessRequest`) dispatches straight to `h.HandleJSONRPCUserMessage` with no caller-level authentication gate before this dedup check — that responsibility is delegated entirely to each handler: [4](#0-3) . The `confidentialrelay` handler itself performs no authorization inside `HandleJSONRPCUserMessage`; the actual attestation and Workflow-DON-quorum authorization (`verifyWorkflowAuthorization`) only happens later, at the node's own `core/capabilities/confidentialrelay/handler.go`, not at the gateway's bookkeeping layer: [5](#0-4) .

This is a materially different design from the sibling `vault` gateway handler, which authorizes first and only afterward computes a `prefixedRequestID` bound to the `authorizedOwner` before using it as the dedup key: [6](#0-5) . The vault handler's `newActiveRequest` collision check therefore only fires within an authorized owner's namespace, not across arbitrary unauthenticated callers: [7](#0-6) . The `confidentialrelay` handler has no equivalent step.

## Impact Explanation
Any network caller able to reach the gateway's public JSON-RPC endpoint can submit `MethodCapabilityExec`/`MethodSecretsGet` requests with an arbitrary or guessed/observed `req.ID` before the legitimate request arrives, occupying the gateway's `activeRequests` slot. The legitimate, properly-attested request is then rejected at the gateway with `"request ID already exists"` — the attacker's unauthenticated request never needs to pass the downstream attestation/Workflow-DON quorum check because it's the gateway's own registration step, not the node-level authorization, that blocks the victim. This is a targeted denial-of-service/censorship of a specific workflow execution's confidential relay operation, achievable without any valid attestation or DON signature.

## Likelihood Explanation
Exploitability depends on the attacker knowing or predicting a target's specific `req.ID` in advance and winning the race to submit it first — the report itself rates this "moderate" likelihood, and nothing in the reviewed code binds or randomizes this ID at the gateway to prevent a race. This mirrors the acknowledged risk profile of the analogous vault handler bug that was already fixed via owner-prefixing.

## Recommendation
Apply the same mitigation pattern already used by the vault gateway handler: perform authorization/attestation checks (or at minimum bind to a stable, hard-to-guess identity/session token) before registering the request in `activeRequests`, and scope the dedup key to that authenticated identity (e.g., prefixing `req.ID` with an owner/session-derived value) rather than trusting the raw caller-supplied ID alone.

## Proof of Concept
1. Attacker observes/predicts a target's upcoming `req.ID` value `X`.
2. Attacker POSTs a JSON-RPC request `{ID: X, Method: MethodCapabilityExec, ...}` to the gateway's public HTTP endpoint before the legitimate request arrives.
3. `HandleJSONRPCUserMessage` → `newActiveRequest` succeeds for the attacker, storing `X` in `h.activeRequests` — reachable via `gateway.ProcessRequest` with no upstream authentication gate.
4. The legitimate request with `ID: X` arrives; `newActiveRequest` returns `"request ID already exists: X"`, matching `TestConfidentialRelayHandler_DuplicateRequestID`.

func (p *GatewayVaultRequestProcessor) authorizeAndStamp(
	ctx context.Context,
	req *jsonrpc.Request[json.RawMessage],
	stamp func(prefixedRequestID string) error,
) (*AuthorizedGatewayVaultRequest, error) {
	incomingOwner := ""
	if idx := strings.Index(req.ID, vaulttypes.RequestIDSeparator); idx != -1 {
		incomingOwner = req.ID[:idx]
	}

	p.lggr.Debugw("authorizing gateway vault request", "method", req.Method, "requestID", req.ID)
	authResult, err := p.authorizer.AuthorizeRequest(ctx, *req)
	if err != nil {
		authErr := fmt.Errorf("request not authorized: %w", err)
		p.lggr.Errorw("gateway vault request authorization failed", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "", "incomingOwner", incomingOwner, "error", authErr)
		return nil, authErr
	}

	originalRequestID := req.ID
	authorizedOwner := authResult.AuthorizedOwner()
	prefixedRequestID := authorizedOwner + vaulttypes.RequestIDSeparator + originalRequestID
	req.ID = prefixedRequestID

	if err := stamp(prefixedRequestID); err != nil {
		p.lggr.Errorw("failed to stamp authorized request params", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, fmt.Errorf("failed to stamp authorized request params: %w", err)
	}

	p.lggr.Debugw("authorized gateway vault request", "method", req.Method, "requestID", req.ID, "owner", authorizedOwner, "orgID", authResult.OrgID(), "workflowOwner", authResult.WorkflowOwner())
	return &AuthorizedGatewayVaultRequest{
		Req:        *req,
		AuthResult: authResult,
	}, nil
}
