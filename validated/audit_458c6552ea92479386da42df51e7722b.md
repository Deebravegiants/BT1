### Title
JWT replay-guard check-then-act race allows single-use JWT to authorize multiple concurrent workflow executions - (File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go)

### Summary
The Sherlock report's root cause is an incorrect assumption about shared mutable state (the oracle assumes index 0 always holds the oldest observation) that a security-relevant check relies on without verifying the actual state at the time of use, producing an inconsistent/unsafe result. The closest unprivileged-actor analog in this repo is `WorkflowMetadataHandler.Authorize`, which relies on an implicit "the JTI is not yet used" assumption checked via `isReplay` and asserted via `recordUsage`, but does not hold a single lock across the whole read-check-write sequence, so the assumption can be stale by the time it's acted upon.

### Finding Description
`Authorize` is the JWT-based authentication path for inbound HTTP trigger requests handled by the gateway on behalf of unprivileged clients (`core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go` calls it, per the `Authorize(` grep result). The replay protection is implemented as: [1](#0-0) 

- `isReplay(claims.ID)` takes an `RLock`, checks map membership, and releases the lock immediately: [2](#0-1) 
- `recordUsage(claims.ID)` takes a separate `Lock` only after JWT verification, workflow lookup, and key-authorization checks succeed: [3](#0-2) 

Between the `isReplay` check (line 87) and the `recordUsage` call (line 105), the code performs signature verification and map lookups but does not hold any lock protecting the JTI's "unused" state. If two requests carrying the identical signed JWT (same `claims.ID`) arrive concurrently, both can pass `isReplay` (both see "not yet recorded") before either calls `recordUsage`, exactly analogous to the Oracle bug's flawed assumption that a single indicator (`initialized` flag / index 0) reliably reflects the true state of the data structure at the moment it's consulted.

### Impact Explanation
This breaks the single-use guarantee of the JWT, which is the mechanism that prevents replay of a captured/leaked signed request. An attacker (or a legitimate client whose JWT is intercepted, e.g., over a compromised link or via logs) can send the exact same signed authorization concurrently multiple times and get multiple workflow executions authorized off a token intended to be used exactly once. Given `HTTPTriggerHandler` fans requests out to DON members and executes workflows, this is a request-impersonation-adjacent replay bypass of an authentication control, matching the "concrete authentication bypass" acceptance criterion.

### Likelihood Explanation
Exploitability requires the attacker to already possess a validly signed JWT for a request (same as any replay attack precondition), and then to race two copies of it in quick succession — a purely client-side, unprivileged action requiring no special network position beyond what any replay attacker already needs. The window is small (µs-scale, bounded by JWT verification + map lookup time) but is real under concurrent request handling that gateways are built to support; likelihood is Low-to-Medium given the tight race window, but the check-then-act flaw is deterministic in design, not probabilistic in existence.

### Recommendation
Make the check-and-record operation atomic: acquire a single `Lock` (not `RLock`) for the entire "check + mark used" sequence in `Authorize`, e.g., have `jwtReplayCache` expose a single `CheckAndRecord(jti string) bool` method (mirroring the pattern already used correctly in `core/capabilities/vault/request_replay_guard.go`'s `CheckAndRecord`, which combines lookup and insertion under one `mu.Lock()`) and use it instead of the separate `isReplay`/`recordUsage` calls. [4](#0-3) 

### Proof of Concept
1. Attacker obtains a validly signed JWT for a `workflow.execute` request (e.g., from a captured request, or is the legitimate token holder attempting to double-spend it).
2. Attacker fires two concurrent HTTP trigger requests to the gateway carrying the identical JWT (`Auth` field / token string), targeting `HTTPTriggerHandler.HandleUserTriggerRequest`, which calls `WorkflowMetadataHandler.Authorize`.
3. Goroutine A: calls `isReplay(claims.ID)` → false (not yet seen) → proceeds to verify signer/workflow authorization.
4. Goroutine B (concurrently, before A reaches line 105): calls `isReplay(claims.ID)` → also false → proceeds identically.
5. Both goroutines pass authorization and both call `recordUsage`; both requests are dispatched to the DON and executed, i.e., the single-use JWT authorized two workflow executions instead of one.

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}

func (cache *jwtReplayCache) isReplay(jti string) bool {
	cache.mu.RLock()
	defer cache.mu.RUnlock()

	_, exists := cache.cache[jti]
	return exists
}

func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}
