Confirmed: `loggerFunc` is registered globally via `engine.Use(...)` in `NewRouter`, applying to all routes including `/query` (GraphQL), and the GraphQL `updateUserPassword` mutation carries `oldPassword`/`newPassword` nested inside a `variables.input` object rather than at the top level of the JSON body.

### Title
Plaintext password disclosure in Debug web-request logs via GraphQL mutation body (nested JSON not redacted) - (File: core/web/router.go)

### Summary
The chainlink node's HTTP request logging middleware (`loggerFunc`) logs every request body at Debug level after attempting to redact sensitive fields via `readSanitizedJSON`/`isBlacklisted`. This redaction only inspects the **top-level keys** of the JSON body. GraphQL requests (`POST /query`) wrap all mutation arguments inside a nested `variables.input` object (e.g. for `updateUserPassword`, `createAPIToken`), so `oldPassword`/`newPassword`/`password` fields are never at the top level and are therefore never matched by `isBlacklisted`, causing them to be written to the application's Debug logs in plaintext — directly analogous to CVE-2020-24804's plaintext-password-in-audit-log issue.

### Finding Description
`loggerFunc` in [1](#0-0)  buffers the raw request body and logs it at Debug level using `readBody`, which calls `readSanitizedJSON`: [2](#0-1) 

`readSanitizedJSON` unmarshals the body into `map[string]any` and only redacts keys found at that top level:
```go
for k, v := range dst {
    if isBlacklisted(k) {
        cleaned[k] = "*REDACTED*"
        continue
    }
    cleaned[k] = v
}
``` [3](#0-2) 

This middleware is installed globally, before routing, via `engine.Use(...)`, and therefore also wraps the GraphQL endpoint `POST /query`: [4](#0-3) 

GraphQL requests are always shaped as `{"query": "...", "variables": {...}}`. Password-bearing mutations place the sensitive fields inside `variables.input`, e.g. `UpdateUserPassword(args struct{ Input UpdatePasswordInput })` handling `OldPassword`/`NewPassword`, and `CreateAPIToken(args struct{ Input struct{ Password string } })`: [5](#0-4) [6](#0-5) 

Because `dst` in `readSanitizedJSON` is only walked one level deep (`query`, `variables` top-level keys — neither of which is blacklisted), the entire `variables` object, including nested `oldPassword`/`newPassword`/`password` strings, is logged verbatim in the "body" field of the Debug log line produced by `loggerFunc`. The equivalent REST-style endpoint `POST /v2/user/token` (`NewAPIToken`) is correctly protected because its `password` field sits at the JSON top level and matches the blacklist substring check in `isBlacklisted`: [7](#0-6) [8](#0-7) 

but the GraphQL path bypasses this protection entirely due to nesting.

### Impact Explanation
Any authenticated node user (even a low-privileged one, e.g. `view`/`run`/`edit` role) invoking `updateUserPassword` or `createAPIToken` over GraphQL causes their own current and new plaintext passwords to be written into the node's Debug-level web request logs. Anyone with read access to those logs (log aggregation systems, operators, support staff, or other tenants of a shared logging pipeline) can recover the plaintext password and escalate by authenticating as that user or another admin who happened to change their password through GraphQL, matching the "secret disclosure via logs" bug class from CVE-2020-24804.

### Likelihood Explanation
Requires only that: (1) the node is running with Debug-level logging (a supported, commonly enabled configuration, not a rare/operator-only mode), and (2) any already-authenticated user calls the standard, documented `updateUserPassword` or `createAPIToken` GraphQL mutation — both are core, expected UI operations (e.g. changing your own password from the Operator UI settings page), making the trigger path trivial and unprivileged.

### Recommendation
Make `readSanitizedJSON`/`isBlacklisted` recurse into nested maps/arrays (not just top-level keys) so that any key matching the password/secret blacklist is redacted regardless of nesting depth — this will correctly cover GraphQL's `variables.input.*` shape as well as any other nested JSON payloads.

### Proof of Concept
1. Run the node with Debug logging enabled.
2. As any authenticated user, send:
```
POST /query
{"query":"mutation($input: UpdatePasswordInput!){ updateUserPassword(input:$input){ user { email } } }",
 "variables":{"input":{"oldPassword":"CurrentSecret123","newPassword":"NewSecret456"}}}
```
3. Inspect the node's Debug logs — the `body` field of the log line emitted by `loggerFunc` for this request will contain `"oldPassword":"CurrentSecret123","newPassword":"NewSecret456"` in cleartext, unlike the equivalent REST call to `/v2/user/token`, whose `password` field is correctly replaced with `*REDACTED*`.

func loggerFunc(lggr logger.Logger) gin.HandlerFunc {
	return func(c *gin.Context) {
		buf, err := io.ReadAll(c.Request.Body)
		if err != nil {
			lggr.Error("Web request log error: ", err.Error())
			// Implicitly relies on limits.RequestSizeLimiter
			// overriding of c.Request.Body to abort gin's Context
			// inside io.ReadAll.
			// Functions as we would like, but horrible from an architecture
			// and design pattern perspective.
			if !c.IsAborted() {
				c.AbortWithStatus(http.StatusBadRequest)
			}
			return
		}
		rdr := bytes.NewBuffer(buf)
		c.Request.Body = io.NopCloser(bytes.NewBuffer(buf))

		start := time.Now()
		c.Next()
		end := time.Now()

		lggr.Debugw(fmt.Sprintf("%s %s", c.Request.Method, c.Request.URL.Path),
			"method", c.Request.Method,
			"status", c.Writer.Status(),
			"path", c.Request.URL.Path,
			"ginPath", c.FullPath(),
			"query", redact(c.Request.URL.Query()),
			"body", readBody(rdr, lggr),
			"clientIP", c.ClientIP(),
			"errors", c.Errors.String(),
			"servedAt", end.Format("2006-01-02 15:04:05"),
			"latency", fmt.Sprintf("%v", end.Sub(start)),
		)
	}

func readSanitizedJSON(buf *bytes.Buffer) (string, error) {
	var dst map[string]any
	err := json.Unmarshal(buf.Bytes(), &dst)
	if err != nil {
		return "", err
	}

	cleaned := map[string]any{}
	for k, v := range dst {
		if isBlacklisted(k) {
			cleaned[k] = "*REDACTED*"
			continue
		}
		cleaned[k] = v
	}

	b, err := json.Marshal(cleaned)
	if err != nil {
		return "", err
	}
	return string(b), err
}

var blacklist = map[string]struct{}{
	"password":             {},
	"newpassword":          {},
	"oldpassword":          {},
	"current_password":     {},
	"new_account_password": {},
}

func isBlacklisted(k string) bool {
	lk := strings.ToLower(k)
	if _, ok := blacklist[lk]; ok || strings.Contains(lk, "password") {
		return true
	}
	return false
}

// NewAPIToken generates a new API token for a user overwriting any pre-existing one set.
func (u *UserController) NewAPIToken(c *gin.Context) {
	ctx := c.Request.Context()
	var request clsession.ChangeAuthTokenRequest
	if err := c.ShouldBindJSON(&request); err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	sessionUser, ok := webauth.GetAuthenticatedUser(c)
	if !ok {
		jsonAPIError(c, http.StatusInternalServerError, errors.New("failed to obtain current user from context"))
		return
	}
	user, err := u.App.AuthenticationProvider().FindUser(ctx, sessionUser.Email)
	if err != nil {
		if errors.Is(err, clsession.ErrNotSupported) {
			jsonAPIError(c, http.StatusBadRequest, errUnsupportedForAuth)
			return
		}
		u.App.GetLogger().Errorf("failed to obtain current user record: %s", err)
		jsonAPIError(c, http.StatusInternalServerError, errors.New("unable to create API token"))
		return
	}
	// In order to create an API token, login validation with provided password must succeed
	err = u.App.AuthenticationProvider().TestPassword(ctx, sessionUser.Email, request.Password)
	if err != nil {
		u.App.GetAuditLogger().Audit(audit.APITokenCreateAttemptPasswordMismatch, map[string]any{"user": user.Email})
		jsonAPIError(c, http.StatusUnauthorized, errors.New("incorrect password"))
		return
	}
