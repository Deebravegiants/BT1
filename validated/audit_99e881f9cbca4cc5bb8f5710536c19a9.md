### Title
Market accrual can permanently freeze a market when scaled debt value overflows before the borrow-index cap - (File: common/src/rates/simulate.rs)

### Summary
`update_indexes` is permissionless and calls the pool’s accrual path for each requested market. During each accrual step, `accrue_step` converts the stored scaled borrow balance to its original asset value before updating the borrow index. [1](#0-0) 

At sufficiently high sustained utilization, the borrow index can keep growing while `scaled_debt * borrow_index` exceeds `i128::MAX`. The multiplication then panics before `update_borrow_index` can apply the market’s index ceiling. [2](#0-1)  The repository’s own boundary test demonstrates that the index remains below `MAX_BORROW_INDEX_RAY` while `scaled_to_original` raises `MathOverflow`, after which withdrawal and repayment also fail because they accrue first. [3](#0-2) 

### Finding Description
The pool divides long accrual periods into bounded chunks in `global_sync`, but every chunk begins by evaluating `accrue_step`. [4](#0-3) 

`accrue_step` computes `borrowed_original` with:

```rust
let borrowed_original = scaled_to_original(env, borrowed, borrow_index);
```

This occurs before `update_borrow_index` returns the capped index. [2](#0-1) 

The domain invariant is therefore incomplete: capping the index does not guarantee that the product `borrowed_scaled * borrow_index` remains representable as an `i128`. Once stored scaled debt and the accrued index exceed the value domain, every subsequent accrual fails at the same conversion. The `update_indexes` controller entrypoint is permissionless and forwards the attacker-selected market list to the pool’s `accrue` implementation, which loads each market and invokes `global_sync`. [5](#0-4) [6](#0-5) 

Because normal market operations synchronize the same market before mutating it, the overflow is not confined to `update_indexes`: it also blocks repayment, withdrawal, borrowing, liquidation, and other paths that accrue the affected market.

### Impact Explanation
Permanent freezing of user funds in the affected market.

Once the scaled-debt/index product crosses the `i128` domain, any operation that first accrues the market panics. The regression test demonstrates the resulting state explicitly: `update_indexes` fails with `MathOverflow`, `withdraw` fails with the same error, and `repay` fails with the same error while the stored borrow index is still below the intended index cap. [7](#0-6) 

Suppliers cannot withdraw, borrowers cannot repay, and liquidators cannot clear the debt through ordinary unprivileged flows. The condition is self-reinforcing because every later operation begins by attempting the same overflowing accrual.

### Likelihood Explanation
Medium likelihood: the path requires an extreme market scale and sustained high utilization, but it does not require privileged access or a third-party failure.

The demonstrated condition requires scaled borrow exposure large enough that even a borrow index below the configured ceiling makes `borrowed * borrow_index / RAY` exceed `i128::MAX`. The test constructs approximately one billion 18-decimal tokens at 98% utilization and waits for the index to grow beyond the value ceiling. [8](#0-7) 

An unprivileged caller can then submit `Controller::update_indexes(caller, vec![affected_hub_asset])`. The triggering call itself is permissionless and requires only caller authorization, while the precondition can arise from normal supply and borrow usage rather than from malformed input. [5](#0-4) 

### Recommendation
Bound the scaled-debt value before unscaling it, rather than relying on the borrow-index cap to imply a safe product.

At minimum:

1. In `accrue_step`, check `borrowed` against `i128::MAX / borrow_index.raw()` before calling `scaled_to_original`.
2. When the product would overflow, clamp the accrual input to the largest representable debt value or use a wider intermediate representation before division.
3. Apply the `MAX_BORROW_INDEX_RAY` cap before recomputing `borrowed_original`, or split the calculation so the index cap is enforced before an unrepresentable intermediate is evaluated.
4. Add the same preflight for `supplied * supply_index`, since the function also computes `supplied_original` before utilization. [9](#0-8) 
5. Add a regression test asserting that after the extreme-utilization scenario, `update_indexes`, `repay`, and `withdraw` either succeed or fail through a bounded market halt that does not permanently trap every later accrual.

### Proof of Concept
1. Create a high-decimal market and configure enough collateral and caps to borrow at sustained high utilization.
2. Supply a scaled-debt balance large enough that `scaled_debt * MAX_BORROW_INDEX_RAY` exceeds `i128::MAX`.
3. Maintain high utilization so accrual increases `borrow_index`.
4. Call:

```text
Controller::update_indexes(
    caller = any unprivileged address,
    assets = vec![affected_hub_asset],
)
```

The controller forwards the request to `Pool::accrue`, which loads the market and calls `interest::global_sync`. [6](#0-5) 

`global_sync` calls `accrue_step`; `accrue_step` evaluates `scaled_to_original(borrowed, borrow_index)` and panics when the product exceeds `i128`. [10](#0-9) [2](#0-1) 

The repository test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` reproduces the full state transition and confirms the permanent freeze: `try_update_indexes_for`, `try_withdraw_raw`, and `try_repay` all return `MATH_OVERFLOW`, while the stored borrow index remains below `MAX_BORROW_INDEX_RAY`. [11](#0-10)

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:

#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(

    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
