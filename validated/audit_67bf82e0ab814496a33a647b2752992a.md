### Title
Unauthenticated `/v2/resume/:runID` endpoint allows any external party to race a legitimate bridge callback and inject a forged result into another user's job run - ([File: core/web/pipeline_runs_controller.go])

### Summary
The JOJO `approveTrade()` bug class is: a piece of data that is meant to be actioned by one specific, legitimate party is instead accepted from *any* party who can present it, and the first-to-submit wins, letting an unintended actor race the legitimate one and capture the outcome. The Chainlink node exposes a structurally similar callback endpoint: `PATCH /v2/resume/:runID`, mounted with **no authentication at all**, which finalizes a suspended pipeline run using attacker-suppliable JSON.

### Finding Description
The route is registered outside the authenticated router group: [1](#0-0) 

The handler accepts only a UUID path parameter (`runID`, actually the async task's UUID) and an arbitrary JSON body, then immediately calls `App.ResumeJobV2` to complete the pending task with the caller-supplied result - there is no signature, no HMAC, no shared secret check, and no binding to the specific bridge/external-adapter that originally received the callback URL: [2](#0-1) 

The only "capability token" is the task UUID itself, which is generated once and embedded verbatim into the `responseURL` field sent out to the external adapter in the bridge task's request body: [3](#0-2) 

The audit log even labels this action `UnauthedRunResumed`, confirming the design deliberately allows unauthenticated completion of the run so long as the caller possesses the UUID: [4](#0-3) 

This mirrors the JOJO pattern precisely: the "secret" needed to claim the outcome (the tradeData / the resume UUID) is transmitted over channels that are not exclusively private to the intended actor (mempool for tradeData; outbound HTTP requests, logs, proxies, and the external adapter's own infrastructure for the UUID), and *whoever presents it first* — not necessarily the intended party — gets to determine the final state of the run. Unlike JOJO's case (which at least required being "a valid order sender"), here the endpoint requires **no credential whatsoever** beyond knowledge of the UUID, making it strictly more exposed: any unauthenticated internet client that learns or intercepts a pending run's UUID (e.g., via a compromised/logging external adapter, a misconfigured proxy, browser history, or a malicious downstream service the adapter itself calls out to) can race the legitimate adapter's real response and inject a forged/attacker-chosen JSON result into that user's pipeline run before the real answer arrives.

### Impact Explanation
If an attacker wins the race (or the legitimate adapter is slow/compromised), they can supply an arbitrary `pipeline.ResumeRequest` value that becomes the task's output, feeding downstream pipeline tasks (e.g., ETH transactions, further bridge calls) with attacker-controlled data. Depending on the job's pipeline (e.g., feeding a value used to sign/submit an on-chain transaction), this could corrupt oracle reports or trigger unintended on-chain actions — directly analogous to the "fee theft" impact in the JOJO report, generalized to "run-outcome theft/corruption."

### Likelihood Explanation
Exploitability depends entirely on how easily an unprivileged party can learn a specific run's UUID. This is not brute-forceable (UUIDv4), so the practical likelihood is lower than the JOJO scenario, where `tradeData` is trivially observable in the public mempool. Concretely, the UUID would need to leak through some other channel (adapter-side logging, error responses, network intermediary, or a compromised/malicious external adapter). Because the analog's initial data (a bridge task's `responseURL`) is not routinely public the way blockchain mempool data is, I could not fully verify a concrete unprivileged leak path within this codebase — this weakens confidence that the analog is exploitable purely from "an unprivileged client request" without an additional prerequisite leak.

### Recommendation
Bind the resume callback to the specific adapter/run by requiring a per-run secret or HMAC signature (e.g., derive an unguessable, single-use signed token tied to the run and bridge, verified server-side) rather than relying solely on knowledge of the run UUID as the entire authorization. Additionally, ensure `ResumeJobV2` enforces single-use/idempotent completion so that even if two callers race, only the first legitimate resume is accepted and subsequent attempts are rejected, and consider rate-limiting or auditing repeated resume attempts on the same run.

### Proof of Concept
Not independently verified with a running instance; based on static code analysis:
1. Create a webhook/bridge job with an `async=true` bridge task; the node sends the external adapter a request whose `requestData.responseURL` is `http://<node>/v2/resume/<taskUUID>` (`core/services/pipeline/task.bridge.go:364-378`).
2. If that UUID is observable to a third party (e.g., via adapter logs, a compromising intermediary, or a slow/malicious adapter), the third party sends `PATCH /v2/resume/<taskUUID>` with a forged JSON body before the legitimate adapter responds.
3. `PipelineRunsController.Resume` (`core/web/pipeline_runs_controller.go:134-161`) accepts the request with no authentication, and `ResumeJobV2` completes the pending run using the attacker's data. [2](#0-1) [1](#0-0) [3](#0-2)

// Resume finishes a task and resumes the pipeline run.
// Example:
// "PATCH <application>/jobs/:ID/runs/:runID"
func (prc *PipelineRunsController) Resume(c *gin.Context) {
	taskID, err := uuid.Parse(c.Param("runID"))
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	rr := pipeline.ResumeRequest{}
	decoder := json.NewDecoder(c.Request.Body)
	err = errors.Wrap(decoder.Decode(&rr), "failed to unmarshal JSON body")
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	result, err := rr.ToResult()
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	if err := prc.App.ResumeJobV2(c.Request.Context(), taskID, result); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
	c.Status(http.StatusOK)
}
