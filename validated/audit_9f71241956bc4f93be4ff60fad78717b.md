Audit Report

## Title
Unhandled nil pointer dereference in Vault node's `MethodPublicKeyGet` handler crashes the node process - (File: `core/capabilities/vault/gw_handler.go`)

## Summary
`GatewayHandler.HandleGatewayMessage` dispatches `vaulttypes.MethodPublicKeyGet` requests to `handlePublicKeyGet` without checking whether `req.Params` is `nil`, and `handlePublicKeyGet` unconditionally dereferences it via `json.Unmarshal(*req.Params, r)`. Since `MethodPublicKeyGet` is explicitly documented and tested as not requiring authorization and supporting `Params: nil` on the gateway side, and the gateway forwards the original (possibly nil) request unchanged to every DON node on a cache miss, an unauthenticated client can trigger a nil-pointer-dereference panic on every node in the Vault DON.

## Finding Description
On the gateway side, `handler.HandleJSONRPCUserMessage` explicitly special-cases `vaulttypes.MethodPublicKeyGet` to skip authorization ("Public key requests don't require authorization"), and on a cache miss calls `h.handlePublicKeyGet(ctx, ar)`, which (per `fanOutToVaultNodes`) forwards `&ar.req` — the original, unmodified request including its `Params` field — to every node via `h.don.SendToNode`. [1](#0-0) [2](#0-1) 

This request shape (`Params: nil`) is explicitly exercised by the gateway's own test suite, confirming it's a supported/expected input at the gateway layer: [3](#0-2) [4](#0-3) 

On the node side, `GatewayHandler.HandleGatewayMessage` routes `MethodPublicKeyGet` directly to `handlePublicKeyGet` with no nil-check on `req.Params`, unlike the other cases which pass through `h.requestProcessor.ProcessRequest` first: [5](#0-4) 

`handlePublicKeyGet` then unconditionally dereferences the pointer: [6](#0-5) 

`json.Unmarshal(*req.Params, r)` where `req.Params` is a `nil` `*json.RawMessage` panics with a nil pointer dereference in Go.

Critically, I verified there is no panic recovery wrapping this call. The connector's `readLoop` invokes `handler.HandleGatewayMessage` directly inside a bare goroutine (`go c.readLoop(gatewayState)`), with only an `err != nil` check afterward — no `recover()` anywhere in the call chain: [7](#0-6) [8](#0-7) 

Since Go panics are per-goroutine and, if unrecovered, crash the entire process regardless of what other goroutines are doing, an unrecovered panic in `readLoop` terminates the node's backend process.

## Impact Explanation
A single JSON-RPC `vault.publicKey.get` request with `params: null` (or omitted `params`) sent to the gateway's public endpoint — with no authorization required — propagates unchanged to every Vault DON node via `fanOutToVaultNodes`, and panics `GatewayHandler.HandleGatewayMessage`'s goroutine on each node, crashing the node process. This is a concrete, unauthenticated Denial-of-Service against the Vault capability's node processes, potentially affecting every member of the DON simultaneously since the request fans out to `h.donConfig.Members`.

## Likelihood Explanation
High. The trigger path requires no authentication, no authorization, and no privileged role — `MethodPublicKeyGet` is explicitly exempted from the Vault authorization pipeline, and the vulnerable code path (cold public-key cache) is a normal, easily-forced operational state. The request shape (`Params: nil`) is not an edge case; it is the exact shape the gateway's own tests use for this method.

## Recommendation
In `core/capabilities/vault/gw_handler.go`, add an explicit nil/empty check on `req.Params` in `handlePublicKeyGet` (and audit other handler branches such as `handleSecretsCreate`, `handleSecretsUpdate`, `handleSecretsDelete`, `handleSecretsList` for the same issue, since they all perform `json.Unmarshal(*req.Params, ...)` without a preceding nil check), returning a structured `api.UserMessageParseError`/`InvalidParamsError` response instead of dereferencing a nil pointer. As defense-in-depth, add `recover()` around the `handler.HandleGatewayMessage` dispatch in `core/services/gateway/connector/connector.go`'s `readLoop` to prevent any single capability handler panic from crashing the entire node process.

## Proof of Concept
1. Send an unauthenticated JSON-RPC request to the gateway's HTTP endpoint targeting the Vault DON/service:
```json
{"jsonrpc":"2.0","id":"1","method":"vault.publicKey.get","params":null}
```
2. `handler.HandleJSONRPCUserMessage` (`core/services/gateway/handlers/vault/handler.go:404-420`) accepts this without authorization; on a cold public-key cache it calls `h.handlePublicKeyGet`, which via `fanOutToVaultNodes` (`handler.go:736-752`) forwards the request unchanged to every Vault DON node.
3. Each node's `GatewayHandler.HandleGatewayMessage` (`core/capabilities/vault/gw_handler.go:180-211`) routes to `handlePublicKeyGet` (`gw_handler.go:364-368`), which executes `json.Unmarshal(*req.Params, r)` with `req.Params == nil`.
4. This panics with a nil pointer dereference inside the `readLoop` goroutine (`core/services/gateway/connector/connector.go:268-299`), which has no `recover()`, crashing the node process.

A minimal Go unit test confirming this would call `GatewayHandler.HandleGatewayMessage(ctx, gatewayID, &jsonrpc.Request[json.RawMessage]{Method: vaulttypes.MethodPublicKeyGet, Params: nil})` directly and observe the panic (as opposed to the existing gateway-side tests in `handler_test.go` which only exercise the gateway, not the node-side `gw_handler.go`).

func (h *handler) fanOutToVaultNodes(ctx context.Context, l logger.Logger, ar *activeRequest) error {
	var nodeErrors []error
	for _, node := range h.donConfig.Members {
		err := h.don.SendToNode(ctx, node.Address, &ar.req)
		if err != nil {
			nodeErrors = append(nodeErrors, err)
			l.Errorw("error sending request to node", "node", node.Address, "error", err)
		}
	}

	if len(nodeErrors) == len(h.donConfig.Members) && len(nodeErrors) > 0 {
		return h.sendResponse(ctx, ar, h.errorResponse(ar.req, api.FatalError, errors.New("failed to forward user request to nodes"), nil))
	}

	l.Debugw("successfully forwarded request to Vault nodes")
	return nil
}

func (c *gatewayConnector) readLoop(gatewayState *gatewayState) {
	defer c.closeWait.Done()
	ctx, cancel := c.shutdownCh.NewCtx()
	defer cancel()

	for {
		select {
		case <-c.shutdownCh:
			return
		case item := <-gatewayState.conn.ReadChannel():
			var req jsonrpc.Request[json.RawMessage]
			err := json.Unmarshal(item.Data, &req)
			if err != nil {
				c.lggr.Errorw("parse error when reading from Gateway", "id", gatewayState.config.ID, "err", err)
				break
			}
			c.handlersMu.RLock()
			handler, exists := c.handlers[req.Method]
			c.handlersMu.RUnlock()
			if !exists {
				c.lggr.Errorw("no handler for method", "id", gatewayState.config.ID, "method", req.Method)
				break
			}
			// do not break on error. HandleGatewayMessage handles errors
			// by sending a response back to the Gateway.
			err = handler.HandleGatewayMessage(ctx, gatewayState.config.ID, &req)
			if err != nil {
				c.lggr.Warnw("failed to handle message from Gateway", "id", gatewayState.config.ID, "method", req.Method, "err", err)
			}
		}
	}
}

func (c *gatewayConnector) Start(ctx context.Context) error {
	return c.StartOnce("GatewayConnector", func() error {
		c.lggr.Info("starting gateway connector")
		c.recordGatewaysPerDon(ctx)
		for _, gatewayState := range c.gateways {
			if err := gatewayState.conn.Start(ctx); err != nil {
				return err
			}
			c.closeWait.Add(2)
			go c.readLoop(gatewayState)
			go c.reconnectLoop(gatewayState)
		}
		return nil
	})
}
