## Analysis

I found a valid analog. The reported pattern—missing zero-address validation on an address parameter that is later used to execute a critical action—maps directly onto the recipient address handling in Hyperbridge's `HyperFungibleToken` cross-chain transfer flow.

### Title
Missing zero-address validation on recipient in `HyperFungibleToken.send()` permanently burns tokens when `timeout` is `0` - (File: `sdk/packages/core/contracts/apps/HyperFungibleToken.sol`)

### Summary
`send()` burns the caller's tokens and dispatches a cross-chain `POST` request without validating that the encoded recipient (`params.to`) decodes to a non-zero address. If the recipient decodes to `address(0)`, the destination chain's `onAccept` will always revert (OpenZeppelin's `ERC20._mint`/`_update` rejects minting to `address(0)`), and if the request was dispatched with `timeout: 0` (which per protocol convention means "never expires"), the funds can never be refunded via the timeout path either — resulting in a permanent loss of the burned tokens.

### Finding Description
`send()` accepts arbitrary `SendParams.to` bytes and burns tokens unconditionally, with no check on the destination address: [1](#0-0) 

On the destination chain, `onAccept` decodes the recipient with `_toAddr` and mints directly: [2](#0-1) 

`_toAddr` only validates the byte length (must be 20 bytes) — it does not reject the zero address: [3](#0-2) 

Since the contract inherits standard OpenZeppelin `ERC20`, minting to `address(0)` always reverts. When `onAccept` reverts, `EvmHost.dispatchIncoming` (or the equivalent Polkadot handler) treats delivery as failed and simply returns without state changes, meaning the message is permanently stuck as "undeliverable": [4](#0-3) 

Recovery is only possible via the timeout flow (`onPostRequestTimeout`, which re-mints to the original sender). But the protocol explicitly treats `timeout: 0` as "no timeout, i.e. messages will never expire": [5](#0-4) 

This is also enforced at the ISMP core level — a zero `timeout_timestamp` is translated to `Duration::MAX`, meaning `timed_out()` can never return true: [6](#0-5) 

The EVM host mirrors this by only assigning a real deadline when `post.timeout != 0`: [7](#0-6) 

So a `send()` call with `to` decoding to `address(0)` and `timeout: 0` results in tokens burned on the source chain with (a) permanently failing delivery at the destination and (b) no possible timeout-triggered refund, ever. The same defect exists in the upgradeable variant: [8](#0-7) 

### Impact Explanation
This causes a permanent, unrecoverable loss (burn with no corresponding mint or refund) of user funds. Although triggered by supplying `address(0)` as the recipient, this is exactly the missing-validation class from the reference report: a single, unprivileged, user-initiated transaction (`send()`) can permanently freeze/destroy funds due to the absence of a zero-address check on a parameter that gates a critical state-changing action (minting/refunding), with no admin or governance involvement required. This satisfies the "permanent freezing of funds" impact bar from the validation criteria.

### Likelihood Explanation
High: any user can trigger this by mistake (e.g., malformed frontend input, encoding bug, or copy-paste error producing a zero-padded/zero address) while also choosing `timeout: 0`, which the documentation explicitly frames as the default "never expire" mode for message validity, making this a realistic and easily triggerable combination. No special privileges or race conditions are needed.

### Recommendation
Validate that the decoded recipient/refund address is non-zero before burning/dispatching in `send()` (and symmetrically validate `message.to` / `message.from` in `onAccept`/`onPostRequestTimeout` before minting), e.g., add a zero-address check inside `_toAddr` or immediately after decoding in `send()`, `onAccept`, and `onPostRequestTimeout`.

### Proof of Concept
1. Caller invokes `HyperFungibleToken.send(SendParams{ dest: <registered chain>, to: abi.encodePacked(address(0)), amount: X, timeout: 0, relayerFee: 0, data: "" })`.
2. `_burn(msg.sender, X)` executes, tokens are destroyed on the source chain.
3. The `POST` request is dispatched with `timeoutTimestamp = 0` (never expires), per `EvmHost.dispatch`.
4. On the destination, `onAccept` decodes `beneficiary = address(0)` and calls `_mint(address(0), X)`, which reverts due to OpenZeppelin's `ERC20InvalidReceiver` check.
5. `EvmHost.dispatchIncoming`/pallet equivalent treats this as a failed delivery and returns without persisting effects — the request can be retried indefinitely but will always fail identically.
6. Because `timeoutTimestamp == 0` maps to `Duration::MAX`/never-timed-out, no relayer can ever submit a valid timeout proof to trigger `onPostRequestTimeout`'s refund mint.
7. Result: `X` tokens are permanently destroyed with no path to mint or refund them on any chain.

    function onAccept(IncomingPostRequest calldata incoming) public virtual override onlyHost whenNotPaused {
        PostRequest calldata request = incoming.request;

        bytes memory expectedSource = _supportedChains[request.source];
        if (expectedSource.length == 0) revert UnsupportedChain();
        if (keccak256(request.from) != keccak256(expectedSource)) revert UnauthorizedSource();

        Message memory message = abi.decode(request.body, (Message));
        address beneficiary = _toAddr(message.to);
        _mint(beneficiary, message.amount);

        if (message.data.length > 0) {
            ICallDispatcher(_dispatcher).dispatch(message.data);
        }

        emit Received({
            from: message.from,
            to: beneficiary,
            source: string(request.source),
            amount: message.amount
        });
    }

    function _toAddr(bytes memory b) internal pure returns (address addr) {
        if (b.length != 20) revert InvalidAddress(b.length);
        // casting to 'bytes20' is safe because we already checked length
        // forge-lint: disable-next-line(unsafe-typecast)
        return address(bytes20(b));
    }

    function dispatchIncoming(PostRequest memory request, address relayer) external restrict(_hostParams.handler) {
        address destination = _bytesToAddress(request.to);
        uint256 size;
        assembly {
            size := extcodesize(destination)
        }
        if (size == 0) {
            // instead of reverting the entire batch, early return here.
            return;
        }

        // replay protection
        bytes32 commitment = request.hash();
        _requestReceipts[commitment] = relayer;

        (bool success,) = address(destination)
            .call(abi.encodeWithSelector(IApp.onAccept.selector, IncomingPostRequest(request, relayer)));

        if (!success) {
            // so that it can be retried
            delete _requestReceipts[commitment];
            return;
        }
        emit PostRequestHandled({commitment: commitment, relayer: relayer});
    }

/// Get the timeout in seconds
fn get_timeout(timeout_timestamp: u64) -> Duration {
	// zero timeout means no timeout.
	if timeout_timestamp == 0 {
		Duration::from_secs(u64::MAX)
	} else {
		Duration::from_secs(timeout_timestamp)
	}
}
