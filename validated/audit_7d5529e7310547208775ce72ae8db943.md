### Title
Emporium `runAction` lets an attacker with zero UTXOs drain Emporium's parked ETH/ERC20 balance via unauthenticated `EmporiumStack` ops - ([File: contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol])

### Summary
When `Hinkal.transact` is called with `Dimensions{0,0,0}`, `erc20TokenAddresses=[]`, and `externalActionId == HINKAL_EMPORIUM_ACTION_ID`, `CircomDataBuilder.formInputForCircom` routes the proof to `formInputEmporiumMin`, whose only circuit is `MainEVMCircuitMin` — a circuit that proves nothing except `message == Poseidon(1)([messageSeed])`. No nullifier, spending key, or signature over `EmporiumStack` is ever proven when `EmporiumStack.signerAddress == address(0)`, and because `erc20TokenAddresses` is empty, `EmporiumUpgradeable.runAction`'s pre/post balance bookkeeping loop is a no-op. This lets any unprivileged EOA execute `stack.ops[i].endpoint.call{value: op.value}(op.callData)` straight from Emporium's own address, moving out Emporium's real parked ETH/ERC20 balance with zero authorization.

### Finding Description
The broken equality: **"every `value`/`callData` executed by `EmporiumUpgradeable` was authorized by the account whose UTXO/key the accompanying proof attests to"** vs. what the code actually enforces, which is **"no authorization at all when `EmporiumStack.signerAddress == address(0)`"**.

Call path:
1. `Hinkal.transact` (contracts/Hinkal.sol:30-56) calls `HinkalHelper.performHinkalChecks`, which only validates hash/dimension consistency (`dimensionsCheck`, `checkOnchainCreation`, calldata-hash integrity) — none of these tie `externalActionMetadata` to any real UTXO ownership [1](#0-0) .
2. Because `externalActionId == HINKAL_EMPORIUM_ACTION_ID` and `erc20TokenAddresses.length == 0`, `formInputForCircom` returns `formInputEmporiumMin`, a 3-element public input array (`emporiumMessage`, `timeStamp`, `calldataHash`) [2](#0-1) .
3. `MainEVMCircuitMin` only constrains `message <== Poseidon(1)([messageSeed])` — no nullifier, no spending key, no signature is proven [3](#0-2) . Any attacker can pick `messageSeed` and generate a valid Groth16 proof trivially.
4. `Hinkal._externalTransact` (contracts/Hinkal.sol:234-261) skips all transfer logic since `circomData.erc20TokenAddresses` is empty, and calls `EmporiumUpgradeable.runAction` with `deltaAmountChanges = []`.
5. Inside `runAction`, `balancesBefore`/`balancesAfter` are computed over the empty `erc20TokenAddresses` array, so the final balance-check loop (`for (uint256 i = 0; i < circomData.erc20TokenAddresses.length; i++)`) never executes — **no bookkeeping constrains what the ops loop actually moved** [4](#0-3) .
6. `verifyWallet` only checks `usedMessages` and, if `stack.signerAddress == address(0)`, **returns immediately without any signature verification** [5](#0-4) .
7. With `signerAddress == address(0)`, each op falls into the "Stateless Interaction" branch and is executed unconditionally: `op.endpoint.call{value: op.value}(op.callData)` — executed from Emporium's own address/balance, no wallet or signature involved [6](#0-5) .

The attacker fully controls `EmporiumStack` (decoded from `circomData.externalActionData.externalActionMetadata`), since the only constraint on it is the `calldataHash` self-consistency check in `performHinkalChecks`/`getHashedCalldata` — a hash equality the attacker computes themselves, not a proof of authorization. `runAction` itself is only gated by `onlyAllowedRecipient`, which restricts `msg.sender` to the `Hinkal` contract (satisfied automatically via the normal `transact → _externalTransact` call chain) — it does **not** restrict who can trigger that chain or what `op.endpoint`/`op.value`/`op.callData` may be.

The comment in `handleOut` — *"total change can be less than zero if there was some balance before the call"* — confirms the protocol's own design expects Emporium to legitimately carry a residual ETH/token balance across transactions [7](#0-6) . That residual balance is exactly what an attacker can now drain.

### Impact Explanation
Any ETH or ERC20 balance sitting on `EmporiumUpgradeable` (leftover from prior swaps, partial fills, dust, or any legitimate multi-step operation) can be transferred out by an attacker to an arbitrary `op.endpoint` with an arbitrary `op.value`/`op.callData`, with zero requirement to own any shielded UTXO, nullifying key, or spending key. This is direct theft of protocol/user funds parked at a Hinkal-registered external action contract — Critical severity. The attack is repeatable every time Emporium holds a nonzero balance, at negligible attacker cost (one Groth16 proof for a trivial circuit plus gas).

### Likelihood Explanation
Preconditions: Emporium must hold ETH/ERC20 balance (acknowledged as an expected state by the code's own comments), and a `MainEVMCircuitMin`/Emporium-min verifier must be registered for `Dimensions{0,0,0}` with the Emporium action id (this is the intended minimal-signal Emporium messaging path per `formInputEmporiumMin`). No privileged role, relay, or victim key is required — the attacker only needs to call `Hinkal.transact` directly (`circomData.relay = address(0)`, `circomData.originalSender = msg.sender`), which is permitted for any unprivileged EOA. Generating the proof requires no secret knowledge. This is fully attacker-repeatable.

### Recommendation
Do not allow `EmporiumStack.signerAddress == address(0)` to bypass authorization entirely for stateless ops that move Emporium's own funds. Either: (1) require every `EmporiumOperation` to be authorized by a signature (or proof-bound value) regardless of `signerAddress`, or (2) bind `runAction`'s pre/post balance accounting to the *actual* set of tokens/ETH touched by `stack.ops` (not just `circomData.erc20TokenAddresses`, which the attacker can leave empty to bypass all bookkeeping), and require `deltaAmountChanges`/slippage invariants to hold for that full set. Additionally, consider disallowing `erc20TokenAddresses.length == 0` combined with any nonzero `op.value`/non-empty `op.callData` unless a cryptographically bound signer/proof authorizes exactly those ops.

### Proof of Concept
Foundry fork test plan:
1. Deploy/fork the protocol; seed `EmporiumUpgradeable` with ETH by executing one legitimate prior `runAction` that leaves residual ETH balance on Emporium (or directly send ETH via its `receive()`).
2. Off-chain: generate a snarkjs Groth16 proof for `MainEVMCircuitMin` with an arbitrary `messageSeed`, computing `message = Poseidon(1)([messageSeed])`.
3. Build `CircomData` with `dimensions = {tokenNumber:0, nullifierAmount:0, outputAmount:0}`, `erc20TokenAddresses = []`, `externalActionData.externalActionId = HINKAL_EMPORIUM_ACTION_ID`, `externalActionData.externalActionMetadata = abi.encode(EmporiumStack({signerAddress: address(0), ops: [EmporiumOperation({endpoint: attacker, invokeWallet: false, value: emporiumEthBalance, callData: ""})], maxFee: 0, deadline: type(uint256).max}))`, and a correctly computed `calldataHash`.
4. Call `Hinkal.transact(a, b, c, dimensions, circomData)` from an attacker EOA with `relay = address(0)`, `originalSender = attacker`.
5. Assert: (a) the call succeeds (`verifyProof` returns true, no `AUTHORITY`-related revert), (b) `address(Emporium).balance` decreases by `emporiumEthBalance` and `attacker.balance` increases correspondingly, (c) no nullifier was inserted and no shielded UTXO was consumed by the attacker (`insertNullifiers` receives empty arrays), proving the equality "funds moved == funds authorized by proof" is violated (LHS: `emporiumEthBalance` moved; RHS: `0` authorized).

        CircomData calldata circomData,
        int256[] calldata deltaAmountChanges
    ) external override onlyAllowedRecipient returns (UTXO[] memory) {

            circomData.externalActionData.externalActionMetadata,
            (EmporiumStack)
        );

        uint256[] memory balancesBefore = getBalancesForArray(
            circomData.erc20TokenAddresses
        );

        verifyWallet(stack, circomData);

        for (uint256 i = 0; i < stack.ops.length; i++) {
            EmporiumOperation memory op = stack.ops[i];

            bool success;
            bytes memory err;

            // CASE 1: Stateful Interaction
            if (op.invokeWallet && stack.signerAddress != address(0)) {
                (success, err) = IHinkalWallet(stack.signerAddress)
                    .callHinkalWallet(op.endpoint, op.callData, op.value);
            }
            // CASE 2: Stateless Interaction
            else {
                bytes4 selector = bytes4(op.callData);
                if (
                    selector == IHinkalWallet.callHinkalWallet.selector ||
                    selector == IHinkalWallet.doSendToRelay.selector
                ) {
                    revert UnauthorizedWalletCall();
                }

                (success, err) = op.endpoint.call{value: op.value}(op.callData);
            }

            if (!success) {
                revert CallFailed(err);
            }
        }

        payRelayFees(circomData, stack.signerAddress, deltaAmountChanges);

        uint256[] memory balancesAfter = getBalancesForArray(
            circomData.erc20TokenAddresses
        );

            circomData.erc20TokenAddresses.length
        );

        uint256 utxoSetLength;

        for (uint256 i = 0; i < circomData.erc20TokenAddresses.length; i++) {

                revert BalanceChangeShouldBePositive();
