### Title
Incomplete request-body redaction in Chainlink node access log leaks nested/non-blacklisted sensitive fields - (File: core/web/router.go)

### Summary
The OpenBao advisory describes raw HTTP request bodies being written to audit logs without proper redaction (HMAC'ing), exposing sensitive short-lived secrets/tokens carried in JSON request bodies. Chainlink's node HTTP server has an analogous, though architecturally different, weakness: the debug-level access-log middleware `loggerFunc` sanitizes request bodies before logging, but the sanitization is shallow (top-level keys only) and uses a narrow hardcoded blacklist, so sensitive values nested inside JSON objects, or fields not matching the blacklist, are written to node logs verbatim.

### Finding Description
`loggerFunc` is installed as a global Gin middleware for the entire node HTTP server, ahead of authentication/session middleware, so it executes for every inbound request, authenticated or not: [1](#0-0) 

For every request it reads and buffers the raw body, then logs it at Debug level after passing it through `readBody`/`readSanitizedJSON`: [2](#0-1) 

`readSanitizedJSON` only unmarshal's the body into a flat `map[string]any` and redacts a value only if its **top-level** key matches `isBlacklisted`; any nested object, array element, or key name it doesn't recognize is logged as-is: [3](#0-2) 

The blacklist itself is extremely narrow — only password-related keys are covered: [4](#0-3) 

This mirrors the OpenBao bug class (raw/insufficiently-redacted request bodies persisted to logs) but here it is even broader: nested JSON structures (e.g., a `{"user":{"apiToken":"..."}}`-shaped payload, or any field not literally named `password`/`newpassword`/etc.) bypass redaction entirely, and the flaw is present on the standard node HTTP API, not a niche subsystem.

### Impact Explanation
Any secret-bearing value sent in a JSON request body to the Chainlink node's HTTP API — API tokens, session-related fields with alternate names, external-initiator credentials, or any future endpoint's payload — can end up unredacted in the node's own logs if it is nested or not spelled exactly as one of the five blacklisted keys. Anyone with read access to node logs (log aggregation systems, support engineers, monitoring pipelines) could recover these values, resulting in credential/secret disclosure. This is a real logging/redaction defect, but the severity is bounded: it requires the node operator to run at Debug log level (this is logged via `Debugw`, not a level that's enabled by default in production), and it requires an attacker to already have log access — it is not directly exploitable by a fully unprivileged remote client without also obtaining log-viewing privileges.

### Likelihood Explanation
Likelihood of triggering the write path is high (any request to the node hits this middleware), but the practical likelihood of the vulnerability leading to compromise depends on: (1) Debug logging being enabled, and (2) sensitive field names in relevant requests not matching the blacklist (e.g., a nested field or a field named differently than the five hardcoded strings). Since the redaction is shallow by design and easily bypassed by nesting, this is a design-level weakness rather than a corner case.

### Recommendation
Make redaction recursive over nested JSON objects/arrays in `readSanitizedJSON`, and broaden/centralize the sensitive-field blacklist (e.g., include token/secret/key/authorization-style field names) rather than relying on five hardcoded password variants. Consider redacting the entire body for known-sensitive endpoints (e.g., `/sessions`, EI registration) instead of relying purely on field-name heuristics.

### Proof of Concept
1. Enable Debug-level logging on a Chainlink node.
2. Send a request to any JSON API endpoint with a payload such as `{"account":{"password":"leak-nested"}}` — because `password` is nested one level deep, `isBlacklisted` never sees the key `"account"`, and the whole nested object (including `password`) is logged verbatim by `readSanitizedJSON`.
3. Inspect the node's Debug logs for the `body` field written by `loggerFunc` and observe the plaintext secret. [3](#0-2)

func loggerFunc(lggr logger.Logger) gin.HandlerFunc {
	return func(c *gin.Context) {
		buf, err := io.ReadAll(c.Request.Body)
		if err != nil {
			lggr.Error("Web request log error: ", err.Error())
			// Implicitly relies on limits.RequestSizeLimiter
			// overriding of c.Request.Body to abort gin's Context
			// inside io.ReadAll.
			// Functions as we would like, but horrible from an architecture
			// and design pattern perspective.
			if !c.IsAborted() {
				c.AbortWithStatus(http.StatusBadRequest)
			}
			return
		}
		rdr := bytes.NewBuffer(buf)
		c.Request.Body = io.NopCloser(bytes.NewBuffer(buf))

		start := time.Now()
		c.Next()
		end := time.Now()

		lggr.Debugw(fmt.Sprintf("%s %s", c.Request.Method, c.Request.URL.Path),
			"method", c.Request.Method,
			"status", c.Writer.Status(),
			"path", c.Request.URL.Path,
			"ginPath", c.FullPath(),
			"query", redact(c.Request.URL.Query()),
			"body", readBody(rdr, lggr),
			"clientIP", c.ClientIP(),
			"errors", c.Errors.String(),
			"servedAt", end.Format("2006-01-02 15:04:05"),
			"latency", fmt.Sprintf("%v", end.Sub(start)),
		)
	}

func readSanitizedJSON(buf *bytes.Buffer) (string, error) {
	var dst map[string]any
	err := json.Unmarshal(buf.Bytes(), &dst)
	if err != nil {
		return "", err
	}

	cleaned := map[string]any{}
	for k, v := range dst {
		if isBlacklisted(k) {
			cleaned[k] = "*REDACTED*"
			continue
		}
		cleaned[k] = v
	}

	b, err := json.Marshal(cleaned)
	if err != nil {
		return "", err
	}
	return string(b), err
}

// NOTE: keys must be in lowercase for case insensitive match
var blacklist = map[string]struct{}{
	"password":             {},
	"newpassword":          {},
	"oldpassword":          {},
	"current_password":     {},
	"new_account_password": {},
}

func isBlacklisted(k string) bool {
	lk := strings.ToLower(k)
	if _, ok := blacklist[lk]; ok || strings.Contains(lk, "password") {
		return true
	}
	return false
}
