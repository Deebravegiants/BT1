This is a real, exploitable finding.

### Title
Occlusion/FaceIdentifier model errors are silently swallowed into `Ok(Pipeline)`, bypassing fail-closed enforcement and allowing degraded-signal signups to proceed to enrollment - ([File: src/plans/biometric_pipeline/mod.rs])

### Summary
`Plan::run` treats `occlusion::Output::Error` and `face_identifier::Output::Error` as non-fatal by storing them as `Some(Err(error))` inside the `Pipeline` struct's `Result` fields instead of returning an `Err` from the function. Only `iris::Output::Error` triggers early termination via `return Err(Error::Iris(error))?`. As a result, `biometric_pipeline()` in `src/plans/mod.rs` receives `Ok(Pipeline{ occlusion: Err(_), face_identifier_fraud_checks: Err(_), .. })`, which is unconditionally wrapped as `Some(pipeline)` and returned - never `None` - so `detect_fraud` and `enroll_user` are still invoked with pipeline data derived from a degraded/occluded capture.

### Finding Description
In `Plan::run` (`src/plans/biometric_pipeline/mod.rs`):
- `mega_agent_one::Output::Occlusion(occlusion::Output::Error(error))` sets `occlusion = Some(Err(error))` [1](#0-0) 
- `face_identifier::Output::Error(error)` sets `face_identifier_fraud_checks = Some(Err(error.clone()))` and `face_identifier_bundle = Some(Err(error.clone()))` [2](#0-1) 

Both of these `Some(Err(_))` values satisfy the loop's `is_none()` exit conditions [3](#0-2) , and the function then returns `Ok(Pipeline{ occlusion: occlusion.unwrap(), face_identifier_fraud_checks: face_identifier_fraud_checks.unwrap(), face_identifier_bundle: face_identifier_bundle.unwrap(), .. })` [4](#0-3) . This is in contrast to `iris::Output::Error`, which is explicitly treated as fatal: `return Err(Error::Iris(error))?` [5](#0-4) .

In `src/plans/mod.rs`, `biometric_pipeline()` calls `Plan::run` and only returns `Ok(None)` if the outer `Result` from `run()` is an `Err` (i.e., `Error::Timeout`, `Error::Agent`, or `Error::Iris`) [6](#0-5) . Since occlusion/face-identifier errors never produce that outer `Err`, execution falls through to `Ok(Some(pipeline))` [7](#0-6) , with the embedded error only logged/reported to the debug report (`debug_report.occlusion_error(pipeline.occlusion.clone().err())`, `debug_report.face_identifier_results(...)`) [8](#0-7)  - no rejection logic exists there.

Downstream, `detect_fraud` explicitly states `// FOSS: WE HAVE DELETED ALL FRAUD CHECKS` and unconditionally returns `Ok(false)` whenever `pipeline` is `Some` [9](#0-8) , and `enroll_user` is called with `pipeline: Some(&biometric_pipeline::Pipeline)` regardless of the embedded `Err` variants [10](#0-9) . There is no code path in `src/plans/mod.rs` between `biometric_pipeline()` and `enroll_user()` that inspects `pipeline.occlusion` or `pipeline.face_identifier_fraud_checks` for an `Err` and aborts the signup.

An unprivileged attacker who occludes the camera (hand, mask, extreme low light, etc.) during their own signup session can therefore reliably force the occlusion/face-identifier python agents to emit `Output::Error`, and the pipeline still completes as `Ok(Some(pipeline))`, reaching `enroll_user` bound to the attacker's own `SignupId`.

### Impact Explanation
This is a fail-open liveness/qualification bypass: signal-quality/liveness gating (occlusion detection, face-identifier fraud checks) that should reject degraded biometric capture is not enforced before enrollment. The impact is scoped to accepting degraded/occluded capture as a qualifying biometric signup for the attacker's own account - a signup integrity/fraud-check bypass rather than identity theft against another user's iris (iris errors are still fatal). This corresponds to Worldcoin/Orb bounty categories for "signup fraud/liveness bypass" or "biometric qualification bypass."

### Likelihood Explanation
Highly feasible and repeatable: any unprivileged user going through the normal signup flow can partially occlude their face or camera during the biometric pipeline phase to induce `occlusion::Output::Error` or `face_identifier::Output::Error` from the python agents, with no special access, hardware tampering, or credentials required. This is deterministic given the code paths above - `Ok(Some(pipeline))` is always returned unless iris fails or a timeout occurs.

### Recommendation
In `Plan::run` (`src/plans/biometric_pipeline/mod.rs`), treat `occlusion::Output::Error` and `face_identifier::Output::Error` as fatal like `iris::Output::Error` (return an `Err` from `run`), or alternatively have `biometric_pipeline()` in `src/plans/mod.rs` explicitly check `pipeline.occlusion.is_err()` / `pipeline.face_identifier_fraud_checks.is_err()` after receiving `Ok(Some(pipeline))` and return `Ok(None)` (rejecting the signup) instead of proceeding to `detect_fraud`/`enroll_user`.

### Proof of Concept
Integration test plan:
1. Construct a `biometric_pipeline::Plan` with a mock `Orb`/mega-agent channel.
2. Inject `mega_agent_one::Output::Occlusion(occlusion::Output::Error(...))` and `mega_agent_two::Output::FaceIdentifier`/`face_identifier::Output::Error(...)` into the model_output channel while allowing iris outputs to succeed normally.
3. Call `Plan::run(orb)` and assert it returns `Ok(Pipeline{ occlusion: Err(_), face_identifier_fraud_checks: Err(_), .. })` (currently succeeds) instead of an `Err`.
4. Call `biometric_pipeline()` in `src/plans/mod.rs` with this scenario and assert it currently returns `Ok(Some(pipeline))` — the fix should make this return `Ok(None)`.
5. Assert that with the fix, `enroll_user` is never invoked for this signup (verify via a spy/mock on `enroll_user::Plan::run` or by checking `debug_report.enrollment_status` remains unset).
