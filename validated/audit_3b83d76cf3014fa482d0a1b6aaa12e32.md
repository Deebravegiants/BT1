Audit Report

## Title
Cleartext storage and unrestricted disclosure of External Initiator `OutgoingToken` via `GET /v2/external_initiators` - (File: `core/web/router.go`, `core/web/presenters/external_initiators.go`)

## Summary
The `OutgoingToken` credential used by the Chainlink node to authenticate outgoing webhook calls to registered External Initiators is stored in plaintext and returned in full, unmasked, by `GET /v2/external_initiators` to any authenticated user, including the lowest-privilege `View` role. This is inconsistent with the sibling write endpoints on the same resource, which correctly require Edit role.

## Finding Description
`external_initiators.outgoing_token`/`outgoing_secret` are plain `text` columns [1](#0-0) , generated via `utils.NewSecret` at creation [2](#0-1) . The route `authv2.GET("/external_initiators", paginatedRequest(eia.Index))` is registered with no `auth.RequiresEditRole`/`RequiresAdminRole` wrapper, unlike the `POST`/`DELETE` routes on the same resource that explicitly use `auth.RequiresEditRole` [3](#0-2) . The `Index` handler builds `ExternalInitiatorResource` for every stored initiator with no redaction and no additional authorization check [4](#0-3) , and the presenter includes `OutgoingToken` unmasked [5](#0-4) . The project's own RBAC test table explicitly documents `GET /v2/external_initiators` as `viewOnlyAllowed: true` (i.e., reachable by View role, the least-privileged authenticated role) [6](#0-5) , contrasted with `POST`/`DELETE` on the same path being restricted (`false, false, true`) [7](#0-6) . The RBAC assertion `TestRBAC_Routemap_ViewOnly` confirms View-role sessions receive non-Unauthorized/Forbidden responses for `viewOnlyAllowed` routes [8](#0-7) . The controller test confirms `OutgoingToken` is populated on list responses, not merely at creation [9](#0-8) .

## Impact Explanation
Any authenticated user with only the `View` role — intended for read-only dashboard access, with no ability to create/update/delete resources — can retrieve the plaintext `OutgoingToken` for every registered external initiator. This credential authenticates the node's outgoing calls to third-party external-initiator systems, so its disclosure enables impersonation of the node's outgoing webhook traffic to any registered external initiator, and constitutes exfiltration of a live secret/key beyond the requester's intended privilege boundary. This maps to the in-scope "key/secret exfiltration" and "node API role bypass" impact categories, since a lower-privileged role is able to read data that only Edit/Admin roles are meant to control.

## Likelihood Explanation
Likelihood is high wherever External Initiators are enabled (`JobPipeline.ExternalInitiatorsEnabled`) and the node uses its standard multi-role RBAC model with multiple users of differing privilege. No special network position, admin access, or host/database access is required — only an ordinary authenticated API session/token with the `View` role, which the report demonstrates is sufficient via the project's own RBAC test expectations.

## Recommendation
- Wrap `GET /v2/external_initiators` with at least `auth.RequiresEditRole` (or `RequiresAdminRole`), matching the write operations on the same resource.
- Remove `OutgoingToken`/`OutgoingSecret` from the list/index presenter (`ExternalInitiatorResource`) entirely; only surface them once at creation via `ExternalInitiatorAuthentication`, or mask them for list responses.
- Consider encrypting `outgoing_secret`/`outgoing_token` at rest rather than storing them as plaintext `text` columns.

## Proof of Concept
1. As Admin/Edit user, `POST /v2/external_initiators {"name":"foo"}` and note the returned `outgoingToken` in the `ExternalInitiatorAuthentication` response.
2. Create or use a session/API token for a user with `sessions.UserRoleView` only.
3. As the View-role user, call `GET /v2/external_initiators`.
4. Observe the JSON response includes `outgoingToken` for `foo` in plaintext, matching the value from step 1 — directly reproduced by the existing test assertions `assert.Equal(t, eiFoo.OutgoingToken, externalInitiators[0].OutgoingToken)` combined with the RBAC table entry `{"GET", "/v2/external_initiators", true, true, true}` confirming View-role reachability.

func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}
