### Title
Missing bounds validation on `protocolFeeBps`/destination fees in Tron `IntentGatewayV2.onAccept(UpdateParams)` and `setParams` causes permanent DoS of `placeOrder` via underflow - (File: `evm/tron/contracts/apps/IntentGatewayV2.sol`)

### Summary
The Tron variant of `IntentGatewayV2` accepts governance parameter updates (`RequestKind.UpdateParams`) and initial setup (`setParams`) without validating that `protocolFeeBps` or per-destination `destinationFeeBps` stay below 10,000 (100%). The canonical EVM implementation (`evm/src/apps/intentsv2/IntentsBase.sol`) enforces this invariant via `_validateParams` and an explicit `feeBps >= 10_000` check before writing `_destinationProtocolFees`, but the Tron contract's `onAccept` and `setParams` write `_params`/`_destinationProtocolFees` directly with no equivalent check.

### Finding Description
In `evm/src/apps/intentsv2/IntentsBase.sol`, both `_validateParams` and `_updateParams` guard against unsafe fee values: [1](#0-0) 

The Tron contract's `onAccept` handler for `RequestKind.UpdateParams`, however, decodes the update and assigns it directly to storage — `_params = update.params;` and `_destinationProtocolFees[stateMachineId] = feeBps;` — with no call to any validation function and no `feeBps >= 10_000` (or similar) check: [2](#0-1) 

Likewise, the initial `setParams` function used to bootstrap the contract also skips validation: [3](#0-2) 

The `placeOrder` fee-deduction logic (mirrored from the standard `IntentGatewayV2.sol`) computes:
```
uint256 protocolFee = (originalAmount * protocolFeeBps) / 10_000;
uint256 reducedAmount = originalAmount - protocolFee;
``` [4](#0-3) 

If `protocolFeeBps` (or a destination-specific override) is ever set to a value ≥ 10,000, `protocolFee` exceeds `originalAmount`, and `reducedAmount = originalAmount - protocolFee` underflows and reverts on every subsequent call — this is structurally identical to the `performanceFee`/`lendingAPR()` underflow described in the external report, just applied to `protocolFeeBps`/`placeOrder`.

### Impact Explanation
Once an out-of-range `protocolFeeBps` (or destination-specific fee) is committed via `onAccept(UpdateParams)` — a legitimate, ISMP-authenticated governance message from Hyperbridge, not requiring a malicious actor, only a missing bounds check — every subsequent `placeOrder` call for that gateway/destination underflows and reverts. This permanently bricks the Tron `IntentGatewayV2` for that route: no order can be placed, effectively freezing that bridge/intents path (denial of service against the message dispatch/intents flow), until a further corrective governance update (which itself is unguarded and could reintroduce the bug) is delivered.

### Likelihood Explanation
This requires a single misconfigured governance/admin update (an off-by-one, a mixed-up bps/percent unit, or a destination fee override typo) — there is no on-chain guard to prevent it, unlike the sibling EVM implementation which explicitly prevents this class of misconfiguration. Given the sibling standard contract already had this exact defensive check added, its absence in the Tron variant indicates the fix was not ported, making accidental triggering plausible whenever the Tron deployment's params are updated.

### Recommendation
Add the same validation used in `evm/src/apps/intentsv2/IntentsBase.sol::_validateParams`/`_updateParams` to the Tron `IntentGatewayV2.onAccept` `UpdateParams` branch and to `setParams`: revert if `update.params.protocolFeeBps >= 10_000`, `update.params.surplusShareBps > 10_000`, or any `destinationFees[i].destinationFeeBps >= 10_000` before committing to storage.

### Proof of Concept
1. Hyperbridge (or the initializing admin via `setParams`) submits an `UpdateParams` request/call setting `protocolFeeBps = 10_001` (or a `DestinationFee` entry with `destinationFeeBps >= 10_000`).
2. `onAccept` (or `setParams`) writes this value into `_params`/`_destinationProtocolFees` with no bounds check.
3. Any user calls `placeOrder` with `order.inputs[i].amount = originalAmount`; the contract computes `protocolFee = originalAmount * protocolFeeBps / 10_000 > originalAmount`.
4. `reducedAmount = originalAmount - protocolFee` underflows, and the transaction reverts — reproducing the pattern from the report's `testPocPerformanceFeeCausePOC`, but against `IntentGatewayV2.placeOrder` on Tron instead of `lendingAPR()`.

    function _validateParams(Params memory p) internal view {
        if (p.host == address(0) || p.host.code.length == 0) revert InvalidInput();
        if (p.dispatcher == address(0) || p.dispatcher.code.length == 0) revert InvalidInput();
        if (p.surplusShareBps > 10_000) revert InvalidInput();
        if (p.protocolFeeBps >= 10_000) revert InvalidInput();
        if (p.priceOracle != address(0) && p.priceOracle.code.length == 0) revert InvalidInput();
    }

    /**
     * @dev Updates the gateway's configuration parameters and per-destination protocol fees.
     * Called by Hyperbridge governance to modify fee settings, host address, dispatcher,
     * price oracle, and other operational parameters.
     *
     * Validates all params before applying. Emits ParamsUpdated with the old and new params,
     * then iterates over any destination-specific fee overrides and applies them to
     * `_destinationProtocolFees`.
     *
     * @param update The parameter update containing new params and destination fee overrides.
     */
    function _updateParams(ParamsUpdate memory update) internal {
        _validateParams(update.params);

        emit ParamsUpdated({previous: _params, current: update.params});
        _params = update.params;

        for (uint256 i; i < update.destinationFees.length;) {
            bytes memory chain = update.destinationFees[i].chain;
            uint256 feeBps = update.destinationFees[i].destinationFeeBps;
            if (feeBps >= 10_000) revert InvalidInput();
            _destinationProtocolFees[keccak256(chain)] = feeBps;

            unchecked {
                ++i;
            }
            emit DestinationProtocolFeeUpdated(string(chain), feeBps);
        }
    }
