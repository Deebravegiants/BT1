### Title
Local biometric image deletion is unconditional even when the backend upload request silently fails - ([File: src/agents/image_uploader.rs])

### Summary
`orb-core`'s data-acquisition image uploader mirrors the "underpaying gas causes loss of funds" bug class from the Optimism bridge report: a step whose success is not verified/enforced before an irreversible cleanup action is taken. In `OptimismBridgeFacet`, an underpaid `l2Gas` causes `finalizeDeposit` to silently fail on L2 while the L1 side already committed the deposit, permanently losing user funds. In `orb-core`, `upload_image()` swallows upload failures and always returns `Ok(())`, and the callers (`upload_saved_images`/`upload_signup_images`) unconditionally delete the local biometric image files/directories after the upload attempt regardless of whether the backend actually received the data — permanently losing the only copy of the captured biometric images.

### Finding Description
`upload_image` performs the HTTP request to the backend and, on failure, only increments a metric and logs an error — it never returns the error to the caller: [1](#0-0) 

`upload_saved_images` calls `upload_image` for every file, then unconditionally removes the entire image directory once the loop completes, with no check on whether any individual upload actually succeeded on the backend: [2](#0-1) 

The higher-level `upload_signup_images` follows the same pattern: after invoking the per-category uploads, it unconditionally deletes the entire signup directory (`fs::remove_dir_all(signup_dir)`), destroying all locally retained biometric captures for that signup, whether or not the uploads to the backend succeeded: [3](#0-2) 

Just as the Optimism bridge deducts/locks the user's funds on L1 while the confirming step (`finalizeDeposit`) on L2 can silently fail if `l2Gas` is insufficient — with no on-chain linkage forcing a rollback — here the "commit" step (local deletion) is decoupled from proof of successful completion of the "critical" step (remote upload), so a failure in the critical step (network error, backend rejection, timeout, insufficient credentials, etc.) is masked and the source data is destroyed anyway.

### Impact Explanation
Biometric image data (IR/RGB/thermal/identification images) captured during a signup is stored only locally until successfully uploaded to the backend. If the upload request fails for any transient or backend-side reason, the error is discarded and the local files are deleted regardless, resulting in permanent, unrecoverable loss of biometric capture data for that signup with no automatic retry and no way to recover the images afterward, since the on-disk copy was the sole copy.

### Likelihood Explanation
This code path executes on every idle-state or fraud-detection upload cycle for every signup directory found on disk, via `upload_all_signup_images`: [4](#0-3) 
Any ordinary network blip, backend outage, or transient HTTP error while uploading a signup's images is sufficient to trigger unconditional deletion — no attacker action or privileged access is required.

### Recommendation
Only delete the local image directory/signup directory after positively confirming that all uploads for that batch succeeded (e.g., propagate/aggregate the `Result` from `upload_image` instead of discarding it, and skip/retry deletion on failure). Consider retry-with-backoff before deletion, and keep local retention until an explicit backend acknowledgment is received for the full signup, analogous to recommending users pay sufficient `l2Gas`/verifying `finalizeDeposit` succeeded before treating a bridge deposit as complete.

### Proof of Concept
1. Trigger `Input::StartUpload` so `upload_all_signup_images` runs for a signup directory containing captured images.
2. Simulate a backend failure (e.g., network drop, 5xx response) for the `upload_image::request` call used inside `upload_image` (src/agents/image_uploader.rs:157-160).
3. Because `upload_image` catches the error and only logs/increments a metric before returning `Ok(()))`, `upload_saved_images` proceeds past the loop and executes `fs::remove_dir_all(image_dir)` (line 143), and `upload_signup_images` subsequently executes `fs::remove_dir_all(signup_dir)` (line 190) — deleting the biometric images even though the backend never received them.

async fn upload_all_signup_images(image_upload_delay: Duration) -> Result<()> {
    // This long delay helps prevent uploading images while the Orb is connected to a hotspot (i.e. while doing signups)
    // Generally, Orbs in the field will only be in the idle state beyond "image_upload_delay" if they are connected to
    // Wifi to upload overnight
    spawn_blocking(log_data_to_upload_left).await??;
    sleep(image_upload_delay).await;
    for path in get_signup_paths().await {
        spawn_blocking(log_data_to_upload_left).await??;
        tracing::info!("Starting to upload images from {}", path.display());
        if let Err(err) = upload_signup_images(&path).await {
            tracing::error!("Error uploading signup images from {}: {}", path.display(), err);
        }
    }
    Ok(())
}
