### Title
IntentGatewayV2 predispatch sweep trusts CallDispatcher's total token balance instead of tracking what the current call actually produced - (File: evm/src/apps/IntentGatewayV2.sol)

### Summary
`IntentGatewayV2.placeOrder`'s predispatch branch determines how much of each input token to escrow by reading `IERC20(token).balanceOf(dispatcher)` / `address(dispatcher).balance` — the *entire* current balance of the shared, stateless `CallDispatcher` — rather than measuring the delta produced specifically by the current predispatch call. Because `CallDispatcher` is a single contract shared by every order and every gateway function that uses predispatch/postdispatch calldata, any token balance left sitting on it (from slippage/excess on a previous user's swap, or a direct external donation) is swept in and credited toward whichever order next happens to call `placeOrder` with a matching predispatch for that token.

### Finding Description
In `placeOrder` [1](#0-0) , predispatch assets are sent to the shared `dispatcher` and `order.predispatch.call` (fully attacker/user-controlled calldata) is executed on it. The gateway then builds sweep calls based on the *dispatcher's current balance*, not on what this particular call produced: [2](#0-1) 

and finally computes the escrowed `received` amount from the gateway's own before/after balance: [3](#0-2) 

`dispatcher` is `_params.dispatcher`, a single shared `CallDispatcher` instance used by every call site in the protocol (`placeOrder`'s predispatch, and `IntentsBase._execute`'s postdispatch sweep) [4](#0-3) . `CallDispatcher` itself is a bare, non-custodial forwarder with no access control and a public `receive()` — anyone can send it tokens or ETH directly [5](#0-4) .

Because the code reads `balanceOf(dispatcher)` for the *whole* balance rather than tracking a delta scoped to the current predispatch execution, any token balance that ends up sitting on the dispatcher between transactions — e.g., a prior user's predispatch call producing a byproduct token that isn't listed in that user's `order.inputs` (so it's never swept by their own loop, since that loop only iterates over the caller's declared input tokens) — is available to be claimed. An attacker simply places a new order whose `predispatch.assets`/`predispatch.call` is a trivial no-op for that same token, and whose `order.inputs` includes it; the gateway will sweep the dispatcher's *entire* balance of that token (residual funds included) into `balancesBefore`/`received`, crediting the attacker's order commitment with tokens they never contributed. The identical pattern exists in the Tron variant of the contract [6](#0-5) .

### Impact Explanation
An attacker can escrow input tokens they never funded by claiming any residual balance stranded on the shared `CallDispatcher` (from another user's incomplete sweep or a direct donation), then get a solver to release real output tokens against that inflated/forged escrow commitment. This is a direct theft vector: value flows out of the protocol (to the solver-paid beneficiary or the attacker) that was never actually deposited by the party the commitment claims deposited it, and it corrupts the "reduced input" accounting (`_orders[commitment][token]`) that downstream withdrawal/fill logic in `IntrinsicIntents`/`IntentsBase` relies on as ground truth.

### Likelihood Explanation
Likelihood depends on residual balance existing on the dispatcher (via imperfect predispatch swap byproducts, reverted-but-partially-effective external calls, or a trivial direct token donation by the attacker to grief/park funds and then race their own placeOrder in the very next transaction). Since `CallDispatcher` is a public, permissionless, shared singleton with no balance-zero invariant enforced by the contract, and `placeOrder`'s predispatch calldata is entirely attacker-supplied, an attacker fully controls both the "seeding" and "claiming" transactions. This is reachable by any unprivileged user submitting a single `placeOrder` transaction.

### Recommendation
Do not use `balanceOf(dispatcher)` as the sweep amount. Instead, snapshot the dispatcher's balance for each relevant token *before* executing `order.predispatch.call`, and only sweep/credit the delta (balance-after minus balance-before) that this specific predispatch execution produced — mirroring the delta-based approach already used for the gateway's own balance in the "measure actual received" step. Additionally, consider making `CallDispatcher` per-call/ephemeral (or asserting it holds zero balance of relevant tokens at the start of each dispatch cycle) so stray balances cannot accumulate and be claimed by unrelated orders.

### Proof of Concept
1. Attacker (or any user, even accidentally) causes the shared `CallDispatcher` to hold a nonzero balance of token `X` that is not fully swept by the owning order (e.g., a predispatch swap that returns a byproduct token not listed in that order's `inputs`, or attacker directly `transfer()`s token `X` to the known `CallDispatcher` address).
2. Attacker calls `placeOrder` with `predispatch.assets = [{token: Y, amount: 1}]` (any trivial token/amount) and a no-op `predispatch.call`, and `order.inputs = [{token: X, amount: <residual balance>}]`.
3. In the sweep step, `balance = IERC20(X).balanceOf(dispatcher)` returns the full residual balance (not something the attacker's own predispatch call produced); since `balance >= requiredAmount`, the entire balance is transferred to the gateway and credited via `received`/`order.inputs[i].amount` to the attacker's order commitment.
4. Attacker's order now escrows token `X` that they never funded; a solver later fills it and pays out real output tokens, completing the theft.

    receive() external payable {}

    /**
     *  @dev reverts if the target is not a contract or if any of the calls reverts.
     */
    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
