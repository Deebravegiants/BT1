### Title
Permanent market freeze from aggregate scaled-balance overflow during interest accrual - (File: common/src/rates/scaling.rs)

### Summary

A sufficiently large market can permanently freeze after interest accrual because each accrual step unscales aggregate `borrowed` and `supplied` shares into `i128` before applying the configured index ceiling. [1](#0-0)  The permissionless controller `update_indexes` path reaches this code, and every subsequent pool mutation accrues through the same path before processing the requested operation. [2](#0-1) [3](#0-2) 

### Finding Description

`controller::update_indexes(caller, assets)` is permissionless and only requires `caller` authorization before forwarding `assets` to the pool. [4](#0-3)  The pool's `update_indexes` owner call delegates to `ops::market::accrue`, which loads each market and invokes `interest::global_sync`. [5](#0-4) [6](#0-5) 

`global_sync` splits elapsed time into bounded chunks and calls `accrue_chunk` for each chunk. [7](#0-6)  `accrue_chunk` calls `accrue_step`, whose first operation converts both aggregate scaled balances with `scaled_to_original`. [8](#0-7) [9](#0-8)  That conversion is `scaled.mul(index)`, so it fails once the aggregate value `scaled * index / RAY` exceeds the `i128` result domain. [10](#0-9) 

The index ceiling does not prevent this condition because `update_borrow_index` only clamps the index after computing the next index, while the aggregate-value multiplication occurs before that update on the next accrual. [11](#0-10)  `MAX_BORROW_INDEX_RAY` is `1e36`, approximately a one-billion-times index, but aggregate shares around `1e36` overflow once the index exceeds roughly `170 * RAY`, far below the configured index ceiling. [12](#0-11) 

The repository's own regression test demonstrates this boundary with one billion 18-decimal tokens and 98% borrowed utilization. [13](#0-12)  The test shows that `update_indexes` eventually returns `MathOverflow` while the borrow index is still below `MAX_BORROW_INDEX_RAY`, after which both `withdraw` and `repay` fail with the same error. [14](#0-13) 

### Impact Explanation

Once the aggregate scaled balance and index cross the representable-value boundary, every mutating pool operation for that market calls `global_sync` before performing the operation. [3](#0-2)  Consequently, suppliers cannot withdraw, borrowers cannot repay, new borrowing or supply is unavailable, and liquidation pool legs cannot proceed. [15](#0-14) [16](#0-15) 

Because the panic occurs before `mark_accrued` or a market commit, the state remains at an earlier timestamp and retries cannot advance past the failing multiplication. [17](#0-16) [18](#0-17)  This permanently freezes the market's pool funds absent a privileged contract migration or other out-of-scope recovery mechanism. [19](#0-18) 

### Likelihood Explanation

The trigger requires an unusually large aggregate scaled balance together with sustained high interest accrual, so ordinary markets may never reach the boundary. [13](#0-12)  No privileged role, leaked key, oracle manipulation, or contract vulnerability outside the arithmetic bound is needed once such a market exists: a funded unprivileged account can supply the liquidity and collateral, borrow against it, and repeatedly call `update_indexes`. [4](#0-3) [20](#0-19)  The severity of the resulting state is high because all funds in the affected market become inaccessible, although the market size and accrual conditions make exploitation dependent on a sufficiently large supported market. [19](#0-18) 

### Recommendation

Compute utilization directly from widened `I256` products, or otherwise compare `borrowed * borrow_index` and `supplied * supply_index` without first materializing each product as `i128`. [21](#0-20)  Alternatively, enforce a stricter global invariant at market creation, cap validation, and each mint so that `supplied * MAX_SUPPLY_INDEX_RAY / RAY` and `borrowed * MAX_BORROW_INDEX_RAY / RAY` remain representable. [12](#0-11)  Add a production regression test equivalent to the existing whale-market test that verifies `update_indexes`, `withdraw`, `repay`, and liquidation remain executable near the `i128` aggregate-value boundary. [22](#0-21) 

### Proof of Concept

1. Use an existing 18-decimal market with sufficient configured caps and a separate collateral market. [23](#0-22) 
2. An unprivileged funded account supplies `1_000_000_000 * 10^18` units of the 18-decimal asset through `controller::supply`. [24](#0-23) 
3. The same or another unprivileged funded account supplies sufficient collateral and calls `controller::borrow` for `980_000_000 * 10^18` units, producing 98% utilization. [25](#0-24) 
4. Any caller periodically invokes `controller::update_indexes(caller, vec![hub_asset])`; after the aggregate value crosses the `i128` boundary, the call returns `MathOverflow` while `borrow_index < MAX_BORROW_INDEX_RAY`. [26](#0-25) 
5. Subsequent `withdraw` and `repay` calls return `MathOverflow`, demonstrating that the market can no longer process exits or debt repayment. [27](#0-26)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);

    let amount = action.amount;

    let (burned, overpayment) = cache.resolve_repay(amount, position);
