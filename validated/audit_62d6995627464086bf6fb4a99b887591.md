### Title
Unauthenticated `/v2/resume/:runID` endpoint allows anyone who obtains a pending task UUID to inject arbitrary bridge/adapter results into a job run - ([File: core/web/pipeline_runs_controller.go])

### Summary
The external report describes a Uniswap `Quoter` swap that is invoked with `sqrtPriceLimitX96 = 0`, meaning `Vault::claimTokens` is a public, unauthenticated action that will execute a trade at **any** price supplied by whoever calls it, allowing an unprivileged actor to manipulate the outcome via sandwich trades. The underlying bug class is: *a state-mutating, outcome-determining action is reachable by an unauthenticated/unprivileged caller with no validation that the supplied data actually originated from the expected trusted source.*

The closest analog in this chainlink node codebase is the `PATCH /v2/resume/:runID` route, which is deliberately placed in the **unauthenticated** router group and lets the caller supply an arbitrary `value`/`error` JSON payload that is written directly into the pipeline task's result and used to resume/complete the job run.

### Finding Description
`v2Routes` registers the resume endpoint outside of any authentication middleware: [1](#0-0) 

`PipelineRunsController.Resume` accepts the request body as-is and forwards it to `App.ResumeJobV2` with no authentication, no signature, and no check that the caller is the original bridge/external-adapter that was asked to perform the async work: [2](#0-1) 

The only "secret" gating this endpoint is the task's UUID, `taskID`, taken directly from the URL path segment `:runID` (`uuid.Parse(c.Param("runID"))`). This value is generated per async task and handed to bridge/external adapters as part of a callback `ResponseURL` (`<node>/v2/resume/<uuid>`), as seen in the async bridge-task flow and tests: [3](#0-2) 

`ResumeRun`/`UpdateTaskRunResult` then blindly write the caller-supplied `Result` (value or error) into the pending task row and resume the pipeline run without validating who submitted it or that it came from the adapter the task was dispatched to: [4](#0-3) [5](#0-4) 

This mirrors the report's bug class: a publicly reachable action that determines the ultimate result/value of a state transition, with the only safeguard being an opaque identifier rather than real authentication of the counterparty, and with no verification that the returned data is consistent with what was actually requested.

### Impact Explanation
If a `taskID` UUID is disclosed, leaked (e.g., via logs, error messages, a compromised/observed external adapter, or a misbehaving/poorly secured third-party bridge that exposes the callback URL), an unprivileged actor can `PATCH /v2/resume/<uuid>` with a forged `value`/`error` and:
- Poison the output of a price/data feed task that feeds downstream OCR/FluxMonitor/VRF logic, analogous to how the audited `Vault` swap allows an attacker to force an arbitrary, favorable price into the protocol's state.
- Prematurely resolve or fail a pending job run with attacker-chosen data, since `UpdateTaskRunResult` performs no authentication of the submitter — only a "does this row exist & is pending" check.

### Likelihood Explanation
Likelihood is bounded by UUIDv4's ~122 bits of entropy, so blind brute-forcing of `taskID` is impractical. However, `WebServer.RateLimit` for unauthenticated endpoints (5 req/20s by default) confirms the endpoint is explicitly designed to be internet-facing and unauthenticated, and the confidentiality of the task UUID depends entirely on downstream external-initiator/bridge implementations (outside chainlink node's control) not leaking it, and on it not being guessable/predictable in some external-adapter integration flows. This is a design-level trust assumption rather than a directly provable, code-level authentication bypass, so I could not confirm a concrete disclosure vector for the UUID within this codebase.

### Recommendation
- Require the resume endpoint to authenticate the request against a per-bridge/per-task secret negotiated when the async task was originally dispatched (not merely the UUID embedded in the callback URL), or sign/HMAC the callback URL.
- Add defense-in-depth validation of the returned `value`/`error` against an expected schema/type for the corresponding task, and audit-log all resume calls with source IP to aid detection of abuse (`audit.UnauthedRunResumed` already exists and should be reviewed for adequacy).
- Consider a short expiry on pending task UUIDs and one-time-use enforcement on top of the existing "must be pending" check (already present in `UpdateTaskRunResult`'s `WHERE ... state in ('running','suspended')` clause) to reduce the exposure window.

### Proof of Concept
1. An operator creates a job with an `async=true` bridge task; the node dispatches a request to an external adapter with `ResponseURL: http://<node>/v2/resume/<taskUUID>` (see `task.bridge_test.go` assertion of this URL format).
2. If an unprivileged party obtains `<taskUUID>` (e.g., via a compromised/observing external adapter, network capture, or a misconfigured/logged callback), they issue:
   ```
   curl -X PATCH http://<node>/v2/resume/<taskUUID> \
     -H "Content-Type: application/json" \
     -d '{"value": "<attacker-chosen data>"}'
   ```
   No authentication headers are required — the route sits in the `unauthedv2` gin group (`core/web/router.go:243`).
3. `PipelineRunsController.Resume` decodes the body, calls `App.ResumeJobV2` → `runner.ResumeRun` → `orm.UpdateTaskRunResult`, which writes the attacker's `value` into the pending task row and resumes the run, feeding the forged data into any downstream task (e.g., price aggregation, on-chain submission) exactly as if the legitimate external adapter had responded.

// Resume finishes a task and resumes the pipeline run.
// Example:
// "PATCH <application>/jobs/:ID/runs/:runID"
func (prc *PipelineRunsController) Resume(c *gin.Context) {
	taskID, err := uuid.Parse(c.Param("runID"))
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	rr := pipeline.ResumeRequest{}
	decoder := json.NewDecoder(c.Request.Body)
	err = errors.Wrap(decoder.Decode(&rr), "failed to unmarshal JSON body")
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	result, err := rr.ToResult()
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	if err := prc.App.ResumeJobV2(c.Request.Context(), taskID, result); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
	c.Status(http.StatusOK)
}

func (r *runner) ResumeRun(ctx context.Context, taskID uuid.UUID, value any, err error) error {
	run, start, err := r.orm.UpdateTaskRunResult(ctx, taskID, Result{
		Value: value,
		Error: err,
	})
	if err != nil {
		return fmt.Errorf("failed to update task run result: %w", err)
	}

	// TODO: Should probably replace this with a listener to update events
	// which allows to pass in a transactionalised database to this function

		// start the runner again

			ctx, cancel := r.chStop.NewCtx()
			defer cancel()
			if _, err := r.Run(ctx, &run, false, nil); err != nil {
				r.lggr.Errorw("Resume run failure", "err", err)
			}
			r.lggr.Debug("Resume run success")
		}()
	}
	return nil
}

func (o *orm) UpdateTaskRunResult(ctx context.Context, taskID uuid.UUID, result Result) (run Run, start bool, err error) {
	if result.OutputDB().Valid && result.ErrorDB().Valid {
		panic("run result must specify either output or error, not both")
	}
	err = o.transact(ctx, func(tx *orm) error {
		sql := `
		SELECT pipeline_runs.*, pipeline_specs.dot_dag_source "pipeline_spec.dot_dag_source", job_pipeline_specs.job_id "job_id"
		FROM pipeline_runs
		JOIN pipeline_task_runs ON (pipeline_task_runs.pipeline_run_id = pipeline_runs.id)
		JOIN pipeline_specs ON (pipeline_specs.id = pipeline_runs.pipeline_spec_id)
		JOIN job_pipeline_specs ON (job_pipeline_specs.pipeline_spec_id = pipeline_specs.id)
		WHERE pipeline_task_runs.id = $1 AND pipeline_runs.state in ('running', 'suspended')
		FOR UPDATE`
		if err = tx.ds.GetContext(ctx, &run, sql, taskID); err != nil {
			return fmt.Errorf("failed to find pipeline run for task ID %s: %w", taskID.String(), err)
		}

		// Update the task with result
		sql = `UPDATE pipeline_task_runs SET output = $2, error = $3, finished_at = $4 WHERE id = $1`
		if _, err = tx.ds.ExecContext(ctx, sql, taskID, result.OutputDB(), result.ErrorDB(), time.Now()); err != nil {
			return fmt.Errorf("failed to update pipeline task run: %w", err)
		}

		if run.State == RunStatusSuspended {
			start = true
			run.State = RunStatusRunning

			sql = `UPDATE pipeline_runs SET state = $2 WHERE id = $1`
			if _, err = tx.ds.ExecContext(ctx, sql, run.ID, run.State); err != nil {
				return fmt.Errorf("failed to update pipeline run state: %w", err)
			}
		}

		return loadAssociations(ctx, tx.ds, []*Run{&run})
	})

	return run, start, err
}
