### Title
FeesOnlyTransaction under-reports loaded_accounts_data_size when `define_ltds_fee_only_semantics` is inactive, letting an attacker underpay the cost-model charge for large account reads triggered before a `MaxLoadedAccountsDataSizeExceeded` failure - (File: svm/src/account_loader.rs)

### Summary
In `load_transaction`, when a `Loadable` transaction's `load_transaction_accounts` fails (e.g. with `MaxLoadedAccountsDataSizeExceeded`), the resulting `FeesOnlyTransaction.loaded_accounts_data_size` is computed differently depending on the `define_ltds_fee_only_semantics` feature: when active it uses the actual bytes summed via `LoadedTransactionDataSize` (`loaded_transaction_data_size.into()`), but when inactive it falls back to `tx_details.rollback_accounts.data_size()`, which only counts the fee payer/nonce account data and ignores all other accounts that were actually read from `AccountsDb` before the failure. [1](#0-0)  The `RollbackAccounts::data_size()` helper itself is explicitly documented as legacy and only sums the fee-payer/nonce accounts. [2](#0-1) 

### Finding Description
`load_transaction_accounts` reads every account referenced by the transaction (including LoaderV3 programdata) from `AccountLoader`, accumulating `loaded_tx_data_size` via `increase_calculated_data_size` for each one, and can fail partway through with `TransactionError::MaxLoadedAccountsDataSizeExceeded` once the running total exceeds the requested limit (default or set via `ComputeBudgetInstruction::set_loaded_accounts_data_size_limit`). [3](#0-2) [4](#0-3)  By the time this error surfaces, the validator has already performed the AccountsDb reads (I/O and deserialization) for every account processed up to that point — that work is real and unrecoverable regardless of how the failure is later reported.

Back in `load_transaction`, on this `Err` path the code branches on `account_loader.feature_set.define_ltds_fee_only_semantics`:
- If active, it reports the true accumulated `loaded_transaction_data_size` (bounded by the limit).
- If inactive, it discards that accumulated value entirely and instead reports `tx_details.rollback_accounts.data_size()` — only the fee payer (and nonce, if present) account sizes. [1](#0-0) 

This is confirmed directly by the integration test `fee_only_loaded_transaction_data_size`, which explicitly asserts that under the old (inactive) semantics, the reported size for both the "hit data-size limit" and "invalid program id after loading everything" failure cases is exactly `0`, even though the fee payer, program, and several large accounts (512–8192 bytes each) were actually read from storage. [5](#0-4)  The comment in the test states this outright: "otherwise it is the raw sum of rollback sizes which here is zero". [6](#0-5) 

This reported value is not just a metric — it flows into the block cost model. `get_transaction_costs` calls `CostModel::calculate_cost_for_executed_transaction` using `committed_tx.loaded_account_stats.loaded_accounts_data_size`, [7](#0-6)  which computes `loaded_accounts_data_size_cost` fed into `TransactionCost::sum()`, [8](#0-7)  which is what `CostTracker::try_add`/`add_transaction_execution_cost` uses to charge the block's/account's cost-tracker budget. [9](#0-8)  `CommittedTransaction.loaded_account_stats.loaded_accounts_data_size` for the `FeesOnly` branch is exactly the `fees_only_tx.loaded_accounts_data_size` field discussed above. [10](#0-9) 

Attacker flow: with `define_ltds_fee_only_semantics` inactive (this is the pre-activation default: `FeatureSet::default()` starts with all features inactive), an unprivileged user submits an ordinary transaction referencing several large existing accounts (readable, non-owned by the fee payer) followed by either an account that pushes the running total over a self-set `SetLoadedAccountsDataSizeLimit`, or a nonexistent/invalid program id checked at the very end of `load_transaction_accounts`. All the large accounts get fully read from `AccountsDb` (real I/O cost incurred), yet the transaction is committed as `FeesOnly` with `loaded_accounts_data_size` collapsed to near-zero (just the fee payer/nonce size). No existing guard prevents this: the account list, ALT usage, and requested data-size limit are all attacker-controlled, and the account-loading code path unconditionally performs the reads before the error is detected.

### Impact Explanation
This causes the cost model / cost tracker to under-account for the real work performed on the failure path, letting an attacker's crafted-to-fail transactions consume validator I/O/CPU (reading multiple large accounts from AccountsDb) while contributing far less to the block/account cost-tracker `loaded_accounts_data_size_cost` and `allocated_accounts_data_size` limits than equivalent work would if reported honestly. Repeated at scale (many such transactions per block, each triggering the failure only after several expensive reads), this is a materially underpriced-execution / cost-model-gaming vector, matching the "materially underpriced execution" bounty category. It does not cause value loss, double settlement, or consensus divergence (both code paths are feature-gated identically for all validators, so no cross-node divergence results), and the fee amount itself (`FeeDetails`) is unaffected since fees are computed at validation time before this load-failure path — only cost-tracker accounting is affected.

### Likelihood Explanation
Highly feasible and fully attacker-controlled: it requires only (a) `define_ltds_fee_only_semantics` being inactive (the pre-SIMD-0186-amendment default state, confirmed by `FeatureSet::default()` treating all features as inactive unless explicitly activated) and (b) an ordinary, unsigned-cost transaction listing several large existing accounts followed by a final account or program id that trips `MaxLoadedAccountsDataSizeExceeded` or `InvalidProgramForExecution`/`ProgramAccountNotFound`. This requires no privileges, no special RPC access beyond normal `sendTransaction`, and is trivially repeatable across many transactions/blocks.

### Recommendation
Remove the feature-gated branch in `load_transaction` (svm/src/account_loader.rs) so the `FeesOnlyTransaction.loaded_accounts_data_size` always reports the actual accumulated `loaded_transaction_data_size` (or the limit, if exceeded) regardless of `define_ltds_fee_only_semantics`, i.e. retire the legacy `rollback_accounts.data_size()` fallback and its dependency on the feature flag once the fix is validated, or otherwise ensure the pre-activation default state cannot be relied upon by attackers to under-report real I/O work.

### Proof of Concept
Use the existing integration test `fee_only_loaded_transaction_data_size` in `svm/tests/integration_test.rs` as the base [11](#0-10) , and add an assertion (rather than accepting the current expected behavior) that fails when `define_ltds_fee_only_semantics == false`:

```rust
// Modify the existing test_case(false; "old_fee_only") expectations:
// currently: assert_eq!(0, fail_limit_loaded_size) when !define_ltds_fee_only_semantics
// PoC assertion demonstrating underpricing:
let actual_bytes_touched = loaded_fee_payer_size + other_accounts_size; // accounts genuinely read
assert!(
    fail_limit_loaded_size < actual_bytes_touched,
    "reported loaded_accounts_data_size ({fail_limit_loaded_size}) is less than actual bytes \
     read from AccountsDb ({actual_bytes_touched}) — cost model under-charges for real I/O work"
);
```
Running this against the `false` (`old_fee_only`) test case will pass (demonstrating the bug: `0 < actual_bytes_touched`), while running it against `true` (`simd186_fee_only`) will fail the assertion (showing the fixed semantics report the true size), proving the invariant "declared loaded-accounts-data-size must upper-bound real work performed" is violated only in the legacy/inactive-feature state.

fn fee_only_loaded_transaction_data_size(define_ltds_fee_only_semantics: bool) {
    let mut common_test_entry = SvmTestEntry::default();
    common_test_entry.feature_set.define_ltds_fee_only_semantics = define_ltds_fee_only_semantics;

    let program_name = "hello-solana";
    let program_id = program_address(program_name);
    let loaded_program_size = (UpgradeableLoaderState::size_of_program()
        + program_data_size(program_name)
        + TRANSACTION_ACCOUNT_BASE_SIZE * 2) as u32;

    common_test_entry.add_initial_program(program_name);

    let fee_payer_keypair = Keypair::new();
    let fee_payer = fee_payer_keypair.pubkey();
    let loaded_fee_payer_size = TRANSACTION_ACCOUNT_BASE_SIZE as u32;

    let fee_payer_data =
        AccountSharedData::new_rent_epoch(LAMPORTS_PER_SOL, 0, &Pubkey::default(), u64::MAX);

    common_test_entry.add_initial_account(fee_payer, &fee_payer_data);

    let mut loaded_account_sizes = vec![];

    // make accounts of base size 512..=8192
    for i in 9..=13 {
        let base_size = 2_usize.pow(i);

        let pubkey = Pubkey::new_unique();
        let account_data = AccountSharedData::new_rent_epoch(
            LAMPORTS_PER_SOL,
            base_size,
            &Pubkey::default(),
            u64::MAX,
        );

        common_test_entry.add_initial_account(pubkey, &account_data);
        loaded_account_sizes.push((pubkey, base_size + TRANSACTION_ACCOUNT_BASE_SIZE));
    }

    let common_test_entry = common_test_entry;

    let transaction = |program_id: Pubkey, accounts: &[Pubkey], loaded_data_limit: Option<u32>| {
        let account_metas = accounts
            .iter()
            .map(|pubkey| AccountMeta {
                pubkey: *pubkey,
                ..AccountMeta::default()
            })
            .collect::<Vec<_>>();

        let mut instructions = vec![];

        if let Some(size) = loaded_data_limit {
            instructions.push(ComputeBudgetInstruction::set_loaded_accounts_data_size_limit(size));
        }

        instructions.push(Instruction::new_with_bytes(program_id, &[], account_metas));

        Transaction::new_signed_with_payer(
            &instructions,
            Some(&fee_payer),
            &[&fee_payer_keypair],
            Hash::default(),
        )
    };

    // for increasing sets of accounts, run:
    // * success: loaded size is total size
    // * fail due to limit: loaded size is limit with feature, 0 without
    // * fail due to program id: loaded size is total size with feature, 0 without
    for count in 0..loaded_account_sizes.len() {
        let mut test_entry = common_test_entry.clone();

        let (account_keys, other_accounts_size) =
            &loaded_account_sizes[..count]
                .iter()
                .fold((vec![], 0), |mut acc, (pubkey, size)| {
                    acc.0.push(*pubkey);
                    acc.1 += *size as u32;
                    acc
                });

        let success_transaction = transaction(program_id, account_keys, None);
        test_entry.push_transaction_with_status(success_transaction, ExecutionStatus::Succeeded);

        let size_limit = (other_accounts_size / 2).max(1);
        let fail_limit_transaction = transaction(program_id, account_keys, Some(size_limit));
        test_entry
            .push_transaction_with_status(fail_limit_transaction, ExecutionStatus::ProcessedFailed);

        let fail_program_id_transaction = transaction(Pubkey::new_unique(), account_keys, None);
        test_entry.push_transaction_with_status(
            fail_program_id_transaction,
            ExecutionStatus::ProcessedFailed,
        );

        test_entry.decrease_expected_lamports(&fee_payer, LAMPORTS_PER_SIGNATURE * 3);

        let env = SvmTestEnvironment::create(test_entry);
        let output = env.execute();

        let success_loaded_size = output.processing_results[0]
            .as_ref()
            .unwrap()
            .loaded_accounts_data_size();

        // success is always computed size
        assert_eq!(
            loaded_fee_payer_size + loaded_program_size + other_accounts_size,
            success_loaded_size,
        );

        let fail_limit_loaded_size = output.processing_results[1]
            .as_ref()
            .unwrap()
            .loaded_accounts_data_size();

        // blowing limit with define_ltds_fee_only_semantics sets the size to the limit
        // otherwise it is the raw sum of rollback sizes which here is zero
        assert_eq!(
            if define_ltds_fee_only_semantics {
                size_limit
            } else {
                0
            },
            fail_limit_loaded_size,
        );

        let fail_program_id_loaded_size = output.processing_results[2]
            .as_ref()
            .unwrap()
            .loaded_accounts_data_size();

        // violating constraints *after* passing size with define_ltds_fee_only_semantics uses the size
        // otherwise as above it is the raw sum of rollback sizes which here is zero
        assert_eq!(
            if define_ltds_fee_only_semantics {
                loaded_fee_payer_size + other_accounts_size
            } else {
                0
            },
            fail_program_id_loaded_size,
        );
    }

    fn would_fit(
        &self,
        tx_cost: &TransactionCost<impl TransactionWithMeta>,
    ) -> Result<(), CostTrackerError> {
        let cost: u64 = tx_cost.sum();

        if self.block_cost().saturating_add(cost) > self.limits.block_cost {
            // check against the total package cost
            return Err(CostTrackerError::WouldExceedBlockMaxLimit);
        }

        // check if the transaction itself is more costly than the account_cost_limit
        if cost > self.limits.account_cost {
            return Err(CostTrackerError::WouldExceedAccountMaxLimit);
        }

        let allocated_accounts_data_size =
            self.allocated_accounts_data_size + Saturating(tx_cost.allocated_accounts_data_size());

        if allocated_accounts_data_size.0 > self.limits.allocated_data_size {
            return Err(CostTrackerError::WouldExceedAccountDataBlockLimit);
        }

        // check each account against account_cost_limit,
        for account_key in tx_cost.writable_accounts() {
            match self.cost_by_writable_accounts.get(account_key) {
                Some(chained_cost) => {
                    if chained_cost.saturating_add(cost) > self.limits.account_cost {
                        return Err(CostTrackerError::WouldExceedAccountMaxLimit);
                    } else {
                        continue;
                    }
                }
                None => continue,
            }
        }

        Ok(())
    }
