**Analysis:**

The script cache key is not an "address/module key" — it is the SHA3-256 hash of the script's own serialized bytecode, computed directly from the content being cached: [1](#0-0) 

Both `unmetered_deserialize_and_cache_script` and `unmetered_verify_and_cache_script` (and the lazy-loader equivalent) compute `let hash = sha3_256(serialized_script);` and use that hash as the sole key for `insert_deserialized_script`/`insert_verified_script`/`get_script`. [2](#0-1) [3](#0-2) 

`UnsyncCodeStorage`'s `script_cache` field is typed `UnsyncScriptCache<[u8; 32], CompiledScript, Script>`, and `UnsyncScriptCache::get_script`/`insert_*` simply do a plain `HashMap` lookup/insert keyed by that `[u8;32]` hash: [4](#0-3) 

For the described attack to succeed, an attacker would need two *different* scripts (one legitimate, one malicious) whose serialized bytecode produces the *same* SHA3-256 digest — i.e., a full SHA3-256 second-preimage/collision. This is computationally infeasible and outside the threat model of "unprivileged attacker crafting transaction/script inputs." The key is not derived from any address, module identifier, or "security domain" label that an attacker could spoof or reuse — it is a cryptographic hash of the exact bytes that will later be resolved, so `get_script` returning a hit for a given hash by construction returns bytecode whose content matches that hash. There is no mechanism here for cross-domain resolution, ownership confusion, or authority leakage related to resource accounts, multisig, or object custody — the script cache is a pure content-addressed memoization structure scoped to a single code-storage instance/session, not a custody or authorization surface.

Since exploiting this requires breaking SHA3-256 collision resistance rather than any logic flaw in cache-key derivation or lookup, this does not cross a real custody boundary and does not meet the bar of unprivileged-input-driven ownership/authority compromise.

impl<K, D, V> ScriptCache for UnsyncScriptCache<K, D, V>
where
    K: Eq + Hash + Clone,
    V: Deref<Target = Arc<D>>,
{
    type Deserialized = D;
    type Key = K;
    type Verified = V;

    fn insert_deserialized_script(
        &self,
        key: Self::Key,
        deserialized_script: Self::Deserialized,
    ) -> Arc<Self::Deserialized> {
        use hashbrown::hash_map::Entry::*;

        match self.script_cache.borrow_mut().entry(key) {
            Occupied(entry) => entry.get().deserialized().clone(),
            Vacant(entry) => entry
                .insert(Code::from_deserialized(deserialized_script))
                .deserialized()
                .clone(),
        }
    }

    fn insert_verified_script(
        &self,
        key: Self::Key,
        verified_script: Self::Verified,
    ) -> Arc<Self::Verified> {
        use hashbrown::hash_map::Entry::*;

        match self.script_cache.borrow_mut().entry(key) {
            Occupied(mut entry) => {
                if !entry.get().is_verified() {
                    let new_script = Code::from_verified(verified_script);
                    let verified_script = new_script.verified().clone();
                    entry.insert(new_script);
                    verified_script
                } else {
                    entry.get().verified().clone()
                }
            },
            Vacant(entry) => entry
                .insert(Code::from_verified(verified_script))
                .verified()
                .clone(),
        }
    }

    fn get_script(&self, key: &Self::Key) -> Option<Code<Self::Deserialized, Self::Verified>> {
        self.script_cache.borrow().get(key).cloned()
    }

    fn num_scripts(&self) -> usize {
        self.script_cache.borrow().len()
    }
}
