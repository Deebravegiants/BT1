### Title
Interest accrual overflow permanently freezes an oversized market - (File: `common/src/rates/scaling.rs`)

### Summary
A market whose RAY-scaled debt or supply value exceeds `i128::MAX` cannot accrue indexes because `accrue_step` evaluates the old balances before applying the borrow-index cap, causing a permanent `MathOverflow` on repayment, withdrawal, liquidation, and maintenance paths. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`accrue_step` first unscales `borrowed` and `supplied` through `scaled_to_original`, which delegates to `Ray::mul`. [4](#0-3) [5](#0-4)   
`mul_div_half_up` uses an `i128` fast path and an exact `I256` intermediate, but still panics when the resulting quotient cannot fit into `i128`. [6](#0-5) [7](#0-6)   
The borrow-index ceiling is applied only after that old balance valuation, so it cannot prevent the overflow. [2](#0-1)   
An unprivileged account can create the precondition through `supply` and `borrow`, and any unprivileged caller can later trigger the failure through `update_indexes(caller, assets)`, which forwards the selected `HubAssetKey` list to the pool. [8](#0-7) [9](#0-8)   
Pool `supply`, `borrow`, `withdraw`, and `repay` all execute through accrual-aware operations, while `update_indexes` directly runs market accrual. [10](#0-9)   
The repository’s regression test demonstrates the exact cliff: a one-billion-whole-token, 18-decimal market at 98% utilization eventually fails `update_indexes` with `MATH_OVERFLOW` before `MAX_BORROW_INDEX_RAY`, after which withdrawal and repayment also fail. [11](#0-10) 

### Impact Explanation
Once `scaled_to_original` overflows, the failed accrual repeats before state can advance, so the market is permanently frozen rather than temporarily unavailable. [12](#0-11) [1](#0-0)   
Suppliers cannot withdraw, borrowers cannot repay, keepers cannot accrue the market, and liquidators cannot clear the position through paths that accrue first. [3](#0-2)   
This is a permanent freezing of user funds and protocol debt settlement in the affected market. [13](#0-12) 

### Likelihood Explanation
The attack requires an extremely large listed market, enough collateral for near-total utilization, and sustained accrual until `scaled_shares * index / RAY` exceeds the `i128` domain. [14](#0-13)   
Those requirements make exploitation dependent on deployed liquidity, caps, price viability, and time, but no privileged runtime action is needed after the market admits the relevant position sizes. [8](#0-7) [9](#0-8)   
Because the failure permanently locks all funds in that market once reached, the issue is appropriately rated Medium despite its demanding preconditions. [13](#0-12) 

### Recommendation
Bound scaled share balances and accrued values to a safe domain below the point where `scaled_to_original` can overflow, or replace the accrual path’s total-value calculations with saturating/wider arithmetic that preserves a usable state. [1](#0-0) [5](#0-4)   
At minimum, apply `MAX_BORROW_INDEX_RAY` before evaluating old debt, clamp or decompose oversized RAY values, and enforce market caps tightly enough that `scaled * index` cannot reach the overflow boundary. [2](#0-1) [15](#0-14)

/// Computes `x * y / d` rounded half up. Requires `x >= 0`, `y >= 0`, and `d > 0`; a
/// `debug_assert` checks this in debug builds. Panics with `GenericError::DivisionByZero` if
/// `d == 0`, and with `GenericError::MathOverflow` if any other precondition is violated or if
/// the result does not fit in `i128`.
pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    // The zero check runs first so debug and release builds agree on a zero
    // divisor: both surface `DivisionByZero` rather than tripping the assert.
    require_nonzero_divisor(env, d);
    debug_assert!(
        x >= 0 && y >= 0 && d > 0,
        "mul_div_half_up: non-negative x, y and positive d"
    );
    try_mul_div_half_up(env, x, y, d)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
}

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
