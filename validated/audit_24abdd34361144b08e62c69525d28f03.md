Audit Report

## Title
CORS Origin Allowlist Bypass via Naive Suffix Matching in Gateway HTTP Server (Wildcard Bailiwick Violation) - ([File: core/services/gateway/network/httpserver.go])

## Summary
`isAllowedOrigin` in `core/services/gateway/network/httpserver.go` implements wildcard CORS origin matching using `strings.HasSuffix(originHost, allowedHost)` after stripping the `*.` prefix, without checking for a literal `.` boundary before the match. This allows an attacker who registers a domain merely ending in the same characters as the configured suffix (e.g., `evilremix.com` for an allowlist entry `*.remix.com`) to have their origin accepted and reflected back in `Access-Control-Allow-Origin`.

## Finding Description
The code at [1](#0-0)  strips the `*.` prefix from the configured allowed host and then performs a raw substring suffix check with no requirement that the character immediately preceding the match be a `.`. This is confirmed directly in the current source: for an entry `*.remix.com`, `allowedHost` becomes `remix.com`, and `strings.HasSuffix("evilremix.com", "remix.com")` evaluates to `true`, incorrectly treating `evilremix.com` as a subdomain of `remix.com`.

This function is called from `handleRequest`, the sole handler for all inbound requests on the gateway's public HTTP path, which reflects the attacker-supplied `Origin` header verbatim into `Access-Control-Allow-Origin` once `isAllowedOrigin` returns true: [2](#0-1) . No additional validation (dot-boundary check, exact suffix normalization, or canonicalization) is applied before or after this check, so the flawed match is the sole gate for the wildcard branch.

The existing test suite exercises only correct-suffix scenarios (`ethereum.remix.org` not matching `*.ethereum.org` because it doesn't end with the string, and `another.valid.domain.org` not matching due to scheme mismatch) but never a "bailiwick" case such as `evilethereum.org` against `*.ethereum.org`, confirmed by inspecting `core/services/gateway/network/httpserver_test.go` [3](#0-2) . This shows the vulnerable code path is untested for the exact suffix-boundary flaw described.

## Impact Explanation
This is a genuine, unpatched logic bug reachable by any unprivileged web attacker who can register a domain string. If an operator configures a wildcard CORS entry (e.g. `*.remix.com`, a pattern shown in sample gateway configs), any attacker-controlled site whose hostname ends in that literal substring (`evilremix.com`, `notremix.com`) is treated as an allowed origin, and its origin is reflected into `Access-Control-Allow-Origin`, letting a browser read cross-origin responses from the gateway's JSON-RPC endpoint (`ProcessRequest`) — undermining the origin-based access-control assumption that CORS is meant to enforce. This maps to the in-scope "allowlist bypass" / "cross-user response corruption via broken access control" impact category. Severity depends heavily on how strongly the gateway relies on Origin/CORS versus JWT/Authorization-header auth for authorization decisions, since the JWT is still required for `ProcessRequest` to act on the request; the CORS bypass primarily affects which browser-origins can read responses, not authentication bypass itself.

## Likelihood Explanation
Exploitation requires: (1) the operator explicitly enabling `CORSEnabled = true`, and (2) configuring a wildcard entry in `CORSAllowedOrigins`. This is an operator-configuration-dependent precondition — with no wildcard CORS origin configured, the bug is not exploitable. Where a wildcard is configured, attacker cost is only domain registration, which is straightforward. Likelihood is therefore moderate-to-high conditional on this non-default configuration choice, rather than universally exploitable on any deployment.

## Recommendation
Change the wildcard suffix check to require a dot-boundary match, e.g.:
```go
if strings.HasPrefix(allowedHost, "*.") {
    suffix := allowedHost[1:] // ".remix.com" (keep leading dot)
    if originHost == suffix[1:] || strings.HasSuffix(originHost, suffix) {
        return true
    }
}
```
This ensures `originHost` either equals the bare domain or ends with `.remix.com` (dot included), rejecting `evilremix.com` while still accepting `foo.remix.com`.

## Proof of Concept
1. Start the gateway HTTP server with `CORSEnabled = true` and `CORSAllowedOrigins = []string{"https://*.remix.com"}`.
2. Send a request to the configured path with header `Origin: https://evilremix.com`.
3. Observe that `isAllowedOrigin` returns `true` (via `strings.HasSuffix("evilremix.com", "remix.com")`), and the response contains `Access-Control-Allow-Origin: https://evilremix.com`, confirmed by tracing the code path in [4](#0-3)  and [2](#0-1) . This can be codified as a Go unit test analogous to `TestHTTPServer_HandleRequest_CORSEnabled_FromNotAllowedOriginWildcards` in `core/services/gateway/network/httpserver_test.go`, asserting that origin `https://evilremix.com` against allowlist `https://*.remix.com` currently (incorrectly) returns a populated `Access-Control-Allow-Origin` header.

func (s *httpServer) isAllowedOrigin(origin string) bool {
	originScheme, originHost, originPort, err := s.splitURL(origin)
	if err != nil {
		s.lggr.Debug("error parsing origin URL", err)
		return false
	}
	for _, allowed := range s.config.CORSAllowedOrigins {
		// probably better to do this once when server starts and store it in a map
		// this is an easier solution so we don't have to apply more changes to the code
		// just need to be careful when specifying allowed origins in the config file
		allowedScheme, allowedHost, allowedPort, err := s.splitURL(allowed)
		if err != nil {
			s.lggr.Debug("error parsing allowed origin URL", err)
			continue
		}
		// skip if the scheme doesn't match at all
		if originScheme != allowedScheme {
			continue
		}
		// skip if the port doesn't match at all
		if originPort != allowedPort {
			continue
		}
		// check for exact host match (e.g., remix.com)
		if originHost == allowedHost {
			return true
		}
		// check for wildcard host match (e.g., *.remix.com)
		if strings.HasPrefix(allowedHost, "*.") {
			allowedHost = allowedHost[2:]
			if strings.HasSuffix(originHost, allowedHost) {
				return true
			}
		}
	}
	return false
}

	if s.config.CORSEnabled {
		origin := r.Header.Get("Origin")
		if s.isAllowedOrigin(origin) {
			w.Header().Set("Access-Control-Allow-Origin", origin)
