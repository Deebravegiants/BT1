## Title
SimplexPaymaster uses a single `maxOracleAge` for all Chainlink feeds despite their differing heartbeats, allowing stale-price gas mispricing - (File: `evm/src/utils/SimplexPaymaster.sol`)

### Summary
`SimplexPaymaster` prices ERC-20 gas payments using two independent Chainlink feeds (`nativeOracle` and each token's `tokenOracle`), but validates staleness for both against one shared `maxOracleAge` value rather than a per-feed heartbeat. This mirrors the reported OracleModule bug class: a single stale-period assumption applied uniformly to feeds with materially different heartbeats.

### Finding Description
`_getOraclePrice` checks staleness against the single contract-wide `maxOracleAge`, applied identically to `nativeOracle` and every `TokenConfig.tokenOracle`: [1](#0-0) 

Governance sets one value for the whole contract via `_setParams`, bounded only by `MAX_ORACLE_AGE = 7 days`: [2](#0-1) 

The contract's own documentation acknowledges heartbeats vary widely per chain and per asset ("BSC stablecoins ~27s, Base/Ethereum stablecoins up to 24h"), yet the code stores only a single `maxOracleAge` field rather than per-oracle heartbeats: [3](#0-2) 

The deployment script further confirms the assumption is tuned for the slowest feed (stablecoin 24h heartbeats), leaving faster-moving feeds like a native asset (ETH/USD, BNB/USD) covered by the same loose bound: [4](#0-3) 

Both prices (`nativeUsd`, `tokenUsd`) feed directly into `_tokenPrice`, which is used by `_fetchDetails` — invoked during ERC-4337 paymaster validation for every UserOperation, i.e. by any unprivileged account/bundler that routes a UserOp through this paymaster: [5](#0-4) [6](#0-5) 

### Impact Explanation
Because the same wide `maxOracleAge` window is applied regardless of a feed's true heartbeat, an oracle that has stopped updating well past its expected refresh interval (e.g., a native-asset feed with a 1-hour heartbeat going stale for several hours) is still treated as "fresh" as long as it's within the 25-hour (or governance-configured, up to 7-day) bound. During that window, if the underlying asset price has moved materially, `_tokenPrice` computes gas cost from a stale ratio between `nativeUsd` and `tokenUsd`. This can cause users paying gas via the paymaster to be systematically overcharged or undercharged in the registered ERC-20 token relative to true market price, and `swapAndDeposit` similarly computes `amountOutMin` from the same stale prices — resulting in mispriced fee recycling. Exploiting this during genuine price volatility can drain treasury value (undercharging) or overcharge end users (theft from users), i.e., concrete loss of funds tied to a path (paymaster gas charging) reachable by any unprivileged UserOperation sender.

### Likelihood Explanation
Likelihood is Low/Medium: it requires one of the configured feeds to actually go stale beyond its real heartbeat while still within the permissive `maxOracleAge`, combined with sufficient price movement during that gap to make exploitation profitable. This is plausible in practice (feed outages, sequencer issues, congestion) and does not require any privileged access — any ordinary UserOp sender benefits/suffers from the mispricing once the condition occurs.

### Recommendation
Store a per-oracle maximum staleness (heartbeat-based) instead of one global `maxOracleAge`, e.g., extend `TokenConfig` and the native oracle configuration with an oracle-specific `maxAge`/heartbeat field set by governance per feed, and check each oracle's own bound in `_getOraclePrice` rather than a single shared parameter.

### Proof of Concept
1. Governance configures `nativeOracle` = ETH/USD (heartbeat ~1h) and registers a stablecoin `tokenOracle` (heartbeat ~24h), both governed by the same `maxOracleAge = 90000` (25h) via `_setParams`/`_registerToken` (`evm/src/utils/SimplexPaymaster.sol:359-404`).
2. The ETH/USD feed stalls (e.g., Chainlink node outage) for 3 hours — far past its 1h heartbeat, but well inside the 25h `maxOracleAge`.
3. During the outage, real ETH price drops sharply (e.g., a flash-crash), but `_getOraclePrice(nativeOracle, ...)` still returns the last stale, higher price without reverting (`evm/src/utils/SimplexPaymaster.sol:662-668`).
4. Any user submits a UserOperation priced through `_fetchDetails`/`_tokenPrice` (`evm/src/utils/SimplexPaymaster.sol:524-556, 653-658`), causing them to be charged stablecoin amounts based on the stale, inflated ETH price — overpaying relative to true market rate, or conversely allowing an attacker who is aware of a stale, favorably low price to underpay for gas, draining the treasury's markup/surplus over time.

        uint8 mode = uint8(data[0]);
        if (mode != 0x00 && mode != 0x02) revert InvalidMode(mode);

        address tokenAddr = address(bytes20(data[1:21]));

        TokenConfig memory cfg = tokenConfigs[tokenAddr];
        if (address(cfg.tokenOracle) == address(0)) revert TokenNotRegistered(tokenAddr);

        token = IERC20(tokenAddr);
        validationData = 0; // no time-range restriction

            (,,, uint256 deadline,,,) = _parsePermit2Data(data);
            // Surfacing the permit deadline as validUntil lets bundlers drop
            // expiring ops instead of discovering it through a Permit2 revert.

            validationData = ERC4337Utils.packValidationData(true, 0, validUntil);
        }
    }

    function _tokenPrice(TokenConfig memory cfg) internal view returns (uint256) {
        uint256 nativeUsd = _getOraclePrice(nativeOracle, nativeOracleDecimals);
        uint256 tokenUsd = _getOraclePrice(cfg.tokenOracle, cfg.tokenOracleDecimals);

        return (nativeUsd * (10 ** cfg.tokenDecimals) * (10_000 + markupBps)) / (tokenUsd * 10_000);
    }

    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
