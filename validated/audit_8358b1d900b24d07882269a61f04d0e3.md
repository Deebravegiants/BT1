### Title
Unauthenticated arbitrary-call execution from Emporium's identity with zero balance accounting via the Emporium-Min proof path - ([File: contracts/CircomDataBuilder.sol, contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol])

### Summary
When `externalActionId == HINKAL_EMPORIUM_ACTION_ID` and `erc20TokenAddresses.length == 0`, `formInputForCircom` routes to `formInputEmporiumMin`, which only constrains `emporiumMessage`, `timeStamp`, and `calldataHash` — no root, nullifier, or signer is enforced by the circuit. Combined with `EmporiumUpgradeable.verifyWallet` skipping ECDSA verification entirely when `stack.signerAddress == address(0)`, and `runAction`'s balance-accounting loop iterating zero times (because `erc20TokenAddresses` is empty), any unprivileged address can force Emporium to execute arbitrary, unauthenticated, unaccounted `op.endpoint.call{value: op.value}(op.callData)` calls from Emporium's own identity.

### Finding Description
The invariant the protocol relies on is: *every asset movement Emporium's ops can cause is captured in `balancesBefore`/`balancesAfter` for `circomData.erc20TokenAddresses`, and any signer-authorized action is protected by an EIP-712 signature.* Both halves of this invariant are voided by the Min path.

1. `formInputForCircom` selects the minimal circuit whenever `externalActionId == HINKAL_EMPORIUM_ACTION_ID && erc20TokenAddresses.length == 0`: [1](#0-0) 
This minimal input vector only contains `emporiumMessage`, `timeStamp`, `calldataHash` — nothing constrains `rootHashHinkal`, nullifiers, or a signer public key. A prover only needs to know a `messageSeed` such that `message == Poseidon(messageSeed)`, something any attacker can pick freely for any `emporiumMessage` value of their choice.

2. Because `dimensionsCheck` forces `erc20TokenAddresses.length == dimensions.tokenNumber` and all other per-token arrays (`amountChanges`, `inputNullifiers`, `outCommitments`, `onChainCreation`, `slippageValues`) to match `tokenNumber`, setting the token array to length 0 forces all of these to length 0 as well: [2](#0-1) 
This makes the whole normal UTXO in/out accounting vacuous for this call — there is nothing for the circuit or the on-chain checks to verify.

3. In `Hinkal.transact`, the balance-diff/slippage loop over `circomData.erc20TokenAddresses` also executes zero times, and `_externalTransact` builds an empty `deltaAmountChanges` array with no transfers: [3](#0-2) [4](#0-3) 

4. `EmporiumUpgradeable.runAction` is then invoked with an attacker-supplied `EmporiumStack` decoded straight from `externalActionMetadata`. `verifyWallet` returns immediately with **no signature check at all** when `stack.signerAddress == address(0)`: [5](#0-4) 
The op loop then executes `op.endpoint.call{value: op.value}(op.callData)` for every attacker-chosen `(endpoint, value, callData)` as `msg.sender == Emporium`: [6](#0-5) 
Finally, `balancesBefore`/`balancesAfter` and the `balanceChange`/`handleOut` sweep loop iterate over `circomData.erc20TokenAddresses`, which is empty, so **nothing is checked or swept back**: [7](#0-6) 

The attacker's exact call: `Hinkal.transact(a,b,c,dimensions,circomData)` with `circomData.externalActionData.externalActionId = HINKAL_EMPORIUM_ACTION_ID`, `circomData.erc20TokenAddresses = []`, `dimensions.tokenNumber = 0` (and all other per-token arrays empty), a trivially self-generated Min-circuit proof for a freely chosen `emporiumMessage`, any historically valid `rootHashHinkal` (unconstrained content since no nullifiers exist), and `externalActionData.externalActionMetadata` encoding an `EmporiumStack{ signerAddress: address(0), ops: [ arbitrary endpoint/value/callData ] }`.

This is only guarded against directly calling `IHinkalWallet.callHinkalWallet`/`doSendToRelay` selectors (blocked in the stateless branch), but any other endpoint — ERC20 token contracts holding an Emporium balance, a router, or any contract that trusts `msg.sender == Emporium` — is fully reachable, and no value moved through those calls is ever accounted for or reverted on.

### Impact Explanation
Any ETH or ERC20 balance resting on the Emporium contract (accumulated protocol/relay fees, dust left over from prior multi-hop swap ops that touched tokens outside a legitimate transaction's declared `erc20TokenAddresses`, or ETH sent to Emporium's `receive()`) can be drained by an unprivileged attacker with zero signature and zero accounting, since the balance-check loop that would normally revert on `balanceChange < 0` never executes for an empty token array. This is direct theft of protocol/relay funds or of shielded/in-flight user funds resting in Emporium's custody, and it is fully repeatable for every new `emporiumMessage` the attacker mints, matching Critical severity ("direct theft of shielded or in-flight user funds" / "executing calls or moving assets a wallet owner or prover never authorised").

### Likelihood Explanation
- No privileged role is required; only self-generated proofs and a self-chosen `emporiumMessage`/`messageSeed`, both fully under attacker control.
- The precondition is that Emporium holds some balance (ETH via `receive()`, ERC20 dust from unaccounted intermediate tokens in past swaps, or fees) at the time of the attack — realistic given multi-hop router ops and the contract's own `receive()` fallback.
- Cost to the attacker is only gas plus generating a trivial ZK proof for the "Min" circuit, which the design explicitly allows for any message.
- Attack is repeatable per unused `emporiumMessage` value, and the attacker can front-run/back-run their own or others' legitimate Emporium transactions to time the drain against any transiently-held balance.

### Recommendation
- Require `stack.signerAddress != address(0)` and enforce the EIP-712 signature check unconditionally in `verifyWallet`, or otherwise gate unsigned stateless ops behind a privileged/allowlisted caller.
- Do not allow the Min-proof path (`erc20TokenAddresses.length == 0`) to reach `runAction`'s op-execution loop without independent accounting; either require `erc20TokenAddresses` to cover every token/ETH balance an op could touch, or add a strict native/ERC20 balance invariant check (`balanceBefore == balanceAfter` for all tokens Emporium could hold, not just the declared list) regardless of array length.
- Consider tracking Emporium's own native/ERC20 balances explicitly (not relying solely on the caller-declared `erc20TokenAddresses`) so stray balances can't be siphoned through an empty-array bypass.

### Proof of Concept
Foundry test plan:
1. Deploy `Hinkal`, `HinkalHelper`, `EmporiumUpgradeable`, register Emporium as an allowed external action and allowed recipient.
2. Fund Emporium directly with ETH (simulate leftover dust, e.g. `vm.deal(address(emporium), 10 ether)`), and confirm `address(emporium).balance == 10 ether`.
3. Craft `CircomData` with `externalActionData.externalActionId = HINKAL_EMPORIUM_ACTION_ID`, `erc20TokenAddresses = []`, `dimensions.tokenNumber = 0`, all per-token arrays empty, and `externalActionMetadata` = `abi.encode(EmporiumStack{ v:0, r:0, s:0, signerAddress: address(0), ops: [EmporiumOperation({endpoint: attackerContract, invokeWallet: false, value: 10 ether, callData: ""})], maxFee: 0, deadline: type(uint256).max })`.
4. Generate a locally valid Min-circuit proof for a self-chosen `emporiumMessage = Poseidon(messageSeed)` and pick any existing `rootHashHinkal`/index.
5. Call `Hinkal.transact(a,b,c,dimensions,circomData)` from an attacker EOA with no prior deposit.
6. Assert: `verifyProof` succeeds, `runAction` executes the op transferring 10 ETH to `attackerContract`, and `address(emporium).balance == 0` afterward with **no revert** from `BalanceChangeShouldBePositive` (since the loop never ran) — proving `assets Emporium moved (10 ETH) != assets accounted in balancesBefore/balancesAfter (0)`.

    function runAction(
        CircomData calldata circomData,
        int256[] calldata deltaAmountChanges
    ) external override onlyAllowedRecipient returns (UTXO[] memory) {
        EmporiumStack memory stack = abi.decode(
            circomData.externalActionData.externalActionMetadata,
            (EmporiumStack)
        );

        uint256[] memory balancesBefore = getBalancesForArray(
            circomData.erc20TokenAddresses
        );

        verifyWallet(stack, circomData);

        for (uint256 i = 0; i < stack.ops.length; i++) {
            EmporiumOperation memory op = stack.ops[i];

            bool success;
            bytes memory err;

            // CASE 1: Stateful Interaction
            if (op.invokeWallet && stack.signerAddress != address(0)) {
                (success, err) = IHinkalWallet(stack.signerAddress)
                    .callHinkalWallet(op.endpoint, op.callData, op.value);
            }
            // CASE 2: Stateless Interaction
            else {
                bytes4 selector = bytes4(op.callData);
                if (
                    selector == IHinkalWallet.callHinkalWallet.selector ||
                    selector == IHinkalWallet.doSendToRelay.selector
                ) {
                    revert UnauthorizedWalletCall();
                }

                (success, err) = op.endpoint.call{value: op.value}(op.callData);
            }

            if (!success) {
                revert CallFailed(err);
            }
        }

        payRelayFees(circomData, stack.signerAddress, deltaAmountChanges);

        uint256[] memory balancesAfter = getBalancesForArray(
            circomData.erc20TokenAddresses
        );

        UTXO[] memory utxoSet = new UTXO[](
            circomData.erc20TokenAddresses.length
        );

        uint256 utxoSetLength;

        for (uint256 i = 0; i < circomData.erc20TokenAddresses.length; i++) {
            int256 balanceChange = int256(balancesAfter[i]) -
                int256(balancesBefore[i]);

            if (deltaAmountChanges[i] < 0) {
                balanceChange -= deltaAmountChanges[i];
                // this equation reads: total change of emporium balance = what was moved to emporium (-deltaAmountChange) + how emporium balance changed through tx (balanceChange)
            }

            // the only case when balanceChange can be < 0, when there were some funds on emporium before the call
            if (balanceChange < 0) {
                revert BalanceChangeShouldBePositive();
            }

            UTXO memory utxoOut = handleOut(balanceChange, circomData, i);

            if (utxoOut.amount > 0) {
                utxoSet[utxoSetLength++] = utxoOut;
            }
        }
