### Title
Unvalidated length in `RawArchivedVec<u8>` deserialization allows out-of-bounds `copy_nonoverlapping` across the RGB-camera agent IPC trust boundary - (File: `src/agents/camera/rgb/worker.rs`)

### Summary
The external report's root cause is a producer-controlled size field that is subtracted/used directly in a `memcpy` without validating it against the actual buffer bounds, causing memory corruption across a process trust boundary (a compromised "producer" tile corrupting a "consumer" tile). The equivalent trust boundary in orb-core is the `agentwire` shared-memory IPC between the main orb-core process (the "host"/broker) and its sandboxed agent worker processes (e.g. the RGB camera worker in `src/agents/camera/rgb/worker.rs`), which are separate, restartable, less-trusted subprocesses [1](#0-0) . The host deserializes messages coming from the agent process using `rkyv::archived_root`, which performs zero-copy, non-validated interpretation of the raw bytes, and then a custom `Deserialize` implementation trusts an embedded length taken from that unvalidated archive to drive a raw `copy_nonoverlapping`.

### Finding Description
In `agentwire/src/port.rs`, when the host receives an `Output` message from an agent's shared-memory output buffer, it decodes a `size` header and calls the unsafe, non-validating `rkyv::archived_root`: [2](#0-1) 

This is analogous to the `sz` field trusted from the mcache fragment in the original report: the byte content of the shared-memory buffer is written by the agent process, and `archived_root` performs no bounds/structure validation of the archive (no `bytecheck`/validation feature is used here) before treating the bytes as a valid, well-formed archive.

That archived value is later deserialized in `src/agents/camera/rgb/worker.rs` via a hand-written, `unsafe` `Deserialize` implementation for the RGB frame's pixel buffer: [3](#0-2) 

`self.len()` and `self.as_ptr()` are derived directly from the (unvalidated) archived `RawArchivedVec<u8>` header inside the shared-memory buffer. Because the archive was never validated, an agent process that writes a crafted archive (with a `len` value that doesn't match the actual amount of pixel data actually present after the header, or a pointer/offset that resolves outside the mapped shared-memory region) causes `copy_nonoverlapping` to read `self.len()` bytes starting at `self.as_ptr()` regardless of the true extent of valid data. Unlike `sz>USHORT_MAX` in the original bug, this Rust code has *no* upper-bound check at all against the actual mapped buffer size before performing the raw copy — the only implicit sizing assumption is `SERIALIZED_OUTPUT_SIZE` on the shared-memory side, but nothing here validates that the *archived* length used for the copy is consistent with that allocation [4](#0-3) .

### Impact Explanation
The RGB camera agent process handles the live face/iris capture stream used during signup and verification (biometric capture flow). If the RGB camera agent process is compromised (e.g., via a malicious/malformed camera driver interaction, or a bug reachable from attacker-influenced camera input), it can write a crafted output archive whose `RawArchivedVec<u8>` length/pointer metadata is inconsistent with the true buffer contents. The host then performs an out-of-bounds `copy_nonoverlapping` read (and, depending on heap layout, potential corruption of adjacent memory in the destination `Vec` if `self.len()` is used to both size the allocation and drive the copy inconsistently), which can lead to memory corruption or disclosure of adjacent heap memory in the main orb-core process — the same process responsible for signup authorization decisions, liveness enforcement, and biometric template handling. This matches the class of impact called out in the rules (biometric data disclosure / cross-process memory corruption via an agent-IPC trust boundary).

### Likelihood Explanation
Exploitation requires first compromising the RGB camera agent subprocess (or otherwise controlling what it writes into the shared-memory output buffer), which is a real, defined trust boundary in this codebase — the agent runs as a separate process specifically because it is treated as less trusted/isolatable [1](#0-0) . This is a two-step chain (agent compromise → host memory corruption), so likelihood is moderate rather than trivially remote, but it is a legitimate defense-in-depth failure: the entire purpose of process isolation is defeated because the host never validates the archive before trusting length fields taken from it.

### Recommendation
- Use `rkyv`'s validating API (`rkyv::validation`/`bytecheck`, i.e. `check_archived_root` or an equivalent safe-checked accessor) instead of the raw `archived_root` call in `deserialize_message`, so that a malformed/inconsistent archive from an agent process is rejected before any field of it (including lengths) is trusted [2](#0-1) .
- In the custom `Deserialize` impl for `FrameData`/`RawArchivedVec<u8>`, cross-check `self.len()` against the known/expected buffer size (`SERIALIZED_OUTPUT_SIZE`, or the frame's `width * height * channels`) before performing `copy_nonoverlapping`, and reject/clamp when it doesn't match [6](#0-5) .
- Apply the same length cross-check pattern to any other hand-rolled `unsafe` `Archive`/`Deserialize` implementations that bypass rkyv's validated accessors across the agent-IPC boundary.

### Proof of Concept
Not independently reproducible from the indexed code alone (would require running the RGB camera agent as a compromised subprocess and writing a crafted `RawArchivedVec<u8>` header — length inconsistent with actual data — into the shared-memory output buffer, then triggering `Inner`/`Outer::recv` on the host so `RawArchivedVec<u8>::deserialize` performs the oversized `copy_nonoverlapping`). This is a structural analysis based on the code paths cited above; dynamic verification would require a Devin session with build/run access to the repository.

    D: Fallible + ?Sized,

    fn deserialize(&self, _: &mut D) -> Result<FrameData, D::Error> {
        let mut result = Vec::with_capacity(self.len());
        unsafe {
            copy_nonoverlapping(self.as_ptr().cast(), result.as_mut_ptr(), self.len());
            result.set_len(self.len());
        }
        Ok(FrameData::Owned(result))
    }
