### Title
Unbounded-depth `RuntimeCall` deserialization from untrusted cross-chain calldata enables stack-exhaustion abort during message delivery - (File: `modules/pallets/hyper-fungible-token/src/module.rs`)

### Summary
`pallet-hyper-fungible-token`'s `on_accept` handler decodes the `runtime_call` bytes embedded in an incoming ISMP `PostRequest`'s calldata directly with plain `codec::Decode::decode` into `T::RuntimeCall`, with no recursion/depth limit. Any account that can trigger a token transfer with calldata through the paired EVM `HyperFungibleToken`/`WrappedHyperFungibleToken` contract (an unprivileged token bridger) fully controls these bytes. A deeply self-referential encoding (e.g. nested `Sudo::sudo(Box<Call>)` variants) causes unbounded recursive stack growth during SCALE decoding, which in Rust aborts the process rather than returning an `Err` — this cannot be caught, unlike a normal dispatch error.

### Finding Description
`on_accept` in [1](#0-0)  decodes optional calldata as `SubstrateCalldata`, and then decodes its `runtime_call: Vec<u8>` field with: [2](#0-1) 

This is a plain, depth-unbounded `Decode::decode` call. The codebase already has a documented awareness of exactly this bug class: `pallet-call-decompressor` decodes runtime calls from untrusted, attacker-supplied bytes using `decode_all_with_depth_limit(MAX_EXTRINSIC_DECODE_DEPTH_LIMIT, ...)`, explicitly bounding recursion to prevent stack exhaustion: [3](#0-2) [4](#0-3) 

A regression test in that pallet even proves the exploit primitive — nested `Sudo::sudo(Box<Call>)` calls that would otherwise blow the stack — is specifically guarded against: [5](#0-4) 

`pallet-hyper-fungible-token` performs the analogous decode of attacker-controlled bytes into `T::RuntimeCall` but omits this depth-limited decode entirely, using the raw, unbounded `Decode::decode` instead. This is a deserialization-of-untrusted-data flaw (CWE-502 class) where the type being deserialized is directly a dispatchable/executable `RuntimeCall`.

This code runs on the consensus-critical message-delivery path: `on_accept` is invoked from `modules/ismp/core/src/handlers/request.rs` `handle()` for every incoming `PostRequest`, once membership of the request has been proven against the source-chain state root: [6](#0-5) 

Reachability: an unprivileged sender on the EVM side can call `HyperFungibleToken.send(...)` with an arbitrary `data` field, which is ABI-encoded into `Message.data` and delivered cross-chain as the `PostRequest.body`: [7](#0-6) 

`ContractToAsset::<T>::get(source, &from)` only authenticates *which asset* the source EVM contract maps to — it does not constrain the contents of `message.data`, which remains fully attacker-controlled.

### Impact Explanation
A stack overflow in Rust triggers a process abort (SIGABRT/SIGSEGV), not a catchable panic. Since `on_accept` executes inside block-import/execution (invoked from `pallet-ismp`'s message handler on every relayed request), a crafted deeply-nested `runtime_call` payload delivered by any unprivileged token bridger can crash the collator/validator node processing that block. Because all honest nodes deterministically execute the same block, this is not merely a single-node crash but a chain-halting condition for the state machine hosting `pallet-hyper-fungible-token` — messages can no longer be delivered/processed (denial of the messaging route), satisfying the "route unable to deliver messages" impact class.

### Likelihood Explanation
Likelihood is high: constructing a deeply nested `RuntimeCall` (e.g., repeated `Sudo::sudo(Box::new(...))`, or any other recursive enum variant present in the runtime's `Call` type) and SCALE-encoding it is trivial and requires no special privileges — only the ability to send a cross-chain token transfer with `data` through the paired EVM contract, exactly the capability of a normal token bridger. No proof forgery or consensus compromise is needed; only a legitimately-proven `PostRequest` whose body contains the malicious calldata.

### Recommendation
Replace the unbounded `T::RuntimeCall::decode(&mut &*substrate_data.runtime_call)` in `modules/pallets/hyper-fungible-token/src/module.rs` with a depth-limited decode, mirroring `pallet-call-decompressor`'s approach — e.g. `T::RuntimeCall::decode_all_with_depth_limit(MAX_DEPTH, &mut &*substrate_data.runtime_call)` with a conservative depth bound, and reject decode failures (including leftover bytes) as `HftError::RuntimeCallDecodeError` as already done. Apply the same bound wherever the same pattern of "SCALE-decode attacker bytes into `RuntimeCall`" occurs elsewhere in the codebase.

### Proof of Concept
1. On the source EVM chain, call `HyperFungibleToken.send(...)` (or `WrappedHyperFungibleToken`) with `data` set to the ABI/SCALE encoding of a `Message` whose `data` field is a SCALE-encoded `SubstrateCalldata { signature: None, runtime_call: <malicious bytes> }`.
2. Set `<malicious bytes>` to the SCALE encoding of `RuntimeCall::Sudo(pallet_sudo::Call::sudo { call: Box::new(RuntimeCall::Sudo(pallet_sudo::Call::sudo { call: Box::new(...) })) })` nested thousands of times (as demonstrated feasible against the same runtime types in the `decompress_stack_exhaustion_poc` test in `pallet-call-decompressor`'s test suite).
3. Have any relayer submit the resulting `PostRequest` with a valid membership proof via `handle_unsigned` to the destination chain running `pallet-hyper-fungible-token`.
4. `handlers::request::handle` calls `cb.on_accept(request)`, which reaches `T::RuntimeCall::decode(&mut &*substrate_data.runtime_call)` — the unbounded recursive decode overflows the call stack and aborts the node process during block execution.

    function onAccept(IncomingPostRequest calldata incoming) public virtual override onlyHost whenNotPaused {
        PostRequest calldata request = incoming.request;

        bytes memory expectedSource = _supportedChains[request.source];
        if (expectedSource.length == 0) revert UnsupportedChain();
        if (keccak256(request.from) != keccak256(expectedSource)) revert UnauthorizedSource();

        Message memory message = abi.decode(request.body, (Message));
        address beneficiary = _toAddr(message.to);
        _mint(beneficiary, message.amount);

        if (message.data.length > 0) {
            ICallDispatcher(_dispatcher).dispatch(message.data);
        }

        emit Received({
            from: message.from,
            to: beneficiary,
            source: string(request.source),
            amount: message.amount
        });
    }
