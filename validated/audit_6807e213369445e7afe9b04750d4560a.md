I have a strong candidate. Let me verify the bad-debt supply-index floor clamp and its reachability.### Title
Supply-index floor clamp on bad-debt socialization leaves wiped-out suppliers a phantom claim that drains future depositors — (`contracts/pool/src/interest.rs`)

### Summary
`apply_bad_debt_to_supply_index` writes supply losses down pro-rata by reducing the supply index, but clamps the result at `SUPPLY_INDEX_FLOOR_RAW` (`RAY/1000`) instead of zeroing supplier shares when the write-off consumes the market's entire supplied value. This is the same bug class as the Y2K finding: a settlement path lacks proper handling of the zero-TVL/zero-claim case, so a share claim survives with no backing and later converts into a payout drawn from fresh depositors' cash. [1](#0-0) 

### Finding Description
When unpaid debt is socialized, `apply_bad_debt_to_supply_index` computes `remaining = total_supplied_value - min(bad_debt, total_supplied_value)` and multiplies the supply index by `remaining / total_supplied_value`. If `bad_debt >= total_supplied_value`, `remaining` is zero and `new_supply_index` is zero — but `set_supply_index(new_supply_index.max(SUPPLY_INDEX_FLOOR_RAW))` raises it back to `RAY/1000`. The stored scaled supply shares are unchanged, so every pre-wipeout supplier's position un-scales to `scaled_amount × RAY/1000` — a strictly positive "phantom" claim backed by zero cash. [2](#0-1) 

The pool test `test_raw_cache_floor_clamp_strands_claim_without_supply_guard` demonstrates the consequences: after `apply_bad_debt_to_supply_index` clamps the index to the floor, `unscale_supply_floor(old_scaled)` returns a positive stranded claim while `cash` is zero; when a fresh supplier deposits, `resolve_withdrawal` on the wiped position pays out real tokens equal to the fresh deposit, leaving `cash < fresh_claim` — the new depositor's funds are lost. [3](#0-2) 

The trigger is reachable by an unprivileged address: bad debt is applied via `pool_seize_positions_call`, invoked both from `execute_bad_debt_cleanup` (permissionless `clean_bad_debt` when ceil risk debt exceeds half-up collateral and collateral is at or below the fixed $5 dust threshold) and from the ordinary `liquidate` path's post-check `check_bad_debt_after_liquidation`. [4](#0-3) [5](#0-4)  Debt can exceed total supplied value through accrued interest (the borrow index compounds above the supply value backing it) combined with collateral seizure, so `bad_debt > total_supplied_value` is attainable in a market that suffered near-total loss.

### Impact Explanation
Theft of user funds: once the index is clamped at the floor, wiped-out suppliers retain positive un-scaled claims. Any subsequent deposit into the market becomes withdrawable by the phantom claimants — the test shows the wiped position draining exactly the fresh deposit. This is permanent loss of the new supplier's principal, not a delay. [6](#0-5) 

### Likelihood Explanation
Requires a market where unrecovered bad debt meets or exceeds total supplied value — a tail-risk scenario (deep price crash plus fully lent-out utilization plus compounding unpaid debt), analogous to the report's "premium funded, collateral empty" edge case. But the entrypoint is permissionless (`liquidate` or `clean_bad_debt` by any caller once the dust/dominance predicates hold), the preconditions arise organically from market activity rather than timing luck, and any later depositor is victimized. The supply-index floor exists precisely to avoid a zero index, so no existing guard removes the phantom claims.

### Recommendation
Zero out the market's supply shares (or the affected positions) when `bad_debt >= total_supplied_value` instead of clamping the index to `SUPPLY_INDEX_FLOOR_RAW` — e.g., in `apply_bad_debt_to_supply_index` (`contracts/pool/src/interest.rs:73-89`), when `capped == total_supplied_value`, burn/zero `supplied` scaled shares alongside setting the index, or store an explicit wiped flag that `resolve_withdrawal`/`unscale_supply_floor` honor. Alternatively, gate withdrawals on a market-level wiped-supply check so a floor-clamped claim cannot pass `require_reserves` against a fresh depositor's cash.

```rust
pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}
```

```rust
fn test_raw_cache_floor_clamp_strands_claim_without_supply_guard() {
    let t = TestSetup::new();
    t.as_contract(|| {
        let old_scaled_raw = 1_000 * RAY;
        let mut cache = t.fresh_cache(PoolStateRaw {
            supplied: old_scaled_raw,
            borrowed: 0,
            revenue: 0,
            borrow_index: RAY,
            supply_index: RAY,
            last_timestamp: 0,
            cash: 0,
        });
        let old_scaled = Ray::from(old_scaled_raw);

        apply_bad_debt_to_supply_index(&mut cache, Ray::from(5_000 * RAY));
        assert_eq!(
            cache.supply_index().raw(),
            SUPPLY_INDEX_FLOOR_RAW,
            "wipeout clamps supply_index UP to RAY/1000 instead of resetting shares to 0",
        );

        let stranded = cache.unscale_supply_floor(old_scaled);
        assert!(stranded > 0, "floor clamp leaves S_old a phantom claim");
        assert_eq!(
            cache.cash(),
            0,
            "no cash yet: invariant only masked by require_reserves"
        );

        let fresh_cash = stranded;
        let fresh_scaled = cache.calculate_scaled_supply(fresh_cash);
        cache.mint_supply(fresh_scaled);
        cache.credit_cash(fresh_cash);

        let fresh_claim = cache.unscale_supply_floor(fresh_scaled);
        assert_eq!(
            fresh_claim, fresh_cash,
            "fresh supplier's claim equals deposit"
        );

        let (burn, gross) = cache.resolve_withdrawal(i128::MAX, old_scaled);
        cache.require_reserves(gross);
        cache.burn_supply(burn);
        cache.debit_cash(gross);

        assert!(gross > 0, "stranded wiped position pays out real tokens");
        assert_eq!(gross, fresh_cash, "S_old drains exactly the fresh deposit");
        assert!(
            cache.cash() < fresh_claim,
            "pool cash ({}) can no longer cover fresh supplier claim ({}): funds lost",
            cache.cash(),
            fresh_claim,
        );
```
