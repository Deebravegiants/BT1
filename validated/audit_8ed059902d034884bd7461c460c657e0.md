### Title
RAY fixed-point value overflows before borrow-index cap, permanently freezing a whale market - (File: `common/src/rates/simulate.rs`)

### Summary
High-utilization accrual can permanently lock a market because debt/share values are recomputed in `i128` RAY units before the borrow-index ceiling provides any protection. Once `scaled_shares * index` exceeds `i128::MAX`, every mutating operation that first syncs the market panics with `MathOverflow`. [1](#0-0) [2](#0-1) 

### Finding Description
The permissionless `Controller.update_indexes(caller, assets)` path calls the pool’s `update_indexes`, which loads each market and runs `interest::global_sync`. [3](#0-2) [4](#0-3) 

`global_sync` invokes `accrue_step`, which computes `borrowed * borrow_index` and `supplied * supply_index` through `scaled_to_original`, then computes old and new total debt through `calculate_supplier_rewards`. [1](#0-0) [5](#0-4) 

`scaled_to_original` delegates to `Ray::mul`, whose underlying `mul_div_half_up` widens the intermediate to `I256` but panics when the resulting RAY value does not fit in `i128`. [6](#0-5) [7](#0-6) [8](#0-7) 

`MAX_BORROW_INDEX_RAY` only caps the stored index; it does not cap or gracefully reduce `borrowed * index`, so a sufficiently large book can overflow its RAY-denominated value while the index remains below the cap. [9](#0-8) [10](#0-9) 

Because `withdraw`, `repay`, and other position mutations load a synced market before changing state, the first overflow turns the panic into a persistent liveness failure rather than an isolated rejected transaction. [2](#0-1) [11](#0-10) [12](#0-11) 

### Impact Explanation
All suppliers’ tokens in the affected `(hub_id, asset)` book become permanently frozen: withdrawals and liquidation withdrawals cannot proceed because they sync first. [2](#0-1) [13](#0-12) 

Borrowers cannot repay and liquidators cannot execute debt-repayment legs against that market, so the protocol cannot recover solvency through normal user actions. [14](#0-13) [15](#0-14) 

The in-repository reproduction reaches this state at approximately one billion whole 18-decimal tokens and sustained 98% utilization; after the panic, both a one-unit withdrawal and a one-unit repayment fail with `MathOverflow`. [16](#0-15) 

### Likelihood Explanation
A single unprivileged address can own both the supplying account and collateralized borrowing account, create them through `supply(caller, 0, spoke_id, assets)`, borrow through `borrow(caller, account_id, borrows, to)`, and later submit `update_indexes(caller, assets)`. [17](#0-16) [18](#0-17) 

The attack requires a market whose admitted cap permits a very large book and enough token liquidity to establish the position, followed by sufficient elapsed accrual; no privileged call, oracle manipulation, malformed token, callback, or leaked key is required. [19](#0-18) 

The checked reproduction uses a valid steep rate curve with a 175% maximum borrow rate and raises configured caps only in the test fixture; production reachability therefore depends on the caps and rate model governance actually admitted. [20](#0-19) [21](#0-20) 

### Recommendation
Before writing a new index, bound every dependent value calculation that can exceed `i128`, or split accrual/charges so a capped index does not require evaluating an unrepresentable total value. [22](#0-21) [9](#0-8) 

At minimum, detect pending market-value overflow in `accrue_step` and clamp the indexes at the last representable point, preserving a liveness-safe exit and repayment path. [23](#0-22) 

Enforce market and account caps against projected future index growth rather than only the token-to-RAY admission maximum, and add the existing whale-market regression test to release-critical coverage. [24](#0-23) [16](#0-15) 

### Proof of Concept
The repository’s test establishes the complete reachable sequence: create a valid 18-decimal market, supply `1_000_000_000 * 10^18` base units, collateralize another account with enough `COL`, borrow 98% of the supplied asset, advance ledger time, and invoke permissionless index accrual. [19](#0-18) 

The accrual fails with `MathOverflow` while `borrow_index < MAX_BORROW_INDEX_RAY`, proving the index cap did not prevent the value-domain overflow. [25](#0-24) 

After that failed sync, both `withdraw` and `repay` continue to fail with `MathOverflow`, confirming permanent market-level freezing rather than a one-off panic. [26](#0-25)

pub fn accrue_step(
    env: &Env,
    params: &MarketParams,
    borrowed: Ray,
    supplied: Ray,
    borrow_index: Ray,
    supply_index: Ray,
    delta_ms: u64,
) -> AccrualStep {
    let borrowed_original = scaled_to_original(env, borrowed, borrow_index);
    let supplied_original = scaled_to_original(env, supplied, supply_index);
    let util = utilization(env, borrowed_original, supplied_original);
    let borrow_rate = calculate_borrow_rate(env, util, params);
    let interest_factor = compound_interest(env, borrow_rate, delta_ms);

    let new_borrow_index = update_borrow_index(env, borrow_index, interest_factor);

    let (supplier_rewards, protocol_fee) =
        calculate_supplier_rewards(env, params, borrowed, new_borrow_index, borrow_index);

    let new_supply_index = update_supply_index(env, supplied, supply_index, supplier_rewards);
    let supplier_shortfall = supply_index_reward_shortfall(
        env,
        supplied,
        supply_index,
        new_supply_index,
        supplier_rewards,
    );

    let protocol_reward = protocol_fee.checked_add(env, supplier_shortfall);
    // Shares are valued at the new supply index, which the caller stores for
    // this step.
    let revenue_shares = if protocol_reward == Ray::ZERO {
        Ray::ZERO
    } else {
        protocol_fee_shares(env, protocol_reward, new_supply_index, supplied)
    };

pub fn try_mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> Option<i128> {
    if x < 0 || y < 0 || d <= 0 {
        return None;
    }
    let half = d / 2;

    // Fast path: the biased product fits `i128`, so the whole computation is
    // native. `x * y + half` is non-negative here, so `/` is the floor the
    // widened path would produce.
    if let Some(biased) = x
        .checked_mul(y)
        .and_then(|product| product.checked_add(half))
    {
        return Some(biased / d);
    }

    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    x256.mul(&y256)
        .add(&I256::from_i128(env, half))
        .div(&d256)
        .to_i128()
}

pub(crate) fn accounting(env: &Env, action: &PoolAction) -> RepayOutcome {
    let (mut cache, position) = ops::load_leg(env, action);
    let amount = action.amount;

    let (burned, overpayment) = cache.resolve_repay(amount, position);
    let net_repay = amount
        .checked_sub(overpayment)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));
    assert_with_error!(
        env,
        net_repay == 0 || burned.raw() > 0,
        GenericError::RepayRoundsToZeroShares
    );

    let position = position.checked_sub(env, burned);
    cache.burn_debt(burned);

    cache.credit_cash(net_repay);

    let snapshot = cache.commit();

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
