### Title
Unsanitized `shop` parameter in OAuth initiation enables forced OAuth completion / redirect to attacker-controlled domain - (File: `lib/shopify_api/auth/oauth.rb`)

### Summary
`ShopifyAPI::Auth::Oauth.begin_auth` builds the OAuth `authorize` redirect URL directly from the caller-supplied `shop` string without validating it against `ShopifyAPI::Utils::ShopValidator`, unlike every other entry point in the gem that consumes a raw shop value.

### Finding Description
`begin_auth` takes a `shop:` argument and passes it straight into `auth_base_uri(shop)`, which returns `"https://#{shop}/admin"`, then appends `/oauth/authorize?client_id=...&redirect_uri=...&state=...` and returns it as the `auth_route` the caller must redirect the browser to. [1](#0-0) [2](#0-1) 

No call to `Utils::ShopValidator.sanitize!`/`sanitize_shop_domain` is made in this path, so `shop` is trusted as-is to construct the base URI that the browser (and the app's `client_id` + `redirect_uri`) is sent to. This breaks the identity binding: `shop domain used to build the OAuth authorize request == a domain actually belonging to Shopify's trusted domain set`.

Contrast this with every other place in the gem that accepts a shop string: `token_exchange.rb`, `client_credentials.rb`, `refresh_token.rb`, and `clients/graphql/storefront.rb` all invoke `ShopValidator.sanitize!`/`sanitize_shop_domain` before using the value, and `ShopValidator` exists specifically to enforce that a shop domain belongs to `TRUSTED_SHOPIFY_DOMAINS` (`shopify.com`, `myshopify.io`, `myshopify.com`, `spin.dev`, `shop.dev`) or a configured `myshopify_domain`. [3](#0-2) [4](#0-3) 

Because `begin_auth` is the one OAuth-initiation entry point in the library, and it is the function documented for host apps to call with the incoming `shop` request parameter (e.g. `/login?shop=...`), the absence of validation here — while present everywhere else — means the gem itself will happily build and return an authorize redirect pointing at an attacker-chosen host if the caller passes through an unsanitized `shop` value, exactly the scenario `ShopValidator` was introduced to prevent elsewhere in the same codebase.

### Impact Explanation
An attacker who controls the `shop` value reaching `begin_auth` (a normal, documented input to this exact function) can cause the app to generate an OAuth authorize URL pointing at an attacker-controlled origin instead of a real Shopify shop domain. The victim's browser is redirected there carrying the app's `client_id` and its real `redirect_uri`/`state`, enabling a forced-OAuth-completion / phishing flow where the attacker's fake "Shopify" login page can capture credentials or manipulate the flow, then redirect back to the app's genuine callback with an attacker-supplied `code`, potentially completing an OAuth session under attacker control. This matches the "session fixation or forced OAuth completion" High-impact category.

### Likelihood Explanation
High. `begin_auth` is the sole documented function for initiating OAuth in this gem, and the `shop` parameter is inherently sourced from the incoming HTTP request in typical app-login flows (a value not verifiable before the initial redirect, since HMAC verification only happens later in `validate_auth_callback`). Every other shop-consuming function in the gem defensively sanitizes this value; this one does not, making exploitation straightforward for any caller that doesn't independently duplicate `ShopValidator`'s logic outside the gem.

### Recommendation
Call `Utils::ShopValidator.sanitize!(shop, myshopify_domain: ...)` (or `sanitize_shop_domain`) inside `begin_auth` before passing `shop` to `auth_base_uri`, raising `Errors::InvalidShopError` for untrusted domains, consistent with `token_exchange.rb`, `client_credentials.rb`, `refresh_token.rb`, and `clients/graphql/storefront.rb`.

### Proof of Concept
```ruby
# Host app login endpoint naively forwards the "shop" query param (a common pattern):
result = ShopifyAPI::Auth::Oauth.begin_auth(
  shop: "attacker-controlled.example.com", # not a myshopify.com/spin.dev domain
  redirect_path: "/auth/callback",
)
result[:auth_route]
# => "https://attacker-controlled.example.com/admin/oauth/authorize?client_id=...&redirect_uri=https://app.example.com/auth/callback&state=...&grant_options%5B%5D=per-user"
```
No call in `Oauth.begin_auth` rejects `attacker-controlled.example.com`, whereas the same string passed to `Utils::ShopValidator.sanitize!` would raise `Errors::InvalidShopError` because it is not in `TRUSTED_SHOPIFY_DOMAINS`. [4](#0-3)

```ruby
        def begin_auth(shop:, redirect_path:, is_online: true, scope_override: nil)
          scope = if scope_override.nil?
            ShopifyAPI::Context.scope
          elsif scope_override.is_a?(ShopifyAPI::Auth::AuthScopes)
            scope_override
          else
            ShopifyAPI::Auth::AuthScopes.new(scope_override)
          end

          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = SecureRandom.alphanumeric(NONCE_LENGTH)

          cookie = SessionCookie.new(value: state, expires: Time.now + 60)

          query = {
            client_id: ShopifyAPI::Context.api_key,
            scope: scope.to_s,
            redirect_uri: "#{ShopifyAPI::Context.host}#{redirect_path}",
            state: state,
            "grant_options[]": is_online ? "per-user" : "",
          }

          query_string = URI.encode_www_form(query)
          auth_route = auth_base_uri(shop) + "/oauth/authorize?#{query_string}"

          { auth_route: auth_route, cookie: cookie }
        end
```

```ruby
        def auth_base_uri(shop)
          return "https://#{shop}/admin" unless defined?(DevServer) && shop.include?(".my.shop.dev")

          # For first-party apps in development only, we leverage DevServer to build the admin base URI
          admin_web = T.unsafe(Object.const_get("DevServer")) # rubocop:disable Sorbet/ConstantsFromStrings
            .new("admin-web")
          admin_host = admin_web.host!(nonstandard_host_prefix: "admin")
          shop_name = shop.split(".").first

          "https://#{admin_host}/store/#{shop_name}"
        end
```
