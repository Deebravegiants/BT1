The strongest analog is liquidation's pro-rata seizure across *all* collateral legs plus `no_seize` flags. I need to check whether a borrower can self-add a `no_seize` asset as collateral to become unliquidatable.### Title
A borrower can make their underwater account permanently unliquidatable by supplying a dust leg of a `no_seize`-flagged asset, forcing bad debt onto suppliers - (File: contracts/controller/src/positions/liquidation/plan.rs)

### Summary

`liquidate` seizes collateral **pro-rata across every supply position the account holds** — the liquidator cannot choose a subset. After the seizure plan is built, `build_liquidation_plan` runs `enforce_spoke_asset_flags(..., FreezePolicy::SeizureLeg)` over *every* planned seizure leg, and `SeizureLeg` reverts with `SpokeAssetSeizureHalted` (`#318`) if **any** leg's listing has `no_seize = true`. Since `supply` only requires `is_collateralizable` and never checks `no_seize`, an unprivileged borrower can add a `no_seize` asset to their own account at any time — including after the flag is set — and thereby veto all liquidations of their account, in both `SeizeMode::Transfer` and `SeizeMode::Credit`. ### Finding Description

This mirrors the Nouns fork bug class: a set of assets is forced into a protective exit path with no ability to subset it, so one "poison" element in the set blocks the whole mechanism.

- Seizure is explicitly all-or-nothing across the collateral set: "One mode governs the whole call rather than one mode per asset: seizure is pro-rata across every collateral the account holds" ( [4](#0-3) ). There is no entrypoint argument letting a liquidator exclude a leg.
- `calculate_seized_collateral` iterates `account.supply_positions` and emits a `SeizeEntry` for any leg whose seizure rounds above zero ( [5](#0-4) ).
- Every emitted leg is then gated on `no_seize` ( [1](#0-0) ). One flagged leg reverts the entire liquidation.
- Entry does not gate on `no_seize`: `require_can_supply` checks only `is_collateralizable` plus `paused`/`frozen` ( [3](#0-2) ; [6](#0-5) ). The invariant doc confirms the gap: "Nonzero `no_seize` collateral can block the whole proportional liquidation, even if supplied after the flag is set" ( [7](#0-6) ).
- `no_seize` is set for a reason — typically governance flagging a compromised/broken asset while an orderly unwind is arranged. A borrower holding (or newly dusting in) that asset converts a risk containment flag into a personal liquidation shield for *all* their collateral, including unrelated healthy assets.

Attack path, all unprivileged:

1. Governance guardian calls `set_spoke_asset_flags` setting `no_seize` on asset X (e.g., X's oracle or issuer is degraded) while X remains `is_collateralizable`.
2. Attacker `supply(caller, account_id, spoke_id, [(X_key, amt)])` with enough X that its pro-rata seizure leg rounds to ≥ 1 unit. Third-party supply restrictions don't apply — it's the attacker's own account.
3. Attacker's account goes HF < 1 (price move or accrued interest on existing debt).
4. Every `liquidate` call reverts at `SpokeAssetSeizureHalted`, regardless of seize mode, because `enforce_spoke_asset_flags` runs before mode dispatch and `Credit` mode does not bypass the flag either.
5. Debt accrues unpaid until collateral value falls below the 5-WAD dust threshold, after which permissionless `clean_bad_debt` socializes the shortfall into the supply index — i.e., onto suppliers ( [8](#0-7) ; `contracts/pool/src/interest.rs::apply_bad_debt_to_supply_index`).

### Impact Explanation

Protocol insolvency / theft of supplier funds: a blocked liquidation path converts recoverable underwater positions into bad debt that is socialized into the supply index via `apply_bad_debt_to_supply_index`, diluting every supplier of the debt market. It also produces temporary freezing of liquidators' expected settlement path — there is no fallback seize mode, subset selection, or privileged force-liquidation entrypoint that bypasses `no_seize` (`clean_bad_debt` only helps *after* losses are already realized).

### Likelihood Explanation

Low-to-moderate. It requires a spoke asset that is simultaneously `no_seize = true` and `is_collateralizable = true` — a plausible intermediate state when governance halts seizure on a degraded asset but has not yet removed collateral privileges (flag relaxation/removal is itself timelocked via `relax_spoke_asset_flags`). No malicious governance proposal is needed; the attacker only needs permissionless `supply` during that window, plus a position that later goes unhealthy — which the attacker can arrange deliberately by borrowing near the limit on volatile collateral. Cost is one dust-ish supply of the flagged asset.

### Recommendation

Do not gate the *entire* pro-rata seizure on `no_seize`. Either:

- Drop `no_seize` legs from `seized_collaterals` instead of reverting, and scale down `repay_usd` to what the remaining collateral backs (the machinery for this already exists via `release_unbacked_repayment` / the `unbacked_usd` path in `build_liquidation_plan`), or
- Block new *supply entries* of `no_seize` assets in `require_can_supply` and treat existing flagged positions as seizable-anyway or as excluded-with-debt-haircut, so the flag cannot be weaponized after the fact.

At minimum, pair `no_seize` enforcement with a deadline after which it degrades to "leg excluded" rather than "liquidation halted".

### Proof of Concept

1. `add_asset_to_spoke` for token X with `can_collateral=true`, then governance `set_spoke_asset_flags(spoke, X, paused=false, frozen=false, no_seize=true)` — flag tightening is permitted immediately by the guardian.
2. Attacker `supply(caller=attacker, account_id=0, spoke_id, [(X, amt), (Y, collateral)])`, then `borrow(...)` near the LTV limit in debt token D.
3. Push the price of Y (or accrue interest) until `is_liquidatable(account_id)` is true.
4. `liquidate(liquidator, account_id, [(D, offer)], SeizeMode::Transfer)` → reverts `#318 SpokeAssetSeizureHalted` at `enforce_spoke_asset_flags` for the X leg; identical for `SeizeMode::Credit(0)`.
5. Repeat: no liquidator can ever close the account while the X leg yields a nonzero planned seizure. When collateral ≤ 5 WAD, any caller runs `clean_bad_debt`, writing the unpaid debt down through the supply index — suppliers absorb the loss.

This is exactly the existing test-observed behavior — "one `no_seize` leg makes the entire liquidation fail with `SpokeAssetSeizureHalted`" ( [9](#0-8) ) — reachable and weaponizable by a permissionless `supply`.
