### Title
Unauthenticated pipeline-run `Resume` endpoint allows unauthorized job completion / DoS via `PATCH /v2/resume/:runID` - (File: core/web/router.go, core/web/pipeline_runs_controller.go)

### Summary
CVE-2019-15043 describes Grafana exposing parts of its HTTP API without authentication, enabling an unauthenticated denial-of-service attack. The Chainlink node's web router has an analogous unauthenticated route: `PATCH /v2/resume/:runID`, registered without any `auth.Authenticate` middleware, which lets any network client resume/complete a pipeline task by UUID.

### Finding Description
In `v2Routes`, the route group `unauthedv2` is created with no authentication middleware and registers: [1](#0-0) 

This is distinct from the `authv2` and `userOrEI` groups later in the same function, which wrap all other job/run endpoints with `auth.Authenticate(...)` and role checks: [2](#0-1) [3](#0-2) 

The handler `PipelineRunsController.Resume` accepts an arbitrary `runID` (a UUID `taskID`), decodes an attacker-controlled JSON body into a `pipeline.ResumeRequest`, and calls `prc.App.ResumeJobV2(ctx, taskID, result)` directly — with no session, no API token, and no external-initiator check: [4](#0-3) 

The code itself acknowledges this is intentionally unauthenticated by logging `audit.UnauthedRunResumed`, meaning it's a known "webhook resume" callback design — but it still constitutes unauthenticated access to a part of the HTTP API that can mutate job/run state, matching the CVE's bug class (unauthenticated HTTP API surface).

### Impact Explanation
An unauthenticated client who can guess or brute-force a valid pending `taskID` (UUID) can complete/resume arbitrary pending pipeline tasks with attacker-supplied `ResumeRequest` results, potentially forcing incorrect task outputs into a running job pipeline (which can gate on-chain transaction submission, e.g. VRF/OCR jobs waiting on external adapter callbacks) or repeatedly hitting the endpoint with garbage/invalid payloads to cause errors/DoS-style load on `ResumeJobV2`, echoing the "unauthenticated API causing DoS" class from the CVE. Because UUIDs are 128-bit and typically not disclosed publicly, exploitation requires knowledge of an in-flight run's `runID`, which somewhat limits blind exploitation, but the endpoint is still fully unauthenticated by design and callable by any internet client if the node's web port is internet-facing.

### Likelihood Explanation
Moderate to low: exploitation requires a valid, still-pending `runID` for a task awaiting resume (typically obtained via a bridge/external-adapter callback URL that the operator configured to call back into this endpoint). If those callback URLs/tokens leak or are guessable, or if a bridge integration echoes the runID insecurely, an external unprivileged actor could invoke this without any Chainlink authentication.

### Recommendation
- Confirm whether `/v2/resume/:runID` is intended to be reachable only via internal/bridge callbacks; if so, ensure it is not exposed on the public-facing listener, or require a per-run unguessable/rotating secret and/or bind it to a private/internal network interface only, separate from the main authenticated API.
- Add validation on `ResumeRequest` size/rate to prevent DoS-style abuse (rate limiting is currently applied node-wide, but this specific route has no dedicated stricter limiter for unauthenticated access, unlike `sessionRoutes`' `unauth` group which applies `rl.UnauthenticatedPeriod()`/`rl.Unauthenticated()`) — compare: [5](#0-4) .
- Consider requiring a signed/HMAC resume token bound to the `runID` rather than relying on UUID secrecy alone.

### Proof of Concept
```
PATCH /v2/resume/<known-or-guessed-runID>
Content-Type: application/json

{"error": null, "value": "<attacker-controlled-result>"}
```
No `Cookie`, `X-Chainlink-EA-AccessKey`, or `X-Chainlink-EA-Secret` headers are required — the request is routed through `unauthedv2` with no `auth.Authenticate` middleware, reaching `PipelineRunsController.Resume` directly, as shown at [1](#0-0)  and [4](#0-3) .

func (prc *PipelineRunsController) Resume(c *gin.Context) {
	taskID, err := uuid.Parse(c.Param("runID"))
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	rr := pipeline.ResumeRequest{}
	decoder := json.NewDecoder(c.Request.Body)
	err = errors.Wrap(decoder.Decode(&rr), "failed to unmarshal JSON body")
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	result, err := rr.ToResult()
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	if err := prc.App.ResumeJobV2(c.Request.Context(), taskID, result); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
	c.Status(http.StatusOK)
}
