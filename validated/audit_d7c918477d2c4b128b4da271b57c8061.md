### Title
Bridge and External Initiator outgoing tokens/secrets are stored unencrypted in the database and exposed in plaintext to any authenticated Read-role user via `GET /v2/bridge_types` and `GET /v2/external_initiators` - ([File: core/web/presenters/bridges.go])

### Summary
The Jenkins OpenShift Pipeline Plugin advisory describes tokens persisted unencrypted in job configuration and readable by users holding only read-level permission. Chainlink has an analogous pattern: `BridgeType.OutgoingToken` and `ExternalInitiator.OutgoingToken`/`OutgoingSecret` are generated once as plaintext, persisted unencrypted in Postgres, and then re-served in plaintext on every subsequent `Index`/`Show` read call, not just at creation time.

### Finding Description
`bridges.NewBridgeType` generates an `OutgoingToken` and stores it unhashed in the `BridgeType` struct that is persisted via `CreateBridgeType`/`UpdateBridgeType`. [1](#0-0) [2](#0-1) 

Unlike `IncomingToken`, which is hashed (`IncomingTokenHash`) and only ever exposed once at creation, `OutgoingToken` has no hash/redaction path at all: it is stored in cleartext and included unconditionally in `presenters.NewBridgeResource`, which backs both `Show` (single bridge) and `Index` (list all bridges) endpoints: [3](#0-2) [4](#0-3) 

The same pattern exists for External Initiators: `ExternalInitiator.OutgoingToken`/`OutgoingSecret` are generated as random plaintext secrets, stored unencrypted in the `external_initiators` table (`outgoing_secret`, `outgoing_token` columns), and `ExternalInitiatorResource.OutgoingToken` is returned on every `Index` call: [5](#0-4) [6](#0-5) [7](#0-6) [8](#0-7) 

These outgoing tokens/secrets are the credentials Chainlink itself sends outward when calling external adapters/initiators (analogous to the "authorization tokens" in the Jenkins advisory) — anyone who can read the config (via API or DB) can replay them to impersonate the Chainlink node to the adapter/initiator, or (for EI) craft authenticated requests back to Chainlink using `OutgoingToken`/`OutgoingSecret` headers, depending on how the initiator validates callbacks.

Also note the generic web-request logging redaction only strips fields literally containing "password"; it does not redact "token" or "secret" fields, so any token/secret values passed through query params or JSON bodies elsewhere in the API would also leak into debug logs: [9](#0-8) 

### Impact Explanation
Because `OutgoingToken` (bridges) and `OutgoingToken`/`OutgoingSecret` (external initiators) are stored unhashed and returned on ordinary read (`GET`) API calls — not only at creation — any authenticated Chainlink node-UI/API user who can list bridges or external initiators (this is gated by session/API-key authentication on the node's web server, but not by any special "admin-only, write-only" separation for these read endpoints) can retrieve live outbound authentication material. This enables:
- Impersonating the Chainlink node when calling the external adapter/bridge (`OutgoingToken`).
- Forging authenticated inbound "run" requests toward the node's External Initiator webhook endpoints using `OutgoingSecret`/`OutgoingToken`, potentially triggering unauthorized job runs.

I could not fully verify from the index whether the bridge/EI read endpoints are restricted to an "Admin"-only role versus any authenticated user role (the `router.go` role-gating logic did not fully resolve in this session), so the exact set of authorized "unprivileged" roles that can reach these endpoints is not confirmed with full certainty.

### Likelihood Explanation
Reaching this requires only a valid, already-authenticated node API session/API key — no additional privilege escalation, chain, or timing constraints. Every `GET` list/show call on bridges or external initiators leaks the token, so exposure is continuous, not a one-time creation response.

### Recommendation
- Hash `OutgoingToken`/`OutgoingSecret` for storage the same way `IncomingToken` is hashed, or encrypt them at rest, and only ever return the plaintext once at creation time (mirroring the existing `IncomingToken` design).
- Remove `OutgoingToken` from `BridgeResource`/`ExternalInitiatorResource` used by `Index`/`Show`, and only return it from `Create` (and rotate on demand).
- Extend `isBlacklisted` in `core/web/router.go` to redact fields containing `token`/`secret` in request/response logging, not just `password`.
- Gate any endpoint that must reveal these secrets behind a stricter role than general read access.

### Proof of Concept
1. Create a bridge via `POST /v2/bridge_types` with a valid node session; note the returned `outgoingToken`.
2. As any authenticated user able to call `GET /v2/bridge_types` or `GET /v2/bridge_types/:name`, observe that `outgoingToken` is returned again in the JSON:API response body (`presenters.NewBridgeResource`), even though this call is a read-only "Show/Index" and was not expected to reveal secret material beyond initial issuance.
3. Repeat with `POST /v2/external_initiators` then `GET /v2/external_initiators`, observing `outgoingToken` returned in the list resource (`presenters.NewExternalInitiatorResource`).
4. Use the leaked `outgoingToken` to authenticate as the node to the corresponding bridge/external adapter, or (for EI) attempt to forge job-run trigger requests using the leaked `OutgoingSecret`/`OutgoingToken` pair.

func (btc *BridgeTypesController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	bridges, count, err := btc.App.BridgeORM().BridgeTypes(ctx, offset, size)

	resources := make([]presenters.BridgeResource, 0, len(bridges))
	for _, bridge := range bridges {

	}

	paginatedResponse(c, "Bridges", size, page, resources, count, err)

// Show returns the details of a specific Bridge.
func (btc *BridgeTypesController) Show(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	bt, err := btc.App.BridgeORM().FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}

// NewExternalInitiator generates an ExternalInitiator from an
// auth.Token, hashing the password for storage
func NewExternalInitiator(
	eia *auth.Token,
	eir *ExternalInitiatorRequest,
) (*ExternalInitiator, error) {
	salt := utils.NewSecret(utils.DefaultSecretSize)
	hashedSecret, err := auth.HashedSecret(eia, salt)
	if err != nil {
		return nil, pkgerrors.Wrap(err, "error hashing secret for external initiator")
	}

	return &ExternalInitiator{
		Name:           strings.ToLower(eir.Name),
		URL:            eir.URL,
		AccessKey:      eia.AccessKey,
		HashedSecret:   hashedSecret,
		Salt:           salt,
		OutgoingToken:  utils.NewSecret(utils.DefaultSecretSize),
		OutgoingSecret: utils.NewSecret(utils.DefaultSecretSize),
	}, nil
}

var blacklist = map[string]struct{}{
	"password":             {},

	"oldpassword":          {},
	"current_password":     {},
	"new_account_password": {},
}

func isBlacklisted(k string) bool {
	lk := strings.ToLower(k)
	if _, ok := blacklist[lk]; ok || strings.Contains(lk, "password") {
		return true
	}
	return false
}
