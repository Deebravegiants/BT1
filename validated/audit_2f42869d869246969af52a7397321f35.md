Audit Report

## Title
Vault gateway handler logs the raw JWT bearer token (`req.Auth`) in plain text on every incoming request - (File: `core/services/gateway/handlers/vault/handler.go`)

## Summary
`HandleJSONRPCUserMessage` in the vault gateway handler logs the entire incoming `jsonrpc.Request[json.RawMessage]` object (`"request", req`) at Debug level before any authentication/authorization occurs. Since the request's `Auth` field carries the caller-supplied JWT used to authenticate vault secret operations, this results in the bearer token being written to node logs verbatim whenever `Log.Level = 'debug'`.

## Finding Description
`HandleJSONRPCUserMessage` unconditionally executes `h.lggr.Debugw("handling vault request", "method", req.Method, "requestID", req.ID, "request", req)` before the request ID length check even completes and well before `h.requestProcessor.ProcessRequest` performs authorization. `req` is a `jsonrpc.Request[json.RawMessage]` whose `Auth` field is populated by clients with a signed JWT that authenticates the entire request (including a digest binding derived via `req.Digest()`) for `vault.secrets.*` methods. Because zap's `Debugw` serializes the passed struct value including all exported fields via reflection, and there is no custom marshaler or redaction applied to `Auth`, the raw JWT ends up in the log output. This is a genuine departure from the codebase's own established discipline: the authorization code paths in `core/capabilities/vault/authorizer.go` and `jwt_based_auth.go` consistently log only `"hasAuth", req.Auth != ""` rather than the raw token, and the system test helpers explicitly strip `Auth` before marshaling the wire body via `outboundRequestWithoutAuth`. No authentication or authorization check precedes this log line, so it fires for any caller reaching the gateway's vault JSON-RPC endpoint.

## Impact Explanation
This maps to a key/secret exfiltration and credential-disclosure impact class. Any party with read access to node logs (log aggregators, support tooling, crash dumps, shared debugging channels) can extract the raw per-request JWT, along with any claims embedded in it (org ID, workflow owner, OAuth scopes). Since the JWT is the object validated by `jwtBasedAuth.AuthorizeRequest` and bound to a request digest, an attacker obtaining a still-valid logged token could replay it against the gateway with a matching payload before expiry, or otherwise recover sensitive tenant/ownership metadata. This is a real, concrete leak of authentication credential material — not merely a hypothetical downstream secondary effect.

## Likelihood Explanation
High. This triggers deterministically on every vault gateway request; no attacker action is required beyond having log access, and the only condition is `Log.Level = 'debug'`, a normal, supported, documented operational configuration (not an exotic or unsupported setting). It is reachable by any unprivileged client capable of sending an HTTP request to the gateway's vault endpoint, since the log statement executes prior to any authorization check.

## Recommendation
Redact `req.Auth` before logging the request object in `HandleJSONRPCUserMessage`, e.g., construct a shallow copy with `Auth` cleared or masked, or log only safe fields (`method`, `id`, `"hasAuth", req.Auth != ""`) as already done consistently elsewhere in the vault authorizer code. Add a regression test analogous to `TestVaultHandler_InvalidParamsDoesNotLogRawParams` that asserts the JWT value never appears in captured log output for `HandleJSONRPCUserMessage`.

## Proof of Concept
1. Configure a node with `Log.Level = 'debug'`.
2. Send a vault JSON-RPC request (e.g., `vault.secrets.list`) to the gateway's vault handler endpoint with header `Authorization: Bearer <jwt>`, which is decoded into `req.Auth` by `jsonrpc2.DecodeRequest`.
3. Observe the log line emitted at `core/services/gateway/handlers/vault/handler.go:403` — `"handling vault request" method=... requestID=... request={... Auth:<jwt> ...}` — containing the full JWT in plaintext, before `ProcessRequest`/authorization has run.
4. Confirm via a Go test using an observed `zap` core (as in `handler_test.go`'s existing pattern) that the log entry's context map or message contains the literal JWT string passed as `req.Auth`. [6](#0-5) [7](#0-6) [8](#0-7) [5](#0-4)

		v.lggr.Debugw("JWTBasedAuth token validation failed", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, fmt.Errorf("invalid JWT auth token: %w", err)
	}

	if scopeErr := enforceVaultJWTOAuthScopes(req.Method, claims.OAuthScopes); scopeErr != nil {

		return nil, fmt.Errorf("invalid JWT auth token: %w", scopeErr)
	}

	if claims.TenantID == 0 {
		return nil, ErrMissingTenantID
	}
	if claims.TenantID != v.expectedTenantID {

func (h *handler) HandleJSONRPCUserMessage(ctx context.Context, req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) error {
	if req.ID == "" {
		return errors.New("request ID cannot be empty")
	}
	if len(req.ID) > 200 {
		// Arbitrary limit to prevent abuse
		return errors.New("request ID is too long: " + strconv.Itoa(len(req.ID)) + ". max is 200 characters")
	}

	h.lggr.Debugw("handling vault request", "method", req.Method, "requestID", req.ID, "request", req)
	if req.Method == vaulttypes.MethodPublicKeyGet {
		// Public key requests don't require authorization,
		// Let's process this request right away.
		// Note we cache this value quite aggressively so don't need to worry about DoS.
		publicKeyResponseBytes, cachedPublicKey := h.getCachedPublicKey()
		if cachedPublicKey == nil {
			// Not found in cache. Fetch from nodes.
			ar, err := h.newActiveRequest(req, callback)
			if err != nil {
				h.lggr.Errorw("failed to create new activeRequest", "error", err)
				return err
			}
			return h.handlePublicKeyGet(ctx, ar)
		}
		h.lggr.Debugw("returning cached public key response")
		return h.handlePublicKeyGetSynchronously(ctx, req, publicKeyResponseBytes, callback)
	}

	if !vaulttypes.IsGatewaySecretsMethod(req.Method) {
		return h.sendImmediateUserResponse(ctx, req, callback, api.UnsupportedMethodError, errors.New("this method is unsupported: "+req.Method))
	}

	_, cachedPublicKey := h.getCachedPublicKey()
	authorized, err := h.requestProcessor.ProcessRequest(ctx, &req, cachedPublicKey)
	if err != nil {
		if vaultcap.IsInvalidVaultParamsError(err) {
			return h.sendImmediateUserResponse(ctx, req, callback, api.InvalidParamsError, err)
		}
		h.lggr.Errorw("request not authorized", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "", "error", err)
		return errors.New("request not authorized: " + err.Error())
	}
