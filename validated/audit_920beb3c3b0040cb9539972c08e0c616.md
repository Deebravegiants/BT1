### Title
Unbounded, unpriced `handle_unsigned` message batches let any peer force full-cost ISMP proof verification on every node's mempool for free — analog of ALPINE-CVE-2020-10745 (Samba NetBios CPU-exhaustion DoS) - ([File: modules/pallets/ismp/src/lib.rs])

### Summary
`pallet_ismp::Call::handle_unsigned` accepts an unbounded `Vec<Message>` and is dispatched with a single static weight regardless of batch size or content. Because it is an **unsigned** extrinsic, every full node on the network runs `ValidateUnsigned::validate_unsigned` on it as soon as it is gossiped — which calls `Self::execute(messages.clone())`, i.e. the *entire* consensus/state-proof verification pipeline for every message in the batch — before any fee is charged and before the transaction is even included in a block. An attacker can submit one crafted unsigned extrinsic containing a very large number of `Message::Request`/`Message::Response`/`Message::Consensus` entries, forcing every receiving node to redo full merkle/consensus verification work for free, repeatedly (on every rebroadcast), with no cost to the attacker. This mirrors the Samba CVE-2020-10745 bug class: unauthenticated network input triggers processing whose cost is not bounded relative to the resources the sender expended, producing a remote CPU-exhaustion DoS.

### Finding Description
- `handle_unsigned` takes `messages: Vec<Message>` with no cap on length and a fixed weight annotation that does not scale with `messages.len()`: [1](#0-0) 
- The static weight function used for this call is a constant regardless of the number/size of messages: [2](#0-1) 
- `ValidateUnsigned::validate_unsigned` for `pallet_ismp` — which every node runs on receipt of any gossiped unsigned transaction, *before* inclusion and *before* any fee is charged — calls `Self::execute(messages.clone())`, i.e. runs the full message-handling pipeline (consensus proof verification, state/membership proof verification, etc.) for the entire batch: [3](#0-2) 
- `Self::execute` iterates over every message in the (unbounded) `Vec<Message>` and calls `handle_incoming_message` for each one, which for `Message::Request`/`Message::Response`/`Message::Consensus` performs full consensus-client lookups, delay-period checks, and membership-proof verification: [4](#0-3) [5](#0-4) 
- There is no `MaxMessages`/`BoundedVec` constraint anywhere in the codebase limiting the number of messages a single `handle_unsigned` extrinsic can carry (confirmed via search — no `MaxMessages`, `max_messages`, or `messages.len()` guard exists in `pallet-ismp`).
- The project's own documentation acknowledges the "free execution" model relies on the mempool validity check being cheap enough to filter spam, but the check itself *is* the full, unbounded verification workload: [6](#0-5) 

Because `RequestMessage::handle` (and the equivalent Response/Consensus paths) does not reject on cheap, size-proportional checks first — it performs consensus-client resolution, duplicate/timeout/proxy checks per request, and *then* full membership-proof verification against the state commitment for every request in the batch — the total CPU work done during `validate_unsigned` scales linearly (or worse, depending on proof type/consensus client) with the number of items an attacker packs into the single extrinsic, while the extrinsic itself costs nothing to submit (unsigned, no fee) and nothing is charged even if it fails validation. [7](#0-6) 

### Impact Explanation
This is a resource-exhaustion / availability issue reachable directly from a single unprivileged, unsigned extrinsic submitted by any network participant (no relayer registration, no stake, no fee) — exactly the class of "unprivileged message dispatcher" reachable path called out in the prompt (pallet-ismp `handle_unsigned`). Because the extrinsic is unsigned and gossiped, the cost is paid by *every full node* on the chain that validates the transaction pool entry, not just the block producer, and it recurs on every re-gossip/re-validation cycle (each node revalidates queued transactions periodically). A sustained stream of such crafted batches can degrade or halt block production and RPC availability for the whole network — a "route unable to deliver messages" condition, matching the "concrete... route unable to deliver messages" acceptance bar in the validation rules.

### Likelihood Explanation
High: the entry point is completely unauthenticated (unsigned transaction, `ensure_none(origin)`), requires no proof to actually verify successfully (verification failure is fine — the CPU cost is paid during validation regardless of the final Ok/Err outcome), and there is no batch-size or per-message weight-based rejection prior to running `Self::execute`. The only limits are generic extrinsic-length/block-length limits, which still permit thousands of small `Request`/`Response`/`Consensus` messages (each is compact — nonce, addresses, small proof blobs) to be packed into one extrinsic.

### Recommendation
- Bound `handle_unsigned`'s `messages: Vec<Message>` with a configurable `MaxMessages` (or a `BoundedVec`), rejected before any verification work begins.
- In `validate_unsigned`, perform cheap, size/format-only checks (e.g., message count, per-message declared proof-size caps, and any cacheable/precomputed rejection heuristics) *before* invoking the full `Self::execute` pipeline, so obviously-oversized or clearly-invalid batches are rejected without doing consensus/membership verification.
- Make the declared `#[pallet::weight(...)]` for `handle_unsigned` scale with `messages.len()` (and/or proof size) so `CheckWeight`-style accounting reflects true worst-case cost, and consider rate-limiting/penalizing peers whose unsigned submissions repeatedly fail validation.

### Proof of Concept
1. Construct a single `pallet_ismp::Call::handle_unsigned` extrinsic whose `messages` field contains a very large number (bounded only by the runtime's max extrinsic/block length) of `Message::Request(RequestMessage { requests: [...], proof: Proof { ... }, signer: ... })` entries, each referencing a valid, existing `StateMachineHeight`/consensus state id so that `validate_state_machine` succeeds and the full membership-proof verification path in `modules/ismp/core/src/handlers/request.rs` is reached for every request in every message.
2. Fill the `proof` field with syntactically valid but ultimately-incorrect merkle proof bytes (so decoding succeeds and full verification runs, but the final commitment check fails only at the very end).
3. Submit the extrinsic unsigned to the network; every peer's transaction pool calls `ValidateUnsigned::validate_unsigned`, which calls `Self::execute(messages.clone())`, running the full per-message pipeline (consensus lookups, duplicate/timeout checks, and merkle membership verification) for the entire batch before rejecting it — with zero fee charged and no weight penalty, since the transaction never gets included.
4. Repeat/resubmit slightly-modified variants continuously (each producing a different `provides` tag so the pool doesn't dedupe it) to sustain CPU load across the network's full nodes.

(Note: I was not able to fully trace the exact per-message cost of every consensus-client variant — e.g., BEEFY/Tendermint/BSC verifiers — within the remaining investigation budget, so the precise multiplier of CPU cost per crafted message versus a `Request`-only batch is not confirmed; the core vulnerability — an unbounded, unsigned, free-to-submit batch that triggers full verification during mempool validation — is confirmed directly from the cited code.)

/// This function serves as an entry point to handle the message types provided by the ISMP protocol
pub fn handle_incoming_message<H>(
	host: &H,
	message: Message,
) -> Result<MessageResult, anyhow::Error>
where
	H: IsmpHost,
{
	match message {
		Message::Consensus(consensus_message) => consensus::update_client(host, consensus_message),
		Message::FraudProof(fraud_proof) => consensus::freeze_client(host, fraud_proof),
		Message::Request(req) => request::handle(host, req),
		Message::Response(resp) => response::handle(host, resp),
		Message::Timeout(timeout) => timeout::handle(host, timeout),
	}
}

## Transaction fees

Pallet ISMP uses unsigned transactions for executing cross-chain messages. This means all cross-chain messages received are executed for free as unsigned transactions. The upside to this is that it cannot be exploited as a spam vector, since the transaction pool will check if the submitted extrinsics are valid before they are included in the pool. This validity check ensures that the transaction can be successfully executed and contains valid proofs. Malformed messages or those with invalid proofs are filtered out by the transaction pool validation logic preventing unnecessary processing and potential network congestion.

pub fn handle<H>(host: &H, msg: RequestMessage) -> Result<MessageResult, anyhow::Error>
where
	H: IsmpHost,
{
	if msg.requests.is_empty() {
		Err(Error::EmptyBatch)?
	}

	let state_machine = validate_state_machine(host, msg.proof.height)?;
	let consensus_clients = host.consensus_clients();
	let check_state_machine_client = |state_machine: StateMachine| {
		consensus_clients
			.iter()
			.find_map(|client| client.state_machine(state_machine).ok())
			.is_none()
	};

	let router = host.ismp_router();

	// Reject duplicate requests within the batch. Wire format is `Vec`,
	// so this is the line of defence against an attacker padding a
	// batch with identical requests.
	let wrapped: Vec<Request> = msg.requests.iter().cloned().map(Request::Post).collect();
	dedup_requests::<H>(&wrapped)?;

	for req in msg.requests.iter() {
		let req = Request::Post(req.clone());
		// If a receipt exists for any request then it's a duplicate and it is not dispatched
		if host.request_receipt(&req).is_some() {
			Err(Error::DuplicateRequest { meta: req.clone().into() })?
		}

		// can't dispatch timed out requests
		if req.timed_out(host.timestamp()) {
			Err(Error::RequestTimeout { meta: req.clone().into() })?
		}

		// either the host is a router and can accept requests on behalf of any chain
		// or the request must be intended for this chain
		if req.dest_chain() != host.host_state_machine() && !host.is_router() {
			Err(Error::InvalidRequestDestination { meta: req.clone().into() })?
		}

		let source_chain = req.source_chain();

		// in order to allow proxies, the host must configure the given state machine
		// as it's proxy and must not have a state machine client for the source chain
		let allow_proxy = host.is_allowed_proxy(&msg.proof.height.id.state_id) &&
			check_state_machine_client(source_chain);

		// check if the request is allowed to be proxied
		if source_chain != msg.proof.height.id.state_id && !allow_proxy {
			Err(Error::RequestProxyProhibited { meta: req.clone().into() })?
		}
	}

	// Verify membership proof
	let state = host.state_machine_commitment(msg.proof.height)?;
