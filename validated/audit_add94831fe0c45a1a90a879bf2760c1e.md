I found a genuine analog: the **Phantom order price snapshot / weighted-median liquidity oracle** in the intents system exhibits the same underlying flaw as the reported `quitLock` bug — a participant can present a **transient, self-inflated balance/weight snapshot to skew a value used by others**, without that snapshot reflecting any durable, penalized commitment. Let me confirm the exact mechanics of the weighting and how balance is read at bid-aggregation time.### Title
Flash-loanable balance inflates a solver's weight in the Phantom-order weighted-median price oracle — ([File: sdk/packages/sdk/src/protocols/intents/phantom-aggregation.ts])

### Summary
The Phantom order price feed weights every solver's price quote by a **point-in-time, unpinned on-chain balance read** (`getBalance`, defaulting to the chain head) rather than by any durable, penalized commitment. Because `weightedMedian` is a *selection* (it returns one bidder's exact quoted price, not a blend), a solver that can transiently inflate its own balance for the duration of one bid window can force the published median to its own extreme value, with **no economic penalty on unwinding** — unlike the reported `quitLock` case, which at least charged a proportional penalty. This is the same bug class as the external report: a transient, flash-loanable balance is read as if it were a durable, economically-backed commitment and used to grant outsized influence over a value other parties rely on.

### Finding Description
`aggregatePhantomBids` in `sdk/packages/sdk/src/protocols/intents/phantom-aggregation.ts` weights each solver's leg quote by `getBalance(destUrl, chain, outputToken, solver)` [1](#0-0) , which is `getTotalSolverBalance` — a live ERC-20 + vault-share balance read, by default at the current chain head with no lock, staking, or penalty attached [2](#0-1) .

The only gate on who can submit a weighted bid is `isVerifiedSolverBid`, which checks a signature over the order and that the sender is **EIP-7702-delegated to the chain's SolverAccount contract** [3](#0-2) . EIP-7702 delegation is self-authorized by the EOA owner to a *public* contract address, so any unprivileged actor can become a "solver" for this purpose without any admission control or bonding.

`weightedMedian` then picks one bidder's exact price once its cumulative weight crosses half the total weight — it is a selection, not an average — and the snapshot explicitly sets `lowestPrice = highestPrice = medianPrice` [4](#0-3) , and the docs confirm: "a solver holding over half the leg's weight sets the published price verbatim" [5](#0-4) .

This mirrors the `quitLock` bug class exactly: in the FIAT DAO report, a flash-loaned balance was locked and immediately unwound to buy transient voting power, with the mitigating factor being a penalty tied to lock duration that (per the fix analysis) made the attack uneconomical. Here, there is **no analogous penalty at all** — a solver only needs to hold the balance long enough for one RPC read (`eth_call` at "latest") during the bid-aggregation window, not even for a full block if timed against the indexer's read.

### Impact Explanation
The resulting `PhantomOrderPriceSnapshotV2.medianPrice` is not just informational — it is consumed by `PhantomSnapshotIntentQuoteStrategy.quote()` to price real user intents [6](#0-5) , and by `updateLiquidityPools` to set the pool's published `sellRate`/`buyRate` used across the indexer [7](#0-6) . An attacker who flash-loans tokens into an EIP-7702-delegated EOA, submits one extreme-priced bid with dominant weight, and returns the funds can push a manifestly wrong price into a feed that subsequently quotes real intents for other users — this is a "forged" market signal analogous to forged message delivery/unsound state commitment in spirit: unbacked temporary capital manipulates a value trusted by third parties, and real users can be quoted (and fill) at manipulated rates, resulting in a realizable loss for users or the protocol's counter-parties. This meets the Medium bar (as in the original C4 finding) rather than a mere informational issue since it affects on-chain economic quoting, not just monitoring.

### Likelihood Explanation
Likelihood is bounded by two factors that reduce it below the original report's severity: (1) the attacker must self-delegate via EIP-7702 to the specific `SolverAccount` contract and (2) must win the flash-loan race against the exact RPC read timing (`blockTag` head at aggregation time), which the periodic indexer sweep does in a narrow window after `PhantomBidWindowExhausted`. However — unlike `quitLock` — there is **zero economic penalty** for holding and releasing the balance, so once the timing is solved the attack is essentially free, making it more attractive than the disputed `quitLock` scenario where the penalty made the attack largely uneconomical at scale.

### Recommendation
- Weight bids by a balance that cannot be manipulated within a single transaction/block — e.g., require the balance to be observed and unchanged across N blocks, or read balance at a block committed to *before* the bid was placed (bid-time snapshot rather than aggregation-time snapshot).
- Introduce an economic cost to influence weight, mirroring what makes `quitLock`'s penalty at least partially effective — e.g., require solvers to lock/stake the inventory they intend to be weighted by for the duration of the bid window, with slashing on early withdrawal.
- Consider bounding a single bidder's maximum share of total weight per leg so no single solver (however funded) can set the price verbatim via the `weightedMedian` selection.

### Proof of Concept
1. Attacker EOA self-delegates via EIP-7702 to the target chain's public `SolverAccount` address (no protocol permission required).
2. Attacker takes a flash loan of the leg's output token into that EOA.
3. Attacker signs and submits a `place_bid` with an extreme output amount for the phantom order's leg (`sdk/packages/sdk/src/chains/intentsCoprocessor.ts submitBid`), timed just before the `PhantomBidWindowExhausted` event fires.
4. `handlePhantomOrderPrices` → `aggregatePhantomBids` reads the attacker's balance at (near) chain head via `getBalance`/`getTotalSolverBalance` [1](#0-0) , giving the bid dominant weight.
5. `weightedMedian` selects the attacker's extreme price verbatim as `medianPrice`/`lowestPrice`/`highestPrice` [8](#0-7) .
6. Attacker repays the flash loan; the manipulated snapshot persists and is served to real users via `PhantomSnapshotIntentQuoteStrategy.quote()` [6](#0-5)  until the next window closes.

//
// Callers must not hand this an entry set whose weights are all zero: with nothing to weight by it
// can only pick a quote by position, and for an even-sized set that position is the upper of the
// two middles — so "the median" becomes "whoever quoted higher", settable by a solver holding no
// inventory at all. aggregatePhantomBids drops such legs instead of pricing them. The fallback
// below stays only so an unguarded caller gets a number rather than a crash; treat reaching it as
// a caller bug.
export function weightedMedian(entries: { price: bigint; weight: bigint }[]): bigint {
	const sorted = [...entries].sort((a, b) => (a.price < b.price ? -1 : a.price > b.price ? 1 : 0))
	const totalWeight = sorted.reduce((acc, e) => (e.weight > 0n ? acc + e.weight : acc), 0n)

	if (totalWeight === 0n) {
		return sorted[Math.floor(sorted.length / 2)].price
	}

	let cumulative = 0n
	for (const entry of sorted) {
		if (entry.weight <= 0n) continue
		cumulative += entry.weight
		if (cumulative * 2n >= totalWeight) return entry.price
	}
	return sorted[sorted.length - 1].price
}

2. Per leg, a solver's quote is weighted by **its balance of that leg's OUTPUT token on the destination chain** — the inventory that actually backs the leg. Zero-weight quotes are dropped entirely, not down-weighted: they never reach the median, `bidCount`, or the bidder list. A leg where no bidder holds the output token is absent from the result, exactly as if nobody quoted it.

3. The leg's price is `weightedMedian` of the backed quotes — a **selection**, not a blend. It returns one bidder's exact integer, so a solver holding over half the leg's weight sets the published price verbatim, and the result can never be a value nobody quoted. `lowestPrice` and `highestPrice` are deliberately overwritten with the median so consumers cannot read an outlier bid as a tradeable bound.
