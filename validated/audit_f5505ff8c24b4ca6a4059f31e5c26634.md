Documented API confirms this is the exploitable path: `docs/usage/webhooks.md` explicitly tells app developers that `Registry.process` "will verify the request did indeed come from Shopify" — implying full trust in the resulting `WebhookMetadata`, including `shop`, once `process` succeeds. But the HMAC only covers the raw body, not the `shop-domain` header, so this documented guarantee is false for the `shop` field specifically.

### Title
Webhook shop identity not bound to HMAC signature enables cross-tenant webhook spoofing - (File: lib/shopify_api/webhooks/request.rb)

### Summary
`ShopifyAPI::Webhooks::Request#to_signable_string` returns only the raw request body, so `Utils::HmacValidator.validate` authenticates the payload bytes but never the `shopify-shop-domain` header. `Webhooks::Registry.process` nevertheless trusts `request.shop` (read straight from that unauthenticated header) and hands it to the app's handler as `WebhookMetadata#shop`, which the documented API tells developers is safe to trust after `process` "verifies the request did indeed come from Shopify."

### Finding Description
The identity binding broken here is: `hmac_verified_bytes == raw_body` while `tenant_identity_used == header["shopify-shop-domain"]`, i.e. `verified content != content used to resolve tenant`.

- `Request#hmac` reads the `hmac-sha256` header, and `Request#to_signable_string` returns `@raw_body` only [1](#0-0) .
- `Request#shop` reads the `shop-domain` header directly, with no relation to the signed bytes [2](#0-1) .
- `HmacValidator.validate` computes the HMAC solely over `verifiable_query.to_signable_string` (the body) and compares it to the header-provided `hmac` [3](#0-2) .
- `Registry.process` raises only if the HMAC (body) check fails, then unconditionally forwards `request.shop` into `WebhookMetadata` for the handler [4](#0-3) .
- The documented usage explicitly tells integrators that `process` "will verify the request did indeed come from Shopify and then call the specified handler," with no caveat that the `shop` field is unauthenticated [5](#0-4) .

Because the app's secret key signs only the body, any two webhook deliveries with identical bodies (e.g. topics whose payload is `{}`, or any payload an attacker's own shop can trigger and capture) produce identical valid HMACs regardless of which shop they were sent for. An attacker who is a legitimate (unprivileged) installer of the app for their own shop can capture one of their own genuine, Shopify-signed webhook deliveries (body + `hmac-sha256` header), then replay that exact body/HMAC pair to the app's webhook endpoint while substituting the `shopify-shop-domain` header for a victim shop. `HmacValidator.validate` still passes (it only checks the body), and `Registry.process` passes the attacker-chosen `shop` value straight to the handler as authenticated-looking `WebhookMetadata#shop`.

### Impact Explanation
Any host application that uses `WebhookMetadata#shop` (as documented) to select which tenant's data/session to mutate will process the forged event as belonging to the victim shop, chosen entirely by the attacker via an unauthenticated header. This is a cross-tenant boundary violation caused directly by this gem's own webhook verification code — the gem asserts request authenticity ("verify the request did indeed come from Shopify") but does not bind the tenant identifier it exposes to that authenticity check.

### Likelihood Explanation
The attacker only needs to be a normal, unprivileged merchant who installs the app on their own store (no special access, no leaked credentials, no access token) to obtain one valid signed webhook body/HMAC pair, then replay it with a modified header to any reachable webhook endpoint of the app. No knowledge of `api_secret_key` is required.

### Recommendation
Include the tenant-identifying header (`shopify-shop-domain`, and ideally `topic`/`webhook-id`/`api-version`) in the signable string used for HMAC verification, or independently verify that the `shop` header corresponds to a shop that is actually subscribed/expected for that specific `webhook_id`/topic before trusting it in `WebhookMetadata`.

      sig { returns(String) }

        T.cast(shopify_header("webhook-id"), String)

      def to_signable_string

      end

      sig { returns(T::Hash[String, T.untyped]) }
      def parsed_body

      end

      sig { params(raw_body: String, headers: T::Hash[String, T.untyped]).void }
      def initialize(raw_body:, headers:)
        # normalize the headers by forcing lowercase, removing any prepended "http"s, and changing underscores to dashes
        headers = headers.to_h { |k, v| [k.to_s.downcase.sub("http_", "").gsub("_", "-"), v] }

        missing_headers = []
        ["topic", "hmac-sha256", "shop-domain"].each do |name|
          unless headers.key?("shopify-#{name}") || headers.key?("x-shopify-#{name}")
            missing_headers << "shopify-#{name} or x-shopify-#{name}"
          end
        end
        unless missing_headers.empty?
          raise Errors::InvalidWebhookError,
            "Missing one or more of the required HTTP headers to process webhooks: #{missing_headers}"
        end

        @headers = headers
        @raw_body = raw_body
      end

      private

      def shopify_header(name)
        @headers["shopify-#{name}"] || @headers["x-shopify-#{name}"]
      end
    end

module ShopifyAPI
  module Utils
    module HmacValidator
      extend T::Sig

      class << self
        extend T::Sig

        sig { params(verifiable_query: VerifiableQuery).returns(T::Boolean) }
        def validate(verifiable_query)
          return false unless verifiable_query.hmac

          result = validate_signature(verifiable_query, Context.api_secret_key)
          if result || Context.old_api_secret_key.nil? || T.must(Context.old_api_secret_key).empty?
            result
          else
            validate_signature(verifiable_query, T.must(Context.old_api_secret_key))
          end
        end

        private

        sig { params(verifiable_query: VerifiableQuery, secret: String).returns(T::Boolean) }
        def validate_signature(verifiable_query, secret)
          received_signature = verifiable_query.hmac
          computed_signature = compute_signature(verifiable_query.to_signable_string, secret)
          OpenSSL.secure_compare(computed_signature, T.must(received_signature))
        end

        sig { params(signable_string: String, secret: String).returns(String) }
        def compute_signature(signable_string, secret)
          OpenSSL::HMAC.hexdigest(
            OpenSSL::Digest.new("sha256"),
            secret,
            signable_string,
          )
        end
      end
    end
  end
