### Title
Vault secret storage keys are case-sensitive while owner authorization is case-insensitive, allowing per-owner quota and duplicate-ID bypass - ([File: core/capabilities/vault/vaulttypes/types.go])

### Summary
The Vault capability authorizes a client's secret requests by comparing the client-supplied `SecretIdentifier.Owner` to the authenticated workflow owner using a case-insensitive/`0x`-agnostic comparison (`vaultutils.NormalizeOwner`). However, the actual storage key used to persist and count secrets (`vaulttypes.KeyFor`, and the raw `owner` string used as the KV-store metadata prefix) is **not** normalized. This mismatch lets an authorized client submit secret requests that are treated as "the same owner" for authorization purposes but as *different* owners for storage/duplicate-detection purposes, bypassing per-owner limits and duplicate-ID checks — the same bug class as the reported `CollateralManager` issue, where an entity with multiple string representations was double-counted/mismatched against a uniqueness check.

### Finding Description
`vaultutils.NormalizeOwner` lowercases and strips the `0x` prefix from an owner address and is used at every authorization comparison site: [1](#0-0) 

This is used in `authorizeRequest`/`validateSecretOwnersMatchAuthorized` to verify that a client-controlled `Id.Owner` in a `CreateSecrets`/`UpdateSecrets`/`DeleteSecrets`/`ListSecretIdentifiers` request matches the authenticated `workflowOwner`: [2](#0-1) [3](#0-2) 

Note this only requires `NormalizeOwner(id.Owner) == NormalizeOwner(workflowOwner)` — i.e., the client is free to pick **any casing** (and optional `0x` prefix) of their own address for `Id.Owner`, since normalization discards that information.

In contrast, `vaulttypes.KeyFor`, which is the canonical identity used for storage keys, duplicate-ID detection, and metadata indexing, does **not** normalize the owner at all: [4](#0-3) 

This raw (unnormalized) `KeyFor` is used to detect duplicate secret identifiers within a single request batch in the request validator: [5](#0-4) 

And the OCR plugin's KV store uses the raw, non-normalized `id.Owner` string directly as the metadata partition key, both for reading/writing metadata and for enforcing per-owner secret limits: [6](#0-5) [7](#0-6) 

Because `metadataPrefix + owner` is case-sensitive, `Owner = "abc123..."` and `Owner = "ABC123..."` (or `"0xabc123..."` vs `"abc123..."`) are two entirely distinct metadata records in the KV store, even though both pass authorization as "the same owner" (via `NormalizeOwner`). This directly parallels the reported `CollateralManager` flaw: a single logical entity (owner address / collateral token) has multiple valid string representations that are treated as equivalent by one check (balance lookup / owner authorization) but as distinct entries by another check (the `EnumerableSet` of collateral addresses / the KV-store owner-keyed metadata and duplicate-ID set).

### Impact Explanation
An authorized workflow owner can:
1. Bypass the "owner has reached maximum number of secrets" quota (enforced via `GetSecretIdentifiersCountForOwner(ctx, id.Owner)` on the raw, case-sensitive owner string) by submitting `CreateSecrets` requests using different casings of their own address as `Id.Owner`. Each casing variant is authorized (passes `NormalizeOwner` check) but creates an independent metadata record/quota bucket in the KV store, allowing unbounded secret storage growth per real owner and resource exhaustion of the shared KV store.
2. Bypass the intra-batch duplicate-secret-identifier check (`ValidateDeleteSecretsRequest`/`ValidateGetSecretsRequest`, which key on unnormalized `vaulttypes.KeyFor`) by supplying the "same" secret identifier twice with differently-cased owners, since the case-sensitive key makes them look distinct even though they refer to the same authorized owner.
3. Fragment their own secrets across multiple case-variant metadata records, complicating downstream consistency and potentially causing "list"/"delete" operations to silently miss secrets stored under a different owner casing than the one used for the list/delete request (a cross-representation state inconsistency), similar in spirit to permanently stranding/duplicating protected resources in the original report.

### Likelihood Explanation
This is fully reachable by any unprivileged, already-DON-authorized workflow (any client that owns a workflow and can send Vault requests through the gateway/OCR reporting path). No special privileges are required beyond being a normal Vault user — the attacker only needs to control the string casing of the `Owner` field in the JSON-RPC request payload, which is entirely client-supplied. The authorization layer's own design explicitly tolerates case/`0x`-prefix variation (that's the stated purpose of `NormalizeOwner`), so triggering the mismatch is trivial and requires no race condition or privileged access.

### Recommendation
Normalize the owner (via `vaultutils.NormalizeOwner` or equivalent) at the single canonical ingress point before it is used to build any storage/duplicate-detection key — i.e., inside `vaulttypes.KeyFor`, and/or immediately when constructing `SecretIdentifier`/KV-store keys in `kvstore.go` (`metadataPrefix+owner`, `keyPrefix+KeyFor(id)`), so that authorization equivalence and storage/quota equivalence are always consistent. Until then, do not rely on separate normalization at comparison sites only; canonicalize `Owner` once at request ingress (e.g., in the gateway/authorizer stamping step already referenced in `validateSecretOwnersMatchAuthorized`'s comment about "owner prefixing and param stamping happen later in GatewayVaultRequestProcessor") and use that canonical value everywhere downstream, including in `KeyFor`, `GetSecretIdentifiersCountForOwner`, and `WriteMetadata`/`GetMetadata` prefixing.

### Proof of Concept
1. Attacker's workflow is authorized with owner address `abc123...def` (arbitrary case as recovered/authenticated by the DON, e.g. lowercase).
2. Attacker sends a `CreateSecrets` request with `EncryptedSecret.Id.Owner = "ABC123...DEF"` (uppercase). `validateEncryptedSecretOwnerMismatch` passes because `NormalizeOwner("ABC123...DEF") == NormalizeOwner("abc123...def")`.
3. The OCR plugin's `KVStore.WriteSecret`/`addIDToMetadata` stores this secret under metadata key `Metadata::ABC123...DEF`, a distinct KV-store partition from `Metadata::abc123...def`.
4. Attacker repeats step 2 with many different casings of the same address, each creating up to `MaxSecretsPerOwner` secrets in its own partition (since `GetSecretIdentifiersCountForOwner` only checks secrets under the exact casing supplied), multiplying the effective per-owner secret quota by the number of distinguishable case permutations, and/or causing a `ListSecretIdentifiers`/`DeleteSecrets` request issued with the "canonical" lowercase owner to miss secrets stored under other casings.

package vaultutils

import "strings"

// NormalizeOwner lowercases an Ethereum owner address for case-insensitive comparison.
// All comparison sites must use this function. When VaultOwnerAddressCanonicalizationEnabled
// is introduced, normalization at ingress will supersede comparison-site calls here.
func NormalizeOwner(owner string) string {
	return strings.ToLower(strings.TrimPrefix(owner, "0x"))
}

func validateEncryptedSecretOwnerMismatch(encryptedSecrets []*vaultcommon.EncryptedSecret, workflowOwner string) error {
	if len(encryptedSecrets) == 0 {
		return errors.New("request batch must contain at least 1 item")
	}
	for idx, encryptedSecret := range encryptedSecrets {
		if encryptedSecret == nil {
			return fmt.Errorf("encrypted secret must not be nil at index %d", idx)
		}
		if encryptedSecret.Id == nil {
			return fmt.Errorf("secret ID must not be nil at index %d", idx)
		}
		if vaultutils.NormalizeOwner(encryptedSecret.Id.Owner) != vaultutils.NormalizeOwner(workflowOwner) {
			return fmt.Errorf("encrypted secret owner at index %d %q does not match authorized workflow owner %q", idx, encryptedSecret.Id.Owner, workflowOwner)
		}
	}
	return nil
}

func (r *RequestValidator) ValidateDeleteSecretsRequest(ctx context.Context, request *vaultcommon.DeleteSecretsRequest) error {
	if request.RequestId == "" {
		return errors.New("request ID must not be empty")
	}
	if err := r.MaxRequestBatchSizeLimiter.Check(ctx, len(request.Ids)); err != nil {
		if errBoundLimited, ok := errors.AsType[limits.ErrorBoundLimited[int]](err); ok {
			return fmt.Errorf("request batch size exceeds maximum of %d: %w", errBoundLimited.Limit, err)
		}
		return fmt.Errorf("failed to check request batch size limit: %w", err)
	}
	if len(request.Ids) == 0 {
		return errors.New("request batch must contain at least 1 item")
	}

	uniqueIDs := map[string]bool{}
	for idx, id := range request.Ids {
		if id == nil {
			return errors.New("secret ID must not be nil at index " + strconv.Itoa(idx))
		}
		if err := r.ValidateSecretIdentifier(ctx, id.Key, id.Owner, id.Namespace); err != nil {
			return fmt.Errorf("invalid secret identifier at index %d: %w", idx, err)
		}

		_, ok := uniqueIDs[vaulttypes.KeyFor(id)]
		if ok {
			return errors.New("duplicate secret ID found at index " + strconv.Itoa(idx) + ": " + id.String())
		}

		uniqueIDs[vaulttypes.KeyFor(id)] = true
	}
	return nil

func (s *KVStore) GetMetadata(ctx context.Context, owner string) (*vault.StoredMetadata, error) {
	defer s.trackDuration(ctx, "GetMetadata", time.Now())
	b, err := s.reader.Read([]byte(metadataPrefix + owner))
	if err != nil {
		return nil, fmt.Errorf("failed to read metadata: %w", err)
	}

	if b == nil {
		return nil, nil
	}

	md := &vault.StoredMetadata{}
	err = proto.Unmarshal(b, md)
	if err != nil {
		return nil, fmt.Errorf("failed to unmarshal md: %w", err)
	}
	return md, nil
}

func (s *KVStore) GetSecretIdentifiersCountForOwner(ctx context.Context, owner string) (int, error) {
	defer s.trackDuration(ctx, "GetSecretIdentifiersCountForOwner", time.Now())
	md, err := s.GetMetadata(ctx, owner)
	if err != nil {
		return 0, fmt.Errorf("failed to get metadata for owner %s: %w", owner, err)
	}

	count := 0
	if md != nil {
		count = len(md.SecretIdentifiers)
	}
	return count, nil
}

func (s *KVStore) metadataContainsID(ctx context.Context, id *vault.SecretIdentifier) (bool, error) {
	if id == nil {
		return false, errors.New("id cannot be nil")
	}
	md, err := s.GetMetadata(ctx, id.Owner)
	if err != nil {
		return false, fmt.Errorf("failed to get metadata for owner %s: %w", id.Owner, err)
	}

	if md == nil {
		return false, nil
	}

	for _, i := range md.SecretIdentifiers {
		if vaulttypes.KeyFor(id) == vaulttypes.KeyFor(i) {
			return true, nil
		}
	}

	return false, nil
}

func (s *KVStore) addIDToMetadata(ctx context.Context, id *vault.SecretIdentifier) error {
	if id == nil {
		return errors.New("id cannot be nil")
	}
	md, err := s.GetMetadata(ctx, id.Owner)
	if err != nil {
		return fmt.Errorf("failed to get metadata for owner %s: %w", id.Owner, err)
	}

	if md == nil {
		md = &vault.StoredMetadata{
			SecretIdentifiers: []*vault.SecretIdentifier{id},
		}
	} else {
		for _, i := range md.SecretIdentifiers {
			if vaulttypes.KeyFor(id) == vaulttypes.KeyFor(i) {
				// Nothing to do, early exit.
				return nil
			}
		}

		md.SecretIdentifiers = append(md.SecretIdentifiers, id)
	}

	err = s.WriteMetadata(ctx, id.Owner, md)
	if err != nil {
		return fmt.Errorf("failed to write metadata for owner %s: %w", id.Owner, err)
	}

	return nil
}
