## Title
`StateMachine::Display` collapses distinct invalid-UTF-8 chain identifiers to the same "XXXX" string, enabling identity confusion in string-keyed cross-chain lookups - (File: modules/ismp/core/src/host.rs)

### Summary
`StateMachine::Display` (used to render `Substrate`, `Tendermint`, and `Relay` variants to strings such as `"SUBSTRATE-<id>"`) silently substitutes any non-UTF-8 4-byte identifier with the literal string `"XXXX"` instead of failing. This mirrors the Netty CVE-2021-43797 bug class: rather than rejecting malformed/uninterpretable input, the code "sanitizes" it into a fixed, generic placeholder, so multiple distinct underlying byte identities become indistinguishable once serialized to string form.

### Finding Description [1](#0-0) 

For `StateMachine::Substrate`, `StateMachine::Tendermint`, and `StateMachine::Relay { relay, .. }`, the 4-byte consensus/parachain identifier is decoded with `String::from_utf8(id.to_vec()).unwrap_or("XXXX".to_string())`. Any byte sequence that is not valid UTF-8 (e.g. `*b"\xf0\x28\x8c\xbc"`) collapses to the same `"XXXX"` output regardless of the actual bytes, as demonstrated by the crate's own test: [2](#0-1) 

This is the same bug class as the Netty advisory: a component that is expected to preserve/validate identity-bearing input instead "sanitizes" it into a normalized form, so two systems that should reject or distinguish the malformed input instead silently agree on a wrong, shared representation. Here, the "proxy"-like layer is any component that takes the raw on-chain `StateMachine` enum (arbitrary bytes, since it decodes directly from SCALE-encoded/ABI-encoded untrusted input, e.g. `bandwidth_manager.chain` field parsed via `StateMachine::from_str` in `modules/pallets/bandwidth/src/abi.rs`) and later re-serializes it to a string for routing, logging, or cross-boundary comparison (e.g. indexers, tesseract relayer registries, or any pipeline round-tripping via `Display`/`FromStr`).

### Impact Explanation
If any downstream consumer (indexer, off-chain relayer, or a pallet/contract that keys state by the string form of a `StateMachine`) treats the `Display` output as an authoritative identity, two genuinely different malformed `StateMachine::Substrate`/`Tendermint`/`Relay` identifiers—each carrying different raw bytes on-chain—would render to the identical string `"SUBSTRATE-XXXX"` / `"TNDRMINT-XXXX"` / `"RELAY-XXXX-<id>"`. This could cause chain-identity confusion in any string-based routing, allowlist, or reward-accounting logic built on top of `to_string()`/`FromStr` round-tripping, similar to how Netty's header sanitization let two systems disagree about identical wire data.

However, based on the code reachable in this repository, the core dispatch/handling paths (`modules/ismp/core/src/handlers/request.rs`, `modules/pallets/ismp/src/dispatcher.rs`, `EvmHost.sol`, `HandlerV2.sol`) all operate on the typed `StateMachine` enum directly (its `Encode`/`Decode`/`PartialEq`/`Hash` derive, not the `Display` string), so byte-for-byte forged/malformed identifiers are distinguished correctly at the protocol layer — they are never confused with each other there. I was not able to find a reachable, in-scope production code path within `handle_unsigned`, `EvmHost`/`HandlerV2` dispatch, the bandwidth gate, or pallet-ismp's commitment/membership logic that keys security-critical state by the `Display`-derived string rather than the typed enum. The comment at lines 321-322 and 329-330 explicitly documents the intended behavior: an invalid byte sequence is meant to render the request "invalid and undeliverable," suggesting this was a deliberate design choice for making malformed identifiers unroutable rather than a smuggling vector.

### Likelihood Explanation
Low, given available evidence. The vulnerable code path is real and reachable (any bandwidth purchaser or relayer can submit a `StateMachine` with non-UTF-8 bytes), but the primary security-relevant contracts/pallets (dispatch, handler, commitment storage, bandwidth allowance `StorageDoubleMap<StateMachine, ...>`) key on the typed enum, not on `Display` strings, so the "XXXX" collision does not appear to reach a state where distinct chains' funds, messages, or proofs get commingled through this exact code. I could not verify with the tools available whether any off-chain component (e.g. the tesseract indexer/relayer, `sdk/packages/indexer`) uses `StateMachine::to_string()` output as a security-relevant lookup key rather than purely for display/logging.

### Recommendation
Change `StateMachine::Display` to return an `Err`/fail visibly (or use a per-identifier-unique fallback, e.g. hex-encoding the raw bytes) instead of collapsing all invalid-UTF-8 identifiers to the fixed literal `"XXXX"`, so that no two distinct raw identifiers can ever produce the same string. Additionally, audit any off-chain or cross-pallet code that treats `StateMachine::to_string()` as an identity key (rather than the typed enum) to ensure none of it makes trust decisions based on the sanitized string form.

### Proof of Concept [2](#0-1) 
As shown in the existing test `invalid_state_machine_conversions`, constructing `StateMachine::Substrate(*b"\xf0\x28\x8c\xbc")` and any other non-UTF-8 4-byte value both yield the string `"SUBSTRATE-XXXX"`. Two `StateMachine` values built from different malformed byte sequences are therefore indistinguishable to any consumer that only sees the `Display` output.

impl Display for StateMachine {
	fn fmt(&self, f: &mut core::fmt::Formatter<'_>) -> core::fmt::Result {
		let str = match self {
			StateMachine::Evm(id) => {
				format!("EVM-{id}")
			},
			StateMachine::Polkadot(id) => format!("POLKADOT-{id}"),
			StateMachine::Kusama(id) => format!("KUSAMA-{id}"),
			// Invalid byte sequence will result in a default state machine id rendering the request
			// invalid and undeliverable
			StateMachine::Substrate(id) => {
				format!(
					"SUBSTRATE-{}",
					String::from_utf8(id.to_vec()).unwrap_or("XXXX".to_string())
				)
			},
			// Invalid byte sequence will result in a default state machine id rendering the request
			// invalid and undeliverable
			StateMachine::Tendermint(id) =>
				format!("TNDRMINT-{}", String::from_utf8(id.to_vec()).unwrap_or("XXXX".to_string())),
			// Invalid byte sequence will result in a default state machine id rendering the request
			// invalid and undeliverable
			StateMachine::Relay { relay, para_id } => format!(
				"RELAY-{}-{para_id}",
				String::from_utf8(relay.to_vec()).unwrap_or("XXXX".to_string())
			),
		};
		write!(f, "{}", str)
	}
