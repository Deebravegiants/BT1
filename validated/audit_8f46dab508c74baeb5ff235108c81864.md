### Title
Post-graduation trades executed directly against the HyperSwap V2 pair bypass Zap's 0.75% fee entirely - ([File: packages/contracts/src/Bonding.sol, packages/contracts/src/Zap.sol])

### Summary
After a token graduates, all trading intentionally moves off the internal, `onlyRouter`-gated `Pair.sol` and onto a real, permissionless HyperSwap V2 pool created in `Bonding.finalizeGraduation`. `Zap` interacts with that pool by transferring tokens to it and calling `pair.swap(...)` directly rather than through any wrapper that enforces fees [1](#0-0) . Because the pool itself is a standard, unrestricted UniswapV2-style pair, any unprivileged wallet can perform the exact same "transfer-then-swap" sequence directly against the pair, completely skipping `Zap.buy`/`Zap.sell` and the 0.75% Alt Fun protocol/creator fee they charge.

### Finding Description
`Bonding.finalizeGraduation` creates (or reuses) a HyperSwap V2 pair for TOKEN/LT via `_ensureUniswapV2Pair` and seeds it with real liquidity locked to `LPLock` [2](#0-1) . This pair is a genuine external AMM contract, not the fee-aware/access-controlled `Pair.sol` used pre-graduation — that internal `Pair.swap` is gated by `onlyRouter` so ordinary users can never call it directly [3](#0-2) . The HyperSwap pair has no such restriction: its `swap`, `mint`, and `skim` entry points are fully public, as documented by the interface used to interact with it [4](#0-3) .

Post-graduation, `Zap` itself performs its swaps by transferring input tokens straight to the pair and calling `pair.swap(amount0Out, amount1Out, to, "")` directly, bypassing HyperSwap's non-standard router entirely [1](#0-0) . The project's own threat-model notes confirm this pattern is trivially replicable by any third party: "A vanilla UniswapV2 pair is deployable by anyone... after creation anyone can call `pair.mint(to)` against pre-transferred tokens" and an attacker can `transfer(pair, smallToken)` + `transfer(pair, smallLT)` + call the pair directly, all without going through any privileged interface [5](#0-4) . The identical capability — transferring TOKEN/LT to the pair and calling `swap` directly — lets any trader buy or sell the graduated token paying only the pool's own ~0.3% LP fee while completely skipping `Zap.buy`/`Zap.sell`'s 0.75% Alt Fun fee deduction and the corresponding `FeeVault.accrue` call [6](#0-5) .

By design, "the fee is charged on every buy — curve **and** post-graduation — not just curve trades" [7](#0-6) , and the same is stated for sells: "the 0.75% Alt Fun fee (forwarded to `FeeVault`...) — identical on curve and post-grad" [8](#0-7) . This policy is enforced only at the `Zap` layer, not at the pool layer — there is no analog to the `Pair.sol` `onlyRouter` gate on the HyperSwap pair, so the fee guarantee is purely optional for any trader who chooses to interact with the pool directly instead of through `Zap`.

### Impact Explanation
Every graduated token's fee revenue — split 0.5% protocol / 0.25% creator on every trade — can be unilaterally and permanently avoided by any trader who swaps directly against the HyperSwap pool instead of calling `Zap.buy`/`Zap.sell`. Since post-graduation is the token's permanent, terminal trading venue ("After graduation, all trades continue through `Zap` via HyperSwap" [9](#0-8) ), this is not a transient edge case but the steady-state trading venue for the token's entire remaining lifetime, so the fee evasion is durable and repeatable, directly diverting creator and protocol fee income that the fee schedule guarantees on "every buy/sell (curve **and** post-grad)" [10](#0-9) .

### Likelihood Explanation
No special privilege, timing, or capital advantage is required — any wallet holding TOKEN, LT, or USDC (to mint LT) can transfer tokens to the known, on-chain-discoverable HyperSwap pair address and call its public `swap` function directly, exactly mirroring the "transfer + swap directly on the pair" pattern the protocol's own code and documentation already use and describe as trivially replicable by an attacker [5](#0-4) . Rational MEV bots and arbitrageurs, and any sophisticated trader wanting to save 0.75%, have direct financial incentive to always trade this way once a token graduates.

### Recommendation
Since the pool must remain a genuine, aggregator-compatible HyperSwap V2 pair (a custom pair was explicitly rejected as "architecturally unacceptable" [11](#0-10) ), fee enforcement cannot be moved into the pool itself. Consider either accepting this as a known limitation of externalizing post-graduation trading to a real DEX (documenting it explicitly, as the original report's "pause transfers" recommendation is not viable here without breaking DEX composability), or exploring a token-level transfer hook/tax that charges the fee on `Token` transfers themselves once graduated, if that is compatible with DEX listing requirements.

### Proof of Concept
1. Wait for a token to graduate via `Bonding.finalizeGraduation`, which creates/seeds the HyperSwap TOKEN/LT pair via `_ensureUniswapV2Pair` / `_seedUniswapV2Direct` [2](#0-1) .
2. Read `bonding.graduatedPair(tokenAddress)` to obtain the HyperSwap pair address (public state, no restriction).
3. Instead of calling `Zap.buy`/`Zap.sell`, transfer LT (or TOKEN) directly to the pair, compute the expected output via the pair's own public `getAmountOut`, and call `pair.swap(amount0Out, amount1Out, myAddress, "")` directly — identical to how `Zap._swapOnUniswapV2` operates internally, per `IUniswapV2Pair` [12](#0-11) .
4. The trade settles at the pool's own K-invariant/fee (~0.3%) with zero USDC ever touching `Zap`, so `FeeVault.accrue` is never called and the 0.75% protocol/creator fee is never collected.

    function finalizeGraduation(
        address tokenAddress
    ) external nonReentrant {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[tokenAddress];
        if (info.lifecycle != Lifecycle.Graduating) revert NotGraduating();

        address lt = info.ltAddress;
        PendingGraduation memory p = $.pendingGraduation[tokenAddress];

        // Anything in this contract beyond `p.ltFromPair` belongs to a
        // concurrent graduation on the same LT (Phase 1 transferred it
        // via `Router.graduate`) or to stray dust. Either way it is
        // off-limits to this graduation's deposit and sweep — see
        // `_routerDepositAndDispose` and `_sweepLTToOwner`.
        // Saturating subtract: a balance below `p.ltFromPair` shouldn't
        // be reachable in normal operation, but we keep finalize from
        // bricking on a Panic if any future code path or non-canonical
        // LT briefly violates the invariant.
        uint256 ltBalance = IERC20(lt).balanceOf(address(this));
        uint256 protectedLT = ltBalance > p.ltFromPair ? ltBalance - p.ltFromPair : 0;

        address lpPair = _ensureUniswapV2Pair(tokenAddress, lt);
        uint256 liquidity = _seedUniswapV2Direct(tokenAddress, lt, lpPair, p.tokensForLP, p.ltFromPair, protectedLT);

        _sweepLTToOwner(lt, protectedLT);

        info.lifecycle = Lifecycle.Graduated;
        $.graduatedPair[tokenAddress] = lpPair;
        delete $.pendingGraduation[tokenAddress];

        LPLock($.lpLock).recordLock(tokenAddress, lpPair, liquidity);

        emit TokenGraduated(tokenAddress, lpPair, liquidity, p.tokensForLP, p.lpBurned, p.unsoldBurned);

    function mint(
        uint256 tokenReserve,
        uint256 assetReserve
    ) external onlyRouter returns (bool) {
        if (_pool.k != 0) revert AlreadyMinted();
        _pool = Pool({tokenReserve: tokenReserve, assetReserve: assetReserve, k: tokenReserve * assetReserve});
        emit Mint(tokenReserve, assetReserve);
        return true;
    }

    function swap(
        uint256 tokenIn,
        uint256 tokenOut,
        uint256 assetIn,
        uint256 assetOut
    ) external onlyRouter returns (bool) {
        uint256 newTokenReserve = (_pool.tokenReserve + tokenIn) - tokenOut;
        uint256 newAssetReserve = (_pool.assetReserve + assetIn) - assetOut;
        if ((newTokenReserve + 1) * (newAssetReserve + 1) < _pool.k) revert KInvariantViolated();

        _pool.tokenReserve = newTokenReserve;
        _pool.assetReserve = newAssetReserve;
        emit Swap(tokenIn, tokenOut, assetIn, assetOut);
        return true;
    }

interface IUniswapV2Pair {
    function token0() external view returns (address);
    function token1() external view returns (address);
    function getReserves() external view returns (uint112 reserve0, uint112 reserve1, uint32 blockTimestampLast);

    /// @notice Fee-aware output quote for swapping `amountIn` of `tokenIn`.
    ///         Reads the pair's live per-token fee, so callers never have to
    ///         assume a fee rate that could diverge from the pair's K-check.
    function getAmountOut(
        uint256 amountIn,
        address tokenIn
    ) external view returns (uint256 amountOut);

    function swap(
        uint256 amount0Out,
        uint256 amount1Out,
        address to,
        bytes calldata data
    ) external;

    /// @notice Mint LP tokens to `to`. Caller must have transferred input
    ///         tokens to this pair first (UniswapV2 `transfer → mint` pattern).
    function mint(
        address to
    ) external returns (uint256 liquidity);

    /// @notice Force the pair to send any token balance in excess of stored

    ///         attacker-LP-share invariants; production reads `mint`'s return.
    function totalSupply() external view returns (uint256);
