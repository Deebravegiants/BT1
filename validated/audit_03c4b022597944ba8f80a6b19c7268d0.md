### Title
`VWAPOracle.init` sets the ISMP host address with no validation and irreversibly burns the admin key, permanently bricking the oracle's governance route - (File: `evm/src/utils/VWAPOracle.sol`)

### Summary
`VWAPOracle.init` mirrors the reported `MeritDutchAuction.setNFT` bug class exactly: a privileged, one-shot setter accepts an arbitrary `address` for a critical dependency (here, the ISMP host) with zero validation that the address is a real, functioning host contract, and then permanently destroys the only key that could ever call it again.

### Finding Description
`init` is guarded only by `msg.sender == _admin`, writes `hostAddr` straight into `_host` with no interface, code-existence, or self-consistency check, and unconditionally zeroes `_admin` at the end so the function can never be invoked a second time by anyone: [1](#0-0) 

`host()` simply returns this unchecked value: [2](#0-1) 

Every governance path into the oracle is gated on that value. `onAccept` is restricted by `onlyHost` (inherited from `HyperApp`, which compares `msg.sender` to `host()`), and internally re-derives the expected source using `IDispatcher(host()).hyperbridge()`: [3](#0-2) 

If `hostAddr` is anything other than the real, live `EvmHost` (a typo'd address, an EOA, a not-yet-deployed proxy, a since-redeployed host, etc.), two things happen simultaneously and irreversibly:
1. `onlyHost` can never again be satisfied by the real ISMP host, so `onAccept`/`UpdateTokenDecimals` governance messages dispatched by Hyperbridge to this module will always revert and never be delivered.
2. `_admin` is already zero, so there is no path — `init` or otherwise — to correct `_host` afterward. The contract has no owner, no upgradeability, and no alternate setter for `_host`.

This is the identical bug class to the external report: a privileged, callable-once configuration function for a critical external dependency with no interface/sanity check, whose failure mode is a permanently unusable contract rather than a recoverable misconfiguration.

### Impact Explanation
Once `init` is called with an incorrect host, `VWAPOracle` permanently loses its only channel for cross-chain governance (`UpdateTokenDecimals` via `onAccept`), which is the mechanism used to configure `_tokenDecimals` for new source chains/tokens. Since `recordSpread` (called by the trusted `_intentGateway` on every intent fill) silently `continue`s when `inputDecimals == 0`, any source-chain token that hasn't already had its decimals configured before the misconfiguration can never have its decimals set, permanently disabling correct spread accounting for those (chain, token) pairs used by intent solvers/fillers to price fills. There is no admin override, no re-init, and no upgrade path in this contract to recover — this is a permanent freeze of the module's governance-driven functionality, matching the "route unable to deliver messages" / permanent-freeze bar.

### Likelihood Explanation
This requires the legitimate admin to call `init` once with a wrong `hostAddr` — the same trigger condition as the original `setNFT` report (an honest deployment/config mistake, not malicious intent). Because `init` is a normal part of the deployment bring-up sequence (bind the oracle to the local `EvmHost`) and has no safety check, a single incorrect deployment/config transaction is sufficient and irrecoverable; this is a realistic, low-friction deployment-time error rather than a contrived attack.

### Recommendation
Add the same class of check the codebase already uses elsewhere (e.g. `EvmHost.updateHostParamsInternal`'s `IERC165(...).supportsInterface(...)` checks) before accepting `hostAddr`:
- Require `hostAddr.code.length > 0`.
- Require `hostAddr` exposes the expected `IDispatcher`/`IHost` interface (e.g. via `supportsInterface` or a sanity call such as `IDispatcher(hostAddr).hyperbridge()` succeeding and returning a plausible value) before committing it to storage.
- Consider not burning `_admin` unconditionally in the same transaction as an unvalidated write, or provide a governance-gated recovery path (e.g., an `onlyHost`-gated `updateHost` reachable once `_host` is correctly bound) so a bad `init` is not unconditionally terminal.

### Proof of Concept
1. Deployer deploys `VWAPOracle(admin, intentGateway)`.
2. Deployer (as `admin`) calls `init(hostAddrWrong, updates)` where `hostAddrWrong` is a mistyped/incorrect address (e.g., an EOA or an old/pre-deployment placeholder for the host).
3. `_host = hostAddrWrong` is stored; `_admin` is set to `address(0)`.
4. Hyperbridge later dispatches a legitimate `UpdateTokenDecimals` governance `PostRequest` to this oracle; the real `EvmHost` calls `onAccept`, but `onlyHost` compares `msg.sender` (`EvmHost`) against `host()` (`hostAddrWrong`) and reverts — the message can never be delivered.
5. No account can call `init` again (`_admin == address(0)`), and no other function can update `_host`, so the oracle's governance channel is permanently dead, and decimals for any not-yet-registered `(sourceChain, token)` pair can never be set, permanently degrading `recordSpread` for those pairs.

    function init(address hostAddr, TokenDecimalsUpdate[] memory updates) external {
        if (msg.sender != _admin) revert Unauthorized();

        _host = hostAddr;

        // Process all token decimal updates
        _processTokenDecimalsUpdates(updates);

        // Reset admin after initialization
        _admin = address(0);
    }

    /**
     * @notice Handles incoming cross-chain governance requests
     * @param incoming The incoming post request
     */
    function onAccept(IncomingPostRequest calldata incoming) external override onlyHost {
        // Only hyperbridge is permitted to perform these actions
        if (keccak256(incoming.request.source) != keccak256(IDispatcher(host()).hyperbridge())) revert Unauthorized();

        RequestKind kind = RequestKind(uint8(incoming.request.body[0]));

        if (kind == RequestKind.UpdateTokenDecimals) {
            TokenDecimalsUpdate[] memory updates = abi.decode(incoming.request.body[1:], (TokenDecimalsUpdate[]));
            _processTokenDecimalsUpdates(updates);
        }
    }
