### Title
Missing-instance fallback in Tron `IntentGatewayV2.authenticate` lets an unregistered source chain forge escrow withdrawals - (File: `evm/tron/contracts/apps/IntentGatewayV2.sol`)

### Summary
The Tron variant of `IntentGatewayV2` resolves the "trusted sender" for an incoming cross-chain message with a fallback that treats *any unregistered source chain* as if it were pre-authorized. This mirrors the Capsule bug class: an authorization check keyed off the *presence* of a security-relevant association (there: `ownerReference`, here: a registered `Deployment`/instance mapping) silently defaults to "trusted" when that association is absent, instead of failing closed.

### Finding Description
In the mainline EVM implementation, `_instance()` fails closed when no deployment is registered for a state machine: [1](#0-0) 

```
function _instance(bytes calldata stateMachineId) internal view returns (address) {
    address gateway = _instances[keccak256(stateMachineId)];
    if (gateway == address(0)) revert UnknownInstance();
    return gateway;
}
```

The Tron implementation instead falls back to `address(this)`: [2](#0-1) 

```
function instance(bytes calldata stateMachineId) public view returns (address) {
    address gateway = _instances[keccak256(stateMachineId)];
    return gateway == address(0) ? address(this) : gateway;
}

function authenticate(PostRequest calldata request) internal view {
    if (request.from.length != 20) revert InvalidInput();
    address module = address(bytes20(request.from));
    // IntentGateway only accepts incoming assets from itself or known instances
    if (instance(request.source) != module) revert Unauthorized();
}
```

For any `request.source` that has **not** been explicitly registered as a peer deployment (i.e., governance has not yet dispatched `NewDeployment` for that state machine — exactly analogous to a Kubernetes namespace lacking an `ownerReference`), `instance()` silently returns `address(this)` rather than reverting. `authenticate()` then accepts the delivery as long as the encoded `request.from` equals the local gateway's own address.

`EvmHost.sol` and `HostManager` deliberately use CREATE2 so contracts land at identical addresses across every chain (documented as load-bearing behavior): [3](#0-2) 

Because the local gateway address is publicly known and identical everywhere, an attacker only needs to deploy any contract (or the same `IntentGatewayV2` bytecode) at that exact address on a chain Hyperbridge already has a working consensus/state-proof client for, but for which governance has not yet issued a `NewDeployment` peering. From there the attacker dispatches a real, consensus-proof-backed `PostRequest` with `from = <gateway address>` and a `RedeemEscrow`/`RefundEscrow` body targeting the real gateway on the victim chain. `authenticate()` passes because `instance(request.source) == address(this) == module`, and the withdrawal executes against real escrowed funds.

### Impact Explanation
This is a forged-message / broken-authentication vulnerability with concrete theft of escrowed intent funds: an attacker who controls (or can bootstrap) a state machine recognized by Hyperbridge's consensus clients, but not yet peered with the target `IntentGatewayV2` instance, can redeem or refund arbitrary escrowed orders on the victim gateway by forging the `from` field to equal the gateway's own CREATE2 address. This satisfies the "concrete theft ... of funds" and "forged message delivery" bar for High/Critical severity, matching the CWE-863 (incorrect authorization relying on incidental/absent state) root cause of the reported Capsule advisory.

### Likelihood Explanation
Reachable from a single relayed/proven message originating from any chain state machine Hyperbridge already trusts consensus-wise but has not yet registered a `Deployment` for on this specific gateway — a state that necessarily exists for every newly-onboarded chain before governance issues `NewDeployment`. Given the deterministic CREATE2 deployment scheme is explicitly relied upon elsewhere in the codebase, reproducing the gateway's address on an unpeered chain is a realistic, low-cost step for an attacker (new EVM chain, permissive/attacker-influenced state machine, or a chain awaiting onboarding).

### Recommendation
Change `instance()`/`authenticate()` in `evm/tron/contracts/apps/IntentGatewayV2.sol` to fail closed exactly like the mainline `_instance()` in `IntentsBase.sol` — revert with `UnknownInstance()` when `_instances[keccak256(stateMachineId)] == address(0)`, rather than defaulting to `address(this)`. Audit any other callers of `instance()` in this file that may depend on the same-chain self-fallback and replace that reliance with an explicit same-chain check (e.g., comparing `request.source` to the local host state machine id) instead of an implicit zero-address fallback.

### Proof of Concept
1. Governance has deployed `IntentGatewayV2` (Tron variant) at address `G` via CREATE2, and Hyperbridge already runs a consensus/state-proof client for state machine `X` (e.g., a newly supported EVM chain), but has not yet dispatched `NewDeployment` for `X` on this gateway — `_instances[keccak256(X)] == address(0)`.
2. Attacker deploys arbitrary bytecode at address `G` on chain `X` (achievable because CREATE2 addresses are chain-independent given the same deployer/salt/init code, a property the codebase itself relies on for legitimate deployments) — see `evm/src/core/EvmHost.sol` constructor comment on CREATE2 parity.
3. From that contract on `X`, attacker calls the real ISMP host's `dispatch(DispatchPost{...})` with `to = abi.encodePacked(G)` and `body = abi.encodePacked(RequestKind.RedeemEscrow, abi.encode(WithdrawalRequest{commitment: <victim's real order commitment>, tokens: <escrowed tokens>, beneficiary: <attacker>}))`. Since the call originates from address `G` on chain `X`, `PostRequest.from = abi.encodePacked(G)`.
4. This message is relayed and delivered through the legitimate `HandlerV2`/`EvmHost.dispatchIncoming` path with valid consensus/state proofs (it is a real message from a real chain the light client trusts), reaching `IntentGatewayV2.onAccept` → `authenticate(request)`.
5. `instance(X)` returns `address(this) == G` (fallback, since `X` is unregistered) and `module == G` (decoded from `request.from`), so `authenticate` passes and the escrowed tokens for the targeted commitment are released to the attacker's chosen beneficiary.
