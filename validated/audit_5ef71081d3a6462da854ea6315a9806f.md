### Title
Global (unscoped) JWT replay cache lets any authorized workflow signer DoS unrelated workflows' HTTP triggers - (File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go)

### Summary
`WorkflowMetadataHandler.Authorize` protects against JWT replay using a `jwtReplayCache` keyed **only** by the JWT's `jti` claim, globally across all workflows, instead of being scoped per-workflow (or per-signer). Because `jti` is fully attacker/client-controlled (a free-form string chosen by whoever signs the request), any actor who is a legitimate authorized signer for *some* workflow can poison the shared replay-cache namespace with a `jti` value that collides with one another workflow's signer later uses, causing that other, unrelated workflow's legitimate, correctly-signed HTTP-trigger request to be wrongly rejected as a "replay."

### Finding Description
The reported Footium bug is a class of accounting/state-tracking mistake: a mapping tracks "already used/claimed" state keyed by an identity that is *missing a scoping dimension* (the specific Merkle root/epoch), so state from one context (`erc20MerkleRoot` #1) improperly blocks legitimate action in another context (`erc20MerkleRoot` #2) for the same underlying key. The result is that fully valid proofs/claims are wrongly treated as already consumed.

The same root-cause pattern (a shared consumption-tracking map lacking the scoping dimension that should separate independent contexts) exists in `jwtReplayCache`: [1](#0-0) 

```go
// jwtReplayCache manages used JWT IDs to prevent replay attacks
type jwtReplayCache struct {
	mu            sync.RWMutex
	cleanupPeriod time.Duration
	cache         map[string]time.Time // jti -> timestamp
}
```

The cache is keyed only by `jti`, with no `workflowID` or signer scoping: [2](#0-1) 

`Authorize` checks and records the replay state before returning success, and the order of checks is: verify JWT signature → check global replay cache → check workflowID's authorized-key set → record usage (still keyed only by `jti`): [3](#0-2) 

Crucially, the `jti` value is entirely chosen by the client creating the JWT (a UUID by convention, but nothing enforces this), as shown in `CreateRequestJWT`: [4](#0-3) 

`VerifyRequestJWT` only checks that the `Digest` claim matches the request digest, expiry/issued-at bounds, and the ECDSA signature recovers to an address — it never ties `jti` to a specific workflow or signer: [5](#0-4) 

Because any signer authorized for *any* workflow can freely pick the `jti` string in their own (correctly-signed) request, and `recordUsage` writes that exact string into the single global `cache` map, a signer who is authorized on Workflow A can pre-emptively claim a `jti` value that a legitimate, unrelated Workflow B signer is expected to use next (e.g., predictable/sequential jti generation by a client library, or simple collision if `jti` is not a full UUID as CreateRequestJWT assumes but is not enforced by VerifyRequestJWT). Workflow B's subsequent legitimate, correctly-signed request with that `jti` is then rejected purely due to a benign or malicious record left by a completely different, unrelated workflow owner: [6](#0-5) 

This mirrors the Footium bug precisely: a single shared map is used to gate legitimate actions for a wide range of independent domains (all workflows on the gateway), but lacks the dimension (workflow/signer scope) needed to keep those domains independent, so a state update in one domain incorrectly blocks a legitimate action in another domain.

### Impact Explanation
This is a Denial-of-Service against unrelated, uninvolved workflow owners' legitimate HTTP-trigger requests. Any account already authorized for at least one workflow (an "unprivileged" workflow owner from the perspective of the wider gateway/DON) can cause legitimate JWTs from unrelated workflows to be rejected, without needing to break cryptography, without any operator privilege, and while only interacting with the public HTTP-trigger endpoint. This directly maps to the accepted class in the rules ("cross-user response confusion"/blocking of legitimate requests via shared unscoped state, analogous to fund-claim DoS in the original report) reachable purely from unprivileged client requests to the internet-facing gateway (`core/services/gateway/handlers/capabilities/v2`).

### Likelihood Explanation
Exploitation requires the attacker to predict or collide with a victim's `jti` value ahead of time. In the common case where all clients use random UUIDv4s (as `CreateRequestJWT` does), collision is astronomically unlikely and this is a low-probability, latent design flaw rather than an immediately practical attack. However, nothing in `VerifyRequestJWT` enforces `jti` format/entropy, so if any client implementation (custom SDKs, scripts, or a compromised/malicious signer deliberately choosing weak jti values) uses predictable or attacker-influenced `jti` values, likelihood rises significantly, and a malicious authorized signer can deliberately author a request with a chosen `jti` to grief another workflow. The core defect — using a single unscoped map as the sole safety boundary between independent workflows — is present regardless of the current UUID convention, matching the Medium-severity, "correct-input-fails" pattern of the source report.

### Recommendation
Scope the replay cache per workflow (and/or per authorized signer), e.g. `map[workflowID]map[string]time.Time` or `map[struct{workflowID, jti string}]time.Time`, so that a `jti` used for one workflow cannot affect JWT validation for any other workflow. This mirrors the report's recommended fix of adding the missing dimension (`erc20MerkleRoot`/`ethMerkleRoot`) to the accounting map.

### Proof of Concept
1. Signer S1, authorized on Workflow A, crafts and sends a valid, correctly-signed JWT-authenticated HTTP-trigger request with `jti = "X"`. `Authorize` succeeds and `recordUsage("X")` stores `cache["X"] = now` (`workflow_metadata_handler.go:105`, `:407-412`).
2. Later, Signer S2, authorized on unrelated Workflow B, independently and legitimately generates (or is influenced/coerced/predicted into using) `jti = "X"` for their own correctly-signed request to Workflow B's trigger.
3. `Authorize` calls `h.jwtCache.isReplay("X")` (`:87`), which returns `true` because `"X"` is already present in the cache from Workflow A's unrelated usage.
4. S2's fully valid, correctly signed, properly authorized request for Workflow B is rejected with `"JWT token has already been used"` even though S2 never reused any token — the collision originated from a completely different workflow (`:88-90`).

```go
func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}
```

```go
func (cache *jwtReplayCache) isReplay(jti string) bool {
	cache.mu.RLock()
	defer cache.mu.RUnlock()

	_, exists := cache.cache[jti]
	return exists
}

func (cache *jwtReplayCache) recordUsage(jti string) {
	cache.mu.Lock()
	defer cache.mu.Unlock()

	cache.cache[jti] = time.Now()
}
```

```go
// VerifyRequestJWT verifies a signed JWT for a JSON-RPC request
// It recovers and returns the public key used to sign the JWT, checks the issuer, validates the digest,
// and performs all validations done by jwt.ParseWithClaims() including expiration checks.
func VerifyRequestJWT[T any](tokenString string, req jsonrpc.Request[T], opts ...VerifyOption) (*JWTClaims, gethcommon.Address, error) {
	options := &verifyOptions{}
	for _, opt := range opts {
		opt(options)
	}

	maxExpiryDuration := maxJWTExpiryDuration
	if options.maxExpiryDuration != nil {
		maxExpiryDuration = *options.maxExpiryDuration
	}

	issuedAtTolerance := defaultIssuedAtTolerance
	if options.issuedAtTolerance != nil {
		issuedAtTolerance = *options.issuedAtTolerance
	}
	signedString, signature, err := splitToken(tokenString)
	if err != nil {
		return nil, gethcommon.Address{}, err
	}
	decodedSignature, err := base64.RawURLEncoding.DecodeString(signature)
	if err != nil {
		return nil, gethcommon.Address{}, fmt.Errorf("signature segment is not valid base64url: %w", err)
	}
	pubKey, err := GetSignersEthAddress([]byte(signedString), decodedSignature)
	if err != nil {
		return nil, gethcommon.Address{}, err
	}
	verifiedToken, err := jwt.ParseWithClaims(tokenString, &JWTClaims{}, func(token *jwt.Token) (any, error) {
		if token.Method.Alg() != EthereumSigningMethod.Alg() {
			return nil, fmt.Errorf("unsupported JWT 'alg': '%s'. Expected '%s'", token.Method.Alg(), EthereumSigningMethod.Alg())
		}
		if _, ok := token.Method.(*SigningMethodEth); !ok {
			return nil, jwt.ErrSignatureInvalid
		}
		return pubKey, nil
	})
	if err != nil {
		return nil, gethcommon.Address{}, err
	}
	verifiedClaims, ok := verifiedToken.Claims.(*JWTClaims)
	if !ok {
		return nil, gethcommon.Address{}, errors.New("claims payload is not in the expected format")
	}
	if !verifiedToken.Valid {
		return nil, gethcommon.Address{}, errors.New("signature or claims validation failed")
	}
	reqDigest, err := req.Digest()
	if err != nil {
		return nil, gethcommon.Address{}, err
	}
	if verifiedClaims.ID == "" {
		return nil, gethcommon.Address{}, errors.New("JWT ID (jti) is required but missing")
	}
	if verifiedClaims.ExpiresAt == nil {
		return nil, gethcommon.Address{}, errors.New("expiredAt (exp) is required but missing")
	}
	if verifiedClaims.IssuedAt == nil {
		return nil, gethcommon.Address{}, errors.New("issuedAt (iat) is required but missing")
	}
	now := time.Now()
	issuedAt := verifiedClaims.IssuedAt
	if issuedAt.After(now.Add(issuedAtTolerance)) {
		return nil, gethcommon.Address{}, fmt.Errorf("issuedAt (iat) is too far in the future (beyond tolerance of %.0f seconds)", issuedAtTolerance.Seconds())
	}
	duration := verifiedClaims.ExpiresAt.Sub(verifiedClaims.IssuedAt.Time)
	if duration > maxExpiryDuration {
		return nil, gethcommon.Address{}, fmt.Errorf("token lifetime %.0f sec exceeds the maximum allowed %.0f sec. Reduce the gap between 'iat' and 'exp'", duration.Seconds(), maxExpiryDuration.Seconds())
	}
	if verifiedClaims.Digest != "0x"+reqDigest {
		return nil, gethcommon.Address{}, fmt.Errorf("claim digest '%s' does not match calculated request digest '0x%s'", verifiedClaims.Digest, reqDigest)
	}

	return verifiedClaims, pubKey, nil
```
