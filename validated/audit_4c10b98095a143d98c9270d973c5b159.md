## Title
Unprivileged livestream client can crash the `livestream` thread agent via `Downstream::new(addr.ip())?`, propagating a `BrokerError::AgentTerminated` that aborts the whole `MasterPlan::run` signup loop - ([File: src/agents/livestream/mod.rs])

## Summary
`Agent::run` in the livestream thread agent calls `Downstream::new(addr.ip())?` on every new TCP connection, and any error (e.g., a gstreamer pipeline/element construction failure) propagates out of `run` via `?`, terminating the dedicated OS thread. Because `livestream::Agent` is a `Thread`-based agent, there is no restart/retry mechanism analogous to `Process::exit_strategy`; the broker only detects the dead port and turns it into `BrokerError::AgentTerminated`, which is propagated with `?` through every plan (`orb.run(&mut self).await?`) all the way up to `MasterPlan::run`, aborting the in-progress signup and the whole broker loop.

## Finding Description
`Downstream::new` builds a gstreamer pipeline (`ElementFactory::make(...).build()?`, `pipeline.set_state(...)?`, etc.) and returns `Result<Self>` [1](#0-0) . In `Agent::run`, on `Event::Connected(addr)` this call is unwrapped with `?`: `downstream = Some(Arc::new(Downstream::new(addr.ip())?));` [2](#0-1) . Any error here (for instance element construction failing under connection churn/resource contention, e.g. repeatedly tearing down/recreating `nvvidconv`/`nvv4l2h264enc`/`udpsink` elements on a Jetson) makes `run` return `Err`.

`livestream::Agent` implements `agentwire::agent::Thread`, not `Process` [3](#0-2) . The `Thread::spawn_thread` wrapper simply logs the error and lets the OS thread exit — there is no `ExitStrategy::Restart`/`Retry` equivalent for thread agents, unlike process agents [4](#0-3) . When the thread exits, the port's sender is dropped, so the next broker poll of the livestream port yields `None`, which the generated broker `run` future turns into `BrokerError::AgentTerminated("livestream")` [5](#0-4) [6](#0-5) .

This error is not specially handled anywhere in the plan chain: `Orb::run(...)` calls (e.g. `orb.run(&mut self).await?` in biometric capture plans) propagate the `BrokerError` upward via `?` through nested plans (`biometric_capture::Plan::run`, `pupil_contraction::Plan::run`, etc.) up to `MasterPlan::run`'s `self.do_signup(orb, qr_codes, dbus.as_ref())).await?` [7](#0-6) [8](#0-7) . In `src/bin/orb-core.rs`, that top-level error terminates `master_plan.run(&mut orb)`, which is the entire orb-core `run` future selected against ctrl-c/observer [9](#0-8) . There is no retry/restart logic for the livestream agent at the broker or plan level to recover mid-signup.

An unprivileged client with network access to TCP port 9200/relevant livestream listener can trigger `Event::Connected` repeatedly by connecting rapidly (and disconnecting to trigger `Event::Closed`), stressing gstreamer pipeline setup/teardown. If any single `Downstream::new` call fails (which is plausible under resource exhaustion from rapid churn, since GPU/NVENC hardware encoder resources are limited and pipeline element creation is unguarded against transient failures), the livestream thread dies and the whole orb-core process's top-level `run()` errors out.

## Impact Explanation
This is a fail-open/crash-then-halt condition, not an authorization or biometric bypass: an unprivileged network client reachable on the livestream port can crash the `livestream` agent thread, which propagates as an unhandled `BrokerError` up through the plan stack and terminates the entire orb-core `run()` future — aborting any in-progress signup and halting the state machine (a denial-of-service / signup-state wedge, matching "hang/wedge of Orb signup state machine due to a dependent agent's crash" in the question's scoped impact). This requires the `livestream` feature to be compiled in and enabled (`cli.livestream` / `orb.enable_livestream()`), and requires network reachability to the livestream port, which is a Preconditions constraint accepted by the question.

## Likelihood Explanation
- Preconditions: attacker must be able to reach the livestream TCP port and the `livestream` feature must be enabled at runtime (it is `#[cfg(feature = "livestream")]`-gated and only enabled via CLI flags in `orb-core.rs`/`health-check.rs`).
- Feasibility: causing `Downstream::new` to fail deterministically via network-only actions (connect/disconnect loop) is not proven in the available code/index — the exact failure conditions of `ElementFactory::make(...).build()` / `pipeline.set_state(gstreamer::State::Playing)` under connection churn depend on gstreamer/hardware behavior not visible in this repo, so I cannot confirm this is reliably triggerable purely by rapid TCP connect/disconnect without additional resource exhaustion (e.g., actual GPU/encoder starvation).
- Repeatability: if triggerable at all, it is repeatable, since nothing in `Agent::run` guards against repeated `Downstream::new` calls or backs off on failure.

## Recommendation
- In `Agent::run`, do not propagate `Downstream::new` errors with `?`; instead log the error and continue without a downstream (treat it like the existing `Event::Right(Some(Err(err)))` upstream error path) so a single connection's pipeline failure doesn't kill the whole thread agent.
- Add restart/backoff logic for the `livestream` thread agent equivalent to `Process::exit_strategy`, or convert it to a `Process`-based agent so `ExitStrategy::Restart`/`Retry` semantics apply.
- Ensure `BrokerError::AgentTerminated` for non-critical agents (like livestream) does not propagate as a fatal error out of signup-critical plan loops; the broker/plan layer should be able to disable/restart the livestream agent independently of the biometric capture / signup state machine.

## Proof of Concept
Integration test plan (not verifiable purely from static analysis, since it depends on forcing a real gstreamer failure):
1. Instantiate a test harness that runs `livestream::Agent::run` inside `agentwire::agent::Thread::spawn_thread`, using a mock/broken `Downstream::new` (e.g., inject a `GST_PLUGIN_PATH` misconfiguration or use a fake `Downstream` type returning `Err` on the Nth call) to simulate a gstreamer pipeline construction failure.
2. Drive `Event::Connected`/`Event::Closed` transitions on the mocked `Upstream` stream to simulate rapid TCP connect/disconnect.
3. Assert that once `Downstream::new` returns `Err`, `Agent::run` returns `Err(...)`, and observe via the `Orb` broker that `orb.run(&mut plan).await` returns `BrokerError::AgentTerminated("livestream")`.
4. In a higher-level test using `MasterPlan::run`, assert that this error currently propagates and terminates the biometric-capture/signup loop (expected failing assertion today), then verify the fix by confirming the broker either restarts/disables the livestream agent internally and `MasterPlan::run` continues signup unaffected.
