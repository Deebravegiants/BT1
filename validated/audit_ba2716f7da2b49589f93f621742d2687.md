### Title
Unrestricted `CallDispatcher.dispatch()` allows any address to drain residual tokens/ETH left in the shared dispatcher - ([File: evm/src/utils/CallDispatcher.sol])

### Summary
`CallDispatcher.dispatch()` mirrors the CowSwap `SwapGuard.envelope()` bug class: it is a public entry point that executes an attacker-supplied array of `{to, value, data}` calls against arbitrary targets with zero access control (no `onlyGateway`/`onlyHost`/`onlySelf` guard). In the CowSwap incident, `SwapGuard.envelope()` let anyone route arbitrary calldata through a contract that held standing token allowances, draining the vault. In Hyperbridge, `CallDispatcher` is a single shared contract reused by `IntentGatewayV2`/`IntentsBase`, `HyperFungibleToken(Upgradeable)`, and `WrappedHyperFungibleToken(Upgradeable)` to execute predispatch/postdispatch order calldata and cross-chain calldata-execution payloads, and it is designed to *hold* ERC20/native balances transiently while it executes swaps and sweeps.

### Finding Description
`CallDispatcher.dispatch(bytes memory encoded)` decodes an ABI-encoded `Call[]` and, for each entry, performs `to.call{value: call.value}(call.data)` after only checking that `to` has code — there is no caller restriction at all: [1](#0-0) 

This same dispatcher instance is wired into every consuming app as `_params.dispatcher` / `_dispatcher`: [2](#0-1) [3](#0-2) [4](#0-3) 

The protocol's own design intentionally lets the dispatcher hold balances mid-flow: assets are pushed to the dispatcher, arbitrary user/solver-supplied calldata is executed there (order `predispatch`/`postdispatch` calls, or HFT `Message.data`), and only the *expected* output tokens are swept back afterward: [5](#0-4) 

The sweep logic in `_execute()` only recovers balances for tokens explicitly enumerated in `order.output.assets` — any other token or dust the arbitrary swap/DeFi call produces (e.g., reward tokens, LP fee remainders, partial refunds) is left behind in the dispatcher: [6](#0-5) 

Because `dispatch()` has no access control, any residual balance sitting in this shared, singleton `CallDispatcher` — whether from unswept dust, a partially completed multi-step flow, or an accidental direct token transfer to the dispatcher's address — can be swept out by any external account simply by calling `dispatch()` with a `Call` that invokes `transfer`/`transferFrom` (for ERC20) or a zero-data call with `value` set (for native ETH) targeting the attacker's own address. This is functionally identical to the CowSwap root cause: an unauthenticated "envelope"/"dispatch" function that executes arbitrary calldata against arbitrary targets using assets currently held by the dispatching contract.

### Impact Explanation
Any tokens or native ETH left in the `CallDispatcher` — even transiently, or as an accounting error from a solver's DeFi route producing an unexpected token — become permanently and immediately stealable by any address, since `dispatch()` performs no origin check and the dispatcher's balance is the only thing that matters for a `to.call{value}(data)` executed against an ERC20/`address(this)`. Given that the same `CallDispatcher` is shared across the intent gateway and both `HyperFungibleToken` variants, the blast radius spans every app relying on it, not just intents.

### Likelihood Explanation
The predispatch/postdispatch calldata routed through `CallDispatcher` is attacker-influenced (order creators/solvers supply arbitrary swap targets and calldata per the documented "swap-then-escrow" and "fill-then-act" patterns), making it plausible for a solver's route to leave behind unlisted tokens or dust, and for anyone monitoring the dispatcher's balance to immediately front-run/opportunistically drain it — no privileged role or governance access is required, only observing a nonzero balance at the dispatcher's address.

### Recommendation
Restrict `CallDispatcher.dispatch()` to a caller allowlist (e.g., `onlyGateway`/`onlyApp` modifier checking `msg.sender` against the known set of apps that are permitted to use it), or deploy a dedicated, single-use/ephemeral dispatcher per call so no shared standing balance can ever exist between transactions. Additionally, ensure the post-`dispatch()` sweep logic recovers *all* token balances present on the dispatcher (not just the tokens enumerated in `order.output.assets`) before returning control, eliminating any residual balance window.

### Proof of Concept
1. A solver fills an order whose `PaymentInfo.call` routes output tokens through a DEX that also emits an incidental reward/fee token not listed in `order.output.assets`.
2. `_execute()` sweeps only the listed output assets; the reward token remains on the `CallDispatcher`. [7](#0-6) 
3. Any attacker calls `CallDispatcher.dispatch(abi.encode(Call[]))` directly with `Call({to: rewardToken, value: 0, data: abi.encodeWithSelector(IERC20.transfer.selector, attacker, balance)})`. [1](#0-0) 
4. The call succeeds because `dispatch()` never checks `msg.sender`, transferring the residual tokens to the attacker.

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }

    /**
     * @dev Executes arbitrary calldata attached to an order's output via the CallDispatcher.
     * After dispatching the calls, any residual token balances left on the dispatcher
     * are swept back to this contract and accounted for as protocol dust.
     *
     * This enables composable order fulfillment — solvers can route through DEXes,
     * lending protocols, or other DeFi primitives as part of filling an order.
     *
     * @param order The order containing the output calldata to execute.
     * @param outputsLen The number of output assets to sweep after execution.
     */
    function _execute(Order calldata order, uint256 outputsLen) internal {
        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            } else {
                uint256 balance = IERC20(token).balanceOf(dispatcher);
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            }

            unchecked {
                ++i;
            }
        }
