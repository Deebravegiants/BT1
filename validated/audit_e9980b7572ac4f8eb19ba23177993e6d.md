### Title
Missing Arbitrum/L2 sequencer-uptime check in `SimplexPaymaster._getOraclePrice()` allows stale-price exploitation of gas-fee pricing - (File: `evm/src/utils/SimplexPaymaster.sol`)

### Summary
`SimplexPaymaster` is a permissionless ERC-4337 paymaster deployed on Arbitrum (and other L2s) that prices gas fees in stablecoins using two Chainlink `AggregatorV3Interface` feeds (native/USD and token/USD). Its staleness check only compares `block.timestamp - updatedAt` against a configured `maxOracleAge`; it never queries the Chainlink L2 sequencer-uptime feed to detect whether the Arbitrum sequencer is or was recently down, matching the exact bug class in the external report.

### Finding Description
`_getOraclePrice()` fetches `latestRoundData()` from a Chainlink aggregator and only validates that the answer is positive and not older than `maxOracleAge`: [2](#0-1) 

Both `_tokenPrice()` (used during `_fetchDetails` in the ERC-4337 validation path, reachable by any unprivileged UserOperation sender) and `swapAndDeposit()` rely on `_getOraclePrice()`: [3](#0-2) [4](#0-3) 

On Arbitrum, when the sequencer goes down, transactions queue on L1 and Chainlink price feeds on L2 stop updating but `latestRoundData().updatedAt` reflects the last valid on-chain answer, which can remain within `maxOracleAge` for a long window (up to 90,000 seconds / 25h per the deploy defaults): [5](#0-4) 

When the sequencer resumes, a backlog of L1-queued transactions can be replayed in an order an attacker can bias (or the L2 network state can diverge sharply from the true market at the moment prices resume), letting a malicious UserOperation sender submit a UserOp priced against a stale/mispriced `tokenPrice`, paying an artificially low amount of the stablecoin for gas the paymaster fronts in native ETH — or conversely draining users by overcharging — without the contract ever detecting the sequencer had been unavailable. Standard Chainlink guidance for this exact scenario is to also check the `L2 Sequencer Uptime Feed`, which this contract omits entirely.

### Impact Explanation
`SimplexPaymaster` fronts native gas from its own `EntryPoint` deposit and charges the UserOperation's `prefunder_`/sender the computed `tokenPrice` in stablecoins. If `tokenPrice` is mispriced during/after a sequencer outage, an attacker can submit UserOperations that pay less stablecoin than the true cost of the sponsored gas, siphoning the paymaster's `EntryPoint` deposit and accumulated stablecoin balance over repeated operations — a direct theft-of-funds vector against protocol-operated infrastructure, satisfying the Medium+ concrete-theft bar.

### Likelihood Explanation
Arbitrum sequencer downtimes have occurred historically (multi-hour outages), and paymaster gas-payment UserOperations are open to any unprivileged actor who can obtain a permit/Permit2 signature and route a UserOp through a bundler — no special privilege is required to exploit a mispriced window. `maxOracleAge` is configured generously (up to 25h) precisely to accommodate normal Chainlink heartbeats, which also widens the exploitable staleness window during an outage.

### Recommendation
Add a Chainlink `L2 Sequencer Uptime Feed` check (per Chainlink's documented pattern) to `_getOraclePrice()`, reverting when the sequencer is down or within a grace period after it comes back up, mirroring the recommendation in the external report.

### Proof of Concept
1. Deploy/observe `SimplexPaymaster` on Arbitrum mainnet at `0x7281Bccb4f0BCE44F3B8542d1fC5e51c2F5fC08C`.
2. Simulate/await an Arbitrum sequencer outage; Chainlink price feeds stop updating but remain within `maxOracleAge` (25h default).
3. During or immediately after the outage, submit a `PackedUserOperation` with `paymasterData` mode `0x00`/`0x02` referencing the affected token; `_fetchDetails` → `_tokenPrice` → `_getOraclePrice` return the stale/mispriced rate because no sequencer check exists (`evm/src/utils/SimplexPaymaster.sol` lines 660-676).
4. The paymaster fronts real ETH gas from its `EntryPoint` deposit while charging the attacker's stablecoin at the stale rate, resulting in a net loss to the paymaster's treasury/deposit.

    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
