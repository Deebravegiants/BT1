Audit Report

## Title
Bridge `OutgoingToken` Secret Disclosure to Any Authenticated User via Unprivileged `GET /v2/bridge_types` and `GET /v2/bridge_types/:BridgeName` - (File: core/web/presenters/bridges.go)

## Summary
The `BridgeResource` JSONAPI presenter unconditionally includes the bridge's `OutgoingToken` secret (with no `omitempty` or redaction) in every serialized response, and the two read routes for bridge types (`Index`/`Show`) are registered without any role-check wrapper, unlike `Create`/`Update`/`Destroy` which require `auth.RequiresEditRole`. As a result, any authenticated user — including one with the lowest-privilege `UserRoleView` role — can retrieve every bridge's `OutgoingToken` in plaintext.

## Finding Description
`BridgeType.OutgoingToken` is a secret generated at bridge creation for authenticating outbound calls to the configured bridge/External Adapter URL: [1](#0-0) 

The `BridgeResource` presenter serializes `OutgoingToken` unconditionally (`json:"outgoingToken"`, no `omitempty`), unlike `IncomingToken`, which is explicitly commented as only provided on Create and marked `omitempty`: [2](#0-1) 

`NewBridgeResource` populates `OutgoingToken` directly from the DB row with no redaction: [3](#0-2) 

Both `Index` and `Show` handlers build this resource straight from the DB and return it as-is, with no filtering based on caller role: [4](#0-3) 

Critically, in the route table, `POST`/`PATCH`/`DELETE` for bridge types are wrapped in `auth.RequiresEditRole`, but the `GET` routes are registered with no role-check wrapper at all — only the outer `authv2` group's `auth.Authenticate` (session or API token) applies: [5](#0-4) 

Verifying the role model confirms `UserRoleView` is a distinct, lower-privilege role than `edit`/`run`/`admin`, and `RequiresEditRole` explicitly blocks `view` and `run` roles: [6](#0-5) [7](#0-6) 

Because the `GET /v2/bridge_types` and `GET /v2/bridge_types/:BridgeName` routes bypass this role gate entirely, a `view`-role authenticated user (or API token restricted to view) can reach these handlers and receive the `OutgoingToken` in the response — the same secret an `edit`/`admin` user would see, defeating the intended role-based access control that protects mutating bridge endpoints.

## Impact Explanation
`OutgoingToken` is a credential used to authenticate the node's outbound requests to the configured External Adapter/bridge URL. Disclosure to a low-privilege, non-edit/non-admin authenticated user allows that user to directly impersonate the node's authorized calls to the third-party adapter, exceeding their intended access level. This is a concrete secret/credential exfiltration issue reachable via a single unprivileged (relative to the edit/admin role required for bridge mutation) authenticated GET request, which maps to the in-scope "key/secret exfiltration" and "node API authentication or role bypass" impact categories.

## Likelihood Explanation
High likelihood: any user who has been granted only the `view` role (a legitimate, low-privilege, non-admin authentication credential) can trivially call the unguarded `GET` endpoints once authenticated, and any deployment with configured bridges (a near-universal Chainlink node setup) is affected. No additional exploit primitives, timing, or race conditions are required — this is a direct single-request disclosure.

## Recommendation
- Redact `OutgoingToken` from `BridgeResource` on read paths (`Index`/`Show`), mirroring `IncomingToken`'s `omitempty` handling, and only populate it at `Create` time (returned once to the creating caller).
- Additionally, gate `GET /v2/bridge_types` and `GET /v2/bridge_types/:BridgeName` with `auth.RequiresEditRole` (or equivalent) so `view`-role users cannot retrieve secrets at all, consistent with how mutating routes are already protected.

## Proof of Concept
1. As an admin, create a user with `UserRoleView` (e.g., via `POST /v2/users` with role `view`) and a bridge via `POST /v2/bridge_types/` (admin/edit session) — the create response includes `outgoingToken`.
2. Authenticate as the `view`-role user (session cookie or API token tied to that user).
3. Call `GET /v2/bridge_types/<bridgeName>` — the JSON response body includes the plaintext `outgoingToken` field, per `presenters.NewBridgeResource` at `core/web/presenters/bridges.go` lines 29-42, despite the caller only holding the `view` role.
4. Call `GET /v2/bridge_types` — the paginated response discloses `outgoingToken` for every configured bridge to the same `view`-role user.
5. Confirm by contrast that `POST/PATCH/DELETE /v2/bridge_types...` return `401 Unauthorized` for the same `view`-role user (per `auth.RequiresEditRole` in `core/web/auth/auth.go` lines 217-234), demonstrating the read routes are the only ones missing the role gate.

// Index lists Bridges, one page at a time.
func (btc *BridgeTypesController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	bridges, count, err := btc.App.BridgeORM().BridgeTypes(ctx, offset, size)

	resources := make([]presenters.BridgeResource, 0, len(bridges))
	for _, bridge := range bridges {
		resources = append(resources, *presenters.NewBridgeResource(bridge))
	}

	paginatedResponse(c, "Bridges", size, page, resources, count, err)
}

// Show returns the details of a specific Bridge.
func (btc *BridgeTypesController) Show(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	bt, err := btc.App.BridgeORM().FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}

// RequiresEditRole extracts the user object from the context, and asserts the user's role is at least
// 'edit'
func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}
