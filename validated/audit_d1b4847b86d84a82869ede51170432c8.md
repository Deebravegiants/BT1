### Title
Unvalidated cross-chain `from` length causes a panic in `pallet-hyper-fungible-token`'s calldata dispatch path - (File: `modules/pallets/hyper-fungible-token/src/module.rs`)

### Summary
The Funadmin RCE (CVE-2023-24776) is a case of untrusted, attacker-influenced input reaching a dangerous low-level operation without validation. The closest reachable analog in this codebase is in `IsmpModule::on_accept` for `pallet-hyper-fungible-token`, where the ABI-decoded `message.from` bytes are copied into a fixed-size buffer without a length check before being used to derive the dispatch origin for an arbitrary `RuntimeCall`.

### Finding Description
In `on_accept`, when the inbound message carries optional calldata (`message.data`) and no `signature` is supplied in `SubstrateCalldata`, the module derives the dispatch origin directly from `message.from`: [1](#0-0) 

Unlike the `to_bytes` (beneficiary) handling a few lines above, which explicitly validates the length and returns `HftError::InvalidRecipientLength` on mismatch: [2](#0-1) 

the `from_bytes` branch for non-EVM sources performs an unchecked `copy_from_slice` into a `[0u8; 32]` buffer: [3](#0-2) 

`copy_from_slice` panics if the source and destination slice lengths differ. The `on_timeout` handler in the very same file demonstrates the pallet author is aware this field needs explicit length validation and does perform it there: [4](#0-3) 

but the equivalent guard is missing in the `on_accept` no-signature origin-derivation path. Once decoded, the attacker-influenced `runtime_call` is dispatched with `RawOrigin::Signed(origin)`: [5](#0-4) 

`message.from` and `message.data` are fields inside the ABI-encoded `Message` body, which is opaque to `pallet-ismp`'s membership-proof verification — it only proves the bytes were included in a `PostRequest` from the registered/paired source contract address; it does not enforce the internal structure or field lengths of `message.from`. Any state machine or contract deployment registered as a source (via `ContractToAsset`) that is not identical to the reference `HyperFungibleToken.sol` encoding (`abi.encodePacked(msg.sender)`, always 20 bytes) — or any bug/edge case in `StateMachine::is_evm()` classification — can cause `from_bytes.len() != 32` to reach the unchecked branch, panicking the runtime during message execution.

### Impact Explanation
A panic inside `on_accept`, which executes as part of ISMP request-handling during block execution (`modules/ismp/core/src/handlers/request.rs`), is not a benign, catchable `DispatchError` — it is an unhandled Rust panic in WASM runtime execution triggered by relayed, attacker-influenced cross-chain message data. This can abort block execution/import for the message batch, effectively halting delivery of that request (and potentially the whole block) — matching the "route unable to deliver messages" / DoS impact category for a single relayed message, reachable without any privileged role.

### Likelihood Explanation
Exploitability depends on getting a `PostRequest` whose `body`, once ABI-decoded, has a `message.from` field whose length is neither 20 nor 32 bytes for a source classified as non-EVM (`source.is_evm() == false`), while still passing the `ContractToAsset::<T>::get(source, &from)` check on the outer `PostRequest.from`/`source`. This is most easily achieved with any misbehaving, misconfigured, or non-reference-implementation paired module on a registered non-EVM source state machine (e.g., a Substrate-based deployment whose message encoding doesn't match the assumed 32-byte convention), which is plausible in a multi-chain deployment topology where governance registers multiple heterogeneous "peer" contracts/pallets.

### Recommendation
Apply the same explicit length validation used for `to_bytes` (and in `on_timeout` for `from_bytes`) to the no-signature origin-derivation branch in `on_accept`, returning a proper `HftError` (e.g., `InvalidSenderLength`) instead of allowing an unchecked `copy_from_slice` to panic.

### Proof of Concept
1. Register (via governance `register_token`/`ContractToAsset`) a non-EVM source state machine and pairing contract/pallet address whose `Message.from` encoding does not strictly follow the 32-byte convention (or exploit any bug that misclassifies an EVM-like source as non-EVM via `is_evm()`).
2. From that paired source, dispatch a `PostRequest` whose ABI-encoded body sets `message.from` to a byte string with length ≠ 32, and `message.data` to a non-empty `SubstrateCalldata` with `signature = None`.
3. Relay the request with a valid membership proof to the destination chain running `pallet-hyper-fungible-token`.
4. `on_accept` reaches `account.copy_from_slice(from_bytes)` with mismatched lengths, panicking during message handling and aborting execution of that message/block.
