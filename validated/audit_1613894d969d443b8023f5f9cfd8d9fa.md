### Title
OAuth callback SSRF: `shop` used to build the token-exchange host without `ShopValidator` sanitization, unlike every sibling auth flow - (File: `lib/shopify_api/auth/oauth.rb`)

### Summary
Every other credential-exchange flow in this gem (`client_credentials.rb`, `refresh_token.rb`, `TokenExchange.migrate_to_expiring_token`) passes the caller-supplied `shop` through `Utils::ShopValidator.sanitize!` before using it to build the session/host that receives `client_secret`. `ShopifyAPI::Auth::Oauth.validate_auth_callback`, by contrast, takes `auth_query.shop` directly — with no `ShopValidator` call — and uses it unsanitized both to build the outbound host (`auth_base_uri`/`HttpClient#initialize` uses `session.shop`) and as the permanent `Session#shop` returned to the host app.

### Finding Description
`validate_auth_callback` only checks that the query is *signed* (via `Utils::HmacValidator.validate(auth_query)`), that `state` matches the cookie, and that the app is not private/embedded-incompatible: [1](#0-0) 
It never calls `Utils::ShopValidator.sanitize!(auth_query.shop)`, unlike `ClientCredentials.client_credentials`, `RefreshToken.refresh_access_token`, and `TokenExchange.migrate_to_expiring_token`, which all sanitize `shop` before constructing a session/host: [2](#0-1) [3](#0-2) [4](#0-3) 

`ShopValidator` exists precisely to constrain `shop` values to `TRUSTED_SHOPIFY_DOMAINS` (`myshopify.com`, `myshopify.io`, `spin.dev`, `shop.dev`, `shopify.com`) and reject anything else: [5](#0-4) 

Instead, `validate_auth_callback` builds a `null_session` directly from `auth_query.shop`, then constructs an `HttpClient` from that session, and posts a body containing `client_id`/`client_secret` to a host derived directly from `session.shop`: [6](#0-5) [7](#0-6) 

`auth_query.shop` is one of five fields covered by the HMAC signature: [8](#0-7) 
The HMAC binding therefore only proves the request was produced by whoever computed `HMAC(api_secret_key, code|host|shop|state|timestamp)` — it does not, on its own, constrain `shop`'s value to a trusted Shopify domain the way the sibling flows explicitly do with `ShopValidator`. The identity binding this code should enforce — "the `shop` value used to receive `client_secret`" == "a validated `*.myshopify.com`/trusted-domain host" — is broken here even though every other credential-issuing path in the same file/module enforces it.

### Impact Explanation
If `shop` is not constrained to a trusted Shopify domain, a value that passes only HMAC/state checks (produced through a genuine OAuth redirect that an app developer might loosely construct, or through host-application code that forwards raw request parameters into `AuthQuery` without additional checks) can cause the gem to POST the app's `client_id` and `client_secret` to an attacker-influenced host (`https://#{shop}/admin/oauth/access_token`) — i.e., SSRF carrying the app's own OAuth client credentials to a non-Shopify endpoint. This matches the "High: SSRF with the app's credentials" impact category, and is a direct architectural inconsistency versus the gem's own established mitigation (`ShopValidator`) used elsewhere for the exact same class of request.

### Likelihood Explanation
Exploitability depends on whether the host application passes attacker-controllable `shop`/`hmac`/`state` values straight into `AuthQuery` without its own domain check — which is exactly the workflow the gem's own docs recommend (`ShopifyAPI::Auth::Oauth::AuthQuery.new(request.parameters...)`), and there is no independent domain check inside the gem to fall back on for this specific call path, unlike its siblings.

### Recommendation
In `ShopifyAPI::Auth::Oauth.validate_auth_callback`, sanitize `auth_query.shop` through `Utils::ShopValidator.sanitize!` before constructing `null_session`/`Session.from`, mirroring `ClientCredentials`, `RefreshToken`, and `TokenExchange.migrate_to_expiring_token`.

### Proof of Concept
1. Host application builds `AuthQuery` from raw callback request parameters as documented (`docs/usage/oauth.md`), without adding its own shop-domain allow-list.
2. `validate_auth_callback` accepts any `shop` value for which a matching HMAC exists over `(code, host, shop, state, timestamp)` — no check restricts `shop` to `TRUSTED_SHOPIFY_DOMAINS`.
3. `Auth::Session.new(shop: auth_query.shop)` → `Clients::HttpClient.new(session: null_session, ...)` builds `@base_uri = "https://#{session.shop}"` and POSTs `{client_id, client_secret, code, expiring}` to `https://<attacker-influenced-shop>/admin/oauth/access_token`, exfiltrating the app's `client_secret` to that host.         def validate_auth_callback(cookies:, auth_query:)
          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::InvalidOauthError, "Invalid OAuth callback." unless Utils::HmacValidator.validate(auth_query)
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = cookies[SessionCookie::SESSION_COOKIE_NAME]
          raise Errors::NoSessionCookieError unless state

          raise Errors::InvalidOauthError,
            "Invalid state in OAuth callback." unless state == auth_query.state

          null_session = Auth::Session.new(shop: auth_query.shop)
          body = {
            client_id: Context.api_key,
            client_secret: Context.api_secret_key,
            code: auth_query.code,
            expiring: Context.expiring_offline_access_tokens ? 1 : 0, # Only applicable for offline tokens
          }

          client = Clients::HttpClient.new(session: null_session, base_path: "/admin/oauth")
          response = begin
            client.request(
              Clients::HttpRequest.new(
                http_method: :post,
                path: "access_token",
                body: body,
                body_type: "application/json",
              ),
            )
          rescue ShopifyAPI::Errors::HttpResponseError => e
            raise Errors::RequestAccessTokenError,
              "Cannot complete OAuth process. Received a #{e.code} error while requesting access token."
          end

        [
          "shopify.com",

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
