### Title
Unprivileged borrower can park an unhealthy position in the un-liquidatable whole-unit margin band — temporary liquidation DoS — (File: contracts/controller/src/positions/liquidation/math.rs)

### Summary
CVE-2018-1140 is a missing-input-sanitization denial of service: an attacker supplies input the implementation never validates, and the server is driven into a state where requests cannot be served. The analog in XOXNO Lending is `whole_unit_repayment`, which decides whether a sub-3-decimal collateral leg may have its liquidation quote raised. The function has three branches but no sanitization for the gap between them: when `floor(U / (1 + b)) - R < D <= ceil((U + m) / (1 + b))` neither rule 1 (full close) nor rule 2 (raised one-unit quote) applies, so the curve quote — which backs less than one whole unit — stands, and every possible `liquidate` offer then reverts with `InvalidPayments`. A borrower can deliberately enter this state with no privilege and hold the protocol's liquidation path closed until interest accrual or an external price move ends it.

### Finding Description
`build_liquidation_plan` normalizes the repayment via `normalize_repayment_plan`, which consults `whole_unit_repayment` for a solvent account whose only supply leg is a collateral asset below `MIN_BORROWABLE_ASSET_DECIMALS` [1](#0-0) .

Inside `whole_unit_repayment`:

- Rule 1 fires only if `unit_at_bonus = floor(U / (1 + b)) >= total_debt + R` (R = one base unit per debt leg), promoting the quote to the full debt [2](#0-1) .
- Rule 2 fires only if the raised quote `ceil((U + m) / (1 + b))` is strictly below `total_debt`; otherwise the function returns the unmodified curve quote [3](#0-2) .

So for `floor(U / (1 + b)) - R < D <= ceil((U + m) / (1 + b))`, the quote is unchanged. Downstream, `calculate_seized_collateral` floors a partial seizure of a sub-3-decimal leg to whole units; the curve quote backs less than one unit, so the leg seizes zero, is dropped, the released repayment leaves `seized_collaterals` empty, and `plan.validate` reverts with `InvalidPayments` [4](#0-3) [5](#0-4) . The docs confirm: "every offer reverts until accrual or a price move ends that state" [6](#0-5) .

The band is reachable and controllable by the borrower: the band width is `R + m` (roughly one debt-unit plus `U/1e6` in WAD terms), and the borrower picks their borrow size `D` and the collateral price environment determines `U` and `b`. By choosing `D` inside the band — easily checked via `get_liquidation_estimate` — an unprivileged user creates an HF < 1 position that no liquidator can touch.

### Impact Explanation
Temporary freezing of funds / liquidation deadlock: while the band holds, the underwater position cannot be liquidated by any caller, at any offer size — debt keeps accruing against collateral the protocol cannot seize. If the collateral price drifts down during the freeze, the account slides from solvent-but-unhealthy into genuine bad debt, which is then socialized onto suppliers via `apply_bad_debt_to_supply_index` — i.e., the sanitization gap converts into protocol insolvency borne by unrelated suppliers.

### Likelihood Explanation
Medium. The band is narrow (`R + m`), so landing `D` inside it requires deliberate positioning, but it costs the attacker nothing unusual — just a `supply` + `borrow` on a listed sub-3-decimal market with a chosen size. The freeze persists until accrual pushes `D` above `ceil((U + m) / (1 + b))` or the price moves `U`; with slow-accrual markets or stable prices this window can be long. Once in the band, no liquidator action can end it — the revert is unconditional.

### Recommendation
Sanitize the quote path in `whole_unit_repayment`: when neither rule 1 nor rule 2 applies and the curve quote would seize less than one whole unit, either clamp the quote up to `raised` (even when `raised >= D`, promoting to a full close at `D` since the leg rounds up to one unit anyway) or clamp it down to the largest quote that backs zero units and revert explicitly with a distinct error so the state is distinguishable from a transient failure. Alternatively, enforce at `borrow`/position-creation time that a sub-3-decimal collateral position cannot be left with `D` inside the margin band, the same way the codebase already enforces the ≥2-whole-units residual rule.

### Proof of Concept
1. Governance lists collateral token T with `asset_decimals = 2` in its own hub/spoke (allowed; e.g., a unit worth `U = 200 USD`).
2. Attacker supplies `k` whole units of T (only supply position) and borrows debt token USDC such that total debt `D` lands in the band: with liquidation bonus `b = 5%`, `unit_at_bonus = floor(200/1.05) ≈ 190.47 USD`, `R ≈ 1e-6 USD`, `m = max(200/1e6, 1) ≈ 2e-4 USD`, `raised = ceil(200.0002/1.05) ≈ 190.48 USD`. Choose `D` with `190.47 - R < D <= 190.48` after the price drop that takes HF below 1.
3. Manipulate timing/prices (or simply wait for the price to move so HF < 1 with `D` in the band).
4. Any liquidator calling `liquidate` — any payment vector, any `SeizeMode` — gets `InvalidPayments` (controller #16): rule 1 fails (`unit_at_bonus < D + R`), rule 2 fails (`raised >= D`), curve quote seizes < 1 unit → seizure floors to 0 → leg dropped → empty plan → revert.
5. The account remains HF < 1, debt accrues; if T's price falls further before accrual lifts `D` out of the band, the residual becomes socializable bad debt written down against suppliers.
