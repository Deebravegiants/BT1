### Title
Overflow in interest accrual permanently freezes an oversized market - ([File: common/src/rates/scaling.rs])

### Summary
A single borrower can create a large, highly utilized market where a later accrual overflows `i128` before the configured borrow-index ceiling can engage. Once this state is reached, every market operation that first accrues interest—including repayment, withdrawal, liquidation, and `update_indexes`—reverts with `MathOverflow`, permanently freezing the market.

### Finding Description
`Controller::borrow` permits an authorized account owner to open a large borrow position, subject to configured spoke caps, available collateral, liquidity, and utilization limits [1](#0-0) . The pool then accrues interest before minting debt shares and debiting cash [2](#0-1) .

All subsequent market mutations load the market and run `global_sync`, which compounds accrual in bounded chunks but does not bound the resulting total interest calculation [3](#0-2) . When scaled borrowed shares and the borrow index are sufficiently large, unscaling the interest-bearing value overflows `i128`; fixed-point conversion surfaces this as `MathOverflow` rather than saturating or capping the index [4](#0-3) [5](#0-4) .

The issue is demonstrated by the harness test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap`, which supplies a billion-unit, 18-decimal market, borrows 98% of it, repeatedly advances time, and observes `MATH_OVERFLOW` before `MAX_BORROW_INDEX_RAY` engages [6](#0-5) . The test then confirms that both withdrawal and repayment fail with the same overflow, proving that the overflow is not confined to the manual index update [7](#0-6) .

### Impact Explanation
Permanent freezing of funds for the affected market. Supplier withdrawals, borrower repayments, liquidations, revenue operations, and explicit index updates all perform accrual before their state transition, so all are blocked by the same `MathOverflow` path [8](#0-7) [9](#0-8) . No privileged parameter change, leaked key, token-specific behavior, or external-service action is required.

### Likelihood Explanation
Likelihood is low. The attacker must build an extraordinarily large 18-decimal borrow book at sustained 98% utilization, and the observed failure requires years of accrued interest rather than a single oversized call [10](#0-9) . Nevertheless, an unprivileged account can supply collateral and borrow through `Controller::supply` and `Controller::borrow`, and ordinary users can keep the market highly utilized or prevent deleveraging through market conditions. Governance caps can reduce exposure, but the failure occurs at the `i128` value ceiling before the intended borrow-index ceiling protects the market [11](#0-10) .

### Recommendation
Bound the value derived during accrual before unscaling or multiplying it, and engage the borrow-index cap before any conversion that can exceed `i128`. In particular:

- Detect `scaled * index` overflow inside the accrual path and clamp the borrow index at `MAX_BORROW_INDEX_RAY`.
- Ensure supply/debt totals and accrued interest use saturating or widened arithmetic where a representable final index exists.
- Add a regression assertion that `withdraw`, `repay`, `liquidate`, and `update_indexes` remain executable after sustained high-utilization accrual at the maximum configured scale.
- Consider explicit supply/debt ceilings that keep `scaled * max_index` representable for every supported decimal domain.

### Proof of Concept
The existing test constructs the complete reachable sequence:

1. Create an 18-decimal market with the steep XLM rate curve and disabled maximum-utilization gate.
2. Raise the spoke caps to the decimal-domain maximum.
3. Supply `1_000_000_000 * 10^18` units of the target asset and borrow 98% of it using separate collateral.
4. Advance ledger time yearly and call `Controller::update_indexes` for the market.
5. Accrual eventually returns `MATH_OVERFLOW` while `borrow_index < MAX_BORROW_INDEX_RAY`.
6. `withdraw` and `repay` then fail with the same `MATH_OVERFLOW`, demonstrating the permanent market freeze [12](#0-11) .

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
