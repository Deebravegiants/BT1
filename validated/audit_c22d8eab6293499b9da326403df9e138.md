### Title
`finalizeGraduation` can revert forever on dust-sized graduations, permanently freezing the curve-raised LT and tokens parked on `Bonding` - ([File: packages/contracts/src/Bonding.sol])

### Summary
`Bonding`'s two-phase graduation splits state commitment (phase 1, `_enterGraduating`/`triggerGraduation`) from LP seeding (phase 2, `finalizeGraduation`) across separate transactions, exactly the "commit now, finish later" shape whose failure mode is analyzed in the CVE report (NFS's SETACL decoding partially succeeds, later fails, and the earlier-allocated resource is never released). In `Bonding`, phase 1 is committed and mined independently of phase 2: it burns unsold tokens, calls `Router.graduate` to transfer the real curve-raised LT (`ltFromPair`) onto `Bonding`, and caches `PendingGraduation{tokensForLP, ltFromPair, ...}` while flipping the token to `Lifecycle.Graduating`. If phase 2 (`finalizeGraduation`) can be made to *deterministically and permanently* revert, the LT and tokens parked by phase 1 are orphaned forever, and there is no on-chain recovery path — `Lifecycle.Graduating` can never advance, `buy`/`sell` reject that lifecycle, and `_sweepLTToOwner` explicitly protects `ltFromPair` from being swept out.

### Finding Description
`_enterGraduating` ( [1](#0-0) ) runs inline at the end of the threshold-crossing buy, or standalone via the permissionless `triggerGraduation` ( [2](#0-1) ). It calls `_prepareGraduationLiquidity`, which transfers the real raised LT onto `Bonding` via `router.graduate(tokenAddress, ltFromPair)` and caches `(tokensForLP, ltFromPair)` in `pendingGraduation` ( [3](#0-2) ). This transaction is mined and final — the LT is now sitting on `Bonding`, and trading is frozen (`Lifecycle.Graduating`).

`triggerGraduation`'s USD leg fires purely off LT price appreciation, not off a nontrivial buy (natspec: "closes the case where LT appreciation pushed the curve past the USD threshold ... without any buy") ( [4](#0-3) ). If the only real buy on the curve was the creator's minimal seed (bounded only by `Zap.MIN_SEED_USDC`/`minSeedUsdc()`), `ltFromPair` and, via `tokensForLP = ltFromPair * tokenReserve / assetReserve`, `tokensForLP` can both be extremely small once appreciation alone pushes `valueUsd` over `graduationThresholdUsd`.

Phase 2, `finalizeGraduation` ( [5](#0-4) ), routes a pristine (empty) HyperSwap V2 pair through `_seedDirectMint`, which transfers `tokensForLP` and `ltFromPair` to the pair and calls `IUniswapV2Pair(pair).mint(lpLock)` directly ( [6](#0-5) ). Standard UniswapV2Pair `mint()` on a pool's first liquidity provision computes `liquidity = sqrt(amount0*amount1) - MINIMUM_LIQUIDITY` and reverts with `INSUFFICIENT_LIQUIDITY_MINTED` if that is ≤ 0. When `tokensForLP` and `ltFromPair` are dust-sized (as engineered above), `sqrt(tokensForLP * ltFromPair)` can fall below V2's `MINIMUM_LIQUIDITY` (1000), making every call to `finalizeGraduation` revert deterministically, forever — the pair state doesn't change between attempts, so retrying changes nothing.

The contract's own comments on `_swapBudget` acknowledge this exact failure class is possible ("`_routerDepositAndDispose` then skips `addLiquidity` ... `finalizeGraduation` returns `liquidity = 0`, and `LPLock.recordLock(...)` records a zero-sized lock") ( [7](#0-6) ) and mitigates it only inside the *rebalance* branch (`_seedRebalancing`/`_pairRebalance`), not in the empty-pair `_seedDirectMint` path used for ~99% of graduations, and not against UniswapV2's own `MINIMUM_LIQUIDITY` floor. Even if `_seedDirectMint` somehow returned `liquidity == 0` without reverting, `LPLock.recordLock` would independently revert with `ZeroAmount` ( [8](#0-7) ) — so the outcome the authors call "degraded" (a zero-sized lock) is in practice a hard, permanent revert of `finalizeGraduation`.

There is no compensating cleanup: `pendingGraduation[tokenAddress]` and `Lifecycle.Graduating` are only ever mutated by a successful `finalizeGraduation` ( [9](#0-8) ), and `_sweepLTToOwner` is deliberately gated to never touch `ltFromPair` ( [10](#0-9) , [11](#0-10) ). The `LPLockStorage.isLocker` natspec itself flags "token permanently stuck in `Lifecycle.Graduating`, no on-chain recovery" as a known catastrophic outcome for this exact contract ( [12](#0-11) ), confirming no recovery mechanism exists for a stuck `Graduating` token.

### Impact Explanation
Once triggered, the curve-raised LT (`ltFromPair`, already transferred onto `Bonding` in the already-mined phase-1 transaction) and `tokensForLP` worth of the launched token are permanently frozen inside `Bonding` with no path to recover, claim, or re-trigger graduation. Every holder of the token is locked out of trading permanently (`buy`/`sell` reject `Lifecycle.Graduating`), and the creator's/holders' economic value in that curve is destroyed. This is a permanent freezing of trader/creator funds, satisfying the High-severity bar analogous to the source CVE's unbounded resource leak "for the lifetime of the server."

### Likelihood Explanation
This requires: (1) a token graduating purely off LT-price appreciation with minimal real LT ever raised on the curve (i.e., creator seeds at/near `minSeedUsdc()` and no one else buys before the LT's `exchangeRate()` drifts the USD value over threshold), and (2) the resulting `(tokensForLP, ltFromPair)` pair landing below UniswapV2's `MINIMUM_LIQUIDITY` floor. Condition (1) is fully permissionless and needs no attacker capital — anyone can call `triggerGraduation` the instant `canGraduate` flips true, and an attacker/creator can deliberately mint only the floor-sized seed and wait for natural LT yield drift, or target a low-liquidity/high-appreciation LT to accelerate it. Condition (2) depends on economic parameters (`VIRTUAL_LIQUIDITY_USD`, `graduationThresholdUsd`, the specific LT's exchange rate) and is not guaranteed for every token, but is directly reachable by choosing (or deploying, since LT selection at `launch()` is attacker-controlled subject only to `Factory.ltExists`) a suitably-priced/low-decimals LT and a minimal seed. This makes it a realistic, deliberately-triggerable griefing/freeze vector rather than a purely theoretical one.

### Recommendation
- Add an explicit minimum-liquidity floor check on `(tokensForLP, ltFromPair)` at `_enterGraduating`/`triggerGraduation` time (before committing phase 1 and moving the real LT), rejecting graduation (or deferring it) if the projected LP mint would fall at or below UniswapV2's `MINIMUM_LIQUIDITY`.
- Alternatively, give `finalizeGraduation` a fallback for the dust case (e.g., route the tiny leftover LT/tokens to `FeeVault`/owner via a bounded, permissionless rescue path) so a `mint()` revert cannot permanently strand phase-1-committed assets.
- Add monitoring/tests asserting `sqrt(tokensForLP * ltFromPair) > 1000` holds for the full range of economically-reachable `(graduationThresholdUsd, VIRTUAL_LIQUIDITY_USD, exchangeRate)` combinations, including the "graduate off appreciation alone" path.

### Proof of Concept
1. Attacker (or creator) calls `Zap.createToken` with a BounceTech LT chosen for rapid `exchangeRate()` appreciation, seeding at exactly `minSeedUsdc()` (the enforced floor) so only a dust amount of real LT (`ltFromPair`) ever enters the curve.
2. No further buys occur. Over time the LT's `exchangeRate()` rises (external, no attacker action needed) until `Bonding.canGraduate(token)`'s USD leg trips solely from appreciation on the dust `realLtRaised` (`packages/contracts/src/Bonding.sol:680-695`).
3. Anyone calls `Bonding.triggerGraduation(token)` (`packages/contracts/src/Bonding.sol:970-979`), which commits phase 1: burns unsold tokens, calls `router.graduate` to move the dust `ltFromPair` onto `Bonding`, and caches `pendingGraduation = {tokensForLP≈dust, ltFromPair≈dust, ...}` (`packages/contracts/src/Bonding.sol:1073-1096`). This transaction is final and mined.
4. Anyone calls `Bonding.finalizeGraduation(token)` (`packages/contracts/src/Bonding.sol:1000-1034`). Because the pair is fresh/empty, it goes through `_seedDirectMint` (`packages/contracts/src/Bonding.sol:1245-1259`), transferring the dust amounts to the HyperSwap V2 pair and calling `pair.mint(lpLock)`. Standard UniswapV2Pair `mint()` reverts with `INSUFFICIENT_LIQUIDITY_MINTED` because `sqrt(tokensForLP * ltFromPair) <= MINIMUM_LIQUIDITY`.
5. Every subsequent call to `finalizeGraduation` reverts identically — the token is stuck in `Lifecycle.Graduating` forever, `buy`/`sell` are permanently blocked, and the dust LT/tokens already parked on `Bonding` since step 3 can never be swept (`_sweepLTToOwner` explicitly protects `ltFromPair`) or recovered by any other function.

    /// @notice Permissionless trigger for phase 1 of graduation. Same flow as
    ///         the inline post-buy trigger inside `_executeBuy`, but callable
    ///         without any buy. Closes the case where `canGraduate` is true
    ///         (LT appreciation pushed the curve past the USD threshold) but
    ///         the closing buy on the curve would mint below the BounceTech
    ///         LT mint floor and revert with `BelowMinTransactionSize`,
    ///         making the token un-graduatable via `Zap.buy`.
    /// @dev    `_enterGraduating` reads pair reserves and the launch-time
    ///         virtual reserve only — it does not depend on a buy having
    ///         just landed, so the same logic is safe to expose as a
    ///         standalone entry point. The lifecycle pre-checks mirror
    ///         `Bonding.buy`; the launch trading delay is intentionally
    ///         not enforced because `canGraduate` already requires either
    ///         the USD threshold or full curve sellout, both of which are
    ///         unreachable from a fresh launch within the delay window.
    function triggerGraduation(
        address tokenAddress
    ) external nonReentrant {
        TokenInfo storage info = _s().tokenInfo[tokenAddress];
        if (info.creator == address(0)) revert TokenNotTrading();
        if (info.lifecycle == Lifecycle.Graduating) revert TokenIsGraduating();
        if (info.lifecycle != Lifecycle.Curve) revert TokenNotTrading();
        if (!canGraduate(tokenAddress)) revert NotGraduatable();
        _enterGraduating(tokenAddress);
    }

    function finalizeGraduation(
        address tokenAddress
    ) external nonReentrant {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[tokenAddress];
        if (info.lifecycle != Lifecycle.Graduating) revert NotGraduating();

        address lt = info.ltAddress;
        PendingGraduation memory p = $.pendingGraduation[tokenAddress];

        // Anything in this contract beyond `p.ltFromPair` belongs to a
        // concurrent graduation on the same LT (Phase 1 transferred it
        // via `Router.graduate`) or to stray dust. Either way it is
        // off-limits to this graduation's deposit and sweep — see
        // `_routerDepositAndDispose` and `_sweepLTToOwner`.
        // Saturating subtract: a balance below `p.ltFromPair` shouldn't
        // be reachable in normal operation, but we keep finalize from
        // bricking on a Panic if any future code path or non-canonical
        // LT briefly violates the invariant.
        uint256 ltBalance = IERC20(lt).balanceOf(address(this));
        uint256 protectedLT = ltBalance > p.ltFromPair ? ltBalance - p.ltFromPair : 0;

        address lpPair = _ensureUniswapV2Pair(tokenAddress, lt);
        uint256 liquidity = _seedUniswapV2Direct(tokenAddress, lt, lpPair, p.tokensForLP, p.ltFromPair, protectedLT);

        _sweepLTToOwner(lt, protectedLT);

        info.lifecycle = Lifecycle.Graduated;
        $.graduatedPair[tokenAddress] = lpPair;
        delete $.pendingGraduation[tokenAddress];

        LPLock($.lpLock).recordLock(tokenAddress, lpPair, liquidity);

        emit TokenGraduated(tokenAddress, lpPair, liquidity, p.tokensForLP, p.lpBurned, p.unsoldBurned);
    }

    function _prepareGraduationLiquidity(
        address tokenAddress
    ) internal returns (uint256 tokensForLP, uint256 ltFromPair, uint256 lpBurned, uint256 unsoldBurned) {
        address pairAddr = _s().tokenInfo[tokenAddress].pair;
        (uint256 tokenReserve, uint256 assetReserve) = IPair(pairAddr).getReserves();

        unsoldBurned = IPair(pairAddr).tokenBalance();
        if (unsoldBurned > 0) {
            Token(tokenAddress).burn(pairAddr, unsoldBurned);
        }

        ltFromPair = assetReserve - _launchTimeVirtualLtReserve(tokenAddress, pairAddr);
        if (ltFromPair > 0) {
            _s().router.graduate(tokenAddress, ltFromPair);
        }

        tokensForLP = assetReserve == 0 ? 0 : (ltFromPair * tokenReserve) / assetReserve;
        if (tokensForLP > LP_RESERVE) tokensForLP = LP_RESERVE;

        lpBurned = LP_RESERVE - tokensForLP;
        if (lpBurned > 0) {
            Token(tokenAddress).burn(address(this), lpBurned);
        }
    }

    /// @dev Cap the rebalance swap at 99% of the available side's budget,
    ///      so the subsequent `addLiquidity` always has a non-zero amount
    ///      of BOTH sides to deposit. Without this, an extreme hostile
    ///      pre-seed (massively imbalanced reserves) drives the
    ///      unconstrained `_noFeeSwapInput` past our per-side budget,
    ///      `_pairRebalance` clamps to the full budget, and the swap
    ///      consumes 100% of one side. `_routerDepositAndDispose` then
    ///      skips `addLiquidity` (`remToken == 0` or `remLT == 0`),
    ///      `finalizeGraduation` returns `liquidity = 0`, and
    ///      `LPLock.recordLock(...)` records a zero-sized lock — the
    ///      attacker's pre-existing LP becomes 100% of the pool. Reserving
    ///      1% guarantees the deposit leg always lands AND mints non-zero
    ///      LP at the post-swap ratio. The 1% comes off the swap, not the
    ///      deposit — for any realistic pre-seed `s_unconstrained` is
    ///      orders of magnitude below `maxSwap`, so the cap doesn't bind
    ///      and behaviour is unchanged. It only kicks in for catastrophic
    ///      pre-seeds beyond our budget capacity, where the alternative
    ///      is bricking.
    function _swapBudget(
        uint256 budget
    ) internal pure returns (uint256) {
        return (budget * 99) / 100;
    }

    function recordLock(
        address token,
        address lpPair,
        uint256 amount
    ) external {
        LPLockStorage storage $ = _s();
        if (!$.isLocker[msg.sender]) revert NotAuthorized();
        if (lpPair == address(0)) revert ZeroAddress();
        if (amount == 0) revert ZeroAmount();
        // `lockedAt` is the one-shot sentinel: it is always set to a non-zero
        // timestamp on the first lock, so the guard holds for any `amount`.
        if ($.locks[token].lockedAt != 0) revert AlreadyLocked();
        if (IERC20(lpPair).balanceOf(address(this)) < amount) revert InsufficientLPBalance();
        $.locks[token] = LockInfo({lpPair: lpPair, amount: amount, lockedAt: block.timestamp});
        emit LPLocked(token, lpPair, amount);
    }
