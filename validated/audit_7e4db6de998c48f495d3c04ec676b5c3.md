### No vulnerability found for this question.

**Basis:** `Auth::Session.from` does not accept an `id:` keyword from its caller — its signature is `def from(shop:, access_token_response:)` [1](#0-0) . The `id` is computed internally as `"#{shop}_#{associated_user.id}"` or `"offline_#{shop}"` and only then forwarded to `new(id: id, shop: shop, ...)` [2](#0-1) ; the attacker has no keyword to inject.

Both components of that id are already bound to authenticated values before `from` is ever called:
- `shop` in `Oauth.validate_auth_callback` is `auth_query.shop`, only used after `Utils::HmacValidator.validate(auth_query)` succeeds [3](#0-2) .
- `shop` in `TokenExchange.exchange_token` is `jwt_payload.shop`, taken from a JWT whose signature is verified against `Context.api_secret_key` [4](#0-3) .
- `shop` in `RefreshToken.refresh_access_token` and `ClientCredentials.client_credentials` passes through `Utils::ShopValidator.sanitize!(shop)` before use [5](#0-4) [6](#0-5) .
- `associated_user.id` comes from `access_token_response`, the body of Shopify's own `/admin/oauth/access_token` response, obtained by the app itself using `Context.api_secret_key` as `client_secret` in the request body [7](#0-6) , not something the unauthenticated attacker can forge or inject independently of the shop that was HMAC/JWT-verified.

There is no reachable path where an attacker can supply `shop` and `access_token_response` such that they refer to different shops without first breaking `HmacValidator.validate` or JWT signature verification — both of which are keyed on `Context.api_secret_key`. The claimed "caller-supplied `id`" divergence does not exist in this code; the premise of the question is factually inaccurate for this codebase.

The tangential "fast validation" (`expired?` returning `false` for a session with `@expires` nil) reflects intended behavior for non-expiring offline tokens [8](#0-7)  and does not establish any cross-tenant/session-id divergence.

```ruby
        def from(shop:, access_token_response:)
          is_online = access_token_response.online_token?

          if is_online
            associated_user = T.must(access_token_response.associated_user)
            associated_user_scope = access_token_response.associated_user_scope
            id = "#{shop}_#{associated_user.id}"
          else
            id = "offline_#{shop}"
          end

          if access_token_response.expires_in
            expires = Time.now + access_token_response.expires_in.to_i
          end

          if access_token_response.refresh_token_expires_in
            refresh_token_expires = Time.now + access_token_response.refresh_token_expires_in.to_i
          end

          new(
            id: id,
            shop: shop,
            access_token: access_token_response.access_token,
            scope: access_token_response.scope,
            is_online: is_online,
            associated_user_scope: associated_user_scope,
            associated_user: associated_user,
            expires: expires,
            shopify_session_id: access_token_response.session,
            refresh_token: access_token_response.refresh_token,
            refresh_token_expires: refresh_token_expires,
          )
```

```ruby
        def validate_auth_callback(cookies:, auth_query:)
          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::InvalidOauthError, "Invalid OAuth callback." unless Utils::HmacValidator.validate(auth_query)
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = cookies[SessionCookie::SESSION_COOKIE_NAME]
          raise Errors::NoSessionCookieError unless state

          raise Errors::InvalidOauthError,
            "Invalid state in OAuth callback." unless state == auth_query.state

          null_session = Auth::Session.new(shop: auth_query.shop)
          body = {
            client_id: Context.api_key,
            client_secret: Context.api_secret_key,
            code: auth_query.code,
            expiring: Context.expiring_offline_access_tokens ? 1 : 0, # Only applicable for offline tokens
          }

          client = Clients::HttpClient.new(session: null_session, base_path: "/admin/oauth")
          response = begin
            client.request(
              Clients::HttpRequest.new(
                http_method: :post,
                path: "access_token",
                body: body,
                body_type: "application/json",
              ),
            )
          rescue ShopifyAPI::Errors::HttpResponseError => e
            raise Errors::RequestAccessTokenError,
              "Cannot complete OAuth process. Received a #{e.code} error while requesting access token."
          end

          session_params = T.cast(response.body, T::Hash[String, T.untyped]).to_h
          session = Session.from(shop: auth_query.shop,
            access_token_response: Oauth::AccessTokenResponse.from_hash(session_params))
```
