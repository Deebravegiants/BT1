### Title
Webhook HMAC only covers the request body, allowing shop/topic header spoofing on replay - (File: lib/shopify_api/webhooks/request.rb, lib/shopify_api/webhooks/registry.rb)

### Summary
`ShopifyAPI::Webhooks::Request` computes and verifies the HMAC signature only over the raw request body, while the `shop`, `topic`, `api_version`, and `webhook_id` fields — all fields the registry acts on to dispatch and attribute the event — are taken from unauthenticated HTTP headers that are never part of the signed material.

### Finding Description
`Request#to_signable_string` returns only `@raw_body`, and `hmac` is read straight off the `hmac-sha256` header: [1](#0-0) 

`Utils::HmacValidator.validate` verifies `verifiable_query.to_signable_string` (the body) against `verifiable_query.hmac`, and never touches `shop`, `topic`, or any other header: [2](#0-1) 

`Registry.process` then trusts `request.shop` and `request.topic` — both unauthenticated header values — to route to a handler and to stamp the resulting `WebhookMetadata`: [3](#0-2) 

Because the signature never binds `shop`/`topic`/`webhook_id` to the body, an attacker who obtains any one valid `(raw_body, hmac)` pair — e.g., by installing the target app on a store they control and capturing a genuinely delivered webhook — can replay that exact body+HMAC to the app's webhook endpoint while freely rewriting the `shopify-shop-domain` and `shopify-topic` headers. The signature check in `HmacValidator.validate` still passes because it only recomputes over the body, so `Registry.process` will hand the attacker-chosen `topic`/`shop` combination to whichever handler is registered, with `data.shop` set to any victim shop domain the attacker chooses. This breaks the identity binding "shop authenticated == shop the event is attributed to," letting one tenant's captured payload be replayed as if it originated from a different, victim tenant.

### Impact Explanation
This allows cross-tenant event injection: an app's webhook handler will process data (and take shop-scoped actions, e.g. mark the victim shop as uninstalled, updated, or trigger GDPR/data flows) attributed to a shop the attacker does not own, using only a body/HMAC pair captured from their own store's legitimate webhook traffic. This matches the Critical "cross-tenant access" category.

### Likelihood Explanation
Requires the attacker to install the target app on a store they control (a normal, unprivileged action any merchant can take) and capture one legitimate webhook delivery to obtain a valid `(body, hmac)` pair, then replay it with modified `shop-domain`/`topic` headers to the app's public webhook endpoint. No access token, secret, or privileged account is required.

### Recommendation
Bind the identity fields into the signed material or otherwise cryptographically tie `shop`, `topic`, and `webhook_id` to the verified payload (e.g., require the host application to additionally validate that `request.shop` matches an installed/known shop session before dispatch), and document that header values must not be trusted independently of the HMAC-covered body.

### Proof of Concept
1. Install the target app on an attacker-controlled store `attacker.myshopify.com`, trigger any event, and capture the delivered webhook's raw body and `x-shopify-hmac-sha256` header (valid pair, `HMAC(secret, body)`).
2. POST that same raw body and HMAC header to the app's webhook endpoint, but set `x-shopify-shop-domain: victim.myshopify.com` and `x-shopify-topic` to any topic registered by the app.
3. `ShopifyAPI::Webhooks::Request.new` accepts the headers, `HmacValidator.validate` succeeds (it only checks the body), and `Registry.process` invokes the handler with `WebhookMetadata` attributing the (attacker-controlled) body content to `victim.myshopify.com` under the spoofed topic. [4](#0-3)

          if result || Context.old_api_secret_key.nil? || T.must(Context.old_api_secret_key).empty?
            result
          else
            validate_signature(verifiable_query, T.must(Context.old_api_secret_key))
          end
        end

        def validate_signature(verifiable_query, secret)
          received_signature = verifiable_query.hmac
          computed_signature = compute_signature(verifiable_query.to_signable_string, secret)
          OpenSSL.secure_compare(computed_signature, T.must(received_signature))
        end
