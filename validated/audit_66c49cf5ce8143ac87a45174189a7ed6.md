### Title
Stale delegate grant survives NFT transfer and silently reactivates when the position NFT returns to its original owner - (File: contracts/controller/src/storage/account.rs)

### Summary
The bug class in the reference report is a pending callback (`mesh_send_done` timer) that is not canceled when its object (`hdev`) is removed, so it fires against stale state. The analog here is a **capability keyed to an account that is not invalidated when ownership changes**: `DelegateGrant` entries under `ControllerKey::Delegates(account_id)` are stamped with `granted_by` and only lazily cleaned. If the NFT is transferred away and later returns to the original owner, the old grant — never canceled — regains full delegate authority without the owner re-authorizing it.

### Finding Description
`add_delegate` stores `DelegateGrant { granted_by: owner, delegates }`. `get_delegates` filters on `grant.granted_by == *owner`, where `owner` is the *current* NFT owner resolved at call time (`try_account_owner`) [1](#0-0) [2](#0-1) .

Nothing purges the grant on NFT transfer — the position-nft contract has no hook into controller storage, and `remove_account_entry` is the only path that deletes `Delegates`, and only runs on account deletion [3](#0-2) .

`remove_delegate` purges a stale grant, but only if the *new* owner calls it and names the stale delegate [4](#0-3) . The codebase's own test acknowledges this resurrection scenario: `remove_delegate_purges_stale_grant_preventing_resurrection` asserts the grant "must not resurrect when the NFT returns to its original owner" — but only after the new owner happens to invoke `remove_delegate` for exactly that delegate [5](#0-4) . If the interim owner never calls it (they may not know the delegate exists — there is no enumeration prompt, and the grant was made by someone else), the stored `DelegateGrant` still carries `granted_by == original_owner`.

When the NFT returns to the original owner, `is_owner_or_delegate` resolves `owner` back to that address, `get_delegates(account_id, owner)` matches the stale grant again, and the delegate — if still an active position manager — regains `require_owner_or_delegate` authority [6](#0-5) . That authority covers `AccountGuard::Migrate`/`Multiply` paths and delegate-gated strategies (`migrate_from_blend`, `multiply`, `swap_debt`, `swap_collateral`, `repay_debt_with_collateral`) [7](#0-6) .

### Impact Explanation
A position manager delegate that was authorized under a previous holding period can act on the account again after the NFT round-trips back, without any fresh authorization. Depending on the manager's powers this enables debt increases (`multiply`, `migrate_from_blend`), forced swaps (`swap_debt`, `swap_collateral`), and self-destructive `repay_debt_with_collateral` on a position the regained owner believes has no standing delegations — theft of funds / protocol insolvency via manipulated positions. The grant was never canceled when the "device" (ownership) was removed — the exact mesh_send_done pattern: the pending authorization fires against a lifecycle that should have invalidated it.

### Likelihood Explanation
Requires: (1) the owner granted a delegate before transfer, (2) the delegate remains an active position manager, (3) the interim owner never calls `remove_delegate` for that delegate (plausible — the grant is invisible to them by default), and (4) the NFT returns to the original owner (resale, round-trip through an intermediary wallet, or marketplace settlement back to the same address). All steps are unprivileged user actions; no admin, upgrade, or leaked key is needed. Medium likelihood, High impact → High.

### Recommendation
Invalidate delegations on ownership change rather than lazily. Options: store an owner "epoch"/generation counter in `AccountMeta` bumped when `try_account_owner` observes a different owner than the last-seen one, and include it in the `granted_by` check; or have the position-nft contract notify the controller on `transfer`/`burn` so `Delegates(account_id)` is removed eagerly — the equivalent of "cancel the timer when the hdev is removed, like other MGMT timers."

### Proof of Concept
1. Alice owns `account_id` A; active manager M exists in the position-manager registry.
2. Alice calls `add_delegate(caller=alice, account_id=A, delegate=M)`. `DelegateGrant { granted_by: alice, delegates: [M] }` is stored.
3. Alice transfers NFT A to Bob (`PositionNft::transfer`). `Delegates(A)` is untouched; `get_delegates(A, bob)` filters it out but `persistent` still holds the record.
4. Bob never calls `remove_delegate` (he does not know M exists). Grant persists.
5. Bob transfers NFT A back to Alice (or Alice re-acquires it).
6. `get_delegates(A, alice)` now matches the stale grant again (`granted_by == alice`), so `is_owner_or_delegate(A, M, alice)` returns true.
7. M calls a delegate-gated entrypoint (e.g., `multiply`/`swap_collateral`/`repay_debt_with_collateral`) on account A with no fresh authorization from Alice — the stale "timer" fires after the ownership object was removed and restored.

pub(crate) fn remove_delegate(
    env: &Env,
    account_id: u64,
    owner: &Address,
    delegate: &Address,
) -> bool {
    let key = ControllerKey::Delegates(account_id);
    let Some(grant) = get_user::<DelegateGrant>(env, &key) else {
        return false;
    };
    if grant.granted_by != *owner {
        env.storage().persistent().remove(&key);
        return false;
    }
    let mut delegates = grant.delegates;
    let Some(index) = delegates.first_index_of(delegate) else {
        return false;
    };
    delegates.remove(index);
    set_delegates(env, account_id, owner, &delegates);
    true
}

/// The new owner's `remove_delegate` deletes a previous owner's grant and returns `false`.
/// The grant stays deleted when the NFT returns to the previous owner.
#[test]
fn remove_delegate_purges_stale_grant_preventing_resurrection() {
    let env = Env::default();
    env.mock_all_auths();
    let admin = Address::generate(&env);
    let contract_id = env.register(Controller, (admin,));
    let nft = setup_position_nft(&env, &contract_id);

    let alice = Address::generate(&env);
    let bob = Address::generate(&env);
    let delegate = Address::generate(&env);
    let account_id = u64::from(position_nft::PositionNftClient::new(&env, &nft).mint(&alice));

    env.as_contract(&contract_id, || {
        assert!(add_delegate(&env, account_id, &alice, &delegate));
        assert_eq!(get_delegates(&env, account_id, &alice).len(), 1);
    });

    position_nft::PositionNftClient::new(&env, &nft).transfer(
        &alice,
        &bob,
        &u32::try_from(account_id).unwrap(),
    );

    env.as_contract(&contract_id, || {
        assert!(!remove_delegate(&env, account_id, &bob, &delegate));
        assert!(
            !env.storage()
                .persistent()
                .has(&ControllerKey::Delegates(account_id)),
            "stale grant must be purged from storage, not merely read as empty"
        );
    });

    position_nft::PositionNftClient::new(&env, &nft).transfer(
        &bob,
        &alice,
        &u32::try_from(account_id).unwrap(),
    );

    env.as_contract(&contract_id, || {
        assert_eq!(
            get_delegates(&env, account_id, &alice).len(),
            0,
            "the purged grant must not resurrect when the NFT returns to its original owner"
        );
    });
}

/// Accepts the owner or a registered, active manager delegated by that owner.
pub(crate) fn is_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) -> bool {
    if caller == owner {
        return true;
    }
    let active_manager =
        storage::get_position_manager(env, caller).is_some_and(|config| config.is_active);
    active_manager && storage::get_delegates(env, account_id, owner).contains(caller)
}

/// Requires the owner or a registered, active manager delegated by that owner.
pub(crate) fn require_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) {
    if is_owner_or_delegate(env, account_id, caller, owner) {
        return;
    }
    panic_with_error!(env, GenericError::NotAuthorized);
}
