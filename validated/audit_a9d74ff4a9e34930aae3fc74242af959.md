### Title
`ShopifyAPI::Auth::Oauth.begin_auth` does not validate the `shop` domain, enabling forced OAuth completion / open-redirect phishing - ([File: lib/shopify_api/auth/oauth.rb])

### Summary
`ShopifyAPI::Auth::Oauth.begin_auth` builds the OAuth authorization redirect URL directly from a caller-supplied `shop` string with no domain validation, while the library elsewhere (`ClientCredentials`, `TokenExchange`) enforces `Utils::ShopValidator.sanitize!`/JWT-bound shop derivation before using a shop value to build a request target.

### Finding Description
The documented parameter for `begin_auth` is a "Shopify domain name in the form `{exampleshop}.myshopify.com`" [1](#0-0)  but the implementation never checks that invariant. `begin_auth` takes `shop:` and passes it straight to `auth_base_uri(shop)`, which returns `"https://#{shop}/admin"` unmodified for any string: [2](#0-1) [3](#0-2) 

Compare this with the two other flows in the same gem that also take a caller-supplied `shop` and build a request host from it: `ClientCredentials.client_credentials` explicitly calls `Utils::ShopValidator.sanitize!(shop)` before constructing the session/host [4](#0-3) , and `TokenExchange.exchange_token` derives the shop only from the HMAC/JWT-signed `dest` claim of the session token rather than trusting a caller-passed `shop` string at all [5](#0-4) . `ShopValidator` exists specifically to reject non-Shopify domains (`TRUSTED_SHOPIFY_DOMAINS`) and was added precisely to bind the "shop" identity to a trusted domain before it is used as a network target [6](#0-5) . `begin_auth`/`auth_base_uri` is the one place in the OAuth-start flow where this binding is missing: the equality that should hold — "`shop` used to build `auth_route` == a trusted `*.myshopify.com`/`myshopify.io` domain" — is never enforced.

Because a `shop` value is very commonly taken by host applications from an unauthenticated query parameter at the very first "login"/"install" HTTP request (before any Shopify signature exists, since this is the *start* of OAuth), an attacker who controls the value that reaches `begin_auth(shop: ...)` can force the app to construct `auth_route = "https://attacker.example/admin/oauth/authorize?client_id=...&scope=...&redirect_uri=...&state=<nonce>&grant_options[]=..."` and set the CSRF-nonce cookie for that state on the victim's browser before redirecting them to `attacker.example` instead of Shopify.

### Impact Explanation
This matches the "session fixation or forced OAuth completion" impact category. The app-controlled `state` nonce and the `redirect_uri`/`client_id`/requested `scope` of the real app are sent to an attacker-controlled host, and the state cookie is set on the victim's browser referencing an OAuth flow the attacker fully controls the origin for. This can be used to run a convincing phishing page (mimicking the Shopify authorization screen) that harvests merchant staff credentials, or to attempt forced completion tricks against the app's callback route using the state value the attacker chose. Because `validate_auth_callback` independently re-validates the callback via `HmacValidator` (requiring the real `api_secret_key`, which the attacker does not have) [7](#0-6) , the attacker cannot ultimately forge a legitimate access-token exchange or steal `client_secret`/tokens this way — the impact is bounded to open-redirect/phishing and state-nonce exposure rather than credential theft.

### Likelihood Explanation
Likelihood depends entirely on how a host application sources the `shop` argument passed into `begin_auth`. If the app takes it from an unauthenticated request parameter (a common integration pattern for the "login" route, as shown even in this gem's own docs example using `request.headers["Shop"]` without validation) [8](#0-7) , this is trivially reachable by an unprivileged internet user with a single crafted link, with no credentials needed. The `ShopValidator` module already exists in this same codebase and is used for exactly this purpose in sibling flows, showing the gem's own security model expects this validation to happen — it is simply missing from `begin_auth`.

### Recommendation
Call `Utils::ShopValidator.sanitize!(shop)` (or `sanitize_shop_domain`) at the top of `ShopifyAPI::Auth::Oauth.begin_auth` before it is used in `auth_base_uri`, mirroring the validation already performed in `ClientCredentials.client_credentials`, so that only `*.myshopify.com`/`myshopify.io`/other trusted Shopify domains can become the OAuth authorization redirect target.

### Proof of Concept
1. Host application implements a login route per this gem's documented pattern: `ShopifyAPI::Auth::Oauth.begin_auth(shop: params[:shop], redirect_path: "/auth/callback")`.
2. Attacker sends a victim (or automates a request) to `https://victim-app.example/login?shop=attacker.example`.
3. `begin_auth` computes `auth_route = "https://attacker.example/admin/oauth/authorize?client_id=<real_client_id>&scope=<real_scopes>&redirect_uri=https://victim-app.example/auth/callback&state=<random_nonce>&grant_options[]=per-user"` [9](#0-8) , sets the `shopify_app_session` cookie to `<random_nonce>` on the victim's browser, and redirects the victim to `attacker.example`.
4. `attacker.example` now controls a page loaded in the victim's browser with the app's real `client_id`/scopes and a valid state-cookie pairing, which it can use to run a convincing phishing/consent-spoofing flow against the merchant.

        def begin_auth(shop:, redirect_path:, is_online: true, scope_override: nil)
          scope = if scope_override.nil?
            ShopifyAPI::Context.scope
          elsif scope_override.is_a?(ShopifyAPI::Auth::AuthScopes)
            scope_override
          else
            ShopifyAPI::Auth::AuthScopes.new(scope_override)
          end

          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = SecureRandom.alphanumeric(NONCE_LENGTH)

          cookie = SessionCookie.new(value: state, expires: Time.now + 60)

          query = {
            client_id: ShopifyAPI::Context.api_key,
            scope: scope.to_s,
            redirect_uri: "#{ShopifyAPI::Context.host}#{redirect_path}",
            state: state,
            "grant_options[]": is_online ? "per-user" : "",
          }

          query_string = URI.encode_www_form(query)
          auth_route = auth_base_uri(shop) + "/oauth/authorize?#{query_string}"

          { auth_route: auth_route, cookie: cookie }
        end

        def auth_base_uri(shop)
          return "https://#{shop}/admin" unless defined?(DevServer) && shop.include?(".my.shop.dev")

          # For first-party apps in development only, we leverage DevServer to build the admin base URI
          admin_web = T.unsafe(Object.const_get("DevServer")) # rubocop:disable Sorbet/ConstantsFromStrings
            .new("admin-web")
          admin_host = admin_web.host!(nonstandard_host_prefix: "admin")
          shop_name = shop.split(".").first

          "https://#{admin_host}/store/#{shop_name}"
        end

        [
          "shopify.com",
          "myshopify.io",
          "myshopify.com",
          "spin.dev",
          "shop.dev",
        ].freeze,
        T::Array[String],
      )

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
