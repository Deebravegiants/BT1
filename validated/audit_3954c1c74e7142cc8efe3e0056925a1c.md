### Title
Legacy Gateway Web-API Trigger Path Skips Allowlist/Rate-Limit Authorization Before Fan-Out to DON — (File: `core/services/gateway/handlers/capabilities/handler.go`)

### Summary
The `handler.HandleLegacyUserMessage` function in the gateway's `capabilities` package validates message structure (payload decoding, timestamp presence, staleness) and then, marked by an explicit `// TODO: apply allowlist and rate-limiting here` comment, proceeds directly to broadcast the unprivileged caller's request to every DON member node — with no allowlist check and no rate-limiting applied, unlike the sibling v2 HTTP trigger path which performs `authorizeRequest`/JWT verification and `checkRateLimit` before fan-out.

### Finding Description
`HandleLegacyUserMessage` [1](#0-0)  is the legacy (v1) capabilities gateway entry point for a client-submitted `web_api_trigger` message. It performs the following checks in order: JSON payload decoding, non-zero timestamp, and message staleness against `MaxAllowedMessageAgeSec` [2](#0-1) . Immediately after these checks, the code contains the comment `// TODO: apply allowlist and rate-limiting here` followed only by a method-name check (`msg.Body.Method != MethodWebAPITrigger`), then it builds the outgoing request and fans it out to **every** DON member: [3](#0-2) 

This is directly analogous to the report's bug class: a security-relevant checkpoint is explicitly marked as unimplemented/deferred ("TODO"/"deprecated"), yet the surrounding authorization-gated action (here, dispatching a caller-controlled request to every node in a DON, which in the newer v2 handler triggers real HTTP calls or capability execution) is performed unconditionally. Compare this to the properly-implemented sibling path in `httpTriggerHandler.HandleUserTriggerRequest`, which explicitly calls `h.authorizeRequest` (JWT/authorized-key check) and `h.checkRateLimit` before dispatching to nodes: [4](#0-3) 

I was not able to fully trace, within the available tool budget, whether `HandleLegacyUserMessage` is still wired to a reachable, unauthenticated, internet-facing gateway route in current production configuration (i.e., whether this legacy handler path is actually registered/dispatched for external HTTP client requests versus only invoked internally/in tests), since the router/dispatch call sites (`core/services/gateway/gateway.go`, `core/services/gateway/multihandler.go`, `core/services/gateway/handlers/handler.go`) were only found via grep and not read in full before the iteration budget was exhausted.

### Impact Explanation
If this legacy path is still reachable from an unauthenticated/unprivileged external client (as the "legacy" naming and continued presence of a dedicated interface method `HandleLegacyUserMessage` on `handlers.Handler` suggests), any caller could submit a well-formed but otherwise unauthorized `web_api_trigger` message and have it broadcast to all DON member nodes, bypassing the allowlist and rate-limit controls that gate the equivalent v2 flow. Depending on what the receiving capability does with the forwarded payload (e.g., outbound HTTP requests per `handleWebAPIOutgoingMessage`/`Request`/`Response` types in the same file), this could enable unauthorized job/capability execution requests, denial-of-service via unlimited fan-out (no rate limiting), or abuse of node egress on behalf of an unauthorized workflow — mirroring the "unauthorized privileged action performed despite a stated but unimplemented authorization step" pattern from the external report.

### Likelihood Explanation
Likelihood is uncertain without confirming live routing. The explicit `TODO` comment is strong evidence the gap is a genuine oversight rather than intentional design, and the function is still exported as part of the `handlers.Handler` interface and exercised by tests (`handler_test.go`, `gateway_test.go`), indicating it is not dead code. However, since I could not confirm the current gateway configuration routes untrusted external client traffic to this specific legacy handler (versus the newer, properly-authorized v2 `httpTriggerHandler`), likelihood cannot be asserted as "high" with confidence from the evidence gathered.

### Recommendation
- Confirm whether `HandleLegacyUserMessage` / `MethodWebAPITrigger` via the v1 `capabilities` handler is still reachable from external/unauthenticated gateway traffic in current deployments.
- If reachable, implement the allowlist and rate-limiting check described by the TODO before forwarding the request to DON members, consistent with the v2 `httpTriggerHandler.authorizeRequest`/`checkRateLimit` pattern.
- If the legacy path is intentionally deprecated and unused, remove it (and the `HandleLegacyUserMessage` interface method) rather than leaving an authorization gap in dispatchable code.

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JSONRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) { //nolint:gosec // G115: comparing unix timestamps, both fit within uint
		h.lggr.Errorw("stale message")
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),
			ErrorCode: api.HandlerError,
		})
	}
	// TODO: apply allowlist and rate-limiting here
	if msg.Body.Method != MethodWebAPITrigger {
		h.lggr.Errorw("unsupported method", "method", body.Method)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.UnsupportedMethodError),
				"invalid method "+msg.Body.Method,
				nil,
			),
			ErrorCode: api.UnsupportedMethodError,
		})
	}
	req, err := common.ValidatedRequestFromMessage(msg)
	if err != nil {
		h.lggr.Errorw(ErrTransformingMessageToRequest)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrTransformingMessageToRequest,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	h.mu.Lock()
	h.savedCallbacks[msg.Body.MessageID] = &savedCallback{id: msg.Body.MessageID, createdAt: time.Now(), Callback: callback}
	don := h.don
	h.mu.Unlock()

	// Send original request to all nodes
	for _, member := range h.donConfig.Members {
		err = errors.Join(err, don.SendToNode(ctx, member.Address, req))
	}
	return err
}

func (h *httpTriggerHandler) HandleUserTriggerRequest(ctx context.Context, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback, requestStartTime time.Time) error {
	triggerReq, err := h.validatedTriggerRequest(ctx, req, callback)
	if err != nil {
		return err
	}

	workflowID, err := h.resolveWorkflowID(ctx, triggerReq, req.ID, callback)
	if err != nil {
		return err
	}

	key, err := h.authorizeRequest(ctx, workflowID, req, callback)
	if err != nil {
		return err
	}

	if err = h.checkRateLimit(ctx, workflowID, req.ID, callback); err != nil {
		return err
	}
