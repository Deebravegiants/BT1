### Title
Stale-Rate Reward Miscalculation in Consensus Incentives Treasury Payouts - (File: modules/pallets/consensus-incentives/src/impls.rs)

### Summary
`pallet-consensus-incentives` pays relayers a reward computed as `(latest_height - baseline) * cost_per_block`, where `cost_per_block` is read at the moment a `ConsensusMessage` happens to be delivered, not checkpointed at the moment governance changes the rate. This is the same bug class as the Radiant `ChefIncentivesController` finding: a rate that can be updated (`rewardsPerSecond` / `cost_per_block`) is only "settled" against pending accrual in some code paths, so accrual spanning a rate change is billed entirely at whichever rate happens to be active when the relayer next triggers the reward path, rather than being split at the schedule/rate boundary.

### Finding Description
`calculate_reward` computes the reward for the entire unrewarded height span using a single, current `block_cost` value: [1](#0-0) 

The span's lower bound (`baseline`) is the `LastRewardedHeight` watermark, only advanced inside `process_message`, which only runs when a relayer actually submits a `ConsensusMessage` and `on_executed` is invoked: [2](#0-1) 

`update_cost_per_block` — the governance call that changes the rate — does nothing to settle/checkpoint any pending, not-yet-rewarded span at the *old* rate before installing the new one: [3](#0-2) 

Exactly like the Radiant report — where `setScheduledRewardsPerSecond`/`_updateEmissions` is only invoked from `addPool` and `claim`, but not from `_handleActionAfterForToken`/`afterLockUpdate` — here the rate-changing call (`update_cost_per_block`) has no corresponding "settle-then-update" step, and the sole path that would checkpoint accrual (`process_message`, reachable only via delivering a `ConsensusMessage`) is decoupled from the rate change. Any accrual that spans a rate change is paid entirely at the rate in effect when the relayer's message happens to land, not the rate(s) actually in effect over each sub-range of blocks.

### Impact Explanation
This directly mispays the `TreasuryAccount`'s funds and mints matching reputation: [4](#0-3) 

A relayer (an unprivileged actor who need only submit a signed `ConsensusMessage`) can withhold delivering consensus proofs while governance is expected to raise `cost_per_block`, then deliver the backlog once the higher rate is live — collecting reward for the entire withheld span at the new, higher rate. This drains the treasury beyond the amount governance intended to allocate for that historical span — an unintended/unbacked payout functionally equivalent to the "incorrect reward emissions" impact described in the source report, reachable purely through the normal, permissionless consensus-message delivery flow that this pallet's `FeeHandler` hook exposes.

### Likelihood Explanation
Likelihood is moderate-to-high: any relayer can trivially time delivery of otherwise-permissionless `ConsensusMessage`s around a known/observable governance rate change (`update_cost_per_block` is an on-chain, ex-ante visible extrinsic), and no special privilege or race condition is required — only patience in delaying an honest delivery, which does not even alter the correctness of the underlying consensus proof.

### Recommendation
When `update_cost_per_block` (or `remove_incentives`) changes the rate for a `state_machine_id`, first settle/checkpoint any pending reward span at the *old* rate (mirroring `_updateEmissions` calling `_updatePool` before applying a new schedule entry) — e.g., by computing and paying/recording the reward up to `latest_commitment_height` at the old rate and advancing `LastRewardedHeight` before writing the new `cost_per_block`. Alternatively, store a rate-history keyed by height so `calculate_reward` can split a pending span across however many rate changes occurred within it.

### Proof of Concept
1. Governance sets `StateMachinesCostPerBlock[X] = 10` via `update_cost_per_block`.
2. Chain `X`'s remote height advances by 1,000 blocks, but the relayer withholds submitting any `ConsensusMessage` (perfectly legal — delivery is voluntary and unpermissioned).
3. Governance, observing sustained progress and wanting to reward it fairly, raises `StateMachinesCostPerBlock[X] = 100` via `update_cost_per_block` — no settlement occurs, `LastRewardedHeight` is untouched.
4. The relayer now submits a single `ConsensusMessage` proving the full 1,000-block advance. `on_executed` → `process_message` → `calculate_reward` computes `1000 * 100 = 100,000` instead of the fair `1000 * 10 = 10,000`, and the treasury pays out (and mints reputation for) 10x the intended amount for that already-elapsed span.

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}

	#[pallet::call]
	impl<T: Config> Pallet<T> {
		/// Update cost per block for a state machine
		#[pallet::call_index(0)]
		#[pallet::weight(T::WeightInfo::update_cost_per_block())]
		pub fn update_cost_per_block(
			origin: OriginFor<T>,
			state_machine_id: StateMachineId,
			cost_per_block: <T as pallet_ismp::Config>::Balance,
		) -> DispatchResult {
			T::IncentivesOrigin::ensure_origin(origin)?;

			StateMachinesCostPerBlock::<T>::mutate(state_machine_id.clone(), |maybe_cost| {
				*maybe_cost = Some(cost_per_block);
			});

			Self::deposit_event(Event::<T>::StateMachineCostPerBlockUpdated {
				state_machine_id,
				cost_per_block,
			});

			Ok(())
		}
