### Title
Permanent market freeze from RAY-valued debt multiplication overflow before borrow-index cap - ([File: common/src/rates/index.rs])

### Summary
Interest accrual computes the new RAY-denominated debt by multiplying scaled debt shares by the newly capped borrow index. For very large high-decimal markets, that product can exceed `i128::MAX` while the index itself remains below `MAX_BORROW_INDEX_RAY`, so the index cap does not prevent a `MathOverflow`. Because every pool mutation accrues before changing shares or cash, the affected market permanently rejects repayment, withdrawal, liquidation, and future index updates. [1](#0-0) [2](#0-1) 

### Finding Description
`update_borrow_index` caps only the index at `MAX_BORROW_INDEX_RAY`, not the value represented by `borrowed * new_borrow_index`. [3](#0-2)   
`calculate_supplier_rewards` then multiplies the full scaled debt balance by both the old and new borrow indexes; either multiplication panics when its result does not fit `i128`. [1](#0-0)   
The equivalent conversion is `scaled_to_original`, which performs `scaled.mul(index)` for a RAY value. [4](#0-3)   
The supply-side path has the same unbounded product at `supplied * old_supply_index`. [5](#0-4) 

`LiquidityPool::update_indexes`, exposed through the controller's public `update_indexes` path, invokes `ops::market::accrue`; that function loads each market and calls `interest::global_sync`. [6](#0-5) [7](#0-6)   
All ordinary pool mutations use `synced_market` or `renewed_market`, which calls the same accrual routine before the operation can burn debt or supply shares. [8](#0-7)   
Consequently, once the next accrual would overflow, no in-band operation can reduce the scaled balances enough to recover. [9](#0-8) 

The repository contains a concrete regression demonstrating the condition: an 18-decimal market with one billion whole tokens and 98% utilization eventually returns `MathOverflow` from `update_indexes`, while `borrow_index` is still below `MAX_BORROW_INDEX_RAY`; subsequent one-unit withdrawals and repayments fail with the same error. [10](#0-9) 

### Impact Explanation
The result is permanent freezing of all user funds in the affected market. Suppliers cannot withdraw, borrowers cannot repay, liquidators cannot cause debt to be burned, and market parameter changes cannot rescue it because `update_params` accrues under the old model before writing the replacement. [11](#0-10) [12](#0-11) [13](#0-12) 

This is not merely a failure of an oversized transaction: a one-unit withdrawal and a small repayment still panic because accrual precedes those operations and performs multiplication on the entire market totals. [9](#0-8)   
The documentation acknowledges that RAY-valued accrued totals must fit `i128` and that overflow can occur before the index ceiling, but the reachable failure still freezes an otherwise admitted market. [14](#0-13) 

### Likelihood Explanation
Triggering this intentionally requires a very large position—approximately one billion whole tokens at 18 decimals—and sustained high utilization under a steep rate curve. Those values are nevertheless inside the protocol's accepted arithmetic/cap domain: the documented 18-decimal token-to-RAY admission bound is about 170.14 billion whole tokens. [15](#0-14) [16](#0-15) 

The state can also arise organically in a successful whale market rather than requiring the attacker to retain ownership of all funds. After the state exists, any unprivileged caller can submit `update_indexes` for the market and force the overflow before governance or users can react. [7](#0-6) 

The required scale and time make the issue less likely than an ordinary input-validation bug, but the irreversible market-wide freeze supports at least High impact; overall severity is Medium-to-High depending on expected market sizes. [17](#0-16) 

### Recommendation
Do not calculate full RAY-valued debt or supply totals with a panicking `i128` result as part of mandatory accrual. At minimum:

- Detect when `borrowed * new_borrow_index` or `supplied * supply_index` cannot fit before accrual.
- At the boundary, cap the relevant index at the greatest index whose total-value product remains representable, rather than only at `MAX_BORROW_INDEX_RAY` / `MAX_SUPPLY_INDEX_RAY`.
- Once an index reaches that value-derived cap, make subsequent accrual a no-op instead of repeatedly attempting the overflowing product.
- Ensure `update_params`, repayment, withdrawal, liquidation, and cleanup remain executable at the capped index.
- Add a regression assertion that the cap engages before `scaled_to_original` or reward calculations overflow. [18](#0-17) [8](#0-7) 

A wider internal type such as `I256` is not sufficient by itself if returned or stored totals must fit `i128`; the fix must define explicit capped state at the representability boundary. [19](#0-18) 

### Proof of Concept
The checked-in stress test demonstrates a reachable sequence:

1. Configure an 18-decimal market with a maximum 175% borrow-rate curve and lift its caps to the admitted maximum.
2. Supply `1_000_000_000 * 10^18` token units.
3. Borrow 98% of that market using sufficient collateral.
4. Advance time in yearly intervals and call `update_indexes`.
5. The first update that would produce `borrowed * new_borrow_index > i128::MAX` returns `MathOverflow`, while the committed `borrow_index` remains below `MAX_BORROW_INDEX_RAY`.
6. A subsequent one-unit `withdraw` and a small `repay` also return `MathOverflow`. [10](#0-9)

```rust
// tests/test-harness/tests/controller/large_positions_and_long_horizons.rs

let debt = principal / 100 * 98;
t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
t.borrow_raw(ALICE, "BIG18", debt);

    t.advance_time(YEAR_SECS);
    if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
```

```rust
/// Applies `interest_factor` to `old_index` to produce the new borrow index,
/// capped at `MAX_BORROW_INDEX_RAY`.
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}

/// Grows `old_index` by distributing `rewards_increase` over the total value
/// currently supplied (`supplied * old_index`). The division rounds down.
///
/// Returns `old_index` unchanged if `supplied` or `rewards_increase` is zero,
/// or if the total supplied value is zero. Clamps the result between
/// `old_index` (itself capped at `MAX_SUPPLY_INDEX_RAY`) and
/// `MAX_SUPPLY_INDEX_RAY`, so the returned index never decreases and never
/// exceeds the cap.
pub fn update_supply_index(env: &Env, supplied: Ray, old_index: Ray, rewards_increase: Ray) -> Ray {
    if supplied == Ray::ZERO || rewards_increase == Ray::ZERO {
        return old_index;
    }

    let total_supplied_value = supplied.mul(env, old_index);

    if total_supplied_value == Ray::ZERO {
        return old_index;
    }

    let new_value = total_supplied_value.checked_add(env, rewards_increase);
    let grown = fp_core::mul_div_floor_saturating(env, new_value.raw(), RAY, supplied.raw());

    let bounded_old = old_index.raw().min(MAX_SUPPLY_INDEX_RAY);
    Ray::from(grown.min(MAX_SUPPLY_INDEX_RAY).max(bounded_old))
```

```rust
pub fn calculate_supplier_rewards(
    env: &Env,
    params: &MarketParams,
    borrowed: Ray,
    new_borrow_index: Ray,
    old_borrow_index: Ray,
) -> (Ray, Ray) {
    let old_total_debt = borrowed.mul(env, old_borrow_index);
    let new_total_debt = borrowed.mul(env, new_borrow_index);
```

```rust
/// Renews instance TTL, then loads and accrues the market.
pub(crate) fn renewed_market(env: &Env, hub_asset: &HubAssetKey) -> Cache {
```

```rust
/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
}
```

```rust
///
/// Resolves full or partial close, burns shares, optionally withholds the
/// liquidation fee, and gates the final state before debiting cash.
pub(crate) fn accounting(
    env: &Env,
    is_liquidation: bool,
    entry: &PoolWithdrawEntry,
) -> WithdrawOutcome {
    require_nonneg_amount(env, entry.protocol_fee);
    let (mut cache, position) = ops::load_leg(env, &entry.action);

    let (burned, gross_amount) = resolve_close_or_partial(&cache, entry.action.amount, position);
    // Burn first: `protocol_fee_shares` caps the fee mint at `i128::MAX - supplied`.

        &mut cache,
        gross_amount,
        is_liquidation,
        entry.protocol_fee,
    );

    // net settlement: it burns no shares and moves no cash.
    let empty_close = position.raw() == 0 && entry.action.amount == i128::MAX;
    gate_and_debit(env, &mut cache, net_transfer, is_liquidation || empty_close);
```

```rust
/// Accrues interest, resolves the repay amount into burned debt shares and
/// overpayment, burns the shares, and credits the net repay to cash without
/// transferring the overpayment refund. Panics if a positive net repay would
/// burn zero scaled shares.
pub(crate) fn accounting(env: &Env, action: &PoolAction) -> RepayOutcome {
    let (mut cache, position) = ops::load_leg(env, action);
    let amount = action.amount;

    let (burned, overpayment) = cache.resolve_repay(amount, position);
    let net_repay = amount
        .checked_sub(overpayment)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));
    assert_with_error!(
        env,
        net_repay == 0 || burned.raw() > 0,
        GenericError::RepayRoundsToZeroShares
    );

    let position = position.checked_sub(env, burned);
    cache.burn_debt(burned);

    cache.credit_cash(net_repay);

    let snapshot = cache.commit();
    let mutation = cache.position_mutation(position, net_repay);
```

```rust
/// Computes `floor(x * y / d)`, rounding toward negative infinity for a negative quotient.
/// Panics with `GenericError::DivisionByZero` if `d == 0`, or with
/// `GenericError::MathOverflow` if the result does not fit in `i128`.
pub fn mul_div_floor(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    require_nonzero_divisor(env, d);
    if let Some(quotient) = x
        .checked_mul(y)
        .and_then(|product| div_floor_i128(product, d))
    {
        return quotient;
    }
    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    let nonneg = quotient_is_nonnegative(x, y, d);
    to_i128(env, &div_floor_i256(env, &x256.mul(&y256), &d256, nonneg))
}

/// Computes `ceil(x * y / d)`, rounding toward positive infinity for a positive quotient and
/// truncating toward zero for a negative one. Panics with `GenericError::DivisionByZero` if
/// `d == 0`, or with `GenericError::MathOverflow` if the result does not fit in `i128`.
pub fn mul_div_ceil(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    require_nonzero_divisor(env, d);
    if let Some(quotient) = x
        .checked_mul(y)
        .and_then(|product| div_ceil_i128(product, d))
    {
        return quotient;
    }
    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    let nonneg = quotient_is_nonnegative(x, y, d);
    to_i128(env, &div_ceil_i256(env, &x256.mul(&y256), &d256, nonneg))
}
```
