## Analysis: Webhook shop-domain header not bound by HMAC signature [1](#0-0) [2](#0-1) [3](#0-2) 

### Title
Webhook `shop` field is not covered by the HMAC signature, allowing cross-tenant webhook spoofing - (File: `lib/shopify_api/webhooks/request.rb`)

### Summary
`ShopifyAPI::Webhooks::Request#to_signable_string` returns only the raw request body, while `shop`, `topic`, and `webhook_id` are read directly from HTTP headers and are never part of the signed material. `Registry.process` validates the HMAC over the body alone and then forwards the unauthenticated `shop` header straight into `WebhookMetadata`, which host applications use to identify which tenant/merchant the webhook belongs to.

### Finding Description
The binding this code is supposed to enforce is: `shop header == shop whose secret produced the HMAC`. In reality the check only proves `HMAC(body, api_secret_key) == received_hmac`; `shop-domain` is excluded entirely. [2](#0-1) 

Since a Shopify app uses a single `api_secret_key` shared across every shop that installs it, the HMAC for a given body is identical no matter which shop the (real) webhook originated from. An unprivileged internet user can:
1. Install the target app on their own (attacker-owned) development/trial store — no privileges beyond a free Shopify account are required.
2. Receive a legitimately Shopify-signed webhook for that store (e.g. `app/uninstalled` or `shop/redact`, whose bodies are constant/empty JSON across shops), capturing a valid `(body, hmac)` pair.
3. Replay that exact `(body, hmac)` pair directly to the app's webhook endpoint, but replace the `x-shopify-shop-domain` header with a victim shop's domain.

`Registry.process` only checks the HMAC of the body: `raise Errors::InvalidWebhookError, "Invalid webhook HMAC." unless Utils::HmacValidator.validate(request)`, and then trusts `request.shop` as the tenant identity passed to the handler. [4](#0-3) 

Because the equality the code actually verifies (`hmac(body)` matches) is weaker than the equality it implicitly claims to guarantee (`shop == the shop that produced this HMAC`), the attacker can make the host application believe an arbitrary victim shop sent this webhook.

### Impact Explanation
This breaks tenant isolation: a host application built on this gem's documented `Registry.process` API will process attacker-supplied data (or trigger side effects like data deletion for GDPR redact topics, deauthorizing a shop on `app/uninstalled`, etc.) under a victim shop's identity — a cross-tenant access issue, matching the Critical impact bucket in scope.

### Likelihood Explanation
Moderate-to-high: any user can create a free Shopify development store, install the target app, and capture a legitimately-signed low-entropy webhook body (many topics have static or empty JSON bodies), then replay it with a spoofed `shop-domain` header to the app's public webhook endpoint. No access to the app's `api_secret_key` or any privileged credential is required — only a signed sample obtained from the attacker's own tenant.

### Recommendation
Include `shop` (and ideally `topic`/`webhook_id`) in the signed/verified material, or otherwise cryptographically bind the `shop-domain` header value to the specific installation — e.g., cross-check `request.shop` against the shop tied to the app's stored session/access token before trusting it, rather than passing the raw header straight to `WebhookMetadata`.

### Proof of Concept
```ruby
# Attacker installs the app on their own store "attacker.myshopify.com"
# and captures a real Shopify-signed "app/uninstalled" webhook:
#   body: "{}"
#   x-shopify-hmac-sha256: "<valid-hmac-for-{}>"
#   x-shopify-shop-domain: "attacker.myshopify.com"

# Attacker replays with a spoofed shop header, same body/hmac:
headers = {
  "x-shopify-topic" => "app/uninstalled",
  "x-shopify-hmac-sha256" => "<valid-hmac-for-{}>",  # unchanged, still valid because HMAC only covers body
  "x-shopify-shop-domain" => "victim-shop.myshopify.com",  # spoofed
  "x-shopify-webhook-id" => "attacker-controlled-id",
  "x-shopify-api-version" => "2024-01",
}

request = ShopifyAPI::Webhooks::Request.new(raw_body: "{}", headers: headers)
ShopifyAPI::Webhooks::Registry.process(request)
# HmacValidator.validate passes (body+hmac match), and the handler receives
# WebhookMetadata with shop: "victim-shop.myshopify.com" — cross-tenant spoofing.
``` [4](#0-3)
