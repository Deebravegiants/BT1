### Title
Sustained high utilization grows the borrow index until accrual overflows i128, permanently freezing the market - (File: common/src/rates/index.rs)

### Summary
The bug class of the external report is "a reachable code path that crashes the server" — in Soroban terms, a path that makes a contract permanently panic. The strongest analog in XOXNO Lending is the RAY-value ceiling in interest accrual: once `borrowed * borrow_index` exceeds `i128::MAX`, every subsequent accrual panics with `MathOverflow`, and because every pool verb (supply, borrow, withdraw, repay, liquidate, `update_indexes`) accrues first via `global_sync`, the market is permanently frozen. The `MAX_BORROW_INDEX_RAY` cap in `update_borrow_index` never engages because the multiplication in `calculate_supplier_rewards` overflows before the capped index is small enough to help — the value ceiling (~170× the scaled principal at 1e36 raw ray per billion 18-decimal tokens) is hit first. The repo's own test documents this freeze explicitly: "Every verb accrues first, so the market freezes: no repay, no withdraw, no liquidation. The index cap never engages" [1](#0-0) .

### Finding Description
`update_borrow_index` caps the index at `MAX_BORROW_INDEX_RAY` [2](#0-1) , but `calculate_supplier_rewards` computes `borrowed.mul(env, new_borrow_index)` where `borrowed` is the scaled share total — with a whale-scale market (e.g. 1e9 whole tokens at 18 decimals), the product overflows `i128` and `mul` panics with `MathOverflow` while the index is still below its cap [3](#0-2) . `global_sync` runs `accrue_chunk` at the head of every mutating call [4](#0-3) , so once the product crosses the ceiling the panic is unrecoverable — `Cache::calculate_utilization` and the unscale helpers (`unscale_supply`, `unscale_borrow_ceil`) hit the same `scaled_to_original`/`mul` overflow on every entrypoint [5](#0-4) . `update_indexes` is permissionless, so any unprivileged address can trigger the transition across the cliff.

### Impact Explanation
Permanent freezing of funds: all suppliers' deposits, borrowers' collateral, and unclaimed protocol revenue in that market become unreachable — repay, withdraw, liquidation, and `clean_bad_debt`/`recapitalize` paths all accrue first and revert. This is not a fail-closed guard; it is an irrecoverable state the market enters through ordinary use.

### Likelihood Explanation
Requires a very large market (order 1e9 whole units at 18 decimals, or proportionally less at higher utilization/rates) sustained near the steep segment of the borrow curve for multiple years. Reachable by unprivileged `supply`/`borrow`/`update_indexes` calls, but the size and duration requirements make it a Medium-severity edge rather than a near-term exploit. Note the condition is documented in-repo as a known boundary ("the bound in docs/reference/formulas.md is wrong"), so it may be a known/accepted limitation — flagging for confirmation.

### Recommendation
Make accrual saturate instead of panic: clamp `borrowed`/`supplied` totals or the product domain inside `scaled_to_original`/`calculate_supplier_rewards` (e.g. compute the index delta first and compare it against headroom `i128::MAX / borrowed`), or enforce the index cap proportionally to position scale so `scaled * MAX_BORROW_INDEX_RAY` fits `i128`. Alternatively cap total supplied value at listing time so `supplied * supply_index` can never reach the ceiling.

### Proof of Concept
`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321` — `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap`: supply `BILLION * 10^18` of an 18-decimal asset on `xlm_curve`, borrow 98% of it, advance time in yearly steps calling `try_update_indexes_for(&["BIG18"])` until it errors with `MATH_OVERFLOW`; then `try_withdraw_raw` and `try_repay` both panic with the same error while `borrow_index < MAX_BORROW_INDEX_RAY` [6](#0-5) .

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
}

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}
