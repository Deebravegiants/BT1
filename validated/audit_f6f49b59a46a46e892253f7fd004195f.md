## Title
Post-graduation trades can bypass the 0.75% Alt Fun fee entirely by swapping directly against the HyperSwap V2 pair instead of through `Zap` - (File: `packages/contracts/src/Zap.sol`)

### Summary
The Footium report shows that royalties enforced only on one asset layer (players) can be bypassed by trading a wrapper asset (clubs) that has no royalty logic. Alt.fun has the analogous structural flaw: the 0.75% buy/sell fee that funds creator + protocol revenue is enforced *only* inside `Zap` — never inside `Pair`, `Token`, or the underlying `IBounceLeveragedToken` (LT). Once a token graduates, its trading venue becomes a real, permissionless HyperSwap V2 pair. Any unprivileged trader can call `pair.swap(...)` directly (exactly the same call `Zap._swapOnUniswapV2` itself makes) using LT/TOKEN they already hold, completely skipping `Zap` and therefore never paying the fee that `FeeVault.accrue` expects.

### Finding Description
`docs/contracts-scope.md` states the fee model explicitly:
"All fees are charged by `Zap` in USDC and forwarded into `FeeVault`. The router holds no fee state." [1](#0-0) 

The fee is applied inside `Zap._executeBuy` / the sell counterpart, computed on `usdcAmount`/gross proceeds and forwarded to `FeeVault` via `_accrueFee`: [2](#0-1) [3](#0-2) 

Once a token is `isGraduated`, `Zap` executes the trade by transferring LT/TOKEN straight to the pair and calling `pair.swap(...)` — a completely standard, permissionless UniswapV2-style call with no access control: [4](#0-3) 

The pair interface confirms `swap`, `mint`, and `skim` are open, unauthenticated entry points on the pair itself: [5](#0-4) 

`AGENTS.md`'s own threat-model writeup for the graduation front-run defense independently confirms the pair is fully open to arbitrary third-party calls: "A vanilla UniswapV2 pair is deployable by anyone... after creation anyone can call `pair.mint(to)` against pre-transferred tokens." [6](#0-5) 

Most tellingly, the codebase itself documents that this bypass is a known, accepted reality for at least one scenario: "Post-graduation, anyone holding LT directly can also still buy by swapping on the HyperSwap TOKEN/LT pair, bypassing Zap." [7](#0-6) 

That comment is scoped to the mint-pause edge case, but the underlying mechanism it relies on — a trader calling `pair.swap` directly instead of going through `Zap` — is available to **every** unprivileged trader for **every** post-graduation trade, not just during a BounceTech mint pause. Since the fee is enforced exclusively in `Zap`'s wrapper logic and never in `Pair`, `Token`, or the LT contract, any trader who already holds LT (minted directly via BounceTech, or received from a prior trade) can:
1. `transfer` LT to the graduated pair,
2. call `IUniswapV2Pair(pair).swap(0, tokensOut, to, "")` directly (computing `tokensOut` from `getAmountOut`),
3. receive TOKEN with zero Alt Fun fee paid, and symmetrically `transfer`+`swap` TOKEN back to LT to sell with zero fee.

This is exactly the Footium analog: a fee/royalty is enforced at one asset-interaction layer (`Zap`) but the same economic event (a token sale) is fully achievable through an alternate, fee-unaware layer (the raw AMM pair) that the protocol itself relies on as the trading venue.

### Impact Explanation
Every post-graduation trade routed around `Zap` permanently denies both the creator's 0.25% share and the protocol's 0.5% share of that trade's fee — this is systemic, recurring loss of creator/protocol revenue on the entire post-graduation trading volume of a token, not a one-off griefing. Since post-graduation is the *permanent* end-state for every successful token (curve trading is finite and capped, DEX trading continues indefinitely), this materially and continuously drains the fee revenue the protocol economically depends on, exactly mirroring the "bypass player royalties" impact rated Medium in the source report.

### Likelihood Explanation
Any rational trader who understands basic UniswapV2 mechanics and wants to save 0.75% per trade will do this — it requires no special permissions, no flash loans, no timing tricks: just holding LT (obtainable directly from BounceTech's `mint`) and calling `pair.swap` directly, exactly as `Zap._swapOnUniswapV2` itself does. The contracts explicitly acknowledge this bypass path exists in their own comments, indicating high awareness and thus high likelihood of exploitation by fee-sensitive traders, MEV bots, and aggregators that route directly to pairs.

### Recommendation
Move fee enforcement (or an equivalent value-capture mechanism) into the pair/LP layer itself for graduated tokens — e.g., a custom pair/hook that skims a fee on every `swap`, or restrict direct `pair.swap` access so all trades must route through `Zap`. Alternatively, accept the tradeoff explicitly as a documented economic limitation (as is currently done only for the mint-pause edge case) and adjust fee-revenue projections accordingly, since a real HyperSwap V2 pair cannot be made non-permissionless without forking the AMM (a tradeoff `AGENTS.md` already rejected for the pre-seed defense for similar reasons).

### Proof of Concept
1. Creator launches a token via `Zap.createToken`, and it graduates (either via `triggerGraduation` supply/USD trigger or organically).
2. Trader mints LT directly via `IBounceLeveragedToken(lt).mint(...)` (not through `Zap`).
3. Trader reads `bonding.graduatedPair(tokenAddress)` to get the pair address, and `IUniswapV2Pair(pair).getAmountOut(ltAmountIn, lt)` to compute the expected TOKEN out.
4. Trader calls `IERC20(lt).transfer(pair, ltAmountIn)` then `IUniswapV2Pair(pair).swap(tokenOutAmount, 0, trader, "")` (or the correct token0/token1 ordering) directly — bypassing `Zap.buy` entirely.
5. Trader receives TOKEN with 0% Alt Fun fee paid, versus the mandatory 0.75% (`buyFeeBps`) that `Zap._executeBuy` would have deducted.
6. Repeat in reverse (`transfer` TOKEN to pair + `swap`) to sell without paying `sellFeeBps`, and without ever calling `FeeVault.accrue`.

    function _swapOnUniswapV2(
        address tokenIn,
        address tokenOut,
        uint256 amountIn
    ) internal returns (uint256 amountOut) {
        Bonding bonding_ = _s().bonding;
        // `graduatedPair` is keyed by the launched token only; check `tokenIn`
        // first (sell direction) then fall back to `tokenOut` (buy direction).
        address pair = bonding_.graduatedPair(tokenIn);
        if (pair == address(0)) pair = bonding_.graduatedPair(tokenOut);

        bool inIsToken0 = IUniswapV2Pair(pair).token0() == tokenIn;
        // Quote from the pair so the output tracks its live fee instead of a
        // hardcoded rate, keeping `amountOut` consistent with the K-check.
        amountOut = IUniswapV2Pair(pair).getAmountOut(amountIn, tokenIn);

        IERC20(tokenIn).safeTransfer(pair, amountIn);

        (uint256 amount0Out, uint256 amount1Out) = inIsToken0 ? (uint256(0), amountOut) : (amountOut, uint256(0));
        IUniswapV2Pair(pair).swap(amount0Out, amount1Out, address(this), new bytes(0));
    }
