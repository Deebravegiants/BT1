### Title
Unchecked RAY-value overflow permanently freezes an overgrown market - ([File: common/src/rates/simulate.rs](common/src/rates/simulate.rs))

### Summary
The accrual engine converts total scaled supply and debt into RAY-denominated values with fallible `Ray::mul`, which reverts when the result exceeds `i128::MAX`. Because every market mutation performs accrual before processing the requested operation, crossing this value ceiling permanently prevents repayment, withdrawal, liquidation, and subsequent index updates for that market. [1](#0-0) [2](#0-1) 

### Finding Description
`accrue_step` unconditionally computes `scaled_to_original(borrowed, borrow_index)` and `scaled_to_original(supplied, supply_index)` before calculating utilization or updating the indexes. [3](#0-2) 

`scaled_to_original` delegates to `Ray::mul`, which evaluates `scaled * index / RAY` using `mul_div_half_up`; the widened `I256` intermediate prevents intermediate-product overflow, but conversion of the final quotient back to `i128` still panics with `MathOverflow` when the value is unrepresentable. [4](#0-3) [5](#0-4) [6](#0-5) [7](#0-6) 

The borrow index is capped only after `old_index.mul(interest_factor)` and can therefore reach `10^36`, while the market-value calculation itself fails much earlier when a large scaled position times the index exceeds `i128::MAX`. [8](#0-7) 

This is reachable through the permissionless controller surface: `supply`, `borrow`, and `update_indexes`; the controller forwards index updates to the pool, whose `update_indexes` calls `ops::market::accrue`, which loads each market and invokes `global_sync`. [9](#0-8) [10](#0-9) [11](#0-10) [12](#0-11) 

The repository’s own integration test demonstrates the condition with a valid 18-decimal market, a one-billion-token deposit, and 98% utilization: accrual eventually reverts before the configured borrow-index ceiling, after which both withdrawal and repayment revert with `MathOverflow`. [13](#0-12) 

### Impact Explanation
The affected market becomes permanently unusable once its scaled market value crosses the `i128` result boundary. [14](#0-13) 

Because accrual runs at the start of pool mutations, the overflow blocks withdrawals, repayments, liquidations, flash paths, recapitalization paths that sync the market, and any later attempt to update indexes. [2](#0-1) [15](#0-14) 

This results in permanent freezing of user deposits and outstanding debt in the market, satisfying the accepted impact category of permanent freezing of funds and a contract unable to operate on that market. [13](#0-12) 

### Likelihood Explanation
An unprivileged whale or coordinated market participant can place a valid large deposit and borrow under the configured caps, then leave the market at sustained high utilization until index growth pushes `scaled * index / RAY` beyond `i128::MAX`. [16](#0-15) 

The integration fixture uses protocol-valid parameters, a one-billion-token 18-decimal market, 98% utilization, and repeated `update_indexes` calls; it intentionally demonstrates that the value ceiling is reached before the protocol’s `MAX_BORROW_INDEX_RAY` cap. [17](#0-16) 

The scenario requires unusually large balances and sustained interest accrual, so it is less likely than ordinary arithmetic manipulation, but it requires no privileged call, malformed parameter, oracle manipulation, or contract upgrade. [9](#0-8) [10](#0-9) 

### Recommendation
Bound total scaled supply and debt at entry so their index-valued RAY amounts can never exceed `i128::MAX` at the maximum possible indexes, or make accrual gracefully saturate market-value calculations before index processing continues. [3](#0-2) 

A safer approach is to cap or reject deposits and debt mints using a dynamic invariant such as `scaled <= i128::MAX / MAX_INDEX`, enforce that invariant separately for `supplied` and `borrowed`, and preserve enough headroom for revenue-share additions. [18](#0-17) [19](#0-18) 

Alternatively, market-total valuation can use a saturating helper for utilization while retaining checked arithmetic for individual positions and cash settlement; this would prevent a representable index from making every exit path unusable. [20](#0-19) [21](#0-20) 

### Proof of Concept
The existing harness test is a complete reproduction:

```rust
let principal = 1_000_000_000i128 * 10i128.pow(18);

t.supply_raw(BOB, "BIG18", principal);
t.supply_raw(ALICE, "COL", 3_000_000_000i128 * 10_000_000);
t.borrow_raw(ALICE, "BIG18", principal / 100 * 98);

loop {
    t.advance_time(31_556_926);
    if t.try_update_indexes_for(&["BIG18"]).is_err() {
        break;
    }
}

assert_contract_error(
    t.try_withdraw_raw(BOB, "BIG18", 1),
    errors::MATH_OVERFLOW,
);
assert_contract_error(
    t.try_repay(ALICE, "BIG18", 1.0),
    errors::MATH_OVERFLOW,
);
```

The test supplies one billion 18-decimal tokens, borrows 98% of the position, advances yearly intervals, and observes `MathOverflow` while `borrow_index < MAX_BORROW_INDEX_RAY`; subsequent withdrawal and repayment calls fail with the same error. [16](#0-15)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Computes `floor(x * y / d)`, saturating to `i128::MAX` (or `i128::MIN` for a negative
/// quotient) instead of panicking if the result does not fit in `i128`. Panics with
/// `GenericError::DivisionByZero` if `d == 0`.
pub fn mul_div_floor_saturating(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    require_nonzero_divisor(env, d);
    if let Some(quotient) = x
        .checked_mul(y)
        .and_then(|product| div_floor_i128(product, d))
    {
        return quotient;
    }
    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    div_floor_i256(
        env,
        &x256.mul(&y256),
        &d256,
        quotient_is_nonnegative(x, y, d),
    )
    .to_i128()
    .unwrap_or(if quotient_is_negative(x, y, d) {
        i128::MIN
    } else {
        i128::MAX
    })
```

pub fn update_supply_index(env: &Env, supplied: Ray, old_index: Ray, rewards_increase: Ray) -> Ray {
    if supplied == Ray::ZERO || rewards_increase == Ray::ZERO {
        return old_index;
    }

    let total_supplied_value = supplied.mul(env, old_index);

    if total_supplied_value == Ray::ZERO {
        return old_index;
    }

    let new_value = total_supplied_value.checked_add(env, rewards_increase);
    let grown = fp_core::mul_div_floor_saturating(env, new_value.raw(), RAY, supplied.raw());

    let bounded_old = old_index.raw().min(MAX_SUPPLY_INDEX_RAY);
    Ray::from(grown.min(MAX_SUPPLY_INDEX_RAY).max(bounded_old))
}
```

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
