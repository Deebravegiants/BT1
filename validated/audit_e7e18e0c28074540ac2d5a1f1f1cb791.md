### Title
Strategy fee charged on the gross minted debt instead of the net proceeds, overcharging `multiply`/`swap_debt` users - ([File: contracts/pool/src/ops/strategy.rs](contracts/pool/src/ops/strategy.rs))

### Summary
`ops::strategy::accounting` mints debt for the user-specified `amount` and deducts the fee from the proceeds: the user owes `amount` but only receives `amount - fee`. The fee is computed as `amount * flashloan_fee / BPS` on the gross `amount` — which already contains the fee — instead of on the net amount actually delivered. This is the same fee-base mismatch as `redeem()`/`deposit()` overcharging in the referenced report: the user-specified value is `proceeds + fee`, so the correct charge is `amount * fee_bps / (BPS + fee_bps)`, not `amount * fee_bps / BPS`.

### Finding Description
Entry path: an unprivileged user calls controller `multiply` or `swap_debt` with a borrow leg of `amount` and `charge_fee` set. The controller forwards a `PoolAction{amount, position}` to the pool's strategy op.

In `contracts/pool/src/ops/strategy.rs`:

- `compute_fee` returns `Bps::from(flashloan_fee).flash_loan_fee_on(env, amount)`, i.e. `half_up(amount * fee_bps / BPS)` computed on the full `amount` [1](#0-0) 
- `borrow::mint_debt(..., amount)` mints debt shares for the whole `amount` — `amount` is the gross obligation, i.e. `net_proceeds + fee` [2](#0-1) 
- `amount_to_send = amount - fee` is what the user actually receives [3](#0-2) 
- the fee is booked as protocol revenue via `interest::add_protocol_revenue` [4](#0-3) 

Because `amount = proceeds + fee`, applying `bps` directly to `amount` charges `bps` on the fee itself. The consistent base is the amount actually delivered (`amount - fee`), equivalently `fee = amount * fee_bps / (BPS + fee_bps)`.

Numerically, at `flashloan_fee = 500` bps (the `MAX_FLASHLOAN_FEE_BPS` cap) and `amount = 10,000` units: code charges `500` units and delivers `9,500`; a fee on delivered proceeds would be `ceil(10,000 * 500 / 10,500) = 477`, delivering `9,523`. The user overpays ~23 units (~4.8% more fee than the stated rate on proceeds) on every charged strategy open.

Contrast with `ops/flash.rs::terms`, where the fee base is correct: the user receives the full `amount` principal and repays `amount + fee`, so `flash_loan_fee_on(amount)` is applied to the net principal [5](#0-4) . The strategy path is the asymmetrical one: the fee is carved out of the draw yet still computed on the whole draw.

### Impact Explanation
Every `multiply`/`swap_debt` call with `charge_fee` skims an excess `amount * fee_bps² / (BPS * (BPS + fee_bps))` from the borrower's proceeds into protocol revenue. The user receives fewer tokens than the configured fee rate implies while carrying the full debt. This is a direct, deterministic overcharge of user funds on a permissionless path; at the 500 bps cap the excess is ~0.24% of the borrowed amount per strategy open, accruing to revenue on each call.

### Likelihood Explanation
High within charged strategy usage: the miscalculation is unconditional — it fires on every `multiply` and `swap_debt` that sets `charge_fee`, with no rounding, timing, or adversary preconditions. Frequency depends only on how often users open charged strategies.

### Recommendation
In `compute_fee`/`accounting`, treat `action.amount` as the gross debt and derive the fee on the net proceeds: `fee = amount * fee_bps / (BPS + fee_bps)` (half-up, keeping the `fee >= 1` dust rule), or equivalently compute `amount_to_send = amount * BPS / (BPS + fee_bps)` and `fee = amount - amount_to_send`. Keep `StrategyFeeExceeds` and mint debt for the full `amount` unchanged.

### Proof of Concept
1. Configure a hub asset with `flashloan_fee = 500` bps, strategy-enabled, with liquidity.
2. As an unprivileged user, call controller `multiply` (or `swap_debt`) requesting a debt draw of `amount = 10,000` base units with `charge_fee = true`.
3. Observe `PoolStrategyMutation`: `actual_amount = 10,000` debt minted, `amount_received = 9,500`, `fee = 500` booked to `add_protocol_revenue` (`events::emit_strategy_fee` shows the same).
4. Compare: charging the 500 bps rate on delivered proceeds should yield `fee = 10,000 * 500 / 10,500 = 476` and `amount_received = 9,524`. The user pays 24 extra units of fee and holds identical debt — the fee was levied on itself because the base `amount` already includes the fee.

fn compute_fee(env: &Env, cache: &Cache, amount: i128, charge_fee: bool) -> i128 {
    if !charge_fee {
        return 0;
    }
    let fee = Bps::from(i128::from(cache.params().flashloan_fee)).flash_loan_fee_on(env, amount);
    assert_with_error!(env, fee <= amount, FlashLoanError::StrategyFeeExceeds);
    fee
}
