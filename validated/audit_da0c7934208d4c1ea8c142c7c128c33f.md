## Analysis

The reported bug class — Chainlink price feeds trusted without an L2 sequencer-uptime check — has a direct analog in `SimplexPaymaster.sol`, an ERC-4337 paymaster that is explicitly designed to run on L2s (its own docstring calls out "BNB/USD on BSC, ETH/USD on Ethereum" and "Base/Ethereum stablecoins up to 24h" heartbeats) and is reachable by any unprivileged UserOp sender ("bandwidth purchaser" of gas).

### Title
Missing L2 sequencer-uptime check in `SimplexPaymaster`'s Chainlink oracle pricing enables theft of paymaster funds during/after sequencer outages - (File: `evm/src/utils/SimplexPaymaster.sol`)

### Summary
`SimplexPaymaster._getOraclePrice` consumes Chainlink `latestRoundData()` for both the native-asset/USD and token/USD feeds and only validates the answer's sign and its staleness against `maxOracleAge`. It never checks an L2 sequencer-uptime feed, so on OP-stack L2s the contract is targeted for (Base is explicitly named in the code) it can accept a price as "fresh" immediately after a sequencer outage even though the price is economically stale relative to the real market that moved during the downtime.

### Finding Description
`_getOraclePrice` is the sole gate on price data used to convert native gas cost into ERC-20 charge amounts: [1](#0-0) 

It is called from `_tokenPrice` (used by `_fetchDetails`, which sets the `tokenPrice` that `PaymasterERC20` uses to compute `erc20Cost`) and from `swapAndDeposit`: [2](#0-1) [3](#0-2) 

The `Params.maxOracleAge` staleness bound is governance-configurable up to a hard ceiling of 7 days, and the contract's own documentation anticipates heartbeats "up to 24h" for Base/Ethereum stablecoin feeds: [4](#0-3) [5](#0-4) 

None of this validates that the underlying L2's sequencer has been up long enough for the Chainlink keeper network to have had a chance to refresh the feed. On OP-stack L2s (including Base), Chainlink feeds are updated by keeper transactions that themselves depend on the sequencer being live; when the sequencer halts and later resumes, `latestRoundData()` can return a round whose `updatedAt` still satisfies `block.timestamp - updatedAt <= maxOracleAge` even though the true market price has since diverged materially, exactly the condition the original report describes for `ChainlinkAggregator.sol`. Any address can trigger a price read at that moment simply by submitting a UserOp through this permissionless paymaster (mode `0x00`/`0x02` in `_fetchDetails`/`_prefund`), so there is no privileged actor required to reach this code path: [6](#0-5) [7](#0-6) 

### Impact Explanation
`tokenPrice` directly sets how many ERC-20 units a UserOp sender pays the paymaster for a given amount of native gas. If the native-asset feed is stale-low (or the token feed stale-high) relative to the real market at the moment a UserOp executes right after a sequencer restart, an attacker can submit UserOps priced off the stale round and systematically underpay for gas relative to its true native-asset cost. Because the paymaster's ERC-20 surplus and EntryPoint deposit are shared assets governed only via Hyperbridge governance requests (`_withdrawAssets`, `swapAndDeposit`), repeated exploitation during/after any sequencer downtime event drains the paymaster's EntryPoint deposit and token balances — a concrete theft-of-funds outcome, not merely a display/accounting bug.

### Likelihood Explanation
The paymaster is permissionless by design (`validatePaymasterUserOp` accepts any UserOp with valid mode-0x00/0x02 data for a registered, active token), so exploitation requires no privileged access — only awareness of a sequencer outage window and submitting a UserOp once the sequencer resumes but before Chainlink keepers refresh the feed. The generous, governance-set `maxOracleAge` (up to 24h for the exact chains this contract targets) widens this window well beyond the immediate outage itself.

### Recommendation
Add a Chainlink L2 sequencer-uptime feed check (per Chainlink's documented pattern) to `_getOraclePrice`: read the sequencer-uptime aggregator's `latestRoundData()`, reject if `answer == 1` (sequencer down), and enforce a grace period (e.g., Chainlink's recommended 3600s) since `startedAt` before trusting any price feed, in addition to the existing `updatedAt`/`maxOracleAge` staleness check.

### Proof of Concept
1. Governance registers `SimplexPaymaster` on Base with `maxOracleAge` set near its documented ~24h ceiling for stablecoin feeds (`_setParams`, `evm/src/utils/SimplexPaymaster.sol:359-383`).
2. The Base sequencer halts; Chainlink keeper transactions that would refresh `nativeOracle`/`tokenOracle` cannot land, so `latestRoundData().updatedAt` freezes at the pre-outage value while the true native-asset/USD price moves materially on L1/CEXes during the outage.
3. Sequencer resumes; an attacker immediately submits a UserOp through `SimplexPaymaster` (mode `0x00` or `0x02`) referencing a registered token.
4. `_fetchDetails` → `_tokenPrice` → `_getOraclePrice` (`evm/src/utils/SimplexPaymaster.sol:653-676`) computes `tokenPrice` from the still-"fresh-by-timestamp" but economically stale round (`block.timestamp - updatedAt` is well under `maxOracleAge`).
5. `_prefund`/`PaymasterERC20._erc20Cost` charges the attacker's UserOp using this stale `tokenPrice`, letting the attacker pay less in ERC-20 than the native gas actually costs the paymaster, draining paymaster funds on each such call until the feed catches up.

            if (address(cfg.tokenOracle) == address(0)) revert TokenNotRegistered(tokenAddr);
            if (!cfg.active) revert TokenNotActive(tokenAddr);

        }

        return super._validatePaymasterUserOp(userOp, userOpHash, maxCost);

    function _fetchDetails(
        PackedUserOperation calldata userOp,
        bytes32 /* userOpHash */
    )
        internal
        view
        override
        returns (uint256 validationData, IERC20 token, uint256 tokenPrice)
    {
        bytes calldata data = userOp.paymasterData();
        if (data.length < 21) revert InvalidPaymasterData(data.length);

        uint8 mode = uint8(data[0]);
        if (mode != 0x00 && mode != 0x02) revert InvalidMode(mode);

        address tokenAddr = address(bytes20(data[1:21]));

        TokenConfig memory cfg = tokenConfigs[tokenAddr];
        if (address(cfg.tokenOracle) == address(0)) revert TokenNotRegistered(tokenAddr);
        if (!cfg.active) revert TokenNotActive(tokenAddr);

        tokenPrice = _tokenPrice(cfg);
        token = IERC20(tokenAddr);
        validationData = 0; // no time-range restriction

        if (mode == 0x02) {
            (,,, uint256 deadline,,,) = _parsePermit2Data(data);
            // Surfacing the permit deadline as validUntil lets bundlers drop
            // expiring ops instead of discovering it through a Permit2 revert.
            uint48 validUntil = deadline > type(uint48).max ? 0 : uint48(deadline);
            validationData = ERC4337Utils.packValidationData(true, 0, validUntil);
        }
    }

    function _prefund(
        PackedUserOperation calldata userOp,
        bytes32 userOpHash,
        IERC20 token,
        uint256 tokenPrice,
        address prefunder_,
        uint256 maxCost
    )
        internal
        override
        returns (bool prefunded, uint256 prefundAmount, address prefunder, bytes memory prefundContext)
    {
        bytes calldata data = userOp.paymasterData();
        if (uint8(data[0]) != 0x02) {
            return super._prefund(userOp, userOpHash, token, tokenPrice, prefunder_, maxCost);
        }

        (, uint256 permitAmount, uint256 nonce, uint256 deadline, uint8 v, bytes32 r, bytes32 s) =
            _parsePermit2Data(data);
        prefundAmount = _erc20Cost(maxCost, userOp.maxFeePerGas(), tokenPrice);
        if (prefundAmount > permitAmount) revert InsufficientPermitAmount(permitAmount, prefundAmount);
        // Solidity's own extcodesize revert on a code-less target is not caught by try/catch.
        if (address(PERMIT2).code.length == 0) revert Permit2NotDeployed();

        // Charge the token _fetchDetails already validated as registered and active, rather
        // than re-trusting the mode byte's token field, so the external call never depends
        // on the caller-ordering of the base contract.
        address tokenAddr = address(token);
        // `prefunder_` is who the base says funds the op (userOp.sender today); use it so this
        // branch stays aligned with the mode-0 branch that forwards it to super._prefund.
        address owner = prefunder_;
        try PERMIT2.permitTransferFrom(
            ISignatureTransfer.PermitTransferFrom({
                permitted: ISignatureTransfer.TokenPermissions({token: tokenAddr, amount: permitAmount}),
                nonce: nonce,
                deadline: deadline
            }),
            ISignatureTransfer.SignatureTransferDetails({to: address(this), requestedAmount: prefundAmount}),
            owner,
            abi.encodePacked(r, s, v)
        ) {
            emit Permit2Executed(tokenAddr, owner, prefundAmount, nonce);
        } catch (bytes memory reason) {
            revert Permit2Failed(tokenAddr, reason);
        }

        return (true, prefundAmount, owner, "");
    }

    function _tokenPrice(TokenConfig memory cfg) internal view returns (uint256) {
        uint256 nativeUsd = _getOraclePrice(nativeOracle, nativeOracleDecimals);
        uint256 tokenUsd = _getOraclePrice(cfg.tokenOracle, cfg.tokenOracleDecimals);

        return (nativeUsd * (10 ** cfg.tokenDecimals) * (10_000 + markupBps)) / (tokenUsd * 10_000);
    }

    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
