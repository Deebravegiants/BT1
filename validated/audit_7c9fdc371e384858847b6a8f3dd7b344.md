### Title
Unbooked tokens sent directly to the liquidity pool are permanently stranded - (`contracts/pool/src/lib.rs`)

### Summary
A direct token transfer to the pool increases the pool’s SAC/token balance without increasing any market’s `cash` book. No permissionless or controller entrypoint reconciles that surplus, credits it to a market, or rescues it, so the transferred amount remains locked in the pool indefinitely. [1](#0-0) [2](#0-1) 

### Finding Description
The pool treats `cash` as bookkeeping rather than deriving it from `token::balance()`. Inbound token movements are credited only when the controller first transfers a measured amount and then invokes an accounting entrypoint such as `supply`, `repay`, or `recapitalize`. [3](#0-2) [4](#0-3) 

For `recapitalize`, the controller pulls `amount` from `payer`, measures only that transfer’s delta, and passes `received` to the pool. A pre-existing pool balance is not measured or claimed. [5](#0-4) 

The pool then applies at most `backing_shortfall` and refunds `amount - applied` to `payer`; it does not inspect the token balance for older donations. [6](#0-5) [7](#0-6) 

All mutating pool entrypoints are owner-only, and the exposed set contains no general token rescue or surplus-sweep function. [8](#0-7) 

### Impact Explanation
An unprivileged user can irrevocably lose any listed token by calling the token contract’s `transfer` with the pool as recipient. Because the amount is outside every market’s `cash` book, no supplier claim, revenue claim, recapitalization, or withdrawal accounts for it. Once all booked obligations are paid, the surplus can still remain at the pool with no callable recovery path. [1](#0-0) [9](#0-8) 

### Likelihood Explanation
The path requires only a direct SAC/token transfer by any holder, including an operator making an overpayment or a user mistakenly sending funds to the published pool address. The probability depends on an erroneous or unsolicited transfer, but no privileged action, market manipulation, oracle condition, or timing dependency is required. [4](#0-3) [10](#0-9) 

### Recommendation
Add an owner-authorized surplus-rescue entrypoint that computes `token.balance(pool) - sum(book cash across all markets sharing the token)` and transfers only that surplus. Alternatively, add an explicit donation function that credits the surplus to a designated market or revenue balance, while documenting that direct token transfers remain unrecoverable. [11](#0-10) [9](#0-8) 

### Proof of Concept
```rust
// `pool` is a deployed LiquidityPool and `asset` is a listed market token.
let pool_cash_before = pool_client.get_sync_data(&hub_asset).cash;
let balance_before = token_client.balance(&pool);

// Any unprivileged holder can transfer directly to the pool.
token_client.transfer(&payer, &pool, &donation);

assert_eq!(
    token_client.balance(&pool),
    balance_before + donation
);

// No market cash changed because no pool entrypoint ran.
assert_eq!(
    pool_client.get_sync_data(&hub_asset).cash,
    pool_cash_before
);

// This does not recover the donation: the controller transfers `amount`
// from `payer` and only passes that measured receipt to the pool.
controller_client.recapitalize(&payer, &hub_asset, &donation);

// If the market is already backed, the newly supplied `donation` is refunded;
// the earlier direct transfer remains outside `cash` and stranded at `pool`.
```

The stranded state follows from three mechanics: direct transfers never call `credit_cash`; controller `recapitalize` measures only the new payer-to-pool transfer; and the pool interface exposes no surplus sweep. [2](#0-1) [4](#0-3) [8](#0-7)

    /// Increases accounting cash by `amount`. Rejects negative amounts and overflow.
    pub(crate) fn credit_cash(&mut self, amount: i128) {
        require_nonneg_amount(&self.env, amount);
        self.cash = self
            .cash
            .checked_add(amount)
            .unwrap_or_else(|| panic_with_error!(&self.env, GenericError::MathOverflow));

/// Transfers funds to the pool, credits the measured receipt up to the backing
/// shortfall, and refunds unused funds. Returns credited cash; rejects flash loans.
pub(crate) fn recapitalize(
    env: &Env,
    payer: Address,
    hub_asset: HubAssetKey,
    amount: i128,
) -> i128 {
    validation::require_authorized_caller(env, &payer);
    require_positive_amount(env, amount);

    let mut cache = Context::new(env);
    let pool_addr = cache.cached_pool_address();
    // Prefund the pool and credit only its measured receipt.
    let received = payments::transfer_amount_measured(
        env,
        &hub_asset.asset,
        &payer,
        &pool_addr,
        amount,
        GenericError::AmountMustBePositive,
    );

    pool_recapitalize_call(env, &pool_addr, &hub_asset, &payer, received).actual_amount
}
