### Title
Emporium "Min" proof path lets an attacker drain arbitrary ERC20 tokens held by Emporium with zero accounting - (File: contracts/CircomDataBuilder.sol, contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol)

### Summary
`formInputForCircom` routes to `formInputEmporiumMin` whenever `externalActionId == HINKAL_EMPORIUM_ACTION_ID` and `erc20TokenAddresses.length == 0`. The `MainEVMCircuitMin` circuit used for this path only constrains `message == Poseidon(messageSeed)` - it has no signature verification and no binding to any UTXO or owner key. Combined with `EmporiumUpgradeable.runAction`'s balance accounting being scoped strictly to `circomData.erc20TokenAddresses` (which is empty on this path) and `verifyWallet` skipping the ECDSA check entirely when `stack.signerAddress == address(0)`, an attacker can submit an `EmporiumStack` whose `op` transfers any ERC20 balance Emporium holds to themselves, with no balance check ever detecting the outflow.

### Finding Description
The broken equality is: **assets Emporium can move in a transaction == assets accounted for in `balancesBefore`/`balancesAfter`**.

- `formInputForCircom` selects the min-circuit input whenever `erc20TokenAddresses.length == 0` and the action id is Emporium's: [1](#0-0) 
- `MainEVMCircuitMin.circom` only computes `message <== Poseidon(1)([messageSeed])`; it declares `outTimeStamp`/`calldataHash` as public but never constrains them, and there is no `spendingPublicKey`/`eddsaSignature`/`signedMessageHash` verification at all, unlike the full `MainEVMCircuit`: [2](#0-1)  versus the signature check present in the normal circuit [3](#0-2) . Since the attacker themselves chooses `emporiumMessage` (the value bound to `message` on-chain), they can trivially pick `messageSeed = 0` and set `emporiumMessage = Poseidon(0)`, producing a valid proof with no knowledge of any secret tied to a real depositor.
- `dimensionsCheck` only requires internal consistency between `circomData` array lengths and the attacker-supplied `dimensions` struct - both sides are attacker controlled, so setting everything to length 0 passes trivially: [4](#0-3) 
- `EmporiumUpgradeable.runAction` decodes `stack` from attacker-controlled `externalActionMetadata`, computes `balancesBefore`/`balancesAfter` only over `circomData.erc20TokenAddresses` (empty here), and when `stack.signerAddress == address(0)` skips all wallet callback restrictions and simply executes the op via `op.endpoint.call{value: op.value}(op.callData)`: [5](#0-4) 
- `verifyWallet` returns immediately without any ECDSA check when `stack.signerAddress == address(0)`, meaning the ops list is entirely unauthenticated: [6](#0-5) 
- The post-loop accounting loop `for (uint256 i = 0; i < circomData.erc20TokenAddresses.length; i++)` never executes because the array length is 0, so any token moved by the op (e.g. `IERC20(endpoint).transfer(attacker, amount)` executed with `msg.sender == Emporium`) is never checked against `balanceChange < 0` or reflected in `utxoSet`: [7](#0-6) 
- `payRelayFees` also iterates the same empty array and short-circuits, and the fallback branch only reverts when `signerAddress != address(0)` is required, which the attacker avoids by setting `feeStructure.flatFee = 0`: [8](#0-7) 
- The outer `Hinkal.transact` also computes `oldBalances`/`newBalances` from `circomData.erc20TokenAddresses` only, so the top-level balance-diff/slippage checks are likewise vacuous on an empty array: [9](#0-8)  and [10](#0-9) 

**Exploit flow**: attacker calls `Emporium.runAction`'s allowed caller (Hinkal) is invoked via `Hinkal.transact` with `externalActionId = HINKAL_EMPORIUM_ACTION_ID`, `erc20TokenAddresses = []`, `dimensions` all zero, `feeStructure.flatFee = 0`, and `externalActionData.externalActionMetadata = abi.encode(EmporiumStack{signerAddress: address(0), ops: [{endpoint: TOKEN, invokeWallet: false, value: 0, callData: transfer(attacker, amount)}], ...})`. They generate a real (non-forged) proof for the trivial `MainEVMCircuitMin` statement with `messageSeed` of their choosing. `performHinkalChecks` and `verifyProof` succeed because the calldata-hash integrity check and dimensions checks are self-consistent and the circuit proves nothing meaningful. `runAction` then executes the attacker's op, transferring Emporium's real ERC20 balance to the attacker, with no balance check anywhere along the call path (`Emporium.runAction`, `Hinkal.transact`) able to detect or reject the outflow since all accounting loops key off the empty `erc20TokenAddresses` array.

Existing guards fail because: `performHinkalChecks`/`dimensionsCheck` only enforce self-consistency of attacker-supplied data, not truthfulness against real state; `verifyProof` for the min circuit proves only a hash-preimage the attacker freely chooses; `rootHashExists` is not tied to the executed action since no nullifiers are spent; and the balance-diff invariant in both `Hinkal.transact` and `EmporiumUpgradeable.runAction` is scoped to `circomData.erc20TokenAddresses`, which the attacker deliberately sets empty specifically to enter this code path.

### Impact Explanation
Any ERC20 balance held by the `EmporiumUpgradeable` contract (accumulated relay fees, transient swap proceeds, deposits mid-flight, or tokens sent there by any other user/integration) can be transferred to the attacker with a single, cheap, unauthenticated call. This is direct theft of protocol/relay and potentially in-flight user funds held by Emporium, matching the Critical severity category ("direct theft of shielded or in-flight user funds"). The attack is fully repeatable for as long as Emporium holds any drainable balance and the bug is unpatched.

### Likelihood Explanation
No privileged role is required. The attacker needs only: (1) the ability to call `Hinkal.transact` (any EOA), (2) a proof for the trivial `MainEVMCircuitMin` statement, which requires no secret tied to any real depositor and can be generated locally with `messageSeed = 0`, and (3) knowledge that Emporium holds a positive balance of some ERC20 token (easily observable on-chain). Cost is a single transaction's gas plus proof generation; the exploit is deterministic and repeatable.

### Recommendation
- Make the "Min" proving path require the same accounting invariants as the normal path, or disallow `erc20TokenAddresses.length == 0` combined with any non-empty `ops` array that performs external calls capable of moving value.
- Bind `EmporiumStack`/ops (or at minimum a hash of them) into the circuit-verified public signals for the Min path, so an unsigned/unauthenticated `signerAddress == address(0)` stack cannot be paired with arbitrary `ops`.
- Do not allow `stack.signerAddress == address(0)` to bypass all authentication of `stack.ops`; require an explicit allow-list of endpoints/selectors or a relay/owner-level attestation for unsigned "self" operations, and ensure `EmporiumUpgradeable.runAction`'s balance snapshot/diff covers every token any op could plausibly move, not just tokens declared in `circomData.erc20TokenAddresses`.

### Proof of Concept
Foundry test plan:
1. Deploy `Hinkal`, `HinkalHelper`, `EmporiumUpgradeable` (as an allowed recipient), and a mock ERC20 `TOKEN`.
2. Fund `EmporiumUpgradeable` directly with `TOKEN.transfer(emporium, 1000e18)` to simulate residual/fee balance.
3. As attacker (unprivileged EOA), build `CircomData` with:
   - `externalActionData.externalActionId = HINKAL_EMPORIUM_ACTION_ID`
   - `erc20TokenAddresses = []`, `amountChanges = []`, `inputNullifiers = []`, `outCommitments = []`, `onChainCreation = []`, `slippageValues = []`, `encryptedOutputs = []`
   - `feeStructure = {feeToken: address(0), flatFee: 0, variableRate: 0}`
   - `externalActionData.externalActionMetadata = abi.encode(EmporiumStack{signerAddress: address(0), ops: [{endpoint: address(TOKEN), invokeWallet: false, value: 0, callData: abi.encodeWithSelector(IERC20.transfer.selector, attacker, 1000e18)}], maxFee: 0, deadline: type(uint256).max, v:0, r:0, s:0})`
   - `emporiumMessage = Poseidon(0)`, matching a locally generated real proof for `MainEVMCircuitMin` with `messageSeed = 0`
   - `dimensions` all zero, `rootHashHinkal`/`rootHashHinkalIndex` set to the genesis root/index.
4. Call `Hinkal.transact(a, b, c, dimensions, circomData)` from attacker.
5. Assert both sides of the broken equality:
   - Before: `TOKEN.balanceOf(emporium) == 1000e18`, `TOKEN.balanceOf(attacker) == 0`.
   - After: `TOKEN.balanceOf(emporium) == 0`, `TOKEN.balanceOf(attacker) == 1000e18`, while `circomData.erc20TokenAddresses.length == 0` and no `require` in `Hinkal.transact` or `EmporiumUpgradeable.runAction` reverted - proving Emporium's real balance changed with zero entries in the accounted balance arrays.

    function payRelayFees(
        CircomData calldata circomData,
        address signerAddress,
        int256[] calldata deltaAmountChanges
    ) internal {
        FeeStructure calldata feeStructure = circomData.feeStructure;

        bool foundToken = false;

        for (uint256 i = 0; i < circomData.erc20TokenAddresses.length; i++) {
            // tokens deposited into Emporium are not charged
            if (deltaAmountChanges[i] >= 0) {
                continue;
            }

            address erc20TokenAddress = circomData.erc20TokenAddresses[i];
            bool isFeeToken = erc20TokenAddress == feeStructure.feeToken;

            if (isFeeToken) {
                foundToken = true;
            }

            uint256 relayFee = 0;
            uint256 flatFee = isFeeToken ? feeStructure.flatFee : 0;

            if (signerAddress == address(0)) {
                uint256 sumAbs = uint256(-deltaAmountChanges[i]);

                EmporiumStorageVars storage $ = _getEmporiumStorage();
                relayFee = $._hinkalHelper.calculateRelayFee(
                    sumAbs,
                    flatFee,
                    feeStructure.variableRate
                );
            } else {
                relayFee = flatFee;
            }

            payRelay(
                circomData.relay,
                signerAddress,
                relayFee,
                erc20TokenAddress
            );
        }

        if (!foundToken && feeStructure.flatFee != 0) {
            require(
                signerAddress != address(0),
                "Gas Token in Emporium is not found"
            );

            payRelay(
                circomData.relay,
                signerAddress,
                feeStructure.flatFee,
                feeStructure.feeToken
            );
        }
    }
