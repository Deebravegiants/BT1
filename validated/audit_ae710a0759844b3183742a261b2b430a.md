### Title
Face self-custody candidate frame accepted despite face_identifier model error - ([File: src/plans/biometric_capture/mod.rs])

### Summary
`Plan::handle_face_identifier` only gates acceptance of a `self_custody_candidate_rgb` frame on `output.is_valid.map_or(false, |v| v)` and a higher `output.score`, while `output.error.is_some()` is only logged, never checked. A crafted/faulty `face_identifier::Output::IsValidImage` carrying both `error: Some(_)` and `is_valid: Some(true)` will still be accepted as the self-custody candidate frame bound to the signup.

### Finding Description
In `handle_face_identifier` [1](#0-0) , the code path is:

```rust
if let face_identifier::Output::IsValidImage(output) = output.value {
    tracing::debug!("Face self-custody frame score: {:?}", output.score);
    if output.error.is_some() {
        tracing::error!("Face self-custody frame error: {:?}", output);
    }

    if output.is_valid.map_or(false, |v| v) {
        let highest = ...;
        if output.score.is_some_and(|s| s > highest) {
            self.self_custody_candidate_rgb = Some(FrameInfoSelfCustodyCandidate::new(output, frame...));
            ...
        }
        orb.only_rgb_net_frames = true;
    }
}
```

The `error` field on `IsValidOutput` (`src/agents/python/face_identifier/types.rs:113-126`) is purely informational for logging/telemetry (also propagated into `FaceIdentifierIsValidMetadata` in `src/debug_report.rs:1324-1345`), and is never used as a gating condition to reject the frame. The only acceptance criteria are `is_valid == Some(true)` and `score` being higher than any previously stored candidate. If the underlying Python face-identifier model (or a fusion path producing `IsValidOutput`, see `mega_agent_two.rs` `fusion_rgb_net_face_identifier` / `handle_fusion_rgb_net_face_identifier` in `src/brokers/orb.rs:1224-1274`) returns an output where `is_valid` was pre-populated/stale as `true` (e.g., a `Default`-initialized struct returned alongside a Python exception path, or any backend/model bug that sets both fields inconsistently) with `error: Some(_)`, the erroneous, non-validated frame is still stored as `self_custody_candidate_rgb`.

This candidate frame is later fed as `frame_self_custody_candidate` into `face_identifier::Input::Estimate` (`src/agents/python/face_identifier/mod.rs:56-57, 141`) for embedding/bundle generation used in the signup's self-custody biometric material, i.e., it becomes part of the enrolled identity material despite the model signaling an error for that exact frame.

### Impact Explanation
This lets an errored/untrustworthy face-identifier validation result be treated as a "passing" liveness/face-image check for the frame bound as the self-custody candidate in a signup. If reachable (i.e., if the model or fusion path can genuinely emit `is_valid: Some(true)` together with `error: Some(_)`), it constitutes fail-open handling of a fraud/liveness signal, violating the stated invariant that errored model output must never be treated as passing, and could bind a bad/incorrectly-validated frame into the signup's self-custody bundle.

### Likelihood Explanation
Exploitability hinges entirely on whether the face_identifier Python model (or the underlying `PyO3`/`FromPyObject` deserialization path for `FIIsValidOutput`) can actually return `error: Some(_)` simultaneously with `is_valid: Some(true))`. From the reachable Rust code alone, the `iterate` function in `src/agents/python/face_identifier/mod.rs:190-197` converts any `PyErr` exception into `Output::Error(PyError)` — a completely separate output variant from `IsValidImage` — meaning a Python-level exception during `is_valid()` does not produce an `IsValidOutput` with `error: Some(_)` at all; it short-circuits to `Output::Error`. The `error` field inside `IsValidOutput`/`FIIsValidOutput` appears to be populated only by the Python model itself as a soft/non-fatal error value returned within a successful call, not from the Rust-level exception handling. Whether the Python model logic can set `is_valid=true` while also setting a non-null `error` is not verifiable from this Rust-only codebase (the Python model implementation is out of scope/not indexed here), so this cannot be confirmed as reachable purely from Rust code under attacker control (scene/QR/backend responses within a session). No attacker-controlled input path was found that forces `error` and `is_valid=true` to coexist within the Rust code visible.

### Recommendation
Regardless of whether the Python model can currently produce this state, defensively harden `handle_face_identifier` to require `output.error.is_none()` in addition to `output.is_valid.map_or(false, |v| v)` before accepting/storing `self_custody_candidate_rgb`, e.g.:
```rust
if output.error.is_none() && output.is_valid.map_or(false, |v| v) { ... }
```

### Proof of Concept
Unit test plan (would need to be added, e.g. in `src/plans/biometric_capture/mod.rs` tests):
1. Construct a `port::Output<face_identifier::Model>` with `value: face_identifier::Output::IsValidImage(IsValidOutput { is_valid: Some(true), error: Some(PyError::default_or_mock()), score: Some(0.9), ..Default::default() })`.
2. Call `Plan::handle_face_identifier` with an empty/default `Plan` state and a dummy `camera::rgb::Frame`.
3. Assert `plan.self_custody_candidate_rgb.is_none()` after the call — currently this assertion **fails** because the code stores the candidate as long as `is_valid == Some(true)` and the score condition holds, regardless of `error`.

**Caveat:** This finding is a defensive-gap/robustness issue in the Rust broker logic; I could not confirm from the available Rust/index context (Python model source not present) that an attacker can actually force the model to emit `is_valid: Some(true)` with `error: Some(_)` simultaneously, since Python-level exceptions are captured as a distinct `Output::Error` variant before ever reaching `IsValidOutput`. Treat this as a hardening recommendation rather than a confirmed exploitable path pending review of the Python face_identifier model source.

    fn handle_face_identifier(
        &mut self,
        orb: &mut Orb,
        output: port::Output<face_identifier::Model>,
        frame: Option<camera::rgb::Frame>,
    ) -> Result<BrokerFlow> {
        if let face_identifier::Output::IsValidImage(output) = output.value {
            tracing::debug!("Face self-custody frame score: {:?}", output.score);
            if output.error.is_some() {
                tracing::error!("Face self-custody frame error: {:?}", output);
            }

            if output.is_valid.map_or(false, |v| v) {
                let highest = self
                    .self_custody_candidate_rgb
                    .as_ref()
                    .map_or(0.0, |p| p.estimate.score.unwrap_or_default());
                if output.score.is_some_and(|s| s > highest) {
                    tracing::info!(
                        "New face self-custody frame captured with score: {:?}",
                        output.score
                    );
                    self.self_custody_candidate_rgb = Some(FrameInfoSelfCustodyCandidate::new(
                        output,
                        frame.expect("frame must be set for FaceIdentifier::IsValidImage"),
                    ));
                    self.face_ir = self.last_face_ir.take();
                    self.thermal = self.last_thermal.take();
                }

                orb.only_rgb_net_frames = true;
            }
        }
        Ok(BrokerFlow::Continue)
    }
