### Title
Attacker-controlled HyperSwap V2 pre-seed reserves can make `_noFeeSwapInput`'s `Math.mulDiv` overflow, permanently reverting `finalizeGraduation` and freezing all curve-raised LT and 250M reserved tokens - ([File: packages/contracts/src/Bonding.sol])

### Summary
`Bonding.finalizeGraduation` is the single, permissionless, non-repeatable exit from `Lifecycle.Graduating`. When it hits the hostile-pre-seed rebalance branch (`_seedRebalancing` → `_pairRebalance` → `_noFeeSwapInput`), it performs unchecked raw multiplication feeding `Math.mulDiv`, whose only guard against an out-of-range result is a `revert`. An attacker who pre-seeds the HyperSwap V2 TOKEN/LT pair with an extreme reserve ratio via `IUniswapV2Pair.mint` can drive that computation to overflow, causing `finalizeGraduation` to revert unconditionally for that token, with no retry path that changes the frozen inputs.

### Finding Description
`_prepareGraduationLiquidity` (called once, inline, during `_enterGraduating`) permanently caches `tokensForLP` and `ltFromPair` into `pendingGraduation[tokenAddress]` [1](#0-0) . These values, together with the pair's live reserves (which are attacker-writable prior to `finalizeGraduation` via a "mint pre-seed" — Regime 3, explicitly documented and handled in `_seedUniswapV2Direct`) [2](#0-1) , feed into `_seedRebalancing` → `_pairRebalance` → `_noFeeSwapInput`:

```solidity
uint256 product = Math.mulDiv(reserveIn * reserveOut, targetN, targetD);
uint256 newIn = Math.sqrt(product);
``` [3](#0-2) 

The developer's own natspec on this function acknowledges the risk: "Constructed adversarial inputs that violate this would `revert` rather than silently truncate, which is the correct failure mode." [4](#0-3)  This is exactly the pattern flagged in the external report — an arithmetic/conversion operation on attacker-influenceable input that panics/reverts instead of gracefully handling out-of-range values, except here the consequence is far more severe than a stateless canister crash: `finalizeGraduation` is the *only* code path that can move `Lifecycle.Graduating` to `Lifecycle.Graduated`, and it is not retryable with different inputs — `pendingGraduation` is deleted only on success [5](#0-4) . If the transaction always reverts for that token's frozen `(tokensForLP, ltFromPair)` pair against the attacker-fixed hostile reserves, the token is permanently stuck in `Lifecycle.Graduating`:
- `buy`/`sell` are blocked (`TokenIsGraduating`) [6](#0-5) .
- All curve-raised LT (already pulled out of the curve `Pair` via `Router.graduate` in `_prepareGraduationLiquidity`) and the full `LP_RESERVE` token allotment (250M tokens, 25% of supply) sit inertly inside `Bonding` with no rescue function.
- `LPLock.recordLock` — the only consumer that finalizes state — is unreachable.

### Impact Explanation
This freezes, indefinitely, all LT raised by every trader on that curve plus 250M reserved tokens, with no admin or user recovery mechanism (`Bonding` has no sweep/rescue function for a stuck `pendingGraduation` state, and `LPLock` also has no rescue path per its own documentation) [7](#0-6) . This is a permanent freezing of trader and protocol funds triggerable by a single unprivileged pre-seeder, satisfying the High-impact bar.

### Likelihood Explanation
The precondition — an attacker calling `IUniswapV2Pair.mint` on the not-yet-graduated TOKEN/LT pair with a self-chosen extreme reserve ratio — is explicitly enumerated as an in-scope, reachable attack surface ("pre-creating or pre-seeding the HyperSwap V2 TOKEN/LT pair before graduation") and is exactly the regime the code's own comments call out as a live threat model (Regime 3). Because `reserveIn`/`reserveOut` come straight from `getReserves()` (uint112, fully attacker-settable within that pre-seed) and `targetN`/`targetD` are fixed per-token, the arithmetic bound depends on the token's specific `tokensForLP`/`ltFromPair` ratio; whether every token's parameters admit an overflow-triggering pre-seed requires per-token numeric verification, which could not be fully completed here — this is the primary uncertainty in the analysis.

### Recommendation
Bound `_noFeeSwapInput`'s output defensively (e.g., clamp/short-circuit before calling `Math.mulDiv` if the operands are large enough to risk overflow, or catch and fall back to `_seedDirectMint`), so a `Math.mulDiv` revert can never brick `finalizeGraduation`. Since the fallback (`_seedDirectMint`) already exists and is exercised on the "too-small-to-rebalance" edge, symmetrically use it (or an equivalent try/catch) whenever the rebalance arithmetic would revert due to being too large, not just too small.

### Proof of Concept
1. `Zap.createToken` a token; let it trade to graduation (`triggerGraduation` or the threshold-crossing `buy`), fixing `pendingGraduation.tokensForLP` / `ltFromPair` at whatever the curve's final ratio was.
2. Before anyone calls `finalizeGraduation`, front-run with a self-funded `IUniswapV2Pair.mint` on the not-yet-existing/empty HyperSwap V2 TOKEN/LT pair (creatable permissionlessly via `Factory`/`_ensureUniswapV2Pair`), choosing token/LT amounts to maximize `reserveIn * reserveOut` relative to the token's fixed `targetN`/`targetD` so that `Math.mulDiv(reserveIn*reserveOut, targetN, targetD)` exceeds `type(uint256).max`.
3. Call `finalizeGraduation(tokenAddress)`; it reverts inside `_noFeeSwapInput` on every call (inputs are frozen), permanently trapping the parked LT/tokens in `Bonding` with no path to `Lifecycle.Graduated`.

Full numeric confirmation that realistic `(tokensForLP, ltFromPair)` values admit an overflow-triggering pre-seed within uint112 reserve bounds was not completed in this pass and should be validated with a Foundry PoC before treating this as fully proven.

    function finalizeGraduation(
        address tokenAddress
    ) external nonReentrant {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[tokenAddress];
        if (info.lifecycle != Lifecycle.Graduating) revert NotGraduating();

        address lt = info.ltAddress;
        PendingGraduation memory p = $.pendingGraduation[tokenAddress];

        // Anything in this contract beyond `p.ltFromPair` belongs to a
        // concurrent graduation on the same LT (Phase 1 transferred it
        // via `Router.graduate`) or to stray dust. Either way it is
        // off-limits to this graduation's deposit and sweep — see
        // `_routerDepositAndDispose` and `_sweepLTToOwner`.
        // Saturating subtract: a balance below `p.ltFromPair` shouldn't
        // be reachable in normal operation, but we keep finalize from
        // bricking on a Panic if any future code path or non-canonical
        // LT briefly violates the invariant.
        uint256 ltBalance = IERC20(lt).balanceOf(address(this));
        uint256 protectedLT = ltBalance > p.ltFromPair ? ltBalance - p.ltFromPair : 0;

        address lpPair = _ensureUniswapV2Pair(tokenAddress, lt);
        uint256 liquidity = _seedUniswapV2Direct(tokenAddress, lt, lpPair, p.tokensForLP, p.ltFromPair, protectedLT);

        _sweepLTToOwner(lt, protectedLT);

        info.lifecycle = Lifecycle.Graduated;
        $.graduatedPair[tokenAddress] = lpPair;
        delete $.pendingGraduation[tokenAddress];

        LPLock($.lpLock).recordLock(tokenAddress, lpPair, liquidity);

        emit TokenGraduated(tokenAddress, lpPair, liquidity, p.tokensForLP, p.lpBurned, p.unsoldBurned);
    }

    function _prepareGraduationLiquidity(
        address tokenAddress
    ) internal returns (uint256 tokensForLP, uint256 ltFromPair, uint256 lpBurned, uint256 unsoldBurned) {
        address pairAddr = _s().tokenInfo[tokenAddress].pair;
        (uint256 tokenReserve, uint256 assetReserve) = IPair(pairAddr).getReserves();

        unsoldBurned = IPair(pairAddr).tokenBalance();
        if (unsoldBurned > 0) {
            Token(tokenAddress).burn(pairAddr, unsoldBurned);
        }

        ltFromPair = assetReserve - _launchTimeVirtualLtReserve(tokenAddress, pairAddr);
        if (ltFromPair > 0) {
            _s().router.graduate(tokenAddress, ltFromPair);
        }

        tokensForLP = assetReserve == 0 ? 0 : (ltFromPair * tokenReserve) / assetReserve;
        if (tokensForLP > LP_RESERVE) tokensForLP = LP_RESERVE;

        lpBurned = LP_RESERVE - tokensForLP;
        if (lpBurned > 0) {
            Token(tokenAddress).burn(address(this), lpBurned);
        }
    }

    function _noFeeSwapInput(
        uint256 reserveIn,
        uint256 reserveOut,
        uint256 targetN,
        uint256 targetD,
        uint256 maxSwap
    ) internal pure returns (uint256) {
        if (reserveIn == 0 || reserveOut == 0 || targetN == 0 || targetD == 0 || maxSwap == 0) {
            return 0;
        }
        uint256 product = Math.mulDiv(reserveIn * reserveOut, targetN, targetD);
        uint256 newIn = Math.sqrt(product);
        if (newIn <= reserveIn) return 0;
        uint256 s = newIn - reserveIn;
        return s > maxSwap ? maxSwap : s;
    }
