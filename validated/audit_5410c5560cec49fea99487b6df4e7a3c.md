### Title
Stale pre-callback oracle prices permit an insolvent `multiply` after mid-route governance execution - (File: `contracts/controller/src/strategies/multiply.rs`)

### Summary
`multiply` caches all account, debt, collateral, and initial-payment prices before invoking the router. [1](#0-0)  The configured router can execute caller-selected venues, and an already-ready governance operation can be executed permissionlessly during that external call. [2](#0-1) [3](#0-2)  `Context::fetch_prices` retains previously cached prices rather than refreshing them, so the post-swap solvency check continues using the pre-callback oracle configuration. [4](#0-3) [5](#0-4) 

### Finding Description
The vulnerable sequence is `multiply -> prefetch_strategy_prices -> router.execute_strategy -> process_deposit -> strategy_finalize`. [1](#0-0) [6](#0-5)  `prefetch_strategy_prices` calls `cache.fetch_prices`, which only populates assets absent from `Context.token_prices`. [7](#0-6) [4](#0-3)  After the external router call, `calculate_account_risk_totals` calls `load_markets`, but that function also preserves existing cached prices and then reads them through `cached_price`. [8](#0-7) [9](#0-8)  Consequently, a route venue can execute a ready governance operation that changes the collateral oracle before returning output, while the controller values the received collateral using the superseded price. [3](#0-2) [4](#0-3) 

### Impact Explanation
An attacker can borrow pool assets, route them through an attacker-controlled venue, receive a small amount of collateral, and have that collateral valued at its pre-callback oracle price. If the mid-route governance operation replaces the collateral oracle with one returning the materially lower correct price, `require_post_pool_risk_gates` still validates LTV coverage and health factor using the stale high price. [10](#0-9)  The attacker-controlled venue keeps the borrowed assets, while the account retains debt exceeding the current value of its collateral, causing protocol bad debt and potential insolvency. [11](#0-10) 

For example, if cached collateral `C` is priced at 100 USD, debt asset `D` is priced at 1 USD, and LTV is 75%, the attacker can borrow 75 `D`, buy 1 `C` from the venue, and deposit that `C`. [12](#0-11)  If the route executes a ready `ConfigureAssetOracle` operation that changes `C`’s price to 1 USD, the final check still sees approximately 100 USD of collateral while a subsequent liquidation sees only 1 USD against 75 USD of debt. [5](#0-4) [13](#0-12) 

### Likelihood Explanation
The attacker needs a governance operation that changes a relevant oracle to already be executable and a router path that can trigger it during the strategy call. [3](#0-2)  Both conditions are reachable by an unprivileged account: ready governance operations can be executed without an executor identity, and strategy routes may invoke venues outside the lending contracts. [2](#0-1)  No leaked key, protocol privilege, oracle misreport, or controller reentry is required; the stale invocation-local cache is the root cause. [14](#0-13) [4](#0-3) 

### Recommendation
Refresh oracle prices after every external router or receiver boundary, immediately before depositing receipts and running `strategy_finalize`. [6](#0-5)  `Context` needs either a `refresh_prices` method that replaces cached `token_prices` or separate pre-callback and post-callback contexts so `load_markets` cannot silently reuse a superseded feed. [15](#0-14)  The post-callback risk calculation should use the oracle configuration and values current after the route, not merely values that were valid when the transaction began. [9](#0-8) 

### Proof of Concept
1. Governance has a ready `ConfigureAssetOracle` operation that changes collateral token `C` from the currently accepted 100 USD source to a 1 USD source. [3](#0-2) 
2. The attacker deploys a route venue that calls governance `execute` for that ready operation and then produces the route’s declared collateral output. [16](#0-15) 
3. The attacker calls `multiply(caller=attacker, account_id=0, spoke_id=S, collateral=C, debt_to_flash_loan=75_D, debt=D, mode=Multiply, swap=attacker_route, initial_payment=None, convert_swap=None)`. [17](#0-16) 
4. The controller caches `C = 100 USD` and `D = 1 USD` before router execution. [1](#0-0) [7](#0-6) 
5. The route executes the ready oracle operation, pays 1 `C` to the controller, and sends the remaining borrowed `D` value to the attacker-controlled venue. [2](#0-1) 
6. The controller deposits the measured `C` receipt and finalizes using the cached 100 USD price, so the 75 USD debt passes LTV and health-factor checks. [18](#0-17) [5](#0-4) 
7. The next invocation creates a fresh `Context`, fetches the new 1 USD oracle value, and reports the account as deeply insolvent, leaving approximately 74 USD of bad debt after collateral recovery. [19](#0-18) [13](#0-12)

    /// Fetches missing prices in one aggregator call; retains cached prices.
    pub(crate) fn fetch_prices(&mut self, assets: &Vec<Address>) {
        let missing = collect_uncached_keys(&self.env, assets, &self.token_prices);
        if missing.is_empty() {
            return;
        }
        let fetched = external::price_aggregator::fetch_prices(&self.env, &missing);
