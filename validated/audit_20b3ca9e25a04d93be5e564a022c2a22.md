Audit Report

## Title
OIDC callback trusts unverified `email` claim to create authenticated sessions with attacker-controlled identity - ([File: core/sessions/oidcauth/oidc.go])

## Summary
`handleTokenExchange` in `core/sessions/oidcauth/oidc.go` extracts the `email` claim from a verified ID token and uses it, without any `email_verified` check, as the sole identity key for a newly created, fully authenticated session. [1](#0-0)  A full-repo search confirms there is no `email_verified` check anywhere in the codebase, so any IdP configuration that permits an unverified or user-editable `email` claim allows a Chainlink session to be created and bound to an arbitrary email address.

## Finding Description
After the ID token signature is verified via `oi.provider.Verifier(oi.oidcConfig).Verify(ctx, rawIDToken)`, the code parses claims and pulls `email` directly with a type assertion, with no check of an `email_verified` field: [2](#0-1)  This raw email is then persisted verbatim (lower-cased) as the session's identity key, paired with a role computed independently from the group/claims list (`idClaims`) present in the same token: [3](#0-2)  Downstream, every session lookup (`AuthorizedUserWithSession`), session cleanup (`ClearNonCurrentSessions`), and audit log entry (`AuthLoginSuccessNo2FA`) is keyed exclusively on this `user_email` value: [4](#0-3) [5](#0-4)  There is no secondary binding to a stable, IdP-issued `sub` claim, and no correlation against a pre-existing local `users` record for OIDC-authenticated identities (that path — `SQLSelectUserbyEmail` — is used only in `FindUser`/`localLoginFallback`, not in the OIDC token-exchange flow). This is the same root-cause pattern as CVE-2022-31107 (Grafana generic-OAuth account takeover): a relying party trusting an IdP-returned `email` attribute as an identity anchor without confirming it was verified.

## Impact Explanation
Because `oidc_sessions` rows and audit entries are keyed purely by whatever `email` string is present in the token — with the role separately derived from the same token's group claims — an authenticated principal at an IdP that does not enforce/require `email_verified=true` (a documented and common OIDC integration pitfall, e.g., some self-hosted/generic providers or custom claim mappings) can cause Chainlink to create a session/audit trail tagged with an arbitrary (e.g., victim's) email while the role reflects the attacker's own group memberships. This produces cross-user identity corruption in the audit log and session table, and via `ClearNonCurrentSessions` (keyed by `lower(user_email)`), an attacker holding a session under a victim's spoofed email can terminate the real session(s) of that email — an in-scope authentication/identity-integrity impact (node API authentication/identity bypass).

## Likelihood Explanation
Exploitability is gated on the deployment's OIDC Identity Provider configuration: it is only exploitable when the configured IdP allows an authenticated user to have (or set) an `email` claim that is not verified/immutably bound to their own account — which is a real-world, non-default but recognized IdP misconfiguration class, not a Chainlink node operator/admin misconfiguration. Chainlink itself provides zero defense-in-depth against this scenario (no `email_verified` check, no `sub`-based binding), unlike well-hardened OIDC relying-party implementations. The attacker only needs the ability to authenticate to the upstream IdP — no Chainlink-side credentials, no admin/operator access.

## Recommendation
- Require and enforce the `email_verified` claim (reject if `false` or absent) before using `email` as session identity.
- Bind `oidc_sessions`/`oidc_user_api_tokens` rows to the immutable `sub` claim rather than (or in addition to) `email`, treating `email` as a display-only attribute.
- Optionally require correlation with a pre-provisioned local identity before granting a session.

## Proof of Concept
1. Stand up (or point Chainlink at) an OIDC IdP that issues ID tokens with a user-controllable/unverified `email` claim (no `email_verified: true` requirement) and configure Chainlink's OIDC provider (`ProviderURL`, `AdminClaim`/etc.) accordingly.
2. As an attacker account on that IdP, complete `/oidc-login` → `/oidc-exchange`, presenting an ID token with `email` set to a victim's known address and whose group claims satisfy `IDClaimsToUserRole`.
3. Observe `handleTokenExchange` insert a new `oidc_sessions` row with `user_email` = victim's email and a role derived from the attacker's own group claims, confirmed via `core/sessions/oidcauth/oidc.go:250-260`.
4. Confirm `AuthorizedUserWithSession` returns the victim's email for the attacker's session cookie, and that calling `ClearNonCurrentSessions` with this session ID deletes any other `oidc_sessions` rows sharing that email (i.e., the victim's legitimate sessions), per `core/sessions/oidcauth/oidc.go:441-449`.

// AuthorizedUserWithSession will return the API user associated with the Session ID if it
// exists and hasn't expired
func (oi *oidcAuthenticator) AuthorizedUserWithSession(ctx context.Context, sessionID string) (clsessions.User, error) {
	if len(sessionID) == 0 {
		return clsessions.User{}, errors.New("session ID cannot be empty")
	}
	var foundUser clsessions.User
	err := sqlutil.TransactDataSource(ctx, oi.ds, nil, func(tx sqlutil.DataSource) error {
		// Query the oidc_sessions table for given session ID, user role and email are saved after the id claims is provided and validated
		var foundSession struct {
			UserEmail string
			UserRole  clsessions.UserRole
			Valid     bool
		}
		if err := tx.GetContext(ctx, &foundSession,
			"SELECT user_email, user_role, created_at + $2 >= now() as valid FROM oidc_sessions WHERE id = $1",
			sessionID, oi.config.SessionTimeout().Duration(),
		); err != nil {
			if errors.Is(err, sql.ErrNoRows) {
				return clsessions.ErrUserSessionExpired
			}
			return err
		}
		if !foundSession.Valid {
			// Sessions expired, purge
			return clsessions.ErrUserSessionExpired
		}
		foundUser = clsessions.User{
			Email: foundSession.UserEmail,
			Role:  foundSession.UserRole,
		}
		return nil
	})
	if err != nil {
		if errors.Is(err, clsessions.ErrUserSessionExpired) {
			if _, execErr := oi.ds.ExecContext(ctx, "DELETE FROM oidc_sessions WHERE id = $1", sessionID); execErr != nil {
				oi.lggr.Errorf("error purging stale OIDC session: %v", execErr)
			}
		}
		return clsessions.User{}, err
	}
	return foundUser, nil
}

// ClearNonCurrentSessions removes other oidc_sessions for the user tied to sessionID.
func (oi *oidcAuthenticator) ClearNonCurrentSessions(ctx context.Context, sessionID string) error {
	var email string
	if err := oi.ds.GetContext(ctx, &email, "SELECT user_email FROM oidc_sessions WHERE id = $1", sessionID); err != nil {
		return err
	}
	_, err := oi.ds.ExecContext(ctx, "DELETE FROM oidc_sessions WHERE lower(user_email) = lower($1) AND id != $2", email, sessionID)
	return err
}
