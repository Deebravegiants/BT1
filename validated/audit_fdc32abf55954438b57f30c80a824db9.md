### Title
Emporium "Min" proof path lets any unprivileged caller drain Emporium's held token/ETH balances via unauthenticated self-calls - (File: contracts/CircomDataBuilder.sol, contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol)

### Summary
When `externalActionData.externalActionId == HINKAL_EMPORIUM_ACTION_ID` and `erc20TokenAddresses.length == 0`, `formInputForCircom` routes to `formInputEmporiumMin`, which only feeds `MainEVMCircuitMin` — a circuit that proves nothing except `message == Poseidon(messageSeed)`. Combined with `EmporiumUpgradeable.runAction`'s `signerAddress == address(0)` branch, which skips ECDSA verification entirely and runs `stack.ops` as direct self-calls from Emporium's own identity, an attacker can invoke arbitrary calls (e.g. `ERC20.transfer(attacker, balance)`) against any token Emporium holds, with zero proof of fund ownership and zero balance accounting (since the accounting loops iterate the empty `erc20TokenAddresses` array).

### Finding Description
The broken equality is: *assets Emporium can move in a transaction* == *assets accounted for in `balancesBefore`/`balancesAfter`*.

Path:
1. `Hinkal.transact` → `hinkalHelper.performHinkalChecks` → `CircomDataBuilder.formInputForCircom` (`contracts/CircomDataBuilder.sol:134-148`). Since `externalActionId == HINKAL_EMPORIUM_ACTION_ID` and `erc20TokenAddresses.length == 0`, it calls `formInputEmporiumMin` [1](#0-0) , which produces only 3 public signals: `emporiumMessage`, `timeStamp`, `calldataHash`.
2. `dimensionsCheck` (`contracts/HinkalHelper.sol:64-90`) permits `tokenNumber == 0`, so no lower bound blocks this path, and no nullifiers/UTXOs are required.
3. The corresponding circuit is `MainEVMCircuitMin`, which only proves `message <== Poseidon(1)([messageSeed])` [2](#0-1) . There is no signature check, no Merkle inclusion proof, no nullifier, no ownership tie to any UTXO. Anyone can compute `messageSeed` and its Poseidon hash themselves and generate a valid Groth16 proof for this trivial circuit.
4. `Hinkal.transact` proceeds; `_externalTransact` builds `deltaAmountChanges` over `erc20TokenAddresses` (empty), so nothing is transferred to Emporium and nothing is checked [3](#0-2) . It then calls `EmporiumUpgradeable.runAction` with an attacker-supplied `EmporiumStack` decoded from `externalActionData.externalActionMetadata`, which is not constrained by the Min circuit at all.
5. In `EmporiumUpgradeable.runAction` [4](#0-3) , `balancesBefore`/`balancesAfter` are computed only over `circomData.erc20TokenAddresses` (empty). `verifyWallet` returns immediately without any signature check when `stack.signerAddress == address(0)` [5](#0-4) . With `signerAddress == 0`, every op falls into "CASE 2: Stateless Interaction," where Emporium itself calls `op.endpoint.call{value: op.value}(op.callData)` directly, using Emporium's own balance/allowance [6](#0-5) .
6. Back in `Hinkal.transact`, the post-action balance/slippage/UTXO-accounting loop also iterates `circomData.erc20TokenAddresses` (empty), so it never observes or reverts on token movements outside that (empty) list [7](#0-6) .

Net effect: the attacker supplies an `EmporiumStack` with `signerAddress == 0` and an `ops` array (chained, up to the array size limits imposed only by gas/ABI) that calls arbitrary ERC20 tokens' `transfer` function (or sends raw ETH) from Emporium's address to the attacker, for every token Emporium happens to be holding at call time (e.g. dust/fees left over from prior transactions, or in-flight balances of tokens moved into Emporium mid multi-step flow). No proof of ownership, no signature, and no balance/UTXO accounting check catches this, because all of the guarding logic (`dimensionsCheck`, balance-diff loops, `verifyWallet`) is either bypassed by the empty-token-array Min path or explicitly skipped for `signerAddress == 0`.

### Impact Explanation
Direct theft of any ERC20/ETH balance sitting in the Emporium contract at the time of the attack, callable by any unprivileged address with a trivially generated proof and zero cost beyond gas. This is repeatable every time Emporium accumulates a balance (e.g., legitimate users routing funds through Emporium mid-transaction, dust, unclaimed fees). This matches Critical: "direct theft of shielded or in-flight user funds" / "executing calls or moving assets... never authorised."

### Likelihood Explanation
Preconditions: Emporium contract must hold some balance (ERC20 or ETH) at the time of attack — plausible given normal flows route withdrawn funds through Emporium before/while executing external ops, and dust/leftover fee balances accumulate over time. The attacker needs no special role, no owned UTXOs, no signature — only the ability to generate a proof for the trivial `MainEVMCircuitMin` circuit (self-chosen `messageSeed`) and construct calldata. This is fully within the described "unprivileged attacker" capabilities and requires no race condition beyond timing the attack when Emporium holds a non-zero balance.

### Recommendation
Do not allow the Emporium-Min proof path to authorize arbitrary op execution with `signerAddress == 0`. Specifically:
- Require `stack.signerAddress != address(0)` (i.e., enforce signature verification) whenever `erc20TokenAddresses.length == 0` / the Min proof path is used, since the Min circuit provides no ownership guarantee.
- Alternatively, disallow the Min circuit path entirely when `externalActionMetadata` encodes non-empty `ops`, or require the balance-accounting loop in `EmporiumUpgradeable.runAction` to snapshot/verify balances of every token touched by `stack.ops` (not just `circomData.erc20TokenAddresses`), reverting on any net balance decrease that isn't attributable to the caller's own deposit.
- Add an explicit invariant check that Emporium's aggregate balance (across all tokens touched by the ops) does not decrease beyond what `deltaAmountChanges` accounts for.

### Proof of Concept
Foundry test plan:
1. Deploy `Hinkal`, `HinkalHelper`, `EmporiumUpgradeable`, register `HINKAL_EMPORIUM_ACTION_ID -> Emporium`, register the `mainEVMCircuitMin0v4` verifier for the `tokenNumber=0` verifier ID via `buildVerifierId`.
2. Fund Emporium directly with e.g. 1000 USDC (simulating parked/dust balance) via `deal`/`transfer`.
3. Attacker (EOA with no UTXOs, no relay role) generates a real Groth16 proof for `MainEVMCircuitMin` with self-chosen `messageSeed`, computing `emporiumMessage = Poseidon(messageSeed)` off-chain (snarkjs), and sets `timeStamp`, `calldataHash` consistently with `getHashedCalldata`.
4. Construct `CircomData` with `erc20TokenAddresses = []`, `amountChanges = []`, `inputNullifiers = []`, `outCommitments = []`, `dimensions.tokenNumber = 0`, `externalActionData.externalActionId = HINKAL_EMPORIUM_ACTION_ID`, `externalActionData.externalAddress = Emporium`, and `externalActionMetadata = abi.encode(EmporiumStack({signerAddress: address(0), ops: [EmporiumOperation({endpoint: USDC, invokeWallet: false, value: 0, callData: abi.encodeCall(IERC20.transfer, (attacker, 1000e6))})], ...}))`.
5. Call `Hinkal.transact(a,b,c,dimensions,circomData)` from attacker.
6. Assert: before call `USDC.balanceOf(Emporium) == 1000e6`, `USDC.balanceOf(attacker) == 0`; after call `USDC.balanceOf(Emporium) == 0`, `USDC.balanceOf(attacker) == 1000e6`, and the transaction did not revert — proving the equality "assets moved == assets accounted for in balancesBefore/balancesAfter" is violated (accounted amount is 0, actual drained amount is 1000e6).

        CircomData calldata circomData,
        int256[] calldata deltaAmountChanges
    ) external override onlyAllowedRecipient returns (UTXO[] memory) {

            circomData.externalActionData.externalActionMetadata,
            (EmporiumStack)
        );

        uint256[] memory balancesBefore = getBalancesForArray(
            circomData.erc20TokenAddresses
        );

        verifyWallet(stack, circomData);

        for (uint256 i = 0; i < stack.ops.length; i++) {
            EmporiumOperation memory op = stack.ops[i];

            bool success;
            bytes memory err;

            // CASE 1: Stateful Interaction
            if (op.invokeWallet && stack.signerAddress != address(0)) {
                (success, err) = IHinkalWallet(stack.signerAddress)
                    .callHinkalWallet(op.endpoint, op.callData, op.value);
            }
            // CASE 2: Stateless Interaction
            else {
                bytes4 selector = bytes4(op.callData);
                if (
                    selector == IHinkalWallet.callHinkalWallet.selector ||
                    selector == IHinkalWallet.doSendToRelay.selector
                ) {
                    revert UnauthorizedWalletCall();
                }

                (success, err) = op.endpoint.call{value: op.value}(op.callData);
            }

            if (!success) {
                revert CallFailed(err);
            }
        }
