**Rationale:**

The behavior described—`serialize_internal`'s curve branch calling `element.into_affine()` and correctly emitting the identity/point-at-infinity encoding for the zero element—is standard, well-defined, and explicitly documented arkworks-compatible serialization behavior, not a flaw. This is confirmed by the module's own documentation, which specifies the infinity-bit encoding procedure for both BLS12-381 and BN254 formats, and by test vectors that assert `serialize<G1, FormatG1Compr>(&point_at_infinity)` deterministically equals a fixed constant. [1](#0-0) [2](#0-1) 

The claimed custody impact requires "custody-relevant Move code that assumes non-identity outputs" and performs a "naive equality-based authorization check" treating the identity encoding as a wildcard. No such code exists in the Aptos framework. To the contrary, the one production module that models cryptographic public keys as a distinguished type (`bls12381::PublicKey`) explicitly documents and enforces that a valid public key "is NOT the identity point," and the corresponding native `validate_pubkey_internal` performs this exact check before any key is trusted for authorization. [3](#0-2) [4](#0-3) 

The generic `crypto_algebra`/`bls12381_algebra`/`bn254_algebra` natives (including `serialize_internal` in `aptos-move/framework/natives/src/cryptography/algebra/serialization.rs`) are low-level, general-purpose elliptic-curve arithmetic primitives with no custody semantics of their own; identity elements are valid group elements and their round-trip serialization is required for correctness (e.g., pairing checks, MSM accumulation in Groth16 verification via `eq`/`multi_pairing`). [5](#0-4) 
The only production custody-adjacent consumer found (`keyless_account.move`'s Groth16 verification-key validation) only checks that deserialization succeeds (`is_some()`), never performs an equality-based identity-as-wildcard check. [6](#0-5) 

Since the hypothesized downstream "naive equality-based authorization check" does not exist in the reviewed codebase, and the one place that models trusted public keys explicitly rejects identity points, this finding does not cross a real custody boundary and is speculative rather than grounded in actual code.
