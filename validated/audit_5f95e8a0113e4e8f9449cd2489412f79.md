## Analysis

The strongest analog to the SPARTAN `getPoolShareWeight` flash-loan bug is in the phantom-order price aggregation path used by Hyperbridge's Intent Gateway pricing pipeline.

### Title
Flash-loan-inflatable on-chain balance weighting lets a solver set the published phantom-order price and pool rate - (File: `sdk/packages/sdk/src/protocols/intents/phantom-aggregation.ts`)

### Summary
`aggregatePhantomBids` weights each solver's quote in a phantom order's price snapshot by a live `eth_call` read of that solver's ERC-20/vault/Uniswap-V4 balance on the destination chain, taken at the `"latest"` block. That weighted-median price is written into `LiquidityPool.sellRate`/`buyRate`, which `IntentGateway.quoteIntent`'s default `indexed_rates` strategy uses to price real user orders. Exactly like SPARTAN's `getPoolShareWeight`, a spot on-chain balance is used as a governance-like weight (here, price-setting power) with no time-delay or manipulation resistance, so a solver can temporarily inflate its balance to dominate the weighted median and set the published market price.

### Finding Description
The weight of a phantom bid's quote is computed directly from a spot balance read: [1](#0-0) 

That balance itself comes from `getTotalSolverBalance`, an `eth_call` pinned to `"latest"` unless a specific block is supplied: [2](#0-1) 

The per-leg price is then a **selection**, not an average: `weightedMedian` picks one bidder's exact quote, and the documentation explicitly notes that a solver controlling more than half a leg's weight sets the published price verbatim: [3](#0-2) 

The resulting median feeds `LiquidityPool.sellRate`/`buyRate` via `updateLiquidityPools`/`resolvePoolLeg`: [4](#0-3) 

and those rates are the **default** pricing source for real intent orders placed through the SDK: [5](#0-4) [6](#0-5) 

This is structurally identical to the SPARTAN bug: an unprivileged actor's on-chain token balance, read at a single point in time with no cooldown, delay, or TWAP, is used directly as an influence weight over a protocol-critical value (there: DAO voting/reward weight; here: the published market price real users' orders are quoted against).

### Impact Explanation
A solver can temporarily inflate its ERC-20/vault balance of a leg's output token (e.g., via a flash loan or short-term borrow) so that, at the moment the indexer's RPC call reads `"latest"` balance for that (chain, token, solver), it dominates the leg's weight. Since `weightedMedian` is a selection, this lets the solver:
- Set the leg's `medianPrice` to its own quoted price verbatim, regardless of what other, honestly-funded solvers quoted.
- Push that manipulated price into the pool's `sellRate`/`buyRate`, which is the default source `quoteIntent` uses to construct real orders' `amountIn`/`amountOut`.
- Simultaneously inflate `PoolBidder.liquidity`/pool depth figures, misrepresenting available liquidity to takers deciding on routing/sizing.

Because the manipulated rate directly determines the raw amounts of real cross-chain intent orders (funds actually escrowed and paid out), this can result in concrete mispricing/value extraction against users relying on the default indexed-rate quote path — not merely a cosmetic indexing error.

### Likelihood Explanation
Exploitation requires the attacker (a permissionless solver) to inflate its balance for the (possibly brief but non-atomic) window between window closure and the indexer's RPC read, since a flash loan must be repaid within one transaction/block while the indexer poll may run later. This makes a pure atomic flash loan harder to time precisely against the exact `"latest"` block read, but a short-duration borrow (not necessarily atomic) held across the relevant blocks is sufficient and inexpensive, and the attacker fully controls when it submits its own bid relative to window closure. No permission or governance role is needed — any solver with a delegated `SolverAccount` can attempt this.

### Recommendation
- Do not weight (or gate) quotes purely by an instantaneous spot balance read at `"latest"`. Require the balance to be sustained over a minimum window (e.g., average/min balance over N blocks) before it counts toward `weightedMedian` weight, mirroring the report's suggested mitigation of delaying the effect of a changed balance.
- Consider capping any single solver's contribution to a leg's weight (e.g., a maximum weight share) so no bidder can unilaterally set `medianPrice`.
- Cross-check the phantom snapshot price against an independent oracle/reference price before it is allowed to update `LiquidityPool.sellRate`/`buyRate`, rejecting outlier updates.

### Proof of Concept
1. Attacker controls a delegated `SolverAccount` and monitors for an upcoming `PhantomBidWindowExhausted` event on a chosen (tokenA, tokenB) phantom order.
2. Shortly before/at window close, attacker borrows a large amount of the leg's output token on the destination chain into its solver EOA (a lending-protocol loan held across a few blocks is enough since the read is not synchronous with window close).
3. Attacker submits a phantom bid quoting an extreme (attacker-favorable) price for the leg.
4. `aggregatePhantomBids` reads the attacker's inflated balance via `getTotalSolverBalance`/`ethCallUint` at `"latest"`, giving the attacker's quote outsized (potentially majority) weight in `weightedMedian`.
5. The attacker's quote becomes the leg's `medianPrice`, which is renormalized into `LiquidityPool.sellRate`/`buyRate`.
6. Attacker repays the loan.
7. Any user calling `quoteIntent` with the default `indexed_rates` strategy for that pair is now quoted the manipulated rate, and any order constructed from it moves real funds at the attacker-favorable price.

export async function getTotalSolverBalance(
	evmRpcUrl: string,
	chain: string,
	token: string,
	solver: string,
	yieldVaults: YieldVaultMap,
	blockTag = "latest",
): Promise<bigint> {
	const padded = solver.replace("0x", "").padStart(64, "0")
	const raw = await ethCallUint(evmRpcUrl, token, `0x70a08231${padded}`, blockTag) // balanceOf(address)
	const vaults = yieldVaults[chain]?.[token.toLowerCase()] ?? []
	const vaultBalances = await Promise.all(
		vaults.map((v) => ethCallUint(evmRpcUrl, v, `0xce96cb77${padded}`, blockTag)), // maxWithdraw(address)
	)
	return vaultBalances.reduce((acc, b) => acc + b, raw)

/** Quotes raw token amounts from the indexer's aggregate directional pool rates. */
export class IndexedRateIntentQuoteStrategy implements IntentQuoteStrategyHandler {
	constructor(
		private readonly chainConfigService: ChainConfigService,
		private readonly getQueryClient: () => IndexerQueryClient,
	) {}

	async quote(
		params: QuoteIntentParams,
		source: IntentQuoteChainContext,
		destination: IntentQuoteChainContext,
	): Promise<IndexedRateQuoteIntentResult> {
		validateQuoteParams(params)
		const sourceConfig = getConfigByStateMachineId(source.stateMachineId)
		const destinationConfig = getConfigByStateMachineId(destination.stateMachineId)
		if (!sourceConfig) throw new UnsupportedLiquidityChainError(source.stateMachineId)
		if (!destinationConfig) throw new UnsupportedLiquidityChainError(destination.stateMachineId)

		const tokenIn = this.resolveAsset(sourceConfig.stateMachineId, params.tokenIn)
		const tokenOut = this.resolveAsset(destinationConfig.stateMachineId, params.tokenOut)
		const [protocolFeeBps, rates] = await Promise.all([
			readProtocolFeeBps(this.chainConfigService, source),
			new LiquidityEngine(this.getQueryClient()).getBuyAndSellRates({
				sourceChain: sourceConfig.stateMachineId,
				destinationChain: destinationConfig.stateMachineId,
				tokenInSymbol: tokenIn.symbol,
				tokenOutSymbol: tokenOut.symbol,
			}),
		])
		if (!rates) {
			throw new IndexedRateUnavailableError({
				source: sourceConfig.stateMachineId,
				destination: destinationConfig.stateMachineId,
				tokenIn: tokenIn.symbol,
				tokenOut: tokenOut.symbol,
			})
		}

		const selectedRate = selectIndexedRate(rates, tokenIn.symbol, tokenOut.symbol)
		return quoteWithIndexedRate(params, tokenIn, tokenOut, selectedRate, rates, protocolFeeBps)
