### Title
Accrued debt value can overflow before the borrow-index cap and permanently freeze a market - (File: `common/src/rates/simulate.rs`)

### Summary
Every market mutation synchronizes interest before changing state, and `accrue_step` first converts aggregate scaled debt and supply into unscaled RAY values using `scaled * index`. [1](#0-0) [2](#0-1)  `scaled_to_original` performs an overflowing `Ray` multiplication when `scaled * index` no longer fits in `i128`, while the separate borrow-index cap is applied only afterward by `update_borrow_index`. [3](#0-2) [4](#0-3)  Consequently, a very large high-utilization market can reach an unrepresentable debt or supply value while the stored index is still below `MAX_BORROW_INDEX_RAY`, after which every operation that accrues that market reverts. [5](#0-4) 

### Finding Description
The affected path is `Controller::{supply, borrow, withdraw, repay, liquidate, clean_bad_debt, flash_loan, flash_position, multiply, swap_debt, swap_collateral, repay_debt_with_collateral, migrate_from_blend, update_indexes, claim_revenue, recapitalize}` when it touches an affected `(hub_id, asset)` market, because the pool runs `global_sync` before each market mutation. [6](#0-5) [7](#0-6)  During synchronization, `global_sync` calls `accrue_chunk`, which calls `accrue_step`; the first two arithmetic statements unscale `cache.borrowed()` and `cache.supplied()` using the previously stored indexes. [8](#0-7) [9](#0-8)  `scaled_to_original` uses `Ray::mul`, whose checked fixed-point multiplication panics with `MathOverflow` when the product or result exceeds `i128`. [3](#0-2) [10](#0-9) 

The intended `10^36` borrow-index ceiling does not prevent this condition because `update_borrow_index` is invoked only after both aggregate positions have already been unscaled. [11](#0-10) [12](#0-11)  The harness reproduces the state with a one-billion-token, 18-decimal market at 98% utilization on the steep curve and confirms that `update_indexes`, `withdraw`, and `repay` all fail with `MathOverflow` while `borrow_index < MAX_BORROW_INDEX_RAY`. [13](#0-12) 

### Impact Explanation
Once either aggregate scaled position crosses the representable-value boundary, the market cannot complete accrual, so repayments, withdrawals, liquidations, bad-debt cleanup, index updates, and later supply or borrow attempts touching that market all revert. [1](#0-0) [14](#0-13)  Because indexes are monotone and time does not reduce the stored scaled balances, ordinary calls cannot restore a representable value; supplier principal, borrower collateral, and unclaimed revenue in that market remain permanently frozen absent an upgrade. [15](#0-14) [16](#0-15) 

### Likelihood Explanation
The trigger is reachable by unprivileged `supply` and `borrow` calls: an attacker or ordinary whale creates an account, supplies the large asset, supplies sufficient collateral, borrows most of that market, and then simply leaves the position untouched until interest raises the aggregate value past `i128::MAX`. [17](#0-16) [18](#0-17)  It is not an instant or low-cost denial of service: it requires an admitted high-decimals market, caps permitting an aggregate position near the RAY domain limit, substantial capital or borrowed exposure, and sustained high utilization while interest compounds. [19](#0-18) [20](#0-19)  The condition is nonetheless protocol-reachable and has already been exercised by the in-repository harness, making it a practical long-lived-market failure rather than a malformed-input crash. [13](#0-12) 

### Recommendation
Enforce a market-specific representable-value ceiling before storing an updated index. [21](#0-20)  For each accrual step, cap `borrow_index` at approximately `floor(i128::MAX / borrowed_scaled)` and `supply_index` at approximately `floor(i128::MAX / supplied_scaled)`, in addition to the protocol-wide index caps, so every subsequent `scaled_to_original` and reward calculation remains in range. [12](#0-11) [3](#0-2)  Alternatively, widen the aggregate unscaled-value, utilization, reward, and shortfall calculations to `I256` and only narrow persisted asset-unit results after explicit bounds checks. [22](#0-21) [23](#0-22)  Add a regression test proving that the maximum admitted scaled aggregate can accrue to its derived index ceiling without `MathOverflow` and that `repay`, `withdraw`, `liquidate`, and `update_indexes` remain usable at the boundary. [13](#0-12) 

### Proof of Concept
```text
Preconditions:
- Governance has listed an 18-decimal asset BIG18 with the steep rate curve and
  caps large enough for roughly 1e27 raw units.
- A second collateral market COL is listed.

1. Supplier calls:
   supply(caller=S, account_id=0, spoke_id=1,
          assets=[(HubAssetKey { hub_id: 0, asset: BIG18 }, 1e27)])
   This creates supply shares for 1,000,000,000 whole BIG18.

2. Borrower calls:
   supply(caller=B, account_id=0, spoke_id=1,
          assets=[(HubAssetKey { hub_id: 0, asset: COL }, sufficient_collateral)])
   borrow(caller=B, account_id=b_id,
          borrows=[(HubAssetKey { hub_id: 0, asset: BIG18 }, 9.8e26)],
          to=None)

3. Leave utilization near 98% while annual index accrual compounds until:
   borrowed_scaled * borrow_index > i128::MAX
   and borrow_index remains below 1e36.

4. Any user then calls:
   update_indexes([HubAssetKey { hub_id: 0, asset: BIG18 }])

5. The call reverts inside accrue_step -> scaled_to_original before
   update_borrow_index can clamp the index.

6. Subsequent calls such as:
   repay(caller=B, account_id=b_id,
         payments=[(HubAssetKey { hub_id: 0, asset: BIG18 }, 1)])
   withdraw(caller=S, account_id=s_id,
            withdrawals=[(HubAssetKey { hub_id: 0, asset: BIG18 }, 1)],
            to=None)
   also revert with MathOverflow because each performs global_sync first.
```

The repository test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` implements this scenario, reaches `MathOverflow` from `update_indexes`, and confirms that both withdrawal and repayment remain blocked. [13](#0-12)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);

/// Computes `x * y / d` rounded half up. Requires `x >= 0`, `y >= 0`, and `d > 0`; a
/// `debug_assert` checks this in debug builds. Panics with `GenericError::DivisionByZero` if
/// `d == 0`, and with `GenericError::MathOverflow` if any other precondition is violated or if
/// the result does not fit in `i128`.
pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    // The zero check runs first so debug and release builds agree on a zero
    // divisor: both surface `DivisionByZero` rather than tripping the assert.
    require_nonzero_divisor(env, d);
    debug_assert!(
        x >= 0 && y >= 0 && d > 0,
        "mul_div_half_up: non-negative x, y and positive d"
    );
    try_mul_div_half_up(env, x, y, d)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
}

## Indexes and accrual

<a id="inv-idx-01"></a>

### INV-IDX-01 — Borrow index is monotone and bounded

Both indexes start at one RAY. Successful accrual with validated rate parameters
cannot lower the borrow index and caps it at the protocol constant 10^36 raw
RAY. At the ceiling, further accrual produces no borrower interest.

Debt-value overflow can still revert accrual before that ceiling is reached.
Bounded indexes do not guarantee representable position or market values.
