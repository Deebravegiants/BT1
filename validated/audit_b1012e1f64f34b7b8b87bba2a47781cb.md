Audit Report

## Title
CORS origin allowlist bypass via unanchored suffix matching enables disallowed-domain access to the Gateway HTTP server - (File: core/services/gateway/network/httpserver.go)

## Summary
`httpServer.isAllowedOrigin` validates wildcard CORS entries (e.g. `https://*.ethereum.org`) using `strings.HasSuffix(originHost, allowedHost)` after stripping the `*.` prefix, with no domain-label boundary check. Any origin host that byte-for-byte ends with the trusted suffix (e.g. `evilethereum.org`) satisfies the check even though it is not a subdomain of the allowlisted domain, causing the Gateway to reflect the malicious `Origin` and grant it full CORS access.

## Finding Description
In `isAllowedOrigin`, wildcard matching strips the `*.` prefix from the allowed host and then only checks `strings.HasSuffix(originHost, allowedHost)`, confirmed at [1](#0-0) . This has no requirement that the matched suffix be preceded by a `.` (domain-label boundary) or otherwise be a proper subdomain, so `evilethereum.org` passes the suffix check against allowed host `ethereum.org` just as legitimately as `remix.ethereum.org` does.

In `handleRequest`, once `isAllowedOrigin` returns true, the raw attacker-supplied `Origin` header is reflected directly into `Access-Control-Allow-Origin`, along with `Access-Control-Allow-Methods` and `Access-Control-Allow-Headers`, confirmed at [3](#0-2) . There is no further normalization, boundary check, or allowlist re-verification downstream.

The scheme and port are pre-filtered exactly via `originScheme != allowedScheme` and `originPort != allowedPort` before the host comparison, confirmed at [4](#0-3) , so those checks do not mitigate the host-boundary flaw.

The existing test suite validates the intended wildcard-match behavior (`remix.ethereum.org`, `another.valid.domain.com`, `example.gov`) and rejects scheme/port mismatches and genuinely unrelated domains like `ethereum.remix.org`, confirmed at [5](#0-4) , but it never exercises the adjacent-prefix bypass case (a domain that merely ends with the same characters, like `evilethereum.org`), so this gap was not caught by the shipped tests.

## Impact Explanation
An attacker who registers or controls any domain ending in the same character sequence as a configured wildcard allowlist entry (e.g. `evilethereum.org` against `*.ethereum.org`) can have the Gateway reflect their origin and grant `Access-Control-Allow-Origin`, `Access-Control-Allow-Methods`, and `Access-Control-Allow-Headers`. This enables browser-based cross-origin requests from a domain the operator never intended to trust to interact with the Gateway's `ProcessRequest` handler as if it were an authorized origin — an allowlist bypass / gateway request impersonation on an internet-facing entrypoint.

## Likelihood Explanation
Exploitation requires only registering a domain string, which is entirely within an unprivileged attacker's control — no credentials, no host/database access, and no privileged role are needed. Any Gateway operator using the documented and tested wildcard CORS pattern (`CORSAllowedOrigins: ["https://*.<domain>"]`) is exposed, making this a realistic, repeatable configuration-triggered bug in shipped code rather than a hypothetical or operator-misconfiguration issue.

## Recommendation
Anchor the wildcard suffix match to a domain-label boundary — e.g., after stripping `*.`, require `originHost == allowedHost || strings.HasSuffix(originHost, "."+allowedHost)` — so that only true subdomains match, and additionally consider normalizing hosts (IDNA/punycode) prior to comparison.

## Proof of Concept
1. Configure Gateway with `CORSEnabled: true`, `CORSAllowedOrigins: ["https://*.ethereum.org"]` (matching `startNewServer` test helper pattern in `httpserver_test.go`).
2. Send a request to the Gateway path with header `Origin: https://evilethereum.org`.
3. Observe `isAllowedOrigin("https://evilethereum.org")` returns `true` (since `strings.HasSuffix("evilethereum.org", "ethereum.org")` is `true`), and the response contains `Access-Control-Allow-Origin: https://evilethereum.org`.
4. Add this as a new test case (analogous to `TestHTTPServer_HandleRequest_CORSEnabled_FromNotAllowedOriginWildcards`) asserting that `evilethereum.org` should be rejected, and confirm it currently incorrectly passes.
