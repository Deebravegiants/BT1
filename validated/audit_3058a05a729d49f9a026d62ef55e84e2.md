## Title
`BandwidthManager._host` is a one-shot, unverified address with no recovery path if set wrong, permanently freezing purchased-bandwidth funds - (File: evm/src/apps/BandwidthManager.sol)

### Summary
`BandwidthManager.setHost()` is the exact analog of the reported `FALLBACK_RECEIVER` bug class: an "important address" is written exactly once, is checked only against being *already set* (not against being correct), and has no setter to correct a mistake afterward. Every fund-bearing and governance path on the contract — `purchase()`, and the `SetTiers`/`Withdraw` governance actions in `onAccept` — depends entirely on this single address being right the first time.

### Finding Description
`_host` is declared as a plain, owner-writable address, gated to be set only once: [1](#0-0) 

```solidity
function setHost(address hostAddr) public onlyOwner {
    if (_host != address(0)) revert UnauthorizedAction();
    _host = hostAddr;
}
```

Unlike `EvmHost.updateHostParams`, which validates every address it stores (non-zero, has code, implements the right interface) before accepting it, `setHost` performs **no validation at all** on `hostAddr` — not a zero check, not a code-existence check, not an interface check. Once called, it can never be called again (`if (_host != address(0)) revert`), so a wrong value (typo, stale/deprecated `EvmHost` deployment address, wrong-network address) is permanent.

`_host` is then load-bearing for every operation on the contract:

- `host()` returns `_host`, gating `onlyHost` on `onAccept` (inherited from `HyperApp`): [2](#0-1) 
- `purchase()` — reachable by any unprivileged bandwidth purchaser — reads the fee token and dispatches through `_host` directly: [3](#0-2) 
- The only governance recovery mechanism, `Withdraw`, is delivered exclusively via `onAccept`, which is `onlyHost`: [4](#0-3) 

If `_host` is set to a wrong-but-valid `IDispatcher`-shaped contract (e.g. a stale `EvmHost` deployment, or the wrong chain's host address reused by mistake), `purchase()` still executes: it pulls the fee token amount from the buyer via `safeTransferFrom` into the manager, then dispatches through that wrong host. The message never reaches the real `pallet-bandwidth` on Hyperbridge, so the buyer's app is never credited, and the fee-token proceeds sit in the manager contract. Because `Withdraw` can only be delivered by the (wrong) `_host`'s governance channel — which will never route a legitimate Hyperbridge message to this manager since it is the wrong host — those proceeds, and any tier prices collected from buyers before the mistake is discovered, are permanently unreachable. `setHost` cannot be called a second time to correct the address.

### Impact Explanation
This is a permanent freezing-of-funds bug reachable purely through the intended unprivileged flow: any bandwidth purchaser calling `purchase()` after a one-time admin mistake in `setHost` has their fee-token payment locked in the contract with no governance path to ever retrieve it, since the sole retrieval mechanism (`Withdraw` via `onAccept`) is itself gated by the same broken `_host`. There is no migration, no re-deployment recovery for funds already collected, and no on-chain way to detect or roll back the mistake once a purchase has occurred.

### Likelihood Explanation
`setHost` is called exactly once per deployment, during bring-up (per the bandwidth configuration runbook: "Owner calls `setHost(hostAddr)` — one-shot"). A copy-paste error picking the wrong chain's host address, or reusing a decommissioned `EvmHost` address, is a realistic operational mistake, especially since the function performs zero validation, unlike `EvmHost.updateHostParams`'s defense-in-depth checks for the equivalent fields (`hostManager`, `handler`, `consensusClient`) in the same codebase.

### Recommendation
Validate `hostAddr` in `setHost` (non-zero, non-EOA, and ideally interface-checked via `IERC165`/`supportsInterface(type(IDispatcher).interfaceId)` the way `EvmHost.updateHostParamsInternal` validates `handler`/`hostManager`/`consensusClient`), and/or add an owner-gated recovery setter (with an event) usable if no purchases/funds have accrued yet, mirroring the `set_fallback_receiver`-style fix recommended for the original `FALLBACK_RECEIVER` finding.

### Proof of Concept
1. Deploy `BandwidthManager(owner)`.
2. Owner calls `setHost(wrongHostAddress)` where `wrongHostAddress` is a deployed, `IDispatcher`-shaped contract but not the intended `EvmHost` (e.g., a stale/prior deployment, or the address meant for a different chain).
3. `setTier`/`dispatch_set_tiers` configure prices as normal on the (wrong) host's Hyperbridge counterpart is never reached, but tier prices can still be pushed if the wrong host happens to also be a live `EvmHost` on some chain — or an attacker/buyer simply calls `purchase()` once tier prices are non-zero via any legitimate-looking `SetTiers` that was actually intended for a different manager.
4. A buyer calls `purchase(app, tier, months, chain)`; `feeToken.safeTransferFrom` pulls funds into the manager, then `IDispatcher(_host).dispatch(...)` succeeds against the wrong host and returns some commitment, emitting `BandwidthPurchased`.
5. The real `pallet-bandwidth` never receives the credit message (it went to the wrong host's ecosystem), so the buyer's app is never credited bandwidth.
6. Governance attempts to recover the buyer's paid fee tokens via a `Withdraw` message — but `onAccept` is `onlyHost`, and the real Hyperbridge relayer network has no route to reach this manager through the wrong `_host`. The funds are permanently stuck, and `setHost` reverts on any further call (`_host != address(0)`).

        external

    {
        if (app.length == 0 || app.length > MAX_APP_LENGTH || chain.length == 0 || months == 0) {
            revert InvalidPurchase();
        }
        uint256 price18d = tierPrice[tier];
        if (price18d == 0) revert UnknownTier();

        uint256 total18d = price18d * months;
        address feeToken = IDispatcher(_host).feeToken();
        uint8 dec = IERC20Metadata(feeToken).decimals();
        uint256 scale = 10 ** (18 - dec);
        if (total18d % scale != 0) revert PriceNotRepresentable();
        uint256 amount = total18d / scale;

        IERC20(feeToken).safeTransferFrom(msg.sender, address(this), amount);

        BandwidthPurchaseMsg memory body = BandwidthPurchaseMsg({
            app: app,
            tier: tier,
            months: months,
            chain: chain
        });

        commitment = IDispatcher(_host).dispatch(
            DispatchPost({
                dest: IDispatcher(_host).hyperbridge(),
                to: PALLET_BANDWIDTH_MODULE_ID,
                body: abi.encode(body),
                timeout: 0,
                fee: 0,
                payer: address(this)
            })
        );

        emit BandwidthPurchased({
            payer: msg.sender,
            feeToken: feeToken,
            tier: tier,
            months: months,
            amountPaid: amount,
            app: app,
            chain: chain,
            commitment: commitment
        });
    }
