### Title
Token Exchange sends `client_secret` to an unvalidated JWT `dest` host, bypassing the gem's own `ShopValidator` domain allowlist - (File: `lib/shopify_api/auth/token_exchange.rb`)

### Summary
`ShopifyAPI::Auth::TokenExchange.exchange_token` derives the destination host for the token-exchange request directly from the session token's `dest` JWT claim and never passes it through `ShopifyAPI::Utils::ShopValidator`, unlike every sibling credential-issuing method in the same module and file.

### Finding Description
`exchange_token` decodes the caller-supplied session token and takes `dest_shop = jwt_payload.shop` [1](#0-0) , then builds `shop_session = ShopifyAPI::Auth::Session.new(shop: dest_shop)` and issues the token request through `Clients::HttpClient.new(session: shop_session, base_path: "/admin/oauth")` with a body containing `client_id` and `client_secret` [2](#0-1) . `HttpClient` builds the request host straight from `session.shop`: `@base_uri = "https://#{api_host || session.shop}"` [3](#0-2) , so `dest_shop` becomes the literal network destination that receives the app's `client_id`/`client_secret`.

`dest_shop` comes from `JwtPayload#shop`, which is simply `@dest.gsub("https://", "")` [4](#0-3) . `JwtPayload#initialize` only checks the HS256 signature and `aud == Context.api_key`; it never checks that `iss`/`dest` fall within a trusted Shopify domain suffix [5](#0-4) .

This is inconsistent with the rest of the same file and module: `TokenExchange.migrate_to_expiring_token`, `RefreshToken.refresh_access_token`, and `ClientCredentials.client_credentials` all call `validated_shop = Utils::ShopValidator.sanitize!(shop)` before constructing the session used to send `client_secret` [6](#0-5) [7](#0-6) [8](#0-7) . `ShopValidator.sanitize!` restricts the resolved host to `TRUSTED_SHOPIFY_DOMAINS` (`shopify.com`, `myshopify.io`, `myshopify.com`, `spin.dev`, `shop.dev`) and rejects anything else [9](#0-8) . `exchange_token` is the one credential-issuing path in this file that skips this check, even though the CHANGELOG documents that `ShopValidator` was specifically added to bind the token-exchange target host [10](#0-9) .

This maps directly onto the report's bug class: a value (`tickUpper - tickLower` / here, `dest_shop`) is used to drive a security-relevant computation (routing a request carrying secret material) on the assumption that a narrower check (JWT signature validity / individual tick bounds) is sufficient, while the actual invariant needed (destination host is a trusted Shopify domain / combined tick width is in-domain) is never independently enforced at the point of use — breaking the equality `validated_host == host_receiving_client_secret` that the gem otherwise enforces everywhere else.

### Impact Explanation
If a `dest` claim ever contains a value outside the `ShopValidator` allowlist — whether from a session token obtained via a non-standard/legacy issuance path, a future Shopify token format, or any component of the host application that forwards attacker-influenced tokens into `exchange_token` without validation — the gem will send `client_id` and `client_secret` in a POST request to that untrusted host. This is credential exfiltration of the app's `client_secret` to an attacker-controlled endpoint (SSRF carrying the app's credentials), matching the High-severity criteria in scope.

### Likelihood Explanation
Low-to-moderate. Under the intended, fully-trusted Shopify issuance flow, `dest` is always a legitimate Shopify domain, so the missing check is latent rather than trivially triggerable by an unprivileged internet user with no other primitive. However, it is a genuine gap relative to the gem's own established invariant (every other credential-sending path validates the destination host), and it depends only on `exchange_token`'s caller supplying a session token — a much weaker trust assumption than the access-token/API-secret-key requirements this scan explicitly excludes.

### Recommendation
In `ShopifyAPI::Auth::TokenExchange.exchange_token`, validate `dest_shop` with `Utils::ShopValidator.sanitize!` (or `sanitize_shop_domain` with an explicit raise on `nil`) before constructing `shop_session`, exactly as done in `migrate_to_expiring_token`, `RefreshToken.refresh_access_token`, and `ClientCredentials.client_credentials`, so the host that receives `client_secret` is always constrained to `ShopValidator::TRUSTED_SHOPIFY_DOMAINS`.

### Proof of Concept
1. Craft or obtain a session token whose `dest` claim resolves (after signature verification) to a non-`TRUSTED_SHOPIFY_DOMAINS` value, e.g. `dest: "https://attacker.example"`.
2. Call `ShopifyAPI::Auth::TokenExchange.exchange_token(session_token: token, requested_token_type: ...)`.
3. Observe that `jwt_payload.shop` (`"attacker.example"`) is used unchecked to build `shop_session`, and `Clients::HttpClient` issues `POST https://attacker.example/admin/oauth/access_token` with `client_id`/`client_secret` in the body — compare against `ClientCredentials.client_credentials("attacker.example")`, which instead raises `ShopifyAPI::Errors::InvalidShopError` via `ShopValidator.sanitize!` before ever constructing the request.

      TRUSTED_SHOPIFY_DOMAINS = T.let(
        [
          "shopify.com",
          "myshopify.io",
          "myshopify.com",
          "spin.dev",
          "shop.dev",
        ].freeze,
        T::Array[String],
      )

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
