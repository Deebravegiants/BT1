### Title
Webhook shop-domain header is not covered by HMAC verification, enabling cross-tenant webhook forgery - (File: `lib/shopify_api/webhooks/request.rb`)

### Summary
`ShopifyAPI::Webhooks::Request` derives the shop identity used to route a webhook to a handler from the `X-Shopify-Shop-Domain` header, but the HMAC signature that authenticates the request only covers the raw request body. An attacker who possesses one valid `(body, hmac)` pair — trivially obtainable by installing the app on their own store and receiving a real webhook — can replay that exact body/hmac pair while swapping in an arbitrary victim shop domain in the `shop-domain` header. `Utils::HmacValidator.validate` will report the request as valid because it only checks the body against the hmac, and `Webhooks::Registry.process` will hand the (attacker-chosen) body to the app's handler labeled as belonging to the victim shop.

which returns only `@raw_body`, excluding the `shop`, `topic`, and `webhook_id` headers. `Utils::HmacValidator.validate` verifies the received `hmac` strictly against `to_signable_string`: [2](#0-1) 

Meanwhile, `Registry.process` trusts `request.shop` (read straight from the unauthenticated header) as the tenant identity forwarded to the app's handler, after only checking the HMAC validity of the body: [3](#0-2) 

The identity binding that should hold is: `shop header == shop that produced/authorized the HMAC-signed body`. Because `shop` is excluded from `to_signable_string`, this equality is never enforced — the gem verifies "bytes are signed by the app's shared secret" but attributes those bytes to whichever `shop-domain` header value accompanies the HTTP request, which is attacker-controlled bytes.

An attacker who operates their own Shopify store can install the target app, trigger any webhook topic the app subscribes to, capture the resulting `(raw_body, hmac)` pair (both attacker-visible, since it's their own store's data), and replay the exact same request to the app's webhook endpoint with `X-Shopify-Shop-Domain` rewritten to a victim's `*.myshopify.com` domain. The HMAC check still passes (body unchanged), and `WebhookMetadata.shop` reports the victim shop to the handler.

### Impact Explanation
This breaks tenant isolation (the `shop` binding) at the point applications rely on most for per-merchant data attribution and lookups. Real-world app integrations (e.g., the reference `shopify_app` pattern) use the webhook's `shop` value to select which merchant's session/config to act on. An attacker can inject data that appears to be authenticated on behalf of an arbitrary shop domain, satisfying the "cross-tenant access" criterion.

### Likelihood Explanation
Exploitation only requires the attacker to control any single Shopify store (trivial — free trial stores are readily available) and the ability to send an HTTP POST with custom headers to the app's public webhook endpoint. No access to the app's `api_secret_key`, access tokens, or the victim's data is required.

### Recommendation
Include `shop-domain` (and ideally `topic`/`webhook_id`) in the HMAC-signed payload construction used for verification, or explicitly cross-check the `shop-domain` header against an independently-verified source (e.g., re-deriving/confirming it from Shopify's API using the shop's own registered credentials) before trusting it in `WebhookMetadata`.

### Proof of Concept
1. Install the target app on attacker-owned store `attacker.myshopify.com`; trigger a subscribed webhook topic (e.g. `orders/create`) and capture the raw POST: body `B` and header `X-Shopify-Hmac-Sha256: H` (valid HMAC of `B` under the shared secret).
2. Replay the captured request to the app's webhook endpoint, keeping body `B` and header `H` unchanged, but set `X-Shopify-Shop-Domain: victim-shop.myshopify.com`.
3. `HmacValidator.validate` succeeds because it only checks `H` against `B`; `Registry.process` dispatches to the handler with `WebhookMetadata.shop == "victim-shop.myshopify.com"`, causing the app to process attacker-controlled data as if it originated from the victim's shop.
