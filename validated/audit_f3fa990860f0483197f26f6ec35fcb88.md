### Title
`EvmHost.storeStateMachineCommitment` accepts state commitments for any `stateMachineId` without checking it against the host's whitelisted state machines - ([File: evm/src/core/EvmHost.sol])

### Summary
`EvmHost.storeStateMachineCommitment` writes a `StateCommitment` into `_stateCommitments[height.stateMachineId][height.height]` for whatever `stateMachineId` is supplied, gated only by `restrict(_hostParams.handler)`. It never checks that `height.stateMachineId` is one of the state machines the host has whitelisted in `_hostParams.stateMachines`. This is the same class of bug as the referenced report: an authorized-but-unscoped actor (there: any `VAULT_ROLE` holder; here: the single configured `handler`/`consensusClient` pair) can mutate the trusted state record of a state machine it was never assigned to.

### Finding Description
`EvmHost` maintains a whitelist of state machines it cares about, populated in `updateHostParamsInternal`: [1](#0-0) 

However, the function that actually records finalized state (`storeStateMachineCommitment`) does not consult this whitelist at all — it only checks the generic `restrict(_hostParams.handler)` modifier and then unconditionally writes the commitment, update time, and latest height for the supplied `stateMachineId`: [2](#0-1) 

The call path from `HandlerV2.handleConsensus` confirms that `stateMachineId` is taken verbatim from the `IntermediateState[]` array returned by the single configured `consensusClient.verify(...)`, with no cross-check against `host.hostParams().stateMachines`: [3](#0-2) 

Foundry's own test suite demonstrates this directly: a state commitment for `stateMachineId = 2000` is stored successfully *before* `2000` is ever added to `_hostParams.stateMachines`: [4](#0-3) 

This mirrors the `CollateralBook.vaultUpdateVirtualPriceAndTime` finding: the caller (handler, driven by whatever the consensus client attests) is authorized in a coarse-grained way ("any handler call is trusted"), but there is no fine-grained check binding the specific `stateMachineId` being written to the set of state machines that this particular host/consensus-client relationship is actually supposed to govern.

### Impact Explanation
Because the whitelist check is absent, any state machine ID that a relayer can get the configured consensus client to attest to (e.g., any parachain header/L2 state bundled into a single BEEFY/SP1 proof or any state id returned by a shared consensus client instance) is accepted and persisted into `_stateCommitments`, `_stateCommitmentsUpdateTime`, and `_latestStateMachineHeight`, and a `StateMachineUpdated` event is emitted for it — regardless of whether that ID belongs to a chain this `EvmHost` deployment was configured to track. Downstream, `handlePostRequests`/`handleGetResponses` and app-level `onAccept` calls rely on `stateMachineCommitment(height)` being trustworthy specifically for whitelisted routes; accepting and overwriting commitments for unlisted/foreign `stateMachineId` values undermines that invariant and can be leveraged to insert or overwrite state for state machine identifiers not vetted for this host, enabling forged proof verification or unauthorized state for routes/apps that assumed only whitelisted chains could ever populate that storage slot.

### Likelihood Explanation
Any relayer capable of submitting a normally-valid consensus proof through `HandlerV2.handleConsensus` can trigger this — no special privilege beyond being a permissionless relayer is required, since `handleConsensus` itself is not restricted to a privileged caller. The missing check is unconditional and always reachable on every consensus update.

### Recommendation
In `EvmHost.storeStateMachineCommitment` (and in `HandlerV2.handleConsensus` before calling it), require that `height.stateMachineId` is a member of `_hostParams.stateMachines` before writing/overwriting `_stateCommitments`, `_stateCommitmentsUpdateTime`, and `_latestStateMachineHeight`. Reject or skip intermediate states whose `stateMachineId` is not in the configured whitelist.

### Proof of Concept
The existing test `testCanAddwhitelistedStateMachines` in `evm/tests/foundry/EvmHostTest.sol` already demonstrates the missing check: it calls `host.storeStateMachineCommitment(height, ...)` for `stateMachineId = 2000` via `vm.prank(params.handler)` *before* `2000` is added to `_hostParams.stateMachines` via `updateHostParams`, and the call succeeds without reverting, proving there is no whitelist enforcement at write time.     function handleConsensus(IHost host, bytes calldata proof) external notFrozen(host) {
        uint256 delay = block.timestamp - host.consensusUpdateTime();
        if (delay >= host.unStakingPeriod()) revert ConsensusClientExpired();

        bytes memory previousState = host.consensusState();
        (bytes memory verifiedState, IntermediateState[] memory intermediates, uint256 nextAuthoritySetId) =
            IConsensusV2(host.consensusClient()).verify(previousState, proof);

        if (keccak256(previousState) == keccak256(verifiedState)) return;
        host.storeConsensusState(verifiedState);

        uint256 intermediatesLen = intermediates.length;
        for (uint256 i = 0; i < intermediatesLen; i++) {
            IntermediateState memory intermediate = intermediates[i];
            uint256 latestHeight = host.latestStateMachineHeight(intermediate.stateMachineId);
            if (latestHeight != 0 && intermediate.height > latestHeight) {
                StateMachineHeight memory stateMachineHeight =
                    StateMachineHeight({stateMachineId: intermediate.stateMachineId, height: intermediate.height});
                host.storeStateMachineCommitment(stateMachineHeight, intermediate.commitment);
            }
        }

    function testCanAddwhitelistedStateMachines() public {
        HostParams memory params = host.hostParams();
        uint256[] memory stateMachines = new uint256[](2);
        stateMachines[0] = 2000;
        stateMachines[1] = 2001;
        params.stateMachines = stateMachines;

        // create a state commitment
        StateMachineHeight memory height = StateMachineHeight({height: 100, stateMachineId: 2000});
        vm.prank(params.handler);
        host.storeStateMachineCommitment(
            height, StateCommitment({timestamp: 200, overlayRoot: bytes32(0), stateRoot: bytes32(0)})
        );

        vm.prank(params.handler);
        assert(host.stateMachineCommitment(height).timestamp == 200);

        assert(host.latestStateMachineHeight(height.stateMachineId) == 100);

        // add the new state machine
        vm.prank(params.hostManager);
        host.updateHostParams(params);
        // should be unchanged
        assert(host.latestStateMachineHeight(height.stateMachineId) == 100);
        // should be set to 1
        assert(host.latestStateMachineHeight(2001) == 1);
    }
