### Title
Unauthenticated Magic QR-code action triggers Wi-Fi/mirror-calibration reset without operator verification - (File: src/plans/qr_scan/operator.rs, src/plans/mod.rs)

### Summary
The Orb parses operator QR codes through `qr_scan::operator::Data::try_parse`, which recognizes special `magic_action:reset_wifi_credentials` / `magic_action:reset_mirror_calibration` strings via a hardcoded regex `MAGIC_QR_CODE`. In both `scan_initial_qr_codes` and `scan_remaining_qr_codes`, `handle_magic_operator_qr_code` is invoked and executes the reset action immediately after the QR content is parsed, and *before* `verify_operator_qr_code` (the only step that performs backend/operator authentication) is ever called. Any bystander who knows or reverse-engineers these plaintext magic strings (visible in this very open-source repo) can print a QR code and force the Orb to reset its Wi-Fi network or mirror calibration with zero operator authentication.

### Finding Description
`Data::try_parse` in [1](#0-0)  matches any string of the form `magic_action:reset_wifi_credentials` or `magic_action:reset_mirror_calibration` and returns `Data::MagicResetWifi` / `Data::MagicResetMirror` — with no cryptographic signature, operator PIN, or backend check involved in the parsing step itself.

The Orb's normal-mode flow reaches the "Operator QR-code scanning" phase after only a button press (`idle_wait_for_button_press`), which requires no operator credential — anyone physically present can press the button and present a QR code [2](#0-1) .

Once the scanned QR-code parses to a magic action, `scan_remaining_qr_codes` (and similarly `scan_initial_qr_codes` for self-serve mode) calls `handle_magic_operator_qr_code` right after `scan_operator_qr_code` returns, and only *after* successful magic-action handling does the loop proceed to `verify_operator_qr_code` for `Normal` QR codes — magic actions never reach that verification step at all: [3](#0-2) .

`handle_magic_operator_qr_code` executes the side effect unconditionally based purely on the QR string match: [4](#0-3) . This directly calls `reset_mirror_calibration` (which erases/re-derives calibration, engages the mirror motor, and recalibrates) [5](#0-4)  or `reset_wifi_and_ensure_network` (which tears down and re-establishes the network connection) [6](#0-5) .

No operator authentication, backend call, or any privilege check gates this path — `verify_operator_qr_code`'s backend `operator_status::request` call, which is the only authentication mechanism for operator QR codes, is bypassed entirely for magic actions [7](#0-6) .

### Impact Explanation
An unprivileged person standing in front of the Orb can force a Wi-Fi network reset or mirror recalibration at will, taking the Orb offline or degrading its calibration/availability without any operator credential. This is a signup-state wedge / denial-of-service: resetting the network disconnects the Orb from the backend (blocking all subsequent signups until connectivity is manually restored), and forcing repeated mirror recalibration disrupts biometric capture readiness. Because the magic action strings are static, publicly known constants baked into the open-source firmware, they provide no secrecy barrier and can be trivially reproduced on a printed/displayed QR code.

### Likelihood Explanation
Fully feasible and repeatable: the attacker only needs to know the fixed strings `magic_action:reset_wifi_credentials` / `magic_action:reset_mirror_calibration` (visible in the repo's source and even its own unit test at [8](#0-7) ), print them as a QR code, and present them to the Orb's camera during the operator-QR scan phase, which is reachable after a mere button press in normal mode. No signup, credentials, or backend interaction is required to trigger the reset.

### Recommendation
Require the magic-action QR code content to be cryptographically signed/authenticated (e.g., signed by a backend-issued short-lived token verified via `verify_operator_qr_code`-equivalent backend call) or require an authenticated operator session/PIN before executing `reset_wifi_and_ensure_network` / `reset_mirror_calibration`. At minimum, route magic actions through the same backend verification (`operator_status::request`) used for `Normal` operator QR codes before executing any state-changing action.

### Proof of Concept
Integration test (extending the existing test module in `src/plans/mod.rs`):
```rust
#[tokio::test]
async fn test_magic_qr_reset_wifi_bypasses_operator_auth() -> Result<()> {
    let mut fake_orb = Orb::builder().build().await?;
    let ms = MasterPlan::builder()
        .qr_scan_timeout(Duration::from_millis(10))
        .operator_qr_code(Some(Some("magic_action:reset_wifi_credentials")))?
        .build()
        .await?;

    let op_code = ms.scan_operator_qr_code(&mut fake_orb, None).await?.expect("op_code exists");
    // No backend/operator credential is presented anywhere above this line.
    let result = ms.handle_magic_operator_qr_code(&mut fake_orb, op_code).await?;
    // handle_magic_operator_qr_code returns None (action consumed) and the network
    // reset side effect (reset_wifi_and_ensure_network) has already executed,
    // with verify_operator_qr_code never invoked.
    assert!(result.is_none());
}
```
Expected assertion: the reset action executes and returns without any call to `verify_operator_qr_code` / `backend::operator_status::request`, confirming the magic-action path is reachable and executed with no operator authentication check.

    fn try_parse(code: &str) -> Option<Self> {
        let normal = user::Data::try_parse(code)

                |d| if d.signup_extension() { d.signup_extension_config.is_some() } else { true },

            return normal;

        if let Some(captures) = MAGIC_QR_CODE.captures(code) {
            return match captures
                .name("magic_action")
                .expect("magic_action group must be present")
                .as_str()
            {
                "reset_wifi_credentials" => Some(Data::MagicResetWifi),
                "reset_mirror_calibration" => Some(Data::MagicResetMirror),
                _ => None,
            };
        }
        None
    }

        orb: &mut Orb,
        qr_code: qr_scan::operator::Data,
    ) -> Result<Option<qr_scan::user::Data>> {
        match qr_code {
            qr_scan::operator::Data::Normal(qr_code) => {
                tracing::info!("Operator QR-code detected: {qr_code:?}");
                Ok(Some(qr_code))
            }
            qr_scan::operator::Data::MagicResetMirror => {
                tracing::info!("Magic QR-code detected: Reset Mirror");
                dd_incr!("main.count.signup.during.general.magic_qr.reset_mirror");
                let result = self.reset_mirror_calibration(orb).await;
                if let Err(err) = &result {
                    tracing::error!("Failed to reset mirror calibration: {err}");
                }
                orb.ui.magic_qr_action_completed(result.is_ok());
                Ok(None)

            qr_scan::operator::Data::MagicResetWifi => {
                tracing::info!("Magic QR-code detected: Reset Wi-Fi");
                dd_incr!("main.count.signup.during.general.magic_qr.reset_wifi");
                let result = self.reset_wifi_and_ensure_network(orb).await;
                if let Err(err) = &result {
                    tracing::error!("Failed to reset wifi: {err}");
                }
                orb.ui.magic_qr_action_completed(result.is_ok());
                Ok(None)
            }
        }
