### Title
Unbounded `GetRequest` batch and key-array size in `pallet-state-coprocessor::handle_unsigned` enables free, fixed-weight computational DoS - (File: `modules/pallets/state-coprocessor/src/lib.rs`)

### Summary
`pallet_state_coprocessor::Pallet::handle_unsigned` accepts a `GetRequestsWithProof` payload containing an unbounded `Vec<GetRequest>`, where each `GetRequest` itself carries an unbounded `keys: Vec<Vec<u8>>`. The call is dispatched with a fixed weight of `DbWeight::reads_writes(1, 2)` regardless of how many requests or keys are supplied, and it is validated via `ValidateUnsigned::validate_unsigned`, which runs the *entire* `handle_get_requests` verification pipeline (proof decoding, membership verification, per-key state-proof verification) on every node that receives the unsigned transaction over the network — before any fee or weight is charged. This mirrors CVE-2022-1099's root cause: an attacker-controlled unbounded array (tags on a runner) that a low-privilege actor can grow arbitrarily, degrading node performance.

### Finding Description
`handle_unsigned` is a `#[pallet::call_index(0)]` extrinsic with only an `ensure_none(origin)?` check, meaning any unsigned transaction can invoke it — no signer, no fee, no stake. [1](#0-0) 

Its `ValidateUnsigned::validate_unsigned` implementation eagerly runs `Self::handle_get_requests(message.clone())` — the full verification logic — just to decide whether the transaction is valid for the pool, before any weight/fee has been assessed and before it's included in a block: [2](#0-1) 

`handle_get_requests` loops over the entire `requests: Vec<GetRequest>` performing dedup checks, per-request source/dest validation, a batch membership proof verification, and then a second loop that runs `dest_state_machine.verify_state_proof(&host, req.keys.clone(), ...)` for every request — where `req.keys` is itself an unbounded `Vec<Vec<u8>>`: [3](#0-2) 

Nowhere in `GetRequest`, `DispatchGet`, or `GetRequestsWithProof` is there a `BoundedVec` or explicit length check on `requests` or `keys` — confirmed by exhaustive search for `MaxKeys`/`MaxRequestsPerBatch`/similar bounds, none of which exist in the codebase. The dispatcher that constructs `GetRequest` from `DispatchGet` copies `keys` verbatim with no size validation: [4](#0-3) 

Despite this unbounded, attacker-controlled input size, the call's declared weight is a flat constant independent of batch size: [5](#0-4) 

Because `validate_unsigned` runs on every node during transaction-pool gossip/validation (not just the block author), and because it performs cryptographic proof verification work proportional to `requests.len() * average(keys.len())` while being free of any transaction fee (unsigned), an attacker can craft a single `GetRequestsWithProof` with a very large number of `GetRequest`s and/or a very large number of `keys` per request. Each submission forces every peer node to perform disproportionate CPU work in `validate_unsigned` relative to the fixed, tiny declared weight — this is directly analogous to GitLab's runner-tags DoS, where an unbounded, user-controlled collection is processed without a size limit, degrading the platform's performance for all participants.

### Impact Explanation
This is a network-wide availability/performance-DoS vector reachable by any unprivileged party capable of submitting an unsigned extrinsic (no signature, no stake, no fee required). Repeated submission of oversized `GetRequestsWithProof` payloads can:
- Cause disproportionate CPU consumption during `validate_unsigned` across the entire network of validating nodes (since unsigned transactions are validated by every peer during gossip, not just the block author).
- Starve legitimate relayer traffic and block production capacity, since the weight charged does not reflect the actual computational cost, meaning blocks could be filled with underpriced/free work.
- Given ISMP's role as cross-chain messaging infrastructure, sustained degradation could delay message delivery, consensus updates, and fee/reward accounting across the entire Hyperbridge network — a protocol-wide availability impact, meeting the Medium severity bar of the source CVE.

### Likelihood Explanation
High reachability: `handle_unsigned` requires no signer, no stake, and no fee, and is exposed to any peer able to submit unsigned transactions/gossip to a Hyperbridge collator/validator node. No `BoundedVec` or explicit length checks exist for `requests` or `keys` at any layer (`DispatchGet`, `GetRequest`, `GetRequestsWithProof`), so the attack payload can be constructed by simply supplying arbitrarily many entries (bounded only by the outer extrinsic/block size limit imposed by the runtime, which is generic and far larger than the fixed weight assumes).

### Recommendation
- Introduce explicit bounds (`BoundedVec` with a `MaxRequestsPerBatch` and `MaxKeysPerRequest`, or equivalent runtime-configured constants) on `GetRequestsWithProof::requests` and `GetRequest::keys`, enforced both at dispatch time (`DispatchGet`) and at `handle_get_requests`/`validate_unsigned` entry, rejecting oversized payloads before any proof verification work is performed.
- Make the declared `#[pallet::weight(...)]` for `handle_unsigned` scale with `requests.len()` and total `keys` count (e.g., via a dynamic weight function based on decoded payload size) rather than a flat `reads_writes(1, 2)`.
- Consider performing a cheap, size-only bound check as the very first step of `validate_unsigned`, before invoking `handle_get_requests`, so that oversized batches are rejected without incurring proof-verification cost even once.

### Proof of Concept
1. Construct a `GetRequestsWithProof` where `requests` contains N `GetRequest` entries (e.g., N = tens of thousands), each with a `keys: Vec<Vec<u8>>` field populated with a large number of distinct 32/52-byte keys.
2. Submit this payload as the unsigned extrinsic `StateCoprocessor::handle_unsigned(message)` to any Hyperbridge node's transaction pool (no signature required, per `ensure_none(origin)` in `handle_unsigned`, and `pre_dispatch` is a no-op).
3. Observe that every peer node validating the transaction invokes `validate_unsigned`, which calls `handle_get_requests(message.clone())` — running dedup, membership-proof verification, and per-request `verify_state_proof` over every key in every request — even though the extrinsic's declared weight is the fixed `DbWeight::reads_writes(1, 2)`.
4. Repeat submission of similarly-shaped payloads (varying content to bypass the `provides` dedup hash) to sustain elevated CPU load across the network's validating nodes at negligible cost to the attacker (no fee, no signature).

	pub fn handle_get_requests(
		GetRequestsWithProof { requests, source, response, address }: GetRequestsWithProof,
	) -> Result<(), Error> {
		// 1. Verify source proofs
		// 2. Extract fees
		// 3. Verify response proof
		// 4. insert GetResponse into mmr and request receipts
		// 5. emit Response events
		let host = <<T as Config>::IsmpHost>::default();

		// Reject duplicate requests within the batch.
		let wrapped: Vec<Request> = requests.iter().cloned().map(Request::Get).collect();
		dedup_requests::<<T as Config>::IsmpHost>(&wrapped)?;

		for req in requests.iter() {
			let full = Request::Get(req.clone());

			// Get requests time out are relative to Hyperbridge
			if full.timed_out(host.timestamp()) {
				Err(Error::RequestTimeout { meta: full.clone().into() })?
			}

			// Source of the request must match the proof
			if full.source_chain() != source.height.id.state_id {
				Err(Error::RequestProofMetadataNotValid { meta: full.clone().into() })?
			}

			// Proof must come from the requested chain
			if full.dest_chain() != response.height.id.state_id {
				Err(Error::RequestProofMetadataNotValid { meta: full.clone().into() })?
			}

			// This request has already been responded to. Mirror `handlers/response.rs:61`:
			// dedup against `response_receipt`, which the dispatch path writes for this exact
			// GetRequest hash after producing a response. The receipt also binds the response
			// commitment, so external auditors can attest "Hyperbridge produced response X for
			// request Y" from one map.
			let probe = GetResponse { get: req.clone(), values: Default::default() };
			if host.response_receipt(&probe).is_some() {
				Err(Error::DuplicateResponse { meta: (&probe).into() })?
			}
		}

		// Ensure the proof height is equal to each retrieval height specified in the Get
		// requests
		if !requests.iter().all(|get| get.height == response.height.height) {
			Err(Error::InsufficientProofHeight)?
		}

		// Verify source proof
		let source_state_machine = validate_state_machine(&host, source.height)?;
		let state_root = host.state_machine_commitment(source.height)?;

		// Verify membership proof to ensure that requests where committed on source chain
		let commitments = requests
			.iter()
			.map(|get| hash_request::<<T as Config>::IsmpHost>(&Request::Get(get.clone())))
			.collect();
		source_state_machine.verify_membership(&host, commitments, state_root, &source)?;

		// Verify response proof
		let dest_state_machine = validate_state_machine(&host, response.height)?;
		let state_root = host.state_machine_commitment(response.height)?;

		// Insert GetResponses into mmr
		let mut responses = vec![];
		// Total payload bytes across this batch, used to mint reputation to
		// the relayer named in `address`. Each response contributes its
		// abi-encoded size — the same quantity the bandwidth gate charges —
		// so the mint stays proportional to the work paid for.
		let mut total_bytes: u32 = 0;
		for req in requests {
			let values: Vec<StorageValue> = dest_state_machine
				.verify_state_proof(&host, req.keys.clone(), state_root.state_root, &response)?
				.into_iter()
				.map(|(key, value)| StorageValue { key, value })
				.collect();

			let response = GetResponse { get: req, values };

			// Meter the app's bandwidth using the full size of the
			// abi-encoded GetResponse. Charged after proof verification
			// so the value sizes are final.
			let bytes = ismp::abi::encode_get_response(&response).len() as u32;
			<T as Config>::BandwidthGate::try_consume(
				&response.get.source,
				&response.get.from,
				bytes,
			)
			.map_err(|err| Error::Custom(alloc::format!("bandwidth gate: {err}")))?;
			total_bytes = total_bytes.saturating_add(bytes);

			responses.push(response);
		}
