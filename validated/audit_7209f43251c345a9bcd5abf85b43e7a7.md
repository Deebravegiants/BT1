### Title
Webhook shop/topic identity headers are not covered by the HMAC signature, allowing tenant-attribution spoofing - (File: `lib/shopify_api/webhooks/request.rb`)

### Summary
`ShopifyAPI::Webhooks::Registry.process` authenticates an incoming webhook solely by validating an HMAC computed over the raw request body. The `shop`, `topic`, `webhook_id`, and `api_version` values that are subsequently trusted and handed to the app's webhook handler are read from HTTP headers that are **not** part of the signed payload. This breaks the identity binding `shop_trusted_by_handler == shop_authenticated_by_hmac`.

### Finding Description
`ShopifyAPI::Webhooks::Request#to_signable_string` returns only the raw HTTP body: [1](#0-0) 

Meanwhile `shop`, `topic`, `webhook_id`, and `api_version` are all pulled straight from HTTP headers, with no cryptographic binding to the signature: [2](#0-1) 

`Registry.process` validates only the body's HMAC via `Utils::HmacValidator.validate(request)`, which internally calls `verifiable_query.to_signable_string` (i.e., the raw body) and HMACs it with `Context.api_secret_key`: [3](#0-2) [4](#0-3) 

After that single check passes, `request.shop`, `request.topic`, and `request.webhook_id` — none of which were part of the signed bytes — are trusted and forwarded verbatim to the app's registered handler as `WebhookMetadata`: [3](#0-2) 

Because the signature only binds the body, any party who can obtain one legitimately-signed `(raw_body, hmac)` pair from Shopify — for example, by installing the app on their own store and capturing a webhook Shopify sends them for their own shop — can replay that exact body/HMAC pair to the app's webhook endpoint while freely rewriting the `x-shopify-shop-domain`, `x-shopify-topic`, `x-shopify-webhook-id`, and `x-shopify-api-version` headers. `HmacValidator.validate` will still return `true` because it only re-hashes the untouched body, so `Registry.process` will happily route the forged headers (with attacker-chosen shop/topic) straight into the handler as if Shopify itself vouched for them.

### Impact Explanation
This is a cross-tenant identity-binding bypass: the "shop" that the webhook handler trusts for tenant-scoped actions (recording events, triggering data updates, invalidating/renewing state, etc.) is attacker-controlled once they possess any one valid signed body/HMAC pair, letting them impersonate arbitrary shops or spoof arbitrary topics to the app's webhook handler logic without ever knowing `api_secret_key`.

### Likelihood Explanation
Obtaining one legitimate `(body, hmac)` pair only requires installing the target app on any store (a routine, unprivileged action available to any developer/merchant), after which the header fields can be freely rewritten in a replayed HTTP request since they are never included in the signed material.

### Recommendation
Include `shop`, `topic`, `webhook_id`, and `api_version` in the HMAC-signable string (or otherwise cryptographically bind them, e.g., via a signed envelope that covers headers + body) so `Utils::HmacValidator.validate` fails if any of these identity fields are altered relative to what Shopify actually signed.

### Proof of Concept
1. Install the target app on `attacker-shop.myshopify.com`; trigger any webhook event so Shopify sends a legitimately signed webhook: headers include `x-shopify-hmac-sha256: <valid hmac over raw_body>` and `x-shopify-shop-domain: attacker-shop.myshopify.com`.
2. Capture the raw body and the `x-shopify-hmac-sha256` value.
3. Replay an HTTP POST to the app's webhook endpoint with the identical raw body and `x-shopify-hmac-sha256`, but set `x-shopify-shop-domain: victim-shop.myshopify.com` (and/or change `x-shopify-topic`).
4. `ShopifyAPI::Webhooks::Request.new` accepts the forged headers, `Utils::HmacValidator.validate` returns `true` (it only hashes the unchanged raw body), and `Registry.process` invokes the handler with `WebhookMetadata.new(shop: "victim-shop.myshopify.com", ...)`, i.e., the app now processes attacker-supplied data as if it originated from `victim-shop.myshopify.com`.

            validate_signature(verifiable_query, T.must(Context.old_api_secret_key))
          end

        def validate_signature(verifiable_query, secret)
          received_signature = verifiable_query.hmac
          computed_signature = compute_signature(verifiable_query.to_signable_string, secret)
          OpenSSL.secure_compare(computed_signature, T.must(received_signature))
        end
