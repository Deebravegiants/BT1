Based on my investigation, the `confidentialrelay` gateway handler's `HandleJSONRPCUserMessage` (`core/services/gateway/handlers/confidentialrelay/handler.go`) creates an unbounded, unauthenticated `activeRequests` map entry for every user request before any authentication or resource check, which is the closest analog to the CVE-2024-52914 orphan-handling DoS bug class (an unprivileged caller can cheaply cause the node to allocate and hold unbounded per-request state).

### Title
Unauthenticated, unbounded per-request state allocation in the gateway ConfidentialRelay user-message handler enables memory/goroutine exhaustion DoS - (File: core/services/gateway/handlers/confidentialrelay/handler.go)

### Summary
`handler.HandleJSONRPCUserMessage` accepts any JSON-RPC request routed to the ConfidentialRelay gateway service and immediately calls `h.newActiveRequest`, which inserts an entry into the `h.activeRequests` map keyed by the caller-supplied `req.ID`, before any authentication, authorization, or global capacity check occurs. [1](#0-0) [2](#0-1) 

### Finding Description
The gateway's `ProcessRequest` entry point decodes and routes any incoming request from the public user-facing HTTP endpoint straight to `h.HandleJSONRPCUserMessage` (no signature/auth gate at the gateway routing layer itself; auth is left to individual handlers). [3](#0-2) 

For the ConfidentialRelay handler specifically, `HandleJSONRPCUserMessage` only validates that `req.ID` is non-empty and ≤200 characters, then unconditionally calls `newActiveRequest` and fans the request out to DON nodes — there is no authentication, authorization, JWT verification, or workflow/owner allowlist check comparable to what the `vault` handler (`ProcessRequest`/authorizer) or the HTTP trigger handler (`authorizeRequest`/`checkRateLimit`) perform before allocating state. [4](#0-3) 

Each call allocates an `activeRequest` struct (containing a `responses` map, timers/grace-window state, and a callback) keyed by the attacker-controlled `req.ID`, and stores it in the shared `h.activeRequests` map guarded only by a mutex — there is no cap on map size and no per-caller rate limit gating entry into this path (contrast with `HandleNodeMessage`, which is protected by `perNodeRateLimiters`/`globalNodeRateLimiter`, but those only rate-limit DON node responses, not the initial unauthenticated user request). [5](#0-4) [6](#0-5) 

Entries are only cleared on completion or by a periodic sweep (`removeExpiredRequests`) bounded by `requestTimeout` (default 30s) and `defaultCleanUpPeriod` (1s), meaning any single request can occupy memory for up to the full timeout window regardless of authentication. [7](#0-6) [8](#0-7) 

This mirrors the Bitcoin Core orphan-handling bug class: an unprivileged/unauthenticated actor can submit cheap, ID-varying requests that the node must hold in unbounded per-request state for a fixed window, consuming memory and fan-out work (one `SendToNode` per DON member per request) with no cost to the attacker, potentially stalling the gateway's ConfidentialRelay service.

### Impact Explanation
An unauthenticated remote caller can flood the gateway's ConfidentialRelay endpoint with distinct request IDs, each triggering a full DON fan-out (`SendToNode` to every DON member) and a 30-second-lived map entry with no authentication gate and no capacity bound. Sustained flooding can exhaust gateway memory/goroutines and DON node bandwidth, degrading or stalling legitimate relay traffic for the duration of the attack (denial of service), analogous in severity/category to the cited orphan-tx stall.

### Likelihood Explanation
Likelihood is high for reachability (the endpoint is user-facing and requires no prior authentication per the code shown) but the actual DoS magnitude depends on deployment-specific factors (gateway ingress rate limiting, number of DON members, request size limits) that are outside this handler and not verified here. I could not confirm within the available context whether an outer HTTP-layer rate limiter (e.g., `WebServer.RateLimit` settings seen in `core/config/docs/core.toml`) applies to this gateway service's ingress path, which would materially reduce exploitability; this is uncertain and would need further verification.

### Recommendation
Add authentication/authorization (or at minimum a per-caller/global rate limiter and a hard cap on `len(h.activeRequests)`) to `HandleJSONRPCUserMessage` in `core/services/gateway/handlers/confidentialrelay/handler.go` before `newActiveRequest` is invoked, mirroring the bounded/authenticated patterns already used by the `vault` handler's authorizer gate and `common.NewRequestCache`'s `maxCacheSize` check.

### Proof of Concept
1. Send repeated JSON-RPC requests to the gateway's public HTTP endpoint with `Method` set to `MethodSecretsGet`/`MethodCapabilityExec` (ConfidentialRelay service), each with a unique `req.ID` and no valid `Auth`.
2. Each request passes the `len(req.ID) <= 200` check and reaches `newActiveRequest`, inserting an entry into `h.activeRequests` and triggering `fanOutToNodes` to every DON member.
3. Repeat rapidly with new IDs faster than the 30s timeout/1s sweep can clear entries; `h.activeRequests` and outbound `SendToNode` calls grow unbounded, consuming gateway memory and DON bandwidth without any authentication check ever being performed.

Note: I was unable to fully verify whether an upstream ingress-level rate limiter (outside this specific handler file) mitigates this in production deployments; this uncertainty should be resolved before treating severity as final.

func (h *handler) removeExpiredRequests(ctx context.Context) {
	h.mu.RLock()
	var expiredRequests []*activeRequest
	now := h.clock.Now()
	for _, userRequest := range h.activeRequests {
		if now.Sub(userRequest.createdAt) > h.requestTimeout {
			expiredRequests = append(expiredRequests, userRequest)
		}
	}
	h.mu.RUnlock()

	for _, er := range expiredRequests {
		responses := er.copiedResponses()
		l := h.requestLogger(er.req, er.labels)
		l.Debugw("request expired, evaluating collected relay responses",
			"collected", len(responses),
			"nodes", len(h.donConfig.Members),
			"unanswered", len(h.donConfig.Members)-len(responses),
		)
		summary, err := h.bundler.Bundle(er.req, responses, l)
		if err != nil {
			l.Errorw("failed to build relay response bundle", "error", err)
			if sendErr := h.sendResponseAndClearRequest(ctx, er, h.constructErrorResponse(er.req, api.FatalError, err)); sendErr != nil {
				l.Errorw("error returning bundle failure on expiry", "error", sendErr)
			}
			continue
		}
		// Expiry makes further responses unavailable to this request. The common
		// readiness path forwards a viable partial bundle or returns a timeout.
		if err := h.forwardBundleOrTerminateIfReady(ctx, l, er, summary, 0, true); err != nil {
			l.Errorw("error forwarding bundle on expiry", "error", err)
		}
	}
}

func (h *handler) HandleJSONRPCUserMessage(ctx context.Context, req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) error {
	if req.ID == "" {
		return errors.New("request ID cannot be empty")
	}
	if len(req.ID) > 200 {
		return errors.New("request ID is too long: " + strconv.Itoa(len(req.ID)) + ". max is 200 characters")
	}

	labels := h.extractRequestLabels(req)
	l := h.requestLogger(req, labels)
	l.Debugw("handling confidential relay request", "nodes", len(h.donConfig.Members), "f", h.donConfig.F)

	ar, err := h.newActiveRequest(req, labels, callback)
	if err != nil {
		return err
	}

	return h.fanOutToNodes(ctx, l, ar)
}

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], labels requestLabels, callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID, "executionID", labels.ExecutionID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		labels:    labels,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

func (h *handler) HandleNodeMessage(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	l := logger.With(h.lggr, "method", resp.Method, "requestID", resp.ID, "nodeAddr", nodeAddr)
	l.Debugw("handling node response")

	nodeRateLimiter, ok := h.perNodeRateLimiters[nodeAddr]
	if !ok {
		return fmt.Errorf("received message from unexpected node %s", nodeAddr)
	}
	if !nodeRateLimiter.Allow(ctx) {
		l.Debugw("node is rate limited", "nodeAddr", nodeAddr)
		return nil
	}
	if !h.globalNodeRateLimiter.Allow(ctx) {
		l.Debug("global relay rate limit exceeded")
		return nil
	}

		// Arbitrary limit to prevent abuse
		return newError(jsonRequest.ID, api.UserMessageParseError, "request ID is too long: "+strconv.Itoa(len(jsonRequest.ID))+". max is 200 characters")
	}
	isLegacyRequest := false
	var h handlers.Handler
	var handlerKey string
	if msg == nil || msg.Body.DonID == "" {
		serviceName := jsonRequest.ServiceName()
		if handler, ok := g.serviceToMultiHandler[serviceName]; ok {
			h = handler
			handlerKey = serviceName
		} else if donID, ok := g.serviceNameToDonID[serviceName]; ok {
			// Fallback to legacy service name -> DON ID mapping
			if handler, ok := g.handlers[donID]; ok {
				h = handler
				handlerKey = donID
			}
		}
		if h == nil {
			return newError(jsonRequest.ID, api.HandlerError, "Service name not found: "+serviceName)
		}

		}
		handlerKey = msg.Body.DonID
		var ok bool
		h, ok = g.handlers[handlerKey]
		if !ok {

		}
	}

	startTime := time.Now()

	callback := handlerscommon.NewCallback()

		err = h.HandleJSONRPCUserMessage(ctx, jsonRequest, callback)
