### Title
i128 overflow in accrual `scaled_to_original` permanently freezes a saturated market — no repay, withdraw, or liquidation - (File: common/src/rates/simulate.rs)

### Summary
The analog of the QEMU integer-overflow DoS is a checked-arithmetic overflow inside the interest-accrual step. `accrue_step` computes `scaled_to_original(env, borrowed, borrow_index)` and `scaled_to_original(env, supplied, supply_index)` at the head of every step; when `scaled × index` exceeds `i128::MAX` the `mul` raises `GenericError::MathOverflow` [1](#0-0) . Every pool verb runs `interest::global_sync` before mutating [2](#0-1) , so once a whale market's ray-value crosses the `i128::MAX` ceiling, the panic repeats forever: `withdraw`, `repay`, `liquidate`, `update_indexes`, `flash_loan`, and even `clean_bad_debt`/`recapitalize` all revert on that market. The borrow-index cap (`MAX_BORROW_INDEX_RAY = 10^36`) never rescues the market because the value ceiling is hit first [3](#0-2) .

### Finding Description
- `accrue_step` multiplies `borrowed`/`supplied` (RAY-scaled shares) by the indexes via `Ray::mul` → `mul_div_half_up`. The I256 widened intermediate is exact, but the result must fit `i128`; above that it panics with `MathOverflow` [4](#0-3) .
- The product `supplied × supply_index` (and `borrowed × borrow_index`) is a RAY asset value. `supplied` can reach ~`10^36` raw (1B whole tokens at 18 decimals, admitted by `max_cap_for_decimals`), so the ceiling is `i128::MAX / 10^36` ≈ 170× on the index.
- `update_borrow_index` clamps the index at `10^36` (1000×) but nothing clamps the *value*; docs explicitly admit "value overflow can occur before the index ceiling and block repayment/withdrawal because those operations accrue first" [5](#0-4) .
- The in-repo test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` demonstrates it end-to-end: after enough accrual at ~98% utilization on a steep curve, `update_indexes`, `withdraw`, and `repay` all fail with `MATH_OVERFLOW` [6](#0-5) .
- Reachability: an unprivileged address only needs `supply` + `borrow` near the market caps (and a second account supplying collateral). Steep-segment utilization maximizes the rate; because utilization drifts upward as debt compounds faster than supply, an untouched whale market crosses into the runaway region on its own — no privileged action is required after the market is seeded.

### Impact Explanation
Permanent freezing of funds on the affected (hub, token) book: supplier principal and accrued yield cannot be withdrawn, borrowers cannot repay, liquidators cannot liquidate, bad debt cannot be cleaned or recapitalized — every path reverts in the accrual preface. All users of that market are frozen, not just the attacker.

### Likelihood Explanation
Medium. The trigger requires a market whose ray-value of supply/debt can reach ~1.7e38, i.e., caps lifted near `max_cap_for_decimals` and a steep rate curve sustained at high utilization — plausible for high-decimal, low-unit-price assets. The attacker must also lock capital (supply + 2× overcollateralized borrow), but any user can then keep the market pinned at high utilization or simply let drift do it; `update_indexes` is permissionless so accrual cannot be skipped.

### Recommendation
Make accrual saturating rather than panicking on value overflow: e.g., clamp `scaled_to_original` via `mul_div_floor_saturating` inside `accrue_step` (rate at the ceiling is already max-rate, so saturation loses nothing), or bound `supplied`/`borrowed` ray-totals in the supply/borrow guards so `scaled × index` can never exceed `i128::MAX` before the index caps. Short-term, keep deployed caps well below the level where ~170× index growth overflows within a plausible horizon.

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
}

/// Computes `floor(x * y / d)`, rounding toward negative infinity for a negative quotient.
/// Panics with `GenericError::DivisionByZero` if `d == 0`, or with
/// `GenericError::MathOverflow` if the result does not fit in `i128`.
pub fn mul_div_floor(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    require_nonzero_divisor(env, d);
    if let Some(quotient) = x
        .checked_mul(y)
        .and_then(|product| div_floor_i128(product, d))
    {
        return quotient;
    }
    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    let nonneg = quotient_is_nonnegative(x, y, d);
    to_i128(env, &div_floor_i256(env, &x256.mul(&y256), &d256, nonneg))
}
