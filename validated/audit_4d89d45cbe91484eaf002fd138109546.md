## Analysis

The unauthenticated pprof/debug-forwarding endpoints in the LOOP registry match the CVE's bug class: a hidden diagnostic surface that leaks internal implementation detail to unprivileged/unauthenticated callers.

In `core/web/router.go`, the top-level `api` route group only applies rate limiting and session middleware — no authentication: [1](#0-0) 

`loopRoutes` is registered directly on this unauthenticated `api` group, unlike the analogous `metricRoutes` (pprof) which is deliberately mounted only under the authenticated `authv2` group with the comment "Debug routes accessible via authentication": [2](#0-1) [3](#0-2) 

The handlers registered by `loopRoutes` forward requests directly to the internal LOOP plugin's pprof and metrics HTTP endpoints without any authentication check, using the caller-controlled `debug`, `gc`, and `seconds` query parameters and the `profile` path parameter: [4](#0-3) 

### Title
Unauthenticated exposure of internal plugin metrics and pprof debug endpoints via LOOP registry routes - (File: core/web/router.go)

### Summary
The `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` routes are registered on the top-level, unauthenticated `api` gin route group, allowing any unauthenticated network caller to retrieve internal plugin metrics and full pprof profiling data (heap dumps, goroutine stacks, CPU profiles, symbol tables) from Chainlink LOOP plugins.

### Finding Description
`NewRouter` builds an `api` route group with only rate-limiting and session middleware — no `auth.Authenticate` call — and then calls `loopRoutes(app, api)` on it [1](#0-0) . Contrast this with the equivalent node-local pprof routes (`metricRoutes`), which are explicitly nested inside the authenticated `authv2` group with a comment noting "Debug routes accessible via authentication" [3](#0-2) , and the `/debug/vars` route, which is separately wrapped with session authentication [5](#0-4) .

`loopRoutes` itself performs no additional authorization check before forwarding requests to internal plugin endpoints (`pluginMetricHandler`, `pluginPPROFHandler`, `pluginPPROFPOSTSymbolHandler`), which proxy caller-supplied query parameters (`debug`, `gc`, `seconds`) and path values (`profile`, `name`) straight through to `http://<loopHostName>:<PrometheusPort>/debug/pprof/...` and `/metrics` [6](#0-5) . This is directly analogous to the Tandoor `?debug=true` bug class: a hidden diagnostic parameter/route that discloses deep internal state (here, Go pprof heap/goroutine/cpu profiling data and metrics — which the codebase's own `InsecurePPROFHeap` documentation flags as capable of exposing "private key components") to callers who should not have that level of access [7](#0-6) .

### Impact Explanation
An unauthenticated network attacker with access to the node's HTTP API can enumerate registered LOOP plugins via `/discovery`, then pull full pprof heap dumps, goroutine traces, and CPU profiles for each plugin. Heap/goroutine dumps can contain sensitive in-memory data (private key material, secrets, internal addresses), and profiling data reveals internal code structure, function names, and call graphs — enabling reconnaissance analogous to the SQL-schema/access-control disclosure in the source CVE.

### Likelihood Explanation
High for any deployment where the web server port is reachable by unprivileged/unauthenticated clients (e.g., misconfigured network boundary, or intentionally internet-facing operator UI port), since no credentials, session, or token are required — only network reachability to the routes.

### Recommendation
Move `loopRoutes` registration to an authenticated route group (mirroring how `metricRoutes` is nested under `authv2`), or wrap it with `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)` / an admin-role check before exposing `/discovery`, `/plugins/:name/metrics`, and `/plugins/:name/debug/pprof/*`.

### Proof of Concept
1. Start a Chainlink node with at least one LOOP plugin registered.
2. Without any session cookie or API token, send `GET /discovery` to enumerate plugin names and ports.
3. Send `GET /plugins/<name>/debug/pprof/heap?debug=1` without authentication; the response returns the plugin's raw pprof heap profile, forwarded unauthenticated by `pluginPPROFHandler`.

// pluginMetricHandlers routes from endpoints published in service discovery to the backing LOOP endpoint
func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/metrics", l.loopHostName, p.EnvCfg.PrometheusPort)
	req, err := http.NewRequestWithContext(gc.Request.Context(), http.MethodGet, pluginURL, nil)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)
	if err != nil {
		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q metrics", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}

const PPROFOverheadSeconds = 30

func pprofURLVals(gc *gin.Context) (urlVals url.Values, timeout time.Duration) {
	urlVals = make(url.Values)
	if db, ok := gc.GetQuery("debug"); ok {
		urlVals.Set("debug", db)
	}
	if gc, ok := gc.GetQuery("gc"); ok {
		urlVals.Set("gc", gc)
	}
	timeout = PPROFOverheadSeconds * time.Second
	if sec, ok := gc.GetQuery("seconds"); ok {
		urlVals.Set("seconds", sec)
		if i, err := strconv.Atoi(sec); err == nil {
			timeout = time.Duration(i+PPROFOverheadSeconds) * time.Second
		}
	}
	return urlVals, timeout
}

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}

func (l *LoopRegistryServer) pluginPPROFPOSTSymbolHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/symbol", l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	body, err := io.ReadAll(gc.Request.Body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error reading plugin pprof request body: %s", err))
		return
	}
	l.doRequest(gc, "POST", pluginURL, bytes.NewReader(body), timeout, pluginName)
}
