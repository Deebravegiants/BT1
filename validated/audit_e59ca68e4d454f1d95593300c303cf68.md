### Title
`CallDispatcher.dispatch()` has no caller restriction, letting anyone drain any balance the shared dispatcher is holding - ([File: evm/src/utils/CallDispatcher.sol])

### Summary
`CallDispatcher.dispatch()` is a public, unauthenticated function that executes an arbitrary attacker-supplied `Call[]` (target, value, calldata) against any contract with code. It is the shared execution primitive `IntentGatewayV2`/`ExtrinsicIntents`/`IntrinsicIntents` (and `HyperFungibleTokenUpgradeable`) use to run predispatch/postdispatch calldata and to sweep intermediate token/ETH balances back to the calling app. Because `dispatch()` has no `onlyGateway`/`onlyHost` check, exactly like the DODO `executeOperation()` bug, anyone can invoke the privileged execution step directly whenever the dispatcher is holding funds it hasn't yet swept, and steal them.

### Finding Description
`CallDispatcher.dispatch(bytes memory encoded)` decodes an ABI-encoded `Call[]` and blindly executes each call with the dispatcher's own balance, with no `msg.sender` check whatsoever: [1](#0-0) 

This contract is not a private, per-order scratch space — it is a single shared instance referenced as `_params.dispatcher` and invoked repeatedly by `IntentsBase`/`IntrinsicIntents`/`ExtrinsicIntents` to run predispatch calls, postdispatch calls, and the subsequent "sweep" transfers back to the gateway: [2](#0-1) [3](#0-2) 

It also accepts arbitrary ETH via an unrestricted `receive()`: [4](#0-3) 

The sweep logic in `_execute` only forwards balances of the tokens explicitly listed in `order.output.assets` back to the gateway; any other token or leftover balance the postdispatch calldata produces (e.g. an unaccounted swap output, rounding remainder, or a stray direct ETH/token transfer to the dispatcher address) is left sitting on the `CallDispatcher` with no owner-only recovery path: [5](#0-4) 

Because `dispatch()` is callable by anyone, any such residual balance — or any balance the dispatcher happens to be holding at any point it's observable on-chain — can be swept out by a completely unrelated third party by simply calling `CallDispatcher.dispatch()` directly with a `Call[]` pointing `to` the token contract with `data` encoding `transfer(attacker, balance)`, or `to` an arbitrary target with attacker-chosen `value`/`data` to drain native ETH. This is functionally identical to the reported bug class: a callback/execution entrypoint meant to be reachable only as part of one legitimate, orchestrated flow is instead open to any caller, letting them hijack funds that are only supposed to be moved by the trusted orchestrator.

### Impact Explanation
Any ERC20 tokens or native ETH sitting on the `CallDispatcher` for any reason — unswept postdispatch dust outside the tracked `order.output.assets` set, ETH sent directly to it, or funds present during any multi-step composition — can be stolen outright by an arbitrary unprivileged address. This is direct, permanent theft of funds from a core protocol contract reachable from a single unprivileged transaction, matching High severity in the reference report (any user can call the privileged execution primitive and steal assets it holds).

### Likelihood Explanation
`dispatch()` requires no special permission, no proof, and no relationship to any order — a bot can simply monitor the `CallDispatcher` address's token/ETH balances and call `dispatch()` the moment any balance appears. The `CallDispatcher` is also a persistent, address-known singleton (deployed and referenced by `_params.dispatcher`), making it a stable, discoverable target rather than an ephemeral one.

### Recommendation
Restrict `CallDispatcher.dispatch()` to the authorized caller(s) that legitimately drive it (e.g., an `onlyGateway`/allow-list modifier set at construction, or deploy a dedicated dispatcher instance per gateway/app rather than sharing one across all callers), and ensure any leftover balance is swept for every token actually touched by the executed calls (not only the tokens enumerated in `order.output.assets`), or add an owner/gateway-only rescue function so third parties can never front-run legitimate fund movement.

### Proof of Concept
1. Any user sends ERC20 tokens (or ETH via the payable `receive()`) directly to the known `CallDispatcher` address, or the address ends up holding dust after a postdispatch swap involving a token that is not part of `order.output.assets`.
2. An attacker calls `CallDispatcher.dispatch(abi.encode(calls))` where `calls[0] = Call({to: token, value: 0, data: abi.encodeWithSelector(IERC20.transfer.selector, attacker, balance)})` (or, for ETH, `Call({to: attacker, value: address(dispatcher).balance, data: ""})`).
3. `dispatch()` executes the call with no check on `msg.sender`: [6](#0-5) 
4. The attacker receives the tokens/ETH that were meant to be swept back to the `IntentGatewayV2`/app contract, with no ability for the protocol to prevent it.

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }

    function _execute(Order calldata order, uint256 outputsLen) internal {
        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            } else {
                uint256 balance = IERC20(token).balanceOf(dispatcher);
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            }

            unchecked {
                ++i;
            }
        }

        if (sweepCount > 0) {

                finalCalls[i] = sweepCalls[i];
                unchecked {
                    ++i;
                }
            }
            ICallDispatcher(dispatcher).dispatch(abi.encode(finalCalls));
        }
    }
