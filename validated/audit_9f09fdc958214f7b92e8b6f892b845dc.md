### Title
Insolvent accounts with collateral above the $5 dust cap but below one base unit of every debt token can never be liquidated or permissionlessly cleaned — permanently stuck bad debt - (contracts/controller/src/positions/liquidation/math.rs)

### Summary
`liquidate` on an insolvent account trims each repayment leg down to whole token units so the paid USD never exceeds the collateral-backed quote. When the collateral-backed quote `floor(C / (1 + base))` is worth less than one base unit of every debt token, every kept leg rounds to zero, every offer is fully refunded, and `liquidate` reverts with `InvalidPayments` (16). At the same time, permissionless `clean_bad_debt` requires the collateral to be at or below the fixed ~$5 dust threshold. Any account that becomes insolvent while holding collateral in the band `(dust cap, one base unit of the cheapest debt token)` is therefore unreachable by both unprivileged cleanup paths: liquidation always reverts and `clean_bad_debt` always reverts. Only the owner-only `force_socialize_bad_debt` remains.

### Finding Description
On an insolvent account, `normalize_repayment_plan` sets the ideal repayment to the collateral-backed curve quote and calls `process_excess_payment`, which drops any leg whose kept amount rounds to zero whole units and refunds it entirely [1](#0-0) . If no leg survives, `process_liquidation` fails at `require_non_empty_payments` / `InvalidPayments` [2](#0-1) . The test `test_insolvent_liquidation_reverts_when_no_debt_unit_fits_the_backed_quote` demonstrates exactly this: $9 of collateral backing debt denominated in a $10-per-unit token — the estimate returns `max_payment_wad = 0`, all legs refunded, and `try_liquidate` reverts [3](#0-2) .

Independently, `clean_bad_debt_standalone` requires `is_socializable_bad_debt` (insolvent **and** collateral ≤ the $5 dust cap) [4](#0-3) . The gap: for a debt asset with few decimals and a high unit price (e.g., a 0–2 decimal token worth ≥ $6 per base unit), an insolvent account holding `$5 < C < unit_price` collateral fails both gates. `liquidate` reverts on every possible offer (any nonzero kept leg would overpay the quote), and `clean_bad_debt` reverts with `CannotCleanBadDebt`. The only remaining path is `process_force_socialize_bad_debt`, which is not permissionless [5](#0-4) .

### Impact Explanation
The debt is permanently stuck: it keeps accruing borrow interest (worsening the shortfall), `seize_positions`/index write-down cannot run, and the unbacked debt sits on the market's books indefinitely. This matches the accepted impact classes of protocol insolvency / contract unable to operate correctly, since the bad-debt write-down that `claim_revenue`, withdrawals, and the supply-index floor depend on cannot be triggered by anyone except the owner, and there is no documented guarantee the owner acts. The analog to the MySQL DOS class: a crafted/positions state renders a core operation unexecutable; here it is not a transient crash but a persistent liquidation/cleanup deadlock producing real insolvency, not merely fail-closed unavailability of a quote.

### Likelihood Explanation
Medium. An unprivileged borrower cannot fully control collateral valuation, but can deliberately construct the condition: supply a small amount of collateral, borrow a low-decimal high-unit-value asset, then let interest accrue or a price move push the account insolvent with residual collateral between $5 and one debt unit (e.g., ~$6–$9 for a $10-unit token). Borrow minima constrain debt size, not residual collateral, and partial liquidations/withdrawals of other collateral legs can be used to land collateral in the band. Once in the band, no unprivileged actor can clear the position at any price, so the attacker's cost is bounded by the dust collateral left behind.

### Recommendation
Close the band between "liquidatable" and "socializable." Options: (a) make `is_socializable_bad_debt` admit insolvent accounts whose collateral is below one base unit of each debt leg, not only the fixed $5 cap; (b) allow the insolvent trim to keep a fractional/ceiled leg when dropping it would leave zero payable legs (cap the kept leg at the quote rather than flooring to zero); or (c) grant a permissionless fallback that calls the `InsolventOnly` cleanup for accounts provably unliquidatable under the whole-unit rule. At minimum, document and monitor the gap and ensure a non-owner recovery path exists.

### Proof of Concept
1. List/assume a debt market whose token has `asset_decimals` such that one base unit is worth more than $5 (e.g., a 0-decimal token priced $10).
2. Attacker supplies ~$9 collateral and borrows the maximum allowed amount of that token (the harness already shows `EXP` with a $10 unit and debt of 2 units is constructible [6](#0-5) ).
3. Wait for accrual or a small price move so `C < D` (insolvent) with `C ≈ $9`.
4. Any liquidator calling `liquidate` with any `debt_payments`: `process_excess_payment` drops every leg (each kept amount floors to 0 whole units), the estimate shows `max_payment_wad = 0` and empty `seized_collaterals`, and execution reverts with `InvalidPayments` — confirmed by the existing test.
5. Any caller calling `clean_bad_debt(account_id)`: `is_socializable_bad_debt` rejects because `C > $5` — reverts with `CannotCleanBadDebt` [7](#0-6) .
6. Debt accrues forever; only the privileged `force_socialize_bad_debt` can clear it.

*Uncertainty note:* whether $5 is the exact compiled constant for the dust cap was inferred from the docs/tests (`"fixed $5 dust threshold"`, `is_socializable_bad_debt`); the constant's definition file wasn't read. The deadlock logic itself is confirmed by `liquidation_extreme.rs:721-744` and `mod.rs:229-235`.

/// $9 of collateral backs $8.57, less than one $10 EXP unit: the estimate
/// keeps no repayment and refunds the whole offer, and execution reverts.
#[test]
fn test_insolvent_liquidation_reverts_when_no_debt_unit_fits_the_backed_quote() {
    let (mut t, account_id) = insolvent_book_with_a_ten_dollar_unit(usd(9) / 1_000);
    let exp = t.resolve_asset("EXP");
    let payments = vec![&t.env, (hub_asset(exp.clone()), 2)];
    let estimate =
        t.ctrl_client()
            .get_liquidation_estimate(&account_id, &payments, &SeizeMode::Transfer);
    assert_eq!(estimate.max_payment_wad, 0);
    assert!(estimate.seized_collaterals.is_empty());
    let refund = estimate.refunds.get(0).expect("EXP refund");
    assert_eq!((refund.asset, refund.amount), (exp, 2));

    let liquidator = t.get_or_create_user(LIQUIDATOR);
    t.resolve_market("EXP").token_admin.mint(&liquidator, &2);
    let result = map_try_ok_value(t.ctrl_client().try_liquidate(
        &liquidator,
        &account_id,
        &payments,
        &SeizeMode::Transfer,
    ));
    assert_contract_error(result, errors::INVALID_PAYMENTS);
    assert_eq!(t.token_balance_raw(LIQUIDATOR, "EXP"), 2);
    assert_eq!(t.borrow_balance_raw(ALICE, "EXP"), 2);
