**Analysis:**

The premise that `object::burn`/`unburn` round-trips `TombStone.original_owner` or `ObjectCore.owner` through `from_bcs::to_address` does not match the actual code. In `unburn`, `from_bcs::to_address` is never used to reconstruct owner-related state — it is used elsewhere in the module solely for deterministic address derivation (`create_object_address`, `create_guid_object_address`, `create_user_derived_object_address`), which operate on hash digests, not on attacker-controlled ownership data. [1](#0-0) 

`TombStone.original_owner` is assigned directly from `signer::address_of(owner)` — an authenticated value derived from the transaction's signer, not from any BCS-deserialized byte buffer: [2](#0-1) 

`unburn` only permits two paths: (1) the current `ObjectCore.owner` matches the caller's signer address (simple tombstone removal, no ownership change), or (2) the current owner is the fixed `BURN_ADDRESS` and the caller's signer address matches `TombStone.original_owner` exactly, triggering `transfer_raw_inner` back to that address. Any other caller aborts with `ENOT_OBJECT_OWNER`. [3](#0-2) 

Move's resource model prevents an unprivileged caller from injecting arbitrary bytes into `TombStone` or `ObjectCore` fields — these are typed structs stored via `move_to`/`borrow_global_mut` inside `object.move`, not raw byte blobs subject to `from_bcs` decoding from external input. `from_bcs::to_address` itself is a generic native deserializer used for constructing values from trusted, module-internal byte sequences (e.g., hash outputs), and has no code path that writes into `TombStone.original_owner` or `ObjectCore.owner`. [4](#0-3) 

The existing test `test_burn_and_unburn_old` already validates that `unburn` restores ownership only to the exact original creator address recorded at burn time: [5](#0-4) 

Since there is no unprivileged entrypoint that lets an attacker supply or tamper with the bytes backing `TombStone.original_owner` or `ObjectCore.owner`, and both fields are set from authenticated signer addresses rather than externally-controlled BCS payloads, the described attack path does not exist in this codebase.

    public entry fun burn<T: key>(owner: &signer, object: Object<T>) {
        let original_owner = signer::address_of(owner);
        assert!(is_owner(object, original_owner), error::permission_denied(ENOT_OBJECT_OWNER));
        let object_addr = object.inner;
        assert!(!exists<TombStone>(object_addr), EOBJECT_ALREADY_BURNT);
        move_to(&create_signer(object_addr), TombStone { original_owner });
    }

    /// Allow origin owners to reclaim any objects they previous burnt.
    public entry fun unburn<T: key>(
        original_owner: &signer,
        object: Object<T>,
    ) {
        let object_addr = object.inner;
        assert!(exists<TombStone>(object_addr), error::invalid_argument(EOBJECT_NOT_BURNT));

        // The new owner of the object can always unburn it, but if it's the burn address, we go to the old functionality
        let object_core = borrow_global<ObjectCore>(object_addr);
        if (object_core.owner == signer::address_of(original_owner)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object_addr);
        } else if (object_core.owner == BURN_ADDRESS) {
            // The old functionality
            let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
            assert!(
                original_owner_addr == signer::address_of(original_owner),
                error::permission_denied(ENOT_OBJECT_OWNER)
            );
            transfer_raw_inner(object_addr, original_owner_addr);
        } else {
            abort error::permission_denied(ENOT_OBJECT_OWNER);
        };
    }
