### Title
Stale `TombStone.original_owner` on ordinary object transfers lets a former owner reclaim a burnt object from a subsequent legitimate owner - (File: `aptos-move/framework/aptos-framework/sources/object.move`)

### Summary
The Aptos Object model's "soft burn" feature (`object::burn` / `object::unburn`) records a `TombStone{original_owner}` resource on the object without changing its `owner` field or disabling ungated transfer. This `TombStone` is cleared only in the `LinearTransferRef`-based path (`transfer_with_ref`), but **not** in the ordinary owner-signer transfer path (`transfer`, `transfer_call`, `transfer_to_object`, all backed by `transfer_raw_inner`). This asymmetry lets a prior owner who "burned" (tomb-stoned) an object before selling/transferring it away later reclaim that object from the well-known `BURN_ADDRESS` even after a subsequent, legitimate owner sends it there, hijacking the object's ownership.

### Finding Description
`object::burn` creates a `TombStone` without moving ownership or revoking transferability: [1](#0-0) 

`object::unburn` grants reclaim rights based purely on the recorded `TombStone.original_owner` once the object's current owner is `BURN_ADDRESS`: [2](#0-1) 

The only place `TombStone` is cleared during a transfer is `transfer_with_ref` (the `LinearTransferRef` path): [3](#0-2) 

However, the standard signer-based transfer functions that most apps/marketplaces use go through `transfer_raw` / `transfer_raw_inner`, which only update `owner` and never touch `TombStone`: [4](#0-3) 

Exploit path:
1. Attacker A owns object `O`. A calls `object::burn(A, O)`, attaching `TombStone{original_owner: A}`. `O`'s owner remains `A`, and ungated transfer is untouched (still enabled).
2. A transfers/sells `O` to victim B via the normal `object::transfer` entry function. Ownership moves to B, but the stale `TombStone{original_owner: A}` is never removed because `transfer_raw_inner` doesn't handle `TombStone`.
3. B, now the legitimate owner, later sends `O` to the well-documented `BURN_ADDRESS` (`0xfff...ff`, described in the module as "Address where unwanted objects can be forcefully transferred to") via a normal `object::transfer(B, O, BURN_ADDRESS)` call, intending to permanently discard it.
4. A calls `object::unburn(A, O)`. Since `owner == BURN_ADDRESS` and the stale `TombStone.original_owner == A`, the assert passes and `transfer_raw_inner` reassigns ownership of `O` back to A — not B.

The broken invariant is that `TombStone.original_owner` should always represent whoever is entitled to reclaim the currently-tomb-stoned object, but it can become stale and point to an unrelated, unprivileged former owner because ordinary ungated transfers don't purge or refresh it.

### Impact Explanation
This is an unauthorized owner reassignment of an Aptos Object to an unprivileged, non-current party, in direct violation of the custody invariant that object ownership and burn/reclaim rights must track the true current/intended owner. Any object type that supports the default `object::transfer` path (e.g., token-v2 digital assets, or any object whose underlying value — fungible asset stores, NFTs, capabilities — is transferred without disabling ungated transfer) is affected. A malicious former holder can pre-plant a tombstone before selling/transferring an asset, then later steal it back from a good-faith buyer/holder the moment that holder performs what looks like a normal, application-encouraged "burn" action. This directly maps to "Unauthorized takeover of ... owner reassignment ... tied to live assets" and "Supply or custody accounting corruption that moves value to the wrong holder."

### Likelihood Explanation
No privileged capability is required by the attacker beyond being a prior owner of the object, and the trigger condition (a later legitimate owner sending the object to `BURN_ADDRESS`) is a documented, expected usage pattern of the burn address rather than an obscure edge case. The attack requires the attacker to plan ahead (burn before transferring away), which is a normal action available to any object owner, and success depends only on the eventual holder later transferring the object to `BURN_ADDRESS` through the standard `transfer`/`transfer_call` path.

### Recommendation
Clear (or update) any existing `TombStone` resource in `transfer_raw_inner` (or at minimum in `transfer_raw`) whenever ownership actually changes, mirroring the cleanup already performed in `transfer_with_ref`. Alternatively, disallow ungated transfer of an object while it carries a `TombStone`, or bind `unburn` eligibility to something that cannot become stale (e.g., require the reclaiming caller to have been the owner immediately prior to the transfer into `BURN_ADDRESS`, not merely the address recorded at burn time).

### Proof of Concept
```
// Pseudocode using object.move public/entry API
// A owns O
object::burn(A, O);                     // TombStone{original_owner: A}, owner still A, ungated transfer still on
object::transfer(A, O, B);              // ordinary transfer: owner -> B, TombStone NOT cleared
// ... time passes, B is unaware O still carries a stale TombStone ...
object::transfer(B, O, BURN_ADDRESS);   // B intends to permanently destroy O
object::unburn(A, O);                   // succeeds: owner reassigned back to A, stealing O from B
assert!(object::owner(O) == A, 0);      // A regained control despite no longer being the rightful owner
```

    /// Transfer to the destination address using a LinearTransferRef.
    public fun transfer_with_ref(self: LinearTransferRef, to: address) {
        assert!(!exists<Untransferable>(self.self), error::permission_denied(EOBJECT_NOT_TRANSFERRABLE));

        // Undo soft burn if present as we don't want the original owner to be able to reclaim by calling unburn later.
        if (exists<TombStone>(self.self)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(self.self);
        };

        let object = borrow_global_mut<ObjectCore>(self.self);
        assert!(
            object.owner == self.owner,
            error::permission_denied(ENOT_OBJECT_OWNER),
        );
        event::emit(
            Transfer {
                object: self.self,
                from: object.owner,
                to,
            },
        );
        object.owner = to;
    }

        let object_core = borrow_global_mut<ObjectCore>(object);
        if (object_core.owner != to) {
            event::emit(
                Transfer {
                    object,
                    from: object_core.owner,
                    to,
                },
            );
            object_core.owner = to;
        };

    /// Allow origin owners to reclaim any objects they previous burnt.
    public entry fun unburn<T: key>(
        original_owner: &signer,
        object: Object<T>,
    ) {
        let object_addr = object.inner;
        assert!(exists<TombStone>(object_addr), error::invalid_argument(EOBJECT_NOT_BURNT));

        // The new owner of the object can always unburn it, but if it's the burn address, we go to the old functionality
        let object_core = borrow_global<ObjectCore>(object_addr);
        if (object_core.owner == signer::address_of(original_owner)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object_addr);
        } else if (object_core.owner == BURN_ADDRESS) {
            // The old functionality
            let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
            assert!(
                original_owner_addr == signer::address_of(original_owner),
                error::permission_denied(ENOT_OBJECT_OWNER)
            );
            transfer_raw_inner(object_addr, original_owner_addr);
        } else {
            abort error::permission_denied(ENOT_OBJECT_OWNER);
        };
    }
