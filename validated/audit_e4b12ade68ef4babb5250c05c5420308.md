Audit Report

## Title
Unprivileged actor can spam pending capability callbacks to evict legitimate in-flight requests via `pruneCallbacks` halving - (File: `core/services/gateway/handlers/capabilities/handler.go`)

## Summary
`HandleLegacyUserMessage` inserts a new entry into `h.savedCallbacks` for every valid-but-unauthenticated-by-allowlist message, and the periodic `pruneCallbacks` routine enforces `MaxSavedCallbacks` by unconditionally deleting the oldest surviving entries down to half capacity, regardless of whether those entries represent legitimate work still awaiting a node response. [1](#0-0) [2](#0-1)  The code itself flags the missing control with `// TODO: apply allowlist and rate-limiting here`. [3](#0-2) 

## Finding Description
The only requirements to insert a `savedCallback` are a syntactically valid, ECDSA-signed message (any keypair works — `Message.Validate()` only checks field lengths and recovers a signer address, it does not check the signer against any allowlist) with a non-stale timestamp and method `MethodWebAPITrigger`. [4](#0-3) [5](#0-4)  Any caller of the gateway's public HTTP endpoint (`gateway.ProcessRequest` → `HandleLegacyUserMessage`) can self-sign a fresh ECDSA keypair, forge as many distinct, well-formed `web_api_trigger` messages as desired, and each one occupies a new slot in `savedCallbacks`. [6](#0-5)  There is no per-sender/per-caller check before the entry is stored — the comment explicitly acknowledges allowlisting and rate-limiting are not yet implemented at this call site. [3](#0-2) 

Once the map exceeds `MaxSavedCallbacks` (default 20000), `pruneCallbacks` sorts by `createdAt` and deletes all but the newest `maxSize/2` entries — a hard "evict legitimate old entries to make room" behavior, confirmed by the existing unit test `TestHandler` (`"enforces max size by evicting oldest"`), which shows only the single newest entry survives even though the older three are still live/unexpired. [7](#0-6)  This contrasts with `RequestCache.NewRequest`, which rejects new entries instead of evicting existing ones once full [8](#0-7) , and with the v2 HTTP trigger handler's `reapExpiredCallbacks`, which only removes callbacks that are actually past TTL, not based on a size cap. [9](#0-8) 

## Impact Explanation
If an attacker generates ≥`MaxSavedCallbacks`/2 (10,000 by default) new distinct `web_api_trigger` requests within roughly a `CallbackPruneIntervalSec` window (30s default) faster than legitimate node responses arrive, `pruneCallbacks` will evict older, still-pending legitimate callers' entries before the corresponding DON node response arrives via `handleWebAPITriggerMessage`. The victim's `savedCallbacks` lookup then fails silently (`found == false`), the response is dropped, and the caller only observes a timeout via `callback.Wait(ctx)` in `gateway.ProcessRequest`. [10](#0-9) [11](#0-10)  This is a genuine denial-of-service / dropped-response condition affecting other users of the same gateway/DON handler, consistent with the "cross-user response confusion/DoS" impact category.

## Likelihood Explanation
No allowlist or per-sender/global rate limiting gates entry into `savedCallbacks` at `HandleLegacyUserMessage` — the code explicitly documents this gap with a TODO. [3](#0-2)  The only cost to the attacker is generating a fresh ECDSA signature per message (cheap, off-chain, no on-chain cost) and sending an HTTP request to the gateway's user-facing endpoint, which requires no privileged credential. `nodeRateLimiter` in this file only limits outgoing messages **from nodes** (`handleWebAPIOutgoingMessage`), not user-submitted trigger requests reaching `HandleLegacyUserMessage`, so it provides no protection against this vector. [12](#0-11)  The default threshold (20,000 entries, 30s prune interval) is high but not prohibitive for a scripted attacker able to sustain thousands of signed requests per interval, and the test file itself contains a `TODO: Validate Senders and rate limit check, pending question in trigger about where senders and rate limits are validated`, confirming this gap is known/unresolved in the codebase. [13](#0-12) 

## Recommendation
Add per-sender/global rate limiting or an allowlist check to `HandleLegacyUserMessage` before a `savedCallback` slot is allocated (as the existing TODO comment indicates was intended), and change `pruneCallbacks`'s overflow handling to reject new callback creation once at capacity (mirroring `RequestCache.NewRequest`'s "cache is full" rejection) rather than silently evicting existing, unexpired, legitimately pending entries.

## Proof of Concept
1. Deploy the gateway with default config (`MaxSavedCallbacks=20000`, `CallbackPruneIntervalSec=30`, `CallbackMaxAgeSec=120`).
2. As an unprivileged actor with no DON/gateway credentials, generate N ephemeral ECDSA keypairs and sign N distinct, well-formed `web_api_trigger` legacy `api.Message`s (valid timestamp, valid method) via `Message.Sign`.
3. Concurrently submit a legitimate victim request (`web_api_trigger`) to the same gateway/DON, expecting a node response before its `CallbackMaxAgeSec` expires.
4. Flood the gateway's `ProcessRequest` HTTP endpoint with the N forged messages so that `len(h.savedCallbacks) > MaxSavedCallbacks` when `pruneCallbacks` runs on its next tick.
5. Observe (as demonstrated by the existing unit test `TestHandler/"enforces max size by evicting oldest"` in `handler_test.go`, lines 518-539) that the victim's still-pending, unexpired entry is deleted from `savedCallbacks` if it is not among the newest `MaxSavedCallbacks/2` entries, causing the victim's subsequent node response to be silently dropped in `handleWebAPITriggerMessage` (`found == false`) and the victim's `callback.Wait` call to time out.

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageID]
	delete(h.savedCallbacks, msg.Body.MessageID)
	h.mu.Unlock()

	if found {

		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
}

// reapExpiredCallbacks removes callbacks that are older than the maximum age
func (h *httpTriggerHandler) reapExpiredCallbacks(ctx context.Context) {
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()
	now := time.Now()
	var expiredCount int
	for reqID, callback := range h.callbacks {
		if now.Sub(callback.createdAt) > time.Duration(h.config.CleanUpPeriodMs)*time.Millisecond {
			if !callback.processed {
				h.metrics.IncrementRequestErrors(ctx, jsonrpc.ErrInternal, h.lggr)
			}
			h.cleanupCallback(reqID)
			expiredCount++
		}
	}
	if expiredCount > 0 {
		h.metrics.IncrementPendingRequestsCleanUpCount(ctx, int64(expiredCount), h.lggr)
		h.lggr.Infow("Removed expired callbacks", "count", expiredCount, "remaining", len(h.callbacks))
	}
	h.metrics.RecordPendingRequestsCount(ctx, int64(len(h.callbacks)), h.lggr)
}
