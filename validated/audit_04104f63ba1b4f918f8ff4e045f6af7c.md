Audit Report

## Title
Cross-user response hijacking via attacker-controlled `MessageID` collision in `WebAPIHandler.HandleLegacyUserMessage` - ([File: core/services/gateway/handlers/capabilities/handler.go])

## Summary
The gateway's legacy WebAPI trigger handler stores a caller's response callback in a shared map keyed solely by the client-supplied `MessageID`, with no check for an existing in-flight entry and no binding between the `MessageID` and the message signer's identity. Any unprivileged client capable of generating an ECDSA keypair can sign a request using a `MessageID` already in use by another party, silently overwriting that party's saved callback, so that the eventual DON response for that `MessageID` is delivered to the attacker instead of the legitimate requester.

## Finding Description
`gateway.ProcessRequest` routes legacy DON-ID requests to `h.HandleLegacyUserMessage(ctx, msg, callback)` after only structural/signature validation via `msg.Validate()` [1](#0-0) . `Message.Validate()` checks signature format/length and derives `m.Body.Sender` from the signature, but it performs no uniqueness check on `MessageID`, nor does it tie `MessageID` to any pre-registered session or prevent a different signer from reusing an ID already active for another signer [2](#0-1) . Because message signing only requires an ECDSA private key (trivially generated by any unprivileged actor, no registration needed) [3](#0-2) , any client can produce a validly-signed message with an arbitrary, attacker-chosen `MessageID`.

Inside `handler.HandleLegacyUserMessage`, the callback is registered unconditionally, overwriting any prior entry under the same key with no conflict check:
```go
h.mu.Lock()
h.savedCallbacks[msg.Body.MessageID] = &savedCallback{id: msg.Body.MessageID, createdAt: time.Now(), Callback: callback}
don := h.don
h.mu.Unlock()
``` [4](#0-3) 

When the DON later responds, routing is purely by `MessageID`:
```go
h.mu.Lock()
savedCb, found := h.savedCallbacks[msg.Body.MessageID]
delete(h.savedCallbacks, msg.Body.MessageID)
h.mu.Unlock()

if found {
    codec := api.JSONRPCCodec{}
    return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
}
``` [5](#0-4) 

The newer `httpTriggerHandler.setupCallback` explicitly guards against this exact scenario by rejecting duplicate in-flight request IDs with `jsonrpc.ErrConflict`, confirming this is a recognized bug class that was fixed in the newer code path but left unaddressed in the legacy handler [6](#0-5) .

## Impact Explanation
An unprivileged client of the gateway's legacy DON-ID endpoint can evict/overwrite another in-flight caller's saved callback simply by signing a request with a colliding `MessageID`, causing that caller's request to time out (denial of service) and causing the DON's eventual response for that `MessageID` to be delivered to the attacker's callback instead — cross-user response confusion/disclosure of another workflow's trigger result. This maps to the in-scope "cross-user response corruption" impact class.

## Likelihood Explanation
Exploitability requires only that the attacker know or predict a `MessageID` used by a victim within the callback TTL (`defaultCallbackMaxAgeSec = 120`s) [7](#0-6) . No credentials, roles, or special access are needed — signing requires only a self-generated ECDSA key. If client `MessageID`s are predictable (sequential, timestamp-derived, or derived from public workflow/execution identifiers as in `getMessageID`), collision is straightforward; even without prediction, this is trivially exploitable whenever two callers intentionally or accidentally choose the same ID, since the legacy handler does nothing to prevent it.

## Recommendation
- In `HandleLegacyUserMessage`, reject requests whose `MessageID` already has an active entry in `savedCallbacks`, mirroring the conflict check in `httpTriggerHandler.setupCallback`.
- Bind saved callbacks to `(Sender, MessageID)` rather than `MessageID` alone, or otherwise scope callback lookup/storage per authenticated signer.
- Migrate the legacy WebAPI trigger path onto the `httpTriggerHandler` model, which already implements this protection.

## Proof of Concept
1. Generate two distinct ECDSA keypairs (attacker A, victim B) — no registration required.
2. A signs and sends a legacy JSON-RPC message to the gateway with `MessageID = "X"`, `Method = web_api_trigger`, targeting a DON; `HandleLegacyUserMessage` stores `savedCallbacks["X"] = callbackA`.
3. Before the DON responds, B signs and sends a message also using `MessageID = "X"`; `HandleLegacyUserMessage` overwrites `savedCallbacks["X"] = callbackB` with no conflict check (`core/services/gateway/handlers/capabilities/handler.go:411-414`).
4. When a DON node responds for `MessageID = "X"`, `handleWebAPITriggerMessage` looks up `savedCallbacks["X"]`, finds `callbackB`, and delivers the response to B (`core/services/gateway/handlers/capabilities/handler.go:148-161`) — demonstrating cross-user response confusion caused by trusting an unauthenticated-uniqueness, attacker-controlled `MessageID` as the sole routing key.
A Go unit test can directly instantiate `handler`, call `HandleLegacyUserMessage` twice with distinct signed messages sharing the same `MessageID` but different callbacks, then call `HandleNodeMessage`/`handleWebAPITriggerMessage` and assert the second (attacker's) callback receives the response while the first is dropped.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageID) == 0 || len(m.Body.MessageID) > MessageIDMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageID, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonID) == 0 || len(m.Body.DonID) > MessageDonIDMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonID, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageID]
	delete(h.savedCallbacks, msg.Body.MessageID)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JSONRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
