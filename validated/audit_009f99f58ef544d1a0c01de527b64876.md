### Title
Stale `IMPORT_FLAG`/`importParams` survive `delete()`, causing a deleted wallet to be silently re-imported with attacker-controlled seed material - (File: features/application/src/modules/application.ts)

### Summary
`import()` with `forceRestart` (or when a wallet already exists) persists `IMPORT_FLAG` and an `importParams` blob (containing the imported mnemonic/seed result) in `#flagsStorage`/`#storage`, and expects a full app restart to consume and clear them [1](#0-0) . `delete()` only sets `DELETE_FLAG` and clears `RESTORE_FLAG` — it never clears `IMPORT_FLAG` or the stored `importParams` [2](#0-1) . If `delete()` is invoked while a pending import's flags are still on disk (i.e., before the process restart that `import()`'s `Hook.Restart` is supposed to trigger), the next `start()` observes both `isDeleting` and `isImporting` as true, wipes the wallet via `wallet.clear()`, and then re-imports the stale, previously attacker-influenced `importParams` from storage — reinstating a wallet the user believed was deleted.

### Finding Description
The three persistent flags (`DELETE_FLAG`, `IMPORT_FLAG`, `RESTORE_FLAG`) are the only mechanism coordinating deferred delete/import/restore logic across process restarts, as documented in the source comments [3](#0-2) .

In `import()`, when `forceRestart || walletExists`, the code performs the real crypto import (`this.#wallet.import(wallet)`), then stores `IMPORT_FLAG=true` and `importParams` (including `importResult` and `seedId`) in `#storage`, and fires `Hook.Restart` expecting the host app to restart the process before these flags are consumed: [1](#0-0) 

`start()` is the only place that consumes and clears `IMPORT_FLAG`/`importParams`, and it does so together with `DELETE_FLAG` in the same `batchDelete` — but only once `start()` actually executes: [4](#0-3) 

`delete()`, however, does not touch `IMPORT_FLAG` or the `importParams` entry in `#storage` at all: [2](#0-1) 

Because `Hook.Restart` is just an emitted lifecycle event (its actual effect — killing/relaunching the process — is implemented by the host/native layer outside this module, per `sdks/headless/src/index.js`'s `application.on('restart', ...)` wiring [5](#0-4) ), there is a window between `import()` setting `IMPORT_FLAG`/`importParams` and the actual restart occurring. If, during that window, `delete()` is called (e.g., the user aborts the import and chooses "delete wallet", or an app-level race triggers both flows), the following happens on the eventual `start()`:

1. `deleteFlag = true`, `importFlag = true` are both read.
2. `isDeleting` is true → `wallet.clear()` wipes the wallet.
3. Both flags are deleted from `#flagsStorage` (masking that anything was wrong).
4. Because `isImporting` is also true, `Hook.Clear` fires, and then `Hook.Import` fires with the **stale** `importParams` object that was written by the earlier `import()` call (this is the "stale seed reuse").
5. Any listener on `onImport` (e.g., wallet-accounts/personal-notes plugins per README hook table ) will treat the wallet as freshly imported using data belonging to that earlier import call, not the delete the user just requested.

This means `delete()`'s emitted lifecycle events/hooks do not reflect the final committed state (a deleted, empty wallet); they instead reflect a stale pre-existing import request, violating the stated invariant that lifecycle hooks/events must reflect committed security state, not transient pre-validation state. The end effect is that a wallet the user explicitly asked to delete comes back with attacker- or previously-supplied seed material (e.g., from a malicious mnemonic supplied through an import/restore flow reachable from normal usage, such as a deeplink- or QR-driven "import wallet" action with `forceRestart: true`).

No code path in `delete()` performs `this.#flagsStorage.delete(IMPORT_FLAG)` or `this.#storage.delete('importParams')`, so nothing currently blocks this sequence.

### Impact Explanation
An attacker who can get the victim to run an `import()` call with `forceRestart: true` and attacker-supplied mnemonic/seed content (e.g., via a "restore/import" deeplink or QR flow that legitimately reaches `Application.import`) can leave that seed staged in `importParams`. If the victim subsequently triggers `delete()` before the actual restart completes, the deletion is subverted: the wallet is wiped and then silently re-populated with the attacker's staged seed. This matches "Private key or private key generation leakage leading to unauthorized access to user funds" because the resulting active wallet account is derived from attacker-supplied key material without the user's informed consent, and funds subsequently deposited/interacted with by the user go into a wallet the attacker controls the seed for.

### Likelihood Explanation
Preconditions: (1) reaching `Application.import()` with `forceRestart: true` or on top of an existing wallet — reachable via normal import/restore UI flows that accept externally-sourced mnemonics (QR/deeplink import is a common pattern in this codebase per `sdks/headless/__tests__/wallet.test.js` tests around `forceRestart`) [6](#0-5) ; (2) `delete()` is invoked before the host process actually restarts in response to the emitted `Hook.Restart`/`restart` event. Because restart is asynchronous and host-controlled (not synchronous within `Application`), this window is plausible in real app usage (e.g., a slow native relaunch, or the user cancels/retries during the import UI before restart completes). No privileged access or key leakage is required — only that the attacker can supply the mnemonic used in a reachable import call and the normal user application flow ends up calling `delete()` in that window.

### Recommendation
In `Application.delete()`, clear the import-related deferred state along with `DELETE_FLAG`/`RESTORE_FLAG`, e.g.:
```ts
delete = async (opts: DeleteApplicationParams = {}) => {
  const { forgotPassphrase, restartOptions } = opts
  await this.#flagsStorage.set(DELETE_FLAG, true)
  await this.#flagsStorage.delete(RESTORE_FLAG)
  await this.#flagsStorage.delete(IMPORT_FLAG)
  await this.#storage.delete('importParams')
  await this.#storage.delete('backupType')
  await this.fire(Hook.Restart, { ...restartOptions, reason: 'delete', forgotPassphrase })
}
```
Additionally, in `start()`, prioritize an explicit `isDeleting` state such that a pending delete always wins over a stale import (i.e., don't fire `Hook.Import` with leftover `importParams` when `isDeleting` is also true), and consider making `DELETE_FLAG`/`IMPORT_FLAG` mutually exclusive at write time (setting one should always clear the other) rather than relying solely on `start()` to reconcile them.

### Proof of Concept
Unit test plan (Jest style, based on existing test patterns in `sdks/headless/__tests__/wallet.test.js`):

```js
test('delete() during a pending forceRestart import must not resurrect the stale imported seed', async () => {
  await exodus.application.start()
  await exodus.application.create({ passphrase })

  // Attacker-influenced import staged for restart, but process has not restarted yet
  const attackerMnemonic = 'attacker mnemonic words ...'
  await exodus.application.import({ passphrase, mnemonic: attackerMnemonic, forceRestart: true })

  // Before the host actually restarts, user decides to delete the wallet instead
  await exodus.application.delete()

  // Simulate the eventual actual process restart
  const newPort = new Emitter()
  const newExodus = createExodus({ adapters: { ...adapters, port: newPort }, config }).resolve()
  await newExodus.application.start()

  // Expected: wallet should NOT exist (delete should win), and the attacker mnemonic
  // must never have been re-imported.
  await expect(newExodus.wallet.exists()).resolves.toBe(false)
})
```
Assertions to add for full coverage:
- Assert no `import`/`onImport` event fires after `delete()` wins the race (spy on `application.on('import', ...)`).
- Assert `#storage.get('importParams')` is empty/undefined after `delete()`.
- Assert `getMnemonic()` never resolves to `attackerMnemonic` post-restart.

  start = async ({ restoring, importing }: StartApplicationParams = {}) => {
    const [deleteFlag, importFlag] = await this.#flagsStorage.batchGet([DELETE_FLAG, IMPORT_FLAG])

    if (restoring) {
      await this.#flagsStorage.set(RESTORE_FLAG, true)
    }

    const isDeleting = !!deleteFlag
    const isImporting = importing || !!importFlag

    if (isDeleting) await this.#wallet.clear()

    if (isDeleting || isImporting) {
      await this.#flagsStorage.batchDelete([DELETE_FLAG, IMPORT_FLAG])
      await this.#passphraseCache.clear()
    }

    const walletExists = await this.#wallet.exists()

    if (isImporting || !walletExists) {
      await this.#eventLog.record({
        event: 'app_state_clear_requested',
        applicationWillFireClearHookOpts: { isImporting, isDeleting, walletExists },
      })

      await this.fire(Hook.Clear, null, { concurrent: true })
    }

    if (isImporting) {
      const params = await this.#storage.get('importParams')
      await this.fire(Hook.Import, params)
      await this.#storage.delete('importParams')
    }
