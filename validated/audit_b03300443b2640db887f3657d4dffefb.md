## Analysis

CVE-2022-3854 is a Ceph RGW crash caused by an unvalidated (null) URL field reaching request-processing code and hard-crashing the whole request handler. The reachable analog in this codebase is `EvmHost.dispatchIncoming(PostRequest, address)`, which validates the `to` field only via a `revert`, and is invoked from `HandlerV2.handlePostRequests` without any per-leaf isolation — unlike the sibling "no contract at destination" case a few lines above it, which is explicitly handled with a non-reverting early return specifically to avoid poisoning the batch.

`EvmHost.dispatchIncoming` converts the request's `to` field to an address with `_bytesToAddress`, which reverts with `InvalidAddressLength()` if the byte length isn't exactly 20: [1](#0-0) 

That conversion happens unconditionally, before the "destination has no code" early return that was added *specifically* to prevent a bad leaf from reverting the whole batch: [2](#0-1) 

`HandlerV2.handlePostRequests` verifies a Merkle-Mountain-Range proof for a whole batch of leaves, then calls `host.dispatchIncoming(...)` directly (a plain external call, not a low-level `.call()`/try-catch) once per leaf in the batch: [3](#0-2) 

Only the downstream `IApp.onAccept` call inside `dispatchIncoming` is wrapped with a low-level `call` and success check, so an app-level failure doesn't abort the batch: [4](#0-3) 

`request.to` is arbitrary attacker/module-controlled bytes set at dispatch time on the source chain (e.g., a Substrate pallet or any `IDispatcher.dispatch` caller); there is no length enforcement anywhere I found on the source-chain dispatch path (`evm/src/core/EvmHost.sol` dispatch functions, `pallet-ismp` request construction) preventing a `to` value of any length other than 20 bytes from being posted and finalized into a Merkle-Mountain-Range commitment destined for an EVM host.

### Title
Malformed `to` address length in a batched PostRequest reverts and blocks delivery of the entire `handlePostRequests` batch - (File: `evm/src/core/EvmHost.sol`)

### Summary
`EvmHost.dispatchIncoming` reverts with `InvalidAddressLength()` when a `PostRequest.to` field is not exactly 20 bytes. Because `HandlerV2.handlePostRequests` calls `dispatchIncoming` directly (no try/catch) once per leaf of a proven MMR batch, a single request with a malformed `to` length reverts the whole transaction, aborting delivery of every other (legitimate) request batched in the same call.

### Finding Description
Any source-chain module that can dispatch an ISMP `PostRequest` destined for this EVM host controls the `to` field with no length validation enforced at dispatch time. When such a message, with `to.length != 20`, is later relayed via `HandlerV2.handlePostRequests`, `EvmHost._bytesToAddress` is invoked unconditionally inside `dispatchIncoming` and reverts before the existing "no code at destination" mitigation (an explicit early-return added to avoid exactly this batch-poisoning problem) can apply [5](#0-4) . Since `dispatchIncoming` is called as a plain external call rather than being wrapped in a low-level call/try-catch in the batch loop [6](#0-5) , the revert propagates and aborts the entire `handlePostRequests` transaction — exactly the CVE-2022-3854 bug class: an attacker-supplied malformed field that is hard-validated by revert instead of being gracefully rejected, crashing/aborting the shared request-processing path.

### Impact Explanation
Requests are proven and delivered in batches against a single MMR root for gas efficiency. A malformed leaf mixed into a batch causes the whole batch's delivery transaction to revert, denying delivery of every other, valid request in that same call — a denial-of-service on the message-delivery route. This matches the "route unable to deliver messages" acceptance criterion: relayers must detect and exclude the poison leaf (requiring off-chain awareness this bug doesn't otherwise necessitate) or fall back to submitting every request individually, degrading throughput and creating a griefing vector that any unprivileged cross-chain dispatcher can trigger cheaply and repeatedly.

### Likelihood Explanation
Reachable from a single dispatched cross-chain request originating on any connected source chain — no special privilege is required to set an arbitrary-length `to` byte string, since `to` is a raw bytes field chosen by whatever module/pallet performs the dispatch. Given the codebase's own comment at the adjacent early-return acknowledging the batch-revert risk ("instead of reverting the entire batch, early return here"), this length-validation path was evidently missed when that mitigation was added, making it plausible and directly analogous to the report's bug class.

### Recommendation
Treat a malformed `to` length the same way as "no contract at destination": have `dispatchIncoming` catch/guard against invalid length and return early instead of reverting, so a single bad leaf cannot abort an otherwise-valid batch. Alternatively/additionally, wrap the `host.dispatchIncoming` call in `HandlerV2.handlePostRequests` with a low-level call and per-leaf success handling, isolating failures the same way `IApp.onAccept` failures are already isolated.

### Proof of Concept
1. From a connected source chain, dispatch a `PostRequest` with `dest` set to the target EVM host's state machine and `to` set to a byte string of length ≠ 20 (e.g., 32 bytes, as is natural for a Substrate-originated destination encoding).
2. Include this request's commitment in the same block/MMR window as N other legitimate PostRequests destined for the same EVM host.
3. Relay/prove the batch via `HandlerV2.handlePostRequests` including all N+1 leaves.
4. Observe the whole transaction reverts with `InvalidAddressLength()` inside `EvmHost.dispatchIncoming` [5](#0-4) , and none of the N legitimate requests are delivered, despite valid proofs and timeouts not having elapsed.

I was not able to fully verify from the available index whether every connected source-chain dispatch path (e.g., a specific pallet's outbound request construction) enforces a 20-byte `to` for EVM-bound destinations; this would need to be confirmed in a full checkout, since it determines whether the malformed field can realistically originate innocently (encoding bugs) versus only via a deliberately malicious dispatcher.

    function dispatchIncoming(PostRequest memory request, address relayer) external restrict(_hostParams.handler) {
        address destination = _bytesToAddress(request.to);
        uint256 size;
        assembly {
            size := extcodesize(destination)
        }
        if (size == 0) {
            // instead of reverting the entire batch, early return here.
            return;
        }

        // replay protection
        bytes32 commitment = request.hash();
        _requestReceipts[commitment] = relayer;

        (bool success,) = address(destination)
            .call(abi.encodeWithSelector(IApp.onAccept.selector, IncomingPostRequest(request, relayer)));

        if (!success) {
            // so that it can be retried
            delete _requestReceipts[commitment];
            return;
        }
        emit PostRequestHandled({commitment: commitment, relayer: relayer});
    }

     * @dev Converts bytes to address.
     * @param _bytes bytes value to be converted
     * @return addr returns the address
     */
    function _bytesToAddress(bytes memory _bytes) internal pure returns (address addr) {
        if (_bytes.length != 20) revert InvalidAddressLength();

        assembly {
            addr := mload(add(_bytes, 20))
        }
    }

    function handlePostRequests(IHost host, PostRequestMessage calldata request) external notFrozen(host) {
        uint256 timestamp = block.timestamp;
        uint256 delay = timestamp - host.stateMachineCommitmentUpdateTime(request.proof.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        uint256 requestsLen = request.requests.length;
        MerkleMountainRange.Leaf[] memory leaves = new MerkleMountainRange.Leaf[](requestsLen);

        for (uint256 i = 0; i < requestsLen; ++i) {
            PostRequestLeaf memory leaf = request.requests[i];
            // check destination
            if (!leaf.request.dest.equals(host.host())) revert InvalidMessageDestination();
            // check time-out
            if (timestamp >= leaf.request.timeout()) revert MessageTimedOut();
            leaves[i] = MerkleMountainRange.Leaf(leaf.index, leaf.request.hash());
        }

        bytes32 root = host.stateMachineCommitment(request.proof.height).overlayRoot;
        if (root == bytes32(0)) revert StateCommitmentNotFound();
        bool valid = MerkleMountainRange.VerifyProof(root, request.proof.multiproof, leaves, request.proof.leafCount);
        if (!valid) revert InvalidProof();
