### Title
Unallowlisted route venue smuggles arbitrary code beneath the victim's authorization tree and drains their wallet - (File: contracts/swap-aggregator/src/venues/mod.rs)

### Summary

`execute_strategy` and the controller strategies that wrap it (`multiply`, `swap_debt`, `swap_collateral`, `repay_debt_with_collateral`) accept an attacker-constructed route that names pool and token addresses by registry index. The router keeps no allowlist of venues, pools, or tokens, so a hop can invoke an attacker-deployed contract. That contract executes while the swap caller's authorization is on the stack; in auth-recording mode, a `token.transfer(victim, attacker, X)` it issues is attached as a child of the victim's own auth entry, and enforcing mode executes it once the victim signs the simulated tree. This is the same bug class as the Go/SWIG report: attacker-controlled input (a filename / a route payload) smuggles executable code past a trust layer (the toolchain's file scan / the caller's signature), causing execution the signer never intended.

### Finding Description

The router dispatches each hop to the `pool` and token addresses carried in the caller-supplied payload, with no venue/pool/token allowlist — the only whitelist in the router selects fee placement [1](#0-0) [2](#0-1) . The controller grants only one exact input-transfer invocation and measures balance deltas, so none of its post-checks bound what route-named contracts do under the caller's auth [3](#0-2) . The threat model confirms the mechanism: "a route can put third-party code on the call stack below the caller's authorization. A token transfer that such code makes from the caller is recorded by an honest simulation as a child of the caller's authorization entry, and it executes if the caller signs that tree... neither the payload minimum nor the final risk gate bounds it" [4](#0-3) .

The harness test `simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry` proves it end-to-end: a `RogueHopPool` named in the route issues `token::Client::transfer(victim, attacker, WALLET_BALANCE)` for a token the protocol never listed, the recorded auth tree attaches that transfer as a child of Alice's `swap_collateral` entry, and Alice's wallet ends at zero while her position still receives a fair swap output [5](#0-4) [6](#0-5) .

### Impact Explanation

Theft of user funds. Any token the victim holds — including assets completely unrelated to the lending protocol — can be transferred to the attacker in the same transaction that delivers a perfectly fair-priced swap. The loss is the victim's whole wallet balance of the targeted token, unbounded by `min_out`, the flash guard, `RouterOverspend`, `NoSwapOutput`, or the final health-factor gate, because the stolen transfer never touches controller accounting.

### Likelihood Explanation

A single unprivileged address reaches this by publishing a route (through the quote channel or directly) whose hop `pool` is an attacker-deployed contract, and getting a victim to submit it via `execute_strategy` or any controller swap strategy. Routes are opaque packed XDR built off-chain; a wallet or client that signs the simulation-produced auth tree without decoding the route — the normal flow — silently authorizes the smuggled child transfer. The route executes honestly otherwise (fair output passes every measured check), so nothing on-chain distinguishes the poisoned path. Residual severity: High — exploitation requires the victim to sign a tree containing the extra child, which a diligent client could refuse.

### Recommendation

Constrain what route payloads can name: maintain a governance-managed registry of approved pool/token addresses per venue in the swap-aggregator and reject hops referencing unregistered contracts; or have the router verify each hop's pool address against the venue contract itself (e.g., pool factory lookup) rather than trusting the payload. On the controller side, reject non-empty `sub_invokes` expectations cannot be enforced on-chain, so the durable fix is the venue allowlist plus a documented requirement that clients simulate and reject any auth tree whose children differ from the single expected input `transfer`.

### Proof of Concept

Provided by the existing harness test: `Scene::route_through_pool_stealing` builds a `RoutedSwap` whose `hop_pool` is a freshly registered `RogueHopPool` constructed with `(victim, wallet_token, attacker, WALLET_BALANCE)`; `RogueHopPool::swap` performs `token::Client::transfer(&victim, &attacker, &amount)` when the router invokes it [5](#0-4) [7](#0-6) . The test runs `swap_collateral` under `mock_all_auths` (recording mode), asserts the recorded tree contains the stolen `transfer(wallet_token, alice → attacker, WALLET_BALANCE)` as a child of the `swap_collateral` entry, and asserts `wallet(alice) == 0`, `wallet(attacker) == WALLET_BALANCE`, while the position still gains the fair ETH output [8](#0-7) . Enforcing mode executes the same transfer once Alice signs the recorded tree.

#[test]
fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
}
