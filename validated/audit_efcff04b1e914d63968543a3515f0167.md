## Title
SimplexPaymaster trusts Chainlink's circuit-breaker-pinned price with no min/max sanity bound - (File: `evm/src/utils/SimplexPaymaster.sol`)

### Summary
`SimplexPaymaster._getOraclePrice` only validates that a Chainlink answer is non-negative and not older than `maxOracleAge`; it never checks the answer against the aggregator's configured `minAnswer`/`maxAnswer` circuit-breaker bounds, so a crashed asset whose feed is pinned at its floor will still be accepted as a fresh, valid price.

### Finding Description
`_getOraclePrice` is the sole gate on both the native-asset and registered-token oracles used to price gas sponsorship: [1](#0-0) 

It reverts on `answer <= 0` and on staleness beyond `maxOracleAge`, but performs no comparison against the underlying aggregator's `minAnswer`/`maxAnswer`. Chainlink aggregators clamp `latestRoundData().answer` to a configured range; when an asset's real market price falls (or spikes) past that range, the feed keeps reporting the boundary value as if it were current and "fresh" — `updatedAt` still advances with each new round, so the staleness check never fires and the pinned price passes every check in this contract.

This pinned price feeds directly into `_tokenPrice`, which is used both to size the amount pulled from users via `_prefund`/`_erc20Cost` and is externally exposed via `getTokenPrice`/`estimateTokenCost`: [2](#0-1) [3](#0-2) 

Any unprivileged account can submit a `PackedUserOperation` through the paymaster (mode `0x00` permit or mode `0x02` Permit2) — no governance or relayer role is required to trigger pricing and prefunding.

### Impact Explanation
If a registered token's price collapses below the Chainlink aggregator's `minAnswer` floor (e.g. a stablecoin de-peg or a LUNA-style collapse), `tokenUsd` in `_tokenPrice` remains pinned at the floor instead of reflecting the real, much lower value. Because `tokenPrice = nativeUsd * 10^tokenDecimals * (1+markup) / tokenUsd`, an inflated `tokenUsd` produces an under-priced `tokenPrice`, so `_erc20Cost`/`_prefund` charges the user far less of the crashed (near-worthless) token than the true gas cost requires. The paymaster still prefunds the EntryPoint in real ETH from its deposit, so each sponsored UserOp drains real value from the paymaster's EntryPoint deposit/treasury in exchange for a crashed token, letting anyone systematically siphon the paymaster's funds once such a depeg occurs — a concrete theft-of-funds scenario reachable by any ordinary UserOp sender using this Hyperbridge-governed paymaster.

### Likelihood Explanation
Requires an external market event (a registered ERC-20's price breaching its Chainlink aggregator's circuit-breaker bounds) — not attacker-controlled, but historically observed (e.g. LUNA/UST). Once it occurs, exploitation requires no special privilege: any address can submit a UserOp using the affected token through this paymaster, and the existing checks (staleness, non-positive) do not catch it, so the drain is trivial to execute repeatedly until governance detects and deactivates the token via `DeactivateToken`.

### Recommendation
Extend `_getOraclePrice` to fetch (or configure per-token) the aggregator's `minAnswer`/`maxAnswer` bounds and revert when `answer` equals or is within a safety margin of either bound, mirroring the report's recommendation:
```solidity
if (answer <= minPrice || answer >= maxPrice) revert InvalidOraclePrice(address(oracle), answer);
```
Alternatively, cross-check the primary Chainlink price against a secondary source (e.g. a TWAP from the Uniswap pools already integrated for fee-recycling) before trusting it for prefunding.

### Proof of Concept
1. Governance registers token `T` with Chainlink feed `F` via `RegisterToken` (`_registerToken`, `evm/src/utils/SimplexPaymaster.sol:387-404`).
2. `T`'s real market price crashes to a small fraction of the aggregator's `minAnswer`. `F.latestRoundData()` continues to report `minAnswer` with a fresh `updatedAt` on every new round.
3. `_getOraclePrice(F, decimals)` passes both its `answer <= 0` and `maxOracleAge` checks (lines 665-668), returning the stale-but-"fresh" `minAnswer`.
4. Any user submits a `PackedUserOperation` with `paymasterData` mode `0x00`/`0x02` referencing `T`; `_fetchDetails` computes `tokenPrice` from the pinned price (line 545), and `_prefund`/`_erc20Cost` (lines 563-609) pulls a token amount computed off that inflated valuation of `T`.
5. The paymaster pays real ETH gas costs from its EntryPoint deposit while receiving near-worthless `T`, repeatable across many UserOps until governance intervenes with `DeactivateToken`.

```text
    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
```
