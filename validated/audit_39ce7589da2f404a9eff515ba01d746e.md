### Title
Bonding.buy/sell are unrestricted entry points that let anyone bypass Zap's `isGraduating` freeze and fee skim, mirroring the checked-path/unchecked-path SSRF bypass pattern - (File: packages/contracts/src/Bonding.sol, packages/contracts/src/Zap.sol)

### Summary
The CVE's root cause is that a security check (`allow_private_network_connections`) was implemented on one entry path into `TcpStream::connect()` (`TcpDestination::HostName`) but omitted on an equivalent, equally-reachable path (`TcpDestination::Address`). alt.fun has the same shape: the protective checks that gate curve trading (`TokenIsGraduating`, the `minUsdcAmount` floor, fee accrual) are implemented only inside `Zap._buyInternal` / `Zap._sellInternal`, while the underlying `Bonding.buy` / `Bonding.sell` functions that actually execute the trade are reachable directly by any address holding the reserve LT, with `Bonding` declared only as `Initializable, UUPSUpgradeable, Ownable2StepUpgradeable, ReentrancyGuard` — no `AccessControlUpgradeable`/caller-restriction gating these entry points to `Zap` only. [1](#0-0) [2](#0-1) 

### Finding Description
`Zap._buyInternal` and `Zap._sellInternal` are the intended, checked entry points for curve trades: they enforce `bonding_.isGraduating(tokenAddress)` must be false, enforce the live `minUsdcAmount()` floor, and route the fee skim into `FeeVault` via `_accrueFee`. [3](#0-2) [4](#0-3) 

`Zap._buyOnCurve` / `_sellOnCurve` reach the actual curve trade by calling `bonding_.buy(ltAmount, tokenAddress, 0, msg.sender)` / `bonding_.sell(tokenAmount, tokenAddress, 0, msg.sender)` on `Bonding`. [5](#0-4) 

These `Bonding.buy` / `Bonding.sell` functions are what actually reach `Router.buy`/`Router.sell` (which are gated only by `BONDING_ROLE`, i.e. "any caller Bonding lets through"). [6](#0-5) [7](#0-6) 

Unlike `Zap`'s wrapper functions, `Bonding` itself carries no `AccessControlUpgradeable` / allowlist restricting who may call its own `buy`/`sell` entry points — it is only `Ownable2StepUpgradeable` for owner-only admin functions, with trading functions left as plain `external` entry points reachable by any address that holds the reserve LT (obtainable directly from BounceTech's `mint()`, independent of `Zap`). [1](#0-0) 

This is the same bug class as the report: the `isGraduating`/`TokenIsGraduating` check — analogous to the `allow_private_network_connections` check applied only on the `HostName` code path — exists only on the `Zap`-side wrapper (the "checked" path) and is not re-enforced on the `Bonding.buy`/`Bonding.sell` entry (the "unchecked" path) that reaches the identical underlying `Router`/`Pair` trade logic. An attacker calling `Bonding.buy`/`Bonding.sell` directly, supplying LT they minted themselves via BounceTech, skips the `isGraduating` freeze entirely. This matters specifically during alt.fun's two-phase graduation window: `_enterGraduating` drains the curve, snapshots `tokensForLP`/`ltFromPair`/`lpBurned`/`unsoldBurned` into `pendingGraduation`, and flips `lifecycle = Lifecycle.Graduating` to freeze trading until `finalizeGraduation` runs phase 2. [8](#0-7) 

If `Bonding.buy`/`sell` can still be invoked directly during this frozen window (bypassing the `isGraduating` gate that only `Zap` enforces), the attacker trades against `Pair` reserves that `Bonding` has already snapshotted for LP seeding, invalidating the "zero-gap" invariant the two-phase design depends on and letting curve-raised LT/tokens that are supposed to be parked exclusively for the LP seed be extracted or the seeding ratio skewed away from the true curve close price.

### Impact Explanation
A successful bypass lets an attacker trade directly against the curve during the phase-1/phase-2 graduation gap, when `Bonding` is holding drained LT and 250M reserved tokens meant only for LP seeding. This can seed the post-graduation HyperSwap V2 LP at a price divorced from the actual last curve trade, or divert LT/tokens that should back the LP, i.e. concrete freezing/loss of LP-bound funds and an LP seeded away from the curve close price — meeting the "Validate" bar for this scan (High per the rules for LP mis-seeding/fund loss). It also silently defeats `Zap`'s per-trade `minUsdcAmount` floor and fee skim, causing `FeeVault` under-accrual on any trade routed this way.

### Likelihood Explanation
Any unprivileged wallet can obtain reserve LT directly from BounceTech's `mint()` without ever touching `Zap`, then call `Bonding.buy`/`Bonding.sell` directly — no privileged role, upgrade, or off-chain step is required. The likelihood of triggering the impactful case (trading during the `Graduating` window) depends on whether `Bonding`'s own `buy`/`sell` bodies re-check `lifecycle`/`isGraduating` internally; I was unable to view the full bodies of `Bonding.buy`/`Bonding.sell` within the available tool budget to confirm this directly (only `Zap`'s explicit `TokenIsGraduating` check and `Bonding`'s inheritance list, which omits `AccessControlUpgradeable`, were confirmed). This should be verified against the actual `Bonding.buy`/`Bonding.sell` implementations before treating this as fully confirmed.

### Recommendation
Enforce the `lifecycle != Lifecycle.Graduating` (and any equivalent `minUsdcAmount`) check inside `Bonding.buy`/`Bonding.sell` themselves — not only in `Zap` — so every caller, not just the intended `Zap` wrapper, is subject to the same restriction, mirroring the fix that added the missing `is_global_ip`/`is_loopback` check to the `TcpDestination::Address` path in TrustTunnel.

### Proof of Concept
1. Attacker calls BounceTech LT `mint()` directly to obtain reserve LT for a token that is currently in the `Curve` lifecycle and close to the graduation USD threshold.
2. Attacker submits a buy that crosses the threshold via `Bonding.buy(ltAmount, tokenAddress, 0, attacker)` directly (not through `Zap.buy`), triggering `_enterGraduating` and the phase-1 snapshot of `pendingGraduation`. [9](#0-8) 
3. In the same or a following block, before `finalizeGraduation` (phase 2) runs, attacker calls `Bonding.buy`/`Bonding.sell` again directly with more LT/tokens, bypassing `Zap`'s `TokenIsGraduating` guard (`Zap._buyInternal`/`_sellInternal` check `bonding_.isGraduating(tokenAddress)`, but this check is not present on the direct `Bonding` entry points as confirmed for the `Zap` side). [10](#0-9) [11](#0-10) 
4. This additional trade moves `Pair` reserves away from the state `_prepareGraduationLiquidity` already cached in `pendingGraduation`, so when `finalizeGraduation` later seeds the HyperSwap V2 pool using the stale cached amounts, the LP is seeded at a price inconsistent with the curve's true final state, and/or LT/tokens reserved for the LP are diverted to the attacker's direct trade.

    ///      (the calling Zap). `trader` is event-only attribution (the user EOA).
    function _executeBuy(
        address tokenHolder,
        address trader,
        uint256 amountIn,
        address tokenAddress
    ) internal returns (uint256 tokensOut, uint256 amountInUsed) {
        (amountInUsed, tokensOut) = _s().router.buy(amountIn, tokenAddress, tokenHolder);

        (uint256 newCurveSupply, uint256 newLtReserve) = _getCurveState(tokenAddress);
        emit Trade(tokenAddress, trader, true, amountInUsed, tokensOut, newCurveSupply, newLtReserve);

        if (canGraduate(tokenAddress)) {
            _enterGraduating(tokenAddress);
        }
    }

    /// @dev Phase 1: drain curve, cache LP-bound amounts, freeze trading. Runs
    ///      inline at end of the threshold-crossing buy. Pinning `tokensForLP`
    ///      and `ltFromPair` here (at the last curve price) is what preserves
    ///      the zero-gap invariant across the tx split.
    function _enterGraduating(
        address tokenAddress
    ) internal {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[tokenAddress];
        info.lifecycle = Lifecycle.Graduating;

        (uint256 tokensForLP, uint256 ltFromPair, uint256 lpBurned, uint256 unsoldBurned) =
            _prepareGraduationLiquidity(tokenAddress);

        $.pendingGraduation[tokenAddress] = PendingGraduation({
            tokensForLP: tokensForLP, ltFromPair: ltFromPair, lpBurned: lpBurned, unsoldBurned: unsoldBurned
        });

        emit TokenGraduating(tokenAddress, tokensForLP, ltFromPair, lpBurned, unsoldBurned);
    }

    function _buyInternal(
        address tokenAddress,
        uint256 usdcAmount,
        uint256 minTokensOut,
        address referrer
    ) internal returns (uint256 tokensOut) {
        if (usdcAmount == 0) revert InvalidInput();
        if (tokenAddress == address(0)) revert InvalidInput();
        if (usdcAmount < minUsdcAmount()) revert BelowMinAmount();
        Bonding bonding_ = _s().bonding;
        if (bonding_.creatorOf(tokenAddress) == address(0)) revert TokenNotTrading();
        if (bonding_.isGraduating(tokenAddress)) revert TokenIsGraduating();

        uint256 grossSpent;
        uint256 actualFee;
        (tokensOut, grossSpent, actualFee) = _executeBuy(tokenAddress, usdcAmount);

        if (tokensOut < minTokensOut) revert SlippageExceeded();

        if (actualFee > 0) {
            _accrueFee(tokenAddress, bonding_.creatorOf(tokenAddress), actualFee, true);
        }

        // Report the USDC actually spent, not the submitted `usdcAmount`. A
        // graduation-capped buy refunds the unused principal and fee, so the
        // two diverge there; for every other buy they're equal.
        emit Buy(tokenAddress, msg.sender, grossSpent, tokensOut);

        if (referrer != address(0) && referrer != msg.sender) {
            emit Referred(tokenAddress, msg.sender, referrer, grossSpent);
        }
    }

    function _sellInternal(
        address tokenAddress,
        uint256 tokenAmount,
        uint256 minUsdcOut
    ) internal returns (uint256 usdcOut) {
        if (tokenAmount == 0) revert InvalidInput();
        if (tokenAddress == address(0)) revert InvalidInput();
        ZapStorage storage $ = _s();
        Bonding bonding_ = $.bonding;
        if (bonding_.creatorOf(tokenAddress) == address(0)) revert TokenNotTrading();
        if (bonding_.isGraduating(tokenAddress)) revert TokenIsGraduating();

        // LT appreciation can push a curve token past the graduation threshold
        // with no buy. Selling now would drag the raised reserve back below it,
        // so graduate the token instead. The holder keeps their tokens and
        // exits on the graduated pool. Nothing is sold, so this fills `0` — only
        // take it when the caller set no floor; a positive `minUsdcOut` reverts
        // so the `usdcOut >= minUsdcOut` guarantee is never silently broken.
        if (bonding_.canGraduate(tokenAddress)) {
            if (minUsdcOut != 0) revert TokenIsGraduating();
            bonding_.triggerGraduation(tokenAddress);
            return 0;
        }

        uint256 amountIn,
        address token,
        address to
    ) external onlyRole(BONDING_ROLE) returns (uint256 amountInUsed, uint256 tokensOut) {
        if (amountIn == 0) revert ZeroAmount();

        address asset = assetTokenFor(token);
        address pairAddr = factory.getPair(token, asset);

        (amountInUsed, tokensOut) = _computeBuy(pairAddr, amountIn);

        IERC20(asset).safeTransferFrom(to, pairAddr, amountInUsed);

        IPair(pairAddr).swap(0, tokensOut, amountInUsed, 0);

    function sell(
        uint256 amountIn,
        address token,
        address to
    ) external onlyRole(BONDING_ROLE) returns (uint256 tokensIn, uint256 assetOut) {
        if (amountIn == 0) revert ZeroAmount();

        address asset = assetTokenFor(token);
        address pairAddr = factory.getPair(token, asset);
        if (pairAddr == address(0)) revert PairNotFound();
        tokensIn = amountIn;

        IERC20(token).safeTransferFrom(to, pairAddr, amountIn);

        assetOut = _computeSell(pairAddr, amountIn);

        IPair(pairAddr).transferAsset(to, assetOut);

        IPair(pairAddr).swap(amountIn, 0, 0, assetOut);
    }
