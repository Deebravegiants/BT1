## Title
Consensus relayer reward rate changes apply retroactively to already-elapsed, unpaid block spans - (`modules/pallets/consensus-incentives/src/lib.rs`)

### Summary
`pallet-consensus-incentives::update_cost_per_block` overwrites `StateMachinesCostPerBlock` immediately, with no step that first settles ("accrues") the reward owed for blocks that have already advanced since the last payout at the *old* rate. The next relayer reward calculation prices the entire unpaid span — including blocks delivered before the rate change — at the *new* rate, exactly the bug class described in the source report ("`setDebtInterestApr` should accrue debt first").

### Finding Description
The reward owed to a relayer is computed lazily in `calculate_reward`: [1](#0-0) 

```
let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);
let blocks = latest_height.saturating_sub(baseline);
let reward = blocks_as_balance.saturating_mul(block_cost);
```

`block_cost` is read fresh from `StateMachinesCostPerBlock` at call time via `T::IncentivesOrigin`-gated governance: [2](#0-1) 

`update_cost_per_block` simply mutates the map and emits an event — it never reads the current `latest_commitment_height`/`LastRewardedHeight` for the state machine and never forces a settlement of the span accrued so far at the *old* rate, nor does it advance `LastRewardedHeight` to "checkpoint" the change. Consequently, whatever span of blocks has accumulated since the last reward payout (`LastRewardedHeight` watermark) — which can span an arbitrary, unbounded amount of time for a state machine that has gone a long while without a consensus update — gets priced entirely with the *new* `cost_per_block` the instant any relayer next submits a valid consensus proof.

This is structurally identical to the `NFTVault.setDebtInterestApr` bug: a rate parameter is mutated without first closing out (accruing) the position measured under the old rate, so the new rate is applied retroactively over the whole unsettled window.

### Impact Explanation
- If governance raises `cost_per_block` (e.g., to attract relayer participation on a new or currently-neglected state machine), the very next relayer to deliver *any* consensus update collects the entire historical backlog of unpaid blocks at the new, higher rate rather than only the blocks delivered after the change. This directly overpays from `TreasuryAccount`: [3](#0-2) 
  drawing down the treasury by more than governance intended, a form of unbudgeted fund loss reachable by a single relayed consensus message.
- Conversely, if governance lowers the rate, relayers who already delivered work under the higher rate are underpaid retroactively, breaking the reward accounting's fairness guarantee and potentially discouraging relaying, which weakens consensus-update liveness for the bridge.
- Because `LastRewardedHeight` only ever advances forward and a state machine with sparse activity accumulates a large unpaid span, the size of the mispriced backlog is unbounded and directly proportional to treasury exposure — this is a Medium/High severity fund-accounting bug, not a cosmetic one.

### Likelihood Explanation
Any account with `IncentivesOrigin` (governance) periodically re-tunes `cost_per_block` per state machine as market/cost conditions change (the pallet's whole purpose). Every time it does so on a state machine that has an outstanding unpaid span (the common case, since rewards are only realized lazily on the next consensus delivery), the next unsigned consensus-message submission — something any relayer can trigger — captures the mispriced backlog. No malicious governance is required; this triggers under normal, expected pallet operation each time the rate is adjusted.

### Recommendation
Before installing the new `cost_per_block`, settle the outstanding reward at the old rate: read `latest_commitment_height` for `state_machine_id`, and if it exceeds `LastRewardedHeight`, either (a) pay out the backlog at the old rate and advance `LastRewardedHeight` to that height before applying the new rate, or (b) simply checkpoint `LastRewardedHeight` to the current `latest_commitment_height` (forfeiting/deferring the backlog explicitly, as a documented policy) so the new rate only ever applies to blocks produced after the change. Either approach prevents `calculate_reward`'s single rate lookup from being applied over a mixed-rate historical span.

### Proof of Concept
1. State machine `S` goes 100,000 blocks without a consensus update being submitted (e.g., low relayer interest), so `LastRewardedHeight::<T>::get(S)` stays far behind `latest_commitment_height`.
2. Governance, wanting to bootstrap relaying on `S`, calls `update_cost_per_block(S, 10x_old_rate)`.
3. A relayer submits a single consensus proof advancing `S` to the current height via `pallet_ismp::handle_unsigned`, invoking `FeeHandler::on_executed` → `process_message` → `calculate_reward`: [4](#0-3) 
4. `blocks = latest_height - baseline` (the full 100,000-block backlog) is multiplied by the *new* 10x rate, not the rate that was actually in effect while those blocks were produced, paying out 10x the intended treasury budget for that historical stretch in one transaction.

```rust
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
```

```rust
	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}
```

```rust
	#[pallet::call]
	impl<T: Config> Pallet<T> {
		/// Update cost per block for a state machine
		#[pallet::call_index(0)]
		#[pallet::weight(T::WeightInfo::update_cost_per_block())]
		pub fn update_cost_per_block(
			origin: OriginFor<T>,
			state_machine_id: StateMachineId,
			cost_per_block: <T as pallet_ismp::Config>::Balance,
		) -> DispatchResult {
			T::IncentivesOrigin::ensure_origin(origin)?;

			StateMachinesCostPerBlock::<T>::mutate(state_machine_id.clone(), |maybe_cost| {
				*maybe_cost = Some(cost_per_block);
			});

			Self::deposit_event(Event::<T>::StateMachineCostPerBlockUpdated {
				state_machine_id,
				cost_per_block,
			});

			Ok(())
		}
```
