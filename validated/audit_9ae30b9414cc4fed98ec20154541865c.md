## Finding Analog

### Title
Global, caller-unbound `requestID` cache lets any authenticated workflow owner block another user's HTTP trigger execution - (File: `core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go`)

### Summary
`httpTriggerHandler.setupCallback` guards workflow-trigger execution with a simple "does this key already exist" check on a globally shared map, exactly like the reported `AgentFactoryV4._createPair()` bug that checked `getPair(...) == address(0)` before creating a pair. In both cases, any unprivileged actor can pre-claim the shared key (LP pair address / `requestID`) before the legitimate actor's transaction/request arrives, causing the legitimate actor's operation to be rejected.

### Finding Description
`HandleUserTriggerRequest` calls `h.setupCallback(ctx, req.ID, ...)` after authorization/rate-limit checks: [1](#0-0) 

```go
func (h *httpTriggerHandler) setupCallback(ctx context.Context, requestID string, callback handlers.Callback, requestStartTime time.Time, workflowID string) (<-chan struct{}, error) {
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()

	if _, found := h.callbacks[requestID]; found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrConflict, fmt.Sprintf("requestID: %s has already been used. Ensure the requestID is unique for each request.", requestID), callback)
		return nil, fmt.Errorf("in-flight request ID: %s", requestID)
	}
	...
```

`h.callbacks` is declared as `map[string]savedCallback // requestID -> savedCallback`, a single global cache shared by every workflow and every caller: [2](#0-1) . The `requestID` itself is fully attacker/client-controlled — `validateRequestID` only rejects empty strings and IDs containing `/`, with no per-caller or per-workflow scoping: [3](#0-2) .

This mirrors the `AgentFactoryV4._createPair()` root cause exactly: the "already exists" check is performed on a resource identified by an attacker-guessable/attacker-observable key, and that key can be permissionlessly claimed by any party (any workflow owner who is authorized to submit *some* trigger request) ahead of the legitimate caller's own request bearing the same key. There is no binding between the `requestID` claimant and the workflow/owner that eventually needs that ID — unlike the LP-pair case there isn't even a later "who owns this" check, just outright rejection.

### Impact Explanation
Any authorized workflow owner (an "unprivileged" actor relative to the victim — they only need their own valid workflow/auth, not the victim's) can pre-insert an entry for a `requestID` a victim is expected to use (e.g., predictable/sequential IDs, IDs derived from external system correlation, or externally observed IDs), causing the legitimate request for that ID to be rejected with `jsonrpc.ErrConflict` at `setupCallback`. The victim's genuine workflow-trigger execution never reaches the DON nodes, i.e., a targeted denial of service against a specific request/execution — the same "prevent the user from executing" impact as the reported bug, just implemented for the gateway's request cache instead of a Uniswap pair.

The attacker can also refresh the block by resubmitting fake claims before `reapExpiredCallbacks` (governed by `CleanUpPeriodMs`) removes the stale entry, extending the denial-of-service window indefinitely at negligible cost: [4](#0-3) .

### Likelihood Explanation
Exploitability depends on the attacker being able to predict or observe the victim's intended `requestID` before the victim's request lands — plausible when IDs are deterministic (timestamps, counters, hashes of known inputs) or when the gateway is reachable early enough for a race. Given this is exactly the same "check non-existence, then rely on it staying that way" pattern flagged in the source report, and the gateway is explicitly an internet-facing entry point with no per-caller partitioning of the `callbacks` map, likelihood is non-trivial but conditioned on requestID predictability/observability.

### Recommendation
Scope the callback/cache key to the authenticated identity (workflow owner/ID, or the authorized key derived in `authorizeRequest`) in addition to the caller-supplied `requestID`, e.g., key by `(workflowID, requestID)` or `(ownerKey, requestID)` rather than by `requestID` alone. This prevents an unrelated caller from occupying another user's request slot, analogous to the recommended fix of checking pair `totalSupply`/ownership rather than mere existence.

### Proof of Concept
1. Victim intends to send a `workflows.execute` request to the gateway with `id = "X"` for their workflow `W_victim`.
2. Attacker, using their own valid/authorized workflow `W_attacker`, sends a `workflows.execute` request with the same `id = "X"` first.
3. `setupCallback` inserts `h.callbacks["X"] = savedCallback{...}` for the attacker's request.
4. When the victim's request with `id = "X"` subsequently arrives, `setupCallback` finds `h.callbacks["X"]` already present and calls `handleUserError` with `jsonrpc.ErrConflict`, returning an error and never invoking `sendWithRetries` for the victim.
5. The victim's workflow execution is blocked until the attacker's entry is reaped by `reapExpiredCallbacks`, which the attacker can repeat to extend the block.

func (h *httpTriggerHandler) validateRequestID(ctx context.Context, requestID string, callback handlers.Callback) error {
	if requestID == "" {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "'id' field is required and cannot be empty. Use a new unique request 'id' for each request", callback)
		return errors.New("empty request ID")
	}
	// Request IDs from users must not contain "/", since this character is reserved
	// for internal node-to-node message routing (e.g., "http_action/{workflowID}/{uuid}").
	if strings.Contains(requestID, "/") {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "request ID must not contain '/'", callback)
		return errors.New("request ID must not contain '/'")
	}
	return nil
}

func (h *httpTriggerHandler) reapExpiredCallbacks(ctx context.Context) {
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()
	now := time.Now()
	var expiredCount int
	for reqID, callback := range h.callbacks {
		if now.Sub(callback.createdAt) > time.Duration(h.config.CleanUpPeriodMs)*time.Millisecond {
			if !callback.processed {
				h.metrics.IncrementRequestErrors(ctx, jsonrpc.ErrInternal, h.lggr)
			}
			h.cleanupCallback(reqID)
			expiredCount++
		}
	}
	if expiredCount > 0 {
		h.metrics.IncrementPendingRequestsCleanUpCount(ctx, int64(expiredCount), h.lggr)
		h.lggr.Infow("Removed expired callbacks", "count", expiredCount, "remaining", len(h.callbacks))
	}
	h.metrics.RecordPendingRequestsCount(ctx, int64(len(h.callbacks)), h.lggr)
}
