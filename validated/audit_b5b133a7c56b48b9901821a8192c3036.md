### Title
Accrued-debt rescaling overflows `i128` and permanently freezes a large market - ([File: common/src/rates/scaling.rs](common/src/rates/scaling.rs))

### Summary

A large borrowed position can push the market into a state where interest accrual always panics with `MathOverflow`. The public `update_indexes` path reaches the pool’s per-market `global_sync`; accrual rescales aggregate debt shares through `scaled_to_original`, whose `Ray` multiplication must produce an `i128` result. Once `borrowed_scaled * borrow_index / RAY` exceeds `i128::MAX`, every subsequent operation that accrues the market reverts before touching position state. This permanently prevents repayment, withdrawal, liquidation, and bad-debt cleanup for that market.

### Finding Description

`Controller::update_indexes` is callable by any authenticated caller and forwards its attacker-controlled `assets` list to the pool. [1](#0-0) [2](#0-1)  The pool entrypoint calls `ops::market::accrue`, which loads each market and invokes `interest::global_sync` before committing state. [3](#0-2) [4](#0-3) 

The vulnerable calculation is the share-to-value conversion performed by `scaled_to_original`: a RAY share balance is multiplied by the market index through `Ray::mul`. [5](#0-4)  `mul_div_half_up` widens the intermediate product to `I256`, but the final quotient still must fit `i128`; an unrepresentable result becomes `None` and panics as `GenericError::MathOverflow`. [6](#0-5) [7](#0-6) 

The arithmetic bound is reachable within the protocol’s own domain: token amounts are admitted whenever their token-to-RAY representation fits `i128`, while the borrow index can continue accruing far above its initial `RAY` value. The repository documents that accrued market totals can overflow before the index ceiling and then block repayment and withdrawal. [8](#0-7)  This is not merely an oversized transaction argument: the aggregate market state becomes permanently unusable because every existing-market mutation performs accrual before its mutation. [9](#0-8) 

### Impact Explanation

Once the threshold is crossed, the borrower keeps the previously extracted funds while all settlement paths fail at accrual:

- Suppliers cannot withdraw.
- Borrowers cannot repay.
- Liquidators cannot seize collateral.
- `clean_bad_debt` cannot socialize the position.
- `claim_revenue`, `recapitalize`, new supply, and additional borrows also load or renew the market and fail.

The result is theft of the borrowed balance from suppliers and a permanently frozen, insolvent market.

### Likelihood Explanation

The attacker needs an unprivileged account and enough collateral/liquidity to establish a very large borrow, plus sufficient accrued index growth for the debt’s scaled value to exceed `i128::MAX`. Both the large position and the accrual trigger use ordinary calls: `supply`, `borrow`, and `update_indexes`. The required scale is extreme and depends on the configured caps and market size, but the admitted share domain and index ceiling do not rule it out. The existing adversarial test constructs exactly this condition: a billion-token, 18-decimal market at 98% utilization eventually makes `update_indexes` return `MathOverflow`, after which both withdrawal and repayment fail with the same error. [10](#0-9) 

### Recommendation

Accrual must never hit the `i128` result boundary after a market has accepted shares. Add an explicit representability ceiling before index growth is committed:

- Compute a market-specific maximum index such as `i128::MAX / max(supplied, borrowed, revenue)` before applying the next accrual step.
- Clamp accrual at that index rather than panicking, or reject new supply/borrow shares early enough that the configured `MAX_BORROW_INDEX_RAY` cannot overflow the largest accepted aggregate.
- Apply the same bound to supply-value and revenue calculations, not only debt.
- Add regression tests for withdrawal, repayment, liquidation, and bad-debt cleanup after a market reaches the boundary.

A lower global index cap or a wider internal representation for accrued totals would also address the root cause, but the committed state must remain representable by every downstream `i128` calculation.

### Proof of Concept

A concrete unprivileged path is:

```text
1. attacker calls controller.supply(
       caller=attacker,
       account_id=0,
       spoke_id=S,
       assets=[
           ((hub_id=H, asset=BIG18), principal),
           ((hub_id=H, asset=COL), collateral)
       ]
   )

2. attacker calls controller.borrow(
       caller=attacker,
       account_id=returned_id,
       borrows=[((hub_id=H, asset=BIG18), borrow_amount)],
       to=attacker
   )

   where borrow_amount is close to the market’s available cash and the
   position passes LTV/health checks because of `collateral`.

3. After ledger time advances enough for the borrow index to grow,
   attacker calls:
       controller.update_indexes(attacker, [(H, BIG18)])

4. `global_sync` attempts to rescale the aggregate debt. The resulting
   `borrowed_scaled * borrow_index / RAY` no longer fits `i128`, so the
   transaction panics with `MathOverflow` and commits nothing.

5. Every later `withdraw`, `repay`, `liquidate`, `clean_bad_debt`,
   `borrow`, `supply`, `claim_revenue`, or `recapitalize` touching that
   market runs accrual first and fails identically.
```

The repository’s harness already implements the core reproducer in `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap`: it creates an 18-decimal market, supplies `BILLION * 10^18` base units, borrows 98%, advances accrual until `update_indexes` fails with `MathOverflow`, and then confirms that both withdrawal and repayment fail with `MathOverflow`. [11](#0-10)

```rust
pub fn try_mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> Option<i128> {
    if x < 0 || y < 0 || d <= 0 {
        return None;
    }
    let half = d / 2;

    // Fast path: the biased product fits `i128`, so the whole computation is
    // native. `x * y + half` is non-negative here, so `/` is the floor the
    // widened path would produce.
    if let Some(biased) = x
        .checked_mul(y)
        .and_then(|product| product.checked_add(half))
    {
        return Some(biased / d);
    }

    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    x256.mul(&y256)
        .add(&I256::from_i128(env, half))
        .div(&d256)
        .to_i128()
}
```

```rust
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
