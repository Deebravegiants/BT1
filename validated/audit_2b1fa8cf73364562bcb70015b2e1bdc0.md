### Title
Stale delegate grant reactivates when position NFT returns to prior owner - ([File: contracts/controller/src/storage/account.rs](contracts/controller/src/storage/account.rs))

### Summary

A revoked-by-ownership-change delegate grant is not cleared when the position NFT is transferred. Although the grant is hidden while another owner holds the NFT, it becomes active again if the NFT returns to the original `granted_by` address. A previously delegated, governance-approved manager can then act as the account owner and withdraw or borrow against the returned position.

### Finding Description

Controller authorization accepts either the current NFT owner or an active position manager contained in the stored delegate list for that owner. `is_owner_or_delegate` loads the delegate list with `storage::get_delegates(env, account_id, owner)` and permits the caller when it contains the manager’s address. [1](#0-0) 

`get_delegates` filters the stored `DelegateGrant` by `granted_by == current_owner`, but leaves the grant in storage when the owner differs. Consequently, transferring the NFT disables the old grant only while a different owner holds it. [2](#0-1) 

If the NFT subsequently returns to the original owner, account loading resolves ownership dynamically from the NFT and the stale grant matches `granted_by` again. [3](#0-2) 

The reactivated delegate can call `withdraw` because `process_withdraw` authorizes owner-or-delegate callers and permits an arbitrary external recipient through the `to` argument. [4](#0-3)  The same authorization pattern also protects `borrow`, allowing the stale delegate to extract borrowed assets to a selected recipient subject to post-borrow solvency. [5](#0-4) 

### Impact Explanation

This is theft of user funds. After the NFT returns to the prior owner, a stale delegate can withdraw the account’s collateral directly to an address it controls, or borrow the maximum permitted amount to itself and leave the position encumbered.

The issue is analogous to use-after-free: ownership transfer semantically invalidates the old owner’s delegation, but the authorization object remains allocated in storage and regains authority when the NFT returns to the former owner.

### Likelihood Explanation

Exploitation requires three prerequisites:

1. The victim previously called `add_delegate` for an attacker-controlled, active position manager.
2. The victim transferred the position NFT to another owner.
3. The NFT later returned to the victim without the intervening owner explicitly calling `remove_delegate` for the stale manager.

The intermediary owner cannot discover the stale delegation through `get_delegates` because it returns an empty list when `granted_by` differs from the current owner. [2](#0-1)  If that owner calls `remove_delegate`, the code detects the stale `granted_by` and deletes the grant, which is the correct remediation behavior but is not automatically performed on transfer. [6](#0-5) 

### Recommendation

Invalidate delegate grants permanently on NFT ownership change or delete them before a transfer can complete.

Because the Position NFT transfer implementation is inherited from OpenZeppelin and does not notify the controller, a practical mitigation is to bind each grant to a non-reusable ownership epoch rather than only `granted_by`. For example, store a monotonically changing owner-generation value, update it whenever NFT ownership is observed to change, and require `grant.owner_epoch == current_epoch`. Alternatively, document and enforce that intermediate owners must clear stale grants, though this is weaker because the stale grant is hidden from them.

At minimum, make `remove_delegate` semantics explicit and provide a view that exposes stale grants to the current owner so they can be removed before returning the NFT.

### Proof of Concept

Assume `A` owns `account_id`, `M` is an active governance-approved manager, and the account holds debt-free collateral.

1. `A` calls:

   ```text
   add_delegate(caller=A, account_id=id, delegate=M)
   ```

   This writes `DelegateGrant { granted_by: A, delegates: [M] }`.

2. `A` calls the Position NFT transfer entrypoint and transfers token `id` to `B`.

3. While `B` owns the NFT, `M` calls `withdraw`; authorization fails because `get_delegates(id, B)` filters out the grant stamped by `A`.

4. `B` transfers the same NFT back to `A`, for example after a sale, custody transfer, or marketplace return.

5. `M` calls:

   ```text
   withdraw(
       caller=M,
       account_id=id,
       withdrawals=[(collateral_hub_asset, 0)],
       to=Some(M)
   )
   ```

   The zero amount means withdraw-all. [7](#0-6) 

6. `storage::get_account` resolves the owner as `A`, `get_delegates(id, A)` now returns the surviving grant containing `M`, and `require_owner_or_delegate` succeeds. [8](#0-7) [2](#0-1) 

7. The controller calls the pool withdrawal path and pays the collateral to `M`; `process_withdraw` explicitly allows a caller-selected external recipient. [9](#0-8)

/// Accepts the owner or a registered, active manager delegated by that owner.
pub(crate) fn is_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) -> bool {
    if caller == owner {
        return true;
    }
    let active_manager =
        storage::get_position_manager(env, caller).is_some_and(|config| config.is_active);
    active_manager && storage::get_delegates(env, account_id, owner).contains(caller)
}

/// Returns grants stamped by `owner`, or an empty list. Ownership changes
/// invalidate a previous owner's grants without deleting them.
pub(crate) fn get_delegates(env: &Env, account_id: u64, owner: &Address) -> Vec<Address> {
    get_user::<DelegateGrant>(env, &ControllerKey::Delegates(account_id))
        .filter(|grant| grant.granted_by == *owner)
        .map(|grant| grant.delegates)
        .unwrap_or_else(|| Vec::new(env))
}

/// Removes a live delegate and reports whether it changed the list.
/// Deletes stale grants but returns false, preventing those grants from
/// reactivating if the NFT returns to their original owner.
pub(crate) fn remove_delegate(
    env: &Env,
    account_id: u64,
    owner: &Address,
    delegate: &Address,
) -> bool {
    let key = ControllerKey::Delegates(account_id);
    let Some(grant) = get_user::<DelegateGrant>(env, &key) else {
        return false;
    };
    if grant.granted_by != *owner {
        env.storage().persistent().remove(&key);
        return false;
    }

/// Withdraws for an authorized owner/delegate and checks post-pool solvency.
/// Zero requests withdraw all; returns the pool's actual payouts per asset.
pub(crate) fn process_withdraw(
    env: &Env,
    caller: &Address,
    account_id: u64,
    withdrawals: &Vec<HubPayment>,
    to: Option<Address>,
) -> Vec<HubPayment> {
    validation::require_authorized_caller(env, caller);

    let mut account = storage::get_account(env, account_id);
    require_owner_or_delegate(env, account_id, caller, &account.owner);

    let recipient = to.unwrap_or_else(|| caller.clone());
    let mut cache = Context::new(env);
    require_external_recipient(env, &mut cache, &recipient);
    let aggregated = payments::aggregate_payments(env, withdrawals, payments::ZeroLeg::MeansAll);

    let paid = settle_withdraw(env, &mut account, &recipient, &aggregated, &mut cache);
    let _ = enforce_post_pool_solvency(env, &mut cache, &mut account);

    finalize_position_flow(
        env,
        account_id,
        &account,
        &mut cache,
        PositionSides::Supply,
        true,
    );
    paid
