Audit Report

## Title
Per-owner secret limit and metadata scoping bypassable via non-canonical owner address casing - (File: core/services/ocr2/plugins/vault/kvstore.go)

## Summary
The Vault DON's authorization layer normalizes owner addresses via `vaultutils.NormalizeOwner` when validating that a request payload's `Owner` matches the authorized workflow owner, but the storage layer (`KVStore.GetMetadata`/`WriteMetadata`) and the OCR3 plugin's quota check (`GetSecretIdentifiersCountForOwner`) key strictly on the raw, un-normalized `Owner` string from the request payload. Because `GatewayVaultRequestProcessor` never rewrites the payload's `Id.Owner` field to the canonical authorized owner before forwarding to the state-transition/storage layer, an authorized owner can submit requests using different textual encodings (checksummed, lower-case, with/without `0x`) of the same address to fragment secrets and bypass the per-owner quota.

## Finding Description
`NormalizeOwner` lower-cases and strips `0x` so authorization comparisons treat multiple textual encodings of one address as equivalent. This is used in `validateEncryptedSecretOwnerMismatch`/`validateSecretIdentifierOwnerMismatch` in `core/capabilities/vault/authorizer.go` to check the payload owner against the authorized workflow owner. However, `GatewayVaultRequestProcessor.processCreateSecretsRequest`/`processUpdateSecretsRequest`/etc. only stamp the request ID and apply namespace defaults (`ApplyEncryptedSecretNamespaceDefaults`) — they do not rewrite `EncryptedSecret.Id.Owner` to the canonical `authResult.AuthorizedOwner()` value. Downstream, `ReportingPlugin.stateTransitionCreateSecretsRequest` in `core/services/ocr2/plugins/vault/plugin.go` calls `store.GetSecretIdentifiersCountForOwner(ctx, req.Id.Owner)` and `store.WriteSecret(ctx, req.Id, ...)` using this raw, uncanonicalized owner string. `vaulttypes.KeyFor` builds the secret storage key directly from `id.Owner` with no normalization, and `KVStore.GetMetadata`/`WriteMetadata` key metadata records by `metadataPrefix + owner` verbatim. Thus the authorization-time equivalence class ("same owner regardless of casing/prefix") is not preserved into storage, breaking the assumption that the per-owner quota and metadata scoping actually track one logical owner.

## Impact Explanation
This allows an authorized workflow owner to bypass the `MaxSecretsPerOwner` limit by varying the casing/`0x`-prefix of the `Owner` field across `CreateSecrets` calls — each distinct string variant is counted and stored independently, since `GetSecretIdentifiersCountForOwner` only sees secrets filed under the exact matching string. It also fragments a single owner's secrets across multiple `Metadata::<owner>` records, which can cause inconsistent enumeration via `ListSecretIdentifiers`/`GetSecrets`/`DeleteSecrets` (which look up metadata by the exact owner string in the request) and can leave orphaned secrets that are hard to fully delete. This is a quota-bypass / resource-limit-bypass and cross-representation data-scoping issue, not a fund-loss or authentication-bypass issue.

## Likelihood Explanation
Medium-to-high feasibility: any already-authorized workflow owner (a legitimate, unprivileged actor with normal Vault write access) can trigger this simply by choosing different valid string encodings of their own address in the `Owner` field of different `CreateSecrets`/`UpdateSecrets` calls. No additional privilege, credential, or host access is required beyond what a normal workflow owner already has to write secrets.

## Recommendation
Canonicalize the `Owner` field (via `NormalizeOwner` or a stricter checksum-based canonical form) once, immediately after the owner-binding check succeeds in `GatewayVaultRequestProcessor`/`authorizeAndStamp`, rewriting `Id.Owner` in the request payload to `authResult.AuthorizedOwner()` before it is used to build any storage key (`KeyFor`), passed to `GetSecretIdentifiersCountForOwner`, or used for `WriteMetadata`. Rely on canonicalization at ingress rather than only comparison-site normalization for authorization.

## Proof of Concept
1. Authorize as workflow owner via allowlist/JWT for address `0xABCDEF...` (checksummed).
2. Send `CreateSecrets` with `SecretIdentifier.Owner = "0xabcdef..."` (lower-case). It passes `validateEncryptedSecretOwnerMismatch` because `NormalizeOwner` treats it as equal to the authorized owner, and is written under `Metadata::0xabcdef...` in the KV store.
3. Send another `CreateSecrets` with `SecretIdentifier.Owner = "ABCDEF..."` (no `0x` prefix, different case) up to `MaxSecretsPerOwner` again — it also passes authorization (same `NormalizeOwner` equivalence) but is stored under a separate `Metadata::ABCDEF...` key, and `GetSecretIdentifiersCountForOwner` for this new raw string starts counting from 0.
4. Repeat with additional casing/prefix permutations to accumulate secrets far beyond `MaxSecretsPerOwner` for what is logically a single owner address. A Go unit test extending `plugin_test.go`/`kvstore_test.go` asserting that `GetSecretIdentifiersCountForOwner` returns independent counts for `"0xABC..."`, `"0xabc..."`, and `"abc..."` after multiple `CreateSecrets` calls each below the limit would confirm the bypass.

func (s *KVStore) GetSecretIdentifiersCountForOwner(ctx context.Context, owner string) (int, error) {
	defer s.trackDuration(ctx, "GetSecretIdentifiersCountForOwner", time.Now())
	md, err := s.GetMetadata(ctx, owner)
	if err != nil {
		return 0, fmt.Errorf("failed to get metadata for owner %s: %w", owner, err)
	}

	count := 0
	if md != nil {
		count = len(md.SecretIdentifiers)
	}
	return count, nil
}

func (s *KVStore) WriteMetadata(ctx context.Context, owner string, metadata *vault.StoredMetadata) error {
	defer s.trackDuration(ctx, "WriteMetadata", time.Now())
	if metadata == nil {
		return errors.New("metadata cannot be nil")
	}
	b, err := proto.Marshal(metadata)
	if err != nil {
		return fmt.Errorf("failed to marshal metadata: %w", err)
	}

	err = s.writer.Write([]byte(metadataPrefix+owner), b)
	if err != nil {
		return fmt.Errorf("failed to write metadata: %w", err)
	}

	return nil
}
