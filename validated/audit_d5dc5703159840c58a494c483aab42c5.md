## Analysis

I traced the analog of the LZ‑message bug (a boolean‑driven branch that skips inclusion of security‑critical data in the message that the recipient trusts) to the choice between `formInputNormal` and `formInputEmporiumMin` in [1](#0-0) , and the corresponding circuit switch between `MainEVMCircuit.circom` (which runs full EdDSA signature verification, [2](#0-1) ) and `MainEVMCircuitMin.circom`, which has **no ownership/signature check at all**: [3](#0-2) 

### Title
Unsigned "Emporium Min" proof path allows unauthorized triggering of external actions and pre/post transaction hooks - (File: `contracts/CircomDataBuilder.sol`, `circuits/MainEVMCircuitMin.circom`)

### Summary
When `circomData.externalActionData.externalActionId == HINKAL_EMPORIUM_ACTION_ID` and `circomData.erc20TokenAddresses.length == 0`, `formInputForCircom` routes to `formInputEmporiumMin`, which builds a public-input vector of only three values (`emporiumMessage`, `timeStamp`, `calldataHash`) — see [4](#0-3) . This is meant to pair with the lightweight `MainEVMCircuitMin` template, which contains **no `spendingPublicKey`, no `eddsaSignature`, no `signedMessageHash`, and no Merkle/nullifier checks whatsoever** — it only computes `message <== Poseidon(1)([messageSeed])` from a caller‑chosen private `messageSeed` [3](#0-2) . Any unprivileged EOA can therefore generate a trivially valid proof for arbitrary `calldataHash`/`timeStamp` values without knowing any spending/nullifying private key.

### Finding Description
`Hinkal.transact` always runs the pre/post hooks and, for a non‑zero `externalActionId`, always calls `_externalTransact`, regardless of which circuit/verifier path was used: [5](#0-4) [6](#0-5) [7](#0-6) 

The only gate before these calls is `performHinkalChecks`, which verifies:
1. `originalSender`/`relay` self-consistency (satisfiable by any caller by setting `originalSender = msg.sender`, `relay = 0`),
2. `getHashedCalldata(circomData) == circomData.calldataHash` — a hash of the *caller-supplied* fields against themselves, proving nothing about authorization by a wallet owner,
3. `verifyProof(...)` against the `MainEVMCircuitMin` verifier when `erc20TokenAddresses.length == 0`. [8](#0-7) 

Because `MainEVMCircuitMin` never verifies an EdDSA signature or Merkle root membership, the "calldataHash" and "timeStamp" public signals are unconstrained free variables in the R1CS — the caller can prove *any* value for them while only knowing an arbitrary `messageSeed`. This breaks the intended equality that a `transact()` call (and the resulting `hookData`/`externalActionData` side effects) is authorized by the holder of a specific `spendingPublicKey`. In the normal path this authorization is enforced by binding `hookData`, `feeStructure`, `relay`, `originalSender`, `extraData`, and `externalActionData` into `calldataHash`, which is itself folded into `signedMessageHash` and checked against the caller's EdDSA signature (`getSignedMessageHash`, [9](#0-8) ). The Min path drops that signature check entirely, exactly mirroring the reported bug class: a boolean/path selector (`data.unwrap` in the report ↔ `erc20TokenAddresses.length==0` here) determines whether a security‑critical binding (composed LZ message ↔ EdDSA authorization over hook/external‑action data) is included, and the "false"/"empty‑array" branch silently omits it while the caller‑reachable side effects (LZ send / hook & external‑action execution) still proceed.

### Impact Explanation
Any unprivileged EOA can call `Hinkal.transact()` with a self-fabricated `MainEVMCircuitMin` proof, `externalActionData.externalActionId = HINKAL_EMPORIUM_ACTION_ID`, `erc20TokenAddresses = []`, and arbitrary `hookData` (pre/post hook contracts + metadata) and `externalActionData.externalActionMetadata`/`extraData`/`relay`/`feeStructure`. This triggers `preTransact`/`afterTransact` hook calls and `IExternalActionV2.runAction` on the registered Emporium contract with attacker‑controlled `circomData`, without any proof that a specific wallet (spendingPublicKey holder) authorized the action. This is an "unauthorized wallet op / external call not sanctioned by the prover" per the impact rubric (High/Critical depending on what the registered external action / hook contracts do with unauthenticated `circomData`).

### Likelihood Explanation
High — no privileged role, relayer collusion, or secret knowledge is required. Constructing a `MainEVMCircuitMin` witness only requires picking an arbitrary `messageSeed`; the circuit imposes no ownership or membership constraint, so a standard snarkjs proof-generation flow trivially produces a valid proof for any chosen `calldataHash`/`timeStamp`.

### Recommendation
Do not allow `_externalTransact`/hook invocation to be gated by a proof that contains no ownership/signature binding. Either:
- Require `MainEVMCircuitMin` (or any reduced circuit) to still verify EdDSA signature over a hash that includes `hookData`, `externalActionData`, `relay`, `feeStructure`, `originalSender`, and `extraData`, or
- Restrict the emporium-min fast path so it can never reach `_externalTransact`/hook execution with attacker-controlled `hookData`/`externalActionMetadata`, or
- Constrain `calldataHash` (and any other public signal meant to carry authorization) inside every circuit variant, not just recompute/compare it in Solidity.

### Proof of Concept
1. Attacker picks `circomData.erc20TokenAddresses = []`, `externalActionData.externalActionId = HINKAL_EMPORIUM_ACTION_ID`, sets `externalActionData.externalAddress` to the registered Emporium address, and freely chooses `hookData.postHookContract` (or metadata consumed by Emporium's `runAction`) plus `originalSender = msg.sender`, `relay = address(0)`.
2. Attacker computes `calldataHash = getHashedCalldata(circomData)` locally (pure function, no secret needed) so the on-chain integrity check passes.
3. Attacker generates a `MainEVMCircuitMin` proof using an arbitrary `messageSeed`; no `spendingPublicKey`/signature is needed since the circuit has none.
4. Attacker calls `Hinkal.transact(a,b,c,dimensions,circomData)`. `performHinkalChecks` passes (self-consistent hash, relay check trivial), `verifyProof` succeeds against the Min verifier, and `Hinkal.transact` proceeds to invoke `preHookContract`/`postHookContract.afterTransact` and `Emporium.runAction` with attacker-supplied `circomData`, despite no wallet ever having signed authorization for this action.

Note: I was not able to inspect `EmporiumUpgradeable.runAction`'s implementation in this pass to confirm the exact downstream fund-impact of the unauthenticated call, since tool access ended before that file could be read; the described gap (missing signature binding on the Min proof path while hook/external-action execution still proceeds) is confirmed directly from `Hinkal.sol`, `HinkalHelper.sol`, `CircomDataBuilder.sol`, and `MainEVMCircuitMin.circom`.

    ) internal pure returns (uint256[] memory input) {
        input = new uint256[](circomData.publicSignalCount);

        uint16 index = 0;

        input[index++] = circomData.emporiumMessage;

        input[index++] = circomData.timeStamp;

        CircomData calldata circomData
    ) internal returns (UTXO[] memory) {
        require(
            externalActionMap[circomData.externalActionData.externalActionId] ==
                circomData.externalActionData.externalAddress &&

        );

        int256[] memory deltaAmountChanges = new int256[](
            circomData.erc20TokenAddresses.length
        );
        for (uint256 i = 0; i < circomData.erc20TokenAddresses.length; i++) {
            deltaAmountChanges[i] = _calculateDeltaAmount(circomData, i);
            if (deltaAmountChanges[i] < 0) {

                    circomData.erc20TokenAddresses[i],
                    circomData.externalActionData.externalAddress,
                    uint256(-deltaAmountChanges[i])
                );
            }
        }

            IExternalActionV2(circomData.externalActionData.externalAddress)

    function performHinkalChecks(
        CircomData calldata circomData,
        Dimensions calldata dimensions,
        address sender
    ) external view returns (uint256[] memory) {
        require(
            (circomData.originalSender == address(0) &&
                circomData.relay != address(0)) ||
                (circomData.originalSender == sender &&
                    circomData.relay == address(0)),
            "invalid value for originalSender"
        );

        require(
            CircomDataBuilder.getHashedCalldata(circomData) ==
                circomData.calldataHash,
            "Calldata Hash Integrity Check Failed"
        );
        relayerIsValid(circomData.relay);
        dimensionsCheck(circomData, dimensions);
        checkOnchainCreation(circomData);

        return
            CircomDataBuilder.formInputForCircom(
                block.chainid,
                hinkalAddress,
                circomData
            );
    }
