### Title
`ShopifyAPI::Auth.embedded_app_url` builds a trusted redirect target from an unvalidated `host` parameter, enabling forced-OAuth-completion open redirect - ([File: lib/shopify_api/auth.rb])

### Summary
`ShopifyAPI::Auth.embedded_app_url` Base64-decodes the caller-supplied `host` value and concatenates it directly into a `https://` URL with no domain allow-listing, unlike every other place in the gem that turns an attacker-influenced "shop"/"host" value into a URL.

### Finding Description
`ShopifyAPI::Auth.embedded_app_url` takes a `host` argument, Base64-decodes it, and returns `"https://#{decoded_host}/apps/#{Context.api_key}"` with no check that `decoded_host` is a legitimate Shopify admin domain: [1](#0-0) 

This is the same `host` value that Shopify appends as a plain (non-HMAC-covered on every load) query parameter to the embedded app's iframe URL on every page render, and that apps use throughout a session to construct the redirect back into the Shopify admin (e.g., after OAuth, or when the app determines it must "break out" of the iframe). Every other place in the codebase that turns a shop/host-like value into a URL used to build trust decisions runs it through `Utils::ShopValidator.sanitize!`, which enforces membership in `TRUSTED_SHOPIFY_DOMAINS` (`shopify.com`, `myshopify.io`, `myshopify.com`, `spin.dev`, `shop.dev`): [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4) 

`embedded_app_url` is the one exception: it neither calls `ShopValidator.sanitize!` nor `sanitize_shop_domain`, so `decoded_host` can be any attacker-chosen string (e.g. `evil-phishing-site.example/apps`). Because Shopify sends `host` unsigned on ordinary embedded-app page loads (it is only inside the HMAC-covered `AuthQuery` during the OAuth callback, not on subsequent renders), any user who can influence the `host` query parameter that reaches this method (a normal capability of anyone who can open the app's URL — no `api_secret_key`, access token, or privileged account is needed) can make the returned URL point to an attacker-controlled origin instead of the real Shopify admin domain. This breaks the identity binding the equation "the host trusted by the app == the host that actually belongs to Shopify admin" is expected to hold.

### Impact Explanation
Apps rely on `embedded_app_url` to compute the address they redirect the merchant's browser to when leaving/re-entering the Shopify admin iframe context (e.g., after finishing OAuth, or when bootstrapping the embedded UI). Since the returned URL is not restricted to a Shopify-owned domain, an attacker can craft a link that causes the merchant's browser to be redirected to an attacker-controlled page that impersonates the Shopify OAuth grant screen or app UI, tricking the merchant into re-authorizing a malicious app or re-entering credentials — a forced-OAuth-completion / open-redirect scenario, matching the High-impact "session fixation or forced OAuth completion" category.

### Likelihood Explanation
Low-to-Medium: exploitation only requires the ability to get a victim merchant to open a URL/iframe with an attacker-chosen `host` query parameter pointing at the app (a normal, unauthenticated capability), and requires the host application to actually use `embedded_app_url`'s output for a redirect (which is exactly its documented purpose). No secret key, access token, or privileged account is required.

### Recommendation
Validate `host` the same way `shop` is validated elsewhere in the gem: Base64-decode it, then run the decoded value through `Utils::ShopValidator.sanitize!`/`sanitize_shop_domain` (or an equivalent allow-list check against `TRUSTED_SHOPIFY_DOMAINS`) before using it to build the redirect URL, raising `Errors::InvalidShopError` (or similar) if it does not resolve to a trusted Shopify admin domain.

### Proof of Concept
1. An app calls `ShopifyAPI::Auth.embedded_app_url(host)` with `host` taken directly from the request's `host` query parameter (the documented way this parameter is used across Shopify apps).
2. An attacker sends the victim merchant a link such as `https://app.example.com/?host=<Base64("evil-attacker.example/store")>`.
3. `embedded_app_url` decodes this to `evil-attacker.example/store` and returns `https://evil-attacker.example/store/apps/<api_key>` with no domain check: [6](#0-5) 
4. If the host app redirects the browser to this URL (its intended use), the merchant is silently taken to an attacker-controlled origin instead of Shopify admin, enabling phishing of Shopify credentials or forced re-consent to a malicious OAuth grant.

      def embedded_app_url(host)
        unless Context.setup?
          raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
        end

        unless host
          raise Errors::MissingRequiredArgumentError, "host argument is required"
        end

        decoded_host = Base64.decode64(host)
        "https://#{decoded_host}/apps/#{Context.api_key}"
      end
