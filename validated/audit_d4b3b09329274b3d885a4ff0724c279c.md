### Title
Griefing via front-run of a single request/response from a batch causes atomic reversion of the entire relayer transaction, wasting gas - ([File: evm/src/core/HandlerV2.sol])

### Summary
`HandlerV2.handlePostRequests`, `handleGetResponses`, `handlePostRequestTimeouts`, and `batchCall` all process arrays of independently-provable leaves/calls atomically: if a single item in the batch fails (e.g. `DuplicateMessage`), the *entire* transaction reverts, even though the merkle-proof verification and message decoding for the whole batch has already consumed gas. The same all-or-nothing semantics exist in `pallet-ismp::handle_unsigned`, which is wrapped in `#[frame_support::transactional]` and documented to "short-circuit and revert if any of the provided messages are invalid."

### Finding Description
`handlePostRequests` builds an MMR leaf array for every request in the batch, verifies a single multiproof against the state-machine's overlay root, and only *after* that succeeds does it loop a second time to check `host.requestReceipts(...)` and call `host.dispatchIncoming(...)` for every leaf: [1](#0-0) 

Because `MerkleMountainRange` multiproofs support proving an arbitrary subset of leaves independently, an attacker can construct their own `PostRequestMessage` containing only one leaf from the same batch a relayer is about to submit, and a valid multiproof for just that leaf. If the attacker's single-leaf transaction is mined first, it marks that leaf's commitment as delivered via `host.requestReceipts`. The relayer's original (larger) batch transaction then still executes the expensive MMR proof verification for all its leaves, but reverts with `DuplicateMessage()` in the second loop once it reaches the already-delivered leaf — losing all the gas spent verifying the batch, with no partial credit.

The same pattern applies to:
- `handleGetResponses`, which similarly verifies a batch proof then dispatches each response, reverting the whole call on `DuplicateMessage` for any single response: [2](#0-1) 
- `batchCall`, which explicitly delegatecalls each encoded handler call sequentially and reverts the *entire* batch if any single inner call fails: [3](#0-2) 
- The Substrate side, `pallet_ismp::Pallet::handle_unsigned`, which is `#[frame_support::transactional]` and documented to short-circuit/revert the whole extrinsic if any message in the batch is invalid: [4](#0-3) 

This mirrors the `handleOps`/`multiSend` bug class in the referenced report exactly: atomic batch execution where a single already-delivered/invalid item can be front-run cheaply by an attacker, forcing a relayer's larger, gas-expensive batch transaction to fully revert.

### Impact Explanation
Relayers routinely batch many post requests / get responses / consensus updates into one `batchCall` or `handle_unsigned` transaction to save gas and simplify nonce management, as confirmed by the relayer client code that always prefers batching ≥2 messages: [5](#0-4) [6](#0-5) 

An attacker can front-run with a cheap single-leaf transaction claiming one message's delivery/fee, causing the relayer's much larger, more expensive batch to revert entirely after having paid for full merkle-proof verification. This is a griefing/gas-wasting vector against relayers (an "unprivileged... relayer" role explicitly in scope), and can degrade message delivery liveness since relayers must retry, and consensus updates bundled with application messages in the same `batchCall` (as done in `BatchConsensusAndPostRequest`) would also fail to land, delaying consensus progression: [7](#0-6) 

### Likelihood Explanation
The attack requires only observing a pending relayer transaction in the mempool and constructing a valid single-leaf multiproof for one message already contained in that batch — the MMR proof and leaf data are public in the mempool. No privileged access or special timing beyond standard front-running (higher gas price) is needed, and can be repeated cheaply against any batched relayer submission.

### Recommendation
Make `handlePostRequests`, `handleGetResponses`, `handlePostRequestTimeouts`, and `batchCall` non-atomic per item: wrap each per-leaf/per-call dispatch (not the proof verification) so that a `DuplicateMessage`/`UnknownMessage`/failed inner call for one item is skipped/emits an event rather than reverting the whole transaction, letting the remaining valid items in the batch still be processed and the relayer still credited for them. Apply the same non-atomic-per-message semantics to `pallet_ismp::handle_unsigned`, removing the `#[frame_support::transactional]` short-circuit for individually-provable message batches, or catching per-message dispatch errors within `Self::execute` similar to how `handlers::response::handle` and `handlers::timeout::handle` already return per-item `Result`s.

### Proof of Concept
1. Relayer builds `PostRequestMessage` for requests `[A, B, C]` from the same MMR root and submits via `handler.handlePostRequests(host, message)` (or wrapped in `batchCall` with a consensus update).
2. Attacker observes the pending tx, extracts leaf `A` and its individual MMR multiproof (`MerkleMountainRange.VerifyProof` supports proving a subset of leaves against the same root), and submits `handlePostRequests(host, {proof: proofForA, requests: [A]})` with higher gas price.
3. Attacker's tx is mined first: `host.requestReceipts(A.hash())` is now set via `dispatchIncoming` in [8](#0-7) .
4. Relayer's original tx executes: MMR verification for `[A,B,C]` succeeds (costing full gas), but the dispatch loop hits `DuplicateMessage()` on leaf `A`, reverting the entire transaction and burning the relayer's gas for `B` and `C` as well.

     * @dev Process a batch of encoded handler calls in a single transaction.
     * Uses delegatecall to self so msg.sender is preserved and storage writes
     * happen in this contract's context. Atomic, any failure reverts the entire batch.
     * @param calls - array of ABI-encoded handler function calls
     */
    function batchCall(bytes[] memory calls) external {
        uint256 len = calls.length;
        for (uint256 i = 0; i < len; ++i) {
            (bool success, bytes memory returnData) = address(this).delegatecall(calls[i]);
            if (!success) revert BatchCallFailed(i, returnData);
        }
    }

    function handlePostRequests(IHost host, PostRequestMessage calldata request) external notFrozen(host) {
        uint256 timestamp = block.timestamp;
        uint256 delay = timestamp - host.stateMachineCommitmentUpdateTime(request.proof.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        uint256 requestsLen = request.requests.length;
        MerkleMountainRange.Leaf[] memory leaves = new MerkleMountainRange.Leaf[](requestsLen);

        for (uint256 i = 0; i < requestsLen; ++i) {
            PostRequestLeaf memory leaf = request.requests[i];
            // check destination
            if (!leaf.request.dest.equals(host.host())) revert InvalidMessageDestination();
            // check time-out
            if (timestamp >= leaf.request.timeout()) revert MessageTimedOut();
            leaves[i] = MerkleMountainRange.Leaf(leaf.index, leaf.request.hash());
        }

        bytes32 root = host.stateMachineCommitment(request.proof.height).overlayRoot;
        if (root == bytes32(0)) revert StateCommitmentNotFound();
        bool valid = MerkleMountainRange.VerifyProof(root, request.proof.multiproof, leaves, request.proof.leafCount);
        if (!valid) revert InvalidProof();

        for (uint256 i = 0; i < requestsLen; ++i) {
            PostRequestLeaf memory leaf = request.requests[i];
            // duplicate request?
            if (host.requestReceipts(leaf.request.hash()) != address(0)) revert DuplicateMessage();
            host.dispatchIncoming(leaf.request, _msgSender());
        }

        uint256 responsesLength = message.responses.length;

            // don't check for timeouts because it's checked on Hyperbridge

            // known request? also serves as source check
            FeeMetadata memory meta = host.requestCommitments(leaf.response.request.hash());

            leaves[i] = MerkleMountainRange.Leaf(leaf.index, leaf.response.hash());
        }

            GetResponseLeaf memory leaf = message.responses[i];
            // duplicate response?
            if (host.responseReceipts(leaf.response.request.hash()).relayer != address(0)) revert DuplicateMessage();
            host.dispatchIncoming(leaf.response, _msgSender());
