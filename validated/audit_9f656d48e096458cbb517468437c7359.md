### Title
`handle_unsigned` charges a fixed, input-size-independent weight for an unbounded `Vec<Message>` batch, allowing resource-consumption DoS - ([File: modules/pallets/ismp/src/lib.rs])

### Summary
`pallet-ismp`'s `handle_unsigned` extrinsic accepts an arbitrary-length `Vec<Message>` and every message can itself carry an arbitrary-length `Vec<PostRequest>`/`Vec<GetRequest>` plus a proof, yet it is annotated with a *static* declared weight (`Weight::from_parts(300_000_000, 0)`) that does not scale with the number of messages, requests, or proof size. This is analogous to the Apollo Router bug: a small, cheap-looking input can trigger disproportionately expensive verification work (trie/consensus proof verification) because the cost-accounting mechanism (query-optimization-limit in Apollo; declared extrinsic weight in Substrate) does not track the actual computational cost, and no per-call timeout exists.

Because `Message` is an unbounded `Vec<Message>` (no `BoundedVec`/`MaxMessages` constraint), and each `RequestMessage`/`ResponseMessage` carries its own unbounded `Vec<PostRequest>`/`Vec<GetRequest>` plus a `Proof` blob: [5](#0-4) 

a single unsigned extrinsic can pack many request/response/consensus sub-messages, each of which triggers full state-machine-client trie verification (`verify_membership`, `verify_non_membership`, `verify_state_proof`) across substrate/EVM/pharos state machines, e.g.: [6](#0-5) [7](#0-6) 

Each of these does trie decode/lookups per key, and this work is fully executed **twice** per submission — once during `validate_unsigned` (run by every full node processing the unsigned transaction pool, before block inclusion) and once inside `handle_unsigned`'s dispatch body — yet the block-weight/fee system only ever sees the constant `300_000_000` declared weight. Because the declared weight does not scale with the actual number of messages/requests/proof depth, the block-authoring logic (which packs extrinsics into a block based on declared weight, refunding only after actual execution) can be tricked into believing the call is cheap while it is actually O(n) or worse in trie lookups and signature/consensus verification.

### Impact Explanation
This maps to CWE-770 (Allocation of Resources Without Limits or Throttling), the same class as the Apollo Router advisory: a single crafted, low-declared-cost transaction can consume outsized CPU time. Concretely:
- A relayer/attacker can submit one `handle_unsigned` extrinsic with a very large `Vec<Message>` (bounded only by the runtime's max extrinsic/block length, not by declared weight), each entry requiring real trie-node decoding and hashing across `substrate`, `evm`, and `pharos` state-machine clients.
- Every full node in the network re-executes `validate_unsigned` → `Self::execute(...)` for this transaction as part of transaction-pool validation, *before* it is even included in a block, multiplying the cost network-wide.
- Because the extrinsic's `#[pallet::weight(weight())]` is a fixed constant unrelated to the actual batch size, the block-weight budget the node/relaychain uses to decide whether to include the call in a block underestimates its true cost, risking block-production stalls / excessive validation time — i.e., "a route unable to deliver messages" for the affected parachain, consistent with the required impact class.

This is High rather than Critical because it is a resource-exhaustion/DoS vector reachable from a single unsigned, permissionless extrinsic (rules explicitly exclude "resource-only" analogs as too low, but this crosses into route-unavailability/DoS territory per the allowed impact list "a route unable to deliver messages").

### Likelihood Explanation
`handle_unsigned` is explicitly permissionless/unsigned — "This allows users execute ISMP datagrams for free. Use with caution" per the pallet's own doc comment on `ValidateUnsigned`. Any relayer or unprivileged actor able to submit an unsigned extrinsic (which is the intended entry point for relayers) can construct such a batch; no special privileges, governance, or key compromise are required, making this directly reachable from "a relayed proof" as called out in the validation rules.

### Recommendation
- Make the declared weight for `handle_unsigned` scale with the actual size of `messages` (and their nested request/response vectors and proof lengths) rather than being a fixed constant, e.g., benchmark per-message/per-key costs and sum them, or enforce a `BoundedVec` cap on the number of messages/requests per call.
- Consider imposing a maximum batch size (`MaxMessages`, `MaxRequestsPerMessage`) enforced before any proof verification runs, both in `validate_unsigned` and in the dispatchable body, to bound worst-case per-transaction work independent of weight metering.
- Ensure the mempool-time `validate_unsigned` path also respects this cap so a rejected-for-cost batch cannot still force full verification during gossip validation.

### Proof of Concept
1. Construct a single `Message::Request(RequestMessage { requests: <N very large PostRequest vec>, proof, signer })` (or a `Vec<Message>` containing many such `RequestMessage`s/`ResponseMessage`s/`ConsensusMessage`s), each with a state proof of the maximum size permitted by the runtime's extrinsic/block-length limit.
2. Submit it as an unsigned extrinsic to `Ismp::handle_unsigned`.
3. Every node performing `validate_unsigned` (module lib.rs:614-646) executes `Self::execute(messages.clone())`, which walks every request through `handle_incoming_message` → `state_machine.verify_membership/verify_non_membership` (substrate/evm/pharos trie proof decode+lookup) for each entry, while the pallet's declared weight for the call remains the fixed `Weight::from_parts(300_000_000, 0)` (lib.rs:727-730) regardless of `N`.
4. Repeat/parallelize submissions to amplify aggregate CPU consumption across the network relative to the weight actually charged, degrading block production/relaying throughput.

impl<T: Config> Pallet<T> {
	/// Execute the provided ISMP datagrams, this will short circuit if any messages are invalid.
	/// This also charges fee on valid message delivery
	pub fn execute(messages: Vec<Message>) -> Result<Vec<events::Event>, Error<T>> {
		let host = Pallet::<T>::default();

		let message_results = messages
			.iter()
			.map(|msg| handle_incoming_message(&host, msg.clone()))
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		let messages_with_weights = message_results
			.iter()
			.zip(messages)
			.map(|(result, message)| MessageWithWeight { message, weight: result.weight() })
			.collect::<Vec<_>>();

		let events = message_results
			.into_iter()
			// check that requests will be successfully dispatched
			// so we can not be spammed with failing txs
			.map(|result| match result {
				MessageResult::Request { events, .. } |
				MessageResult::Response { events, .. } |
				MessageResult::Timeout { events, .. } => events,
				MessageResult::ConsensusMessage(events) => events.into_iter().map(Ok).collect(),
				MessageResult::FrozenClient(_) => vec![],
			})
			.flatten()
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		T::FeeHandler::on_executed(messages_with_weights, events.clone())
			.map_err(|_| Error::<T>::ErrorChargingFee)?;

		for event in events.clone() {
			// deposit any relevant events
			Pallet::<T>::deposit_event(event.into());
		}

		Ok(events)
	}

	fn verify_state_proof(
		&self,
		_host: &dyn IsmpHost,
		keys: Vec<Vec<u8>>,
		root: H256,
		proof: &Proof,
	) -> Result<BTreeMap<Vec<u8>, Option<Vec<u8>>>, Error> {
		// The trie root is supplied by the caller, bound to the calling context, so a relayer
		// cannot steer verification at the wrong trie.
		let StateMachineProof { hasher, storage_proof } =
			codec::Decode::decode(&mut &*proof.proof)
				.map_err(SubstrateStateMachineError::ProofDecodeError)?;
		let data = match hasher {
			HashAlgorithm::Keccak => {
				let db = StorageProof::new(storage_proof).into_memory_db::<Keccak256>();
				let trie = TrieDBBuilder::<LayoutV0<Keccak256>>::new(&db, &root).build();
				keys.into_iter()
					.map(|key| {
						let value = trie
							.get(&key)
							.map_err(|e| SubstrateStateMachineError::TrieError(format!("{e:?}")))?;
						Ok::<_, SubstrateStateMachineError>((key, value))
					})
					.collect::<Result<BTreeMap<_, _>, _>>()?
			},
			HashAlgorithm::Blake2 => {
				let db = StorageProof::new(storage_proof).into_memory_db::<BlakeTwo256>();
				let trie = TrieDBBuilder::<LayoutV0<BlakeTwo256>>::new(&db, &root).build();
				keys.into_iter()
					.map(|key| {
						let value = trie
							.get(&key)
							.map_err(|e| SubstrateStateMachineError::TrieError(format!("{e:?}")))?;
						Ok::<_, SubstrateStateMachineError>((key, value))
					})
					.collect::<Result<BTreeMap<_, _>, _>>()?
			},
		};

		Ok(data)
	}

	fn verify_state_proof(
		&self,
		_host: &dyn IsmpHost,
		keys: Vec<Vec<u8>>,
		root: H256,
		proof: &Proof,
	) -> Result<BTreeMap<Vec<u8>, Option<Vec<u8>>>, Error> {
		let ismp_host_address = EvmHosts::<T>::get(&proof.height.id.state_id)
			.ok_or(SubstrateEvmError::IsmpContractNotFound)?;

		let proof: SubstrateEvmProof =
			Decode::decode(&mut &proof.proof[..]).map_err(SubstrateEvmError::ProofDecodeError)?;

		let state_root = root;

		let keys_len = keys.len();
		let mut contract_keys: BTreeMap<H160, Vec<Vec<u8>>> = BTreeMap::new();
		for key in keys {
			let address = if key.len() == 52 {
				H160::from_slice(&key[..20])
			} else if key.len() == 32 {
				ismp_host_address
			} else {
				return Err(SubstrateEvmError::InvalidKeyLength(key.len()).into());
			};
			contract_keys.entry(address).or_default().push(key);
		}

		let mut result_map = BTreeMap::new();

		for (address, keys) in contract_keys {
			let contract_info_key = contract_info_key(address);
			let trie_id = fetch_trie_id_from_main_proof::<H>(
				&proof.main_proof,
				state_root,
				&contract_info_key,
			)?;

			let child_root =
				fetch_child_root_from_main_proof::<H>(&proof.main_proof, state_root, &trie_id)?;

			let storage_proof = proof
				.storage_proof
				.get(address.as_bytes())
				.ok_or(SubstrateEvmError::StorageProofMissing(address.as_bytes().to_vec()))?;

			let storage_keys: Vec<Vec<u8>> = keys
				.iter()
				.map(|k| {
					let slot = if k.len() == 52 { &k[20..] } else { &k[..] };
					blake2_256(slot).to_vec()
				})
				.collect();

			let values = verify_child_trie_values::<H>(child_root, storage_proof, storage_keys)?;

			for (key, value) in keys.into_iter().zip(values.into_iter()) {
				result_map.insert(key, value);
			}
		}

		if result_map.len() != keys_len {
			return Err(SubstrateEvmError::MismatchedValuesAndKeys.into());
		}

		Ok(result_map)
	}
