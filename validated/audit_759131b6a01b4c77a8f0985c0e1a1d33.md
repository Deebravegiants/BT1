**Analysis:**

The runtime reference checker described in `native_models_for_runtime_ref_checks.rs` is a *defense-in-depth safety net* layered on top of the actual native execution, not the mechanism that determines which storage slot a `table::borrow_box_mut` call actually touches. The real value semantics come from `native_borrow_box`/`native_borrow_box_mut` in `third_party/move/mono-move/natives/src/table.rs`, which reads the table handle and serializes the actual `key` argument to look up the corresponding box in storage <cite repo="Alyssadaypin/aptos-core--037" path="third_party/move/mono-move/natives/src/table.rs" start="42="50" end="99" />. This real lookup is fully key-dependent and independent of the shadow ref-checker's abstract node labeling.

The abstract label `0` used in `native_static_dispatch_return` only affects the *shadow* access-path tree used for poisoning/exclusivity bookkeeping [1](#0-0) . If a Move module recursively/reentrantly calls `borrow_box_mut` on the same `&mut Table` for two different keys while the first returned `&mut Box<V>` is still live, the second call first passes the `&mut Table` argument again, and passing a mutable reference into any call is treated as a destructive write that poisons descendant references at that node [2](#0-1) . Since both borrows are modeled at the same child label `0` off the table's root node, the checker treats them as aliasing rather than disjoint — but the effect of this imprecision is that the earlier live reference gets poisoned, and any subsequent use of it raises `ref_check_failure!`, aborting the transaction [3](#0-2) . This is a fail-closed (over-conservative abort) outcome, not a fail-open corruption: it can only cause a spurious transaction abort, never a silent merge of the split and remainder balances or a write to one bypassing detection while affecting the other's real storage value, since the underlying storage box for each key is still addressed independently by the native implementation.

In short, the single-label-per-parameter limitation documented in the source (`native_models_for_runtime_ref_checks.rs`) is an acknowledged, intentional restriction whose worst-case effect is a false-positive poisoning/abort of legitimate reentrant patterns, not a custody-breaking collapse of two distinct balances [4](#0-3) . There is no path by which this abstraction bug lets an unprivileged caller cause a real write to one split half to mutate the tracked balance of the other half in actual storage.
