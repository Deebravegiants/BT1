### Title
RAY-value overflow in `scaled_to_original` permanently freezes a market — all accrual-first entrypoints revert (File: common/src/rates/scaling.rs)

### Summary
Every state-mutating pool operation — `supply`, `borrow`, `withdraw`, `repay`, `liquidate`, `clean_bad_debt`, flash paths — and the permissionless `update_indexes` path first run `global_sync`, which calls `accrue_step`. `accrue_step` computes `scaled_to_original(borrowed, borrow_index)` = `half_up(borrowed × borrow_index / RAY)` via `mul_div_half_up`, which panics with `GenericError::MathOverflow` when the RAY-scaled debt value exceeds `i128::MAX`. The index ceiling `MAX_BORROW_INDEX_RAY = 10^36` does not prevent this: a large market at sustained high utilization hits the value ceiling while the index is still below the cap, so the accrual panics before the cap can clamp it. Once this happens, the market is permanently bricked — the panic re-executes identically on every subsequent accrual because it depends only on stored `borrowed` and `borrow_index`, which never decrease without a successful repay (which itself accrues first). ### Finding Description
The WebKit bug class (crafted input → memory corruption → crash) maps to crafted state → unrepresentable fixed-point product → panic. `mul_div_half_up` widens intermediates to `I256` but still requires the *result* to fit `i128`, returning `None` and panicking otherwise [6](#0-5) . `scaled_to_original` uses `Ray::mul` (half-up), so the debt value `borrowed × borrow_index / RAY` must be < `i128::MAX ≈ 1.7e38`; i.e., value is bounded at ~170× RAY. The borrow index cap of `10^36` (1e9× initial) is far above this 170× cliff [7](#0-6) . The repo's own test confirms: after enough years at 98% utilization on the XLM rate curve, `try_update_indexes_for`, `try_withdraw_raw` and `try_repay` all revert with `MATH_OVERFLOW` while `borrow_index < MAX_BORROW_INDEX_RAY` [8](#0-7) . This is a state-integrity failure, not a fail-closed design: the corruption is permanent because the panic precedes any state write and every corrective path (repay, withdraw, liquidate, clean_bad_debt, recapitalize) is behind the same accrual gate.

### Impact Explanation
Permanent freezing of all funds in the affected market: no supplier can withdraw, no borrower can repay, no liquidator can liquidate, and bad debt cannot be cleaned. Protocol revenue in that market is also locked. The freeze is unrecoverable since there is no accrual-bypassing escape hatch — `Cache::load` explicitly does not accrue, and `global_sync`/`synced_market` is invoked by every mutation before any share movement.

### Likelihood Explanation
Requires an extremely large market — on the order of the ~170-billion-whole-token arithmetic domain bound — combined with sustained high utilization on a steep rate-curve segment over multiple years. That is a high practical bar, so likelihood is low; but the trigger inputs (supply volume, borrow demand, elapsed time) are all reachable by unprivileged users via `supply`/`borrow`, and `update_indexes` is callable by anyone to push accrual forward. Severity: Medium (High impact, low likelihood given capital requirements).

### Recommendation
Bound the value computation rather than the index alone: in `accrue_step`/`update_borrow_index`, clamp `borrow_index` to `min(cap, i128::MAX * RAY / borrowed)` (and similarly for the supply index in `update_supply_index`/`apply_bad_debt_to_supply_index`), so accrual saturates instead of reverting. Alternatively, make `scaled_to_original` saturating inside accrual so utilization/rate computation degrades gracefully while position-level unscaling keeps its strict overflow checks.

### Proof of Concept
Reproduced by the existing test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` [9](#0-8) :

1. Permissionless setup: `supply` 1e9 whole units of an 18-decimal asset; a second account supplies collateral and `borrow`s 98% of it.
2. Any address repeatedly calls `update_indexes` as time advances (`advance_time` in the test; natural ledger time in production) on the steep-utilization rate curve.
3. Within the tested horizon, `update_indexes` reverts with `MATH_OVERFLOW` at `borrow_index ≈ x170` — below `MAX_BORROW_INDEX_RAY`.
4. From then on, `withdraw(BOB, "BIG18", 1)` and `repay(ALICE, "BIG18", 1.0)` both revert with `MATH_OVERFLOW`; all supplier and borrower funds in the market are permanently frozen.

pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    // The zero check runs first so debug and release builds agree on a zero
    // divisor: both surface `DivisionByZero` rather than tripping the assert.
    require_nonzero_divisor(env, d);
    debug_assert!(
        x >= 0 && y >= 0 && d > 0,
        "mul_div_half_up: non-negative x, y and positive d"
    );
    try_mul_div_half_up(env, x, y, d)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
}

/// Computes `x * y / d` rounded half up. Returns `None` if `x < 0`, `y < 0`, `d <= 0`, or the
/// result does not fit in `i128`.
pub fn try_mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> Option<i128> {
    if x < 0 || y < 0 || d <= 0 {
        return None;
    }
    let half = d / 2;

    // Fast path: the biased product fits `i128`, so the whole computation is
    // native. `x * y + half` is non-negative here, so `/` is the floor the
    // widened path would produce.
    if let Some(biased) = x
        .checked_mul(y)
        .and_then(|product| product.checked_add(half))
    {
        return Some(biased / d);
    }

    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    x256.mul(&y256)
        .add(&I256::from_i128(env, half))
        .div(&d256)
        .to_i128()
}

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
}
