### Title
Attacker-controlled Python exception text can overflow fixed `SharedPort::SERIALIZED_OUTPUT_SIZE` and panic the biometric-pipeline agent process - ([File: `ai-interface/src/lib.rs`], [File: `agentwire/src/port.rs`])

### Summary
`PyError` (built from arbitrary Python exception `message`/`traceback` strings, see `PyError::from_py_err`) is serialized with rkyv into a fixed-size shared-memory buffer whose size is a compile-time constant (`Model::SERIALIZED_OUTPUT_SIZE = 4096`, `MegaAgentTwo::SERIALIZED_OUTPUT_SIZE`). If the serialized `Output::Error(PyError)` exceeds that fixed buffer, `serializer.serialize_value(value).expect(...)` in `serialize_message` (`agentwire/src/port.rs:743-760`) panics because the underlying `BufferSerializer` cannot write past the end of the slice.

### Finding Description
`PyError::from_py_err` (`ai-interface/src/lib.rs:25-33`) captures `error_type`, `message` (`py_err.value(py).to_string()`), and `traceback` (`tb.format()`) with no length bound. These strings are attacker-influenceable: crafted/malformed scenes fed to the RGB-Net / Face-Identifier / Iris Python models (`src/agents/python/face_identifier/mod.rs`, `src/agents/python/mega_agent_two.rs`) can trigger Python-side exceptions (e.g. deep recursion, numpy/OpenCV errors with large repr of arrays, long file paths embedded in tracebacks) whose textual representation can be arbitrarily long.

When such an error occurs, it is wrapped into `Output::Error(PyError)` / `Output::FusionError(...)` and sent across the shared-memory channel via `RemoteInner::send` → `serialize_message` (`agentwire/src/port.rs:717-726, 743-760`). The destination buffer size is fixed at compile time:
- `face_identifier::Model::SERIALIZED_OUTPUT_SIZE = 4096` bytes (`src/agents/python/face_identifier/mod.rs:121-126`)
- `MegaAgentTwo::SERIALIZED_OUTPUT_SIZE` similarly bounded by a fixed formula (`src/agents/python/mega_agent_two.rs:110-120`)

`serialize_message` uses `BufferSerializer::new(&mut buf[...])`; when the serialized payload does not fit in the remaining buffer, the underlying `Write` impl for `&mut [u8]` returns an `io::Error` (write past end of slice), which propagates as an `Err` from `serializer.serialize_value(value)`. The code immediately calls `.expect("failed to serialize an IPC message")` on this result (`agentwire/src/port.rs:755`), so an oversized `PyError` does not silently truncate or corrupt memory — it causes a **panic** inside the `tx` task driving the shared-memory output channel of the Python agent process.

This panic occurs inside `spawn_shared_tx_task`'s `task::spawn_local` (via `RemoteInner::send`, invoked from `run_python_process`'s main loop in `src/agents/python/mod.rs:157-168`), which will abort/crash the mega-agent-two (or face-identifier) Python subprocess, breaking the shared-memory pipeline for that biometric-pipeline process.

### Impact Explanation
This is a Denial-of-Service / process-crash within the biometric AI subprocess (mega-agent-two / face-identifier), not a memory-corruption or type-confusion primitive: rkyv's `BufferSerializer` is bounds-checked and returns an error rather than writing out of bounds, so there is no actual buffer overflow, truncation-induced type confusion, or arbitrary memory write. The concrete effect is a crashed/desynced Python agent process during a signup attempt, which the broker can detect (subprocess exit) and needs to restart — a capture-disruption/availability issue rather than unauthorized signup, wrong-identity binding, biometric data disclosure, or an attestation/signing bypass.

### Likelihood Explanation
Reachability requires that an attacker's presented scene actually cause the Python model code to raise an exception whose formatted `message`/`traceback` text exceeds ~4KB (or the corresponding `MegaAgentTwo` bound, which also includes a large frame-sized headroom via `RGB_NATIVE_HEIGHT * RGB_NATIVE_WIDTH * 3`). This repo does not contain the Python model source, so it cannot be confirmed from Rust-side code alone whether any code path in the actual models produces multi-kilobyte exception text from attacker-controlled image content (most Python tracebacks from vision-model exceptions are on the order of a few hundred bytes to ~1-2 KB, well under 4096 bytes). No evidence in the reachable Rust code shows an existing exploit trigger; this would need to be validated against the actual Python model implementations, which are outside this repo's indexed content.

### Recommendation
Truncate `PyError.message` / `PyError.traceback` to a bounded length (e.g., in `PyError::from_py_err`) before returning them cross-process, and/or make `serialize_message` handle serialization failure gracefully (log + drop/replace with a bounded fallback error) instead of `.expect()`-panicking, so an oversized error payload degrades gracefully rather than crashing the agent process.

### Proof of Concept
Unit test plan (in `agentwire`):
1. Construct a `PyError { error_type: "E".repeat(10), message: "M".repeat(8192), traceback: "T".repeat(8192) }` (exceeding `face_identifier::Model::SERIALIZED_OUTPUT_SIZE = 4096`).
2. Wrap it in `face_identifier::Output::Error(py_error)` and call `serialize_message` directly with a `4096`-byte buffer as used by `RemoteInner::send`.
3. Assert that the call currently panics with `"failed to serialize an IPC message"` (confirming crash-on-overflow, not corruption) — and after the fix, assert it returns an `Err`/bounded fallback with no panic and no out-of-bounds write, verified via `BufferSerializer` bounds and buffer content inspection (e.g., wrapping the buffer in a guard/canary region and asserting canary bytes remain untouched).
