The strongest analog to the `PeripheryPayments.refundETH()` bug class in this codebase is `CallDispatcher.dispatch()`, a completely unauthenticated external function that lets anyone force the contract to execute arbitrary calls — including transferring out any ETH or ERC-20 balance currently sitting in it.This confirms `CallDispatcher` is a single shared singleton used across `IntentGatewayV2.sol`, `HyperFungibleToken.sol`, `WrappedHyperFungibleToken.sol`, and their upgradeable variants — all of which route tokens/ETH through it as a temporary holding contract during calldata execution.

### Title
Unprotected `CallDispatcher.dispatch()` allows any caller to drain residual ETH/ERC-20 balances left in the shared dispatcher contract - (File: evm/src/utils/CallDispatcher.sol)

### Summary
`CallDispatcher.dispatch()` is `external` with zero access control, and executes attacker-supplied `Call[]` entries via `to.call{value: call.value}(data)` using the dispatcher's own balance. This is structurally identical to the reported `PeripheryPayments.refundETH()` bug class: an unauthenticated function that lets `msg.sender` push out the contract's current balance to any address. Because `CallDispatcher` is a shared singleton receiving ETH and ERC-20 tokens from `IntentGatewayV2`, `HyperFungibleToken`, and `WrappedHyperFungibleToken` during calldata execution, any residual balance left in it between transactions is stealable by an unprivileged party.

### Finding Description
`CallDispatcher` declares an open `receive() external payable {}` [1](#0-0)  and a `dispatch()` function with no modifier or caller check that forwards the contract's balance to arbitrary targets chosen by the caller: [2](#0-1) 

The apps that integrate with it treat it purely as a *temporary* holding contract within a single atomic transaction: `IntentGatewayV2._execute()`/predispatch flows push tokens/ETH to the dispatcher, invoke user-supplied calldata via `ICallDispatcher(dispatcher).dispatch(order.output.call)`, then sweep back whatever balance the dispatcher ends up holding via a second `dispatch(abi.encode(sweepCalls))` call [3](#0-2) , and `HyperFungibleToken`/`WrappedHyperFungibleToken` forward bridged funds through it the same way when `message.data.length > 0` [4](#0-3) .

The sweep logic only rebuilds `Call[]` entries for the exact set of tokens declared in `order.output.assets`, and only for the balance measured at sweep time [5](#0-4) . Any of the following leaves a non-zero balance sitting in the singleton `CallDispatcher` after the transaction completes:
- Fee-on-transfer or rebasing tokens whose balance changes between the transfer-in and the sweep-out call.
- Output/calldata tokens not enumerated in `order.output.assets` (e.g. reward tokens claimed incidentally by the user-supplied calldata).
- Direct/accidental ETH sends to the dispatcher's public `receive()`.
- Reverts partway through a multi-call batch of `dispatch()` from an unrelated app, leaving state that a partially-succeeded external call already transferred in before the batch as a whole reverted in a way that doesn't roll back a prior successful sub-transaction (e.g. cross-app races where two apps use the same dispatcher instance).

Because `dispatch()` has no authentication, any unprivileged address can, in an ordinary transaction, submit `dispatch(abi.encode([Call{to: attacker, value: dispatcher.balance, data: ""}]))` for ETH, or the equivalent `IERC20.transfer` call for any ERC-20, and pull out whatever balance is currently resident — including funds that legitimately belong mid-flight to another user's `placeOrder`/`fillOrder`/bridge-transfer operation if it is not atomic with respect to the dispatcher's balance, or dust left after prior operations.

### Impact Explanation
Any native ETH or ERC-20 tokens that end up resident in the shared `CallDispatcher` — whether from incomplete sweeps, fee-on-transfer dust, or direct transfers — can be permanently stolen by any unprivileged caller. Since the same `CallDispatcher` deployment is shared across `IntentGatewayV2`, `HyperFungibleToken`, and `WrappedHyperFungibleToken` on a given chain [6](#0-5) , this is a shared attack surface across all of Hyperbridge's EVM app contracts that route calldata through it, satisfying the "concrete theft of funds" bar for a valid finding.

### Likelihood Explanation
Reachable directly by any unprivileged externally-owned account with a single transaction to `CallDispatcher.dispatch()` — no proof, no relayed message, and no privileged role required. The precondition (non-zero resident balance) depends on dust/edge-case accumulation (fee-on-transfer tokens, partial sweep mismatches, or stray direct transfers via the open `receive()`), which is plausible given fee-on-transfer tokens are explicitly anticipated elsewhere in the codebase (`IntentGatewayV2.sol` comments on "fee-on-transfer tokens" reducing received amounts).

### Recommendation
Restrict `CallDispatcher.dispatch()` to be callable only by an authorized caller (e.g., an allowlist of registered app contracts, or make each app deploy/own its own dispatcher instance instead of sharing one singleton), and/or ensure the dispatcher never retains a standing balance across transactions by having it self-sweep any residual native/token balance back to a fixed, trusted recipient at the end of every `dispatch()` call rather than relying on the caller's downstream sweep logic.

### Proof of Concept
1. Suppose `IntentGatewayV2.fillOrder()` executes `order.output.call` through the shared `CallDispatcher`, and the calldata claims a reward token not listed in `order.output.assets`, or a fee-on-transfer output token leaves a small residual balance after the sweep `dispatch(abi.encode(sweepCalls))` call completes.
2. That residual ETH/token balance now sits in `CallDispatcher`, a permanently deployed, shared contract.
3. Any attacker calls `CallDispatcher.dispatch(abi.encode([Call({to: attacker, value: CallDispatcher.balance /* for ETH */, data: ""})]))` directly — this passes the `NotContract` check trivially (attacker can point `to` at a throwaway contract with a `receive()`), and the unauthenticated `dispatch()` forwards the entire balance out.
4. For ERC-20 dust, the attacker instead submits `Call({to: token, value: 0, data: abi.encodeWithSelector(IERC20.transfer.selector, attacker, token.balanceOf(dispatcher))})`.
5. The funds are irrecoverably transferred to the attacker with no on-chain check that the caller has any relationship to the original order/transfer.

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }

        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            } else {
                uint256 balance = IERC20(token).balanceOf(dispatcher);
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            }

                ++i;
            }
        }
