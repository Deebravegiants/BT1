Confirmed: `Bonding.sol` has only two rescue-type functions (`_sweepLTToOwner` used during graduation phase-2, and something in `FeeVault.sol` for donations), and none of them cover LT donated directly to the curve `Pair` before or during `Curve` lifecycle. There is no admin/owner function anywhere in `Pair.sol`, `Router.sol`, or `Bonding.sol` that can call `Pair.transferAsset` outside of `Router.sell` and `Router.graduate` (both `BONDING_ROLE`-gated and both unreachable once `Bonding.graduate` has already run once per token). This confirms the freeze is permanent and matches the OptimismPortal `donateETH` bug class: unrecoverable value sent to a contract with no sweep path.

### Title
Unrecoverable LT locked forever in curve `Pair` from direct donation before/after graduation - ([File: packages/contracts/src/Router.sol], [File: packages/contracts/src/Pair.sol], [File: packages/contracts/src/Bonding.sol])

### Summary
Any unprivileged wallet can call `IERC20(lt).transfer(pairAddress, amount)` directly on a bonding-curve `Pair`. The protocol deliberately design excludes such donated LT from graduation accounting (`ltFromPair = assetReserve - virtualLtReserve`, based on stored reserves, not live balance) so the donation never enters the LP and never influences the graduation trigger. However, once the token graduates, the only code paths capable of moving asset tokens out of the `Pair` (`Router.sell` and `Router.graduate`, both gated `onlyRole(BONDING_ROLE)` and reached only through `Bonding`) become permanently unreachable for that pair, leaving the donated LT stranded in the abandoned `Pair` contract with no rescue mechanism, exactly mirroring the `OptimismPortal.donateETH` stuck-funds bug class (value accepted with no path to recover it).

### Finding Description
- `Pair.transferAsset` is gated `onlyRouter` [1](#0-0) .
- `Router` exposes `transferAsset` only through `sell` and `graduate`, both requiring `BONDING_ROLE`, which only `Bonding` holds [2](#0-1) [3](#0-2) .
- `Bonding` only calls `Router.graduate` once per token from `_prepareGraduationLiquidity`, itself only reachable from `_enterGraduating` while the token's lifecycle is still `Curve` [4](#0-3) . After `finalizeGraduation` sets `lifecycle = Lifecycle.Graduated` [5](#0-4) , there is no remaining call path back into `graduate` for that pair.
- The team's own natspec confirms this is a deliberate but unenforced trust assumption, not an on-chain guarantee: "‘Locked’ here is a trust-assumption claim, not an on-chain guarantee... the leftover is unreachable as long as (a) `BONDING_ROLE` is not granted to any other address, and (b) future `Bonding` upgrades preserve the lifecycle gate" [6](#0-5) .
- No sweep/rescue function exists anywhere in `Pair.sol`, `Router.sol`, or `Bonding.sol` for LT sitting in a `Pair` outside the `ltFromPair` window (the only similar mechanisms, `Bonding._sweepLTToOwner` and `FeeVault.sweepDonations`, operate on `Bonding`'s and `FeeVault`'s own balances respectively, not on a graduated `Pair`'s residual balance) [7](#0-6) [8](#0-7) .
- The existing test `test_graduate_leavesDonationBehind` confirms the donated LT is intentionally left in the pair post-`graduate` [9](#0-8) .

### Impact Explanation
Any LT donated to a curve `Pair`, by an attacker, a well-meaning user, or by mistake (e.g., a wrong-decimal transfer, or an over-generous "seed the pair" attempt), is permanently and irrecoverably lost once that token graduates. This is a direct, unbounded loss of funds with no admin escape hatch — the same root cause class flagged in the OptimismPortal report (accept-but-never-recover). The amount at risk scales with donation size and is entirely attacker- or user-controlled.

### Likelihood Explanation
Reaching this state requires only a plain `IERC20.transfer` call to a publicly known `Pair` address — no privileged role, no contract interaction beyond a standard ERC20 transfer. Because it costs the donor real LT with zero benefit (donation-resistance by design means it neither pumps the price nor triggers graduation early for the donor's benefit), it is more likely to occur accidentally (a user or bot mistakenly sending LT to what looks like a pool address) than as a deliberate griefing attack, but it is trivially reachable by any unrelated wallet at any time before or during the curve's life.

### Recommendation
Add a permissionless (or owner-gated) sweep function reachable after `Lifecycle.Graduated` that calls `Pair.transferAsset`/`Pair.transferToken` for any pair-side balance above the recorded reserves (mirroring the `skim`-then-classify pattern already used in `_seedUniswapV2Direct`), and route the recovered LT to `FeeVault` or the protocol owner, consistent with how `_sweepLTToOwner` already handles residual LT held by `Bonding` itself.

### Proof of Concept
1. `Bonding.launch()` creates `tokenA` and its `Pair` against LT `X`.
2. A stranger (no role required) calls `X.transfer(pairAddress, 1000e18)` directly on the ERC20, donating 1000 LT to the curve `Pair`.
3. Trading proceeds normally; `canGraduate()` reads only stored reserves, so the donation is correctly excluded from the graduation trigger, per `_prepareGraduationLiquidity`'s `assetReserve`-based computation [4](#0-3) .
4. The token eventually graduates via `_enterGraduating` → `finalizeGraduation`; `Router.graduate` drains only `ltFromPair` (the curve-raised amount), explicitly leaving the 1000 LT donation behind in the `Pair`, as verified by `test_graduate_leavesDonationBehind` [9](#0-8) .
5. `info.lifecycle` is now `Graduated`; no function in `Bonding`, `Router`, or `Pair` can ever again call `Pair.transferAsset` for that pair (both call sites require `BONDING_ROLE` and are gated behind `Curve`-lifecycle-only entry points).
6. The 1000 LT sits in the abandoned `Pair` contract forever, with no owner, no depositor, and no sweep path to retrieve it — a permanent, unrecoverable loss identical in structure to the OptimismPortal `donateETH` stuck-ether issue.

    /// @notice Transfer exactly `amount` of LT out of the pair to the caller.
    ///         Called by `Bonding._prepareGraduationLiquidity` during graduation
    ///         with `amount = stored assetReserve - virtualLtReserve` (i.e. the
    ///         real LT raised by the curve, excluding the virtual seed).
    /// @dev    Donation-resistant: passing an explicit `amount` instead of
    ///         draining `assetBalance()` ensures any LT that was donated
    ///         directly to the pair via `IERC20.transfer` is left behind and
    ///         excluded from LP seeding.
    ///
    ///         "Locked" here is a trust-assumption claim, not an on-chain
    ///         guarantee. `Pair.transferAsset` is gated by `onlyRouter`, and
    ///         `Router` only exposes it via this function and `sell`. Both
    ///         require `BONDING_ROLE`, which only `Bonding` holds. `Bonding`
    ///         in turn only calls `graduate` from
    ///         `_prepareGraduationLiquidity` — which is unreachable once the
    ///         token's lifecycle has flipped past `Curve`. So the leftover
    ///         is unreachable as long as (a) `BONDING_ROLE` is not granted
    ///         to any other address, and (b) future `Bonding` upgrades
    ///         preserve the lifecycle gate.
    function graduate(
        address token,
        uint256 amount
    ) external onlyRole(BONDING_ROLE) {
        address asset = assetTokenFor(token);
        address pairAddr = factory.getPair(token, asset);
        if (pairAddr == address(0)) revert PairNotFound();
        IPair(pairAddr).transferAsset(msg.sender, amount);
    }

    function finalizeGraduation(
        address tokenAddress
    ) external nonReentrant {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[tokenAddress];
        if (info.lifecycle != Lifecycle.Graduating) revert NotGraduating();

        address lt = info.ltAddress;
        PendingGraduation memory p = $.pendingGraduation[tokenAddress];

        // Anything in this contract beyond `p.ltFromPair` belongs to a
        // concurrent graduation on the same LT (Phase 1 transferred it
        // via `Router.graduate`) or to stray dust. Either way it is
        // off-limits to this graduation's deposit and sweep — see
        // `_routerDepositAndDispose` and `_sweepLTToOwner`.
        // Saturating subtract: a balance below `p.ltFromPair` shouldn't
        // be reachable in normal operation, but we keep finalize from
        // bricking on a Panic if any future code path or non-canonical
        // LT briefly violates the invariant.
        uint256 ltBalance = IERC20(lt).balanceOf(address(this));
        uint256 protectedLT = ltBalance > p.ltFromPair ? ltBalance - p.ltFromPair : 0;

        address lpPair = _ensureUniswapV2Pair(tokenAddress, lt);
        uint256 liquidity = _seedUniswapV2Direct(tokenAddress, lt, lpPair, p.tokensForLP, p.ltFromPair, protectedLT);

        _sweepLTToOwner(lt, protectedLT);

        info.lifecycle = Lifecycle.Graduated;
        $.graduatedPair[tokenAddress] = lpPair;
        delete $.pendingGraduation[tokenAddress];

        LPLock($.lpLock).recordLock(tokenAddress, lpPair, liquidity);

        emit TokenGraduated(tokenAddress, lpPair, liquidity, p.tokensForLP, p.lpBurned, p.unsoldBurned);
    }

    function _prepareGraduationLiquidity(
        address tokenAddress
    ) internal returns (uint256 tokensForLP, uint256 ltFromPair, uint256 lpBurned, uint256 unsoldBurned) {
        address pairAddr = _s().tokenInfo[tokenAddress].pair;
        (uint256 tokenReserve, uint256 assetReserve) = IPair(pairAddr).getReserves();

        unsoldBurned = IPair(pairAddr).tokenBalance();
        if (unsoldBurned > 0) {
            Token(tokenAddress).burn(pairAddr, unsoldBurned);
        }

        ltFromPair = assetReserve - _launchTimeVirtualLtReserve(tokenAddress, pairAddr);
        if (ltFromPair > 0) {
            _s().router.graduate(tokenAddress, ltFromPair);
        }

        tokensForLP = assetReserve == 0 ? 0 : (ltFromPair * tokenReserve) / assetReserve;
        if (tokensForLP > LP_RESERVE) tokensForLP = LP_RESERVE;

        lpBurned = LP_RESERVE - tokensForLP;
        if (lpBurned > 0) {
            Token(tokenAddress).burn(address(this), lpBurned);
        }
    }
