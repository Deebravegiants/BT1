### Title
Arbitrary swap-route venue can inject token transfers into the caller's authorization tree - (File: contracts/controller/src/strategies/swap.rs)

### Summary
User-controlled `swap` bytes reach the configured router without the controller decoding or constraining the route. A route can therefore name an attacker-controlled venue, which can add an unrelated token transfer beneath the caller's `swap_collateral` authorization. If simulation returns that authorization tree and the caller signs it, the malicious venue can steal wallet assets unrelated to the lending swap.

### Finding Description
`swap_collateral` accepts a caller-supplied `StrategySwap` and forwards it through `withdraw_and_swap_from_supply` [1](#0-0) . `swap_tokens` authorizes only the expected input transfer to the configured router, but then passes the opaque `swap` payload to `execute_strategy` [2](#0-1) . The controller measures router input and output balances, but it does not restrict which contracts the route causes the router to call [3](#0-2) .

A route-selected venue can invoke a token transfer from the caller to an attacker-controlled recipient [4](#0-3) . Soroban simulation records that transfer as a child of the caller's controller authorization rather than rejecting the route outright [5](#0-4) . The test confirms that the transfer executes when the returned poisoned tree is signed [6](#0-5) .

### Impact Explanation
The caller can lose unrelated tokens held in their wallet. The stolen amount is not limited to the collateral being swapped or to assets deposited in the lending account; any token transfer that simulation records and the caller signs can execute. The test demonstrates complete theft of an unrelated wallet-token balance while still supplying the expected swap output [7](#0-6) .

### Likelihood Explanation
Exploitation requires the victim to submit an attacker-crafted route and sign the authorization tree containing the malicious token transfer. Balance-delta checks, positive output requirements, and the final risk check do not detect or bound that extra transfer [3](#0-2) . Clients that decode and enforce the simulated authorization tree can avoid the attack, but the production controller accepts the injected route and provides no protocol-level venue allowlist.

### Recommendation
Reject arbitrary route-selected venues. Decode the `StrategySwap` and enforce a governance-managed allowlist of venue contracts and expected venue entrypoints before calling the router. Independently, wallet and SDK integrations should fail any swap authorization tree containing children other than the expected input-token transfer.

### Proof of Concept
1. The attacker deploys a contract whose `swap` function calls `token::Client::transfer(victim, attacker, amount)` for a token unrelated to the lending position.
2. The attacker constructs a `swap` payload that routes through that contract.
3. The victim calls `swap_collateral(caller, account_id, current, amount, new, swap)` or another strategy entrypoint that reaches `swap_tokens`.
4. Simulation returns an authorization tree containing the malicious token transfer beneath `swap_collateral`.
5. If the victim signs that tree, the route produces normal swap output while the unrelated token balance moves to the attacker. The repository's regression test implements this behavior and demonstrates that signing the poisoned tree empties the victim's wallet-token balance [6](#0-5) .

#[test]
fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
