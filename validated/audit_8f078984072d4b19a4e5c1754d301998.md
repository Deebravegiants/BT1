### Title
Unrecoverable `MathOverflow` panic in interest accrual permanently freezes a market once scaled debt × borrow index exceeds `i128` - (File: common/src/rates/index.rs)

### Summary
Analogous to the Besu "raises exception leading to chain split" bug class — an arithmetic edge case produces an unhandled exception — the pool's accrual path panics when `borrowed * borrow_index` overflows `i128`, and because every state-changing entrypoint runs `global_sync` first, the panic becomes a permanent, deterministic halt of the entire market: no repay, no withdraw, no borrow, no liquidation. An unprivileged borrower can push a market into this absorbing failure state by opening a very large debt position and letting interest accrue.

### Finding Description
`accrue_step` in `common/src/rates/simulate.rs` calls `scaled_to_original(env, borrowed, borrow_index)` (`common/src/rates/scaling.rs:14-16`) and `calculate_supplier_rewards`, which computes `borrowed.mul(env, new_borrow_index)` (`common/src/rates/index.rs:80-81`). `borrowed` is a RAY-scaled quantity (`raw_asset × 10^27 / 10^decimals`), so the product grows quadratically in index. `update_borrow_index` caps the index at `MAX_BORROW_INDEX_RAY = 10^36` (`common/src/rates/index.rs:13-19`), but the value-overflow cliff is `i128::MAX ≈ 1.7e38` — for a scaled `borrowed` on the order of `1e36` RAY-raw (≈1 billion whole tokens at 18 decimals), the product overflows at an index of only ~170×, far below the 1000× index cap. The multiplication panics via `Ray::mul`/`checked_*` → `GenericError::MathOverflow`.

`global_sync` (`contracts/pool/src/interest.rs:20-33`) runs this accrual before every pool verb, so once the panic condition is reached there is no transaction that can advance `last_timestamp` or shrink `borrowed` — repayments, withdrawals, borrows, `update_indexes`, and liquidations all accrue first and all hit the same panic. The repository's own harness proves this end-to-end: `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-360` supplies a billion-unit market, borrows 98% of it, advances time, and asserts `MATH_OVERFLOW` on `update_indexes`, `withdraw`, and `repay`, with the comment "the market is frozen: no repay, no withdraw, no liquidation. The index cap never engages."

### Impact Explanation
Permanent freezing of funds and protocol insolvency. All suppliers to the affected (hub, token) book lose access to their deposits forever; borrower debt can never be repaid or liquidated, so the collateral backing it is also locked and bad debt can never be cleaned. The state is absorbing — the panic is deterministic on every subsequent call, not a transient revert.

### Likelihood Explanation
Requires a whale-scale position: on an 18-decimal asset, ~1 billion whole tokens borrowed against roughly equivalent collateral, plus a few years of accrual at high utilization on a steep rate curve. The supply/borrow caps are governance-set parameters and `require_cap_within_asset_domain` only validates them against the asset domain, so nothing protocol-internal prevents listing a market with caps this large. INV-IDX-01 in `docs/reference/invariants.md` already acknowledges "Debt-value overflow can still revert accrual before that ceiling is reached," confirming the reachable domain.

### Recommendation
Guard the accrual path so debt growth saturates instead of panicking: e.g., compute `new_total_debt` via a saturating `mul_div` and clamp `new_borrow_index` so that `borrowed * new_borrow_index` stays within `i128` (an effective per-market index ceiling below `MAX_BORROW_INDEX_RAY`), or clamp the scaled `borrowed`/`supplied` totals at entry. Alternatively, enforce a borrow cap `scaled_borrowed × MAX_BORROW_INDEX_RAY < i128::MAX` at listing time in `require_cap_within_asset_domain` so the overflow domain is unreachable.

### Proof of Concept
- `common/src/rates/index.rs:80-83` — `borrowed.mul(env, new_borrow_index)` panics on `i128` overflow before the `MAX_BORROW_INDEX_RAY` clamp can protect it.
- `common/src/rates/simulate.rs:60-66` — `accrue_step` reaches this via `scaled_to_original` and `calculate_supplier_rewards`.
- `contracts/pool/src/interest.rs:20-33` — `global_sync` runs accrual before every mutating verb, making the panic absorbing.
- `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-360` — executable PoC: supply 1e9 × 10^18, borrow 98%, advance years, then `update_indexes`, `withdraw`, and `repay` all revert with `MATH_OVERFLOW` while `borrow_index < MAX_BORROW_INDEX_RAY`.
