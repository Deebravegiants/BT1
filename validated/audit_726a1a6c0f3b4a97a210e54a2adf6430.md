### Title
Stale `_requestCommitments` entry after a successful GET response enables a second `onGetTimeout` delivery for the same request - (File: `evm/src/core/EvmHost.sol`)

### Summary
`EvmHost.dispatchIncoming(GetResponse ...)` never clears the outgoing request's `_requestCommitments[commitment]` entry after successfully delivering the response and paying the relayer fee. Because `HandlerV2.handleGetRequestTimeouts` only checks `_requestCommitments[commitment].sender != address(0)` (plus a destination-side non-membership proof that is trivially satisfiable for GET requests, since GET reads never produce a destination-side "response receipt"), a relayer can later drive the same request through the timeout path and force a second, contradictory delivery (`onGetTimeout`) to the destination application after `onGetResponse` already fired.

### Finding Description
`dispatchIncoming(GetResponse)` sets the response receipt, invokes `onGetResponse` on the destination module, and on success pays the relayer fee out of `_requestCommitments[commitment].fee` — but does not delete `_requestCommitments[commitment]`: [1](#0-0) 

Compare this with the timeout path, `dispatchTimeOut(GetRequestTimeout, ...)`, which is the only other consumer of `_requestCommitments` for outgoing GET requests and is guarded solely by that mapping's `sender != address(0)`: [2](#0-1) 

`HandlerV2.handleGetRequestTimeouts` fetches `meta = host.requestCommitments(commitment)` and only reverts with `UnknownMessage` if `meta.sender == address(0)`. It then requires a *destination*-side non-membership proof for a `ResponseReceipts` child-trie key: [3](#0-2) 

For GET requests, the "response" is produced by directly reading destination-chain state and proving it via `handleGetResponses` on the *source* host — the destination chain itself never writes a `ResponseReceipts` entry for a GET (that receipt type exists for POST/Get-response bookkeeping on chains that process requests, not for stateless key-reads). This means the non-membership proof required by `handleGetRequestTimeouts` for a GET request is essentially always satisfiable, regardless of whether the response was already delivered to the source host. The *only* real safeguard against re-processing a fulfilled GET request through the timeout path is the `_requestCommitments[commitment].sender != address(0)` check in `handleGetRequestTimeouts` / `dispatchTimeOut` — and that check never becomes false for a request whose response has already been delivered, because `dispatchIncoming(GetResponse)` fails to delete the entry.

Consequently, after a request has been fully and successfully serviced through `onGetResponse`, an unprivileged relayer can subsequently (once `request.timeout()` elapses) submit `handleGetRequestTimeouts` for the same request/commitment and force `onGetTimeout` to also execute on the destination module — a forged, duplicate terminal callback for a request that already completed.

### Impact Explanation
Applications built on Hyperbridge's ISMP interface (`IApp`) are expected to receive exactly one terminal callback per request — either `onGetResponse` or `onGetTimeout` — and typically gate state transitions or fund releases on that single callback. Because the host allows both callbacks to fire for the same request, any downstream application (token bridge, intent solver, escrow contract) that performs an action (e.g., releasing collateral, minting, unlocking escrow, finalizing an order) on `onGetResponse` and a *different* action (e.g., refund/cancel) on `onGetTimeout` can be driven through both paths, corrupting internal accounting or enabling double-spend/double-refund conditions in the app layer. This is a forged/duplicate message delivery from the host to unprivileged downstream logic, satisfying the "unauthorized app action" / "forged message delivery" criteria.

### Likelihood Explanation
Reachable by any relayer (unprivileged) with a single additional transaction: no special permissions, governance, or admin actions are required — only a normal timeout-message submission after a request has already been serviced by another relayer. The precondition (destination-side non-membership proof for GET's `ResponseReceipts` key) is structurally satisfiable for GET requests since that trie entry is never populated for GET flows, making exploitation straightforward rather than probabilistic.

### Recommendation
In `EvmHost.dispatchIncoming(GetResponse ...)`, delete `_requestCommitments[commitment]` once the response has been successfully delivered (mirroring the replay-protection pattern already used in `dispatchTimeOut`), and have `handleGetRequestTimeouts`/`dispatchTimeOut` treat an already-cleared commitment as `UnknownMessage`/no-op rather than allow a second dispatch to the destination module for the same request.

### Proof of Concept
1. Source chain dispatches a `DispatchGet` request; `_requestCommitments[commitment]` is populated with `{sender, fee}` (`evm/src/core/EvmHost.sol:974-1013`).
2. A relayer proves the destination-chain state and calls `handleGetResponses` → `dispatchIncoming(GetResponse)`; `onGetResponse` succeeds, the relayer fee is paid, but `_requestCommitments[commitment]` is left untouched.
3. After `request.timeout()` elapses, any relayer calls `handleGetRequestTimeouts` with `message.timeouts` containing the same `GetRequest` and a (trivially valid) non-membership proof for the `ResponseReceipts` key on the destination trie.
4. `meta.sender != address(0)` still holds (stale metadata), so the call passes `UnknownMessage` check and reaches `host.dispatchTimeOut(GetRequestTimeout, meta, commitment)`, which calls `onGetTimeout` on the same destination module that already received `onGetResponse` for this exact request.

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
