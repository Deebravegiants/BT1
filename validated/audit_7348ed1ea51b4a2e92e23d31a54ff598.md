### Title
Optimism/OP-Stack fault-dispute-game consensus client accepts unresolved, permissionlessly-created dispute games as canonical L2 state after a too-short internal challenge period - (File: `modules/ismp/clients/optimism/src/lib.rs`)

### Summary
Hyperbridge's OP-Stack consensus client accepts an L2 state root as soon as a fault-dispute-game proxy for it exists in the `DisputeGameFactory` and currently shows no counter-claim (`claimData.length == 1`), rather than requiring the game's real, bonded fault-proof resolution (`status()`/`resolvedAt()`/`Resolved` event indicating `DEFENDER_WINS`) to have actually completed. Because dispute-game creation is explicitly permissionless ("anyone can create dispute games including bots"), and Hyperbridge's own `challenge_period` for OP-Stack clients is configured to just 5 minutes — far shorter than the real OP-Stack fault-proof resolution window — an attacker can register a dispute game with a forged root claim, get it accepted by Hyperbridge as a trusted `StateCommitment`, and have request/response/state proofs verified against that forged root before the real dispute game is ever contested or resolved on L1. This mirrors the Cozy Finance bug class: an oracle/trigger is treated as final based on "currently undisputed" status rather than true, finalized resolution, and eligibility (here, state-proof verification) is not tied to the real underlying event.

### Finding Description
`verify_optimism_dispute_game_proof` in `modules/ismp/clients/optimism/src/lib.rs` verifies only that:
1. A dispute-game proxy for the claimed `(game_type, root_claim, extra_data)` exists in the factory's `_disputeGames` map [3](#0-2) .
2. The proxy's implementation matches the configured `expected_impl` [4](#0-3) .
3. The game is "not challenged", which for `FaultDisputeGame` only checks that `claimData.length == 1` (i.e., only the root claim has been registered, no `move()` has been submitted yet) [5](#0-4) .

Nowhere does this verification check the OP-Stack game's actual `status()` (`DEFENDER_WINS`/`CHALLENGER_WINS`/`IN_PROGRESS`) or `resolvedAt()`, i.e. whether the OP-Stack fault-proof process has truly concluded. "Unchallenged so far" is treated as equivalent to "finalized correct", exactly like Cozy Finance's UMA trigger treating "no dispute submitted yet" as equivalent to "verified true".

Dispute-game creation on OP-Stack is explicitly permissionless: "Any bonded party can submit an L2 output root as a fault dispute game at any time" [2](#0-1) , and Hyperbridge's own relayer code acknowledges this: "Since anyone can create dispute games including bots we need to be sure the block number exists" [1](#0-0) .

Hyperbridge additionally enforces only its own internal `challenge_period`, configured to a flat 5 minutes for OP-Stack clients: [6](#0-5) 

That 5-minute window is enforced generically via `validate_state_machine`/`verify_delay_passed`, which only checks Hyperbridge's own configured `challenge_period`, not the real OP-Stack dispute-resolution clock (typically multi-day) [7](#0-6) .

An attacker can:
1. Call `DisputeGameFactory.create(gameType, forgedRootClaim, extraData)` for the target OP-Stack chain, bonding only `initBonds[gameType]` (a moderate, refundable/losable bond, not proportional to funds at risk on Hyperbridge).
2. Immediately submit an `OptimismConsensusProof::OpFaultProofGames` update to Hyperbridge's `ismp-optimism`/op consensus client with a proof that this freshly-created game exists and is unchallenged (`claimData.length == 1`, trivially true for a brand-new game).
3. `verify_optimism_dispute_game_proof` accepts the forged `state_root` as a new `StateCommitment` for the destination chain, entering only Hyperbridge's 5-minute `challenge_period` [8](#0-7) .
4. Once the 5-minute delay elapses (`verify_delay_passed`), any state/withdrawal proof built against the forged root — e.g., ISMP `PostRequest`/`GetResponse` message delivery via `HandlerV2`, `IntentGatewayV2`/`IntrinsicIntents` escrow releases, or `accumulate_fees`/outbound-request reward claims — is accepted as authentic by Hyperbridge, while the real OP-Stack `FaultDisputeGame` is still fully open for challenge for days afterward.

The only mitigation present, `FishermanBlacklist`/`is_dispute_game_blacklisted`, is a reactive, governance/fisherman-driven blacklist checked before verification [9](#0-8)  — it requires someone to notice and blacklist the malicious game within the 5-minute window, which is not guaranteed, especially for lower-traffic OP-Stack chains where fishermen may not be actively monitoring every new dispute game.

### Impact Explanation
Accepting a forged state root within a 5-minute window (versus the multi-day real OP-Stack dispute period) lets an attacker forge arbitrary destination-chain state to Hyperbridge — enabling unauthorized ISMP message delivery, forged storage-proof-based token bridge mint/release, intents escrow withdrawal, or fee/reward claims against state that never actually existed on the real L2. This is a direct path to theft of escrowed/bridged funds and forged message delivery, matching "unsound state commitment" and "forged message delivery" in the validation criteria.

### Likelihood Explanation
The attack requires only a single permissionless `DisputeGameFactory.create()` call plus a single consensus-update submission to Hyperbridge — both actions any unprivileged relayer/user can perform, no governance or validator collusion needed. The bond cost is fixed and small relative to potential funds unlocked on Hyperbridge for high-value chains, and the 5-minute acceptance window is far shorter than realistic fisherman/challenger reaction time for a freshly-deployed, low-visibility dispute game.

### Recommendation
Require the dispute-game's actual on-chain `status()`/`resolvedAt()` (or `Resolved` event) to show `DEFENDER_WINS` and, if using the "not challenged" fast-path, size Hyperbridge's `challenge_period` for OP-Stack clients to be at least as long as the OP-Stack `FaultDisputeGame`'s configured max clock duration / resolution window for that specific deployment, rather than a flat 5 minutes, so that a still-contestable dispute game can never back a Hyperbridge state commitment used for state-proof verification.

### Proof of Concept
1. On the target OP-Stack L2's L1, call `DisputeGameFactory.create(CANNON, forged_root_claim, extra_data_with_arbitrary_l2_block_number)`, paying `initBonds[CANNON]`.
2. Build an `OptimismDisputeGameProof` referencing this freshly created game (membership proof of `_disputeGames[gameUUID]`, `gameImpls[gameType]`, and the proxy's `claimData` slot showing length `1`), per `verify_optimism_dispute_game_proof` in `modules/ismp/clients/optimism/src/lib.rs`.
3. Submit it via `update_client`/`OptimismConsensusProof::OpFaultProofGames` to Hyperbridge; `ismp-optimism` accepts `forged_root_claim`'s embedded `state_root` as the new `StateCommitment` for that L2 at the claimed height.
4. Wait out Hyperbridge's 5-minute `challenge_period` (vs. the real multi-day OP-Stack game clock, still open).
5. Submit any state/withdrawal proof (e.g., a forged `RequestReceipts`/escrow-slot proof) against this state root through `HandlerV2`/`accumulate_fees`/`IntentGatewayV2` to extract funds or force message delivery that never happened on the genuine L2.

pub fn verify_optimism_dispute_game_proof<H: Keccak256 + Send + Sync>(
	payload: OptimismDisputeGameProof,
	root: H256,
	dispute_factory_address: H160,
	game_type_configs: Vec<GameTypeConfig>,
	consensus_state_id: ConsensusStateId,
) -> Result<IntermediateState, Error> {
	// Find the per-game-type configuration for this proof's game type.
	let game_config = game_type_configs
		.iter()
		.find(|c| c.game_type == payload.game_type)
		.ok_or(Error::UnsupportedGameType(payload.game_type))?
		.clone();

	let factory_storage_root =
		get_contract_account::<H>(payload.dispute_factory_proof, &dispute_factory_address.0, root)?
			.storage_root
			.0
			.into();
	let l2_block_hash = Header::from(&payload.header).hash::<H>();

	let root_claim = calculate_output_root::<H>(
		payload.version,
		payload.header.state_root,
		payload.withdrawal_storage_root,
		l2_block_hash,
	);

	let game_uuid = get_game_uuid::<H>(payload.game_type, root_claim, payload.extra_data);

	let dispute_game_key = derive_map_key::<H>(game_uuid.0.to_vec(), DISPUTE_GAMES_SLOT);

	// Does the dispute game's unique identifier exist in the _disputeGames map?
	let proof_value = match get_value_from_proof::<H>(
		dispute_game_key.0.to_vec(),
		factory_storage_root,
		payload.dispute_game_proof,
	)? {
		Some(value) => value.clone(),
		_ => Err(Error::DisputeGameIdMissing)?,
	};

	let mut encoded_game_id = <alloy_primitives::Bytes as Decodable>::decode(&mut &*proof_value)
		.map_err(|_| Error::DecodeDisputeGameId(format!("{:?}", &proof_value)))?
		.0
		.to_vec();

	let game_id = get_game_id(payload.game_type, payload.timestamp, payload.proxy);
	let game_id_bytes = game_id.to_big_endian();

	// Pad the encoded game id gotten from proof with zeros so it becomes 32 bytes long
	(0..game_id_bytes.len().saturating_sub(encoded_game_id.len()))
		.for_each(|_| encoded_game_id.insert(0, 0));

	// Derived game id must be equal to encoded game id
	if encoded_game_id != game_id_bytes {
		Err(Error::DisputeGameIdMismatch)?
	}

	match kind {
		DisputeGameImpl::FaultDisputeGame => {
			// `claimData` is a dynamic `ClaimData[]` at `FAULT_DISPUTE_CLAIM_DATA_SLOT`. Solidity
			// stores a dynamic array's element count in the slot itself (the elements live at
			// `keccak256(slot)`). A freshly created, unchallenged game holds exactly one entry —
			// the root claim appended in `initialize()` — and every `move()` (attack or defense)
			// appends another. So `claimData.length == 1` iff the game has not been challenged.
			// Any other length (including absence, i.e. length 0 for a game that never registered
			// its root claim) is rejected.
			//
			// The MPT trie path for a direct storage slot is `keccak256(slot)`.
			let storage_key = U256::from(FAULT_DISPUTE_CLAIM_DATA_SLOT).to_big_endian();
			let trie_path = H::keccak256(&storage_key);
			let value = get_value_from_proof::<H>(
				trie_path.0.to_vec(),
				proxy_storage_root,
				challenge_proof,
			)?
			.ok_or(Error::ClaimDataSlotMissing)?;
			let raw = <alloy_primitives::Bytes as Decodable>::decode(&mut &*value)
				.map_err(|_| Error::DecodeClaimData(format!("{:?}", value)))?
				.0
				.to_vec();
			if raw.len() > 32 {
				Err(Error::ClaimDataTooLong)?
			}
			// RLP strips leading zeros from the stored length; reconstruct the uint256 and require
			// it to be exactly one.
			if U256::from_big_endian(&raw) != U256::one() {
				Err(Error::FaultDisputeGameChallenged)?
			}
			Ok(())
		},

pub fn verify_delay_passed<H>(host: &H, proof_height: &StateMachineHeight) -> Result<bool, Error>
where
	H: IsmpHost,
{
	let update_time = host.state_machine_update_time(*proof_height)?;
	let delay_period = host
		.challenge_period(proof_height.id)
		.ok_or(Error::ChallengePeriodNotConfigured { state_machine: proof_height.id })?;
	let current_timestamp = host.timestamp();
	Ok(delay_period.as_secs() == 0 || current_timestamp.saturating_sub(update_time) > delay_period)
}
