Audit Report

## Title
Exposure of External Initiator Secrets (AccessKey/OutgoingToken) to Any Authenticated User Regardless of Role - ([File: core/web/router.go])

## Summary
`GET /v2/external_initiators` is registered without any role-gating wrapper, while its sibling `POST`/`DELETE` routes are wrapped in `auth.RequiresEditRole`. Any authenticated user — including one holding only `UserRoleView` — can call this endpoint and receive every External Initiator's `AccessKey` and `OutgoingToken` in the JSON:API response, credentials that should require at least `edit`-level trust to view.

## Finding Description
The route table in `v2Routes` shows the inconsistency directly: `POST`/`DELETE /external_initiators` are wrapped with `auth.RequiresEditRole`, but `GET /external_initiators` is wrapped only with `paginatedRequest`, with no role check at all. [1](#0-0) 

The base `authv2` group only requires successful authentication (session or token) via `auth.Authenticate`, with no minimum role enforced at the group level — role checks are applied per-route via `RequiresEditRole`/`RequiresAdminRole`/`RequiresRunRole` wrappers, none of which are present on this GET route. [2](#0-1) 

`RequiresEditRole` explicitly rejects `UserRoleView` and `UserRoleRun`, confirming that the intended design gates edit/run-adjacent data behind at least `edit` role — a gate this GET route is missing entirely. [3](#0-2) 

The handler itself performs no supplemental authorization and serializes every stored initiator via `presenters.NewExternalInitiatorResource`. [4](#0-3) 

The presenter unconditionally includes `AccessKey` and `OutgoingToken` — both are live credential material: `AccessKey` pairs with a `Secret`/`HashedSecret` for `AuthenticateExternalInitiator` header-based auth, and `OutgoingToken` is a generated secret (`utils.NewSecret`) created alongside `OutgoingSecret` for outbound authentication to the initiator's webhook. [5](#0-4) [6](#0-5) 

A test confirms these exact fields are present on `Index` responses. [7](#0-6) 

This is a genuine authorization inconsistency: the write operations on this resource require `edit` role, but the read operation that discloses sensitive tokens requires no role beyond basic authentication, breaking the intended least-privilege model.

## Impact Explanation
A user with only `UserRoleView` (or `UserRoleRun`) — a role explicitly meant to be excluded from edit-level resources per `RequiresEditRole` — can read `AccessKey` and `OutgoingToken` for every configured External Initiator. `OutgoingToken` is a bearer credential the node itself uses to authenticate to the initiator's webhook, so its disclosure to an unauthorized low-privilege account is a concrete secret-exfiltration issue (CWE-200 analog) and maps to the in-scope "key/secret exfiltration" impact category. This does not, on its own, grant `AccessKey`+`Secret` pair completion (the `Secret`/`HashedSecret` isn't exposed by this endpoint), so the "trigger job runs via forged EI auth" escalation claimed in the original report is not directly substantiated by this endpoint alone, but the credential disclosure itself is a real and concrete vulnerability.

## Likelihood Explanation
Exploitation requires only a valid low-privilege (`view`-role) authenticated session or API token — a realistic and common configuration (e.g., monitoring/read-only dashboard accounts) in Chainlink Node Operator deployments. The request is a single unauthenticated-role-gated `GET`, trivially repeatable.

## Recommendation
Wrap `authv2.GET("/external_initiators", ...)` with `auth.RequiresEditRole` (or `auth.RequiresAdminRole`) to match the write routes on the same resource. Additionally, consider excluding `OutgoingToken`/`AccessKey` from list/index responses, surfacing them only once at creation (as is already done for `Secret` via `NewExternalInitiatorAuthentication`).

## Proof of Concept
1. Create/obtain a Chainlink Node user with `UserRoleView`.
2. Authenticate as that user (session cookie or `X-API-KEY`/`X-API-SECRET`).
3. Issue `GET /v2/external_initiators`.
4. Observe the JSON:API response includes `accessKey` and `outgoingToken` for every configured External Initiator, as verified by `core/web/router.go:264` (no role wrapper) and `core/web/presenters/external_initiators.go:57-77` (fields always serialized), and matching the assertions in `core/web/external_initiators_controller_test.go:104-109`.

// RequiresEditRole extracts the user object from the context, and asserts the user's role is at least
// 'edit'
func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {

// ExternalInitiator represents a user that can initiate runs remotely
type ExternalInitiator struct {
	ID             int64
	Name           string
	URL            *models.WebURL
	AccessKey      string
	Salt           string
	HashedSecret   string
	OutgoingSecret string
	OutgoingToken  string

	CreatedAt time.Time
	UpdatedAt time.Time
}

// NewExternalInitiator generates an ExternalInitiator from an
// auth.Token, hashing the password for storage
func NewExternalInitiator(
	eia *auth.Token,
	eir *ExternalInitiatorRequest,
) (*ExternalInitiator, error) {
	salt := utils.NewSecret(utils.DefaultSecretSize)
	hashedSecret, err := auth.HashedSecret(eia, salt)
	if err != nil {
		return nil, pkgerrors.Wrap(err, "error hashing secret for external initiator")
	}

	return &ExternalInitiator{
		Name:           strings.ToLower(eir.Name),
		URL:            eir.URL,
		AccessKey:      eia.AccessKey,
		HashedSecret:   hashedSecret,
		Salt:           salt,
		OutgoingToken:  utils.NewSecret(utils.DefaultSecretSize),
		OutgoingSecret: utils.NewSecret(utils.DefaultSecretSize),
	}, nil
}
