### Title

Supply-index floor preserves wiped-out shares after bad-debt cleanup, letting them consume future deposits - ([File: contracts/pool/src/interest.rs](https://github.com/Alyssadaypin/rs-lending-xlm--010/blob/main/contracts/pool/src/interest.rs))

### Summary

`clean_bad_debt` writes down the debt market's `supply_index`, but `apply_bad_debt_to_supply_index` forcibly raises a completely wiped index to `SUPPLY_INDEX_FLOOR_RAW`, leaving scaled supply shares with residual value after their full backing was socialized away. A later deposit into that market can therefore be captured by the owner of those supposedly wiped shares through `withdraw`. [1](#0-0) 

### Finding Description

The controller permits any authorized caller to invoke `clean_bad_debt` when an account has open debt, is insolvent, and its remaining collateral is at or below the socialization threshold. [2](#0-1) 

Cleanup first converts each remaining deposit position into protocol revenue and then submits each debt position to the pool's borrow-side seizure path. [3](#0-2) 

For borrow-side entries, `seize_positions` calculates the debt's current underlying value, applies it to the supply index, and burns the debt shares. [4](#0-3) 

When bad debt equals or exceeds total supplied value, `capped` consumes all supplied value and `reduction_factor` becomes zero; however, the final `.max(SUPPLY_INDEX_FLOOR_RAW)` raises the resulting zero index to `RAY / 1000`. [5](#0-4) 

The corresponding `supplied` share total is not reduced during borrow-side cleanup, so every pre-existing supply share retains a claim worth approximately 0.1% of its pre-cleanup index value despite the entire supplier base having been written down. [4](#0-3) 

### Impact Explanation

This creates protocol insolvency and can steal funds from later suppliers: shares whose economic backing was fully consumed remain withdrawable and can consume cash deposited after the wipeout. An attacker who owns pre-cleanup supply shares can create or wait for severe bad debt, call `clean_bad_debt`, and later withdraw value represented only by the artificial floor. The repository's own pool-level regression test demonstrates that a floored residual position can pay out a fresh deposit and leave the fresh depositor under-backed. [6](#0-5) 

### Likelihood Explanation

The path is permissionless once a naturally or market-induced insolvent account reaches the dust-collateral threshold: `clean_bad_debt` requires only `caller.require_auth()` and checks the two USD totals rather than restricting the caller. [7](#0-6) 

An attacker can also control both sides beforehand by supplying the debt asset in one account and borrowing it from another account, provided the borrowing position is initially solvent; adverse oracle price movement or permitted self-executed market trades can then move it into cleanup eligibility. The strongest profitability condition is a debt-market write-down greater than or equal to its total supplied value, because that produces a zero reduction factor and activates the floor. [5](#0-4) 

### Recommendation

Do not clamp a fully written-down supply index to a nonzero value. Either allow the index to reach zero and explicitly handle first deposit after a wipeout, or proportionally burn/rebase outstanding supply shares so `scaled_supply * index` cannot retain value after `remaining` reaches zero. Add an end-to-end invariant for `clean_bad_debt` asserting that no pre-cleanup supply position can withdraw value when `bad_debt >= total_supplied_value`, including a regression test covering a fresh post-cleanup deposit. [1](#0-0) 

### Proof of Concept

1. The attacker calls `supply(caller=attacker, account_id=0, spoke_id=S, assets=[(X, Sx)])`, creating supplier account `A` holding scaled `X` supply shares. [8](#0-7) 
2. The attacker creates borrower account `B`, supplies collateral `Y`, and calls `borrow(..., borrows=[(X, D)], to=Some(attacker))`, with `D` sized so a subsequent `X` bad-debt write-down is at least the market's total `X` supplied value.
3. After price movement makes `total_debt > total_collateral` and `total_collateral <= dust`, the attacker calls `clean_bad_debt(caller=attacker, account_id=B)`. The controller sends `B`'s borrow position to the pool, and the pool writes the debt against `X`'s supply index. [9](#0-8) 
4. Because `remaining == 0`, `new_supply_index` computes to zero but is stored as `SUPPLY_INDEX_FLOOR_RAW`; account `A`'s supply shares remain intact and now represent an artificial residual claim. [5](#0-4) 
5. A victim calls `supply(..., assets=[(X, Sv)])`, adding real `X` cash while receiving shares valued using the floored index. [10](#0-9) 
6. The attacker calls `withdraw(caller=attacker, account_id=A, withdrawals=[(X, 0)], to=Some(attacker))`; zero requests the full position, and the pool pays the residual claim from cash that should have belonged to the post-cleanup supplier. [11](#0-10)

pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}

#[derive(Clone, Copy, PartialEq)]
enum BadDebtGate {
    /// Permissionless: insolvent *and* collateral at or below the dust threshold.
    DustCapped,
    /// Owner-only: insolvent alone, with no cap on the collateral left behind.
    InsolventOnly,
}

/// Requires open debt and the selected insolvency gate, then cleans up the account.
fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    bad_debt::execute_bad_debt_cleanup(env, &mut cache, account_id, &account, &totals);
}

fn test_raw_cache_floor_residual_can_consume_fresh_cash_without_supply_guard() {
    let t = TestSetup::new();
    t.as_contract(|| {
        let scaled_a_raw = 1_000_000 * RAY;
        let mut cache = t.fresh_cache(PoolStateRaw {
            supplied: scaled_a_raw,
            borrowed: 0,
            revenue: 0,
            borrow_index: RAY,
            supply_index: RAY,
            last_timestamp: 0,
            cash: 0,
        });
        let scaled_a = Ray::from(scaled_a_raw);

        apply_bad_debt_to_supply_index(&mut cache, Ray::from(2_000_000 * RAY));
        assert_eq!(
            cache.supply_index().raw(),
            SUPPLY_INDEX_FLOOR_RAW,
            "wipeout must clamp supply index UP to the floor, not reset the base"
        );

        let stranded = cache.unscale_supply_floor(scaled_a);
        assert!(stranded > 0, "floor clamp leaves userA a phantom claim");
        assert_eq!(cache.cash(), 0, "empty market: no cash to extract yet");

        let c = stranded;
        let scaled_b = cache.calculate_scaled_supply(c);
        cache.mint_supply(scaled_b);
        cache.credit_cash(c);

        let b_claim = cache.unscale_supply_floor(scaled_b);
        assert_eq!(b_claim, c, "userB's honest claim equals their deposit");

        let (burn, gross) = cache.resolve_withdrawal(i128::MAX, scaled_a);
        cache.require_reserves(gross);
        cache.burn_supply(burn);
        cache.debit_cash(gross);

        assert!(gross > 0, "stranded position pays out non-zero");
        assert_eq!(
            gross, c,
            "userA drains exactly userB's fresh deposit out of the pool"
        );

        assert!(
            cache.cash() < b_claim,
            "pool cash ({}) can no longer cover userB's claim ({}): honest supplier lost funds",
            cache.cash(),
            b_claim
        );
        assert_eq!(cache.cash(), 0, "userA drained the pool to empty");
    });

pub(crate) fn process_withdraw(
    env: &Env,
    caller: &Address,
    account_id: u64,
    withdrawals: &Vec<HubPayment>,
    to: Option<Address>,
) -> Vec<HubPayment> {
    validation::require_authorized_caller(env, caller);

    let mut account = storage::get_account(env, account_id);
    require_owner_or_delegate(env, account_id, caller, &account.owner);

    let recipient = to.unwrap_or_else(|| caller.clone());
    let mut cache = Context::new(env);
    require_external_recipient(env, &mut cache, &recipient);
    let aggregated = payments::aggregate_payments(env, withdrawals, payments::ZeroLeg::MeansAll);

    let paid = settle_withdraw(env, &mut account, &recipient, &aggregated, &mut cache);
    let _ = enforce_post_pool_solvency(env, &mut cache, &mut account);

    finalize_position_flow(
        env,
        account_id,
        &account,
        &mut cache,
        PositionSides::Supply,
        true,
    );
    paid
}
