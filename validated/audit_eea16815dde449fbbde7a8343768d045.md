### Title
Cached graduation amounts too small trip UniswapV2's `MINIMUM_LIQUIDITY` floor, permanently bricking `finalizeGraduation` - (File: packages/contracts/src/Bonding.sol)

### Summary
`Bonding._seedDirectMint` (the empty-pair / dust-preseed regime used by ~99% of graduations) unconditionally calls `IUniswapV2Pair(pair).mint(lpLock)` with the phase-1-cached `(tokensForLP, ltFromPair)` amounts [1](#0-0) . Standard UniswapV2 `mint()` on a fresh pool computes `liquidity = sqrt(amount0*amount1) - MINIMUM_LIQUIDITY` and reverts with `INSUFFICIENT_LIQUIDITY_MINTED` whenever that value is `<= 0`. Because `tokensForLP`/`ltFromPair` are pinned once in phase 1 and can never be recomputed or resized, a graduation whose cached amounts are small enough to trip this floor makes `finalizeGraduation` revert unconditionally and forever — exactly the "always-revert-below-a-threshold on an external AMM call, chosen amounts can't be changed later" bug class from the Whirlpool report, just manifesting in HyperSwap V2's `mint` guard instead of `updateFeesAndRewards`'s zero-liquidity guard.

### Finding Description
Phase 1 (`_enterGraduating` → `_prepareGraduationLiquidity`) computes and permanently caches `tokensForLP` and `ltFromPair` from the pair's reserves at the moment of the threshold-crossing trade, storing them in `pendingGraduation[token]` [2](#0-1) . `finalizeGraduation` later reads this struct verbatim and feeds it into `_seedUniswapV2Direct` → `_seedDirectMint`, which transfers exactly those two amounts to the pair and calls `pair.mint(lpLock)` [3](#0-2) .

The supply trigger (`IPair(pair).tokenBalance() == 0`) is explicitly designed to graduate flat/crashed-rate curves — the invariant test suite deliberately crashes `exchangeRate` to `0.0001 ether` and drives the curve to full sellout via the supply leg [4](#0-3) . In that regime `ltFromPair` (the real LT raised, in LT units) can be driven arbitrarily small relative to `tokensForLP`, because a crashed/low-rate LT lets a small LT amount buy through the entire 750M real-token curve supply. If `sqrt(tokensForLP * ltFromPair) <= MINIMUM_LIQUIDITY (1000)` on the underlying V2 pair, `pair.mint` reverts unconditionally.

Unlike `Zap`'s buy-floor handling — which explicitly anticipates and floor-bumps around BounceTech's own `BelowMinTransactionSize` revert [5](#0-4)  — there is no analogous floor-bump, minimum-LP guard, or recompute path anywhere in `_prepareGraduationLiquidity` / `_seedDirectMint` / `finalizeGraduation` for the V2 pool's own `MINIMUM_LIQUIDITY` constraint. Since `(tokensForLP, ltFromPair)` are pinned at end-of-phase-1 by design (documented as intentionally immutable so the LP opens at the exact curve-close ratio) [6](#0-5) , there is no way to retry `finalizeGraduation` with different amounts — every call reverts identically, forever.

### Impact Explanation
Once phase 1 has fired, `Lifecycle` is already `Graduating`: trading is frozen (`buy`/`sell` both revert with `TokenIsGraduating`) [7](#0-6) , and the curve-raised LT has already been drained out of the pair into `Bonding` via `Router.graduate` inside `_prepareGraduationLiquidity` [8](#0-7) . If `finalizeGraduation` can never succeed, that LT (all curve-raised value from every buyer of the token) plus the 250M reserved `Token` allocation sit permanently stuck in `Bonding` with `Lifecycle` stuck at `Graduating` — there is no admin rescue path, no re-entry to `Curve`, and no alternate graduation route. This is a permanent freeze of all curve-raised trader funds for the affected token, matching the "permanent freezing of trader/creator funds" impact bar.

### Likelihood Explanation
Reachable purely through unprivileged trading: any address can push a token's LT rate down (or launch against a naturally low-rate LT) and buy through the curve's full 750M real-token supply to trip the supply trigger with a tiny `ltFromPair`, or via the USD trigger at a very low `graduationThresholdUsd` / `VIRTUAL_LIQUIDITY_USD` configuration where `ltFromPair` is small in absolute LT units. `finalizeGraduation` is explicitly permissionless and callable by anyone [9](#0-8) , so no privileged actor is needed to attempt (and permanently fail) the call. The exact numeric bound depends on deployment constants (`VIRTUAL_LIQUIDITY_USD`, `graduationThresholdUsd`, `LP_RESERVE`) and the paired LT's live exchange rate, which I could not fully quantify from the indexed code, so the precise probability of tripping `MINIMUM_LIQUIDITY` under mainnet parameters is uncertain — but the code path itself has no defensive floor at all, unlike every other BounceTech-floor interaction in the codebase.

### Recommendation
Add an explicit pre-flight check in `_prepareGraduationLiquidity` (or in `_seedDirectMint`/`_seedUniswapV2Direct`) enforcing `tokensForLP * ltFromPair` stays above the V2 `MINIMUM_LIQUIDITY^2` bound before caching the phase-1 amounts, and define a recovery path (e.g. bump `tokensForLP`/`ltFromPair` up to a minimum viable LP size, mirroring the `Zap` floor-bump pattern) rather than allowing `pendingGraduation` to cache values that provably cannot be minted.

### Proof of Concept
Conceptual PoC (bounded by index limits — exact constant values for `VIRTUAL_LIQUIDITY_USD`/`graduationThresholdUsd` should be confirmed in a live Foundry run):
1. Launch a token paired to a mock LT; crash `exchangeRate()` toward a very small value (as done in `test_inv_supplyTrigger_belowUsdThreshold` [4](#0-3) ), sized so that the eventual `ltFromPair` computed in `_prepareGraduationLiquidity` is only a handful of wei while `tokensForLP` stays non-trivial (or vice versa), such that `sqrt(tokensForLP * ltFromPair) <= 1000`.
2. Drive buys until the supply trigger (`tokenBalance() == 0`) fires, which calls `_enterGraduating` inline and caches the tiny `(tokensForLP, ltFromPair)` pair into `pendingGraduation[token]`.
3. Call `bonding.finalizeGraduation(token)` — `_seedDirectMint`'s `IUniswapV2Pair(pair).mint(lpLock)` reverts with `INSUFFICIENT_LIQUIDITY_MINTED`.
4. Confirm the revert is permanent: repeated calls to `finalizeGraduation` always revert identically since `pendingGraduation[token]` is never recomputed, and `buy`/`sell` remain blocked by `Lifecycle.Graduating` forever, freezing the curve's raised LT and 250M token reserve.

    function finalizeGraduation(
        address tokenAddress
    ) external nonReentrant {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[tokenAddress];
        if (info.lifecycle != Lifecycle.Graduating) revert NotGraduating();

        address lt = info.ltAddress;
        PendingGraduation memory p = $.pendingGraduation[tokenAddress];

        // Anything in this contract beyond `p.ltFromPair` belongs to a
        // concurrent graduation on the same LT (Phase 1 transferred it
        // via `Router.graduate`) or to stray dust. Either way it is
        // off-limits to this graduation's deposit and sweep — see
        // `_routerDepositAndDispose` and `_sweepLTToOwner`.
        // Saturating subtract: a balance below `p.ltFromPair` shouldn't
        // be reachable in normal operation, but we keep finalize from
        // bricking on a Panic if any future code path or non-canonical
        // LT briefly violates the invariant.
        uint256 ltBalance = IERC20(lt).balanceOf(address(this));
        uint256 protectedLT = ltBalance > p.ltFromPair ? ltBalance - p.ltFromPair : 0;

        address lpPair = _ensureUniswapV2Pair(tokenAddress, lt);
        uint256 liquidity = _seedUniswapV2Direct(tokenAddress, lt, lpPair, p.tokensForLP, p.ltFromPair, protectedLT);

    function _prepareGraduationLiquidity(
        address tokenAddress
    ) internal returns (uint256 tokensForLP, uint256 ltFromPair, uint256 lpBurned, uint256 unsoldBurned) {
        address pairAddr = _s().tokenInfo[tokenAddress].pair;
        (uint256 tokenReserve, uint256 assetReserve) = IPair(pairAddr).getReserves();

        unsoldBurned = IPair(pairAddr).tokenBalance();
        if (unsoldBurned > 0) {
            Token(tokenAddress).burn(pairAddr, unsoldBurned);
        }

        ltFromPair = assetReserve - _launchTimeVirtualLtReserve(tokenAddress, pairAddr);
        if (ltFromPair > 0) {
            _s().router.graduate(tokenAddress, ltFromPair);
        }

        tokensForLP = assetReserve == 0 ? 0 : (ltFromPair * tokenReserve) / assetReserve;
        if (tokensForLP > LP_RESERVE) tokensForLP = LP_RESERVE;

        lpBurned = LP_RESERVE - tokensForLP;
        if (lpBurned > 0) {
            Token(tokenAddress).burn(address(this), lpBurned);
        }
    }

        address tokenAddress,
        address lt,
        address pair,
        uint256 tokensForLP,
        uint256 ltFromPair
    ) internal returns (uint256 liquidity) {
        IERC20(tokenAddress).safeTransfer(pair, tokensForLP);
        IERC20(lt).safeTransfer(pair, ltFromPair);
        liquidity = IUniswapV2Pair(pair).mint(_s().lpLock);
        uint256 leftoverToken = IERC20(tokenAddress).balanceOf(address(this));
        if (leftoverToken > 0) {
            Token(tokenAddress).burn(address(this), leftoverToken);
        }
    }
