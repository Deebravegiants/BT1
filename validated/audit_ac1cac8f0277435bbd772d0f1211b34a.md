### Title
Min-circuit path lets an attacker with zero UTXOs run unauthenticated CASE-2 `EmporiumStack` ops via `Hinkal.transact` — ([File: contracts/CircomDataBuilder.sol])

### Summary
When `externalActionId == HINKAL_EMPORIUM_ACTION_ID` and `circomData.erc20TokenAddresses.length == 0`, `formInputForCircom` routes to `formInputEmporiumMin`, which proves only `Poseidon(messageSeed) == emporiumMessage` — no `nullifyingPrivateKey`, `rootHashHinkal`, `stealthAddress`, or nullifier is a public input. Because `dimensions.tokenNumber == 0`, every downstream per-token check (Hinkal's balance/slippage loop, `EmporiumUpgradeable`'s balance-before/after check, UTXO minting) iterates zero times, so a stateless CASE-2 `EmporiumOperation` (`signerAddress == address(0)`) executes with no signature, no balance accounting, and no spend proof at all.

### Finding Description
Broken equality: **every value-moving action against Emporium must be gated by proof of ownership of a spent UTXO (one `inNullifier` per leaf) OR a wallet-owner EIP-712 signature.** The Min path satisfies neither.

Trace:
- `CircomDataBuilder.formInputForCircom` selects the Min path solely based on `externalActionId`/empty token array [1](#0-0) .
- `formInputEmporiumMin` emits only `[emporiumMessage, timeStamp, calldataHash]` — no `H1x/H1y/stealthAddress/rootHashHinkal` [2](#0-1) .
- `MainEVMCircuitMin` only constrains `message <== Poseidon(1)([messageSeed])`; it has no `nullifyingPrivateKey`, no Merkle root, no signature verification whatsoever [3](#0-2) . Since `emporiumMessage` is attacker-chosen and `messageSeed` is computed forward to match it, **any unprivileged EOA can trivially produce a valid Groth16 proof with zero prior deposits.**
- `dimensionsCheck` only enforces internal array-length consistency (all arrays must equal `dimensions.tokenNumber`); it never enforces `tokenNumber > 0` for the Emporium action [4](#0-3) .
- In `Hinkal.transact`, the per-token balance/slippage `require` loop iterates `circomData.erc20TokenAddresses.length` times — zero when tokenCount=0, so it enforces nothing [5](#0-4) . `insertNullifiers` then runs over an empty `inputNullifiers` array — no leaf is spent [6](#0-5) .
- `_externalTransact`'s deposit loop is likewise empty (`deltaAmountChanges = []`), so `EmporiumUpgradeable.runAction` is invoked without any funds being pushed into Emporium as part of this call [7](#0-6) .
- Inside `runAction`, `getBalancesForArray([])` is trivially empty, `verifyWallet` skips all signature checks when `stack.signerAddress == address(0)` [8](#0-7) , and CASE-2 executes `op.endpoint.call{value: op.value}(op.callData)` directly as the Emporium contract, with the post-loop balance/UTXO reconciliation loop also iterating zero times [9](#0-8) .

Root cause: the "self-consistency" invariant that makes unsigned CASE-2 ops safe in the normal path (the op can only move funds that were just deposited in this same atomic call, bounded by the balance-diff check) is completely absent when `tokenCount == 0`, because there is no token array to bound it. The attacker's call is thus free to invoke `op.endpoint.call` against any contract with attacker-chosen `value`/`callData`, executed with `msg.sender == Emporium`, capable of moving any ETH/ERC20 balance or exercising any privilege Emporium's address holds (residual allowances, dust from prior calls, refunded ETH, etc.) — with zero proof of Hinkal fund ownership.

### Impact Explanation
This is a proof/nullifier-verification bypass: value-moving `runAction` execution is reachable without spending any nullifier and without any wallet signature, matching the Critical category "proof or nullifier verification bypass." Whatever balance/approval currently resides at the Emporium contract's address (ETH dust from prior ops, ERC20 dust, or any privileged approval granted to Emporium by past interactions) can be drained or misused by any unprivileged attacker, repeatably, at near-zero cost (one self-generated proof per call).

### Likelihood Explanation
- Preconditions: attacker needs no deposit, no UTXO, no signature — only the ability to call `Hinkal.transact` with `erc20TokenAddresses = []`, a self-satisfying Min proof, and a crafted `EmporiumStack` with `signerAddress = address(0)`.
- Exploitability depends on Emporium holding exploitable value/privilege at call time (dust ETH/tokens, stale approvals); the bypass itself is unconditionally reachable regardless of whether Emporium currently holds funds.
- Fully repeatable — each call costs only gas plus trivial proof generation (forward Poseidon hash, no discrete-log/inversion needed).

### Recommendation
- Reject the Min-circuit/`formInputEmporiumMin` path for any CASE-2 (`signerAddress == address(0)`) operation, or require `dimensions.tokenNumber > 0` whenever `externalActionId == HINKAL_EMPORIUM_ACTION_ID` so real balance/nullifier accounting always applies.
- Alternatively, require CASE-2 ops to always be signed (drop the `signerAddress == address(0)` bypass in `verifyWallet`), and/or bind the Min circuit's public inputs to `rootHashHinkal` and a real spend-authority signal so it cannot be satisfied by an attacker with no deposit.
- Ensure Emporium sweeps/reverts on any non-zero residual balance at the end of `runAction` regardless of `erc20TokenAddresses.length`, so no exploitable dust or privilege persists between calls.

### Proof of Concept
Hardhat test plan:
1. Deploy Hinkal stack with `EmporiumUpgradeable`, register `VerifierEVMMin0v4` for `buildVerifierId({tokenNumber:0, nullifierAmount:0, outputAmount:0}, HINKAL_EMPORIUM_ACTION_ID)`.
2. Fund Emporium with test ERC20 tokens directly (simulating residual dust from a prior legitimate flow) — assert `token.balanceOf(emporium) == X > 0`.
3. As attacker EOA (no prior Hinkal deposit, no UTXO), pick `messageSeed`, compute `message = Poseidon(messageSeed)` off-chain, set `circomData.emporiumMessage = message`, `erc20TokenAddresses=[]`, `amountChanges=[]`, `inputNullifiers=[]`, `outCommitments=[]`, `onChainCreation=[]`, `slippageValues=[]`.
4. Build `EmporiumStack{signerAddress: address(0), ops: [{endpoint: token, invokeWallet:false, value:0, callData: abi.encodeCall(token.transfer, (attacker, X))}]}`, put it in `externalActionData.externalActionMetadata`.
5. Generate a real Groth16 proof for `MainEVMCircuitMin` with public inputs `[message, timeStamp, calldataHash]`.
6. Call `Hinkal.transact(a,b,c,dimensions,circomData)` from attacker; assert it does not revert.
7. Assert both sides of the equality: before — `nullifiers` set unchanged (`insertNullifiers` iterated 0 times), `token.balanceOf(emporium) == X`; after — `token.balanceOf(attacker) == X`, `token.balanceOf(emporium) == 0`, while `nullifiers[...]` mapping still has no entries recorded for this attacker — proving funds moved with zero nullifier/UTXO proof.
