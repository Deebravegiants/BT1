No vulnerability found for this question.

**Reasoning:**

The premise conflates an irrelevant feature flag with the hash function actually used. `aptos_hash::keccak256` is registered as an always-available native function with no feature gate [1](#0-0) , unlike `sha2_512`/`sha3_512`/`ripemd160_internal`, which are explicitly guarded by `features::sha_512_and_ripemd_160_enabled()` [2](#0-1) . `keccak256` never checks that feature, so the flag's on/off state has no bearing on `ethereum_derivable_account::authenticate_auth_data`'s use of `aptos_hash::keccak256` [3](#0-2) .

The actual native implementation is a standard Keccak-256 (`tiny_keccak::Keccak::v256`) with no custom or weakened logic [4](#0-3) . Producing two distinct SIWE messages that collide under Keccak-256 (a 256-bit cryptographic hash with no known practical collision attack) is a request to break the underlying cryptographic primitive itself, not to exploit a logic flaw in Aptos's Move code. This is outside the scope of a custody-logic review: the `authenticate_auth_data` flow correctly recovers the public key via `secp256k1::ecdsa_recover` from the message hash and compares the derived Ethereum address (last 20 bytes of `keccak256(pubkey)`) against the claimed `ethereum_address` in `SIWEAbstractPublicKey`, aborting on mismatch via `EADDR_MISMATCH` [5](#0-4) . No unprivileged, code-level path exists to force this check to pass for an attacker-chosen unauthorized public key without an actual Keccak-256 collision, which is not a demonstrated or currently feasible attack.

fn native_keccak256(
    context: &mut SafeNativeContext,
    mut _ty_args: &[Type],
    mut args: VecDeque<Value>,
) -> SafeNativeResult<SmallVec<[Value; 1]>> {
    debug_assert!(_ty_args.is_empty());
    debug_assert!(args.len() == 1);

    let bytes = safely_pop_arg!(args, Vec<u8>);

    let cost = HASH_KECCAK256_BASE + HASH_KECCAK256_PER_BYTE * NumBytes::new(bytes.len() as u64);
    context.charge(cost)?;

    let mut hasher = Keccak::v256();
    hasher.update(&bytes);
    let mut output = [0u8; 32];
    hasher.finalize(&mut output);

    Ok(smallvec![Value::vector_u8(output)])
}
