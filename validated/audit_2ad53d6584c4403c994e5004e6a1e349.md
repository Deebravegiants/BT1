Audit Report

## Title
CORS wildcard-origin allowlist bypass via missing dot-boundary check in `isAllowedOrigin` - (File: `core/services/gateway/network/httpserver.go`)

## Summary
`httpServer.isAllowedOrigin` validates the `Origin` header against configured `CORSAllowedOrigins` wildcard entries by stripping the `*.` prefix and calling `strings.HasSuffix(originHost, allowedHost)` with no separator/dot boundary check. As a result, an attacker-controlled origin host that merely ends with the allowed suffix (e.g. `evilethereum.org` against allowed pattern `*.ethereum.org`) is incorrectly treated as a valid subdomain and granted CORS access.

## Finding Description
In `core/services/gateway/network/httpserver.go` lines 184-190, the wildcard host match logic is:
```go
if strings.HasPrefix(allowedHost, "*.") {
    allowedHost = allowedHost[2:]
    if strings.HasSuffix(originHost, allowedHost) {
        return true
    }
}
```
This strips `*.` to get `allowedHost = "ethereum.org"`, then does a raw suffix comparison. `strings.HasSuffix("evilethereum.org", "ethereum.org")` returns `true` even though `evilethereum.org` is not a subdomain of `ethereum.org` — there is no dot separator enforced between the arbitrary label and the trusted domain. This function is called directly from `handleRequest` (lines 195-202), which is the handler for the Gateway's user-facing, unauthenticated HTTP endpoint: if `isAllowedOrigin` returns true, the server sets `Access-Control-Allow-Origin` to the attacker's exact `Origin` value, granting the attacker's page read access to cross-origin JSON-RPC responses from a victim's browser session. No existing check (scheme/port/exact-host checks preceding it) mitigates this, since they are independent, and the existing test suite (`httpserver_test.go`) only exercises legitimate subdomains, not the boundary-bypass case, so the bug is unguarded and undetected by current tests.

## Impact Explanation
This is a genuine allowlist/boundary-check bug: an operator using wildcard CORS entries (e.g. `*.mycompany.com`) unintentionally also allows any sibling domain sharing that suffix without a dot (e.g. `evilmycompany.com`), enabling cross-origin response exposure to an attacker-controlled origin — a CORS allowlist bypass / cross-user response corruption class impact against the Gateway's internet-facing HTTP endpoint.

## Likelihood Explanation
Exploitation requires only that the operator configure a wildcard `CORSAllowedOrigins` entry (a documented, supported feature demonstrated in the project's own test suite and sample configs) and that an attacker register/control any domain ending in the same string without a separating dot — a trivial, low-cost step fully within an unprivileged external attacker's capability. No credentials, host access, or special roles are needed to trigger the flawed comparison; only a crafted `Origin` header on an ordinary HTTP request.

## Recommendation
Enforce a dot boundary (or exact match) for wildcard suffix comparisons:
```go
if strings.HasPrefix(allowedHost, "*.") {
    allowedHost = allowedHost[2:]
    if originHost == allowedHost || strings.HasSuffix(originHost, "."+allowedHost) {
        return true
    }
}
```

## Proof of Concept
1. Configure Gateway with `CORSEnabled = true` and `CORSAllowedOrigins = ["https://*.ethereum.org"]`.
2. Send an HTTP POST to the Gateway's user endpoint with header `Origin: https://evilethereum.org`.
3. Observe the response contains `Access-Control-Allow-Origin: https://evilethereum.org`, confirming `isAllowedOrigin("https://evilethereum.org")` returns `true` for allowed pattern `https://*.ethereum.org`, even though `evilethereum.org` shares no dot-delimited subdomain relationship with `ethereum.org`. This can be added as a unit test alongside the existing `TestHTTPServer_HandleRequest_CORSEnabled_FromAllowedOriginWildcards` in `core/services/gateway/network/httpserver_test.go`, asserting the (currently passing but incorrect) `Access-Control-Allow-Origin` header for a non-subdomain sibling origin. 	originScheme, originHost, originPort, err := s.splitURL(origin)

		return false
	}
	for _, allowed := range s.config.CORSAllowedOrigins {
		// probably better to do this once when server starts and store it in a map
		// this is an easier solution so we don't have to apply more changes to the code
		// just need to be careful when specifying allowed origins in the config file
		allowedScheme, allowedHost, allowedPort, err := s.splitURL(allowed)
		if err != nil {
			s.lggr.Debug("error parsing allowed origin URL", err)
			continue
		}
		// skip if the scheme doesn't match at all
		if originScheme != allowedScheme {
			continue
		}
		// skip if the port doesn't match at all
		if originPort != allowedPort {

		}
