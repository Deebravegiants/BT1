### Title
`claim_revenue` allows any signed account to permanently destroy another user's pooled coretime revenue claim before settlement, returning success with a semantically incomplete/zero payout - (File: substrate/frame/broker/src/dispatchable_impls.rs)

### Summary
The `claim_revenue` extrinsic performs no ownership check tying the caller to the `region_id`'s `payee`, and `do_claim_revenue` treats any timeslice lacking a settled `InstaPoolHistory` record as already-processed (`continue`) rather than deferring the claim. An unprivileged attacker can call `claim_revenue` on a victim's freshly-pooled `RegionId` before the relay chain revenue for those timeslices has been reported, causing the loop to consume the entire `contribution.length` against unsettled (nonexistent) history records, delete `InstaPoolContribution` for that region with a zero payout, and still return `Ok(())`/emit `RevenueClaimPaid{ amount: 0, next: None }` as if the claim were fully and correctly settled.

### Finding Description
`claim_revenue` in [1](#0-0)  only requires `ensure_signed(origin)` — it never checks that the caller is `contribution.payee` or the owner of `region_id`. This means any signed account can invoke it against any other user's pooled region.

Inside `do_claim_revenue` [2](#0-1) , the loop unconditionally advances the claim cursor before checking whether the relevant `InstaPoolHistory` record has settled revenue:

```
for r in region.begin..last {
    region.begin = r + 1;
    contribution.length.saturating_dec();

    let Some(mut pool_record) = InstaPoolHistory::<T>::get(r) else { continue };
    let Some(total_payout) = pool_record.maybe_payout else { break };
    ...
}
``` [3](#0-2) 

`InstaPoolHistory` entries for a timeslice `r` are only created once `process_pool` runs for that committed timeslice [4](#0-3) , and `maybe_payout` is only populated once `process_revenue` later receives the relay-chain revenue report for that timeslice [5](#0-4) . Both events happen well after a region has been pooled via `do_pool` [6](#0-5) .

If the record does not exist yet (future/uncommitted timeslice), the loop `continue`s — silently treating that timeslice as "already handled" and permanently decrementing `contribution.length` / advancing `region.begin` — instead of stopping and preserving the claim for a later call. Because `contribution.length.min(max_timeslices)` bounds the loop only by the pooled region's total duration (fixed at pool time from `region.end - region_id.begin`), an attacker can call `claim_revenue(region_id, duration)` immediately after the victim pools their region — before any of the region's timeslices have even been committed — and the loop will `continue` through every timeslice, exhausting `contribution.length` to zero with `payout == 0`.

After the loop:
```
if contribution.length > 0 {
    InstaPoolContribution::<T>::insert(region, &contribution);
}
T::Currency::transfer(&Self::account_id(), &contribution.payee, payout, Expendable).defensive_ok();
...
Self::deposit_event(Event::RevenueClaimPaid { who: contribution.payee, amount: payout, next });
Ok(())
``` [7](#0-6) 

Since `contribution.length` reaches 0, the `InstaPoolContribution` record (already `take`n at the top of the function) is never reinserted — it is permanently deleted. The call still succeeds with `Ok(())` and emits `RevenueClaimPaid { amount: 0, next: None }`, which any downstream observer (including the victim) will interpret as "this region's pool claim is fully and correctly settled," when in fact the region's real (future) revenue share — already reflected in the aggregate `InstaPoolIo`/`private_pool_size` accounting used by `process_pool`/`process_revenue` — can never be claimed by anyone, since the specific `InstaPoolContribution` entry that would have driven a future correct claim (and the corresponding reduction of `InstaPoolHistoryRecord::private_contributions`) no longer exists.

### Impact Explanation
This is a griefing/fund-destruction bug reachable by any unprivileged signed account against any other user's pooled `RegionId` because `claim_revenue` has no ownership/authorization check. It permanently destroys the victim's future coretime pool revenue entitlement (transfers 0 instead of the rightful payout) while returning a success state indistinguishable from a legitimate, fully-settled zero-revenue claim. Additionally, because the aggregate `InstaPoolHistoryRecord::private_contributions` for the affected timeslices is never reduced by the destroyed contribution (the reduction code path is only reached when a settled record exists), that record can never reach zero via legitimate claims from other contributors, leaving orphaned/unclaimable balances permanently stuck in the Broker pot account — a pool insolvency/accounting-drift condition matching the scoped impact.

### Likelihood Explanation
Fully feasible with a single unprivileged signed extrinsic call, requiring no special privileges, timing races beyond "call immediately/soon after observing a `Pooled` event for a target region," and no signature/origin/proxy checks stop it since `claim_revenue` accepts any signed origin and any `region_id`. It is repeatable against every newly pooled region in the system.

### Recommendation
1. Enforce that `claim_revenue`'s caller matches `contribution.payee` (or an authorized proxy/delegate of it), preventing third parties from claiming/consuming other users' pool contributions.
2. In `do_claim_revenue`, distinguish "timeslice not yet committed/settled" from "already fully paid and cleaned up": for timeslices whose `InstaPoolHistory` record doesn't exist yet because they are still in the future relative to `status.last_committed_timeslice`/`status.last_timeslice`, `break` out of the loop (preserving `region.begin`/`contribution.length` for a later retry) instead of `continue`-ing through them and silently consuming the claim.

### Proof of Concept
Rust integration test (in `substrate/frame/broker/src/tests.rs` style):
```rust
#[test]
fn claim_revenue_can_be_griefed_by_anyone_before_settlement() {
    TestExt::new().endow(1, 1000).execute_with(|| {
        let item = ScheduleItem { assignment: Pool, mask: CoreMask::complete() };
        assert_ok!(Broker::do_reserve(Schedule::truncate_from(vec![item])));
        assert_ok!(Broker::do_start_sales(100, 3));
        advance_to(2);

        // Victim (account 1) purchases and pools a region with payee = 1.
        let region = Broker::do_purchase(1, u64::max_value()).unwrap();
        assert_ok!(Broker::do_pool(region, None, 1, Final));
        assert!(InstaPoolContribution::<Test>::get(region).is_some());

        // Attacker (account 2, unrelated) immediately claims revenue for the victim's
        // region, before any timeslice in it has been committed/settled.
        assert_ok!(Broker::do_claim_revenue(region, 100));

        // Contribution is destroyed with zero payout, even though timeslices will later
        // settle with real revenue.
        assert!(InstaPoolContribution::<Test>::get(region).is_none());
        assert_eq!(balance(1), 0); // victim never receives anything

        // Later, revenue for those timeslices arrives...
        advance_to(8);
        assert_ok!(TestCoretimeProvider::spend_instantaneous(1, 10));
        advance_to(11);

        // ...but the victim (payee 1) can no longer claim it: their contribution is gone.
        assert_noop!(Broker::do_claim_revenue(region, 100), Error::<Test>::UnknownContribution);
        assert_eq!(balance(1), 0); // revenue permanently unclaimable / stuck in pot
    });
}
```
Expected assertions: `InstaPoolContribution` for the victim's region is deleted after the attacker's call with `payout == 0`, and after real revenue later settles, the victim cannot claim anything, demonstrating permanent loss of funds caused by an unrelated, unprivileged caller.

	pub(crate) fn do_claim_revenue(
		mut region: RegionId,
		max_timeslices: Timeslice,
	) -> DispatchResult {
		ensure!(max_timeslices > 0, Error::<T>::NoClaimTimeslices);
		let mut contribution =
			InstaPoolContribution::<T>::take(region).ok_or(Error::<T>::UnknownContribution)?;
		let contributed_parts = region.mask.count_ones();

		Self::deposit_event(Event::RevenueClaimBegun { region, max_timeslices });

		let mut payout = BalanceOf::<T>::zero();
		let last = region.begin + contribution.length.min(max_timeslices);
		for r in region.begin..last {
			region.begin = r + 1;
			contribution.length.saturating_dec();

			let Some(mut pool_record) = InstaPoolHistory::<T>::get(r) else { continue };
			let Some(total_payout) = pool_record.maybe_payout else { break };
			let p = total_payout
				.saturating_mul(contributed_parts.into())
				.checked_div(&pool_record.private_contributions.into())
				.unwrap_or_default();

			payout.saturating_accrue(p);
			pool_record.private_contributions.saturating_reduce(contributed_parts);

			let remaining_payout = total_payout.saturating_sub(p);
			if !remaining_payout.is_zero() && pool_record.private_contributions > 0 {
				pool_record.maybe_payout = Some(remaining_payout);
				InstaPoolHistory::<T>::insert(r, &pool_record);
			} else {
				InstaPoolHistory::<T>::remove(r);
			}
			if !p.is_zero() {
				Self::deposit_event(Event::RevenueClaimItem { when: r, amount: p });
			}
		}

		if contribution.length > 0 {
			InstaPoolContribution::<T>::insert(region, &contribution);
		}
		T::Currency::transfer(&Self::account_id(), &contribution.payee, payout, Expendable)
			.defensive_ok();
		let next = if last < region.begin + contribution.length { Some(region) } else { None };
		Self::deposit_event(Event::RevenueClaimPaid {
			who: contribution.payee,
			amount: payout,
			next,
		});
		Ok(())
	}

	pub(crate) fn process_revenue() -> bool {
		let Some(OnDemandRevenueRecord { until, amount }) = RevenueInbox::<T>::take() else {
			return false;
		};
		let when: Timeslice =
			(until / T::TimeslicePeriod::get()).saturating_sub(One::one()).saturated_into();
		let mut revenue = T::ConvertBalance::convert_back(amount.clone());
		if revenue.is_zero() {
			Self::deposit_event(Event::<T>::HistoryDropped { when, revenue });
			InstaPoolHistory::<T>::remove(when);
			return true;
		}

		log::debug!(
			target: "pallet_broker::process_revenue",
			"Received {amount:?} from RC, converted into {revenue:?} revenue",
		);

		let mut r = InstaPoolHistory::<T>::get(when).unwrap_or_default();
		if r.maybe_payout.is_some() {
			Self::deposit_event(Event::<T>::HistoryIgnored { when, revenue });
			return true;
		}
		// Payout system InstaPool Cores.
		let total_contrib = r.system_contributions.saturating_add(r.private_contributions);
		let system_payout = if !total_contrib.is_zero() {
			let system_payout =
				revenue.saturating_mul(r.system_contributions.into()) / total_contrib.into();
			Self::charge(&Self::account_id(), system_payout).defensive_ok();
			revenue.saturating_reduce(system_payout);

			system_payout
		} else {
			Zero::zero()
		};

		log::debug!(
			target: "pallet_broker::process_revenue",
			"Charged {system_payout:?} for system payouts, {revenue:?} remaining for private contributions",
		);

		if !revenue.is_zero() && r.private_contributions > 0 {
			r.maybe_payout = Some(revenue);
			InstaPoolHistory::<T>::insert(when, &r);
			Self::deposit_event(Event::<T>::ClaimsReady {
				when,
				system_payout,
				private_payout: revenue,
			});
		} else {
			InstaPoolHistory::<T>::remove(when);
			Self::deposit_event(Event::<T>::HistoryDropped { when, revenue });
		}
		true

	pub(crate) fn process_pool(when: Timeslice, status: &mut StatusRecord) {
		let pool_io = InstaPoolIo::<T>::take(when);
		status.private_pool_size = (status.private_pool_size as SignedCoreMaskBitCount)
			.saturating_add(pool_io.private) as CoreMaskBitCount;
		status.system_pool_size = (status.system_pool_size as SignedCoreMaskBitCount)
			.saturating_add(pool_io.system) as CoreMaskBitCount;
		let record = InstaPoolHistoryRecord {
			private_contributions: status.private_pool_size,
			system_contributions: status.system_pool_size,
			maybe_payout: None,
		};
		InstaPoolHistory::<T>::insert(when, record);
		Self::deposit_event(Event::<T>::HistoryInitialized {
			when,
			private_pool_size: status.private_pool_size,
			system_pool_size: status.system_pool_size,
		});
	}
