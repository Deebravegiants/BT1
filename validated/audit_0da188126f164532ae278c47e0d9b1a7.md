### Title
Unauthenticated `/v2/resume/:runID` endpoint allows anyone to inject arbitrary results into suspended pipeline runs - (File: core/web/router.go, core/web/pipeline_runs_controller.go)

### Summary
The `PATCH /v2/resume/:runID` route is registered in the `unauthedv2` group (no session/token/external-initiator auth middleware applied), unlike virtually every other `/v2` endpoint which requires `auth.Authenticate(...)`. Anyone who can reach the node's HTTP API and who knows (or guesses/observes) the `runID` (a task UUID) can call `PipelineRunsController.Resume` to supply arbitrary `pending`/`error` result data that gets fed directly back into a suspended pipeline run.

### Finding Description
In `core/web/router.go`, `v2Routes` explicitly separates the resume route from the authenticated group: [1](#0-0) 
```
func v2Routes(app chainlink.Application, r *gin.RouterGroup) {
	unauthedv2 := r.Group("/v2")

	prc := PipelineRunsController{app}
	psec := PipelineJobSpecErrorsController{app}
	unauthedv2.PATCH("/resume/:runID", prc.Resume)

	authv2 := r.Group("/v2", auth.Authenticate(app.AuthenticationProvider(),
		auth.AuthenticateByToken,
		auth.AuthenticateBySession,
	))
```
Every other job/run/bridge/config-mutating endpoint in this file lives under `authv2` and requires a session token or admin/edit/run role. `Resume` is the sole exception, mirrored in the Nexus `fallback()` bug where every other external entrypoint is `onlyEntrypoint`/`onlySelf` except the one unrestricted alternate path.

`PipelineRunsController.Resume` performs no caller authentication or authorization check at all — it only validates that `runID` parses as a UUID, decodes the JSON body into a `pipeline.ResumeRequest`, and forwards straight to `App.ResumeJobV2`: [2](#0-1) 

The only "protection" is that `taskID` is a randomly-generated UUID (assigned to a `BridgeTask`'s async response URL, e.g. `.../v2/resume/<uuid>`), analogous to relying on `msg.sig`/selector matching in the Solidity fallback rather than an explicit authorization check. There is no secret/token comparison, no binding of the resuming caller to the bridge/job that created the pending task, and no rate limiting/expiry enforcement visible in this handler.

### Impact Explanation
If an attacker learns or brute-forces a pending `runID` (e.g., via log/metrics leakage, a compromised bridge adapter that echoes the callback URL, or simply because UUIDs from a weak/duplicated source could collide), they can:
- Inject falsified data/errors into an in-flight pipeline run that feeds an oracle report (e.g., forcing a bad price into a median/multiply task before it's used for an OCR round), a direct "cross-user response confusion" / unauthorized job-run manipulation.
- Repeatedly resume/interfere with legitimate async bridge callbacks, causing denial-of-service on pending job runs or corrupting reported values, similar to how the fallback() bug lets an attacker misuse an account's approved funds via an unguarded alternate call path.

This is a Medium-risk class issue: the impact depends on the caller being able to obtain a valid, still-pending `runID`, but the endpoint itself provides zero authentication as a defense-in-depth layer — precisely the "fallback() unrestricted" pattern the reported bug flags in Nexus.

### Likelihood Explanation
Reachability is high: the route is exposed on the node's HTTP API with no auth middleware, callable by anyone with network access to the node. Exploitability requires knowledge of a valid pending `runID`, which is a UUID normally only known to the external bridge adapter that received the callback URL — but this echoes exactly the report's caveat that direct/authenticated call paths ("no `userOp`... no validator modules") bypass normal controls whenever the caller can reach the alternate path, and the codebase itself flags the design via `audit.UnauthedRunResumed`, indicating awareness that this endpoint is intentionally unauthenticated by design (bridges cannot hold a session/API token) rather than a coding oversight.

### Recommendation
Bind the resume capability to the specific requester by requiring a shared secret/HMAC in the callback URL or an external-initiator-style token tied to the specific `taskID`/bridge, rather than relying solely on UUID unguessability, mirroring the report's recommendation to add "authorization control ... based on the appended `msg.sender`" or an allow-listed set of callers. At minimum, ensure `runID` is cryptographically unpredictable, single-use, time-bound, and scoped to the specific bridge/job that created it, and add audit alerting/rate limiting on this endpoint given it is deliberately outside the normal auth pipeline.

### Proof of Concept
1. Start a webhook/bridge async job whose `BridgeTask` generates a resume URL like `http://<node>:6688/v2/resume/<taskUUID>` (see `core/services/pipeline/task.bridge_test.go` lines 635, 799 for the URL format).
2. An attacker who obtains this URL (e.g., via a compromised or malicious bridge adapter, logs, or network observation) sends:
   `PATCH /v2/resume/<taskUUID>` with body `{"error": null, "value": "<attacker-controlled value>"}` — with no Authorization header, no API key/secret, no session cookie.
3. `PipelineRunsController.Resume` accepts the request (route is in `unauthedv2`), calls `App.ResumeJobV2`, and the attacker-supplied value is injected into the suspended pipeline run, affecting downstream oracle computation, all without any authentication check. [1](#0-0) [3](#0-2)

// Resume finishes a task and resumes the pipeline run.
// Example:
// "PATCH <application>/jobs/:ID/runs/:runID"
func (prc *PipelineRunsController) Resume(c *gin.Context) {
	taskID, err := uuid.Parse(c.Param("runID"))
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	rr := pipeline.ResumeRequest{}
	decoder := json.NewDecoder(c.Request.Body)
	err = errors.Wrap(decoder.Decode(&rr), "failed to unmarshal JSON body")
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	result, err := rr.ToResult()
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	if err := prc.App.ResumeJobV2(c.Request.Context(), taskID, result); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
	c.Status(http.StatusOK)
}
