Audit Report

## Title
Withdrawing a fully unbonded stash permanently forfeits unclaimed era staking rewards for the stash and all its nominators - ([File: substrate/frame/staking/src/pallet/impls.rs], [File: substrate/frame/staking-async/src/pallet/impls.rs])

## Summary
In both `pallet-staking` and `pallet-staking-async`, `do_withdraw_unbonded` calls `kill_stash` once a stash's active bonded balance drops below the existential deposit and it has no remaining unlocking chunks. `kill_stash`/`StakingLedger::kill` removes the `Ledger`, `Bonded`, and `Payee` entries for that stash. Because `payout_stakers` / `do_payout_stakers_by_page` must resolve the validator stash's `Ledger` via `Self::ledger(StakingAccount::Stash(validator_stash))` to compute commission, track `legacy_claimed_rewards`, and mark pages as claimed, this resolution fails with `Error::NotStash` once the ledger is gone — permanently blocking payout for any era still within `HistoryDepth` that had not yet been claimed.

## Finding Description
`do_withdraw_unbonded` in `substrate/frame/staking/src/pallet/impls.rs` (L204-219) kills the stash's ledger, bonded mapping, and payee once the active balance is below ED and no unlocking chunks remain, via `Self::kill_stash`, which in turn calls `StakingLedger::<T>::kill(&stash)` removing `Ledger`, `Bonded`, and `Payee` (L787-798). `payout_stakers` (L283-290) then requires resolving the *validator stash's* ledger through `Self::ledger(account.clone())`; if that lookup fails and the account is not bonded, it returns `Error::<T>::NotStash`. This ledger lookup is not incidental — it is used further downstream to prune/check `legacy_claimed_rewards` (L292-295), determine `validator_commission` via `EraInfo::<T>::get_validator_commission(era, &ledger.stash)` (L339), and to emit the `PayoutStarted` event with `next: EraInfo::<T>::get_next_claimable_page(...)`. None of this logic has a fallback path when the ledger has been deleted, so once a validator stash is killed, the entire payout path for any of its unclaimed eras (within `HistoryDepth`) is permanently inaccessible — this affects not only the killed stash's own rewards but every nominator's exposure behind that validator for that era, since `payout_stakers` is the sole mechanism to release an era/page's rewards for a given validator.

The identical structure exists in `pallet-staking-async`: `do_withdraw_unbonded` (L288-317) calls `kill_stash`, which calls `StakingLedger::kill` (`substrate/frame/staking-async/src/ledger.rs` L320-338), removing `Ledger`, `Bonded`, `Payee`. `do_payout_stakers_by_page` (`substrate/frame/staking-async/src/pallet/impls.rs` L368-375) performs the same ledger-resolution-or-`NotStash` pattern.

No code path in either pallet auto-flushes or blocks the kill/reap operation when unclaimed reward pages exist for eras still within `HistoryDepth`. The security assumption broken is that "a stash's earned-but-unclaimed rewards remain claimable for the duration of `HistoryDepth`" — this assumption is violated whenever the stash is unbonded and withdrawn/reaped before that window elapses, which is entirely plausible since `BondingDuration` and `HistoryDepth` are independently configured and typically overlap (a stash can fully withdraw well before HistoryDepth eras have elapsed for a given past era).

## Impact Explanation
This is a concrete, permanent loss/freezing of already-accrued yield. For a nominator, the impact is limited to their own unclaimed rewards. For a validator, the impact is severe: killing the validator's own stash blocks `payout_stakers`/`do_payout_stakers_by_page` for the *entire* exposure of that era/page, meaning all nominators who were exposed to that validator in that era also permanently lose their rewards for that era, since there is no alternate claim path once the validator's `Ledger` entry is gone. This is triggerable without any privileged role, purely through normal staking mechanics (`unbond` → wait `BondingDuration` → `withdraw_unbonded`, or via permissionless `reap_stash`).

## Likelihood Explanation
The exploit path requires no special privilege and is a natural/likely occurrence for ordinary stakers or automated unbonding bots who don't carefully sequence `payout_stakers` calls before `withdraw_unbonded`. It is entirely plausible in practice since `BondingDuration` (unbonding wait period) is commonly shorter than `HistoryDepth` (reward-claim retention window) in real network configurations, meaning a staker can legitimately have unclaimed eras still within the claim window at the moment full withdrawal becomes possible.

## Recommendation
Before killing a stash in `do_withdraw_unbonded` (and in `reap_stash`) in both `pallet-staking` and `pallet-staking-async`, either: (a) automatically claim/flush all unclaimed reward pages for eras within `HistoryDepth` for the stash, or (b) refuse the kill/reap and return an error until the caller (or any permissionless caller) has called `payout_stakers`/`payout_stakers_by_page` for all such outstanding eras. Alternatively, decouple the payout-eligibility check from the possibly-deleted `Ledger` so that a killed stash's exposures/commission data can still be resolved and claims processed independently of the live ledger.

## Proof of Concept
1. Bond stash `S`, nominate a validator (or have `S` be the validator), and accrue rewards for eras `E1` and `E2` without calling `payout_stakers` for either.
2. Call `unbond` for the full active amount from `S`.
3. Advance past `BondingDuration` eras (while still within `HistoryDepth` for `E1`/`E2`).
4. Call `withdraw_unbonded(0)`: since `ledger.active < ExistentialDeposit` and `unlocking` is empty, `kill_stash` executes, deleting `Ledger`, `Bonded`, `Payee` for `S` (`substrate/frame/staking/src/pallet/impls.rs` L204-219, L787-798).
5. Call `payout_stakers(S, E1)`: fails with `Error::NotStash` because `Self::ledger(StakingAccount::Stash(S))` no longer resolves (`substrate/frame/staking/src/pallet/impls.rs` L283-290). Rewards for `E1`/`E2` are permanently unclaimable for `S` and, if `S` is a validator, for every nominator exposed through it in those eras.
