### Title
Slippage floor declared in `CircomData.slippageValues` is never actually enforced against the swap output - ([File: contracts/external-actions/swaps/ExternalActionSwap.sol])

### Summary
The reported Pendle bug (`minPtOut` hard-coded to `0`) is a generic “declared slippage protection that is never enforced” class of bug. The same class exists in this repo's swap external action: `ExternalActionSwap.swap()` requires `circomData.slippageValues[1] != 0` but never compares the actual `swappedAmount` returned by the router against that value, so the floor the user/prover committed to is decorative.

### Finding Description
`ExternalActionSwap.swap()` is the shared logic used by swap external actions (e.g. `LifiExternalAction`). It only checks that a slippage value was *set*, not that the swap actually respected it: [1](#0-0) 

`swappedAmount` is computed from `callRouter(...)`, whose LI.FI implementation just diffs balances before/after an arbitrary `router.call(externalActionMetadata)`: [2](#0-1) 

Nowhere after `swappedAmount` is obtained does the code assert `swappedAmount >= uint256(circomData.slippageValues[1])` (or equivalent). `slippageValues` is included as a dimension check (its length must equal `tokenNumber`) and is folded into the `calldataHash`/circuit public input via `HinkalHelper.dimensionsCheck` and `formInputForCircom`, so the field is committed to by the prover, but the on-chain equality "declared floor ⇔ enforced floor" is never checked: [3](#0-2) 

Because `externalActionMetadata` (the actual router calldata, including whatever `amountOutMin` is embedded in it) is built off-chain by whoever submits the LI.FI route — typically the relay, since routes must reflect current market data at execution time — a malicious/careless relay can submit a proof-valid `CircomData` with a non-zero `slippageValues[1]` (satisfying the `require`) while supplying LI.FI swap calldata with little or no real `minOut`, sandwiching the swap. The contract has no independent check to catch this, so the field the user/prover believes protects them provides no actual protection.

### Impact Explanation
This allows a relay (or anyone able to influence `externalActionMetadata`) to extract value from a shielded user's swap via sandwich/MEV manipulation without violating any on-chain invariant, resulting in the user receiving less output than the amount they committed to and proved as their acceptable floor — a form of theft of shielded user funds during an external swap that Hinkal is supposed to gate on `slippageValues`.

### Likelihood Explanation
High: LI.FI route calldata is inherently constructed at execution time (off-chain), so it is realistic for a relay to submit a technically-valid, non-zero `slippageValues[1]` merely to pass the `require`, while the router calldata itself carries a much weaker or absent slippage guard. No privileged role beyond acting as relay/submitter is required, and this can happen on every swap.

### Recommendation
Enforce the committed floor in `ExternalActionSwap.swap()` explicitly, e.g.:
```solidity
require(
    swappedAmount >= uint256(circomData.slippageValues[1]),
    "swap output below slippage floor"
);
```
placed immediately after `swappedAmount` is computed, so the value proven/committed in `CircomData` is actually the value enforced on-chain, closing the gap between the declared and enforced slippage protection.

### Proof of Concept
1. Relay receives a shielded swap request where the user's app sets `circomData.slippageValues[1] = 1` (any non-zero placeholder value satisfies the `require`), well below the user's true expected minimum.
2. Relay crafts (or is handed) `externalActionMetadata` for the LI.FI router that itself sets a near-zero `amountOutMin`, then sandwiches the trade with its own bot before/after this transaction.
3. `ExternalActionSwap.swap()` executes: `require(circomData.slippageValues[1] != 0, ...)` passes trivially; `callRouter` returns a `swappedAmount` far below what the user actually expected.
4. No further check exists, so `amountToSendToHinkal = swappedAmount - totalFee` is minted into the user's new shielded UTXO — the user has silently lost value to the sandwich, and the contract never reverts. [4](#0-3)

```text
    function callRouter(
        address inputToken,
        uint256 inputAmount,
        address outputToken,
        bytes calldata externalActionMetadata
    ) internal override returns (uint256 swappedAmount) {
        uint256 balanceBefore = getERC20OrETHBalance(outputToken);

        if (inputToken == address(0)) {
            (bool success, ) = router.call{value: inputAmount}(
                externalActionMetadata
            );
            require(success, "LI.FI swap failed: native coin");
        } else {
            approveUnlimited(inputToken, router);
            (bool success, ) = router.call(externalActionMetadata);
            require(success, "LI.FI swap failed: erc-20 token");
        }

        swappedAmount = getERC20OrETHBalance(outputToken) - balanceBefore;
    }
```
