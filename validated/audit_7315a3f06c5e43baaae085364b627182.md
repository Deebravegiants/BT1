### Title
Webhook `shop` (and `topic`/`webhook_id`/`api_version`) identity fields are not covered by the HMAC, enabling cross-tenant webhook spoofing - (File: lib/shopify_api/webhooks/request.rb)

### Summary
`ShopifyAPI::Webhooks::Request` computes its HMAC-signable content from the raw body only, while the `shop`, `topic`, `webhook_id`, and `api_version` values consumed by `ShopifyAPI::Webhooks::Registry.process` are taken from unauthenticated HTTP headers that are never included in that signed content. This breaks the intended binding `HMAC-verified bytes == identity used by the handler`.

### Finding Description
`Webhooks::Request#to_signable_string` returns only `@raw_body`: [1](#0-0) 

`Utils::HmacValidator.validate` computes and compares the HMAC solely over that `to_signable_string` value: [2](#0-1) 

But `Registry.process` derives the tenant identity (`shop`) and event routing (`topic`, `webhook_id`, `api_version`) straight from HTTP headers that were never part of the signed payload: [3](#0-2) [4](#0-3) 

So the equality that should hold — `hmac(raw_body ‖ shop ‖ topic)` verified ⇒ `shop`/`topic` are authentic — does not hold. Only `raw_body` is authenticated; `shop`, `topic`, `webhook_id`, `api_version` are attacker-controllable headers that ride along unauthenticated.

### Impact Explanation
An attacker who legitimately receives even one valid `(raw_body, hmac)` pair from Shopify (e.g., by installing the app on their own development/trial store and letting Shopify deliver any webhook, including one with an easily-reproducible/empty body) can replay that exact `raw_body` + `shopify-hmac-sha256` value to the app's public webhook endpoint while substituting the `shopify-shop-domain` header with an arbitrary victim shop, and/or the `shopify-topic` header with any topic the app has registered a handler for. `HmacValidator.validate` will pass because it only checks the body's HMAC, and `Registry.process` will invoke the corresponding `WebhookHandler` with `shop: <victim shop chosen by attacker>` and `topic: <attacker-chosen topic>`. Any app logic keyed off `WebhookMetadata#shop` (e.g., processing `app/uninstalled` to revoke/deactivate a merchant's stored session, or business logic keyed by shop for orders/fulfillments) can be triggered against a tenant the attacker does not control — a cross-tenant identity/authorization bypass.

### Likelihood Explanation
Requires only: (1) the app to expose the standard webhook endpoint (already reachable by an unprivileged internet user), and (2) attacker possession of any single valid signed webhook body from Shopify, which the attacker can trivially obtain by installing the app on their own store (no victim credentials, TLS interception, or leaked secrets needed). This satisfies the "unprivileged internet user" bar.

### Recommendation
Include the identity-bearing headers (`shop`, `topic`, and ideally `webhook_id`) in the HMAC-signed material, or otherwise cryptographically bind them to the signature (e.g., validate against Shopify's documented header set the way Shopify's own webhook signature already binds body+headers), and reject requests where the header-derived shop/topic cannot be independently corroborated (e.g., against a known/registered shop list) before dispatching to handlers.

### Proof of Concept
```ruby
# 1. Attacker installs the target app on their own throwaway shop and captures
#    a legitimate webhook delivery, e.g. body = "{}" with a valid
#    x-shopify-hmac-sha256 computed by Shopify using the app's real client_secret.
captured_body = "{}"
captured_hmac = "<hmac Shopify sent for captured_body, base64>"

# 2. Attacker replays the same body/hmac to the app's public webhook endpoint,
#    but swaps the shop-domain (and optionally topic) header to target a victim shop
#    that never sent this request:
forged_headers = {
  "x-shopify-topic" => "app/uninstalled",       # attacker-chosen, unsigned
  "x-shopify-hmac-sha256" => captured_hmac,     # valid only for captured_body
  "x-shopify-shop-domain" => "victim-shop.myshopify.com", # attacker-chosen, unsigned
}

request = ShopifyAPI::Webhooks::Request.new(raw_body: captured_body, headers: forged_headers)
ShopifyAPI::Webhooks::Registry.process(request)
# => HmacValidator.validate(request) passes (only raw_body is checked),
#    and the registered handler is invoked with shop: "victim-shop.myshopify.com",
#    even though this shop never sent the webhook.
```
