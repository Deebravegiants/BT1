### Title
Unauthenticated Confidential Relay Gateway Handler Allows Request-ID Squatting DoS - ([File: core/services/gateway/handlers/confidentialrelay/handler.go])

### Summary
The `AlignedLayerServiceManager.createNewTask()` bug allowed an unauthenticated caller to front-run a legitimate `batchMerkleRoot` submission by claiming the same global identifier first, permanently blocking the real submission. The Chainlink gateway's confidential relay handler has the same root cause: `HandleJSONRPCUserMessage` accepts any caller's JSON-RPC request with **no authentication** and inserts it into a single global map keyed only by the caller-supplied `req.ID`, with no binding to the caller's identity.

### Finding Description
`handler.HandleJSONRPCUserMessage` only validates that `req.ID` is non-empty and ≤200 characters before calling `newActiveRequest`, with no authentication/authorization step of any kind: [1](#0-0) 

`newActiveRequest` then keys the process-wide `activeRequests` map purely by the attacker-controlled `req.ID`, rejecting any second request with the same ID regardless of who sent it: [2](#0-1) 

This is confirmed directly by the handler's own test, which shows a second, unrelated `HandleJSONRPCUserMessage` call with the same `req.ID` is rejected outright: [3](#0-2) 

Contrast this with the sibling `vault` gateway handler, which was hardened against exactly this class of bug (the same fix pattern used to resolve the original `createNewTask` finding, `hash(merkle_root, msg.sender)`): the vault handler requires an authorization step (`h.requestProcessor.ProcessRequest`) that resolves an `authorizedOwner`, and downstream request IDs sent to nodes are namespaced by that authenticated owner (`owner + vaulttypes.RequestIDSeparator + requestID`), so two different callers can never collide on the same key: [4](#0-3) [5](#0-4) 

The confidential relay handler has no equivalent authentication or per-caller namespacing anywhere in `Methods()`, `HandleJSONRPCUserMessage`, or `newActiveRequest`, so any unprivileged client reaching the gateway (`gateway.ProcessRequest` routes JSON-RPC requests by method name/service name to this handler without an auth gate specific to confidential relay) can pre-empt or collide with another caller's request ID. [6](#0-5) 

### Impact Explanation
An unprivileged, unauthenticated actor who can reach the gateway's public JSON-RPC endpoint can:
1. Predict or observe a legitimate caller's forthcoming `req.ID` (these are workflow/execution-tied identifiers logged and correlated with `workflowID`/`executionID`), and submit a request with that same ID first.
2. Cause the legitimate request to fail immediately with `"request ID already exists"`, denying service to that workflow execution's confidential relay request — directly analogous to the original `createNewTask` DoS where a front-runner claims the `batchMerkleRoot` key first and blocks the real batcher.
3. Alternatively, flood the map with garbage IDs to hold entries open until `requestTimeout`, without any authentication cost, amplifying resource exhaustion on the gateway node.

This does not itself leak secrets, but it is a concrete, unauthenticated DoS/request-hijack vector on an internet-facing gateway handler, matching the accepted "unprivileged-actor" bug class scope (message envelope / handler / no authentication on task/request creation).

### Likelihood Explanation
Likelihood is high for any deployment where the confidential relay method is exposed on the public gateway HTTP endpoint without an additional authentication layer in front of it, since `HandleJSONRPCUserMessage` performs zero authentication before mutating the shared `activeRequests` map — this is a straightforward single HTTP POST from any client.

### Recommendation
Adopt the same mitigation pattern already used by the vault handler: require authentication of the caller (e.g., JWT/allowlist-based authorization as in `AllowListBasedAuth`/`JWTBasedAuth`) before accepting a confidential relay request, and namespace/prefix the `activeRequests` key (and any downstream identifiers) by the authenticated caller identity (e.g., `authenticatedCallerID + separator + req.ID`) rather than trusting the raw client-supplied `req.ID` as a global key.

### Proof of Concept
1. Attacker learns/predicts a legitimate caller's upcoming `req.ID` (e.g., correlated `workflowID`/`executionID` values are logged by the gateway).
2. Attacker sends a JSON-RPC request to the confidential relay gateway endpoint with `Method: MethodCapabilityExec` (or `MethodSecretsGet`) and that same `ID`, with arbitrary/garbage `Params` — no authentication token is required.
3. `newActiveRequest` inserts the attacker's entry into `activeRequests[req.ID]`.
4. When the legitimate caller's request with the same `ID` arrives, `HandleJSONRPCUserMessage` returns `"request ID already exists: <id>"`, denying the legitimate request until the attacker's bogus entry expires via `removeExpiredRequests` after `requestTimeout` (default 30s), as reproduced by `TestConfidentialRelayHandler_DuplicateRequestID`.

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], labels requestLabels, callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID, "executionID", labels.ExecutionID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		labels:    labels,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

func (h *handler) HandleJSONRPCUserMessage(ctx context.Context, req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) error {
	if req.ID == "" {
		return errors.New("request ID cannot be empty")
	}
	if len(req.ID) > 200 {
		// Arbitrary limit to prevent abuse
		return errors.New("request ID is too long: " + strconv.Itoa(len(req.ID)) + ". max is 200 characters")
	}

	h.lggr.Debugw("handling vault request", "method", req.Method, "requestID", req.ID, "request", req)
	if req.Method == vaulttypes.MethodPublicKeyGet {
		// Public key requests don't require authorization,
		// Let's process this request right away.
		// Note we cache this value quite aggressively so don't need to worry about DoS.
		publicKeyResponseBytes, cachedPublicKey := h.getCachedPublicKey()
		if cachedPublicKey == nil {
			// Not found in cache. Fetch from nodes.
			ar, err := h.newActiveRequest(req, callback)
			if err != nil {
				h.lggr.Errorw("failed to create new activeRequest", "error", err)
				return err
			}
			return h.handlePublicKeyGet(ctx, ar)
		}
		h.lggr.Debugw("returning cached public key response")
		return h.handlePublicKeyGetSynchronously(ctx, req, publicKeyResponseBytes, callback)
	}

	if !vaulttypes.IsGatewaySecretsMethod(req.Method) {
		return h.sendImmediateUserResponse(ctx, req, callback, api.UnsupportedMethodError, errors.New("this method is unsupported: "+req.Method))
	}

	_, cachedPublicKey := h.getCachedPublicKey()
	authorized, err := h.requestProcessor.ProcessRequest(ctx, &req, cachedPublicKey)
	if err != nil {
		if vaultcap.IsInvalidVaultParamsError(err) {
			return h.sendImmediateUserResponse(ctx, req, callback, api.InvalidParamsError, err)
		}
		h.lggr.Errorw("request not authorized", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "", "error", err)
		return errors.New("request not authorized: " + err.Error())
	}
	authorizedOwner := authorized.AuthResult.AuthorizedOwner()

	h.lggr.Debugw("handling authorized vault request", "method", req.Method, "requestID", req.ID, "authorizedOwner", authorizedOwner)
	ar, activeRequestErr := h.newActiveRequest(req, callback)
	if activeRequestErr != nil {
		return activeRequestErr
	}

// Called by the server
func (g *gateway) ProcessRequest(ctx context.Context, rawRequest []byte, auth string) (rawResponse []byte, httpStatusCode int) {
	// decode
	jsonRequest, err := jsonrpc2.DecodeRequest[json.RawMessage](rawRequest, auth)
	if err != nil {
		return newError("", api.UserMessageParseError, err.Error())
	}
	msg, err := g.codec.DecodeJSONRequest(jsonRequest)
	if err != nil {
		return newError(jsonRequest.ID, api.UserMessageParseError, err.Error())
	}
	if len(jsonRequest.ID) > 200 {
		// Arbitrary limit to prevent abuse
		return newError(jsonRequest.ID, api.UserMessageParseError, "request ID is too long: "+strconv.Itoa(len(jsonRequest.ID))+". max is 200 characters")
	}
	isLegacyRequest := false
	var h handlers.Handler
	var handlerKey string
	if msg == nil || msg.Body.DonID == "" {
		serviceName := jsonRequest.ServiceName()
		if handler, ok := g.serviceToMultiHandler[serviceName]; ok {
			h = handler
			handlerKey = serviceName
		} else if donID, ok := g.serviceNameToDonID[serviceName]; ok {
			// Fallback to legacy service name -> DON ID mapping
			if handler, ok := g.handlers[donID]; ok {
				h = handler
				handlerKey = donID
			}
		}
		if h == nil {
			return newError(jsonRequest.ID, api.HandlerError, "Service name not found: "+serviceName)
		}
	} else {
		// Legacy request with DON ID - validate and fetch handler
		isLegacyRequest = true
		if err = msg.Validate(); err != nil {
			return newError(jsonRequest.ID, api.UserMessageParseError, err.Error())
		}
		handlerKey = msg.Body.DonID
		var ok bool
		h, ok = g.handlers[handlerKey]
		if !ok {
			return newError(jsonRequest.ID, api.UnsupportedDONIdError, "Unsupported DON ID: "+handlerKey)
		}
	}
