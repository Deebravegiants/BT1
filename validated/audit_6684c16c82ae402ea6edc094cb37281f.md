### Title
Sender-controlled duplicate output commitments produce colliding nullifiers, permanently freezing a recipient's UTXO - (File: circuits/OriginalCommitmentCalculator.circom, circuits/NullifierCalculator.circom)

### Summary
Output UTXO commitments in `OriginalCommitmentCalculator` are computed only from `amount`, `erc20TokenAddress`, `publicKey`, and `timeStamp`, with no per-leaf nonce or tree-index binding. Because a single `transact()` call shares one `outTimeStamp` across all outputs, a sender can create two outputs to the *same* recipient stealth `publicKey` with the same `amount`/token in one transaction, producing two identical `outCommitments` values. Since the nullifier (`NullifierCalculator`) is derived purely from `(commitment, signature)` — and `signature = Poseidon(nullifyingPrivateKey, commitment)` — both identical leaves resolve to the *same* nullifier. When the victim spends the first, the second becomes permanently unspendable because its (identical) nullifier is already marked used.

### Finding Description
`OriginalCommitmentCalculator` computes the leaf commitment as `Poseidon(amount, erc20TokenAddress, publicKey, timeStamp)` with no leaf index, salt, or nonce input: [1](#0-0) 

In `MainEVMCircuit`, every output for a given token type in a single call uses the same shared `outTimeStamp` signal: [2](#0-1) 

The nullifier is derived only from the commitment value and a signature over that commitment, with no dependency on the leaf's tree position/index: [3](#0-2) [4](#0-3) 

`HinkalBase.insertCommitments` inserts every non-zero commitment as a leaf without any duplicate check, and `insertNullifiers`/`nullifiers` mapping only rejects nullifier reuse at spend time, not at creation time: [5](#0-4) 

`HinkalHelper.dimensionsCheck` validates array shapes/lengths but never checks that `outCommitments` entries are distinct: [6](#0-5) 

This is directly analogous to the UMA report's root cause: a hash/commitment used as a unique identifier is not bound to enough context (there, the voter; here, a per-leaf nonce/index), so two logically distinct entries can collide and become indistinguishable to the downstream verification logic (there: duplicate votes; here: duplicate nullifiers).

### Impact Explanation
Any sender who legitimately controls valid input UTXOs (their own funds, requiring no privileged access) can, within a single `transact()` call, mint two identical output commitments to an arbitrary third-party recipient's stealth `publicKey` (same amount, same token, same shared `outTimeStamp`). Both are accepted and inserted as valid leaves. When the recipient later spends the first UTXO with their `nullifyingPrivateKey`, the deterministic nullifier for the second, still-unspent, equal-value UTXO is simultaneously marked as used (`nullifiers[...] = true`), because it is the same value. The second UTXO can never be spent by its rightful owner — a permanent freeze of value-bearing funds belonging to a party who never authorized or triggered the colliding transaction. This satisfies the Critical impact bar: "permanent freezing of user funds."

### Likelihood Explanation
This requires no admin/relay/oracle privilege — only an ordinary Hinkal user constructing two outputs to the same known public key within one proof (both a normal and adversarial usage pattern, since Hinkal supports multi-output transactions natively via `outputCount`). The attacker only needs to know the victim's stealth public key (which is exchanged for normal private transfers) and set both outputs' amount/token identically, which is fully attacker-controlled circuit input with no on-chain uniqueness check preventing it.

### Recommendation
Bind the output commitment (and/or nullifier) to a value that is unique per leaf, e.g. include the tree insertion index, a per-output random salt/nonce chosen by the sender, or an output-slot index (`j`) inside `OriginalCommitmentCalculator`'s Poseidon preimage, so that two outputs with identical amount/token/recipient/timestamp still produce distinct commitments and distinct nullifiers. Additionally, add an on-chain or in-circuit check rejecting duplicate `outCommitments` entries within the same call as defense in depth.

### Proof of Concept
1. Victim shares stealth `publicKey` P (as normal for receiving private transfers).
2. Attacker (any user with a spendable UTXO of token `T`) calls `transact()` with `outputCount ≥ 2`, setting `outAmounts[i][0] = outAmounts[i][1] = X`, `outPublicKeys[i][0] = outPublicKeys[i][1] = P`, and one shared `outTimeStamp`, adjusting `amountChanges`/other outputs to balance the equation `inTotal + amountChanges[i] === outTotal`.
3. `calcOutCommitment[i][0].out === calcOutCommitment[i][1].out` both equal `Poseidon(X, T, P, outTimeStamp)`; both pass circuit checks and are accepted by `Hinkal.transact` and inserted via `insertCommitments`.
4. Two identical leaves for value `X` of token `T` now exist in the tree, both spendable only by holder of the private key behind `P` (the victim).
5. Victim spends the first leaf: circuit computes `commitment = Poseidon(X,T,P,outTimeStamp)`, `signature = Poseidon(nullifyingPrivateKey, commitment)`, `nullifier = Poseidon(commitment, signature)`; `insertNullifiers` marks this nullifier as used.
6. Victim attempts to spend the second identical leaf: the circuit computes the *same* nullifier (identical commitment and same `nullifyingPrivateKey`), and `HinkalBase.insertNullifiers`'s `require(!nullifiers[...], "Nullifier cannot be reused")` reverts, permanently locking the second UTXO's value.

template OriginalCommitmentCalculator() {
  signal input amount;
  signal input erc20TokenAddress;
  signal input publicKey;
  signal input timeStamp;
  signal output out;

  component calcIsAmountZero = IsZero();
  calcIsAmountZero.in <== amount;

  component calcCommitment = Poseidon(4);
  calcCommitment.inputs[0] <== amount;
  calcCommitment.inputs[1] <== erc20TokenAddress;
  calcCommitment.inputs[2] <== publicKey;
  calcCommitment.inputs[3] <== timeStamp;

  out <== calcCommitment.out * (1 - calcIsAmountZero.out);
}

    function insertCommitments(
        uint256[][] memory offChainCommitments,
        bytes[][] memory offChainEncryptedOutputs,
        OnChainCommitment[] memory onChainCommitments,
        bool[] memory onChainCreation
    ) internal {
        // 1) Total Length of Commitments
        uint256 length = 0;
        for (uint256 i = 0; i < offChainCommitments.length; i++) {
            for (uint256 j = 0; j < offChainCommitments[i].length; j++) {
                if (onChainCreation[i]) break;
                length += offChainCommitments[i][j] != 0 ? 1 : 0;
            }
        }
        length += onChainCommitments.length;

        if (length > 0) {
            // 2) Flattening leaves array
            uint256[] memory leaves = new uint256[](length);
            uint256 index = 0;
            for (uint256 i = 0; i < offChainCommitments.length; i++) {
                for (uint256 j = 0; j < offChainCommitments[i].length; j++) {
                    if (onChainCreation[i] == true) break;
                    if (offChainCommitments[i][j] != 0) {
                        leaves[index++] = offChainCommitments[i][j];
                    }
                }
            }
            for (uint256 i = 0; i < onChainCommitments.length; i++) {
                leaves[index++] = onChainCommitments[i].commitment;
            }

            // 3) Inserting Leaves
            uint256[] memory insertedIndexes = insertMany(leaves);

            // 4) Emitting Commitments/EncryptedOutputs
            index = 0;
            for (uint256 i = 0; i < offChainEncryptedOutputs.length; i++) {
                for (uint256 j = 0; j < offChainEncryptedOutputs[i].length; j++) {
                    if (onChainCreation[i] == true) break;
                    if (offChainCommitments[i][j] != 0) {
                        emit NewCommitment(
                            leaves[index],
                            int256(insertedIndexes[index]),
                            offChainEncryptedOutputs[i][j]
                        );
                        index++;
                    }
                }
            }
            for (uint256 i = 0; i < onChainCommitments.length; i++) {
                emit NewCommitment(
                    leaves[index],
                    -1 * int256(insertedIndexes[index++]),
                    abi.encode(
                        onChainCommitments[i].utxo,
                        onChainCommitments[i].onChainEncryptedOutput
                    )
                );
            }
        }
    }

    function insertNullifiers(
        uint256[][] calldata inputNullifiers,
        bool[] calldata onChainCreation
    ) internal {
        for (uint256 i = 0; i < inputNullifiers.length; i++) {
            for (uint256 j = 0; j < inputNullifiers[i].length; j++) {
                if (onChainCreation[i] == true) break;
                if (inputNullifiers[i][j] != 0) {
                    require(
                        !nullifiers[inputNullifiers[i][j]],
                        "Nullifier cannot be reused"
                    );
                    nullifiers[inputNullifiers[i][j]] = true;
                    emit Nullified(inputNullifiers[i][j]);
                }
            }
