### Title
Permanent market freeze: RAY-value overflow in `accrue_step` bricks every market entrypoint - (File: contracts/pool/src/interest.rs)

### Summary
An invalid-memory-dereference crash in FAAC maps onto Soroban as an unrecoverable arithmetic trap inside a state transition that every caller must pass through. In XOXNO Lending, `interest::global_sync` runs inside `ops::synced_market`, which is the first step of every pool mutation (supply, borrow, withdraw, repay, seize, flash, recapitalize) and of `update_indexes` [1](#0-0) . The chunked accrual loop calls `accrue_step` [2](#0-1) , whose RAY-domain value computations panic with `MathOverflow` once `borrowed × borrow_index` exceeds the i128/RAY capacity — a point reachable before the `MAX_BORROW_INDEX_RAY` index cap ever engages [3](#0-2) . Once crossed, the panic is deterministic and permanent: every subsequent call that touches the market accrues first and traps identically.

### Finding Description
`compound_interest` and the share/value math in `accrue_step` panic on overflow (`GenericError::MathOverflow`) [4](#0-3) . `global_sync` loops over elapsed time applying `accrue_chunk`, so the overflow fires inside the sync itself, before `mark_accrued` can commit a new `last_timestamp` — the market can never advance past the overflowing step [5](#0-4) . Because `borrow_index` is monotone non-decreasing [6](#0-5) , the condition is irreversible: no deposit, repayment, or governance-settable knob shrinks `borrowed × borrow_index` back into range (repayment itself must accrue first, so it also traps). The integration test demonstrates the end state concretely: after enough accrual at high utilization, `update_indexes`, `withdraw`, and `repay` all revert with `MATH_OVERFLOW` [7](#0-6) .

### Impact Explanation
All value in the affected market is permanently frozen: suppliers cannot withdraw, borrowers cannot repay, liquidators cannot seize (seize paths call `ops::seize` → `synced_market` [8](#0-7) ), and `claim_revenue`/`recapitalize`/`flash_loan` on that market fail identically. Because the pool keeps separate books per `(hub, token)` over one physical balance, the freeze is per-market, but the trapped cash and outstanding debt are lost forever — matching the "permanent freezing of funds" and "protocol insolvency" impact classes.

### Likelihood Explanation
No privileged call is needed to create the precondition: any unprivileged address can supply and borrow through `controller.supply`/`borrow`, pushing utilization high on a large book. The overflow requires a very large book (finite RAY value capacity exhausted before the index ceiling [9](#0-8) ) and sustained high utilization over a long accrual horizon — the harness test reaches the cliff at ~98% utilization over years on a steep rate curve [10](#0-9) . An attacker with sufficient capital can deliberately construct and maintain such a market; natural markets at high utilization can also drift into it since caps are denominated in asset units and do not account for index growth [11](#0-10) . Medium likelihood at best, matching the Medium severity of the source report.

### Recommendation
Make `accrue_step` saturating rather than trapping at the value ceiling: cap the computed value at `i128::MAX` (or clamp `borrow_index` growth so `borrowed × index` stays in domain), so `global_sync` can always complete and exits/repayments remain possible. Alternatively, add a governance-reachable `update_params`-based rate reduction path that does not require accrual first — currently even risk-reducing operations sync before acting. Emit an event or expose a flag when accrual approaches the ceiling so markets can be wound down before the cliff.

### Proof of Concept
Covered by the existing harness test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap`: supply a large `BIG18` book, borrow ~98% of it, advance ledger time year-by-year; `try_update_indexes_for(["BIG18"])` eventually fails with `MATH_OVERFLOW` while `borrow_index < MAX_BORROW_INDEX_RAY`, and afterwards `withdraw` and `repay` both revert with the same error [12](#0-11) . The entrypoints used (`supply`, `borrow`, `update_indexes`) are all callable by unprivileged addresses.

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
}
