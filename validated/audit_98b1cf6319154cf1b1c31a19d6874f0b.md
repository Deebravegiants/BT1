### Title
Cross-workflow HTTP response mix-up due to under-scoped cache key - ([File: core/services/gateway/handlers/capabilities/v2/response_cache.go])

### Summary
The gateway's outbound-HTTP-action `responseCache` keys cached responses by `req.Hash()`, which the code comment states covers "method, URL, headers, body, workflowOwner" [1](#0-0) . Tests explicitly confirm the hash is **identical regardless of `WorkflowID`**, while it does vary by `WorkflowOwner` [2](#0-1) . This contradicts the component's own documented invariant that "Cache entries are scoped by workflow ID to prevent cross-workflow data leakage" [3](#0-2) .

### Finding Description
`Fetch` and `Set` on `responseCache` use `req.Hash()` as the sole cache key [4](#0-3) [5](#0-4) . This key is computed purely from the outbound request shape (method/URL/headers/body) plus `WorkflowOwner`, but deliberately excludes `WorkflowID` (and `ExecutionID`), as proven by the test `"having different workflowID results in same Hash"` [2](#0-1) .

Because `makeOutgoingRequest` in `gatewayHandler` calls `h.responseCache.Fetch`/`Set` directly with the untouched `gateway_common.OutboundHTTPRequest` decoded from an untrusted workflow-node message [6](#0-5) , any two different workflows belonging to the same owner that happen to issue an HTTP Action with the same method/URL/headers/body will collide on the same cache entry. Whichever workflow's execution populates the cache first will have its response (including body content and headers, which may embed workflow-specific or session-specific data returned by the external endpoint) served back to the other workflow's request — a cross-workflow response mix-up, directly analogous to the Tomcat CVE-2024-52317 class of bug where improperly-scoped shared state (there: pooled request/response objects; here: a cache keyed on an incomplete identity) causes one actor's response to be delivered to a different actor.

The request originates from workflow (capability) nodes acting on behalf of end users/workflow owners, reaching this handler through the gateway's `ProcessRequest`/`HandleNodeMessage` path with no re-validation that a cached response actually belongs to the requesting workflow [7](#0-6) .

### Impact Explanation
An owner running multiple concurrent or sequential workflows that call the same external HTTP endpoint (same method/URL/headers/body) can have HTTP Action results silently swapped across workflow executions. If the endpoint's response is workflow/session-specific (e.g., depends on server-side state, nonces, or is cached before headers like per-execution auth tokens are appended), a workflow can receive and act on data that was fetched for a different workflow/execution. This is a cross-user/cross-execution response-confusion bug consistent with CWE-326/incorrect recycling classes: state intended to be execution-scoped is shared across a broader (owner-scoped) boundary. It does not directly leak secrets or bypass authentication, but produces incorrect results being fed into a different workflow's execution — impacting integrity/confidentiality of workflow-specific outbound HTTP data.

### Likelihood Explanation
Any workflow owner who runs more than one workflow performing identical outbound HTTP requests (a common pattern for shared APIs/webhooks) will trigger this collision whenever `CacheSettings.Store`/`MaxAgeMs` are used, which per the README is normal, supported functionality, not an edge case [3](#0-2) . No malicious action or elevated privilege is required — a legitimate, unprivileged workflow-owner-controlled request pattern is sufficient to trigger cross-workflow mix-up.

### Recommendation
Include `WorkflowID` (and ideally `ExecutionID`, if per-execution isolation is desired) in the cache key computed by `OutboundHTTPRequest.Hash()`, or otherwise scope the `responseCache` map by workflow ID in addition to the request hash, so that the documented "Workflow Isolation" guarantee in the README actually matches the implementation.

### Proof of Concept
1. Workflow owner `0xabc` runs Workflow A (`workflowID = wfA`) with an HTTP Action: `GET https://api.example.com/data`, `CacheSettings.Store = true`, `MaxAgeMs = 600000`.
2. The gateway fetches the external endpoint, gets a workflow-specific response body (e.g., because the external service returns per-caller data based on some other correlated signal), and caches it keyed by `Hash(method, URL, headers, body, workflowOwner=0xabc)` — note `wfA` is not part of the key, per `TestRequestHash`'s `"having different workflowID results in same Hash"` case [2](#0-1) .
3. The same owner `0xabc` runs Workflow B (`workflowID = wfB`) issuing an outbound HTTP Action with the identical method/URL/headers/body, within the cache TTL.
4. `Fetch` computes the same hash (ignoring `WorkflowID`) and returns Workflow A's cached response to Workflow B's execution [5](#0-4) , even though Workflow B never actually issued a request to the external endpoint for its own execution context.

func (rc *responseCache) Fetch(ctx context.Context, req gateway.OutboundHTTPRequest, fetchFn func() gateway.OutboundHTTPResponse, storeOnFetch bool) gateway.OutboundHTTPResponse {
	cacheKey := req.Hash()
	cacheMaxAge := time.Duration(req.CacheSettings.MaxAgeMs) * time.Millisecond

	// Fast path: check cache without singleflight overhead.
	rc.cacheMu.RLock()
	cachedResp, exists := rc.cache[cacheKey]
	rc.cacheMu.RUnlock()
	if exists && cachedResp.storedAt.Add(cacheMaxAge).After(time.Now()) {
		rc.metrics.IncrementCacheHitCount(ctx, rc.lggr)
		return cachedResp.response
	}

	// Slow path: singleflight deduplicates concurrent fetches per key.
	// Cache check + store happen inside the flight so the key isn't released
	// until the result is cached, closing the race window between singleflight
	// completion and cache write.
	result, _, _ := rc.flight.Do(cacheKey, func() (any, error) {
		// Re-check cache: a previous flight may have just stored the result.
		rc.cacheMu.RLock()
		cachedResp, exists := rc.cache[cacheKey]
		rc.cacheMu.RUnlock()
		if exists && cachedResp.storedAt.Add(cacheMaxAge).After(time.Now()) {
			rc.metrics.IncrementCacheHitCount(ctx, rc.lggr)
			return cachedResp.response, nil
		}

		response := fetchFn()

		if storeOnFetch && isCacheableStatusCode(response.StatusCode) {
			rc.cacheMu.Lock()
			rc.cache[cacheKey] = &cachedResponse{
				response: response,
				storedAt: time.Now(),
			}
			rc.cacheMu.Unlock()
		}

		return response, nil
	})

	return result.(gateway.OutboundHTTPResponse)
}

// Called by the server
func (g *gateway) ProcessRequest(ctx context.Context, rawRequest []byte, auth string) (rawResponse []byte, httpStatusCode int) {
	// decode
	jsonRequest, err := jsonrpc2.DecodeRequest[json.RawMessage](rawRequest, auth)
	if err != nil {
		return newError("", api.UserMessageParseError, err.Error())
	}
	msg, err := g.codec.DecodeJSONRequest(jsonRequest)
	if err != nil {
		return newError(jsonRequest.ID, api.UserMessageParseError, err.Error())
	}
	if len(jsonRequest.ID) > 200 {
		// Arbitrary limit to prevent abuse
		return newError(jsonRequest.ID, api.UserMessageParseError, "request ID is too long: "+strconv.Itoa(len(jsonRequest.ID))+". max is 200 characters")
	}
	isLegacyRequest := false
	var h handlers.Handler
	var handlerKey string
	if msg == nil || msg.Body.DonID == "" {
		serviceName := jsonRequest.ServiceName()
		if handler, ok := g.serviceToMultiHandler[serviceName]; ok {
			h = handler
			handlerKey = serviceName
		} else if donID, ok := g.serviceNameToDonID[serviceName]; ok {
			// Fallback to legacy service name -> DON ID mapping
			if handler, ok := g.handlers[donID]; ok {
				h = handler
				handlerKey = donID
			}
		}
		if h == nil {
			return newError(jsonRequest.ID, api.HandlerError, "Service name not found: "+serviceName)
		}
	} else {
		// Legacy request with DON ID - validate and fetch handler
		isLegacyRequest = true
		if err = msg.Validate(); err != nil {
			return newError(jsonRequest.ID, api.UserMessageParseError, err.Error())
		}
		handlerKey = msg.Body.DonID
		var ok bool
		h, ok = g.handlers[handlerKey]
		if !ok {
			return newError(jsonRequest.ID, api.UnsupportedDONIdError, "Unsupported DON ID: "+handlerKey)
		}
	}

	startTime := time.Now()
	var method string
	callback := handlerscommon.NewCallback()
	if isLegacyRequest {
		method = msg.Body.Method
		err = h.HandleLegacyUserMessage(ctx, msg, callback)
	} else {
		method = jsonRequest.Method
		err = h.HandleJSONRPCUserMessage(ctx, jsonRequest, callback)
	}
	if err != nil {
		return newError(jsonRequest.ID, api.HandlerError, err.Error())
	}

	response, err := callback.Wait(ctx)
	duration := time.Since(startTime)
	if err != nil {
		response := api.RequestTimeoutError
		g.gMetrics.RecordUserMsgHandlerDuration(ctx, method, response.String(), duration)
		g.gMetrics.RecordUserMsgHandlerInvocation(ctx, method, response.String())
		return newError(jsonRequest.ID, response, "handler timeout: "+err.Error())
	}
	g.gMetrics.RecordUserMsgHandlerDuration(ctx, method, response.ErrorCode.String(), duration)
	g.gMetrics.RecordUserMsgHandlerInvocation(ctx, method, response.ErrorCode.String())

	g.lggr.Debugw("received response from handler", "handler", handlerKey, "response", response, "requestID", jsonRequest.ID)
	promRequest.WithLabelValues(response.ErrorCode.String()).Inc()
	return response.RawResponse, api.ToHTTPErrorCode(response.ErrorCode)
}
