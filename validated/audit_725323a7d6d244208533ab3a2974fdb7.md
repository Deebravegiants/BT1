### Title
`sanitize_shop_domain` trusts the whole `uri.host` string while only validating its trailing labels via `uri.domain`, letting a control-byte-padded shop string return a non-Shopify host as `@base_uri` — (File: `lib/shopify_api/utils/shop_validator.rb`)

### Summary
`ShopValidator.sanitize_shop_domain` decides trust by comparing `uri.domain` (Addressable's public-suffix based registrable-domain projection, computed by splitting the host on `"."` from the right) against `TRUSTED_SHOPIFY_DOMAINS`, but then returns the *entire, unmodified* `uri.host` string as the "sanitized" shop. Because `.strip` in `uri_from_shop_domain` only trims leading/trailing whitespace and Addressable's URI parser is a lenient, regex-based splitter that does not itself reject embedded control bytes/tabs/newlines in the authority component, a crafted string such as `"evil.example\ttest-shop.myshopify.com"` can have its *trust decision* pass (because the rightmost dot-separated labels resolve to `myshopify.com`) while the *value actually returned and used downstream* still contains the attacker's prefix and the embedded control byte. That contaminated string is passed unmodified into `Clients::HttpClient#initialize`'s `@base_uri = "https://#{api_host || session.shop}"` [1](#0-0)  and into the `Host` header [2](#0-1) , so the string that was "verified" (its trailing labels) is not the string that is "used" (the full host, sent to whatever the transport layer resolves it to).

### Finding Description
The invariant this code is supposed to enforce is:
`sanitize!(shop) == host` **if and only if** `host` is entirely and unambiguously a subdomain of one of `TRUSTED_SHOPIFY_DOMAINS`.

The actual code breaks this into two different computations over two different projections of the same string:

- Trust decision: `uri_domain = uri.domain` and `from_trusted_domain = trusted_domain == uri_domain` [3](#0-2) . `uri.domain` (Addressable, via the public suffix list) is computed by taking the rightmost `.`-delimited labels of `uri.host` — it never looks at non-`.` characters elsewhere in the string.
- Returned value: plain `host = T.cast(uri.host, String)`, returned verbatim [4](#0-3) .

`uri_from_shop_domain` only calls `shop_domain.to_s.downcase.strip` before parsing with `Addressable::URI.parse` [5](#0-4) . `strip` removes leading/trailing ASCII whitespace only; it does nothing for control bytes, tabs, or newlines embedded in the middle of the string. Addressable's URI parser is a permissive, RFC-3986-style regex splitter that captures the authority/host component without validating character legality at parse time (validation is only triggered by explicit setter calls, not by `.parse`), so a string like:

```
evil.example\ttest-shop.myshopify.com
```

parses with no scheme/slash present, is prefixed with `https://`, and Addressable places the entire remainder — including the embedded tab and `evil.example` prefix — into `uri.host`. `uri.domain`, computed from the trailing dot-separated labels (`test-shop.myshopify.com` → registrable domain `myshopify.com`), matches a trusted domain, so `from_trusted_domain` is `true` and `unified_admin?` (`host.split(".").first == "admin"`) is `false` (first label is `evil.example` up to no dot boundary — still not `"admin"`). The method therefore returns `host` unmodified — the full string with the embedded control byte and the `evil.example` prefix — as a "sanitized" shop, and `sanitize!` accepts it without raising `Errors::InvalidShopError`.

This value then flows into `Clients::HttpClient#initialize` as `session.shop`, becoming `@base_uri` and the `Host` header verbatim [6](#0-5) , without any further re-validation. Whatever HTTP transport (`HTTParty`/`Net::HTTP`) does with a hostname containing an embedded control byte — truncate at the control byte when serializing the `Host` header, or perform DNS resolution on a mangled string — is unspecified/undefined behavior that the validator cannot vouch for: the string it "verified" (the trailing labels ending in `myshopify.com`) is not the string it returned and that ultimately gets used as the network destination and carries `X-Shopify-Access-Token` / refresh-token material in `ClientCredentials.client_credentials`, `RefreshToken.refresh_access_token`, and `TokenExchange.migrate_to_expiring_token`.

None of the existing guards catch this: `HmacValidator`, the `state` comparison, `JwtPayload`'s `aud` check, and `Context.setup?`/`private?`/`embedded?` are unrelated to this code path — they protect webhook/callback/session-token verification, not the shop-domain sanitizer used for outbound token requests. `ShopValidator.sanitize!` itself is the only guard on this path, and it is the exact function shown to diverge between its trust check and its return value.

### Impact Explanation
If the underlying HTTP/DNS handling of a control-byte-contaminated host string can be steered to an attacker-reachable endpoint (e.g., via truncation at the control byte during header serialization, or via inconsistent host parsing between the trust check and the actual socket connection), the attacker's server would receive the outbound request that `ClientCredentials.client_credentials`, `RefreshToken.refresh_access_token`, or `TokenExchange.migrate_to_expiring_token` send — including the app's `client_secret` and/or the merchant's refresh token in the request body/headers. This is repeatable against any shop string the caller can influence and matches the Critical category (theft of `client_secret`/refresh token) and the High category (SSRF driving an authenticated request to an unintended host) in the rules.

### Likelihood Explanation
Exploitability is contingent on how the underlying HTTP client (HTTParty/Net::HTTP) and OS resolver actually treat a hostname string containing an embedded control byte/tab at socket-connect time versus at header-serialization time — that behavior is outside this gem's code and was not verified against a live HTTP stack in this analysis. If the transport instead raises `URI::InvalidURIError`/`SocketError`/refuses to connect on such a malformed host (which is plausible for strict RFC-3986 URI construction via `URI()` in `HttpClient#request`), the divergence is caught downstream and no request leaves the process. The core logic flaw — validating `uri.domain` while returning the unrelated, unvalidated `uri.host` string — is real and demonstrable in `ShopValidator` in isolation regardless of what the transport does with the result.

### Recommendation
In `sanitize_shop_domain`, return the exact registrable-domain-validated projection instead of the raw `uri.host`: reject (return `nil`) if `uri.host` contains any character outside the RFC-1123 hostname character set (`a-z0-9.-`), and/or explicitly compare `host` for equality against `uri_domain`'s expected full hostname computed by re-composing from validated labels, instead of trusting `uri.host` verbatim once `uri.domain` matches.

require_relative "../test_helper"

module ShopifyAPITest
  module Utils
    class ShopValidatorControlByteTest < Test::Unit::TestCase
      def test_sanitize_rejects_or_fully_normalizes_control_byte_padded_shop
        malicious = "evil.example\ttest-shop.myshopify.com"

        result = begin
          ShopifyAPI::Utils::ShopValidator.sanitize!(malicious)
        rescue ShopifyAPI::Errors::InvalidShopError
          nil
        end

        # BINDING: sanitize! must either raise, or return a value that is
        # byte-for-byte identical to a clean myshopify.com host with no
        # extraneous prefix/control bytes.
        assert(result.nil? || result == "test-shop.myshopify.com",
          "sanitize! returned a contaminated host: #{result.inspect}")
      end

      def test_client_credentials_never_sends_secret_off_domain
        malicious = "evil.example\ttest-shop.myshopify.com"
        stub_request(:post, /.+/).to_return(status: 200, body: "{}")

        begin
          ShopifyAPI::Auth::Oauth::ClientCredentials.client_credentials(shop: malicious)
        rescue StandardError
          nil
        end

        # BINDING: no request containing client_secret should reach a host
        # other than *.myshopify.com
        assert_not_requested(:post, /evil\.example/)
      end
    end
  end
end
