### Title
Self-serve underage-detection escalation flag (`self_serve_ask_op_qr_for_possibly_underaged`) is defined but never enforced, allowing unsupervised self-serve signups by possibly-underaged persons - (File: `src/config.rs`, `src/plans/mod.rs`)

### Summary
The Peapods `spTKNMinimalOracle` bug is a case where an "advanced" combined configuration (podded pod + fraxlend pairing) is declared/expected to be supported but the code path that should handle that combination is simply absent, silently defeating the safety/pricing logic for that mode. The analogous pattern in orb-core is `Config::self_serve_ask_op_qr_for_possibly_underaged` — a config flag whose purpose ("Ask the operator for a QR code when a possibly underaged person is detected", and its companion timeout field) is fully wired into the config download/deserialization pipeline, but is never read or acted upon anywhere in the signup/fraud-enforcement flow.

### Finding Description
`Config` declares the field with an explicit safety purpose: [1](#0-0) 

It is populated from the backend response and given a default value, exactly like every other enforced flag (e.g. `self_serve_app_skip_capture_trigger`, which *is* consumed later): [2](#0-1) [3](#0-2) 

And the backend deserialization struct also carries it end-to-end: [4](#0-3) 

However, a repo-wide search for any consumer of `self_serve_ask_op_qr_for_possibly_underaged` (or its timeout counterpart) outside of `src/config.rs` and `src/backend/config.rs` returns nothing. In particular, the self-serve signup flow in `MasterPlan::run`, `idle_wait_for_signup_request`, `idle_scan_user_qr_code`, and `proceed_with_biometric_capture` destructure `Config` and use `self_serve`, `self_serve_button`, `self_serve_app_skip_capture_trigger`, etc., but never destructure or check `self_serve_ask_op_qr_for_possibly_underaged`: [5](#0-4) [6](#0-5) [7](#0-6) 

The person-classifier / underage-detection related config (`child_threshold`, `Underaged` pipeline feedback) exists on the fraud/pipeline side: [8](#0-7) [9](#0-8) 

and the relay protocol even defines the escalation message type intended for this feature: [10](#0-9) 

But nothing in `plans/mod.rs` (or elsewhere) ever constructs/sends an `AgeVerificationRequiredFromOperator` message gated by `self_serve_ask_op_qr_for_possibly_underaged`, nor does the self-serve idle/signup loop pause to request an operator QR code when the person classifier flags a possible minor. The "advanced" combined mode — self-serve signup + underage escalation to operator — is configured end-to-end but structurally unimplemented, mirroring the oracle bug where the `BASE_IS_POD && BASE_IS_FRAX_PAIR` combined configuration is declared possible (`LeverageManager._hasSelfLendingPairPod`) but has no corresponding branch in `_calculateSpTknPerBase`.

### Impact Explanation
If this flag is enabled by the backend/operator to require an operator's supervision/QR confirmation whenever the age classifier detects a possibly-underaged individual in self-serve mode, that safeguard is never triggered. This is a fraud/liveness-enforcement bypass: a minor could complete an unsupervised self-serve signup and enrollment without the intended human-in-the-loop escalation, defeating the age-verification control that the config option exists to provide. This falls squarely within "liveness/fraud enforcement" bypass impact accepted by the validation rules.

### Likelihood Explanation
The likelihood of this configuration actually being deployed and relied upon is uncertain from static analysis alone — it's possible the enforcement logic lives in another crate/binary not indexed here (e.g. within the mega-agent/person-classifier module, which may not be part of this repository's visible source), or the feature is simply unfinished/unshipped. Given the index size limits noted for this codebase, it's possible not all files (e.g. `agents/python/*` classifier consumers or `mega_agent_two` handling) were retrievable, so I cannot fully rule out that consumption exists in an unindexed file. This should be treated as a finding requiring confirmation via full source access (a Devin session with full repo access) rather than a fully proven bug.

### Recommendation
Confirm whether `self_serve_ask_op_qr_for_possibly_underaged` and its timeout are consumed anywhere in the full source tree (including files not covered by the current index). If they are not, wire the flag into the self-serve signup flow so that when the person/age classifier flags a possibly-underaged subject during self-serve capture, the orb pauses and requires an operator QR scan (sending `AgeVerificationRequiredFromOperator` over `orb_relay`) within `self_serve_ask_op_qr_for_possibly_underaged_timeout`, failing the signup if the operator does not confirm in time.

### Proof of Concept
Static analysis: `grep`/search across the indexed repository content for `self_serve_ask_op_qr_for_possibly_underaged` and `AgeVerificationRequiredFromOperator` shows matches only in `src/config.rs`, `src/backend/config.rs`, and the message-payload boilerplate in `orb-relay-client/src/lib.rs` — no call site in `src/plans/mod.rs` or any signup/fraud-detection code path invokes or checks this flag or sends the corresponding relay message.

    async fn idle_wait_for_signup_request(
        &mut self,
        orb: &mut Orb,
        qr_codes: &QrCodes,
        self_serve: bool,
        self_serve_button: bool,
        operator_qr_expiration_time: Duration,
    ) -> Result<Option<QrCodes>> {
        // We currently support 4 scenarios:
        // 1. Internal testing with a biometric input file.
        // 2. Self-serve mode that always scans for a user QR code.
        // 3. Self-serve mode that expects a button press to ask for a user QR code.
        // 4. Normal mode that expects a button press to ask for an operator QR code and then a user QR code.
        //
        // Scenarios 3 and 4 are handled by the same code path in the following last else-statement.
        let ui_idle_delay = self.ui_idle_delay.take();
        let qr_codes = if self.oneshot || self.has_biometric_input() {
            qr_codes.clone()
        } else if self_serve && !self_serve_button {
            orb.set_phase("User QR-code idle scanning").await;
            let QrCodes::Operator { operator_data } = &qr_codes else {
                panic!("operator QR code needs to be scanned beforehand in self-serve mode");
            };
            let Some((user_qr_code, user_data, user_qr_code_string)) = self
                .idle_scan_user_qr_code(
                    orb,
                    operator_data,
                    operator_qr_expiration_time,
                    ui_idle_delay,
                )
                .await?
            else {
                return Ok(None);
            };
            qr_codes.with_user_qr_code(user_qr_code, user_data, user_qr_code_string)
        } else {
            orb.set_phase("Idle waiting for button press").await;
            self.idle_wait_for_button_press(orb, ui_idle_delay).await?;
            orb.ui.signup_start_operator();
            qr_codes.clone()
        };
        Ok(Some(qr_codes))
    }

    async fn idle_scan_user_qr_code(
        &mut self,
        orb: &mut Orb,
        operator_data: &OperatorData,
        operator_qr_expiration_time: Duration,
        mut ui_idle_delay: Option<time::Sleep>,
    ) -> Result<Option<(qr_scan::user::Data, backend::user_status::UserData, String)>> {
        loop {
            orb.reset_rgb_camera().await?;
            match idle::Plan::with_user_qr_scan(
                ui_idle_delay.take(),
                Some(operator_qr_expiration_time.saturating_sub(operator_data.timestamp.elapsed())),
                #[cfg(feature = "internal-data-acquisition")]
                self.data_acquisition,
            )
            .run(orb)
            .await?
            {
                idle::Value::UserQrCode(qr_scan_result) => {
                    if !check_signup_conditions(orb).await? {
                        continue;
                    }
                    if let Some(Some((user_qr_code, user_data, user_qr_code_string))) =
                        self.handle_user_qr_code(qr_scan_result, orb, operator_data, None).await?
                    {
                        break Ok(Some((user_qr_code, user_data, user_qr_code_string)));
                    }
                }
                idle::Value::TimedOut => break Ok(None),
                idle::Value::ButtonPress => unreachable!(),
            }
        }

async fn proceed_with_biometric_capture(orb: &mut Orb) -> Result<bool> {
    let Config {
        self_serve,
        self_serve_app_skip_capture_trigger,
        self_serve_app_capture_trigger_timeout,
        ..
    } = *orb.config.lock().await;
    if !self_serve || self_serve_app_skip_capture_trigger {
        // Biometric capture not gated by a user action. Continue.
        orb.ui.signup_start();
        return Ok(true);
    }

    let orb_relay = orb.orb_relay.as_mut().expect("orb_relay to exist");

    tracing::info!("Waiting for self-serve biometric-capture trigger...");
    if let Err(e) = orb_relay
        .wait_for_msg::<self_serve::app::v1::StartCapture>(self_serve_app_capture_trigger_timeout)
        .await
    {
        if let Err(e) = orb_relay.send(self_serve::orb::v1::CaptureTriggerTimeout {}).await {
            tracing::warn!("failed to send CaptureTriggerTimeout: {e}");
        };
        orb.ui.signup_fail(SignupFailReason::Timeout);
        tracing::warn!("Self-serve biometric-capture start was not triggered: {e}");
        return Ok(false);
    };

    tracing::info!("Self-serve biometric-capture start triggered");
    orb.ui.signup_start();

    tracing::info!("Self-serve: Informing orb-relay that biometric_capture has started");
    orb_relay
        .send(self_serve::orb::v1::CaptureStarted {})
        .await
        .inspect_err(|e| tracing::error!("Relay: Failed to CaptureStarted: {e}"))?;

    Ok(true)
}
