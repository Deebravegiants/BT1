## Title
Stale `_requestCommitments` entry is never invalidated after a successful GET response delivery, allowing a subsequent timeout proof to be replayed against it — duplicate relayer-fee payout and conflicting `onGetResponse`/`onGetTimeout` callbacks delivered for the same request - ([File: evm/src/core/EvmHost.sol])

### Summary
`EvmHost.dispatchIncoming(GetResponse, ...)` pays the relayer fee out of `_requestCommitments[commitment]` on successful delivery but never deletes that entry [1](#0-0) . Because the commitment is left intact, the same request is still considered "known" by `HandlerV2.handleGetRequestTimeouts`, which only checks `meta.sender != 0` and a non-membership proof of the response-receipt key against a *chosen* stored state height — it never checks whether the EvmHost's own `_responseReceipts` mapping already recorded a delivery [2](#0-1) . Since old `StateMachineHeight` entries persist in `_stateCommitments` until explicitly vetoed, an attacker/relayer can pick a stale, already-stored height whose `timestamp` is past the request's `timeoutTimestamp` but predates the response actually being committed on the relay chain, and use it to prove "non-membership" even after the response has already been delivered on this host.

### Finding Description
The relevant state-machine is:

1. `EvmHost.dispatch(DispatchGet)` escrows the fee in `_requestCommitments[commitment]` [3](#0-2) .
2. When the response arrives, `HandlerV2.handleGetResponses` only guards against replay via `_responseReceipts`, and explicitly does **not** check the request's timeout locally ("don't check for timeouts because it's checked on Hyperbridge") [4](#0-3) . It calls `EvmHost.dispatchIncoming(GetResponse, relayer)`, which records `_responseReceipts[commitment]`, invokes `onGetResponse` on the destination module, and on success pays the fee out of `_requestCommitments[commitment].fee` — **without deleting `_requestCommitments[commitment]`** [1](#0-0) .
3. Independently, `HandlerV2.handleGetRequestTimeouts` re-derives `meta = host.requestCommitments(commitment)`, requires only `meta.sender != 0`, and verifies a Substrate non-membership proof for `RESPONSE_RECEIPTS_STORAGE_PREFIX || commitment` against a caller-supplied `StateMachineHeight` (`message.height`) whose only constraint is `request.timeout() <= state.timestamp` [2](#0-1) . It does not check the local `_responseReceipts` mapping on `EvmHost` at all, nor does it require `message.height` to be the *latest* known height — any previously stored, unvetoed height satisfying the timestamp inequality is accepted, because `_stateCommitments` retains every height submitted until an explicit veto/delete [5](#0-4) .
4. `EvmHost.dispatchTimeOut(GetRequestTimeout, meta, commitment)` then deletes `_requestCommitments[commitment]` (only restoring it if the module callback itself reverts), calls `onGetTimeout` on the module, and refunds the escrowed fee a second time to whichever relayer submits the timeout proof [6](#0-5) .

Because step 2 never frees (`delete`s) `_requestCommitments`, the resource that should be consumed exactly once after a successful delivery remains reachable and is "used after free" by step 3/4 — mirroring the CVE's use-after-free class where a resource that should have been invalidated stays accessible and is acted upon again, corrupting state and enabling privilege/asset abuse.

### Impact Explanation
- **Duplicate fee payout**: The same escrowed relayer fee (`_requestCommitments[commitment].fee`) is paid out once in `dispatchIncoming(GetResponse)` and a second time in `dispatchTimeOut(GetRequestTimeout)` for the identical commitment, directly draining the host's `feeToken` balance (theft of funds affecting other users' escrowed fees, since payouts come from the shared token pool held by `EvmHost`).
- **Conflicting application state**: Any `IApp` module built on this host (token bridge apps, intents/escrow modules such as `ExtrinsicIntents`) receives both a successful `onGetResponse` callback and a later `onGetTimeout` callback for the same logical request. Application logic that assumes these are mutually exclusive (e.g., releasing funds on success, refunding escrow on timeout) can be driven into an inconsistent state, enabling unbacked refunds/double-spend at the application layer.
- This satisfies "concrete theft ... of funds" and "unauthorized app action" impact classes reachable purely from a single relayed proof submission — no privileged role required.

### Likelihood Explanation
Both `handleGetResponses` and `handleGetRequestTimeouts` are fully permissionless entry points reachable by any relayer with a valid (even stale/historical) state proof [7](#0-6) . Since `_stateCommitments` heights are retained indefinitely absent an explicit veto, and GET responses are explicitly allowed to be delivered without a local timeout check (per the code comment), an attacker only needs to hold onto (or wait for) any state proof whose height/timestamp satisfies `request.timeout() <= state.timestamp` and predates the response's inclusion — a condition that will commonly exist given normal relay-chain finality lag. This makes exploitation practical for any relayer monitoring GET request/response pairs, not merely a theoretical race.

### Recommendation
- Delete `_requestCommitments[commitment]` in `EvmHost.dispatchIncoming(GetResponse, ...)` immediately upon a successful `onGetResponse` callback, mirroring the delete-then-restore-on-failure pattern already used in `dispatchTimeOut` [1](#0-0) .
- Additionally/defensively, have `dispatchTimeOut(GetRequestTimeout, ...)` and/or `HandlerV2.handleGetRequestTimeouts` check `_responseReceipts[commitment]` (or an equivalent "already delivered" flag) and revert if a response has already been recorded, regardless of which stale height's non-membership proof is presented.
- Consider requiring `message.height` in `handleGetRequestTimeouts` to be at least the latest verified height (or otherwise bound how "stale" an accepted non-membership proof may be) to close the historical-height replay window entirely.

### Proof of Concept
1. User dispatches a `GetRequest` via `EvmHost.dispatch(DispatchGet)`; fee is escrowed in `_requestCommitments[commitment]`.
2. Request's `timeoutTimestamp` elapses, but Hyperbridge still finishes computing the GET and a relayer submits `HandlerV2.handleGetResponses` — accepted because timeout isn't checked locally; `dispatchIncoming(GetResponse)` pays the fee to relayer A and calls the module's `onGetResponse`. `_requestCommitments[commitment]` is left intact.
3. Any relayer (A or B) collects an older, already-stored `StateMachineHeight` (satisfying `request.timeout() <= state.timestamp` but predating the response's commitment on the relay chain) and submits `HandlerV2.handleGetRequestTimeouts` with a non-membership proof for `RESPONSE_RECEIPTS_STORAGE_PREFIX || commitment` against that height.
4. `meta.sender != 0` check passes (commitment was never deleted), the stale non-membership proof verifies, `dispatchTimeOut(GetRequestTimeout, meta, commitment)` runs, calling `onGetTimeout` on the module and refunding the fee a second time — resulting in double payment and the module receiving both success and timeout callbacks for the same request.

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function handlePostRequests(IHost host, PostRequestMessage calldata request) external notFrozen(host) {
        uint256 timestamp = block.timestamp;
        uint256 delay = timestamp - host.stateMachineCommitmentUpdateTime(request.proof.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        uint256 requestsLen = request.requests.length;
        MerkleMountainRange.Leaf[] memory leaves = new MerkleMountainRange.Leaf[](requestsLen);

        for (uint256 i = 0; i < requestsLen; ++i) {
            PostRequestLeaf memory leaf = request.requests[i];
            // check destination
            if (!leaf.request.dest.equals(host.host())) revert InvalidMessageDestination();
            // check time-out
            if (timestamp >= leaf.request.timeout()) revert MessageTimedOut();
            leaves[i] = MerkleMountainRange.Leaf(leaf.index, leaf.request.hash());
        }

        bytes32 root = host.stateMachineCommitment(request.proof.height).overlayRoot;
        if (root == bytes32(0)) revert StateCommitmentNotFound();
        bool valid = MerkleMountainRange.VerifyProof(root, request.proof.multiproof, leaves, request.proof.leafCount);
        if (!valid) revert InvalidProof();

        for (uint256 i = 0; i < requestsLen; ++i) {
            PostRequestLeaf memory leaf = request.requests[i];
            // duplicate request?
            if (host.requestReceipts(leaf.request.hash()) != address(0)) revert DuplicateMessage();
            host.dispatchIncoming(leaf.request, _msgSender());
        }
    }

        uint256 timestamp = block.timestamp;
        uint256 delay = timestamp - host.stateMachineCommitmentUpdateTime(message.proof.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        uint256 responsesLength = message.responses.length;
        MerkleMountainRange.Leaf[] memory leaves = new MerkleMountainRange.Leaf[](responsesLength);

        for (uint256 i = 0; i < responsesLength; ++i) {
            GetResponseLeaf memory leaf = message.responses[i];

            // known request? also serves as source check
            FeeMetadata memory meta = host.requestCommitments(leaf.response.request.hash());

        if (root == bytes32(0)) revert StateCommitmentNotFound();

        if (!valid) revert InvalidProof();

            // duplicate response?
            if (host.responseReceipts(leaf.response.request.hash()).relayer != address(0)) revert DuplicateMessage();
            host.dispatchIncoming(leaf.response, _msgSender());
        }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
