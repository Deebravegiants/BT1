### Title
Bad-debt supply-index floor leaves phantom claims that drain fresh deposits - ([File: contracts/pool/src/interest.rs])

### Summary
When `clean_bad_debt` writes off bad debt equal to or exceeding total supplied value, `apply_bad_debt_to_supply_index` clamps `supply_index` to `SUPPLY_INDEX_FLOOR_RAW` instead of zeroing it. Every holder of scaled supply shares retains a non-zero floored claim. Any subsequent depositor's cash can then be withdrawn by the wiped-out holder — a proven theft in `contracts/pool/tests/interest.rs:317`.

### Finding Description
The bad-debt write-down computes `reduction_factor = remaining / total_supplied_value` and then applies `.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW))` to the result [1](#0-0) . On a full wipeout (`bad_debt >= total_supplied_value`), `remaining` is zero and `reduction_factor` is zero, but the floor clamp resurrects the index to a positive value. Since claims are `scaled_shares * supply_index` and shares are never burned, wiped-out suppliers keep a residual "phantom" claim.

The test `test_raw_cache_floor_residual_can_consume_fresh_cash_without_supply_guard` demonstrates the exploit end-to-end: after the floor clamp, user A's `scaled_a` still unscales to `stranded > 0`; when user B deposits `c`, A calls withdraw with `i128::MAX` and `resolve_withdrawal` pays out the phantom claim against B's fresh cash, emptying the pool [2](#0-1) . No supply-side solvency guard (`require_backed_market`) blocks the withdrawal on this path.

### Impact Explanation
Theft of user funds / protocol insolvency. The first honest depositor(s) after a bad-debt wipeout lose their deposit to legacy share holders whose positions should have been worth exactly zero. The pool's accounting cash is drained by claims with no backing.

### Likelihood Explanation
Requires a bad-debt cleanup reaching `bad_debt >= total_supplied_value` (a near-total wipeout), then any fresh supply deposit. `clean_bad_debt` and `withdraw` are both reachable by unprivileged addresses; the attacker is simply a pre-existing supplier whose shares survive. Conditional on a wipeout occurring, the drain is deterministic — whoever supplies first subsidizes the stranded claim.

### Recommendation
On full write-down, zero out the supply index semantics properly: either allow `supply_index` to reach zero and treat unscaling at zero index as zero claim, or burn/void scaled supply shares when the write-down saturates. Additionally run `require_backed_market` (or an equivalent backing check) on withdrawal/settlement paths so phantom claims cannot draw cash.

### Proof of Concept
See `contracts/pool/tests/interest.rs:317-369` (`test_raw_cache_floor_residual_can_consume_fresh_cash_without_supply_guard`):
1. Market has `supplied = scaled_a`, `supply_index = RAY`, `cash = 0`.
2. `apply_bad_debt_to_supply_index(cache, 2_000_000 * RAY)` (via `clean_bad_debt`) clamps `supply_index` to `SUPPLY_INDEX_FLOOR_RAW`.
3. `unscale_supply_floor(scaled_a)` still returns `stranded > 0`.
4. User B supplies `c = stranded` (minted at the floored index, honest claim = `c`).
5. User A calls `withdraw(i128::MAX)`; `resolve_withdrawal` returns `gross = c`, `require_reserves`/`debit_cash` pass, cash goes to 0.
6. B's claim `b_claim = c` is unbacked — B's funds are permanently stolen by A's wiped-out position.

#[test]
fn test_raw_cache_floor_residual_can_consume_fresh_cash_without_supply_guard() {
    let t = TestSetup::new();
    t.as_contract(|| {
        let scaled_a_raw = 1_000_000 * RAY;
        let mut cache = t.fresh_cache(PoolStateRaw {
            supplied: scaled_a_raw,
            borrowed: 0,
            revenue: 0,
            borrow_index: RAY,
            supply_index: RAY,
            last_timestamp: 0,
            cash: 0,
        });
        let scaled_a = Ray::from(scaled_a_raw);

        apply_bad_debt_to_supply_index(&mut cache, Ray::from(2_000_000 * RAY));
        assert_eq!(
            cache.supply_index().raw(),
            SUPPLY_INDEX_FLOOR_RAW,
            "wipeout must clamp supply index UP to the floor, not reset the base"
        );

        let stranded = cache.unscale_supply_floor(scaled_a);
        assert!(stranded > 0, "floor clamp leaves userA a phantom claim");
        assert_eq!(cache.cash(), 0, "empty market: no cash to extract yet");

        let c = stranded;
        let scaled_b = cache.calculate_scaled_supply(c);
        cache.mint_supply(scaled_b);
        cache.credit_cash(c);

        let b_claim = cache.unscale_supply_floor(scaled_b);
        assert_eq!(b_claim, c, "userB's honest claim equals their deposit");

        let (burn, gross) = cache.resolve_withdrawal(i128::MAX, scaled_a);
        cache.require_reserves(gross);
        cache.burn_supply(burn);
        cache.debit_cash(gross);

        assert!(gross > 0, "stranded position pays out non-zero");
        assert_eq!(
            gross, c,
            "userA drains exactly userB's fresh deposit out of the pool"
        );

        assert!(
            cache.cash() < b_claim,
            "pool cash ({}) can no longer cover userB's claim ({}): honest supplier lost funds",
            cache.cash(),
            b_claim
        );
        assert_eq!(cache.cash(), 0, "userA drained the pool to empty");
    });
