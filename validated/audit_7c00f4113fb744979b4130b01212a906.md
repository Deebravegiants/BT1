### Title
Durable nonce authority change does not advance the stored blockhash, permitting replay of a temporarily-invalidated signed transaction if authority is reverted - ([File: programs/system/src/system_instruction.rs])

### Summary
`AuthorizeNonceAccount` only mutates the nonce account's `authority` field and leaves `durable_nonce` untouched, while `AdvanceNonceAccount` is the only instruction that rotates the stored `durable_nonce` value. Because signature validity for a durable-nonce transaction is gated purely on `(stored durable_nonce == tx.recent_blockhash) && (signer == stored authority)`, a transaction that was pre-signed under authority A and rejected solely because the authority was changed to B can become valid again — with no re-signing — if the authority is later reverted back to A before the nonce is ever advanced. This mirrors the report's core defect: a signature that fails validation in one state can silently regain validity in a later state because the "reuse guard" (durable_nonce) was never actually consumed by the failed attempt.

### Finding Description
The nonce-authority check is implemented in `advance_nonce_account`, `authorize_nonce_account` (`programs/system/src/system_instruction.rs`), and validated for whole transactions in `TransactionBatchProcessor::validate_transaction_nonce` (`svm/src/transaction_processor.rs:833-892`) and `Bank::check_nonce_transaction_validity` (`runtime/src/bank/check_transactions.rs:258-284`).

Key facts:
- `authorize_nonce_account` (`programs/system/src/system_instruction.rs:213-249`) calls `Versions::authorize(signers, new_authority)` and writes back the resulting state. This call changes only the `authority` field of the nonce `Data`; the `durable_nonce` field is preserved (confirmed by the SVM integration test at `svm/tests/integration_test.rs:1941-1979`, batch 10, where after an authority change the `final_nonce_data` still uses the original `initial_durable` value, unchanged).
- `advance_nonce_account` (`programs/system/src/system_instruction.rs:25-78`) is the only path that rotates `durable_nonce` to `DurableNonce::from_blockhash(&environment_config.blockhash)`, and it requires `signers.contains(&data.authority)` (line 42) before doing so.
- Nonce transaction validation (`validate_transaction_nonce`, `svm/src/transaction_processor.rs:865-891`) requires the tx's `recent_blockhash` to equal the stored `durable_nonce`, AND that an ix-signer at the marker index equals the *current* `nonce_data.authority`. If the authority check fails, the whole transaction is rejected as `BlockhashNotFound` and the nonce state (including `durable_nonce`) is left completely untouched — the same behavior verified in `svm/tests/integration_test.rs:1941-1965` ("a nonce transaction that uses the nonce with the old authority; this transaction must be dropped").

Because a failed authority check never advances `durable_nonce`, the following sequence is possible:
1. Nonce account initialized with `authority = A`, `durable_nonce = X`.
2. User signs transaction T with `recent_blockhash = X`, signed by A.
3. Before T lands, authority is changed `A → B` via `AuthorizeNonceAccount` (legitimately, by a multisig rotation, or by an operator mistake). `durable_nonce` remains `X`.
4. T is submitted/rebroadcast; it fails validation (`authority mismatch`) and is dropped. No fee is charged, `durable_nonce` is not advanced — matches `svm/tests/integration_test.rs` batch 10 semantics.
5. The user, seeing the failure, believes T is permanently void.
6. Authority is later changed back `B → A` (e.g., the operator reverts a bad rotation, or the account is handed back).
7. `durable_nonce` is *still* `X`, unchanged since step 1. T (signed with A, recent_blockhash=X) is now fully valid again and can be replayed by anyone holding a copy of the previously "failed" transaction, executing it as if it were new.

This is the direct analog of the reported bug class: a signature that transiently fails validation due to an authority/key change is not permanently invalidated, and reverting the authority resurrects it, enabling unexpected execution of a transaction the signer/observer believed dead.

### Impact Explanation
This allows unintended execution of a transaction the account owner considered void, potentially transferring funds, changing account state, or executing arbitrary instructions the payer never intended to authorize a second time (e.g., double-spend of an intended one-time transfer, replay of a stale governance/administrative instruction). Impact is bounded by the instructions bundled in the pre-signed transaction and by how long the durable-nonce transaction is retained/leaked before replay, but the core protocol invariant — "each durable-nonce transaction is single-use because using it always advances the nonce" — is violated for the class of transactions rejected purely by an authority mismatch. This is not a validator/consensus-halting bug; it's an unprivileged-user-reachable value-transfer/replay hazard in the transaction validation and fee/nonce accounting path (`svm/src/transaction_processor.rs`, `runtime/src/bank/check_transactions.rs`).

### Likelihood Explanation
Requires a nonce-authority rotation to occur and later be reverted (or two authorities where control returns to a prior authority) while a previously signed but rejected durable-nonce transaction is retained by any observer (the tx creator, a bystander who saw it broadcast, or an attacker who intercepted it off-chain). Nonce-authority changes are a normal, supported operation (`AuthorizeNonceAccount`), and "revert to previous authority" is a realistic operational pattern (e.g., custody hand-off/hand-back, key-rotation rollback after an incident). No special validator privilege is needed to trigger or exploit it — any holder of the stale signed transaction can rebroadcast it.

### Recommendation
Short term: have `authorize_nonce_account` also rotate `durable_nonce` (e.g., re-derive from the current environment blockhash) whenever the authority changes, so that any signature built against the pre-change nonce value is permanently invalidated regardless of whether the authority is later reverted. Alternatively, track nonce-authority version/generation and require a matching generation as part of validation. Long term: add explicit unit/integration tests (extending the existing `svm/tests/integration_test.rs` nonce-authority-change batches) that specifically cover "authority changed then reverted to original" and assert that a transaction signed before the first change is *not* replayable after the revert.

### Proof of Concept
1. Create nonce account N with authority A, `durable_nonce = X` (via `InitializeNonceAccount`).
2. Sign transaction T = `[advance_nonce_account(N, A), transfer(...)]`, `recent_blockhash = X`, signer A. Do not submit yet.
3. Submit `authorize_nonce_account(N, A, B)` signed by A — authority becomes B, `durable_nonce` remains X.
4. Submit T — observe it is rejected with `TransactionError::BlockhashNotFound` (per `check_nonce_transaction_validity`/`validate_transaction_nonce`), and confirm via `get_nonce_blockhash` that `durable_nonce` is still X and no fee was charged (mirrors `runtime/src/bank/tests.rs::test_nonce_authority`, lines 4340-4391).
5. Submit `authorize_nonce_account(N, B, A)` signed by B — authority reverts to A; `durable_nonce` remains X (per the unchanged-durable-nonce behavior demonstrated in `svm/tests/integration_test.rs:1941-1979`).

pub fn advance_nonce_account(
    account: &mut BorrowedInstructionAccount,
    signers: &HashSet<Pubkey>,
    invoke_context: &InvokeContext,
) -> Result<(), InstructionError> {
    if !account.is_writable() {
        ic_msg!(
            invoke_context,
            "Advance nonce account: Account {} must be writeable",
            account.get_key()
        );
        return Err(InstructionError::InvalidArgument);
    }

    let state: Versions = account.get_state()?;
    match state.state() {
        State::Initialized(data) => {
            if !signers.contains(&data.authority) {
                ic_msg!(
                    invoke_context,
                    "Advance nonce account: Account {} must be a signer",
                    data.authority
                );
                return Err(InstructionError::MissingRequiredSignature);
            }
            let next_durable_nonce =
                DurableNonce::from_blockhash(&invoke_context.environment_config.blockhash);
            if data.durable_nonce == next_durable_nonce {
                ic_msg!(
                    invoke_context,
                    "Advance nonce account: nonce can only advance once per slot"
                );
                return Err(SystemError::NonceBlockhashNotExpired.into());
            }

            let new_data = nonce::state::Data::new(
                data.authority,
                next_durable_nonce,
                invoke_context
                    .environment_config
                    .blockhash_lamports_per_signature,
            );
            account.set_state(&Versions::new(State::Initialized(new_data)))
        }
        State::Uninitialized => {
            ic_msg!(
                invoke_context,
                "Advance nonce account: Account {} state is invalid",
                account.get_key()
            );
            Err(InstructionError::InvalidAccountData)
        }
    }
}

pub(crate) fn authorize_nonce_account(
    account: &mut BorrowedInstructionAccount,
    nonce_authority: &Pubkey,
    signers: &HashSet<Pubkey>,
    invoke_context: &InvokeContext,
) -> Result<(), InstructionError> {
    if !account.is_writable() {
        ic_msg!(
            invoke_context,
            "Authorize nonce account: Account {} must be writeable",
            account.get_key()
        );
        return Err(InstructionError::InvalidArgument);
    }
    match account
        .get_state::<Versions>()?
        .authorize(signers, *nonce_authority)
    {
        Ok(versions) => account.set_state(&versions),
        Err(AuthorizeNonceError::Uninitialized) => {
            ic_msg!(
                invoke_context,
                "Authorize nonce account: Account {} state is invalid",
                account.get_key()
            );
            Err(InstructionError::InvalidAccountData)
        }
        Err(AuthorizeNonceError::MissingRequiredSignature(account_authority)) => {
            ic_msg!(
                invoke_context,
                "Authorize nonce account: Account {} must sign",
                account_authority
            );
            Err(InstructionError::MissingRequiredSignature)
        }
    }
}

    fn validate_transaction_nonce<CB: TransactionProcessingCallback>(
        account_loader: &mut AccountLoader<CB>,
        message: &impl SVMMessage,
        nonce_address: &Pubkey,
        next_durable_nonce: &DurableNonce,
        next_lamports_per_signature: u64,
        strict_nonce_size_check: bool,
        error_counters: &mut TransactionErrorMetrics,
    ) -> TransactionResult<NonceInfo> {
        // When SIMD83 is enabled, if the nonce has been used in this batch already, we must drop
        // the transaction. This is the same as if it was used in different batches in the same slot.
        // It is possible that the nonce account was used, closed, closed and reopened, closed and
        // spoofed by a non-system program, or had its authority changed. Such a transaction cannot
        // be processed, even as fee-only.

        let Some(mut nonce_account) = account_loader
            .load_transaction_account(nonce_address, true)
            .map(|loaded| loaded.account)
        else {
            error_counters.account_not_found += 1;
            return Err(TransactionError::AccountNotFound);
        };

        if strict_nonce_size_check && nonce_account.data().len() != NonceState::size() {
            error_counters.blockhash_not_found += 1;
            return Err(TransactionError::BlockhashNotFound);
        }

        // This function verifies:
        // * Nonce account owner is SystemProgram
        // * Nonce account parses as State::Initialized
        // * Stored durable nonce matches the message blockhash
        let Some(nonce_data) = verify_nonce_account(&nonce_account, message.recent_blockhash())
        else {
            error_counters.blockhash_not_found += 1;
            return Err(TransactionError::BlockhashNotFound);
        };

        // We must still check that the nonce account is usable and that its authority has signed.
        let nonce_can_be_advanced = &nonce_data.durable_nonce != next_durable_nonce;
        let nonce_authority_is_valid = message
            .get_ix_signers(NONCED_TX_MARKER_IX_INDEX as usize)
            .any(|signer| signer == &nonce_data.authority);

        if nonce_can_be_advanced && nonce_authority_is_valid {
            let next_nonce_state = NonceState::new_initialized(
                &nonce_data.authority,
                *next_durable_nonce,
                next_lamports_per_signature,
            );
            nonce_account
                .set_state(&NonceVersions::new(next_nonce_state))
                .expect("Serializing into a validated nonce account cannot fail");

            Ok(NonceInfo::new(*nonce_address, nonce_account))
        } else {
            error_counters.blockhash_not_found += 1;
            Err(TransactionError::BlockhashNotFound)
        }
    }

    pub(super) fn check_nonce_transaction_validity(
        &self,
        message: &impl SVMMessage,
        next_durable_nonce: &DurableNonce,

        let nonce_is_advanceable = message.recent_blockhash() != next_durable_nonce.as_hash();

                .any(|signer| signer == &nonce_data.authority)
        {
            return None;
        }

        let previous_lamports_per_signature = nonce_data.get_lamports_per_signature();

        Some((nonce_address, previous_lamports_per_signature))
    }

#[test]
fn test_nonce_authority() {
    agave_logger::setup();
    let (mut bank, _mint_keypair, custodian_keypair, nonce_keypair, bank_forks) =
        setup_nonce_with_bank(10_000_000, |_| {}, 5_000_000, 250_000, None).unwrap();
    let alice_keypair = Keypair::new();
    let alice_pubkey = alice_keypair.pubkey();
    let custodian_pubkey = custodian_keypair.pubkey();
    let nonce_pubkey = nonce_keypair.pubkey();
    let bad_nonce_authority_keypair = Keypair::new();
    let bad_nonce_authority = bad_nonce_authority_keypair.pubkey();
    let custodian_account = bank.get_account(&custodian_pubkey).unwrap();

    debug!("alice: {alice_pubkey}");
    debug!("custodian: {custodian_pubkey}");
    debug!("nonce: {nonce_pubkey}");
    debug!("nonce account: {:?}", bank.get_account(&nonce_pubkey));
    debug!("cust: {custodian_account:?}");
    let nonce_hash = get_nonce_blockhash(&bank, &nonce_pubkey).unwrap();

    for _ in 0..MAX_RECENT_BLOCKHASHES + 1 {
        goto_end_of_slot(bank.clone());
        bank = new_from_parent_with_fork_next_slot(bank, bank_forks.as_ref());
    }

    let nonce_tx = Transaction::new_signed_with_payer(
        &[
            system_instruction::advance_nonce_account(&nonce_pubkey, &bad_nonce_authority),
            system_instruction::transfer(&custodian_pubkey, &alice_pubkey, 42),
        ],
        Some(&custodian_pubkey),
        &[&custodian_keypair, &bad_nonce_authority_keypair],
        nonce_hash,
    );
    debug!("{nonce_tx:?}");
    let initial_custodian_balance = custodian_account.lamports();
    assert_eq!(
        bank.process_transaction(&nonce_tx),
        Err(TransactionError::BlockhashNotFound),
    );
    /* Check fee was *not* charged and nonce has *not* advanced */
    let mut recent_message = nonce_tx.message;
    recent_message.recent_blockhash = bank.last_blockhash();
    assert_eq!(
        bank.get_balance(&custodian_pubkey),
        initial_custodian_balance
    );
    assert_eq!(
        nonce_hash,
        get_nonce_blockhash(&bank, &nonce_pubkey).unwrap()
    );
}
