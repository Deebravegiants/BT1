### Title
Uniswap V4 spot-price venue pricing (no TWAP) lets a same-block swap manipulate solver fill quotes for optionally-unguarded pairs - ([File: sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts])

### Summary
Simplex's "pool-based pricing" venue prices curveless cross-asset pairs directly from a Uniswap V4 pool's current tick (spot price), refreshed synchronously at quote time, with the only defense being an *optional* static-reference deviation guard that operators can simply omit. This mirrors the Elephant Money root cause: a price derived from a manipulable AMM state is fed directly into an economically consequential decision (there, TRUNK minting; here, the amount of output token the filler commits to hand an intent orderer) within the same window an attacker can move the pool.

### Finding Description
`UniswapV4FundingPlanner.getExoticTokenPrice` reads the *live* pool state on every quote (`await state.refresh()`) and returns `computeDirectPoolPriceUsd`, which is the raw pool mid derived from `sqrtPriceX96`/tick with no time-weighting: [1](#0-0) [2](#0-1) 

This spot price is consumed by `resolveLegRates` in the FX strategy to set the exchange rate for a curveless pair whose `token0` is a USD stable, and it is only rejected if a `checkPriceGuard` trips: [3](#0-2) 

The guard itself is optional per the documented design: `referencePrice`/`maxDeviationBps` "must be set together; omit both to leave the chain unguarded," and pool pricing is explicitly described as trusting "the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote": [4](#0-3) 

The flow doc confirms the price used is the raw mid with no fee-tier or size/impact adjustment and that the guard is the only defense on that path: [5](#0-4) 

This is structurally the same bug class as Elephant Money: a price read straight off an AMM's current reserves/tick — attacker-movable with a swap (flash-loanable if needed) — is used, unguarded or thinly guarded, to compute how many tokens the protocol/solver commits to pay out. In Elephant Money, the manipulated ELEPHANT price inflated TRUNK minted per BUSD deposited; here, a manipulated pool mid inflates the `rate` (`token1 per token0`) that `computeLegPolicyOutput` uses to size `policyMaxOutput` — the exact amount of the exotic token the filler will hand the orderer for a given stable input, computed via a straight linear multiplication with no slippage/impact term: [6](#0-5) 

### Impact Explanation
An attacker who can move a configured Uniswap V4 pool's tick (a normal swap, optionally flash-loan-funded for capital efficiency) immediately before/around triggering a fill on an unguarded (or loosely guarded) pair can cause the filler to quote and pay out based on the manipulated price, over-delivering the exotic token (or under-charging) relative to its true market value. Because pool pricing yields "a single price used in both directions" with margin coming only from `order.fees`, there is no bid/ask cushion to absorb the manipulation, and the linear extension of the mid across the whole leg notional (no impact term, as called out in the flow doc) means larger orders scale the loss proportionally. This is a direct drain of solver/filler funds reachable from a single order/intent plus an ordinary swap — fitting "concrete theft... via unsound state commitment" against the intents escrow/bid path.

### Likelihood Explanation
Likelihood is Medium: exploitability depends on (a) an operator configuring a curveless USD-stable pair funded purely by `[vault.uniswapV4]` without setting `referencePrice`/`maxDeviationBps` (explicitly permitted and even shown as the default example in the docs), and (b) the configured pool having liquidity thin enough, or the attacker having enough capital/flash-loan access, to move the tick meaningfully within the price-guard's tolerance window (or entirely absent when unguarded). Given the docs present the unguarded config as the baseline and only recommend the guard as an optional hardening step, misconfiguration is plausible in production deployments, and the attack requires only a standard DEX swap plus submitting/timing an intent order — no privileged access.

### Recommendation
- Make the deviation guard (`referencePrice`/`maxDeviationBps`) mandatory for any pair priced via `[vault.uniswapV4]`, rejecting startup validation if omitted, instead of allowing "unguarded" pool pricing.
- Replace or supplement the raw `sqrtPriceX96` spot read with a TWAP (time-weighted average) or multi-block observation window before using it as `venueUsd`.
- Apply a size/impact-aware price function (e.g., simulate the actual swap or apply a slippage curve) rather than a flat linear extension of the mid across the whole leg notional in `computeLegPolicyOutput`.

### Proof of Concept
1. Operator configures a curveless pair (e.g., `USDC/CNGN`) funded solely by a `[vault.uniswapV4]` position, omitting `referencePrice`/`maxDeviationBps` (a configuration explicitly shown as valid in the docs).
2. Attacker executes a swap against the underlying Uniswap V4 pool to push its tick/`sqrtPriceX96` so the exotic token appears cheaper (or richer) in USD than its true market value.
3. Attacker (or an accomplice) submits/wins a phantom/intent order on this pair while the tick remains skewed; `getExoticTokenPrice` → `resolveLegRates` → `computeLegPolicyOutput` computes `policyMaxOutput` off the skewed mid with no impact adjustment, and the filler commits to deliver an inflated amount of the exotic token for the stable input.
4. Attacker reverses the pool-skewing swap (recovering most of the capital, including via flash loan) once the fill executes, keeping the excess exotic tokens extracted from the filler.

	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}

	private computeDirectPoolPriceUsd(
		pos: HydratedV4Position,
		sdkPool: V4Pool,
		chain: string,
	): { exoticToken: string; priceUsd: Decimal } | null {
		const usdc = this.configService.getUsdcAsset(chain).toLowerCase()
		const usdt = this.configService.getUsdtAsset(chain).toLowerCase()
		const c0 = pos.currency0.toLowerCase()
		const c1 = pos.currency1.toLowerCase()

		if (c0 === usdc || c0 === usdt) {
			// currency0 is stable → exotic is currency1
			// token1Price = "token0 per token1" = USD per exotic
			return {
				exoticToken: c1,
				priceUsd: new Decimal(sdkPool.token1Price.toFixed(18)),
			}
		}

		if (c1 === usdc || c1 === usdt) {
			// currency1 is stable → exotic is currency0
			// token0Price = "token1 per token0" = USD per exotic
			return {
				exoticToken: c0,
				priceUsd: new Decimal(sdkPool.token0Price.toFixed(18)),
			}
		}

		return null
	}

	private computeLegPolicyOutput(
		inputAmount: bigint,
		inputIsToken0: boolean,
		token0Decimals: number,
		token1Decimals: number,
		/**
		 * Token0 left in the pair's per-order exposure budget, or `null` to price the whole
		 * input unbudgeted. Only a price probe passes `null`: it commits no capital, so there
		 * is no exposure to ration, and a clamped quantity would silently misprice it.
		 */
		remainingToken0: Decimal | null,
		rate: Decimal,
	): { token0Used: Decimal; policyMaxOutput: bigint } | null {
		let legMaxToken0: Decimal
		if (inputIsToken0) {
			legMaxToken0 = new Decimal(formatUnits(inputAmount, token0Decimals))
		} else {
			legMaxToken0 = new Decimal(formatUnits(inputAmount, token1Decimals)).div(rate)
		}

		const token0ForLeg = remainingToken0 === null ? legMaxToken0 : Decimal.min(legMaxToken0, remainingToken0)
		if (token0ForLeg.lte(0)) {
			return null
		}

		let policyMaxOutput: bigint
		if (inputIsToken0) {
			// Output is token1: convert the token0 allocation at the pair rate.
			policyMaxOutput = BigInt(
				token0ForLeg.mul(rate).mul(new Decimal(10).pow(token1Decimals)).floor().toFixed(0),
			)
		} else {
			// Output is token0: pay out the token0 equivalent of the token1 input.
			policyMaxOutput = BigInt(token0ForLeg.mul(new Decimal(10).pow(token0Decimals)).floor().toFixed(0))
		}

		return { token0Used: token0ForLeg, policyMaxOutput }

**File:** docs/content/developers/evm/simplex/pricing.mdx (L68-72)
```text
## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.
```

resolveLegRates(...)
  curveless pair && token0 is a USD stable
    -> venuePriceMemo() -> getVenueUsdPrice(chain, token1)
         -> UniswapV4FundingPlanner.getExoticTokenPrice
              picks the position with the largest pool liquidity
              -> computeDirectPoolPriceUsd -> sdkPool.token0Price / token1Price
    -> checkPriceGuard(...)   reject if outside maxDeviationBps of the static reference
    -> rate = 1 / venueUsd
  otherwise -> the pair's ask/bid curve at the leg's notional
```

`computeDirectPoolPriceUsd` returns the **raw pool mid** derived from `sqrtPriceX96`. The pool's
fee tier is read and stored on the hydrated position (`pos.fee`) but never applied to the price,
and there is no size or impact term — `computeLegPolicyOutput` extends the mid linearly across the
whole priced quantity. `checkPriceGuard` is the only defense on this path, and it checks deviation
from a static reference, not execution cost. A venue-priced pair that has to swap through its own
pool to source inventory pays a fee tier it never quoted against.
```
