### Title
`triggerGraduation` skips the anti-snipe launch delay based on an unenforced assumption, letting anyone force an irreversible, thin-liquidity graduation - ([File: packages/contracts/src/Bonding.sol])

### Summary
The GHSA-w3q8-m492-4pwp bug class is: a state-changing action checks that an object exists in a certain status but not that a *time-bound precondition* (the invitation's `invite_for` expiry) still holds, because a second code path to the same effect (password reset) relies on an *assumption* rather than an explicit check. `Bonding.triggerGraduation` reproduces exactly this pattern: `Bonding.buy` enforces the anti-snipe `LAUNCH_TRADING_DELAY_BLOCKS` gate via `_enforceLaunchDelay` before it can flip a token from `Curve` to `Graduating`, but `triggerGraduation` reaches the identical state transition (`_enterGraduating`) with no delay check at all, relying purely on a documented assumption that `canGraduate()` "is unreachable from a fresh launch within the delay window."

### Finding Description
`Bonding.buy` is gated by `_enforceLaunchDelay`, which reverts with `TradingNotOpen` for any caller other than the same-tx seed buy until `block.number > launchBlock + LAUNCH_TRADING_DELAY_BLOCKS`: [1](#0-0) 

`triggerGraduation`, however, is a **permissionless** entry point to the very same phase-1 transition (`_enterGraduating`) and performs no launch-delay check whatsoever - only a lifecycle/`canGraduate` check: [2](#0-1) 

The natspec on this function openly states the omission is intentional and rests on an assumption, not an enforced invariant: [3](#0-2) 

`canGraduate()` is a pure function of live pair reserves and the LT's live `exchangeRate()` — it is not itself time-gated: [4](#0-3) 

The only structural guard against `canGraduate()` becoming true immediately is that `graduationThresholdUsd_` must be `>= VIRTUAL_LIQUIDITY_USD` — it is **not** required to be strictly greater, and there is no minimum margin enforced beyond that: [5](#0-4) 

Combined with `exchangeRate()` being read live from an *external* BounceTech leveraged token (whose price can move independently of any trade on the curve — this is explicitly the "USD ripening" case the natspec itself calls out as reachable "with no intervening buy"), `canGraduate()` can flip true purely from LT price appreciation while the token is still inside its `LAUNCH_TRADING_DELAY_BLOCKS` window. In that state, any unprivileged address can call `triggerGraduation` and then the permissionless `finalizeGraduation` to push the token straight from `Curve` → `Graduating` → `Graduated`, entirely skipping the delay window that `_enforceLaunchDelay` exists to enforce for `buy`.

This is structurally identical to the devise_invitable defect: the primary path (`buy`) enforces the time gate before the sensitive transition; a second path to the same transition (`triggerGraduation`) omits the check and instead depends on an assumption about what states are reachable, which is not itself asserted or `require`d anywhere in the code.

### Impact Explanation
Once `_enterGraduating` fires, `TokenInfo.lifecycle` becomes `Graduating` and **both buys and sells are frozen** (`TokenIsGraduating`) for that token — permanently, since the lifecycle enum is documented as "strictly-forward": [6](#0-5) 

Because this can happen while the token is still inside the anti-snipe window (before the creator has had the chance to build out the curve beyond the mandatory `$20` `MIN_SEED_USDC` floor), `finalizeGraduation` will lock in a HyperSwap V2 LP sized off the thin, still-forming curve state and hand the LP tokens to `LPLock`, which has **no withdraw path in v1**: [7](#0-6) 

The creator's launch is thus irreversibly force-graduated into a minimal, permanently-locked liquidity pool before the anti-snipe delay's protective window elapses, defeating the entire purpose of `LAUNCH_TRADING_DELAY_BLOCKS`/`MIN_SEED_USDC` and permanently freezing the creator's ability to grow the curve — an unprivileged, permissionless griefing vector against any freshly-launched token whose paired LT experiences a price move (or whose `graduationThresholdUsd` is configured close to the `VIRTUAL_LIQUIDITY_USD` floor) in the first few blocks.

### Likelihood Explanation
`triggerGraduation` and `finalizeGraduation` are both explicitly permissionless and reachable by any address in a single transaction each, with no role check beyond the lifecycle/`canGraduate` gate. The precondition (an LT exchange-rate move sufficient to trip `canGraduate()` within `LAUNCH_TRADING_DELAY_BLOCKS = 3` blocks of launch, or a deployment where `graduationThresholdUsd` sits near the enforced minimum of `VIRTUAL_LIQUIDITY_USD`) depends on external market/config conditions rather than attacker-controlled state, so likelihood is bounded by how volatile the paired LT is and how the threshold is configured — but the code path itself is a straightforward, permissionless call with no additional obstacles once that precondition is met.

### Recommendation
Have `triggerGraduation` call `_enforceLaunchDelay(tokenAddress)` (or an equivalent explicit `require(block.number > launchBlock[tokenAddress] + LAUNCH_TRADING_DELAY_BLOCKS)`) before invoking `_enterGraduating`, mirroring the check already present in `Bonding.buy`, so the permissionless phase-1 trigger cannot fire during the anti-snipe window regardless of whether `canGraduate()` is assumed to be unreachable there.

### Proof of Concept
1. Deploy `Bonding` with `graduationThresholdUsd_` set at (or only marginally above) `VIRTUAL_LIQUIDITY_USD`, or select an LT known to be volatile.
2. Creator calls `Zap.createToken` with the mandatory `MIN_SEED_USDC` seed; `launchBlock[token]` is recorded and the token is inside `LAUNCH_TRADING_DELAY_BLOCKS`.
3. Within that window, the paired LT's `exchangeRate()` moves such that `canGraduate(token)` returns `true` purely from price appreciation (no buy needed), exactly the scenario the `triggerGraduation` natspec itself calls out (see `Bonding.sol` lines 955-969, `docs/contracts-scope.md` "no rate-only trigger... settled by the next buy" note).
4. Any unprivileged address calls `bonding.triggerGraduation(token)` — succeeds with no delay check (`test_triggerGraduation_succeedsWhenCanGraduate` in `test/Bonding.t.sol` already demonstrates this call succeeds for a `randomCaller` with no block-roll past the delay).
5. Any address then calls `bonding.finalizeGraduation(token)`, locking a thin LP into `LPLock` before the anti-snipe window has elapsed and before the creator could add further depth — permanently freezing the token's curve growth.

```text
    function canGraduate(
        address token_
    ) public view returns (bool) {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[token_];
        if (info.creator == address(0)) return false;
        if (info.lifecycle != Lifecycle.Curve) return false;

        address pair = info.pair;
        if (IPair(pair).tokenBalance() == 0) return true;

        (, uint256 assetReserve) = IPair(pair).getReserves();
        uint256 realLtRaised = assetReserve - _launchTimeVirtualLtReserve(token_, pair);
        uint256 valueUsd = (realLtRaised * IBounceLeveragedToken(info.ltAddress).exchangeRate()) / 1e18;
        return valueUsd >= $.graduationThresholdUsd;
    }
```
