## Title
Sensitive credentials in nested GraphQL request bodies are logged in plaintext due to shallow top-level-only redaction - (File: core/web/router.go)

## Summary
The `loggerFunc` middleware, registered globally via `engine.Use(...)` [1](#0-0) , logs every request body at Debug level using `readBody`/`readSanitizedJSON`, which only redacts top-level JSON keys against a small hardcoded blacklist [2](#0-1) . Since the GraphQL endpoint (`POST /query`), which is subject to the same middleware [3](#0-2) , always nests client-supplied sensitive fields (e.g. `variables.input.password`) one level below the top-level `variables` key, this redaction logic never catches them, and plaintext credentials get written to logs whenever Debug-level logging is enabled.

## Finding Description
The code exactly matches the claim: `loggerFunc` reads the raw body, calls `c.Next()`, then emits a `Debugw` log line including `"body", readBody(rdr, lggr)` [4](#0-3) . `readBody` delegates to `readSanitizedJSON`, which unmarshals into a flat `map[string]any` and only checks the top-level key against `isBlacklisted` (`password`, `newpassword`, `oldpassword`, `current_password`, `new_account_password`, or substring `"password"`) [2](#0-1) . There is no recursion into nested maps/arrays, confirmed by the direct `for k, v := range dst` loop with no nested handling. Because GraphQL bodies are always `{"query": "...", "variables": {...}}`, and sensitive fields like a login/change-password/`createAPIToken` password live inside `variables.input.password` (as shown by test fixtures constructing this exact shape) [5](#0-4) , `isBlacklisted("variables")` returns `false` and the entire nested payload including the plaintext password is preserved and logged.

## Impact Explanation
This is a real, confirmed logic bug: an unprivileged or malicious client's plaintext password (from login attempts, password changes, or API token creation) can end up recorded in the node's logs, which if exposed (log aggregation, misconfigured shipping, support access) would let an attacker recover operator credentials, potentially leading to account/session takeover and downstream node management actions. This maps to a legitimate credential/secret disclosure impact class.

## Likelihood Explanation
The exploit path itself requires no special privileges — any client can send a normal GraphQL mutation — but the actual precondition for the log record to exist is that the node operator has explicitly set `Log.Level = 'debug'`. The default log level, confirmed from `docs/CONFIG.md` and `core/web/resolver/testdata/config-empty-effective.toml`, is `'info'`, not `'debug'` [6](#0-5) . At the default `info` level, `lggr.Debugw` calls do not get written to logs at all, so this bug is dormant unless an operator opts into verbose/debug logging (a realistic but non-default operational configuration, e.g. for troubleshooting). This is a genuine defense-in-depth/logging-hygiene gap rather than a directly and unconditionally exploitable disclosure under default node configuration.

## Recommendation
Make `readSanitizedJSON` recursively walk nested JSON objects/arrays and redact blacklisted keys at any depth. Additionally, consider redacting the entire `variables` payload by default for the `/query` GraphQL endpoint, or maintain an explicit recursively-applied denylist covering GraphQL input field names (`password`, `secret`, `token`, `newPassword`, `oldPassword`, `accessKey`, etc.).

## Proof of Concept
1. Configure a Chainlink node with `Log.Level = 'debug'` in `config.toml`.
2. Send `POST /query` with body:
```json
{"query":"mutation($input: CreateAPITokenInput!){ createAPIToken(input:$input){ ... on CreateAPITokenSuccess { token { accessKey secret } } } }","variables":{"input":{"password":"SuperSecretAdminPass123"}}}
```
3. Observe the resulting `Debugw` log line from `loggerFunc` — the `body` field contains the full nested JSON including `"password":"SuperSecretAdminPass123"` in cleartext, since `readSanitizedJSON` only redacts the top-level keys `query` and `variables`, not the nested `password` field.

func readSanitizedJSON(buf *bytes.Buffer) (string, error) {
	var dst map[string]any
	err := json.Unmarshal(buf.Bytes(), &dst)
	if err != nil {
		return "", err
	}

	cleaned := map[string]any{}
	for k, v := range dst {
		if isBlacklisted(k) {
			cleaned[k] = "*REDACTED*"
			continue
		}
		cleaned[k] = v
	}

	b, err := json.Marshal(cleaned)
	if err != nil {
		return "", err
	}
	return string(b), err
}

func redact(values url.Values) string {
	cleaned := url.Values{}
	for k, v := range values {
		if isBlacklisted(k) {
			cleaned[k] = []string{"REDACTED"}
			continue
		}
		cleaned[k] = v
	}
	return cleaned.Encode()
}

// NOTE: keys must be in lowercase for case insensitive match
var blacklist = map[string]struct{}{
	"password":             {},
	"newpassword":          {},
	"oldpassword":          {},
	"current_password":     {},
	"new_account_password": {},
}

func isBlacklisted(k string) bool {
	lk := strings.ToLower(k)
	if _, ok := blacklist[lk]; ok || strings.Contains(lk, "password") {
		return true
	}
	return false
}
