Audit Report

## Title
Unauthenticated LOOP plugin pprof/metrics proxy with unsanitized path forwarding enables internal endpoint traversal - (File: core/web/loop_registry.go)

## Summary
`loopRoutes` is registered on the `api` gin group in `NewRouter` with only rate-limiting and session middleware attached, and it is never wrapped in `auth.Authenticate(...)` the way `debugRoutes` explicitly is. This exposes `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` to any unauthenticated caller, and `pluginPPROFHandler` further concatenates the unsanitized wildcard `gc.Param("profile")` directly into the proxied internal URL via `fmt.Sprintf`, without any validation or cleaning.

## Finding Description
`NewRouter` builds the `api` gin group with only rate limiting and a cookie session middleware attached, then calls `loopRoutes(app, api)` with no auth wrapper: [1](#0-0) 

In contrast, `debugRoutes` — registered in the same function, on the same `api` group — explicitly requires `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)`: [2](#0-1) 

`loopRoutes` itself registers the plugin discovery, metrics, and pprof endpoints with no such wrapper: [3](#0-2) 

`pluginPPROFHandler` takes `gc.Param("profile")` — the gin wildcard capture from the `*profile` route segment — and concatenates it directly into the outbound proxy URL string with no path cleaning, allow-listing, or traversal rejection: [4](#0-3) 

`pluginMetricHandler` has the analogous issue for the `/metrics` path, also reachable without authentication: [5](#0-4) 

Because gin's engine matches on `c.Request.URL.Path` without normalizing dot-segments the way an HTTP proxy or `filepath.Clean` would, and because the resulting string is passed straight into `http.NewRequestWithContext` without any `path.Clean`/allow-list check, an attacker-controlled wildcard value flows unsanitized into a server-side outbound request to the internal LOOP plugin listener (`loopHostName:PrometheusPort`).

## Impact Explanation
This maps to an in-scope information-disclosure/authentication-bypass class: any unauthenticated network client reaching the node's HTTP API can pull full Go `pprof` profiles (`goroutine`, `heap`, `cmdline`, `trace`, etc.) and Prometheus metrics from registered LOOP plugins without any session, cookie, or API key — none of the existing session/auth middleware in `router.go` applies to this route group, unlike every comparable debug/admin surface (`debugRoutes`). This is a genuine broken-security-assumption bug: sensitive introspection endpoints assumed to require authentication are reachable by anyone with network access to the node's web port. The unsanitized `profile` wildcard concatenation additionally allows attempts to pivot the proxied request to other paths on the internal plugin listener, compounding the exposure, though the practical blast radius of that secondary issue is limited to whatever the internal LOOP plugin process itself exposes over HTTP.

## Likelihood Explanation
Exploitation requires nothing beyond network reachability to the node's web server and requires at least one LOOP plugin registered in `plugins.LoopRegistry` (a supported, non-test production feature used for LOOPP-based plugins such as Mercury/Median). No credentials, session, or elevated role is needed — a single unauthenticated `GET /plugins/<name>/debug/pprof/goroutine?debug=2` is sufficient, since the code path shows no auth check exists between the gin group definition and the handler invocation.

## Recommendation
- Wrap `loopRoutes` (or at minimum `pluginMetricHandler`, `pluginPPROFHandler`, `pluginPPROFPOSTSymbolHandler`) with `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)` and appropriate role checks, matching the pattern already used for `debugRoutes`.
- Validate/allow-list `gc.Param("profile")` before use (e.g., restrict to known pprof sub-paths such as `profile`, `heap`, `goroutine`, `block`, `mutex`, `threadcreate`, `trace`, `cmdline`) instead of directly concatenating it into the proxied URL, and reject values containing `..` or encoded traversal sequences.

## Proof of Concept
1. Start a chainlink node with the web server reachable and at least one LOOP plugin registered (e.g., a Mercury/Median LOOPP plugin) so `plugins.LoopRegistry` has an entry for `<name>`.
2. Without any session cookie or API token, send:
   `GET /plugins/<name>/debug/pprof/goroutine?debug=2`
   Observe the request is routed straight to `pluginPPROFHandler` (`core/web/loop_registry.go:150-166`) and full pprof data is returned, confirming no auth middleware is applied per the route registration in `core/web/router.go:230-236` compared to `debugRoutes` at `core/web/router.go:180-183`.
3. Send `GET /plugins/<name>/debug/pprof/../otherpath` and observe the literal wildcard value is concatenated into `http://<loopHostName>:<PrometheusPort>/debug/pprof/../otherpath` (`core/web/loop_registry.go:159`), demonstrating the lack of path sanitization before the internal proxy request is issued.

func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/metrics", l.loopHostName, p.EnvCfg.PrometheusPort)
	req, err := http.NewRequestWithContext(gc.Request.Context(), http.MethodGet, pluginURL, nil)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)
	if err != nil {
		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q metrics", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
