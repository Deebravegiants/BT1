### Title
`CallDispatcher.dispatch` has no access control, letting anyone drain tokens/ETH left in the shared dispatcher used by `IntentGatewayV2` - ([File: evm/src/utils/CallDispatcher.sol])

### Summary
The Convex/Aura report shows that a "claim"-style function meant to be invoked only as part of a coordinated internal flow is instead world-callable, letting an outsider desynchronize a before/after balance accounting scheme and steal or corrupt funds that were meant to flow through that accounting. The Hyperbridge analog is `CallDispatcher.dispatch`, the function `IntentGatewayV2.placeOrder` relies on to stage and sweep user tokens through a single shared dispatcher contract. `dispatch` is a plain `external` function with no caller restriction, and `IntentGatewayV2` treats the dispatcher's balance as if it were exclusively under the gateway's control during its predispatch/sweep sequence.

### Finding Description
`CallDispatcher.dispatch` executes arbitrary `Call[]` (`to.call{value: call.value}(call.data)`) using the dispatcher contract's own identity and balance, with no `onlyGateway`/ownership check whatsoever: [1](#0-0) 

`IntentGatewayV2.placeOrder` treats this shared, singleton contract (`_params.dispatcher`) as a private staging area during predispatch flows: it directs user funds to the dispatcher, executes `order.predispatch.call` through it, then snapshots the dispatcher's per-token/ETH balance ("before"), issues a second `dispatch` call to sweep the dispatcher's full balance back to the gateway, and finally measures the "after" delta on the gateway side to determine `order.inputs[i].amount` — the amount that becomes the on-chain escrow commitment for the order: [2](#0-1) 

The sweep call transfers whatever `IERC20(token).balanceOf(dispatcher)` happens to be at that moment (line 274) — the entire balance, not a value scoped to this particular order. Because `dispatch` is public and unauthenticated, and the dispatcher is a single shared contract reused by every `placeOrder` call across every user, any residual balance sitting in the dispatcher (e.g., leftover from an imperfect predispatch swap that produces a token not enumerated in `order.predispatch.assets`, dust from slippage, or tokens mistakenly/directly sent to the dispatcher's publicly-known address, which also has a permissive `receive()`) is not protected. Anyone can call `dispatch` directly, before a legitimate `placeOrder` transaction lands, with a `Call` that transfers the dispatcher's current balance of any ERC20/ETH to themselves — exactly as an attacker can call Convex/Aura's `getReward` directly to intercept funds a victim contract's before/after accounting expected to receive.

### Impact Explanation
This breaks the invariant `IntentGatewayV2` depends on — that the dispatcher's balance during the predispatch window is attributable only to the in-flight order. An attacker can:
- Permissionlessly sweep any token/ETH dust that accumulates in the shared `CallDispatcher` (theft of funds that should have flowed back to the gateway/order escrow or been refunded as `DustCollected`).
- Race a specific user's `placeOrder` predispatch flow: if a predispatch call ever leaves the dispatcher non-empty for a token that a subsequent legitimate order also touches, an attacker's `dispatch` call can zero out that balance right before the gateway's own sweep step reads it, causing `order.inputs[i].amount` to be computed as less than the amount actually escrowed/expected — corrupting the commitment hash and the amount solvers are supposed to match, mirroring how the Convex bug caused `LiquidationRow._increaseBalance` to receive a wrong, understated amount.

This is a direct, unauthenticated funds-extraction and accounting-corruption vector on the intent escrow path, reachable from a single externally submitted transaction.

### Likelihood Explanation
`dispatch` is a bare `external` function with zero access control — no modifier, no `msg.sender` check — so exploitation requires nothing more than knowing the deployed `CallDispatcher` address (readable from `IntentGatewayV2.params()`) and crafting a `Call[]` payload. The dispatcher is a long-lived, address-stable, shared component reused across all `placeOrder` invocations with predispatch calldata, so any transient balance it holds is a standing target, not a narrow one-block race.

### Recommendation
Restrict `CallDispatcher.dispatch` to only be callable by the authorized gateway (`onlyGateway`/`onlyOwner` modifier set at deployment), or make the dispatcher a per-order ephemeral contract instead of a shared singleton. Additionally, `IntentGatewayV2` should not rely on reading the dispatcher's *total* balance (`balanceOf(dispatcher)`) as the "before/after" basis for crediting an order — it should scope the sweep to amounts explicitly attributable to the specific predispatch call in the current transaction, so no permissionless third-party interaction with the dispatcher can influence the escrowed amount.

### Proof of Concept
1. Observe (via `IntentGatewayV2.params()`) that all orders share one `CallDispatcher` instance. [3](#0-2) 
2. Note `CallDispatcher.dispatch` has no caller restriction: `function dispatch(bytes memory encoded) external { ... }`. [4](#0-3) 
3. Whenever the dispatcher ends a `placeOrder` predispatch flow holding any non-zero balance of a token/ETH not fully swept by `transferCalls` (e.g., a token produced as a side effect of the predispatch call but not enumerated in `order.inputs`), an attacker submits their own transaction calling `dispatch` with a `Call{to: token, data: transfer(attacker, balance)}` (or, for ETH, `Call{to: attacker, value: address(dispatcher).balance}`), draining the balance before any legitimate order can claim or sweep it.
4. Because `dispatch` performs no ownership/order-linkage check, the transfer succeeds unconditionally, confirming the shared dispatcher's assets are not protected against arbitrary third-party calls — the same "anyone can call the privileged claim/sweep function" bug class as the referenced Convex/Aura `getReward` report.

            Call memory call = calls[i];

            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
