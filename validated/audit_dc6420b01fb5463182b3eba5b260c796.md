### Title
`IntentGatewayV2.authenticate` accepts forged withdrawal requests from any unregistered source chain due to a zero-default same-origin check - (File: evm/tron/contracts/apps/IntentGatewayV2.sol)

### Summary
`IntentGatewayV2` (Tron variant) authenticates incoming `RedeemEscrow`/`RefundEscrow` requests by comparing the claimed sender module against the registered peer instance for the request's source chain. When no peer instance is registered for that source chain, `instance()` silently falls back to `address(this)` instead of rejecting the source, collapsing the "same-origin" check into a value an attacker fully controls.

### Finding Description
`instance()` is defined as: [1](#0-0) 

and is used directly for authentication in `authenticate()`: [2](#0-1) 

For any `request.source` (state machine) that has never had a `NewDeployment` registered in `_instances`, `instance(request.source)` returns `address(this)` — the local gateway's own address — instead of reverting. `authenticate()` then only checks that `request.from == instance(request.source)`. An attacker who can get a POST request delivered to this contract with `request.source` set to an unregistered/unsupported chain, and `request.from` set to bytes20 of this contract's own address (a value known publicly, especially since IntentGateway deployments are CREATE2-based to a consistent address across chains), passes authentication as if it came from a legitimate registered peer.

This is directly analogous to CVE-2018-4117: a same-origin verification mechanism that is supposed to reject unverified/foreign origins instead silently treats an unrecognized origin as trusted (in WebKit's case via a fetch-API logic flaw; here via a zero-address fallback that maps to the local contract's own identity, `address(this)`, rather than an explicit rejection).

For comparison, the primary EVM `IntentsBase._instance()` used by `evm/src/apps/intentsv2/IntentsBase.sol` explicitly reverts with `UnknownInstance` when no gateway is registered: [3](#0-2) 
The Tron variant's silent fallback removes this rejection.

`authenticate()` gates the withdrawal path in `onAccept`: [4](#0-3) 

which calls `withdraw()`, directly releasing escrowed tokens to an attacker-chosen beneficiary: [5](#0-4) 

### Impact Explanation
An attacker who can get Hyperbridge to deliver a POST request whose `source` is any state machine not present in `_instances` (e.g. a chain the deployer never registered a peer gateway for, or one intentionally left unconfigured), with `from` forged to the local gateway's own address, can call `RedeemEscrow`/`RefundEscrow` and drain escrowed order funds (`_orders[commitment][token]`) to an arbitrary beneficiary, provided a matching `UnknownOrder` check (`_orders[commitment][token] != 0`) is satisfiable — i.e., against real, filled escrow balances tied to legitimate orders. This is a direct theft-of-funds vector reachable by delivering a single crafted cross-chain message, satisfying the "concrete theft of funds" bar.

### Likelihood Explanation
Exploitability depends on whether an attacker can cause a request with an unregistered `source` state machine to reach `onAccept` — this requires either (a) a state machine Hyperbridge has a consensus client for but for which the gateway operator never called `NewDeployment`, or (b) any chain whose real IntentGateway address differs from the CREATE2-predicted address so it never got registered. Given IntentGatewayV2 is deployed via CREATE2 for deterministic cross-chain addressing, an attacker deploying a malicious contract at the predicted address on an unregistered/low-security chain that Hyperbridge nonetheless relays for is a realistic and low-cost path, making this a medium-to-high likelihood issue on any deployment that leaves `_instances` incomplete.

### Recommendation
Change `instance()` (or the check in `authenticate()`) to revert (e.g. `UnknownInstance`) when `_instances[keccak256(stateMachineId)] == address(0)`, matching the pattern already used in `IntentsBase._instance()`. Never let missing state resolve to `address(this)` for authentication purposes.

### Proof of Concept
1. Deploy or identify an unregistered state machine `X` for which the gateway operator never called `_addDeployment`/`NewDeployment` (so `_instances[keccak256(X)] == address(0)`).
2. Get Hyperbridge to deliver a `PostRequest` to the target `IntentGatewayV2` with:
   - `source = X`
   - `from = abi.encodePacked(address(intentGatewayV2))` (the local contract's own address)
   - `body[0] = RequestKind.RedeemEscrow`, `body[1:] = abi.encode(WithdrawalRequest{commitment: <existing filled order commitment>, tokens: <escrowed tokens>, beneficiary: <attacker>})`
3. `onAccept` calls `authenticate(request)` → `instance(X)` returns `address(this)` (no entry registered) → equals `module` (attacker-supplied `from`) → check passes.
4. `withdraw()` executes, transferring escrowed tokens to the attacker-controlled `beneficiary`.

Note: I was unable to fully verify from the index whether any production deployment actually leaves a reachable state machine unregistered in `_instances` while Hyperbridge still relays messages claiming that `source` — this depends on deployment/governance configuration not visible in the indexed code. A Devin session with full repository and deployment-script access would be needed to confirm live exploitability across deployed chains.

```text
    function authenticate(PostRequest calldata request) internal view {
        if (request.from.length != 20) revert InvalidInput();
        address module = address(bytes20(request.from));
        // IntentGateway only accepts incoming assets from itself or known instances
        if (instance(request.source) != module) revert Unauthorized();
    }
```

```text
    function withdraw(WithdrawalRequest memory body, bool isRefund) internal {
        address beneficiary = address(uint160(uint256(body.beneficiary)));
        _filled[body.commitment] = beneficiary;

        // redeem escrowed tokens
        uint256 len = body.tokens.length;
        for (uint256 i; i < len;) {
            address token = address(uint160(uint256(body.tokens[i].token)));
            uint256 amount = body.tokens[i].amount;
            if (_orders[body.commitment][token] == 0) revert UnknownOrder();

            if (token == address(0)) {
                (bool sent,) = beneficiary.call{value: amount}("");
                if (!sent) revert InsufficientNativeToken();
            } else {
                (bool success,) = token.call(abi.encodeWithSelector(IERC20.transfer.selector, beneficiary, amount));
                if (!success) revert TransferFailed();
            }

            _orders[body.commitment][token] -= amount;
            unchecked {
                ++i;
            }
        }

        // redeem tx fees
        uint256 fees = _orders[body.commitment][TRANSACTION_FEES];
        if (fees > 0) {
            address feeToken = IDispatcher(host()).feeToken();
            (bool success,) = feeToken.call(abi.encodeWithSelector(IERC20.transfer.selector, beneficiary, fees));
            if (!success) revert TransferFailed();
            delete _orders[body.commitment][TRANSACTION_FEES];
        }

        if (isRefund) {
            emit EscrowRefunded({commitment: body.commitment});
        } else {
            emit EscrowReleased({commitment: body.commitment});
        }
    }
```
