### Title
Overfill clamp disabled + unbounded static-reference price guard lets a manipulated Uniswap V4 pool price drain solver funds via `IntentGateway` fills - (File: `sdk/packages/simplex/src/strategies/fx.ts`)

### Summary
`FXFiller` prices curve-less pairs directly off the live Uniswap V4 pool mid (`sqrtPriceX96`) with no TWAP, no size/impact term, and — since the overfill clamp is explicitly disabled — no ceiling on the resulting payout. The only defense is `checkPriceGuard`, an optional, static-reference deviation check that is off entirely unless an operator configures `referencePrice`/`maxDeviationBps`, and even when configured only bounds deviation from a stale number, not real execution cost. This mirrors the Cascade incident's bug class: an attacker moves a thin market's price, an unprivileged actor (any user submitting an `IntentGateway` order) then trades against the mispriced venue, and the counterparty (here, the solver's own vault/LP position) suffers the loss.

### Finding Description
`resolveLegRates` venue-prices any curve-less pair whose `token0` is a USD stable by reading the raw Uniswap V4 pool mid: [1](#0-0) 

The mid price comes straight from `computeDirectPoolPriceUsd`, derived from `sdkPool.token0Price`/`token1Price` (i.e. `sqrtPriceX96`), with the pool's fee tier read but never applied and no depth/impact term: [2](#0-1) [3](#0-2) 

This is a documented, known-risk path in the codebase itself: [4](#0-3) 

The single mitigation, `checkPriceGuard`, is optional per-chain and simply compares the live quote to a static configured reference: [5](#0-4) 

Per the docs, if `referencePrice`/`maxDeviationBps` are omitted the chain is "left unguarded" entirely: [6](#0-5) 

Even when this guard is set, it only bounds deviation from the operator's last-set number — not the trade's actual on-chain execution cost — so an attacker only needs to keep the manipulated price inside `maxDeviationBps` of that stale reference to have the venue price accepted.

Critically, the per-leg overfill clamp that would otherwise cap a mispriced payout has been deliberately disabled, with the code comment explicitly calling out the venue-price-manipulation scenario it used to defend against: [7](#0-6) 

The unclamped `policyMaxOutput` becomes `targetOutput`, which the filler pays out of its own wallet plus funding-venue withdrawals (the same manipulated V4 pool position it prices from): [8](#0-7) 

### Impact Explanation
An attacker who can move the price of a thin Uniswap V4 pool that a Simplex solver uses for venue pricing (exactly the "accumulate a position to move a low-liquidity market" pattern from the Cascade report) can:
1. Manipulate the pool's `sqrtPriceX96` mid within the (optional, static) `maxDeviationBps` band.
2. Submit (or have selected) an `IntentGateway` order that the solver fills at that manipulated rate.
3. Because the overfill clamp is disabled, the solver pays out `policyMaxOutput` computed from the manipulated mid with no ceiling relative to what the user actually requested, funding it in part by withdrawing liquidity from its own manipulated V4 position.

This is concrete theft of solver/LP funds through a legitimate, unprivileged transaction path (placing/filling an intent order) — the same bug class (external price manipulation → mispriced settlement → drained funds) as the Cascade incident, just against Hyperbridge's intent-solver vault liquidity instead of a perp vault.

### Likelihood Explanation
- No privileged access is required: any address can place an order and move a pool the solver has configured for venue pricing.
- The price guard is optional (undocumented as required) and, even configured, only checks distance from a stale operator-set number, not manipulation resistance.
- The overfill clamp — the one mechanism explicitly documented as protecting against "a manipulated venue price" — has been intentionally turned off (warn-only), per the comment at `fx.ts:678-701`.
- Thin/low-liquidity exotic-token pools (e.g. cNGN/USDC, as used in the shipped configs and tests) are realistically manipulable with modest capital, matching the "low-liquidity market" precondition in the external report.

### Recommendation
- Re-enable a hard overfill ceiling (not just a warning) for venue-priced legs, or otherwise never allow a fill computed from live pool state to exceed the order's requested amount by more than a small, non-configurable bound.
- Replace the raw pool mid with a manipulation-resistant price (TWAP over a meaningful window, or a size/impact-aware quote using the pool's actual liquidity depth) instead of `sqrtPriceX96` at a single block.
- Make `referencePrice`/`maxDeviationBps` mandatory whenever `[vault.uniswapV4]` venue pricing is enabled, and consider re-deriving the reference from a longer-horizon oracle rather than a static operator-set value.
- Apply the pool's fee tier and slippage/impact cost to the quoted rate rather than treating the mid as the executable price.

### Proof of Concept
1. Operator configures a curve-less pair (e.g. `USDC/CNGN`) priced solely from a Uniswap V4 position, with `checkPriceGuard` either unconfigured or configured with a loose `maxDeviationBps` (`docs/content/developers/evm/simplex/pricing.mdx:68-84`).
2. Attacker takes a large swap against the low-liquidity CNGN/USDC V4 pool, shifting `sqrtPriceX96` so `computeDirectPoolPriceUsd` reports a materially better-than-fair CNGN/USD rate (`UniswapV4FundingPlanner.ts:206-275`), staying within any configured `maxDeviationBps` band.
3. Attacker places/has selected an `IntentGateway` order (USDC in, CNGN out) at this window. `resolveLegRates` accepts the manipulated venue rate (`fx.ts:1443-1465`), `computeLegPolicyOutput` computes an inflated `policyMaxOutput` from it (`fx.ts:1397-1434`).
4. `evaluateOrder`'s overfill check only warns — it does not clamp — because the ceiling enforcement was disabled (`fx.ts:678-701`), so `targetOutput = policyMaxOutput` unclamped (`fx.ts:736`).
5. The solver pays the inflated CNGN amount, funding the shortfall by withdrawing liquidity from its own V4 position at the same manipulated price (`fx.ts:740-754`), realizing a loss on the mismatch between the attacker's true value received and the fair-market value it paid out.

	/**
	 * Validates a live venue quote against the static reference price for the chain.
	 * Returns true (pass) when no guard is configured, or no reference exists for the
	 * chain. Returns false when the quote (token1 per USD) deviates from the reference
	 * by more than `maxDeviationBps`, in which case the order must not be filled.
	 */
	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {
			this.logger.warn(
				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
	}

		// would just be the asset's own USD price, not a spread).
		const curveless = !leg.pair.bidPricePolicy && !leg.pair.askPricePolicy

				// the venue-specific defense.

		const state = this.stateByChain.get(chain)

		const tokenLower = exoticToken.toLowerCase()

		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")

```text
## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.

```toml lineNumbers
[vault.uniswapV4]
# referencePrice is the expected cNGN per USD;
# reject if the quote is more than 2% off.
# The two go together — one without the other is rejected.
[[vault.uniswapV4.positions]]
chain           = "EVM-8453"
tokenId         = "2087350"
referencePrice  = "1575"
maxDeviationBps = 200
```
