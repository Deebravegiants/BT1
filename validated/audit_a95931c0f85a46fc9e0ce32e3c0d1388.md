### Title
Permissionless `finalizeGraduation` can be forced to swap up to 99% of a token's curve-raised LT into an attacker-controlled HyperSwap V2 pre-seed, which the attacker then redeems via LP burn - ([File: packages/contracts/src/Bonding.sol])

### Summary
`Bonding.finalizeGraduation` is permissionless and, when it detects that the HyperSwap V2 `TOKEN/LT` pair has been pre-seeded with a hostile ratio (`_seedRebalancing`), executes a corrective swap (`_pairRebalance`) whose size is derived entirely from the *live, attacker-controlled* V2 pair reserves, up to a budget of 99% of the token's entire curve-raised LT (`ltFromPair`). An attacker who mints a maximally-imbalanced LP position into the pair before calling `triggerGraduation`/`finalizeGraduation` can force Bonding to swap real, curve-raised LT into that attacker-owned pool, then redeem it by burning their LP position afterwards - stealing LT contributed by every other curve buyer of that token.

### Finding Description
`_seedUniswapV2Direct` branches into `_seedRebalancing` whenever the target HyperSwap V2 pair already has a non-zero LP `totalSupply()` (Regime 3, "mint pre-seed") [1](#0-0) . This is explicitly reachable: the pair can be created and seeded by anyone with `IUniswapV2Factory.createPair` + a normal `transfer` + `mint` before `finalizeGraduation` ever runs.

Inside `_seedRebalancing`, the pool's live reserves (`r0`, `r1`, fully attacker-controlled) are compared against the cached curve-close target `(tokensForLP, ltFromPair)`, and if the pool is "TOKEN-rich" a corrective swap is issued with `tokenIn = lt`, budgeted at `_swapBudget(_ltSwapInventory(lt, protectedLT))`, i.e. 99% of Bonding's *entire* real LT balance for that graduation [2](#0-1) . `_swapBudget` caps at 99% of the available inventory [3](#0-2) .

The actual swap size `s` is computed by `_noFeeSwapInput`, which purely solves for the input needed to move the *live pool ratio* to the target, capped at `maxSwap`:
```
uint256 product = Math.mulDiv(reserveIn * reserveOut, targetN, targetD);
uint256 newIn = Math.sqrt(product);
...
return s > maxSwap ? maxSwap : s;
``` [4](#0-3) 
Because `reserveIn`/`reserveOut` are the attacker's own pre-seeded numbers, the attacker can trivially choose a ratio (tiny LT reserve, large Token reserve) that drives `s` to hit the `maxSwap` cap - i.e., 99% of the token's `ltFromPair`.

`_pairRebalance` then executes this swap directly against the attacker's pool via `pair.swap`, sending Bonding's real LT into the pool and pulling Token out at the pool's *own* attacker-set price - there is no check against the curve's closing price or against `exchangeRate()`, only against the pool's self-reported `getAmountOut` [5](#0-4) . Since the attacker held 100% of the pre-existing LP supply at the moment of the swap (a fresh hostile `mint`), the LT that Bonding injects becomes part of the pool's reserves, entirely reclaimable by the attacker afterwards via a normal `IUniswapV2Pair.burn` call - a step outside Bonding's control, on the external, unmodifiable HyperSwap V2 pair.

The `ltFromPair` amount at risk is the *entire* real LT raised by the curve (all buyers, not just the attacker), transferred to `Bonding` during phase 1 via `Router.graduate` [6](#0-5) , and both `triggerGraduation` and `finalizeGraduation` are explicitly permissionless entry points [7](#0-6) [8](#0-7) .

This is a direct structural analog of the Bunni "excess liquidity inflated to create arbitrarily large rebalance orders" report: a JIT/pre-seeded liquidity position is used to inflate the size of an autonomously-triggered rebalancing trade, letting the position-holder capture the trade's proceeds by removing their liquidity afterward.

### Impact Explanation
An attacker can extract up to 99% of the entire LT raised by a token's bonding curve - contributed by every buyer on that curve, not just the attacker - by front-running `finalizeGraduation` with a hostile pre-seed of the destination HyperSwap V2 pair, and later burning their LP position to redeem the injected LT. This is concrete theft of curve-raised value that was meant to seed and lock the token's graduated liquidity (`LPLock`), directly harming curve buyers and leaving the "locked" LP thin/hollow. This qualifies as Critical/High-severity fund theft.

### Likelihood Explanation
- `triggerGraduation`/`finalizeGraduation` are permissionless, callable by anyone, from any wallet.
- Pre-creating/pre-seeding the target HyperSwap V2 pair via the standard factory + `transfer` + `mint` is a normal, unprivileged action explicitly anticipated by the code's own natspec (Regime 3).
- The attacker fully controls the reserve ratio it seeds, and the `_noFeeSwapInput` sqrt formula makes it straightforward to force the swap to the `maxSwap` cap (99% of `ltFromPair`) with a cheap, lopsided seed (large Token amount, near-zero LT amount).
- No code path validates the corrective swap's price against the curve's own closing price or `exchangeRate()`; it trusts the live, attacker-set V2 reserves as ground truth.

### Recommendation
- **Short term:** Before performing the rebalance swap in `_seedRebalancing`/`_pairRebalance`, validate the pre-seeded pool's implied price against the curve's own closing ratio (`tokensForLP`/`ltFromPair`) within a tight tolerance, and refuse (fall back to burning/rejecting the hostile pre-seed, or reverting `finalizeGraduation`) rather than swapping Bonding's real LT into an arbitrarily-priced attacker pool.
- **Long term:** Avoid trusting live external V2 reserves as a price reference for a value-moving swap at all; consider skimming and permanently burning/quarantining any pre-existing LP position/reserves before seeding (rather than rebalancing against them), or require that `finalizeGraduation` only ever mints against a pristine, empty pair, deploying the canonical pair through a mechanism only `Bonding` can seed atomically with `launch`/`triggerGraduation`.

### Proof of Concept
1. Token `T` launches; curve accumulates real LT from many buyers over time until `canGraduate(T)` becomes true (USD threshold or sellout).
2. Attacker calls `IUniswapV2Factory(uniswapV2Factory).createPair(T, LT)` (or lets `_ensureUniswapV2Pair` do it - irrelevant, attacker just needs to seed before phase 2 runs).
3. Attacker acquires a large amount of `T` cheaply (e.g., via curve buys during the curve's life, or via secondary market) and a minimal amount of `LT`.
4. Attacker `transfer`s a large `T` amount and a tiny `LT` amount directly to the V2 pair, then calls `IUniswapV2Pair(pair).mint(attacker)` - this is Regime 3 ("mint pre-seed") and attacker now owns ~100% of the pair's LP supply, with reserves heavily skewed Token-rich.
5. Anyone (attacker or a keeper) calls `Bonding.triggerGraduation(T)` then `Bonding.finalizeGraduation(T)`.
6. Inside `finalizeGraduation` → `_seedUniswapV2Direct` → `_seedRebalancing`, the pool is detected as Token-rich; `_pairRebalance` swaps `s ≈ 99% * ltFromPair` of Bonding's real, curve-raised LT into the attacker's pool for `Token` out, per `packages/contracts/src/Bonding.sol:1316-1332` and `:1414-1429`.
7. The remaining balanced LT/Token is deposited via `_routerDepositAndDispose` (`addLiquidity(min=1,min=1)`), minting new LP to `LPLock` proportional to the post-swap ratio - this does not reduce the attacker's dollar-value claim on the pool.
8. After `finalizeGraduation` completes, the attacker calls the standard `IUniswapV2Pair(pair).burn(attacker)` (having transferred their LP tokens to the pair first, per standard V2 flow) and withdraws their proportional share of pool reserves, which now includes the LT that Bonding injected in step 6 - realizing profit equal to close to the entire `ltFromPair` amount, funded by every prior curve buyer of `T`, in exchange for `Token` supply the attacker acquired cheaply.

    function finalizeGraduation(
        address tokenAddress
    ) external nonReentrant {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[tokenAddress];
        if (info.lifecycle != Lifecycle.Graduating) revert NotGraduating();

        address lt = info.ltAddress;
        PendingGraduation memory p = $.pendingGraduation[tokenAddress];

        // Anything in this contract beyond `p.ltFromPair` belongs to a
        // concurrent graduation on the same LT (Phase 1 transferred it
        // via `Router.graduate`) or to stray dust. Either way it is
        // off-limits to this graduation's deposit and sweep — see
        // `_routerDepositAndDispose` and `_sweepLTToOwner`.
        // Saturating subtract: a balance below `p.ltFromPair` shouldn't
        // be reachable in normal operation, but we keep finalize from
        // bricking on a Panic if any future code path or non-canonical
        // LT briefly violates the invariant.
        uint256 ltBalance = IERC20(lt).balanceOf(address(this));
        uint256 protectedLT = ltBalance > p.ltFromPair ? ltBalance - p.ltFromPair : 0;

        address lpPair = _ensureUniswapV2Pair(tokenAddress, lt);
        uint256 liquidity = _seedUniswapV2Direct(tokenAddress, lt, lpPair, p.tokensForLP, p.ltFromPair, protectedLT);

        _sweepLTToOwner(lt, protectedLT);

        info.lifecycle = Lifecycle.Graduated;
        $.graduatedPair[tokenAddress] = lpPair;
        delete $.pendingGraduation[tokenAddress];

        LPLock($.lpLock).recordLock(tokenAddress, lpPair, liquidity);

        emit TokenGraduated(tokenAddress, lpPair, liquidity, p.tokensForLP, p.lpBurned, p.unsoldBurned);
    }

    function _pairRebalance(
        RebalanceParams memory p
    ) internal returns (bool) {
        uint256 s = _noFeeSwapInput(p.reserveIn, p.reserveOut, p.targetN, p.targetD, p.maxSwap);
        if (s == 0) return false;

        // Quote from the pair so the output tracks its live fee; a value
        // derived from a stale fee rate would trip the pair's K-check.
        uint256 expectedOut = IUniswapV2Pair(p.pair).getAmountOut(s, p.tokenIn);
        if (expectedOut == 0) return false;

        IERC20(p.tokenIn).safeTransfer(p.pair, s);
        (uint256 amount0Out, uint256 amount1Out) = p.tokenInIs0 ? (uint256(0), expectedOut) : (expectedOut, uint256(0));
        IUniswapV2Pair(p.pair).swap(amount0Out, amount1Out, address(this), new bytes(0));
        return true;
    }

    function _noFeeSwapInput(
        uint256 reserveIn,
        uint256 reserveOut,
        uint256 targetN,
        uint256 targetD,
        uint256 maxSwap
    ) internal pure returns (uint256) {
        if (reserveIn == 0 || reserveOut == 0 || targetN == 0 || targetD == 0 || maxSwap == 0) {
            return 0;
        }
        uint256 product = Math.mulDiv(reserveIn * reserveOut, targetN, targetD);
        uint256 newIn = Math.sqrt(product);
        if (newIn <= reserveIn) return 0;
        uint256 s = newIn - reserveIn;
        return s > maxSwap ? maxSwap : s;
    }
