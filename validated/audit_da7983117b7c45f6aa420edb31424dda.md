Audit Report

## Title
Unchecked type-assertion error allows OIDC session creation to proceed with an empty/unattributed user identity - (File: core/sessions/oidcauth/oidc.go)

## Summary
In `handleTokenExchange`, the `email, ok := claims["email"].(string)` type assertion failure is logged and written as a `500` response but does not `return`, unlike every sibling error branch in the same function. Execution falls through with an empty `email`, causing the OIDC login flow to insert a new `oidc_sessions` row with `user_email = ''`, log an audit entry with an empty email, set a valid session cookie, and ultimately return `200 {"success": true}` to the client.

## Finding Description
The bug is exactly as described: `handleTokenExchange` extracts `email` from claims, and on assertion failure logs an error and writes a `500` body but omits `return`, breaking the pattern used consistently by all other error paths in the function (state mismatch, exchange failure, missing `id_token`, verify failure, claim parse failure, `ExtractIDClaimValues` failure, role-mapping failure, and session-save failure all `return` immediately). Because of the missing `return`, the function proceeds to resolve `role` via `IDClaimsToUserRole` (independent of `email`), inserts the new session with an empty `user_email`, emits `audit.AuthLoginSuccessNo2FA` with `{"email": ""}`, sets the session cookie, and returns `200 OK`. The same fail-open pattern also affects the `ExecContext` insert-error branch immediately below, which likewise lacks a `return`. Existing checks (state validation, token exchange, ID-token verification, claims parsing) are all correctly enforced with `return`, but this one path breaks the fail-closed convention the rest of the function establishes.

## Impact Explanation
This produces a functioning, cookie-backed, role-privileged session that is not attributable to any email/user, corrupting the audit trail (`AuthLoginSuccessNo2FA` and any subsequent per-request audits keyed on `sessionUser.Email`) and any session-listing/admin UI relying on `Sessions()`. Since the OIDC "email" claim is optional per spec and role attribution here derives only from group claims (`AdminClaim`/`EditClaim`/`RunClaim`/`ReadClaim`), an identity provider response lacking an `email` claim — whether due to scope configuration or a compromised/rogue IdP — will trigger this every time, letting the intended-to-be-fatal check silently fail open into a working authenticated session. This is a genuine authentication-flow correctness bug and audit-integrity issue in an internet-facing endpoint, though it does not itself escalate privileges beyond what the IdP's group claims already grant.

## Likelihood Explanation
Reachable by any actor able to complete the standard `/oidc-login` → callback OAuth2 code-exchange flow against a configured OIDC provider whose token response omits the `email` claim while still including a role-mapping group claim — a realistic scenario for misconfigured or attacker-influenced IdP responses, requiring no special chainlink-node privilege.

## Recommendation
Add `return` immediately after the error response in the `email` type-assertion failure branch (lines 226-230) and in the `ExecContext` insert-error branch (lines 257-260), consistent with every other error path in `handleTokenExchange`.

## Proof of Concept
1. Configure/point the node at an OIDC provider whose ID token includes a group claim matching `oi.config.RunClaim()` (or another mapped role claim) but omits the `email` claim.
2. Perform `GET /oidc-login` to obtain `state`, complete provider consent, then `POST` the resulting `code`/`state` to the `handleTokenExchange` endpoint.
3. Observe the server logs `"Failed to get email from claims"` and writes a `500` body, but still inserts a new `oidc_sessions` row with `user_email=''`, logs `audit.AuthLoginSuccessNo2FA` with an empty email, sets the session cookie, and finally responds `200 {"success": true}`.
4. Use the returned cookie against an endpoint gated by `RequiresRunRole` to confirm the session is fully functional despite the earlier logged failure.

func (oi *oidcAuthenticator) handleTokenExchange(c *gin.Context) {
	// parse and validate the incoming JSON request
	var req ExchangeTokenRequest
	if err := c.ShouldBindJSON(&req); err != nil {
		c.JSON(http.StatusBadRequest, ExchangeTokenResponse{
			Success: false,
			Message: "Invalid request: " + err.Error(),
		})
		return
	}

	// check state matches stored value on the session
	ginSession := sessions.Default(c)
	storedState := ginSession.Get("state")
	if storedState == nil || req.State != storedState.(string) {
		c.JSON(http.StatusBadRequest, ExchangeTokenResponse{
			Success: false,
			Message: "Invalid state parameter",
		})
		return
	}
	ginSession.Delete("state")

	// Begin token exchange to retrieve attested claims of authenticated user
	ctx := context.Background()
	oauth2Token, err := oi.oauth2Config.Exchange(ctx, req.Code)
	if err != nil {
		oi.lggr.Errorf("Failed to exchange token: %v", err)
		c.JSON(http.StatusInternalServerError, ExchangeTokenResponse{
			Success: false,
			Message: "OIDC exchange failed",
		})
		return
	}

	// Request token from provider for claims lookup and verification
	rawIDToken, ok := oauth2Token.Extra("id_token").(string)
	if !ok {
		oi.lggr.Errorf("No id_token field in oauth2 token: %v", err)
		c.String(http.StatusInternalServerError, "Missing id_token field in response")
		return
	}

	// Verify claim and retrieve attested user id claims
	idToken, err := oi.provider.Verifier(oi.oidcConfig).Verify(ctx, rawIDToken)
	if err != nil {
		oi.lggr.Errorf("Failed to verify ID token: %v", err)
		c.String(http.StatusInternalServerError, "Failed to verify ID token")
		return
	}

	var claims map[string]any
	if err = idToken.Claims(&claims); err != nil {
		oi.lggr.Errorf("Failed to parse OIDC return claims: %v", err)
		c.String(http.StatusInternalServerError, "Failed to parse OIDC return claims")
		return
	}
	idClaims, err := oi.ExtractIDClaimValues(claims, oi.config.ClaimName())
	if err != nil {
		oi.lggr.Errorf("Failed to extract ID claims from ID token. ClaimName: '%s': error %v", oi.config.ClaimName(), err)
		c.String(http.StatusInternalServerError, "Failed to extract ID claims from claims")
		return
	}
