### Title
Unauthenticated `PATCH /v2/resume/:runID` endpoint allows any unprivileged network client to resume/complete arbitrary suspended pipeline runs by guessing/observing the task UUID - (File: `core/web/router.go`)

### Summary
The `PATCH /v2/resume/:runID` route is registered in the "unauthed" route group with no session, API-token, or external-initiator authentication middleware, and calls `PipelineRunsController.Resume`, which directly forwards attacker-controlled JSON as the "result" of a suspended pipeline task via `App.ResumeJobV2`. This mirrors the audited `VestingWallet#release()` bug class: a state-transition entry point that a supervising/authorized component (the bridge adapter that is supposed to call back, analogous to `Upkeep`) assumes only it will invoke, but which in fact has no access control, letting any unprivileged caller resume/finalize the run out-of-band, with the node itself flagging this via the `UnauthedRunResumed` audit event name.

### Finding Description
In `core/web/router.go`, the route is registered outside the authenticated group:

```go
unauthedv2 := r.Group("/v2")
prc := PipelineRunsController{app}
...
unauthedv2.PATCH("/resume/:runID", prc.Resume)
``` [1](#0-0) 

`Resume` parses `runID` as a UUID (a `pipeline.TaskRun` ID), decodes an attacker-supplied JSON body into a `pipeline.ResumeRequest`, and calls `App.ResumeJobV2` to complete the pending task with that value:

```go

	...
	prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
``` [2](#0-1) 

This endpoint is the async callback path for tasks (e.g. `bridge` tasks) that suspend the pipeline and expect a designated external bridge/adapter to `PATCH` back the result once its off-chain work completes — conceptually the same "coupling of two flows with no enforced coordination" as `Upkeep#performUpkeep()`/`teamVestingWallet.release()`: the node assumes the *correct* off-chain adapter is the only party that will call this URL with the task ID, but nothing enforces that. The corresponding `audit.UnauthedRunResumed` event ID (`"UNAUTHED_RUN_RESUMED"`) confirms the node's own author labels the call path as explicitly unauthenticated:

```go
UnauthedRunResumed EventID = "UNAUTHED_RUN_RESUMED"
``` [3](#0-2) 

The only "secret" gating a legitimate caller is the unguessable UUID `runID`/task ID. If that value leaks (logs, error messages, network traces, response payloads, or is guessed/brute-forced since these route paths are network-reachable with no auth and no rate limiting beyond the global unauthenticated rate limiter), any unprivileged network client can:
- Complete a pending pipeline task with attacker-chosen data before the legitimate bridge/adapter responds (a race, analogous to calling `release()` before `performUpkeep()`), corrupting or short-circuiting the pipeline's real data flow, or
- Resume/complete runs that should remain pending, causing them to finish with attacker-supplied results, potentially feeding malicious data into downstream contract-writing tasks depending on job configuration.

### Impact Explanation
This is a state-desync/impersonation issue equivalent in class to the referenced finding: a component with no access control that a privileged workflow assumes is exclusive to it. Depending on the job pipeline configuration, an attacker completing a suspended run with attacker-controlled data can inject falsified data into a job's execution path (request impersonation / unauthorized run completion), or race the legitimate resumer to corrupt state. The severity is bounded by needing to know/guess a per-run UUID, but there is zero authentication layer defense-in-depth once that ID is known, unlike the external-initiator/bridge model elsewhere in the codebase, which requires a hashed secret (`AuthenticateExternalInitiator`) [4](#0-3) .

### Likelihood Explanation
Moderate: task IDs are UUIDs, which are not trivially guessable, but this identifier is not treated as a secret elsewhere in the system (it's logged, returned in API responses to the job show/run APIs, and passed through webhook/bridge configuration), meaning there are multiple avenues (logging, monitoring, error responses, network capture) for it to leak to an unprivileged party, at which point exploitation is immediate and one HTTP call away with no further authentication check.

### Recommendation
- Require authentication on `PATCH /v2/resume/:runID` — either scope it under the authenticated `/v2` group (requiring session/API token or a scoped bridge-specific secret) or bind resumption to a per-task secret/HMAC issued when the task was created, verified in the handler, similar to `bridges.AuthenticateExternalInitiator`'s constant-time secret comparison.
- If backward-compatibility with existing bridge adapters prevents adding session auth, at minimum require the resuming caller to present a bridge-scoped, per-request signed token bound to `runID` so that only the adapter that was handed the callback URL by the node can complete it, closing the "any unprivileged network caller can complete this run" gap and eliminating the race with the legitimate resumer.

### Proof of Concept
1. Create a job whose pipeline contains a `bridge` task (or any task type that suspends execution and awaits an external resume callback), and note/leak the resulting `runID`(task UUID) for a pending run — via logs, the `/v2/jobs/:ID/runs` show API, or network capture of the outgoing bridge request that embeds the callback URL.
2. Without any session cookie, API token, or external-initiator header, send:
```
PATCH /v2/resume/<runID>
Content-Type: application/json

{"error": null, "value": "<attacker-controlled-result>"}
```
3. Observe HTTP 200 and that `App.ResumeJobV2` completes the pipeline run with the attacker-supplied value — confirmable via the `pipeline_runs`/`pipeline_task_runs` tables or by observing the job's downstream effect — with the only server-side record being the `UnauthedRunResumed` audit event, and no rejection based on caller identity.

func (prc *PipelineRunsController) Resume(c *gin.Context) {
	taskID, err := uuid.Parse(c.Param("runID"))
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	rr := pipeline.ResumeRequest{}
	decoder := json.NewDecoder(c.Request.Body)
	err = errors.Wrap(decoder.Decode(&rr), "failed to unmarshal JSON body")
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	result, err := rr.ToResult()
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	if err := prc.App.ResumeJobV2(c.Request.Context(), taskID, result); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
	c.Status(http.StatusOK)
```

// AuthenticateExternalInitiator compares an auth against an initiator and
// returns true if the password hashes match
func AuthenticateExternalInitiator(eia *auth.Token, ea *ExternalInitiator) (bool, error) {
	hashedSecret, err := auth.HashedSecret(eia, ea.Salt)
	if err != nil {
		return false, err
	}
	return subtle.ConstantTimeCompare([]byte(hashedSecret), []byte(ea.HashedSecret)) == 1, nil
}
