### Title
Secure-Element Signature Omits Signup Session Binding (`signup_id`/`signup_reason`) - ([File: src/plans/enroll_user.rs])

### Summary
The reported PLONK bug is a "missing commitment" class issue: a Fiat-Shamir transcript that omits required parameters (`[Qci]1`) from challenge derivation, letting security-relevant context be excluded from what the cryptographic proof actually binds. The orb-core analog is `make_signature` in [1](#0-0)  which builds a secure-element-signed digest that omits the `signup_id` and `signup_reason` — both of which are sent alongside the signature as separate, unsigned form fields to the backend.

### Finding Description
`make_signature` constructs the SHA-256 digest that is signed by the secure element from: `ORB_ID`, the user QR code `user_id`, `ir_net_version`, `iris_version`, and the left/right iris codes, masks, and code versions [1](#0-0) . This signed blob is then transmitted together with `signup_id` (used to construct the request URL path `/api/v2/signups/{signup_id}`) and `signup_reason` (`NORMAL`/`FAILURE`/`FRAUD`) as independent, unsigned multipart form fields in `signup_post::request` [2](#0-1) .

Because `signup_id` and `signup_reason` are not part of the signed transcript, the secure-element attestation over the iris biometric data does not cryptographically bind to the specific signup transaction it is meant to authorize. This is structurally identical to the reported bug: the "commitment" (secure-element signature) is computed over an incomplete transcript, omitting parameters that determine which specific protocol execution (signup session/reason) the attestation applies to.

### Impact Explanation
Because the secure element's signature is agnostic to `signup_id` and `signup_reason`, the same signed attestation blob for a given `(orb_id, user_id, iris data)` tuple is valid input for any `signup_id`/`signup_reason` combination the calling software chooses to send. If any component upstream of the multipart request construction (the orb-core software itself, or a compromised/modified in-process caller) is able to substitute a different `signup_id` or `signup_reason` while reusing an already-signed blob, the backend cannot detect this from the signature since it never covered those fields. This creates a cross-signup state bleed risk — biometric attestation data cryptographically intended for one signup transaction can be misattributed to a different signup session or reason without invalidating the secure-element signature.

### Likelihood Explanation
The likelihood is constrained by the fact that `signup_id` is generated per attempt and the request flow is largely deterministic within a single `Plan::run` invocation [3](#0-2) . However, the structural weakness — an SE attestation that fails to commit to the full transaction context — is a real deviation from expected security properties, matching exactly the "missing commitment" class from the report: fields that are eventually sent to the backend (`signup_id`, `signup_reason`) are never part of what the trusted signer actually attests to.

### Recommendation
Include `signup_id` and `signup_reason` (and any other session-binding fields such as timestamp) in the SHA-256 context fed to `secure_element::sign` inside `make_signature`, so the secure element's attestation cryptographically commits to the full transaction context rather than only to the biometric/identity payload.

### Proof of Concept
Not applicable as a runtime exploit within this static analysis; the issue is demonstrated by direct code inspection: `make_signature` digest inputs [4](#0-3)  versus the fields sent unsigned alongside the signature in `signup_post::request`'s form construction [5](#0-4) , showing `signup_id` and `reason` are excluded from the signed transcript while being transmitted as independent, mutable form fields.

fn make_signature(user_qr_code: &qr_scan::user::Data, pipeline: &Pipeline) -> Result<String> {
    let mut ctx = Context::new(&SHA256);
    ctx.update(ORB_ID.as_str().as_bytes());
    ctx.update(user_qr_code.user_id.as_bytes());
    ctx.update(pipeline.v2.ir_net_version.as_bytes());
    ctx.update(pipeline.v2.iris_version.as_bytes());
    ctx.update(pipeline.v2.eye_left.iris_code.as_bytes());
    ctx.update(pipeline.v2.eye_left.mask_code.as_bytes());
    ctx.update(pipeline.v2.eye_left.iris_code_version.as_bytes());
    ctx.update(pipeline.v2.eye_right.iris_code.as_bytes());
    ctx.update(pipeline.v2.eye_right.mask_code.as_bytes());
    ctx.update(pipeline.v2.eye_right.iris_code_version.as_bytes());
    let signed = secure_element::sign(ctx.finish())?;
    Ok(BASE64.encode(&signed))
}

/// Makes a signup request.
#[allow(clippy::too_many_arguments)]
pub async fn request(
    signature: Option<&String>,
    signup_id: &str,
    operator_qr_code: &qr_scan::user::Data,
    user_qr_code: &qr_scan::user::Data,
    s3_region: &str,
    capture: &Capture,
    pipeline: Option<&Pipeline>,
    signup_reason: SignupReason,
) -> Result<Response> {
    dd_gauge!(
        "main.gauge.signup.sharpest_iris",
        capture.eye_left.ir_net_estimate.score.to_string(),
        "side:left"
    );
    dd_gauge!(
        "main.gauge.signup.sharpest_iris",
        capture.eye_right.ir_net_estimate.score.to_string(),
        "side:right"
    );
    tracing::info!("Orb OS version: {:?}", &*ORB_OS_VERSION);
    tracing::info!("Signup reason: {:?}", signup_reason);
    let codes = pipeline.map_or(String::new(), |p| {
        serde_json::to_string_pretty(&format_pipeline(p)).expect("always a valid JSON")
    });
    let mut form = Form::new()
        .text("softwareVersion", &*ORB_OS_VERSION)
        .text("orbId", ORB_ID.as_str())
        .text("distributorId", operator_qr_code.user_id.clone())
        .text("userId", user_qr_code.user_id.clone())
        .text("region", s3_region.to_owned())
        .text("signature", signature.map_or(String::default(), Clone::clone))
        .text("codes", codes)
        .text("reason", signup_reason.to_screaming_snake_case().to_string());
    if let Some(latitude) = capture.latitude {
        form = form.text("latitude", latitude.to_string());
    }
    if let Some(longitude) = capture.longitude {
        form = form.text("longitude", longitude.to_string());
    }
    let request = super::client()?
        .post(format!("{}/api/v2/signups/{signup_id}", *SIGNUP_BACKEND_URL))
        .basic_auth(&*ORB_ID, Some(get_orb_token()?))
        .multipart(form);
