### Title
`TokenExchange.exchange_token` skips shop-domain validation, allowing the app's `client_secret` to be sent to an attacker-controlled host - (File: `lib/shopify_api/auth/token_exchange.rb`)

### Summary
`ShopifyAPI::Auth::TokenExchange.exchange_token` derives the OAuth "shop" host directly from the `dest` claim of an untrusted-format-checked JWT and uses it, unsanitized, to build the HTTP request that carries the app's `client_secret`. Every other credential-issuing flow in the same module (`migrate_to_expiring_token`) and in sibling modules (`ClientCredentials.client_credentials`, `RefreshToken.refresh_access_token`) explicitly run the shop value through `Utils::ShopValidator.sanitize!` before using it to build the request host. `exchange_token` omits this check, breaking the intended invariant that "the host that receives `client_secret` must equal a Shopify-trusted domain."

### Finding Description
`JwtPayload#initialize` only checks the JWT signature (HMAC with `Context.api_secret_key`) and `aud == Context.api_key`: [1](#0-0) 

It exposes `dest` (and `shop`, which is simply `dest` with `"https://"` stripped) with no validation that the value is a trusted Shopify domain: [2](#0-1) 

`TokenExchange.exchange_token` takes this unvalidated `dest_shop` and uses it directly to build the session/host that receives the OAuth token-exchange request, which includes `client_id`/`client_secret`: [3](#0-2) 

`Clients::HttpClient#initialize` builds the request's base URI directly from `session.shop`: [4](#0-3) 

This is the exact same shop value used as the network target for the POST that contains `client_secret`, so if `dest_shop` is attacker-influenced, the secret is sent to that host.

Compare this to the sibling function in the *same file*, `migrate_to_expiring_token`, and to `ClientCredentials.client_credentials` / `RefreshToken.refresh_access_token`, all of which call `Utils::ShopValidator.sanitize!(shop)` — which restricts the resulting host to `TRUSTED_SHOPIFY_DOMAINS` (`shopify.com`, `myshopify.io`, `myshopify.com`, `spin.dev`, `shop.dev`) or a configured `myshopify_domain` — before constructing the session/host: [5](#0-4) [6](#0-5) [7](#0-6) [8](#0-7) 

This maps exactly to the report's bug class of "a check exists and is enforced on other paths but is bypassed/missing on one specific path" — here the equality that should hold is: `host that receives client_secret == host validated by ShopValidator.sanitize!`. In `exchange_token`, this equality is broken because the host used is `jwt_payload.shop` with no domain-trust check at all.

### Impact Explanation
If the `dest` claim of a session token can be influenced to a non-Shopify host (e.g., through a shop configured with a merchant-controlled custom domain, or any deviation between what Shopify's admin issues in `dest` and the trusted-domain list enforced elsewhere in this gem), `exchange_token` will POST the app's `client_id` and `client_secret` to that host. This is credential exfiltration of the app's `client_secret` via SSRF, matching the "High – SSRF with the app's credentials … or credential leakage" impact category. It is also inconsistent defense-in-depth: the gem's own author explicitly guards this exact class of issue in three other, nearly identical, credential-issuing call sites but not in `exchange_token`.

### Likelihood Explanation
Likelihood is Low-to-Medium: exploitation depends on the actual contents Shopify puts in the `dest` claim for a given install (which is outside this gem's control), and whether that value can ever diverge from a Shopify-trusted domain (e.g., via a merchant-controlled custom domain or a spoofed embedding context). The code path itself, however, unconditionally trusts `dest` with zero domain validation, unlike its sibling functions, so any scenario where `dest` is not already constrained to `TRUSTED_SHOPIFY_DOMAINS` results in immediate exposure.

### Recommendation
In `TokenExchange.exchange_token`, sanitize `dest_shop` through `Utils::ShopValidator.sanitize!(dest_shop)` (mirroring `migrate_to_expiring_token`) before constructing `shop_session`/`Session.from`, so that the host receiving `client_id`/`client_secret` is provably constrained to Shopify's trusted domain list, consistent with every other OAuth token-issuing code path in this file and module.

### Proof of Concept
1. Obtain (or have Shopify issue) a valid session token whose `dest` claim resolves, after `JwtPayload#shop` (strip `"https://"`), to a host not in `ShopValidator::TRUSTED_SHOPIFY_DOMAINS` (e.g. any host outside `shopify.com`/`myshopify.io`/`myshopify.com`/`spin.dev`/`shop.dev`).
2. Call `ShopifyAPI::Auth::TokenExchange.exchange_token(session_token: token, requested_token_type: ...)`.
3. Because `dest_shop` is never passed through `Utils::ShopValidator.sanitize!` (unlike `migrate_to_expiring_token`), `Clients::HttpClient.new(session: shop_session, base_path: "/admin/oauth")` builds `@base_uri = "https://#{dest_shop}"` and the subsequent POST — containing `client_id` and `client_secret` in the body — is sent to that untrusted host instead of a Shopify-trusted domain.       TRUSTED_SHOPIFY_DOMAINS = T.let(
        [
          "shopify.com",
          "myshopify.io",
          "myshopify.com",
          "spin.dev",
          "shop.dev",
        ].freeze,
        T::Array[String],
      )

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
