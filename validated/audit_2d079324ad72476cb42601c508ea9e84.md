### Title
Consensus relayer rewards use the *current* `cost_per_block` rate for an entire unpaid block span, ignoring rate changes during that span - ([File: modules/pallets/consensus-incentives/src/impls.rs])

### Summary
`pallet-consensus-incentives` pays a relayer for delivering a `ConsensusMessage` by multiplying the number of newly-committed blocks (`latest_height - baseline`) by a single `cost_per_block` value read at the moment the reward is calculated. If `StateMachinesCostPerBlock` is updated one or more times while blocks accumulate unpaid, the entire backlog span is paid (or underpaid) entirely at whatever rate happens to be current at claim time, exactly the "average/aggregate rate applied over a variable-length period" bug class described in the external report for `RewardsMath.sol`.

### Finding Description
`calculate_reward` computes the reward as: [1](#0-0) 

```
blocks = latest_height - baseline
reward = blocks * block_cost   // block_cost = StateMachinesCostPerBlock::get(state_machine_id) at call time
```

`baseline` is `LastRewardedHeight` (or `previous_commitment_height` before the first reward), i.e. the watermark of the last paid height [2](#0-1) . The `block_cost` used is whatever value is currently stored in `StateMachinesCostPerBlock` — a single scalar governed by `update_cost_per_block` [3](#0-2) . The pallet keeps no history of which rate applied to which sub-range of blocks; when `blocks` spans a period during which the rate changed, the whole span is priced at one flat rate rather than the sum of each sub-period's applicable rate — the same fault pattern flagged in the reported `RewardsMath.sol` issue (average rate applied across a variable-length combined interval instead of per-interval accounting).

This is reachable by any unprivileged relayer: a `ConsensusMessage` is delivered via the permissionless `handle_unsigned` extrinsic of `pallet-ismp`, which invokes `FeeHandler::on_executed` → `process_message` → `calculate_reward` [4](#0-3) . A relayer fully controls *when* it submits a consensus update, and therefore controls how much of a rate-change window is folded into a single claim.

### Impact Explanation
A relayer can withhold submitting an available, valid consensus proof for a state machine while `cost_per_block` is low, wait until governance raises the per-block price for legitimate reasons (chain congestion, cost re-pricing, etc. — a routine administrative action, not an attack), and then submit the backlog in one message. The entire multi-block span accrued at the old (low) rate is instead paid out of `T::TreasuryAccount` at the new (higher) rate [5](#0-4) , over-draining the treasury relative to the amount actually owed for work done while the old rate was in force. Because the reward and an equal amount of `ReputationAsset` are both minted from this single miscalculated figure [6](#0-5) , the miscalculation also inflates the relayer's on-chain reputation. This is a concrete, protocol-funded overpayment (theft of treasury funds), not merely a rounding nuisance.

### Likelihood Explanation
Any relayer already permitted to submit consensus messages can trigger this by simply timing submission around a known/observed governance rate change — no privileged role or malicious governance/collusion is required, since the rate update itself is an ordinary, expected governance action, not an attack. The `LastRewardedHeight` watermark logic that prevents double-payment does nothing to segment a span by rate, so every legitimate `update_cost_per_block` call creates an exploitable window until the next relayer claim.

### Recommendation
Track the block height at which each `cost_per_block` change takes effect (e.g. a per-state-machine history/checkpoint list), and when computing a reward for a span `[baseline, latest_height]` that crosses one or more rate-change checkpoints, sum `blocks_in_subrange * rate_for_subrange` for each sub-range instead of applying a single current rate to the whole span.

### Proof of Concept
1. Governance sets `StateMachinesCostPerBlock[SM] = 10` via `update_cost_per_block`.
2. State machine `SM` advances from height 1000 to height 2000 (1000 unpaid blocks) while no relayer submits a consensus update (`LastRewardedHeight` stays at 1000).
3. Governance later raises the rate: `update_cost_per_block(SM, 1000)`.
4. A relayer submits a single `ConsensusMessage` for `SM`; `on_executed` → `calculate_reward` computes `blocks = 2000 - 1000 = 1000`, `reward = 1000 * 1000 = 1_000_000`, all paid from `TreasuryAccount` at the new rate, even though 1000 of those blocks accrued while the rate was still `10` (correct amount should have been `1000*10 = 10_000`) [7](#0-6) .
5. `LastRewardedHeight` is updated to 2000, permanently foreclosing any correction, and the treasury has paid ~100x the intended amount for that backlog.

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}

		/// Update cost per block for a state machine
		#[pallet::call_index(0)]
		#[pallet::weight(T::WeightInfo::update_cost_per_block())]
		pub fn update_cost_per_block(
			origin: OriginFor<T>,
			state_machine_id: StateMachineId,
			cost_per_block: <T as pallet_ismp::Config>::Balance,
		) -> DispatchResult {
			T::IncentivesOrigin::ensure_origin(origin)?;

			StateMachinesCostPerBlock::<T>::mutate(state_machine_id.clone(), |maybe_cost| {
				*maybe_cost = Some(cost_per_block);
			});

			Self::deposit_event(Event::<T>::StateMachineCostPerBlockUpdated {
				state_machine_id,
				cost_per_block,
			});

			Ok(())
		}
