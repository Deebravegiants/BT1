## Title
`ExternalActionSwap`/`LifiExternalAction` never returns or accounts for unspent `inputToken`, permanently locking user funds on partial-fill or exact-out swaps - (File: `contracts/external-actions/swaps/ExternalActionSwap.sol`, `contracts/external-actions/swaps/LifiExternalAction.sol`)

### Summary
`ExternalActionSwap.swap()` pulls the entire `inputAmount` from Hinkal into the swap action contract and then blindly forwards an off-chain-built `externalActionMetadata` blob to the LI.FI `router` via `LifiExternalAction.callRouter`. The function only measures `outputToken` balance change to compute `swappedAmount` and only returns/accounts for `outputToken`. Any portion of `inputToken` that the router does not consume (partial fills, exact-out routes, dust refunds from the aggregator) is left sitting in the action contract's balance with no mechanism to recover, refund, or represent it as a UTXO.

### Finding Description
In `ExternalActionSwap.swap()`: [1](#0-0) 
`inputAmount` (the full amount debited from the user's private balance via `deltaAmounts[0]`) is handed to `callRouter`, which in `LifiExternalAction` simply does `approveUnlimited(inputToken, router)` and `router.call(externalActionMetadata)`: [2](#0-1) 
`swappedAmount` is derived solely from the `outputToken` balance delta; there is no check that the router actually consumed the full `inputAmount` via its allowance. Only `outputToken` is transferred back to `msg.sender` (Hinkal) and wrapped into a `UTXO`: [3](#0-2) 

Because `inputAmount` was already transferred out of Hinkal to the action contract *before* `runAction`/`swap` executes: [4](#0-3) 
Hinkal's own per-token balance equation (`balanceDif == amountChanges[i] + utxoAmount`) is satisfied purely by that upfront transfer and is blind to what actually happens to the tokens once inside `ExternalActionSwap`: [5](#0-4) 

Neither `ExternalActionSwap`, `LifiExternalAction`, nor `ExternalActionBaseV2` expose any owner/rescue function to reclaim stray token balances: [6](#0-5) 
so any residual `inputToken` left in the action contract after a partial-fill / exact-out LI.FI route (a normal, legitimate router behavior, not requiring attacker malice) is permanently unrecoverable by the user whose private balance was debited for it.

### Impact Explanation
This is a permanent freezing of user funds: value that was validly deducted from a user's shielded balance (and thus consistent with Hinkal's on-chain balance equation) never becomes spendable again, either as returned tokens or as a new UTXO. This matches the "permanent freezing of user funds" impact class.

### Likelihood Explanation
This requires no admin/relay/owner privilege and no malicious relayer assumption. It triggers whenever the LI.FI-encoded `externalActionMetadata` route does not consume 100% of the approved `inputAmount` — a routine occurrence for exact-out swaps or multi-hop routes with slippage buffers, which the LI.FI SDK can and does generate. The Hinkal contract itself performs no cross-check that `inputAmount` was fully consumed, so nothing in the current code prevents this loss for ordinary swap usage.

### Recommendation
After `callRouter` returns, measure the `inputToken` balance held by the action contract; if any residual remains, either revert (forcing exact-in-only calldata) or return the leftover to the caller (`msg.sender`, i.e., Hinkal) as an additional UTXO output, mirroring the recommended fix in the referenced DODORouteProxy report (support exact-out mode explicitly and refund unused `fromToken`).

### Proof of Concept
1. User builds a Hinkal swap transaction (via the standard `transact` flow) specifying `inputToken` amount `X` for an exact-out LI.FI route where the router only needs to pull `Y < X` of `inputToken` to deliver the requested `outputToken` amount, refunding `X - Y` back to the caller (`LifiExternalAction`) or simply not pulling it.
2. `Hinkal._externalTransact` transfers the full `X` of `inputToken` to `LifiExternalAction` before calling `runAction`. [7](#0-6) 
3. `LifiExternalAction.callRouter` approves the router for `X` and calls the router with the exact-out calldata; the router only consumes `Y`, leaving `X - Y` of `inputToken` in `LifiExternalAction`'s balance. [8](#0-7) 
4. `swap()` computes `swappedAmount` purely from the `outputToken` delta, sends only `outputToken` back to Hinkal, and returns a single-element `UTXO[]` for `outputToken`. [9](#0-8) 
5. Hinkal's balance-equation check passes because Hinkal's own `inputToken` balance already dropped by exactly `X` (matching `amountChanges[0]`), regardless of what happened downstream. [5](#0-4) 
6. The `X - Y` remainder is now permanently stranded in `LifiExternalAction`'s token balance with no rescue path, representing a permanent loss of the user's private balance that was never returned as spendable value.

    function callRouter(
        address inputToken,
        uint256 inputAmount,
        address outputToken,
        bytes calldata externalActionMetadata
    ) internal override returns (uint256 swappedAmount) {
        uint256 balanceBefore = getERC20OrETHBalance(outputToken);

        if (inputToken == address(0)) {
            (bool success, ) = router.call{value: inputAmount}(
                externalActionMetadata
            );
            require(success, "LI.FI swap failed: native coin");
        } else {
            approveUnlimited(inputToken, router);
            (bool success, ) = router.call(externalActionMetadata);
            require(success, "LI.FI swap failed: erc-20 token");
        }

        swappedAmount = getERC20OrETHBalance(outputToken) - balanceBefore;
    }

// SPDX-License-Identifier: BUSL-1.1
pragma solidity ^0.8.17;

import {CircomData} from "../types/CircomData.sol";
import {UTXO} from "../types/UTXO.sol";
import {IExternalActionV2} from "../types/IExternalActionV2.sol";
import {OwnerHinkal} from "../OwnerHinkal.sol";

abstract contract ExternalActionBaseV2 is IExternalActionV2, OwnerHinkal {
    mapping(address => bool) internal isAllowedRecipient;

    /*
     * @dev Modifier to check if the sender is allowed to call the action
     * @dev Used to handle VolatileTokenAction and Hinkal interactions
     */
    modifier onlyAllowedRecipient() {
        require(
            isAllowedRecipient[msg.sender],
            "ExternalActionBase: sender not allowed"
        );
        _;
    }

    constructor(address[] memory _allowedRecipients) {
        for (uint i = 0; i < _allowedRecipients.length; i++) {
            isAllowedRecipient[_allowedRecipients[i]] = true;
        }
    }

    function setAllowedRecipients(
        address[] calldata recipients
    ) external onlyOwner {
        for (uint i = 0; i < recipients.length; i++) {
            require(recipients[i] != address(0), "zero address!");
            isAllowedRecipient[recipients[i]] = true;
        }
    }

    function runAction(
        CircomData calldata circomData,
        int256[] calldata deltaAmountChanges
    ) external virtual returns (UTXO[] memory utxoSet) {}
}
