### Title
Fraud detection is unconditionally disabled, causing fail-open bypass of all fraud/liveness enforcement during signup - (File: src/plans/fraud_check.rs, src/plans/mod.rs)

### Summary
`N_FRAUD_CHECKS` is hard-coded to `0`, making `Report::fraud_checks()`, `fraud_checks_strict()`, and `enabled_checks_from_config()` all return empty arrays, so `Report::fraud_detected()` and `fraud_detected_with_config()` can never report fraud regardless of the underlying RGB-Net/face_identifier signals. `detect_fraud` in `src/plans/mod.rs` is explicitly commented "FOSS: WE HAVE DELETED ALL FRAUD CHECKS" and unconditionally returns `Ok(false)`, meaning any signup, including one with obviously fraudulent biometric geometry, is routed to `SignupReason::Normal`.

### Finding Description
`FraudChecks::run` in `src/plans/fraud_check.rs` (lines 148-152) constructs a `Report {}` with no fields, since `Report` is an empty struct (`pub struct Report {}`, line 36). All of its check-related methods are hard-coded to operate on zero-length arrays because `const N_FRAUD_CHECKS: usize = 0;` (line 12) — `fraud_checks()` returns `[]` (line 68), `enabled_checks_from_config()` returns `[]` (line 78), and consequently `fraud_detected()` (`self.fraud_checks_strict().iter().any(...)` over an empty array, lines 112-114) and `fraud_detected_with_config()` (lines 88-108) can only ever yield `false`/no feedback. This is independent of whatever landmarks, bounding boxes, or occlusion/multi-face signals RGB-Net or face_identifier produce and feed into the `biometric_pipeline::Pipeline` passed to `FraudChecks::new`. The `detect_fraud` function in `src/plans/mod.rs` compounds this by unconditionally returning `Ok(false)` with a comment stating fraud checks were deliberately deleted, so the pipeline's downstream `SignupReason` classification treats every signup as `SignupReason::Normal` regardless of how egregious the captured scene is (multi-face, occluded face, etc.).

### Impact Explanation
This is a complete, unconditional bypass of biometric fraud/liveness enforcement for every signup performed by this orb-core build. Any attacker presenting an obviously fraudulent scene to the cameras (multiple faces, occluded face, photograph/spoof geometry recognized by RGB-Net) will still be classified `SignupReason::Normal` and proceed to `enroll_user`, defeating the fail-closed invariant that fraud/liveness verdicts must block enrollment. This matches a liveness/fraud-bypass class of impact under the Worldcoin/Orb bounty program, since it undermines the integrity of the identity-enrollment process itself.

### Likelihood Explanation
No special preconditions are required beyond starting a normal signup flow — the code path is unconditional and always executed (`start_signup -> biometric_pipeline -> detect_fraud -> Ok(false) -> SignupReason::Normal -> enroll_user`). This is fully repeatable on every signup attempt, since the bypass is baked into constants and function bodies rather than depending on runtime conditions, config, or attacker-controlled data beyond simply attempting a signup.

### Recommendation
Restore real fraud-check implementations backing `Report::fraud_checks()` and `enabled_checks_from_config()` (i.e., set `N_FRAUD_CHECKS` to the actual number of checks and populate `fraud_checks()`/`feedback_messages()` with genuine per-check logic derived from RGB-Net/face_identifier outputs), and update `detect_fraud` in `src/plans/mod.rs` to call `FraudChecks::run(...).fraud_detected_with_config(...)` (or equivalent) instead of unconditionally returning `Ok(false)`. Ensure fail-closed behavior: missing/invalid fraud data should count as fraud detected, consistent with the doc comment "If fraud data are missing, we assume fraud is detected" that is currently unreachable dead logic.
