### Title
Single collateral price-feed failure permanently freezes a solvent user's unrelated collateral - (File: `mainnet/contracts/market/v0-4-market.clar`)

### Summary
`collateral-remove` (and equivalently `borrow`) computes a user's health by calling `get-assets(mask)`, which resolves oracle prices for **every** collateral asset in the user's position mask via `price-multi-resolve`. If price resolution for just one of those assets fails (oracle revert, or `oracle-timestamp-fresh`/confidence check failure), the entire call aborts, blocking withdrawal of every other, unaffected collateral asset the user holds - even collateral whose own price feed is perfectly healthy. This is the same bug class as C4 [M-16]: one misbehaving asset renders unrelated backing permanently inaccessible.

### Finding Description
`get-assets` builds price data for the full user mask, not just the asset being acted on: [1](#0-0) 

Price resolution for the whole batch is all-or-nothing: `iter-price-multi` marks the batch invalid if a single `price-resolve` call fails, and `price-multi-resolve` asserts the batch is valid, propagating failure via `unwrap-panic` in `get-assets`: [2](#0-1) 

`price-resolve` itself can fail for reasons entirely out of the user's control: the oracle contract call reverting, or the staleness/legality assertion tripping: [3](#0-2) 

`collateral-remove`'s debt-bearing path calls `get-assets(position-mask)` over the user's *entire* mask before it can even evaluate whether withdrawing a specific, unrelated collateral asset is safe: [4](#0-3) 

`borrow` has the identical pattern — it calls `get-assets(mask)` across all of the user's held collateral before allowing a borrow against any single asset: [5](#0-4) 

Concretely: a user pledges two collaterals — `zUSDH` (priced via the DIA oracle) and `zUSDC` (priced via Pyth) — and has open debt. If the DIA oracle for USDH becomes unavailable or stale (`call-dia`/`resolve-dia` revert, or `oracle-timestamp-fresh` fails because the feed hasn't been updated within `max-staleness`), then `get-assets(position-mask)` reverts for *any* mask that includes the USDH bit — even when the caller only wants to withdraw the healthy `zUSDC` collateral. The withdrawal, and any borrow, is blocked entirely.

### Impact Explanation
This freezes funds that are otherwise fully solvent and unaffected by the broken oracle. The user cannot withdraw their `zUSDC` collateral (or any other collateral in the same mask) as long as the USDH price feed remains broken/stale, and there is no unprivileged escape hatch: the check happens inside the same atomic call that would perform the withdrawal, and it is keyed off the user's full mask rather than the specific asset being withdrawn. Until the DAO manually intervenes (offboards the asset / fixes the oracle / adjusts staleness), the position's non-broken collateral is permanently locked — a temporary-to-permanent freezing of funds depending on how long the oracle stays broken, matching the High/Critical "permanent freezing of funds" impact class from the reference finding.

### Likelihood Explanation
Requires only two conditions that are realistic in production: (1) a user holds ≥2 different collateral asset types simultaneously with open debt (a normal, encouraged usage pattern given the "Efficiency Groups"/multi-collateral design), and (2) one of the oracle feeds used by those assets becomes stale beyond `max-staleness` or the upstream oracle contract call reverts (DIA/Pyth downtime, decommissioning, or contract upgrade are realistic external events, not attacker-controlled manipulation of price data). No governance compromise or privileged action is needed to trigger it — only an external oracle outage, which is explicitly analogous to the "hack/upgrade/freeze" scenarios enumerated in the source report as the root-cause vector, not a data-correctness (depeg) issue.

### Recommendation
Decouple health/price evaluation from unrelated assets:
- When withdrawing/repaying a specific asset, only require a fresh price for the assets whose valuation actually changes as a result of the action, or allow a "safe mode" that skips assets not involved in the current operation when they are not needed to prove health improves.
- Provide a per-asset circuit breaker (already partially present via `disable`) that lets the DAO exclude a broken-oracle asset from the health computation (treat as zero collateral value, similar to the disabled-collateral branch already implemented in `collateral-remove`) without blocking access to a user's other collateral.
- Consider allowing withdrawal of non-debt-bearing / already-disabled collateral without needing `get-assets` over the whole mask when the removal cannot cause insolvency (e.g., partial withdraw when remaining position mask excludes the broken asset).

### Proof of Concept
1. DAO registers `zUSDH` with a DIA oracle feed (`DIA-USDH`) and `zUSDC` with a Pyth feed, both enabled as collateral, per `local-testing/contracts/registry/assets.clar` `insert`/`enable`.
2. Alice deposits `zUSDC` and `zUSDH` as collateral and borrows `USDC` against them via `borrow`, establishing `position-mask` covering both collateral bits.
3. The DIA oracle contract backing `DIA-USDH` becomes unreachable/reverts, or simply stops updating past `max-staleness` seconds.
4. Alice calls `collateral-remove` to withdraw only her `zUSDC` collateral. Because she has debt, the has-debt branch executes `get-assets position-mask`, which internally calls `price-multi-resolve` over both `zUSDH` and `zUSDC` oracle entries.
5. `price-resolve` for the USDH entry fails (`call-dia` reverts via `unwrap!` to `ERR-ORACLE-DIA`, or `oracle-timestamp-fresh` returns `false` causing `ERR-ORACLE-INVARIANT`), causing `iter-price-multi` to mark the whole batch invalid and `price-multi-resolve`/`get-assets` to abort.
6. The entire `collateral-remove` call reverts, even though the `zUSDC` withdrawal itself would have kept Alice healthy — her `zUSDC` (and any debt repayment/borrow actions gated the same way) remain frozen for as long as the USDH oracle stays broken.

(define-private (price-resolve
  (data { type: (buff 1), ident: (buff 32), callcode: (optional (buff 1)), max-staleness: uint }))
  (let ((type (get type data))
        (ident (get ident data))
        (key { type: type, ident: ident })
        (resolution (try! (resolve-price-feed type ident)))
        (price (get value resolution))
        (callcode (get callcode data))
        (final-price (try! (resolve-callcode price callcode)))
        (last-update-time (oracle-last-update key))
        (timestamp (get timestamp resolution))
        (max-staleness (get max-staleness data)))

    ;; validate price and timestamp using max-staleness from oracle data
    (asserts! (and (oracle-price-legal final-price) (oracle-timestamp-fresh timestamp last-update-time max-staleness))
              ERR-ORACLE-INVARIANT)

    ;; update timestamp if newer
    (if (> timestamp last-update-time)
        (map-set last-update key timestamp)
        false)

    (ok final-price)))

(define-private (price-multi-resolve
  (data (list 64 { type: (buff 1), ident: (buff 32), callcode: (optional (buff 1)), max-staleness: uint }))
  (aids (list 64 uint)))
  (let ((init { output: (list), valid: true, aids: aids, idx: u0 })
        (response (fold iter-price-multi data init)))
    (asserts! (get valid response) ERR-ORACLE-MULTI)
    (ok (get output response))))

(define-private (iter-price-multi
  (oracle-data { type: (buff 1), ident: (buff 32), callcode: (optional (buff 1)), max-staleness: uint })
  (acc { output: (list 64 uint), valid: bool, aids: (list 64 uint), idx: uint }))
  (let ((valid (get valid acc))
        (skip? (asserts! valid acc))
        (asset-ids (get aids acc))
        (idx (get idx acc))
        ;; resolve price - will use cache for ztokens
        (price (unwrap! (price-resolve oracle-data) (merge acc { valid: false })))
        (next (unwrap-panic (as-max-len? (append (get output acc) price) u64))))
    { output: next,
      valid: true,
      aids: asset-ids,
      idx: (+ idx u1) }))

(define-public (collateral-remove (ft <ft-trait>) (amount uint) (receiver (optional principal)) (price-feeds (optional (list 3 (buff 8192)))))
  (let ((ft-address (contract-of ft))
        (asset (try! (get-asset ft-address)))
        (asset-id (get id asset))
        (account contract-caller)
        (collateral-receiver (match receiver recv recv contract-caller))
        (position (try! (get-position account)))
        (has-debt (> (len (get debt position)) u0)))

    (asserts! (> amount u0) ERR-AMOUNT-ZERO)

    (if has-debt
        ;; HAS DEBT: Full flow with price resolution and health checks
        (let ((is-collateral-enabled (get collateral asset))
              (feeds-check (try! (write-feeds price-feeds)))
              (position-mask (get mask position))
              (pos-full (if is-collateral-enabled position (try! (get-full-position account))))
              (u-debt (accrue-user-debts (get debt pos-full)))
              (u-coll (accrue-user-collateral (get collateral pos-full)))
              (assets (get-assets position-mask))

              (current-ltvb (buff-to-uint-be (get LTV-BORROW current-group)))
              (notional-valued-assets (get-notional-evaluation { position: position, assets: assets }))
              (collateral-value (get collateral notional-valued-assets))
              (debt-value (get debt notional-valued-assets))
              (removed-asset-value (find-and-resolve-asset-value assets asset-id amount true)))
