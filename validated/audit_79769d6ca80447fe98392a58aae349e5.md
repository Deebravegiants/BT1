## Analysis

The `SimplexPaymaster` contract's `_getOraclePrice` follows the exact anti-pattern described in the report: it calls Chainlink's `latestRoundData()` unconditionally and reverts the entire transaction on stale or invalid data, with no try/catch or fallback path.

### Title
Unhandled Chainlink oracle failure causes full paymaster DoS - (File: `evm/src/utils/SimplexPaymaster.sol`)

### Summary
`SimplexPaymaster._getOraclePrice` reads `latestRoundData()` directly and reverts (`StaleOraclePrice`/`InvalidOraclePrice`) whenever the feed is stale or returns a non-positive answer, with no try/catch or secondary price source, exactly mirroring the reported ChainlinkPriceFeed pattern.

### Finding Description
`_getOraclePrice` is called for both the `nativeOracle` and every registered token's oracle inside `_tokenPrice`, which is invoked from `_fetchDetails` during ERC-4337 `_validatePaymasterUserOp`/`postOp` accounting for every single UserOperation that pays gas through this paymaster. [1](#0-0) [2](#0-1) 

If either the shared `nativeOracle` or any active token's oracle becomes "abandoned" (Chainlink stops updating it, i.e. `updatedAt` grows stale) or returns a non-positive answer, `_getOraclePrice` unconditionally reverts. Since `_fetchDetails` is reached by any unprivileged party submitting a UserOperation with paymaster data referencing that token, every gas-paying UserOp for that token (and any UserOp at all, since `nativeOracle` is shared across all tokens) reverts during validation. [3](#0-2) 

The comment on `_registerToken` confirms the only recovery path is a governance-gated re-registration — there is no permissionless fallback, no secondary oracle, and no graceful degradation: [4](#0-3) 

The same unguarded call pattern is also used in `swapAndDeposit`'s fee-recycling logic, meaning treasury-driven fee recycling is likewise DoS'd if the oracle is abandoned: [5](#0-4) 

### Impact Explanation
Because `nativeOracle` is shared across all registered tokens, a single abandoned Chainlink feed (native asset or any active token) permanently DoSes gas payment through the entire paymaster for every user, until Hyperbridge governance intervenes via `UpdateParams`/`RegisterToken`. This blocks any unprivileged relayer/bundler from getting UserOperations sponsored by this paymaster, effectively freezing usage of the contract (funds already deposited/staked in the EntryPoint become unusable for gas sponsorship) until a manual governance fix, which satisfies "route unable to deliver messages"/permanent freezing-of-funds class of impact for a Medium.

### Likelihood Explanation
Chainlink feeds being deprecated or going stale (e.g. after a network migration, feed deprecation, or extended sequencer/oracle outage) is a realistic, historically observed occurrence, and no attacker action is required — an unprivileged UserOp sender simply triggers the revert path once the feed misbehaves. Likelihood is largely dependent on external oracle health rather than an active attacker, keeping this at Medium.

### Recommendation
Wrap `latestRoundData()` calls in `_getOraclePrice` (and in `swapAndDeposit`) in a try/catch, and provide a defined fallback behavior (e.g., pause only the affected token rather than reverting for all tokens sharing `nativeOracle`, or allow permissionless emergency deactivation of a token whose oracle throws/goes stale) so a single misbehaving feed cannot brick gas payments for every token and user.

### Proof of Concept
1. Chainlink deprecates/abandons the `nativeOracle` feed configured in `SimplexPaymaster` (stops publishing rounds, so `updatedAt` ages past `maxOracleAge`).
2. Any user submits a UserOperation with `paymasterData` selecting any registered token; the EntryPoint calls `validatePaymasterUserOp` → `_fetchDetails` → `_tokenPrice` → `_getOraclePrice(nativeOracle, ...)`.
3. `_getOraclePrice` reverts with `StaleOraclePrice`, causing `_validatePaymasterUserOp` to revert and the UserOperation to fail validation.
4. This repeats for every UserOperation from every user attempting to pay gas via this paymaster with any registered token, until Hyperbridge governance pushes an `UpdateParams` request to replace `nativeOracle`. [6](#0-5)

    function _registerToken(address token, AggregatorV3Interface oracle) internal {
        if (token == address(0) || address(oracle) == address(0)) revert ZeroAddress();

        bool isNew = !tokenConfigs[token].active && address(tokenConfigs[token].tokenOracle) == address(0);

        tokenConfigs[token] = TokenConfig({
            tokenOracle: oracle,
            tokenOracleDecimals: oracle.decimals(),
            tokenDecimals: IERC20Metadata(token).decimals(),
            active: true
        });

        if (isNew) {
            registeredTokens.push(token);
        }

        emit TokenRegistered(token, address(oracle));
    }

    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
