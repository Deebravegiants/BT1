### Title
Double payment of GET-request relayer fee via race between `dispatchIncoming(GetResponse)` and `dispatchTimeOut(GetRequestTimeout)` — ([File: evm/src/core/EvmHost.sol])

### Summary
`EvmHost` tracks a GET request's fee bookkeeping in a single map, `_requestCommitments[commitment]`, but two independent, handler-restricted entry points can each pay out funds attributed to that same map without ever checking whether the *other* path has already settled the request. `dispatchIncoming(GetResponse)` pays the relayer fee on successful delivery but never clears `_requestCommitments[commitment]` [1](#0-0) . `dispatchTimeOut(GetRequestTimeout)` independently deletes `_requestCommitments[commitment]` and refunds `meta.fee` to `meta.sender`, based solely on a Merkle-Patricia non-membership proof of a `ResponseReceipts` key at a caller-chosen historical `message.height` on the counterparty state machine — it never consults `_responseReceipts` (the local record of whether the response was already delivered on this host) [2](#0-1) .

This mirrors the CVE-2018-18559 bug class: two "linked" pieces of state that should be kept consistent (the GET request's local delivery/payment status vs. its remote timeout-eligibility proof) are updated by independent code paths, and the cleanup/replay-protection routine (`dispatchTimeOut`) only inspects one of them — exactly like `packet_release` operating on only one of two applicable linked lists after a race between `fanout_add` and `bind`.

### Finding Description
`HandlerV2.handleGetRequestTimeouts` fetches a state commitment for an arbitrary previously-finalized `message.height`, checks only that `request.timeout() > state.timestamp` (i.e., that the timeout had already elapsed as of that snapshot's timestamp), and then proves *non-membership* of a `RESPONSE_RECEIPTS_STORAGE_PREFIX` key at that snapshot against the counterparty chain's state root [3](#0-2) . It performs no check against the *local* EVM host's own bookkeeping for whether a response has already been delivered and paid via `dispatchIncoming(GetResponse)` [1](#0-0) .

Because the destination chain (e.g., Hyperbridge/pallet-ismp) may process and store its own response receipt for the GET request at a height *later* than the earliest height whose timestamp already exceeds `request.timeout()`, a relayer can legitimately obtain two independent, individually-valid proofs for the same `commitment`:
1. A membership/storage proof (against a later or different state) sufficient to satisfy `handleGetResponses`, which calls `dispatchIncoming(GetResponse)` and pays the relayer fee out of `_requestCommitments[commitment].fee` — without clearing that map entry.
2. A non-membership proof against an earlier snapshot height (timestamp ≥ `request.timeout()` but predating the counterparty's own response-receipt write) sufficient to satisfy `handleGetRequestTimeouts`, which calls `dispatchTimeOut`, deletes `_requestCommitments[commitment]`, and refunds `meta.fee` to `meta.sender`.

Nothing prevents both messages from being included in the same `batchCall` (or two separate transactions), because `dispatchTimeOut` never checks `_responseReceipts[commitment]` (populated by the response path) before paying out and deleting the fee record. The two code paths that must stay mutually exclusive for a given `commitment` — "response delivered & fee paid" vs. "request never answered & fee refunded" — are enforced by disjoint, independently-triggerable proofs instead of a shared, atomically-checked state flag.

### Impact Explanation
This allows theft/duplication of protocol fee-token funds: the same GET request's fee can be paid out twice — once to the delivering relayer (`GetRequestHandled`) and once refunded to the original `meta.sender` via the timeout path (`GetRequestTimeoutHandled`) — draining the fee token balance held by `EvmHost` beyond what was ever escrowed for that request. This is a concrete theft/loss-of-funds bug reachable by any unprivileged relayer who can source both a delivery proof and a stale non-membership proof for the same outstanding GET request, satisfying the "concrete theft ... of funds" bar in scope.

### Likelihood Explanation
Exploitability depends on the relayer being able to obtain a non-membership proof at a snapshot height whose timestamp is ≥ `request.timeout()` but that predates the counterparty chain's write of its own response receipt for that GET request. Because Hyperbridge state commitments accumulate over time and old finalized heights remain queryable/provable indefinitely (via `stateMachineCommitment(height)`), and because there is no requirement that `message.height` be the *most recent* commitment, an adversarial or merely uncoordinated relayer set can pick an older height that already crosses the timeout threshold while the response is processed at a later height — a realistic race given that request timeout windows and Hyperbridge's response-processing latency are independently timed. Any relayer who submits `handleGetResponses` first (or races to submit both in the same batch) can trigger the double-payout.

### Recommendation
`dispatchTimeOut(GetRequestTimeout, ...)` must check `_responseReceipts[commitment]` (or an equivalent locally-owned delivered flag) and reject with a "response already delivered"-style error if a response receipt already exists for that commitment, before deleting `_requestCommitments` and refunding the fee. Symmetrically, `dispatchIncoming(GetResponse)` should be the single writer that finalizes `_requestCommitments[commitment]` (e.g., deleting it after paying the fee), so both consumers agree on one canonical "settled" state instead of two independently-provable, disjoint code paths that each unconditionally act on the same fee record.

### Proof of Concept
1. A user's app dispatches a GET request from `EvmHost` A to a Hyperbridge-tracked destination, escrowing `fee` in `_requestCommitments[commitment]`.
2. After `request.timeout()`, an old, previously-finalized `StateCommitment` at `message.height0` (timestamp ≥ `request.timeout()`, but predating the destination/Hyperbridge recording a response receipt for `commitment`) is used to build a valid non-membership proof of the `ResponseReceipts` key for `commitment`.
3. Separately (or in the same relayer's batch), a later, valid storage proof showing the query result is used to satisfy `handleGetResponses`, which calls `EvmHost.dispatchIncoming(GetResponse, relayer)`, paying `fee` to `relayer` (`EvmHost.sol:842-845`) without touching `_requestCommitments[commitment]`.
4. The relayer then submits `handleGetRequestTimeouts` with the stale non-membership proof from step 2; it passes `request.timeout() > state.timestamp` and the non-membership check (since, at `message.height0`, no response receipt yet existed), calling `EvmHost.dispatchTimeOut`, which deletes `_requestCommitments[commitment]` and refunds `meta.fee` to `meta.sender` (`EvmHost.sol:862-877`).
5. Net effect: `fee` has been paid out twice for the same GET request commitment — once to the relayer, once refunded to `meta.sender` — draining the `EvmHost`'s fee-token balance.

Note: I was unable to fully trace, within the available tool budget, the exact liveness/latency guarantees pallet-ismp provides between "response processed on Hyperbridge" and "state commitment finalized with a timestamp past `request.timeout()`," so the precise window size for obtaining a qualifying stale height is not independently confirmed from code alone — this would need empirical/timing verification against a live or test Hyperbridge deployment.

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
