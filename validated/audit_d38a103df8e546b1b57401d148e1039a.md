### Title
Iris-signature anti-fraud proof omits signup nonce/session binding, enabling signature replay across signups - (File: `src/plans/enroll_user.rs`)

### Summary
`enroll_user::make_signature` computes the SHA256-based, secure-element-signed "iris code signature" that is sent to the signup backend as proof-of-origin for a signup attempt. The digest it signs is built only from the Orb ID, user ID, and the iris pipeline codes/versions — it never incorporates the per-attempt `signup_id` or any incrementing nonce/timestamp. This mirrors the Astaria `commitToLien` bug class: a signed authorization artifact that lacks a consumable nonce, so the same signed value remains valid and reusable across multiple distinct authorization events instead of being bound to (and invalidated after) a single one.

### Finding Description
The signature is computed in `make_signature`: [1](#0-0) 

Only `ORB_ID`, `user_qr_code.user_id`, and the iris pipeline (`ir_net_version`, `iris_version`, iris codes/masks for both eyes) are hashed and signed via `secure_element::sign`. The resulting `signature` is submitted to the backend alongside `signup_id`, but `signup_id` itself is **not** part of the signed payload: [2](#0-1) 

The `signup_id` is generated fresh per signup attempt and passed as a separate multipart form field / URL path segment, so nothing cryptographically ties a given signature to the specific `signup_id` it was produced for. As long as the user id and iris codes/versions used for signing are held constant (e.g., a retried signup for the same user after `enroll_user::Plan::run`'s retry loop, or any flow where the same capture pipeline output is reused for a second submission), the identical signature blob remains a valid, backend-acceptable authorization value for a different `signup_id`.

This is structurally analogous to the Astaria issue: `AstariaRouter.validateCommitment` never checks a strategist nonce bound to the signed commitment, so the same signed commitment can be replayed indefinitely. Here, the analogous "nonce" that should scope the signature to one authorization event (`signup_id`) is simply absent from what gets signed.

### Impact Explanation
Because the anti-fraud signature is not bound to the `signup_id` it is presented with, a signature captured for one signup attempt can be resubmitted (replayed) against a different `signup_id` for the same user/iris-code payload without re-invoking the secure element. This weakens the backend's ability to use the signature as strong per-attempt proof that "this specific signup request" originated from a legitimate, freshly-signed Orb operation, enabling potential cross-signup replay of biometric enrollment attempts.

### Likelihood Explanation
Exploitation requires the ability to intercept/replay the `signature` and `codes` form fields against the signup endpoint with an alternate `signup_id` — reachable by anyone able to interact with the signup HTTP flow (the orb-to-backend channel), without needing any privileged operator/admin keys, mirroring the "malicious normal user abusing valid protocol flows" profile.

### Recommendation
Include the `signup_id` (and/or a fresh per-attempt nonce/timestamp) inside the data hashed by `make_signature` before signing, so the resulting signature is cryptographically bound to exactly one signup attempt and cannot be replayed for a different `signup_id`.

### Proof of Concept
1. Trigger a signup for `user_id = U` with iris pipeline output `P`; capture the resulting `signature = Sign(ORB_ID || U || P)` and observe it is submitted with `signup_id = S1` via `signup_post::request`.
2. Trigger (or intercept) a second signup request for the same `user_id = U` and same pipeline output `P`, yielding a new `signup_id = S2`.
3. Because `make_signature` never includes `signup_id` in the signed digest, the signature from step 1 is byte-for-byte valid to submit alongside `signup_id = S2`, since nothing in the signed material differs between the two requests.

fn make_signature(user_qr_code: &qr_scan::user::Data, pipeline: &Pipeline) -> Result<String> {
    let mut ctx = Context::new(&SHA256);
    ctx.update(ORB_ID.as_str().as_bytes());
    ctx.update(user_qr_code.user_id.as_bytes());
    ctx.update(pipeline.v2.ir_net_version.as_bytes());
    ctx.update(pipeline.v2.iris_version.as_bytes());
    ctx.update(pipeline.v2.eye_left.iris_code.as_bytes());
    ctx.update(pipeline.v2.eye_left.mask_code.as_bytes());
    ctx.update(pipeline.v2.eye_left.iris_code_version.as_bytes());
    ctx.update(pipeline.v2.eye_right.iris_code.as_bytes());
    ctx.update(pipeline.v2.eye_right.mask_code.as_bytes());
    ctx.update(pipeline.v2.eye_right.iris_code_version.as_bytes());
    let signed = secure_element::sign(ctx.finish())?;
    Ok(BASE64.encode(&signed))
}
