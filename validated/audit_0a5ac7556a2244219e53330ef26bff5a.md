### Title
OAuth `begin_auth` fails to validate the `shop` domain, enabling forced OAuth completion / session fixation via redirect to an attacker-controlled host - ([File: lib/shopify_api/auth/oauth.rb])

### Summary
`ShopifyAPI::Auth::Oauth.begin_auth` builds the Shopify authorization redirect URL directly from the caller-supplied `shop` string without validating that it is a trusted Shopify domain. Every other method in this gem that accepts a raw `shop` parameter and uses it to reach an external host (`ClientCredentials.client_credentials`, `RefreshToken.refresh_access_token`, `TokenExchange.migrate_to_expiring_token`) explicitly calls `Utils::ShopValidator.sanitize!(shop)` first — `begin_auth` is the one exception.

### Finding Description
`begin_auth` takes an untrusted `shop:` argument (the docs' own example reads it straight from a request header/param, i.e. attacker-controlled) and passes it unchecked into `auth_base_uri`: [1](#0-0) [2](#0-1) 

```ruby
auth_route = auth_base_uri(shop) + "/oauth/authorize?#{query_string}"
...
def auth_base_uri(shop)
  return "https://#{shop}/admin" unless ...
```

Compare this to the sibling methods that all sanitize `shop` before it is used to determine which host receives sensitive data: [3](#0-2) [4](#0-3) [5](#0-4) 

The identity binding that is broken is: **host that receives the OAuth initiation (client_id, redirect_uri, and the CSRF `state` nonce) == a trusted Shopify domain (`ShopValidator::TRUSTED_SHOPIFY_DOMAINS`)**. `begin_auth` never enforces this equality, whereas `ShopValidator.sanitize!` (used by the sibling auth methods) does: [6](#0-5) 

Because `begin_auth` sets the CSRF `state` cookie on the victim's browser *before* redirecting, and then redirects the browser to an attacker-chosen host with `state`, `client_id`, and `redirect_uri` all present in the query string, an attacker who controls that host can capture the `state` nonce. The attacker can then start a *real* Shopify OAuth authorization using their own store, supplying the captured `state` value and the app's real `redirect_uri`. Shopify will legitimately sign the resulting callback (`code`, `shop`, `state`, `timestamp`, `host`, `hmac`) for the attacker's own shop. When the victim's browser (which still carries the `state` cookie) is directed to that callback URL, `validate_auth_callback` will pass every check — HMAC is valid (real Shopify signature) and the state comparison passes (attacker deliberately supplied the leaked nonce) — completing OAuth for the **attacker's shop** inside the **victim's session**: [7](#0-6) 

This is a forced OAuth completion / session fixation attack, requires no access to `api_secret_key`, no leaked credentials, and no privileged account — only that the app pass a user-controlled `shop` value to `begin_auth`, which is exactly the documented usage pattern shown in this gem's own docs (`shop = request.headers["Shop"]`).

### Impact Explanation
This allows an unprivileged internet user to fixate a victim's app session/browser to an OAuth grant for a shop the attacker controls, satisfying the "session fixation or forced OAuth completion" High-impact category. Depending on how the host app uses the resulting session (e.g., using it as the "current shop" context for subsequent victim actions), this can lead to the victim unknowingly interacting with, or leaking data into, the attacker's Shopify store.

### Likelihood Explanation
Reachable by any unauthenticated internet user who can get a merchant/browser to click a link to the app's login route with an attacker-controlled `shop` value — consistent with the documented usage pattern in `docs/usage/oauth.md`. No secrets, tokens, or privileged access are required; the only asymmetry exploited is the gem's own inconsistent validation (three sibling methods validate `shop`, this one does not).

### Recommendation
In `ShopifyAPI::Auth::Oauth.begin_auth` (and `auth_base_uri`), validate/sanitize `shop` with `Utils::ShopValidator.sanitize!(shop)` (or equivalent) before constructing `auth_route`, mirroring the behavior already present in `ClientCredentials.client_credentials`, `RefreshToken.refresh_access_token`, and `TokenExchange.migrate_to_expiring_token`.

### Proof of Concept
1. App implements the documented pattern: `ShopifyAPI::Auth::Oauth.begin_auth(shop: params[:shop], redirect_path: "/auth/callback")`.
2. Attacker sends victim a link to the app's login route with `shop=evil.example.com`.
3. `begin_auth` sets the `state` cookie (nonce `N`) on the victim's browser, then returns `auth_route = "https://evil.example.com/admin/oauth/authorize?client_id=...&redirect_uri=https://legit-app.com/auth/callback&state=N&..."`, and the app redirects the victim there — leaking `N`, `client_id`, and `redirect_uri` to the attacker's server.
4. Attacker manually visits Shopify's real authorize endpoint for their own store using the leaked `redirect_uri` and `state=N`, approving app installation.
5. Shopify redirects to `https://legit-app.com/auth/callback?code=<attacker_code>&shop=<attacker_shop>&state=N&timestamp=...&host=...&hmac=<valid>`.
6. Attacker causes the victim's browser (which still holds the `state=N` cookie) to load this callback URL.
7. `Oauth.validate_auth_callback` passes HMAC and state checks and completes OAuth for the attacker's shop inside the victim's session.

        def begin_auth(shop:, redirect_path:, is_online: true, scope_override: nil)
          scope = if scope_override.nil?
            ShopifyAPI::Context.scope
          elsif scope_override.is_a?(ShopifyAPI::Auth::AuthScopes)
            scope_override
          else
            ShopifyAPI::Auth::AuthScopes.new(scope_override)
          end

          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = SecureRandom.alphanumeric(NONCE_LENGTH)

          cookie = SessionCookie.new(value: state, expires: Time.now + 60)

          query = {
            client_id: ShopifyAPI::Context.api_key,
            scope: scope.to_s,
            redirect_uri: "#{ShopifyAPI::Context.host}#{redirect_path}",
            state: state,
            "grant_options[]": is_online ? "per-user" : "",
          }

          query_string = URI.encode_www_form(query)
          auth_route = auth_base_uri(shop) + "/oauth/authorize?#{query_string}"

          { auth_route: auth_route, cookie: cookie }
        end

        def validate_auth_callback(cookies:, auth_query:)
          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::InvalidOauthError, "Invalid OAuth callback." unless Utils::HmacValidator.validate(auth_query)
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = cookies[SessionCookie::SESSION_COOKIE_NAME]
          raise Errors::NoSessionCookieError unless state

          raise Errors::InvalidOauthError,
            "Invalid state in OAuth callback." unless state == auth_query.state

          null_session = Auth::Session.new(shop: auth_query.shop)
          body = {
            client_id: Context.api_key,
            client_secret: Context.api_secret_key,
            code: auth_query.code,
            expiring: Context.expiring_offline_access_tokens ? 1 : 0, # Only applicable for offline tokens
          }

          client = Clients::HttpClient.new(session: null_session, base_path: "/admin/oauth")
          response = begin
            client.request(
              Clients::HttpRequest.new(
                http_method: :post,
                path: "access_token",
                body: body,
                body_type: "application/json",
              ),
            )
          rescue ShopifyAPI::Errors::HttpResponseError => e
            raise Errors::RequestAccessTokenError,
              "Cannot complete OAuth process. Received a #{e.code} error while requesting access token."
          end

          session_params = T.cast(response.body, T::Hash[String, T.untyped]).to_h
          session = Session.from(shop: auth_query.shop,
            access_token_response: Oauth::AccessTokenResponse.from_hash(session_params))

          cookie = if Context.embedded?
            SessionCookie.new(
              value: "",
              expires: Time.now,
            )
          else
            SessionCookie.new(
              value: session.id,
              expires: session.expires ? session.expires : nil,
            )
          end

          { session: session, cookie: cookie }
        end

        sig { params(shop: String).returns(String) }
        def auth_base_uri(shop)
          return "https://#{shop}/admin" unless defined?(DevServer) && shop.include?(".my.shop.dev")

          # For first-party apps in development only, we leverage DevServer to build the admin base URI
          admin_web = T.unsafe(Object.const_get("DevServer")) # rubocop:disable Sorbet/ConstantsFromStrings
            .new("admin-web")
          admin_host = admin_web.host!(nonstandard_host_prefix: "admin")
          shop_name = shop.split(".").first

          "https://#{admin_host}/store/#{shop_name}"
        end
