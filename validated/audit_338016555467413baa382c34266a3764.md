## Analysis

The reported bug class — an unprivileged address being blacklisted by a stablecoin (e.g. USDT/USDC) permanently freezing funds because the payout function hard-codes `msg.sender` as recipient with no way to redirect — has a direct analog in `FeeVault.claim()`.

### Title
Creator fee payouts in `FeeVault.claim()` are permanently frozen if the creator's address is blacklisted by the USDC asset - (File: `packages/contracts/src/FeeVault.sol`)

### Summary
`FeeVault.claim()` pays out a creator's accrued protocol fees by transferring USDC directly to `msg.sender`, with no `receiver` parameter. Alt.fun's fee layer uses real USDC (6dp) as the settlement asset for buy/sell fees.

### Finding Description
Every buy/sell in `Zap` skims a fee and forwards it to `FeeVault` via `_accrueFee`, crediting `creatorBalance[creator]` inside `accrue()` [1](#0-0) . The only way for a creator to retrieve this already-earned balance is `claim()`:

```solidity
function claim() external nonReentrant returns (uint256 amount) {
    FeeVaultStorage storage $ = _s();
    amount = $.creatorBalance[msg.sender];
    if (amount == 0) revert NothingToClaim();
    $.creatorBalance[msg.sender] = 0;
    $.totalAccruedCreator -= amount;
    $.usdc.safeTransfer(msg.sender, amount);
    emit CreatorFeesClaimed(msg.sender, amount);
}
``` [2](#0-1) 

There is no `receiver`/`to` argument — the payout is hard-coded to `msg.sender`, exactly the shape flagged in the external report. Because `$.usdc` is a real, Circle-issued USDC token (per the protocol's own docs and comments describing "real USDC, 6dp") [3](#0-2) , USDC's centralized blacklist (`blacklister` role freezing an address from sending/receiving) applies to this flow. If a creator's wallet is ever blacklisted by Circle for any reason unrelated to alt.fun (e.g., flagged for sanctions/fraud elsewhere), every call to `claim()` from that address reverts at `$.usdc.safeTransfer(msg.sender, amount)`, and since the whole transaction reverts, `creatorBalance[msg.sender]` is never reset — the balance remains permanently stuck in `FeeVault` with no alternate withdrawal path. This mirrors `claimProtocol()`, which at least pays a separately admin-configurable `feeTo` address (so protocol funds can be redirected around a blacklist) [4](#0-3)  — but creators have no equivalent redirect mechanism.

### Impact Explanation
Creator fee earnings accrue continuously from all buy/sell trading of a launched token (0.25% creator share, per `docs/contracts-scope.md`) . Once a creator's address is USDC-blacklisted, that balance is permanently unrecoverable — no admin function exists to reassign a creator's `creatorBalance` to a different address or to claim on their behalf. This is a permanent freeze of legitimately earned creator funds, consistent with the High-severity classification in the source report.

### Likelihood Explanation
This requires no privileged action or bug in alt.fun's own logic — it only requires the creator's wallet to be blacklisted by USDC's issuer (Circle), an event entirely outside alt.fun's control but realistic given USDC's centralized freeze capability. Any token creator (an unprivileged, permissionless role — anyone can call `Zap.createToken`) is exposed the moment they've earned any fees.

### Recommendation
Add a `claim(address receiver)` (or `claimTo`) variant, or an owner/creator-designated "fallback recipient" mechanism, so a creator can redirect payout to an unblacklisted address, analogous to how `claimProtocol()` already benefits from a separately settable `feeTo`.

### Proof of Concept
1. Creator `C` launches a token via `Zap.createToken`, and multiple trades accrue creator fees into `FeeVault.creatorBalance[C]` via `_accrueFee` → `FeeVault.accrue` [5](#0-4) .
2. Circle adds `C` to USDC's blacklist (independent real-world event).
3. `C` calls `FeeVault.claim()`; `$.usdc.safeTransfer(msg.sender, amount)` reverts because USDC's `transfer`/`transferFrom` checks the blacklist and blocks transfers to `C` [2](#0-1) .
4. The revert unwinds `creatorBalance[msg.sender] = 0` and `totalAccruedCreator -= amount`, so the balance persists in storage but can never be withdrawn — `C`'s entire accrued fee balance is permanently frozen in `FeeVault` with no recovery path.

    function accrue(
        address token,
        address creator,
        uint256 creatorAmount,
        uint256 protocolAmount,
        bool isBuy
    ) external onlyDepositor {
        FeeVaultStorage storage $ = _s();
        if (creatorAmount > 0) {
            if (creator == address(0)) revert ZeroAddress();
            $.creatorBalance[creator] += creatorAmount;
            $.totalAccruedCreator += creatorAmount;
            $.lifetimeCreatorEarned[creator] += creatorAmount;
        }
        if (protocolAmount > 0) {
            $.protocolBalance += protocolAmount;
            $.lifetimeProtocolEarned += protocolAmount;
        }
        if ($.usdc.balanceOf(address(this)) < $.totalAccruedCreator + $.protocolBalance) {
            revert UnderfundedAccrual();
        }
        emit FeeAccrued(token, creator, creatorAmount, protocolAmount, isBuy);
    }
```
