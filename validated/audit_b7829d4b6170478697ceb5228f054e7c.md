### Title
`liquidate` gives the liquidator no bound on collateral received, so a stale quote can make them overpay for seized collateral - (File: contracts/controller/src/positions/liquidation/plan.rs)

### Summary
`Controller::liquidate(liquidator, account_id, debt_payments, seize_mode)` lets the caller commit debt-token payment amounts, but provides no parameter to bound the minimum collateral (or maximum effective price) they accept in return. The seizure plan is fully recomputed at execution time from current oracle prices and accrued indexes. A liquidator who signs a transaction based on `get_liquidation_estimate` can have it included after a price/index update that shrinks the seized collateral for the same payment, forcing them to pay more than intended per unit of collateral — the same bug class as the Kairos `useLoan` report, adapted to a liquidation that lacks a min-received bound rather than a max-price bound.

### Finding Description
The liquidation entrypoint accepts only `debt_payments: Vec<HubPayment>` and a `SeizeMode`; there is no `min_seized`, `min_received_usd`, or `max_price` argument [1](#0-0) . The plan is rebuilt inside the same call via `build_liquidation_plan`, which recomputes `total_collateral`, `weighted_collateral`, and `health_factor` from `risk::calculate_account_risk_totals` using Context-cached strict oracle prices and indexes read at execution time [2](#0-1) . The quote size and bonus are likewise derived at execution from the live snapshot via `estimate_liquidation_amount` / `liquidation_at_target` [3](#0-2) .

When the quoted repayment is the full debt, nothing is trimmed: the controller pulls each offered amount and only refunds the excess above each leg's debt (`offered` is aggregated and passed to `apply_liquidation_repayments`) [4](#0-3) . The collateral side is then recomputed (`calculate_seized_collateral`, `scale_seizures_to_received`) at whatever the prices say at inclusion [5](#0-4) . The documented behavior confirms the drift: "Execution can differ from an estimate because prices, indexes and measured token delivery can change" [6](#0-5) .

So a liquidator simulates `get_liquidation_estimate`, sees seizure worth e.g. 105% of payment, signs `liquidate` offering the full debt, and an oracle price update (collateral down / debt up, or a debt index accrual flipping the close band) lands in the same or an earlier ledger. The tx still succeeds because HF < 1 remains true, pulls the offered debt tokens, but the seizure legs — recomputed pro rata at the new prices and rounded down to whole units — deliver materially less value, or in the whole-unit sub-3-decimal case can even be repriced upward to a worse effective bonus. The liquidator has no way to make the call revert when the realized price is worse than what they signed for.

### Impact Explanation
Direct loss of liquidator funds: the liquidator's debt-token payment is pulled and burned against the account's debt, while the collateral received is valued at inclusion-time prices, which can be lower than at signing with no recourse or bound. In the worst case (a leg whose seizure rounds to zero is dropped), a payment can seize nothing on some legs while the repayment is still credited. This is theft/loss of user funds caused by missing execution-bound input, classified Medium: it requires an adverse price/index movement between simulation and inclusion rather than an action the victim controls.

### Likelihood Explanation
Medium. Stellar has no reorgs, so the original trigger doesn't apply verbatim, but the mechanism doesn't need one: Soroban transactions execute against ledger state at inclusion, and Reflector/RedStone price updates and millisecond-chunked index accrual land continuously. Any liquidation signed from a simulation is inherently a stale quote; bots are explicitly told to re-simulate after every competing liquidation, acknowledging quote drift [7](#0-6) . A competing liquidation or an oracle tick that drops collateral value before inclusion realizes the loss. Contract liquidators cannot hedge this in-protocol because there is no bound parameter to encode.

### Recommendation
Add a minimum-received bound to `liquidate`, e.g. `min_seized_usd_wad: i128` (or a per-leg `min_seized: Vec<HubPayment>` checked against the computed `seized` vector before any token moves), and revert with a dedicated error when the execution-time plan would deliver less. Equivalent alternatives: accept a `max_repayment_usd` cap scaled down with the realized price, or let the caller pin an expected `bonus_bps`/`proportion_seized` floor. Extend `get_liquidation_estimate` callers to pass the estimate's values as the bound so signed transactions are atomic with their quotes.

### Proof of Concept
1. Borrower ALICE supplies $10,000 USDC and borrows ~$9,524 ETH-denominated debt; HF < 1, so `is_liquidatable(account_id)` is true.
2. Liquidator CAROL calls `get_liquidation_estimate(account_id, [(eth_key, 3_0000000)], Transfer)`; it returns `seized_collaterals = [(USDC, 100_000_000_000)]` with a 5% bonus — exactly as in `test_liquidation_estimate_matches_execution_on_an_insolvent_over_offer` [8](#0-7) .
3. CAROL signs `liquidate(CAROL, account_id, [(eth_key, 3_0000000)], Transfer)` expecting ~$5,000 of USDC net.
4. Before inclusion, a Reflector price update drops USDC 20% (or a RedStone tick lands). `build_liquidation_plan` recomputes `total_collateral` at the new strict price [9](#0-8) ; the backed quote `floor(C / (1 + base))` still pulls CAROL's offered ETH up to the new quote, but the pro-rata seizure now delivers the same nominal USDC worth 20% less USD — or fewer whole units after `scale_seizures_to_received` — while CAROL's payment is unchanged.
5. The call succeeds; CAROL paid $X of debt tokens for collateral now worth below her payment minus resource fees. No parameter existed to bound the outcome — `liquidate` takes only `(liquidator, account_id, debt_payments, seize_mode)` [10](#0-9) .

pub(crate) fn estimate_liquidation_amount(
    env: &Env,
    snap: &LiquidationSnapshot,
    bounds: BonusBounds,
    curve: &LiquidationCurve,
) -> (Wad, Bps) {
    let scaled_bonus = calculate_linear_bonus_with_target(
        env,
        snap.hf,
        bounds.base,
        bounds.max,
        curve,
        curve.target_hf,
    );

    let bonus = match max_hf_preserving_bonus_bps(snap) {
        None => scaled_bonus,
        Some(_) if snap.total_collateral < snap.total_debt => {
            let one_plus_base = Wad::ONE.checked_add(env, bounds.base.to_wad(env));
            let backed = snap.total_collateral.div_floor(env, one_plus_base);
            return (backed.min(snap.total_debt), bounds.base);
        }
        Some(cap) if cap < bounds.base.raw() => {
            return (snap.total_debt, Bps::from(cap.max(0)));
        }
        Some(cap) => Bps::from(scaled_bonus.raw().min(cap)),
    };

    let ideal = liquidation_at_target(env, snap, bonus, curve.target_hf);

    let remaining_debt = snap.total_debt.checked_sub(env, ideal);
    if remaining_debt > Wad::ZERO && remaining_debt < Wad::from(BAD_DEBT_USD_THRESHOLD) {
        return (snap.total_debt, bonus);
    }

    (ideal, bonus)
}
