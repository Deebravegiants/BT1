### Title
Attacker-supplied route executes arbitrary pool code beneath the caller's signed authorization, draining wallet tokens unrelated to the swap — ([File: contracts/controller/src/strategies/swap.rs])

### Summary
The Joker advisory is about a tool that locates and executes code supplied by an untrusted repository before doing its nominal job. The lending analog is the router strategy path: the controller forwards a fully caller-supplied `swap_xdr` program to the swap aggregator, and the aggregator invokes whatever pool addresses the payload's `assets` registry names — there is no venue or pool allowlist. A malicious "pool" contract placed on that call stack runs inside the transaction the victim authorizes, and token transfers it issues from the victim are recorded as children of the victim's signed auth entry. If the victim signs the simulated tree, the rogue pool drains arbitrary tokens from the victim's wallet — funds that were never routed, never listed, and never bounded by the payload's `min_out` or the controller's risk gates.

### Finding Description
`multiply`, `swap_collateral`, `swap_debt`, and `repay_debt_with_collateral` all funnel through `swap_tokens`, which passes the caller's `swap` bytes verbatim to `router.execute_strategy` after granting one exact input transfer [1](#0-0) . On the router side, `dispatch_hop` resolves the hop's pool from the payload-supplied address registry and invokes the venue adapter against it; the venue enum is fixed, but the contract address called is attacker-controlled [2](#0-1) . The threat model confirms the router "calls the pool and token addresses its payload names and keeps no allowlist of them," so third-party code runs below the caller's authorization, and a transfer it makes from the caller "executes if the caller signs that tree" [3](#0-2) . The harness test `rogue_hop_pool_transfer_joins_caller_auth_tree.rs` demonstrates the mechanism end-to-end: an `UnlistedPoolRouter` double invokes the payload-named `hop_pool`, whose `swap` performs `token.transfer(victim → attacker)` of an unlisted wallet token, and recording mode attaches that theft as a child of the caller's `swap_collateral` auth entry [4](#0-3) .

### Impact Explanation
Theft of user funds: the rogue venue can transfer any spendable token from the caller's wallet to an attacker address, and the stolen amount is unbounded — the payload `min_out` check, the controller's `RouterOverspend`/`NoSwapOutput` measurements, and the final health/collateral gates only cover the routed token pair, not arbitrary wallet assets [5](#0-4) . The test shows Alice losing her entire `WALLET_BALANCE` of an unrelated token while her collateral swap still succeeds with fair output [6](#0-5) . This meets "theft of user funds."

### Likelihood Explanation
Exploitation requires a crafted `swap_xdr` and a victim who signs the poisoned authorization tree — e.g., a malicious or compromised route source, or a manipulated quote — since non-root auth recording mode silently attaches the rogue transfer under the caller's entry during simulation [7](#0-6) . No protocol privilege is needed by the attacker; only a deployed contract and a payload that names it. The defense today is entirely client-side ("a client must decode the route it signs and refuse an authorization tree with any other child"), so any wallet or integration that signs simulated auth trees without inspecting children is exploitable [8](#0-7) .

### Recommendation
Constrain the code a route can execute: maintain an on-chain allowlist of venue pool/share-token addresses (or venue-specific pool registries) in the aggregator and reject payload `assets` entries that are not registered for their venue, analogous to Joker's fix of only trusting `~/.jokerd` rather than project-local files. Short of that, the controller could verify the route's pool addresses against per-token market configuration, and documentation should be elevated so integrators enforce the "exactly one child auth entry" invariant before signing.

### Proof of Concept
1. Attacker deploys `RogueHopPool` whose `swap()` calls `token.transfer(victim, attacker, victim_balance)` on an unrelated wallet token [9](#0-8) .
2. Attacker serves the victim a route for `swap_collateral` whose `assets` registry names `RogueHopPool` as the hop pool; the victim calls `controller.swap_collateral(caller, account_id, token_in, amount_in, token_out, route)`.
3. The controller authorizes its single input transfer and calls `router.execute_strategy`, which invokes the attacker's pool [10](#0-9) .
4. Simulation records the wallet-draining transfer as a child of the victim's `swap_collateral` auth entry; the victim signs the tree and the theft executes — confirmed by the harness test asserting the recorded tree contains the stolen transfer and `wallet(alice) == 0` [11](#0-10) .

    pub fn execute_strategy(env: Env, sender: Address, total_in: i128, swap_xdr: Bytes) -> i128 {
        sender.require_auth();
        let route = RoutedSwap::from_xdr(&env, &swap_xdr).expect("route must decode");
        let router = env.current_contract_address();
        token::Client::new(&env, &route.token_in).transfer(&sender, &router, &total_in);
        let _: Val = env.invoke_contract(&route.hop_pool, &symbol_short!("swap"), vec![&env]);
        token::Client::new(&env, &route.token_out).transfer(&router, &sender, &route.min_out);
        route.min_out
    }
}

/// Attacker-deployed "pool". `amount == 0` is the benign control.
#[contract]
pub struct RogueHopPool;

#[contractimpl]
impl RogueHopPool {
    pub fn __constructor(env: Env, victim: Address, token: Address, to: Address, amount: i128) {
        env.storage()
            .instance()
            .set(&symbol_short!("PLAN"), &(victim, token, to, amount));
    }

    pub fn swap(env: Env) {
        let (victim, wallet_token, to, amount): (Address, Address, Address, i128) = env
            .storage()
            .instance()
            .get(&symbol_short!("PLAN"))
            .expect("plan is set by the constructor");
        if amount > 0 {
            token::Client::new(&env, &wallet_token).transfer(&victim, &to, &amount);
        }
    }
