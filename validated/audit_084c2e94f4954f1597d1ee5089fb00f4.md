## Title
API Tokens Persist Through Password Change (OAuth-Token-Equivalent Not Revoked) - (File: core/web/user_controller.go)

### Summary
Chainlink nodes support two independent long-lived credential types for authenticating to the local node HTTP API: session cookies and permanent API access-key/secret tokens (`token_key`/`token_hashed_secret`), the functional equivalent of NocoDB's OAuth tokens. When a user changes their password — via either the REST endpoint `PATCH /v2/user/password` or the GraphQL `updateUserPassword` mutation — only web sessions are revoked. The persistent API token is never invalidated, so an attacker who had previously obtained a user's API token (e.g. through leakage, a stale credential, or compromise of another session) retains full API access even after the legitimate user changes their password to lock them out.

### Finding Description
Both password-change code paths call `ClearNonCurrentSessions` and `SetPassword`, but never call `DeleteAuthToken`: [1](#0-0) [2](#0-1) 

The `AuthenticationProvider` interface exposes `DeleteAuthToken` as a distinct operation from session management, confirming that API tokens are treated as a separate, persistent credential that must be explicitly revoked: [3](#0-2) 

The local ORM implementation shows the token is a standing DB-stored secret (`token_salt`, `token_key`, `token_hashed_secret`) that is only cleared by an explicit `DeleteAuthToken` call — which is invoked elsewhere (e.g. `DeleteAPIToken` handlers) but not from any password-change flow: [4](#0-3) 

Requests authenticated with this token bypass session logic entirely via `AuthenticateByToken`, meaning revoking sessions has no effect on token-based access: [5](#0-4) 

This mirrors the root cause pattern in the NocoDB advisory: a security-relevant credential-rotation event (password change) fails to cascade to all standing credential types, leaving one class (OAuth tokens there, API tokens here) silently valid.

### Impact Explanation
An attacker holding a valid API access key/secret for a user retains full, unattended API access to the Chainlink node — including all Edit/Admin-role capabilities available via that role — even after the victim changes their password specifically to remediate a suspected compromise. Since the token is used with `AuthenticateByToken` independent of sessions, this is a durable authentication bypass of the node's primary remediation mechanism for account compromise.

### Likelihood Explanation
Any authenticated user (via UI, CLI `chainlink admin chpass`, or GraphQL) who changes their own password will trigger this incomplete revocation; no privileged or attacker action is required to create the exposure — it is a default behavior gap in the two shipped password-change endpoints. Exploitation only requires that an attacker already possesses a leaked/stolen API token, which is the exact threat model a password change is meant to defeat.

### Recommendation
Call `orm.DeleteAuthToken(ctx, user)` (or otherwise rotate the `token_key`/`token_hashed_secret`) alongside `ClearNonCurrentSessions`/`SetPassword` in both `UserController.updateUserPassword` (core/web/user_controller.go) and `Resolver.UpdateUserPassword` (core/web/resolver/mutation.go), and audit-log the revocation. Consider surfacing this in the UI/CLI so users understand their API token must be regenerated after a password change.

### Proof of Concept
1. As a legitimate user, call `POST /v2/user/token` (or GraphQL `createAPIToken`) to obtain an API access key/secret.
2. Simulate compromise: an attacker captures this key/secret.
3. Victim calls `PATCH /v2/user/password` (or `updateUserPassword` mutation) to change their password, believing this revokes attacker access.
4. Attacker sends any authenticated request using the old API key/secret via `X-Chainlink-EA-AccessKey`/`X-Chainlink-EA-Secret` headers (`AuthenticateByToken`) — the request succeeds because `DeleteAuthToken` was never invoked during the password change.

func (u *UserController) updateUserPassword(c *gin.Context, user *clsession.User, newPassword string) error {
	ctx := c.Request.Context()
	sessionID, err := getCurrentSessionID(c)
	if err != nil {
		return err
	}
	orm := u.App.AuthenticationProvider()
	if err := orm.ClearNonCurrentSessions(ctx, sessionID); err != nil {
		u.App.GetLogger().Errorf("failed to clear non current user sessions: %s", err)
		return errors.New("unable to update password")
	}
	if err := orm.SetPassword(ctx, user, newPassword); err != nil {
		if errors.Is(err, clsession.ErrNotSupported) {
			return errUnsupportedForAuth
		}
		u.App.GetLogger().Errorf("failed to update current user password: %s", err)
		return errors.New("unable to update password")
	}
	return nil
}

func (r *Resolver) UpdateUserPassword(ctx context.Context, args struct {
	Input UpdatePasswordInput
}) (*UpdatePasswordPayloadResolver, error) {
	if err := authenticateUser(ctx); err != nil {
		return nil, err
	}

	session, ok := webauth.GetGQLAuthenticatedSession(ctx)
	if !ok {
		return nil, errors.New("couldn't retrieve user session")
	}

	dbUser, err := r.App.AuthenticationProvider().FindUser(ctx, session.User.Email)
	if err != nil {
		return nil, err
	}

	if !utils.CheckPasswordHash(args.Input.OldPassword, string(dbUser.HashedPassword)) {
		r.App.GetAuditLogger().Audit(audit.PasswordResetAttemptFailedMismatch, map[string]any{"user": dbUser.Email})

		return NewUpdatePasswordPayload(nil, map[string]string{
			"oldPassword": "old password does not match",
		}), nil
	}

	if err = r.App.AuthenticationProvider().ClearNonCurrentSessions(ctx, session.SessionID); err != nil {
		return nil, clearSessionsError{}
	}

	err = r.App.AuthenticationProvider().SetPassword(ctx, &dbUser, args.Input.NewPassword)
	if err != nil {
		return nil, failedPasswordUpdateError{}
	}

	r.App.GetAuditLogger().Audit(audit.PasswordResetSuccess, map[string]any{"user": dbUser.Email})
	return NewUpdatePasswordPayload(session.User, nil), nil
}

// SetAuthToken updates the user to use the given Authentication Token.
func (o *orm) SetAuthToken(ctx context.Context, user *sessions.User, token *auth.Token) error {
	salt := utils.NewSecret(utils.DefaultSecretSize)
	hashedSecret, err := auth.HashedSecret(token, salt)
	if err != nil {
		return pkgerrors.Wrap(err, "user")
	}
	sql := "UPDATE users SET token_salt = $1, token_key = $2, token_hashed_secret = $3, updated_at = now() WHERE email = $4 RETURNING *"
	return o.ds.GetContext(ctx, user, sql, salt, token.AccessKey, hashedSecret, user.Email)
}

// DeleteAuthToken clears and disables the users Authentication Token.
func (o *orm) DeleteAuthToken(ctx context.Context, user *sessions.User) error {
	sql := "UPDATE users SET token_salt = '', token_key = '', token_hashed_secret = '', updated_at = now() WHERE email = $1 RETURNING *"
	return o.ds.GetContext(ctx, user, sql, user.Email)
}

// AuthenticateByToken authenticates a User by their API token.
//
// Implements authMethod
func AuthenticateByToken(c *gin.Context, authr Authenticator) error {
	ctx := c.Request.Context()
	token := &auth.Token{
		AccessKey: c.GetHeader(APIKey),
		Secret:    c.GetHeader(APISecret),
	}
	if token.AccessKey == "" {
		return auth.ErrorAuthFailed
	}

	if token.Secret == "" {
		return auth.ErrorAuthFailed
	}

	// We need to first load the user row so we can compare tokens using the stored salt
	user, err := authr.FindUserByAPIToken(ctx, token.AccessKey)
	if err != nil {
		if errors.Is(err, sql.ErrNoRows) || errors.Is(err, clsessions.ErrUserSessionExpired) {
			return auth.ErrorAuthFailed
		}
		return err
	}

	ok, err := clsessions.AuthenticateUserByToken(token, &user)
	if err != nil {
		return err
	}
	if !ok {
		return auth.ErrorAuthFailed
	}

	c.Set(SessionUserKey, &user)

	return nil
}
