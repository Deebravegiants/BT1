### Title
Unprivileged market growth can permanently freeze all operations through accrual overflow - ([File: common/src/rates/simulate.rs](common/src/rates/simulate.rs))

### Summary

The pool converts scaled market totals back to RAY token values during every interest-accrual step, but `scaled_to_original` panics when the resulting value exceeds `i128`. [1](#0-0) [2](#0-1)  Because accrual occurs before market mutations and standalone index updates, a sufficiently large market can cross this numeric boundary and make repayment, withdrawal, liquidation, and later accrual permanently revert. [3](#0-2) [4](#0-3) 

### Finding Description

Market debt and supply are stored as scaled RAY shares, while each accrual step derives utilization by calling `scaled_to_original(borrowed, borrow_index)` and `scaled_to_original(supplied, supply_index)`. [5](#0-4)  `scaled_to_original` delegates to `Ray::mul`, and `Ray::mul` panics with `MathOverflow` when the exact multiply-divide result cannot fit in `i128`. [2](#0-1) [6](#0-5) [7](#0-6) 

The index cap does not prevent this condition because `update_borrow_index` caps only the index itself at `MAX_BORROW_INDEX_RAY`; it does not ensure that `borrowed * borrow_index / RAY` or `supplied * supply_index / RAY` remains representable. [8](#0-7)  Market caps likewise validate only that an individual asset amount can be represented in the RAY domain; they do not bound the later product of stored scaled shares and a grown index. [9](#0-8) 

An unprivileged user can build the prerequisite state through `Controller::supply` and `Controller::borrow`, both of which only require caller authorization and the normal entry/risk checks. [10](#0-9) [11](#0-10) [12](#0-11)  Once either market total crosses the representable-value boundary, every subsequent `global_sync` fails before the mutation proceeds. [13](#0-12) [14](#0-13) 

### Impact Explanation

This is a permanent market-level denial of service affecting all suppliers and borrowers in the affected `(hub_id, asset)` book. [13](#0-12)  Suppliers cannot withdraw, borrowers cannot repay, liquidators cannot reduce risk, and the permissionless index-update path cannot advance the market because each path reaches the same overflowing accrual calculation. [15](#0-14) [16](#0-15)  The result is permanent freezing of user funds and a contract market unable to operate through its public interfaces. [2](#0-1) 

### Likelihood Explanation

The attack is unprivileged and deterministic once the market reaches the numeric boundary. [17](#0-16) [14](#0-13)  Its practical likelihood is limited by the very large liquidity and collateral amounts required, the configured caps and risk parameters, and the index growth needed before overflow. [9](#0-8) [18](#0-17)  Those conditions reduce the attack's feasibility but do not remove the arithmetic flaw, so the issue is Medium severity. [8](#0-7) 

### Recommendation

Prevent admission of market sizes that can overflow at any reachable index. In particular, validate supply and debt growth against `scaled <= i128::MAX * RAY / MAX_BORROW_INDEX_RAY` or the corresponding supply-index bound, rather than validating only the initial asset-to-RAY conversion. [9](#0-8) [8](#0-7)  Longer term, store market totals in a representation whose value domain cannot overflow before the configured index ceiling, or make `scaled_to_original` return a saturating value only for utilization while retaining checked arithmetic for accounting. [2](#0-1) [19](#0-18)  Because an already-overflowed market cannot execute the repair path without accrual, deploy the bound before a market approaches the boundary. [13](#0-12) 

### Proof of Concept

1. On an admitted 18-decimal market with a sufficiently large supply cap, call `Controller::supply(attacker, 0, spoke_id, [(target_hub_asset, S)])` to create supply `S`.
2. Using separate collateral sufficient for the borrow risk gate, call `Controller::supply(attacker, 0, spoke_id, [(collateral_hub_asset, C)])`.
3. Call `Controller::borrow(attacker, collateral_account_id, [(target_hub_asset, D)], Some(attacker))`, choosing `D` close to the supplied liquidity so utilization remains high.
4. Allow index accrual and call `Controller::update_indexes(attacker, [target_hub_asset])` until `D_scaled * borrow_index / RAY > i128::MAX`.
5. The next call to `update_indexes` reaches `accrue_step`, whose first `scaled_to_original` call panics with `MathOverflow`. [14](#0-13) [7](#0-6) 
6. Subsequent `repay`, `withdraw`, `liquidate`, or `update_indexes` calls for that market reach the same pre-mutation accrual and fail before changing state. [13](#0-12) [15](#0-14)

```rust
/// Accrues borrow/supply indexes from `last_timestamp` to the cache's current time.
///
/// No-op when no time has elapsed. Splits long gaps into max-sized compound
/// windows, then sets `last_timestamp` to `current_timestamp`.
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

```rust
/// Computes `x * y / d` rounded half up. Requires `x >= 0`, `y >= 0`, and `d > 0`; a
/// `debug_assert` checks this in debug builds. Panics with `GenericError::DivisionByZero` if
/// `d == 0`, and with `GenericError::MathOverflow` if any other precondition is violated or if
/// the result does not fit in `i128`.
pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    // The zero check runs first so debug and release builds agree on a zero
    // divisor: both surface `DivisionByZero` rather than tripping the assert.
    require_nonzero_divisor(env, d);
    debug_assert!(
        x >= 0 && y >= 0 && d > 0,
        "mul_div_half_up: non-negative x, y and positive d"
    );
    try_mul_div_half_up(env, x, y, d)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
}
```

```rust
/// Returns the largest cap, in asset base units, whose ray-scaled form still
/// fits in `i128`.
///
/// Returns 0 when `asset_decimals > RAY_DECIMALS`, since the ray form is not
/// representable in that case. Enforced by
/// [`require_cap_within_asset_domain`], so stored caps can never overflow the
/// asset→ray rescale.
pub fn max_cap_for_decimals(asset_decimals: u32) -> i128 {
    let Some(exp) = RAY_DECIMALS.checked_sub(asset_decimals) else {
        return 0;
    };
    let upscale = 10i128
        .checked_pow(exp)
        .expect("10^(RAY_DECIMALS - asset_decimals) fits i128 for asset_decimals <= RAY_DECIMALS");
    i128::MAX / upscale
}

/// Panics with `CollateralError::AssetDecimalsTooHigh` if `asset_decimals`
/// exceeds `RAY_DECIMALS`, or with `CollateralError::InvalidBorrowParams` if
/// `cap` exceeds the value returned by `max_cap_for_decimals`.
pub fn require_cap_within_asset_domain(env: &Env, cap: i128, asset_decimals: u32) {
    if RAY_DECIMALS.checked_sub(asset_decimals).is_none() {
        panic_with_error!(env, CollateralError::AssetDecimalsTooHigh);
    }
    assert_with_error!(
        env,
        cap <= max_cap_for_decimals(asset_decimals),
        CollateralError::InvalidBorrowParams
    );
```

```rust
/// Borrows to `to` or the authorized owner/delegate, then checks solvency.
/// Persists supply alongside debt when the check restamps supply LTVs.
pub(crate) fn process_borrow(
    env: &Env,
    caller: &Address,
    account_id: u64,
    borrows: &Vec<HubPayment>,
    to: Option<Address>,
) {
    validation::require_authorized_caller(env, caller);

    let mut account = storage::get_account(env, account_id);
    require_owner_or_delegate(env, account_id, caller, &account.owner);

    let recipient = to.unwrap_or_else(|| caller.clone());
    let mut cache = Context::new(env);
    require_external_recipient(env, &mut cache, &recipient);
    let aggregated = payments::aggregate_positive_payments(env, borrows);

    validate_position_entry_gates(
        env,
        &account,
        &aggregated,
        &mut cache,
        AccountPositionType::Borrow,
    );
    settle_borrow(env, &mut account, &recipient, &aggregated, &mut cache);

    let restamped = enforce_post_pool_solvency(env, &mut cache, &mut account);
```
