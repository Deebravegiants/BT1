### Title
Unconditional, fallback-less `exchangeRate()` call in `Zap.sell`'s `canGraduate` pre-check permanently bricks buy **and** sell for any curve-stage token whose paired LT reverts on `exchangeRate()` - (File: `packages/contracts/src/Zap.sol`, `packages/contracts/src/Bonding.sol`)

### Summary
The C4 report's root cause — a core protocol function calling an external price oracle with no try/catch or fallback, so a revert on the oracle side DoSes core lending functions — has a direct analog here. `Bonding.canGraduate` performs an unguarded external call to the paired LT's `exchangeRate()` and is invoked unconditionally at the very top of both the buy path (`_executeBuy`) and, more importantly, the sell path (`Zap._sellInternal`). If that call ever reverts, every curve-stage token backed by that LT loses **both** its buy and sell functions, with no fallback — contradicting the protocol's own stated invariant that "holders can always exit via redeem, so no funds are stranded."

### Finding Description
`Zap._sellInternal` calls `bonding_.canGraduate(tokenAddress)` unconditionally, before any transfer or redeem logic, to decide whether a sell should instead trigger graduation: [1](#0-0) 

`canGraduate` (used by `_executeBuy`, `previewLtUntilGraduation`, `triggerGraduation`, and `Zap.sell`) reads reserves and then makes a bare, unguarded external call to the LT's `exchangeRate()`: [2](#0-1) 

There is no `try/catch` around this call anywhere in `Bonding.sol` or `Zap.sol`. If `exchangeRate()` reverts on the paired BounceTech LT (e.g., an emergency pause of the *view* function, a protocol-side circuit breaker, or any other externally-triggered blockage of that read — mirroring the Chainlink multisig-block scenario from the referenced report), the revert propagates through:
- `Bonding._executeBuy` → all buys through `Zap.buy` and direct `Bonding.buy` revert (already an accepted, documented v1 tradeoff for the *mint-pause* case).
- `Bonding.triggerGraduation` → the permissionless graduation escape hatch also reverts.
- **`Zap._sellInternal`** → **every sell reverts too**, because `canGraduate` is checked unconditionally before the sell/redeem logic even runs.

This is materially different from — and worse than — the documented "mint-pausable but NOT redeem-pausable" tradeoff described in the codebase docs, which explicitly assumes sells remain available as an escape valve: [3](#0-2) 

That assumption is only true if `redeem()`/the sell path never needs a working `exchangeRate()` call — but `Zap.sell`'s own pre-check does need it, unconditionally, for any token still in `Lifecycle.Curve`.

### Impact Explanation
For any token still in `Lifecycle.Curve` whose paired LT's `exchangeRate()` reverts:
- Buys revert (accepted tradeoff).
- Sells revert (`Zap.sell` → `canGraduate` → `exchangeRate()`), so holders cannot redeem their tokens for USDC.
- `triggerGraduation` also reverts (same `canGraduate` dependency), so there is no permissionless path to move the token into `Graduated` state and escape onto the HyperSwap venue, which is the only path that no longer depends on `canGraduate`.

The result is a total, unrecoverable freeze of the curve-raised LT reserve and every holder's tokens for that market — no buy, no sell, no graduation — as long as the LT's `exchangeRate()` keeps reverting. This is a permanent freezing-of-funds condition reachable purely by an unprivileged trader attempting `Zap.sell`, and it directly contradicts the protocol's own documented safety invariant that sells always remain available.

### Likelihood Explanation
The LT is an external, third-party (BounceTech) contract outside alt.fun's control. The codebase itself repeatedly acknowledges the LT can enter degraded/paused/retired states (mint-pausable LT, LT de-registration) as expected operational events, not edge cases. A revert specifically on `exchangeRate()` (rather than only `mint`) is plausible under the same class of external circuit-breaker/pause/emergency-freeze events already anticipated for `mint`, making this a realistic, non-hypothetical failure mode for any actively-traded curve-stage token.

### Recommendation
Wrap the `exchangeRate()` call inside `canGraduate` (and anywhere else it gates buy/sell availability) in a `try/catch`, and treat a reverting oracle-like call as "not graduatable right now" rather than propagating the revert. At minimum, `Zap._sellInternal` should not let a failure in the graduation pre-check block the underlying sell/redeem path — the sell/redeem flow should degrade gracefully (skip the graduation check) rather than revert entirely when `exchangeRate()` is unavailable, preserving the documented "sell always works" guarantee.

### Proof of Concept
1. A token is launched and trading normally on the curve against LT `L` (`Lifecycle.Curve`).
2. `L.exchangeRate()` starts reverting (e.g., BounceTech pauses/blocks the view, or the LT enters some other externally-triggered failure state not covered by the "mint-pausable" carve-out).
3. Alice, a normal holder, calls `Zap.sell(tokenAddress, tokenAmount, minUsdcOut)`.
4. `_sellInternal` immediately calls `bonding_.canGraduate(tokenAddress)`, which calls `L.exchangeRate()` and reverts.
5. Alice's sell reverts; she cannot redeem her tokens for USDC.
6. Alice or anyone else calls `Bonding.triggerGraduation(tokenAddress)` to try to move the token to the graduated (HyperSwap) venue instead — this also calls `canGraduate` and reverts.
7. The token remains stuck in `Lifecycle.Curve` with no working buy, sell, or graduation path for as long as `L.exchangeRate()` reverts.
