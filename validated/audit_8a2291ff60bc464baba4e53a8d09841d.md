Audit Report

## Title
Unbounded in-memory JWT replay cache in the HTTP Trigger gateway handler allows memory-exhaustion DoS - (File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go)

## Summary
The Gateway's HTTP Trigger handler records every successfully-authorized JWT's `jti` into an in-memory, unbounded map (`jwtReplayCache.cache`) that is only pruned by a 24-hour ticker by default. Because this write happens in `Authorize`/`authorizeRequest`, which runs before the per-workflow-owner rate limiter (`checkRateLimit`) in `HandleUserTriggerRequest`, a caller who owns one registered HTTP-trigger workflow can grow this map without bound for up to 24 hours, consuming gateway memory.

## Finding Description
`jwtReplayCache` is a plain `map[string]time.Time` with no capacity bound [1](#0-0) . Every successful `Authorize` call (valid signature, digest match, unused `jti`, authorized signer) unconditionally records the `jti` via `h.jwtCache.recordUsage(claims.ID)` [2](#0-1) . Eviction only happens via `cleanupOldEntries`, scheduled through a ticker at `h.jwtCache.cleanupPeriod` [3](#0-2) , whose default is `defaultJWTReplayPeriodMs = 1000 * 60 * 60 * 24` (24 hours) [4](#0-3) . In `HandleUserTriggerRequest`, `authorizeRequest` (which triggers the cache write) executes before `checkRateLimit` is enforced [5](#0-4) , so the write to the unbounded cache is not gated by any per-workflow throttle. I confirmed the only rate limiters present in the gateway handler (`globalNodeRateLimiter`, `perNodeRateLimiters`, `userRateLimiter`, `mtlsRequestRateLimiter`) are either scoped to node-to-gateway traffic (`HandleNodeMessage`) or to the per-workflow-owner limiter applied *after* the cache write [8](#0-7) . There is no size-bounded eviction structure analogous to `requestcache.go`'s `maxCacheSize`, unlike other caches in the same package.

## Impact Explanation
Sustained flooding by any authorized workflow owner before the 24-hour cleanup window elapses can accumulate unbounded map entries, consuming gateway node memory and potentially causing OOM on the shared Gateway process, denying service to all workflows using that gateway instance. This is a legitimate memory-exhaustion DoS vector reachable by any registered, unprivileged workflow owner — not an operator or node-level actor — and maps to an in-scope "unauthorized resource exhaustion / denial of service via unbounded cache growth" class of finding for the Gateway component.

## Likelihood Explanation
Likelihood is realistic for any party operating a registered workflow with an HTTP trigger: they hold the private key needed to sign valid JWTs for their own workflow and can trivially generate unique `jti`/request IDs at high volume. The exploit path requires only capabilities normal end-users already have (their own workflow's authorized signing key), and the only friction is the per-workflow-owner rate limiter, which does not gate the actual cache-growth step (it runs after `Authorize`). The 24-hour default cleanup window provides a long accumulation window.

## Recommendation
- Move or duplicate rate-limit enforcement (`checkRateLimit`) to run before or alongside `authorizeRequest`, so that JWT-cache growth is capped by the same limiter gating downstream traffic.
- Add an explicit maximum size / bounded LRU eviction to `jwtReplayCache`, similar to the `maxCacheSize` bound in `core/services/gateway/handlers/common/requestcache.go`.
- Consider shortening the default `JWTReplayPeriodMs` cleanup interval or evicting proactively once the map exceeds a configured entry-count threshold.

## Proof of Concept
1. Register a workflow with an HTTP trigger and obtain a valid ECDSA signing key registered as an `AuthorizedKey` for that workflow.
2. For N requests, construct a `jsonrpc.Request` with a unique `id`, compute its digest, and sign a JWT with a fresh unique `jti` (as in `createTestJWTToken` in `http_trigger_handler_test.go`).
3. Submit all N requests to the Gateway's `workflows.execute` endpoint in rapid succession, faster than the 24-hour cleanup ticker.
4. Each request that passes `Authorize` (signature + digest + authorized-signer checks) adds a permanent entry to `WorkflowMetadataHandler.jwtCache.cache` regardless of whether `checkRateLimit` subsequently throttles the request — verifiable via a Go unit test asserting `len(h.jwtCache.cache)` growth exceeds what the per-workflow rate limiter would otherwise allow through to the DON.

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}

		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())

	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}

func (h *httpTriggerHandler) checkRateLimit(ctx context.Context, workflowID, requestID string, callback handlers.Callback) error {
	workflowRef, found := h.workflowMetadataHandler.GetWorkflowReference(workflowID)
	if !found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "workflow reference not found", callback)
		return errors.New("workflow reference not found")
	}

	orgID := h.resolveOrgID(ctx, workflowRef.workflowOwner)
	ctx = contexts.WithCRE(ctx, contexts.CRE{Owner: workflowRef.workflowOwner, Org: orgID, Workflow: workflowID})
	if err := h.userRateLimiter.AllowErr(ctx); err != nil {
		lggr := logger.With(h.lggr, platform.KeyWorkflowID, workflowID, platform.KeyWorkflowOwner, workflowRef.workflowOwner, "requestID", requestID, "err", err)
		if errLimited, ok := errors.AsType[limits.ErrorRateLimited](err); ok {
			switch errLimited.Scope {
			case settings.ScopeWorkflow:
				lggr.Errorf("failed to start execution: per workflow rate limit exceeded")
				h.metrics.IncrementWorkflowThrottled(ctx, h.lggr)
			default:
				lggr.Errorf("failed to start execution: unexpected rate limit for scope %s", errLimited.Scope)
			}
			h.handleUserError(ctx, requestID, jsonrpc.ErrLimitExceeded, "rate limit exceeded", callback)
			return err
		}
		return fmt.Errorf("failed to check rate limit: %w", err)
	}
	return nil
}
