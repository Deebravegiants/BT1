### Title
Global average-based gas price formula masks single-shard congestion, allowing underpriced execution on a hot shard - (File: core/primitives/src/block.rs)

### Summary
The reported bug class is a single hardcoded cap/threshold applied uniformly across multiple heterogeneous "assets," causing some assets to be under-restricted (staying stale/underpriced) while others are over-restricted. nearcore's block-level gas price mechanism exhibits the same structural flaw: one global gas price is derived from a single 50%-utilization threshold applied to the **sum/average of gas used and gas limit across all shards**, rather than per-shard. This is explicitly acknowledged in the protocol documentation.

### Finding Description
`Block::compute_next_gas_price_checked` computes a single `next_gas_price` for the whole chain using `gas_used` and `gas_limit` that are aggregated across all shards via `self.chunks().compute_gas_used_checked()` and `compute_gas_limit_checked()`, then applies the fixed formula `gas_price * (1 + (gas_used/gas_limit - 1/2) * adjustment_rate)`, clamped between `min_gas_price` and `max_gas_price`. [1](#0-0) 

This mirrors the `_capReserve()` design flaw in the report: instead of a per-token/per-shard threshold, a single 50%-of-capacity benchmark (analogous to `LOG_MAX_INCREASE`/`LOG_MAX_DECREASE`) is applied to the combined state of many independent units (shards), and the protocol documentation itself confirms the consequence:

> "Note that all shards share the same gas price. Hence, if one out of four shards is at 100% capacity, this will not cause the price to increase. The 50% capacity is calculated as an average across all shards." [2](#0-1) 

### Impact Explanation
Because the 50%-of-capacity cap is a single hardcoded benchmark applied to the aggregate/average of all shards rather than per-shard, a shard that is at or near 100% capacity does not, by itself, raise the gas price if the other shards are comparatively idle. This is directly analogous to the report's "may fail to have any effects on relatively more stable assets" scenario: a heavily congested (volatile) shard is effectively treated the same as idle shards, so gas remains underpriced on that specific shard even under sustained full utilization. Underpriced gas on a congested shard is an economic vulnerability — it permits continued cheap transaction/receipt execution precisely where demand-based pricing should be raising costs, undermining the fee market's purpose of throttling congestion via price signals. Conversely, other shards' gas price is forced to move with the aggregate/average even though their own individual utilization does not justify it, again matching the report's "no effects on other stable assets" / "unfairly stale" dichotomy.

### Likelihood Explanation
This is not a hypothetical edge case — it is the documented, always-active behavior of the gas price formula for every block, on every shard, and is trivially reachable by any user submitting transactions concentrated on a single shard/contract. No privileged access, validator collusion, or malicious node behavior is required; only transaction volume directed at one shard is needed to exploit the gap between per-shard reality and the chain-wide averaged cap.

### Recommendation
Adapt the mitigation from the referenced report to nearcore's sharded gas pricing: compute and apply gas price adjustments (or an analogous per-shard multiplier/limit) based on each shard's own `gas_used/gas_limit` ratio rather than a single chain-wide average, so that a fully congested shard is priced according to its own congestion level independent of other shards' idle capacity. If a shared global price is required for interoperability, consider incorporating a per-shard congestion signal (similar to the per-shard `CongestionControlConfig` already used for receipt forwarding) into the price formula so highly congested shards cannot hide behind idle shards.

### Proof of Concept
No new PoC was constructed; the existence and mechanics of this behavior are confirmed by the codebase's own aggregation logic and accompanying documentation cited above. Existing tests such as `test_capped_gas_price` and `test_cap_max_gas_price` only verify the min/max clamps of the single global price, not per-shard fairness, and do not exercise the single-shard-saturation scenario described here.     pub fn compute_next_gas_price_checked(
        gas_price: Balance,
        gas_used: Gas,
        gas_limit: Gas,
        gas_price_adjustment_rate: Rational32,
        min_gas_price: Balance,
        max_gas_price: Balance,
    ) -> Option<Balance> {
        // If block was skipped, the price does not change.
        if gas_limit == Gas::ZERO {
            return Some(gas_price);
        }

        let gas_used = u128::from(gas_used.as_gas());
        let gas_limit = u128::from(gas_limit.as_gas());
        let adjustment_rate_numer = *gas_price_adjustment_rate.numer() as u128;
        let adjustment_rate_denom = *gas_price_adjustment_rate.denom() as u128;

        // This number can never be negative as long as gas_used <= gas_limit and
        // adjustment_rate_numer <= adjustment_rate_denom.
        let numerator = 2u128
            .checked_mul(adjustment_rate_denom)?
            .checked_mul(gas_limit)?
            .checked_add(2u128.checked_mul(adjustment_rate_numer)?.checked_mul(gas_used)?)?
            .checked_sub(adjustment_rate_numer.checked_mul(gas_limit)?)?;
        let denominator = 2u128.checked_mul(adjustment_rate_denom)?.checked_mul(gas_limit)?;
        let next_gas_price =
            U256::from(gas_price.as_yoctonear()) * U256::from(numerator) / U256::from(denominator);

        Some(Balance::from_yoctonear(
            next_gas_price
                .clamp(
                    U256::from(min_gas_price.as_yoctonear()),
                    U256::from(max_gas_price.as_yoctonear()),
                )
                .as_u128(),
        ))
    }

use crate::utils::process_blocks::prepare_env_with_congestion;
use near_primitives::num_rational::Ratio;
use near_primitives::version::PROTOCOL_VERSION;
use near_store::ShardUId;

#[test]
fn test_capped_gas_price() {
    let mut env = prepare_env_with_congestion(PROTOCOL_VERSION, Some(Ratio::new_raw(2, 1)), 7).0;
    let mut was_congested = false;
    let mut price_exceeded_limit = false;

    for i in 3..20 {
        env.produce_block(0, i);
        let block = env.clients[0].chain.get_block_by_height(i).unwrap().clone();
        let min_gas_price = env.clients[0].chain.block_economics_config.min_gas_price();
        let chunk_extra =
            env.clients[0].chain.get_chunk_extra(block.hash(), &ShardUId::single_shard()).unwrap();
        was_congested |= chunk_extra.gas_used() >= chunk_extra.gas_limit();
        price_exceeded_limit |=
            block.header().next_gas_price() > min_gas_price.checked_mul(20).unwrap();
    }

    assert!(was_congested);
    assert!(!price_exceeded_limit);
}

#[test]
fn test_cap_max_gas_price() {
    use near_chain::Provenance;
    let mut genesis = Genesis::test(vec!["test0".parse().unwrap(), "test1".parse().unwrap()], 1);
    let epoch_length = 5;
    genesis.config.min_gas_price = Balance::from_yoctonear(1_000);
    genesis.config.max_gas_price = Balance::from_yoctonear(1_000_000);
    genesis.config.protocol_version = PROTOCOL_VERSION;
    genesis.config.epoch_length = epoch_length;
    genesis.config.transaction_validity_period = epoch_length * 2;
    let mut env = TestEnv::builder(&genesis.config).nightshade_runtimes(&genesis).build();

    for i in 1..epoch_length {
        let block = env.clients[0].produce_block(i).unwrap().unwrap();
        env.process_block(0, block, Provenance::PRODUCED);
    }

    let min_gas_price = env.clients[0].chain.block_economics_config.min_gas_price();
    let max_gas_price = env.clients[0].chain.block_economics_config.max_gas_price();
    assert!(max_gas_price <= min_gas_price.checked_mul(20).unwrap());
}
