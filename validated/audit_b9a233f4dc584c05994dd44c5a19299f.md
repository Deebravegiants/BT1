Audit Report

## Title
Bridge and External Initiator outgoing authentication tokens stored and served in plaintext to any authenticated user regardless of role - ([File: core/bridges/bridge_type.go], [File: core/web/bridge_types_controller.go], [File: core/bridges/external_initiator.go], [File: core/web/external_initiators_controller.go], [File: core/web/router.go])

## Summary
`BridgeType.OutgoingToken` and `ExternalInitiator.OutgoingToken`/`OutgoingSecret` are generated in plaintext, persisted unencrypted, and returned unredacted by the standard `Index`/`Show` JSON:API endpoints and GraphQL read queries. Critically, the corresponding routes (`GET /v2/bridge_types`, `GET /v2/bridge_types/:BridgeName`, `GET /v2/external_initiators`) carry no role-based restriction, so even the lowest-privileged authenticated "View"-role user can retrieve these outbound-authentication secrets for every bridge/external initiator configured on the node.

## Finding Description
`bridges.NewBridgeType` generates `OutgoingToken` as plaintext and stores it unencrypted on the persisted `BridgeType` struct: [1](#0-0)  The `BridgeType.OutgoingToken` field has no hashing/redaction, unlike `IncomingTokenHash` which is salted and hashed: [2](#0-1) 

`presenters.NewBridgeResource` copies the plaintext `OutgoingToken` directly into the JSON:API response body with no redaction, and this resource is used by both `Index` and `Show`: [3](#0-2) 

The identical pattern applies to `ExternalInitiator.OutgoingSecret`/`OutgoingToken`, generated in plaintext and returned unredacted by `Index`: [4](#0-3) [5](#0-4)  A test explicitly asserts the plaintext token is present in the listing response body, confirming the behavior: [6](#0-5) 

Crucially, I verified the route-level authorization in `core/web/router.go`: the GET routes for these resources carry **no role-restricting middleware** at all, unlike the corresponding POST/PATCH/DELETE routes which are wrapped in `auth.RequiresEditRole`:
```go
authv2.GET("/external_initiators", paginatedRequest(eia.Index))
authv2.POST("/external_initiators", auth.RequiresEditRole(eia.Create))
...
authv2.GET("/bridge_types", paginatedRequest(bt.Index))
authv2.POST("/bridge_types", auth.RequiresEditRole(bt.Create))
authv2.GET("/bridge_types/:BridgeName", bt.Show)
``` [7](#0-6) 

This is corroborated by the RBAC test matrix in `core/web/auth/auth_test.go`, which explicitly marks these GET routes as `viewOnlyAllowed: true`, confirming a "View"-role user (the lowest privilege tier) can successfully call them: [8](#0-7)  The `TestRBAC_Routemap_ViewOnly` test enforces exactly this expectation — that view-only users receive non-Unauthorized/Forbidden responses on these routes: [9](#0-8) 

This resolves the uncertainty flagged in the original report: the routes are reachable by the lowest "View" role, not gated to admin-only, so this does cross a real privilege boundary — a View-role user, who is only supposed to have read access for inspection purposes, obtains live outbound-authentication credentials that let them impersonate the node's outbound calls to bridges/external initiators.

This differs materially from the general secrets-handling pattern elsewhere in the codebase (`config.SecretString`/`SecretURL`), which redacts values as `xxxxx` on marshal: [10](#0-9)  The bridge/external-initiator outgoing credentials were never migrated to this pattern.

## Impact Explanation
The `OutgoingToken`/`OutgoingSecret` is the credential the node itself presents when calling out to a bridge adapter or notifying an external initiator. Any authenticated node user — including the standard "View" role, which by design should only permit inspection, not credential access — can call `GET /v2/bridge_types`, `GET /v2/bridge_types/:BridgeName`, or `GET /v2/external_initiators` and receive these plaintext secrets for every configured bridge/initiator. This maps to CWE-522 (Insufficiently Protected Credentials) and to an in-scope Chainlink impact category of secret exfiltration via a node API role/authorization gap — a View-level session escalates to obtaining credentials that could be used to impersonate the node toward its external integrations.

## Likelihood Explanation
Exploitation requires only a standard authenticated "View"-role session/API token — no admin or edit privilege, no host or database access, and no social engineering. This is a normal, expected credential tier in multi-operator Chainlink deployments, making the disclosure readily reachable via a single unauthenticated-role-elevated GET request in any deployment with more than one user role in use.

## Recommendation
- Redact `OutgoingToken`/`OutgoingSecret` from `BridgeResource`/`ExternalInitiatorResource` on `Index`/`Show` responses and the equivalent GraphQL queries; return them only once, at creation time.
- Add `auth.RequiresEditRole` (or stricter) to the `GET /v2/bridge_types`, `GET /v2/bridge_types/:BridgeName`, and `GET /v2/external_initiators` routes if raw secret exposure is retained, or otherwise strip the secret field for view-only callers.
- Wrap `OutgoingToken`/`OutgoingSecret` in `config.SecretString` or an equivalent redaction/encryption-at-rest wrapper, consistent with other node secrets.

## Proof of Concept
1. As an admin, create a bridge via `POST /v2/bridge_types` — response includes `outgoingToken`.
2. Create a second user with `Role: sessions.UserRoleView` (lowest privilege tier).
3. Using that View-role session, call `GET /v2/bridge_types` or `GET /v2/bridge_types/{name}` — per `router.go` these routes carry no role middleware, and per `auth_test.go`'s `viewOnlyAllowed: true` marking, the call succeeds (not 401/403).
4. Observe the JSON:API response's `attributes.outgoingToken` contains the plaintext token generated at creation — directly demonstrated by the existing test assertion `assert.Equal(t, eiBar.OutgoingToken, externalInitiators[0].OutgoingToken)` for the analogous `external_initiators` endpoint. // Index lists Bridges, one page at a time.
func (btc *BridgeTypesController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	bridges, count, err := btc.App.BridgeORM().BridgeTypes(ctx, offset, size)

	resources := make([]presenters.BridgeResource, 0, len(bridges))
	for _, bridge := range bridges {
		resources = append(resources, *presenters.NewBridgeResource(bridge))
	}

	paginatedResponse(c, "Bridges", size, page, resources, count, err)
}

// Show returns the details of a specific Bridge.
func (btc *BridgeTypesController) Show(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	bt, err := btc.App.BridgeORM().FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}

type ExternalInitiator struct {

// NewExternalInitiator generates an ExternalInitiator from an
// auth.Token, hashing the password for storage
func NewExternalInitiator(
	eia *auth.Token,
	eir *ExternalInitiatorRequest,
) (*ExternalInitiator, error) {
	salt := utils.NewSecret(utils.DefaultSecretSize)
	hashedSecret, err := auth.HashedSecret(eia, salt)
	if err != nil {
		return nil, pkgerrors.Wrap(err, "error hashing secret for external initiator")
	}

	return &ExternalInitiator{
		Name:           strings.ToLower(eir.Name),
		URL:            eir.URL,
		AccessKey:      eia.AccessKey,
		HashedSecret:   hashedSecret,
		Salt:           salt,
		OutgoingToken:  utils.NewSecret(utils.DefaultSecretSize),
		OutgoingSecret: utils.NewSecret(utils.DefaultSecretSize),
	}, nil
}

func TestRBAC_Routemap_ViewOnly(t *testing.T) {
	t.Parallel()
	app := cltest.NewApplicationEVMDisabled(t)
	require.NoError(t, app.Start(t.Context()))

	router := web.Router(t, app, nil)
	ts := httptest.NewServer(router)
	defer ts.Close()

	// Create a test run user to work with
	u := &cltest.User{Role: sessions.UserRoleView}
	client := app.NewHTTPClient(u)

	// Assert all view only routes
	for i, route := range routesRolesMap {
		t.Run(fmt.Sprintf("%d-%s-%s", i, route.verb, route.path), func(t *testing.T) {
			t.Parallel()
			var resp *http.Response
			var cleanup func()

			switch route.verb {
			case "GET":
				resp, cleanup = client.Get(route.path)
			case "POST":
				resp, cleanup = client.Post(route.path, nil)
			case "DELETE":
				resp, cleanup = client.Delete(route.path)
			case "PATCH":
				resp, cleanup = client.Patch(route.path, nil)
			case "PUT":
				resp, cleanup = client.Put(route.path, nil)
			default:
				t.Fatalf("Unknown HTTP verb %s\n", route.verb)
			}
			defer cleanup()

			// If this route only allows view only, don't expect an unauthorized response
			switch {
			case route.viewOnlyAllowed:
				assert.NotEqual(t, http.StatusUnauthorized, resp.StatusCode)
				assert.NotEqual(t, http.StatusForbidden, resp.StatusCode)
			case !route.EditAllowed:
				assert.Equal(t, http.StatusForbidden, resp.StatusCode)
			default:
				assert.Equal(t, http.StatusUnauthorized, resp.StatusCode)
			}
		})
	}
}
