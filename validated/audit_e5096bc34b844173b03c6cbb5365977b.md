### Title
Deterministic accounts referencing `GlobalContractIdentifier::AccountId` do not commit to fixed code — the "deterministic" code can be silently changed after derivation/deployment - (File: `runtime/runtime/src/global_contracts.rs`, `core/primitives/src/utils.rs`)

### Summary
NEP-616 deterministic accounts are documented as having "fixed code and fixed initial state" that is fully committed to by the derived `0s…` account id [1](#0-0) . However, when the `code` field of `DeterministicAccountStateInit` is a `GlobalContractIdentifier::AccountId(...)` rather than a `CodeHash(...)`, the id derivation only hashes the *reference* (the account id string), not the actual bytecode [2](#0-1) . The account whose id is referenced can redeploy completely different WASM code to that same `GlobalContractCode` trie key at any time via a normal `DeployGlobalContractAction` with `AccountId` deploy mode, with no restriction preventing overwrite of previously-deployed code [3](#0-2) [4](#0-3) . This is the same bug class as the `TokenWrapped` report: an address/identifier that is supposed to deterministically commit to fixed "creation code" in fact resolves to code that can differ from what was used to compute/trust the identifier.

### Finding Description
`derive_near_deterministic_account_id` computes `'0s' + keccak256(borsh(state_init))[12:32]`, where `state_init.code` may be either `GlobalContractIdentifier::CodeHash(hash)` (content-addressed, immutable) or `GlobalContractIdentifier::AccountId(account_id)` (reference-addressed) [2](#0-1) [5](#0-4) .

For the `AccountId` variant, the borsh encoding embeds only the referenced account name, not a hash of its bytecode. When `action_deterministic_state_init` first initializes the account ("uninit" → "active"), it resolves `state_init.code()` via `use_global_contract`, which sets `AccountContract::GlobalByAccount(id)` on the new account — a live pointer to whatever code is currently, or will ever be, stored under that global-contract-by-account-id key [6](#0-5) [7](#0-6) .

The owner of that referenced account can redeploy new code to the exact same `GlobalContractIdentifier::AccountId` at will: `action_deploy_global_contract`/`initiate_distribution` always derives the trie key purely from `account_id` for `GlobalContractDeployMode::AccountId`, with no check that code hasn't already been deployed there, and `apply_distribution_current_shard` simply overwrites the `TrieKey::GlobalContractCode` entry with the new bytes as long as the distribution nonce is fresh (which it always will be, since the deployer controls when to redeploy) [8](#0-7) [9](#0-8) .

Because every account with `AccountContract::GlobalByAccount(id)` resolves its executable code live from that shared, mutable slot (see `RuntimeContractIdentifier::resolve`/`GlobalContractAccessExt::code`, which for `AccountId` always re-reads current state rather than pinning a hash) [10](#0-9) , any "deterministic account" created with `code: GlobalContractIdentifier::AccountId(x)` does not actually have fixed code as NEP-616/the docs claim — the executing code changes transparently the moment `x` redeploys, without changing the derived `0s…` id and without any additional `DeterministicStateInitAction`.

This mirrors the `TokenWrapped` root cause precisely: an identifier meant to deterministically commit to "creation code"/contract bytecode (used for precalculating a fixed, trusted address) in practice resolves to code that can silently change, because the commitment is over a mutable reference rather than the content itself.

### Impact Explanation
Any protocol or application logic that relies on the NEP-616 guarantee that a deterministic account's code is fixed and fully defined by its `state_init` — for example, deposit-and-trust patterns where a user deposits funds into a deterministic account before it is even created, trusting that only the pre-agreed code (e.g. an escrow, vault, or bridge-style contract) will ever run there — can be broken. The account/registrar controlling the referenced `AccountId` global contract can redeploy arbitrary code after users have already funded or interacted with dependent deterministic accounts, enabling unauthorized state/logic changes and potential fund redirection from any deterministic account built on that reference, without needing to alter the account id that users verified off-chain. This is reachable purely through ordinary transactions (`DeployGlobalContractAction`, `DeterministicStateInitAction`) — no validator/node-privileged access required.

### Likelihood Explanation
Using `GlobalContractIdentifier::AccountId` (rather than `CodeHash`) inside `DeterministicAccountStateInit.code` is a normal, supported option exposed directly through the public action/type surface (`DeterministicStateInitAction`, `GlobalContractIdentifier`) [5](#0-4) ; nothing in validation restricts deterministic accounts to only the content-addressed `CodeHash` variant. Any application or wallet that builds on deterministic accounts referencing an account-id-mode global contract (rather than exclusively hash-mode) is exposed, and the redeploy step is a single ordinary transaction signed by the referenced account's own key — requiring no privileged role.

### Recommendation
Either (a) disallow `GlobalContractIdentifier::AccountId` as the `code` of a `DeterministicAccountStateInit`, requiring `CodeHash` only so the derived id truly commits to immutable bytecode, or (b) pin/freeze the resolved code hash into the account state at first initialization (e.g., convert `GlobalByAccount` references into a fixed `Global(code_hash)` snapshot at `deploy_deterministic_account` time) so subsequent redeployments to the referenced account no longer affect already-created deterministic accounts. Documentation (NEP-616 / `Account.md`) should also explicitly warn that `AccountId`-mode global contracts are mutable and thus unsuitable for "fixed code" guarantees.

### Proof of Concept
1. Deploy a global contract in `AccountId` mode from account `provider.near` containing benign logic V1 (`DeployGlobalContractAction{ code: V1, deploy_mode: AccountId }`) [11](#0-10) .
2. A user computes `state_init = DeterministicAccountStateInit::V1{ code: GlobalContractIdentifier::AccountId("provider.near"), data }` and derives `det_account = derive_near_deterministic_account_id(&state_init)` off-chain, verifying V1's source before trusting the resulting `0s…` id [2](#0-1) .
3. User sends `DeterministicStateInitAction{ state_init, deposit }` to `det_account`, funding it; the account is initialized with `AccountContract::GlobalByAccount("provider.near")` [12](#0-11) .
4. `provider.near` later submits a new `DeployGlobalContractAction{ code: V2 (malicious), deploy_mode: AccountId }` — this overwrites the same `TrieKey::GlobalContractCode{AccountId("provider.near")}` entry [13](#0-12) .
5. `det_account` now executes V2's logic on every subsequent call, even though its `0s…` id (computed in step 2) never changed and no new `DeterministicStateInitAction` was ever sent to it — violating the "fixed code" guarantee the id was supposed to encode.

/// Returns a NEP-616 compliant deterministic account id.
/// This is a NEAR-implicit account ID which is fully defined by its initial state.
pub fn derive_near_deterministic_account_id(
    state_init: &DeterministicAccountStateInit,
) -> AccountId {
    use sha3::Digest;
    let mut hasher = sha3::Keccak256::new();
    borsh::to_writer(&mut hasher, state_init).expect("borsh must not fail");
    let hash: [u8; 32] = hasher.finalize().into();
    format!("0s{}", hex::encode(&hash[12..32])).parse().unwrap()
}

pub(crate) fn use_global_contract(
    state_update: &mut TrieUpdate,
    account_id: &AccountId,
    account: &mut Account,
    contract_identifier: &GlobalContractIdentifier,
    result: &mut ActionResult,
) -> Result<(), RuntimeError> {
    let key = TrieKey::GlobalContractCode { identifier: contract_identifier.clone().into() };
    if !state_update.contains_key(&key, AccessOptions::DEFAULT)? {
        result.result = Err(ActionErrorKind::GlobalContractDoesNotExist {
            identifier: contract_identifier.clone(),
        }
        .into());
        return Ok(());
    }
    clear_account_contract_storage_usage(state_update, account_id, account)?;
    if account.contract().is_local() {
        state_update.remove(TrieKey::ContractCode { account_id: account_id.clone() });
    }
    let contract = match contract_identifier {
        GlobalContractIdentifier::CodeHash(code_hash) => AccountContract::Global(*code_hash),
        GlobalContractIdentifier::AccountId(id) => AccountContract::GlobalByAccount(id.clone()),
    };
    account.set_storage_usage(
        account.storage_usage().checked_add(contract_identifier.len() as u64).ok_or_else(|| {
            StorageError::StorageInconsistentState(format!(
                "Storage usage integer overflow for account {}",
                account_id
            ))
        })?,
    );
    account.set_contract(contract).or_inconsistent_state(account_id)?;
    Ok(())

fn initiate_distribution(
    state_update: &mut TrieUpdate,
    account_id: AccountId,
    contract_code: Arc<[u8]>,
    deploy_mode: &GlobalContractDeployMode,
    current_shard_id: ShardId,
    result: &mut ActionResult,
) -> Result<(), RuntimeError> {
    let id = match deploy_mode {
        GlobalContractDeployMode::CodeHash => {
            GlobalContractIdentifier::CodeHash(hash(&contract_code))
        }
        GlobalContractDeployMode::AccountId => {
            GlobalContractIdentifier::AccountId(account_id.clone())
        }
    };
    // Increment the nonce and write it to state immediately to prevent multiple
    // distributions with the same nonce from being initiated. This requires
    // allowing the same nonce in the freshness check when applying the
    // distribution receipt.
    let nonce = increment_nonce(state_update, &id)?;
    let distribution_receipt =
        GlobalContractDistributionReceipt::new(id, current_shard_id, vec![], contract_code, nonce);
    let distribution_receipts =
        Receipt::new_global_contract_distribution(account_id, distribution_receipt);
    // No need to set receipt_id here, it will be generated as part of apply_action_receipt
    result.new_receipts.push(distribution_receipts);
    Ok(())
}

/// Increments the nonce for the given global contract identifier and writes
/// it to state immediately.
fn increment_nonce(
    state_update: &mut TrieUpdate,
    id: &GlobalContractIdentifier,
) -> Result<u64, RuntimeError> {
    let identifier: GlobalContractCodeIdentifier = id.clone().into();

    let nonce_key = TrieKey::GlobalContractNonce { identifier };
    let stored_nonce = get_nonce(state_update, &nonce_key)?;

    let new_nonce = stored_nonce.checked_add(1).ok_or_else(|| {
        RuntimeError::UnexpectedIntegerOverflow("increment_global_contract_nonce".into())
    })?;
    set_nonce(state_update, nonce_key, new_nonce);
    Ok(new_nonce)
}

fn apply_distribution_current_shard(
    receipt: &Receipt,
    global_contract_data: &GlobalContractDistributionReceipt,
    apply_state: &ApplyState,
    state_update: &mut TrieUpdate,
) -> Result<Compute, RuntimeError> {
    let identifier = match &global_contract_data.id() {
        GlobalContractIdentifier::CodeHash(hash) => GlobalContractCodeIdentifier::CodeHash(*hash),
        GlobalContractIdentifier::AccountId(account_id) => {
            GlobalContractCodeIdentifier::AccountId(account_id.clone())
        }
    };

    let is_nonce_fresh = check_and_update_nonce(global_contract_data, &identifier, state_update)?;
    if !is_nonce_fresh {
        return Ok(0);
    }

    let config = apply_state.config.wasm_config.clone();
    let trie_key = TrieKey::GlobalContractCode { identifier };
    let code_len = global_contract_data.code().len() as u64;
    state_update.set(trie_key, global_contract_data.code().to_vec());
    state_update.commit(StateChangeCause::ReceiptProcessing { receipt_hash: receipt.get_hash() });
    let code_hash = match global_contract_data.id() {
        GlobalContractIdentifier::CodeHash(hash) => Some(*hash),
        GlobalContractIdentifier::AccountId(_) => None,
    };
    precompile_contract_with_warming(
        &ContractCode::new(global_contract_data.code().to_vec(), code_hash),
        config,
        apply_state.next_wasm_config.clone(),
        apply_state.cache.as_deref(),
    );
    near_vm_runner::report_metrics(apply_state.shard_id, "global_contract");
    let fees = &apply_state.config.fees;
    let per_byte_total = fees
        .deploy_global_contract_execution_per_byte
        .checked_mul(code_len)
        .ok_or(IntegerOverflowError)?;
    let compute = fees
        .deploy_global_contract_execution_base
        .checked_add(per_byte_total)
        .ok_or(IntegerOverflowError)?;
    Ok(compute)

    state_update: &mut TrieUpdate,
    apply_state: &ApplyState,
    maybe_account: &mut Option<Account>,
    account_id: &AccountId,
    receipt: &Receipt,
    action: &DeterministicStateInitAction,
    result: &mut ActionResult,
) -> Result<(), RuntimeError> {
    // See https://github.com/near/NEPs/blob/master/neps/nep-0616.md#account-state
    // for the detailed description around deterministic account state.
    let storage_usage_config = &apply_state.config.fees.storage_usage_config;
    let account = match maybe_account {
        Some(account) => account,
        None => {
            // cspell:ignore nonexist
            // `nonexist` -> `uninit` account state transition
            // Create with zero balance now and check later how much of the
            // provided deposit is needed.
            let new_account = create_deterministic_account(Balance::ZERO, storage_usage_config);
            maybe_account.insert(new_account)
        }

        // NEP-616 sense, a deterministic account with no contract yet, not
        // `Account::Uninitialized`: a `0u` id can never reach this, because
        // `validate_deterministic_state_init` pins the receiver to the derived
        // `0s` id.
        deploy_deterministic_account(
            state_update,
            account,
            account_id,
            &action.state_init,
            result,
            storage_usage_config,
        )?;
    }

impl GlobalContractAccessExt for GlobalContractIdentifier {
    fn hash(self, store: &TrieUpdate, access: AccessOptions) -> Result<CryptoHash, StorageError> {
        if let GlobalContractIdentifier::CodeHash(hash) = self {
            return Ok(hash);
        }
        let key = TrieKey::GlobalContractCode { identifier: self.into() };
        let value_ref =
            store.get_ref(&key, KeyLookupMode::MemOrFlatOrTrie, access)?.ok_or_else(|| {
                let TrieKey::GlobalContractCode { identifier } = key else { unreachable!() };
                StorageError::StorageInconsistentState(format!(
                    "Global contract identifier not found {:?}",
                    identifier
                ))
            })?;
        Ok(value_ref.value_hash())
    }

    fn code(self, store: &TrieUpdate) -> Result<Option<ContractCode>, StorageError> {
        let key = TrieKey::GlobalContractCode { identifier: self.clone().into() };
        let code_hash = match self {
            GlobalContractIdentifier::AccountId(_) => None,
            GlobalContractIdentifier::CodeHash(hash) => Some(hash),
        };
        let code = store.get(&key, AccessOptions::DEFAULT)?;
        Ok(code.map(|code| ContractCode::new(code, code_hash)))
    }
