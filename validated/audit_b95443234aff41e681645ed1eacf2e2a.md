### Title
Tokens held by the pool or controller outside tracked `cash` have no withdrawal path and are permanently locked - (File: contracts/pool/src/cache/cash.rs)

### Summary
The pool segregates token custody from accounting: every outbound transfer must pass through `Cache::transfer_out`, and every exit path (`withdraw`, `borrow`, `repay` refund, `recapitalize` refund, `claim_revenue`, `flash_loan`) is bounded by the tracked `cash` book, not by `token.balance(pool)`. Tokens that arrive at the pool without a corresponding `credit_cash` — i.e., any direct `token.transfer` to the pool address — raise the real balance but never the book, and no endpoint in the pool ABI can pay them out. The same applies to the controller: `flash_position` returns only positive deltas on declared `refund_assets`; undeclared callback assets "receive neither credit nor refund" and the docs explicitly state "There is no controller sweep endpoint." Both are permanent locks reachable by a single unprivileged address.

### Finding Description
`Cache::transfer_out` is the only outbound token mechanism in the pool, and it never inspects the live SAC balance — it just transfers whatever the caller asked for, while all upstream callers gate the amount on the `cash` book via `require_reserves` (`cash.rs:15-21`) or the backing shortfall (`recapitalize::accounting`, `ops/recapitalize.rs:52`). Donations are explicitly documented as non-accrediting: INV-ACCT-02 states "token donations alone do not increase [cash]" and "Outbound token transfer and cash bookkeeping remain separate actions." The pool's complete ABI surface (per `contracts/pool/README.md`) contains no skim, sweep, rescue, or sync function — `upgrade` is the only escape and is owner-gated. On the controller side, `docs/reference/endpoints.md:86` documents that undeclared `flash_position` callback assets receive neither credit nor refunds and that no controller sweep endpoint exists, so any token balance the controller accumulates is stranded.

### Impact Explanation
Permanent freezing of funds. Any user, integration, or flash receiver that pushes tokens directly to the pool (e.g., pre-funding a `supply`/`recapitalize` in the mistaken belief the pool reads its balance, or a token callback that pays the pool) creates an unrecoverable surplus. Likewise, tokens delivered to the controller during a `flash_position` callback for an asset not declared in `refund_assets` are stuck forever. Unlike the ReachFactory case, the funds cannot even be rescued by governance execution within the current ABI, since no outbound path exists for untracked balances.

### Likelihood Explanation
Requires a caller error — sending tokens to a contract address outside the measured-receipt entrypoints — so likelihood is moderate-to-low, but it is fully reachable by an unprivileged address via ordinary `token.transfer` or an own flash receiver that pushes extra/undeclared assets. No privileged action, oracle manipulation, or race is needed; once sent, the lock is unconditional.

### Recommendation
Either add an owner-gated `sweep(asset, amount)` on the pool bounded to `balance - sum_of_all_market_cash(asset)` (and an analogous controller sweep), or document the donation-stranding behavior in user-facing docs. Note the pool shares one physical balance across all `(hub, token)` books for the same token, so the sweep bound must aggregate `cash` across hubs for that `asset_id`, not just one market.

### Proof of Concept

```rust
// Attacker/mistaken user path — any unprivileged address:
let token = token::Client::new(&env, &asset);
token.transfer(&user, &pool_address, &1_000_000);   // direct donation

// pool's real balance increases by 1_000_000, but `cash` does not.
// Every payout is capped by the book:
//   withdraw/borrow/claim_revenue -> require_reserves(amount)  // cash.rs:15
//   recapitalize refund -> min(amount, backing_shortfall)      // ops/recapitalize.rs:52
//   flash_loan        -> principal+fee pulled back by measure  // ops/flash_loan.rs
// The pool ABI lists no sweep/rescue endpoint (contracts/pool/README.md Surface),
// so the 1_000_000 can never leave the contract.

// Controller variant:
// call controller.flash_position(...) with refund_assets = [];
// inside execute_flash_loan, the receiver transfers tokens of an undeclared
// asset to the controller. Per endpoints.md: "Undeclared callback assets
// receive neither credit nor refunds. There is no controller sweep endpoint."
// -> tokens are permanently locked in the controller.
```
