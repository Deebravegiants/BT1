## Title
Webhook shop-domain identity spoofing due to HMAC not covering shop/topic headers - (File: `lib/shopify_api/webhooks/request.rb`)

### Summary
`ShopifyAPI::Webhooks::Request` computes its signable content from the raw HTTP body only, while the `shop`, `topic`, `webhook_id`, and `api_version` values are read straight from unauthenticated HTTP headers. `Registry.process` validates the HMAC and then trusts these header-derived values to build `WebhookMetadata`, which is handed to the app's webhook handler as the identity of the shop that "owns" the event.

### Finding Description
`Request#to_signable_string` returns only `@raw_body`: [1](#0-0) 

The `shop`, `topic`, `webhook_id`, and `api_version` accessors are derived from headers that are never part of the signed content: [2](#0-1) 

`HmacValidator.validate` only checks that the raw body was signed with the app's shared `api_secret_key` — it says nothing about which shop the payload belongs to: [3](#0-2) 

`Registry.process` validates only this body HMAC, then immediately trusts `request.shop`, `request.topic`, and `request.webhook_id` to construct the metadata passed to the app's handler: [4](#0-3) 

Because `api_secret_key` is one shared secret for the whole app (not per-shop), `HMAC(secret, raw_body)` is identical no matter which of the app's installed shops originally triggered the webhook. This breaks the intended identity binding: **`request.shop` (used by the handler to attribute the event) ≠ the shop actually covered by the HMAC (none — only `raw_body` is covered)**.

### Impact Explanation
Any user who has legitimately installed the app on their own shop (an unprivileged, un-elevated position — installing a Shopify app requires no special access) receives real webhook deliveries: a `(raw_body, x-shopify-hmac-sha256)` pair that is valid under the app's shared secret. Because the shop-domain header is not covered by that HMAC, the same attacker can POST that exact `raw_body` + valid `hmac` header to the app's public webhook endpoint while substituting `x-shopify-shop-domain` (and optionally `topic`/`webhook-id`) with a victim shop's domain. `HmacValidator.validate` still succeeds since it only checks the body signature, and `Registry.process` invokes the handler with `WebhookMetadata.shop` set to the forged victim domain. Any app logic that trusts `webhook.shop` to select the tenant record, session, or access token to act on will now operate on the victim shop's data/session using attacker-controlled payload content — a cross-tenant identity confusion.

### Likelihood Explanation
Requires only: (1) the attacker's own legitimate app installation (no special privileges), to obtain one authentic body+hmac pair, and (2) the ability to POST arbitrary HTTP headers to the app's public webhook URL, which is by design internet-reachable and unauthenticated apart from this HMAC check. No `api_secret_key`, access token, or other privileged credential is needed.

### Recommendation
Include the identity-binding headers (`shop`, `topic`, `webhook_id`, `api_version`) in the signable content, or otherwise cryptographically bind the shop domain to the signature verification (e.g., verify a per-shop expectation server-side) so that `HmacValidator.validate` fails whenever any of these values are altered independently of the body.

### Proof of Concept
1. Attacker installs the target app on `attacker-shop.myshopify.com`; Shopify sends a real webhook: body `B`, header `x-shopify-hmac-sha256: H` (valid because `H = HMAC(api_secret_key, B)`), and `x-shopify-shop-domain: attacker-shop.myshopify.com`.
2. Attacker replays the exact same `B` and `H`, but sets `x-shopify-shop-domain: victim-shop.myshopify.com` in a POST to the app's webhook endpoint.
3. `ShopifyAPI::Webhooks::Request.new` parses these forged headers (`lib/shopify_api/webhooks/request.rb:45-63`).
4. `Registry.process` calls `Utils::HmacValidator.validate(request)`, which passes because it only checks `HMAC(api_secret_key, B) == H` (`lib/shopify_api/utils/hmac_validator.rb:12-31`, `lib/shopify_api/webhooks/registry.rb:190`).
5. The handler receives `WebhookMetadata.new(shop: "victim-shop.myshopify.com", body: parsed(B), ...)` (`lib/shopify_api/webhooks/registry.rb:198-199`) and performs whatever shop-scoped action the app implements, attributing attacker-controlled body content to the victim tenant.
