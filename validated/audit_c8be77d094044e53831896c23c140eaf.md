### Title
LT (leveraged-token reserve asset) sent directly to a curve `Pair` is permanently and irrecoverably locked with no rescue path - ([File: packages/contracts/src/Pair.sol])

### Summary
Any LT (the ERC20 reserve asset paired against a launched token on the bonding curve) that is transferred directly into a `Pair` contract — by a trader, a bot, or by mistake — becomes permanently unrecoverable. `Pair` exposes no `skim`/`sweep`/`withdraw` function, and the only privileged exit path (`Router.graduate`) can be called exactly once per token, for an amount that explicitly excludes any donated balance. Once a token graduates, that LT can never leave the `Pair` contract again, by anyone, including the protocol owner.

### Finding Description
`Pair.sol` tracks `_pool.tokenReserve` / `_pool.assetReserve` as accounting state, separate from the live ERC20 balance the contract actually holds: [1](#0-0) 

The only way asset tokens leave the pair is `transferAsset`, gated `onlyRouter`: [2](#0-1) 

`Router` exposes `transferAsset` through exactly two paths: `sell` (which transfers only the curve-computed `assetOut`, derived from stored reserves/`k`, never the live balance) and `graduate` (which transfers only an explicit `amount` passed by `Bonding`): [3](#0-2) [4](#0-3) 

`Bonding._prepareGraduationLiquidity` is the sole caller of `Router.graduate`, and it deliberately computes `ltFromPair` from the pair's *stored* `assetReserve` minus the recovered launch-time virtual reserve — excluding any directly-donated LT by construction, and this function runs at most once per token (guarded by the `Lifecycle.Curve → Graduating` transition): [5](#0-4) 

This donation-exclusion is explicitly acknowledged in the project's own documentation as a permanent lock, framed only as a "trust assumption": [6](#0-5) 

Unlike `Bonding`, which has a dedicated sweep for LT that lands in the wrong place (`_sweepLTToOwner`, run at the end of every `finalizeGraduation`): [7](#0-6) 

`Pair` has **no equivalent mechanism at all** — no `skim`, no owner-gated rescue, nothing. Once `graduate` has fired once for a token (or if the token never graduates and simply sits with LT balance above `assetReserve` forever), the surplus balance is permanently stranded: `Router.sell`'s payout is bounded by curve math on stored reserves, not by the pair's actual balance, and `Router.graduate` cannot be invoked a second time because `Bonding`'s lifecycle gate has already flipped past `Curve`. This is a direct structural analog to the referenced report's core defect — an accounting value (`poolAmount` there, `assetReserve`/curve math here) permanently caps what can ever leave a contract, while the contract's actual token balance can exceed it with no recovery path.

### Impact Explanation
Any LT sent directly to a `Pair` — whether by user error, a bot mis-targeting an address, or an intentional "donation" attempting to influence the curve — is permanently and irreversibly lost. This is a direct, unconditional loss of funds with no privileged recovery path (not even the protocol owner can retrieve it), for every single launched token's `Pair` contract, both pre- and post-graduation. Because `Pair` is deployed once per launched token and is a first-class, publicly known address (returned from `Bonding.getTokenInfo`/`Factory.getPair`), this is trivially reachable by any unprivileged wallet.

### Likelihood Explanation
Reaching this requires nothing more than a standard `IERC20(lt).transfer(pairAddress, amount)` call from any wallet holding the relevant LT — no special permissions, no timing constraints, and it can be triggered accidentally (e.g., a user resolving the wrong recipient from a UI) just as easily as intentionally. Given that `Pair` addresses are public and the LT is a widely-traded external asset, the likelihood of some LT eventually landing there via error or curiosity is high over the life of the protocol.

### Recommendation
Add an explicit sweep/rescue path on `Pair` (or on `Bonding`/`Router` acting through it) that lets a privileged actor (e.g., protocol owner via `Router`'s `BONDING_ROLE`) recover `assetBalance() - assetReserve` (and analogously `tokenBalance()` overage beyond `tokenReserve`, if any) at any lifecycle stage, mirroring the `_sweepLTToOwner` pattern already used for `Bonding`'s own escrow. This closes the parity gap between "LT stuck in `Bonding`" (recoverable) and "LT stuck in `Pair`" (currently unrecoverable).

### Proof of Concept
1. A token `T` is launched via `Bonding.launch(...)`, creating pair `P` against LT `L`.
2. Any wallet (no privilege required) calls `IERC20(L).transfer(P, X)` directly — this only increases `P`'s ERC20 balance; `Pair._pool.assetReserve` is untouched (only `mint`/`swap` mutate it, per `packages/contracts/src/Pair.sol` lines 55-79).
3. Trading continues normally; `Router.sell` computes payouts from `_pool` (stored reserves/`k`), never from the live balance, so `X` is never paid out to sellers.
4. The token eventually graduates: `Bonding._prepareGraduationLiquidity` computes `ltFromPair = assetReserve - virtualLtReserve` from the *stored* reserve (lines 1073-1096), which excludes `X`. `Router.graduate(T, ltFromPair)` drains only that computed amount from `P`.
5. `T`'s lifecycle flips to `Graduated`; `_prepareGraduationLiquidity`/`Router.graduate` can never be invoked again for `T`.
6. `X` LT remains in `P` forever. No function on `Pair`, `Router`, or `Bonding` — not even one restricted to the contract owner — can ever move it out, since `Pair.transferAsset` is `onlyRouter`, and `Router`'s only two callers of it (`sell`, `graduate`) are exhausted/formula-bound as shown above.

    function swap(
        uint256 tokenIn,
        uint256 tokenOut,
        uint256 assetIn,
        uint256 assetOut
    ) external onlyRouter returns (bool) {
        uint256 newTokenReserve = (_pool.tokenReserve + tokenIn) - tokenOut;
        uint256 newAssetReserve = (_pool.assetReserve + assetIn) - assetOut;
        if ((newTokenReserve + 1) * (newAssetReserve + 1) < _pool.k) revert KInvariantViolated();

        _pool.tokenReserve = newTokenReserve;
        _pool.assetReserve = newAssetReserve;
        emit Swap(tokenIn, tokenOut, assetIn, assetOut);
        return true;
    }

    function sell(
        uint256 amountIn,
        address token,
        address to
    ) external onlyRole(BONDING_ROLE) returns (uint256 tokensIn, uint256 assetOut) {
        if (amountIn == 0) revert ZeroAmount();

        address asset = assetTokenFor(token);
        address pairAddr = factory.getPair(token, asset);
        if (pairAddr == address(0)) revert PairNotFound();
        tokensIn = amountIn;

        IERC20(token).safeTransferFrom(to, pairAddr, amountIn);

        assetOut = _computeSell(pairAddr, amountIn);

        IPair(pairAddr).transferAsset(to, assetOut);

        IPair(pairAddr).swap(amountIn, 0, 0, assetOut);
    }

    function _computeSell(
        address pairAddr,
        uint256 amountIn
    ) internal view returns (uint256 assetOut) {
        IPair pair = IPair(pairAddr);
        (uint256 reserveToken, uint256 reserveAsset) = pair.getReserves();
        uint256 k = pair.k();

        uint256 newReserveToken = reserveToken + amountIn;
        assetOut = reserveAsset - (k / newReserveToken);
    }

        address token,
        uint256 amount
    ) external onlyRole(BONDING_ROLE) {
        address asset = assetTokenFor(token);
        address pairAddr = factory.getPair(token, asset);
        if (pairAddr == address(0)) revert PairNotFound();
        IPair(pairAddr).transferAsset(msg.sender, amount);

    ///      emitting `LTRescued`. Called at the end of
    ///      `finalizeGraduation` with `keep = protectedLT` (any escrow
    ///      that doesn't belong to this graduation), so only THIS
    ///      graduation's rebalance residue lands on the owner. No-op on
    ///      the empty-pair fast path (nothing to sweep).
    function _sweepLTToOwner(
        address lt,
        uint256 keep
    ) internal {
        uint256 bal = IERC20(lt).balanceOf(address(this));
        if (bal <= keep) return;
        uint256 amount = bal - keep;
        address recipient = owner();
        IERC20(lt).safeTransfer(recipient, amount);
        emit LTRescued(lt, recipient, amount);
    }

    function _prepareGraduationLiquidity(
        address tokenAddress
    ) internal returns (uint256 tokensForLP, uint256 ltFromPair, uint256 lpBurned, uint256 unsoldBurned) {
        address pairAddr = _s().tokenInfo[tokenAddress].pair;
        (uint256 tokenReserve, uint256 assetReserve) = IPair(pairAddr).getReserves();

        unsoldBurned = IPair(pairAddr).tokenBalance();
        if (unsoldBurned > 0) {
            Token(tokenAddress).burn(pairAddr, unsoldBurned);
        }

        ltFromPair = assetReserve - _launchTimeVirtualLtReserve(tokenAddress, pairAddr);
        if (ltFromPair > 0) {
            _s().router.graduate(tokenAddress, ltFromPair);
        }

        tokensForLP = assetReserve == 0 ? 0 : (ltFromPair * tokenReserve) / assetReserve;
        if (tokensForLP > LP_RESERVE) tokensForLP = LP_RESERVE;

        lpBurned = LP_RESERVE - tokensForLP;
        if (lpBurned > 0) {
            Token(tokenAddress).burn(address(this), lpBurned);
        }
    }
