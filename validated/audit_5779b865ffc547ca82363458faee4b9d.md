### Title
A stuck/reverting BounceTech LT `exchangeRate()` permanently freezes all buys and sells on a bonding curve - ([File: packages/contracts/src/Bonding.sol])

### Summary
`Bonding.buy()` and `Bonding.sell()` both unconditionally consult `canGraduate(token_)` as part of every trade, and `canGraduate` calls the external LT's `exchangeRate()` whenever the pair still holds curve supply. `Zap._sellInternal` also calls `bonding.canGraduate(tokenAddress)` before every sell, and `Zap._executeBuy` (via `Bonding.previewLtUntilGraduation`) calls `exchangeRate()` on every pre-graduation buy. The paired LT address (`TokenInfo.ltAddress`) is written once at launch and has no setter, and there is no governance/timelock path to repoint a token's curve at a different LT. If the external LT's `exchangeRate()` enters a permanently reverting state, every buy and sell for that token becomes permanently unusable — the exact "stuck aggregator" bug class from the referenced Chainlink report, mapped onto alt.fun's external-LT dependency.

### Finding Description
`Bonding.canGraduate()` is the single choke point that every curve trade passes through: [1](#0-0) 

`Bonding.sell()` calls `canGraduate(tokenAddress)` unconditionally before executing the actual swap, on every sell, regardless of whether the token is anywhere near the graduation threshold: [2](#0-1) 

The docs confirm this call happens "at the end of every buy inside `_executeBuy`" as well, and `Zap._sellInternal` independently calls `bonding_.canGraduate(tokenAddress)` before routing a sell: [3](#0-2) 

`Zap._executeBuy` on the pre-graduation path also depends on `exchangeRate()` via `Bonding.previewLtUntilGraduation`, which itself calls `IBounceLeveragedToken(info.ltAddress).exchangeRate()`: [4](#0-3) 

The paired LT address is fixed once at launch in `TokenInfo.ltAddress` with no update path — `transferCreator` only rotates the creator, not the LT: [5](#0-4) [6](#0-5) 

The project's own documentation acknowledges a *de-registration* scenario for BounceTech LTs but explicitly assumes `exchangeRate()` "still works" in that case and concludes "no funds are stranded": [7](#0-6) 

That assumption does not hold if the LT's `exchangeRate()` view itself starts reverting (e.g., a division-by-zero in its `totalAssets/totalSupply` computation, an internal oracle it depends on getting stuck, or a botched BounceTech upgrade) rather than merely returning a stale/frozen number. In that failure mode:
- `Bonding.sell()` reverts for every trader on that curve (via `canGraduate`'s `exchangeRate()` call), contradicting the doc's claim that "holders can always exit via redeem."
- `Bonding.buy()` / `Zap.buy()` also revert (via `previewLtUntilGraduation`'s `exchangeRate()` call).
- There is no admin/governance function anywhere in `Bonding.sol` to repoint `TokenInfo.ltAddress` for an already-launched token, so the curve is permanently bricked — the exact analog of the reported Chainlink "stuck aggregator" defect in `TwapOracle.consult`.

### Impact Explanation
Every unprivileged holder of the affected launched token is permanently unable to sell their tokens back through `Bonding.sell()`/`Zap.sell()`, and no one can buy through `Bonding.buy()`/`Zap.buy()` either, since both paths route through `canGraduate`/`previewLtUntilGraduation`, both of which call the stuck LT's `exchangeRate()`. Because `Bonding.launch` never wrote a mutable LT pointer and there is no admin setter for `TokenInfo.ltAddress`, the freeze is irrecoverable for that token: curve-held LT (from prior buys) and trader-held launched tokens are permanently locked out of the trading surface. This is a permanent freezing-of-funds condition scoped to any token paired against the affected LT.

### Likelihood Explanation
Likelihood depends entirely on the external BounceTech LT staying healthy — the same low-probability-but-nonzero risk class judged Medium/severity-2 in the referenced Chainlink report ("the risk exists, and third-party dependencies should be treated with respect"). Given the LT is a fully external, upgradeable, permissionlessly-selectable dependency (any creator can pick any registered LT at `launch()`), and the protocol has zero fallback or escape hatch if that dependency's `exchangeRate()` reverts, this is a design gap rather than a one-off implementation bug.

### Recommendation
Add a fallback path so a stuck LT cannot permanently brick a curve:
- Wrap the `exchangeRate()` call in `canGraduate`/`previewLtUntilGraduation`/`Zap._executeBuy`/`Zap._sellInternal` in a try/catch (or low-level staticcall) so a revert degrades gracefully — e.g., treat the USD graduation leg as unavailable while the LT is stuck.
- Give governance a way to migrate an existing token's curve to a replacement LT (ideally with a timelock) as an emergency recovery path, since a launched curve otherwise has no way to unstick itself.
- At minimum, decouple `Bonding.sell()`'s ability to let holders exit from `canGraduate`'s USD leg — sells should not require a live `exchangeRate()` read to redeem back through `redeem()`.

### Proof of Concept
1. Launch a token paired with LT `L` via `Bonding.launch`, then buy through `Zap.buy` so the curve accrues real LT reserve.
2. Cause `L.exchangeRate()` to permanently revert (in production this maps to BounceTech's internal accounting hitting a division-by-zero, an internal price source becoming stuck, or a botched upgrade — mirrored in the mock via `vm.mockCallRevert(address(lt), abi.encodeWithSelector(IBounceLeveragedToken.exchangeRate.selector), "")`, analogous to the mock-revert pattern already used in `test_buy_capPath_doesNotInvokeLTRedeem`: [8](#0-7) ).
3. Any subsequent call to `Zap.sell(tokenAddress, tokenAmount, minUsdcOut)` reverts, because `_sellInternal` calls `bonding_.canGraduate(tokenAddress)` first, which calls the now-reverting `exchangeRate()`.
4. Any subsequent call to `Zap.buy(tokenAddress, usdcAmount, minTokensOut, referrer)` on the pre-graduation path also reverts via `previewLtUntilGraduation`'s `exchangeRate()` call.
5. No function in `Bonding.sol` exists to change `TokenInfo.ltAddress` for this already-launched token, so both buy and sell remain permanently reverting — trader tokens and curve-held LT are stuck.

    function canGraduate(
        address token_
    ) public view returns (bool) {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[token_];
        if (info.creator == address(0)) return false;
        if (info.lifecycle != Lifecycle.Curve) return false;

        address pair = info.pair;
        if (IPair(pair).tokenBalance() == 0) return true;

        (, uint256 assetReserve) = IPair(pair).getReserves();
        uint256 realLtRaised = assetReserve - _launchTimeVirtualLtReserve(token_, pair);
        uint256 valueUsd = (realLtRaised * IBounceLeveragedToken(info.ltAddress).exchangeRate()) / 1e18;
        return valueUsd >= $.graduationThresholdUsd;
    }

    function previewLtUntilGraduation(
        address token_
    ) external view returns (uint256) {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[token_];
        if (info.creator == address(0)) return 0;
        if (info.lifecycle != Lifecycle.Curve) return 0;

        address pair = info.pair;
        uint256 realBalance = IPair(pair).tokenBalance();
        if (realBalance == 0) return 0;

        (uint256 reserveToken, uint256 reserveAsset) = IPair(pair).getReserves();

        uint256 ltUntilThreshold = type(uint256).max;
        uint256 exchangeRate = IBounceLeveragedToken(info.ltAddress).exchangeRate();
        if (exchangeRate > 0) {
            uint256 realLtRaised = reserveAsset - _launchTimeVirtualLtReserve(token_, pair);
            uint256 thresholdRealLt = ($.graduationThresholdUsd * 1e18 + exchangeRate - 1) / exchangeRate;
            if (realLtRaised >= thresholdRealLt) return 0;
            ltUntilThreshold = thresholdRealLt - realLtRaised;
        }

**Retired LTs.** The reserve asset is an external BounceTech LT. If BounceTech de-registers it (it redeploys a fresh LT at a new address and flips the old address's `ltExists` to `false`), bonding curves already pointing at the old LT keep trading — `mint` / `redeem` / `exchangeRate` still work — but its `exchangeRate` stops tracking the underlying, so leverage is effectively frozen. The USD trigger above then can't ripen further; the supply trigger still graduates the token, and holders can always exit via `redeem`, so no funds are stranded. `Bonding.launch` rejects new bonding curves against a retired LT (its `ltExists` gate), so only pre-existing bonding curves are affected.         uint256 buyAmount = bonding.graduationThresholdUsd() * 2;
        usdc.mint(trader, buyAmount);
