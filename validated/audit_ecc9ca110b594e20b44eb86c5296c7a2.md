### Title
Deposits above roughly 170 million whole tokens revert after a bad-debt supply-index write-down - (File: common/src/rates/scaling.rs)

### Summary
`Controller::supply` can become unusable for a single large deposit after bad debt drives a market’s `supply_index` to `SUPPLY_INDEX_FLOOR_RAW = RAY / 1_000`. At that floor, minting supply shares multiplies the deposited token amount by an additional `1_000`; a deposit above approximately `i128::MAX / 1e30`, or about `170_141_183` whole tokens, produces a scaled share amount that does not fit in `i128` and reverts with `MathOverflow`. This is reachable through the permissionless `supply` entrypoint and affects low-priced, high-supply assets.

### Finding Description
A public `supply` call reaches `contracts/pool/src/ops/supply.rs::apply`, which calls `Cache::calculate_scaled_supply` with the caller’s token amount. [1](#0-0) [2](#0-1) 

The share calculation is `floor(Ray::from_asset(amount) * RAY / supply_index)`. [3](#0-2) 

`supply_index` can be reduced to `SUPPLY_INDEX_FLOOR_RAW`, equal to `RAY / 1_000`, when bad debt is socialized. [4](#0-3) 

Although `mul_div_floor` uses an exact `I256` intermediate product, it still converts the final quotient back to `i128` and panics when that result is unrepresentable. [5](#0-4) [6](#0-5) 

For any asset decimals `d`, the effective share count at the floor is:

```text
amount * 10^(27-d) * RAY / (RAY/1000)
= amount * 10^(27-d) * 1000
= whole_tokens * 10^30
```

Therefore the maximum representable single deposit is about:

```text
i128::MAX / 10^30
≈ 170_141_183 whole tokens
```

This boundary is explicitly reflected by the protocol’s own test showing that a fully written-down market loses three decades of deposit headroom. [7](#0-6) 

### Impact Explanation
A user holding more than roughly 170 million whole units of a low-priced token cannot deposit that amount in one transaction once the market’s supply index has reached the floor. The call reverts after share calculation, causing the user to miss deposits, yield, or a desired market entry point. In extreme cases, aggregate share supply can also approach the `i128` ceiling, making further deposits fail even when the configured asset-unit cap has not been reached.

The impact is a deposit-liveness failure and temporary denial of a large supply action rather than direct theft.

### Likelihood Explanation
The issue requires a market that has undergone a severe bad-debt write-down and then remains or is made solvent enough to accept deposits. `clean_bad_debt` is permissionless, while `recapitalize` can restore backing without increasing `supply_index`. [8](#0-7) [9](#0-8) 

The amount threshold is fixed in whole-token terms, so it is most realistic for low-priced or high-circulating-supply assets. For example, 200 million whole tokens priced at `$0.01` represent about `$2 million`, while still exceeding the approximately 170 million-token limit.

### Recommendation
Bound or downscale the share result before conversion back to `i128`. At minimum, validate deposits against a per-index maximum that accounts for the reduced headroom at `SUPPLY_INDEX_FLOOR_RAW`; preferably use a wider internal share representation or reduce stored share precision after extreme supply-index write-downs. The configured cap check should also occur before share minting or use a non-saturating cap representation so the protocol returns a deliberate cap error rather than `MathOverflow`.

### Proof of Concept
Assume:

1. A listed market uses an 18-decimal low-priced token.
2. Bad debt has reduced `supply_index` to `RAY / 1_000`.
3. The market is solvent, for example because remaining debt or recapitalized cash covers the residual floor-valued supplier claims.
4. The configured supply cap permits a 200 million-token deposit.

An unprivileged caller invokes:

```rust
Controller::supply(
    env,
    caller,
    0,          // create a new account
    spoke_id,
    vec![
        &env,
        (
            HubAssetKey {
                hub_id,
                asset: low_priced_token,
            },
            200_000_000i128 * 10i128.pow(18),
        ),
    ],
)
```

The share calculation becomes:

```text
amount       = 200_000_000 * 10^18 = 2e26
amount_ray   = 2e26 * 10^9        = 2e35
shares       = 2e35 * 1e27 / 1e24 = 2e38
```

`2e38` exceeds `i128::MAX ≈ 1.7014e38`, so the widened division succeeds but `to_i128` panics with `GenericError::MathOverflow`, reverting the entire supply transaction.

/// Socializes `bad_debt` by reducing the supply index (capped at total supply value).
///
/// Used when seizing unpaid debt: remaining supplier claims shrink pro-rata.
/// No-op when total supplied value is zero. Floors the resulting index at
/// [`SUPPLY_INDEX_FLOOR_RAW`] to avoid a zero index.
pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}
```

pub fn mul_div_floor(env: &Env, x: i128, y: i128, d: i128) -> i128 {

fn supply_index_floor_costs_three_decades_of_deposit_headroom() {
    use crate::constants::SUPPLY_INDEX_FLOOR_RAW;
    use crate::validation::max_cap_for_decimals;

    let env = Env::default();
    let floor = Ray::from(SUPPLY_INDEX_FLOOR_RAW);
    let decimals = 7u32;

    // At index 1.0 the ceiling is the balance ceiling itself.
    let ceiling = max_cap_for_decimals(decimals);
    assert!(calculate_scaled_supply(&env, ceiling, decimals, Ray::ONE).raw() > 0);

    // At the floor the scaled form is 1_000x larger, so the largest deposit a
    // written-down market can still take is the ceiling divided by 1_000.
    let at_floor_ceiling = ceiling / 1_000;
    assert!(calculate_scaled_supply(&env, at_floor_ceiling, decimals, floor).raw() > 0);
    assert_eq!(at_floor_ceiling / 10i128.pow(decimals), 170_141_183);
```

/// Sizes and books the cash injection without transferring tokens.
///
/// Credits `min(amount, backing_shortfall)` to cash and commits. `refund` is
/// `amount - applied`.
pub(crate) fn accounting(
    env: &Env,
    hub_asset: HubAssetKey,
    amount: i128,
) -> RecapitalizationOutcome {
    require_nonneg_amount(env, amount);
    let mut cache = ops::renewed_market(env, &hub_asset);

    let applied = amount.min(guards::backing_shortfall(&cache));
    let refund = amount
        .checked_sub(applied)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));

    cache.credit_cash(applied);
    cache.commit();
