## Finding

### Title
Stale `TombStone` records survive ordinary object ownership transfers, allowing a historical (unrelated) address to hijack a "burned" object's ownership via `unburn` — (File: `aptos-move/framework/aptos-framework/sources/object.move`)

### Summary
Aptos's soft-burn mechanism for objects (used for NFTs, fungible-asset stores, and any `key`-typed object) records the burner's address in a `TombStone` resource so they can later reclaim the object. This `TombStone` is only cleared on the `TransferRef`-mediated transfer path (`transfer_with_ref`), but **not** on the ordinary ungated transfer path (`transfer`, `transfer_raw`, `transfer_to_object`) that most object transfers actually use. If an object is ever soft-burned and later resold/transferred normally one or more times, the stale `TombStone` persists silently. If any subsequent (legitimate) owner later disposes of the object by sending it to the well-known `BURN_ADDRESS` constant (a completely normal and expected way to permanently destroy an object, not requiring the `burn()`/`unburn()` API at all), the original, no-longer-associated address recorded in the stale `TombStone` can call `unburn` and reclaim full ownership of the object — hijacking it away from its rightful final custody chain.

### Finding Description
`burn()` does **not** move the object's ownership to `BURN_ADDRESS`; it only attaches a `TombStone { original_owner }` marker for indexer-hiding purposes, leaving `ObjectCore.owner` unchanged: [1](#0-0) 

`unburn()` allows reclaiming in two cases: (1) the caller is the current owner (harmless no-op cleanup), or (2) the current owner is `BURN_ADDRESS` and the caller matches the address stored in the `TombStone`, in which case ownership is reassigned back to that address via `transfer_raw_inner`: [2](#0-1) 

The only transfer path that proactively clears a stale `TombStone` is `transfer_with_ref` (`LinearTransferRef`-based transfer), as its own comment states — explicitly to prevent an old owner from later calling `unburn`: [3](#0-2) 

However, the ordinary/ungated transfer path used by `transfer`, `transfer_raw`, and `transfer_to_object` goes through `transfer_raw_inner`, which only updates `owner` and emits an event — it never checks for or removes an existing `TombStone`: [4](#0-3) 

This asymmetry means a `TombStone` set by owner A survives any number of subsequent ordinary ownership transfers to B, C, D, etc. If the object eventually reaches `BURN_ADDRESS` (a public constant, and the conventional/expected way for any current owner to permanently destroy an object without using the framework's `burn()` API), `unburn`'s second branch treats the *stale* recorded `original_owner` (A) as authoritative, letting A silently reclaim the object regardless of who legitimately owned or destroyed it since.

### Impact Explanation
This breaks the custody invariant that "object creation, transfer, burn, and ownership refs must preserve the intended controller." A completely unprivileged, historical address can reassign `ObjectCore.owner` for an object it no longer has any claim over, effectively stealing custody of whatever value the object represents or holds — a fungible asset primary store, an NFT/token object, or any resource reachable via that object's signer/`ExtendRef`. Simultaneously, the legitimate final owner who intentionally and permanently destroyed the object (by sending it to `BURN_ADDRESS`, the standard convention) loses it to an unrelated third party — a custody accounting corruption that moves value to the wrong holder and defeats the intended permanence of a burn. This is high/critical severity on mainnet given objects underlie a large share of Aptos-native asset custody (fungible asset stores, digital assets/NFTs, code objects).

### Likelihood Explanation
Likelihood is moderate-to-high: soft-burning-then-reselling an object is a plausible real-world flow (e.g., a marketplace listing utility, or a user mistakenly burning then later transferring instead of unburning), and sending an object to the literal `BURN_ADDRESS` via ordinary `transfer`/`transfer_raw` is a natural, expected pattern for "permanent destruction" independent of the specific `burn()`/`TombStone` API. No special privileges are required by the attacker (the original tombstone holder) beyond having burned the object at some point in its history — a normal, unprivileged action.

### Recommendation
Clear any existing `TombStone` on `object_addr` inside `transfer_raw_inner` (and/or `transfer_raw`/`transfer`/`transfer_to_object`) whenever ownership changes, mirroring the cleanup already performed in `transfer_with_ref`. This ensures a `TombStone`'s reclaim rights cannot outlive the ownership transfer that superseded it.

### Proof of Concept
1. Alice owns object `O` (e.g., a `FungibleStore` or NFT object) and calls `object::burn(alice, O)` → `TombStone { original_owner: alice }` is attached; `ObjectCore.owner` remains `alice` [5](#0-4) .
2. Alice sells/transfers `O` to Bob using the ordinary path: `object::transfer(alice, O, bob)`. This routes through `transfer_raw_inner`, which updates `owner` to `bob` but never touches the `TombStone` [6](#0-5) .
3. Later, Bob (legitimate current owner) decides to permanently destroy `O` and sends it directly to the well-known constant: `object::transfer(bob, O, BURN_ADDRESS)` [7](#0-6) . `ObjectCore.owner` becomes `BURN_ADDRESS`; the stale `TombStone{original_owner: alice}` is still present.
4. Alice — who no longer has any claim on `O` since step 2 — calls `object::unburn(alice, O)`. The check `object_core.owner == BURN_ADDRESS` passes, and `original_owner_addr (alice) == signer::address_of(alice)` passes, so `transfer_raw_inner(object_addr, alice)` reassigns ownership of `O` back to Alice [8](#0-7) .
5. Alice now controls `O` (and any value/state it holds), despite having sold it and despite Bob's explicit intent to permanently burn it.

    /// Transfer to the destination address using a LinearTransferRef.
    public fun transfer_with_ref(self: LinearTransferRef, to: address) {
        assert!(!exists<Untransferable>(self.self), error::permission_denied(EOBJECT_NOT_TRANSFERRABLE));

        // Undo soft burn if present as we don't want the original owner to be able to reclaim by calling unburn later.
        if (exists<TombStone>(self.self)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(self.self);
        };

        let object = borrow_global_mut<ObjectCore>(self.self);
        assert!(
            object.owner == self.owner,
            error::permission_denied(ENOT_OBJECT_OWNER),
        );
        event::emit(
            Transfer {
                object: self.self,
                from: object.owner,
                to,
            },
        );
        object.owner = to;
    }

    /// Attempts to transfer using addresses only. Transfers the given object if
    /// allow_ungated_transfer is set true. Note, that this allows the owner of a nested object to
    /// transfer that object, so long as allow_ungated_transfer is enabled at each stage in the
    /// hierarchy.
    public fun transfer_raw(
        owner: &signer,
        object: address,
        to: address,
    ) {
        let owner_address = signer::address_of(owner);
        verify_ungated_and_descendant(owner_address, object);
        transfer_raw_inner(object, to);
    }

    inline fun transfer_raw_inner(object: address, to: address) {
        let object_core = borrow_global_mut<ObjectCore>(object);
        if (object_core.owner != to) {
            event::emit(
                Transfer {
                    object,
                    from: object_core.owner,
                    to,
                },
            );
            object_core.owner = to;
        };
    }

    /// This only works for objects directly owned and for simplicity does not apply to indirectly owned objects.
    /// Original owners can reclaim burnt objects any time in the future by calling unburn.
    /// Please use the test only [`object::burn_object_with_transfer`] for testing with previously burned objects.
    public entry fun burn<T: key>(owner: &signer, object: Object<T>) {
        let original_owner = signer::address_of(owner);
        assert!(is_owner(object, original_owner), error::permission_denied(ENOT_OBJECT_OWNER));
        let object_addr = object.inner;
        assert!(!exists<TombStone>(object_addr), EOBJECT_ALREADY_BURNT);
        move_to(&create_signer(object_addr), TombStone { original_owner });
    }

    /// Allow origin owners to reclaim any objects they previous burnt.
    public entry fun unburn<T: key>(
        original_owner: &signer,
        object: Object<T>,
    ) {
        let object_addr = object.inner;
        assert!(exists<TombStone>(object_addr), error::invalid_argument(EOBJECT_NOT_BURNT));

        // The new owner of the object can always unburn it, but if it's the burn address, we go to the old functionality
        let object_core = borrow_global<ObjectCore>(object_addr);
        if (object_core.owner == signer::address_of(original_owner)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object_addr);
        } else if (object_core.owner == BURN_ADDRESS) {
            // The old functionality
            let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
            assert!(
                original_owner_addr == signer::address_of(original_owner),
                error::permission_denied(ENOT_OBJECT_OWNER)
            );
            transfer_raw_inner(object_addr, original_owner_addr);
        } else {
            abort error::permission_denied(ENOT_OBJECT_OWNER);
        };
    }
