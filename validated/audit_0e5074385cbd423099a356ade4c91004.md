### Title
Stale `_requestCommitments` entry after a delivered GetResponse allows a duplicate `handleGetRequestTimeouts` payout — (File: `evm/src/core/EvmHost.sol`)

### Summary
`EvmHost.dispatchIncoming(GetResponse, ...)` pays the relayer fee for a GetRequest once its response is delivered, but never deletes the corresponding `_requestCommitments[commitment]` entry the way every other terminal path (`dispatchTimeOut` for both Post and Get) does. This leaves fee metadata for an already-answered request "alive" indefinitely, so it can later be consumed a second time by `HandlerV2.handleGetRequestTimeouts`, which checks *only* a non-membership proof against a historical, already-stored Hyperbridge state root rather than the local EVM host's own response-delivery bookkeeping.

### Finding Description
`EvmHost.dispatchIncoming(GetResponse memory response, address relayer)` [1](#0-0)  writes a `_responseReceipts` entry, invokes the destination module's `onGetResponse`, and on success pays the relayer directly from `_requestCommitments[commitment].fee` — but it never clears `_requestCommitments[commitment]`. Contrast this with `dispatchTimeOut` for Post requests, which explicitly does `delete _requestCommitments[commitment];` before invoking the module callback [2](#0-1) , and the Get-timeout variant, which relies on the same `_requestCommitments` map for its own replay protection [3](#0-2) .

`HandlerV2.handleGetRequestTimeouts` only checks:
1. `host.requestCommitments(commitment).sender != address(0)` (still true, since it was never deleted), and
2. A non-membership proof that Hyperbridge's `ResponseReceipts` child-trie entry for this commitment is absent **at the specific `message.height` the caller supplies** [4](#0-3) .

It never checks the EVM host's own `_responseReceipts` map, which is the mapping actually set when the response was already delivered. Because `EvmHost` does not appear to prune old `_stateCommitments`/`_stateCommitmentsUpdateTime` entries once stored [5](#0-4) , a relayer can hold onto an *earlier*, already-verified Hyperbridge state root (from before Hyperbridge's `state-coprocessor` pallet recorded the response receipt) and use it to build a technically-valid non-membership proof against that stale height, even though the response has since been genuinely delivered and paid for.

The corresponding write on the Hyperbridge side happens in `handle_get_requests`, which calls `host.store_response_receipt(&get_response, &address)?` before dispatching the response out [6](#0-5) ; there is no code path that removes this receipt afterward, so membership at *later* heights is permanent — but nothing stops proving non-membership against an *older* height that predates the write.

### Impact Explanation
When both conditions are met (fee already paid via `handleGetResponses`, then a `handleGetRequestTimeouts` submitted with a stale height satisfying `request.timeout() <= state(height).timestamp`), `dispatchTimeOut` is invoked a second time for the same commitment:
- It deletes `_requestCommitments[commitment]` (finally), and
- Invokes `onGetTimeout` on the module even though the module already received `onGetResponse` for the same request — an inconsistent double dispatch, and
- Refunds `meta.fee` to `meta.sender`, on top of the relayer fee already paid out during the earlier successful `dispatchIncoming` [7](#0-6) .

This is a duplicate payout of the escrowed fee (paid once to the relayer, then again to the original payer as a "timeout refund"), directly draining the host's fee-token balance, and it also delivers a contradictory `onGetTimeout` callback to an application that already processed the response — undermining any invariants the application maintains about "answered vs timed-out" requests.

### Likelihood Explanation
This requires no privileged role — any relayer or observer of a normal GetRequest lifecycle can trigger it: dispatch/respond to a GetRequest as usual, then replay a `handleGetRequestTimeouts` call keyed to an earlier, already-verified consensus height with a genuine non-membership proof from before Hyperbridge recorded the response. Since `EvmHost` retains historical state commitments and their update timestamps without apparent expiry, and challenge periods only gate recency (not staleness), the necessary inputs (a valid earlier root, a request whose timeout predates that root's timestamp) are realistically obtainable for many GetRequest configurations, particularly those with short timeouts.

### Recommendation
In `EvmHost.dispatchIncoming(GetResponse, address)`, delete `_requestCommitments[commitment]` immediately after (or as part of) successfully paying the relayer fee, mirroring the pattern already used in `dispatchTimeOut`. Additionally, `handleGetRequestTimeouts`/`dispatchTimeOut` should check the host's own `_responseReceipts` for the commitment and reject the timeout if a response was already recorded locally, rather than relying solely on a non-membership proof against a caller-chosen historical height.

### Proof of Concept
1. Dispatch a `GetRequest` from `EvmHost` with a non-zero fee and a short `timeout`.
2. Capture and verify an early Hyperbridge consensus/state-machine height `H1` via `handleConsensus`, before the request is answered.
3. Let Hyperbridge answer the request; the response is delivered via `HandlerV2.handleGetResponses` → `EvmHost.dispatchIncoming(GetResponse, relayer)`, paying `relayer` the escrowed fee; `_requestCommitments[commitment]` remains set (bug).
4. Construct a valid Merkle/trie non-membership proof for `RESPONSE_RECEIPTS_STORAGE_PREFIX ++ commitment` against Hyperbridge's state root at `H1` (valid because the receipt was written only at a later height, after `H1`).
5. Call `HandlerV2.handleGetRequestTimeouts(host, message)` with `message.height = H1` and the proof from step 4; since `request.timeout() <= state(H1).timestamp` and `meta.sender != address(0)`, the call passes and `dispatchTimeOut` refunds `meta.fee` to `meta.sender` a second time and re-invokes `onGetTimeout` on the destination module — confirming duplicate payout and inconsistent module state.

     * @dev Dispatch an incoming GET response to source module
     * @param response - get response

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
