### Title
Fraud detection is unconditionally disabled, causing every signup to bypass fraud/liveness checks - (File: `src/plans/fraud_check.rs`)

### Summary
The original report describes `AccountantDelegate::sweepInterest` unconditionally destroying (transferring to `address(0)`) all `cnote` held by the contract without any check against how much should actually be preserved, permanently breaking the accounting invariant and any future computation that depends on it. The orb-core analog is the Fraud Check Engine: the code that decides whether a signup is fraudulent has been unconditionally hard-coded to report "no fraud," with the actual fraud logic entirely stripped out, regardless of any real signal computed by the biometric pipeline.

### Finding Description
In `src/plans/fraud_check.rs`, the number of fraud checks is hard-coded to zero and every helper returns an empty result: [1](#0-0) 

`Report::fraud_checks`, `fraud_checks_strict`, `enabled_checks_from_config`, and `feedback_messages` all return empty arrays, so `fraud_detected()` and `fraud_detected_with_config()` can never signal fraud: [2](#0-1) 

The call site that is supposed to run these checks during every signup, `MasterPlan::detect_fraud`, short-circuits with an explicit comment admitting the checks were deleted, and unconditionally returns `Ok(false)` (no fraud) for any pipeline output, no matter what the face-identifier fraud checks or biometric pipeline actually computed: [3](#0-2) 

This mirrors the `sweepInterest` bug class precisely: a critical state/decision (the escrowed `cnote` balance in the original; the fraud verdict here) is unconditionally wiped/forced to a fixed value ("transfer all cnote to address(0)" vs. "always return `Ok(false)`") instead of being derived from an actual check of the underlying data (`cNoteConverted >= noteDifferential` vs. the real face-identifier fraud signals in `pipeline.face_identifier_fraud_checks`). The pipeline still computes `face_identifier_fraud_checks` via the biometric pipeline (`pipeline::mod.rs`), but this signal is never plumbed into `detect_fraud`, exactly analogous to how the correct interest calculation exists conceptually but is destroyed before it can be used.

### Impact Explanation
Because `detect_fraud` always returns `false`, the `signup_reason` computed in `do_signup` can never become `SignupReason::Fraud` through this path: [4](#0-3) 

This means any fraudulent signup attempt that would have been caught by the Fraud Check Engine (e.g., presentation attacks, duplicate/fraud signals detected by the face identifier model) proceeds straight to enrollment as if it were a normal, legitimate signup. This is a direct fraud/liveness-bypass impact: unauthorized or fraudulent enrollments are attributed the same trust level as genuine ones, with no accounting for the fraud signal that was computed but discarded.

### Likelihood Explanation
This code path executes unconditionally on every production signup that reaches the fraud-check stage (i.e., every biometric capture that produces a pipeline), with no special privileges or conditions required to trigger it — it is not gated behind a feature flag guarding malicious behavior, it is simply the default, always-reached behavior of `MasterPlan::do_signup`. Any regular signup flow exercises this bypass.

### Recommendation
Restore fraud-check evaluation so `detect_fraud` derives its result from the actual computed signals (e.g., `pipeline.face_identifier_fraud_checks`) instead of an unconditional `Ok(false)`. At minimum, add explicit validation/require-style checks before treating a signup as fraud-free, mirroring the suggested fix for `sweepInterest` (require a real condition to be verified rather than defaulting to a destructive/no-op outcome). If the fraud check engine is intentionally stripped for the open-source build, this should be clearly gated and never allowed to silently apply to production enrollment decisions.

### Proof of Concept
1. Trigger a signup so that `biometric_pipeline` runs and produces `face_identifier_fraud_checks` with a genuine fraud signal (e.g., simulate/mock a `FraudChecks` result indicating fraud) — see [5](#0-4) .
2. Observe that `MasterPlan::detect_fraud` is invoked in `do_signup` at [6](#0-5)  and always returns `Ok(false)` per [7](#0-6) , regardless of the fraud signal from step 1.
3. Confirm `signup_reason` becomes `SignupReason::Normal` and the signup proceeds to `enroll_user`, completing enrollment despite the underlying fraud indicator.

impl Report {
    const DATADOG_TAGS: [&'static str; N_FRAUD_CHECKS] = [];

    fn fraud_checks(&self) -> [Option<bool>; N_FRAUD_CHECKS] {
        []
    }

    /// If fraud data are missing, we assume fraud is detected.
    fn fraud_checks_strict(&self) -> [bool; N_FRAUD_CHECKS] {
        self.fraud_checks().map(|v| v.unwrap_or(true))
    }

    fn enabled_checks_from_config(_config: &BackendConfig) -> [bool; N_FRAUD_CHECKS] {
        []
    }

    fn feedback_messages() -> [Option<PipelineFailureFeedbackMessage>; N_FRAUD_CHECKS] {
        []
    }

    /// Get the || result of all fraud checks, but under the Orb configuration.
    /// The end result might be different from the || of all fraud booleans as
    /// we might decide to not block a signup even if it's fraudulent.
    #[must_use]
    pub fn fraud_detected_with_config(
        &self,
        config: &BackendConfig,
    ) -> (bool, Vec<PipelineFailureFeedbackMessage>) {
        let enabled_checks = Self::enabled_checks_from_config(config);
        let fraud_results = self.fraud_checks_strict();
        let feedback_msgs = Self::feedback_messages();

        let feedback: Vec<PipelineFailureFeedbackMessage> = enabled_checks
            .iter()
            .zip(fraud_results.iter())
            .zip(feedback_msgs.iter())
            .filter_map(
                |((&enabled, &result), feedback_msg)| {
                    if enabled && result { feedback_msg.clone() } else { None }
                },
            )
            .collect();

        (!feedback.is_empty(), feedback)
    }

    /// If any fraud check fails or is missing data, fraud is reported.
    #[must_use]
    pub fn fraud_detected(&self) -> bool {
        self.fraud_checks_strict().iter().any(|&v| v)
    }
