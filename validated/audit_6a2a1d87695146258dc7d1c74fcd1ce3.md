## Custody Analog Found

### Title
Stale `TombStone.original_owner` survives ungated object transfers, letting a past owner reclaim an object a legitimate new owner sent to `BURN_ADDRESS` - (File: `aptos-move/framework/aptos-framework/sources/object.move`)

### Summary
Aptos's object model implements a "soft burn" via `TombStone`, directly analogous to the reported `retractLockedLizard` pattern: a past owner retains a latent reclaim right over an object even after it has legitimately changed hands. The framework partially defends against this — `transfer_with_ref` explicitly clears any existing `TombStone` before transferring — but the plain ungated-transfer path (`object::transfer` / `transfer_call` / `transfer_to_object`, all routed through `transfer_raw_inner`) does **not**. This omission lets a malicious former owner reclaim an object from `BURN_ADDRESS` that a subsequent, legitimate owner intentionally and permanently destroyed.

### Finding Description
`object::burn` does not move the object to `BURN_ADDRESS`; it only stamps a `TombStone { original_owner }` while leaving `ObjectCore.owner` untouched: [1](#0-0) 

`object::unburn` grants full reclaim rights to `original_owner` whenever the object's *current* owner is `BURN_ADDRESS`: [2](#0-1) 

The only place that proactively clears a stale `TombStone` on ownership change is `transfer_with_ref` (the `LinearTransferRef` path), whose own comment states the exact intended invariant: [3](#0-2) 

However, the plain/ungated transfer path used by `transfer`, `transfer_call`, and `transfer_to_object` goes through `transfer_raw` → `transfer_raw_inner`, which only updates `owner` and emits an event — it never checks for or clears an existing `TombStone`: [4](#0-3) 

Because of this asymmetry, if attacker **A** soft-burns an object they own (creating `TombStone{original_owner: A}` while still holding it), then transfers it to victim **B** via the plain `object::transfer` entry function (a normal wallet-to-wallet send or OTC trade — not a marketplace flow using `LinearTransferRef`), the `TombStone` survives untouched. `B` is now the legitimate owner and has no on-chain visibility that a dangling tombstone exists. If `B` later performs the framework's documented way to permanently discard the object — transferring it to `BURN_ADDRESS` via plain `object::transfer` — `ObjectCore.owner` becomes `BURN_ADDRESS` per the intended semantics (`BURN_ADDRESS: address = @0xff...ff` — "Address where unwanted objects can be forcefully transferred to"): [5](#0-4) 

At that point, attacker `A` calls `unburn(A, object)`. The check `object_core.owner == BURN_ADDRESS` succeeds, and `original_owner_addr == signer::address_of(A)` also succeeds (since the tombstone was never cleared), so `transfer_raw_inner(object_addr, A)` restores ownership to `A` — the attacker — even though `A` had no involvement in `B`'s decision to burn the object and no ownership at the time of that burn.

### Impact Explanation
This is a direct object/asset-ownership takeover: a party that no longer owns an object (and had transferred it away in good faith or via sale) can reclaim it from `BURN_ADDRESS` at the expense of the legitimate current owner who intended a permanent, irreversible burn. Any token/NFT object minted with default `allow_ungated_transfer = true` (the common case, e.g. `aptos_token`, marketplace containers not using `TransferRef`) is exposed. This corrupts custody/ownership-recovery invariants: `B`'s intended irrecoverable destruction of the asset is silently reversed and redirected to `A`, effectively stealing the asset back from the party who should have final say over its own burn. This matches the "Custody Pivots" requirement that burn/transfer paths must preserve the intended controller and that a "permanent lock or non-recoverable loss" (from `B`'s perspective, an unauthorized recovery) not be exploitable by an unprivileged, non-owning party.

### Likelihood Explanation
Medium-to-High. It requires no special privileges — only that the attacker be a past owner of an object that (a) was soft-burned once, then (b) transferred onward via a plain `object::transfer`/`transfer_call` rather than a `TransferRef`-based marketplace flow, and (c) the new owner later sends it to `BURN_ADDRESS` to genuinely discard it (the framework's own documented mechanism for permanent burns). This is a realistic path for any object minted with ungated transfer left enabled and moved via simple owner-to-owner transfers (exactly the "OTC trade" scenario called out in the source report), and the attacker fully controls step (a) and can simply wait for step (c), or induce it via social/product flows that encourage burning unwanted objects.

### Recommendation
Clear any existing `TombStone` in `transfer_raw_inner` (or in `transfer_raw`) whenever ownership changes, mirroring the logic already present in `transfer_with_ref`:
```move
inline fun transfer_raw_inner(object: address, to: address) {
    if (exists<TombStone>(object)) {
        let TombStone { original_owner: _ } = move_from<TombStone>(object);
    };
    let object_core = borrow_global_mut<ObjectCore>(object);
    ...
}
```
Alternatively, scope `unburn`'s reclaim-from-`BURN_ADDRESS` branch to only succeed if no ownership transfer has occurred since the tombstone was created (e.g., by tracking the owner at burn time and requiring it match the owner right before the burn-address transfer), ensuring the stale `original_owner` recorded by a *different* prior custody chain can never be honored.

### Proof of Concept
```move
// Assume `hero` is an Object<Hero> with allow_ungated_transfer = true, owned by A.

// 1. Attacker A soft-burns while still owning it (owner field unchanged).
object::burn(A, hero); // TombStone{ original_owner: A } created; hero.owner == A

// 2. A sends the (still tomb-stoned) object to victim B via plain ungated transfer,
//    e.g. an OTC trade or simple wallet transfer, NOT via TransferRef/marketplace flow.
object::transfer(A, hero, B_address); // hero.owner == B; TombStone NOT cleared

// 3. B, the legitimate new owner, decides to permanently discard the object
//    using the framework's documented burn-address mechanism.
object::transfer(B, hero, BURN_ADDRESS); // hero.owner == BURN_ADDRESS

// 4. Attacker A reclaims the object B intentionally destroyed.
object::unburn(A, hero);
// object_core.owner == BURN_ADDRESS  -> true
// original_owner_addr (A) == signer::address_of(A) -> true
// => transfer_raw_inner(hero, A) executes; hero.owner becomes A again.
// A now owns an object that B rightfully and intentionally burned.
```

    inline fun transfer_raw_inner(object: address, to: address) {
        let object_core = borrow_global_mut<ObjectCore>(object);
        if (object_core.owner != to) {
            event::emit(
                Transfer {
                    object,
                    from: object_core.owner,
                    to,
                },
            );
            object_core.owner = to;
        };
    }
