# Finding: Stale `TombStone.original_owner` Enables Object Theft via `unburn` After Ownership Transfer

The external report's core custody invariant — *"an operation that changes an asset's economic finality must not silently misdirect recovery rights to the wrong party"* — has a direct analog in `aptos_framework::object`'s soft-burn/reclaim mechanism.

### Title
Stale `TombStone.original_owner` allows a former owner to reclaim an object legitimately owned and burned by someone else - (File: `aptos-move/framework/aptos-framework/sources/object.move`)

### Summary
`object::burn` creates a `TombStone { original_owner }` record without changing the object's actual `owner` field, and this `TombStone` is only cleared during ref-based transfers (`transfer_with_ref`), not during ordinary signer-based transfers (`object::transfer` / `transfer_raw`). If an object is soft-burned by owner A, then transferred normally to a new owner B, the stale `TombStone{original_owner: A}` persists. If B later sends the object to the well-known `BURN_ADDRESS` (the documented convention for permanently discarding an object), A — who no longer owns the object — can call `unburn` and reclaim it, stealing it from B.

### Finding Description
Key code, `aptos-move/framework/aptos-framework/sources/object.move`: [1](#0-0) 

- `burn` (line 645) only asserts the caller is the *current* owner and creates `TombStone{ original_owner }`; it does **not** transfer ownership.
- `unburn` (line 654) has two recovery branches:
  - If `object_core.owner == signer::address_of(original_owner)` → tombstone is simply removed (current owner reclaiming their own soft-burnt object — safe).
  - If `object_core.owner == BURN_ADDRESS` → the tombstone's stored `original_owner_addr` is checked against the caller and, if it matches, the object is transferred back to that address via `transfer_raw_inner`.

Ordinary ownership transfers do not clear an existing `TombStone`: [2](#0-1) 

Compare this to `transfer_with_ref`, which explicitly clears a stale `TombStone` on transfer: [3](#0-2) 

`transfer_raw`/`transfer`/`transfer_to_object` (the standard, signer-authorized transfer path most users and apps call) route through `transfer_raw_inner`, which has no such cleanup logic. This asymmetry means the tombstone written by an *earlier* owner survives an arbitrary number of subsequent legitimate ownership changes.

### Impact Explanation
Exploit path:
1. Attacker **A** owns a valuable object (e.g., an NFT/token object, or an object that itself holds a `FungibleStore`/other value).
2. A calls `object::burn(A, object)`. This is cheap and harmless-looking: ownership stays with A, only a `TombStone{original_owner: A}` is added (the object is merely hidden from indexers per the doc comment).
3. A transfers/sells the object normally to victim **B** via `object::transfer`. `TombStone` is *not* cleared because this is a raw/ungated transfer, not a `TransferRef`-based one.
4. B, now the legitimate sole owner, later decides to permanently destroy the object by sending it to the documented `BURN_ADDRESS` constant (`0xff...ff`), the only production-usable way to fully retire an object (the two-step combination of `burn` + transfer-to-`BURN_ADDRESS` is the real production pattern; the single-call helper `burn_object_with_transfer` is `#[test_only]`). Since `burn()` aborts if a `TombStone` already exists, B cannot re-stamp it with their own address — B just transfers straight to `BURN_ADDRESS`.
5. A calls `object::unburn(A, object)`. Because `object_core.owner == BURN_ADDRESS` and the stale `TombStone.original_owner == A`, the check passes and `transfer_raw_inner` sends the object back to **A**, not B.

This is a direct, unprivileged theft/misdirection of object-held value: ownership and recovery rights are given to a party (A) that no longer legitimately controls the asset, while the true final owner (B) permanently loses it. This satisfies the custody gate's "theft ... or owner reassignment of ... token objects" and "supply or custody accounting corruption that moves value to the wrong holder" criteria.

### Likelihood Explanation
- No privileged access is required; both `burn`, `transfer`, and `unburn` are public entry functions callable by any signer who is (at the relevant time) the object owner.
- The setup cost for the attacker is a single cheap `burn` call before selling/transferring the object — indistinguishable from ordinary usage since burnt objects are simply "hidden from indexers," not restricted from transfer.
- The trigger (victim sending an object to the canonical `BURN_ADDRESS`) is exactly the documented, expected way to discard an object in production, making the attack practical against marketplaces, token-burning UIs, or any protocol logic that discards objects by sending to `BURN_ADDRESS`.

### Recommendation
- Clear any existing `TombStone` whenever ownership changes through *any* transfer path (`transfer_raw_inner`), not only `transfer_with_ref`, so a stale `original_owner` can never outlive a legitimate ownership change.
- Alternatively/additionally, when checking the `owner == BURN_ADDRESS` branch in `unburn`, require that the address recorded as `original_owner` was the *immediately preceding* owner at the time of the burn-address transfer, or track the "last owner before burn" at the time of the actual transfer to `BURN_ADDRESS` rather than relying on a `TombStone` timestamped at an arbitrary earlier soft-burn.
- Consider disallowing `object::transfer`/`transfer_raw` on objects that already carry a `TombStone` (forcing callers to `unburn` first), removing the possibility of ownership changing hands while a stale tombstone is outstanding.

### Proof of Concept
```
// Move pseudo-scenario using aptos_framework::object
// 1. A creates and owns `obj`.
object::burn(&A, obj);                       // TombStone{original_owner: A}; owner stays A

// 2. A sells/transfers obj to B via normal transfer (TombStone NOT cleared).
object::transfer(&A, obj, address_of(&B));

// 3. B, the legitimate owner, "burns" (permanently discards) obj the standard way:
object::transfer(&B, obj, BURN_ADDRESS);     // owner = BURN_ADDRESS; stale TombStone.original_owner still A

// 4. A reclaims the object that rightfully belonged to B:
object::unburn<T>(&A, obj);                  // succeeds: owner == BURN_ADDRESS branch matches A
// Result: obj.owner == address_of(&A)  -- stolen from B
```

    inline fun transfer_raw_inner(object: address, to: address) {
        let object_core = borrow_global_mut<ObjectCore>(object);
        if (object_core.owner != to) {
            event::emit(
                Transfer {
                    object,
                    from: object_core.owner,
                    to,
                },
            );
            object_core.owner = to;
        };
    }

    /// Add a TombStone to the object.  The object will then be interpreted as hidden via indexers.
    /// This only works for objects directly owned and for simplicity does not apply to indirectly owned objects.
    /// Original owners can reclaim burnt objects any time in the future by calling unburn.
    /// Please use the test only [`object::burn_object_with_transfer`] for testing with previously burned objects.
    public entry fun burn<T: key>(owner: &signer, object: Object<T>) {
        let original_owner = signer::address_of(owner);
        assert!(is_owner(object, original_owner), error::permission_denied(ENOT_OBJECT_OWNER));
        let object_addr = object.inner;
        assert!(!exists<TombStone>(object_addr), EOBJECT_ALREADY_BURNT);
        move_to(&create_signer(object_addr), TombStone { original_owner });
    }

    /// Allow origin owners to reclaim any objects they previous burnt.
    public entry fun unburn<T: key>(
        original_owner: &signer,
        object: Object<T>,
    ) {
        let object_addr = object.inner;
        assert!(exists<TombStone>(object_addr), error::invalid_argument(EOBJECT_NOT_BURNT));

        // The new owner of the object can always unburn it, but if it's the burn address, we go to the old functionality
        let object_core = borrow_global<ObjectCore>(object_addr);
        if (object_core.owner == signer::address_of(original_owner)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object_addr);
        } else if (object_core.owner == BURN_ADDRESS) {
            // The old functionality
            let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
            assert!(
                original_owner_addr == signer::address_of(original_owner),
                error::permission_denied(ENOT_OBJECT_OWNER)
            );
            transfer_raw_inner(object_addr, original_owner_addr);
        } else {
            abort error::permission_denied(ENOT_OBJECT_OWNER);
        };
    }
