### Title

Interest accrual overflow permanently freezes a whale-utilized market - (File: common/src/rates/scaling.rs)

### Summary

A sufficiently large market can enter a state in which interest accrual always reverts before any repayment or withdrawal logic executes. `accrue_step` first converts scaled borrowed and supplied balances to their current values with `scaled_to_original`, which performs checked `i128` fixed-point multiplication. When `scaled * index` exceeds `i128::MAX`, every market operation that calls `global_sync` reverts with `MathOverflow`, permanently freezing supplier and borrower funds.

### Finding Description

Every pool mutation loads the market through `synced_market`, which calls `interest::global_sync` before applying the requested action. [1](#0-0)  `global_sync` invokes `accrue_step` for each elapsed chunk. [2](#0-1)  `accrue_step` unconditionally computes both `scaled_to_original(borrowed, borrow_index)` and `scaled_to_original(supplied, supply_index)` before calculating utilization. [3](#0-2)  `scaled_to_original` delegates to checked `Ray::mul`. [4](#0-3)  `Ray::mul` calls `mul_div_half_up`, which panics with `MathOverflow` if the represented quotient exceeds `i128`. [5](#0-4) [6](#0-5) 

The borrow-index ceiling does not prevent this state because the represented debt value can exceed `i128::MAX` before the index reaches `MAX_BORROW_INDEX_RAY`. The existing harness demonstrates a market holding one billion 18-decimal tokens at 98% utilization, advancing time, reverting `update_indexes` with `MathOverflow`, and then reverting both `withdraw` and `repay` for the same reason. [7](#0-6) 

An unprivileged attacker can construct the precondition through ordinary controller calls: `supply` accepts collateral and pool liquidity through `assets: Vec<(HubAssetKey, i128)>`, while `borrow` accepts `borrows: Vec<(HubAssetKey, i128)>` and pays the requested destination. [8](#0-7)  Once the represented balance crosses the overflow boundary, `withdraw`, `repay`, `liquidate`, `clean_bad_debt`, `recapitalize`, `claim_revenue`, and other paths that accrue the market all fail before their corrective logic can run.

### Impact Explanation

This causes permanent freezing of all supplier funds and prevents repayment, liquidation, bad-debt cleanup, recapitalization, and revenue recovery for the affected market. Because the overflow happens inside mandatory accrual rather than in an optional view or caller-selected calculation, no ordinary unprivileged or protocol workflow can return the market to an operable state after the boundary is reached.

### Likelihood Explanation

Exploitation requires a very large whale market and sustained high utilization, so it depends on substantial available token liquidity and elapsed time. It does not require privileged access, oracle manipulation, leaked keys, reentrancy, or malformed parameters: the attacker's ordinary `supply` and `borrow` positions create the state, and every later accrual deterministically reverts. The test proves the cliff using a one-billion-token, 18-decimal market at 98% utilization. [9](#0-8) 

### Recommendation

Represent intermediate accrued debt and supply values in a wider type such as `I256`, or explicitly bound market-scaled balances against the maximum possible index before accepting supply or debt. Add a recovery path that does not require successful `scaled_to_original` conversion before repaying, withdrawing, writing down debt, or capping the borrow index. Extend the regression test to prove that repayment and supplier exit remain possible at the maximum accepted market size and index boundary.

/// Computes `x * y / d` rounded half up. Requires `x >= 0`, `y >= 0`, and `d > 0`; a
/// `debug_assert` checks this in debug builds. Panics with `GenericError::DivisionByZero` if
/// `d == 0`, and with `GenericError::MathOverflow` if any other precondition is violated or if
/// the result does not fit in `i128`.
pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    // The zero check runs first so debug and release builds agree on a zero
    // divisor: both surface `DivisionByZero` rather than tripping the assert.
    require_nonzero_divisor(env, d);
    debug_assert!(
        x >= 0 && y >= 0 && d > 0,
        "mul_div_half_up: non-negative x, y and positive d"
    );
    try_mul_div_half_up(env, x, y, d)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
}

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
}
