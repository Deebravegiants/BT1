Audit Report

## Title
Plaintext passwords leaked in Debug-level HTTP request logs for GraphQL mutations due to non-recursive JSON redaction - (File: `core/web/router.go`)

## Summary
The Gin request-logging middleware `loggerFunc`, registered globally via `engine.Use(...)` and thus wrapping the GraphQL `POST /query` route, logs the full JSON request body at Debug level via `readBody`/`readSanitizedJSON`. Because `readSanitizedJSON` only inspects top-level JSON keys against the `blacklist`, and GraphQL mutation arguments are nested under `variables.input.*`, sensitive fields like `password`, `oldPassword`, and `newPassword` from the `createAPIToken` and `updateUserPassword` mutations bypass redaction and are written to logs in plaintext.

## Finding Description
`loggerFunc` is registered globally on the `engine` and wraps every route, including `api.POST("/query", auth.AuthenticateGQL(...), loader.Middleware(app), graphqlHandler(app))`. [1](#0-0) 

It reads the raw request body before `c.Next()` runs (i.e., before authentication is even evaluated) and logs it at Debug level after the handler chain completes: [2](#0-1) 

The redaction helper `readSanitizedJSON` unmarshals into a flat `map[string]any` and only redacts entries whose *top-level* key matches `isBlacklisted`: [3](#0-2) [4](#0-3) 

GraphQL requests place mutation arguments in a nested `variables` object (e.g., `CreateAPITokenInput.password`, `UpdatePasswordInput.oldPassword`/`newPassword`), so the top-level keys seen by `readSanitizedJSON` are only `"query"` and `"variables"` — neither is blacklisted — and the entire nested payload, including plaintext passwords, is logged verbatim. This is a genuine, code-verified logic flaw: the loop `for k, v := range dst` has no recursion into nested maps/objects, so any sensitive value more than one level deep in the JSON body is never redacted regardless of key name.

## Impact Explanation
When Debug-level logging is enabled, any client invoking `createAPIToken` or `updateUserPassword` (or any other mutation with sensitive nested input) causes the node to persist the plaintext password/secret into its own log stream. This is a CWE-532 sensitive-data-in-logs issue with a legitimate credential-exfiltration impact if logs are aggregated, shipped to centralized logging, or otherwise accessible to a party who should not see plaintext user passwords. This maps to the "key/secret exfiltration" impact class since raw passwords used for authentication/API-token issuance are exposed.

## Likelihood Explanation
The exploit requires no special privilege to *trigger* — the request body is read and logged after `c.Next()` returns regardless of whether `auth.AuthenticateGQL` ultimately rejects the request, since the body buffer is captured before the auth middleware executes. A normal authenticated user calling `updateUserPassword` as part of standard app workflow already causes the leak. The dependency on Debug-level logging being enabled is a real precondition (not proven to be default in this codebase, and not confirmed either way given available context), which is why likelihood is moderate rather than high — this is a genuine limitation of the finding, not a fabricated one.

## Recommendation
Make redaction recursive: walk nested objects/arrays (including anything under `variables`) rather than only checking `map[string]any` at the top level, or apply the blacklist check to GraphQL variable payloads specifically before logging. Alternatively, exclude the `/query` route body from full logging, or hash/mask input maps to any known-sensitive field name at any depth in the JSON tree.

## Proof of Concept
1. Enable Debug logging (`Log.Level = 'debug'`).
2. As an authenticated user, send:
```
POST /query
{
  "query": "mutation UpdateUserPassword($input: UpdatePasswordInput!) { updateUserPassword(input: $input) { ... } }",
  "variables": {"input": {"oldPassword": "CurrentPlainText123", "newPassword": "NewPlainText456"}}
}
```
3. Inspect node logs — the `loggerFunc` Debug log line's `"body"` field contains the full `variables` object with `oldPassword`/`newPassword` unredacted, since `readSanitizedJSON` only checks the top-level keys `query`/`variables`, neither of which is blacklisted.

Suggested Go unit test: call `readSanitizedJSON` directly with a JSON body shaped like the GraphQL `updateUserPassword` request above, and assert that the returned string still contains the literal plaintext password values — proving the redaction is bypassed.

func loggerFunc(lggr logger.Logger) gin.HandlerFunc {
	return func(c *gin.Context) {
		buf, err := io.ReadAll(c.Request.Body)
		if err != nil {
			lggr.Error("Web request log error: ", err.Error())
			// Implicitly relies on limits.RequestSizeLimiter
			// overriding of c.Request.Body to abort gin's Context
			// inside io.ReadAll.
			// Functions as we would like, but horrible from an architecture
			// and design pattern perspective.
			if !c.IsAborted() {
				c.AbortWithStatus(http.StatusBadRequest)
			}
			return
		}
		rdr := bytes.NewBuffer(buf)
		c.Request.Body = io.NopCloser(bytes.NewBuffer(buf))

		start := time.Now()
		c.Next()
		end := time.Now()

		lggr.Debugw(fmt.Sprintf("%s %s", c.Request.Method, c.Request.URL.Path),
			"method", c.Request.Method,
			"status", c.Writer.Status(),
			"path", c.Request.URL.Path,
			"ginPath", c.FullPath(),
			"query", redact(c.Request.URL.Query()),
			"body", readBody(rdr, lggr),
			"clientIP", c.ClientIP(),
			"errors", c.Errors.String(),
			"servedAt", end.Format("2006-01-02 15:04:05"),
			"latency", fmt.Sprintf("%v", end.Sub(start)),
		)
	}

func readSanitizedJSON(buf *bytes.Buffer) (string, error) {
	var dst map[string]any
	err := json.Unmarshal(buf.Bytes(), &dst)
	if err != nil {
		return "", err
	}

	cleaned := map[string]any{}
	for k, v := range dst {
		if isBlacklisted(k) {
			cleaned[k] = "*REDACTED*"
			continue
		}
		cleaned[k] = v
	}

	b, err := json.Marshal(cleaned)
	if err != nil {
		return "", err
	}
	return string(b), err
}

// NOTE: keys must be in lowercase for case insensitive match
var blacklist = map[string]struct{}{
	"password":             {},
	"newpassword":          {},
	"oldpassword":          {},
	"current_password":     {},
	"new_account_password": {},
}

func isBlacklisted(k string) bool {
	lk := strings.ToLower(k)
	if _, ok := blacklist[lk]; ok || strings.Contains(lk, "password") {
		return true
	}
	return false
}
