### Title
Accrued RAY market value can overflow before the index cap and permanently freeze a market - (File: common/src/rates/simulate.rs)

### Summary
A permissionless `update_indexes` call can permanently freeze an oversized, high-utilization market because accrual multiplies scaled supply and debt by their indexes before those products are bounded. The result is a `MathOverflow` panic before the borrow index reaches `MAX_BORROW_INDEX_RAY`; after that state is reached, repayments, withdrawals, and liquidation cannot complete because they must accrue first. Severity: Medium.

### Finding Description
`Controller::update_indexes(caller, assets)` is permissionless apart from caller authorization and forwards the selected markets to the pool's `update_indexes` entrypoint. [1](#0-0) [2](#0-1)  The pool splits elapsed time into bounded chunks and calls `accrue_step` for each chunk. [3](#0-2) [4](#0-3) 

`accrue_step` first unscales total borrowed and supplied shares by multiplying each by its index. [5](#0-4)  That conversion is a direct `Ray::mul` of the scaled amount and index, so a market value exceeding the `i128` range raises `MathOverflow`. [6](#0-5)  The borrow-index ceiling does not prevent this: `update_borrow_index` performs the multiplication first and clamps only the completed result. [7](#0-6) [8](#0-7) 

The same unchecked value domain is then used to calculate old debt, new debt, accrued interest, supplied value, and rewards. [9](#0-8) [10](#0-9)  The repository's stress test demonstrates that a valid billion-token, 18-decimal market at 98% utilization reaches this value ceiling while `borrow_index < MAX_BORROW_INDEX_RAY`, after which both `withdraw` and `repay` fail with `MathOverflow`. [11](#0-10) 

### Impact Explanation
Once the market crosses the representable `scaled_shares * index` boundary, every accrual attempt panics before `last_timestamp` advances, making subsequent accrual attempts fail for the same reason. Because the pool's supply, borrow, withdraw, repay, liquidation, and strategy paths accrue the market before mutating it, users cannot withdraw supplied funds or repay debt, and liquidators cannot close the position through the normal path. [12](#0-11) [11](#0-10) 

This permanently freezes supplier principal and accrued yield in the affected market and prevents the market from operating. The borrower also cannot reduce the overflowed debt because repayment itself performs accrual first. [13](#0-12) [3](#0-2) 

### Likelihood Explanation
Likelihood is conditional but nonzero: the market must be admitted with sufficient decimals, caps, collateral liquidity, and a rate model that can grow the index far enough while utilization remains high. An unprivileged participant can then create or preserve the required high-utilization book through ordinary `supply` and `borrow` calls and trigger the failure through permissionless `update_indexes`. [14](#0-13) [1](#0-0) 

The proof uses a valid 175% maximum borrow rate, below the protocol's 200% bound, and lifts caps only to the admitted domain maximum; it does not rely on malformed calldata, privileged mutation during the attack, or an oracle deviation. [15](#0-14) [16](#0-15) [17](#0-16) 

### Recommendation
Avoid materializing `scaled * index` market totals in `i128` when they can exceed the fixed-point value domain. Perform utilization and accrued-interest calculations in the widened `I256` domain or saturate the intermediate market values before deriving rates, while still emitting bounded indexes. At minimum, ensure `update_borrow_index` reaches `MAX_BORROW_INDEX_RAY` before debt valuation can panic and provide a recovery path that can advance accrual, socialize overflowed debt, or cap market totals without requiring the same overflowing multiplication. [18](#0-17) [7](#0-6) 

### Proof of Concept
The existing stress test constructs the complete path:

1. Create an 18-decimal asset priced at 1 USD with the valid XLM stress rate model and a 7-decimal collateral asset priced at 1 USD. [19](#0-18) 
2. Call `supply` to deposit `1_000_000_000 * 10^18` units of the debt asset and `30_000_000_000 * 10^7` units of collateral. [17](#0-16) 
3. Call `borrow` for 98% of the debt asset's supplied balance. [20](#0-19) 
4. Advance ledger time and call permissionless `update_indexes` for that market until it returns `MathOverflow`. [21](#0-20) 
5. Observe that `borrow_index` remains below `MAX_BORROW_INDEX_RAY`, meaning the configured cap did not safely absorb the growth. [22](#0-21) 
6. Attempt `withdraw` and `repay`; both fail with the same `MathOverflow`, leaving the market frozen. [23](#0-22)

```rust
pub fn accrue_step(

    params: &MarketParams,
    borrowed: Ray,

    borrow_index: Ray,
    supply_index: Ray,
    delta_ms: u64,

    let borrowed_original = scaled_to_original(env, borrowed, borrow_index);
    let supplied_original = scaled_to_original(env, supplied, supply_index);
    let util = utilization(env, borrowed_original, supplied_original);
    let borrow_rate = calculate_borrow_rate(env, util, params);
    let interest_factor = compound_interest(env, borrow_rate, delta_ms);

    let new_borrow_index = update_borrow_index(env, borrow_index, interest_factor);

    let (supplier_rewards, protocol_fee) =
        calculate_supplier_rewards(env, params, borrowed, new_borrow_index, borrow_index);

    let new_supply_index = update_supply_index(env, supplied, supply_index, supplier_rewards);
    let supplier_shortfall = supply_index_reward_shortfall(
        env,
        supplied,
        supply_index,
        new_supply_index,
        supplier_rewards,
    );

    let protocol_reward = protocol_fee.checked_add(env, supplier_shortfall);
    // Shares are valued at the new supply index, which the caller stores for
    // this step.
    let revenue_shares = if protocol_reward == Ray::ZERO {
        Ray::ZERO
    } else {
        protocol_fee_shares(env, protocol_reward, new_supply_index, supplied)
    };
```

```rust
/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
```
