## Finding

### Title
Stale `TombStone` survives ungated ownership transfer, letting a past owner hijack an object that a later legitimate owner burns — [File: aptos-move/framework/aptos-framework/sources/object.move]

### Summary
`object::burn` marks an object as "soft burned" by attaching a `TombStone { original_owner }` resource while leaving normal ownership and transferability untouched. The only transfer path that clears this `TombStone` is `transfer_with_ref` (used with a `LinearTransferRef`). The default, ungated transfer path — `object::transfer` / `object::transfer_call` / `object::transfer_raw` — does **not** clear it. This lets a prior owner who once called `burn()` retain a latent reclaim right that resurfaces and hijacks the object from a completely unrelated, later legitimate owner once that later owner sends the object to the real `BURN_ADDRESS`.

### Finding Description
`burn()` requires the caller to be the current owner and simply attaches a `TombStone` without disabling ungated transfers: [1](#0-0) 

Ownership can still move freely afterward through the standard entrypoints, whose core transfer logic is `transfer_raw_inner`, which only emits a `Transfer` event and updates `owner` — it never checks or clears `TombStone`: [2](#0-1) 

By contrast, the reference-based transfer path explicitly clears a stale `TombStone` before honoring the transfer, showing the framework is aware `TombStone` must be invalidated on ownership change — but only implements that invalidation for one of the two transfer paths: [3](#0-2) 

Finally, `unburn()` grants reclaim rights based purely on the stored `TombStone.original_owner` matching the caller once the object address currently sits at `BURN_ADDRESS`, with no check on how many ownership transfers happened in between: [4](#0-3) 

**Exploit chain:**
1. Owner `A` owns object `O` and calls `object::burn(A, O)` → `TombStone{original_owner: A}` is attached; `O` stays owned by `A`, ungated transfer remains enabled.
2. `A` legitimately transfers `O` to `B` via `object::transfer` (ungated). `transfer_raw_inner` updates `owner = B` but does **not** touch the stale `TombStone`.
3. `B`, the new rightful owner, later decides to genuinely retire `O` by sending it to `BURN_ADDRESS`. `B` cannot call `object::burn` (it would abort with `EOBJECT_ALREADY_BURNT` due to the leftover `TombStone`), so `B` uses the standard/documented pattern of `object::transfer(B, O, BURN_ADDRESS)`, which succeeds since `transfer_raw` doesn't inspect `TombStone`.
4. `object_core.owner == BURN_ADDRESS` while `TombStone.original_owner` is still the stale value `A`.
5. `A` calls `object::unburn(A, O)`. The `owner == BURN_ADDRESS` branch fires, `original_owner_addr (A) == signer::address_of(A)` passes, and `transfer_raw_inner(object_addr, A)` restores ownership to `A` — even though `A` had no custody claim over `O` since step 2, and it was `B` who performed the real burn.

### Impact Explanation
This breaks the custody invariant that "object creation, transfer, burn, extensibility, and ownership refs must preserve the intended controller." Any object-held asset (an NFT/token object, or any object wrapping fungible-asset stores or other value) can be hijacked back by a former owner after being legitimately transferred away and then genuinely burned by its rightful current owner. This is a theft/owner-reassignment vulnerability with no privileged action required — it moves object-held value to the wrong holder and destroys the legitimate burner's expectation of permanent, non-recoverable disposal.

### Likelihood Explanation
The root cause requires only unprivileged, ordinary user actions available to anyone: call `burn()` once on an object you own, transfer it away normally (the common/default transfer path, since `burn()` does not disable ungated transfers), and wait for any subsequent owner to send the object to `BURN_ADDRESS` — a normal, documented way to hard-burn an object. No special permissions, race conditions, or governance access are needed, making this readily triggerable by any malicious former owner of a transferable object.

### Recommendation
Clear (or otherwise invalidate) the `TombStone` resource in `transfer_raw_inner` / `transfer_raw` whenever ownership changes, mirroring the behavior already implemented in `transfer_with_ref`. Alternatively, `unburn()` should validate that no ownership-changing transfer has occurred since the `TombStone` was created (e.g., by tracking the owner at burn time and requiring it still equals the owner just prior to reaching `BURN_ADDRESS`), rather than trusting a static `original_owner` field that can become stale across multiple ownership transitions.

### Proof of Concept
```move
// Owner A burns (soft) the object while still owning it.
object::burn(&signer_a, object_o);              // TombStone{original_owner: A} attached

// A legitimately sells/transfers O to B via the normal ungated path.
object::transfer(&signer_a, object_o, addr_b);  // owner = B, TombStone still present (stale)

// B, wanting to genuinely retire O, cannot call object::burn (would abort EOBJECT_ALREADY_BURNT),
// so B uses the standard hard-burn pattern:
object::transfer(&signer_b, object_o, BURN_ADDRESS); // owner = BURN_ADDRESS

// A reclaims the object that B just burned, despite having no custody since step 2:
object::unburn(&signer_a, object_o);            // succeeds, owner set back to A
```

```text
    /// Transfer to the destination address using a LinearTransferRef.
    public fun transfer_with_ref(self: LinearTransferRef, to: address) {
        assert!(!exists<Untransferable>(self.self), error::permission_denied(EOBJECT_NOT_TRANSFERRABLE));

        // Undo soft burn if present as we don't want the original owner to be able to reclaim by calling unburn later.
        if (exists<TombStone>(self.self)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(self.self);
        };

        let object = borrow_global_mut<ObjectCore>(self.self);
        assert!(
            object.owner == self.owner,
            error::permission_denied(ENOT_OBJECT_OWNER),
        );
        event::emit(
            Transfer {
                object: self.self,
                from: object.owner,
                to,
            },
        );
        object.owner = to;
    }
```

```text
    /// Allow origin owners to reclaim any objects they previous burnt.
    public entry fun unburn<T: key>(
        original_owner: &signer,
        object: Object<T>,
    ) {
        let object_addr = object.inner;
        assert!(exists<TombStone>(object_addr), error::invalid_argument(EOBJECT_NOT_BURNT));

        // The new owner of the object can always unburn it, but if it's the burn address, we go to the old functionality
        let object_core = borrow_global<ObjectCore>(object_addr);
        if (object_core.owner == signer::address_of(original_owner)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object_addr);
        } else if (object_core.owner == BURN_ADDRESS) {
            // The old functionality
            let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
            assert!(
                original_owner_addr == signer::address_of(original_owner),
                error::permission_denied(ENOT_OBJECT_OWNER)
            );
            transfer_raw_inner(object_addr, original_owner_addr);
        } else {
            abort error::permission_denied(ENOT_OBJECT_OWNER);
        };
    }
```
