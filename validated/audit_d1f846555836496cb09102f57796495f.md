### Title
Legacy WebAPI Gateway Handler Lacks Allowlist and Rate-Limiting on User Trigger Requests - (File: `core/services/gateway/handlers/capabilities/handler.go`)

### Summary
The legacy WebAPI capability handler's `HandleLegacyUserMessage` function, which is invoked for every unprivileged user request that reaches the gateway with a `web_api_trigger` method, contains an explicit unimplemented security control: allowlist and rate-limiting are marked as TODO but never applied before the request is dispatched to every node in the DON. [1](#0-0)  This mirrors the NamelessMC forum-reply issue, where an authenticated but otherwise unprivileged actor could submit requests in an unbounded, unthrottled loop because no spam-prevention mechanism was implemented on the message-submission path.

### Finding Description
`HandleLegacyUserMessage` performs payload decoding and a staleness check (via `MaxAllowedMessageAgeSec`) but has no per-user/per-sender allowlist or rate-limiting check before broadcasting the trigger request to all DON members: [2](#0-1) 

The only gating logic present is a staleness check on `payload.Timestamp` and a method-name check; the code comment `// TODO: apply allowlist and rate-limiting here` at line 384 explicitly documents that the intended check was never implemented. [1](#0-0)  Once past these checks, the handler saves a callback keyed by `MessageID` and fans the message out to `SendToNode` for every configured DON member: [3](#0-2) 

Notably, this legacy handler is architecturally distinct from the newer v2 gateway path (`core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go`), which does enforce authentication (JWT), authorization (`authorizeRequest`), and per-workflow-owner rate limiting via `checkRateLimit`/`userRateLimiter` before dispatching to nodes: [4](#0-3)  That confirms the project's own security model expects such checks for user-submitted trigger messages, and that the legacy path is the outlier lacking them.

The `Handler` interface documents `HandleLegacyUserMessage` as the entry point invoked once per incoming user request from a separate goroutine (i.e., directly reachable from an inbound gateway request), which underscores that this is a client-facing, per-request code path rather than an internal or node-to-node interaction: [5](#0-4) 

I was unable to fully trace, within the available index, the exact HTTP route/middleware in `core/services/gateway/gateway.go` that calls into `HandleLegacyUserMessage` to confirm whether any allowlist/rate-limiting is applied at an earlier network layer (e.g., mTLS-based node/DON allowlisting) before this handler executes; the file appeared in search results but its content could not be retrieved in this session. This is a gap in verification — if an outer layer already gates callers, the impact would be reduced to intra-DON abuse rather than fully unauthenticated abuse. Given the index limitation, I recommend confirming this in a full Devin session with complete file access.

### Impact Explanation
If reachable without additional gating, an actor who can reach the gateway's legacy WebAPI endpoint can submit `web_api_trigger` messages with no per-sender/per-workflow rate limit, causing:
- Uncontrolled fan-out of `SendToNode` calls to every DON member per submitted message, consuming node processing and network resources.
- Unbounded growth pressure on `savedCallbacks` (bounded only by periodic pruning, not by intake throttling), which can be used to force frequent eviction/pruning cycles and increase memory/CPU churn.
This matches the "uncontrolled surge of posts... disrupt normal operations" impact class from the CVE.

### Likelihood Explanation
Likelihood depends on whether the legacy WebAPI trigger path is still exposed in production DON configurations and whether any outer-layer (transport/mTLS/node allowlist) restricts who can submit `web_api_trigger` messages to this handler. Given the explicit TODO comment left in the code, the missing check appears to be a known, unresolved gap rather than a defense compensated elsewhere in this file. Confirmation of exposure requires reviewing `core/services/gateway/gateway.go` request routing, which could not be completed in this session.

### Recommendation
Implement the allowlist and rate-limiting check called out in the TODO at `core/services/gateway/handlers/capabilities/handler.go:384` before saving the callback and dispatching to DON members — mirroring the pattern already used in the v2 HTTP trigger handler (`authorizeRequest` + `checkRateLimit` in `core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go`). At minimum, apply a per-sender/per-workflow token-bucket limiter and require sender-level allowlisting consistent with the rest of the gateway's handlers (e.g., `vault`, `confidentialrelay`, and v2 `http_handler.go`, which all instantiate per-node/per-workflow rate limiters at construction time).

### Proof of Concept
Not independently reproducible from static analysis alone; the concrete PoC would be: repeatedly send `web_api_trigger` JSON payloads with valid, non-stale timestamps to the gateway's legacy user-message endpoint from a single sender and observe that no request is rejected for rate-limit/allowlist reasons (unlike the v2 endpoint, which returns `jsonrpc.ErrLimitExceeded` once `userRateLimiter.AllowErr` denies the request, as exercised in `TestHttpTriggerHandler_HandleUserTriggerRequest_RateLimiting`: [6](#0-5) ). Full confirmation requires access to the routing code in `core/services/gateway/gateway.go`, which was not retrievable in this session.

```go
func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JSONRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) { //nolint:gosec // G115: comparing unix timestamps, both fit within uint
		h.lggr.Errorw("stale message")
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),
			ErrorCode: api.HandlerError,
		})
	}
	// TODO: apply allowlist and rate-limiting here
	if msg.Body.Method != MethodWebAPITrigger {
		h.lggr.Errorw("unsupported method", "method", body.Method)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.UnsupportedMethodError),
				"invalid method "+msg.Body.Method,
				nil,
			),
			ErrorCode: api.UnsupportedMethodError,
		})
	}
	req, err := common.ValidatedRequestFromMessage(msg)
	if err != nil {
		h.lggr.Errorw(ErrTransformingMessageToRequest)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrTransformingMessageToRequest,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	h.mu.Lock()
	h.savedCallbacks[msg.Body.MessageID] = &savedCallback{id: msg.Body.MessageID, createdAt: time.Now(), Callback: callback}
	don := h.don
	h.mu.Unlock()

	// Send original request to all nodes
	for _, member := range h.donConfig.Members {
		err = errors.Join(err, don.SendToNode(ctx, member.Address, req))
	}
	return err
```

```go
func (h *httpTriggerHandler) checkRateLimit(ctx context.Context, workflowID, requestID string, callback handlers.Callback) error {
	workflowRef, found := h.workflowMetadataHandler.GetWorkflowReference(workflowID)
	if !found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "workflow reference not found", callback)
		return errors.New("workflow reference not found")
	}

	orgID := h.resolveOrgID(ctx, workflowRef.workflowOwner)
	ctx = contexts.WithCRE(ctx, contexts.CRE{Owner: workflowRef.workflowOwner, Org: orgID, Workflow: workflowID})
	if err := h.userRateLimiter.AllowErr(ctx); err != nil {
		lggr := logger.With(h.lggr, platform.KeyWorkflowID, workflowID, platform.KeyWorkflowOwner, workflowRef.workflowOwner, "requestID", requestID, "err", err)
		if errLimited, ok := errors.AsType[limits.ErrorRateLimited](err); ok {
			switch errLimited.Scope {
			case settings.ScopeWorkflow:
				lggr.Errorf("failed to start execution: per workflow rate limit exceeded")
				h.metrics.IncrementWorkflowThrottled(ctx, h.lggr)
			default:
				lggr.Errorf("failed to start execution: unexpected rate limit for scope %s", errLimited.Scope)
			}
			h.handleUserError(ctx, requestID, jsonrpc.ErrLimitExceeded, "rate limit exceeded", callback)
			return err
		}
		return fmt.Errorf("failed to check rate limit: %w", err)
	}
	return nil
}
```
