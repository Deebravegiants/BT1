### Title
Instantaneous Uniswap V4 spot-price sizing without depth or impact term lets a flash-loan-manipulated pool drain solver-funded intent fills - (File: sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts)

### Summary
Simplex's `FXFiller` prices curveless (venue-priced) trading pairs directly from a Uniswap V4 pool's current tick (`sqrtPriceX96`), the same class of bug that let the Harvest Finance attacker use a flash loan to distort an instantaneous price used to value deposits/withdrawals. Here the instantaneous, unweighted spot price is used to size and price an unprivileged user's cross-chain/same-chain intent order, and the only defense is a static-band deviation check with no TWAP and no execution-size/impact adjustment.

### Finding Description
`UniswapV4FundingPlanner.getExoticTokenPrice` / `computeDirectPoolPriceUsd` reads `sdkPool.token0Price`/`token1Price`, derived straight from the pool's current `sqrtPriceX96`, and returns it as the USD price of the exotic token: [1](#0-0) . This is invoked per-order from `FXFiller.resolveLegRates`/`referenceRate`, which uses it to price and size any curveless (venue-priced) pair whenever a user submits an intent order touching that pair: [2](#0-1) [3](#0-2) .

The project's own documentation confirms there is no size/impact term and the price is the raw pool mid: "`computeDirectPoolPriceUsd` returns the raw pool mid derived from `sqrtPriceX96`... there is no size or impact term ... `checkPriceGuard` is the only defense on this path, and it checks deviation from a static reference, not execution cost." [4](#0-3) 

The only mitigation is `checkPriceGuard`, a static ±`maxDeviationBps` band check against a configured `referencePrice`: [5](#0-4) . This guard is optional (unguarded chains pass every quote) and, even when configured, only bounds absolute deviation from a stale, manually-set reference — it does not detect or resist a transient flash-loan-driven price move that stays within the configured band (which the pricing docs recommend setting as wide as 200bps/2%): [6](#0-5) .

An attacker can, in a single transaction (or an atomic bundle), flash-loan-swap the configured Uniswap V4 pool to move its instantaneous tick within the guard band (or on an unguarded chain, arbitrarily), then immediately submit/trigger an intent order priced against that pool via `quotePhantomFill`/`resolveLegRates`. The solver, funded from its own Uniswap V4 LP position or vault treasury (`planWithdrawalForToken`), fills the order at the manipulated rate, releasing more of the exotic/stable asset than the true market price justifies. This is structurally identical to Harvest Finance's exploit, where a flash loan distorted an instantaneous share-price/exchange-rate calculation (`get_virtual_price`-style) consumed by a vault's deposit/withdraw accounting, letting the attacker repeatedly extract value from the mispriced conversion.

### Impact Explanation
A successful attack directly drains the solver's on-chain inventory (Uniswap V4 LP position funds and/or vault treasury assets) that back intent fills, by having orders filled at a manipulated exchange rate rather than the true market rate. This is a concrete theft-of-funds vector reachable purely by an unprivileged user submitting/triggering an order against a pool they can manipulate with a flash loan — the same bug class and blast radius (protocol-controlled liquidity drained via a distorted price feeding a settlement/valuation calculation) as the Harvest Finance incident.

### Likelihood Explanation
Likelihood is Medium: it requires (1) a configured `[vault.uniswapV4]` venue-priced pair with no independent curve, (2) a pool with insufficient depth/liquidity relative to available flash-loan capital, and (3) either no price guard configured or a guard band wide enough to admit a profitable manipulation. These are all solver/operator configuration choices, not protocol-enforced invariants, and the code explicitly documents the missing size/impact term as a known gap, making misconfiguration plausible in production deployments that use pool-based pricing for lower-liquidity "exotic" tokens (the intended use case per the docs).

### Recommendation
Replace the raw instantaneous `sqrtPriceX96`-derived spot price with a TWAP (time-weighted average, e.g. Uniswap V4 oracle observations) or a multi-block/multi-sample price, and add a real size/impact-aware pricing model (as `computeDirectPoolPriceUsd`'s own comments acknowledge is missing) instead of relying solely on a static deviation-band guard. Make the price guard mandatory (not optional) for venue-priced pairs, and additionally bound the maximum order/notional size fillable per block per pool to limit the profit available from a single-block manipulation, mirroring Harvest Finance's post-mortem remediation of tightening arbitrage/slippage tolerances and removing reliance on manipulable instantaneous pricing.

### Proof of Concept
1. Configure a Simplex filler with a curveless, venue-priced pair (e.g. `USDC/CNGN`) funded from a `[vault.uniswapV4]` position on a low-liquidity pool, per `docs/content/developers/evm/simplex/pricing.mdx`, with either no `referencePrice`/`maxDeviationBps` guard, or one wide enough (e.g. `maxDeviationBps = 200`) to admit typical flash-loan-driven moves.
2. Attacker takes a flash loan and swaps a large amount through the configured Uniswap V4 pool in the same transaction/bundle, shifting `sqrtPriceX96` so `token0Price`/`token1Price` moves favorably within (or beyond, if unguarded) the allowed band.
3. In the same atomic sequence, the attacker submits (or has already pending) an IntentGateway order on the affected pair; the FXFiller's `resolveLegRates`/`referenceRate` reads the manipulated pool price via `getExoticTokenPrice`/`computeDirectPoolPriceUsd` and prices/sizes the fill using that distorted rate, since no TWAP or impact model corrects for the single-block manipulation: [7](#0-6) .
4. The solver, funded by `planWithdrawalForToken` pulling from its own Uniswap V4 position: [8](#0-7) , fills the order at the manipulated rate, delivering more value than the true market price.
5. Attacker reverses the flash-loan swap and repays the loan within the same transaction, keeping the arbitrage profit extracted from the solver's inventory — mirroring Harvest Finance's repeated flash-loan cycles against a manipulable instantaneous price used in fund-releasing calculations.

	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}

	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {
			this.logger.warn(
				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
	}

	private async referenceRate(
		leg: ResolvedLeg,
		venueUsdPrice: (chain: string, token1Address: string) => Promise<Decimal | null>,
	): Promise<Decimal | null> {
		const policy = leg.pair.bidPricePolicy ?? leg.pair.askPricePolicy
		if (policy) {
			const rate = policy.getPrice(new Decimal(0))
			return rate.gt(0) ? rate : null
		}
		// Venue-priced pair: token0 is USD-stable (constructor invariant), so the
		// venue's USD-per-token1 quote inverts straight into token1-per-token0.
		const venueUsd = await venueUsdPrice(leg.token1Chain, leg.token1Address)
		if (!venueUsd) return null
		const venueRate = new Decimal(1).div(venueUsd)
		// Same guard as trade pricing: this rate sizes the order's USD notional
		// for confirmation depth, and a manipulated pool understating the value
		// would shrink the reorg protection — the exact attack the guard exists
		// to stop. Refusing to size skips the order, consistent with pricing.
		if (!this.checkPriceGuard(undefined, leg.token1Chain, venueRate)) return null
		return venueRate
	}

## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.

```toml lineNumbers
[vault.uniswapV4]
# referencePrice is the expected cNGN per USD;
# reject if the quote is more than 2% off.
# The two go together — one without the other is rejected.
[[vault.uniswapV4.positions]]
chain           = "EVM-8453"
tokenId         = "2087350"
referencePrice  = "1575"
maxDeviationBps = 200
```
