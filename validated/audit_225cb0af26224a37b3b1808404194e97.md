## Finding: Permanent Graduation Brick via Degenerate LP-Mint Amounts (`sqrt(tokensForLP × ltFromPair) < MINIMUM_LIQUIDITY`)

### Title
Dust-sized cached graduation amounts cause an unrecoverable `finalizeGraduation` revert, permanently freezing curve funds - (File: `packages/contracts/src/Bonding.sol`)

### Summary
The CVE describes PostGIS's `ST_AsX3D` mishandling a degenerate/empty geometry input and crashing rather than handling it gracefully. The structural analog here is `Bonding._seedDirectMint` feeding a degenerate (near-zero) `(tokensForLP, ltFromPair)` pair into the HyperSwap V2 pair's first-liquidity `mint()`, whose `sqrt(amount0*amount1) - MINIMUM_LIQUIDITY` computation underflows and reverts whenever the geometric mean of the two amounts is below `1000`. Because `finalizeGraduation` is the only path out of `Lifecycle.Graduating` and it replays the *cached* phase-1 amounts verbatim with no re-pricing or retry mechanism, hitting this degenerate case permanently bricks the token.

### Finding Description
`Bonding._enterGraduating` (phase 1) computes and caches `tokensForLP` / `ltFromPair` in `pendingGraduation[token]` [1](#0-0) , derived from `_prepareGraduationLiquidity`:

```
ltFromPair = assetReserve - virtualLtReserve
tokensForLP = (ltFromPair * tokenReserve) / assetReserve
``` [2](#0-1) 

`finalizeGraduation` (phase 2, permissionless) reuses these cached values exactly and, on a fresh/empty HyperSwap pair (the ~99% "Regime 1" case per the code's own comment), calls `_seedDirectMint`, which transfers both sides to the pair and calls the pair's `mint()`: [3](#0-2) 

A first-liquidity UniswapV2-style `mint()` (mirrored exactly by the test mock) computes:
```solidity
liquidity = _sqrt(amount0 * amount1) - MINIMUM_LIQUIDITY;   // MINIMUM_LIQUIDITY = 1000
``` [4](#0-3) 

If `sqrt(tokensForLP × ltFromPair) < 1000`, this subtraction underflows and reverts (Solidity 0.8 Panic) — an exact analog to PostGIS crashing on an "empty" geometry it never validated.

`ltFromPair` can be driven to a dust value by the same rate-pump-only graduation path the protocol already documents and tests (`_ratePumpForStagedGraduation`, `triggerGraduation`): because the USD trigger is `realLtRaised × exchangeRate() ≥ $9K` [5](#0-4) , an LT whose `exchangeRate()` is pumped high enough (a leveraged, externally-priced BounceTech LT is explicitly designed to move sharply) lets a **tiny** `realLtRaised` (down to just above zero, e.g. low-wei amounts) satisfy the USD threshold. `tokensForLP` scales with `ltFromPair`, so both cached amounts can simultaneously be small enough that their geometric mean falls under `MINIMUM_LIQUIDITY`.

Once phase 1 has cached these dust values, there is no recomputation: `finalizeGraduation` is documented to "read the cached value verbatim" specifically so "a recompute would return byte-identical values" [6](#0-5) . Every call to `finalizeGraduation` — by the keeper or anyone else — replays the same degenerate amounts and reverts identically, forever.

The protocol's own "brick resistance" hardening (`_pairRebalance`'s dust fallback, `_swapBudget`, `addLiquidity(min=1,min=1)`) is exclusively designed to defend Regime 3 (a hostile pre-seed against a non-empty pair) [7](#0-6) ; Regime 1's direct mint (the normal, empty-pool path) has no analogous guard against a `MINIMUM_LIQUIDITY` underflow.

### Impact Explanation
Once this state is reached, the token is stuck permanently in `Lifecycle.Graduating`:
- Trading is frozen (curve trading is disabled once `Graduating`), and it can never reach `Graduated` since `finalizeGraduation` always reverts.
- All curve-raised LT (`ltFromPair`, routed to `Bonding` via `Router.graduate` in phase 1) and the 250M `LP_RESERVE` tokens held by `Bonding` are permanently locked with no rescue path.
- `LPLock.recordLock`, the required one-shot bookend, is never reached, so the token also can never appear on HyperSwap.

This is a permanent freeze of creator/trader/protocol-adjacent funds triggerable by ordinary market movement or a deliberately timed dust-sized `triggerGraduation`/`buy` call from any unprivileged address — satisfying the "concrete... permanent freezing of trader, creator or LP funds" bar.

### Likelihood Explanation
`Bonding.triggerGraduation` is explicitly permissionless [8](#0-7)  and designed precisely to catch the "LT appreciation pushed it past threshold with no buy" case. Any address (or organic HYPE-linked leverage move) that pumps `exchangeRate()` while `realLtRaised` is still small enough that `sqrt(tokensForLP × ltFromPair) < 1000` reaches this bug with a single permissionless call plus the following permissionless `finalizeGraduation`. No privileged role, upgrade, or off-chain component is required.

### Recommendation
- In `_prepareGraduationLiquidity` / `_enterGraduating`, enforce a floor ensuring `tokensForLP` and `ltFromPair` cannot both be small enough to make `sqrt(tokensForLP * ltFromPair) < MINIMUM_LIQUIDITY` (e.g., defer/refuse graduation, or bump the seed amounts, when this condition would occur), mirroring the defensive floor already applied to hostile pre-seeds.
- Alternatively, have `_seedDirectMint` detect an impending underflow before calling `mint()` and fall back to a safe alternate path (e.g., treat as Regime-3-style handling, or explicitly top up one side from `Bonding`'s existing float) rather than letting the panic propagate.
- Add a regression test seeding `_launchToken` with a large synthetic `exchangeRate()` pump immediately after the minimum `$20` seed buy, then calling `triggerGraduation` + `finalizeGraduation`, asserting it does not revert.

### Proof of Concept
1. Launch a token with the mandatory minimum `$20` seed buy (`Zap.createToken`), which mints only a small amount of real LT into the curve.
2. From any unprivileged address, pump the LT's `exchangeRate()` (via the mock/BounceTech LT's normal rate mechanics) high enough that `realLtRaised × exchangeRate() ≥ graduationThresholdUsd` while `realLtRaised` (in LT wei) remains a few hundred wei or less.
3. Call `Bonding.triggerGraduation(token)` — succeeds, caches `pendingGraduation[token] = (tokensForLP, ltFromPair, ...)` with both values dust-sized such that `sqrt(tokensForLP * ltFromPair) < 1000`.
4. Call `Bonding.finalizeGraduation(token)` — reverts with an arithmetic underflow inside the HyperSwap pair's `mint()` (mirrored in `MockHyperswapRouter.mint`, `packages/contracts/test/mocks/MockHyperswapRouter.sol:56-59`).
5. Every subsequent call to `finalizeGraduation(token)` reverts identically (cached values are replayed verbatim), permanently freezing the token in `Lifecycle.Graduating` along with all curve-raised LT and the 250M reserved tokens held in `Bonding`.

        address token_

        BondingStorage storage $ = _s();

        if (info.creator == address(0)) return false;

    /// @dev Transfer the full `(tokensForLP, ltFromPair)` to the pair and
    ///      `mint` the LP to `LPLock`, opening at the exact cached
    ///      curve-close ratio. Used by the empty-pair regime and as the
    ///      dust-pre-seed fallback in `_seedRebalancing` — against dust
    ///      reserves the V2 `min()` formula's donation to any pre-existing
    ///      LP is negligible (see `_seedUniswapV2Direct` natspec). Any TOKEN
    ///      remainder (a skimmed pure-donation pre-seed) is burned; the LT
    ///      remainder is left for `finalizeGraduation`'s `_sweepLTToOwner`
    ///      post-bookend.
    function _seedDirectMint(
        address tokenAddress,
        address lt,
        address pair,
        uint256 tokensForLP,
        uint256 ltFromPair
    ) internal returns (uint256 liquidity) {
        IERC20(tokenAddress).safeTransfer(pair, tokensForLP);
        IERC20(lt).safeTransfer(pair, ltFromPair);
        liquidity = IUniswapV2Pair(pair).mint(_s().lpLock);
        uint256 leftoverToken = IERC20(tokenAddress).balanceOf(address(this));
        if (leftoverToken > 0) {
            Token(tokenAddress).burn(address(this), leftoverToken);
        }
    }
