### Title
RAY-value overflow during interest accrual permanently freezes a market - (File: common/src/rates/simulate.rs)

### Summary
A sufficiently large market can accrue until `borrowed * borrow_index / RAY` exceeds `i128::MAX`; the next accrual panics before committing state, and every subsequent market operation repeats the same overflowing accrual, permanently freezing supplier and borrower funds. [1](#0-0) 

### Finding Description
`accrue_step` unconditionally computes `borrowed_original` by calling `scaled_to_original(borrowed, borrow_index)`, which evaluates `Ray::mul` as `borrowed * borrow_index / RAY`. [2](#0-1) [3](#0-2) [4](#0-3) 

Although the multiplication itself can widen to `I256`, the quotient is converted back to `i128`; when the resulting RAY-scaled market value exceeds `i128::MAX`, `mul_div_half_up` raises `MathOverflow`. [5](#0-4) 

The permissionless path is `Controller::update_indexes(caller, hub_assets)` with `hub_assets = [HubAssetKey { hub_id, asset }]`, which reaches `LiquidityPool::update_indexes`, `ops::market::accrue`, `interest::global_sync`, and finally `accrue_step`. [6](#0-5) [7](#0-6) [8](#0-7) 

After the first crossing, the failed call does not persist a new index or timestamp, so the same overflow is recomputed on every later attempt; `synced_market` runs `global_sync` before ordinary mutations, meaning `withdraw`, `repay`, `borrow`, liquidation, bad-debt cleanup, and recapitalization paths touching the market fail at accrual before their recovery logic can run. [9](#0-8) [10](#0-9) 

The index cap does not prevent the condition because the overflow is on the total RAY-scaled value rather than on the index itself; a scaled debt of `D` becomes unrepresentable once `borrow_index > i128::MAX * RAY / D`, which can occur well below `MAX_BORROW_INDEX_RAY`. [11](#0-10) [12](#0-11) 

### Impact Explanation
Once the state crosses the representable RAY-value boundary, no unprivileged transaction can move the market forward: suppliers cannot withdraw, borrowers cannot repay, liquidators cannot liquidate, bad debt cannot be cleaned, and recapitalization cannot proceed because each path accrues first. [13](#0-12) 

This permanently freezes all cash claims and unclaimed yield in the affected market unless an owner upgrade changes the arithmetic, which is outside the unprivileged threat model. [8](#0-7) 

### Likelihood Explanation
The attacker only needs ordinary `supply`, `borrow`, and `update_indexes` calls, but the market’s configured caps and collateralization must admit a very large book; smaller caps or balances cannot reach the threshold. [12](#0-11) 

The repository’s own regression test demonstrates the condition with a one-billion-token, 18-decimal market and a 98% borrow, after which `update_indexes`, `withdraw`, and `repay` all fail with `MathOverflow`. [14](#0-13) 

### Recommendation
Enforce a protocol invariant that keeps every scaled supply/debt total below `floor(i128::MAX * RAY / MAX_INDEX)` for the corresponding index domain, or reduce the index ceilings so configured token caps cannot cross the representable-value boundary. [15](#0-14) 

Alternatively, represent accrued market totals with `I256` through accrual and define explicit saturation/write-down behavior before converting values back to `i128`; a panic must not be the mechanism that discovers the boundary because it leaves no unprivileged recovery path. [16](#0-15)

```rust
    alice,
    alice_account_id,
    vec![(HubAssetKey { hub_id, asset: big18 }, principal * 98 / 100)],
    None,
);

// After enough accrual that scaled_debt * borrow_index / RAY > i128::MAX:
controller.update_indexes(anyone, vec![HubAssetKey { hub_id, asset: big18 }]);
// => MathOverflow; no index or timestamp is committed.

// All later market paths accrue first and repeat the same panic.
controller.withdraw(bob, bob_account_id, vec![(big18_key, 1)], None);
controller.repay(anyone, alice_account_id, vec![(big18_key, 1)]);
```

```rust
pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    // The zero check runs first so debug and release builds agree on a zero
    // divisor: both surface `DivisionByZero` rather than tripping the assert.
    require_nonzero_divisor(env, d);
    debug_assert!(
        x >= 0 && y >= 0 && d > 0,
        "mul_div_half_up: non-negative x, y and positive d"
    );
    try_mul_div_half_up(env, x, y, d)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
}

/// Computes `x * y / d` rounded half up. Returns `None` if `x < 0`, `y < 0`, `d <= 0`, or the
/// result does not fit in `i128`.
pub fn try_mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> Option<i128> {
    if x < 0 || y < 0 || d <= 0 {
        return None;
    }
    let half = d / 2;

    // Fast path: the biased product fits `i128`, so the whole computation is
    // native. `x * y + half` is non-negative here, so `/` is the floor the
    // widened path would produce.
    if let Some(biased) = x
        .checked_mul(y)
        .and_then(|product| product.checked_add(half))
    {
        return Some(biased / d);
    }

    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    x256.mul(&y256)
        .add(&I256::from_i128(env, half))
        .div(&d256)
        .to_i128()
}
```

```rust
/// Computes `floor(x * y / d)`, saturating to `i128::MAX` (or `i128::MIN` for a negative
/// quotient) instead of panicking if the result does not fit in `i128`. Panics with
/// `GenericError::DivisionByZero` if `d == 0`.
pub fn mul_div_floor_saturating(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    require_nonzero_divisor(env, d);
    if let Some(quotient) = x
        .checked_mul(y)
        .and_then(|product| div_floor_i128(product, d))
    {
        return quotient;
    }
    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    div_floor_i256(
        env,
        &x256.mul(&y256),
        &d256,
        quotient_is_nonnegative(x, y, d),
    )
    .to_i128()
    .unwrap_or(if quotient_is_negative(x, y, d) {
        i128::MIN
    } else {
        i128::MAX
    })
}
```

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

```rust
/// Loads a market cache and accrues interest through the current ledger time.
pub(crate) fn synced_market(env: &Env, hub_asset: &HubAssetKey) -> Cache {
    let mut cache = Cache::load(env, hub_asset);
    interest::global_sync(env, &mut cache);
    cache
}

/// Renews instance TTL, then loads and accrues the market.
pub(crate) fn renewed_market(env: &Env, hub_asset: &HubAssetKey) -> Cache {
    renew_instance(env);
    synced_market(env, hub_asset)
}

/// Validates `action.amount ≥ 0`, syncs the market, and returns (cache, scaled position).
pub(crate) fn load_leg(env: &Env, action: &PoolAction) -> (Cache, Ray) {
    require_nonneg_amount(env, action.amount);
    let cache = synced_market(env, &action.hub_asset);
    (cache, Ray::from(action.position.scaled_amount))
}
```

```rust
/// Applies `interest_factor` to `old_index` to produce the new borrow index,
/// capped at `MAX_BORROW_INDEX_RAY`.
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}
```

```rust
/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
