### Title
Stale delegate grant resurrects when the position NFT returns to the original owner — ([File: contracts/controller/src/storage/account.rs](contracts/controller/src/storage/account.rs))

### Summary
The Keycloak CVE is session fixation: a restarted authentication reuses the previous session's identifier, so an authorization the user believes was discarded silently reattaches to the new session. XOXNO Lending carries the same shape in its delegate system. A `DelegateGrant` is keyed only by `account_id` and stamped with `granted_by`; when the NFT moves to a new owner the grant is merely filtered out of `get_delegates`, not deleted. If the token ever returns to the original owner, the dormant grant becomes live again with no fresh authorization — exactly the "new session, old SID" pattern.

### Finding Description
`Delegates(account_id)` stores a single `DelegateGrant { granted_by, delegates }` [1](#0-0) . `get_delegates` returns the stored list only when `grant.granted_by == current_owner`; on any other owner it returns an empty list but leaves the entry in persistent storage [2](#0-1) . The position-NFT README documents this explicitly: "The stale grant stays in storage and re-arms if the token returns to `granted_by`" [3](#0-2) .

The only purge paths are `remove_delegate` (which deletes the entry when `granted_by != owner`) and `add_delegate` (overwrite), both callable solely by the *current* owner [4](#0-3) . Neither the protocol nor the NFT's `transfer` hook touches the grant on handover — nothing in the controller runs on NFT transfer [5](#0-4) . The test `remove_delegate_purges_stale_grant_preventing_resurrection` confirms resurrection is the default absent an explicit purge [6](#0-5) .

Delegate entries in `supply.rs`, `debt.rs`, `liquidation/mod.rs`, `swap_collateral.rs`, `swap_debt.rs`, and `repay_debt_with_collateral.rs` show delegates are accepted as acting authority on the account's owner-gated verbs (borrow, withdraw, strategy operations), not just reads.

### Impact Explanation
A resurrected delegate regains full acting power over the account — can borrow against its collateral, withdraw, or run strategies — after the grant's apparent revocation by change of ownership. This is theft of user funds: the owner who reacquires the NFT (or gets it back after a sale, loan, or custody transfer) has no on-chain signal that an old grant reactivated, and never authorized the delegate under the new ownership "session".

### Likelihood Explanation
Reachable by an unprivileged address: `position-nft transfer` is in-scope and unprivileged. The attacker needs only to (1) hold or obtain a delegate grant on an account while the victim owns it (delegation is a normal feature), (2) arrange for the token to leave and return to `granted_by` — e.g., the attacker is the intermediate holder during a legitimate sale that is unwound, or an escrow that returns the NFT. The intermediate holder has every incentive *not* to call `remove_delegate` (it costs them a call and the grant is inert for them anyway), so the purge never happens. Severity is bounded by needing a prior grant plus a return transfer, matching the original advisory's Medium.

### Recommendation
Delete `Delegates(account_id)` on every ownership transition. Since no controller code runs on `transfer`, stamp the grant with a value that changes on handover — e.g., store the owner alongside a transfer counter or a mint/epoch nonce the NFT contract bumps per transfer — and treat `granted_by` mismatches as deletion on *read* (`get_delegates` should `persistent().remove` the stale entry, not just filter it). Alternatively, expose a permissionless `purge_delegates(account_id)` that removes grants whose `granted_by != owner_of(account_id)` so anyone can clean them.

### Proof of Concept
1. Alice owns account NFT `id`. Alice calls `add_delegate(caller=alice, account_id=id, delegate=mallory)` — grant `{granted_by: alice, delegates: [mallory]}` is stored.
2. Alice transfers token `id` to Bob (`position-nft transfer`). `get_delegates(id, bob)` now returns empty; the entry remains. Bob does not call `remove_delegate`.
3. Token `id` returns to Alice — Bob sells/transfers it back, or Mallory herself was the intermediate holder and transfers it back (e.g., an aborted sale where Mallory was custodian).
4. `get_delegates(id, alice)` returns `[mallory]` again: `grant.granted_by == alice` [7](#0-6) . No event or fresh auth occurred.
5. Mallory calls `borrow` / `withdraw` / a strategy verb on `id` as delegate and extracts value up to the account's borrowing power — authorization Alice never granted under the current ownership.

/// Returns grants stamped by `owner`, or an empty list. Ownership changes
/// invalidate a previous owner's grants without deleting them.
pub(crate) fn get_delegates(env: &Env, account_id: u64, owner: &Address) -> Vec<Address> {
    get_user::<DelegateGrant>(env, &ControllerKey::Delegates(account_id))
        .filter(|grant| grant.granted_by == *owner)
        .map(|grant| grant.delegates)
        .unwrap_or_else(|| Vec::new(env))
}

fn set_delegates(env: &Env, account_id: u64, owner: &Address, delegates: &Vec<Address>) {
    let key = ControllerKey::Delegates(account_id);
    if delegates.is_empty() {
        env.storage().persistent().remove(&key);
    } else {
        set_user(
            env,
            &key,
            &DelegateGrant {
                granted_by: owner.clone(),
                delegates: delegates.clone(),
            },
        );
    }
}

pub(crate) fn remove_delegate(
    env: &Env,
    account_id: u64,
    owner: &Address,
    delegate: &Address,
) -> bool {
    let key = ControllerKey::Delegates(account_id);
    let Some(grant) = get_user::<DelegateGrant>(env, &key) else {
        return false;
    };
    if grant.granted_by != *owner {
        env.storage().persistent().remove(&key);
        return false;
    }
    let mut delegates = grant.delegates;
    let Some(index) = delegates.first_index_of(delegate) else {
        return false;
    };
    delegates.remove(index);
    set_delegates(env, account_id, owner, &delegates);
    true
}
```

/// The new owner's `remove_delegate` deletes a previous owner's grant and returns `false`.
/// The grant stays deleted when the NFT returns to the previous owner.
#[test]
fn remove_delegate_purges_stale_grant_preventing_resurrection() {
    let env = Env::default();
    env.mock_all_auths();
    let admin = Address::generate(&env);
    let contract_id = env.register(Controller, (admin,));
    let nft = setup_position_nft(&env, &contract_id);

    let alice = Address::generate(&env);
    let bob = Address::generate(&env);
    let delegate = Address::generate(&env);
    let account_id = u64::from(position_nft::PositionNftClient::new(&env, &nft).mint(&alice));

    env.as_contract(&contract_id, || {
        assert!(add_delegate(&env, account_id, &alice, &delegate));
        assert_eq!(get_delegates(&env, account_id, &alice).len(), 1);
    });

    position_nft::PositionNftClient::new(&env, &nft).transfer(
        &alice,
        &bob,
        &u32::try_from(account_id).unwrap(),
    );

    env.as_contract(&contract_id, || {
        assert!(!remove_delegate(&env, account_id, &bob, &delegate));
        assert!(
            !env.storage()
                .persistent()
                .has(&ControllerKey::Delegates(account_id)),
            "stale grant must be purged from storage, not merely read as empty"
        );
    });

    position_nft::PositionNftClient::new(&env, &nft).transfer(
        &bob,
        &alice,
        &u32::try_from(account_id).unwrap(),
    );

    env.as_contract(&contract_id, || {
        assert_eq!(
            get_delegates(&env, account_id, &alice).len(),
            0,
            "the purged grant must not resurrect when the NFT returns to its original owner"
        );
    });
```
