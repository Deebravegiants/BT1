### Title
Occlusion (`THRESHOLD_OCCLUSION_30`) verdict is never enforced before iris-code signing - ([File: src/plans/biometric_capture/mod.rs])

### Summary
`update_occlusion` in `src/plans/biometric_capture/mod.rs` computes `occlusion_30_low_pass` against `THRESHOLD_OCCLUSION_30` (`src/consts.rs`) but only drives a UI indicator (`orb.ui.biometric_capture_occlusion`); it never rejects the frame or aborts capture. The frame-acceptance logic in `handle_ir_net` and the downstream `enroll_user::make_signature`/`secure_element::sign` path never re-check occlusion, so an eye whose sharpness `score` clears `IRIS_SCORE_MIN` but is heavily occluded can still be captured, hashed, and signed.

### Finding Description
In `handle_ir_net` (`src/plans/biometric_capture/mod.rs:216-268`), a frame is accepted into `self.left_ir`/`self.right_ir` purely based on: [1](#0-0) 
i.e. `estimate.score >= IRIS_SCORE_MIN`, IR brightness range, and capture timing — `occlusion_30` is not part of this condition. Separately, `update_occlusion` (`src/plans/biometric_capture/mod.rs:666-690`) computes the low-pass occlusion value and compares it to `THRESHOLD_OCCLUSION_30`, but its only side effects are `orb.ui.biometric_capture_occlusion(true/false)` calls: [2](#0-1) . There is no `Result`/flag returned that feeds back into `valid_capture`, `Objective` completion, or `Plan::run_check`.

Once a `Capture` is produced, `biometric_pipeline::Plan::run` (not directly re-examined here but consistent with the call chain) builds `Pipeline` including `iris_code`/`mask_code`, and `enroll_user::Plan::run` unconditionally calls `make_signature` whenever `self.pipeline` is `Some`: [3](#0-2) . `make_signature` itself hashes `pipeline.v2.eye_left.iris_code`/`eye_right.iris_code` and calls `secure_element::sign` with no occlusion or liveness check: [4](#0-3) .

Additionally, the only Orb-side fraud gate in the signup flow, `detect_fraud` in `src/plans/mod.rs`, has had all its checks removed: [5](#0-4) , so there is no secondary gate that would catch an occluded/borderline capture before `enroll_user` is invoked.

The `score`/`valid_for_identification` fields used for frame selection come from the IR-Net Python model and are computed independently of `occlusion_30` in the visible Rust code path (`calculate_selection_score` in `src/agents/python/ir_net.rs:299-308` only considers `sharpness`, `status`, and `valid_for_identification`, not `occlusion_30`). Whether the Python model's `valid_for_identification`/`score` internally already accounts for occlusion cannot be verified from this repository's indexed Rust code, since that logic lives in the external `occlusion_detection`/`ir_net` Python models not included in this index.

### Impact Explanation
This allows biometric enrollment (hashing and cryptographic signing via the Secure Element) of an iris capture that fails the dedicated occlusion quality gate (`THRESHOLD_OCCLUSION_30 = 0.85`), since occlusion enforcement is limited to a UI hint and does not gate signature generation. This degrades the intended fail-closed guarantee that a poor-quality/occluded iris sample should never be signed and submitted to the backend, potentially enabling low-quality or partially covered iris data to be enrolled as a legitimate signup, assuming other independent sharpness thresholds happen to be satisfied.

### Likelihood Explanation
Requires an attacker to present an eye at borderline occlusion where `occlusion_30_low_pass` stays near/above `THRESHOLD_OCCLUSION_30` while sharpness/score still clears `IRIS_SCORE_MIN` — plausible since occlusion and sharpness are measuring different properties and are not correlated by the acceptance logic. No privileged access is needed; the attacker only needs to control what is shown to the IR camera during their own signup session.

### Recommendation
Have `handle_ir_net`'s `valid_capture` condition (or an equivalent gate in `run_check`/`run_post`) explicitly require `occlusion_30 <= THRESHOLD_OCCLUSION_30` (or that `occlusion_detected == false`) before accepting a frame into `left_ir`/`right_ir`, and/or have `biometric_pipeline::Plan::run` / `enroll_user::Plan::run` refuse to call `make_signature` when the selected capture's occlusion metric fails the threshold, returning a dedicated failure status instead of `Status::Success`.

### Proof of Concept
Integration test plan:
1. Construct a `Capture`/`FrameInfoIr` sequence where `ir_net::EstimateOutput.score >= IRIS_SCORE_MIN` but `occlusion_30 > THRESHOLD_OCCLUSION_30` for both eyes.
2. Feed it through `biometric_capture::Plan` (or directly construct the resulting `Capture`) and drive it into `biometric_pipeline::Plan::run` to obtain a `Pipeline`.
3. Call `enroll_user::Plan::run` with that `Pipeline` and assert that `Status::Success` (and a non-`None` signature from `secure_element::sign`) is never produced when occlusion exceeds `THRESHOLD_OCCLUSION_30`; currently the test would show `make_signature` succeeds and returns a valid signature regardless of the occlusion value, confirming the gap.

    fn update_occlusion(&mut self, orb: &mut Orb, estimate: &EstimateOutput) {
        let dt = self.occlusion_center_led_timer.get_dt().unwrap_or(0.0);
        let EstimateOutput { mut occlusion_30, sharpness, .. } = *estimate;
        if occlusion_30.is_nan() || sharpness.is_nan() || sharpness < IRIS_SHARPNESS_MIN {
            occlusion_30 = THRESHOLD_OCCLUSION_30 * 1.05;
        }
        let occlusion_30_low_pass =
            self.occlusion_30_filter.add(occlusion_30, dt, OCCLUSION_CENTER_LED_LOW_PASS_FILTER_RC);
        // Apply hysteresis and a minimum pulse time.
        let occlusion_detected =
            if let Some(occlusion_indicator_on_time) = self.occlusion_indicator_on_time {
                occlusion_30_low_pass < THRESHOLD_OCCLUSION_30 * 1.025
                    || occlusion_indicator_on_time.elapsed() < OCCLUSION_INDICATOR_MIN_TIME_INTERVAL
            } else {
                occlusion_30_low_pass < THRESHOLD_OCCLUSION_30 * 0.975
            };
        if occlusion_detected {
            self.occlusion_indicator_on_time.get_or_insert_with(Instant::now);
            orb.ui.biometric_capture_occlusion(true);
        } else {
            orb.ui.biometric_capture_occlusion(false);
            self.occlusion_indicator_on_time = None;
        }
    }

fn make_signature(user_qr_code: &qr_scan::user::Data, pipeline: &Pipeline) -> Result<String> {
    let mut ctx = Context::new(&SHA256);
    ctx.update(ORB_ID.as_str().as_bytes());
    ctx.update(user_qr_code.user_id.as_bytes());
    ctx.update(pipeline.v2.ir_net_version.as_bytes());
    ctx.update(pipeline.v2.iris_version.as_bytes());
    ctx.update(pipeline.v2.eye_left.iris_code.as_bytes());
    ctx.update(pipeline.v2.eye_left.mask_code.as_bytes());
    ctx.update(pipeline.v2.eye_left.iris_code_version.as_bytes());
    ctx.update(pipeline.v2.eye_right.iris_code.as_bytes());
    ctx.update(pipeline.v2.eye_right.mask_code.as_bytes());
    ctx.update(pipeline.v2.eye_right.iris_code_version.as_bytes());
    let signed = secure_element::sign(ctx.finish())?;
    Ok(BASE64.encode(&signed))
}
