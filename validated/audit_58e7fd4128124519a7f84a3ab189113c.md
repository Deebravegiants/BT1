### Title
Iris-code signature lacks session/action binding (missing nonce, signup ID, and purpose field) - (File: `src/plans/enroll_user.rs`)

### Summary
`make_signature` in `src/plans/enroll_user.rs` builds the Secure-Element signature that accompanies a signup by hashing only `ORB_ID`, the scanned user ID, and the iris/mask pipeline outputs and versions, then signing that digest with the Secure Element. [1](#0-0)  Unlike the ChainPort signature scheme discussed in the report — which binds signed messages to a `networkId` (context) and an `action` (purpose) to prevent cross-context/cross-purpose replay — this signature has no field identifying the specific signup session (e.g. `signup_id`), no timestamp/nonce, and no explicit "action" discriminator, even though `signup_id` is generated and used elsewhere in the same enrollment flow. [2](#0-1) 

### Finding Description
The signed payload is composed purely of:
- `ORB_ID` (fixed per-device identity)
- `user_qr_code.user_id` (from the scanned, user-supplied QR code)
- pipeline version strings and iris/mask codes for both eyes [3](#0-2) 

There is no `signup_id`, timestamp, or nonce mixed into the signed digest, despite `signup_id` being generated per signup attempt and sent alongside the signature to the backend in `signup_post::request`. [4](#0-3)  This mirrors the exact class of issue flagged in the external report: without a unique per-session/per-action binding field, a signature computed for one signup context carries no cryptographic guarantee that it was intended for that specific signup transaction (analogous to ChainPort's missing `networkId`/`action` fields enabling replay across chains/bridges).

The actual signing primitive itself is opaque to orb-core — it shells out to `/usr/bin/orb-sign-iris-code` via `secure_element::sign` [5](#0-4)  — and the corresponding server-side verification logic that would check signature/nonce uniqueness (the second half of the report's concern) is not present in this repository, so I cannot confirm from orb-core alone whether the backend compensates for the missing binding by tying the signature to `signup_id` through some other channel.

### Impact Explanation
If the backend's verification of this signature does not independently and cryptographically bind it to the specific `signup_id` of the request it accompanies (which orb-core cannot guarantee, since the signed digest itself contains no such binding), a previously observed valid `(user_id, iris/mask codes, signature)` tuple could be resubmitted in a different signup transaction for the same user, potentially causing misattributed or duplicate signup processing without requiring a fresh Secure-Element signing operation. This is the closest reachable orb-core analog to "unauthorized or misattributed signup" impact, but the actual exploitability depends entirely on backend-side checks that are outside this repository's visibility.

### Likelihood Explanation
Reachability requires only the unprivileged signup flow: presenting a QR code and completing a biometric capture. [6](#0-5)  No privileged access is needed to trigger `make_signature`. However, because the exploit's success hinges on backend verification behavior not visible in orb-core, the likelihood of a concrete, provable exploit purely from this code cannot be fully established.

### Recommendation
Include a unique per-signup context in the signed digest — at minimum the `signup_id` already generated for the transaction — and consider an explicit purpose/action discriminator if `secure_element::sign` or this signed format is (or could be) reused for other purposes, mirroring the `networkId`/`action` design recommended in the source report. Document the intended security properties (integrity/non-repudiation of "this orb produced this iris code for this specific signup") explicitly, so that backend verification can be checked against a clear specification.

### Proof of Concept
Not independently reproducible from orb-core alone: the code shows that `make_signature`'s digest omits `signup_id`/nonce/action binding [1](#0-0) , and `signup_id` is generated and transmitted separately from the signature in `signup_post::request` [4](#0-3) . Full exploitability requires observing whether the backend (not present in this repo) treats a resubmitted `(user_id, codes, signature)` tuple under a new `signup_id` as valid.

fn make_signature(user_qr_code: &qr_scan::user::Data, pipeline: &Pipeline) -> Result<String> {
    let mut ctx = Context::new(&SHA256);
    ctx.update(ORB_ID.as_str().as_bytes());
    ctx.update(user_qr_code.user_id.as_bytes());
    ctx.update(pipeline.v2.ir_net_version.as_bytes());
    ctx.update(pipeline.v2.iris_version.as_bytes());
    ctx.update(pipeline.v2.eye_left.iris_code.as_bytes());
    ctx.update(pipeline.v2.eye_left.mask_code.as_bytes());
    ctx.update(pipeline.v2.eye_left.iris_code_version.as_bytes());
    ctx.update(pipeline.v2.eye_right.iris_code.as_bytes());
    ctx.update(pipeline.v2.eye_right.mask_code.as_bytes());
    ctx.update(pipeline.v2.eye_right.iris_code_version.as_bytes());
    let signed = secure_element::sign(ctx.finish())?;
    Ok(BASE64.encode(&signed))
}

#[cfg(not(test))]
pub fn sign<T: AsRef<[u8]>>(data: T) -> Result<Vec<u8>> {
    fn inner(data: &[u8]) -> Result<Vec<u8>> {
        let encoded = BASE64.encode(data);

        tracing::info!("Running orb-sign-iris-code");
        let mut command = Command::new("/usr/bin/orb-sign-iris-code");
        command.stdin(Stdio::piped());
        command.stdout(Stdio::piped());
        command.stderr(Stdio::piped());
        let mut child = command.spawn().wrap_err("running orb-sign-iris-code")?;

        let mut stdin = child.stdin.take().unwrap();
        stdin.write_all(encoded.as_bytes())?;
        drop(stdin);

        let output = child.wait_with_output().wrap_err("waiting for orb-sign-iris-code")?;
        let success = output.status.success();
        for line in String::from_utf8_lossy(&output.stderr).lines() {
            if success {
                tracing::trace!("orb-sign-iris-code {}", line);
            } else {
                tracing::error!("orb-sign-iris-code {}", line);
            }
        }
        if !success {
            if let Some(code) = output.status.code() {
                bail!("orb-sign-iris-code exited with non-zero exit code: {code}");
            } else {
                bail!("orb-sign-iris-code terminated by signal");
            }
        }
        BASE64.decode(&output.stdout).wrap_err("decoding orb-sign-iris-code output")
    }

    inner(data.as_ref())
}
