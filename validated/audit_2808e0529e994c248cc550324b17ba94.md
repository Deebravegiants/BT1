### Title
`recapitalize` refunds the unmeasured "excess" before checking any payment arrived, letting an unprivileged caller drain pool custody and permanently freeze suppliers' funds - (File: contracts/pool/src/ops/recapitalize.rs)

### Summary
The f2fs bug class — an operation that commits to a relocation without first checking the destination has enough room, then fails mid-way — maps onto XOXNO Lending's `recapitalize` path. The pool trusts the caller's declared `offered` amount, books `min(offered, shortfall)` as new cash, and refunds `offered − shortfall` to the payer via `Cache::transfer_out`, **without ever measuring an inbound token transfer**. The only bound on the refund is live token custody, not any verified receipt. An unprivileged address can declare the pool's entire balance as "offered", receive it back as a refund for a payment that never happened, and leave the `cash` book unchanged — after which every supplier exit passes the pool's own `require_reserves`/`require_utilization_below_max`/`require_supply_for_debt` guards (all of which read the book) and then fails inside the SAC transfer, permanently freezing user funds.

### Finding Description
`recapitalize(hub_asset, payer, offered)` is permissionless. In `contracts/pool/src/ops/recapitalize.rs` the op computes `backing_shortfall` ( [1](#0-0) ), credits `min(offered, shortfall)` to `cash`, and unconditionally sends `offered − actual` back to `payer` with `Cache::transfer_out` ( [2](#0-1) ). No balance-delta measurement of the payer's inbound payment is performed — unlike the flash path which reconciles balances, and unlike `payments::balance_delta_since` used elsewhere in the controller. The in-repo regression test demonstrates the end state directly: calling `recapitalize` with `offered = pool token balance` leaves `token.balance(pool) == 0` while `state.cash` is untouched ( [3](#0-2) ), and a subsequent full withdraw passes both `InsufficientLiquidity` and `PoolInsolvent` guards only to revert inside the SAC transfer with `BalanceError = 10` ( [4](#0-3) ). This mirrors the CVE: the resize never checked that the post-shrink filesystem could hold the blocks it was about to migrate; here recapitalize never checks that the payment it is about to refund was actually received.

### Impact Explanation
Two sequential impacts, both reachable by a single unprivileged address calling `controller::recapitalize` (or `pool::recapitalize` via the pool's authed entrypoint with any `payer`):

1. **Theft of user funds**: the refund leg pays `offered − shortfall` out of pool custody to an arbitrary `payer`. With `offered` set to the full token balance and no real payment made, the attacker receives the entire market's underlying.
2. **Permanent freezing of funds**: because the `cash` book is only credited by the shortfall amount and never debited for the refund, the books still report full backing. Exits clear `require_reserves` ( [5](#0-4) ) and `require_backed_market` ( [6](#0-5) ), then revert inside the SAC `transfer` — not fail-closed by design, but fail-open bookkeeping that strands every supplier in that market.

### Likelihood Explanation
Single call, no timing, no price manipulation, no privileged role. `recapitalize` is an advertised permissionless repair path (docs list it among reachable entrypoints), and the attack cost is one invocation per market with `offered` set to the pool's custody balance. The only constraint is the refund is bounded by live custody ( [7](#0-6) ), which is exactly what the attacker wants to take.

### Recommendation
Measure the actual inbound payment with a balance delta (or require the controller to pull funds from `payer` via `require_auth` + `transfer` before crediting), and only refund `received − min(received, shortfall)`. Alternatively, split the entrypoint: credit only the measured shortfall and never refund. At minimum, reconcile `cash` against `token.balance(pool)` after settlement.

```rust
pub(crate) fn backing_shortfall(cache: &Cache) -> i128 {
    let supplied_claim = cache.unscale_supply_floor(cache.supplied());
    let outstanding_debt = cache.unscale_borrow_ceil(cache.borrowed());
    let backing = cache.cash().saturating_add(outstanding_debt);
    supplied_claim.saturating_sub(backing).max(0)
}
```

```rust
fn test_unfunded_recapitalize_is_bounded_by_custody_not_by_the_declared_amount() {
    let t = TestSetup::new();
    let token = token::Client::new(&t.env, &t.asset);
    let payer = Address::generate(&t.env);

    let custody = token.balance(&t.pool);
    let before = t.state_snapshot();

    let outcome = t
        .client()
        .try_recapitalize(&hub(&t.asset), &payer, &(custody + 1));

    assert!(
        outcome.is_err(),
        "over-claiming past custody must not succeed"
    );
    assert_eq!(
        token.balance(&t.pool),
        custody,
        "a reverted over-claim leaves custody intact"
    );
    assert_eq!(token.balance(&payer), 0);
    assert_eq!(t.state_snapshot().cash, before.cash);
```
