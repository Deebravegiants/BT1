### Title
`Zap._sellInternal()` blocks a legitimate token sale whenever a live LT price tick flips `canGraduate()` true, even though the sale itself does not threaten the graduation invariant - (File: `packages/contracts/src/Zap.sol`)

### Summary
`Zap._sellInternal` unconditionally re-checks `Bonding.canGraduate(tokenAddress)` before every curve sell and, if true, diverts the entire call into forced graduation instead of executing the user's sale [1](#0-0) . `canGraduate` is not a static/structural property of the trade being executed — it is recomputed live from the external LT's `exchangeRate()`, an independently fluctuating, rebasing price feed [2](#0-1) . This is the same bug class as the `withdraw()` finding: a validation condition that has nothing to do with the specific action being executed (selling tokens you already hold vs. withdrawing already-borrowed funds) can flip due to ordinary price movement and block/redirect the user's otherwise-valid transaction.

### Finding Description
`Bonding.canGraduate` computes a USD-value trigger as `realLtRaised * IBounceLeveragedToken(info.ltAddress).exchangeRate() / 1e18 >= graduationThresholdUsd` [3](#0-2) . `exchangeRate()` is read live off the BounceTech leveraged token and can tick up between the moment a user signs/broadcasts a `sell` transaction and the moment it executes, purely from LT price drift/streaming-fee accrual — with zero action by the seller.

In `Zap._sellInternal`, this live, price-driven boolean gates the sell path itself:

```solidity
if (bonding_.canGraduate(tokenAddress)) {
    if (minUsdcOut != 0) revert TokenIsGraduating();
    bonding_.triggerGraduation(tokenAddress);
    return 0;
}
``` [4](#0-3) 

Two outcomes follow, both undesired from the seller's perspective:
1. If the caller supplied any non-zero `minUsdcOut` (i.e., any real slippage protection at all), the call reverts outright with `TokenIsGraduating` — the sale that the user's tokens already fully entitle them to simply fails.
2. If the caller passes `minUsdcOut == 0` to route around the revert, no tokens are sold at all (`return 0`) — the user's sell intent is discarded and graduation is triggered instead, with the tokens remaining locked in `Lifecycle.Graduating` state where further curve sells are blocked (`bonding_.isGraduating(tokenAddress)` check at the top of `_sellInternal`) [5](#0-4)  until phase-2 `finalizeGraduation` completes and a HyperSwap V2 pool exists.

The direct `Bonding.sell()` entrypoint has the identical unconditional gate for any router that doesn't pre-trigger graduation itself [6](#0-5) .

Just as in the original report — where withdrawing `underlyingBorrowToken` (an action that doesn't move `collateralRatio`) was blocked by a `collateralRatio`-based check that can fail from ordinary price ticks — here, selling tokens a user already owns (an action whose only real constraint should be curve liquidity/slippage) is blocked/redirected by a graduation-USD-value check driven by an unrelated, live, external exchange rate.

### Impact Explanation
A trader holding curve tokens who wants to exit at a specific price (any nonzero `minUsdcOut`) can be denied the ability to sell at all the moment `exchangeRate()` ticks the curve's raised-LT value past `graduationThresholdUsd`, even though their sell would otherwise execute fine against curve liquidity. Their only way to interact is to accept `minUsdcOut = 0` and get zero proceeds while their tokens sit frozen through the `Lifecycle.Graduating` window until a permissionless keeper/anyone calls `finalizeGraduation`. During that window they cannot sell on the curve (`isGraduating` gate) and cannot yet sell on the graduated V2 pool (doesn't exist until phase 2 completes). This is a temporary freeze of trader funds/liquidity access driven purely by price movement of an asset (the LT) that the trader has no control over, mirroring the "Medium" characterization of the original report (no permanent loss, but forced illiquidity/blocked withdrawal due to an unrelated, fluctuating check).

### Likelihood Explanation
`exchangeRate()` on the BounceTech LT is continuously drifting (streaming fee accrual, rebasing), and `graduationThresholdUsd` is a fixed USD figure, so any curve sitting close to the threshold will flip `canGraduate()` from false to true (and possibly flap) purely from price movement with no trading activity at all, exactly as the external report describes for `collateralRatio` near `openingLimitBorrowCR`. Any seller submitting a `sell` transaction during that window is affected without any way to predict or avoid it client-side beyond re-simulating immediately before submission — likelihood is high for tokens trading near the graduation threshold.

### Recommendation
Do not let a sell-time trigger of `canGraduate` unconditionally cancel/deny the caller's specific sell request. Options: (a) allow the sell to execute against current curve reserves first and only enter graduation afterward if `canGraduate` is still true post-trade (mirroring the buy path's post-trade `canGraduate` check in `_executeBuy`/`_enterGraduating`), or (b) if forced-graduation-on-detection is intentional, surface it via a dedicated non-reverting preview/quote so front-ends can warn users pre-submission rather than reverting/zeroing an already-signed transaction, and let users explicitly opt into "trigger graduation instead of selling" rather than having their sell silently repurposed.

### Proof of Concept
1. Launch a token whose curve's real-LT-raised value is close to (just under) `graduationThresholdUsd`.
2. A holder submits `Zap.sell(tokenAddress, tokenAmount, minUsdcOut)` with `minUsdcOut > 0` (normal slippage protection).
3. Before the transaction lands, the underlying LT's `exchangeRate()` ticks up slightly (ordinary streaming-fee accrual/rebasing, no attacker action needed) such that `Bonding.canGraduate(tokenAddress)` now returns `true`.
4. `_sellInternal` hits `if (bonding_.canGraduate(tokenAddress)) { if (minUsdcOut != 0) revert TokenIsGraduating(); ... }` and the transaction reverts — the holder cannot sell tokens they already own [7](#0-6) .
5. Retrying with `minUsdcOut = 0` does not sell either — it calls `bonding_.triggerGraduation(tokenAddress)` and returns `0`, leaving the holder's tokens stuck in `Lifecycle.Graduating` (curve sells blocked via `isGraduating`) until an unrelated permissionless `finalizeGraduation` call completes [8](#0-7) .

    function canGraduate(
        address token_
    ) public view returns (bool) {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[token_];
        if (info.creator == address(0)) return false;
        if (info.lifecycle != Lifecycle.Curve) return false;

        address pair = info.pair;
        if (IPair(pair).tokenBalance() == 0) return true;

        (, uint256 assetReserve) = IPair(pair).getReserves();
        uint256 realLtRaised = assetReserve - _launchTimeVirtualLtReserve(token_, pair);
        uint256 valueUsd = (realLtRaised * IBounceLeveragedToken(info.ltAddress).exchangeRate()) / 1e18;
        return valueUsd >= $.graduationThresholdUsd;
    }
```
