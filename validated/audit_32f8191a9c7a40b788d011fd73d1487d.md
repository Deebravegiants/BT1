### Title
Relay-fee obligation for Emporium wallet-invoke flows can be silently bypassed by supplying an EOA as `signerAddress` - (File: contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol)

### Summary
`EmporiumUpgradeable.runAction` and `payRelayFees` pay the relay's flat fee by calling `IHinkalWallet(stack.signerAddress).doSendToRelay(...)` whenever `stack.signerAddress != address(0)`, but never verify that `signerAddress` is a real deployed `HinkalWallet` contract that actually moves funds. Since `signerAddress` only has to satisfy a plain ECDSA recovery check (an EOA-only check), a user can set `signerAddress` to their own EOA, sign the EIP-712 message themselves, and the "fee payment" call becomes a no-op CALL to an address with no code — which succeeds trivially without transferring anything to the relay.

### Finding Description
`verifyWallet` only performs `ECDSA.tryRecover(...)` and compares the recovered address to `stack.signerAddress`: [1](#0-0) 

This check can only succeed when `signerAddress` is an EOA (an ECDSA-recoverable key), since it does not use `SignatureChecker`/EIP-1271 to validate that `signerAddress` is actually a smart-contract wallet. Yet the same `signerAddress` is subsequently treated as an `IHinkalWallet` contract that must physically hold and transfer tokens: [2](#0-1) 

and is used to compute/skip the actual balance-based relay fee: [3](#0-2) 

`IHinkalWallet(signerAddress).doSendToRelay(...)` and `.callHinkalWallet(...)` are external calls typed against an interface; if `signerAddress` has no deployed code (an EOA), the low-level `CALL` opcode still returns success with empty return data, so Solidity does not revert. The intended flow — `HinkalWallet.doSendToRelay` calling `Transferer.sendToRelay` to actually push tokens to the relay — [4](#0-3) [5](#0-4)  — simply never executes, and `EmporiumUpgradeable.runAction` has no post-call assertion (e.g., relay balance delta) to detect this. There is no `Address.isContract`/extcodesize check anywhere on `signerAddress`.

Note that including `circomData.externalActionData` (which carries the ABI-encoded `EmporiumStack`, hence `signerAddress`) inside `calldataHash`/the circuit's public inputs — [6](#0-5) [7](#0-6)  — provides no real protection here, since the entire `circomData` (including `calldataHash` itself) is self-supplied by the same attacker who controls the transaction; the equality only proves internal consistency, not that `signerAddress` corresponds to a legitimate funded wallet.

This is directly analogous to the referenced DsToken bug class: an account that is supposed to bear a cost (there: `payer` for token-account rent; here: the "payer" of the relay's flat fee) is taken from attacker-controlled input and never validated to be the entity actually intended/able to pay, letting the attacker redirect or entirely evade the obligation.

### Impact Explanation
This matches the "High — theft or permanent freezing of protocol/relay fees" category. A user routing a transaction through Emporium (`Hinkal._externalTransact` → `EmporiumUpgradeable.runAction`) with `stack.ops = []` and `stack.signerAddress` set to their own EOA can complete the operation, have `feeStructure.flatFee` "charged" on paper via `payRelayFees`, yet the relay never actually receives the fee — a relay processes/pays gas for a transaction and never gets compensated. Repeated abuse causes systematic relay-fee loss for the protocol/relayers.

### Likelihood Explanation
High. No special privileges are required: any unprivileged EOA can call the standard Emporium external-action flow, self-sign the EIP-712 `EmporiumSignature` with their own key, and pick their own address as `signerAddress`. No relayer, admin, or upgrade key involvement is needed, and the ZK circuit does not constrain `signerAddress`'s nature (contract vs EOA) — it only ties `calldataHash` to values the attacker themselves supplies.

### Recommendation
Before relying on `signerAddress` as a fee-paying wallet, verify it is a genuine `HinkalWallet` deployed by the protocol (e.g., check a deployment registry/factory mapping, or verify `extcodesize(signerAddress) > 0` and that it matches an expected deterministic deployment address for the recovered signer). Alternatively, assert an actual balance change on the fee token held by the relay (before/after check) analogous to the balance-delta checks already used elsewhere in `runAction`, and revert if the expected fee amount was not received.

### Proof of Concept
1. Attacker (EOA `A`) constructs `circomData` for an Emporium external action with `feeStructure.flatFee = X > 0`, `relay = <a valid registered relay>`.
2. `externalActionData.externalActionMetadata` encodes an `EmporiumStack` with `signerAddress = A`, `ops = []`, `maxFee >= X`, `deadline` in future.
3. Attacker signs the EIP-712 `EmporiumSignature(message, ops, maxFee, deadline)` digest with `A`'s own private key, producing `(v, r, s)` that recovers to `A`.
4. Attacker submits the Hinkal transaction with a valid ZK proof over their own self-consistent `circomData` (calldataHash matches, since attacker computed it themselves).
5. `EmporiumUpgradeable.runAction` calls `verifyWallet` — passes (`recoveredAddress == A == stack.signerAddress`).
6. `payRelayFees` computes `relayFee = flatFee` (since `signerAddress != address(0)`) and calls `sendToRelayFromWallet(relay, A, flatFee, feeToken)` → `IHinkalWallet(A).doSendToRelay(...)`.
7. Since `A` is an EOA with no code, this call returns success without executing any code — no tokens move to `relay`.
8. Transaction completes successfully; the relay receives nothing despite the protocol logic believing the fee was paid.

    function payRelayFees(
        CircomData calldata circomData,
        address signerAddress,
        int256[] calldata deltaAmountChanges
    ) internal {
        FeeStructure calldata feeStructure = circomData.feeStructure;

        bool foundToken = false;

        for (uint256 i = 0; i < circomData.erc20TokenAddresses.length; i++) {
            // tokens deposited into Emporium are not charged
            if (deltaAmountChanges[i] >= 0) {
                continue;
            }

            address erc20TokenAddress = circomData.erc20TokenAddresses[i];
            bool isFeeToken = erc20TokenAddress == feeStructure.feeToken;

            if (isFeeToken) {
                foundToken = true;
            }

            uint256 relayFee = 0;
            uint256 flatFee = isFeeToken ? feeStructure.flatFee : 0;

            if (signerAddress == address(0)) {
                uint256 sumAbs = uint256(-deltaAmountChanges[i]);

                EmporiumStorageVars storage $ = _getEmporiumStorage();
                relayFee = $._hinkalHelper.calculateRelayFee(
                    sumAbs,
                    flatFee,
                    feeStructure.variableRate
                );
            } else {
                relayFee = flatFee;
            }

            payRelay(
                circomData.relay,
                signerAddress,
                relayFee,
                erc20TokenAddress
            );
        }

        if (!foundToken && feeStructure.flatFee != 0) {
            require(
                signerAddress != address(0),
                "Gas Token in Emporium is not found"
            );

            payRelay(
                circomData.relay,
                signerAddress,
                feeStructure.flatFee,
                feeStructure.feeToken
            );
        }
    }

    function verifyWallet(
        EmporiumStack memory stack,
        CircomData calldata circomData
    ) internal {
        EmporiumStorageVars storage $ = _getEmporiumStorage();

        if ($.usedMessages[circomData.emporiumMessage]) {
            revert UsedMessage();
        }

        $.usedMessages[circomData.emporiumMessage] = true;

        if (stack.signerAddress == address(0)) {
            return;
        }

        bytes32 hashedMessage = _hashTypedDataV4(
            keccak256(
                abi.encode(
                    EMPORIUM_SIGNATURE_TYPEHASH,
                    circomData.emporiumMessage,
                    _hashEmporiumOps(stack.ops),
                    stack.maxFee,
                    stack.deadline
                )
            )
        );

        (address recoveredAddress, ECDSA.RecoverError err) = ECDSA.tryRecover(
            hashedMessage,
            stack.v,
            stack.r,
            stack.s
        );
        bool verified = err == ECDSA.RecoverError.NoError &&
            recoveredAddress == stack.signerAddress;
        if (!verified) {
            revert InvalidSignature();
        }
