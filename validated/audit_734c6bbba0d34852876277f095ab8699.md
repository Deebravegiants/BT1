## Finding: LOOP Plugin discovery/metrics/pprof endpoints exposed without authentication

### Title
Unauthenticated access to LOOP plugin metrics and pprof profiling endpoints - (`core/web/router.go`)

### Summary
The Chainlink node's HTTP router wires the `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` routes onto the base `api` route group, which only applies rate limiting and session storage — not any authentication middleware. Every other debug/profiling surface in the router (`/debug/vars`, the node's own `/debug/pprof/*`) is explicitly wrapped with `auth.Authenticate(...)`, but the LOOP-plugin equivalent is not, allowing any unauthenticated network client to retrieve profiling data and metrics for registered LOOP plugins.

### Finding Description
In `core/web/router.go`, `NewRouter` builds an `api` group with only rate limiting and cookie-session middleware, then calls: [1](#0-0) 

`loopRoutes` registers its handlers directly on that unauthenticated `api` group: [2](#0-1) 

By contrast, the node's own `/debug/vars` route is wrapped with `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)`, and the node's own `/debug/pprof/*` (`metricRoutes`) is only registered inside `authv2`, which requires token or session auth: [3](#0-2) [4](#0-3) [5](#0-4) 

The unauthenticated `pluginPPROFHandler` proxies arbitrary pprof profile paths (heap, goroutine, cpu, etc.) to the internal LOOP plugin process and returns the raw response body to the caller: [6](#0-5) 

and `pluginMetricHandler` proxies the plugin's `/metrics` Prometheus endpoint: [7](#0-6) 

This is the same bug class as CVE-2025-68435: authentication middleware is not applied to certain API endpoints, so they are reachable without any session or token credential.

### Impact Explanation
An unauthenticated actor with network access to the node's web server (the same interface used for the authenticated `/v2/*` API) can pull heap/goroutine/CPU pprof profiles and Prometheus metrics for any registered LOOP plugin by name. Heap and goroutine dumps can leak sensitive in-memory data (stack arguments, buffers, potentially key material or other secrets handled by the plugin process), and the discovery/metrics data leaks internal topology (plugin names, ports, hostnames). The CPU-profile `seconds` query parameter is attacker-controlled and used to size the request timeout, letting an unauthenticated caller hold connections/resources open on the node's proxy path.

### Likelihood Explanation
High. The route is reachable with a single unauthenticated HTTP request to a standard, always-registered path; there is no precondition beyond network reachability to the node's web server, which is the same reachability assumption as the rest of the `/v2/*` API that is normally gated by `auth.Authenticate`.

### Recommendation
Wrap `loopRoutes` registration with the same authentication middleware used for the node's own debug/pprof routes, e.g. call `loopRoutes` on the `authv2`/authenticated group (or explicitly wrap with `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)`) instead of the bare `api` group, consistent with `debugRoutes` and `metricRoutes(authv2)`.

### Proof of Concept
Against a running node (no cookie/token supplied):
```
curl http://<node-host>:6688/discovery
curl http://<node-host>:6688/plugins/<plugin-name>/metrics
curl "http://<node-host>:6688/plugins/<plugin-name>/debug/pprof/heap?debug=1"
curl "http://<node-host>:6688/plugins/<plugin-name>/debug/pprof/goroutine?debug=2"
```
All succeed without any `Cookie`/`X-Chainlink-EA-AccessKey`/`X-Chainlink-EA-Secret` header, because the routes in `loopRoutes` (`core/web/router.go:230-236`) never pass through `auth.Authenticate`.

```go
func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/metrics", l.loopHostName, p.EnvCfg.PrometheusPort)
	req, err := http.NewRequestWithContext(gc.Request.Context(), http.MethodGet, pluginURL, nil)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)
	if err != nil {
		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q metrics", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}
```

```go
func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
```
