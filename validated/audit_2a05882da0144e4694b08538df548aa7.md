### Title
Permanent market freeze from `i128` overflow during interest accrual - (File: contracts/pool/src/interest.rs)

### Summary
A sufficiently large borrowed market can reach a state where calculating its accrued RAY debt value overflows `i128`, causing every subsequent market operation that performs accrual to revert and permanently freezing supplier and borrower funds.

### Finding Description
`interest::global_sync` processes elapsed time through `accrue_chunk`, which calls `accrue_step` using the market’s total scaled borrow amount and current indexes. [1](#0-0)  The fixed-point implementation widens the intermediate product to `I256`, but converts the final quotient back to `i128` and panics with `GenericError::MathOverflow` when that result is unrepresentable. [2](#0-1)  Debt valuation itself converts scaled debt by multiplying it by the borrow index. [3](#0-2)  All pool mutation legs load an interest-synced market before acting, and the explicit `update_indexes` path uses the same accrual routine. [4](#0-3) [5](#0-4) 

The reachable trigger is demonstrated by `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap`: a market holding one billion 18-decimal units borrows 98% of the principal, advances time under sustained high utilization, and `update_indexes` reverts with `MathOverflow` before `MAX_BORROW_INDEX_RAY` is reached. [6](#0-5) 

### Impact Explanation
After the overflow boundary is crossed, accrual cannot complete and the failed call does not advance `last_timestamp`, so the next call retries the same overflowing computation. [7](#0-6)  Because withdrawals and repayments both call `ops::load_leg`, they necessarily execute `synced_market` and therefore hit the same panic before burning shares or crediting cash. [4](#0-3) [8](#0-7) [9](#0-8)  The regression test confirms that both `withdraw` and `repay` fail after the accrual failure, permanently freezing market cash unless an excluded upgrade path intervenes. [10](#0-9) 

### Likelihood Explanation
An unprivileged caller can trigger the failing public controller `update_indexes` path once the market’s scaled debt times its borrow index exceeds the `i128` RAY-value range. [11](#0-10)  Reaching that state requires an exceptionally large market and sustained high utilization, since the demonstrated setup uses one billion 18-decimal units and 98% utilization. [12](#0-11)  The condition is nevertheless possible through ordinary `supply` and `borrow` usage, does not require private keys or oracle manipulation, and cannot be remedied by calling rate-model replacement because that path accrues first. [13](#0-12) 

### Recommendation
Make accrual reach a recoverable terminal state before total-debt valuation overflows `i128`: clamp the borrow index or elapsed accrual step to the largest value representable for the current scaled debt, persist `last_timestamp`, and permit debt repayment and liquidation paths to continue from that capped state. Alternatively, store accrued totals in a wider representation or add an explicit pre-overflow guard that finalizes the market in an orderly wind-down mode rather than repeatedly panicking inside `accrue_step`.

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```

pub(crate) fn accounting(env: &Env, action: &PoolAction) -> RepayOutcome {
    let (mut cache, position) = ops::load_leg(env, action);
    let amount = action.amount;

    let (burned, overpayment) = cache.resolve_repay(amount, position);
    let net_repay = amount
        .checked_sub(overpayment)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));
    assert_with_error!(
        env,
        net_repay == 0 || burned.raw() > 0,
        GenericError::RepayRoundsToZeroShares
    );

    let position = position.checked_sub(env, burned);
    cache.burn_debt(burned);

    cache.credit_cash(net_repay);

    let snapshot = cache.commit();
```
