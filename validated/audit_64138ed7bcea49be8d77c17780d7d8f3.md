### Title
`connectedOrigins.updateConnection` allows a connected dApp to mutate `connectedAssetName` and cause disclosure of receive addresses for un-consented assets across *all* wallet accounts - (File: `features/connected-origins/module/connections.js`)

### Summary
`ConnectedOrigins.updateConnection` lets an already-connected origin change the `connectedAssetName` attribute of its own stored connection record without any re-consent flow, similarly to how the reported `StakingRewards`/`BGTStaker` bug allowed the mutable `rewardToken` to be swapped after the fact and then leveraged through another exposed method (`rewardToken`/reward transfer) to reach unintended assets. Here the mutable field is `connectedAssetName`, and the "reach" happens through `getConnectedAccounts`, which trusts whatever asset name is currently stored, not what the user originally approved.

### Finding Description
`add()` is the only method that is documented/tested as the "consent" path — it merges an origin's requested `connectedAssetName`/`assetNames` and persists them, presumably after user approval in the UI layer. [1](#0-0) 

However, `updateConnection` is exposed on the same public API surface (`connectedOriginsApi`) as `add`, and it performs **no trust or origin-consent check**, and no validation that the new `connectedAssetName` was ever part of the original `assetNames` grant — it just checks that the origin record exists: [2](#0-1) [3](#0-2) 

When `connectedAssetName` is changed, `#setAttributes` → `#setData` recomputes the full set of "connected assets" from the record (`connectedAssetName` + `assetNames`) and regenerates/persists receive addresses for **every enabled wallet account** for that asset set into `#connectedAccountsAtom`: [4](#0-3) [5](#0-4) 

Then `getConnectedAccounts` only checks `isTrusted` (a boolean per-origin flag) — not whether the specific asset was ever granted to that origin — and returns addresses, for **all wallet accounts** (not just the one connected/active), filtered by whatever `connectedAssetName`/`assetNames` are currently stored: [6](#0-5) 

This mirrors the report's root cause: a "mutable" trust-relevant field (`rewardToken` there, `connectedAssetName` here) with an exposed setter (`BGTStaker.rewardToken` setter there, `connectedOrigins.updateConnection` here) that is later consumed by a second privileged operation (`transfer of unclaimed rewards` there, `getConnectedAccounts` disclosure here) which trusts the mutated field rather than the originally-approved value.

### Impact Explanation
A dApp that has been trusted/connected for asset A (e.g., `solana`) can call `connectedOrigins.updateConnection({ origin, connectedAssetName: 'ethereum' })` without any additional user approval, then call `getConnectedAccounts({ origin })` to obtain Ethereum (or any other supported asset) receive addresses for **every enabled wallet account in the wallet**, not just the address(es)/account the user consented to share. This is a cross-account/cross-asset privilege-bleed: private wallet topology (all account addresses across chains) that the user never intended to disclose to that origin becomes accessible through a state mutation that bypasses the original consent boundary, directly analogous to how mutating `rewardToken` bypassed the intended constraint on which token could be moved.

### Likelihood Explanation
Any origin that has achieved a single legitimate "trusted" connection (a very common baseline state for most connected dApps) can immediately call the exposed `updateConnection` and `getConnectedAccounts` API methods with no UI confirmation and no check that the new asset was ever part of the granted `assetNames`. No additional privileges or race conditions are required beyond the ordinary one-time trust flow that every DApp integration already goes through.

### Recommendation
- In `updateConnection`, disallow changing `connectedAssetName`/`assetNames` to values outside a previously-approved set, or route any change through the same consent/approval flow as `add`.
- In `getConnectedAccounts`, only return addresses for assets that are present in the record's originally-approved `assetNames`, and avoid returning addresses for wallet accounts beyond the ones explicitly connected for that origin.
- Treat trust and asset-scope as jointly required and immutable outside of an explicit re-approval UX (do not allow a lightweight "update" call to expand the disclosed asset/account surface for an already-trusted origin).

### Proof of Concept
```js
// 1. User approves origin "evil.example" for solana only:
await connectedOrigins.add({
  origin: 'evil.example',
  name: 'Evil dApp',
  connectedAssetName: 'solana',
  assetNames: ['solana'],
  trusted: true,
})

// 2. Later, the origin itself (via exposed RPC/background API) calls:
await connectedOrigins.updateConnection({
  origin: 'evil.example',
  connectedAssetName: 'ethereum', // asset never granted by the user
})

// 3. The origin queries:
const accounts = await connectedOrigins.getConnectedAccounts({ origin: 'evil.example' })
// => returns ethereum addresses for ALL enabled wallet accounts,
//    even though the user only ever approved sharing solana addresses.

    const connectedAccounts = await this.#connectedAccountsAtom.get()
    const entries = await Promise.all(
      assetNames.map(async (assetName) => {
        const existingAddress = connectedAccounts[walletAccount]?.addresses[assetName]
        if (existingAddress) {
          return [assetName, existingAddress]
        }

        const address = await this.#addressProvider.getDefaultAddress({ assetName, walletAccount })
        return [assetName, address.toString()]
      })
    )

    return Object.fromEntries(entries)
  }

  getConnectedAccounts = async ({ origin }) => {
    const isTrusted = await this.isTrusted({ origin })
    if (!isTrusted) return []

    const value = await this.#getOrigin({ origin })
    const assetNames = [value.connectedAssetName, ...(value.assetNames ?? [])].filter(
      (name, index, ary) => Boolean(name) && ary.indexOf(name) === index
    )

    const activeWalletAccount = await this.#activeWalletAccountAtom.get()
    const accounts = await this.#connectedAccountsAtom.get()

    const connectedAccounts = []
    for (const name of Object.keys(accounts)) {
      if (name === activeWalletAccount) continue
      connectedAccounts.push({ name, addresses: pick(accounts[name].addresses, assetNames) })
    }

    connectedAccounts.unshift({
      name: activeWalletAccount,
      addresses: pick(accounts[activeWalletAccount].addresses, assetNames),
    })

    return connectedAccounts
  }

  updateConnection = async ({ origin, icon, connectedAssetName }) => {
    const value = await this.#getOrigin({ origin })

    if (!value) return

    const attributes = {}

    if (icon) {
      attributes.icon = icon
    }

    if (connectedAssetName) {
      attributes.connectedAssetName = connectedAssetName
    }
