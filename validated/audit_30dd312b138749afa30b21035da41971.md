I'll check the bad-debt cleanup path, which is the closest analog shape (permissionless transition invalidating a gated action).### Title
Permissionless `supply` top-up keeps an insolvent account's collateral above the dust threshold, permanently griefing `clean_bad_debt` — (File: contracts/controller/src/positions/liquidation/mod.rs)

### Summary
The original bug class is a permissionless state transition (`settle`) that can be frontrun against or used to permanently invalidate a needed call (`refund_highest_bidder`). XOXNO Lending has the same shape: the permissionless `clean_bad_debt` path is only callable while an insolvent account's remaining collateral is at or below `BAD_DEBT_USD_THRESHOLD` (5 USD WAD), while `supply` deliberately lets any third party top up supply assets an account already holds (INV-AUTH-03). A griefer can therefore keep an insolvent account forever ineligible for bad-debt cleanup by repeatedly topping up its existing collateral slot, blocking the socialization/write-down the protocol needs to keep its books solvent.

### Finding Description
`clean_bad_debt` is permissionless but gated: it succeeds only when the account's debt exceeds its unweighted collateral **and** collateral is at most `BAD_DEBT_USD_THRESHOLD`, reverting with `CannotCleanBadDebt` (`controller #114`) otherwise. At the same time, `controller::supply` accepts payments from arbitrary callers to a foreign `account_id` provided the hub asset already exists as a supply position on that account — it cannot open a new slot, but it *can* grow an existing one. A liquidated-insolvent account retains its supply positions until cleanup deletes it, so every leftover collateral slot is an open door for a top-up.

The attack:

1. An account ends liquidation rounds with residual debt and tiny leftover collateral ≤ $5 — the exact state `clean_bad_debt` exists for.
2. Before (or whenever) anyone calls `clean_bad_debt`, the griefer calls `supply(caller, account_id, payments)` with a payment just above the $5 threshold into an asset the account already supplies. `supply` skips post-action solvency checks (it is risk-reducing), so it cannot fail on the target's health.
3. The account's unweighted collateral is now > `BAD_DEBT_USD_THRESHOLD`, so `clean_bad_debt` reverts and post-liquidation cleanup skips the account.
4. Each time index accrual/price drift pushes collateral back under the cap, the griefer repeats for a few dollars, indefinitely.

### Impact Explanation
`clean_bad_debt` performs the supply-index write-down that realises the loss on the books. While it is blocked, the market keeps accounting debt and lender supply shares as if fully backed while the underlying cash is gone — interest keeps accruing on phantom debt, utilization and rates are distorted, and late withdrawers hit a cash shortfall the write-down was supposed to expose. That maps to protocol insolvency persisting / temporary freezing of funds (withdrawals of the last suppliers failing) for as long as the griefer keeps funding the attack. The owner-gated `force_socialize_bad_debt` has no dust cap, but it is a timelocked governance path meant for exceptional cases — relying on it converts a permissionless, immediate cleanup into a delayed governance action, which is exactly the "needed call can't execute" harm of the original report.

Note the griefer's top-up partially reduces the shortfall each round (the supplied tokens become real collateral), so the attack costs real money; the harm is the *continued* denial of socialization and accrual distortion, which persists as long as the attacker outbids the dust cap — cheap ($5-scale) per round relative to a large insolvency.

### Likelihood Explanation
Fully permissionless: any EOA can call `controller::supply` for an existing foreign slot with no allowlist, and the trigger state (post-liquidation dust collateral) is a routine outcome of partial liquidations, especially for assets whose prices drift. No privileged access, leaked key, or off-chain component is required. The blocker is only economic: sustained griefing costs ≥ the dust threshold per round, so it is most attractive against large bad-debt accounts where freezing lender withdrawals is valuable (e.g., shorting the asset elsewhere, or sabotage).

### Recommendation
Make cleanup eligibility monotone so a third-party top-up cannot revoke it, e.g.:

- Evaluate `clean_bad_debt` against collateral *excluding* third-party-supplied top-ups received after the account became insolvent, or snapshot the "bad-debt eligible" flag when debt first exceeds collateral and let cleanup proceed while that flag stands; or
- Allow `supply` to a foreign account only while its health factor is ≥ 1 / while it is not in the bad-debt-eligible state (debt > collateral), closing the slot to top-ups once insolvency is established; or
- Have cleanup sweep (seize/write-down) whatever collateral exists at execution time, including top-ups, so topping up never helps the griefer — the added collateral just reduces the socialized amount in the same call.

The third option is simplest: collateral above dust is consumed by the write-down anyway, so gating on a pre-call collateral ceiling serves no purpose other than enabling this DoS.

### Proof of Concept
1. Bootstrap markets USDC (collateral) and ETH (debt). ALICE supplies USDC, borrows ETH; ETH price rises until HF < 1.
2. LIQUIDATOR executes `liquidate` leaving residual ETH debt and ~$3 of USDC collateral (`get_total_collateral_usd(account) < BAD_DEBT_USD_THRESHOLD`, `debt_usd > collateral_usd`).
3. `clean_bad_debt(account_id)` succeeds — confirm via `CannotCleanBadDebt` absence.
4. Rewind: attacker calls `controller::supply(attacker, account_id, [(USDC_key, 6 * 10^decimals)])` — the account already holds a USDC supply slot, so the foreign-slot guard passes and `supply` runs no HF check on the target.
5. `clean_bad_debt(account_id)` now reverts with `CannotCleanBadDebt` (#114); post-liquidation cleanup also skips the account.
6. Advance time until accrual re-qualifies the account, repeat step 4 — the state is indefinitely griefer-controlled.
