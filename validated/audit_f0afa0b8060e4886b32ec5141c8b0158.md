## Analysis Result

The `Payment.sol` "signature replay" bug class — a check that determines a signed request hasn't been used yet, followed by a separate step that marks it used, with no atomicity binding the two — has a direct analog in the Chainlink gateway's HTTP-trigger JWT authentication path.

### Title
JWT replay-guard check-then-record race allows concurrent replay of a single signed HTTP-trigger request - (File: `core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go`)

### Summary
The gateway's `WorkflowMetadataHandler.Authorize` function is meant to guarantee a JWT-authenticated (ECDSA-signed) HTTP trigger request can only be accepted once, using the `jti` claim as a one-time-use nonce. However, the "already used" check and the "mark as used" write are two separate, non-atomic operations, each acquiring its own lock. A narrow window exists in which two concurrent requests carrying the same signed JWT can both pass the replay check before either records usage, letting the same signed request be admitted and dispatched to the DON twice.

### Finding Description
`Authorize` calls `h.jwtCache.isReplay(claims.ID)` and, several lines later (after signer/key lookup), `h.jwtCache.recordUsage(claims.ID)`: [1](#0-0) 

`isReplay` takes an `RLock`, checks map membership, and releases the lock; `recordUsage` separately takes a `Lock` and writes the entry: [2](#0-1) 

Because these are two independent critical sections rather than one atomic "check-and-record" operation (unlike the analogous `vault.RequestReplayGuard.CheckAndRecord`, which performs the lookup and insert under a single lock — [3](#0-2) ), two goroutines racing to authorize the *same* JWT (same `jti`) can both observe `isReplay == false` before either calls `recordUsage`. Both then pass signer/key authorization and are treated as valid, distinct authorizations of the identical signed request.

This is invoked directly from the unprivileged, internet-facing `httpTriggerHandler.HandleUserTriggerRequest` → `authorizeRequest` path, i.e. from client-submitted HTTP trigger requests reaching the gateway: [4](#0-3) [5](#0-4) 

The JWT itself binds to the request digest and carries `jti` specifically "for replay protection," per the intended design documented in `CreateRequestJWT`: [6](#0-5) 

### Impact Explanation
If an unprivileged client (or someone who intercepts/replays a previously-observed valid JWT-signed trigger request while it is still within its short `exp` window) submits it twice concurrently, both submissions can be authorized and forwarded to the DON, resulting in duplicate workflow execution/duplicate job run from a single signed authorization — the same class of impact ("replayed distribution"/duplicate fund movement) described in the report, translated to "duplicate workflow run" in the gateway's domain. This breaks the one-time-use guarantee the `jti`-based replay cache is explicitly designed to provide.

### Likelihood Explanation
The race window is narrow (time between the `RLock` release in `isReplay` and the `Lock` acquisition in `recordUsage`, during which key/workflow lookups occur) but is fully reachable from unprivileged, unauthenticated network input — any client capable of sending two near-simultaneous copies of the same signed request to the gateway HTTP endpoint can attempt to trigger it. No special network position or node compromise is required, and the trigger handler dispatches to nodes fully in parallel per shard, so exploitation only requires ordinary request duplication (e.g., simple client-side concurrency or a retrying proxy), not sophisticated timing control.

### Recommendation
Make the JWT replay check-and-record atomic: hold a single lock across both the membership check and the insert (mirroring `vault.RequestReplayGuard.CheckAndRecord`'s pattern), e.g. add a combined `checkAndRecord(jti string) error` method to `jwtReplayCache` that performs the lookup and insertion under one `Lock()`/`Unlock()` critical section, and call it before proceeding with signer/key authorization in `Authorize`.

### Proof of Concept
1. Client creates one valid signed JWT (`CreateRequestJWT` + ECDSA sign) for a given HTTP trigger request/`jti`.
2. Client fires two goroutines/requests almost simultaneously against the gateway's HTTP trigger endpoint, both carrying the identical JWT.
3. Both requests reach `httpTriggerHandler.authorizeRequest` → `WorkflowMetadataHandler.Authorize` concurrently.
4. Goroutine A calls `isReplay(jti)` → false (lock released). Before A calls `recordUsage(jti)`, goroutine B calls `isReplay(jti)` → also false.
5. Both A and B pass the signer/authorized-key check and proceed to dispatch the trigger request to the DON, resulting in two accepted, DON-forwarded executions from one signed authorization.

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}

func (cache *jwtReplayCache) isReplay(jti string) bool {
	cache.mu.RLock()
	defer cache.mu.RUnlock()

	_, exists := cache.cache[jti]
	return exists
}

func (cache *jwtReplayCache) recordUsage(jti string) {
	cache.mu.Lock()
	defer cache.mu.Unlock()

	cache.cache[jti] = time.Now()
}

func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}

func (h *httpTriggerHandler) authorizeRequest(ctx context.Context, workflowID string, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback) (*gateway_common.AuthorizedKey, error) {
	h.lggr.Debugw("authorizing request", "workflowID", workflowID, "requestID", req.ID)
	key, err := h.workflowMetadataHandler.Authorize(workflowID, req.Auth, req)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInvalidRequest, "Auth failure: "+err.Error(), callback)
		return nil, errors.Join(errors.New("auth failure"), err)
	}
	return key, nil
}
