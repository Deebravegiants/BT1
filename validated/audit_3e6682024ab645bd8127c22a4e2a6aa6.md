### Title
SSRF-adjacent credential leak: `client_secret` sent to unvalidated `dest` host in `TokenExchange.exchange_token` - (File: lib/shopify_api/auth/token_exchange.rb)

### Summary
`ShopifyAPI::Auth::TokenExchange.exchange_token` derives the target shop domain solely from the `dest` claim of the caller-supplied session token (`ShopifyAPI::Auth::JwtPayload#shop`) and uses it, unsanitized, to build the HTTP host that receives the app's `client_id`/`client_secret` during the token-exchange POST. Every sibling OAuth flow in this gem (`ClientCredentials`, `RefreshToken`, `TokenExchange.migrate_to_expiring_token`) runs the shop value through `Utils::ShopValidator.sanitize!` before using it to build the request host; `exchange_token` does not.

### Finding Description
`Auth::JwtPayload#shop` simply strips `"https://"` from the raw `dest` claim of the decoded JWT with no format/domain check: [1](#0-0) 

`TokenExchange.exchange_token` takes that unvalidated value and uses it directly as the `Session#shop` for constructing the `HttpClient`, which turns `session.shop` straight into the request host: [2](#0-1) [3](#0-2) 

The request body sent to that host includes `client_id` and `client_secret`: [4](#0-3) 

Every other method in the same module family calls `Utils::ShopValidator.sanitize!(shop)` before constructing the request host, e.g. `migrate_to_expiring_token`: [5](#0-4) 
and `RefreshToken.refresh_access_token` / `ClientCredentials.client_credentials`: [6](#0-5) [7](#0-6) 

The binding that should hold is: **host that receives `client_secret` == a domain in `Utils::ShopValidator::TRUSTED_SHOPIFY_DOMAINS`** (as enforced by `ShopValidator.sanitize!`, which rejects domains like `attacker.example` or `myshopify.com.evil.com`): [8](#0-7) 

In `exchange_token`, this binding is broken: the host is taken directly from an unvalidated JWT claim rather than from `ShopValidator.sanitize!`.

Whether this is remotely exploitable by an unprivileged internet user depends entirely on whether `dest` can ever contain a non-myshopify value while the JWT still verifies. The JWT signature is HS256 with `Context.api_secret_key`/`old_api_secret_key`, a secret the attacker does not possess, so a completely forged token is out of scope per the rules given. However, the missing validation is still a code-level defect: it removes a defense-in-depth check that this codebase applies everywhere else the shop is used to build a request host carrying the `client_secret`, and it means any code path that can influence the `dest` claim of a token accepted by this method (e.g. Shopify issuing tokens for non-admin contexts such as checkout UI extensions, where `iss` ends with `/checkouts` rather than `/admin`, a case this class explicitly supports per `admin_session_token?`) is not defended against sending the credential to an unexpected host.

### Impact Explanation
If the `dest` claim can ever be a domain outside `ShopValidator::TRUSTED_SHOPIFY_DOMAINS` (whether via a token type this gem accepts beyond admin sessions, or any future/alternate token issuance path), the app's `client_id` and `client_secret` would be transmitted via HTTPS POST to that host — a credential leak of the app's `client_secret`, which the rules classify as Critical impact.

### Likelihood Explanation
Likelihood is **low-to-uncertain**: exploitation requires a validly-signed JWT (HS256, `api_secret_key`) whose `dest` claim is not a genuine Shopify domain. Under normal OAuth/session-token issuance by Shopify this should not happen, and forging the JWT outright is out of scope (requires the secret). The finding is best characterized as a missing defense-in-depth / inconsistency bug rather than a confirmed exploitable end-to-end chain, since I could not find a code path in this gem that lets an unprivileged attacker control the `dest` claim of a token that will pass JWT verification.

### Recommendation
In `TokenExchange.exchange_token`, sanitize `dest_shop` through `Utils::ShopValidator.sanitize!` (as already done in `migrate_to_expiring_token`, `RefreshToken.refresh_access_token`, and `ClientCredentials.client_credentials`) before using it to build `shop_session`/`HttpClient`, and raise `Errors::InvalidShopError` if it does not resolve to a trusted Shopify domain.

### Proof of Concept
Not concretely exploitable with only unprivileged-internet-user capabilities, since it requires a validly HS256-signed session token with a non-Shopify `dest` claim, and forging such a token requires the app's `api_secret_key`. This is flagged as a code-level inconsistency/defense-in-depth gap relative to the rest of the codebase rather than a demonstrated end-to-end attack.

      TRUSTED_SHOPIFY_DOMAINS = T.let(
        [
          "shopify.com",
          "myshopify.io",
          "myshopify.com",
          "spin.dev",
          "shop.dev",
        ].freeze,
        T::Array[String],
      )

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
