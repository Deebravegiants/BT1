Audit Report

## Title
GET /v2/external_initiators exposes OutgoingToken/AccessKey credentials to view-only users due to missing role gate - ([File: core/web/router.go])

## Summary
`core/web/router.go` registers `GET /v2/external_initiators` with only the base `Authenticate` middleware, while `POST`/`DELETE` on the same resource require `auth.RequiresEditRole`. The `Index` handler returns `presenters.ExternalInitiatorResource`, which includes the plaintext `OutgoingToken` and `AccessKey` fields for every stored external initiator, so any authenticated user with the lowest-privilege `view` role can read these outbound-webhook credentials.

## Finding Description
In `core/web/router.go` (L263-266), the external initiator routes are:
```go
eia := ExternalInitiatorsController{app}
authv2.GET("/external_initiators", paginatedRequest(eia.Index))
authv2.POST("/external_initiators", auth.RequiresEditRole(eia.Create))
authv2.DELETE("/external_initiators/:Name", auth.RequiresEditRole(eia.Destroy))
```
Only `authv2`'s group-level `auth.Authenticate` (token or session) applies to `GET`, with no role check, whereas `Create`/`Destroy` explicitly require the `edit` role. `ExternalInitiatorsController.Index` (`core/web/external_initiators_controller.go` L50-59) fetches all external initiators from the ORM and maps each to `presenters.NewExternalInitiatorResource`, which copies `AccessKey` and `OutgoingToken` verbatim into JSON fields `accessKey` and `outgoingToken` (`core/web/presenters/external_initiators.go` L57-77). This differs from the `Create` response, which uses `ExternalInitiatorAuthentication` — a one-time reveal of secrets at creation time only. The RBAC test table in `core/web/auth/auth_test.go` (L224-226) explicitly documents `viewOnlyAllowed=true` for `GET /v2/external_initiators` versus `false` for the write verbs, confirming this is the actual, currently-tested behavior rather than a hypothetical gap.

## Impact Explanation
`OutgoingToken` (and `AccessKey`) are secrets the node uses to authenticate its outbound calls to configured external initiator webhook endpoints. A user provisioned with only `sessions.UserRoleView` — the lowest privilege tier intended for read-only access — can retrieve these secrets for all configured external initiators via a single authenticated GET request, enabling impersonation of the node toward those external systems. This is a concrete secret-exfiltration / authorization-boundary issue, not merely elevated read access to non-sensitive metadata.

## Likelihood Explanation
Exploitation requires only a valid `view`-role API token or session — no admin/edit privilege, no chained exploit, no timing window. The RBAC test suite treats this as expected/tested behavior, so it is reliably reproducible in any deployment using role-based accounts, including OIDC/LDAP-mapped view-only users.

## Recommendation
Gate `GET /v2/external_initiators` with `auth.RequiresEditRole` to match the sensitivity of the data and consistency with `Create`/`Destroy`, or remove `OutgoingToken`/`AccessKey` from `ExternalInitiatorResource` and only expose them once via `ExternalInitiatorAuthentication` at creation time.

## Proof of Concept
1. As an edit/admin user, `POST /v2/external_initiators` to create an initiator (secrets returned once via `ExternalInitiatorAuthentication`).
2. Authenticate as a `UserRoleView` user (token or session).
3. Call `GET /v2/external_initiators`.
4. Observe the JSON response contains `outgoingToken` and `accessKey` for the initiator created in step 1, confirmed by the existing RBAC test case `{"GET", "/v2/external_initiators", true, true, true}` in `core/web/auth/auth_test.go` (L224), meaning no `403`/`401` is enforced for view-only role. func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}

}

// NewExternalInitiatorAuthentication creates an instance of ExternalInitiatorAuthentication.
func NewExternalInitiatorAuthentication(
	ei bridges.ExternalInitiator,
	eia auth.Token,
) *ExternalInitiatorAuthentication {
	var result = &ExternalInitiatorAuthentication{
		Name:           ei.Name,
		AccessKey:      ei.AccessKey,
		Secret:         eia.Secret,
		OutgoingToken:  ei.OutgoingToken,
		OutgoingSecret: ei.OutgoingSecret,
	}
	if ei.URL != nil {
		result.URL = *ei.URL
	}
	return result
}
