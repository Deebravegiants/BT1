### Title
Unbounded aggregate debt valuation can permanently freeze a lending market - ([File: common/src/rates/index.rs])

### Summary
Interest accrual computes aggregate RAY-denominated debt as `borrowed * borrow_index` before enforcing the borrow-index cap. When the product exceeds `i128::MAX`, accrual panics with `MathOverflow`. Because every affected market operation syncs interest before accounting, the crossing permanently disables repayment, withdrawal, liquidation, bad-debt cleanup, and recapitalization for that market. [1](#0-0) [2](#0-1) 

### Finding Description
`calculate_supplier_rewards` multiplies total scaled debt by both the old and new borrow indexes:

- `old_total_debt = borrowed * old_borrow_index`
- `new_total_debt = borrowed * new_borrow_index`
- `accrued_interest = new_total_debt - old_total_debt` [1](#0-0) 

`Ray::mul` ultimately performs checked `i128` fixed-point multiplication and panics when the represented result cannot fit in `i128`. [3](#0-2) [4](#0-3) 

Although `update_borrow_index` caps the index itself at `MAX_BORROW_INDEX_RAY`, that cap is applied only after `old_index * interest_factor`; it does not cap the separate aggregate value `borrowed * new_borrow_index`. [5](#0-4) 

The vulnerable sequence is reachable through the permissionless controller entrypoint:

```rust
update_indexes(caller, vec![debt_hub_asset])
```

The controller authorizes the caller and forwards the request to the pool’s owner-only `update_indexes`; authorization does not make the caller privileged. [6](#0-5) [7](#0-6) [8](#0-7) 

The pool loads each market and calls `interest::global_sync` before committing. `global_sync` performs the accrual and calls `accrue_step`, which reaches `calculate_supplier_rewards`. [9](#0-8) [10](#0-9) 

Once `borrowed * new_borrow_index > i128::MAX`, the transaction aborts before `mark_accrued` runs. Repeating the call later cannot skip the overflowing interval because `last_timestamp` remains behind the current ledger time. [11](#0-10) 

### Impact Explanation
This is a permanent freezing-of-funds condition for the affected market.

Every ordinary pool leg first calls `synced_market`, and `synced_market` unconditionally calls `global_sync`. [2](#0-1) 

Consequently, once the aggregate debt valuation overflows:

- `repay` reverts before `resolve_repay`, debt burning, or cash crediting. [12](#0-11) 
- `withdraw` reverts before supply-share burning or cash withdrawal. [13](#0-12) 
- liquidation seizure reverts before debt socialization or collateral absorption. [14](#0-13) 
- `recapitalize` reverts before it can measure or cover the backing shortfall. [15](#0-14) 
- direct `update_indexes` reverts while attempting the same accrual. [16](#0-15) 

Suppliers cannot recover underlying assets, borrowers cannot repay or unlock collateral, and liquidators cannot reduce the insolvent debt. The repository’s long-horizon test demonstrates this exact end state: accrual fails with `MATH_OVERFLOW`, the borrow index remains below `MAX_BORROW_INDEX_RAY`, and subsequent withdrawal and repayment attempts fail with the same error. [17](#0-16) 

### Likelihood Explanation
Likelihood is low but nonzero because triggering the condition requires an exceptionally large admitted market and enough elapsed interest for `scaled_debt * borrow_index` to exceed the `i128` domain.

A single unprivileged account can construct the state using only public paths:

1. Supply a very large amount of the debt asset.
2. Supply sufficient collateral in another listed market.
3. Borrow a large fraction of the debt market.
4. Wait for interest to increase the aggregate RAY-valued debt beyond `i128::MAX`.
5. Call `update_indexes(caller, vec![debt_hub_asset])`. [18](#0-17) [6](#0-5) 

The trigger does not require oracle manipulation, leaked keys, privileged calls, malformed storage, or an external service failure. It does require caps and available token liquidity large enough to admit the position. For an 18-decimal market, the repository’s test uses 1 billion whole tokens—`10^36` RAY before interest—so an index above approximately 170× approaches the `i128::MAX` boundary. [19](#0-18) 

The protocol documentation acknowledges that aggregate accrual values can overflow before the index ceiling and block repayment or withdrawal, but that documented limit does not prevent the permanent denial of all recovery paths once crossed. [20](#0-19) 

### Recommendation
Do not require the full aggregate debt value to fit in `i128` merely to advance indexes.

Recommended changes:

- Compute `new_total_debt - old_total_debt` algebraically as `borrowed * (new_index - old_index)` where mathematically equivalent, using widened arithmetic for the intermediate product.
- Alternatively perform aggregate debt calculations in `I256` and return structured saturation/failure data rather than panicking during mandatory pre-operation accrual.
- Bound admitted scaled supply and debt so `scaled * MAX_BORROW_INDEX_RAY` and `scaled * MAX_SUPPLY_INDEX_RAY` cannot exceed `i128::MAX`, rather than bounding only the token input.
- Add a recovery path that can advance `last_timestamp`, cap indexes, or isolate the overflowing market without requiring the overflowing aggregate valuation.
- Add regression coverage proving that repayment, withdrawal, liquidation seizure, and recapitalization remain executable after the index cap or aggregate-value boundary is reached. [21](#0-20) [22](#0-21) 

### Proof of Concept
The repository already contains a harness test for this condition. Its relevant sequence is: [23](#0-22) 

```text
1. Create an 18-decimal debt market and a collateral market.
2. Raise the market caps.
3. BOB supplies 1_000_000_000 * 10^18 base units of BIG18.
4. ALICE supplies sufficient collateral.
5. ALICE borrows 98% of BIG18.
6. Advance ledger time repeatedly.
7. Any caller invokes:
   update_indexes(caller, [HubAssetKey { hub_id, asset: BIG18 }])
8. Accrual fails with MathOverflow before the borrow-index cap engages.
9. withdraw(BOB, ..., BIG18, 1) fails with MathOverflow.
10. repay(ALICE, ..., BIG18, 1) fails with MathOverflow.
```

The panic occurs because the accrual calculates `borrowed * new_borrow_index` over aggregate scaled debt that is already near `10^36`; a sufficiently grown index pushes the intermediate represented value past `i128::MAX`. The stored `last_timestamp` is not advanced on panic, so all later operations repeat the same failing accrual. [24](#0-23) [2](#0-1)

/// Applies `interest_factor` to `old_index` to produce the new borrow index,
/// capped at `MAX_BORROW_INDEX_RAY`.
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}

/// Grows `old_index` by distributing `rewards_increase` over the total value
/// currently supplied (`supplied * old_index`). The division rounds down.
///
/// Returns `old_index` unchanged if `supplied` or `rewards_increase` is zero,
/// or if the total supplied value is zero. Clamps the result between
/// `old_index` (itself capped at `MAX_SUPPLY_INDEX_RAY`) and
/// `MAX_SUPPLY_INDEX_RAY`, so the returned index never decreases and never
/// exceeds the cap.
pub fn update_supply_index(env: &Env, supplied: Ray, old_index: Ray, rewards_increase: Ray) -> Ray {
    if supplied == Ray::ZERO || rewards_increase == Ray::ZERO {
        return old_index;
    }

    let total_supplied_value = supplied.mul(env, old_index);

    if total_supplied_value == Ray::ZERO {
        return old_index;
    }

    let new_value = total_supplied_value.checked_add(env, rewards_increase);
    let grown = fp_core::mul_div_floor_saturating(env, new_value.raw(), RAY, supplied.raw());

    let bounded_old = old_index.raw().min(MAX_SUPPLY_INDEX_RAY);
    Ray::from(grown.min(MAX_SUPPLY_INDEX_RAY).max(bounded_old))
```

pub fn calculate_supplier_rewards(
    env: &Env,
    params: &MarketParams,
    borrowed: Ray,
    new_borrow_index: Ray,
    old_borrow_index: Ray,
) -> (Ray, Ray) {
    let old_total_debt = borrowed.mul(env, old_borrow_index);
    let new_total_debt = borrowed.mul(env, new_borrow_index);

    let accrued_interest = new_total_debt.checked_sub(env, old_total_debt);

    let protocol_fee = params.reserve_factor.apply_to_ray(env, accrued_interest);
    let supplier_rewards = accrued_interest.checked_sub(env, protocol_fee);

    (supplier_rewards, protocol_fee)
}

/// Converts a Ray-denominated `fee` into scaled supply-index shares
/// (`fee / supply_index`), floor-rounded and saturating on overflow. Caps the
/// result so that adding it to `supplied` cannot overflow `i128::MAX`.
pub fn protocol_fee_shares(env: &Env, fee: Ray, supply_index: Ray, supplied: Ray) -> Ray {
    let raw = fp_core::mul_div_floor_saturating(env, fee.raw(), RAY, supply_index.raw());

    let headroom = i128::MAX.saturating_sub(supplied.raw());
    Ray::from(raw.min(headroom))
}

/// Computes `x * y / d` rounded half up. Requires `x >= 0`, `y >= 0`, and `d > 0`; a
/// `debug_assert` checks this in debug builds. Panics with `GenericError::DivisionByZero` if
/// `d == 0`, and with `GenericError::MathOverflow` if any other precondition is violated or if
/// the result does not fit in `i128`.
pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {

    );
    try_mul_div_half_up(env, x, y, d)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))

/// Accrues borrow/supply indexes from `last_timestamp` to the cache's current time.
///
/// No-op when no time has elapsed. Splits long gaps into max-sized compound
/// windows, then sets `last_timestamp` to `current_timestamp`.
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}
```

/// Accrues interest, resolves the repay amount into burned debt shares and
/// overpayment, burns the shares, and credits the net repay to cash without
/// transferring the overpayment refund. Panics if a positive net repay would
/// burn zero scaled shares.
pub(crate) fn accounting(env: &Env, action: &PoolAction) -> RepayOutcome {
    let (mut cache, position) = ops::load_leg(env, action);
    let amount = action.amount;

    let (burned, overpayment) = cache.resolve_repay(amount, position);
    let net_repay = amount
        .checked_sub(overpayment)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));
    assert_with_error!(
        env,
        net_repay == 0 || burned.raw() > 0,
        GenericError::RepayRoundsToZeroShares
    );

    let position = position.checked_sub(env, burned);
    cache.burn_debt(burned);

    cache.credit_cash(net_repay);

    let snapshot = cache.commit();

/// Runs withdraw accounting without transferring tokens.
///
/// Resolves full or partial close, burns shares, optionally withholds the
/// liquidation fee, and gates the final state before debiting cash.
pub(crate) fn accounting(
    env: &Env,
    is_liquidation: bool,
    entry: &PoolWithdrawEntry,
) -> WithdrawOutcome {
    require_nonneg_amount(env, entry.protocol_fee);
    let (mut cache, position) = ops::load_leg(env, &entry.action);

    let (burned, gross_amount) = resolve_close_or_partial(&cache, entry.action.amount, position);
    // Burn first: `protocol_fee_shares` caps the fee mint at `i128::MAX - supplied`.
    let remaining = burn_position(env, &mut cache, position, burned);
    let net_transfer = withhold_liquidation_fee(
        env,
        &mut cache,
        gross_amount,
        is_liquidation,
        entry.protocol_fee,
    );

    // A footprint-only close must not add a utilization gate to same-market
    // net settlement: it burns no shares and moves no cash.
    let empty_close = position.raw() == 0 && entry.action.amount == i128::MAX;
    gate_and_debit(env, &mut cache, net_transfer, is_liquidation || empty_close);

    let snapshot = cache.commit();
    let mutation = cache.position_mutation(remaining, gross_amount);

/// reclassifying supply as revenue depending on `entry.side`, and returns the
