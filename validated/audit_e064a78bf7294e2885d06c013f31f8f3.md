## Analog Found

### Title
Request-ID collision from an unauthenticated caller can block another user's in-flight Confidential Relay request - (File: `core/services/gateway/handlers/confidentialrelay/handler.go`)

### Summary
The external report describes a resource-ID collision: an unprivileged actor can mint a token with an ID that intersects a range another party expects to use exclusively, causing the victim's transaction (`buyNFT`) to fail. The `NFTMintSaleMultiple` contract never partitions the ID namespace per caller, so any external actor sharing the same ID space can disrupt another party's operation.

The Chainlink Gateway's Confidential Relay handler has the same class of bug: the in-flight request table is keyed **only** by the caller-supplied `req.ID` string, with no per-caller/per-owner namespacing, even though the gateway is internet-facing and receives `HandleJSONRPCUserMessage` calls from external, unprivileged callers.

### Finding Description
`handler.newActiveRequest` inserts a pending request into a single shared map keyed solely by the raw request ID supplied in the message: [1](#0-0) 

`HandleJSONRPCUserMessage` — the entry point invoked for every user message routed to this handler through `multiHandler.HandleJSONRPCUserMessage` — performs only length/emptiness validation of `req.ID` before calling `newActiveRequest`; it does not bind the ID to the caller's identity, workflow, or owner: [2](#0-1) [3](#0-2) 

This is in stark contrast to the sibling Vault gateway path, which explicitly re-derives the request ID by prefixing it with the *authorized owner* precisely to prevent cross-owner ID collisions: [4](#0-3) 

Because the confidential relay handler skips this owner-scoping step, `h.activeRequests[req.ID]` is a single global namespace shared by every caller of the gateway. If two different, mutually untrusting callers (e.g., two different workflow enclaves, or an attacker crafting a raw JSON-RPC message) submit a `MethodSecretsGet` or `MethodCapabilityExec` request using the same `req.ID` while the first is still in flight, `newActiveRequest` rejects the second request outright:

```
if h.activeRequests[req.ID] != nil {
    return nil, errors.New("request ID already exists: " + req.ID)
}
```

The test suite confirms this collision behavior is the actual code path (not merely a benign duplicate-submission guard for the *same* caller): [5](#0-4) 

Exactly like `NFTMintSaleMultiple`, where the contract has no mechanism to prevent an unrelated actor from claiming an ID inside another party's reserved range, this handler has no mechanism to prevent one caller's chosen `req.ID` from colliding with, and therefore blocking, a concurrent, unrelated caller's request.

### Impact Explanation
An unprivileged, unauthenticated caller who can reach the gateway's JSON-RPC user-message endpoint (the gateway is designed to receive requests from external nodes/workflows without per-request-ID authorization in this handler) can deny service to another party's Confidential Relay request simply by guessing or observing a request ID and re-submitting a message with the same ID while the original is still pending. The victim's legitimate operation (a secrets fetch or capability execution routed through the relay DON) fails with `request ID already exists`, exactly mirroring the disruption pattern in the original report where a legitimate `buyNFT` call reverts because of an ID chosen by an unrelated party.

### Likelihood Explanation
Request IDs for this handler are visible in the JSON-RPC envelope (`req.ID`) and are not derived from any secret; the handler's own comments note IDs "change per retry," implying they are often simple, low-entropy, or predictable values generated by legitimate clients. Any party able to send `HandleJSONRPCUserMessage` traffic to the gateway for `MethodSecretsGet`/`MethodCapabilityExec` can attempt an ID collision without needing to compromise any node, key, or credential, making this a low-effort, network-reachable DoS.

### Recommendation
Namespace `activeRequests` by both the caller's authenticated identity (or connection/session identifier) and the caller-supplied request ID — mirroring the `authorizedOwner + separator + requestID` scheme already used in `core/capabilities/vault/gateway_vault_request_processor.go` — so that one caller's chosen ID cannot collide with, and block, another caller's concurrent request.

### Proof of Concept
1. Caller A sends a `MethodCapabilityExec` (or `MethodSecretsGet`) JSON-RPC request to the gateway with `id = "req-1"`; the request is accepted and remains pending in `h.activeRequests["req-1"]`.
2. Before Caller A's request completes/times out, Caller B (an unrelated, unprivileged party) sends its own `MethodCapabilityExec` request also using `id = "req-1"`.
3. `newActiveRequest` finds `h.activeRequests["req-1"] != nil` and returns `"request ID already exists: req-1"`, so Caller B's request is rejected — this is the intended “duplicate” rejection but is trivially triggerable cross-caller. This is directly reproduced by `TestConfidentialRelayHandler_DuplicateRequestID`, which simply issues two `HandleJSONRPCUserMessage` calls with the same `ID` and asserts the second is rejected: [5](#0-4) . Nothing in the handler distinguishes whether the second call originates from the same caller as the first, so a malicious actor can use this to grief a victim whose ID they can predict/observe.

func (h *handler) HandleJSONRPCUserMessage(ctx context.Context, req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) error {
	if req.ID == "" {
		return errors.New("request ID cannot be empty")
	}
	if len(req.ID) > 200 {
		return errors.New("request ID is too long: " + strconv.Itoa(len(req.ID)) + ". max is 200 characters")
	}

	labels := h.extractRequestLabels(req)
	l := h.requestLogger(req, labels)
	l.Debugw("handling confidential relay request", "nodes", len(h.donConfig.Members), "f", h.donConfig.F)

	ar, err := h.newActiveRequest(req, labels, callback)
	if err != nil {
		return err
	}

	return h.fanOutToNodes(ctx, l, ar)
}

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], labels requestLabels, callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID, "executionID", labels.ExecutionID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		labels:    labels,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}
```

func (p *GatewayVaultRequestProcessor) authorizeAndStamp(
	ctx context.Context,
	req *jsonrpc.Request[json.RawMessage],
	stamp func(prefixedRequestID string) error,
) (*AuthorizedGatewayVaultRequest, error) {
	incomingOwner := ""
	if idx := strings.Index(req.ID, vaulttypes.RequestIDSeparator); idx != -1 {
		incomingOwner = req.ID[:idx]
	}

	p.lggr.Debugw("authorizing gateway vault request", "method", req.Method, "requestID", req.ID)
	authResult, err := p.authorizer.AuthorizeRequest(ctx, *req)
	if err != nil {
		authErr := fmt.Errorf("request not authorized: %w", err)
		p.lggr.Errorw("gateway vault request authorization failed", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "", "incomingOwner", incomingOwner, "error", authErr)
		return nil, authErr
	}

	originalRequestID := req.ID
	authorizedOwner := authResult.AuthorizedOwner()
	prefixedRequestID := authorizedOwner + vaulttypes.RequestIDSeparator + originalRequestID
	req.ID = prefixedRequestID

	if err := stamp(prefixedRequestID); err != nil {
		p.lggr.Errorw("failed to stamp authorized request params", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, fmt.Errorf("failed to stamp authorized request params: %w", err)
	}

	p.lggr.Debugw("authorized gateway vault request", "method", req.Method, "requestID", req.ID, "owner", authorizedOwner, "orgID", authResult.OrgID(), "workflowOwner", authResult.WorkflowOwner())
	return &AuthorizedGatewayVaultRequest{
		Req:        *req,
		AuthResult: authResult,
	}, nil
```

func TestConfidentialRelayHandler_DuplicateRequestID(t *testing.T) {
	t.Parallel()
	h, cb, don, _ := setupHandler(t, 4)
	don.On("SendToNode", mock.Anything, mock.Anything, mock.Anything).Return(nil)

	params := json.RawMessage(`{"workflow_id":"wf1"}`)
	req := jsonrpc.Request[json.RawMessage]{
		ID:     "req-dup",
		Method: MethodCapabilityExec,
		Params: &params,
	}

	err := h.HandleJSONRPCUserMessage(t.Context(), req, cb)
	require.NoError(t, err)

	cb2 := common.NewCallback()
	err = h.HandleJSONRPCUserMessage(t.Context(), req, cb2)
	require.ErrorContains(t, err, "request ID already exists")
}
