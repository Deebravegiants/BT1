Confirmed: `lib/shopify_api/auth/oauth.rb`'s `begin_auth` never calls `ShopValidator.sanitize!` on the `shop:` parameter, unlike `token_exchange.rb#migrate_to_expiring_token`, which does validate `shop` via `ShopValidator.sanitize!` before building `auth_base_uri`/request host [1](#0-0) . This means `begin_auth` builds the OAuth authorize redirect URL directly from caller-supplied `shop` text without confirming it is a trusted `*.myshopify.com`/`myshopify.io`/etc. domain [2](#0-1) , whereas `TokenExchange.migrate_to_expiring_token` explicitly guards the analogous call with `Utils::ShopValidator.sanitize!(shop)` [3](#0-2) .

### Title
Unvalidated `shop` parameter in `Oauth.begin_auth` enables forced OAuth completion against attacker-controlled host - (File: `lib/shopify_api/auth/oauth.rb`)

### Summary
`ShopifyAPI::Auth::Oauth.begin_auth` builds the `/oauth/authorize` redirect URL by directly interpolating the caller-supplied `shop` string into `auth_base_uri(shop)`, without ever routing it through `Utils::ShopValidator.sanitize!` the way other credential-bearing flows in this gem do.

### Finding Description
`begin_auth` accepts `shop:` and calls the private helper `auth_base_uri(shop)`, which returns `"https://#{shop}/admin"` (or a dev-server variant) with no format check [2](#0-1) . The resulting `auth_route` embeds the app's `client_id` and requested `scope` in the query string sent to that host [4](#0-3) .

Contrast this with `TokenExchange.migrate_to_expiring_token`, which treats `shop` as attacker-influenceable input and validates it before using it to construct the request host: `validated_shop = Utils::ShopValidator.sanitize!(shop)` [3](#0-2) . `ShopValidator.sanitize!` enforces that the host resolves to one of `TRUSTED_SHOPIFY_DOMAINS` (`shopify.com`, `myshopify.io`, `myshopify.com`, `spin.dev`, `shop.dev`) or the configured `myshopify_domain` [5](#0-4) . `begin_auth` has no equivalent check, so the identity binding "the host that receives the OAuth authorize request and later the redirected code" is never checked against "a trusted Shopify domain," even though the sibling `TokenExchange` code path treats this exact binding as security-relevant.

### Impact Explanation
If a host application passes through a user- or query-string-controlled `shop` value to `begin_auth` (a common integration pattern, since `shop` is typically taken from the initial login request), an attacker can supply a non-Shopify host. The generated `auth_route` will point the browser at `https://attacker-controlled-host/admin/oauth/authorize?...&client_id=<app client id>&scope=<app scope>&state=<nonce>&redirect_uri=<app redirect>`. This can be used to leak the app's `client_id`/scope pairing and nonce/state to an attacker-controlled endpoint, and to run phishing/forced-OAuth-completion style flows where the victim is misdirected to a look-alike domain instead of real Shopify, undermining the OAuth begin step's implicit trust boundary. This aligns with the "session fixation or forced OAuth completion" High-impact category, since the state/nonce and redirect flow can be steered off the legitimate `*.myshopify.com` domain.

### Likelihood Explanation
Exploitability depends entirely on whether the host application forwards untrusted input into `begin_auth`'s `shop:` parameter without its own validation — this gem provides no such validation for this specific entry point despite providing it in the closely related `migrate_to_expiring_token` method, which is the inconsistency that makes this a code defect rather than purely a caller mistake. Because the risk is conditioned on host-application input handling and no example in the docs shows validating `shop` before `begin_auth`, likelihood is moderate.

### Recommendation
Call `Utils::ShopValidator.sanitize!(shop)` (or `sanitize_shop_domain`) at the top of `Oauth.begin_auth`, mirroring the guard already present in `TokenExchange.migrate_to_expiring_token`, before using `shop` in `auth_base_uri`.

### Proof of Concept
1. Configure `ShopifyAPI::Context` normally.
2. Call `ShopifyAPI::Auth::Oauth.begin_auth(shop: "evil.example.com", redirect_path: "/auth/callback")`.
3. Observe the returned `auth_route` is `"https://evil.example.com/admin/oauth/authorize?client_id=...&scope=...&redirect_uri=...&state=..."`, i.e., the app's `client_id` and scope are sent to a non-Shopify domain instead of raising `Errors::InvalidShopError` (as `TokenExchange.migrate_to_expiring_token` does for the same kind of input, per `test_migrate_to_expiring_token_rejects_non_shopify_domain`) [6](#0-5) .

        [
          "shopify.com",
          "myshopify.io",
          "myshopify.com",
          "spin.dev",
          "shop.dev",
        ].freeze,
        T::Array[String],
      )

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
