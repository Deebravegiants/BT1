### Title
Route-selected venue can abuse the caller’s signed authorization tree to steal unrelated wallet tokens - ([File: contracts/swap-aggregator/src/venues/mod.rs](contracts/swap-aggregator/src/venues/mod.rs))

### Summary
Controller strategy routes can name an arbitrary venue contract, and a malicious venue invoked below `caller.require_auth()` can place an unrelated `token.transfer(caller, attacker, amount)` inside the caller’s simulated authorization tree. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`swap_collateral` requires caller authorization, loads the caller’s account, withdraws collateral into controller custody, and invokes `swap_tokens`. [4](#0-3)  `swap_tokens` authorizes only the exact controller-to-router input transfer and then executes the caller-supplied route through `router.execute_strategy`. [5](#0-4)  The router derives each hop’s `pool`, `token_in`, and `token_out` directly from the payload and dispatches it without checking that `pool` is a known venue deployment. [1](#0-0) [6](#0-5)  For a Soroswap-shaped hop, the router calls the payload-selected pool’s `get_reserves` and `swap` functions. [7](#0-6) 

Because that malicious contract executes below the caller-authorized root, its `token.transfer(victim, attacker, amount)` becomes a child invocation attributed to the victim’s authorization. [8](#0-7)  The harness demonstrates that an honest root-only signature rejects the transfer, while signing the simulation-produced poisoned tree authorizes it and drains the unrelated wallet token. [9](#0-8) 

### Impact Explanation
A malicious route can make a normal-looking controller strategy transaction steal arbitrary unrelated token balances from the signer’s wallet, not merely the routed collateral or debt proceeds. [10](#0-9)  The measured router checks still pass if the malicious pool retains the routed input and sends sufficient output from attacker-controlled liquidity, because `dispatch_hop` verifies only the router’s token-in decrease and positive token-out increase. [11](#0-10) 

### Likelihood Explanation
The attacker needs to get the victim to submit a route containing the malicious pool and sign the authorization tree returned by simulation. [12](#0-11)  No privileged role, key disclosure, upgrade, oracle manipulation, or protocol insolvency prerequisite is needed; the deployed venue contract and crafted route bytes are sufficient. [13](#0-12)  The same hazard applies to every user-facing controller strategy that accepts route bytes, including `multiply`, `swap_debt`, `swap_collateral`, and `repay_debt_with_collateral`. [14](#0-13) [15](#0-14) [16](#0-15) 

### Recommendation
Constrain each route hop to an allowlisted pool deployment for its selected venue, or otherwise bind the route to a registry of validated venue contracts before dispatch. [17](#0-16)  Clients should also reject any simulated authorization tree containing children beyond the expected controller operation and protocol token pull, but contract-side venue allowlisting is required to make this safe by construction. [18](#0-17) 

### Proof of Concept
1. Deploy a contract that exposes the selected venue’s expected functions, such as `get_reserves` and `swap`, and whose `swap` additionally executes `wallet_token.transfer(victim, attacker, victim_balance)`. [19](#0-18) 
2. Craft `swap` bytes containing that contract as the hop pool, with a positive minimum output and enough attacker-funded `token_out` to satisfy the router’s measured-output checks. [11](#0-10) 
3. Have the victim call `Controller::swap_collateral(caller=victim, account_id=victim_account, current=USDC_market, amount=swap_amount, new=ETH_market, swap=malicious_route)`; the controller withdraws the collateral and calls `swap_tokens`. [20](#0-19) 
4. `swap_tokens` authorizes only the exact controller input transfer, but the router invokes the malicious pool address supplied by the route. [21](#0-20) [17](#0-16) 
5. Simulation records the malicious wallet-token transfer as a child of the victim’s `swap_collateral` authorization; signing that tree drains the wallet token while the swap still succeeds and deposits fair output. [22](#0-21) 
6. The harness confirms the honest tree rejects the theft and that the poisoned simulation tree authorizes it. [9](#0-8)

fn enforced_auth_moves_the_wallet_token_only_when_the_signed_tree_lists_the_rogue_transfer() {
    let s = Scene::new();

    // Control: a pool that touches nothing passes with the honest root-only tree.
    let benign = s.route_through_pool_stealing(0);
    s.try_swap_with_signed_tree(&benign, &[])
        .expect("the honest tree authorizes an honest route");
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);

    // Rogue pool, honest tree: the host refuses the transfer and the whole call rolls back.
    s.t.env.mock_all_auths_allowing_non_root_auth();
    let rogue = s.route_through_pool_stealing(WALLET_BALANCE);
    let usdc_before = s.t.supply_balance_raw(ALICE, "USDC");
    let refused = s
        .try_swap_with_signed_tree(&rogue, &[])
        .expect_err("a transfer outside the signed tree is unauthorized");
    std::println!("rogue transfer under the honest tree = {refused:?}");
    assert!(
        refused.is_type(ScErrorType::Auth) || refused.is_type(ScErrorType::Context),
        "expected a host auth failure, got {refused:?}"
    );
    assert!(s
        .diagnostics()
        .contains("Unauthorized function call for address"));
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);
    assert_eq!(s.wallet(&s.attacker), 0);

pub(crate) fn dispatch_hop(
    env: &Env,
    router: &Address,
    hop: &SwapHop,
    amount_in: i128,
    tokens_cache: &mut Map<Address, Vec<Address>>,
) -> i128 {
    let ctx = HopContext::new(env, router, hop, amount_in);
    let before_in = ctx.input_balance();
    let before_out = ctx.output_balance();

    match hop.venue {
        SwapVenue::Soroswap => soroswap::swap(&ctx),
        SwapVenue::Aquarius => aquarius::swap(&ctx, tokens_cache),
        SwapVenue::Phoenix => phoenix::swap(&ctx),
        SwapVenue::Sushi => sushi::swap(&ctx),
        SwapVenue::CometDex => comet::swap(&ctx),
    };
