### Title
Multi-wavelength (940nm/740nm) IR eye frames stored without any liveness/sharpness/score gating - (File: `src/plans/biometric_capture/multi_wavelength.rs`)

### Finding Description
`multi_wavelength::Plan::handle_ir_eye_camera`, when in `State::ExtraWavelength`, unconditionally stores every incoming IR frame into `left_940nm`/`left_740nm`/`right_940nm`/`right_740nm` with no sharpness, brightness, or IRIS_SCORE_MIN check: `*slot = Some(output.value);` [1](#0-0) . During this same state, `handle_ir_net` (which is the component that normally enforces `IRIS_SCORE_MIN`/`IRIS_BRIGHTNESS_RANGE` in `biometric_capture::Plan::handle_ir_net`) is short-circuited to `Ok(BrokerFlow::Continue)` and never runs its scoring logic [2](#0-1) , contrasted with the gated path in `biometric_capture::Plan::handle_ir_net` [3](#0-2) . These captured frames are then merged straight into the final `Capture` in `Plan::run` with no verdict check: `capture.eye_left.ir_frame_940nm = self.left_940nm; ...` [4](#0-3) .

However, this extension (`perform_multi_wavelength`) only runs *after* the core `biometric_capture::Plan` has already completed a full objective cycle and produced a validated `left_ir`/`right_ir` frame pair via `run_check`/`set_next_objective`, which is gated on `IRIS_SCORE_MIN` and `IRIS_BRIGHTNESS_RANGE` in `handle_ir_net` [5](#0-4) . The primary identification frames (`eye_left.ir_frame`, `eye_right.ir_frame`) used for iris uniqueness/liveness decisioning are unaffected — only the supplementary `ir_frame_940nm`/`ir_frame_740nm` fields lack per-frame quality gating.

### Impact Explanation
An attacker who passes the primary 850nm liveness/sharpness gate (a separate, harder bar) can cause the supplementary 940nm/740nm frames attached to the same `Capture` to be low-quality, non-live, or otherwise unverified frames, since those slots are populated with zero score/sharpness checks. This is a data-integrity issue on secondary spectral frames, not a bypass of the core "IRIS_SCORE_MIN" fail-closed liveness gate that determines whether a signup is accepted — the main `ir_frame` used for the signup decision still enforces `IRIS_SCORE_MIN`/`IRIS_BRIGHTNESS_RANGE`. Whether unvalidated 940nm/740nm frames constitute an unauthorized-signup or liveness-bypass impact depends on backend-side usage of these auxiliary frames (e.g., additional presentation-attack detection), which was not found in the reachable code within the index; no downstream consumer enforcing a liveness verdict specifically on `ir_frame_940nm`/`ir_frame_740nm` was located.

### Likelihood Explanation
Reaching `State::ExtraWavelength` requires the attacker to have already passed the main biometric capture's IRIS_SCORE_MIN/brightness/liveness gating for the 850nm frames, since `perform_multi_wavelength` executes as a per-iteration extension after a completed capture objective. This significantly narrows the realistic attack surface: the described PoC (driving `perform_multi_wavelength` directly with a synthetic non-live frame and asserting `ir_frame_940nm` is `Some` despite low score) is technically achievable at the unit-test level for this isolated function, but does not by itself demonstrate an unauthorized signup, wrong-identity binding, or liveness-bypass of the actual accepted identity, because the code path that decides signup success/failure (`is_success`, `into_capture`, using `left_ir`/`right_ir`) is untouched by this gap.

### Recommendation
Apply the same or an equivalent quality gate (sharpness threshold and/or brightness range) inside `multi_wavelength::Plan::handle_ir_eye_camera`'s `State::ExtraWavelength` branch before storing a frame into the `left_940nm`/`left_740nm`/`right_940nm`/`right_740nm` slots, or re-enable a lightweight IR-Net pass during the 940nm/740nm captures to attach a quality/liveness verdict, so that consumers of these auxiliary frames (backend fraud/liveness pipelines) are not silently fed unverified images.

### Proof of Concept
Unit/integration test plan (for the isolated storage gap, not full signup bypass):
1. Construct a `multi_wavelength::Plan` wrapping a `biometric_capture::Plan`.
2. Force `state` to `State::ExtraWavelength { target_left_eye: true, target_740nm: false, .. }`.
3. Call `handle_ir_eye_camera` with a synthetic `camera::ir::Frame` representing a printed/non-live iris (e.g., uniform low-sharpness pixel data).
4. Assert `self.left_940nm.is_some()` is `true` regardless of the frame's sharpness/score, demonstrating the missing gate.
5. To assess actual product impact, additionally trace whether `Capture.eye_left.ir_frame_940nm`/`ir_frame_740nm` are consumed by any backend liveness/fraud check — this could not be confirmed from the available index and should be verified with full repo access (backend/upload code) before treating this as more than a data-quality gap on supplementary frames.

impl OrbPlan for Plan {
    fn handle_ir_net(
        &mut self,
        orb: &mut Orb,
        output: port::Output<ir_net::Model>,
        frame: Option<camera::ir::Frame>,
    ) -> Result<BrokerFlow> {
        match output.value {
            ir_net::Output::Estimate(estimate) => {
                self.update_occlusion(orb, &estimate);
                if let Some(perceived_side) = estimate.perceived_side {
                    if perceived_side != i32::from(!self.target_left_eye) {
                        tracing::debug!("Skipping frame due to target and perceived side mismatch");
                        return Ok(BrokerFlow::Continue);
                    }
                } else {
                    tracing::debug!("IRNet perceived_side=None, skipping frame");
                    return Ok(BrokerFlow::Continue);
                }

                self.update_ux(orb, estimate.sharpness);

                let frame = frame.expect("frame must be set for an estimate output");
                let valid_capture = estimate.score >= IRIS_SCORE_MIN
                    && (!orb.ir_auto_exposure.is_enabled()
                        || IRIS_BRIGHTNESS_RANGE.contains(&frame.mean()))
                    && self.valid_capture_after <= Instant::now();

                if valid_capture {
                    let slot =
                        if self.target_left_eye { &mut self.left_ir } else { &mut self.right_ir };
                    if slot.is_none() {
                        dd_incr!(
                            "main.count.signup.during.biometric_capture.\
                             first_side_sharp_iris_detected",
                            &format!(
                                "side:{}",
                                if self.target_left_eye { "left" } else { "right" }
                            )
                        );
                    }
                    tracing::debug!("Found sharp iris: {}", estimate.score);
                    *slot = Some(FrameInfoIr::new(estimate, frame));
                }
            }
