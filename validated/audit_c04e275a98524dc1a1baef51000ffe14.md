## Analysis Result

### Title
Value Extraction via Pre-Seeded HyperSwap V2 Pool Rebalance Swap During Graduation - (File: packages/contracts/src/Bonding.sol)

### Summary
The Jimbo exploit abused a protocol-controlled rebalancing action (`controller.shift()`/`reset()`) that was triggered against attacker-manipulated bin state, letting the attacker extract value from the protocol's own rebalancing swaps. alt.fun's analog is the permissionless graduation flow: `finalizeGraduation` → `_seedUniswapV2Direct` → `_seedRebalancing`, which performs a **protocol-executed swap directly against a HyperSwap V2 pair that any unprivileged address can pre-seed** before graduation completes. Whoever holds LP shares in that pair when the rebalance swap executes captures the AMM swap fee generated by Bonding's own rebalancing trade.

### Finding Description
`finalizeGraduation` is permissionless and, for any token whose graduation has been triggered (`triggerGraduation`/inline threshold-cross in `buy`), calls `_seedUniswapV2Direct` [1](#0-0) .

If the HyperSwap V2 TOKEN/LT pair already has LP supply (`totalSupply() != 0`) — i.e., an attacker minted liquidity into it beforehand with `IUniswapV2Router02.addLiquidity`/direct `pair.mint`, which is fully permissionless since `_ensureUniswapV2Pair` will happily reuse or create that pair — the code takes the "Regime 3" hostile-pre-seed path and calls `_seedRebalancing`, which executes a **direct `pair.swap`** (not router-mediated) to push the pool toward the curve-close ratio before depositing the remaining balanced amounts via `router.addLiquidity(..., amountMin=1, amountMin=1)` [2](#0-1) .

The natspec on `_seedUniswapV2Direct` explicitly documents this rebalance-swap mechanic and its purpose (defending the LP-seed *ratio*), but does not address who profits from the swap's AMM fee [3](#0-2) . In standard Uniswap-V2-style pairs, a swap's fee (taken from the input side) is retained in the pool and accrues pro-rata to whoever holds LP shares at redemption time. Because the pre-seed is attacker-controlled and typically tiny relative to `tokensForLP`/`ltFromPair` (the graduation deposit), the attacker can be the **sole LP holder** in that pair at the moment Bonding's rebalance swap executes, meaning the entire fee generated by that forced swap (funded by curve-raised LT/tokens that belong to the graduating token's future LP) is captured by the attacker's pre-existing LP position. The attacker then withdraws their LP (pre-seed + accrued fee) immediately after `finalizeGraduation` lands, walking away with value that should have stayed in the token's liquidity.

This mirrors the Jimbo bug class precisely: an external actor sets up a price/reserve condition on a pool/bin structure, then the protocol's own rebalancing logic (Jimbo's `controller.shift()`, alt.fun's `_seedRebalancing`'s `pair.swap`) executes against that manipulated state and the attacker profits from the resulting flow.

### Impact Explanation
Every graduation whose HyperSwap V2 pair is pre-seeded by an attacker leaks part of the curve-raised LT/token value (the swap fee on the rebalance leg) to that attacker's LP position instead of it landing entirely in the locked LP (`LPLock.recordLock`). This is a permanent, protocol-funded value transfer out of the token's graduation liquidity to an unrelated wallet — a direct loss to LP/token holders. Because `finalizeGraduation` is permissionless and pre-seeding a fresh HyperSwap V2 pair costs only gas plus a small liquidity deposit (which the attacker fully reclaims), this is repeatable across every newly-launching token, cumulatively siphoning protocol/LP value.

### Likelihood Explanation
High reachability: pre-seeding the pair only requires calling `IUniswapV2Router02.addLiquidity` or `pair.mint` directly for the predictable `(token, lt)` pair address before `finalizeGraduation` executes — no privileged role required, and `_ensureUniswapV2Pair` will simply reuse whatever pair already exists [4](#0-3) . Since `triggerGraduation`/the threshold-crossing buy and `finalizeGraduation` are both permissionless, an attacker who monitors near-graduating tokens can front-run the graduation trigger or wait for a keeper to call `finalizeGraduation` and simply hold LP through it.

### Recommendation
- Route the rebalance leg through a mechanism that does not let a pre-existing, attacker-controlled LP position capture the swap fee — e.g., mint the rebalance-swap fee-equivalent value to `LPLock` rather than leaving it in the pool's fee-accrual mechanics, or refuse to graduate into a pair that already has non-zero LP supply (treat any pre-existing LP as a bricked target and deploy to a fresh, deterministic pair instead).
- Alternatively, cap/reject Regime-3 rebalancing when the pre-existing LP supply exceeds a negligible bound, forcing a fresh pair deployment path for anything beyond dust pre-seeds, since dust pre-seeds (per `DIRECT_MINT_PRESEED_BPS`) already fall back to `_seedDirectMint` and are not exploitable this way.

### Proof of Concept
Conceptual (cannot be simulated without a live fork, but reachable purely via unprivileged calls):
1. Attacker observes a token approaching `canGraduate` on `Bonding` (via `previewLtUntilGraduation`).
2. Attacker predicts/derives the HyperSwap V2 pair address for `(token, lt)` and calls `IUniswapV2Router02.addLiquidity` to become its sole LP holder with an off-ratio deposit.
3. Attacker (or anyone) triggers graduation (buy that crosses threshold, or `triggerGraduation`), then calls `finalizeGraduation(token)`.
4. `_seedRebalancing` executes `pair.swap` against the attacker's pre-seeded pair to correct the ratio toward curve-close price; the AMM fee on that swap is retained in the pool.
5. Attacker immediately removes their LP (`removeLiquidity`) before/around the deposit leg completing further dilution, capturing the fee revenue generated entirely by Bonding's forced rebalance trade.

Full transaction-level exploitation (exact fee magnitude, gas ordering, and MEV race with the keeper calling `finalizeGraduation`) is not verifiable from static code alone and would need to be confirmed on a forked testnet.

```text
    function finalizeGraduation(
        address tokenAddress
    ) external nonReentrant {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[tokenAddress];
        if (info.lifecycle != Lifecycle.Graduating) revert NotGraduating();

        address lt = info.ltAddress;
        PendingGraduation memory p = $.pendingGraduation[tokenAddress];

        // Anything in this contract beyond `p.ltFromPair` belongs to a
        // concurrent graduation on the same LT (Phase 1 transferred it
        // via `Router.graduate`) or to stray dust. Either way it is
        // off-limits to this graduation's deposit and sweep — see
        // `_routerDepositAndDispose` and `_sweepLTToOwner`.
        // Saturating subtract: a balance below `p.ltFromPair` shouldn't
        // be reachable in normal operation, but we keep finalize from
        // bricking on a Panic if any future code path or non-canonical
        // LT briefly violates the invariant.
        uint256 ltBalance = IERC20(lt).balanceOf(address(this));
        uint256 protectedLT = ltBalance > p.ltFromPair ? ltBalance - p.ltFromPair : 0;

        address lpPair = _ensureUniswapV2Pair(tokenAddress, lt);
        uint256 liquidity = _seedUniswapV2Direct(tokenAddress, lt, lpPair, p.tokensForLP, p.ltFromPair, protectedLT);
```

```text
    function _seedUniswapV2Direct(
        address tokenAddress,
        address lt,
        address pair,
        uint256 tokensForLP,
        uint256 ltFromPair,
        uint256 protectedLT
    ) internal returns (uint256 liquidity) {
        // Regime 2 — pull any donation pre-seed into this contract so it
        // doesn't pollute the post-swap ratio. Routed to `address(this)`
        // (NOT `lpLock`) so donated TOKEN can be burned and donated LT
        // can be swept to the owner via `_sweepLTToOwner` — `LPLock` has
        // no rescue path, so anything sent there is permanently stuck.
        // No-op on a freshly-created pair (balance == reserves == 0).
        IUniswapV2Pair(pair).skim(address(this));

        // Regime 1 — no LP minted yet (`totalSupply == 0`): a pristine empty
        // pair, or a dust pre-seed from `transfer(pair, dust) + sync()` that
        // leaves reserves non-zero while supply is still zero. Keying on
        // supply rather than reserves routes the dust shape here instead of
        // the rebalance path: with zero supply V2 mints from our amounts
        // alone, so the pool opens at the cached ratio and any dust becomes
        // reserves with no LP claim.
        if (IUniswapV2Pair(pair).totalSupply() == 0) {
            return _seedDirectMint(tokenAddress, lt, pair, tokensForLP, ltFromPair);
        }

        // Regime 3 — mint pre-seed: rebalance, then deposit balanced subset.
        // `lpLock_` re-read from storage inside `_routerDepositAndDispose`.
        // Reserves and token-ordering re-read inside `_seedRebalancing` to
        // keep this function's stack pressure under solc's 16-slot ceiling
        // without `viaIR`.
        return _seedRebalancing(tokenAddress, lt, pair, tokensForLP, ltFromPair, protectedLT);
    }
```
