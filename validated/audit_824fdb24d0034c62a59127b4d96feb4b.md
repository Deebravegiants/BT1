Audit Report

## Title
Missing Role-Based Authorization on External Initiator Listing Endpoint - (File: core/web/router.go)

## Summary
The `GET /v2/external_initiators` route in `core/web/router.go` is registered without any role guard, unlike its sibling `POST`/`DELETE` routes which require `auth.RequiresEditRole`. Any authenticated user, including one with only the lowest-privilege `view` role, can call this endpoint and retrieve every configured external initiator's `AccessKey` and `OutgoingToken`, which are integration secrets used for outgoing webhook authentication.

## Finding Description
The `authv2` group only enforces identity via `auth.Authenticate(..., AuthenticateByToken, AuthenticateBySession)` [1](#0-0) , and individual routes must layer on role checks. For external initiators, `GET` is left unguarded while `POST`/`DELETE` are wrapped in `auth.RequiresEditRole`: [2](#0-1) 

The role hierarchy is `view` < `run` < `edit` < `admin`, confirmed in `core/sessions/user.go`. `RequiresEditRole` explicitly rejects `view` and `run` roles [3](#0-2) , but since `GET /external_initiators` has no such wrapper, a `view`-role user passes only the identity check in `Authenticate` and reaches `ExternalInitiatorsController.Index` directly.

`Index` queries all external initiators and serializes them via `presenters.NewExternalInitiatorResource`, which includes `AccessKey` and `OutgoingToken` in the JSON response: [4](#0-3) [5](#0-4) 

This is a genuine inconsistency in the role model for this resource: the same sensitive fields (`AccessKey`, `OutgoingToken`) that are protected by `RequiresEditRole` on `Create`/`Destroy` are freely exposed on `Index` to any authenticated user regardless of role.

## Impact Explanation
A `view`-role authenticated API user (a role explicitly supported by the node's own RBAC model for read-only/dashboard use cases) can enumerate all configured external initiators' `AccessKey` and `OutgoingToken` values — data that should only be visible to `edit`/`admin` users per the resource's own authorization design. This is an authorization-boundary bug (CWE-862 analog) resulting in disclosure of integration credentials to an under-privileged authenticated actor, mapping to the "node API authentication or role bypass" / key-secret exfiltration impact category, though the severity is capped since it discloses outgoing-auth tokens (not the node's own signing/private keys) and requires a valid low-privilege account to already exist.

## Likelihood Explanation
Exploitation requires only a pre-existing `view`-role API credential (which an admin may routinely provision for monitoring/dashboard purposes) and a single unauthenticated-role-check `GET` request — no race conditions, no additional privilege escalation, and 100% reproducible on any node with external initiators configured.

## Recommendation
Wrap `authv2.GET("/external_initiators", ...)` in `auth.RequiresEditRole` (or an equivalent role guard consistent with the sensitivity of `AccessKey`/`OutgoingToken`), or redact those fields from `ExternalInitiatorResource` for callers below `edit` role, matching the protection already applied to `Create` and `Destroy` on the same resource.

## Proof of Concept
1. As an admin, provision an API user with `UserRoleView` via `POST /v2/users`.
2. Authenticate as that view-role user via session or `X-API-KEY`/`X-API-SECRET` token headers.
3. Send `GET /v2/external_initiators`. The request passes `auth.Authenticate` (identity-only check) and reaches `ExternalInitiatorsController.Index` with no role check, returning all configured initiators including `accessKey` and `outgoingToken` fields, despite the caller lacking the `edit` role required for `POST`/`DELETE` on the same resource.

// RequiresEditRole extracts the user object from the context, and asserts the user's role is at least
// 'edit'
func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}
