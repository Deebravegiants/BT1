### Title
Unvalidated swap pool address enables arbitrary contract execution and caller-wallet theft - (File: contracts/swap-aggregator/src/execute/mod.rs)

### Summary
`execute_strategy` lets an unprivileged caller supply arbitrary contract addresses as route pools, and the router invokes those addresses as the selected venue. A malicious pool can perform unrelated token transfers requiring the caller’s authorization; simulation incorporates those transfers into the caller’s signed authorization tree, allowing theft beyond the routed input. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
The public `execute_strategy` entrypoint decodes caller-controlled `swap_xdr`, requires only `sender.require_auth()`, pulls `total_in`, and executes the packed route program. [4](#0-3) [5](#0-4) 

`Program::decode` range-checks pool, token, and amount indexes, but it does not authenticate that an `assets` entry naming a pool belongs to the selected venue or an approved venue registry. [6](#0-5) 

Each swap hop copies `assets[idx_a]` into `SwapHop.pool` and dispatches to the venue adapter selected by the attacker-controlled opcode. [2](#0-1) [7](#0-6) 

For a Soroswap-labelled hop, the router calls `get_reserves`, transfers the routed input to the supplied address, and invokes that address’s `swap` function. [8](#0-7) 

A malicious `swap` implementation can call an unrelated token’s `transfer(sender, attacker, amount)`; because the original sender authorization is still the matching authority, the host records that transfer as a child of the sender’s authorization tree. [9](#0-8) [3](#0-2) 

The measured input and output checks only verify that the pool consumed the expected routed input and returned positive output; they do not prevent the pool from making additional sender-authorized token calls during its callback. [10](#0-9) [11](#0-10) 

### Impact Explanation
A victim who signs the simulated authorization tree for a malicious route can lose arbitrary balances of unrelated wallet tokens, not merely the declared swap input. [12](#0-11) [13](#0-12) 

The malicious pool can preserve the expected protocol settlement by accepting the measured input and paying a sufficient output, so the swap can complete successfully while the unrelated wallet transfer is also executed. [10](#0-9) [14](#0-13) 

### Likelihood Explanation
No privileged role, leaked key, upgrade, or protocol account is required because the malicious pool is selected entirely through caller-supplied route data and reached through a permissionless swap entrypoint. [4](#0-3) [2](#0-1) 

Exploitation requires the victim to submit or be convinced to sign a malicious route whose simulation records the extra transfer child, so this is not fully unilateral against an already-signed transaction. [15](#0-14) 

The opaque XDR route and generated nested authorization make the additional transfer difficult for a user to identify when relying on normal simulation output, while the router provides no on-chain pool allowlist to reject the malicious code. [16](#0-15) [17](#0-16) 

### Recommendation
Require every executable pool address to come from an authenticated venue/pool registry rather than directly from untrusted `StrategyPayload.assets`, or otherwise bind each pool to a governance-approved venue deployment before invoking it. [2](#0-1) [18](#0-17) 

Add a regression test asserting that a route containing a non-registered pool address fails before any venue invocation, including a case where the fake pool attempts an unrelated `token.transfer` from the sender. [15](#0-14) 

### Proof of Concept
1. Deploy a malicious contract implementing the Soroswap pair surface used by the adapter: `get_reserves` returns positive reserves, and `swap` calls `token.transfer(victim, attacker, victim_balance)` for an unrelated victim-held token and then pays the router positive `token_out`. [8](#0-7) [9](#0-8) 

2. Construct a valid `StrategyPayload` whose `assets` list contains `[malicious_pool, token_in, token_out]`, whose `amounts[0]` is a positive `min_out`, and whose single packed op is `[opcode=0 Soroswap, mode=All, idx_a=0, idx_b=1, idx_c=2]`. [19](#0-18) [20](#0-19) 

3. Have the victim call `execute_strategy(victim, total_in, swap_xdr)`; the router authenticates the victim, pulls `token_in`, invokes the malicious pool as a Soroswap pair, and measures its positive `token_out` receipt. [4](#0-3) [21](#0-20) [10](#0-9) 

4. During transaction simulation, the malicious pool’s unrelated token transfer is recorded beneath the victim’s authorization invocation, and signing that returned tree makes the transfer execute alongside the otherwise successful swap. [3](#0-2) [11](#0-10)

impl Program {
    /// Copies, parses, and structurally validates `ops` against the registry sizes, returning
    /// the decoded program.
    ///
    /// Panics with [`Error::InvalidRouteXdr`] on a malformed header, version, length, opcode, or
    /// index, and with a more specific error for other structural violations (empty/oversized
    /// batch, same-token swap, broken `Prev` chain, out-of-range split weight). Touches no
    /// external contract.
    pub(crate) fn decode(env: &Env, ops: &Bytes, assets_len: u32, amounts_len: u32) -> Self {
        if assets_len == 0 || assets_len > MAX_ASSETS || amounts_len > MAX_AMOUNTS {
            panic_with_error!(env, Error::InvalidRouteXdr);
        }

        let len = ops.len();
        if len < HEADER_LEN || len as usize > MAX_PROGRAM_BYTES {
            panic_with_error!(env, Error::InvalidRouteXdr);
        }

        let mut buf = [0u8; MAX_PROGRAM_BYTES];
        ops.copy_into_slice(&mut buf[..len as usize]);

        if buf[head::VERSION] != VERSION {
            panic_with_error!(env, Error::InvalidRouteXdr);
        }

        let op_count = buf[head::OP_COUNT] as u32;
        let weight_count = buf[head::WEIGHT_COUNT] as u32;
        if op_count == 0 || op_count > MAX_OPS || weight_count > MAX_WEIGHTS {
            panic_with_error!(env, Error::EmptyBatch);
        }
        let weights_at = HEADER_LEN + OP_LEN * op_count;
        if len != weights_at + WEIGHT_LEN * weight_count {
            panic_with_error!(env, Error::InvalidRouteXdr);
        }

        let token_in = buf[head::TOKEN_IN] as u32;
        let token_out = buf[head::TOKEN_OUT] as u32;
        let min_out = buf[head::MIN_OUT] as u32;
        if token_in >= assets_len || token_out >= assets_len || min_out >= amounts_len {
            panic_with_error!(env, Error::InvalidRouteXdr);
        }
        if token_in == token_out {
            panic_with_error!(env, Error::SameToken);
        }

        let referral = &buf[head::REFERRAL..head::REFERRAL + 4];
        let referral_id =
            u32::from_be_bytes([referral[0], referral[1], referral[2], referral[3]]) as u64;

        let program = Self {
            buf,
            op_count,
            weights_at,
            token_in,
            token_out,
            min_out,
            referral_id,
        };
        program.validate(env, assets_len, amounts_len, weight_count);

    /// Validates every instruction's opcode, mode, and indices before execution begins,
    /// including the `Prev` chain, same-token swaps, and split-weight bounds.
    fn validate(&self, env: &Env, assets_len: u32, amounts_len: u32, weight_count: u32) {
        for i in 0..self.op_count {
            let record = self.raw(i);
            let Some(opcode) = Opcode::from_u8(record[field::OPCODE]) else {
                panic_with_error!(env, Error::InvalidRouteXdr);
            };
            let mode = Mode::from_u8(record[field::MODE]);
            let (idx_a, idx_b, idx_c) = (
                record[field::POOL] as u32,
                record[field::TOKEN_IN] as u32,
                record[field::TOKEN_OUT] as u32,
            );

            // `Prev` is a purely structural link: the predecessor must exist,
            // must have a single output, and that output must be this
            // instruction's input.
            if mode == Mode::Prev {
                if i == 0 {
                    panic_with_error!(env, Error::BrokenTokenChain);
                }
                let previous = self.raw(i - 1);
                let produced = match Opcode::from_u8(previous[field::OPCODE]) {
                    // A swap produces its `token_out`, a mint its share token.
                    Some(Opcode::Swap(_)) => previous[field::TOKEN_OUT],
                    Some(Opcode::Mint) => previous[field::TOKEN_IN],
                    // A burn releases every constituent at once.
                    _ => panic_with_error!(env, Error::BrokenTokenChain),
                };
                if idx_b != produced as u32 {
                    panic_with_error!(env, Error::BrokenTokenChain);
                }
            }
            match mode {
                Mode::Fixed(idx) if idx as u32 >= amounts_len => {
                    panic_with_error!(env, Error::InvalidRouteXdr)
                }
                Mode::Ppm(idx) if idx as u32 >= weight_count => {
                    panic_with_error!(env, Error::InvalidRouteXdr)
                }
                _ => {}
            }

            if idx_a >= assets_len || idx_b >= assets_len {
                panic_with_error!(env, Error::InvalidRouteXdr);
            }
            match opcode {
                Opcode::Swap(_) => {
                    if idx_c >= assets_len {
                        panic_with_error!(env, Error::InvalidRouteXdr);
                    }
                    if idx_b == idx_c {
                        panic_with_error!(env, Error::SameToken);
                    }
                }
                // Liquidity legs spend the full vault balance, so only `Mode::All` is valid.
                Opcode::Burn | Opcode::Mint => {
                    if mode != Mode::All {
                        panic_with_error!(env, Error::InvalidRouteXdr);
                    }
                    if idx_c >= amounts_len {
                        panic_with_error!(env, Error::InvalidRouteXdr);
                    }
                }
            }
