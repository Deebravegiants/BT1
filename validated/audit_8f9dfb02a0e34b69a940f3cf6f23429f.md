This confirms the vulnerability chain end-to-end: `validateAddress` dispatches Litecoin validation to `validateLitecoinAddress`, which for addresses starting with `3` decodes as Base58Check with `expectedVersion 0x05` [1](#0-0) . Since Bitcoin legacy P2SH also uses version byte `0x05` [2](#0-1) , the Base58Check payload+checksum of a valid Bitcoin P2SH address is byte-identical in structure to a valid Litecoin legacy P2SH address, so `validateLitecoinBase58Address` returns `true` for a real Bitcoin address. The code comment even acknowledges this: `[Inference] This also matches Bitcoin P2SH; cannot distinguish by prefix+version alone.` [3](#0-2) 

The call path is real: `PoaBridge.validateWithdrawal` calls `validateAddress(args.destinationAddress, assetInfo.blockchain)` and only throws if it returns `false` [4](#0-3) . No other check compares the address against Litecoin-specific network semantics — `compareAddresses` only checks against `origin_chain_address`, unrelated to this issue [5](#0-4) . Once validated, `createWithdrawIntentPrimitive` encodes `destinationAddress` verbatim into the withdraw memo as `WITHDRAW_TO:<address>` [6](#0-5) , with no chain-specific transformation that would catch the mismatch.

### Title
Litecoin address validation accepts Bitcoin P2SH addresses (version-byte collision), causing withdrawn funds to be encoded to an address that is only meaningful on Bitcoin - (File: packages/intents-sdk/src/lib/validateAddress.ts)

### Summary
`validateLitecoinAddress` treats any Base58Check string beginning with `3` and version byte `0x05` as a valid Litecoin P2SH address, but this is exactly the same encoding used by Bitcoin mainnet P2SH addresses. A user withdrawing a Litecoin-network asset (e.g. `nep141:ltc.omft.near` or Omni/PoA Litecoin token) who supplies a real Bitcoin P2SH address as `destinationAddress` will pass validation, and the SDK will encode that Bitcoin address verbatim into the withdraw intent's PoA memo, sending Litecoin to a destination whose bytes are only decodable/spendable on the Bitcoin network.

### Finding Description
The broken equality: "address format validated as `(Chains.Litecoin, address)`" should imply "address is spendable on the Litecoin network." For `3`-prefixed addresses, this equality is violated: `validateLitecoinBase58Address(address, 0x05)` only checks Base58Check structure (25 bytes, version byte `0x05`, valid double-SHA256 checksum) [7](#0-6) . Since Bitcoin P2SH mainnet addresses use the identical version byte `0x05` [2](#0-1) , `'3J98t1WpEZ73CNmQviecrnyiWrnqRhWNLy'` (a well-known valid Bitcoin P2SH address) passes the Litecoin check unchanged, returning `true`.

Call sequence: `SDK.createWithdrawalIntents` → `PoaBridge.validateWithdrawal` calls `validateAddress(destinationAddress, Chains.Litecoin)` and only rejects on `false` [4](#0-3)  → `PoaBridge.createWithdrawalIntents` calls `createWithdrawIntentPrimitive`, which builds the `ft_withdraw` memo as `WITHDRAW_TO:<destinationAddress>` with no re-validation or chain-specific canonicalization [8](#0-7) . No other guard (`compareAddresses`, `supports()`, min-amount checks) inspects whether the address is chain-exclusive to Litecoin.

### Impact Explanation
The `memo` field of the signed `ft_withdraw` intent is the sole instruction the PoA bridge relayer uses to determine the payout destination on Litecoin. Because the attacker's own Bitcoin-formatted address is accepted, the withdrawn LTC is directed to a hash160 that, when interpreted as a Litecoin P2SH script, corresponds to an arbitrary/unrelated redeem script the withdrawer does not control on Litecoin (it only has meaning as a Bitcoin script). This matches "funds delivered to a wrong address/chain/contract with no recovery" (Critical) — the withdrawing user's own signed withdrawal permanently misdirects their funds with no on-chain recovery path once the PoA bridge executes the payout.

### Likelihood Explanation
Preconditions are trivial: any ordinary user withdrawing to Litecoin via `SDK.estimateWithdrawalFee`/`createWithdrawalIntents` can supply any string as `destinationAddress`; no privileged action, no special route configuration beyond selecting a Litecoin-network asset is needed. The attacker (or a confused/careless user) needs only to know or reuse any valid Bitcoin P2SH address (an enormous, easily obtainable set — e.g. any real-world Bitcoin address of the `3...` form). This is deterministic and repeatable on every call with a `3...`-prefixed Bitcoin P2SH address as the Litecoin destination.

### Recommendation
Reject `3`-prefixed (version `0x05`) Base58Check addresses in `validateLitecoinAddress`, since they are cryptographically indistinguishable from Bitcoin P2SH addresses at the format level, or require callers to disambiguate by only accepting the unambiguous Litecoin-specific prefixes (`L`/`0x30`, `M`/`0x32`, and `ltc1...` bech32/bech32m). At minimum, surface a strong warning/error for the ambiguous legacy `3...` P2SH form rather than silently validating it as Litecoin-exclusive.

function validateLitecoinBase58Address(
	address: string,
	expectedVersion: number,
): boolean {
	let decoded: Uint8Array;

	try {
		decoded = base58.decode(address);
	} catch {
		return false;
	}

	// version (1) + payload (20) + checksum (4)
	if (decoded.length !== 25) return false;

	const version = decoded[0];
	if (version !== expectedVersion) return false;

	const payload = decoded.subarray(0, 21); // version + hash160
	const checksum = decoded.subarray(21, 25);

	const hash1 = sha256(payload);
	const hash2 = sha256(hash1);
	const expectedChecksum = hash2.subarray(0, 4);

	for (let i = 0; i < 4; i++) {
		if (checksum[i] !== expectedChecksum[i]) return false;
	}

	return true;
}

export function createWithdrawIntentPrimitive(params: {
	assetId: string;
	destinationAddress: string;
	destinationMemo: string | undefined;
	amount: bigint;
}): Extract<IntentPrimitive, { intent: "ft_withdraw" }> {
	const { contractId: tokenAccountId } = utils.parseDefuseAssetId(
		params.assetId,
	);
	return {
		intent: "ft_withdraw",
		token: tokenAccountId,
		receiver_id: tokenAccountId,
		amount: params.amount.toString(),
		memo: createWithdrawMemo({
			receiverAddress: params.destinationAddress,
			xrpMemo: params.destinationMemo,
		}),
		min_gas: MIN_GAS_AMOUNT,
	};
}

function createWithdrawMemo({
	receiverAddress,
	xrpMemo,
}: {
	receiverAddress: string;
	xrpMemo: string | undefined;
}) {
	// Strip "bitcoincash:" prefix from BCH CashAddr addresses
	const normalizedAddress = receiverAddress
		.toLowerCase()
		.startsWith("bitcoincash:")
		? receiverAddress.slice("bitcoincash:".length)
		: receiverAddress;

	const memo = ["WITHDRAW_TO", normalizedAddress];

	if (xrpMemo != null && xrpMemo !== "") {
		memo.push(xrpMemo);
	}

	return memo.join(":");
}
