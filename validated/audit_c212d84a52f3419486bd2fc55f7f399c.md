### Title
Unauthenticated `/readyz` endpoint discloses internal service error details via `full` query parameter - ([File: core/web/health_controller.go])

### Summary
The web2py advisory describes an unauthenticated `status` endpoint leaking sensitive internal state (`session_cookie_key`) to any remote caller. Chainlink's node API has an analogous unauthenticated debug-style endpoint: `GET /readyz?full=1`, which returns per-check names and raw internal error strings from every registered health checker, with no authentication required.

### Finding Description
`healthRoutes` registers `/readyz`, `/public-readyz`, `/health`, and `/health.txt` directly on the top-level `api` router group, which only has rate-limiting and session middleware applied — no `auth.Authenticate` guard, unlike `/debug` (which explicitly requires session auth) or `/v2/*` (which requires token/session auth). [1](#0-0) 

`Readyz` returns `http.StatusServiceUnavailable`/`StatusOK` for a plain call, but when the caller supplies `?full=<any>` it builds a full list of `presenters.Check` entries containing the check `Name` and `Output`, where `Output` is `err.Error()` from each internal health-check component, then serializes it as a JSON API response — all without any authentication check on the route or in the handler itself. [2](#0-1) 

Notably, the sibling `PublicReadyz` handler was explicitly written to *avoid* this exact problem — its doc comment states it "never returns per-check details regardless of query parameters, to avoid leaking internal service state on publicly reachable endpoints" — which confirms that `Readyz`'s `full` output is considered sensitive internal state, yet `Readyz` itself remains reachable on the same unauthenticated route group as `PublicReadyz`. [3](#0-2) 

The `Health` handler has the same unauthenticated exposure pattern, additionally supporting HTML/plaintext negotiation of the same error outputs. [4](#0-3) 

### Impact Explanation
Any unauthenticated remote client that can reach the node's HTTP API can call `GET /readyz?full=1` (or `/health`) and receive the internal names and raw `Error()` strings of every registered health/service check. Depending on what services register checks (DB, RPC clients, subsystems), these error strings can leak internal topology, connection details, or other diagnostic information not intended for external unauthenticated exposure — the same class of issue as CVE-2016-3954 (CWE-200), where an unauthenticated status page revealed backend secrets/state. This does not by itself grant code execution or fund movement, but it is a genuine, unprivileged, remotely reachable information-disclosure primitive that can aid further attacks (reconnaissance for chained exploits), matching the accepted "cross-user/unauthenticated disclosure" category.

### Likelihood Explanation
High. The route requires no credentials, no special headers, and is reachable by any client that can hit the node's HTTP port; the `full` toggle is a simple query parameter with no validation, and the code path is unconditionally executed within a single handler function.

### Recommendation
Restrict `/readyz`'s `full` detail output the same way `PublicReadyz` already does — either remove the `full` parameter's detailed output entirely from the unauthenticated route, or require `auth.Authenticate` (as is already done for `/debug`) before returning `Output`/error strings from `Readyz`/`Health`. Audit health-check implementations to ensure their `Error()` strings never embed secrets (credentials, tokens, internal URLs) as a defense-in-depth measure.

### Proof of Concept
```
GET /readyz?full=1 HTTP/1.1
Host: <chainlink-node>:6688
```
No `Cookie` or `Authorization` header is required; the response body contains a JSON array of `checks` with `name`/`status`/`output` fields where `output` is the raw internal error text for any failing subsystem check, as produced by `hc.App.GetHealthChecker().IsReady()` and rendered in `Readyz`. // Unlike Readyz, it never returns per-check details regardless of query parameters, to avoid

func (hc *HealthController) PublicReadyz(c *gin.Context) {
	ready, _ := hc.App.GetHealthChecker().IsReady()
	if !ready {
		c.Status(http.StatusServiceUnavailable)
		return
	}
	c.Status(http.StatusOK)
}

func (hc *HealthController) Readyz(c *gin.Context) {
	status := http.StatusOK

	checker := hc.App.GetHealthChecker()

	ready, errors := checker.IsReady()

	if !ready {
		status = http.StatusServiceUnavailable
	}

	c.Status(status)

	if _, ok := c.GetQuery("full"); !ok {
		return
	}

	checks := make([]presenters.Check, 0, len(errors))

	for name, err := range errors {
		status := HealthStatusPassing
		var output string

		if err != nil {
			status = HealthStatusFailing
			output = err.Error()
		}

		checks = append(checks, presenters.Check{
			JAID:   presenters.NewJAID(name),
			Name:   name,
			Status: status,
			Output: output,
		})
	}

	// return a json description of all the checks
	jsonAPIResponse(c, checks, "checks")
}

func (hc *HealthController) Health(c *gin.Context) {
	_, failing := c.GetQuery("failing")

	status := http.StatusOK

	checker := hc.App.GetHealthChecker()

	healthy, errors := checker.IsHealthy()

	if !healthy {
		status = http.StatusMultiStatus
	}

	c.Status(status)

	checks := make([]presenters.Check, 0, len(errors))
	for name, err := range errors {
		status := HealthStatusPassing
		var output string

		if err != nil {
			status = HealthStatusFailing
			output = err.Error()
		} else if failing {
			continue // omit from returned data
		}

		checks = append(checks, presenters.Check{
			JAID:   presenters.NewJAID(name),
			Name:   name,
			Status: status,
			Output: output,
		})
	}

	switch c.NegotiateFormat(gin.MIMEJSON, gin.MIMEHTML, gin.MIMEPlain) {
	case gin.MIMEJSON:
		break // default

	case gin.MIMEHTML:
		if err := newCheckTree(checks).WriteHTMLTo(c.Writer); err != nil {
			hc.App.GetLogger().Errorw("Failed to write HTML health report", "err", err)
			c.AbortWithStatus(http.StatusInternalServerError)
		}
		return

	case gin.MIMEPlain:
		if err := writeTextTo(c.Writer, checks); err != nil {
			hc.App.GetLogger().Errorw("Failed to write plaintext health report", "err", err)
			c.AbortWithStatus(http.StatusInternalServerError)
		}
		return
	}

	slices.SortFunc(checks, presenters.CmpCheckName)
	jsonAPIResponseWithStatus(c, checks, "checks", status)
}
