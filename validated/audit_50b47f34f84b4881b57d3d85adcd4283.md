**Reasoning:**

`calculate_top_levels` and the underlying `put_top_levels_nodes` are internal storage-engine functions, not reachable from any unprivileged transaction, package, view, authenticator, API, or proof-input surface. They are called only from `merklize_snapshot`/`merklize_value_set`, where `shard_root_nodes` is always constructed via `.enumerate()` over a fixed-size `[Vec; NUM_STATE_SHARDS]` array whose per-index contents are populated by the deterministic `get_state_shard_id` hash-based sharding function, not by any caller-supplied ordering. [1](#0-0) 

There is no code path where an external actor can inject duplicate or reordered `Node` entries into this vector — the index `i` used in `Children::from_sorted(shard_root_nodes.iter().enumerate()...)` is always the canonical shard id assigned by the deterministic sharding function during state-value hashing, not attacker-controlled input. [2](#0-1) 

Since the `len() == 16` assertion / `ensure!` only guards against malformed internal call sites (a pure Rust-level invariant check on trusted, node-local code, not user data), and the vector's per-index content is fixed by `NUM_STATE_SHARDS`-based enumeration rather than any transaction, package, view, authenticator, API, or proof input, this does not cross a real custody boundary as required by the Review Bounds. The scenario described (swapping two `shard_root_nodes` entries) would require code-level control of the storage engine's internal commit pipeline, which is not achievable via any unprivileged entrypoint — it is out of scope per the review's requirement that the path start from unprivileged input.

    /// Assumes 16 shards here, top levels only contain root node.
    pub fn put_top_levels_nodes(
        &self,
        shard_root_nodes: Vec<Node<K>>,
        persisted_version: Option<Version>,
        version: Version,
    ) -> Result<(HashValue, usize, TreeUpdateBatch<K>)> {
        ensure!(
            shard_root_nodes.len() == 16,
            "sharded root nodes {} must be 16",
            shard_root_nodes.len()
        );

        let children = Children::from_sorted(shard_root_nodes.iter().enumerate().filter_map(
            |(i, shard_root_node)| {
                let node_type = shard_root_node.node_type();
                match node_type {
                    NodeType::Null => None,
                    _ => Some((
                        Nibble::from(i as u8),
                        Child::new(shard_root_node.hash(), version, node_type),
                    )),
                }
            },
        ));
        let root_node = if children.is_empty() {
            Node::Null
        } else {
            Node::Internal(InternalNode::new(children))
        };
