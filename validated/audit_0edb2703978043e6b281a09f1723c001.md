Based on my investigation, this vulnerability class does not have a reachable analog in the core-contracts codebase.

The external report's root cause is specific to a **historical checkpoint / binary-search snapshot architecture**: `VotingEscrow` writes checkpoints at `block.timestamp` and answers historical balance queries via an inclusive `ts <= t` binary search over stored checkpoint history, while `TrustBonding` computes reward eligibility by querying that historical balance *at a fixed past epoch-boundary timestamp*. The bug arises because a brand-new checkpoint written exactly at the boundary timestamp gets included in the *previous* epoch's snapshot query.

The NEAR `staking-pool` contract uses a fundamentally different reward-accrual model with no historical/backward-looking snapshot queries at all:

- Rewards are distributed via `internal_ping()`, which computes `total_reward = total_balance - last_total_balance` and immediately mutates the **current** share price (`total_staked_balance`, `total_stake_shares`) in place — there is no stored history of balances at past epoch heights, and no function ever queries "what was my balance at epoch N" after the fact. [1](#0-0) 

- Crucially, every state-mutating entry point (`deposit`, `deposit_and_stake`, `stake`, `stake_all`, `unstake`, `unstake_all`) calls `internal_ping()` **before** applying the caller's own stake/unstake delta, meaning pending rewards are settled into share price using the *pre-existing* share holders before the new depositor's shares are added. [2](#0-1) [3](#0-2) 

- The only "epoch boundary" gating in this codebase is `last_epoch_height == epoch_height` short-circuit in `internal_ping`, and `unstaked_available_epoch_height = env::epoch_height() + NUM_EPOCHS_TO_UNLOCK` for withdrawal cooldown — neither of these involves inclusive/exclusive historical range lookups that could retroactively re-attribute already-realized rewards to a late joiner.

```rust
    /// Distributes rewards after the new epoch. It's automatically called before every action.
    /// Returns true if the current epoch height is different from the last epoch height.
    pub(crate) fn internal_ping(&mut self) -> bool {
        let epoch_height = env::epoch_height();
        if self.last_epoch_height == epoch_height {
            return false;
        }
        self.last_epoch_height = epoch_height;

        // New total amount (both locked and unlocked balances).
        // NOTE: We need to subtract `attached_deposit` in case `ping` called from `deposit` call
        // since the attached deposit gets included in the `account_balance`, and we have not
        // accounted it yet.
        let total_balance =
            env::account_locked_balance() + env::account_balance() - env::attached_deposit();

        assert!(
            total_balance >= self.last_total_balance,
            "The new total balance should not be less than the old total balance"
        );
        let total_reward = total_balance - self.last_total_balance;
        if total_reward > 0 {
            // The validation fee that the contract owner takes.
            let owners_fee = self.reward_fee_fraction.multiply(total_reward);

            // Distributing the remaining reward to the delegators first.
            let remaining_reward = total_reward - owners_fee;
            self.total_staked_balance += remaining_reward;
```
