Audit Report

## Title
User Enumeration via Distinct Login Error Messages in Session Creation - (File: core/sessions/localauth/orm.go)

## Summary
The unauthenticated `/sessions` login endpoint (`SessionsController.Create`) forwards the raw error returned by `AuthenticationProvider().CreateSession` straight into the JSON response body via `jsonAPIError`. Because the local, LDAP, and OIDC authenticators return semantically distinct error values for "no such user" (`sql.ErrNoRows` / `"invalid email"`) versus "wrong password" (`"Invalid password"` / `"invalid password"`), an unauthenticated caller can enumerate valid Chainlink node account emails by diffing login responses.

## Finding Description
`SessionsController.Create` calls `sc.App.AuthenticationProvider().CreateSession(ctx, sr)` and, on failure, passes the error directly to `jsonAPIError(c, http.StatusUnauthorized, err)` [3](#0-2) . `jsonAPIError` serializes `err.Error()` verbatim into the response body when it is not a `*models.JSONAPIErrors` [4](#0-3) .

In `localauth/orm.go`, `CreateSession` first calls `FindUser`, which does a case-insensitive lookup (`SELECT * FROM users WHERE lower(email) = lower($1)`); if no row is found, the database's "no rows" error propagates unchanged [2](#0-1) . If a matching row is found but the password hash check fails, a distinct `"Invalid password"` error is returned instead [1](#0-0) . These two codepaths yield different literal strings in the HTTP response, letting a caller distinguish "account does not exist" from "wrong password for existing account." The same divergent-message pattern exists in the LDAP and OIDC local-fallback authenticators (`"invalid email"` vs. `"invalid password"`).

No middleware, generic-error wrapper, or response normalization intervenes between the authenticator and the client-facing JSON body. The rate limiter referenced in `TestSessions_RateLimited` only throttles request volume after repeated attempts; it does not alter or unify the response content, so the very first request already leaks the distinguishing signal.

## Impact Explanation
This is a disclosure/reconnaissance issue (CWE-200/CWE-204 style, analogous to CVE-2014-3662): an attacker can determine which email addresses correspond to real Chainlink node operator accounts without needing valid credentials. This does not directly grant access or fund movement, but it materially assists follow-on credential stuffing, targeted brute force, or phishing against confirmed valid/administrative accounts on a node whose admin API can control job configuration and fund movement. This maps to an information-disclosure/reconnaissance category rather than a direct authentication bypass or fund-movement bug.

## Likelihood Explanation
High likelihood for the disclosure itself: `/sessions` is an unauthenticated, internet-facing endpoint by design, requires no special network position, and every failed login attempt (the very first one, before any rate limiting kicks in) exposes the differentiating error content.

## Recommendation
Return a single, generic authentication-failure message (e.g., "Invalid email or password") from `CreateSession` (and its LDAP/OIDC equivalents) for all failure branches — no-such-user, wrong-password, and the MFA-related branches — while preserving the detailed distinction only in the audit log entries (`audit.AuthLoginFailedEmail`/`audit.AuthLoginFailedPassword`) rather than in the value passed to `jsonAPIError`.

## Proof of Concept
1. `POST /sessions` with `{"email":"realadmin@node.com","password":"wrongpwd"}` — response body contains `"Invalid password"`.
2. `POST /sessions` with `{"email":"doesnotexist@node.com","password":"wrongpwd"}` — response body contains a distinct message (a "no rows"-style error from `FindUser`, or `"Invalid email"` in the rare case-mismatch scenario).
3. Diffing responses for a list of candidate emails reveals which accounts exist on the node, without needing any valid credentials. A Go integration test invoking `SessionsController.Create` (or hitting the router as in `TestSessions_RateLimited`) with these two payloads and asserting the differing response bodies would confirm this deterministically.
