Audit Report

## Title
Directory Traversal in `newHTTPFetcher` allows workflow-owner-controlled artifact URLs to escape the configured base path - (File: `core/services/workflows/syncer/v2/fetcher.go`)

## Summary
`NewFetcherFunc` in `core/services/workflows/syncer/v2/fetcher.go` returns `newHTTPFetcher` for `http(s)://` configured base URLs, but unlike its sibling `newFileFetcher`, it never verifies that the joined path stays within the configured `baseURL` prefix. [1](#0-0)  This lets a workflow owner supply a `binaryURL`/`configURL` containing `../` sequences that `filepath.Join` resolves past the intended base path, causing the node to issue outbound GET requests to arbitrary paths on the configured trusted host.

## Finding Description
`newFileFetcher` explicitly re-checks the joined path with `strings.HasPrefix(fullPath, basePath+string(filepath.Separator))` before reading from disk. [2](#0-1)  `newHTTPFetcher` performs no equivalent check — it only cleans `req.URL`, strips a leading slash, and joins it onto `u.Path` via `filepath.Join`, which resolves `..` segments across the join boundary and can walk past the intended base path prefix before the request is issued with `http.NewRequestWithContext`. [3](#0-2) 

`req.URL` is populated directly from `Store.FetchWorkflowArtifacts`'s `binaryURL`/`configURL` parameters, which originate from on-chain-registered workflow metadata. [4](#0-3)  The host-allowlist / signed-URL redirection via `retrieveFunc` is only applied when `parsedBinaryURL.Host == h.config.ArtifactStorageHost`, and is entirely skipped whenever `retrieveFunc` is nil — which is exactly the case when the node uses the overridden direct fetcher (`opts.FetcherFunc`) instead of the gateway-backed `FetcherService`. [5](#0-4)  This override path is wired from `cfg.CRE().WorkflowFetcher().URL()` in `core/cmd/shell.go`, and produces `newHTTPFetcher` when that URL has an `http(s)://` scheme. [6](#0-5) 

## Impact Explanation
When a node operator enables this non-default, gateway-bypass fetcher configuration with an `http(s)://` base, any actor able to register a workflow (an ordinary, comparatively low-privileged action gated by workflow-registry authorization rather than node-operator privilege) fully controls the string joined onto the configured base path. This breaks the path-confinement invariant that the code itself establishes for the `file://` variant, and can force the node to issue outbound requests to unintended paths on the configured host — potentially exposing internal endpoints/data reachable from that origin. This maps to the in-scope "unauthorized data disclosure via request/path confinement bypass" category.

## Likelihood Explanation
Exploitation requires the node operator to have specifically configured `CRE.WorkflowFetcher.URL` with an `http(s)://` scheme — this is not the default configuration and represents an intentional, documented gateway-bypass mode (per the code comment "bypasses the gateway"). Given that precondition, the actual traversal step requires only a normal workflow registration with a crafted `binaryURL`/`configURL`, with no additional privilege. The vulnerability is real and code-confirmed, but its exposure is gated by this specific operator opt-in.

## Recommendation
Add the same containment check used in `newFileFetcher` to `newHTTPFetcher`: after computing `u.Path = filepath.Join(basePath, cleanPath)`, verify the resulting path still has the original base path as a prefix (segment-aware, not raw string) and reject the request otherwise, or reject any `req.URL` containing `..` segments prior to joining.

## Proof of Concept
1. Configure `CRE.WorkflowFetcher.URL = "https://artifacts.internal.example/prefix"`, causing `newFetcherServiceV2` to use `opts.FetcherFunc` = `newHTTPFetcher` with no `retrieveFunc`/host allowlist. [5](#0-4) 
2. Register a workflow with `binaryURL = "../../internal/admin-config"`.
3. `FetchWorkflowArtifacts` calls `fetchFn` with `req.URL = "../../internal/admin-config"` since `retrieveFunc` is nil. [7](#0-6) 
4. `newHTTPFetcher` computes `filepath.Join("/prefix", "../../internal/admin-config")` → `/internal/admin-config` and issues `GET https://artifacts.internal.example/internal/admin-config`, outside the intended `/prefix` scope. [8](#0-7)

// NewFetcher creates a new FetcherFunc based on the provided URL configuration
// The implementation supports both file and HTTP(S) URLs and bypasses the gateway
func NewFetcherFunc(baseURL string, lggr logger.Logger) (types.FetcherFunc, error) {
	if baseURL == "" {
		return nil, errors.New("baseURL cannot be empty")
	}

	u, err := url.Parse(baseURL)
	if err != nil {
		return nil, fmt.Errorf("invalid URL: %w", err)
	}

	switch u.Scheme {
	case "file":
		// Ensure the basePath is absolute
		if !filepath.IsAbs(u.Path) {
			return nil, fmt.Errorf("basePath must be an absolute path, got: %s", u.Path)
		}
		return newFileFetcher(u.Path, lggr), nil
	case "http", "https":
		return newHTTPFetcher(baseURL, lggr), nil
	default:
		return nil, fmt.Errorf("unsupported URL scheme: %s", u.Scheme)
	}
}

func (h *Store) FetchWorkflowArtifacts(ctx context.Context, workflowID, binaryURL, configURL string) ([]byte, []byte, error) {
	// Check if the workflow spec is already stored in the database.
	// A row whose binary payload is empty is a pause tombstone - don't use it.
	if spec, err := h.orm.GetWorkflowSpec(ctx, workflowID); err == nil && spec.Workflow != "" {
		// there is no update in the BinaryURL or ConfigURL, lets decode the stored artifacts
		decodedBinary, err := hex.DecodeString(spec.Workflow)
		if err != nil {
			return nil, nil, fmt.Errorf("failed to decode stored workflow spec: %w", err)
		}
		return decodedBinary, []byte(spec.Config), nil
	}

	// Determine which URL to retrieve workflow binary artifacts from
	parsedBinaryURL, err := url.Parse(binaryURL)
	if err != nil {
		return nil, nil, fmt.Errorf("invalid binary URL: %w", err)
	}

	// If the binary URL points to the artifact storage host, use the retrieve function to get the signed URL.
	// NOTE: retrieveFunc may be nil if the fetcherFunc was overridden.
	// TODO CRE-632: retrieverFunc should enforced made to always be set, once local CRE can support it.
	if h.retrieveFunc != nil && parsedBinaryURL.Host == h.config.ArtifactStorageHost {
		signedBinaryURL, err2 := h.retrieveFunc(ctx, &storage_service.DownloadArtifactRequest{
			Id:   workflowID,
			Type: storage_service.ArtifactType_ARTIFACT_TYPE_BINARY,
		})
		if err2 != nil {
			return nil, nil, fmt.Errorf("failed to get binary artifact URL: %w", err2)
		}
		binaryURL = signedBinaryURL
	}

	// Fetch the binary files from the specified URLs.
	var (
		binary, decodedBinary, config []byte
	)

	maxBinarySize, err := h.limiters.MaxBinarySize.Limit(ctx)
	if err != nil {
		return nil, nil, fmt.Errorf("failed to get binary size limit: %w", err)
	} else if maxBinarySize < 0 {
		maxBinarySize = 0
	}
	req := ghcapabilities.Request{
		URL:              binaryURL,
		Method:           http.MethodGet,
		MaxResponseBytes: safeUint32(uint64(maxBinarySize)),
		WorkflowID:       workflowID,
	}

		return nil, nil, &types.ArtifactFetchError{ArtifactType: "binary", URL: binaryURL, Err: err}
