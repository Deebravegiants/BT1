### Title
Long-horizon index accrual overflows and permanently freezes a market - (`common/src/rates/simulate.rs`)

### Summary
Market accrual recomputes token-denominated borrowed and supplied value at every compounding step before updating either index. Both values are calculated by `scaled_to_original`, which delegates to checked `Ray::mul`; once `scaled_amount * index / RAY` exceeds `i128::MAX`, accrual panics with `MathOverflow` before `update_borrow_index` can apply the index cap. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`accrue_step` first multiplies the stored scaled borrow balance by the current borrow index and the scaled supply balance by the current supply index to calculate utilization. [4](#0-3)  Both conversions use `scaled_to_original`, a half-up fixed-point multiplication over the `i128` raw representation. [2](#0-1) [5](#0-4) 

For a sufficiently large market, a valid borrow index below `MAX_BORROW_INDEX_RAY` can nevertheless make `borrowed * borrow_index` exceed the `i128` value domain. Because that multiplication runs before `update_borrow_index`, the intended `MAX_BORROW_INDEX_RAY` clamp never executes. [6](#0-5) [3](#0-2) 

The production accrual loop applies this step to every elapsed interval, while `market::accrue` invokes it for each requested market and commits the cache only after `global_sync` returns. [7](#0-6) [8](#0-7)  Therefore, once the intermediate ray value crosses the `i128` ceiling, neither forced index synchronization nor ordinary pool mutations can progress that market.

### Impact Explanation
The market becomes permanently frozen: accrual reverts, `last_timestamp` is never advanced, and every later operation that accrues first encounters the same panic. A market in this state cannot process repayments, withdrawals, liquidations, bad-debt cleanup, or fresh accounting-dependent actions, leaving supplier collateral and borrower obligations trapped and preventing orderly resolution of debt. [9](#0-8) [8](#0-7) 

The repository already contains a harness reproduction demonstrating the sequence: sustained high utilization eventually causes `update_indexes` to return `MATH_OVERFLOW` while `borrow_index` remains below `MAX_BORROW_INDEX_RAY`, after which even a one-unit withdrawal and a minimal repayment fail with the same overflow. [10](#0-9) 

### Likelihood Explanation
An unprivileged caller can trigger the terminal failure by waiting for the required index growth and submitting the public controller `update_indexes` flow for the affected `(hub_id, asset)` market. [8](#0-7)  The triggering condition requires an unusually large principal together with enough sustained utilization for the index to grow to the ray-value ceiling; the regression harness uses a one-billion-token, 18-decimal market at 98% utilization and repeatedly advances a year before synchronization. [11](#0-10) 

The attacker does not need to retain ownership of all funds once the state exists because any participant can call the accrual path when the market crosses the boundary. The extreme capitalization and prolonged high utilization make the issue less likely than an ordinary user-input bug, but the resulting freeze is permanent and affects the entire market rather than only the caller. [12](#0-11) 

### Recommendation
Bound the calculation before multiplying by the index. In `accrue_step`, cap or saturate `scaled_to_original` at a defined ray-value ceiling before utilization, or determine utilization with a saturating `borrowed/supplied` ratio rather than materializing both full ray values. [13](#0-12) 

Also ensure the borrow-index cap remains reachable when the unscaled debt value saturates: clamp `new_borrow_index` before any later multiplication that assumes `borrowed * new_borrow_index <= i128::MAX`, and define the terminal market behavior explicitly once debt value reaches the representation bound. [3](#0-2) [14](#0-13) 

### Proof of Concept
The repository’s `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` test supplies one billion 18-decimal units, borrows 98%, advances time annually, and calls `try_update_indexes_for(&["BIG18"])` until synchronization fails. [11](#0-10)  The assertion verifies `MATH_OVERFLOW`, confirms `borrow_index < MAX_BORROW_INDEX_RAY`, and then shows both `withdraw` and `repay` revert with `MATH_OVERFLOW`. [15](#0-14)

/// Applies `interest_factor` to `old_index` to produce the new borrow index,
/// capped at `MAX_BORROW_INDEX_RAY`.
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
