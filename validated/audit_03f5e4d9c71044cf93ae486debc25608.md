Confirmed: `placeOrder` in `IntentGatewayV2.sol` computes `protocolFee = (originalAmount * protocolFeeBps) / 10_000` with no minimum-amount enforcement — if `protocolFee` rounds to zero it simply skips emitting `DustCollected` and the input passes through untaxed, exactly mirroring the reported `Allo._fundPool` rounding-to-zero bug. ### Title
Protocol fee on `placeOrder` can be bypassed by splitting orders into sub-rounding-threshold amounts - (File: evm/src/apps/IntentGatewayV2.sol)

### Summary
`IntentGatewayV2.placeOrder()` deducts a `protocolFeeBps`-based fee from each order input using integer division with no minimum-fee or minimum-amount check. Any unprivileged user placing an order can choose an `originalAmount` small enough that `(originalAmount * protocolFeeBps) / 10_000` rounds down to `0`, in which case no `DustCollected` event fires and the full input amount is escrowed for the order with zero protocol fee collected.

### Finding Description
In `placeOrder`, the protocol fee is computed per input token as:
```solidity
uint256 protocolFee = (originalAmount * protocolFeeBps) / 10_000;
uint256 reducedAmount = originalAmount - protocolFee;
...
if (protocolFee > 0) emit DustCollected(token, protocolFee);
``` [2](#0-1) 

There is no `require(protocolFee > 0)` or minimum notional check analogous to the recommended fix in the source report. A caller can repeatedly invoke `placeOrder` with `originalAmount < 10_000 / protocolFeeBps` (e.g. at the documented 5 bps default, any amount below 2,000 units of the token's smallest denomination) to guarantee `protocolFee == 0` on every call, fully bypassing the protocol's fee mechanism while still creating valid, escrowed, fillable orders. This is directly reachable by any unprivileged order placer — the exact "unprivileged message dispatcher"-equivalent actor for the IntentGateway — with a single `placeOrder` transaction, and is repeatable without any privileged role. The Tron deployment of the same contract has the identical logic. [3](#0-2) 

The severity is amplified relative to the original Allo report because here fee avoidance doesn't require repeated calls to fund one pool with dust amounts — a user can size *every single order* just under the rounding threshold and place normal-scale volume by fragmenting it across many sub-threshold orders (particularly on low-fee L2s/L1s where gas is cheap and `protocolFeeBps` is small, e.g. the documented 5 bps default), systematically routing volume through the gateway while consistently paying zero protocol fee.

### Impact Explanation
Protocol fee revenue (paid to governance/treasury via the `DustCollected`/dust-retention mechanism) can be permanently avoided for fragmented order flow, causing a persistent under-collection of protocol fees — a direct value leak from the protocol's revenue stream. This does not corrupt escrow accounting or the order-commitment/settlement logic (the reduced amount and commitment remain internally consistent), so the impact is confined to fee-avoidance rather than fund theft from other users, but it is a concrete, repeatable loss of protocol revenue reachable by any caller.

### Likelihood Explanation
High likelihood: bypassing the fee requires no special conditions beyond choosing a small enough `originalAmount` per order relative to `protocolFeeBps`, which is trivial to determine off-chain, and the exploit is a single, ordinary `placeOrder` call available to any user at no cost beyond gas.

### Recommendation
Add a `require(protocolFee > 0)` (or an equivalent minimum-input-amount check) alongside the existing `if (protocolFeeBps > 0)` branch in `placeOrder`, mirroring the audit's suggested fix, so that orders whose input amount would round the fee to zero are rejected (or rounded up) rather than silently exempted:
```solidity
if (protocolFeeBps > 0) {
    ...
    uint256 protocolFee = (originalAmount * protocolFeeBps) / 10_000;
    require(protocolFee > 0, "AmountTooSmall");
    ...
}
```
Apply the same fix to `evm/tron/contracts/apps/IntentGatewayV2.sol`, which contains the identical fee-computation logic.

### Proof of Concept
1. Deploy/observe an `IntentGatewayV2` with `protocolFeeBps = 5` (the documented default). [4](#0-3) 
2. Any user calls `placeOrder` with `order.inputs[0].amount = 1999` (any USDC-denominated amount `< 2000`, since `10_000/5 = 2000`).
3. `protocolFee = (1999 * 5) / 10_000 = 0` (integer division truncates), so `reducedAmount == originalAmount`, no `DustCollected` event is emitted, and the full `1999` is escrowed for the order. [5](#0-4) 
4. The user repeats step 2 with as many sub-2000-unit orders as needed to move arbitrary volume, paying zero protocol fee on each, in contrast to a single large order which would correctly be charged the fee.
