## Title
Unauthenticated exposure of LOOP-plugin pprof/metrics/discovery endpoints - (File: core/web/router.go)

## Summary
`loopRoutes` is registered directly on the top-level `api` `*gin.RouterGroup` in `NewRouter`, which carries only rate-limiting and cookie-session middleware, not `auth.Authenticate(...)`. This is inconsistent with every other debug/metrics route group in the same file, allowing unauthenticated access to plugin discovery, Prometheus metrics, and full `pprof` heap/goroutine/CPU dumps of LOOP plugin processes.

## Finding Description
In `core/web/router.go`, `NewRouter` builds `api` with only rate limiting and session middleware: [1](#0-0) 

`loopRoutes(app, api)` is called on this unauthenticated `api` group and registers four handlers with no auth wrapper: [2](#0-1) 

By contrast, `debugRoutes` wraps `/debug/vars` in `auth.Authenticate(...)`: [3](#0-2) 

And `metricRoutes` (native Go pprof) is only ever invoked inside the authenticated `authv2` group: [4](#0-3) 

The handlers in `core/web/loop_registry.go` confirm the exposure: `discoveryHandler` lists all registered plugins' metrics paths, `pluginMetricHandler` proxies `/metrics` from the plugin's internal Prometheus port, and `pluginPPROFHandler`/`pluginPPROFPOSTSymbolHandler` forward attacker-supplied `:profile` wildcards into requests against the plugin's internal `/debug/pprof/*` endpoints: [5](#0-4) [6](#0-5) 

None of these handlers reference `auth.Authenticate`, `RequiresEditRole`, or any role check — confirmed by grep across `loop_registry.go`, which returns no matches for authentication constructs. The only test file present (`loop_registry_internal_test.go`) exercises internal error paths of `discoveryHandler` and does not touch authentication at all, so there is no evidence the omission was an intentional, tested design decision.

## Impact Explanation
This maps to unauthorized information disclosure of internal node/plugin state — Prometheus metrics reveal plugin topology and internal hostnames/ports, and `pprof` heap/goroutine/trace dumps can expose in-memory secrets, request data, or other sensitive runtime state of LOOP plugin processes. This is a legitimate node API authentication bypass class finding: an unauthenticated client can reach data that should require session/token authentication, consistent with how every comparable route (`/debug/vars`, `/debug/pprof/*`) in this exact file is protected.

## Likelihood Explanation
High. The routes are reachable on the standard node HTTP port without any credentials — subject only to the generic rate limiter shared with all authenticated routes — and require no special preconditions beyond the node running LOOP plugins, which is a normal production configuration for OCR2/plugin-based deployments. The attack requires zero privilege and is trivially repeatable via plain HTTP GET/POST requests.

## Recommendation
Wrap `loopRoutes` registrations with `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)` (matching the pattern used for `debugRoutes` and `authv2`/`metricRoutes`), and apply an appropriate role check (e.g., `RequiresEditRole`/`RequiresAdminRole`) given the sensitivity of raw pprof dumps. Alternatively, move these endpoints off the public web server entirely onto an internal-only listener not exposed to external clients.

## Proof of Concept
Against a running node with LOOP plugins configured, without any session cookie or Authorization header:
```
GET /discovery HTTP/1.1
Host: <node>:6688
```
returns plugin discovery JSON (per `discoveryHandler`, `core/web/loop_registry.go:52-65`), and:
```
GET /plugins/<pluginName>/debug/pprof/heap HTTP/1.1
Host: <node>:6688
```
returns a full heap dump of the named plugin process, since `loopRoutes(app, api)` in `core/web/router.go:230-236` is mounted on the `api` group with no `auth.Authenticate` middleware in the call chain, unlike `debugRoutes` (`router.go:180-183`) and `metricRoutes` (`router.go:445-447`).

```go
// discoveryHandler implements service discovery of prom endpoints for LOOPs in the registry
func (l *LoopRegistryServer) discoveryHandler(w http.ResponseWriter, req *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	groups := make([]*targetgroup.Group, 0, 1+len(l.registry.List()))

	// add node metrics to service discovery
	groups = append(groups, pluginGroup(l.discoveryHostName, l.exposedPromPort, "/metrics"))

	// add all the plugins
	for _, registeredPlugin := range l.registry.List() {
		group := pluginGroup(l.discoveryHostName, l.exposedPromPort, pluginMetricPath(registeredPlugin.Name))
		group.Labels[LabelMetaPluginName] = model.LabelValue(registeredPlugin.Name)
		groups = append(groups, group)
	}
```

```go
func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
```
