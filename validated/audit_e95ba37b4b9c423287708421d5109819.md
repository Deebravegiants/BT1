### Title
Sensitive Bridge/External-Initiator secrets and other non-"password" secrets are logged in plaintext in Debug-level HTTP request logs - (File: core/web/router.go)

### Summary
The chainlink node's global HTTP request-logging middleware `loggerFunc` in [1](#0-0)  logs the full raw request body of every API call at Debug level. The sanitization it applies, `readSanitizedJSON`/`redact`, only strips fields whose key literally contains the substring "password" [2](#0-1) . This mirrors the root cause of GHSA-8fm4-r23p-v68v (Jenkins MQ Notifier): a debug-mode logging path that captures sensitive parameters that were never meant to be persisted to the log stream.

### Finding Description
`NewRouter` registers `loggerFunc(app.GetLogger())` as global middleware applied to every route in the engine, including bridge and external-initiator management endpoints [3](#0-2) . `loggerFunc` reads the entire request body and, when `LOG_LEVEL=debug`, logs it as a `body` field after passing it through `readBody`/`readSanitizedJSON` [4](#0-3) . The only redaction logic is the `isBlacklisted` check, which matches only keys equal to or containing "password" (`password`, `newpassword`, `oldpassword`, `current_password`, `new_account_password`) [5](#0-4) .

Bridge and External Initiator create/update requests carry secret fields that are explicitly designed to be write-only/one-time-displayed and are hidden from normal API JSON responses (`OutgoingToken`, `IncomingAccessKey`, `IncomingSecret`, `OutgoingSecret` in [6](#0-5)  and [7](#0-6) , redacted in the corresponding presenters). None of these field names contain "password", so they are not caught by the blacklist and get written verbatim into the request-body debug log when a client calls `POST /v2/bridge_types` or `POST /v2/external_initiators`.

### Impact Explanation
Any secret submitted through JSON request bodies whose key does not contain "password" is captured in cleartext in the node's log output whenever debug logging is enabled (a supported, user-toggleable mode, e.g. via the `/v2/log` PATCH endpoint at [8](#0-7) , or `LOG_LEVEL=debug` config). This includes bridge `OutgoingToken` (used to authenticate to external adapters) and external-initiator `IncomingAccessKey`/`IncomingSecret`/`OutgoingSecret`/`OutgoingToken` — credentials that the presenters deliberately hide from API responses precisely because they are sensitive. Anyone with access to the node's logs (log aggregation systems, shared operator tooling, support bundles) can recover these secrets even though the application's own response-serialization layer treats them as confidential. This is a direct match to CWE-532.

### Likelihood Explanation
Debug-level logging is a normal, commonly enabled operational mode (not an exotic configuration), and creating/rotating bridges or external initiators is a routine admin action. Every such request passes through the shared `loggerFunc` middleware automatically — there is no per-route opt-out or field-level redaction beyond the password blacklist — so the exposure is triggered incidentally by normal usage, without any special exploitation effort.

### Recommendation
Extend the redaction blacklist in `isBlacklisted`/`readSanitizedJSON` (`core/web/router.go`) beyond `password` substrings to cover all known secret-bearing fields (e.g., `token`, `secret`, `accesskey`, `outgoingtoken`, `incomingsecret`, `outgoingsecret`, or better, an explicit allowlist/structural redaction driven by the presenter's own "sensitive field" metadata) before the raw body is ever logged. Alternatively, disable full-body debug logging for endpoints known to accept credentials, or redact known secret field names at the model level so the sanitizer redacts consistently regardless of endpoint.

### Proof of Concept
1. Enable debug logging: `PATCH /v2/log {"level":"debug"}` (see [8](#0-7) ).
2. Create a bridge with a secret outgoing token: `POST /v2/bridge_types` with body `{"name":"mybridge","url":"http://adapter","outgoingToken":"SUPER_SECRET_TOKEN"}`.
3. Observe the node's application log: the `loggerFunc` middleware writes a Debug entry containing `"body":"{...\"outgoingToken\":\"SUPER_SECRET_TOKEN\"...}"`, because `outgoingToken` does not match the `password`-only blacklist in `isBlacklisted` [9](#0-8) , while the corresponding HTTP JSON *response* to the same call redacts/omits the token per the bridge presenter.

func loggerFunc(lggr logger.Logger) gin.HandlerFunc {
	return func(c *gin.Context) {
		buf, err := io.ReadAll(c.Request.Body)
		if err != nil {
			lggr.Error("Web request log error: ", err.Error())
			// Implicitly relies on limits.RequestSizeLimiter
			// overriding of c.Request.Body to abort gin's Context
			// inside io.ReadAll.
			// Functions as we would like, but horrible from an architecture
			// and design pattern perspective.
			if !c.IsAborted() {
				c.AbortWithStatus(http.StatusBadRequest)
			}
			return
		}
		rdr := bytes.NewBuffer(buf)
		c.Request.Body = io.NopCloser(bytes.NewBuffer(buf))

		start := time.Now()
		c.Next()
		end := time.Now()

		lggr.Debugw(fmt.Sprintf("%s %s", c.Request.Method, c.Request.URL.Path),
			"method", c.Request.Method,
			"status", c.Writer.Status(),
			"path", c.Request.URL.Path,
			"ginPath", c.FullPath(),
			"query", redact(c.Request.URL.Query()),
			"body", readBody(rdr, lggr),
			"clientIP", c.ClientIP(),
			"errors", c.Errors.String(),
			"servedAt", end.Format("2006-01-02 15:04:05"),
			"latency", fmt.Sprintf("%v", end.Sub(start)),
		)
	}

func readSanitizedJSON(buf *bytes.Buffer) (string, error) {
	var dst map[string]any
	err := json.Unmarshal(buf.Bytes(), &dst)
	if err != nil {
		return "", err
	}

	cleaned := map[string]any{}
	for k, v := range dst {
		if isBlacklisted(k) {
			cleaned[k] = "*REDACTED*"
			continue
		}
		cleaned[k] = v
	}

	b, err := json.Marshal(cleaned)
	if err != nil {
		return "", err
	}
	return string(b), err
}

func redact(values url.Values) string {
	cleaned := url.Values{}
	for k, v := range values {
		if isBlacklisted(k) {
			cleaned[k] = []string{"REDACTED"}
			continue
		}
		cleaned[k] = v
	}
	return cleaned.Encode()
}

// NOTE: keys must be in lowercase for case insensitive match
var blacklist = map[string]struct{}{
	"password":             {},
	"newpassword":          {},
	"oldpassword":          {},
	"current_password":     {},
	"new_account_password": {},
}

func isBlacklisted(k string) bool {
	lk := strings.ToLower(k)
	if _, ok := blacklist[lk]; ok || strings.Contains(lk, "password") {
		return true
	}
	return false
}
