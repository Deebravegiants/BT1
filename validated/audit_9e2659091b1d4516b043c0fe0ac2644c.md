### Title
Unauthenticated "Magic QR-code" actions allow any unprivileged person to reset the Orb's mirror calibration and Wi-Fi credentials without operator entry checks - (File: `src/plans/qr_scan/operator.rs`, `src/plans/mod.rs`)

### Summary
Analogous to the MarginRouter `crossSwap[Exact]TokensFor[Exact]Tokens` bug — where privileged trading actions execute with no check on the caller's identity and fully attacker-controlled input parameters — `orb-core`'s operator QR-code scanning step performs privileged, local hardware/network actions (mirror recalibration, Wi-Fi credential reset) triggered purely by the *content* of a scanned QR code, with no verification that the presenter is an authorized operator.

### Finding Description
During every signup attempt, the orb first scans what it expects to be an "operator" QR code via `scan_operator_qr_code`, which just decodes whatever is shown to the camera with no identity check at that point [1](#0-0) . The decoded value is passed to `handle_magic_operator_qr_code`, which special-cases two "magic" QR-code payloads and executes privileged local actions immediately — before any backend validation of the operator ever occurs: [2](#0-1) 

The QR content matched against these magic actions is a plain, unauthenticated regex match on arbitrary text with no cryptographic signature or backend check: [3](#0-2) 

Only *after* this magic-action branch — for the `Normal` variant — does the code proceed to `verify_operator_qr_code`, which calls the backend to check that the operator ID is registered/valid [4](#0-3) . The magic actions bypass this backend authorization entirely: `MagicResetMirror` calls `reset_mirror_calibration`, which overwrites the persisted mirror calibration file and re-applies it to the hardware [5](#0-4) , and `MagicResetWifi` calls `reset_wifi_and_ensure_network`, which restores the default `wpa_supplicant` config (dropping the current Wi-Fi connection) and re-enters the Wi-Fi-provisioning flow that accepts new SSID/password from the next QR code scanned [6](#0-5) [7](#0-6) .

This mirrors the root cause of the referenced finding precisely: a function reachable by any caller/content, with no check on "who" is presenting the input and no validation that the parsed content is legitimate before it drives a privileged, security-relevant action.

### Impact Explanation
Any person who can present a QR code to the orb's camera during the operator-scanning phase — not necessarily a vetted, registered operator — can print/display the string `magic_action:reset_wifi_credentials` or `magic_action:reset_mirror_calibration` and force the orb to: (1) drop its current Wi-Fi connection and enter Wi-Fi provisioning mode, allowing an attacker to redirect the orb onto an attacker-controlled network (a foothold for further attacks such as backend traffic interception, denial of service, or in combination with a network MITM, manipulation of biometric/signup requests), or (2) silently reset the mirror's calibration to factory defaults mid-operation, degrading eye-tracking/focus accuracy in ways that could be leveraged to force capture failures or facilitate fraud/liveness-bypass attempts during subsequent biometric captures. Both actions require no authorization token, no valid operator ID, and no interaction with the backend prior to execution.

### Likelihood Explanation
Likelihood is high: the magic strings are static, unauthenticated, and publicly derivable from the open-source regex/match arms in `qr_scan/operator.rs`; any bystander with a printed QR code and physical access to the orb during the idle/operator-scan phase can trigger the action with a single scan, no special tooling or credentials required.

### Recommendation
Require the same backend-mediated operator authorization (`verify_operator_qr_code` / operator-status check) before executing `MagicResetMirror` / `MagicResetWifi`, or otherwise cryptographically sign/whitelist magic QR-code payloads so they can only be produced by trusted operators, and rate-limit/log these privileged actions distinctly from normal signup flow.

### Proof of Concept
1. Print or display a QR code containing the literal text `magic_action:reset_wifi_credentials`.
2. Present it to the orb's camera during the "Operator QR-code scanning" phase (`scan_operator_qr_code` in `src/plans/mod.rs`).
3. `Data::try_parse` in `src/plans/qr_scan/operator.rs` matches the `MAGIC_QR_CODE` regex and returns `Data::MagicResetWifi` without any authentication.
4. `handle_magic_operator_qr_code` immediately invokes `reset_wifi_and_ensure_network`, which calls `network::reset()` (restoring default wpa_supplicant config and disconnecting) and then `wifi::Plan.ensure_network_connection`, prompting the orb to scan a new Wi-Fi MECARD QR code — which the same unauthenticated attacker can then supply to join the orb to an attacker-controlled network.
5. Repeat with `magic_action:reset_mirror_calibration` to silently wipe the persisted mirror calibration via `reset_mirror_calibration`.

static MAGIC_QR_CODE: Lazy<Regex> = Lazy::new(|| {
    Regex::new(
        r"(?x)
        ^
        magic_action
        :
        (?P<magic_action>[\w]+)
        $
    ",
    )
    .expect("bad regex")
});

/// Operator QR-code data.
#[derive(Clone, Debug)]
pub enum Data {
    /// Normal Operator QR-code.
    Normal(user::Data),
    /// Action to reconfigure WiFi.
    MagicResetWifi,
    /// Action to reset mirror calibration.
    MagicResetMirror,
}

impl Schema for Data {
    fn ui() -> ui::QrScanSchema {
        ui::QrScanSchema::Operator
    }

    fn try_parse(code: &str) -> Option<Self> {
        let normal = user::Data::try_parse(code)
            .filter(
                |d| if d.signup_extension() { d.signup_extension_config.is_some() } else { true },
            )
            .map(Data::Normal);
        if normal.is_some() {
            return normal;
        }
        if let Some(captures) = MAGIC_QR_CODE.captures(code) {
            return match captures
                .name("magic_action")
                .expect("magic_action group must be present")
                .as_str()
            {
                "reset_wifi_credentials" => Some(Data::MagicResetWifi),
                "reset_mirror_calibration" => Some(Data::MagicResetMirror),
                _ => None,
            };
        }
        None
    }

/// Then forces wpa_supplicant to re-read its configuration file,

pub async fn reset() -> Result<()> {
    spawn_blocking(move || {
        Command::new(WPA_SUPPLICANT_INTERFACE_BIN)
            .arg("restore-default-config")
            .status()
            .wrap_err("running `wpa-supplicant-interface`")?
            .success()

            .arg("reconfigure")

            .then_some(())
