### Title
Bad debt is socialized only after withdrawals, allowing early suppliers to exit unimpaired - (File: `contracts/pool/src/ops/withdraw.rs`)

### Summary
XOXNO Lending resolves ordinary withdrawals against the current supply index and only verifies that pool cash covers the payout, while bad debt is not written into the supply index until a later liquidation or cleanup invokes `PoolSeizeEntry::Borrow`. [1](#0-0) [2](#0-1)  Consequently, once a borrower becomes publicly insolvent but before a liquidation transaction socializes the loss, an unprivileged supplier can withdraw at the pre-write-down index and transfer the eventual loss to the remaining suppliers. [3](#0-2) 

### Finding Description
`Controller.withdraw` is callable by an account owner or delegate and accepts a zero asset amount as a withdraw-all request. [4](#0-3)  The controller converts that request into a `PoolWithdrawEntry` containing the sender's current scaled supply position and the withdraw-all sentinel. [5](#0-4) 

The pool then resolves the withdrawal using only the position shares and the market's currently stored `supply_index`. [6](#0-5)  Its liquidity gate checks accounting `cash`, but it does not check whether another account's debt is already economically unrecoverable. [7](#0-6)  `require_reserves` is satisfied whenever pool cash is at least the requested transfer amount. [8](#0-7) 

Bad debt is applied separately through seizure: a `Borrow` seize entry computes the unpaid debt at the borrow index, calls `apply_bad_debt_to_supply_index`, and burns the debt. [9](#0-8)  The write-down reduces the affected market's supply index, spreading the realized loss pro rata across all supply shares that remain at that point. [10](#0-9)  Because suppliers who already withdrew no longer hold shares in that market, their former pro-rata share of the loss is shifted onto suppliers who did not exit. [11](#0-10) 

The repository's own regression test demonstrates the missing ordering: after Alice becomes liquidatable, Bob withdraws before liquidation, recovers his full supplied balance, and Carol's loss increases by approximately her relative share amplification. [12](#0-11) 

### Impact Explanation
Remaining suppliers suffer a disproportionate share of realized bad debt and can lose substantially more than their pro-rata allocation. [13](#0-12)  In the limiting case, early withdrawals can consume the available cash before the index write-down, leaving later suppliers with claims that cannot be paid from pool reserves. [8](#0-7)  This creates theft or permanent loss of user funds, and it also creates a first-mover withdrawal race whenever collateral prices make a borrowing account publicly insolvent. [14](#0-13) 

### Likelihood Explanation
No privileged role, leaked key, oracle manipulation, or contract upgrade is required: the caller only needs to own or be delegated for an existing supply position and submit `Controller.withdraw` before another permissionless account calls `liquidate` or `clean_bad_debt`. [15](#0-14) [16](#0-15)  The prerequisite is a publicly liquidatable account plus enough free pool cash to fund the early withdrawal, which is a normal consequence of a collateral price decline. [17](#0-16) 

### Recommendation
Do not allow ordinary withdrawals to value supply at an index that excludes a known, executable bad-debt write-down. [18](#0-17)  The controller should atomically realize eligible bad debt before permitting the affected market's supply to exit, or maintain a market-level pending-loss reserve that blocks withdrawal value corresponding to publicly insolvent debt. [19](#0-18)  Any fix should ensure that the loss allocation performed by `apply_bad_debt_to_supply_index` applies to the supply set that existed when the account became insolvent, rather than only to suppliers who failed to win the withdrawal race. [20](#0-19) 

### Proof of Concept
1. Bob and Carol call `Controller.supply` to supply 75 ETH and 25 ETH respectively to the same hub market. [21](#0-20) 
2. Alice supplies collateral and calls `Controller.borrow` for ETH. [22](#0-21) 
3. Alice's collateral price falls until her position is liquidatable, but neither `liquidate` nor `clean_bad_debt` has executed yet. [23](#0-22) 
4. Bob calls `Controller.withdraw(caller=bob, account_id=bob_account, withdrawals=vec![(eth_hub_asset, 0)], to=None)`, where zero selects his full ETH supply. [24](#0-23) 
5. The pool resolves Bob's shares at the unchanged supply index, verifies cash with `require_reserves`, burns Bob's shares, and transfers the underlying to him. [1](#0-0) 
6. A liquidator then calls `Controller.liquidate` for Alice's ETH debt; the borrow-side pool seize path burns the residual debt and lowers the ETH supply index. [25](#0-24) [9](#0-8) 
7. Because Bob's shares were already burned, Carol's remaining 25% supply position absorbs the loss that would otherwise have been divided across all original suppliers; the in-repository test measures Bob recovering at least his full balance and Carol's loss becoming more than three times the passive-case loss. [26](#0-25)

```rust
    cache.require_reserves(net_transfer);

    if !skip_utilization_check {
        guards::require_utilization_below_max(env, cache);
    }
    guards::require_supply_for_debt(env, cache);
```

```rust
/// Withdraws for an authorized owner/delegate and checks post-pool solvency.
/// Zero requests withdraw all; returns the pool's actual payouts per asset.
pub(crate) fn process_withdraw(
    env: &Env,
    caller: &Address,
    account_id: u64,
    withdrawals: &Vec<HubPayment>,
    to: Option<Address>,
) -> Vec<HubPayment> {
    validation::require_authorized_caller(env, caller);

    let mut account = storage::get_account(env, account_id);
    require_owner_or_delegate(env, account_id, caller, &account.owner);

    let recipient = to.unwrap_or_else(|| caller.clone());
    let mut cache = Context::new(env);
    require_external_recipient(env, &mut cache, &recipient);
    let aggregated = payments::aggregate_payments(env, withdrawals, payments::ZeroLeg::MeansAll);

    let paid = settle_withdraw(env, &mut account, &recipient, &aggregated, &mut cache);
    let _ = enforce_post_pool_solvency(env, &mut cache, &mut account);

    finalize_position_flow(
        env,
        account_id,
        &account,
        &mut cache,
        PositionSides::Supply,
        true,
    );
    paid
}

/// Enforces exit flags and withdraws the batch, treating zero as withdraw-all.
/// Returns each asset's actual pool payout.
fn settle_withdraw(
    env: &Env,
    account: &mut Account,
    recipient: &Address,
    aggregated: &AggregatedPayments,
    cache: &mut Context,
) -> Vec<HubPayment> {
    let mut entries: Vec<PoolWithdrawEntry> = Vec::new(env);
    for (hub_asset, amount) in aggregated.iter() {
        enforce_spoke_asset_flags(
            env,
            cache,
            account.spoke_id,
            &hub_asset,
            FreezePolicy::AllowOnExit,
        );
        let position = get_supply_position_or_panic(env, account, &hub_asset);
        let requested = if amount == 0 {
            WITHDRAW_ALL_SENTINEL
        } else {
            amount
        };
        entries.push_back(PoolWithdrawEntry {
            action: make_pool_action(&position, requested, hub_asset.clone()),
            protocol_fee: 0,
        });
```

```rust
pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
```
