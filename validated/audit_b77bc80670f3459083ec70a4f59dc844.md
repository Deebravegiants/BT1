### Title
Emporium's arbitrary `op.endpoint.call` lets any prover drain ERC20 tokens/ETH held by the Emporium contract that fall outside `circomData.erc20TokenAddresses` - (File: `contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol`)

### Summary
`EmporiumUpgradeable.runAction` decodes a fully user-supplied `EmporiumStack` from `circomData.externalActionData.externalActionMetadata` and, in the "stateless" branch, executes `op.endpoint.call{value: op.value}(op.callData)` directly from the Emporium contract with no restriction on `op.endpoint` other than blocking the two `IHinkalWallet` selectors. The only post-condition check iterates exclusively over `circomData.erc20TokenAddresses`, so any token/asset the Emporium contract holds that is not listed in that (attacker-controlled, possibly empty) array is never accounted for and can be swept to the attacker via an arbitrary call (e.g. `token.transfer(attacker, amount)` or `token.approve(attacker, max)`).

### Finding Description
`runAction` decodes the stack and only performs a balance-invariant check over `circomData.erc20TokenAddresses`: [1](#0-0) 

The loop that validates the outcome is scoped strictly to `circomData.erc20TokenAddresses`: [2](#0-1) 

`circomData.erc20TokenAddresses` and the accompanying array lengths are fully attacker-controlled (they are validated only against `dimensions` and against the calldata hash, but their *contents*, including being an empty array, are chosen by whoever builds the proof). For the Emporium action id specifically, the protocol even supports an explicit zero-token mode: [3](#0-2) 

With `erc20TokenAddresses.length == 0`, the `getBalancesForArray`/loop in `runAction` iterates zero times, so **no balance invariant is enforced at all**, while `stack.ops` can still contain operations with arbitrary `op.endpoint` and `op.callData` (stateless case, i.e. `invokeWallet == false` or `signerAddress == address(0)`): [4](#0-3) 

Any unprivileged EOA can reach this: `runAction` is only gated by `onlyAllowedRecipient`, which just checks `msg.sender == Hinkal`, and Hinkal calls it for any `externalActionId` that maps to Emporium once a valid Groth16 proof and matching `calldataHash` are presented: [5](#0-4) 

The `calldataHash`/`signedMessageHash` machinery binds the *proof owner's* intended `externalActionMetadata` to the transaction, but it does not constrain which ERC20s the attacker chooses to list in `erc20TokenAddresses` (an attacker can trivially list zero or few tokens while still embedding an arbitrary op targeting any other token contract). The Emporium contract legitimately accumulates dust/leftover ERC20 or ETH balances over time (acknowledged in code comments: "the only case when balanceChange can be < 0, when there were some funds on emporium before the call"), which is exactly the value this finding shows can be stolen.

This breaks the balance equation the report's bug class targets: value held by the external action contract is moved out via an externally-triggered call, but is not counted by the balance-conservation check because the check is scoped to a caller-chosen token list, not to "everything the contract could touch."

### Impact Explanation
Any leftover ERC20 token balance or ETH sitting on the `EmporiumUpgradeable` contract (dust from prior swaps, rounding remainders, tokens mistakenly sent to it, or unswept relay-fee remainders) can be stolen by an unprivileged attacker who only needs to submit one valid (even trivial/zero-value) Hinkal transaction. This is theft of protocol-held funds via calls the protocol itself makes, without any admin/relay/manager privilege — a High severity impact per the given classification ("theft ... of protocol/relay fees, ... executing calls or moving assets ... never authorised").

### Likelihood Explanation
High. The attacker needs only: (1) a valid shielded UTXO to build a legitimate proof (can be trivial/free via `HINKAL_EMPORIUM_ACTION_ID` zero-token mode), (2) knowledge that Emporium holds some balance of a target token/ETH (observable on-chain), and (3) to craft an `EmporiumStack` with a stateless op (`invokeWallet=false` or `signerAddress=0`) whose `endpoint`/`callData` calls the token's `transfer`/`approve` in favor of the attacker. No signature from any legitimate wallet owner is required for the stateless path, and no special role is needed to call `Hinkal.transact`.

### Recommendation
Enforce a global balance-conservation check across *all* assets the Emporium contract could plausibly hold/touch during `runAction`, not just the caller-supplied `erc20TokenAddresses` list — e.g., require an explicit, owner-curated allow-list of endpoints for stateless ops (as is done for the LI.FI router, which is `immutable` and fixed at deploy time), or disallow stateless calls whose target/selector could transfer/approve arbitrary ERC20s the contract holds. At minimum, forbid `erc20TokenAddresses.length == 0` combined with stateless ops that carry `callData` matching `transfer`/`approve`/`transferFrom` selectors on arbitrary token contracts.

### Proof of Concept
1. Attacker (or anyone) makes any Emporium-related deposit or transfer that leaves dust — e.g. a partial swap or relay-fee remainder — on `EmporiumUpgradeable`, or simply waits for such dust from normal protocol use, and confirms via a block explorer that the Emporium address holds `X` of `TargetToken` (not necessarily anything owned by the attacker).
2. Attacker builds a valid Hinkal proof/UTXO where `circomData.externalActionData.externalActionId == HINKAL_EMPORIUM_ACTION_ID` and `circomData.erc20TokenAddresses = []` (using the `formInputEmporiumMin` code path in `CircomDataBuilder.sol`), so the post-call balance check loop in `runAction` iterates zero times.
3. Attacker encodes an `EmporiumStack` in `externalActionData.externalActionMetadata` with one `EmporiumOperation` where `invokeWallet = false`, `signerAddress = address(0)` (stateless path), `endpoint = TargetToken`, `callData = abi.encodeWithSelector(IERC20.transfer.selector, attacker, X)`.
4. Attacker calls `Hinkal.transact(...)` with this `circomData` and a valid proof/signature over it (the EdDSA/EIP-712 signatures only prove the attacker legitimately owns/spends their own UTXO — they do not restrict which unrelated token `op.endpoint` targets).
5. `Hinkal._externalTransact` routes to `EmporiumUpgradeable.runAction`, which executes `TargetToken.call(transfer(attacker, X))` directly from the Emporium contract, succeeding because Emporium is `TargetToken`'s holder; the subsequent balance check is a no-op since `circomData.erc20TokenAddresses` is empty. `X` tokens are now transferred to the attacker with no debit ever recorded against the attacker's shielded balance.

    function runAction(
        CircomData calldata circomData,
        int256[] calldata deltaAmountChanges
    ) external override onlyAllowedRecipient returns (UTXO[] memory) {
        EmporiumStack memory stack = abi.decode(
            circomData.externalActionData.externalActionMetadata,
            (EmporiumStack)
        );

        uint256[] memory balancesBefore = getBalancesForArray(
            circomData.erc20TokenAddresses
        );

        verifyWallet(stack, circomData);

        for (uint256 i = 0; i < stack.ops.length; i++) {
            EmporiumOperation memory op = stack.ops[i];

            bool success;
            bytes memory err;

            // CASE 1: Stateful Interaction
            if (op.invokeWallet && stack.signerAddress != address(0)) {
                (success, err) = IHinkalWallet(stack.signerAddress)
                    .callHinkalWallet(op.endpoint, op.callData, op.value);
            }
            // CASE 2: Stateless Interaction
            else {
                bytes4 selector = bytes4(op.callData);
                if (
                    selector == IHinkalWallet.callHinkalWallet.selector ||
                    selector == IHinkalWallet.doSendToRelay.selector
                ) {
                    revert UnauthorizedWalletCall();
                }

                (success, err) = op.endpoint.call{value: op.value}(op.callData);
            }

            if (!success) {
                revert CallFailed(err);
            }
        }

    function formInputEmporiumMin(

        input = new uint256[](circomData.publicSignalCount);

        uint16 index = 0;
