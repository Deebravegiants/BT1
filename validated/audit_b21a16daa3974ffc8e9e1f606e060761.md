### Title
`_latestStateMachineHeight` is reset to a hard-coded low value on veto, allowing a previously-vetoed height to be re-accepted - (File: `evm/src/core/EvmHost.sol`)

### Summary
This is the same bug class as the `pauseTranche` finding: a monotonic security-critical state variable is overwritten with an arbitrary/hard-coded value instead of being recomputed from the remaining valid state, silently defeating the invariant a downstream check relies on.

### Finding Description
`EvmHost.deleteStateMachineCommitmentInternal` deletes a vetoed state commitment and, if the vetoed height happened to be the tracked "latest" height, resets the tracker to the constant `1` instead of the actual highest remaining verified height: [1](#0-0) 

`_latestStateMachineHeight` is the value `HandlerV2.handleConsensus` uses to decide whether a newly-verified intermediate state from the consensus client is allowed to be persisted: [2](#0-1) 

The relevant guard is `if (latestHeight != 0 && intermediate.height > latestHeight)`. Once a fraudulent/vetoed height `H` is deleted and `_latestStateMachineHeight` is force-reset to `1` (rather than to the highest still-valid height below `H`), any subsequent consensus proof carrying an intermediate state at height `H` (or any other height `> 1`, including heights that were already superseded) again satisfies `intermediate.height > latestHeight` and is written back via `storeStateMachineCommitment`, which unconditionally overwrites `_stateCommitments` and `_latestStateMachineHeight` for that height: [3](#0-2) 

This exactly mirrors the `pauseTranche` root cause: `pauseTranche = borrowTier` (unconditional overwrite instead of `max(borrowTier, pauseTranche)`) let a later, lower borrower tier erase the protective state set by an earlier, higher one. Here, `_latestStateMachineHeight[...] = 1` (unconditional overwrite instead of recomputing the true remaining maximum) erases the protection that a vetoed height's replacement should not be reintroducible below the previously-known-good frontier.

The Substrate side (`pallet-ismp`) already documents an analogous, narrower symptom of the same "veto rewinds the latest pointer" design, confirming the pattern exists across implementations of the protocol: [4](#0-3) 

### Impact Explanation
If the "latest height" tracker is rewound to `1` instead of the true remaining highest valid height, a malicious or compromised relayer/consensus-client combination can resubmit a consensus proof reintroducing a commitment for the exact height that fishermen/verifiers had already vetoed as fraudulent (or any stale height that had been superseded). `handleConsensus`'s only defense against replay of the same state is `keccak256(previousState) == keccak256(verifiedState)`, which checks the encoded client state, not the per-height intermediate commitments — so a differently-encoded consensus proof carrying the same (or another) previously-invalidated height's intermediate state passes the `intermediate.height > latestHeight` check again. This re-establishes an unsound `StateCommitment` at that height, which `HandlerV2.handlePostRequests`/`handleGetResponses`/timeout handlers then trust for Merkle-proof verification — i.e., forged message delivery / unsound state commitment against the exact primitives called out as in-scope (state membership proofs, consensus verification, ISMP handling).

### Likelihood Explanation
This requires a veto/fraud-proof event to have first occurred against the latest height (a bad-debt-equivalent precondition, just as in the original finding), and a consensus client whose `verify()` can still be induced to re-emit an intermediate state at (or below) the vetoed height. It is not trivially exploitable by an arbitrary unprivileged caller in one transaction, but it is reachable through the normal, permissionless `handleConsensus` relaying path once the precondition (a veto having occurred) is met, matching the original report's "medium likelihood, requires a rare precondition" profile.

### Recommendation
On veto, recompute `_latestStateMachineHeight[stateMachineId]` as the true maximum height with a live, non-deleted `_stateCommitments` entry (or track a monotonically-non-decreasing frontier explicitly), rather than resetting it to the hard-coded sentinel `1`. At minimum, `storeStateMachineCommitment`/`handleConsensus` should refuse to re-accept a height that has previously been explicitly vetoed (e.g., via a persistent "vetoed heights" set checked before write), independent of what `_latestStateMachineHeight` currently reads.

### Proof of Concept
1. Attacker-influenced/compromised consensus client causes `handleConsensus` to legitimately store a fraudulent commitment at height `H` as the new latest height (`_latestStateMachineHeight = H`).
2. A fisherman detects the fraud and the host's `handler` calls `deleteStateMachineCommitment(height=H, fisherman)`, which deletes the commitment and, per `EvmHost.sol:719-721`, sets `_latestStateMachineHeight[stateMachineId] = 1` because `H` was the latest.
3. The same (or colluding) relayer resubmits a consensus proof to `handleConsensus` whose verified intermediate state again reports height `H` (or any height `> 1`, potentially the same fraudulent commitment). Since `H > 1`, the guard `intermediate.height > latestHeight` passes, and `storeStateMachineCommitment` rewrites `_stateCommitments[stateMachineId][H]` and `_latestStateMachineHeight[stateMachineId] = H` — reinstating a state that had already been ruled fraudulent and vetoed, which downstream `HandlerV2` proof-verification functions will now trust.

    /**
     * @dev Delete the state commitment at given state height.
     */
    function deleteStateMachineCommitmentInternal(StateMachineHeight memory height, address fisherman) internal {
        StateCommitment memory stateCommitment = _stateCommitments[height.stateMachineId][height.height];
        delete _stateCommitments[height.stateMachineId][height.height];
        delete _stateCommitmentsUpdateTime[height.stateMachineId][height.height];
        // technically any state commitment can be vetoed, safety check that it's the latest before resetting it.
        if (_latestStateMachineHeight[height.stateMachineId] == height.height) {
            _latestStateMachineHeight[height.stateMachineId] = 1;
        }

        // track the fisherman responsible for rewards on hyperbridge through state proofs
        _vetoes[height.stateMachineId][height.height] = fisherman;

        emit StateCommitmentVetoed({
            stateMachineId: this.stateMachineId(_hostParams.hyperbridge, height.stateMachineId),
            stateCommitment: stateCommitment,
            height: height.height,
            fisherman: fisherman
        });
    }

    function handleConsensus(IHost host, bytes calldata proof) external notFrozen(host) {
        uint256 delay = block.timestamp - host.consensusUpdateTime();
        if (delay >= host.unStakingPeriod()) revert ConsensusClientExpired();

        bytes memory previousState = host.consensusState();
        (bytes memory verifiedState, IntermediateState[] memory intermediates, uint256 nextAuthoritySetId) =
            IConsensusV2(host.consensusClient()).verify(previousState, proof);

        if (keccak256(previousState) == keccak256(verifiedState)) return;
        host.storeConsensusState(verifiedState);

        uint256 intermediatesLen = intermediates.length;
        for (uint256 i = 0; i < intermediatesLen; i++) {
            IntermediateState memory intermediate = intermediates[i];
            uint256 latestHeight = host.latestStateMachineHeight(intermediate.stateMachineId);
            if (latestHeight != 0 && intermediate.height > latestHeight) {
                StateMachineHeight memory stateMachineHeight =
                    StateMachineHeight({stateMachineId: intermediate.stateMachineId, height: intermediate.height});
                host.storeStateMachineCommitment(stateMachineHeight, intermediate.commitment);
            }
        }
