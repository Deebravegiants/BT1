**Reasoning:** The premise that `PackClosure(FunctionHandleIndex, ClosureMask)` can be constructed with a mask that "omits or duplicates capture slots relative to the target function's signature" is not possible in this codebase — the invariant is enforced by the bytecode verifier before any such `Instruction` reaches execution, and again defensively at runtime.

- At bytecode-verification time, `instruction_consistency.rs::check_closure_mask` rejects any mask whose highest set bit exceeds the target function's parameter count (`INVALID_CLOSURE_MASK`) before the module can be published or executed: [1](#0-0) 
- `type_safety.rs::clos_pack` further validates that captured stack argument types are assignable to the corresponding parameter types selected by the mask, rejecting `Instruction`s where the captured arguments don't match the declared signature (`PACK_TYPE_MISMATCH_ERROR`), and also rejects reference-typed captures: [2](#0-1) 
- Even at execution time, the interpreter re-validates via `verify_pack_closure` (and async checks) before pushing the closure value, so a mismatched mask cannot slip through even if verification were somehow bypassed for a given execution context: [3](#0-2) 
- For the `mono-move` runtime path (a separate, lower-level IR), `verify_pack_closure`/`verify.rs` performs an analogous per-slot size/alignment check between captured arguments and the callee's declared `param_slots`, rejecting mismatches with `ClosureMaskExceedsParams`/`PackClosure: captured[...] != callee param_slots[...]` errors: [4](#0-3) 
- Additionally, `CallClosure` re-validates the closure's declared signature against the actually loaded callee's parameter/result counts at call time, so even a hypothetical corrupted closure value would be caught before invocation: [5](#0-4) 

Since `instr.rs` line 343 (`B::PackClosure(idx, mask) => O::PackClosure(idx, mask)`) is a pure conversion that runs only after the module has already passed bytecode verification (`check_closure_mask`, `clos_pack`), there is no way for attacker-controlled bytecode to produce an `Instruction::PackClosure` with a mask/capture-signature mismatch — the verifier rejects such modules at load/publish time, well before any dispatchable fungible-asset hook or store reference could be manipulated. This does not cross a custody boundary because the ownership/authority checks (mask-to-signature validation) already close the path, per the review's own rejection criterion.

        func_handle_index: FunctionHandleIndex,
