Investigation: the reported bug class (unsafe `approve()` not handling non-standard ERC20 tokens, e.g. USDT requiring zero-allowance reset) has no structural analog in this codebase. `raydium-amm` is a Solana program using SPL Token instructions exclusively through `Invokers` in `program/src/invokers.rs`, which only wraps `transfer`, `transfer_with_authority`, `burn`, `mint_to`, `close_account`, `set_authority`, `sync_native`, `withdraw_excess_lamports`, and `unwrap_lamports` — there is no `approve`/allowance-based instruction anywhere in the codebase (`grep_search` for `approve` returned zero matches).

All fund movements in the swap, deposit, withdraw, and initialize2 paths use direct `token_transfer`/`token_transfer_with_authority` CPIs under PDA authority rather than an approve+transferFrom allowance pattern, e.g. in the swap handlers [1](#0-0)  and deposit handler [2](#0-1) . The `Invokers` struct itself contains no approve wrapper [3](#0-2) . Since the SPL Token approve/allowance mechanism is not used by this AMM at all, the "unsafe approve halts auction/burns bond" bug class from the Solidity report has no reachable equivalent path here.

    /// Issue a spl_token `Transfer` instruction.
    pub fn token_transfer<'a>(
        token_program: AccountInfo<'a>,
        source: AccountInfo<'a>,
        destination: AccountInfo<'a>,
        owner: AccountInfo<'a>,
        deposit_amount: u64,
    ) -> Result<(), ProgramError> {
        let ix = spl_token::instruction::transfer(
            token_program.key,
            source.key,
            destination.key,
            owner.key,
            &[],
            deposit_amount,
        )?;
        solana_program::program::invoke_signed(
            &ix,
            &[source, destination, owner, token_program],
            &[],
        )
    }

    /// Issue a spl_token `Transfer` instruction.
    pub fn token_transfer_with_authority<'a>(
        token_program: AccountInfo<'a>,
        source: AccountInfo<'a>,
        destination: AccountInfo<'a>,
        authority: AccountInfo<'a>,
        amm_seed: &[u8],
        nonce: u8,
        amount: u64,
    ) -> Result<(), ProgramError> {
        let authority_signature_seeds = [amm_seed, &[nonce]];
        let signers = &[&authority_signature_seeds[..]];
        let ix = spl_token::instruction::transfer(
            token_program.key,
            source.key,
            destination.key,
            authority.key,
            &[],
            amount,
        )?;
        solana_program::program::invoke_signed(
            &ix,
            &[source, destination, authority, token_program],
            signers,
        )
    }

    pub fn token_set_authority<'a>(

            authority_type,

        )?;
        solana_program::program::invoke_signed(&ix, &[account, authority, token_program], signers)
    }
