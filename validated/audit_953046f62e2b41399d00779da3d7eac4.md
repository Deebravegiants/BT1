### Title
Call-decompressor's unsigned `decompress_call` may bypass `IsmpCallFilter`'s BEEFY SP1 enforcement via an unconditional `pre_dispatch` - (File: `modules/pallets/call-decompressor/src/lib.rs`)

### Summary
Gargantua and Nexus runtimes install an `IsmpCallFilter` (`BaseCallFilter`) specifically to prevent raw, SP1-unverified BEEFY consensus updates from reaching `pallet_ismp::Call::handle_unsigned` — every such update must instead flow through `pallet-beefy-consensus-proofs::submit_proof`, which enforces SP1 zk verification before advancing consensus state. However, `pallet-call-decompressor` provides a second path to invoke arbitrary decoded `RuntimeCall`s (including `pallet_ismp::Call::handle_unsigned`) via its own unsigned `decompress_call` extrinsic. Its `ValidateUnsigned` implementation manually re-checks `BaseCallFilter::contains(&runtime_call)` only inside `validate_unsigned` (the tx-pool gossip/mempool gate), while `pre_dispatch` — the check that actually runs at block-execution/inclusion time — is hard-coded to always return `Ok(())`.

### Finding Description
The runtime-level filter is documented as load-bearing security: [1](#0-0) 

`pallet-call-decompressor` re-executes decoded calls from an unsigned extrinsic, and only performs the equivalent `BaseCallFilter` check inside `validate_unsigned`: [2](#0-1) 

Critically, `pre_dispatch` — the hook invoked during actual extrinsic application/block execution for unsigned transactions — is a no-op that unconditionally succeeds: [3](#0-2) 

`validate_unsigned` only gates transaction-pool admission/gossip; it is not guaranteed to be re-run for every extrinsic that ends up included in a block (e.g. direct submission to a block-authoring node, or reordering/inclusion races). Because `pre_dispatch` performs no equivalent check, if a `decompress_call` extrinsic carrying a decompressed `pallet_ismp::Call::handle_unsigned { messages: [Message::Consensus(BEEFY proof)] }` reaches block execution without transiting the txpool's `validate_unsigned`, the decompressor's internal `decode_and_execute` path (which must use an unfiltered dispatch path to invoke `pallet_ismp::Call::handle_unsigned` under an unsigned pseudo-origin, since a normal `.dispatch()` on the generated `RuntimeCall` would already reapply `BaseCallFilter` and make the manual check in `validate_unsigned` redundant) would execute the raw BEEFY consensus update, completely bypassing the `IsmpCallFilter`'s SP1-verification requirement that the runtime comment explicitly calls out as the reason the filter exists.

This mirrors the Casdoor advisory precisely: a security-relevant check (`checkMfaEnable` / `IsmpCallFilter`'s BEEFY block) is correctly invoked on one code path (normal login / mempool `validate_unsigned`) but is missing from a second, reachable code path that performs the same privileged action (social-login binding / block-inclusion `pre_dispatch` + call execution).

### Impact Explanation
If confirmed, this allows injection of an unverified/forged BEEFY consensus state update directly into `pallet-ismp`, bypassing the SP1 zkVM proof requirement that authenticates authority-set rotations, parachain header inclusion, and MMR leaf inclusion. A forged consensus state can be used to forge state commitments, enabling forged message delivery, unsound state commitments, and consequently mint/unlock of bridged assets or acceptance of fraudulent cross-chain messages — a Medium/High severity, single-transaction-reachable authentication bypass.

### Likelihood Explanation
The `decompress_call` extrinsic is dispatched with `ensure_none(origin)` (unsigned, permissionless) and is reachable by anyone submitting an unsigned extrinsic to a node. Exploitation depends on the extrinsic reaching block execution without passing through the txpool's `validate_unsigned` gate — this is a real but not universally guaranteed condition in Substrate (unsigned transactions can be included by any block author without re-running `validate_unsigned`, since only `pre_dispatch` runs at execution time, and this pallet's `pre_dispatch` is a no-op).

### Recommendation
Move the `BaseCallFilter::contains` check (and ideally the full `pallet_ismp::Call::handle_unsigned`/`pallet_ismp_relayer::Call::accumulate_fees` allow-list logic currently only in `validate_unsigned`) into `pre_dispatch` as well, so it is enforced at actual block-execution time regardless of whether the extrinsic passed through the transaction pool. Alternatively, ensure `decode_and_execute` dispatches the decoded `RuntimeCall` through the ordinary filtered `Dispatchable::dispatch` path rather than an unfiltered/bypass path.

/// Gargantua routes all BEEFY consensus updates through `pallet-beefy-consensus-proofs`, which
/// requires each proof to pass SP1 zkVM verification before it can advance the BEEFY state.
/// Allowing raw updates through `handle_unsigned` would bypass that requirement entirely, so
/// any batch that carries a BEEFY consensus message is rejected here. `fund_message` is also
/// disabled because gargantua uses the bandwidth model for request fees; per-message top-ups
/// have no role in that accounting.
///
/// A consensus message only names the state it updates, so we ask the host which client owns
/// that state and compare against BEEFY. Reading from the host remains correct even as more
/// states (Polkadot, Paseo) are bound to the same client over time.
pub struct IsmpCallFilter;
impl frame_support::traits::Contains<RuntimeCall> for IsmpCallFilter {
	fn contains(call: &RuntimeCall) -> bool {
		use ::ismp::{host::IsmpHost, messaging::Message};
		match call {
			RuntimeCall::Ismp(pallet_ismp::Call::fund_message { .. }) => false,
			RuntimeCall::Ismp(pallet_ismp::Call::handle_unsigned { messages }) => {
				let host = Ismp::default();
				!messages.iter().any(|message| match message {
					Message::Consensus(consensus) =>
						host.consensus_client_id(consensus.consensus_state_id) ==
							Some(ismp_beefy::BEEFY_CONSENSUS_ID),
					_ => false,
				})
			},
			_ => true,
		}
	}
}
