### Title
Unpriceable dust collateral leg permanently shields an insolvent account from `liquidate`, `withdraw` and `clean_bad_debt` — (File: contracts/controller/src/positions/liquidation/mod.rs)

### Summary
CVE-2021-3531 is a crash-on-edge-input denial of service: one malformed request shape kills an otherwise healthy component. The analog in XOXNO Lending is the strict all-legs price read in account risk valuation. `supply` never reads prices, so an unprivileged borrower can attach a dust-sized supply leg on an asset whose price feed they can later break (e.g., an Aquarius LP collateral whose pool the attacker drains below `min_pool_value_wad`, or any feed that goes stale). From then on every price-dependent entrypoint on that account — `liquidate`, `withdraw`, permissionless `clean_bad_debt` and even owner-only `force_socialize_bad_debt` — reverts, leaving the bad debt permanently unclosable and unsocializable. [1](#0-0) [2](#0-1) 

### Finding Description
`socialize_bad_debt` calls `risk::calculate_account_risk_totals` over *all* `supply_positions` and `borrow_positions`, which requires a valid strict price for every leg; a single failed leg aborts the call. [3](#0-2)  The same strict read underlies liquidation HF and withdrawal risk gates. Supply itself is exempt: the controller README states "Supply needs no price", and the harness test `audit_supply_setup_blocks_liquidation_via_stale_dust_leg` shows `supply` accepting a WBTC leg while the WBTC feed is already stale, after which `try_liquidate`, `try_clean_bad_debt_by_id` and `try_withdraw` all fail with `PRICE_FEED_STALE`. [4](#0-3) [5](#0-4)  Unlike the generic stale-feed case in that test, an attacker holding LP in the Aquarius pool backing an LP-collateral leg can cause the outage themselves by pulling pool value below `min_pool_value_wad`, making the feed failure permanent rather than weather-dependent. [2](#0-1) 

### Impact Explanation
Permanent freezing of funds and protocol insolvency: the attacker's own collateral becomes unfrozen-able (acceptable cost — it is dust), while their real debt can never be liquidated and can never be written off by `clean_bad_debt` or `force_socialize_bad_debt`, since all three paths compute risk totals over every leg. Interest accrues on debt the protocol cannot touch, and suppliers' claims are eroded with no remediation path that does not require the attacker to cooperate.

### Likelihood Explanation
Fully within a single unprivileged address's reach: open an account, `borrow`, `supply` a dust amount of an Aquarius-LP collateral asset, then execute own trades/withdrawals on that Aquarius pool to push it below `min_pool_value_wad`. Cost is the dust leg plus the attacker's own LP position; no privileged role, no oracle dishonesty within bands, no third-party cooperation.

### Recommendation
Decouple dust leg pricing from account-critical reads: e.g., treat supply legs whose floored token value is below a small threshold (or below 3 decimals / one raw unit) as zero-value and price-optional in `calculate_account_risk_totals`, or skip legs whose price read fails while keeping their contribution at zero for risk purposes. At minimum, let `clean_bad_debt`/`force_socialize_bad_debt` tolerate a failed price on a dust-valued leg so insolvent accounts remain socializable.

### Proof of Concept
Reproduced by `tests/test-harness/tests/controller/audit_supply_stale_shield.rs` and `audit_liquidate_and_clean_bricked_by_unpriceable_dust_leg.rs`: supply collateral, borrow, plant a 0.001-unit leg on an asset with a stale feed (supply succeeds), drop the collateral price so HF < 1, then observe `liquidate`, `clean_bad_debt` and `withdraw` all reverting `PRICE_FEED_STALE` until the feed recovers — recovery the attacker can prevent indefinitely for an LP-priced leg by keeping the pool drained. /// Admission condition for bad-debt socialization.
#[derive(Clone, Copy, PartialEq)]
enum BadDebtGate {
    /// Permissionless: insolvent *and* collateral at or below the dust threshold.
    DustCapped,
    /// Owner-only: insolvent alone, with no cap on the collateral left behind.
    InsolventOnly,
}

/// Requires open debt and the selected insolvency gate, then cleans up the account.
fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    bad_debt::execute_bad_debt_cleanup(env, &mut cache, account_id, &account, &totals);
}
