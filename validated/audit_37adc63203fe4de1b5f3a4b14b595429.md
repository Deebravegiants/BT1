### Title
IntentGatewayV2's fee-swap accounting assumes a Uniswap V2 return-value contract that `GnosisUniswapV2Wrapper` does not honor, causing solver/user excess native token to be silently absorbed instead of refunded - (File: `evm/src/utils/uniswapv2/GnosisUniswapV2Wrapper.sol`, `evm/src/apps/IntentGatewayV2.sol`)

### Summary
`IntentGatewayV2.placeOrder` pays the Hyperbridge dispatch fee in `feeToken` by calling `IUniswapV2Router02(uniswapV2).swapETHForExactTokens{value: msgValue}(order.fees, path, address(this), block.timestamp)` and then subtracts `amounts[0]` from the tracked `msgValue` before refunding the remainder to the caller. This mirrors the exact bug class in the referenced report: a caller decodes a swap's return array assuming a fixed semantic (`amounts[0]` = native token actually spent), but one of the pluggable implementations behind the shared `IUniswapV2Router02` interface — `GnosisUniswapV2Wrapper` — does not honor that semantic, breaking the downstream accounting that depends on it.

### Finding Description
In `evm/src/apps/IntentGatewayV2.sol`: [1](#0-0) 

`msgValue -= amounts[0]` assumes `amounts[0]` equals exactly the native token consumed for the fee purchase (order.fees worth), leaving any surplus in `msgValue` to be refunded to the user later.

The real `IUniswapV2Router02.swapETHForExactTokens` (and the project's own `UniV3UniswapV2Wrapper`/`UniV4UniswapV2Wrapper`) honor this: they swap for an **exact output** amount and refund unused ETH back to `msg.sender` (the gateway), returning `amounts[0]` as the true amount spent: [2](#0-1) [3](#0-2) 

However, `GnosisUniswapV2Wrapper` — deployed as the `uniswapV2Router()` on Gnosis chain, where native token wrapping is trivial (xDAI/WXDAI 1:1) — implements the same interface completely differently: [4](#0-3) 

It only reverts if `amountOut > msg.value`; it never refunds any excess `msg.value` over `amountOut`, and it wraps and transfers the **entire** `msg.value` to the caller (not just `amountOut`), then returns `amounts[0] = msg.value` (the full sent amount), not the amount actually needed for `order.fees`.

Because `IntentGatewayV2.placeOrder` blindly trusts `amounts[0]` as "amount spent for the fee," on Gnosis this line:
```solidity
msgValue -= amounts[0];
```
zeroes out the entire remaining `msgValue` whenever a solver/user sends more native token than `order.fees` requires (e.g., overestimating the fee, or intentionally sending headroom as is standard/recommended in the SDK per `docs/content/developers/evm/intent-gateway/placing-orders.mdx`). The excess native token is converted into `feeToken` and held by the contract, but only `order.fees` is credited to escrow (`_orders[commitment][TRANSACTION_FEES] = order.fees`): [5](#0-4) 

The subsequent "refund unspent native tokens" branch (`if (msgValue > 0) _sendValue(...)`) never fires because `msgValue` was already fully consumed by the incorrect subtraction, so the user's excess native token is not refunded and the surplus `feeToken` minted from it is not tracked anywhere as `order.fees`, escrow, or `DustCollected` — it is simply orphaned value captured by the contract.

The identical unguarded pattern also exists in the Tron fork of the contract: [6](#0-5) 

### Impact Explanation
Any user who places a cross-chain or same-chain order and pays `order.fees` in native token on a chain where `uniswapV2Router()` resolves to `GnosisUniswapV2Wrapper` loses any native token sent in excess of the exact fee requirement — funds that the SDK documentation explicitly expects to be refunded (`docs/content/developers/evm/intent-gateway/placing-orders.mdx` describes `msg.value` including headroom for the fee-token swap, with excess refunded). This is a concrete, unauthorized loss of user funds triggered by a single, unprivileged `placeOrder` transaction, matching the "concrete theft or permanent freezing of funds" bar. It is directly analogous to the source issue: a swap adapter behind a common interface returns/behaves differently than assumed by the caller's accounting, corrupting the amount used downstream.

### Likelihood Explanation
Every `placeOrder` call that pays `order.fees` with native token and supplies `msgValue` greater than the exact swap requirement (a normal and expected pattern, since exact fee-token pricing is not always known in advance and slight overpayment for slippage/safety margin is standard) triggers this on any deployment using `GnosisUniswapV2Wrapper`. No special privileges or attacker setup are required — a normal user transaction triggers the loss.

### Recommendation
Do not trust `amounts[0]` from the swap call to represent the amount of native token consumed unless the concrete `uniswapV2Router()` implementation is guaranteed to refund unused input and report the true spent amount. Instead:
- Snapshot `address(this).balance` (or a dedicated pre/post state) before and after the `swapETHForExactTokens{value: msgValue}` call and compute the ETH actually consumed as `balanceBefore - balanceAfter`, mirroring the recommendation in the source report to use `token.balanceOf(address(this))` instead of trusting a return value.
- Alternatively, fix `GnosisUniswapV2Wrapper.swapETHForExactTokens` to transfer only `amountOut` worth of wrapped token to the caller and refund `msg.value - amountOut` to `msg.sender`, so its behavior matches the real `IUniswapV2Router02` semantics that all callers (`IntentGatewayV2.sol`, `EvmHost.sol`) rely upon.
- Apply the same fix to the Tron fork's `placeOrder`.

### Proof of Concept
1. Deploy `IntentGatewayV2` on a chain where `IDispatcher(hostAddr).uniswapV2Router()` returns `GnosisUniswapV2Wrapper`.
2. User calls `placeOrder{value: X}(order, ...)` where `order.fees = F` (F in `feeToken`) and `X > F`'s native equivalent (e.g., user sends `X = 2 * F` in native token as safety margin).
3. Inside `placeOrder`, `swapETHForExactTokens{value: msgValue}(F, path, address(this), ...)` is called on `GnosisUniswapV2Wrapper`; it wraps and transfers the **full** `msgValue` (not just `F`) to the gateway and returns `amounts[0] = msgValue`.
4. `msgValue -= amounts[0]` sets `msgValue` to `0`.
5. `_orders[commitment][TRANSACTION_FEES] = F` is escrowed, but the excess native token (converted to `feeToken`) is neither escrowed under any order slot nor refunded to the user, since the final `if (msgValue > 0) _sendValue(msg.sender, msgValue)` check is skipped (`msgValue == 0`).
6. The user's excess native token is permanently unaccounted for in the gateway, unrecoverable through any user-facing flow.

    /**
     * @notice Swaps ETH for exact amount of tokens through V3 with deadline protection.
     * @param amountOut The exact amount of tokens to receive
     * @param path Array of token addresses representing the swap path
     * @param recipient Address that will receive the output tokens
     * @param deadline Unix timestamp deadline by which the transaction must confirm
     * @return amounts Array of amounts [ethSpent, tokensReceived]
     */
    function swapETHForExactTokens(uint256 amountOut, address[] calldata path, address recipient, uint256 deadline)
        external
        payable
        returns (uint256[] memory)
    {
        address weth = _params.WETH;
        if (path[0] != weth) revert InvalidWethAddress();

        (bool sent,) = weth.call{value: msg.value}("");
        if (!sent) revert DepositFailed();

        IV3SwapRouter.ExactOutputSingleParams memory params = IV3SwapRouter.ExactOutputSingleParams({
            tokenIn: weth,
            tokenOut: path[1],
            fee: _params.maxFee,
            recipient: recipient,
            amountOut: amountOut,
            amountInMaximum: msg.value,
            sqrtPriceLimitX96: 0
        });

        bytes memory swapCall = abi.encodeWithSelector(IV3SwapRouter.exactOutputSingle.selector, params);

        bytes[] memory data = new bytes[](1);
        data[0] = swapCall;

        bytes[] memory results = IMulticallExtended(_params.swapRouter).multicall(deadline, data);
        uint256 spent = abi.decode(results[0], (uint256));

        if (spent < msg.value) {
            uint256 refund = msg.value - spent;
            IWETH(weth).withdraw(refund);

            (bool success,) = msg.sender.call{value: refund}("");
            if (!success) revert RefundFailed();
        }

        uint256[] memory amounts = new uint256[](2);
        amounts[0] = spent;
        amounts[1] = amountOut;

        return amounts;
    }

    function swapETHForExactTokens(uint256 amountOut, address[] calldata path, address recipient, uint256 deadline)
        external
        payable
        returns (uint256[] memory amounts)
    {
        PoolKey memory poolKey = _createPoolKey(path[1]);

        bytes[] memory params = new bytes[](3);
        params[0] = abi.encode(poolKey, true, uint128(amountOut), uint128(msg.value), bytes(""));
        params[1] = abi.encode(poolKey.currency0, uint256(0), false);
        params[2] = abi.encode(poolKey.currency1, recipient, amountOut);

        bytes[] memory inputs = new bytes[](1);
        inputs[0] = abi.encode(
            abi.encodePacked(uint8(Actions.SWAP_EXACT_OUT_SINGLE), uint8(Actions.SETTLE), uint8(Actions.TAKE)), params
        );

        // Snapshot standing balance (excluding inbound msg.value) so the refund is the swap-call delta only,
        // immune to any ETH that lands on the wrapper from outside the router (e.g., selfdestruct, coinbase).
        uint256 balanceBefore = address(this).balance - msg.value;

        IUniversalRouter(_params.universalRouter).execute{value: msg.value}(
            abi.encodePacked(bytes1(uint8(Commands.V4_SWAP))), inputs, deadline
        );

        uint256 refundETH = address(this).balance - balanceBefore;

        if (refundETH > 0) {
            (bool success,) = msg.sender.call{value: refundETH}("");
            require(success, "ETH refund failed");
        }

        amounts = new uint256[](2);
        amounts[0] = msg.value - refundETH;
        amounts[1] = amountOut;
    }

    /**
     * @dev The native token for Gnosis itself is DAI so this method simply wraps
     * the native token and returns it to the caller.
     */
    function swapETHForExactTokens(uint256 amountOut, address[] calldata, address, uint256)
        external
        payable
        returns (uint256[] memory)
    {
        if (amountOut > msg.value) revert MsgValueLessThanExactAmount();

        (bool sent,) = WETH().call{value: msg.value}("");
        if (!sent) revert DepositFailed();

        IERC20(WETH()).safeTransfer(msg.sender, msg.value);

        uint256[] memory out = new uint256[](1);
