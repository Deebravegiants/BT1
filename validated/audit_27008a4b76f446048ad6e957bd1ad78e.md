### Title
Bad-debt write-down clamps `supply_index` up to `SUPPLY_INDEX_FLOOR_RAW`, leaving wiped suppliers a phantom "freed" claim that drains fresh deposits - (File: contracts/pool/src/interest.rs)

### Summary
When bad debt is socialized, `apply_bad_debt_to_supply_index` computes `remaining = total_supplied_value - bad_debt` and derives a new supply index — but then clamps it with `.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW))`. On a full wipeout (`bad_debt >= total_supplied_value`) the index is clamped *up* to `RAY/1000` instead of going to zero, so every supply share that should have been destroyed retains a residual claim of `scaled_shares × RAY/1000`. This is the exact analog of CVE-2024-4948's use-after-free class: a claim that was economically freed by the write-down remains usable and is later redeemed against unrelated state. [1](#0-0) 

### Finding Description
`apply_bad_debt_to_supply_index` (called from the seizure / bad-debt settlement paths in `contracts/pool/src/ops/seize.rs` and `net_settle.rs`) writes down `supply_index` pro-rata, capped at total supplied value, but floors the result at `SUPPLY_INDEX_FLOOR_RAW` (`RAY/1000`, see `common/src/constants/pool.rs`). [2](#0-1) 

After a wipeout, `supplied` scaled shares are not burned — only the index moved — so `unscale_supply_floor(position) > 0` for every wiped supplier while `cash == 0` and `borrowed == 0`. The phantom claim is dormant only because `cache.require_reserves(net_transfer)` in `gate_and_debit` blocks withdrawals while the pool is empty. [3](#0-2) 

The two other guards do not stop the payout once fresh cash arrives: `require_supply_for_debt` only fires when `supplied == 0 && borrowed != 0` (scaled shares still exist, debt was burned), and `require_utilization_below_max` is skipped for liquidation withdrawals and vacuous with zero debt. [4](#0-3) 

The protocol's own unit tests prove the drain: `test_raw_cache_floor_clamp_strands_claim_without_supply_guard` and `test_raw_cache_seizure_residual_would_drain_fresh_cash_without_supply_guard` show a stranded wiped position paying out `gross == fresh_deposit`, leaving `cash < fresh_supplier_claim` — i.e., the new depositor's funds are gone. [5](#0-4) 

### Impact Explanation
Any wiped-out supplier (or the dust-position holder whose debt was cleaned) holds a zombie claim worth `1/1000` of the pre-wipeout market value. The first honest user to `supply` into the dead market recapitalizes it; the zombie holder then calls `withdraw` (or `liquidate`/seize legs in `SeizeMode::Transfer`) through the normal unprivileged controller entrypoints and extracts the fresh deposit in full. Result: theft of user funds and permanent pool insolvency (`claims > cash + debt`), matching the accepted impact classes. The attacker needs no privileges — `liquidate`, `clean_bad_debt`, `supply`, and `withdraw` are all permissionless. [6](#0-5) 

### Likelihood Explanation
Triggering requires a full bad-debt wipeout — a position whose unpaid debt exceeds total supplied value, or enough accumulated bad debt to zero the market — reachable via `clean_bad_debt` on dust positions or a liquidation where collateral is exhausted, both permissionless and economically realistic in thin markets or after an oracle-gap liquidation cascade. The attacker can also *be* a wiped supplier and simply wait for or induce a fresh deposit (even dust), then withdraw. Note a caveat I could not fully verify in the remaining scope: if `recapitalize` is invoked to restore the market before fresh supply, admin recapitalization covers the hole without minting shares — but the drain does not depend on recapitalize; it needs only one honest `supply`, so the attack window is real.

### Recommendation
On full wipeout, zero the supply index AND clear `supplied`/`revenue` scaled totals (burn all outstanding shares) rather than clamping to `SUPPLY_INDEX_FLOOR_RAW`; alternatively keep a "wiped" market flag that blocks `withdraw` until `recapitalize` resets `supplied` to match restored backing. At minimum, `require_backed_market` (guards.rs:52) should be enforced on the withdraw path when the index is at the floor, so a clamped-index market cannot pay out phantom residuals against fresh cash. [7](#0-6) 

### Proof of Concept
Mirroring `contracts/pool/tests/interest.rs:430-495` at the controller level:

1. Alice supplies `S` units of USDC into hub market `(hub, USDC)`; Bob borrows against collateral in another market.
2. Collateral value collapses (or interest accrues) until Bob's debt exceeds recoverable collateral; attacker calls `liquidate` then `clean_bad_debt(account_id, ...)`. Pool seizes, `burn_debt` zeroes `borrowed`, and `apply_bad_debt_to_supply_index` clamps `supply_index` to `RAY/1000` — Alice's `scaled` shares now represent a residual claim `S/1000 > 0` with `cash == 0`.
3. Carol (or attacker-controlled fresh account) calls `supply` depositing `D ≥ S/1000`; `credit_cash(D)` makes `cash = D`.
4. Attacker (Alice, or whoever holds wiped shares) calls `withdraw(account_id, amount = i128::MAX)`. `resolve_withdrawal` computes `gross = scaled × RAY/1000 = D`; `require_reserves(D)` passes, `require_supply_for_debt` passes (`supplied > 0`, `borrowed == 0`), `debit_cash(D)` succeeds and `transfer_out` pays the attacker. [8](#0-7) 
5. Carol later calls `withdraw`; `require_reserves` fails — `cash == 0 < her claim`. Carol's deposit is permanently stolen/insolvent, exactly as the test asserts: `"cash {} cannot cover Bob's honest claim {}"`. [9](#0-8)

```rust
pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}
```

```rust
fn gate_and_debit(env: &Env, cache: &mut Cache, net_transfer: i128, skip_utilization_check: bool) {
    cache.require_reserves(net_transfer);

    if !skip_utilization_check {
        guards::require_utilization_below_max(env, cache);
    }
    guards::require_supply_for_debt(env, cache);
    cache.debit_cash(net_transfer);
```

```rust
pub(crate) fn require_supply_for_debt(env: &Env, cache: &Cache) {
    if cache.supplied() == Ray::ZERO && cache.borrowed() != Ray::ZERO {
        panic_with_error!(env, CollateralError::PoolInsolvent);

}
```
