### Title
Missing `address(0)` check on `admin` in `EvmHost`/`TestnetHost` constructor can permanently brick host initialization - (File: evm/src/core/EvmHost.sol)

### Summary
`EvmHost`'s constructor sets `_hostParams.admin = _admin` with no validation that `_admin != address(0)`, and this admin is subsequently the sole account permitted to call the one-shot `initialize(HostParams)` function. If the host is deployed (via `DeployIsmp.s.sol` or any CREATE2-based deployment flow) with `_admin` erroneously passed as `address(0)`, the host can never be initialized, permanently freezing all bridge functionality and requiring a full redeployment of the host and any already-wired manager/handler/consensus-client contracts.

### Finding Description
The `EvmHost` constructor only sets the admin and consensus timestamp, deferring all other parameters to `initialize`, but performs no zero-address check on `_admin`: [1](#0-0) 

`initialize` is guarded so that only `_hostParams.admin` may call it, and it can only be called once (`_initialized`): [2](#0-1) 

Since `_msgSender()` can never equal `address(0)` in a live transaction, if `_admin` is set to `address(0)` in the constructor, `initialize` becomes permanently uncallable by anyone — there is no other path to set `_hostParams`. This is a real risk because the constructor of `TestnetHost` simply forwards `_admin` to `EvmHost` without any additional validation either: [3](#0-2) 

By contrast, the codebase's own `HostManager` contract — which is deployed and wired to the host in the very same deploy script — explicitly guards against this exact class of bug in its constructor: [4](#0-3) 

This shows the project is aware of and treats a zero admin as a critical invariant violation elsewhere (`InvalidAdmin` error), but the check was omitted from `EvmHost`'s constructor, which is the more central, harder-to-recover contract: `EvmHost` is deployed via CREATE2 to a deterministic address across every chain specifically so its `admin` and bytecode line up chain to chain, per the constructor's own docstring. A CREATE2 deployment mistake or misconfigured deploy parameter supplying `address(0)` for `admin` would deterministically brick the host on every chain that reused the same salt/admin, not just one.

Downstream, `updateHostParamsInternal` (called both by `initialize` and by later `updateHostParams` governance calls) validates `hostManager`, `handler`, and `consensusClient` against `address(0)` and against ERC165 interface support, but never validates `params.admin`: [5](#0-4) 

So even after a successful `initialize`, a subsequent governance-driven `updateHostParams` call (routed through `HostManager`) could set `_hostParams.admin` to `address(0)` without reverting, silently disabling any future admin-gated path (e.g. `TestnetHost.updateHostParams`'s admin branch, or `setConsensusState`/`setFrozenState` admin-restricted calls) that relies on `_hostParams.admin`.

### Impact Explanation
A zero `admin` at construction permanently prevents `initialize` from ever succeeding, meaning the deployed `EvmHost` (and by extension the entire bridge instance on that chain — `HandlerV2`, `HostManager`, consensus client, and every downstream `IApp` module that would have been wired to it) can never process any cross-chain message. Recovery requires a full redeployment of the host and re-registration of state at every dependent module and off-chain relayer/indexer, which the referenced report classifies as Medium severity due to cost and operational impact rather than direct fund loss. If the zero-admin were instead injected via a subsequent `updateHostParams` governance call, admin-gated safety functions become permanently unreachable, weakening operational control over the host without any explicit revert to warn the caller.

### Likelihood Explanation
This requires a deployment-time (or governance-update-time) parameter error, not an attacker-controlled input path reachable by an ordinary user — the constructor argument is chosen by whoever deploys the contract (e.g. via `DeployIsmp.s.sol`), and `updateHostParams` is only reachable through the trusted `hostManager`/governance-relayer path. However, given the CREATE2/deterministic-address requirement discussed in the constructor's own comments, and the analogous check already present in the sibling `HostManager` contract, this is a real, plausible operational mistake class the project has otherwise defended against, matching the pattern described in the referenced report exactly (critical protocol address parameters accepted in a constructor with no zero-address validation).

### Recommendation
Add an explicit zero-address check on `_admin` in the `EvmHost` constructor, reverting with a dedicated error (e.g. `InvalidAdmin()`, mirroring `HostManager`'s pattern) if `_admin == address(0)`. Additionally, extend `updateHostParamsInternal` to validate `params.admin != address(0)` before committing `_hostParams.admin = params.admin`, consistent with the existing checks for `hostManager`, `handler`, and `consensusClient`.

### Proof of Concept
1. Deployer calls `new EvmHost(address(0))` (or `new TestnetHost(address(0))`) — succeeds, `_hostParams.admin` is set to `address(0)`.
2. Deployer (or anyone) attempts `host.initialize(params)`. `initialize` checks `_msgSender() != _hostParams.admin`; since no real transaction sender can be `address(0)`, this check always fails and reverts with `UnauthorizedAction`.
3. `_initialized` remains `false` forever; no `HostParams` can ever be set, and the host can never dispatch, verify, or accept any ISMP message. The only remedy is redeploying `EvmHost` (and rewiring `HostManager`, `HandlerV2`, the consensus client, and all `IApp` modules that reference the bricked host address).

    /**
     * @dev One-shot initializer. Can only be called once, and only by the
     * admin set in the constructor. Applies the initial `HostParams` via
     * the internal updater.
     */
    function initialize(HostParams memory params) external {
        if (_msgSender() != _hostParams.admin) revert UnauthorizedAction();
        if (_initialized) revert UnauthorizedAction();
        _initialized = true;
        updateHostParamsInternal(params);
    }
```

    function updateHostParamsInternal(HostParams memory params) internal {
        // check the params to prevent the host from getting bricked.
        if (
            params.hostManager == address(0) || address(params.hostManager).code.length == 0
                || !IERC165(params.hostManager).supportsInterface(type(IApp).interfaceId)
        ) {
            // otherwise cannot process new cross-chain governance requests
            revert InvalidHostManager();
        }

        if (
            params.handler == address(0) || address(params.handler).code.length == 0
                || !IERC165(params.handler).supportsInterface(type(IHandlerV2).interfaceId)
        ) {
            // otherwise cannot process new datagrams
            revert InvalidHandler();
        }

        if (
            params.consensusClient == address(0) || address(params.consensusClient).code.length == 0
                || !IERC165(params.consensusClient).supportsInterface(type(IConsensusV2).interfaceId)
        ) {
            // otherwise cannot process new consensus datagrams
            revert InvalidConsensusClient();
        }
```
