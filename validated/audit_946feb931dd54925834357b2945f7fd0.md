### Title
Missing `extcodesize` check in `EvmHost.dispatchIncoming(GetResponse)` and `dispatchTimeOut` allows phantom "delivery" of undeliverable messages - (File: `evm/src/core/EvmHost.sol`)

### Summary
`EvmHost.dispatchIncoming(PostRequest, ...)` explicitly checks that the resolved destination module has code before attempting delivery, returning early (leaving the request retriable/undelivered) when it does not [1](#0-0) . The sibling handler-only entry points that also resolve a destination address dynamically from message data and low-level `.call` into it — `dispatchIncoming(GetResponse, ...)`, `dispatchTimeOut(GetRequestTimeout, ...)`, and `dispatchTimeOut(PostRequestTimeout, ...)` — omit this guard entirely [2](#0-1) .

### Finding Description
Solidity's low-level `.call` to an address with no code always returns `success == true` (there is no code to execute or revert), which is exactly the class of bug the external report flags: a dynamically resolved target that may have no code, whose "no-op" outcome is indistinguishable from a successful delivery.

`dispatchIncoming(PostRequest, ...)` defends against this specifically:
```solidity
address destination = _bytesToAddress(request.to);
uint256 size;
assembly { size := extcodesize(destination) }
if (size == 0) {
    // instead of reverting the entire batch, early return here.
    return;
}
``` [3](#0-2) 

But `dispatchIncoming(GetResponse, ...)` skips straight to writing the replay-protection receipt and calling the destination:
```solidity
function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
    bytes32 commitment = response.request.hash();
    _responseReceipts[commitment] = ResponseReceipt({relayer: relayer, responseCommitment: response.hash()});
    (bool success,) = _bytesToAddress(response.request.from)
        .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));
    ...
``` [4](#0-3) 

The same pattern (no `extcodesize` check) appears in both timeout dispatchers: [5](#0-4) [6](#0-5) 

If `response.request.from` (or `timeout.request.from`) resolves to an address with no code — because the originating caller was an EOA (`dispatch`/`dispatchTimeOut` on `IDispatcher` is not restricted to contracts, and `from` is simply set to `_msgSender()`), or because the app contract self-destructed or was not yet deployed between request dispatch and response/timeout delivery — the `.call` trivially "succeeds" with empty return data. This causes the code to take the success branch unconditionally: replay-protection storage (`_responseReceipts`, deleted `_requestCommitments`) is finalized, the relayer fee is paid out, and a `*Handled` event is emitted, even though no `IApp` callback logic actually ran.

### Impact Explanation
This breaks the same invariant `dispatchIncoming(PostRequest)` is careful to preserve: a message should only be marked delivered (and only pay out relayer fees) when the destination module actually executed its callback. For GET responses/timeouts:
- The relayer is paid `meta.fee`/the request fee for a delivery that never reached real application logic.
- The response/timeout is permanently consumed (commitment deleted / receipt recorded) with no retry path, since the "failure" branch (used for genuine reverts) is never taken.
- Any application state that depends on `onGetResponse`/`onGetTimeout`/`onPostRequestTimeout` executing (e.g., escrow release or cancellation flows gated on a GET response, as in `ExtrinsicIntents.onGetResponse`) can become permanently stuck, since the protocol believes the message was delivered.

This is a fund-accounting and message-delivery-soundness issue (unearned relayer payouts, permanently undeliverable/irretryable messages) rather than a purely cosmetic one.

### Likelihood Explanation
Reachable without any privileged role: any account can call `IDispatcher.dispatch(DispatchGet)` directly (it is not gated to contracts), setting itself, an EOA, as `from`; or a legitimate app contract can self-destruct, or not yet be deployed at the time a relayer's proof for the GET response/timeout is submitted through the normal handler flow. The handler itself only checks `restrict(_hostParams.handler)`, so this triggers via completely ordinary relaying of a GET response or timeout — no admin/governance misconfiguration is required, unlike the framing in the external report for the delegatecall proxy case.

### Recommendation
Add the same `extcodesize` guard used in `dispatchIncoming(PostRequest)` to `dispatchIncoming(GetResponse, ...)`, `dispatchTimeOut(GetRequestTimeout, ...)`, and `dispatchTimeOut(PostRequestTimeout, ...)` before performing the low-level `.call`, returning early (leaving state as undelivered/retriable and withholding relayer fee) when the resolved destination has no code, mirroring:
```solidity
uint256 size;
assembly { size := extcodesize(destination) }
if (size == 0) { return; }
```

### Proof of Concept
1. An account (EOA or a contract about to self-destruct) calls `IDispatcher(host).dispatch(DispatchGet)`, which sets `request.from = abi.encodePacked(_msgSender())` [7](#0-6) .
2. Before a response/timeout proof is delivered, the destination address ends up with no code (EOA by construction, or a self-destructed contract, or a counterfactual CREATE2 address not yet deployed).
3. A relayer submits a valid state/timeout proof through the handler; `EvmHost.dispatchIncoming(GetResponse, ...)` or `dispatchTimeOut(...)` is invoked.
4. `_bytesToAddress(...).call(...)` targets the code-less address and returns `success = true` unconditionally.
5. `_responseReceipts`/commitment bookkeeping finalizes the message as delivered, the relayer is paid the fee, and the `*Handled` event fires — even though no `IApp.onGetResponse`/`onGetTimeout`/`onPostRequestTimeout` logic ever executed, and the message can never be retried.

    /**
     * @dev Dispatch an incoming GET response to source module
     * @param response - get response
     */
    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    /**
     * @dev Dispatch an incoming GET timeout to the source module.
     * @notice Does not refund any protocol fees.
     * @param timeout - timed-out get request bundled with the relayer that submitted the timeout proof
     * @param meta - fee metadata for the original request
     * @param commitment - request commitment
     */
    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }
