### Title
Outgoing authentication token for External Initiators disclosed unredacted to view-only users - (File: core/web/presenters/external_initiators.go)

### Summary
The `GET /v2/external_initiators` endpoint is accessible to users holding only the `view` role, but its response includes the `OutgoingToken` credential field in plaintext, which Chainlink uses to authenticate itself when calling back into the external initiator service.

### Finding Description
`ExternalInitiator` is a persisted credential-bearing entity used to let a third-party service authenticate requests into the node and to let the node authenticate its callbacks to that service. On creation, the model stores a hashed `HashedSecret` (for incoming auth) but keeps `OutgoingToken` and `OutgoingSecret` as plaintext fields, since the node must resend them verbatim on every outbound callback: [1](#0-0) 

`ExternalInitiatorsController.Index` (mapped to `GET /v2/external_initiators`) lists all initiators and serializes them with `presenters.NewExternalInitiatorResource`: [2](#0-1) 

That presenter explicitly copies the plaintext `OutgoingToken` into the JSON API response returned to the caller: [3](#0-2) 

The RBAC test suite confirms this route is reachable by the lowest-privileged authenticated role (`view`), not just `edit`/`admin`: [4](#0-3) 

This is directly analogous to CVE-2020-2250: a credential needed for automated/legitimate use (there, a stored project password; here, the outgoing callback token) is persisted and returned unredacted to accounts holding only a read-level role, rather than being masked/redacted the way other secret material in the codebase is (e.g. `models.Secret`/`SecretURL` types format as `"xxxxx"`, and the `OutgoingSecret` field itself is deliberately *not* included in this same resource): [5](#0-4) 

### Impact Explanation
A user who is granted the minimal `view` role (or a `view`-scoped API token, or an LDAP `NodeReadOnly` group member) can enumerate all configured external initiators and obtain each one's `OutgoingToken`. Depending on how the external-initiator service validates the outgoing callback (some deployments accept the token alone as a bearer credential in the callback header), this can enable impersonation of the Chainlink node when it "calls back" to that external service, or at minimum leaks operational secret material to an actor who should only have read access to job/run state, not to authentication tokens.

### Likelihood Explanation
Likelihood is limited by two factors: (1) the External Initiator feature must be enabled (`ExternalInitiatorsEnabled`) and initiators must exist, and (2) the practical exploitability of the leaked `OutgoingToken` alone (without the paired `OutgoingSecret`, which is correctly omitted from this resource) depends on how the receiving external-initiator server validates that token. Nonetheless, the disclosure itself — a stored authentication credential returned in plaintext to the lowest-privileged authenticated role — is a concrete instance of the same bug class as the CVE (secret exposed to a permission tier that should not see it).

### Recommendation
Redact `OutgoingToken` (and any other authentication-material fields) from `ExternalInitiatorResource`/`NewExternalInitiatorResource`, mirroring the treatment already given to `OutgoingSecret` and to `models.Secret`/`SecretURL`. If operators need to verify which token an initiator is configured with, restrict that to the one-time creation response (`ExternalInitiatorAuthentication`, already `edit`-gated) rather than the general list/read endpoint, or require `admin`/`edit` role for `GET /v2/external_initiators`.

### Proof of Concept
1. Create a user with role `view` (or an LDAP account mapped only to `ReadUserGroupCN`).
2. Ensure at least one `ExternalInitiator` exists (created previously by an `edit`/`admin` user).
3. As the `view` user, call `GET /v2/external_initiators`.
4. Observe the JSON API response contains `outgoingToken` in plaintext for every initiator, despite the requester holding only read/view privileges.

func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}

type ExternalInitiatorResource struct {

		JAID:          NewJAID(strconv.FormatInt(ei.ID, 10)),

		URL:           ei.URL,
		AccessKey:     ei.AccessKey,
		OutgoingToken: ei.OutgoingToken,
		CreatedAt:     ei.CreatedAt,
		UpdatedAt:     ei.UpdatedAt,
	}
}
