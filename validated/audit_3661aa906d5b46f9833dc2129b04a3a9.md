### Title
Session-key private keys for IntentGatewayV2 orders are persisted unencrypted in local storage - (File: sdk/packages/sdk/src/storage/index.ts)

### Summary
The Hyperbridge SDK's intents module generates a disposable ECDSA "session key" for every order placed through `IntentGatewayV2` when `solverSelection` is enabled. This session key is the sole authority that can authorize a solver to fill the order via an EIP-712 `SelectSolver` signature. The SDK persists the session key's raw private key in plaintext via `createSessionKeyStorage` [1](#0-0) , backed by `localStorage`/`indexedDB` in the browser [2](#0-1)  with no encryption applied to the stored `SessionKeyData.privateKey` field [3](#0-2) .

### Finding Description
When a user places a solver-selection-protected order, the SDK creates a session keypair and stores it as JSON — including the raw hex `privateKey` — under a predictable key (`session-key:<commitment>` / `session-key-address:<address>`) using `setSessionKey`/`setSessionKeyByAddress` [4](#0-3) . This data is later read back to sign the `SelectSolver` EIP-712 message that authorizes a specific solver to fill the order [5](#0-4) , which is precisely what `SolverAccount.validateUserOp` and `IntentsBase._select` trust as proof of the order owner's authorization [6](#0-5) [7](#0-6) .

Because the private key is stored as plaintext JSON in browser `localStorage`/`indexedDB` (or an equivalent unencrypted node driver), any code or process with read access to that storage medium — a malicious/compromised browser extension, an XSS payload in the dApp, a synced browser profile, or another local process on a shared/compromised machine — can extract the session private key directly, with no additional secret (password, device-bound key) required to decrypt it. This directly parallels the ZecWallet finding: sensitive per-session secrets are written to non-volatile local storage in cleartext, so anyone who can read that storage (rather than just "an attacker with a rooted phone") recovers the key outright.

### Impact Explanation
Recovering a session private key from storage allows the attacker to forge a valid `SelectSolver(commitment, solver)` EIP-712 signature and select an attacker-controlled/colluding solver for the victim's pending order, or to select a solver who would otherwise have lost the fair auction, effectively hijacking solver selection for any order still awaiting fill. Combined with a colluding solver, this can be used to fill the order with worse-than-quoted outputs (since `select`/`fillOrder` only check the session signature and the solver's own bid signature, not price fairness beyond what's encoded in the order) or to front-run legitimate solver selection, which can result in the user's escrowed input tokens being released for degraded/adversarial output — a direct funds-loss vector reachable from ordinary SDK usage, matching the "concrete theft" bar for Medium/High severity.

### Likelihood Explanation
Exploitation requires local read access to the user's browser storage (e.g., via XSS in the integrating dApp, a malicious browser extension, or malware on the user's machine) — this is a realistic and common attack surface for web-based wallets/dApps, and does not require privileged blockchain roles, making it reachable by any ordinary user of the intents SDK. It does not require a malicious admin, governance, collator, or node, satisfying the scope rules.

### Recommendation
**Short term:** Do not persist raw session private keys in plaintext. Encrypt the `SessionKeyData` payload before writing to `localStorage`/`indexedDB` with a key derived from a user-supplied passphrase or a non-extractable WebCrypto key, and avoid embedding the private key directly in `JSON.stringify` output as done in `setSessionKey`/`setSessionKeyByAddress` [8](#0-7) .

**Long term:** Prefer non-extractable, hardware/browser-backed key material (e.g., WebCrypto `CryptoKey` with `extractable: false`, or a passkey/HSM-backed signer) for session keys so the private key material never needs to touch application-readable storage, and add expiry/clearing of session keys once an order is filled or cancelled.

### Proof of Concept
1. User places an order via the SDK with `solverSelection` enabled; the SDK creates a session key and calls `setSessionKey`/`setSessionKeyByAddress`, storing `{ privateKey, address, commitment, createdAt }` as plaintext JSON in `localStorage` under key `session-key:<commitment>` [9](#0-8) .
2. An attacker with any local storage read primitive (XSS in the hosting dApp, malicious extension, or shared machine access) runs `localStorage.getItem("hyperbridge/sdk/proof:session-key:<commitment>")` and parses out `privateKey`.
3. Using this key, the attacker calls `CryptoUtils.signSolverSelection` off-chain to produce a valid `SelectSolver` signature for a solver of their choosing [10](#0-9) .
4. The forged signature is submitted as part of a `SolverAccount` UserOperation, passing `IntentsBase._select` verification since it correctly recovers to the (stolen) session key [7](#0-6) , letting the attacker's colluding solver fill the order on their own terms.

/**
 * Creates a session key storage instance for IntentGatewayV2 orders.
 * The storage is used to persist session key private keys so they can be
 * used later to sign solver selection messages.
 *
 * @param options - Optional configuration for the storage driver
 * @returns A storage instance with methods to get, set, and remove session keys
 */
export function createSessionKeyStorage(options: SessionKeyStorageOptions = {}) {
	const key = options.env ?? detectEnvironment()
	const driver = loadDriver({ key, options }) ?? inMemoryDriver()
	const baseStorage = createStorage({ driver })

	const SESSION_KEY_PREFIX = "session-key:"
	const SESSION_KEY_ADDRESS_PREFIX = "session-key-address:"

	/**
	 * Gets a session key by order commitment
	 */
	const getSessionKey = async (commitment: HexString): Promise<SessionKeyData | null> => {
		const storageKey = `${SESSION_KEY_PREFIX}${commitment}`
		const value = await baseStorage.getItem<string>(storageKey)
		if (!value) return null

		try {
			return JSON.parse(value) as SessionKeyData
		} catch {
			return null
		}
	}

	/**
	 * Gets a session key by session key address
	 */
	const getSessionKeyByAddress = async (address: HexString): Promise<SessionKeyData | null> => {
		const storageKey = `${SESSION_KEY_ADDRESS_PREFIX}${address.toLowerCase()}`
		const value = await baseStorage.getItem<string>(storageKey)
		if (!value) return null

		try {
			return JSON.parse(value) as SessionKeyData
		} catch {
			return null
		}
	}

	/**
	 * Stores a session key for an order commitment
	 */
	const setSessionKey = async (commitment: HexString, data: SessionKeyData): Promise<void> => {
		const storageKey = `${SESSION_KEY_PREFIX}${commitment}`
		await baseStorage.setItem(storageKey, JSON.stringify(data))
	}

	/**
	 * Stores a session key for a session key address
	 */
	const setSessionKeyByAddress = async (address: HexString, data: SessionKeyData): Promise<void> => {
		const storageKey = `${SESSION_KEY_ADDRESS_PREFIX}${address.toLowerCase()}`
		await baseStorage.setItem(storageKey, JSON.stringify(data))
	}

	private async signSelection(): Promise<HexString> {
		if (this.cachedSignature) return this.cachedSignature

		const commitment = this.order.id as HexString

			this.solverAddress,
			this.domainSeparator,
			sessionKeyData.privateKey,
		)

			throw new Error("Failed to sign solver selection")

    function _select(SelectOptions calldata options) internal returns (address) {
        bytes32 structHash = keccak256(abi.encode(SELECT_SOLVER_TYPEHASH, options.commitment, options.solver));
        bytes32 digest = _hashTypedDataV4(structHash);
        address sessionKey = ECDSA.recover(digest, options.signature);

        bytes32 commitment = options.commitment;
        bytes32 selectionHash = keccak256(abi.encode(options.solver, sessionKey));
        assembly {
            tstore(commitment, selectionHash)
        }

        return sessionKey;

	static async signSolverSelection(
		commitment: HexString,
		solverAddress: HexString,
		domainSeparator: HexString,
		privateKey: HexString,
	): Promise<HexString | null> {
		const account = privateKeyToAccount(privateKey as Hex)

		const structHash = keccak256(
			encodeAbiParameters(
				[{ type: "bytes32" }, { type: "bytes32" }, { type: "address" }],
				[SELECT_SOLVER_TYPEHASH, commitment, solverAddress],
			),
		)

		const digest = keccak256(concat(["0x1901" as Hex, domainSeparator as Hex, structHash]))
		const signature = await account.sign({ hash: digest })

		return signature as HexString
	}
