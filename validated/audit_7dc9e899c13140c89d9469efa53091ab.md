### Title
Bridge outgoing credential token disclosed to unprivileged "view"-role users via bridge read APIs - ([File: core/web/presenters/bridges.go])

### Summary
The Nexus CVE describes a delegated (non-full-admin) repository administrator being able to disclose upstream proxy credentials that should only be visible to a more privileged actor. The same bug class exists in chainlink's bridge-type read APIs: the `OutgoingToken` — the credential chainlink uses to authenticate itself to an external adapter/bridge — is unconditionally serialized into the `BridgeResource` returned by both the REST bridge endpoints and the GraphQL bridge resolvers, and these read endpoints are reachable by the lowest-privilege "view" role (and even the GraphQL variant only requires a valid session, no role check at all).

### Finding Description
`BridgeResource` includes `OutgoingToken` with no `omitempty` and no redaction: [1](#0-0) 

This resource is returned by `BridgeTypesController.Show` and `.Index`: [2](#0-1) 

The router wires `GET /v2/bridge_types` and `GET /v2/bridge_types/:BridgeName` without any role gate at all (only `POST`/`PATCH`/`DELETE` require `auth.RequiresEditRole`): [3](#0-2) 

The project's own RBAC test matrix documents that these GET routes are `viewOnlyAllowed: true`, i.e. accessible by every role including `UserRoleView`, the lowest of the four (`view`, `run`, `edit`, `admin`): [4](#0-3) [5](#0-4) 

The GraphQL path is even weaker: `Resolver.Bridge`/`Resolver.Bridges` only call `authenticateUser(ctx)`, which merely checks that a session exists — it does not check role at all (compare to `authenticateUserCanEdit`/`authenticateUserIsAdmin` used elsewhere): [6](#0-5) [7](#0-6) 

The GraphQL `BridgeResolver.OutgoingToken()` also directly exposes the raw token: [8](#0-7) 

By contrast, other secrets in the codebase are explicitly redacted at the config layer (`models.Secret`/`SecretString`, `xxxxx` masking), showing the project has an established pattern of not returning credential material to lower-trust callers: [9](#0-8) 

### Impact Explanation
`OutgoingToken` is the shared secret bridges use to authenticate outbound calls from chainlink to the external adapter (analogous to the "upstream proxy credentials" in the Nexus CVE). Any node user provisioned with only the `view` role — intended for read-only monitoring, explicitly barred from mutating jobs/bridges/keys (`RequiresEditRole`, `RequiresRunRole`, `RequiresAdminRole` gates elsewhere in the same router) — can nonetheless read every configured bridge's outgoing credential simply by calling `GET /v2/bridge_types` or `GET /v2/bridge_types/:BridgeName`, or via the GraphQL `bridge`/`bridges` queries with any authenticated session. This allows a low-privileged, delegated user to impersonate the node to the external adapter or reuse the credential elsewhere, which is exactly the "delegated admin discloses upstream credential" bug class from the report, applied to chainlink's own node API authorization model.

### Likelihood Explanation
High for any deployment that provisions `view`-role API users/tokens for dashboards, audits, or read-only integrations (a documented, intended use case per the RBAC route map) — no additional privilege escalation is required, only a valid low-privilege session/API token. The GraphQL entry point requires even less: any authenticated session regardless of role.

### Recommendation
- Redact `OutgoingToken` from `BridgeResource` (and the GraphQL `BridgeResolver.OutgoingToken`) for callers below `edit`/`admin` role, or omit it entirely from read (`Show`/`Index`) responses and only return it (like `IncomingToken`) at creation time.
- Add an explicit role check (`authenticateUserCanEdit`/`authenticateUserIsAdmin`) to the GraphQL `Bridge`/`Bridges` resolvers before exposing token fields.
- Add RBAC test coverage asserting `outgoingToken` is absent from view/run-role bridge read responses.

### Proof of Concept
1. Create an API user with role `view` (`POST /v2/users` as admin, role=`view`).
2. As that view-role user, call `GET /v2/bridge_types` or `GET /v2/bridge_types/<name>`.
3. Observe the JSON:API response includes `"outgoingToken": "<secret>"` for each bridge, confirming disclosure to a role that per `RequiresEditRole`/`RequiresAdminRole` elsewhere is not trusted with mutating or sensitive operations.
4. Repeat via GraphQL `query { bridge(id:"<name>") { outgoingToken } }` using any authenticated session — no role check is enforced at all.

Note: I could not fully verify whether any additional server-side filtering strips `outgoingToken` before serialization outside of what `NewBridgeResource` and `BridgeResolver.OutgoingToken` do (e.g., a jsonapi field-level ACL), since the index did not surface such a layer; based on the code paths found, no such filtering exists.

// Index lists Bridges, one page at a time.
func (btc *BridgeTypesController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	bridges, count, err := btc.App.BridgeORM().BridgeTypes(ctx, offset, size)

	resources := make([]presenters.BridgeResource, 0, len(bridges))
	for _, bridge := range bridges {
		resources = append(resources, *presenters.NewBridgeResource(bridge))
	}

	paginatedResponse(c, "Bridges", size, page, resources, count, err)
}

// Show returns the details of a specific Bridge.
func (btc *BridgeTypesController) Show(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	bt, err := btc.App.BridgeORM().FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}

// Bridge retrieves a bridges by name.
func (r *Resolver) Bridge(ctx context.Context, args struct{ ID graphql.ID }) (*BridgePayloadResolver, error) {
	if err := authenticateUser(ctx); err != nil {
		return nil, err
	}

	name, err := bridges.ParseBridgeName(string(args.ID))
	if err != nil {
		return nil, err
	}

	bridge, err := r.App.BridgeORM().FindBridge(ctx, name)
	if err != nil {
		if errors.Is(err, sql.ErrNoRows) {
			return NewBridgePayload(bridge, err), nil
		}

		return nil, err
	}

	return NewBridgePayload(bridge, nil), nil
}
