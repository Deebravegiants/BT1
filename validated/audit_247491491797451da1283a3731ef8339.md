### Title
Unbounded FIFO Eviction of Prepaid Bandwidth Subscriptions Permits Griefing/Loss of Paid-For Allowance - ([File: modules/pallets/bandwidth/src/lib.rs])

### Summary
`pallet-bandwidth`'s `push_subscription` unconditionally evicts the single oldest entry in a `(chain, app)` FIFO list once it hits the hard cap of `MAX_SUBSCRIPTIONS` (1024), with no regard to that entry's remaining value (unspent bytes, remaining duration) or who paid for it. Because `BandwidthManager.purchase()` on the EVM side lets *any* caller credit *any* `app` address on *any* `chain` (the sponsorship model), an unprivileged bandwidth purchaser can push cheap, minimal-tier purchases against a victim `(chain, app)` pair to force the FIFO list to the cap and evict a victim's legitimately paid, high-value subscription before it is consumed — permanently losing the bytes/duration the victim already paid for.

### Finding Description
`push_subscription` appends every new subscription (from a real purchase or `force_credit`) to a `BoundedVec` capped at `MAX_SUBSCRIPTIONS = 1024`. When the list is already full, it evicts `list.remove(0)` — strictly the oldest entry by insertion order — regardless of that entry's size, tier, or remaining lifetime: [1](#0-0) 

The queue is keyed by `(app_chain, app)` — taken from the purchase message body, not from `request.source` or `msg.sender` — precisely so a purchase from any chain can sponsor any app anywhere: [2](#0-1) 

On the EVM side, `BandwidthManager.purchase()` accepts an arbitrary `app` and `chain` argument from any `msg.sender` with no ownership or allowlist check tying the caller to the app being credited: [3](#0-2) 

This mirrors the referenced bug class exactly: multiple independent "bidders" (purchasers) write into a shared capped resource, and the *order* in which they arrive determines whose entry survives once the cap is reached. Just as `Mythos.sendTokensAndRefund` allowed an early bidder to be denied minting once the cap was hit because ordering wasn't protected on-chain, here a victim's early (and possibly large, long-duration) subscription can be silently evicted by a flood of later, cheap purchases from an unrelated attacker, because the eviction policy is blind to value and enforces no relationship between "who paid" and "whose allowance survives."

### Impact Explanation
Eviction is a permanent loss for the victim: `SubscriptionEvicted` is emitted, but the fee already paid to `BandwidthManager` for that subscription is not refunded, and the bytes/duration it represented are gone. An attacker who wants to disrupt a specific app's message flow (e.g., a competing dApp, or someone trying to force an app off Hyperbridge's bandwidth gate so its messages get rejected) can:
1. Observe (or predict) a victim's `(chain, app)` and purchase minimal tier subscriptions targeting it.
2. Drive the FIFO list to the 1024 cap.
3. Continue purchasing to evict the victim's still-valid, unconsumed subscription(s) out from under it.

The victim then has its outbound-affecting `BandwidthGate::try_consume` calls fail (`NoAllowance`/`Insufficient`), which the docs state causes the message to be rejected — a denial-of-service on that app's ISMP messaging that also destroys the value of what the victim already paid for. This is a permanent loss of purchased/escrowed value reachable from a fully unprivileged, permissionless entry point (`purchase()`), matching the "permanent freezing of funds" bar.

### Likelihood Explanation
`purchase()` is fully permissionless and requires no relationship to the target app; the only cost is the tier price for however many purchases are needed to fill/evict past the victim's position. Since a busy app naturally accumulates subscriptions toward the 1024 cap through its own legitimate repurchases (same-tier repurchases queue rather than stack), it does not take an attacker 1024 purchases in the worst case — only enough to advance past the victim's position, which can be small if the victim's subscription was made when the queue was already populated. This makes the attack economically feasible against active, real-world apps rather than only against freshly-created ones.

### Recommendation
- Tie subscription ownership/eviction eligibility to the payer, or require an allowlist/ownership check so that only the app's controller (or its own configured `BandwidthManager` payer) can credit or evict its own queue, preventing third-party griefing via arbitrary `app` targeting.
- Alternatively, protect against eviction of subscriptions that still have significant unspent value/duration (e.g., evict by lowest remaining-bytes×remaining-time score, or refuse the push and refund/redirect if all entries are still substantially unconsumed) rather than blind oldest-first FIFO.
- Consider a per-`(chain, app)` minimum purchase amount or rate-limiting to make griefing repurchases economically prohibitive.

### Proof of Concept
1. Victim app `X` on `EVM-8453` legitimately purchases a large, long-duration Tier-4 subscription via `BandwidthManager.purchase(app=X, tier=4, months=12, chain="EVM-8453")`, landing in `Allowance[EVM-8453][X]` at some position `k` in the FIFO list (queue not yet full).
2. An unrelated attacker calls `purchase(app=X, tier=1, months=1, chain="EVM-8453")` repeatedly (no restriction on `msg.sender` vs. `app`) until the list length reaches `MAX_SUBSCRIPTIONS` (1024) and then `k+1` more times.
3. Each push beyond the cap calls `push_subscription`, which does `list.remove(0)` unconditionally: [4](#0-3) 
4. After `k+1` griefing purchases, `X`'s Tier-4 subscription is evicted (`SubscriptionEvicted` emitted) with most of its 12-month allowance unconsumed and unrefunded, while `X` continues to be charged the ISMP protocol's expectation of having bandwidth — its subsequent dispatches are rejected by `BandwidthGate::try_consume` once the remaining cheap entries drain, at a fraction of the cost `X` originally paid.

		/// Append a fresh subscription with a fixed expiry. If the list
		/// is already at `MaxSubscriptions`, evict the oldest entry and
		/// emit [`Event::SubscriptionEvicted`] so the lost bytes are
		/// auditable. Returns the new subscription's `expires_at`.
		fn push_subscription(
			app_chain: &StateMachine,
			app: &AppKey,
			tier: TierIndex,
			bytes: BandwidthBytes,
			duration_secs: u64,
		) -> u64 {
			let now = <T as pallet_ismp::Config>::TimestampProvider::now().as_secs();
			let expires_at = now.saturating_add(duration_secs);
			let new_sub =
				Subscription { tier, remaining_bytes: bytes, expires_at, purchased_at: now };

			let evicted = Allowance::<T>::mutate(app_chain, app, |list| {
				let evicted = if list.len() == MAX_SUBSCRIPTIONS as usize {
					Some(list.remove(0))
				} else {
					None
				};
				// Capacity is now guaranteed; try_push can't fail.
				let _ = list.try_push(new_sub);
				evicted
			});

			if let Some(old) = evicted {
				Self::deposit_event(Event::SubscriptionEvicted {
					app_chain: *app_chain,
					app: app.clone(),
					tier: old.tier,
					lost_bytes: old.remaining_bytes,
				});
			}

			expires_at
		}

    function purchase(bytes calldata app, uint256 tier, uint256 months, bytes calldata chain)
        external
        returns (bytes32 commitment)
    {
        if (app.length == 0 || app.length > MAX_APP_LENGTH || chain.length == 0 || months == 0) {
            revert InvalidPurchase();
        }
        uint256 price18d = tierPrice[tier];
        if (price18d == 0) revert UnknownTier();

        uint256 total18d = price18d * months;
        address feeToken = IDispatcher(_host).feeToken();
        uint8 dec = IERC20Metadata(feeToken).decimals();
        uint256 scale = 10 ** (18 - dec);
        if (total18d % scale != 0) revert PriceNotRepresentable();
        uint256 amount = total18d / scale;

        IERC20(feeToken).safeTransferFrom(msg.sender, address(this), amount);

        BandwidthPurchaseMsg memory body = BandwidthPurchaseMsg({
            app: app,
            tier: tier,
            months: months,
            chain: chain
        });

        commitment = IDispatcher(_host).dispatch(
            DispatchPost({
                dest: IDispatcher(_host).hyperbridge(),
                to: PALLET_BANDWIDTH_MODULE_ID,
                body: abi.encode(body),
                timeout: 0,
                fee: 0,
                payer: address(this)
            })
        );

        emit BandwidthPurchased({
            payer: msg.sender,
            feeToken: feeToken,
            tier: tier,
            months: months,
            amountPaid: amount,
            app: app,
            chain: chain,
            commitment: commitment
        });
    }
