## Title
Legacy user QR-code format allows signup identity binding without any cryptographic ownership proof - (File: `src/backend/user_status.rs`)

### Summary
The referenced Code4rena finding describes `VaderPoolV2.mintFungible()`/`mintSynth()` accepting caller-supplied `from`/`to` identity parameters and performing privileged fund transfers on behalf of that identity without verifying the caller actually controls it. The equivalent access-control gap in orb-core is in the user-identity binding path of the signup flow: the legacy ("old") user QR-code format is accepted and bound to a signup with **no cryptographic proof that the presenter of the QR code controls that user_id**, unlike the new/current QR format which is protected by a `user_data_hash` + `verify()` check.

### Finding Description
`qr_scan::user::Data::try_parse` supports three QR-code formats: the new encrypted `decode_qr` format (which carries a `user_data_hash`), the `QR_CODE_V2` regex format `userid:<uuid>:<data_policy>` (legacy, `user_data_hash: None`), and (behind `internal-data-acquisition`) a signup-extension format, also without a hash. [1](#0-0) 

In `backend::user_status::request`, when the backend returns `backend_keys`/`authenticated_app_data` (the modern, cryptographically-bound flow), the code requires `qr_code.user_data_hash` to be present and calls `user_data.verify(user_data_hash)` before trusting the identity data: [2](#0-1) 

However, when the backend responds without `backend_keys`/`authenticated_app_data` (the "old QR-code format" branch), the code performs **no verification at all** of the `user_id` that was scanned — it only checks that `user_data_hash` is *absent*, then unconditionally returns a valid `UserData` (with `user_centric_signup: false`, `pcp_version: 0`) bound to whatever `user_id` string was decoded from the QR code: [3](#0-2) 

Because `qr_scan::user::Data::user_id` in the legacy path is parsed directly from plaintext QR-code content via a regex with no signature or hash binding it to a specific holder of a private key or app session, any operator/attacker who can present (print, display, or replay) a QR code encoding an arbitrary `userid:<uuid>:<policy>` string can have the orb accept and use that identity for the signup, exactly as the `from`/`to` parameters in `mintFungible()`/`mintSynth()` were trusted without checking that the caller actually controlled them. [4](#0-3) 

This `user_id` subsequently flows into the signature computation (`make_signature`) and the backend signup POST (`signup_post::request`), tying biometric capture data to that unverified `user_id`: [5](#0-4) [6](#0-5) 

### Impact Explanation
If the backend still serves (or is downgraded/misconfigured to serve) the legacy response without `backend_keys`/`authenticated_app_data`, the orb will accept and process a signup for an arbitrary attacker-chosen `user_id` with no proof of ownership — a direct analog to unauthorized action performed against an identity the caller doesn't control. This can result in biometric enrollment being misattributed to a victim's `user_id` (cross-signup identity bleed), similar in class to the referenced report's unauthorized use of another party's identity/funds.

### Likelihood Explanation
Exploitability depends entirely on the backend still returning the legacy (unauthenticated) response shape for some `user_id`s/QR formats; the orb-core code as written places no independent constraint preventing this and trusts the backend's `valid: true` + absence of `authenticated_app_data`/`backend_keys` as sufficient to proceed. This is a real, reachable code path (not test-only, not requiring privileged/hardware access) gated purely by whichever QR-code format is scanned, which is unprivileged, attacker-influenceable input.

### Recommendation
Remove or hard-fail the legacy/unauthenticated branch in `backend::user_status::request` (lines 245-270) in production, or require that every accepted `UserData` be cryptographically bound (via `user_data_hash`/`verify`) to the scanned QR code regardless of which backend response shape is returned, mirroring the check already enforced in the modern path.

### Proof of Concept
1. Present a QR code matching `QR_CODE_V2` format, e.g. `userid:<victim-uuid>:1`, to the orb (no cryptographic hash embedded). [7](#0-6) 
2. `qr_scan::user::Data::try_parse` parses it into `Data { user_id: "<victim-uuid>", user_data_hash: None, .. }`. [4](#0-3) 
3. `backend::user_status::request` calls the backend; if the backend does not return `backend_keys`/`authenticated_app_data` for this query (legacy response), the "old QR-code format" branch runs and returns `Ok(Some(UserData { .. }))` bound to `<victim-uuid>` with zero verification. [3](#0-2) 
4. The signup proceeds, and `signup_post::request` submits the capture to the backend tagged with `userId: <victim-uuid>` — attributing the attacker's biometric signup to the victim's identity without ever proving control of it. [8](#0-7)

impl Schema for Data {
    fn ui() -> ui::QrScanSchema {
        ui::QrScanSchema::User
    }

    fn try_parse(code: &str) -> Option<Self> {
        if let Ok((user_id, user_data_hash)) = decode_qr(code) {
            return Some(Self {
                user_id: user_id.hyphenated().to_string(),
                signup_extension: false,
                signup_extension_config: None,
                user_data_hash: Some(user_data_hash),
            });
        }
        if let Some(captures) = QR_CODE_V2.captures(code) {
            return Some(Data::from_v2(&captures));
        }
        #[cfg(feature = "internal-data-acquisition")]
        if let Some(captures) = QR_CODE_SIGNUP_EXTENSION.captures(code) {
            return Some(Data::from_signup_extension(&captures));
        }
        None
    }
}

fn make_signature(user_qr_code: &qr_scan::user::Data, pipeline: &Pipeline) -> Result<String> {
    let mut ctx = Context::new(&SHA256);
    ctx.update(ORB_ID.as_str().as_bytes());
    ctx.update(user_qr_code.user_id.as_bytes());
    ctx.update(pipeline.v2.ir_net_version.as_bytes());
    ctx.update(pipeline.v2.iris_version.as_bytes());
    ctx.update(pipeline.v2.eye_left.iris_code.as_bytes());
    ctx.update(pipeline.v2.eye_left.mask_code.as_bytes());
    ctx.update(pipeline.v2.eye_left.iris_code_version.as_bytes());
    ctx.update(pipeline.v2.eye_right.iris_code.as_bytes());
    ctx.update(pipeline.v2.eye_right.mask_code.as_bytes());
    ctx.update(pipeline.v2.eye_right.iris_code_version.as_bytes());
    let signed = secure_element::sign(ctx.finish())?;
    Ok(BASE64.encode(&signed))
}
