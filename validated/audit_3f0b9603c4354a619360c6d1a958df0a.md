## Title
Double-spend of GET request relayer fees via unfreed `_requestCommitments` entry reused by a stale timeout proof - ([File: evm/src/core/EvmHost.sol])

### Summary
CVE-2020-15389 is a use-after-free/double-free in `opj_decompress.c` caused by a resource (`opj_image`) being destroyed twice when a batch mixes valid and invalid inputs, because the cleanup path fails to null out / consume the freed pointer. The equivalent flaw in Hyperbridge is in `EvmHost.sol`'s handling of `_requestCommitments` for GET requests: the fee-metadata "resource" attached to an outgoing GET request is consumed (paid out) by two independent, permissionless code paths — successful response delivery and a stale/late non-membership timeout proof — but only one of these paths clears the underlying storage. The other path can be replayed against historical state, paying the same escrowed fee a second time.

### Finding Description
`EvmHost.dispatchIncoming(GetResponse memory response, address relayer)` pays the relayer the request's fee by reading `_requestCommitments[commitment].fee` but never deletes `_requestCommitments[commitment]`: [1](#0-0) 

Compare this to `dispatchTimeOut(GetRequestTimeout, FeeMetadata, bytes32)`, which explicitly deletes `_requestCommitments[commitment]` up front as "replay protection", and only restores it if the destination callback reverts: [2](#0-1) 

Both functions are reachable permissionlessly, respectively via `HandlerV2.handleGetResponses` and `HandlerV2.handleGetRequestTimeouts`: [3](#0-2) [4](#0-3) 

`handleGetRequestTimeouts` validates a non-membership proof of the response receipt against a historical `host.stateMachineCommitment(message.height)`. Old height entries in `_stateCommitments` are never pruned (they are only ever added or overwritten at higher heights), so a **valid, honestly-produced** non-membership proof from *before* the response was actually delivered remains submittable indefinitely.

Because `dispatchIncoming(GetResponse,...)` never clears `_requestCommitments[commitment]`, the following sequence pays the same escrowed fee out twice from one deposited amount:
1. A GET request is dispatched with fee `F`; `_requestCommitments[commitment] = {payer, F}`.
2. A relayer captures an early non-membership proof at height `h1` (before the response exists) but does not submit it yet, or submits it and the app's `onGetTimeout` callback reverts (so `_requestCommitments[commitment]` is restored to `{payer, F}` per lines 866–870).
3. Later, the real `GetResponse` proof (at height `h2 > h1`) is delivered via `handleGetResponses` → `dispatchIncoming(GetResponse,...)`. The destination app succeeds, `_responseReceipts[commitment]` is set (blocking response replay), and the relayer is paid `F` from `_requestCommitments[commitment].fee` — but that storage slot is left untouched.
4. The attacker (or any permissionless caller) now submits `handleGetRequestTimeouts` using the still-valid stale proof from height `h1`. `host.requestCommitments(commitment)` still returns `{payer, F}` (never cleared in step 3), the stale non-membership proof still verifies against the historical `h1` commitment, and `dispatchTimeOut` pays `F` again to `payer`.

Both payouts draw from the same single fee deposit — the protocol pays `2F` for `1F` escrowed, an unbacked double payment of protocol/user funds analogous to the double-free: the same "resource" (`_requestCommitments[commitment]`) is consumed a second time because the first consuming path (`dispatchIncoming` for `GetResponse`) never invalidates it, mirroring `opj_image_destroy` being reachable twice because the first destroy path didn't null the pointer.

### Impact Explanation
This allows draining of the fee-token balance held by `EvmHost` — any relayer/attacker able to hold or manufacture a valid stale non-membership proof (a completely legitimate byproduct of normal timeout-proof preparation) can extract twice the escrowed fee for a single GET request. This is a concrete theft of funds / unbacked payment vulnerability reachable by an unprivileged relayer via a single permissionless transaction (`handleGetRequestTimeouts`), satisfying the "concrete theft ... of funds" bar.

### Likelihood Explanation
Likelihood is Medium: it requires the attacker to have captured (or triggered a reverted attempt with) an honest non-membership proof at a height prior to the response's inclusion height, and for the destination app's timeout callback to eventually succeed on replay. Both are realistic for any relayer participating in normal protocol operation (timeout proofs are routinely generated speculatively before responses land), and historical state commitments are never invalidated, so the exploit window is unbounded.

### Recommendation
Delete (or otherwise invalidate) `_requestCommitments[commitment]` inside `dispatchIncoming(GetResponse memory response, address relayer)` immediately after the fee has been paid (mirroring the "replay protection" pattern already used in the two `dispatchTimeOut` overloads), and/or additionally gate `dispatchTimeOut(GetRequestTimeout,...)` on `_responseReceipts[commitment]` being unset before honoring a timeout proof, so a response delivery and a timeout can never both settle the same fee.

### Proof of Concept
1. Dispatch a `DispatchGet` with `fee = F`, `payer = P`; `_requestCommitments[commitment] = {P, F}`.
2. Off-chain, construct (but don't yet need to submit) a non-membership proof of the response-receipt key at destination height `h1`, where no response exists yet.
3. Wait until the response is actually produced/finalized on the destination at height `h2 > h1`; relay it via `handlePostRequests`-analog `handleGetResponses`. The destination `IApp.onGetResponse` succeeds; `EvmHost` transfers `F` fee tokens to the relayer via `dispatchIncoming(GetResponse,...)` (evm/src/core/EvmHost.sol:841-845), leaving `_requestCommitments[commitment]` untouched.
4. Submit `handleGetRequestTimeouts` with the height-`h1` non-membership proof captured in step 2. `host.requestCommitments(commitment)` still resolves to `{P, F}`; the proof verifies against the still-available historical `h1` state commitment; `dispatchTimeOut` transfers `F` fee tokens to `P` a second time.
5. Total fee-token outflow from `EvmHost` for this request is `2F`, against a single `F` deposit.

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function handleGetResponses(IHost host, GetResponseMessage calldata message) external notFrozen(host) {
        uint256 timestamp = block.timestamp;
        uint256 delay = timestamp - host.stateMachineCommitmentUpdateTime(message.proof.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        uint256 responsesLength = message.responses.length;
        MerkleMountainRange.Leaf[] memory leaves = new MerkleMountainRange.Leaf[](responsesLength);

        for (uint256 i = 0; i < responsesLength; ++i) {
            GetResponseLeaf memory leaf = message.responses[i];
            // don't check for timeouts because it's checked on Hyperbridge

            // known request? also serves as source check
            FeeMetadata memory meta = host.requestCommitments(leaf.response.request.hash());
            if (meta.sender == address(0)) revert UnknownMessage();
            leaves[i] = MerkleMountainRange.Leaf(leaf.index, leaf.response.hash());
        }

        bytes32 root = host.stateMachineCommitment(message.proof.height).overlayRoot;
        if (root == bytes32(0)) revert StateCommitmentNotFound();
        bool valid = MerkleMountainRange.VerifyProof(root, message.proof.multiproof, leaves, message.proof.leafCount);
        if (!valid) revert InvalidProof();

        for (uint256 i = 0; i < responsesLength; ++i) {
            GetResponseLeaf memory leaf = message.responses[i];
            // duplicate response?
            if (host.responseReceipts(leaf.response.request.hash()).relayer != address(0)) revert DuplicateMessage();
            host.dispatchIncoming(leaf.response, _msgSender());
        }
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
