Confirmed: gateway DONs run multiple independent gateway node instances (e.g. `bootstrap-gateway-us` / `gateway-eu` sets, each with their own `gatewayHandler`/`WorkflowMetadataHandler` process) that each maintain their own separate, unshared, in-memory `jwtReplayCache`. There is no shared/persistent store for used `jti` values across gateway node instances or across restarts.

### Title
JWT replay-protection state is per-process/in-memory, allowing an authorized-but-already-used HTTP trigger request to be re-relayed to a workflow via a different gateway instance or after a restart - (File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go)

### Summary
`WorkflowMetadataHandler.Authorize` prevents replay of an HTTP-trigger JWT solely by checking an in-memory map (`jwtReplayCache.cache`) for the JWT's `jti` claim [1](#0-0) . This mirrors the reported bug class exactly: a "already relayed" check backed by state that is not preserved/synchronized across all paths that can process the same signed message, so the same signed message can be validly relayed more than once.

### Finding Description
`Authorize()` verifies the JWT signature/digest/expiry via `utils.VerifyRequestJWT`, then checks `h.jwtCache.isReplay(claims.ID)`, and finally records usage with `h.jwtCache.recordUsage(claims.ID)` [1](#0-0) . This `jwtCache` is a plain `map[string]time.Time` guarded by a `sync.RWMutex`, created fresh per handler instance with `newJWTReplayCache` [2](#0-1) [3](#0-2) .

There is no external, shared, or persistent store backing this cache. Consequently:
- On process restart of a gateway node (crash, deploy/rolling-upgrade, pod eviction), the `jwtCache` is re-initialized empty — exactly analogous to the reported bug's "storage wiped, causing the already-relayed check to always pass".
- Independent gateway node instances in a gateway DON (confirmed by the `bootstrap-gateway-us` / `gateway-eu` multi-gateway topology and per-node `AuthGatewayID`/`GatewayDonID` config [4](#0-3) [5](#0-4) ) each run their own `WorkflowMetadataHandler`/`jwtCache`, with no cross-instance synchronization visible in the codebase.

The JWT itself does not otherwise bind the request to a specific gateway instance or single-use nonce enforced anywhere but this local map: `VerifyRequestJWT` only checks signature, digest match, `exp`/`iat` bounds (max 5 minutes lifetime) [6](#0-5) . Anyone possessing a previously-used, still-unexpired signed JWT + its exact original request body (an unprivileged party that observed or was given that request, e.g. a compromised/duplicated client, a proxy, or a routing/retry layer) can resubmit it to a different gateway node or to the same node after it restarts, and it will be accepted as if new.

Downstream, `HandleUserTriggerRequest` treats each accepted `Authorize` result as a fresh execution request, forwarding it to `sendWithRetries`/`setupCallback` which fans it out to workflow DON nodes to trigger workflow execution [7](#0-6) . The in-flight/duplicate-`requestID` guard (`h.callbacks[requestID]`) is likewise a per-instance in-memory map [8](#0-7) , so it does not prevent cross-instance duplication either — a second gateway node has an empty `callbacks` map and will happily accept and forward the identical `req.ID` + JWT.

### Impact Explanation
A single previously-valid, signed HTTP-trigger request can cause the target workflow to be executed more than once: once via one gateway instance/before a restart, and again via a different gateway instance/after a restart, exactly as the CrossDomainMessenger bug allowed a withdrawal to be relayed once as legacy and once again post-migration. If the triggered workflow performs any state-changing or fund-moving action (on-chain transaction, external system side effect), this results in unauthorized duplicate execution — the "unauthorized job run" class explicitly called out as in-scope. Impact scales with how many independent gateway node processes/replicas exist per DON and how often gateway nodes are restarted/redeployed in normal operations.

### Likelihood Explanation
This requires no compromise of any node's key material and no privileged access: the requester only needs to already hold one previously-issued, still-unexpired (≤5 min) signed JWT + matching request body — something any legitimate workflow-triggering client naturally possesses right after making its first request. Multi-gateway DON topologies are a first-class, documented, tested configuration in this codebase (see the multi-gateway smoke test and TOML configs), and gateway node restarts (deploys/crashes) are routine operational events, not attacker-controlled privileged actions. This makes the replay window realistically reachable by an ordinary/unprivileged client during normal gateway operation.

### Recommendation
Back JWT replay protection (and the trigger-request in-flight `callbacks` dedup) with a shared, durable store (e.g., a DB table or distributed cache) keyed by `jti`/`requestID`, scoped per gateway DON, so that "already used" state is consistent across all gateway node instances and survives process restarts. Alternatively, require workflow nodes (not gateway instances) to perform the authoritative once-only execution check keyed by the JWT digest/execution ID before actually running the workflow, so gateway-level replay cannot cause duplicate execution regardless of how many gateway instances or restarts occur.

### Proof of Concept
1. Deploy a gateway DON with ≥2 independent gateway node instances (as in the tested multi-gateway topology) or restart a single gateway node mid-operation.
2. Client signs one `workflows.execute` HTTP-trigger request with a JWT (`jti`, `exp` ≤5 min) and submits it to gateway instance A; `Authorize()` succeeds, `jwtCache.recordUsage` records it only in A's local map, and the workflow executes.
3. Client resubmits the identical signed request (same JWT, same body) to gateway instance B (or to instance A after it restarts). B's/A's fresh `jwtCache` has no record of the `jti`; `isReplay` returns false, `Authorize()` succeeds again, and `HandleUserTriggerRequest` triggers a second execution of the same workflow with the same input before the JWT's `exp` elapses.

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil

func newJWTReplayCache(cleanupPeriod time.Duration) *jwtReplayCache {
	return &jwtReplayCache{
		cache:         make(map[string]time.Time),
		cleanupPeriod: cleanupPeriod,
	}
}

func (cache *jwtReplayCache) isReplay(jti string) bool {
	cache.mu.RLock()
	defer cache.mu.RUnlock()

	_, exists := cache.cache[jti]
	return exists
}

func (cache *jwtReplayCache) recordUsage(jti string) {
	cache.mu.Lock()
	defer cache.mu.Unlock()

	cache.cache[jti] = time.Now()
}

// VerifyRequestJWT verifies a signed JWT for a JSON-RPC request
// It recovers and returns the public key used to sign the JWT, checks the issuer, validates the digest,
// and performs all validations done by jwt.ParseWithClaims() including expiration checks.
func VerifyRequestJWT[T any](tokenString string, req jsonrpc.Request[T], opts ...VerifyOption) (*JWTClaims, gethcommon.Address, error) {
	options := &verifyOptions{}
	for _, opt := range opts {
		opt(options)
	}

	maxExpiryDuration := maxJWTExpiryDuration
	if options.maxExpiryDuration != nil {
		maxExpiryDuration = *options.maxExpiryDuration
	}

	issuedAtTolerance := defaultIssuedAtTolerance
	if options.issuedAtTolerance != nil {
		issuedAtTolerance = *options.issuedAtTolerance
	}
	signedString, signature, err := splitToken(tokenString)
	if err != nil {
		return nil, gethcommon.Address{}, err
	}
	decodedSignature, err := base64.RawURLEncoding.DecodeString(signature)
	if err != nil {
		return nil, gethcommon.Address{}, fmt.Errorf("signature segment is not valid base64url: %w", err)
	}
	pubKey, err := GetSignersEthAddress([]byte(signedString), decodedSignature)
	if err != nil {
		return nil, gethcommon.Address{}, err
	}
	verifiedToken, err := jwt.ParseWithClaims(tokenString, &JWTClaims{}, func(token *jwt.Token) (any, error) {
		if token.Method.Alg() != EthereumSigningMethod.Alg() {
			return nil, fmt.Errorf("unsupported JWT 'alg': '%s'. Expected '%s'", token.Method.Alg(), EthereumSigningMethod.Alg())
		}
		if _, ok := token.Method.(*SigningMethodEth); !ok {
			return nil, jwt.ErrSignatureInvalid
		}
		return pubKey, nil
	})
	if err != nil {
		return nil, gethcommon.Address{}, err
	}
	verifiedClaims, ok := verifiedToken.Claims.(*JWTClaims)
	if !ok {
		return nil, gethcommon.Address{}, errors.New("claims payload is not in the expected format")
	}
	if !verifiedToken.Valid {
		return nil, gethcommon.Address{}, errors.New("signature or claims validation failed")
	}
	reqDigest, err := req.Digest()
	if err != nil {
		return nil, gethcommon.Address{}, err
	}
	if verifiedClaims.ID == "" {
		return nil, gethcommon.Address{}, errors.New("JWT ID (jti) is required but missing")
	}
	if verifiedClaims.ExpiresAt == nil {
		return nil, gethcommon.Address{}, errors.New("expiredAt (exp) is required but missing")
	}
	if verifiedClaims.IssuedAt == nil {
		return nil, gethcommon.Address{}, errors.New("issuedAt (iat) is required but missing")
	}
	now := time.Now()
	issuedAt := verifiedClaims.IssuedAt
	if issuedAt.After(now.Add(issuedAtTolerance)) {
		return nil, gethcommon.Address{}, fmt.Errorf("issuedAt (iat) is too far in the future (beyond tolerance of %.0f seconds)", issuedAtTolerance.Seconds())
	}
	duration := verifiedClaims.ExpiresAt.Sub(verifiedClaims.IssuedAt.Time)
	if duration > maxExpiryDuration {
		return nil, gethcommon.Address{}, fmt.Errorf("token lifetime %.0f sec exceeds the maximum allowed %.0f sec. Reduce the gap between 'iat' and 'exp'", duration.Seconds(), maxExpiryDuration.Seconds())
	}
	if verifiedClaims.Digest != "0x"+reqDigest {
		return nil, gethcommon.Address{}, fmt.Errorf("claim digest '%s' does not match calculated request digest '0x%s'", verifiedClaims.Digest, reqDigest)
	}

	return verifiedClaims, pubKey, nil
}

func (h *httpTriggerHandler) HandleUserTriggerRequest(ctx context.Context, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback, requestStartTime time.Time) error {
	triggerReq, err := h.validatedTriggerRequest(ctx, req, callback)
	if err != nil {
		return err
	}

	workflowID, err := h.resolveWorkflowID(ctx, triggerReq, req.ID, callback)
	if err != nil {
		return err
	}

	key, err := h.authorizeRequest(ctx, workflowID, req, callback)
	if err != nil {
		return err
	}

	if err = h.checkRateLimit(ctx, workflowID, req.ID, callback); err != nil {
		return err
	}

	strippedWorkflowID := strings.TrimPrefix(workflowID, "0x")
	legacyExecutionID, err := workflows.EncodeExecutionID(strippedWorkflowID, req.ID) //nolint:staticcheck // legacy ID kept for observability comparison
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInternal, internalErrorMessage, callback)
		return errors.New("error generating execution ID: " + err.Error())
	}
	// Workflows shouldn't use more than one HTTP trigger. If we ever need to support multiple triggers, we'd need to pass
	// trigger index to the Gateway handler and somehow allow senders to pick. For now, we use trigger index 0.
	// Execution IDs here are used only for logging.
	executionIDWithTriggerIndex, err := workflows.GenerateExecutionIDWithTriggerIndex(strippedWorkflowID, req.ID, 0)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInternal, internalErrorMessage, callback)
		return errors.New("error generating execution ID with trigger index: " + err.Error())
	}
	h.lggr.Debugw("processing request",
		"legacyExecutionID", legacyExecutionID,
		"executionIDWithTriggerIndex", executionIDWithTriggerIndex,
		"requestID", req.ID,
		"workflowID", workflowID)

	reqWithKey, err := reqWithAuthorizedKey(triggerReq, *key)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInternal, internalErrorMessage, callback)
		return errors.New("error marshaling trigger request: " + err.Error())
	}

	doneCh, err := h.setupCallback(ctx, req.ID, callback, requestStartTime, workflowID)
	if err != nil {
		return err
	}

	return h.sendWithRetries(ctx, legacyExecutionID, executionIDWithTriggerIndex, reqWithKey, workflowID, doneCh)
}
