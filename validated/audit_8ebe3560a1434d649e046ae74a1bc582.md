## Analysis

The `ImmutableBundle` bug class is "a wrong-function transfer permanently locks the sender's own asset because the protocol's rescue path deliberately/structurally excludes it." alt.fun's bonding-curve `Pair` has the same shape for LT (the leveraged-token reserve asset). [1](#0-0) 

`Pair.transferAsset` is the only exit for the LT sitting in a curve `Pair`, and it is gated `onlyRouter`. `Router` exposes it through exactly two call sites — the sell path and `Router.graduate`, both of which pull a computed amount, never `assetBalance()`: [2](#0-1) 

`Bonding._prepareGraduationLiquidity` computes `ltFromPair = assetReserve - _launchTimeVirtualLtReserve(...)` from the pair's **stored** reserves, not its live `assetBalance()`, and drains only that amount via `Router.graduate`: [3](#0-2) 

Because `_prepareGraduationLiquidity`/`Router.graduate` fires exactly once per token (gated by the `Lifecycle.Curve → Graduating` transition in `triggerGraduation`/`_enterGraduating`), any LT that a trader or bot sends directly to the `Pair` via `IERC20(lt).transfer(pair, amount)` — instead of going through `Zap.buy`/`Zap.sell` — is excluded from `ltFromPair` by construction and can never be drained afterward. The docs confirm this is treated as intentionally "locked" behind a trust assumption, not something with a recovery path: [4](#0-3) [5](#0-4) 

Unlike the graduated-LP donation case (Regime 2), where `pair.skim`, burn, and `_sweepLTToOwner`/`LTRescued` explicitly reclaim donated TOKEN/LT during `finalizeGraduation`, the pre-graduation curve `Pair` has **no** skim, no admin rescue function, and no way to reach `Pair.transferAsset` once the one-shot `graduate()` call has already happened (or if the donation lands after graduation, `BONDING_ROLE`'s only entry point is gone for that token). `Pair.sol` itself defines no rescue/skim function at all — its complete external surface is `mint`, `swap`, `transferAsset`, `transferToken`, and the two balance views, all `onlyRouter`.

### Title
Direct LT transfers into a bonding-curve `Pair` bypass `Zap.buy`/`sell` and are permanently unrecoverable - (File: packages/contracts/src/Pair.sol, packages/contracts/src/Bonding.sol)

### Summary
A trader (or anyone) can send LT directly to a token's bonding-curve `Pair` with a plain `IERC20.transfer` instead of routing through `Zap.buy`/`Zap.sell`. `Bonding._prepareGraduationLiquidity` computes the LT to drain (`ltFromPair`) from the pair's cached/stored reserves rather than its live balance, so the donated LT is excluded from `Router.graduate`'s draw. `Router.graduate` and the sell path are the only functions capable of moving asset tokens out of the `Pair` (`Pair.transferAsset` is `onlyRouter`), and `graduate` fires exactly once per token, gated by the `Curve → Graduating` lifecycle transition. There is no skim, sweep, or admin rescue function anywhere in `Pair.sol`, `Router.sol`, or `Bonding.sol` capable of reaching that stranded balance once the one-shot graduation drain has occurred (or for tokens that never graduate before the donation, once no future call to `graduate`/`sell` targets exactly that excess).

### Finding Description
`Pair.sol`'s only outbound-asset function is `transferAsset`, restricted to `router` ( [6](#0-5) ). `Router` calls it only from `graduate`, passing an externally supplied `amount` ( [7](#0-6) ), and `Bonding._prepareGraduationLiquidity` is the sole caller of `graduate`, computing that `amount` as `assetReserve - virtualLtReserve` — both values sourced from the `Pair`'s stored `Pool` struct, which is only mutated by `mint`/`swap`, never by a raw `IERC20.transfer` ( [3](#0-2) ). A raw transfer changes `assetBalance()` (a live `balanceOf` read) but not `_pool.assetReserve`, so the donated LT is mathematically walled off from ever being included in `ltFromPair`. `_prepareGraduationLiquidity`/`graduate()` executes exactly once per token because `triggerGraduation`/`_enterGraduating` requires `info.lifecycle == Lifecycle.Curve` and immediately flips it to `Graduating` ( [8](#0-7) ). After that one-shot drain, no code path calls `graduate` again for that token, and `sell()`'s asset payout is likewise bounded by curve math, not by draining arbitrary excess balance. The donated LT is therefore permanently stuck inside the `Pair` contract with zero recovery paths — not to the original sender, and not even to the protocol admin (contrast with the graduated-LP donation handling, which explicitly skims/burns/sweeps donations via `_sweepLTToOwner`/`LTRescued`).

### Impact Explanation
This is a permanent freeze of trader funds: any LT sent directly to a curve `Pair` — a plausible user error given that `Zap` is the documented, UI-driven entry point but the `Pair`/LT addresses are all public and directly transferable — is lost forever with no rescue mechanism. This mirrors the original report's core harm (funds locked with no admin or user recovery path) and is a design gap the protocol explicitly solved for the post-graduation LP-donation case but left open for the pre-graduation curve case.

### Likelihood Explanation
Reachable by any unprivileged wallet with a single `IERC20(lt).transfer(pair, amount)` call; no special role or timing is required. Likelihood is bounded mainly by user behavior (accidental or exploratory direct transfers rather than using `Zap`), which is exactly the scenario the original `ImmutableBundle` report and this alt.fun documentation both acknowledge as a real-world occurrence.

### Recommendation
Add a permissionless "sweep excess asset" function to `Pair` (or a `Router`-gated equivalent) that computes `excess = assetBalance() - assetReserve` (analogous to UniswapV2's `skim`) and routes it somewhere recoverable — e.g., back to `msg.sender`/original depositor if tracked, or to the protocol owner with an event for observability, matching the pattern already used for post-graduation LP donations (`pair.skim` + `_sweepLTToOwner`/`LTRescued`).

### Proof of Concept
1. `Bonding.launch` creates `tokenA` with paired LT `lt` and curve `Pair` at address `pairAddr`.
2. A trader (or anyone) calls `IERC20(lt).transfer(pairAddr, 1000e18)` directly, bypassing `Zap.buy`.
3. `Pair._pool.assetReserve` is unchanged (only `mint`/`swap` update it); `Pair.assetBalance()` is now `assetReserve + 1000e18`.
4. The curve trades normally and eventually graduates. `_prepareGraduationLiquidity` computes `ltFromPair = assetReserve - virtualLtReserve` using the stored reserve, excluding the donated `1000e18`.
5. `Router.graduate` drains only `ltFromPair`; the pair retains the donated `1000e18` LT.
6. `info.lifecycle` is now `Graduated`; no code path in `Bonding`, `Router`, or `Pair` can ever call `Pair.transferAsset` for that token again. The `1000e18` LT is permanently stranded in `pairAddr` with no rescue function to recover it.

    /// @notice Transfer exactly `amount` of LT out of the pair to the caller.
    ///         Called by `Bonding._prepareGraduationLiquidity` during graduation
    ///         with `amount = stored assetReserve - virtualLtReserve` (i.e. the
    ///         real LT raised by the curve, excluding the virtual seed).
    /// @dev    Donation-resistant: passing an explicit `amount` instead of
    ///         draining `assetBalance()` ensures any LT that was donated
    ///         directly to the pair via `IERC20.transfer` is left behind and
    ///         excluded from LP seeding.
    ///
    ///         "Locked" here is a trust-assumption claim, not an on-chain
    ///         guarantee. `Pair.transferAsset` is gated by `onlyRouter`, and
    ///         `Router` only exposes it via this function and `sell`. Both
    ///         require `BONDING_ROLE`, which only `Bonding` holds. `Bonding`
    ///         in turn only calls `graduate` from
    ///         `_prepareGraduationLiquidity` — which is unreachable once the
    ///         token's lifecycle has flipped past `Curve`. So the leftover
    ///         is unreachable as long as (a) `BONDING_ROLE` is not granted
    ///         to any other address, and (b) future `Bonding` upgrades
    ///         preserve the lifecycle gate.
    function graduate(
        address token,
        uint256 amount
    ) external onlyRole(BONDING_ROLE) {
        address asset = assetTokenFor(token);
        address pairAddr = factory.getPair(token, asset);
        if (pairAddr == address(0)) revert PairNotFound();
        IPair(pairAddr).transferAsset(msg.sender, amount);
    }

    function _prepareGraduationLiquidity(
        address tokenAddress
    ) internal returns (uint256 tokensForLP, uint256 ltFromPair, uint256 lpBurned, uint256 unsoldBurned) {
        address pairAddr = _s().tokenInfo[tokenAddress].pair;
        (uint256 tokenReserve, uint256 assetReserve) = IPair(pairAddr).getReserves();

        unsoldBurned = IPair(pairAddr).tokenBalance();
        if (unsoldBurned > 0) {
            Token(tokenAddress).burn(pairAddr, unsoldBurned);
        }

        ltFromPair = assetReserve - _launchTimeVirtualLtReserve(tokenAddress, pairAddr);
        if (ltFromPair > 0) {
            _s().router.graduate(tokenAddress, ltFromPair);
        }

        tokensForLP = assetReserve == 0 ? 0 : (ltFromPair * tokenReserve) / assetReserve;
        if (tokensForLP > LP_RESERVE) tokensForLP = LP_RESERVE;

        lpBurned = LP_RESERVE - tokensForLP;
        if (lpBurned > 0) {
            Token(tokenAddress).burn(address(this), lpBurned);
        }
    }
