Confirmed: `SimplexPaymaster` is deployed on Arbitrum mainnet (chain 42161) per `sdk/packages/sdk/src/configs/chain.ts:538` and its oracle price logic contains the same class of bug as the reported Chainlink staleness issue.

### Title
`SimplexPaymaster._getOraclePrice()` doesn't check the Arbitrum sequencer uptime feed, allowing stale Chainlink prices to be treated as fresh — ([File: evm/src/utils/SimplexPaymaster.sol])

### Summary
`SimplexPaymaster._getOraclePrice()` reads Chainlink's `latestRoundData()` and only validates the answer sign and staleness against `block.timestamp` [1](#0-0) . On Arbitrum, where this contract is deployed [2](#0-1) , this staleness check is meaningless during a sequencer outage: when the sequencer goes down, L2 block timestamps stop advancing at the normal cadence, and once it resumes, a burst of blocks can be produced with timestamps that make an old, unrefreshed Chainlink answer appear "fresh" relative to `block.timestamp`, or conversely the price feed used for pricing/settlement can be stale for the entire outage window without reverting.

### Finding Description
`_getOraclePrice` is the sole price source for both the gas-sponsorship pricing path (`_tokenPrice` → `validate`/`postOp` in the ERC-4337 flow) and the governance-triggered `swapAndDeposit` keeper flow, which uses the oracle price to bound the minimum acceptable output of a stablecoin→native swap through a Uniswap router [3](#0-2) . Neither path consults an L2 sequencer-uptime feed (e.g., Chainlink's `0xFdB631F5EE196F0ed6FAa767959853A9F217697D` sequencer-uptime feed on Arbitrum) before trusting `latestRoundData()`. This is the same root-cause bug class as the referenced report against `Kept.sol` — an unprotected `AggregatorV3Interface.latestRoundData()` consumer on an L2 that can have sequencer downtime.

### Impact Explanation
If the Arbitrum sequencer is down or has just recovered, `nativeOracle`/token oracle prices can be stale while still passing the `block.timestamp - updatedAt <= maxOracleAge` check, because `maxOracleAge` is set generously (up to 90,000 seconds / ~25h per the deploy script default) [4](#0-3) . This lets:
1. `swapAndDeposit` execute a stablecoin→native swap using a stale price as the minimum-output bound, allowing a swap to be executed at a manipulated/incorrect rate and draining value from the paymaster's stablecoin balance to the treasury/router at a bad rate, or letting a keeper's swap settle in a thin/manipulated post-outage market since the min-out bound is based on stale data.
2. `_tokenPrice`, used to size the ERC-20 stablecoin cost charged for gas sponsorship, mis-price gas cost in USDC/USDT terms during the outage window, allowing an attacker to under-pay (or the paymaster to overcharge) stablecoin for sponsored gas.

This is a concrete route to fund loss for the paymaster's treasury / solver funds via mispriced swaps, meeting the Medium-severity bar for oracle staleness bypass on an L2 dependent on Chainlink price feeds.

### Likelihood Explanation
Requires an actual Arbitrum sequencer outage or degraded-sequencer window, which is an infrequent but historically observed event (Arbitrum has had multi-hour sequencer outages). During such a window, anyone who can trigger `swapAndDeposit` (the treasury-controlled keeper per `PaymasterKeeperService`) or any UserOperation validated by the paymaster on Arbitrum is affected; the trigger doesn't require special privileges beyond normal protocol operation, only the timing coincidence with sequencer downtime.

### Recommendation
Add a Chainlink L2 sequencer-uptime-feed check (per Chainlink's documented pattern) to `_getOraclePrice`, gating on both `answer == 0` (sequencer up) and a grace period since `startedAt`, reverting for both `nativeOracle` and each `TokenConfig.tokenOracle` read when the sequencer is down or has not been up for the configured grace period, before trusting `updatedAt`-based staleness in `evm/src/utils/SimplexPaymaster.sol`'s `_getOraclePrice()` function.

### Proof of Concept
1. Sequencer goes down on Arbitrum; Chainlink price feeds stop updating `updatedAt` but `block.timestamp` on the L2 either freezes or later jumps forward in a burst once resumed.
2. `PaymasterKeeperService.recycleToken()` calls `paymaster.swapAndDeposit(token, 0)` [5](#0-4) , which internally calls `_tokenPrice`/`_getOraclePrice` to compute the oracle-bounded minimum swap output.
3. Because `_getOraclePrice` only checks `block.timestamp - updatedAt > maxOracleAge` (with `maxOracleAge` set to tens of thousands of seconds) and does not check sequencer liveness, the stale price is accepted [6](#0-5) .
4. The swap executes against the stale/incorrect price bound, letting the router fill at unfavorable rates, causing loss to the paymaster's swapped stablecoin reserves.

    function _tokenPrice(TokenConfig memory cfg) internal view returns (uint256) {
        uint256 nativeUsd = _getOraclePrice(nativeOracle, nativeOracleDecimals);
        uint256 tokenUsd = _getOraclePrice(cfg.tokenOracle, cfg.tokenOracleDecimals);

        return (nativeUsd * (10 ** cfg.tokenDecimals) * (10_000 + markupBps)) / (tokenUsd * 10_000);
    }

    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
