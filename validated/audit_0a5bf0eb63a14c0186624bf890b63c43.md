### Title
Emporium `runAction()` allows fully unauthenticated arbitrary external calls when reached via the zero-token `MainEVMCircuitMin` proof path - ([File: contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol])

### Summary
When `circomData.externalActionData.externalActionId == HINKAL_EMPORIUM_ACTION_ID` and `circomData.erc20TokenAddresses.length == 0`, `Hinkal.transact()` is verified against the trivial `MainEVMCircuitMin` circuit instead of the full `MainEVMCircuit`. That circuit has no nullifier, signature, or ownership constraints at all, so any unprivileged EOA can produce a valid proof for it. Combined with `EmporiumUpgradeable.verifyWallet()` skipping signature verification whenever `signerAddress == address(0)`, and with the Emporium balance-equality check being computed only over `circomData.erc20TokenAddresses` (empty in this path), an attacker can drive `runAction()` to execute arbitrary `op.endpoint.call{value: op.value}(op.callData)` calls from the Emporium contract with zero economic or cryptographic authorization.

### Finding Description
`Hinkal.transact()` selects the circuit/public-input builder based on `CircomDataBuilder.formInputForCircom`: [1](#0-0) 

When the action is the Emporium action and `erc20TokenAddresses.length == 0`, only `emporiumMessage`, `timeStamp`, and `calldataHash` are used as public inputs, and the underlying circuit is `MainEVMCircuitMin`, whose entire logic is: [2](#0-1) 

There is no `spendingPublicKey`, `eddsaSignature`, `nullifyingPrivateKey`, `rootHashHinkal`, or nullifier/commitment logic whatsoever — any prover can produce a valid proof for arbitrary self-chosen `messageSeed`/`calldataHash`/`timeStamp` because there is no secret witness tying the proof to a real UTXO or private key. `performHinkalChecks` only checks that `calldataHash` matches a hash of the (attacker-controlled) calldata, and calls `formInputForCircom`, then `Hinkal.transact()` verifies the trivial proof and proceeds: [3](#0-2) [4](#0-3) 

Since `erc20TokenAddresses.length == 0`, `_externalTransact` moves no funds itself and calls `runAction` directly: [5](#0-4) 

Inside `EmporiumUpgradeable.runAction`, `balancesBefore`/`balancesAfter` are computed only over `circomData.erc20TokenAddresses` (empty array here), so no balance-equality check exists for any other token the Emporium contract holds: [6](#0-5) 

`verifyWallet` is supposed to bind the `EmporiumOperation[]` (endpoint/value/callData) to a signer via EIP-712, but if the attacker sets `stack.signerAddress == address(0)` it just marks the message used and returns — no signature check at all: [7](#0-6) 

The "stateless" branch of the op loop then performs a completely attacker-controlled external call from the Emporium contract's context, blocking only the wallet-hijack selectors: [8](#0-7) 

Because `circomData.erc20TokenAddresses` is empty, the post-call balance check (`balanceChange < 0 → revert`) never runs for any token — an attacker can craft `op.callData = IERC20(token).transfer(attacker, amount)` against any ERC20 the Emporium contract holds (accumulated relay fees, dust left over from swaps/multi-op sequences, or any token temporarily routed through Emporium) and drain it without tripping any check, without a valid signature, and without proving ownership of any shielded UTXO.

This breaks the intended equality that ties Emporium's `EmporiumOperation[]` (and hence any external call it performs) to a valid `signedMessageHash`/nullifier-authorized spend — the design elsewhere ties `externalActionMetadata` into `calldataHash`, which is itself folded into `getSignedMessageHash` and checked against `eddsaSignature` in `MainEVMCircuit`: [9](#0-8) 
but that binding is entirely absent in the `MainEVMCircuitMin` path, so the "arbitrary call authorized by a real signer/prover" invariant does not hold on this path.

### Impact Explanation
This is unauthorised asset movement / theft of protocol funds: an attacker with no shielded balance, no signature, and no valid nullifier can force the Emporium contract to execute arbitrary external calls (e.g., ERC20 `transfer`/`approve`+`transferFrom`) and drain any token balance sitting in the Emporium contract that is not explicitly listed in `circomData.erc20TokenAddresses`. This matches the "High — theft … of protocol/relay fees, temporary freezing of user funds … executing calls or moving assets a wallet owner or prover never authorised" criterion, and could reach "Critical" if user shielded funds are ever transiently held in the Emporium contract during a batched operation sequence.

### Likelihood Explanation
High: the `MainEVMCircuitMin` verifier (`mainEVMCircuit1x2x2v4`-style naming convention shows a dedicated `mainEVMCircuitMin0v4` verifier is registered) is a first-class, intentionally supported code path (`erc20TokenAddresses.length == 0` combined with the Emporium action id is explicitly branched on in `formInputForCircom`), not a theoretical/edge configuration. Generating a valid Groth16 proof for `MainEVMCircuitMin` requires no secret — any EOA can do it off the shelf with snarkjs given the circuit and proving key, which are public artifacts.

### Recommendation
Require the same EIP-712 signature/authorization binding for the zero-token Emporium action as for the funded path, or disallow `stack.signerAddress == address(0)` entirely for stateless external calls; alternatively, always compute/verify a `balancesBefore`/`balancesAfter` check against the full set of tokens the Emporium contract could plausibly move, and ensure `MainEVMCircuitMin` cannot be used to reach `runAction` without cryptographic proof of authorization over the exact `EmporiumOperation[]` being executed.

### Proof of Concept
1. Deploy/observe that the Emporium proxy holds some ERC20 balance (e.g., accumulated relay-fee dust from prior transactions).
2. Off-chain, craft `circomData` with: `erc20TokenAddresses = []`, `amountChanges = []`, `externalActionData.externalActionId = HINKAL_EMPORIUM_ACTION_ID`, `externalActionData.externalAddress = <Emporium proxy>`, `externalActionData.externalActionMetadata = abi.encode(EmporiumStack{ signerAddress: address(0), ops: [EmporiumOperation{endpoint: <token>, invokeWallet: false, value: 0, callData: abi.encodeCall(IERC20.transfer, (attacker, dustAmount))}] , maxFee:0, deadline: type(uint256).max, v/r/s: 0})`.
3. Compute `calldataHash = CircomDataBuilder.getHashedCalldata(circomData)` and set it in `circomData.calldataHash`; pick any `messageSeed`, compute `message = Poseidon(messageSeed)`, and generate a valid Groth16 proof `(a,b,c)` for `MainEVMCircuitMin` with public inputs `[emporiumMessage, timeStamp, calldataHash]` — no private key or nullifier knowledge required.
4. Call `Hinkal.transact(a, b, c, dimensions{tokenNumber:0,...}, circomData)` from any EOA.
5. `performHinkalChecks` passes (calldata hash matches), the trivial proof verifies, `_externalTransact` calls `EmporiumUpgradeable.runAction`, `verifyWallet` returns immediately (signer is zero), the stateless op executes `IERC20(token).transfer(attacker, dustAmount)` from the Emporium contract, and since `erc20TokenAddresses` is empty, no balance check catches the outgoing transfer.

    function runAction(
        CircomData calldata circomData,
        int256[] calldata deltaAmountChanges
    ) external override onlyAllowedRecipient returns (UTXO[] memory) {
        EmporiumStack memory stack = abi.decode(
            circomData.externalActionData.externalActionMetadata,
            (EmporiumStack)
        );

        uint256[] memory balancesBefore = getBalancesForArray(
            circomData.erc20TokenAddresses
        );

        verifyWallet(stack, circomData);

        for (uint256 i = 0; i < stack.ops.length; i++) {
            EmporiumOperation memory op = stack.ops[i];

            bool success;
            bytes memory err;

            // CASE 1: Stateful Interaction
            if (op.invokeWallet && stack.signerAddress != address(0)) {
                (success, err) = IHinkalWallet(stack.signerAddress)
                    .callHinkalWallet(op.endpoint, op.callData, op.value);
            }
            // CASE 2: Stateless Interaction
            else {
                bytes4 selector = bytes4(op.callData);
                if (
                    selector == IHinkalWallet.callHinkalWallet.selector ||
                    selector == IHinkalWallet.doSendToRelay.selector
                ) {
                    revert UnauthorizedWalletCall();
                }

                (success, err) = op.endpoint.call{value: op.value}(op.callData);
            }

            if (!success) {
                revert CallFailed(err);
            }
        }
