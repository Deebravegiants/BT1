### Title
Missing timestamp/deadline validation in OAuth callback allows replay of stale authorization requests - (File: `lib/shopify_api/auth/oauth.rb`)

### Summary
`ShopifyAPI::Auth::Oauth.validate_auth_callback` verifies the integrity of the callback query (via HMAC) and matches the `state` nonce against the session cookie, but never checks the `timestamp` field for freshness. The `timestamp` is part of the HMAC-signed payload but is otherwise unused, so a captured/leaked OAuth callback URL remains cryptographically "valid" to this library indefinitely, with no deadline enforced on its own end — the exact bug class described in the report (a signed field/parameter that should bound execution to a time window, but is never checked against `now`).

### Finding Description
`AuthQuery#to_signable_string` includes `timestamp` in the string that gets HMAC-signed: [1](#0-0) 

`Utils::HmacValidator.validate` only checks that the signature over `code, host, shop, state, timestamp` matches — it treats `timestamp` purely as signed data, never comparing it to `Time.now`: [2](#0-1) 

`Oauth.validate_auth_callback` then only performs: (1) HMAC validation, (2) private-app check, (3) cookie-state equality check against `auth_query.state`. It never inspects `auth_query.timestamp`: [3](#0-2) 

The only other place a time bound is applied is the `SessionCookie`'s browser expiry (`Time.now + 60`) set at `begin_auth`, which is enforced by the browser deleting the cookie — not by this library: [4](#0-3) 

Because the library performs no server-side check that `auth_query.timestamp` is recent, the binding that should hold is: `time_of_use == time_of_issuance` (within a bounded window). Instead, the code only proves `hmac(query) == expected` and `cookie.state == query.state`, with no upper bound on how long after issuance the callback may be replayed through this library's own logic.

### Impact Explanation
This maps to the "forced OAuth completion" category: if a stale or previously-observed callback URL (e.g. leaked via browser history, proxy/access logs, Referer headers, or a shared/rediscovered link) is replayed, and the corresponding `state` cookie value is still present in the browser (or an attacker can plant/fixate that cookie value ahead of time), `validate_auth_callback` will accept the request as fully valid and proceed to exchange the `code` for an access token — with no check on how much time has elapsed since the callback was originally issued. This effectively removes a defense-in-depth check that this library should apply on its own, independent of whatever expiry Shopify's own `/oauth/authorize` endpoint enforces on `code`.

### Likelihood Explanation
Requires an attacker to obtain a valid, HMAC-signed callback query string (leaked/logged/observed) and have (or fixate) a matching state cookie in the victim's browser. This is a real, documented OAuth CSRF/replay pattern (state-fixation + delayed replay), and the fact that `timestamp` is deliberately included in Shopify's signed callback payload — precisely so consuming code can bound its acceptance window — but is never read anywhere in this gem, makes the gap concrete and directly attributable to this library's logic rather than to host-application misuse.

### Recommendation
In `ShopifyAPI::Auth::Oauth.validate_auth_callback`, after validating the HMAC, parse `auth_query.timestamp` and reject the callback with `Errors::InvalidOauthError` if `Time.now.to_i - timestamp.to_i` exceeds a small bounded window (e.g. a few minutes), mirroring the deadline check recommended in the report.

### Proof of Concept
1. A legitimate OAuth callback URL is generated by Shopify and hits the app's callback endpoint, e.g.:
`.../auth/callback?code=...&host=...&shop=shop.myshopify.com&state=nonce&timestamp=1690000000&hmac=<valid>`
2. This URL (with valid `hmac`) is captured (e.g. via server access logs, proxy logs, or browser history) well after issuance.
3. Later, an attacker gets the `state` cookie (`shopify_app_session`) with value `nonce` set in a victim's browser (e.g. via session/cookie fixation) and causes the browser to hit the same callback URL.
4. `ShopifyAPI::Auth::Oauth.validate_auth_callback(cookies:, auth_query:)` is called:
   - `Utils::HmacValidator.validate(auth_query)` → `true` (signature still valid, no expiry logic exists).
   - `state == auth_query.state` → `true`.
   - No check exists anywhere on `auth_query.timestamp`, so the flow proceeds to exchange `code` for an access token as if the request had just occurred. [5](#0-4)

        def validate_auth_callback(cookies:, auth_query:)
          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::InvalidOauthError, "Invalid OAuth callback." unless Utils::HmacValidator.validate(auth_query)
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = cookies[SessionCookie::SESSION_COOKIE_NAME]
          raise Errors::NoSessionCookieError unless state

          raise Errors::InvalidOauthError,
            "Invalid state in OAuth callback." unless state == auth_query.state

          null_session = Auth::Session.new(shop: auth_query.shop)
          body = {
            client_id: Context.api_key,
            client_secret: Context.api_secret_key,
            code: auth_query.code,
            expiring: Context.expiring_offline_access_tokens ? 1 : 0, # Only applicable for offline tokens
          }

          client = Clients::HttpClient.new(session: null_session, base_path: "/admin/oauth")
          response = begin
            client.request(
              Clients::HttpRequest.new(
                http_method: :post,
                path: "access_token",
                body: body,
                body_type: "application/json",
              ),
            )
          rescue ShopifyAPI::Errors::HttpResponseError => e
            raise Errors::RequestAccessTokenError,
              "Cannot complete OAuth process. Received a #{e.code} error while requesting access token."
          end

          session_params = T.cast(response.body, T::Hash[String, T.untyped]).to_h
          session = Session.from(shop: auth_query.shop,
            access_token_response: Oauth::AccessTokenResponse.from_hash(session_params))
