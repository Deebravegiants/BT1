### Title
PodNodeSelector admission plugin only registers for Create, allowing NodeSelector mutation via gated-pod Update to bypass namespace node-selector/whitelist enforcement - ([File: plugin/pkg/admission/podnodeselector/admission.go])

### Summary
`NewPodNodeSelector` registers the plugin with `admission.NewHandler(admission.Create)` only, so `Plugin.Admit`/`Plugin.Validate` never run on Pod Update requests. `ValidatePodUpdate` in the core validation package explicitly allows *additions* to `Spec.NodeSelector` for pods that still have `SchedulingGates` set (via `validateNodeSelectorMutation`), meaning an unprivileged user with only `update`/`patch` rights on a gated pod can add arbitrary node-selector labels post-creation without ever going through the namespace's node-selector conflict check or whitelist enforcement.

### Finding Description
The plugin is wired up as create-only:
<cite repo="Tylerpinwa/kubernetes--011" path="plugin/pkg/admission/podnodeselector/admission.go" start="195|201" end="195|201" /> [1](#0-0) 

Both `Admit` (which merges namespace selector into the pod and enforces conflicts) and `Validate` (which enforces the whitelist) are only invoked for `Create` because `admission.NewHandler(admission.Create)` sets the handler's supported operations: [2](#0-1) 

Meanwhile, `ValidatePodUpdate` in the core validation code treats `Spec.NodeSelector` as generally immutable, *except* it explicitly permits additive-only mutations when the pod still carries `SchedulingGates` (a legitimate KEP-3521 feature for mutable scheduling directives): [3](#0-2) 

Because the podnodeselector admission plugin never runs on Update, this validation-layer allowance for gated pods has no corresponding re-check of the namespace's forced/whitelisted node selectors. An attacker who can create a gated pod (with `spec.schedulingGates` non-empty) and later `update`/`patch` that same pod can add new `nodeSelector` entries that conflict with, or fall outside, the namespace's configured `scheduler.alpha.kubernetes.io/node-selector` annotation or the plugin's `clusterNodeSelectors` whitelist — entirely bypassing the isolation the admin configured via `PodNodeSelector`.

### Impact Explanation
This allows a tenant confined by namespace-scoped node-selector policy (a common multi-tenant isolation mechanism to keep workloads from a given namespace pinned to specific node pools) to steer a pod onto nodes outside its permitted set by exploiting the gated-pod update path, bypassing an admission-enforced isolation boundary. This matches the "admission bypass leading to cross-tenant/workload isolation escape" bounty class, though impact is bounded to scheduling placement rather than direct privilege escalation, and is only reachable when scheduling gates are used.

### Likelihood Explanation
Requires only namespace-scoped RBAC permitting `create` and `update`/`patch` on `pods` — permissions many ordinary users/service accounts already have. The pod must be created with a non-empty `spec.schedulingGates` (fully controllable by the requester) so the pod remains "gated" until the malicious update is applied, and the update must occur before the gate is removed and the pod is scheduled. This is deterministic and repeatable, not dependent on races beyond timing the update before the gate-removal/scheduling.

### Recommendation
Extend `NewPodNodeSelector` to also handle `admission.Update` (`admission.NewHandler(admission.Create, admission.Update)`), and have `Plugin.Admit`/`Plugin.Validate` re-validate/re-merge `Spec.NodeSelector` against the namespace's selector and whitelist whenever it changes on update (in addition to the existing gated-pod additive-mutation check in `ValidatePodUpdate`).

### Proof of Concept
Integration test plan:
1. Configure `PodNodeSelector` admission plugin with a namespace annotation `scheduler.alpha.kubernetes.io/node-selector: "team=a"` and/or a whitelist `clusterNodeSelectors["ns"] = "team=a,zone=z1"`.
2. As an unprivileged user with namespace-scoped `pods` create/update RBAC, create a pod with `spec.schedulingGates: [{name: "example.com/gate"}]` and no `nodeSelector` (passes Create-time admission, which merges in `team=a`).
3. Update the pod (still gated) adding `nodeSelector: {team: "a", zone: "z2"}` (an addition, not a deletion/mutation of existing keys, so `ValidatePodUpdate`'s `validateNodeSelectorMutation` allows it) where `zone=z2` violates the whitelist/conflicts with intended policy.
4. Assert the update succeeds (200 OK) and `pod.Spec.NodeSelector["zone"] == "z2"` persists, demonstrating that neither the namespace-conflict check (`labels.Conflicts`) nor the whitelist check (`isSubset`) in `plugin/pkg/admission/podnodeselector/admission.go` were applied, confirming the bypass.

// Admit enforces that pod and its namespace node label selectors matches at least a node in the cluster.
func (p *Plugin) Admit(ctx context.Context, a admission.Attributes, o admission.ObjectInterfaces) error {
	if shouldIgnore(a) {
		return nil
	}
	if !p.WaitForReady() {
		return admission.NewForbidden(a, fmt.Errorf("not yet ready to handle request"))
	}

	resource := a.GetResource().GroupResource()
	pod := a.GetObject().(*api.Pod)
	namespaceNodeSelector, err := p.getNamespaceNodeSelectorMap(a.GetNamespace())
	if err != nil {
		return err
	}

	if labels.Conflicts(namespaceNodeSelector, labels.Set(pod.Spec.NodeSelector)) {
		return errors.NewForbidden(resource, pod.Name, fmt.Errorf("pod node label selector conflicts with its namespace node label selector"))
	}

	// Merge pod node selector = namespace node selector + current pod node selector
	// second selector wins
	podNodeSelectorLabels := labels.Merge(namespaceNodeSelector, pod.Spec.NodeSelector)
	pod.Spec.NodeSelector = map[string]string(podNodeSelectorLabels)
	return p.Validate(ctx, a, o)
}

// Validate ensures that the pod node selector is allowed
func (p *Plugin) Validate(ctx context.Context, a admission.Attributes, o admission.ObjectInterfaces) error {
	if shouldIgnore(a) {
		return nil
	}
	if !p.WaitForReady() {
		return admission.NewForbidden(a, fmt.Errorf("not yet ready to handle request"))
	}

	resource := a.GetResource().GroupResource()
	pod := a.GetObject().(*api.Pod)

	namespaceNodeSelector, err := p.getNamespaceNodeSelectorMap(a.GetNamespace())
	if err != nil {
		return err
	}
	if labels.Conflicts(namespaceNodeSelector, labels.Set(pod.Spec.NodeSelector)) {
		return errors.NewForbidden(resource, pod.Name, fmt.Errorf("pod node label selector conflicts with its namespace node label selector"))
	}

	// whitelist verification
	whitelist, err := labels.ConvertSelectorToLabelsMap(p.clusterNodeSelectors[a.GetNamespace()])
	if err != nil {
		return err
	}
	if !isSubset(pod.Spec.NodeSelector, whitelist) {
		return errors.NewForbidden(resource, pod.Name, fmt.Errorf("pod node label selector labels conflict with its namespace whitelist"))
	}

	return nil
}
