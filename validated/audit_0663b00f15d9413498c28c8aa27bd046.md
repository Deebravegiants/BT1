### Title
Bad-debt cleanup leaves wiped supply shares redeemable against future deposits - (File: contracts/pool/src/interest.rs)

### Summary

Borrow-side bad-debt cleanup lowers the supply index to reflect the loss, but clamps the result to `SUPPLY_INDEX_FLOOR_RAW` instead of allowing a complete write-down. The wiped suppliers’ old shares therefore retain a positive residual claim even when the market has no cash or debt backing. A later deposit can satisfy that stale claim, allowing an attacker who held wiped supply shares to withdraw the fresh depositor’s funds.

### Finding Description

`execute_bad_debt_cleanup` submits both deposit and borrow positions to `pool_seize_positions_call` before removing the insolvent account and burning its NFT. [1](#0-0) 

For a borrow-side entry, `ops::seize::apply` converts the position to its outstanding debt value, calls `interest::apply_bad_debt_to_supply_index`, and then burns the debt shares. [2](#0-1) 

The documented accounting model explicitly makes `supply_index` non-monotone during this path and floors it at `RAY/1000`. [3](#0-2) 

When the bad debt is equal to or greater than the surviving supply value, the economically correct index is zero, but the upward clamp leaves every old supply share worth a non-zero amount. The repository’s pool test demonstrates this exact state: 1,000 wiped supply shares are clamped to a positive residual, a new 1-unit deposit is credited to cash, and the wiped holder withdraws that unit in full. [4](#0-3) 

The withdrawal path then resolves the stale position into a positive gross amount, permits the debit, burns the shares, and commits the reduced cash balance. [5](#0-4) 

This is analogous to the kernel bug class because cleanup leaves a resource that should have been fully released still usable: bad-debt socialization semantically destroys the supply claim, while the non-zero floor resurrects part of that claim against later liquidity.

### Impact Explanation

An attacker can hold supply shares in a market before bad debt is cleaned, invoke the permissionless `clean_bad_debt` path on an eligible insolvent account, wait for another user to supply the same market, and withdraw the residual claim created by the supply-index floor. The withdrawal pays the wiped holder from the new depositor’s cash while leaving the new depositor’s shares insufficiently backed, which is theft of user funds and can make the market permanently insolvent. [6](#0-5) 

The extracted amount is bounded by the residual value left by the floor, but repeating the cycle across fresh deposits or markets can drain each new deposit up to the stranded claim. Once cash is removed, subsequent honest withdrawals can fail even though the pool’s books still show outstanding supply claims. [7](#0-6) 

### Likelihood Explanation

The attack requires a market whose bad-debt socialization would write the supply index below `RAY/1000`, plus an attacker-controlled supply position that survives cleanup. Both are reachable through normal `supply`, `borrow`, interest accrual, price movement, and the unprivileged dust-gated `clean_bad_debt` entrypoint; the residual holder can then call `withdraw`, and any subsequent user can trigger the loss through `supply`. [8](#0-7) 

Likelihood is medium because the exploit depends on a severe insolvency and fresh liquidity arriving afterward, but no privileged role, leaked key, token malfunction, or third-party oracle violation is required. [2](#0-1) 

### Recommendation

Do not clamp a calculated bad-debt write-down upward when doing so creates economically unbacked supply claims. If the loss exhausts supplier value, set the index to the exact covered value and either retire all residual supply shares, mark the market as wiped and prevent new supply until recapitalization, or otherwise ensure old shares cannot redeem later deposits. Add an integration-level regression that performs permissionless bad-debt cleanup, makes a new deposit, and verifies that wiped shares cannot withdraw from that deposit.

### Proof of Concept

1. Alice supplies 1,000 units and Bob borrows enough that the borrow position later becomes eligible for dust-gated `clean_bad_debt`.
2. A caller invokes `clean_bad_debt(account_id = BobAccount)`.
3. The borrow-side seize writes the full loss into the supply index, but `apply_bad_debt_to_supply_index` clamps it to `SUPPLY_INDEX_FLOOR_RAW`; Alice’s shares now retain a positive residual claim despite zero backing. [9](#0-8) 
4. Carol supplies the same asset, crediting real cash to the pool.
5. Alice calls `withdraw` for her old supply shares.
6. Withdrawal pays Carol’s deposit to Alice, leaving Carol with shares whose cash backing has been removed. The existing pool test reproduces this sequence and asserts that Alice extracts exactly the fresh deposit while Carol’s claim exceeds remaining cash. [10](#0-9)

fn test_raw_cache_seizure_residual_would_drain_fresh_cash_without_supply_guard() {
    let t = TestSetup::new();
    t.as_contract(|| {
        let alice_scaled_raw = 1_000 * RAY;
        let borrowed_scaled_raw = 1_000 * RAY;
        let mut cache = t.fresh_cache(PoolStateRaw {
            supplied: alice_scaled_raw,
            borrowed: borrowed_scaled_raw,
            revenue: 0,
            borrow_index: RAY,
            supply_index: RAY,
            last_timestamp: 0,
            cash: 0,
        });
        let alice_scaled = Ray::from(alice_scaled_raw);
        let borrow_scaled = Ray::from(borrowed_scaled_raw);

        let bad_debt = cache.unscale_borrow_ceil_ray(borrow_scaled);
        apply_bad_debt_to_supply_index(&mut cache, bad_debt);
        cache.burn_debt(borrow_scaled);

        assert_eq!(
            cache.supply_index().raw(),
            SUPPLY_INDEX_FLOOR_RAW,
            "seize wipeout clamps supply_index UP to RAY/1000, leaving unburned shares a residual"
        );

        let alice_stranded = cache.unscale_supply_floor(alice_scaled);
        assert!(alice_stranded > 0, "wiped survivor keeps a stranded claim");
        assert_eq!(
            cache.cash(),
            0,
            "empty market: claim masked by require_reserves"
        );

        let deposit = alice_stranded;
        let bob_scaled = cache.calculate_scaled_supply(deposit);
        cache.mint_supply(bob_scaled);
        cache.credit_cash(deposit);

        let total_owed = cache.unscale_supply_floor(cache.supplied());
        assert!(
            total_owed > cache.cash(),
            "post-deposit books insolvent: owed {} > cash {}",
            total_owed,
            cache.cash()
        );

        let (burn, gross) = cache.resolve_withdrawal(i128::MAX, alice_scaled);
        cache.require_reserves(gross);
        cache.burn_supply(burn);
        cache.debit_cash(gross);

        assert!(gross > 0, "wiped position pays out real cash");
        assert_eq!(gross, deposit, "Alice extracts exactly Bob's fresh deposit");

        let bob_claim = cache.unscale_supply_floor(bob_scaled);
        assert!(
            cache.cash() < bob_claim,
            "cash {} cannot cover Bob's honest claim {}: fresh depositor lost funds",
            cache.cash(),
            bob_claim
        );

/// Authorizes permissionless dust-gated cleanup outside flash loans.
pub(crate) fn process_clean_bad_debt(env: &Env, caller: &Address, account_id: u64) {
    caller.require_auth();
    validation::require_not_flash_loaning(env);
    clean_bad_debt_standalone(env, account_id);
}

/// Admission condition for bad-debt socialization.
#[derive(Clone, Copy, PartialEq)]
enum BadDebtGate {
    /// Permissionless: insolvent *and* collateral at or below the dust threshold.
    DustCapped,
    /// Owner-only: insolvent alone, with no cap on the collateral left behind.
    InsolventOnly,
}

/// Requires open debt and the selected insolvency gate, then cleans up the account.
fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    bad_debt::execute_bad_debt_cleanup(env, &mut cache, account_id, &account, &totals);
