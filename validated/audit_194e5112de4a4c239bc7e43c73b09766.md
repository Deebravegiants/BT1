### Title
`flash_position` bypasses the strategy origination fee - (File: contracts/controller/src/strategies/flash_position.rs)

### Summary
An account owner can open the same leveraged position as `multiply` through `flash_position` without paying the configured strategy fee. `multiply` mints strategy debt with `charge_fee = true`, while `flash_position` deliberately invokes the same borrowing primitive with `charge_fee = false`. [1](#0-0) [2](#0-1) 

### Finding Description
`multiply` calls `borrow_into_controller` with `charge_fee = true`, causing the pool to withhold `flashloan_fee` and book it as protocol revenue. [1](#0-0) [3](#0-2) 

The permissionless `flash_position` entrypoint instead mints the gross debt, forwards the full measured receipt to a caller-selected Wasm receiver, and invokes `execute_flash_position` with `fee = 0`. [4](#0-3) [5](#0-4) [6](#0-5) 

After the callback, the controller measures the receiver's collateral transfer, deposits the resulting balance increase into the caller's account, and applies the same solvency finalization used by `multiply`. [7](#0-6) [8](#0-7) 

The regression test confirms equivalence: both routes incur comparable debt and acquire collateral, but `multiply` books the expected origination fee while `flash_position` books zero and consequently obtains more collateral. [9](#0-8) 

### Impact Explanation
Every leveraged-position user can retain the configured origination fee instead of paying it to protocol revenue. Since the resulting account records the same gross debt while receiving more usable proceeds, the skipped amount is value that should have been added to the pool's `revenue` shares. [10](#0-9) [11](#0-10) 

This is theft or prevention of unclaimed protocol yield rather than a harmless routing difference: users systematically choosing `flash_position` deprive the protocol of every strategy origination fee on those positions. [12](#0-11) 

### Likelihood Explanation
Any account owner can exploit this with an owned flash receiver and a flash-loan-enabled debt market; no privileged role, malformed parameter, oracle manipulation, or external victim is required. [13](#0-12) 

The receiver can perform the debt-to-collateral conversion itself or through normal DEX liquidity and only needs to transfer at least the declared collateral minimum back to the controller before returning. [14](#0-13) [8](#0-7) 

The only material prerequisite is `is_flashloanable` on the debt market, but `flash_position` is intentionally exposed for arbitrary caller-selected receivers once that market flag is enabled. [15](#0-14) 

### Recommendation
Charge `flash_position` the same origination fee as `multiply` for equivalent debt, or document and enforce a distinct fee policy that cannot be used to replace `multiply` fee-free. [16](#0-15) 

The direct correction is to pass `true` to `borrow_into_controller` in `mint_and_forward`, pass the nonzero resulting fee to the callback, and size the forwarded amount from `amount_received` net of that fee. [5](#0-4) [17](#0-16) 

If fee-free custom receivers are intended, `multiply` should instead expose equivalent execution semantics without the fee; otherwise both entrypoints must share one fee policy to remove the economic routing decision. [18](#0-17) [19](#0-18) 

### Proof of Concept
1. Configure a debt market with a positive `flashloan_fee` and `is_flashloanable = true`. [20](#0-19) [17](#0-16) 
2. Deploy a Wasm receiver implementing `execute_flash_position`; when invoked, swap or otherwise source the target collateral and transfer it to the controller. [21](#0-20) 
3. Call `multiply(account_id = 0, collateral = USDC, debt_to_flash_loan = 1 ETH, debt = ETH, mode = Multiply, ...)` and record `ETH` debt, `USDC` collateral, and ETH-market revenue. [22](#0-21) [23](#0-22) 
4. Call `flash_position(account_id = 0, debt = ETH, amount = 1 ETH, receiver = owned_receiver, collaterals = [(USDC, min)], ...)`; the receiver returns enough USDC to satisfy `min`. [24](#0-23) [7](#0-6) 
5. Compare the positions: the existing harness test shows nearly equal debt, greater collateral from `flash_position`, the exact origination fee booked for `multiply`, and zero revenue booked for `flash_position`. [9](#0-8)

#[test]
fn flash_position_substitutes_multiply_without_origination_fee() {
    let (mul_collateral, mul_debt, mul_revenue) = open_via_multiply();
    let (fp_collateral, fp_debt, fp_revenue) = open_via_flash_position();

    std::println!("multiply       : collateral={mul_collateral:.4} USDC  debt={mul_debt:.6} ETH  revenue={mul_revenue}");
    std::println!("flash_position : collateral={fp_collateral:.4} USDC  debt={fp_debt:.6} ETH  revenue={fp_revenue}");

    // Same debt taken on both routes.
    assert!(
        (mul_debt - fp_debt).abs() < 0.01,
        "routes should take comparable debt: multiply={mul_debt} flash_position={fp_debt}"
    );

    // `multiply` books exactly the fee on 1.0 ETH of strategy debt at
    // `DEFAULT_FLASHLOAN_FEE_BPS`; `flash_position` books nothing.
    let strategy_debt_raw = 10_000_000i128;
    let expected_fee = strategy_debt_raw - apply_flash_fee(strategy_debt_raw);
    assert_eq!(
        mul_revenue, expected_fee,
        "multiply must book exactly the origination fee on {strategy_debt_raw} \
         raw ETH of debt: expected {expected_fee}, got {mul_revenue}"
    );
    assert_eq!(
        fp_revenue, 0,
        "flash_position books no protocol revenue, got {fp_revenue}"
    );

    // The fee-free route ends with more collateral for the same debt.
    assert!(
        fp_collateral > mul_collateral,
        "flash_position should yield more collateral for the same debt: \
         multiply={mul_collateral} flash_position={fp_collateral}"
    );
