Audit Report

## Title
LDAP Session Authentication Accepts Empty Password via Unauthenticated Bind, Allowing Login as Any Known User - (File: core/sessions/ldapauth/ldap.go)

## Summary
`ldapAuthenticator.CreateSession` performs an LDAP simple bind using the caller-supplied `sr.Password` without validating that it is non-empty before calling `conn.Bind(searchBaseDN, sr.Password)`. Per RFC 4513 §5.1.2, a simple bind with a valid DN and zero-length password is an "unauthenticated bind," which many LDAP servers treat as successful, letting an unprivileged client authenticate as any known user without a valid credential.

## Finding Description
`CreateSession` builds the bind DN directly from `sr.Email` and forwards `sr.Password` unmodified into `conn.Bind`, with no check rejecting an empty password: [1](#0-0) . If the bind reports success, the code proceeds to `FindUser` to resolve the user's role and, absent any further password verification, inserts a new persisted row into `ldap_sessions` and returns a valid session ID: [2](#0-1) . This contrasts with the sibling `localauth` implementation, which always verifies a password hash via `utils.CheckPasswordHash` before issuing a session: [3](#0-2) . The unauthenticated `/sessions` HTTP endpoint accepts arbitrary `email`/`password` JSON and routes directly into `CreateSession` with no prior authentication required: [4](#0-3) .

## Impact Explanation
If the operator's upstream LDAP server permits unauthenticated ("anonymous") binds for the searched DN, an unprivileged network client can obtain a fully persisted Chainlink session for any user whose email is known or guessed — including admin accounts — by submitting a login request with an empty password. This grants session-level access to the node's HTTP API depending on the impersonated user's role, satisfying an in-scope "node API authentication/role bypass" impact.

## Likelihood Explanation
The vulnerability is directly reachable by an unprivileged actor through the public `/sessions` endpoint with only a known/guessed email address — no credential, host access, or elevated role is required. The Chainlink code itself provides no defense-in-depth against unauthenticated bind, unlike its `localauth` sibling. Exploitability is conditioned on the external LDAP server's configuration (whether unauthenticated bind is permitted for the target DN), but the missing empty-password guard in `CreateSession` is a real, current gap in the reachable code path, not a hypothetical one.

## Recommendation
In `ldapAuthenticator.CreateSession`, explicitly reject session requests where `sr.Password == ""` before calling `conn.Bind`, so that the code does not rely on the upstream LDAP server's unauthenticated-bind behavior for security.

## Proof of Concept
1. Configure a Chainlink node with `AuthenticationProviderName = ldap` pointing at an LDAP server that permits unauthenticated bind for valid DNs.
2. As an unprivileged client, `POST /sessions` with `{"email": "admin@company.com", "password": ""}`.
3. `conn.Bind(searchBaseDN, "")` succeeds as an unauthenticated bind; `FindUser` resolves the admin's role; a row is inserted into `ldap_sessions`; a valid session cookie is returned without ever supplying a correct password.

// Create creates a session ID for the given user credentials, and returns it
// in a cookie.
func (sc *SessionsController) Create(c *gin.Context) {
	defer sc.App.WakeSessionReaper()
	ctx := c.Request.Context()
	sc.App.GetLogger().Debugf("TRACE: Starting Session Creation")

	session := sessions.Default(c)
	var sr clsessions.SessionRequest
	if err := c.ShouldBindJSON(&sr); err != nil {
		jsonAPIError(c, http.StatusBadRequest, fmt.Errorf("error binding json %w", err))
		return
	}

	// Does this user have 2FA enabled?
	userWebAuthnTokens, err := sc.App.AuthenticationProvider().GetUserWebAuthn(ctx, sr.Email)
	if err != nil {
		sc.App.GetLogger().Errorf("Error loading user WebAuthn data: %s", err)
		jsonAPIError(c, http.StatusInternalServerError, errors.New("internal Server Error"))
		return
	}

	// If the user has registered MFA tokens, then populate our session store and context
	// required for successful WebAuthn authentication
	if len(userWebAuthnTokens) > 0 {
		sr.SessionStore = sc.sessions
		sr.WebAuthnConfig = sc.App.GetWebAuthnConfiguration()
	}

	sid, err := sc.App.AuthenticationProvider().CreateSession(ctx, sr)
	if err != nil {
		jsonAPIError(c, http.StatusUnauthorized, err)
		return
	}
