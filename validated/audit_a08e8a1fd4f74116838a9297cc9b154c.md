### Title
Sub-3-decimal collateral legs create a liquidation dead-band where every liquidation offer reverts, temporarily freezing an underwater account - (File: contracts/controller/src/positions/liquidation/mod.rs)

### Summary
The liquidation planner special-cases collateral legs on markets with fewer than 3 decimals: seizure is quantized to whole token units. Two corrective rules exist — rounding up to one whole unit when the curve quote's one-unit value covers the whole debt plus one base unit per debt leg, and bumping the quote to back one unit plus a `1e-6` margin when that repayment is below the whole debt — but they leave an explicit gap: a debt whose curve quote backs less than one unit, where neither correction applies, makes **every** liquidation offer revert. The protocol's own invariant documentation states that in this band "every offer reverts until accrual or a price move ends that state" [1](#0-0) .

### Finding Description
This is the analog of CVE-2018-2622's "easily exploitable, low-privileged attacker causes a repeatable crash/hang": an unprivileged borrower can deliberately size a position so that its only collateral leg is a sub-3-decimal asset and its debt lands inside the revert band.

Mechanism:
- Whole-unit legs are forced to be the account's only supply position, so the seizure stays proportional and there is no second collateral leg to route around the reversion [2](#0-1) .
- Liquidation sizing derives the repayment quote from the HF-based bonus curve; for whole-unit legs the plan either rounds up to a full close (only when `one_unit_value / (1 + bonus)` covers whole debt + one base unit per debt leg) or bumps the quote to back one unit plus the `1e-6` margin (only if that bumped repayment is below the whole debt) [3](#0-2) .
- Between those two boundaries — quote backs less than one unit, and the one-unit-plus-margin repayment is not below the whole debt — a plan is left with no seizure and reverts. The revert is in the plan/settle path (`positions/liquidation` module feeding pool `ops::seize`), not a caller mistake, so it reproduces for every liquidator and every offer size while the band holds [4](#0-3) .

An attacker reaches this state through the ordinary permissionless path: `supply` a whole-unit (<3 decimals) asset as sole collateral, `borrow` against it sized so the debt falls in the band, then let the account drift below `HF = 1` via interest accrual or a price tick. While the account sits in the band, no `liquidate` call can succeed against it.

### Impact Explanation
Temporary freezing of funds / delayed insolvency cleanup. For the duration of the band the account is unliquidatable: liquidators' attempts revert, so the distressed debt keeps accruing (`global_sync` keeps compounding the borrow index on every touch [5](#0-4) ) and the account can slide from merely underwater to genuinely insolvent before a price move or accrual closes the band. If accrual carries it past the dust gate, cleanup becomes possible via `clean_bad_debt`, but only after suppliers have absorbed extra accrued losses — i.e., the DoS window converts a cleanly liquidatable position into socialized bad debt, costing suppliers real funds [6](#0-5) .

### Likelihood Explanation
Medium-low, matching a Medium report. The attacker controls the debt size and collateral composition, so hitting the band is a sizing exercise, not luck; no privileged action is needed and the attack is repeatable across accounts. However, the band is narrow (bounded by the one-unit/margin gap), it self-heals when accrual or oracle movement shifts the quote across a boundary, and on assets where one whole unit is cheap the window is short-lived. The protocol documents the gap deliberately as an exception, suggesting awareness, but the freeze still exists on-chain and is attacker-reachable.

### Recommendation
Close the revert band instead of documenting it: when the curve quote for a whole-unit leg backs less than one unit, clamp the plan deterministically — e.g., always offer the smaller of "repay whole debt" and "repay exactly what backs one unit" — rather than reverting. Alternatively, permit partial whole-unit seizure (one unit seized against a floor-scaled repayment) so a valid plan exists for every debt size below the full-close boundary.

### Proof of Concept
1. Attacker calls `supply` on a spoke listing a sub-3-decimal asset (e.g., a 2-decimal token), depositing a small whole-unit amount as the account's only supply position.
2. Attacker calls `borrow` sized so that: (a) the bonus-curve quote seizes strictly less than one unit, and (b) the repayment that would back one unit plus the `1e-6` margin is **not** below the whole debt — placing the account inside the documented dead band.
3. A price move (or accrual) pushes `HF < 1`. The account is now liquidatable in principle but not in practice: every `liquidate` invocation computes a plan with no payable seizure and reverts, as described in INV-LIQ-02 [1](#0-0) .
4. The position remains frozen until accrual or another price move exits the band; meanwhile debt grows, potentially pushing the account into `clean_bad_debt` eligibility and forcing a supply-index write-down on suppliers [7](#0-6) .

/// Admission condition for bad-debt socialization.
#[derive(Clone, Copy, PartialEq)]
enum BadDebtGate {
    /// Permissionless: insolvent *and* collateral at or below the dust threshold.
    DustCapped,
    /// Owner-only: insolvent alone, with no cap on the collateral left behind.
    InsolventOnly,
}

/// Requires open debt and the selected insolvency gate, then cleans up the account.
fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    bad_debt::execute_bad_debt_cleanup(env, &mut cache, account_id, &account, &totals);
}

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}
