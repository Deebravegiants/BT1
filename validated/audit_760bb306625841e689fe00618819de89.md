## Analysis

The reported bug class — an unauthenticated function that lets anyone drain a contract's native/token balance meant to serve a protocol flow — maps directly onto `CallDispatcher.dispatch()` in this codebase. [1](#0-0) 

`CallDispatcher` is a shared, stateless utility contract wired into `IntentGatewayV2` (`_params.dispatcher`), `HyperFungibleTokenUpgradeable`, and `WrappedHyperFungibleTokenUpgradeable` to execute arbitrary attacker/order-supplied `Call[]` arrays during predispatch/postdispatch and cross-chain token-receive flows.### Title
Unauthenticated `CallDispatcher.dispatch()` lets anyone drain any native/token balance the shared dispatcher holds - (File: `evm/src/utils/CallDispatcher.sol`)

### Summary
`CallDispatcher.dispatch()` is `external` with no caller restriction — any address may call it directly with an arbitrary `Call[]` and instruct the dispatcher to send its own native-token or ERC20 balance anywhere. This is the same bug class as the external report's unprotected `sweepNative`: a "utility"/escrow-adjacent contract with an unguarded function that sweeps its balance to a caller-chosen address.

### Finding Description
`CallDispatcher` is a shared, stateless helper referenced by `IntentGatewayV2` (`_params.dispatcher`), `IntentsBase`/`ExtrinsicIntents`, `HyperFungibleTokenUpgradeable`, and `WrappedHyperFungibleTokenUpgradeable` to execute caller/order-supplied calldata during predispatch/postdispatch and on cross-chain receive: [1](#0-0) 

`dispatch(bytes memory encoded)` decodes an arbitrary `Call[]` and, for each entry, does `to.call{value: call.value}(call.data)` using whatever native token or ERC20 balance the dispatcher currently holds — with **no modifier restricting the caller to the app contracts that are supposed to own the funds momentarily sitting there**.

This contract is used in flows where it legitimately, if only transiently, holds funds:
- `IntentGatewayV2.placeOrder`/`fillOrder` push predispatch/postdispatch assets (native or ERC20) to the dispatcher, invoke `dispatch()` with order-supplied calldata, then sweep the resulting balance back — [2](#0-1)  and [3](#0-2) .
- `HyperFungibleTokenUpgradeable.onAccept` mints tokens directly to the dispatcher and then dispatches attacker/receiver-supplied calldata against that balance — [4](#0-3) , a pattern the docs explicitly describe ("mint to the CallDispatcher so the swap can spend the tokens") [5](#0-4) .

Because `dispatch()` has no access control, any balance that is not fully consumed/swept by the order's own calldata — leftover swap dust, tokens sent by a `Call` that targets an address outside `order.output.assets`/`order.inputs`, unconsumed minted tokens on a receive-with-calldata path, or any ETH otherwise sitting on the dispatcher between transactions — is freely stealable by any unrelated third party. They simply call `CallDispatcher.dispatch()` themselves with a `Call{to: attacker, value: address(this).balance, data: ""}` (or an ERC20 `transfer` call), exactly analogous to the reported `sweepNative()` being callable by anyone instead of `onlyOwner`.

### Impact Explanation
Any native ETH or ERC20 tokens that transiently reside in the shared `CallDispatcher` — across `IntentGatewayV2` predispatch/postdispatch, and `HyperFungibleToken`/`WrappedHyperFungibleToken` calldata-execution-on-receive paths — can be permanently stolen by an arbitrary unprivileged address, not just the intended order participant or app. This is concrete theft of protocol/user funds rather than a resource-only or no-impact bug, satisfying the High bar (analogous to draining fee/relayer funds in the original report).

### Likelihood Explanation
`dispatch()` is a plain external function reachable from any EOA/contract in a single transaction, with no gating whatsoever — the only precondition is that the dispatcher be holding a non-zero balance at some point, which routinely happens by design across three different app integrations (Intent Gateway swap flows, HFT mint-and-execute flows). No governance, consensus proof, or privileged role is required to trigger it, making likelihood high whenever any dust/unswept balance exists.

### Recommendation
Restrict `CallDispatcher.dispatch()` to be callable only by the specific app/contract instance that owns the funds for a given operation (e.g., pass and check an authorized caller, or make `CallDispatcher` non-shared/instance-scoped per app with an `onlyOwner`/`onlyApp` modifier), and/or ensure every code path that sends assets to the dispatcher fully sweeps 100% of any balance (including tokens outside the expected asset list) back atomically within the same transaction before it returns control, so no residual balance can ever be left for an external caller to claim.

### Proof of Concept
1. A user calls `IntentGatewayV2.placeOrder` with `predispatch.call` performing a swap that sends slightly more native ETH to the dispatcher than is later reclaimed by the sweep loop's `order.inputs` set (e.g., calldata sends ETH to a third address not accounted for in `order.inputs`), or `WrappedHyperFungibleTokenUpgradeable`/`HyperFungibleTokenUpgradeable.onAccept` mints tokens to the dispatcher via `message.data` calldata that doesn't consume the full minted amount.
2. Leftover ETH/ERC20 balance now sits on the shared `CallDispatcher` contract.
3. Any third party calls `CallDispatcher.dispatch(abi.encode([Call({to: attacker, value: address(callDispatcher).balance, data: ""})]))` directly (no relationship to the original order/message required) and receives the stray funds. [6](#0-5)

    /**
     *  @dev reverts if the target is not a contract or if any of the calls reverts.
     */
    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }

    function onAccept(IncomingPostRequest calldata incoming) external override onlyHost whenNotPaused {
        PostRequest calldata request = incoming.request;

        bytes memory expectedSource = _supportedChains[request.source];
        if (expectedSource.length == 0) revert UnsupportedChain();
        if (keccak256(request.from) != keccak256(expectedSource)) revert UnauthorizedSource();

        Message memory message = abi.decode(request.body, (Message));

        }
