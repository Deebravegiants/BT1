### Title
Immutable single Uniswap V2 router dependency in `EvmHost.dispatch` can permanently brick native-fee message dispatch on mainnet - (File: `evm/src/core/EvmHost.sol`)

### Summary
`EvmHost.dispatch(DispatchPost)` and `EvmHost.dispatch(DispatchGet)` are the only entry points an unprivileged caller uses to pay for cross-chain message dispatch with native tokens. When `msg.value > 0`, both functions hard-swap through a single router address stored in `_hostParams.uniswapV2`, with no fallback path and no alternate route. [1](#0-0) [2](#0-1) 

### Finding Description
`dispatch()` swaps `msg.value` for the exact fee-token amount via `IUniswapV2Router02(uniswapV2).swapETHForExactTokens(...)`, using a pool/router path (`WETH → feeToken`) resolved from that single `uniswapV2` address. `HyperApp.quote()`, used by every app to price a dispatch before calling it, also depends exclusively on this same router. [3](#0-2) 

Crucially, on mainnet `EvmHost` deployments the admin can only set `HostParams` once — `updateHostParams` reverts for the mainnet host, confirmed by the test suite: [4](#0-3) 

There is no `setUniswapV2Router`/comptroller-migration function, no secondary router fallback (unlike the Sablier fix which added Lido's native queue as a second exit path), and no way for the fee-token conversion pool/router to be swapped if it becomes illiquid, deprecated, or otherwise non-functional. This mirrors the reported bug class exactly: an immutable, single external liquidity dependency embedded as the *sole* mechanism for a fundamental protocol action (there: unstaking exit; here: native-to-fee-token conversion needed to pay for message dispatch), with no admin rescue and no alternate route.

### Impact Explanation
If the configured Uniswap V2 router/pool for `WETH→feeToken` becomes illiquid, deprecated, paused, or otherwise reverts (e.g., insufficient liquidity for `swapETHForExactTokens`, or the router contract itself is upgraded/retired upstream), then:
- Every unprivileged caller attempting to dispatch a POST/GET request while paying in native token on that `EvmHost` permanently loses the ability to do so — `dispatch()` and `HyperApp.quote()` both revert unconditionally.
- Since fee-token-based dispatch is still technically possible, this is not a full protocol halt, but for the (likely majority of) integrators and end users who rely on paying dispatch fees in native currency, this permanently forecloses that route with no governance-independent recovery — matching the "route unable to deliver messages" acceptance criterion for a subset of dispatchers.
- Because the mainnet host's `HostParams` (which contains `uniswapV2`) is a one-shot admin write, there is no built-in on-chain remediation once deployed; any fix would require deploying an entirely new `EvmHost` and migrating all app configuration, consensus state, and pending requests — a scenario the ISMP host is not designed for.

### Likelihood Explanation
Low-to-medium. Uniswap V2 is broadly liquid and unlikely to vanish, but many deployments configure a `UniV3UniswapV2Wrapper` or `UniV4UniswapV2Wrapper` (immutable, one-shot `init()`-configured shim contracts) rather than a canonical V2 pool, as seen in the deploy scripts. [5](#0-4) 
These wrapper contracts are themselves immutable after `init()` and depend on specific Uniswap V3/V4 router, quoter, and fee-tier/pool parameters that can become stale, under-liquid, or incompatible after a Uniswap protocol upgrade — a materially higher-likelihood failure mode than the canonical V2 router alone, especially over the multi-year operational horizon Hyperbridge is designed for as core cross-chain infrastructure.

### Recommendation
Add a governance/comptroller-gated `setUniswapV2Router(address newRouter)` function to `EvmHost` (or route this update through the existing `HostManager`/Hyperbridge governance channel used for other mainnet host parameter changes) so the fee-token swap dependency can be migrated without a full host redeployment, mirroring the Sablier fix pattern of making the previously-immutable exit dependency updatable by a privileged, non-adversarial party. Alternatively, support a secondary swap path (e.g., a different DEX or router) that `dispatch()` can fall back to if the primary router call reverts, so native-fee dispatch capability degrades gracefully rather than reverting entirely.

### Proof of Concept
1. Deploy a mainnet `EvmHost` with `HostParams.uniswapV2` pointing at a `UniV4UniswapV2Wrapper` instance configured against a specific Uniswap V4 pool (per `DeployUniV4Wrapper.s.sol`). [6](#0-5) 
2. Simulate the underlying V4 pool/universal router becoming non-functional (e.g., liquidity fully withdrawn, or the router contract paused/deprecated upstream) so `swapETHForExactTokens`/`execute` reverts.
3. Call `host.dispatch{value: x}(DispatchPost{...})` as any unprivileged user — the call reverts inside the router/wrapper call. [1](#0-0) 
4. Attempt `host.updateHostParams(...)` as the admin to point `uniswapV2` elsewhere — this reverts with `UnauthorizedAction` on a mainnet host. [4](#0-3) 
5. Result: native-token dispatch is permanently broken for this host with no on-chain remediation path, matching the reported bug's "immutable single external dependency with no fallback" root cause.

contract DeployScript is BaseScript {
    using strings for *;

    /// @notice Main deployment logic - called by BaseScript's run() functions
    /// @dev This function is called within a broadcast context
    function deploy() internal override {
        address universalRouter = config.get("UNIVERSAL_ROUTER").toAddress();
        address quoter = config.get("V4_QUOTER").toAddress();
        uint24 defaultFee = uint24(config.get("DEFAULT_FEE").toUint256());
        int24 defaultTickSpacing = int24(config.get("DEFAULT_TICK_SPACING").toInt256());
        address weth = config.get("WETH").toAddress();

        UniV4UniswapV2Wrapper wrapper = new UniV4UniswapV2Wrapper{salt: salt}(admin);

        wrapper.init(
            UniV4UniswapV2Wrapper.Params({
                universalRouter: universalRouter,
                quoter: quoter,
                WETH: weth,
                defaultFee: defaultFee,
                defaultTickSpacing: defaultTickSpacing
            })
        );
        vm.stopBroadcast();
        console.log("UniV4UniswapV2Wrapper deployed at:", address(wrapper));
        console.log("UniV4UniswapV2Wrapper initialized");
        // Persist the deployed wrapper address into the UNISWAP_V2 config field.
        config.set("UNISWAP_V2", address(wrapper));
    }
