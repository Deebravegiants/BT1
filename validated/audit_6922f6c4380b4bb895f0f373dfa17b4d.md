### Title
Bad-debt supply-index floor leaves phantom claims that drain recapitalized cash - (contracts/pool/src/interest.rs)

### Summary
When `apply_bad_debt_to_supply_index` writes down a market's supply index for a bad debt larger than the total supplied value, it clamps the index *up* to `SUPPLY_INDEX_FLOOR_RAW` (`RAY/1000`) instead of zeroing supplier shares. Every pre-existing supplier in that market is left with shares still valued at the floored index — a phantom claim exceeding real backing. The pool's own test suite demonstrates that once fresh cash enters the market, the wiped position withdraws real tokens and drains it to empty. The missing piece the tests label `without_supply_guard` is reachable in production via the permissionless `recapitalize` entrypoint, which credits pool `cash` without minting shares — exactly what the phantom claim then consumes.

### Finding Description
The bug class of the report (a routine over-reads state beyond what was validly backed, on attacker-influenced input) maps onto the pool's share/index accounting: [1](#0-0) 

`apply_bad_debt_to_supply_index` computes `remaining = total_supplied_value - min(bad_debt, total_supplied_value)`; when bad debt ≥ total supply, `reduction_factor` is 0, but the new index is clamped to `SUPPLY_INDEX_FLOOR_RAW`, not 0. Suppliers' `scaled_amount` shares are untouched, so `unscale_supply_floor(shares, floor_index)` still returns a positive token claim with zero backing — documented in `docs/reference/formulas.md`: "The non-zero floor can leave residual claims without backing."

The pool unit tests prove the drain at cache level: [2](#0-1) 

`resolve_withdrawal(i128::MAX, old_scaled)` + `require_reserves` + `debit_cash` pays `gross = c` — exactly the fresh deposit — leaving the honest supplier underfunded. In production the same flow is reachable:

1. Attacker supplies into a market, then a bad-debt event (permissionless `clean_bad_debt`, or seize during `liquidate` via `ops::seize::apply` → `apply_bad_debt_to_supply_index`) wipes the market to the index floor. The attacker's supply shares survive — `clean_bad_debt` deletes only the insolvent account, not other suppliers.
2. The backing gate blocks new `supply`, but `recapitalize` is permissionless and credits `cash` with no shares minted (`docs/reference/invariants.md` INV-LIQ-04: "Recapitalization fills that shortfall without restoring the lost index").
3. The attacker calls `recapitalize` (or waits for any third party to recapitalize/donate), then `withdraw` on their surviving shares. `require_reserves` only checks `cash`, so the phantom claim withdraws real tokens.

### Impact Explanation
Theft of funds / protocol insolvency (Medium). The phantom claimant extracts token value strictly greater than what remains backed; whoever replenishes the market — a recapitalizer or a new depositor admitted once the shortfall is nominally covered — loses funds to wiped positions that should hold zero claim. The loss equals `supplied_scaled × SUPPLY_INDEX_FLOOR_RAW` in token terms per wiped market.

### Likelihood Explanation
Requires a near-total bad-debt wipeout in one market (bad debt ≥ total supplied value at the borrow index). Utilization caps make this uncommon in a single liquidation, but `clean_bad_debt`/`force_socialize_bad_debt` and cascading insolvencies can reach it, and the attacker needs no privilege — only to hold supply shares in the market beforehand and call `recapitalize` + `withdraw` afterward. Moderate likelihood, bounded payoff → Medium.

### Recommendation
When `remaining == 0` (or the computed index would fall below the floor), zero the market's claim surface instead of clamping: burn/void residual `supplied` shares proportional bookkeeping, or store a wipeout flag that forces `unscale_supply*` to 0 and rejects `withdraw`/`recapitalize`-funded payouts until governance resets the market. At minimum, make `require_reserves`/`backing_shortfall` treat floored-index claims as unbacked so phantom shares can never pass the cash check.

### Proof of Concept
The repository's own test is the PoV; the production delta is adding the permissionless `recapitalize` step:

```text
1. supply(MALLORY, X, N)                     // shares S_m at index ~RAY
2. (bad debt ≥ total supplied value)         // clean_bad_debt / liquidate
   → apply_bad_debt_to_supply_index clamps supply_index to RAY/1000
   → MALLORY's S_m now claims phantom = floor(S_m * RAY/1000 / 10^(27-d)) > 0
3. recapitalize(payer=MALLORY, hub_asset=X, amount=C)   // permissionless, cash += C, C < phantom
4. withdraw(account=MALLORY, X, 0 /*all*/)   // resolve_withdrawal pays min(phantom, cash) = C+ε or drains other recap cash
```

Cache-level proof: `contracts/pool/tests/interest.rs:317-370` (`test_raw_cache_floor_residual_can_consume_fresh_cash_without_supply_guard`) asserts `gross == c` and `cash() == 0` — the wiped position drains the fresh deposit exactly.

```rust
pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}
```
