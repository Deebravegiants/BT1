### Title
Missing rate limiting/allowlisting on unprivileged Gateway legacy user messages enables DON-wide amplification DoS - (File: `core/services/gateway/handlers/capabilities/handler.go`)

### Summary
The Arbitrum One incident stemmed from the Sequencer getting stuck after receiving a burst of transactions with no effective throttling in place. The equivalent bug class here — an internet-facing ingress path that lacks per-request rate limiting/allowlisting before fanning work out to downstream infrastructure — is reachable in Chainlink's Gateway `capabilities` handler for legacy WebAPI trigger messages, which explicitly documents the missing control with a `TODO`.

### Finding Description
Any external, unprivileged client can `POST` a JSON-RPC "legacy" message (one carrying `Body.DonID`) to the Gateway's HTTP endpoint. `gateway.ProcessRequest` routes it straight to `handler.HandleLegacyUserMessage` with no per-caller rate limiting or allowlist check applied at this layer: [1](#0-0) 

Inside `HandleLegacyUserMessage`, the code validates payload shape/timestamp but explicitly skips authorization/throttling: [2](#0-1) 

Every accepted message is then stored in the handler's in-memory `savedCallbacks` map and fanned out to **every DON member**: [3](#0-2) 

The only bound on `savedCallbacks` size is a periodic prune (`defaultCallbackPruneIntervalSec = 30`, `defaultMaxSavedCallbacks = 20000`), and the constant's own comment acknowledges it "could briefly exceed under heavy load": [4](#0-3) [5](#0-4) 

By contrast, the newer HTTP trigger handler in `capabilities/v2` does apply an explicit per-workflow `userRateLimiter` before dispatch, showing that rate limiting on this exact class of ingress was subsequently recognized as necessary: [6](#0-5) 

The `nodeRateLimiter` field on the legacy `handler` only throttles DON-node-originated traffic (`handleWebAPIOutgoingMessage`), not user-originated traffic: [7](#0-6) 

### Impact Explanation
An unprivileged caller can send a high-frequency burst of distinct legacy trigger messages (unique `MessageID`s) to the Gateway. Each message: (1) grows the `savedCallbacks` map faster than the 30s prune interval can shrink it, and (2) triggers a fan-out `SendToNode` call to every member of the target DON. This is directly analogous to the Arbitrum Sequencer bug — an unthrottled ingress causing internal state/queues to balloon under a short burst, degrading or stalling processing for legitimate users. Because the fan-out touches all DON nodes, the blast radius extends beyond the Gateway process to the connected node fleet.

### Likelihood Explanation
The path is reachable by any unauthenticated caller who can reach the Gateway's HTTP listener and knows (or can construct) a valid legacy-format request with a valid `DonID`; no credentials, allowlist membership, or JWT is required to reach `HandleLegacyUserMessage`. The only mitigations are generic body-size limiting (`MaxRequestBytesLimiter`) and staleness/format checks, none of which bound request rate.

### Recommendation
Add per-caller (e.g., per source IP or per API key, mirroring `userRateLimiter` in `capabilities/v2/http_trigger_handler.go`) rate limiting and/or an allowlist check in `HandleLegacyUserMessage` before storing the callback and fanning out to DON members. Resolve the `TODO` at `core/services/gateway/handlers/capabilities/handler.go:384` and consider bounding `savedCallbacks` insertion synchronously (reject when at `MaxSavedCallbacks`) rather than relying solely on periodic pruning.

### Proof of Concept
1. Identify a Gateway HTTP endpoint and a valid `DonID` served by a `capabilities` legacy handler.
2. Script a loop sending distinct JSON-RPC legacy messages (`Body.Method = "web_api_trigger"`, unique `MessageID`, current timestamp, valid `DonID`) at high frequency, with no authentication headers.
3. Observe (via metrics/logs) that `savedCallbacks` map size grows and `SendToNode` fan-out calls scale linearly with attacker request rate, with no rejection until the periodic prune cycle runs — demonstrating the missing rate limit/allowlist gate flagged by the `TODO` at line 384.

func (h *handler) pruneCallbacks() {
	h.mu.Lock()
	defer h.mu.Unlock()

	// First, remove expired callbacks.
	maxAge := time.Duration(h.config.CallbackMaxAgeSec) * time.Second
	now := time.Now()
	var expired int
	for id, cb := range h.savedCallbacks {
		if now.Sub(cb.createdAt) > maxAge {
			delete(h.savedCallbacks, id)
			expired++
		}
	}

	// If there are still too many callbacks, sort them by creation time and remove the oldest ones.
	maxSize := h.config.MaxSavedCallbacks
	var evicted int
	if len(h.savedCallbacks) > maxSize {
		type entry struct {
			id        string
			createdAt time.Time
		}
		entries := make([]entry, 0, len(h.savedCallbacks))
		for id, cb := range h.savedCallbacks {
			entries = append(entries, entry{id, cb.createdAt})
		}
		sort.Slice(entries, func(i, j int) bool {
			return entries[i].createdAt.Before(entries[j].createdAt)
		})
		// Trim to maxSize/2 to avoid sorting the list too frequently.
		for _, e := range entries[:len(entries)-maxSize/2] {
			delete(h.savedCallbacks, e.id)
			evicted++
		}
	}

	if expired > 0 || evicted > 0 {
		h.lggr.Infow("Pruned savedCallbacks", "expired", expired, "evicted", evicted, "remaining", len(h.savedCallbacks))
	}
}

func (h *httpTriggerHandler) checkRateLimit(ctx context.Context, workflowID, requestID string, callback handlers.Callback) error {
	workflowRef, found := h.workflowMetadataHandler.GetWorkflowReference(workflowID)
	if !found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "workflow reference not found", callback)
		return errors.New("workflow reference not found")
	}

	orgID := h.resolveOrgID(ctx, workflowRef.workflowOwner)
	ctx = contexts.WithCRE(ctx, contexts.CRE{Owner: workflowRef.workflowOwner, Org: orgID, Workflow: workflowID})
	if err := h.userRateLimiter.AllowErr(ctx); err != nil {
		lggr := logger.With(h.lggr, platform.KeyWorkflowID, workflowID, platform.KeyWorkflowOwner, workflowRef.workflowOwner, "requestID", requestID, "err", err)
		if errLimited, ok := errors.AsType[limits.ErrorRateLimited](err); ok {
			switch errLimited.Scope {
			case settings.ScopeWorkflow:
				lggr.Errorf("failed to start execution: per workflow rate limit exceeded")
				h.metrics.IncrementWorkflowThrottled(ctx, h.lggr)
			default:
				lggr.Errorf("failed to start execution: unexpected rate limit for scope %s", errLimited.Scope)
			}
			h.handleUserError(ctx, requestID, jsonrpc.ErrLimitExceeded, "rate limit exceeded", callback)
			return err
		}
		return fmt.Errorf("failed to check rate limit: %w", err)
	}
	return nil
}
