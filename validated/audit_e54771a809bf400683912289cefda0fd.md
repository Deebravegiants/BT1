### Title
Dust top-up griefing blocks permissionless `clean_bad_debt` socialization of insolvent accounts - (File: contracts/controller/src/positions/liquidation/mod.rs)

### Summary
The SymmIO M-3 class — an unprivileged actor front-runs a victim's time-sensitive transaction with a near-costless state change that makes it revert — maps onto XOXNO Lending's permissionless bad-debt cleanup. `clean_bad_debt` only admits an insolvent account whose remaining collateral value is at or below the fixed `BAD_DEBT_USD_THRESHOLD` ($5 WAD), while `supply` lets any third party top up an existing supply position of any account. An attacker can front-run every `clean_bad_debt` call with a dust `supply` to the target account, pushing `total_collateral` just above the threshold so the cleanup reverts with `CannotCleanBadDebt`, indefinitely delaying socialization of bad debt.

### Finding Description
`clean_bad_debt` is permissionless (`process_clean_bad_debt` only requires `caller.require_auth()` and no open flash loan) and routes to `socialize_bad_debt` with `BadDebtGate::DustCapped`, which asserts `is_socializable_bad_debt(total_debt, total_collateral)` — i.e., `total_debt > total_collateral AND total_collateral <= BAD_DEBT_USD_THRESHOLD` — else it reverts `CollateralError::CannotCleanBadDebt` [1](#0-0) . Independently, the controller README and INV-AUTH-03 document that a third-party `supply` may top up hub assets an account already holds a supply position in, with no owner or delegate check on that leg [2](#0-1) . The gate is value-based and evaluated at execution time, so a single inbound supply that moves the account's unweighted collateral above the threshold atomically disqualifies it — exactly like the SymmIO nonce bump invalidating a pre-built transaction. The Certora spec explicitly acknowledges this straddle: "An attacker who raises `total_collateral` strictly above `BAD_DEBT_USD_THRESHOLD` … blocks the permissionless dust-gated socialization path while staying insolvent" [3](#0-2) . The dust threshold is fixed at $5 WAD and not configurable per-market [4](#0-3) . The block can be repeated: each time a liquidation shaves collateral back under $5, the attacker tops up again before the cleanup lands.

### Impact Explanation
`clean_bad_debt` is the only *permissionless* path that writes down a market's supply index, burns residual debt shares, deletes the insolvent account, and burns its NFT [5](#0-4) . While it is blocked, the bad debt stays on the books: suppliers' supply index is never written down but also cannot recover, utilization/borrow-cap space stays consumed by zombie debt, and interest continues accruing on debt that will never be repaid. The impact is temporary freezing of a protocol-maintenance function and delayed recognition of insolvency. Mitigating factors: each block requires the attacker to post real collateral above the $5 threshold that becomes protocol revenue on eventual cleanup, and the owner-gated `force_socialize_bad_debt` (`BadDebtGate::InsolventOnly`, no dust cap) can bypass the gate [6](#0-5) . These bound the severity to Medium rather than a permanent freeze.

### Likelihood Explanation
Reachable by any unprivileged address: `supply(caller, account_id, spoke_id, assets)` with a dust amount in an asset the insolvent account already holds requires only the caller's own auth and the listing not being paused/frozen [7](#0-6) . The natural attacker is the insolvent account's owner keeping their account/NFT alive, or a griefer front-running keeper-submitted `clean_bad_debt` transactions. The recurring cost (≥ ~$5 of donated collateral per successful block) keeps likelihood moderate; it is most attractive when a borrower wants to avoid account deletion or when griefing a market with thin keeper activity.

### Recommendation
- Treat `clean_bad_debt`'s dust gate as measuring collateral that predates the socialization window: e.g., exclude (or cap) supply that arrived within the last N ledgers when evaluating `is_socializable_bad_debt`, or record a per-account "cleanup-eligible" flag once the gate first opens so later top-ups cannot reset it.
- Alternatively, allow `clean_bad_debt` to atomically seize-then-socialize (apply the would-be liquidation of the newly added collateral inside the cleanup call), so topping up only donates to suppliers instead of blocking.
- At minimum, emit an event when a third-party supply targets an insolvent account so keepers can escalate to `force_socialize_bad_debt` promptly.

### Proof of Concept
1. BOB opens an account, supplies $30 of collateral token `LIQC`, borrows $12 of `LIQD`; the oracle crashes `LIQC` to 15% so collateral ≈ $4.50 ≤ $5 and debt $12 — the dust gate is open (setup mirrors `flow_clean_bad_debt`) [8](#0-7) .
2. A keeper submits `clean_bad_debt(caller=KEEPER, account_id=bob_acct)`.
3. Attacker (any address, including BOB) front-runs with `supply(caller=ATTACKER, account_id=bob_acct, spoke_id, [(hub, LIQC, dust)])` sized so collateral lands above $5 WAD — allowed because BOB's account already holds a `LIQC` supply position and third-party top-up needs no owner auth [9](#0-8) .
4. The keeper's call recomputes totals, `is_socializable_bad_debt` returns false on `total_collateral > BAD_DEBT_USD_THRESHOLD`, and reverts `CannotCleanBadDebt` (#114) [10](#0-9) .
5. Repeat step 3 whenever liquidation or price drift returns collateral below $5; the account, its debt, and its NFT persist and the write-down is deferred until governance invokes `force_socialize_bad_debt`.

```rust
/// Authorizes permissionless dust-gated cleanup outside flash loans.
pub(crate) fn process_clean_bad_debt(env: &Env, caller: &Address, account_id: u64) {
    caller.require_auth();
    validation::require_not_flash_loaning(env);
    clean_bad_debt_standalone(env, account_id);
}

/// Admission condition for bad-debt socialization.
#[derive(Clone, Copy, PartialEq)]
enum BadDebtGate {
    /// Permissionless: insolvent *and* collateral at or below the dust threshold.
    DustCapped,
    /// Owner-only: insolvent alone, with no cap on the collateral left behind.
    InsolventOnly,
}

/// Requires open debt and the selected insolvency gate, then cleans up the account.
fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    bad_debt::execute_bad_debt_cleanup(env, &mut cache, account_id, &account, &totals);
}

/// Socializes insolvent debt when remaining collateral is at or below the dust cap.
pub(crate) fn clean_bad_debt_standalone(env: &Env, account_id: u64) {
    socialize_bad_debt(env, account_id, BadDebtGate::DustCapped);
}
```

```rust
/// Straddle, first half. An attacker who raises `total_collateral` strictly above
/// `BAD_DEBT_USD_THRESHOLD` (`BAD_DEBT_USD_THRESHOLD + 1` is the cheapest such state) blocks
/// the permissionless dust-gated socialization path while staying insolvent. The gate is
/// value-based, not count-based, so one unit of a second collateral cannot block it: the
/// attacker must post value above the threshold and keep it there.
#[rule]
fn bad_debt_straddle_blocks_dust_gate(e: Env, debt_wad: i128, collateral_wad: i128) {
    let _ = e;
    cvlr_assume!(collateral_wad >= BAD_DEBT_USD_THRESHOLD + 1);
    cvlr_assume!(collateral_wad <= 1_000_000 * WAD);
    cvlr_assume!(debt_wad > collateral_wad && debt_wad <= 2_000_000 * WAD);

    // Symbolic straddle: anywhere strictly above the cap, the dust gate is shut.
    cvlr_assert!(!is_socializable_bad_debt(
        Wad::from(debt_wad),
        Wad::from(collateral_wad)
    ));
```

```markdown
`clean_bad_debt` is permissionless. It succeeds only when debt exceeds
```

```markdown
### INV-LIQ-04 — Bad-debt socialization is explicit and total

Permissionless cleanup requires ceil risk debt greater than half-up unweighted
collateral and collateral at or below the fixed $5 dust threshold. Owner-only
forced cleanup omits the dust cap. Both require debt, readable account and NFT
state, valid required prices and no active flash guard. Listing flags and
global pause do not block standalone cleanup.

Cleanup reclassifies all remaining collateral shares as revenue and writes off
all remaining debt against each debt's market. It releases spoke usage and
atomically removes account entries and the NFT. It does not net same-market
supply against debt. Standalone cleanup emits `CleanBadDebtEvent` with
pre-cleanup USD totals, without a controller position-update batch.

Ordinary liquidation and cleanup apply no final account-health or full-backing
assertion. The index floor can leave a shortfall. Recapitalization fills that
shortfall without restoring the lost index or deleted account.
```
