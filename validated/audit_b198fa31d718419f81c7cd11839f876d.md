# No Vulnerability found for this question.

The behavior described is intentional, documented protocol design, not a bypass.

**Why there's no exploitable gap:**

1. **Memory normalization is documented and uniform for all contracts.** `docs/RuntimeSpec/Preparation.md` explicitly states: "All near contracts have the same amount of memory made available for execution... If the original memory instance definition specified limits different from those specified by the genesis configuration parameters, the limits are reset to the configured parameters." [1](#0-0)  This means `PrepareContext::memory_type()` always emits `initial_memory_pages`/`max_memory_pages` from `config.limit_config` regardless of what the original module declared, by design. [2](#0-1) 

2. **There is no separate "declared maximum" enforcement path that an attacker's contract or any cost estimator could rely on.** The prepare pass entirely strips the module-local/import memory type and substitutes the network-wide constant before validation, compilation, and instrumentation happen — this is confirmed by the existing test suite (e.g. `memory_imports`, `internal_memory_declaration`) which asserts that any declared memory limits are either rejected (if they exceed the configured max) or silently normalized. [3](#0-2) 

3. **`memory.grow` gas is charged dynamically per actual page grown at runtime**, not based on any originally-declared maximum. The finite-wasm instrumentation charges a linear fee per page for `memory.grow`/`table.grow`, as shown by `visit_memory_grow => Fee { linear: ..., constant: ... }` in the v3 gas cost visitor, and confirmed by runtime tests (`test_memory_grow_1_page_gas`, `test_memory_grow_10_pages_gas`) showing gas scales with the actual pages requested at call time. [4](#0-3) [5](#0-4) 

4. **WASM linear memory growth is unrelated to state/storage/witness accounting.** The `memory` referenced here is the contract's runtime scratch heap, not the trie state. Storage usage (`current_storage_usage`) and witness/proof size (`RecordedStorageCounter`) are tracked independently based on actual trie reads/writes, not on WASM memory page counts. [6](#0-5)  So there is no metering completeness invariant tied to a contract's self-declared memory maximum — the enforced maximum is a single global constant (`max_memory_pages`) applied identically to every contract, and gas is charged per page actually grown regardless of any pre-normalization declaration.

Since the "original declared maximum" has no protocol meaning after normalization (it's discarded entirely, per spec) and gas for growth is metered live per page, there is no scenario where an attacker gains free/underpriced execution, unaccounted storage growth, or a metering bypass. This is consistent, intended behavior with existing test coverage, not a vulnerability.

## Memory normalization

All near contracts have the same amount of memory made available for execution. The exact amount is
specified specified by the `initial_memory_pages` and `max_memory_pages` genesis configuration
parameters. In order to ensure a level playing field, any module-local memory definitions are
transparently replaced with an import of a standard memory instance from `env.memory`.

If the original memory instance definition specified limits different from those specified by the
genesis configuration parameters, the limits are reset to the configured parameters.

    #[test]
    fn memory_imports() {
        with_vm_variants(|kind| {
            let config = test_vm_config(Some(kind));
            // This test assumes that maximum page number is configured to a certain number.
            assert_eq!(config.limit_config.max_memory_pages, 2048);

            let r = parse_and_prepare_wat(
                &config,
                kind,
                r#"(module (import "env" "memory" (memory 1 1)))"#,
            );
            assert_matches!(r, Err(PrepareError::Memory));

            // No memory import
            let r = parse_and_prepare_wat(&config, kind, r#"(module)"#);
            assert_matches!(r, Ok(_));

            // initial exceed maximum
            let r = parse_and_prepare_wat(
                &config,
                kind,
                r#"(module (import "env" "memory" (memory 17 1)))"#,
            );
            assert_matches!(r, Err(PrepareError::Deserialization));

            // no maximum
            let r = parse_and_prepare_wat(
                &config,
                kind,
                r#"(module (import "env" "memory" (memory 1)))"#,
            );
            assert_matches!(r, Err(PrepareError::Memory));

            // requested maximum exceed configured maximum
            let r = parse_and_prepare_wat(
                &config,
                kind,
                r#"(module (import "env" "memory" (memory 1 33)))"#,
            );
            assert_matches!(r, Err(PrepareError::Memory));
        })
    }
