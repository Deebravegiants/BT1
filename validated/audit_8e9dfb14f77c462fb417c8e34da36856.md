Audit Report

## Title
Unprivileged (view-role) authenticated users can enumerate External Initiator `AccessKey` and `OutgoingToken` via `GET /v2/external_initiators` - (File: core/web/external_initiators_controller.go)

## Summary
`ExternalInitiatorsController.Index`, registered at `GET /v2/external_initiators`, is reachable by any authenticated user regardless of role (including the lowest `view` role), because unlike the `Create`/`Destroy` routes on the same resource it is not wrapped in `auth.RequiresEditRole` or `auth.RequiresAdminRole`. The handler serializes every external initiator's `AccessKey` and `OutgoingToken` in the JSON response, exposing these values to low-privilege users who should not otherwise have access to them.

## Finding Description
`ExternalInitiatorsController.Index` queries all external initiators and maps each into `presenters.ExternalInitiatorResource`, which includes the `AccessKey` and `OutgoingToken` fields. The route is registered as `authv2.GET("/external_initiators", paginatedRequest(eia.Index))` — inside the authenticated group but without any role-restriction middleware — while the sibling `POST`/`DELETE` routes on the same resource are explicitly wrapped with `auth.RequiresEditRole`. The test suite's own RBAC route table confirms this asymmetry by marking `GET /v2/external_initiators` as `viewOnlyAllowed: true`. This is a missing-authorization gap (CWE-862): the write operations enforce a minimum privilege level, but the read operation that exposes credential-adjacent fields does not.

## Impact Explanation
Exposure is limited to `AccessKey` (an identifier, not the actual secret) and `OutgoingToken`; the real authentication secret (`Secret`/`HashedSecret`/`Salt`) and `OutgoingSecret` are not part of this response. Nonetheless, `OutgoingToken` and `AccessKey` are credential-adjacent values intended to be restricted to privileged operators, and their disclosure to `view`-role users constitutes an in-scope confidentiality/token-exfiltration issue, consistent with a low-severity missing-authorization finding.

## Likelihood Explanation
Any deployment provisioning `view`-role API users, session users, or OIDC/LDAP read-only role mappings can trigger this with a single authenticated `GET` request — no elevated privileges, timing, or additional preconditions are needed, making exploitation straightforward and repeatable for any such low-privilege principal.

## Recommendation
Wrap `GET /v2/external_initiators` (and the `Show`/`:id` variant if one exists) with `auth.RequiresEditRole` or `auth.RequiresAdminRole` to match the protection level of `Create`/`Destroy`, or alternatively strip `AccessKey`/`OutgoingToken` from `ExternalInitiatorResource` for non-privileged callers.

## Proof of Concept
1. Provision a Chainlink node user with role `view` (e.g., via `POST /v2/users` as admin, or an OIDC/LDAP read-only claim mapping).
2. Authenticate as that user via session cookie or API token.
3. Send `GET /v2/external_initiators` using that low-privilege credential.
4. Observe the JSON response contains `accessKey` and `outgoingToken` for every configured external initiator — confirmable via a Go handler test asserting a `view`-role session against `router.go`'s route table returns HTTP 200 with these fields populated, mirroring the existing `viewOnlyAllowed: true` assertion in `core/web/auth/auth_test.go`.

func AuthenticateExternalInitiator(c *gin.Context, store Authenticator) error {
	ctx := c.Request.Context()
	eia := &auth.Token{
		AccessKey: c.GetHeader(static.ExternalInitiatorAccessKeyHeader),
		Secret:    c.GetHeader(static.ExternalInitiatorSecretHeader),
	}

	ei, err := store.FindExternalInitiator(ctx, eia)
	if err != nil {
		if errors.Is(err, sql.ErrNoRows) {
			return auth.ErrorAuthFailed
		}

		return errors.Wrap(err, "finding external initiator")
	}

	ok, err := bridges.AuthenticateExternalInitiator(eia, ei)
	if err != nil {
		return err
	}
	if !ok {
		return auth.ErrorAuthFailed
	}

	// External initiator endpoints (wrapped with AuthenticateExternalInitiator) inherently assume the role
	// of 'run' (required to trigger job runs)
	c.Set(SessionExternalInitiatorKey, ei)
	c.Set(SessionUserKey, &clsessions.User{Role: clsessions.UserRoleRun})

	return nil
