### Title
Stale-vs-fresh `total_coins` mismatch in `staking_contract::update_distribution_pool` causes division-by-zero abort, permanently locking staker/operator commission distributions - (File: `aptos-move/framework/aptos-framework/sources/staking_contract.move`)

### Summary
`pool_u64::amount_to_shares_with_total_coins` decides whether to take its "empty pool" fast path using the pool's **stored** `self.total_coins`, but performs the actual division using an **externally supplied** `total_coins` parameter as the divisor. `staking_contract::update_distribution_pool` calls this function with `updated_total_coins` computed from live stake-pool state, which can be `0` while the distribution pool's stored `total_coins` is still non-zero and shareholders still hold shares. This causes `math64::mul_div` to abort on division-by-zero, permanently reverting `distribute`, `unlock_stake`, `request_commission`, `switch_operator`, and `update_commision` for that staker/operator pair.

### Finding Description
In `pool_u64.move`, the branch selection and the division use two different sources of truth: [2](#0-1) 

The guard `self.total_coins == 0 || self.total_shares == 0` reads the pool's *stored* state, but the `else` branch divides by the caller-supplied `total_coins` parameter, not `self.total_coins`.

`staking_contract::update_distribution_pool` calls this with a freshly computed `updated_total_coins` argument that is independent of the pool's stored `total_coins`: [3](#0-2) 

If, at the time this runs, `distribution_pool.total_coins()` (stored, possibly stale/non-zero) is non-zero and shareholders exist, but `updated_total_coins` (the fresh argument, derived from `stake::get_stake(...).pending_inactive`) is `0`, then:
- `pool_u64::shares_to_amount_with_total_coins(distribution_pool, shares, updated_total_coins=0)` safely returns `0` because `total_coins` is used as the multiplicand, not divisor, in that function.
- `pool_u64::amount_to_shares_with_total_coins(distribution_pool, unpaid_commission, updated_total_coins=0)` takes the `else` branch (since stored `self.total_coins`/`self.total_shares` are non-zero) and calls `multiply_then_divide(coins_amount, self.total_shares, total_coins=0)`, i.e. `math64::mul_div(x, y, 0)`, which asserts `c != 0` and aborts.

This mirrors exactly the reported bug pattern: a stale/cached "total" value is non-zero while the value actually used as divisor is zero, causing an unconditional abort in a core value-distribution path. `add_distribution` is only reached after `distribute_internal` normally clears the distribution pool to zero shareholders and zero `total_coins` whenever there was anything withdrawable to distribute: [4](#0-3) 

But note the early return at line ~875-878: if `total_potential_withdrawable == 0` (i.e., `inactive + pending_inactive == 0` at that moment), `distribute_internal` returns *without* touching `distribution_pool` at all, leaving any previously-recorded (but not-yet-withdrawable) shareholder distributions and stored `total_coins` intact. This is the mechanism by which stored `distribution_pool.total_coins()` can remain non-zero with live shareholders while a subsequently-computed `updated_total_coins` argument can independently be `0`.

The Move Prover annotations corroborate that this exact function resists verification for this reason: [5](#0-4) 

### Impact Explanation
If triggered, every code path that eventually calls `add_distribution`/`update_distribution_pool` for the affected staker/operator's `StakingContract` (i.e. `unlock_stake`, `request_commission`, `switch_operator`, `switch_operator_with_same_commission`, `update_commision`) will abort. Since `staking_contract.distribution_pool` is a resource-account-owned custody structure tracking commission/staker entitlements to real APT held in the stake pool, a permanent abort here permanently freezes the ability to distribute, unlock, or reassign operator/commission rights for that pool — a non-recoverable loss of the standard withdrawal/commission path for held APT, matching the "permanent lock / non-recoverable loss of resource-account-held value" custody-impact category.

### Likelihood Explanation
This requires a specific but plausible on-chain sequence: (1) an existing commission/staker distribution recorded in `distribution_pool` (non-zero shares, non-zero stored `total_coins`) that has not yet been redeemed because `distribute_internal`'s early-return path was taken (no `inactive`/`pending_inactive` funds withdrawable at that moment), combined with (2) a subsequent `add_distribution` call whose freshly-read `stake::get_stake(...).pending_inactive` evaluates to exactly `0`. Because this depends on precise timing of unlock/lockup/epoch transitions relative to `distribute`/`unlock_stake`/`request_commission` calls, I could not fully construct or verify an end-to-end concrete trigger sequence within the available exploration; the exact conditions under which `pending_inactive` reads `0` while `distribution_pool` still holds non-redeemed shares from a prior cycle would need dedicated Move-test simulation (e.g., in `staking_contract.move`'s test module) to confirm reachability, given the module's already-known verification gaps for this exact function.

### Recommendation
In `pool_u64::amount_to_shares_with_total_coins` (and the symmetric `shares_to_amount_with_total_coins`), make the branch-selection condition consistent with the value actually used for computation — i.e., check `total_coins == 0` (the parameter) rather than `self.total_coins == 0` when `total_coins` is what's used as divisor/multiplicand. Alternatively, in `staking_contract::update_distribution_pool`, explicitly guard the `else`/loop body with `if (updated_total_coins == 0) { /* handle degenerate case, e.g. treat all existing shares as zero-valued or skip commission charge */ }` before calling into `pool_u64` with a possibly-zero externally-derived total.

### Proof of Concept
Not independently constructed/verified end-to-end due to the complexity of reproducing the exact stake-pool epoch/lockup timing needed to make `stake::get_stake(pool_address).pending_inactive == 0` while `distribution_pool` still holds unredeemed shares from a prior `add_distribution` call. A Devin session with Move test-harness execution (using the existing `staking_contract.move` test helpers such as `setup_staking_contract`, `stake::fast_forward_to_unlock`, and manipulating epoch/lockup transitions) would be needed to confirm whether this exact sequence is reachable and to produce a concrete `#[expected_failure]` Move test demonstrating the `mul_div` abort in `update_distribution_pool`.

    /// Return the number of new shares `coins_amount` can buy in `self` with a custom total coins number.
    /// `amount` needs to big enough to avoid rounding number.
    public fun amount_to_shares_with_total_coins(self: &Pool, coins_amount: u64, total_coins: u64): u64 {
        // No shares yet so amount is worth the same number of shares.
        if (self.total_coins == 0 || self.total_shares == 0) {
            // Multiply by scaling factor to minimize rounding errors during internal calculations for buy ins/redeems.
            // This can overflow but scaling factor is expected to be chosen carefully so this would not overflow.
            coins_amount * self.scaling_factor
        } else {
            // Shares price = total_coins / total existing shares.
            // New number of shares = new_amount / shares_price = new_amount * existing_shares / total_amount.
            // We rearrange the calc and do multiplication first to avoid rounding errors.
            self.multiply_then_divide(coins_amount, self.total_shares, total_coins)
        }
    }

        operator: address,

        };
        let (_, inactive, _, pending_inactive) = stake::get_stake(pool_address);
        let total_potential_withdrawable = inactive + pending_inactive;
        let coins =
            stake::withdraw_with_cap(

            );
        let distribution_amount = coin::value(&coins);
        if (distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        let distribution_pool = &mut staking_contract.distribution_pool;
        update_distribution_pool(
            distribution_pool,
            distribution_amount,
            operator,
            staking_contract.commission_percentage
        );

        // Buy all recipients out of the distribution pool.
        while (distribution_pool.shareholders_count() > 0) {
            let recipients = distribution_pool.shareholders();
            let recipient = recipients[0];
            let current_shares = distribution_pool.shares(recipient);
            let amount_to_distribute =
                distribution_pool.redeem_shares(recipient, current_shares);
            // If the recipient is the operator, send the commission to the beneficiary instead.
            if (recipient == operator) {
                recipient = beneficiary_for_operator(operator);
            };
            aptos_account::deposit_coins(
                recipient, coin::extract(&mut coins, amount_to_distribute)
            );

            emit(
                Distribute {
                    operator,
                    pool_address,
                    recipient,
                    amount: amount_to_distribute
                }
            );
        };

        // In case there's any dust left, send them all to the staker.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(staker, coins);
            distribution_pool.update_total_coins(0);
        } else {
            coin::destroy_zero(coins);
        }

    fun update_distribution_pool(
        distribution_pool: &mut Pool,
        updated_total_coins: u64,
        operator: address,
        commission_percentage: u64
    ) {
        // Short-circuit and do nothing if the pool's total value has not changed.
        if (distribution_pool.total_coins() == updated_total_coins) { return };

        // Charge all stakeholders (except for the operator themselves) commission on any rewards earnt relatively to the
        // previous value of the distribution pool.
        let shareholders = &distribution_pool.shareholders();
        shareholders.for_each_ref(
            |shareholder| {
                let shareholder: address = *shareholder;
                if (shareholder != operator) {
                    let shares = pool_u64::shares(distribution_pool, shareholder);
                    let previous_worth = pool_u64::balance(distribution_pool, shareholder);
                    let current_worth =
                        pool_u64::shares_to_amount_with_total_coins(
                            distribution_pool, shares, updated_total_coins
                        );
                    let unpaid_commission =
                        (current_worth - previous_worth) * commission_percentage / 100;
                    // Transfer shares from current shareholder to the operator as payment.
                    // The value of the shares should use the updated pool's total value.
                    let shares_to_transfer =
                        pool_u64::amount_to_shares_with_total_coins(
                            distribution_pool, unpaid_commission, updated_total_coins
                        );
                    pool_u64::transfer_shares(
                        distribution_pool, shareholder, operator, shares_to_transfer
                    );
                };
            }
        );

        distribution_pool.update_total_coins(updated_total_coins);
    }
