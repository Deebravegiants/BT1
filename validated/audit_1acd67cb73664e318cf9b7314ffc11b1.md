### Title
No password strength enforcement when creating/importing a wallet or changing passphrase - (File: `features/wallet/module/wallet.js`)

### Summary
The `@exodus/wallet` module's `create`, `import`, and `changePassphrase` methods accept any arbitrary string as the encryption passphrase for the seed with zero strength validation, allowing users to set trivially weak passwords such as `"123"`, `"abc"`, or `"0000"` to protect their mnemonic/seed.

### Finding Description
`wallet.create()` accepts a `passphrase` parameter and passes it directly to `#setSeed`, which forwards it to `seedStorage.set(..., { passphrase })` for encryption, with no length, complexity, or strength check performed anywhere in the flow [1](#0-0) . The same is true for `import()`, which only validates the mnemonic (via `assertMnemonic`) but not the passphrase, before delegating to `create()` [2](#0-1) , and for `changePassphrase()` which swaps the encryption passphrase without any strength check [3](#0-2) .

Notably, the codebase already contains a dedicated `@exodus/passphrase-strength` library built on `zxcvbn` that exposes `getPassphraseStrength(passphrase, { minimumValidScore, minimumPassphraseLength })` to score passphrase strength [4](#0-3) , but a repo-wide search shows no other package declares a dependency on `@exodus/passphrase-strength` and it is not referenced or invoked anywhere in `features/wallet` or elsewhere — the library is unused/orphaned. Tests explicitly confirm the wallet accepts extremely weak passphrases like `'abc'` and `'123'` for `create`/`changePassphrase` without any rejection [5](#0-4) .

This mirrors the reported bug class ("no password policy enforced when setting up a password") but in a materially more severe production context: here the "password" is the actual encryption passphrase protecting the wallet's mnemonic seed via `seedStorage.set(value, { passphrase })`, as documented in the feature's own README [6](#0-5) .

### Impact Explanation
The passphrase directly gates encryption of the wallet seed/mnemonic in `seedStorage`. A weak, guessable passphrase (e.g., `"123456"`, `"abcdef"`) drastically lowers the brute-force search space needed to decrypt the seed if the encrypted blob is exfiltrated (e.g., via device compromise, backup extraction, or storage leak), leading to direct compromise of all funds/assets controlled by the wallet — a more severe outcome than the original PIN/login-password report since this passphrase encrypts the cryptographic secret itself, not just a device unlock gate.

### Likelihood Explanation
Likelihood is high: nothing in the UI-agnostic module layer blocks weak input, and any consuming app (mobile/extension/etc.) built on `@exodus/wallet` must independently implement its own strength enforcement or users can trivially set weak passphrases, exactly as shown by the test suite using values like `'123'` and `'abc'` without rejection [7](#0-6) .

### Recommendation
Integrate the existing (but currently unused) `@exodus/passphrase-strength` library into `wallet.create`, `wallet.import`, and `wallet.changePassphrase` to enforce a minimum `zxcvbn` score and minimum length before accepting a user-supplied passphrase, rejecting weak values at the module boundary rather than relying solely on downstream UI implementations.

### Proof of Concept
1. Call `exodus.wallet.create({ passphrase: '123' })` — succeeds with no error [7](#0-6) .
2. Call `exodus.wallet.changePassphrase({ currentPassphrase: 'abc', newPassphrase: '123' })` — succeeds and the wallet is now encrypted with `'123'` [8](#0-7) .
3. Confirm `getPassphraseStrength('123')` from `@exodus/passphrase-strength` would flag this as weak (`score` near 0, below `minimumValidScore`), yet this check is never invoked by `features/wallet` [9](#0-8) .

import zxcvbn from 'zxcvbn'

export const getPassphraseStrength = (
  passphrase,
  { minimumValidScore = 2, minimumPassphraseLength = 8 } = {}
) => {
  const { score } = zxcvbn(passphrase)
  return {
    score,
    strong: score >= minimumValidScore && passphrase.length >= minimumPassphraseLength,
  }
}
