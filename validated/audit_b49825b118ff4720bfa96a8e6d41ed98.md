### Title
`setDelegate` recovery-delegate race allows a compromised delegate to nilify/skip/burn inbound LayerZero payloads before revocation lands - (File: `sdk/packages/lz-endpoint/contracts/HyperbridgeLzEndpoint.sol`)

### Summary
`HyperbridgeLzEndpoint.setDelegate` is the direct analog of `setSignatureValidatorApproval`: an OApp grants a delegate address standing authority (`_delegates[msg.sender] = _delegate`) to perform privileged recovery actions on its behalf, revocable only by calling `setDelegate` again. Between the moment an OApp detects delegate compromise and the revocation transaction being mined, the compromised delegate can still front-run and invoke `nilify`/`skip`/`burn` on legitimate stuck inbound messages.

### Finding Description
`setDelegate` (`HyperbridgeLzEndpoint.sol:500-503`) stores a single persistent delegate per OApp with no timelock, cooldown, or nonce-based invalidation:
```solidity
function setDelegate(address _delegate) external override {
    _delegates[msg.sender] = _delegate;
    emit RecoveryDelegateSet(msg.sender, _delegate);
}
```
That delegate, gated only by `onlyOAppOrDelegate` (`HyperbridgeLzEndpoint.sol:143-146`), can call:
- `skip` (`:513-524`) — force-advances `_inboundNonce`, discarding whatever payload sits at that slot.
- `nilify` (`:527-539`) — marks a stored inbound payload as permanently un-executable (`NIL_PAYLOAD_HASH`).
- `burn` (`:542-553`) — permanently deletes a nilified payload's record.
- `clear` (`:471-483`) — discards a stored failed payload without ever executing it.

These are exactly the kind of "validate/act on my behalf" delegated powers the external report describes for `setSignatureValidatorApproval`: a persistent boolean/address mapping, revocable, with an unavoidable window between submitting the revocation and its inclusion in a block. If an OApp owner's delegate key is compromised (leaked signer, compromised ops account, etc.) and the owner submits a transaction to `setDelegate(newDelegate)` or `setDelegate(address(0))` to cut off the old delegate, the attacker holding the old delegate key can observe the pending revocation in the mempool and front-run it with `skip`/`nilify`/`burn`/`clear` calls, permanently discarding or skipping legitimate stuck inbound cross-chain messages before the revocation lands.

### Impact Explanation
Unlike a plain access-control revocation race, the specific actions gated by `_delegates` are irreversible destructive operations on retained ISMP-delivered payloads: `nilify` + `burn` permanently erase a message's payload hash, and `skip` force-advances the inbound nonce and deletes any stored payload at that slot. Any of these on a legitimate reverted `lzReceive` payload permanently prevents that cross-chain message from ever being retried through `retryPayload`, which is the endpoint's whole point of retaining `_inboundPayloadHashes` — "a single reverting message can never permanently brick a channel" (comment at `:376-378`). A malicious/compromised delegate abusing this window can therefore cause a **permanent loss of a cross-chain message intended for the OApp** (funds transfer, state update, etc., depending on what the OApp's `lzReceive` was meant to do), which meets the "route unable to deliver messages" / permanent freezing criterion.

### Likelihood Explanation
Requires the delegate key to already be compromised (external precondition, matching the source report's own "Low" difficulty framing) and requires the attacker to observe the pending revocation transaction and win a front-run — feasible on any public mempool. No governance or protocol-level privilege is needed beyond already holding the compromised delegate key; the destructive calls (`skip`, `nilify`, `burn`, `clear`) are permissionless from the delegate's perspective once granted.

### Recommendation
**Short term:** Document that `setDelegate` revocation is not atomic with respect to pending transactions, and that OApps must treat delegate compromise as urgent (e.g., pause the OApp/endpoint before or simultaneously with revocation). Consider emitting/monitoring `RecoveryDelegateSet` off-chain to detect and react to unexpected delegate changes.

**Long term:** Add a per-OApp pause or a delegate "freeze" flag that can be set atomically with revocation and takes effect before the delegate-mapping update is even read (e.g., a monotonically increasing delegate-generation counter checked by `onlyOAppOrDelegate`, or gating destructive recovery calls behind an additional short timelock), so a compromised delegate cannot race a revocation to execute `nilify`/`skip`/`burn`/`clear`.

### Proof of Concept
1. OApp owner calls `setDelegate(delegateA)`, granting `delegateA` recovery rights (`HyperbridgeLzEndpoint.sol:500`).
2. `delegateA`'s key is leaked. The OApp owner submits `setDelegate(address(0))` (or a new delegate) to revoke it.
3. Before that transaction is mined, the attacker (holding `delegateA`) submits `nilify(oapp, srcEid, sender, nonce, payloadHash)` (or `skip`/`burn`/`clear`) targeting a legitimately stuck inbound message stored in `_inboundPayloadHashes` (`:527-539`), with a higher gas price to front-run the revocation.
4. `onlyOAppOrDelegate` still resolves `_delegates[oapp] == delegateA` at execution time, so the call succeeds, permanently destroying the payload record via `NIL_PAYLOAD_HASH` before `burn`, or deleting it outright via `skip`/`clear`.
5. The owner's revocation transaction then lands, but the damage (permanently lost inbound message) is already done — mirroring the exploit scenario in the external `setSignatureValidatorApproval` report. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3)

    /// @notice Advances the inbound nonce past `_nonce` (which must be the next expected nonce),
    /// discarding any stored payload at that slot. Callable by the OApp or its delegate.
    function skip(
        address _oapp,
        uint32 _srcEid,
        bytes32 _sender,
        uint64 _nonce
    ) external override onlyOAppOrDelegate(_oapp) {
        uint64 expected = _inboundNonce[_oapp][_srcEid][_sender] + 1;
        if (_nonce != expected) revert InvalidNonce(expected, _nonce);
        _inboundNonce[_oapp][_srcEid][_sender] = _nonce;
        delete _inboundPayloadHashes[_oapp][_srcEid][_sender][_nonce];
        emit InboundNonceSkippedBy(_oapp, _srcEid, _sender, _nonce);
    }

    /// @notice Marks a stored payload as nil (deliberately un-executable) prior to burning it.
    function nilify(
        address _oapp,
        uint32 _srcEid,
        bytes32 _sender,
        uint64 _nonce,
        bytes32 _payloadHash
    ) external override onlyOAppOrDelegate(_oapp) {
        bytes32 stored = _inboundPayloadHashes[_oapp][_srcEid][_sender][_nonce];
        if (stored == bytes32(0) || stored == NIL_PAYLOAD_HASH) revert PayloadNotFound();
        if (stored != _payloadHash) revert InvalidPayloadHash();
        _inboundPayloadHashes[_oapp][_srcEid][_sender][_nonce] = NIL_PAYLOAD_HASH;
        emit InboundPayloadNilified(_oapp, _srcEid, _sender, _nonce, _payloadHash);
    }

    /// @notice Permanently removes a previously nilified payload.
    function burn(
        address _oapp,
        uint32 _srcEid,
        bytes32 _sender,
        uint64 _nonce,
        bytes32 _payloadHash
    ) external override onlyOAppOrDelegate(_oapp) {
        if (_payloadHash != NIL_PAYLOAD_HASH) revert InvalidPayloadHash();
        if (_inboundPayloadHashes[_oapp][_srcEid][_sender][_nonce] != NIL_PAYLOAD_HASH) revert PayloadNotNilified();
        delete _inboundPayloadHashes[_oapp][_srcEid][_sender][_nonce];
        emit InboundPayloadBurned(_oapp, _srcEid, _sender, _nonce);
    }
