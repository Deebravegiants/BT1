### Title
Unbounded accrued debt value overflows before the RAY index cap and permanently freezes the market - ([File: common/src/rates/index.rs](common/src/rates/index.rs))

### Summary
The pool caps `borrow_index` at `MAX_BORROW_INDEX_RAY`, but it does not bound the underlying debt value represented by `borrowed * borrow_index`; once that product exceeds `i128::MAX`, every accrual panics with `MathOverflow`. [1](#0-0) [2](#0-1)  Because every market mutation accrues before operating, the overflow permanently blocks repayments, withdrawals, liquidations, further `update_indexes` calls, and even rate-parameter updates for that market. [3](#0-2) [4](#0-3) 

### Finding Description
`calculate_supplier_rewards` derives `old_total_debt` and `new_total_debt` through `borrowed.mul(...)`, where `borrowed` is a RAY-scaled aggregate position and `Ray::mul` returns an `i128`. [5](#0-4) [6](#0-5)  The fixed-point multiplication panics when the quotient does not fit `i128`, so aggregate debt can exceed the representable value range even while `borrow_index` remains below `MAX_BORROW_INDEX_RAY`. [7](#0-6) [1](#0-0) 

The overflow condition is approximately:

```text
borrowed * new_borrow_index / RAY > i128::MAX
```

A single unprivileged address can create the state through `supply` and `borrow`, provided the market’s configured caps and token liquidity admit a sufficiently large position. [8](#0-7) [9](#0-8)  After ledger time advances far enough that interest pushes the debt value over the `i128` boundary, calling `update_indexes(caller, vec![hub_asset])` commits the panic into every subsequent accrual attempt. [10](#0-9) [11](#0-10) 

### Impact Explanation
This permanently freezes user funds in the affected market: suppliers cannot withdraw and borrowers cannot repay, while liquidations and other pool mutations cannot bypass the mandatory accrual step. [3](#0-2) [12](#0-11)  The existing regression test demonstrates that the panic occurs before `MAX_BORROW_INDEX_RAY` is reached and that both `withdraw` and `repay` subsequently fail with `MATH_OVERFLOW`. [13](#0-12) 

### Likelihood Explanation
Likelihood is medium: the attacker cannot forge a timestamp and must fund or borrow enough token units for the accrued debt value to exceed `i128::MAX`, but the trigger uses only ordinary `supply`, `borrow`, and permissionless `update_indexes` calls. [14](#0-13) [10](#0-9)  The exploit is therefore configuration-dependent, but it is not limited to privileged actions, malformed external data, or third-party oracle misbehavior. [9](#0-8) 

### Recommendation
Enforce a market-level invariant that keeps `supplied * MAX_SUPPLY_INDEX_RAY` and `borrowed * MAX_BORROW_INDEX_RAY` representable in `i128`, rather than relying on token-unit caps alone. [1](#0-0) [2](#0-1)  In addition, make aggregate-value accrual use a checked/wide representation and fail safely before committing an unrecoverable market state; governance-listing validation should derive hard supply and borrow caps from `asset_decimals`, `MAX_BORROW_INDEX_RAY`, `MAX_SUPPLY_INDEX_RAY`, and the `i128` ceiling. [7](#0-6) 

### Proof of Concept
The repository already contains a harness reproduction for this exact state transition: create an 18-decimal market, admit a billion-token position, borrow 98% of it, advance ledger time until `update_indexes` returns `MathOverflow`, and then confirm that `withdraw` and `repay` also fail. [15](#0-14) 

```rust
// tests/test-harness/tests/controller/large_positions_and_long_horizons.rs
let principal = BILLION * 10i128.pow(18);
t.supply_raw(ATTACKER, "BIG18", principal);
t.supply_raw(ATTACKER, "COL", BILLION * 10_000_000 * 3);
t.borrow_raw(ATTACKER, "BIG18", principal / 100 * 98);

loop {
    t.advance_time(YEAR_SECS);
    if t.try_update_indexes_for(&["BIG18"]).is_err() {
        break;
    }
}

assert_contract_error(
    t.try_withdraw_raw(ATTACKER, "BIG18", 1),
    errors::MATH_OVERFLOW,
);
assert_contract_error(
    t.try_repay(ATTACKER, "BIG18", 1.0),
    errors::MATH_OVERFLOW,
);
```

```rust
pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {
```

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
```

```rust
/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
