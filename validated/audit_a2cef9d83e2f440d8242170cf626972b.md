### Title
Single-bidder phantom auctions during solver-participation collapse let one solver set the published indexed pool rate with no floor, mispricing real orders - (File: `sdk/packages/sdk/src/protocols/intents/phantom-aggregation.ts`)

### Summary
`aggregatePhantomBids` reduces a phantom order's solver bids to one liquidity-weighted `medianPrice` per leg via `weightedMedian` [1](#0-0) . That per-leg selection is a **verbatim pick of one bidder's quote**, not a blend, and it carries no reserve/floor bound: `weightedMedian` documents that "a solver holding over half the leg's weight sets the published price verbatim" [2](#0-1) . When only one verified, inventory-backed solver bids in a window — exactly the scenario the MakerDAO incident describes, where network congestion starved an auction of competing participants — that lone solver's self-chosen quote becomes `medianPrice = lowestPrice = highestPrice` for the leg with no sanity check against a prior price, deviation limit, or minimum-participant requirement.

### Finding Description
The auction is unprivileged and open: any address delegated as a `SolverAccount` can submit a `FillerBid` for a `PhantomOrderV2` during its bid window [3](#0-2) . Bids are only dropped for failing signature/delegation verification or holding zero output-token inventory [4](#0-3) ; there is no requirement that more than one solver participate, and no floor comparing the winning quote to a reference price. `weightedMedian` then returns exactly the quote of whichever bidder reaches half the cumulative weight — with a single qualifying bidder, that is always its own number [5](#0-4) .

This medianPrice is written into `PhantomOrderPriceSnapshotV2` and folded by `updateLiquidityPools`/`mergeChainRowsIntoPool` into `LiquidityPool.sellRate`/`buyRate` [6](#0-5) . The only guard on that merge, `warnOnDivergentSample`, requires at least two chain rows to compare and even then only logs, never rejects, a >5x outlier [7](#0-6) . Since `2026-08-25`, `IntentGateway.quoteIntent` prices real user orders directly from this aggregate rate by default (`indexed_rates` strategy) [8](#0-7) , and `quoteWithIndexedRate` consumes `selectedRate.scaledRate` with only a `>0`/valid-timestamp check — no deviation cap, no minimum age, no minimum-bidder provenance check [9](#0-8) .

An attacker who is (or briefly becomes, e.g. during high gas/congestion that keeps other solvers' bid extrinsics from landing in the window, exactly like the MakerDAO scenario) the sole surviving delegated bidder on a phantom order's leg can quote an extreme, self-serving output amount. That single quote becomes the leg's `medianPrice` with no floor, propagates unblocked into the pool's published `sellRate`/`buyRate`, and is then used verbatim by `quoteIntent` to price subsequent real intent orders for other users on that pair — letting the attacker extract value from real swappers or drain solver/pool depth advertised against a fabricated rate.

### Impact Explanation
This is a High-severity finding: it is a direct analog of the MakerDAO zero-bid liquidation flaw — an auction/price-discovery mechanism with no reserve price that degrades to "whoever shows up wins at their own price" when competition is suppressed by network congestion. Real user funds move through `IntentGateway` orders priced from `quoteIntent`'s `indexed_rates` strategy, so a manipulated `LiquidityPool.buyRate`/`sellRate` directly mis-prices escrowed token swaps, causing economic loss to users or to the solvers/LPs whose liquidity is measured against the tainted rate.

### Likelihood Explanation
Likelihood is Medium-to-High: no privileged access is required, only being a delegated `SolverAccount` — a role any market participant can obtain — and being the sole (or dominant-weight) bidder in a given window, which is exactly the condition network congestion or targeted transaction-inclusion griefing naturally produces, per the referenced incident's root cause.

### Recommendation
Require a minimum number of independent verified bidders (or minimum aggregate weight diversity) before a leg's `medianPrice` is allowed to update `LiquidityPool` rates; bound any single-window rate movement against the pool's prior `sellRate`/`buyRate` (a deviation cap, not just a >5x cross-chain warning); and have `quoteIntent`'s indexed-rate strategy reject rates whose backing snapshot had fewer than N distinct bidders or whose bidCount collapsed relative to recent history.

### Proof of Concept
1. Attacker becomes a delegated `SolverAccount` for a phantom-order pair with real trading volume.
2. During a period of network congestion (or by front-running/griefing other solvers' bid-submission extrinsics so they miss the bid window), the attacker ensures they are the only verified, inventory-backed bidder for a leg when `PhantomBidWindowExhausted` fires.
3. The attacker submits a single bid quoting an extreme output amount for that leg (favorable to themselves, e.g. very low `sellRate` or very high `buyRate`).
4. `aggregatePhantomBids` → `weightedMedian` returns that quote verbatim as `medianPrice` since it is the only backed quote [10](#0-9) .
5. `updateLiquidityPools` folds it into `LiquidityPool.sellRate`/`buyRate` with no floor/deviation check against the prior rate [6](#0-5) .
6. A subsequent, unrelated user calls `quoteIntent`, which reads this tainted rate directly and prices their real order off it [11](#0-10) , letting the attacker (or any solver filling at that rate) capture value at the victim's expense.

function mergeChainRowsIntoPool(pool: LiquidityPool, rows: PoolChainLiquidity[], referenceBlock: bigint): void {
	for (const direction of [SELL, BUY]) {
		const directionRows = rows.filter((row) => row.direction === direction)
		if (directionRows.length === 0) continue

		// Blocks are processed in order, so the difference is non-negative in practice; a row
		// from a "future" block would simply count as fresh, which is the right reading anyway.
		const fresh = directionRows.filter((row) => referenceBlock - row.lastUpdatedBlock <= MAX_SAMPLE_AGE_BLOCKS)
		const merged = fresh.length > 0 ? fresh : directionRows

		warnOnDivergentSample(pool.id, direction, merged)

		const depth = merged.reduce((acc, row) => acc + row.depth, 0n)
		const rate = weightedRate(merged)
		const bidCount = merged.reduce((acc, row) => acc + row.bidCount, 0)

		if (direction === SELL) {
			pool.sellRate = rate
			pool.sellDepth = depth
			pool.sellBidCount = bidCount
		} else {
			pool.buyRate = rate
			pool.buyDepth = depth
			pool.buyBidCount = bidCount
		}
	}
}

function warnOnDivergentSample(
	poolId: string,
	direction: string,
	rows: { chain: string; rate: bigint; depth: bigint }[],
): void {
	if (rows.length < 2) return
	for (const row of rows) {
		const consensus = weightedRate(rows.filter((other) => other !== row))
		if (consensus === 0n) continue
		if (row.rate > consensus * 5n || row.rate * 5n < consensus) {
			logger.warn(
				{ poolId, direction, chain: row.chain, rate: row.rate.toString(), consensus: consensus.toString() },
				"Pool chain sample diverges >5x from the other chains — check the token registry decimals",
			)
		}
	}
}

function quoteWithIndexedRate(
	params: QuoteIntentParams,
	tokenIn: ResolvedQuoteAsset,
	tokenOut: ResolvedQuoteAsset,
	selectedRate: SelectedIndexedRate,
	rates: BuyAndSellRates,
	protocolFeeBps: bigint,
): IndexedRateQuoteIntentResult {
	const inputUnit = 10n ** BigInt(tokenIn.decimals)
	const outputUnit = 10n ** BigInt(tokenOut.decimals)
	if (params.amountIn !== undefined) {
		const netAmountIn = deductProtocolFee(params.amountIn, protocolFeeBps)
		const amountOut =
			selectedRate.side === "buy"
				? (netAmountIn * selectedRate.scaledRate * outputUnit) / (inputUnit * INDEXED_RATE_SCALE)
				: (netAmountIn * outputUnit * INDEXED_RATE_SCALE) / (inputUnit * selectedRate.scaledRate)
		if (amountOut <= 0n) throw new InvalidIndexedRateError("quote rounds down to zero output")
		return buildResult("EXACT_INPUT", params.amountIn, amountOut, selectedRate, rates, protocolFeeBps)
	}

	if (params.amountOut === undefined) throw new Error("Quote amount is missing after validation")
	const netAmountIn =
		selectedRate.side === "buy"
			? divCeil(params.amountOut * inputUnit * INDEXED_RATE_SCALE, selectedRate.scaledRate * outputUnit)
			: divCeil(params.amountOut * inputUnit * selectedRate.scaledRate, outputUnit * INDEXED_RATE_SCALE)
	const amountIn = grossUpForProtocolFee(netAmountIn, protocolFeeBps)
	return buildResult("EXACT_OUTPUT", amountIn, params.amountOut, selectedRate, rates, protocolFeeBps)
}
