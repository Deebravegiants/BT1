### Title
Untrusted swap payload can execute route-selected code under caller authorization and steal unrelated wallet tokens - (File: `contracts/controller/src/strategies/swap.rs`)

### Summary
Controller strategy entrypoints accept an opaque `StrategySwap` payload and forward it to the configured router while the strategy caller’s authorization remains active. A malicious route can name an attacker-controlled venue or token address; code reached through that route can request unrelated `token::transfer(caller, attacker, amount)` authorization as a child of the caller’s signed strategy invocation. [1](#0-0) [2](#0-1) 

### Finding Description
`swap_tokens` checks only that `swap` is non-empty, authorizes one exact controller-to-router input transfer, and calls `router.execute_strategy(&controller, &amount_in, swap)`. It does not decode or constrain the contracts selected by `swap`. [3](#0-2) 

The subsequent controller checks bound only the controller’s measured input spend and positive output receipt; they do not prevent route-selected code from requesting additional transfers authorized by the strategy caller. [4](#0-3) 

`swap_collateral` reaches this path after caller and account authorization checks, passing the user-provided `swap` through `withdraw_and_swap_from_supply`. [5](#0-4) 

A route-selected rogue venue can call an unrelated token’s `transfer(victim, attacker, amount)`. Honest simulation records that transfer beneath the caller’s `swap_collateral` authorization, and enforcement executes it if the caller signs the returned authorization tree. [6](#0-5) [7](#0-6) 

### Impact Explanation
A crafted strategy payload can steal tokens unrelated to the lending operation directly from the caller’s wallet. The loss is not limited to the collateral amount routed through the controller: the malicious child transfer may drain any token balance the victim signs for. [2](#0-1) 

### Likelihood Explanation
Any user reachable through `swap_collateral`, `swap_debt`, `multiply`, or `repay_debt_with_collateral` can submit an attacker-provided route payload. Exploitation requires that user to sign the authorization tree containing the rogue child transfer, but opaque XDR routes and complex auth trees make the malicious transfer difficult to distinguish without client-side route decoding. [3](#0-2) [8](#0-7) 

### Recommendation
Reject arbitrary venue/token addresses in controller strategy payloads or require the router to enforce a governance-managed venue allowlist before executing route-selected contracts. At minimum, reject authorization trees containing children other than the expected controller input transfer, and expose a decoded, human-verifiable route before signing. [9](#0-8) [2](#0-1) 

### Proof of Concept
The repository’s regression test demonstrates the complete flow:

1. Alice supplies USDC and holds `WALLET_BALANCE` of an unrelated, unlisted token.
2. The attacker deploys a `RogueHopPool` configured with `(victim = Alice, wallet_token, to = attacker, amount = WALLET_BALANCE)`.
3. A route names that rogue pool.
4. Alice calls:

   `swap_collateral(alice, account_id, USDC, 50_000_000_000, ETH, route)`

5. During router execution, the rogue pool calls `wallet_token.transfer(Alice, attacker, WALLET_BALANCE)`.
6. Simulation places that token transfer as a child of Alice’s `swap_collateral` authorization.
7. When Alice signs the returned tree, the unrelated wallet token is transferred to the attacker while the swap still produces the expected ETH collateral. [10](#0-9) [11](#0-10) [6](#0-5)

#[test]
fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
}
