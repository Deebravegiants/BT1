Confirmed: `handle_unsigned` in `modules/pallets/ismp/src/lib.rs` accepts an arbitrary `Vec<Message>` from any unsigned submitter, executes them all via `Pallet::<T>::execute`, and calls `T::FeeHandler::on_executed(messages_with_weights, events)` once for the whole batch [1](#0-0) . `pallet-consensus-incentives`'s `on_executed` identifies the rewarded relayer solely from `messages.get(0)` — the signer recovered from the **first** message in the batch, if and only if it is a `Message::Consensus` — and then pays that single signer for **every** `StateMachineUpdated` event collected across the whole batch, regardless of which message in the batch actually produced which update [2](#0-1) .

### Title
Reward theft via first-message anchoring in batched `handle_unsigned` consensus submissions - (File: `modules/pallets/consensus-incentives/src/impls.rs`)

### Summary
`pallet-consensus-incentives::on_executed` attributes the reward for *every* `StateMachineUpdated` event produced by a `handle_unsigned` batch to the signer recovered from `messages[0]` only, rather than tying each state-machine's reward to the message that actually advanced it. Since `handle_unsigned` is a permissionless, unsigned extrinsic that accepts an arbitrary caller-supplied `Vec<Message>` [1](#0-0) , an attacker can prepend a cheap, self-authored consensus message for a low-value/low-cost-per-block chain as `messages[0]`, then append other relayers' or third-party valid consensus proofs for high-value chains in the same batch. All resulting `StateMachineUpdated` rewards across the whole batch are paid to the attacker's `messages[0]` signer, exactly analogous to the Nouns DAO H-1 pattern where a bogus/cheap anchor entity was used to capture rewards belonging to a legitimate, more valuable competing entity.

### Finding Description
`execute()` runs every message in the caller-supplied batch, aggregates all resulting events, and invokes the `FeeHandler` exactly once for the entire batch [3](#0-2) . The consensus-incentives handler then does:

```rust
let maybe_relayer_account = messages.get(0).and_then(|first_message| {
    if let Message::Consensus(consensus_msg) = &first_message.message { ... }
});
...
for (state_machine_id, latest_height) in highest_per_state_machine {
    let _ = Self::process_message(state_machine_height, state_machine_id, relayer_account.clone().into());
}
``` [4](#0-3) 

The reward attribution is keyed off position 0 of the batch, not off which `Message::Consensus` entry actually produced each `StateMachineUpdated` event in `highest_per_state_machine`. Because `handle_unsigned` is unsigned/permissionless and accepts any `Vec<Message>` the caller assembles (the only requirement is that every message individually carries a valid proof, since `execute` "short-circuits and revert[s] if any of the provided messages are invalid") [5](#0-4) , an attacker can:

1. Watch the mempool/relayer network for a soon-to-be-submitted, high-value consensus update for chain B (e.g. one with a high `StateMachinesCostPerBlock`, or one that has accumulated a large unrewarded block span since the last `LastRewardedHeight` watermark) — this is analogous to hyh's "attacker front-runs proposal 1 creation."
2. Construct their own trivially cheap, valid `Message::Consensus` update for an unrelated chain A (place it at index 0), then append the legitimate consensus proof(s) for chain B (which any honest relayer could have submitted, or which the attacker copies wholesale since consensus proofs are public and freely resubmittable data, not secrets tied to the original submitter).
3. Submit the whole batch as their own `handle_unsigned` transaction, front-running or racing the honest relayer's own submission of the chain-B proof.
4. `on_executed` computes `highest_per_state_machine` over *all* `StateMachineUpdated` events in the batch (chain A and chain B), and pays the reward for **both** to the attacker's signer (recovered from `messages[0]`, the chain-A message), because reward payout is decoupled from which message produced which state machine's update.

This mirrors the Nouns DAO H-1 root cause precisely: a cheap/bogus anchor entity (here, a trivial consensus message occupying slot 0) is used to capture rewards that should have accrued to a separate, legitimate piece of work (the chain-B update) bundled in the same call, at the expense of whichever relayer would otherwise have delivered chain B and collected its own reward.

### Impact Explanation
This directly steals treasury-funded `$BRIDGE` rewards and reputation-asset mints (`T::ReputationAsset::mint_into`) from the relayers who should be credited for delivering specific consensus updates [6](#0-5) . Reputation is also the primary input to collator selection per the docs, so this additionally lets an attacker unfairly inflate their collator-selection weight by attaching to other relayers' proofs [7](#0-6) . Because rewards scale with `blocks_as_balance * block_cost` and multiple state machines can be updated in one batch, the stolen amount is not bounded to a trivial sum — it can capture the full reward for any number of high-value chain updates bundled alongside the attacker's cheap anchor message. This is a direct, deterministic misdirection of protocol funds (treasury drain to the wrong account) reachable by any permissionless caller of `handle_unsigned`.

### Likelihood Explanation
`handle_unsigned` is explicitly documented as callable by "anyone" with valid proofs, and there is no restriction preventing an attacker from combining a self-authored trivial consensus message with additional, independently-valid consensus proofs for unrelated chains in the same call [8](#0-7) . Consensus proofs, once produced, are public data (finality proofs of a source chain) and are not bound to a particular submitter's identity until included in a transaction, so an attacker can freely copy a proof that another relayer would otherwise submit and repackage it behind their own anchor message, provided they win the race to have their `handle_unsigned` call included first. This only requires monitoring pending consensus updates and constructing/submitting a batch faster than the legitimate relayer — a purely economic MEV-style race with no special privileges, similar in kind to the "front-run any next valid proposal creation" step in the original report.

### Recommendation
Attribute each `StateMachineUpdated` reward to the signer of the specific `Message::Consensus` entry that produced it, not to `messages[0]`. Concretely, when building `highest_per_state_machine`, iterate the batch pairing each `Message::Consensus` with the `StateMachineId`(s) it actually advances (e.g. by tracking which message index generated which `IsmpEvent::StateMachineUpdated`, similar to how `intermediate_states` in `update_client` is already keyed per consensus message) and recover/pay the signer from that specific message rather than a single batch-wide signer derived from position 0.

### Proof of Concept
1. Attacker observes an honest relayer about to submit `handle_unsigned([Message::Consensus(proof_for_chain_B)])` where chain B has a large unrewarded block span (`latest_height - LastRewardedHeight` large) and/or high `StateMachinesCostPerBlock`.
2. Attacker crafts their own minimal, valid `Message::Consensus(proof_for_chain_A)` signed with their own key (chain A can be any connected chain with even a 1-block advance, cost negligible to produce).
3. Attacker submits `handle_unsigned([Message::Consensus(proof_for_chain_A), Message::Consensus(proof_for_chain_B)])` as a single unsigned extrinsic, using the observed/copied `proof_for_chain_B`, racing to land before the honest relayer's own submission.
4. `execute()` processes both messages, successfully verifying both proofs and emitting `StateMachineUpdated` for chain A and chain B [9](#0-8) .
5. `on_executed` recovers the relayer solely from `messages[0]` (attacker's chain-A message) and pays the treasury-funded reward for **both** chain A's and chain B's updates to the attacker, while the honest relayer who would have submitted chain B's proof independently receives nothing for that update [4](#0-3) .

	fn on_executed(
		messages: Vec<MessageWithWeight>,
		events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});

		if let Some(relayer_account) = maybe_relayer_account {
			// When a batch contains multiple `StateMachineUpdated` events for the
			// same `state_machine_id` (sequential consensus updates for the same
			// chain), `calculate_reward` reads the same persisted
			// `(latest_commitment_height, previous_commitment_height)` pair on
			// every iteration and pays the same block-span reward N times.
			// Collapse the per-state-machine event stream to the single highest
			// `latest_height` so each state machine receives one reward per
			// batch, sized by the actual span of its commitment advance.
			let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
			for event in events {
				if let IsmpEvent::StateMachineUpdated(update) = event {
					highest_per_state_machine
						.entry(update.state_machine_id)
						.and_modify(|h| {
							if update.latest_height > *h {
								*h = update.latest_height;
							}
						})
						.or_insert(update.latest_height);
				}
			}

			for (state_machine_id, latest_height) in highest_per_state_machine {
				let state_machine_height =
					StateMachineHeight { id: state_machine_id.clone(), height: latest_height };

				let _ = Self::process_message(
					state_machine_height,
					state_machine_id,
					relayer_account.clone().into(),
				);
			}
		}

	pub fn execute(messages: Vec<Message>) -> Result<Vec<events::Event>, Error<T>> {
		let host = Pallet::<T>::default();

		let message_results = messages
			.iter()
			.map(|msg| handle_incoming_message(&host, msg.clone()))
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		let messages_with_weights = message_results
			.iter()
			.zip(messages)
			.map(|(result, message)| MessageWithWeight { message, weight: result.weight() })
			.collect::<Vec<_>>();

		let events = message_results
			.into_iter()
			// check that requests will be successfully dispatched
			// so we can not be spammed with failing txs
			.map(|result| match result {
				MessageResult::Request { events, .. } |
				MessageResult::Response { events, .. } |
				MessageResult::Timeout { events, .. } => events,
				MessageResult::ConsensusMessage(events) => events.into_iter().map(Ok).collect(),
				MessageResult::FrozenClient(_) => vec![],
			})
			.flatten()
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		T::FeeHandler::on_executed(messages_with_weights, events.clone())
			.map_err(|_| Error::<T>::ErrorChargingFee)?;

		for event in events.clone() {
			// deposit any relevant events
			Pallet::<T>::deposit_event(event.into());
		}

		Ok(events)
