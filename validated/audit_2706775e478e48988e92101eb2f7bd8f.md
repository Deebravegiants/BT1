### Title
Silent single-primary-face selection with no fraud/multi-face enforcement enables misattributed signup - (File: src/agents/python/rgb_net.rs, src/plans/mod.rs)

### Summary
`EstimateOutput::primary()` picks exactly one "primary" prediction out of an arbitrary-length `predictions: Vec<EstimatePredictionOutput>` list returned per frame, and every downstream consumer (distance tracking, eye tracking, biometric capture, biometric pipeline, face-identifier fusion) uses only that single prediction, discarding all other detected faces/bodies in frame with no logging, no accumulation, and no identity-continuity check across frames. [1](#0-0)  The one nominal safety net for this — fraud detection, specifically the `MultipleFaces` feedback signal — is defined in the enum but never populated because `detect_fraud` returns `Ok(false)` unconditionally in this build. [2](#0-1) [3](#0-2) 

### Finding Description
Throughout the signup pipeline, `rgb_net::EstimateOutput::primary()` is the sole selection mechanism for which detected face in-frame is used for biometric capture, iris/eye landmark extraction, and face-identifier processing: it is called in `biometric_capture::Plan::handle_rgb_net` (capturing frames), `biometric_pipeline::Plan::new` (choosing bboxes/landmarks fed to the models), `distance::Agent::run` (proximity gating), `eye_tracker::Input::track` (mirror steering), and `mega_agent_two::Environment::fusion_rgb_net_face_identifier`. [4](#0-3) [5](#0-4) [6](#0-5) [7](#0-6) [8](#0-7) 

There is no mechanism ensuring the "primary" prediction refers to the same physical person across the multiple frames used within a single capture/enrollment session — the model re-selects "primary" independently per frame based on its own internal heuristic (e.g. bbox score), and every non-primary detection is dropped silently, analogous to how `MAX_ROYALTY_RECIPIENTS_INDEX` silently drops recipients beyond the fixed index rather than erroring or accumulating them. In a well-formed system, this risk is intended to be caught by a fraud check that flags `MultipleFaces` during signup (`PipelineFailureFeedbackMessage::MultipleFaces`), but the entire fraud-detection stage is stubbed out: `Pipeline::run` in `fraud-engine`/`plans/fraud_check.rs` never emits any check results (`N_FRAUD_CHECKS = 0`, `fraud_checks()` returns `[]`), and `Plan::detect_fraud` in `src/plans/mod.rs` short-circuits to `Ok(false)` before any pipeline-derived signal — including a legitimate multiple-person detection — can be evaluated. [9](#0-8) [10](#0-9) 

### Impact Explanation
Because non-primary detections are unconditionally discarded and no compensating fraud/multi-face check runs, a second person present in-frame during capture (e.g. a "primary" swap between the person who satisfied QR/liveness gating early in the session and a different person present during iris/face capture) is neither flagged nor blocked. This can lead to biometric data (iris code, face embeddings) being captured from and misattributed to a signup session/identity that does not match the intended, verified subject — a misattributed-signup / cross-signup-identity-binding failure, since `enroll_user` and `build_pcp` proceed using whatever the model happened to mark "primary" in the final frames without re-validating it against the person originally gated into the flow. [11](#0-10) 

### Likelihood Explanation
Exploitability depends on physically staging a scenario where a second person enters/exits frame during the capture window and becomes the model's "primary" prediction for some subset of frames, which requires physical presence at the orb but no software authentication bypass — this is a plausible operator/unprivileged-user-adjacent physical-proximity scenario during an otherwise unattended or self-serve signup, made concretely more likely here because the FOSS build has zero fraud checks (`N_FRAUD_CHECKS = 0`) that would otherwise catch it. [3](#0-2) 

### Recommendation
Track a stable per-person identity/track ID across frames within a capture session (not just per-frame "is_primary") and reject/flag the session if the primary identity changes mid-capture; reinstate or document a `MultipleFaces`-equivalent fraud check that actually gates `detect_fraud`'s boolean result rather than relying on a stub that always returns `Ok(false)`.

### Proof of Concept
Not independently reproducible from static analysis alone: this requires a live orb capture session where the RGB-Net model's `is_primary` flag switches between two distinct persons across the frame sequence consumed in `biometric_capture::Plan` and `biometric_pipeline::Plan::new`; the code paths cited above show no continuity check preventing this, and `detect_fraud` confirms no runtime enforcement exists in this build. impl Environment<'_> {
    fn fusion_rgb_net_face_identifier(
        &mut self,
        py: Python,
        frame: &camera::rgb::ArchivedFrame,
    ) -> Result<Output> {
        let ndframe = frame.into_ndarray();

        let rgb_net_res = self.rgb_net_env.rgb_net_estimate(py, ndframe.clone())?;
        // If RGB-Net fails to estimate the eyes coordinates and bbox, avoid running the slow Face Identifier.
        let Some(prediction) = rgb_net_res.primary() else {
            return Ok(Output::FusionError(FusionErrors::RgbNetFaceIdentifier(
                Some(rgb_net::Output::Error),
                None,
            )));
        };
        let face_identifier_res = self.face_identifier_env.is_valid(
            py,
            ndframe,
            (prediction.landmarks.left_eye, prediction.landmarks.right_eye),
            prediction.bbox.coordinates,
        )?;

        Ok(Output::FusionRgbNetFaceIdentifier {
            rgb_net: rgb_net_res,
            face_identifier: face_identifier_res,
        })
    }
