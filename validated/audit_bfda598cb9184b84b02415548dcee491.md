### Title
Zero-`tokenNumber` Emporium proof path (`MainEVMCircuitMin`) bypasses all fund-conservation and wallet-authorization checks in `EmporiumUpgradeable.runAction` - (File: `contracts/CircomDataBuilder.sol`, `contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol`)

### Summary
When `circomData.externalActionData.externalActionId == HINKAL_EMPORIUM_ACTION_ID` and `circomData.erc20TokenAddresses.length == 0`, `CircomDataBuilder.formInputForCircom` routes to `formInputEmporiumMin`, whose public-input vector contains only `emporiumMessage`, `timeStamp`, and `calldataHash` — no `rootHashHinkal`, no `amountChanges`, no nullifiers, no stealth-address/wallet-secret binding at all. Because `dimensionsCheck` forces `erc20TokenAddresses.length == amountChanges.length == dimensions.tokenNumber == 0`, both the deposit accounting in `Hinkal._externalTransact` and the balance-conservation loop in `EmporiumUpgradeable.runAction` iterate zero times, and `verifyWallet` is bypassed entirely when `stack.signerAddress == address(0)`. The result is that any self-generated, self-consistent proof (no real UTXO, no wallet key, no spend authorization) is accepted as full authorization to execute arbitrary `stack.ops` — including sending the Emporium contract's real, pooled ETH/token balance to an attacker-chosen address.

### Finding Description
Broken equality: **"proof accepted by `verifyProof`" should imply "spend/asset-movement is authorized by ownership of a real UTXO / wallet key that backs the amounts moved."** In the `tokenNumber == 0` Emporium path this equality is broken — the proof's public inputs `[emporiumMessage, timeStamp, calldataHash]` (`contracts/CircomDataBuilder.sol:150-161`) carry no key material and no fund-linked signal (no `rootHashHinkal`, no `amountChanges`, no nullifiers, no `stealthAddressStructure.H0x/H0y`).

Path:
1. `Hinkal.transact` (`contracts/Hinkal.sol:30-65`) calls `hinkalHelper.performHinkalChecks` → `dimensionsCheck` (`contracts/HinkalHelper.sol:64-90`) which only requires the *lengths* of `erc20TokenAddresses`/`amountChanges`/`onChainCreation`/`inputNullifiers`/`outCommitments` to match `dimensions.tokenNumber`; an attacker simply sets `dimensions.tokenNumber = 0`, satisfying every check trivially with empty arrays.
2. `CircomDataBuilder.formInputForCircom` (`contracts/CircomDataBuilder.sol:134-148`) detects `externalActionId == HINKAL_EMPORIUM_ACTION_ID && erc20TokenAddresses.length == 0` and returns `formInputEmporiumMin`'s 3-element input array instead of the normal input that binds `rootHashHinkal`, `amountChanges`, nullifiers, outCommitments, and wallet-related stealth-address fields (`getSignedMessageHash`).
3. `verifyProof` (`contracts/VerifierFacade.sol:45-58`) only checks the Groth16 proof against these 3 unconstrained public signals via the `mainEVMCircuitMin0v4` verifier — trivially satisfiable by an attacker who picks their own `emporiumMessage`/`calldataHash`/`timeStamp` and generates a matching witness locally with `snarkjs`, no wallet secret or UTXO needed.
4. `rootHashExists` (`Hinkal.sol:57-64`) is checked against `circomData.rootHashHinkal`, but since this field is never a circuit public input in the Min path, the attacker can pass any historically valid root — it proves nothing about ownership.
5. `Hinkal._externalTransact` (`contracts/Hinkal.sol:234-261`) loops `for i < erc20TokenAddresses.length` (=0), so no deposit is taken and `deltaAmountChanges` is an empty array.
6. `EmporiumUpgradeable.runAction` (`contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol:76-160`) decodes attacker-controlled `EmporiumStack` from `externalActionMetadata`. `verifyWallet` (lines 302-349) only enforces `usedMessages[emporiumMessage]` uniqueness (trivially satisfiable — attacker picks a fresh nonce) and returns immediately without any signature check when `stack.signerAddress == address(0)` (lines 314-316).
7. The `for (i < stack.ops.length)` loop then executes `op.endpoint.call{value: op.value}(op.callData)` (stateless `Case 2`, line 112) with attacker-chosen `endpoint`, `callData`, and `value`, moving real ETH/tokens that are already sitting in the Emporium contract (pooled balance backing other users'/protocol's Emporium-related UTXOs or in-flight fee/leftover funds) to an attacker-controlled address.
8. The balance-conservation guard at lines 132-151 (`balanceChange < 0 → revert BalanceChangeShouldBePositive`) is a `for (i < circomData.erc20TokenAddresses.length)` loop — with `erc20TokenAddresses.length == 0` this loop body never executes, so **no conservation check applies to any asset moved by `op.value`/`callData`.**

Existing guards fail because: `dimensionsCheck` only checks array-length equality (satisfiable with all-zero-length arrays), `verifyProof` is checking a public-input vector that in this branch has been intentionally stripped of every ownership/fund-binding signal, `rootHashExists` is a generic existence check disconnected from the (missing) proof binding, and `verifyWallet`'s signature check is opt-out via `signerAddress == address(0)`.

### Impact Explanation
An attacker can drain any ETH/ERC20 balance currently held by the `EmporiumUpgradeable` contract (funds from other users' partially-completed Emporium flows, protocol/relay fee accruals, or any leftover balance) to an arbitrary address, with a self-generated proof that requires no wallet secret, no valid UTXO, and no nullifier spend. This is a direct theft of protocol/in-flight user funds and a fund-movement authorization bypass — matching **Critical** ("direct theft of shielded or in-flight user funds ... proof or nullifier verification bypass") since the "proof" accepted here carries no verifiable link to the funds it authorizes moving. The attack is fully repeatable for as long as the Emporium contract holds a non-zero balance of any asset, at near-zero cost (gas only).

### Likelihood Explanation
Preconditions: the `EmporiumUpgradeable` contract must hold a non-zero balance of some asset (realistic given it is a persistent pooled-execution contract for multi-step DeFi actions where funds can remain between transactions) and the attacker needs the ability to register/target the Emporium's registered `externalActionId` (already public/known) and craft `CircomData` (fully within the attacker's described capabilities — deposit, proof generation, calldata crafting). No privileged role, victim key, or relayer collusion is required. The only cost is generating one Groth16 proof for `MainEVMCircuitMin` with self-chosen inputs, which is standard `snarkjs` usage requiring no secret material tied to any account. This is directly reachable through `Hinkal.transact`, the sole public entrypoint.

### Recommendation
The `formInputEmporiumMin` public-input reduction must not be usable to authorize real fund movement. Either: (1) forbid `tokenNumber == 0` from reaching `EmporiumUpgradeable.runAction` when `stack.ops` contains value-bearing/state-changing operations (i.e., require `erc20TokenAddresses.length > 0` whenever `stack.ops.length > 0`, or otherwise bind the operation set into the proof's public inputs), (2) enforce the balance-conservation check in `EmporiumUpgradeable.runAction` over the *actual* set of assets touched by `stack.ops` rather than only `circomData.erc20TokenAddresses`, and (3) never allow `verifyWallet` to fully bypass signature verification for external, fund-moving operations — require `stack.signerAddress != address(0)` (or an equivalent binding) whenever `op.invokeWallet == false` and `op.value > 0` / `callData` targets an arbitrary external call.

### Proof of Concept
Foundry test plan (fork or local, using a locally generated `snarkjs` proof for `MainEVMCircuitMin`):
1. Deploy/fork `Hinkal`, `HinkalHelper`, `VerifierFacade` with the real `mainEVMCircuitMin0v4` verifier registered, and `EmporiumUpgradeable` registered as `externalActionMap[HINKAL_EMPORIUM_ACTION_ID]`.
2. Fund `EmporiumUpgradeable` with ETH (e.g., simulate a legitimate prior deposit leaving `address(emporium).balance == 10 ether`) — assert `balanceBefore == 10 ether`.
3. Off-chain: generate a Groth16 proof for `MainEVMCircuitMin` with attacker-chosen `emporiumMessage`, `timeStamp`, and a `calldataHash` computed to equal `CircomDataBuilder.getHashedCalldata` of the crafted `CircomData` (self-consistent, no real UTXO/nullifier/root needed).
4. Build `CircomData` with `dimensions.tokenNumber = 0`, all token-number-length arrays empty, `externalActionData.externalActionId = HINKAL_EMPORIUM_ACTION_ID`, `externalActionData.externalAddress = emporium`, `externalActionData.externalActionMetadata = abi.encode(EmporiumStack({signerAddress: address(0), ops: [EmporiumOperation({endpoint: attacker, invokeWallet: false, value: 10 ether, callData: ""})], maxFee:0, deadline:0}))`, and a `rootHashHinkal` equal to any existing valid root.
5. Call `Hinkal.transact(a, b, c, dimensions, circomData)` from attacker EOA.
6. Assert: `verifyProof` succeeds, `rootHashExists` succeeds, `EmporiumUpgradeable.runAction` executes with no revert, and `address(attacker).balance` increased by `10 ether` while `address(emporium).balance == 0` — i.e., **`balanceChange` (real asset movement) != 0 while the on-chain conservation equality `balancesAfter[i] - balancesBefore[i] + deltaAmountChanges[i] >= 0` was never evaluated for the ETH asset** because `circomData.erc20TokenAddresses.length == 0`, proving funds left the protocol with no wallet-secret or nullifier check anywhere in the call path.     function runAction(
        CircomData calldata circomData,
        int256[] calldata deltaAmountChanges
    ) external override onlyAllowedRecipient returns (UTXO[] memory) {
        EmporiumStack memory stack = abi.decode(
            circomData.externalActionData.externalActionMetadata,
            (EmporiumStack)
        );

        uint256[] memory balancesBefore = getBalancesForArray(
            circomData.erc20TokenAddresses
        );

        verifyWallet(stack, circomData);

        for (uint256 i = 0; i < stack.ops.length; i++) {
            EmporiumOperation memory op = stack.ops[i];

            bool success;
            bytes memory err;

            // CASE 1: Stateful Interaction
            if (op.invokeWallet && stack.signerAddress != address(0)) {
                (success, err) = IHinkalWallet(stack.signerAddress)
                    .callHinkalWallet(op.endpoint, op.callData, op.value);
            }
            // CASE 2: Stateless Interaction
            else {
                bytes4 selector = bytes4(op.callData);
                if (
                    selector == IHinkalWallet.callHinkalWallet.selector ||
                    selector == IHinkalWallet.doSendToRelay.selector
                ) {
                    revert UnauthorizedWalletCall();
                }

                (success, err) = op.endpoint.call{value: op.value}(op.callData);
            }

            if (!success) {
                revert CallFailed(err);
            }
        }

        payRelayFees(circomData, stack.signerAddress, deltaAmountChanges);

        uint256[] memory balancesAfter = getBalancesForArray(
            circomData.erc20TokenAddresses
        );

        UTXO[] memory utxoSet = new UTXO[](
            circomData.erc20TokenAddresses.length
        );

        uint256 utxoSetLength;

        for (uint256 i = 0; i < circomData.erc20TokenAddresses.length; i++) {
            int256 balanceChange = int256(balancesAfter[i]) -
                int256(balancesBefore[i]);

            if (deltaAmountChanges[i] < 0) {
                balanceChange -= deltaAmountChanges[i];
                // this equation reads: total change of emporium balance = what was moved to emporium (-deltaAmountChange) + how emporium balance changed through tx (balanceChange)
            }

            // the only case when balanceChange can be < 0, when there were some funds on emporium before the call
            if (balanceChange < 0) {
                revert BalanceChangeShouldBePositive();
            }

            UTXO memory utxoOut = handleOut(balanceChange, circomData, i);

            if (utxoOut.amount > 0) {
                utxoSet[utxoSetLength++] = utxoOut;
            }
        }

        if (utxoSetLength < circomData.erc20TokenAddresses.length) {
            utxoSet.skipLast(
                circomData.erc20TokenAddresses.length - utxoSetLength
            );
        }

        return utxoSet;
    }

    function verifyWallet(
        EmporiumStack memory stack,
        CircomData calldata circomData
    ) internal {
        EmporiumStorageVars storage $ = _getEmporiumStorage();

        if ($.usedMessages[circomData.emporiumMessage]) {
            revert UsedMessage();
        }

        $.usedMessages[circomData.emporiumMessage] = true;

        if (stack.signerAddress == address(0)) {
            return;
        }

        bytes32 hashedMessage = _hashTypedDataV4(
            keccak256(
                abi.encode(
                    EMPORIUM_SIGNATURE_TYPEHASH,
                    circomData.emporiumMessage,
                    _hashEmporiumOps(stack.ops),
                    stack.maxFee,
                    stack.deadline
                )
            )
        );

        (address recoveredAddress, ECDSA.RecoverError err) = ECDSA.tryRecover(
            hashedMessage,
            stack.v,
            stack.r,
            stack.s
        );
        bool verified = err == ECDSA.RecoverError.NoError &&
            recoveredAddress == stack.signerAddress;
        if (!verified) {
            revert InvalidSignature();
        }

        if (block.timestamp > stack.deadline) {
            revert SignatureExpired();
        }

        if (circomData.feeStructure.flatFee > stack.maxFee) {
            revert FeeExceedsSignedMax();
        }
    }
