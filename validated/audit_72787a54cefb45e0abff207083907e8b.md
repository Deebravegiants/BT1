Audit Report

## Title
Bridge URL (which may embed Basic Auth credentials) is exposed unredacted to lower-privileged authenticated users via unauthenticated-role-check `GET /v2/bridge_types` and `GET /v2/bridge_types/:BridgeName` - ([File: core/web/router.go])

## Summary
`BridgeType.URL` is a free-form URL supplied by an Edit/Admin-role user when creating a bridge, and nothing prevents embedding Basic Auth or token credentials in it (e.g. `https://user:pass@adapter.example.com`). While `Create`, `Update`, and `Destroy` on `/v2/bridge_types` require `auth.RequiresEditRole`, the `Index` and `Show` routes are registered with only the generic session/token authentication middleware, so any authenticated user of any role (including the lowest "Run" role, since "View" cannot even reach `authv2` handlers requiring more than base auth) can read bridge URLs and any embedded credentials.

## Finding Description
`bridges.NewBridgeType` stores the caller-supplied `URL` unchanged into the persisted `BridgeType` [5](#0-4) . `ValidateBridgeType` only checks non-emptiness, performing no credential or format validation [4](#0-3) . `BridgeResource`, the JSON-API presenter, includes `URL` in plaintext for any successful `Show`/`Index` response [6](#0-5) . In `v2Routes`, `Create`/`Update`/`Destroy` are wrapped in `auth.RequiresEditRole`, but `Index` and `Show` are not [1](#0-0) . The role-check middleware confirms a hierarchy of View < Run < Edit < Admin — `RequiresRunRole` blocks only `View`, and `RequiresEditRole` blocks `View` and `Run` [2](#0-1) . Since `Index`/`Show` apply no role gate at all, a "Run"-role (or even "View"-role, since the base `Authenticate` middleware doesn't restrict by role) authenticated user/API-token holder can retrieve bridge URLs — including any embedded credentials an Edit/Admin operator placed there — despite not being authorized to create/modify bridges.

## Impact Explanation
This is a genuine authorization inconsistency: mutating bridge operations require Edit role, but reading bridge details (which can expose embedded secrets) requires no role beyond basic authentication. If an operator embeds credentials in a bridge URL (a discouraged but technically permitted pattern, since `ValidateBridgeType` never rejects it), any lower-privileged authenticated user (e.g., "Run"-role API token, which is commonly issued to less-trusted job-triggering integrations) can exfiltrate those credentials via a normal read-only API call. This maps to the in-scope "node API authentication or role bypass" / secret-exfiltration category, since a lower-privileged role obtains data that should be gated behind Edit-role authorization.

## Likelihood Explanation
Moderate. It requires (1) an Edit/Admin operator to have embedded credentials in a bridge URL and (2) existence of a lower-privileged ("Run"-role) authenticated account/token, which is a standard multi-role deployment pattern supported by the node's own role system (`clsessions.UserRoleView/Run/Edit/Admin`). No host, database, or admin access is needed by the attacker — only a valid but lower-privileged API credential and an unauthenticated-role-check HTTP GET.

## Recommendation
Add `auth.RequiresEditRole` (or at minimum `auth.RequiresRunRole`, if broader Run-role read access to bridges is intentionally desired for job-execution purposes) to `GET /v2/bridge_types` and `GET /v2/bridge_types/:BridgeName` in `core/web/router.go`, matching the mutating routes. Additionally, consider redacting embedded userinfo from `BridgeResource.URL` in `core/web/presenters/bridges.go` (similar to `models.SecretURL` masking in `core/store/models/secrets.go`), and reject credential-embedded URLs in `ValidateBridgeType`.

## Proof of Concept
1. As an Admin/Edit user, create a bridge with a credentialed URL: `POST /v2/bridge_types {"name":"eabridge","url":"https://svc_user:s3cr3t@adapter.example.com/call"}`.
2. As a different, "Run"-role (or otherwise non-Edit) authenticated user/API token, call `GET /v2/bridge_types/eabridge`. Per `core/web/router.go` L271, this route applies no role check beyond base session/token authentication.
3. The response includes `"url":"https://svc_user:s3cr3t@adapter.example.com/call"` per `presenters.NewBridgeResource` at `core/web/presenters/bridges.go` L29-40, disclosing the embedded credential to an actor without Edit rights. A Go integration test can register a test app, create two users of different roles, create a bridge with a credentialed URL as the Edit user, then assert the Run-role user's `GET` on `/v2/bridge_types/:BridgeName` succeeds (200) and returns the raw URL, while `POST/PATCH/DELETE` on the same route correctly return 401/403 for that user.

func RequiresRunRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)

	}

// Show returns the details of a specific Bridge.
func (btc *BridgeTypesController) Show(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	bt, err := btc.App.BridgeORM().FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}
