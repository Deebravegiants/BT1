### Title
Emporium `maxFee` from the wallet-signer's EIP-712 authorization is never enforced against the fee actually withdrawn from the wallet - (File: `contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol`)

### Summary
`EmporiumUpgradeable.payRelayFees` moves real (non-shielded) funds out of a user's `HinkalWallet` by calling `doSendToRelay`, which is authorized only by the `onlyEmporium` modifier — not by any check that the amount respects the fee cap (`maxFee`) the wallet owner actually signed in `verifyWallet`. This mirrors the RewardThrottle bug class: a value-affecting field (`maxFee`) is included in one code path's "commitment" (the EIP-712 hash) but silently dropped/never re-checked in the path that actually moves value (`payRelayFees` → `sendToRelayFromWallet` → `doSendToRelay`), breaking the equality that "funds moved from wallet == funds the signer authorized."

### Finding Description
`EmporiumUpgradeable.verifyWallet` builds an EIP-712 digest that binds `stack.maxFee` (and `stack.deadline`) to the wallet owner's signature: [1](#0-0) 

However, `maxFee` appears nowhere else in the contract besides being decoded into `EmporiumStack` and hashed into this message — it is never compared against the fee that is actually withdrawn. The actual fee amount is computed independently in `payRelayFees`, from `circomData.feeStructure.flatFee` / `variableRate`, which are supplied as part of the transaction's `CircomData` (i.e., attacker/relay-controlled inputs to the call), and then unconditionally sent out of the wallet: [2](#0-1) 

`doSendToRelay` on `HinkalWallet` only checks `onlyEmporium`, not any fee-cap the wallet owner agreed to: [3](#0-2) 

So the wallet owner's signature commits to a maximum fee they are willing to pay, but the contract logic that actually transfers funds out of the wallet (`sendToRelayFromWallet` → `doSendToRelay`) never validates `relayFee <= stack.maxFee`. Whoever submits the transaction (the relay, which also controls `circomData.feeStructure` and `circomData.relay`) can set `flatFee`/`variableRate` to withdraw up to the entire outgoing amount from the wallet as "fee," while still satisfying the wallet owner's EIP-712 signature over `ops`/`maxFee`/`deadline`, because that signature is never actually checked against the real value moved.

### Impact Explanation
This allows a relay/transaction submitter to move assets out of a `HinkalWallet` in an amount the wallet owner never authorized (the owner only authorized up to `maxFee`), i.e., "executing calls or moving assets a wallet owner ... never authorised" — a High-impact unauthorized asset movement / theft of wallet funds beyond the signed fee cap.

### Likelihood Explanation
Any relay or party constructing/submitting the `transact()` call for a signer-based Emporium action controls `circomData.feeStructure`. Since `maxFee` is bound into the signature but never re-checked on-chain, exploitation requires no cryptographic break — only submitting a transaction with an inflated `feeStructure` alongside a validly-signed `EmporiumStack` (the signature does not protect the fee amount at all).

### Recommendation
In `payRelayFees` (or immediately after `verifyWallet`), enforce `require(relayFee <= stack.maxFee, "fee exceeds signed max")` for the signer-based path before calling `sendToRelayFromWallet`/`doSendToRelay`, and enforce `require(block.timestamp <= stack.deadline)` as well, since `deadline` is likewise signed but unused elsewhere in the reviewed code.

### Proof of Concept
1. Wallet owner signs an `EmporiumStack` with `ops`, `maxFee = X`, `deadline = D` via `verifyWallet`'s EIP-712 digest.
2. A relay submits `Hinkal.transact(...)` with this signed stack but crafts `circomData.feeStructure.flatFee`/`variableRate` such that `payRelayFees` computes `relayFee` far greater than `X` (up to the full withdrawn amount for that token).
3. `verifyWallet` only checks the `ops`/`maxFee`/`deadline` hash matches the signature — it never compares `relayFee` computed later to `stack.maxFee`.
4. `payRelay` → `sendToRelayFromWallet` → `IHinkalWallet(signerAddress).doSendToRelay(relay, relayFee, feeToken)` executes, and `HinkalWallet.doSendToRelay` only checks `onlyEmporium`, transferring `relayFee` out of the wallet regardless of the signed `maxFee`. [4](#0-3) [5](#0-4)

    function payRelayFees(
        CircomData calldata circomData,
        address signerAddress,
        int256[] calldata deltaAmountChanges
    ) internal {
        FeeStructure calldata feeStructure = circomData.feeStructure;

        bool foundToken = false;

        for (uint256 i = 0; i < circomData.erc20TokenAddresses.length; i++) {
            // tokens deposited into Emporium are not charged
            if (deltaAmountChanges[i] >= 0) {
                continue;
            }

            address erc20TokenAddress = circomData.erc20TokenAddresses[i];
            bool isFeeToken = erc20TokenAddress == feeStructure.feeToken;

            if (isFeeToken) {
                foundToken = true;
            }

            uint256 relayFee = 0;
            uint256 flatFee = isFeeToken ? feeStructure.flatFee : 0;

            if (signerAddress == address(0)) {
                uint256 sumAbs = uint256(-deltaAmountChanges[i]);

                EmporiumStorageVars storage $ = _getEmporiumStorage();
                relayFee = $._hinkalHelper.calculateRelayFee(
                    sumAbs,
                    flatFee,
                    feeStructure.variableRate
                );
            } else {
                relayFee = flatFee;
            }

            payRelay(
                circomData.relay,
                signerAddress,
                relayFee,
                erc20TokenAddress
            );
        }

        if (!foundToken && feeStructure.flatFee != 0) {
            require(
                signerAddress != address(0),
                "Gas Token in Emporium is not found"
            );

            payRelay(
                circomData.relay,
                signerAddress,
                feeStructure.flatFee,
                feeStructure.feeToken
            );
        }
    }

    function payRelay(
        address relay,
        address signerAddress,
        uint256 relayFee,
        address erc20TokenAddress
    ) internal {
        if (relay == address(0) || relayFee == 0) {
            return;
        }

        if (signerAddress == address(0)) {
            sendToRelay(relay, relayFee, erc20TokenAddress);
        } else {
            sendToRelayFromWallet(
                relay,
                signerAddress,
                relayFee,
                erc20TokenAddress
            );
        }
    }
