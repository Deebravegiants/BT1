### Title
JWT Replay Protection Race Condition (TOCTOU) Allows Duplicate Authorization of Workflow-Trigger Requests - ([File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go])

### Summary
The AzukiDAO incident stemmed from a `signatureClaimed` flag that was checked and set non-atomically, letting two transactions race through the check before either one recorded the claim, resulting in a successful replay. The `WorkflowMetadataHandler.Authorize` function in the chainlink gateway's HTTP-trigger authorization path has the same non-atomic "check-then-record" pattern for its JWT single-use (`jti`) replay guard, allowing an unprivileged client to replay the exact same signed JWT/request twice by racing two concurrent requests.

### Finding Description
`Authorize` verifies a signer's JWT, then checks whether the JWT's `jti` was already used via `h.jwtCache.isReplay(claims.ID)`, and only records the `jti` as used at the very end via `h.jwtCache.recordUsage(claims.ID)`, after unrelated business logic (workflow-to-key lookup, signer authorization) runs in between: [1](#0-0) 

The underlying cache implements `isReplay` and `recordUsage` as two independently-locked operations rather than a single atomic check-and-set: [2](#0-1) 

Because `isReplay` (`RLock`) and `recordUsage` (`Lock`) are separate critical sections with unguarded logic executing between them, two goroutines handling two concurrent requests carrying the identical signed JWT can both pass `isReplay` == false before either calls `recordUsage`. This is exactly the "check not properly guarded before mutation" flaw that caused the AzukiDAO `signatureClaimed` replay: the intended invariant ("a given `jti` is authorized at most once") is not enforced atomically.

This contrasts with the Vault authorization path in the same repo, which correctly implements the check-and-record as a single atomic operation under one mutex: [3](#0-2) 

The vulnerable `Authorize` function is reachable directly from an unauthenticated HTTP client hitting the internet-facing gateway's HTTP trigger handler: [4](#0-3) 

### Impact Explanation
A malicious but otherwise unprivileged workflow-trigger client can fire the same signed JWT-bearing HTTP trigger request twice (or more) concurrently at the gateway. Both requests can race past the single-use `jti` check before either records usage, letting the same signed authorization be used to authorize more than one workflow execution/run. Since this is the authentication gate for triggering workflow executions on the DON, a successful race bypasses the "one JWT = one authorized action" guarantee, enabling duplicate/unauthorized job execution using a single, otherwise-expended credential — the direct analog of the unauthorized fund/asset movement caused by AzukiDAO's improperly-checked `signatureClaimed`.

### Likelihood Explanation
The race window is small but real: it requires the attacker to fire two requests with an identical JWT at (roughly) the same time to the gateway, which is straightforward for a remote unprivileged client to attempt repeatedly until the race succeeds. No special privileges beyond possessing one valid signed JWT are needed, and the gateway is an internet-facing entry point designed to process many concurrent requests, increasing the practical odds of hitting the window under load.

### Recommendation
Make the JWT replay check-and-record atomic under a single critical section (mirroring `RequestReplayGuard.CheckAndRecord` in the vault package): acquire the write lock once, check for existence of the `jti`, and if absent, immediately insert it before releasing the lock — performing this compare-and-set before any other authorization logic runs, and rejecting the request outright if the `jti` was already present.

### Proof of Concept
1. Client obtains one valid signed JWT for a `MethodWorkflowExecute` request per `utils.CreateRequestJWT`/`VerifyRequestJWT`.
2. Client sends this JWT concurrently in two simultaneous HTTP trigger requests to the gateway's `httpTriggerHandler`, which calls `workflowMetadataHandler.Authorize(workflowID, req.Auth, req)`.
3. Both goroutines executing `Authorize` call `h.jwtCache.isReplay(claims.ID)` before either has called `h.jwtCache.recordUsage(claims.ID)` (per [5](#0-4) ), so both observe `isReplay == false` and both pass authorization, resulting in two authorized executions from a single signed, intended-to-be-single-use JWT.

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}

func (cache *jwtReplayCache) isReplay(jti string) bool {
	cache.mu.RLock()
	defer cache.mu.RUnlock()

	_, exists := cache.cache[jti]
	return exists
}

func (cache *jwtReplayCache) recordUsage(jti string) {
	cache.mu.Lock()
	defer cache.mu.Unlock()

	cache.cache[jti] = time.Now()
}

func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}

func (h *httpTriggerHandler) authorizeRequest(ctx context.Context, workflowID string, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback) (*gateway_common.AuthorizedKey, error) {
	h.lggr.Debugw("authorizing request", "workflowID", workflowID, "requestID", req.ID)
	key, err := h.workflowMetadataHandler.Authorize(workflowID, req.Auth, req)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInvalidRequest, "Auth failure: "+err.Error(), callback)
		return nil, errors.Join(errors.New("auth failure"), err)
	}
	return key, nil
}
