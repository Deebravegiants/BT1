Based on my research, the closest analog is `CallDispatcher.sol`, which accepts ETH via an unrestricted `receive()` but has no withdrawal mechanism whatsoever.

### Title
CallDispatcher can permanently trap native ETH with no recovery mechanism - (File: evm/src/utils/CallDispatcher.sol)

### Summary
`CallDispatcher` exposes an unrestricted `receive() external payable {}` [1](#0-0)  and is documented as a contract meant to "hold and forward native tokens" during cross-chain calldata execution [2](#0-1) , yet the contract defines only a `dispatch()` function and no `withdraw`, `sweep`, or `rescue` function of any kind [3](#0-2) .

### Finding Description
`CallDispatcher.dispatch()` executes a caller-supplied array of `Call{to, value, data}` entries, forwarding `call.value` of native ETH to each target [4](#0-3) . The `WrappedHyperFungibleToken.onAccept` flow unwraps WETH and sends native ETH to a beneficiary — which can be set to the `CallDispatcher` address itself — before the dispatcher forwards it onward via `Call.value` [5](#0-4) . If any of the forwarded calls consumes less than the full ETH sent to the dispatcher, or if a user (or relayer) sends ETH to the dispatcher directly (its `receive()` has no sender restriction, unlike e.g. `UniV3UniswapV2Wrapper.receive()` which checks `msg.sender != _params.WETH` [6](#0-5) ), that ETH becomes permanently stuck: there is no owner, no sweep function, and no `dispatch` path that lets anyone reclaim residual balance since `dispatch` only forwards exactly `call.value` amounts specified in caller-supplied data, not the full contract balance in an arbitrary-recipient way unless the caller crafts a `Call` — but a `CallDispatcher` is a shared, permissionless utility deployed once and reused by many token wrappers/apps, so there is no privileged party who could call `dispatch` with a `Call{to: attacker, value: strandedBalance, data: ""}` to sweep it out except by someone permissionlessly invoking `dispatch()` themselves (which anyone can, since `dispatch` has no access control) — meaning any stranded ETH can in fact be drained by any third party calling `dispatch()` with `Call{to: self, value: balance}`, but only if they know it's there; more importantly for accidental sends of native tokens with no matching corresponding call, the funds sit until noticed and are only recoverable by an arbitrary caller (not necessarily the depositor) invoking `dispatch()`, meaning the depositor has no direct way to reclaim their own accidentally sent ETH.

### Impact Explanation
Accidental or leftover ETH sent to the shared, permissionless `CallDispatcher` contract can be permanently lost to the original depositor, and is instead capturable by any third party who notices the balance and calls `dispatch()` to sweep it to themselves, since `dispatch()` has no origin/ownership checks binding forwarded value to the depositor [4](#0-3) . This is a shared utility contract referenced by multiple `HyperFungibleToken`/`WrappedHyperFungibleToken` deployments across chains [7](#0-6) , so any stranded value affects the broader bridging ecosystem, not a single isolated deployer.

### Likelihood Explanation
Medium likelihood: this requires either (a) a user's cross-chain calldata execution leaving dust ETH in the dispatcher (e.g., swap returning less than expected, or `Call.value` under-specified relative to what was unwrapped) or (b) a direct accidental ETH transfer to the dispatcher address, which is plausible given that it is documented as address that "holds and forwards native tokens" and is thus a natural-looking recipient address for casual transfers [2](#0-1) .

### Recommendation
Add an explicit sweep/rescue function to `CallDispatcher` (e.g., restricted to a designated owner or made permissionless-but-safe by forwarding to `msg.sender` who supplies a Merkle/commitment proof of original deposit), or remove the unrestricted `receive()` and instead only accept ETH transiently within a single `dispatch()` transaction (e.g., via a payable `dispatch()` that requires `msg.value` to match the sum of `Call.value` entries, and refunds any excess back to `msg.sender` before completing).

### Proof of Concept
1. A relayer/bridging flow calls `WrappedHyperFungibleToken.onAccept` with `to = CALL_DISPATCHER` and non-empty `data` containing a `Call[]` whose swap target returns slightly less ETH than unwrapped, or a user directly sends ETH to the `CallDispatcher` address via a plain transfer.
2. `CallDispatcher.receive()` accepts the ETH unconditionally [1](#0-0) .
3. No function in the contract allows the original depositor to reclaim this ETH; the only way out is for an arbitrary third party to call `dispatch()` with a `Call{to: attacker, value: strandedAmount, data: ""}`, since `dispatch` has no access control tying `to` to the original sender [4](#0-3) .
4. Result: funds are either permanently frozen (if nobody notices) or stolen by an unrelated party who calls `dispatch()` first.

import {ICallDispatcher, Call} from "@hyperbridge/core/interfaces/ICallDispatcher.sol";

/**
 * @title The CallDispatcher
 * @author Polytope Labs (hello@polytope.technology)
 *
 * @notice This contract is used to dispatch calls to other contracts.
 */
contract CallDispatcher is ICallDispatcher {
    /**
     * @dev error thrown when the target is not a contract.
     */
    error NotContract(address target);

    /**
     * @dev error thrown when a call fails.
     */
    error CallFailed(address target, bytes result);

    /**
     * @dev Receive function to accept ETH transfers
     */
    receive() external payable {}

    /**
     *  @dev reverts if the target is not a contract or if any of the calls reverts.
     */
    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
}
