The claim is accurate and verifiable against the code. `loopRoutes` at [1](#0-0)  registers `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` on the bare `api` group with no `auth.Authenticate` wrapper, called directly in `NewRouter` at [2](#0-1) . This is inconsistent with `debugRoutes`, which wraps `/debug/vars` in `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)` [3](#0-2) , and with `metricRoutes`, whose identical pprof handler set is mounted only under the authenticated `authv2` group [4](#0-3) .

The handler implementations confirm the unauthenticated forwarding behavior: `pluginMetricHandler` and `pluginPPROFHandler` proxy to internal plugin ports based solely on the `:name` path parameter, performing no session/token check [5](#0-4) [6](#0-5) , and `pluginPPROFPOSTSymbolHandler` behaves identically for the `/symbol` endpoint [7](#0-6) . `discoveryHandler` enumerates all registered plugin names via `l.registry.List()` without any auth check [8](#0-7) .

This matches CWE-862 (Missing Authorization) — reachable, unauthenticated disclosure of plugin names, metrics, and pprof/debug data (including potential memory/goroutine/heap dumps) — and the codebase's own security model (as reflected in the auth wrapping of `/debug/vars` and `authv2`'s pprof group) treats this class of endpoint as requiring at least session authentication. None of the exclusions in `SECURITY.md` (leaked credentials, privileged-address attacks, config/test files, DDoS-only, non-sensitive info disclosure) apply here, since this is unauthenticated disclosure of internal node/plugin operational state and a functioning debug/profiling proxy, not merely non-sensitive metadata like IP/server names.

Audit Report

## Title
Missing authentication on LOOP plugin discovery/metrics/pprof endpoints allows unauthenticated enumeration and debug-data disclosure - (File: core/web/router.go)

## Summary
The `loopRoutes` function registers `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` on the router's top-level `api` group with no `auth.Authenticate` middleware, unlike every other sensitive route group in the same file (`debugRoutes`, `authv2`). This allows any unauthenticated network client reaching the node's HTTP port to enumerate registered LOOP plugin names and pull Prometheus metrics and pprof/debug data proxied from internal plugin processes.

## Finding Description
`NewRouter` calls `loopRoutes(app, api)` directly on the shared, unauthenticated `api` group, alongside `debugRoutes`, `healthRoutes`, `sessionRoutes`, and `v2Routes`. Unlike `debugRoutes`, which wraps `/debug/vars` in `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)`, and unlike `metricRoutes` (structurally identical pprof handlers), which is only mounted under the `authv2` group requiring token or session authentication, `loopRoutes` applies no authentication wrapper at all to its four routes.

As a result, `discoveryHandler` returns a JSON list of all registered plugin names and their Prometheus scrape targets to any caller. `pluginMetricHandler` looks up a plugin by the caller-supplied `:name` parameter and proxies a GET request to that plugin's internal Prometheus port, returning the response body directly to the unauthenticated caller. `pluginPPROFHandler` and `pluginPPROFPOSTSymbolHandler` similarly forward requests to the plugin's internal `/debug/pprof/*` and `/debug/pprof/symbol` endpoints — including profiling operations like `heap`, `goroutine`, `trace`, and `profile` — without any authentication check, in contrast to the equivalent `metricRoutes` pprof group that is deliberately gated behind `authv2`.

## Impact Explanation
This is a Missing Authorization (CWE-862) issue: reachable, unprivileged, and previously undisclosed internal node state is exposed to any network client that can reach the node's HTTP port. Impact includes enumeration of internal plugin identifiers, plugin metrics, and the ability to trigger CPU/heap/goroutine profiling and pull pprof dumps that can leak process-internal memory contents, stack traces, and other operational internals of LOOP plugin processes — without any credential. This falls squarely under the "node API authentication or role bypass" impact category applicable to Chainlink's bug bounty scope.

## Likelihood Explanation
Likelihood is high: these routes are registered unconditionally whenever the web server starts (regardless of whether any LOOP plugins are configured), require no special network position beyond reaching the node's already-exposed HTTP port, and require zero credentials, tokens, or cookies to invoke.

## Recommendation
Wrap `loopRoutes`'s route registrations in the same `auth.Authenticate` middleware used for `/debug/vars` and the `authv2` group, requiring at minimum session or token authentication before serving `/discovery`, `/plugins/:name/metrics`, and the pprof-forwarding endpoints. If `/discovery` must remain reachable by an external unauthenticated Prometheus scraper, restrict it via network-level allowlisting rather than leaving it open on the shared API router, and unconditionally gate the higher-risk pprof/symbol endpoints behind authentication.

## Proof of Concept
Without any cookie or API token:
```
curl -i http://<node-host>:6688/discovery
curl -i http://<node-host>:6688/plugins/<plugin-name>/metrics
curl -i http://<node-host>:6688/plugins/<plugin-name>/debug/pprof/heap
curl -i -X POST http://<node-host>:6688/plugins/<plugin-name>/debug/pprof/symbol
```
Per `loopRoutes` (`core/web/router.go` lines 230-236) and its unauthenticated registration in `NewRouter` (lines 87-91), all four requests succeed (HTTP 200, or 404 only for an unknown plugin name) without any authentication header/cookie, unlike every other sensitive route in the file.

// discoveryHandler implements service discovery of prom endpoints for LOOPs in the registry
func (l *LoopRegistryServer) discoveryHandler(w http.ResponseWriter, req *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	groups := make([]*targetgroup.Group, 0, 1+len(l.registry.List()))

	// add node metrics to service discovery
	groups = append(groups, pluginGroup(l.discoveryHostName, l.exposedPromPort, "/metrics"))

	// add all the plugins
	for _, registeredPlugin := range l.registry.List() {

		group.Labels[LabelMetaPluginName] = model.LabelValue(registeredPlugin.Name)
		groups = append(groups, group)
	}

func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/metrics", l.loopHostName, p.EnvCfg.PrometheusPort)
	req, err := http.NewRequestWithContext(gc.Request.Context(), http.MethodGet, pluginURL, nil)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)
	if err != nil {
		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q metrics", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}
