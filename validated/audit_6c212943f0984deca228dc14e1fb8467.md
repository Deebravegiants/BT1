### Title
Missing local-response-receipt check lets `handleGetRequestTimeouts` double-pay a GET request's relayer fee and re-run `onGetTimeout` after `onGetResponse` already settled the same commitment - (File: `evm/src/core/HandlerV2.sol`)

### Summary
`EvmHost.dispatchIncoming(GetResponse, ...)` pays the stored relayer fee and invokes the app's `onGetResponse`, but never deletes `_requestCommitments[commitment]`. `HandlerV2.handleGetRequestTimeouts` / `EvmHost.dispatchTimeOut(GetRequestTimeout, ...)` only checks that `_requestCommitments[commitment]` is still non-empty and a *remote* (Hyperbridge-side) response-receipt non-membership proof at a relayer-chosen historical height — it never checks the *local* `_responseReceipts` mapping that records a response already delivered on this host. A relayer can therefore deliver a valid `GetResponse` (paying itself the fee and triggering `onGetResponse`), and separately submit a `GetRequestTimeout` using an older, already-finalized state-machine height whose non-membership proof predates Hyperbridge's response generation, causing `dispatchTimeOut` to refund the same fee a second time to `meta.sender` and to invoke `onGetTimeout` on a request the app already finalized via `onGetResponse`.

### Finding Description
`EvmHost.dispatchIncoming(GetResponse memory response, address relayer)` (evm/src/core/EvmHost.sol:824-847) sets `_responseReceipts[commitment]`, calls `IApp.onGetResponse`, and on success pays `meta.fee` from `_requestCommitments[commitment]` to the relayer — but it does **not** delete `_requestCommitments[commitment]`: [1](#0-0) 

`EvmHost.dispatchTimeOut(GetRequestTimeout ...)` (evm/src/core/EvmHost.sol:856-877) is guarded only by "replay protection: delete `_requestCommitments[commitment]`" and unconditionally calls `onGetTimeout`, then refunds `meta.fee` to `meta.sender` on success: [2](#0-1) 

`HandlerV2.handleGetRequestTimeouts` (evm/src/core/HandlerV2.sol:293-321) gates the call only on: (a) `_requestCommitments[commitment]` still existing (`meta.sender != 0`), and (b) a non-membership storage proof, verified against `host.stateMachineCommitment(message.height)` — an arbitrary, relayer-chosen, already-committed height — for the key `RESPONSE_RECEIPTS_STORAGE_PREFIX ++ commitment`. That proof concerns Hyperbridge's own (remote) response-receipt bookkeeping, not this host's local `_responseReceipts` map: [3](#0-2) 

Because `challengePeriod` is only checked against the delay since the *chosen* height's commitment was recorded (not against the *latest* height), a relayer can pick any historical height that is already past the challenge period, even one that predates the moment Hyperbridge generated and recorded the GET response. At that historical height the non-membership proof is legitimately valid, so `handleGetRequestTimeouts` succeeds even though:
1. The response has already been delivered and settled locally via `handleGetResponses` → `dispatchIncoming(GetResponse, relayer)` (which already paid the fee and ran `onGetResponse`), and
2. `_requestCommitments[commitment]` was never cleared by that earlier response delivery, so it still passes the `meta.sender != 0` check in the timeout path.

The Substrate side of the protocol treats this exact scenario as unsafe and explicitly guards against it: `modules/ismp/core/src/handlers/timeout.rs` rejects a GET timeout when a response receipt already exists — [4](#0-3) 
No equivalent check against the EVM host's own `_responseReceipts` exists in `HandlerV2`/`EvmHost` for GET timeouts, which is the root-cause asymmetry that a WebRTC-style "use-after-free" analog maps to here: a resource (`_requestCommitments[commitment]`) that has already been logically consumed/finalized by one code path (`onGetResponse` + fee payment) is not invalidated, so a second, conflicting code path (`onGetTimeout` + fee refund) can still legally operate on it using stale proof data.

### Impact Explanation
This is a direct loss of protocol/relayer funds: the same `meta.fee` (feeToken) escrowed for one GET request can be paid out twice — once to the relayer via `dispatchIncoming(GetResponse,...)` and a second time to `meta.sender` (the payer) via `dispatchTimeOut(GetRequestTimeout,...)`. It also causes the destination app (e.g. `ExtrinsicIntents`/`IntentGatewayV2` GET-based cancel-from-source flow) to receive a second, conflicting callback (`onGetTimeout`) for a commitment whose `onGetResponse` already executed — a request whose outcome was already finalized is reprocessed, an unsound state transition that the design explicitly tries to prevent on the Substrate side. This qualifies as concrete fund loss/duplication (fee double-payment) and unsound handling of a finalized message, reachable by any relayer/user with a valid but stale proof from an unprivileged transaction — no admin/governance/collator compromise required.

### Likelihood Explanation
Exploitability depends on: (1) an attacker/relayer being able to submit both the `GetResponseMessage` and a `GetTimeoutMessage` for the same commitment, and (2) a state-machine height existing (already committed and past `challengePeriod`) whose timestamp already satisfies `request.timeout() <= state.timestamp` yet predates Hyperbridge's own response-receipt write for that GET request. This is plausible for GET requests with a timeout close to or shorter than the round-trip time Hyperbridge needs to generate the response, or simply when a relayer intentionally selects an older already-available height/proof after the response has been delivered. Both `handleGetResponses` and `handleGetRequestTimeouts` are permissionless entry points reachable by any relayer, so likelihood is not gated by any privileged role — only by proof/height availability, which any active relayer routinely has.

### Recommendation
In `HandlerV2.handleGetRequestTimeouts` (or in `EvmHost.dispatchTimeOut(GetRequestTimeout ...)`), add an explicit check that the local `_responseReceipts[commitment]` has not already been set before allowing the timeout to proceed — mirroring the `GetResponseAlreadyReceived` check in `modules/ismp/core/src/handlers/timeout.rs`. Additionally, either require the timeout proof height to be the current/latest state-machine height for the relevant remote state machine, or otherwise ensure no response can have been generated remotely by any height ≤ the chosen proof height once a response has been locally delivered, closing the "stale historical proof" race entirely.

### Proof of Concept
1. User dispatches a `DispatchGet` on the EVM host with `fee = F`, timeout `T1`, creating `_requestCommitments[commitment] = {sender, F}` — evm/src/core/EvmHost.sol dispatch(DispatchGet) path.
2. Hyperbridge processes the GET, produces a `GetResponse`, and (per protocol design) records a response receipt on its own chain at height `H2`.
3. A relayer submits `handleGetResponses` with a valid proof; `EvmHost.dispatchIncoming(GetResponse, relayer)` runs `onGetResponse` and pays fee `F` to `relayer`. `_requestCommitments[commitment]` is left untouched (evm/src/core/EvmHost.sol:824-847).
4. The same or a colluding relayer, once `T1` has elapsed relative to some earlier already-committed height `H0 < H2` (still valid and past `challengePeriod`), submits `handleGetRequestTimeouts` with a non-membership proof of the response-receipt key at height `H0`. Because at `H0` Hyperbridge had not yet written the response receipt, the proof passes.
5. `EvmHost.dispatchTimeOut(GetRequestTimeout, meta, commitment)` runs, invoking `onGetTimeout` on the app (already finalized via step 3) and refunding fee `F` again to `meta.sender`.
6. Net result: fee `F` paid out twice from the host's fee-token balance, and the destination app processes both `onGetResponse` and `onGetTimeout` for the same commitment.

Note: full confirmation that Hyperbridge always writes a response receipt strictly at generation time (and the exact height semantics of `stateMachineCommitment`) requires deeper review of the Hyperbridge-side GET-response generation code, which was not fully inspected in this pass; the EVM-side missing local-receipt check is confirmed directly from `EvmHost.sol` and `HandlerV2.sol`.

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
