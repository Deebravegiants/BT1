### Title
`TokenExchange.exchange_token` trusts the JWT `dest` claim as the OAuth token-exchange host without domain sanitization or token-type binding - ([File: lib/shopify_api/auth/token_exchange.rb])

### Summary
`ShopifyAPI::Auth::TokenExchange.exchange_token` derives the shop host used to send the app's `client_secret` directly from the session token's `dest` claim, without validating that the token is an admin session token or that the domain is a trusted Shopify domain — unlike its sibling methods in the same module.

### Finding Description
`JwtPayload` only verifies the JWT signature and that `aud == Context.api_key`; it does not bind `dest` to `iss` or verify that the token was issued for the merchant-admin surface: [1](#0-0) 

`admin_session_token?` (checking `iss.end_with?("/admin")`) exists as a helper but is never called by `TokenExchange.exchange_token`: [2](#0-1) 

The gem's own test suite confirms that non-admin tokens (e.g. checkout UI extension tokens, `iss` ending in `/checkouts`) are valid, signature-verifiable `JwtPayload` instances with a usable `dest`/`shop`: [3](#0-2) [4](#0-3) 

`exchange_token` takes `dest_shop = jwt_payload.shop` and uses it, unsanitized, to build the session/host that receives the outbound POST carrying `client_id`/`client_secret`: [5](#0-4) 

This is inconsistent with the two sibling privileged flows in the same file and in `client_credentials.rb`, which both explicitly sanitize the shop domain before using it to build the request host: [6](#0-5) [7](#0-6) 

`ShopValidator.sanitize!`/`sanitize_shop_domain` is the mechanism that restricts the host to `ShopValidator::TRUSTED_SHOPIFY_DOMAINS`: [8](#0-7) 

The broken identity binding, stated as an equality that should hold but doesn't:
`host that receives client_secret == ShopValidator.sanitize!(shop)` and `token surface used for exchange == admin session token (iss ends with "/admin")`.
In `exchange_token`, neither equality is enforced — `dest_shop` bypasses `ShopValidator` entirely, and the caller never checks `admin_session_token?` before performing the privileged exchange.

### Impact Explanation
`exchange_token` sends the app's `client_id`/`client_secret` to `https://#{dest_shop}/admin/oauth/access_token` (via `Clients::HttpClient`) using a value that (a) came straight from a JWT claim without being run through the domain allow-list used elsewhere in this same module, and (b) is not confirmed to originate from an admin session token, as opposed to a lower-trust surface token (e.g. checkout extensibility) that shares the same signing secret and claim shape. Because a valid, non-admin token is sufficient to drive this call to a merchant-supplied `dest` value, this creates the potential to redirect the credential-bearing POST request, which matches the High-impact "SSRF with the app's credentials" category.

### Likelihood Explanation
Exploitation requires possession of a JWT that is validly signed with the app's `api_secret_key` — this holds for any Shopify-issued session token for the app, including ones scoped to lower-trust embedded surfaces (e.g. checkout UI extensions), which are exposed to client-side code the app does not fully control. No `api_secret_key` leak is required by the attacker; only a legitimately Shopify-issued token for a non-admin surface, which the app then passes into `exchange_token` unmodified. This is a real gap versus the two sibling methods that already treat shop-domain sanitization as mandatory, indicating the omission is a code defect rather than a deliberate design choice.

### Recommendation
In `TokenExchange.exchange_token`:
1. Run `dest_shop` through `Utils::ShopValidator.sanitize!(dest_shop)` before constructing `shop_session`, exactly as `client_credentials` and `migrate_to_expiring_token` already do.
2. Reject the exchange if `jwt_payload` is not an admin session token (i.e., enforce the existing but unused `admin_session_token?` check, or an equivalent public check) before allowing it to drive a `client_secret`-bearing request.

### Proof of Concept
1. Obtain (or have supplied to the app) a Shopify-issued session token whose `iss` does not end in `/admin` (e.g., a checkout UI extension session token) but whose `dest` claim is attacker-influenced or points at an untrusted host reachable by the merchant's shop naming.
2. Call `ShopifyAPI::Auth::TokenExchange.exchange_token(session_token: token, requested_token_type: ...)`.
3. Observe that `dest_shop = jwt_payload.shop` is used directly (no `ShopValidator.sanitize!`, no `admin_session_token?` check) to build `shop_session` and the resulting request host: [9](#0-8) 
4. Compare with `client_credentials.rb`, where the same class of input is required to pass `ShopValidator.sanitize!` first: [10](#0-9)

      TRUSTED_SHOPIFY_DOMAINS = T.let(
        [
          "shopify.com",
          "myshopify.io",
          "myshopify.com",
          "spin.dev",
          "shop.dev",
        ].freeze,
        T::Array[String],
      )

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
