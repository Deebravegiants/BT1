### Title
`_prepareGraduationLiquidity`'s `tokensForLP` can round to 0, permanently bricking `finalizeGraduation` and freezing the graduating token's raised LT - ([File: packages/contracts/src/Bonding.sol])

### Summary
`tokensForLP` is computed as `(ltFromPair * tokenReserve) / assetReserve` with truncating integer division. When `ltFromPair` is small relative to `assetReserve` (the pair's stored virtual+real LT reserve), the division can round down to `0`. This value is then cached immutably in `pendingGraduation[token]` and, in phase 2, fed straight into `_seedDirectMint`, which calls `IUniswapV2Pair(pair).mint(lpLock)` after depositing `tokensForLP = 0` tokens and `ltFromPair` LT into the pair. A standard UniswapV2 pair's `mint` reverts with `INSUFFICIENT_LIQUIDITY_MINTED` whenever `liquidity == 0` (which is guaranteed when one deposited amount is `0`), so `finalizeGraduation` reverts every single time it is called — permanently. [2](#0-1) 

### Finding Description
`_enterGraduating` (fired inline from a threshold-crossing buy in `_executeBuy`, or permissionlessly via `triggerGraduation`) calls `_prepareGraduationLiquidity`, which:
1. Drains the real LT raised by the curve (`ltFromPair = assetReserve - virtualLtReserve`) out of the pair via `router.graduate(tokenAddress, ltFromPair)` — this LT moves into `Bonding` immediately, in phase 1, **before** any LP-seeding sanity check.
2. Computes `tokensForLP = (ltFromPair * tokenReserve) / assetReserve`, capped at `LP_RESERVE`, and burns `LP_RESERVE - tokensForLP` tokens right away.
3. Caches `(tokensForLP, ltFromPair, lpBurned, unsoldBurned)` in `pendingGraduation[token]` and flips the lifecycle to `Graduating`, freezing all trading. [3](#0-2) 

Because `canGraduate` can be armed purely by the LT's `exchangeRate()` appreciating past the USD threshold (the "rate-only ripening" case documented in `docs/contracts-scope.md` — no intervening buy is required, the next buy or `triggerGraduation` just settles the already-ripe state), `ltFromPair` can be an extremely small LT-wei amount that is nonetheless worth ≥ the USD graduation threshold when the reserve LT's `exchangeRate()` is very large (e.g. a long-lived, heavily-leveraged, heavily-appreciated BounceTech LT). In that regime, `ltFromPair` is tiny relative to `assetReserve` (which includes the large fixed `virtualLtReserve` seeded at launch), so `ltFromPair * tokenReserve / assetReserve` truncates to `0`.

Once `tokensForLP == 0` is cached, phase 2 is unrecoverable: every call to `finalizeGraduation` re-reads the same cached `PendingGraduation`, calls `_seedUniswapV2Direct` → `_seedDirectMint` (since the HyperSwap pair is fresh, `totalSupply() == 0`), transfers `0` tokens / `ltFromPair` LT to the pair, and calls `pair.mint(lpLock)`, which always reverts because a zero-amount side makes `liquidity = sqrt(amount0 * amount1) = 0`. [4](#0-3) [5](#0-4) 

This is the direct structural analog of the external report: a computed payout amount (`toPay` there, `tokensForLP` here) can legitimately drop to `0`, and the downstream code unconditionally attempts an operation (an ERC20 transfer there, a UniswapV2 `mint` here) that is guaranteed to revert on a zero amount, permanently blocking the intended action.

### Impact Explanation
- `finalizeGraduation` is the **only** path out of `Lifecycle.Graduating`; there is no rescue/retry with different parameters, and `pendingGraduation[token]` is fixed once phase 1 runs.
- Once bricked, the token is permanently stuck: `Lifecycle.Graduating` forever, trading (`buy`/`sell`) frozen for that token, and the entire `ltFromPair` (all real LT raised by the curve) plus `LP_RESERVE - tokensForLP` burned tokens are permanently locked/lost inside `Bonding` with no owner sweep path for this specific state (the token never reaches `Graduated`, so the eventual `LPLock.recordLock` and `_sweepLTToOwner` bookend never run for this token).
- This is a permanent freezing of trader/creator funds (all LT raised by the curve for that token) — squarely within the "Accept only concrete theft or permanent freezing of trader, creator or LP funds" criterion, and warrants Medium/High severity given the total, unrecoverable loss of the token's raised LT.

### Likelihood Explanation
Reaching `ltFromPair > 0` with `tokensForLP` rounding to `0` requires the LT's `exchangeRate()` to be large enough that a tiny LT-wei amount already exceeds the USD graduation threshold — plausible for long-running, heavily-leveraged/appreciated BounceTech LTs (documented in the codebase's own notes on LT appreciation triggering graduation "via LT appreciation alone, no buy in the loop"). No privileged role is needed: any unprivileged caller can invoke the permissionless `triggerGraduation(tokenAddress)` once `canGraduate` is armed by rate appreciation, or simply let the next ordinary buy through `Zap.buy` trip the inline trigger. This is a rounding/edge-case bug rather than a common-path failure, so likelihood is assessed as low-to-medium, but the impact (total, permanent fund loss) is severe enough to warrant Medium severity.

### Recommendation
Guard `_prepareGraduationLiquidity` (or `_enterGraduating`) against `tokensForLP == 0` (and symmetrically `ltFromPair == 0`, e.g. via `Math.max(tokensForLP, 1)` or by reverting `_enterGraduating`/`triggerGraduation` with a clear error until the curve has raised enough LT that the rounding is non-degenerate. Alternatively, round `tokensForLP` up (ceiling division) rather than down, ensuring at least 1 wei of token is always allocated to the LP whenever `ltFromPair > 0`, matching the "do not send/deposit a computed zero amount" fix pattern from the original report.

### Proof of Concept
1. Launch a token against a BounceTech LT whose `exchangeRate()` is set (or has appreciated) to a very large value (e.g. `exchangeRate = 1e30`+, i.e. 1 LT-wei worth many dollars).
2. Perform a minimal buy so `ltFromPair` is a very small nonzero LT-wei amount while `(ltFromPair) × exchangeRate() ≥ graduationThresholdUsd`. `canGraduate(tokenAddress)` becomes `true` via the USD trigger with `ltFromPair` tiny relative to `assetReserve`.
3. Call `bonding.triggerGraduation(tokenAddress)` (permissionless) — `_prepareGraduationLiquidity` computes `tokensForLP = (ltFromPair * tokenReserve) / assetReserve == 0` due to truncation, drains `ltFromPair` LT out of the pair via `router.graduate`, burns `LP_RESERVE` tokens, and caches `tokensForLP = 0` in `pendingGraduation[token]`.
4. Call `bonding.finalizeGraduation(tokenAddress)` — `_seedUniswapV2Direct` routes to `_seedDirectMint` (fresh pair), which transfers `0` tokens + `ltFromPair` LT to the pair and calls `pair.mint(lpLock)`, reverting with `INSUFFICIENT_LIQUIDITY_MINTED`.
5. Every subsequent call to `finalizeGraduation` reverts identically; the token is permanently stuck in `Lifecycle.Graduating`, and the drained `ltFromPair` LT plus burned tokens are unrecoverable.

    function finalizeGraduation(
        address tokenAddress
    ) external nonReentrant {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[tokenAddress];
        if (info.lifecycle != Lifecycle.Graduating) revert NotGraduating();

        address lt = info.ltAddress;
        PendingGraduation memory p = $.pendingGraduation[tokenAddress];

        // Anything in this contract beyond `p.ltFromPair` belongs to a
        // concurrent graduation on the same LT (Phase 1 transferred it
        // via `Router.graduate`) or to stray dust. Either way it is
        // off-limits to this graduation's deposit and sweep — see
        // `_routerDepositAndDispose` and `_sweepLTToOwner`.
        // Saturating subtract: a balance below `p.ltFromPair` shouldn't
        // be reachable in normal operation, but we keep finalize from
        // bricking on a Panic if any future code path or non-canonical
        // LT briefly violates the invariant.
        uint256 ltBalance = IERC20(lt).balanceOf(address(this));
        uint256 protectedLT = ltBalance > p.ltFromPair ? ltBalance - p.ltFromPair : 0;

        address lpPair = _ensureUniswapV2Pair(tokenAddress, lt);
        uint256 liquidity = _seedUniswapV2Direct(tokenAddress, lt, lpPair, p.tokensForLP, p.ltFromPair, protectedLT);

        _sweepLTToOwner(lt, protectedLT);

        info.lifecycle = Lifecycle.Graduated;
        $.graduatedPair[tokenAddress] = lpPair;
        delete $.pendingGraduation[tokenAddress];

        LPLock($.lpLock).recordLock(tokenAddress, lpPair, liquidity);

        emit TokenGraduated(tokenAddress, lpPair, liquidity, p.tokensForLP, p.lpBurned, p.unsoldBurned);

    function _prepareGraduationLiquidity(
        address tokenAddress
    ) internal returns (uint256 tokensForLP, uint256 ltFromPair, uint256 lpBurned, uint256 unsoldBurned) {
        address pairAddr = _s().tokenInfo[tokenAddress].pair;
        (uint256 tokenReserve, uint256 assetReserve) = IPair(pairAddr).getReserves();

        unsoldBurned = IPair(pairAddr).tokenBalance();
        if (unsoldBurned > 0) {
            Token(tokenAddress).burn(pairAddr, unsoldBurned);
        }

        ltFromPair = assetReserve - _launchTimeVirtualLtReserve(tokenAddress, pairAddr);
        if (ltFromPair > 0) {
            _s().router.graduate(tokenAddress, ltFromPair);
        }

        tokensForLP = assetReserve == 0 ? 0 : (ltFromPair * tokenReserve) / assetReserve;
        if (tokensForLP > LP_RESERVE) tokensForLP = LP_RESERVE;

        lpBurned = LP_RESERVE - tokensForLP;
        if (lpBurned > 0) {
            Token(tokenAddress).burn(address(this), lpBurned);
        }
    }

    function _seedDirectMint(
        address tokenAddress,
        address lt,
        address pair,
        uint256 tokensForLP,
        uint256 ltFromPair
    ) internal returns (uint256 liquidity) {
        IERC20(tokenAddress).safeTransfer(pair, tokensForLP);
        IERC20(lt).safeTransfer(pair, ltFromPair);
        liquidity = IUniswapV2Pair(pair).mint(_s().lpLock);
        uint256 leftoverToken = IERC20(tokenAddress).balanceOf(address(this));
        if (leftoverToken > 0) {
            Token(tokenAddress).burn(address(this), leftoverToken);
        }
    }
