### Title
Emporium-Min proof path (`formInputEmporiumMin`) never binds `rootHashHinkal`, `inputNullifiers`, `outCommitments`, or `amountChanges` to the verified proof - (File: `contracts/CircomDataBuilder.sol`)

### Summary
When `externalActionData.externalActionId == HINKAL_EMPORIUM_ACTION_ID` and `erc20TokenAddresses.length == 0`, `formInputForCircom` routes to `formInputEmporiumMin`, which builds a public-input vector of exactly `[emporiumMessage, timeStamp, calldataHash]`. Neither this vector, the `calldataHash` value itself, nor the `MainEVMCircuitMin` circuit that verifies it constrain `rootHashHinkal`, `amountChanges`, `inputNullifiers`, or `outCommitments`, yet those exact fields from the same `CircomData` struct are later used to insert nullifiers/commitments and check roots.

### Finding Description
The broken equality: every field of `CircomData` that is acted on by state-changing logic (`rootHashHinkal` used for root membership, `inputNullifiers`/`outCommitments` used for nullifier insertion/commitment insertion, `amountChanges` used for balance movement) must be bound inside the value actually verified by the ZK proof (the public-input vector fed to `verifyProof`, or transitively through `calldataHash`/circuit constraints). In the Emporium-Min branch this equality fails:

- `formInputEmporiumMin` (`contracts/CircomDataBuilder.sol` lines 150-161) produces only 3 signals: `emporiumMessage`, `timeStamp`, `calldataHash`.
- `calldataHash` is checked against `getHashedCalldata(circomData)` in `performHinkalChecks` (`contracts/HinkalHelper.sol` lines 221-225), but `getHashedCalldata`/`getHashedCalldata1`/`getHashedCalldata2` (`contracts/CircomDataBuilder.sol` lines 10-54) hash only `publicSignalCount, relay, emporiumMessage, externalActionData, slippageValues, hookData, encryptedOutputs, onChainEncryptedOutput, feeStructure, onChainCreation, originalSender, extraData` — it explicitly omits `rootHashHinkal`, `amountChanges`, `inputNullifiers`, `outCommitments`, `erc20TokenAddresses`, and `timeStamp`.
- The Min circuit itself, `circuits/MainEVMCircuitMin.circom`, only declares `outTimeStamp` and `calldataHash` as public signals plus a private `messageSeed`, and its sole constraint is `message <== Poseidon(1)([messageSeed])`. It contains no constraints referencing nullifiers, commitments, or the Merkle root at all.

So in this branch, `inputNullifiers`, `outCommitments`, `rootHashHinkal`, and `amountChanges` are pure unconstrained calldata: the attacker can set them to anything, and the same `a,b,c` proof (which only needs to know a `messageSeed` whose Poseidon hash matches `message`) still verifies against the Min verifier, because none of these fields appear anywhere in the values the verifier checks.

`performHinkalChecks` → `dimensionsCheck` / `checkOnchainCreation` only validate array-length consistency and internal-transaction onChainCreation rules; they do not tie array contents to the proof. Root existence/nullifier-insertion logic downstream (in `Hinkal.sol`) then acts on `rootHashHinkal`, `inputNullifiers`, and `outCommitments` values that were never part of any signal the Min circuit or `calldataHash` constrains.

### Impact Explanation
This is a proof/nullifier verification bypass (Critical). An attacker who registers/uses an Emporium external action with zero `erc20TokenAddresses` can submit a validly-verifying Min proof while freely choosing `inputNullifiers` and `outCommitments` unconstrained by the circuit, enabling either replay of previously-used nullifiers or insertion of arbitrary/forged commitments not backed by any real deposit, and use of an arbitrary `rootHashHinkal` value not tied to the proof — a leaf-spend/double-spend or unbacked shielded-value-minting primitive. This is repeatable per transaction as long as the Emporium-Min path (empty `erc20TokenAddresses`) remains reachable.

### Likelihood Explanation
Preconditions are minimal and available to an unprivileged attacker: register/use an emporium external action id and craft `CircomData` with `erc20TokenAddresses.length == 0`, which is explicitly a supported, non-privileged code path (`formInputForCircom` branch selection at `contracts/CircomDataBuilder.sol` lines 139-147). No special role is required; the attacker generates one legitimate Min-circuit proof (for a `messageSeed`) and can reuse the same `a,b,c` while freely varying `inputNullifiers`/`outCommitments`/`rootHashHinkal` in the surrounding calldata, since `dimensionsCheck` only enforces array-length parity, not content binding, and `getHashedCalldata` (which becomes `calldataHash`, the only field of these that is public) never covers these values.

### Recommendation
Include `rootHashHinkal`, `amountChanges`, the flattened `inputNullifiers`, and the flattened `outCommitments` either as explicit public signals in the Emporium-Min public-input vector, or fold them into `calldataHash`/`getSignedMessageHash` in a way that is itself constrained by `MainEVMCircuitMin` (or a corrected Min circuit variant), so the Min-circuit proof cannot verify unless it commits to the exact nullifier/commitment/root/amount values that `insertNullifiers`/`insertCommitments`/root checks subsequently act upon.

### Proof of Concept
Hardhat test:
1. Deploy the protocol, register an Emporium external action id equal to `HINKAL_EMPORIUM_ACTION_ID`.
2. Generate one valid witness/proof for `MainEVMCircuitMin` (choose `messageSeed`, compute `message = Poseidon(messageSeed)`, set `timeStamp`, and compute `calldataHash = getHashedCalldata(circomDataA)` for a `CircomData` struct A with `erc20TokenAddresses = []`, some `inputNullifiers`, `outCommitments`, `rootHashHinkal`, `amountChanges`).
3. Call `transact` with `circomDataA` and the generated `a,b,c` — assert success and record inserted nullifiers/commitments.
4. Build `circomDataB` identical to A except with different `inputNullifiers`/`outCommitments`/`rootHashHinkal`/`amountChanges` (but same `publicSignalCount, relay, emporiumMessage, externalActionData, slippageValues, hookData, encryptedOutputs, onChainEncryptedOutput, feeStructure, onChainCreation, originalSender, extraData`, so `getHashedCalldata` — and thus `calldataHash` — is unchanged) and reuse the same `calldataHash`, `timeStamp`, `emporiumMessage`, and same `a,b,c` proof.
5. Call `transact` with `circomDataB` and assert it still passes `verifyProof` (same 3-signal input `[emporiumMessage, timeStamp, calldataHash]`) and that `insertNullifiers`/`insertCommitments` execute using B's differing nullifier/commitment/root values — demonstrating PROOF COVERAGE is broken (same proof accepted for two different nullifier/commitment/root sets).
