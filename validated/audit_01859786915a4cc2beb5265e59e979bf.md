### Title
Predictable, publicly-observable Phantom bid window lets a dominant solver dictate the published intent price feed - (File: modules/pallets/intents-coprocessor/src/lib.rs, sdk/packages/sdk/src/protocols/intents/phantom-aggregation.ts)

### Summary
The Phantom order price-discovery mechanism used to quote real user intents is fully deterministic in timing and fully transparent in bid content before the window closes, and its price-selection function (`weightedMedian`) returns one bidder's exact quote verbatim whenever that bidder holds ≥50% of the leg's weight. This is the same class of bug as the Tokemak report: predictable "snapshot" timing combined with pre-snapshot observability allows an actor to game the published price that downstream consumers (real user swap quotes, liquidity-pool rates) treat as trustworthy.

### Finding Description
1. **Predictable timing**: `PhantomOrderInfo.created_at_block` and `PhantomBidWindow`/`PhantomOrderBidWindowBlocks` are on-chain values. The exact block at which the bid window closes and `PhantomBidWindowExhausted` fires is `created_at_block + window`, computable by anyone the moment the order is registered: [3](#0-2) .
2. **Pre-close observability**: any account can call `place_bid` (unprivileged, `ensure_signed`) and immediately read every other filler's bid via `getBidsForOrder`/`intents_getBidsForOrder`, well before the window closes and the snapshot is aggregated: [4](#0-3) .
3. **Selection, not blend**: `weightedMedian` returns the exact price of whichever bidder's cumulative weight crosses 50% of total weight — not an average — so a single solver holding a majority of the leg's output-token inventory sets the published price verbatim: [5](#0-4) , confirmed by tests: [6](#0-5) .
4. **Consumption in real trades**: the resulting `PhantomOrderPriceSnapshotV2.medianPrice` is fed straight into `PhantomSnapshotIntentQuoteStrategy.quote()` to price real `amountIn`/`amountOut` for user intents: [2](#0-1) , and into `updateLiquidityPools`, which derives pool `sellRate`/`buyRate` from the same median: [7](#0-6) .

Combining these: a dominant/well-capitalized solver (no privilege required, any signed account with enough on-chain balance of the leg's output token) can observe all competing bids already placed (transparent on-chain state, stronger than mempool observation in the original report), then place or adjust its own bid last, within the same closing block, quoting an arbitrary price. Because its weight dominates the leg, `weightedMedian` selects that arbitrary price verbatim as the "market" price, which then prices real users' cross-chain swaps and updates the indexed liquidity-pool exchange rate.

### Impact Explanation
The manipulated `medianPrice` directly determines `amountOut`/`amountIn` for real intents quoted via `PhantomSnapshotIntentQuoteStrategy`, and the derived pool `sellRate`/`buyRate` used elsewhere. A dominant solver can push the published price favorably (e.g., quote a worse-than-fair rate) right before the window closes, after seeing it has no competing weight to outvote it, extracting value from users who accept quotes based on that snapshot, or mispricing downstream integrations that read `PoolChainLiquidity`/`LiquidityPool` rates. This is a concrete economic manipulation of a price oracle feeding real fund movement (intent settlement), reachable by any unprivileged intent solver — Medium severity, consistent with the original report's classification.

### Likelihood Explanation
Likelihood is Medium-High: the mechanism requires no special privilege — only capital dominance in one leg's output token on one destination chain, which is realistic for a well-funded single solver, and the timing/observability primitives (`created_at_block`, `PhantomBidWindow`, on-chain bids) are all public by design.

### Recommendation
- Do not let a single bidder's raw quote pass through unmodified when it holds dominant weight; consider a depth-weighted mean (as already used for `sellRate`/`buyRate` aggregation across chains) instead of a "selection" median for the leg-level price, or cap any single solver's weight contribution.
- Consider committing bids (hash-commit / reveal) so bids are not readable by other participants until the window closes, removing the "observe-then-bid-last" advantage.
- Add sanity/deviation bounds (similar to the `referencePrice`/`maxDeviationBps` guard already used for Uniswap-pool pricing) to the phantom snapshot median before it is trusted by `PhantomSnapshotIntentQuoteStrategy` or `updateLiquidityPools`.

### Proof of Concept
1. Governance/config registers a Phantom order for chain X with `PhantomBidWindow = W`; `created_at_block` and `W` are both public, so the closing block `created_at_block + W` is known to everyone at registration time.
2. Solver A places a small, fair bid early in the window; other fillers do the same.
3. A dominant solver B (holding >50% of the leg's output-token inventory on chain X) queries `getBidsForOrder` mid-window, observes all competing quotes, and — right before `created_at_block + W` — submits (or is the sole bidder for) a quote priced arbitrarily far from fair value.
4. At `on_finalize` of block `created_at_block + W`, `PhantomBidWindowExhausted` fires; `aggregatePhantomBids` runs `weightedMedian`, which (per the unit test at `phantomAggregation.test.ts:190-198`) returns B's exact price verbatim because its cumulative weight ≥ 50% of total.
5. `PhantomOrderPriceSnapshotV2.medianPrice` is now B's chosen value; any real user intent quoted through `PhantomSnapshotIntentQuoteStrategy.quote()` in that window is priced off it, and `updateLiquidityPools` republishes it as the pool's `sellRate`/`buyRate`.

// Liquidity-weighted median of solver quotes. Each quote's influence is proportional to `weight` —
// the solver's total balance for the output token across native + vault venues — so a solver that
// can actually deliver size moves the price more than one quoting on thin liquidity. Returns the
// lower weighted median: the smallest price whose cumulative weight reaches half of the total.
// Zero-weight quotes contribute nothing.
//
// Callers must not hand this an entry set whose weights are all zero: with nothing to weight by it
// can only pick a quote by position, and for an even-sized set that position is the upper of the
// two middles — so "the median" becomes "whoever quoted higher", settable by a solver holding no
// inventory at all. aggregatePhantomBids drops such legs instead of pricing them. The fallback
// below stays only so an unguarded caller gets a number rather than a crash; treat reaching it as
// a caller bug.
export function weightedMedian(entries: { price: bigint; weight: bigint }[]): bigint {
	const sorted = [...entries].sort((a, b) => (a.price < b.price ? -1 : a.price > b.price ? 1 : 0))
	const totalWeight = sorted.reduce((acc, e) => (e.weight > 0n ? acc + e.weight : acc), 0n)

	if (totalWeight === 0n) {
		return sorted[Math.floor(sorted.length / 2)].price
	}

	let cumulative = 0n
	for (const entry of sorted) {
		if (entry.weight <= 0n) continue
		cumulative += entry.weight
		if (cumulative * 2n >= totalWeight) return entry.price
	}
	return sorted[sorted.length - 1].price
}

		#[pallet::call_index(0)]
		#[pallet::weight(T::WeightInfo::place_bid())]
		pub fn place_bid(
			origin: OriginFor<T>,
			commitment: H256,
			user_op: BoundedVec<u8, ConstU32<1_048_576>>,
		) -> DispatchResult {
			let filler = ensure_signed(origin)?;

			// Validate user_op is not empty
			ensure!(!user_op.is_empty(), Error::<T>::InvalidUserOp);

			// Phantom orders have stricter rules: one bid per filler, no updates, and only
			// within the configured acceptance window after the order was registered. Every
			// chain's active order is checked, not just the most recently generated one.
			if let Some(active) = CurrentPhantomOrder::<T>::get() {
				if let Some((_, info)) = active.iter().find(|(c, _)| *c == commitment) {
					let window: BlockNumberFor<T> = Self::phantom_bid_window().into();
					ensure!(
						frame_system::Pallet::<T>::block_number() <= info.created_at_block + window,
						Error::<T>::PhantomOrderBidWindowClosed
					);
					ensure!(
						!Bids::<T>::contains_key(&commitment, &filler),
						Error::<T>::DuplicatePhantomBid
					);
				}
			}

			// If a bid already exists, unreserve the old deposit first
			if let Some(old_deposit) = Bids::<T>::get(&commitment, &filler) {
				<T as Config>::Currency::unreserve(&filler, old_deposit);
			}

			let deposit = Self::storage_deposit_fee();

			// Reserve the new deposit
			<T as Config>::Currency::reserve(&filler, deposit)
				.map_err(|_| Error::<T>::InsufficientBalance)?;

			// Store the bid in offchain storage
			let bid = Bid { filler: filler.clone(), user_op: user_op.to_vec() };
			let offchain_key = Self::offchain_bid_key(&commitment, &filler);
			offchain_index::set(&offchain_key, &bid.encode());

			// Store deposit amount in onchain storage for discoverability and accurate refunds
			Bids::<T>::insert(&commitment, &filler, deposit);

			Self::deposit_event(Event::BidPlaced { filler, commitment, deposit });

			Ok(())
		}
