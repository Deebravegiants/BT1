### Title
Debt-holding accounts permanently keep an elevated liquidation-threshold stamp after an asset is removed as collateral, because the liquidator-favoring gate can never clear for a zero/cut threshold - (contracts/controller/src/risk/params.rs)

### Summary
XOXNO Lending stamps each supply position's `loan_to_value`, `liquidation_threshold`, `liquidation_bonus` and `liquidation_fees` at position creation and thereafter trusts the stored stamp, not the live spoke listing. This is the protocol's analog of Aave's E-Mode collateral factors: the "is this asset collateral, and at what weight" decision lives on the position. When governance removes an asset as collateral (`can_collateral = false` / LTV and liquidation threshold set to zero via `EditAssetInSpoke`), the stamp is supposed to be restamped by `update_account_threshold`, supply legs, or withdraw legs. However, `apply_gated_liquidation_params` refuses to apply any change that "favors the liquidator" unless the account's hypothetical health factor under the *new* threshold is ≥ 1.05. For an asset removed from collateral (threshold → 0), that hypothetical HF is 0 for any account with debt, so the stamp can never be restamped. The position keeps counting its old elevated `liquidation_threshold` in `weighted_collateral` forever, making the account unliquidatable and letting it carry bad debt the protocol must absorb.

### Finding Description
- Every supply position stores its own LTV/LT copied from the listing at creation; health factor and borrow limits use the stored values, not the live listing (`calculate_account_risk_totals` uses `position.liquidation_threshold` and `min(position.loan_to_value, position.liquidation_threshold)` with no `is_collateralizable` check). [1](#0-0) 
- Restamp happens in `refresh_supply_risk_params` / `apply_gated_liquidation_params`. A change that lowers the threshold, raises the bonus, or lowers the fee is deemed liquidator-favoring and is skipped unless the account's HF computed with the *new* threshold is ≥ `THRESHOLD_UPDATE_MIN_HF_RAW` (1.05); on failure the function returns early and silently keeps the old stamp. [2](#0-1) 
- `restamp_listed_supply_ltv` and `sync_account_thresholds` additionally `continue` on any asset for which `cache.cached_spoke_asset` returns `None`, so a fully unlisted asset's stamp can never be touched at all. [3](#0-2) 
- The harness tests confirm the stamp is sticky below the gate: `poc_lt_cut_stays_sticky_when_hf_below_min` shows LT stays 8000 after a cut whenever post-cut HF < 1.05, and `a_stranger_cannot_tighten_a_stale_threshold_below_the_update_floor` shows even a stranger's dust top-up cannot force it. [4](#0-3) 
- The runbook documents that stored LT/bonus/fee only refresh on the three gated paths, and that a liquidation never refreshes them. [5](#0-4) 

The E-Mode analog maps cleanly: removing an asset from a category ≈ governance executing `EditAssetInSpoke` with `can_collateral = false`, `ltv = 0`, `threshold = 0`. For accounts holding debt, the old elevated `liquidation_threshold` stamp is permanent — no unprivileged or privileged restamp path can ever satisfy a 1.05 HF gate computed against a zero threshold, and `calculate_account_risk_totals` never re-checks whether the asset is still collateralizable.

### Impact Explanation
Protocol insolvency. Once an asset is removed as collateral (e.g., because it de-pegged, its oracle is deprecated, or its spoke category is removed — `remove_spoke_category` is exercised in tests), every indebted account that supplied it keeps it valued at the old LT in `weighted_collateral`. Such an account's reported HF stays artificially ≥ 1, so `liquidate` rejects attempts on it, while its debt keeps accruing interest. The inflated stamp also means `min(LTV, LT)` can remain nonzero if LT was cut but LTV was not zeroed in the same operation, letting the account keep borrowing against a de-listed asset. The eventual write-down lands on `clean_bad_debt`/supply-index write-down — i.e., all suppliers of the borrowed assets take the loss.

### Likelihood Explanation
Requires one governance-executed `EditAssetInSpoke` (or spoke deprecation) that zeroes or cuts the threshold — an explicitly supported, timelocked operation shown in ops configs and harness tests — plus a pre-existing borrower whose HF under the new parameters is below 1.05. For a removal-style edit (threshold 0) that second condition holds for *every* account with debt, so the stale stamp is guaranteed, not probabilistic. Because `update_account_threshold` is permissionless and liquidations never restamp, there is no recovery path once the state exists. Severity: High (theft-adjacent insolvency / permanent sheltering of bad debt), contingent on an admin action, consistent with the medium-severity E-Mode report.

### Recommendation
- In `refresh_supply_risk_params`/`apply_gated_liquidation_params`, bypass or weaken the 1.05 gate when the listing marks the asset non-collateralizable or sets `liquidation_threshold == 0`: an asset that is no longer collateral must always restamp, since "not liquidatable under new rules" cannot be grounds to keep it as collateral.
- In `calculate_account_risk_totals` and `calculate_ltv_collateral_wad`, consult the live listing (`cached_spoke_asset` / `is_collateralizable`) and weight a non-collateralizable or unlisted supply position at zero instead of trusting the stamp.
- In `sync_account_thresholds`/`restamp_listed_supply_ltv`, do not silently `continue` on missing listings — zero out the stamp so delisted assets stop contributing to HF.

### Proof of Concept
```text
1. ALICE supplies USDC (LTV 7500, LT 8000 stamps) and borrows ETH up to the
   borrow limit, as in poc_lt_cut_sticky_when_hf_below_min.
2. Governance executes a ready operation: EditAssetInSpoke(USDC,
   can_collateral=false, ltv=0, threshold=0) — e.g., oracle deprecation.
3. Any caller invokes update_account_threshold(true, [alice_id]), or anyone
   dust-tops ALICE's USDC (supply_to) or ALICE withdraws:
   - refresh_supply_risk_params sets loan_to_value = 0,
   - apply_gated_liquidation_params: favors_liquidator == true,
     debt_free == false, clears_min_hf with threshold 0 → HF = 0 < 1.05
     → early return; liquidation_threshold stamp stays 8000.
4. Repeat at any later time or after price moves: the same gate can never
   pass, so the stamp is permanent.
5. calculate_account_risk_totals still computes weighted_collateral using
   the 8000 stamp → ALICE's HF stays ≥ 1 → try_liquidate reverts, and her
   ETH debt accrues interest until the position is deep bad debt.
6. Protocol loss is absorbed via clean_bad_debt's supply-index write-down,
   paid by all USDC/ETH suppliers.
```

#[test]
fn poc_lt_cut_stays_sticky_when_hf_below_min() {
    let mut t = LendingTest::new().standard_two_asset_dust_disabled();

    t.supply(ALICE, "USDC", 10_000.0);
    t.borrow(ALICE, "ETH", 3.0);
    let id = t.resolve_account_id(ALICE);
    let (ltv_before, lt_before) = supply_ltv_and_lt(&t, id, "USDC");
    assert_eq!(lt_before, 8_000, "preset LT stamp");
    assert_eq!(ltv_before, 7_500, "preset LTV stamp");

    t.edit_asset_config("USDC", |c| {
        c.loan_to_value = 5_000;
        c.liquidation_threshold = 6_100;
    });

    t.update_account_threshold(true, &[id]);
    assert_eq!(
        supply_ltv_and_lt(&t, id, "USDC").1,
        8_000,
        "H-RISK-04: the keeper path holds the LT stamp under the HF floor too"
    );

    t.try_supply_to_account(BOB, ALICE, "USDC", 1.0)
        .expect("top-up must remain allowed");
    let (ltv_after, lt_after) = supply_ltv_and_lt(&t, id, "USDC");
    assert_eq!(
        ltv_after, 5_000,
        "H-RISK-03/04: LTV always restamps on supply refresh"
    );
    assert_eq!(
        lt_after, 8_000,
        "H-RISK-04: LT stamp must stay sticky when post-cut HF < 1.05"
    );

    assert!(
        !t.can_be_liquidated(ALICE),
        "sticky LT keeps HF ≥ 1 at original prices after listing cut"
    );
