Based on my investigation, the claim is substantively supported by the code, with one important nuance worth noting for the Vault handler but which does not invalidate the core finding for `confidentialrelay`.

Audit Report

## Title
Unauthenticated, unbounded `activeRequests` map growth in the Gateway's Confidential Relay handler enables remote memory-exhaustion DoS - ([File: core/services/gateway/handlers/confidentialrelay/handler.go])

## Summary
The Gateway's user-facing HTTP endpoint accepts JSON-RPC requests with no transport-layer authentication and routes them directly into `confidentialrelay.HandleJSONRPCUserMessage`, which performs only an ID length check before unconditionally inserting an entry into the unbounded `map[string]*activeRequest` via `newActiveRequest`. [1](#0-0) [2](#0-1)  Entries are only reclaimed by a 1-second periodic sweep expiring requests older than `requestTimeout` (default 30s), giving an attacker a rolling 30-second window to accumulate arbitrarily many entries limited only by their ability to generate unique IDs and send HTTP requests. [3](#0-2) [4](#0-3) 

## Finding Description
`gateway.ProcessRequest` reads the raw body (size-bounded only by `MaxRequestBytesLimiter`), decodes it, and dispatches directly to the resolved handler's `HandleJSONRPCUserMessage` — no session, API key, or allowlist check happens before this point. [5](#0-4)  For `confidentialrelay`, `HandleJSONRPCUserMessage` validates only that `req.ID` is non-empty and ≤200 characters, then calls `newActiveRequest`, which locks the handler mutex, checks for ID collision, and unconditionally inserts into `h.activeRequests` — there is no size cap, no rate limit gating admission, and no authentication check anywhere in this path. [6](#0-5)  The `globalNodeRateLimiter`/`perNodeRateLimiters` fields exist on the handler struct but (per my search of the file) are only referenced in node-response-handling code paths, not gating inbound user request admission before `newActiveRequest`. The map itself has no capacity bound at declaration. [7](#0-6)  The only reclamation mechanism is the ticker-driven `removeExpiredRequests`, run once per second, which only evicts entries whose age exceeds `requestTimeout` (default 30s) — a purely time-based sweep, not a size-based backpressure mechanism. [4](#0-3)  This is the same bug class the codebase's own `handlers/common/requestcache.go` explicitly guards against via `maxCacheSize` enforcement and rejection once full — a safeguard that was not applied here. [8](#0-7) 

Note on the Vault handler: unlike the claim's characterization, for `MethodSecretsCreate/Update/Delete/List` the Vault handler calls `h.requestProcessor.ProcessRequest` (which performs authorization via `AuthorizeRequest`) *before* `h.newActiveRequest` is ever invoked — an unauthorized request is rejected before any map entry is created. [9](#0-8)  Only `vaulttypes.MethodPublicKeyGet` creates an activeRequest without authorization, but this is gated by an aggressively-cached public key (default 300s cache duration) — so unbounded growth via this path is far more limited than the confidentialrelay path, since after the first cache population subsequent identical requests hit the cache short-circuit rather than creating new entries. [10](#0-9) 

## Impact Explanation
For `confidentialrelay`, the unauthenticated, unbounded, per-unique-ID map growth is real and directly reachable: any client that can reach the Gateway's user HTTP port can submit JSON-RPC requests with unique IDs (up to 200 chars) faster than the 1-second/30-second sweep can reclaim them, growing `h.activeRequests` without bound and driving heap growth toward OOM, which would crash the Gateway process and take down all DONs/services it fronts. This is a legitimate availability/DoS impact against an in-scope, internet-facing component.

## Likelihood Explanation
High for `confidentialrelay`: no authentication, allowlist, or per-caller/global rate limit gates admission into `newActiveRequest`; the attacker only needs to generate unique string IDs and issue HTTP POSTs, which is trivial to script at volume.

## Recommendation
Apply the bounded-cache discipline already implemented in `handlers/common/requestcache.go` to `confidentialrelay`'s `activeRequests` map: enforce a `maxActiveRequests` limit in `newActiveRequest`, rejecting new admissions once full, and/or require authentication or per-source rate limiting before an entry is created. Consider tightening the cleanup interval relative to `requestTimeout` or adopting size-aware eviction so admission is throttled proactively.

## Proof of Concept
1. Stand up a Gateway node with a configured Confidential Relay DON exposing the user HTTP port.
2. Script a flood of HTTP POST requests to the gateway's JSON-RPC endpoint, each with a fresh unique `id` and method `confidentialrelay.secrets_get` (or `capability_exec`), with no credentials.
3. Sustain submission at a rate exceeding the 1-second cleanup sweep's reclamation capacity for entries younger than the 30-second `requestTimeout`.
4. Observe the Gateway process's heap/RSS grow unbounded as `activeRequests` accumulates, eventually leading to OOM termination.

					h.removeExpiredRequests(ctx)

					return

func (h *handler) removeExpiredRequests(ctx context.Context) {
	h.mu.RLock()
	var expiredRequests []*activeRequest
	now := h.clock.Now()
	for _, userRequest := range h.activeRequests {
		if now.Sub(userRequest.createdAt) > h.requestTimeout {
			expiredRequests = append(expiredRequests, userRequest)
		}
	}

func (h *handler) HandleJSONRPCUserMessage(ctx context.Context, req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) error {
	if req.ID == "" {
		return errors.New("request ID cannot be empty")
	}
	if len(req.ID) > 200 {
		return errors.New("request ID is too long: " + strconv.Itoa(len(req.ID)) + ". max is 200 characters")
	}

	labels := h.extractRequestLabels(req)
	l := h.requestLogger(req, labels)
	l.Debugw("handling confidential relay request", "nodes", len(h.donConfig.Members), "f", h.donConfig.F)

	ar, err := h.newActiveRequest(req, labels, callback)
	if err != nil {
		return err
	}

	return h.fanOutToNodes(ctx, l, ar)
}

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], labels requestLabels, callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID, "executionID", labels.ExecutionID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}

func NewRequestCache[T any](timeout time.Duration, maxCacheSize uint32) RequestCache[T] {
	return &requestCache[T]{cache: make(map[globalID]*pendingRequest[T]), timeout: timeout, maxCacheSize: maxCacheSize}

func (c *requestCache[T]) NewRequest(lggr logger.Logger, request *api.Message, callback handlers.Callback, responseData *T) error {
	if request == nil {
		return errors.New("request is nil")
	}
	if responseData == nil {
		return errors.New("responseData is nil")
	}
	key := globalID{request.Body.Sender, request.Body.MessageID}
	c.mu.Lock()
	defer c.mu.Unlock()
	_, ok := c.cache[key]
	if ok {
		return errors.New("request already exists")
	}
	if len(c.cache) >= int(c.maxCacheSize) {
		return errors.New("request cache is full")
	}
