## Finding: CORS Origin Allowlist Wildcard Bypass via Missing Label Boundary Check

### Title
CORS wildcard-origin allowlist bypass due to unanchored suffix match - (File: core/services/gateway/network/httpserver.go)

### Summary
The gateway's HTTP server implements a private, hand-rolled wildcard matcher for `CORSAllowedOrigins` in `isAllowedOrigin`. Like the curl `x*` puny-code flaw in ALPINE-CVE-2023-28321, the check treats a wildcard pattern (`*.example.com`) as matching any origin whose hostname merely ends with the literal string `example.com`, without verifying that the preceding character is a `.` label separator. This lets an attacker register an unrelated domain (e.g. `notexample.com`) that satisfies the suffix check and gets treated as a trusted subdomain.

### Finding Description
`isAllowedOrigin` strips the `*.` prefix from a configured wildcard entry and then does a raw `strings.HasSuffix` comparison against the request's `Origin` header hostname: [1](#0-0) 

There is no check that `originHost[len(originHost)-len(allowedHost)-1] == '.'`. Consequently, for an allowed pattern like `*.ethereum.org`, an origin host such as `evilethereum.org` or `notethereum.org` also satisfies `strings.HasSuffix(originHost, "ethereum.org")` and is incorrectly treated as a legitimate `*.ethereum.org` subdomain — this is the exact bug class from the CVE: the wildcard boundary is not anchored to a domain-label separator, so an attacker-chosen string that merely shares a trailing substring bypasses the intended restriction.

This logic is invoked directly from the internet-facing request path, `handleRequest`, which reflects the caller-supplied `Origin` header back as `Access-Control-Allow-Origin` whenever `isAllowedOrigin` returns true: [2](#0-1) 

The existing test suite even documents the intended (safe) negative case — that an origin merely sharing a suffix without a dot boundary should be rejected — but only tests obviously non-matching strings, not adversarial ones crafted specifically to abuse the missing boundary check (e.g. `evilethereum.org` against `*.ethereum.org`): [3](#0-2) 

### Impact Explanation
Any operator who configures a wildcard CORS entry (e.g. `https://*.chain.link`) unintentionally grants a wide swath of unrelated attacker-registrable domains (any domain ending in `chain.link` as a raw string, such as `evilchain.link`) permission to have their `Origin` reflected in `Access-Control-Allow-Origin`. Because the gateway is unauthenticated at the CORS layer and reflects the origin directly, a malicious website hosted at such a domain can issue credentialed/browser-originated requests to the gateway's HTTP endpoint and have the browser permit reading the response cross-origin, defeating the purpose of the allowlist (`CORSAllowedOrigins`) that is meant to restrict which frontends may talk to the gateway. This is an allowlist bypass affecting the internet-facing gateway component.

### Likelihood Explanation
Exploitation requires: (1) the operator has configured at least one wildcard entry in `CORSAllowedOrigins`, and (2) the attacker registers/controls a domain whose hostname string ends with the same suffix (without the domain being an actual subdomain). Domain registration to satisfy an arbitrary suffix is generally feasible for attackers (domain names are largely attacker-choosable strings), making this practically exploitable wherever wildcard CORS entries are used.

### Recommendation
Anchor the wildcard suffix match to a label boundary, e.g.:
```go
if strings.HasPrefix(allowedHost, "*.") {
    suffix := allowedHost[1:] // keep the leading dot: ".example.com"
    if originHost == suffix[1:] || strings.HasSuffix(originHost, suffix) {
        return true
    }
}
```
This ensures `originHost` must either equal the base domain or end with `.` + base domain, closing the substring-suffix bypass.

### Proof of Concept
1. Configure the gateway with `CORSEnabled = true` and `CORSAllowedOrigins = ["https://*.ethereum.org"]`.
2. Send a request to the gateway's configured path with header `Origin: https://evilethereum.org`.
3. Observe that `isAllowedOrigin` returns `true` (since `strings.HasSuffix("evilethereum.org", "ethereum.org")` is `true`), and the response includes `Access-Control-Allow-Origin: https://evilethereum.org`, even though `evilethereum.org` is not a subdomain of `ethereum.org`.

func (s *httpServer) handleRequest(w http.ResponseWriter, r *http.Request) {
	if s.config.CORSEnabled {
		origin := r.Header.Get("Origin")
		if s.isAllowedOrigin(origin) {
			w.Header().Set("Access-Control-Allow-Origin", origin)
			w.Header().Set("Access-Control-Allow-Methods", "GET, POST, OPTIONS")
			w.Header().Set("Access-Control-Allow-Headers", "Content-Type")
		}

		// handle preflight requests
		if r.Method == http.MethodOptions {
			w.WriteHeader(http.StatusNoContent)

		}
	}
