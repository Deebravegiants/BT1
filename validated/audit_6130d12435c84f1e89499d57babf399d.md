### Title
Unauthenticated resource-exhaustion via unbounded per-owner rate-limiter tenant creation in Vault gateway request validation - ([File: core/capabilities/vault/validator.go])

### Summary
The TensorFlow advisory describes a memory leak where a validation failure path allocates a resource but skips the corresponding cleanup/limit check, letting an attacker repeatedly trigger the failing path to leak memory. The chainlink Vault gateway pipeline has a structurally analogous bug: per-owner scoped rate-limiter "tenants" — which the code's own comments say spawn **persistent background updater goroutines** — are instantiated during **pre-authentication** structural validation of `SecretsCreate`, `SecretsUpdate`, `SecretsDelete`, and `SecretsList` requests, using attacker-controlled `owner` strings, before any authorization check runs.

### Finding Description
`RequestValidator.ValidateSecretIdentifier` scopes several `BoundLimiter` checks to the caller-supplied `owner` string via `contexts.WithCRE(ctx, contexts.CRE{Owner: idOwner})`: [1](#0-0) [2](#0-1) 

The code's own documentation explicitly warns that this pattern creates unbounded resources when invoked before authentication — but that warning was only acted on for the ciphertext-size limiter, not the identifier-length limiters: [3](#0-2) [4](#0-3) 

Despite this, `ValidateSecretIdentifier` (which triggers the per-owner tenant registration) is still invoked by every pre-auth structural validator:
- `validateWriteRequest` (used by `ValidateEncryptedSecretsStructure`, called for `SecretsCreate`/`SecretsUpdate` **before** `authorizeAndStamp`): [5](#0-4) 
- `ValidateDeleteSecretsRequest`: [6](#0-5) 
- `ValidateListSecretIdentifiersRequest`: [7](#0-6) 

In the gateway pipeline, these validations run strictly before `authorizeAndStamp` (which calls `authorizer.AuthorizeRequest`): [8](#0-7) [9](#0-8) [10](#0-9) 

`GatewayHandler.HandleGatewayMessage` is the internet-facing entrypoint invoked for every inbound message from any gateway client, and it dispatches straight into `ProcessRequest` (i.e., into the pre-auth validators above) without any prior authentication of the sender: [11](#0-10) 

An unprivileged/unauthenticated actor able to send messages to the gateway (or any node reachable via the gateway connector) can therefore submit `SecretsCreate`, `SecretsUpdate`, `SecretsDelete`, or `SecretsList` requests containing many distinct, arbitrary (non-owned, non-existent) `owner` values. Each distinct owner value causes `MaxIdentifierOwnerLengthLimiter.Check` (and the namespace/key length limiters) to register a new scoped-limiter tenant with a persistent background updater — resources that, per the code's own comment, are never expected to be created pre-auth and are not bounded or cleaned up when the request is subsequently rejected by authorization.

### Impact Explanation
This mirrors CWE-20 (Improper Input Validation) from the reference advisory: a validation/pre-check code path allocates a persistent resource keyed off attacker-controlled input, and that resource is not released even though the overall request is ultimately rejected. Repeated exploitation (batches up to `vaultcommon`/`MaxBatchSize` items per request, across arbitrarily many requests and owner strings) leads to unbounded growth of limiter tenants and their background goroutines/updaters on the vault-capable node or gateway process — a memory/goroutine exhaustion (availability) issue reachable by any unprivileged, unauthenticated client of the gateway.

### Likelihood Explanation
High. No authentication or allowlist membership is required to reach the vulnerable code — `HandleGatewayMessage` processes the request and runs structural validation before `AuthorizeRequest` is ever called. An attacker only needs to be able to send JSON-RPC messages that reach the gateway/connector, which is the intended entrypoint for external node/gateway traffic in this subsystem.

### Recommendation
Defer the identifier-length limiter checks (owner/namespace/key) in `ValidateSecretIdentifier` until after authorization, the same way `ValidateCiphertextSizes` was deliberately split out and deferred in `gateway_vault_request_processor.go`. Alternatively, perform only stateless/non-tenant-creating length checks (e.g. plain `len()` comparisons against static config) pre-auth, and only invoke the actual scoped `BoundLimiter.Check` calls once the request's owner has been confirmed authorized.

### Proof of Concept
1. As an unauthenticated client, connect to the gateway and send a `SecretsList` (or `SecretsCreate`/`SecretsUpdate`/`SecretsDelete`) JSON-RPC request whose payload references a syntactically valid but arbitrary/unauthorized `owner` string, e.g. `owner-0001`.
2. `GatewayHandler.HandleGatewayMessage` routes the request to `requestProcessor.ProcessRequest`, which calls `ValidateListSecretIdentifiersRequest` → `ValidateSecretIdentifier`, registering a scoped limiter tenant for `owner-0001` and spawning its background updater — all before `AuthorizeRequest` is called.
3. The request is subsequently rejected at the authorization stage ("not allowlisted"), but the tenant/updater created in step 2 is not torn down.
4. Repeat with `owner-0002`, `owner-0003`, ... to accumulate unbounded limiter tenants/goroutines on the node/gateway process.

func (r *RequestValidator) ValidateSecretIdentifier(ctx context.Context, idKey, idOwner, idNamespace string) error {
	if idKey == "" {
		return errors.New("key cannot be empty")
	}
	if idOwner == "" {
		return errors.New("owner cannot be empty")
	}

	if !isValidIDComponent(idKey) || !isValidIDComponent(idOwner) || (idNamespace != "" && !isValidIDComponent(idNamespace)) {
		return errors.New("key, owner and namespace must only contain alphanumeric characters")
	}

	// TODO orgID https://smartcontract-it.atlassian.net/browse/CRE-1707
	ctx = contexts.WithCRE(ctx, contexts.CRE{Owner: idOwner})
	if err := r.MaxIdentifierOwnerLengthLimiter.Check(ctx, pkgconfig.Size(len(idOwner))); err != nil {
		if errBoundLimited, ok := errors.AsType[limits.ErrorBoundLimited[pkgconfig.Size]](err); ok {
			return fmt.Errorf("owner exceeds maximum length of %s: %w", errBoundLimited.Limit, err)
		}
		return fmt.Errorf("failed to check owner length limit: %w", err)
	}

	if err := r.MaxIdentifierNamespaceLengthLimiter.Check(ctx, pkgconfig.Size(len(idNamespace))); err != nil {
		if errBoundLimited, ok := errors.AsType[limits.ErrorBoundLimited[pkgconfig.Size]](err); ok {
			return fmt.Errorf("namespace exceeds maximum length of %s: %w", errBoundLimited.Limit, err)
		}
		return fmt.Errorf("failed to check namespace length limit: %w", err)
	}

	if err := r.MaxIdentifierKeyLengthLimiter.Check(ctx, pkgconfig.Size(len(idKey))); err != nil {
		if errBoundLimited, ok := errors.AsType[limits.ErrorBoundLimited[pkgconfig.Size]](err); ok {
			return fmt.Errorf("key exceeds maximum length of %s: %w", errBoundLimited.Limit, err)
		}
		return fmt.Errorf("failed to check key length limit: %w", err)
	}

	return nil
}

func (h *GatewayHandler) HandleGatewayMessage(ctx context.Context, gatewayID string, req *jsonrpc.Request[json.RawMessage]) (err error) {
	reqLggr := h.requestLogger(req, gatewayID)
	reqLggr.Debugw("received message from gateway", "req", req)

	var response *jsonrpc.Response[json.RawMessage]
	var authResult *AuthResult

	switch req.Method {
	case vaulttypes.MethodSecretsCreate, vaulttypes.MethodSecretsUpdate:
		publicKey, pkErr := h.getMasterPublicKey(ctx)
		if pkErr != nil {
			response = h.gatewayErrorResponse(ctx, gatewayID, req, pkErr)
			break
		}
		authorized, pipelineErr := h.requestProcessor.ProcessRequest(ctx, req, publicKey)
		if pipelineErr != nil {
			response = h.gatewayErrorResponse(ctx, gatewayID, req, pipelineErr)
			break
		}
		authResult = authorized.AuthResult
	case vaulttypes.MethodSecretsDelete, vaulttypes.MethodSecretsList:
		authorized, pipelineErr := h.requestProcessor.ProcessRequest(ctx, req, nil)
		if pipelineErr != nil {
			response = h.gatewayErrorResponse(ctx, gatewayID, req, pipelineErr)
			break
		}
		authResult = authorized.AuthResult
	case vaulttypes.MethodPublicKeyGet:
		response = h.handlePublicKeyGet(ctx, gatewayID, req)
	default:
		response = h.errorResponse(ctx, gatewayID, req, api.UnsupportedMethodError, errors.New("unsupported method: "+req.Method))
	}
