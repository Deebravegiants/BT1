### Title
Unauthenticated pipeline-run resume endpoint permits guessable-token job-run manipulation - (File: core/web/router.go, core/web/pipeline_runs_controller.go)

### Summary
The Sipeed NanoKVM CVE describes an endpoint reachable without authentication that lets an unauthenticated network attacker mutate saved state (Wi-Fi config) or send a crafted request that exhausts memory/terminates the process. In chainlink, `PATCH /v2/resume/:runID` is registered on an explicitly unauthenticated router group and accepts attacker-controlled JSON that is forwarded into the pipeline engine to complete a suspended task.

### Finding Description
In `v2Routes`, the `/resume/:runID` route is mounted on `unauthedv2 := r.Group("/v2")`, with no `auth.Authenticate(...)` middleware attached, unlike every other `/v2` route which is wrapped in `authv2` or `userOrEI` groups requiring session/token/EI credentials [1](#0-0) . The handler `PipelineRunsController.Resume` parses `runID` as a UUID, decodes an attacker-supplied JSON body into a `pipeline.ResumeRequest`, and calls `App.ResumeJobV2` directly — completing a suspended pipeline task with attacker-controlled result data, with no session, API token, or external-initiator check performed [2](#0-1) . The only "protection" is that `runID` is presumed to be an unguessable UUID (a bearer-token-like capability), but this route inherits only the generic authenticated rate limiter from the parent `api` group (1000 req/min by default) [3](#0-2) , rather than the stricter `Unauthenticated` limiter (5 req/20s) applied elsewhere to intentionally-unauthenticated endpoints such as `/sessions` [4](#0-3) . This mirrors the NanoKVM bug class: an unauthenticated, unprivileged actor can hit a state-mutating endpoint with a crafted request, relying only on weak/implicit protections (UUID secrecy + a generous rate limit) rather than actual authentication.

### Impact Explanation
If a `runID` UUID is leaked (logs, error messages, URLs, browser history, referer headers, timing side-channels, or brute force at up to 1000 req/min), an unauthenticated attacker can complete/resume a job run with attacker-chosen result payload, corrupting pipeline execution state or triggering downstream task logic (e.g., HTTP task branching, VRF/OCR task completion paths) without any credential. This matches the "unauthorized job run" impact category referenced in the report.

### Likelihood Explanation
This requires the attacker to know or guess a valid, currently-pending `runID` (a v4 UUID), which is a significant practical barrier — this differs materially from the NanoKVM issue where no secret was needed at all. Likelihood is therefore lower than the original CVE and depends entirely on UUID leakage or brute-forcing at the endpoint's rate limit.

### Recommendation
- Bind the `/resume/:runID` route to the same strict `Unauthenticated` rate limiter used for `/sessions` rather than the generic authenticated limiter, to reduce brute-force feasibility.
- Consider requiring an additional secret/HMAC token tied to the run (not solely the UUID) for resume, or scoping resume authorization to the external initiator/service that owns the suspended task.
- Audit-log rate/anomaly detection on `audit.UnauthedRunResumed` events for repeated failed/successful resume attempts.

### Proof of Concept
```
PATCH /v2/resume/<guessed-or-leaked-run-uuid> HTTP/1.1
Host: <chainlink-node>
Content-Type: application/json
(no Authorization/session cookie)

{"error": "attacker controlled"}
```
No authentication headers are required; if the UUID is valid and the run is pending, `PipelineRunsController.Resume` [5](#0-4)  will call `App.ResumeJobV2` with the attacker-supplied result, and respond `200 OK`.

**Note on confidence**: I was unable to fully trace `ResumeJobV2`'s downstream implementation (`core/services/chainlink/application.go`) within the available tool budget to confirm exactly what state mutation or resource consumption occurs on resume, so the severity of the resulting impact (beyond "unauthorized job run completion") is not fully verified.

```go
// Resume finishes a task and resumes the pipeline run.
// Example:
// "PATCH <application>/jobs/:ID/runs/:runID"
func (prc *PipelineRunsController) Resume(c *gin.Context) {
	taskID, err := uuid.Parse(c.Param("runID"))
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	rr := pipeline.ResumeRequest{}
	decoder := json.NewDecoder(c.Request.Body)
	err = errors.Wrap(decoder.Decode(&rr), "failed to unmarshal JSON body")
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	result, err := rr.ToResult()
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	if err := prc.App.ResumeJobV2(c.Request.Context(), taskID, result); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
	c.Status(http.StatusOK)
```
