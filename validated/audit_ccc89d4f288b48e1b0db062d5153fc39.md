### Title
Accrued market totals overflow `i128` before index clamp, permanently freezing a borrowed market - (File: common/src/rates/simulate.rs)

### Summary
The interest-accrual path recomputes total borrowed and supplied RAY values before applying the borrow-index ceiling. Once `borrowed * borrow_index / RAY` exceeds `i128::MAX`, `scaled_to_original` panics with `MathOverflow`, and because every market operation performs accrual first, repayment, withdrawal, liquidation, index updates, and parameter recovery for that market all become unusable. [1](#0-0) [2](#0-1) 

### Finding Description
`accrue_step` unconditionally computes `borrowed_original` and `supplied_original` through `scaled_to_original` before deriving utilization, compounding interest, or updating either index. [3](#0-2)  `scaled_to_original` calls `Ray::mul`, and `Ray::mul` uses checked fixed-point multiplication that panics with `MathOverflow` on an `i128` overflow. [4](#0-3) [5](#0-4) 

The borrow-index ceiling is applied only inside `update_borrow_index`, after those total-value multiplications have already run. [6](#0-5)  Consequently, a market whose debt shares are large enough can cross the representable RAY-value boundary while its index remains below `MAX_BORROW_INDEX_RAY`; the checked multiplication traps before the intended index clamp can stop growth. [7](#0-6) [8](#0-7) 

Every pool mutation reaches `ops::synced_market` or `ops::load_leg`, both of which execute `interest::global_sync` before the operation-specific accounting. [9](#0-8)  `global_sync` invokes `accrue_step` for each elapsed chunk, so the same overflow is hit by `borrow`, `withdraw`, `repay`, liquidation withdrawals, revenue operations, and the standalone `update_indexes` maintenance path. [10](#0-9) [11](#0-10) 

An unprivileged attacker can create the prerequisite state using ordinary controller calls: `supply(caller, account_id, spoke_id, [(liquidity_asset, amount)])` provides market liquidity, `supply(caller, collateral_account_id, spoke_id, [(collateral_asset, collateral_amount)])` establishes collateral, and `borrow(caller, collateral_account_id, [(liquidity_asset, borrowed_amount)], Some(caller))` leaves utilization high. [12](#0-11)  After enough ledger time at high utilization, anyone can trigger the permanent failure through `update_indexes(caller, [liquidity_asset])`; subsequent `repay`, `withdraw`, or `liquidate` calls fail during their mandatory accrual stage. [13](#0-12) [14](#0-13) 

### Impact Explanation
This permanently freezes all funds and debt operations in the affected `(hub_id, asset)` market. Suppliers cannot withdraw pool cash, borrowers cannot repay, liquidators cannot de-risk the market, and governance cannot replace the interest-rate model through `update_params` because that path also accrues under the old model first. [15](#0-14) [16](#0-15)  The in-repository stress test demonstrates this exact end state: the index remains below its cap while `update_indexes`, `withdraw`, and `repay` all revert with `MathOverflow`. [17](#0-16) 

### Likelihood Explanation
Likelihood is constrained by the need for a very large market position and sustained high utilization. A single funded address can create it without privileged access, but only on a market whose configured caps and collateral configuration admit sufficient size; the repository’s proof uses an 18-decimal market, roughly one billion whole debt tokens, 98% utilization, and a steep 175%-maximum rate curve. [18](#0-17)  Once such a position exists, ordinary elapsed time—not an additional privileged action—drives the market to the cliff, and the index ceiling does not prevent it because the value multiplication overflows first. [19](#0-18) [20](#0-19) 

### Recommendation
Bound the representable debt value before multiplying by the index in `accrue_step`; for example, compute the post-growth debt value with a checked intermediate and clamp utilization or accrual when it reaches the RAY-value domain instead of panicking. Enforce a stricter market-level scaled-debt/value ceiling during borrow and cap admission so `borrowed * MAX_BORROW_INDEX_RAY / RAY` cannot exceed `i128::MAX`. Add regression coverage based on the existing whale-market test, and provide a tested recovery path that can lower or replace the rate model without first executing the overflowing accrual calculation. [21](#0-20) [22](#0-21) [17](#0-16)

pub fn accrue_step(

    params: &MarketParams,
    borrowed: Ray,
    supplied: Ray,
    borrow_index: Ray,
    supply_index: Ray,
    delta_ms: u64,

    let supplied_original = scaled_to_original(env, supplied, supply_index);

        calculate_supplier_rewards(env, params, borrowed, new_borrow_index, borrow_index);

/// Applies `interest_factor` to `old_index` to produce the new borrow index,
/// capped at `MAX_BORROW_INDEX_RAY`.
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}

    t.supply_raw(BOB, "BIG18", principal);

    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
