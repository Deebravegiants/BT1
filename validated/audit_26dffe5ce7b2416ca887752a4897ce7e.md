Audit Report

## Title
Missing EVM memory-expansion gas charge allows near-free 1MB memory allocation per call in `Memory::<T>::resize` - (File: substrate/frame/revive/src/vm/evm/memory.rs)

## Summary
`Memory::<T>::resize` in `substrate/frame/revive/src/vm/evm/memory.rs` only enforces the hard `EVM_MEMORY_BYTES` (1MB) cap before performing `self.data.resize(target_len, 0)`, with no incremental gas/weight surcharge tied to the size of the expansion. The opcode handlers that trigger this resize (`mload`, `mstore`, `mstore8`, `mcopy`, and the generic `resize_memory`/`memory_resize` helpers used by `CALL`-family and `CALLDATACOPY`/`RETURNDATACOPY`) charge only fixed, size-independent costs, so a single `MSTORE` near the 1MB boundary forces an allocation/zero-fill far larger than what its EVM-gas cost or benchmarked weight represents.

## Finding Description
`Memory::<T>::resize` computes `target_len` and rejects only if it exceeds `EVM_MEMORY_BYTES`, then unconditionally calls `self.data.resize(target_len, 0)`: [1](#0-0) . The 1MB cap is defined as `EVM_MEMORY_BYTES` [2](#0-1) .

`mload`/`mstore` charge only `EVMGas(VERYLOW)` (a fixed cost) before calling `resize`: [3](#0-2) . `mstore8` behaves the same way: [4](#0-3) . `mcopy`'s gas cost is a function only of the copied length (`copy_cost_verylow(len)`), not of the resulting memory footprint `max(dst, src) + len`: [5](#0-4) . The generic `resize_memory`/`memory_resize` helpers used by `CALL`/`CALLDATACOPY`/`RETURNDATACOPY` similarly charge fixed per-byte-copied costs without any expansion surcharge tied to memory size: [6](#0-5) [7](#0-6) .

Critically, the EVM gas that is charged is itself converted to a `Weight` via a fixed per-gas-unit rate benchmarked from `T::WeightInfo::evm_opcode`: `EVMGas::weight()` = `(evm_opcode(1) - evm_opcode(0)) * gas` [8](#0-7) . The `evm_opcode` benchmark itself only exercises no-op (`JUMPDEST`-like) instructions and never performs any memory resize/allocation: [9](#0-8) . This confirms that neither the EVM-gas layer nor the underlying Substrate `Weight` layer accounts for the cost of `Memory::resize`'s allocation and zero-fill — the benchmark that calibrates gas-to-weight conversion does not include memory expansion at all. No `MemoryExpansion`/`memory_gas_cost`-equivalent quadratic or size-proportional charge exists anywhere in the `substrate/frame/revive/src/vm/evm` tree.

## Impact Explanation
Because the charged gas/weight for `MLOAD`/`MSTORE`/`MSTORE8`/`MCOPY` is a small fixed constant regardless of the offset, an attacker can trigger up to ~1MB of allocation and zero-fill in `Memory::<T>::resize` for a cost of only a few EVM gas units (3 for `VERYLOW`), and since each fresh call starts with only 4KB pre-allocated (`Memory::new`) [10](#0-9) , this cost is paid again on every new call/transaction. This breaks the metering invariant that gas/weight charged should be proportional to actual computational work performed, and can be repeated across many transactions in a block to inflate real block-production time/memory churn disproportionately to the weight collected. The damage per call is bounded by the 1MB hard cap, limiting severity to a performance/griefing issue rather than unbounded memory exhaustion.

## Likelihood Explanation
This is trivially reachable by any unprivileged account via a normal signed EVM `bare_call` executing a contract with a single `MSTORE`/`MLOAD` at a high offset. No special privileges, races, or victim mistakes are required, and it is fully repeatable across transactions within a block.

## Recommendation
Implement a memory-expansion gas/weight charge inside or immediately before `Memory::<T>::resize`, tracking the previous memory-size-in-words and charging the incremental cost (standard EVM quadratic formula `memory_size_word^2/512 + 3*memory_size_word`, or an equivalent weight-based charge scaled to the actual allocation/zero-fill cost) before performing `self.data.resize(...)`, returning `OutOfGas` if the caller cannot cover it. Ensure `mcopy` and the generic `resize_memory`/`memory_resize` helpers charge based on the resulting memory footprint, not just the bytes copied. Additionally, recalibrate the `evm_opcode`/`EVMGas` weight conversion or add a dedicated benchmark that captures the cost of memory resizing so the Substrate `Weight` accounting reflects real allocation cost.

## Proof of Concept
1. Deploy a minimal EVM bytecode contract that executes a single `PUSH... MSTORE` with `offset = EVM_MEMORY_BYTES - 32` (just under the 1MB cap), similar to the existing `expandMemory` helper in `substrate/frame/revive/fixtures/contracts/Memory.sol`.
2. Call it via `Pallet::<T>::bare_call` as a normal signed account; record the EVM gas charged (≈`VERYLOW` = 3) and the actual `Weight`/wall-clock time consumed.
3. Repeat with `offset = 32` for comparison; observe the `weight_consumed / gas_charged` ratio is effectively identical between the two cases despite one causing ~1MB of allocation/zero-fill and the other essentially none, showing weight is not proportional to actual work.
4. Repeat step 2 in a loop simulating many transactions in one block to demonstrate cumulative allocation/zero-fill cost inflation relative to metered weight.

	pub fn resize(&mut self, offset: usize, len: usize) -> ControlFlow<Halt> {
		let current_len = self.data.len();
		let target_len = revm::interpreter::num_words(offset.saturating_add(len)) * 32;
		if target_len > crate::limits::EVM_MEMORY_BYTES as usize {

		if target_len > current_len {
			self.data.resize(target_len, 0);
		}

		ControlFlow::Continue(())
	}

pub fn mcopy<E: Ext>(interpreter: &mut Interpreter<E>) -> ControlFlow<Halt> {
	let [dst, src, len] = interpreter.stack.popn()?;

	// Into usize or fail
	let len = as_usize_or_halt::<E::T>(len)?;
	// Deduce gas
	let Some(gas_cost) = copy_cost_verylow(len) else {
		return ControlFlow::Break(Error::<E::T>::OutOfGas.into());
	};
	interpreter.ext.charge_or_halt(EVMGas(gas_cost))?;
	if len == 0 {
		return ControlFlow::Continue(());
	}

	let dst = as_usize_or_halt::<E::T>(dst)?;
	let src = as_usize_or_halt::<E::T>(src)?;
	// Resize memory
	interpreter.memory.resize(max(dst, src), len)?;
	// Copy memory in place
	interpreter.memory.copy(dst, src, len);
	ControlFlow::Continue(())
}

	interpreter: &mut Interpreter<'a, E>,
	memory_offset: U256,
	len: usize,
) -> ControlFlow<Halt, Option<usize>> {
	if len == 0 {
		return ControlFlow::Continue(None);
	}

	interpreter.ext.charge_or_halt(RuntimeCosts::CopyToContract(len as u32))?;
	let memory_offset = as_usize_or_halt::<E::T>(memory_offset)?;
	interpreter.memory.resize(memory_offset, len)?;
	ControlFlow::Continue(Some(memory_offset))
}

/// Cost  for a single unit of EVM gas.
#[derive(Eq, PartialEq, Debug, Clone, Copy)]
pub struct EVMGas(pub u64);

impl<T: Config> Token<T> for EVMGas {
	fn weight(&self) -> Weight {
		let base_cost = T::WeightInfo::evm_opcode(1).saturating_sub(T::WeightInfo::evm_opcode(0));
		base_cost.saturating_mul(self.0)
	}
}
