### Title
Unchecked RAY debt-value growth during interest accrual permanently freezes a high-utilization market - (File: common/src/rates/scaling.rs)

### Summary

An attacker can open an extremely large borrow position in a market whose configured caps permit it, sustain high utilization, and let the borrow index grow until unscaling total debt overflows `i128`. Every subsequent state-changing pool operation accrues interest first, so repayment, withdrawal, liquidation, parameter updates, and cleanup all revert with `MathOverflow`, permanently freezing the market. [1](#0-0) 

### Finding Description

`Cache::calculate_utilization` converts total scaled debt back to its original value through `scaled_to_original` using the accrued borrow index. [2](#0-1)  Interest accrual is executed before market mutations by `global_sync`, which compounds the market index in bounded chunks and then records the market as accrued. [3](#0-2) 

The accrual/index ceiling does not bound the resulting debt value: at sufficient principal and utilization, `borrowed_scaled * borrow_index` can overflow before `MAX_BORROW_INDEX_RAY` is reached. [4](#0-3)  Once this condition exists, the same overflow recurs during every later accrual, including repayments and withdrawals, so there is no unprivileged recovery path. [5](#0-4) 

### Impact Explanation

This causes a permanent denial of service for the affected market: suppliers cannot withdraw, borrowers cannot repay or be liquidated, and governance operations that first accrue the market also revert. [6](#0-5)  Supplier funds and borrower collateral associated with the frozen market remain inaccessible, satisfying permanent freezing of funds. [5](#0-4) 

### Likelihood Explanation

Likelihood is constrained by the need for an exceptionally large market position, borrow capacity, collateral, and a long period at high utilization. [7](#0-6)  No privileged action is required after governance has configured caps and risk parameters that admit the position; the attacker only needs `supply`, `borrow`, and later `update_indexes` or another market-touching entrypoint. [8](#0-7) 

### Recommendation

Bound the *unscaled value*, not only the borrow index: before committing a new index, check `borrowed_scaled * proposed_index` and `supplied_scaled * proposed_index` in the same decimal domain used by `scaled_to_original`. [9](#0-8)  If the result would exceed `i128::MAX`, clamp accrual or reject the additional exposure before the market enters an unrecoverable state, and include regression coverage matching the existing overflow scenario. [10](#0-9) 

### Proof of Concept

1. The attacker supplies approximately `10^28` base units of an 18-decimal debt asset to create deep liquidity. [11](#0-10) 
2. The same attacker supplies sufficient collateral and calls `borrow(caller, account_id, [(debt_hub_asset, debt)], None)` for about 98% of that liquidity. [12](#0-11) 
3. After sustained high-utilization accrual, the attacker calls `update_indexes` for the debt market; accrual reaches the `i128` value ceiling and returns `MathOverflow` before the index cap engages. [13](#0-12) 
4. Subsequent `withdraw` and `repay` calls revert with the same error because both load and accrue the market before mutating it. [5](#0-4)

/// Accrues borrow/supply indexes from `last_timestamp` to the cache's current time.
///
/// No-op when no time has elapsed. Splits long gaps into max-sized compound
/// windows, then sets `last_timestamp` to `current_timestamp`.
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
