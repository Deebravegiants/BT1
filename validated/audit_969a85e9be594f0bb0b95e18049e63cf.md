### Title
Unsigned GRANDPA consensus messages carry no bound on `unknown_headers`/`votes_ancestries`, so weight is fixed while verification cost is attacker-controlled - (File: modules/consensus/grandpa/primitives/src/justification.rs)

### Summary
`pallet_ismp::handle_unsigned` accepts free (`Pays::No` by default, `ensure_none` origin), unsigned `Message::Consensus` submissions and dispatches them to `verify_grandpa_finality_proof`, which walks attacker-supplied `unknown_headers` and `votes_ancestries` with no upper bound on their length. The extrinsic's declared weight is a fixed constant (`Weight::from_parts(300_000_000, 0)`), independent of the number of headers/precommits actually processed, so a relayer can submit a single unsigned extrinsic whose real execution cost vastly exceeds its accounted weight.

### Finding Description
`pallet_ismp::Pallet::handle_unsigned` is declared with a static weight function that ignores message content: [1](#0-0) [2](#0-1) 

It is also validated and admitted as an unsigned, fee-free transaction via `ValidateUnsigned::validate_unsigned`, which itself calls `Self::execute(messages.clone())` (i.e. fully executes/verifies the batch) just to compute the `provides`/`priority` tags — meaning the expensive verification runs once in the transaction pool (at `validate_unsigned` time, for every peer that receives the gossiped transaction) and again at block execution: [3](#0-2) 

For GRANDPA consensus messages, the ISMP GRANDPA consensus client decodes a `FinalityProof` and calls `verify_grandpa_finality_proof`, which:
1. Builds a `BTreeMap` from the entire `unknown_headers` vector,
2. For every precommit in the justification's `commit.precommits`, walks parent links across the `AncestryChain` to compute a route from the base hash to the precommit's target hash,
3. Additionally cross-checks the walked ancestry set against `votes_ancestries`. [4](#0-3) [5](#0-4) [6](#0-5) 

None of `GrandpaJustification` (`round`, `commit.precommits`, `votes_ancestries`) nor `FinalityProof.unknown_headers` are bounded (`BoundedVec`, `MaxEncodedLen`, or an explicit length check) anywhere in `modules/consensus/grandpa/primitives/src/justification.rs` or `modules/ismp/clients/grandpa/src/consensus.rs`; a search across the GRANDPA consensus module found no `MAX_HEADERS`/`BoundedVec`/length-guard constants. The number of precommits and ancestor headers a caller can supply is limited only by the outer block/extrinsic byte-length limit (typically a few MB in a Substrate runtime), which for compact SCALE-encoded headers/precommits can still translate into many thousands of entries — each triggering an `O(chain length)` parent-hash walk (`AncestryChain::ancestry`, `justification.rs:180-197`) and signature verification (`check_message_signature`). The combined cost is effectively `O(headers × chain-depth)` in the worst case, entirely uncapped by the extrinsic's declared/accounted weight.

Because `handle_unsigned` requires no signature and by default incurs `Pays::No` (see `WeightFeeHandler::on_executed`, which under the common `POLICY = false` configuration always returns `Pays::No` regardless of actual weight consumed): [7](#0-6) 

an attacker pays nothing to submit oversized GRANDPA consensus proofs, and the fixed weight declared on `handle_unsigned` means block-authoring nodes will under-account the actual CPU time these proofs consume, both while gossiping/validating in the pool (`validate_unsigned` fully executes the message) and during block execution.

### Impact Explanation
This is directly analogous to the reported Synapse bug class: an unprivileged, no-cost message (server ACL event / here, an unsigned consensus message) whose acceptance criteria don't bound its processing cost, causing a denial-of-service that can degrade block production or transaction-pool validation performance for the chain running `pallet-ismp` with the GRANDPA consensus client (e.g. the Hyperbridge/Nexus parachain or standalone chains bridging via GRANDPA). Sustained submission of maximally-sized proofs can cause block-time overruns or transaction-pool congestion, a temporary-to-persistent denial of service for the message-passing route, satisfying "a route unable to deliver messages" under the validation criteria.

### Likelihood Explanation
Reachable by any unprivileged actor: `handle_unsigned` requires only `ensure_none` origin (no signature, no fee) and accepts arbitrary `Message::Consensus` payloads up to the runtime's extrinsic/block length limits. Constructing an oversized-but-otherwise-valid-looking `GrandpaJustification`/`FinalityProof` requires no cryptographic break — only padding `unknown_headers` with a long (but real or crafted) ancestor chain and stuffing many precommits/ancestries; actual full validity is not required to make `validate_unsigned` do the expensive computation (verification only fails afterward, but the CPU has already been spent by then).

### Recommendation
- Add explicit `BoundedVec`/length caps to `GrandpaJustification.commit.precommits`, `votes_ancestries`, and `FinalityProof.unknown_headers` (e.g. capped to a small multiple of the largest realistic epoch/session length), rejecting oversized proofs before any verification work is performed.
- Make `handle_unsigned`'s declared weight scale with the actual message size/content (e.g., number of headers, precommits) rather than a fixed constant, so block weight accounting reflects real cost.
- Avoid fully executing (`Self::execute`) unsigned messages inside `validate_unsigned` for cheap tagging purposes — perform a cheap size/shape pre-check first and only do full verification once during block execution/import, or cache/memoize the result so it isn't computed twice.

### Proof of Concept
1. An attacker crafts a `Message::Consensus` for the GRANDPA `ConsensusStateId`, wrapping a `FinalityProof` whose `unknown_headers` contains the maximum number of headers that fits within the extrinsic size limit (thousands of headers, chained as parent/child) and whose `commit.precommits` similarly contains the maximum number of (possibly duplicate-target) precommits permitted by extrinsic size, plus a matching `votes_ancestries` set forcing `AncestryChain::ancestry` to walk long chains for each precommit.
2. Submit this as an unsigned extrinsic via `pallet_ismp::handle_unsigned` (`RuntimeCall::Ismp(pallet_ismp::Call::handle_unsigned { messages: vec![Message::Consensus(...)] })`).
3. Because `ValidateUnsigned::validate_unsigned` calls `Self::execute(messages.clone())`, every node that receives this transaction over gossip performs the full `verify_grandpa_finality_proof` computation (BTreeMap construction over all headers + per-precommit ancestry walk) before the transaction is even included in a block, and the fixed `weight()` (300M ref-time regardless of content) means this cost is never priced into the extrinsic — no fee is paid (`Pays::No`) and no weight limit rejects it up front.
4. Repeating step 2 with many such transactions (still free and validated by every peer) degrades transaction-pool validation throughput and/or block execution time for nodes running the GRANDPA consensus client, producing a denial-of-service on the message-relay path for that route.

pub fn verify_grandpa_finality_proof<H>(
	mut consensus_state: ConsensusState,
	finality_proof: FinalityProof<H>,
) -> Result<(ConsensusState, H, Vec<H256>, AncestryChain<H>), Error>
where
	H: Header<Hash = H256, Number = u32>,
	H::Number: finality_grandpa::BlockNumberOps + Into<u32>,
{
	// First validate unknown headers.
	let headers = AncestryChain::<H>::new(&finality_proof.unknown_headers);

	let target = finality_proof
		.unknown_headers
		.iter()
		.max_by_key(|h| *h.number())
		.ok_or(Error::UnknownHeadersEmpty)?;

	// this is illegal
	if target.hash() != finality_proof.block {
		Err(Error::LatestBlockMismatch)?;
	}

	let justification =
		GrandpaJustification::<H>::decode_all(&mut &finality_proof.justification[..])
			.map_err(|e| Error::DecodeJustification(alloc::format!("{e:?}")))?;

	if justification.commit.target_hash != finality_proof.block {
		Err(Error::JustificationTargetMismatch)?;
	}

	let from = consensus_state.latest_hash;

	let base = finality_proof
		.unknown_headers
		.iter()
		.min_by_key(|h| *h.number())
		.ok_or(Error::UnknownHeadersEmpty)?;

	if base.number() < &consensus_state.latest_height {
		headers
			.ancestry(base.hash(), consensus_state.latest_hash)
			.map_err(|_| Error::InvalidAncestry)?;
	}

	let finalized = headers.ancestry(from, target.hash()).map_err(|_| Error::InvalidAncestry)?;

	fn ancestry(
		&self,
		base: H::Hash,
		block: H::Hash,
	) -> Result<Vec<H::Hash>, finality_grandpa::Error> {
		let mut route = vec![block];
		let mut current_hash = block;
		while current_hash != base {
			match self.ancestry.get(&current_hash) {
				Some(current_header) => {
					current_hash = *current_header.parent_hash();
					route.push(current_hash);
				},
				_ => return Err(finality_grandpa::Error::NotDescendent),
			};
		}
		Ok(route)
	}
