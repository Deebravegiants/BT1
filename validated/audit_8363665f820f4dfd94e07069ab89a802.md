### Title
Unhandled Chainlink oracle revert freezes all ERC-20-sponsored UserOps in `SimplexPaymaster` - (File: evm/src/utils/SimplexPaymaster.sol)

### Summary
`SimplexPaymaster._getOraclePrice` fetches Chainlink data via a bare `oracle.latestRoundData()` call with no try/catch. Any unprivileged user submitting an ERC-20-sponsored `UserOperation` (mode `0x00` permit or mode `0x02` Permit2) triggers this call through `_fetchDetails` → `_tokenPrice` → `_getOraclePrice` during `_validatePaymasterUserOp`. If the underlying Chainlink aggregator reverts (e.g., feed paused/deprecated, access-controlled multisig-only feed, or the aggregator contract goes offline/self-destructs), the call bubbles up and the entire paymaster validation reverts, exactly mirroring the referenced VMEX finding where an un-caught `oracle.getAssetPrice()` call froze liquidations. [1](#0-0) 

### Finding Description
`_getOraclePrice` is the sole price-fetch primitive used for both the native/USD and token/USD Chainlink feeds: [1](#0-0) 

It is invoked unconditionally from `_tokenPrice`: [2](#0-1) 

`_tokenPrice` in turn is called from `_fetchDetails`, which the base `PaymasterERC20` contract calls during every `_validatePaymasterUserOp` for ERC-20-sponsored ops: [3](#0-2) 

There is no try/catch around either `nativeOracle.latestRoundData()` or `cfg.tokenOracle.latestRoundData()`. If either Chainlink aggregator reverts on the call (which happens if the feed is deprecated/paused by the operator, or the aggregator proxy points to a contract that reverts), `_getOraclePrice` reverts, which reverts `_tokenPrice`, which reverts `_fetchDetails`, which reverts `_validatePaymasterUserOp` for **every** UserOp using that token. The same unguarded call is also on the path of `swapAndDeposit` (fee recycling) and the public view helpers `getTokenPrice`/`estimateTokenCost`: [4](#0-3) 

Since ERC-4337 bundlers call `validatePaymasterUserOp` (which invokes `_fetchDetails`) as part of simulating/including any UserOp that uses this paymaster, an oracle outage for a single registered token freezes gas sponsorship for that token entirely — no unprivileged relayer, solver, or user can push a UserOp through until governance re-registers a working oracle via `RegisterToken`.

### Impact Explanation
This is a Medium-severity denial-of-service: during a Chainlink outage/pause, every account attempting to pay gas via the affected ERC-20 token through this paymaster is blocked, and the fee-recycling `swapAndDeposit` path also breaks. Unlike liquidations under insolvency risk, no direct fund loss occurs, but sponsored transactions are frozen for as long as the oracle is unavailable, and the only recovery path is a governance `UpdateParams`/`RegisterToken` action delivered cross-chain through Hyperbridge, which is not instantaneous.

### Likelihood Explanation
Likelihood is low-to-moderate: it requires a genuine Chainlink aggregator failure/pause (as opposed to staleness, which is already explicitly handled via `maxOracleAge`). Chainlink feeds have occasionally been deprecated or paused by node operators without warning, and any contract behind the feed reverting (rather than just returning stale data) triggers this exact path.

### Recommendation
Wrap the `oracle.latestRoundData()` call in `_getOraclePrice` in a try/catch, and on failure either (a) fall back to a secondary price source, (b) fail gracefully by disabling that specific token (mirroring `_deactivateToken`) rather than reverting all paymaster validation, or (c) allow permissionless deactivation of a token whose oracle reverts so other tokens/native flows remain usable.

### Proof of Concept
1. Governance registers token `T` with Chainlink oracle `O` via `RegisterToken`.
2. Chainlink pauses/deprecates `O`'s underlying aggregator so `O.latestRoundData()` reverts (e.g., access-controlled aggregator, or aggregator self-destructed/replaced).
3. Any user submits a UserOperation with `paymasterData` mode `0x00` or `0x02` referencing token `T`.
4. The EntryPoint calls `validatePaymasterUserOp` → `_fetchDetails` → `_tokenPrice(cfg)` → `_getOraclePrice(cfg.tokenOracle, ...)`.
5. `oracle.latestRoundData()` reverts inside `_getOraclePrice` (no try/catch present, see lines 662-668), the revert propagates through `_tokenPrice`/`_fetchDetails`/`_validatePaymasterUserOp`, and the UserOp cannot be included by any bundler until governance repairs the token's oracle configuration.

    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
