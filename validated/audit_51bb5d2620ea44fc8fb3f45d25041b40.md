Audit Report

## Title
`EngineMeter::charge_ref_time` never actually decrements engine fuel, letting contracts execute host-call-equivalent extra WASM instructions for free - (File: substrate/frame/contracts/src/gas.rs)

## Summary
`EngineMeter::charge_ref_time` computes `self.fuel.checked_sub(amount)` to validate that ref_time charged by a host call doesn't exceed the tracked fuel, but discards the `Some(value)` payload instead of writing it back to `self.fuel`. This confirmed by direct inspection of the code: [1](#0-0)  As a result, the fuel value returned to the wasmi executor via `Syncable` (and ultimately used as the engine's new remaining-fuel budget) is the pre-charge, un-decremented value rather than the correctly reduced one.

## Finding Description
`charge_ref_time` is invoked from `GasMeter::sync_to_executor`, which is called every time a host function returns, to fold the ref_time cost charged by the host function (via `GasMeter::charge`) back into the wasmi engine's fuel counter: [2](#0-1)  Within `charge_ref_time`, the amount to subtract is computed from `ref_time`, and `self.fuel.checked_sub(amount)` is called purely for its `Option`-driven error-detection side effect via `.ok_or_else(...)?` — the `Some(value)` result is dropped and `self.fuel` is never reassigned, unlike the analogous `set_fuel` function used by `sync_from_executor`, which does correctly perform `self.fuel = fuel`: [3](#0-2)  Because `Syncable(self.fuel)` returns the unchanged fuel value, the caller that consumes this value to reset the wasmi engine's remaining fuel effectively restores the engine to a pre-host-call fuel level, granting a "refund" every time a host call is charged. This lets the wasm interpreter execute additional real instructions using fuel that should have been consumed by the host call's own ref_time weight.

The existing checks (the `checked_sub`/`ok_or_else` underflow guard) only detect underflow — they do nothing to actually apply the decrement, so they are insufficient to prevent the accounting bug. The parallel, correctly-implemented `set_fuel` function demonstrates that the intended behavior was to reassign `self.fuel`, confirming this is a genuine missing-assignment bug rather than intended behavior.

## Impact Explanation
This is a real gas/weight-metering integrity bug: it allows the wasmi engine to be granted extra fuel (bonus WASM instruction budget) on every host-function call, letting a contract execute more real computation than its `gas_limit` should permit. Repeated over many host calls in a loop, this compounds, and can allow the contract to perform additional storage/host-call side effects beyond what its metered `gas_consumed()` reflects. This constitutes a concrete gas/weight-limit bypass reachable by any unprivileged contract caller and is squarely an accounting/resource-limit defect in the FRAME contracts pallet, which is in-scope SDK code (not admin-only, not requiring privileged access, and not reliant on unrealistic assumptions).

## Likelihood Explanation
The bug is unconditional and deterministic: it triggers on every single host-function call, regardless of `Schedule` parameters, since it is a missing assignment rather than a conditional edge case. Any unprivileged account can deploy a contract that loops host calls (e.g., `seal_debug_message`, `seal_now`) via the standard `Contracts::upload_code` + `instantiate_with_code` + `call` extrinsics and reproduce the fuel-refund effect repeatably.

## Recommendation
Fix `EngineMeter::charge_ref_time` to actually update `self.fuel`:
```rust
self.fuel = self.fuel.checked_sub(amount).ok_or_else(|| Error::<T>::OutOfGas)?;
Ok(Syncable(self.fuel))
```
Add a regression test asserting that `EngineMeter`/`GasMeter` fuel strictly decreases across a `sync_to_executor` call proportional to the ref_time charged, and add an integration/fork test that deploys a host-call-looping contract and confirms real wasmi fuel consumption never exceeds `gas_limit` converted to fuel units.

## Proof of Concept
1. Unit test in `substrate/frame/contracts/src/gas.rs`: construct a `GasMeter::<Test>::new(gas_limit)`, call `sync_from_executor(initial_engine_fuel)`, then `gas_meter.charge(SimpleToken(cost))` to simulate a host call's own weight charge, then `sync_to_executor(before)`. Assert the returned `Syncable` value equals `previous_fuel - (cost / ref_time_by_fuel())`. Today, this assertion fails because `self.fuel` is unchanged, directly proving the bug.
2. Integration test: deploy a contract looping a cheap host call (e.g., `seal_debug_message`) `N` times with `gas_limit` set to only cover `N` calls' worth of charged weight, and demonstrate via `ContractExecResult::gas_consumed` and actual executed-instruction/storage-write counts that the contract performs more real work than `gas_limit` should allow.
