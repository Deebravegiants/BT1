### Title
Emporium `EmporiumSignature` never binds the shielded output's destination, allowing anyone holding a harvested wallet signature to redirect a victim's on-chain-moved funds to their own stealth address - (`contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol`)

### Summary
`EmporiumUpgradeable.verifyWallet` checks the victim's ECDSA signature only over `(emporiumMessage, ops, maxFee, deadline)` via `EMPORIUM_SIGNATURE_TYPEHASH` [1](#0-0) . Neither this typed struct nor the on-chain balance/UTXO check ever binds `circomData.stealthAddressStructure`, which is the field `handleOut` uses to build the resulting UTXO for funds moved through the victim's `HinkalWallet` [2](#0-1) . Any unprivileged party who obtains a validly-signed, still-unused `EmporiumStack` can resubmit it through their own `Hinkal.transact` call with their own `stealthAddressStructure`/proof and claim the resulting shielded UTXO.

### Finding Description
Broken equality: `(assets that leave the victim's wallet, the destination of the resulting shielded value)` must equal `(what the victim's EmporiumStack signature authorized)`. The victim's EIP-712 signature covers only `EmporiumSignature(uint256 message, EmporiumOperation[] ops, uint256 maxFee, uint256 deadline)` [3](#0-2)  - `stealthAddressStructure` (the identity that will own the resulting UTXO) is not part of this hash at all.

Call path: `Hinkal.transact` → `hinkalHelper.performHinkalChecks` (only checks that the *submitter* controls `circomData.stealthAddressStructure` via their own Groth16 proof, and that `originalSender == msg.sender` when self-relaying with `relay == address(0)`) [4](#0-3)  → `_externalTransact` → `EmporiumUpgradeable.runAction` → `verifyWallet` recovers `stack.signerAddress` from the victim's signature and only reverts on bad signature, expired deadline, used `emporiumMessage`, or fee-cap violation — it never checks who is calling `transact` or who supplied `circomData.stealthAddressStructure` [3](#0-2) . The signed `ops` are then executed, with `invokeWallet=true` ops routed to `IHinkalWallet(stack.signerAddress).callHinkalWallet(...)`, which is `onlyEmporium`-gated on the victim's own `HinkalWallet` contract, moving the victim's assets according to the pre-authorized calldata [5](#0-4) [6](#0-5) . Finally `handleOut` wraps whatever balance increase resulted into `UTXO(balanceChange, token, circomData.stealthAddressStructure, timeStamp)` — using the attacker-supplied `stealthAddressStructure`, not anything tied to `stack.signerAddress` [2](#0-1) .

Nothing downstream repairs this: `Hinkal.transact`'s balance equation only checks that `balanceDif == amountChanges[i] + utxoAmount` (a value equality, not an identity/ownership equality) [7](#0-6) , and the Groth16 proof only constrains that the *submitter* (attacker) knows the `nullifyingPrivateKey`/`spendingPublicKey` behind their own `stealthAddressStructure` via `StealthAddressCalculator` [8](#0-7)  and that `inTotal + amountChanges[i] === outTotal` for the attacker's own commitments [9](#0-8)  — it has no signal at all tied to `stack.signerAddress` or the victim's identity. The `emporiumMessage` value appears in both the victim's EIP-712 hash and the attacker's `signedMessageHash` (`getSignedMessageHash`) [10](#0-9) , but this is merely a shared nonce value, not a cryptographic binding between the two signers — the attacker just needs to know/harvest that value along with `v,r,s` and `signerAddress` to reuse the stack.

Because `performHinkalChecks` allows self-relaying (`originalSender == msg.sender && relay == address(0)`), the attacker does not need to be a whitelisted relay to submit this; they only need any harvested, unconsumed, validly-signed `EmporiumStack`.

### Impact Explanation
An attacker can permanently steal a victim's funds that the victim intended to move through Emporium (e.g., a DeFi swap/withdrawal executed via `callHinkalWallet`) by reusing the victim's signed `EmporiumStack` in a `transact` call carrying the attacker's own `circomData.stealthAddressStructure`. The resulting on-chain UTXO commitment is inserted into the Merkle tree keyed to the attacker's stealth address and is spendable only with the attacker's `nullifyingPrivateKey`, i.e., direct theft of shielded/in-flight user funds — Critical severity. This is repeatable for every harvestable signed `EmporiumStack` until the corresponding `emporiumMessage` is consumed (by the legitimate submission or `cancelEmporiumMessage`).

### Likelihood Explanation
Preconditions: attacker must obtain (harvest) a fully signed, not-yet-submitted `EmporiumStack` (v, r, s, signerAddress, ops, maxFee, deadline) plus the matching `emporiumMessage`, which is plausible in any off-chain relay/mempool/dapp flow where such signed intents are transmitted before submission. The attacker needs no special role — just their own funds/keys to generate a self-relayed proof. Cost is limited to generating one proof and gas. This is entirely feasible given the described preconditions in the prompt (a genuinely victim-signed stack is available to be relayed).

### Recommendation
Bind the resulting UTXO's destination identity to the victim's authorization. At minimum, include `circomData.stealthAddressStructure` (or a hash of it) inside `EMPORIUM_SIGNATURE_TYPEHASH` so the wallet owner explicitly signs off on where the Emporium-produced UTXO will go, and reject execution if the recovered `stealthAddressStructure` used in the proof doesn't match what the signer authorized. Alternatively, require that the party submitting `transact` for a non-zero `stack.signerAddress` be an address explicitly designated by the signer (e.g., include `msg.sender`/`originalSender` in the signed payload).

### Proof of Concept
Foundry test plan:
1. Deploy `Hinkal`, `HinkalHelper`, `EmporiumUpgradeable`, and a `HinkalWallet` for `victim`.
2. Have `victim` sign a valid `EmporiumStack` (`EMPORIUM_SIGNATURE_TYPEHASH`) with an op that, via `invokeWallet=true`, moves `victim`'s ERC20 balance from their `HinkalWallet` into the Emporium contract (e.g., calling a mock DEX/router that pulls victim tokens and sends output to Emporium).
3. As `attacker`, generate a valid Groth16 proof for their own fresh `spendingPublicKey`/`nullifyingPrivateKey`, producing `circomData.stealthAddressStructure` bound to attacker's own key, and embed the harvested `stack` bytes in `externalActionData.externalActionMetadata`, with `originalSender = attacker`, `relay = address(0)`.
4. Call `Hinkal.transact(...)` as `attacker`.
5. Assert: (a) `victim`'s `HinkalWallet` balance decreased by the swap amount; (b) the emitted commitment/UTXO in `insertCommitments` corresponds to `attacker`'s `stealthAddressStructure`, not `victim`'s; (c) `attacker` can later spend that UTXO in a subsequent `transact` using their own `nullifyingPrivateKey`/nullifier derivation, proving the funds are attacker-spendable while `victim` has no matching output UTXO for the moved funds.

    function verifyWallet(
        EmporiumStack memory stack,
        CircomData calldata circomData
    ) internal {
        EmporiumStorageVars storage $ = _getEmporiumStorage();

        if ($.usedMessages[circomData.emporiumMessage]) {
            revert UsedMessage();
        }

        $.usedMessages[circomData.emporiumMessage] = true;

        if (stack.signerAddress == address(0)) {
            return;
        }

        bytes32 hashedMessage = _hashTypedDataV4(
            keccak256(
                abi.encode(
                    EMPORIUM_SIGNATURE_TYPEHASH,
                    circomData.emporiumMessage,
                    _hashEmporiumOps(stack.ops),
                    stack.maxFee,
                    stack.deadline
                )
            )
        );

        (address recoveredAddress, ECDSA.RecoverError err) = ECDSA.tryRecover(
            hashedMessage,
            stack.v,
            stack.r,
            stack.s
        );
        bool verified = err == ECDSA.RecoverError.NoError &&
            recoveredAddress == stack.signerAddress;
        if (!verified) {
            revert InvalidSignature();
        }

        if (block.timestamp > stack.deadline) {
            revert SignatureExpired();
        }

        if (circomData.feeStructure.flatFee > stack.maxFee) {
            revert FeeExceedsSignedMax();
        }
    }

    function getSignedMessageHash(
        uint256 chainId,
        address verifyingContract,
        CircomData calldata circomData,
        uint256 emporiumMessage
    ) internal pure returns (uint256) {
        // split into two encode calls to avoid "stack too deep"
        uint256 hash1 = uint256(
            keccak256(
                abi.encode(
                    chainId,
                    verifyingContract,
                    circomData.rootHashHinkal,
                    _encodeTokenAddresses(circomData.erc20TokenAddresses),
                    _encodeAmountChanges(circomData.amountChanges),
                    circomData.timeStamp,
                    _flatUint256Matrix(circomData.inputNullifiers),
                    _flatUint256Matrix(circomData.outCommitments),
                    circomData.calldataHash,
                    emporiumMessage
                )
            )
        );
        uint256 hash2 = uint256(
            keccak256(
                abi.encode(
                    circomData.stealthAddressStructure.H1x,
                    circomData.stealthAddressStructure.H1y,
                    circomData.stealthAddressStructure.H0x,
                    circomData.stealthAddressStructure.H0y
                )
            )
        );
        return
            uint256(keccak256(abi.encode(hash1, hash2))) % CIRCOM_P;
