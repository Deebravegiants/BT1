### Title
Direct LT Donations To A Bonding-Curve Pair Are Permanently Locked With No Recovery Path - (File: `packages/contracts/src/Pair.sol`, `packages/contracts/src/Router.sol`, `packages/contracts/src/Bonding.sol`)

### Summary
Any unprivileged wallet that sends LT tokens directly to a bonding-curve `Pair` (e.g. by mistake, or intending to "support" a token) has those funds permanently and irrecoverably locked once the token graduates. The graduation math is deliberately donation-resistant — it excludes any LT balance above the tracked `assetReserve` from `Router.graduate`'s drain — but nothing ever retrieves that excess afterward. `Pair.sol` exposes no owner/admin rescue function, and the only functions capable of moving `assetToken` out of the pair (`Router.graduate` and `Router.sell`) are gated to `onlyRole(BONDING_ROLE)` and only reachable pre-graduation through `Bonding`'s lifecycle checks.

### Finding Description
`Router.graduate(token, amount)` drains only the exact `ltFromPair` computed by `Bonding._prepareGraduationLiquidity` — `assetReserve - virtualLtReserve` — deliberately leaving behind anything donated directly via `IERC20.transfer(pair, X)`, since donations don't move the pair's internally tracked `_pool.assetReserve` [2](#0-1) . This is confirmed by the invariant test asserting donated LT remains in the pair post-graduation: `assertEq(IPair(pairAddr).assetBalance(), donation, "donated LT must remain locked in the curve pair")` [3](#0-2) .

Once `finalizeGraduation` flips `info.lifecycle` to `Lifecycle.Graduated`, `Bonding` can never again call `Router.graduate` for that token — the natspec explicitly states the leftover is "locked" only as a trust assumption, since the code path is permanently unreachable post-graduation [2](#0-1) . `Pair.sol` itself has no owner, no admin function, and no `skim`/`rescue`/`sweep` mechanism for `assetToken` — `transferAsset` and `transferToken` are the only egress functions and both are `onlyRouter` [1](#0-0) . Unlike `FeeVault`, which has an explicit, permissionless `sweepDonations()` to recover excess USDC and route it to `feeTo` [4](#0-3) , and unlike `finalizeGraduation`'s `_sweepLTToOwner`, which explicitly rescues donated/rebalance-residue LT sitting in `Bonding` itself [5](#0-4) , no equivalent recovery mechanism exists for LT donated to the `Pair` contract. This is the same root cause as the referenced Concur `Shelter.sol` bug: a donation mechanism (`donate`) exists conceptually, but the surrounding lifecycle transition (`enterShelter`/`exitShelter` there, `Curve → Graduating → Graduated` here) has no path back to the donor or to any owner, so the funds become permanently stranded in a contract with zero withdrawal capability.

### Impact Explanation
Any LT sent directly to a `Pair` address before graduation is permanently frozen forever after that token graduates — no creator, protocol admin, or the donor themselves can ever retrieve it. This is a permanent freeze of real economic value (LT, itself pegged to an underlying leveraged position) with no recovery path, satisfying the "permanent freezing of funds" impact criterion. The amount at risk scales with donation size and is unbounded, since `Bonding.launch` places no cap on how much LT a wallet can transfer to a pair.

### Likelihood Explanation
Likelihood is real but incidental rather than attacker-driven: it requires a wallet to send LT directly to a `Pair` contract address instead of routing through `Zap.buy`/`Bonding.buy`. This can happen from user error (typing the pair address instead of the token address in a wallet), from third parties attempting a "seed the pool" donation pattern that is common on other bonding-curve platforms, or from bots/automation misconfigured to top up a pair. Because the pair address is public and discoverable via `TokenLaunched`/`Factory.getPair`, no privileged access is needed to trigger the loss — a single unprivileged `IERC20.transfer` call is sufficient.

### Recommendation
Add a permissionless (or owner-gated, paid-to-donor-unknown-so-owner-gated) sweep function to `Pair.sol`, analogous to `FeeVault.sweepDonations()`, that computes `assetToken.balanceOf(address(this)) - assetReserve` (and the token-side equivalent for `tokenBalance() - tokenReserve` pre-graduation) and forwards the excess to a designated recipient (e.g. protocol owner, mirroring `Bonding._sweepLTToOwner`'s pattern) once the pair has fully graduated and no further curve activity can occur. Alternatively, expose a `Router`-mediated `rescueDonation(token, recipient)` restricted to a role held even post-graduation, so any pre- or post-graduation donation can still be recovered rather than being unconditionally excluded and abandoned.

### Proof of Concept
1. A creator launches a token via `Bonding.launch`/`Zap.createToken`, creating `Pair` at address `P` for `token`/`LT`.
2. An unrelated wallet, believing it is contributing extra liquidity/support, calls `LT.transfer(P, 1000e18)` directly — bypassing `Bonding.buy`. This does not change `_pool.assetReserve` (only `assetBalance()` increases) [6](#0-5) .
3. Trading continues; the token eventually crosses the graduation threshold (USD or supply trigger) via `Bonding._enterGraduating` → `Bonding.finalizeGraduation`.
4. `Bonding._prepareGraduationLiquidity` computes `ltFromPair = assetReserve - virtualLtReserve`, deliberately excluding the 1000e18 donation, and `Router.graduate` drains only that amount, per the test assertion `assertEq(IPair(pairAddr).assetBalance(), donation, ...)` [3](#0-2) .
5. `info.lifecycle` is now `Graduated`; `Router.graduate` is permanently unreachable for this token (gated behind `Lifecycle.Curve`-only logic in `Bonding`), and `Pair.sol` has no other function capable of moving `assetToken` out [1](#0-0) .
6. The 1000e18 LT donation is now permanently and irrecoverably stuck in `Pair` `P`, with no function on any contract able to extract it.

```text
    /// @notice Transfer exactly `amount` of LT out of the pair to the caller.
    ///         Called by `Bonding._prepareGraduationLiquidity` during graduation
    ///         with `amount = stored assetReserve - virtualLtReserve` (i.e. the
    ///         real LT raised by the curve, excluding the virtual seed).
    /// @dev    Donation-resistant: passing an explicit `amount` instead of
    ///         draining `assetBalance()` ensures any LT that was donated
    ///         directly to the pair via `IERC20.transfer` is left behind and
    ///         excluded from LP seeding.
    ///
    ///         "Locked" here is a trust-assumption claim, not an on-chain
    ///         guarantee. `Pair.transferAsset` is gated by `onlyRouter`, and
    ///         `Router` only exposes it via this function and `sell`. Both
    ///         require `BONDING_ROLE`, which only `Bonding` holds. `Bonding`
    ///         in turn only calls `graduate` from
    ///         `_prepareGraduationLiquidity` — which is unreachable once the
    ///         token's lifecycle has flipped past `Curve`. So the leftover
    ///         is unreachable as long as (a) `BONDING_ROLE` is not granted
    ///         to any other address, and (b) future `Bonding` upgrades
    ///         preserve the lifecycle gate.
    function graduate(
        address token,
        uint256 amount
    ) external onlyRole(BONDING_ROLE) {
        address asset = assetTokenFor(token);
        address pairAddr = factory.getPair(token, asset);
        if (pairAddr == address(0)) revert PairNotFound();
        IPair(pairAddr).transferAsset(msg.sender, amount);
    }
```

```text
    /// @notice Sweep unbacked USDC (donations) to `feeTo`. Required because
    ///         direct USDC transfers would otherwise inflate `balanceOf` above
    ///         the accrual tally and silently mask the `accrue` underfund
    ///         check. Permissionless — funds always go to the admin-set `feeTo`.
    function sweepDonations() external nonReentrant returns (uint256 amount) {
        FeeVaultStorage storage $ = _s();
        uint256 backed = $.totalAccruedCreator + $.protocolBalance;
        uint256 balance = $.usdc.balanceOf(address(this));
        if (balance <= backed) revert NothingToClaim();
        amount = balance - backed;
        address feeTo_ = $.feeTo;
        $.usdc.safeTransfer(feeTo_, amount);
        emit DonationsSwept(feeTo_, amount);
    }
```

```text
    /// @dev Send LT held by this contract above `keep` to the owner,
    ///      emitting `LTRescued`. Called at the end of
    ///      `finalizeGraduation` with `keep = protectedLT` (any escrow
    ///      that doesn't belong to this graduation), so only THIS
    ///      graduation's rebalance residue lands on the owner. No-op on
    ///      the empty-pair fast path (nothing to sweep).
    function _sweepLTToOwner(
        address lt,
        uint256 keep
    ) internal {
        uint256 bal = IERC20(lt).balanceOf(address(this));
        if (bal <= keep) return;
        uint256 amount = bal - keep;
        address recipient = owner();
        IERC20(lt).safeTransfer(recipient, amount);
        emit LTRescued(lt, recipient, amount);
    }
```
