## Title
Missing gateway-side allowlist/rate-limiting before forwarding legacy `web_api_trigger` messages to DON nodes - (File: core/services/gateway/handlers/capabilities/handler.go)

## Summary
`HandleLegacyUserMessage` in `core/services/gateway/handlers/capabilities/handler.go` only performs structural checks (payload decoding, timestamp presence/freshness, method name) before broadcasting a `web_api_trigger` message to every member of the DON via `don.SendToNode`. [1](#0-0)  The code contains an explicit `// TODO: apply allowlist and rate-limiting here` comment directly preceding the method check and the node fan-out loop, confirming the intended gateway-level control is unimplemented in this legacy code path. [2](#0-1) 

## Finding Description
The handler struct carries a `nodeRateLimiter` field, but it is only invoked in `handleWebAPIOutgoingMessage` (which processes node-originated outgoing HTTP requests keyed by `nodeAddr`), never in `HandleLegacyUserMessage`. [3](#0-2)  The only gate before dispatch to `don.SendToNode` in `HandleLegacyUserMessage` is `msg.Validate()`, invoked upstream in `gateway.go`'s `ProcessRequest` for legacy requests, which validates message structure/signature format and extracts the signer address into `msg.Body.Sender` — but does not check that the signer is an authorized/allowlisted sender. [4](#0-3)  `Message.Validate()` itself confirms this: it checks field lengths and extracts a valid ECDSA signer, but performs no authorization check against any allowlist. [5](#0-4)  Any party can generate an arbitrary keypair, self-sign a fresh-timestamped message, and pass all checks in `HandleLegacyUserMessage`, causing the gateway to broadcast the request to every DON member address in `h.donConfig.Members`. [6](#0-5) 

Node-side filtering exists in `processTrigger` (per-workflow `allowedSenders`/`allowedTopics`/rate limiter), but this executes only after each DON node has already received and parsed the broadcast payload — it does not prevent the gateway from fanning the message out to every node in the first place. [7](#0-6) 

Notably, the codebase already contains a newer "V2" HTTP handler implementation (`core/services/gateway/handlers/capabilities/v2/`) that does implement the missing controls the TODO calls for — JWT-based authentication, per-workflow authorized-key checks, and per-sender/global rate limiting before dispatching to DON nodes. [8](#0-7) [9](#0-8)  This confirms the legacy `handler.go` path (the file under review) is the outdated, genuinely-unprotected implementation that the TODO flags.

## Impact Explanation
Because `HandleLegacyUserMessage` performs no allowlist or rate-limit check before iterating `h.donConfig.Members` and calling `don.SendToNode` for each one, an unauthenticated caller who can only self-generate a signing key can force fan-out of arbitrary payloads to every node in a targeted DON, repeatedly, with no throttling at the gateway layer for this method. This is a resource-exhaustion/DoS vector against an entire DON's node fleet, reachable without any legitimate relationship to a registered workflow, and increases probing surface against per-workflow trigger allowlists at the node layer.

## Likelihood Explanation
High likelihood of reachability: the gateway's public HTTP endpoint (`ProcessRequest` in `core/services/gateway/gateway.go`) routes any structurally valid, signed legacy message to the DON-ID-mapped handler without additional gateway-level sender authorization. [4](#0-3)  The gap is explicitly marked as a known, unimplemented control via the `TODO` comment rather than being incidental, and repeated invocation costs the attacker only signature generation and an HTTP POST.

## Recommendation
Implement the intended allowlist and rate-limiting check in `HandleLegacyUserMessage` before dispatching to `don.SendToNode`, invoking the existing `h.nodeRateLimiter` (or a dedicated per-sender limiter) keyed on `msg.Body.Sender`, and/or restricting broadcast to senders present in a configured allowlist — mirroring the approach already implemented in the newer V2 HTTP trigger handler and the per-workflow controls in `core/capabilities/webapi/trigger/trigger.go`.

## Proof of Concept
1. Generate an arbitrary ECDSA keypair (no DON registration needed).
2. Craft a `web_api_trigger` legacy `api.Message` with fresh `Timestamp`, arbitrary `Topics`/`Params`, and sign it with the arbitrary key, following the pattern in `core/scripts/gateway/web_api_trigger/invoke_trigger.go`. [10](#0-9) 
3. POST the signed, encoded legacy request to the gateway's public `/user` endpoint targeting a known `DonID`.
4. Observe `HandleLegacyUserMessage` accepts the message (payload decode, timestamp checks, method check all pass) and forwards it via `don.SendToNode` to every DON member address, with no allowlist/rate-limit gate at that layer.
5. Repeat rapidly to flood every DON node's capability handler pipeline; the request reaches and is processed by all nodes before any per-workflow `allowedSenders` filter in `trigger.go` discards it.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageID) == 0 || len(m.Body.MessageID) > MessageIDMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageID, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonID) == 0 || len(m.Body.DonID) > MessageDonIDMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonID, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
