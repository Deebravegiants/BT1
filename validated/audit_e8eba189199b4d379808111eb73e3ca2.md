### Title
Unchecked RAY-value overflow during accrual permanently freezes a market - (File: contracts/pool/src/interest.rs)

### Summary
A sufficiently large market can reach a state where `borrowed * borrow_index` or `supplied * supply_index` no longer fits in `i128`; `global_sync` nevertheless runs the full `accrue_step` without first checking that the market’s RAY values remain representable. [1](#0-0)  Once that boundary is crossed, every market mutation runs accrual first and therefore reverts with `MathOverflow`, permanently blocking repayment, withdrawal, borrowing, liquidation, and bad-debt settlement for that market. [2](#0-1) [3](#0-2) 

### Finding Description
The pool unconditionally calls `accrue_step` from `global_sync`, then commits the returned indexes and revenue shares. [1](#0-0)  The accrual path uses `scaled_to_original` to convert total scaled debt and total scaled supply into RAY asset values when deriving utilization. [4](#0-3)  These conversions are checked operations, but the code has no preflight bound that detects an already-too-large stored `shares * index` product and no fallback path that skips utilization, caps the indexes, or permits risk-reducing operations after overflow. [5](#0-4) [6](#0-5) 

The in-tree stress test creates a one-billion-token, 18-decimal market at 98% utilization under a 175%-maximum-rate curve and demonstrates that the index reaches the value-overflow cliff before the configured `MAX_BORROW_INDEX_RAY` cap. [7](#0-6)  The same test then shows that both a minimal supplier withdrawal and a minimal debt repayment fail with `MathOverflow`, confirming that the state is not merely a temporary transaction failure. [8](#0-7) 

The path is reachable through ordinary controller calls: `supply` can grow the market, `borrow` can push utilization to the steep part of the curve, and permissionless `update_indexes` can commit accrual until the product overflows. [9](#0-8) [10](#0-9)  The required principal is within the protocol’s documented raw-amount domain for an 18-decimal asset, provided the listed market’s supply and borrow caps admit it. [11](#0-10) 

### Impact Explanation
This causes permanent freezing of user funds in the affected hub asset: suppliers cannot withdraw and borrowers cannot repay because both flows must synchronize the market before applying their accounting changes. [12](#0-11) [13](#0-12)  Liquidation also cannot rescue the market because liquidation repayment and seizure legs use the same accrual-first market operations. [3](#0-2)  The result is not a fail-closed oracle outage or missing account object; it is a persistent arithmetic state in which every valid recovery path re-enters the overflowing accrual calculation. [14](#0-13) 

### Likelihood Explanation
Exploitation requires an unusually large listed market and enough collateral to hold roughly 98% utilization, so it is not practical on a tightly capped market. [15](#0-14)  It does not require privileged access, leaked keys, malformed token behavior, or an external oracle failure: the attacker only needs permissionless user operations and enough elapsed ledger time for the stored scaled positions to cross the `i128` value ceiling. [16](#0-15) [17](#0-16)  Because pool bookkeeping permits token amounts near `i128::MAX / 10^(27-d)`, a billion whole 18-decimal tokens remain within the admitted numeric domain even though their later index-valued products need not fit. [11](#0-10) 

### Recommendation
Add a recovery path that never requires recomputing utilization from unrepresentable aggregate RAY values: saturate utilization for rate selection, cap index growth before value conversion overflows, or split emergency repay/withdraw/bad-debt operations from full `accrue_step`. [1](#0-0) [4](#0-3)  At minimum, `global_sync` should detect `borrowed * borrow_index` or `supplied * supply_index` overflow before calling `accrue_step` and transition the market into a bounded terminal mode that still permits repayment and withdrawal. [5](#0-4)  Market caps should also enforce a reserve below the protocol’s theoretical token-domain maximum so admitted `shares * index` products cannot reach the `i128` boundary before the index ceiling. [11](#0-10) 

### Proof of Concept
The repository’s deterministic harness already contains the exploit-shaped scenario: [3](#0-2) 

1. Create an 18-decimal market using the test’s 175%-maximum-rate XLM curve and enough listed supply/borrow cap for one billion whole tokens. [18](#0-17) 
2. Call controller `supply(caller, supplier_account, spoke_id, [(BIG18, 1_000_000_000 * 10^18)])`. [19](#0-18) 
3. From a sufficiently collateralized account, call `borrow(caller, borrower_account, [(BIG18, 980_000_000 * 10^18)], to)`, reaching approximately 98% utilization. [20](#0-19) 
4. Advance ledger time in yearly steps and call permissionless `update_indexes(caller, [BIG18])` until `accrue_step` hits `MathOverflow` before `MAX_BORROW_INDEX_RAY`. [21](#0-20) 
5. Attempt `withdraw(supplier, supplier_account, [(BIG18, 1)], to)` or `repay(payer, borrower_account, [(BIG18, 1)])`; both fail with `MathOverflow`, and all later accrual-dependent operations encounter the same state. [8](#0-7)

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
```

```rust
/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```

```rust
pub(crate) fn accounting(env: &Env, action: &PoolAction) -> RepayOutcome {
    let (mut cache, position) = ops::load_leg(env, action);
    let amount = action.amount;

    let (burned, overpayment) = cache.resolve_repay(amount, position);
    let net_repay = amount
        .checked_sub(overpayment)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));
    assert_with_error!(
        env,
        net_repay == 0 || burned.raw() > 0,
        GenericError::RepayRoundsToZeroShares
    );

    let position = position.checked_sub(env, burned);
    cache.burn_debt(burned);

    cache.credit_cash(net_repay);

    let snapshot = cache.commit();
```

```rust
    let snapshot = cache.commit();
    let mutation = cache.position_mutation(remaining, gross_amount);
```
