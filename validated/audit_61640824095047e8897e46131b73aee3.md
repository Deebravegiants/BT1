The reported issue concerns Dinari's `OrderProcessor.sol`, where an off-chain real-world security price (e.g., oil futures) is stored as `uint256` and cannot represent a negative market price. Raydium's AMM has no such analog: prices in `program/src/math.rs` (e.g. `swap_token_amount_base_in`, `swap_token_amount_base_out`, `get_max_buy_size_at_price`, `get_max_sell_size_at_price`) are derived purely as ratios of on-chain SPL token reserve amounts (`total_pc_without_take_pnl` / `total_coin_without_take_pnl`), which are `u64`/`u128` non-negative balances held in vault accounts [1](#0-0) . Because a constant-product AMM's implied price is always `reserve_y / reserve_x` of two non-negative token balances, it is mathematically impossible for the price to go negative — there is no off-chain oracle feed or external market price input analogous to a security/futures price that could turn negative. The `TargetOrder.price` and `OrderRequest`-like fields in `program/src/state.rs` (e.g. [2](#0-1) ) are also `u64` internal order-book prices computed from the same non-negative reserves, not external security prices, so the same "negative price" bug class from the Dinari report does not transfer to this codebase.

    pub fn swap_token_amount_base_in(
        amount_in: U128,
        total_pc_without_take_pnl: U128,
        total_coin_without_take_pnl: U128,

            SwapDirection::Coin2PC => {
                // (x + delta_x) * (y + delta_y) = x * y
                // (coin + amount_in) * (pc - amount_out) = coin * pc
                // => amount_out = pc - coin * pc / (coin + amount_in)
                // => amount_out = ((pc * coin + pc * amount_in) - coin * pc) / (coin + amount_in)
                // => amount_out =  pc * amount_in / (coin + amount_in)
                let denominator = total_coin_without_take_pnl.checked_add(amount_in).unwrap();
                amount_out = total_pc_without_take_pnl
                    .checked_mul(amount_in)
                    .unwrap()
                    .checked_div(denominator)
                    .unwrap();
            }
            SwapDirection::PC2Coin => {
                // (x + delta_x) * (y + delta_y) = x * y
                // (pc + amount_in) * (coin - amount_out) = coin * pc
                // => amount_out = coin - coin * pc / (pc + amount_in)
                // => amount_out = (coin * pc + coin * amount_in - coin * pc) / (pc + amount_in)

                    .checked_mul(amount_in)

                    .unwrap();
            }
        }
        return amount_out;
