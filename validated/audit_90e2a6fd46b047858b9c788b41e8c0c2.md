## Analysis: CVE-2018-14671 (unixODBC arbitrary shared-object loading → RCE) mapped to Hyperbridge

The bug class in CVE-2018-14671 is an execution primitive that loads/executes arbitrary external code without validating who is allowed to trigger it or what it's allowed to target. The closest reachable analog in this codebase is `CallDispatcher.dispatch()`, which executes arbitrary attacker-specified calls with the dispatcher's own identity, and is **not restricted to the trusted apps that are supposed to be its only callers**. [1](#0-0) 

### Title
Unauthenticated `CallDispatcher.dispatch()` allows any unprivileged caller to execute arbitrary calls and drain funds held by the dispatcher - (File: `evm/src/utils/CallDispatcher.sol`)

### Summary
`CallDispatcher.dispatch()` is `external` with no caller restriction (no `onlyOwner`/`onlyApp`/`msg.sender` allow-list), yet it is the execution primitive relied upon by `IntentGatewayV2` (predispatch/postdispatch calldata and sweep transfers) and by `HyperFungibleToken`/`WrappedHyperFungibleToken` (`onAccept` calldata execution), all of which transiently place value (ETH or ERC20) at the dispatcher's address before or during a `dispatch()` call. [2](#0-1) [3](#0-2) 

### Finding Description
`CallDispatcher.dispatch(bytes encoded)` decodes a `Call[]` and, for each entry, performs `to.call{value: call.value}(call.data)` — with `to`, `value` and `data` fully attacker-controlled and `msg.sender` of the resulting call being the `CallDispatcher` contract itself. The only check performed is that `to` has code (`extcodesize`); there is no restriction on *who may invoke* `dispatch()`. [1](#0-0) 

The contract is also `payable` via an unrestricted `receive()`, so it can hold native ETH from any source, and it is deployed as a single shared instance reused across `IntentGatewayV2`, `HyperFungibleToken`, and `WrappedHyperFungibleToken` (per the deployment scripts, using a deterministic CREATE2 salt and referenced by address in each app's params). [4](#0-3) [5](#0-4) 

Documentation itself acknowledges the dispatcher "holds tokens temporarily during execution," which is the precondition for theft given zero access control on `dispatch()`: [6](#0-5) 

Concretely:
- `IntentGatewayV2.placeOrder` transfers `order.predispatch.assets` (ETH or ERC20) to the dispatcher, then invokes `dispatch()` on `order.predispatch.call`. [7](#0-6) 
- `IntentsBase._execute` invokes `dispatch()` on `order.output.call` while the dispatcher holds output funds, then sweeps residual balance back. [3](#0-2) 
- `HyperFungibleToken.onAccept`/`WrappedHyperFungibleToken.onAccept` call `dispatch()` with `message.data` — a payload fully controlled by the *original sender* on the source chain (via `SendParams.data`), sent to the shared dispatcher. [2](#0-1) [8](#0-7) 

Because `dispatch()` accepts calls from any `msg.sender`, any ETH or ERC20 balance that lands at the dispatcher's address (via its permissionless `receive()`, via any app's asset-transfer step prior to `dispatch()` execution, or via leftover dust from a partially-completed multi-step flow) is exposed to being swept out by an unrelated third party who simply calls `CallDispatcher.dispatch()` directly with a `Call[]` routing those funds to themselves — using the dispatcher's own identity as `msg.sender`, exactly analogous to how unixODBC's unauthenticated dynamic-library loading let an untrusted input path result in arbitrary code execution under the trusted process's identity.

### Impact Explanation
Any native ETH or ERC20 balance held (even transiently or accidentally, given the public payable `receive()`) by the shared `CallDispatcher` can be stolen by an unprivileged third party, since the sole gate protecting fund movement out of that contract (`dispatch()`) performs no caller authentication at all. Given the dispatcher is reused across `IntentGatewayV2` order escrow flows and multiple `HyperFungibleToken`/`WrappedHyperFungibleToken` deployments, this is a direct theft-of-funds primitive reachable from a single unprivileged transaction, meeting the Critical/High bar for concrete theft of funds.

### Likelihood Explanation
High: `dispatch()` is a public external function with no modifier, callable by anyone at any time, and the contract is explicitly payable and designed to be funded by other trusted contracts as part of normal, expected order/token flows — meaning attacker opportunities to race or exploit any window where value sits at the dispatcher's address are a normal, recurring part of the system's operation, not an edge case.

### Recommendation
Add caller authorization to `CallDispatcher.dispatch()` — e.g., restrict callers to an allow-list of trusted app contracts (`IntentGatewayV2`, `HyperFungibleToken`, `WrappedHyperFungibleToken` instances) set at construction/configuration time, or scope dispatcher deployments 1:1 per app so no shared/attacker-reachable balance window exists. Reject direct external `receive()` funding, or ensure any balance is swept atomically within the same transaction that funded it before any other party's transaction can be mined.

### Proof of Concept
1. Any account sends native ETH directly to the deployed `CallDispatcher` address (its `receive()` is unrestricted), or waits for an in-flight `IntentGatewayV2`/`HyperFungibleToken` transaction to leave a token/ETH balance at the dispatcher's address.
2. Attacker constructs `Call[] calls = [Call({to: attackerContractOrEOA, value: <dispatcherBalance>, data: ""})]` (or an ERC20 `transfer` call to itself for token balances) and ABI-encodes it.
3. Attacker calls `CallDispatcher.dispatch(encodedCalls)` directly — no access control prevents this — draining the balance currently held by the dispatcher to the attacker's address. [1](#0-0)

```text
    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
```

```text
        PostRequest calldata request = incoming.request;

        bytes memory expectedSource = _supportedChains[request.source];
        if (expectedSource.length == 0) revert UnsupportedChain();
        if (keccak256(request.from) != keccak256(expectedSource)) revert UnauthorizedSource();

        Message memory message = abi.decode(request.body, (Message));
        address beneficiary = _toAddr(message.to);
        _mint(beneficiary, message.amount);

        if (message.data.length > 0) {
            ICallDispatcher(_dispatcher).dispatch(message.data);
        }

        emit Received({
            from: message.from,
            to: beneficiary,
            source: string(request.source),
            amount: message.amount
        });
```
