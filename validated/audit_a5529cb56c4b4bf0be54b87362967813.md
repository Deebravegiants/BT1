### Title
Stale stored owner retains account authority after position-NFT transfer - ([File: contracts/controller/src/account.rs](contracts/controller/src/account.rs))

### Summary
The controller authorizes privileged account operations against the `owner` field stored in `Account` at NFT mint time rather than against live ownership reported by the position-NFT contract. When a user transfers their position NFT, the stored owner never changes, so the *previous* owner keeps full delegate-class authority over the account (borrow/multiply/migrate paths) while the *new* NFT holder is rejected. This is the direct analog of CVE-2023-24010: a permission/identity check that validates a stale or wrong authorization artifact instead of the authoritative credential.

### Finding Description
`create_account_with` mints the NFT and permanently stores `owner` inside `Account` in `contracts/controller/src/account.rs:64-70`. The authority checks used by `AccountGuard::Migrate` and `AccountGuard::Multiply` call `require_owner_or_delegate`, which compares the caller to `account.owner` — the cached field, not the NFT contract (`account.rs:102-107`, `130-140`):

```rust
pub(crate) fn is_owner_or_delegate(env, account_id, caller, owner) -> bool {
    if caller == owner { return true; }   // `owner` is account.owner, set at mint
    ...
}
``` [1](#0-0) [2](#0-1) [3](#0-2) 

By contrast, `require_account_owner` goes through `storage::account_owner` (which appears intended to resolve live NFT ownership, consistent with `nft_try_owner_of_call` in `contracts/controller/src/external/position_nft.rs:19-25`). So the codebase maintains *two* notions of ownership — live NFT ownership and the stale `account.owner` — and different entrypoints verify different ones. `add_delegate`/`remove_delegate`/`set_account_delegate` authenticate `caller` via `require_account_owner` but then mutate delegate lists keyed under `caller`, while `is_owner_or_delegate` checks delegates under `account.owner` — a transferred NFT's new owner can add delegates for themselves, but `is_owner_or_delegate` looks up `get_delegates(account_id, owner=old_owner)`, so the new owner's delegates are invisible and the old owner's delegates remain effective (`account.rs:126`, `242-275`).

### Impact Explanation
An unprivileged attacker path:

- Buy or receive a position NFT for an account holding collateral (position-nft `transfer` is in scope).
- The *seller* (old `account.owner`) still passes `require_owner_or_delegate`, so they can invoke `multiply`/`migrate_from_blend`-class operations — including opening debt and moving collateral — on an account they no longer own, i.e., theft of the buyer's collateralized position or forcing the account into bad debt.
- Conversely, the buyer cannot authenticate through the owner/delegate path that these operations require (their address never equals `account.owner`, and delegates they add are stored under the wrong key), permanently or semi-permanently freezing their control over the position depending on which entrypoints consult which ownership source.

Both theft of user funds and freezing of funds are reachable.

### Likelihood Explanation
Trigger requires only a position-NFT transfer — a supported, unprivileged operation (`transfer`/`approve` on `contracts/position-nft`, explicitly in scope per the rules). No privileged role, oracle manipulation, or timing dependence is needed. The severity of the *theft* leg depends on which post-transfer entrypoints (`multiply`, `migrate_from_blend`, `swap_collateral`, `repay_debt_with_collateral`) rely solely on `account.owner` versus `require_account_owner`; `AccountGuard::Multiply` and `AccountGuard::Migrate` demonstrably use the stale field (`account.rs:101-109`). The *lockout* leg follows unconditionally: the new owner can never satisfy `caller == account.owner`.

Uncertainty: I could not confirm whether `storage::account_owner` reads NFT ownership live or returns the cached field, nor whether position-NFT `transfer` invokes a controller hook that updates `account.owner`. If the NFT contract notifies the controller on transfer and `account.owner` is rewritten, this finding collapses — but no such hook is visible in `account.rs`, and `set_account_delegate` explicitly keys delegates by the *caller* owner while lookups key by the *stored* owner, confirming the two ownership views diverge after transfer.

### Recommendation
Make NFT ownership the single source of truth:

- In `require_owner_or_delegate`/`is_owner_or_delegate`, resolve the owner via `nft_try_owner_of_call` (or `storage::account_owner` if it already queries the NFT) instead of `account.owner`.
- On delegate bookkeeping, key `get_delegates`/`add_delegate`/`remove_delegate` by `account_id` alone (or by live owner resolved at call time) so grants follow the token, and consider clearing delegates on NFT transfer.
- If `account.owner` is retained as a cache for gas reasons, it must be invalidated/synced on every NFT transfer or re-verified at each privileged call.

### Proof of Concept
1. Alice calls `supply` (or `multiply`) with `account_id = 0`; `create_account` mints NFT `N` to Alice and stores `Account { owner: Alice, ... }` (`account.rs:62-70`).
2. Alice calls `position_nft.transfer(alice, bob, N)` — in-scope unprivileged call.
3. Alice calls `controller.multiply(caller=alice, account_id=N, ...)`: `load_or_create_account` → `AccountGuard::Multiply` → `require_owner_or_delegate(..., &account.owner)` — `account.owner` is still Alice → passes auth → Alice opens borrows/moves collateral on Bob's NFT-backed account.
4. Bob calls `controller.add_delegate(caller=bob, account_id=N, delegate=bob_manager)`: `require_account_owner` succeeds (NFT owner is Bob), but `add_delegate` stores under `(N, bob)` while `is_owner_or_delegate` looks up `get_delegates(N, account.owner=alice)` — Bob's delegation never takes effect, and Bob cannot satisfy `caller == account.owner`, so the owner/delegate-gated operations are unusable to the legitimate holder.

```rust
pub(crate) fn is_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) -> bool {
    if caller == owner {
        return true;
    }
    let active_manager =
        storage::get_position_manager(env, caller).is_some_and(|config| config.is_active);
    active_manager && storage::get_delegates(env, account_id, owner).contains(caller)
}

/// Requires the owner or a registered, active manager delegated by that owner.
pub(crate) fn require_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) {
    if is_owner_or_delegate(env, account_id, caller, owner) {
        return;
    }
    panic_with_error!(env, GenericError::NotAuthorized);
}
