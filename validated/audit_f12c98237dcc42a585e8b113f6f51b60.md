### Title
Webhook HMAC validates only the request body, not the `shop-domain`/`topic`/`webhook-id` headers used for tenant routing - (File: lib/shopify_api/webhooks/request.rb)

### Summary
`ShopifyAPI::Webhooks::Request#to_signable_string` returns only `@raw_body`, so `Utils::HmacValidator.validate` verifies nothing but the JSON body bytes. The `shop`, `topic`, `webhook_id`, and `api_version` values that `Registry.process` hands to the app's `WebhookHandler` are parsed straight from HTTP headers and are never part of the signed payload, breaking the equality `hmac_verified_bytes == bytes_the_app_trusts_for_tenant_identity`.

### Finding Description
`Request#hmac` decodes the `X-Shopify-Hmac-SHA256` header, and `Request#to_signable_string` returns just `@raw_body`: [1](#0-0) 

`Utils::HmacValidator.validate` computes the HMAC over `to_signable_string` (the raw body only) and compares it to the header-supplied HMAC: [4](#0-3) 

`Registry.process` treats a passing HMAC check as proof of authenticity for the whole request, then forwards `request.shop`, `request.topic`, and `request.webhook_id` — all parsed from headers — to the handler as trusted tenant/topic metadata: [2](#0-1) 

Because the signature covers only the body, `shop-domain`, `topic`, `webhook-id`, and `api-version` headers can be freely modified on a request carrying a *previously valid* `(body, hmac)` pair without invalidating the signature. Any actor who has ever received one legitimate webhook delivery (e.g., for their own shop, which is trivial to obtain by installing a test app) captures a valid `(raw_body, hmac)` pair signed with the app's `client_secret`, then replays it to the app's public webhook endpoint with an arbitrary `X-Shopify-Shop-Domain` header value. `HmacValidator.validate` still succeeds because it only checks the body, so `Registry.process` will invoke the handler believing the event came from the victim shop named in the header.

### Impact Explanation
This crosses the tenant boundary: an app that keys any per-shop side effect (writes, cache invalidation, redaction handling, `shop/redact`/`customers/redact` flows, etc.) off `WebhookMetadata#shop` can be made to apply the body payload against a shop the attacker does not own, i.e., cross-tenant data corruption/confusion delivered by an unprivileged internet actor with no access token or leaked secret. This meets the Critical bar of cross-tenant access.

### Likelihood Explanation
Requires only: (1) a publicly reachable webhook endpoint built with this gem, standard for any Shopify app, and (2) one legitimate webhook body+hmac pair, obtainable by the attacker for their own shop/dev store. No secrets, no privileged accounts, no TLS interception needed — only header replay against a public HTTP endpoint.

### Recommendation
Bind the `shop-domain`, `topic`, and `webhook-id` header values into the signed payload before comparison (e.g., include a canonicalized representation of the relevant headers in `to_signable_string`, or independently verify `shop` against session/tenant records established out of band), so a header cannot be substituted while reusing a previously valid body/HMAC pair.

### Proof of Concept
1. Register a test/dev shop `attacker.myshopify.com` with the target app; trigger any webhook topic the app handles (e.g. `orders/create`) to capture a legitimate delivery: raw body `B` and header `X-Shopify-Hmac-Sha256: H` (valid for the app's `client_secret`).
2. Replay an HTTP POST to the app's webhook endpoint with the same body `B` and header `H`, but set `X-Shopify-Shop-Domain: victim-shop.myshopify.com` (and, if desired, `X-Shopify-Topic`/`X-Shopify-Webhook-Id` to whatever is useful).
3. `ShopifyAPI::Webhooks::Registry.process` calls `Utils::HmacValidator.validate(request)`, which passes because it only hashes `B`.
4. The handler receives `WebhookMetadata.new(topic: ..., shop: "victim-shop.myshopify.com", body: parsed(B), ...)` and performs its shop-scoped action against `victim-shop.myshopify.com`, even though that shop never sent this webhook.

        def validate_signature(verifiable_query, secret)
          received_signature = verifiable_query.hmac
          computed_signature = compute_signature(verifiable_query.to_signable_string, secret)
          OpenSSL.secure_compare(computed_signature, T.must(received_signature))
