### Title
LP seeded away from curve-close price via unbounded `totalSupply() == 0` dust pre-seed of the HyperSwap V2 pair - ([File: packages/contracts/src/Bonding.sol])

### Summary
`Bonding._seedUniswapV2Direct` treats *any* pre-existing HyperSwap V2 pair whose `totalSupply() == 0` as a "negligible dust pre-seed" and routes it straight into `_seedDirectMint` with **no size bound**, unlike the sibling "mint pre-seed" branch (`_seedRebalancing`) which only bypasses ratio-correction when the pre-seed is below `DIRECT_MINT_PRESEED_BPS` (1 bp). An attacker can pre-create the canonical TOKEN/LT pair, dump an arbitrarily large one-sided donation into it, and call the pair's own permissionless `sync()` — this sets large reserves while `totalSupply()` stays `0` (no LP was ever minted). When `finalizeGraduation` later runs, this path is taken unconditionally, and Uniswap V2's first-mint formula computes the opening reserves/price from the *balances* (attacker's donation + the curve's `tokensForLP`/`ltFromPair`), permanently locking the LP at a price far from the curve-close ratio.

### Finding Description
`Bonding._seedUniswapV2Direct` (`packages/contracts/src/Bonding.sol:1201-1234`) implements three regimes for seeding the graduated V2 pair, deliberately hardened against a "mint pre-seed" (regime 3, `_seedRebalancing`) where the pre-seeder actually calls `pair.mint`. That branch is protected by `DIRECT_MINT_PRESEED_BPS`: [1](#0-0) , so a large pre-seed is forced through the ratio-correcting `_pairRebalance` + router-deposit path instead of a naked direct mint.

However, regime 1 — reached whenever `IUniswapV2Pair(pair).totalSupply() == 0` — has no such size check: [2](#0-1) 

The `skim(address(this))` call immediately preceding this check cannot recover a donation that has already been folded into reserves via `sync()` — `skim` only pulls `balance - reserve`, which is zero once `sync()` has equalized them. So an attacker can:
1. Call the real `IUniswapV2Factory(uniswapV2Factory).createPair(tokenAddress, lt)` themselves (permissionless, standard V2 factory function) for a token that is still trading on the curve.
2. Acquire LT (or, post some curve activity, TOKEN) and `transfer` a large one-sided amount directly to the pair, then call the pair's own `sync()` — a totally standard, permissionless Uniswap V2 pair function.
3. This leaves `getReserves()` large/skewed while `totalSupply() == 0` (no LP token has ever been minted, since the attacker never called `mint`).
4. Later, when the token graduates and anyone calls `Bonding.finalizeGraduation`, `_ensureUniswapV2Pair` finds this pre-existing pair (`getPair` returns non-zero) at `packages/contracts/src/Bonding.sol:1121-1130`, and `_seedUniswapV2Direct` takes the unconditional `totalSupply() == 0` branch straight into `_seedDirectMint`: [3](#0-2) 

Because this is the *first* mint on the pair (`totalSupply()==0`), Uniswap V2's `mint()` sets `liquidity = sqrt(balance0*balance1)` and, via `_update`, sets the pair's `reserve0/reserve1` (i.e. the pool's opening price) equal to the **current token balances** — which now include the attacker's donation on top of `(tokensForLP, ltFromPair)`. The curve-close price invariant that the rest of the file goes to great lengths to preserve (`tokensForLP / ltFromPair == tokenReserve/assetReserve` at curve close, per the natspec on `_prepareGraduationLiquidity`) is broken: the graduated pool opens at whatever ratio the attacker chose for their donation, not at the curve's closing price.

### Impact Explanation
The freshly seeded LP — permanently locked via the one-shot `LPLock.recordLock` call in `finalizeGraduation` (`packages/contracts/src/Bonding.sol:1031`, no rescue path per the code's own comments) — opens at an attacker-controlled price instead of the curve-close price. Any arbitrageur (including the attacker) can then trade against the mispriced pool immediately after seeding to extract value: buying the underpriced side / selling the overpriced side pulls real TOKEN/LT out of the newly locked liquidity at the expense of the protocol, the creator, and legitimate post-graduation traders. Because the LP is irrevocably locked, this loss is permanent — it directly matches the accepted impact class "an LP seeded away from the curve close price."

### Likelihood Explanation
Every step is permissionless and requires no privileged role: creating a Uniswap-V2-fork pair via the factory, transferring an owned ERC-20 to an address, and calling that pair's own `sync()` are all standard, unauthenticated actions any wallet can take before a token's `finalizeGraduation` fires. The attacker only needs to know the deterministic (`tokenAddress`, `ltAddress`) pair in advance, which is public the moment a token is launched, and can act at any point in the token's `Curve`/`Graduating` lifecycle before phase 2 executes.

### Recommendation
Apply the same size/ratio guard used in `_seedRebalancing` (`DIRECT_MINT_PRESEED_BPS`) to the `totalSupply() == 0` branch of `_seedUniswapV2Direct` as well: after `skim`, re-read the pair's reserves and only take the unconditional direct-mint fast path when both reserves are within the negligible band relative to `(tokensForLP, ltFromPair)`; otherwise route through the rebalancing/`addLiquidity`-with-quote path (or burn/skim the donation before minting) so the opening price cannot be pushed away from curve close regardless of whether the pre-seeder minted LP or merely donated + synced.

### Proof of Concept
1. `Zap.createToken` launches `TOKEN` paired with `LT` on the curve; deterministic V2 pair address for `(TOKEN, LT)` is now known.
2. Attacker calls `IUniswapV2Factory(uniswapV2Factory).createPair(TOKEN, LT)` directly (bypassing `Bonding`).
3. Attacker mints/acquires a large amount of `LT`, `transfer`s it to the pair, then calls `pair.sync()`. Now `getReserves() = (0, hugeLT)` while `pair.totalSupply() == 0`.
4. Curve trading pushes the token to graduation (`canGraduate` true); `_enterGraduating` runs, caching `(tokensForLP, ltFromPair)` at the true curve-close ratio.
5. Anyone calls `Bonding.finalizeGraduation(TOKEN)`. `_ensureUniswapV2Pair` returns the attacker's pre-created pair; `_seedUniswapV2Direct` sees `totalSupply()==0` and calls `_seedDirectMint(TOKEN, LT, pair, tokensForLP, ltFromPair)` unconditionally.
6. `_seedDirectMint` transfers `tokensForLP` TOKEN and `ltFromPair` LT into the pair (now holding `tokensForLP` TOKEN and `ltFromPair + hugeLT` LT) and calls `pair.mint(lpLock)`. The pool's opening price is `(ltFromPair + hugeLT) / tokensForLP`, far above the true curve-close price `ltFromPair / tokensForLP`.
7. Attacker (or a bot) immediately swaps TOKEN into the pool at the inflated LT price, draining real value from the locked LP before the market arbitrages it back — value permanently lost to `LPLock`-held liquidity since it cannot be rebalanced or rescued afterward.

    function _seedDirectMint(
        address tokenAddress,
        address lt,
        address pair,
        uint256 tokensForLP,
        uint256 ltFromPair
    ) internal returns (uint256 liquidity) {
        IERC20(tokenAddress).safeTransfer(pair, tokensForLP);
        IERC20(lt).safeTransfer(pair, ltFromPair);
        liquidity = IUniswapV2Pair(pair).mint(_s().lpLock);
        uint256 leftoverToken = IERC20(tokenAddress).balanceOf(address(this));
        if (leftoverToken > 0) {
            Token(tokenAddress).burn(address(this), leftoverToken);
        }
    }
