### Title
Webhook shop identity (`shop-domain` header) is not covered by the HMAC signature, allowing cross-tenant webhook replay - (File: `lib/shopify_api/webhooks/request.rb`)

### Summary
`ShopifyAPI::Webhooks::Request` authenticates an incoming webhook by computing an HMAC over the raw request body only, while the tenant identifier (`shop`) that the host application will use to route/act on the webhook is read from an HTTP header that is never included in the signed bytes.

### Finding Description
`Request#to_signable_string` returns only `@raw_body`: [1](#0-0) 

`Request#hmac` and the `HmacValidator` compute/verify the signature strictly against that signable string: [2](#0-1) [3](#0-2) 

Meanwhile, `Request#shop` — the value a host app is expected to use to identify which tenant/merchant the webhook belongs to — is pulled straight from the `X-Shopify-Shop-Domain` (or `Shopify-Shop-Domain`) header, which is not part of `to_signable_string` and therefore is entirely outside the cryptographic check: [4](#0-3) [5](#0-4) 

This is structurally the same class of defect as the reported Solidity bug: the code validates one thing (`proposalIndex` against `lastProposalIndex`, here: the *body* against its HMAC) but then acts on a related-but-different value that was never checked against that validation (the *wrong array slot* deleted, here: the *shop* header trusted for tenant routing). The equality that should hold — `verified_bytes == acted_upon_identity` — is broken: `HMAC-verifies(raw_body)` is true, but `shop` (used to decide "whose data is this") is never bound into that verified region.

### Impact Explanation
Because `topic`, `webhook_id`, and `shop` are all sourced from headers outside the HMAC's coverage, once an attacker is in possession of a single validly-signed `(raw_body, hmac)` pair for the app (e.g. a real webhook the app receives for one installed shop, or any body the attacker can get legitimately signed by triggering an event on a shop they control), they can replay that exact body/HMAC pair to the app's public webhook endpoint while substituting an arbitrary `X-Shopify-Shop-Domain` header naming a different, victim shop. `HmacValidator.validate` will still return `true` (it only checks the body), and any host code that trusts `request.shop` for tenant attribution — the documented and only way this gem exposes shop identity for webhooks — will process attacker-supplied payload content as if it belongs to the victim tenant. Depending on how the host acts on that payload (data writes keyed by shop, session/state changes, `app/uninstalled` side effects, etc.), this enables cross-tenant data confusion/injection, which falls under the Critical "cross-tenant access" bucket.

### Likelihood Explanation
Exploitation requires the attacker to already hold one valid `(raw_body, hmac)` pair for the app (obtainable without needing `api_secret_key` or any merchant's access token, e.g., by legitimately triggering a webhook on the attacker's own installed shop and capturing the delivery), plus the ability to POST directly to the app's public webhook receiving endpoint with a forged shop header — both of which are attainable by an unprivileged internet user/merchant. No secret material or account of the victim shop is required.

### Recommendation
Bind the shop (and ideally topic/webhook-id) into the signed material that `HmacValidator` checks, or otherwise cryptographically tie the trusted header set to the raw body before exposing `Request#shop`/`Request#topic` as authenticated accessors — e.g., include the shop domain in `to_signable_string`, or require the host to independently confirm the delivered `shop` value corresponds to a shop for which the app expected this specific webhook (topic + webhook_id) before trusting it for any tenant-scoped action.

### Proof of Concept
1. Install the app on shop A (`shop-a.myshopify.com`) and trigger any webhook event, capturing the raw POST body and its `X-Shopify-Hmac-Sha256` value delivered by Shopify.
2. Replay that exact body and HMAC header to the app's webhook endpoint, but set `X-Shopify-Shop-Domain: shop-b.myshopify.com` (victim shop).
3. `ShopifyAPI::Utils::HmacValidator.validate` on the constructed `Request` returns `true` because it only checks `@raw_body` against the HMAC.
4. `Request#shop` reports `shop-b.myshopify.com`, so any host logic keyed off `request.shop` processes shop A's payload as belonging to shop B. [6](#0-5)

module ShopifyAPI
  module Webhooks
    class Request
      extend T::Sig
      include Utils::VerifiableQuery

      sig { override.returns(String) }
      def hmac
        Digest.hexencode(Base64.decode64(T.cast(shopify_header("hmac-sha256"), String)))
      end

      sig { returns(String) }
      def topic
        T.cast(shopify_header("topic"), String)
      end

      sig { returns(String) }
      def shop
        T.cast(shopify_header("shop-domain"), String)
      end

      sig { returns(String) }
      def api_version
        T.cast(shopify_header("api-version"), String)
      end

      sig { returns(String) }
      def webhook_id
        T.cast(shopify_header("webhook-id"), String)
      end

      sig { override.returns(String) }
      def to_signable_string
        @raw_body
      end

      sig { returns(T::Hash[String, T.untyped]) }
      def parsed_body
        JSON.parse(@raw_body)
      end

      sig { params(raw_body: String, headers: T::Hash[String, T.untyped]).void }
      def initialize(raw_body:, headers:)
        # normalize the headers by forcing lowercase, removing any prepended "http"s, and changing underscores to dashes
        headers = headers.to_h { |k, v| [k.to_s.downcase.sub("http_", "").gsub("_", "-"), v] }

        missing_headers = []
        ["topic", "hmac-sha256", "shop-domain"].each do |name|
          unless headers.key?("shopify-#{name}") || headers.key?("x-shopify-#{name}")
            missing_headers << "shopify-#{name} or x-shopify-#{name}"
          end
        end
        unless missing_headers.empty?
          raise Errors::InvalidWebhookError,
            "Missing one or more of the required HTTP headers to process webhooks: #{missing_headers}"
        end

        @headers = headers
        @raw_body = raw_body
      end
