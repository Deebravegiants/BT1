Based on my research, I found a legitimate structural analog to CVE-2017-11142 in this codebase's free/unpriced ISMP message-validation path.

### Title
Unbounded free-of-charge CPU consumption via unsigned `handle_unsigned` batches in `pallet-ismp` and `pallet-state-coprocessor` - (File: `modules/pallets/ismp/src/lib.rs`, `modules/pallets/state-coprocessor/src/lib.rs`)

### Summary
CVE-2017-11142 is a CPU-exhaustion DoS caused by PHP processing an attacker-controlled, unbounded quantity of input "variables" for free before any authorization/cost gate is applied. Hyperbridge has a structurally identical pattern: both `pallet_ismp::Pallet::validate_unsigned` and `pallet_state_coprocessor::Pallet::validate_unsigned` fully execute the submitted ISMP message batch — including SCALE decode, dedup, keccak hashing of every request/response, and full membership/state proof verification — during unsigned transaction-pool validation, which runs for free on every full node in the network, before any fee or per-item bound is enforced.

### Finding Description
`pallet_ismp`'s `validate_unsigned` is explicitly documented as allowing "users execute ISMP datagrams for free": [1](#0-0) 

It calls `Self::execute(messages.clone())` directly inside mempool validation, where `messages: Vec<Message>` and each `Message::Request`/`Message::Response` carries an unbounded `Vec<PostRequest>` / `Vec<GetRequest>`: [2](#0-1) 

The identical pattern exists in `pallet_state_coprocessor`, whose `GetRequestsWithProof.requests: Vec<GetRequest>` is likewise unbounded, and whose `validate_unsigned` runs `Self::handle_get_requests(message.clone())` — full dedup, timeout checks, and (crucially) `verify_membership`/`verify_state_proof` cryptographic proof verification — before any fee gate: [3](#0-2) [4](#0-3) 

Neither `RequestMessage`, `ResponseMessage`, nor `GetRequestsWithProof` bound the number of batched requests/keys with a `BoundedVec` or explicit `ensure!(len <= MAX)` check at the pallet level; the only ambient limit is Substrate's generic max-extrinsic/block-length configuration, which caps *bytes*, not the CPU cost per byte (each request triggers a keccak hash, a `dedup_requests` sort/compare pass, and — for GET batches — real cryptographic state-proof verification). Since `handle_unsigned`/its GET-request analog are unsigned extrinsics reachable by any unprivileged relayer/gossiping peer with zero balance, an attacker can construct maximally-sized batches (many requests, each near the max body/key size) and gossip them repeatedly; every node re-validates the full batch — including proof verification — in `validate_unsigned` before rejecting or accepting, for free, on every propagation hop.

### Impact Explanation
This is analogous to the CVE's "long form variables ⇒ CPU consumption DoS": an unauthenticated/unpriced actor can force the entire validator/full-node set to spend disproportionate CPU (hashing + proof verification over large, attacker-sized batches) with no economic cost, since the fee (`WeightFeeHandler`) is only charged `on_executed`, after the free `validate_unsigned` pass has already done the expensive work. Sustained abuse degrades block production and transaction-pool throughput network-wide — a route-unable-to-deliver-messages condition for the whole bridge.

### Likelihood Explanation
Moderate-to-high: the attack requires no signed transaction, no fee, and no privileged role — only gossiping unsigned extrinsics, which `pallet_ismp`'s own doc comment flags as "use with caution." The main friction is the generic Substrate max-extrinsic-size limit and `longevity`/`provides` tag dedup in the transaction pool, which bound rate somewhat but do not bound the CPU cost of a single large batch.

### Recommendation
Enforce an explicit, low `MaxRequestsPerBatch`/`MaxKeysPerRequest`-style bound (via `BoundedVec` or `ensure!`) on `RequestMessage::requests`, `ResponseMessage::requests`, and `GetRequestsWithProof::requests` before any decoding/hash/proof work is performed in `validate_unsigned`, and consider moving expensive proof verification out of the free `validate_unsigned` path (or charging a nominal weight-based cost during validation itself) so unpriced peers cannot force full cryptographic verification for free.

### Proof of Concept
1. Construct an unsigned extrinsic calling `pallet_state_coprocessor::handle_unsigned` (or `pallet_ismp::handle_unsigned`) with a `GetRequestsWithProof`/`Message::Response` whose `requests` vector is filled up to the block's max extrinsic size with distinct `GetRequest`s (varying `nonce`/`keys` to avoid trivial dedup pruning) and a syntactically-plausible-but-ultimately-invalid proof.
2. Submit and re-gossip many such extrinsics (varying content so `provides` tags differ) via the P2P transaction pool.
3. Observe that every full node executing `validate_unsigned` performs the full `dedup_requests`, per-request hashing, and `verify_membership`/`verify_state_proof` cryptographic work for each batch before rejecting it for an invalid proof — at zero cost to the attacker — repeatable indefinitely to degrade node CPU and mempool throughput. 	pub fn handle_get_requests(
		GetRequestsWithProof { requests, source, response, address }: GetRequestsWithProof,
	) -> Result<(), Error> {
		// 1. Verify source proofs
		// 2. Extract fees
		// 3. Verify response proof
		// 4. insert GetResponse into mmr and request receipts
		// 5. emit Response events
		let host = <<T as Config>::IsmpHost>::default();

		// Reject duplicate requests within the batch.
		let wrapped: Vec<Request> = requests.iter().cloned().map(Request::Get).collect();
		dedup_requests::<<T as Config>::IsmpHost>(&wrapped)?;

		for req in requests.iter() {
			let full = Request::Get(req.clone());

			// Get requests time out are relative to Hyperbridge
			if full.timed_out(host.timestamp()) {
				Err(Error::RequestTimeout { meta: full.clone().into() })?
			}

			// Source of the request must match the proof
			if full.source_chain() != source.height.id.state_id {
				Err(Error::RequestProofMetadataNotValid { meta: full.clone().into() })?
			}

			// Proof must come from the requested chain
			if full.dest_chain() != response.height.id.state_id {
				Err(Error::RequestProofMetadataNotValid { meta: full.clone().into() })?
			}

			// This request has already been responded to. Mirror `handlers/response.rs:61`:
			// dedup against `response_receipt`, which the dispatch path writes for this exact
			// GetRequest hash after producing a response. The receipt also binds the response
			// commitment, so external auditors can attest "Hyperbridge produced response X for
			// request Y" from one map.
			let probe = GetResponse { get: req.clone(), values: Default::default() };
			if host.response_receipt(&probe).is_some() {
				Err(Error::DuplicateResponse { meta: (&probe).into() })?
			}
		}

		// Ensure the proof height is equal to each retrieval height specified in the Get
		// requests
		if !requests.iter().all(|get| get.height == response.height.height) {
			Err(Error::InsufficientProofHeight)?
		}

		// Verify source proof
		let source_state_machine = validate_state_machine(&host, source.height)?;
		let state_root = host.state_machine_commitment(source.height)?;

		// Verify membership proof to ensure that requests where committed on source chain
		let commitments = requests
			.iter()
			.map(|get| hash_request::<<T as Config>::IsmpHost>(&Request::Get(get.clone())))
			.collect();
		source_state_machine.verify_membership(&host, commitments, state_root, &source)?;
