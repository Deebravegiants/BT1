### Title
No identity-continuity binding across left/right/self-custody frames in biometric capture allows mixed-subject capture set - (File: src/plans/biometric_capture/mod.rs, src/plans/biometric_capture/overcapture.rs)

### Summary
`handle_rgb_net` in `overcapture.rs` merely delegates to `biometric_capture::Plan::handle_rgb_net`, which stores whichever RGB-Net estimate has a valid bounding box into the `left_rgb`/`right_rgb` slot for the currently targeted eye, and separately the face-identifier candidate into `self_custody_candidate_rgb` based only on `is_valid`/score. None of these per-frame acceptance checks compare face embeddings, iris codes, or any other identity signal between the left-eye frame, right-eye frame, and self-custody face frame that ultimately get bundled together in `into_capture`.

### Finding Description
`overcapture::Plan::handle_rgb_net` (src/plans/biometric_capture/overcapture.rs:82-89) forwards every RGB-Net output directly to `biometric_capture::Plan::handle_rgb_net` [1](#0-0) , without adding any identity-consistency logic of its own.

The core acceptance logic in `biometric_capture::Plan::handle_rgb_net` only checks that the RGB-Net bounding box is geometrically valid (`is_correct()`) before overwriting `left_rgb`/`right_rgb` for the eye side currently targeted by `self.target_left_eye`: [2](#0-1) 

Similarly, `handle_ir_net` only checks `perceived_side`, `score`, brightness range and a timing gate (`valid_capture_after`) — again with no identity/embedding check — before storing the IR frame into `left_ir`/`right_ir`: [3](#0-2) 

The self-custody face candidate is selected purely by the highest `face_identifier` validity score seen so far, again with no cross-check against the previously captured eye frames: [4](#0-3) 

Finally, `into_capture` assembles `left_ir`, `left_rgb`, `right_ir`, `right_rgb`, and `face_self_custody_candidate` into a single `Capture` struct purely by whichever data happens to be present in each slot — there is no check that these frames originated from a continuously tracked, single subject: [5](#0-4) 

`run_check`/`poll_extra` gate progression on eye-quality/timing conditions (sharp iris + rgb frame present, or timeout), not on subject identity continuity: [6](#0-5) [7](#0-6) 

Because the objectives are processed sequentially — first the left eye (or right, chosen randomly at `Plan::new`), then the right eye, with a `delay_between_eye_captures` gap between them (`run_check` at line 499) — an attacker could physically swap places with another person during that gap, or during an `overcapture` extension window (up to `overcapture_duration`, default 1000ms, plus the surrounding `sleep(1000ms)` in `overcapture::Plan::run`), such that the left-eye/right-eye/self-custody frames captured into a single `Capture` come from two different individuals. Nothing in the reachable code path re-validates that the second eye or the self-custody face frame belongs to the same person whose first eye was captured.

### Impact Explanation
If exploitable, this would let an unprivileged party create a single biometric `Capture` record blending iris/face data from two different people. Depending on downstream processing (iris code extraction, uniqueness check, self-custody image binding), this could corrupt the uniqueness invariant that the World ID/Orb system depends on, or bind one person's self-custody face image to another person's iris data. This matches an Immunefi-style impact of "wrong-identity binding" / corrupted biometric uniqueness.

### Likelihood Explanation
Feasibility is constrained by the very short capture windows involved (a total signup capture is typically a few seconds; `delay_between_eye_captures` and the overcapture window are on the order of ~1 second), requiring precise physical timing by two cooperating people, and any accidental interruption (target/perceived-side mismatch, insufficient sharpness score, occlusion) would simply cause that slot to remain unfilled and the capture to time out or retry rather than silently blend identities. There is no evidence in the reachable code of any downstream identity-consistency check (e.g., embedding-distance comparison) that would catch a successfully swapped capture before signup finalization, based on what is visible in this file/module; whether a later stage (e.g., backend-side dedup/uniqueness check, or an iris-code comparator elsewhere in the pipeline not covered here) mitigates this could not be fully confirmed from the code explored.

### Recommendation
Add an identity-continuity check before merging left/right/self-custody frames into a single `Capture` — e.g., compare face-identifier embeddings (or IR-Net/RGB-Net facial features) between the frame that produced `left_ir`/`left_rgb`, the frame that produced `right_ir`/`right_rgb`, and the `self_custody_candidate_rgb` frame, and reject/reset the capture (returning to the beginning of the objective sequence) if similarity falls below a threshold. This check should live in `biometric_capture::Plan` (e.g., in `run_check` or `into_capture`) so it applies uniformly to all extensions (`overcapture`, `focus_sweep`, `mirror_sweep`, `multi_wavelength`, `pupil_contraction`) that delegate to it.

### Proof of Concept
Integration test plan (in `src/plans/biometric_capture/mod.rs` test module or a new test):
1. Construct a `biometric_capture::Plan` with mocked/injected `rgb_net`/`ir_net`/`face_identifier` outputs.
2. Feed a synthetic frame sequence: left-eye objective frames tagged with "subject A" embedding/features, satisfying `IRIS_SCORE_MIN` and bbox validity, causing `left_ir`/`left_rgb` to populate.
3. After the objective switches (simulate `delay_between_eye_captures` elapsing), feed right-eye objective frames tagged with "subject B" embedding/features, again satisfying validity thresholds, causing `right_ir`/`right_rgb` to populate.
4. Feed a self-custody-candidate frame tagged "subject B" (or a third subject C) that passes `face_identifier::is_valid`.
5. Drive `run_check`/`poll_extra` to completion and call `into_capture()`.
6. Assert that `into_capture()` returns `Some(Capture)` even though `left_*` and `right_*`/`face_self_custody_candidate` originate from different subjects — demonstrating that no rejection occurs. Expected (fixed) behavior: the plan should detect the mismatch and either return `None` or restart the objective sequence instead of assembling a mixed-subject `Capture`.

    fn handle_ir_net(
        &mut self,
        orb: &mut Orb,
        output: port::Output<ir_net::Model>,
        frame: Option<camera::ir::Frame>,
    ) -> Result<BrokerFlow> {
        match output.value {
            ir_net::Output::Estimate(estimate) => {
                self.update_occlusion(orb, &estimate);
                if let Some(perceived_side) = estimate.perceived_side {
                    if perceived_side != i32::from(!self.target_left_eye) {
                        tracing::debug!("Skipping frame due to target and perceived side mismatch");
                        return Ok(BrokerFlow::Continue);
                    }
                } else {
                    tracing::debug!("IRNet perceived_side=None, skipping frame");
                    return Ok(BrokerFlow::Continue);
                }

                self.update_ux(orb, estimate.sharpness);

                let frame = frame.expect("frame must be set for an estimate output");
                let valid_capture = estimate.score >= IRIS_SCORE_MIN
                    && (!orb.ir_auto_exposure.is_enabled()
                        || IRIS_BRIGHTNESS_RANGE.contains(&frame.mean()))
                    && self.valid_capture_after <= Instant::now();

                if valid_capture {
                    let slot =
                        if self.target_left_eye { &mut self.left_ir } else { &mut self.right_ir };
                    if slot.is_none() {
                        dd_incr!(
                            "main.count.signup.during.biometric_capture.\
                             first_side_sharp_iris_detected",
                            &format!(
                                "side:{}",
                                if self.target_left_eye { "left" } else { "right" }
                            )
                        );
                    }
                    tracing::debug!("Found sharp iris: {}", estimate.score);
                    *slot = Some(FrameInfoIr::new(estimate, frame));
                }
            }

    fn handle_face_identifier(
        &mut self,
        orb: &mut Orb,
        output: port::Output<face_identifier::Model>,
        frame: Option<camera::rgb::Frame>,
    ) -> Result<BrokerFlow> {
        if let face_identifier::Output::IsValidImage(output) = output.value {
            tracing::debug!("Face self-custody frame score: {:?}", output.score);
            if output.error.is_some() {
                tracing::error!("Face self-custody frame error: {:?}", output);
            }

            if output.is_valid.map_or(false, |v| v) {
                let highest = self
                    .self_custody_candidate_rgb
                    .as_ref()
                    .map_or(0.0, |p| p.estimate.score.unwrap_or_default());
                if output.score.is_some_and(|s| s > highest) {
                    tracing::info!(
                        "New face self-custody frame captured with score: {:?}",
                        output.score
                    );
                    self.self_custody_candidate_rgb = Some(FrameInfoSelfCustodyCandidate::new(
                        output,
                        frame.expect("frame must be set for FaceIdentifier::IsValidImage"),
                    ));
                    self.face_ir = self.last_face_ir.take();
                    self.thermal = self.last_thermal.take();
                }

                orb.only_rgb_net_frames = true;
            }
        }
        Ok(BrokerFlow::Continue)
    }

    fn poll_extra(&mut self, orb: &mut Orb, cx: &mut Context<'_>) -> Result<BrokerFlow> {
        while let Poll::Ready(output) = orb.main_mcu.rx_mut().next_broadcast().poll_unpin(cx) {
            if let mcu::main::Output::Gps(message) = output? {
                self.track_gps(message);
            }
        }

        let (rgb, ir) = if self.target_left_eye {
            (&self.left_rgb, &self.left_ir)
        } else {
            (&self.right_rgb, &self.right_ir)
        };

        // TODO: Maybe we can refactor the following into "objectives termination conditions"? When we switch objectives
        // we can call a function to check if we have completed the objective.

        // Check if we have both the iris and the face.
        if let (Some(_rgb), Some(_ir)) = (rgb, ir) {
            if !self.is_last_objective() {
                // We have completed scanning one side. It's ok for us to move forward even if we don't have the
                // self-custody frame, as still have 1 more eye to capture.
                return Ok(BrokerFlow::Break);
            }
            // We are now in the last objective and we have completed scanning both sides. We Just need to make sure
            // we have an self-custody frame before we completely exit the biometric capture phase.
            if self.self_custody_candidate_rgb.is_some() {
                return Ok(BrokerFlow::Break);
            }
        }

        if let Poll::Ready(()) = self.timeout.poll_unpin(cx) {
            self.timed_out = true;
            return Ok(BrokerFlow::Break);
        }
        Ok(BrokerFlow::Continue)
    }

    pub(crate) async fn run_check(&mut self, orb: &mut Orb) -> Result<bool> {
        if let Some(mirror_offset) = orb.mirror_offset {
            self.mirror_offsets.push(mirror_offset);
        }
        if self.timed_out {
            tracing::info!("Biometric capture timeout");
            return Ok(true);
        }
        if !self.set_next_objective(orb).await? {
            dd_incr!("main.count.signup.during.biometric_capture.both_eye_captured");
            tracing::info!("All objectives achieved");
            orb.ui.biometric_capture_progress(1.1);
            return Ok(true);
        }
        self.valid_capture_after = Instant::now() + self.delay_between_eye_captures;
        Ok(false)
    }
