## Analysis: CPU-exhaustion analog found in the Tendermint/Polygon consensus client's validator-set hashing

The Zabbix CVE is a classic "cheap request parameter, disproportionate CPU cost" bug. The closest reachable analog in this codebase is in the Tendermint (and Polygon, which reuses the same verifier) consensus client's handling of the attacker-supplied `next_validators` list, which is hashed with no size bound before any real cryptographic verification gates it, and this path is reachable via the fee-less `handle_unsigned` extrinsic — including during mempool `validate_unsigned`, i.e. before block inclusion.

### Title
Unbounded attacker-supplied `next_validators` list drives disproportionate CPU cost in Tendermint/Polygon consensus proof validation, reachable via the fee-less `handle_unsigned` extrinsic - (File: `modules/consensus/tendermint/verifier/src/verifier.rs`)

### Summary
`pallet_ismp`'s `handle_unsigned` call is explicitly documented as allowing "users execute ISMP datagrams for free" [1](#0-0)  and its `ValidateUnsigned::validate_unsigned` calls `Self::execute(messages.clone())` directly during mempool validation [2](#0-1) , meaning any peer that receives the gossiped extrinsic pays the verification cost even before block inclusion. For a `ConsensusMessage` targeting the Tendermint/Polygon consensus client, `verify_header_update` calls `extract_validators`, which — whenever the header signals a validator-set rotation — hashes the attacker-supplied `consensus_proof.next_validators: Option<Vec<Validator>>` via `validate_validator_set_hash` [3](#0-2) . Unlike other consensus/proof structures in this codebase (Pharos's `MAX_VALIDATORS` cap [4](#0-3) , sync-committee's SSZ-bounded `List<Validator, VALIDATOR_REGISTRY_LIMIT>` types, BSC's fixed-width 64-bit bitvector), Tendermint's `next_validators` is a plain unbounded `Vec<CodecValidator>` decoded via SCALE with no cap [5](#0-4) .

### Finding Description
`validate_validator_set_hash` iterates every validator in the supplied set, re-encodes each one as a protobuf `SimpleValidator` (decompressing/normalizing the public key), and then computes a Merkle hash over all of them with `cometbft::merkle::simple_hash_from_byte_vectors` [6](#0-5) . This function is invoked by `extract_validators` on the attacker-controlled `provided` validator list whenever the header's `next_validators_hash` differs from the currently trusted one (which is trivially arranged since the attacker also controls the signed header bytes carried in the SCALE-decoded proof) [7](#0-6) . `ConsensusProof::validate()` only checks that `next_validators` is non-empty when required — it never bounds its length [8](#0-7) .

The only limit on the size of this list is the runtime's maximum extrinsic/block length, which is orders of magnitude larger than any real validator set (Cosmos/Heimdall chains have on the order of 100–150 validators). An attacker can pad `next_validators` with tens of thousands of syntactically-valid but bogus `Validator` entries, forcing the client (and every peer relaying the unsigned extrinsic) to perform tens of thousands of key re-encodings and hash computations purely to reach the (inevitable) hash-mismatch rejection — work that scales with an attacker-chosen parameter rather than with any legitimate protocol quantity, exactly the CVE-2025-49643 bug class ("specially crafted parameters causing disproportionate CPU load").

This is materially different from the request-batch/get-response paths and the EVM/Pharos state-proof paths in this repo, which already carry explicit anti-inflation guards (duplicate-key rejection before hashing, `MAX_PROOF_DEPTH`, `MAX_VALIDATORS`, bandwidth metering) — the Tendermint validator-set path lacks an equivalent cap.

### Impact Explanation
Because the cost is paid during `ValidateUnsigned::validate_unsigned` — which every full node executes on receipt of the unsigned extrinsic during transaction-pool gossip, not only on block-authoring nodes — a single crafted message can be broadcast to impose disproportionate CPU load across the network's nodes without paying any transaction fee, degrading availability of the relayer/consensus-update pipeline for the affected state machine (denial of service). This matches the "route unable to deliver messages" acceptance criterion: sustained abuse can starve legitimate Tendermint/Polygon consensus updates from being processed in a timely manner.

### Likelihood Explanation
The path is reachable by any unprivileged actor able to submit or gossip an unsigned extrinsic (`pallet_ismp::Call::handle_unsigned`), which is explicitly designed to be free of charge. Constructing a decodable `ConsensusMessage` with a bloated `next_validators` list requires no cryptographic material beyond well-formed (but bogus) key bytes, and the "rotation signaled" branch is trivially reachable by choosing an arbitrary `next_validators_hash` in the attacker's own header. No privileged role or race condition is needed.

### Recommendation
Enforce an explicit upper bound on `consensus_proof.next_validators.len()` (mirroring the `MAX_VALIDATORS` pattern already used for Pharos, or the SSZ-bounded lists used for sync-committee) inside `ConsensusProof::validate()` or before `validate_validator_set_hash` is invoked in `extract_validators`, rejecting any proof whose validator-set size exceeds the real-world maximum for the tracked chain before any hashing/encoding work is performed.

### Proof of Concept
1. Construct a `TendermintConsensusUpdate` / `CodecConsensusProof` whose `signed_header.header.next_validators_hash` is set to an arbitrary 32-byte value that does not match the trusted state's stored `next_validators_hash`.
2. Set `next_validators` to a `Vec<CodecValidator>` with, e.g., 50,000 entries of dummy-but-well-formed `Ed25519`/`Secp256k1` public keys (well within the default max extrinsic size).
3. Submit as `pallet_ismp::Call::handle_unsigned { messages: [Message::Consensus(...)] }` via the unsigned transaction pool.
4. Observe that every node validating/gossiping the extrinsic executes `extract_validators` → `validate_validator_set_hash`, performing ~50,000 protobuf encodings and SHA-256 hashing operations before the proof is ultimately rejected for hash mismatch — cost fully controlled by the attacker's chosen list size and paid by every receiving peer, not just the submitter.

	pub fn validate(&self) -> Result<(), String> {
		// Validate that if next_validators_hash is not empty, next_validators must be provided
		let header_next_validators_hash = &self.signed_header.header.next_validators_hash;
		if !header_next_validators_hash.is_empty() {
			// Hash is not empty, so next_validators must be provided
			if self.next_validators.is_none() {
				return Err("Header has non-empty next_validators_hash but consensus proof has no next_validators".to_string());
			}
			if self.next_validators.as_ref().unwrap().is_empty() {
				return Err("Header has non-empty next_validators_hash but consensus proof has empty next_validators".to_string());
			}
		}

		if self.height() == 0 {
			return Err("Height cannot be zero".to_string());
		}
		if self.timestamp() == 0 {
			return Err("Timestamp cannot be zero".to_string());
		}
		if self.chain_id().is_empty() {
			return Err("Chain ID cannot be empty".to_string());
		}
		Ok(())
	}

/// Helper function to validate a validator set hash using both main and fallback strategies.
pub fn validate_validator_set_hash(
	validators: &ValidatorSet,
	header_validators_hash: Hash,
	is_next_validators: bool,
) -> Result<(), cometbft_light_client_verifier::errors::VerificationError> {
	let hash = validators.hash_with::<SpIoSha256>();
	if hash != header_validators_hash {
		let validator_bytes: Vec<Vec<u8>> = validators
			.validators
			.iter()
			.map(|validator| {
				let pub_key_bytes = {
					if let Some(secp256k1_key) = validator.pub_key.secp256k1() {
						secp256k1_key.to_encoded_point(false).as_bytes().to_vec()
					} else {
						validator.pub_key.to_bytes()
					}
				};

				let simple_validator_bytes = SimpleValidator {
					pub_key: Some(cometbft_proto::crypto::v1::PublicKey {
						sum: Some(cometbft_proto::crypto::v1::public_key::Sum::Bls12381(
							pub_key_bytes,
						)),
					}),
					voting_power: validator.power.into(),
				};

				simple_validator_bytes.encode_to_vec()
			})
			.collect();

		let simple_validator_hash =
			cometbft::merkle::simple_hash_from_byte_vectors::<SpIoSha256>(&validator_bytes);

		if Hash::Sha256(simple_validator_hash) != header_validators_hash {
			use cometbft_light_client_verifier::errors::VerificationError;
			return if is_next_validators {
				Err(VerificationError::invalid_next_validator_set(header_validators_hash, hash))
			} else {
				Err(VerificationError::invalid_validator_set(header_validators_hash, hash))
			};
		}
	}
	Ok(())
