Confirmed: `Pair.sol` has no owner or admin rescue function — `transferAsset` and `transferToken` are gated purely by `onlyRouter`, and the only caller path is `Router.graduate`, which requires `BONDING_ROLE` and is only ever invoked once, from `Bonding._prepareGraduationLiquidity`, which itself is only reachable while `Lifecycle == Curve`. Once a token's lifecycle advances past `Curve` (into `Graduating`/`Graduated`), that call path is permanently closed off, matching the report's core defect: value sitting in a contract with no function anywhere in the codebase that can ever move it out.

### Title
LT donated directly to a bonding-curve `Pair` becomes permanently unrecoverable once the token graduates - (File: `packages/contracts/src/Pair.sol`, `packages/contracts/src/Router.sol`, `packages/contracts/src/Bonding.sol`)

### Summary
Any LT sent via direct `IERC20.transfer` to a token's `Pair` contract while it is still trading on the bonding curve is intentionally excluded from graduation's LP-seeding math and is left behind in the `Pair`. The only function capable of moving asset tokens out of a `Pair` is `Pair.transferAsset`, callable exclusively by `Router`, which exposes it solely through `sell()` and the `BONDING_ROLE`-gated `graduate()`. `graduate()` is called exactly once per token, from `Bonding._prepareGraduationLiquidity`, and only while the token's lifecycle is `Curve`. After `_enterGraduating` flips the lifecycle, this call path is closed forever — there is no other function, in `Pair`, `Router`, or `Bonding`, that can ever extract that donated LT again.

### Finding Description
`Pair.transferAsset` ( [1](#0-0) ) is `onlyRouter`-gated with no other access path. `Router` only invokes it from `sell()` ( [2](#0-1) ) and from `graduate()` ( [3](#0-2) ), the latter of which is documented as "unreachable once the token's lifecycle has flipped past `Curve`" ( [4](#0-3) ).

`Bonding._prepareGraduationLiquidity` computes `ltFromPair = assetReserve - virtualLtReserve` — i.e., only the LT tracked by the pair's *stored* reserve — and calls `router.graduate(tokenAddress, ltFromPair)` exactly once during phase 1 of graduation ( [5](#0-4) ). Any LT balance in the `Pair` above the stored `assetReserve` (i.e. a direct donation via `transfer`) is, by construction, excluded from `ltFromPair` and therefore never drained. Once `_enterGraduating` sets `info.lifecycle = Lifecycle.Graduating` ( [6](#0-5) ), the token can never re-enter `Lifecycle.Curve`, so `_prepareGraduationLiquidity` — the only caller of `graduate()` — can never run again for that token. The `Pair` contract itself ( [7](#0-6) ) exposes no owner, no `LPLock`-style rescue, and no other withdrawal mechanism whatsoever — `transferAsset`/`transferToken` are its only outbound-asset functions and both are `onlyRouter`.

This is precisely the H-4 pattern: value is deposited into a contract, and by the contract's own design and immutable call graph, no function exists — now or ever, short of a governance-controlled contract upgrade of `Bonding`/`Router` — that can move it back out. The project's own comment in `Router.sol` (line ~193) explicitly frames this as merely a "trust-assumption claim, not an on-chain guarantee," which is an admission that the funds are trapped rather than protected.

### Impact Explanation
Any LT donated to a curve `Pair` — whether accidental (a wrong-address transfer) or the by-product of the documented donation-resistance design for graduation math — is permanently and irrecoverably frozen in the `Pair` contract the moment the token graduates. Since LT itself represents leveraged, yield-bearing collateral (it is minted from USDC and accrues via `exchangeRate()`), any amount left behind constitutes a permanent loss of real economic value with no path to recovery for the protocol, the token's creator, or the donor. Given that `Bonding.launch` deploys `Pair`s permissionlessly and any address (bot, misconfigured integrator, or well-meaning user attempting to "support" a token) can transfer LT to a public, indexable `Pair` address at any point before graduation, this is a systemic freezing risk affecting every token launched by the protocol, not a one-off edge case.

### Likelihood Explanation
Likelihood is moderate to high: `Pair` addresses are publicly known (emitted in `TokenLaunched`), LT is a live ERC20 that any wallet can `transfer` to any address, and graduation (`Bonding.triggerGraduation`/inline via `_executeBuy`) is a normal, expected, permissionless event that every actively-traded token eventually reaches. No privileged role or attacker sophistication is required — a single unprivileged wallet sending `IERC20(lt).transfer(pairAddress, amount)` before the triggering buy is sufficient to strand funds forever once graduation fires.

### Recommendation
Add a governance- or permissionless-gated sweep function analogous to `FeeVault.sweepDonations()` that lets `Router`/`Bonding` drain any `Pair.assetBalance()` in excess of the pair's own accounted reserve to a designated recipient (e.g. the protocol owner, mirroring `_sweepLTToOwner`'s pattern for post-graduation rebalance residue), and make it callable regardless of the token's `Lifecycle` state, rather than exclusively during the one-shot phase-1 `graduate()` call.

### Proof of Concept
1. `Bonding.launch(...)` deploys a new `Token`/`Pair` pair for LT `L`; `TokenLaunched` emits the `Pair` address.
2. Any unprivileged wallet calls `IERC20(L).transfer(pairAddress, X)` at any point while the token trades on the curve — this is a direct ERC20 transfer, requiring no special role.
3. `Pair.assetBalance()` now exceeds `_pool.assetReserve` by `X`; per `_launchTimeVirtualLtReserve`/`_prepareGraduationLiquidity`'s math, `ltFromPair` is derived purely from the stored `assetReserve`, so `X` is excluded from the amount drained by `router.graduate()`.
4. Normal trading continues; eventually `canGraduate()` fires (via a buy or `triggerGraduation()`), `_enterGraduating` sets `Lifecycle.Graduating`, and `finalizeGraduation()` seeds the HyperSwap LP and sets `Lifecycle.Graduated`.
5. From this point forward, no function in `Pair`, `Router`, or `Bonding` can call `Pair.transferAsset` again for this pair — `graduate()`'s sole caller (`_prepareGraduationLiquidity`) is gated on `Lifecycle.Curve`, which this token can never re-enter.
6. `X` LT sits in the dead `Pair` contract permanently, with `Pair.assetBalance()` reporting a nonzero, un-sweepable balance forever.

contract Pair is IPair {
    using SafeERC20 for IERC20;

    address public immutable router;
    address public immutable launchedToken;
    address public immutable assetToken;

    struct Pool {
        uint256 tokenReserve;
        uint256 assetReserve;
        uint256 k;
    }

    Pool private _pool;

    event Mint(uint256 tokenReserve, uint256 assetReserve);
    event Swap(uint256 tokenIn, uint256 tokenOut, uint256 assetIn, uint256 assetOut);

    error OnlyRouter();
    error AlreadyMinted();
    error KInvariantViolated();
    error ZeroAddress();
    error IdenticalTokens();

    modifier onlyRouter() {
        if (msg.sender != router) revert OnlyRouter();
        _;
    }

    constructor(
        address router_,
        address launchedToken_,
        address assetToken_
    ) {
        if (router_ == address(0) || launchedToken_ == address(0) || assetToken_ == address(0)) revert ZeroAddress();
        if (launchedToken_ == assetToken_) revert IdenticalTokens();
        router = router_;
        launchedToken = launchedToken_;
        assetToken = assetToken_;
    }

    function mint(
        uint256 tokenReserve,
        uint256 assetReserve
    ) external onlyRouter returns (bool) {
        if (_pool.k != 0) revert AlreadyMinted();
        _pool = Pool({tokenReserve: tokenReserve, assetReserve: assetReserve, k: tokenReserve * assetReserve});
        emit Mint(tokenReserve, assetReserve);
        return true;
    }

    function swap(
        uint256 tokenIn,
        uint256 tokenOut,
        uint256 assetIn,
        uint256 assetOut
    ) external onlyRouter returns (bool) {
        uint256 newTokenReserve = (_pool.tokenReserve + tokenIn) - tokenOut;
        uint256 newAssetReserve = (_pool.assetReserve + assetIn) - assetOut;
        if ((newTokenReserve + 1) * (newAssetReserve + 1) < _pool.k) revert KInvariantViolated();

        _pool.tokenReserve = newTokenReserve;
        _pool.assetReserve = newAssetReserve;
        emit Swap(tokenIn, tokenOut, assetIn, assetOut);
        return true;
    }

    function transferAsset(
        address recipient,
        uint256 amount
    ) external onlyRouter {
        IERC20(assetToken).safeTransfer(recipient, amount);
    }

    function transferToken(
        address recipient,
        uint256 amount
    ) external onlyRouter {
        IERC20(launchedToken).safeTransfer(recipient, amount);
    }

    function getReserves() external view returns (uint256, uint256) {
        return (_pool.tokenReserve, _pool.assetReserve);
    }

    function k() external view returns (uint256) {
        return _pool.k;
    }

    function tokenBalance() external view returns (uint256) {
        return IERC20(launchedToken).balanceOf(address(this));
    }

    function assetBalance() external view returns (uint256) {
        return IERC20(assetToken).balanceOf(address(this));
    }

    function _prepareGraduationLiquidity(
        address tokenAddress
    ) internal returns (uint256 tokensForLP, uint256 ltFromPair, uint256 lpBurned, uint256 unsoldBurned) {
        address pairAddr = _s().tokenInfo[tokenAddress].pair;
        (uint256 tokenReserve, uint256 assetReserve) = IPair(pairAddr).getReserves();

        unsoldBurned = IPair(pairAddr).tokenBalance();
        if (unsoldBurned > 0) {
            Token(tokenAddress).burn(pairAddr, unsoldBurned);
        }

        ltFromPair = assetReserve - _launchTimeVirtualLtReserve(tokenAddress, pairAddr);
        if (ltFromPair > 0) {
            _s().router.graduate(tokenAddress, ltFromPair);
        }

        tokensForLP = assetReserve == 0 ? 0 : (ltFromPair * tokenReserve) / assetReserve;
        if (tokensForLP > LP_RESERVE) tokensForLP = LP_RESERVE;

        lpBurned = LP_RESERVE - tokensForLP;
        if (lpBurned > 0) {
            Token(tokenAddress).burn(address(this), lpBurned);
        }
    }
