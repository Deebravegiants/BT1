### Title
Unauthenticated Magic QR-Code Triggers Privileged WiFi/Mirror Reset Before Operator Verification - (File: `src/plans/mod.rs`)

### Summary
`handle_magic_operator_qr_code()` is invoked immediately after a QR-code is optically decoded and before `verify_operator_qr_code()` performs the backend authorization check that confirms the presenter is a legitimate, registered operator [1](#0-0) . If the decoded payload matches the `MagicResetWifi` or `MagicResetMirror` variants, the Orb performs the privileged action unconditionally and then discards the QR code, looping back to scan again without ever calling the operator-authorization endpoint [2](#0-1) .

### Finding Description
`qr_scan::operator::Data::try_parse()` recognizes a `magic_action:<name>` text pattern independently of any operator-identity fields, and maps `reset_wifi_credentials` / `reset_mirror_calibration` strings to the `MagicResetWifi` / `MagicResetMirror` enum variants with no cryptographic signature or backend authorization component [3](#0-2) . In both `scan_initial_qr_codes()` and `scan_remaining_qr_codes()`, the raw decoded QR data is routed through `handle_magic_operator_qr_code()` *prior* to `verify_operator_qr_code()`, which is the only step that calls `backend::operator_status::request()` to confirm the presenter holds a valid operator badge [4](#0-3) [5](#0-4) . Because the magic-action branch returns `Ok(None)` right after executing the reset, the loop `continue`s and `verify_operator_qr_code()` is never reached for that code — the privileged action has already run unconditionally, analogous to a state-changing function missing its `onlyHordCongress`/`onlyOperator` access modifier.

`MagicResetWifi` calls `reset_wifi_and_ensure_network()`, which calls `network::reset()` (restoring the default `wpa_supplicant.conf` and disconnecting from the currently configured WiFi) and then `wifi::Plan::ensure_network_connection()`, which — once disconnected — actively scans for and joins WiFi credentials from **any** subsequently presented QR code using MECARD parsing, with no validation of the network or its authenticity [6](#0-5) [7](#0-6) .

### Impact Explanation
Any unauthenticated individual with camera-level access to the Orb (the device's normal, intended interaction channel for QR/MECARD-based operator and WiFi provisioning) can force the device off its currently configured, presumably trusted network and cause it to join an attacker-supplied WiFi network by simply presenting two QR codes in sequence — the magic reset code followed by attacker WiFi credentials — without ever being validated as an authorized operator. Rerouting the Orb's network connection is a foothold for a broader network-level compromise (e.g., MITM positioning against backend API calls used for signup, biometric key exchange, and attestation), which elevates this beyond a low-impact configuration toggle.

### Likelihood Explanation
Likelihood is high: the magic QR code format is a simple, undocumented-but-discoverable static string pattern (`magic_action:reset_wifi_credentials`), requires no cryptographic material, no backend interaction, and is processed unconditionally by the QR decode pipeline in the normal idle/signup scanning loop, exactly the surface an unprivileged member of the public interacts with.

### Recommendation
Move the magic-action authorization check ahead of, or fold it into, the privileged action: require `verify_operator_qr_code()` (or equivalent backend-confirmed operator authorization) to succeed before dispatching `MagicResetWifi` / `MagicResetMirror`, so unauthenticated QR presenters cannot trigger network or calibration resets.

### Proof of Concept
1. Print/display a QR code encoding the literal string `magic_action:reset_wifi_credentials`.
2. Present it to an idle Orb; `scan_operator_qr_code()` decodes it and `handle_magic_operator_qr_code()` immediately executes `reset_wifi_and_ensure_network()` — before any call to `backend::operator_status::request()` [8](#0-7) .
3. The Orb disconnects from its configured WiFi and begins scanning for WiFi-credential QR codes via `wifi::Plan::ensure_network_connection()` [9](#0-8) .
4. Present a second QR code with attacker-controlled MECARD WiFi credentials (`WIFI:S:evil;P:pass;;`); the Orb parses and joins it via `network::join()` [10](#0-9) , all without ever presenting an operator badge that passes backend validation.

        qr_code: qr_scan::operator::Data,

                Ok(Some(qr_code))

                dd_incr!("main.count.signup.during.general.magic_qr.reset_mirror");

                if let Err(err) = &result {
                    tracing::error!("Failed to reset wifi: {err}");
                }
                orb.ui.magic_qr_action_completed(result.is_ok());
                Ok(None)
            }
        }
    }

/// Joins WiFi network using the given `credentials`.
pub async fn join(credentials: Credentials) -> Result<()> {
    spawn_blocking(move || {
        let mut cmd = Command::new(WPA_SUPPLICANT_INTERFACE_BIN);
        cmd.arg("join");
        match credentials.auth_type {
            AuthType::Wep | AuthType::Nopass => {
                cmd.arg("--auth").arg("NONE");
            }
            AuthType::Wpa | AuthType::Sae => {
                cmd.arg("--auth").arg("WPA-PSK");
            }
        }
        cmd.arg("--ssid").arg(hex_string(credentials.ssid.as_bytes()));
        if let Some(password) = &credentials.password {
            cmd.arg("--password").arg(wpa_passphrase(&credentials.ssid, password));
        }
        cmd.status()
            .wrap_err("running `wpa-supplicant-interface`")?
            .success()
            .then_some(())
            .ok_or_else(|| eyre!("`wpa-supplicant-interface` terminated unsuccessfully"))?;
        Ok(())
    })
    .await?
}
