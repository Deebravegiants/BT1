### Title
Accrual-time RAY value overflow permanently freezes a market's funds - (File: common/src/rates/index.rs)

### Summary
The bug class in the report is an arithmetic-overflow panic that aborts processing (qcp/ring QUIC counter overflow → panic → DoS). The direct analog here: debt valuation inside interest accrual overflows `i128` and panics with `GenericError::MathOverflow`. Because every market entrypoint accrues first, once `borrowed * borrow_index` exceeds the RAY value ceiling the market is bricked forever — supply, borrow, withdraw, repay, liquidate, clean_bad_debt and recapitalize all trap in `global_sync`.

### Finding Description
`accrue_step` (`common/src/rates/simulate.rs:60`) computes `borrowed_original = scaled_to_original(borrowed, borrow_index)`, i.e. `Ray::mul` → `mul_div_half_up` (`common/src/math/fp.rs` / `fp_core.rs:108`), which panics with `MathOverflow` when `scaled * index / RAY` does not fit `i128`. The same product is computed again in `calculate_supplier_rewards` (`common/src/rates/index.rs:80-81`) via `borrowed.mul(env, new_borrow_index)`.

`update_borrow_index` caps the index at `MAX_BORROW_INDEX_RAY` (10^36) but that cap does not prevent the *value* overflow: with `borrowed` near the admission cap (~`i128::MAX / 10^(27-d)` ≈ 170 billion whole tokens) the product `borrowed * index` crosses `i128::MAX` long before the index hits its cap.

`global_sync` (`contracts/pool/src/interest.rs:20-33`) runs `accrue_step` before every mutation, so the panic gates every verb. The repo's own test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` (`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-356`) demonstrates this: after the overflow, `withdraw` and `repay` both fail with `MATH_OVERFLOW`, and there is no recovery path — even `clean_bad_debt`/`recapitalize` accrue first.

### Impact Explanation
Permanent freezing of funds: all supplier deposits and outstanding debt in the affected market become unreachable. Liquidation is also blocked, so underwater positions cannot be resolved; if the frozen market's debt backs positions collateralized elsewhere, the protocol carries unremovable bad debt. This is a contract-unable-to-operate condition with trapped token funds, not a transient DoS.

### Likelihood Explanation
Requires a large market (approaching ~170B whole-token scale at the cap ceiling) sustained at high utilization for years — the harness test uses 1 billion 18-decimal tokens at 98% utilization on the steep XLM curve and reaches the cliff before the index cap engages. An unprivileged attacker cannot trigger it alone without whale-scale capital, but no privileged action is needed: `supply` + `borrow` + waiting, then any call to `update_indexes` locks the market. Given real XLM/USDC market sizes this is a medium-severity tail risk, matching the report's Medium rating.

### Recommendation
- Make `accrue_step` clamp at the value ceiling instead of panicking: when `borrowed * new_index` would overflow, cap `new_borrow_index` at `i128::MAX / borrowed` (floor) so accrual stalls rather than traps, mirroring the existing `mul_div_floor_saturating`/`protocol_fee_shares` headroom pattern.
- Alternatively, enforce a dynamic borrow cap `cap <= i128::MAX / MAX_BORROW_INDEX_RAY` (value ceiling ÷ index ceiling) at listing/cap-update time so the product can never overflow within the admitted domain.
- Emit an event / flag the market as accrual-halted so repay-only or unwind paths can still run with accrual skipped.

```rust
// tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321
let mut t = LendingTest::new()
    .with_market(big("BIG18", 18, xlm_curve()))
    .with_market(col())
    .with_max_utilization_disabled_all_markets()
    .build();
lift_caps(&t, "BIG18", 18);
lift_caps(&t, "COL", 7);
let principal = BILLION * 10i128.pow(18);
t.supply_raw(BOB, "BIG18", principal);            // unprivileged supply
let debt = principal / 100 * 98;
t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
t.borrow_raw(ALICE, "BIG18", debt);               // unprivileged borrow, 98% util

loop {
    t.advance_time(YEAR_SECS);
    if t.try_update_indexes_for(&["BIG18"]).is_err() { break; } // panics here first
}
// borrowed * borrow_index > i128::MAX inside calculate_supplier_rewards
// (common/src/rates/index.rs:81) while borrow_index < MAX_BORROW_INDEX_RAY.

// Permanent freeze — every verb accrues first via interest::global_sync:
assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
