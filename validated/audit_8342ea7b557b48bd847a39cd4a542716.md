### Title
Accrual-time `i128` overflow permanently freezes an oversized market - (File: common/src/rates/simulate.rs)

### Summary
`accrue_step` converts total scaled debt and supply back into RAY amounts before applying the borrow-index ceiling, so a sufficiently large market can cross the `i128` representable-value boundary and make every subsequent pool operation revert with `MathOverflow`. [1](#0-0) [2](#0-1) 

The crash is reachable through the permissionless `controller.update_indexes(caller, assets)` path and also precedes ordinary repayments, withdrawals, borrows, liquidations, and parameter changes because those paths load an interest-synced market first. [3](#0-2) [4](#0-3) [5](#0-4) 

### Finding Description
Each accrual step starts by evaluating `borrowed * borrow_index / RAY` and `supplied * supply_index / RAY` through `scaled_to_original` and `Ray::mul`. [6](#0-5) [7](#0-6) 

Those fixed-point operations use an exact intermediate but still require the final RAY value to fit in `i128`; an unrepresentable result panics with `GenericError::MathOverflow`. [2](#0-1) 

The borrow-index cap is applied only after this debt-value multiplication in `calculate_supplier_rewards`, so the cap cannot prevent debt-value overflow on the following accrual. [8](#0-7) [9](#0-8) 

`interest::global_sync` runs this accrual before `supply`, `borrow`, `withdraw`, `repay`, `net_settle`, seizure, recapitalization, revenue claim, flash-loan accounting, and rate-model updates because all of them load a synchronized `Cache`. [4](#0-3) [10](#0-9) 

Consequently, once either market value crosses the `i128` boundary, there is no ordinary non-accreting escape path: repayment and withdrawal call `load_leg`, standalone accrual calls `global_sync`, and even `update_params` accrues before installing a safer curve. [11](#0-10) [12](#0-11) [13](#0-12) 

### Impact Explanation
All token funds accounted for by the affected `(hub_id, asset)` market can become permanently inaccessible: suppliers cannot withdraw, borrowers cannot repay, liquidators cannot settle positions in that market, and recapitalization cannot pass the mandatory accrual step. [4](#0-3) [14](#0-13) 

The protocol’s own regression test demonstrates the failure state: after a large 18-decimal market accrues enough interest, `update_indexes`, `withdraw`, and `repay` all return `MATH_OVERFLOW`, while the borrow index remains below `MAX_BORROW_INDEX_RAY`. [15](#0-14) 

Absent a contract upgrade or migration outside the normal flow, this is a permanent market freeze rather than a temporary failed transaction. [10](#0-9) [13](#0-12) 

### Likelihood Explanation
A caller can create or use its own accounts through `supply(account_id = 0, ...)` and `borrow(...)`, grow a valid high-utilization market, and then trigger or wait for accrual through the permissionless `update_indexes` entrypoint. [16](#0-15) [3](#0-2) 

The existing proof reaches the cliff with `1_000_000_000 * 10^18` base units supplied and 98% of that amount borrowed on a supported 18-decimal market configuration. [17](#0-16) 

The required market size is extreme and depends on admitted caps and sustained accrued index growth, but those sizes remain inside the protocol’s documented arithmetic domain rather than relying on malformed parameters or privileged mutation. [18](#0-17) [19](#0-18) 

### Recommendation
Enforce a worst-case scaled-total bound at supply and debt admission, not merely at the current index: `supplied * MAX_SUPPLY_INDEX_RAY / RAY` and `borrowed * MAX_BORROW_INDEX_RAY / RAY` must remain representable in `i128`. [9](#0-8) [20](#0-19) 

Alternatively, widen accrued market and position values to a larger fixed-point representation and redesign share/index storage accordingly; simply catching `MathOverflow` during accrual would still leave conversion-dependent exits unable to value the market safely. [21](#0-20) [4](#0-3) 

Add a regression assertion that every admitted cap keeps `calculate_scaled_cap`-equivalent market totals below the maximum-index value bound, and test the boundary for every supported decimal width. [22](#0-21) [23](#0-22) 

### Proof of Concept
The repository already contains a deterministic reproduction in `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs`: create a large 18-decimal market, supply `BILLION * 10^18` base units, collateralize a second account, borrow 98% of the supplied market, advance ledger time, and invoke `update_indexes` until accrual returns `MATH_OVERFLOW`. [24](#0-23) 

The equivalent external call sequence is:

```text
supply(
  caller = ATTACKER,
  account_id = 0,
  spoke_id = S,
  assets = [(HubAssetKey { hub_id: H, asset: TARGET }, LARGE_SUPPLY)]
)

supply(
  caller = ATTACKER,
  account_id = 0,
  spoke_id = S,
  assets = [(HubAssetKey { hub_id: H, asset: COLLATERAL }, LARGE_COLLATERAL)]
)

borrow(
  caller = ATTACKER,
  account_id = BORROW_ACCOUNT,
  borrows = [(HubAssetKey { hub_id: H, asset: TARGET }, LARGE_DEBT)],
  to = None
)

update_indexes(
  caller = ATTACKER,
  assets = [HubAssetKey { hub_id: H, asset: TARGET }]
)
```

After the overflow is committed into the reachable state boundary, `withdraw`, `repay`, and subsequent `update_indexes` calls on that market all fail before their operation-specific logic because each begins with `global_sync`. [4](#0-3) [25](#0-24)

```rust
pub fn update_supply_index(env: &Env, supplied: Ray, old_index: Ray, rewards_increase: Ray) -> Ray {
    if supplied == Ray::ZERO || rewards_increase == Ray::ZERO {
        return old_index;
    }

    let total_supplied_value = supplied.mul(env, old_index);

    if total_supplied_value == Ray::ZERO {
        return old_index;
    }

    let new_value = total_supplied_value.checked_add(env, rewards_increase);
    let grown = fp_core::mul_div_floor_saturating(env, new_value.raw(), RAY, supplied.raw());

    let bounded_old = old_index.raw().min(MAX_SUPPLY_INDEX_RAY);
    Ray::from(grown.min(MAX_SUPPLY_INDEX_RAY).max(bounded_old))
```

```rust
pub fn calculate_supplier_rewards(
    env: &Env,
    params: &MarketParams,
    borrowed: Ray,
    new_borrow_index: Ray,
    old_borrow_index: Ray,
) -> (Ray, Ray) {
    let old_total_debt = borrowed.mul(env, old_borrow_index);
    let new_total_debt = borrowed.mul(env, new_borrow_index);

    let protocol_fee = params.reserve_factor.apply_to_ray(env, accrued_interest);
    let supplier_rewards = accrued_interest.checked_sub(env, protocol_fee);

    (supplier_rewards, protocol_fee)
```

```rust
/// Accrues borrow/supply indexes from `last_timestamp` to the cache's current time.
///
/// No-op when no time has elapsed. Splits long gaps into max-sized compound
/// windows, then sets `last_timestamp` to `current_timestamp`.
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

```rust
pub(crate) fn accounting(env: &Env, action: &PoolAction) -> RepayOutcome {
    let (mut cache, position) = ops::load_leg(env, action);
    let amount = action.amount;

    let (burned, overpayment) = cache.resolve_repay(amount, position);
    let net_repay = amount
        .checked_sub(overpayment)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));
    assert_with_error!(
        env,
        net_repay == 0 || burned.raw() > 0,
        GenericError::RepayRoundsToZeroShares
    );

    let position = position.checked_sub(env, burned);
    cache.burn_debt(burned);

    cache.credit_cash(net_repay);

    let snapshot = cache.commit();
    let mutation = cache.position_mutation(position, net_repay);
```
