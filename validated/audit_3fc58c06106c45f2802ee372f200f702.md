### Title
Unstaked balance withdrawal in staking-pool silently loses funds on transfer failure due to missing callback/error handling - (File: staking-pool/src/internal.rs)

### Summary
`StakingContract::internal_withdraw` in `staking-pool/src/internal.rs` decrements the caller's `unstaked` balance and the contract's `last_total_balance` ledger *before* issuing the NEAR transfer, and fires `Promise::new(account_id).transfer(amount)` with no `.then()` callback attached and no check of the promise result whatsoever [1](#0-0) . This is reachable by any unprivileged staking pool depositor through the public `withdraw` and `withdraw_all` entrypoints [2](#0-1) .

### Finding Description
Every other cross-contract transfer/withdraw flow in this codebase that mutates accounting attaches a callback that checks `is_promise_success()`/`PromiseResult` and rolls back state on failure — e.g. the lockup contract's `on_staking_pool_withdraw` [3](#0-2)  and `on_withdraw_unvested_amount` [4](#0-3) , which restore/adjust internal state depending on whether the underlying transfer succeeded.

In contrast, `internal_withdraw` in the staking-pool contract does not do this at all:
```rust
account.unstaked -= amount;
self.internal_save_account(&account_id, &account);
...
Promise::new(account_id).transfer(amount);
self.last_total_balance -= amount;
``` [5](#0-4) 

The account's `unstaked` ledger balance and the contract-wide `last_total_balance` accounting are both permanently decremented as soon as the transfer promise is scheduled, with no callback ever validating that the transfer actually succeeded. If the outbound `Promise::transfer` fails for any reason (e.g., the contract's actual liquid NEAR balance is insufficient to cover the promised `amount`, which can diverge from the `unstaked` bookkeeping due to reward/rounding drift tracked in `internal_ping`, or any other runtime transfer failure), the receipt fails silently: the caller receives nothing, but the code has already deducted their withdrawable balance and the contract's total-balance ledger. There is no mechanism to reclaim or retry the withdrawal because the ledger entry that would have permitted it is gone.

### Impact Explanation
This falls under "Critical: Permanent freezing, unrecoverable lock, or irrevocable loss of user or protocol funds in ... unstake-withdraw ... flows." A user's already-unbonded `unstaked` balance is destroyed from the ledger the moment `withdraw`/`withdraw_all` is called, regardless of whether the actual token transfer succeeds, resulting in irrecoverable loss of funds for the affected delegator with no recourse (the funds are neither in their wallet nor recoverable from the pool's accounting).

### Likelihood Explanation
The entrypoint is public and requires no privilege — any account with an `unstaked` balance can call `withdraw`/`withdraw_all` [2](#0-1) . The failure condition (actual liquid balance being lower than the internally tracked `unstaked` figure) is a plausible outcome of the pool's discretionary reward/fee accounting in `internal_ping`, since only `total_staked_balance`/`total_stake_shares` are reconciled against `account_balance() + account_locked_balance()`, while unstaked-but-not-yet-withdrawn balances rely on that same pooled fund remaining physically present and liquid. There is no test or code path in this file that verifies or restores state on a failed transfer, unlike the equivalent code in `lockup`, indicating this is a genuine gap rather than an intentional design choice.

### Recommendation
Attach a callback to the transfer in `internal_withdraw` (mirroring the `lockup` module's pattern), and only finalize the ledger decrement (or restore the `unstaked` balance and `last_total_balance`) based on the callback's `is_promise_success()` result, so a failed transfer does not silently and irrecoverably erase the user's withdrawable balance.

### Proof of Concept
1. A delegator stakes and later unstakes funds through the normal `unstake` flow, accumulating an `unstaked` balance that becomes available after `NUM_EPOCHS_TO_UNLOCK`.
2. The delegator calls `withdraw(amount)` (or `withdraw_all()`).
3. `internal_withdraw` immediately decrements `account.unstaked` and `self.last_total_balance`, then fires `Promise::new(account_id).transfer(amount)` with no attached callback.
4. If that transfer receipt fails for any runtime reason (e.g., contract's actual liquid balance temporarily insufficient), the funds never reach the delegator, yet the contract's internal ledger already reflects the withdrawal as completed — the delegator has no way to retry or reclaim the amount, resulting in permanent loss of those funds.

    pub(crate) fn internal_withdraw(&mut self, amount: Balance) {
        assert!(amount > 0, "Withdrawal amount should be positive");

        let account_id = env::predecessor_account_id();
        let mut account = self.internal_get_account(&account_id);
        assert!(
            account.unstaked >= amount,
            "Not enough unstaked balance to withdraw"
        );
        assert!(
            account.unstaked_available_epoch_height <= env::epoch_height(),
            "The unstaked balance is not yet available due to unstaking delay"
        );
        account.unstaked -= amount;
        self.internal_save_account(&account_id, &account);

        env::log(
            format!(
                "@{} withdrawing {}. New unstaked balance is {}",
                account_id, amount, account.unstaked
            )
            .as_bytes(),
        );

        Promise::new(account_id).transfer(amount);
        self.last_total_balance -= amount;
    }

    /// It's only allowed if the `unstake` action was not performed in the four most recent epochs.
    pub fn withdraw_all(&mut self) {
        let need_to_restake = self.internal_ping();

        let account_id = env::predecessor_account_id();
        let account = self.internal_get_account(&account_id);
        self.internal_withdraw(account.unstaked);

        if need_to_restake {
            self.internal_restake();
        }
    }

    /// Withdraws the non staked balance for given account.

        let need_to_restake = self.internal_ping();

        let amount: Balance = amount.into();
        self.internal_withdraw(amount);

        if need_to_restake {
            self.internal_restake();
        }
    }

    pub fn on_staking_pool_withdraw(&mut self, amount: WrappedBalance) -> bool {
        assert_self();

        let withdraw_succeeded = is_promise_success();
        self.set_staking_pool_status(TransactionStatus::Idle);

        if withdraw_succeeded {
            {
                let staking_information = self.staking_information.as_mut().unwrap();

            }

                format!(

                    amount.0,
                    self.staking_information
                        .as_ref()
                        .unwrap()
                        .staking_pool_account_id
                )
                .as_bytes(),
            );

                    "The withdrawal of {} from @{} failed",

                    self.staking_information
                        .as_ref()
                        .unwrap()
                        .staking_pool_account_id
                )
                .as_bytes(),
            );

        withdraw_succeeded

    /// Called after the foundation tried to withdraw the terminated unvested balance.
    pub fn on_withdraw_unvested_amount(
        &mut self,
        amount: WrappedBalance,
        receiver_id: AccountId,
    ) -> bool {
        assert_self();

        let withdraw_succeeded = is_promise_success();
        if withdraw_succeeded {
            env::log(
                format!(
                    "Termination Step: The withdrawal of the terminated unvested amount of {} to @{} succeeded.",
                    amount.0, receiver_id
                )
                    .as_bytes(),
            );
            // Decreasing lockup amount after withdrawal.
            self.lockup_information.termination_withdrawn_tokens += amount.0;
            let unvested_amount = self.get_terminated_unvested_balance().0;
            if unvested_amount > amount.0 {
                // There is still unvested balance remaining.
                let remaining_balance = unvested_amount - amount.0;
                self.vesting_information =
                    VestingInformation::Terminating(TerminationInformation {
                        unvested_amount: remaining_balance.into(),
                        status: TerminationStatus::ReadyToWithdraw,
                    });
                env::log(
                    format!(
                        "Termination Step: There is still terminated unvested balance of {} remaining to be withdrawn",
                        remaining_balance
                    )
                        .as_bytes(),
                );
                if self.get_account_balance().0 == 0 {
                    env::log(b"The withdrawal is completed: no more balance can be withdrawn in a future call");
                }
            } else {
                self.foundation_account_id = None;
                self.vesting_information = VestingInformation::None;
                env::log(b"Vesting schedule termination and withdrawal are completed");
            }
        } else {
            self.set_termination_status(TerminationStatus::ReadyToWithdraw);
            env::log(
                format!(
                    "Termination Step: The withdrawal of the terminated unvested amount of {} to @{} failed",
                    amount.0, receiver_id,
                )
                .as_bytes(),
            );
        }
        withdraw_succeeded
    }
