### Title
Single-step `transferCreator()` can permanently misdirect a token's future creator fees to an unrecoverable address - (File: `packages/contracts/src/Bonding.sol`)

### Summary
`Bonding.transferCreator()` changes the fee-attribution `creator` for a launched token in a single, irreversible step, with no destination-address confirmation and no admin override to correct a mistake.

### Finding Description
`Bonding.transferCreator()` writes `info.creator = newCreator` directly after only a zero-address check, with no requirement that `newCreator` accept the role in a second transaction: [1](#0-0) 

This `creator` field is the sole attribution key used by the fee-accrual path: `Zap` reads `Bonding.tokenInfo(token).creator` and forwards it into `FeeVault.accrue`, which credits `creatorBalance[creator]` — a mapping keyed purely by address, with no separate acceptance step: [2](#0-1) 

`FeeVault.claim()` pays out strictly to `msg.sender`'s recorded `creatorBalance`, so only the holder of the private key for the address on record can ever retrieve it: [3](#0-2) 

Crucially, `transferCreator` is gated only by `msg.sender != info.creator` — once `info.creator` is set to a wrong/inaccessible address, that same check makes the mistake permanent: the new (wrong) address is the only one who can call `transferCreator` again, and there is no `onlyOwner`/admin escape hatch in `Bonding.sol` to reset a token's `creator`. This mirrors the "M-02" `changeUberOwner` bug class in the external report — a single-step critical-address rotation that, once set to an address without a corresponding private key, cannot be corrected — except here it's reachable by an ordinary, unprivileged token creator (explicitly in the allowed reachable-surface list) rather than a privileged admin.

Note that this project *does* use `Ownable2StepUpgradeable` for actual contract-ownership rotation (see `packages/contracts/test/OwnershipTransfer.t.sol` and the `FeeVault` header comment noting "a bad `transferOwnership` can be cancelled... single-step transfer... would otherwise brick every owner-only path"), showing the team is aware of and defends against this exact bug class for `Ownable` roles — but `transferCreator`, a separate business-logic role with the same "critical, funds-bearing, irreversible" characteristics, was left as a single-step write.

### Impact Explanation
If the current creator calls `transferCreator(tokenAddress, newCreator)` with an incorrect address (typo, unsupported contract, or an address whose key is not held), every future buy/sell fee accrued for that token (0.25% of volume, per `docs/contracts-scope.md` fee rate) is credited via `FeeVault.accrue` to `creatorBalance[newCreator]`, which becomes permanently unclaimable since no one controls that address and there is no way to reassign `info.creator` back. This is a permanent freezing of creator funds for the life of that token — the bug class's real-world impact (low probability, high/permanent impact) directly transposes onto alt.fun.

### Likelihood Explanation
Requires only a legitimate creator's own mistake (fat-fingered address, wrong-chain/wrong-format address, or unsupported contract address) in a permissionless function they are entitled to call — no attacker collusion needed, matching the low-probability/high-impact profile the original report describes for `uberOwner`.

### Recommendation
Convert `transferCreator` into a two-step process (`proposeCreator` / `acceptCreator`), analogous to the `Ownable2StepUpgradeable` pattern already used elsewhere in the codebase for `owner()` rotation: the current creator nominates a `pendingCreator`, and only that `pendingCreator` calling a follow-up function actually takes over `info.creator`, with the ability to re-propose if the wrong address was set before it's accepted.

### Proof of Concept
1. `creator` launches a token via `Bonding.launch`, `info.creator = creator`.
2. Trading accrues creator fees normally through `Zap` → `FeeVault.accrue`, crediting `creatorBalance[creator]`.
3. `creator` calls `bonding.transferCreator(tokenAddress, wrongAddress)` where `wrongAddress` is a valid non-zero address but one whose private key nobody holds (e.g. a mistyped address). This succeeds because the only checks are `newCreator != 0` and `newCreator != info.creator` (`packages/contracts/src/Bonding.sol:738-748`).
4. Subsequent trades continue to attribute fees to `wrongAddress` via `FeeVault.accrue` (`packages/contracts/src/FeeVault.sol:101-123`).
5. No account can call `FeeVault.claim()` successfully for that balance (requires `msg.sender == wrongAddress`), and no account (not even the protocol owner) can call `Bonding.transferCreator` again for this token since it requires `msg.sender == info.creator == wrongAddress`. All future creator fees for the token are permanently locked.

```text
    function transferCreator(
        address tokenAddress,
        address newCreator
    ) external {
        if (newCreator == address(0)) revert ZeroAddress();
        TokenInfo storage info = _s().tokenInfo[tokenAddress];
        if (msg.sender != info.creator) revert NotCreator();
        if (newCreator == info.creator) revert InvalidInput();
        info.creator = newCreator;
        emit CreatorTransferred(tokenAddress, msg.sender, newCreator);
    }
```

```text
    function accrue(
        address token,
        address creator,
        uint256 creatorAmount,
        uint256 protocolAmount,
        bool isBuy
    ) external onlyDepositor {
        FeeVaultStorage storage $ = _s();
        if (creatorAmount > 0) {
            if (creator == address(0)) revert ZeroAddress();
            $.creatorBalance[creator] += creatorAmount;
            $.totalAccruedCreator += creatorAmount;
            $.lifetimeCreatorEarned[creator] += creatorAmount;
        }
        if (protocolAmount > 0) {
            $.protocolBalance += protocolAmount;
            $.lifetimeProtocolEarned += protocolAmount;
        }
        if ($.usdc.balanceOf(address(this)) < $.totalAccruedCreator + $.protocolBalance) {
            revert UnderfundedAccrual();
        }
        emit FeeAccrued(token, creator, creatorAmount, protocolAmount, isBuy);
    }
```

```text
    function claim() external nonReentrant returns (uint256 amount) {
        FeeVaultStorage storage $ = _s();
        amount = $.creatorBalance[msg.sender];
        if (amount == 0) revert NothingToClaim();
        $.creatorBalance[msg.sender] = 0;
        $.totalAccruedCreator -= amount;
        $.usdc.safeTransfer(msg.sender, amount);
        emit CreatorFeesClaimed(msg.sender, amount);
```
