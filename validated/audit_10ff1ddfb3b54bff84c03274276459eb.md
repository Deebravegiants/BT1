### Title
Virgin-supply share minting ignores residual vault assets, letting a trivial deposit capture leftover backing and future interest — ([File: mainnet/contracts/vault/v0-vault-stx.clar] and identical logic in the other vault contracts)

### Summary
Every Zest vault (`v0-vault-stx.clar`, `v0-vault-sbtc.clar`, `v0-vault-usdc.clar`, `v0-vault-usdh.clar`, `v0-vault-ststx.clar`, `v0-vault-ststxbtc.clar`) mints shares via `convert-to-shares-preview`, which returns `shares = amount` whenever `total-supply == 0`, completely ignoring any existing `total-assets-preview` value. Because interest accrual (`accrue`) runs independently of `total-supply` and continues to grow the vault's debt/interest ledger even while `total-supply == 0`, any account that deposits a trivial amount right after `total-supply` reaches zero — while residual/uncollected value (`assets` var leftover and/or uncollected interest) still exists in the vault — mints shares that are massively over-valued relative to its own deposit, entitling it to that residual value.

### Finding Description
`convert-to-shares-preview` in every vault, e.g. `v0-vault-stx.clar:308-315`:
```
(define-private (convert-to-shares-preview (amount uint))
  (let ((ta (total-assets-preview))
        (ts (total-supply-preview)))
    (if (is-eq ts u0)
        amount
        (if (is-eq ta u0)
            u0
            (mul-div-down amount ts ta)))))
``` [1](#0-0) 

When `ts == 0`, this branch mints `shares = amount`, ignoring `ta` (`total-assets-preview`) entirely, unlike the non-zero-supply branch which correctly prices shares as `amount * ts / ta`.

`total-assets-preview` includes uncollected/accrued interest independent of the current `total-supply`:
```
(define-private (total-assets-preview)
  (let ((current-assets (var-get assets))
        (debt (debt-preview))
        (borrowed (var-get total-borrowed))
        (interest (if (> debt borrowed) (- debt borrowed) u0)))
    (+ current-assets interest)))
``` [2](#0-1) 

`accrue()` — called on every `deposit`/`redeem`/`system-borrow`/`system-repay` — advances `index`/`lindex` purely as a function of elapsed time and outstanding `principal-scaled`, with **no dependency on `total-supply`**:
```
(define-public (accrue)
  (let ((states (var-get pause-states)) (idx (var-get index)) (lidx (var-get lindex)))
    (if (get accrue states) (ok {index: idx, lindex: lidx})
      (let ((next (next-index)) (nliq (next-liquidity-index)) ...)
        ...))))
``` [3](#0-2) 

Debt/interest continues to compound based only on `principal-scaled` and elapsed time, which is populated by `system-borrow` and independent of the LP `zft` supply:
```
(define-public (system-borrow (amount uint) (receiver principal))
  (let (...)
    (var-set principal-scaled updated-scaled-principal)
    (var-set total-borrowed (+ (var-get total-borrowed) amount))
    (try! (send-underlying amount receiver))
    ...))
``` [4](#0-3) 

`redeem` allows the sole shareholder to burn 100% of `zft`, driving `total-supply` to zero, as long as `current-assets >= inkind`:
```
(define-public (redeem (amount uint) (min-out uint) (recipient principal))
  (let (...)
  (asserts! (>= current-assets inkind) ERR-INSUFFICIENT-ASSETS)
  ...
  (try! (ft-burn? zft amount account))
  (try! (send-underlying inkind recipient))
  (var-set assets (- current-assets inkind))
  ...))
``` [5](#0-4) 

**Attack sequence, mirroring the wxETH "virgin stake" bug:**
1. The sole LP fully redeems at a moment where `debt == borrowed` (no uncollected interest yet), so `current-assets == total-assets-preview` and the redeem's `ERR-INSUFFICIENT-ASSETS` check passes. `total-supply` becomes `0`, but `principal-scaled`/`total-borrowed` remain non-zero (outstanding borrower debt tracked independently of LP shares).
2. Time passes. Every `accrue()` call (triggered even by unrelated `system-borrow`/`system-repay` calls from the lending market) advances `index`, growing `interest = debt - borrowed` in `total-assets-preview`, exactly like wxETH's drip firing while `totalSupply() == 0`.
3. An attacker deposits a trivial `amount` (e.g., `1` unit). Because `total-supply-preview() == 0` at that instant, `convert-to-shares-preview` mints `shares = amount`, ignoring the accumulated `interest` and any residual `assets` var value. The attacker now owns effectively 100% of `total-supply` (their `1` share), but the vault's `total-assets-preview` equals `amount + leftover_assets + accrued_interest`.
4. The attacker immediately redeems. `inkind = convert-to-assets-preview(1) = ta_new * 1 / ts_new ≈ ta_new`, i.e., nearly the entire vault value (residual `assets` var cash portion is redeemable immediately; the interest portion becomes redeemable as soon as the borrower's next `system-repay` converts it into real `assets` var balance).

This breaks the share/backing identity: `shares_minted / total_supply_after` should equal `deposit_value / total_assets_after` for a fair mint, but the `ts==0` branch instead grants `shares = amount` while `total_assets_after` includes value the depositor did not contribute.

### Impact Explanation
This is theft of unclaimed yield/interest (and any residual protocol cash) that rightfully belongs to previous LPs/the protocol, awarded instead to a virgin depositor who contributes a negligible amount. Per the report's impact bar, this qualifies as High: theft of unclaimed yield via a share-minting/backing identity break.

### Likelihood Explanation
Requires a window where `total-supply == 0` while `principal-scaled > 0` (outstanding debt) — plausible whenever a vault has only one active LP who fully exits while a borrow position remains open (borrowing is driven by the separate lending/market contract via `system-borrow`, not by LP share ownership), followed by any transaction that triggers `accrue()` (deposit, redeem, borrow, or repay from other market activity) before the next real deposit. Given `MINIMUM-LIQUIDITY` is declared as a constant (`u1000`) but is not enforced inside `redeem` or `deposit` in the reviewed code, there appears to be no floor preventing `total-supply` from reaching exactly zero.

### Recommendation
Do not allow `convert-to-shares-preview` to ignore `total-assets-preview` when `total-supply == 0`: either (a) prevent `total-supply` from reaching zero while `principal-scaled > 0` (enforce a minimum-liquidity/minimum-share floor as `MINIMUM-LIQUIDITY` suggests was intended), or (b) when `ts == 0` and `ta > 0`, require the depositor to absorb/donate the residual `ta` into the mint (e.g., mint shares such that the new depositor's share of `ta_after` equals only their contributed `amount`, forcing any leftover value to be burned/assigned to the DAO treasury rather than the new depositor).

### Proof of Concept
1. LP deposits `X` into `v0-vault-stx`; market contract calls `system-borrow` to borrow `X` from the vault (utilization 100%, `debt == borrowed`, so `interest == 0`).
2. LP calls `redeem` for their full balance while `debt == borrowed` — passes `ERR-INSUFFICIENT-ASSETS` check (`current-assets >= inkind` since no uncollected interest yet); `total-supply` → `0`, `principal-scaled`/`total-borrowed` remain `> 0`.
3. Time elapses; a `system-repay`/`system-borrow` call (unrelated market activity) triggers `accrue()`, growing `interest = debt - borrowed > 0` inside `total-assets-preview`.
4. Attacker calls `deposit(1, 0, attacker)`. `convert-to-shares-preview(1)` returns `1` (since `ts == 0`), granting the attacker ~100% ownership of a pool now worth `1 + interest`.
5. Attacker calls `redeem` for their `1` share; `convert-to-assets-preview` returns `≈ 1 + interest`, and once the borrower's next `system-repay` lands the interest into the `assets` var, the attacker redeems the full accrued interest that should have belonged to prior LPs/the treasury. (define-public (accrue)
  (let ((states (var-get pause-states))
        (idx (var-get index))
        (lidx (var-get lindex)))
      (if (get accrue states)
          ;; PAUSED: Pass-through without reverting
          (ok { index: idx, lindex: lidx })
          ;; NOT PAUSED: Normal accrual logic
          (let ((next (next-index))
                (nliq (next-liquidity-index))
                (scaled-principal (var-get principal-scaled))
                (old-debt (mul-div-down scaled-principal idx INDEX-PRECISION))
                (new-debt (mul-div-down scaled-principal next INDEX-PRECISION))
                (debt-delta (if (> new-debt old-debt) (- new-debt old-debt) u0))
                (reserve-inc (mul-div-down debt-delta (var-get fee-reserve) BPS))
                (treasury-lp (if (> reserve-inc u0) (mul-div-down reserve-inc (total-supply) (- (total-assets-preview) reserve-inc)) u0)))
            (if (not (is-eq idx next))
                (var-set index next)
                false)
