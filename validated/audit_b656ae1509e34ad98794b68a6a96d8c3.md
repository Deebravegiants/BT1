### Title
Interest accrual panics on RAY value overflow, permanently freezing all market operations - (File: common/src/rates/index.rs)

### Summary
The CVE analog class is an attacker-reachable arithmetic overflow that crashes the protocol. In XOXNO Lending, every pool verb accrues interest first via `global_sync`, which calls `accrue_step` → `calculate_supplier_rewards`. That function computes `borrowed.mul(env, new_borrow_index)` — `borrowed * index / RAY` in `i128`. When a whale-scale market sits at high utilization on a steep rate curve, the borrow index grows until `borrowed × index` exceeds `i128::MAX`. `Ray::mul` widens to `I256` only for the intermediate product; `.to_i128()` then fails and `mul_div_half_up` panics with `MathOverflow`. Since `update_indexes`, `repay`, `withdraw`, `borrow`, `supply`, and `liquidate` all accrue first, the entire market freezes permanently. The `MAX_BORROW_INDEX_RAY` cap in `update_borrow_index` cannot prevent it because the value-level overflow occurs before/at a lower index than the cap. [1](#0-0) [2](#0-1) 

### Finding Description
`calculate_supplier_rewards` computes `old_total_debt = borrowed.mul(old_index)` and `new_total_debt = borrowed.mul(new_index)` where both operands are RAY-scaled `i128` values (common/src/rates/index.rs:80-83). The underlying `fp_core::mul_div_half_up` panics with `GenericError::MathOverflow` when `borrowed * index / RAY` does not fit in `i128` (common/src/math/fp_core.rs:108-118). The borrow index cap `MAX_BORROW_INDEX_RAY` is applied in `update_borrow_index` (common/src/rates/index.rs:13-18), but for a sufficiently large `borrowed` the `supplied/borrowed × index` product overflows at an index well below that cap, so the cap never engages. This is confirmed by the in-repo harness test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap`, which asserts `try_update_indexes_for`, `try_withdraw_raw`, and `try_repay` all revert with `MATH_OVERFLOW` while `borrow_index < MAX_BORROW_INDEX_RAY` (tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:316-361). [3](#0-2) [4](#0-3) 

### Impact Explanation
Permanent freezing of funds and a contract unable to operate: once `borrowed × borrow_index` crosses the `i128` ceiling, every state-changing entrypoint on that market (`supply`, `borrow`, `withdraw`, `repay`, `liquidate`, `clean_bad_debt`, `update_indexes`) panics in `global_sync` before touching position state. Suppliers cannot exit and borrowers cannot repay; liquidations cannot run, so the market's solvency tooling is dead. No privileged action can unwind it because the panic is arithmetic, not authorization-based. [5](#0-4) [6](#0-5) 

### Likelihood Explanation
Reachable by unprivileged addresses: a whale calls `controller.supply` (minting scaled shares) and a collateralized `controller.borrow`, then time does the rest — each subsequent `update_indexes` accrues the index until overflow. The required scale is extreme (the harness test uses ~10^45 wei-scale principal at 98% utilization over years on a steep curve), and it requires a large real token balance and market caps permitting it, so the likelihood is low. But no privileged or leaked-key action is needed, and once crossed the freeze is irreversible — this is the DoS-via-integer-overflow bug class of the report mapped onto the RAY index domain. Severity: Medium. [7](#0-6) 

### Recommendation
In `calculate_supplier_rewards` and `update_supply_index`, compute debt/supply values with the saturating or `I256`-retaining variant instead of panicking `mul`, e.g. compute `borrowed * index / RAY` via `mul_div_floor_saturating` or clamp `new_total_debt` to `i128::MAX` and let the index cap path handle it. Alternatively, gate index growth so `borrowed × MAX_BORROW_INDEX_RAY` always fits `i128` — i.e. cap effective scaled totals per market at `i128::MAX / MAX_BORROW_INDEX_RAY` at borrow/supply mint time — so accrual can never reach the value ceiling before the index cap. [3](#0-2) [8](#0-7) 

### Proof of Concept
The repository's own harness demonstrates it end-to-end: list an 18-decimal market on the steep `xlm_curve`, disable max utilization, lift caps, supply ~1e36 units and borrow ~98% of it, then advance ledger time year-by-year calling `pool.update_indexes`. Within 40 years `try_update_indexes_for` fails with `errors::MATH_OVERFLOW`, and both `try_withdraw_raw(BOB, "BIG18", 1)` and `try_repay(ALICE, "BIG18", 1.0)` fail with the same error while `borrow_index` remains below `MAX_BORROW_INDEX_RAY` — showing the freeze is in the shared accrual preamble, reachable from the unprivileged `supply`/`borrow`/`update_indexes` entrypoints. pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
}

pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    // The zero check runs first so debug and release builds agree on a zero
    // divisor: both surface `DivisionByZero` rather than tripping the assert.
    require_nonzero_divisor(env, d);
    debug_assert!(
        x >= 0 && y >= 0 && d > 0,
        "mul_div_half_up: non-negative x, y and positive d"
    );
    try_mul_div_half_up(env, x, y, d)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
}

pub fn mul_div_floor_saturating(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    require_nonzero_divisor(env, d);
    if let Some(quotient) = x
        .checked_mul(y)
        .and_then(|product| div_floor_i128(product, d))
    {
        return quotient;
    }
    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    div_floor_i256(
        env,
        &x256.mul(&y256),
        &d256,
        quotient_is_nonnegative(x, y, d),
    )
    .to_i128()
    .unwrap_or(if quotient_is_negative(x, y, d) {
        i128::MIN
    } else {
        i128::MAX
    })
}
