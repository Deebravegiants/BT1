### Title
`bonding_curve_launchpad` swap functions compute output on-chain with no minimum-output/slippage parameter, allowing sandwich extraction of APT and FA value held in the liquidity-pair object - (File: aptos-move/move-examples/bonding_curve_launchpad/sources/liquidity_pairs.move)

### Summary
`liquidity_pairs::swap_fa_to_apt` and `swap_apt_to_fa`, invoked via the public entry point `bonding_curve_launchpad::swap`, compute the swap output entirely from on-chain reserve state at execution time via `get_amount_out`, then immediately transfer the computed amount with no caller-supplied minimum-output check anywhere in the call path. [1](#0-0) [2](#0-1) 

### Finding Description
`bonding_curve_launchpad::swap` is a public entry function callable by any account, taking only `amount_in` (no minimum-out parameter) and dispatching to `liquidity_pairs::swap_fa_to_apt` / `swap_apt_to_fa`: [3](#0-2) 

Both swap functions derive `apt_gained`/`fa_gained` purely from the live `fa_reserves`/`apt_reserves` stored on the `LiquidityPair` object via the constant-product `get_amount_out`, and then immediately execute the transfer with that computed value - there is no `amount_out_min` parameter, no post-transfer assertion, and no slippage guard of any kind: [4](#0-3) [5](#0-4) [6](#0-5) 

The APT and FA reserves are custody-held directly in the `LiquidityPair` object (`fa_store`, plus a signer-controlled account holding APT via `extend_ref`), so any value extracted through reserve manipulation comes directly out of that object's held value: [7](#0-6) 

This is the exact custody invariant broken by the external report's bug class: an unprivileged caller can submit a large swap transaction immediately before a victim's swap (front-run) and another immediately after (back-run) within the same block/mempool window, moving `fa_reserves`/`apt_reserves` before the victim's `get_amount_out` executes and reverting them afterward, extracting the difference between the fair price and the manipulated price directly from the victim and the pool. Contrast this with the properly-guarded `move-examples/swap/router.move::swap`, which explicitly takes `amount_out_min` and asserts `fungible_asset::amount(&out) >= amount_out_min`: [8](#0-7) 
No equivalent check exists anywhere in `bonding_curve_launchpad`/`liquidity_pairs`.

### Impact Explanation
Any unprivileged caller can sandwich victim swaps against the bonding-curve pool to steal APT and/or FA value that is custody-held in the pair's `fa_store` and pool-controlled account, corrupting the intended value exchange for a swapping user and moving reserve value to the attacker instead of the fair-price holder. Because the pool also gates FA transferability via a dispatchable `withdraw` hook tied to `is_frozen`/graduation state, and reserves feed the graduation threshold, a manipulated swap sequence can also distort the reserve accounting used to decide `graduate()` — i.e. moving supply/custody state to an unintended party at an unintended price.

### Likelihood Explanation
Medium-to-High: this is a permissionless entry function (`bonding_curve_launchpad::swap`) reachable by anyone with FA/APT, the classic sandwich pattern is well understood and tooling exists, and there is zero protective parameter or check to defeat it — unlike the sibling `swap` example in the same repository that correctly implements `amount_out_min`.

### Recommendation
Add a mandatory `min_amount_out` parameter to `bonding_curve_launchpad::swap` and thread it through `liquidity_pairs::swap_fa_to_apt`/`swap_apt_to_fa`, asserting the computed `apt_gained`/`fa_gained` meets or exceeds the caller-specified minimum before executing the transfer, mirroring the pattern already used in `move-examples/swap/router.move`.

### Proof of Concept
1. Attacker observes a pending `bonding_curve_launchpad::swap(victim, name, symbol, swap_to_apt=false, amount_in=X)` transaction in the mempool.
2. Attacker front-runs with their own large `swap(attacker, name, symbol, false, large_amount)` call, which moves `apt_reserves`/`fa_reserves` unfavorably for the victim (per `get_amount_out`'s constant-product math at lines 91-112 of `liquidity_pairs.move`).
3. Victim's transaction executes against the now-skewed reserves, receiving far fewer FA/APT than the pre-manipulation quote, with no min-out check to reject the trade.
4. Attacker back-runs with an opposite swap to restore reserves and realize profit, extracting value directly from the FA/APT held in the pool object at `liquidity_pairs::LiquidityPair.fa_store` / pool signer's APT balance. [2](#0-1)

    #[view]
    public fun get_amount_out(
        fa_reserves: u128,
        apt_reserves: u128,
        swap_to_apt: bool,
        amount_in: u64
    ): (u64, u64, u128, u128) {
        if (swap_to_apt) {
            let divisor = fa_reserves + (amount_in as u128);
            let apt_gained = (math128::mul_div(apt_reserves, (amount_in as u128), divisor) as u64);
            let fa_updated_reserves = fa_reserves + (amount_in as u128);
            let apt_updated_reserves = apt_reserves - (apt_gained as u128);
            assert!(apt_gained > 0, ELIQUIDITY_PAIR_SWAP_AMOUNTOUT_INSIGNIFICANT);
            (amount_in, apt_gained, fa_updated_reserves, apt_updated_reserves)
        } else {
            let divisor = apt_reserves + (amount_in as u128);
            let fa_gained = (math128::mul_div(fa_reserves, (amount_in as u128), divisor) as u64);
            let fa_updated_reserves = fa_reserves - (fa_gained as u128);
            let apt_updated_reserves = apt_reserves + (amount_in as u128);
            assert!(fa_gained > 0, ELIQUIDITY_PAIR_SWAP_AMOUNTOUT_INSIGNIFICANT);
            (fa_gained, amount_in, fa_updated_reserves, apt_updated_reserves)
        }
    }

    /// Facilitate swapping between a given FA to APT.
    public(friend) fun swap_fa_to_apt(
        name: String,
        symbol: String,
        transfer_ref: &TransferRef,
        swapper_account: &signer,
        fa_object_metadata: Object<Metadata>,
        amount_in: u64
    ) acquires Pairs, LiquidityPair {
        // Verify the liquidity pair exists and is enabled for trading.
        assert_liquidity_pair_exists(name, symbol);
        let liquidity_pair = borrow_global_mut<LiquidityPair>(get_pair_obj_address(name, symbol));
        assert!(liquidity_pair.is_enabled, ELIQUIDITY_PAIR_DISABLED);
        // Determine the amount received of APT, when given swapper-supplied amount_in of FA.
        let (fa_given, apt_gained, fa_updated_reserves, apt_updated_reserves) = get_amount_out(
            liquidity_pair.fa_reserves,
            liquidity_pair.apt_reserves,
            true,
            amount_in
        );
        // Verify the swapper holds the FA.
        let swapper_address = signer::address_of(swapper_account);
        let does_primary_store_exist_for_swapper = primary_fungible_store::primary_store_exists(
            swapper_address,
            fa_object_metadata
        );
        assert!(does_primary_store_exist_for_swapper, EFA_PRIMARY_STORE_DOES_NOT_EXIST);
        // Perform the swap.
        // Swapper sends FA to the liquidity pair object. The liquidity pair object sends APT to the swapper, in return.
        let liquidity_pair_signer = object::generate_signer_for_extending(&liquidity_pair.extend_ref);
        let from_swapper_store = primary_fungible_store::ensure_primary_store_exists(
            swapper_address,
            fungible_asset::transfer_ref_metadata(transfer_ref)
        );
        fungible_asset::transfer_with_ref(transfer_ref, from_swapper_store, liquidity_pair.fa_store, fa_given);
        aptos_account::transfer(&liquidity_pair_signer, swapper_address, apt_gained);
        // Record state changes to the liquidity pair's reserves, and emit changes as events.
        let former_fa_reserves = liquidity_pair.fa_reserves;
        let former_apt_reserves = liquidity_pair.apt_reserves;
        liquidity_pair.fa_reserves = fa_updated_reserves;
        liquidity_pair.apt_reserves = apt_updated_reserves;
        event::emit(
            LiquidityPairReservesUpdated {
                former_fa_reserves,
                former_apt_reserves,
                new_fa_reserves: fa_updated_reserves,
                new_apt_reserves: apt_updated_reserves
            }
        );
        event::emit(
            LiquidityPairSwap {
                is_fa_else_apt: false,
                gained: (apt_gained as u128),
                swapper_address
            }
        );
    }

    public fun swap(
        in: FungibleAsset,
        amount_out_min: u64,
        to_token: Object<Metadata>,
        is_stable: bool,
    ): FungibleAsset {
        let from_token = fungible_asset::asset_metadata(&in);
        let pool = liquidity_pool::liquidity_pool(from_token, to_token, is_stable);
        let out = liquidity_pool::swap(pool, in);
        assert!(fungible_asset::amount(&out) >= amount_out_min, EINSUFFICIENT_OUTPUT_AMOUNT);
        out
    }
