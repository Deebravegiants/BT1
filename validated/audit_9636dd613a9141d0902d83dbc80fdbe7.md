Audit Report

## Title
Unauthenticated-role disclosure of External Initiator `outgoingToken` via `GET /v2/external_initiators` - (File: core/web/router.go)

## Summary
The route `authv2.GET("/external_initiators", paginatedRequest(eia.Index))` at [1](#0-0)  is wrapped only in `paginatedRequest`, with no `auth.RequiresEditRole`/`auth.RequiresRunRole`/`auth.RequiresAdminRole` guard, while the sibling `POST` and `DELETE` routes on the same resource both require `auth.RequiresEditRole`. Any authenticated user — including one with only `UserRoleView` — can call this endpoint and receive every External Initiator's `OutgoingToken` in the response.

## Finding Description
`v2Routes` mounts `authv2` with `auth.Authenticate(..., auth.AuthenticateByToken, auth.AuthenticateBySession)`, which only verifies that the caller has *any* valid session or API token — it performs no role check itself [2](#0-1) . Role enforcement is applied per-route via wrappers like `RequiresEditRole`, which explicitly rejects `UserRoleView` and `UserRoleRun` [3](#0-2) . On the external-initiators routes, `Create` and `Destroy` are wrapped with `auth.RequiresEditRole`, but `Index` is not [1](#0-0) , so `ExternalInitiatorsController.Index` is reachable by a `UserRoleView` (or `UserRoleRun`) authenticated user.

`Index` fetches all stored external initiators and serializes them with `presenters.NewExternalInitiatorResource` [4](#0-3) , and that resource struct explicitly includes `OutgoingToken` in the JSON payload [5](#0-4) . This is inconsistent with `Create`, which only returns the token/secret once via `ExternalInitiatorAuthentication` at creation time [6](#0-5) . The `OutgoingToken`/`OutgoingSecret` pair is generated as a credential the node uses to authenticate outbound calls to the external initiator's URL [7](#0-6) . There is no redaction or additional authorization check in `Index` to compensate for the missing route-level role gate.

## Impact Explanation
A low-privileged, authenticated user (role `view`, the lowest role in the system) can retrieve `OutgoingToken` for every configured external initiator without any elevated privilege, purely via a normal authenticated `GET` request. This token is meant to be known only to edit/admin-level operators (per the access control enforced on `Create`/`Destroy`), and its disclosure allows an unprivileged internal actor to impersonate the Chainlink node's outbound calls to the external initiator's endpoint. This is a legitimate secret-exfiltration / broken-access-control class finding (asymmetric authorization on a listing endpoint that leaks credentials) and maps to the in-scope "key/secret exfiltration" and "node API ... role bypass" impact categories.

## Likelihood Explanation
High. Any principal that can authenticate to the node's HTTP API — including a `view`-role user or a `view`-scoped API token, which is a legitimate, unprivileged, commonly-provisioned credential class — can trivially issue `GET /v2/external_initiators` and receive the secret for every registered external initiator in the JSON response, with full repeatability and no race conditions or special setup required.

## Recommendation
Add the missing role wrapper to match the rest of the resource's access-control pattern, e.g.:
```go
authv2.GET("/external_initiators", auth.RequiresEditRole(paginatedRequest(eia.Index)))
```
Alternatively, if `view`-role listing access must be preserved, strip `OutgoingToken` (and any other secret material) from `ExternalInitiatorResource` and only ever return it once, at creation time, via `ExternalInitiatorAuthentication`.

## Proof of Concept
1. Create/obtain a user or API token with role `view` (the lowest privilege role, per `clsessions.UserRoleView`).
2. Authenticate as that user (session cookie or `X-API-KEY`/`X-API-SECRET`) and issue `GET /v2/external_initiators`.
3. Observe HTTP 200 with a JSON body whose `data[].attributes.outgoingToken` fields contain the real `OutgoingToken` secrets for every stored external initiator, per the `ExternalInitiatorResource` struct at [5](#0-4) .
4. Contrast with `POST /v2/external_initiators` or `DELETE /v2/external_initiators/:Name` using the same `view`-role credentials, which return `401/403 Unauthorized`/`Forbidden` due to `auth.RequiresEditRole` at [3](#0-2) , demonstrating the inconsistent, missing access control specifically on the `Index` route.

// Authenticate is middleware which authenticates the request by attempting to

func Authenticate(store Authenticator, methods ...authMethod) gin.HandlerFunc {
	return func(c *gin.Context) {
		var err error
		for _, method := range methods {
			err = method(c, store)
			if !errors.Is(err, auth.ErrorAuthFailed) {
				break
			}
		}
		if err != nil {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, err)

			return
		}

		c.Next()
	}
}

		}

			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}

	}
}
