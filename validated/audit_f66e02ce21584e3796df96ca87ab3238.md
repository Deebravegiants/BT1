## Finding

The naive attack literally described (silently truncating a message from the inherent while claiming a matching MQC head) is **blocked**: `enqueue_inbound_downward_messages` recomputes the DMQ MQC head from every message the collator submits — including ones represented only as hashes — via `extend_downward`/`extend_with_hashed_msg`, and then panics with `"DMQ head mismatch"` if the recomputed head doesn't match `relevant_messaging_state.dmq_mqc_head` proven from the relay chain. [1](#0-0) 

However, investigating the actual "abridgement" mechanism (`into_abridged`) reveals a related, genuine bug with the same root cause and impact: messages that get **compressed into hashes** (rather than fully omitted) are cryptographically accounted for in the MQC chain, but are never handed to `T::DmpQueue`, and the on-chain watermark (`LastProcessedDownwardMessage`) advances past them anyway — permanently orphaning them.

### Root cause

- `into_abridged` splits messages into `full_messages` (kept intact) and `hashed_messages` (only `sent_at` + hash of data) once a size budget is exceeded. [2](#0-1) 
- `bounded_msgs_iter()`, which feeds `T::DmpQueue::handle_messages`, only iterates `full_messages` — hashed messages are never dispatched for execution. [3](#0-2) 
- Yet in `enqueue_inbound_downward_messages`, the loop that advances `last_processed_msg`/`LastProcessedDownwardMessage` iterates over `hashed_messages` too, treating them as processed for watermark purposes, even though they were skipped by `T::DmpQueue`. [4](#0-3) 
- On the next block, `do_create_inherent` calls `drop_processed_messages(&last_processed_msg)` against the freshly fetched DMQ contents, using this same watermark — which discards the previously-hashed messages before they can ever be resubmitted in full form. [5](#0-4) [6](#0-5) 

Because `LastProcessedDownwardMessage` never distinguishes "fully executed by DmpQueue" from "merely hashed/compressed", once a message is compressed instead of fully included, it can never be replayed: the watermark has already moved past it.

### Trigger

`messages_collection_size_limit()` is derived from `remaining_block_weight().remaining().proof_size()`, i.e. from how much PoV/proof-size budget is left in the block when the inherent executes. [7](#0-6) 
A malicious collator (who fully controls block construction/extrinsic ordering) can deliberately consume proof-size budget with other transactions before the mandatory inherent runs, shrinking `size_limit` so that target DMP/XCM messages (e.g. a reserve-transfer or teleport) fall past the size cutoff in `into_abridged` and get hashed instead of included in full — triggering the permanent-orphan path described above, without ever violating the DMQ-head assertion.

### Title
Compressed/hashed downward messages advance `LastProcessedDownwardMessage` without ever being dispatched to `DmpQueue`, permanently orphaning them - (File: cumulus/pallets/parachain-system/src/lib.rs, cumulus/pallets/parachain-system/src/parachain_inherent.rs)

### Summary
When a collator's inherent-construction logic compresses (hashes) downward messages that exceed the per-block size limit, those messages are correctly folded into the DMQ MQC-head hash chain but are never passed to `T::DmpQueue::handle_messages`. The pallet's watermark tracking (`LastProcessedDownwardMessage`) nonetheless advances past them, and subsequent inherent construction (`drop_processed_messages`) discards them from future full-message resubmission, permanently preventing their execution.

### Finding Description
`into_abridged` (cumulus/pallets/parachain-system/src/parachain_inherent.rs:122-142) splits the pending DMQ messages into `full_messages` and `hashed_messages` based on a size budget. `enqueue_inbound_downward_messages` (cumulus/pallets/parachain-system/src/lib.rs:1319-1367) folds both categories into the running `dmq_head` to satisfy the `assert_eq!` MQC check, but only iterates `full_messages` when calling `T::DmpQueue::handle_messages` via `bounded_msgs_iter()` (parachain_inherent.rs:249-265). The loop that updates `last_processed_msg`/`LastProcessedDownwardMessage` iterates `hashed_messages` as well, so the watermark treats hashed (never-dispatched) messages as fully processed. On the following block, `do_create_inherent` (lib.rs:1279-1308) calls `drop_processed_messages` using this watermark, discarding those messages from the freshly retrieved DMQ contents before they can ever be resubmitted with full data. `ProcessedDownwardMessages` reported back to the relay chain only counts `full_messages.len()`, so the relay chain does not prune these messages from its own queue — but the parachain-side logic never fetches them again in full form regardless, because the local watermark has already passed them.

### Impact Explanation
Any DMP message (including XCM reserve-transfer or teleport instructions carrying real value) that gets compressed instead of fully included in a block is permanently unexecuted on the parachain. This is a lock/loss of the corresponding cross-chain transfer's assets on the sending side, since the message can never be replayed once the watermark has advanced past it — matching the scoped impact exactly.

### Likelihood Explanation
Compression is a normal, protocol-endorsed code path triggered whenever `messages_collection_size_limit()` is exceeded (large DMQ backlog, big messages, or a malicious collator artificially shrinking `remaining_block_weight()` by filling the block with other extrinsics before the mandatory inherent executes). No signature forgery or origin bypass is needed — the collator fully controls inherent construction and block composition, making this reliably reproducible in a single block under attacker control.

### Recommendation
Track two separate watermarks (or a flag per hashed message) distinguishing "included in MQC chain" from "dispatched to `DmpQueue`". Do not advance `LastProcessedDownwardMessage`/allow `drop_processed_messages` to discard hashed messages until they have actually been resubmitted in full and processed by `T::DmpQueue`. Alternatively, disallow permanently dropping hashed messages in `drop_processed_messages` — only drop messages that were in `full_messages` and thus actually dispatched.

### Proof of Concept
Add an integration test in `cumulus/pallets/parachain-system/src/tests.rs`:
1. Build a relay sproof whose `dmq_mqc_head` covers N downward messages, where message sizes force `into_abridged` (with an artificially small `messages_collection_size_limit`) to hash messages `k..N`.
2. Submit the block; assert the inherent succeeds (no "DMQ head mismatch" panic) and `LastProcessedDownwardMessage` advances to cover all N messages.
3. Assert `HANDLED_DMP_MESSAGES` (mirroring `T::DmpQueue::handle_messages` calls) only contains messages `0..k`, i.e., messages `k..N` were never dispatched.
4. Run a subsequent block that re-fetches the same DMQ contents (simulating the relay chain not having pruned them, since `ProcessedDownwardMessages` under-reported the count) and assert that messages `k..N` are dropped by `drop_processed_messages` in `do_create_inherent` without ever appearing in `HANDLED_DMP_MESSAGES` — proving they are permanently orphaned.

	fn enqueue_inbound_downward_messages(
		expected_dmq_mqc_head: relay_chain::Hash,
		downward_messages: AbridgedInboundDownwardMessages,
	) -> Weight {
		downward_messages.check_enough_messages_included_basic("DMQ");

		let mut dmq_head = <LastDmqMqcHead<T>>::get();

		let (messages, hashed_messages) = downward_messages.messages();
		let message_count = messages.len() as u32;
		let weight_used = T::WeightInfo::enqueue_inbound_downward_messages(message_count);
		if let Some(last_msg) = messages.last() {
			Self::deposit_event(Event::DownwardMessagesReceived { count: message_count });

			// Eagerly update the MQC head hash:
			for msg in messages {
				dmq_head.extend_downward(msg);
			}
			<LastDmqMqcHead<T>>::put(&dmq_head);
			Self::deposit_event(Event::DownwardMessagesProcessed {
				weight_used,
				dmq_head: dmq_head.head(),
			});

			let mut last_processed_msg =
				InboundMessageId { sent_at: last_msg.sent_at, reverse_idx: 0 };
			for msg in hashed_messages {
				dmq_head.extend_with_hashed_msg(msg);

				if msg.sent_at == last_processed_msg.sent_at {
					last_processed_msg.reverse_idx += 1;
				}
			}
			LastProcessedDownwardMessage::<T>::put(last_processed_msg);

			T::DmpQueue::handle_messages(downward_messages.bounded_msgs_iter());
		}

		// After hashing each message in the message queue chain submitted by the collator, we
		// should arrive to the MQC head provided by the relay chain.
		//
		// A mismatch means that at least some of the submitted messages were altered, omitted or
		// added improperly.
		assert_eq!(dmq_head.head(), expected_dmq_mqc_head, "DMQ head mismatch");

		ProcessedDownwardMessages::<T>::put(message_count);

		weight_used
	}

	/// Drop all the messages up to `last_processed_msg`.
	pub fn drop_processed_messages(&mut self, last_processed_msg: &InboundMessageId) {
		let mut last_processed_msg_idx = None;
		let messages = &mut self.messages;
		for (idx, message) in messages.iter().enumerate().rev() {
			let sent_at = message.sent_at();
			if sent_at == last_processed_msg.sent_at {
				last_processed_msg_idx = idx.checked_sub(last_processed_msg.reverse_idx as usize);
				break;
			}
			// If we build on the same relay parent twice, we will receive the same messages again
			// while `last_processed_msg` may have been increased. We need this check to make sure
			// that the old messages are dropped.
			if sent_at < last_processed_msg.sent_at {
				last_processed_msg_idx = Some(idx);
				break;
			}
		}
		if let Some(last_processed_msg_idx) = last_processed_msg_idx {
			messages.drain(..=last_processed_msg_idx);
		}
	}

	pub fn into_abridged(
		self,
		size_limit: &mut usize,
	) -> AbridgedInboundMessagesCollection<Message> {
		let mut messages = self.messages;

		let mut split_off_pos = messages.len();
		for (idx, message) in messages.iter().enumerate() {
			if *size_limit < message.data().len() {
				break;
			}
			*size_limit -= message.data().len();

			split_off_pos = idx + 1;
		}

		let extra_messages = messages.split_off(split_off_pos);
		let hashed_messages = extra_messages.iter().map(|msg| msg.to_compressed()).collect();

		AbridgedInboundMessagesCollection { full_messages: messages, hashed_messages }
	}

	/// Returns an iterator over the messages that maps them to `BoundedSlices`.
	pub fn bounded_msgs_iter<MaxMessageLen: Get<u32>>(
		&self,
	) -> impl Iterator<Item = BoundedSlice<'_, u8, MaxMessageLen>> {

			.filter_map(|m| match BoundedSlice::try_from(&m.msg[..]) {
				Ok(bounded) => Some(bounded),
				Err(_) => {
					defensive!("Inbound Downward message was too long; dropping");
					None
				},
			})
	}
