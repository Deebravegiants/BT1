### Title
Un-mitigated UniswapV2 `MINIMUM_LIQUIDITY` first-mint revert permanently bricks `Bonding.finalizeGraduation` via the one-shot `LPLock.recordLock` - ([File: packages/contracts/src/Bonding.sol])

### Summary
CVE-2018-19210 is a NULL-pointer-dereference DoS in LibTIFF's directory-write path: an unchecked edge case in a "commit" routine causes a crash with no recovery. The alt.fun analog is in `Bonding.finalizeGraduation`: the LP amounts it commits to the HyperSwap pair are computed once in phase 1 and replayed byte-identically on every retry, with no floor check against Uniswap V2's `MINIMUM_LIQUIDITY` first-mint requirement. If those cached amounts are small enough, the pair's `mint()` call reverts deterministically forever, and because `LPLock.recordLock` is a one-shot, unskippable step, the token is permanently stuck in `Lifecycle.Graduating` with its curve-raised LT and 250M `LP_RESERVE` tokens frozen inside `Bonding`.

### Finding Description
`Bonding._enterGraduating` computes and freezes `(tokensForLP, ltFromPair)` in `pendingGraduation[token]` via `_prepareGraduationLiquidity`: [1](#0-0) 

These cached values are pure pair-state arithmetic and are documented as never changing across retries ("Phase 2 uses the cached value verbatim"): [2](#0-1) 

`finalizeGraduation` is permissionless and callable by anyone to "rescue a stuck token," but it always replays the same cached amounts: [3](#0-2) 

In the ~99%-of-graduations "empty pair" regime, `_seedDirectMint` transfers the cached amounts to a fresh HyperSwap pair and calls the standard V2 `mint()`: [4](#0-3) 

Canonical UniswapV2 `mint()` on the first deposit (`totalSupply == 0`) computes `liquidity = sqrt(amount0*amount1) - MINIMUM_LIQUIDITY` and reverts with `INSUFFICIENT_LIQUIDITY_MINTED` if that underflows (i.e., `sqrt(tokensForLP * ltFromPair) <= 1000`). Nothing in `_prepareGraduationLiquidity` or `_seedUniswapV2Direct` enforces a floor above this threshold — the code only defends against pre-seed manipulation (skim, rebalance, 99% swap-budget cap), not against `tokensForLP`/`ltFromPair` themselves being too small in absolute terms: [5](#0-4) 

`ltFromPair` is the real LT raised, and it can be arbitrarily small in wei terms even while satisfying the USD graduation threshold, because the threshold is denominated in USD via the LT's live, externally-driven `exchangeRate()` while `virtualLtReserve` is fixed at the token's *launch-time* rate: [6](#0-5) 

If a token launches when the paired LT's `exchangeRate()` is low, and the LT later appreciates enormously before the USD trigger fires (a legitimate, attacker-uncontrolled market move on an externally-priced leveraged token — not a bug in the LT itself), `realLtRaised` needed to cross the fixed USD threshold shrinks proportionally, while `tokenReserve` (dominated by the still mostly-unsold virtual 1B-token reserve) stays large. In the pathological limit, `tokensForLP * ltFromPair` can fall at or below the UniswapV2 `MINIMUM_LIQUIDITY` product floor, causing `pair.mint()` to revert on every call.

Because `finalizeGraduation` is the *only* path out of `Lifecycle.Graduating`, and `LPLock.recordLock` enforces a hard one-shot/no-retry-with-different-inputs semantic (there is no alternate seeding function, and the code itself documents `LPLock` "has no rescue path in v1" for anything routed to it): [7](#0-6) 

a first-mint revert becomes permanent: the deterministic cached inputs guarantee every subsequent `finalizeGraduation(tokenAddress)` call fails identically, with no owner or keeper override to change the seeded amounts.

### Impact Explanation
This is a permanent freezing-of-funds bug matching the "Reject ... no-impact analogs" bar for Medium+: once a token enters `Lifecycle.Graduating` with sub-`MINIMUM_LIQUIDITY` cached amounts, the real LT the curve raised (already drained into `Bonding` by `Router.graduate` in phase 1) and the 250M `LP_RESERVE` tokens reserved for that token are permanently locked in `Bonding` with no function to withdraw or re-seed them. Traders holding pre-graduation tokens also lose the ability to ever trade (curve is frozen, HyperSwap pool never seeds), matching the "permanent freezing of trader, creator or LP funds" impact criterion.

### Likelihood Explanation
Reachable by any market condition, not a privileged action — the USD graduation trigger fires automatically off `canGraduate()`/`triggerGraduation()`, which is explicitly permissionless: [8](#0-7) 
However, triggering the exact `sqrt(tokensForLP*ltFromPair) <= 1000` condition requires an extreme ratio between the LT's launch-time exchange rate and the rate at graduation time (i.e., the underlying leveraged token appreciating by many orders of magnitude between token launch and graduation). This is a real, externally-driven market condition rather than a contrived one, but the magnitude needed makes it a low-to-moderate likelihood edge case rather than a routinely-hit path — consistent with the CVE's own DoS class, which likewise requires a specific malformed-input edge case rather than ordinary usage.

### Recommendation
Add an explicit floor check in `_prepareGraduationLiquidity` (or `_seedDirectMint`/`_seedUniswapV2Direct`) that guarantees `tokensForLP * ltFromPair` (and any rebalanced-deposit equivalent) stays safely above UniswapV2's `MINIMUM_LIQUIDITY` product before committing to `pendingGraduation`. If the computed amounts would round to an unmintable pair, either (a) scale both sides up using a portion of `LP_RESERVE`/protocol-owned buffer while preserving price, or (b) provide an owner-gated recovery path (e.g., a rescue function that lets governance re-seed or refund the parked LT/tokens for tokens irrecoverably stuck in `Lifecycle.Graduating`), so a first-mint revert can never become a terminal, unrecoverable state.

### Proof of Concept
1. Launch a token against an LT at a low `exchangeRate` (e.g., `r0`), so `virtualLtReserve = VIRTUAL_LIQUIDITY_USD * 1e18 / r0` is set and the curve stays essentially unsold (`tokenReserve` ≈ virtual 1B supply).
2. Let the LT's live `exchangeRate()` climb to a very large `r1 >> r0` (a legitimate, externally-driven price move — no calls into the LT are needed since only its `exchangeRate()` view is read).
3. Call `Bonding.triggerGraduation(tokenAddress)` (permissionless) once `canGraduate` flips true; `_prepareGraduationLiquidity` computes `ltFromPair = graduationThresholdUsd*1e18/r1` (tiny) and `tokensForLP = ltFromPair * tokenReserve / assetReserve`.
4. Call `Bonding.finalizeGraduation(tokenAddress)` (permissionless): `_seedDirectMint` transfers the cached tiny amounts to the fresh HyperSwap pair and calls `pair.mint(lpLock)`, which reverts with `INSUFFICIENT_LIQUIDITY_MINTED` because `sqrt(tokensForLP * ltFromPair) <= MINIMUM_LIQUIDITY`.
5. Every subsequent call to `finalizeGraduation(tokenAddress)` replays the identical cached `pendingGraduation[tokenAddress]` values and reverts identically — the token is permanently stuck in `Lifecycle.Graduating`, and its curve-raised LT plus 250M reserved tokens are unrecoverable.

    function finalizeGraduation(
        address tokenAddress
    ) external nonReentrant {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[tokenAddress];
        if (info.lifecycle != Lifecycle.Graduating) revert NotGraduating();

        address lt = info.ltAddress;
        PendingGraduation memory p = $.pendingGraduation[tokenAddress];

        // Anything in this contract beyond `p.ltFromPair` belongs to a
        // concurrent graduation on the same LT (Phase 1 transferred it
        // via `Router.graduate`) or to stray dust. Either way it is
        // off-limits to this graduation's deposit and sweep — see
        // `_routerDepositAndDispose` and `_sweepLTToOwner`.
        // Saturating subtract: a balance below `p.ltFromPair` shouldn't
        // be reachable in normal operation, but we keep finalize from
        // bricking on a Panic if any future code path or non-canonical
        // LT briefly violates the invariant.
        uint256 ltBalance = IERC20(lt).balanceOf(address(this));
        uint256 protectedLT = ltBalance > p.ltFromPair ? ltBalance - p.ltFromPair : 0;

        address lpPair = _ensureUniswapV2Pair(tokenAddress, lt);
        uint256 liquidity = _seedUniswapV2Direct(tokenAddress, lt, lpPair, p.tokensForLP, p.ltFromPair, protectedLT);

        _sweepLTToOwner(lt, protectedLT);

        info.lifecycle = Lifecycle.Graduated;
        $.graduatedPair[tokenAddress] = lpPair;
        delete $.pendingGraduation[tokenAddress];

        LPLock($.lpLock).recordLock(tokenAddress, lpPair, liquidity);

        emit TokenGraduated(tokenAddress, lpPair, liquidity, p.tokensForLP, p.lpBurned, p.unsoldBurned);
    }

    function _prepareGraduationLiquidity(
        address tokenAddress
    ) internal returns (uint256 tokensForLP, uint256 ltFromPair, uint256 lpBurned, uint256 unsoldBurned) {
        address pairAddr = _s().tokenInfo[tokenAddress].pair;
        (uint256 tokenReserve, uint256 assetReserve) = IPair(pairAddr).getReserves();

        unsoldBurned = IPair(pairAddr).tokenBalance();
        if (unsoldBurned > 0) {
            Token(tokenAddress).burn(pairAddr, unsoldBurned);
        }

        ltFromPair = assetReserve - _launchTimeVirtualLtReserve(tokenAddress, pairAddr);
        if (ltFromPair > 0) {
            _s().router.graduate(tokenAddress, ltFromPair);
        }

        tokensForLP = assetReserve == 0 ? 0 : (ltFromPair * tokenReserve) / assetReserve;
        if (tokensForLP > LP_RESERVE) tokensForLP = LP_RESERVE;

        lpBurned = LP_RESERVE - tokensForLP;
        if (lpBurned > 0) {
            Token(tokenAddress).burn(address(this), lpBurned);
        }
    }

    ///           `Bonding`; path then collapses to (1). Donated TOKEN is

    /// @notice Record an LP lock. LP tokens must already sit at this address.
    function recordLock(
        address token,
        address lpPair,
        uint256 amount
    ) external {
        LPLockStorage storage $ = _s();
        if (!$.isLocker[msg.sender]) revert NotAuthorized();
        if (lpPair == address(0)) revert ZeroAddress();
        if (amount == 0) revert ZeroAmount();
        // `lockedAt` is the one-shot sentinel: it is always set to a non-zero
        // timestamp on the first lock, so the guard holds for any `amount`.
        if ($.locks[token].lockedAt != 0) revert AlreadyLocked();
        if (IERC20(lpPair).balanceOf(address(this)) < amount) revert InsufficientLPBalance();
        $.locks[token] = LockInfo({lpPair: lpPair, amount: amount, lockedAt: block.timestamp});
        emit LPLocked(token, lpPair, amount);
    }
