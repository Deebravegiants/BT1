### Title
Unconstrained `calldataHash` preimage lets any caller mutate `feeStructure`, `relay`, and `externalActionData.externalAddress` while reusing a valid proof - ([File: contracts/CircomDataBuilder.sol])

### Summary
`CircomDataBuilder.getHashedCalldata`/`getHashedCalldata1`/`getHashedCalldata2` define how `feeStructure`, `relay`, `externalActionData`, `hookData`, `slippageValues`, `onChainCreation`, `originalSender` and `extraData` are supposed to be bound into `circomData.calldataHash`, but this recomputation is never invoked anywhere else in the codebase to check it against the `calldataHash` value actually supplied in calldata. `formBasicInput` simply forwards the caller-supplied `circomData.calldataHash` as a public signal [1](#0-0) , so the SNARK only proves knowledge of a signature over an opaque field element - it never proves that element is the hash of the specific `feeStructure`/`relay`/`externalActionData` the transaction actually executes.

### Finding Description
The claimed equality is: `circomData.calldataHash == getHashedCalldata(circomData)` for the `circomData` struct the chain acts on. Tracing the reachable path:

- `getHashedCalldata2` folds `hookData`, `encryptedOutputs`, `onChainEncryptedOutput`, `feeStructure`, `onChainCreation`, `originalSender`, `extraData` into `calldataHash2`, and `getHashedCalldata1` folds `publicSignalCount`, `relay`, `emporiumMessage`, `externalActionData`, `slippageValues` into `calldataHash1`; both combine into `getHashedCalldata` [2](#0-1) .
- `getSignedMessageHash` only consumes `circomData.calldataHash` as an already-opaque number when building `signedMessageHash` [3](#0-2) .
- `formBasicInput` places `circomData.calldataHash` directly into the public input vector without ever calling `getHashedCalldata(circomData)` to check it against the struct actually being executed [4](#0-3) .
- `Hinkal.transact` calls `hinkalHelper.performHinkalChecks` to build `inputForCircom`, then calls `verifyProof`/`buildVerifierId` with that vector [5](#0-4) ; nowhere in the visible checks (`dimensionsCheck`, the `feeStructure.variableRate <= 10000` bound, `checkOnchainCreation`) is `getHashedCalldata` re-invoked to enforce the binding [6](#0-5) .
- `getHashedCalldata`/`getHashedCalldata1`/`getHashedCalldata2` have no callers anywhere in the repo outside their own definitions, confirming they are effectively dead validation code - the binding they are meant to enforce is never checked on-chain.

Root cause: the circuit and the SNARK verifier only constrain the numeric value of `calldataHash` as a public signal (via the pairing check, e.g. `mainEVMCircuit2x2x2v4.sol` reading `pubSignals` directly into `g1_mulAccC`) [7](#0-6) . That number was fixed off-chain by whoever generated the proof for a specific `feeStructure`/`relay`/`externalActionData`. But since `Hinkal.transact` never recomputes `getHashedCalldata` from the calldata `circomData` and compares it to the submitted `calldataHash`, any caller can resubmit the exact same `(a,b,c)` proof and the exact same `calldataHash` number while substituting a completely different `feeStructure` (feeToken/flatFee/variableRate), `relay`, or `externalActionData.externalAddress` in the surrounding calldata struct. `_internalTransact` then uses these attacker-substituted values directly for fee math and recipient selection [8](#0-7) .

Existing guards don't catch this: `performHinkalChecks`'s `dimensionsCheck`/`checkOnchainCreation` only validate array-length relationships and bounds on `variableRate`, not the hash binding; `verifyProof` only checks the SNARK pairing over the (unchanged) public-input numbers; `rootHashExists`, nullifier insertion, and the balance/slippage `require`s in `Hinkal.transact` operate on `amountChanges`/`balanceDif` which are independently included in the public input vector and thus are separately constrained - but `feeStructure`, `relay`, and `externalActionData.externalAddress` are not part of that vector at all, only hashed into the unverified `calldataHash`.

### Impact Explanation
Because `circomData.externalActionData.externalAddress` (withdrawal/deposit recipient) and `circomData.relay` (fee recipient) are both folded into the never-recomputed `calldataHash1`, and `feeStructure` is folded into the never-recomputed `calldataHash2`, any party who can see or resubmit a valid `transact` calldata (including the original submitter/attacker on their own transaction) can:
- Zero out `feeStructure.flatFee`/`variableRate` to avoid paying relay fees (High: theft/freezing of protocol/relay fees), or
- Redirect `circomData.relay` to their own address to capture someone else's relay fee (High/Critical: theft of relay fees not belonging to them), or
- Swap `externalActionData.externalAddress` to redirect the withdrawn/deposited funds to an address never authorized by the prover's signature (Critical: moving assets a wallet owner/prover never authorized), since `_internalTransact` pays out to `circomData.externalActionData.externalAddress` directly using the caller-supplied (unverified) struct.

This is repeatable for every `transact` call observed in the mempool or reused off-chain, since the proof itself never changes and remains valid.

### Likelihood Explanation
The attacker needs only to observe or possess a valid `(a,b,c)` proof and its accompanying `circomData` (their own transaction qualifies trivially, and any public mempool `transact` call is visible to anyone). No privileged role, no signature forgery, and no circuit break is required - only omission of an on-chain equality check that the codebase's own `CircomDataBuilder` helper functions were clearly designed to enforce but which is never invoked. This makes the finding highly likely to be practically exploitable, contingent on confirming (outside the scope of what I could inspect) that `performHinkalChecks`'s full body - which I could not fully view - does not perform this recomputation elsewhere.

### Recommendation
In `Hinkal.transact` (or inside `performHinkalChecks`), recompute `getHashedCalldata(circomData)` and `require(circomData.calldataHash == computedHash, "calldataHash mismatch")` before calling `verifyProof`, so that `feeStructure`, `relay`, `externalActionData`, `hookData`, `slippageValues`, `onChainCreation`, `originalSender`, and `extraData` are cryptographically bound to the exact values the proof was generated against.

### Proof of Concept
Foundry test plan:
1. Generate one valid proof `(a,b,c)` plus `circomData_A` with `feeStructure = {feeToken: T, flatFee: 100, variableRate: 50}`, `relay = relayA`, `externalActionData.externalAddress = userA`, computing `calldataHash = getHashedCalldata(circomData_A)` off-chain and using it to build `signedMessageHash`.
2. Call `Hinkal.transact(a, b, c, dimensions, circomData_A)` - assert success and record relay fee paid to `relayA` and funds sent to `userA`.
3. Build `circomData_B` identical to `circomData_A` except `feeStructure = {feeToken: T, flatFee: 0, variableRate: 0}` and/or `externalActionData.externalAddress = attacker`, but keep `calldataHash` numerically unchanged (same value from step 1).
4. Call `Hinkal.transact(a, b, c, dimensions, circomData_B)` with the SAME proof - assert it also succeeds (`verifyProof` returns true because the public-input vector, including `calldataHash`, is unchanged), but assert the effects differ: no/zero relay fee paid, or funds routed to `attacker` instead of `userA`.
5. Assert the equality `getHashedCalldata(circomData_B) != circomData_B.calldataHash` while the transaction still executed - proving the invariant "value acted on == value the circuit constrained" is broken.

        uint256 calldataHash1 = getHashedCalldata1(circomData);

    function dimensionsCheck(
        CircomData calldata circomData,
        Dimensions calldata dimensions
    ) internal pure {
        require(
            circomData.erc20TokenAddresses.length == dimensions.tokenNumber,
            "erc20TokenAddresses number should be equal to token number"
        );
        require(
            circomData.amountChanges.length == dimensions.tokenNumber,
            "AmountChanges number should be equal to token number"
        );

        require(
            circomData.onChainCreation.length == dimensions.tokenNumber,
            "onchain creation is equal to tokens count"
        );

        require(
            circomData.slippageValues.length == dimensions.tokenNumber,
            "slippageValues length should be equal to tokens count"
        );

        require(
            circomData.inputNullifiers.length == dimensions.tokenNumber,
            "InputNullifiers number should be equal to token number"
        );

        uint previousNullifierAmount = circomData.inputNullifiers.length > 0
            ? circomData.inputNullifiers[0].length
            : 0;
        for (uint i = 1; i < circomData.inputNullifiers.length; i++) {
            require(
                circomData.inputNullifiers[i].length == previousNullifierAmount,
                "Nullifier amount should be equal"
            );
        }
        require(
            previousNullifierAmount == dimensions.nullifierAmount,
            "Actual and Claimed Nullifier Amount should be equal"
        );

        require(
            circomData.outCommitments.length == dimensions.tokenNumber,
            "OutCommitments number should be equal to token number"
        );

        uint previousCommitmentAmount = circomData.outCommitments.length > 0
            ? circomData.outCommitments[0].length
            : 0;

        for (uint i = 1; i < circomData.outCommitments.length; i++) {
            require(
                circomData.outCommitments[i].length == previousCommitmentAmount,
                "Commitment amount should be equal"
            );
        }
        require(
            previousCommitmentAmount == dimensions.outputAmount,
            "Actual and Claimed Commitment Amount should be equal"
        );

        require(
            circomData.encryptedOutputs.length == dimensions.tokenNumber,
            "EncryptedOutputs number should be equal to token number"
        );

        uint previousEncryptedOutputAmount = circomData
            .encryptedOutputs
            .length > 0
            ? circomData.encryptedOutputs[0].length
            : 0;

        for (uint i = 0; i < circomData.encryptedOutputs.length; i++) {
            require(
                circomData.encryptedOutputs[i].length ==
                    previousEncryptedOutputAmount,
                "Encrypted output amount should be equal"
            );

            for (uint j = 0; j < circomData.encryptedOutputs[i].length; j++) {
                require(
                    circomData.encryptedOutputs[i][j].length > 0,
                    "Missing encrypted output for off-chain commitment"
                );
            }
        }

        require(
            previousEncryptedOutputAmount == dimensions.outputAmount,
            "Actual and Claimed Encrypted Output Amount should be equal"
        );

        require(
            circomData.onChainEncryptedOutput.length > 0,
            "Missing encrypted output for on-chain commitment"
        );

        require(
            circomData.stealthAddressStructure.H0x != 0,
            "H0x cannot be zero"
        );

        require(
            circomData.feeStructure.variableRate <= 10000,
