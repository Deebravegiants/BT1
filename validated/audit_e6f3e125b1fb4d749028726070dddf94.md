Confirmed: no mutex serializes concurrent calls into `Authorize` — `HandleUserTriggerRequest` calls `h.authorizeRequest` per-request with no locking around it [1](#0-0) , and `WorkflowMetadataHandler.Authorize` performs `isReplay` (RLock) and `recordUsage` (Lock) as two independent critical sections with unlocked work (authorized-key map lookup) in between [2](#0-1) [3](#0-2) . Audit Report

## Title
JWT replay-protection check-then-act race in `WorkflowMetadataHandler.Authorize` allows concurrent replay of a single-use HTTP-trigger JWT - (File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go)

## Summary
`WorkflowMetadataHandler.Authorize` enforces single-use JWTs for the internet-facing HTTP trigger by checking `jwtReplayCache.isReplay(jti)` and later calling `jwtReplayCache.recordUsage(jti)`, but these are two independently-locked operations (`RLock`/`RUnlock` then, after unlocked work, `Lock`/`Unlock`) rather than one atomic check-and-set. Two requests carrying the identical valid, signed JWT submitted concurrently can both pass `isReplay` before either calls `recordUsage`, both getting authorized and forwarded to the DON as legitimate `workflows.execute` invocations, defeating the intended "used-once" guarantee.

## Finding Description
`Authorize` is invoked per-request from `httpTriggerHandler.authorizeRequest`, called from `HandleUserTriggerRequest`, with no synchronization serializing concurrent requests carrying the same `jti` [1](#0-0) . Inside `Authorize`, the replay check and the state mutation are separate critical sections:

```go
if h.jwtCache.isReplay(claims.ID) { ... return error }
...
h.jwtCache.recordUsage(claims.ID)
``` [4](#0-3) 

`isReplay` takes an `RLock`, checks map membership, and releases; `recordUsage` separately takes a full `Lock` to insert the `jti` [3](#0-2) . Between these two calls, `Authorize` does unlocked work (map lookup on `h.authorizedKeys[workflowID]`, building the `AuthorizedKey`). Two goroutines processing the same JWT concurrently can both observe `isReplay == false` before either executes `recordUsage`, so both pass authorization.

I checked for any additional lock or single-flight mechanism around the `Authorize` call path (e.g., in `authorizeRequest`, `HandleUserTriggerRequest`, or the JSON-RPC dispatch layer) and found none — each inbound request is processed independently and concurrently, with `Authorize` itself being the only replay-prevention mechanism.

The existing test suite only exercises the *sequential* case (`TestWorkflowMetadataHandler_Authorize`, subtest "JWT replay protection", and `TestHttpTriggerHandler_HandleUserTriggerRequest`, subtest "duplicate JWT token and request ID") [5](#0-4) [6](#0-5) , calling `Authorize`/`HandleUserTriggerRequest` twice one after another — this does not exercise or protect against concurrent invocation, so the race is not currently tested or guarded against.

Notably, an analogous replay-protection mechanism elsewhere in the same codebase, `RequestReplayGuard.CheckAndRecord` (used by the Vault JWT/allowlist authorizer), correctly implements the check and the record as a single atomic operation under one lock [7](#0-6) , and has a dedicated concurrency test proving exactly-once semantics under 100 concurrent goroutines [8](#0-7) . This confirms the maintainers are aware of the check-then-act hazard and have solved it correctly in one place, while the `jwtReplayCache` in `workflow_metadata_handler.go` does not use the same pattern.

## Impact Explanation
Exploiting the race allows an unprivileged actor able to duplicate a valid, in-flight (or otherwise obtainable) signed JWT to obtain two authorized executions of a `workflows.execute` HTTP trigger request from a single JWT, instead of the intended exactly-one execution. This is a duplicate/unauthorized job run resulting from an authentication single-use guarantee bypass, potentially causing duplicate on-chain actions or other duplicate side effects attributable to the workflow owner, and evading the intended one-shot rate/compute budget for that authorization.

## Likelihood Explanation
The attack requires only the ability to submit the same valid signed request bytes (`tokenString` + JSON-RPC body) twice, essentially simultaneously, to the gateway's HTTP trigger endpoint — no signing key, no privileged role, and no cryptographic break are needed. The race window spans a map lookup and struct construction between the `RLock`-protected read and `Lock`-protected write, which, while narrow, is real, remotely triggerable, and deterministically demonstrable via a Go concurrency test (e.g., firing `Authorize` concurrently from multiple goroutines with the same JWT, analogous to `TestRequestReplayGuard_ConcurrentAccess` for the Vault path, but expected to fail for `jwtReplayCache`).

## Recommendation
Merge `isReplay` and `recordUsage` into a single atomic check-and-set method (e.g., `checkAndRecord(jti) (alreadyUsed bool)`) that takes one `Lock` for the full check-then-insert sequence, mirroring the correct pattern already used in `core/capabilities/vault/request_replay_guard.go`'s `CheckAndRecord`. Call this single method from `Authorize` immediately when validating replay, removing the separate unlocked `isReplay`/`recordUsage` calls.

## Proof of Concept
1. Write a Go test in `core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler_test.go` that constructs one signed JWT (`CreateRequestJWT` + `SignedString`) for a valid `workflows.execute` request, as done in the existing "JWT replay protection" subtest.
2. Launch N goroutines (e.g., 50-100) that all call `handler.Authorize(workflowID, tokenString, req)` concurrently with the same token, collecting each returned `(key, err)`.
3. Assert that more than one goroutine returns a non-nil key/no error (i.e., successCount > 1), analogous to `TestRequestReplayGuard_ConcurrentAccess` in `core/capabilities/vault/request_replay_guard_test.go`, which asserts exactly one success for the correctly-implemented guard — the `jwtReplayCache` variant is expected to allow more than one success under race conditions, proving the TOCTOU bypass.

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}

func (cache *jwtReplayCache) isReplay(jti string) bool {
	cache.mu.RLock()

func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}

func TestRequestReplayGuard_ConcurrentAccess(t *testing.T) {
	guard := NewRequestReplayGuard()
	futureExpiry := time.Now().UTC().Unix() + 100

	const goroutines = 100
	results := make([]error, goroutines)
	var wg sync.WaitGroup
	wg.Add(goroutines)

	for i := range goroutines {
		go func(idx int) {
			defer wg.Done()
			results[idx] = guard.CheckAndRecord("same-digest", futureExpiry)
		}(i)
	}
	wg.Wait()

	successCount := 0
	duplicateCount := 0
	for _, err := range results {
		if err == nil {
			successCount++
		} else {
			require.ErrorIs(t, err, ErrRequestAlreadySeen)
			duplicateCount++
		}
	}

	assert.Equal(t, 1, successCount, "exactly one goroutine should succeed")
	assert.Equal(t, goroutines-1, duplicateCount, "all others should be rejected as duplicates")
}
