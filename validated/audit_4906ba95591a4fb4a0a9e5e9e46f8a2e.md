### Title
Unvalidated `shop` parameter in `Oauth.begin_auth` allows forced OAuth redirection to an attacker-controlled host - (File: `lib/shopify_api/auth/oauth.rb`)

### Summary
`ShopifyAPI::Auth::Oauth.begin_auth` builds the OAuth "authorize" redirect URL directly from the caller-supplied `shop` string without ever validating that it is a genuine, trusted Shopify domain. Every other entry point in the gem that accepts a `shop` string and turns it into a request host (`ClientCredentials.client_credentials`, `RefreshToken.refresh_access_token`, `TokenExchange.migrate_to_expiring_token`, `Clients::Graphql::Storefront#initialize`) explicitly calls `Utils::ShopValidator.sanitize!(shop)` first. `begin_auth` is the one path that skips this check.

### Finding Description
`begin_auth` takes `shop:` and interpolates it straight into the redirect target: [1](#0-0) 
The host portion of the returned `auth_route` comes from `auth_base_uri(shop)`: [2](#0-1) 
which simply does `"https://#{shop}/admin"` with no domain-format validation at all.

By contrast, every sibling method that turns a `shop:` argument into a request host does call the dedicated validator before using it: [3](#0-2) [4](#0-3) [5](#0-4) [6](#0-5) 

`ShopValidator.sanitize!` exists specifically to enforce that a shop string resolves to one of the `TRUSTED_SHOPIFY_DOMAINS` (`shopify.com`, `myshopify.io`, `myshopify.com`, `spin.dev`, `shop.dev`) and rejects anything else: [7](#0-6) 

The binding that should hold is: *the domain the user is redirected to for authorization* == *a domain in `TRUSTED_SHOPIFY_DOMAINS`*. `begin_auth` never enforces this equality, so an attacker-influenced `shop` value (e.g. `evil.example.com`) is accepted verbatim and turned into `https://evil.example.com/admin/oauth/authorize?...&state=<nonce>&redirect_uri=<legit-app-redirect>`.

Note the query built for the authorize URL does not include `client_secret` — only `client_id` (public), `scope`, `redirect_uri`, and `state` are sent: [8](#0-7) 
so this does not directly leak the app's secret. The state nonce and its cookie are also generated correctly here and are not themselves attacker-controlled: [9](#0-8) 

### Impact Explanation
If a host application passes a shop value it received from an untrusted source (e.g. a query parameter on the login route, which is exactly the pattern shown in the gem's own usage docs: `shop = request.headers["Shop"]`) straight into `begin_auth`, the user's browser is redirected to an attacker-chosen host instead of Shopify. This is a forced/hijacked OAuth flow: the attacker's page can present a fake "Install/Authorize" screen, harvest merchant credentials via phishing, or redirect back into the app's legitimate callback with attacker-influenced parameters to attempt to manipulate the flow. Because completion of `validate_auth_callback` still requires an HMAC signed with `api_secret_key` (which the attacker does not have), the attacker cannot forge a fully valid callback and obtain a real access token — so this stops short of full authentication bypass, but it still qualifies as a "forced OAuth completion" / redirect-target integrity issue under the High-impact category, and is a real inconsistency versus the validation performed by every comparable method in the gem.

### Likelihood Explanation
Likelihood depends on the host application forwarding an untrusted `shop` value into `begin_auth`. This is realistic because the gem does not document nor enforce that the caller must pre-validate `shop` before calling `begin_auth` (unlike, say, `ClientCredentials`/`RefreshToken`, which perform validation internally regardless of what the caller passes). Given the gem's own example code retrieves `shop` directly from a request header without sanitization, and the sibling functions all defensively validate internally, the omission in `begin_auth` is a genuine gap in the library's defense-in-depth rather than something that only manifests if the host "ignores documented behavior."

### Recommendation
Call `Utils::ShopValidator.sanitize!(shop)` (or `sanitize_shop_domain`) inside `ShopifyAPI::Auth::Oauth.begin_auth` before constructing `auth_base_uri(shop)`, mirroring the validation already performed in `ClientCredentials.client_credentials`, `RefreshToken.refresh_access_token`, `TokenExchange.migrate_to_expiring_token`, and `Clients::Graphql::Storefront#initialize`. This ensures the OAuth authorize redirect can only ever target a trusted Shopify domain regardless of what the caller supplies.

### Proof of Concept
```ruby
ShopifyAPI::Context.setup(api_key: "key", api_secret_key: "secret", api_version: "2024-01", host: "https://my-app.example.com", scope: "read_products")

result = ShopifyAPI::Auth::Oauth.begin_auth(shop: "evil-phishing-site.example", redirect_path: "/auth/callback")
puts result[:auth_route]
# => "https://evil-phishing-site.example/admin/oauth/authorize?client_id=key&scope=read_products&redirect_uri=https%3A%2F%2Fmy-app.example.com%2Fauth%2Fcallback&state=<nonce>&grant_options%5B%5D=per-user"
```
No exception is raised and no `ShopValidator` check rejects the non-Shopify host, unlike calling `ShopifyAPI::Auth::ClientCredentials.client_credentials(shop: "evil-phishing-site.example")`, which immediately raises `ShopifyAPI::Errors::InvalidShopError`.

        def begin_auth(shop:, redirect_path:, is_online: true, scope_override: nil)
          scope = if scope_override.nil?
            ShopifyAPI::Context.scope
          elsif scope_override.is_a?(ShopifyAPI::Auth::AuthScopes)
            scope_override
          else
            ShopifyAPI::Auth::AuthScopes.new(scope_override)
          end

          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = SecureRandom.alphanumeric(NONCE_LENGTH)

          cookie = SessionCookie.new(value: state, expires: Time.now + 60)

          query = {
            client_id: ShopifyAPI::Context.api_key,
            scope: scope.to_s,
            redirect_uri: "#{ShopifyAPI::Context.host}#{redirect_path}",
            state: state,
            "grant_options[]": is_online ? "per-user" : "",
          }

          query_string = URI.encode_www_form(query)
          auth_route = auth_base_uri(shop) + "/oauth/authorize?#{query_string}"

          { auth_route: auth_route, cookie: cookie }
        end

      TRUSTED_SHOPIFY_DOMAINS = T.let(
        [
          "shopify.com",
          "myshopify.io",
          "myshopify.com",
          "spin.dev",
          "shop.dev",
        ].freeze,
        T::Array[String],
      )

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
