Token Exchange leaks the app's `client_secret` to an attacker-controlled host because the JWT `dest` claim is used unsanitized as the outbound request host - (File: `lib/shopify_api/auth/token_exchange.rb`)

### Summary
`ShopifyAPI::Auth::TokenExchange.exchange_token` builds the OAuth token-exchange session directly from the session token's `dest` claim without ever passing it through `Utils::ShopValidator.sanitize!`. Every other credential-exchanging method in this gem (`client_credentials`, `refresh_access_token`, `migrate_to_expiring_token`) validates the shop string against `ShopValidator::TRUSTED_SHOPIFY_DOMAINS` before using it. `exchange_token` skips this step, so the value becomes the literal request host that receives the app's `client_id`/`client_secret` in the POST body.

### Finding Description
`JwtPayload#initialize` verifies the JWT signature (HMAC with `api_secret_key`) and checks `aud == Context.api_key`, but it does not check that `dest` is a trusted Shopify domain [1](#0-0) . `JwtPayload#shop` simply strips the `https://` prefix from `dest` and returns it verbatim [2](#0-1) .

`TokenExchange.exchange_token` takes this unvalidated value (`dest_shop = jwt_payload.shop`) and uses it directly to build the session that drives the outbound HTTP request: [3](#0-2) 

Contrast this with the sibling methods in the same file and module, which all call `Utils::ShopValidator.sanitize!(shop)` before constructing the session: [4](#0-3) [5](#0-4) [6](#0-5) 

`ShopValidator.sanitize!` exists precisely to constrain a shop string to `TRUSTED_SHOPIFY_DOMAINS` (`shopify.com`, `myshopify.io`, `myshopify.com`, `spin.dev`, `shop.dev`), rejecting arbitrary attacker-controlled hosts: [7](#0-6) 

`Clients::HttpClient` then builds the request URI straight from `session.shop` when no `Context.api_host` override is configured: [8](#0-7) 

So the equality that should hold — "host the app validated as a legitimate Shopify tenant" == "host that receives the `client_secret`" — is broken: the `dest` claim is trusted as the destination host with only signature/`aud` checks, not a domain-allowlist check.

### Impact Explanation
This is a credential-exfiltration path for the app's `client_secret`, which the docs classify as Critical impact. A shop able to get Shopify to issue a session token whose `dest` claim resolves to a host outside `TRUSTED_SHOPIFY_DOMAINS` (e.g. via a shop's primary/custom domain configuration under the merchant's own DNS control) causes the app to POST `client_id`/`client_secret`/`subject_token` (the session token itself) directly to that host over HTTPS. That grants a malicious tenant possession of the app's `client_secret`, enabling it to mint tokens or impersonate the app across all its merchant tenants — a cross-tenant/credential-theft outcome.

### Likelihood Explanation
Every other OAuth credential-issuing entry point in the module (`client_credentials`, `refresh_access_token`, `migrate_to_expiring_token`) enforces `ShopValidator.sanitize!`, showing this check is the intended invariant for any code path that sends `client_secret` to a shop-derived host. `exchange_token` is the sole exception and is also the documented, recommended flow for embedded apps (`docs/usage/oauth.md`), making it the most heavily used code path, and the omission is a straightforward oversight rather than requiring any secret/token access to trigger — it is reachable by any party able to cause Shopify to issue a session token whose `dest` is not myshopify/admin-trusted.

### Recommendation
In `TokenExchange.exchange_token`, validate `dest_shop` with `Utils::ShopValidator.sanitize!(dest_shop)` (as done in `client_credentials`, `refresh_access_token`, and `migrate_to_expiring_token`) before constructing `shop_session`/`Session.new`, raising `Errors::InvalidShopError` for any `dest` claim that does not resolve to a trusted Shopify domain.

### Proof of Concept
1. Obtain (or have Shopify legitimately issue) a session token whose `dest` claim is a host that is not in `ShopValidator::TRUSTED_SHOPIFY_DOMAINS` (e.g. a shop-controlled custom/primary domain that resolves under attacker DNS control), signed correctly with the app's real `api_secret_key`/`aud` matching `Context.api_key` — this token passes all checks in `JwtPayload#initialize`.
2. Call:
```ruby
ShopifyAPI::Auth::TokenExchange.exchange_token(
  session_token: attacker_controlled_dest_token,
  requested_token_type: ShopifyAPI::Auth::TokenExchange::RequestedTokenType::OFFLINE_ACCESS_TOKEN,
)
```
3. `dest_shop` (equal to the attacker-controlled host) is used unsanitized in `Session.new(shop: dest_shop)` [9](#0-8) .
4. `Clients::HttpClient.new(session: shop_session, base_path: "/admin/oauth")` builds `@base_uri = "https://#{session.shop}"` from that host [8](#0-7) .
5. The subsequent POST to `access_token` sends `client_id`, `client_secret`, and the raw session token in the request body to the attacker-controlled host, exfiltrating the app's `client_secret`.

      class << self

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
