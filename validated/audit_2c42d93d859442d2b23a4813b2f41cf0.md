The external report describes a vulnerability in `LMPVaultRouter.sol` where WETH deposited into the contract can be stolen due to a lack of access control on the `unwrapWETH9` function.  This allows any unprivileged user to withdraw the WETH. 

### Title
WETH deposited into `LMPVaultRouter.sol` can be stolen due to missing access control - ([Project: AuditingProject/AllProjects] [File: issues.md])

### Summary
The `unwrapWETH9` function in `LMPVaultRouter.sol` lacks proper access control, allowing any external caller to withdraw WETH that has been deposited into the contract.  This vulnerability is similar to a pattern identified in the `AuditingProject/AllProjects` codebase where a router approves a caller-supplied address without validation. 

### Finding Description
When a user calls `mint` or `deposit` with `msg.value`, the ETH is wrapped into WETH and held by the `LMPVaultRouter.sol` contract.  The `unwrapWETH9` function, which is intended to convert WETH back to ETH and send it to a recipient, does not have any access restrictions.  Consequently, any arbitrary user can call `unwrapWETH9` and drain the WETH balance from the contract. 

### Impact Explanation
Any ETH sent to the `LMPVaultRouter.sol` contract, which is subsequently wrapped into WETH, is at risk of being stolen by an attacker.  This leads to a direct loss of user funds. 

### Likelihood Explanation
The likelihood of this vulnerability being exploited is high because the `unwrapWETH9` function is externally callable and lacks any authorization checks.  An attacker only needs to observe WETH being deposited into the contract and then call `unwrapWETH9` to steal the funds. 

### Recommendation
Implement robust access control mechanisms for the `unwrapWETH9` function.  Only authorized entities, such as the contract owner or a designated role, should be permitted to call this function. 

### Proof of Concept
The `AuditingProject/AllProjects` codebase contains a similar pattern described as "a router calls `approve(asset, vault, amount)` where `vault` is a **caller-supplied parameter**; an attacker passes a phantom vault with the right interface, the router approves it, and the attacker's contract pulls the funds later".  While this specific example refers to an `approve` function, the underlying principle of an unprivileged caller manipulating a contract's funds through a public function is analogous. 

In the context of `LMPVaultRouter.sol`, the `unwrapWETH9` function allows any caller to initiate a withdrawal of WETH from the contract. 

1.  A user (Alice) calls `mint` or `deposit` on `LMPVaultRouter.sol`, sending ETH with `msg.value`. 
2.  The `_processEthIn` function is called, which wraps the ETH into WETH and deposits it into the `LMPVaultRouter.sol` contract. 
3.  An attacker (Bob) observes the WETH balance increase in `LMPVaultRouter.sol`. 
4.  Bob calls the `unwrapWETH9` function, specifying himself as the `recipient`. 
5.  The `unwrapWETH9` function, lacking access control, executes the `weth9.withdraw(balanceWETH9)` and `Address.sendValue(payable(recipient), balanceWETH9)` calls, transferring all WETH from the contract to Bob.
