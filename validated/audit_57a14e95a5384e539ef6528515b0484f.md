### Title
Unbounded per-request linear scan over a globally-shared, attacker-growable allowlist in Vault gateway authorization - ([File: core/capabilities/vault/allow_list_based_auth.go])

### Summary
`allowListBasedAuth.AuthorizeRequest` authorizes every unprivileged Vault secrets request (`SecretsCreate`, `SecretsUpdate`, `SecretsDelete`, `SecretsList`) that arrives through the internet-facing Gateway by doing an O(n) linear scan over the *entire* in-memory allowlisted-requests cache, repeated up to 11 times with 3-second sleeps between attempts. This cache holds every non-expired allowlisted request from *every* workflow owner across the whole system, and entries are only removed by expiry pruning — there is no cap on how many entries a single owner (or the aggregate of all owners) can add. This is the same bug class as the reported `TokenState.getLockedCount` issue: an operation on the hot request path grows linearly with a list an unprivileged actor can make arbitrarily large, and it runs on every single incoming request rather than being precomputed/indexed.

### Finding Description
`allowListBasedAuth.AuthorizeRequest` calls `findAllowlistedItemWithRetry`, which for each retry attempt fetches the full snapshot via `WorkflowRegistrySyncer.GetAllowlistedRequests` and calls `fetchAllowlistedItem`, a plain `for` loop over the slice comparing `RequestDigest` byte arrays: [1](#0-0) 

```
func (r *allowListBasedAuth) findAllowlistedItemWithRetry(...) {
	for attempt := 0; attempt <= r.retryCount; attempt++ {
		allowedRequests := r.workflowRegistrySyncer.GetAllowlistedRequests(ctx)
		...
		allowlistedRequest := r.fetchAllowlistedItem(allowedRequests, requestDigestBytes32)
		...
	}
}
func (r *allowListBasedAuth) fetchAllowlistedItem(allowListedRequests []..., digest [32]byte) *... {
	for _, item := range allowListedRequests {
		if item.RequestDigest == digest {
			return &item
		}
	}
	return nil
}
```

`retryCount` is 10 and `retryInterval` is 3 seconds, so a request whose digest is not (yet) present scans the full list up to 11 times and blocks the calling goroutine for up to ~33 seconds: [2](#0-1) 

The backing list (`w.allowListedRequests`) is populated by `syncAllowlistedRequests`, which merges newly-read on-chain entries with the still-unexpired subset of the previous snapshot, and is *shared across all workflow owners* rather than being indexed/keyed by owner or digest: [3](#0-2) 

The only removal mechanism is expiry (`request.ExpiryTimestamp > now`), and the expiry timestamp for each entry is chosen by the workflow owner who calls `AllowlistRequest` on-chain (an unprivileged actor from the node's perspective). Any workflow owner can therefore add an unbounded number of entries to this globally shared list (bounded only by the number of transactions/gas they're willing to spend, not by any per-owner or global cap enforced in this Go code — no such cap was found in the reachable Go/contract-reader code), and can additionally choose long expiry windows so their entries persist. Each such addition increases `len(w.allowListedRequests)`, which linearly increases the cost of `fetchAllowlistedItem` for *every other user's* Vault requests, since the scan is not scoped by owner or digest lookup — it's a full O(n) walk regardless of which owner issued the request.

This directly parallels the reported `getLockedCount` bug: an unbounded, attacker-influenced collection is iterated in full on every hot-path request instead of being looked up in O(1) (e.g., via a map keyed by digest).

### Impact Explanation
This is a request-handling/allowlist path inside the internet-facing Gateway → node Vault flow (`GatewayHandler.HandleGatewayMessage` → `GatewayVaultRequestProcessor.ProcessRequest` → `Authorizer.AuthorizeRequest` → `allowListBasedAuth.AuthorizeRequest`), reachable by any client sending Vault `SecretsCreate`/`SecretsUpdate`/`SecretsDelete`/`SecretsList` requests without a JWT (`req.Auth == ""`), which is the default path for unmodified existing clients: [4](#0-3) 

As the shared allowlist grows (driven by legitimate or adversarial owners who keep allowlisting requests with long expiries), authorization latency for every user's request grows linearly, and unauthorized/mismatched requests additionally suffer the full 11×scan × ~33s retry-and-sleep penalty per request. Because the goroutine handling a Vault gateway request blocks synchronously in this loop, a sufficiently large allowlist combined with concurrent unauthorized requests can degrade or effectively deny Vault service availability for all workflow owners on that node — a resource-usage DoS caused by a reachable, unprivileged-actor request pattern, analogous in class (unbounded iteration on attacker-growable state, on the hot path, no O(1) precomputation) to the original `getLockedCount` finding.

### Likelihood Explanation
Likelihood is moderate: growing the shared list requires an on-chain `AllowlistRequest` transaction (a cost to the attacker), so this is not "free" the way an in-memory-only structure would be, and the retry loop is a per-request cost rather than a permanent lock. However, no per-owner or global size cap was found enforced in the reachable Go code, and any authorized workflow owner is effectively unprivileged with respect to other tenants sharing the same node/allowlist, so a moderately funded or normal high-volume owner naturally causes this list to grow over time, degrading the shared authorization path for everyone.

### Recommendation
Replace the shared linear-scan slice with an O(1) lookup structure (e.g., a map keyed by `RequestDigest`) maintained by `workflowRegistry.syncAllowlistedRequests`/`GetAllowlistedRequests`, so `fetchAllowlistedItem` becomes a map lookup instead of iterating the full list. Additionally consider bounding per-owner allowlist size/expiry, and avoid the full re-scan-and-sleep retry pattern blocking the request-handling goroutine (e.g., use a change-notification/wait mechanism scoped to the specific digest instead of repeated full-list rescans).

### Proof of Concept
Conceptual, since exploitation requires on-chain transactions against `WorkflowRegistry` which is out of scope to execute here:
1. An unprivileged workflow owner repeatedly calls `AllowlistRequest(digest, expiry)` on the `WorkflowRegistry` contract with far-future expiry timestamps, growing the on-chain allowlist to a large size (e.g., tens of thousands of entries) over time — each addition costs only normal gas and is not otherwise capped in the reviewed code.
2. `workflowRegistry.syncAllowlistedRequests` (`core/services/workflows/syncer/v2/workflow_registry.go:766`) pulls and retains all of these unexpired entries in `w.allowListedRequests`, a single shared in-memory slice.
3. Any other user's Vault `SecretsCreate`/`SecretsList`/etc. gateway request now triggers `allowListBasedAuth.AuthorizeRequest` → `findAllowlistedItemWithRetry` → `fetchAllowlistedItem`, which linearly scans the now-large list; requests whose digest is not present additionally incur up to 11 scans and ~33 seconds of blocking sleep.
4. As list size grows, authorization latency for all Vault requests on that node grows proportionally, degrading Vault availability for all tenants — demonstrating the same class of issue as the original `getLockedCount` unbounded-iteration bug, but here in a reachable, unprivileged-actor gateway authorization path rather than the audited Solidity contract.

```go
func (r *allowListBasedAuth) findAllowlistedItemWithRetry(ctx context.Context, req jsonrpc.Request[json.RawMessage], requestDigest string, requestDigestBytes32 [32]byte) (*workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest, []string, error) {
	for attempt := 0; attempt <= r.retryCount; attempt++ {
		allowedRequests := r.workflowRegistrySyncer.GetAllowlistedRequests(ctx)
		allowedRequestsStrs := make([]string, 0, len(allowedRequests))
		for _, rr := range allowedRequests {
			allowedReqStr := fmt.Sprintf("AuthorizedOwner: %s, RequestDigest: %s, ExpiryTimestamp: %d", rr.Owner.Hex(), hex.EncodeToString(rr.RequestDigest[:]), rr.ExpiryTimestamp)
			allowedRequestsStrs = append(allowedRequestsStrs, allowedReqStr)
		}
		r.lggr.Debugw("AllowListBasedAuth loaded allowlisted requests", "method", req.Method, "requestID", req.ID, "attempt", attempt+1, "allowedRequests", allowedRequestsStrs)

		allowlistedRequest := r.fetchAllowlistedItem(allowedRequests, requestDigestBytes32)
		if allowlistedRequest != nil {
			return allowlistedRequest, allowedRequestsStrs, nil
		}
		if attempt == r.retryCount {
			return nil, allowedRequestsStrs, nil
		}

		r.lggr.Debugw("AllowListBasedAuth request digest not yet allowlisted, retrying",
			"method", req.Method,
			"requestID", req.ID,
			"digestHexStr", requestDigest,
			"attempt", attempt+1,
			"maxAttempts", r.retryCount+1,
			"retryInterval", r.retryInterval)
		if err := sleepWithContext(ctx, r.retryInterval); err != nil {
			r.lggr.Debugw("AllowListBasedAuth retry canceled", "method", req.Method, "requestID", req.ID, "error", err)
			return nil, nil, err
		}
	}

	return nil, nil, nil // unreachable: loop always returns
}
```

```go
func (w *workflowRegistry) syncAllowlistedRequests(ctx context.Context) {
	ticker := w.getTicker(defaultTickIntervalForAllowlistedRequests)
	w.lggr.Debug("starting syncAllowlistedRequests")
	for {
		select {
		case <-ctx.Done():
			w.lggr.Debug("shutting down syncAllowlistedRequests, %s", ctx.Err())
			return
		case <-ticker:
			newAllowListedRequests, totalAllowlistedRequests, head, err := w.getAllowlistedRequests(ctx, w.contractReader)
			if err != nil {
				w.lggr.Errorw("failed to call getAllowlistedRequests", "err", err)
				continue
			}
			w.allowListedMu.Lock()
			// Prune expired requests
			activeAllowlistedRequests := []workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest{}
			expiredRequestsCount := 0
			for _, request := range w.allowListedRequests {
				if int64(request.ExpiryTimestamp) > time.Now().Unix() {
					activeAllowlistedRequests = append(activeAllowlistedRequests, request)
				} else {
					expiredRequestsCount++
				}
			}

			// Add new requests
			activeAllowlistedRequests = append(activeAllowlistedRequests, newAllowListedRequests...)
			w.allowListedRequests = activeAllowlistedRequests
			w.lastSeenAllowlistedRequestsCount = totalAllowlistedRequests
			w.lggr.Debugw("synced allowlisted requests",
				"newRequestsNum", len(newAllowListedRequests),
				"expiredRequestsNum", expiredRequestsCount,
				"activeRequestsNum", len(w.allowListedRequests),
				"lastSeenOnchainRequestsNum", w.lastSeenAllowlistedRequestsCount,
				"blockHeight", head.Height,
			)
			w.allowListedMu.Unlock()
```

```go
func (a *authorizer) authorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	// Requests without req.Auth continue using the allowlist-based path for backwards compatibility.
	// Existing clients do not populate the auth field yet, so treating an empty value as JWT would break them.
	if req.Auth == "" {
		return a.authorizeAllowListBasedAuth(ctx, req)
	}
	return a.authorizeJWTBasedAuth(ctx, req)
}
```
