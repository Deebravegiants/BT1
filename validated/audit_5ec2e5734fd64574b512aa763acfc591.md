## Custody Analog Found

### Title
Stale `TombStone` survives ordinary object transfers, letting a past owner reclaim an object out of `BURN_ADDRESS` after it changes hands and is legitimately burned - (File: `aptos-move/framework/aptos-framework/sources/object.move`)

### Summary
`object::burn` marks an object as "soft-burned" by attaching a `TombStone{original_owner}` resource to the object address while leaving `ObjectCore.owner` unchanged. Only one of the two ownership-transfer code paths — `transfer_with_ref` (the `LinearTransferRef`-based path) — clears this `TombStone` on transfer. The ordinary transfer path (`transfer`, `transfer_raw`, `transfer_call`, `transfer_to_object`, all of which bottom out in `transfer_raw_inner`) does **not** clear it. This asymmetry lets a party who once called `burn()` on an object they owned, then gave the object away through an ordinary transfer, later reclaim it out of `BURN_ADDRESS` via `unburn()` — even though the object has since had one or more legitimate owners who never knew about the stale tombstone and who deliberately sent the object to the well-known burn sink.

### Finding Description
`object::burn` creates the marker without moving the object: [1](#0-0) 

`transfer_with_ref` (used by refs-based flows) is the only place that removes a stale `TombStone` before performing the ownership change: [2](#0-1) 

But the ordinary transfer path — `transfer`, `transfer_raw`, `transfer_call`, `transfer_to_object` — goes through `transfer_raw_inner`, which only emits a `Transfer` event and updates `owner`; it never checks for or clears `TombStone`: [3](#0-2) 

`unburn` then trusts whatever `TombStone.original_owner` is currently stored, regardless of how many ordinary transfers happened after the tombstone was created, and regardless of who most recently and intentionally sent the object to `BURN_ADDRESS`: [4](#0-3) 

`BURN_ADDRESS` is explicitly documented and intended as the sink "where unwanted objects can be forcefully transferred to": [5](#0-4) 

Combining these: any owner can plant a `TombStone` naming themselves, hand the object off through the standard `transfer`/`transfer_raw`/`transfer_to_object` APIs (the tombstone silently rides along, only hiding the object from indexers), and later — after any number of legitimate owners have held it and one of them deliberately "burns" it by sending it to `BURN_ADDRESS` via an ordinary transfer — reclaim the object for themselves via `unburn`, overriding the actual burner's intent and the entire subsequent ownership chain.

### Impact Explanation
This breaks the object custody invariant that "object creation, transfer, burn... must preserve the intended controller." A stale, attacker-planted `TombStone` allows unauthorized owner reassignment of an object out of the canonical burn sink, effectively letting a former owner steal back (or steal outright) an object — and any resources/value nested under it (e.g., a token, an FA store object, or any resource moved to the object's address) — that current and intermediate legitimate owners believed was permanently destroyed or that never belonged to the reclaiming party in the current chain of custody. This is a high-severity custody/ownership-control break because it is fully unprivileged (any account can seed the exploit against its own object before giving it away) and defeats the documented guarantee of `BURN_ADDRESS` as a terminal sink.

### Likelihood Explanation
The attack requires only standard, unprivileged, publicly-callable entry functions (`burn`, `transfer`/`transfer_to_object`, and later `unburn`) with no special permissions, timing constraints, or races. The only precondition is that a subsequent owner in the chain uses the ordinary transfer path to send the object to `BURN_ADDRESS` rather than a `LinearTransferRef`-based burn/transfer — a very natural pattern since `BURN_ADDRESS` is documented for exactly this purpose and most simple objects/dApps do not generate a `TransferRef` for every object. This makes the scenario realistic for any marketplace, token, or object-composability flow that uses vanilla `object::transfer`.

### Recommendation
Make `TombStone` cleanup path-independent: have `transfer_raw_inner` (or a wrapper shared by both transfer paths) clear any existing `TombStone` whenever ownership actually changes, exactly as `transfer_with_ref` already does. Alternatively, disallow transferring a tombstoned object via the raw/ungated path entirely (require an explicit `unburn` first), so a `TombStone`'s validity can never outlive the owner who created it.

### Proof of Concept
1. Attacker `A` creates or already owns `Object<T> X`.
2. `A` calls `object::burn(A, X)` → `TombStone{original_owner: A}` is attached to `X`'s address; `X.owner` remains `A`.
3. `A` calls `object::transfer(A, X, B)` (ordinary transfer) to give/sell `X` to `B`. `TombStone` is untouched by `transfer_raw_inner`; `B` is unaware anything is different (the object behaves normally except being hidden from indexers).
4. `B` may optionally pass `X` through further legitimate owners via ordinary transfers — the stale `TombStone{original_owner: A}` persists at every hop.
5. At some point a legitimate current owner `C` decides to permanently retire `X` and calls `object::transfer(C, X, BURN_ADDRESS)` (the documented burn convention), believing the object is now unrecoverable.
6. `A` calls `object::unburn(A, X)`. Since `X.owner == BURN_ADDRESS` and the stored `TombStone.original_owner == A`, the assertion passes and `transfer_raw_inner(X, A)` executes, transferring `X` back to `A` — bypassing every legitimate owner since step 3 and `C`'s intended permanent burn.

    /// Transfer to the destination address using a LinearTransferRef.
    public fun transfer_with_ref(self: LinearTransferRef, to: address) {
        assert!(!exists<Untransferable>(self.self), error::permission_denied(EOBJECT_NOT_TRANSFERRABLE));

        // Undo soft burn if present as we don't want the original owner to be able to reclaim by calling unburn later.
        if (exists<TombStone>(self.self)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(self.self);
        };

        let object = borrow_global_mut<ObjectCore>(self.self);
        assert!(
            object.owner == self.owner,
            error::permission_denied(ENOT_OBJECT_OWNER),
        );
        event::emit(
            Transfer {
                object: self.self,
                from: object.owner,
                to,
            },
        );
        object.owner = to;
    }

                    from: object_core.owner,
                    to,

    /// This only works for objects directly owned and for simplicity does not apply to indirectly owned objects.
    /// Original owners can reclaim burnt objects any time in the future by calling unburn.
    /// Please use the test only [`object::burn_object_with_transfer`] for testing with previously burned objects.
    public entry fun burn<T: key>(owner: &signer, object: Object<T>) {
        let original_owner = signer::address_of(owner);
        assert!(is_owner(object, original_owner), error::permission_denied(ENOT_OBJECT_OWNER));
        let object_addr = object.inner;
        assert!(!exists<TombStone>(object_addr), EOBJECT_ALREADY_BURNT);
        move_to(&create_signer(object_addr), TombStone { original_owner });

    /// Allow origin owners to reclaim any objects they previous burnt.
    public entry fun unburn<T: key>(
        original_owner: &signer,
        object: Object<T>,
    ) {
        let object_addr = object.inner;
        assert!(exists<TombStone>(object_addr), error::invalid_argument(EOBJECT_NOT_BURNT));

        // The new owner of the object can always unburn it, but if it's the burn address, we go to the old functionality
        let object_core = borrow_global<ObjectCore>(object_addr);
        if (object_core.owner == signer::address_of(original_owner)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object_addr);
        } else if (object_core.owner == BURN_ADDRESS) {
            // The old functionality
            let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
            assert!(
                original_owner_addr == signer::address_of(original_owner),
                error::permission_denied(ENOT_OBJECT_OWNER)
            );
            transfer_raw_inner(object_addr, original_owner_addr);
        } else {
            abort error::permission_denied(ENOT_OBJECT_OWNER);
        };
    }
