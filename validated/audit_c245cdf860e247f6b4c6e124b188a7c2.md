### Title
Bad-debt floor resurrects wiped supplier claims and permanently insolvents the pool - (`contracts/pool/src/interest.rs`)

### Summary

`apply_bad_debt_to_supply_index` caps the loss at total supplied value, computes a wiped-out index of zero, and then clamps it upward to `SUPPLY_INDEX_FLOOR_RAW` without reducing the pool's total scaled supply or every supplier's stored scaled position. [1](#0-0)  Because unrelated suppliers keep their scaled positions, the clamp leaves each claim with a residual value equal to approximately 0.1% of a `RAY`-index position even when the loss consumed all supplier value. [2](#0-1)  The resulting floored supply claim exceeds cash plus outstanding debt, which is the pool's own definition of a backing shortfall. [3](#0-2) 

### Finding Description

An unprivileged caller can reach the vulnerable write-down through `Controller::clean_bad_debt`, which only requires the caller's authorization and then runs the dust-gated cleanup. [4](#0-3)  The cleanup gate accepts an account when `is_socializable_bad_debt(total_debt, total_collateral)` is true and sends every debt position to the pool through `pool_seize_positions_call`. [5](#0-4)  For each borrow-side entry, the pool converts the debt shares to their ceiling-rounded RAY value, applies it to the supply index, and burns the debt shares. [6](#0-5) 

Inside `apply_bad_debt_to_supply_index`, `bad_debt` is capped at `total_supplied_value`; if the debt equals or exceeds that value, `remaining` is zero and `new_supply_index` is zero. [7](#0-6)  The subsequent `.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW))` raises the completely wiped index to `RAY/1000` while `cache.supplied()` remains unchanged. [8](#0-7)  Existing account-level scaled positions therefore still unscale to positive asset claims at the floor even though the socialized loss was supposed to consume the full supplier value. [9](#0-8) 

Deposit-side cleanup does not eliminate the inconsistency: it reclassifies the liquidated account's shares as revenue and leaves total `supplied` unchanged. [10](#0-9)  Other suppliers' positions are not touched at all because cleanup serializes only the insolvent account's own supply and debt entries. [2](#0-1)  Consequently, `backing_shortfall` calculates `supplied_claim - (cash + outstanding_debt)` as positive after a full write-down. [11](#0-10) 

### Impact Explanation

The pool becomes insolvent after a catastrophic bad-debt cleanup: total supply claims remain positive at the index floor while the underlying cash and debt backing are exhausted. [11](#0-10)  Any later recorded pool cash, including recapitalized or otherwise newly credited liquidity, can be withdrawn by holders of these residual scaled positions through the normal withdrawal path. [12](#0-11)  Since withdrawals transfer the resolved pool payout to the receiver, the phantom residual converts into real token claims once cash exists. [13](#0-12) 

This is theft of subsequent pool funds and permanent market insolvency rather than a temporary denial of service. [3](#0-2) 

### Likelihood Explanation

A supplier market can accumulate debt value exceeding total supplied value through interest, particularly when protocol revenue takes part of the accrual. [14](#0-13)  Once the borrower's remaining collateral falls to the socialization threshold, any address may invoke `clean_bad_debt` and trigger the write-down; no administrator, oracle manipulation, leaked key, or special role is needed. [15](#0-14)  The full-loss branch is reached whenever the ceiling-rounded bad debt is at least the current total supplied RAY value. [16](#0-15) [1](#0-0) 

### Recommendation

Do not raise a mathematically wiped supply index without an equivalent write-down or retirement of all outstanding scaled supply claims. [8](#0-7)  If a nonzero denominator is required for later markets, introduce a market generation or reinitialization boundary so positions created before a total wipeout cannot unscale against the restarted index. [1](#0-0)  At minimum, add an invariant test that a `bad_debt >= total_supplied_value` cleanup leaves `backing_shortfall(cache) == 0` rather than merely asserting that the index reached `SUPPLY_INDEX_FLOOR_RAW`. [11](#0-10) 

### Proof of Concept

1. Supplier `B` calls `Controller::supply` and receives scaled shares `S`; with an initial index of `RAY`, `S`'s asset value is `D` units. [17](#0-16) 
2. Borrower `A` obtains debt in the same market and later becomes insolvent with only dust-valued collateral. [18](#0-17) 
3. Any caller invokes `Controller::clean_bad_debt(caller, A_id)`; the dust gate admits the account and cleanup sends its debt position to the pool. [15](#0-14) 
4. The pool computes `bad_debt >= supplied * supply_index`, so `capped == total_supplied_value`, `remaining == 0`, and the calculated index is zero. [7](#0-6) 
5. The floor changes that zero index to `RAY/1000`, while `B`'s unchanged scaled position now floor-unscales to roughly `D / 1000` tokens. [8](#0-7) [9](#0-8) 
6. `backing_shortfall` is positive because the residual supplied claim has no cash or debt backing. [11](#0-10) 
7. When pool cash is later credited, `B` calls the normal `withdraw` path and resolves/transfers the phantom residual amount to its receiver. [12](#0-11)

```rust
pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
```

```rust
pub(crate) fn backing_shortfall(cache: &Cache) -> i128 {
    let supplied_claim = cache.unscale_supply_floor(cache.supplied());
    let outstanding_debt = cache.unscale_borrow_ceil(cache.borrowed());
    let backing = cache.cash().saturating_add(outstanding_debt);
    supplied_claim.saturating_sub(backing).max(0)
```

```rust
/// Admission condition for bad-debt socialization.
#[derive(Clone, Copy, PartialEq)]
enum BadDebtGate {
    /// Permissionless: insolvent *and* collateral at or below the dust threshold.
    DustCapped,
    /// Owner-only: insolvent alone, with no cap on the collateral left behind.
    InsolventOnly,
}

/// Requires open debt and the selected insolvency gate, then cleans up the account.
fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    bad_debt::execute_bad_debt_cleanup(env, &mut cache, account_id, &account, &totals);
```
