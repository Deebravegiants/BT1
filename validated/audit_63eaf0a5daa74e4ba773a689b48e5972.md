No vulnerability found for this question.

**Reasoning:**

The `TokenDeposit` struct in `types/src/account_config/events/token_deposit.rs` is a pure deserialization type used by off-chain consumers (API/indexer) to decode event bytes that the Move VM already emitted during transaction execution [1](#0-0) . It has no role in custody enforcement — it cannot be "crafted" to alter on-chain state because on-chain events are only produced as a side effect of executing the corresponding Move function within a validated transaction, not from arbitrary bytes supplied by an unprivileged party.

The actual emission site is `direct_deposit` in `aptos-move/framework/aptos-token/sources/token.move`, which emits `TokenDeposit { account: account_addr, id: token.id, amount: token.amount }` where `account_addr` is the recipient of the deposit (not necessarily the transaction sender) [2](#0-1) . The `account` field has always recorded the deposit *recipient*, and by protocol design token deposits can be sent to any address (subject to `opt_in_direct_transfer` gating in `direct_deposit_with_opt_in`/`transfer`) — this is normal Move token-standard behavior, not an authorization claim about who *moved* the token or a signature from the resource account's controller [3](#0-2) . The event never encoded "signer-capability verified movement" in the first place, so there is no invariant being broken.

Custody of the actual token asset is enforced entirely by the on-chain `TokenStore` resource and `withdraw_with_event_internal`/`direct_deposit` state transitions, guarded by signer checks and balance assertions in Move bytecode [4](#0-3) . Events are a derivative, informational side-channel computed by the VM after the real state change; an unprivileged party cannot forge event bytes that get accepted as authentic on-chain events without actually executing the underlying authorized Move logic, since events are committed as part of consensus-validated transaction execution, not accepted as free-standing byte blobs. The `event_v2_translator.rs` `TokenDepositTranslator` similarly only processes events that came from genuine `ContractEventV2` records tied to validated transactions, using the real on-chain `TokenStore` resource to determine event sequencing — it does not accept arbitrary attacker-supplied bytes as a trusted event [5](#0-4) .

Since no unprivileged path exists to inject a fabricated `TokenDeposit` event into the authenticated event stream, and the event was never a custody-authorization signal to begin with (only a recipient-tracking log entry), there is no real custody boundary crossed, no balance, owner, or authority is misrepresented in on-chain state, and this does not meet the Custody Impact Gate or Review Path criteria.

    ): Token acquires TokenStore {
        // It does not make sense to withdraw 0 tokens.
        assert!(amount > 0, error::invalid_argument(EWITHDRAW_ZERO));
        // Make sure the account has sufficient tokens to withdraw.
        assert!(balance_of(account_addr, id) >= amount, error::invalid_argument(EINSUFFICIENT_BALANCE));

        assert!(
            exists<TokenStore>(account_addr),
            error::not_found(ETOKEN_STORE_NOT_PUBLISHED),
        );

        event::emit(TokenWithdraw { account: account_addr, id, amount });

        let tokens = &mut TokenStore[account_addr].tokens;
        assert!(
            tokens.contains(id),
            error::not_found(ENO_TOKEN_IN_TOKEN_STORE),
        );
        // balance > amount and amount > 0 indirectly asserted that balance > 0.
        let balance = &mut tokens.borrow_mut(id).amount;
        if (*balance > amount) {
            *balance -= amount;
            Token { id, amount, token_properties: property_map::empty() }
        } else {
            tokens.remove(id)
        }
    }

struct TokenDepositTranslator;
impl EventV2Translator for TokenDepositTranslator {
    fn translate_event_v2_to_v1(
        &self,
        v2: &ContractEventV2,
        engine: &EventV2TranslationEngine,
    ) -> Result<ContractEventV1> {
        let deposit = TokenDeposit::try_from_bytes(v2.event_data())?;
        let struct_tag = StructTag::from_str("0x3::token::TokenStore")?;
        let (key, sequence_number) = if let Some(state_value_bytes) =
            engine.get_state_value_bytes_for_resource(deposit.account(), &struct_tag)?
        {
            let token_store_resource: TokenStoreResource = bcs::from_bytes(&state_value_bytes)?;
            let key = *token_store_resource.deposit_events().key();
            let sequence_number = engine
                .get_next_sequence_number(&key, token_store_resource.deposit_events().count())?;
            (key, sequence_number)
        } else {
            // If the token store resource is not found, we skip the event translation to avoid panic
            // because the creation number cannot be decided.
            return Err(AptosDbError::from(anyhow::format_err!(
                "Token store resource not found"
            )));
        };
