### Title
Sustained borrow-index growth overflows the RAY debt value during accrual and permanently freezes the entire market — (File: contracts/pool/src/interest.rs)

### Summary
The analog of a reachable crash/segfault is an irrecoverable panic in interest accrual. Every pool and controller verb calls `global_sync` before doing anything, and `accrue_step` recomputes the debt value (`borrowed` scaled shares × `borrow_index`) on each compound chunk. When `debt_value` exceeds the `i128` RAY-domain ceiling (~`i128::MAX`), the fixed-point multiply panics with `GenericError::MathOverflow`. Because accrual runs first in `supply`, `borrow`, `withdraw`, `repay`, `liquidate`, `flash_loan`, `update_indexes`, `recapitalize`, and `clean_bad_debt`, the panic bricks the market for every caller — a permanent freeze, not a per-call rejection. The `MAX_BORROW_INDEX_RAY` cap does not save it: the value overflow triggers before the index reaches the cap, so the panic recurs on every subsequent call with no recovery path.

### Finding Description
`global_sync` loops over elapsed time in `MAX_COMPOUND_DELTA_MS` chunks and invokes `accrue_chunk` → `accrue_step(env, params, cache.borrowed(), cache.supplied(), cache.borrow_index(), cache.supply_index(), delta_ms)` [1](#0-0) . Inside `accrue_step` (common/src/rates), the accrued debt value is computed by scaling `borrowed` by the new `borrow_index` (`scaled_to_original`), which goes through `Ray::mul`/`mul_ceil` in `common/src/math/fp.rs` and panics with `MathOverflow` when the product no longer fits `i128` [2](#0-1) . The borrow index is monotone and capped at `10^36` raw RAY, but the docs themselves note that "debt-value overflow can still revert accrual before that ceiling is reached" [3](#0-2) . The integration test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` demonstrates the end state: with a ~1e9-whole-token (18-decimal) market at ~98% utilization on the steep XLM rate curve, `update_indexes`, `withdraw`, and `repay` all revert with `MATH_OVERFLOW`, with `borrow_index < MAX_BORROW_INDEX_RAY` — i.e., the panic is sticky and unrecoverable [4](#0-3) . Since `last_timestamp`/`borrowed`/`borrow_index` are never rewritten to a safe state by any unprivileged path, no call can unstick the market.

### Impact Explanation
Permanent freezing of funds and protocol insolvency for that market: all supplier deposits in the affected book are locked (withdraw accrues first and panics), borrowers can neither repay nor be liquidated (liquidate also accrues first), bad debt cannot be cleaned or recapitalized, and flash loans/positions over the market are dead. The book keeps accounting debt that can never be settled, freezing both user principal and unclaimed yield.

### Likelihood Explanation
The trigger requires an unprivileged attacker (or ordinary usage) to build a very large borrow position — the test uses ~1 billion whole units of an 18-decimal token borrowed at ~98% utilization against supplied collateral — and then let a steep utilization curve compound the debt value past the `i128` RAY ceiling. No privileged call is needed: `supply`, `borrow`, and the passage of ledger time suffice, and caps can be lifted only via governance but are not required where caps are already high or the market is simply large. The precondition is extreme (whale-scale market at sustained max utilization for an extended period), which lowers likelihood, but once reached the freeze is unconditional and irreversible, and it also DoSes liquidations of every position in the market. Severity: High impact, low-to-moderate likelihood → Medium/High.

### Recommendation
Compute the accrued debt value in a wider type or check it explicitly: e.g., perform `borrowed × borrow_index` via `I256`/`try_mul_div` and clamp the index growth (stop accrual, freeze the index at `MAX_BORROW_INDEX_RAY` or at the largest index whose debt value still fits `i128`) instead of panicking. Alternatively, enforce per-market `supply_cap`/`borrow_cap` bounds in units that keep `borrowed_scaled × MAX_BORROW_INDEX_RAY` provably inside `i128` at market-creation time, so the overflow state is unreachable rather than merely unwinding cleanly.

### Proof of Concept
Proven by the in-repo harness test at `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:320-361`: seed `BIG18` (18 decimals, XLM curve) with ~1e9 whole tokens supplied, borrow ~98% of it, advance ledger time year by year; `try_update_indexes_for(["BIG18"])` eventually returns `MATH_OVERFLOW` while `borrow_index < MAX_BORROW_INDEX_RAY`, and subsequent `try_withdraw_raw` and `try_repay` calls also revert with `MATH_OVERFLOW`, confirming the market is permanently bricked.

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
}
