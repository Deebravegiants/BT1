### Title
Stale delegate authorization reactivates after position NFT round-trip - (File: contracts/controller/src/storage/account.rs)

### Summary
Account delegate grants are keyed only by the original granting owner and are not invalidated permanently when the position NFT is transferred. If the NFT returns to the original owner before an intervening owner overwrites or purges the grant, the previous delegate regains full owner-like control of the account and can withdraw collateral or borrow to an arbitrary recipient.

### Finding Description
`get_delegates` retrieves one stored `DelegateGrant` per account and authorizes it whenever `grant.granted_by` equals the current NFT owner; transfer does not clear the underlying `ControllerKey::Delegates` entry. [1](#0-0)  `is_owner_or_delegate` accepts any address in that returned list if it is still an active position manager. [2](#0-1)  The stale grant is deleted only if a later owner calls `remove_delegate`, or overwritten if the later owner calls `add_delegate`. [3](#0-2)  The project documentation confirms that a grant becomes inactive on transfer “and can revive if the NFT returns before an intervening owner updates delegates.” [4](#0-3) 

### Impact Explanation
Once reactivated, the delegate can call `borrow` with `to` set to itself or another external recipient, extracting the maximum borrow value and leaving debt on the victim account. [5](#0-4)  For unencumbered collateral, it can instead call `withdraw` with `to` set to itself; the payout recipient defaults to the caller or accepts the supplied recipient. [6](#0-5)  This is theft of account funds by an actor whose authority should have ended when ownership changed.

### Likelihood Explanation
The attack requires the position NFT to return to the granting owner before the interim owner performs any delegate-list write, but no privileged action is required: only ordinary `position-nft::transfer` calls followed by a delegate-authorized controller call. Transfers back to a prior owner can occur through sales, refunds, custody workflows, mistaken transfers, marketplace settlement, or arrangements in which the prior owner later reacquires the position. The stale authorization can persist indefinitely because it is stored persistently rather than carrying a transfer epoch.

### Recommendation
Invalidate delegate grants permanently on every ownership change. The controller needs an ownership epoch or transfer counter included in `DelegateGrant`, or the position NFT needs to notify the controller to delete `ControllerKey::Delegates(account_id)` during `transfer` and `transfer_from`. At minimum, require ownership changes to clear `ControllerKey::Delegates` unconditionally rather than relying on an intervening owner to overwrite or remove the stale grant.

### Proof of Concept
1. Alice owns account `A`, backed by position NFT token `A`, and governance has activated manager `M` as a position manager.
2. Alice calls `controller.add_delegate(alice, A, M)`, storing `DelegateGrant { granted_by: alice, delegates: [M] }`.
3. Alice calls `position_nft.transfer(alice, bob, A)`. The grant now reads empty for Bob, but remains in `ControllerKey::Delegates(A)`.
4. Bob does not call `add_delegate` or `remove_delegate`, then calls `position_nft.transfer(bob, alice, A)`.
5. `get_delegates(A, alice)` again returns `[M]` because the stored `granted_by` still equals the current owner Alice.
6. `M` calls `controller.borrow(M, A, [(asset, max_amount)], Some(M))`; `require_owner_or_delegate` accepts `M`, and the pool pays the borrowed assets to `M`.
7. Alternatively, where the account’s solvency gates allow it, `M` calls `controller.withdraw(M, A, [(collateral, amount)], Some(M))` and receives Alice’s collateral.

/// Returns grants stamped by `owner`, or an empty list. Ownership changes
/// invalidate a previous owner's grants without deleting them.
pub(crate) fn get_delegates(env: &Env, account_id: u64, owner: &Address) -> Vec<Address> {
    get_user::<DelegateGrant>(env, &ControllerKey::Delegates(account_id))
        .filter(|grant| grant.granted_by == *owner)
        .map(|grant| grant.delegates)
        .unwrap_or_else(|| Vec::new(env))

/// Adds a delegate, enforcing `MAX_DELEGATES`; returns false for duplicates.
/// Overwrites stale grants with a list stamped by the current owner.
pub(crate) fn add_delegate(
    env: &Env,
    account_id: u64,
    owner: &Address,
    delegate: &Address,
) -> bool {
    let mut delegates = get_delegates(env, account_id, owner);
    if delegates.contains(delegate) {
        return false;
    }
    assert_with_error!(
        env,
        delegates.len() < MAX_DELEGATES,
        GenericError::RegistryCapReached
    );
    delegates.push_back(delegate.clone());
    set_delegates(env, account_id, owner, &delegates);
    true
}

/// Removes a live delegate and reports whether it changed the list.
/// Deletes stale grants but returns false, preventing those grants from
/// reactivating if the NFT returns to their original owner.
pub(crate) fn remove_delegate(
    env: &Env,
    account_id: u64,
    owner: &Address,
    delegate: &Address,
) -> bool {
    let key = ControllerKey::Delegates(account_id);
    let Some(grant) = get_user::<DelegateGrant>(env, &key) else {
        return false;
    };
    if grant.granted_by != *owner {
        env.storage().persistent().remove(&key);
        return false;
    }
    let mut delegates = grant.delegates;
    let Some(index) = delegates.first_index_of(delegate) else {
        return false;
    };
    delegates.remove(index);
    set_delegates(env, account_id, owner, &delegates);
    true
}

/// Accepts the owner or a registered, active manager delegated by that owner.
pub(crate) fn is_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) -> bool {
    if caller == owner {
        return true;
    }
    let active_manager =
        storage::get_position_manager(env, caller).is_some_and(|config| config.is_active);
    active_manager && storage::get_delegates(env, account_id, owner).contains(caller)
}

/// Borrows to `to` or the authorized owner/delegate, then checks solvency.
/// Persists supply alongside debt when the check restamps supply LTVs.
pub(crate) fn process_borrow(
    env: &Env,
    caller: &Address,
    account_id: u64,
    borrows: &Vec<HubPayment>,
    to: Option<Address>,
) {
    validation::require_authorized_caller(env, caller);

    let mut account = storage::get_account(env, account_id);
    require_owner_or_delegate(env, account_id, caller, &account.owner);

    let recipient = to.unwrap_or_else(|| caller.clone());
    let mut cache = Context::new(env);
    require_external_recipient(env, &mut cache, &recipient);
    let aggregated = payments::aggregate_positive_payments(env, borrows);

    validate_position_entry_gates(
        env,
        &account,
        &aggregated,
        &mut cache,
        AccountPositionType::Borrow,
    );
    settle_borrow(env, &mut account, &recipient, &aggregated, &mut cache);
