The `unauthedv2.PATCH("/resume/:runID", prc.Resume)` route is unauthenticated - worth checking if it allows unprivileged state changes.### Title
Unauthenticated Pipeline Run Resume Endpoint Allows Anyone With a Task ID to Inject Task Results - (File: core/web/pipeline_runs_controller.go)

### Summary
The Chainlink node exposes `PATCH /v2/resume/:runID` completely outside of the authenticated route group, allowing any unauthenticated client to resume a suspended pipeline run and inject an arbitrary `value` or `error` into the underlying async task, mirroring the "anyone can call a state-changing function without authorization" bug class described in the external report (there, `burn` was callable by anyone; here, `Resume` is callable by anyone).

### Finding Description
In [1](#0-0) , the `Resume` handler is registered on `unauthedv2` — a route group created with no `auth.Authenticate(...)` middleware, unlike every other pipeline/job endpoint which is mounted on `authv2` and typically further wrapped with `auth.RequiresRunRole`/`RequiresEditRole` (see the authenticated group construction and role-gated routes at [2](#0-1)  and [3](#0-2) ).

The handler itself, `PipelineRunsController.Resume`, parses a task UUID from the URL, decodes a JSON body into a `ResumeRequest` (`value`/`error`), and calls `App.ResumeJobV2` directly — with no session, API token, or external-initiator check performed anywhere in the call path: [4](#0-3) 

This in turn calls `runner.ResumeRun`, which updates the task run result and, if the run was suspended, restarts the pipeline: [5](#0-4) 
and `orm.UpdateTaskRunResult`, which only checks that the run is in `running`/`suspended` state — it performs no check that the caller is authorized to supply that specific task's result: [6](#0-5) 

The only "credential" gating this operation is the task UUID itself, which is treated as a bearer-token-like secret embedded in outgoing bridge/HTTP task requests, but is not validated with any constant-time secret comparison, hashing, or expiry mechanism (contrast with the external-initiator auth flow at [7](#0-6)  and [8](#0-7) , which do use `subtle.ConstantTimeCompare` against a stored hashed secret).

### Impact Explanation
Any unprivileged actor who obtains or brute-forces a pending task's UUID can supply an arbitrary result (or error) for that task, forcing the node to resume the associated pipeline run with attacker-controlled data. Since pipeline runs commonly drive on-chain actions (e.g., OCR-triggered transactions, VRF fulfillment callbacks, bridge task chains), this is directly analogous to the reported "anyone can burn tokens" class — an unprivileged caller invoking a state-mutating, side-effecting operation that was intended to be restricted to a specific caller (the external bridge/adapter that owns that particular task), not the general public. The audit log entry is even explicitly named `audit.UnauthedRunResumed`, acknowledging the lack of authentication in the codebase itself: [9](#0-8) 

### Likelihood Explanation
Exploitation requires knowledge of a valid, currently-suspended task run UUID (128-bit, effectively unguessable if generated securely and never leaked). This is the same mitigating factor that make this a "by design" pattern for async bridge/HTTP adapter callbacks — the UUID functions as an implicit capability token. Because of this, the likelihood of exploitation depends entirely on whether task UUIDs ever leak (e.g., via logs, error messages, or a compromised downstream adapter), similar to how the original Storj report was ultimately marked as intended behavior once the byproduct was understood to be an accepted design trade-off.

### Recommendation
If this endpoint is intended to remain unauthenticated for external bridge/adapter callbacks, treat the task UUID as a true secret: generate it with a CSPRNG (verify current generation does so), never log it, and consider adding a secondary shared-secret/HMAC check tied to the specific bridge to prevent trivial resumption once other paths in the request pipeline are compromised (e.g. via logs, error tracebacks, or SSRF against the node). Alternatively, require that the resuming request also present the originating bridge's outgoing token/secret so that presenting an intercepted task ID alone is insufficient.

### Proof of Concept
1. Create a job with an async bridge/HTTP task that suspends the pipeline run pending an external callback.
2. Observe or leak the generated task run UUID (e.g., from node logs at debug level, from the outgoing bridge request, or from any incidental exposure).
3. Without any authentication headers or session cookie, send:
   ```
   PATCH /v2/resume/<taskUUID>
   Content-Type: application/json

   {"value": "<attacker-controlled data>"}
   ```
4. The node accepts the request, updates the task result, and resumes the pipeline run with attacker-supplied data — no credential beyond the UUID was required.

// Resume finishes a task and resumes the pipeline run.
// Example:
// "PATCH <application>/jobs/:ID/runs/:runID"
func (prc *PipelineRunsController) Resume(c *gin.Context) {
	taskID, err := uuid.Parse(c.Param("runID"))
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	rr := pipeline.ResumeRequest{}
	decoder := json.NewDecoder(c.Request.Body)
	err = errors.Wrap(decoder.Decode(&rr), "failed to unmarshal JSON body")
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	result, err := rr.ToResult()
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	if err := prc.App.ResumeJobV2(c.Request.Context(), taskID, result); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
	c.Status(http.StatusOK)
}

func (r *runner) ResumeRun(ctx context.Context, taskID uuid.UUID, value any, err error) error {
	run, start, err := r.orm.UpdateTaskRunResult(ctx, taskID, Result{
		Value: value,
		Error: err,
	})
	if err != nil {
		return fmt.Errorf("failed to update task run result: %w", err)
	}

	// TODO: Should probably replace this with a listener to update events
	// which allows to pass in a transactionalised database to this function
	if start {
		// start the runner again
		go func() {
			ctx, cancel := r.chStop.NewCtx()
			defer cancel()
			if _, err := r.Run(ctx, &run, false, nil); err != nil {
				r.lggr.Errorw("Resume run failure", "err", err)
			}
			r.lggr.Debug("Resume run success")
		}()
	}
	return nil
}

func (o *orm) UpdateTaskRunResult(ctx context.Context, taskID uuid.UUID, result Result) (run Run, start bool, err error) {
	if result.OutputDB().Valid && result.ErrorDB().Valid {
		panic("run result must specify either output or error, not both")
	}
	err = o.transact(ctx, func(tx *orm) error {
		sql := `
		SELECT pipeline_runs.*, pipeline_specs.dot_dag_source "pipeline_spec.dot_dag_source", job_pipeline_specs.job_id "job_id"
		FROM pipeline_runs
		JOIN pipeline_task_runs ON (pipeline_task_runs.pipeline_run_id = pipeline_runs.id)
		JOIN pipeline_specs ON (pipeline_specs.id = pipeline_runs.pipeline_spec_id)
		JOIN job_pipeline_specs ON (job_pipeline_specs.pipeline_spec_id = pipeline_specs.id)
		WHERE pipeline_task_runs.id = $1 AND pipeline_runs.state in ('running', 'suspended')
		FOR UPDATE`
		if err = tx.ds.GetContext(ctx, &run, sql, taskID); err != nil {
			return fmt.Errorf("failed to find pipeline run for task ID %s: %w", taskID.String(), err)
		}

		// Update the task with result
		sql = `UPDATE pipeline_task_runs SET output = $2, error = $3, finished_at = $4 WHERE id = $1`
		if _, err = tx.ds.ExecContext(ctx, sql, taskID, result.OutputDB(), result.ErrorDB(), time.Now()); err != nil {
			return fmt.Errorf("failed to update pipeline task run: %w", err)
		}

		if run.State == RunStatusSuspended {
			start = true
			run.State = RunStatusRunning

			sql = `UPDATE pipeline_runs SET state = $2 WHERE id = $1`
			if _, err = tx.ds.ExecContext(ctx, sql, run.ID, run.State); err != nil {
				return fmt.Errorf("failed to update pipeline run state: %w", err)
			}
		}

		return loadAssociations(ctx, tx.ds, []*Run{&run})
	})

	return run, start, err
}

// AuthenticateExternalInitiator compares an auth against an initiator and
// returns true if the password hashes match
func AuthenticateExternalInitiator(eia *auth.Token, ea *ExternalInitiator) (bool, error) {
	hashedSecret, err := auth.HashedSecret(eia, ea.Salt)
	if err != nil {
		return false, err
	}
	return subtle.ConstantTimeCompare([]byte(hashedSecret), []byte(ea.HashedSecret)) == 1, nil
}

// AuthenticateExternalInitiator authenticates an external initiator request.
//
// Implements authMethod
func AuthenticateExternalInitiator(c *gin.Context, store Authenticator) error {
	ctx := c.Request.Context()
	eia := &auth.Token{
		AccessKey: c.GetHeader(static.ExternalInitiatorAccessKeyHeader),
		Secret:    c.GetHeader(static.ExternalInitiatorSecretHeader),
	}

	ei, err := store.FindExternalInitiator(ctx, eia)
	if err != nil {
		if errors.Is(err, sql.ErrNoRows) {
			return auth.ErrorAuthFailed
		}

		return errors.Wrap(err, "finding external initiator")
	}

	ok, err := bridges.AuthenticateExternalInitiator(eia, ei)
	if err != nil {
		return err
	}
	if !ok {
		return auth.ErrorAuthFailed
	}

	// External initiator endpoints (wrapped with AuthenticateExternalInitiator) inherently assume the role
	// of 'run' (required to trigger job runs)
	c.Set(SessionExternalInitiatorKey, ei)
	c.Set(SessionUserKey, &clsessions.User{Role: clsessions.UserRoleRun})

	return nil
}
