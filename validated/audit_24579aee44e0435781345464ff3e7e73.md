### Title
Zero oracle price permanently bricks liquidation and bad-debt cleanup for a collapsed asset - (File: contracts/price-aggregator/src/engine.rs)

### Summary
The price aggregator hard-fails on any resolved price `<= 0` (`OracleError::InvalidPrice`), and every account-resolution path in the controller — `liquidate`, permissionless `clean_bad_debt`, and even owner-only `force_socialize_bad_debt` — computes strict priced risk totals through `risk::calculate_account_risk_totals` before any liquidation-specific logic runs. If an asset's price legitimately collapses to zero (the exact scenario of GMX M-20), no position denominated in or collateralized by that asset can ever be liquidated or cleaned up. Unlike the original GMX code, XOXNO has not even a privileged fallback that bypasses pricing, so debt accrues while the account is permanently unresolvable — protocol insolvency.

### Finding Description
The resolution engine rejects non-positive blended prices in `Outcome::failure` before sanity bands are consulted: `if self.price_wad <= 0 { return Some(OracleError::InvalidPrice) }` at `contracts/price-aggregator/src/engine.rs:139-141`, and `force` converts that failure into a panic at `engine.rs:181-184`. The same rejection exists for dual-leg tolerance blending (`midpoint_if_in_band` divides by the smaller leg, so a zero anchor can never blend — `certora/price-aggregator/spec/tolerance_math_rules.rs:36-52`) and for LP-derived prices (`fair_lp_price_wad`/`fair_stable_lp_price_wad` return `InvalidPrice` on `reserve <= 0` or `price_wad <= 0` in `common/src/oracle/lp.rs:63-70` and `common/src/oracle/lp_stable.rs:87-94`).

On the controller side, both resolution paths require priced risk totals:

- `liquidate` → `plan::build_liquidation_plan` → strict `Context`-cached prices (`contracts/controller/src/positions/liquidation/mod.rs:58`), so the call panics with `InvalidPrice`/`NoLastPrice` before the health-factor check. The harness test `test_oracle_rejects_zero_price_before_liquidation_check` proves `liquidate` errors with `NO_LAST_PRICE` when the collateral asset's feed reports `0` (`tests/test-harness/tests/controller/liquidation_coverage.rs:67-85`).
- `socialize_bad_debt` calls `risk::calculate_account_risk_totals` and only then checks the insolvency gate (`contracts/controller/src/positions/liquidation/mod.rs:212-237`), so `clean_bad_debt` panics on the same price read before reaching `CannotCleanBadDebt`.
- The privileged escape hatch does not help: `process_force_socialize_bad_debt` → `socialize_bad_debt` → the same `calculate_account_risk_totals` (`mod.rs:246-249`). The operations runbook documents this: "Missing or invalid required prices prevent cleanup; listing flags and global pause do not waive pricing" (`docs/reference/runbooks/force-socialize-bad-debt.md:34-35`).

Because risk totals are computed across *all* of an account's positions, one zero-priced leg poisons every resolution path for that account, and the price will never "recover" — zero is the correct terminal value of a dead asset, not staleness.

### Impact Explanation
Protocol insolvency via permanent freezing of resolution. The moment a listed asset's price reaches zero, every account holding it (as collateral or debt) can be neither liquidated nor socialized — permissionlessly or by governance. Debt keeps accruing via borrow-index accrual while collateral value is unaccountable, and the pool's suppliers absorb the loss with no mechanism to close it out. This matches the accepted Medium severity of the source report: an unlikely but viable market scenario that permanently breaks the liquidation invariant rather than a recoverable fail-closed pause.

### Likelihood Explanation
Low but non-zero, identical to the source report's reasoning: real assets do go to zero (delisted/dead tokens, collapsed stablecoins, drained LP underlyings). The trigger requires only that an oracle source honestly reports zero — no attacker action, no misconfiguration, no dishonesty within sanity bands (zero is rejected before and independently of the bands). `supply` accepts legs whose feeds are already failing (`audit_supply_stale_shield` plants a position with a stale feed successfully, `tests/test-harness/tests/controller/audit_supply_stale_shield.rs:26-34`), so accounts can hold exposure to an asset at the moment its feed dies.

### Recommendation
Introduce a resolution path that tolerates a terminal zero price for a defaulted market — e.g., treat `InvalidPrice` on a position's market as collateral value zero for risk-total purposes so liquidation/cleanup can proceed to seize remaining positive-priced collateral and socialize the debt, or add a governance- or permissionless market-settlement path that resolves accounts using only the subset of still-priceable assets. At minimum, `force_socialize_bad_debt` should be able to waive pricing for the defaulted market so insolvent accounts remain closable.
