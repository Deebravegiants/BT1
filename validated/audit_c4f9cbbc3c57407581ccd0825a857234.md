## Title
Emporium `runAction` allows arbitrary, unauthenticated calls when `signerAddress == address(0)` and `tokenNumber == 0` (`MainEVMCircuitMin` provides no real proof-of-ownership) - (`contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol`, `circuits/MainEVMCircuitMin.circom`)

### Summary
`EmporiumUpgradeable.runAction` authorizes arbitrary external calls (`op.endpoint.call{value: op.value}(op.callData)`) either via an ECDSA signature from `stack.signerAddress`, or — when `stack.signerAddress == address(0)` — solely via the accompanying zk-SNARK proof. When `circomData.erc20TokenAddresses.length == 0`, `Hinkal.transact()` selects the reduced `MainEVMCircuitMin` circuit, whose only constraint is `message <== Poseidon(1)([messageSeed])`, with `messageSeed` a free private witness chosen by the prover. Because `formInputEmporiumMin` feeds `circomData.emporiumMessage` as the expected public output, any caller can pick an arbitrary `messageSeed` and set `emporiumMessage = Poseidon(messageSeed)` themselves — no nullifier, no root hash, no signature, and no proof of ownership of any UTXO or private key is required. This lets any unprivileged EOA drive `runAction` with attacker-chosen `ops`, executing calls funded by the Emporium contract's own balance, without any of the intended authorization (signer signature) or authenticated proof (spend proof) mechanisms.

### Finding Description
`Hinkal.transact()` selects the proof-verification input set based on the action and token count: [1](#0-0) 

When `externalActionId == HINKAL_EMPORIUM_ACTION_ID` and `erc20TokenAddresses.length == 0`, only three public values are checked against the proof: `emporiumMessage`, `timeStamp`, `calldataHash`: [2](#0-1) 

The circuit compiled for this path, `MainEVMCircuitMin`, has no constraint tying `message`/`messageSeed` to any nullifier, merkle root, or signature — `messageSeed` is a free private witness: [3](#0-2) 

Meanwhile, `EmporiumUpgradeable.verifyWallet` only performs an ECDSA check when `stack.signerAddress != address(0)`; if it is the zero address, it merely marks the anti-replay `emporiumMessage` as used and returns — no other check is performed: [4](#0-3) 

`runAction` then executes each op unconditionally once `verifyWallet` returns, including the "Stateless Interaction" branch that performs a raw external call using attacker-controlled `endpoint`, `value`, and `callData` (only the `callHinkalWallet`/`doSendToRelay` selectors on that direct path are blocked): [5](#0-4) 

Because the `MainEVMCircuitMin` proof does not encode ownership of any commitment, spending key, or on-chain root (`rootHashHinkal` is not part of `formInputEmporiumMin`'s inputs, and no `inputNullifiers` exist since `dimensionsCheck` binds their length to `tokenNumber == 0`), any unprivileged party can generate a trivially valid proof (choose `messageSeed`, compute `emporiumMessage = Poseidon(messageSeed)`, satisfy `calldataHash` by constructing matching `circomData`). Combined with `signerAddress == address(0)` skipping the signature check entirely, the "authorised by signer or prover" equality that the protocol relies on is broken: `runAction` executes attacker-chosen calls with no real authorization at all.

The impact is bounded by whatever balance the `Emporium` (`ExternalActionBaseUpgradeable`) contract itself holds — e.g., ETH/ERC20 sent along in prior ops, relay fees paid to it (`payRelay`/`sendToRelay`), or ERC20 approvals it has previously granted — since `op.value`/`op.callData` execute in the context of that contract and can direct its held funds or approvals to any attacker-controlled `endpoint`.

### Impact Explanation
This is a proof/authorization bypass: unauthorized execution of arbitrary calls (potential theft of protocol/relay fee balances held by the Emporium contract, or manipulation of any approvals/state it holds) without a wallet owner's signature or a valid proof of shielded-fund ownership. This matches the "High/Critical - proof or nullifier verification bypass; executing calls or moving assets a wallet owner or prover never authorised" impact category.

### Likelihood Explanation
Reachable by any unprivileged EOA: `transact()` has no access restriction beyond `relayerIsValid` (which only applies when `circomData.relay != address(0)`; an attacker can self-relay with `relay == address(0)` and `originalSender == msg.sender`). Constructing a satisfying `MainEVMCircuitMin` proof requires no secret information — only choosing a `messageSeed` and computing its Poseidon hash — which is trivial for anyone with the public circuit artifacts.

### Recommendation
Do not allow the zero-signature ("no wallet") path to skip authentication for the `MainEVMCircuitMin`/`tokenNumber == 0` case unless the circuit truly binds `message`/`emporiumMessage` to a verified UTXO ownership proof (nullifier + root) as the full circuit does. Either require `stack.signerAddress != address(0)` whenever `erc20TokenAddresses.length == 0`, or extend `MainEVMCircuitMin` to include meaningful ownership constraints (e.g., a real signature/nullifier check) before `runAction` is allowed to execute arbitrary external calls.

### Proof of Concept
1. Attacker calls `Hinkal.transact()` with `dimensions.tokenNumber == 0`, `circomData.erc20TokenAddresses == []`, `circomData.externalActionData.externalActionId == HINKAL_EMPORIUM_ACTION_ID`, `circomData.relay == address(0)`, `circomData.originalSender == attacker`.
2. Attacker picks any `messageSeed`, computes `emporiumMessage = Poseidon(1)([messageSeed])`, and generates a valid Groth16 proof for `MainEVMCircuitMin` (no secret knowledge required) satisfying `calldataHash` over their chosen `circomData`.
3. `circomData.externalActionData.externalActionMetadata` encodes an `EmporiumStack` with `signerAddress = address(0)` and `ops = [{endpoint: attacker, invokeWallet: false, value: <emporium balance>, callData: ""}]`.
4. `Hinkal.transact()` verifies the (trivially satisfiable) proof and root, then calls `_externalTransact` → `Emporium.runAction`.
5. `verifyWallet` returns immediately (no signature check since `signerAddress == address(0)`).
6. The stateless branch executes `op.endpoint.call{value: op.value}(op.callData)`, sending the Emporium contract's held ETH/ERC20 balance to the attacker with no ownership proof or signer authorization ever validated.
