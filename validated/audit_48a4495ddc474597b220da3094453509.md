## Title
Unrestricted `CallDispatcher.dispatch()` allows any unprivileged caller to drain funds left in the shared dispatcher - (`evm/src/utils/CallDispatcher.sol`)

### Summary
`CallDispatcher.dispatch()` is a bare `external` function with no caller restriction whatsoever. It decodes a caller-supplied `bytes` blob into a `Call[]` array and blindly executes each call `to.call{value: call.value}(call.data)` from the dispatcher's own balance/context. The dispatcher is a single, shared, permissionless singleton reused by `IntentGatewayV2` (predispatch/postdispatch execution) and the `HyperFungibleToken`/`WrappedHyperFungibleToken` apps (calldata-on-receive). Exactly like the `RevenueManagement`/`DexSwapStrategy` bug referenced in the report — where a downstream primitive trusts only the attacker-influenceable `bytes` payload and ignores whether it corresponds to the declared inputs — `CallDispatcher.dispatch()` trusts its `bytes` argument unconditionally and is reachable by literally anyone, not just the apps that are supposed to own it.

### Finding Description
`CallDispatcher.dispatch(bytes memory encoded)` has no `onlyOwner`/`onlyGateway`/`onlyHost` modifier: [1](#0-0) 

It accepts a `receive()` for plain ETH transfers and executes arbitrary `Call{to, value, data}` entries against any contract with code, using whatever native/token balance currently sits on the dispatcher: [2](#0-1) [3](#0-2) 

`IntentGatewayV2.placeOrder`'s predispatch flow deliberately routes user funds through this same shared dispatcher: assets are pushed to `dispatcher` first, then `order.predispatch.call` (attacker/user-supplied bytes) is executed on it, and finally only the tokens explicitly listed in `order.inputs` are swept back to the gateway: [4](#0-3) 

The sweep loop only iterates `order.inputs` — any other asset produced by the predispatch call (e.g., unused native ETH refunded by a DEX router back to the dispatcher, or a different token than the declared input) is never swept and is left sitting on the dispatcher's balance. The identical pattern exists for postdispatch execution in `IntentsBase._execute`, where the sweep is scoped only to `order.output.assets`: [5](#0-4) 

Because `CallDispatcher.dispatch()` is globally callable, any residual balance left on the dispatcher — from an imperfect sweep, a slippage refund, an unswept dust token, or any other flow that momentarily deposits value into this shared contract — can be swept out by an unrelated, unprivileged third party simply by calling `dispatch()` directly with a `Call[]` that transfers the balance to themselves. This is architecturally the same root cause as the reported bug: an execution primitive (`DexSwapStrategy`/here, `CallDispatcher`) is driven purely by attacker-suppliable `bytes`, decoupled from any binding to the legitimate caller or the declared inputs/outputs of the calling flow, and the surrounding access control (whitelist in the report; none at all here) does not constrain what the primitive itself can be tricked into doing.

### Impact Explanation
Any value that ends up on the shared `CallDispatcher` — whether from `HyperFungibleToken`/`WrappedHyperFungibleToken` cross-chain calldata execution, or from `IntentGatewayV2` predispatch/postdispatch swap flows — is at risk of outright theft by any unprivileged address, since `dispatch()` places no restriction on who may invoke it or what it does with the dispatcher's current balance. This is a direct path to concrete theft of funds for any party (relayer, intent solver, or ordinary user) whose transaction leaves value transiently or permanently on the dispatcher.

### Likelihood Explanation
The dispatcher is a shared, cross-app singleton per chain, so the attack surface is broad: any predispatch/postdispatch swap route with slippage, a refund path, or an asset not enumerated in `order.inputs`/`order.output.assets` creates exploitable residual balance. No privileged role, timing race, or governance action is required — an attacker only needs to observe a nonzero balance on the publicly known `CallDispatcher` address and submit a single `dispatch()` call.

### Recommendation
Restrict `CallDispatcher.dispatch()` to authorized callers (e.g., an `onlyAuthorized` allowlist of the gateway/HFT contracts that are meant to drive it), and/or make the dispatcher single-use/ephemeral per flow (e.g., deploy a fresh minimal-proxy dispatcher instance per order/message so no cross-flow balance can accumulate). Additionally, ensure sweep logic in `IntentGatewayV2`/`IntentsBase` accounts for *all* assets that could plausibly land on the dispatcher (not just the declared `inputs`/`output.assets`), and revoke any approvals granted to external routers during predispatch/postdispatch execution.

### Proof of Concept
1. A user calls `IntentGatewayV2.placeOrder` with a `predispatch.call` that swaps native ETH for `DAI` via UniswapV2 (as in `IntentGatewayV2Test.testDustCollectionFromPredispatchSwapWithUniswapV2`), sending slightly more ETH than the swap consumes; the router refunds the unused ETH to `msg.sender`, which is the `CallDispatcher`.
2. `placeOrder`'s sweep loop only sweeps the `DAI` amount declared in `order.inputs`; the leftover native ETH remains on the `CallDispatcher` contract's balance after the transaction completes.
3. Any unrelated address calls `CallDispatcher.dispatch(abi.encode([Call({to: attacker, value: strayETH, data: ""})]))` directly — there is no access check — and drains the stray ETH to themselves. [1](#0-0) [6](#0-5)

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
