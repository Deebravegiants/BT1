Audit Report

## Title
Log injection via unescaped user-controlled email in LDAP login logging - (File: core/sessions/ldapauth/ldap.go)

## Summary
The unauthenticated `POST /sessions` endpoint accepts an attacker-controlled `email` field that is passed unmodified into `ldapAuthenticator.CreateSession`, which writes it directly into a `%s`-formatted log message without stripping `\r`/`\n` or other control characters. This allows an unauthenticated caller to inject forged/spoofed log lines into the node's application log stream, unlike the equivalent OIDC code path which explicitly sanitizes the same value before logging.

## Finding Description
`SessionsController.Create` binds the JSON request body into `clsessions.SessionRequest{Email, Password}` and forwards it unmodified to `AuthenticationProvider().CreateSession(ctx, sr)` [1](#0-0) , reachable via the unauthenticated `/sessions` route [2](#0-1) .

When LDAP auth is configured, `ldapAuthenticator.CreateSession` uses `sr.Email` raw (not the LDAP-filter-escaped `escapedEmail`) in a format-string log call on the success path: [3](#0-2) 
and `escapedEmail` (which is only LDAP-filter escaping via `ldap.EscapeFilter`, not log/control-character escaping) is used similarly on error paths [4](#0-3) .

By contrast, the sibling `oidcAuthenticator.CreateSession` explicitly strips `\n`/`\r` from `sr.Email` before logging the analogous message: [5](#0-4) . No equivalent sanitization exists in the LDAP path, confirming the asymmetry described in the claim.

## Impact Explanation
An unauthenticated attacker can inject `\r\n`-delimited or control-character content into the node's structured/text log stream by submitting a crafted `email` in a login attempt against an LDAP-configured node. This enables forging fake log entries (e.g., spoofed "Successful LDAP login" lines for other users) or corrupting downstream log parsers/SIEM ingestion pipelines. This maps to a persistent plain-text injection into application logs — a real but log-integrity/observability-only impact (no credential/session bypass, no data exfiltration), consistent with a low/medium severity classification. SECURITY.md explicitly does not exclude persistent plain-text injection, only reflected plain-text injection, so this is in-scope as reported (albeit low impact).

## Likelihood Explanation
The trigger is trivially reachable by any unauthenticated client sending a single crafted `POST /sessions` request; it requires no credentials, no privileged role, and no special network position — only that the target node has `[WebServer.LDAP]` configured (an optional deployment mode). The unauthenticated endpoint is rate-limited but not otherwise gated, so the log injection is easily repeatable within rate limits.

## Recommendation
Sanitize `sr.Email` (strip/escape `\r`, `\n`, and other control characters) before it is used in any `Infof`/`Errorf` string-interpolated log message in `core/sessions/ldapauth/ldap.go`, mirroring the `strings.ReplaceAll` sanitization already present in `core/sessions/oidcauth/oidc.go`. Prefer structured logging (`lggr.Infow("...", "user", sr.Email, "role", foundUser.Role)`) so the zap encoder handles safe escaping instead of relying on manual sanitization at each call site.

## Proof of Concept
1. Configure a Chainlink node with LDAP authentication enabled (`[WebServer.LDAP]`).
2. Send: `POST /sessions` with body `{"email":"attacker@example.com\r\n2024-01-01T00:00:00Z\tINFO\tSuccessful LDAP login request for user admin@example.com - admin","password":"x"}`.
3. Observe the log line at `core/sessions/ldapauth/ldap.go:435` (`l.lggr.Infof("Successful LDAP login request for user %s - %s", sr.Email, foundUser.Role)`) writes the injected `\r\n`-delimited content verbatim into the log stream, producing a forged log entry, whereas the equivalent OIDC path at `core/sessions/oidcauth/oidc.go:418-420` strips these characters first.

func (oi *oidcAuthenticator) CreateSession(ctx context.Context, sr clsessions.SessionRequest) (string, error) {
	foundUser, err := oi.localLoginFallback(ctx, sr)
	if err != nil {
		return "", err
	}

	sanitizedEmail := strings.ReplaceAll(sr.Email, "\n", "")
	sanitizedEmail = strings.ReplaceAll(sanitizedEmail, "\r", "")
	oi.lggr.Infof("Successful local admin login request for user %s - %s", sanitizedEmail, foundUser.Role)
