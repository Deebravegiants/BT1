### Title
`placeOrder()` escrows funds for a `destination` chain with no validation that a peer `IntentGatewayV2` deployment exists there, permanently freezing funds for cross-chain fills that can never be delivered - ([File: evm/src/apps/IntentGatewayV2.sol])

### Summary
This is analogous to the TRST-M-6 bug class: a function accepts a user-supplied routing target (there, a gauge pool; here, a destination state-machine id) and commits value against it without checking that the target has a valid, registered counterpart. In `_vote()` the missing check was `isGauge[pool]`; in `IntentGatewayV2.placeOrder()` the missing check is that `order.destination` has a registered peer gateway in `_instances` (the same mapping `_instance()`/`instance()` enforces everywhere else in the contract).

### Finding Description
`placeOrder()` [1](#0-0)  escrows the user's input tokens and stamps `order.destination` with whatever the caller supplies, with no check that a peer `IntentGatewayV2` instance is registered for that destination via `_instances`/`_instance()`. Every other cross-chain code path in the same contracts *does* check this mapping: `instance()`/`_instance()` reverts with `UnknownInstance` for an unregistered chain [2](#0-1) , and `_post()`/`_fillCrossChain()` rely on `_instance(order.source)` to route the redeem message back [3](#0-2) . `placeOrder()` is the one entry point that skips this validation for `order.destination`.

Because of this gap, a user (or a filler front-end bug, or simply user error) can place a cross-chain order whose `destination` is a chain string with no counterpart gateway registered anywhere. `fillOrder()` only checks that `orderDest == currentChain` for routing purposes [4](#0-3)  — it never checks that the destination gateway is a known peer of the source gateway. If no solver operates/deploys a valid `IntentGatewayV2` for that "destination" (because it was never registered as a peer at all, or the mapping only exists asymmetrically on one side), the order can never be filled cross-chain, since a solver attempting to fill would need the destination-side contract to exist and recognize the source as a peer to dispatch `RedeemEscrow` back through `_instance(order.source)`.

### Impact Explanation
Escrowed input tokens are then only recoverable via `cancelOrder()`. The cross-chain cancel path (`_cancelFromSource`) requires dispatching a Hyperbridge GET request to the destination chain to verify the order was not filled there, which in turn depends on Hyperbridge having a valid connected state machine for that destination — the same guarantee that was never validated at `placeOrder()` time. If the destination string does not correspond to any Hyperbridge-connected/supported state machine, the GET dispatch and/or its response delivery has no route, and the user's escrowed funds are permanently frozen with no code path to reclaim them. This matches the "permanent freezing of funds" impact bar for a Medium/High finding — funds enter escrow against a target that was never confirmed to be reachable, exactly mirroring TRST-M-6's "emissions redirected to a pool with no gauge is lost."

### Likelihood Explanation
Reachable directly from a single unprivileged `placeOrder()` transaction — no special privileges, governance, or admin action required. Likelihood of hitting it depends on whether a legitimate SDK/frontend always supplies a validated destination (the docs note this is enforced client-side by `EvmChain.create()` rejecting unsupported chains) [5](#0-4) , but the on-chain contract itself provides no such guarantee, so any direct contract caller, a compromised/buggy frontend, or a user who copies an order template with a stale/wrong destination bytes string can trigger the freeze.

### Recommendation
In `placeOrder()`, before escrowing tokens, validate that `order.destination` is a known peer by calling `_instance(order.destination)` (reverting with the existing `UnknownInstance` error) — mirroring the recommended `isGauge[_gauge]` check pattern from the reference report. For same-chain orders where `order.destination == order.source == host()`, this check can be skipped/short-circuited since no cross-chain routing is required.

### Proof of Concept
1. Call `placeOrder()` on the source-chain `IntentGatewayV2` with `order.destination` set to an arbitrary/unregistered state-machine id string (e.g., a chain that has never been added via `NewDeployment`/`_addDeployment` and is not a Hyperbridge-connected state machine).
2. `placeOrder()` succeeds: tokens are transferred into escrow, `_orders[commitment][token]` is credited, and `OrderPlaced` is emitted — none of this checks `_instances[keccak256(order.destination)]`.
3. No solver can ever complete `_fillCrossChain` for this order in a way that lets the destination gateway dispatch `RedeemEscrow` back, because either no gateway exists at that destination or, symmetrically, that destination gateway does not list the source chain as a peer.
4. `cancelOrder()`'s cross-chain path depends on a Hyperbridge GET round trip to the same unregistered/unreachable destination and therefore cannot complete either.
5. The escrowed input tokens are permanently stuck in the `IntentGatewayV2` contract on the source chain.

    function fillOrder(Order calldata order, FillOptions calldata options) public payable nonReentrant {
        uint256 blockNumber = _blockNumber();
        if (order.deadline < blockNumber) revert Expired();
        // The solver's own bound on how long its quoted price stands. Zero means unbounded,
        // which is the right default for a solver filling directly — it is only at risk from
        // its own staleness. It matters for a bid signed through the coprocessor, where the
        // order placer chooses the moment of execution and nothing else caps the wait.

    /**
     * @dev Resolves the IntentGateway instance address for a given state machine.
     * Reverts with `UnknownInstance` if no remote deployment has been registered for that chain.
     * @param stateMachineId The raw state machine identifier bytes.
     * @return The gateway address for the given state machine.
     */
    function _instance(bytes calldata stateMachineId) internal view returns (address) {
        address gateway = _instances[keccak256(stateMachineId)];
        if (gateway == address(0)) revert UnknownInstance();
        return gateway;
    }

## Before you begin

You need:

- An RPC URL for the source chain, and one for the destination chain if this is cross-chain.
