## Title
Users can permanently lose access to sub-floor token remainders because `Zap.sell` enforces BounceTech's live `minTransactionSize` floor on the *redeemed* amount, with no path to bypass `Zap` - (File: `packages/contracts/src/Zap.sol`)

### Summary
`Zap._sellInternal` rejects any sell whose LT-redemption value falls below `minUsdcAmount()` (BounceTech's live `minTransactionSize()` floor, read via `Bonding.bounceGlobalStorage()`). Because `Bonding.buy`/`Bonding.sell` are gated `onlyRouter` and only an allowlisted `Zap` can call them, an unprivileged holder has no alternate path to exit a curve position. A trader who buys tokens and then partially sells can be left holding a residual token balance whose current redemption value sits below the floor, permanently un-sellable through the only permissionless exit route, unless they buy more tokens first to push the position's value back above the floor and pay fees again on the added spend.

### Finding Description
`Zap._sellInternal` computes the gross USDC-equivalent of the LT the curve sell yields and reverts if it is below the floor: [1](#0-0) 

`minUsdcAmount()` mirrors BounceTech's `GlobalStorage.minTransactionSize()` live: [2](#0-1) 

There is no unprivileged bypass: `Bonding.buy`/`Bonding.sell` (the only entry points into the curve `Router`) are gated `onlyRouter`, and only allowlisted `Zap` contracts can call them: [3](#0-2) [4](#0-3) 

The floor is not fixed - it tracks BounceTech's admin-settable `minTransactionSize()` and can be raised at any time, as demonstrated by the test suite raising it to `50e6` / `75e6`: [5](#0-4) 

The buy side has the analogous floor on the post-fee mint amount: [6](#0-5) 

Consequently, a holder whose token balance's current redemption value is below `minUsdcAmount()` (whether because they partially sold down to a small remainder, or because the floor was subsequently raised above their remaining position's value) cannot sell any of it through `Zap.sell` - the only permissionless sell path in the protocol - and is stuck. The one available escape is to buy additional tokens to lift the position's value above the (possibly raised) floor and then sell the combined balance, which is exactly the same "deposit more, then withdraw all, paying extra fees" workaround called out and disputed in the referenced report, only here it is enforced by an external dependency (BounceTech) rather than an internal policy choice, making the frozen amount unbounded from alt.fun's own perspective if BounceTech raises its floor.

### Impact Explanation
This is an availability/fund-freezing issue for ordinary traders: a residual token balance can become permanently unredeemable via the only sanctioned exit (`Zap.sell`) whenever its live redemption value drops below `minUsdcAmount()`. Because the floor is sourced live from BounceTech's `GlobalStorage.minTransactionSize()` and is entirely outside alt.fun's control, the frozen amount is not bounded by alt.fun's own default ($10) - a BounceTech floor raise (the contracts and tests explicitly anticipate raises to `50e6`/`75e6`) can strand a much larger slice of a user's position with no on-chain recourse other than paying additional buy+sell fees to top up and exit in bulk.

### Likelihood Explanation
This requires no privileged action and is trivially reachable by any trader who partially sells a curve position down near the floor, or who holds a position that a subsequent BounceTech floor raise pushes below the new minimum. Both are ordinary, unprivileged usage patterns, and the second is entirely outside alt.fun's control.

### Recommendation
Allow `Zap.sell` to fully liquidate a holder's entire remaining token balance for a given token even when the resulting redemption value falls below `minUsdcAmount()`, e.g. by special-casing "sell full balance" to skip the floor check (mirroring the accepted mitigation direction in the referenced report), or by batching/aggregating dust redemptions so the floor is checked against a user's total exposure rather than a single call's output.

### Proof of Concept
1. Trader buys tokens via `Zap.buy` for an amount just above `minSeedUsdc()`/`minUsdcAmount()`.
2. Trader sells most of the position via `Zap.sell`, leaving a token balance whose live LT-redemption value is now below `minUsdcAmount()`.
3. Trader calls `Zap.sell` again for the remaining balance; `_sellInternal`'s `grossUsdcEstimate / 1e12 < minUsdcAmount()` check reverts with `BelowMinAmount` (see `packages/contracts/test/Zap.t.sol` `test_sell_revertsBelowMinAmount` / `test_sell_belowMinAmount_normalisesDecimalScale` for the exact revert path exercised with a crashed/small position).
4. Because `Bonding.sell` is `onlyRouter`-gated, the trader cannot call the curve directly to force an exit; the only recovery is to buy additional tokens through `Zap.buy` (paying the buy fee again) to push the combined position back above the floor, then sell the whole thing (paying the sell fee again) - matching the exact "deposit more, withdraw all, pay extra fees" pattern from the referenced report, except the floor here can also be silently raised by BounceTech at any time (`bounceGlobalStorage.setMinTransactionSize(...)`), stranding previously-sellable positions retroactively.

    /// @notice Buy tokens on the curve. Router-only.
    /// @param trader        Attributed in the emitted `Trade` event. Trusted
    ///                      because only allowlisted routers can reach here.
    /// @return tokensOut    Tokens delivered to the calling router.
    /// @return amountInUsed LT actually consumed (≤ amountIn).
    function buy(
        uint256 amountIn,
        address tokenAddress,
        uint256 amountOutMin,
        address trader
    ) external onlyRouter nonReentrant returns (uint256 tokensOut, uint256 amountInUsed) {
        TokenInfo storage info = _s().tokenInfo[tokenAddress];
        // `creator == 0` means the slot was never written. `Lifecycle.Curve` is
        // the zero value, so without this an unknown token would fall through
        // and revert deep in `router.buy` with an opaque error.
        if (info.creator == address(0)) revert TokenNotTrading();
        if (info.lifecycle == Lifecycle.Graduating) revert TokenIsGraduating();
        if (info.lifecycle != Lifecycle.Curve) revert TokenNotTrading();
        _enforceLaunchDelay(tokenAddress);

        (tokensOut, amountInUsed) = _executeBuy(msg.sender, trader, amountIn, tokenAddress);
        if (tokensOut < amountOutMin) revert SlippageExceeded();
    }

    /// @notice Sell tokens on the curve. Router-only.
    function sell(
        uint256 amountIn,
        address tokenAddress,
        uint256 amountOutMin,
        address trader
    ) external onlyRouter nonReentrant returns (uint256) {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[tokenAddress];
        if (info.creator == address(0)) revert TokenNotTrading();
        if (info.lifecycle == Lifecycle.Graduating) revert TokenIsGraduating();
        if (info.lifecycle != Lifecycle.Curve) revert TokenNotTrading();
        // A graduatable curve token must graduate, not sell back below the
        // threshold. The user-facing router triggers graduation up front via
        // `triggerGraduation`; rejecting here stops any router that skipped
        // that step from un-ripening a ready graduation.
        if (canGraduate(tokenAddress)) revert TokenIsGraduating();

        (, uint256 assetOut) = $.router.sell(amountIn, tokenAddress, msg.sender);
        if (assetOut < amountOutMin) revert SlippageExceeded();

        (uint256 newCurveSupply, uint256 newLtReserve) = _getCurveState(tokenAddress);
        emit Trade(tokenAddress, trader, false, assetOut, amountIn, newCurveSupply, newLtReserve);
        return assetOut;
    }
