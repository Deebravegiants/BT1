A route venue inside a caller-supplied swap payload can spend the caller's auth for arbitrary token transfers, draining wallet tokens unrelated to the swap — (`File: contracts/controller/src/strategies/swap.rs`)

### Summary
The lending strategy verbs (`swap_collateral`, `swap_debt`, `repay_debt_with_collateral`, `multiply`) and the standalone router (`execute_strategy`) accept opaque, caller-supplied route bytes that name arbitrary "pool" contracts. During route execution, a malicious venue contract can call `token.transfer(victim, attacker, amount)` on any token; the resulting `require_auth` on the victim resolves as a sub-invocation under the victim's single signature on the root entrypoint. This is the direct analog of the emlog CSRF: a single authenticated action (one signed swap) is silently used to perform an unrelated privileged effect (arbitrary transfer of the victim's funds), because the protocol places no venue allowlist between the victim's `require_auth` and attacker-chosen code.

### Finding Description
`swap_collateral` and siblings take a `swap: Bytes` payload and pass it to `swap_tokens`, which calls `router.execute_strategy(&controller, &amount_in, swap)` — or, for standalone swaps, `execute_strategy(sender, total_in, swap_xdr)` calls `sender.require_auth()` at the root and then decodes `ops` naming arbitrary `assets` entries as venue pools, dispatching `invoke_contract` into them. [1](#0-0) [2](#0-1) 

Inside that venue call, `token.transfer(victim, attacker, X)` triggers `victim.require_auth_for_args`; on Soroban this is satisfied by any matching sub-invocation in the victim's already-signed auth tree. The repository's own harness test proves the mechanics end-to-end: a `RogueHopPool` named in the route calls `token::Client::transfer(&victim, &to, &amount)`, simulation records the theft as a child of Alice's `swap_collateral` root invocation, and once that recorded tree is signed, the enforced call moves her entire wallet balance of a token the protocol never listed — while the swap itself returns a fair output. [3](#0-2) [4](#0-3) [5](#0-4) 

Crucially, the enforced-mode control shows the protocol offers no protection beyond "the user must notice": with the honest root-only tree the theft is refused, but the tree produced by the standard `simulateTransaction` → sign flow *includes* the rogue transfer, and wallets need not render nested sub-invocations prominently. The router self-authorizes its own venue pulls (`authorize_as_current_contract`), so the only signer in the tree is the victim — there is no second party whose auth would have to be forged. [6](#0-5) 

### Impact Explanation
Theft of user funds: any token balance in the victim's wallet — including assets entirely unrelated to the protocol — can be transferred to the attacker in the same transaction that executes an otherwise fair, correctly-priced swap. The victim's only visible intent was a collateral swap or standalone swap; the theft rides inside it, exactly as the emlog CSRF rides arbitrary SQL execution inside a routine upgrade request.

### Likelihood Explanation
Requires the victim to sign a transaction built from a malicious route — comparable to the report's "trick an authenticated administrator into visiting a malicious link." Routes are opaque XDR blobs produced off-chain (`routeXdr` from a quote server or dapp); a compromised or malicious quote/frontend can embed a rogue venue hop whose theft is only visible as a nested auth sub-invocation. An unprivileged attacker deploys the venue contract and crafts the payload; no privileged access is needed. Medium likelihood → Medium severity.

### Recommendation
Constrain what runs under the sender's auth: maintain an on-chain allowlist/registry of permitted venue pool contracts (governance-managed), or at minimum bind each hop's pool address to a venue-type check against a known-pool registry rather than accepting an arbitrary `assets` entry. Additionally, on the controller side, document and enforce that strategy `swap` payloads must come from the trusted quote pipeline, and encourage wallets/integrators to reject auth trees where a `transfer` of a non-route token appears under the root invocation.

### Proof of Concept
The shipped test `simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry` and `enforced_auth_moves_the_wallet_token_only_when_the_signed_tree_lists_the_rogue_transfer` in `tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs` demonstrate the full attack: `RogueHopPool` (constructor args: victim, wallet token, attacker, amount) is named as the hop pool in the route bytes passed to `swap_collateral(alice, account_id, USDC, amount, ETH, route)`; the pool's `swap` executes `token.transfer(alice, attacker, WALLET_BALANCE)`, the recorded auth tree nests it under Alice's root, and signing that simulated tree drains her 77,770 units of an unlisted token while the swap pays out its fair `min_out`.

fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
