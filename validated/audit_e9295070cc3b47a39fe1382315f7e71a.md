### Title
Missing role restriction on `GET /v2/external_initiators` discloses initiator credentials to view-only users - (File: core/web/router.go)

### Summary
The Jenkins CVE describes a missing permission check that lets a low-privileged (`Overall/Read`) actor obtain credentials used to connect to an attacker-controlled remote endpoint. Chainlink's `GET /v2/external_initiators` endpoint has the analogous flaw: it is reachable by the lowest authenticated role (`view`) and returns each External Initiator's `AccessKey` and `OutgoingToken`, which are secrets meant to gate/authenticate the node's outbound and inbound job-run interactions with that initiator.

### Finding Description
The v2 router wires `GET /v2/external_initiators` to `eic.Index` with no role-elevation wrapper, unlike the mutating routes on the same resource: [1](#0-0) 

Compare this to `POST`/`DELETE` on the same resource, which are wrapped in `auth.RequiresEditRole`: [1](#0-0) 

The project's own RBAC route matrix documents this as intentional/expected — `viewOnlyAllowed: true` for `GET /v2/external_initiators`: [2](#0-1) 

The handler queries all external initiators and serializes them without any additional filtering: [3](#0-2) 

The response presenter includes `AccessKey` and `OutgoingToken` fields directly on the returned resource: [4](#0-3) 

`OutgoingToken`/`OutgoingSecret` are generated per-initiator as authentication material the node uses to interact with the initiator (created alongside the hashed incoming secret): [5](#0-4) 

While `HashedSecret` and `OutgoingSecret` are correctly excluded from the list resource, `AccessKey` and `OutgoingToken` are not — both are credential material tied to the initiator's authentication scheme (`AccessKey`/`Secret` pair used to authenticate calls to Chainlink, and `OutgoingToken` used by Chainlink to authenticate its own callback traffic to the initiator). A `view`-role API user — the lowest privilege tier, analogous to Jenkins `Overall/Read` — can enumerate this material for every configured initiator via a simple authenticated GET, even though creating/deleting initiators (and other role-sensitive routes such as `POST /v2/bridge_types`) require `edit`/`admin`.

### Impact Explanation
Any authenticated user provisioned with the minimal `view` role — intended only for read-only dashboard access — can retrieve `AccessKey` and `OutgoingToken` values for all configured External Initiators. Depending on how a deployment's initiator integration validates the `OutgoingToken`, this could allow the view-role user to impersonate the Chainlink node's outbound callback traffic to the initiator's service, or combine leaked `AccessKey` values with other disclosure vectors. This is a clear violation of least-privilege / role-segregation, matching the "key/secret disclosure" and "cross-user response confusion" categories called out in scope.

### Likelihood Explanation
Any operator that provisions `view`-role API tokens for read-only integrations (a documented, supported use case) is automatically exposed; no additional bug or race condition is required — a single authenticated GET request is sufficient.

### Recommendation
Wrap `GET /v2/external_initiators` with at least `auth.RequiresEditRole` (matching the write operations on the same resource), or strip `AccessKey`/`OutgoingToken` from the `ExternalInitiatorResource` returned to non-privileged roles.

### Proof of Concept
1. Provision an API user with `UserRoleView`.
2. Authenticate and call `GET /v2/external_initiators` (routed at `core/web/router.go:264`).
3. Observe the response includes `accessKey` and `outgoingToken` for every configured external initiator, per `presenters.ExternalInitiatorResource` (`core/web/presenters/external_initiators.go:57-77`) — despite `view` being the lowest privilege role and creation/deletion of initiators requiring `edit`.

```go
func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}
```

```go
type ExternalInitiatorResource struct {
	JAID
	Name          string         `json:"name"`
	URL           *models.WebURL `json:"url"`
	AccessKey     string         `json:"accessKey"`
	OutgoingToken string         `json:"outgoingToken"`
	CreatedAt     time.Time      `json:"createdAt"`
	UpdatedAt     time.Time      `json:"updatedAt"`
}

func NewExternalInitiatorResource(ei bridges.ExternalInitiator) ExternalInitiatorResource {
	return ExternalInitiatorResource{
		JAID:          NewJAID(strconv.FormatInt(ei.ID, 10)),
		Name:          ei.Name,
		URL:           ei.URL,
		AccessKey:     ei.AccessKey,
		OutgoingToken: ei.OutgoingToken,
		CreatedAt:     ei.CreatedAt,
		UpdatedAt:     ei.UpdatedAt,
	}
}
```

```go
// NewExternalInitiator generates an ExternalInitiator from an
// auth.Token, hashing the password for storage
func NewExternalInitiator(
	eia *auth.Token,
	eir *ExternalInitiatorRequest,
) (*ExternalInitiator, error) {
	salt := utils.NewSecret(utils.DefaultSecretSize)
	hashedSecret, err := auth.HashedSecret(eia, salt)
	if err != nil {
		return nil, pkgerrors.Wrap(err, "error hashing secret for external initiator")
	}

	return &ExternalInitiator{
		Name:           strings.ToLower(eir.Name),
		URL:            eir.URL,
		AccessKey:      eia.AccessKey,
		HashedSecret:   hashedSecret,
		Salt:           salt,
		OutgoingToken:  utils.NewSecret(utils.DefaultSecretSize),
		OutgoingSecret: utils.NewSecret(utils.DefaultSecretSize),
	}, nil
}
```
