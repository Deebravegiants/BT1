### Title
Connected dApp Origins Receive Address Data For All Enabled Wallet Accounts Instead Of Only The Account They Were Granted - ([File: features/connected-origins/module/connections.js])

### Summary
`ConnectedOrigins.getConnectedAccounts` is the method the wallet exposes (even while locked) to tell a connected dApp origin which wallet accounts/addresses it may see. Although each connection stores a `walletAccount` field indicating which specific wallet account the user picked when approving the connection, `getConnectedAccounts` ignores that scoping and returns address data for every wallet account present in `#connectedAccountsAtom`, which is populated from **all enabled wallet accounts**, not just the one associated with the origin.

### Finding Description
When an origin is added via `add()`, a `walletAccount` value is stored per connection, intended to record which wallet account the user connected that origin to [1](#0-0) . However, `getConnectedAccounts` never filters by this stored `walletAccount` field. It instead iterates over every key in `#connectedAccountsAtom` (built from *all* enabled wallet accounts via `#getAccounts`) and returns an address list for each one, only reordering so the currently active account appears first: [2](#0-1) 

`#getAccounts` itself is populated for the full set of enabled wallet accounts, independent of which origins are connected to which account [3](#0-2) .

This mirrors the reported bug class: a security-relevant check/derivation ("what should this relationship expose") is performed over the wrong scope (all accounts) instead of the scope that is actually relevant to the specific relationship (the single `walletAccount` the origin was connected to), silently broadening what an origin can retrieve, in the same way the EVC/EVault controller check was applied to vaults that had no relation to the position.

### Impact Explanation
A website (dApp origin) that a user trusts/connects to only one of their wallet accounts (e.g., "Account 2") can retrieve receive addresses for every other enabled wallet account in the same wallet (e.g., "Account 1", "Account 3", ...), including accounts the user never intended to expose to that origin. This is a cross-account isolation break: addresses for unrelated personas/accounts are disclosed to a third-party origin, which can be used for on-chain correlation/deanonymization of the user's other accounts, undermining the account-isolation guarantees the multi-wallet-account feature is meant to provide.

### Likelihood Explanation
This code path (`getConnectedAccounts`) is explicitly documented as usable "while the wallet is locked" [4](#0-3) , meaning it is reachable from the RPC/background bridge exposed to any already-trusted origin without requiring an unlock or fresh user approval, and is exercised whenever `multipleWalletAccountsEnabled` is true and more than one wallet account is enabled — a normal, common configuration.

### Recommendation
Filter the accounts returned by `getConnectedAccounts` to only the wallet account(s) recorded in the connection's `walletAccount` field (plus any accounts the user has explicitly added via a share/connect-more-accounts flow), rather than returning the full `#connectedAccountsAtom` for all enabled wallet accounts. Add regression tests asserting that an origin connected to `exodus_1` cannot retrieve addresses belonging to `exodus_0`/`exodus_2` unless explicitly granted.

### Proof of Concept
1. Enable multiple wallet accounts (`exodus_0`, `exodus_1`).
2. Connect a dApp origin and call `connectedOrigins.add({ origin, walletAccount: 'exodus_1', connectedAssetName: 'ethereum' })`.
3. From the same origin, call `connectedOrigins.getConnectedAccounts({ origin })`.
4. Observe the result includes an entry not only for `exodus_1` but also for `exodus_0` (and any other enabled accounts), as shown by the unscoped loop over `Object.keys(accounts)` in [5](#0-4) , confirming addresses for accounts outside the connection's intended scope are disclosed.

  getConnectedAccounts = async ({ origin }) => {
    const isTrusted = await this.isTrusted({ origin })
    if (!isTrusted) return []

    const value = await this.#getOrigin({ origin })
    const assetNames = [value.connectedAssetName, ...(value.assetNames ?? [])].filter(
      (name, index, ary) => Boolean(name) && ary.indexOf(name) === index
    )

    const activeWalletAccount = await this.#activeWalletAccountAtom.get()
    const accounts = await this.#connectedAccountsAtom.get()

    const connectedAccounts = []
    for (const name of Object.keys(accounts)) {
      if (name === activeWalletAccount) continue
      connectedAccounts.push({ name, addresses: pick(accounts[name].addresses, assetNames) })
    }

    connectedAccounts.unshift({
      name: activeWalletAccount,
      addresses: pick(accounts[activeWalletAccount].addresses, assetNames),
    })

    return connectedAccounts
  }
