### Title
Accrued-value i128 overflow permanently freezes a large market — no repay, withdraw, or liquidation possible - (File: contracts/pool/src/interest.rs)

### Summary
The CVE class is unbounded arithmetic overflowing a fixed-size buffer/integer. In XOXNO Lending, every market-impacting entrypoint first runs `global_sync` in `contracts/pool/src/interest.rs:20-33`, which calls `accrue_step` → `scaled_to_original` (`common/src/rates/scaling.rs:14-16`) → `Ray::mul` → `mul_div_*` in `common/src/math/fp_core.rs`. That multiply-divide widens to `I256` only for the intermediate product; if the *result* (`borrowed × new_index / RAY`) does not fit `i128`, it raises `GenericError::MathOverflow`.

An unprivileged user can create this state: `supply` a position near the cap (~170B whole tokens at 18 decimals, the exact representable maximum per `docs/reference/formulas.md:426-430`) and `borrow` at ~98% utilization on a steep rate curve (max APR 2 RAY). Interest accrual then grows `borrowed × borrow_index` past `i128::MAX` **before** `borrow_index` reaches the `MAX_BORROW_INDEX_RAY` cap, so the index ceiling never engages.

### Impact Explanation
Permanent freezing of funds / contract unable to operate. Once the RAY-value product overflows, `global_sync` panics, and since every verb (`supply`, `borrow`, `withdraw`, `repay`, `liquidate`, `clean_bad_debt`, `recapitalize`, `update_indexes`) accrues first, the entire market is bricked forever — suppliers cannot withdraw and liquidators cannot act. This is demonstrated end-to-end by `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-361`, which asserts `MATH_OVERFLOW` from `update_indexes`, `withdraw`, and `repay` while `borrow_index < MAX_BORROW_INDEX_RAY`. `docs/reference/formulas.md:434-437` acknowledges: "Value overflow can occur before the index ceiling and block repayment/withdrawal… No dedicated ceiling alarm is emitted."

### Likelihood Explanation
Requires a whale-scale market (≈170B whole-token supply) sustained at high utilization for years of compounding — not cheap, but no privileged access is needed: two ordinary `supply`/`borrow` calls create the preconditions, and time does the rest. Utilization caps and borrow caps are optional and can be lifted; nothing on-chain prevents reaching the cliff. Medium likelihood, severe impact — consistent with High.

### Recommendation
Cap accrual on the *value* side, not only the index: in `accrue_step`/`update_borrow_index`, detect when `borrowed × new_index / RAY` would overflow and clamp `new_index` to `floor(i128::MAX / borrowed_scaled)`, or stop accrual (freeze index, emit an event) rather than panic — matching the "cap fails open instead of trapping" precedent set by `calculate_scaled_cap`'s saturating path. A `clean_bad_debt`/deleveraging escape path that bypasses `global_sync` (or accrues with a clamped index) would let the market unwind instead of bricking.

### Proof of Concept
```rust
// tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321
let mut t = LendingTest::new()
    .with_market(big("BIG18", 18, xlm_curve()))
    .with_market(col())
    .with_max_utilization_disabled_all_markets()
    .build();
lift_caps(&t, "BIG18", 18);
t.supply_raw(BOB, "BIG18", BILLION * 10i128.pow(18));      // unprivileged supply
t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
t.borrow_raw(ALICE, "BIG18", principal / 100 * 98);        // 98% utilization
// advance ~years; accrual eventually panics inside scaled_to_original:
assert_contract_error(t.try_update_indexes_for(&["BIG18"]), errors::MATH_OVERFLOW);
assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW); // frozen
assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0),    errors::MATH_OVERFLOW); // frozen
// last.borrow_index < MAX_BORROW_INDEX_RAY — the index cap never engaged
```
