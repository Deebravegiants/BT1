Confirmed: `CallDispatcher.dispatch` is fully permissionless — `function dispatch(bytes memory encoded) external` has no access control and can be called by anyone, and `CallDispatcher` itself has a `receive() external payable {}` so it can accumulate arbitrary native/ERC-20 balance from anyone at any time [1](#0-0) . This is the shared, permissionless dispatcher address referenced by `_params.dispatcher` and used identically by `placeOrder`'s predispatch sweep [2](#0-1)  and by `_execute`'s post-fill sweep [3](#0-2) .

### Title
`placeOrder`'s predispatch sweep credits an order with the CallDispatcher's *entire* token/native balance instead of the amount the predispatch call actually produced, letting an attacker inflate their own escrow with funds anyone (including an unrelated victim) sent to the shared, permissionless `CallDispatcher` - ([File: evm/src/apps/IntentGatewayV2.sol])

### Summary
`IntentGatewayV2.placeOrder`'s predispatch flow mirrors the AutoRoller `eject` root cause: instead of computing the amount that the user's own predispatch operation actually yielded, it reads `IERC20(token).balanceOf(dispatcher)` / `dispatcher.balance` — the dispatcher's *total* current balance — and sweeps that whole amount back to the gateway, crediting it to `order.inputs[i].amount` [4](#0-3) . Because `CallDispatcher.dispatch` is a public, access-control-free function that any address can call to route arbitrary `Call[]` through the dispatcher, and `CallDispatcher` has a `receive()` fallback, its balance is not scoped to the caller's own transaction — anyone can pre-fund the dispatcher with tokens/ETH.

### Finding Description
In `placeOrder`, when `order.predispatch.call.length > 0`, the gateway transfers `order.predispatch.assets` to `dispatcher`, invokes `ICallDispatcher(dispatcher).dispatch(order.predispatch.call)`, then computes the sweep amount from the dispatcher's raw balance rather than from a delta specific to this call [5](#0-4) :
```solidity
uint256 balance = IERC20(token).balanceOf(dispatcher);
if (balance < requiredAmount) revert InvalidInput();
transferCalls[i] = Call({to: token, value: 0, data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)});
```
The sweep call moves the dispatcher's *entire* balance of that token, and the "received" amount attributed to the order is computed from the *gateway's* own before/after balance [6](#0-5) . Because `CallDispatcher.dispatch(bytes)` has no caller restriction and `CallDispatcher` accepts native ETH via `receive()` [7](#0-6) , any external account (or a stuck/partially-processed prior flow, e.g. `_execute`'s own post-fill sweep of the same shared dispatcher [8](#0-7) , or funds routed there by `HyperFungibleToken`/`WrappedHyperFungibleToken` calldata-execution flows that also target this same dispatcher address for swap intermediates) can leave a balance sitting in the dispatcher. An attacker who times a `placeOrder` predispatch call to land while such a balance is present in the dispatcher will have that balance swept into `order.inputs[i].amount` on top of what their own predispatch call actually produced — inflating the escrow they place. Since the attacker is also the order's `user`, they can subsequently cancel the order (`_cancelSameChain`/cross-chain refund path) to reclaim the full inflated escrow, or supply themselves as solver to capture it — converting balance that belonged to someone else's transaction into their own withdrawable escrow. This is structurally the same root cause the Sense Finance report identifies: crediting the caller with the *whole* balance of a shared account rather than the amount specifically attributable to their own action.

### Impact Explanation
An attacker can convert tokens/ETH that transiently sit in the shared, permissionless `CallDispatcher` (whether from another user's front-run/back-run `dispatch()` call, from Hyperbridge-driven calldata execution by `HyperFungibleToken`/`WrappedHyperFungibleToken`, or from a griefing deposit made directly via `dispatch()`/`receive()`) into their own escrowed order input, then withdraw it via cancellation or self-fill — a theft/fund-diversion primitive reachable from a single `placeOrder` transaction by any unprivileged caller.

### Likelihood Explanation
Requires the attacker to time their `placeOrder` predispatch call so a non-zero balance is present in `CallDispatcher` for the target token at sweep time. This is achievable by the attacker themselves (e.g., calling `CallDispatcher.dispatch` directly to pre-seed a balance in a preceding transaction, or via MEV bundling around any legitimate flow that transiently uses the same dispatcher address), since `dispatch()` is entirely permissionless and dispatcher balance is not namespaced per caller or per order.

### Recommendation
Compute the sweep amount from a balance delta captured immediately before and after `order.predispatch.call` executes (i.e., snapshot the dispatcher's balance right before dispatching the predispatch call, not just before the final sweep), rather than sweeping the dispatcher's total balance. Alternatively, deploy a fresh, single-use dispatcher (or dispatcher session) per order, or otherwise ensure the dispatcher cannot accumulate balance attributable to anyone other than the current caller's own predispatch execution before the sweep runs.

### Proof of Concept
1. Attacker (or any party) sends `X` tokens of type `T` to the `CallDispatcher` address directly (permissionless `receive()`/direct `transfer`), or triggers any legitimate cross-app flow (e.g. an `HyperFungibleToken.send` with calldata targeting the same `CallDispatcher`) that leaves `X` of token `T` sitting in the dispatcher.
2. Attacker calls `placeOrder` with `predispatch.assets` supplying a small amount `Y` of token `T`, and `predispatch.call` a no-op/minimal call that doesn't consume the dispatcher's balance.
3. In the sweep step, `IERC20(T).balanceOf(dispatcher)` reads `X + Y` (not just `Y`), so `transferCalls` sweeps `X + Y` to the gateway, and `order.inputs[0].amount` is credited with `X + Y` (minus protocol fee) [9](#0-8) .
4. Attacker cancels the order via `_cancelSameChain` (attacker is `order.user`) and receives the full inflated escrow `X + Y`, having only supplied `Y` [10](#0-9) .

contract CallDispatcher is ICallDispatcher {
    /**
     * @dev error thrown when the target is not a contract.
     */
    error NotContract(address target);

    /**
     * @dev error thrown when a call fails.
     */
    error CallFailed(address target, bytes result);

    /**
     * @dev Receive function to accept ETH transfers
     */
    receive() external payable {}

    /**
     *  @dev reverts if the target is not a contract or if any of the calls reverts.
     */
    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
