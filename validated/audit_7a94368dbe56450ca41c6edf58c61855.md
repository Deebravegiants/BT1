Audit Report

## Title
Wildcard CORS origin allowlist bypass via unbounded suffix match - (File: core/services/gateway/network/httpserver.go)

## Summary
`isAllowedOrigin` in `core/services/gateway/network/httpserver.go` matches wildcard `CORSAllowedOrigins` entries (e.g. `*.example.com`) using a bare `strings.HasSuffix(originHost, allowedHost)` check with no domain-label boundary enforcement [1](#0-0) . This lets an attacker who controls a look-alike domain such as `evilexample.com` (which is not a subdomain of `example.com`) satisfy a `*.example.com` allowlist entry, causing the Gateway to reflect that attacker origin into `Access-Control-Allow-Origin` and grant it cross-origin access to the `/user` endpoint [2](#0-1) .

## Finding Description
The wildcard branch strips the `*.` prefix from the configured allowlist entry and then checks only `strings.HasSuffix(originHost, allowedHost)`, without requiring that the character immediately preceding the matched suffix in `originHost` be a `.` (i.e., a true subdomain boundary) or that `originHost` equal `allowedHost` exactly [3](#0-2) . As a result, `evilexample.com`, `notexample.com`, or any domain an attacker registers that merely ends with the string `example.com` will pass the check even though it shares no actual subdomain relationship with `example.com`. Scheme and port checks earlier in the loop do not mitigate this since they only gate scheme/port equality, not the host suffix logic itself [4](#0-3) . The existing unit tests only cover a negative case where the origin does not end with the allowed suffix at all (`ethereum.remix.org` vs `*.ethereum.org`) [5](#0-4) ; there is no test covering the actual bypass scenario of a domain that shares the suffix string without a genuine subdomain relationship, confirming the flaw is present and unaddressed in the codebase.

## Impact Explanation
When `isAllowedOrigin` returns `true`, the handler sets `Access-Control-Allow-Origin` to the attacker-supplied `Origin` value and enables `GET, POST, OPTIONS` with `Content-Type` header access [6](#0-5) , allowing a page hosted on the attacker's look-alike domain to make authenticated-looking cross-origin browser requests to the Gateway's user-facing endpoint and read the JSON-RPC response. This is a concrete allowlist-bypass condition affecting an internet-facing Chainlink Gateway component, falling under the "allowlist bypass" / "gateway request impersonation" impact category.

## Likelihood Explanation
Exploitation requires only that (a) the operator use a wildcard entry in `CORSAllowedOrigins`, which is a documented, supported configuration pattern (present in sample configs), and (b) the attacker register any domain string ending with the allowed suffix and host a page there. Browsers automatically set the `Origin` header to the true origin of the requesting page, so no header spoofing is needed — the attacker only needs to control a domain matching the suffix pattern, well within reach of an unprivileged external actor.

## Recommendation
Change the wildcard comparison in `isAllowedOrigin` to enforce a proper label boundary, e.g.:
```go
if strings.HasPrefix(allowedHost, "*.") {
    allowedHost = allowedHost[2:]
    if originHost == allowedHost || strings.HasSuffix(originHost, "."+allowedHost) {
        return true
    }
}
```
Consider using a vetted hostname/domain-suffix comparison library instead of manual string operations to avoid similar boundary errors.

## Proof of Concept
1. Configure `HTTPServerConfig.CORSEnabled = true` and `CORSAllowedOrigins = ["https://*.example.com"]`.
2. Send a request to the gateway's configured path with header `Origin: https://evilexample.com`.
3. Observe that `isAllowedOrigin` returns `true` (since `strings.HasSuffix("evilexample.com", "example.com")` is `true`), and the response includes `Access-Control-Allow-Origin: https://evilexample.com`.
4. This can be added as a Go unit test in `core/services/gateway/network/httpserver_test.go` alongside `TestHTTPServer_HandleRequest_CORSEnabled_FromNotAllowedOriginWildcards`, asserting that origin `https://evilexample.com` against allowed `https://*.example.com` incorrectly yields a non-empty `Access-Control-Allow-Origin` header.

func (s *httpServer) isAllowedOrigin(origin string) bool {
	originScheme, originHost, originPort, err := s.splitURL(origin)
	if err != nil {
		s.lggr.Debug("error parsing origin URL", err)
		return false
	}
	for _, allowed := range s.config.CORSAllowedOrigins {
		// probably better to do this once when server starts and store it in a map
		// this is an easier solution so we don't have to apply more changes to the code
		// just need to be careful when specifying allowed origins in the config file
		allowedScheme, allowedHost, allowedPort, err := s.splitURL(allowed)
		if err != nil {
			s.lggr.Debug("error parsing allowed origin URL", err)
			continue
		}
		// skip if the scheme doesn't match at all
		if originScheme != allowedScheme {
			continue
		}
		// skip if the port doesn't match at all
		if originPort != allowedPort {
			continue
		}
		// check for exact host match (e.g., remix.com)
		if originHost == allowedHost {
			return true
		}
		// check for wildcard host match (e.g., *.remix.com)
		if strings.HasPrefix(allowedHost, "*.") {
			allowedHost = allowedHost[2:]
			if strings.HasSuffix(originHost, allowedHost) {
				return true
			}
		}
	}
	return false
}

func (s *httpServer) handleRequest(w http.ResponseWriter, r *http.Request) {
	if s.config.CORSEnabled {
		origin := r.Header.Get("Origin")
		if s.isAllowedOrigin(origin) {
			w.Header().Set("Access-Control-Allow-Origin", origin)
			w.Header().Set("Access-Control-Allow-Methods", "GET, POST, OPTIONS")
			w.Header().Set("Access-Control-Allow-Headers", "Content-Type")
		}

		// handle preflight requests
		if r.Method == http.MethodOptions {
			w.WriteHeader(http.StatusNoContent)
			return
		}
	}
