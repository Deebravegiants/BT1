### Title
Swap fee/relay-fee amounts are permanently frozen in `ExternalActionSwap` when `circomData.relay == address(0)` but `feeStructure.flatFee`/`variableRate > 0` - (`contracts/external-actions/swaps/ExternalActionSwap.sol`)

### Summary
`ExternalActionSwap.swap()` unconditionally deducts `totalFee` (relay flat fee + protocol/"hinkal" variable fee) from the swapped output before forwarding the remainder to the Hinkal contract, but it only *actually transfers* those fees out via `sendToRelay`, which silently no-ops whenever `circomData.relay == address(0)`. This is the same equality-breaking pattern as the Merit Circle `escrowedReward`/`escrowPool` bug: an "amount destined for X" is computed and subtracted from the user payout, while the transfer to X is conditionally skipped, leaving the corresponding value permanently stuck in the contract with no recovery path.

### Finding Description
In `swap()`: [1](#0-0) 

`relayFee`/`hinkalFee` are computed from `circomData.feeStructure.flatFee` and `circomData.feeStructure.variableRate`, and `totalFee` is subtracted from `swappedAmount` to compute `amountToSendToHinkal`, which is the only amount actually sent to `msg.sender` (the Hinkal contract) and recorded in the outgoing UTXO.

The actual fee payment is routed through `sendToRelay`: [2](#0-1) 

`sendToRelay` is a no-op when `relay == address(0)`. Whether `circomData.relay` is `address(0)` is entirely under the caller's control and is a legitimate, checked value combination: `HinkalHelper.performHinkalChecks` explicitly permits `circomData.relay == address(0)` as long as `circomData.originalSender == sender` (a normal, non-relayed self-submitted transaction): [3](#0-2) 

No check anywhere in `HinkalHelper`, `Hinkal.sol`, or `ExternalActionSwap.sol` forces `feeStructure.flatFee == 0 && feeStructure.variableRate == 0` when `relay == address(0)`. A user can therefore submit a valid proof/transaction where:
- `circomData.relay == address(0)` (self-relay path, passes `relayerIsValid` and the originalSender check), and
- `circomData.feeStructure.flatFee > 0` and/or `circomData.feeStructure.variableRate > 0`.

`swap()` will still compute `relayFee`/`hinkalFee > 0` and subtract `totalFee` from the amount sent to the user's new UTXO, but `sendToRelay(...)` will do nothing because `relay == address(0)`. The `totalFee` worth of `outputToken` (or `feeToken`) remains in the `LifiExternalAction`/`ExternalActionSwap` contract's balance indefinitely: there is no owner/rescue function in `ExternalActionBaseV2`, `LifiExternalAction`, or `ExternalActionSwap` that can retrieve stranded token balances: [4](#0-3) [5](#0-4) 

This contrasts with `EmporiumUpgradeable.payRelayFees`/`payRelay`, which has the identical `relay == address(0)` guard, but is safe because its output UTXO is computed from an actual balance-diff (`balancesAfter - balancesBefore`) rather than an arithmetic subtraction of the intended fee — so any fee that fails to leave the contract there is automatically swept back to the user via `handleOut`: [6](#0-5) 

`ExternalActionSwap.swap()` lacks this balance-diff safety net — it computes `amountToSendToHinkal` by subtraction, not by measuring the contract's residual balance, so the equality "swapped value out = user payout + fees actually paid" is broken whenever the fee transfer is skipped.

### Impact Explanation
Every user who submits a self-relayed swap (`relay == address(0)`) with nonzero `feeStructure.flatFee`/`variableRate` permanently loses the fee-equivalent portion of their swap output — it is stranded in the `LifiExternalAction`/`ExternalActionSwap` contract with no admin or user recovery mechanism. This matches "permanent freezing of user funds," a Critical-severity impact per the rubric, since neither the user, the relay, nor the protocol owner can retrieve the stuck tokens.

### Likelihood Explanation
This is trivially reachable by any unprivileged EOA: it only requires constructing a valid `CircomData`/proof where `relay = address(0)` and `feeStructure.flatFee`/`variableRate` are nonzero — both are ordinary, contract-permitted field combinations with no additional guard preventing them. No admin, relayer, or oracle assumptions are needed.

### Recommendation
In `ExternalActionSwap.swap()`, compute `amountToSendToHinkal` from an actual post-fee-transfer balance measurement (mirroring `EmporiumUpgradeable`'s `balancesBefore`/`balancesAfter` diff pattern) instead of arithmetic subtraction, or alternatively enforce that `feeStructure.flatFee == 0 && feeStructure.variableRate == 0` whenever `circomData.relay == address(0)` (analogous to the Sherlock-recommended fix of validating incompatible field combinations at the point of use).

### Proof of Concept
1. Deploy/observe an existing `LifiExternalAction` (subclass of `ExternalActionSwap`) registered as a Hinkal external action.
2. A user builds and proves a `transact` call with:
   - `circomData.externalActionData.externalActionId` pointing to the Lifi/swap action,
   - `circomData.erc20TokenAddresses = [inputToken, outputToken]`,
   - `circomData.relay = address(0)`, `circomData.originalSender = msg.sender` (passes `performHinkalChecks`),
   - `circomData.feeStructure = { feeToken: outputToken, flatFee: F > 0, variableRate: R > 0 }`.
3. `Hinkal.transact` → `_externalTransact` → `LifiExternalAction.runAction` → `ExternalActionSwap.swap()` executes the router swap, computes `relayFee = F`, `hinkalFee = calculateRelayFee(swappedAmount, 0, R) > 0`, `totalFee = relayFee + hinkalFee`.
4. `sendToRelay(address(0), relayFee + hinkalFee, outputToken)` is called but no-ops (`relay == address(0)` guard in `Transferer.sendToRelay`).
5. `amountToSendToHinkal = swappedAmount - totalFee` is transferred to `msg.sender` (Hinkal) and recorded as the user's UTXO amount; `totalFee` worth of `outputToken` remains stuck in the `LifiExternalAction` contract's token balance permanently, unrecoverable by user or owner.

pragma solidity ^0.8.17;

import "./ExternalActionSwap.sol";

contract LifiExternalAction is ExternalActionSwap {
    constructor(
        address _hinkalHelper,
        address _wrapper,
        address _router,
        address[] memory _allowedRecipients
    )
        ExternalActionSwap(_hinkalHelper, _wrapper, _router, _allowedRecipients)
    {}

    function callRouter(
        address inputToken,
        uint256 inputAmount,
        address outputToken,
        bytes calldata externalActionMetadata
    ) internal override returns (uint256 swappedAmount) {
        uint256 balanceBefore = getERC20OrETHBalance(outputToken);

        if (inputToken == address(0)) {
            (bool success, ) = router.call{value: inputAmount}(
                externalActionMetadata
            );
            require(success, "LI.FI swap failed: native coin");
        } else {
            approveUnlimited(inputToken, router);
            (bool success, ) = router.call(externalActionMetadata);
            require(success, "LI.FI swap failed: erc-20 token");
        }

        swappedAmount = getERC20OrETHBalance(outputToken) - balanceBefore;
    }
}

abstract contract ExternalActionBaseV2 is IExternalActionV2, OwnerHinkal {
    mapping(address => bool) internal isAllowedRecipient;

    /*
     * @dev Modifier to check if the sender is allowed to call the action
     * @dev Used to handle VolatileTokenAction and Hinkal interactions
     */
    modifier onlyAllowedRecipient() {
        require(
            isAllowedRecipient[msg.sender],
            "ExternalActionBase: sender not allowed"
        );
        _;
    }

    constructor(address[] memory _allowedRecipients) {
        for (uint i = 0; i < _allowedRecipients.length; i++) {
            isAllowedRecipient[_allowedRecipients[i]] = true;
        }
    }

    function setAllowedRecipients(
        address[] calldata recipients
    ) external onlyOwner {
        for (uint i = 0; i < recipients.length; i++) {
            require(recipients[i] != address(0), "zero address!");
            isAllowedRecipient[recipients[i]] = true;
        }
    }

    function runAction(
        CircomData calldata circomData,
        int256[] calldata deltaAmountChanges
    ) external virtual returns (UTXO[] memory utxoSet) {}
