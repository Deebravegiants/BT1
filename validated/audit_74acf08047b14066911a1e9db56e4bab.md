### Title
Unauthenticated on-chain calldata execution as the token sender's account via unsigned `SubstrateCalldata` in HFT bridging - (File: modules/pallets/hyper-fungible-token/src/module.rs)

### Summary
`HyperFungibleToken::onAccept` (Solidity, `sdk/packages/core/contracts/apps/HyperFungibleToken.sol`) sets `Message.from = abi.encodePacked(msg.sender)` [1](#0-0) , so `from` is genuinely the caller's own address and cannot be spoofed to impersonate a different account. On the Substrate destination side, `Pallet::on_accept` decodes `SubstrateCalldata` from `message.data` and, when no `signature` is supplied, derives the dispatch `origin` directly from `message.from` and dispatches an attacker-supplied, SCALE-decoded `RuntimeCall` as `RawOrigin::Signed(origin)`, gated only by `BaseCallFilter` [2](#0-1) .

### Finding Description
This mirrors the xalpha bug class ("attacker-controlled bytes reach a powerful execution sink with insufficient validation of what may be executed"): here the sink is `Dispatchable::dispatch`, and the "insufficient validation" is that arbitrary, permissionless `RuntimeCall` bytes crossing a bridge are executed with only a coarse `BaseCallFilter::contains` check [3](#0-2) .

Because `message.from` is always `msg.sender` on the EVM side (not user-suppliable), the unsigned path only ever dispatches as the sender's own mapped account, so it is not by itself a cross-account authorization bypass. However, the filter that is supposed to bound the blast radius is only the runtime's global `BaseCallFilter` — a static allow/deny list applied to normal signed extrinsics — and not a bridge-specific policy. Any dispatchable not excluded by `BaseCallFilter` (e.g. pallet calls for staking, governance voting, XCM, proxy management, `set_code` via authorized-upgrade style calls, or other pallets configured in the destination runtime) can be triggered purely by relaying an ISMP message with attacker-chosen calldata plus a minimal/zero-value token transfer, with **no substrate-side signature verification required at all** for the unsigned branch. This turns the HFT bridge into a generic, filter-gated remote call executor reachable by anyone who can originate an EVM-side `send()` (an unprivileged action) and get it relayed — exactly the "attacker input drives an evaluator/executor whose safety rests on an incomplete allowlist" pattern the xalpha CVE exemplifies (there, insufficiently-validated input reached `eval`; here, insufficiently-scoped input reaches `Dispatchable::dispatch`).

### Impact Explanation
An attacker who is confident that `BaseCallFilter` on a given deployment does not exclude a sensitive dispatchable (this is runtime-configuration-dependent and not verifiable from this pallet alone) can execute that call as their own bridged identity account, using it to trigger unauthorized app/pallet actions cross-chain — e.g., interacting with other pallets that trust the bridged identity, staking/locking/voting using assets already present at the mapped `EvmToSubstrate::convert(msg.sender)` account, or invoking other bridge/pallet extrinsics that were never intended to be reachable via unsigned cross-chain relay. Because the pallet performs no additional restriction (e.g., a dedicated bridge-calldata filter, weight/complexity caps, or requiring signature even for the sender's own calls), this significantly expands the dispatchable surface reachable from a single cross-chain token transfer beyond what the destination chain's extrinsic submission normally allows for an unauthenticated relay path.

### Likelihood Explanation
Medium: exploitability is entirely dependent on the destination runtime's `BaseCallFilter` configuration, which is out of scope of this pallet and unknown from the code reviewed. If the filter is permissive (a common configuration, since `BaseCallFilter` is usually built for extrinsic categories like "maintenance mode," not calldata provenance), any address that can call `HyperFungibleToken.send()` (fully permissionless) and get the message relayed can trigger this path with zero token value and arbitrary runtime calldata.

### Recommendation
- Do not treat the unsigned branch as safe merely by dispatching as the sender's own account; either require a signature unconditionally for calldata execution, or restrict the calls reachable from bridged messages to an explicit allow-list distinct from the general `BaseCallFilter` (e.g., a pallet-specific `CallFilter` type in `Config`).
- Consider bounding weight/complexity of `runtime_call` before dispatch and emitting a specific event distinguishing bridge-originated dispatches for monitoring.
- Audit all downstream runtimes deploying this pallet to confirm `BaseCallFilter` excludes governance, staking, proxy, and upgrade-related calls from being reachable via this path.

### Proof of Concept
1. Attacker calls `HyperFungibleToken.send()` on the source EVM chain with `params.amount = 0` (or minimal), `params.to` = attacker's own destination account bytes, and `params.data` = an ABI-encoded `SubstrateCalldata { signature: None, runtime_call: <SCALE-encoded RuntimeCall> }`.
2. `_buildDispatchPost` sets `Message.from = abi.encodePacked(msg.sender)` automatically [1](#0-0) .
3. Once relayed and accepted on the destination Substrate chain, `Pallet::on_accept` decodes `substrate_data`, sees `signature == None`, and sets `origin = EvmToSubstrate::convert(H160::from(message.from))` (the attacker's own mapped account) [4](#0-3) .
4. The pallet decodes `runtime_call` and dispatches it with `RawOrigin::Signed(origin)`, subject only to `BaseCallFilter::contains` [3](#0-2) .
5. If `BaseCallFilter` permits the chosen call, it executes fully — permissionlessly, without any substrate-side signature — as an on-chain effect solely from the relayed cross-chain message. [5](#0-4) [6](#0-5)

    function onAccept(IncomingPostRequest calldata incoming) public virtual override onlyHost whenNotPaused {
        PostRequest calldata request = incoming.request;

        bytes memory expectedSource = _supportedChains[request.source];
        if (expectedSource.length == 0) revert UnsupportedChain();
        if (keccak256(request.from) != keccak256(expectedSource)) revert UnauthorizedSource();

        Message memory message = abi.decode(request.body, (Message));
        address beneficiary = _toAddr(message.to);
        _mint(beneficiary, message.amount);

        if (message.data.length > 0) {
            ICallDispatcher(_dispatcher).dispatch(message.data);
        }

        emit Received({
            from: message.from,
            to: beneficiary,
            source: string(request.source),
            amount: message.amount
        });
    }
