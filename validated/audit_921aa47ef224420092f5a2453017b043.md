### Title
NULL Pointer Dereference in Vault Gateway `GetPublicKeyGet` Handler via Missing Params - (File: core/capabilities/vault/gw_handler.go)

### Summary
The `GatewayHandler.HandleGatewayMessage` dispatcher routes `vaulttypes.MethodPublicKeyGet` requests directly to `handlePublicKeyGet` without first passing them through the `GatewayVaultRequestProcessor` validation pipeline that the other vault methods use. `handlePublicKeyGet` immediately dereferences `*req.Params` with no nil check, so a JSON-RPC request that omits the `params` field (or sets it to `null`) triggers a Go nil-pointer-dereference panic. This is analogous to the Bento4 `AP4_Processor::Process` NULL pointer dereference (CVE-2017-12475), where a crafted/malformed input file with a missing expected field leads to a crash, except here the "file" is an attacker-controlled JSON-RPC message reaching a Chainlink node's gateway connector.

### Finding Description
`GatewayHandler.HandleGatewayMessage` switches on `req.Method`: [1](#0-0) 

For `MethodSecretsCreate`, `MethodSecretsUpdate`, `MethodSecretsDelete`, and `MethodSecretsList`, the request first passes through `h.requestProcessor.ProcessRequest(...)`, which runs `ValidateStructureBeforeAuth → AuthorizeRequest → ...` on the raw request before any handler unmarshals params: [2](#0-1) 

However, `MethodPublicKeyGet` bypasses this pipeline entirely and is dispatched straight to `handlePublicKeyGet`: [3](#0-2) 

`handlePublicKeyGet` unconditionally dereferences `req.Params`: [4](#0-3) 

If `req.Params` is `nil` (a JSON-RPC request that omits the `"params"` key, which is legal per JSON-RPC 2.0), the expression `*req.Params` dereferences a nil `*json.RawMessage`, causing an unrecovered Go panic.

This request is delivered to the node process via `gatewayConnector.readLoop`, which invokes `handler.HandleGatewayMessage` directly on the read-loop goroutine with no `recover()`: [5](#0-4) 

Because Go panics that are not recovered terminate the entire process (not just the goroutine), a single malformed gateway message can crash the whole Chainlink node process.

### Impact Explanation
An unprivileged actor able to reach the gateway's public-facing JSON-RPC endpoint (or spoof/replay a gateway-to-node message for the `MethodPublicKeyGet` method) can crash the node process with a single malformed request — a denial-of-service condition matching the severity class of CVE-2017-12475. Unlike the other vault methods, this path has no upstream structural validation gate, so the nil check that protects `handleSecretsCreate`/`Update`/`Delete`/`List` (via the request-processor pipeline) does not apply here.

### Likelihood Explanation
The trigger is trivial: send (or relay) a JSON-RPC request with `method: "vault_publicKeyGet"` (or the equivalent `vaulttypes.MethodPublicKeyGet` constant) and omit or null out the `params` field. No authentication bypass or cryptographic work is required to reach `handlePublicKeyGet`, since it is one of the methods reachable from `GatewayHandler.HandleGatewayMessage` without going through the authorization pipeline.

### Recommendation
Add an explicit nil/empty check on `req.Params` before dereferencing in `handlePublicKeyGet` (and audit all other `*req.Params` dereference sites in `gw_handler.go` for the same pattern), returning `api.UserMessageParseError` instead of panicking. Additionally, wrap `gatewayConnector.readLoop`'s call to `handler.HandleGatewayMessage` in a `recover()` to prevent any single malformed/handler-bug message from crashing the entire node process.

### Proof of Concept
```json
{
  "jsonrpc": "2.0",
  "id": "1",
  "method": "vault_publicKeyGet"
}
```
Send this JSON-RPC message (with `params` omitted or set to `null`) to the gateway so it is routed to the node's `GatewayHandler.HandleGatewayMessage` with method `vaulttypes.MethodPublicKeyGet`. Execution reaches:
```go
r := &vaultcommon.GetPublicKeyRequest{}
if err := json.Unmarshal(*req.Params, r); err != nil { // panics here: req.Params == nil
``` [6](#0-5) 
causing a nil-pointer-dereference panic that propagates unrecovered from `gatewayConnector.readLoop`, crashing the node process.

**Note on verification limits:** I was unable to locate the exact source of `ValidateStructureBeforeAuth`/`processRequest` in `core/capabilities/vault/gateway_vault_request_processor.go` (only lines 1-90 were retrieved), so I could not fully confirm the specific nil-params check logic applied to the other vault methods that go through the pipeline. This does not affect the finding above, since `handlePublicKeyGet` provably bypasses that pipeline entirely.
