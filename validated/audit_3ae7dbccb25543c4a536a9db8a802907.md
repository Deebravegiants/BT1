### Title
Shared `maxOracleAge` staleness bound lets a stale, volatile native-asset price be used for gas-fee pricing and fee-recycling swaps — ([File: evm/src/utils/SimplexPaymaster.sol])

### Summary
`SimplexPaymaster` prices ERC-20 gas payments and fee-recycling swaps from Chainlink `latestRoundData()`, gated by a single staleness bound `maxOracleAge` applied identically to both the volatile native-asset oracle (`nativeOracle`, e.g. ETH/USD) and the near-stable token oracle (`tokenOracle`, e.g. USDC/USD). The deployment script explicitly sizes `maxOracleAge` to accommodate the *stablecoin* feed's 24h heartbeat, but that same bound is reused to validate the *native* oracle's freshness, even though native/USD feeds update far more frequently in practice. This mirrors the USSD `mintForToken` bug class: any unprivileged UserOp sender can be charged based on a native price that is up to `maxOracleAge` stale, letting them realize an economic gain (underpay for gas) whenever the real native price has moved favorably since the last on-chain update.

### Finding Description
`_getOraclePrice` is the sole gate against stale prices: [1](#0-0) 

It is invoked identically for both oracles from `_tokenPrice`: [2](#0-1) 

`_tokenPrice` feeds directly into what a UserOp sender is charged in `_fetchDetails`, which is reachable by any unprivileged UserOp sender routed through this paymaster (no relayer/allow-list gate on gas payments): [3](#0-2) 

Deployment configuration sets `maxOracleAge` specifically to tolerate the *stablecoin* feed's 24h heartbeat: [4](#0-3) 

But `Params.maxOracleAge` is a single, shared bound — there is no separate, tighter staleness bound for `nativeOracle`, which is materially more volatile than the stablecoin feed it's sized around: [5](#0-4) 

The hard governance ceiling on this shared bound is 7 days: [6](#0-5) 

The same stale-tolerant price also drives the treasury's `swapAndDeposit` fee-recycling flow, where `expectedWei`/`amountOutMin` for a live Uniswap V2 swap are derived from the same possibly-stale oracle pair: [7](#0-6) 

If `nativeOracle`'s last update is old (up to `maxOracleAge`, which can be tens of hours per the deployment default, or governance-configured up to 7 days) and the real native price has since risen relative to the oracle's recorded value, `tokenPrice` in `_tokenPrice` computes a lower-than-market stablecoin cost per unit of gas. Any UserOp sender paying gas via this paymaster (mode `0x00` permit or mode `0x02` Permit2) is charged that stale, undervalued price, extracting value from the paymaster's treasury/EntryPoint deposit on every sponsored operation until the oracle updates.

### Impact Explanation
This does not directly mint unbacked tokens, but it lets any unprivileged UserOp sender systematically underpay for sponsored gas relative to the true native-asset cost, draining the paymaster's EntryPoint deposit and treasury reserves — the same "arbitrage against a stale oracle" root cause as the referenced USSD report, just expressed as fee/value leakage rather than a stablecoin depeg. It is repeatable per UserOp and scales with the size of the price gap and transaction volume during the staleness window, and additionally degrades the execution price obtained on treasury-triggered `swapAndDeposit` swaps.

### Likelihood Explanation
Reachable by any unprivileged actor able to submit a UserOp priced through the paymaster — no special privilege required. The condition (native price moving meaningfully within the configured staleness window, which the deployment sizes to tens of hours to accommodate an unrelated stablecoin feed) is realistic for a volatile ETH/BNB market and is entirely foreseeable given the documented 24h buffer choice.

### Recommendation
Use independent, appropriately tight staleness bounds per oracle role instead of one shared `maxOracleAge` — bound `nativeOracle` freshness to its own (short) Chainlink heartbeat, and only allow the longer bound for the stablecoin `tokenOracle`. Consider also capping the maximum acceptable price deviation (not just staleness) or falling back to a TWAP for pricing when the native oracle is older than its expected heartbeat.

### Proof of Concept
1. Deploy `SimplexPaymaster` with `maxOracleAge = 90_000` (per `DeploySimplexPaymaster.s.sol` default for a 24h stablecoin heartbeat) and a native (e.g. ETH/USD) Chainlink feed with a ~1h heartbeat.
2. Let the native oracle go stale (e.g. 20 hours without an update) while the real ETH price rises meaningfully from the recorded `answer`.
3. Submit UserOps through the paymaster (mode `0x00`/`0x02`) — `_fetchDetails` → `_tokenPrice` → `_getOraclePrice` accepts the 20‑hour‑old native price because it is still within `maxOracleAge`, computing a stablecoin cost far below the real market cost of gas.
4. Repeat across many UserOps during the staleness window to drain the paymaster's EntryPoint deposit at a discount, analogous to `SimplexPaymasterTest.t.sol`'s `testStaleOracleReverts`/`testUpdateParamsTightensOracleAge` tests, which only assert reverts *past* `maxOracleAge`, not protection against a stale-but-in-bound divergence.     function swapAndDeposit(address token, uint256 amountIn) external {
        if (msg.sender != treasury) revert UnauthorizedCall();
        address router = IDispatcher(host()).uniswapV2Router();
        if (router == address(0)) revert InvalidRouter(router);
        TokenConfig memory cfg = tokenConfigs[token];
        if (address(cfg.tokenOracle) == address(0)) revert TokenNotRegistered(token);

        uint256 balance = IERC20(token).balanceOf(address(this));
        if (amountIn == 0 || amountIn > balance) amountIn = balance;

        uint256 nativeUsd = _getOraclePrice(nativeOracle, nativeOracleDecimals);
        uint256 tokenUsd = _getOraclePrice(cfg.tokenOracle, cfg.tokenOracleDecimals);
        uint256 expectedWei = (amountIn * tokenUsd * 1e18) / (nativeUsd * (10 ** cfg.tokenDecimals));
        uint256 amountOutMin = (expectedWei * (10_000 - swapSlippageBps)) / 10_000;

        address[] memory path = new address[](2);
        path[0] = token;
        path[1] = IUniswapV2Router02(router).WETH();

        IERC20(token).forceApprove(router, amountIn);
        uint256[] memory amounts = IUniswapV2Router02(router)
            .swapExactTokensForETH(amountIn, amountOutMin, path, address(this), block.timestamp);

        uint256 deposited = address(this).balance;
        entryPoint().depositTo{value: deposited}(address(this));
        emit FeesRecycled(token, amountIn, amounts[1], deposited);
    }

        if (address(cfg.tokenOracle) == address(0)) revert TokenNotRegistered(tokenAddr);

    function _tokenPrice(TokenConfig memory cfg) internal view returns (uint256) {
        uint256 nativeUsd = _getOraclePrice(nativeOracle, nativeOracleDecimals);
        uint256 tokenUsd = _getOraclePrice(cfg.tokenOracle, cfg.tokenOracleDecimals);

        return (nativeUsd * (10 ** cfg.tokenDecimals) * (10_000 + markupBps)) / (tokenUsd * 10_000);
    }

    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
