The reported bug class is a claim function that computes a reward amount from state but fails to reset the underlying accounting (`lastRewardTime`, `cachedUserRewards`) before transferring, allowing the same reward to be claimed repeatedly.

Checking the closest analogs on alt.fun — `FeeVault.claim()`, `FeeVault.claimProtocol()`, and `FeeVault.sweepDonations()` — all three correctly zero the relevant state variable *before* performing the `safeTransfer`, and the accompanying running totals (`totalAccruedCreator`, `protocolBalance`) are decremented in the same call: [1](#0-0) [2](#0-1) [3](#0-2) 

`claim()` zeroes `creatorBalance[msg.sender]` and decrements `totalAccruedCreator` before transferring, `claimProtocol()` zeroes `protocolBalance` before transferring, and `sweepDonations()` recomputes the sweepable surplus from `balanceOf` minus the backed total on every call (no leftover claimable state persists). All three are also guarded by `nonReentrant`, and this is exercised in the test suite (`test_claim_paysOutAndResetsBalance`, `test_claimProtocol_paysOutAndResets`, `test_sweepDonations_paysSurplusToFeeTo`, `test_claim_reentrancyBlocked`), confirming state is settled in the same transaction as the payout with no re-entrant or repeat-claim window. [4](#0-3) [5](#0-4) 

There is no other claim-style path (`Bonding`, `Zap`, `LPLock`) that computes a payable amount from unresettable accrual state the way `internalRewardsForToken`/`_claimInternalRewards` did in the source report, so the bug class does not map onto any in-scope reachable function here.

    function claim() external nonReentrant returns (uint256 amount) {
        FeeVaultStorage storage $ = _s();
        amount = $.creatorBalance[msg.sender];
        if (amount == 0) revert NothingToClaim();
        $.creatorBalance[msg.sender] = 0;
        $.totalAccruedCreator -= amount;
        $.usdc.safeTransfer(msg.sender, amount);
        emit CreatorFeesClaimed(msg.sender, amount);
    }

    function sweepDonations() external nonReentrant returns (uint256 amount) {
        FeeVaultStorage storage $ = _s();
        uint256 backed = $.totalAccruedCreator + $.protocolBalance;
        uint256 balance = $.usdc.balanceOf(address(this));
        if (balance <= backed) revert NothingToClaim();
        amount = balance - backed;
        address feeTo_ = $.feeTo;
        $.usdc.safeTransfer(feeTo_, amount);
        emit DonationsSwept(feeTo_, amount);
    }

    function test_claim_reentrancyBlocked() public {
        // Redeploy with a malicious USDC that attempts to re-enter `claim()`
        // from inside the outbound transfer.
        ReentrantUsdc hostileUsdc = new ReentrantUsdc();
        FeeVault impl = new FeeVault();
        bytes memory init = abi.encodeCall(FeeVault.initialize, (address(hostileUsdc), feeTo));
        FeeVault hostileVault = FeeVault(address(new ERC1967Proxy(address(impl), init)));
        hostileUsdc.setVault(hostileVault);

        hostileVault.addDepositor(depositor);
        hostileUsdc.mint(address(hostileVault), 100 ether);
        vm.prank(depositor);
        hostileVault.accrue(address(0xbeef), creator, 20 ether, 80 ether, true);

        // Claim succeeds at the outer level; the inner re-entry is caught and
        // swallowed by the hostile USDC. Balance still fully zeroes out.
        vm.prank(creator);
        uint256 claimed = hostileVault.claim();
        assertEq(claimed, 20 ether);
        assertEq(hostileVault.creatorBalance(creator), 0);
        assertEq(hostileUsdc.balanceOf(creator), 20 ether);
