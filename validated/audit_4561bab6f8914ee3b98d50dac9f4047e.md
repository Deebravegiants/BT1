### Title
`Pool::recapitalize` credits cash and pays a "refund" without verifying any tokens were deposited — unprivileged caller can drain pool custody - ([File: contracts/pool/src/ops/recapitalize.rs])

### Summary
The pool's `recapitalize` entrypoint books up to `min(amount, backing_shortfall)` into the cash ledger and transfers `amount - applied` back to the `payer`, trusting that "the controller transfers `amount` into the pool before this call" (`contracts/pool/src/ops/recapitalize.rs:4`). No authentication and no measured balance check enforces that precondition. Analogous to the kernel leaving `sock->sk` dangling on the `pf->create` failure path, the pool leaves a dangling cash-book credit and pays out an unbacked refund when the expected inbound transfer never happened.

### Finding Description
`recapitalize::accounting` performs all state changes before any token flow is verified:

1. It loads the synced market and computes `applied = amount.min(backing_shortfall(&cache))` (`contracts/pool/src/ops/recapitalize.rs:52`).
2. It calls `cache.credit_cash(applied)` and `cache.commit()` (`:57-58`), permanently writing the credit into the cash book.
3. `apply` then executes `outcome.cache.transfer_out(&payer, outcome.refund)` (`:34`), sending `amount - applied` real tokens to the arbitrary `payer` address.

The function never checks the pool's token balance before the refund, and it never requires the `payer` (or anyone) to authorize or perform a deposit. The pool `recapitalize` entrypoint is callable directly by an unprivileged address — the in-repo test calls `t.client().recapitalize(&hub(&t.asset), &payer, &custody)` on a freshly generated `payer` with no auth setup and it succeeds (`contracts/pool/tests/flows.rs:3432`).

### Impact Explanation
Two concrete, unprivileged losses:

- **Theft of user funds (healthy market):** On a solvent market `backing_shortfall == 0`, so `applied == 0` and `refund == amount`. Calling `recapitalize(hub_asset, attacker, pool_balance)` transfers `pool_balance` tokens from pool custody to `attacker` in exchange for nothing — a direct drain.
- **Insolvency / frozen funds (any market):** Even when a shortfall exists, calling with `amount = full custody` pays the refund leg from real reserves while `credit_cash` still inflates the book. `test_unfunded_recapitalize_leaves_the_cash_book_overstating_custody` demonstrates the pool is left with `balance == 0` while `cash >= deposit` (`contracts/pool/tests/flows.rs:3430-3439`), so honest suppliers' withdrawals clear the pool's own liquidity guards and then fail inside the SAC transfer (`:3443-3477`) — permanently freezing their funds behind an overstated book.

### Likelihood Explanation
Single transaction, single unprivileged call: `Pool::recapitalize(hub_asset, payer, amount)` with `payer` = attacker-controlled address and `amount` = desired extraction. No governance, no timing window, no price manipulation needed. The only prerequisite is knowing a `hub_asset` key with pool custody, which is public state.

### Recommendation
Enforce the inbound-transfer invariant inside the pool instead of trusting the caller:

- Measure the pool's token balance before and after (or require a same-transaction deposit), and only credit/refund based on measured received funds; or
- Restrict `recapitalize` to the controller via `require_auth`/caller check and have the controller perform the transfer first; and
- In `accounting`, only `transfer_out` the refund after confirming the pool's custody actually increased by `applied` — i.e., never let `refund` be paid out of pre-existing reserves.

### Proof of Concept
```rust
// Attacker, no funds, no auth beyond the call itself.
let token = token::Client::new(&env, &asset);
let pool_balance = token.balance(&pool);

// On a solvent market: backing_shortfall == 0 => applied == 0, refund == amount.
pool_client.recapitalize(&hub_asset(&asset), &attacker, &pool_balance);

assert_eq!(token.balance(&attacker), pool_balance);
assert_eq!(token.balance(&pool), 0);
// Cash book still shows suppliers' deposits; withdrawals now fail in the SAC.
```

This matches the existing in-repo demonstration `test_unfunded_recapitalize_leaves_the_cash_book_overstating_custody` (`contracts/pool/tests/flows.rs:3408-3483`), which confirms the refund drains custody while the book overstates reserves and subsequent exits revert inside the token transfer.
