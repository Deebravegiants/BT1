### Title
On-orb fraud/liveness detection is stubbed out and always reports "no fraud" - ([File: src/plans/mod.rs])

### Summary
The orb-core signup pipeline exposes a `detect_fraud` step that is documented and wired into the signup flow as the on-device fraud/liveness enforcement gate, but its implementation has been reduced to an unconditional `Ok(false)`, meaning no signup can ever be flagged as fraudulent by this check regardless of the actual biometric/fraud signals produced by the pipeline. This mirrors the zDAO Token analog: the mechanism (state fields, report struct, call sites) is fully scaffolded, but the core enforcement action never executes.

### Finding Description
`Plan::do_signup` calls `self.detect_fraud(orb, debug_report, pipeline.as_ref())` and uses its boolean result to decide `SignupReason::Fraud` vs `SignupReason::Normal`, which subsequently determines whether `enroll_user` proceeds with a successful enrollment path [1](#0-0) .

However, the actual `detect_fraud` implementation short-circuits: after checking that a pipeline exists, the entire body is replaced by a comment and an unconditional `Ok(false)`:
```
// FOSS: WE HAVE DELETED ALL FRAUD CHECKS
Ok(false)
``` [2](#0-1) 

The supporting `fraud_check::Report` type follows the same pattern: `N_FRAUD_CHECKS` is hard-coded to `0`, `fraud_checks()` returns an empty array, and `Report::fraud_detected()` / `fraud_detected_with_config()` therefore always evaluate over zero elements, making them structurally unable to ever return "fraud detected" [3](#0-2) [4](#0-3) .

The `FraudChecks::run()` plan (constructed from a real `biometric_pipeline::Pipeline`) similarly discards its input and always returns an empty `Report {}`:
```
pub fn run(&mut self) -> Report {
    Report {}
}
``` [5](#0-4) 

The `Report` and `FraudCheckResults` structures are still fully wired into `DebugReport` metadata (`fraud_check_report`, `face_identifier_results`, `fraud_check_results`) and uploaded/reported as if they reflect genuine fraud-detection outcomes [6](#0-5) [7](#0-6) . Just as the zDAO Token never calls `_snapshot()` despite the balance-tracking scaffolding being present, this codebase never allows `detect_fraud`/`Report::fraud_detected()` to actually flag fraud despite the full reporting/telemetry scaffolding being present.

### Impact Explanation
Because `fraud_detected` from `detect_fraud` can never be `true`, no signup passing through this on-orb path can ever be classified as `SignupReason::Fraud` via the on-device check. `signup_reason` will always resolve to `Normal` (or `Failure` only if the biometric pipeline itself fails), so enrollment (`enroll_user`) always proceeds down the "normal" signup path regardless of any spoofing, liveness-bypass, or fraud signal that the underlying face-identifier/fraud-engine plans might have computed. This is a concrete fraud/liveness-bypass impact: the on-orb enforcement gate that operators and the specification rely on to reject fraudulent signups is a no-op, silently reporting to telemetry/backend as though checks ran.

### Likelihood Explanation
This is reached on every single signup that completes the biometric pipeline successfully — `detect_fraud` is unconditionally invoked in `do_signup` unless `skip_fraud_checks()` is set, and its result unconditionally feeds into signup classification [1](#0-0) . No attacker action is required beyond reaching the fraud-detection step of a normal signup; the bypass is deterministic and always-on rather than probabilistic.

### Recommendation
Restore real fraud/liveness checks in `detect_fraud` (`src/plans/mod.rs`) and `FraudChecks::run` / `Report` (`src/plans/fraud_check.rs`) so that `N_FRAUD_CHECKS`, `fraud_checks()`, `fraud_checks_strict()`, and `enabled_checks_from_config()` reflect actual evaluated signals from the biometric pipeline, rather than empty arrays. If this stub is intentional for the open-source distribution, ensure the code path is not used in the production/deployed build (e.g., via a feature flag that fails closed rather than open, or by refusing to enroll when fraud checks are unavailable) instead of silently defaulting to "no fraud detected."

### Proof of Concept
1. Complete a signup through the biometric pipeline so that `pipeline` is `Some(...)` in `do_signup`.
2. Regardless of the biometric data quality, spoofing indicators, or any fraud signal that `biometric_pipeline::Pipeline` (face identifier fraud checks, occlusion, etc.) may have captured, `detect_fraud` executes only:
   ```
   let Some(_pipeline) = pipeline else { return Ok(false); };
   // FOSS: WE HAVE DELETED ALL FRAUD CHECKS
   Ok(false)
   ``` [8](#0-7) 
3. `fraud_detected` is therefore always `false`, `signup_reason` resolves to `SignupReason::Normal`, and `enroll_user` is invoked as if no fraud indicators existed [9](#0-8) , completing enrollment for what may be a fraudulent/spoofed signup.

Note: this `detect_fraud`/`fraud_check.rs` stub is explicitly marked in-code as an intentional FOSS redaction ("WE HAVE DELETED ALL FRAUD CHECKS"), so it is uncertain whether this exact no-op behavior is also present in the non-public production build of orb-core; I could not verify that from this repository alone.

impl Report {
    const DATADOG_TAGS: [&'static str; N_FRAUD_CHECKS] = [];

    fn fraud_checks(&self) -> [Option<bool>; N_FRAUD_CHECKS] {
        []
    }

    /// If fraud data are missing, we assume fraud is detected.
    fn fraud_checks_strict(&self) -> [bool; N_FRAUD_CHECKS] {
        self.fraud_checks().map(|v| v.unwrap_or(true))
    }

    fn enabled_checks_from_config(_config: &BackendConfig) -> [bool; N_FRAUD_CHECKS] {
        []
    }

    fn feedback_messages() -> [Option<PipelineFailureFeedbackMessage>; N_FRAUD_CHECKS] {
        []
    }

    /// Get the || result of all fraud checks, but under the Orb configuration.
    /// The end result might be different from the || of all fraud booleans as
    /// we might decide to not block a signup even if it's fraudulent.
    #[must_use]
    pub fn fraud_detected_with_config(
        &self,
        config: &BackendConfig,
    ) -> (bool, Vec<PipelineFailureFeedbackMessage>) {
        let enabled_checks = Self::enabled_checks_from_config(config);
        let fraud_results = self.fraud_checks_strict();
        let feedback_msgs = Self::feedback_messages();

        let feedback: Vec<PipelineFailureFeedbackMessage> = enabled_checks
            .iter()
            .zip(fraud_results.iter())
            .zip(feedback_msgs.iter())
            .filter_map(
                |((&enabled, &result), feedback_msg)| {
                    if enabled && result { feedback_msg.clone() } else { None }
                },
            )
            .collect();

        (!feedback.is_empty(), feedback)
    }

    /// If any fraud check fails or is missing data, fraud is reported.
    #[must_use]
    pub fn fraud_detected(&self) -> bool {
        self.fraud_checks_strict().iter().any(|&v| v)
    }
