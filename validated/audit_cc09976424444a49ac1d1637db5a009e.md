Confirmed: `Pallet::<T>::dispatch_request` in `modules/pallets/ismp/src/impls.rs` accepts any caller-supplied `dest: StateMachine` and unconditionally stores the commitment and escrows the fee, without checking that a consensus client for that destination is actually configured on this host.

### Title
Unvalidated destination state machine on outgoing dispatch permanently strands escrowed relayer fees - (File: modules/pallets/ismp/src/impls.rs)

### Summary
CVE-2016-1954 is a bug class about failing to validate a caller-supplied destination/scheme before committing to using it, allowing side effects at an unintended location. The Hyperbridge analog is `Pallet::<T>::dispatch_request` accepting a `DispatchPost`/`DispatchGet` with an arbitrary `dest: StateMachine` from any pallet/user-facing dispatcher, without verifying the destination is a chain this instance can actually reach (i.e., has a registered consensus client/state machine).

### Finding Description
Any pallet that exposes `IsmpDispatcher::dispatch_request` to end users (e.g. the demo pallets shown in `modules/pallets/demo/src/lib.rs` and `docs/content/developers/polkadot/receiving.mdx`) forwards a caller-controlled `DispatchPost { dest, ... }` down to `modules/pallets/ismp/src/dispatcher.rs::dispatch_request` (lines 92-151), which builds a `PostRequest`/`GetRequest` from the raw `dest` field with no membership check against `host.consensus_clients()` or any known-state-machine list. This is then handed to `Pallet::<T>::dispatch_request` (`modules/pallets/ismp/src/impls.rs:90-121`), which:
- Computes the commitment,
- Pushes the leaf to the offchain MMR (so relayers will pick it up and attempt delivery),
- Inserts `RequestCommitments::<T>::insert(commitment, RequestMetadata { fee, claimed: false, .. })` unconditionally.

At no point is `dest_chain` checked against any consensus client registered on the host (contrast with `modules/ismp/core/src/handlers/request.rs`, which validates `msg.proof.height.id.state_id` via `validate_state_machine` only on the *incoming* path). There is no equivalent gate on the *outgoing* dispatch path in `impls.rs`. [1](#0-0) [2](#0-1) 

### Impact Explanation
A request dispatched to a `StateMachine` value with no corresponding consensus client can never be delivered by any relayer, because no relayer/light client exists to produce state or membership proofs for that chain. The commitment is nonetheless minted into `RequestCommitments`, and if a nonzero fee was supplied, `T::Currency::transfer` escrows the relayer fee into `RELAYER_FEE_ACCOUNT`. Because the request can never be delivered nor (depending on the destination pallet's timeout wiring) reliably timed out through the normal consensus-verified timeout path — a timeout still requires a state/non-membership proof against a real state machine, which does not exist for an unconfigured destination — the escrowed fee and any downstream funds tied to the message become effectively permanently frozen. This matches the "route unable to deliver messages" / "permanent freezing of funds" acceptance criteria.

### Likelihood Explanation
Any unprivileged user of a pallet built on top of `IsmpDispatcher` (the demo pallet pattern shown in the docs and in `modules/pallets/demo/src/lib.rs` is representative of how downstream pallets are expected to wire this) can trigger this by simply passing an arbitrary/unsupported `StateMachine` variant/id as `dest` in a single signed extrinsic. No special privilege, governance, or malicious relayer/collator role is required — it is reachable directly from `dispatch_request`, an unprivileged message-dispatcher path explicitly in scope.

### Recommendation
In `Pallet::<T>::dispatch_request` (or earlier, in `modules/pallets/ismp/src/dispatcher.rs::dispatch_request`), validate that `dest_chain` corresponds to a configured consensus client / known state machine (e.g., by consulting `host.consensus_clients()` the same way `check_state_machine_client` does in `modules/ismp/core/src/handlers/request.rs:40-45`) before collecting fees, writing to the offchain MMR, or inserting into `RequestCommitments`. Reject the dispatch with a clear error (e.g. `UnknownDestinationStateMachine`) if no client is registered for the destination.

### Proof of Concept
1. Deploy/instantiate a downstream pallet that exposes `dispatch_request` to signed users (pattern identical to `dispatch_to_evm` in `modules/pallets/demo/src/lib.rs:216-239`).
2. Submit a signed extrinsic with `DispatchPost { dest: StateMachine::Evm(999999 /* unregistered chain id */), from, to, timeout, body }` and a nonzero fee.
3. Observe: `T::Currency::transfer` moves the fee into `RELAYER_FEE_ACCOUNT` and `RequestCommitments::<T>::insert` succeeds — no error is raised despite no consensus client existing for `StateMachine::Evm(999999)`.
4. No relayer can ever produce a valid proof for this destination, so the request is never delivered, and (absent an out-of-band manual remediation) the escrowed fee remains locked indefinitely. [3](#0-2) [4](#0-3) [5](#0-4)

	pub fn dispatch_request(request: Request, meta: FeeMetadata<T>) -> Result<H256, ismp::Error> {
		let commitment = hash_request::<Pallet<T>>(&request);

		if RequestCommitments::<T>::contains_key(commitment) {
			Err(ismp::Error::Custom("Duplicate request".to_string()))?
		}

		let (dest_chain, source_chain, nonce) =
			(request.dest_chain(), request.source_chain(), request.nonce());
		let leaf_index_and_pos = T::OffchainDB::push(Leaf::Request(request));
		// Deposit Event
		Pallet::<T>::deposit_event(Event::Request {
			request_nonce: nonce,
			source_chain,
			dest_chain,
			commitment,
		});

		RequestCommitments::<T>::insert(
			commitment,
			RequestMetadata {
				offchain: LeafIndexAndPos {
					leaf_index: leaf_index_and_pos.index,
					pos: leaf_index_and_pos.position,
				},
				fee: meta,
				claimed: false,
			},
		);

		Ok(commitment)
	}

	fn dispatch_request(
		&self,
		request: DispatchRequest,
		fee: FeeMetadata<T>,
	) -> Result<H256, anyhow::Error> {
		// collect payment for the request
		if fee.fee != Zero::zero() {
			T::Currency::transfer(
				&fee.payer,
				&RELAYER_FEE_ACCOUNT.into_account_truncating(),
				fee.fee,
				Preservation::Expendable,
			)
			.map_err(|err| IsmpError::Custom(format!("Error withdrawing request fees: {err:?}")))?;
		}

		let request = match request {
			DispatchRequest::Get(dispatch_get) => {
				let get = GetRequest {
					source: self.host_state_machine(),
					dest: dispatch_get.dest,
					nonce: self.next_nonce(),
					from: dispatch_get.from,
					keys: dispatch_get.keys,
					height: dispatch_get.height,
					context: dispatch_get.context,
					timeout_timestamp: if dispatch_get.timeout == 0 {
						0
					} else {
						<T::TimestampProvider as UnixTime>::now()
							.as_secs()
							.saturating_add(dispatch_get.timeout)
					},
				};
				Request::Get(get)
			},
			DispatchRequest::Post(dispatch_post) => {
				let post = PostRequest {
					source: self.host_state_machine(),
					dest: dispatch_post.dest,
					nonce: self.next_nonce(),
					from: dispatch_post.from,
					to: dispatch_post.to,
					timeout_timestamp: if dispatch_post.timeout == 0 {
						0
					} else {
						<T::TimestampProvider as UnixTime>::now()
							.as_secs()
							.saturating_add(dispatch_post.timeout)
					},
					body: dispatch_post.body,
				};
				Request::Post(post)
			},
		};

		let commitment = Pallet::<T>::dispatch_request(request, fee)?;

		Ok(commitment)
	}
