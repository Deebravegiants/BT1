### Title
HyperbridgeLzEndpoint has no `receive()`/`fallback()` payable function despite relying on the Uniswap router to refund excess native fees, causing native-fee dispatches to revert and permanently lock/DoS message delivery - (File: sdk/packages/lz-endpoint/contracts/HyperbridgeLzEndpoint.sol)

### Summary
`HyperbridgeLzEndpoint` computes and forwards native value for cross-chain dispatch fees and explicitly documents that "Excess native is refunded by the uniswap router" [1](#0-0) , yet, unlike every other contract in this codebase that participates in native-ETH flows (`IntentGatewayV2`, `CallDispatcher`, `EvmHost`, `HostManager`, `SimplexPaymaster`, all `UniswapV2Wrapper` variants, `WrappedHyperFungibleToken(Upgradeable)`), it contains no `receive()` or `fallback()` payable function to accept that refund.

### Finding Description
Across the Hyperbridge EVM contracts, any contract that can end up on the receiving side of an unsolicited native-token transfer — because it forwards `msg.value` to a router/host that may refund unused native — implements `receive() external payable {}` (or a restricted variant). Examples: `IntentGatewayV2.sol` [2](#0-1) , `CallDispatcher.sol` [3](#0-2) , `SimplexPaymaster.sol` [4](#0-3) , and the Uniswap wrapper contracts [5](#0-4) .

`HyperbridgeLzEndpoint.sol`, however, quotes messaging fees with "a generous 2x buffer to absorb the legacy deployed host's per-byte protocol fee," explicitly relying on the fact that "Excess native is refunded by the uniswap router" when `payInLzToken` is false [1](#0-0) . This mirrors the `IntentGatewayV2`/`ExtrinsicIntents` pattern where `swapETHForExactTokens{value: msgValue}` is invoked and unspent ETH is sent back to the caller [6](#0-5) ; in that pattern the caller (the gateway contract itself) is protected by its own `receive()`. `HyperbridgeLzEndpoint` performs the analogous forwarding of `msg.value`/native fees into the host/dispatch path but has no `receive()`/`fallback()` anywhere in the file (confirmed absent by direct search) despite having 119 references to `msg.value`, native fee handling, and WETH/router-related logic.

### Impact Explanation
If the endpoint contract itself is the address that receives the router's or host's ETH refund (analogous to how `IntentGatewayV2` receives its own excess-ETH refund via `receive()`), that refund transfer will revert because there is no payable fallback to accept it. Since the refund happens as part of the same dispatch transaction (not a separate call), this reverts the entire `lzSend`/dispatch operation, meaning any OApp message that pays its native cross-chain fee through this endpoint with excess value supplied would permanently fail to be dispatched — a denial-of-service on the LayerZero-compatible messaging path routed through Hyperbridge. If, instead, the ETH is trapped as `address(this).balance` rather than reverting (depending on exact call site), the value becomes permanently stuck/unrecoverable native token, since no sweep/receive mechanism exists for it in this contract.

### Likelihood Explanation
Any unprivileged caller triggering `lzSend`-style dispatch that pays the native messaging fee with any surplus (a very common client pattern, matching the buffer/quote pattern the code itself documents) will encounter this path. This requires no special privileges — a single ordinary user transaction dispatching a LayerZero-compatible message through the Hyperbridge endpoint is sufficient to trigger it.

### Recommendation
Add a `receive() external payable {}` (optionally restricted to trusted senders such as the configured Uniswap router/WETH address, following the pattern used in `UniV3UniswapV2Wrapper.sol` and `UniV4UniswapV2Wrapper.sol`) to `HyperbridgeLzEndpoint.sol` so that native-token refunds from the fee-swap/dispatch path can be accepted without reverting, and ensure any accepted excess is forwarded back to the original caller rather than trapped in the contract.

### Proof of Concept
1. A user or OApp calls the endpoint's send/dispatch function with `payInLzToken = false`, supplying `nativeFee = quote(request) * 2` as computed by `HyperbridgeLzEndpoint` [1](#0-0) .
2. Internally the dispatch path (mirroring `IntentGatewayV2`'s fee-swap logic) swaps native value for the fee token via the Uniswap router, expecting unused native to be refunded to the caller of that swap (the endpoint contract).
3. Because `HyperbridgeLzEndpoint.sol` has no `receive()`/`fallback()` payable function, the refund transfer fails, reverting the whole transaction and preventing message dispatch — or, depending on where the refund lands, leaving native ETH permanently stuck in the contract with no recovery mechanism.
