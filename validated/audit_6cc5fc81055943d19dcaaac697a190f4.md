No exploitable admission bypass in CSR approval subresource guard - ([File: plugin/pkg/admission/certificates/approval/admission.go])

### Summary
The proposed attack requires crafting a request whose `RequestInfo.Subresource` and `GroupResource` are decoupled from the actual API path being served, but subresource and group/resource are derived deterministically by the apiserver's request routing (`RequestInfoFactory`) from the URL path before admission ever runs, not attacker-suppliable independent of the URL. There is no code path by which a genuine main-resource UPDATE to `certificatesigningrequests/<name>` can present `GetSubresource() == "approval"` to admission, so the guard cannot be bypassed via aliasing.

### Finding Description
The admission plugin's `Validate` at `plugin/pkg/admission/certificates/approval/admission.go` lines 78-81 only inspects `a.GetSubresource()` and `a.GetResource().GroupResource()`, which come from `admission.Attributes` populated from the parsed `RequestInfo` for the actual REST path invoked (`/apis/certificates.k8s.io/v1/certificatesigningrequests/<name>` vs `.../approval`). The apiserver routes these to distinct REST storage handlers (`Strategy` vs `ApprovalStrategy`) based on path, and `RequestInfo.Subresource`/`Resource` are not independently attacker-controlled fields that can be "aliased" while still invoking the approval endpoint's semantics. Even hypothesizing a routing confusion were possible, the main-resource update path is protected independently: `csrStrategy.PrepareForUpdate` in `pkg/registry/certificates/certificates/strategy.go` (lines 105-111) unconditionally sets `newCSR.Status = oldCSR.Status`, discarding any attacker-supplied `status.conditions` on a plain (non-subresource) UPDATE before validation/persistence, confirmed by `TestStrategyCreate`/strategy tests in `pkg/registry/certificates/certificates/strategy_test.go`. So even a hypothetical admission skip would not result in a persisted Approved condition via the main-resource path.

### Impact Explanation
No impact: the described bypass is not reachable, and existing defense-in-depth (`PrepareForUpdate` status stripping on the main resource) independently prevents any status/condition mutation via non-approval-subresource updates.

### Likelihood Explanation
Not applicable — the precondition (crafting a request that reports subresource "approval" while actually being routed as the main resource, or vice versa) does not exist in the routing/admission architecture; `RequestInfo` subresource parsing is derived from the URL path itself, not an independently spoofable attribute.

### Recommendation
No code change required for this specific concern. func (p *Plugin) Validate(ctx context.Context, a admission.Attributes, _ admission.ObjectInterfaces) error {
	// Ignore all calls to anything other than 'certificatesigningrequests/approval'.
	// Ignore all operations other than UPDATE.
	if a.GetSubresource() != "approval" ||
		a.GetResource().GroupResource() != csrGroupResource {
		return nil
	}

	// We check permissions against the *old* version of the resource, in case
	// a user is attempting to update the SignerName when calling the approval
	// endpoint (which is an invalid/not allowed operation)
	csr, ok := a.GetOldObject().(*api.CertificateSigningRequest)
	if !ok {
		return admission.NewForbidden(a, fmt.Errorf("expected type CertificateSigningRequest, got: %T", a.GetOldObject()))
	}

	if !certauthorization.IsAuthorizedForSignerName(ctx, p.authz, a.GetUserInfo(), "approve", csr.Spec.SignerName) {

		return admission.NewForbidden(a, fmt.Errorf("user not permitted to approve requests with signerName %q", csr.Spec.SignerName))
	}

	return nil
}

// PrepareForUpdate clears fields that are not allowed to be set by end users
// on update. Certificate requests are immutable after creation except via subresources.
func (csrStrategy) PrepareForUpdate(ctx context.Context, obj, old runtime.Object) {
	newCSR := obj.(*certificates.CertificateSigningRequest)
	oldCSR := old.(*certificates.CertificateSigningRequest)

	newCSR.Spec = oldCSR.Spec
	newCSR.Status = oldCSR.Status
}

func (csrApprovalStrategy) PrepareForUpdate(ctx context.Context, obj, old runtime.Object) {

	populateConditionTimestamps(newCSR, oldCSR)

	// Updating the approval should only update the conditions.
