Audit Report

## Title
Compressed/hashed downward messages advance `LastProcessedDownwardMessage` without ever being dispatched to `DmpQueue`, permanently orphaning them - (File: cumulus/pallets/parachain-system/src/lib.rs, cumulus/pallets/parachain-system/src/parachain_inherent.rs)

## Summary
`into_abridged` splits pending DMQ messages into `full_messages` and `hashed_messages` once a size budget is exceeded, but only `full_messages` are ever handed to `T::DmpQueue::handle_messages` via `bounded_msgs_iter()`. `enqueue_inbound_downward_messages`, however, folds both categories into the MQC hash chain and advances `LastProcessedDownwardMessage` past the hashed messages as well, so on the next block `do_create_inherent`'s call to `drop_processed_messages` discards those messages before they can ever be resubmitted in full, permanently orphaning them.

## Finding Description
`into_abridged` (cumulus/pallets/parachain-system/src/parachain_inherent.rs:122-142) splits messages by a size budget into `full_messages` (kept) and `hashed_messages` (hash-only). `bounded_msgs_iter()` (parachain_inherent.rs:249-265), which feeds `T::DmpQueue::handle_messages` in `enqueue_inbound_downward_messages` (cumulus/pallets/parachain-system/src/lib.rs:1354), only iterates `full_messages`. Yet the loop that computes `last_processed_msg`/`LastProcessedDownwardMessage` (lib.rs:1343-1352) iterates `hashed_messages` too, advancing the on-chain watermark past messages that were never dispatched. `check_enough_messages_included_basic` (parachain_inherent.rs:172-184) — the only check invoked at lib.rs:1323 — merely requires at least one full message when any hashed messages are present; it does not constrain which specific messages get hashed, and `check_enough_messages_included_advanced` (parachain_inherent.rs:192-218), which would enforce "as many full messages as possible," is not called from the on-chain enqueue path. On the following block, `do_create_inherent` (lib.rs:1284-1308) calls `drop_processed_messages` using this watermark against the freshly fetched DMQ contents, discarding the previously hashed messages before they can be resubmitted with full data. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4) 

The "DMQ head mismatch" assertion (lib.rs:1362) does not prevent this: it only verifies that the submitted collection (full + hashed) hashes to the correct MQC head, which is fully satisfiable while still hashing arbitrary messages instead of including them in full — the assertion checks integrity of the MQC chain, not whether messages were actually dispatched for execution.

## Impact Explanation
Any DMP message — including an XCM reserve-transfer or teleport carrying real value — that ends up in `hashed_messages` instead of `full_messages` is permanently unexecuted on the parachain, since the watermark used by `drop_processed_messages` on the next block will discard it before it can be resubmitted in full. This constitutes a concrete, non-reversible loss of the corresponding cross-chain transfer since it cannot be replayed once the local watermark has advanced past it.

## Likelihood Explanation
Since the on-chain enqueue path only enforces `check_enough_messages_included_basic` (requiring at least one full message when hashed messages exist) and not `check_enough_messages_included_advanced`, a malicious collator — who fully controls the `InboundMessagesData`/`AbridgedInboundDownwardMessages` submitted as part of the `set_validation_data` inherent — can choose to place a specific target message (e.g., a reserve-transfer) into `hashed_messages` while satisfying the MQC and basic-check constraints, without needing to rely on genuinely exhausting `remaining_block_weight()`. This makes the attack directly and reliably triggerable by any block-producing collator in a single block, with no signature forgery or origin bypass required.

## Recommendation
Track two separate watermarks (or per-message flags) distinguishing "included in the MQC hash chain" from "actually dispatched to `DmpQueue`." Do not advance `LastProcessedDownwardMessage` (and do not allow `drop_processed_messages` to discard) hashed messages until they have been resubmitted in full and processed by `T::DmpQueue`. Additionally, enforce `check_enough_messages_included_advanced` (or an equivalent on-chain constraint) in `enqueue_inbound_downward_messages` so a collator cannot arbitrarily choose which messages to hash independent of the actual size budget.

## Proof of Concept
Add an integration test in `cumulus/pallets/parachain-system/src/tests.rs`:
1. Build a relay sproof whose `dmq_mqc_head` covers N downward messages; construct an `AbridgedInboundDownwardMessages` where a specific target message (e.g., index k) is placed into `hashed_messages` instead of `full_messages`, while keeping at least one full message to satisfy `check_enough_messages_included_basic`, and ensuring the MQC hash still matches (using `extend_downward`/`extend_with_hashed_msg` correctly).
2. Submit the block; assert the inherent succeeds (no "DMQ head mismatch" panic) and `LastProcessedDownwardMessage` advances past message k.
3. Assert `HANDLED_DMP_MESSAGES` (mirroring `T::DmpQueue::handle_messages` calls) does not contain message k.
4. Run a subsequent block that re-fetches the same DMQ contents (simulating the relay chain not pruning them because `ProcessedDownwardMessages` only counted full messages) and assert message k is dropped by `drop_processed_messages` in `do_create_inherent` without ever appearing in `HANDLED_DMP_MESSAGES` — proving permanent orphaning.

	pub fn into_abridged(
		self,
		size_limit: &mut usize,
	) -> AbridgedInboundMessagesCollection<Message> {
		let mut messages = self.messages;

		let mut split_off_pos = messages.len();
		for (idx, message) in messages.iter().enumerate() {
			if *size_limit < message.data().len() {
				break;
			}
			*size_limit -= message.data().len();

			split_off_pos = idx + 1;
		}

		let extra_messages = messages.split_off(split_off_pos);
		let hashed_messages = extra_messages.iter().map(|msg| msg.to_compressed()).collect();

		AbridgedInboundMessagesCollection { full_messages: messages, hashed_messages }
	}

	/// Check that the current collection contains at least 1 full message if needed.
	pub fn check_enough_messages_included_basic(&self, collection_name: &str) {
		if self.hashed_messages.is_empty() {
			return;
		}

		// Here we just check that there is at least 1 full message.
		assert!(
			self.full_messages.len() >= 1,
			"[{}] Advancement rule violation: full messages missing",
			collection_name,
		);
	}

	/// Check that the current collection contains as many full messages as possible, taking into
	/// consideration the collection constraints.
	///
	/// The `AbridgedInboundMessagesCollection` is provided to the runtime by a collator.
	/// A malicious collator can provide a collection that contains no full messages or fewer
	/// full messages than possible, leading to censorship.
	pub fn check_enough_messages_included_advanced(
		&self,
		collection_name: &str,
		size_info: AbridgedInboundMessagesSizeInfo,
	) {
		// We should check that the collection contains as many full messages as possible
		// without exceeding the max expected size.
		let AbridgedInboundMessagesSizeInfo { max_full_messages_size, first_hashed_msg_max_size } =
			size_info;

		let mut full_messages_size = 0usize;
		for msg in &self.full_messages {
			full_messages_size = full_messages_size.saturating_add(msg.data().len());
		}

		// The worst case scenario is that were the first message that had to be hashed
		// is a max size message.
		assert!(
			full_messages_size.saturating_add(first_hashed_msg_max_size) > max_full_messages_size,
			"[{}] Advancement rule violation: full messages size smaller than expected. \
			full msgs size: {}, first hashed msg max size: {}, max full msgs size: {}",
			collection_name,
			full_messages_size,
			first_hashed_msg_max_size,
			max_full_messages_size
		);
	}

impl AbridgedInboundDownwardMessages {
	/// Returns an iterator over the messages that maps them to `BoundedSlices`.
	pub fn bounded_msgs_iter<MaxMessageLen: Get<u32>>(
		&self,
	) -> impl Iterator<Item = BoundedSlice<'_, u8, MaxMessageLen>> {
		self.full_messages
			.iter()
			// Note: we are not using `.defensive()` here since that prints the whole value to
			// console. In case that the message is too long, this clogs up the log quite badly.
			.filter_map(|m| match BoundedSlice::try_from(&m.msg[..]) {
				Ok(bounded) => Some(bounded),
				Err(_) => {
					defensive!("Inbound Downward message was too long; dropping");
					None
				},
			})
	}

		let (data, mut downward_messages, mut horizontal_messages) =
			deconstruct_parachain_inherent_data(data);
		let last_relay_block_number = LastRelayChainBlockNumber::<T>::get();

		let messages_collection_size_limit = Self::messages_collection_size_limit();
		// DMQ.
		let last_processed_msg = LastProcessedDownwardMessage::<T>::get()
			.unwrap_or(InboundMessageId { sent_at: last_relay_block_number, reverse_idx: 0 });
		downward_messages.drop_processed_messages(&last_processed_msg);
		let mut size_limit = messages_collection_size_limit;
		let downward_messages = downward_messages.into_abridged(&mut size_limit);

		// HRMP.
		let last_processed_msg = LastProcessedHrmpMessage::<T>::get()
			.unwrap_or(InboundMessageId { sent_at: last_relay_block_number, reverse_idx: 0 });
		horizontal_messages.drop_processed_messages(&last_processed_msg);
		size_limit = size_limit.saturating_add(messages_collection_size_limit);
		let horizontal_messages = horizontal_messages.into_abridged(&mut size_limit);

		let inbound_messages_data =
			InboundMessagesData::new(downward_messages, horizontal_messages);

		Call::set_validation_data { data, inbound_messages_data }
	}

	fn enqueue_inbound_downward_messages(
		expected_dmq_mqc_head: relay_chain::Hash,
		downward_messages: AbridgedInboundDownwardMessages,
	) -> Weight {
		downward_messages.check_enough_messages_included_basic("DMQ");

		let mut dmq_head = <LastDmqMqcHead<T>>::get();

		let (messages, hashed_messages) = downward_messages.messages();
		let message_count = messages.len() as u32;
		let weight_used = T::WeightInfo::enqueue_inbound_downward_messages(message_count);
		if let Some(last_msg) = messages.last() {
			Self::deposit_event(Event::DownwardMessagesReceived { count: message_count });

			// Eagerly update the MQC head hash:
			for msg in messages {
				dmq_head.extend_downward(msg);
			}
			<LastDmqMqcHead<T>>::put(&dmq_head);
			Self::deposit_event(Event::DownwardMessagesProcessed {
				weight_used,
				dmq_head: dmq_head.head(),
			});

			let mut last_processed_msg =
				InboundMessageId { sent_at: last_msg.sent_at, reverse_idx: 0 };
			for msg in hashed_messages {
				dmq_head.extend_with_hashed_msg(msg);

				if msg.sent_at == last_processed_msg.sent_at {
					last_processed_msg.reverse_idx += 1;
				}
			}
			LastProcessedDownwardMessage::<T>::put(last_processed_msg);

			T::DmpQueue::handle_messages(downward_messages.bounded_msgs_iter());
		}

		// After hashing each message in the message queue chain submitted by the collator, we
		// should arrive to the MQC head provided by the relay chain.
		//
		// A mismatch means that at least some of the submitted messages were altered, omitted or
		// added improperly.
		assert_eq!(dmq_head.head(), expected_dmq_mqc_head, "DMQ head mismatch");

		ProcessedDownwardMessages::<T>::put(message_count);

		weight_used
	}
