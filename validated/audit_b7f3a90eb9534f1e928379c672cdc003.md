Confirmed: `HttpClient#initialize` builds `@base_uri = "https://#{api_host || session.shop}"` directly from `session.shop` with no further validation [1](#0-0) , and `client_secret` is placed in the POST body sent to that URI in the token-exchange flow [2](#0-1) .

### Title
Unsanitized JWT `dest` claim used to build the token-exchange host that receives `client_secret` - (File: lib/shopify_api/auth/token_exchange.rb)

### Summary
`TokenExchange.exchange_token` builds the outbound OAuth host from `jwt_payload.shop` (the JWT `dest` claim) without ever passing it through `Utils::ShopValidator.sanitize!`, unlike every sibling credential-bearing flow in the same file/module.

### Finding Description
`JwtPayload#shop` is derived by naively stripping `"https://"` from the `dest` claim with no format constraint: `@dest.gsub("https://", "")` [3](#0-2) . `JwtPayload#initialize` only validates the signature and `aud == Context.api_key`; it never checks that `dest`/`iss` is a trusted `*.myshopify.com` (or configured) domain [4](#0-3) .

`exchange_token` takes this unvalidated value straight as `dest_shop` and uses it to build the session whose `shop` attribute becomes the request host: `shop_session = ShopifyAPI::Auth::Session.new(shop: dest_shop)` then `Clients::HttpClient.new(session: shop_session, base_path: "/admin/oauth")` [5](#0-4) . `HttpClient` turns `session.shop` directly into `@base_uri = "https://#{session.shop}"` [1](#0-0) , and the POST body carrying `client_secret` is sent to that exact URI [6](#0-5) .

Contrast this with the three sibling flows in the very same module/neighboring files, which all call `Utils::ShopValidator.sanitize!(shop)` before building the credential-bearing request:
- `TokenExchange.migrate_to_expiring_token` [7](#0-6) 
- `RefreshToken.refresh_access_token` [8](#0-7) 
- `ClientCredentials.client_credentials` [9](#0-8) 

`ShopValidator.sanitize!` enforces that the host is a subdomain of a small `TRUSTED_SHOPIFY_DOMAINS` list (`shopify.com`, `myshopify.io`, `myshopify.com`, `spin.dev`, `shop.dev`), raising `InvalidShopError` otherwise [10](#0-9) . This exact check is bypassed in `exchange_token`, breaking the intended equality "host that receives `client_secret` == a validated Shopify domain."

The identity binding that should hold is: `host receiving client_secret == ShopValidator.sanitize!(shop-claim)`. Before the request, this equality is violated because `dest_shop` is used raw; after the fix (as done in the other three call sites), it is enforced.

### Impact Explanation
If the `dest` claim inside a session token can ever be a non-myshopify string (e.g., due to a misconfigured/legacy environment, a proxy that forwards a modified session token, or any code path that constructs a `JwtPayload`/session with attacker-influenced `dest` before this call), the gem will happily POST the app's `client_id` and `client_secret` to that arbitrary host — an SSRF that exfiltrates the app's own OAuth credentials to a third party, matching the High-impact category "SSRF with the app's credentials" / credential leakage.

### Likelihood Explanation
Low-to-Medium. In the normal, fully-trusted flow, session tokens are minted and signed by Shopify itself, so `dest` is expected to always be a legitimate shop domain — meaning this specific path is not directly triggerable by an unprivileged attacker without already controlling a signed session token or an upstream component that forwards attacker-supplied `dest` values. However, it is a real defense-in-depth gap: the library itself provides `ShopValidator` for exactly this purpose and applies it consistently everywhere except this one spot, so any environment where the `dest` claim's trustworthiness assumption is weaker (proxies, custom App Bridge integrations, test/staging shops using non-`.myshopify.com` names) turns this into an exploitable SSRF leaking `client_secret`.

### Recommendation
Apply `Utils::ShopValidator.sanitize!(dest_shop)` in `TokenExchange.exchange_token` before constructing `shop_session`/`HttpClient`, mirroring `migrate_to_expiring_token`, `refresh_access_token`, and `client_credentials`, so that the host receiving `client_id`/`client_secret` is always constrained to `ShopValidator::TRUSTED_SHOPIFY_DOMAINS`.

### Proof of Concept
1. Obtain or construct a session token whose `dest` claim is set to an attacker-controlled value not restricted to `*.myshopify.com` (any pathway that produces a `JwtPayload` with a non-Shopify `dest`, e.g. a compromised/looser upstream verifier, or a future code path that trusts an externally supplied token before full validation).
2. Call `ShopifyAPI::Auth::TokenExchange.exchange_token(session_token: token, requested_token_type: ...)`.
3. `dest_shop` is taken from the unsanitized `dest` claim and directly becomes `session.shop`.
4. `Clients::HttpClient` builds `https://#{dest_shop}` as the base URI and issues `POST https://#{dest_shop}/admin/oauth/access_token` with body containing `client_id` and `client_secret` in plaintext JSON — sending the app's credentials to the attacker-chosen host.

        [
          "shopify.com",
          "myshopify.io",
          "myshopify.com",
          "spin.dev",
          "shop.dev",

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
