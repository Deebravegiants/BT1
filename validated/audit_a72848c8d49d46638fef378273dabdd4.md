## Title
Flash-loan-inflatable balance weighting lets a solver dictate the published `LiquidityPool.buyRate`/`sellRate` used to price real IntentGateway swaps - (File: `sdk/packages/sdk/src/protocols/intents/phantom-aggregation.ts`)

### Summary
`aggregatePhantomBids` weights every phantom bid by a live, unpinned-to-bid-time on-chain balance read (`getTotalSolverBalance` / `getBalance`, defaulting to `blockTag = "latest"`), and `weightedMedian` then *selects* one bidder's exact price verbatim whenever that bidder holds over half the total weight for a leg [1](#0-0) . This is structurally the same class of bug as the xWin Finance incident: a reward/weighting formula scales linearly with a balance/liquidity amount that the actor can inflate instantaneously and temporarily (e.g. via a flash loan) around the exact snapshot moment, then withdraw immediately after, capturing an outsized influence on-chain state for the cost of one transaction.

### Finding Description
The weighted-median price selection is not a "blend" but a **selection** — the bidder holding over half the leg's inventory weight sets `medianPrice` (and `lowestPrice`/`highestPrice`, which are overwritten to match it) verbatim [2](#0-1) . The weight is the solver's redeemable ERC-20 + ERC-4626 vault balance of the leg's output token, read live from the destination chain via `getTotalSolverBalance`, which defaults to `blockTag = "latest"` [3](#0-2) . In the periodic-sweep path (`memoizedSolverBalance`), balances are similarly read at head rather than pinned to the moment the bid was actually made.

A solver that can borrow (flash-loan) the leg's output token on the destination EVM chain, hold it in its wallet or a configured vault for the single block/moment the aggregation runs, and repay it afterward, can dominate the weight computation and force `weightedMedian` to publish its own quoted price as the pool's `medianPrice`. This published price then propagates via `updateLiquidityPools`/`poolRateFromQuote` into the pool's authoritative `sellRate`/`buyRate` [4](#0-3) , which `IndexedRateIntentQuoteStrategy.quote` uses directly to price real `IntentGateway` orders for every subsequent trader — with no other price source or fallback [5](#0-4) .

Exactly like xWin Finance's reward mechanism scaling unboundedly with transient liquidity added via flash loan, this pricing mechanism scales unboundedly with transient balance an attacker can manufacture for the cost of a single flash-loan transaction, defeating the "inventory that actually backs the leg" assumption the design otherwise relies on.

### Impact Explanation
An attacker-controlled published rate directly prices real user swaps through `IntentGateway.quoteIntent`/`executeBest` — a manipulated `sellRate`/`buyRate` can be pushed arbitrarily favorable to the attacker's own subsequent order, or unfavorable enough to grief other traders/solvers, resulting in fund loss for users who accept quotes built on the poisoned rate. This satisfies "unsound state commitment"/"unbacked" pricing feeding real value transfer, reachable from a single flash-loan transaction plus one signed phantom bid — no privileged access required.

### Likelihood Explanation
Medium: it requires (1) flash-loan liquidity available for the target output token on the destination chain, (2) a live `SolverAccount` delegation and valid signed `UserOperation` bid (achievable by any address, since bids are permissionless and only require passing `isVerifiedSolverBid`), and (3) timing the loan around `PhantomBidWindowExhausted`/the periodic sweep's live balance read. These are all realistic for a motivated, well-funded actor and require no insider access, matching the flash-loan-attack pattern in the reference incident.

### Recommendation
Pin the balance read used for weighting to a block *before* the bid window opened (or to the block at which the bid's `UserOperation` was actually submitted/signed), rather than defaulting to `blockTag = "latest"` at aggregation time. Alternatively, require a time-locked/vested minimum holding period, or cap a single solver's weight contribution to a fixed fraction of total quoted weight so no single bidder can force the median outright.

### Proof of Concept
1. Attacker deploys a `SolverAccount`/is delegated on the destination chain and signs a phantom bid `UserOperation` quoting an extreme (self-favorable) price for a leg's output token, satisfying `isVerifiedSolverBid`.
2. Shortly before `PhantomBidWindowExhausted` fires (or before the periodic sweep re-reads balances), attacker flash-loans a large amount of the leg's output token into their solver wallet/ERC-4626 vault position.
3. `aggregatePhantomBids` runs, calls `getTotalSolverBalance`/`getBalance` at `latest`, sees the inflated balance, and the attacker's bid weight exceeds half of total weight for that leg.
4. `weightedMedian` returns the attacker's bid price verbatim as `medianPrice`; `updateLiquidityPools` merges it into the pool's `sellRate`/`buyRate`.
5. Attacker repays the flash loan in the same transaction.
6. Attacker (or an accomplice) immediately calls `quoteIntent`/places a real `IntentGateway` order priced off the now-poisoned `sellRate`/`buyRate`, extracting value at the expense of the counterparty solver/user who accepts the manipulated rate.

export async function getTotalSolverBalance(
	evmRpcUrl: string,
	chain: string,
	token: string,
	solver: string,
	yieldVaults: YieldVaultMap,
	blockTag = "latest",
): Promise<bigint> {
	const padded = solver.replace("0x", "").padStart(64, "0")
	const raw = await ethCallUint(evmRpcUrl, token, `0x70a08231${padded}`, blockTag) // balanceOf(address)
	const vaults = yieldVaults[chain]?.[token.toLowerCase()] ?? []
	const vaultBalances = await Promise.all(
		vaults.map((v) => ethCallUint(evmRpcUrl, v, `0xce96cb77${padded}`, blockTag)), // maxWithdraw(address)
	)
	return vaultBalances.reduce((acc, b) => acc + b, raw)
}

export function poolRateFromQuote(
	medianPrice: bigint,
	resolved: Pick<ResolvedPoolLeg, "inDecimals" | "outDecimals">,
	standardAmount: bigint,
): bigint {
	const scale = 10n ** BigInt(POOL_RATE_DECIMALS - resolved.outDecimals)
	const inputUnit = 10n ** BigInt(resolved.inDecimals)
	return (medianPrice * scale * inputUnit) / standardAmount
}
