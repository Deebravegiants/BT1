### Title
Liquidation quote promotion leaves a coverage gap: every `liquidate` offer reverts for a solvent account whose only supply leg is a whole-unit sub-3-decimal asset in a narrow debt band - (File: contracts/controller/src/positions/liquidation/math.rs)

### Summary
The reported bug class is an input validator (a regex) that rejects a legitimate input representation (`0x`-prefixed keys), and two overlapping validators that should be merged but together leave a gap. The on-chain analog in XOXNO Lending is `whole_unit_repayment`, the "merged" quote-promotion rule for solvent accounts whose only supply position is a collateral token below `MIN_BORROWABLE_ASSET_DECIMALS` (3 decimals). Its two promotion rules are written as complementary conditions over the debt `D`, but they are not exhaustive: a band of debt values satisfies neither rule, and in that band no liquidator offer can ever execute. The unprivileged `liquidate` entrypoint therefore reverts on every call for a live, below-HF-1 account, temporarily freezing liquidation of that debt while interest accrues.

### Finding Description
`whole_unit_repayment` (`contracts/controller/src/positions/liquidation/math.rs:235-291`) adjusts the partial-liquidation quote for accounts that hold a single supply position in a sub-3-decimal asset with at least one whole unit:

- Rule 1 (full close): if `unit_at_bonus = floor(U / (1 + b)) >= D + R` (where `R` is one base unit per debt leg), the quote becomes the whole debt `D` and the leg rounds up to one unit (math.rs:275-280).
- Rule 2 (one-unit sale): if the curve quote seizes less than `U + m`, the quote rises to `raised = ceil((U + m) / (1 + b))` — but only when `raised < D`; otherwise the original curve quote is returned unchanged (math.rs:281-289).

The gap: when `unit_at_bonus < D + R` **and** `raised >= D`, neither rule fires. If the curve quote in that state backs less than one whole unit, every offer seizes nothing and `liquidate` reverts with `InvalidPayments` (16). The protocol's own documentation confirms the uncovered band: "While `floor(U / (1 + b)) - R < D <= ceil((U + m) / (1 + b))`, neither rule 1 nor rule 2 applies. If the curve quote then backs less than one unit, every offer reverts until accrual or a price move ends that state" (`docs/reference/formulas.md:305-308`, mirrored in `docs/reference/invariants.md` INV-LIQ-02, lines 434-437).

Like the regex fix, the issue is a consolidated validator whose merged conditions fail to accept a valid input form: a debt size that is legitimately between "one unit covers everything" and "the raised quote is below the debt" is silently kept on the curve quote, which cannot express a whole-unit seizure and so rejects all offers.

### Impact Explanation
An account with HF < 1, a single sub-3-decimal supply leg holding ≥ 1 whole unit, and total debt inside the band is unliquidatable through `liquidate` regardless of offer size or `SeizeMode`. The debt keeps accruing interest against the protocol, the account drifts deeper underwater, and the position can only be resolved once accrual or a price move pushes `D` out of the band (or grows to `D > raised`, at which point rule 2 works again — but `raised` grows with `U`, not `D`, so a falling collateral price can instead push the account insolvent before it exits the band). This is temporary freezing of funds / impaired liquidation: liquidator repayments and collateral seizure are blocked for an arbitrary duration determined by market conditions, worsening eventual bad-debt socialization. Severity: Medium.

### Likelihood Explanation
Fully permissionless trigger: any borrower can construct the state. Opening a position with a sole sub-3-decimal collateral (e.g., a 0–2 decimal listing such as a share-token market) and borrowing just below HF = 1 places the account one price tick or accrual step inside the band — the same setup the in-repo tests exercise (`tests/test-harness/tests/controller/zero_decimal_collateral.rs`, `liqvid_rwa_collateral.rs`). The band width is the gap between `floor(U/(1+b)) - R` and `ceil((U+m)/(1+b))`, roughly `R + m` in USD terms, so it is narrow but non-empty and is crossed continuously as interest accrues. No privileged action, leaked key, or off-chain component is required; the only precondition is a listed market with < 3 decimals, which the codebase explicitly supports.

### Recommendation
Make the two promotion rules exhaustive over `D` instead of complementary with a hole. Concretely, in `whole_unit_repayment` (`contracts/controller/src/positions/liquidation/math.rs:275-289`), when `raised >= snap.total_debt` but `unit_at_bonus < full_close_ceiling`, return `snap.total_debt` (full close) rather than the unchanged curve quote — a one-unit sale at `U/(1+b) >= D` already covers the debt, so promoting to full debt is consistent with rule 1's intent and removes the band where every offer reverts. Alternatively, explicitly clamp `unit_repayment` to `min(unit_repayment, snap.total_debt)` so the raised quote can never strand a liquidatable account. Add a regression test that walks `D` across the band and asserts `get_liquidation_estimate` returns a nonzero `max_payment_wad` and `liquidate` succeeds.

### Proof of Concept
1. List a collateral market with `asset_decimals < 3` (e.g., 0 decimals, unit price ~$850–$1,000) and a debt market (USDC). This matches `setup_listing(Listing { decimals, ..THOUSAND_DOLLAR_SHARES })` in `liqvid_rwa_collateral.rs`.
2. Alice supplies `k` whole units as her only supply position and borrows to just below HF = 1 (as in `open(&mut z, "alice", units, ...)` in `zero_decimal_collateral.rs`).
3. Move the price or let interest accrue until `D` satisfies `floor(U/(1+b)) - R < D <= ceil((U+m)/(1+b))` while the curve quote backs less than one unit.
4. Any liquidator calls `get_liquidation_estimate(account_id, payments, SeizeMode::Transfer)` → `max_payment_wad = 0`, `seized_collaterals` empty, whole offer refunded.
5. `liquidate(liquidator, account_id, payments, SeizeMode::Transfer)` reverts with `InvalidPayments` (16) for every `payments` vector, including a full-debt offer — confirmed by the documented behavior and by the revert paths in `zdc_sub_unit_liquidation_reverts_without_charging` and `test_insolvent_liquidation_reverts_when_no_debt_unit_fits_the_backed_quote`, which demonstrate the same `InvalidPayments` terminal when no leg remains payable.
6. The account stays frozen in this unliquidatable state until `D` accrues past `raised` or the collateral price moves — at which point it may already be insolvent, forcing the residue into `clean_bad_debt` and socializing a loss that a timely liquidation would have covered.
