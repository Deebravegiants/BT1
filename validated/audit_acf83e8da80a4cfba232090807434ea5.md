### Title
Unbounded, unpriced `commitments` vector in `accumulate_fees` lets any relayer make block execution cost scale far beyond its fixed declared weight - ([File: modules/pallets/relayer/src/lib.rs])

### Summary
`pallet_ismp_relayer::accumulate_fees` accepts a `WithdrawalProof` whose `commitments: Vec<H256>` field has no length bound, yet the extrinsic is declared with a flat, size-independent weight of `1_000_000`. Every commitment in the vector drives a full state-proof membership check plus decode/verify work in `Pallet::accumulate` / `validate_results`, so actual execution cost grows linearly with the batch size while the weight accounted to the block stays constant — the same "unbounded loop, unaccounted cost" root cause as the OpenQ `deposits`/`getLockedFunds` OUT_OF_GAS report.

### Finding Description
`accumulate_fees` is dispatched as an unsigned extrinsic (`ensure_none(origin)?`) and calls straight into `Self::accumulate(withdrawal_proof)`: [1](#0-0) 

Its declared weight is a fixed literal, independent of `withdrawal_proof.commitments.len()`: [2](#0-1) 

Inside `accumulate`, the function iterates the caller-supplied `commitments` multiple times: once to de-duplicate, once to filter against `RequestCommitments`, once (via `verify_state_proof`) to verify a Merkle/trie membership proof per key on both source and destination chains, once in `validate_results` to decode fee metadata and receipts per commitment, and once more to mark each commitment claimed: [3](#0-2) [4](#0-3) [5](#0-4) 

`verify_state_proof`/`verify_withdrawal_proof` performs real cryptographic trie-proof verification for every key in the batch: [6](#0-5) 

None of these loops are capped by a constant analogous to OpenQ's `nftDepositLimit`/`TOKEN_ADDRESS_LIMIT`. Because the extrinsic is unsigned, the only gating happens in `validate_unsigned`/`pre_dispatch` (not found bounding batch size in the reviewed code) before the transaction pool accepts it; once accepted, the fixed `1_000_000` weight is what gets charged against the block's weight budget regardless of how many commitments (and therefore how many trie-proof verifications) are actually processed.

### Impact Explanation
An attacker (or any relayer, since the call is permissionless/unsigned but validated) can submit `accumulate_fees` with a very large `commitments` vector (bounded only by the max extrinsic/block length, which is still orders of magnitude larger than what `1_000_000` weight was sized for). Because the declared weight does not scale with `commitments.len()`, the pallet's own weight accounting under-charges the block for the real work performed (many trie-proof verifications and RLP/SCALE decodes). This can push actual block-authoring/import time past the block's real time budget, causing the "authorship stall / cannot include further extrinsics" failure mode this scan is instructed to treat as a route unable to deliver messages — i.e., legitimate relayer fee-accumulation and other same-block extrinsics can be starved or delayed, degrading the fee-accounting/reward route relayers rely on to get paid for delivering Hyperbridge messages. This mirrors the OpenQ report's core defect: an unbounded, attacker-reachable loop whose cost was not priced into the operation meant to protect/refund honest participants.

### Likelihood Explanation
Medium. The call is unsigned, so no privileged account or governance action is required — any node capable of gossiping unsigned transactions (a relayer or an unprivileged peer relaying on the relayer's behalf) can craft a `WithdrawalProof` with many `commitments`. The commitments still need to correspond to real, structurally valid entries for `RequestCommitments`/proof decoding to proceed far enough to matter, but building a large batch of syntactically valid (if not all "successfully verified") commitments and proof nodes is feasible without any deposit or stake, unlike the collateral required in most other Hyperbridge write paths.

### Recommendation
Bound `WithdrawalProof.commitments.len()` to a fixed maximum (mirroring OpenQ's suggested `deposits.length <= 1000` cap) and reject batches over that limit before verification begins. Additionally, make `accumulate_fees`'s declared weight a function of `commitments.len()` (e.g. `#[pallet::weight(T::WeightInfo::accumulate_fees(withdrawal_proof.commitments.len() as u32))]`) so the weight system correctly prices the state-proof verification and decoding work performed per commitment, consistent with how `update_commitment_caps` already scales its weight by `commitment_caps.len()`.

### Proof of Concept
1. Construct a `WithdrawalProof` whose `commitments: Vec<H256>` contains as many valid (or plausibly valid) commitment hashes as the max extrinsic size permits, each requiring `RequestCommitments::<T>::get`, source/destination trie-proof verification, and RLP/SCALE decoding in `accumulate`/`validate_results`.
2. Submit it as an unsigned extrinsic to `pallet_ismp_relayer::accumulate_fees`.
3. Observe that the extrinsic is charged the fixed `1_000_000` weight declared in `#[pallet::weight({1_000_000})]` regardless of `commitments.len()`, while its actual execution performs O(n) trie-proof verifications and decodes — demonstrating the weight/computation mismatch that lets a single unprivileged submission consume execution time disproportionate to its accounted weight.

Note: I was unable to fully confirm the `validate_unsigned`/`pre_dispatch` implementation that gates this unsigned call before it reaches `accumulate` (grep did not surface it in `modules/pallets/relayer/src/lib.rs`), so I cannot rule out that some additional off-chain or txpool-level size restriction mitigates this; this should be verified directly in the repository (e.g., via a Devin session with full file access) before treating this as fully confirmed.

	pub fn accumulate(mut withdrawal_proof: WithdrawalProof) -> DispatchResult {
		// Reject duplicate commitments within the batch. The wire format is a
		// `Vec` and this extrinsic is unsigned, so this is the line of defence
		// against an attacker padding the batch with identical commitments to
		// double-claim fees.
		let mut seen = alloc::collections::BTreeSet::new();
		for key in withdrawal_proof.commitments.iter() {
			ensure!(seen.insert(key.encode()), Error::<T>::DuplicateCommitment);
		}

		// Filter out already-claimed / missing commitments
		withdrawal_proof.commitments = withdrawal_proof
			.commitments
			.into_iter()
			.filter(|req| match RequestCommitments::<T>::get(*req) {
				Some(leaf_meta) => !leaf_meta.claimed,
				// If request commitment does not exist in storage which should not be
				// possible, we skip it
				None => false,
			})
			.collect();
		ensure!(!withdrawal_proof.commitments.is_empty(), Error::<T>::MissingCommitments);
		let host = <T as Config>::IsmpHost::default();
		let source_sm = validate_state_machine(&host, withdrawal_proof.source_proof.height)
			.map_err(|_| Error::<T>::ProofValidationError)?;
		let dest_sm = validate_state_machine(&host, withdrawal_proof.dest_proof.height)
			.map_err(|_| Error::<T>::ProofValidationError)?;
		let state_machine = withdrawal_proof.source_proof.height.id.state_id;
		let source_keys = Self::source_fee_commitment_keys(
			state_machine,
			&*source_sm,
			&withdrawal_proof.commitments,
		);
		let dest_keys = dest_sm.receipts_state_trie_key(withdrawal_proof.commitments.clone());

		let source_result = Self::verify_withdrawal_proof(
			&*source_sm,
			&withdrawal_proof.source_proof,
			source_keys.clone(),
		)?;
		let dest_result = Self::verify_withdrawal_proof(
			&*dest_sm,
			&withdrawal_proof.dest_proof,
			dest_keys.clone(),
		)?;
		let (result, claimed_commitments) = Self::validate_results(
			&withdrawal_proof,
			source_keys,
			dest_keys,
			source_result,
			dest_result,
		)?;

	pub fn verify_withdrawal_proof(
		state_machine: &dyn ismp::consensus::StateMachineClient,
		proof: &Proof,
		keys: Vec<Vec<u8>>,
	) -> Result<BTreeMap<Vec<u8>, Option<Vec<u8>>>, DispatchError> {
		let host = <T as Config>::IsmpHost::default();
		let state = host
			.state_machine_commitment(proof.height)
			.map_err(|_| Error::<T>::ProofValidationError)?;
		// Select the trie root explicitly instead of letting the relayer-supplied proof choose
		// it. Fee accumulation reads ISMP request/receipt metadata, which lives in the global
		// state trie on EVM chains and in the ISMP child trie (overlay root) on substrate
		// chains.
		let root = if proof.height.id.state_id.is_evm() {
			state.state_root
		} else {
			state.overlay_root.ok_or(Error::<T>::ProofValidationError)?
		};
		let result = state_machine
			.verify_state_proof(&host, keys, root, proof)
			.map_err(|_| Error::<T>::ProofValidationError)?;

		Ok(result)
	}

	pub fn validate_results(
		proof: &WithdrawalProof,
		source_keys: Vec<Vec<u8>>,
		dest_keys: Vec<Vec<u8>>,
		source_result: BTreeMap<Vec<u8>, Option<Vec<u8>>>,
		dest_result: BTreeMap<Vec<u8>, Option<Vec<u8>>>,
	) -> Result<(BTreeMap<Vec<u8>, U256>, Vec<H256>), Error<T>> {
		let mut result = BTreeMap::new();
		// Only store commitments that were claimed
		let mut commitments = Vec::new();
		for ((commitment, source_key), dest_key) in
			proof.commitments.clone().into_iter().zip(source_keys).zip(dest_keys)
		{
			let encoded_metadata =
				if let Some(encoded) = source_result.get(&source_key).cloned().flatten() {
					encoded
				} else {
					// If fee is a null value skip it, evm returns non membership proof for
					// zero values
					continue;
				};

			let fee = match proof.source_proof.height.id.state_id {
				s if crate::is_pharos(&s) =>
					if encoded_metadata.len() == 32 {
						U256::from_big_endian(&encoded_metadata)
					} else {
						return Err(Error::<T>::ProofValidationError);
					},
				s if s.is_evm() => {
					use alloy_rlp::Decodable;
					let fee = alloy_primitives::U256::decode(&mut &*encoded_metadata)
						.map_err(|_| Error::<T>::ProofValidationError)?;
					U256::from_big_endian(&fee.to_be_bytes::<32>())
				},
				s if s.is_substrate() => {
					use codec::Decode;
					let fee: u128 = pallet_ismp::dispatcher::RequestMetadata::<T>::decode(
						&mut &*encoded_metadata,
					)
					.map_err(|_| Error::<T>::ProofValidationError)?
					.fee
					.fee
					.into();
					U256::from(fee)
				},
				// unsupported
				_ => Err(Error::<T>::MismatchedStateMachine)?,
			};
			let encoded_receipt = dest_result
				.get(&dest_key)
				.cloned()
				.flatten()
				.ok_or_else(|| Error::<T>::ProofValidationError)?;
			let address = Self::decode_receipt_relayer(
				proof.dest_proof.height.id.state_id,
				&encoded_receipt,
			)?;
			let entry = result.entry(address).or_insert(U256::zero());
			*entry += fee;
			commitments.push(commitment);
		}
