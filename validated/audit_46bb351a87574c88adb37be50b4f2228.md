### Title
Market accrual overflow permanently freezes repayments, withdrawals, and liquidations - (File: common/src/rates/simulate.rs)

### Summary
An unprivileged whale can create a very large, highly utilized debt position and leave it untouched until the market’s RAY-scaled value exceeds `i128::MAX`. The next accrual panics in `scaled_to_original`; because every market operation synchronizes first, the market subsequently rejects repayment, withdrawal, liquidation, index updates, revenue claims, and recapitalization. This is the protocol-level analogue of CVE-2019-2495’s repeatedly triggerable denial-of-service crash.

### Finding Description
`global_sync` runs before market mutations and accrues elapsed time in bounded chunks. [1](#0-0)  Each `accrue_step` first computes `borrowed * borrow_index` and `supplied * supply_index` through `scaled_to_original`. [2](#0-1)  `scaled_to_original` directly multiplies the scaled balance by the index. [3](#0-2) 

The borrow index is capped at `1e36`, but that cap does not prevent the already-scaled market total from overflowing first. [4](#0-3)  The protocol’s numeric reference explicitly states that accrued market totals can overflow before the index ceiling and that repayment and withdrawal are blocked because they accrue first. [5](#0-4) 

The controller exposes the required setup and trigger paths through `supply`, `borrow`, and permissionless `update_indexes`. [6](#0-5)  Once the value crosses the representable boundary, the failure is persistent: decreasing `borrowed` requires a successful repayment or liquidation, but those paths must complete the same failing accrual before they can reduce the balance.

### Impact Explanation
This permanently freezes user funds in the affected `(hub_id, asset)` market:

- suppliers cannot withdraw;
- borrowers cannot repay;
- liquidators cannot seize collateral or repay the bad debt;
- `update_indexes`, `claim_revenue`, and `recapitalize` fail before performing their mutation;
- pool cash and collectible debt remain inaccessible.

The existing long-horizon test demonstrates the terminal state: after the accrual returns `MathOverflow`, a one-unit withdrawal and a normal repayment both fail with the same error, while the stored borrow index remains below `MAX_BORROW_INDEX_RAY`. [7](#0-6) 

### Likelihood Explanation
Likelihood is constrained by capital and time requirements rather than authorization. A single funded account can:

1. supply the target asset and sufficient collateral;
2. borrow most of the target market’s cash;
3. leave the position untouched while utilization and the borrow index grow;
4. submit `update_indexes` after the scaled borrow total has exceeded `i128::MAX`.

The market must have sufficiently high admitted caps and enough time must pass at elevated utilization, so this is not triggerable in an ordinary small market. However, no privileged call, leaked key, malformed parameter, oracle manipulation, or external token behavior is required after a suitable market has been admitted. The deterministic test reaches the failure using a billion-token book at 98% utilization. [8](#0-7) 

### Recommendation
Prevent stored RAY-scaled totals from entering the unrepresentable range:

- derive a per-market maximum safe scaled supply/debt from `i128::MAX / MAX_*_INDEX_RAY`;
- enforce that scaled-headroom cap during `supply`, `borrow`, strategy debt minting, and revenue-share minting;
- reject interest accrual before producing an unrepresentable value and expose a bounded-loss settlement path;
- alternatively store or operate on widened values where the product can exceed `i128`, and persist only bounded state;
- add an emergency governed path that can settle the market without invoking the failing interest projection.

### Proof of Concept
The repository’s `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` test constructs an 18-decimal market, supplies `1_000_000_000 * 10^18` units, borrows 98% of that liquidity, advances time in one-year intervals, and observes `MathOverflow` from `update_indexes`. [8](#0-7) 

It then verifies that the failure is terminal rather than transactional: both `withdraw` and `repay` hit the same overflow because each calls the common accrual path first. [9](#0-8)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
