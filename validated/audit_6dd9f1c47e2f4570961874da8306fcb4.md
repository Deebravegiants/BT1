`isAllowedOrigin` at [1](#0-0)  performs an unanchored `strings.HasSuffix` check after stripping the `*.` prefix, with no verification that the matched suffix begins at a domain-label boundary (i.e., no check for a preceding `.` in `originHost`). Audit Report

## Title
CORS wildcard-origin allowlist bypass via unanchored suffix match - ([File: core/services/gateway/network/httpserver.go])

## Summary
The gateway HTTP server's `isAllowedOrigin` function matches wildcard CORS allowlist entries (e.g. `https://*.ethereum.org`) using a raw `strings.HasSuffix` check on the origin host, without anchoring the match to a domain-label boundary. This lets an attacker-registered domain that merely ends with the configured suffix (e.g. `evilethereum.org`) — not a genuine subdomain — be incorrectly treated as an allowed origin, resulting in `Access-Control-Allow-Origin` being reflected back to a malicious site.

## Finding Description
In `isAllowedOrigin` [1](#0-0) , once the `*.` prefix is stripped from the configured `allowedHost` (e.g. `ethereum.org`), the code checks `strings.HasSuffix(originHost, allowedHost)`. This is true not only for legitimate subdomains like `remix.ethereum.org` but also for any domain string that simply ends with `ethereum.org`, such as `evilethereum.org` or `attacker-ethereum.org`, since there is no check that the character immediately preceding the suffix is a `.`.

This flawed check directly gates whether `Access-Control-Allow-Origin` is reflected to the client's `Origin` header in `handleRequest` [3](#0-2) . Since the `Origin` header is fully attacker-controlled and no other validation layer exists between this check and the CORS header being set, the broken suffix match is the sole security boundary and it fails to enforce the intended subdomain-scoping semantics of the wildcard.

The existing test suite only exercises genuine subdomains (accepted) and non-suffix-matching hosts like `ethereum.remix.org` (correctly rejected because it doesn't end with `ethereum.org`), but never a lookalike domain such as `evilethereum.org` that satisfies `HasSuffix` while not being an actual subdomain — so this gap was never caught.

## Impact Explanation
This is an internet-facing gateway HTTP server used for JSON-RPC style requests. When an operator configures a wildcard CORS allowlist entry (a supported, documented, and tested pattern), an attacker who controls a domain sharing the same suffix can have their origin wrongly trusted, enabling credentialed cross-origin reads of gateway responses that should be restricted to the legitimate allowlisted origin family. This maps to the in-scope "allowlist bypass" / cross-origin response exposure impact category.

## Likelihood Explanation
Exploitation requires only: (1) an operator has configured a wildcard entry in `CORSAllowedOrigins`, and (2) an attacker registers any domain ending in the same suffix and gets a victim's browser to send a credentialed cross-origin request to the gateway. No privileged access, node compromise, or special credentials are needed — an unprivileged client fully controls the `Origin` header value sent to the gateway.

## Recommendation
Anchor the wildcard match to a domain-label boundary in `isAllowedOrigin`, e.g., require `originHost == baseDomain || strings.HasSuffix(originHost, "."+baseDomain)` instead of a raw `strings.HasSuffix(originHost, baseDomain)` check. Add regression tests for suffix-only lookalike domains (e.g. `evilethereum.org` should be rejected against `*.ethereum.org`).

## Proof of Concept
1. Start the gateway HTTP server with `CORSEnabled = true` and `CORSAllowedOrigins = []string{"https://*.ethereum.org"}`.
2. Send an HTTP request to the gateway endpoint with header `Origin: https://evilethereum.org`.
3. Observe the response includes `Access-Control-Allow-Origin: https://evilethereum.org`, confirming `isAllowedOrigin` incorrectly returned `true` for a non-subdomain lookalike, as can be verified by extending `TestHTTPServer_HandleRequest_CORSEnabled_FromNotAllowedOriginWildcards` in `httpserver_test.go` with an `evilethereum.org` origin case and asserting the header is unexpectedly present.
