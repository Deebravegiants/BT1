### Title
Path Traversal in Workflow Artifact HTTP Fetcher Allows Escaping the Configured Base URL Prefix - (File: `core/services/workflows/syncer/v2/fetcher.go`)

### Summary
`newHTTPFetcher` in `core/services/workflows/syncer/v2/fetcher.go` builds the artifact-download URL by joining a fixed, operator-configured `baseURL` with an externally-supplied `req.URL` path using `filepath.Join`, without ever verifying that the resulting path stays under the configured base path. This mirrors the FastMCP `_build_url()` flaw: a "clean the path" comment gives the impression of protection, but nothing actually bounds the final URL to the intended prefix, so a caller-supplied value containing enough `../` segments can make the fetcher request an arbitrary path on the same host that the node has been configured to trust.

### Finding Description
`newHTTPFetcher` is created by `NewFetcherFunc` when a node operator configures `CRE().WorkflowFetcher().URL()` with an `http(s)://` URL, and is used to fetch workflow binaries/configs directly, bypassing the gateway: [1](#0-0) 

The path-building logic:
```go
cleanPath := strings.TrimPrefix(filepath.Clean(req.URL), "/")
u, err := url.Parse(baseURL)
...
u.Path = filepath.Join(u.Path, cleanPath)
fetchURL := u.String()
```
only normalizes `req.URL` with `filepath.Clean`; it never checks that the joined result still lives under `u.Path`. Because `filepath.Join` internally re-cleans the concatenated path, a value like `../../../admin/internal` in `req.URL` climbs out of the configured `u.Path` prefix (e.g. `/workflows`) and can reach an entirely different path on the same host — exactly the class of bug described in the FastMCP advisory (`_build_url()` substituting an unescaped, traversal-laden value and relying on a resolver to "fix it up", which instead lets the traversal escape the intended prefix).

This is a real gap, not a theoretical one: the sibling function `newFileFetcher`, which handles the same `req.URL` input for `file://` base URLs, explicitly guards against this by checking the joined path is prefixed by `basePath`: [2](#0-1) 

`newHTTPFetcher` has no equivalent prefix check, and the project's own tests only exercise the traversal guard for the file fetcher, never for the HTTP fetcher — confirming this validation was implemented for one code path and omitted for the other: [3](#0-2) 

The `req.URL` value that reaches this function is not operator-supplied — it is `binaryURL`/`configURL` taken from the on-chain `WorkflowRegisteredEvent`, i.e. controlled by whoever registers a workflow on the Workflow Registry contract: [4](#0-3) 

and this fetcher is wired in whenever the node operator has configured a direct workflow fetcher URL: [5](#0-4) 

So the untrusted, workflow-owner-controlled `BinaryURL`/`ConfigURL` strings flow directly into `newHTTPFetcher`'s unguarded path-join logic.

### Impact Explanation
An entity able to register a workflow (a workflow owner — an external, unprivileged-relative-to-the-node actor, not a node operator) can set `BinaryURL`/`ConfigURL` values containing `../` sequences. When the node's `WorkflowFetcher` is configured with an HTTP(S) base URL (e.g., pointing at an internal artifact host), this lets the workflow owner force the node to issue an HTTP GET to arbitrary paths on that same host — outside the intended `/workflows`-style prefix — while the request is made using the node's own outbound HTTP client (any headers/auth the operator might rely on being scoped to the configured prefix are not enforced). This can be used to reach internal endpoints not meant to be exposed to workflow owners on that host, matching the "allowlist/prefix bypass leading to unauthorized backend access" impact class from the reference advisory.

### Likelihood Explanation
Likelihood is moderate: exploitation requires (1) the node operator to have configured `CRE.WorkflowFetcher.URL` with an `http`/`https` scheme (an explicit, non-default opt-in that bypasses the gateway), and (2) an actor capable of registering workflows on the Workflow Registry contract to control `BinaryURL`/`ConfigURL`. Given that workflow registration is the normal external-facing entry point for CRE workflow owners (not restricted to node operators), and no code-level boundary check exists once that configuration is enabled, the vulnerable code path is directly reachable by design whenever this fetcher mode is used.

### Recommendation
Mirror the protection already present in `newFileFetcher`: after computing `u.Path = filepath.Join(u.Path, cleanPath)`, verify the resulting path is still prefixed by the original base path (`strings.HasPrefix`) before issuing the request, and reject the request otherwise. Alternatively, URL-encode/validate `req.URL` so that `..` path segments cannot be used to escape the configured prefix, rather than relying on `filepath.Clean` + `filepath.Join` alone.

### Proof of Concept
1. Configure a node with `CRE.WorkflowFetcher.URL = "http://internal-artifact-host/workflows"`.
2. As a workflow owner, register a workflow on the Workflow Registry contract with `ConfigURL` set to `"../../admin/secrets"` (relative to the fetch flow) or an absolute-looking value crafted to traverse out of `/workflows` when joined.
3. When the node syncs the workflow, `FetchWorkflowArtifacts` calls `newHTTPFetcher`'s returned function with `req.URL` equal to the malicious value; `filepath.Join("/workflows", "../../admin/secrets")` resolves to `/admin/secrets` (or another path outside `/workflows`), and the node issues `GET http://internal-artifact-host/admin/secrets` — a request the operator did not intend to allow from workflow-supplied input.

func newHTTPFetcher(baseURL string, lggr logger.Logger) types.FetcherFunc {
	client := &http.Client{
		Timeout: 30 * time.Second,
	}

	return func(ctx context.Context, messageID string, req ghcapabilities.Request) ([]byte, error) {
		// Clean the path to prevent directory traversal
		cleanPath := strings.TrimPrefix(filepath.Clean(req.URL), "/")

		// Join base URL with path
		u, err := url.Parse(baseURL)
		if err != nil {
			return nil, fmt.Errorf("failed to parse base URL: %w", err)
		}

		u.Path = filepath.Join(u.Path, cleanPath)
		fetchURL := u.String()

		lggr.Debugw("Fetching HTTP resource", "url", fetchURL, "workflowID", req.WorkflowID)

func (h *Store) FetchWorkflowArtifacts(ctx context.Context, workflowID, binaryURL, configURL string) ([]byte, []byte, error) {
	// Check if the workflow spec is already stored in the database.
	// A row whose binary payload is empty is a pause tombstone - don't use it.
	if spec, err := h.orm.GetWorkflowSpec(ctx, workflowID); err == nil && spec.Workflow != "" {
		// there is no update in the BinaryURL or ConfigURL, lets decode the stored artifacts
		decodedBinary, err := hex.DecodeString(spec.Workflow)
		if err != nil {
			return nil, nil, fmt.Errorf("failed to decode stored workflow spec: %w", err)
		}
		return decodedBinary, []byte(spec.Config), nil
	}

	// Determine which URL to retrieve workflow binary artifacts from
	parsedBinaryURL, err := url.Parse(binaryURL)
	if err != nil {
		return nil, nil, fmt.Errorf("invalid binary URL: %w", err)
	}

	// If the binary URL points to the artifact storage host, use the retrieve function to get the signed URL.
	// NOTE: retrieveFunc may be nil if the fetcherFunc was overridden.
	// TODO CRE-632: retrieverFunc should enforced made to always be set, once local CRE can support it.
	if h.retrieveFunc != nil && parsedBinaryURL.Host == h.config.ArtifactStorageHost {
		signedBinaryURL, err2 := h.retrieveFunc(ctx, &storage_service.DownloadArtifactRequest{
			Id:   workflowID,
			Type: storage_service.ArtifactType_ARTIFACT_TYPE_BINARY,
		})
		if err2 != nil {
			return nil, nil, fmt.Errorf("failed to get binary artifact URL: %w", err2)
		}
		binaryURL = signedBinaryURL
	}

	// Fetch the binary files from the specified URLs.
	var (
		binary, decodedBinary, config []byte
	)

	maxBinarySize, err := h.limiters.MaxBinarySize.Limit(ctx)
	if err != nil {
		return nil, nil, fmt.Errorf("failed to get binary size limit: %w", err)
	} else if maxBinarySize < 0 {
		maxBinarySize = 0
	}
	req := ghcapabilities.Request{
		URL:              binaryURL,
		Method:           http.MethodGet,
		MaxResponseBytes: safeUint32(uint64(maxBinarySize)),
		WorkflowID:       workflowID,
	}
	binary, err = h.fetchFn(ctx, messageID(binaryURL, workflowID), req)
	if err != nil {
		return nil, nil, &types.ArtifactFetchError{ArtifactType: "binary", URL: binaryURL, Err: err}
	}
