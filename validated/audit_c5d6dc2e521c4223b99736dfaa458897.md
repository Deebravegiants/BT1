### Title
Missing L2 sequencer-uptime check on Chainlink price feeds lets stale prices under/overcharge `SimplexPaymaster` gas fees - (File: evm/src/utils/SimplexPaymaster.sol)

### Summary
`SimplexPaymaster` prices ERC-20 gas payments using Chainlink `AggregatorV3Interface.latestRoundData()` for both the native/USD oracle and each token/USD oracle, guarding only against a stale `updatedAt` timestamp and non-positive answers. It never checks an L2 sequencer-uptime feed, even though the contract is explicitly designed to run on L2 chains (comments reference "BNB/USD on BSC, ETH/USD on Ethereum, etc." and the oracle age is tunable "per chain"). [1](#0-0) 

### Finding Description
`_getOraclePrice` is the sole gate on price freshness:

```solidity
function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
    (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();
    if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
    if (block.timestamp - updatedAt > maxOracleAge) {
        revert StaleOraclePrice(address(oracle), updatedAt);
    }
    ...
}
``` [2](#0-1) 

This check only verifies the last update was recent relative to `maxOracleAge` (governance-configurable, up to `MAX_ORACLE_AGE = 7 days`) — it never verifies that the L2 sequencer producing `block.timestamp` and relaying the price update is actually up. On Optimism/Arbitrum/Base-style L2s, when the sequencer goes down, on-chain `block.timestamp` can lag or jump upon sequencer resumption while the Chainlink price feed's `updatedAt` was still committed before the outage. During this window, `_getOraclePrice` reports a price that looks "fresh" by timestamp arithmetic but is actually stale relative to real market conditions, exactly the pattern from the referenced report's `PriceTierVesting._getOraclePrice`.

`_getOraclePrice` feeds directly into unprivileged, permissionless entry points:
- `_fetchDetails`, invoked from ERC-4337 `_validatePaymasterUserOp` for every UserOperation that uses this paymaster with mode `0x00` or `0x02`, computes `tokenPrice` via `_tokenPrice` → `_getOraclePrice` for both `nativeOracle` and the chosen token's oracle. [3](#0-2) [4](#0-3) 

Any address can submit a UserOperation naming this paymaster, so the mispriced oracle path is reachable by an unprivileged transaction submitter with no governance/relayer permissions.

### Impact Explanation
`_tokenPrice` sets `tokenPrice = (nativeUsd * 10^tokenDecimals * (10000+markupBps)) / (tokenUsd * 10000)`, which directly determines how many ERC-20 tokens are pulled from the UserOp's sender/prefunder to cover gas costs (`_erc20Cost` in `PaymasterERC20`). If the stale price during a sequencer outage is skewed:
- A stale price that undervalues the token relative to native gas lets attackers pay far less ERC-20 than the real cost of the gas the paymaster spends — directly draining the paymaster's EntryPoint deposit (funded by the treasury) each time a UserOp is processed, which is a concrete theft of protocol funds.
- A stale price that overvalues the token overcharges honest users, but the more severe and directly exploitable direction is undercharging, which an attacker can trigger deliberately by timing submissions to a known/predictable stale window (sequencer outages are publicly observable events).

The same stale price also feeds `swapAndDeposit`'s `amountOutMin` computation, but that path is treasury-gated so the primary open attack surface is the permissionless `validatePaymasterUserOp`/`postOp` gas-charging flow. [5](#0-4) 

### Likelihood Explanation
The paymaster is explicitly built for multi-chain deployment including L2s whose sequencers can go down (an operational reality, not a hypothetical); the doc comment enumerates BSC/Base/Ethereum-class per-chain heartbeats, implying deployments beyond L1. Every UserOp submitted while a sequencer outage window exists is automatically routed through the unguarded `_getOraclePrice`, so no special privilege or complex setup is required to trigger the mispricing — only timing a UserOp submission during/immediately after a known sequencer outage.

### Recommendation
Add an L2 sequencer-uptime feed check (Chainlink's canonical pattern) in `_getOraclePrice` or as a precondition in `_fetchDetails`/`swapAndDeposit`: read the sequencer uptime feed's `latestRoundData()`, revert if `answer != 0` (sequencer down), and additionally enforce a grace period after `startedAt` (the standard recommendation is >= 1 hour) before trusting price data again. Make the sequencer feed address and grace period governance-configurable per chain, consistent with how `maxOracleAge` is already configured per deployment.

### Proof of Concept
1. Governance deploys `SimplexPaymaster` on an OP-Stack L2 (e.g., Base) with `nativeOracle`/token oracles per `initialize`.
2. The L2 sequencer halts; the last Chainlink round's `updatedAt` remains within `maxOracleAge` of `block.timestamp` once the sequencer resumes (or `block.timestamp` catches up in a way that keeps the delta under the bound), so `_getOraclePrice` does not revert with `StaleOraclePrice`.
3. An attacker (any unprivileged address) submits a UserOperation with `paymasterData` selecting a registered token, during/around the outage window when the true off-chain USD price of the token or native asset has diverged from the last on-chain round.
4. `_validatePaymasterUserOp` → `_fetchDetails` → `_tokenPrice` → `_getOraclePrice` computes `tokenPrice` off the stale-but-"fresh-looking" round; `postOp` charges the attacker's account the resulting, mispriced ERC-20 amount while the paymaster's EntryPoint deposit pays the real gas cost — realizing a loss whenever the skew favors the attacker.

    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
```
