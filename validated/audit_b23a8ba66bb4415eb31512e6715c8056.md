### Title
Uncontrolled Recursion in `T::RuntimeCall::decode` for Cross-Chain Calldata Leads to Stack Overflow and Parachain Crash (Denial of Service) - ([File: modules/pallets/hyper-fungible-token/src/module.rs])

### Summary
The `hyper-fungible-token` pallet's `on_accept` ISMP callback decodes an attacker-controlled `runtime_call` blob taken from cross-chain token-transfer calldata using plain, depth-unlimited `Decode::decode`, unlike the sibling `pallet-call-decompressor` path, which was specifically hardened against this exact bug class (recursive SCALE decode of a `RuntimeCall` causing native stack exhaustion).

### Finding Description
In `on_accept`, when a token-transfer message carries optional `data`, the pallet decodes `substrate_data.runtime_call` with unrestricted recursion: [1](#0-0) 

`substrate_data.runtime_call` is a raw `Vec<u8>` sourced from `message.data`, which is decoded from the ISMP `PostRequest.body` sent by the source chain contract: [2](#0-1) [3](#0-2) 

`T::RuntimeCall` is the aggregated FRAME `RuntimeCall` enum, which includes recursively-boxed variants (e.g. `pallet_sudo::Call::sudo { call: Box<RuntimeCall> }`, `pallet_utility::Call::batch`, `pallet_proxy::Call::proxy`). `parity-scale-codec`'s derived `Decode` for such enums recurses once per nesting level with no built-in depth limit unless `decode_with_depth_limit`/`decode_all_with_depth_limit` is explicitly used. The codebase already recognizes and mitigates this exact class of vulnerability in the sibling `pallet-call-decompressor`, which decodes `RuntimeCall` from relayer-supplied bytes using `decode_all_with_depth_limit(MAX_EXTRINSIC_DECODE_DEPTH_LIMIT, ...)`, with an explicit regression test (`decompress_stack_exhaustion_poc`) that constructs 1000 nested `Sudo(Sudo(...))` calls to prove the guard works: [4](#0-3) [5](#0-4) [6](#0-5) 

`hyper-fungible-token::on_accept`, however, uses plain `T::RuntimeCall::decode` with no depth limit at all, meaning the exact attack the team already fixed elsewhere remains open in this pallet's cross-chain message-execution path.

### Impact Explanation
`on_accept` runs during dispatch of an incoming ISMP `PostRequest` from any state machine configured with a contract-to-asset mapping — i.e., it executes automatically for every relayed token-bridge message that includes non-empty calldata, without any privileged gate. A malicious sender on the source chain (an unprivileged token bridger) can craft a token-transfer message whose `data` field contains a deeply nested `RuntimeCall` (e.g. thousands of nested `Sudo`/`Utility::batch`/`Proxy::proxy` wrappers). Decoding this blob during block execution triggers a native `StackOverflowException`-equivalent abort in the Rust/Wasm runtime, which cannot be caught, crashing the collator/validator process executing the block — a full parachain liveness/Denial-of-Service impact reachable by a single relayed cross-chain message.

### Likelihood Explanation
Likelihood is high: the attacker only needs to (1) have a contract registered via `ContractToAsset` on the source chain (a standard, permissionless part of using the bridge) and (2) send one token transfer with a crafted `data` payload containing a deeply nested call. No signature bypass, consensus break, or special privilege is required — only that `message.data` be non-empty, which is entirely attacker-controlled. The message reaches this code as soon as the ISMP handler processes and dispatches the relayed request (`handle_unsigned`/`handle`), consistent with the "unprivileged relayer/token bridger" reachability the codebase already treats as a first-class threat model in `pallet-call-decompressor`.

### Recommendation
Mirror the fix already applied in `pallet-call-decompressor`: replace `T::RuntimeCall::decode(&mut &*substrate_data.runtime_call)` with `T::RuntimeCall::decode_all_with_depth_limit(MAX_DEPTH, &mut &*substrate_data.runtime_call)` using a small bounded depth (e.g. 4, matching `MAX_EXTRINSIC_DECODE_DEPTH_LIMIT`), and reject calls exceeding it with a dedicated error before dispatch. Add a regression test analogous to `decompress_stack_exhaustion_poc` that constructs deeply nested `Sudo`/`Utility` calls inside `SubstrateCalldata.runtime_call` and asserts a clean decode error rather than a crash.

### Proof of Concept
1. Attacker deploys/uses a source-chain contract already registered in `ContractToAsset` for a valid asset.
2. Attacker sends a token transfer whose ABI-encoded `Message.data` field contains a SCALE-encoded `SubstrateCalldata { signature: None, runtime_call: encoded_nested_call }`, where `encoded_nested_call` is built exactly as in the existing test:
```rust
let inner_call = RuntimeCall::System(frame_system::Call::remark { remark: Vec::new() });
let mut nested_calls = RuntimeCall::Sudo(pallet_sudo::Call::sudo { call: Box::new(inner_call) });
for _ in 1..100_000 {
    nested_calls = RuntimeCall::Sudo(pallet_sudo::Call::sudo { call: Box::new(nested_calls) });
}
let encoded_call_bytes = nested_calls.encode();
```
3. Relay the corresponding ISMP `PostRequest` to the destination parachain via `handle_unsigned`/`handle`.
4. During `on_accept`, `T::RuntimeCall::decode(&mut &*substrate_data.runtime_call)` recurses once per nesting level with no depth cap, exhausting the native stack and aborting the executing node process — the same failure mode the `decompress_stack_exhaustion_poc` test in `pallet-call-decompressor` was written to prevent, but which is not guarded against here. #[test]
fn decompress_stack_exhaustion_poc() {
	let mut ext = new_test_ext();
	ext.execute_with(|| {
		use crate::runtime::RuntimeCall;
		use codec::Encode;

		let inner_call = RuntimeCall::System(frame_system::Call::remark { remark: Vec::new() });

		let mut nested_calls =
			RuntimeCall::Sudo(pallet_sudo::Call::sudo { call: Box::new(inner_call) });

		for _ in 1..1000 {
			nested_calls =
				RuntimeCall::Sudo(pallet_sudo::Call::sudo { call: Box::new(nested_calls) });
		}

		let encoded = nested_calls.encode();
		let mut buffer = vec![0u8; 1000000];
		let compressed = zstd_safe::compress(&mut buffer[..], encoded.as_slice(), 3).unwrap();
		let final_compressed_call = buffer[..compressed].to_vec();

		let res = pallet_call_decompressor::Pallet::<Test>::decompress_call(
			RuntimeOrigin::none(),
			final_compressed_call.to_vec(),
			encoded.len() as u32,
		)
		.err()
		.unwrap();

		assert_eq!(
			res,
			DispatchError::Module(ModuleError {
				index: 10,
				error: [3, 0, 0, 0],
				message: Some("ErrorDecodingCall")
			})
		);
	});
}
