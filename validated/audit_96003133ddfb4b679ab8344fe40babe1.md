### Title
Missing walletAccount enforcement in getConnectedAccounts exposes addresses for all enabled wallet accounts to any trusted origin - ([File: features/connected-origins/module/connections.js])

### Summary
`add()` accepts an optional `walletAccount` and stores it on the connection object, implying per-account scoping, but `getConnectedAccounts` never reads or filters by `value.walletAccount`. Any origin that becomes trusted—regardless of whether it specified a `walletAccount`—receives addresses for every enabled wallet account, filtered only by `assetNames` and `isTrusted`.

### Finding Description
In `add` (features/connected-origins/module/connections.js:140-185), `walletAccount` is optional and simply stored via `#addNewItem`/`#setAttributes` (lines 99, 168, 183). `getConnectedAccounts` (lines 249-273) computes trust via `isTrusted` and reads `value.connectedAssetName`/`value.assetNames` to build `assetNames`, but at no point reads `value.walletAccount`. It then iterates `Object.keys(accounts)` — the full set derived from `#enabledWalletAccountsAtom` via `#getAccounts`/`#setData` (lines 41-49, 108-121) — and returns an entry for every enabled wallet account, only filtering the per-account address object by `assetNames` via `pick(accounts[name].addresses, assetNames)` (lines 264, 269). Thus a connection created with `add({ origin, trusted: true, assetNames: ['btc'] })` and no `walletAccount` (or even one created with an explicit `walletAccount`) results in `getConnectedAccounts({ origin })` returning addresses for every enabled wallet account (e.g. `exodus_0`, `exodus_1`, `exodus_2`, ...), not just the one associated with the origin's `walletAccount`. The stored `walletAccount` field is dead data as far as this read path is concerned. The existing unit test `returns connected accounts with active wallet account first` (connections.test.js:160-196) already demonstrates that both `exodus_0` and `exodus_1` addresses are returned for a single trusted origin that never referenced `walletAccount`, confirming there is no per-account isolation whatsoever — only asset-name filtering and trust-gating exist.

### Impact Explanation
Any dapp/origin that becomes trusted (which can happen through normal connect flows, e.g. `trusted: true` on first connect/approval) is able to enumerate the receive addresses of every wallet account enabled in the wallet, not just the account(s) it was scoped to interact with. This is an address/account-enumeration disclosure across wallet accounts to a single-origin-scoped dapp — a privacy/isolation break, though it does not by itself lead to signing authorization or key compromise since `getConnectedAccounts` only returns addresses, not keys or the ability to sign for those accounts.

### Likelihood Explanation
Fully deterministic and always reachable: any origin that reaches `trusted: true` status (a normal outcome of connecting/approving a dapp) will get this behavior on the very next `getConnectedAccounts` call, with no additional preconditions, since the code unconditionally iterates over all `#connectedAccountsAtom` entries and never consults `value.walletAccount`.

### Recommendation
In `getConnectedAccounts`, filter the returned account set by `value.walletAccount` when present (i.e., only include that wallet account, plus the active one if desired for UX), instead of returning entries for `Object.keys(accounts)` unconditionally. If `walletAccount` is intentionally meant to be non-restrictive (multi-account exposure by design), the field's purpose/documentation should be corrected, and the API should not imply per-account isolation.

### Proof of Concept
Extend `features/connected-origins/module/__tests__/connections.test.js` with:
```js
test('walletAccount field does not scope getConnectedAccounts to a single account', async () => {
  await enabledWalletAccountsAtom.set((current) => ({
    ...current,
    exodus_2: WalletAccount.defaultWith({ index: 2, name: 'Exodus 2', seedId }),
  }))

  await connectedOrigins.add({
    origin: 'exodus.com',
    trusted: true,
    assetNames: ['solana'],
    walletAccount: 'exodus_1', // origin only ever specified this account
  })

  const accounts = await connectedOrigins.getConnectedAccounts({ origin: 'exodus.com' })

  // Expected (if isolation worked): only exodus_1 returned
  // Actual: all enabled accounts (exodus_0, exodus_1, exodus_2) are returned
  expect(accounts.map((a) => a.name).sort()).not.toEqual(['exodus_1'])
  expect(accounts).toHaveLength(3)
})
```
This asserts the disclosed account list exceeds the single `walletAccount` the origin specified, exposing the missing enforcement.
