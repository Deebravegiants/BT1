### Title
Protocol fee on `prooflessDeposit` can be bypassed by calling `Hinkal.sol` directly instead of `HinkalWrapper` - (File: contracts/Hinkal.sol, contracts/HinkalWrapper.sol)

### Summary
`Hinkal.prooflessDeposit()` is a `public` function with no restriction on the caller. Protocol fees for proofless deposits are only ever collected by `HinkalWrapper.prooflessDeposit()`, which settles the fee and then forwards the call to `Hinkal`. Since `Hinkal` itself has no fee logic, any user can call `Hinkal.prooflessDeposit()` directly and create the exact same shielded on-chain commitments while paying zero protocol fee.

### Finding Description
`HinkalWrapper.sol` is explicitly documented as the fee-collection layer: *"Settles the protocol fee for a proofless deposit, then forwards the deposit itself to Hinkal (which has no fee-taking logic of its own)"* [1](#0-0) . Its `prooflessDeposit()` calls `_settleFee()` to charge `feeStructure.feeAmount` before forwarding to `Hinkal` [2](#0-1) .

However, `Hinkal.prooflessDeposit()` is declared `public payable nonReentrant` with no access-control check (no `onlyWrapper`, no `msg.sender == hinkalWrapper` check, and it is also exposed via the `IHinkal` interface used externally) [3](#0-2) [4](#0-3) . It only runs `hinkalHelper.performProoflessDepositChecks(...)`, pulls the deposited tokens from `msg.sender`, and creates the on-chain commitments — none of which enforce that the caller came through `HinkalWrapper` or that any fee was paid.

Consequently, a user can skip `HinkalWrapper` entirely, call `Hinkal.prooflessDeposit()` directly with their own tokens/ETH, and receive fully valid shielded UTXOs/commitments while paying the protocol's designated `feeRecipient` nothing.

This mirrors the referenced `DecentEthRouter::bridgeWithPayload()` analog exactly: a privileged/fee-aware wrapper entrypoint (`UTB.bridgeAndExecute` / `HinkalWrapper.prooflessDeposit`) is the only path that is supposed to collect a fee before the "real" state-changing function (`DecentEthRouter.bridgeWithPayload` / `Hinkal.prooflessDeposit`) is invoked, but the real function has no access control tying it back to the fee-collecting wrapper.

### Impact Explanation
This results in permanent loss of protocol fee revenue for every proofless deposit made this way — matching the "theft or permanent freezing of protocol/relay fees" High-impact category, since the fee that should be routed to `feeStructure.feeRecipient` is never captured and there is no way to retroactively recover it once the on-chain commitments are created.

### Likelihood Explanation
Likelihood is high: any unprivileged EOA can call `Hinkal.prooflessDeposit()` directly (it's a public, non-reentrant function reachable by anyone with tokens/ETH to deposit), and no proof, signature, or relayer cooperation is required to exploit this — the caller simply skips the wrapper contract.

### Recommendation
Restrict `Hinkal.prooflessDeposit()` so it can only be called by the designated `HinkalWrapper` address (e.g., an `onlyWrapper`/`msg.sender == hinkalWrapper` check), or move fee settlement/enforcement into `Hinkal.sol` itself so that bypassing `HinkalWrapper` is not possible.

### Proof of Concept
1. Attacker holds ERC20 tokens (or ETH) intended for a proofless deposit.
2. Instead of calling `HinkalWrapper.prooflessDeposit()` (which would call `_settleFee()` and transfer `feeStructure.feeAmount` to `feeRecipient`), the attacker calls `Hinkal.prooflessDeposit()` directly with the same `erc20Addresses`, `amounts`, `stealthAddressStructures`, `onChainEncryptedOutputs` [3](#0-2) .
3. `hinkalHelper.performProoflessDepositChecks` passes (it only validates dimensions/integrity, not fee payment), tokens are transferred from the attacker to `Hinkal`, and valid on-chain commitments are created exactly as if the wrapper had been used.
4. No ETH/ERC20 fee is ever sent to `feeStructure.feeRecipient`, since that logic exists only in `HinkalWrapper._settleFee()` [5](#0-4) , which was never invoked.

    function _settleFee(
        ProoflessFeeStructure calldata feeStructure
    ) internal returns (uint256 ethForHinkal) {
        ethForHinkal = msg.value;
        if (feeStructure.feeToken == address(0)) {
            require(
                msg.value >= feeStructure.feeAmount,
                "insufficient ETH for fee"
            );
            ethForHinkal = msg.value - feeStructure.feeAmount;
            if (feeStructure.feeAmount > 0) {
                transferETH(feeStructure.feeRecipient, feeStructure.feeAmount);
            }
        } else if (feeStructure.feeAmount > 0) {
            transferERC20TokenFrom(
                feeStructure.feeToken,
                msg.sender,
                feeStructure.feeRecipient,
                feeStructure.feeAmount
            );
        }
    }
