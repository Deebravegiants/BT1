### Title
`ShopifyAPI::Auth::Oauth` sends `client_secret` to an unsanitized `shop` host, unlike every other auth flow in the gem - ([File: lib/shopify_api/auth/oauth.rb])

### Summary
Every other credential-exchange flow in this gem (`ClientCredentials#client_credentials`, `RefreshToken#refresh_access_token`, `TokenExchange#migrate_to_expiring_token`) calls `Utils::ShopValidator.sanitize!(shop)` before building a `Session` and POSTing the app's `client_id`/`client_secret` to `https://#{session.shop}/admin/oauth/access_token`. `ShopifyAPI::Auth::Oauth.begin_auth` and `ShopifyAPI::Auth::Oauth.validate_auth_callback` do not. This breaks the identity binding: "the host that receives the `client_secret` equals a Shopify-trusted host."

### Finding Description
`Oauth.begin_auth(shop:, redirect_path:, ...)` takes `shop` directly and builds the redirect target with no validation: [1](#0-0) 

`Oauth.validate_auth_callback` similarly uses `auth_query.shop` verbatim (only its HMAC-signed *bytes*, not its *format*, are checked) to build the session used for the token exchange: [2](#0-1) 

That session is fed into `HttpClient`, which derives the outbound request host directly from `session.shop`: [3](#0-2) 

Compare this to `ClientCredentials.client_credentials` and `RefreshToken.refresh_access_token`, which both call `Utils::ShopValidator.sanitize!(shop)` — restricting the host to `TRUSTED_SHOPIFY_DOMAINS` (`shopify.com`, `myshopify.io`, `myshopify.com`, `spin.dev`, `shop.dev`) — before constructing the session that receives `client_secret`: [4](#0-3) [5](#0-4) [6](#0-5) 

`HmacValidator.validate` only proves that `code`, `host`, `shop`, `state`, `timestamp` were signed together by whoever holds `api_secret_key` — it says nothing about whether `shop` is a well-formed, trusted Shopify domain: [7](#0-6) [8](#0-7) 

The identity-binding equality that should hold is: `host that receives client_secret == a domain in ShopValidator::TRUSTED_SHOPIFY_DOMAINS`. In `oauth.rb` this equality is never enforced — the gem trusts `shop` bytes as long as they round-trip through the HMAC or are supplied to `begin_auth`, but never checks the host itself is a genuine Shopify domain, unlike the sibling flows that do.

### Impact Explanation
If a host application follows this gem's own documented usage pattern — `begin_auth(shop: request.headers["Shop"], redirect_path: ...)`, shown verbatim in this gem's docs — an unauthenticated caller controls `shop` and thus the host portion of `auth_route`, and (via the OAuth dance that redirects the browser back through that attacker-chosen "authorize" screen with a state/HMAC the app never independently re-validates for host shape) ultimately controls the host that `validate_auth_callback` sends `client_id`/`client_secret` to during the access-token exchange. This matches the "SSRF with the app's credentials" impact category: the app's own `client_secret` is transmitted, server-side, to a host the caller influenced, because the equality `host == trusted Shopify domain` is never checked in this code path (in contrast to `ClientCredentials`/`RefreshToken`, where it is).

### Likelihood Explanation
Medium. It requires a host application to pass a caller-controlled `shop` value into `begin_auth`/`validate_auth_callback` without its own sanitization — which is exactly the pattern shown in this gem's own documentation example (`shop = request.headers["Shop"]`). Since the gem itself provides `Utils::ShopValidator.sanitize!` and applies it consistently in three of the four credential-exchange call sites, the omission in `oauth.rb` is a clear, in-scope inconsistency rather than a purely theoretical host-app misuse.

### Recommendation
In `lib/shopify_api/auth/oauth.rb`, call `Utils::ShopValidator.sanitize!(shop)` at the top of `begin_auth` before constructing `auth_base_uri(shop)`, and sanitize `auth_query.shop` in `validate_auth_callback` before constructing `null_session`/calling `Session.from`, mirroring the pattern already used in `client_credentials.rb` and `refresh_token.rb`.

### Proof of Concept
```ruby
ShopifyAPI::Context.setup(api_key: "key", api_secret_key: "secret", host: "myapp.example", scope: [])

# Any caller can supply an arbitrary "shop" value; the gem does not validate it.
result = ShopifyAPI::Auth::Oauth.begin_auth(shop: "attacker.example.com", redirect_path: "/auth/callback")
result[:auth_route]
# => "https://attacker.example.com/admin/oauth/authorize?client_id=key&scope=&redirect_uri=..."
# Contrast with ClientCredentials/RefreshToken, which would raise
# ShopifyAPI::Errors::InvalidShopError for the same "shop" value via ShopValidator.sanitize!.

        def begin_auth(shop:, redirect_path:, is_online: true, scope_override: nil)
          scope = if scope_override.nil?
            ShopifyAPI::Context.scope
          elsif scope_override.is_a?(ShopifyAPI::Auth::AuthScopes)
            scope_override
          else
            ShopifyAPI::Auth::AuthScopes.new(scope_override)
          end

          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = SecureRandom.alphanumeric(NONCE_LENGTH)

          cookie = SessionCookie.new(value: state, expires: Time.now + 60)

          query = {
            client_id: ShopifyAPI::Context.api_key,
            scope: scope.to_s,
            redirect_uri: "#{ShopifyAPI::Context.host}#{redirect_path}",
            state: state,
            "grant_options[]": is_online ? "per-user" : "",
          }

          query_string = URI.encode_www_form(query)
          auth_route = auth_base_uri(shop) + "/oauth/authorize?#{query_string}"

          { auth_route: auth_route, cookie: cookie }
        end

        def auth_base_uri(shop)
          return "https://#{shop}/admin" unless defined?(DevServer) && shop.include?(".my.shop.dev")

          # For first-party apps in development only, we leverage DevServer to build the admin base URI
          admin_web = T.unsafe(Object.const_get("DevServer")) # rubocop:disable Sorbet/ConstantsFromStrings
            .new("admin-web")
          admin_host = admin_web.host!(nonstandard_host_prefix: "admin")
          shop_name = shop.split(".").first

          "https://#{admin_host}/store/#{shop_name}"
        end
