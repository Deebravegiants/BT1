### Title
Unfunded repay/recapitalize overpayment refunds pay out of pool custody - ([File: contracts/pool/src/ops/repay.rs])

### Summary
The bug class from the report — a transfer path that trusts a declared amount instead of the value actually received — exists in XOXNO Lending in inverted, more severe form. In `contracts/pool/src/ops/repay.rs`, `accounting` derives `overpayment` purely from the declared `action.amount` versus the position's outstanding debt, and `apply` then calls `cache.transfer_out(payer, outcome.overpayment)` without verifying that `action.amount` was ever transferred into the pool. When a market carries no debt, the entire declared amount becomes `overpayment`, and the pool pays it out of real token custody with its cash book untouched — draining supplier funds to an arbitrary `payer`.

### Finding Description
In `contracts/pool/src/ops/repay.rs`:

- `accounting` computes `(burned, overpayment) = cache.resolve_repay(amount, position)` where `amount` is the caller-declared `action.amount` (lines 42–47).
- With zero outstanding debt, `current_debt_ceil` is 0, so the full-close branch yields `net_repay = 0` and `overpayment = amount`. The `RepayRoundsToZeroShares` assert passes on its `net_repay == 0` disjunct (lines 48–52).
- `apply` executes `outcome.cache.transfer_out(payer, outcome.overpayment)` (line 32), sending tokens from pool custody. Neither `credit_cash`/`commit` nor `transfer_out` verifies an actual inbound transfer or debits a measured receipt.
- The same shape exists in `ops::recapitalize::apply`, which refunds the excess over the shortfall from a declared amount.

The repo's own test `test_unfunded_repay_overpayment_refund_also_pays_out_of_custody` in `contracts/pool/tests/flows.rs:3590` demonstrates the drain: `pool.repay(&payer, ract(0, custody_before))` with nothing transferred in and `borrowed == 0` returns `actual_amount == 0` while the payer receives the full pool custody balance. Unlike the controller paths, which measure received deltas (`refund_controller_balance_delta` in `contracts/controller/src/payments.rs:41`, `balance_delta_since` at lines 10–20), this pool leg refunds against a declared figure.

### Impact Explanation
Theft of user funds. An attacker calls `repay` (or `recapitalize`) on a market with no debt, declaring `amount` equal to the pool's token balance. The pool credits nothing to `cash`, burns no shares, and transfers the full declared "overpayment" from custody — real supplier/borrower tokens — to the attacker-chosen `payer`. This is a direct, repeatable drain of every market with zero outstanding debt, including freshly seeded or fully-repaid markets.

### Likelihood Explanation
The path requires only a single call with an attacker-controlled `payer` and a large declared `amount` on a `borrowed == 0` market; no position, collateral, or oracle interaction is needed. The in-repo test proves it executes end-to-end with book/custody divergence as the only trace. One caveat I could not fully confirm: whether `pool::repay` enforces controller-only access on-chain (the pool's `lib.rs` auth wiring was not inspected before this analysis was finalized). The presence of `repay` entries in `scripts/permissionless_entrypoints.txt` and the direct-client test indicate it is reachable, but if repay is gated to the controller, the same defect remains exploitable through `recapitalize`'s declared-shortfall excess or any controller leg that forwards a declared amount without a measured receipt.

### Recommendation
Measure inbound payment instead of trusting the declared amount: snapshot the pool's token balance before the leg, resolve `net_repay`/`overpayment` against the *measured* balance delta, and only `transfer_out` the portion of the delta exceeding the credited repay — mirroring `refund_controller_balance_delta` in `contracts/controller/src/payments.rs`. Concretely, cap `overpayment` at the measured inbound delta (`min(overpayment, delta)`), or require the caller to have pre-transferred `net_repay` and treat only the measured surplus as refundable. Apply the same fix to `ops::recapitalize::apply`.

### Proof of Concept
```rust
// Adapted from contracts/pool/tests/flows.rs::test_unfunded_repay_overpayment_refund_also_pays_out_of_custody
let t = TestSetup::new();
let token = token::Client::new(&t.env, &t.asset);
let payer = Address::generate(&t.env);            // attacker, zero funding
let custody_before = token.balance(&t.pool);      // suppliers' tokens
assert_eq!(t.state_snapshot().borrowed, 0);       // market carries no debt

// Attacker transfers nothing; declares repay of the full custody balance.
let credited = t.client()
    .repay(&payer, &t.ract(0, custody_before))
    .get_unchecked(0)
    .actual_amount;

assert_eq!(credited, 0);                                       // no debt retired
assert_eq!(token.balance(&t.pool), 0);                         // custody drained
assert_eq!(token.balance(&payer), custody_before);             // attacker paid
assert_eq!(t.state_snapshot().cash, custody_before);           // books still claim full cash
```
The divergence between `cash` (unchanged) and the real token balance (zero) subsequently breaks withdraws/borrows for all suppliers in that market even after the direct theft.
