## Finding

### Title
Unauthenticated `CallDispatcher.dispatch()` allows theft of dust/residual funds left in the shared dispatcher contract - (File: `evm/src/utils/CallDispatcher.sol`)

### Summary
`CallDispatcher` accepts native tokens via `receive()` but exposes `dispatch()` with **no access control whatsoever**, and no rescue/sweep function restricted to its intended callers. Because `CallDispatcher` is a single, shared, permanent contract used transiently by `IntentGatewayV2`/`IntentsBase`/`HyperFungibleToken` flows to route swap/calldata execution (predispatch/postdispatch calls), any residual native or ERC-20 balance that is not perfectly enumerated and swept back by the calling gateway is immediately drainable by *any* third party.

### Finding Description
`CallDispatcher.sol` implements:
```solidity
receive() external payable {}

function dispatch(bytes memory encoded) external {
    Call[] memory calls = abi.decode(encoded, (Call[]));
    ...
    (bool success, bytes memory result) = to.call{value: call.value}(call.data);
    if (!success) revert CallFailed(to, result);
}
``` [1](#0-0) 

`dispatch()` has no `onlyOwner`/`onlyGateway`/reentrancy restriction — it is a bare `external` function callable by anyone, and `call.value` is drawn from the dispatcher's own balance, not `msg.value`.

`IntentGatewayV2`/`IntentsBase` route predispatch and postdispatch calldata execution through this single shared `CallDispatcher` instance: assets are transferred into it, `dispatch()` runs the order's calls (e.g. a Uniswap swap), and then the calling contract issues a *second* `dispatch()` call with a hand-built sweep list to pull the expected tokens back out [2](#0-1) . That sweep only iterates over the order's known `output.assets`/`inputs` — any token or native dust the executed calldata actually produced but that isn't in that enumerated list is left sitting in `CallDispatcher`'s balance.

Because `dispatch()` is unauthenticated, any unrelated address can call `CallDispatcher.dispatch(...)` directly at any point (e.g. right after a legitimate flow leaves unswept dust in the same block, or after a stray direct ETH transfer to the contract's `receive()`), supplying a `Call` that forwards the dispatcher's current balance to itself. The same shared dispatcher is also documented as being used by `WrappedHyperFungibleToken`/`HyperFungibleToken` to unwrap and forward funds [3](#0-2) , further increasing the surface area of value that can transiently pass through (or accidentally land in) this one contract.

This is the analog of the reported `IPayoutStrategy` bug class: a `receive()`-accepting contract with no privileged rescue mechanism for value that ends up stuck in it — except here it is strictly worse because the "rescue" path (`dispatch()`) is not gated to any privileged party at all, turning "funds can get stuck" into "funds can be stolen by anyone who notices the dust."

### Impact Explanation
Any dust left in `CallDispatcher` — from imperfect sweep enumeration, fee-on-transfer tokens, swap slippage producing an unlisted token, or a stray direct transfer to `receive()` — is a bounty for any address monitoring the chain. This is a direct loss of protocol/user funds (theft), not merely a griefing/DoS issue, and requires no special privilege to exploit: a single unprivileged transaction calling `dispatch()` suffices.

### Likelihood Explanation
Medium-to-High. Dust generation is a normal, expected byproduct of swap-based predispatch/postdispatch calldata execution (already acknowledged and handled by the protocol's own `DustCollected`/`DustSwept` mechanism for the *gateway* itself), so it's plausible some flows leave value in the intermediate `CallDispatcher` that the enumerated sweep misses. Exploitation only requires observing the dispatcher's balance and issuing a single unauthenticated `dispatch()` call.

### Recommendation
- Restrict `CallDispatcher.dispatch()` to be callable only by an authorized/trusted caller (e.g. only the deploying gateway/HFT contract, or a per-call authorized `msg.sender` allowlist), removing the fully permissionless entry point.
- Alternatively/additionally, add reentrancy protection and a privileged sweep/rescue function so any residual native or ERC-20 balance can be recovered by the intended owner instead of being reachable by arbitrary callers.

### Proof of Concept
1. During a normal `IntentGatewayV2.placeOrder`/fill flow with predispatch/postdispatch calldata, the swap executed via `CallDispatcher.dispatch()` produces a token amount not included in `order.inputs`/`order.output.assets` (e.g. extra reward token, rounding dust, or fee-on-transfer residual). This dust is left on `CallDispatcher`'s balance because `IntentsBase._execute`'s sweep only iterates `outputsLen` known tokens [4](#0-3) .
2. An attacker observes `CallDispatcher`'s non-zero balance (native ETH or ERC-20).
3. Attacker calls `CallDispatcher.dispatch(abi.encode(calls))` directly with `calls = [{to: attackerContract, value: <dust balance>, data: ""}]` (or an ERC-20 `transfer` call to themselves) — this succeeds because `dispatch()` has no caller restriction: `function dispatch(bytes memory encoded) external { ... }` [5](#0-4) .
4. Attacker receives the stray funds with no permission check preventing it.

    receive() external payable {}

    /**
     *  @dev reverts if the target is not a contract or if any of the calls reverts.
     */
    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }

    function _execute(Order calldata order, uint256 outputsLen) internal {
        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            } else {
                uint256 balance = IERC20(token).balanceOf(dispatcher);
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            }

            unchecked {
                ++i;
            }
        }

        if (sweepCount > 0) {
            Call[] memory finalCalls = new Call[](sweepCount);
            for (uint256 i; i < sweepCount;) {
                finalCalls[i] = sweepCalls[i];
                unchecked {
                    ++i;
                }
            }
            ICallDispatcher(dispatcher).dispatch(abi.encode(finalCalls));
        }

### Calldata Execution

Pass a non-empty `data` field to execute arbitrary calls on the destination chain after tokens are unlocked. The `data` must be an ABI-encoded `Call[]` array (see [overview](/developers/evm/hyper-fungible-token/overview#calldata-execution) for the full `Call` struct and security details).

When `isWeth = true`, the WrappedHFT unwraps WETH to native ETH on receive. This example bridges WETH back to the home chain, where it's unwrapped to native ETH and swapped for an exact amount of USDC via UniswapV2. The `Call.value` field forwards the native ETH to the router — demonstrating that the `CallDispatcher` can hold and forward native tokens:

```solidity lineNumbers

address[] memory path = new address[](2);
path[0] = WETH;
path[1] = USDC;

Call[] memory calls = new Call[](1);

// Swap native ETH → exact USDC via UniswapV2
// The CallDispatcher holds the unwrapped ETH and forwards it via Call.value
calls[0] = Call({
    to: UNISWAP_V2_ROUTER,
    // forward the native ETH to the router
    value: amount,
    data: abi.encodeWithSelector(
        IUniswapV2Router02.swapETHForExactTokens.selector,
        usdcAmountOut,
        path,
        recipientAddress,
        block.timestamp
    )
});

IHyperFungibleToken(address(wrapper)).send{value: nativeFee}(
