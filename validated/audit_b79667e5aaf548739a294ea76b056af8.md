### Title
Non-fatal `is_valid` model error is ignored when selecting `self_custody_candidate_rgb`, allowing a degraded/erroneous frame to be bound as self-custody key material - ([File: src/plans/biometric_capture/mod.rs])

### Summary
In `Plan::handle_face_identifier`, when the Face Identifier's `IsValidOutput.error` field is populated, the code only logs the error via `tracing::error!` and continues to evaluate `output.is_valid.map_or(false, |v| v)` without rejecting the candidate. If the model can be induced to return `is_valid: Some(true)` alongside a non-fatal `error`, the frame is still accepted as `self_custody_candidate_rgb` and later bound as the final self-custody key material.

### Finding Description
`handle_face_identifier` at [1](#0-0)  logs any reported error but does not use it to gate acceptance:

```rust
if output.error.is_some() {
    tracing::error!("Face self-custody frame error: {:?}", output);
}
if output.is_valid.map_or(false, |v| v) {
    ...
    self.self_custody_candidate_rgb = Some(FrameInfoSelfCustodyCandidate::new(output, frame...));
```

The only gate is `is_valid == Some(true)` and a higher `score` than the current best candidate; `error.is_some()` has zero effect on the accept/reject decision. The `IsValidOutput`/`FIIsValidOutput` type indeed allows `error`, `is_valid`, and `score` to be independently populated [2](#0-1) , so a model/backend response with `is_valid: Some(true), error: Some(_), score: Some(low_but_valid)` is a structurally valid, reachable output.

The accepted frame is then propagated into `Capture::face_self_custody_candidate` (`SelfCustodyCandidate { rgb_frame, rgb_net_eye_landmarks, rgb_net_bbox }`) at [3](#0-2) , and subsequently fed into the biometric pipeline's full `FaceIdentifier::Estimate` call as `frame_self_custody_candidate` [4](#0-3) .

### Impact Explanation
This is a real code defect but its exploitable *impact* is limited by downstream verification. The `self_custody_candidate_rgb` frame is not itself used directly as cryptographic key material at the capture stage — it is re-submitted to `face_identifier::Input::Estimate`, which independently recomputes `fraud_checks` and the `bundle` (embeddings/thumbnail) in `run_face_identifier`. Those `fraud_checks`/`bundle` results (not the raw `IsValidOutput`) are what actually flow forward as `face_identifier_fraud_checks` / `face_identifier_bundle` in the `Pipeline` output. I could not fully trace, within the available index, whether `fraud_check.rs` or `personal_custody_package.rs` re-validates for a model `error` on the *estimate* path (the relevant snippets were not retrievable before the tool budget ran out), so I cannot confirm whether accepting a low-confidence/error-flagged frame at the capture stage actually survives into signed/uploaded key material, or is caught by a later independent check.

Given this uncertainty, the finding is a real robustness/fail-closed gap in `handle_face_identifier` (frame selection should reject any output carrying a reported `error`), but I cannot confirm end-to-end unauthorized identity binding without visibility into the fraud-check gating in `src/plans/fraud_check.rs` and `src/plans/personal_custody_package.rs`, which the index did not surface in time.

### Likelihood Explanation
Preconditions require the attacker to influence the on-orb Face Identifier model's output such that it returns `is_valid: Some(true)` with a simultaneous `error` and a merely-higher-than-current score — this requires degrading model confidence/behavior via the presented physical scene (feasible in principle for an unprivileged attacker controlling only what the camera sees), but the actual likelihood of achieving `is_valid=true` alongside `error=Some` from the real model (vs. the mock model in `src/agents/python/face_identifier/mod.rs` which always sets `error: None`) is unverified.

### Recommendation
In `Plan::handle_face_identifier` (`src/plans/biometric_capture/mod.rs`), treat `output.error.is_some()` as disqualifying: skip the `is_valid`/score comparison entirely (or explicitly `return Ok(BrokerFlow::Continue)`) whenever an error is reported, so that no frame carrying a model error can become `self_custody_candidate_rgb`, matching the fail-closed intent implied by the `tracing::error!` log.

### Proof of Concept
Unit test in `src/plans/biometric_capture/mod.rs` (or a new test module) constructing a `face_identifier::types::IsValidOutput { is_valid: Some(true), error: Some(<PyError>), score: Some(0.51), .. }`, invoking `Plan::handle_face_identifier` with this output and a valid `camera::rgb::Frame`, and asserting that `self.self_custody_candidate_rgb` remains `None` (or unchanged if a prior valid candidate existed) — currently this assertion fails because the frame is accepted.

    fn handle_face_identifier(
        &mut self,
        orb: &mut Orb,
        output: port::Output<face_identifier::Model>,
        frame: Option<camera::rgb::Frame>,
    ) -> Result<BrokerFlow> {
        if let face_identifier::Output::IsValidImage(output) = output.value {
            tracing::debug!("Face self-custody frame score: {:?}", output.score);
            if output.error.is_some() {
                tracing::error!("Face self-custody frame error: {:?}", output);
            }

            if output.is_valid.map_or(false, |v| v) {
                let highest = self
                    .self_custody_candidate_rgb
                    .as_ref()
                    .map_or(0.0, |p| p.estimate.score.unwrap_or_default());
                if output.score.is_some_and(|s| s > highest) {
                    tracing::info!(
                        "New face self-custody frame captured with score: {:?}",
                        output.score
                    );
                    self.self_custody_candidate_rgb = Some(FrameInfoSelfCustodyCandidate::new(
                        output,
                        frame.expect("frame must be set for FaceIdentifier::IsValidImage"),
                    ));
                    self.face_ir = self.last_face_ir.take();
                    self.thermal = self.last_thermal.take();
                }

                orb.only_rgb_net_frames = true;
            }
        }
        Ok(BrokerFlow::Continue)
    }
