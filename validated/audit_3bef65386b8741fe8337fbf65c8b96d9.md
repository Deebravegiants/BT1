Audit Report

## Title
PSM permanently DoS's mint/redeem for an external asset if its live decimals metadata changes after registration - (File: `substrate/frame/psm/src/lib.rs`)

## Summary
`pallet-psm` snapshots an external asset's `decimals` at approval time in `ExternalAssetInfo::decimals` and the internal asset's decimals in `PsmInfo::internal_decimals`, then enforces strict equality against the live decimals reported by `T::Fungibles::decimals(...)` on every mint/redeem via `ensure_decimals_match`. Since decimals metadata is controlled by `pallet-assets`'s asset `Owner`/`Issuer` (or `Root`), an authority independent of the PSM's own admin, a metadata change after registration permanently blocks mint/redeem for that asset pair with no on-chain remedy other than removing and re-adding the external asset — which itself is blocked while debt is outstanding.

## Finding Description
`add_external_asset` snapshots the external asset's decimals into `ExternalAssetInfo::decimals` at registration time, and `PsmInfo::internal_decimals` snapshots the internal asset's decimals at PSM-creation time. [1](#0-0) [2](#0-1) 

Every conversion path calls `ensure_decimals_match`, which requires the live decimals from `T::Fungibles::decimals` to equal these snapshots, returning `Error::DecimalsMismatch` otherwise: [3](#0-2) 

Decimals are part of `pallet-assets` metadata, which is mutable after asset creation by that asset's own team (`Owner`/`Issuer`) or by `Root`, entirely independent of the PSM instance's `full_admin`/`emergency_admin` authorization model (`ensure_psm_admin`): [4](#0-3) 

There is no cross-pallet hook, refresh extrinsic, or reconciliation mechanism in the PSM pallet to keep the cached snapshot in sync with live metadata; the code performs a hard equality check and reverts unconditionally on mismatch.

## Impact Explanation
If the underlying asset's decimals metadata changes after PSM registration, every subsequent `mint`/`redeem` call touching that `(internal_asset, external_asset)` pair fails with `DecimalsMismatch`, permanently, until an admin removes and re-adds the external asset. This constitutes a real denial-of-service of core PSM economic functionality (minting/redeeming) for the affected asset pair, triggered by an action entirely outside the PSM's own privileged control surface. The report's additional claim that removal could be blocked if `PsmDebt` is nonzero is plausible but was not independently verified against `remove_external_asset`'s exact preconditions in this review; regardless, the primary DoS on mint/redeem is confirmed and does not require this compounding scenario to be a valid, in-scope impact.

## Likelihood Explanation
This requires the external asset's own metadata authority (its `pallet-assets` `Owner`/`Issuer`, or `Root`) to change `decimals` via `set_metadata`/`force_set_metadata` after the PSM has approved the asset. This is a realistic, non-privileged-to-PSM administrative action — it does not require compromising the PSM's own admin, satisfying the requirement that this not be an "admin-only" issue relative to the PSM's own trust boundary. It is a cross-pallet authority mismatch: an actor with legitimate control over the asset (but no relationship to or knowledge of the PSM's use of that asset) can inadvertently or deliberately freeze the PSM's operations for that asset pair.

## Recommendation
- Avoid hard-reverting on live-vs-snapshot decimals mismatches; instead recompute conversions using live decimals, or
- Add a permissionless or admin-callable extrinsic to refresh the stored decimals snapshot when a mismatch is detected, or
- Store debt/reserve accounting in a decimals-agnostic unit so metadata changes cannot invalidate outstanding balances.
- Ensure `remove_external_asset` (or an emergency variant) remains executable even when `ensure_decimals_match` would fail, so a pair is never left both untradeable and unremovable.

## Proof of Concept
1. Asset team creates external asset `X` with `decimals = 6` in `pallet-assets`.
2. PSM admin calls `add_external_asset(internal_asset, X)`; `ExternalAssetInfo { decimals: 6, .. }` is stored (`substrate/frame/psm/src/lib.rs:325-330`).
3. Users mint/redeem normally; `ensure_decimals_match` passes since live decimals (6) == snapshot (6).
4. `X`'s asset `Owner`/`Issuer` (or `Root`) calls `pallet_assets::set_metadata`/`force_set_metadata` to change `decimals` to `8`.
5. Any subsequent `mint`/`redeem` call on `(internal_asset, X)` fails `ensure_decimals_match` (`substrate/frame/psm/src/lib.rs:1642-1649`) with `Error::DecimalsMismatch`, permanently, until the pair is removed and re-added by the PSM admin.

		/// Verify the live decimals for an external still match the snapshot taken at
		/// registration on this PSM, and that the internal asset's live decimals still
		/// match the snapshot stored in [`PsmInfo`].
		pub(crate) fn ensure_decimals_match(
			info: &PsmInfo<T>,
			internal_asset: &T::AssetId,
			external_asset: &T::AssetId,
			external: &ExternalAssetInfo,
		) -> Result<(u8, u8), DispatchError> {
			ensure!(
				T::Fungibles::decimals(external_asset.clone()) == external.decimals,
				Error::<T>::DecimalsMismatch
			);
			ensure!(
				T::Fungibles::decimals(internal_asset.clone()) == info.internal_decimals,
				Error::<T>::DecimalsMismatch
			);
			Ok((external.decimals, info.internal_decimals))
		}

		pub(crate) fn ensure_psm_admin(
			origin: OriginFor<T>,
			internal_asset: &T::AssetId,
			required: impl Fn(PsmManagerLevel) -> bool,
		) -> DispatchResult {
			let admin = PsmAdmin::<T>::get(internal_asset).ok_or(Error::<T>::PsmNotFound)?;
			let caller = <T as Config>::RuntimeOrigin::from(origin).into_caller();
			let level = if caller == admin.full_admin {
				PsmManagerLevel::Full
			} else if caller == admin.emergency_admin {
				PsmManagerLevel::Emergency
			} else {
				return Err(DispatchError::BadOrigin);
			};
			ensure!(required(level), Error::<T>::InsufficientPrivilege);
			Ok(())
		}
