### Title
Hostile HyperSwap V2 pre-seed can bypass the `_seedRebalancing` protection and force a naive `_seedDirectMint` against a large pre-existing attacker LP, donating curve-raised LT/token value - (File: `packages/contracts/src/Bonding.sol`)

### Summary
`finalizeGraduation` is a fully permissionless function [1](#0-0) , and the HyperSwap V2 `(TOKEN, LT)` pair it seeds into can be pre-created and pre-minted by anyone before graduation via `_ensureUniswapV2Pair` calling `IUniswapV2Factory.createPair`/`getPair` [2](#0-1) . `Bonding` defends against a hostile pre-seed with a rebalance-then-deposit routine (`_seedRebalancing` / `_pairRebalance` / `_routerDepositAndDispose`), falling back to a raw `pair.mint()` (`_seedDirectMint`) only when the pre-seed is "negligible dust" — but the fallback is also triggered whenever the corrective swap's fee-adjusted output rounds to zero, which can occur on a *large* pre-seed whose ratio is engineered to sit only a few wei off the curve-close price. In that case the protocol's full curve-raised LT and up-to-250M tokens are minted through the unprotected, ratio-donating V2 `mint()` formula against the attacker's dominant pre-existing LP supply, letting the attacker redeem a disproportionate share of the just-deposited real value.

### Finding Description
`_seedUniswapV2Direct` routes into three regimes depending on the state of the HyperSwap V2 pair at the moment of `finalizeGraduation` [3](#0-2) . Regime 3 (mint pre-seed) is meant to neutralize an attacker who called `pair.mint()` before graduation with self-funded liquidity, by rebalancing the pool toward the cached curve-close ratio via a direct `pair.swap()` and only then depositing through the router's `quote()`-based optimal split [4](#0-3) .

The "below-the-band" early exit to the naive `_seedDirectMint` is explicitly gated on *both* sides of the pre-seed being tiny relative to the LP targets (`DIRECT_MINT_PRESEED_BPS = 1`, i.e. ≤0.01%) [5](#0-4) . However, `_pairRebalance` itself can also return `false` — independent of that band check — whenever the computed no-fee corrective swap `s` is nonzero but its fee-adjusted `getAmountOut(s)` rounds to zero [6](#0-5) . This rounding-to-zero condition is a function of how close the pre-seed ratio already is to the target ratio (`_noFeeSwapInput`'s `s = sqrt(reserveIn*reserveOut*targetN/targetD) - reserveIn`) [7](#0-6) , not of the absolute size of the reserves. An attacker can therefore pre-seed the pair with a *large* self-funded LP position at a ratio deliberately within a few wei of the eventual curve-close price, so that:

1. `reserveToken`/`reserveLT` are large enough to fail the `DIRECT_MINT_PRESEED_BPS` band check, forcing the code into the rebalance branch, but
2. the required corrective swap `s` is small enough that `getAmountOut(s) == 0`, causing `_pairRebalance` to return `false`.

Both call sites of `_pairRebalance` treat this `false` return identically to the tiny-dust case and fall back to `_seedDirectMint` [8](#0-7) , which unconditionally calls `IUniswapV2Pair(pair).mint(_s().lpLock)` [9](#0-8) . When the pair already has non-zero `totalSupply()` (guaranteed in this branch, since regime 1's empty-pair check already failed), standard Uniswap-V2 `mint()` computes `liquidity = min(amount0*totalSupply/_reserve0, amount1*totalSupply/_reserve1)` — the exact "donation to a pre-existing LP" outcome that the whole rebalance mechanism exists to prevent, as the code's own comments state for regime 3 [10](#0-9) . Since the attacker holds essentially 100% of `totalSupply()` (they minted it themselves), any imbalance between the deposited `(tokensForLP, ltFromPair)` and the pre-seed ratio is captured as extra reserves distributed pro‑rata to existing LP holders — i.e., to the attacker — who can immediately burn their LP to redeem a share of the protocol's real curve-raised LT and graduation tokens.

### Impact Explanation
This lets an unprivileged attacker capture (steal) a portion of the LT raised by the bonding curve and/or the tokens reserved for the post-graduation LP, both of which are real trader/creator funds locked via `LPLock.recordLock` [11](#0-10) . Because the attacker's LP position is not routed to `LPLock` (only the freshly minted portion is), the attacker can withdraw their share and the donated value immediately after `finalizeGraduation` completes — a concrete, permanent value transfer from the protocol/curve holders to the attacker, and the resulting LP is seeded away from the true curve-close price. This satisfies the "LP seeded away from curve close price" / "concrete theft ... of trader, creator or LP funds" impact bar.

### Likelihood Explanation
`finalizeGraduation` is permissionless and callable by anyone once a token enters `Lifecycle.Graduating` [1](#0-0) , and pre-creating/pre-seeding the HyperSwap V2 pair is itself unauthenticated (standard `IUniswapV2Factory.createPair` + `IUniswapV2Pair.mint`), explicitly called out as in-scope. An attacker only needs to watch for a token approaching graduation (observable from `TokenGraduating` events / curve state), then mint a self-funded LP at a ratio within a few wei of the pinned `(tokensForLP, ltFromPair)` cache to land in the rounding-to-zero window before calling/racing `finalizeGraduation`. Precisely computing the target ratio requires reading `_prepareGraduationLiquidity`'s pinned values (public via `pendingGraduation` and reserve state), which is feasible for a determined attacker, though it does require some numerical precision to land in the narrow rounding window — a Medium/High likelihood rather than trivial.

### Recommendation
- Make the `_pairRebalance` "swap rounds to zero" fallback conditional on the pre-seed *also* satisfying the `DIRECT_MINT_PRESEED_BPS` negligible-size check, rather than falling back to `_seedDirectMint` for any size of reserves whenever `s` or `getAmountOut(s)` rounds to zero.
- When falling back to a raw `mint()` against a non-empty pool, cap the deposited amounts to the currently-optimal ratio (mirroring the router's `quote()`-based split used in `_routerDepositAndDispose`) instead of depositing the full `(tokensForLP, ltFromPair)` via the naive V2 formula.
- Alternatively, require `_seedDirectMint` to only be reachable when `pair.totalSupply() == 0`, and treat any non-empty pool with a rounding-blocked swap as a distinct "residual imbalance" case handled by iterating/rounding the swap input up rather than skipping it.

### Proof of Concept
Conceptual sequence (cannot be executed without a full Foundry harness, but the mechanism is fully derivable from the cited code):
1. Attacker monitors a token nearing `canGraduate(token) == true` and reads the pinned `(tokensForLP, ltFromPair)` that `_enterGraduating`/`_prepareGraduationLiquidity` will cache [12](#0-11) .
2. Before `finalizeGraduation` is called, attacker calls `IUniswapV2Factory(uniswapV2Factory).createPair(token, lt)` (or reuses an existing empty pair), then funds it and calls `pair.mint(attacker)` with a large `(tokenAmt, ltAmt)` chosen so that `tokenAmt/ltAmt` is within a few wei of `tokensForLP/ltFromPair` — large enough to fail the `DIRECT_MINT_PRESEED_BPS` band check in `_seedRebalancing`, but close enough that `_noFeeSwapInput`'s corrective `s` produces `getAmountOut(s) == 0` in `_pairRebalance`.
3. Anyone calls `finalizeGraduation(token)`. `_seedRebalancing` computes the swap direction, `_pairRebalance` returns `false` due to the zero-rounding, and the code falls back to `_seedDirectMint`, calling `pair.mint(lpLock)` against the attacker's dominant existing supply [13](#0-12) .
4. The V2 `mint()` formula donates the imbalanced side to the pool's existing reserves (attacker-owned LP share); attacker burns their pre-existing LP tokens to redeem the donated LT/token value.

    function _seedUniswapV2Direct(
        address tokenAddress,
        address lt,
        address pair,
        uint256 tokensForLP,
        uint256 ltFromPair,
        uint256 protectedLT
    ) internal returns (uint256 liquidity) {
        // Regime 2 — pull any donation pre-seed into this contract so it
        // doesn't pollute the post-swap ratio. Routed to `address(this)`
        // (NOT `lpLock`) so donated TOKEN can be burned and donated LT
        // can be swept to the owner via `_sweepLTToOwner` — `LPLock` has
        // no rescue path, so anything sent there is permanently stuck.
        // No-op on a freshly-created pair (balance == reserves == 0).
        IUniswapV2Pair(pair).skim(address(this));

        // Regime 1 — no LP minted yet (`totalSupply == 0`): a pristine empty
        // pair, or a dust pre-seed from `transfer(pair, dust) + sync()` that
        // leaves reserves non-zero while supply is still zero. Keying on
        // supply rather than reserves routes the dust shape here instead of
        // the rebalance path: with zero supply V2 mints from our amounts
        // alone, so the pool opens at the cached ratio and any dust becomes
        // reserves with no LP claim.
        if (IUniswapV2Pair(pair).totalSupply() == 0) {
            return _seedDirectMint(tokenAddress, lt, pair, tokensForLP, ltFromPair);
        }

        // Regime 3 — mint pre-seed: rebalance, then deposit balanced subset.
        // `lpLock_` re-read from storage inside `_routerDepositAndDispose`.
        // Reserves and token-ordering re-read inside `_seedRebalancing` to
        // keep this function's stack pressure under solc's 16-slot ceiling
        // without `viaIR`.
        return _seedRebalancing(tokenAddress, lt, pair, tokensForLP, ltFromPair, protectedLT);
    }

    function _seedRebalancing(
        address tokenAddress,
        address lt,
        address pair,
        uint256 tokensForLP,
        uint256 ltFromPair,
        uint256 protectedLT
    ) internal returns (uint256 liquidity) {
        (uint112 r0, uint112 r1,) = IUniswapV2Pair(pair).getReserves();
        bool tokenIs0 = IUniswapV2Pair(pair).token0() == tokenAddress;
        (uint256 reserveToken, uint256 reserveLT) = tokenIs0 ? (uint256(r0), uint256(r1)) : (uint256(r1), uint256(r0));

        // Below the band on BOTH sides, overpower the pre-seed with a direct
        // mint at the cached ratio: the rebalance swap is too coarse to reach
        // the ratio against such small reserves, and the pre-existing LP's
        // claim on the deposit stays bounded by `DIRECT_MINT_PRESEED_BPS`. A
        // side that is large relative to its LP target still takes the
        // rebalance path so it isn't donated under the empty-mint `min()`.
        if (
            reserveToken * BPS_DENOM <= tokensForLP * DIRECT_MINT_PRESEED_BPS
                && reserveLT * BPS_DENOM <= ltFromPair * DIRECT_MINT_PRESEED_BPS
        ) {
            return _seedDirectMint(tokenAddress, lt, pair, tokensForLP, ltFromPair);
        }

        // Budget reads `balanceOf(this)` rather than `tokensForLP` /
        // `ltFromPair` so any skim donation contributes to the rebalance
        // and not only to `_routerDepositAndDispose`'s deposit.
        // Direction: pool TOKEN-rich vs target ⇒ swap LT in (TOKEN out).
        // Pool LT-rich ⇒ swap TOKEN in (LT out). Bounded by uint112 reserves
        // and curve-close-shape targets, both products fit in uint256.
        // When `_pairRebalance` returns false the seed is too small for any
        // swap to move the ratio (its fee-charging quote rounds to zero), so
        // the reserves are negligible against this graduation's inventory:
        // overpower them with a direct mint at the cached ratio rather than
        // letting the router deposit at the attacker's ratio. A swap that
        // does fire leaves the pool ≈ at target for the router deposit.
        if (reserveToken * ltFromPair > reserveLT * tokensForLP) {
            // Pool TOKEN-rich. tokenIn = lt, tokenOut = tokenAddress.
            // tokenInIs0 = (lt is token0) = !tokenIs0.
            if (!_pairRebalance(
                    RebalanceParams({
                        pair: pair,
                        tokenIn: lt,
                        tokenInIs0: !tokenIs0,
                        reserveIn: reserveLT,
                        reserveOut: reserveToken,
                        targetN: ltFromPair,
                        targetD: tokensForLP,
                        maxSwap: _swapBudget(_ltSwapInventory(lt, protectedLT))
                    })
                )) {
                return _seedDirectMint(tokenAddress, lt, pair, tokensForLP, ltFromPair);
            }
        } else if (reserveToken * ltFromPair < reserveLT * tokensForLP) {
            // Pool LT-rich. tokenIn = tokenAddress, tokenInIs0 = tokenIs0.
            if (!_pairRebalance(
                    RebalanceParams({
                        pair: pair,
                        tokenIn: tokenAddress,
                        tokenInIs0: tokenIs0,
                        reserveIn: reserveToken,
                        reserveOut: reserveLT,
                        targetN: tokensForLP,
                        targetD: ltFromPair,
                        maxSwap: _swapBudget(IERC20(tokenAddress).balanceOf(address(this)))
                    })
                )) {
                return _seedDirectMint(tokenAddress, lt, pair, tokensForLP, ltFromPair);
            }
        }
        // else: pool already at curve-close ratio (rare — e.g. attacker
        // pre-seeded at exactly target). Skip swap, deposit directly.

        return _routerDepositAndDispose(tokenAddress, lt, protectedLT);
    }

    function _pairRebalance(
        RebalanceParams memory p
    ) internal returns (bool) {
        uint256 s = _noFeeSwapInput(p.reserveIn, p.reserveOut, p.targetN, p.targetD, p.maxSwap);
        if (s == 0) return false;

        // Quote from the pair so the output tracks its live fee; a value
        // derived from a stale fee rate would trip the pair's K-check.
        uint256 expectedOut = IUniswapV2Pair(p.pair).getAmountOut(s, p.tokenIn);
        if (expectedOut == 0) return false;

        IERC20(p.tokenIn).safeTransfer(p.pair, s);
        (uint256 amount0Out, uint256 amount1Out) = p.tokenInIs0 ? (uint256(0), expectedOut) : (expectedOut, uint256(0));
        IUniswapV2Pair(p.pair).swap(amount0Out, amount1Out, address(this), new bytes(0));
        return true;
    }

    function _noFeeSwapInput(
        uint256 reserveIn,
        uint256 reserveOut,
        uint256 targetN,
        uint256 targetD,
        uint256 maxSwap
    ) internal pure returns (uint256) {
        if (reserveIn == 0 || reserveOut == 0 || targetN == 0 || targetD == 0 || maxSwap == 0) {
            return 0;
        }
        uint256 product = Math.mulDiv(reserveIn * reserveOut, targetN, targetD);
        uint256 newIn = Math.sqrt(product);
        if (newIn <= reserveIn) return 0;
        uint256 s = newIn - reserveIn;
        return s > maxSwap ? maxSwap : s;
    }
