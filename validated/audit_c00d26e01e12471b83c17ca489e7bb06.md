### Title
Supply-index floor clamp resurrects wiped-out supplier claims after bad-debt socialization, letting insolvent positions drain fresh deposits - (File: contracts/pool/src/interest.rs)

### Summary
When bad debt is socialized, `apply_bad_debt_to_supply_index` scales `supply_index` down but clamps it at `SUPPLY_INDEX_FLOOR_RAW` (`RAY/1000`) instead of driving supplier claims to zero. Any account holding scaled supply shares from before the wipeout retains a phantom claim equal to `scaled_shares × RAY/1000`. Once new cash enters the market, those stale shares withdraw real tokens that should belong to post-wipeout suppliers, producing protocol insolvency / theft of user funds.

### Finding Description
The pool README documents that `supply_index` is "not monotone: `apply_bad_debt_to_supply_index` scales it down to socialize a loss across suppliers, floored at `SUPPLY_INDEX_FLOOR_RAW` (`RAY/1000`)" [1](#0-0) . Claims are valued as `scaled_amount × supply_index` (`Cache::unscale_supply_floor` used in `resolve_withdrawal`) [2](#0-1) . Because the index is floored rather than the shares being zeroed, a write-down that should wipe supplier claims to ~0 instead leaves every pre-wipeout position with a strictly positive claim — a state the withdrawal path does not re-validate beyond `require_reserves`.

This is the analog of CVE-2020-15107: an unprivileged caller can drive the system across a boundary the callee assumed unreachable — there, a host violating the ABI's FPU-control-word contract; here, bad-debt entrypoints (`clean_bad_debt`, liquidation shortfall socialization, `recapitalize`) pushing `supply_index` into the floor-clamp regime where the accounting invariant "wiped positions hold no claim" silently breaks.

### Impact Explanation
The repository's own test proves the theft end-to-end: after `apply_bad_debt_to_supply_index` clamps the index, the stranded claim `unscale_supply_floor(old_scaled)` is `> 0`, a fresh supplier deposits, and the wiped position's `resolve_withdrawal(i128::MAX, old_scaled)` pays out `gross == fresh_cash`, leaving `cache.cash() < fresh_claim` — the fresh supplier's funds are drained by the phantom claim [3](#0-2) . This is theft of user funds / protocol insolvency, meeting the acceptance criteria.

### Likelihood Explanation
Reaching the floor requires a write-down of ≥99.9% of supplied value — a tail event (market collapse plus failed liquidations). However, the permissionless keeper surface (`clean_bad_debt`/`recapitalize`/`update_indexes`, per `scripts/permissionless_entrypoints.txt`) is exactly what triggers socialization, and a single clamp event corrupts all historical suppliers simultaneously — every pre-wipeout share becomes a live claim against future cash, with no further attacker action needed. The test is explicitly written as a regression for the missing supply guard ("strands_claim_without_supply_guard"), indicating the production path lacks the protective check [4](#0-3) . Medium likelihood, high impact.

### Recommendation
When a bad-debt write-down would push `supply_index` to the floor, zero out `supplied`/`revenue` share accounting for the market (or mark the market wiped) rather than clamping the index, so that pre-wipeout `scaled_amount` values resolve to zero via `unscale_supply_floor`. Alternatively, add a withdrawal-time guard rejecting exits from positions whose index was floor-clamped, or treat a floor-clamped index as a market-reset event requiring governance re-initialization before new supply is accepted.

### Proof of Concept
Existing in-repo reproduction: `test_raw_cache_floor_clamp_strands_claim_without_supply_guard` in `contracts/pool/tests/interest.rs` [5](#0-4) :

```rust
apply_bad_debt_to_supply_index(&mut cache, Ray::from(5_000 * RAY));
// supply_index clamps UP to SUPPLY_INDEX_FLOOR_RAW; old_scaled keeps a phantom claim
let stranded = cache.unscale_supply_floor(old_scaled);        // > 0
cache.mint_supply(fresh_scaled); cache.credit_cash(fresh_cash); // fresh deposit
let (burn, gross) = cache.resolve_withdrawal(i128::MAX, old_scaled);
// gross == fresh_cash: the wiped position drains the entire new deposit
assert!(cache.cash() < fresh_claim);                           // insolvent
```

An unprivileged attacker path: wait for (or induce via liquidation on a collapsed market) bad debt that triggers the socialization write-down through `clean_bad_debt`/`recapitalize`, then supply fresh tokens and have a pre-wipeout position — including the attacker's own dust position retained before the crash — withdraw phantom value ahead of honest re-depositors.

```rust
#[test]
fn test_raw_cache_floor_clamp_strands_claim_without_supply_guard() {
    let t = TestSetup::new();
    t.as_contract(|| {
        let old_scaled_raw = 1_000 * RAY;
        let mut cache = t.fresh_cache(PoolStateRaw {
            supplied: old_scaled_raw,
            borrowed: 0,
            revenue: 0,
            borrow_index: RAY,
            supply_index: RAY,
            last_timestamp: 0,
            cash: 0,
        });
        let old_scaled = Ray::from(old_scaled_raw);

        apply_bad_debt_to_supply_index(&mut cache, Ray::from(5_000 * RAY));
        assert_eq!(
            cache.supply_index().raw(),
            SUPPLY_INDEX_FLOOR_RAW,
            "wipeout clamps supply_index UP to RAY/1000 instead of resetting shares to 0",
        );

        let stranded = cache.unscale_supply_floor(old_scaled);
        assert!(stranded > 0, "floor clamp leaves S_old a phantom claim");
        assert_eq!(
            cache.cash(),
            0,
            "no cash yet: invariant only masked by require_reserves"
        );

        let fresh_cash = stranded;
        let fresh_scaled = cache.calculate_scaled_supply(fresh_cash);
        cache.mint_supply(fresh_scaled);
        cache.credit_cash(fresh_cash);

        let fresh_claim = cache.unscale_supply_floor(fresh_scaled);
        assert_eq!(
            fresh_claim, fresh_cash,
            "fresh supplier's claim equals deposit"
        );

        let (burn, gross) = cache.resolve_withdrawal(i128::MAX, old_scaled);
        cache.require_reserves(gross);
        cache.burn_supply(burn);
        cache.debit_cash(gross);

        assert!(gross > 0, "stranded wiped position pays out real tokens");
        assert_eq!(gross, fresh_cash, "S_old drains exactly the fresh deposit");
        assert!(
            cache.cash() < fresh_claim,
            "pool cash ({}) can no longer cover fresh supplier claim ({}): funds lost",
            cache.cash(),
            fresh_claim,
        );
    });
```
