### Title
Hardcoded single-hop UniswapV2 swap path for native-fee payments can permanently block message dispatch - ([File: evm/src/core/EvmHost.sol])

### Summary
`EvmHost.dispatch(DispatchPost)`, `EvmHost.dispatch(DispatchGet)`, and `EvmHost.fundRequest` all convert native-token payments into the protocol `feeToken` using a single hardcoded two-hop `UniswapV2` path (`WETH -> feeToken`) through one fixed router, with no fallback router or alternate path available to the caller.

### Finding Description
Whenever any unprivileged user or `IApp` dispatches a POST/GET request or tops up a relayer fee while paying with native tokens, `EvmHost` performs the swap using a rigid, single-liquidity-source route: [1](#0-0) 

The same fixed `path[0] = WETH, path[1] = feeToken()` construction with the same `_hostParams.uniswapV2` router is repeated verbatim for `dispatch(DispatchGet)` and `fundRequest`: [2](#0-1) [3](#0-2) 

There is no way for the caller (or the protocol) to select a different, more liquid route or a different DEX at call time — the router and the exact two-token path are baked into the dispatch logic itself, mirroring the hardcoded `booToUsdcPath`/router pattern flagged in the source report. Client-side fee quoting in `HyperApp.quote()` makes the same fixed-router, fixed-path assumption: [4](#0-3) 

### Impact Explanation
Because the `WETH -> feeToken` pair is the only route ever used, any degradation of that specific pool's liquidity (LP migration, incentive removal, or an attacker temporarily draining/skewing the pool) directly breaks the native-token payment path for every `dispatch`/`fundRequest` call network-wide. Since the swap is `swapETHForExactTokens` with `amountInMaximum = msg.value`, a shallow or manipulated pool causes the swap to revert, meaning native-fee-paying POST/GET dispatches and relayer-fee top-ups fail outright — a `"route unable to deliver messages"` condition for any application relying on native payment through `EvmHost`, with no on-chain fallback path or router to route around the illiquid pool.

### Likelihood Explanation
This is triggered by ordinary usage — any unprivileged caller dispatching a cross-chain message or funding a relayer fee with native tokens exercises this exact hardcoded path. No governance or admin action is required to trigger the failure; only degradation/manipulation of the single `WETH/feeToken` pool referenced by `_hostParams.uniswapV2` is needed, which is a realistic and externally influenceable market condition, not a privileged-actor scenario.

### Recommendation
Add configurable, multi-route swap support (e.g., an allow-listed list of routers/paths per fee token, selectable at dispatch time or automatically chosen by best quote) instead of hardcoding a single router and single two-hop path in `EvmHost.dispatch`/`fundRequest`. Alternatively, support an on-chain fallback (e.g., direct `feeToken` payment enforcement) if the native-swap route fails, so dispatch is never permanently blocked by a single pool's liquidity conditions.

### Proof of Concept
1. Identify (or induce, via flash-loan-based large trades) low liquidity/high price-impact conditions in the specific `WETH/feeToken` UniswapV2 pool referenced by `_hostParams.uniswapV2`.
2. Call `EvmHost.dispatch(DispatchPost)` (or `DispatchGet`/`fundRequest`) with `msg.value` sized for the previously-quoted fee.
3. Because `path = [WETH, feeToken]` and the router are hardcoded with no alternative, `swapETHForExactTokens` reverts due to insufficient output/excess input, causing the dispatch/fundRequest call to fail even though liquidity may be available through a different route or DEX not accessible to `EvmHost`.

    function dispatch(DispatchPost memory post) external payable notFrozen returns (bytes32 commitment) {
        if (msg.value > 0) {
            address[] memory path = new address[](2);
            address uniswapV2 = _hostParams.uniswapV2;
            path[0] = IUniswapV2Router02(uniswapV2).WETH();
            path[1] = feeToken();
            IUniswapV2Router02(uniswapV2).swapETHForExactTokens{value: msg.value}(
                post.fee, path, address(this), block.timestamp
            );
        } else if (post.fee > 0) {
            IERC20(feeToken()).safeTransferFrom(_msgSender(), address(this), post.fee);
        }
