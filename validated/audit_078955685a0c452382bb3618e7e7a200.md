### Title
Permissionless `clean_bad_debt` pays no incentive, so insolvent dust accounts keep accruing phantom interest that inflates supplier claims beyond backing - (File: contracts/controller/src/positions/liquidation/mod.rs)

### Summary
`clean_bad_debt` is the only permissionless path that finalizes an insolvent account: it reclassifies the account's remaining collateral shares as protocol revenue and writes the gross debt off against the supply index. The caller receives nothing — not the residual collateral, not a fee — while paying the transaction cost and requiring fresh oracle prices. Until someone volunteers this call, the account's debt shares remain live in the pool's `borrowed` total, so `accrue_step` keeps growing `borrow_index`, `supply_index`, and protocol revenue shares against debt that can never be repaid. This is the same bug class as Audius `evaluateProposalOutcome`: a state-finalizing function that only costs the caller gas and benefits everyone else.

### Finding Description
`process_clean_bad_debt` authorizes any caller, then `socialize_bad_debt` runs `bad_debt::execute_bad_debt_cleanup`, which (per INV-LIQ-04) reclassifies *all* remaining collateral as revenue and writes off *all* debt — nothing flows to `caller`. [1](#0-0) 

The admission gate (`BadDebtGate::DustCapped`) requires `total_debt > total_collateral` and collateral ≤ `BAD_DEBT_USD_THRESHOLD` (fixed $5 WAD). Crucially there is no cap on the *debt*: an account with $4 of collateral and $50,000 of unbacked debt qualifies. [2](#0-1) 

Meanwhile `interest::global_sync` / `accrue_step` accrue interest over the market's total `borrowed` shares — which still include the dead account's debt — minting `revenue_shares` into `supplied` and `revenue` and growing `supply_index` on every chunk. [3](#0-2)  The bad debt write-down that would correct this (`apply_bad_debt_to_supply_index`) only runs inside cleanup. [4](#0-3) 

No economic alternative exists: liquidating the account seizes at most ~$5 of collateral against a much larger repayment (a guaranteed loss for the liquidator), and `update_account_threshold`/`update_indexes` are likewise unrewarded keeper chores. [5](#0-4) 

### Impact Explanation
Two converging effects produce real protocol insolvency, not just cosmetic staleness:

1. **Phantom accrual**: every millisecond the dead account sits uncleaned, its debt shares grow `borrow_index`, and the supplier side books matching "yield" into `supply_index` plus protocol revenue shares — inflating supplier claims over cash that does not exist. The longer cleanup is delayed, the larger the eventual write-down against honest suppliers.
2. **Loss socialization is indefinitely deferred**: until cleanup runs, `get_borrowed_amount`/`get_supplied_amount` overstate the book; early suppliers can withdraw at the inflated index and leave the shortfall concentrated on whoever exits last — a bank-run dynamic the protocol explicitly acknowledges ("a supplier who exits before cleanup can avoid that loss"). [6](#0-5) 

### Likelihood Explanation
The gate opens routinely: any price move that pushes collateral below $5 while debt exceeds it qualifies, and the test suite confirms the gate can never open before the account is liquidatable — i.e., these accounts exist whenever an underwater liquidation is no longer profitable. [7](#0-6)  Calling `clean_bad_debt` requires `caller.require_auth()`, a funded transaction, valid prices on all account legs, and returns zero — the same economics that produced the Audius finding. A keeper exists but is off-chain infrastructure, not a contract-level guarantee; the repo's own runbook contemplates these calls failing for missing prices or archived entries. [8](#0-7) 

### Recommendation
Pay the cleanup caller. Either (a) transfer a bounded slice of the reclassified collateral (e.g., up to the dust amount) to `caller` inside `execute_bad_debt_cleanup` before booking the rest as revenue, or (b) mint a small fixed share credit on the account's collateral markets to the caller. Alternatively, run `clean_bad_debt_standalone` automatically inside `liquidate` whenever the post-liquidation account crosses the dust gate — the repo notes post-liquidation cleanup already "applies the same gate but skips instead of reverting," so extending an auto-cleanup call there removes the dependence on altruistic callers. [9](#0-8) 

### Proof of Concept
1. Alice supplies $5.00 of collateral and borrows; a price crash leaves `total_debt = $1,000`, `total_collateral = $4` (harness pattern: `t.supply(ALICE, ...)`, `t.borrow(...)`, `t.set_price(...)`, then `try_clean_bad_debt_by_id` succeeds).
2. No `clean_bad_debt` call is made — economically rational, since it costs fees and returns 0.
3. Time advances; each `update_indexes`/mutation runs `accrue_chunk`, which grows `supply_index` and mints `revenue_shares` on the $1,000 of phantom debt.
4. Any supplier withdrawing before cleanup exits at the inflated index; the eventual cleanup caller eats nothing but gas, while remaining suppliers absorb the full write-down via `apply_bad_debt_to_supply_index`, floored at `SUPPLY_INDEX_FLOOR_RAW` — potentially leaving permanent unbacked claims that only `recapitalize` (another unrewarded donation) can fill.

```rust
/// Authorizes permissionless dust-gated cleanup outside flash loans.
pub(crate) fn process_clean_bad_debt(env: &Env, caller: &Address, account_id: u64) {
    caller.require_auth();
    validation::require_not_flash_loaning(env);
    clean_bad_debt_standalone(env, account_id);
}

/// Admission condition for bad-debt socialization.
#[derive(Clone, Copy, PartialEq)]
enum BadDebtGate {
    /// Permissionless: insolvent *and* collateral at or below the dust threshold.
    DustCapped,
    /// Owner-only: insolvent alone, with no cap on the collateral left behind.
    InsolventOnly,
}

/// Requires open debt and the selected insolvency gate, then cleans up the account.
fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    bad_debt::execute_bad_debt_cleanup(env, &mut cache, account_id, &account, &totals);
}

/// Socializes insolvent debt when remaining collateral is at or below the dust cap.
pub(crate) fn clean_bad_debt_standalone(env: &Env, account_id: u64) {
    socialize_bad_debt(env, account_id, BadDebtGate::DustCapped);
}
```

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}
```

```rust
pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
```

```markdown
Cleanup converts all remaining account supply to protocol revenue and socializes
its gross debt, including same-market supply/debt pairs. It does not net those
pairs first. Suppliers present at cleanup bear index write-downs; a supplier
who exits before cleanup can avoid that loss. The index floor can leave
material unpaid backing, so displayed supplier claims are not a universal
pro-rata cash-payout guarantee. New supply checks backing; recapitalization
repairs the book's measured shortfall without minting shares.
```

```rust
/// Sweeps the permissionless `clean_bad_debt` gate across the
/// `BAD_DEBT_USD_THRESHOLD` line by price alone.
///
/// The gate is in WAD USD, so an oracle move decides which side an account sits
/// on. Every price at which the gate opens is a price at which the account is
/// liquidatable: `is_socializable_bad_debt` requires
/// `total_debt > total_collateral`, which implies `HF < 1` for any liquidation
/// threshold below 100%.
///
/// The Certora rules and `contracts/controller/tests/positions/liquidation_curve.rs`
/// pin the predicate in isolation; this test drives it through the oracle.
#[test]
fn clean_bad_debt_gate_never_opens_before_liquidation_does() {
    let mut t = LendingTest::new()
        .with_market(usdc6())
        .with_market(low3())
        .with_min_borrow_collateral_disabled()
        .with_max_utilization_disabled_all_markets()
        .build();

    t.supply(BOB, "LOW3", 100_000.0);
    t.supply(ALICE, "USDC6", 20.0);
    t.borrow(ALICE, "LOW3", 10.0);
    let alice_id = t.resolve_account_id(ALICE);

    // Walk the USDC6 price down. Each step re-prices Alice's collateral only.
    let mut opened_at: Option<i128> = None;
    for step in 1..=40i128 {
        let price = usd(1) - (usd(1) * step) / 40; // 1.00 -> 0.025
        if price <= 0 {
            break;
        }
        t.set_price("USDC6", price);

        let collateral = t.total_collateral_raw(ALICE);
        let debt = t.total_debt_raw(ALICE);
        let liquidatable = t.can_be_liquidated(ALICE);
        let gate_open = debt > collateral && collateral <= controller::constants::WAD * 5;

        if gate_open {
            assert!(
                liquidatable,
                "clean_bad_debt gate opened at price={price} \
                 (collateral={collateral} debt={debt}) while the account was NOT \
                 liquidatable -- a price move must never open the dust gate first"
            );
            if opened_at.is_none() {
                opened_at = Some(price);
                std::println!("gate opened at price={price} collateral={collateral} debt={debt}");
            }
        }
    }

    let opened = opened_at.expect("the price walk never crossed the dust gate");
    assert!(opened > 0);

    // The gate is callable at the final price, so the sweep was not vacuous.
    t.clean_bad_debt_by_id(alice_id);
    assert!(
        !t.try_nft_owner_of(alice_id),
        "a successful clean_bad_debt must delete the account and burn its NFT"
    );
}
```

```markdown
## Bad debt

`clean_bad_debt` is permissionless. It succeeds only when debt exceeds
collateral and collateral is at most `BAD_DEBT_USD_THRESHOLD`, a fixed 5 USD
in WAD. `CannotCleanBadDebt` (`controller #114`) is a legitimate result when
those conditions do not hold; it is not inherently a collision or a non-user
error. Post-liquidation cleanup applies the same gate but skips instead of
reverting. The owner-only `force_socialize_bad_debt` has no collateral cap.
Always identify the panicking contract before interpreting #114.
```
