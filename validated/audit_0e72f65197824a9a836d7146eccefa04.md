## Title
`RequestState` message handling bypasses source-authentication check, allowing state disclosure to unauthenticated relay clients - (File: `orb-relay-client/src/client.rs`)

### Summary
In the orb-relay client's `PollerAgent::main_loop`, incoming messages are supposed to be validated against the expected remote peer (`src.id != self.config.dst_id`) before being processed. However, a `RequestState` message is matched and handled *before* this source check is performed, so any entity able to route a message to the orb's relay session — not just the paired app identified by `dst_id` — can force the orb to resend its `last_message` (the most recent outgoing payload, which may include signup-session state such as `AnnounceOrbId`, `CaptureStarted`, or `SignupEnded`).

### Finding Description
The `main_loop` function processes inbound relay payloads in this order: [1](#0-0) 

The `self_serve::app::v1::RequestState::matches(&payload)` check is evaluated unconditionally, before the `else if src.id != self.config.dst_id` guard that filters out messages from an unexpected source. This means the ordering of checks establishes the security invariant ("only the paired `dst_id` entity may interact with this session") *after* a privileged action (replaying `last_message`) has already been dispatched for one message type. This is the same bug class as the referenced external report: a check that should gate a state-affecting action is deferred past the point where the action is taken, so the invariant no longer reliably holds by the time the response is sent.

The `last_message` field is set on every outgoing send in `PollerAgent`: [2](#0-1) 

During a self-serve signup, this outgoing state includes orb-relay session/signup lifecycle messages sent via `orb_relay_announce_orb_id` and `after_signup`: [3](#0-2) [4](#0-3) 

Because the `RequestState` branch is reached without verifying `src.id == self.config.dst_id`, any relay-routed sender who can produce a payload matching `self_serve::app::v1::RequestState` will receive a replay of the orb's last signup-session message, regardless of whether they are the app identity (`orb_relay_app_id`) that was actually bound to that signup.

### Impact Explanation
This breaks the identity-binding invariant of the self-serve relay session (that only the paired app for a given signup receives the orb's session state). An unpaired or unauthorized relay client could use this to query/replay signup lifecycle state (e.g. `SignupEnded`, `CaptureStarted`) tied to another user's in-progress or completed signup, which is a concrete instance of cross-signup state bleed / misattributed-signup information disclosure via the agent-IPC (orb-relay) trust boundary.

### Likelihood Explanation
Exploitation only requires the ability to send a `RequestState`-shaped payload that reaches this client's poller loop; it does not require passing the `src.id` check, since that check is skipped for this specific message type. Given orb-relay is intended precisely to let apps and orbs multiplex over a shared backend/session, the bypassed check is exactly the mechanism meant to prevent this kind of cross-talk.

### Recommendation
Move the `src.id == self.config.dst_id` validation ahead of the `RequestState` handling so it applies uniformly to all inbound payload types, e.g.:
```rust
} else if src.id != self.config.dst_id {
    tracing::error!("Skipping received message from unexpected source: {:?}", src.id);
} else if self_serve::app::v1::RequestState::matches(&payload).is_some() {
    sender_tx.send(self.last_message.clone()).await...
} else {
    self.handle_message(...).await?;
}
```

### Proof of Concept
1. Establish a relay connection to the same backend/session routing as an orb's self-serve client, with a `src.id` different from the orb's configured `dst_id` (the paired app).
2. Send a payload that matches `self_serve::app::v1::RequestState`.
3. Observe that `PollerAgent::main_loop` responds with `self.last_message.clone()` without ever checking the sender's identity against `dst_id`, disclosing the orb's most recent session-state message.
