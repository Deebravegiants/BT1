### Title
Webhook shop-identity spoofing via signature not covering the `shop-domain` header - (File: lib/shopify_api/webhooks/request.rb)

### Summary
`ShopifyAPI::Webhooks::Request#to_signable_string` returns only the raw request body, so `Utils::HmacValidator.validate` proves the *body* was HMAC-signed with the app's `api_secret_key`, but never proves which shop the event belongs to. The `shop` value that `Registry.process` hands to the app's handler is read straight from the unauthenticated `shopify-shop-domain` / `x-shopify-shop-domain` header.

### Finding Description
`Registry.process` only calls `Utils::HmacValidator.validate(request)` before dispatching to the handler: [1](#0-0) 

`HmacValidator.validate` computes/compares the signature against `verifiable_query.to_signable_string`: [2](#0-1) 

For `Webhooks::Request`, `to_signable_string` is just `@raw_body` — none of the headers (`shop`, `topic`, `webhook_id`, `api_version`) are included in the signed material: [3](#0-2) 

Yet `Registry.process` builds `WebhookMetadata` — which the app's handler is documented to trust as "The shop domain of the webhook" — directly from that unauthenticated header: [1](#0-0) [4](#0-3) 

**Binding that should hold but doesn't:** `hmac-covered bytes == identity fields acted upon`. In practice: `HMAC(raw_body, api_secret_key) valid` is treated by downstream handler code as if it also implies `request.shop == the shop that actually generated raw_body`, but the equality `signable_string == raw_body ∪ shop ∪ topic ∪ webhook_id` never holds — only `signable_string == raw_body`.

An attacker who legitimately installs the app on their own store (an "unprivileged" merchant, no special credentials needed) will receive a genuine webhook: a valid `raw_body` + `x-shopify-hmac-sha256` pair signed with the app's real `api_secret_key`, for events on their own store. Because the signature never covers `shop-domain`, the attacker can replay that exact `(raw_body, hmac)` pair directly to the app's public webhook endpoint (bypassing Shopify's delivery infrastructure entirely) while substituting an arbitrary `x-shopify-shop-domain` header value (e.g., a victim's shop). `HmacValidator.validate` will still return `true` because the body/hmac pair is untouched, and `Registry.process` will call the handler with `WebhookMetadata.shop` set to the attacker-chosen value.

### Impact Explanation
This breaks the tenant-identity boundary the gem is expected to enforce for webhook processing: it allows a shop-confusion / cross-tenant injection where actions or data updates keyed by `data.shop` (as explicitly recommended in the gem's own docs, e.g. `perform_later(topic:, shop_domain: data.shop, webhook: data.body)`) can be attributed to any shop the attacker names, using content that was never generated for that shop. Depending on how the host app uses `data.shop` (e.g., looking up per-shop settings/tokens, writing into a shop-scoped record, or triggering fulfillment/inventory side effects), this can lead to cross-tenant data corruption or unauthorized cross-tenant effects. This aligns with the "Critical – cross-tenant access" impact category, since the confusion crosses the shop/tenant boundary that `WebhookMetadata.shop` is presented as authoritatively verified.

### Likelihood Explanation
Likelihood is non-trivial but bounded: the attacker needs (a) the ability to install the target app on some shop they control (any developer/merchant can do this — no privileged credentials, tokens, or `api_secret_key` needed), and (b) the app's webhook endpoint to be reachable directly over the internet (which it is, by design, since it's a public HTTP callback). The attacker does not need to know `api_secret_key`; they only need one real webhook delivery from their own installation to reuse its already-valid `(body, hmac)` pair with a forged `shop-domain` header. The main mitigating factor is that the replayed body content is fixed (whatever the attacker's own store generated), limiting attacker control over the exact payload contents, but the `shop` attribution is fully attacker-controlled.

### Recommendation
Bind the tenant-identifying fields into the signed material, or otherwise independently validate `request.shop`/`request.topic`/`request.webhook_id` against server-side state before trusting them:
- Have `Registry.process` (or `Webhooks::Request`) cross-check `request.shop` against an expected/allow-listed shop for the given `webhook_id`/registration, rather than passing it through unauthenticated.
- At minimum, sanitize `request.shop` through `Utils::ShopValidator` and document clearly (more strongly than the current docs) that `data.shop` is not covered by the HMAC and must not be treated as cryptographically bound to the payload; recommend that host apps independently confirm the shop identity (e.g., via `webhook_id` uniqueness tracking plus reconciliation against known installed shops) before performing shop-scoped side effects.

### Proof of Concept
```ruby
# 1. Attacker installs the target app on their own shop "attacker.myshopify.com"
#    and captures one legitimate webhook delivery, e.g. from orders/create:
raw_body = '{"id":123,"note":"hi"}'
valid_hmac = OpenSSL::HMAC.digest(OpenSSL::Digest.new("sha256"), ShopifyAPI::Context.api_secret_key, raw_body)
# (This is exactly what Shopify would have sent to the attacker's own store's webhook.)

# 2. Attacker replays the same raw_body/hmac pair directly to the app's
#    public webhook endpoint, but swaps the shop-domain header to a victim shop:
forged_headers = {
  "x-shopify-topic"        => "orders/create",
  "x-shopify-hmac-sha256"  => Base64.encode64(valid_hmac),
  "x-shopify-shop-domain"  => "victim-shop.myshopify.com", # attacker-controlled, unauthenticated
  "x-shopify-webhook-id"   => "attacker-chosen-id",
  "x-shopify-api-version"  => "2024-01",
}

request = ShopifyAPI::Webhooks::Request.new(raw_body: raw_body, headers: forged_headers)

# 3. HMAC validation passes because only raw_body is checked:
ShopifyAPI::Utils::HmacValidator.validate(request) # => true

# 4. Registry.process dispatches to the handler believing the event
#    is authentically from "victim-shop.myshopify.com":
ShopifyAPI::Webhooks::Registry.process(request)
# handler.handle(data: WebhookMetadata.new(shop: "victim-shop.myshopify.com", ...))

# typed: strict
# frozen_string_literal: true

module ShopifyAPI
  module Utils
    module HmacValidator
      extend T::Sig

      class << self
        extend T::Sig

        sig { params(verifiable_query: VerifiableQuery).returns(T::Boolean) }
        def validate(verifiable_query)
          return false unless verifiable_query.hmac

          result = validate_signature(verifiable_query, Context.api_secret_key)
          if result || Context.old_api_secret_key.nil? || T.must(Context.old_api_secret_key).empty?
            result
          else
            validate_signature(verifiable_query, T.must(Context.old_api_secret_key))
          end
        end

        private

        sig { params(verifiable_query: VerifiableQuery, secret: String).returns(T::Boolean) }
        def validate_signature(verifiable_query, secret)
          received_signature = verifiable_query.hmac
          computed_signature = compute_signature(verifiable_query.to_signable_string, secret)
          OpenSSL.secure_compare(computed_signature, T.must(received_signature))
        end

        sig { params(signable_string: String, secret: String).returns(String) }
        def compute_signature(signable_string, secret)
          OpenSSL::HMAC.hexdigest(
            OpenSSL::Digest.new("sha256"),
            secret,
            signable_string,
          )
        end
      end
    end
  end
end

# typed: strict

module ShopifyAPI
  module Webhooks
    class Request
      extend T::Sig
      include Utils::VerifiableQuery

      sig { override.returns(String) }
      def hmac
        Digest.hexencode(Base64.decode64(T.cast(shopify_header("hmac-sha256"), String)))
      end

      sig { returns(String) }
      def topic
        T.cast(shopify_header("topic"), String)
      end

      sig { returns(String) }
      def shop
        T.cast(shopify_header("shop-domain"), String)
      end

      sig { returns(String) }
      def api_version
        T.cast(shopify_header("api-version"), String)
      end

      sig { returns(String) }
      def webhook_id
        T.cast(shopify_header("webhook-id"), String)
      end

      sig { override.returns(String) }
      def to_signable_string
        @raw_body
      end

      sig { returns(T::Hash[String, T.untyped]) }
      def parsed_body
        JSON.parse(@raw_body)
