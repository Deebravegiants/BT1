### Title
Zero-amount `send()` in `HyperFungibleToken` burns nothing but dispatches a full cross-chain message and emits misleading events - ([File: sdk/packages/core/contracts/apps/HyperFungibleToken.sol])

### Summary
`HyperFungibleToken.send()` and `HyperFungibleTokenUpgradeable.send()` accept `params.amount` with no validation that it is non-zero, mirroring the reported `MeritDutchAuction.mint(0)` pattern. A caller can invoke `send()` with `amount = 0`, and the function completes its full flow — burning 0 tokens, dispatching a real ISMP `PostRequest`, and emitting a `Sent` event — with no reverting check.

### Finding Description
`send()` unconditionally calls `_burn(msg.sender, params.amount)` and builds/dispatches a `DispatchPost`, then emits `Sent` regardless of the amount value: [1](#0-0) 

On the receiving side, `onAccept()` decodes the message and calls `_mint(beneficiary, message.amount)` without checking `message.amount != 0`: [2](#0-1) 

Unlike `IntentGatewayV2.placeOrder`, which explicitly reverts on a zero-value input (`if (order.inputs[i].amount == 0) revert InvalidInput();`) [3](#0-2) 
, `HyperFungibleToken`/`HyperFungibleTokenUpgradeable` have no equivalent guard anywhere in `send()`, `onAccept()`, or `onPostRequestTimeout()`. The upgradeable variant has the identical unguarded pattern: [4](#0-3) 

### Impact Explanation
A zero-amount `send()` still dispatches a genuine cross-chain `PostRequest` through the ISMP host, consuming relayer fees/gas and requiring a relayer to actually deliver and prove it — this is spurious but real bandwidth/relayer cost, and produces on-chain `Sent`/`Received`/`Refunded` events with `amount = 0` that off-chain indexers, accounting systems, and integrators consuming these events (e.g. the SDK's teleport status stream) may misinterpret as legitimate transfers. This is a data-integrity/off-chain-integration issue rather than direct fund theft, consistent with the Medium severity of the original report.

### Likelihood Explanation
Trivial to trigger: any unprivileged address holding the token (or even zero balance, since burning 0 always succeeds) can call `send()` with `amount = 0` at any time, with no preconditions beyond `whenNotPaused`.

### Recommendation
Add an explicit check in `send()` (and mirror it in the upgradeable variant) requiring `params.amount > 0`, reverting with a dedicated error (e.g. `ZeroAmount()`), before burning and dispatching. Consider the same guard for `onAccept`'s decoded `message.amount` as a defense-in-depth measure against a compromised or misconfigured peer sending zero-value messages.

### Proof of Concept
1. Deploy/register a `HyperFungibleToken` pair between chain A and chain B via `addChain`/`configure`.
2. From chain A, call `send(SendParams{dest: B, to: recipient, amount: 0, timeout: t, relayerFee: 0, data: ""})`.
3. Observe: `_burn(msg.sender, 0)` succeeds trivially, a real `DispatchPost` is created and dispatched through the ISMP host, and a `Sent(msg.sender, to, dest, 0, commitment)` event is emitted.
4. Once relayed, chain B's `onAccept` mints `0` tokens to the beneficiary and emits `Received(from, beneficiary, source, 0)` — a fully-formed, indexer-visible "transfer" event carrying no economic value, at the cost of real relaying/gas resources.

    function send(SendParams calldata params) external payable whenNotPaused {
        _burn(msg.sender, params.amount);
        DispatchPost memory request = _buildDispatchPost(params);

        bytes32 commitment;
        if (msg.value > 0) {
            commitment = IDispatcher(_host).dispatch{value: msg.value}(request);
        } else {
            commitment = dispatchWithFeeToken(request);
        }

        emit Sent({
            from: msg.sender,
            to: params.to,
            dest: string(params.dest),
            amount: params.amount,
            commitment: commitment
        });
    }

    function onAccept(IncomingPostRequest calldata incoming) public virtual override onlyHost whenNotPaused {
        PostRequest calldata request = incoming.request;

        bytes memory expectedSource = _supportedChains[request.source];
        if (expectedSource.length == 0) revert UnsupportedChain();
        if (keccak256(request.from) != keccak256(expectedSource)) revert UnauthorizedSource();

        Message memory message = abi.decode(request.body, (Message));
        address beneficiary = _toAddr(message.to);
        _mint(beneficiary, message.amount);

        if (message.data.length > 0) {
            ICallDispatcher(_dispatcher).dispatch(message.data);
        }

        emit Received({
            from: message.from,
            to: beneficiary,
            source: string(request.source),
            amount: message.amount
        });
    }
