### Title
Silent zero-fallback for the ISMP overlay root on BEEFY-verified parachain headers - (File: `modules/ismp/clients/beefy/src/consensus.rs`)

### Summary
`fetch_overlay_root_and_timestamp` (used by GRANDPA) errors out when a header's digest lacks the ISMP consensus log, but the BEEFY consensus client's own inline digest-parsing loop does not enforce the same invariant for `overlay_root` — only `timestamp` is validated.

### Finding Description
In `verify_consensus` of `BeefyConsensusClient` (`modules/ismp/clients/beefy/src/consensus.rs:123-150`), for each verified parachain header the code initializes local defaults and then scans the header's digest logs to overwrite them:

```rust
let (mut timestamp, mut overlay_root) = (0, H256::default());
for digest in header.digest().logs.iter() {
    match digest {
        DigestItem::Consensus(id, value) if *id == ISMP_TIMESTAMP_ID => { timestamp = ...; },
        DigestItem::Consensus(id, value) if *id == ISMP_ID => {
            let log = ConsensusDigest::decode(&mut &value[..]);
            if let Ok(log) = log { overlay_root = log.child_trie_root; } else { Err(...)? }
        },
        _ => {},
    };
}
if timestamp == 0 {
    Err(BeefyError::TimestampNotFound)?
}
```

There is an explicit `TimestampNotFound` guard for `timestamp == 0`, but no equivalent guard for `overlay_root` remaining at its `H256::default()` (all-zero) value when the `ISMP_ID` digest item is simply absent from the header's log list (as opposed to present-but-malformed, which is already rejected). The GRANDPA client's equivalent path, `fetch_overlay_root_and_timestamp` (`modules/ismp/clients/grandpa/src/consensus.rs:134,178,235`), treats a missing ISMP digest as an error and never falls back to a default, showing the intended invariant that this code path should also enforce but doesn't.

This zero `overlay_root` is then written unconditionally into the accepted `StateCommitmentHeight` (lines ~161-168) as `overlay_root: Some(overlay_root)` and stored via `intermediates.insert(...)`, becoming the trusted child-trie root for that parachain height in pallet-ismp's state.

### Impact Explanation
Downstream, `SubstrateStateMachine::verify_membership` (`modules/ismp/state-machines/substrate/src/lib.rs:140-143`) uses exactly this `overlay_root` as the trie root to verify ISMP request/receipt commitments for non-coprocessor parachains. If a tracked parachain header that BEEFY successfully finalizes/verifies happens to omit (or a bug/misconfiguration causes it to omit) the `ISMP_ID` consensus digest for a given block, the height is accepted anyway with `overlay_root = 0x00..00` instead of being rejected. Any subsequent membership proof submitted against that height either (a) can never succeed against an all-zero root, permanently freezing/blocking delivery of any request committed at that height (denial of message delivery — a "route unable to deliver messages" per the outlined impact categories), or, more seriously, (b) if an adversary can additionally influence the child-trie proof format such that a trivial/empty trie proof validates against root zero, could allow a forged non-membership/membership result. At minimum this is a reliable, permissionless griefing vector against a bridge whose correctness assumes overlay roots come only from validated digests.

### Likelihood Explanation
Reachability requires only a normal BEEFY consensus update submission (`verify_consensus`) carrying a legitimately-finalized parachain header that lacks the `ISMP_ID` digest for that block — this can occur naturally (e.g., blocks where the ISMP pallet's digest hook is skipped, chain misconfiguration, or a parachain runtime upgrade window) and does not require compromising validators or governance. Any relayer submitting a standard consensus proof exercises this code path, so the trigger condition is plausible without any privileged access, though it is conditioned on encountering (or engineering) a block whose digest omits the ISMP log while still passing BEEFY finality checks.

### Recommendation
Mirror the `timestamp == 0` guard with an equivalent check that the `ISMP_ID` digest was actually observed and used to set `overlay_root` (e.g., use an `Option<H256>` initialized to `None` and require `.ok_or(BeefyError::OverlayRootNotFound)?` before constructing the `StateCommitmentHeight`), consistent with how GRANDPA's `fetch_overlay_root_and_timestamp` already errors instead of defaulting.

### Proof of Concept
1. Construct (or await) a BEEFY consensus proof containing a tracked parachain's finalized header at height `H` whose digest logs contain an `ISMP_TIMESTAMP_ID` entry but no `ISMP_ID` entry.
2. Submit this proof via the normal consensus-update extrinsic handled by `BeefyConsensusClient::verify_consensus`.
3. Observe that verification succeeds (no error is raised for the missing `ISMP_ID` digest) and the resulting `StateCommitmentHeight` for height `H` is stored with `overlay_root = Some(H256::zero())`.
4. Any later `verify_membership`/`verify_non_membership` call against height `H` (`modules/ismp/state-machines/substrate/src/lib.rs:140-143`) uses this zero root, causing all genuine membership proofs for that height to fail permanently (denial of delivery) instead of the height being rejected at consensus-update time.
