### Title
`CallDispatcher.dispatch` has no caller/target/asset restriction, allowing anyone to redirect funds staged for Intents predispatch/postdispatch execution - ([File: evm/src/utils/CallDispatcher.sol])

### Summary
The external report describes fee/value manipulation in a lending proxy caused by failing to validate the variable parameters (`asset`, `amount`, `receiver`) embedded in calldata forwarded to an external contract. The same bug class exists in `CallDispatcher.dispatch`, the shared execution primitive used by `IntentGatewayV2`/`IntentsBase` for both `predispatch` (pre-escrow) and `output.call` (post-fill) calldata. `dispatch` places zero restriction on who may call it and zero validation that the `to`/`value`/`data` triplets it executes correspond to a legitimate, currently-executing order — it blindly performs `to.call{value: call.value}(call.data)` for whatever `Call[]` the caller supplies.

### Finding Description
`CallDispatcher.dispatch` is a public, unrestricted external function: [1](#0-0) 

There is no `onlyOwner`/`onlyGateway`/`msg.sender` check anywhere in the contract, and no verification that the `Call[]` being executed belongs to any specific order, gateway instance, or expected asset flow. Any externally owned account can call `dispatch()` directly with an arbitrary array of `{to, value, data}` and have the `CallDispatcher` execute it using the dispatcher's own native/token balance and any outstanding approvals it holds.

This dispatcher is the same contract referenced by `_params.dispatcher` in `IntentsBase`, used in two places:
1. `_execute`, which runs after a solver has already paid the beneficiary/protocol the declared output amounts, executes the *order-placer-supplied* `order.output.call`, then sweeps any residual balance left on the dispatcher back into the gateway as "dust": [2](#0-1) 
2. `predispatch`, where assets are escrowed to the dispatcher before executing a placer-supplied `predispatch.call` (referenced in `OrderPlaced`'s `predispatch`/`predispatchCall` fields): [3](#0-2) 

Because `dispatch()` itself performs no check that the caller is `IntentGatewayV2`, no check that `to`/`value`/`data` matches any order's declared assets, and no check that a call is even associated with an in-flight order, any balance the dispatcher holds at any point — whether from a predispatch escrow, dust left after `_execute`'s sweep loop (which only sweeps tokens named in `order.output.assets`, not arbitrary tokens the placer's calldata may have produced), or any other transient balance — is exposed to being swept by an unrelated third party who simply calls `CallDispatcher.dispatch()` with a `Call` that transfers the balance to themselves. This is the same root cause pattern as the reported issue: parameters carried through generic calldata (`to`, `value`, `data`, and implicitly the token/receiver they encode) are never validated against what the protocol actually intends to happen, so an unprivileged actor can redirect value or bypass the accounting the surrounding contract (fee split, dust sweep) assumes.

### Impact Explanation
Any funds that transiently sit at the shared `CallDispatcher` address — pre-escrowed predispatch assets, or dust from output-call execution not covered by the sweep's fixed token list — can be stolen outright by any address, since `dispatch()` lets an attacker specify an arbitrary `to`/`data`/`value` and executes it unconditionally. This is direct, concrete theft of user/protocol funds reachable from a single unprivileged transaction, with no proof, relay, or governance step required.

### Likelihood Explanation
High. `dispatch()` requires no special privilege, no signature, and no relationship to any order — merely calling the function with a self-crafted `Call[]` targeting a token contract (e.g., `IERC20.transfer(attacker, balance)`) or a native transfer is enough. Any window where the dispatcher holds a nonzero balance (between the predispatch transfer and the predispatch call's own accounting, or leftover ERC20/ETH from a placer-authored `output.call`/`predispatch.call` that the dust-sweep in `_execute` does not fully account for) is directly exploitable by racing a transaction against the dispatcher.

### Recommendation
Restrict `CallDispatcher.dispatch` to be callable only by the authorized `IntentGatewayV2`/gateway instance(s) that own it (e.g., an `onlyGateway`/`onlyOwner` modifier set at deployment), and/or deploy a fresh, single-use dispatcher (or use `delegatecall`/ephemeral proxy pattern) per order execution so no shared, persistently-reachable contract ever holds funds outside of an atomic, caller-controlled transaction. Additionally, validate that every token swept or moved through `dispatch()` corresponds to assets explicitly declared by the order (as recommended in the original report: expand verification to cover all non-static parameters, or use an adapter/allowlist pattern) rather than relying on an open, unauthenticated call-forwarding primitive shared across all orders.

### Proof of Concept
1. A user places a cross-chain intent order whose `predispatch.assets` transfer 1,000 USDC to `_params.dispatcher` before `predispatch.call` (e.g., a DEX swap) executes, per `IntentsBase`'s predispatch flow.
2. Because `CallDispatcher.dispatch` (evm/src/utils/CallDispatcher.sol:44-62) has no caller restriction, an attacker observing the mempool submits their own transaction directly to the `CallDispatcher` address:
   `dispatch(abi.encode([Call({to: USDC, value: 0, data: abi.encodeWithSelector(IERC20.transfer.selector, attacker, 1000e6)})]))`
3. This executes before (or instead of) the intended `predispatch.call`, since nothing ties the dispatcher's balance or its `dispatch` calls to a specific order or caller — the attacker drains the escrowed USDC to themselves.
4. The same technique applies to any dust left in the dispatcher after `_execute`'s sweep loop, since that loop only sweeps tokens explicitly listed in `order.output.assets` (IntentsBase.sol:498-545), leaving any other token balance the placer's `output.call` produced permanently exposed to an outside `dispatch()` call.

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }

    function _execute(Order calldata order, uint256 outputsLen) internal {
        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            } else {
                uint256 balance = IERC20(token).balanceOf(dispatcher);
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            }

            unchecked {
                ++i;
            }
        }

        if (sweepCount > 0) {
            Call[] memory finalCalls = new Call[](sweepCount);
            for (uint256 i; i < sweepCount;) {
                finalCalls[i] = sweepCalls[i];
                unchecked {
                    ++i;
                }
            }
            ICallDispatcher(dispatcher).dispatch(abi.encode(finalCalls));
        }
    }
