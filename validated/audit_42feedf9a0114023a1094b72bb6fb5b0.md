Audit Report

## Title
Unauthenticated Nil Pointer Dereference in Vault Gateway Handler `handlePublicKeyGet` Crashes Node - (File: `core/capabilities/vault/gw_handler.go`)

## Summary
The `vault.publicKey.get` JSON-RPC method is the only Vault gateway method that bypasses `GatewayVaultRequestProcessor.ProcessRequest`'s nil-params validation, going straight to `GatewayHandler.handlePublicKeyGet`, which dereferences `*req.Params` without a nil check. Since this method is explicitly exempted from authorization on the gateway side and forwarded to all DON nodes unmodified, an unauthenticated client can send a `vault.publicKey.get` request with `params` omitted to crash any node's process handling gateway traffic.

## Finding Description
`GatewayHandler.HandleGatewayMessage` dispatches `vaulttypes.MethodPublicKeyGet` directly to `h.handlePublicKeyGet`, unlike `MethodSecretsCreate/Update/Delete/List`, which are routed through `h.requestProcessor.ProcessRequest` first. [1](#0-0)  Every method handled by `GatewayVaultRequestProcessor` (`processCreateSecretsRequest`, `processUpdateSecretsRequest`, `processDeleteSecretsRequest`, `processListSecretIdentifiersRequest`) explicitly checks `req.Params == nil` before dereferencing, returning an `InvalidVaultParamsError` instead. [2](#0-1) [3](#0-2)  `handlePublicKeyGet`, by contrast, unconditionally executes `json.Unmarshal(*req.Params, r)` with no nil check, which panics if `req.Params` is `nil`. [4](#0-3) 

On the gateway side, `handler.HandleJSONRPCUserMessage` explicitly special-cases `MethodPublicKeyGet` as not requiring authorization, bypassing `requestProcessor.ProcessRequest` (and thus its nil-params check) entirely and forwarding the request to nodes. [5](#0-4)  The node-side `readLoop` in the gateway connector dispatches `handler.HandleGatewayMessage` with no `recover()` in the call stack, so an unrecovered panic crashes the whole node process. [6](#0-5) 

## Impact Explanation
This is a concrete, in-scope availability issue: an unauthenticated, unprivileged external actor reachable through the internet-facing Gateway can crash any node running the Vault capability by sending a single malformed JSON-RPC request omitting `params` for method `vault.publicKey.get`. This directly breaks the implicit security invariant that all Vault gateway message paths validate params before parsing, as demonstrated by the parallel checks present everywhere except this one method.

## Likelihood Explanation
High. No authentication, credentials, allowlist membership, or prior state is required — `vault.publicKey.get` is intentionally exempted from authorization per the code comment "Public key requests don't require authorization," and the request is trivially crafted (`{"jsonrpc":"2.0","id":"x","method":"vault.publicKey.get"}` with no `params` field, which is legal JSON-RPC 2.0). The exploit is repeatable against every node in the DON.

## Recommendation
Add an explicit `req.Params == nil` (or `req.Params != nil` guard before dereference) check at the start of `GatewayHandler.handlePublicKeyGet` in `core/capabilities/vault/gw_handler.go`, returning a `UserMessageParseError`/`InvalidParamsError` response instead of dereferencing a nil pointer — consistent with the checks already present in `GatewayVaultRequestProcessor`'s other method handlers. As defense in depth, wrap the `handler.HandleGatewayMessage` invocation in `readLoop` (`core/services/gateway/connector/connector.go`) with a `recover()` so a single malformed message or handler bug cannot take down the whole node process.

## Proof of Concept
1. Deploy a Gateway + Vault-capability node per standard chainlink configuration.
2. As an unauthenticated client, send to the Gateway's public endpoint: `{"jsonrpc":"2.0","id":"poc-1","method":"vault.publicKey.get"}` (no `"params"` key).
3. `handler.HandleJSONRPCUserMessage` (`core/services/gateway/handlers/vault/handler.go:404-420`) treats this method as not requiring authorization and forwards it to nodes via `fanOutToVaultNodes`/`SendToNode`.
4. The node's `readLoop` (`core/services/gateway/connector/connector.go:268-298`) dispatches to `GatewayHandler.HandleGatewayMessage`, which calls `handlePublicKeyGet` (`core/capabilities/vault/gw_handler.go:364-368`), executing `json.Unmarshal(*req.Params, r)` with `req.Params == nil`, panicking and crashing the node process since no `recover()` exists in the call chain.
5. A Go unit test constructing `jsonrpc.Request[json.RawMessage]{Method: vaulttypes.MethodPublicKeyGet, Params: nil}` and calling `GatewayHandler.HandleGatewayMessage` directly reproduces the panic deterministically.

func (h *handler) HandleJSONRPCUserMessage(ctx context.Context, req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) error {
	if req.ID == "" {
		return errors.New("request ID cannot be empty")
	}
	if len(req.ID) > 200 {
		// Arbitrary limit to prevent abuse
		return errors.New("request ID is too long: " + strconv.Itoa(len(req.ID)) + ". max is 200 characters")
	}

	h.lggr.Debugw("handling vault request", "method", req.Method, "requestID", req.ID, "request", req)
	if req.Method == vaulttypes.MethodPublicKeyGet {
		// Public key requests don't require authorization,
		// Let's process this request right away.
		// Note we cache this value quite aggressively so don't need to worry about DoS.
		publicKeyResponseBytes, cachedPublicKey := h.getCachedPublicKey()
		if cachedPublicKey == nil {
			// Not found in cache. Fetch from nodes.
			ar, err := h.newActiveRequest(req, callback)
			if err != nil {
				h.lggr.Errorw("failed to create new activeRequest", "error", err)
				return err
			}
			return h.handlePublicKeyGet(ctx, ar)
		}
		h.lggr.Debugw("returning cached public key response")
		return h.handlePublicKeyGetSynchronously(ctx, req, publicKeyResponseBytes, callback)
	}

func (c *gatewayConnector) readLoop(gatewayState *gatewayState) {
	defer c.closeWait.Done()
	ctx, cancel := c.shutdownCh.NewCtx()
	defer cancel()

	for {
		select {
		case <-c.shutdownCh:
			return
		case item := <-gatewayState.conn.ReadChannel():
			var req jsonrpc.Request[json.RawMessage]
			err := json.Unmarshal(item.Data, &req)
			if err != nil {
				c.lggr.Errorw("parse error when reading from Gateway", "id", gatewayState.config.ID, "err", err)
				break
			}
			c.handlersMu.RLock()
			handler, exists := c.handlers[req.Method]
			c.handlersMu.RUnlock()
			if !exists {
				c.lggr.Errorw("no handler for method", "id", gatewayState.config.ID, "method", req.Method)
				break
			}
			// do not break on error. HandleGatewayMessage handles errors
			// by sending a response back to the Gateway.
			err = handler.HandleGatewayMessage(ctx, gatewayState.config.ID, &req)
			if err != nil {
				c.lggr.Warnw("failed to handle message from Gateway", "id", gatewayState.config.ID, "method", req.Method, "err", err)
			}
		}
	}
