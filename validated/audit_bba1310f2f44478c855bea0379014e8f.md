### Title
Missing transaction deadline on `Zap.buy` / `Zap.sell` (and their permit variants) exposes traders to stale-quote sandwich/MEV extraction - (File: `packages/contracts/src/Zap.sol`)

### Summary
`Zap.buy`, `Zap.buyWithPermit`, `Zap.sell`, and `Zap.sellWithPermit` let a trader supply a slippage bound (`minTokensOut` / `minUsdcOut`) but accept no `deadline` parameter, so a signed transaction has no on-chain expiry. [1](#0-0)  A transaction can sit in the mempool indefinitely and be executed long after the trader's price expectations were valid, at which point an MEV bot can sandwich it up to the full width of the now-stale slippage bound.

### Finding Description
`_buyInternal` and `_sellInternal` only enforce a final-amount floor (`tokensOut < minTokensOut` / `usdcOut < minUsdcOut`) computed at execution time — there is no check that the transaction is being mined within any bound of when it was signed. [2](#0-1) [3](#0-2) 

The slippage floor a trader picks is derived from a quote taken at signing time (e.g. via `Router.previewBuy` / `getAmountOut`). [4](#0-3)  Because the reserve asset is an externally-priced, rebasing BounceTech LT whose `exchangeRate()` drifts continuously with leverage/funding independent of any curve activity, and because the curve's own `reserve0/reserve1` move with every intervening buy/sell, the gap between the trader's chosen floor and the "fair" price at execution time can widen substantially the longer the transaction remains unconfirmed. With no `deadline`, nothing forces the transaction to either land promptly or revert — it stays valid and exploitable for as long as it remains in the mempool (whether because of low gas, network congestion, or a bot deliberately delaying inclusion).

This is the same underlying defect class as the referenced Talos finding: allowing a trade to be executed arbitrarily far from when its risk parameters were chosen. On alt.fun the effect is on `Zap`'s two only user-facing trade entry points rather than a vault's compounding routine, but the mechanism (stale slippage bound + no expiry) and exploitation path (mempool-resident sandwich) are directly analogous.

### Impact Explanation
Any curve or post-graduation buy/sell submitted through `Zap` can be sandwiched for up to the full width of the trader's own slippage tolerance once the price has moved (from curve trading, LT exchangeRate drift, or attacker-driven front/back-running) far enough from the quote-time price, without the trader having any way to cause the transaction to self-cancel. This is a direct value-extraction (theft) vector against ordinary traders, the primary users of `Zap.buy`/`Zap.sell`.

### Likelihood Explanation
Likelihood is moderate-to-high: any trader who signs a transaction with a generous slippage tolerance (common UX default) and experiences even modest delay before inclusion — congestion, low gas bid, or an MEV searcher intentionally delaying inclusion to wait for a better sandwich opportunity — is exposed. No privileged access or unusual conditions are required; only that the transaction remain unconfirmed for a meaningful period while price conditions move.

### Recommendation
Add a `deadline` parameter to `Zap.buy`, `Zap.buyWithPermit`, `Zap.sell`, and `Zap.sellWithPermit` (and `createToken`/`createTokenWithPermit` if desired), and revert with `block.timestamp > deadline` at the top of `_buyInternal`/`_sellInternal`, mirroring the pattern already used for permit deadlines in `PermitData`. [5](#0-4) 

### Proof of Concept
1. Alice calls `Zap.buy(token, usdcAmount, minTokensOut, referrer)` with `minTokensOut` computed from a quote taken at signing time via `Router.previewBuy`. [6](#0-5) 
2. Alice's transaction sits unconfirmed (low gas fee / congestion). During this time the curve's `reserve0/reserve1` shift from other trades and/or the LT's `exchangeRate()` drifts, both of which change the true fair value of a buy of `usdcAmount`.
3. When average fees fall enough for validators/bots to include the transaction, an MEV bot detects it in the mempool and sandwiches it: front-run buy pushes the curve price up, Alice's buy executes and still satisfies `tokensOut >= minTokensOut` (since her floor was set generously relative to the now-stale price), back-run sell captures the difference.
4. Because `_buyInternal` has no deadline check, this remains executable no matter how long the transaction has been pending, and the slippage check alone cannot prevent the sandwich — it only bounds how much can be extracted, not whether extraction is possible. [7](#0-6)

    function _buyInternal(
        address tokenAddress,
        uint256 usdcAmount,
        uint256 minTokensOut,
        address referrer
    ) internal returns (uint256 tokensOut) {
        if (usdcAmount == 0) revert InvalidInput();
        if (tokenAddress == address(0)) revert InvalidInput();
        if (usdcAmount < minUsdcAmount()) revert BelowMinAmount();
        Bonding bonding_ = _s().bonding;
        if (bonding_.creatorOf(tokenAddress) == address(0)) revert TokenNotTrading();
        if (bonding_.isGraduating(tokenAddress)) revert TokenIsGraduating();

        uint256 grossSpent;
        uint256 actualFee;
        (tokensOut, grossSpent, actualFee) = _executeBuy(tokenAddress, usdcAmount);

        if (tokensOut < minTokensOut) revert SlippageExceeded();

        if (actualFee > 0) {
            _accrueFee(tokenAddress, bonding_.creatorOf(tokenAddress), actualFee, true);
        }

        // Report the USDC actually spent, not the submitted `usdcAmount`. A
        // graduation-capped buy refunds the unused principal and fee, so the
        // two diverge there; for every other buy they're equal.
        emit Buy(tokenAddress, msg.sender, grossSpent, tokensOut);

        if (referrer != address(0) && referrer != msg.sender) {
            emit Referred(tokenAddress, msg.sender, referrer, grossSpent);
        }
    }

    function _sellInternal(
        address tokenAddress,
        uint256 tokenAmount,
        uint256 minUsdcOut
    ) internal returns (uint256 usdcOut) {
        if (tokenAmount == 0) revert InvalidInput();
        if (tokenAddress == address(0)) revert InvalidInput();
        ZapStorage storage $ = _s();
        Bonding bonding_ = $.bonding;
        if (bonding_.creatorOf(tokenAddress) == address(0)) revert TokenNotTrading();
        if (bonding_.isGraduating(tokenAddress)) revert TokenIsGraduating();

        // LT appreciation can push a curve token past the graduation threshold
        // with no buy. Selling now would drag the raised reserve back below it,
        // so graduate the token instead. The holder keeps their tokens and
        // exits on the graduated pool. Nothing is sold, so this fills `0` — only
        // take it when the caller set no floor; a positive `minUsdcOut` reverts
        // so the `usdcOut >= minUsdcOut` guarantee is never silently broken.
        if (bonding_.canGraduate(tokenAddress)) {
            if (minUsdcOut != 0) revert TokenIsGraduating();
            bonding_.triggerGraduation(tokenAddress);
            return 0;
        }

        address lt = bonding_.ltOf(tokenAddress);

        IERC20(tokenAddress).safeTransferFrom(msg.sender, address(this), tokenAmount);

        uint256 ltReceived = bonding_.isGraduated(tokenAddress)
            ? _sellOnUniswapV2(tokenAddress, lt, tokenAmount)
            : _sellOnCurve(tokenAddress, tokenAmount);

        uint256 grossUsdcEstimate = (ltReceived * IBounceLeveragedToken(lt).exchangeRate()) / 1e18;
        if (grossUsdcEstimate / 1e12 < minUsdcAmount()) revert BelowMinAmount();

        // Intentional v1 tradeoff: sells only use BounceTech's atomic
        // `redeem()` path (no `prepareRedeem` fallback/queue in Zap). If the
        // LT idle-USDC buffer is temporarily depleted, `redeem` reverts and
        // users must retry in smaller chunks after buffer replenishment.
        // Redeem into this zap (not the user) so we can deduct the fee.
        uint256 grossUsdc = IBounceLeveragedToken(lt).redeem(address(this), ltReceived, 0);

        // Symmetric with `_executeBuy`: fee charged on EVERY sell — curve
        // AND post-graduation. The `isGraduated` branch above selects the
        // venue, not the fee policy. See `_executeBuy` for the rationale.
        uint256 fee = Math.mulDiv(grossUsdc, $.sellFeeBps, BPS_DENOM, Math.Rounding.Ceil);
        usdcOut = grossUsdc - fee;

        if (usdcOut < minUsdcOut) revert SlippageExceeded();

        $.usdc.safeTransfer(msg.sender, usdcOut);

        if (fee > 0) {
            _accrueFee(tokenAddress, bonding_.creatorOf(tokenAddress), fee, false);
        }

        emit Sell(tokenAddress, msg.sender, tokenAmount, usdcOut);
    }
