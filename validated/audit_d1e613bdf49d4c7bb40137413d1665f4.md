Audit Report

## Title
Unbounded Slippage in `SwapFirstAssetTrader::refund_weight` XCM Fee Refund Swap - (File: `cumulus/primitives/utility/src/lib.rs`)

## Summary
`SwapFirstAssetTrader::refund_weight` swaps the unused portion of `total_fee` back into the asset the XCM sender originally paid with by calling `SwapCredit::swap_exact_tokens_for_tokens` with `amount_out_min` hardcoded to `None`, providing no minimum-output/slippage protection. [1](#0-0) . This contrasts with `buy_weight`, which uses a bounded exact-output swap [2](#0-1) , and with `SingleAssetExchangeAdapter::exchange_asset`, which correctly supplies `Some(want_amount)` as a minimum for its exact-in swap [3](#0-2) .

## Finding Description
`refund_weight` extracts `refund_amount` from `self.total_fee` (denominated in `Target`) and swaps it into `refund_swap_asset` via `SwapCredit::swap_exact_tokens_for_tokens(vec![Target::get(), refund_swap_asset], refund, None)` [4](#0-3) . The `SwapCredit::swap_exact_tokens_for_tokens` trait explicitly supports an `Option<Balance>` minimum-output guard for this purpose [5](#0-4) , and the pallet's extrinsic-level path (`do_swap_exact_tokens_for_tokens`) enforces a non-zero minimum via `ProvidedMinimumNotSufficientForSwap` when a caller supplies one [6](#0-5) , and the credit-based analog `do_swap_exact_credit_tokens_for_tokens` performs the identical check when `amount_out_min` is `Some` [7](#0-6) . Passing `None` bypasses this protection entirely, so the refund swap will accept whatever output the pool produces at execution time, however unfavorable.

## Impact Explanation
Because AMM pool price can move between quote/computation time and the block in which the XCM message (and its refund) is actually executed, a party able to influence transaction/message ordering around that block (e.g. a MEV-aware collator or a searcher co-located within the same block) could sandwich the refund swap, extracting value from the difference between fair price and executed price. The affected value is bounded by the unused-weight refund amount — the difference between the weight limit set by the XCM sender and the weight actually consumed — which is typically a small fraction of the total fee rather than a user's full trade amount, limiting the maximum extractable value per occurrence.

## Likelihood Explanation
This is triggerable through the ordinary user-facing path of sending an XCM message that overestimates its execution weight (a common practice, since senders must set a weight limit before knowing exact weight consumption), causing `refund_weight` to execute the unbounded swap. No privileged access is required. Exploitation likelihood depends on an adversary's ability to observe pending XCM/refund execution and control block-level transaction ordering, which is a realistic MEV threat model on permissionless parachains, though it requires more capability than a plain end user.

## Recommendation
Compute a safe, non-`None` `amount_out_min` in `refund_weight`, e.g. via `QuotePrice::quote_price_exact_tokens_for_tokens` with an applied tolerance, mirroring the pattern already used correctly in `SingleAssetExchangeAdapter::exchange_asset` [8](#0-7)  and enforced by the pallet's own extrinsics.

## Proof of Concept
No executable PoC was constructed by the reporter; the finding rests on direct code inspection of `refund_weight`'s call site (`cumulus/primitives/utility/src/lib.rs:539-544`), confirmed by reading the surrounding function and comparing it against the bounded swap in `buy_weight` (same file, lines 471-475) and the safe pattern in `SingleAssetExchangeAdapter::exchange_asset`. A concrete reproduction would require a fork/integration test that (1) sets up an `AssetConversion` pool, (2) constructs a `SwapFirstAssetTrader`, (3) calls `buy_weight` followed by `refund_weight` while a second actor moves the pool price between the two calls, and (4) shows the refunded amount is worse than a fair-price quote — this was not built or verified here; existing unit tests in `cumulus/primitives/utility/src/tests/swap_first.rs` reference `refund_weight` but were not inspected in enough depth to confirm whether slippage scenarios are covered.

	fn refund_weight(&mut self, weight: Weight, _context: &XcmContext) -> Option<AssetsInHolding> {
		log::trace!(
			target: "xcm::weight",
			"SwapFirstAssetTrader::refund_weight weight: {:?}, self.total_fee: {:?}",
			weight,
			self.total_fee,
		);
		if weight.is_zero() || self.total_fee.peek().is_zero() {
			// noting to refund.
			return None;
		}
		let refund_asset = if let Some(asset) = &self.last_fee_asset {
			// create an initial zero refund in the asset used in the last `buy_weight`.
			(asset.clone(), Fungible(0)).into()
		} else {
			return None;
		};
		let refund_amount = WeightToFee::weight_to_fee(&weight);
		if refund_amount >= self.total_fee.peek() {
			// not enough was paid to refund the `weight`.
			return None;
		}

		let refund_swap_asset = FungiblesAssetMatcher::matches_fungibles(&refund_asset)
			.map(|(a, _)| a.into())
			.ok()?;

		let refund = self.total_fee.extract(refund_amount);
		let refund = match SwapCredit::swap_exact_tokens_for_tokens(
			vec![Target::get(), refund_swap_asset],
			refund,
			None,
		) {
			Ok(refund_in_target) => refund_in_target,
			Err((refund, _)) => {
				// return an attempted refund back to the `total_fee`.
				let _ = self.total_fee.subsume(refund).map_err(|refund| {
					// error may occur if `total_fee.asset` differs from `refund.asset`, which does
					// not apply in this context.
					defensive!(
						"`total_fee.asset` must be equal to `refund.asset`",
						(self.total_fee.asset(), refund.asset())
					);
				});
				return None;
			},
		};

		let refund = AssetsInHolding::new_from_fungible_credit(refund_asset.id, Box::new(refund));
		Some(refund)
	}
