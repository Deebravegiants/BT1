### Title
Relay fee silently evaded when `EmporiumStack.signerAddress` points to a code-less (EOA) address - ([File: contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol])

### Summary
`EmporiumUpgradeable.runAction` pays the relay fee for wallet-based Emporium actions by calling `IHinkalWallet(signerAddress).doSendToRelay(...)`. Because `doSendToRelay` has no return value, Solidity inserts no `extcodesize`/return-data check on this external call. If `signerAddress` is an EOA (any address the caller controls and can produce a valid signature for) rather than an actual deployed `HinkalWallet` contract, the call to `doSendToRelay` is a silent no-op that still reports success. The transaction completes normally, funds are returned to the caller as a fresh UTXO, but the relay never receives its fee.

### Finding Description
`verifyWallet` only checks that `stack.signerAddress` produced a valid ECDSA signature over the `EmporiumStack`; it never checks that `signerAddress` is a genuine contract implementing `IHinkalWallet`: [1](#0-0) 

Since any EOA can sign an EIP‑712 message with its own key, `stack.signerAddress` can be set to an ordinary externally-owned address with no code.

When `runAction` needs to charge the relay fee for a wallet-mode transaction, it calls into `signerAddress`: [2](#0-1) [3](#0-2) 

`doSendToRelay` is declared with no return value: [4](#0-3) [5](#0-4) 

Because the interface function has no return type, the Solidity compiler does not insert a check that the call target has code. A plain `CALL` to an address without code always succeeds trivially (returns `success = true`, empty return data) without executing anything. Consequently `sendToRelayFromWallet` "succeeds" even though the fee transfer never happened, and `payRelayFees`/`runAction` proceed to completion with no error and no fee-payment assertion (unlike `_internalTransact` in `Hinkal.sol`, which explicitly requires `hasPaidToRelay`, there is no analogous check for the Emporium path): [6](#0-5) 

By contrast, if `op.invokeWallet` is used for a "stateful" op, the call `IHinkalWallet(signerAddress).callHinkalWallet(...)` *does* have a return type `(bool, bytes)`, so calling it on a code-less address reverts (insufficient return data to decode) — but an attacker simply avoids stateful ops (`stack.ops` can be empty) and only relies on the fee-payment leg, which has no such protection: [7](#0-6) 

This breaks the intended equality that the relay fee amount (`feeStructure.flatFee`, bounded by the signer-approved `stack.maxFee`) is actually transferred out of the signer's wallet to the relay before the remaining balance is returned to the caller as a private UTXO via `handleOut`: [8](#0-7) 

### Impact Explanation
This allows an unprivileged EOA (acting as its own `signerAddress`) to have a relay process and pay for a shielded withdrawal via the Emporium wallet path while the protocol-mandated relay fee is never actually transferred anywhere. The relay performs work (submits proof, pays gas) and receives no compensation — "theft ... of protocol/relay fees," a High-impact outcome per the specified impact classes. No `revert` occurs anywhere in this path, so this is not merely a DoS/griefing scenario; the transaction completes and funds are returned intact to the attacker while fee obligations silently vanish.

### Likelihood Explanation
Likelihood is high for any wallet-mode Emporium withdrawal where the fee-paying address is not independently verified to be a deployed `HinkalWallet` contract on-chain. The only requirement is that the attacker signs the EIP‑712 `EmporiumStack` message with their own private key (trivial, since anyone can sign for their own address) and sets `stack.signerAddress` to that same address instead of a real wallet contract. No proof forgery, no privileged role, and no additional preconditions are needed beyond crafting `circomData`/`EmporiumStack` for a normal withdrawal with `ops = []` (or ops that avoid `invokeWallet`).

### Recommendation
Before relying on `IHinkalWallet(signerAddress)` calls for fee payment (and wallet invocation), explicitly verify the target has code, e.g. `require(signerAddress.code.length > 0, "signer must be a wallet contract")`, and/or restrict `signerAddress` to addresses deployed through a trusted wallet factory/registry (verify the expected `CREATE2` bytecode hash, analogous to how `HinkalFactory` verifies bytecode via `bytecodeHash`). Additionally, add an explicit on-chain assertion that the relay fee was actually paid (mirroring the `hasPaidToRelay` check in `Hinkal._internalTransact`) rather than assuming success of a call with no return value.

### Proof of Concept
1. Attacker (as user) constructs an Emporium withdrawal `circomData` with `relay = <thirdPartyRelay>`, `feeStructure.flatFee = X > 0`, and `externalActionData.externalActionMetadata` encoding an `EmporiumStack` with `ops = []`, `signerAddress = attackerEOA`, `maxFee >= X`, `deadline` in the future.
2. Attacker signs the `EMPORIUM_SIGNATURE_TYPEHASH` message with `attackerEOA`'s own private key — `verifyWallet` passes since `ecrecover` returns `attackerEOA`.
3. Relay submits `Hinkal.transact(...)`, which calls `_externalTransact` → `EmporiumUpgradeable.runAction`.
4. `stack.ops.length == 0` so the operations loop is skipped (no revert path exercised).
5. `payRelayFees` → `payRelay` → `sendToRelayFromWallet` → `IHinkalWallet(attackerEOA).doSendToRelay(relay, X, token)`; since `attackerEOA` has no code and `doSendToRelay` has no return value, this call succeeds with zero effect — no tokens move to `relay`.
6. Execution continues normally; `handleOut` sends the full remaining balance back to Hinkal as a UTXO for the attacker, and the relay is never paid fee `X` despite having relayed the transaction.

    function verifyWallet(
        EmporiumStack memory stack,
        CircomData calldata circomData
    ) internal {
        EmporiumStorageVars storage $ = _getEmporiumStorage();

        if ($.usedMessages[circomData.emporiumMessage]) {
            revert UsedMessage();
        }

        $.usedMessages[circomData.emporiumMessage] = true;

        if (stack.signerAddress == address(0)) {
            return;
        }

        bytes32 hashedMessage = _hashTypedDataV4(
            keccak256(
                abi.encode(
                    EMPORIUM_SIGNATURE_TYPEHASH,
                    circomData.emporiumMessage,
                    _hashEmporiumOps(stack.ops),
                    stack.maxFee,
                    stack.deadline
                )
            )
        );

        (address recoveredAddress, ECDSA.RecoverError err) = ECDSA.tryRecover(
            hashedMessage,
            stack.v,
            stack.r,
            stack.s
        );
        bool verified = err == ECDSA.RecoverError.NoError &&
            recoveredAddress == stack.signerAddress;
        if (!verified) {
            revert InvalidSignature();
        }
