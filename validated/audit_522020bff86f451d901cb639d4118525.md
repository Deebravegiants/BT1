## Analysis

The report's bug class — a value/attribution slot that is claimed on a first-write basis, keyed by public data anyone can resubmit, so a front-runner can seize the slot and redirect funds intended for the original submitter — has a direct analog in Hyperbridge's outbound consensus relayer-reward mechanism. ### Title
Consensus-proof front-running lets a copycat relayer steal `OutboundConsensusDeliveryReward` attribution - (File: evm/src/core/EvmHost.sol, evm/src/core/HandlerV2.sol)

### Summary
`EvmHost._epochs[authoritySetId]` records "the relayer that first submitted the consensus proof for the given epoch" via `recordEpoch`, called from `HandlerV2.handleConsensus` with `_msgSender()` as the credited relayer. `handleConsensus` is a fully public, unauthenticated function that accepts a valid consensus proof from anyone. Because Hyperbridge's `pallet-ismp-relayer::claim_outbound_consensus_delivery_reward` pays the `OutboundConsensusDeliveryReward` to whichever address is recorded in that `_epochs[set_id]` slot, an attacker who observes a legitimate relayer's `handleConsensus` transaction in the mempool can copy its calldata (the proof is public data, not bound to a submitter) and resubmit it with higher gas to land first, becoming the address permanently recorded in `_epochs[set_id]` and thus the party the destination-chain reward is later paid out to.

### Finding Description
`recordEpoch` is a simple first-write-wins mapping: [4](#0-3) 

It is invoked unconditionally from `handleConsensus`, whose only caller-derived value is `_msgSender()`: [5](#0-4) 

`handleConsensus` itself has no access control beyond `notFrozen(host)` — any address can submit any valid consensus proof bytes it observes. Unlike the Substrate-side BEEFY prover reward mechanism (`pallet-beefy-consensus-proofs`), which explicitly binds each SP1 proof to its submitting account via a committed nonce so "a proof cannot be stolen... copying the proof bytes from the mempool and submitting them under a different account is rejected," the EVM `IConsensusV2.verify()` / `HandlerV2.handleConsensus` path has no such binding. The proof content that advances Hyperbridge's view of the destination consensus state is identical regardless of who submits it, so `_msgSender()` is the only thing distinguishing "credit" — and it is exactly the value an MEV searcher can substitute by front-running.

The destination-side reward pallet trusts this slot as ground truth for attribution: [6](#0-5) 

and pays out to whoever can produce a signature recovering to the address stored at that slot: [7](#0-6) 

Since the attacker chose to submit the copied proof under their own address, they hold the matching key and can sign the claim themselves, collecting the full `OutboundConsensusDeliveryReward` for a rotation whose actual verification/delivery work was performed by the honest relayer whose transaction they front-ran.

### Impact Explanation
This is direct theft of relayer reward funds from the Hyperbridge treasury payout: the address entitled to the `OutboundConsensusDeliveryReward` for a given `(destination, set_id)` is permanently fixed by whichever address wins the mempool race, and that race can be won by copying public, unauthenticated calldata rather than by performing any of the actual work of running a relayer against the source chain. Because `_epochs[set_id]` is set once (`if (authoritySetId <= _currentEpoch) return;`) and never updated afterward, and `OutboundConsensusRotationsClaimed` enforces one payout per `(destination, set_id)`, the honest relayer is permanently and irreversibly denied the reward it earned, while the treasury loses the same amount to an unproductive front-runner. This falls squarely within the allowed "relayer fee and reward accounting" analog category.

### Likelihood Explanation
Likelihood is high in an adversarial MEV environment: `handleConsensus` transactions are broadcast publicly to mempools on every destination EVM chain before inclusion, the proof bytes are self-contained and require no secret to replay, and gas-price front-running is a well-understood, cheap, and automatable technique. The reward being non-trivial (BRIDGE token payouts per accepted mandatory rotation) creates a direct financial incentive to run exactly this kind of sniping bot.

### Recommendation
Bind consensus-proof submission credit to the account that actually possesses/produced the proof, mirroring the SP1 "Prover-Bound Proofs" design already used in `pallet-beefy-consensus-proofs`: require the consensus proof (or its associated public inputs) to commit to the submitting address/signature, and have `EvmHost.recordEpoch` / `HandlerV2.handleConsensus` verify that binding before crediting `_msgSender()`. Alternatively, decouple "who delivered the state update" from "who is owed the reward" by having the legitimate relayer include a self-signed claim inside the same transaction that only they could have produced, so a copied calldata blob cannot be replayed profitably by a third party.

### Proof of Concept
1. Honest relayer R constructs a valid consensus proof `proof` advancing Hyperbridge's authority set to `set_id`, and broadcasts `HandlerV2.handleConsensus(host, proof)` to the destination EVM chain's mempool.
2. Attacker A observes the pending transaction, copies `proof` verbatim, and submits `HandlerV2.handleConsensus(host, proof)` with a higher gas price/priority fee.
3. A's transaction is mined first; `IConsensusV2.verify` succeeds identically for A's copy since the proof content is unchanged; `host.recordEpoch(epoch, A)` is called, setting `_epochs[epoch] = A`. R's now-redundant transaction reverts or is a no-op (`keccak256(previousState) == keccak256(verifiedState)` returns early).
4. A builds an `OutboundConsensusDeliveryClaim` on Hyperbridge, signing `outbound_consensus_delivery_message(set_id, destination, payee)` with the key controlling address A, and submits `claim_outbound_consensus_delivery_reward`.
5. `process_outbound_consensus_delivery_claim` verifies the state proof against `_epochs[set_id] == A`, recovers A's signature matching, and pays the full `OutboundConsensusDeliveryReward` to A — despite A having contributed nothing but copying R's public transaction.

    /**
     * @dev Record the relayer that first submitted a consensus proof for a new authority set epoch.
     * Only callable by the configured handler. Stale or duplicate epoch IDs are ignored.
     * @param authoritySetId the new authority set / epoch ID
     * @param relayer the relayer that delivered the consensus proof
     */
    function recordEpoch(uint256 authoritySetId, address relayer) external restrict(_hostParams.handler) {
        if (authoritySetId <= _currentEpoch) return;
        _currentEpoch = authoritySetId;
        _epochs[authoritySetId] = relayer;
        emit NewEpoch({authoritySetId: authoritySetId, relayer: relayer});
    }

    function handleConsensus(IHost host, bytes calldata proof) external notFrozen(host) {
        uint256 delay = block.timestamp - host.consensusUpdateTime();
        if (delay >= host.unStakingPeriod()) revert ConsensusClientExpired();

        bytes memory previousState = host.consensusState();
        (bytes memory verifiedState, IntermediateState[] memory intermediates, uint256 nextAuthoritySetId) =
            IConsensusV2(host.consensusClient()).verify(previousState, proof);

        if (keccak256(previousState) == keccak256(verifiedState)) return;
        host.storeConsensusState(verifiedState);

        uint256 intermediatesLen = intermediates.length;
        for (uint256 i = 0; i < intermediatesLen; i++) {
            IntermediateState memory intermediate = intermediates[i];
            uint256 latestHeight = host.latestStateMachineHeight(intermediate.stateMachineId);
            if (latestHeight != 0 && intermediate.height > latestHeight) {
                StateMachineHeight memory stateMachineHeight =
                    StateMachineHeight({stateMachineId: intermediate.stateMachineId, height: intermediate.height});
                host.storeStateMachineCommitment(stateMachineHeight, intermediate.commitment);
            }
        }

        // `nextAuthoritySetId` identifies the upcoming set; the relayer that delivered the proof
        // is credited as the relayer for the just-ended epoch (`nextAuthoritySetId - 1`).
        // If `nextAuthoritySetId == 0` no rotation has occurred, so there is nothing to record.
        if (nextAuthoritySetId == 0) return;
        uint256 epoch = nextAuthoritySetId - 1;
        if (epoch > host.currentEpoch()) {
            host.recordEpoch(epoch, _msgSender());
        }
    }
