### Title
Suppliers can atomically exit before bad-debt cleanup and socialize the loss to remaining suppliers - (File: contracts/pool/src/interest.rs)

### Summary
An unprivileged supplier can withdraw at the pre-write-down supply index, invoke permissionless `clean_bad_debt`, and redeposit atomically. Cleanup reduces the market’s supply index for unpaid debt, so the attacker preserves its full deposit while forcing the remaining suppliers to absorb the loss.

### Finding Description
`Controller::withdraw` authorizes a normal withdrawal, treats amount `0` as withdraw-all, and settles it at the current pool supply index. [1](#0-0)  Pool withdrawal burns the supplier’s shares, checks reserves/utilization and debits cash, but does not reserve an anticipated bad-debt loss against that withdrawal. [2](#0-1) [3](#0-2) 

`Controller::clean_bad_debt` is permissionless and only requires caller authorization. [4](#0-3)  During cleanup, the controller submits the victim’s remaining borrow positions to `pool_seize_positions_call`. [5](#0-4)  For each borrow leg, the pool converts the debt to underlying value and applies it to the supply index. [6](#0-5)  `apply_bad_debt_to_supply_index` reduces the index pro-rata across all suppliers that remain after the attacker’s withdrawal. [7](#0-6) 

A caller-controlled contract can sequence these public controller calls atomically: withdraw all, clean the eligible insolvent account, then supply again through `account_id = 0`. This sequence is already exercised by the repository’s integration test, which withdraws `ETH`, calls `CleanBadDebt`, redeposits, and asserts that the attacker kept its stake while another supplier absorbed the write-down. [8](#0-7) 

### Impact Explanation
Remaining suppliers suffer a direct loss of claim value because their supply-index denominated balances are reduced by debt that the attacker would otherwise have shared pro-rata. [9](#0-8)  A dominant supplier can concentrate the loss onto small remaining suppliers, potentially reducing their claims to the supply-index floor. The attacker can then redeposit at the reduced index without having paid its share. This constitutes theft/redistribution of user funds rather than merely route-quality MEV.

### Likelihood Explanation
The path requires an account eligible for permissionless cleanup—insolvent debt with remaining collateral at or below the bad-debt dust threshold—and enough withdrawable cash and post-withdrawal utilization headroom for the attacker to exit. [10](#0-9)  Those conditions are externally observable and the calls are permissionless. A supplier can monitor public account/market state and use a contract to execute the sequence atomically when the state becomes eligible.

### Recommendation
Apply pending bad-debt write-downs before permitting ordinary withdrawals from the affected market, or treat pending unrecoverable debt conservatively when calculating withdrawal solvency and available cash. Alternatively, prevent a supplier from exiting and immediately re-entering around `clean_bad_debt` by requiring cleanup/write-down execution before withdrawal settlement or by attributing cleanup losses to all supply held at a recorded pre-eligibility snapshot.

### Proof of Concept
For a market `hub_asset` containing attacker supply and a victim account eligible for `clean_bad_debt`:

1. Attacker contract invokes:
   ```text
   withdraw(
       caller = attacker_contract,
       account_id = attacker_account,
       withdrawals = [(hub_asset, 0)],
       to = attacker_contract
   )
   ```
   The zero amount selects withdraw-all and pays at the pre-write-down index. [11](#0-10) 

2. In the same contract orchestration, invoke:
   ```text
   clean_bad_debt(
       caller = attacker_contract,
       account_id = victim_account
   )
   ```
   The victim’s borrow position is seized and its unpaid debt reduces the market supply index. [12](#0-11) [6](#0-5) 

3. Invoke:
   ```text
   supply(
       caller = attacker_contract,
       account_id = 0,
       spoke_id = attacker_spoke,
       assets = [(hub_asset, withdrawn_amount)]
   )
   ```
   A zero account id creates a new Normal account and mints shares at the post-write-down index. [13](#0-12) 

The attacker retains approximately the full underlying value while suppliers who remained in the market own shares worth less after the index reduction; the repository test demonstrates this exact ordering and asserts the remaining supplier absorbs the entire write-down. [14](#0-13)

    env: &Env,
    account: &mut Account,
    recipient: &Address,
    aggregated: &AggregatedPayments,
    cache: &mut Context,
) -> Vec<HubPayment> {
    let mut entries: Vec<PoolWithdrawEntry> = Vec::new(env);
    for (hub_asset, amount) in aggregated.iter() {
        enforce_spoke_asset_flags(
            env,
            cache,
            account.spoke_id,
            &hub_asset,
            FreezePolicy::AllowOnExit,
        );
        let position = get_supply_position_or_panic(env, account, &hub_asset);
        let requested = if amount == 0 {
            WITHDRAW_ALL_SENTINEL

            amount

            action: make_pool_action(&position, requested, hub_asset.clone()),
            protocol_fee: 0,

        recipient,

        cache,

        paid.push_back((entry.action.hub_asset, result.actual_amount));

/// Socializes `bad_debt` by reducing the supply index (capped at total supply value).
///
/// Used when seizing unpaid debt: remaining supplier claims shrink pro-rata.
/// No-op when total supplied value is zero. Floors the resulting index at
/// [`SUPPLY_INDEX_FLOOR_RAW`] to avoid a zero index.
pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}

#[test]
fn exit_then_clean_then_re_enter_dodges_the_write_down_when_utilization_allows() {
    let Seed {
        t,
        runner,
        runner_account,
        victim,
    } = seed(true, 0.0);
    let bob_before = t.supply_balance_raw(BOB, "ETH");
    let ops: Vec<Op> = vec![
        &t.env,
        withdraw_op(&t, runner_account, "ETH", 0, None),
        Op::CleanBadDebt(AccountOp { account_id: victim }),
        supply_op(&t, 0, "ETH", 50 * U),
    ];
    let new_id = t
        .run_script(&runner, &ops)
        .expect("atomic exit, clean, re-enter");
    assert!(new_id > 0 && new_id != runner_account);
    assert!(
        t.supply_balance_raw_for(new_id, "ETH") >= 50 * U - 1,
        "the runner kept its whole stake"
    );
    assert!(
        t.supply_balance_raw(BOB, "ETH") < bob_before,
        "BOB absorbed the entire write-down"
    );
}
