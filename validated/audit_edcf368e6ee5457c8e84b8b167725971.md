### Title
Global contract identity is bound only to a reusable `AccountId` string, allowing account recreation to hijack shared contract code for all existing consumers - (File: `runtime/runtime/src/global_contracts.rs`)

### Summary
NEAR's `GlobalContractDeployMode::AccountId` mode lets an account deploy WASM code that many other, unrelated accounts can adopt via `UseGlobalContractAction` by referencing `GlobalContractIdentifier::AccountId(<owner>)` [1](#0-0)  instead of pinning a specific code hash. The identity of "who owns this shared implementation" is nothing more than the literal `AccountId` string. Because deleted account names can later be recreated by an unrelated party, and because `remove_account` never cleans up the `GlobalContractCode`/`GlobalContractNonce` trie entries tied to that name, a brand-new, completely unprivileged account can re-register the deleted name and push new (potentially malicious) code that is automatically inherited by every pre-existing account still referencing that identifier - mirroring the Ambire finding where a privileged party controlling a shared "implementation" could silently and unilaterally change behavior for every dependent, without their consent.

### Finding Description
`DeployGlobalContractAction` with `GlobalContractDeployMode::AccountId` stores contract code keyed only by the deploying `AccountId`, explicitly documented as mutable/owner-updatable: [2](#0-1) 

`initiate_distribution` derives the `GlobalContractIdentifier::AccountId(account_id)` purely from the current predecessor's account id at deploy time, with no binding to any persistent public key, creation timestamp, or account "generation": [3](#0-2) 

Consumers call `UseGlobalContractAction`, which resolves the code purely by looking up the current `TrieKey::GlobalContractCode { identifier }` — it does not pin to a code hash or to any specific "version"/owner key when `AccountId` mode is used, so every future redeploy under that identifier is automatically inherited by all past adopters: [4](#0-3) 

Crucially, when an account is deleted, `remove_account` removes the `Account`, its local `ContractCode`, access/gas keys and contract data — but it never touches `TrieKey::GlobalContractCode` or `TrieKey::GlobalContractNonce` entries for global contracts previously deployed under that account's name: [5](#0-4) 

Named NEAR accounts (e.g. `alice.near`) can be deleted via `DeleteAccountAction` and later recreated as a brand-new account by any party able to satisfy the normal creation rule (top-level registrar or direct parent of a sub-account) — `action_create_account` performs no check that the name was never previously used, it simply re-initializes a fresh `Account`: [6](#0-5) 

Putting this together: if `alice.near` deploys a global contract in `AccountId` mode and many accounts across the network call `UseGlobalContractAction` with `GlobalContractIdentifier::AccountId(alice.near)`, then `alice.near` is later deleted (e.g. voluntarily, or because it fails the storage/gas-key checks and is force-deleted, or simply chooses to exit), and the name is subsequently recreated by an entirely different, unrelated, unprivileged party (nothing prevents renaming/re-registration of a freed account id), that new controller can submit an ordinary `DeployGlobalContractAction` with `AccountId` mode. Because the nonce/code storage under that identifier persists independently of the account's lifecycle, this redeploy is accepted as a normal "update" via `check_and_update_nonce`/`apply_distribution_current_shard`: [7](#0-6) 

All pre-existing accounts that still reference `GlobalContractIdentifier::AccountId(alice.near)` will transparently begin executing this new, attacker-controlled code the next time they are invoked — with no notification, no re-authorization, and no re-`UseGlobalContractAction` required from them.

### Impact Explanation
Every account that previously opted into `AccountId`-mode shared code implicitly trusts that identifier to remain controlled by the same party forever. Since NEAR account names are freely reusable after deletion and the global-contract storage/nonce state is not tied to the account's lifetime, control over "who can push code to all dependents" silently transfers to whoever re-registers the name. The new controller can deploy WASM that drains balances, corrupts contract state, or simply reverts/panics on every call (functionally bricking every dependent account, the direct analog of the Ambire "destroy the shared implementation" scenario). This is a genuine unauthorized state/behavior change reachable purely through ordinary, unprivileged transactions (`DeleteAccount`, `CreateAccount`, `DeployGlobalContract`) with no validator, P2P, or malicious-node involvement.

### Likelihood Explanation
The trigger path requires only:
1. An `AccountId`-mode global contract with third-party adopters (an explicitly supported, documented usage pattern).
2. The owning account being deleted (which can happen at will by its own controller, or due to gas-key/storage forced-deletion paths).
3. Anyone re-registering that same account name and deploying new code.

None of these steps require special privilege beyond normal account/contract lifecycle actions available to any user, making this readily reachable in production usage of the global-contracts (NEP-591) feature.

### Recommendation
Bind `GlobalContractIdentifier::AccountId` global contracts to a persistent, non-reusable identity rather than the raw `AccountId` string — for example, key the global contract record by `(account_id, account creation nonce/generation)` or by the account's original public key, and/or invalidate/require re-consent from consumers when the owning account is deleted. At minimum, `remove_account` (or `action_delete_account`) should purge or freeze any `GlobalContractCode`/`GlobalContractNonce` entries associated with that account id so a freshly recreated account cannot silently inherit control over a previously-deployed shared implementation.

### Proof of Concept
1. Account `alice.near` submits `DeployGlobalContractAction { code: benign_wasm, deploy_mode: AccountId }` — global contract is distributed and stored under `GlobalContractIdentifier::AccountId(alice.near)` (`runtime/runtime/src/global_contracts.rs:142-169`).
2. Accounts `bob.near`, `carol.near`, ... submit `UseGlobalContractAction { contract_identifier: AccountId(alice.near) }`, adopting the shared code (`runtime/runtime/src/global_contracts.rs:75-107`).
3. `alice.near` submits `DeleteAccountAction`; `remove_account` deletes the account/local data but leaves `TrieKey::GlobalContractCode`/`GlobalContractNonce` for identifier `AccountId(alice.near)` untouched (`core/store/src/utils/mod.rs:504-510`).
4. An unrelated party recreates `alice.near` (via the registrar/parent-account creation path, `runtime/runtime/src/actions.rs:167-209`) and submits a new `DeployGlobalContractAction { code: malicious_wasm, deploy_mode: AccountId }`, which is accepted as a normal nonce-incrementing update (`runtime/runtime/src/global_contracts.rs:190-234`).
5. On their next invocation, `bob.near` and `carol.near` execute `malicious_wasm` without ever re-submitting `UseGlobalContractAction`, since their `AccountContract::GlobalByAccount(alice.near)` resolves code by identifier lookup at call time.

pub(crate) fn use_global_contract(
    state_update: &mut TrieUpdate,
    account_id: &AccountId,
    account: &mut Account,
    contract_identifier: &GlobalContractIdentifier,
    result: &mut ActionResult,
) -> Result<(), RuntimeError> {
    let key = TrieKey::GlobalContractCode { identifier: contract_identifier.clone().into() };
    if !state_update.contains_key(&key, AccessOptions::DEFAULT)? {
        result.result = Err(ActionErrorKind::GlobalContractDoesNotExist {
            identifier: contract_identifier.clone(),
        }
        .into());
        return Ok(());
    }
    clear_account_contract_storage_usage(state_update, account_id, account)?;
    if account.contract().is_local() {
        state_update.remove(TrieKey::ContractCode { account_id: account_id.clone() });
    }
    let contract = match contract_identifier {
        GlobalContractIdentifier::CodeHash(code_hash) => AccountContract::Global(*code_hash),
        GlobalContractIdentifier::AccountId(id) => AccountContract::GlobalByAccount(id.clone()),
    };
    account.set_storage_usage(
        account.storage_usage().checked_add(contract_identifier.len() as u64).ok_or_else(|| {
            StorageError::StorageInconsistentState(format!(
                "Storage usage integer overflow for account {}",
                account_id
            ))
        })?,
    );
    account.set_contract(contract).or_inconsistent_state(account_id)?;
    Ok(())

fn initiate_distribution(
    state_update: &mut TrieUpdate,
    account_id: AccountId,
    contract_code: Arc<[u8]>,
    deploy_mode: &GlobalContractDeployMode,
    current_shard_id: ShardId,
    result: &mut ActionResult,
) -> Result<(), RuntimeError> {
    let id = match deploy_mode {
        GlobalContractDeployMode::CodeHash => {
            GlobalContractIdentifier::CodeHash(hash(&contract_code))
        }
        GlobalContractDeployMode::AccountId => {
            GlobalContractIdentifier::AccountId(account_id.clone())
        }
    };
    // Increment the nonce and write it to state immediately to prevent multiple
    // distributions with the same nonce from being initiated. This requires
    // allowing the same nonce in the freshness check when applying the
    // distribution receipt.
    let nonce = increment_nonce(state_update, &id)?;
    let distribution_receipt =
        GlobalContractDistributionReceipt::new(id, current_shard_id, vec![], contract_code, nonce);
    let distribution_receipts =
        Receipt::new_global_contract_distribution(account_id, distribution_receipt);
    // No need to set receipt_id here, it will be generated as part of apply_action_receipt
    result.new_receipts.push(distribution_receipts);
    Ok(())

fn apply_distribution_current_shard(
    receipt: &Receipt,
    global_contract_data: &GlobalContractDistributionReceipt,
    apply_state: &ApplyState,
    state_update: &mut TrieUpdate,
) -> Result<Compute, RuntimeError> {
    let identifier = match &global_contract_data.id() {
        GlobalContractIdentifier::CodeHash(hash) => GlobalContractCodeIdentifier::CodeHash(*hash),
        GlobalContractIdentifier::AccountId(account_id) => {
            GlobalContractCodeIdentifier::AccountId(account_id.clone())
        }
    };

    let is_nonce_fresh = check_and_update_nonce(global_contract_data, &identifier, state_update)?;
    if !is_nonce_fresh {
        return Ok(0);
    }

    let config = apply_state.config.wasm_config.clone();
    let trie_key = TrieKey::GlobalContractCode { identifier };
    let code_len = global_contract_data.code().len() as u64;
    state_update.set(trie_key, global_contract_data.code().to_vec());
    state_update.commit(StateChangeCause::ReceiptProcessing { receipt_hash: receipt.get_hash() });
    let code_hash = match global_contract_data.id() {
        GlobalContractIdentifier::CodeHash(hash) => Some(*hash),
        GlobalContractIdentifier::AccountId(_) => None,
    };
    precompile_contract_with_warming(
        &ContractCode::new(global_contract_data.code().to_vec(), code_hash),
        config,
        apply_state.next_wasm_config.clone(),
        apply_state.cache.as_deref(),
    );
    near_vm_runner::report_metrics(apply_state.shard_id, "global_contract");
    let fees = &apply_state.config.fees;
    let per_byte_total = fees
        .deploy_global_contract_execution_per_byte
        .checked_mul(code_len)
        .ok_or(IntegerOverflowError)?;
    let compute = fees
        .deploy_global_contract_execution_base
        .checked_add(per_byte_total)
        .ok_or(IntegerOverflowError)?;
    Ok(compute)
}

pub(crate) fn action_create_account(
    fee_config: &RuntimeFeesConfig,
    account_creation_config: &AccountCreationConfig,
    account: &mut Option<Account>,
    actor_id: &mut AccountId,
    account_id: &AccountId,
    predecessor_id: &AccountId,
    result: &mut ActionResult,
) {
    if account_id.is_top_level() {
        if account_id.len() < account_creation_config.min_allowed_top_level_account_length as usize
            && predecessor_id != &account_creation_config.registrar_account_id
        {
            // A short top-level account ID can only be created registrar account.
            result.result = Err(ActionErrorKind::CreateAccountOnlyByRegistrar {
                account_id: account_id.clone(),
                registrar_account_id: account_creation_config.registrar_account_id.clone(),
                predecessor_id: predecessor_id.clone(),
            }
            .into());
            return;
        } else {
            // OK: Valid top-level Account ID
        }
    } else if !account_id.is_sub_account_of(predecessor_id) {
        // The sub-account can only be created by its root account. E.g. `alice.near` only by `near`
        result.result = Err(ActionErrorKind::CreateAccountNotAllowed {
            account_id: account_id.clone(),
            predecessor_id: predecessor_id.clone(),
        }
        .into());
        return;
    } else {
        // OK: Valid sub-account ID by proper predecessor.
    }

    *actor_id = account_id.clone();
    *account = Some(Account::new(
        Balance::ZERO,
        Balance::ZERO,
        AccountContract::None,
        fee_config.storage_usage_config.num_bytes_account,
    ));
