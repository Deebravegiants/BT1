### Title
Missing shop-domain validation before sending `client_secret` in OAuth callback - (File: `lib/shopify_api/auth/oauth.rb`)

### Summary
`ShopifyAPI::Auth::Oauth.validate_auth_callback` derives the token-exchange host directly from the unsanitized `auth_query.shop` value and never runs it through `Utils::ShopValidator`, unlike every other credential-issuing flow in the gem (`token_exchange.rb`, `client_credentials.rb`, `refresh_token.rb`). HMAC verification proves the `shop` field wasn't tampered with in transit, but it does not prove `shop` is actually a `*.myshopify.com`/trusted Shopify host — that binding is supposed to be enforced separately by `ShopValidator.sanitize!`, and here it isn't.

### Finding Description
`validate_auth_callback` computes the HMAC over the callback bytes via `Utils::HmacValidator.validate(auth_query)` [1](#0-0) , and `AuthQuery#to_signable_string` includes `shop` in the signed string [2](#0-1) . That only guarantees "bytes verified == bytes parsed" — it does not guarantee "shop == a trusted Shopify domain". The code then immediately builds the token-exchange host from that raw string:

```ruby
null_session = Auth::Session.new(shop: auth_query.shop)
...
client = Clients::HttpClient.new(session: null_session, base_path: "/admin/oauth")
```
and `auth_base_uri(shop)` builds `"https://#{shop}/admin/oauth"` with no sanitation [3](#0-2) . The POST body containing `client_id` and `client_secret` (line 74-79) is sent to that host [4](#0-3) .

By contrast, the other credential-issuing code paths in this gem explicitly call `Utils::ShopValidator.sanitize!`/`sanitize_shop_domain` before trusting a shop value for a network call — confirmed by grep hits in `lib/shopify_api/auth/token_exchange.rb`, `lib/shopify_api/auth/client_credentials.rb`, and `lib/shopify_api/auth/refresh_token.rb` [5](#0-4) . `oauth.rb` has no such call anywhere in `validate_auth_callback`. This is the exact "host validated versus host that receives the client_secret" mismatch called out in the analog rules: the equality that should hold is `sanitize!(auth_query.shop) == host_that_receives_client_secret`, but the code instead uses `auth_query.shop` directly for the latter without ever invoking the former.

### Impact Explanation
If the HMAC-signing party (Shopify) will happily sign a callback for any hostname/shop value supplied by the app during `begin_auth` (which itself performs no `ShopValidator` sanitation either [6](#0-5) ), the loop from "value the app sent to Shopify's authorize endpoint" to "value trusted as the token-exchange host" never passes through the one function (`ShopValidator`) whose entire purpose in this codebase is to guarantee the host is `myshopify.com`/`shopify.com`/etc. Any code path that lets `shop` reach `begin_auth`/`validate_auth_callback` un-sanitized ends with the app's `client_secret` being POSTed to whatever host ends up in `auth_query.shop`, which is High severity (credential leakage of the app's `client_secret` to a non-Shopify host).

### Likelihood Explanation
Medium: exploitation requires the host application to pass an unsanitized `shop`/`host` value into `begin_auth` (common integration pattern is to take `shop` straight from the initial, unauthenticated install request query string) and for that same value to flow through to the callback. The gem provides `ShopValidator` for exactly this purpose but conspicuously does not invoke it inside `oauth.rb`, unlike its sibling flows, so the gem itself does not close this gap even for well-behaved callers who assume the library validates shop domains as it does everywhere else.

### Recommendation
Call `Utils::ShopValidator.sanitize!(shop)` (or `sanitize_shop_domain`) at the top of both `Oauth.begin_auth` and `Oauth.validate_auth_callback`, matching the pattern already used in `token_exchange.rb`, `client_credentials.rb`, and `refresh_token.rb`, before the value is used to build `auth_base_uri` or included in any HTTP request carrying `client_id`/`client_secret`.

### Proof of Concept
1. Host application receives an unauthenticated request with `shop=attacker.example` and calls `ShopifyAPI::Auth::Oauth.begin_auth(shop: "attacker.example", redirect_path: ...)` without pre-sanitizing (no call to `ShopValidator` inside the gem itself).
2. `auth_base_uri("attacker.example")` returns `"https://attacker.example/admin"`, and the generated `auth_route` sends the browser to `https://attacker.example/admin/oauth/authorize?...`.
3. If the flow completes with a callback whose `shop=attacker.example` and a valid `hmac` (computed by whatever service is driving the callback, since the value was accepted from step 1 without a trusted-domain check), `validate_auth_callback` proceeds to `auth_base_uri("attacker.example")` → `https://attacker.example/admin/oauth/access_token`, and the POST body containing `client_secret` (line 76) is sent to `attacker.example` [7](#0-6) .

# typed: strict
# frozen_string_literal: true

require "addressable/uri"

module ShopifyAPI
  module Utils
    module ShopValidator
      TRUSTED_SHOPIFY_DOMAINS = T.let(
        [
          "shopify.com",
          "myshopify.io",
          "myshopify.com",
          "spin.dev",
          "shop.dev",
        ].freeze,
        T::Array[String],
      )

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
