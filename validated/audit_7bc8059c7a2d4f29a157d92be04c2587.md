Based on my analysis of the external-action contracts, I found a concrete accounting gap that is the direct analog of the Connext Executor bug (tokens left/unaccounted after an approve+external‑call pattern), but it manifests as an incomplete on-chain balance reconciliation rather than a mere "stuck funds" annoyance.

### Title
Swap external actions credit only the output-token balance delta, leaving input-token surplus unaccounted and stealable by a later caller - (File: contracts/external-actions/swaps/ExternalActionSwap.sol, contracts/external-actions/swaps/LifiExternalAction.sol)

### Summary
`ExternalActionSwap.swap()` / `LifiExternalAction.callRouter()` grant the fixed `router` an **unlimited, persistent** ERC20 allowance and then forward a fully attacker/off-chain-controlled `externalActionMetadata` blob straight into `router.call(...)`, without ever verifying how much of the input token the call actually consumed.

### Finding Description
`LifiExternalAction.callRouter()` only measures the **output** token balance before/after the call: [1](#0-0) 

`ExternalActionSwap.swap()` then unconditionally forwards the entire measured `swappedAmount` (minus fees) to `msg.sender` as a brand-new UTXO, with `inputAmount` (`-deltaAmounts[0]`, i.e. the officially declared debit from the caller's shielded balance) never being reconciled against the input token's actual balance change in the contract: [2](#0-1) 

Contrast this with `EmporiumUpgradeable.runAction()`, which computes `balancesBefore`/`balancesAfter` for **every** token in `circomData.erc20TokenAddresses` and enforces `balanceChange >= 0` per token before sweeping the result to the caller: [3](#0-2) 

So Emporium correctly ties every token's local balance movement to the declared `deltaAmountChanges`, but `ExternalActionSwap`/`LifiExternalAction` only performs this check for the output side. The input side's local equality — "balance decrease of `inputToken` in this contract == declared `inputAmount`" — is never asserted.

At the top level, `Hinkal.transact()` only reconciles **Hinkal's own** balance change against `amountChanges[i] + utxoAmount` for each declared token: [4](#0-3) 

This check is self-consistent with whatever the external action reports back as `utxoSet`/actual transfer — it has no visibility into the external action contract's own internal token accounting, so it cannot catch a mismatch that happens purely inside `ExternalActionSwap`/`LifiExternalAction`.

Because `approveUnlimited(inputToken, router)` persists indefinitely and `externalActionMetadata` is arbitrary, attacker-chosen calldata forwarded verbatim to a fixed router address, any input-token balance sitting in the `LifiExternalAction` contract (regardless of which transaction funded it) is available to be pulled by the router on behalf of whichever transaction's calldata instructs it to do so. Since the code path that computes the resulting shielded UTXO (`swappedAmount`) is driven solely by the output-token balance diff, a transaction that debits only a small `inputAmount` from its own shielded balance can still result in a large real swap (and large resulting UTXO) if the input-token balance available to the router at call time exceeds what was declared and funded for that specific transaction.

### Impact Explanation
If value is realized in `LifiExternalAction`/`ExternalActionSwap` without a corresponding equal debit from the actor's own shielded balance, the resulting UTXO is effectively minted without backing / represents theft of value that was not authorized by that actor's proof for that transaction — a Critical-severity break of the "shielded debit == externally realized value" balance equation that `EmporiumUpgradeable` enforces but `ExternalActionSwap`/`LifiExternalAction` does not.

### Likelihood Explanation
Exploitation requires the `LifiExternalAction` contract to already hold input-token balance beyond what a given transaction itself funds (e.g., left over from an earlier partial-fill or non-atomic router route). Given `Hinkal._externalTransact` funds the contract with exactly the declared `inputAmount` right before the call, a single isolated transaction cannot self-fund the surplus needed; the issue only becomes concretely exploitable once any residual balance accumulates in the contract, at which point ANY subsequent caller — not just the one who left the residue — can route it out via `router.call`. The missing check is unconditional and always present in the code, independent of how the residue arose.

### Recommendation
In `ExternalActionSwap.swap()` / `LifiExternalAction.callRouter()`, measure and assert the input token balance before/after the router call, requiring `balanceBefore(inputToken) - balanceAfter(inputToken) == inputAmount` (mirroring the per-token reconciliation already done in `EmporiumUpgradeable.runAction()`), and replace the unlimited persistent approval with a per-call approval scoped to exactly `inputAmount`, reset to `0` after the call.

### Proof of Concept
1. Any transaction (own or another user's) causes `LifiExternalAction` to hold `R` residual units of `tokenX` after `router.call` completes successfully without fully consuming the funded `inputAmount` (the contract has no check preventing or detecting this).
2. Attacker submits a new Hinkal `transact()` call with `circomData.erc20TokenAddresses = [tokenX, tokenY]`, declaring a tiny `deltaAmounts[0] = -1` (debiting only 1 wei of `tokenX` from their own shielded balance).
3. `Hinkal._externalTransact` transfers just 1 wei of `tokenX` to `LifiExternalAction`, bringing its balance to `R + 1`.
4. Attacker's `externalActionMetadata` encodes router calldata that pulls the full `R + 1` balance of `tokenX` (permitted by the pre-existing unlimited `approveUnlimited` allowance) and swaps it to `tokenY`.
5. `swappedAmount = balanceAfter(tokenY) - balanceBefore(tokenY)` reflects the full swap of `R + 1`, and `ExternalActionSwap` forwards that entire amount (minus fees) to the attacker as a new UTXO — while the attacker's shielded balance was only debited 1 wei of `tokenX`, netting them `R` worth of `tokenY` unbacked by any shielded debit.

    function callRouter(
        address inputToken,
        uint256 inputAmount,
        address outputToken,
        bytes calldata externalActionMetadata
    ) internal override returns (uint256 swappedAmount) {
        uint256 balanceBefore = getERC20OrETHBalance(outputToken);

        if (inputToken == address(0)) {
            (bool success, ) = router.call{value: inputAmount}(
                externalActionMetadata
            );
            require(success, "LI.FI swap failed: native coin");
        } else {
            approveUnlimited(inputToken, router);
            (bool success, ) = router.call(externalActionMetadata);
            require(success, "LI.FI swap failed: erc-20 token");
        }

        swappedAmount = getERC20OrETHBalance(outputToken) - balanceBefore;
    }

    function swap(
        CircomData calldata circomData,
        int256[] calldata deltaAmounts
    ) internal returns (UTXO[] memory utxoSet) {
        address inputToken = circomData.erc20TokenAddresses[0];
        uint256 inputAmount = uint256(-deltaAmounts[0]);

        if (inputToken == circomData.feeStructure.feeToken) {
            inputAmount -= circomData.feeStructure.flatFee;
        }

        address outputToken = circomData.erc20TokenAddresses[1];

        require(
            circomData.slippageValues[1] != 0,
            "swap output slippage floor not set"
        );

        require(
            block.timestamp <= circomData.timeStamp + SWAP_DEADLINE_WINDOW,
            "swap expired"
        );

        uint256 swappedAmount = callRouter(
            inputToken,
            inputAmount,
            outputToken,
            circomData.externalActionData.externalActionMetadata
        );

        uint256 relayFee = circomData.feeStructure.flatFee;

        uint256 hinkalFee = hinkalHelper.calculateRelayFee(
            swappedAmount,
            0,
            circomData.feeStructure.variableRate
        );

        if (circomData.feeStructure.feeToken == outputToken) {
            sendToRelay(circomData.relay, relayFee + hinkalFee, outputToken);
        } else {
            sendToRelay(
                circomData.relay,
                relayFee,
                circomData.feeStructure.feeToken
            );
            sendToRelay(circomData.relay, hinkalFee, outputToken);
        }

        uint256 totalFee = hinkalFee +
            (outputToken == circomData.feeStructure.feeToken ? relayFee : 0);
        uint256 amountToSendToHinkal = swappedAmount - totalFee;

        transferERC20TokenOrETH(outputToken, msg.sender, amountToSendToHinkal);

        utxoSet = new UTXO[](1);
        utxoSet[0] = UTXO({
            amount: amountToSendToHinkal,
            erc20Address: outputToken,
            stealthAddressStructure: circomData.stealthAddressStructure,
            timeStamp: block.timestamp
        });
    }
