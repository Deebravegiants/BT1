### Title
Webhook `shop` identity is not covered by the HMAC signature, allowing cross-tenant webhook spoofing - (File: `lib/shopify_api/webhooks/request.rb`)

### Summary
`ShopifyAPI::Webhooks::Registry.process` validates the authenticity of an incoming webhook using only the raw request body against the `X-Shopify-Hmac-Sha256` header, but the `shop` identity that is handed to the app's handler is read from the unauthenticated `X-Shopify-Shop-Domain` header, which is never part of the signed payload. This breaks the binding: *shop authenticated by HMAC* ≠ *shop trusted as the tenant key by the handler*.

### Finding Description
`ShopifyAPI::Webhooks::Request` implements `Utils::VerifiableQuery`, and its `to_signable_string` method returns only the raw HTTP body: [1](#0-0) 

The `shop` accessor, however, is read straight from an HTTP header with no cryptographic binding to the signature at all: [2](#0-1) 

`HmacValidator.validate` only recomputes the signature over `to_signable_string` (the body) and compares it to the `hmac` header — it never touches `shop`: [3](#0-2) 

`Registry.process` then trusts `request.shop` directly to build the `WebhookMetadata` that is dispatched to the app's handler as the tenant identifier, immediately after confirming only that the body's HMAC is valid: [4](#0-3) 

By contrast, the OAuth callback's `AuthQuery` (also a `VerifiableQuery`) explicitly includes `shop` inside `to_signable_string`, so `shop` there is cryptographically bound to the signature: [5](#0-4) 

No such binding exists for webhooks — `shop` is excluded from the signable string entirely, so the gem asserts (via `Registry.process`'s own comment "This will verify the request did indeed come from Shopify") that the request is authenticated, while the tenant-identifying field is not covered by that authentication at all.

### Impact Explanation
Any unprivileged party who can install the target app on a shop they control (e.g., a free development store) receives genuine webhooks with a valid HMAC computed by Shopify using the app's real `client_secret`. They can capture one such `raw_body` + `X-Shopify-Hmac-Sha256` pair and replay it to the app's webhook endpoint with the `X-Shopify-Shop-Domain` header changed to an arbitrary victim shop domain. `HmacValidator.validate` still succeeds because it only checks the body signature, and `Registry.process` passes the attacker-chosen `shop` value straight to the handler as `WebhookMetadata#shop`. Any app logic that keys per-tenant behavior off this field (data attribution, `app/uninstalled` handling, order/customer record updates, billing state, etc.) can be tricked into acting as though the event originated from a shop the attacker does not control — a cross-tenant confusion crossing an authentication boundary this gem is expected to enforce.

### Likelihood Explanation
Likely and low-effort: the attacker only needs to install the app once on any shop (their own), capture one webhook delivery, and replay it with a modified header — no secrets, tokens, or privileged access are required, and the HMAC check as implemented cannot detect the header substitution.

### Recommendation
Include the shop-identifying value in the webhook's signable content, or otherwise verify `request.shop` against the app's own record of shops that were the actual signer of the delivered body before trusting it in `WebhookMetadata`. At minimum, the gem should document loudly, next to `Registry.process`, that `shop` is unauthenticated and must be independently cross-checked by the host application against a known/installed shop list before being used for tenant-sensitive decisions.

### Proof of Concept
1. Install the target Shopify app on shop `attacker.myshopify.com` and receive a genuine `orders/create` webhook: capture `raw_body` and the `X-Shopify-Hmac-Sha256` header value (valid for the app's real secret).
2. Send a POST to the app's webhook endpoint with the same `raw_body` and `X-Shopify-Hmac-Sha256` header, but set `X-Shopify-Shop-Domain: victim.myshopify.com`.
3. `ShopifyAPI::Utils::HmacValidator.validate(request)` returns `true` (per `lib/shopify_api/utils/hmac_validator.rb`, only the body is checked).
4. `ShopifyAPI::Webhooks::Registry.process` calls the registered handler with `WebhookMetadata.new(..., shop: "victim.myshopify.com", ...)`, even though the payload never actually came from, nor was authorized by, `victim.myshopify.com`.

        def validate_signature(verifiable_query, secret)
          received_signature = verifiable_query.hmac
          computed_signature = compute_signature(verifiable_query.to_signable_string, secret)
          OpenSSL.secure_compare(computed_signature, T.must(received_signature))
        end
