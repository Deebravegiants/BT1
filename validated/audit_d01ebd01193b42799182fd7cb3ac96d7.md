### Title
Stale `ExposureController` exposure/gain state persists across signups on `Input::SetTargetMean` - ([File: src/agents/ir_auto_exposure.rs])

### Summary
`ir_auto_exposure::Agent::run` runs as a single long-lived actor whose `ExposureController` (`gain`/`exposure` fields) lives for the entire orb process lifetime, not per signup session. When `biometric_capture::Plan::run_pre` calls `orb.start_ir_auto_exposure(IR_TARGET_MEAN)` for a new user, it sends `Input::SetTargetMean`, but the handler only resets `controller.pid` and the `timer`, leaving `controller.exposure`/`controller.gain` at whatever value they were driven to by the previous user's session.

### Finding Description
The `Agent::run` loop holds a single `ExposureController` instance across the whole agent lifetime: [1](#0-0) 

On `Input::SetTargetMean`, only `target_mean`, `controller.pid`, and `timer` are reset — `controller.exposure` and `controller.gain` are untouched: [2](#0-1) 

`ExposureController::update` computes the next exposure multiplicatively from `self.exposure`, so the very first update for the new session starts from the stale, previously-saturated value rather than the documented defaults (`IR_CAMERA_DEFAULT_GAIN`, `DEFAULT_IR_LED_DURATION`) that are only applied once, at agent construction: [3](#0-2) 

An attacker completing signup A can present a very bright or very dark scene to drive `frame.mean()` to an extreme, causing `self.exposure` to clamp at a bound of `DEFAULT_EXPOSURE_RANGE` (`IR_LED_MIN_DURATION`/`IR_LED_MAX_DURATION`). Because the PID reset on out-of-range clamp only resets the PID controller — not `exposure` itself — the clamped value is retained in `controller.exposure` across the `SetTargetMean` call boundary. When signup B starts and `run_pre` re-invokes `start_ir_auto_exposure(IR_TARGET_MEAN)`, the controller resumes from the wrong exposure baseline instead of the intended default, producing under/over-exposed initial IR frames for the new user.

### Impact Explanation
This is a genuine cross-signup state bleed: session isolation is violated for the auto-exposure subsystem, and the wrong initial exposure/gain is applied to the next user. Degraded initial IR frames feed downstream `IRIS_BRIGHTNESS_RANGE`-style gating and capture-quality checks for a different identity, which can affect enrollment quality for an unrelated legitimate user. It is a data/state-integrity issue affecting capture quality rather than an authentication bypass, unauthorized signup, or biometric data disclosure.

### Likelihood Explanation
The precondition (attacker fully controls the scene presented during their own signup) is trivially achievable by any unprivileged user with a very bright or very dark presented target, and the bug is deterministic: any two consecutive signups trigger it because `SetTargetMean` never resets `exposure`/`gain`. Recovery happens naturally, however, once enough `Input::Frame` updates run for signup B, because the PID loop will converge `exposure` back toward the target mean within a small number of frames — meaning the practical impact is a bounded transient rather than a persistent corruption.

### Recommendation
In the `Input::SetTargetMean` handler in `Agent::run`, also reset `controller.gain`/`controller.exposure` to their defaults (`IR_CAMERA_DEFAULT_GAIN`, `DEFAULT_IR_LED_DURATION`), e.g. by reconstructing `controller = ExposureController::new(IR_CAMERA_DEFAULT_GAIN as _, f64::from(DEFAULT_IR_LED_DURATION))` alongside the existing `pid.reset()`/`timer.reset()` calls, so each new signup session starts from a known-good exposure/gain baseline.

### Proof of Concept
Integration test plan:
1. Instantiate `ir_auto_exposure::Agent` via `agentwire` test harness (or directly construct `ExposureController` + drive the `run` loop's logic through the port).
2. Send a sequence of `Input::Frame` values with `mean()` pinned at an extreme (e.g., 0 or 255) repeatedly until `controller.exposure` clamps to `*DEFAULT_EXPOSURE_RANGE.end()` or `.start()`.
3. Send `Input::SetTargetMean(DEFAULT_TARGET_MEAN)` (simulating `start_ir_auto_exposure(IR_TARGET_MEAN)` for the next signup).
4. Assert that immediately after this call, `controller.exposure == f64::from(DEFAULT_IR_LED_DURATION)` and `controller.gain == IR_CAMERA_DEFAULT_GAIN as f64` — the test will fail because both retain the clamped value from step 2, demonstrating the stale cross-session state.

    pub fn update(
        &mut self,
        curr_mean: f64,
        target_mean: f64,
        exposure_range: RangeInclusive<f64>,
        dt: f64,
    ) -> (f64, f64) {
        self.exposure *= 1.0 + self.pid.advance(target_mean, curr_mean, dt);
        if !exposure_range.contains(&self.exposure) {
            self.exposure = self.exposure.clamp(*exposure_range.start(), *exposure_range.end());
            self.pid.reset();
        }
        (self.gain, self.exposure)
    }
