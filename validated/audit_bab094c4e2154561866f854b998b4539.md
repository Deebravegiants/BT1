### Title
Unbounded digest-count length field in `Codec.DecodeHeader` allows a memory-exhaustion / gas-bomb denial of service on the BEEFY parachain header consensus path - ([File: evm/src/consensus/Codec.sol])

### Summary
`Codec.DecodeHeader` reads a SCALE compact-encoded digest count directly from attacker-supplied header bytes and immediately allocates a fixed-size memory array of that length, before any bytes have been consumed to justify the count. This mirrors CVE-2016-9376, where the Wireshark OpenFlow dissector trusted a length field to size an allocation without checking it against the actual amount of available data, causing memory exhaustion. Here, the same pattern is reachable by anyone submitting a BEEFY/SP1 consensus proof containing parachain headers.

### Finding Description
`DecodeHeader` decodes the digest count with `ScaleCodec.decodeUintCompact` and uses it unchecked to size a memory array: [1](#0-0) 

SCALE's compact encoding (mode 2/3) lets a 4–8 byte prefix express a `length` value up into the billions/quadrillions, far larger than the actual bytes remaining in `encoded`. `new Digest[](length)` is executed *before* the loop that would otherwise fail on `read`/`readByte` bounds checks: [2](#0-1) 

Allocating a large `Digest[]` in EVM memory (each `Digest` struct itself embeds two `DigestItem` structs with dynamic `bytes` fields) triggers the EVM's quadratic memory-expansion gas cost, so a crafted `length` can force the transaction to consume all available gas and revert, well before the decode loop ever reaches an actual out-of-bounds read that would otherwise bound the attack.

`DecodeHeader` is invoked on every parachain header supplied in a consensus proof, in both the ECDSA-signed BEEFY path and the SP1 zk-BEEFY path: [3](#0-2) [4](#0-3) 

Both `verifyParachainHeaderProof` (EcdsaBeefy) and `verifyConsensus` (SP1Beefy) loop over caller-supplied `para.header`/`proof.headers[i].header` byte blobs and call `Codec.DecodeHeader` on each one without any bound on the encoded digest count, and without isolating each header decode in a try/catch. A single malicious/oversized digest-count field in any one header in the batch causes the whole consensus-update transaction to revert.

### Impact Explanation
Consensus state updates (BEEFY/SP1) are the mechanism by which Hyperbridge learns new parachain state roots, which subsequently gate `handlePostRequests`/`handleGetResponses` message delivery via `HandlerV2` (state-commitment membership proofs are checked against the roots established here). If an attacker can force the parachain-header decode step to exhaust gas and revert, they can repeatedly poison consensus-update submissions for a tracked parachain/state machine, delaying or denying legitimate state-root updates and thereby stalling proof verification and message delivery for that route ("a route unable to deliver messages"). This is a Medium-severity availability impact rather than direct fund theft, consistent with the CVSS 5.9/Medium rating of the analog Wireshark CVE.

### Likelihood Explanation
Submission of BEEFY/SP1 consensus proofs (and the parachain headers they embed) is intended to be relayer-driven and permissionless by design (any relayer can push a new consensus update), so an attacker does not need any privileged role to supply a crafted `para.header`/`proof.headers[i].header` byte string with a manipulated SCALE compact length prefix. The exact permission model of the top-level `updateConsensusState`/`verify` entry point in `ConsensusRouter`/`EvmHost` could not be fully confirmed in this session (grep for `onlyOwner`/`onlyGovernance` on `EvmHost.sol` returned no matches, suggesting no such gate, but the full call chain from an external relayer transaction into `IConsensusV2.verify` was not exhaustively traced end-to-end). This uncertainty should be verified before treating likelihood as fully "attacker-controlled, no gate."

### Recommendation
- In `Codec.DecodeHeader`, bound `length` (digest count) against a sane maximum (e.g., a small constant, since Substrate headers realistically carry only a handful of digest items) and/or against the remaining bytes in `encoded` (each digest consumes at least 1 byte, so `length` can never legitimately exceed `slice.data.length - slice.offset`).
- Apply the same remaining-bytes bound to `decodeDigestItem`'s inner `length` before calling `Bytes.read(slice, length)`.
- Consider wrapping per-header decoding in `verifyParachainHeaderProof`/`verifyConsensus` so a single malformed header cannot revert the entire batch of otherwise-valid parachain header updates.

### Proof of Concept
1. An attacker (any permissionless relayer) submits a BEEFY (or SP1) consensus proof containing a `ParachainHeader`/`Parachain` entry whose `header` bytes are: 32 bytes parent hash + valid compact block number + 32 bytes state root + 32 bytes extrinsics root + a SCALE compact-encoded digest count using the 4-byte "mode 2" or 8-byte "mode 3" prefix set to a very large value (e.g., `0x3FFFFFFF`-scale value in the hundreds of millions), followed by no (or minimal) actual digest bytes.
2. `EcdsaBeefy.verifyParachainHeaderProof` (or `SP1Beefy.verifyConsensus`) calls `Codec.DecodeHeader(para.header)` on this blob.
3. `ScaleCodec.decodeUintCompact` returns the attacker-chosen large `length`.
4. `Digest[] memory digests = new Digest[](length);` forces EVM memory expansion proportional to `length`, whose gas cost grows quadratically, causing the transaction to run out of gas and revert.
5. Because this happens inside a loop over all `parachains`/`headers` in the batch, one such malicious header entry blocks the entire proof submission, denying the update of legitimate parachain state roots for that batch/route.

    // @dev Deserializes a substrate header
    function DecodeHeader(bytes memory encoded) internal pure returns (Header memory) {
        ByteSlice memory slice = ByteSlice(encoded, 0);
        bytes32 parentHash = Bytes.toBytes32(Bytes.read(slice, 32));
        uint256 blockNumber = ScaleCodec.decodeUintCompact(slice);
        bytes32 stateRoot = Bytes.toBytes32(Bytes.read(slice, 32));
        bytes32 extrinsicsRoot = Bytes.toBytes32(Bytes.read(slice, 32));

        uint256 length = ScaleCodec.decodeUintCompact(slice);
        Digest[] memory digests = new Digest[](length);

        for (uint256 i = 0; i < length; i++) {
            uint8 kind = Bytes.readByte(slice);
            Digest memory digest;
            if (kind == DIGEST_ITEM_OTHER) {
                digest.isOther = true;
            } else if (kind == DIGEST_ITEM_CONSENSUS) {
                digest.isConsensus = true;
                digest.consensus = decodeDigestItem(slice);
            } else if (kind == DIGEST_ITEM_SEAL) {
                digest.isSeal = true;
                digest.seal = decodeDigestItem(slice);
            } else if (kind == DIGEST_ITEM_PRERUNTIME) {
                digest.isPreRuntime = true;
                digest.preruntime = decodeDigestItem(slice);
            } else if (kind == DIGEST_ITEM_RUNTIME_ENVIRONMENT_UPDATED) {
                digest.isRuntimeEnvironmentUpdated = true;
            }
            digests[i] = digest;
        }

        return Header(parentHash, blockNumber, stateRoot, extrinsicsRoot, digests);
    }

    /// @dev Reads `len` bytes from the slice at the current offset and advances the cursor.
    function read(ByteSlice memory self, uint256 len) internal pure returns (bytes memory) {
        require(self.offset + len <= self.data.length);
        if (len == 0) {
            return "";
        }
        uint256 addr = Memory.dataPtr(self.data);
        bytes memory slice = Memory.toBytes(addr + self.offset, len);
        self.offset += len;
        return slice;
    }

    /// @dev Reads a single byte from the slice at the current offset and advances the cursor.
    function readByte(ByteSlice memory self) internal pure returns (uint8) {
        require(self.offset + 1 <= self.data.length);

        uint8 b = uint8(self.data[self.offset]);
        self.offset += 1;

        return b;
    }
