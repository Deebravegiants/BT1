### Title
A stale non-Market oracle leg bypasses the dual-source age-spread check and can leave debt undercollateralized - (File: contracts/price-aggregator/src/engine.rs)

### Summary
The dual-source aggregator checks the timestamp spread between its two legs only when both are labeled `FeedNature::Market`. A `Fundamental` RedStone leg can therefore remain almost a full day old while the other market leg is fresh. If that stale anchor still reports a value inside the configured tolerance, the aggregator accepts the midpoint instead of rejecting the observation. A borrower can exploit the skewed midpoint through `borrow` or `withdraw` to extract more value than the fresh price would authorize. [1](#0-0) 

### Finding Description
`blend` computes the age difference between two valid legs, but applies `MAX_LEG_AGE_SPREAD_SECONDS` only when `primary.nature == FeedNature::Market && anchor.nature == FeedNature::Market`. For a fresh Reflector leg and a `Fundamental` RedStone leg, the spread condition is disabled even though both prices describe the same asset. The outcome is stale only when either leg exceeds its own `max_stale_seconds`, and deviation only when their price ratio exceeds the configured tolerance. [2](#0-1) 

The accepted price is the midpoint of the fresh and stale observations, after which `failure` rejects only staleness, deviation, non-positive prices, and sanity-bound violations. A stale anchor within both its own freshness window and the price tolerance therefore produces a valid `PriceFeedRaw`. [3](#0-2) 

The harness demonstrates the reachable flaw: it configures a fresh Reflector primary with a RedStone anchor allowed to be 86,400 seconds old, sets the anchor 82,800 seconds behind the current ledger, and keeps its $1.00 price while the fresh price is $0.91. The accepted blend inflates collateral by more than 4%, and a $70,000 borrow succeeds even though the all-fresh control fails with `INSUFFICIENT_COLLATERAL`. [4](#0-3) [5](#0-4) 

This is the same validation weakness as the mirrored-zone report: data that should be constrained by a trusted cross-check is accepted because the temporal validity rule does not cover the trusted anchor's actual freshness relative to the other source.

### Impact Explanation
An attacker can turn an ordinarily rejected borrow into an accepted one by waiting for a tolerated stale anchor to diverge from the fresh market leg. If the stale leg overprices collateral, the attacker borrows above the intended LTV. If it underprices an already-held debt asset, the attacker can withdraw collateral while the midpoint still reports sufficient health. Once the legs converge to the fresh value, the account can be liquidatable or economically undercollateralized, leaving lenders to absorb any subsequent shortfall. [6](#0-5) 

### Likelihood Explanation
No privileged call is required once such a market exists. The attacker only needs a configured mixed-nature pair whose slower leg remains within its own staleness and tolerance bounds, then calls `borrow` or `withdraw` during the lag. Feed lags and tolerated price differences are normal operating conditions; the dedicated regression shows a 23-hour lag is accepted and changes the borrowing decision. The maximum instantaneous skew remains bounded by the configured tolerance, making this a Medium-severity economic-risk bypass rather than an arbitrary oracle price write. [7](#0-6) 

### Recommendation
Apply the two-leg timestamp-spread bound to every dual-source price, regardless of declared `FeedNature`, or explicitly bound each mixed-nature pair with a conservative maximum age spread. At minimum, reject a blended result when the two accepted observation timestamps differ by more than the lower leg's market-cadence requirement rather than relying only on each leg's independent `max_stale_seconds`. Revalidate existing oracle configurations and add a regression requiring the 82,800-second lagged anchor to fail closed. [8](#0-7)

/// Converts composed `Legs` into an `Outcome`. For two readings, marks the
/// outcome stale when either leg is individually stale, or when both legs
/// are market-nature feeds whose timestamps differ by more than
/// `MAX_LEG_AGE_SPREAD_SECONDS`. Takes the earlier of the two timestamps,
/// flags a deviation when the legs fall outside the oracle's tolerance band, and
/// sets the blended price to the midpoint of the two legs (zero if the
/// midpoint computation fails).
fn blend(env: &Env, oracle: &AssetOracle, legs: Legs) -> Outcome {
    match legs {
        Legs::Empty => Outcome::unreadable(),
        Legs::One(r) => Outcome::one(r),
        Legs::Partial { reading, slot } => Outcome::partial(reading, slot),
        Legs::Two { primary, anchor } => {
            let spread_bounded =
                primary.nature == FeedNature::Market && anchor.nature == FeedNature::Market;
            let age_spread = primary.timestamp.abs_diff(anchor.timestamp);
            let stale = primary.stale
                || anchor.stale
                || (spread_bounded && age_spread > MAX_LEG_AGE_SPREAD_SECONDS);
            let ts = primary.timestamp.min(anchor.timestamp);
            let deviation =
                !within_tolerance_band(env, anchor.price_wad, primary.price_wad, &oracle.tolerance);

            let price_wad = midpoint_price_or_zero(anchor.price_wad, primary.price_wad);
            Outcome {
                price_wad,
                timestamp: ts,
                first_wad: primary.price_wad,
                second_wad: anchor.price_wad,
                stale,
                deviation,
                err: None,
