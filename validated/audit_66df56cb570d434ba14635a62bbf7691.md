### Title
Fraud Detection Engine Never Evaluates Any Check, Always Reports "No Fraud" - (File: src/plans/fraud_check.rs, src/plans/mod.rs)

### Summary
`orb-core`'s signup pipeline calls `MasterPlan::detect_fraud` (src/plans/mod.rs) after biometric capture, which is documented as "Performs the fraud checks" and gates the `SignupStatus::Fraud` outcome. In this build, `N_FRAUD_CHECKS` is hardcoded to `0` and the actual check logic has been removed, so the function structurally can never detect fraud regardless of the biometric pipeline output (occlusion, contact lenses, mask detection, multiple faces, etc.) that is still computed and plumbed through `biometric_pipeline::Pipeline`.

### Finding Description
`detect_fraud` in [1](#0-0)  is invoked during every signup with the fully-populated `biometric_pipeline::Pipeline` (which includes `face_identifier_fraud_checks`, occlusion estimates, etc., as seen in [2](#0-1) ). Despite receiving `Some(_pipeline)`, the function immediately falls through to `// FOSS: WE HAVE DELETED ALL FRAUD CHECKS` and unconditionally returns `Ok(false)`.

This mirrors the `fraud_check.rs` module itself, where `N_FRAUD_CHECKS` is set to `0` and every helper (`fraud_checks`, `enabled_checks_from_config`, `feedback_messages`) returns an empty array, so `Report::fraud_detected` and `fraud_detected_with_config` can never return `true`: [3](#0-2) [4](#0-3) 

The `FraudChecks::run` plan itself is a no-op that always returns an empty `Report {}`: [5](#0-4) 

Meanwhile, `PipelineFailureFeedbackMessage` still enumerates concrete fraud/liveness categories (ContactLenses, EyeGlasses, Mask, MultipleFaces, EyesOcclusion, Underaged, LowImageQuality) that the pipeline is capable of computing ( [6](#0-5) ), and the CLI still exposes a `--skip-fraud-checks` flag implying fraud checks are otherwise active ( [7](#0-6) ). The `SignupStatus::Fraud` branch in the UI-completion logic is consequently dead code for this build ( [8](#0-7) ), since `detect_fraud` never returns `true`.

### Impact Explanation
This is a direct analog of the HardVault bug class: a function documented and structurally wired to perform a protective action (fraud/liveness enforcement gating signup completion) never actually performs it. Any signup attempt that would otherwise be flagged for spoofing indicators the pipeline is capable of detecting (contact lenses, masks/occlusion, multiple faces, underage subjects, low image quality) is unconditionally allowed to proceed to `enroll_user`, producing a fully-enrolled, misattributed/fraudulent signup with no fraud-based rejection path available in this codebase.

### Likelihood Explanation
Likelihood is high: this triggers on every single signup performed with this build — no attacker action is required beyond the pipeline computing the (unused) fraud signals, since `detect_fraud` is unconditionally `Ok(false)` whenever a pipeline result exists.

### Recommendation
Either restore/re-implement genuine fraud/liveness enforcement logic in `detect_fraud`/`fraud_check.rs` using the already-computed pipeline signals (occlusion, face identifier fraud checks, etc.) so that a fraudulent or spoofed capture can actually cause `SignupStatus::Fraud`, or, if fraud detection is intentionally out of scope for the FOSS distribution, gate signup finalization behind an explicit "unverified/unaudited fraud protection" acknowledgment and update all consumer-facing documentation/config (`BackendConfig`, CLI flags, feedback message enum) to make unambiguous that no protection is actually enforced, rather than leaving structures that imply active enforcement.

### Proof of Concept
1. Build/run `orb-core` with the default (FOSS) feature set.
2. Perform a signup using a spoofed presentation that the underlying biometric pipeline is capable of flagging (e.g., contact lenses, a printed photo/mask, or multiple faces in frame) so that `biometric_pipeline::Pipeline` yields non-nominal `occlusion`/`face_identifier_fraud_checks` results.
3. Observe that `MasterPlan::detect_fraud` (src/plans/mod.rs:1390-1406) still returns `Ok(false)` because `N_FRAUD_CHECKS == 0`, causing the signup to proceed to `enroll_user` and complete as `SignupStatus::Success` instead of being rejected as `SignupStatus::Fraud`.

impl Report {
    const DATADOG_TAGS: [&'static str; N_FRAUD_CHECKS] = [];

    fn fraud_checks(&self) -> [Option<bool>; N_FRAUD_CHECKS] {
        []
    }

    /// If fraud data are missing, we assume fraud is detected.
    fn fraud_checks_strict(&self) -> [bool; N_FRAUD_CHECKS] {
        self.fraud_checks().map(|v| v.unwrap_or(true))
    }

    fn enabled_checks_from_config(_config: &BackendConfig) -> [bool; N_FRAUD_CHECKS] {
        []
    }

    fn feedback_messages() -> [Option<PipelineFailureFeedbackMessage>; N_FRAUD_CHECKS] {
        []
    }

    /// Get the || result of all fraud checks, but under the Orb configuration.
    /// The end result might be different from the || of all fraud booleans as
    /// we might decide to not block a signup even if it's fraudulent.
    #[must_use]
    pub fn fraud_detected_with_config(
        &self,
        config: &BackendConfig,
    ) -> (bool, Vec<PipelineFailureFeedbackMessage>) {
        let enabled_checks = Self::enabled_checks_from_config(config);
        let fraud_results = self.fraud_checks_strict();
        let feedback_msgs = Self::feedback_messages();

        let feedback: Vec<PipelineFailureFeedbackMessage> = enabled_checks
            .iter()
            .zip(fraud_results.iter())
            .zip(feedback_msgs.iter())
            .filter_map(
                |((&enabled, &result), feedback_msg)| {
                    if enabled && result { feedback_msg.clone() } else { None }
                },
            )
            .collect();

        (!feedback.is_empty(), feedback)
    }

    /// If any fraud check fails or is missing data, fraud is reported.
    #[must_use]
    pub fn fraud_detected(&self) -> bool {
        self.fraud_checks_strict().iter().any(|&v| v)
    }
