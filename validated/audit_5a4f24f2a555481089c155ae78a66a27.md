### Title
RAY debt-value overflow before the borrow-index cap permanently freezes a whale market - ([File: common/src/rates/index.rs](common/src/rates/index.rs))

### Summary
Medium. A sufficiently large debt position can make `borrowed * borrow_index` exceed `i128::MAX` long before `MAX_BORROW_INDEX_RAY` is reached. Once this happens, `update_indexes` and every state-changing market operation panic while accruing interest, leaving supplier funds and borrower collateral inaccessible without a privileged code fix. [1](#0-0) 

### Finding Description
Pool mutations load the market through `synced_market`, which calls `interest::global_sync` before processing the operation. [2](#0-1) 

During accrual, `calculate_supplier_rewards` computes both the old and new aggregate debt as `borrowed.mul(index)`. [3](#0-2) 

RAY multiplication uses an exact widened intermediate but still requires the resulting RAY value to fit in `i128`; an unrepresentable result raises `MathOverflow`. [4](#0-3) [5](#0-4) 

`update_borrow_index` caps the index itself, but this cap does not bound the product of outstanding shares and the index. [6](#0-5) 

For example, one billion whole tokens at 18 decimals produces approximately `10^36` scaled debt shares, so the approximately `1.70e38` RAY-value ceiling is reached at roughly a 170× index while the configured index ceiling is `10^9` times the initial index. [1](#0-0) [7](#0-6) 

An unprivileged account can reach the condition through the controller by supplying the target asset, supplying separate collateral, borrowing a very large fraction of the target market, and invoking `update_indexes` for that market; the pool-facing call is `update_indexes(Vec<HubAssetKey>)`. [8](#0-7) [9](#0-8) 

Because the panicking accrual runs before `supply`, `borrow`, `withdraw`, `repay`, liquidation, bad-debt cleanup, strategies, and revenue operations, the failed transaction cannot advance `last_timestamp`, and every subsequent attempt repeats the same overflowing accrual. [10](#0-9) [2](#0-1) 

Even replacing the rate model first calls `renewed_market`, which performs the same accrual, so changing the curve through the existing entrypoint does not rescue the market. [11](#0-10) 

### Impact Explanation
This permanently freezes all supplier principal and yield in the affected market and prevents borrowers from repaying or liquidators from unwinding debt through the existing contract ABI. [12](#0-11) 

The regression test demonstrates that `update_indexes`, `withdraw`, and `repay` all fail with `MathOverflow` once the cliff is crossed. [13](#0-12) 

### Likelihood Explanation
The attack requires a whale-scale balance and sustained high utilization under a market configuration that permits the required borrow exposure, so it is not reachable in a small market. [14](#0-13) 

No privileged key, leaked secret, malformed parameter, or dishonest oracle is required after such liquidity exists; the triggering call is the ordinary index-update path available through normal protocol use. [8](#0-7) 

### Recommendation
Bound aggregate scaled debt and supply so `scaled * MAX_*_INDEX` cannot exceed `i128::MAX`, and reject new exposure before that product can overflow. Add a pre-accrual rescue path that bounds the debt value or safely clamps index growth without first evaluating overflowing aggregate debt; alternatively, store market totals in an `I256`-safe representation until they are reduced to transfer-sized `i128` values. Regression coverage should assert that the configured caps enforce the stricter arithmetic bound rather than relying only on token-domain maximums. [6](#0-5) [2](#0-1) 

### Proof of Concept
The existing test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` reproduces the issue. It creates an 18-decimal market, supplies `BILLION * 10^18`, borrows 98% of that principal, advances ledger time, calls `update_indexes`, and then verifies that both withdrawal and repayment fail with `MathOverflow`. [15](#0-14) 

```rust
let principal = BILLION * 10i128.pow(18);

// One unprivileged account supplies the borrowable asset and enough separate collateral.
supply(account, "BIG18", principal);
supply(account, "COL", sufficient_collateral);

// The same account borrows nearly the entire BIG18 pool.
borrow(account, "BIG18", principal / 100 * 98);

// Advance the ledger until accrual reaches the RAY-value cliff.
loop {
    advance_ledger();
    match try_update_indexes(&["BIG18"]) {
        Err(MathOverflow) => break,
        Ok(()) => continue,
    }
}

// All subsequent state-changing exits repeat accrual first.
assert_eq!(try_withdraw(account, "BIG18", 1), Err(MathOverflow));
assert_eq!(try_repay(account, "BIG18", debt_payment), Err(MathOverflow));
```

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```
