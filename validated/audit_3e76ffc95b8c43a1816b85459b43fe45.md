I have one strong analog candidate. Let me verify the `supply` path permits third-party top-ups of an existing asset slot, and confirm the dust gate on `clean_bad_debt`.### Title
Permissionless third-party `supply` top-ups can permanently block bad-debt socialization by pushing an insolvent account's collateral above the $5 dust gate — (File: contracts/controller/src/positions/supply.rs)

### Summary
Like CVE-2019-0136 (insufficient access control enabling an unauthenticated denial of service), `process_supply` intentionally lets any authenticated stranger top up an existing collateral leg of any account. `clean_bad_debt`, the permissionless path that socializes an insolvent account's residual debt, only admits accounts whose total collateral is at or below `BAD_DEBT_USD_THRESHOLD` ($5 WAD). An unprivileged attacker can therefore keep any insolvent-but-socializable account permanently above the dust cap with a cheap top-up, indefinitely preventing permissionless cleanup.

### Finding Description
`require_third_party_existing_supply` in `contracts/controller/src/positions/supply.rs` enforces only that a non-owner/non-delegate caller tops up a hub asset the account already holds a supply position in — it does not check the account's solvency or the caller's relationship to the account [1](#0-0) . Third-party top-ups are an accepted, tested behavior [2](#0-1) .

Separately, `process_clean_bad_debt` is callable by anyone and routes to `BadDebtGate::DustCapped`, which admits only when `total_debt > total_collateral && total_collateral <= BAD_DEBT_USD_THRESHOLD` [3](#0-2) [4](#0-3) .

The gate is value-based, not count-based: the Certora rules explicitly pin that raising `total_collateral` to `BAD_DEBT_USD_THRESHOLD + 1` shuts the dust gate while the account remains insolvent [5](#0-4) . Because cleanup reclassifies *all* remaining collateral as revenue and deletes the account, the attacker must keep topping up to stay above the cap — but each top-up costs only ~$5 of an asset the account already holds, and the account can never be permissionless cleaned while the attacker maintains the straddle.

### Impact Explanation
Blocking `clean_bad_debt` leaves unbooked insolvent debt on the pool's books: suppliers' supply index is never written down and the backing shortfall is never formalized, which delays accounting of protocol insolvency and keeps the protocol reliant on the privileged `force_socialize_bad_debt` governance-timelocked path [6](#0-5) . For deeply underwater accounts whose remaining collateral is near the dust cap, this converts a permissionless cleanup into a forced governance operation — a denial of service of the liveness-critical cleanup function that maps to temporary freezing/unavailability of the socialization path. Impact is Medium: the loss is bounded by the dust-cap griefing window and governance retains a fallback, but the fallback requires the Sensitive timelock delay and manual scheduling [7](#0-6) .

### Likelihood Explanation
The attack requires only: (1) an insolvent account whose collateral is at or below $5, (2) the account holding any existing supply position, and (3) ~$5+ of that asset. `supply` is callable by any authenticated address, is unpaused-independent only in the sense that clean_bad_debt stays callable during global pause while supply does not — a minor defense that disappears whenever the controller is unpaused [8](#0-7) . An attacker motivated to keep bad debt unbooked (e.g., a borrower whose own positions benefit, or a griefer) can automate a minimal top-up whenever `clean_bad_debt` becomes callable. Interest accrual and price moves that push collateral back under the cap reopen the window, so the attacker must repeatedly top up — the attack is a persistent, cheap grief rather than a one-shot.

### Recommendation
Exclude third-party top-ups to insolvent or dust-adjacent accounts, e.g., in `require_third_party_existing_supply`, reject the top-up (or cap it) when `is_socializable_bad_debt`-adjacent conditions hold — computing `calculate_account_risk_totals` on the foreign account and reverting `NotAuthorized` when `total_debt > total_collateral`. Alternatively, evaluate the dust gate on collateral excluding *recent* third-party top-ups, or let `clean_bad_debt` first sweep collateral above the cap to revenue before testing the gate. Any fix must preserve the legitimate keeper top-up use case pinned by `regression_third_party_cannot_open_new_supply_slots` [9](#0-8) .

### Proof of Concept
1. ALICE supplies $20 USDC and borrows ETH; the USDC price crashes so `total_collateral ≈ $5` < `total_debt` (insolvent, exactly at the dust gate — the same fixture shape as `flow_clean_bad_debt` in `tests/integration/flows/liquidation.sh` [10](#0-9) ).
2. Attacker BOB, neither owner nor delegate, calls `controller.supply(caller=BOB, account_id=alice_id, spoke_id=alice_spoke, assets=[(hub_asset(USDC), dust_amount)])` with `dust_amount` worth ~$5.01. `require_third_party_existing_supply` passes because ALICE already holds a USDC supply position [11](#0-10) .
3. `total_collateral` is now `> BAD_DEBT_USD_THRESHOLD` while `total_debt > total_collateral` still holds, so `is_socializable_bad_debt` returns false and every `clean_bad_debt(caller, alice_id)` reverts with `CannotCleanBadDebt` [4](#0-3) [12](#0-11) .
4. Whenever accrual or price movement reopens the gate, BOB repeats step 2 with a minimal top-up. The bad debt is never socialized permissionlessly; only owner-gated `force_socialize_bad_debt` via the governance Sensitive timelock can clean the account [13](#0-12) .

```rust
/// Straddle, first half. An attacker who raises `total_collateral` strictly above
/// `BAD_DEBT_USD_THRESHOLD` (`BAD_DEBT_USD_THRESHOLD + 1` is the cheapest such state) blocks
/// the permissionless dust-gated socialization path while staying insolvent. The gate is
/// value-based, not count-based, so one unit of a second collateral cannot block it: the
/// attacker must post value above the threshold and keep it there.
#[rule]
fn bad_debt_straddle_blocks_dust_gate(e: Env, debt_wad: i128, collateral_wad: i128) {
    let _ = e;
    cvlr_assume!(collateral_wad >= BAD_DEBT_USD_THRESHOLD + 1);
    cvlr_assume!(collateral_wad <= 1_000_000 * WAD);
    cvlr_assume!(debt_wad > collateral_wad && debt_wad <= 2_000_000 * WAD);

    // Symbolic straddle: anywhere strictly above the cap, the dust gate is shut.
    cvlr_assert!(!is_socializable_bad_debt(
        Wad::from(debt_wad),
        Wad::from(collateral_wad)
    ));

    // Explicit +1 witness: one raw WAD unit above the cap blocks it.
    cvlr_assert!(!is_socializable_bad_debt(
        Wad::from(BAD_DEBT_USD_THRESHOLD + 2),
        Wad::from(BAD_DEBT_USD_THRESHOLD + 1)
    ));
```

```markdown
### INV-LIQ-04 — Bad-debt socialization is explicit and total

Permissionless cleanup requires ceil risk debt greater than half-up unweighted
collateral and collateral at or below the fixed $5 dust threshold. Owner-only
forced cleanup omits the dust cap. Both require debt, readable account and NFT
state, valid required prices and no active flash guard. Listing flags and
global pause do not block standalone cleanup.

Cleanup reclassifies all remaining collateral shares as revenue and writes off
all remaining debt against each debt's market. It releases spoke usage and
atomically removes account entries and the NFT. It does not net same-market
supply against debt. Standalone cleanup emits `CleanBadDebtEvent` with
pre-cleanup USD totals, without a controller position-update batch.

Ordinary liquidation and cleanup apply no final account-health or full-backing
assertion. The index floor can leave a shortfall. Recapitalization fills that
shortfall without restoring the lost index or deleted account.
```
