### Title
Unvalidated cross-chain `PostRequest.body` bytes are converted to a `String` via `from_utf8_unchecked` in `IsmpModuleCallback::on_accept`, causing undefined behavior/panics reachable by any unprivileged sender on a connected EVM chain - (File: modules/pallets/demo/src/lib.rs)

### Summary
`pallet-ismp-demo`'s `IsmpModule::on_accept` handler, reachable via `ProxyModule::on_accept` in the Gargantua runtime whenever an incoming ISMP `PostRequest` targets the `ismp-ast` (demo) pallet ID, converts the untrusted request `body` bytes directly into a Rust `String` using the `unsafe` `String::from_utf8_unchecked` call without any UTF-8 validation, whenever the request's `source` is `StateMachine::Evm(_)`.

``` [2](#0-1) 

The `PostRequest.body` field is defined as "arbitrary bytes" that a module on any source chain may send: [3](#0-2) 

Any unprivileged contract on a connected EVM chain (e.g. via `IDispatcher(_host).dispatch(DispatchPost{...})`, exactly analogous to the LegacyMessagePasser's public `passMessageToL1`) can construct a `DispatchPost` whose `body` is any byte sequence, including sequences that are not valid UTF-8. Once this request is relayed, verified by the ISMP handler (the membership/consensus proof only verifies that the bytes were included in the source chain's commitment - it makes no claim about the content being UTF-8), and routed through `ProxyModule::on_accept` to the demo pallet: [4](#0-3) 

`from_utf8_unchecked` is documented by Rust as undefined behavior if the input is not valid UTF-8: the resulting `String` may contain corrupted data, and any subsequent access to it (string slicing, `Display`/`Debug` formatting in event decoding/indexing, SCALE encoding, RPC serialization of the emitted event, etc.) can panic, produce corrupted state, or, in the worst case under `no_std`/WASM runtime execution, trigger memory-safety violations. This is precisely analogous to the M-9 pattern: a public, unprivileged dispatch path (LegacyMessagePasser's `passMessageToL1` in the original; `IDispatcher.dispatch` from any EVM contract targeting the demo module here) allows attacker-controlled bytes to violate an implicit format assumption (valid ABI-encoded `relayMessage` calldata in the original; valid UTF-8 in this case) that downstream code does not defensively check, and the downstream code path is `unsafe`/unchecked rather than gracefully erroring.

### Impact Explanation
If triggered, this can panic the node's runtime execution while processing `on_accept`, or produce a corrupted `String` value that is subsequently serialized/indexed/displayed, which can crash indexers, RPC nodes, or block production/finalization depending on where the malformed `String` is consumed. This maps to the Hyperbridge threat model's "unsound state commitment / route unable to deliver messages" bucket - a single malformed but validly-proven cross-chain message can disrupt processing of the ISMP handler pipeline for the destination-module route, analogous to how a single malformed LegacyMessagePasser call could brick the entire Optimism migration.

### Likelihood Explanation
Likelihood is moderate: the demo pallet (`pallet-ismp-demo`, module id `ismp-ast`) is wired into the production Gargantua runtime's `ProxyModule` dispatch table, so any EVM-side contract that can send an ISMP POST request destined for that module ID (with `source = StateMachine::Evm(_)`) can trigger the bug with a single malformed message and no special privileges, similar to the original report where anyone could call the public `passMessageToL1`. However, since this is specifically the "demo"/"ismp-ast" pallet rather than a core production application module (HyperFungibleToken, IntentGateway, BandwidthManager all use safe `abi.decode`/`try_from` patterns with error propagation rather than `unsafe` UTF-8 conversion), the practical severity depends on whether this demo pallet is deployed and reachable on a live production Hyperbridge instance versus only test/dev networks.

### Recommendation
Replace `String::from_utf8_unchecked(request.body)` with the safe, fallible `String::from_utf8(request.body)`, propagating a decode error (e.g. `map_err(|_| IsmpError::Custom("invalid utf8 body".to_string()))?`) instead of invoking `unsafe` code on untrusted, attacker-controlled bytes. This mirrors the recommendation in the referenced report: never assume a specific encoding/format for data that arrives through a permissionless dispatch path, and always validate or gracefully reject malformed data rather than trusting an implicit format invariant.

### Proof of Concept
1. On a connected EVM chain, from any address, call `IDispatcher(hostAddr).dispatch(DispatchPost({ dest: <gargantua-state-machine-id>, to: ModuleId::Pallet(PalletId(*b"ismp-ast")) encoding, body: bytes(hex"FF FE 80"), timeout: 0, fee: 0, payer: msg.sender }))` — i.e., a `body` containing bytes that are not valid UTF-8 (e.g. a lone continuation byte `0x80` or overlong sequence `0xC0 0x80`).
2. A relayer delivers the proven request to Hyperbridge; `ProxyModule::on_accept` routes it (based on `request.to` matching `pallet_ismp_demo::PALLET_ID`) to `IsmpModuleCallback::on_accept`. [5](#0-4) 
3. Since `request.source` is `StateMachine::Evm(_)`, the handler executes `unsafe { String::from_utf8_unchecked(request.body) }` on the invalid bytes, producing a `String` containing invalid UTF-8 - undefined behavior per Rust's safety contract - which is then stored in the deposited `Event::Request` and can panic or corrupt state whenever it is later read/formatted/encoded. impl<T: Config> IsmpModule for IsmpModuleCallback<T> {
	fn on_accept(&self, request: PostRequest) -> Result<Weight, anyhow::Error> {
		let source_chain = request.source;

		match source_chain {
			StateMachine::Evm(_) => Pallet::<T>::deposit_event(Event::Request {
				source: source_chain,
				data: unsafe { String::from_utf8_unchecked(request.body) },
			}),
			StateMachine::Polkadot(_) | StateMachine::Kusama(_) => {
				let payload =
					<Payload<T::AccountId, <T as Config>::Balance> as codec::Decode>::decode(
						&mut &*request.body,
					)
					.map_err(|_| IsmpError::Custom("Failed to decode request data".to_string()))?;
				<T::NativeCurrency as Mutate<T::AccountId>>::mint_into(
					&payload.to,
					payload.amount.into(),
				)
				.map_err(|_| IsmpError::Custom("Failed to mint funds".to_string()))?;
				Pallet::<T>::deposit_event(Event::<T>::BalanceReceived {
					from: payload.from,
					to: payload.to,
					amount: payload.amount,
					source_chain,
				});
			},
			source => Err(IsmpError::Custom(format!("Unsupported source {source:?}")))?,
		}

		Ok(weight())
	}
