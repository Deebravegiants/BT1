### Title
Refund/timeout path in `HyperFungibleToken`/`WrappedHyperFungibleToken` is blocked by `whenNotPaused`, permanently freezing already-committed user funds while paused - (File: `sdk/packages/core/contracts/apps/HyperFungibleToken.sol`)

### Summary
`HyperFungibleToken`, `HyperFungibleTokenUpgradeable`, `WrappedHyperFungibleToken`, and `WrappedHyperFungibleTokenUpgradeable` guard `onPostRequestTimeout` — the function that returns a user's already-burned/locked tokens after a cross-chain `send()` times out — with the same `whenNotPaused` modifier used to gate new outbound transfers. As in the ECG `RateLimitedMinter`/`SurplusGuildMinter` finding, pausing is meant to stop *new* protocol usage, not prevent users from recovering funds already committed to an in-flight action; here it does exactly that.

### Finding Description
`send()` burns the caller's tokens immediately and dispatches an ISMP POST request cross-chain, guarded by `whenNotPaused`: [1](#0-0) 

If that message times out (e.g., relayer inactivity, no proof delivered in time, or the destination is unreachable), the sender's only path to recover the burned tokens is `onPostRequestTimeout`, which re-mints the amount to the original sender. This refund path is also gated by `whenNotPaused`: [2](#0-1) 

The owner's `pause()`/`unpause()` functions toggle the same `Pausable` flag used by both `send()` (new usage) and `onPostRequestTimeout` (refund of already-escrowed/burned funds): [3](#0-2) 

The identical pattern exists in the upgradeable variant: [4](#0-3) 

and in the wrapped-token variants, where the timeout handler additionally unwraps WETH back to the sender — also blocked while paused: [5](#0-4) [6](#0-5) 

Sequence of the bug:
1. A user calls `send()` before the contract is paused, burning their tokens and dispatching a cross-chain POST request.
2. Before the request is delivered, the owner calls `pause()` (e.g., in response to a detected exploit elsewhere, or routine incident response) — this is exactly the "freeze new usage" scenario the pause mechanism is designed for.
3. The dispatched request times out (relayer never delivers proof within the timeout window, or challenge period lapses without delivery).
4. Any account attempts to submit the timeout proof and call `onPostRequestTimeout` to refund the user — this reverts with `EnforcedPause` because of `whenNotPaused`, exactly mirroring how `RateLimitedMinter.mint()`'s `whenNotPaused` blocked `SurplusGuildMinter.unstake()`'s reward-claim step and thus blocked withdrawal.
5. The user's tokens remain burned/unminted and cannot be recovered until the owner unpauses — and if the ISMP timeout-claim window elapses or the owner refuses/delays unpausing, the funds can be stuck indefinitely, unlike the `send()`/`onAccept` gating which is a legitimate "stop new usage" control.

### Impact Explanation
This directly parallels the confirmed Medium-severity ECG finding: a pause meant only to halt new protocol usage instead traps user funds that are already committed to an in-flight cross-chain action. Users cannot access an `emergencyWithdraw`-style unconditional refund path — the only refund mechanism (`onPostRequestTimeout`) is itself pausable — so during any pause window, all pending timed-out transfers are frozen rather than refunded, and depending on incident duration this can become a hard, permanent loss if the owner never resumes or if downstream conditions change (e.g., request expiry/pruning) before unpause.

### Likelihood Explanation
Likely to occur in exactly the scenario pause exists for: an owner reacts to an incident by pausing the token app while in-flight `send()` transfers are outstanding. Any transfer sent shortly before a pause, or any transfer whose relayer/proof delivery is delayed for any reason during a pause window, will hit this bug when its timeout is claimed. No privileged access or malicious actor is required — a normal, honest pause by the owner combined with normal network/relayer latency triggers the freeze.

### Recommendation
Remove the `whenNotPaused` modifier from `onPostRequestTimeout` in `HyperFungibleToken.sol`, `HyperFungibleTokenUpgradeable.sol`, `WrappedHyperFungibleToken.sol`, and `WrappedHyperFungibleTokenUpgradeable.sol` (refunds of already-burned/escrowed tokens should always be permitted). Keep `whenNotPaused` only on functions that initiate *new* protocol usage (`send()`, `onAccept()` for new incoming mints, `transfer`/`transferFrom` if intentionally pausable). Add tests confirming refunds succeed while paused.

### Proof of Concept
1. Deploy `HyperFungibleToken`, configure host/dispatcher and a supported chain.
2. User calls `send()` with `amount`, burning tokens and emitting `Sent` with `commitment`.
3. Owner calls `pause()`.
4. Simulate/produce an ISMP timeout for that request (host calls `onPostRequestTimeout` with the matching `PostRequestTimeout`).
5. Observe the call reverts due to `Pausable: paused` (via `whenNotPaused`), leaving the user's balance permanently reduced by `amount` with no way to reclaim it until `unpause()` is called by the owner. [7](#0-6)

    function send(SendParams calldata params) external payable whenNotPaused {
        _burn(msg.sender, params.amount);
        DispatchPost memory request = _buildDispatchPost(params);

        bytes32 commitment;
        if (msg.value > 0) {
            commitment = IDispatcher(_host).dispatch{value: msg.value}(request);
        } else {
            commitment = dispatchWithFeeToken(request);
        }

        emit Sent({
            from: msg.sender,
            to: params.to,
            dest: string(params.dest),
            amount: params.amount,
            commitment: commitment
        });
    }

    /**
     * @notice Handles incoming cross-chain token transfer messages
     * @dev Called by the ISMP host when a POST request is received. Verifies the source
     * address matches the configured contract for that chain, then mints tokens to the
     * recipient. If calldata is present, executes it via the CallDispatcher. Virtual so a token
     * can gate deliveries, e.g. on the relayer, before calling `super`.
     * @param incoming The incoming POST request containing the token transfer message
     */
    function onAccept(IncomingPostRequest calldata incoming) public virtual override onlyHost whenNotPaused {
        PostRequest calldata request = incoming.request;

        bytes memory expectedSource = _supportedChains[request.source];
        if (expectedSource.length == 0) revert UnsupportedChain();
        if (keccak256(request.from) != keccak256(expectedSource)) revert UnauthorizedSource();

        Message memory message = abi.decode(request.body, (Message));
        address beneficiary = _toAddr(message.to);
        _mint(beneficiary, message.amount);

        if (message.data.length > 0) {
            ICallDispatcher(_dispatcher).dispatch(message.data);
        }

        emit Received({
            from: message.from,
            to: beneficiary,
            source: string(request.source),
            amount: message.amount
        });
    }

    /**
     * @notice Handles timeout of a previously dispatched cross-chain transfer
     * @dev Called by the ISMP host when a sent message times out without being delivered.
     * Re-mints the burned tokens back to the original sender as a refund.
     * @param incoming The timed-out POST request and the relayer that submitted the timeout proof
     */
    function onPostRequestTimeout(PostRequestTimeout memory incoming) public virtual override onlyHost whenNotPaused {
        Message memory message = abi.decode(incoming.request.body, (Message));
        address refundee = _toAddr(message.from);
        _mint(refundee, message.amount);
        emit Refunded({to: refundee, amount: message.amount});
    }

    function onPostRequestTimeout(PostRequestTimeout calldata incoming) external override onlyHost whenNotPaused {
        HyperFungibleToken.Message memory message = abi.decode(incoming.request.body, (HyperFungibleToken.Message));
        address refundee = _toAddr(message.from);

        if (_isWeth) {
            // Try a native-ETH push first; if the refundee cannot accept native value
            // (e.g. the caller used the ERC-20 deposit path in `send()` from a
            // non-payable contract), re-wrap the withdrawn ETH and deliver the
            // underlying WETH as an ERC-20 transfer so the timeout still settles and
            // funds are not permanently locked.
            IWETH(_underlying).withdraw(message.amount);
            (bool sent,) = refundee.call{value: message.amount}("");
            if (!sent) {
                IWETH(_underlying).deposit{value: message.amount}();
                IERC20(_underlying).safeTransfer(refundee, message.amount);
            }
        } else {
            IERC20(_underlying).safeTransfer(refundee, message.amount);
        }

        emit Refunded({to: refundee, amount: message.amount});
    }
