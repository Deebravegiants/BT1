Audit Report

## Title
Unauthenticated attacker can exhaust the gateway's Confidential Relay `activeRequests` map, causing an O(n) DoS on request processing - (File: `core/services/gateway/handlers/confidentialrelay/handler.go`)

## Summary
`handler.HandleJSONRPCUserMessage` admits any JSON-RPC request with a non-empty `req.ID` (≤200 chars) directly into `h.activeRequests`, an unbounded `map[string]*activeRequest`, with no authentication and no rate limiting on the ingress path. The only guard on the ingress path at the HTTP layer is a request body size limiter (`MaxRequestBytesLimiter` in `core/services/gateway/network/httpserver.go`), which does not bound request *count* or *concurrency*, letting an attacker inflate the map indefinitely and drive up the cost of the per-second O(n) sweep loops and DON fan-out.

## Finding Description
`gateway.ProcessRequest` in `core/services/gateway/gateway.go` routes non-legacy JSON-RPC requests straight to `h.HandleJSONRPCUserMessage` without calling `msg.Validate()` or any signature/auth check (that validation path is only exercised for `isLegacyRequest`). `handler.HandleJSONRPCUserMessage` in `core/services/gateway/handlers/confidentialrelay/handler.go` then only checks `req.ID` length constraints before calling `h.newActiveRequest`, which unconditionally inserts into `h.activeRequests` with no maximum size check — unlike the sibling `common.requestCache`, which enforces `maxCacheSize` and rejects once full. The two existing rate limiters (`globalNodeRateLimiter`, `perNodeRateLimiters`) only guard `HandleNodeMessage` (DON→gateway responses), not this inbound user path. Each admitted entry is scanned by two O(n) background sweeps (`removeExpiredRequests`, `forwardGracedRequests`) every `defaultCleanUpPeriod` (1s) for up to `requestTimeout` (30s default), and also triggers a fan-out `SendToNode` call to every DON member via `fanOutToNodes`. This confirms the reported code path: unbounded, unauthenticated, unrate-limited admission into a map that is both linearly swept and multiplicatively fanned out.

## Impact Explanation
An unauthenticated network attacker can grow `h.activeRequests` arbitrarily by sending unique `req.ID` values, increasing per-tick CPU cost of the sweep loops (proportional to map size), memory usage, lock contention under `h.mu`, and amplified outbound traffic to every DON member per request. This degrades or denies legitimate confidential-relay/vault request processing on the gateway — a concrete availability impact on a public-facing, unauthenticated ingress path, consistent with an in-scope gateway-availability/DoS impact class.

## Likelihood Explanation
High. The entry point (`gateway.ProcessRequest` → `HandleJSONRPCUserMessage`) is internet-facing, requires no credentials, and no code path rejects requests once the map grows large — this is a straightforward, repeatable resource-exhaustion primitive, not an edge case requiring special conditions.

## Recommendation
- Add a maximum size to `h.activeRequests` (mirroring `common.requestCache.maxCacheSize`) and reject new admissions past the limit with a clear error/response code.
- Add a per-sender and/or global rate limiter on the `HandleJSONRPCUserMessage` ingress path, similar to the `userRateLimiter` pattern used in `core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go`.
- Consider a time-ordered eviction structure so sweep cost doesn't scale with attacker-controlled backlog size.

## Proof of Concept
1. Configure a gateway with the Confidential Relay handler enabled for a DON.
2. Send a high rate of HTTP POST requests to the gateway's public endpoint with JSON-RPC method `confidentialrelay_secretsGet` (or `capabilityExec`), each with a fresh unique `id`, no `Authorization` header, and arbitrary `params`.
3. Since `gateway.ProcessRequest` performs no signature/authorization check for non-legacy requests, and `HandleJSONRPCUserMessage` performs only an ID-length check before calling `newActiveRequest`, each request is admitted into `h.activeRequests` and fanned out via `SendToNode` to every DON member.
4. Send requests faster than the 1-second cleanup cadence can drain them (e.g., thousands/sec); observe `len(h.activeRequests)` grow unbounded, increased per-tick latency in `removeExpiredRequests`/`forwardGracedRequests`, and amplified traffic to DON nodes. func (h *handler) forwardGracedRequests(ctx context.Context) {
	h.mu.RLock()
	var graced []*activeRequest
	now := h.clock.Now()
	for _, ar := range h.activeRequests {
		if ar.graceElapsed(now) {
			graced = append(graced, ar)
		}
	}
	h.mu.RUnlock()

	for _, ar := range graced {
		h.forwardAfterGrace(ctx, ar)
	}
}
