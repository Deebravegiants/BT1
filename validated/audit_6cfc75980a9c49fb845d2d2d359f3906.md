## Analog Found

### Title
Missing Arbitrum/L2 sequencer-uptime check in `SimplexPaymaster` Chainlink price reads allows stale-price gas mispricing during sequencer outages - (File: `evm/src/utils/SimplexPaymaster.sol`)

### Summary
`SimplexPaymaster` is an ERC-4337 paymaster deployed across multiple chains, including Arbitrum, that prices gas in ERC-20 tokens using Chainlink `AggregatorV3Interface` feeds [1](#0-0) . Its oracle read path, `_getOraclePrice`, checks only for a non-positive answer and staleness against `maxOracleAge`, with no check that the L2 sequencer (e.g. Arbitrum's) is up, exactly the missing check flagged in the referenced report.

### Finding Description
`_getOraclePrice` is the sole gate on Chainlink data used for every gas-priced UserOperation: [2](#0-1) 

It is invoked from `_tokenPrice`, which is called during `validatePaymasterUserOp`/prefund calculation for both the token oracle and the native oracle: [3](#0-2) 

When an Arbitrum sequencer goes down, the last Chainlink round on L1-relayed feeds can remain within `maxOracleAge` while the L2 itself is not producing fresh blocks/state, or, upon sequencer restart, a backlog of stale rounds can be reported as "fresh" relative to a jumped `block.timestamp`. Chainlink explicitly recommends checking the L2 sequencer uptime feed (`0xFdB631F5EE196F0ed6FAa767959853A9F217697D` and analogous feeds) before trusting `latestRoundData()` on any Arbitrum/Optimism-style rollup, exactly as flagged in the referenced Blueberry report. `SimplexPaymaster` does not include this check anywhere; a `grep` for sequencer-related identifiers turns up no such feed integration in the EVM contracts.

### Impact Explanation
Any unprivileged user submitting a UserOperation through the ERC-4337 EntryPoint can have their gas priced off a stale/incorrect Chainlink answer during or immediately after an Arbitrum sequencer outage, since `_getOraclePrice`'s only safety checks are `answer <= 0` and the staleness window [4](#0-3) . This can result in users being charged incorrect (potentially far too low or far too high) token amounts for gas, and — since the same price feeds gate the paymaster's fee-recycling swaps (`swapAndDeposit`) — the treasury/paymaster funds can also be swapped at a stale price, causing fund loss to the paymaster's ERC-20 surplus or draining the deposit at a bad rate.

### Likelihood Explanation
Arbitrum sequencer downtime is an infrequent but recurring, publicly-documented event (multiple historical outages), and the exploit requires no privileged access: any user or bundler can submit UserOperations during/after such a window and be priced by `_tokenPrice`/`_getOraclePrice`. Because the contract is explicitly designed to be deployed on Arbitrum among other chains (BSC, Base, Ethereum) per its own documentation [5](#0-4) , the L2-specific gap is directly reachable in production configurations.

### Recommendation
Add an Arbitrum (and other L2) sequencer-uptime feed check in `_getOraclePrice` (or a wrapper called before it), reverting if the sequencer feed reports `down`, or if it has been `up` for less than a grace period (e.g. Chainlink's recommended pattern using `latestRoundData()` on the sequencer uptime feed plus a `GRACE_PERIOD_TIME`). This should gate both the token oracle and native oracle reads used in `_tokenPrice`, `estimateTokenCost`, and `swapAndDeposit`.

### Proof of Concept
1. Deploy `SimplexPaymaster` on Arbitrum with `nativeOracle`/`tokenConfigs[token].tokenOracle` pointed at real Chainlink ETH/USD and TOKEN/USD feeds, per `Params`/`TokenConfig` [6](#0-5) .
2. Simulate an Arbitrum sequencer outage (as in Chainlink's documented June 2022 incident) where the last on-chain round remains within `maxOracleAge` of `block.timestamp` even though the L2 state/price is stale relative to real market conditions.
3. Submit a UserOperation through the EntryPoint; `validatePaymasterUserOp` → `_tokenPrice` → `_getOraclePrice` accepts the stale answer because only `answer <= 0` and `block.timestamp - updatedAt > maxOracleAge` are checked [4](#0-3) , mispricing the user's gas payment or a concurrent `swapAndDeposit` fee-recycling swap.

```text
    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
```
