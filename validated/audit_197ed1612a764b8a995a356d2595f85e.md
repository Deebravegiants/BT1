### Title
Gas key owner can burn a gas key's deposited balance by deleting the key instead of returning funds to depositor - (File: `runtime/runtime/src/access_keys.rs`)

### Summary
This is a valid analog of the MasterChef "owner locks depositor's tokens" pattern (C4 2022-02-concur, M-15). In MasterChef, the contract owner controls a whitelist of "depositors"; removing a depositor after funds were deposited leaves those funds permanently stuck/unrecoverable. In nearcore's gas key feature, the account's `FullAccess` key holder plays the role of "owner": it can fund a gas key via `TransferToGasKeyAction` and later unilaterally delete that gas key via `DeleteKeyAction`. When the gas key balance is at or below `GasKeyInfo::MAX_BALANCE_TO_BURN` (1 NEAR), deletion succeeds and the entire remaining balance is silently burned rather than refunded to the account or to whoever funded the key, instead of being routed through the normal `WithdrawFromGasKeyAction` path that returns funds to the account.

### Finding Description
A gas key is an access key type (`GasKeyFullAccess`/`GasKeyFunctionCall`) holding a prepaid `Balance` used to pay for gas/fees of transactions signed by that key [1](#0-0) . Funds are added to the key via `action_transfer_to_gas_key`, which increases `gas_key_info.balance` [2](#0-1) . The only intended way to recover this balance back to the account is `action_withdraw_from_gas_key`, which requires knowledge of the gas key's own signature to authorize the withdrawal and credits the balance back to `account.amount()` [3](#0-2) .

However, the account's `FullAccess` key (the "owner" of the account, analogous to the MasterChef contract owner) can issue a `DeleteKeyAction` against the gas key's public key at any time. This is handled by `action_delete_key` → `delete_gas_key`: [4](#0-3) 

If `gas_key_info.balance <= GasKeyInfo::MAX_BALANCE_TO_BURN` (currently 1 NEAR, per `core/primitives-core/src/account.rs:552-554`), the delete succeeds unconditionally: the balance is added to `result.tokens_burnt` (i.e., destroyed — not refunded to the account, and not accessible to whoever funded the key), and the access key (and its nonces) are removed from state. Only if the balance exceeds the 1 NEAR threshold does the runtime reject the deletion with `GasKeyBalanceTooHigh` [5](#0-4) . Tests confirm this exact behavior — a gas key with exactly 1 NEAR is deleted and the deposit is burned: [6](#0-5) 

whereas a balance of 1 NEAR + 1 yoctoNEAR is blocked [7](#0-6) . The same threshold/burn logic also applies in bulk when the whole account is deleted (`action_delete_account` → `compute_gas_key_balance_sum` / `GasKeyBalanceTooHigh`) [8](#0-7) .

This mirrors the MasterChef bug class precisely: an unprivileged/underprivileged actor (the entity relying on the gas key balance being withdrawable, e.g. a relayer that funded a session/relayer key, per the wallet-contract relayer pattern [9](#0-8) ) has funds parked in a construct (`gas key`) that the privileged actor (`FullAccess` key holder) can revoke at will, and revocation destroys the funds instead of returning them to any party.

### Impact Explanation
Whenever a `FullAccess` key holder deletes a gas key with a balance up to 1 NEAR, that balance is permanently destroyed (`tokens_burnt`), rather than being refunded to the account (as the `WithdrawFromGasKeyAction` path does) or to whoever transferred funds into the gas key. This is a legitimate, protocol-level token-burning/loss primitive triggerable purely by a transaction from the account owner, with no economic benefit to anyone and unrecoverable funds loss up to 1 NEAR per gas key (and cumulatively up to 1 NEAR across all gas keys when deleting the whole account). Unlike the MasterChef case, this is "by design" (deliberate anti-DoS/anti-spam threshold to bound burn amounts on deletion) rather than an oversight, but it does constitute real, protocol-sanctioned token destruction attributable to owner action, matching the "concrete token... loss" acceptance criterion.

### Likelihood Explanation
This requires no special privilege beyond what every account already has (its own `FullAccess` key), and no attacker coordination — it is reachable by any account holder simply submitting a `DeleteKeyAction` for a gas key it created, funded (or that a third party funded via `TransferToGasKeyAction`), and choosing not to first withdraw the balance. Because the 1 NEAR burn threshold is a hard protocol limit (not configurable per-application), any relayer/session-key design that leaves funds in a gas key for later use is exposed to this loss if the key is deleted (maliciously or accidentally) before `WithdrawFromGasKeyAction` is called.

### Recommendation
When deleting a gas key (or account) with a non-zero balance below `MAX_BALANCE_TO_BURN`, refund the balance to the account (`account.set_amount`) instead of adding it to `tokens_burnt`, mirroring the behavior of `action_withdraw_from_gas_key`. If burning small balances is intentionally retained as an anti-spam mechanism (to bound the cost of iterating/cleanup), this should be clearly documented as an accepted, bounded-loss design decision, and any relayer-facing documentation (e.g. `docs/architecture/how/meta-tx.md`) should explicitly warn that gas key balances up to 1 NEAR can be destroyed by the account owner via key deletion, so relaying/session-key implementations withdraw balances before allowing key rotation/deletion.

### Proof of Concept
1. Account `A` (holds a `FullAccess` key) adds a gas key `G` via `AddKeyAction` with `AccessKey::gas_key_full_access(n)` [10](#0-9) .
2. `A` (or any relayer/user funding on `A`'s behalf) funds `G` with `TransferToGasKeyAction { public_key: G, deposit: 1 NEAR }`, increasing `gas_key_info.balance` to `1 NEAR` [2](#0-1) .
3. Before anyone withdraws via `WithdrawFromGasKeyAction`, `A` submits `DeleteKeyAction { public_key: G }` using its `FullAccess` key.
4. `action_delete_key` routes to `delete_gas_key`; since `1 NEAR <= MAX_BALANCE_TO_BURN`, the deletion succeeds, `result.tokens_burnt += 1 NEAR`, and `G` is removed from state [4](#0-3) .
5. The 1 NEAR is gone — not credited back to `A`'s `account.amount()`, and unreachable by anyone (this exact flow is unit-tested and asserted in `test_delete_gas_key_balance_at_threshold`) [6](#0-5) .

fn delete_gas_key(
    config: &RuntimeConfig,
    state_update: &mut TrieUpdate,
    account: &mut Account,
    result: &mut ActionResult,
    account_id: &AccountId,
    public_key: &PublicKey,
    access_key: &AccessKey,
    gas_key_info: &GasKeyInfo,
) -> Result<(), RuntimeError> {
    if gas_key_info.balance > GasKeyInfo::MAX_BALANCE_TO_BURN {
        result.result = Err(ActionErrorKind::GasKeyBalanceTooHigh {
            account_id: account_id.clone(),
            public_key: Some(Box::new(public_key.clone())),
            balance: gas_key_info.balance,
        }
        .into());
        return Ok(());
    }
    result.tokens_burnt =
        result.tokens_burnt.checked_add(gas_key_info.balance).ok_or(IntegerOverflowError)?;
    let num_nonces = gas_key_info.num_nonces as usize;
    for i in 0..gas_key_info.num_nonces {
        remove_gas_key_nonce(state_update, account_id.clone(), public_key.clone(), i);
    }
    let nonce_key_len = gas_key_nonce_key_len(account_id, &public_key.into());
    let nonce_remove_compute = storage_removes_compute(
        &config.wasm_config.ext_costs,
        num_nonces,
        nonce_key_len * num_nonces,
        AccessKey::NONCE_VALUE_LEN * num_nonces,
    );
    result.compute_usage = safe_add_compute(result.compute_usage, nonce_remove_compute)?;
    remove_access_key(state_update, account_id.clone(), public_key.clone());
    account.set_storage_usage(account.storage_usage().saturating_sub(gas_key_storage_cost(
        &config.fees,
        public_key,
        access_key,
        gas_key_info.num_nonces,
    )));
    Ok(())
}

pub(crate) fn action_transfer_to_gas_key(
    state_update: &mut TrieUpdate,
    result: &mut ActionResult,
    account_id: &AccountId,
    action: &TransferToGasKeyAction,
) -> Result<(), RuntimeError> {
    let Some(mut access_key) = get_access_key(state_update, account_id, &action.public_key)? else {
        result.result = Err(ActionErrorKind::GasKeyDoesNotExist {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
        }
        .into());
        return Ok(());
    };
    let Some(gas_key_info) = access_key.gas_key_info_mut() else {
        // Key exists but is not a gas key
        result.result = Err(ActionErrorKind::GasKeyDoesNotExist {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
        }
        .into());
        return Ok(());
    };

    gas_key_info.balance = gas_key_info.balance.checked_add(action.deposit).ok_or_else(|| {
        RuntimeError::StorageError(StorageError::StorageInconsistentState(
            "gas key balance integer overflow".to_string(),
        ))
    })?;
    set_access_key(state_update, account_id.clone(), action.public_key.clone(), &access_key);
    Ok(())
}

pub(crate) fn action_withdraw_from_gas_key(
    state_update: &mut TrieUpdate,
    account: &mut Account,
    result: &mut ActionResult,
    account_id: &AccountId,
    action: &WithdrawFromGasKeyAction,
) -> Result<(), RuntimeError> {
    let Some(mut access_key) = get_access_key(state_update, account_id, &action.public_key)? else {
        result.result = Err(ActionErrorKind::GasKeyDoesNotExist {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
        }
        .into());
        return Ok(());
    };
    let Some(gas_key_info) = access_key.gas_key_info_mut() else {
        // Key exists but is not a gas key
        result.result = Err(ActionErrorKind::GasKeyDoesNotExist {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
        }
        .into());
        return Ok(());
    };

    let Some(updated_balance) = gas_key_info.balance.checked_sub(action.amount) else {
        result.result = Err(ActionErrorKind::InsufficientGasKeyBalance {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
            balance: gas_key_info.balance,
            required: action.amount,
        }
        .into());
        return Ok(());
    };
    gas_key_info.balance = updated_balance;
    set_access_key(state_update, account_id.clone(), action.public_key.clone(), &access_key);

    let new_account_balance = account.amount().checked_add(action.amount).ok_or_else(|| {
        RuntimeError::StorageError(StorageError::StorageInconsistentState(
            "Account balance integer overflow".to_string(),
        ))
    })?;
    account.set_amount(new_account_balance);
    Ok(())
}
