## Finding

### Title
Stale `TombStone.original_owner` survives ordinary object transfers, letting a past owner reclaim an object via `object::unburn` after it changes hands - ([File: aptos-move/framework/aptos-framework/sources/object.move])

### Summary
The external report's root cause — a lower-level primitive (`VotesUpgradeable::delegate`) mutating a custody/authority-relevant field while bypassing the side-effect (`addValidator`) that a higher-level wrapper (`stake`) normally performs, leaving a stale/incorrect record of "who is entitled to what" — has a structural analog in Aptos's object model around soft-burn/reclaim bookkeeping.

### Finding Description
`aptos_framework::object` supports a "soft burn" mechanism: `burn<T>()` moves a `TombStone { original_owner }` resource under the object, and `unburn<T>()` later lets that address reclaim the object if it ever ends up owned by the sentinel `BURN_ADDRESS`: [1](#0-0) 

Two independent transfer code paths exist for objects:
- `transfer_with_ref` (via `LinearTransferRef`) explicitly clears any existing `TombStone` on transfer: "Undo soft burn if present as we don't want the original owner to be able to reclaim by calling unburn later." [2](#0-1) 
- `transfer`/`transfer_call`/`transfer_to_object` all resolve to `transfer_raw` → `transfer_raw_inner`, which only updates `object_core.owner` and emits an event — it never checks for or clears `TombStone`: [3](#0-2) 

`burn` does not disable `allow_ungated_transfer`, so a tombstoned object can still be freely moved through the ordinary `transfer` path any number of times, all while the original `TombStone.original_owner` field keeps pointing at whoever performed the *original* soft burn, not the current or most recent owner.

`unburn`'s "old functionality" branch relies on that field to decide who may reclaim an object once it lands at `BURN_ADDRESS`: [4](#0-3) 
It checks only `original_owner_addr == signer::address_of(original_owner)` — it has no way to know that the object has changed hands one or more times since the tombstone was created via `transfer_raw_inner`.

### Impact Explanation
Sequence:
1. Alice owns object `O`. She calls `object::burn(alice, O)` → `TombStone{original_owner: alice}` is attached; `O` is still transferable (ungated transfer is not disabled by `burn`).
2. Alice sells/transfers `O` to Bob via the ordinary `object::transfer` entry function. Ownership moves to Bob, but the stale `TombStone{original_owner: alice}` remains untouched (only `transfer_with_ref` clears it).
3. `O` continues through the normal economy (Bob → Carol → a marketplace/vault, etc.) with the stale tombstone silently riding along, since nothing in the ungated `transfer` path surfaces or resets it.
4. At some point the current legitimate owner deliberately (or a contract/vault logic does so on their behalf) sends `O` to `BURN_ADDRESS` to actually destroy it, relying on the documented semantics that only the entity that performed that burn can reclaim it.
5. Alice — who parted with `O` legitimately long before and has no remaining claim — calls `object::unburn(alice, O)`. Because `object_core.owner == BURN_ADDRESS` and `TombStone.original_owner == alice` (unchanged since step 1), the second branch fires and `transfer_raw_inner(object_addr, alice)` reassigns ownership of `O` back to Alice.

This reassigns owner control of an object — and everything nested/held under it (e.g., a token, an NFT, a resource-account-owned object, or a fungible-asset holding object) — to a stale prior owner instead of the party that actually controlled/burned it, breaking the "burn/reclaim rights track the real custody chain" invariant. This is an unauthorized ownership reassignment of object-held value with no signer authority from the legitimate current/former owner at the time of reclaim.

### Likelihood Explanation
The precondition is narrow but realistic: it requires (a) a soft-burned object to be later transferred through the ordinary `transfer`/`transfer_call`/`transfer_to_object` path (not `transfer_with_ref`) without any subsequent owner calling `unburn` to clear the marker, and (b) the object eventually being sent to the literal `BURN_ADDRESS` (the documented "old functionality" path). Any protocol or wallet flow that soft-burns objects and later re-uses/re-sells them (rather than immediately clearing the tombstone) is exposed. The bug is a pure logic/state-consistency flaw reachable by any two unprivileged signers with no special permissions, matching the custody-gate criteria (unauthorized ownership reassignment, corrupted recovery rights).

### Recommendation
Make `transfer_raw_inner` (or `transfer_raw`) clear any existing `TombStone` on ownership change, mirroring the behavior already implemented in `transfer_with_ref`, so that reclaim rights cannot outlive a legitimate transfer of the object to a new owner. Alternatively, disallow ungated transfer of tombstoned objects entirely (require an explicit `unburn` before any further transfer), removing the possibility of a stale `original_owner` record.

### Proof of Concept
Conceptual Move test sequence (not run, derived from code reading):
```
// 1. alice owns object `obj`
object::burn(&alice, obj);                       // TombStone{original_owner: alice} attached

// 2. alice sells/transfers via ordinary path (does NOT clear TombStone)
object::transfer(&alice, obj, bob_addr);         // owner = bob, TombStone unchanged

// 3. bob transfers further (e.g. to a marketplace or carol) — still no TombStone check
object::transfer(&bob, obj, carol_addr);

// 4. carol, believing this finalizes destruction, "burns" by moving to BURN_ADDRESS
object::transfer(&carol, obj, BURN_ADDRESS);

// 5. alice, who has had no claim on `obj` since step 2, reclaims it:
object::unburn(&alice, obj);                     // succeeds: owner reassigned back to alice
assert!(object::owner(obj) == alice_addr, 0);    // alice now owns an object she sold away
```

    /// Transfer to the destination address using a LinearTransferRef.
    public fun transfer_with_ref(self: LinearTransferRef, to: address) {
        assert!(!exists<Untransferable>(self.self), error::permission_denied(EOBJECT_NOT_TRANSFERRABLE));

        // Undo soft burn if present as we don't want the original owner to be able to reclaim by calling unburn later.
        if (exists<TombStone>(self.self)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(self.self);
        };

        let object = borrow_global_mut<ObjectCore>(self.self);
        assert!(
            object.owner == self.owner,
            error::permission_denied(ENOT_OBJECT_OWNER),
        );
        event::emit(
            Transfer {
                object: self.self,
                from: object.owner,
                to,
            },
        );
        object.owner = to;
    }

    /// Add a TombStone to the object.  The object will then be interpreted as hidden via indexers.
    /// This only works for objects directly owned and for simplicity does not apply to indirectly owned objects.
    /// Original owners can reclaim burnt objects any time in the future by calling unburn.
    /// Please use the test only [`object::burn_object_with_transfer`] for testing with previously burned objects.
    public entry fun burn<T: key>(owner: &signer, object: Object<T>) {
        let original_owner = signer::address_of(owner);
        assert!(is_owner(object, original_owner), error::permission_denied(ENOT_OBJECT_OWNER));
        let object_addr = object.inner;
        assert!(!exists<TombStone>(object_addr), EOBJECT_ALREADY_BURNT);
        move_to(&create_signer(object_addr), TombStone { original_owner });
    }

    /// Allow origin owners to reclaim any objects they previous burnt.
    public entry fun unburn<T: key>(
        original_owner: &signer,
        object: Object<T>,
    ) {
        let object_addr = object.inner;
        assert!(exists<TombStone>(object_addr), error::invalid_argument(EOBJECT_NOT_BURNT));

        // The new owner of the object can always unburn it, but if it's the burn address, we go to the old functionality
        let object_core = borrow_global<ObjectCore>(object_addr);
        if (object_core.owner == signer::address_of(original_owner)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object_addr);
        } else if (object_core.owner == BURN_ADDRESS) {
            // The old functionality
            let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
            assert!(
                original_owner_addr == signer::address_of(original_owner),
                error::permission_denied(ENOT_OBJECT_OWNER)
            );
            transfer_raw_inner(object_addr, original_owner_addr);
        } else {
            abort error::permission_denied(ENOT_OBJECT_OWNER);
        };
    }
