### Title
AquariusStableLp fair price multiplies the raw StableSwap invariant `D` by the minimum leg price, undervaluing LP collateral whose legs are not pegged in USD terms and enabling premature liquidation theft - (File: common/src/oracle/lp_stable.rs)

### Summary
`fair_stable_lp_price_wad` values an Aquarius stable-pool share as `D * min(price_a, price_b) / total_shares`, where `D` is solved from raw WAD-normalized reserves. This is the Curve-style "virtual price times cheapest coin" convention, but it is only exact when both legs are valued in the same numéraire (e.g., USDC/USDT). For pools pairing a yield-bearing or otherwise repriced asset against its base (the live `xSolvBTC/SolvBTC_LP` market), the legs have legitimately different USD prices and the formula underprices the LP by up to the full leg-price ratio. Because the same strict price feeds `Context`-cached collateral valuation in health-factor computation, an unprivileged liquidator can call `liquidate` on positions that are solvent at the true LP value and seize collateral whose real worth exceeds the accounted debt plus bonus — theft of borrower funds.

### Finding Description
In `common/src/oracle/lp_stable.rs:96-109`, `fair_stable_lp_price_wad` converts both reserves to WAD, solves the two-coin invariant `D` via `solve_stable_d`, then applies `min_price = a.price_wad.min(b.price_wad)` and returns `D * min_price / share_supply_wad`. `D` is denominated in raw token units; it is not a base-asset-denominated redemption rate. The true USD value of the pool is `(reserve_a * price_a + reserve_b * price_b)`-equivalent along the invariant, which the min-price expression lower-bounds. The gap equals the spread between the two leg prices on the richer leg's share of liquidity.

The analogous Balancer report questioned multiplying `getRate()` by the minimum token price. Here the situation is inverted in detail but identical in class: the formula bakes in `min()` unconditionally. For a pool like `xSolvBTC/SolvBTC` (configured in `configs/mainnet/markets.json:1293-1314` with `AquariusStableLp`, sanity band 4000–12000 USD), `xSolvBTC` is a receipt token that appreciates against `SolvBTC` as yield accrues. Its nested leg price `key_a` therefore legitimately exceeds `key_b`, and every share is valued as if all `xSolvBTC` reserves were plain `SolvBTC`. The mispricing grows monotonically over time and requires no manipulation — the leg prices are honest oracle readings within their bands.

The provider path in `contracts/price-aggregator/src/providers/aquarius.rs:88-114` resolves both leg prices via `engine::resolve_nested`, reads reserves/shares/amp from the pool, and emits this underpriced `price_wad` as the asset's strict price. That price is what the controller's `Context`-cached risk math uses for collateral valuation and health-factor checks before `liquidate` executes its multi-leg seize plan.

### Impact Explanation
Theft of user funds via wrongful liquidation. A borrower whose collateral is the mispriced LP token shows a health factor lower than the economically correct one. Once the reported HF crosses 1.0 — earlier than it should — any unprivileged address can call `liquidate`, repay debt, and receive collateral through `SeizeMode::Transfer`/`Credit` plus the HF-based bonus. The seized LP's true market value exceeds the debt repaid by more than the intended bonus margin; the difference is extracted from the borrower. The borrower also loses borrowing capacity earlier than warranted (`min_borrow_collateral_usd` is computed from the same strict price). The undervaluation is bounded by the leg-price ratio, but for a yield-bearing leg the ratio compounds indefinitely with no corrective mechanism.

### Likelihood Explanation
Medium. Exploitation requires no price manipulation, flash loan, or privileged action — only that the two legs' oracle prices diverge and a victim position approaches the liquidation threshold. The `xSolvBTC/SolvBTC_LP` market is configured precisely this way: a yield-bearing leg whose price naturally drifts upward versus the base leg. The mispricing cannot produce overvaluation (min() is a lower bound), so the insolvency/over-borrow direction is not reachable; the harm is bounded to unfair liquidations and reduced collateral utility, which keeps severity below High. For pegged stable pairs like `PYUSDUSDC_LP` the error is negligible while the peg holds.

### Recommendation
For `AquariusStableLp` sources, value the pool by the actual reserves rather than by `D * min_price` when the legs are priced in a common numéraire: compute `fair = (reserve_a_norm * price_a + reserve_b_norm * price_b) / share_supply` for the withdrawal-style lower bound, or at minimum multiply `D` by a liquidity-weighted leg price instead of `min`. If the conservative `min` bound is intentionally retained as the strict (liquidation-side) price, document it as an ADR and bound the resulting error — e.g., reject the source when `price_a / price_b` diverges beyond a configured ratio — so that yield-bearing-legged pools cannot silently drift into wrongful-liquidation territory.

### Proof of Concept
Consider the live `xSolvBTC/SolvBTC` stable pool (`pool: CCNXGPE4AQCSNEBZO3XJDKKDI3CRLYMVS6UWBBTVDLALLWMJEXBORQ2A`, `reserve_a_decimals = reserve_b_decimals = 8`, amp reported by `aquarius_amp_call`). Suppose the pool holds 40 xSolvBTC and 60 SolvBTC (units of 1e8) and the honest leg prices are `price_a = 1.10e18` (xSolvBTC appreciated 10%) and `price_b = 1.00e18`. With `total_shares = 100e7`-scale supply, `D ≈ 100e18` WAD-units and the code returns `fair = 100e18 * 1.00e18 / 100e18 = 1.00` USD/share, while the reserve-weighted value is `(40*1.10 + 60*1.00)/100 = 1.04` USD/share — a ~3.8% understatement that grows as `xSolvBTC` accrues. A borrower posted this LP at a threshold leaving 3% headroom shows `HF < 1` on-chain while truly solvent; `liquidate` then succeeds, the liquidator repays debt and seizes LP worth 4% more than accounted, pocketing the mispricing plus the liquidation bonus at the borrower's expense. All steps use only `liquidate` and honest oracle reads.
