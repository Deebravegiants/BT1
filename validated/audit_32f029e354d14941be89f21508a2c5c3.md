Audit Report

## Title
Missing fuel reassignment in `EngineMeter::charge_ref_time` breaks wasmi fuel/ref_time reconciliation - ([File: substrate/frame/contracts/src/gas.rs])

## Summary
`EngineMeter::<T>::charge_ref_time` computes `amount = ref_time / ref_time_by_fuel()` and calls `self.fuel.checked_sub(amount)` purely to check for underflow, but discards the `Option<u64>` result instead of assigning it back to `self.fuel`. `self.fuel` is therefore never decremented by this function, so the `Syncable` value it returns (which is subsequently pushed into the wasmi engine's fuel counter) is always the stale, pre-host-call value rather than the correctly reduced post-host-call value. [1](#0-0) 

## Finding Description
The code at lines 69-76 is exactly as described in the claim: `self.fuel.checked_sub(amount).ok_or_else(|| Error::<T>::OutOfGas)?;` evaluates and drops the `Option<u64>`, then `Ok(Syncable(self.fuel))` returns the unmodified `self.fuel`. [1](#0-0)  This is called from `GasMeter::sync_to_executor`, invoked when leaving a host function to reconcile the engine's fuel counter with the ref_time consumed by that host call. [2](#0-1)  Contrast this with the sibling method `set_fuel`, used on entering a host function, which correctly does `self.fuel = fuel;` after computing consumed weight. [3](#0-2)  The asymmetry (one method mutates `self.fuel`, the other doesn't despite an identical “compute delta, mutate state” pattern) strongly indicates an unintentional omission rather than deliberate design.

Primary ref_time accounting is unaffected because `GasMeter::charge` independently reduces `gas_left` directly via `checked_sub`, and this path is not touched by the bug. [4](#0-3)  However, the `engine_meter.fuel` field — which represents the execution engine's own budget for raw bytecode execution between host-call boundaries — never decreases across `charge_ref_time` calls, so each time `sync_to_executor` is invoked, the returned `Syncable` (destined to update the wasmi engine's actual fuel counter) still carries the pre-call value.

## Impact Explanation
This is a real, reproducible logic bug in the ref_time reconciliation path for contracts host-function calls. However, based on the code alone, its exploitability for actual weight-budget overrun is questionable and requires the surrounding pipeline (specifically how `Syncable` is consumed by callers to actually re-arm the wasmi engine's fuel counter) to confirm the severity claimed. The claim itself acknowledges gas_left (the primary weight budget enforced by the runtime) is not bypassed, since `charge` directly reduces `gas_left`, independent of `engine_meter.fuel`. The only affected quantity is the internal wasmi engine fuel counter, which — if truly disconnected from decrementing — could let a contract execute more raw wasm instructions per host-call boundary than intended, but the actual ref_time cost of each host call is still correctly charged against `gas_left` via `charge()`, meaning the overall transaction weight limit is still respected and the runtime will still terminate/reject execution once `gas_left` is exhausted. This limits the impact to an internal metering inefficiency in the wasmi engine's own instruction-counting granularity rather than a genuine consensus-breaking weight-limit bypass, since the outer `gas_left` accounting (which the runtime enforces for extrinsic weight fees and DoS protection) remains intact and correctly charged.

## Likelihood Explanation
The code path is definitely reachable on every host function call in pallet-contracts, requiring no special preconditions — this part of the claim is accurate. However, because `gas_left` (the actual enforced budget) is untouched by this bug, the practical consequence is bounded and does not by itself demonstrate a weight-budget bypass exploitable to cause resource exhaustion beyond the already-enforced `gas_limit`.

## Recommendation
Fix `charge_ref_time` to assign the decremented value back to `self.fuel`:
```rust
self.fuel = self.fuel.checked_sub(amount).ok_or_else(|| Error::<T>::OutOfGas)?;
```

## Proof of Concept
A unit test in `substrate/frame/contracts/src/gas.rs`'s test module can directly demonstrate the bug: construct a `GasMeter`, call `sync_from_executor` to set an initial `engine_meter.fuel`, then `charge()` and `sync_to_executor()`, and assert that the returned `Syncable`'s value equals `initial_fuel - (consumed_ref_time / ref_time_by_fuel())`. This assertion fails against current code since `self.fuel` is never reduced by `charge_ref_time`, confirming the code defect at lines 69-76. [1](#0-0)
