### Title
Pending bad debt is invisible to the supply index, so suppliers can withdraw at the pre-write-down index and concentrate the loss on remaining suppliers - (File: contracts/pool/src/ops/withdraw.rs)

### Summary
CVE-2022-26716 is a memory-corruption bug where an object is used with stale/incorrect internal state. The analog in XOXNO Lending is the split between *booked* bad debt and the *materialized* supply index. When an account goes insolvent, the unrecoverable debt exists on the controller's position books, but the pool's `supply_index` is only written down when `liquidate`, `clean_bad_debt`, or `force_socialize_bad_debt` eventually calls `interest::apply_bad_debt_to_supply_index`. Between insolvency and that write-down, `withdraw` still values every supply share at the stale (un-written-down) index. Any supplier who withdraws in that window exits whole, and the remaining suppliers absorb a strictly larger pro-rata share of the socialized loss. A single unprivileged address controlling a large supply share can therefore transfer most of a bad-debt loss onto passive suppliers.

### Finding Description
- `withdraw` → `contracts/pool/src/ops/withdraw.rs::apply`/`accounting` burns shares at the current cached supply index and debits cash with only `require_reserves`, `require_utilization_below_max`, and `require_supply_for_debt` gates (`gate_and_debit`). None of these gates account for pending-but-unapplied bad debt: `require_supply_for_debt` compares supply against booked debt at face value, and the harness test explicitly notes "`backing_shortfall` still values Alice's uncollateralised debt at face" [1](#0-0) .
- The write-down only happens inside a seize: `contracts/pool/src/ops/seize.rs::apply` calls `interest::apply_bad_debt_to_supply_index(&mut cache, bad_debt)` then `cache.burn_debt(position)` [2](#0-1) , and `apply_bad_debt_to_supply_index` reduces `supply_index` by `bad_debt / total_supplied_value` [3](#0-2) .
- Because the reduction factor is computed against `supplied` *at seize time*, every share withdrawn before the seize is paid out at the old index and shrinks the denominator, amplifying each remaining supplier's loss.
- The repository's own test proves the asymmetry: `supplier_can_exit_ahead_of_bad_debt_writedown` shows Bob recovering `>=` his full deposit while Carol's loss is amplified ~4x when Bob exits before the liquidation commits the write-down [4](#0-3) .

The reachable path is: an attacker supplies the dominant share of a debt market, a public price update makes an account insolvent (`set_price` in tests; on chain this is just observed oracle state), the attacker calls `withdraw` (their own position, own auth), then any third party's `liquidate`/`clean_bad_debt` commits the write-down onto the shrunken supplier base.

### Impact Explanation
Theft of user funds by redistribution. Insolvency is inevitable in lending; what the index timing bug changes is *who pays*. A supplier with fraction `f` of a market should absorb `f` of the write-down; by exiting first they absorb zero and push their share onto everyone else — measured at ~4x amplification for a 25% remaining supplier in the pinned test. On a large market with real bad debt this is a material, quantifiable loss transferred to passive suppliers, not a rounding artifact. It also worsens the index-floor shortfall: each pre-write-down exit removes claims *and* backing cash, leaving a smaller supplier base to absorb the capped `SUPPLY_INDEX_FLOOR_RAW` residual.

### Likelihood Explanation
Requires an insolvent account (common during sharp price moves — exactly when bad debt occurs) and a supplier large enough for the dodge to matter. No privilege is needed: `withdraw` is the attacker's own position. The window is however bounded — it closes as soon as any liquidator or `clean_bad_debt` caller commits the write-down — so it is a race the attacker must win (e.g., via transaction ordering around the liquidation). That is a Medium/High-likelihood race, not a guaranteed exploit, and note this behavior is pinned by an existing harness test, so reviewers may consider it a known design consequence rather than a defect; the loss-transfer asymmetry is nonetheless real and externally measurable.

### Recommendation
Make pending bad debt visible to exits, or make exits pay for it:
- In the withdraw gate, charge withdrawals against `backing_shortfall` (value unrecoverable debt at what the write-down would actually cost, not face value) so a supplier cannot exit whole while a known insolvency is pending.
- Alternatively, apply `apply_bad_debt_to_supply_index` eagerly inside `liquidate`/repay paths the moment a leg goes undercollateralized past the dust test, before collateral legs are settled, so the index reflects the loss before any further withdrawal can commit.
- At minimum, expose a permissionless `sync_bad_debt`/`update_indexes`-style entrypoint that materializes the write-down so keepers can close the window deterministically.

### Proof of Concept
The repository already contains the executable PoC. `tests/test-harness/tests/controller/bad_debt_index.rs::supplier_can_exit_ahead_of_bad_debt_writedown` runs two identical scenarios (Bob 75%, Carol 25% of ETH supply; Alice insolvent after a USDC price crash):

- Scenario A (no dodge): `liquidate(LIQUIDATOR, ALICE, "ETH", 0.001)`; Carol absorbs her pro-rata loss.
- Scenario B (dodge): `withdraw_all(BOB, "ETH")` *before* the same `liquidate` call; `bob_recovered >= bob_before_b` (Bob exits whole) and `carol_loss_b > 3 * carol_loss_a` (~4x concentration onto Carol).

Key assertions from the test [5](#0-4) :

```rust
b.withdraw_all(BOB, "ETH");                       // exits at pre-write-down index
b.liquidate(LIQUIDATOR, ALICE, "ETH", 0.001);     // write-down now hits only Carol
assert!(bob_recovered >= bob_before_b, "Bob exits whole");
assert!(carol_loss_b > carol_loss_a);
assert!(carol_loss_b / carol_loss_a > 3.0);       // ~4x amplification
```

No privileged call, no oracle manipulation, and no reentrancy is involved — only the ordering between a plain `withdraw` and the commit that materializes already-existing bad debt.

fn supplier_can_exit_ahead_of_bad_debt_writedown() {
    // Scenario A: nobody dodges. Bob 75%, Carol 25% of the ETH supply.
    let mut a = setup();
    a.supply(BOB, "ETH", 75.0);
    a.supply(CAROL, "ETH", 25.0);
    a.supply(ALICE, "USDC", 10.0);
    a.borrow(ALICE, "ETH", 0.003);

    let carol_before_a = a.supply_balance(CAROL, "ETH");
    a.set_price("USDC", usd_cents(10));
    a.liquidate(LIQUIDATOR, ALICE, "ETH", 0.001);
    let carol_loss_a = carol_before_a - a.supply_balance(CAROL, "ETH");

    // Scenario B: identical state, but Bob withdraws before the write-down.
    let mut b = setup();
    b.supply(BOB, "ETH", 75.0);
    b.supply(CAROL, "ETH", 25.0);
    b.supply(ALICE, "USDC", 10.0);
    b.borrow(ALICE, "ETH", 0.003);

    let carol_before_b = b.supply_balance(CAROL, "ETH");
    let bob_before_b = b.supply_balance(BOB, "ETH");
    let bob_wallet_before = b.token_balance(BOB, "ETH");

    // The crash is public state. Alice is insolvent from here on, but no
    // write-down has been applied yet.
    b.set_price("USDC", usd_cents(10));
    b.assert_liquidatable(ALICE);

    // Bob exits at the un-written-down index. No gate stops him: the
    // liquidation buffer only guards borrow draws, and `backing_shortfall`
    // still values Alice's uncollateralised debt at face.
    b.withdraw_all(BOB, "ETH");
    let bob_recovered = b.token_balance(BOB, "ETH") - bob_wallet_before;

    b.liquidate(LIQUIDATOR, ALICE, "ETH", 0.001);
    let carol_loss_b = carol_before_b - b.supply_balance(CAROL, "ETH");

    assert!(
        bob_recovered >= bob_before_b,
        "Bob exits whole: supplied={:.9} recovered={:.9}",
        bob_before_b,
        bob_recovered
    );
    assert!(
        carol_loss_b > carol_loss_a,
        "dodging must push loss onto Carol: A={:.9} B={:.9}",
        carol_loss_a,
        carol_loss_b
    );

    // Carol holds 25% of supply, so passing the whole loss to her is ~4x.
    let amplification = carol_loss_b / carol_loss_a;
    assert!(
        amplification > 3.0,
        "expected ~4x concentration onto the remaining supplier, got {:.3}x \
         (A={:.9} B={:.9})",
        amplification,
        carol_loss_a,
        carol_loss_b
    );

    std::println!(
        "A4-econ dodge: bob_supplied={:.9} bob_recovered={:.9} \
         carol_loss_passive={:.9} carol_loss_after_dodge={:.9} amplification={:.3}x",
        bob_before_b,
        bob_recovered,
        carol_loss_a,
        carol_loss_b,
        amplification
    );
}

pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
