## Analysis

There is a concrete, reachable analog in the chainlink web server: several routes that proxy to a LOOP (Local Out-Of-Process) plugin's internal `pprof`/metrics endpoints are registered **without any authentication middleware**, unlike sibling debug/session routes in the same router.

### Root cause

In `core/web/router.go`, `NewRouter` mounts `api` as the top-level route group with only rate-limiting and session middleware — no authentication is applied at that level: [1](#0-0) 

`debugRoutes` explicitly wraps its `/debug/vars` route with `auth.Authenticate(...)`: [2](#0-1) 

But `loopRoutes` — also called directly on the unauthenticated `api` group at line 91 — registers the plugin pprof/metrics proxy endpoints with **no** `auth.Authenticate` wrapper at all: [3](#0-2) 

The handler backing `/plugins/:name/debug/pprof/*profile` forwards the request (including query parameters like `debug`, `seconds`) straight to the plugin's internal `/debug/pprof/<profile>` endpoint, which includes `cmdline`, `heap`, `goroutine`, `profile`, `trace`, etc.: [4](#0-3) 

The sibling metrics proxy `/plugins/:name/metrics` is likewise unauthenticated: [5](#0-4) 

This mirrors the SpiceDB bug class: an internet/network-reachable HTTP endpoint exposes `pprof`'s `cmdline`/profiling data without requiring the caller to be authenticated, unlike the equivalent authenticated `/debug/vars` route in the same file.

### Caveat / what I could not fully verify

I could not confirm whether the separate `metricRoutes` function (which registers the *node's own* `/debug/pprof/*` handlers, including `pprof.Cmdline`) is actually wired into `NewRouter` — it is defined but I did not find a call site for it in the portion of `core/web/router.go` I was able to inspect: [6](#0-5) 
If `metricRoutes` is dead code (never invoked), it would not itself be exploitable; the confirmed, reachable issue is the `loopRoutes` plugin-proxy path described above, since `loopRoutes` is definitively called from `NewRouter` at line 91.

Also, unlike SpiceDB's `--grpc-preshared-key`, chainlink's node CLI takes secrets via file paths (`--password`, `--api`, `-s secrets.toml`) rather than raw secret values on the command line, so the direct "flag value leaked via cmdline" impact is reduced — the disclosed data would be plugin subprocess argv/env-derived invocation details, goroutine/heap dumps, and internal state, not necessarily the preshared key itself. I was unable to inspect how LOOP plugin subprocesses are invoked (e.g., whether any secrets are passed via `argv`) to confirm severity of the `cmdline` leak specifically.

### Title
Unauthenticated exposure of LOOP plugin pprof/metrics proxy endpoints - (File: core/web/router.go, core/web/loop_registry.go)

### Summary
The chainlink node's HTTP router mounts `/plugins/:name/debug/pprof/*profile`, `/plugins/:name/debug/pprof/symbol`, and `/plugins/:name/metrics` on the top-level `api` group without any authentication middleware, while the analogous `/debug/vars` route explicitly requires session authentication.

### Finding Description
`NewRouter` in `core/web/router.go` calls `loopRoutes(app, api)` on the same unauthenticated `api` group used for all other routes, but unlike `debugRoutes`/`sessionRoutes` it never wraps these paths in `auth.Authenticate`. The handlers `pluginPPROFHandler`, `pluginPPROFPOSTSymbolHandler`, and `pluginMetricHandler` in `core/web/loop_registry.go` proxy arbitrary unauthenticated requests to the internal `/debug/pprof/<profile>` and `/metrics` HTTP endpoints of any registered LOOP plugin, including `cmdline`, `heap`, `goroutine`, `profile` (CPU), and `trace`.

### Impact Explanation
An unauthenticated network client that can reach the node's web server can retrieve plugin process command-line invocation data, memory/goroutine/CPU profiles, and Prometheus metrics for any named LOOP plugin — the same class of information disclosure (CWE-209/debug info leak) as the SpiceDB advisory, reachable without any credentials.

### Likelihood Explanation
High for any deployment where the node's web API port is reachable by untrusted clients (the same threat model called out in the SpiceDB advisory for exposed metrics/debug ports), since no authentication check exists on this specific route group.

### Recommendation
Wrap `loopRoutes` (and ideally `metricRoutes`, if it is in fact reachable) with the same `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)` middleware used for `/debug/vars`, or bind these debug/metrics proxy routes to a separate, non-public listener as SpiceDB's fix/workaround recommends (`--metrics-addr=localhost:...`).

### Proof of Concept
Without any session cookie or API key, send: `GET /plugins/<plugin-name>/debug/pprof/cmdline` or `GET /plugins/<plugin-name>/metrics` to the node's web server; per [3](#0-2)  and [4](#0-3)  the request is proxied and returned without any authentication check.

func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/metrics", l.loopHostName, p.EnvCfg.PrometheusPort)
	req, err := http.NewRequestWithContext(gc.Request.Context(), http.MethodGet, pluginURL, nil)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)
	if err != nil {
		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q metrics", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
