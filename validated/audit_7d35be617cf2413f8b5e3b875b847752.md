## Title
Reserve-size-blind `totalSupply() == 0` fast path in `_seedUniswapV2Direct` lets a pre-`sync()` pre-seed open the graduated LP away from curve-close price - (File: `packages/contracts/src/Bonding.sol`)

### Summary
`Bonding.finalizeGraduation` seeds the HyperSwap V2 TOKEN/LT pair by routing on a single condition — `pair.totalSupply() == 0` — into an unconditional direct-mint fast path (`_seedDirectMint`), on the documented assumption that any pre-seed reaching that branch is "dust." That assumption is not enforced anywhere in the code, unlike the parallel size guard (`DIRECT_MINT_PRESEED_BPS`) that exists for the `totalSupply() > 0` rebalancing branch. An unprivileged address can inflate the pair's reserves to an arbitrary size via a plain `transfer` + `sync()` (which updates reserves without minting any LP supply), keeping `totalSupply() == 0`, and force the fast path to open the permanently-locked LP at an attacker-chosen price.

### Finding Description
`_seedUniswapV2Direct` first skims any raw-donation pre-seed, then branches purely on LP-token supply: [1](#0-0) 

Regime 1's natspec explicitly frames the `totalSupply() == 0` branch as covering "a pristine empty pair, **or a dust pre-seed** (`transfer(pair, dust) + sync()` leaves `reserves > 0` but `totalSupply == 0`)": [2](#0-1) 

Nothing in `_seedUniswapV2Direct` bounds how large that `transfer + sync()` pre-seed can be before falling into this branch — it only checks `totalSupply() == 0`. Contrast this with the sibling `totalSupply() > 0` branch, `_seedRebalancing`, which explicitly gates the equivalent direct-mint fallback behind a strict smallness check, `DIRECT_MINT_PRESEED_BPS = 1` bps of the LP target on both sides: [3](#0-2) 

No equivalent bound exists for Regime 1. `_seedDirectMint` simply transfers the phase-1-cached `(tokensForLP, ltFromPair)` into the pair on top of whatever the attacker already parked there, and calls the pair's standard V2 `mint`, which (with `totalSupply()==0`) derives LP supply from `sqrt(balance0*balance1)` and sets the new reserves to the full post-transfer balances — i.e. `(attackerToken + tokensForLP, attackerLT + ltFromPair)`: [4](#0-3) 

Because an attacker fully controls the pre-seeded ratio and can make it arbitrarily large relative to `tokensForLP`/`ltFromPair` (their `transfer` amounts are unconstrained; `sync()` is a permissionless call on the standard V2 pair), the pool's opening price after `finalizeGraduation` is dictated by the attacker's chosen ratio, not by `tokensForLP : ltFromPair` (the curve-close price the whole design is meant to preserve — see the "zero-gap" and price-equality invariants documented on `_prepareGraduationLiquidity`).

`finalizeGraduation` is permissionless and callable by anyone once phase 1 (`_enterGraduating`) has fired, so the attacker only needs to win the race to pre-seed+sync before calling (or letting a keeper call) `finalizeGraduation`: [5](#0-4) 

### Impact Explanation
The resulting LP is minted entirely to `LPLock` via `recordLock`, which has no rescue path — the mispriced position is permanent and cannot be corrected after the fact. Because the pool opens away from the curve-close price, anyone (including the attacker) can immediately arbitrage the newly graduated pair against its "true" price, extracting value from the locked LP — i.e. a concrete, permanent value transfer out of the protocol/creator-owned locked liquidity. This matches the explicitly in-scope impact "an LP seeded away from the curve close price," and satisfies the CVSS-relevant class of the source report: a fast path scoped for one narrow case ("ordinary"/dust) is silently reachable and abused from a different, adversarial case (large hostile pre-seed), bypassing the safeguard (`DIRECT_MINT_PRESEED_BPS`) that the sibling code path enforces for exactly this scenario.

### Likelihood Explanation
Every graduation is a target: the attacker only needs (a) to acquire TOKEN and LT before graduation (both freely tradable on the still-open curve/market), (b) call `IUniswapV2Factory.createPair`/locate the deterministic pair address (permissionless, `_ensureUniswapV2Pair` creates it lazily but an attacker can create it first), (c) `transfer` tokens to the pair and call the standard, permissionless `sync()`, and (d) either call `finalizeGraduation` itself or simply wait for the keeper to call it — nothing in the flow re-checks pre-seed size. This requires no privileged role, no governance action, and no protocol code beyond calls any wallet can submit.

### Recommendation
Apply the same smallness bound used in `_seedRebalancing` (`DIRECT_MINT_PRESEED_BPS`) to the `totalSupply() == 0` branch of `_seedUniswapV2Direct` before treating it as "dust": read the pair's live reserves (not just `totalSupply()`), and if they exceed the dust band relative to `tokensForLP`/`ltFromPair`, route through the rebalancing path (or an equivalent swap-to-target-ratio step) instead of `_seedDirectMint`, regardless of `totalSupply()`.

### Proof of Concept
1. Attacker observes a token nearing graduation and accumulates TOKEN (via curve buys) and LT (open market/BounceTech mint) in an arbitrarily skewed ratio.
2. Attacker locates/creates the deterministic HyperSwap V2 pair for `(token, lt)` via `IUniswapV2Factory.createPair` (permissionless) before phase 2 runs.
3. Attacker `transfer`s the skewed TOKEN/LT amounts directly to the pair, then calls the pair's standard `sync()` — this sets `reserve0`/`reserve1` to the transferred balances but mints no LP tokens, so `totalSupply() == 0` still holds.
4. Graduation phase 1 fires normally (`_enterGraduating`), caching `tokensForLP`/`ltFromPair` at curve-close price via `_prepareGraduationLiquidity`.
5. Anyone calls `Bonding.finalizeGraduation(tokenAddress)`. `_seedUniswapV2Direct` calls `pair.skim(address(this))` — a no-op since balances equal reserves post-`sync()` — then sees `totalSupply() == 0` and unconditionally calls `_seedDirectMint`.
6. `_seedDirectMint` transfers `tokensForLP`/`ltFromPair` into the pair and calls `pair.mint(lpLock)`. Because `totalSupply()==0`, V2 mint sets the pool's opening reserves to `(attackerToken + tokensForLP, attackerLT + ltFromPair)` — a ratio controlled by the attacker's pre-seed, not the curve-close price.
7. The LP is locked (permanent, no rescue) at the wrong price; the attacker immediately trades against the mispriced pool to extract value.

    function finalizeGraduation(
        address tokenAddress
    ) external nonReentrant {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[tokenAddress];
        if (info.lifecycle != Lifecycle.Graduating) revert NotGraduating();

        address lt = info.ltAddress;
        PendingGraduation memory p = $.pendingGraduation[tokenAddress];

        // Anything in this contract beyond `p.ltFromPair` belongs to a
        // concurrent graduation on the same LT (Phase 1 transferred it
        // via `Router.graduate`) or to stray dust. Either way it is
        // off-limits to this graduation's deposit and sweep — see
        // `_routerDepositAndDispose` and `_sweepLTToOwner`.
        // Saturating subtract: a balance below `p.ltFromPair` shouldn't
        // be reachable in normal operation, but we keep finalize from
        // bricking on a Panic if any future code path or non-canonical
        // LT briefly violates the invariant.
        uint256 ltBalance = IERC20(lt).balanceOf(address(this));
        uint256 protectedLT = ltBalance > p.ltFromPair ? ltBalance - p.ltFromPair : 0;

        address lpPair = _ensureUniswapV2Pair(tokenAddress, lt);
        uint256 liquidity = _seedUniswapV2Direct(tokenAddress, lt, lpPair, p.tokensForLP, p.ltFromPair, protectedLT);

        _sweepLTToOwner(lt, protectedLT);

        info.lifecycle = Lifecycle.Graduated;
        $.graduatedPair[tokenAddress] = lpPair;
        delete $.pendingGraduation[tokenAddress];

        LPLock($.lpLock).recordLock(tokenAddress, lpPair, liquidity);

        emit TokenGraduated(tokenAddress, lpPair, liquidity, p.tokensForLP, p.lpBurned, p.unsoldBurned);
    }

    function _seedDirectMint(
        address tokenAddress,
        address lt,
        address pair,
        uint256 tokensForLP,
        uint256 ltFromPair
    ) internal returns (uint256 liquidity) {
        IERC20(tokenAddress).safeTransfer(pair, tokensForLP);
        IERC20(lt).safeTransfer(pair, ltFromPair);
        liquidity = IUniswapV2Pair(pair).mint(_s().lpLock);
        uint256 leftoverToken = IERC20(tokenAddress).balanceOf(address(this));
        if (leftoverToken > 0) {
            Token(tokenAddress).burn(address(this), leftoverToken);
        }
    }
