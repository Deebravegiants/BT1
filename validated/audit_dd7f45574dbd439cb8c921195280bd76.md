### Title
Unauthenticated `/v2/resume/:runID` endpoint allows resuming and injecting attacker-controlled results into any pipeline run - ([File: core/web/pipeline_runs_controller.go])

### Summary
The `PipelineRunsController.Resume` HTTP handler accepts a task UUID and an arbitrary JSON result body and calls `App.ResumeJobV2` to inject that result into the corresponding suspended pipeline run — with no authentication check on the caller and no verification that the caller is the async adapter that originally suspended that specific run.

### Finding Description
`Resume` parses `runID` (a task UUID) straight from the URL and a JSON body into a `pipeline.ResumeRequest`, then calls `prc.App.ResumeJobV2(ctx, taskID, result)` without checking `auth.GetAuthenticatedUser` or `auth.GetAuthenticatedExternalInitiator`, unlike `Create` in the same file, which explicitly checks `isUser`/`isEI` before running a job: [1](#0-0) 

`ResumeJobV2` forwards directly into the pipeline runner: [2](#0-1) 

`ResumeRun` looks the run up purely by `taskID`, writes the caller-supplied `value`/`error` into `pipeline_task_runs`, flips the run to `running`, and re-executes the pipeline (potentially reaching downstream tasks such as `ETHTxTask`, which can push on-chain transactions): [3](#0-2) [4](#0-3) 

The handler even records the action under an audit event named `UnauthedRunResumed`, confirming the endpoint is intentionally reachable without a session: [5](#0-4) 

The only "authorization" for this action is possession of the task's UUID. This is the same bug-class as the reported `BalancedVault.claim`: a state-changing action that lets an unprivileged caller act on a resource ("account"/"run") they don't own, supplying data (claim amount / task result) that influences the resource's final outcome, with no ownership or role check gating the call — only the UUID plays the role that `account` plays in `claim`.

### Impact Explanation
If a task UUID is ever exposed (e.g. via logs, a bridge adapter that leaks it, race conditions, or a misconfigured external adapter response), any unauthenticated actor can:
- Overwrite the pending task's result with attacker-chosen data (`value`/`error`), and
- Force the pipeline to resume/execute downstream tasks (including `ETHTxTask`, which submits on-chain transactions) using that forged data.

This can corrupt job outcomes, cause incorrect data to be reported on-chain, or trigger unwanted transactions, all without the caller ever authenticating.

### Likelihood Explanation
Likelihood is **not** as high as the vault issue because it additionally requires the attacker to know a specific pending task UUID (not merely a public account address). This significantly narrows exploitability to scenarios where the UUID is guessable, logged, or leaked by a misbehaving/compromised external adapter. Nonetheless, the endpoint has zero authentication or ownership check by design (as documented by the `UnauthedRunResumed` audit label), so the entire security of the action rests on UUID secrecy rather than any access control, which is a fragile trust boundary comparable in spirit to the `claim` issue's lack of caller restriction.

### Recommendation
- Bind resume requests to the specific bridge/adapter that created the pending task (e.g. via a per-task secret/token embedded in the callback URL, HMAC-signed callback, or requiring the external initiator/bridge credentials used to originate the async task).
- At minimum, validate that the resuming request matches metadata recorded when the task was suspended (originating bridge name/URL) before accepting the result.
- Rate-limit and audit-log resume attempts with mismatched or unknown task IDs to detect scanning/brute-force attempts against the UUID space.

### Proof of Concept
1. Obtain (or brute force from logs, error messages, or a compromised/malicious "async" bridge target) the UUID of a pending `pipeline_task_runs.id` for a suspended run (e.g. from a `bridge async=true` task waiting on `/v2/resume/<taskID>`).
2. Without any Chainlink session cookie or API token, send:
   ```
   PATCH /v2/resume/<taskID>
   Content-Type: application/json

   {"data": {"result": "<attacker-controlled value>"}}
   ```
   as shown by the unauthenticated request path in `PipelineRunsController.Resume`.
3. The pipeline runner accepts this as the legitimate adapter response, marks the task finished with the attacker's value, and resumes the run, potentially causing a downstream `ETHTxTask` to submit a transaction based on forged data — confirmed by the code path `Resume` → `App.ResumeJobV2` → `runner.ResumeRun` → `orm.UpdateTaskRunResult` shown above, with no auth check anywhere in that chain.

// Resume finishes a task and resumes the pipeline run.
// Example:
// "PATCH <application>/jobs/:ID/runs/:runID"
func (prc *PipelineRunsController) Resume(c *gin.Context) {
	taskID, err := uuid.Parse(c.Param("runID"))
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	rr := pipeline.ResumeRequest{}
	decoder := json.NewDecoder(c.Request.Body)
	err = errors.Wrap(decoder.Decode(&rr), "failed to unmarshal JSON body")
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	result, err := rr.ToResult()
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	if err := prc.App.ResumeJobV2(c.Request.Context(), taskID, result); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
	c.Status(http.StatusOK)
}

func (r *runner) ResumeRun(ctx context.Context, taskID uuid.UUID, value any, err error) error {
	run, start, err := r.orm.UpdateTaskRunResult(ctx, taskID, Result{
		Value: value,
		Error: err,
	})
	if err != nil {
		return fmt.Errorf("failed to update task run result: %w", err)
	}

	// TODO: Should probably replace this with a listener to update events
	// which allows to pass in a transactionalised database to this function
	if start {
		// start the runner again
		go func() {
			ctx, cancel := r.chStop.NewCtx()
			defer cancel()
			if _, err := r.Run(ctx, &run, false, nil); err != nil {
				r.lggr.Errorw("Resume run failure", "err", err)
			}
			r.lggr.Debug("Resume run success")
		}()
	}
	return nil
}

func (o *orm) UpdateTaskRunResult(ctx context.Context, taskID uuid.UUID, result Result) (run Run, start bool, err error) {
	if result.OutputDB().Valid && result.ErrorDB().Valid {
		panic("run result must specify either output or error, not both")
	}
	err = o.transact(ctx, func(tx *orm) error {
		sql := `
		SELECT pipeline_runs.*, pipeline_specs.dot_dag_source "pipeline_spec.dot_dag_source", job_pipeline_specs.job_id "job_id"
		FROM pipeline_runs
		JOIN pipeline_task_runs ON (pipeline_task_runs.pipeline_run_id = pipeline_runs.id)
		JOIN pipeline_specs ON (pipeline_specs.id = pipeline_runs.pipeline_spec_id)
		JOIN job_pipeline_specs ON (job_pipeline_specs.pipeline_spec_id = pipeline_specs.id)
		WHERE pipeline_task_runs.id = $1 AND pipeline_runs.state in ('running', 'suspended')
		FOR UPDATE`
		if err = tx.ds.GetContext(ctx, &run, sql, taskID); err != nil {
			return fmt.Errorf("failed to find pipeline run for task ID %s: %w", taskID.String(), err)
		}

		// Update the task with result
		sql = `UPDATE pipeline_task_runs SET output = $2, error = $3, finished_at = $4 WHERE id = $1`
		if _, err = tx.ds.ExecContext(ctx, sql, taskID, result.OutputDB(), result.ErrorDB(), time.Now()); err != nil {
			return fmt.Errorf("failed to update pipeline task run: %w", err)
		}

		if run.State == RunStatusSuspended {
			start = true
			run.State = RunStatusRunning

			sql = `UPDATE pipeline_runs SET state = $2 WHERE id = $1`
			if _, err = tx.ds.ExecContext(ctx, sql, run.ID, run.State); err != nil {
				return fmt.Errorf("failed to update pipeline run state: %w", err)
			}
		}

		return loadAssociations(ctx, tx.ds, []*Run{&run})
	})

	return run, start, err
}
