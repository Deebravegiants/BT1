### Title
Unprivileged value-overflow panic in accrual permanently freezes an entire market (no repay, withdraw, or liquidation) - (File: common/src/rates/scaling.rs)

### Summary
Every mutating pool entrypoint and every controller verb on a market runs `interest::global_sync` → `accrue_step` first, which unscales `borrowed` by `borrow_index` via `scaled_to_original` (`Ray::mul`). That multiplication panics with `MathOverflow` once `borrowed * borrow_index / RAY` leaves `i128`. The borrow index cap (`MAX_BORROW_INDEX_RAY = 10^36`) is applied to the index, not to the scaled debt value, so on a large book the value product overflows before the index cap can stop accrual. Once a single accrual panics, every subsequent call on that market panics at the same point — permanently. There is no recovery path, since repayment, withdrawal, liquidation, bad-debt cleanup, and recapitalization all accrue first. This mirrors the CVE's "repeatable crash → complete DoS plus unauthorized data modification" class: an unprivileged attacker can grow a market book toward the cliff and then trip it with the permissionless `update_indexes`, permanently freezing all suppliers' funds in that market.

### Finding Description
- `contracts/pool/src/interest.rs::global_sync` accrues on every mutation; `accrue_chunk` calls `accrue_step`, which computes `scaled_to_original(borrowed, new_borrow_index)` to derive interest. [1](#0-0) 
- `common/src/rates/scaling.rs::scaled_to_original` is `scaled.mul(env, index)`; `Ray::mul` is checked and panics on i128 overflow (`GenericError::MathOverflow`). [2](#0-1) 
- The only ceiling is on the index itself (`borrow_index' = min(..., 10^36)`), so `borrowed` (scaled shares) times index can exceed `i128::MAX` while the index is still far below the cap. [3](#0-2) 
- The protocol's own regression test demonstrates the end state: "the next accrual panics inside `scaled_to_original`. Every verb accrues first, so the market freezes: no repay, no withdraw, no liquidation. The index cap never engages," with `try_withdraw_raw` and `try_repay` both failing with `MATH_OVERFLOW` and `borrow_index < MAX_BORROW_INDEX_RAY`. [4](#0-3) 
- Reachability for an unprivileged caller: `controller::update_indexes` (and any supply/borrow/withdraw/repay/liquidate/clean_bad_debt) triggers `global_sync`; an attacker can deliberately construct the state by supplying a very large amount of an 18-decimal asset and borrowing near max utilization (both permissionless with lifted/large caps), then waiting for accrual to push `borrowed * borrow_index` past `i128::MAX`.

### Impact Explanation
Permanent freezing of funds for every supplier and borrower in the affected market: repay, withdraw, liquidate, clean_bad_debt, and recapitalize all accrue first and all revert, so pool cash and lent principal are locked forever. The attacker's own capital is burned too, but the freeze captures all other users' deposits in that market — griefing-style permanent DoS matching the CVE's "complete DOS" impact, plus integrity loss since no account state can ever be updated again in that market.

### Likelihood Explanation
Real but capital-intensive. The cliff requires a book on the order of ~10^35–10^36 raw RAY value (≈170 billion whole tokens at 18 decimals) sustained at high utilization until the index grows past ~170×. On realistic deployed markets with supply caps and `max_utilization` enforcement this is hard; however caps are governance-settable, `max_utilization` can equal `RAY` (uncapped), and 18-decimal listings are admitted — the docs acknowledge "valid caps and bounded indexes do not guarantee that future accrual fits." Any caller can trip the panic once the boundary is near via a zero-cost `update_indexes`. Medium severity is consistent: high preconditions, unbounded impact when met.

### Recommendation
Bound the accrual math by value, not just by index. Options: (a) in `accrue_step`/`update_borrow_index`, saturate `borrow_index` at `min(MAX_BORROW_INDEX_RAY, i128::MAX * RAY / borrowed)` so `scaled_to_original` can never overflow — accrual harmlessly stops producing interest at the effective cap instead of trapping; (b) make `scaled_to_original` saturate for the accrual path (interest derivation can use a saturating multiply while position accounting keeps panicking); (c) enforce a market supply cap in value terms (`supplied * supply_index`) at entry so `borrowed` can never approach `i128::MAX / borrow_index`. Option (a) is the minimal fix: it preserves the documented "no interest at cap" semantics and keeps the market operable.

### Proof of Concept
Conceptual reproduction (mirrors the existing test):
1. Market created with an 18-decimal asset, XLM-style steep rate curve, caps lifted, `max_utilization = RAY`.
2. Attacker calls `supply` with `10^9 * 10^18` base units (~`1e36` raw RAY), then `borrow` ~98% of it using separate collateral.
3. Time advances; each `update_indexes` compounds `borrow_index` (up to `e^2` per 1-year chunk at `MAX_BORROW_RATE_RAY`).
4. Once `borrowed_scaled * borrow_index / RAY > i128::MAX`, the next permissionless `update_indexes` (or any verb) panics in `scaled_to_original` with `MathOverflow`.
5. Thereafter `withdraw`, `repay`, `liquidate`, and `clean_bad_debt` on that market all revert at the same accrual step — permanently, since nothing can reduce `borrowed` or roll back `borrow_index` without accruing first.

Confirmed shape by `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` (test file above), which asserts exactly this freeze with `MATH_OVERFLOW` on withdraw and repay and the index cap never engaging.

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}
```

```rust
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
