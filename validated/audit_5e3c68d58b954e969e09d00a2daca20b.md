## Title
Overly Permissive CORS Wildcard-Origin Matching via Improper Domain-Suffix Check - ([File: core/services/gateway/network/httpserver.go])

## Summary
The Gateway's `isAllowedOrigin` function in `core/services/gateway/network/httpserver.go` validates wildcard CORS entries (e.g. `*.ethereum.org`) using a raw `strings.HasSuffix` check with no `.` boundary enforcement. This allows an attacker-controlled origin such as `evil-ethereum.org` to be treated as a valid subdomain of an allowed origin `ethereum.org`, bypassing the intended allowlist restriction.

## Finding Description
In `isAllowedOrigin`, when an allowed entry starts with `*.`, the code strips the prefix and does: [1](#0-0)  This performs a plain suffix comparison (`strings.HasSuffix(originHost, allowedHost)`) without verifying that the character preceding the match is a `.`. Consequently, any origin host that merely ends with the allowed string — not just true subdomains — satisfies the check. For example, with an allowed entry `*.ethereum.org` (stripped to `ethereum.org`), the origin host `evil-ethereum.org` also ends with `ethereum.org` and is incorrectly accepted.

This function is invoked for every incoming request in `handleRequest`, which reflects the request's `Origin` header value directly into the `Access-Control-Allow-Origin` response header when `isAllowedOrigin` returns true: [2](#0-1)  No other validation, dot-boundary check, or allowlist normalization exists elsewhere in the codebase to compensate for this gap. The wildcard feature itself is a documented, supported configuration pattern, confirmed by sample configs and existing tests exercising exactly this wildcard path.

## Impact Explanation
This is a genuine CORS allowlist bypass (cross-origin request impersonation category). If an operator configures any wildcard `CORSAllowedOrigins` entry, an attacker who registers a lookalike domain sharing the same suffix (without an intervening dot) can have their origin reflected in `Access-Control-Allow-Origin`, allowing their web page to make authenticated/credentialed cross-origin requests to the gateway and read JSON-RPC responses intended only for the legitimate whitelisted domain.

## Likelihood Explanation
Exploitation requires only that the operator use a wildcard entry in `CORSAllowedOrigins` (an intended, supported feature, not a misconfiguration outside spec) and that the attacker register a cheaply obtainable domain sharing the suffix (e.g., `evil-ethereum.org` for `*.ethereum.org`). No additional privilege, credentials, or host access is needed beyond a normal browser request with a crafted `Origin` header, which is fully within reach of an unprivileged client/attacker-controlled webpage.

## Recommendation
Enforce a `.` boundary in the wildcard match:
```go
if strings.HasPrefix(allowedHost, "*.") {
    allowedHost = allowedHost[2:]
    if originHost == allowedHost || strings.HasSuffix(originHost, "."+allowedHost) {
        return true
    }
}
```

## Proof of Concept
1. Configure the gateway with `CORSEnabled = true` and `CORSAllowedOrigins = ["https://*.ethereum.org"]`.
2. Send an HTTP POST to the gateway's user endpoint with header `Origin: https://evil-ethereum.org`.
3. Observe `isAllowedOrigin` returns `true` (since `strings.HasSuffix("evil-ethereum.org", "ethereum.org")` is `true`), and the response includes `Access-Control-Allow-Origin: https://evil-ethereum.org`, as implemented in `handleRequest`: [3](#0-2) 
4. A page hosted at `https://evil-ethereum.org` can then issue cross-origin `fetch`/XHR requests to the gateway and read responses, since the browser permits it based on the reflected `Access-Control-Allow-Origin` header. This can be codified as a Go unit test analogous to the existing `TestHTTPServer_HandleRequest_CORSEnabled_FromAllowedOriginWildcards` in `core/services/gateway/network/httpserver_test.go`, but asserting that `evil-ethereum.org` is incorrectly accepted for an allowed entry `*.ethereum.org`.

func (s *httpServer) isAllowedOrigin(origin string) bool {
	originScheme, originHost, originPort, err := s.splitURL(origin)
	if err != nil {
		s.lggr.Debug("error parsing origin URL", err)
		return false
	}
	for _, allowed := range s.config.CORSAllowedOrigins {
		// probably better to do this once when server starts and store it in a map
		// this is an easier solution so we don't have to apply more changes to the code
		// just need to be careful when specifying allowed origins in the config file
		allowedScheme, allowedHost, allowedPort, err := s.splitURL(allowed)
		if err != nil {
			s.lggr.Debug("error parsing allowed origin URL", err)
			continue
		}
		// skip if the scheme doesn't match at all
		if originScheme != allowedScheme {
			continue
		}
		// skip if the port doesn't match at all
		if originPort != allowedPort {
			continue
		}
		// check for exact host match (e.g., remix.com)
		if originHost == allowedHost {
			return true
		}
		// check for wildcard host match (e.g., *.remix.com)
		if strings.HasPrefix(allowedHost, "*.") {
			allowedHost = allowedHost[2:]
			if strings.HasSuffix(originHost, allowedHost) {
				return true
			}
		}
	}
	return false
}
