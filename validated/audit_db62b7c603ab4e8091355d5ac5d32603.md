### Title
Permissionless `CallDispatcher.dispatch()` Combined with an Unrestricted `receive()` Lets Any Address Drain Residual Native ETH Left Behind by Intent Fills - (File: `evm/src/utils/CallDispatcher.sol`)

### Summary
`CallDispatcher` is a shared, singleton, access‑control‑free contract used by `IntentGatewayV2`/`IntentsBase` to execute solver‑supplied output calldata during order fills. It exposes an unrestricted `receive()` and an unrestricted `dispatch()` function with no owner, no rescue/withdraw mechanism, and no restriction on who may invoke it or where its held native balance may be forwarded to.

### Finding Description
`CallDispatcher` accepts arbitrary ETH via a bare `receive()` and forwards its own balance to arbitrary targets via `dispatch()`, which anyone can call: [1](#0-0) 

`IntentsBase._execute` uses this dispatcher to run solver‑provided `order.output.call` calldata, and then attempts to sweep back only the token/native balances that are explicitly declared in `order.output.assets`: [2](#0-1) 

If a fill's `output.call` leaves native ETH on the `CallDispatcher` that is not accounted for in `order.output.assets` (e.g. the solver's calldata sends/leaves ETH on the dispatcher for a token/leg the order didn't declare, or the swept amount doesn't match the true balance at settlement time due to interleaving with another order's fill in the same block), that ETH is never returned to the `IntentGatewayV2` contract's own dust accounting and remains parked on `CallDispatcher`. Because `dispatch()` has no access control and simply does `to.call{value: call.value}(data)` funded from `address(this).balance`, any unrelated third party can subsequently call `CallDispatcher.dispatch()` directly with a `Call{to: attacker, value: <residualBalance>, data: ""}` and steal that stranded ETH. There is no owner-only sweep/rescue function on `CallDispatcher` itself — the only balance recovery ever built is the order‑scoped sweep in `_execute`, which is incomplete by construction (it only sweeps tokens present in the specific order's declared output asset list).

This mirrors the reported bug class exactly: a contract with a payable `receive()` and no withdrawal mechanism, except here the impact is compounded because the dispatcher is a shared multi-tenant contract reachable from many independent order fills, and the missing "withdraw" access control converts stranded funds into an outright race for theft by any unprivileged address, rather than merely a freeze.

### Impact Explanation
Any native ETH accidentally or transiently left on `CallDispatcher` — arising from normal intent‑fill flows that route solver calldata through it — is not recoverable by governance/the protocol and is instead freely claimable by any address able to front-run a call to `dispatch()`. This is a direct loss-of-funds vector: value that should have flowed back to `IntentGatewayV2` as protocol dust (and ultimately been swept to a beneficiary via `_sweepDust`) can be permanently diverted to an arbitrary unprivileged caller. This satisfies the "concrete theft of funds" bar since the loss is realizable by a plain unprivileged transaction against a production, reachable contract in the intents fill path.

### Likelihood Explanation
`CallDispatcher` is invoked on every fill that carries `order.output.call` (composable/DeFi-routed fills), a documented and expected usage pattern for solvers. Any mismatch between what the solver's calldata does with native value and what the order's `output.assets` declares — plausible given solvers/output calldata are attacker/solver-controlled and not validated against actual dispatcher balance — leaves ETH parked on the shared dispatcher. Because `dispatch()` is unauthenticated, exploitation requires nothing more than monitoring the dispatcher's balance and submitting a single transaction; no privileged role, governance compromise, or complex race condition is needed.

### Recommendation
- Add access control to `CallDispatcher.dispatch()` so only an authorized caller (e.g., the `IntentGatewayV2`/`IntentsBase` contract(s) that own a given execution, or an explicit allowlist of gateway addresses) may invoke it, preventing arbitrary third parties from redirecting its balance.
- Alternatively/additionally, make the dispatcher balance non-persistent by design: sweep the *entire* residual native and any token balance unconditionally back to the caller/gateway at the end of every `dispatch()` invocation, instead of only sweeping tokens explicitly enumerated in `order.output.assets`.
- Add an owner/governance-gated rescue function on `CallDispatcher` to recover any stray balance, consistent with the mitigation pattern recommended in the referenced report (either remove the unrestricted `receive()`/broaden dispatch to disallow leftover balances, or add an explicit withdrawal path).

### Proof of Concept
1. A solver fills an order via `IntentGatewayV2`/`ExtrinsicIntents` or `IntrinsicIntents` with `order.output.call` set to calldata that, when executed by `CallDispatcher.dispatch(order.output.call)` in `IntentsBase._execute` (line 502), leaves native ETH on the dispatcher for a token/leg not listed in `order.output.assets` (or in an amount not captured by the strict per-asset sweep loop at lines 507–533).
2. `_execute`'s sweep step only issues a `Call{to: address(this), value: balance, ...}` for `address(0)` when `order.output.assets` includes a zero-address entry; ETH outside that path is left in `CallDispatcher.balance`.
3. Any external account then calls `CallDispatcher.dispatch(abi.encode([Call({to: attacker, value: strandedBalance, data: ""})]))` directly (`evm/src/utils/CallDispatcher.sol` lines 44–62) — this call is unauthenticated, so it succeeds and transfers the stranded ETH to the attacker.
4. Neither `IntentGatewayV2` nor `CallDispatcher` has any mechanism to recover or reclaim this ETH once it is stolen, and `CallDispatcher` has no owner/withdraw function to have preemptively swept it to safety.

    /**
     *  @dev reverts if the target is not a contract or if any of the calls reverts.
     */
    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }

    function _execute(Order calldata order, uint256 outputsLen) internal {
        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            } else {
                uint256 balance = IERC20(token).balanceOf(dispatcher);
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            }

            unchecked {
                ++i;
            }
        }

        if (sweepCount > 0) {
            Call[] memory finalCalls = new Call[](sweepCount);
            for (uint256 i; i < sweepCount;) {
                finalCalls[i] = sweepCalls[i];
                unchecked {
                    ++i;
                }
            }
            ICallDispatcher(dispatcher).dispatch(abi.encode(finalCalls));
        }
    }
