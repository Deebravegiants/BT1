### Title
Missing contract-existence check in `EvmHost.dispatchIncoming(GetResponse)` and `dispatchTimeOut` lets low-level calls to non-existent/self-destructed destinations be treated as delivered - ([File: evm/src/core/EvmHost.sol])

### Summary
`EvmHost.dispatchIncoming(PostRequest, ...)` explicitly guards against calling a destination with no code by checking `extcodesize` before invoking `onAccept`, and returns early (leaving the request retryable) when the destination has no code. [1](#0-0)  The three sibling delivery paths — `dispatchIncoming(GetResponse, ...)`, `dispatchTimeOut(GetRequestTimeout, ...)`, and `dispatchTimeOut(PostRequestTimeout, ...)` — perform the exact same style of raw low-level `.call()` to an address decoded from request bytes, but with **no** existence check at all. [2](#0-1) 

### Finding Description
Per Solidity's own documented EVM semantics (the same warning cited in the external report), a low-level `call` to an address with no code always returns `success == true` without executing any logic. `EvmHost` clearly acknowledges this risk — it added an `extcodesize` guard specifically for `dispatchIncoming(PostRequest, ...)`:

```solidity
address destination = _bytesToAddress(request.to);
uint256 size;
assembly { size := extcodesize(destination) }
if (size == 0) {
    // instead of reverting the entire batch, early return here.
    return;
}
``` [3](#0-2) 

However, the analogous callback dispatch functions omit this check entirely:

- `dispatchIncoming(GetResponse memory response, address relayer)` calls `_bytesToAddress(response.request.from).call(...)` directly, with no code-existence check, then unconditionally treats the trivially-successful call as a completed delivery — storing the response receipt, paying the relayer fee, and emitting `GetRequestHandled`. [4](#0-3) 
- `dispatchTimeOut(GetRequestTimeout, ...)` deletes the request commitment (replay protection) up front, calls `_bytesToAddress(timeout.request.from).call(...)` with no existence check, and on a trivial "success" refunds the relayer fee and emits `GetRequestTimeoutHandled` — with no way to ever retry, since the commitment record was already deleted. [5](#0-4) 
- `dispatchTimeOut(PostRequestTimeout, ...)` follows the identical pattern for `onPostRequestTimeout`. [6](#0-5) 

In every one of these three paths, the destination (`request.from`) is an address supplied by the *original request initiator* at dispatch time — `_msgSender()` of the account that called `dispatch(DispatchPost)`/`dispatch(DispatchGet)` on the source chain. [7](#0-6) [8](#0-7)  If that contract self-destructs (or was never actually deployed with code by the time the response/timeout is relayed), the raw `.call()` in these three functions silently "succeeds" without executing `onGetResponse`/`onGetTimeout`/`onPostRequestTimeout`. Because the code treats the trivial success identically to a real, executed callback, it:
1. permanently deletes replay-protection state (commitment/receipt) so the message can never be redelivered even once the situation is corrected, and
2. pays out the relayer fee / fee refund as if the application logic actually ran.

This is a direct analog of the reported DSExec/DSProxy issue: a low-level call to a non-existent-code address is indistinguishable from a real successful call, and the calling contract (`EvmHost`) relies on that boolean without checking `extcodesize`, unlike its own sibling function `dispatchIncoming(PostRequest, ...)` which does perform this check.

### Impact Explanation
Any application relying on `onGetResponse`/`onGetTimeout`/`onPostRequestTimeout` to release escrowed funds, finalize a fill, or otherwise act on cross-chain state (e.g. an intents/token-bridge app) can have that message marked as permanently and irreversibly delivered/refunded without its callback logic ever executing, if the destination app has no code at delivery time. Since the commitment/receipt state is deleted unconditionally on the trivial "success" path, there is no mechanism to retry delivery once the condition is noticed — this is a form of permanent freezing/loss of the funds or state transition that depended on that callback executing. This is qualitatively different from the guarded `dispatchIncoming(PostRequest, ...)` path, which deliberately returns early (rather than deleting/consuming state) specifically to keep such a message retryable.

### Likelihood Explanation
Exploitability depends on the destination `from`/`to` address having no code at the moment a relayer submits the response/timeout proof — for example a self-destructing or not-yet-initialized contract, matching the exact "Exploit Scenario" described in the external report. This requires either an app-level self-destruct path or a timing race where a contract account address is targeted before deployment; both are realistic conditions the audited report explicitly calls out as its core scenario, and Hyperbridge's own code demonstrates awareness of the exact risk (via the guard present only in one of the four sibling functions).

### Recommendation
Add the same `extcodesize` existence check used in `dispatchIncoming(PostRequest, ...)` to `dispatchIncoming(GetResponse, ...)`, `dispatchTimeOut(GetRequestTimeout, ...)`, and `dispatchTimeOut(PostRequestTimeout, ...)` before performing the low-level `.call()`, and on a zero-size destination, return early leaving replay-protection state intact so the message remains retryable, exactly as is already done for incoming POST requests.

### Proof of Concept
1. On the source chain, an EOA-controlled or later-self-destructible contract `C` calls `EvmHost.dispatch(DispatchGet)` (or `dispatch(DispatchPost)`), setting `request.from = address(C)`. [8](#0-7) 
2. `C` self-destructs (or is destroyed by some other mechanism) before the response/timeout is relayed.
3. A relayer later relays the GET response (or timeout) via `HandlerV2.handleGetResponses`/`handlePostRequestTimeouts`, which calls `host.dispatchIncoming(response, relayer)` / `host.dispatchTimeOut(timeout, meta, commitment)`. [9](#0-8) 
4. Inside `EvmHost`, `_bytesToAddress(...).call(...)` targets the now-empty address `C`, trivially returns `success == true`, and the function proceeds to delete the commitment/receipt and pay out the fee/refund, as if `C.onGetResponse`/`onGetTimeout`/`onPostRequestTimeout` actually executed — even though no code ran. [2](#0-1)

    function dispatchIncoming(PostRequest memory request, address relayer) external restrict(_hostParams.handler) {
        address destination = _bytesToAddress(request.to);
        uint256 size;
        assembly {
            size := extcodesize(destination)
        }
        if (size == 0) {
            // instead of reverting the entire batch, early return here.
            return;
        }

        // replay protection
        bytes32 commitment = request.hash();
        _requestReceipts[commitment] = relayer;

        (bool success,) = address(destination)
            .call(abi.encodeWithSelector(IApp.onAccept.selector, IncomingPostRequest(request, relayer)));

        if (!success) {
            // so that it can be retried
            delete _requestReceipts[commitment];
            return;
        }
        emit PostRequestHandled({commitment: commitment, relayer: relayer});
    }

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

        uint256 timestamp = block.timestamp;

        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        uint256 responsesLength = message.responses.length;
        MerkleMountainRange.Leaf[] memory leaves = new MerkleMountainRange.Leaf[](responsesLength);

        for (uint256 i = 0; i < responsesLength; ++i) {
            GetResponseLeaf memory leaf = message.responses[i];
            // don't check for timeouts because it's checked on Hyperbridge

            // known request? also serves as source check
            FeeMetadata memory meta = host.requestCommitments(leaf.response.request.hash());
            if (meta.sender == address(0)) revert UnknownMessage();
            leaves[i] = MerkleMountainRange.Leaf(leaf.index, leaf.response.hash());
        }

        bytes32 root = host.stateMachineCommitment(message.proof.height).overlayRoot;
        if (root == bytes32(0)) revert StateCommitmentNotFound();
