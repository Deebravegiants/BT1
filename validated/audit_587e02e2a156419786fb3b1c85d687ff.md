### Title
Missing per-session freshness/challenge binding in `handle_rgb_net` allows replayed recordings to be accepted as live biometric capture - (File: src/plans/biometric_capture/mod.rs)

### Summary
`Plan::handle_rgb_net` in `src/plans/biometric_capture/mod.rs` accepts any RGB-Net estimate/frame pair that passes a static geometric check (`bbox.coordinates.is_correct()`) and stores it as the capture candidate, with no verification that the presented face is responding to an unpredictable, session-specific stimulus. A pre-recorded video or screen playback of a face, if it satisfies the bounding-box sanity check, is indistinguishable from a live subject to this handler.

### Finding Description
`handle_rgb_net` only checks that an `rgb_net::Output::Estimate`'s primary prediction has a valid bounding box before storing the frame into `left_rgb`/`right_rgb`: [1](#0-0) 

Similarly, `handle_ir_net` gates acceptance purely on iris sharpness score, perceived side, brightness range, and a cooldown timer (`valid_capture_after`), none of which are unpredictable per-session stimuli: [2](#0-1) 

Across the entire `biometric_capture` module and its extensions (`focus_sweep.rs`, `mirror_sweep.rs`, `multi_wavelength.rs`, `overcapture.rs`, `pupil_contraction.rs`), all of these simply proxy to the same `biometric_capture::Plan::handle_rgb_net`/`handle_ir_net`, and none introduce a random/unpredictable challenge that the capture must respond to before a frame is accepted. A search across the repository for liveness/anti-spoofing/challenge/nonce constructs (`liveness`, `anti-spoof`, `challenge`, `nonce`) returns no matches outside of `RESEARCHER.md` documentation — there is no code enforcing such a check.

The `pupil_contraction` extension does drive a light stimulus (ramping LED brightness) and could, in principle, serve as a liveness signal, but it is an optional `SignupExtensionConfig` mode, not the default/basic path, and even there `handle_rgb_net` (line 120-127) still just forwards to the same unconditional slot-filling logic without validating that the observed frame actually reflects a pupil response tied to that specific stimulus instance.

### Impact Explanation
Because no code path binds capture acceptance to a per-session unpredictable stimulus, an attacker who can present a recorded sequence (screen playback or recorded IR/RGB video timed to satisfy face-detection, bounding box, brightness, and sharpness heuristics) can have `handle_rgb_net`/`handle_ir_net` treat it as a legitimate live capture. This maps to "signup completed using another person's recorded biometrics" — enabling unauthorized enrollment/signup binding to a victim's biometric identity without the victim's live presence.

### Likelihood Explanation
Feasibility depends on defeating the existing heuristic gates (bounding box correctness, iris sharpness ≥ `IRIS_SCORE_MIN`, brightness range, occlusion filter, face-identifier validity score) purely through image/video quality — these are static image-quality checks, not liveness checks, and are plausibly satisfiable by a good-quality recording or a properly lit screen replay. This does not require any hardware tampering, operator access, or secrets — only presenting a recording to the sensors during the capture window, consistent with the "unprivileged attacker" threat model. The attack is repeatable for any recorded footage that meets image-quality thresholds.

### Recommendation
Introduce a per-session, unpredictable liveness challenge (e.g., randomized light pattern/timing, randomized gaze/movement prompts with response verification, or challenge-response using variable illumination sequences) and enforce that `handle_rgb_net`/`handle_ir_net` (and the corresponding IR-Net path) validate the captured frames against the expected response to that specific challenge before accepting a frame into `left_rgb`/`right_rgb`/`left_ir`/`right_ir`. Reject captures that don't exhibit the expected freshness/response signal.

### Proof of Concept
Integration test outline for `src/plans/biometric_capture/mod.rs`:
1. Construct a `biometric_capture::Plan` in test harness with a mocked `Orb`.
2. Feed a scripted sequence of `rgb_net::Output::Estimate` outputs (with valid `bbox.coordinates`) and `ir_net::Output::Estimate` outputs (with `score >= IRIS_SCORE_MIN`, brightness in range) sourced from a previously "recorded" fixture (i.e., reuse of estimate/frame pairs saved from a prior run) — with no synthesized response to any session-issued challenge.
3. Call `Plan::handle_rgb_net` / `Plan::handle_ir_net` directly with these replayed outputs.
4. Assert that the capture currently succeeds (`left_rgb`/`right_rgb`/`left_ir`/`right_ir` become `Some`) despite the absence of any freshness/challenge validation — demonstrating the missing check.
5. After remediation, the same replayed fixture should fail because it cannot satisfy the injected freshness challenge.

        &mut self,
        orb: &mut Orb,
        output: port::Output<ir_net::Model>,
        frame: Option<camera::ir::Frame>,
    ) -> Result<BrokerFlow> {
        match output.value {
            ir_net::Output::Estimate(estimate) => {
                self.update_occlusion(orb, &estimate);
                if let Some(perceived_side) = estimate.perceived_side {
                    if perceived_side != i32::from(!self.target_left_eye) {
                        tracing::debug!("Skipping frame due to target and perceived side mismatch");
                        return Ok(BrokerFlow::Continue);
                    }
                } else {
                    tracing::debug!("IRNet perceived_side=None, skipping frame");
                    return Ok(BrokerFlow::Continue);
                }

                self.update_ux(orb, estimate.sharpness);

                let frame = frame.expect("frame must be set for an estimate output");
                let valid_capture = estimate.score >= IRIS_SCORE_MIN
                    && (!orb.ir_auto_exposure.is_enabled()
                        || IRIS_BRIGHTNESS_RANGE.contains(&frame.mean()))
                    && self.valid_capture_after <= Instant::now();

                if valid_capture {
                    let slot =
                        if self.target_left_eye { &mut self.left_ir } else { &mut self.right_ir };
                    if slot.is_none() {
                        dd_incr!(
                            "main.count.signup.during.biometric_capture.\
                             first_side_sharp_iris_detected",
                            &format!(
                                "side:{}",
                                if self.target_left_eye { "left" } else { "right" }
                            )
                        );
                    }
                    tracing::debug!("Found sharp iris: {}", estimate.score);
                    *slot = Some(FrameInfoIr::new(estimate, frame));
                }
            }

    fn handle_rgb_net(
        &mut self,
        _orb: &mut Orb,
        output: port::Output<rgb_net::Model>,
        frame: Option<camera::rgb::Frame>,
    ) -> Result<BrokerFlow> {
        if let rgb_net::Output::Estimate(estimate) = output.value {
            if let Some(prediction) = estimate.primary() {
                if prediction.bbox.coordinates.is_correct() {
                    let frame = frame.expect("frame must be set for an estimate output");
                    let slot =
                        if self.target_left_eye { &mut self.left_rgb } else { &mut self.right_rgb };
                    *slot = Some(FrameInfoRgb::new(estimate, frame));
                }
            }
        }
        Ok(BrokerFlow::Continue)
    }
