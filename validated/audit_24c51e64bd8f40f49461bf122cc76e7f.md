### Title
Balance-conservation guard in `EmporiumUpgradeable.runAction` is fully bypassed when `erc20TokenAddresses` is empty, allowing theft of any token balance stranded on the Emporium contract - ([File: contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol])

### Summary
`runAction`'s only defense against Emporium's arbitrary `op.endpoint.call` operations draining pre-existing token balances is the `balanceChange < 0` → `BalanceChangeShouldBePositive` check, but that check is inside a `for` loop bounded by `circomData.erc20TokenAddresses.length`. Since this array (and the matching `dimensions.tokenNumber`) is fully attacker-controlled and can legally be empty, an attacker can execute arbitrary `ops` (including plain `token.transfer(attacker, amount)` calls) with zero balance-conservation enforcement for any token not listed, stealing any balance sitting on the Emporium contract.

### Finding Description
The claimed equality is: **for every ERC20 the transaction touches, `balancesAfter[i] - balancesBefore[i] (+|deltaAmountChanges[i]| if negative) >= 0`** must hold before UTXOs are minted out. This is enforced only inside: [1](#0-0) 

which iterates `i < circomData.erc20TokenAddresses.length`. The arbitrary-call execution loop over `stack.ops`, however, is entirely decoupled from `erc20TokenAddresses` and runs regardless: [2](#0-1) 

In the "stateless" case (`stack.signerAddress == address(0)`), `verifyWallet` performs no signature check at all and simply returns after marking the message used: [3](#0-2) 

so `op.endpoint.call{value: op.value}(op.callData)` executes with `msg.sender == Emporium`, fully attacker-chosen `endpoint`/`callData`, restricted only by the blocked `callHinkalWallet`/`doSendToRelay` selectors — nothing else.

`erc20TokenAddresses` is attacker-supplied `CircomData`, and `HinkalHelper.dimensionsCheck` only requires internal consistency (`erc20TokenAddresses.length == dimensions.tokenNumber`, matched by `amountChanges`, `onChainCreation`, `slippageValues`, `inputNullifiers`, `outCommitments`, `encryptedOutputs` all being length 0 too): [4](#0-3) 

There is nothing preventing `dimensions.tokenNumber == 0`, and the attacker generates their own proof, so this is trivially satisfiable. With `erc20TokenAddresses = []`, `_externalTransact` also builds `deltaAmountChanges` as a zero-length array, so no pre-funding transfer into Emporium happens for this transaction, but the `for` loop in `runAction` that would catch any net-negative movement of a *pre-existing* balance on Emporium (from a prior transaction's residue, e.g. a partial/incomplete token listing that stranded output tokens on the Emporium address, or slippage dust) never executes — confirmed by the loop bound at line 132. `handleOut` is likewise never invoked for that stranded token, so no compensating UTXO is minted, and the funds simply leave with no accounting.

The comment at line 141 ("the only case when balanceChange can be < 0, when there were some funds on emporium before the call") explicitly documents that this check exists *specifically* to guard against pre-existing Emporium balances being siphoned off by `ops` — and that guard is precisely what disappears when the array is empty.

### Impact Explanation
Any ERC20 (or ETH) balance that ends up resting on the Emporium contract's address — from a prior user's transaction that only partially listed tokens touched by its `ops` (e.g., a swap router sending output tokens to Emporium without that token being included in `erc20TokenAddresses`), or any other residue — can be drained by any unprivileged attacker in one call: submit `Hinkal.transact` targeting Emporium's `externalActionId` with `dimensions.tokenNumber = 0` (hence `erc20TokenAddresses = []`) and `ops = [{ endpoint: strandedToken, callData: transfer(attacker, strandedBalance) }]`. No signature, no relay, no privileged role is required. This is direct theft of another user's in-flight/stranded shielded funds with no compensating ledger entry — Critical severity, and repeatable for every token that ever becomes stranded on Emporium.

### Likelihood Explanation
Requires only that some ERC20 balance is (or becomes) held by the Emporium contract outside of the current attacker's own pre-funded flow — a state reachable by any legitimate/careless multi-step Emporium usage (partial token listings, swap-router dust, rounding). The attack itself costs only gas and one proof generation with an empty token dimension, and is fully repeatable against every stranded balance.

### Recommendation
Do not gate the balance-conservation check by `erc20TokenAddresses.length`. Either (a) require `erc20TokenAddresses.length > 0` whenever `stack.ops.length > 0` for Emporium actions, or (b) independently snapshot and verify balances of every token actually touched by `ops` (e.g., by requiring `ops` to declare touched tokens and cross-checking against `erc20TokenAddresses`), so the invariant `balanceChange >= 0` (adjusted for `deltaAmountChanges`) is enforced for all assets the call could move, not just the ones the caller chooses to list.

### Proof of Concept
1. Fork test: seed the Emporium contract with a stranded ERC20 balance (simulating a prior partial-listing transaction) by directly transferring `tokenX` to the deployed `EmporiumUpgradeable` proxy.
2. Craft `ops = [{endpoint: tokenX, invokeWallet: false, value: 0, callData: abi.encodeWithSelector(IERC20.transfer.selector, attacker, strandedBalance)}]`.
3. Run A: call `Hinkal.transact` with `dimensions.tokenNumber = 1`, `erc20TokenAddresses = [tokenX]`, generating a locally-produced proof; assert revert `BalanceChangeShouldBePositive`.
4. Run B: same `ops`/payload but `dimensions.tokenNumber = 0`, `erc20TokenAddresses = []` (and correspondingly empty `amountChanges`/`onChainCreation`/`slippageValues`/`inputNullifiers`/`outCommitments`/`encryptedOutputs`), with a matching locally-generated proof; assert the call **succeeds** and `tokenX.balanceOf(attacker)` increases by `strandedBalance` while `tokenX.balanceOf(Emporium)` decreases by the same amount, with no UTXO created to account for it.
