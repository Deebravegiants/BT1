### Title
`EvmHost.dispatch`/`dispatch(DispatchGet)`/`fundRequest` price native-fee swaps off the live, un-TWAP'd Uniswap V2 spot pool, permanently trapping any un-consumed `msg.value` - (File: `evm/src/core/EvmHost.sol`)

### Summary
`EvmHost` prices every native-token-paid dispatch by swapping `msg.value` of WETH for an *exact* amount of `feeToken` through the configured Uniswap V2 router, using the pool's current reserves with no TWAP, no caller-supplied slippage bound, and — critically — no refund of unconsumed ETH back to the caller. Because the amount of WETH the exact-output swap actually consumes is a direct function of the pool's spot price at execution time, and that price can be pushed in either direction within a single block (flash loan / same-block manipulation), any unused `msg.value` is refunded by the router to `address(this)` (the Host) rather than to the payer, permanently stranding the difference inside the Host contract with no withdrawal path back to the user.

### Finding Description
`EvmHost.dispatch(DispatchPost)`, `dispatch(DispatchGet)`, and `fundRequest` all execute the same pattern when paid in native token: [1](#0-0) 

```solidity
if (msg.value > 0) {
    address[] memory path = new address[](2);
    address uniswapV2 = _hostParams.uniswapV2;
    path[0] = IUniswapV2Router02(uniswapV2).WETH();
    path[1] = feeToken();
    IUniswapV2Router02(uniswapV2).swapETHForExactTokens{value: msg.value}(
        post.fee, path, address(this), block.timestamp
    );
}
```

`swapETHForExactTokens` computes the required WETH input directly from the pool's current reserves (`getAmountsIn`) with no oracle/TWAP smoothing — exactly the pattern the external report flags for "direct usage of Pool state in oracle/price calculation." Any ETH from `msg.value` beyond what the manipulated spot price requires is refunded by the Uniswap router to its immediate caller, which is `address(this)` — the `EvmHost` contract — not the original `_msgSender()`/payer of the `dispatch`/`fundRequest` call. There is no subsequent refund-to-payer logic anywhere in these functions.

The same unprotected spot-price read backs the advisory quoting helper used by integrators to size `msg.value` before calling dispatch: [2](#0-1) 

Since `quote()` and the actual `dispatch()` execution can be separated by any number of blocks/transactions, and the on-chain swap has no minimum-output/maximum-input caller-supplied bound beyond `msg.value` itself, an attacker can manipulate the WETH/feeToken pool (e.g., via a flash loan swap immediately before a victim's `dispatch` transaction in the same block) to change how much ETH the exact-output swap consumes, then reverse the manipulation afterward. Depending on direction, this either reverts the victim's honestly-sized dispatch (message never gets dispatched — a route unable to deliver messages) or under-consumes the sent ETH, leaving the untouched remainder locked in `EvmHost` permanently, since no function exists to sweep unspent native balance back to a payer.

### Impact Explanation
Any unspent `msg.value` sent alongside a native-token-paid `dispatch`/`fundRequest` call becomes permanently unrecoverable by the paying user, and the amount at risk is directly steerable by an attacker manipulating the WETH/feeToken pool's spot price in the same block, satisfying "permanent freezing of funds" — this is reachable by any unprivileged account dispatching a message or funding a pending request through `EvmHost`, the core message-dispatch entry point.

### Likelihood Explanation
The Uniswap V2 pools backing the Host's fee token are ordinary, typically lower-liquidity pairs (fee token vs. WETH) rather than deep venues, making single-block price manipulation via flash loan economically feasible; the acknowledged root cause matches the underlying report exactly (no TWAP, raw pool-state read), and the attack requires only a single flash-loanable transaction sandwiching a normal dispatch call — no privileged access needed.

### Recommendation
Add a caller-specified `amountInMax`/slippage bound to the native-fee swap path and refund any unconsumed `msg.value` back to `_msgSender()` after the swap. Additionally, price the WETH↔feeToken conversion off a TWAP (or a bounded oracle) rather than the instantaneous Uniswap V2 reserves, consistent with the acknowledged recommendation in the referenced report.

### Proof of Concept
1. Attacker takes a flash loan and swaps a large amount of WETH into the `feeToken`/WETH Uniswap V2 pool used by `EvmHost`, moving the pool's spot price so that acquiring `post.fee` units of `feeToken` requires substantially less WETH than at the block a victim priced their `msg.value` with `HyperApp.quote()`.
2. Victim's pre-signed/pending `dispatch{value: msg.value}(post)` transaction executes in the same block; `swapETHForExactTokens` only consumes the now-cheaper WETH amount and refunds the rest to `address(this)` (the Host), not to the victim.
3. Attacker reverses the flash-loan swap in the same block, restoring the pool and recovering their capital.
4. The victim's overpaid ETH remains inside `EvmHost` indefinitely; no function in `evm/src/core/EvmHost.sol` [3](#0-2)  refunds it, and it is never accounted for in any user-claimable balance.

    /**
     * @dev Dispatch a POST request to Hyperbridge
     *
     * @notice Payment for the request can be made with either the native token or the feeToken.
     * If native tokens are supplied, it will perform a swap under the hood using the local uniswap router.
     * Will revert if enough native tokens are not provided.
     *
     * If no native tokens are provided then it will try to collect payment from the calling contract in
     * the feeToken.
     *
     * @param post - post request
     * @return commitment - the request commitment
     */
    function dispatch(DispatchPost memory post) external payable notFrozen returns (bytes32 commitment) {
        if (msg.value > 0) {
            address[] memory path = new address[](2);
            address uniswapV2 = _hostParams.uniswapV2;
            path[0] = IUniswapV2Router02(uniswapV2).WETH();
            path[1] = feeToken();
            IUniswapV2Router02(uniswapV2).swapETHForExactTokens{value: msg.value}(
                post.fee, path, address(this), block.timestamp
            );
        } else if (post.fee > 0) {
            IERC20(feeToken()).safeTransferFrom(_msgSender(), address(this), post.fee);
        }

        // adjust the timeout
        uint64 timeoutTimestamp = post.timeout == 0 ? 0 : uint64(block.timestamp) + uint64(post.timeout);
        PostRequest memory request = PostRequest({
            source: host(),
            dest: post.dest,
            nonce: uint64(_nextNonce()),
            from: abi.encodePacked(_msgSender()),
            to: post.to,
            timeoutTimestamp: timeoutTimestamp,
            body: post.body
        });

        // make the commitment
        commitment = request.hash();
        _requestCommitments[commitment] = FeeMetadata({sender: post.payer, fee: post.fee});
        emit PostRequestEvent({
            source: string(request.source),
            dest: string(request.dest),
            from: _msgSender(),
            to: abi.encodePacked(request.to),
            nonce: request.nonce,
            timeoutTimestamp: request.timeoutTimestamp,
            body: request.body,
            fee: post.fee
        });
    }

     * @dev returns the quoted fee in the native token for dispatching a POST request

    function quote(DispatchPost memory request) public returns (uint256) {
        address _host = host();
        address _uniswap = IDispatcher(_host).uniswapV2Router();
        address[] memory path = new address[](2);
        path[0] = IUniswapV2Router02(_uniswap).WETH();
