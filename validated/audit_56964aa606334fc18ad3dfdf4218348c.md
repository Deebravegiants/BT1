### Title
`flash_position` opens fee-free leveraged debt, letting users bypass the `multiply` strategy fee - (File: contracts/controller/src/strategies/flash_position.rs)

### Summary
`multiply` charges the market `flashloan_fee` on the debt leg of a leveraged position (`charge_fee = true`), while `flash_position` opens the same position mode (Multiply/Long/Short) with `charge_fee = false`. Any unprivileged user with a WASM receiver contract can replicate a `multiply` through `flash_position` and permanently skip the strategy fee, draining protocol revenue.

### Finding Description
`process_multiply` opens a leveraged position by minting debt via `borrow_into_controller` with `charge_fee = true`, so the pool withholds `Bps::flash_loan_fee_on(amount)` and books it as protocol revenue [1](#0-0) . The pool-side fee logic lives in `compute_fee`, which derives the fee from `flashloan_fee` bps and credits it via `interest::add_protocol_revenue` [2](#0-1) .

`process_flash_position` accepts the same `PositionMode::Multiply | Long | Short` modes and mints the same debt through `mint_and_forward`, but passes `charge_fee = false` [3](#0-2) . The event even hardcodes `fee: 0` [4](#0-3) .

The only extra requirements are: the market is `is_flashloanable`, `receiver` is a WASM contract implementing `execute_flash_position` (not the controller or pool), and the callback must return collateral tokens to the controller so the measured deltas satisfy `collaterals` minimums [5](#0-4) . All of these are reachable by an unprivileged address deploying its own receiver that swaps the forwarded debt tokens on Aquarius/Soroswap and returns the collateral, exactly what `multiply` does internally via `swap_tokens_or_passthrough`.

Impact classification: theft of unclaimed yield / protocol revenue loss on every leveraged open routed this way.

### Impact Explanation
The strategy fee on leveraged opens is fully avoidable. For any `multiply` intent, a user calls `flash_loan`-style `flash_position` instead, receives the gross debt amount (`amount_received == amount`, no fee withheld), performs the identical swap inside their receiver callback, and ends with the same collateral deposit and debt position — at zero fee cost. At the cap of `MAX_FLASHLOAN_FEE_BPS = 500` (5%), every leveraged position opened this way withholds nothing, so LPs/treasury lose the entire intended fee stream on leveraged flow.

### Likelihood Explanation
Requires only a WASM receiver contract and a swap route — both explicitly allowed per the threat model (own flash receiver, own trades on Aquarius/Soroswap). No timing, liquidation risk, or privileged role is needed; it is a pure fee-arbitrage on the protocol's own entrypoints, repeatable on every open/extend.

### Recommendation
Charge the same `flashloan_fee` in `process_flash_position` by passing `charge_fee = true` to `borrow_into_controller` in `mint_and_forward` (and forwarding `amount_received` net of fee, reporting the real fee in `FlashPositionEvent` and the `execute_flash_position` callback argument instead of the hardcoded `0`). Alternatively, if fee-free flash positions are intended, remove the fee from `multiply` so the fee cannot be selectively bypassed.

### Proof of Concept
1. Market USDC has `is_flashloanable = true`, `flashloan_fee = 100` (1%).
2. Attacker deploys a WASM receiver implementing `execute_flash_position` that swaps received debt tokens on Aquarius into the collateral asset and transfers the proceeds to the controller.
3. Instead of `multiply(debt_to_flash_loan = X)` (which nets `X - fee`), attacker calls `flash_position(mode = Multiply, debt = USDC, amount = X, receiver = own contract, collaterals = [(collateral_key, min_out)], refund_assets = [])`.
4. `mint_and_forward` mints debt `X` and forwards the full `X` (`charge_fee = false`); receiver swaps to collateral; `collect_collateral_deposits` measures the receipt and deposits it; risk checks pass identically to a `multiply`.
5. Result: identical leveraged position, `fee = 0` instead of `X * 100 / BPS`; repeatable for every position open/extension, e.g., `swap_debt`-style rebalances that do charge a fee can also be replicated fee-free through the callback.

```rust
fn compute_fee(env: &Env, cache: &Cache, amount: i128, charge_fee: bool) -> i128 {
    if !charge_fee {
        return 0;
    }
    let fee = Bps::from(i128::from(cache.params().flashloan_fee)).flash_loan_fee_on(env, amount);
    assert_with_error!(env, fee <= amount, FlashLoanError::StrategyFeeExceeds);
    fee
}
```
