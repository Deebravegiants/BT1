### Title
Zero LT `exchangeRate()` permanently freezes both `Zap.buy` and `Zap.sell` for a curve token, locking holder funds - ([File: packages/contracts/src/Zap.sol])

### Summary
`Zap._sellInternal` and `Zap._executeBuy` both read the external BounceTech LT's `exchangeRate()` and use it in a way that hard-fails when the rate reaches `0`. If a paired LT's `exchangeRate()` ever settles at `0` (e.g., a fully-liquidated leveraged token, matching the "supported asset value falls to 0" scenario in the source report), every pre-graduation holder of that curve token becomes permanently unable to buy or sell through the only sanctioned trading path (`Zap`), freezing their funds in the same fashion as the referenced `MarginAccount` bug.

### Finding Description
`Zap._sellInternal` computes the USDC value of the LT received from a curve/HyperSwap sell and gates it with a fixed floor check: [1](#0-0) 

`grossUsdcEstimate = ltReceived * exchangeRate / 1e18`. If `exchangeRate()` returns `0`, `grossUsdcEstimate` is `0` **regardless of `ltReceived`** — i.e. regardless of how many tokens the seller is dumping. The check `grossUsdcEstimate / 1e12 < minUsdcAmount()` is therefore unconditionally true, and `_sellInternal` reverts with `BelowMinAmount()` for every sell size, including selling 100% of a holder's balance. Crucially, the tokens have *already* been pulled from the seller (`safeTransferFrom` at line 438) and swapped into LT (`_sellOnCurve`/`_sellOnUniswapV2` at 440-442) before this check runs, but since the whole external call reverts, the transaction unwinds — the seller keeps the tokens but can never successfully complete a sell.

Symmetrically, `_executeBuy` computes `ltIfFull = IBounceLeveragedToken(lt).baseToLtAmount(netUsdc)` on the non-graduated path: [2](#0-1) 

`baseToLtAmount` is defined by BounceTech (and mirrored in the test mock) as `(baseAmount * 1e18) / exchangeRate`, per the mock's implementation: [3](#0-2) 

When `exchangeRate == 0`, this division panics on the LT contract, reverting every `Zap.buy` for that token as well.

With both `buy` and `sell` permanently reverting, `Bonding.canGraduate` (which multiplies `realLtRaised * exchangeRate`) can never satisfy the USD leg, and the supply leg (`tokenBalance() == 0`) can never be reached because no further buys can drain the curve: [4](#0-3) 

Since `Bonding.buy`/`Bonding.sell` are only reachable through the allowlisted `Router`-role holder (`Zap`), and pre-graduation Token holders hold no direct claim on the LT (only the curve `Token`), there is no bypass analogous to post-graduation direct HyperSwap trading. The project's own documentation acknowledges LT-freeze scenarios but only claims safety via "holders can always exit via `redeem`" — that claim applies to the LT itself, not to the curve `Token`, which has no direct redemption path outside `Zap`: [5](#0-4) 

### Impact Explanation
Any curve-stage token paired with an LT whose `exchangeRate()` settles to `0` becomes permanently untradeable: buyers can no longer mint LT via `mint`/`baseToLtAmount` (division-by-zero revert on the LT), and existing holders can no longer sell via `Zap.sell` because the USD-floor check is unconditionally tripped to `0`. This permanently locks all trader (and creator) funds held in that curve token, mirroring "All assets are locked" impact from the analog report — no governance or admin lever exists in-scope to unpause, bypass the check, or manually graduate the token, since `triggerGraduation` itself depends on `canGraduate`, which is gated by the same broken `exchangeRate()` read.

### Likelihood Explanation
BounceTech LTs are leveraged tokens; by design, a highly leveraged long/short position can be fully liquidated to zero collateral value in an adverse market move, at which point `exchangeRate()` (`totalAssets/totalSupply`) settles at `0`. This is a foreseeable market condition for a leveraged reserve asset (not a contrived edge case), and the protocol explicitly reasons about degraded/retired LT states in its own docs, showing the maintainers are aware LT prices can go to extremes but did not add a safeguard for the `exchangeRate() == 0` case in `Zap`.

### Recommendation
- Decouple the sell-side USD floor check from a multiplicative estimate that collapses to `0` when `exchangeRate() == 0`; e.g., gate on `ltReceived` (or a raw LT-denominated minimum) rather than `ltReceived * exchangeRate`, or explicitly special-case `exchangeRate() == 0` to skip/bypass the USD floor and let the sell (and `redeem`) proceed at whatever (possibly zero) USDC value results, so holders can still exit their position.
- Add an emergency/manual graduation or "retire curve" path gated by an owner/governance role that can force a curve token out of `Lifecycle.Curve` (e.g., burn remaining curve reserves and let holders redeem directly against a rescued LT balance) when `exchangeRate()` is stuck at `0`, so funds are not held hostage indefinitely by the Zap-only trading gate.
- Consider allowing a permissionless fallback that lets a `Token` holder redeem their pro-rata share of the curve's raised LT directly (bypassing `Router`/`Zap`) if the curve becomes permanently non-tradable, similar to a rescue/emergency-withdraw pattern.

### Proof of Concept
1. Launch a token via `Bonding.launch`/`Zap.createToken` against an LT with a nonzero `exchangeRate()`; several buys accumulate real curve holders.
2. The LT's underlying position is fully liquidated (a realistic BounceTech scenario for high-leverage tokens), and `exchangeRate()` settles at `0`.
3. Any holder calls `zap.sell(tokenAddress, tokenAmount, 0)`. Trace: `_sellInternal` → `_sellOnCurve` succeeds and returns `ltReceived > 0` → `grossUsdcEstimate = ltReceived * 0 / 1e18 = 0` → `0 / 1e12 < minUsdcAmount()` is true → revert `BelowMinAmount()`. This reverts unconditionally, for any `tokenAmount`, including a full-balance sell.
4. Any address calls `zap.buy(tokenAddress, usdcAmount, 0, referrer)` on the curve path: `_executeBuy` calls `IBounceLeveragedToken(lt).baseToLtAmount(netUsdc)`, which internally divides by `exchangeRate() == 0` and reverts.
5. With both `buy` and `sell` permanently reverting, `Bonding.canGraduate` never flips true (USD leg multiplies by `0`; supply leg needs more buys that can't happen), so `triggerGraduation`/`finalizeGraduation` are unreachable, and every existing holder's curve-token position is permanently frozen with no recovery path in-scope.
