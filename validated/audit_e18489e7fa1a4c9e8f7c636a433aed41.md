### Title
RAY-value `i128` overflow in interest accrual permanently bricks a market before the borrow-index cap engages - (File: common/src/rates/simulate.rs)

### Summary
`accrue_step` values total borrowed and total supplied at the live indexes via `scaled_to_original` before compounding. On a very large market the product `borrowed_scaled * borrow_index` exceeds `i128::MAX` and the fixed-point multiply panics with `MathOverflow`. Because `global_sync` runs accrual before every mutating verb, the panic permanently reverts `supply`, `borrow`, `withdraw`, `repay`, `liquidate`, `clean_bad_debt`, and `recapitalize` on that market — while the `MAX_BORROW_INDEX_RAY` cap, which is supposed to stop accrual, is never reached. [1](#0-0) [2](#0-1) 

### Finding Description
The LibRaw stack overflow is a memory-safety violation reachable with attacker-controlled input; the analog here is an arithmetic overflow reachable purely through public entrypoints. `accrue_step` computes `borrowed_original = scaled_to_original(env, borrowed, borrow_index)` and `supplied_original = scaled_to_original(env, supplied, supply_index)` on every chunk, before calling `update_borrow_index` which is the only place the `MAX_BORROW_INDEX_RAY` clamp applies. [1](#0-0)  `scaled_to_original` is a `Ray::mul` (`mul_div_half_up`), which widens to `I256` for the product but then requires the *quotient* to fit `i128`, panicking `MathOverflow` otherwise. [3](#0-2) [4](#0-3)  The value ceiling (`i128::MAX` for `borrowed * index`) is hit at an index roughly `i128::MAX / borrowed` — far below the `10^36` index cap whenever total debt is large. The repo's own integration test demonstrates a 98%-utilization billion-unit market hitting `MATH_OVERFLOW` inside accrual after some years, with `borrow_index < MAX_BORROW_INDEX_RAY`, and every subsequent `withdraw`/`repay` reverting with the same error. [5](#0-4) 

### Impact Explanation
Permanent freezing of funds and protocol insolvency on the affected market: once `borrowed * borrow_index` crosses the `i128` value ceiling, every verb accrues first and panics, so suppliers cannot withdraw, borrowers cannot repay (debt keeps nominally existing but is unpayable and unseizable), liquidators cannot liquidate, and bad debt cannot be cleaned or recapitalized. All tokens held by the pool book for that market are frozen forever, and accrual can never resume because `global_sync` itself is the panicking call. [2](#0-1) [6](#0-5) 

### Likelihood Explanation
Reachable only with ordinary unprivileged `supply`/`borrow` calls plus time — no governance action beyond the initial market listing is required. The precondition is a market whose scaled debt times index exceeds `i128::MAX`, which needs a very large deposit (the demonstration uses ~10^27 base units of an 18-decimal asset) and sustained high utilization long enough for the index to grow; the test shows this happens at realistic borrow rates while the index is still far below `MAX_BORROW_INDEX_RAY`. Once the state exists, any third party's ordinary call — or simply the passage of time before the next call — triggers the freeze. [7](#0-6) 

### Recommendation
Enforce the value ceiling, not just the index cap, inside `accrue_step`:
- In `update_borrow_index`/`accrue_step`, clamp the grown index to `min(MAX_BORROW_INDEX_RAY, i128::MAX_safe / borrowed)` so the accrual path saturates instead of panicking, mirroring the existing `revenue_shares = min(..., i128::MAX - supplied)` pattern. [8](#0-7) 
- Alternatively, bound `borrowed`/`supplied` at scaling time (`calculate_scaled_supply`/`calculate_scaled_borrow` call sites in `contracts/pool/src/cache/scale.rs`) so `scaled * index` can never approach `i128::MAX`, rejecting oversized deposits/borrows with a protocol error rather than letting the market drift into a permanently panicking state. [9](#0-8) 
- Document and test a residual-index bound consistent with `docs/reference/formulas.md`'s arithmetic-domain claims.

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Computes `floor(x * y / d)`, rounding toward negative infinity for a negative quotient.
/// Panics with `GenericError::DivisionByZero` if `d == 0`, or with
/// `GenericError::MathOverflow` if the result does not fit in `i128`.
pub fn mul_div_floor(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    require_nonzero_divisor(env, d);
    if let Some(quotient) = x
        .checked_mul(y)
        .and_then(|product| div_floor_i128(product, d))
    {
        return quotient;
    }
    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    let nonneg = quotient_is_nonnegative(x, y, d);
    to_i128(env, &div_floor_i256(env, &x256.mul(&y256), &d256, nonneg))
}

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
