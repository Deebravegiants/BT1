### Title
Unallowlisted swap routes can attach arbitrary wallet-token transfers to controller strategy authorization - ([File: contracts/controller/src/strategies/swap.rs](contracts/controller/src/strategies/swap.rs))

### Summary
Controller strategy entrypoints accept opaque `swap` bytes and pass them to the configured router after authorizing only the controller's exact input-token transfer. A route can invoke attacker-chosen venue code that requests a nested token transfer from the strategy caller; if the caller signs the auth tree returned by simulation, that unrelated wallet balance is transferred to the attacker.

### Finding Description
`multiply`, `swap_debt`, `swap_collateral`, and `repay_debt_with_collateral` all expose caller-controlled `swap` bytes through the public controller ABI. [1](#0-0) 

`process_swap_collateral` requires ownership or delegation, withdraws collateral into controller custody, and passes `swap` through `withdraw_and_swap_from_supply` without inspecting the route destinations. [2](#0-1) 

`withdraw_and_swap_from_supply` forwards the same payload to `swap_tokens_or_passthrough`. [3](#0-2) 

`swap_tokens` authorizes only one exact `token_in.transfer(controller, router, amount_in)` invocation for the router call, so the controller's own grant does not constrain which contracts later execute under the caller's broader authorization tree. [4](#0-3) [5](#0-4) 

The router-side dispatch derives `pool`, `token_in`, and `token_out` from payload registry indexes and invokes the selected venue without requiring that the pool address be on a lending-managed allowlist. [6](#0-5) [7](#0-6) 

A malicious hop contract can therefore call `token.transfer(caller, attacker, amount)` while the swap is active; Soroban records that transfer as a child invocation beneath the caller's `swap_collateral` authorization and executes it when the signed tree includes that child. [8](#0-7) [9](#0-8) 

### Impact Explanation
An attacker can steal arbitrary tokens held by the strategy caller, including assets never supplied to or listed by the lending protocol. The regression test drains an unrelated wallet-token balance to an attacker while simultaneously delivering a fair ETH output and completing the collateral swap successfully. [10](#0-9) [11](#0-10) 

The measured-input, measured-output, overspend, and final-risk checks do not bound this loss because the stolen token is neither the routed input nor the expected output. [12](#0-11) 

### Likelihood Explanation
The attack does not bypass authorization: the malicious child invocation must appear in the authorization tree that the caller signs. [13](#0-12) 

It remains practical because the route bytes are opaque to the controller and simulation presents the malicious wallet transfer as an authorization subtree of the otherwise valid strategy call. A wallet or user that validates only the root call and intended swap amount can sign the expanded tree. [14](#0-13) 

### Recommendation
Maintain an explicit allowlist of route venue contracts and pool addresses accepted by lending strategies, and reject payloads whose pool or token targets are not listed. For venue adapters that support approval-based pulls, continue clearing temporary allowances, but do not treat that cleanup as a substitute for destination allowlisting. Clients should additionally reject any simulated authorization tree containing child invocations beyond the exact expected input transfer, as demonstrated by the honest-tree control. [15](#0-14) [16](#0-15) 

### Proof of Concept
1. Alice supplies `10,000 USDC` and creates a lending account.
2. The attacker deploys a hop contract storing `(alice, unrelated_wallet_token, attacker, WALLET_BALANCE)` as its execution plan.
3. The attacker supplies route bytes for `swap_collateral(alice, account_id, usdc_market, 50_000_000_000, eth_market, route)` whose `pool` field is the malicious hop contract.
4. The malicious `swap()` entrypoint executes `wallet_token.transfer(alice, attacker, WALLET_BALANCE)` while still allowing the route to return `25_000_000` ETH.
5. Simulation records the token transfer as a child of Alice's `swap_collateral` authorization.
6. If Alice signs that returned tree, the transaction succeeds: Alice has `0` wallet tokens, the attacker has `77_770_000_000`, and Alice receives the expected ETH collateral.

The repository's executable fixture implements these steps through `UnlistedPoolRouter`, `RogueHopPool`, and `swap_collateral`; its recording-mode and enforcing-mode assertions demonstrate both the poisoned auth tree and the resulting token drain. [17](#0-16) [18](#0-17) [8](#0-7) [9](#0-8)

/// Authorizes, on behalf of the current contract, one `transfer(from, to, amount)`

        },
        sub_invocations: Vec::new(env),
    });
    env.authorize_as_current_contract(vec![env, entry]);

#[test]
fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
}
