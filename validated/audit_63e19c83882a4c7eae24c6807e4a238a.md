The Quint bug class is "state that should be updated to prevent a repeat privileged action is not durably/atomically maintained, allowing the same action to be replayed." The closest reachable analog in an unprivileged, internet-facing gateway path is the JWT anti-replay cache used to authorize HTTP-triggered workflow executions.

### Title
JWT replay protection state is non-durable, in-memory only, and lost on gateway restart, enabling replay of used workflow-trigger tokens - ([File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go])

### Summary
The `WorkflowMetadataHandler.Authorize` function is the authentication gate for unprivileged, internet-facing HTTP trigger requests that execute workflows on the Chainlink gateway. It relies on a `jwtReplayCache` to prevent a signed JWT (bound to a specific JSON-RPC request digest) from being used more than once. This cache is a plain in-process `map[string]time.Time` with no persistence, so the "already used" state that is supposed to block a second execution of the same signed request is lost whenever the gateway process restarts (deploy, crash, pod reschedule) — mirroring the Quint root cause where the reward/claim state was not durably updated, allowing the same claim to be executed again.

### Finding Description
`Authorize` checks `h.jwtCache.isReplay(claims.ID)` and, if the JWT hasn't been seen, later calls `h.jwtCache.recordUsage(claims.ID)`: [1](#0-0) 

The cache itself is defined and implemented purely in memory, with no persistence layer: [2](#0-1) [3](#0-2) 

The JWT itself remains valid (per signature/expiry) for up to the configured max lifetime, independent of the replay cache: [4](#0-3) 

Because `jwtCache.cache` is only held in the process's memory, any event that clears or bypasses that specific process's memory state (restart, crash-recovery, redeploy, or — in a horizontally scaled gateway deployment — routing to a different gateway instance/shard listener that maintains its own independent `WorkflowMetadataHandler`/`jwtCache`) resets the "used" bookkeeping to empty. An attacker (or anyone who has legitimately captured a previously-used, still-unexpired signed request/JWT — e.g., via logs, network capture, or replaying their own already-consumed token) can resend the exact same signed request after such an event and have it re-authorized and re-executed, because `isReplay` will report `false` again. This is directly analogous to the Quint `reStake` bug: a piece of state meant to prevent a repeated privileged action (claiming a reward / consuming a token) is not durably persisted, so the same privileged action can be triggered again.

### Impact Explanation
A successful replay causes an authorized, duplicate `workflows.execute` trigger to be dispatched to the DON nodes for the same workflow and request, i.e., an unauthorized/duplicate job run outside of the request originator's intent. For workflows that move funds, submit on-chain transactions, or have other side effects, a duplicated execution can cause real financial or state-consistency damage, matching the "unauthorized job run" acceptance criterion.

### Likelihood Explanation
Exploitation does not require compromising any key material — the attacker only needs a previously valid (but consumed) signed JWT/request pair, which is not treated as a secret and can be observed in transit, logs, or by legitimate but malicious replay from the original caller across an operational event (deploy/restart/failover) that is common in normal operations of a production gateway service. The JWT max lifetime (`maxJWTExpiryDuration`) defines the exploitation window during which a captured-but-consumed token remains "revivable."

### Recommendation
Persist the JWT replay state (e.g., in a shared/external store such as the gateway's database or a distributed cache) so that "used" status for a `jti` survives process restarts and is consistent across all gateway instances/shards that can authorize requests for the same workflow. Alternatively/additionally, make the check in `Authorize` atomic (single check-and-set operation) to close any TOCTOU window between `isReplay` and `recordUsage`, and ensure the store used for this purpose is durable rather than purely in-memory.

### Proof of Concept
1. Client sends a valid signed workflow-trigger request (`workflows.execute`) with JWT `jti=X` to gateway instance A; `Authorize` succeeds and `recordUsage(X)` marks it used in A's in-memory `jwtCache`.
2. Gateway instance A restarts (deploy/crash) or the same request is routed to gateway instance B (separate process/memory), both of which start with an empty `jwtCache`.
3. The same signed request (still within its JWT expiry window) is resent to the (now-restarted or alternate) gateway.
4. `isReplay(X)` returns `false` because the in-memory cache no longer contains `X`; `Authorize` succeeds a second time and the workflow is executed again for the same request, demonstrating that the intended one-time-use guarantee is not durably enforced.

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}

func newJWTReplayCache(cleanupPeriod time.Duration) *jwtReplayCache {
	return &jwtReplayCache{
		cache:         make(map[string]time.Time),
		cleanupPeriod: cleanupPeriod,
	}
}

func (cache *jwtReplayCache) isReplay(jti string) bool {
	cache.mu.RLock()
	defer cache.mu.RUnlock()

	_, exists := cache.cache[jti]
	return exists
}

func (cache *jwtReplayCache) recordUsage(jti string) {
	cache.mu.Lock()
	defer cache.mu.Unlock()

	cache.cache[jti] = time.Now()
}
