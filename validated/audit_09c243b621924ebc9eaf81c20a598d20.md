### Title
CPU-exhaustion DoS via unbounded RFC3339 timestamp string parsing in Tendermint consensus proof verification - (File: modules/consensus/tendermint/primitives/src/verifier.rs)

### Summary
The Tendermint light-client consensus type `CodecCommitSig` (and `TendermintCodecHeader`) carries attacker-controlled `timestamp: String` / `time: String` fields that are SCALE-decoded with no length bound and later parsed with `cometbft::Time::parse_from_rfc3339(timestamp)` for every signature in a commit. This mirrors the CVE-2020-35573 bug class: a length-unbounded, attacker-supplied "timestamp tag" is fed into a parser whose cost scales with the attacker's input, and the parsing happens for every element in an attacker-controlled collection before any cryptographic or business-logic check can reject the proof.

### Finding Description
`CodecCommitSig` is defined with a `String` timestamp field per validator vote: [1](#0-0) 

`to_commit_sig()` unconditionally parses this string for every signature via `cometbft::Time::parse_from_rfc3339(timestamp)`: [2](#0-1) 

and `CodecCommit::to_commit()` maps this conversion over the entire `signatures: Vec<CodecCommitSig>`: [3](#0-2) 

`CodecCommit.signatures` and each `timestamp`/`time` `String` field are SCALE-decoded straight from the submitted proof bytes with no explicit length caps (unlike other parts of this codebase, e.g. Pharos `MAX_PROOF_DEPTH` or the zstd decompressor's `MaxCallSize` bound, which were specifically hardened against oversized/attacker-controlled inputs). The whole update is decoded and dispatched through `TendermintClient::verify_consensus`: [4](#0-3) 

which is reachable through `pallet_ismp::Call::handle_unsigned`, an unsigned (fee-less) extrinsic that every full node validates for free in the transaction pool before block inclusion: [5](#0-4) [6](#0-5) 

Every node's `validate_unsigned` path runs `Self::execute(messages)` → `handle_incoming_message` → the Tendermint client's `verify_consensus`, decoding and RFC3339-parsing every commit-sig timestamp, before the proof is finally rejected as invalid (e.g. bad chain ID, bad validator set, insufficient voting power). An attacker can therefore submit a cheap, self-consistently-encoded but otherwise invalid `TendermintConsensusUpdate` containing a `Commit` with many `CodecCommitSig::BlockIdFlagCommit`/`BlockIdFlagNil` entries, each carrying a long, malformed (but not empty) `timestamp` string, forcing every full node in the network to perform expensive RFC3339 parsing work repeatedly — at essentially zero cost to the submitter, since the transaction is unsigned/free and is rejected only after the expensive parsing step.

### Impact Explanation
This is a route-availability / DoS issue: nodes performing free, unsigned tx-pool validation of a crafted (and cheap-to-produce) Tendermint consensus message would burn disproportionate CPU on RFC3339 string parsing across an attacker-inflated `signatures` vector and attacker-inflated timestamp strings, before the proof is rejected. Because the pallet's fee-less design explicitly relies on "proof validity" checks happening cheaply/quickly to prevent transaction-pool spam (as documented for `pallet-ismp`), a parsing step whose cost scales with attacker-chosen string length and vector length undermines that anti-spam assumption and can degrade or halt message delivery for the Tendermint consensus client (and any host application relying on it), i.e., "a route unable to deliver messages."

### Likelihood Explanation
Reachable by any unprivileged relayer/user submitting an unsigned `handle_unsigned` extrinsic — no fees, no privileged origin required. Constructing a syntactically valid SCALE-encoded `TendermintConsensusUpdate` with a large `Vec<CodecCommitSig>` and long garbage timestamp strings requires no cryptographic material and is cheap to produce, satisfying the "concrete, reachable from a single dispatched request" bar. However, I was not able to fully verify (due to index/tool limits) whether an upstream size cap exists on the overall extrinsic/call length (e.g. `MaxCallSize`/`decode_all_with_depth_limit`) that would bound how large `signatures`/`timestamp` can actually get in practice, nor the precise CPU cost of `Time::parse_from_rfc3339` on adversarial strings (i.e., whether the parser itself is linear-time and thus this is closer to "bounded amplification" than genuine unbounded CPU consumption). This uncertainty affects the exploitability magnitude and should be confirmed with a proof-of-concept before treating this as fully weaponizable.

### Recommendation
- Bound `CodecCommit.signatures.len()` and the byte-length of each `timestamp`/`time` `String` at decode time (or immediately after decode, before any parsing), consistent with the sizing patterns already used elsewhere in the codebase (e.g. `MAX_PROOF_DEPTH`, `MaxCallSize`).
- Reject a `TendermintConsensusUpdate` whose `signatures.len()` exceeds the maximum plausible validator-set size before running any per-signature parsing.
- Perform cheap syntactic sanity checks (e.g., fixed expected RFC3339 length, e.g. exactly the canonical `YYYY-MM-DDTHH:MM:SS(.nnnnnnnnn)?Z` length range) prior to invoking the full RFC3339 parser, so malformed but oversized strings are rejected in O(1) instead of paying the full parser cost.
- Consider validating the "cheap" structural invariants of `CodecCommit`/`CodecCommitSig` (vote count vs. known validator set size, from `TrustedState`) before performing any timestamp parsing, similar to how BLS/GRANDPA/SPV verifiers here already validate sizes/depths before doing expensive crypto work.

### Proof of Concept
1. Construct a SCALE-encoded `TendermintConsensusUpdate` wrapping a `CodecConsensusProof` whose `signed_header.commit.signatures` is a `Vec<CodecCommitSig>` with, e.g., several thousand `BlockIdFlagCommit` entries, each with a `timestamp: String` set to a long (e.g. kilobytes), syntactically-plausible-but-invalid RFC3339-like string (so it is not rejected by a trivial length/format check before parsing).
2. Wrap this in `ismp::messaging::ConsensusMessage::... ` as required by `verify_consensus`, and submit it via `pallet_ismp::Call::handle_unsigned` as an unsigned extrinsic (no signature, no fee) to a node's transaction pool.
3. Observe that `ValidateUnsigned::validate_unsigned` → `Pallet::execute` → `handle_incoming_message` → `TendermintClient::verify_consensus` → `to_consensus_proof()` → `CodecCommit::to_commit()` iterates over all signatures and calls `cometbft::Time::parse_from_rfc3339` on each large/malformed timestamp string before the proof is ultimately rejected (e.g., due to an unmatched validator set/chain ID), measuring the CPU time spent per submitted (free) transaction versus a normal proof submission — repeated submission at near-zero cost by the attacker should show disproportionate aggregate CPU cost across the validating node set.

impl CodecCommit {
	/// Convert back to Commit
	pub fn to_commit(&self) -> Result<crate::Commit, String> {
		let height = cometbft::block::Height::try_from(self.height)
			.map_err(|e| format!("Invalid commit height: {}", e))?;
		let round = cometbft::block::Round::try_from(self.round)
			.map_err(|e| format!("Invalid commit round: {}", e))?;
		let block_id = self.block_id.to_block_id()?;
		let signatures = self
			.signatures
			.iter()
			.map(|codec_sig| codec_sig.to_commit_sig())
			.collect::<Result<Vec<_>, _>>()?;
		Ok(crate::Commit { height, round, block_id, signatures })
	}
}

impl CodecCommitSig {
	/// Convert back to CommitSig
	pub fn to_commit_sig(&self) -> Result<crate::CommitSig, String> {
		match self {
			CodecCommitSig::BlockIdFlagAbsent => Ok(crate::CommitSig::BlockIdFlagAbsent),
			CodecCommitSig::BlockIdFlagCommit { validator_address, timestamp, signature } => {
				let validator_address = cometbft::account::Id::try_from(validator_address.to_vec())
					.map_err(|e| format!("Invalid validator address: {}", e))?;
				let timestamp = cometbft::Time::parse_from_rfc3339(timestamp)
					.map_err(|e| format!("Invalid timestamp: {}", e))?;
				let signature = if let Some(sig_bytes) = signature {
					Some(
						cometbft::Signature::try_from(sig_bytes.as_slice())
							.map_err(|e| format!("Invalid signature: {}", e))?,
					)
				} else {
					None
				};
				Ok(crate::CommitSig::BlockIdFlagCommit { validator_address, timestamp, signature })
			},
			CodecCommitSig::BlockIdFlagNil { validator_address, timestamp, signature } => {
				let validator_address = cometbft::account::Id::try_from(validator_address.to_vec())
					.map_err(|e| format!("Invalid validator address: {}", e))?;
				let timestamp = cometbft::Time::parse_from_rfc3339(timestamp)
					.map_err(|e| format!("Invalid timestamp: {}", e))?;
				let signature = if let Some(sig_bytes) = signature {
					Some(
						cometbft::Signature::try_from(sig_bytes.as_slice())
							.map_err(|e| format!("Invalid signature: {}", e))?,
					)
				} else {
					None
				};
				Ok(crate::CommitSig::BlockIdFlagNil { validator_address, timestamp, signature })
			},
		}
	}
