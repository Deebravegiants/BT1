## Finding

### Title
Unauthenticated `/v2/resume/:runID` endpoint allows request impersonation / front-run data-poisoning of suspended pipeline task runs - (File: `core/web/pipeline_runs_controller.go`)

### Summary
The external-adapter callback endpoint `PipelineRunsController.Resume` (mounted as the `PATCH /v2/resume/:runID` route referenced by the audit event `audit.UnauthedRunResumed`) accepts any caller who knows a task's UUID and immediately writes the caller-supplied result into the pipeline task run, with no check that the task hasn't already been completed and no verification that the caller is the bridge that was actually asked to do the work.

### Finding Description
`Resume` parses the `runID` path param as a task UUID and forwards the client-supplied JSON body directly into `App.ResumeJobV2` → `pipeline.Runner.ResumeRun` → `orm.UpdateTaskRunResult`: [1](#0-0) 

`ResumeRun` simply forwards the value/error into the ORM update and, if the run was suspended, restarts it: [2](#0-1) 

`UpdateTaskRunResult` locates the run by `pipeline_task_runs.id = $1` filtered only on the *run's* state (`running`/`suspended`) — it never checks whether that specific task run already has a result (i.e. is already finished) before unconditionally overwriting `output`/`error`/`finished_at`: [3](#0-2) 

The only "credential" that authorizes this write is knowledge of the task UUID embedded in the `ResponseURL` sent to the external adapter/bridge (`http://.../v2/resume/<taskID>`), as seen in the async bridge test flow: [4](#0-3) 

Because this route bypasses the normal session/API-token/external-initiator authentication (its audit event is explicitly named `UnauthedRunResumed`), and because `UpdateTaskRunResult` has no idempotency guard for a task run that has not yet reported a result, an attacker who can observe or guess the UUID can race the legitimate bridge's callback: whichever request reaches `UpdateTaskRunResult` first wins, its value is persisted as the task's `output`, and (if the run was suspended) the pipeline resumes immediately using the attacker-supplied value. This mirrors the reported `liquidate()` bug class: an unprivileged actor can front-run a legitimate state-changing call that lacks a guard against being pre-empted, forcing the "victim" outcome (correct external-adapter data) to be discarded or superseded by attacker-controlled data.

### Impact Explanation
If the UUID is discoverable (e.g., via network observation, logging, error messages, or because the adapter response is delayed and the attacker races with it), an unauthenticated actor can:
- Inject arbitrary values/errors into a running job's pipeline (data poisoning of oracle/job results), and
- Grief/deny the legitimate external adapter's response, since the run may have already progressed past the task by the time the genuine callback arrives, silently discarding correct data.

Because job pipelines can feed values used for on-chain transactions (e.g., ETHTx tasks), successful exploitation can result in bad data driving downstream fund-moving actions. Impact is scoped to nodes where async/bridge job types (with `ResponseURL` webhooks) are used and the taskID can be obtained by a third party.

### Likelihood Explanation
Likelihood depends on the attacker being able to learn or predict the resume UUID before/at the same time as the legitimate adapter. This is not trivial (UUIDs are random) but is realistic in scenarios where: adapter responses can be delayed/dropped and retried, UUIDs leak through logs/URLs/network intermediaries, or a malicious/compromised bridge operator intentionally races the callback. The complete lack of a "task already resolved" check and the explicit "unauthenticated" design of this endpoint make it a plausible target class for this bug family (front-run/race + no re-entrancy or replay guard), matching the reported pattern of unguarded, front-runnable state transitions in `liquidate()`/`repayInternal`.

### Recommendation
- Add a guard in `UpdateTaskRunResult` that only accepts an update for a task run whose `finished_at`/`output`/`error` are still unset (i.e., not already resolved) — reject or no-op otherwise, closing the race window and preventing overwrite of an already-completed task.
- Prevent restarting the run in `ResumeRun`/`Run` more than once for a task; make the `resume` operation idempotent and returns a clear conflict when a task is already finished.
- Consider binding the resume token to additional out-of-band verification (e.g., a per-run secret/HMAC in the outgoing bridge request separate from the identifying UUID, rather than relying purely on UUID secrecy) and shortening/auditing UUID exposure paths.

### Proof of Concept
1. Configure a job with an async bridge task, causing the node to suspend the run and send the external adapter a `ResponseURL` such as `http://node:6688/v2/resume/<taskID>`.
2. As soon as the request is sent (or by leaking/observing the URL), send a forged `PATCH /v2/resume/<taskID>` request with attacker-controlled JSON body before the legitimate adapter responds:
   - Confirmed via `orm.UpdateTaskRunResult` (`core/services/pipeline/orm.go:271-308`), which will accept and persist the attacker's payload as long as the parent run is still `running`/`suspended`, with no check that the task run has not already received a result.
3. Because `ResumeRun` (`core/services/pipeline/runner.go:732-755`) immediately restarts the run if it was `suspended`, the pipeline continues executing with the attacker's injected value; the legitimate adapter's later, genuine response either loses the race (silently discarded/ignored since the pipeline has moved on) or is itself accepted last, demonstrating the unguarded race condition.

func (prc *PipelineRunsController) Resume(c *gin.Context) {
	taskID, err := uuid.Parse(c.Param("runID"))
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	rr := pipeline.ResumeRequest{}
	decoder := json.NewDecoder(c.Request.Body)
	err = errors.Wrap(decoder.Decode(&rr), "failed to unmarshal JSON body")
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	result, err := rr.ToResult()
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	if err := prc.App.ResumeJobV2(c.Request.Context(), taskID, result); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
	c.Status(http.StatusOK)
}

func (o *orm) UpdateTaskRunResult(ctx context.Context, taskID uuid.UUID, result Result) (run Run, start bool, err error) {
	if result.OutputDB().Valid && result.ErrorDB().Valid {
		panic("run result must specify either output or error, not both")
	}
	err = o.transact(ctx, func(tx *orm) error {
		sql := `
		SELECT pipeline_runs.*, pipeline_specs.dot_dag_source "pipeline_spec.dot_dag_source", job_pipeline_specs.job_id "job_id"
		FROM pipeline_runs
		JOIN pipeline_task_runs ON (pipeline_task_runs.pipeline_run_id = pipeline_runs.id)
		JOIN pipeline_specs ON (pipeline_specs.id = pipeline_runs.pipeline_spec_id)
		JOIN job_pipeline_specs ON (job_pipeline_specs.pipeline_spec_id = pipeline_specs.id)
		WHERE pipeline_task_runs.id = $1 AND pipeline_runs.state in ('running', 'suspended')
		FOR UPDATE`
		if err = tx.ds.GetContext(ctx, &run, sql, taskID); err != nil {
			return fmt.Errorf("failed to find pipeline run for task ID %s: %w", taskID.String(), err)
		}

		// Update the task with result
		sql = `UPDATE pipeline_task_runs SET output = $2, error = $3, finished_at = $4 WHERE id = $1`
		if _, err = tx.ds.ExecContext(ctx, sql, taskID, result.OutputDB(), result.ErrorDB(), time.Now()); err != nil {
			return fmt.Errorf("failed to update pipeline task run: %w", err)
		}

		if run.State == RunStatusSuspended {
			start = true
			run.State = RunStatusRunning

			sql = `UPDATE pipeline_runs SET state = $2 WHERE id = $1`
			if _, err = tx.ds.ExecContext(ctx, sql, run.ID, run.State); err != nil {
				return fmt.Errorf("failed to update pipeline run state: %w", err)
			}
		}

		return loadAssociations(ctx, tx.ds, []*Run{&run})
	})

	return run, start, err
}
