Audit Report

## Title
Audit Logger `Authorization` Header Credential Exposed via Unprivileged `/v2/config` Endpoint - (File: core/web/config_controller.go)

## Summary
The `AuditLogger.Headers` configuration value (typically holding an `Authorization` bearer token used to authenticate outbound audit-log POST requests) is stored as plain-text `models.ServiceHeaders` within the general `Config` struct, not the redacted `Secrets` struct, and is returned verbatim by the `GET /v2/config` endpoint to any authenticated user regardless of role.

## Finding Description
`ConfigController.Show` at `core/web/config_controller.go:23-42` returns `cfg.ConfigTOML()`, i.e. the full `inputTOML`/`effectiveTOML` blob defined at `core/services/chainlink/config_general.go:29-32,288-290`. This route is registered at `core/web/router.go:283-285` as `authv2.GET("/config", cc.Show)` — unlike most other routes in the same block (e.g. `uc.Index`, `eia.Create`, `bt.Create`), it is **not wrapped** in `auth.RequiresEditRole` or `auth.RequiresAdminRole`, so only the generic `auth.Authenticate` session/token check applies. This is corroborated by the RBAC test table at `core/web/auth/auth_test.go:236-237`, which marks `/v2/config` and `/v2/config/v2` as accessible with `viewOnlyAllowed=true`.

`AuditLogger.Headers` is defined as `models.ServiceHeaders` (`[]ServiceHeader`) in `core/store/models/common.go:274-348`, wired through `core/services/chainlink/config_audit_logger.go:33-35`, and each `ServiceHeader.MarshalText` at `core/store/models/common.go:289-293` serializes the raw `Header: Value` pair with no redaction — unlike `models.Secret`/`config.SecretString` fields which always marshal as `xxxxx` (`core/store/models/secrets.go:7-12`). The documented intended use is precisely to carry an `Authorization` token (`docs/CONFIG.md:397-401`), and that header value is used verbatim on outbound requests at `core/logger/audit/audit_logger.go:235-237`. Because `AuditLogger.Headers` lives in `Config` (serialized into `inputTOML`/`effectiveTOML`) rather than `Secrets` (serialized separately/redacted), it is included unredacted in the TOML returned by `/v2/config`.

## Impact Explanation
Any authenticated node user — including the lowest-privilege `UserRoleView` role, or an API token scoped for read-only dashboards — can retrieve the operator's audit-log `Authorization` credential via a single `GET /v2/config` request. This falls under key/secret exfiltration: the disclosed token could be replayed to impersonate the node when posting to the configured `ForwardToUrl` SIEM endpoint, or reused if the same credential material is shared with other systems.

## Likelihood Explanation
No privilege escalation or special network position is required. The only precondition is that the operator has configured `AuditLogger.Headers` with a credential-bearing header (a pattern explicitly documented as the intended usage in `CONFIG.md`) and that the requester holds any valid low-privilege session/API token. The route's lack of a `RequiresEditRole`/`RequiresAdminRole` wrapper, confirmed by the auth test matrix, makes this trivially and repeatably reachable.

## Recommendation
Redact `AuditLogger.Headers` values (particularly `Authorization`-style headers) from `ConfigTOML()`/general config serialization, following the `models.Secret`/`SecretString` redaction pattern used elsewhere (e.g., `Database.URL`). Alternatively, move header *values* into the `Secrets` struct, or restrict `GET /v2/config` (and `/v2/config/v2`) to `auth.RequiresAdminRole`.

## Proof of Concept
1. Configure a node with:
```toml
[AuditLogger]
Enabled = true
ForwardToUrl = 'https://siem.example.com/ingest'
Headers = ['Authorization: Bearer sk_live_supersecret123']
```
2. Create a session/API token for a `UserRoleView` user.
3. Send `GET /v2/config` with that credential:
```
curl -H "Cookie: <view-role session>" https://node-host/v2/config
```
4. Observe the JSON `config` field contains the full TOML including the raw `Headers = ['Authorization: Bearer sk_live_supersecret123']` value, confirming disclosure to a low-privilege authenticated user via `ConfigController.Show` (`core/web/config_controller.go:23-42`) and the un-role-gated route registration (`core/web/router.go:283-285`). // ServiceHeader is an HTTP header to include in POST to log service.
type ServiceHeader struct {
	Header string
	Value  string
}

func (h *ServiceHeader) UnmarshalText(input []byte) error {
	parts := strings.SplitN(string(input), ":", 2)
	h.Header = parts[0]
	if len(parts) > 1 {
		h.Value = strings.TrimSpace(parts[1])
	}
	return h.Validate()
}

func (h *ServiceHeader) MarshalText() ([]byte, error) {
	var b bytes.Buffer
	fmt.Fprintf(&b, "%s: %s", h.Header, h.Value)
	return b.Bytes(), nil
}

type ServiceHeaders []ServiceHeader

func (sh *ServiceHeaders) UnmarshalText(input []byte) error {
	if sh == nil {
		return errors.New("Cannot unmarshal to a nil receiver")
	}

	headers := string(input)

	var parsedHeaders []ServiceHeader
	if headers != "" {
		headerLines := strings.SplitSeq(headers, "\\")
		for header := range headerLines {
			keyValue := strings.Split(header, "||")
			if len(keyValue) != 2 {
				return errors.Errorf("invalid headers provided for the audit logger. Value, single pair split on || required, got: %s", keyValue)
			}
			h := ServiceHeader{
				Header: keyValue[0],
				Value:  keyValue[1],
			}

			if err := h.Validate(); err != nil {
				return err
			}
			parsedHeaders = append(parsedHeaders, h)
		}
	}

	*sh = parsedHeaders
	return nil
}

func (sh *ServiceHeaders) MarshalText() ([]byte, error) {
	if sh == nil {
		return nil, errors.New("Cannot marshal to a nil receiver")
	}

	sb := strings.Builder{}
	for _, header := range *sh {
		sb.WriteString(header.Header)
		sb.WriteString("||")
		sb.WriteString(header.Value)
		sb.WriteString("\\")
	}

	serialized := sb.String()

	if len(serialized) > 0 {
		serialized = serialized[:len(serialized)-1]
	}

	return []byte(serialized), nil
}
