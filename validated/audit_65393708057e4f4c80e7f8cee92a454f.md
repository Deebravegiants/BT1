Audit Report

## Title
Unauthenticated Access to Node's LOOP Plugin Debug/PPROF and Metrics Endpoints - (File: core/web/router.go)

## Summary
`loopRoutes` in `core/web/router.go` registers `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` directly on the top-level `api` group, which carries only rate-limiting and session-loading middleware, with no call to `auth.Authenticate(...)`. This is inconsistent with every other sensitive route group (`debugRoutes`, `sessionRoutes`, `v2Routes`), all of which wrap themselves in authentication middleware before exposing internal diagnostic or state-mutating handlers.

## Finding Description
`NewRouter` builds the `api` group with `rateLimiter(...)` and `sessions.Sessions(...)` only, then calls `debugRoutes`, `healthRoutes`, `sessionRoutes`, `v2Routes`, and `loopRoutes` on it directly: [1](#0-0) 

`debugRoutes` gates `/debug/vars` behind `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)`, and `v2Routes` gates most `/v2/*` endpoints (including `metricRoutes`, which exposes the node's own pprof) behind `auth.Authenticate(..., auth.AuthenticateByToken, auth.AuthenticateBySession)`: [2](#0-1) [3](#0-2) 

`loopRoutes`, by contrast, registers its handlers with no authentication wrapper at all: [4](#0-3) 

`pluginPPROFHandler` and `pluginMetricHandler` take attacker-supplied path/query parameters (`:name`, `:profile`, `debug`, `gc`, `seconds`) and forward them to the internal LOOP plugin's `/debug/pprof/<profile>` or `/metrics` endpoint, relaying the raw response back to the caller, with an explicit comment noting these are meant to be "internal btw the node and plugin": [5](#0-4) [6](#0-5) 

The code exactly matches the claim: there is no session/token check anywhere in the `loopRoutes` registration or in `LoopRegistryServer`'s handlers, so any client that can reach the node's HTTP port can invoke these forwarding endpoints without credentials.

## Impact Explanation
An unauthenticated network client can retrieve pprof profiles (goroutine dumps, heap profiles, cmdline, profiling traces) and Prometheus metrics from any registered LOOP plugin via `/plugins/<name>/debug/pprof/*` and `/plugins/<name>/metrics`. This is a CWE-200 information-disclosure issue: goroutine/heap dumps can reveal internal runtime state, stack traces with file paths, and potentially sensitive in-memory data held by plugins, which could aid further attacks against a production Chainlink node.

## Likelihood Explanation
The routes are exposed on the node's main API listener with no authentication requirement — only generic rate limiting — so exploitation requires no credentials and is repeatable by any client with network access to the node's configured port (default `6688`).

## Recommendation
Wrap `loopRoutes` (at minimum the `/plugins/:name/metrics` and `/plugins/:name/debug/pprof/*` routes) in the same `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)` middleware used for `/v2/*` and `/debug/vars`, consistent with how the node's own pprof endpoints (`metricRoutes`) are gated under `authv2`.

## Proof of Concept
Against a running node with a registered LOOP plugin (e.g. `medianpoc`), issue with no session cookie or API token:
```
GET /plugins/medianpoc/debug/pprof/goroutine?debug=2 HTTP/1.1
Host: node-host:6688
```
`pluginPPROFHandler` forwards this unauthenticated request to the internal plugin's pprof endpoint at `http://<loopHostName>:<PrometheusPort>/debug/pprof/goroutine?debug=2` and relays the full response back to the caller — verifiable by adding a Go integration test in `core/web/loop_registry_internal_test.go` that hits the route with no `Authorization`/session cookie set and asserts a `200 OK` with pprof body content, contrasted with a `401`/redirect expected from `/v2/*` or `/debug/vars` under identical unauthenticated conditions.

func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/metrics", l.loopHostName, p.EnvCfg.PrometheusPort)
	req, err := http.NewRequestWithContext(gc.Request.Context(), http.MethodGet, pluginURL, nil)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)
	if err != nil {
		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q metrics", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
