### Title
Requesters cannot reclaim relayer fee refunds via `handlePostRequestTimeouts`/`handleGetRequestTimeouts` while `EvmHost` is frozen for incoming messages - (File: `evm/src/core/HandlerV2.sol`)

### Summary
The Rigor `Community.sol` bug shows that gating a fund-recovery path (`repayLender`, `reduceDebt`, `escrow`) behind a "system not paused" check causes unprivileged users to be unable to settle their obligations while paused, forcing them to accrue avoidable costs (extra interest) with no alternative recovery path. `HandlerV2.sol` in Hyperbridge has the structurally identical pattern: the `notFrozen(host)` modifier blocks **all** incoming-message handlers, including the timeout-refund handlers, whenever `EvmHost.frozen()` returns `FrozenStatus.Incoming` or `FrozenStatus.All`.

### Finding Description
`HandlerV2.sol` defines: [1](#0-0) 

This single modifier is applied uniformly to `handleConsensus`, `handlePostRequests`, `handleGetResponses`, `handlePostRequestTimeouts`, and `handleGetRequestTimeouts`: [2](#0-1) [3](#0-2) 

Both timeout handlers are documented as permissionless, self-service recovery paths for a request that has already been dispatched (and its relayer fee escrowed) by an ordinary application/user: [4](#0-3) 

The actual refund of the escrowed relayer fee happens in `EvmHost.dispatchTimeOut`, which itself has no independent frozen check and relies entirely on being reachable through the handler: [5](#0-4) 

Because `notFrozen` in `HandlerV2` treats `Incoming` (a state meant to stop *new* untrusted inbound message processing, e.g., during a security incident) the same as it treats timeout processing for a user's *own, previously-dispatched* outgoing request, freezing incoming traffic incidentally also blocks the unrelated self-help mechanism that lets a requester reclaim funds already committed. This mirrors the Rigor pattern exactly: `pauseProtocol` (a legitimate protective control, not necessarily malicious) collaterally disables the specific mechanism users need to avoid ongoing loss (interest in Rigor, an un-refunded relayer fee here), and there is no alternate code path to recover funds while frozen.

### Impact Explanation
While `EvmHost.frozen()` is `Incoming` or `All`, a dispatcher who paid a relayer fee for a POST/GET request that later times out cannot execute `handlePostRequestTimeouts` / `handleGetRequestTimeouts` to reclaim that fee via `EvmHost.dispatchTimeOut`. The fee remains locked in the `feeToken` balance of `EvmHost` for the entire duration of the freeze, with no alternative withdrawal path available to the requester. If the freeze period is prolonged (e.g., a long-running incident response or governance dispute over unfreezing), this constitutes a temporary-to-indefinite freezing of user funds that the requester has no way to mitigate, analogous to builders being unable to repay lenders and thus accruing forced additional interest during a Rigor pause.

### Likelihood Explanation
Freezing is an expected operational lever for the protocol (it exists specifically to be invoked during abnormal conditions), so the precondition is realistic and not contingent on an attacker compromising governance — it is a normal, foreseeable state transition of the system, exactly like Rigor's `pauseProtocol`. Any user who dispatched a request with a nonzero fee and whose request times out during a freeze window is affected, making the likelihood of triggering the impact moderate whenever a freeze coincides with pending timeouts.

### Recommendation
Scope the `notFrozen` check in `HandlerV2` timeout handlers (`handlePostRequestTimeouts`, `handleGetRequestTimeouts`) to not treat `Incoming` freezes as blocking, or introduce a distinct `FrozenStatus` value that halts new inbound request/response dispatch without blocking timeout-driven fee refunds for the caller's own already-committed requests. Alternatively, only prevent timeout refund processing while `FrozenStatus.All` is active, and clearly document that `Incoming`-only freezes must not stall user fund recovery.

### Proof of Concept
1. Application `A` calls `EvmHost.dispatch(post)` with `post.fee > 0`; `EvmHost` escrows the fee and stores `FeeMetadata{sender: payer, fee}` in `_requestCommitments` (evm/src/core/EvmHost.sol:921-959).
2. Governance/admin sets `frozen = FrozenStatus.Incoming` (or `All`) via the host's freeze mechanism to respond to an unrelated incident.
3. The dispatched request times out (`timeoutTimestamp` elapses) before being delivered.
4. A relayer or the payer attempts `HandlerV2.handlePostRequestTimeouts(host, message)` to trigger `EvmHost.dispatchTimeOut`, which would refund `meta.fee` to `meta.sender` (evm/src/core/EvmHost.sol:885-906).
5. The call reverts with `HostFrozen()` due to the `notFrozen(host)` modifier (evm/src/core/HandlerV2.sol:106-112, 254-260), since `frozen()` returns `Incoming`/`All`.
6. The payer's fee remains stuck in `EvmHost` for as long as the freeze persists, with no other function available to reclaim it.

    function handlePostRequestTimeouts(IHost host, PostRequestTimeoutMessage calldata message)
        external
        notFrozen(host)
    {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            PostRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            // known request? also serves as source check
            bytes32 requestCommitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(requestCommitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(REQUEST_RECEIPTS_STORAGE_PREFIX, requestCommitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(PostRequestTimeout(request, _msgSender()), meta, requestCommitment);
        }
    }

### handlePostRequestTimeouts()

Processes timed-out POST requests and triggers refunds.

```solidity lineNumbers
function handlePostRequestTimeouts(
    IHost host,
    PostRequestTimeoutMessage calldata message
) external
```

| Parameter | Type | Description |
|-----------|------|-------------|
| `host` | `IHost` | The IHost contract |
| `message` | `PostRequestTimeoutMessage` | Struct containing timeout proof and requests |

**Access:** Permissionless (can be called by anyone)

**Process:**
1. Verifies timeout proof
2. For each request:
   - Validates timeout timestamp has passed
   - Calls `onPostRequestTimeout()` on source application
   - Refunds relayer fee to payer (only if callback succeeds)

**Important:**
- Application timeout callback is called **before** refund
- If callback reverts, no refund occurs
- Timeout can be resubmitted until callback succeeds

**Reverts:**
- `MessageNotTimedOut()` - Timeout period not elapsed
- `UnknownMessage()` - Request not found

    function dispatchTimeOut(
        PostRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onPostRequestTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit PostRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }
