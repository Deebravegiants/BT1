### Title
`canGraduate`'s unguarded external call to the reserve LT's `exchangeRate()` can permanently DoS every buy and sell of a curve token - (File: `packages/contracts/src/Bonding.sol`)

### Summary
`Bonding.canGraduate` (called on every curve buy via `_executeBuy` and on every curve sell / graduation attempt via `Zap._sellInternal` / `triggerGraduation`) makes a direct, un-try/catch'd external call to the third-party BounceTech LT's `exchangeRate()`. This is structurally the same single-point-of-failure pattern as the referenced report: one external contract's revert propagates and bricks the caller's entire critical-path transaction. Unlike the C4 finding, alt.fun has no admin escape hatch (no `setSponsorVault`-equivalent to swap or bypass a broken LT for an already-launched token), so the resulting DoS is not "temporary" but effectively permanent for that token's curve trading.

### Finding Description
`canGraduate` is a `public view` used unconditionally in the hot buy/sell paths: [1](#0-0) 

It calls `IBounceLeveragedToken(info.ltAddress).exchangeRate()` directly, with no `try/catch`:
```solidity
uint256 valueUsd = (realLtRaised * IBounceLeveragedToken(info.ltAddress).exchangeRate()) / 1e18;
```

This is invoked in three unprivileged, permissionless entry points:
1. `Bonding._executeBuy` — runs at the end of *every* curve buy (`Router.buy` result is followed unconditionally by `if (canGraduate(tokenAddress)) { _enterGraduating(tokenAddress); }`): [2](#0-1) 

2. `Zap._sellInternal` — calls `bonding_.canGraduate(tokenAddress)` before every curve sell: [3](#0-2) 

3. `Bonding.triggerGraduation` — the permissionless standalone graduation trigger also calls `canGraduate`: [4](#0-3) 

If the LT's `exchangeRate()` reverts (a bug, a paused/bricked internal accounting state, or any other failure mode in the third-party BounceTech contract, which the codebase's own comments acknowledge as an external dependency that can misbehave — see the "Retired LTs" and mint-pausable discussions), every one of these three call paths reverts as well, because the external call is unguarded. Since `_executeBuy` and `_sellInternal` are the only ways an unprivileged user can trade a curve token, and `triggerGraduation` is the only permissionless way to force graduation, all three become simultaneously and completely unusable.

Critically, `ltAddress` is set once at launch and is immutable per token — `Bonding` has no admin setter to redirect a live curve token to a different LT or otherwise route around a broken `exchangeRate()` call. This differs from the referenced report's `SponsorVault`, which had a `setSponsorVault` recovery path making the DoS temporary; here, once `exchangeRate()` starts reverting there is no recovery, so the token's curve-phase funds (both traders' locked LT reserves and the creator's/protocol's future fee stream, plus any path to graduation and the DEX) are frozen indefinitely.

### Impact Explanation
For any curve-phase token, a single failure of `exchangeRate()` on the paired BounceTech LT:
- Blocks every `Zap.buy` (and its permit variant) for that token, permanently freezing new capital inflows.
- Blocks every `Zap.sell` (and its permit variant) for that token, freezing all traders' ability to exit to USDC via the curve.
- Blocks `Bonding.triggerGraduation`, so the token can never reach `Lifecycle.Graduating`/`Graduated` even if it would otherwise qualify, permanently trapping the LT already raised in the curve `Pair` and the 250M `lpReserve` tokens held in `Bonding`.

This satisfies the "permanent freezing of trader, creator, or LP funds" impact bar: all USDC/LT/token liquidity associated with that curve is stuck with no on-chain recovery path, since the LT address binding is immutable and there is no fail-safe around the `exchangeRate()` call.

### Likelihood Explanation
The LT is an external, third-party (BounceTech) contract that the protocol's own documentation treats as a non-trivial dependency subject to failure modes (mint-pausing, de-registration/redeploy, streaming-fee checkpoint quirks). `exchangeRate()` is a simple view, so a revert would typically stem from an implementation bug, an upgrade regression, or an unexpected internal state (e.g., division by a zero `totalSupply`, or a revert introduced by a future BounceTech upgrade) in that external contract — plausible over the lifetime of many independently-created LTs, especially since `Bonding.launch` is permissionless with respect to which whitelisted LT a creator pairs against. Given there are many concurrently-live curve tokens each pointing at potentially different LTs, the aggregate probability that at least one LT's `exchangeRate()` starts reverting is non-negligible, and the effect is total and un-recoverable for that token as soon as it happens.

### Recommendation
Wrap the external `exchangeRate()` call inside `canGraduate` (and any other externally-facing read of the LT used on the hot trading path) in a `try/catch`, treating a revert as "USD trigger not satisfied" (fall through to the supply-trigger check) rather than propagating the revert. This preserves the ability to buy/sell/trigger graduation via the supply trigger and via `redeem`, mirroring the recommended fix pattern in the referenced report. Additionally, consider giving governance an emergency mechanism to force-graduate or otherwise release a curve whose paired LT has become permanently non-functional, so that funds are not solely dependent on the correctness of a third-party contract with no admin-level recovery.

### Proof of Concept
1. A creator launches a token via `Zap.createToken` paired with LT `L` (a whitelisted BounceTech LT that currently behaves correctly).
2. Users buy/sell normally through `Zap.buy` / `Zap.sell`; every call to `_executeBuy` / `_sellInternal` succeeds because `L.exchangeRate()` returns normally.
3. `L`'s internal accounting enters a state where `exchangeRate()` reverts (e.g., a division-by-zero on `totalAssets/totalSupply` after some LT-internal drain, or any other bug/upgrade regression in BounceTech's contract) — this is entirely outside alt.fun's control since `L` is a third-party contract referenced only by its immutable address.
4. Any subsequent call to `Zap.buy(tokenAddress, ...)` for this token reaches `Bonding._executeBuy` → `canGraduate(tokenAddress)` → `IBounceLeveragedToken(L).exchangeRate()`, which reverts, causing the whole buy transaction to revert.
5. Any subsequent call to `Zap.sell(tokenAddress, ...)` reaches `_sellInternal` → `bonding_.canGraduate(tokenAddress)`, which also reverts, blocking sells.
6. `Bonding.triggerGraduation(tokenAddress)` likewise reverts via the same `canGraduate` call, so the token can never be forced into `Lifecycle.Graduating`.
7. Because `info.ltAddress` is immutable and there is no admin function to change it or bypass `canGraduate`, the token's curve is permanently stuck: no buys, no sells, no graduation — all curve-held LT and the 250M `lpReserve` are frozen indefinitely. [1](#0-0) [2](#0-1) [5](#0-4) [4](#0-3)

    function canGraduate(
        address token_
    ) public view returns (bool) {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[token_];
        if (info.creator == address(0)) return false;
        if (info.lifecycle != Lifecycle.Curve) return false;

        address pair = info.pair;
        if (IPair(pair).tokenBalance() == 0) return true;

        (, uint256 assetReserve) = IPair(pair).getReserves();
        uint256 realLtRaised = assetReserve - _launchTimeVirtualLtReserve(token_, pair);
        uint256 valueUsd = (realLtRaised * IBounceLeveragedToken(info.ltAddress).exchangeRate()) / 1e18;
        return valueUsd >= $.graduationThresholdUsd;
    }

    function triggerGraduation(
        address tokenAddress
    ) external nonReentrant {
        TokenInfo storage info = _s().tokenInfo[tokenAddress];
        if (info.creator == address(0)) revert TokenNotTrading();
        if (info.lifecycle == Lifecycle.Graduating) revert TokenIsGraduating();
        if (info.lifecycle != Lifecycle.Curve) revert TokenNotTrading();
        if (!canGraduate(tokenAddress)) revert NotGraduatable();
        _enterGraduating(tokenAddress);
    }

    function _sellInternal(
        address tokenAddress,
        uint256 tokenAmount,
        uint256 minUsdcOut
    ) internal returns (uint256 usdcOut) {
        if (tokenAmount == 0) revert InvalidInput();
        if (tokenAddress == address(0)) revert InvalidInput();
        ZapStorage storage $ = _s();
        Bonding bonding_ = $.bonding;
        if (bonding_.creatorOf(tokenAddress) == address(0)) revert TokenNotTrading();
        if (bonding_.isGraduating(tokenAddress)) revert TokenIsGraduating();

        // LT appreciation can push a curve token past the graduation threshold
        // with no buy. Selling now would drag the raised reserve back below it,
        // so graduate the token instead. The holder keeps their tokens and
        // exits on the graduated pool. Nothing is sold, so this fills `0` — only
        // take it when the caller set no floor; a positive `minUsdcOut` reverts
        // so the `usdcOut >= minUsdcOut` guarantee is never silently broken.
        if (bonding_.canGraduate(tokenAddress)) {
            if (minUsdcOut != 0) revert TokenIsGraduating();
            bonding_.triggerGraduation(tokenAddress);
            return 0;
        }
