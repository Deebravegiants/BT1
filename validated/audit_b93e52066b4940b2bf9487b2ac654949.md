## Finding

### Title
Operator beneficiary redirection is bypassed for commission distributions recorded under a stale operator address after `switch_operator` - (File: `aptos-move/framework/aptos-framework/sources/staking_contract.move`)

### Summary
`staking_contract::distribute_internal` redirects an operator's commission payout to the operator's configured beneficiary (`BeneficiaryForOperator`) only when the distribution-pool `recipient` equals the *current* `operator` parameter passed into the function. When a staker calls `switch_operator`, any commission that was already recorded (via `add_distribution`) but not yet unlocked at switch time keeps the **old operator's address** as its `distribution_pool` recipient key, while the `StakingContract` (and its `distribution_pool`) is subsequently re-keyed under the **new operator**. Once that pending amount becomes withdrawable and someone later calls `distribute`/`request_commission` for the new operator, `distribute_internal` is invoked with `operator = new_operator`, so the stale `recipient == old_operator` never matches `operator`, and the beneficiary redirect is skipped — the funds are paid straight to the old operator's raw account instead of the beneficiary address the old operator explicitly configured.

### Finding Description
The custody-relevant control here is `BeneficiaryForOperator`, set via `set_beneficiary_for_operator`, which is meant to guarantee that all commission owed to an operator is delivered to a chosen beneficiary address rather than the operator's own account: [1](#0-0) 

Commission is recorded into `staking_contract.distribution_pool` keyed by the operator address at the time it accrues: [2](#0-1) [3](#0-2) 

`switch_operator` calls `distribute_internal` (for already-inactive stake) and then `request_commission_internal` (which unlocks newly accrued, but not-yet-withdrawable, commission and records it in `distribution_pool` under `old_operator`), before moving the `StakingContract` under the `new_operator` key: [4](#0-3) 

The bug is in the redirect check inside `distribute_internal`, which compares the pool's `recipient` to the function's `operator` argument (the *current* operator looked up from the table) rather than checking whether `recipient` itself has a registered beneficiary: [5](#0-4) 

Because the `distribution_pool` can legitimately still contain a shareholder entry for `old_operator` (recorded before the switch, but not yet paid because the stake was still `pending_inactive`), any later `distribute(staker, new_operator)` call passes `operator = new_operator`, so `recipient (== old_operator) == operator (== new_operator)` is false, and the coins are deposited directly to `old_operator`'s address via `aptos_account::deposit_coins(recipient, ...)`, completely skipping `beneficiary_for_operator(old_operator)`.

### Impact Explanation
This breaks the custody invariant that operator commission must always be routed to the operator's configured beneficiary. In real staking setups the beneficiary is often used specifically to keep commission payouts on a secure/cold address distinct from the operator's hot signing key. This bug silently strands the redirect for any commission that happens to be "in flight" (already unlocked-requested but not yet inactive) at the exact moment `switch_operator` executes, sending real APT rewards to the operator's raw account instead of the intended custody address — a supply/custody accounting corruption that delivers value to the wrong holder.

### Likelihood Explanation
Requires: (1) `operator_beneficiary_change_enabled` feature and a beneficiary set for the operator, (2) commission that has been requested/unlocked (`pending_inactive`) but not yet finalized as `inactive`, and (3) a `switch_operator` call by the staker occurring in that window, followed by a later `distribute`/`request_commission` call once the lockup ends. This is a plausible, staker-triggerable ordering (the staker fully controls when `switch_operator` is called) rather than a contrived edge case, but it does require this specific timing, making it Medium likelihood.

### Recommendation
In `distribute_internal`, the beneficiary redirect should be based on whether `recipient` itself (not the current `operator` parameter) has a `BeneficiaryForOperator` entry, e.g. replace:
```
if (recipient == operator) {
    recipient = beneficiary_for_operator(operator);
};
```
with a check that always resolves `recipient` through `beneficiary_for_operator(recipient)` when `recipient` corresponds to any operator address (current or historical) that has a beneficiary registered, ensuring stranded pre-switch commission entries are still routed correctly.

### Proof of Concept
1. Operator `O1` calls `set_beneficiary_for_operator(B)` (feature enabled).
2. Rewards accrue on the stake pool under staking contract `(staker, O1)`.
3. Staker calls `switch_operator(staker, O1, O2, new_commission)`:
   - `distribute_internal(staker, O1, sc)` pays out any already-inactive stake correctly to `B` (operator == recipient matches here).
   - `request_commission_internal(O1, sc)` computes newly accrued commission, calls `add_distribution(O1, sc, O1, commission_amount)` (buys shares for recipient `O1`), and calls `stake::unlock_with_cap` — this commission is now `pending_inactive`, not yet paid.
   - `stake::set_operator_with_cap(O2)`; the `StakingContract` (with its `distribution_pool` entry for `O1`) is moved to be keyed by `O2`.
4. Wait for the lockup to expire so the pending commission becomes `inactive`.
5. Anyone calls `distribute(staker, O2)` → `distribute_internal(staker, O2, sc)`.
   - `distribution_pool.shareholders()` includes `O1`.
   - Check `if (recipient == operator)` → `O1 == O2` is false.
   - Coins for `O1`'s pending commission are deposited directly to `O1`, not to `B`.

Expected: commission for `O1` should always be delivered to `beneficiary_for_operator(O1) == B`. Actual: it is delivered to `O1` directly, bypassing the configured beneficiary.

    fun request_commission_internal(
        operator: address,
        staking_contract: &mut StakingContract,
    ): u64 {
        // Unlock just the commission portion from the stake pool.
        let (total_active_stake, accumulated_rewards, commission_amount) =
            get_staking_contract_amounts_internal(staking_contract);
        staking_contract.principal = total_active_stake - commission_amount;

        // Short-circuit if there's no commission to pay.
        if (commission_amount == 0) {
            return 0
        };

        // Add a distribution for the operator.
        add_distribution(
            operator,
            staking_contract,
            operator,
            commission_amount
        );

        // Request to unlock the commission from the stake pool.
        // This won't become fully unlocked until the stake pool's lockup expires.
        stake::unlock_with_cap(commission_amount, &staking_contract.owner_cap);

        let pool_address = staking_contract.pool_address;
        emit(
            RequestCommission {
                operator,
                pool_address,
                accumulated_rewards,
                commission_amount
            }
        );

        commission_amount
    }

    public entry fun switch_operator(
        staker: &signer,
        old_operator: address,
        new_operator: address,
        new_commission_percentage: u64
    ) acquires Store, BeneficiaryForOperator {
        let staker_address = signer::address_of(staker);
        assert_staking_contract_exists(staker_address, old_operator);

        assert!(
            new_commission_percentage <= 100,
            error::invalid_argument(EINVALID_COMMISSION_PERCENTAGE)
        );
        // Merging two existing staking contracts is too complex as we'd need to merge two separate stake pools.
        let store = borrow_global_mut<Store>(staker_address);
        let staking_contracts = &mut store.staking_contracts;
        assert!(
            !staking_contracts.contains_key(&new_operator),
            error::invalid_state(ECANT_MERGE_STAKING_CONTRACTS)
        );

        let (_, staking_contract) = staking_contracts.remove(&old_operator);
        // Force distribution of any already inactive stake.
        distribute_internal(
            staker_address,
            old_operator,
            &mut staking_contract,
        );

        // For simplicity, we request commission to be paid out first. This avoids having to ensure to staker doesn't
        // withdraw into the commission portion.
        request_commission_internal(
            old_operator,
            &mut staking_contract,
        );

        // Update the staking contract's commission rate and stake pool's operator.
        stake::set_operator_with_cap(&staking_contract.owner_cap, new_operator);
        staking_contract.commission_percentage = new_commission_percentage;

        let pool_address = staking_contract.pool_address;
        staking_contracts.add(new_operator, staking_contract);
        emit(SwitchOperator { pool_address, old_operator, new_operator });
    }

    /// Allows an operator to change its beneficiary. Any existing unpaid commission rewards will be paid to the new
    /// beneficiary. To ensures payment to the current beneficiary, one should first call `distribute` before switching
    /// the beneficiary. An operator can set one beneficiary for staking contract pools, not a separate one for each pool.
    public entry fun set_beneficiary_for_operator(
        operator: &signer, new_beneficiary: address
    ) acquires BeneficiaryForOperator {
        assert!(
            features::operator_beneficiary_change_enabled(),
            std::error::invalid_state(EOPERATOR_BENEFICIARY_CHANGE_NOT_SUPPORTED)
        );
        // The beneficiay address of an operator is stored under the operator's address.
        // So, the operator does not need to be validated with respect to a staking pool.
        let operator_addr = signer::address_of(operator);
        let old_beneficiary = beneficiary_for_operator(operator_addr);
        if (exists<BeneficiaryForOperator>(operator_addr)) {
            borrow_global_mut<BeneficiaryForOperator>(operator_addr).beneficiary_for_operator =
                new_beneficiary;
        } else {
            move_to(
                operator,
                BeneficiaryForOperator { beneficiary_for_operator: new_beneficiary }
            );
        };

        emit(
            SetBeneficiaryForOperator {
                operator: operator_addr,
                old_beneficiary,
                new_beneficiary
            }
        );
    }

        operator: address,

        recipient: address,
