This is a confirmed pattern gap: every other flow that accepts a raw, caller-supplied `shop` string and then uses it to build the host that receives `client_id`/`client_secret` calls `Utils::ShopValidator.sanitize!(shop)` first — `ClientCredentials.client_credentials` [1](#0-0) , `RefreshToken.refresh_access_token` [2](#0-1) , and `TokenExchange.migrate_to_expiring_token` [3](#0-2) . But `Oauth.begin_auth` builds the authorization redirect URL directly from the caller-supplied `shop` with no call to `ShopValidator` anywhere in `oauth.rb`.

### Title
Unvalidated `shop` parameter in `Oauth.begin_auth` allows attacker-controlled OAuth authorization host - (File: `lib/shopify_api/auth/oauth.rb`)

### Summary
`ShopifyAPI::Auth::Oauth.begin_auth` accepts a `shop:` string and passes it straight into `auth_base_uri(shop)` to build the URL the user's browser is redirected to for OAuth authorization, without validating that `shop` is a genuine Shopify domain, unlike sibling methods that always call `Utils::ShopValidator.sanitize!` on caller-supplied shop values.

### Finding Description
`begin_auth` takes the `shop` argument and builds the redirect target with no sanitization: [4](#0-3) 
The `shop` value flows unchecked into `auth_base_uri`: [5](#0-4) 

Compare this to `ClientCredentials.client_credentials`, `RefreshToken.refresh_access_token`, and `TokenExchange.migrate_to_expiring_token`, which all call `validated_shop = Utils::ShopValidator.sanitize!(shop)` before building a `Session`/`HttpClient` from a caller-supplied shop string [1](#0-0) [2](#0-1) [3](#0-2) . `ShopValidator` exists precisely to reject non-Shopify hosts, including confusable domains like `test-shop.notmyshopify.com` or `myshopify.com.evil.com` [6](#0-5) , and the test suite explicitly documents this as a defense against "attacker controlled domain" input [7](#0-6) . `Oauth.begin_auth` is the one entry point in this family that receives raw external input (documented as coming straight from an inbound request, e.g. `shop = request.headers["Shop"]`) yet is the one that skips this validation entirely [8](#0-7) .

### Impact Explanation
If a value like `shop.notmyshopify.com`, `myshopify.com.evil.com`, or any other confusable/attacker-controlled string reaches `begin_auth` (this is the documented, expected calling pattern — passing a raw request-supplied shop into `begin_auth`), the generated `auth_route` will point the merchant's browser at `https://<attacker-controlled-host>/admin/oauth/authorize?client_id=...&redirect_uri=...&state=...`. The `state` nonce (also placed in a cookie the library returns) and `client_id` are sent to a host the attacker controls, enabling an attacker to intercept/replace the authorization flow (forced OAuth completion) and, depending on how the calling application handles the flow, control what code/state get echoed back to `validate_auth_callback`. This falls under the "session fixation or forced OAuth completion" High-impact category, since it undermines the confidentiality/integrity of the initial leg of the OAuth exchange despite `validate_auth_callback` later checking HMAC and state equality.

### Likelihood Explanation
This does not require the `api_secret_key`, an access token, or privileged access — only the ability to influence the `shop` value passed into `begin_auth`, which per this gem's own documented usage pattern comes directly from an unauthenticated inbound request header/query parameter. No other gem method in the same family (`client_credentials`, `refresh_access_token`, `migrate_to_expiring_token`) omits this check, indicating the omission in `begin_auth` is an inconsistency/gap rather than an intentional design choice.

### Recommendation
Call `Utils::ShopValidator.sanitize!(shop)` (or `sanitize_shop_domain`) at the top of `Oauth.begin_auth` before deriving `auth_base_uri`, consistent with `ClientCredentials`, `RefreshToken`, and `TokenExchange.migrate_to_expiring_token`, and raise `Errors::InvalidShopError` for non-trusted domains.

### Proof of Concept
1. Host application implements the documented pattern: `shop = request.headers["Shop"]; ShopifyAPI::Auth::Oauth.begin_auth(shop: shop, redirect_path: "/auth/callback")` [9](#0-8) .
2. Attacker sends a request with `Shop: evil.example.com`.
3. `begin_auth` computes `auth_route = auth_base_uri("evil.example.com") + "/oauth/authorize?client_id=...&state=...&redirect_uri=..."`, i.e. `https://evil.example.com/admin/oauth/authorize?...` [10](#0-9) [11](#0-10) .
4. The victim's browser is redirected to the attacker's host with the app's `client_id` and freshly-minted `state` nonce, which the attacker's server can capture and use to attempt to complete/forge the OAuth handshake back at the legitimate callback endpoint.

        def begin_auth(shop:, redirect_path:, is_online: true, scope_override: nil)
          scope = if scope_override.nil?
            ShopifyAPI::Context.scope
          elsif scope_override.is_a?(ShopifyAPI::Auth::AuthScopes)
            scope_override
          else
            ShopifyAPI::Auth::AuthScopes.new(scope_override)
          end

          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = SecureRandom.alphanumeric(NONCE_LENGTH)

          cookie = SessionCookie.new(value: state, expires: Time.now + 60)

          query = {
            client_id: ShopifyAPI::Context.api_key,
            scope: scope.to_s,
            redirect_uri: "#{ShopifyAPI::Context.host}#{redirect_path}",
            state: state,
            "grant_options[]": is_online ? "per-user" : "",
          }

          query_string = URI.encode_www_form(query)
          auth_route = auth_base_uri(shop) + "/oauth/authorize?#{query_string}"

          { auth_route: auth_route, cookie: cookie }
        end

        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end

    auth_response = ShopifyAPI::Auth::Oauth.begin_auth(shop: domain, redirect_path: "/auth/callback")
