Found a real analog in the older/tron `IntentGatewayV2.sol` implementation.

### Title
Fallback-to-self `instance()` combined with unauthenticated 20-byte `from` allows spoofed cross-chain messages from unregistered chains - (File: `evm/tron/contracts/apps/IntentGatewayV2.sol`)

### Summary
`evm/src/apps/intentsv2/IntentsBase.sol`'s `_instance()` correctly reverts with `UnknownInstance` when a peer gateway is not registered for a given `stateMachineId` [1](#0-0) . However, the separate, still-present `evm/tron/contracts/apps/IntentGatewayV2.sol` implementation's `instance()` does the opposite: for any state machine with no registered `_instances` entry, it silently falls back to `address(this)` instead of reverting [2](#0-1) .

### Finding Description
`authenticate()` in this contract checks only that the 20 bytes decoded from `request.from` equal whatever `instance(request.source)` returns: [3](#0-2) 

Because `instance()` returns `address(this)` whenever `_instances[keccak256(stateMachineId)]` is unset (rather than reverting, as the newer `IntentsBase._instance` does), this authentication check becomes trivially satisfiable for *any unregistered source chain*: an attacker only needs `request.from` to equal the gateway's own address, i.e. `abi.encodePacked(address(this))`. This is exactly the RocketPool bug-class: a lookup for a peer/contract address silently returns a non-error sentinel (here, `address(this)` instead of `address(0x0)`) when the entry was never set, and the caller treats that sentinel as if it were a legitimately configured value, defeating the intended authorization check.

Contrast with the guarded pattern already adopted in `IntentsBase._instance`, which requires the entry to be explicitly registered and reverts with `UnknownInstance` otherwise [4](#0-3) .

### Impact Explanation
`onAccept` on this gateway dispatches based on `RequestKind` decoded from the request body once `authenticate` passes, including `RedeemEscrow` (release escrowed input tokens to a solver) and other governance/administrative actions gated only by this from/source check. Any relayer able to get the ISMP host to call `onAccept` for a POST request whose `source` state machine has never had a peer registered (any chain not yet configured as an IntentGateway deployment) can forge `request.from = abi.encodePacked(address(gatewayContract))` and pass authentication, then trigger `RedeemEscrow`/other privileged request kinds against real escrowed funds. This is a theft-of-funds / forged-message-delivery vector reachable by an unprivileged relayer delivering a single crafted message.

### Likelihood Explanation
Exploitability depends on (a) whether `evm/tron/contracts/apps/IntentGatewayV2.sol` is the live/deployed variant on Tron (versus the newer `evm/src/apps/intentsv2/*` gateway used on EVM chains) and (b) whether there exists at least one state machine ID that is a legitimate ISMP source but has no `_instances` entry registered for this Tron gateway. Given the module explicitly documents itself as "the IntentGateway contract instance for a chain" with mapping-based per-chain registration, and given peer registration happens incrementally (`NewDeployment` action), there will routinely be unregistered source chains during rollout, making this reachable without any privileged action by the attacker — only a valid ISMP-delivered POST request with a forged `from` field is needed.

### Recommendation
Change `instance()` in `evm/tron/contracts/apps/IntentGatewayV2.sol` to revert (e.g. with `UnknownInstance`) when `_instances[keccak256(stateMachineId)] == address(0)`, matching the pattern already used in `IntentsBase._instance()`, instead of falling back to `address(this)`. Audit all other callers of `instance()`/`authenticate()` in this file to ensure they don't rely on the fallback-to-self behavior for legitimate same-contract flows before tightening it.

### Proof of Concept
1. Identify a `stateMachineId` (source chain) for which the Tron `IntentGatewayV2` has no `_instances` entry registered.
2. Have (or induce) the ISMP host deliver a `PostRequest` with `source = <that unregistered stateMachineId>`, `from = abi.encodePacked(address(gatewayContractItself))`, and `to` addressed to the gateway.
3. `authenticate()` computes `instance(request.source)`, which returns `address(this)` (the fallback) since no entry is registered — this equals `module = address(bytes20(request.from))`, so the check passes.
4. `onAccept` proceeds to decode `RequestKind` from the forged body and executes attacker-chosen actions (e.g., `RedeemEscrow`) against real escrow balances, as if the message legitimately originated from a registered peer gateway.

     * @dev Checks that the request originates from a known instance of the IntentGateway.
     */
    function authenticate(PostRequest calldata request) internal view {
        if (request.from.length != 20) revert InvalidInput();
        address module = address(bytes20(request.from));
        // IntentGateway only accepts incoming assets from itself or known instances
        if (instance(request.source) != module) revert Unauthorized();
    }
