Based on the investigation, the strongest reachable analog is the **magic operator QR-code handling** in `orb-core`, where physically presenting a specially-crafted QR code to the operator-facing camera triggers privileged device state changes (mirror recalibration reset, Wi-Fi credential reset) with **no backend authentication or authorization check** — directly analogous to the report's "publicly exposed functions" bug class (unauthenticated state-mutating calls).

### Title
Unauthenticated privileged device actions via "magic" operator QR-codes - (File: src/plans/qr_scan/operator.rs, src/plans/mod.rs)

### Summary
The operator QR-code scanning path accepts two special "magic" codes — `magic_action:reset_wifi_credentials` and `magic_action:reset_mirror_calibration` — and executes privileged device actions (mirror calibration reset, Wi-Fi network reset) immediately upon scan, without any backend validation, operator authentication, or signature check, unlike the normal operator QR-code flow which requires backend verification via `verify_operator_qr_code`.

### Finding Description
`qr_scan::operator::Data::try_parse` first attempts to parse a normal operator QR-code (`userid:...`) and, if that fails, matches against `MAGIC_QR_CODE` regex, returning `Data::MagicResetWifi` or `Data::MagicResetMirror` for any string of the form `magic_action:reset_wifi_credentials` / `magic_action:reset_mirror_calibration`: [1](#0-0) 

These variants are dispatched in `handle_magic_operator_qr_code`, which runs `reset_mirror_calibration` or `reset_wifi_and_ensure_network` directly and returns `Ok(None)` — bypassing `verify_operator_qr_code` (the backend HTTP validation step used for normal operator codes): [2](#0-1) 

Critically, `handle_magic_operator_qr_code` is invoked directly on the raw scan result from `scan_operator_qr_code`, *before* any backend validity check is performed, both in `scan_initial_qr_codes` and `scan_remaining_qr_codes`: [3](#0-2) [4](#0-3) 

By contrast, a *normal* operator QR-code (`Data::Normal`) must still pass through `verify_operator_qr_code`, which calls the backend `/api/v1/distributor/.../status` endpoint and only proceeds if the backend reports `valid: true`: [5](#0-4) [6](#0-5) 

The magic QR-code path has no equivalent check — anyone able to present a QR code to the orb's operator-facing camera (a normal, unprivileged interaction channel, not a hardware-tampering or physical-teardown attack) can trigger `reset_mirror_calibration` or `reset_wifi_and_ensure_network` at will.

### Impact Explanation
- `MagicResetWifi` invokes `network::reset()` followed by `wifi::Plan.ensure_network_connection(orb)`, which (per its usage in the normal WiFi provisioning flow: `src/plans/qr_scan/wifi.rs`, `src/network/mecard.rs`) causes the orb to disconnect from its current network and prompt for a new WiFi QR-code (MECARD format) to reconnect. An attacker with no privileges could force the orb off its legitimate network and, if reachable, provide their own WiFi MECARD QR-code to redirect the orb onto an attacker-controlled network — a foothold for network-level interference with backend communication (signup requests, biometric key exchange, orb-relay messages), though TLS/cert-pinning (seen in `orb-relay-client` and `orb_security_utils::reqwest`) would need to be independently bypassed for full MITM.
- `MagicResetMirror` invokes `reset_mirror_calibration`, degrading or interrupting the mirror positioning system used for iris capture, causing signup/service disruption (denial of service) for legitimate operators/users at that orb, repeatable at will by any passerby with a printed QR code.

This maps to the same root-cause class as the original report: state-mutating operations reachable without any authorization boundary. Unlike the original Solidity report (financial-pool state), the orb-core impact is primarily availability/integrity of the signup process and a network-redirection foothold, not biometric data disclosure or forged attestation — I could not confirm (given tool-call limits) whether this magic-QR path can be chained further into biometric data exposure or signup misattribution; that would require deeper tracing of `wifi::Plan.ensure_network_connection` and `network::reset()` implementations, which I was not able to fully inspect.

### Likelihood Explanation
High: the attack requires only printing/displaying a short static string (`magic_action:reset_wifi_credentials` or `magic_action:reset_mirror_calibration`) as a QR code and presenting it to the orb's operator-facing camera during the idle/operator-scan phase — no credentials, no operator badge, no backend account, and no physical device tampering are required. The regex and dispatch logic are hard-coded and always active regardless of feature flags (unlike `allow-plan-mods` or `skip-user-qr-validation`, which are compile-time gated and out of scope).

### Recommendation
Require the magic QR-code payload to be authenticated (e.g., signed by the backend, or validated in the same way as `verify_operator_qr_code`) before executing `reset_mirror_calibration` or `reset_wifi_and_ensure_network`, or restrict magic-action execution to sessions where a valid, backend-verified operator QR-code has already been presented.

3. Observe that `qr_scan::operator::Data::try_parse` matches `MAGIC_QR_CODE`, `handle_magic_operator_qr_code` executes the reset action immediately, with no backend call and no operator authentication, per: [2](#0-1)

/// Operator QR-code data.
#[derive(Clone, Debug)]
pub enum Data {
    /// Normal Operator QR-code.
    Normal(user::Data),
    /// Action to reconfigure WiFi.
    MagicResetWifi,
    /// Action to reset mirror calibration.
    MagicResetMirror,
}

impl Schema for Data {
    fn ui() -> ui::QrScanSchema {
        ui::QrScanSchema::Operator
    }

    fn try_parse(code: &str) -> Option<Self> {
        let normal = user::Data::try_parse(code)
            .filter(
                |d| if d.signup_extension() { d.signup_extension_config.is_some() } else { true },
            )
            .map(Data::Normal);
        if normal.is_some() {
            return normal;
        }
        if let Some(captures) = MAGIC_QR_CODE.captures(code) {
            return match captures
                .name("magic_action")
                .expect("magic_action group must be present")
                .as_str()
            {
                "reset_wifi_credentials" => Some(Data::MagicResetWifi),
                "reset_mirror_calibration" => Some(Data::MagicResetMirror),
                _ => None,
            };
        }
        None
    }

        orb: &mut Orb,

                dd_incr!("main.count.signup.during.general.magic_qr.reset_mirror");

                if let Err(err) = &result {

                }
                orb.ui.magic_qr_action_completed(result.is_ok());
                Ok(None)

                let result = self.reset_wifi_and_ensure_network(orb).await;
                if let Err(err) = &result {
                    tracing::error!("Failed to reset wifi: {err}");
                }
                orb.ui.magic_qr_action_completed(result.is_ok());
                Ok(None)
            }
        }
    }

pub async fn request(qr_code: &qr_scan::user::Data) -> Result<Status> {
    let request = super::client()?
        .get(format!(
            "{}/api/v1/distributor/{}/orb/{}/status",
            *SIGNUP_BACKEND_URL, qr_code.user_id, *ORB_ID
        ))
        .basic_auth(&*ORB_ID, Some(get_orb_token()?));
    let status: Status = match request.send().await?.error_for_status() {
        Ok(response) => response.json().await?,
        Err(err) => {
            tracing::error!("Received error response {err:?}");
            return Err(err.into());
        }
    };
    if !status.valid {
        tracing::info!(
            "Operator QR-code invalid: {qr_code:?}, reason: {:?}",
            status.reason.as_deref().unwrap_or("<empty>")
        );
        return Ok(status);
    }
