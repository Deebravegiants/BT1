### Title
Stale delegate authorization reactivates after a position NFT round-trip and enables account theft - (File: common/src/types/controller.rs)

### Summary

Controller delegate grants are keyed only by the granting owner's address. An NFT transfer makes an old owner's grant inaccessible, but does not delete it; if the same NFT later returns to that owner, the previous delegate automatically regains account authority. [1](#0-0) 

That delegate can then call owner-gated controller actions such as `withdraw` and `borrow`, including specifying a recipient controlled by the delegate. [2](#0-1) 

### Finding Description

`DelegateGrant` stores `granted_by` and a delegate list, while `get_delegates` returns the stored list whenever `granted_by` equals the NFT's current owner. [3](#0-2) 

There is no ownership-generation or transfer-epoch component in the authorization key. Consequently, the authorization state sequence `owner A → owner B → owner A` restores the grant originally issued by owner A unless owner B called `add_delegate` or `remove_delegate` while holding the NFT. [1](#0-0) 

The check used by spending entrypoints then accepts any active position manager present in that revived list. [4](#0-3) 

### Impact Explanation

A reactivated delegate has broad economic control over the restored account. It can withdraw transferable collateral to itself through `withdraw`, or borrow pool liquidity to itself through `borrow` while leaving the resulting debt on the victim's account, subject to the account's ordinary solvency checks. [5](#0-4) 

This permits theft of user funds and encumbrance of the victim's remaining collateral with attacker-controlled proceeds. It also enables the other owner-or-delegate strategies to restructure the victim's position without a fresh authorization by the restored owner.

### Likelihood Explanation

The attack requires three preconditions: the attacker controls an active registered position manager, the account owner previously delegated that manager, and the NFT leaves and later returns to the same owner without an intervening delegate write. [6](#0-5) 

Those conditions can occur in custody, escrow, marketplace, wrapper-contract, or temporary-transfer workflows. Because the stale grant remains live under the original owner, the attacker does not need the restored owner to sign a new delegation before acting.

### Recommendation

Invalidate delegate grants permanently on every NFT ownership transition rather than treating a transfer as a temporary suspension.

Use a controller-visible ownership epoch, transfer nonce, or NFT transfer hook in delegate validation, so `owner A → owner B → owner A` produces a different authorization context. Alternatively, require the returned owner to explicitly reauthorize each delegate after regaining the NFT. Merely storing `granted_by = current_owner` is insufficient because it maps both ownership periods to the same key.

### Proof of Concept

1. Alice owns lending account `account_id` and delegates active position manager `mallory` through `controller::add_delegate(alice, account_id, mallory)`. This stores `DelegateGrant { granted_by: alice, delegates: [mallory] }`. [7](#0-6) 
2. Alice transfers the position NFT to Bob using `position_nft::transfer(alice, bob, account_id)`. While Bob owns it, `get_delegates(account_id, bob)` does not match `granted_by == alice`, so Mallory is rejected. [8](#0-7) 
3. Bob does not call `add_delegate` or `remove_delegate`, leaving Alice's stale grant in storage. [6](#0-5) 
4. Bob transfers the same NFT back to Alice using `position_nft::transfer(bob, alice, account_id)`. `get_delegates(account_id, alice)` again returns the stored list containing Mallory. [3](#0-2) 
5. Mallory calls `controller::withdraw(caller=mallory, account_id, withdrawals=[...], to=Some(mallory))`, or `controller::borrow(caller=mallory, account_id, borrows=[...], to=Some(mallory))`. `require_owner_or_delegate` passes because Mallory is an active manager in the revived grant. [9](#0-8) 
6. The collateral or borrowed tokens are paid to Mallory while the account and any resulting debt remain associated with Alice's NFT. [2](#0-1)

```rust
/// Returns grants stamped by `owner`, or an empty list. Ownership changes
/// invalidate a previous owner's grants without deleting them.
pub(crate) fn get_delegates(env: &Env, account_id: u64, owner: &Address) -> Vec<Address> {
    get_user::<DelegateGrant>(env, &ControllerKey::Delegates(account_id))
        .filter(|grant| grant.granted_by == *owner)
        .map(|grant| grant.delegates)
        .unwrap_or_else(|| Vec::new(env))
```

```rust
/// Adds a delegate, enforcing `MAX_DELEGATES`; returns false for duplicates.
/// Overwrites stale grants with a list stamped by the current owner.
pub(crate) fn add_delegate(
    env: &Env,
    account_id: u64,
    owner: &Address,
    delegate: &Address,
) -> bool {
    let mut delegates = get_delegates(env, account_id, owner);
    if delegates.contains(delegate) {
        return false;
    }
    assert_with_error!(
        env,
        delegates.len() < MAX_DELEGATES,
        GenericError::RegistryCapReached
    );
    delegates.push_back(delegate.clone());
    set_delegates(env, account_id, owner, &delegates);
    true
```

```rust
/// Removes a live delegate and reports whether it changed the list.
/// Deletes stale grants but returns false, preventing those grants from
/// reactivating if the NFT returns to their original owner.
pub(crate) fn remove_delegate(
    env: &Env,
    account_id: u64,
    owner: &Address,
    delegate: &Address,
) -> bool {
    let key = ControllerKey::Delegates(account_id);
    let Some(grant) = get_user::<DelegateGrant>(env, &key) else {
        return false;
    };
    if grant.granted_by != *owner {
        env.storage().persistent().remove(&key);
        return false;
    }
```

```rust
/// Accepts the owner or a registered, active manager delegated by that owner.
pub(crate) fn is_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) -> bool {
    if caller == owner {
        return true;
    }
    let active_manager =
        storage::get_position_manager(env, caller).is_some_and(|config| config.is_active);
    active_manager && storage::get_delegates(env, account_id, owner).contains(caller)
}

/// Requires the owner or a registered, active manager delegated by that owner.
pub(crate) fn require_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) {
    if is_owner_or_delegate(env, account_id, caller, owner) {
        return;
    }
    panic_with_error!(env, GenericError::NotAuthorized);
```
