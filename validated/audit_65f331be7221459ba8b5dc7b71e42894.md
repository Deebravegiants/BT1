**Analysis:**

`StateSlot::to_cold` is a pure, ownership-consuming transformation (`fn to_cold(self) -> Self`) on an in-memory Rust struct — it takes `self` by value, not by reference, so there is no shared mutable state that could be aliased or raced against within this function itself. [1](#0-0) 

The only call site is inside `HotStateLRU::maybe_evict`, which is invoked synchronously, per-shard, per-block, from `State::update` in the execution/commit pipeline. [2](#0-1)  Within a single `HotStateLRU` instance, `delete`/`get_slot` always resolve the *current* slot from a strict fallback chain (`pending` → `overlay` → `committed`), so the slot passed to `to_cold` is always the latest known value for that key at the time of that deterministic, sequential computation — there's no "stale reference retained across an async eviction batch" in this code path. [3](#0-2) [4](#0-3) 

`State::update`, which drives `HotStateLRU`, is itself a deterministic, versioned, single-pass computation over `per_version_updates`/checkpoints per block — it is not an attacker-controllable concurrent/async process that an unprivileged transaction can race against. [5](#0-4) 

Additionally, even downstream at the cold-JMT commit stage, `maybe_update_cold_state`/`passes_jmt_filter` explicitly guard against committing stale values by checking `value_version >= min_version`, filtering out cached/stale values that predate the last snapshot. [6](#0-5) [7](#0-6) 

The proposed proof idea (mutating "an equivalent slot in a simulated concurrent hot-state update" while holding a stale reference to the original) does not correspond to any real code path reachable from an unprivileged transaction, package, or API input — it requires positing a race condition that the actual single-threaded, ownership-based Rust implementation and version-gated commit logic do not exhibit. This does not cross a real custody boundary and is not a valid vulnerability per the review bounds.

        let mut current = match self.tail {
            Some(tail) => tail,
            None => {
                assert_eq!(self.num_items, 0);
                return Vec::new();
            },
        };

                .expect("There must be entries to evict when current size is above capacity.");

                .prev()

    fn delete(&mut self, key_hash: &HashValue) -> Option<StateSlot> {
        // Fetch the slot corresponding to the given key. Note that `self.pending` and
        // `self.overlay` may contain cold slots, like the ones recently evicted, and we need to
        // ignore them.
        let old_slot = match self.get_slot(key_hash) {
            Some(slot) if slot.is_hot() => slot,
            _ => return None,
        };

        match old_slot.prev() {
            Some(prev_key_hash) => {
                let mut prev_slot = self.expect_hot_slot(prev_key_hash);
                prev_slot.set_next(old_slot.next().copied());
                self.pending.insert(*prev_key_hash, prev_slot);
            },
            None => {
                // There is no newer entry. The current key was the head.
                self.head = old_slot.next().copied();
            },
        }

        match old_slot.next() {
            Some(next_key_hash) => {
                let mut next_slot = self.expect_hot_slot(next_key_hash);
                next_slot.set_prev(old_slot.prev().copied());
                self.pending.insert(*next_key_hash, next_slot);
            },
            None => {
                // There is no older entry. The current key was the tail.
                self.tail = old_slot.prev().copied();
            },
        }

        Some(old_slot)
    }
