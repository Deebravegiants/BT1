### Title
Pool `repay` trusts the declared leg amount and refunds unbacked "overpayment" out of real custody — (File: contracts/pool/src/ops/repay.rs)

### Summary
The pool's `repay` entrypoint resolves each repayment leg entirely from the *declared* `action.amount`. `resolve_repay` splits that declared amount into `net_repay` (capped at the position's outstanding debt) and `overpayment`, credits only `net_repay` to the market's cash book, and then `transfer_out`s the `overpayment` back to `payer` — without ever checking that the declared amount was actually transferred in. On a market with zero outstanding debt the entire declared amount is treated as overpayment and paid out of the pool's real token custody, letting an unprivileged caller drain the reserve by "repaying" a debt that does not exist. This mirrors CVE-2019-7283: the protocol acts on a counterparty-supplied value (the declared repay amount, analogous to the rcp server-chosen object name) instead of a measured receipt, and writes to attacker-controlled output (the refund).

### Finding Description
`ops::repay::apply` calls `accounting`, which computes `(burned, overpayment) = cache.resolve_repay(amount, position)` from `action.amount`, commits the book, then executes `outcome.cache.transfer_out(payer, outcome.overpayment)` — a real token transfer out of pool custody funded by nothing [1](#0-0) . The book is untouched (`credit_cash(net_repay)` only) and no reserve check guards the refund — the codebase's own regression test documents this: `test_unfunded_repay_overpayment_refund_also_pays_out_of_custody` shows a repay on a market with `borrowed == 0` and *nothing transferred in* refunding the full declared `custody_before` amount out of custody [2](#0-1) . The `RepayRoundsToZeroShares` assert passes vacuously on the `net_repay == 0` disjunct [3](#0-2) .

The controller path is safe only because *it* prefunds each leg with `payments::transfer_amount_measured` before calling the pool [4](#0-3) . The pool contract itself performs no measured-receipt check — it trusts the caller's declared amount, exactly the under-validated-server-response shape of the CVE. The pool test suite invokes `client.repay(&payer, ...)` directly with a fresh `Address::generate` payer and no controller, indicating `repay` is reachable with nothing more than the payer's own authorization [5](#0-4) .

### Impact Explanation
Theft of user funds / protocol insolvency. An attacker calls `pool.repay(attacker, [(hub_asset, X)])` on any market whose outstanding debt is zero — every unit of `X` up to the pool's token balance is computed as `overpayment` and transferred to the attacker out of suppliers' custody, while the market's `cash`/`supplied` books are unchanged. The books-vs-custody divergence then breaks withdrawals and borrows for all suppliers of that market. Repeating across markets drains each market's reserve.

### Likelihood Explanation
Requires only: a listed market with zero outstanding debt (e.g., a fresh market, or any market momentarily fully repaid — achievable via `repay` or a full-close liquidation), and the attacker's own address authorization. No collateral, oracle conditions, governance, or privileged role is needed. The only caveat I could not fully confirm from the index is whether `pool.repay` is gated to the controller address in production builds; if it is, the bug is latent defense-in-depth rather than live — but no such check appears in `ops/repay.rs`, and the test harness calls it directly.

### Recommendation
Make the pool's repay leg settle on a measured receipt, not the declared amount: snapshot the pool's token balance at batch start and cap the cumulative `repay`/`overpayment` outflow at `balance_before + sum_of_actual_inbound` (or require the controller to pre-deposit and pass a per-batch measured total). Alternatively, gate `repay` to the configured controller and document that as a hard invariant, since the declared-amount design is only sound when the sole caller prefunds with `transfer_amount_measured`.

### Proof of Concept
1. Identify a listed `(hub_id, asset)` market with `borrowed == 0` and pool custody `B > 0` (freshly listed market funded by a supplier, or a market just fully repaid).
2. As an unprivileged attacker `A`, call `pool.repay(A, [PoolAction { hub_asset, position: <zero position>, amount: B }])` authorizing as `A`.
3. In `ops::repay::accounting`, `resolve_repay(B, zero_debt_position)` returns `(burned = 0, overpayment = B)`; `net_repay == 0` so `RepayRoundsToZeroShares` is skipped and `credit_cash(0)` leaves the book unchanged.
4. `cache.transfer_out(A, B)` executes `token.transfer(pool, A, B)`, paying the pool's entire token custody to `A`.
5. Result: `token.balance(pool)` drops by `B` while `cash`/`supplied` still record supplier claims — direct theft of deposited funds, matching the repository's own `test_unfunded_repay_overpayment_refund_also_pays_out_of_custody` demonstration [6](#0-5) .

pub(crate) fn apply(
    env: &Env,
    payer: &Address,
    action: &PoolAction,
) -> (PoolPositionMutation, MarketStateSnapshot) {
    let outcome = accounting(env, action);

    outcome.cache.transfer_out(payer, outcome.overpayment);
    (outcome.mutation, outcome.snapshot)
}

/// Accrues interest, resolves the repay amount into burned debt shares and
/// overpayment, burns the shares, and credits the net repay to cash without
/// transferring the overpayment refund. Panics if a positive net repay would
/// burn zero scaled shares.
pub(crate) fn accounting(env: &Env, action: &PoolAction) -> RepayOutcome {
    let (mut cache, position) = ops::load_leg(env, action);
    let amount = action.amount;

    let (burned, overpayment) = cache.resolve_repay(amount, position);
    let net_repay = amount
        .checked_sub(overpayment)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));
    assert_with_error!(
        env,
        net_repay == 0 || burned.raw() > 0,
        GenericError::RepayRoundsToZeroShares
    );

    let position = position.checked_sub(env, burned);
    cache.burn_debt(burned);

    cache.credit_cash(net_repay);

    let snapshot = cache.commit();
    let mutation = cache.position_mutation(position, net_repay);
    RepayOutcome {
        cache,
        mutation,
        snapshot,
        overpayment,
    }
}

/// The refund gap is not specific to `recapitalize`. Two pool legs refund an
/// excess derived from a declared inbound amount, not from the cash book:
/// `ops::recapitalize::apply` (the excess over the shortfall) and
/// `ops::repay::apply` (the excess over the debt). Neither refund debits `cash`
/// or passes `require_reserves`.
///
/// A repay against a market with no debt makes the entire declared amount an
/// overpayment: `current_debt_ceil` is zero, so `resolve_repay` takes the
/// full-close branch and `net_repay` is zero. The `RepayRoundsToZeroShares`
/// assert in `ops::repay::accounting` passes on its `net_repay == 0` disjunct,
/// and the whole amount is refunded out of real custody with the book untouched.
#[test]
fn test_unfunded_repay_overpayment_refund_also_pays_out_of_custody() {
    let t = TestSetup::new();
    let token = token::Client::new(&t.env, &t.asset);
    let payer = Address::generate(&t.env);

    let custody_before = token.balance(&t.pool);
    let before = t.state_snapshot();
    assert_eq!(
        before.cash, custody_before,
        "fixture guard: book and custody must start in sync"
    );
    assert_eq!(before.borrowed, 0, "fixture must carry no debt");

    // Nothing transferred in, no debt to retire: the whole amount is "excess".
    let credited = t
        .client()
        .repay(&payer, &t.ract(0, custody_before))
        .get_unchecked(0)
        .actual_amount;
    assert_eq!(credited, 0, "no debt was retired, so nothing is credited");
    assert_unfunded_refund_drained_custody(&t, &payer, custody_before, &before);
}

/// Funds the pool with measured transfers and repays the corresponding debts.
fn settle_repay(
    env: &Env,
    account: &mut Account,
    payer: &Address,
    aggregated: &AggregatedPayments,
    cache: &mut Context,
) {
    let pool_addr = cache.cached_pool_address();
    let mut actions: Vec<PoolAction> = Vec::new(env);
    for (hub_asset, amount) in aggregated.iter() {
        enforce_spoke_asset_flags(
            env,
            cache,
            account.spoke_id,
            &hub_asset,
            FreezePolicy::AllowOnExit,
        );
        let position = get_debt_position_or_panic(env, account, &hub_asset);
        let amount_in = payments::transfer_amount_measured(
            env,
            &hub_asset.asset,
            payer,
            &pool_addr,
            amount,
            GenericError::AmountMustBePositive,
        );
        actions.push_back(make_pool_action(&position, amount_in, hub_asset.clone()));
    }
    apply_repay_batch(
        env,
        account,
        payer,
        events::PositionAction::Repay,
        &actions,
        cache,
    );
}
