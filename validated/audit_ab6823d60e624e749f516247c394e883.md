### Title
BCH legacy address checksum bypass allows corrupted destination address to reach withdrawal memo unverified - (File: `packages/intents-sdk/src/lib/validateAddress.ts`)

### Summary
`validateBchAddress` accepts any string matching `/^3[1-9A-HJ-NP-Za-km-z]{25,34}$/` (or the `1...` P2PKH pattern) without verifying the base58Check `sha256(sha256())` checksum, unlike the sibling `validateBtcBase58Address`, `validateTronBase58Address`, `validateLitecoinBase58Address`, and `validateDashAddress` functions in the same file, which all perform this check. This lets an unprivileged caller submit a syntactically valid but checksum-corrupted BCH legacy address that is embedded verbatim into the `WITHDRAW_TO:<address>` memo.

### Finding Description
The broken equality: the address that `validateAddress`/`validateBchAddress` "approves" for a BCH legacy withdrawal is claimed to equal an address the BCH network can actually resolve on-chain. In reality, `validateBchAddress` at [1](#0-0)  only runs a regex test for the legacy `1...`/`3...` branches and never decodes base58 or checks the trailing 4-byte checksum, in stark contrast to `validateBtcBase58Address` at [2](#0-1)  which decodes base58, verifies length, version byte, and the `sha256(sha256(payload))` checksum before returning true.

The reachable path: `PoaBridge.validateWithdrawal` calls `validateAddress(args.destinationAddress, assetInfo.blockchain)` at [3](#0-2) , and for `assetId: 'nep141:bch.omft.near'` this dispatches to `validateBchAddress`. The only other checks performed are `compareAddresses` (rejects only if destination equals the token's own origin_chain_address) and min-amount checks — neither verifies checksum validity of a legacy BCH address. If validation passes, `createWithdrawalIntents` → `createWithdrawIntentPrimitive` → `createWithdrawMemo` embeds `receiverAddress` unchanged into `memo: "WITHDRAW_TO:<address>"` at [4](#0-3) . A corrupted-checksum but regex-valid string (e.g., a `3...` string with one flipped base58 character in the last 4 checksum bytes) will pass the SDK's validation gate untouched and be signed into the withdrawal intent.

Existing guards do not catch this: `compareAddresses` only guards against self-send to the token's own address, `getUnderlyingFee`/`FeeExceedsAmountError` are unrelated to address integrity, and there is no other checksum verification anywhere else on this path for the legacy BCH branch (CashAddr format, by contrast, is protected via `verifyBchChecksum`'s polymod check).

### Impact Explanation
An intent is signed and a withdrawal submitted with a destination memo (`WITHDRAW_TO:<corrupted-address>`) that decodes to a different or entirely invalid BCH address than the one intended, with no on-chain guarantee it resolves. This matches the High-severity category "a withdrawal stuck until manual intervention" — the BCH connector/relayer processing the memo either rejects it or resolves to an unintended/unresolvable address, and the user's funds already debited via the signed intent become stuck pending manual intervention. This is repeatable on every legacy-format BCH withdrawal call since the check is structurally missing, not a one-off race.

### Likelihood Explanation
Preconditions are minimal: any ordinary SDK user (or an integrator forwarding attacker-controlled `destinationAddress` strings) can call `PoaBridge.validateWithdrawal` / the withdrawal creation flow with `assetId: 'nep141:bch.omft.near'` and a legacy-format address (`1...`/`3...`) that matches the length/charset regex but has a corrupted checksum. No special privileges, no bridge/relayer collusion needed — just crafting a 25-34 character base58-alphabet string starting with `1` or `3`. This is fully attacker-cost-free and deterministically reproducible.

### Recommendation
In `validateBchAddress`, replace the raw regex checks for legacy addresses with full base58Check decoding and checksum verification, mirroring `validateBtcBase58Address` (decode via `base58.decode`, verify 25-byte length, valid version byte 0x00/0x05, and `sha256(sha256(payload))` checksum match) before returning `true`.

import { base58 } from "@scure/base";
import { sha256 } from "@noble/hashes/sha2";
import { validateBchAddress } from "../../lib/validateAddress";
import { createWithdrawIntentPrimitive } from "./poa-bridge-utils";
import { poaBridge } from "@defuse-protocol/internal-utils";

function buildCorruptedP2SH(): string {
  const payload = new Uint8Array(21);
  payload[0] = 0x05; // P2SH version
  crypto.getRandomValues(payload.subarray(1));
  const checksum = sha256(sha256(payload)).subarray(0, 4);
  checksum[0] ^= 0x01; // corrupt one checksum byte
  const full = new Uint8Array([...payload, ...checksum]);
  return base58.encode(full);
}

describe("BCH legacy checksum bypass", () => {
  it("validateBchAddress accepts a corrupted-checksum legacy address", () => {
    const corrupted = buildCorruptedP2SH();
    expect(corrupted).toMatch(/^3[1-9A-HJ-NP-Za-km-z]{25,34}$/);
    expect(validateBchAddress(corrupted)).toBe(true); // BROKEN: should be false
  });

  it("validateWithdrawal resolves and memo embeds the unresolvable address", async () => {
    vi.spyOn(poaBridge.httpClient, "getSupportedTokens").mockResolvedValue({
      tokens: [{
        intents_token_id: "nep141:bch.omft.near",
        min_withdrawal_amount: "1",
        origin_chain_address: "native",
        // ...other required fields
      }],
    } as any);

    const corrupted = buildCorruptedP2SH();
    const bridge = new PoaBridge({ /* ...config */ } as any);

    await expect(bridge.validateWithdrawal({
      assetId: "nep141:bch.omft.near",
      amount: 50000n,
      destinationAddress: corrupted,
    })).resolves.toBeUndefined(); // DESTINATION_TRUTH never checked

    const intent = createWithdrawIntentPrimitive({
      assetId: "nep141:bch.omft.near",
      destinationAddress: corrupted,
      destinationMemo: undefined,
      amount: 50000n,
    });
    expect(intent.memo).toBe(`WITHDRAW_TO:${corrupted}`);
  });
});

function validateBtcBase58Address(address: string): boolean {
	const decoded: Uint8Array = base58.decode(address);

	// version (1) + hash160 (20) + checksum (4) = 25 bytes
	if (decoded.length !== 25) return false;

	const version = decoded[0];
	// 0x00 = P2PKH mainnet, 0x05 = P2SH mainnet
	if (version !== 0x00 && version !== 0x05) return false;

	const payload = decoded.subarray(0, 21);
	const checksum = decoded.subarray(21, 25);
	const expectedChecksum = sha256(sha256(payload)).subarray(0, 4);

	for (let i = 0; i < 4; i++) {
		if (checksum[i] !== expectedChecksum[i]) return false;
	}
	return true;
}

export function validateBchAddress(address: string): boolean {
	// Legacy address format (same as Bitcoin)
	if (
		/^1[1-9A-HJ-NP-Za-km-z]{25,34}$/.test(address) ||
		/^3[1-9A-HJ-NP-Za-km-z]{25,34}$/.test(address)
	) {
		return true;
	}

	// CashAddr format
	return validateBchCashAddr(address);
}

function createWithdrawMemo({
	receiverAddress,
	xrpMemo,
}: {
	receiverAddress: string;
	xrpMemo: string | undefined;
}) {
	// Strip "bitcoincash:" prefix from BCH CashAddr addresses
	const normalizedAddress = receiverAddress
		.toLowerCase()
		.startsWith("bitcoincash:")
		? receiverAddress.slice("bitcoincash:".length)
		: receiverAddress;

	const memo = ["WITHDRAW_TO", normalizedAddress];

	if (xrpMemo != null && xrpMemo !== "") {
		memo.push(xrpMemo);
	}

	return memo.join(":");
}
