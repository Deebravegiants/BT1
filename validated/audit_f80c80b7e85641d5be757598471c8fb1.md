### Title
Bonding LP graduation seeding accepts an attacker-created HyperSwap V2 pool as the trusted deposit channel, letting a hostile pre-seed larger than the graduation's own inventory permanently skew the locked LP price away from curve-close - ([File: packages/contracts/src/Bonding.sol])

### Summary
`Bonding.finalizeGraduation` trusts whatever HyperSwap V2 `TOKEN/LT` pair sits at `uniswapV2Factory.getPair(token, lt)` (or lazily creates one) as the deposit target for the curve-raised LP inventory. Because `IUniswapV2Factory.createPair` and `IUniswapV2Pair.mint` are permissionless external contracts, any unprivileged address can pre-create and pre-seed that exact pair — an "alternate channel" into the same graduation state that bypasses `Bonding`'s own creation/authorization boundary (`_ensureUniswapV2Pair`) — before `finalizeGraduation` ever runs. `_seedRebalancing`'s defense against such a hostile pre-seed caps the corrective swap at 99% of **Bonding's own** LT/token inventory (`_swapBudget`), not at a size proportional to the attacker's pre-seed. When the attacker's pre-seed reserves are large relative to the graduation's own `tokensForLP`/`ltFromPair`, the capped rebalance swap cannot fully correct the pool ratio, and `_routerDepositAndDispose` then deposits the remaining curve-raised inventory at the still-skewed post-swap ratio instead of the true curve-close price.

### Finding Description
`finalizeGraduation` is permissionless and callable by anyone once a token enters `Lifecycle.Graduating`: [1](#0-0) 

It resolves (or creates) the HyperSwap pair via `_ensureUniswapV2Pair`, which is a thin, unauthenticated wrapper around the external factory: [2](#0-1) 

Because `IUniswapV2Factory.createPair` is itself permissionless on-chain (any address can call it directly, independent of `Bonding`), an attacker can pre-create the exact `(token, lt)` pair — right after a token's `TokenLaunched` event reveals its address, and well before the curve can graduate — and `mint()` an arbitrary, self-funded reserve ratio into it. This is exactly the "alternate path/channel" pattern from the reference CVE: the protocol's intended entry point (`Bonding._ensureUniswapV2Pair` at graduation time) is not the only path to that same protected resource (the V2 pair address), and the un-gated alternate path lets an outsider stage state ahead of the protected flow.

`_seedUniswapV2Direct` branches into `_seedRebalancing` once the pair already has non-zero LP supply (Regime 3 — the "mint pre-seed" attacker path): [3](#0-2) 

The rebalance swap's input is capped by `_swapBudget`, which caps at 99% of `Bonding`'s **own** available LT or token inventory — not scaled to the size of the attacker's pre-seed reserves: [4](#0-3) 

`_noFeeSwapInput` computes the swap size needed to reach the target ratio and then clamps it to `maxSwap`: [5](#0-4) 

When the attacker's pre-seed reserves are large enough that the ideal corrective swap `s` exceeds `maxSwap` (i.e., the attacker capitalizes the pool with reserves that dwarf the graduation's own `tokensForLP`/`ltFromPair`), the swap only partially corrects the ratio, and `_routerDepositAndDispose` deposits the remaining curve-raised balance through the V2 router's `quote()`-based optimal split at that still-skewed ratio: [6](#0-5) 

The natspec on `_swapBudget` explicitly acknowledges the cap "only kicks in for catastrophic pre-seeds beyond our budget capacity," confirming the code's own author is aware the defense is bounded by `Bonding`'s side of the trade, not the attacker's: [7](#0-6) 

The result: `LPLock.recordLock` (a one-shot, unskippable sentinel) permanently locks LP minted at a price that is not the curve-close price, because the corrective mechanism was sized to the protocol's own inventory rather than the attacker's staged reserves: [8](#0-7) 

### Impact Explanation
This is a High-severity issue: an unprivileged attacker who is willing to capitalize a HyperSwap V2 pool with a large, skewed `(TOKEN, LT)` reserve before a target token graduates can force the graduation's entire curve-raised LT and the 250M reserved tokens to be deposited into the pool at a price divergent from the fair curve-close price. Because the resulting LP is immediately and irrevocably locked by `LPLock.recordLock` with no rescue path, the mispricing is permanent: value that curve buyers paid into the bonding curve is transferred to whichever side of the attacker's pre-seed benefits from the skewed deposit ratio, at the expense of the token's future LP-backed liquidity depth. This matches the allowed impact class of "an LP seeded away from the curve close price," causing permanent economic harm to curve traders/creators whose funds fund the LP.

### Likelihood Explanation
Likelihood is Medium-High: `Bonding.uniswapV2Factory`/`uniswapV2Router` are fixed, well-known addresses; any address (the launched token address is public from the `TokenLaunched` event) can call the standard, permissionless `createPair`/`mint` functions on that factory ahead of any graduation. The attack requires capital proportional to the amount needed to overwhelm `Bonding`'s own reserved LP inventory for that specific token (`tokensForLP`, `ltFromPair`), which for smaller/newer launches (before the curve raises much LT) can be modest. The window to act is the entire `Lifecycle.Curve` phase before `canGraduate` fires — potentially many blocks.

### Recommendation
Scale the rebalance defense to the actual pre-seed size rather than only to `Bonding`'s own inventory: detect when the ideal corrective swap `s` computed in `_noFeeSwapInput` exceeds the budget by more than a safe multiple of the graduation's intended `tokensForLP`/`ltFromPair`, and in that case revert/park the graduation (with an owner-recoverable escape hatch) instead of depositing at a still-skewed ratio. Alternatively, have `Bonding` deploy and pre-seed the HyperSwap V2 pair itself at `launch()` time (mirroring the curve `Pair`'s creation model, where the pair address is deterministically owned by the protocol from block one), removing the permissionless external `createPair`/`mint` alternate channel entirely.

### Proof of Concept
1. Attacker watches for `Bonding.TokenLaunched(token, creator, ltAddress, ...)`.
2. Before the curve for `token` reaches `canGraduate`, attacker calls `IUniswapV2Factory(uniswapV2Factory).createPair(token, ltAddress)` directly (bypassing `Bonding._ensureUniswapV2Pair`), obtaining `pair`.
3. Attacker acquires a large amount of `token` (e.g., by buying heavily on the curve, which is itself permissionless via `Zap.buy`) and `ltAddress` LT, then `transfer`s both into `pair` and calls `IUniswapV2Pair(pair).mint(attacker)`, establishing large reserves at a ratio favorable to the attacker and far from what the curve's eventual close price will be.
4. Curve trading continues; eventually `canGraduate(token)` becomes true and `_enterGraduating` snapshots `(tokensForLP, ltFromPair)` at the true curve-close price.
5. Anyone calls `Bonding.finalizeGraduation(token)`. `_seedRebalancing` detects the non-empty pool (Regime 3) and attempts `_pairRebalance`, but `_swapBudget` caps the corrective swap at 99% of `Bonding`'s own `tokensForLP`/`ltFromPair` — which, because the attacker's pre-seed is sized larger, is insufficient to fully correct the ratio.
6. `_routerDepositAndDispose` deposits the remaining curve-raised token/LT at the still-skewed ratio via `IUniswapV2Router02.addLiquidity(..., 1, 1, lpLock_, ...)`.
7. `LPLock.recordLock` permanently locks the resulting LP tokens at the off-curve-close price; the attacker's pre-existing LP position captures the value differential when they eventually exit, at the expense of the curve-raised funds that should have backed the token's liquidity at the fair curve-close price.

    function _seedRebalancing(
        address tokenAddress,
        address lt,
        address pair,
        uint256 tokensForLP,
        uint256 ltFromPair,
        uint256 protectedLT
    ) internal returns (uint256 liquidity) {
        (uint112 r0, uint112 r1,) = IUniswapV2Pair(pair).getReserves();
        bool tokenIs0 = IUniswapV2Pair(pair).token0() == tokenAddress;
        (uint256 reserveToken, uint256 reserveLT) = tokenIs0 ? (uint256(r0), uint256(r1)) : (uint256(r1), uint256(r0));

        // Below the band on BOTH sides, overpower the pre-seed with a direct
        // mint at the cached ratio: the rebalance swap is too coarse to reach
        // the ratio against such small reserves, and the pre-existing LP's
        // claim on the deposit stays bounded by `DIRECT_MINT_PRESEED_BPS`. A
        // side that is large relative to its LP target still takes the
        // rebalance path so it isn't donated under the empty-mint `min()`.
        if (
            reserveToken * BPS_DENOM <= tokensForLP * DIRECT_MINT_PRESEED_BPS
                && reserveLT * BPS_DENOM <= ltFromPair * DIRECT_MINT_PRESEED_BPS
        ) {
            return _seedDirectMint(tokenAddress, lt, pair, tokensForLP, ltFromPair);
        }

        // Budget reads `balanceOf(this)` rather than `tokensForLP` /
        // `ltFromPair` so any skim donation contributes to the rebalance
        // and not only to `_routerDepositAndDispose`'s deposit.
        // Direction: pool TOKEN-rich vs target ⇒ swap LT in (TOKEN out).
        // Pool LT-rich ⇒ swap TOKEN in (LT out). Bounded by uint112 reserves
        // and curve-close-shape targets, both products fit in uint256.
        // When `_pairRebalance` returns false the seed is too small for any
        // swap to move the ratio (its fee-charging quote rounds to zero), so
        // the reserves are negligible against this graduation's inventory:
        // overpower them with a direct mint at the cached ratio rather than
        // letting the router deposit at the attacker's ratio. A swap that
        // does fire leaves the pool ≈ at target for the router deposit.
        if (reserveToken * ltFromPair > reserveLT * tokensForLP) {
            // Pool TOKEN-rich. tokenIn = lt, tokenOut = tokenAddress.
            // tokenInIs0 = (lt is token0) = !tokenIs0.
            if (!_pairRebalance(
                    RebalanceParams({
                        pair: pair,
                        tokenIn: lt,
                        tokenInIs0: !tokenIs0,
                        reserveIn: reserveLT,
                        reserveOut: reserveToken,
                        targetN: ltFromPair,
                        targetD: tokensForLP,
                        maxSwap: _swapBudget(_ltSwapInventory(lt, protectedLT))
                    })
                )) {
                return _seedDirectMint(tokenAddress, lt, pair, tokensForLP, ltFromPair);
            }
        } else if (reserveToken * ltFromPair < reserveLT * tokensForLP) {
            // Pool LT-rich. tokenIn = tokenAddress, tokenInIs0 = tokenIs0.
            if (!_pairRebalance(
                    RebalanceParams({
                        pair: pair,
                        tokenIn: tokenAddress,
                        tokenInIs0: tokenIs0,
                        reserveIn: reserveToken,
                        reserveOut: reserveLT,
                        targetN: tokensForLP,
                        targetD: ltFromPair,
                        maxSwap: _swapBudget(IERC20(tokenAddress).balanceOf(address(this)))

                return _seedDirectMint(tokenAddress, lt, pair, tokensForLP, ltFromPair);
            }

        // pre-seeded at exactly target). Skip swap, deposit directly.

    function _noFeeSwapInput(
        uint256 reserveIn,
        uint256 reserveOut,
        uint256 targetN,
        uint256 targetD,
        uint256 maxSwap
    ) internal pure returns (uint256) {
        if (reserveIn == 0 || reserveOut == 0 || targetN == 0 || targetD == 0 || maxSwap == 0) {
            return 0;
        }
        uint256 product = Math.mulDiv(reserveIn * reserveOut, targetN, targetD);
        uint256 newIn = Math.sqrt(product);
        if (newIn <= reserveIn) return 0;
        uint256 s = newIn - reserveIn;
        return s > maxSwap ? maxSwap : s;
    }

    function recordLock(
        address token,
        address lpPair,
        uint256 amount
    ) external {
        LPLockStorage storage $ = _s();
        if (!$.isLocker[msg.sender]) revert NotAuthorized();
        if (lpPair == address(0)) revert ZeroAddress();
        if (amount == 0) revert ZeroAmount();
        // `lockedAt` is the one-shot sentinel: it is always set to a non-zero
        // timestamp on the first lock, so the guard holds for any `amount`.
        if ($.locks[token].lockedAt != 0) revert AlreadyLocked();
        if (IERC20(lpPair).balanceOf(address(this)) < amount) revert InsufficientLPBalance();
        $.locks[token] = LockInfo({lpPair: lpPair, amount: amount, lockedAt: block.timestamp});
        emit LPLocked(token, lpPair, amount);
    }
