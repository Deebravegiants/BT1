### Title
Attacker can permanently block permissionless bad-debt cleanup by topping up an insolvent account's collateral above the $5 dust gate - (File: contracts/controller/src/positions/supply.rs)

### Summary
The permissionless `clean_bad_debt` path is gated on `is_socializable_bad_debt`: debt must exceed collateral **and** collateral must be at or below `BAD_DEBT_USD_THRESHOLD` ($5). Any unprivileged address can push an insolvent account's `total_collateral` above that threshold by calling `supply` on a collateral asset the account already holds — third-party supply is deliberately allowed to top up existing slots (`require_third_party_existing_supply`). Once collateral is above the cap, `clean_bad_debt` reverts with `CannotCleanBadDebt`, and ordinary liquidation cannot bring it back down when the collateral asset's seizure leg is unavailable (`no_seize`) or the collateral cannot be seized for other reasons. The account's bad debt then persists until the owner-gated, timelocked `force_socialize_bad_debt` governance path is invoked. The codebase's own Certora spec proves the straddle: `bad_debt_straddle_blocks_dust_gate` shows `collateral = BAD_DEBT_USD_THRESHOLD + 1` blocks the dust gate while `debt > collateral` still holds.

### Finding Description
Two facts combine into the flaw:

1. `socialize_bad_debt` admits the permissionless path only through `BadDebtGate::DustCapped`, which evaluates `is_socializable_bad_debt(total_debt, total_collateral)` — i.e. `total_debt > total_collateral && total_collateral <= $5`. The check is value-based, not share- or provenance-based; it does not care who posted the collateral. `contracts/controller/src/positions/liquidation/mod.rs:229-235`, `contracts/controller/src/positions/liquidation/curve.rs:25-27`.

2. `process_supply` lets any authenticated caller top up an existing supply position on a foreign account. `require_third_party_existing_supply` only rejects opening a *new* asset slot; topping up a held collateral is expressly permitted (INV-AUTH-03). `contracts/controller/src/positions/supply.rs:61,86-97`.

The collateral used for the gate is half-up **unweighted** USD (`totals.total_collateral`), so a `no_seize`-flagged asset counts toward it even though ordinary liquidation seizure reverts on `no_seize` legs (INV-HALT-02) — meaning the donated collateral is unseizable yet still shuts the dust gate.

### Impact Explanation
Insolvent-account cleanup is the protocol's mechanism for writing down the supply index and reclassifying residual collateral to revenue. Permanently parking an account in the straddled state (collateral slightly above $5, debt larger) leaves its bad debt accruing interest on suppliers while no permissionless actor can remove it. Recovery then depends on governance scheduling `ForceSocializeBadDebt` on the Sensitive delay tier — a temporary freezing of supplier value and a liveness dependency the permissionless design was meant to avoid. For a `no_seize` collateral asset the straddle is stable: no liquidation can push collateral back under the cap.

### Likelihood Explanation
The attacker's cost is bounded: the smallest top-up that flips the gate is just above $5 of an asset the account already holds. Any address qualifies — `supply` requires only `caller.require_auth` plus the existing-slot check, no ownership, delegate grant, or whitelist. The prerequisites are an insolvent account near the dust boundary and (for permanence) a collateral asset whose seizure is blocked or economically unattractive; without `no_seize`, liquidators can re-drain the donation, making the griefing repeatable but costly per cycle. Medium likelihood overall.

### Recommendation
Make the dust gate robust against donated collateral. Options:
- Exclude `no_seize` supply positions (or positions added after insolvency) from `total_collateral` when evaluating `is_socializable_bad_debt`, so unseizable collateral cannot hold the gate shut.
- Alternatively, let `clean_bad_debt` tolerate collateral above the cap when the excess cannot be seized — i.e., gate on *seizable* collateral rather than total collateral.
- A weaker mitigation is lowering effective donor leverage by crediting third-party top-ups on insolvent accounts directly toward the liquidation/bad-debt path rather than the supply book.

### Proof of Concept
1. Alice supplies USDC (which governance later flags `no_seize`, or which simply sits near the boundary) and borrows ETH; the price moves so the account is insolvent with collateral ≈ $4.90 and debt $50 — `clean_bad_debt` would currently succeed.
2. Attacker Bob calls `controller::supply(caller=Bob, account_id=alice_id, spoke_id, assets=[USDC, 0.20])`. `require_third_party_existing_supply` passes because Alice already holds a USDC supply position.
3. `total_collateral` is now ≈ $5.10 > `BAD_DEBT_USD_THRESHOLD`; `is_socializable_bad_debt` returns false and every subsequent `clean_bad_debt` reverts `CannotCleanBadDebt` (`liquidation/mod.rs:230-235`).
4. Liquidators cannot restore eligibility: the proportional seizure leg reverts on the `no_seize` USDC (INV-HALT-02), so collateral stays above $5 while debt remains.
5. The only remaining remedy is the privileged `force_socialize_bad_debt` (`BadDebtGate::InsolventOnly`), which requires the controller owner via the Sensitive-tier timelock — the account is frozen in bad-debt limbo until governance acts.

This mirrors the Hats `renounceHat` class exactly: a cleanup/exit action gated on a state predicate (`collateral <= dust` / `isWearerInGoodStanding`) that a third party can flip to keep the target stuck.
