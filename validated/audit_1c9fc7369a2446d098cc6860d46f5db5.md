### Title
Vault node `GatewayHandler` permanently caches the master public key with no refresh, causing desync from the authoritative `SecretsService` key - (File: core/capabilities/vault/gw_handler.go)

### Summary
`GatewayHandler.getMasterPublicKey` fetches the vault master public key from `secretsService` once, lazily, on the first `MethodSecretsCreate`/`MethodSecretsUpdate` request, and caches it forever in `h.cachedMasterPublicKey`. There is no TTL, no periodic refresh goroutine, and no public API to invalidate or update the cached copy, so if the underlying master public key changes on the `SecretsService` side, this node keeps using the stale key indefinitely.

### Finding Description
`GatewayHandler` stores a private, mutex-guarded field `cachedMasterPublicKey *tdh2easy.PublicKey` [1](#0-0)  that is populated once inside `getMasterPublicKey`:

```go
func (h *GatewayHandler) getMasterPublicKey(ctx context.Context) (*tdh2easy.PublicKey, error) {
	h.mu.RLock()
	if h.cachedMasterPublicKey != nil {
		cachedCopy := *h.cachedMasterPublicKey
		h.mu.RUnlock()
		return &cachedCopy, nil
	}
	...
	h.cachedMasterPublicKey = publicKey
	...
}
``` [2](#0-1) 

This function is invoked on the hot path for `vaulttypes.MethodSecretsCreate` and `vaulttypes.MethodSecretsUpdate` messages received from the gateway, i.e. every time an end user's create/update secret request is routed through the gateway to this node:

```go
case vaulttypes.MethodSecretsCreate, vaulttypes.MethodSecretsUpdate:
    publicKey, pkErr := h.getMasterPublicKey(ctx)
    ...
    authorized, pipelineErr := h.requestProcessor.ProcessRequest(ctx, req, publicKey)
``` [3](#0-2) 

Once set, `cachedMasterPublicKey` is never re-fetched, cleared, or updated for the remainder of the process lifetime — there is no ticker, no expiry check, and no exposed setter, exactly mirroring the reported bug class: an authoritative value (`Core.vcon` / here the vault master public key from `SecretsService`) can change at its source, but a dependent component (`CoreRef._vcon` / here `GatewayHandler.cachedMasterPublicKey`) caches a copy once and has no mechanism to pick up the change.

This is notably different from the sibling implementation in `core/services/gateway/handlers/vault/handler.go`, which caches the same kind of key but refreshes it via a dedicated background ticker every minute and overwrites the cache on every successful fetch (`fetchVaultPublicKey`/`tryCachePublicKeyResponse`) [4](#0-3) [5](#0-4) . The `core/capabilities/vault/gw_handler.go` `GatewayHandler` has no equivalent refresh path.

### Impact Explanation
If the vault master public key is ever rotated on the `SecretsService` side (e.g. as part of a key-rotation/re-keying operation intended to invalidate previously-issued encryption capability or as part of node/DON re-provisioning), this node will silently continue to authorize and process `CreateSecrets`/`UpdateSecrets` requests using the stale, cached key via `requestProcessor.ProcessRequest(ctx, req, publicKey)`. Consequences include:
- Requests encrypted by legitimate callers under the new key may be rejected/misprocessed on this node while being accepted elsewhere in the DON, causing cross-node/cross-response inconsistency and potential OCR aggregation failures for secret create/update flows.
- If key rotation was performed specifically to revoke the validity of the old key, this node continues honoring the old key indefinitely (only cleared by a process restart), undermining the intended revocation.

### Likelihood Explanation
The cache is populated automatically and silently as soon as the first unprivileged client submits a `CreateSecrets`/`UpdateSecrets` request through the gateway — no special privilege is required to trigger the caching. The only trigger needed for the vulnerability to manifest is an operator-side key rotation occurring after that point, which is a legitimate expected operational event, not an attacker action.

### Recommendation
Apply the same mitigation used in `core/services/gateway/handlers/vault/handler.go`: add a periodic background refresh (or TTL-based invalidation) for `cachedMasterPublicKey` in `GatewayHandler`, or fetch it fresh (with short-lived caching) on each request instead of caching indefinitely after the first successful fetch.

### Proof of Concept
1. Start a node with `GatewayHandler` wired to a `SecretsService` returning public key `PK1`.
2. Submit any `CreateSecrets` request through the gateway; `getMasterPublicKey` fetches and permanently caches `PK1` in `h.cachedMasterPublicKey`.
3. Rotate the master key on the `SecretsService` so it now returns `PK2` for `GetPublicKey`.
4. Submit another `CreateSecrets`/`UpdateSecrets` request; `getMasterPublicKey` returns the cached `PK1` (per lines 238-244 of `gw_handler.go`) instead of `PK2`, so `requestProcessor.ProcessRequest` validates against the outdated key indefinitely, until the node process restarts.

func (h *GatewayHandler) getMasterPublicKey(ctx context.Context) (*tdh2easy.PublicKey, error) {
	h.mu.RLock()
	if h.cachedMasterPublicKey != nil {
		cachedCopy := *h.cachedMasterPublicKey
		h.mu.RUnlock()
		return &cachedCopy, nil
	}
	h.mu.RUnlock()

	publicKey, err := MasterPublicKeyFromSecretsService(ctx, h.secretsService)
	if err != nil {
		return nil, err
	}

	h.mu.Lock()
	defer h.mu.Unlock()
	if h.cachedMasterPublicKey != nil {
		cachedCopy := *h.cachedMasterPublicKey
		return &cachedCopy, nil
	}
	h.cachedMasterPublicKey = publicKey
	cachedCopy := *publicKey
	return &cachedCopy, nil
}

func (h *handler) tryCachePublicKeyResponse(resp *jsonrpc.Response[json.RawMessage], l logger.Logger) {
	if resp.Result == nil {
		l.Debugw("no result in public key response, not caching")
		return
	}

	r := &vaultcommon.GetPublicKeyResponse{}
	err := h.unmarshal(bytes.NewReader(*resp.Result), r)
	if err != nil {
		l.Debugw("failed to unmarshal public key response, not caching", "error", err)
		return
	}

	if r.PublicKey == "" {
		l.Debugw("no public key in unmarshaled response, not caching", "response", resp, "result", r)
		return
	}
	masterPublicKey := tdh2easy.PublicKey{}
	masterPublicKeyBytes, err := hex.DecodeString(r.PublicKey)
	if err != nil {
		l.Debugw("failed to decode master public key string", "error", err)
		return
	}
	err = masterPublicKey.Unmarshal(masterPublicKeyBytes)
	if err != nil {
		l.Debugw("failed to unmarshal master public key", "error", err)
		return
	}

	h.mu.Lock()
	h.cachedPublicKeyGetResponse = *resp.Result
	h.cachedPublicKeyObject = &masterPublicKey
	h.mu.Unlock()
	l.Debugw("successfully cached public key response")
