### Title
Simplex venue pricing ignores pool fee tier and price impact when pricing cross-asset intents from a Uniswap V4 pool - (File: `sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts`)

### Summary
Simplex's `UniswapV4FundingPlanner` prices curveless cross-asset trading pairs by reading the raw mid-price (`sqrtPriceX96`) of a single, solver-configured Uniswap V4 position, without ever applying that pool's own fee tier or any price-impact/size term to the quoted rate. This mirrors the rETH/WETH finding's root cause: relying on a single AMM's raw spot price as an execution price/oracle without accounting for the real cost (fees + slippage) of actually trading through that venue, which understates true execution cost and leaks value whenever a fill has to source inventory from the priced pool itself.

### Finding Description
When a pair has no static bid/ask curves and at least one Uniswap V4 position is configured under `[vault.uniswapV4]`, `FXFiller` fetches the pair's price from `UniswapV4FundingPlanner.getExoticTokenPrice`, which selects the most-liquid qualifying pool for the exotic token and returns `computeDirectPoolPriceUsd`'s raw pool mid price derived straight from `sqrtPriceX96`: [1](#0-0) [2](#0-1) 

This value is fed into `FXFiller.getVenueUsdPrice`/`venuePriceMemo` and ultimately used as `rate = 1 / venueUsd` for the leg, i.e. as the price at which the order is filled: [3](#0-2) 

The repository's own internal flow documentation confirms the gap explicitly: the pool's fee tier is read and stored on the hydrated position but *never applied* to the price, there is no size/impact term (`computeLegPolicyOutput` extends the mid linearly across the whole quantity), and `checkPriceGuard` only bounds deviation from a static reference — it does not account for execution cost: [4](#0-3) 

Separately, when the fill actually needs to source the exotic token, `planWithdrawalForToken` withdraws liquidity directly from the same configured Uniswap V4 position(s) rather than considering any alternative, deeper/cheaper venue (e.g. Curve, Balancer, or other DEXs) — the venue and its pricing are hard-tied to whatever single position the operator configured: [5](#0-4) 

This is the same class of bug as the referenced report: an unbacked/naive execution-price assumption (raw mid, no fee, no impact) drawn from a single AMM venue that may be thin, when better-priced or deeper alternatives exist or should at minimum be accounted for in the quoted rate.

### Impact Explanation
Because the quoted rate never subtracts the pool's fee tier or price impact, orders large enough to move the pool (or simply large relative to a thin position) are priced more favorably to the order submitter than what the solver can actually realize on-chain when it withdraws liquidity to fund the fill. Any user able to submit an intent order against such a curveless, pool-priced pair can systematically extract the unaccounted fee/impact spread from the solver on every fill, draining solver value over repeated trades — a concrete, unbacked-value leak analogous to the rETH swap-fee leak in the referenced report, but here affecting the solver operating in front of `IntentGatewayV2` rather than the vault contract itself.

### Likelihood Explanation
High for any operator running this documented, supported configuration (`[vault.uniswapV4]` with no curves). It requires no special privilege — any counterparty submitting a normal-sized order against a curveless, venue-priced pair triggers the mispricing on every fill; larger orders relative to the position's liquidity increase the leaked value further.

### Recommendation
Apply the pool's fee tier and a price-impact/size term to `computeDirectPoolPriceUsd`'s output before using it as the fill rate (e.g., quote the actual swap output for the leg's notional through the pool rather than the raw mid), and/or extend `checkPriceGuard` to bound against realized execution cost, not just static-reference deviation. Consider allowing multiple funding/pricing venues (comparable to the report's RocketSwapRouter-style aggregation) so pricing and funding are not both hard-tied to a single, potentially thin AMM position.

### Proof of Concept
1. Operator configures a curveless pair (`token0` = USDC, `token1` = exotic token) with a single `[vault.uniswapV4]` position as in the shipped example config.
2. `FXFiller.resolveLegRates` calls `venuePriceMemo` → `getVenueUsdPrice` → `UniswapV4FundingPlanner.getExoticTokenPrice`, which returns the pool's raw mid price with no fee/impact deduction, per [1](#0-0)  and [3](#0-2) .
3. An order submitter places an order sized close to (or larger than) the position's available liquidity; the solver quotes/fills at the mid price and then must withdraw liquidity via `planWithdrawalForToken`, incurring the pool's real fee tier and slippage that were never reflected in the quoted rate, per [5](#0-4) .
4. The solver realizes less value than quoted; repeating this captures the unaccounted fee/impact spread from the solver on every such fill, as acknowledged directly in [6](#0-5) .

	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}

	private computeDirectPoolPriceUsd(
		pos: HydratedV4Position,
		sdkPool: V4Pool,
		chain: string,
	): { exoticToken: string; priceUsd: Decimal } | null {
		const usdc = this.configService.getUsdcAsset(chain).toLowerCase()
		const usdt = this.configService.getUsdtAsset(chain).toLowerCase()
		const c0 = pos.currency0.toLowerCase()
		const c1 = pos.currency1.toLowerCase()

		if (c0 === usdc || c0 === usdt) {
			// currency0 is stable → exotic is currency1
			// token1Price = "token0 per token1" = USD per exotic
			return {
				exoticToken: c1,
				priceUsd: new Decimal(sdkPool.token1Price.toFixed(18)),
			}
		}

		if (c1 === usdc || c1 === usdt) {
			// currency1 is stable → exotic is currency0
			// token0Price = "token1 per token0" = USD per exotic
			return {
				exoticToken: c0,
				priceUsd: new Decimal(sdkPool.token0Price.toFixed(18)),
			}
		}

		return null

	/**
	 * Queries funding venues for `token1Address`'s USD price on a chain.
	 * Uniswap V4 is preferred; falls back to other venues. Returns null when no
	 * venue can price the token there.
	 */
	private async getVenueUsdPrice(chain: string, token1Address: string): Promise<Decimal | null> {
		if (this.fundingVenues.length === 0) return null

		// Prefer V4, fall back to others
		const v4 = this.fundingVenues.filter((v) => v.name === "UniswapV4")
		const venues = v4.length > 0 ? v4 : this.fundingVenues

		for (const venue of venues) {
			const usdPrice = await venue.getExoticTokenPrice(chain, token1Address)
			if (usdPrice?.isPositive()) return usdPrice
		}
		return null
	}

	/** Per-evaluation memo over `getVenueUsdPrice`, keyed by (chain, token1). */
	private venuePriceMemo(): (chain: string, token1Address: string) => Promise<Decimal | null> {
		const cache = new Map<string, Decimal | null>()
		return async (chain: string, token1Address: string) => {
			const key = `${chain}:${token1Address}`
			const cached = cache.get(key)
			if (cached !== undefined) return cached
			const price = await this.getVenueUsdPrice(chain, token1Address)
			cache.set(key, price)
			return price
		}
	}

# Venue pricing (Uniswap V4 funded pairs)

Verified 2026-08-19.

```
resolveLegRates(...)
  curveless pair && token0 is a USD stable
    -> venuePriceMemo() -> getVenueUsdPrice(chain, token1)
         -> UniswapV4FundingPlanner.getExoticTokenPrice
              picks the position with the largest pool liquidity
              -> computeDirectPoolPriceUsd -> sdkPool.token0Price / token1Price
    -> checkPriceGuard(...)   reject if outside maxDeviationBps of the static reference
    -> rate = 1 / venueUsd
  otherwise -> the pair's ask/bid curve at the leg's notional
```

`computeDirectPoolPriceUsd` returns the **raw pool mid** derived from `sqrtPriceX96`. The pool's
fee tier is read and stored on the hydrated position (`pos.fee`) but never applied to the price,
and there is no size or impact term — `computeLegPolicyOutput` extends the mid linearly across the
whole priced quantity. `checkPriceGuard` is the only defense on this path, and it checks deviation
from a static reference, not execution cost. A venue-priced pair that has to swap through its own
pool to source inventory pays a fee tier it never quoted against.
