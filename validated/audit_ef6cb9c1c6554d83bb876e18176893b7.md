Audit Report

## Title
Missing sender allowlist/authorization check before broadcasting legacy user messages to all DON nodes - (File: core/services/gateway/handlers/capabilities/handler.go)

## Summary
`(h *handler) HandleLegacyUserMessage` validates payload structure, timestamp freshness, and method name, but explicitly skips any allowlist or rate-limit check on the message sender before forwarding the request to every DON node member via `don.SendToNode`. The code contains a literal `// TODO: apply allowlist and rate-limiting here` comment directly preceding the method check, confirming this is a known, unfinished gap.

## Finding Description
`HandleLegacyUserMessage` [1](#0-0)  performs the following checks in order: payload decode, timestamp presence, staleness check, and method allowlist (`MethodWebAPITrigger` only) [2](#0-1) . None of these checks inspect `msg.Body.Sender` against any per-sender allowlist or rate limiter. After `common.ValidatedRequestFromMessage` transforms the message, the handler unconditionally broadcasts it to every DON member: [3](#0-2) .

By contrast, the `handleWebAPIOutgoingMessage` path (node-to-client direction) does apply `h.nodeRateLimiter.Allow(nodeAddr)` [4](#0-3) , and other handlers in the codebase (webapi outgoing connector, vault) apply sender-based rate limiting/authorization before acting — confirming this is an established pattern that the legacy user-message path in this handler does not follow.

I was unable to fully trace the HTTP-to-handler wiring (i.e., where in `gateway.go` an inbound HTTP request is authenticated/signature-checked and routed to `HandleLegacyUserMessage`) within the available tool budget, so I cannot confirm from the indexed code whether an upstream layer performs sender validation/allowlisting before this handler is invoked, or whether this legacy code path is still reachable/enabled in current production Gateway deployments versus superseded by JSON-RPC/vault/webapi handlers.

## Impact Explanation
If reachable without upstream mitigation, this allows any client capable of producing a syntactically valid signed `api.Message` to cause the Gateway to broadcast requests to every configured DON node, bypassing the intended per-sender allowlist/rate-limiting that the code's own TODO comment indicates is expected. This maps to unauthorized job/trigger dispatch and node resource-exhaustion/amplification risk, which is a plausible in-scope impact category (gateway request dispatch without authorization).

## Likelihood Explanation
Likelihood is uncertain rather than clearly high or low. The claim itself acknowledges (in the "Likelihood Explanation" and PoC sections) that it could not confirm whether this legacy path is actually reachable via any exposed endpoint in current Gateway configurations, nor whether upstream signature/session validation or DON-level allowlisting (mentioned in code comments elsewhere as "the connection between the Gateway and DON Node is already authorized via a DON-side and Gateway-side allowlist, and secured via TLS") [5](#0-4)  mitigates this at the transport layer. Without confirming the concrete reachable entrypoint and demonstrating that no other layer enforces authorization, this remains a code-quality/defense-in-depth gap rather than a demonstrated exploitable vulnerability.

## Recommendation
Implement the allowlist and rate-limiting check called out in the TODO comment in `HandleLegacyUserMessage` before `req` is forwarded to `don.SendToNode`, mirroring the sender-based rate limiter pattern already used in `handleWebAPIOutgoingMessage` and in other Gateway handlers (webapi outgoing connector, vault), so that only allowlisted/authorized senders' messages reach DON nodes.

## Proof of Concept
Not independently verified. The finding is supported only by static code review of the `TODO` comment and the unconditional broadcast loop; no HTTP/gateway request trace, unit test, or confirmation of the legacy path's live reachability was established. To validate, an engineer would need to: (1) confirm whether `HandleLegacyUserMessage` is wired to a live, unauthenticated HTTP endpoint in the current Gateway server configuration (`gateway.go`), (2) confirm whether any upstream layer (HTTP middleware, `Validate()`, or DON-side mTLS allowlist) already restricts senders before this handler runs, and (3) if not, write an integration test sending a validly-signed but non-allowlisted sender's `api.Message` to the legacy endpoint and observe whether it is broadcast to all `donConfig.Members`.

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JSONRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) { //nolint:gosec // G115: comparing unix timestamps, both fit within uint
		h.lggr.Errorw("stale message")
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),
			ErrorCode: api.HandlerError,
		})
	}
	// TODO: apply allowlist and rate-limiting here
	if msg.Body.Method != MethodWebAPITrigger {
		h.lggr.Errorw("unsupported method", "method", body.Method)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.UnsupportedMethodError),
				"invalid method "+msg.Body.Method,
				nil,
			),
			ErrorCode: api.UnsupportedMethodError,
		})
	}
	req, err := common.ValidatedRequestFromMessage(msg)
	if err != nil {
		h.lggr.Errorw(ErrTransformingMessageToRequest)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageID,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrTransformingMessageToRequest,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	h.mu.Lock()
	h.savedCallbacks[msg.Body.MessageID] = &savedCallback{id: msg.Body.MessageID, createdAt: time.Now(), Callback: callback}
	don := h.don
	h.mu.Unlock()

	// Send original request to all nodes
	for _, member := range h.donConfig.Members {
		err = errors.Join(err, don.SendToNode(ctx, member.Address, req))
	}
	return err
}
