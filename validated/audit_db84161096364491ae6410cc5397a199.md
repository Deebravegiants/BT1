### Title
IntentGatewayV2's `_paused` flag exists in storage but is never enforced by any modifier - (File: evm/src/apps/intentsv2/IntentsBase.sol)

### Summary
`IntentsBase.sol`, the shared base contract for `IntentGatewayV2`, declares a `_paused` storage flag but neither `IntentsBase.sol` nor `IntentGatewayV2.sol` contains a `whenNotPaused`/`whenPaused` modifier or any check against it in the externally reachable entry points (`placeOrder`, `fillOrder`, `cancel`, `onAccept`, etc.). This mirrors the referenced report: a pausing mechanism is present but is functionally inert because nothing actually gates execution on it.

### Finding Description
`IntentsBase.sol` declares: [1](#0-0) 
with an explicit comment that it was "Appended last to preserve existing storage slots," and a companion decision doc confirms an accompanying getter/setter/event/checks were dropped purely to stay under the EIP-170 bytecode size limit: [2](#0-1) 

Searching the actual gateway implementation (`evm/src/apps/IntentGatewayV2.sol` and the mirrored `sdk/packages/core/contracts/apps/IntentGatewayV2.sol` and `evm/tron/contracts/apps/IntentGatewayV2.sol`) for any reference to `_paused`, `pause`, or `Paused` returns zero matches — the flag is never read anywhere in the contract that defines `placeOrder`, `fillOrder`, `cancel`, and the cross-chain `onAccept`/message-handling entry points. The only other places `_paused` is referenced are the test file `evm/tests/foundry/IntentGatewayV2Test.sol` and changelog/decision docs, not the production dispatch/fill/cancel/escrow-release code paths.

This is structurally identical to the reported Synthetix `StakingRewards` bug: a `Pausable`-style boolean is wired into storage (and, per the decision doc, was originally meant to have a setter/event/checks) but the enforcement was stripped out, leaving the pause state completely disconnected from execution.

### Impact Explanation
If governance (or whichever privileged path sets `_paused`, if any remains) believes the IntentGateway can be halted in an emergency (e.g., a discovered bug in fill/escrow logic, a compromised price oracle, or an ongoing exploit), it cannot actually stop order placement, filling, or escrow release/refund through this mechanism. Since `placeOrder`, `fillOrder`, and the cross-chain `RedeemEscrow`/`RefundEscrow` handlers in `IntentsBase._withdraw` (which moves escrowed user/solver funds) never check `_paused`, an attacker exploiting any other vulnerability in the intents flow could continue draining escrowed funds even after operators attempt to pause the contract, defeating the incident-response safety control and leading to continued unauthorized fund movement.

### Likelihood Explanation
High likelihood of being triggered as designed-but-broken: any transaction submitted to `placeOrder`/`fillOrder`/cancel by ordinary users, solvers, or relayers will always execute regardless of the intended pause state, since the flag is dead code in the reachable dispatch path. No attacker action is needed to trigger the missing check — it is a systemic gap that only manifests as harmful when an emergency pause is actually needed, at which point it silently fails to stop fund flows.

### Recommendation
Add an explicit `whenNotPaused` check (or equivalent inline `if (_paused) revert ...`) to all externally/cross-chain reachable state-changing entry points in `IntentGatewayV2.sol` that move escrowed funds or create new orders (`placeOrder`, `fillOrder`, `cancel`, and the `onAccept` branches handling `RedeemEscrow`/`RefundEscrow`). Restore a minimal setter (e.g., a governance-only `Execute`-routed pause toggle) that flips `_paused`, and ensure both are covered by tests exercising the paused state against every fund-moving function, not just direct storage manipulation in `IntentGatewayV2Test.sol`.

    function _withdraw(WithdrawalRequest memory body, bool isRefund, bool finalize) internal {
        address beneficiary = address(uint160(uint256(body.beneficiary)));
        if (finalize) _filled[body.commitment] = beneficiary;

        uint256 len = body.tokens.length;
        for (uint256 i; i < len; i++) {
            address token = address(uint160(uint256(body.tokens[i].token)));
            uint256 amount = body.tokens[i].amount;
            if (amount == 0) continue;

            uint256 escrowed = _orders[body.commitment][token];
            if (escrowed == 0) revert UnknownOrder();

            _orders[body.commitment][token] = escrowed - amount;
            if (token == address(0)) {
                _sendValue(beneficiary, amount);
            } else {
                IERC20(token).safeTransfer(beneficiary, amount);
            }
        }

        if (finalize) {
            uint256 fees = _orders[body.commitment][TRANSACTION_FEES];
            if (fees > 0) {
                delete _orders[body.commitment][TRANSACTION_FEES];
                IERC20(IDispatcher(host()).feeToken()).safeTransfer(beneficiary, fees);
            }

            if (isRefund) {
                emit EscrowRefunded({commitment: body.commitment, tokens: body.tokens});
            } else {
                emit EscrowReleased({commitment: body.commitment, tokens: body.tokens});
            }
        }
    }
