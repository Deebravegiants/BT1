### Title
Missing `ShopValidator` sanitization of `shop` in `Auth::Oauth.begin_auth` allows attacker-controlled OAuth authorization host - (File: `lib/shopify_api/auth/oauth.rb`)

### Summary
`ShopifyAPI::Auth::Oauth.begin_auth` builds the OAuth authorization URL directly from the caller-supplied `shop:` parameter without ever validating it against `Utils::ShopValidator`, unlike every other credential-bearing OAuth-family method in the gem (`ClientCredentials.client_credentials`, `RefreshToken.refresh_access_token`, `TokenExchange.migrate_to_expiring_token`), which all call `Utils::ShopValidator.sanitize!(shop)` before constructing the host used by `Clients::HttpClient`.

### Finding Description
`Auth::Oauth.begin_auth` accepts `shop:` and passes it unmodified into the private helper `auth_base_uri`, which returns `"https://#{shop}/admin"` [1](#0-0) . This value is then used verbatim to build the `auth_route` the app redirects the merchant's browser to, embedding `client_id`, `scope`, and `redirect_uri` as query parameters [2](#0-1) .

Compare this to the sibling flows that also build a host from a caller-supplied `shop` and then send `client_secret` to it via `Clients::HttpClient`: `RefreshToken.refresh_access_token` calls `validated_shop = Utils::ShopValidator.sanitize!(shop)` before constructing the session/host used for the token request body containing `client_secret` [3](#0-2) ; `ClientCredentials.client_credentials` and `TokenExchange.migrate_to_expiring_token` do the same [4](#0-3) [5](#0-4) . `ShopValidator.sanitize!` restricts the host to `TRUSTED_SHOPIFY_DOMAINS` (`shopify.com`, `myshopify.io`, `myshopify.com`, `spin.dev`, `shop.dev`) and raises `Errors::InvalidShopError` otherwise [6](#0-5) .

`begin_auth` skips this check entirely, breaking the intended binding: `shop` used to construct the OAuth host == `shop` validated as a trusted Shopify domain. `HttpClient` itself never validates `session.shop`; it directly interpolates it as the request host: `@base_uri = "https://#{api_host || session.shop}"` [7](#0-6) , reinforcing that host-domain validation is expected to happen at the call site (as done in the three sibling methods) — and is missing in `begin_auth`.

### Impact Explanation
If a host application forwards a client-supplied shop identifier straight into `begin_auth` (a usage pattern the gem's own docs show, e.g. `shop = request.headers["Shop"]` then `Oauth.begin_auth(shop: domain, ...)`), an unprivileged internet user can supply an arbitrary string as `shop`. Because `auth_base_uri` performs no domain restriction, the app will redirect the merchant's browser to an attacker-controlled host with the app's real `client_id` and `redirect_uri` in the query string. This is a documented-API-consistent SSRF/host-confusion primitive within the gem: the same `shop` input that in every other Auth module is required to pass `ShopValidator.sanitize!` before being trusted as a request host is, in `begin_auth`, trusted with zero validation. This falls under High severity as a credential/redirect-target confusion analogous to forced OAuth completion / SSRF-adjacent host validation bypass — it undermines the exact host-binding property (`shop` used == `shop` validated as trusted) that the gem enforces everywhere else in the OAuth family.

### Likelihood Explanation
High for any integrator following the gem's own documented pattern (`docs/usage/oauth.md`, which explicitly shows `shop` taken from a request header and passed directly to `begin_auth`) without performing independent validation, since the gem provides `ShopValidator` specifically for this purpose but never invokes it in this code path, unlike its sibling methods.

### Recommendation
Add `validated_shop = Utils::ShopValidator.sanitize!(shop)` at the start of `begin_auth`, and use `validated_shop` (not the raw parameter) in `auth_base_uri`, mirroring the pattern already used in `RefreshToken.refresh_access_token`, `ClientCredentials.client_credentials`, and `TokenExchange.migrate_to_expiring_token`.

### Proof of Concept
1. Host app (following the gem's documented example) does: `ShopifyAPI::Auth::Oauth.begin_auth(shop: request.headers["Shop"], redirect_path: "/auth/callback")`.
2. Attacker sends a request with `Shop: attacker.example`.
3. `auth_base_uri("attacker.example")` returns `"https://attacker.example/admin"` with no error raised [1](#0-0) , unlike calling `Utils::ShopValidator.sanitize!("attacker.example")` directly, which raises `Errors::InvalidShopError` as demonstrated in the test suite [8](#0-7) .
4. The victim's browser is redirected to `https://attacker.example/admin/oauth/authorize?client_id=...&redirect_uri=...&state=...`, leaking the app's `client_id` and intended `redirect_uri` to the attacker-controlled host and enabling forced/hijacked OAuth flows.

      TRUSTED_SHOPIFY_DOMAINS = T.let(
        [
          "shopify.com",
          "myshopify.io",
          "myshopify.com",
          "spin.dev",
          "shop.dev",
        ].freeze,
        T::Array[String],
      )

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
