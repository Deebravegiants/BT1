### Title
Debt value overflow in `calculate_supplier_rewards` permanently freezes a high-utilization whale market before the borrow-index cap engages - (File: common/src/rates/index.rs)

### Summary
Accrual computes total debt as `borrowed * borrow_index` with a checked `Ray::mul` that panics on `i128` overflow (`common/src/rates/index.rs:80-81`, via `scaled_to_original` at `common/src/rates/scaling.rs:14-16`). The borrow index is clamped only after the multiplication in `update_borrow_index` (`common/src/rates/index.rs:13-19`), so on a market whose scaled debt is large enough, index growth makes `borrowed * new_borrow_index` exceed `i128::MAX` *before* the index reaches `MAX_BORROW_INDEX_RAY` (`common/src/constants/pool.rs:19`). Every pool verb runs `global_sync` first (`contracts/pool/src/interest.rs:20-33`), so once the product crosses the ceiling, `supply`, `borrow`, `withdraw`, `repay`, `liquidate`, `clean_bad_debt`, and `update_indexes` all revert with `GenericError::MathOverflow` on that market.

### Finding Description
The bug class in the report — out-of-range numeric input triggering an overflow/abort in a decompression path — maps here to out-of-range *scaled-debt × index* products trapping the accrual path. `accrue_chunk` calls `accrue_step` each compound window (`contracts/pool/src/interest.rs:39-53`), and `accrue_step` splits interest via `calculate_supplier_rewards`, which multiplies the full scaled debt by the new index unconditionally (`common/src/rates/index.rs:80-81`). The representable ceiling is `i128::MAX / RAY ≈ 170_141_183_460` whole tokens, independent of decimals (`common/tests/math/fp.rs:792-801`). A market holding ~10^11 native units of debt at ~98% utilization on a steep rate curve reaches this value-overflow cliff while `borrow_index < MAX_BORROW_INDEX_RAY`, so the intended index cap never saves it (`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:316-361`).

### Impact Explanation
Permanent freezing of funds. After the cliff, every entrypoint on the affected `(hub, token)` book panics during mandatory accrual: suppliers cannot withdraw, borrowers cannot repay, liquidators cannot liquidate, and even governance cannot fix it (the index cap path is unreachable because accrual itself traps; `clean_bad_debt`/`recapitalize` also accrue first). The harness test demonstrates `withdraw` and `repay` both reverting with `MathOverflow` after the freeze. All supplied collateral and principal in that market are locked indefinitely.

### Likelihood Explanation
An unprivileged address drives utilization by borrowing; the conditions are a whale-scale market (debt principal on the order of 10^11 whole tokens — feasible for 18-decimal assets or high-supply hubs), caps lifted or uncapped (`with_max_utilization_disabled` in the test; cap governance is not required for the overflow to exist, only for the market to reach the size), and sustained near-max utilization over an extended period so index compounding pushes the product over `i128::MAX`. No privilege, upgrade, or leaked key is needed — only ordinary `supply`/`borrow` and waiting. That makes it a real but high-setup-cost scenario: Medium severity.

### Recommendation
- Make accrual fail-safe at the value ceiling: in `calculate_supplier_rewards` and `update_supply_index`, detect when `borrowed * new_index` (or `supplied * new_index`) would overflow and clamp `new_index`/`grown` to the largest index whose product still fits `i128` (i.e., `new_index <= i128::MAX / borrowed`), or use a saturating `mul` plus an explicit cap to `MAX_*_INDEX_RAY`.
- Alternatively, scale new debt so `borrowed_scaled` is capped below `i128::MAX / MAX_BORROW_INDEX_RAY`, guaranteeing `borrowed * capped_index` never overflows for any index the cap permits.
- Add a regression test asserting `update_indexes` clamps the index rather than panicking when `borrowed * index` exceeds `i128::MAX`.

### Proof of Concept
```rust
// tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:320
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;              // ~98% utilization
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    // Advance time until accrual traps inside scaled_to_original /
    // calculate_supplier_rewards (borrowed * new_borrow_index > i128::MAX).
    let failure = loop {
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) { break e; }
    };
    assert_contract_error(Err(failure), errors::MATH_OVERFLOW);
    assert!(book(&t, "BIG18").borrow_index < MAX_BORROW_INDEX_RAY); // cap never engaged

    // Market is frozen: every verb accrues first and hits the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
}
```

Root cause: `common/src/rates/index.rs:80-81` (`borrowed.mul(env, new_borrow_index)` panics on overflow), invoked from `accrue_step` in every `accrue_chunk` (`contracts/pool/src/interest.rs:39-48`), which precedes every state-changing pool verb via `global_sync` (`contracts/pool/src/interest.rs:20-33`).
