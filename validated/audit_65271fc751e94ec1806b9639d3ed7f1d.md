### Title
Webhook `shop` and `topic` identity fields are not covered by the HMAC signature, allowing shop-spoofing via webhook replay - ([File: lib/shopify_api/webhooks/request.rb])

### Summary
`ShopifyAPI::Webhooks::Request` derives `shop`, `topic`, and `webhook_id` directly from unauthenticated HTTP headers, while `Utils::HmacValidator.validate` only verifies the HMAC over the raw request body. `Registry.process` trusts `request.shop` as the tenant identity and hands it straight to the app's webhook handler without any cross-check against the signed payload, breaking the intended binding `shop_authenticated == shop_acted_on`.

### Finding Description
`Request#to_signable_string` returns only `@raw_body`: [1](#0-0) 

`Request#shop`, `#topic`, and `#webhook_id` are read straight from HTTP headers that are never mixed into the signable string: [2](#0-1) 

`HmacValidator.validate` computes the signature purely from `verifiable_query.to_signable_string` (i.e. the body) and compares it against the `hmac` header: [3](#0-2) 

`Registry.process` uses this HMAC check as the sole authentication gate, then forwards `request.shop` (and `request.topic`, `request.webhook_id`) to the app's handler as trusted tenant identity, with no verification that the shop header actually matches the shop that produced/owns the signed body: [4](#0-3) 

Because the HMAC only binds the body, an unprivileged holder of a valid `(body, hmac)` pair — obtainable, for example, from any shop where the attacker has installed the app and received a genuine webhook — can replay that exact body/HMAC to the app's webhook endpoint while substituting an arbitrary `x-shopify-shop-domain` header (e.g. a victim's shop). `Utils::HmacValidator.validate` still returns `true` because it never inspects the shop header, and `Registry.process` will invoke the handler believing the event originated from the victim's shop. Equality that should hold — "shop whose secret produced this signature" == "shop attributed to this webhook by the gem" — is broken.

### Impact Explanation
This is a cross-tenant identity confusion: the app-level webhook handler (uninstall/GDPR/data-sync handlers keyed by shop) receives a `WebhookMetadata` with a `shop` value that was never actually bound by the cryptographic proof the gem performed. An attacker controlling one legitimate installation can forge webhook events "from" another merchant's shop, causing the host application to act on/against the wrong tenant (e.g. triggering app-uninstall cleanup, GDPR data erasure, or state changes) — a cross-tenant access impact.

### Likelihood Explanation
Requires only an unprivileged party who has installed the app on any shop (to obtain one genuine `(body, hmac)` pair) and the ability to send an HTTP request to the app's public webhook endpoint with a modified `x-shopify-shop-domain`/`shopify-shop-domain` header — no access token, `client_secret`, or privileged credential is needed, since the HMAC secret itself is never involved in producing the spoofed shop value.

### Recommendation
Include `shop`, `topic`, and `webhook_id` in the value that is HMAC-verified (or otherwise cryptographically bind them to the body, e.g. by requiring the host app to cross-check the shop header against a known/registered shop for that webhook subscription) before trusting `request.shop` in `Registry.process`/`WebhookMetadata`.

### Proof of Concept
1. Install the app on `attacker-shop.myshopify.com`; capture a genuine webhook delivery `{raw_body, x-shopify-hmac-sha256}`.
2. Send a POST to the app's webhook endpoint with the same `raw_body` and `x-shopify-hmac-sha256`, but set `x-shopify-shop-domain: victim-shop.myshopify.com`.
3. `Utils::HmacValidator.validate(request)` in `lib/shopify_api/webhooks/registry.rb#process` returns `true` because it only checks the body-derived signature.
4. The handler receives `WebhookMetadata` with `shop == "victim-shop.myshopify.com"` and processes the event as if it came from the victim shop.

          if result || Context.old_api_secret_key.nil? || T.must(Context.old_api_secret_key).empty?

            validate_signature(verifiable_query, T.must(Context.old_api_secret_key))
          end
        end

        def validate_signature(verifiable_query, secret)
          received_signature = verifiable_query.hmac
          computed_signature = compute_signature(verifiable_query.to_signable_string, secret)
          OpenSSL.secure_compare(computed_signature, T.must(received_signature))
        end
