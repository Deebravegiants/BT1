### Title
Unbounded on-chain allowlist causes linear-scan cost growth in Vault request authorization, enabling authorization-path DoS - ([File: core/capabilities/vault/allow_list_based_auth.go])

### Summary
`allowListBasedAuth.AuthorizeRequest` authorizes every incoming Vault gateway request by linearly scanning the full in-memory slice of allowlisted requests synced from the `WorkflowRegistry` contract. That slice (`w.allowListedRequests` in `core/services/workflows/syncer/v2/workflow_registry.go`) is only pruned by expiry and grows without any cap as owners call `AllowlistRequest` on-chain. This mirrors the reported `StakingModule._claim()` bug class: an unbounded, attacker-influenceable collection iterated on every user-facing call, which can degrade or block the authorization hot path used by unprivileged clients.

### Finding Description
`AuthorizeRequest` computes a digest for the incoming request and calls `findAllowlistedItemWithRetry`, which repeatedly calls `fetchAllowlistedItem` — an O(n) linear scan over `allowedRequests` — up to `retryCount+1` times with sleeps in between: [1](#0-0) [2](#0-1) 

The source data `allowedRequests` comes from `WorkflowRegistrySyncer.GetAllowlistedRequests`, whose backing store is `workflowRegistry.allowListedRequests`, populated by `syncAllowlistedRequests`. This function only removes entries once their `ExpiryTimestamp` has passed; new entries are appended unconditionally every tick with no upper bound on total active count: [3](#0-2) 

The entries originate from the `AllowlistRequest` transaction on `WorkflowRegistry`, callable by any linked workflow owner (an unprivileged/user-level actor relative to the node), with an owner-chosen `expiryTimestamp`: [4](#0-3) [5](#0-4) 

No cap on the number of active (non-expired) allowlist entries per owner or globally is present in the indexed Go code; the only bound found is `MaxResultsPerQuery` (1,000), which merely paginates the *fetch* from the contract, not the total size retained in memory: [6](#0-5) [7](#0-6) 

Because `AuthorizeRequest` runs on every Vault request path and performs this O(n) scan up to 11 times per call (`retryCount = 10`), a large accumulated allowlist (built by any owner submitting many `AllowlistRequest` transactions with far-future expiries) increases CPU cost per authorization call linearly with the number of active entries, on every Vault DON node, for every incoming request — not just the attacker's own.

### Impact Explanation
This is analogous to the reported issue: an unbounded collection populated by ordinary (unprivileged) actors is iterated synchronously on a critical, user-facing authorization path. Unlike the original `StakingModule` bug, this does not have a hard revert threshold from a single call, but it degrades a shared authentication path used to gate Vault secret operations for the whole DON — an availability/DoS risk on the Vault gateway's request authorization, which could stall or slow legitimate secret creation/consumption if the allowlist is inflated.

### Likelihood Explanation
Requires no privileged role — any address that has linked ownership can call `AllowlistRequest` repeatedly with distinct digests and long expiries, growing the in-memory list indefinitely since pruning is expiry-based only. The cost is gas to submit many transactions, which is a real but not prohibitive economic barrier; it is lower-likelihood than a free-loop DoS but still a legitimate resource-growth vector directly reachable by unprivileged users through documented contract methods.

### Recommendation
- Enforce an on-chain/off-chain cap on the number of active (non-expired) allowlist entries per owner (and/or globally), rejecting new `AllowlistRequest` calls beyond the cap.
- Replace the linear scan in `fetchAllowlistedItem` with a map/set lookup keyed by digest instead of scanning a slice, to make lookups O(1) regardless of collection size.
- Consider bounding retry/backoff cost in `findAllowlistedItemWithRetry` independent of allowlist size, and add metrics/alerts on allowlist size growth to detect abuse early.

### Proof of Concept
1. An attacker links ownership on `WorkflowRegistry` (a normal, unprivileged onboarding step).
2. The attacker repeatedly calls `AllowlistRequest` with unique random digests and expiry timestamps far in the future (e.g., 1 year), submitting many transactions over time (cost bound only by gas).
3. `workflowRegistry.syncAllowlistedRequests` (`core/services/workflows/syncer/v2/workflow_registry.go:766-803`) syncs and retains all of these because none has expired, growing `w.allowListedRequests` without bound.
4. Every subsequent Vault request from any user triggers `allowListBasedAuth.AuthorizeRequest` → `findAllowlistedItemWithRetry` → `fetchAllowlistedItem`, each performing an O(n) scan over the bloated list, up to 11 times per authorization attempt (`allowListBasedAuthRetryCount = 10`), increasing latency/CPU load for all Vault DON authorization traffic.

func (r *allowListBasedAuth) findAllowlistedItemWithRetry(ctx context.Context, req jsonrpc.Request[json.RawMessage], requestDigest string, requestDigestBytes32 [32]byte) (*workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest, []string, error) {
	for attempt := 0; attempt <= r.retryCount; attempt++ {
		allowedRequests := r.workflowRegistrySyncer.GetAllowlistedRequests(ctx)
		allowedRequestsStrs := make([]string, 0, len(allowedRequests))
		for _, rr := range allowedRequests {
			allowedReqStr := fmt.Sprintf("AuthorizedOwner: %s, RequestDigest: %s, ExpiryTimestamp: %d", rr.Owner.Hex(), hex.EncodeToString(rr.RequestDigest[:]), rr.ExpiryTimestamp)
			allowedRequestsStrs = append(allowedRequestsStrs, allowedReqStr)
		}
		r.lggr.Debugw("AllowListBasedAuth loaded allowlisted requests", "method", req.Method, "requestID", req.ID, "attempt", attempt+1, "allowedRequests", allowedRequestsStrs)

		allowlistedRequest := r.fetchAllowlistedItem(allowedRequests, requestDigestBytes32)
		if allowlistedRequest != nil {
			return allowlistedRequest, allowedRequestsStrs, nil
		}
		if attempt == r.retryCount {
			return nil, allowedRequestsStrs, nil
		}

		r.lggr.Debugw("AllowListBasedAuth request digest not yet allowlisted, retrying",
			"method", req.Method,
			"requestID", req.ID,
			"digestHexStr", requestDigest,
			"attempt", attempt+1,
			"maxAttempts", r.retryCount+1,
			"retryInterval", r.retryInterval)
		if err := sleepWithContext(ctx, r.retryInterval); err != nil {
			r.lggr.Debugw("AllowListBasedAuth retry canceled", "method", req.Method, "requestID", req.ID, "error", err)
			return nil, nil, err
		}
	}

	return nil, nil, nil // unreachable: loop always returns
}

func (w *workflowRegistry) syncAllowlistedRequests(ctx context.Context) {
	ticker := w.getTicker(defaultTickIntervalForAllowlistedRequests)
	w.lggr.Debug("starting syncAllowlistedRequests")
	for {
		select {
		case <-ctx.Done():
			w.lggr.Debug("shutting down syncAllowlistedRequests, %s", ctx.Err())
			return
		case <-ticker:
			newAllowListedRequests, totalAllowlistedRequests, head, err := w.getAllowlistedRequests(ctx, w.contractReader)
			if err != nil {
				w.lggr.Errorw("failed to call getAllowlistedRequests", "err", err)
				continue
			}
			w.allowListedMu.Lock()
			// Prune expired requests
			activeAllowlistedRequests := []workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest{}
			expiredRequestsCount := 0
			for _, request := range w.allowListedRequests {
				if int64(request.ExpiryTimestamp) > time.Now().Unix() {
					activeAllowlistedRequests = append(activeAllowlistedRequests, request)
				} else {
					expiredRequestsCount++
				}
			}

			// Add new requests
			activeAllowlistedRequests = append(activeAllowlistedRequests, newAllowListedRequests...)
			w.allowListedRequests = activeAllowlistedRequests
			w.lastSeenAllowlistedRequestsCount = totalAllowlistedRequests
			w.lggr.Debugw("synced allowlisted requests",
				"newRequestsNum", len(newAllowListedRequests),
				"expiredRequestsNum", expiredRequestsCount,
				"activeRequestsNum", len(w.allowListedRequests),
				"lastSeenOnchainRequestsNum", w.lastSeenAllowlistedRequestsCount,
				"blockHeight", head.Height,
			)
			w.allowListedMu.Unlock()

	totalAllowlistedRequestsBefore, err := wfRegC.TotalAllowlistedRequests(&bind.CallOpts{

	})

		From: th.ContractsOwner.From,
