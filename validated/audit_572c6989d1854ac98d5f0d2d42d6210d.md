## Title
Stale `TombStone` from a prior soft-burn allows a former owner to reclaim an object legitimately transferred to and later sent to `BURN_ADDRESS` by a new, unrelated owner - (File: `aptos-move/framework/aptos-framework/sources/object.move`)

### Summary
`object::burn` performs a "soft burn": it attaches a `TombStone{original_owner}` resource to the object but does **not** change `ObjectCore.owner`, and does not disable `allow_ungated_transfer`. The object can therefore continue to be transferred normally afterward. However, ordinary ownership transfers (`transfer`, `transfer_raw`, `transfer_call`, `transfer_to_object`) never clear a pre-existing `TombStone`. Only `transfer_with_ref` (the `LinearTransferRef` path) clears it. If a formerly-burning owner transfers the object away and the new owner later sends the object to the literal `BURN_ADDRESS` (e.g. as their own burn/cleanup action), `unburn` will let the *original* (stale) `TombStone.original_owner` reclaim the object instead of the actual last owner, silently reassigning custody of the object.

### Finding Description
The relevant state and functions: [1](#0-0) 

`burn` only adds a `TombStone`; it leaves `owner` and `allow_ungated_transfer` untouched: [2](#0-1) 

Ordinary transfer paths (`transfer`, `transfer_call`, `transfer_to_object` all route through `transfer_raw` → `transfer_raw_inner`) update `owner` but never inspect or clear `TombStone`: [3](#0-2) 

Only the `LinearTransferRef` path explicitly clears a stale `TombStone` before transferring, precisely because its author was aware that a stale tombstone is dangerous ("Undo soft burn if present as we don't want the original owner to be able to reclaim by calling unburn later."): [4](#0-3) 

`unburn` grants a reclaim path keyed off `TombStone.original_owner` whenever the object's current owner is `BURN_ADDRESS`, with no check that the *current* real owner (the one who actually sent it to `BURN_ADDRESS`) is the same as `TombStone.original_owner`: [5](#0-4) 

Attack sequence:
1. Alice owns object `O`, calls `burn(alice, O)` → `TombStone{original_owner: alice}` is attached; `O.owner` stays `alice` (soft burn, no ownership change).
2. Alice transfers `O` to Bob via the normal, unprivileged `object::transfer` entry function (ungated transfer is still allowed; nothing checks/clears `TombStone`). `O.owner` becomes `bob`. The stale `TombStone{original_owner: alice}` remains attached to the object.
3. Bob, as the new legitimate owner, later sends `O` to the literal `BURN_ADDRESS` constant via plain `object::transfer(bob, O, BURN_ADDRESS)` (this is a normal, unprivileged path any owner can call directly, independent of the "soft burn" API, and is in fact how burning worked historically / how `TombStone`+`BURN_ADDRESS` combo is documented to work in `unburn`).
4. Alice calls `unburn(alice, O)`. Since `O.owner == BURN_ADDRESS` and the stale `TombStone.original_owner == alice`, the assertion passes and `O` is transferred back to Alice — even though Alice had no ownership claim at the time Bob sent it to the burn address.

This breaks the custody invariant that only the actual current owner (or someone they explicitly authorized) can determine the eventual disposition/recipient of an object once it reaches the burn address; a prior, already-divested owner regains control instead.

### Impact Explanation
This is an unauthorized ownership-reassignment / custody-takeover of any object (NFT, code object, or object holding a fungible asset store, etc.) whose ownership chain includes a soft-burn-then-transfer step followed by any subsequent transfer to `BURN_ADDRESS` by a later owner. The impact is direct theft of the object (and any value/assets held at that object address) by a previous owner who no longer has any legitimate claim, which matches the custody-impact gate ("Theft ... or owner reassignment of ... token objects, or other object-held value").

### Likelihood Explanation
The precondition (an object being burned once, transferred away, and later sent to `BURN_ADDRESS` again by a different owner) is a plausible real-world sequence: `BURN_ADDRESS` is a well-known, callable literal constant, and many users/protocols may intentionally send objects there to signal burning without knowing this exact `TombStone` mechanic, or without realizing an old `TombStone` survives ownership transfers. Since `burn`/`unburn` and plain `transfer` are all public, unprivileged entry points, no special privileges are required to set up or trigger the exploit — only the initial victim (the later legitimate owner, Bob) needs to send the object to `BURN_ADDRESS`, a common disposal pattern.

### Recommendation
Clear any existing `TombStone` on every ownership-changing path, not just `transfer_with_ref`. Specifically, `transfer_raw_inner` (or `transfer_raw`) should remove a stale `TombStone` whenever `object_core.owner` changes, mirroring the logic already present in `transfer_with_ref`. Alternatively, `unburn`'s `BURN_ADDRESS` branch should additionally verify that no intervening non-tombstone-aware transfer occurred (e.g., by recording the owner active at burn time and requiring it match immediately prior to the `BURN_ADDRESS` transfer), or disallow reaching `BURN_ADDRESS` through untracked transfer paths altogether.

### Proof of Concept
```move
// Step 1: Alice burns (soft-burn only, owner stays alice)
object::burn(&alice, obj);                       // TombStone{original_owner: alice} attached

// Step 2: Alice sells/transfers the (still-tombstoned) object to Bob normally
object::transfer(&alice, obj, signer::address_of(&bob));   // owner = bob, TombStone untouched

// Step 3: Bob, unaware of stale tombstone, sends the object to the burn address
object::transfer_call(&bob, object::object_address(&obj), object::burn_address()); // owner = BURN_ADDRESS

// Step 4: Alice reclaims Bob's object using the stale tombstone
object::unburn(&alice, obj);   // succeeds: owner becomes alice again, Bob's ownership is stolen
```

    /// Transfer to the destination address using a LinearTransferRef.
    public fun transfer_with_ref(self: LinearTransferRef, to: address) {
        assert!(!exists<Untransferable>(self.self), error::permission_denied(EOBJECT_NOT_TRANSFERRABLE));

        // Undo soft burn if present as we don't want the original owner to be able to reclaim by calling unburn later.
        if (exists<TombStone>(self.self)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(self.self);
        };

        let object = borrow_global_mut<ObjectCore>(self.self);
        assert!(
            object.owner == self.owner,
            error::permission_denied(ENOT_OBJECT_OWNER),
        );
        event::emit(
            Transfer {
                object: self.self,
                from: object.owner,
                to,
            },
        );
        object.owner = to;
    }

    inline fun transfer_raw_inner(object: address, to: address) {
        let object_core = borrow_global_mut<ObjectCore>(object);
        if (object_core.owner != to) {
            event::emit(
                Transfer {
                    object,
                    from: object_core.owner,
                    to,
                },
            );
            object_core.owner = to;
        };

    /// Add a TombStone to the object.  The object will then be interpreted as hidden via indexers.
    /// This only works for objects directly owned and for simplicity does not apply to indirectly owned objects.
    /// Original owners can reclaim burnt objects any time in the future by calling unburn.
    /// Please use the test only [`object::burn_object_with_transfer`] for testing with previously burned objects.
    public entry fun burn<T: key>(owner: &signer, object: Object<T>) {
        let original_owner = signer::address_of(owner);
        assert!(is_owner(object, original_owner), error::permission_denied(ENOT_OBJECT_OWNER));
        let object_addr = object.inner;
        assert!(!exists<TombStone>(object_addr), EOBJECT_ALREADY_BURNT);
        move_to(&create_signer(object_addr), TombStone { original_owner });
    }

    /// Allow origin owners to reclaim any objects they previous burnt.
    public entry fun unburn<T: key>(
        original_owner: &signer,
        object: Object<T>,
    ) {
        let object_addr = object.inner;
        assert!(exists<TombStone>(object_addr), error::invalid_argument(EOBJECT_NOT_BURNT));

        // The new owner of the object can always unburn it, but if it's the burn address, we go to the old functionality
        let object_core = borrow_global<ObjectCore>(object_addr);
        if (object_core.owner == signer::address_of(original_owner)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object_addr);
        } else if (object_core.owner == BURN_ADDRESS) {
            // The old functionality
            let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
            assert!(
                original_owner_addr == signer::address_of(original_owner),
                error::permission_denied(ENOT_OBJECT_OWNER)
            );
            transfer_raw_inner(object_addr, original_owner_addr);
        } else {
            abort error::permission_denied(ENOT_OBJECT_OWNER);
        };
    }
