### Title
Unbounded router call + unlimited approval in `ExternalActionSwap.swap` lets a caller sweep any stranded token balance into their own output UTXO - (File: `contracts/external-actions/swaps/ExternalActionSwap.sol`)

### Summary
`ExternalActionSwap.swap()` never verifies that the router actually consumed only the `inputAmount` that Hinkal transferred to the action for the current transaction. Because `LifiExternalAction.callRouter` grants the router an unlimited, persistent ERC20 approval and then forwards fully attacker-controlled `externalActionMetadata` bytes to it, any residual/stranded balance of `inputToken` sitting in the action contract (from a prior transaction's dust, from an unused extra token index, or from any other source) can be pulled by the router and swapped together with the current transaction's declared input. The resulting inflated `swappedAmount` is credited entirely to `msg.sender` as a single output UTXO, exceeding the value backed by that transaction's own `-deltaAmountChanges`.

### Finding Description
Broken equality: *tokens leaving the action in transaction T == `-deltaAmountChanges` Hinkal sent to the action in transaction T*. In practice, tokens leaving the action can include leftover balance from a different transaction because nothing ties the router's actual consumption of `inputToken` to the current call's `inputAmount`.

Code path:
- `contracts/Hinkal.sol` `_externalTransact` (`contracts/Hinkal.sol:244-261`) transfers `-deltaAmountChanges[i]` of every negative-delta token to the action address, then calls `runAction`.
- `ExternalActionSwap.swap` (`contracts/external-actions/swaps/ExternalActionSwap.sol:40-102`) only reads `erc20TokenAddresses[0]` (input) and `[1]` (output); it computes `inputAmount` from `deltaAmounts[0]` but never checks the action's actual `inputToken` balance before/after the swap.
- `LifiExternalAction.callRouter` (`contracts/external-actions/swaps/LifiExternalAction.sol:16-36`) calls `approveUnlimited(inputToken, router)` (persistent, not reset per-call — `contracts/TransfererBase.sol:32-43`) and then executes `router.call(externalActionMetadata)` — calldata fully supplied by the caller via `circomData.externalActionData.externalActionMetadata`. `swappedAmount` is measured solely as the `outputToken` balance delta around this call; `inputAmount` is not even passed to the router call for the ERC20 branch.
- Back in `swap()`, the entire measured `swappedAmount` (minus fees) is sent to `msg.sender` (Hinkal, in the call context) and wrapped as one `UTXO` credited to the caller (`contracts/external-actions/swaps/ExternalActionSwap.sol:93-101`).

Because the router's unlimited approval persists across transactions and the calldata is attacker-controlled, any balance of `inputToken` already sitting in the action contract (e.g., stranded because a prior transaction supplied a 3rd token address with a negative delta that `swap()` never consumes/returns, or ordinary swap dust) can be included in a subsequent `router.call` invocation and swapped alongside the new transaction's own `inputAmount`. `Hinkal.sol`'s own invariant check (`contracts/Hinkal.sol:97-146`, `balanceDif == amountChanges[i] + utxoAmount`) only verifies Hinkal's own balance change against what it recorded as sent/received in *that* transaction — it has no way to detect that the action's output was inflated by unrelated stranded funds, since that cross-token/cross-transaction linkage is never constrained by the circuit (`inTotal + amountChanges === outTotal` in `circuits/MainEVMCircuit.circom:168` is per-token, per-transaction only) nor by the action contract.

Attacker's exact call: craft a `CircomData` for a swap transaction (`externalActionData.externalActionId` pointing to `LifiExternalAction`) with `erc20TokenAddresses` optionally containing an extra token index whose negative delta strands funds in the action (or simply wait for organic dust from any prior swap), then in a follow-up transaction supply `externalActionMetadata` that instructs the LI.FI router to pull and swap the action's *entire* `inputToken` balance (using the pre-existing unlimited approval) rather than only the newly-transferred `inputAmount`.

### Impact Explanation
The caller receives an output UTXO backed by more value than their transaction's own `-deltaAmountChanges` recorded — direct theft of funds parked in the action by a prior/unrelated transaction (dust, rounding leftovers, or funds stranded via the unused extra-token-index path). This is repeatable every time residual balance accumulates in the action contract, and is a direct theft-of-user/protocol-parked-funds primitive, matching Critical severity (direct theft of in-flight funds).

### Likelihood Explanation
The attacker only needs to be an ordinary Hinkal user able to submit a `transact` call to an `ExternalActionSwap`-derived action (e.g., `LifiExternalAction`), fully controls `externalActionMetadata`, and needs some residual balance to already exist in the action (which can arise naturally from swap dust/rounding across any user's transactions, or be self-seeded by the same attacker using the unused extra-token-index gap). No privileged role is required. Cost is a single transaction; the technique is repeatable indefinitely as dust accumulates.

### Recommendation
In `ExternalActionSwap.swap`/`callRouter`, measure and require that the `inputToken` balance of the action decreased by exactly `inputAmount` (not less, not more) after the router call, rather than trusting attacker-controlled calldata plus an unlimited approval. Alternatively, use exact, per-call `approve(router, inputAmount)` instead of `approveUnlimited`, and revoke/reset it after the swap so no persistent allowance survives between transactions. Sweep any genuinely unconsumed residual balance to relay/owner rather than allowing it to be silently pulled by a future arbitrary call.

### Proof of Concept
Foundry plan:
1. Deploy `LifiExternalAction` with a mock router that: (a) on first call, only partially swaps (leaves `inputToken` residual in the action) or accept a crafted `CircomData` with a 3rd token index whose negative delta is transferred to the action but never consumed by `swap()`; (b) on a second call, accepts calldata that pulls the action's *entire* `inputToken` balance (via the standing unlimited approval) and swaps all of it to `outputToken`.
2. Transaction 1 (attacker or victim): call `Hinkal.transact` with a swap `CircomData` whose declared `inputAmount` is `X`; verify action's `inputToken` balance after tx1 is `X - consumedByRouter > 0` (residual `R` stranded).
3. Transaction 2 (attacker, different/same address): call `Hinkal.transact` with a swap declaring a tiny `inputAmount` `Y << R`, but with `externalActionMetadata` that causes the mock router to swap `Y + R` of `inputToken`.

        CircomData calldata circomData,

            inputAmount -= circomData.feeStructure.flatFee;

            circomData.slippageValues[1] != 0,
            "swap output slippage floor not set"
        );

        require(
            block.timestamp <= circomData.timeStamp + SWAP_DEADLINE_WINDOW,
            "swap expired"
        );

        uint256 swappedAmount = callRouter(
            inputToken,
            inputAmount,
            outputToken,
            circomData.externalActionData.externalActionMetadata
        );

        uint256 relayFee = circomData.feeStructure.flatFee;

        uint256 hinkalFee = hinkalHelper.calculateRelayFee(
            swappedAmount,
            0,

        if (circomData.feeStructure.feeToken == outputToken) {
            sendToRelay(circomData.relay, relayFee + hinkalFee, outputToken);

    function callRouter(
        address inputToken,
        uint256 inputAmount,
        address outputToken,
        bytes calldata externalActionMetadata
    ) internal override returns (uint256 swappedAmount) {
        uint256 balanceBefore = getERC20OrETHBalance(outputToken);

        if (inputToken == address(0)) {
            (bool success, ) = router.call{value: inputAmount}(
                externalActionMetadata
            );
            require(success, "LI.FI swap failed: native coin");
        } else {
            approveUnlimited(inputToken, router);
            (bool success, ) = router.call(externalActionMetadata);
            require(success, "LI.FI swap failed: erc-20 token");
        }

        swappedAmount = getERC20OrETHBalance(outputToken) - balanceBefore;
    }
