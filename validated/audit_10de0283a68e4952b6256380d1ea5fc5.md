Audit Report

## Title
Unvalidated nil `req.Params` dereference in Vault gateway `PublicKeyGet` path causes node-crashing panic - (File: core/capabilities/vault/gw_handler.go)

## Summary
`GatewayHandler.HandleGatewayMessage` dispatches `vaulttypes.MethodPublicKeyGet` directly to `handlePublicKeyGet` without running it through `GatewayVaultRequestProcessor.ProcessRequest`, unlike `SecretsCreate`/`SecretsUpdate`/`SecretsDelete`/`SecretsList`. [1](#0-0)  `handlePublicKeyGet` immediately dereferences `*req.Params` with no nil check. [2](#0-1)  This is reachable end-to-end from an unauthenticated user, since the gateway-side `HandleJSONRPCUserMessage` forwards `PublicKeyGet` requests to nodes via `fanOutToVaultNodes`/`don.SendToNode` without ever validating that `req.Params` is non-nil. [3](#0-2) 

## Finding Description
On the gateway side, `handler.HandleJSONRPCUserMessage` special-cases `MethodPublicKeyGet` to skip the authorization/`ProcessRequest` pipeline entirely ("Public key requests don't require authorization") and, on a cache miss, calls `h.handlePublicKeyGet(ctx, ar)` which ultimately calls `fanOutToVaultNodes`, forwarding the raw client-supplied `jsonrpc.Request[json.RawMessage]` (including a possibly-nil `Params`) unmodified to every DON node via `h.don.SendToNode(ctx, node.Address, &ar.req)`. [4](#0-3) [5](#0-4)  No code path in `HandleJSONRPCUserMessage` checks `req.Params == nil` for this method, unlike the `InvalidVaultParamsError` params-nil guard used inside `GatewayVaultRequestProcessor` for the authorized methods. [6](#0-5) 

On the node side, `gatewayConnector.readLoop` decodes the incoming message into `jsonrpc.Request[json.RawMessage]` and calls `handler.HandleGatewayMessage` synchronously with no `recover()` around the dispatch. [7](#0-6)  A search of the gateway connector and handler packages found no `recover()` calls protecting this dispatch path. `GatewayHandler.HandleGatewayMessage` routes `MethodPublicKeyGet` straight to `handlePublicKeyGet` without going through `requestProcessor.ProcessRequest` (contrast with the `SecretsCreate/Update/Delete/List` branches). [8](#0-7)  `handlePublicKeyGet` then executes `json.Unmarshal(*req.Params, r)`, dereferencing a `*json.RawMessage` that can be `nil` if the client omits/nulls `params`. [2](#0-1)  This differs from `handleSecretsDelete`/`handleSecretsList`, which are only reached after `ProcessRequest` has already validated `req.Params != nil`. [9](#0-8) 

Because Go panics propagate up an unrecovered goroutine and terminate the whole process, a nil-pointer dereference here crashes the entire node, not just the single request.

## Impact Explanation
An external, unauthenticated client that can reach a Gateway's public vault HTTP/JSON-RPC endpoint can send a `vault_publicKeyGet` request with `params` omitted or `null`. The gateway forwards this unmodified to every node in the DON with no params validation for this method, and each node panics inside its un-recovered connector read loop, crashing the node process. This is a remote, pre-authentication denial-of-service against node/DON availability, matching an in-scope "unauthenticated node crash / DoS via malformed gateway message" impact class. The gateway itself explicitly documents that `PublicKeyGet` intentionally bypasses authorization ("Public key requests don't require authorization"), confirming no auth middleware stands between an arbitrary client and this vulnerable code path. [10](#0-9) 

## Likelihood Explanation
Triggering this requires no credentials, allowlist membership, or JWT — only the ability to send an HTTP request to the gateway's public vault endpoint (`vault_publicKeyGet` with `params: null` or omitted). This is a trivial, single-request, repeatable attack against every node in the DON simultaneously since the gateway fans the request out to all `donConfig.Members`. [11](#0-10)  The only mitigating factor is the gateway's public-key response cache: if a valid cached response already exists (`getCachedPublicKey`), the malicious request is served from cache instead of being forwarded to nodes. [3](#0-2)  However, on a fresh/restarted gateway, or after cache expiry/before first successful fetch, the forward-to-nodes path is taken every time, making this reliably reproducible.

## Recommendation
1. Add a `req.Params == nil` guard in `handlePublicKeyGet` in `core/capabilities/vault/gw_handler.go`, returning a `UserMessageParseError` response instead of dereferencing a nil pointer.
2. Add the same guard in the gateway-side `handler.HandleJSONRPCUserMessage`/`handlePublicKeyGet` in `core/services/gateway/handlers/vault/handler.go` before forwarding to nodes, so malformed requests are rejected at the gateway instead of being fanned out to every DON node.
3. Audit all other `GatewayHandler` methods dispatched outside `GatewayVaultRequestProcessor.ProcessRequest` for the same nil-params dereference class of bug.
4. Wrap the per-message handler dispatch in `gatewayConnector.readLoop` (`core/services/gateway/connector/connector.go`) with `recover()` so a panic in any single handler cannot crash the entire node process, as defense in depth.

## Proof of Concept
1. As an external client with no credentials, send an HTTP/JSON-RPC request to the gateway's vault endpoint:
```json
{"jsonrpc":"2.0","id":"1","method":"vault_publicKeyGet"}
```
(no `"params"` key, or `"params": null`), on a gateway instance where `cachedPublicKeyGetResponse` is not yet populated (e.g., freshly started gateway).
2. `handler.HandleJSONRPCUserMessage` detects `req.Method == vaulttypes.MethodPublicKeyGet`, finds no cached response, and calls `handlePublicKeyGet` → `fanOutToVaultNodes` → `don.SendToNode` for every node in the DON, forwarding the request with `Params == nil` unmodified.
3. Each node's `gatewayConnector.readLoop` decodes the message and calls `GatewayHandler.HandleGatewayMessage`, which dispatches to `handlePublicKeyGet`.
4. `json.Unmarshal(*req.Params, r)` dereferences a nil `*json.RawMessage`, panicking inside the un-recovered `readLoop` goroutine and crashing each node process.
5. A Go unit test can directly confirm the unguarded dereference by calling `GatewayHandler.handlePublicKeyGet` (or `HandleGatewayMessage`) with a `jsonrpc.Request[json.RawMessage]{Method: vaulttypes.MethodPublicKeyGet, Params: nil}` and observing a panic, and a corresponding test on `handler.HandleJSONRPCUserMessage` in `core/services/gateway/handlers/vault/handler.go` confirming it forwards such a request to `SendToNode` without rejecting it first.

func (h *GatewayHandler) handleSecretsDelete(ctx context.Context, gatewayID string, req *jsonrpc.Request[json.RawMessage]) *jsonrpc.Response[json.RawMessage] {
	r := &vaultcommon.DeleteSecretsRequest{}
	if err := json.Unmarshal(*req.Params, r); err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.UserMessageParseError, err)
	}

	h.lggr.Debugw("Processing authorized delete secrets request", "request", r.String())
	resp, err := h.secretsService.DeleteSecrets(ctx, r)
	if err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.HandlerError, fmt.Errorf("failed to delete secrets: %w", err))
	}

	resultBytes, err := resp.ToJSONRPCResult()
	if err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.NodeReponseEncodingError, err)
	}

	return &jsonrpc.Response[json.RawMessage]{
		Version: jsonrpc.JsonRpcVersion,
		ID:      req.ID,
		Method:  req.Method,
		Result:  (*json.RawMessage)(&resultBytes),
	}
}

func (h *handler) handlePublicKeyGet(ctx context.Context, ar *activeRequest) error {
	l := logger.With(h.lggr, "method", ar.req.Method, "requestID", ar.req.ID)

	publicKeyResponseBytes, cachedPublicKey := h.getCachedPublicKey()
	if cachedPublicKey != nil {
		l.Debugw("returning cached public key response")
		return h.sendSuccessResponse(ctx, l, ar, &jsonrpc.Response[json.RawMessage]{
			Version: jsonrpc.JsonRpcVersion,
			ID:      ar.req.ID,
			Method:  ar.req.Method,
			Result:  (*json.RawMessage)(&publicKeyResponseBytes),
		})
	}

	l.Debugw("cache stale: forwarding request to nodes", "now", h.clock.Now())
	return h.fanOutToVaultNodes(ctx, l, ar)
}

func (h *handler) fanOutToVaultNodes(ctx context.Context, l logger.Logger, ar *activeRequest) error {
	var nodeErrors []error
	for _, node := range h.donConfig.Members {
		err := h.don.SendToNode(ctx, node.Address, &ar.req)
		if err != nil {
			nodeErrors = append(nodeErrors, err)
			l.Errorw("error sending request to node", "node", node.Address, "error", err)
		}
	}

	if len(nodeErrors) == len(h.donConfig.Members) && len(nodeErrors) > 0 {
		return h.sendResponse(ctx, ar, h.errorResponse(ar.req, api.FatalError, errors.New("failed to forward user request to nodes"), nil))
	}

	l.Debugw("successfully forwarded request to Vault nodes")
	return nil
}

func (c *gatewayConnector) readLoop(gatewayState *gatewayState) {
	defer c.closeWait.Done()
	ctx, cancel := c.shutdownCh.NewCtx()
	defer cancel()

	for {
		select {
		case <-c.shutdownCh:
			return
		case item := <-gatewayState.conn.ReadChannel():
			var req jsonrpc.Request[json.RawMessage]
			err := json.Unmarshal(item.Data, &req)
			if err != nil {
				c.lggr.Errorw("parse error when reading from Gateway", "id", gatewayState.config.ID, "err", err)
				break
			}
			c.handlersMu.RLock()
			handler, exists := c.handlers[req.Method]
			c.handlersMu.RUnlock()
			if !exists {
				c.lggr.Errorw("no handler for method", "id", gatewayState.config.ID, "method", req.Method)
				break
			}
			// do not break on error. HandleGatewayMessage handles errors
			// by sending a response back to the Gateway.
			err = handler.HandleGatewayMessage(ctx, gatewayState.config.ID, &req)
			if err != nil {
				c.lggr.Warnw("failed to handle message from Gateway", "id", gatewayState.config.ID, "method", req.Method, "err", err)
			}
		}
	}
