## Title
Dangerous 1:1 stablecoin price assumption in intent bid ranking allows a solver to extract value from users during depegs - (File: `sdk/packages/sdk/src/protocols/intents/BidManager.ts`)

### Summary
`BidManager` prices and ranks competing solver bids for `IntentGateway` orders. When an order's outputs are entirely USDC/USDT, it uses `isStableToken`/`computeStablesUsdValue`/`sortAllStables`, which treat every USDC and USDT amount as worth exactly $1, regardless of actual market price. This mirrors the reported "1 rETH = 1 ETH" bug class: a hard-coded 1:1 price assumption between two related-but-not-identical assets that can temporarily diverge, and that assumption directly drives on-chain value transfer decisions (which bid the user signs and executes).

### Finding Description
`isStableToken` classifies any output token as "stable" if it matches the chain's configured USDC or USDT address: [1](#0-0) 

`computeStablesUsdValue` then sums amounts normalized only by decimals, with no actual price lookup — 1 USDC and 1 USDT are always summed as $1 each: [2](#0-1) 

`sortAllStables` (invoked from `sortBids` whenever every output asset is USDC/USDT) ranks competing solver bids purely by this par-value sum: [3](#0-2) [4](#0-3) 

This is the exact bug class from the external report: USDC and USDT are related but distinct assets whose market prices can diverge (e.g. during a depeg event), yet the code hard-codes a 1:1 USD-parity assumption when comparing solver bids that a user is about to accept and execute on-chain via `Bid.execute()`.

### Impact Explanation
The Intent Gateway flow is: "the user reviews all bids and selects the `UserOperation` that gives them the most assets" (per the protocol docs), and the SDK's `sortBids`/`sortAllStables` is the mechanism that ranks bids and is expected to always surface the best available offer. If USDT trades below $1 (a historically observed, non-hypothetical event), a solver can:
1. Post a bid that satisfies the order using depegged USDT instead of USDC, at the same nominal amount as a competing (fair-value) USDC bid.
2. Because `computeStablesUsdValue` prices both at flat $1, the depegged-USDT bid ranks equal to (or, with a wider basket, can be engineered to outrank) a bid that would actually deliver more real value to the user.
3. The user's client selects and executes the misranked bid, receiving USDT worth less than the USDC alternative it was compared against, while the solver captures the spread.

This is a direct value-extraction path reachable by any unprivileged solver submitting a bid into the auction — no privileged role is required — and it results in the user receiving strictly less value than the (mis-)represented "best" bid, i.e., concrete loss of funds to the counterparty. This is the same mechanism as the report's rETH/ETH 1:1 assumption exploited around a temporary depeg, just instantiated on the USDC/USDT leg of the Intent Gateway's off-chain bid-selection logic that gates an on-chain fund transfer.

### Likelihood Explanation
USDT (and USDC) depegs, even by small amounts, are a recurring market event, and any solver can participate in the auction and shape its bid composition to exploit this ranking blind spot without any special privilege — they only need to win the ranking by offering the depegged token at nominal parity. The `computeOutputsUsdValue`/`quoteTokenToUsdc` path used for *mixed* (non-stable) outputs already fetches live DEX quotes, underscoring that the pure "$1 flat" shortcut used specifically for the all-stables case is the outlier and the actual root cause.

### Recommendation
Do not assume USDC and USDT are always worth exactly $1 relative to each other in `isStableToken`/`computeStablesUsdValue`/`sortAllStables`. Either:
- Route all-stable baskets through the same live-price (DEX quote or oracle) valuation used in `computeOutputsUsdValue` for mixed baskets, so a depegged stable is priced at its real market rate, or
- Bound the acceptable price deviation for stables (e.g., reject/deprioritize bids that substitute a token trading meaningfully below its peg) instead of hard-coding parity.

### Proof of Concept
1. An order requests 1,000 USDC as output.
2. Two solvers bid: Solver A offers 1,000 USDC; Solver B offers 1,000 USDT while USDT is trading at $0.95 (temporary depeg).
3. `sortAllStables` computes `computeStablesUsdValue` for both bids as exactly 1000 (each stable flat-priced at $1), so the bids tie / Solver B's bid is not penalized for its real ~$50 shortfall.
4. If Solver B's bid is selected (e.g., due to tie-break ordering, gas/fee tiebreakers, or a larger nominal offer engineered to look superior while still being worth less than a competing USDC bid), the user executes it via `Bid.execute()` and receives USDT worth $950 in real terms instead of the $1,000 of value a fair comparison would have surfaced, with the difference effectively captured by the solver.

	 * Sorts a list of bids for the given order by output value.
	 *
	 * Delegates to one of three strategies based on the order's output token
	 * composition:
	 * - Single output token: sort by offered amount descending.
	 * - All stable outputs (USDC/USDT): sort by normalised USD value descending.
	 * - Mixed outputs: sort by DEX-quoted USD value descending, with a raw-amount
	 *   fallback if pricing fails.
	 *
	 * Bids that cannot satisfy the order's token set are dropped.
	 *
	 * @param order - The placed order whose output spec drives sorting logic.
	 * @param bids - Executable bids to sort (from {@link buildBids}).
	 * @returns Sorted array of `Bid` objects ready for simulation.
	 */
	async sortBids(order: Order, bids: Bid[]): Promise<Bid[]> {
		const outputs = order.output.assets

		if (outputs.length <= 1) {
			console.log(`[BidManager] Using single-output sorting (1 output asset)`)
			return this.sortSingleOutput(bids, outputs[0])
		}

		const chainId = this.ctx.dest.config.stateMachineId
		const allStables = outputs.every((o) => this.isStableToken(bytes32ToBytes20(o.token), chainId))

		if (allStables) {
			console.log(`[BidManager] Using all-stables sorting (${outputs.length} stable output assets)`)
			return this.sortAllStables(bids, outputs, chainId)
		}

		console.log(`[BidManager] Using mixed-output sorting (${outputs.length} output assets, some non-stable)`)
		return this.sortMixedOutputs(bids, outputs, chainId)
	}

	/**
	 * Case B: all outputs are USDC/USDT.
	 * Sum normalised USD values (treating each stable as $1) and sort descending.
	 * Partial fill bids are allowed.
	 */
	private sortAllStables(bids: Bid[], orderOutputs: TokenInfo[], chainId: string): Bid[] {
		const requiredUsd = this.computeStablesUsdValue(orderOutputs, chainId)
		console.log(`[BidManager] sortAllStables: required USD value=${requiredUsd.toString()}`)

		const validBids: { bid: Bid; usdValue: Decimal }[] = []

		for (const bid of bids) {
			const bidUsd = this.computeStablesUsdValue(bid.outputs, chainId)

			if (bidUsd === null) {
				console.warn(`[BidManager] Bid from solver=${bid.solverAddress} REJECTED: unable to compute USD value`)
				continue
			}

			if (bidUsd.lt(requiredUsd)) {
				console.log(
					`[BidManager] Bid from solver=${bid.solverAddress}: partial fill candidate ` +
						`(bid=${bidUsd.toString()}, required=${requiredUsd.toString()}, ` +
						`covers=${bidUsd.div(requiredUsd).mul(100).toFixed(2)}%)`,
				)
			} else {
				console.log(`[BidManager] Bid from solver=${bid.solverAddress} ACCEPTED: USD value=${bidUsd.toString()}`)
			}

			validBids.push({ bid, usdValue: bidUsd })
		}

		validBids.sort((a, b) => b.usdValue.comparedTo(a.usdValue))
		return validBids.map(({ bid }) => bid)
	}

	/**
	 * Returns `true` if `tokenAddr` is either USDC or USDT on the given chain.
	 *
	 * @param tokenAddr - 20-byte ERC-20 token address (hex).
	 * @param chainId - State-machine ID of the chain to look up token addresses on.
	 */
	private isStableToken(tokenAddr: HexString, chainId: string): boolean {
		const configService = this.ctx.dest.configService
		const usdc = configService.getUsdcAsset(chainId)
		const usdt = configService.getUsdtAsset(chainId)
		const normalized = tokenAddr.toLowerCase()
		return normalized === usdc.toLowerCase() || normalized === usdt.toLowerCase()
	}

	// ── Basket valuation helpers ──────────────────────────────────────

	/**
	 * Sums the USD value of a basket of stable tokens (USDC/USDT only),
	 * normalising each amount by its decimal count and treating each token as $1.
	 *
	 * @param outputs - List of token/amount pairs where every token is a stable.
	 * @param chainId - State-machine ID used to look up decimals.
	 * @returns Total USD value as a `Decimal`.
	 */
	private computeStablesUsdValue(outputs: TokenInfo[], chainId: string): Decimal {
		let total = new Decimal(0)
		for (const output of outputs) {
			const tokenAddr = bytes32ToBytes20(output.token)
			const decimals = this.getStableDecimals(tokenAddr, chainId)
			total = total.plus(new Decimal(output.amount.toString()).div(new Decimal(10).pow(decimals)))
		}
		return total
	}
