### Title
Unbounded Uniswap V4 spot-price venue pricing lets an attacker flashloan-manipulate a pool to drain solver inventory on curveless FX pairs - (File: `sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts`)

### Summary
Simplex's FX filler prices "curveless" pairs (a pair with no configured bid/ask curve) directly off a Uniswap V4 pool's instantaneous `sqrtPriceX96`, with no TWAP and no size/impact adjustment. The only defense, `checkPriceGuard`, is optional and disabled by default. This mirrors the Harvest Finance bug class: a value used to size a payout is read as a manipulable single-block spot price rather than a resistant one, and a flashloan-style swap immediately before the priced action can move it.

### Finding Description
`UniswapV4FundingPlanner.getExoticTokenPrice` selects the position with the largest liquidity and calls `computeDirectPoolPriceUsd`, which returns the **raw pool mid** derived straight from the freshly-read `sqrtPriceX96` (via `state.refresh()` → `getSlot0`), with no TWAP/oracle averaging: [1](#0-0) [2](#0-1) 

The pool state itself is fetched live and unaveraged in `UniswapV4LiquidityState.refresh`: [3](#0-2) 

This price feeds `resolveLegRates` in the FX strategy (`sdk/packages/simplex/src/strategies/fx.ts`), which for a curveless pair whose `token0` is a USD stable calls `getVenueUsdPrice`/`getExoticTokenPrice`, applies `checkPriceGuard`, and then derives `rate = 1 / venueUsd` used to size the fill linearly across the whole notional (per the documented flow): [4](#0-3) 

`checkPriceGuard` is the *only* mitigation, and it is opt-in per chain — configured via `referencePrice` + `maxDeviationBps`, and explicitly documented that omitting both leaves the chain **unguarded**: [5](#0-4) 

This is confirmed by the guard's own unit test, which asserts the price guard passes *every* quote when unconfigured, including a wildly deviated one (1575 vs 5000): [6](#0-5) 

Even when configured, the guard only rejects deviation beyond a static band (e.g. 200 bps ≈ 2%), it does not detect or prevent manipulation within that band, and it checks the price at read time, not execution cost/slippage: [7](#0-6) [8](#0-7) 

Attack pattern (Harvest analog): an unprivileged user
1. Executes a large swap against the exact Uniswap V4 pool backing the solver's `UniswapV4PositionConfig` for a given exotic token, pushing `sqrtPriceX96` away from the true market price (a flashloan-funded swap works, since the position is atomically reversible).
2. Immediately (same block / next block before arbitrage corrects it) submits an intent order on the `IntentGateway`/`IntentGatewayV2` for that exotic↔USD pair, sized up to the pair's `maxOrderSize`.
3. The Simplex filler bot reads the manipulated spot price via `getExoticTokenPrice`, computes `rate = 1 / venueUsd` off the skewed price, and fills the order using `planWithdrawalForToken`, crediting the attacker at the bad rate and paying out from the solver's real Uniswap V4 LP inventory.
4. The attacker reverses the manipulating swap, recovering the capital used to move the price, net of gas/fees, keeping the arbitrage profit extracted from the solver.

Because there is no size/impact term and the fee tier is read but never applied to the price, `computeLegPolicyOutput` linearly extends the manipulated mid across the whole order notional, amplifying the loss for large `maxOrderSize` pairs.

### Impact Explanation
This directly drains a solver's real on-chain funds (Uniswap V4 LP position value) through fills executed at attacker-manipulated prices — concrete theft of funds reachable from a single unprivileged order placed by an ordinary intent submitter, exactly the class the rules require (theft of funds via unsound/unprotected price input). Because the price guard is disabled by default and even when enabled only bounds deviation rather than manipulation resistance, this is not a hypothetical edge case but the shipped default behavior for any curveless pair funded by Uniswap V4 without a configured `referencePrice`.

### Likelihood Explanation
High for any deployment using curveless Uniswap V4-funded pairs without `referencePrice`/`maxDeviationBps` configured (the default/unguarded state per the documentation), since it requires only capital for a flashloan/large swap against a single identifiable pool and a normal `placeOrder`/`fillOrder` intent flow — no privileged access, no governance, no relayer collusion. Even with the guard configured, an attacker can still extract profit within the allowed deviation band repeatedly. Likelihood is somewhat mitigated by the requirement that the manipulated pool must be the specific position configured for the solver and have exploitable depth/slippage economics, but this is a standard, well-understood DeFi attack precondition (as in the original Harvest Finance case).

### Recommendation
- Require `referencePrice`/`maxDeviationBps` (or an equivalent oracle/TWAP check) to be mandatory, not optional, for any Uniswap V4-funded curveless pair; refuse to fill rather than defaulting to "unguarded" when unset.
- Replace or supplement the instantaneous `sqrtPriceX96` mid with a TWAP (Uniswap V4 truncated oracle observations) or cross-venue sanity check before pricing a fill.
- Apply the pool's fee tier and a size/impact term to the quoted price instead of extending the raw mid linearly across the whole notional (`computeLegPolicyOutput`), and cap solver exposure per pool proportional to actual available on-chain depth, not just `maxOrderSize`.
- Consider a same-block/same-transaction manipulation guard (e.g., minimum number of blocks since last large trade on the reference pool, or a secondary TWAP window) before trusting a spot read for sizing a large fill.

### Proof of Concept
1. Deploy/target a Simplex filler configured with a curveless FX pair (e.g. USDC/EXOTIC) funded solely by a `[[vault.uniswapV4.positions]]` entry, with **no** `referencePrice`/`maxDeviationBps` set (the documented default/unguarded configuration).
2. Attacker flashloans funds and swaps against the exact pool referenced by that position's `tokenId`, moving `sqrtPriceX96` significantly (e.g. +50%).
3. Attacker immediately submits an `IntentGatewayV2` order for the pair at/near `maxOrderSize`.
4. Simplex's `getExoticTokenPrice`/`computeDirectPoolPriceUsd` reads the manipulated `sqrtPriceX96` (unit-testable directly, as in `sdk/packages/simplex/src/tests/funding/uniswapV4Price.test.ts`), `checkPriceGuard` passes trivially since unconfigured (verified by `fx.price-guard.test.ts`'s "passes every quote when no guard is configured" case), and the filler fills the order at the skewed rate via `planWithdrawalForToken`, withdrawing real LP inventory.
5. Attacker reverses the manipulating swap and repays the flashloan, retaining the arbitrage profit extracted from the solver's Uniswap V4 position. [6](#0-5) [1](#0-0)

	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}

	private computeDirectPoolPriceUsd(
		pos: HydratedV4Position,
		sdkPool: V4Pool,
		chain: string,
	): { exoticToken: string; priceUsd: Decimal } | null {
		const usdc = this.configService.getUsdcAsset(chain).toLowerCase()
		const usdt = this.configService.getUsdtAsset(chain).toLowerCase()
		const c0 = pos.currency0.toLowerCase()
		const c1 = pos.currency1.toLowerCase()

		if (c0 === usdc || c0 === usdt) {
			// currency0 is stable → exotic is currency1
			// token1Price = "token0 per token1" = USD per exotic
			return {
				exoticToken: c1,
				priceUsd: new Decimal(sdkPool.token1Price.toFixed(18)),
			}
		}

		if (c1 === usdc || c1 === usdt) {
			// currency1 is stable → exotic is currency0
			// token0Price = "token1 per token0" = USD per exotic
			return {
				exoticToken: c0,
				priceUsd: new Decimal(sdkPool.token0Price.toFixed(18)),
			}
		}

		return null
	}

	async refresh(): Promise<void> {
		const client = this.clientManager.getPublicClient(this.chain)
		const chainId = chainIdFromIdentifier(this.chain)

		// Group positions by poolId to avoid duplicate pool state fetches
		const poolIds = new Set(this.tokenIdToPoolId.values())

		// Fetch slot0 + liquidity for each unique pool via StateView
		const poolStateMap = new Map<string, { sqrtPriceX96: bigint; tick: number; poolLiquidity: bigint }>()

		for (const poolId of poolIds) {
			const [slot0Result, poolLiquidity] = await Promise.all([
				client.readContract({
					address: this.stateView,
					abi: UNISWAP_V4_STATE_VIEW_ABI,
					functionName: "getSlot0",
					args: [poolId as HexString],
				}) as Promise<[bigint, number, number, number]>,
				client.readContract({
					address: this.stateView,
					abi: UNISWAP_V4_STATE_VIEW_ABI,
					functionName: "getLiquidity",
					args: [poolId as HexString],
				}) as Promise<bigint>,
			])

			poolStateMap.set(poolId, {
				sqrtPriceX96: slot0Result[0],
				tick: slot0Result[1],
				poolLiquidity,
			})
		}

		// Refresh per-position liquidity and rebuild SDK Pool objects
		for (const pos of this.positions.values()) {
			const key = pos.tokenId.toString()
			const poolId = this.tokenIdToPoolId.get(key)
			const poolState = poolId ? poolStateMap.get(poolId) : undefined
			if (!poolId || !poolState) {
				throw new Error(
					`UniswapV4 refresh: missing pool state for tokenId ${key} (poolId=${poolId ?? "undefined"})`,
				)
			}

			// Read current position liquidity
			const liquidity = (await client.readContract({
				address: pos.positionManager,
				abi: UNISWAP_V4_POSITION_MANAGER_ABI,
				functionName: "getPositionLiquidity",
				args: [pos.tokenId],
			})) as bigint

			pos.liquidity = liquidity
			const prevOnChain = this.lastOnChainLiquidity.get(key) ?? liquidity
			const decrease = prevOnChain > liquidity ? prevOnChain - liquidity : 0n
			const prevConsumed = this.consumed.get(key) ?? 0n
			const newConsumed = prevConsumed > decrease ? prevConsumed - decrease : 0n
			this.consumed.set(key, newConsumed)
			this.lastOnChainLiquidity.set(key, liquidity)
			pos.remainingLiquidity = liquidity > newConsumed ? liquidity - newConsumed : 0n
			pos.sqrtPriceX96 = poolState.sqrtPriceX96
			pos.currentTick = poolState.tick

			// Build SDK Pool (without tick data provider — we only need amount calcs)
			const currency0 = currencyFromHydratedDecimals(chainId, pos.currency0, pos.decimals0)
			const currency1 = currencyFromHydratedDecimals(chainId, pos.currency1, pos.decimals1)

			const sdkPool = new V4Pool(
				currency0,
				currency1,
				pos.fee,
				pos.tickSpacing,
				pos.hooks,
				poolState.sqrtPriceX96.toString(),
				poolState.poolLiquidity.toString(),
				poolState.tick,
			)

			this.sdkPools.set(poolId, sdkPool)

# Venue pricing (Uniswap V4 funded pairs)

Verified 2026-08-19.

```
resolveLegRates(...)
  curveless pair && token0 is a USD stable
    -> venuePriceMemo() -> getVenueUsdPrice(chain, token1)
         -> UniswapV4FundingPlanner.getExoticTokenPrice
              picks the position with the largest pool liquidity
              -> computeDirectPoolPriceUsd -> sdkPool.token0Price / token1Price
    -> checkPriceGuard(...)   reject if outside maxDeviationBps of the static reference
    -> rate = 1 / venueUsd
  otherwise -> the pair's ask/bid curve at the leg's notional
```

`computeDirectPoolPriceUsd` returns the **raw pool mid** derived from `sqrtPriceX96`. The pool's
fee tier is read and stored on the hydrated position (`pos.fee`) but never applied to the price,
and there is no size or impact term — `computeLegPolicyOutput` extends the mid linearly across the
whole priced quantity. `checkPriceGuard` is the only defense on this path, and it checks deviation
from a static reference, not execution cost. A venue-priced pair that has to swap through its own
pool to source inventory pays a fee tier it never quoted against.

## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.

```toml lineNumbers
[vault.uniswapV4]
# referencePrice is the expected cNGN per USD;
# reject if the quote is more than 2% off.
# The two go together — one without the other is rejected.
[[vault.uniswapV4.positions]]
chain           = "EVM-8453"
tokenId         = "2087350"
referencePrice  = "1575"
maxDeviationBps = 200
```
