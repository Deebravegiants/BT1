### Title
Missing Chainlink min/max answer validation lets a saturated price feed under- or over-charge SimplexPaymaster gas fees - (File: evm/src/utils/SimplexPaymaster.sol)

### Summary
`SimplexPaymaster._getOraclePrice()` reads `latestRoundData()` from a registered Chainlink `AggregatorV3Interface` and only rejects a non-positive or stale answer; it never checks the returned `answer` against the feed's `minAnswer`/`maxAnswer` bounds.

### Finding Description
`_getOraclePrice` is the sole price-reading function for both the native/USD and token/USD Chainlink feeds registered via governance (`RegisterToken`): [1](#0-0) 

It validates `answer <= 0` and staleness (`block.timestamp - updatedAt > maxOracleAge`), but never checks the answer against the aggregator's `minAnswer`/`maxAnswer` circuit-breaker bounds, exactly the missing check described in the referenced report. If the underlying asset's market price moves outside the aggregator's configured range (a de-peg or crash, e.g. a stablecoin losing its peg or a "LUNA-style" event), Chainlink's aggregator continues to report the clamped `minAnswer`/`maxAnswer` rather than reverting, and this contract accepts that clamped value as if it were the true price.

This value feeds directly into the gas-charging logic reachable by any unprivileged UserOp sender: [2](#0-1) 

`_tokenPrice` is called from `_fetchDetails`, which runs during EntryPoint's `validatePaymasterUserOp`/`postOp` for every UserOp that names a registered token in `paymasterData`: [3](#0-2) 

and the resulting `tokenPrice` sets `prefundAmount = _erc20Cost(maxCost, userOp.maxFeePerGas(), tokenPrice)` charged from the sender's tokens (via `transferFrom` or Permit2), as well as feeding `swapAndDeposit`'s treasury-only fee-recycling swap: [4](#0-3) 

### Impact Explanation
Any address can submit a UserOperation naming a registered token (no permission needed to call the paymaster's validation/postOp path). If the token's or native asset's Chainlink feed is clamped at `minAnswer` (or `maxAnswer`) during a real market dislocation, `_tokenPrice` computes gas cost from the stale clamped price instead of the true market price:
- If the token's real value has crashed below `minAnswer`, the paymaster undercharges — attackers can pay negligible real value for arbitrary gas sponsorship, draining the paymaster's EntryPoint deposit.
- If the native asset's real value has spiked/crashed relative to `maxAnswer`/`minAnswer`, users can be systematically over- or under-charged, and `swapAndDeposit`'s slippage-protected swap can execute at a mispriced `amountOutMin`, misallocating recycled fees.

This is a concrete funds-drain vector on the paymaster's treasury/deposit reachable by an ordinary UserOp sender, satisfying the "concrete theft" bar.

### Likelihood Explanation
Requires the underlying Chainlink feed to actually saturate at its min/max bound, which happens historically during severe depegs/crashes (the exact scenario the original report cites, e.g. LUNA). Given SimplexPaymaster is meant to support arbitrary governance-registered ERC-20 stablecoins/tokens across chains, and stablecoin depegs are a recurring real-world event, likelihood is non-negligible but conditioned on an external market event, making it Medium severity, consistent with the source report's own rating.

### Recommendation
In `_getOraclePrice`, additionally fetch and enforce the aggregator's `minAnswer`/`maxAnswer` (e.g., via the proxy's underlying aggregator `aggregator()` and its `minAnswer()/maxAnswer()`, or by having governance configure per-feed bounds in `TokenConfig`) and revert when `answer <= minAnswer || answer >= maxAnswer`, mirroring the recommendation in the referenced report.

### Proof of Concept
1. Governance registers a token `T` with Chainlink feed `F` via `RegisterToken`, where `F.minAnswer = X`. [5](#0-4) 
2. `T`'s real market price crashes far below `X`; `F.latestRoundData()` keeps returning `X` (Chainlink's built-in clamp), with `updatedAt` still fresh.
3. An attacker submits a UserOp with `paymasterData` mode `0x00`/`0x02` naming `T`. `_fetchDetails` calls `_tokenPrice(cfg)` → `_getOraclePrice(cfg.tokenOracle, ...)`, which accepts `X` because it only checks `answer <= 0` and staleness. [6](#0-5) 
4. The stale clamped `X` (far above the token's true worthless price) makes `tokenPrice` understate the true cost of gas in `T` terms, so `_erc20Cost` charges the attacker only a small amount of (now near-worthless) `T` for gas the paymaster pays for in real native currency — repeatable to drain the paymaster's EntryPoint deposit. [7](#0-6)

            tokenOracleDecimals: oracle.decimals(),
            tokenDecimals: IERC20Metadata(token).decimals(),
            active: true
        });

            registeredTokens.push(token);
        }

        token = IERC20(tokenAddr);

    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
