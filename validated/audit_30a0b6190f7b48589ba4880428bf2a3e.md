### Title
Emporium Min-proof path lets an attacker drain any ERC20 tokens held by Emporium with zero balance accounting - (File: contracts/CircomDataBuilder.sol / contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol)

### Summary
When `externalActionData.externalActionId == HINKAL_EMPORIUM_ACTION_ID` and `erc20TokenAddresses.length == 0`, `formInputForCircom` routes to `formInputEmporiumMin`, which only publicly commits `emporiumMessage`, `timeStamp` and `calldataHash` — none of the actual operations, tokens, or amounts are constrained by the proof. `EmporiumUpgradeable.runAction` then executes an attacker-supplied `EmporiumStack` whose `ops` can perform an arbitrary external call (including an ERC20 `transfer`) moving tokens Emporium holds to the attacker, while the balance-accounting loop (`balancesBefore`/`balancesAfter`, lines 85-151) iterates zero times because it is keyed off the same empty `erc20TokenAddresses` array supplied by the attacker.

### Finding Description
The claimed broken equality is:
`assets Emporium can move in a tx == assets accounted for in balancesBefore/balancesAfter`.

Path:
1. `formInputForCircom` (contracts/CircomDataBuilder.sol:134-148) selects `formInputEmporiumMin` whenever `externalActionId == HINKAL_EMPORIUM_ACTION_ID && erc20TokenAddresses.length == 0`.
2. `formInputEmporiumMin` (contracts/CircomDataBuilder.sol:150-161) builds only 3 public signals: `emporiumMessage`, `timeStamp`, `calldataHash`. There is no constraint tying the proof to `amountChanges`, `erc20TokenAddresses`, or the `externalActionMetadata` (the `EmporiumStack`) content itself — the attacker is free to choose `calldataHash` and generate a matching Min proof entirely off-chain for their own crafted `CircomData`, since they control every field of `CircomData` before proof generation.
3. `EmporiumUpgradeable.runAction` (contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol:76-160) decodes `EmporiumStack` from `circomData.externalActionData.externalActionMetadata` and takes `balancesBefore = getBalancesForArray(circomData.erc20TokenAddresses)` — an **empty** array by construction.
4. `verifyWallet` (lines 302-349): when `stack.signerAddress == address(0)`, it returns immediately after marking the message used — no ECDSA signature is required at all for this path.
5. In the ops loop (lines 91-118), since `stack.signerAddress == address(0)`, `op.invokeWallet && stack.signerAddress != address(0)` is false, so execution falls into "CASE 2: Stateless Interaction" (lines 102-113): `op.endpoint.call{value: op.value}(op.callData)`. The only restriction is that the selector cannot be `callHinkalWallet` or `doSendToRelay` — an ERC20 `transfer(address,uint256)` call is not blocked.
6. This call can invoke any ERC20 token contract that Emporium currently holds a balance in and transfer those tokens directly to the attacker's address (`msg.sender` of that low-level call context is the Emporium contract itself, so `token.transfer(attacker, amount)` succeeds against Emporium's own balance).
7. The post-accounting loop (lines 132-151), which is the only place that would detect an unauthorized balance movement (`balanceChange < 0` reverts with `BalanceChangeShouldBePositive`), never executes because `circomData.erc20TokenAddresses.length == 0`.

Result: value leaves the Emporium contract, but is never checked against `balancesBefore`/`balancesAfter`, never causes a revert, and no UTXO debit/credit is required to justify it — a direct violation of the invariant that all asset movement performed by an Emporium op must be captured by the balance diff loop.

### Impact Explanation
Any ERC20 tokens currently held by the Emporium contract (e.g., balances awaiting settlement from a previous multi-op transaction, dust, or intentionally routed funds) can be stolen by an unprivileged attacker with a single crafted transaction, using only a self-generated Min-circuit proof (a trivial Poseidon preimage proof they can always produce for their own chosen `emporiumMessage`). This is direct theft of protocol/in-flight funds held by Emporium, matching the "Critical: direct theft of shielded or in-flight user funds" category. The attack is repeatable every time Emporium holds a nonzero balance of any token.

### Likelihood Explanation
Preconditions: Emporium contract must hold a nonzero balance of some ERC20 token at the time of the attack (a realistic and recurring state given multi-step Emporium flows, leftover dust, or intermediate transfers). The attacker needs no special role — they only need to be able to call `Hinkal.transact` with a crafted `CircomData` (`erc20TokenAddresses = []`, `externalActionId = HINKAL_EMPORIUM_ACTION_ID`) and generate a matching Min-circuit proof, which requires no privileged secret since the Min circuit only proves knowledge of `messageSeed` for `Poseidon(messageSeed) == emporiumMessage` (both chosen by the attacker). Cost is a single transaction; the exploit is fully repeatable whenever Emporium re-accumulates balance.

### Recommendation
Do not let `erc20TokenAddresses.length == 0` bypass all balance/ops accounting. At minimum:
- In `EmporiumUpgradeable.runAction`, snapshot and verify balances for every token address that any `op.endpoint` in `stack.ops` could plausibly affect, not just `circomData.erc20TokenAddresses` — or forbid the Min-circuit path from executing arbitrary `ops` entirely (Min path should only be usable for pure signature/message verification flows with no token-moving side effects).
- Constrain the Min circuit's public inputs to also commit to a hash of `stack.ops`/`externalActionMetadata`, and enforce in `runAction` that no external call can transfer ERC20/ETH held by Emporium unless the corresponding token is included and accounted for in `erc20TokenAddresses`.
- Alternatively, restrict "CASE 2: Stateless Interaction" targets to a contract allow-list that excludes arbitrary ERC20 token contracts, and/or require `erc20TokenAddresses.length > 0` whenever `stack.ops` contains any call capable of moving Emporium's own asset balances.

### Proof of Concept
Foundry test plan:
1. Deploy `Hinkal`, `EmporiumUpgradeable`, and a test ERC20 token `T`.
2. Fund the Emporium contract directly with `T` (simulate leftover/in-flight balance), e.g. `T.transfer(address(emporium), 1000e18)`.
3. As an unprivileged attacker EOA, construct `CircomData` with:
   - `externalActionData.externalActionId = HINKAL_EMPORIUM_ACTION_ID`
   - `erc20TokenAddresses = []`
   - `externalActionData.externalActionMetadata = abi.encode(EmporiumStack({v:0,r:0,s:0, signerAddress: address(0), ops: [EmporiumOperation({endpoint: address(T), invokeWallet: false, value: 0, callData: abi.encodeCall(T.transfer, (attacker, 1000e18))})], maxFee: 0, deadline: type(uint256).max}))`
   - `emporiumMessage`, `timeStamp`, `calldataHash` set/computed by attacker; generate a valid Min-circuit proof locally for `message == Poseidon(messageSeed)`.
4. Call `Hinkal.transact` with this proof and `circomData`.
5. Assertions:
   - Before: `T.balanceOf(address(emporium)) == 1000e18`, `T.balanceOf(attacker) == 0`.
   - After: `T.balanceOf(address(emporium)) == 0`, `T.balanceOf(attacker) == 1000e18`, transaction did not revert with `BalanceChangeShouldBePositive` or any other guard.
   - Confirm `balancesBefore`/`balancesAfter` arrays computed inside `runAction` were both length-0 (`circomData.erc20TokenAddresses.length == 0`), proving the moved value was never checked against the equality `assets moved == assets accounted`. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3)

    function runAction(
        CircomData calldata circomData,
        int256[] calldata deltaAmountChanges
    ) external override onlyAllowedRecipient returns (UTXO[] memory) {
        EmporiumStack memory stack = abi.decode(
            circomData.externalActionData.externalActionMetadata,
            (EmporiumStack)
        );

        uint256[] memory balancesBefore = getBalancesForArray(
            circomData.erc20TokenAddresses
        );

        verifyWallet(stack, circomData);

        for (uint256 i = 0; i < stack.ops.length; i++) {
            EmporiumOperation memory op = stack.ops[i];

            bool success;
            bytes memory err;

            // CASE 1: Stateful Interaction
            if (op.invokeWallet && stack.signerAddress != address(0)) {
                (success, err) = IHinkalWallet(stack.signerAddress)
                    .callHinkalWallet(op.endpoint, op.callData, op.value);
            }
            // CASE 2: Stateless Interaction
            else {
                bytes4 selector = bytes4(op.callData);
                if (
                    selector == IHinkalWallet.callHinkalWallet.selector ||
                    selector == IHinkalWallet.doSendToRelay.selector
                ) {
                    revert UnauthorizedWalletCall();
                }

                (success, err) = op.endpoint.call{value: op.value}(op.callData);
            }

            if (!success) {
                revert CallFailed(err);
            }
        }

        payRelayFees(circomData, stack.signerAddress, deltaAmountChanges);

        uint256[] memory balancesAfter = getBalancesForArray(
            circomData.erc20TokenAddresses
        );

        UTXO[] memory utxoSet = new UTXO[](
            circomData.erc20TokenAddresses.length
        );

        uint256 utxoSetLength;

        for (uint256 i = 0; i < circomData.erc20TokenAddresses.length; i++) {
            int256 balanceChange = int256(balancesAfter[i]) -
                int256(balancesBefore[i]);

            if (deltaAmountChanges[i] < 0) {
                balanceChange -= deltaAmountChanges[i];
                // this equation reads: total change of emporium balance = what was moved to emporium (-deltaAmountChange) + how emporium balance changed through tx (balanceChange)
            }

            // the only case when balanceChange can be < 0, when there were some funds on emporium before the call
            if (balanceChange < 0) {
                revert BalanceChangeShouldBePositive();
            }

            UTXO memory utxoOut = handleOut(balanceChange, circomData, i);

            if (utxoOut.amount > 0) {
                utxoSet[utxoSetLength++] = utxoOut;
            }
        }

        if (utxoSetLength < circomData.erc20TokenAddresses.length) {
            utxoSet.skipLast(
                circomData.erc20TokenAddresses.length - utxoSetLength
            );
        }

        return utxoSet;
    }
