### Title
Overflow during interest accrual permanently freezes a large high-decimal market - (File: `common/src/rates/simulate.rs`)

### Summary
Interest accrual multiplies scaled debt and supply shares by their indexes in checked `i128` arithmetic without first constraining the result to the market's representable value range. For sufficiently large positions, the borrow index can grow past the point where `borrowed * borrow_index` fits in `i128`, after which every accrual panics before the configured borrow-index cap can engage. This permanently prevents withdrawals, repayments, liquidations, and index updates for the market. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`accrue_step` calls `scaled_to_original` on `borrowed` and `supplied` before calculating the new borrow index. [4](#0-3) 

`scaled_to_original` delegates to `Ray::mul`, which uses checked fixed-point arithmetic and panics on overflow. [5](#0-4) [6](#0-5) 

Although `update_borrow_index` clamps the next index to `MAX_BORROW_INDEX_RAY`, that clamp only runs after the current stored scaled balances have already been multiplied by the current index. [7](#0-6) 

`global_sync` executes this step for every elapsed accrual chunk, while `update_indexes` loads the market, calls `global_sync`, and only commits after accrual returns successfully. [8](#0-7) [9](#0-8) 

An unprivileged user can create the prerequisite state through `Controller::supply` and `Controller::borrow`, then permissionlessly advance the market through `Controller::update_indexes` until accrual overflows. [10](#0-9) [11](#0-10) 

### Impact Explanation
Once `borrowed.raw() * borrow_index.raw() / RAY` exceeds `i128::MAX`, the accrual transaction reverts before `mark_accrued` or `commit` can record progress. [12](#0-11) [13](#0-12) 

Because the stored index remains unchanged, every subsequent market operation that synchronizes interest repeats the same overflowing multiplication. The repository's regression test demonstrates that both withdrawal and repayment revert with `MathOverflow` after this point. [14](#0-13) 

This results in permanent freezing of supplier and borrower funds, and prevents repayments, withdrawals, liquidations, bad-debt cleanup, recapitalization, and parameter updates that require prior accrual. [15](#0-14) 

### Likelihood Explanation
The attack requires a listed high-decimal market whose configured supply and borrow caps permit scaled balances near or above the `i128` value ceiling divided by the attainable borrow index. [16](#0-15) [17](#0-16) 

The in-repository scenario uses a one-billion-token, 18-decimal market at approximately 98% utilization and shows that the value ceiling is reached before `MAX_BORROW_INDEX_RAY`. [18](#0-17) 

An attacker can control both the supplier and borrower accounts, making the attack unprivileged, although its feasibility depends on real token liquidity and governance-configured market caps rather than a configuration mistake alone. [10](#0-9) [19](#0-18) 

### Recommendation
Bound indexes by the largest value that can safely be multiplied by the market's stored scaled balances before calling `scaled_to_original`, rather than only applying a global `MAX_BORROW_INDEX_RAY` after computing the next index. [1](#0-0) [2](#0-1) 

For example, calculate a per-market safe index bound such as `safe_index = i128::MAX * RAY / scaled.raw()` and clamp both borrow and supply indexes to `min(protocol_cap, safe_index)` so accrual remains representable. Alternatively, perform utilization and reward accounting in widened or saturating arithmetic, but ensure that committed indexes never make future mandatory accrual panic. [20](#0-19) [21](#0-20) 

Add a regression test based on `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` asserting that accrual reaches the applicable index cap and remains callable instead of reverting with `MathOverflow`. [22](#0-21) 

### Proof of Concept
1. Deploy or use an 18-decimal borrow market and a collateral market whose configured caps permit approximately `1e9` whole debt-market tokens. [23](#0-22) 
2. From attacker-controlled accounts, call `Controller::supply` to provide the debt-market liquidity and sufficient collateral. [24](#0-23) [25](#0-24) 
3. Call `Controller::borrow` to borrow approximately 98% of the supplied debt asset. [26](#0-25) [27](#0-26) 
4. Advance ledger time and call `Controller::update_indexes` until `borrowed * borrow_index` exceeds `i128::MAX` inside `scaled_to_original`; the call reverts with `MathOverflow`. [4](#0-3) [28](#0-27) 
5. Subsequent `withdraw` and `repay` calls repeat mandatory accrual and fail with the same `MathOverflow`, leaving funds frozen even though `borrow_index < MAX_BORROW_INDEX_RAY`. [29](#0-28)

pub fn update_supply_index(env: &Env, supplied: Ray, old_index: Ray, rewards_increase: Ray) -> Ray {
    if supplied == Ray::ZERO || rewards_increase == Ray::ZERO {
        return old_index;
    }

    let total_supplied_value = supplied.mul(env, old_index);

    if total_supplied_value == Ray::ZERO {
        return old_index;
    }

    let new_value = total_supplied_value.checked_add(env, rewards_increase);

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
