### Title
`Oauth.begin_auth` Builds the OAuth Authorization Redirect from an Unvalidated `shop` Parameter, Enabling Forced OAuth Completion - (File: `lib/shopify_api/auth/oauth.rb`)

### Summary
`ShopifyAPI::Auth::Oauth.begin_auth` builds the redirect URL that starts the OAuth flow directly from the caller-supplied `shop:` argument, without ever validating that it is a trusted `*.myshopify.com`/allow-listed domain. Every other credential-issuing flow in the gem (`ClientCredentials.client_credentials`, `TokenExchange.migrate_to_expiring_token`) explicitly calls `Utils::ShopValidator.sanitize!(shop)` before using the shop to construct an outbound request host. `begin_auth` is the one flow that skips this check, breaking the equality the rest of the gem enforces: `validated_shop == host_used_to_build_the_authorize_URL`.

### Finding Description
`begin_auth` takes `shop:` and passes it unmodified into `auth_base_uri(shop)`: [1](#0-0) 

```
auth_route = auth_base_uri(shop) + "/oauth/authorize?#{query_string}"
``` [2](#0-1) 

```
def auth_base_uri(shop)
  return "https://#{shop}/admin" unless defined?(DevServer) && shop.include?(".my.shop.dev")
  ...
end
```

No call to `Utils::ShopValidator.sanitize!` is made here, unlike the analogous flows: [3](#0-2) [4](#0-3) 

The `query` built for the redirect includes the app's `client_id` and the app's own `redirect_uri` (built from `Context.host`, not from `shop`), and a freshly generated `state` nonce, which is also stored in a cookie: [5](#0-4) 

Because `shop` is never checked against `ShopValidator::TRUSTED_SHOPIFY_DOMAINS` (`shopify.com`, `myshopify.com`, `myshopify.io`, `spin.dev`, `shop.dev`) as done elsewhere in the library: [6](#0-5) 

a caller (or any code path that forwards an unsanitized query-string `shop` value straight into `begin_auth`) will cause the app to redirect the merchant's browser — carrying the real app's `client_id`, `redirect_uri`, and the freshly minted `state` cookie value — to an attacker-controlled host instead of a genuine Shopify domain. This is a textbook "confused deputy"/forced-OAuth-completion setup: the attacker's server can capture the state/authorize request destined for the app's real `redirect_uri` and orchestrate a forced completion of the OAuth flow against a shop of the attacker's choosing, since the gem provides no internal safety net that other credential flows in the same file family provide.

### Impact Explanation
This falls into the High-impact category of "session fixation or forced OAuth completion" explicitly listed as in-scope: the OAuth handshake's authorize destination is not bound to a verified Shopify tenant, allowing an attacker to redirect a victim's authorization flow to an arbitrary host and manipulate which shop the state/nonce pair is later completed against.

### Likelihood Explanation
Likelihood is moderate to high: `begin_auth`'s `shop` parameter is, by design, typically sourced from an inbound HTTP request (`?shop=` query parameter during app install/login), an unauthenticated, attacker-controllable value at that point in the flow — exactly the class of input the library's own `ShopValidator` module exists to sanitize. Every sibling method in the auth family (`client_credentials`, `migrate_to_expiring_token`) treats this input as untrusted and sanitizes it before use; `begin_auth` is the outlier.

### Recommendation
Call `Utils::ShopValidator.sanitize!(shop)` (or `sanitize_shop_domain`) at the top of `Oauth.begin_auth`, exactly as done in `ClientCredentials.client_credentials` and `TokenExchange.migrate_to_expiring_token`, and raise `Errors::InvalidShopError` for any shop value that is not a trusted Shopify domain before it is used to construct `auth_base_uri`.

### Proof of Concept
1. A host application exposes a login route that calls:
   ```ruby
   ShopifyAPI::Auth::Oauth.begin_auth(shop: params[:shop], redirect_path: "/auth/callback")
   ```
2. An attacker sends a victim a link with `?shop=attacker.example`.
3. `begin_auth` computes `auth_base_uri("attacker.example")` → `"https://attacker.example/admin"`, with no validation, and returns:
   `auth_route = "https://attacker.example/admin/oauth/authorize?client_id=<real_app_client_id>&scope=...&redirect_uri=<real_app_host>/auth/callback&state=<nonce>"`
4. The victim's browser is redirected to the attacker's server carrying the real app's `client_id` and the OAuth `state` nonce (also stored in the `state` cookie via `SessionCookie`), which the attacker can use to stage a forced-completion / phishing attack against the OAuth flow, since neither `begin_auth` nor `auth_base_uri` performs the `ShopValidator` check that the sibling flows perform.

        def begin_auth(shop:, redirect_path:, is_online: true, scope_override: nil)
          scope = if scope_override.nil?
            ShopifyAPI::Context.scope
          elsif scope_override.is_a?(ShopifyAPI::Auth::AuthScopes)
            scope_override
          else
            ShopifyAPI::Auth::AuthScopes.new(scope_override)
          end

          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = SecureRandom.alphanumeric(NONCE_LENGTH)

          cookie = SessionCookie.new(value: state, expires: Time.now + 60)

          query = {
            client_id: ShopifyAPI::Context.api_key,
            scope: scope.to_s,
            redirect_uri: "#{ShopifyAPI::Context.host}#{redirect_path}",
            state: state,
            "grant_options[]": is_online ? "per-user" : "",
          }

          query_string = URI.encode_www_form(query)
          auth_route = auth_base_uri(shop) + "/oauth/authorize?#{query_string}"

          { auth_route: auth_route, cookie: cookie }
        end
```

        def auth_base_uri(shop)
          return "https://#{shop}/admin" unless defined?(DevServer) && shop.include?(".my.shop.dev")

          # For first-party apps in development only, we leverage DevServer to build the admin base URI
          admin_web = T.unsafe(Object.const_get("DevServer")) # rubocop:disable Sorbet/ConstantsFromStrings
            .new("admin-web")
          admin_host = admin_web.host!(nonstandard_host_prefix: "admin")
          shop_name = shop.split(".").first

          "https://#{admin_host}/store/#{shop_name}"
        end
