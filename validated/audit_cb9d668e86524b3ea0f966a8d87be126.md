### Title
Emporium arbitrary-call execution with empty `erc20TokenAddresses` bypasses all balance accounting, allowing theft of funds held by the shared Emporium contract - (File: `contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol`, `contracts/CircomDataBuilder.sol`)

### Summary
The reported Yield Protocol issue is about minting tokens to `msg.sender` based on ambient contract state instead of an audited, atomic flow, letting an attacker capture value that belongs to someone else. The Hinkal analog is structurally different but breaks the same kind of equality: the `EmporiumUpgradeable.runAction` "Stateless Interaction" branch executes attacker-supplied `endpoint.call(callData)` from the Emporium contract's own context [1](#0-0) , and when `circomData.erc20TokenAddresses` is empty, neither `Hinkal.sol`'s balance-diff loop nor `EmporiumUpgradeable`'s own before/after balance loop execute at all, so any asset moved by those ops is completely unaccounted for.

### Finding Description
`Hinkal.sol`'s outer balance equation iterates only over `circomData.erc20TokenAddresses` [2](#0-1) . `EmporiumUpgradeable.runAction` also snapshots and re-checks balances only for the same array [3](#0-2) . `CircomDataBuilder.formInputForCircom` explicitly special-cases the situation where the Emporium action is used with `erc20TokenAddresses.length == 0`, switching to a drastically reduced public-input set (`formInputEmporiumMin`) that contains only `emporiumMessage`, `timeStamp`, and `calldataHash` — no root hash, no nullifiers, no amount changes [4](#0-3) .

Combining these: an unprivileged caller can submit a `transact()` call with `externalActionData.externalActionId` set to the Emporium action and `erc20TokenAddresses = []`. This causes:
1. `Hinkal.sol`'s per-token balance/slippage loop to run zero iterations, so it enforces nothing about the tokens actually touched by the Emporium ops.
2. `EmporiumUpgradeable.runAction`'s own `balancesBefore`/`balancesAfter` loop to also run zero iterations, so `handleOut` (the only function tying moved value back to a UTXO/msg.sender) never executes and never gates the ops.
3. The `EmporiumStack.ops` array (decoded from `externalActionData.externalActionMetadata`) to still be executed via `op.endpoint.call{value: op.value}(op.callData)` [1](#0-0) , with `msg.sender` (i.e., `address(this)` from the token's perspective) being the Emporium contract itself.
4. `verifyWallet` skipping any ECDSA signature check whenever `stack.signerAddress == address(0)` [5](#0-4) .

The only remaining gate is `calldataHash`/proof verification, but that only proves the attacker knows a preimage consistent with `formInputEmporiumMin`'s three values — it does not constrain what tokens the crafted `ops` interact with, since no root hash or nullifier is part of that minimal public-input vector. As a result, an attacker can set `op.endpoint` to any ERC20 token that currently has a balance sitting on the shared Emporium contract (leftover dust from partial swaps, unswept intermediate router hops, accumulated relay fees, or accidental transfers) and `op.callData` to `transfer(attacker, amount)`, draining it with zero balance accounting on either side of the system.

### Impact Explanation
This is a direct theft path: value held by the shared Emporium contract (protocol/relay fees, dust from other users' swap routes, or any ERC20/ETH balance resident on that contract) can be moved to an attacker-controlled address without spending any nullifier, without any signature, and without triggering any balance-equation revert, because the accounting loop that would normally catch an unbacked/unauthorized balance change is skipped entirely when `erc20TokenAddresses` is empty. This matches the "Critical: direct theft of shielded or in-flight user funds ... executing calls or moving assets a wallet owner or prover never authorised" impact tier.

### Likelihood Explanation
Likelihood is high for anyone who can construct a valid proof for the `formInputEmporiumMin` circuit shape (which requires no knowledge of another user's secret — only self-consistent `emporiumMessage`/`timeStamp`/`calldataHash`), and who observes any nonzero balance sitting on the Emporium contract address (a very plausible on-chain condition given multi-hop router usage and fee residue). No admin, relay, or another user's key is required.

### Recommendation
Do not allow `erc20TokenAddresses.length == 0` to bypass the Emporium balance-accounting loop in `EmporiumUpgradeable.runAction`; require the Emporium action to always enumerate every token address touched by `ops` (or scan and diff Emporium's balance for any token the ops reference), and require `formInputForCircom` to still bind a full public-input vector (root hash / nullifiers) even for the "min" Emporium branch. Additionally, restrict `op.endpoint.call` in the Stateless Interaction branch to only the tokens declared in `circomData.erc20TokenAddresses`, so arbitrary token contracts held by the Emporium cannot be targeted by unaccounted calls.

### Proof of Concept
1. Attacker observes (or forces via a partial/failed swap route) some ERC20 token balance `T` sitting on the deployed `EmporiumUpgradeable` proxy.
2. Attacker calls `Hinkal.transact()` with `circomData.externalActionData.externalActionId = HINKAL_EMPORIUM_ACTION_ID`, `circomData.erc20TokenAddresses = []`, and `externalActionMetadata` encoding an `EmporiumStack` with `signerAddress = address(0)` and a single op: `{ endpoint: T, invokeWallet: false, value: 0, callData: abi.encodeCall(IERC20.transfer, (attacker, balanceOfT)) }`.
3. Attacker supplies a self-generated proof consistent with `formInputEmporiumMin` (only `emporiumMessage`, `timeStamp`, `calldataHash` — no nullifier/root-hash knowledge of anyone else's funds needed).
4. `Hinkal.sol`'s and `EmporiumUpgradeable.runAction`'s balance loops both run zero iterations (array length 0); `verifyWallet` skips signature verification (`signerAddress == address(0)`); the op executes `T.transfer(attacker, balanceOfT)` from the Emporium contract, draining it with no revert and no accounting record.

    function formInputForCircom(
        uint256 chainId,
        address verifyingContract,
        CircomData calldata circomData
    ) internal pure returns (uint256[] memory) {
        if (
            circomData.externalActionData.externalActionId ==
            HINKAL_EMPORIUM_ACTION_ID &&
            circomData.erc20TokenAddresses.length == 0
        ) {
            return formInputEmporiumMin(circomData);
        } else {
            return formInputNormal(chainId, verifyingContract, circomData);
        }
    }

    function formInputEmporiumMin(
        CircomData calldata circomData
    ) internal pure returns (uint256[] memory input) {
        input = new uint256[](circomData.publicSignalCount);

        uint16 index = 0;

        input[index++] = circomData.emporiumMessage;

        input[index++] = circomData.timeStamp;
        input[index++] = circomData.calldataHash;
    }
