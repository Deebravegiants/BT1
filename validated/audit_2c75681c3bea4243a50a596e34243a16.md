## Analog Found

### Title
Consensus relayer rewards priced at the current `cost_per_block` rate instead of the rate in effect during each backlog block, enabling retroactive reward inflation - ([File: modules/pallets/consensus-incentives/src/impls.rs])

### Summary
`pallet-consensus-incentives` pays relayers for delivering ISMP consensus messages using `Reward = (LatestHeight − Baseline) × CostPerBlock`, where `CostPerBlock` is read live at claim time rather than tracked historically. A relayer that delays submitting a consensus update accumulates a large unpaid block span (`LatestHeight − LastRewardedHeight`) and then collects the *entire* span at whatever rate governance happens to have set at the moment of submission — identical in shape to the RLQ-1 pattern where a lazily-updated "level" is applied retroactively to an entire holding period instead of being time-weighted.

`process_message` then pays out `reward = blocks_as_balance * block_cost` using this single rate for the whole `blocks` span, and advances the `LastRewardedHeight` watermark: [4](#0-3) 

Because `on_executed` fires on every accepted consensus message and is fully permissionless — any relayer submitting a valid consensus proof triggers `process_message` — a relayer controls *when* it "checks in" a backlog of blocks, and therefore which `CostPerBlock` value applies to that whole backlog. This mirrors RLQ-1's root cause exactly: the reward-relevant "level" (here, the per-block cost) is evaluated only at settlement time and applied uniformly across a historical period that should have been split across the different levels that were actually in effect.

### Impact Explanation
If governance raises `CostPerBlock` for a state machine (e.g., due to rising RPC/infra costs), a relayer who withholds delivery of consensus updates for that chain builds up a large unpaid `blocks` span at the old (lower) rate, then submits once the new (higher) rate is live and collects the full backlog at the higher rate. This directly overpays from the protocol `TreasuryAccount`, draining funds beyond what the per-block schedule was designed to cover — a treasury/fund-loss issue reachable from a single relayed consensus message, with no privileged access required beyond normal relaying.

### Likelihood Explanation
Any account watching for `StateMachineCostPerBlockUpdated` governance events (a public, on-chain event) can trivially time a single consensus message submission to land immediately after a rate increase, converting a purely observable governance action into outsized personal profit. No special access or race condition beyond public event-watching and normal relaying is required.

### Recommendation
Track the cost-per-block rate historically (e.g., a per-height or per-epoch schedule), and compute the reward as a sum over the sub-spans that were active under each historical rate rather than applying the single current rate to the entire unpaid span. Alternatively, cap the maximum unpaid block span a single claim can cover, or snapshot/settle the reward at each rate-change boundary so no backlog can straddle a rate change.

### Proof of Concept
1. Governance sets `StateMachinesCostPerBlock[chain_X] = 10` via `update_cost_per_block`.
2. A relayer refrains from submitting consensus updates for `chain_X` while its actual height advances by, say, 10,000 blocks (`LastRewardedHeight` watermark stays frozen at the old height).
3. Governance later raises the rate: `update_cost_per_block(chain_X, 1000)` (e.g., due to increased verification cost).
4. The relayer immediately submits a single consensus message that advances `latest_height` by the full 10,000-block backlog.
5. `on_executed` → `process_message` → `calculate_reward` reads the *current* `block_cost = 1000` and pays `10,000 × 1000` instead of the ~`10,000 × 10` that reflects the rate actually in effect while those blocks were produced — a ~100x overpayment from the treasury for a single message.

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}

		/// Update cost per block for a state machine
		#[pallet::call_index(0)]
		#[pallet::weight(T::WeightInfo::update_cost_per_block())]
		pub fn update_cost_per_block(
			origin: OriginFor<T>,
			state_machine_id: StateMachineId,
			cost_per_block: <T as pallet_ismp::Config>::Balance,
		) -> DispatchResult {
			T::IncentivesOrigin::ensure_origin(origin)?;

			StateMachinesCostPerBlock::<T>::mutate(state_machine_id.clone(), |maybe_cost| {
				*maybe_cost = Some(cost_per_block);
			});

			Self::deposit_event(Event::<T>::StateMachineCostPerBlockUpdated {
				state_machine_id,
				cost_per_block,
			});

			Ok(())
		}
