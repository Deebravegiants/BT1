### Title
Webhook shop identity spoofing via unauthenticated `shop-domain` header not covered by HMAC - (File: lib/shopify_api/webhooks/request.rb)

### Summary
`ShopifyAPI::Webhooks::Request` computes its HMAC-signable string from the raw body only [1](#0-0) , but `shop`, `topic`, `webhook_id`, and `api_version` are all read from HTTP headers that are never included in the HMAC computation [2](#0-1) . Because the webhook HMAC secret (`Context.api_secret_key`) is shared across every shop that installs the app [4](#0-3) , any party that legitimately receives one valid webhook (e.g. by installing the app on their own store) can capture that request's `(body, hmac)` pair — which remains valid for that body regardless of shop — and resubmit it to the app's webhook endpoint with an arbitrary `x-shopify-shop-domain` header. `Registry.process` only checks the HMAC of the body before trusting `request.shop` as the identity for dispatch [3](#0-2) .

### Finding Description
The identity binding broken is: **shop authenticated by HMAC ≠ shop used as the tenant key for dispatch.** The HMAC only proves "this body was produced with the app's secret"; it says nothing about which shop the body belongs to, since `shop` comes from the `x-shopify-shop-domain`/`shopify-shop-domain` header, entirely outside `to_signable_string`. Any attacker who is themselves a merchant using the app (an "unprivileged" but legitimate webhook sender for their own shop) receives valid `(raw_body, hmac)` webhook payloads signed with the single, non-shop-specific `api_secret_key`. They can replay that exact `raw_body`/`hmac` pair to the same webhook endpoint while substituting a different value for the `shop-domain` header (and freely for `topic`/`webhook_id`/`api_version`, also unauthenticated). `Utils::HmacValidator.validate` will still succeed because it recomputes the HMAC only over the (unchanged) body [5](#0-4) , and `Registry.process` passes the spoofed `request.shop` straight to the host application's handler as the shop identity for that event [6](#0-5) .

### Impact Explanation
This enables cross-tenant confusion: the app processes an event that is HMAC-valid (attesting only "made by our app secret") as if it belongs to shop B when it actually originated from/for shop A. Any host application that uses `data.shop` from `WebhookMetadata` to key writes (e.g., updating billing state, order data, redact/GDPR compliance actions, or shop-scoped records) can be made to apply shop-A's webhook content under shop-B's identity, or vice versa — a cross-tenant data integrity/access issue.

### Likelihood Explanation
Requires only that the attacker be a merchant able to install the app (to receive at least one real signed webhook) or otherwise observe one legitimate webhook delivery, then replay it with a modified `shop-domain` header value against the app's public webhook endpoint. No access to `api_secret_key`, tokens, or any privileged access is required.

### Recommendation
Include `shop`, `topic`, `webhook_id`, and `api_version` in the HMAC-signed payload (or otherwise cryptographically bind them to the body), or independently verify that the shop-domain header corresponds to a shop known to have a currently-registered webhook subscription/session before dispatching to handlers.

### Proof of Concept
```ruby
# Attacker legitimately installs the app on shop-a.myshopify.com and
# receives a real webhook, e.g. body = "{}" with a valid hmac computed
# from api_secret_key over "{}" (the body only, per to_signable_string).
hmac = OpenSSL::HMAC.digest(OpenSSL::Digest.new("sha256"), api_secret_key, "{}")

# Attacker resubmits the same body+hmac to the app's webhook endpoint,
# but swaps the shop-domain header to a victim shop:
headers = {
  "x-shopify-topic"       => "shop/redact",              # also attacker-controlled
  "x-shopify-hmac-sha256" => Base64.encode64(hmac),        # still valid - body unchanged
  "x-shopify-shop-domain" => "victim-shop.myshopify.com",  # spoofed identity
  "x-shopify-webhook-id"  => "attacker-chosen-id",
  "x-shopify-api-version" => "2024-01",
}

request = ShopifyAPI::Webhooks::Request.new(raw_body: "{}", headers: headers)
ShopifyAPI::Webhooks::Registry.process(request)
# => HmacValidator.validate(request) returns true (only body is checked)
# => handler.handle(data: WebhookMetadata(shop: "victim-shop.myshopify.com", ...))
```
