### Title
Reward accumulation during zero-cost (paused) incentive period lets a relayer claim a windfall treasury payout on re-enable - ([File: modules/pallets/consensus-incentives/src/impls.rs])

### Summary
`pallet-consensus-incentives` rewards a relayer for consensus updates based on `(latest_height − baseline) * cost_per_block`, where `baseline` is either the `LastRewardedHeight` watermark or the previous commitment height. The watermark is only advanced when a *non-zero* reward is actually paid. If governance pauses incentives for a state machine by setting `cost_per_block = 0` (rather than removing the entry), any consensus updates that land during the pause never advance `LastRewardedHeight`. When incentives are later re-enabled with a non-zero `cost_per_block`, the next relayer to submit a consensus message is paid for the *entire* block span accumulated since the last non-zero payout — including the whole "inactive"/paused interval — exactly the reward-accumulation-during-inactive-time-period bug class described in the report, ported from a per-second accrual model to this per-block accrual model.

### Finding Description
`calculate_reward` computes the payable span purely as a height delta against a stored watermark, with no accounting for whether reward emission was actually "on" during that span: [1](#0-0) 

`process_message` only advances `LastRewardedHeight` inside the branch that actually transfers a non-zero reward: [2](#0-1) 

Note the early return `if reward.is_zero() { return Ok(()); }` executes **before** the `LastRewardedHeight::<T>::mutate(...)` call. Consequently, whenever `StateMachinesCostPerBlock` for a chain is `Some(0)` (the state after `update_cost_per_block(id, 0)`, distinct from `remove_incentives` which deletes the entry entirely), every consensus update processed by `on_executed` computes `reward == 0` and skips updating the watermark — even though the underlying state machine's `latest_commitment_height` keeps advancing block-by-block as consensus messages are submitted (via the unprivileged, unsigned `pallet_ismp::handle_unsigned` extrinsic path used by any relayer).

`on_executed` is invoked unconditionally on every accepted `ConsensusMessage`: [3](#0-2) 

`update_cost_per_block` is a normal governance-settable value with no restriction against being set to `0` and later raised again: [4](#0-3) 

So the sequence:
1. Governance sets `cost_per_block = 0` for chain X (e.g., to temporarily pause spend, or simply never having enabled rewards yet after removal via a different path).
2. Height keeps advancing for many blocks/epochs while relayers submit consensus updates for free (reward = 0, watermark frozen).
3. Governance sets `cost_per_block` back to a non-zero value.
4. The very next relayer to submit a `ConsensusMessage` triggers `calculate_reward`, which computes `latest_height − baseline` where `baseline` is the *stale* `LastRewardedHeight` (or `previous_commitment_height` if never set) from before the pause began. The relayer is paid for the **full accumulated span**, including all blocks that elapsed during the zero-reward window, at the *newly re-enabled* rate — a lump-sum payout for work (and time) during which the protocol had explicitly set the incentive to zero.

This is analogous to the reported Move `update_reward_infos` bug: the accrual calculation is driven only by "current vs. last recorded checkpoint," with no notion of whether the emission was actually active in that interval, so re-enabling a zero-reward feed retroactively (and unintentionally) grants rewards for the entire dormant period to whichever single relayer transaction happens to land first after re-enable.

### Impact Explanation
This causes an unbacked/unintended drain of the `TreasuryAccount` funds and an unbacked mint of the `ReputationAsset` to a single relayer account, sized by however many blocks accumulated during the pause (potentially very large if the state machine was paused for a long period while still being finalized/updated). This is a real, direct value-transfer bug reachable by any unprivileged relayer simply submitting the next unsigned `ConsensusMessage` after governance re-enables the reward — satisfying "concrete theft... of funds" from the treasury via unsound reward accounting.

### Likelihood Explanation
Requires governance to have used `update_cost_per_block(id, 0)` (versus `remove_incentives`) to pause a chain's incentive and later re-enable it — a plausible operational action (e.g., temporarily halting spend without losing the configured watermark semantics, or simply configuring a chain before deciding on final pricing). Once that state occurs, exploitation requires no special access: any relayer's routine, permissionless, unsigned consensus-message submission triggers the payout. Likelihood is Medium — contingent on a specific but realistic governance operational sequence.

### Recommendation
Decouple "was a reward computed and paid" from "should the accrual baseline advance." The watermark `LastRewardedHeight` should be advanced to `latest_height` whenever a consensus update is processed, regardless of whether `cost_per_block` was zero at the time, so that a later non-zero rate never retroactively covers a window that was explicitly zero-cost. Concretely, move the `LastRewardedHeight::mutate` call out of the "reward is non-zero" branch and execute it unconditionally whenever a `StateMachineUpdated` event advances `latest_height` for that state machine (whether or not a transfer occurs), while still guarding the actual `T::Currency::transfer`/`mint_into` calls behind `reward.is_zero()`.

### Proof of Concept
1. Governance calls `update_cost_per_block(state_machine_id, 100)` — incentive active, watermark advances normally with each relayed consensus update.
2. Governance calls `update_cost_per_block(state_machine_id, 0)` — incentive "paused."
3. Over N blocks, relayers keep submitting valid consensus updates for state_machine_id (as required to keep the light client current); each call to `on_executed` → `process_message` → `calculate_reward` returns `0`, and `LastRewardedHeight` is never mutated, remaining at the value from step 1's last payout while `latest_commitment_height` advances by N.
4. Governance calls `update_cost_per_block(state_machine_id, 100)` again.
5. The next relayer submits one more consensus update; `calculate_reward` computes `reward = N * 100` (covering the entire paused span) and pays it in full to that single relayer via `T::Currency::transfer` from `TreasuryAccount`, plus mints `N*100` reputation asset — confirmable by adapting the existing test `reward_covers_only_unpaid_heights_after_rollback` in `modules/pallets/testsuite/src/tests/pallet_consensus_incentives.rs` to insert a zero-cost interval between two non-zero-cost periods and asserting the treasury debit equals the full span rather than only the post-re-enable span.

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}

	fn on_executed(
		messages: Vec<MessageWithWeight>,
		events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});

		if let Some(relayer_account) = maybe_relayer_account {
			// When a batch contains multiple `StateMachineUpdated` events for the
			// same `state_machine_id` (sequential consensus updates for the same
			// chain), `calculate_reward` reads the same persisted
			// `(latest_commitment_height, previous_commitment_height)` pair on
			// every iteration and pays the same block-span reward N times.
			// Collapse the per-state-machine event stream to the single highest
			// `latest_height` so each state machine receives one reward per
			// batch, sized by the actual span of its commitment advance.
			let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
			for event in events {
				if let IsmpEvent::StateMachineUpdated(update) = event {
					highest_per_state_machine
						.entry(update.state_machine_id)
						.and_modify(|h| {
							if update.latest_height > *h {
								*h = update.latest_height;
							}
						})
						.or_insert(update.latest_height);
				}
			}

			for (state_machine_id, latest_height) in highest_per_state_machine {
				let state_machine_height =
					StateMachineHeight { id: state_machine_id.clone(), height: latest_height };

				let _ = Self::process_message(
					state_machine_height,
					state_machine_id,
					relayer_account.clone().into(),
				);
			}
		}

	#[pallet::call]
	impl<T: Config> Pallet<T> {
		/// Update cost per block for a state machine
		#[pallet::call_index(0)]
		#[pallet::weight(T::WeightInfo::update_cost_per_block())]

			state_machine_id: StateMachineId,

				state_machine_id,
				cost_per_block,
			});
