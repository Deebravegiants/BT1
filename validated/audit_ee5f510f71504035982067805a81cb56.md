**Reasoning summary:**

The claimed attack requires the API's script-argument decoder to derive an argument's displayed type from the client-supplied `TransactionArgument` tag (e.g., trusting that a byte blob is "U8Vector" vs "Address") independently of the actual script code. That is not how decoding works.

`try_into_script_payload` in [1](#0-0)  calls `view_script_arguments`, which is implemented in the Move resource viewer at [2](#0-1) . This function:

1. Deserializes the **actual submitted script bytecode** into a `CompiledScript` and reads its **true parameter type signature** (`compiled_script.signature_at(compiled_script.parameters)`), i.e. the ground-truth types the Move VM itself will use to execute the script.
2. Converts the client's `TransactionArgument` list into raw BCS bytes via `convert_txn_args` [3](#0-2) . The `TransactionArgument` variant only controls *how the value is BCS-serialized*, not how it is later *interpreted*.
3. `view_arguments_or_returns` then decodes each argument's bytes strictly according to the script's own compiled parameter type (`FatType`), not according to the tag the attacker chose [4](#0-3) .

Because the same compiled-script signature is the ground truth for both (a) how the Move VM actually executes the script and (b) how the API annotates/display its arguments, an attacker cannot make the API display an address argument as a byte vector (or vice versa) while the VM executes it as the opposite type — the interpretation is single-sourced from the real bytecode, not from client metadata. If decoding fails (e.g., due to a genuine type mismatch), the code falls back to `convert_txn_args` and renders **every** argument uniformly as raw hex bytes [5](#0-4) , which is a generic degraded display, not a selective type-mislabeling that could disguise an ownership-transfer call.

The entry-function path is analogous: `view_function_arguments` resolves parameter types from the real, on-chain entry function definition, not from client-declared argument types [6](#0-5) .

There is therefore no path by which crafting a `ScriptPayload`'s `TransactionArgument` list can desynchronize the API's decoded `script.arguments` from what the script will actually do on-chain, so this does not cross a custody boundary.

        &self,

        args: &[TransactionArgument],
        ty_args: &[TypeTag],

    fn view_arguments_or_returns(
        &self,
        param_tys: &[FatType],
        ty_args: &[TypeTag],
        args: &[Vec<u8>],
        limit: &mut Limiter,
    ) -> anyhow::Result<Vec<AnnotatedMoveValue>> {
        let types: Vec<&FatType> = param_tys
            .iter()
            .filter(|t| match t {
                FatType::Signer | FatType::Function(_) => false,
                FatType::Reference(inner) => !matches!(&**inner, FatType::Signer),
                FatType::Bool
                | FatType::U8
                | FatType::U64
                | FatType::U128
                | FatType::Address
                | FatType::Vector(_)
                | FatType::Struct(_)
                | FatType::MutableReference(_)
                | FatType::TyParam(_)
                | FatType::U16
                | FatType::U32
                | FatType::U256
                | FatType::I8
                | FatType::I16
                | FatType::I32
                | FatType::I64
                | FatType::I128
                | FatType::I256 => true,
            })
            .collect();
        anyhow::ensure!(
            types.len() == args.len(),
            "unexpected error: argument types({}) and values({}) are not matched",
            types.len(),
            args.len(),
        );

        let ty_args: Vec<FatType> = ty_args
            .iter()
            .map(|ty| self.resolve_type_impl(ty, limit))
            .collect::<anyhow::Result<_>>()?;

        if ty_args.is_empty() {
            types
                .iter()
                .enumerate()
                .map(|(i, ty)| self.view_value_by_fat_type(ty, &args[i], limit))
                .collect::<anyhow::Result<Vec<AnnotatedMoveValue>>>()
        } else {

/// Convert the transaction arguments into Move values.
pub fn convert_txn_args(args: &[TransactionArgument]) -> Vec<Vec<u8>> {
    args.iter()
        .map(|arg| {
            if let TransactionArgument::Serialized(bytes) = arg {
                bytes.clone()
            } else {
                MoveValue::from(arg.clone())
                    .simple_serialize()
                    .expect("transaction arguments must serialize")
            }
        })
        .collect()
}
