### Title
Successful GET response delivery does not clear `_requestCommitments`, allowing the same request to also be dispatched as a timeout - ([File: evm/src/core/EvmHost.sol])

### Summary
This is a direct analog of the reported bug class: a tracking mapping (`orderTriggerBlock` in the external report, `_requestCommitments` here) is left stale after the event it guards has been fully processed, allowing a second, conflicting operation to be dispatched against the same logical request. On Hyperbridge's EVM side, `EvmHost.dispatchIncoming(GetResponse)` never deletes `_requestCommitments[commitment]` when the GET response is successfully delivered, whereas the timeout path (`dispatchTimeOut(GetRequestTimeout)`) treats a non-empty `_requestCommitments[commitment]` entry as proof that the request is still "live" and eligible for timeout.

### Finding Description
`EvmHost.dispatchIncoming(GetResponse)` stores a `_responseReceipts[commitment]` for replay protection and, on success, reads `_requestCommitments[commitment].fee` to pay the relayer — but it never deletes `_requestCommitments[commitment]` on the success path: [1](#0-0) 

Compare this with `dispatchTimeOut(GetRequestTimeout, ...)`, which relies on `_requestCommitments[commitment]` being present/absent to gate whether a timeout can be processed, and explicitly deletes it for replay protection: [2](#0-1) 

`HandlerV2.handleGetRequestTimeouts` (and the analogous post-timeout handler) treats a non-zero `FeeMetadata.sender` from `host.requestCommitments(commitment)` as proof that the request is "known" and eligible for timeout processing — it does not check whether a `GetResponse` has already been delivered for that same request: [3](#0-2) 

By contrast, the Substrate/pallet-ismp implementation of the same protocol explicitly guards against this exact scenario: the GET timeout handler checks `host.response_receipt(&response).is_some()` and rejects the timeout with `GetResponseAlreadyReceived` if a response was already received: [4](#0-3) 

This confirms the protocol's own invariant is that a request must be resolved by *either* a response *or* a timeout, never both — but the EVM `EvmHost` implementation fails to enforce it, because it never clears the `_requestCommitments` entry once the response path has completed. This is architecturally identical to the reported `orderTriggerBlock` bug: a per-entity tracking value that should be reset on "removal"/finalization of the entity is left behind, and a later, differently-gated code path (timeout dispatch) treats the stale value as evidence the entity is still pending.

### Impact Explanation
If a relayer (an unprivileged, permissionless actor — `handleGetResponses`/`handleGetRequestTimeouts` are both callable by anyone) delivers a valid `GetResponse` for a request whose `timeoutTimestamp` has since elapsed (or elapses shortly after), a second relayer can subsequently submit a valid non-membership timeout proof for the very same request. Because `_requestCommitments[commitment]` was never deleted after the successful response, `HandlerV2.handleGetRequestTimeouts`'s "known request" check still passes, and `EvmHost.dispatchTimeOut` will call `IApp.onGetTimeout` on the same application that already received `IApp.onGetResponse` for that request. Any `IApp` (such as `IntentGatewayV2`, which uses GET requests/timeouts to drive escrow refund logic) that assumes response and timeout are mutually exclusive for a given commitment can be made to execute both code paths, potentially causing duplicate state transitions (e.g., double refund/withdraw attempts) or unauthorized app actions triggered from a state the app believed to be already resolved.

### Likelihood Explanation
The precondition is fully attacker/relayer-controllable and requires no privileged role: any relayer can call `handleGetResponses`, and any relayer can subsequently call `handleGetRequestTimeouts` with a valid non-membership proof once the timeout timestamp has passed. No governance, admin, or protocol-side race condition beyond ordinary relayer timing is required — only a request whose response arrives close to (or slightly after) its `timeoutTimestamp`, which is a normal-enough occurrence in cross-chain messaging under network delay.

### Recommendation
In `EvmHost.dispatchIncoming(GetResponse)`, delete `_requestCommitments[commitment]` once the response has been successfully delivered (mirroring how `dispatchTimeOut` deletes it for the timeout path), and/or have `HandlerV2.handleGetRequestTimeouts` explicitly check `_responseReceipts[commitment]` and reject the timeout if a response was already recorded — matching the `GetResponseAlreadyReceived` guard already implemented in the Substrate `handlers::timeout` module.

### Proof of Concept
1. App `A` dispatches a `GetRequest` with `timeoutTimestamp = T`; `EvmHost.dispatch` stores `_requestCommitments[commitment] = meta` (fee, sender).
2. Just before or around `T`, a relayer submits a valid `GetResponseMessage` to `HandlerV2.handleGetResponses`, which calls `EvmHost.dispatchIncoming(GetResponse)`. `IApp.onGetResponse` executes successfully (e.g., `IntentGatewayV2` refunds escrow via `withdraw()`); `_requestCommitments[commitment]` remains untouched (per `evm/src/core/EvmHost.sol` lines 824-847).
3. After `T` has elapsed, any relayer submits a valid non-membership timeout proof to `HandlerV2.handleGetRequestTimeouts`. The "known request" check `host.requestCommitments(requestCommitment).sender != address(0)` still passes because the entry was never deleted.
4. `EvmHost.dispatchTimeOut(GetRequestTimeout, ...)` is invoked, calling `IApp.onGetTimeout` on the same app for the same commitment that already processed `onGetResponse` — resulting in duplicate/conflicting state transitions in the destination application.

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function handlePostRequestTimeouts(IHost host, PostRequestTimeoutMessage calldata message)
        external
        notFrozen(host)
    {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            PostRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            // known request? also serves as source check
            bytes32 requestCommitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(requestCommitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(REQUEST_RECEIPTS_STORAGE_PREFIX, requestCommitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(PostRequestTimeout(request, _msgSender()), meta, requestCommitment);
        }
    }
