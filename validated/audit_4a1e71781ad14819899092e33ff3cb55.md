## Analysis

The Symmetrical bug pattern is: a fee is collected upfront to fund an action, that action later becomes permanently unresolvable through no fault of the fee-payer, and the fee is neither delivered to its intended recipient nor refunded to the payer. The closest reachable analog in Hyperbridge is in the Intent Gateway's **source-side order cancellation** flow, which dispatches an ISMP GET request to prove an order is unfilled before refunding escrow.

### Title
Relayer fee for a source-chain order cancellation is permanently locked when the order was actually filled - (File: `evm/src/apps/intentsv2/ExtrinsicIntents.sol`)

### Summary
When a user cancels a cross-chain order from the source chain, `_cancelFromSource` dispatches a Hyperbridge `DispatchGet` request with `timeout: 0` and pays `options.relayerFee` upfront to fund the request/response round trip. If the destination proof shows the order was genuinely filled, `onGetResponse` reverts with `Filled()` every time it is delivered — permanently, since the underlying fact (the order is filled) never changes. Because the GET request has no timeout, and `EvmHost.dispatchIncoming(GetResponse)` only pays out the relayer fee when the app callback succeeds, the fee sits forever in the fee-token commitment for that request with no code path to release it to the relayer or refund it to the payer.

### Finding Description
`_cancelFromSource` builds and dispatches the cancellation-proof request: [1](#0-0) 

The relayer fee is escrowed by `EvmHost.dispatch(DispatchGet)` under `_requestCommitments[commitment]`, keyed only by the request commitment, with no distinguishing timeout since `timeout: 0` is passed (i.e., the request never times out).

When the destination proof is delivered, the source gateway's callback either refunds escrow (slot empty) or reverts if the order was filled: [2](#0-1) 

`EvmHost.dispatchIncoming(GetResponse)` pays the relayer fee to the delivering relayer **only if** the callback succeeds; on revert it merely deletes the response receipt so the same delivery can be retried, leaving the fee untouched in the commitment mapping: [3](#0-2) 

If the order was actually filled by a solver, `onGetResponse` will always revert with `Filled()` for that commitment, no matter how many times the message is resubmitted — the destination storage slot will never become empty. Since the GET request's `timeout` is hardcoded to `0` in `_cancelFromSource`, `EvmHost.dispatchTimeOut(GetRequestTimeout)` — the only other exit path that could release these funds (though explicitly documented as *not* refunding fees for GET requests) — can never even be triggered. The `options.relayerFee` paid by the user when calling `cancelOrder` is therefore permanently stranded in the host's fee-token balance: never paid to a relayer (the callback never succeeds), never refunded to the payer (no refund path exists for a non-timing-out, permanently-reverting GET response).

### Impact Explanation
This is a permanent freezing of user funds. Any user who calls `cancelOrder` on the source chain for an order that has already been (or gets) filled on the destination before the cancellation proof is generated loses their `options.relayerFee` unconditionally — the fee-token amount is locked in the `EvmHost` contract forever, unreachable by governance, the user, or any relayer. This is a normal, expected user action (attempting a cancellation) rather than a malicious one, and the loss occurs with high likelihood: any race between a solver's fill and a user's cancellation from source will trigger it.

### Likelihood Explanation
Likelihood is high: fill-vs-cancel races are an expected, permissionless, and common occurrence in the Intent Gateway's cross-chain order lifecycle. The `_cancelFromSource` path is explicitly documented as usable any time after `order.deadline`, precisely the window when a solver may have just filled the order, so a legitimate user following documented cancellation flow can trigger this loss without any special conditions or malicious actors.

### Recommendation
Give the source-chain GET request a real, bounded `timeout` in `_cancelFromSource` so that `EvmHost.dispatchTimeOut(GetRequestTimeout)` can eventually be triggered, and/or add an explicit fee-refund path invoked from `onGetResponse` when reverting with `Filled()`, so the `payer` recovers `options.relayerFee` instead of it being permanently stranded in the host.

### Proof of Concept
1. User places a cross-chain order and it is later filled by a solver, calling `RedeemEscrow` back to the source chain via `onAccept`, so `_filled[commitment]` is set on the destination.
2. After `order.deadline`, the user (unaware of the fill, or racing it) calls `cancelOrder` → `_cancelFromSource`, paying `options.relayerFee` and dispatching a `DispatchGet` with `timeout: 0`.
3. A relayer submits the storage proof; `onGetResponse` decodes a non-empty `_filled` slot value and reverts with `Filled()`.
4. `EvmHost.dispatchIncoming(GetResponse)` catches the revert, deletes only the response receipt, and returns — the fee under `_requestCommitments[commitment]` is untouched.
5. Because the destination fact (`_filled[commitment]` is non-empty) never changes and `timeout == 0`, no future resubmission of the same message will ever succeed, and `dispatchTimeOut` can never be invoked. `options.relayerFee` remains permanently locked in `EvmHost`, unrecoverable by the user or any relayer.

    /**
     * @dev Handles the response to a Hyperbridge GET request dispatched during
     * `_cancelFromSource`. Verifies that the `_filled` storage slot on the destination
     * chain is empty (meaning the order was never filled), then refunds the escrowed
     * tokens to the original user. Reverts with `Filled` if the slot is non-empty.
     *
     * @param incoming The incoming GET response from Hyperbridge containing the storage proof.
     */
    function onGetResponse(IncomingGetResponse calldata incoming) external override onlyHost {
        _checkRelayer(incoming.relayer);
        if (incoming.response.values[0].value.length != 0) revert Filled();

        WithdrawalRequest memory body = abi.decode(incoming.response.request.context, (WithdrawalRequest));
        _withdraw(body, true, true);
    }

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }
