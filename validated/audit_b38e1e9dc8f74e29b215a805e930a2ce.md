Audit Report

## Title
Unprivileged "View" role can read outgoing secret tokens for External Initiators via `GET /v2/external_initiators` - (File: core/web/external_initiators_controller.go)

## Summary
The `/v2/external_initiators` list endpoint is registered without any elevated-role middleware (only the base session/token authentication check), while the sibling `Create` and `Destroy` routes are gated with `auth.RequiresEditRole`. The `Index` handler returns each External Initiator's `OutgoingToken` field in plaintext via `presenters.ExternalInitiatorResource`, exposing a secret used by the node to authenticate outbound webhook calls to any authenticated user, including those with the lowest-privilege `UserRoleView` role.

## Finding Description
In `core/web/router.go`, the route table shows the asymmetry directly: `authv2.GET("/external_initiators", paginatedRequest(eia.Index))` has no role wrapper, whereas `POST` and `DELETE` on the same resource are wrapped in `auth.RequiresEditRole` [1](#0-0) . The `Index` handler in `core/web/external_initiators_controller.go` fetches all external initiators and converts each into an `ExternalInitiatorResource` via `presenters.NewExternalInitiatorResource` [2](#0-1) . That presenter struct explicitly includes `OutgoingToken` as a non-omitted JSON field and copies it directly from the `bridges.ExternalInitiator` model [3](#0-2) . Unlike `ExternalInitiatorAuthentication` (used only in the one-time `Create` response, which itself also includes secrets but is only shown once and requires `RequiresEditRole` to trigger), the list resource discloses the same secret repeatedly to anyone who can call the unauthenticated-role-gated `GET` route. This is a genuine broken access control: the read path lacks the role gate that protects the write path, and the presenter leaks a live credential rather than redacting it.

## Impact Explanation
`OutgoingToken` is the credential the Chainlink node uses to authenticate itself when POSTing job-run trigger requests to the configured External Initiator's endpoint. A `UserRoleView` account — the lowest privilege tier, intended only for read-only dashboard access — can retrieve this token and use it to impersonate the node's outbound calls to the initiator's service or replay/forge requests that the initiator would trust as coming from the legitimate Chainlink node. This is a concrete secret disclosure / request impersonation vulnerability that crosses an RBAC privilege boundary, matching an in-scope Chainlink impact category (key/secret exfiltration enabling request impersonation).

## Likelihood Explanation
Exploitation only requires a valid `UserRoleView` session or API token — a normal, supported low-privilege account — and a single authenticated `GET /v2/external_initiators` request. No admin/edit privileges, host access, or unusual configuration is needed beyond having at least one External Initiator configured, which is a standard node feature. The `auth_test.go` table explicitly marks this route `viewOnlyAllowed: true`, confirming this is the tested/expected (but incorrect) authorization behavior rather than a hypothetical edge case [4](#0-3) , and `external_initiators_controller_test.go` demonstrates the response body contains `OutgoingToken` for listed initiators [5](#0-4) .

## Recommendation
Gate `GET /v2/external_initiators` behind at least `auth.RequiresEditRole` (matching `Create`/`Destroy`), or redact `OutgoingToken`/`OutgoingSecret` from `ExternalInitiatorResource` so the secret is only ever returned once, at creation time, via `ExternalInitiatorAuthentication`.

## Proof of Concept
1. As an admin, create an External Initiator: `POST /v2/external_initiators {"name":"foo","url":"http://example.com"}`; note the returned one-time `outgoingToken`.
2. Create/authenticate as a `UserRoleView` user and obtain a session cookie or API token.
3. Call `GET /v2/external_initiators` as that View-role user.
4. Observe the response includes `outgoingToken` in the `externalInitiators` list, as verified by the assertions in `core/web/external_initiators_controller_test.go` (lines 104-126), confirming a low-privileged user can read a secret intended to be scoped to Edit/Admin operators.
