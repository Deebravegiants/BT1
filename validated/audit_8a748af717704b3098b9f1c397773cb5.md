### Title
Missing "blocking domain" fallback for detached NFT ownership: an account whose position-NFT `Owner` entry lapses becomes unliquidatable and unclosable, freezing collateral and blocking bad-debt cleanup — ([File: contracts/controller/src/storage/account.rs])

### Summary
CVE-2024-53232 fixed a crash in `iommu/s390` where a surprise-removed device left a NULL domain pointer because the code had no safe "blocking domain" to attach during teardown. The XOXNO Lending controller has the same structural flaw: account teardown verbs (liquidation, bad-debt cleanup, repay) resolve the account owner by a live cross-contract `owner_of` read on the position NFT, and when that read cannot resolve — a burned or TTL-evicted `Owner(token_id)` entry — every verb fails with `AccountNotFound` instead of falling back to a safe teardown mode. The debt and collateral legs remain fully intact in controller storage while the ownership leg is gone, exactly mirroring the kernel's NULL-domain-on-detach.

### Finding Description
`try_account_owner` resolves ownership via `nft_try_owner_of_call`, which returns `None` for a missing token, an out-of-range id, or any failed `owner_of` invocation — including a persistent `Owner` entry that has been evicted on TTL expiry (`contracts/controller/src/external/position_nft.rs:19-25`). `get_account` and `get_account_borrow_only` convert that `None` into `panic_with_error!(AccountNotFound)` (`contracts/controller/src/storage/account.rs:35-44, 146-172`).

Two asymmetries make the detached state reachable by an unprivileged address:

1. NFT `burn` is controller-only, so a user cannot detach directly — but the `Owner`/`Balance` entries are persistent user-TTL entries. Controller-side account keys (`AccountMeta`, `SupplyPositions`, `BorrowPositions`) are renewed on *every read/write* (`get_user`/`set_user` renew user TTL, `account.rs:1-2`), and `renew_user_account` explicitly "does not renew the NFT" (`account.rs:258-259`). The NFT `Owner` entry is only lifted to the 120-day user window at mint and at `renew_account`/`nft_renew_call`; the stock OZ `owner_of` read renews it for only ~30 days (`contracts/position-nft/src/contract.rs:103-104` comment). Any controller interaction that reads account metadata without crossing into `owner_of` renews the debt/collateral legs while letting the ownership leg expire — after which the `Owner` entry is evicted and `try_owner_of` fails permanently.
2. There is no fallback. Every teardown path routes through `get_account`/`account_owner`: `process_liquidation` (`positions/liquidation/mod.rs`), `socialize_bad_debt` behind `clean_bad_debt`/`force_socialize_bad_debt`, and `get_account_borrow_only` used on the borrow-side verbs. The in-repo test `partial_liquidation_resolves_nft_ownership` (`tests/test-harness/tests/controller/position_nft_ttl_and_ownership_reads.rs:281-308`) proves the failure mode directly: with the `Owner` leg burned and "every controller-side account entry intact," a partial liquidation reverts `AccountNotFound`, and the neighboring test notes `clean_bad_debt`/`force_socialize_bad_debt` fail identically on the same owner read.

### Impact Explanation
Once the `Owner` entry is gone while debt is live, the account is a zombie: liquidators cannot seize collateral (`liquidate` reverts), debt-reducing `repay` reverts on `account_owner`, and `clean_bad_debt`/`recapitalize`-adjacent socialization reverts — permanently. An underwater borrower can let (or arrange, via metadata-renewing calls that skip `owner_of`) the NFT leg lapse, making their position unliquidatable and unclosable while the liability stays on the books. That is permanent freezing of the collateral and protocol insolvency via unremovable bad debt — the same "crash on teardown with no blocking domain" outcome as the CVE.

### Likelihood Explanation
Triggering requires no privilege, no leaked key, and no admin action — only the passage of ledger time arranged so that user-TTL renewals hit the controller-side keys while the NFT `Owner` entry misses its renewal window. The renewal asymmetry is structural and documented in the code (`renew_user_account` skips the NFT; OZ `owner_of` bumps only 30 days). It is not a single-transaction attack and depends on the renewal gap being achievable through permissionless entrypoints, which lowers likelihood relative to a direct call — but the vulnerable state, once reached, is irreversible because `renew` itself panics on a missing token (`contract.rs:107-115`) and no verb can run to repair it.

### Recommendation
Attach a "blocking domain" equivalent: when `try_account_owner` fails but `AccountMeta` and position maps still exist, teardown verbs should fall back to a stored/last-known owner or an ownerless-liquidation mode that permits `liquidate`, `repay`, and `clean_bad_debt` to proceed against the stored positions while blocking owner-gated verbs (`withdraw`, `borrow`, `add_delegate`). Concretely: persist `last_owner` in `AccountMeta` at mutation time, have `get_account_borrow_only`/`process_liquidation`/`socialize_bad_debt` use it when `owner_of` fails, and align TTL renewal so `renew_user_account` also bumps the NFT `Owner`/`Balance` entries (or renews via `nft_renew_call`) on every account touch.

### Proof of Concept
1. Alice supplies collateral and borrows in `standard_two_asset`; account `id` is minted as position-NFT token `id` (`nft_mint_call`).
2. Alice becomes liquidatable (`set_price` drop), confirmed by `assert_liquidatable`.
3. The `Owner(id)` entry is detached while all controller entries remain live — demonstrated in the repo's own harness by `PositionNftClient::burn(token_id)` with `account_exists(id) == true` (`position_nft_ttl_and_ownership_reads.rs:297-303`); in production the same state arises from TTL eviction of `Owner(id)` while `AccountMeta`/`BorrowPositions` are kept renewed by any metadata-touching call, since `renew_user_account` skips the NFT.
4. `liquidate(liquidator, id, debt_asset, amount)` reverts `AccountNotFound` at `storage::get_account`; `clean_bad_debt(id)` reverts the same way inside `socialize_bad_debt`; `repay` reverts at `account_owner` in `get_account_borrow_only`.
5. Result: debt and collateral are permanently locked, the bad debt can never be socialized, and the protocol absorbs the shortfall — with no fallback path equivalent to the kernel's blocking domain.
