### Title
Permanent market freeze via debt-value `i128` overflow in interest accrual - ([File: common/src/rates/scaling.rs](common/src/rates/scaling.rs))

### Summary
The CVE class is a crash triggered by attacker-controlled input reaching an unchecked operation. The XOXNO Lending analog: every mutating pool verb runs `interest::global_sync`, which calls `accrue_step`, which calls `scaled_to_original` (`borrowed.mul(env, borrow_index)`) via `calculate_supplier_rewards` in `common/src/rates/index.rs:80-81`. `Ray::mul` is `mul_div_half_up` with `panic_with_error!(GenericError::MathOverflow)` on non-representable results (`common/src/math/fp_core.rs:108-118`). Once `borrowed * borrow_index` exceeds `i128::MAX`, the panic fires **before** the `MAX_BORROW_INDEX_RAY` cap in `update_borrow_index` (`common/src/rates/index.rs:13-19`) can engage, and it fires on every subsequent call — permanently freezing that (hub, token) market's repayments, withdrawals, liquidations, and `recapitalize`.

### Finding Description
- `Cache::calculate_utilization` and `accrue_step` unscale `borrowed` and `supplied` by their indexes using `scaled_to_original` (`contracts/pool/src/cache/scale.rs:19-27`, `common/src/rates/scaling.rs:14-16`), which calls `Ray::mul` → `mul_div_half_up` → `panic_with_error!(GenericError::MathOverflow)` when `x * y / d` does not fit `i128`.
- `interest::global_sync` (`contracts/pool/src/interest.rs:20-33`) runs at the top of every verb, so the panic traps every entrypoint touching the market: `withdraw`, `repay`, `liquidate`/`seize`, `borrow`, `supply` (`require_backed_market` also values the book), `claim_revenue`, `recapitalize`, and the permissionless `update_indexes`.
- Entry is unprivileged: an attacker supplies a large amount (`supply`) and borrows at high utilization (`borrow`), or simply waits/calls `update_indexes` on an already-large market at a steep rate curve. No governance, upgrade, or key compromise is needed — only tokens, which can be obtained via `flash_loan` for the initial position seeding.
- The caps fail open or don't help: `calculate_scaled_cap` saturates at `i128::MAX` (`common/src/rates/scaling.rs:26-33`), and `protocol_fee_shares` only caps *share* headroom (`index.rs:94-99`) — neither bounds `borrowed * borrow_index`.

### Impact Explanation
Permanent freezing of funds / partial protocol insolvency: all supplier principal in that market becomes unwithdrawable, all borrower debt unrepayable, and liquidation impossible, because the accrual panic precedes every state transition. Existing test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` (`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:316-361`) demonstrates exactly this: after enough index growth, `try_update_indexes`, `try_withdraw`, and `try_repay` all revert with `MATH_OVERFLOW` while `borrow_index < MAX_BORROW_INDEX_RAY`.

### Likelihood Explanation
Requires a very large book (`borrowed` approaching `i128::MAX / borrow_index`) — feasible only on high-decimal, high-cap markets with a steep rate curve sustained at high utilization for years, or after caps are lifted. Docs acknowledge the residual risk (INV-IDX-01, threat-model Tamper.6), which lowers novelty but does not remove the impact; the freeze is deterministic once the value ceiling is crossed and no recovery path exists.

### Recommendation
Saturate rather than panic in accrual-critical valuation: make `calculate_supplier_rewards` and utilization use `mul_div_floor_saturating`/a `try_` variant, treat `borrowed_value` overflow as "at ceiling" (clamp borrow index to `MAX_BORROW_INDEX_RAY` and stop accruing), so exits remain callable. Alternatively gate `supply`/`borrow` so `borrowed` and `supplied` scaled shares stay below `i128::MAX / MAX_*_INDEX_RAY` at entry, which makes the overflow unreachable rather than merely unlikely.

```rust
pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    // The zero check runs first so debug and release builds agree on a zero
    // divisor: both surface `DivisionByZero` rather than tripping the assert.
    require_nonzero_divisor(env, d);
    debug_assert!(
        x >= 0 && y >= 0 && d > 0,
        "mul_div_half_up: non-negative x, y and positive d"
    );
    try_mul_div_half_up(env, x, y, d)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
}
```

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

```rust
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
}
```

```markdown
### INV-IDX-01 — Borrow index is monotone and bounded

Both indexes start at one RAY. Successful accrual with validated rate parameters
```
