### Title
AllowListBasedAuth authorizes any client who replays a publicly-known request digest, without proving they are the actual workflow owner - ([File: core/capabilities/vault/allow_list_based_auth.go])

### Summary
The Vault capability's `AllowListBasedAuth.AuthorizeRequest` grants authorization based solely on whether a request's content-derived digest matches an entry in the on-chain workflow-registry allowlist, with no cryptographic binding to the sender's identity. Because the allowlisted `(Owner, RequestDigest, ExpiryTimestamp)` tuple is public on-chain data, and the digest is deterministically derived from the request body, any unprivileged client that can reconstruct/observe the exact request body can submit it through the gateway and be authorized "as" the allowlisted workflow owner — this is structurally the same "replay of an approved proof without doing the actual privileged work" pattern as the reported specimen-hash replay issue.

### Finding Description
`allowListBasedAuth.AuthorizeRequest` computes `req.Digest()` from the incoming JSON-RPC request and checks it against `workflowRegistrySyncer.GetAllowlistedRequests(ctx)`, an on-chain-sourced list of `(Owner, RequestDigest, ExpiryTimestamp)` entries: [1](#0-0) 
If a match is found and not expired, the function returns an `AuthResult` asserting `workflowOwner: allowlistedRequest.Owner.Hex()` — i.e., it treats the caller as that owner: [2](#0-1) 

This is a pure "did anyone previously approve/allowlist this exact payload" check — it never verifies that the request actually originates from, or is signed by, the owner it attributes the request to. The only guard against reuse is `RequestReplayGuard.CheckAndRecord`, which just tracks whether a digest was seen once and rejects a second use, again purely by digest — no sender identity is checked there either: [3](#0-2) [4](#0-3) 

This path is reachable from the internet-facing Gateway, which is an unprivileged-client-facing entry point: `HandleJSONRPCUserMessage`/`newActiveRequest` in `core/services/gateway/handlers/vault/handler.go` accepts external JSON-RPC requests and forwards them to the DON nodes, which run this same `AllowListBasedAuth`/`Authorizer` logic: [5](#0-4) 

Because the allowlisted digest, owner, and expiry are all readable from the public workflow-registry contract, and the request body needed to reproduce the matching digest is either public (workflow-registration data) or easily observed once submitted once (e.g., from gateway logs, network traces, or the first legitimate submission attempt), a different, unprivileged actor can submit the *exact same* request bytes to the gateway before the legitimate owner does (or after, if the replay guard has expired/rolled over), and the Authorizer will accept it and treat it as coming from the allowlisted `workflowOwner`. This is the same weakness class as the reported bug: possession of previously-observed "proof" data (there: a specimen hash; here: an allowlisted request digest + reproducible request body) is treated as equivalent to actually being the authorized party, with no signature or session binding tying the request to a specific caller.

Note: `validateSecretOwnersMatchAuthorized` in `authorizer.go` only checks that secret owner fields inside the payload match the `AuthorizedOwner()` returned by the (already-forged) `AuthResult` — since the attacker submits the identical payload that was allowlisted for that owner, this check trivially passes: [6](#0-5) 

### Impact Explanation
An attacker who is not the legitimate workflow owner (and holds no signing key or session credential for that owner) can get Vault secret operations (`SecretsCreate`, `SecretsUpdate`, `SecretsDelete`, `SecretsList`) attributed to and authorized as another workflow owner, purely by submitting an already-approved request body ahead of or in place of the legitimate submitter. This is a cross-user authorization/impersonation issue on a security-sensitive, internet-facing secrets-management path.

### Likelihood Explanation
Requires the attacker to know the exact request bytes that hash to an allowlisted digest. In practice this is plausible: workflow allowlisting metadata (owner, expiry, and often the associated request template) is publicly visible on-chain via the workflow registry, and the Gateway is an internet-facing, unauthenticated (from a transport standpoint) JSON-RPC endpoint that will forward whatever request it receives to nodes for evaluation — so any party racing to submit the same bytes first (or exploiting an expired/cleared replay-guard entry across node restarts, since the guard is in-memory only) can win authorization.

### Recommendation
Bind the allowlist/JWT authorization to sender identity, not just content digest — e.g., require the request to be signed by (or delivered over a session authenticated as) the workflow owner referenced in the allowlist entry, and verify that signature/session in `AuthorizeRequest` in addition to the digest match. Consider making the `RequestReplayGuard` persistent (not purely in-memory per node) so a restart or node failover cannot reopen a replay window, and add sender-binding metadata to the digest computation itself so a digest cannot be replayed by an unrelated caller.

### Proof of Concept
1. Workflow owner `0xAbc` registers a workflow and the workflow-registry allowlists a specific Vault request (owner=`0xAbc`, digest=`D`, expiry=`T`) — this tuple is publicly readable on-chain via `workflowRegistrySyncer.GetAllowlistedRequests`.
2. An unrelated party reconstructs the exact JSON-RPC request body whose `req.Digest()` equals `D` (from public workflow metadata or by observing the first submission attempt over the network).
3. The attacker submits this request to the Gateway's Vault handler (`HandleJSONRPCUserMessage` → `newActiveRequest`) before/instead of the real owner.
4. `allowListBasedAuth.AuthorizeRequest` matches digest `D`, and returns `AuthResult{workflowOwner: "0xAbc", ...}` — the node processes the request (e.g., creates/updates/deletes secrets) as if `0xAbc` authorized it, even though the attacker supplied it. [7](#0-6)

func (r *allowListBasedAuth) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	r.lggr.Debugw("AllowListBasedAuth authorizing request", "method", req.Method, "requestID", req.ID)
	requestDigest, err := req.Digest()
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to create digest", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, err
	}
	requestDigestBytes, err := hex.DecodeString(requestDigest)
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to decode digest", "method", req.Method, "requestID", req.ID, "requestDigest", requestDigest, "error", err)
		return nil, err
	}
	requestDigestBytes32 := [32]byte(requestDigestBytes)
	if r.workflowRegistrySyncer == nil {
		r.lggr.Errorw("AllowListBasedAuth workflowRegistrySyncer is nil", "method", req.Method, "requestID", req.ID)
		return nil, errors.New("internal error: workflowRegistrySyncer is nil")
	}
	allowlistedRequest, allowedRequestsStrs, err := r.findAllowlistedItemWithRetry(ctx, req, requestDigest, requestDigestBytes32)
	if err != nil {
		return nil, err
	}
	if allowlistedRequest == nil {
		r.lggr.Debugw("AllowListBasedAuth request digest not allowlisted",
			"method", req.Method,
			"requestID", req.ID,
			"digestHexStr", requestDigest,
			"allowedRequestsStrs", allowedRequestsStrs)
		return nil, errors.New("request not allowlisted")
	}

	if time.Now().UTC().Unix() > int64(allowlistedRequest.ExpiryTimestamp) {
		authorizedRequestStr := string(allowlistedRequest.RequestDigest[:])
		r.lggr.Debugw("AllowListBasedAuth authorization expired", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", authorizedRequestStr, "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
		return nil, errors.New("request authorization expired")
	}

	digestKey := string(allowlistedRequest.RequestDigest[:])
	r.lggr.Debugw("AllowListBasedAuth authorization succeeded", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", digestKey, "owner", allowlistedRequest.Owner.Hex(), "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
	return &AuthResult{
		workflowOwner: allowlistedRequest.Owner.Hex(),
		digest:        digestKey,
		expiresAt:     int64(allowlistedRequest.ExpiryTimestamp),
	}, nil
}

func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}

func (a *authorizer) authorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	// Requests without req.Auth continue using the allowlist-based path for backwards compatibility.
	// Existing clients do not populate the auth field yet, so treating an empty value as JWT would break them.
	if req.Auth == "" {
		return a.authorizeAllowListBasedAuth(ctx, req)
	}
	return a.authorizeJWTBasedAuth(ctx, req)
}

// validateSecretOwnersMatchAuthorized checks that secret identifiers in the request payload
// match the authorized workflow owner. This is read-only validation; owner prefixing and
// param stamping happen later in GatewayVaultRequestProcessor.
func validateSecretOwnersMatchAuthorized(req jsonrpc.Request[json.RawMessage], workflowOwner string) error {
	switch req.Method {
	case vaulttypes.MethodPublicKeyGet:
		return nil
	case vaulttypes.MethodSecretsCreate:
		if req.Params == nil {
			return errors.New("request params must not be nil")
		}
		var createReq vaultcommon.CreateSecretsRequest
		if err := json.Unmarshal(*req.Params, &createReq); err != nil {
			return err
		}
		return validateEncryptedSecretOwnerMismatch(createReq.EncryptedSecrets, workflowOwner)

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}
