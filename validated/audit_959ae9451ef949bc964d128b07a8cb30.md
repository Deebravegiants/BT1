### Title
Simplex Uniswap V4 venue pricing derives fill rates from a manipulable spot pool price with no TWAP or price-impact protection - ([File: sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts])

### Summary
The Synapse Protocol incident (Nov 2021) resulted from a bridge component pricing an asset from a virtual/spot AMM value that an attacker could manipulate within a single transaction, letting the attacker extract value from the pool's liquidity providers before the manipulation reverted. Hyperbridge's Simplex solver client contains an analogous pattern: when a curveless cross-asset pair is configured for "venue pricing," the fill rate used to price and execute an intent order is read directly from a Uniswap V4 pool's current spot price (`sqrtPriceX96`), with no TWAP, no execution-size/impact term, and only an optional static-reference deviation guard as protection. This lets an order placer manipulate the referenced pool and profit at the expense of the filling solver's escrowed/LP-backed inventory.

### Finding Description
`UniswapV4FundingPlanner.getExoticTokenPrice` picks the most-liquid position for a token and calls `computeDirectPoolPriceUsd`, which reads the raw pool mid derived from the pool's current `sqrtPriceX96`/tick via `sdkPool.token0Price`/`token1Price`: [1](#0-0) 

This spot price is consumed by `FXFiller.resolveLegRates` as the fill rate for the whole leg, and by `referenceRate` for confirmation-depth sizing, whenever a pair has no static bid/ask curves and its `token0` is a USD stablecoin: [2](#0-1) 

The only defense is `checkPriceGuard`, which is optional (a pair can be configured with no guard at all) and only checks static deviation from a fixed `referencePrice`, not execution cost or size impact: [3](#0-2) 

This exact gap is already documented internally: the pool's fee tier is read but never applied to the quoted price, `computeLegPolicyOutput` extends the raw mid linearly across the full order size with no impact term, and the guard only bounds deviation from a static reference rather than bounding manipulation cost or execution slippage: [4](#0-3) 

The root cause mirrors Synapse's bug class: a bridge/solver-side settlement path prices an asset directly off a live, cheaply-manipulable AMM state (spot price/virtual price) rather than a manipulation-resistant oracle (TWAP, or a price bounded by trade size and depth), and the only sanity check is a coarse static band that can be configured loosely, omitted entirely, or bypassed by staying inside the tolerated deviation while still moving the price enough to profit given the pool's actual (thin) depth.

### Impact Explanation
An attacker who places (or arranges to have filled) an order against a venue-priced pair can cheaply move the referenced Uniswap V4 pool's spot price with a same-block swap, then have Simplex price and fill the order against the manipulated spot rate. Because the withdrawal from the solver's LP position (`planWithdrawalForToken`) is sized off the same manipulated mid price, the attacker extracts value directly from the solver's Uniswap V4-backed inventory — the same asymmetry that let the Synapse attacker take from Avalanche LPs via a manipulated nUSD virtual price. Unlike curve-priced pairs, this path has no bid/ask spread of its own and no execution-cost accounting, so the guard band is the sole limiting factor, and that guard is optional per configuration.

### Likelihood Explanation
Reachable by any unprivileged order placer/intent user targeting a venue-priced pair backed by a thin Uniswap V4 pool: no special privilege, governance access, or insider position is required — only placing an order sized to be filled while the pool is in a manipulated state. The public filler config documentation explicitly warns that "Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote," confirming this is a known, exploitable configuration surface rather than a purely theoretical one: [5](#0-4) 

### Recommendation
- Require the price guard (`referencePrice` + `maxDeviationBps`) to be mandatory, not optional, for any venue-priced pair.
- Replace or supplement the raw spot price with a manipulation-resistant source (TWAP over multiple blocks, or a multi-block sanity check) before using it to price a fill or size an LP withdrawal.
- Incorporate the pool's actual fee tier and a size/impact term (e.g., quote via the pool's swap-simulation rather than the static mid) so quoted prices reflect the true cost of sourcing the exact amount needed, not merely the instantaneous mid.
- Cap the maximum single-order/withdrawal notional a venue-priced pair will fill relative to the pool's actual on-chain depth, independent of the deviation guard.

### Proof of Concept
1. Configure/observe a Simplex solver with a venue-priced pair (e.g., `USDC/CNGN` with `[vault.uniswapV4]` positions) and a thin-liquidity Uniswap V4 pool, either with no `referencePrice`/`maxDeviationBps` guard configured, or with a loose guard.
2. Attacker performs a swap against the referenced pool in the same block to move `sqrtPriceX96` favorably (e.g., understating CNGN's USD value) while remaining within any configured deviation band.
3. Attacker (or an accomplice) submits an `IntentGatewayV2` order on the venue-priced pair sized to be filled by the target solver.
4. `FXFiller.resolveLegRates` → `getVenueUsdPrice` → `UniswapV4FundingPlanner.getExoticTokenPrice` → `computeDirectPoolPriceUsd` reads the manipulated spot price and returns it as the fill rate; `checkPriceGuard` passes because the manipulated price is within the tolerated band (or no guard exists) — see [6](#0-5) .
5. The solver fills the order and withdraws LP inventory via `planWithdrawalForToken`, crediting the attacker's beneficiary at the manipulated (unfavorable-to-solver) rate, extracting value from the solver's Uniswap V4 position — see [7](#0-6) .

```typescript
	private computeDirectPoolPriceUsd(
		pos: HydratedV4Position,
		sdkPool: V4Pool,
		chain: string,
	): { exoticToken: string; priceUsd: Decimal } | null {
		const usdc = this.configService.getUsdcAsset(chain).toLowerCase()
		const usdt = this.configService.getUsdtAsset(chain).toLowerCase()
		const c0 = pos.currency0.toLowerCase()
		const c1 = pos.currency1.toLowerCase()

		if (c0 === usdc || c0 === usdt) {
			// currency0 is stable → exotic is currency1
			// token1Price = "token0 per token1" = USD per exotic
			return {
				exoticToken: c1,
				priceUsd: new Decimal(sdkPool.token1Price.toFixed(18)),
			}
		}

		if (c1 === usdc || c1 === usdt) {
			// currency1 is stable → exotic is currency0
			// token0Price = "token1 per token0" = USD per exotic
			return {
				exoticToken: c0,
				priceUsd: new Decimal(sdkPool.token0Price.toFixed(18)),
			}
		}

		return null
	}
```

```typescript
	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {
			this.logger.warn(
				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
	}
```

```text
## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.
```
