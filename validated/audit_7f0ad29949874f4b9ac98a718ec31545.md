### Title
Protocol fee is minted on accrued (unpaid) interest that is later socialized as bad debt, letting the DAO treasury keep fee shares that dilute LPs who absorb the resulting loss - (File: `mainnet/contracts/vault/v0-vault-usdc.clar` and equivalent vault contracts)

### Summary
`accrue()` mints protocol-fee vault shares (`treasury-lp`) to `.dao-treasury` based on the *accrued* growth of the debt index (`debt-delta`), i.e. interest that has merely been recognized in the borrower's outstanding debt, not interest actually repaid in underlying assets. When a loan later becomes uncollectible and `socialize-debt` is called to write down the loss, the write-down only reduces `lindex`/`assets` for existing LP shares — it never claws back the `treasury-lp` shares that were already minted for that same never-collected interest. This is the same value-identity break as the referenced Astaria report: protocol fee is charged on "interest" as it is virtually recognized over time, not when it is actually paid, so LPs can pay (via dilution/loss-socialization) for interest the protocol already took a cut of but that was never truly received.

### Finding Description
In `accrue()`, on every state-changing call (deposit, redeem, borrow, repay, etc.) the vault computes: [1](#0-0) 

`debt-delta` is the increase in `total-debt` (`principal-scaled` compounded by the `index`), which increases purely as a function of elapsed time and the interest-rate curve — regardless of whether the borrower has made any actual repayment: [2](#0-1) 

`reserve-inc` (the protocol's cut of `debt-delta`) is immediately minted as `zft` shares to `.dao-treasury`: [3](#0-2) 

`total-assets` itself already counts this uncollected interest as if it were real backing: [4](#0-3) 

If the borrower defaults (or the position is liquidated below par) before actually repaying that accrued interest, `socialize-debt` is invoked to write off the shortfall. It reduces `lindex` (haircutting every LP's share value) and reduces `assets`/`total-borrowed`, but it contains no logic to burn or otherwise recover the `treasury-lp` shares that were minted earlier for that exact unrealized interest: [5](#0-4) 

There is no counterpart burn of `dao-treasury`'s shares anywhere in the contract — the only fee-related transfer besides `accrue`'s mint is the unrelated flashloan fee `send-underlying`: [6](#0-5) 

The broken identity: `fees minted to treasury` should equal `protocol_fee_rate × interest_actually_collected`, but the contract instead mints `fees minted to treasury = protocol_fee_rate × interest_accrued_in_debt_ledger`, with no reversal path when `interest_accrued_in_debt_ledger > interest_actually_collected` (i.e., on default/socialize-debt). The gap is permanently borne by LP shareholders via the `lindex` haircut in `socialize-debt`, while `dao-treasury` keeps shares it was never entitled to. This is identical in structure to the reported Astaria `_handleStrategistInterestReward` issue (fee minted from time-accrued interest, not from interest actually paid), just implemented via an Aave-style scaled-debt index instead of a slope/`yIntercept` model, and it is present identically across `v0-vault-sbtc.clar`, `v0-vault-ststx.clar`, `v0-vault-ststxbtc.clar`, `v0-vault-stx.clar`, `v0-vault-usdc.clar`, and `v0-vault-usdh.clar`.

### Impact Explanation
This causes theft of unclaimed yield / permanent freezing of funds for regular LPs: the DAO treasury permanently retains fee shares corresponding to interest that other LPs never actually received (since that interest was written off in `socialize-debt`). Depositors present at the time of default effectively pay the protocol fee twice — once through the `treasury-lp` mint that priced in the (subsequently unrealized) interest, and again through the `lindex` write-down that socializes the shortfall across all remaining LPs, while the treasury's cut is not correspondingly reduced.

### Likelihood Explanation
This triggers under ordinary, expected protocol conditions — any borrower default or under-collateralized liquidation that requires `socialize-debt` to be invoked will exhibit this behavior. No privileged/malicious action, oracle manipulation, or governance compromise is required; it is a systemic accounting gap that manifests whenever bad debt occurs, which is a normal risk event for a lending protocol.

### Recommendation
Track `treasury-lp` shares minted per outstanding loan (or maintain a running "unrealized fee shares" ledger) and burn/claw back the proportional `treasury-lp` shares from `.dao-treasury` inside `socialize-debt` whenever the corresponding debt is written off, so that the treasury's fee shares only reflect interest that has actually been repaid. Alternatively, defer minting `treasury-lp` until `system-repay` actually receives the interest portion (`interest-paid`), computing the fee off realized `interest-paid` rather than off the projected `debt-delta` in `accrue()`.

### Proof of Concept
1. Borrower opens a loan via `system-borrow`; time passes and `accrue()` is repeatedly invoked (e.g., via deposits/redeems from other users), each time minting `treasury-lp` shares to `.dao-treasury` proportional to `debt-delta` — see `accrue()` at lines 833-861 of `v0-vault-usdc.clar`.
2. Borrower's collateral value drops and the position is never repaid; the position is deemed a loss and `socialize-debt` is called with `scaled-amount` equal to the unpaid scaled principal (including the previously-accrued-but-unpaid interest baked into `total-debt`).
3. `socialize-debt` reduces `lindex` for all LP token holders (line 954-961) and reduces `assets`/`total-borrowed`, but performs no burn on the `zft` balance held by `.dao-treasury`.
4. Net result: `.dao-treasury`'s `zft` balance (minted in step 1) remains untouched and redeemable for real underlying assets, while all other LPs' redeemable value has been reduced by the full write-off amount including the portion that funded the treasury's mint — the treasury profits from interest that was never actually collected from the borrower.

(define-public (socialize-debt (scaled-amount uint))
  (let ((scaled-principal (var-get principal-scaled))
        (borrowed (var-get total-borrowed))
        (idx (var-get index))
        (current-assets (var-get assets))
        (current-lindex (var-get lindex))
        (old-total-assets (total-assets))
        (debt-reduction (mul-div-down scaled-amount idx INDEX-PRECISION))
        (principal-reduction (if (> scaled-principal u0)
                                (mul-div-down scaled-amount borrowed scaled-principal)
                                u0))
        ;; Write down lindex proportionally to loss in total-assets
        (new-lindex (if (and (> old-total-assets u0) (> old-total-assets debt-reduction))
                       (mul-div-down current-lindex (- old-total-assets debt-reduction) old-total-assets)
                       u0)))

    (try! (check-caller-auth))
    (asserts! (> scaled-amount u0) ERR-AMOUNT-ZERO)

    (var-set lindex new-lindex)
    (var-set principal-scaled (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0))
    (var-set total-borrowed (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0))
    (var-set assets (if (> current-assets principal-reduction) (- current-assets principal-reduction) u0))

    (print {
      action: "socialize-debt",
      caller: contract-caller,
      data: {
        scaled-amount: scaled-amount,
        debt-reduction: debt-reduction,
        principal-reduction: principal-reduction,
        old-lindex: current-lindex,
        new-lindex: new-lindex,
        old-total-assets: old-total-assets,
        principal-scaled: (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0),
        total-borrowed: (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0),
        index: idx
      }
    })

    (ok true)))
