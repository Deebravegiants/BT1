Audit Report

## Title
Missing Function Level Access Control in `BridgeTypesController.Show` Exposes Bridge `OutgoingToken` Secret to Any Authenticated User - ([File: core/web/bridge_types_controller.go])

## Summary
`GET /v2/bridge_types/:BridgeName` and `GET /v2/bridge_types` are registered without any role-based authorization wrapper, while `POST`, `PATCH`, and `DELETE` on the same resource are wrapped in `auth.RequiresEditRole` [1](#0-0) . Because `authv2` only applies session/token authentication (not role checks), any authenticated user regardless of role — including the lowest `view` role — can call `Show` and receive the bridge's `OutgoingToken` in the response body.

## Finding Description
`BridgeTypesController.Show` fetches the bridge and serializes it via `presenters.NewBridgeResource` with no additional privilege check beyond the generic authentication middleware [2](#0-1) . `BridgeResource` includes `OutgoingToken` unconditionally (unlike `IncomingToken`, which is only populated on creation) [3](#0-2) . The route table confirms the asymmetry: `Create`, `Update`, `Destroy` are wrapped with `auth.RequiresEditRole`, but `Index` and `Show` are not [1](#0-0) . Reviewing `auth.RequiresEditRole` shows it explicitly rejects `UserRoleView` and `UserRoleRun`, confirming that without this wrapper, `view`-role sessions pass straight through to the handler [4](#0-3) . The existing RBAC test matrix in `core/web/auth/auth_test.go` explicitly documents `GET /v2/bridge_types/MOCK` as `viewOnlyAllowed: true`, confirming this is the intended (not accidental) access policy for the route, yet the response body still leaks `OutgoingToken`, a secret intended to be write/admin-scoped based on the sibling-route protection pattern.

## Impact Explanation
Any authenticated user holding only the `view` role (the lowest privilege tier, intended for read-only access) can retrieve any bridge's `OutgoingToken` via a single GET request. This token is the credential Chainlink uses to authenticate outbound calls to the configured External Adapter; its disclosure to an unprivileged principal allows impersonation of the node in bridge callback flows and potential corruption of pipeline run results — mapping to the in-scope "key/secret exfiltration" and "cross-user response corruption" impact classes.

## Likelihood Explanation
The endpoint is a documented, always-reachable REST route requiring only a valid authenticated session/API token of any role — no admin, edit, or host access is needed. Any deployment provisioning `view`-role accounts (dashboards, auditors, monitoring integrations) alongside bridges with meaningful `OutgoingToken` values is immediately exposed, making this a low-effort, high-repeatability information disclosure.

## Recommendation
Redact `OutgoingToken` from `BridgeResource` for callers below the `edit`/`admin` role (mirroring how `IncomingToken` is only conditionally populated), or wrap `GET /v2/bridge_types` and `GET /v2/bridge_types/:BridgeName` with `auth.RequiresEditRole`/`auth.RequiresAdminRole` consistent with the other bridge-mutating routes, and update `auth_test.go`'s expectations accordingly.

## Proof of Concept
1. Provision a user with `sessions.UserRoleView`.
2. Authenticate as that user via `/sessions` to obtain a session cookie.
3. Send `GET /v2/bridge_types/<bridge-name>` with that cookie.
4. Observe HTTP 200 with a JSON body containing `"outgoingToken": "<secret>"`, despite the requester holding only the `view` role — confirmed against `core/web/bridge_types_controller.go` L125-146 and `core/web/presenters/bridges.go` L10-41, with the routing gap shown at `core/web/router.go` L268-273 and role-check logic at `core/web/auth/auth.go` L217-234.

func (btc *BridgeTypesController) Show(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	bt, err := btc.App.BridgeORM().FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}

// RequiresEditRole extracts the user object from the context, and asserts the user's role is at least
// 'edit'
func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}
