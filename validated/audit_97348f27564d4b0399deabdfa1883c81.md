### Title
Irrevocable biometric custody-package upload occurs before backend enrollment/fraud verdict is finalized - (File: src/plans/mod.rs)

### Summary
`MasterPlan::do_signup` builds and permanently uploads the user's Personal Custody Package (PCP) — containing raw iris codes, normalized iris/face images, and face embeddings — to backend/self-custody storage *before* the backend's authoritative enrollment decision (`signup_post`/`signup_poll`) is known. Just like the VTVL `revokeClaim` bug, where an irreversible action (revocation) is applied without regard to state that has already been legitimately committed by an earlier step (vesting/withdrawal), here an irreversible action (biometric data upload) is committed before the step that determines whether that data should ever have been persisted at all (fraud/duplicate/verification failure). The order of operations therefore determines whether sensitive biometric data ends up permanently retained regardless of the final signup verdict.

### Finding Description
In `do_signup`, the biometric pipeline and on-device fraud check run first: [1](#0-0) 

`detect_fraud` is a local, on-device signal, but the authoritative disposition of the signup (duplicate detection, backend fraud detection, "inflight matches", legacy signup requests) is only established later, in `enroll_user::Plan::run`, via `signup_post`/`signup_poll`: [2](#0-1) 

However, `build_pcp` and the subsequent `upload_pcp_tier_0` / `data_uploader` calls that push the encrypted iris/face/normalized-iris tarballs to the backend's presigned-URL custody storage happen *before* `enroll_user` is ever invoked: [3](#0-2) [4](#0-3) 

The upload itself is a one-way, fire-and-forget HTTP multipart POST with no corresponding deletion/retraction endpoint call anywhere in the plan: [5](#0-4) [6](#0-5) 

Once `enroll_user` later returns `SignupVerificationNotSuccessful` (backend duplicate/fraud/inflight match) or `ServerError`, `after_signup` only records that status for UI/reporting purposes — it never triggers removal of the PCP tiers that were already durably persisted: [7](#0-6) 

This mirrors the VTVL root cause precisely: the "commit" operation (biometric upload / vesting-based withdrawal) and the "final determination" operation (backend enrollment verdict / claim revocation) are not atomic and are not reconciled after the fact — whichever runs first wins, and the losing side's rightful state (here, the user's expectation that a rejected/fraudulent/duplicate signup's biometric data is not retained) is silently discarded.

### Impact Explanation
If the backend later determines the signup is fraudulent, a duplicate, or an "inflight match" (explicitly enumerated as reasons for a completed-but-unsuccessful poll result), the user's raw iris codes, normalized iris images, and face embeddings have already been irrevocably uploaded and stored by the backend/self-custody pipeline. This is a biometric-data retention/disclosure issue: data that should never have been permanently persisted (because the signup was never validly authorized) is retained with no code path to reverse the upload. This directly matches the accepted "biometric data disclosure and retention" impact class, and is a concrete unprivileged-user (any orb operator/user completing a scan) reachable path, not a hypothetical.

### Likelihood Explanation
This triggers on every normal signup flow for pcp_version >= 3 or v2 packages whenever the backend ultimately rejects the enrollment (duplicate, fraud, inflight match, legacy request, or internal pipeline failure classified by the backend as such) — a routine and expected occurrence in production given documented backend rejection reasons in `enroll_user.rs`. No attacker action or malicious operator is required; it is a structural ordering defect in the standard signup pipeline.

### Recommendation
Do not treat the local PCP upload as final until the backend's `signup_post`/`signup_poll` verdict is known. Either:
1. Defer `build_pcp`/`upload_pcp_tier_0`/tier1/tier2 upload until after `enroll_user` confirms `Status::Success`, or
2. If early upload is required for latency/availability reasons, add a compensating deletion/retraction call to the backend custody-storage endpoint that is invoked whenever `enroll_user` ultimately returns anything other than `Success` (mirroring `revokeClaimProper`'s approach of reconciling state based on the final authoritative event rather than operation ordering).

### Proof of Concept
1. Complete a normal signup: biometric capture and pipeline succeed, `detect_fraud` (device-side) returns `false`, so `signup_reason = SignupReason::Normal`.
2. `build_pcp` + `upload_pcp_tier_0` (and tier1/tier2 for pcp_v3) execute and successfully upload the full PCP (iris codes, normalized iris images, face embeddings, thumbnail) to backend storage — see `src/plans/mod.rs:574-637`.
3. `enroll_user` is subsequently invoked; the backend's `signup_poll` responds with `success: false, status: Completed` due to a backend-side duplicate/fraud/inflight-match determination — see `src/plans/enroll_user.rs:157-176`.
4. `after_signup` records `SignupStatus::Fraud`/`ServerFailure` for UI/telemetry purposes only (`src/plans/mod.rs:1463-1498`); no call is made to delete or revoke the already-uploaded PCP tiers.
5. The user's biometric data (iris codes/images, face embeddings) remains permanently stored despite the signup never being validly authorized by the backend.

    async fn after_signup(&mut self, orb: &mut Orb, signup_result: SignupResult) -> Result<()> {
        let SignupResult { capture_start, debug_report, .. } = signup_result;
        if self.skip_pipeline() {
            // This is just to give the UI ring some time to reset.
            sleep(Duration::from_secs(5)).await;
            return Ok(());
        }
        let Some(debug_report) = debug_report else { return Ok(()) };

        tracing::info!("After-signup phase");
        dd_timing!("main.time.signup.full_signup", capture_start);

        let signup_status = debug_report.signup_status.clone();

        let enrollment_status = debug_report.enrollment_status.clone();
        let failure_feedback = debug_report.failure_feedback_after_capture_proto();
        Box::pin(self.upload_debug_report(orb, debug_report)).await?;

        if let Some(signup_status) = signup_status {
            Self::ui_complete_signup(orb, &signup_status, enrollment_status);
        }

        if orb.config.lock().await.self_serve {
            if let Some(relay) = orb.orb_relay.as_mut() {
                relay
                    .send(self_serve::orb::v1::SignupEnded {
                        success: signup_result.success,
                        failure_feedback,
                    })
                    .await
                    .inspect_err(|e| tracing::error!("Relay: Failed to SignupEnded: {e}"))?;
            }
        }

        Ok(())
    }

pub async fn request(
    signup_id: &SignupId,
    session_id: &str,
    checksum: &[u8],
    data: &[u8],
    tier: Option<u8>,
    config: &Arc<Mutex<Config>>,
) -> Result<()> {
    let t0 = Instant::now();
    let presigned_url::Response { url: presigned_url, fields: form_data_params } =
        if let Some(tier) = tier {
            presigned_url::request_tiered_package(
                &DATA_BACKEND_URL,
                signup_id,
                session_id,
                &BASE64.encode(checksum),
                tier,
            )
            .await?
        } else {
            presigned_url::request_package(
                &DATA_BACKEND_URL,
                signup_id,
                session_id,
                &BASE64.encode(checksum),
            )
            .await?
        };
    dd_timing!("main.time.signup.upload_custody_images.presigned", t0);
    tracing::debug!("Images self-custody presigned_url: {presigned_url:?}");
    tracing::debug!("Images self-custody form_data_params: {form_data_params:?}");
    let file = Part::bytes(data.to_vec())
        .file_name("package.tar.gz")
        .mime_str("application/octet-stream")?;
    let form = form_data_params
        .into_iter()
        .flatten()
        .fold(Form::new(), |form, (key, value)| form.text(key, value))
        .part("file", file);
    let Config { backend_http_connect_timeout, backend_http_request_timeout, .. } =
        *config.lock().await;
    let request =
        super::client_with_timeouts(backend_http_connect_timeout, backend_http_request_timeout)?
            .post(presigned_url)
            .multipart(form);
    tracing::debug!("Sending request {request:#?}");
    let t1 = Instant::now();
    let response = request.send().await?;
    dd_timing!("main.time.signup.upload_custody_images.upload", t1);
    tracing::debug!("Received response {response:#?}");
    response.error_for_status()?;
    Ok(())

                &user_id,
                checksum.as_ref(),

                Some(tier),
                &self.config,
            )

                Ok(()) => {

                                    "type:network_error",

                                break;
                            }
                        }
                    }

            }
