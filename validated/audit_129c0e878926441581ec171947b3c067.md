### Title
Cross-signup biometric state bleed via unauthenticated livestream socket - ([File: src/agents/livestream/mod.rs])

### Summary
The livestream `Agent::run` loop only replaces `downstream` on `Event::Connected`, without resetting `gpu.app` or `gpu.clear_textures()`, so an unauthenticated TCP client connecting to the livestream port (9201) after one signup ends and before the next signup's `Input::Clear` arrives can receive rendered frames still containing the previous user's `ir_net_estimate`, `rgb_net_estimate`, `qr_code_points`, and `mirror_points`. This violates the invariant that biometric/derived signals from a scan stay contained to that user's session.

### Finding Description
`Event::Connected(addr)` handling only does `downstream = Some(Arc::new(Downstream::new(addr.ip())?))` [1](#0-0) , with no call to `gpu.clear_textures()` or `gpu.app.clear()`. Those clears only happen on `Input::Clear`, which is sent from `start_signup` at the *beginning* of the next signup [2](#0-1) , not on disconnect/reconnect. Between the end of a signup (or an abort) and the next `start_signup`, `gpu.app` retains whatever was set via `Input::IrNetEstimate`, `Input::RgbNetEstimate`, `Input::QrCode`, `Input::SetMirrorPoint` from the prior pipeline run — these setters simply overwrite fields with no expiry [3](#0-2) . The render loop calls `gpu.render(events, ...)` for any active `downstream` regardless of when it was connected, using the current (stale) `App` state to draw dashboards including IR sharpness/landmark overlays, RGB face bbox/eye landmarks, and QR-code outline [4](#0-3) [5](#0-4) . The TCP listener in `Upstream::new` binds `0.0.0.0:9201` with no authentication, TLS, or peer allow-list — any client that can reach the socket is accepted [6](#0-5) [7](#0-6) . `App::clear()` only runs on `Input::Clear`, which the orchestrator sends once per signup start — it is not tied to connection lifecycle, so a fresh connection accepted mid-gap does not trigger any reset [8](#0-7) [9](#0-8) .

### Impact Explanation
An attacker who can reach TCP port 9201 (same network / same host process boundary — livestream is intended for local/dev debugging, not authenticated remote access) can observe derived biometric signals (IR/RGB landmark positions, sharpness scores, QR-code geometry, mirror aim history) belonging to a *different* user's just-completed or aborted signup, before that state is cleared. This is a biometric-signal disclosure / cross-session data bleed: the exposed data is derived from iris/face capture and is scoped to the previous signup only, not the current viewer's session — a low-to-moderate confidentiality impact (not raw iris codes/images, but session-linked derived pipeline metadata), matching an "unauthorized information disclosure across signup sessions" category.

### Likelihood Explanation
Exploitability requires only network reachability to the (unauthenticated) livestream port and timing a connection in the window between a signup's pipeline output and the next `Input::Clear`. No credentials, MCU access, or operator privileges are needed, and the window is reproducible/deterministic in code (any interval between completion of one signup and the `start_signup` call of the next). Likelihood is moderate: it depends on the deployment exposing/allowing access to this debug port, but the code path itself has no gating logic preventing the observed bleed once connected.

### Recommendation
In the `Event::Connected(addr)` branch of `Agent::run` in `src/agents/livestream/mod.rs`, call `gpu.clear_textures()` and `gpu.app.clear()` (or equivalently send a synthetic `Input::Clear`) before attaching the new `Downstream`, so every new connection starts from a blank state regardless of pipeline timing. Additionally consider adding authentication/access control to the livestream TCP listener in `upstream.rs`.

### Proof of Concept
Integration test plan:
1. Instantiate the `livestream::Agent` thread harness (or drive `Gpu`/`App` directly) and simulate one signup: send `Input::IrNetEstimate(estimate_with_known_sharpness)`, `Input::QrCode(known_points)`.
2. Do not send `Input::Clear` yet.
3. Open a new TCP connection to the `Upstream` listener (simulating `Event::Connected`).
4. Call `gpu.render(...)` and capture the produced buffer / inspect `gpu.app` state.
5. Assert the rendered output / `App` state still exposes the prior `ir_net_estimate.sharpness` value and `qr_code_points` — demonstrating leakage to the new connection.
6. Then send `Input::Clear` and assert the state is now empty, confirming the fix (adding clear-on-connect) removes the leak when applied to step 3.

    fn update_rgb_net_estimate(&self, ui: &mut Ui, rect: Rect) {
        const STROKE: Stroke = Stroke { width: 2.0, color: Color32::YELLOW };

        // Draw the estimated eye landmarks.

        else {
            return;
        };
        let left = Pos2::new(
            rect.min.x + rect.size().x * prediction.landmarks.left_eye.x as f32,
            rect.min.y + rect.size().y * prediction.landmarks.left_eye.y as f32,
        );
        let right = Pos2::new(
            rect.min.x + rect.size().x * prediction.landmarks.right_eye.x as f32,
            rect.min.y + rect.size().y * prediction.landmarks.right_eye.y as f32,
        );
        ui.painter().circle_filled(left, CIRCLE_RADIUS, Color32::RED);
        ui.painter().circle_filled(right, CIRCLE_RADIUS, Color32::GREEN);

        // Draw the bounding box of the face.
        let start = Vec2::new(
            prediction.bbox.coordinates.start_x as f32,

        let max = rect.min + rect.size() * end;
        ui.painter().rect_stroke(Rect::from_min_max(min, max), Rounding::ZERO, STROKE);
    }
