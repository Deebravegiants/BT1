### Title
Relayer fee double-payment via reentrant/cross-path invocation before `_requestCommitments` is finalized in `EvmHost.dispatchIncoming(GetResponse)` - (File: `evm/src/core/EvmHost.sol`)

### Summary
`EvmHost.dispatchIncoming(GetResponse, address)` performs an external, low-level `.call` to an attacker-controlled destination module (`IApp.onGetResponse`) before the request's escrowed fee accounting (`_requestCommitments[commitment]`) is finalized/cleared, mirroring the `executeTrade`/`makeOrder.market` pattern in the referenced report where a callback into an untrusted, user-supplied contract happens mid-function without adequate reentrancy protection.

### Finding Description
`dispatchIncoming(GetResponse)` writes a `_responseReceipts[commitment]` entry, then calls the destination module: [1](#0-0) 

Notice it reads `_requestCommitments[commitment].fee` and pays it out to `relayer` after the external call succeeds, but it never deletes `_requestCommitments[commitment]`. Deletion of that mapping only happens in the timeout paths: [2](#0-1) 

Because `IApp.onGetResponse` is an arbitrary external contract (`_bytesToAddress(response.request.from)`), and `EvmHost`/`HandlerV2` have no reentrancy guard on `dispatchIncoming`/`dispatchTimeOut`/`handleGetRequestTimeouts`, a malicious destination module can, inside its `onGetResponse` callback, synchronously trigger delivery of `HandlerV2.handleGetRequestTimeouts` for the very same `GetRequest` commitment (supplying a non-membership proof against Hyperbridge's own receipt trie, which is independent of the destination EVM host's local `_responseReceipts`). That timeout path reads the still-populated `_requestCommitments[commitment]` and pays out `meta.fee` a second time via `IERC20(feeToken()).safeTransfer(meta.sender, meta.fee)`, this time crediting the timeout-submitter, before finally deleting the entry. The result is that the escrowed relayer fee for a single GET request can be paid out twice (once via the response path, once via the timeout path) because the response path never clears the fee-bearing state before yielding control to an untrusted contract, exactly the class of bug flagged in the report (external call to a user-controlled contract executed before critical state is finalized, with no reentrancy guard).

### Impact Explanation
This allows an attacker who deploys a malicious `IApp` module (or controls a source contract address referenced by `response.request.from`) to drain the host's fee-token balance by collecting the same escrowed fee twice for one request — a direct theft of protocol/relayer funds reachable from a single relayed `GetResponseMessage` proof submission. This qualifies as concrete theft of funds under the acceptance criteria.

### Likelihood Explanation
Exploitation requires: (1) the attacker's own module be the destination of a `GetRequest` (fully attacker-controlled, since anyone can dispatch requests to any `to`/`from` address they own), and (2) the ability to also supply a valid `handleGetRequestTimeouts` non-membership proof for the same request within the same transaction context, which is plausible since GET request timeout is proven independently of destination-chain response delivery and no destination-side lock prevents concurrent processing of both message types for the same commitment. This is a moderately involved but realistic attack path requiring proof-crafting skill, giving it Medium likelihood.

### Recommendation
- Apply checks-effects-interactions in `dispatchIncoming(GetResponse)`: delete/finalize `_requestCommitments[commitment]` (and pay/queue the fee) before making the external `.call` to the destination module.
- Add a reentrancy guard (e.g., OpenZeppelin's `ReentrancyGuard`/`ReentrancyGuardTransient`, already used elsewhere in the codebase such as `IntentGatewayV2`) around `dispatchIncoming`, `dispatchTimeOut`, and the `HandlerV2` entry points that call into these host functions, so a module callback cannot re-enter another handler/dispatch path within the same transaction.

### Proof of Concept
1. Attacker deploys `EvilModule` implementing `IApp` and dispatches a `GetRequest` from it via `EvmHost.dispatch(DispatchGet)`, escrowing `fee` in `_requestCommitments[commitment]`.
2. A relayer submits a valid `GetResponseMessage` via `HandlerV2.handleGetResponses`, which calls `host.dispatchIncoming(response, relayer)`.
3. Inside `EvmHost.dispatchIncoming`, the low-level call to `EvilModule.onGetResponse(...)` executes; `EvilModule`'s implementation synchronously calls back into `HandlerV2.handleGetRequestTimeouts` with a (separately obtainable) non-membership proof for the same commitment.
4. Because `_requestCommitments[commitment]` was not yet deleted, `EvmHost.dispatchTimeOut(GetRequestTimeout, meta, commitment)` pays out `meta.fee` again to the timeout submitter, and only then deletes the entry.
5. Control returns to the outer `dispatchIncoming` call, which pays the fee a second time (or the first payment, depending on ordering) to `relayer` — net result: fee paid twice from one escrow. [3](#0-2)

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
