## Analog Found: Manipulable Uniswap V4 spot price used to price/fund IntentGateway fills, with the anti-manipulation guard optional and off by default

### Title
Solver fills priced off single-block, flash-loan-manipulable Uniswap V4 spot price, guarded only by an optional and disabled-by-default deviation check - ([File: sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts])

### Summary
The XToken exploit worked because minting/pricing logic trusted a manipulable AMM spot price (reached through Kyber → Uniswap V2) that an attacker could move within a single flash-loaned transaction, then transact against the mispriced result. The Simplex solver component of Hyperbridge's Intent Gateway has the same structural weakness: for "curveless" pairs, the fill price is derived directly from a Uniswap V4 pool's current `sqrtPriceX96`/tick — an instantaneous spot read with no TWAP — and the only defense is an optional, static `referencePrice`/`maxDeviationBps` guard that the documentation explicitly says can be, and often is, left unset ("omit both to leave the chain unguarded").

### Finding Description
`UniswapV4FundingPlanner.getExoticTokenPrice` reads live pool state and derives a USD price straight from `sqrtPriceX96` via `computeDirectPoolPriceUsd`, using whichever qualifying position has the most on-chain liquidity: [1](#0-0) . The underlying pool state (`sqrtPriceX96`, `tick`) is fetched fresh via `StateView.getSlot0` right before each pricing/withdrawal decision, with no time-weighting: [2](#0-1) .

That raw pool price feeds directly into the fill rate for curveless pairs in `FXFiller.resolveLegRates`: [3](#0-2) , and also into order-sizing/confirmation depth via `referenceRate`: [4](#0-3) .

The only defense, `checkPriceGuard`, compares the live quote against a **static, operator-supplied** `referencePrice` within `maxDeviationBps`: [5](#0-4) . Both fields are explicitly optional in config validation — a chain with neither is accepted as "unguarded": [6](#0-5) , and the product documentation states this outright: "The two fields must be set together; omit both to leave the chain unguarded," alongside an admission that "Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote": [7](#0-6) .

The engineering team's own internal note confirms there's no execution-cost or size-impact adjustment either — the mid price is applied linearly across the whole quantity, and even the fee tier the solver would actually pay to restock isn't factored in: "computeDirectPoolPriceUsd returns the raw pool mid derived from sqrtPriceX96 ... checkPriceGuard is the only defense on this path, and it checks deviation from a static reference, not execution cost": [8](#0-7) .

### Impact Explanation
An attacker who places (or times) an IntentGateway order against a chain where a solver has no `referencePrice`/`maxDeviationBps` configured — the config-valid default — can flash-loan-manipulate the referenced Uniswap V4 pool's `sqrtPriceX96` in the same block the solver's `refresh()`/pricing read occurs, exactly as in the XToken exploit's Uniswap V2 spot-price manipulation. This directly distorts the rate `resolveLegRates` computes, letting the attacker's order extract exotic-token liquidity from the solver's own Uniswap V4 LP position at a manipulated (favorable-to-attacker) price, i.e. concrete theft of solver funds routed through a Hyperbridge Intent Gateway fill. Even where a guard is configured, it only bounds deviation from a stale, manually-set reference and does nothing about pool depth/impact, so a thin pool can still be moved within the configured band and repeatedly drained.

### Likelihood Explanation
The vulnerable path is reachable by any unprivileged party who can submit an IntentGateway order (a single submitted transaction/order) and manipulate the referenced Uniswap V4 pool (e.g., via a flash loan) within the same block window the solver reads `getSlot0`. The guard being optional and documented as commonly omitted (the shipped `filler-config-example.toml` shows it commented out) makes the "unguarded" state a realistic production configuration rather than a contrived edge case: [9](#0-8) .

### Recommendation
Replace the raw `slot0` spot read with a manipulation-resistant price (e.g., a Uniswap V4 TWAP oracle over a meaningful window, or a Chainlink-style external oracle as already used elsewhere in `SimplexPaymaster`), make the deviation guard mandatory rather than optional for any curveless/venue-priced pair, and additionally bound quote acceptance by pool liquidity depth/expected price impact rather than a purely time-invariant static reference band.

### Proof of Concept
1. Operator configures a curveless pair (`token0 = USDC`, `token1 = <exotic>`) with a `[vault.uniswapV4]` position and no `referencePrice`/`maxDeviationBps` (a config state the validator in `filler-toml.ts` accepts).
2. Attacker takes a flash loan and swaps heavily against the referenced Uniswap V4 pool in the same block, moving `sqrtPriceX96`/tick far from the pool's fair value.
3. In the same block, attacker (or an accomplice) places/fills an IntentGateway order on the affected pair; `UniswapV4FundingPlanner.getExoticTokenPrice` → `computeDirectPoolPriceUsd` reads the manipulated `slot0`, and `FXFiller.resolveLegRates`/`checkPriceGuard` (no-op, unguarded) accepts it, sizing the solver's fill at the manipulated rate.
4. Solver's UserOperation executes the fill (and any V4 liquidity withdrawal to fund it) at the bad rate, attacker unwinds the flash loan and pockets the difference — the solver's LP position/wallet is drained analogously to XToken's mispriced xSNXa/xBNTa mints.

	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}

	/**
	 * Validates a live venue quote against the static reference price for the chain.
	 * Returns true (pass) when no guard is configured, or no reference exists for the
	 * chain. Returns false when the quote (token1 per USD) deviates from the reference
	 * by more than `maxDeviationBps`, in which case the order must not be filled.
	 */
	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {
			this.logger.warn(
				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
	}

	private async referenceRate(
		leg: ResolvedLeg,
		venueUsdPrice: (chain: string, token1Address: string) => Promise<Decimal | null>,
	): Promise<Decimal | null> {
		const policy = leg.pair.bidPricePolicy ?? leg.pair.askPricePolicy
		if (policy) {
			const rate = policy.getPrice(new Decimal(0))
			return rate.gt(0) ? rate : null
		}
		// Venue-priced pair: token0 is USD-stable (constructor invariant), so the
		// venue's USD-per-token1 quote inverts straight into token1-per-token0.
		const venueUsd = await venueUsdPrice(leg.token1Chain, leg.token1Address)
		if (!venueUsd) return null
		const venueRate = new Decimal(1).div(venueUsd)
		// Same guard as trade pricing: this rate sizes the order's USD notional
		// for confirmation depth, and a manipulated pool understating the value
		// would shrink the reorg protection — the exact attack the guard exists
		// to stop. Refusing to size skips the order, consistent with pricing.
		if (!this.checkPriceGuard(undefined, leg.token1Chain, venueRate)) return null
		return venueRate
	}

	// Per-position price guard: referencePrice and maxDeviationBps are optional but
	// must be set together. A given chain may not carry conflicting guard values.
	const guardByChain: Record<string, { referencePrice: string; maxDeviationBps: number }> = {}
	for (const position of uniswapV4?.positions ?? []) {
		const hasRef = position.referencePrice !== undefined
		const hasBps = position.maxDeviationBps !== undefined
		if (hasRef !== hasBps) {
			throw new Error(
				"vault.uniswapV4: a position price guard needs both 'referencePrice' and 'maxDeviationBps', or neither",
			)
		}
		if (!hasRef) continue

		const parsedRef = Number(position.referencePrice)
		if (!Number.isFinite(parsedRef) || parsedRef <= 0) {
			throw new Error(
				`vault.uniswapV4: position 'referencePrice' for chain '${position.chain}' must be a positive number`,
			)
		}
		if (
			!Number.isFinite(position.maxDeviationBps!) ||
			position.maxDeviationBps! <= 0 ||
			position.maxDeviationBps! > 10_000
		) {
			throw new Error(
				`vault.uniswapV4: position 'maxDeviationBps' for chain '${position.chain}' must be a number between 0 (exclusive) and 10000`,
			)
		}
		const existing = guardByChain[position.chain]
		if (
			existing &&
			(existing.referencePrice !== position.referencePrice || existing.maxDeviationBps !== position.maxDeviationBps)
		) {
			throw new Error(`vault.uniswapV4: conflicting price guard values for chain '${position.chain}'`)
		}
		guardByChain[position.chain] = {
			referencePrice: position.referencePrice!,
			maxDeviationBps: position.maxDeviationBps!,
		}
	}

```text
## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.
```
