### Title
Unauthenticated "Magic" QR Codes Allow Arbitrary Users to Trigger Privileged Orb Actions Without Operator Verification - ([File: src/plans/qr_scan/operator.rs])

### Summary
The Orb's operator QR-code scanning schema recognizes a special "magic" QR code format (`magic_action:reset_wifi_credentials` / `magic_action:reset_mirror_calibration`) that bypasses the normal operator-authentication path entirely. Unlike a normal operator QR code, which is validated against the backend (`backend::operator_status::request`) before being trusted, a magic QR code is accepted purely from local, client-side regex matching and dispatched to sensitive local actions with no authorization check.

### Finding Description
`qr_scan::operator::Data::try_parse` first tries to parse the scanned code as a normal, backend-verifiable operator QR (`user::Data::try_parse`); if that fails, it falls back to matching a `MAGIC_QR_CODE` regex and returns `Data::MagicResetWifi` or `Data::MagicResetMirror` for any string of the form `magic_action:reset_wifi_credentials` / `magic_action:reset_mirror_calibration`. [1](#0-0) 

In the signup flow, `scan_remaining_qr_codes` scans an operator QR code, then immediately calls `self.handle_magic_operator_qr_code(orb, operator_qr_code)` before any backend verification (`verify_operator_qr_code`) occurs: [2](#0-1) 

`handle_magic_operator_qr_code` dispatches directly to `reset_mirror_calibration` or `reset_wifi_and_ensure_network` for the `MagicResetMirror`/`MagicResetWifi` variants — with no requirement that the scanning party be a verified/authorized operator, and no backend call at all for this branch: [3](#0-2) 

This mirrors the root cause of the external report: a privileged, state-changing operation (there: minting/purchasing tokens that affect a shared `Royalties` contract; here: resetting the Orb's WiFi credentials or mirror calibration) is reachable via attacker-controlled input (`TokenFactory1155.createToken()` accepting arbitrary `Royalties` addresses; here, an arbitrary, self-crafted QR-code string) with no access-control gate analogous to `onlyOwner`. In both cases the acceptance/validation logic that should gate the privileged action is skipped for the exploited code path, while it is enforced for the "normal"/expected path (backend `operator_status` validation for normal operator QR codes vs. none for magic QR codes).

### Impact Explanation
Any person able to present a printed/displayed QR code to the Orb's RGB camera — with no possession of a valid, backend-issued operator QR code — can force the Orb to:
- Wipe and reset WiFi credentials (`reset_wifi_and_ensure_network`), disconnecting the Orb from its configured network and forcing it into WiFi-QR pairing mode, or
- Reset mirror/eye-tracking calibration (`reset_mirror_calibration`), degrading biometric capture quality/availability.

This is an availability/integrity impact on the signup pipeline: an unprivileged party can disrupt or manipulate a shared piece of Orb state (network configuration, hardware calibration) outside the intended operator-authorization boundary, exactly the "shared state manipulated by an unvetted party" bug class flagged in the report. It does not, on its own, disclose biometric data, but it undermines the assumption that only an authenticated operator can alter Orb configuration state, and — after a forced WiFi reset — opens a path for an attacker to subsequently supply attacker-controlled WiFi credentials via the WiFi MECARD QR flow (`src/plans/qr_scan/wifi.rs`, `src/network/mod.rs::join`), potentially rerouting the Orb's network path used for backend communication and biometric data upload.

### Likelihood Explanation
High for the mirror/WiFi reset itself: the magic QR code requires no backend interaction, no secret, and no operator credential — only a person able to briefly show a QR code to the camera during idle/signup-start scanning. It is trivially reproducible with a printed sticker. The follow-on network-redirection scenario has lower likelihood, since it depends on additional steps (attacker also supplying a WiFi QR and being in physical proximity of the target network) and is bounded by TLS/auth of subsequent backend calls.

### Recommendation
Require the same backend-verified authorization for magic QR-code actions as for normal operator QR codes (e.g., only accept `magic_action:*` codes after `verify_operator_qr_code` succeeds, or require a distinct backend-issued/signed token for magic actions) before calling `reset_mirror_calibration` or `reset_wifi_and_ensure_network`. At minimum, gate these actions behind an authenticated operator session rather than trusting client-side-only regex parsing of scanned text.

### Proof of Concept
1. Print or display the string `magic_action:reset_wifi_credentials` as a QR code.
2. Present it to the Orb during idle/signup-start QR scanning (the phase that normally expects an operator QR code).
3. `qr_scan::operator::Data::try_parse` matches the `MAGIC_QR_CODE` regex and returns `Data::MagicResetWifi` (src/plans/qr_scan/operator.rs:40-61).
4. `scan_remaining_qr_codes` invokes `handle_magic_operator_qr_code`, which calls `reset_wifi_and_ensure_network` without ever calling `backend::operator_status::request`/`verify_operator_qr_code` (src/plans/mod.rs:821-841, 978-1009).
5. The Orb's WiFi is wiped/reset with no operator authentication having occurred.

/// Operator QR-code data.
#[derive(Clone, Debug)]
pub enum Data {
    /// Normal Operator QR-code.
    Normal(user::Data),
    /// Action to reconfigure WiFi.
    MagicResetWifi,
    /// Action to reset mirror calibration.
    MagicResetMirror,
}

impl Schema for Data {
    fn ui() -> ui::QrScanSchema {
        ui::QrScanSchema::Operator
    }

    fn try_parse(code: &str) -> Option<Self> {
        let normal = user::Data::try_parse(code)
            .filter(
                |d| if d.signup_extension() { d.signup_extension_config.is_some() } else { true },
            )
            .map(Data::Normal);
        if normal.is_some() {
            return normal;
        }
        if let Some(captures) = MAGIC_QR_CODE.captures(code) {
            return match captures
                .name("magic_action")
                .expect("magic_action group must be present")
                .as_str()
            {
                "reset_wifi_credentials" => Some(Data::MagicResetWifi),
                "reset_mirror_calibration" => Some(Data::MagicResetMirror),
                _ => None,
            };
        }
        None
    }

    async fn handle_magic_operator_qr_code(
        &self,
        orb: &mut Orb,
        qr_code: qr_scan::operator::Data,
    ) -> Result<Option<qr_scan::user::Data>> {
        match qr_code {
            qr_scan::operator::Data::Normal(qr_code) => {
                tracing::info!("Operator QR-code detected: {qr_code:?}");
                Ok(Some(qr_code))
            }
            qr_scan::operator::Data::MagicResetMirror => {
                tracing::info!("Magic QR-code detected: Reset Mirror");
                dd_incr!("main.count.signup.during.general.magic_qr.reset_mirror");
                let result = self.reset_mirror_calibration(orb).await;
                if let Err(err) = &result {
                    tracing::error!("Failed to reset mirror calibration: {err}");
                }
                orb.ui.magic_qr_action_completed(result.is_ok());
                Ok(None)
            }
            qr_scan::operator::Data::MagicResetWifi => {
                tracing::info!("Magic QR-code detected: Reset Wi-Fi");
                dd_incr!("main.count.signup.during.general.magic_qr.reset_wifi");
                let result = self.reset_wifi_and_ensure_network(orb).await;
                if let Err(err) = &result {
                    tracing::error!("Failed to reset wifi: {err}");
                }
                orb.ui.magic_qr_action_completed(result.is_ok());
                Ok(None)
            }
        }
    }
