A genuine analog exists in the gateway's CORS origin allowlist logic.

### Title
CORS wildcard allowlist bypass via missing domain-label boundary check - (File: core/services/gateway/network/httpserver.go)

### Summary
The gateway HTTP server's CORS origin check performs a plain string-suffix match instead of a domain-label-boundary match when validating wildcard-allowed origins (e.g. `*.remix.com`). Any origin string that merely *ends with* the allowed suffix — not just true subdomains — is accepted, letting an attacker-registered domain such as `evilremix.com` pass as if it were `sub.remix.com`. This is the same bug class as the CVE referenced in the report: a suffix check that omits the required separator (dot) boundary, allowing an unrelated but cosmetically similar origin to be scoped into a trust boundary meant for a specific domain and its subdomains.

### Finding Description
`isAllowedOrigin` in [1](#0-0)  strips the `*.` prefix from a configured allowed origin and then does:

```go
if strings.HasPrefix(allowedHost, "*.") {
    allowedHost = allowedHost[2:]
    if strings.HasSuffix(originHost, allowedHost) {
        return true
    }
}
``` [2](#0-1) 

`strings.HasSuffix(originHost, allowedHost)` has no check that the character preceding the matched suffix in `originHost` is a `.` (or that `originHost` equals `allowedHost`). So if `CORSAllowedOrigins` contains `https://*.remix.com`, then an origin `https://evilremix.com` also satisfies `strings.HasSuffix("evilremix.com", "remix.com")` and is treated as allowed, even though `evilremix.com` is a completely unrelated domain, not a subdomain of `remix.com`.

This function is invoked directly from `handleRequest`, which is wired to every incoming HTTP request to the gateway's public-facing endpoint via `mux.Handle(config.Path, handler)` in `NewHTTPServer` [3](#0-2) . When `isAllowedOrigin` returns true, the server reflects the attacker's `Origin` header back in `Access-Control-Allow-Origin` and enables cross-origin credentialed-style access [4](#0-3) .

### Impact Explanation
Any unprivileged remote actor can register a domain that merely ends with an allowlisted suffix (no dot required) — e.g. `evilremix.com` for an allowlist entry `*.remix.com`, or `notremix.com`, `attackerremix.com`, etc. — and have browsers running on that origin treated as CORS-trusted by the gateway. Combined with the gateway's role as the internet-facing entry point for job/workflow/vault requests, this can enable cross-origin reading of gateway JSON-RPC responses (which may include job run results, vault/secrets metadata, or other sensitive response data) from a page hosted on the attacker's look-alike domain, effectively a cross-origin trust/allowlist bypass at the gateway boundary.

### Likelihood Explanation
Exploitation only requires registering a domain name whose string ends with the configured suffix (trivial, no special privileges, no interaction with legitimate subdomains) and getting a victim to visit a page on that domain that issues a request to the gateway with credentials/cookies or relies on the reflected CORS header. Given `CORSEnabled`/`CORSAllowedOrigins` with any wildcard entry is a supported, likely-used configuration [5](#0-4) , this is readily reachable whenever wildcard CORS allowlisting is configured.

### Recommendation
Fix `isAllowedOrigin` to require a domain-label boundary: accept the wildcard match only if `originHost == allowedHost` or `originHost` ends with `"."+allowedHost`, e.g.:
```go
if strings.HasPrefix(allowedHost, "*.") {
    allowedHost = allowedHost[2:]
    if originHost == allowedHost || strings.HasSuffix(originHost, "."+allowedHost) {
        return true
    }
}
```

### Proof of Concept
1. Configure the gateway with `CORSEnabled: true` and `CORSAllowedOrigins: ["https://*.remix.com"]`.
2. Send a request to the gateway's configured path with header `Origin: https://evilremix.com`.
3. Observe `isAllowedOrigin` returns `true` (via `strings.HasSuffix("evilremix.com", "remix.com")`), and the response includes `Access-Control-Allow-Origin: https://evilremix.com`, even though `evilremix.com` is not a subdomain of `remix.com`.

func (s *httpServer) isAllowedOrigin(origin string) bool {
	originScheme, originHost, originPort, err := s.splitURL(origin)
	if err != nil {
		s.lggr.Debug("error parsing origin URL", err)
		return false
	}
	for _, allowed := range s.config.CORSAllowedOrigins {
		// probably better to do this once when server starts and store it in a map
		// this is an easier solution so we don't have to apply more changes to the code
		// just need to be careful when specifying allowed origins in the config file
		allowedScheme, allowedHost, allowedPort, err := s.splitURL(allowed)
		if err != nil {
			s.lggr.Debug("error parsing allowed origin URL", err)
			continue
		}
		// skip if the scheme doesn't match at all
		if originScheme != allowedScheme {
			continue
		}
		// skip if the port doesn't match at all
		if originPort != allowedPort {
			continue
		}
		// check for exact host match (e.g., remix.com)
		if originHost == allowedHost {
			return true
		}
		// check for wildcard host match (e.g., *.remix.com)
		if strings.HasPrefix(allowedHost, "*.") {
			allowedHost = allowedHost[2:]
			if strings.HasSuffix(originHost, allowedHost) {
				return true
			}
		}
	}
	return false
}

func (s *httpServer) handleRequest(w http.ResponseWriter, r *http.Request) {
	if s.config.CORSEnabled {
		origin := r.Header.Get("Origin")
		if s.isAllowedOrigin(origin) {
			w.Header().Set("Access-Control-Allow-Origin", origin)
			w.Header().Set("Access-Control-Allow-Methods", "GET, POST, OPTIONS")
			w.Header().Set("Access-Control-Allow-Headers", "Content-Type")
		}

		// handle preflight requests
		if r.Method == http.MethodOptions {
			w.WriteHeader(http.StatusNoContent)
			return
		}
