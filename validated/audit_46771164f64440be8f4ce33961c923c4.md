Audit Report

## Title
JWT replay-protection TOCTOU race allows a single-use HTTP Trigger token to be replayed - (File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go)

## Summary
`WorkflowMetadataHandler.Authorize` verifies a request JWT, checks `isReplay(claims.ID)`, then—only after further validation—calls `recordUsage(claims.ID)`. The check and the marking-as-used are two separate, independently-locked critical sections rather than one atomic check-and-set, so concurrent requests carrying the same `jti` can both pass the replay check before either records usage.

## Finding Description
The vulnerable sequence is in `Authorize`: [1](#0-0) . It calls `h.jwtCache.isReplay(claims.ID)` first, and only calls `h.jwtCache.recordUsage(claims.ID)` at the very end of the function, after the authorized-key lookup succeeds. The underlying cache implements these as two separate operations, each independently locked: `isReplay` takes an `RLock`, reads, and releases; `recordUsage` is a distinct call that later takes a `Lock` to write [2](#0-1) . There is no compare-and-swap or single write-locked critical section spanning the read-check and the write-mark, so this is a genuine check-then-act race.

Critically, `Authorize` is invoked per incoming request from `httpTriggerHandler.authorizeRequest`, which is called from `HandleUserTriggerRequest` on every user request [3](#0-2) . The only other uniqueness enforcement in the pipeline is on the JSON-RPC `requestID`, guarded separately in `setupCallback` via `callbacksMu` [4](#0-3) , which is a distinct field from the JWT `jti` and does not protect the JWT replay cache at all — an attacker can freely choose distinct `requestID`s per request while reusing the identical signed JWT/`jti`. `HandleJSONRPCUserMessage` processes each incoming user message (including concurrent ones) by calling `HandleUserTriggerRequest`, so nothing upstream serializes calls to `Authorize` for the same `jti`. This confirms no existing lock/gate closes the race window.

## Impact Explanation
An unprivileged external caller holding one valid, signed HTTP Trigger JWT can send multiple concurrent requests (with distinct `requestID`s, which are unrelated to the replay cache key) that all reach `Authorize` before any of them calls `recordUsage`. This defeats the single-use guarantee of the JWT and lets one token authorize more than one workflow-trigger dispatch to the DON, i.e., an authentication/replay-protection bypass leading to duplicate/unauthorized job execution — an in-scope impact category (node/gateway authentication bypass leading to unauthorized job run).

## Likelihood Explanation
Likelihood is realistic: it requires only possession of one valid JWT (something already necessary to trigger a workflow at all) and the trivial ability to fire a handful of near-simultaneous requests, no special network position or privilege escalation needed. The race window (between the `RLock` read and the later `Lock` write, separated by authorized-key lookup logic) is small but fully attacker-controllable by issuing several duplicate requests concurrently, which is a standard, low-cost technique.

## Recommendation
Make check-and-mark atomic under one lock in `jwtReplayCache`, e.g., add a single `Acquire(jti string) bool` method that takes `mu.Lock()`, checks for existence, inserts if absent, and returns whether it was already present—all within one critical section—replacing the separate `isReplay` + `recordUsage` calls in `Authorize`.

## Proof of Concept
1. Obtain one valid, signed JWT with `jti = X` for an HTTP Trigger request.
2. Fire two or more concurrent `HandleJSONRPCUserMessage` gateway requests with distinct `requestID`s but the identical JWT (`jti = X`).
3. Each concurrent call reaches `WorkflowMetadataHandler.Authorize` → `isReplay(X)` before any has yet called `recordUsage(X)`, per the code at `workflow_metadata_handler.go` lines 87-105 and 399-412.
4. Both requests pass authorization and are dispatched via `sendWithRetries` as distinct, legitimate trigger invocations despite the JWT being single-use, demonstrable via a Go unit test that spins up two goroutines calling `Authorize` with the same `jti` and asserts both succeed.

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}

```go
func (cache *jwtReplayCache) isReplay(jti string) bool {
	cache.mu.RLock()
	defer cache.mu.RUnlock()

	_, exists := cache.cache[jti]
	return exists
}

func (cache *jwtReplayCache) recordUsage(jti string) {
	cache.mu.Lock()
	defer cache.mu.Unlock()

	cache.cache[jti] = time.Now()
}
```

func (h *httpTriggerHandler) authorizeRequest(ctx context.Context, workflowID string, req *jsonrpc.Request[json.RawMessage], callback handlers.Callback) (*gateway_common.AuthorizedKey, error) {
	h.lggr.Debugw("authorizing request", "workflowID", workflowID, "requestID", req.ID)
	key, err := h.workflowMetadataHandler.Authorize(workflowID, req.Auth, req)
	if err != nil {
		h.handleUserError(ctx, req.ID, jsonrpc.ErrInvalidRequest, "Auth failure: "+err.Error(), callback)
		return nil, errors.Join(errors.New("auth failure"), err)
	}
	return key, nil
}
