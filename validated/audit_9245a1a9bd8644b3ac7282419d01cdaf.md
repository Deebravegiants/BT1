### Title
GET-response delivery never clears `_requestCommitments`, letting a stale timeout proof re-fire `onGetTimeout` and double-pay the relayer fee - (File: `evm/src/core/EvmHost.sol`)

### Summary
`EvmHost.dispatchIncoming(GetResponse,...)` pays out the relayer fee for a `GetRequest` but never deletes the corresponding `_requestCommitments[commitment]` entry, unlike every other terminal delivery path in the same contract (`dispatchTimeOut` for both GET and POST requests explicitly `delete _requestCommitments[commitment]` before invoking the app). This leaves the fee metadata live after a response has already been delivered, so a later `handleGetRequestTimeouts` → `dispatchTimeOut(GetRequestTimeout,...)` call for the same commitment is still accepted: it re-invokes the destination module's `onGetTimeout` after it already received `onGetResponse`, and pays `meta.fee` out of the host's fee-token balance a second time.

### Finding Description
Compare the two terminal handlers for a dispatched `GetRequest`:

- `dispatchIncoming(GetResponse memory response, address relayer)` [1](#0-0)  sets `_responseReceipts[commitment]` for replay protection of the *response* path, calls `IApp.onGetResponse`, and — only after that external call returns successfully — reads `_requestCommitments[commitment].fee` and transfers it to the relayer. It never touches `_requestCommitments[commitment]`.
- `dispatchTimeOut(GetRequestTimeout memory timeout, FeeMetadata memory meta, bytes32 commitment)` [2](#0-1)  explicitly does `delete _requestCommitments[commitment]` **before** calling `IApp.onGetTimeout`, precisely so the same commitment cannot be replayed through this same function again.

Because `dispatchIncoming(GetResponse,...)` doesn't clear `_requestCommitments`, the `meta.sender != address(0)` "known request" gate used by both `HandlerV2.handleGetResponses` [3](#0-2)  and `HandlerV2.handleGetRequestTimeouts` [4](#0-3)  stays open forever for a request that already received its response.

The comment in `handleGetResponses`, `// don't check for timeouts because it's checked on Hyperbridge`, confirms responses can be delivered close to or even after the nominal timeout without any local check [5](#0-4) . `handleGetRequestTimeouts` independently verifies a **non-membership** proof of the response receipt at some previously-stored state height and `request.timeout() > state.timestamp` [4](#0-3) . Old `stateMachineCommitment` heights remain queryable (`host.stateMachineCommitment(height)`), so a relayer holding (or able to construct) a non-membership proof from a height *before* the response was actually committed can submit `handleGetRequestTimeouts` for a commitment whose response has *already* been delivered on this chain. Since `_requestCommitments[commitment]` was never cleared by the response path, `meta.sender != address(0)` still holds, and `dispatchTimeOut` proceeds: it re-invokes `onGetTimeout` on an app that already processed the corresponding `onGetResponse`, and unconditionally refunds `meta.fee` to `meta.sender` from the host's shared fee-token balance — a fee amount that was already paid out once to the relayer in the response path.

This is the same bug class as the CVE hint (state that one code path assumes is still valid, but which another independently-reachable path can mutate/consume out of expected order — here, "response delivered" state is never recorded in the structure the timeout path actually checks).

### Impact Explanation
This allows duplicate payout of the protocol fee-token balance for a single logical request: once via the relayer reward in `dispatchIncoming(GetResponse,...)` and again via the refund in `dispatchTimeOut(GetRequestTimeout,...)`. It also forces a destination `IApp` module to process both `onGetResponse` and `onGetTimeout` for the same request, which most app implementations do not expect and can corrupt app-level accounting (e.g., double refunds/double execution of a pending action). Repeated across many requests this drains the host's shared `feeToken` balance — concrete theft of protocol/user funds, reachable by any relayer with a valid (if stale) non-membership proof, without any privileged role.

### Likelihood Explanation
Exploitability depends on the relayer's ability to obtain or construct a non-membership proof at a state height prior to the one at which the response was actually delivered, while still satisfying `request.timeout() > state.timestamp` and the challenge-period delay check. Since old `_stateCommitments` entries are retained indefinitely and are not pruned once superseded [6](#0-5) , and challenge periods/consensus updates are attacker-influenceable in timing, a relayer that races a timeout proof against (or shortly after) a delayed response delivery has a realistic window to hit this path. This requires no compromised admin/governance/collator — only a permissionless proof submission — matching the required threat model.

### Recommendation
In `EvmHost.dispatchIncoming(GetResponse memory response, address relayer)`, delete `_requestCommitments[commitment]` (mirroring `dispatchTimeOut`) as soon as the response is accepted for delivery, before or immediately after the fee transfer, so a subsequent `dispatchTimeOut(GetRequestTimeout,...)` for the same commitment is rejected by the `meta.sender == address(0)` check in `handleGetRequestTimeouts`.

### Proof of Concept
Conceptual sequence (would need to be validated against a Foundry fork with a real relayer/consensus setup):
1. User dispatches a `GetRequest` via `EvmHost.dispatch(DispatchGet)`, funding `fee`; `_requestCommitments[commitment] = {sender, fee}` [7](#0-6) .
2. A relayer submits the corresponding response through `HandlerV2.handleGetResponses` → `EvmHost.dispatchIncoming(GetResponse,...)`; `onGetResponse` succeeds and `fee` is paid to the relayer. `_requestCommitments[commitment]` remains set (bug).
3. The same or a colluding relayer later submits `HandlerV2.handleGetRequestTimeouts` for the same commitment using a stored, earlier state height where the response receipt was still absent, satisfying the non-membership proof and `request.timeout() > state.timestamp`.
4. `EvmHost.dispatchTimeOut(GetRequestTimeout,...)` executes: `onGetTimeout` fires on the destination app a second time, and `meta.fee` is transferred again to `meta.sender` — a second payout for the same request from the host's fee-token pool.

     * @dev Dispatch an incoming GET response to source module
     * @param response - get response

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function handleGetResponses(IHost host, GetResponseMessage calldata message) external notFrozen(host) {
        uint256 timestamp = block.timestamp;
        uint256 delay = timestamp - host.stateMachineCommitmentUpdateTime(message.proof.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        uint256 responsesLength = message.responses.length;
        MerkleMountainRange.Leaf[] memory leaves = new MerkleMountainRange.Leaf[](responsesLength);

        for (uint256 i = 0; i < responsesLength; ++i) {
            GetResponseLeaf memory leaf = message.responses[i];
            // don't check for timeouts because it's checked on Hyperbridge

            // known request? also serves as source check
            FeeMetadata memory meta = host.requestCommitments(leaf.response.request.hash());
            if (meta.sender == address(0)) revert UnknownMessage();
            leaves[i] = MerkleMountainRange.Leaf(leaf.index, leaf.response.hash());
        }

        bytes32 root = host.stateMachineCommitment(message.proof.height).overlayRoot;
        if (root == bytes32(0)) revert StateCommitmentNotFound();
        bool valid = MerkleMountainRange.VerifyProof(root, message.proof.multiproof, leaves, message.proof.leafCount);
        if (!valid) revert InvalidProof();

        for (uint256 i = 0; i < responsesLength; ++i) {
            GetResponseLeaf memory leaf = message.responses[i];
            // duplicate response?
            if (host.responseReceipts(leaf.response.request.hash()).relayer != address(0)) revert DuplicateMessage();
            host.dispatchIncoming(leaf.response, _msgSender());
        }
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
