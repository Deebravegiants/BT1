### Title
Deposits into markets with unrealized bad debt are immediately socialized into losses - (File: contracts/pool/src/guards.rs)

### Summary

The supply solvency gate treats every outstanding debt share as fully collectible backing until liquidation or cleanup writes it off. Consequently, `supply` accepts deposits into a market containing an account already eligible for permissionless `clean_bad_debt`. The subsequent cleanup burns the account’s entire debt position and reduces that market’s `supply_index`, permanently diluting the new depositor’s shares. The backing check prevents deposits only after a realized pool-level shortfall, not while bad debt remains recorded at face value. [1](#0-0) [2](#0-1) 

### Finding Description

`pool::ops::supply::apply` invokes `require_backed_market` before minting supply shares. That guard computes backing as `cash + ceil(borrowed * borrow_index)` and compares it with the current supply claim. It does not discount debt whose borrower is insolvent or eligible for cleanup. [3](#0-2) [1](#0-0) 

Any authorized caller can invoke `clean_bad_debt(caller, account_id)`. The entrypoint admits an account when `total_debt > total_collateral` and `total_collateral <= BAD_DEBT_USD_THRESHOLD`, then seizes every supply and borrow position. [4](#0-3) [5](#0-4) 

For each borrow leg, the pool computes the entire ceiled debt value, applies it as a bad-debt reduction to the market’s supply index, and burns the debt shares. The write-down is pro-rata over total supplied value and is floored at `SUPPLY_INDEX_FLOOR_RAW`. [2](#0-1) [6](#0-5) 

Thus, between the time an account becomes eligible for cleanup and the time `clean_bad_debt` or liquidation executes, the debt market can pass `require_backed_market` while containing economically uncollectible debt. A deposit accepted during that window is immediately included in the denominator of the later supply-index write-down. [7](#0-6) [8](#0-7) 

### Impact Explanation

A new depositor suffers a permanent loss proportional to the socialized debt even though the market passed the pool’s insolvency guard. For example, if pre-deposit supply claims are 100 units, cash is 5 units, and uncollectible debt is 95 units, the backing check returns zero shortfall because it values the 95 units of debt at face value. A 100-unit deposit raises total claims to 200 units; cleanup then writes off 95 units and leaves each supplier with approximately 52.5% of its previous claim. The depositor loses approximately 47.5 units permanently rather than receiving shares backed by their fresh deposit. [7](#0-6) [8](#0-7) 

The loss is not dependent on privileged action because `clean_bad_debt` is callable by any authenticated caller once the dust-gated insolvency predicate holds. The same outcome can also occur through ordinary liquidation followed by automatic cleanup when residual collateral falls below the dust cap. [9](#0-8) [10](#0-9) 

### Likelihood Explanation

The vulnerable window is publicly observable: an account must already satisfy `total_debt > total_collateral` and `total_collateral <= $5`. During that window, no market flag marks the debt as impaired, and the pool’s supply gate still counts it at face value. A depositor can therefore enter immediately before anyone performs the permissionless cleanup. [5](#0-4) [1](#0-0) 

The loss requires a specific pre-existing bad-debt state and a depositor entering during the cleanup lag, rather than arbitrary attacker creation of the condition in one call. Nevertheless, once the state exists, both the harmful deposit and cleanup are reachable by unprivileged addresses, and no deposited amount or health threshold protects the new shares from the write-down. [11](#0-10) [12](#0-11) 

### Recommendation

Do not admit supply into a market containing known cleanup-eligible debt at face value. Before accepting `supply`, the controller should either force cleanup of all eligible debt affecting that market or mark the affected debt as impaired so `require_backed_market` excludes its unrecoverable component. If enumeration is not feasible, maintain per-market accrued bad-debt/impairment accounting updated by liquidation, cleanup, or threshold refresh and use the recoverable debt value rather than gross `borrowed * borrow_index` in the deposit backing check. [13](#0-12) [7](#0-6) 

At minimum, block or warn `supply` when a caller provides an account list demonstrating cleanup eligibility, and expose a market-level expected-bad-debt view so depositor frontends can prevent entry during the unwritten-loss window. Recapitalization should remain the recovery path only for realized shortfalls after cleanup. [14](#0-13) 

### Proof of Concept

Assume hub asset `M` has token price $1, `supply_index = borrow_index = RAY`, supply shares representing 100 units, tracked `cash = 5`, and debt shares representing 95 units. Account `A` owes those 95 units and holds at most $5 of collateral, so `is_socializable_bad_debt(95, <=5)` is true. [5](#0-4) 

1. User `U` invokes:

```text
Controller::supply(
    caller = U,
    account_id = 0,
    spoke_id = S,
    assets = [(M, 100)]
)
```

2. The controller transfers 100 units of `M` to the pool and calls the pool supply batch. [15](#0-14) 

3. The pool computes:

```text
supplied_claim   = 100
outstanding_debt = 95
backing          = cash 5 + debt 95 = 100
shortfall        = 0
```

Therefore `require_backed_market` passes, `U` receives approximately 100 units worth of shares, and `cash` increases to 105. [1](#0-0) [13](#0-12) 

4. Any unprivileged caller, including `U`, another user, or a liquidation bot, invokes:

```text
Controller::clean_bad_debt(
    caller = caller,
    account_id = A
)
```

5. `socialize_bad_debt` admits `A` because its debt exceeds collateral and collateral is below the dust cap. `execute_bad_debt_cleanup` emits a `PoolSeizeEntry` for the 95-unit borrow position. [16](#0-15) [17](#0-16) 

6. `pool::ops::seize::apply` computes bad debt as 95 units, calls `apply_bad_debt_to_supply_index`, and burns the debt. Total supplied value is now 200 units, so:

```text
reduction_factor = (200 - 95) / 200 = 0.525
new_supply_index = RAY * 0.525
```

The depositor’s approximately 100-unit claim becomes approximately 52.5 units. The market still has 105 units of cash backing 105 units of residual claims, so the depositor can withdraw only about 52.5 units and has permanently lost about 47.5 units. [2](#0-1) [8](#0-7)

/// Panics with `PoolInsolvent` if the market has a positive backing shortfall.
///
/// Backing = cash + ceiled debt value; claims = floored supply value.
pub(crate) fn require_backed_market(env: &Env, cache: &Cache) {
    assert_with_error!(
        env,
        backing_shortfall(cache) == 0,
        CollateralError::PoolInsolvent
    );
}

/// Asset units by which supplier claims exceed cash + debt (0 if solvent).
pub(crate) fn backing_shortfall(cache: &Cache) -> i128 {
    let supplied_claim = cache.unscale_supply_floor(cache.supplied());
    let outstanding_debt = cache.unscale_borrow_ceil(cache.borrowed());
    let backing = cache.cash().saturating_add(outstanding_debt);
    supplied_claim.saturating_sub(backing).max(0)
}

/// Admission condition for bad-debt socialization.
#[derive(Clone, Copy, PartialEq)]
enum BadDebtGate {
    /// Permissionless: insolvent *and* collateral at or below the dust threshold.
    DustCapped,
    /// Owner-only: insolvent alone, with no cap on the collateral left behind.
    InsolventOnly,
}

/// Requires open debt and the selected insolvency gate, then cleans up the account.
fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    bad_debt::execute_bad_debt_cleanup(env, &mut cache, account_id, &account, &totals);
}

/// Socializes `bad_debt` by reducing the supply index (capped at total supply value).
///
/// Used when seizing unpaid debt: remaining supplier claims shrink pro-rata.
/// No-op when total supplied value is zero. Floors the resulting index at
/// [`SUPPLY_INDEX_FLOOR_RAW`] to avoid a zero index.
pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}
