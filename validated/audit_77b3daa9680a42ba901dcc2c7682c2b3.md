### Title
OAuth `shop` parameter is not validated against `ShopValidator` in `begin_auth`, enabling `state`-nonce leakage via attacker-controlled host - (File: lib/shopify_api/auth/oauth.rb)

### Summary
`ShopifyAPI::Auth::Oauth.begin_auth` builds the OAuth authorize redirect URL directly from the caller-supplied `shop` string with no domain validation, unlike `ClientCredentials.client_credentials` and `RefreshToken.refresh_access_token`, which both call `Utils::ShopValidator.sanitize!(shop)` before using the shop to construct a request that carries the app's `client_secret` [2](#0-1) [3](#0-2) .

### Finding Description
`begin_auth` takes `shop:` as a raw string and passes it straight into `auth_base_uri(shop)`, which interpolates it into a URL with no validation that it is a genuine `*.myshopify.com`/trusted Shopify domain: `"https://#{shop}/admin" + "/oauth/authorize?#{query_string}"` [4](#0-3) [5](#0-4) . The query string embeds a server-generated CSRF `state` nonce and `client_id`/`redirect_uri` [6](#0-5) . If the host application forwards a `shop` value that originated from an unauthenticated source (e.g. a `?shop=` query parameter on a login route, which is the conventional entry point for the Shopify OAuth install flow) without itself sanitizing it, the browser is redirected to an attacker-chosen host with the `state` value in the URL, leaking the anti-CSRF nonce to that host.

By contrast, `Auth::JwtPayload`/`TokenExchange.exchange_token` derive the shop from an HMAC/JWT-verified claim rather than trusting caller input [7](#0-6) , and `ClientCredentials`/`RefreshToken` explicitly sanitize the shop before it is used to build a request carrying `client_secret` [8](#0-7) . `begin_auth` is the outlier that performs neither check.

Note: `validate_auth_callback`'s use of `auth_query.shop` is HMAC-protected end‑to‑end (`Utils::HmacValidator.validate(auth_query)` is checked before the value is used to build the `client_secret`-bearing request) [9](#0-8) [10](#0-9) , so I could not construct a path from this gem's own code where the `client_secret` itself is exfiltrated — forging that HMAC requires the `api_secret_key`, which is out of scope. The confirmed, in-scope weakness is limited to `begin_auth`'s unvalidated redirect target and the resulting nonce leak.

### Impact Explanation
Leaking the `state` nonce alone does not let an attacker complete a forged OAuth flow, because `validate_auth_callback` still requires a Shopify-issued HMAC over `code/host/shop/state/timestamp` that an attacker without `api_secret_key` cannot forge [11](#0-10) . I was not able to establish a complete chain from the leaked nonce to session fixation, forced OAuth completion, or credential theft using only in-scope code. Without that chain, the issue does not clearly meet the Critical/High bar (authentication bypass, credential theft, cross-tenant access, RCE, or SSRF/session-fixation with a demonstrated end-to-end path).

### Likelihood Explanation
Exploitability depends on the host application forwarding unauthenticated user input directly into `begin_auth(shop:)` without its own sanitization, which the library's docs and `ShopValidator` addition elsewhere suggest is exactly the risk this gem intends to guard against, but does not enforce here.

### Recommendation
Call `Utils::ShopValidator.sanitize!(shop)` (already used by `ClientCredentials` and `RefreshToken`) at the top of `Oauth.begin_auth` (and defensively in `validate_auth_callback`) before constructing `auth_base_uri`, so an invalid/untrusted domain raises `Errors::InvalidShopError` instead of being used to build a redirect or outbound request.

### Proof of Concept
Given inconsistent validation is present in sibling methods but absent here, a concrete PoC would be: host app route `GET /login?shop=evil.example.com` calls `ShopifyAPI::Auth::Oauth.begin_auth(shop: params[:shop], redirect_path: "/callback")`; the returned `auth_route` is `https://evil.example.com/admin/oauth/authorize?client_id=...&state=<nonce>&...`, and redirecting the user's browser there discloses `state` to `evil.example.com`. I could not extend this into a full credential-theft or session-fixation PoC using only the code available in this repository — this final step is unconfirmed and flagged as such.

        def validate_auth_callback(cookies:, auth_query:)
          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::InvalidOauthError, "Invalid OAuth callback." unless Utils::HmacValidator.validate(auth_query)
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = cookies[SessionCookie::SESSION_COOKIE_NAME]
          raise Errors::NoSessionCookieError unless state

          raise Errors::InvalidOauthError,
            "Invalid state in OAuth callback." unless state == auth_query.state

          null_session = Auth::Session.new(shop: auth_query.shop)
          body = {
            client_id: Context.api_key,
            client_secret: Context.api_secret_key,
            code: auth_query.code,
            expiring: Context.expiring_offline_access_tokens ? 1 : 0, # Only applicable for offline tokens
          }

          client = Clients::HttpClient.new(session: null_session, base_path: "/admin/oauth")
          response = begin
            client.request(
              Clients::HttpRequest.new(
                http_method: :post,
                path: "access_token",
                body: body,
                body_type: "application/json",
              ),
            )
          rescue ShopifyAPI::Errors::HttpResponseError => e
            raise Errors::RequestAccessTokenError,
              "Cannot complete OAuth process. Received a #{e.code} error while requesting access token."
          end

          session_params = T.cast(response.body, T::Hash[String, T.untyped]).to_h
          session = Session.from(shop: auth_query.shop,
            access_token_response: Oauth::AccessTokenResponse.from_hash(session_params))

        def auth_base_uri(shop)
          return "https://#{shop}/admin" unless defined?(DevServer) && shop.include?(".my.shop.dev")

            .new("admin-web")
          admin_host = admin_web.host!(nonstandard_host_prefix: "admin")
          shop_name = shop.split(".").first

          "https://#{admin_host}/store/#{shop_name}"
        end
