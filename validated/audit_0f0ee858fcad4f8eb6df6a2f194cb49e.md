### Title
Unvalidated swap routes can inject unauthorized token transfers under the caller's authorization tree - ([File: contracts/controller/src/strategies/swap.rs](contracts/controller/src/strategies/swap.rs))

### Summary
Controller strategy endpoints accept arbitrary router payload bytes and execute routes containing attacker-controlled pool addresses without an allowlist or authorization-shape restriction. A malicious route can place rogue contract code beneath the caller's `require_auth`, causing a wallet transfer unrelated to the requested swap to appear as a child authorization and execute if the caller signs the simulated tree. [1](#0-0) 

### Finding Description
`swap_collateral` accepts caller-supplied `swap` bytes and forwards them through `withdraw_and_swap_from_supply` after only checking account ownership and market eligibility. [2](#0-1)  The shared strategy helper invokes the configured router with the unvalidated payload and only verifies measured input/output balances afterward. [3](#0-2)  Because route venues and token addresses are payload-controlled, malicious venue code can execute under the transaction authorization context and request an unrelated token transfer from the caller. [4](#0-3) 

### Impact Explanation
An attacker can steal unrelated wallet assets from a user who signs a malicious route-generated authorization tree. The regression test demonstrates a route that returns the expected collateral while a rogue hop pool transfers the victim's entire unrelated wallet-token balance to the attacker. [5](#0-4)  The measured-output and account-risk checks do not bound this loss because the stolen token need not participate in the swap. [6](#0-5) 

### Likelihood Explanation
The route bytes are user-supplied to reachable entrypoints such as `swap_collateral`, `swap_debt`, `multiply`, `flash_position`, and `repay_debt_with_collateral`, while the router invokes payload-named venues. [7](#0-6)  Exploitation requires the victim to submit or sign the poisoned route, but ordinary wallet simulation represents the rogue transfer as a child of the legitimate controller authorization rather than as an obviously separate authorization. [8](#0-7) 

### Recommendation
Restrict controller strategy routes to governance-approved venues/pools, or bind the strategy authorization to an exact expected authorization tree and reject any additional child invocation. At minimum, reject third-party contract execution under the caller's authorization context and require route decoding/validation before `execute_strategy`.

### Proof of Concept
1. Victim owns a lending account with USDC collateral and holds an unrelated wallet token.
2. Attacker deploys a contract exposing the expected pool callback and encodes it as a hop pool in the `swap` bytes.
3. Victim calls `swap_collateral(caller=victim, account_id, current=USDC, amount, new=ETH, swap=malicious_route)`.
4. The malicious pool executes `wallet_token.transfer(victim, attacker, victim_balance)` during route execution. [9](#0-8) 
5. Simulation records that transfer as a child of the victim's `swap_collateral` authorization; signing that tree makes the theft succeed while the swap still returns fair output. [10](#0-9)

fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
