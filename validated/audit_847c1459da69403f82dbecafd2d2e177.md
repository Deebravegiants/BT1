### Title
Cookie-based session lookup trusts a raw, unsigned, deterministic session ID (`offline_<shop>`) with no HMAC/signature verification - (File: lib/shopify_api/utils/session_utils.rb)

### Summary
`SessionUtils.current_session_id` / `cookie_session_id` return the value of the `shopify_app_session` cookie verbatim as the session ID to load, with no cryptographic verification that the value was actually issued by this server for the requesting client. Because offline session IDs are deterministically generated as `"offline_#{shop}"` [1](#0-0)  and `shop` (the `.myshopify.com` domain) is public/guessable, any unprivileged attacker can fabricate the `Cookie: shopify_app_session=offline_<victim-shop>` header without ever completing OAuth or possessing a real cookie issued by the server.

### Finding Description
The claimed binding — `session_id_returned == cookies['shopify_app_session']` should instead require `session_id_returned == HMAC_verified(cookies['shopify_app_session'], Context.api_secret_key)` — is accurate. Tracing the code:

- `current_session_id(nil, cookies, false)` for a non-embedded app goes straight to `cookie_session_id(cookies)` [2](#0-1) .
- `cookie_session_id` simply returns `cookies[Auth::Oauth::SessionCookie::SESSION_COOKIE_NAME]` with no verification whatsoever [3](#0-2) .
- The cookie itself is a plain, non-random value: in `Oauth.validate_auth_callback`, for non-embedded apps the cookie is set to `session.id` directly (`SessionCookie.new(value: session.id, expires: ...)`) [4](#0-3) , and for offline sessions `session.id` is always `"offline_#{shop}"` [1](#0-0) .
- `SessionCookie` itself carries no signature, MAC, or secret-derived value — it is a bare `T::Struct` of `name`, `value`, `expires` [5](#0-4) .

Because the "session cookie" content is fully deterministic from public information (the shop's `.myshopify.com` domain), it is not a secret credential at all — it's a predictable identifier. The gem never binds this cookie value to `Context.api_secret_key` via HMAC (the way `HmacValidator.validate` protects the OAuth callback `state`/query params during `validate_auth_callback` at line 64). The host app documentation instructs non-embedded apps to pass raw request cookies straight into `current_session_id` [6](#0-5) , with no guidance to sign or encrypt the cookie value themselves.

Attacker request: `GET /callback` (or any authenticated route reading the current session) with header `Cookie: shopify_app_session=offline_another-shop.myshopify.com`. `current_session_id` returns `"offline_another-shop.myshopify.com"` verbatim, the host app loads `Auth::Session` for that ID from its session store, and subsequent REST/GraphQL calls execute using the victim shop's stored access token.

None of the existing guards prevent this: `HmacValidator.validate` only protects the initial OAuth callback query string, not this cookie read path; `ShopValidator.sanitize!` isn't invoked here; `Context.embedded?` merely selects the `else` branch that leads to the same unverified `cookie_session_id` call; there is no JWT involved in this flow at all.

### Impact Explanation
An attacker gains the ability to impersonate any shop that has completed offline OAuth with the app, purely by guessing/knowing its `.myshopify.com` domain (which is often discoverable — public storefront URL, app listing, referral links, etc.). This is full cross-tenant access: the attacker's requests are treated as authenticated for the victim shop and can read/write its data and exfiltrate its access token if the app echoes/exposes it anywhere. This is repeatable against arbitrary victim shops with zero cost per target beyond knowing the domain name. This matches the Critical category: cross-tenant access / authentication bypass.

### Likelihood Explanation
Preconditions: non-embedded app (`Context.embedded? == false`), the app relies on cookie-based session lookup as documented, and the victim shop has already completed offline OAuth (a normal, common state for installed apps). No secrets, tokens, or victim interaction are required — the attacker only needs the victim's shop domain, which is essentially public. This makes exploitation very low-cost and highly repeatable.

### Recommendation
Do not use the raw session ID as the cookie's cleartext value. Either:
1. Store the cookie as an HMAC-signed or encrypted value (e.g., `HMAC-SHA256(session.id, Context.api_secret_key)` or a random opaque token mapped server-side to the session), and have `cookie_session_id` verify the signature/lookup before returning a session ID, rejecting mismatches; or
2. Delegate cookie session storage entirely to a signed/encrypted session mechanism (e.g., Rails' encrypted cookie store) rather than a plain custom cookie, and document this requirement explicitly instead of instructing developers to pass raw request cookies into `current_session_id`.

### Proof of Concept
```ruby
# test/utils/session_utils_test.rb (new test)
def test_cookie_session_id_accepts_forged_cookie_without_verification
  ShopifyAPI::Context.setup(
    api_key: "key", api_secret_key: "secret", host_name: "app.com",
    scope: "read_products", is_embedded: false, is_private: false, api_version: "2023-01"
  )

  forged_cookies = { ShopifyAPI::Auth::Oauth::SessionCookie::SESSION_COOKIE_NAME =>
                        "offline_another-shop.myshopify.com" }

  returned_id = ShopifyAPI::Utils::SessionUtils.current_session_id(nil, forged_cookies, false)

  # Binding check: server accepts the raw cookie value with NO HMAC verification
  assert_equal "offline_another-shop.myshopify.com", returned_id
  # No call to Utils::HmacValidator or any signature check occurs anywhere in this path -
  # demonstrated by mocking HmacValidator.validate to raise and showing it's never invoked:
  ShopifyAPI::Utils::HmacValidator.expects(:validate).never
  ShopifyAPI::Utils::SessionUtils.current_session_id(nil, forged_cookies, false)
end
```
This demonstrates that `session_id_returned == cookies['shopify_app_session']` holds unconditionally, while the required `session_id_returned == HMAC_verified(...)` check never executes.

      class SessionCookie < T::Struct
        extend T::Sig

        SESSION_COOKIE_NAME = "shopify_app_session"

        const :name, String, default: SESSION_COOKIE_NAME
        const :value, String
        const :expires, T.nilable(Time)

        alias_method :eql?, :==
        sig { params(other: T.nilable(SessionCookie)).returns(T::Boolean) }
        def ==(other)
          return false unless other

          name == other.name &&
            value == other.value &&
