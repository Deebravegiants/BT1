### Title
Unbounded residual-balance capture in `ExternalActionSwap.swap`/`LifiExternalAction.callRouter` lets any swap attacker steal stranded token balances beyond `-deltaAmountChanges` - (File: `contracts/external-actions/swaps/ExternalActionSwap.sol`)

### Summary
`ExternalActionSwap.swap` never checks that the amount consumed by the router equals `inputAmount` (the `-deltaAmounts[0]` Hinkal actually delivered for this transaction), and it forwards the *entire* measured `swappedAmount` to `msg.sender`'s own output UTXO. Combined with `approveUnlimited` (`contracts/TransfererBase.sol:32-43`), which leaves a persistent, uncapped ERC20 allowance from the action contract to `router` across transactions, an attacker who supplies their own LI.FI router calldata (`externalActionMetadata`) can make the router pull more `inputToken` than Hinkal transferred them that tx — including any stranded/residual `inputToken` balance left in the contract from a prior transaction — and walk away with the extra swap output as their own UTXO.

### Finding Description
Equality claimed by the invariant: tokens leaving the action contract in a tx == `-deltaAmountChanges` Hinkal sent it that tx.

Trace:
- `Hinkal._externalTransact` (`contracts/Hinkal.sol:234-261`) transfers exactly `uint256(-deltaAmountChanges[i])` of `inputToken` into the action contract before calling `runAction`.
- `ExternalActionSwap.swap` (`contracts/external-actions/swaps/ExternalActionSwap.sol:40-68`) computes `inputAmount = uint256(-deltaAmounts[0])` and calls `callRouter(inputToken, inputAmount, outputToken, externalActionMetadata)`.
- `LifiExternalAction.callRouter` (`contracts/external-actions/swaps/LifiExternalAction.sol:16-36`) never passes `inputAmount` into the router call in a way that is enforced on-chain. It does `approveUnlimited(inputToken, router)` then blindly `router.call(externalActionMetadata)` — the actual amount the router pulls via `transferFrom` is whatever is encoded inside the attacker-supplied `externalActionMetadata`, not `inputAmount`. `swappedAmount` is simply `balanceAfter(outputToken) - balanceBefore(outputToken)`, measured fresh at call time.
- Back in `swap()`, the whole `swappedAmount` (minus fees) is sent to `msg.sender` as `amountToSendToHinkal` (line 91-93) and packaged into the caller's own output UTXO (`stealthAddressStructure: circomData.stealthAddressStructure`, lines 95-101). The only "slippage" check is `require(circomData.slippageValues[1] != 0, ...)` (line 53-56) — it only requires the floor be non-zero; it is never compared against `swappedAmount` or `amountToSendToHinkal`, so nothing on-chain bounds output to input.

`approveUnlimited` (`contracts/TransfererBase.sol:32-43`) only re-approves when the existing allowance drops below `type(uint256).max / 2`, i.e. once any swap for a given `inputToken` has run, the router keeps an effectively infinite, permanent allowance over *whatever balance of that token the action contract holds at any future time*, not just the amount transferred for that specific transaction.

Because dust/residual `inputToken` naturally accumulates in the shared action contract (routers rarely consume 100% of an approved/transferred amount exactly, and nothing here forces full consumption or refund-back-to-user of unspent input), any later, unprivileged attacker can submit their own valid Hinkal transaction (their own UTXOs, their own proof, their own `externalActionMetadata`) where the router calldata specifies an `amountIn` larger than the `inputAmount` Hinkal delivered for that tx. The router, using the pre-existing unlimited allowance, pulls the extra stranded balance too. The resulting inflated `swappedAmount` is entirely attributed to the attacker's own output UTXO, none of it constrained by `-deltaAmountChanges` for that transaction.

None of the existing guards catch this: `performHinkalChecks`/`calldataHash` only prove the attacker's own `externalActionMetadata` matches their own proof (they are entitled to choose it since it's their own transaction); the circuit's `inTotal + amountChanges === outTotal` constrains the shielded UTXO bookkeeping inside the tree, not what the external action contract actually receives/returns externally; `onlyAllowedRecipient` only checks the caller is Hinkal, not that amounts reconcile.

### Impact Explanation
An unprivileged attacker can repeatedly drain any stranded/residual ERC20 balance sitting in the `LifiExternalAction` contract (accumulated dust from imperfect router fills across all users' swaps) into their own shielded output UTXO, capturing value they never deposited. This is direct theft of in-flight/stranded protocol/user funds routed through the action contract — Critical severity per the taxonomy ("direct theft of shielded or in-flight user funds"). It is repeatable every time residual balance accrues, and the attacker's cost is only their own minimal deposit plus gas.

### Likelihood Explanation
Preconditions: (1) some non-zero residual balance of a given `inputToken` exists in the action contract from a prior transaction's imperfect router fill/refund — plausible since nothing forces exact consumption of `inputAmount`; (2) the router (LI.FI diamond) executes attacker-supplied calldata that pulls a larger `amountIn` than `inputAmount` via the pre-existing unlimited allowance — standard aggregator behavior when calldata embeds its own transfer amount. The attacker needs only to deposit a small amount of their own funds, generate a normal proof for their own UTXO, and craft `externalActionMetadata`/router calldata specifying the larger amount — all within the described unprivileged attacker capabilities. Feasibility is high once residual balance exists; exact residual size depends on real router fill behavior, which was not directly testable here.

### Recommendation
- In `LifiExternalAction.callRouter` (and any other `ExternalActionSwap` subclass), snapshot and enforce the `inputToken` balance delta consumed by the router call equals exactly `inputAmount` (revert or refund any excess back to the depositor's UTXO rather than silently leaving/allowing it to be swept), instead of only measuring the `outputToken` delta.
- Replace `approveUnlimited`'s persistent max-allowance pattern for swap routers with a per-call `SafeERC20.forceApprove(router, inputAmount)` set immediately before the call and reset to `0` immediately after, so no allowance persists between transactions.
- Actually enforce `slippageValues[1]` as a real minimum: `require(amountToSendToHinkal >= circomData.slippageValues[1], "slippage")`.

        CircomData calldata circomData,
        int256[] calldata deltaAmounts

        address inputToken = circomData.erc20TokenAddresses[0];
        uint256 inputAmount = uint256(-deltaAmounts[0]);

        if (inputToken == circomData.feeStructure.feeToken) {
            inputAmount -= circomData.feeStructure.flatFee;
        }

        address outputToken = circomData.erc20TokenAddresses[1];

        require(
            circomData.slippageValues[1] != 0,
            "swap output slippage floor not set"
        );

        require(
            block.timestamp <= circomData.timeStamp + SWAP_DEADLINE_WINDOW,
            "swap expired"
        );

        uint256 swappedAmount = callRouter(
            inputToken,
            inputAmount,
            outputToken,
            circomData.externalActionData.externalActionMetadata
        );

        uint256 relayFee = circomData.feeStructure.flatFee;

        uint256 hinkalFee = hinkalHelper.calculateRelayFee(
            swappedAmount,
            0,
            circomData.feeStructure.variableRate
        );

        if (circomData.feeStructure.feeToken == outputToken) {
            sendToRelay(circomData.relay, relayFee + hinkalFee, outputToken);
        } else {
            sendToRelay(
                circomData.relay,
                relayFee,
                circomData.feeStructure.feeToken
            );
            sendToRelay(circomData.relay, hinkalFee, outputToken);
        }

        uint256 totalFee = hinkalFee +
            (outputToken == circomData.feeStructure.feeToken ? relayFee : 0);
        uint256 amountToSendToHinkal = swappedAmount - totalFee;

        transferERC20TokenOrETH(outputToken, msg.sender, amountToSendToHinkal);

        utxoSet = new UTXO[](1);
        utxoSet[0] = UTXO({
            amount: amountToSendToHinkal,
            erc20Address: outputToken,
            stealthAddressStructure: circomData.stealthAddressStructure,
            timeStamp: block.timestamp
        });
    }

    function callRouter(
        address inputToken,
        uint256 inputAmount,
        address outputToken,
        bytes calldata externalActionMetadata
    ) internal override returns (uint256 swappedAmount) {
        uint256 balanceBefore = getERC20OrETHBalance(outputToken);

        if (inputToken == address(0)) {
            (bool success, ) = router.call{value: inputAmount}(
                externalActionMetadata
            );
            require(success, "LI.FI swap failed: native coin");
        } else {
            approveUnlimited(inputToken, router);
            (bool success, ) = router.call(externalActionMetadata);
            require(success, "LI.FI swap failed: erc-20 token");
        }

        swappedAmount = getERC20OrETHBalance(outputToken) - balanceBefore;
    }

    function _externalTransact(
        CircomData calldata circomData
    ) internal returns (UTXO[] memory) {
        require(
            externalActionMap[circomData.externalActionData.externalActionId] ==
                circomData.externalActionData.externalAddress &&
                circomData.externalActionData.externalAddress != address(0),
            "Unknown externalAddress"
        );

        int256[] memory deltaAmountChanges = new int256[](
            circomData.erc20TokenAddresses.length
        );
        for (uint256 i = 0; i < circomData.erc20TokenAddresses.length; i++) {
            deltaAmountChanges[i] = _calculateDeltaAmount(circomData, i);
            if (deltaAmountChanges[i] < 0) {
                transferERC20TokenOrETH(
                    circomData.erc20TokenAddresses[i],
                    circomData.externalActionData.externalAddress,
                    uint256(-deltaAmountChanges[i])
                );
            }
        }

        return
            IExternalActionV2(circomData.externalActionData.externalAddress)
                .runAction(circomData, deltaAmountChanges);
    }
