### Title
Missing wallet-lock guard on `getMnemonic()` allows mnemonic disclosure while wallet is "locked" - (File: features/wallet/module/wallet.js)

### Summary
`Wallet` implements a lock/unlock (Emergency-Stop-style) gate via `#isLocked` / `#assertWalletIsUnlocked()`, and sensitive mutation methods such as `addSeed` and `removeManySeeds` correctly call `await this.#assertWalletIsUnlocked()` before executing. [1](#0-0) [2](#0-1)  However, `getMnemonic()` — the single most sensitive operation in the module, exposing the raw BIP39 secret — never checks `#isLocked` or calls `#assertWalletIsUnlocked()`. It only relies on `#getSeed({ passphrase })` succeeding. [3](#0-2) 

### Finding Description
This is the same bug class as the reported `Crate.sol` issue: an Emergency-Stop-style gate (`whenNotPaused` in Solidity, `#assertWalletIsUnlocked()`/`#isLocked` in `Wallet`) is applied inconsistently — some sensitive functions enforce it, others (`getMnemonic`) do not.

`#getSeed()` decrypts and returns the seed straight from `walletStorage` using the supplied (or auto-generated) `passphrase`, independent of the in-memory `#isLocked` flag: [4](#0-3) 

`getMnemonic()` calls `#getSeed()` directly with no lock check at all: [5](#0-4) 

Compare this to `addSeed()`/`removeManySeeds()`, both of which explicitly gate on `#assertWalletIsUnlocked()` before touching seed material: [6](#0-5) 

Critically, when `config.useAutoGeneratedPassword` is enabled, `#getSeed()` transparently fetches a stored auto-generated passphrase with zero caller-supplied secret: [7](#0-6) 

This means `getMnemonic()` can be invoked and will succeed in returning the plaintext mnemonic even while `wallet.isLocked()` reports `true`, and even with no passphrase argument at all (in the auto-generated-password configuration). `getMnemonic` is exposed unguarded through the public wallet API surface (`exodus.wallet.getMnemonic`) alongside `isLocked`, `lock`, and `unlock`, so any caller with access to that API (e.g., cross-context/UI-side callers, or any code able to reach the exposed `exodus.wallet` object) can retrieve the mnemonic without first unlocking the wallet: [8](#0-7) 

The README documents "locked" as the expected default gate state for wallet operations ("by default a wallet is locked until explicitly unlocked"), reinforcing that `getMnemonic` should honor this invariant like the other seed-mutating operations do: [9](#0-8) 

### Impact Explanation
`getMnemonic()` returns the raw BIP39 mnemonic — the master secret controlling every derived key/address in the wallet. Bypassing the intended "wallet must be unlocked" gate to retrieve this secret is a direct wallet-compromise primitive: any component or process able to invoke this method (without having gone through the deliberate `unlock({ passphrase })` flow) can exfiltrate the seed phrase. This is equivalent in class/severity to the reported `Crate.sol` issue (fund-draining `withdraw/redeem` while paused), except the impact here is total wallet takeover rather than partial fund loss, since seed disclosure exposes all assets across all chains.

### Likelihood Explanation
Likelihood depends on the specific application/config wiring `@exodus/wallet` (i.e., whether `usePassword`/`useAutoGeneratedPassword` are enabled and whether any layer above `Wallet` re-adds a lock check before calling `getMnemonic`). In configurations using `useAutoGeneratedPassword` (no user-supplied secret needed), the call requires no additional input, making exploitation straightforward for any caller who can reach the `wallet.getMnemonic` API entry regardless of `isLocked` state. In configurations requiring `usePassword` with a user-chosen passphrase, an attacker would still need to know/guess that passphrase, lowering (but not eliminating) likelihood, since the passphrase check is only a data-encryption gate, not the same as the wallet's own `isLocked` session gate other methods rely on.

### Recommendation
Add `await this.#assertWalletIsUnlocked()` at the start of `getMnemonic()` (and audit any other sensitive read paths, e.g. `getSeedMetadata`, `getPrimarySeedId`, for the same gap), so that the lock/pause invariant is uniformly enforced across all sensitive wallet operations, matching the pattern already used in `addSeed()` and `removeManySeeds()`.

### Proof of Concept
```js
// Config: usePassword=true, useAutoGeneratedPassword=true (or usePassword=false)
await exodus.wallet.create({ passphrase: undefined }) // wallet stores auto-generated passphrase
await exodus.wallet.lock()
await exodus.wallet.isLocked() // true - wallet believes it is locked/protected

// No unlock() call was made, yet the mnemonic can still be extracted:
const mnemonic = await exodus.wallet.getMnemonic()
// mnemonic is the plaintext BIP39 seed phrase, disclosed despite isLocked() === true
``` [10](#0-9)

  isLocked = async () => this.#isLocked

  lock = async () => {
    this.#keychain.removeAllSeeds()

    this.#isLocked = true
  }

  unlock = async ({ passphrase } = {}) => {
    try {
      const { seed } = await this.#getSeed({ passphrase })
      const primarySeedId = await this.#keychain.addSeed(seed)
      this.#primarySeedIdAtom.set(primarySeedId)

      const extraSeeds = await this.#getExtraSeeds()
      await Promise.all(extraSeeds.map(({ seed }) => this.#keychain.addSeed(seed)))

      this.#isLocked = false

      return { primarySeedId }
    } catch (err) {
      this.#logger.debug('unlock() failed: wrong password', err)
      throw new Error('Wrong password. Try again.')
    }
  }

  getMnemonic = async ({ passphrase, seedId } = {}) => {
    try {
      // always need to get primary seed first to make sure the user entered the right passphrase
      // even if passed seedId is not primary
      const { mnemonic } = await this.#getSeed({ passphrase })
      if (!mnemonic) throw new Error('Wrong password. Try again.')

      if (!seedId || (await this.getPrimarySeedId()) === seedId) return mnemonic

      // Sequential, as sync fallback is slower
      for (const seed of await this.#getExtraSeeds()) {
        if (seedId !== (await getSeedId(seed.seed))) continue
        if (!seed.mnemonic) throw new Error('No mnemonic found for seedId.')
        return seed.mnemonic
      }

      throw new Error('No seed matches seedId.')
    } catch (err) {
      if (err.message === 'No seed matches seedId.') {
        this.#logger.debug('getMnemonic() failed: no seed matches seedId.')
        throw err
      }

      this.#logger.debug('getMnemonic() failed: wrong password')
      throw new Error('Wrong password. Try again.')
    }
  }
