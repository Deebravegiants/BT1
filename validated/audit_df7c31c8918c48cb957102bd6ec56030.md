### Title
Session ID cookie is trusted as an opaque, unauthenticated session-storage key with no binding to the requester - ([File: lib/shopify_api/utils/session_utils.rb])

### Summary
For non-embedded apps, `ShopifyAPI::Utils::SessionUtils.current_session_id` resolves the "current session" purely from the raw value of the `shopify_app_session` cookie, with no cryptographic binding proving that the browser presenting the cookie is the one for which OAuth was completed. Because session IDs are constructed from public, guessable values (`"offline_#{shop}"` or `"#{shop}_#{user_id}"`), an unprivileged attacker can set this cookie value on their own request to name a *different* merchant's session and have the host application look up and use that merchant's access token, exactly analogous to the report's root cause: a value is trusted/acted upon without being bound to the identity check that is supposed to authorize it.

### Finding Description
`SessionUtils.cookie_session_id` simply returns the browser-supplied cookie content verbatim: [1](#0-0) 

`current_session_id` uses this raw value directly as the session identifier for non-embedded apps (and as a fallback for embedded apps without a JWT): [2](#0-1) 

This cookie is populated by `Oauth.validate_auth_callback` with `session.id`, which is deterministically derived: `"offline_#{shop}"` for offline sessions or `"#{shop}_#{associated_user.id}"` for online sessions: [3](#0-2) 

The cookie itself is a plain, unsigned value (no HMAC, no server-side binding token): [4](#0-3) [5](#0-4) 

The gem's own documentation confirms this is the intended, documented usage pattern (not a case of the host app deviating from the API): [6](#0-5) 

**Identity binding broken (as an equality):** the code implicitly assumes `session_id_presented_in_cookie == session_id_the_browser_actually_completed_oauth_for`. Because the cookie value is never verified against anything the server independently controls (no signature, no server-side session table entry check at this layer, no binding to the shop or user actually authenticated in this request), that equality does not hold — any bytes an attacker chooses to set as the cookie satisfy the check.

### Impact Explanation
Since `shop` domains are public (they are visible in app-install URLs, App Store links, or via storefront `X-Shopify-*` metadata) and offline session IDs are simply `"offline_#{shop}"`, an attacker can trivially construct the session ID string for a target merchant. If the host application (following this gem's documented pattern) uses `current_session_id` to fetch a session from its storage and then makes authenticated Admin API calls on the caller's behalf using that session's access token, an attacker who sets the `shopify_app_session` cookie to `offline_victim-shop.myshopify.com` on their own outbound request can cause the app to act using the victim shop's access token — a cross-tenant access / access-token misuse impact, matching the report's "attacker manipulates state to divert real value intended for a legitimate binding to themselves."

### Likelihood Explanation
High: exploitation requires no secrets, no privileged account, and no interaction with Shopify's servers — only knowledge of the target shop's `myshopify.com` domain (public) and the ability to set an HTTP cookie header, both trivially available to any unprivileged internet user interacting with the host app's endpoints that rely on this documented gem API.

### Recommendation
Do not treat the session-id cookie as self-authenticating. Bind the cookie to the actual authenticated context, for example by:
- Signing/HMAC-ing the cookie value with the app's secret so it cannot be forged or repurposed to reference another shop's session, and validating that signature in `SessionUtils.cookie_session_id`.
- Alternatively, storing only an opaque, unguessable, server-generated session identifier in the cookie (unrelated to `shop`/user id), and looking up the shop/session server-side by that opaque key.
- Requiring the caller to independently prove which shop's session it is requesting (e.g. corroborate with a signed OAuth state or JWT `dest` claim) before trusting a session id derived from cookies alone.

### Proof of Concept
```ruby
# Attacker knows only the victim's public shop domain, e.g. "victim-shop.myshopify.com"

forged_cookie_value = "offline_victim-shop.myshopify.com"

cookies = { ShopifyAPI::Auth::Oauth::SessionCookie::SESSION_COOKIE_NAME => forged_cookie_value }

session_id = ShopifyAPI::Utils::SessionUtils.current_session_id(nil, cookies, false)
# => "offline_victim-shop.myshopify.com"

# The host application (per documented usage) now loads a Session from its
# storage using this attacker-chosen ID and uses its access_token for
# subsequent Admin API calls made on the attacker's behalf, e.g.:
#
#   session = MyApp::SessionRepository.load_session(session_id)
#   ShopifyAPI::Context.activate_session(session)
#   ShopifyAPI::Clients::Rest::Admin.new(session: session).get(path: "orders")
#
# No access token, api_secret_key, or Shopify-side interaction was required —
# only the ability to set an HTTP cookie and knowledge of the target shop's
# public domain name.
```

        def current_session_id(shopify_id_token, cookies, online)
          if Context.embedded?
            if shopify_id_token
              id_token = shopify_id_token.gsub("Bearer ", "")
              session_id_from_shopify_id_token(id_token: id_token, online: online)

            raise Errors::CookieNotFoundError, "Session cookie not found for app" unless
              cookies && cookies[Auth::Oauth::SessionCookie::SESSION_COOKIE_NAME]

          end
        end

**File:** docs/getting_started.md (L47-52)
```markdown
#### Cookie
Cookie based authentication is not supported for embedded apps due to browsers dropping support for third party cookies due to security concerns. Non-embedded apps are able to use cookies for session storage/retrieval.

For *non-embedded* apps, you can pass the cookies into:
 - `ShopifyAPI::Utils::SessionUtils.current_session_id(nil, cookies, true)` for online (user) sessions or
 - `ShopifyAPI::Utils::SessionUtils.current_session_id(nil, cookies, false)` for offline (store) sessions.
```
