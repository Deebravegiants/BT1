## Custody Analog Found: Atomic Multi-Shareholder Coin Distribution Can Be Permanently Blocked by a Single Unregistered/Opted-Out Recipient

### Title
Single griefing shareholder can permanently block `vesting::distribute()`/`terminate_vesting_contract()` and `staking_contract::distribute_internal()`, locking all shareholders' unlocked stake — (File: `aptos-move/framework/aptos-framework/sources/vesting.move`, `aptos-move/framework/aptos-framework/sources/staking_contract.move`)

### Summary
The external report's core custody invariant is: *a settlement function that atomically pays out multiple parties in one call must not be able to be blocked entirely by one party's inability/refusal to receive funds, and there must be a pull-based fallback.* The Aptos-native analog is `vesting::distribute()` [1](#0-0)  and `staking_contract::distribute_internal()` [2](#0-1) , both of which loop over a fixed shareholder list and call `aptos_account::deposit_coins` for each recipient inside a single atomic transaction, with no per-shareholder pull mechanism.

### Finding Description
`distribute()` withdraws all inactive/pending-inactive stake into a single `Coin<AptosCoin>` value, then iterates every shareholder in the pool and calls `aptos_account::deposit_coins(recipient_address, share_of_coins)` [3](#0-2) . `deposit_coins` aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS` if the recipient is not registered for the coin type and has explicitly opted out via `can_receive_direct_coin_transfers` [4](#0-3) , which is controlled by `DirectTransferConfig.allow_arbitrary_coin_transfers`, itself settable by any account owner via `set_allow_direct_coin_transfers` [5](#0-4) .

Because Move transactions are atomic, an abort mid-loop reverts the entire `distribute()` call — including the withdrawal from the stake pool — leaving every shareholder's inactive/pending-inactive stake locked in the contract, non-distributable. Critically, `terminate_vesting_contract()` unconditionally calls `distribute(contract_address)` as its first step before doing anything else (including the admin check) [6](#0-5) . If `distribute()` aborts, `terminate_vesting_contract()` also aborts, so the admin has no override path to force termination and recovery. `admin_withdraw()` similarly requires the contract to already be in `VESTING_POOL_TERMINATED` state, which is unreachable if termination itself is blocked [7](#0-6) .

The shareholder list itself cannot be modified by anyone once a `VestingContract`/`StakingContract` is created — shares are fixed at creation, so a single non-cooperative shareholder (who sets `allow_arbitrary_coin_transfers = false` on their own account and never registers a `CoinStore<AptosCoin>`) permanently blocks distribution/termination for every other shareholder in the same pool, with no pull-based fallback such as a `postpone`/`claim` function comparable to `returnPostponedCollateral()` in the Solidity report.

### Impact Explanation
This breaks the custody invariant that resource-account-held stake rewards/vesting grants must remain recoverable by their rightful, cooperative owners. A single uncooperative or malicious shareholder can cause a permanent, non-recoverable lock of APT (AptosCoin) held by the vesting contract's/staking pool's resource account for all shareholders — up to `MAXIMUM_SHAREHOLDERS` (30) parties per pool [8](#0-7) . Because the admin's only exit path (`terminate_vesting_contract` → `admin_withdraw`) also depends on a successful `distribute()`, there is no privileged recovery mechanism either. This satisfies the custody gate's "permanent lock or non-recoverable loss of ... resource-account-held value."

### Likelihood Explanation
Whether this is practically reachable depends on one unverified detail: whether `coin::is_account_registered<AptosCoin>` is bypassed (always returns true) as part of the coin-to-fungible-asset migration for `AptosCoin` specifically, which would neutralize the `can_receive_direct_coin_transfers` check inside `aptos_account::deposit_coins` for this coin type. I was unable to confirm the current implementation of `coin::is_account_registered`/`coin::register` for the post-migration `AptosCoin` path within the available index, so I cannot state with certainty that the abort is currently reachable in production for `AptosCoin`. If the migration indeed short-circuits this check for `AptosCoin`, this specific finding does not hold today, though the structural design flaw (no pull-based fallback, atomic all-or-nothing multi-party settlement, admin recovery path gated on the same call) remains present in the code and would become exploitable for any coin type where the registration/opt-out check is enforced.

### Recommendation
- Verify whether `deposit_coins`'s registration/opt-out check is actually enforced for `AptosCoin` after FA migration; if so, this is directly exploitable.
- Regardless, redesign `distribute()`/`distribute_internal()` to not depend on every shareholder's deposit succeeding in the same atomic call — e.g., accumulate each shareholder's owed amount in per-shareholder storage and let each shareholder pull their own funds (as recommended in the original report), decoupling one recipient's failure from others' ability to claim.
- Decouple `terminate_vesting_contract()`'s termination/state-transition logic from a successful `distribute()` call so an admin can still transition state and eventually allow recovery even if one shareholder's payout cannot currently be completed.

### Proof of Concept
1. Admin creates a vesting contract (or staking contract) with shareholders `A`, `B`, `C`, none registered for `CoinStore<AptosCoin>` beyond default account creation.
2. Shareholder `C` calls `aptos_account::set_allow_direct_coin_transfers(C, false)` on their own account — a fully permissionless, unprivileged action.
3. Stake pool earns rewards; `unlock_rewards`/`vest` unlocks funds; lockup period passes so funds become withdrawable.
4. Anyone calls `vesting::distribute(contract_address)`. The loop reaches shareholder `C`; `aptos_account::deposit_coins` finds `C` unregistered and opted out, aborting with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`, reverting the entire transaction — `A` and `B` receive nothing, and the withdrawn stake is rolled back into the pool state.
5. Admin calls `terminate_vesting_contract(admin, contract_address)`, which also calls `distribute(contract_address)` first and aborts identically — admin cannot terminate or later `admin_withdraw` to recover shareholder `A`'s or `B`'s funds.

    public entry fun distribute(contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        let coins = withdraw_stake(vesting_contract, contract_address);
        let total_distribution_amount = coin::value(&coins);
        if (total_distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        // Distribute coins to all shareholders in the vesting contract.
        let grant_pool = &vesting_contract.grant_pool;
        let shareholders = &grant_pool.shareholders();
        shareholders.for_each_ref(|shareholder| {
            let shareholder = *shareholder;
            let shares = pool_u64::shares(grant_pool, shareholder);
            let amount = pool_u64::shares_to_amount_with_total_coins(grant_pool, shares, total_distribution_amount);
            let share_of_coins = coin::extract(&mut coins, amount);
            let recipient_address = get_beneficiary(vesting_contract, shareholder);
            aptos_account::deposit_coins(recipient_address, share_of_coins);
        });

        // Send any remaining "dust" (leftover due to rounding error) to the withdrawal address.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(vesting_contract.withdrawal_address, coins);
        } else {
            coin::destroy_zero(coins);
        };

        emit(
            Distribute {
                admin: vesting_contract.admin,
                vesting_contract_address: contract_address,
                amount: total_distribution_amount,
            },
        );
    }

    fun distribute_internal(
        staker: address,
        operator: address,
        staking_contract: &mut StakingContract,
    ) acquires BeneficiaryForOperator {
        let pool_address = staking_contract.pool_address;
        // Create the Staker resource if it doesn't exist to backfill the Staker resource for each pool.
        if (!exists<Staker>(pool_address)) {
            let pool_signer =
                &account::create_signer_with_capability(&staking_contract.signer_cap);
            move_to(pool_signer, Staker { staker });
        };
        let (_, inactive, _, pending_inactive) = stake::get_stake(pool_address);
        let total_potential_withdrawable = inactive + pending_inactive;
        let coins =
            stake::withdraw_with_cap(
                &staking_contract.owner_cap, total_potential_withdrawable
            );
        let distribution_amount = coin::value(&coins);
        if (distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        let distribution_pool = &mut staking_contract.distribution_pool;
        update_distribution_pool(
            distribution_pool,
            distribution_amount,
            operator,
            staking_contract.commission_percentage
        );

        // Buy all recipients out of the distribution pool.
        while (distribution_pool.shareholders_count() > 0) {
            let recipients = distribution_pool.shareholders();
            let recipient = recipients[0];
            let current_shares = distribution_pool.shares(recipient);
            let amount_to_distribute =
                distribution_pool.redeem_shares(recipient, current_shares);
            // If the recipient is the operator, send the commission to the beneficiary instead.
            if (recipient == operator) {
                recipient = beneficiary_for_operator(operator);
            };
            aptos_account::deposit_coins(
                recipient, coin::extract(&mut coins, amount_to_distribute)
            );

            emit(
                Distribute {
                    operator,
                    pool_address,
                    recipient,
                    amount: amount_to_distribute
                }
            );
        };

        // In case there's any dust left, send them all to the staker.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(staker, coins);
            distribution_pool.update_total_coins(0);
        } else {
            coin::destroy_zero(coins);
        }
    }

    /// Set whether `account` can receive direct transfers of coins that they have not explicitly registered to receive.
    public entry fun set_allow_direct_coin_transfers(
        account: &signer, allow: bool
    ) acquires DirectTransferConfig {
        let addr = signer::address_of(account);
        if (exists<DirectTransferConfig>(addr)) {
            let direct_transfer_config = borrow_global_mut<DirectTransferConfig>(addr);
            // Short-circuit to avoid emitting an event if direct transfer config is not changing.
            if (direct_transfer_config.allow_arbitrary_coin_transfers == allow) { return };

            direct_transfer_config.allow_arbitrary_coin_transfers = allow;

            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
        } else {
            let direct_transfer_config = DirectTransferConfig {
                allow_arbitrary_coin_transfers: allow,
                update_coin_transfer_events: new_event_handle<
                    DirectCoinTransferConfigUpdatedEvent>(account)
            };
            emit(
                DirectCoinTransferConfigUpdated {
                    account: addr,
                    new_allow_direct_transfers: allow
                }
            );
            move_to(account, direct_transfer_config);
        };
    }
