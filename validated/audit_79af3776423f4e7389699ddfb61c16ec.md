### Title
Missing L2 Sequencer Uptime Check in SimplexPaymaster's Chainlink Price Feeds on Arbitrum/Optimism - (File: evm/src/utils/SimplexPaymaster.sol)

### Summary
`SimplexPaymaster` is deployed on Arbitrum and used by the Optimism-family stack, and prices every gas-sponsored ERC-20 fee token purely from `AggregatorV3Interface.latestRoundData()`, checking only for a non-positive answer and a maximum staleness window against `updatedAt`. It never queries a Chainlink L2 sequencer-uptime feed, so if the Arbitrum/Optimism sequencer goes down and later resumes, the first fresh `updatedAt` timestamp after resumption can pass the staleness check while the underlying price used for that round may still reflect market conditions from before or during the outage, letting sponsored UserOps be priced off unreliable data during the grace period recommended by Chainlink.

### Finding Description
`_getOraclePrice` is the sole gate on price freshness for both `nativeOracle` and every registered `TokenConfig.tokenOracle`: it reverts only on `answer <= 0` or `block.timestamp - updatedAt > maxOracleAge`. [2](#0-1)  This function backs `_tokenPrice`, which is invoked from the unprivileged, per-UserOp `_fetchDetails` hook that every bundler-submitted `UserOperation` triggers during `validatePaymasterUserOp`. [3](#0-2)  `_getOraclePrice` is also used by the treasury-only `swapAndDeposit` to compute `amountOutMin`, but the paymaster-charging path via `_fetchDetails`/`_prefund` is reachable by any account submitting a sponsored UserOp through the standard ERC-4337 bundler flow — no privileged role is required to trigger a price read. [4](#0-3) 

Chainlink's own guidance for Arbitrum/Optimism deployments is to additionally check a `SequencerUptimeFeed` (and enforce a grace period after resumption) precisely because a Chainlink Data Feed's `updatedAt` can look "fresh" immediately after the sequencer restarts even though the price it reports may not reflect a legitimate, timely market update during the outage window. `SimplexPaymaster` implements none of this: there is no `sequencerUptimeFeed`, `GRACE_PERIOD`, or `isSequencerUp`-style check anywhere in the contract or the rest of the repo (confirmed via repo-wide search).

### Impact Explanation
Because `_tokenPrice` directly determines `tokenPrice`, which feeds `_erc20Cost` and thus `prefundAmount`/the ERC-20 amount pulled from the UserOp's sender via `transferFrom` or Permit2 in `_prefund`, a stale-but-"fresh-looking" price during/after an Arbitrum or Optimism sequencer outage can misprice how much ERC-20 the sender is charged relative to native gas. [5](#0-4)  An attacker who can predict or race a sequencer resumption (or exploit any window where the reported round is fresh by timestamp but priced off stale/instantaneously-resumed data) could submit sponsored UserOps that undercharge their ERC-20 relative to the native gas the paymaster fronts, draining the paymaster's EntryPoint deposit/token reserves over repeated sponsored operations — a fund-drain vector against the paymaster's treasury-controlled reserves.

### Likelihood Explanation
This requires an actual Arbitrum or Optimism sequencer downtime/restart event, which is an infrequent but historically recurring occurrence on both networks. During such an event, any unprivileged bundler/user submitting a sponsored UserOp automatically exercises the vulnerable pricing path — no special permissions, governance compromise, or malicious insider is needed, matching the reachable, unprivileged-message-dispatcher class this scan targets.

### Recommendation
Add Chainlink's recommended `SequencerUptimeFeed` check to `_getOraclePrice` (or a wrapper called before pricing) on Arbitrum and Optimism deployments: read the uptime feed's `latestRoundData()`, revert if `answer == 1` (sequencer down), and additionally revert/pause pricing until `block.timestamp - startedAt` exceeds a configured grace period after the sequencer comes back up, mirroring Chainlink's documented L2 pattern.

### Proof of Concept
1. Arbitrum's sequencer goes offline for an extended period; during this time L2 blocks/timestamps may stall or later jump forward once the sequencer resumes.
2. Once the sequencer resumes, the underlying Chainlink price feed posts a new round with a fresh `updatedAt` timestamp that satisfies `block.timestamp - updatedAt <= maxOracleAge` in `_getOraclePrice`. [6](#0-5) 
3. An attacker (or the attacker's own solver/bundler) immediately submits a sponsored `UserOperation` using the SimplexPaymaster on Arbitrum (deployed at `0x7281Bccb4f0BCE44F3B8542d1fC5e51c2F5fC08C`). [7](#0-6) 
4. `_fetchDetails` computes `tokenPrice` from `_tokenPrice`/`_getOraclePrice` using this just-resumed round, which passes the staleness check without any sequencer-uptime validation, and the ERC-20 amount charged in `_prefund` is derived from this potentially unreliable price, letting the attacker's sponsored op be undercharged relative to the native gas actually consumed. [8](#0-7)

    ///
    ///      PaymasterERC20 computes `erc20Cost = weiCost * tokenPrice / 1e18`,
    ///      so tokenPrice must be token base units per wei, scaled by 1e18:
    ///        tokenPrice = (nativeUsd * 10^tokenDecimals) / tokenUsd
    ///      e.g. BNB at $600, USDC at $1 with 6 decimals: 0.001 BNB (1e15 wei)
    ///      should cost 0.60 USDC (600000 units), giving tokenPrice = 6e8, which
    ///      is exactly (600e8 * 1e6) / 1e8. Markup is applied on top.
    function _fetchDetails(
        PackedUserOperation calldata userOp,
        bytes32 /* userOpHash */
    )
        internal
        view
        override
        returns (uint256 validationData, IERC20 token, uint256 tokenPrice)
    {
        bytes calldata data = userOp.paymasterData();
        if (data.length < 21) revert InvalidPaymasterData(data.length);

        uint8 mode = uint8(data[0]);
        if (mode != 0x00 && mode != 0x02) revert InvalidMode(mode);

        address tokenAddr = address(bytes20(data[1:21]));

        TokenConfig memory cfg = tokenConfigs[tokenAddr];
        if (address(cfg.tokenOracle) == address(0)) revert TokenNotRegistered(tokenAddr);
        if (!cfg.active) revert TokenNotActive(tokenAddr);

        tokenPrice = _tokenPrice(cfg);
        token = IERC20(tokenAddr);

    function _tokenPrice(TokenConfig memory cfg) internal view returns (uint256) {
        uint256 nativeUsd = _getOraclePrice(nativeOracle, nativeOracleDecimals);
        uint256 tokenUsd = _getOraclePrice(cfg.tokenOracle, cfg.tokenOracleDecimals);

        return (nativeUsd * (10 ** cfg.tokenDecimals) * (10_000 + markupBps)) / (tokenUsd * 10_000);
    }

    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
