### Title
Attacker-controlled route XDR injects arbitrary contract invocations beneath the caller's authorization, enabling wallet draining through `swap_collateral`/`multiply`/`swap_debt`/`repay_debt_with_collateral` and direct `execute_strategy` — (`contracts/controller/src/strategies/swap.rs`, `contracts/swap-aggregator/src/venues/mod.rs`)

### Summary
The external report describes shell-command injection: untrusted RSS item text is interpolated into an OS command, producing user-assisted code execution. The analog on this codebase is XDR/route-data injection into the invocation context: the `swap` bytes argument of controller strategy verbs (and of `execute_strategy` directly) is fully attacker-controlled XDR that names arbitrary `assets` registry entries — token and "pool" contract addresses — which the router then invokes via `env.invoke_contract` with no allowlist. A maliciously crafted route places attacker-deployed contract code on the call stack below the victim's `require_auth`, where it can call `token.transfer(victim, attacker, …)`; simulation records that transfer as a child of the victim's own authorization entry, and if the victim signs the simulated tree, the wallet transfer executes — the same "user-assisted code execution" shape as CVE-2017-12904.

### Finding Description
- `swap_tokens` in `contracts/controller/src/strategies/swap.rs:13-38` forwards the caller-supplied `swap: StrategySwap` bytes verbatim to `router.execute_strategy` after authorizing only the exact input transfer. Nothing in the controller inspects which contracts the route will call.
- The router's `StrategyPayload.assets` registry (`contracts/swap-aggregator/src/types.rs`) lets each hop name an arbitrary `pool` address, and venue adapters dispatch `env.invoke_contract(&ctx.hop.pool, "swap"/"swap_exact_amount_in", …)` — e.g. Phoenix at `contracts/swap-aggregator/src/venues/phoenix.rs:23-25` and Comet at `contracts/swap-aggregator/src/venues/comet.rs:30-34`. There is no venue or pool allowlist.
- `docs/explanation/threat-model.md:154-165` states the consequence directly: a route "can put third-party code on the call stack below the caller's authorization"; a token transfer that such code makes from the caller "executes if the caller signs that tree", and "the loss is then the caller's wallet, not the routed amount, and neither the payload minimum nor the final risk gate bounds it."
- The harness test `tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs` proves it end-to-end through `swap_collateral`: a `RogueHopPool` contract named by the payload's `hop_pool` calls `token::Client::transfer(alice → attacker, WALLET_BALANCE)` for a token the protocol never listed; `simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry` shows the stolen transfer attached under Alice's `swap_collateral` auth entry (lines 194-227), and `enforced_auth_moves_the_wallet_token_only_when_the_signed_tree_lists_the_rogue_transfer` shows the signed poisoned tree executes the drain (lines 229-269).

### Impact Explanation
Theft of user funds. A victim who signs a route that traverses a rogue pool loses arbitrary balances of arbitrary tokens held in their wallet — unbounded by the routed `amount_in`, the route's `min_out`, or the controller's `RouterOverspend`/`NoSwapOutput` checks, all of which measure only the swap's own input/output tokens. The same vector applies to standalone `execute_strategy` callers.

### Likelihood Explanation
User-assisted, like the CVE: the theft executes only if the victim signs the authorization tree that simulation returns without checking for unexpected children (wallets sign recorded trees; an honest route produces either no child for a composed call or exactly one input transfer for a direct swap). An attacker can serve poisoned `routeXdr` through any compromised or malicious quote source; the victim's transaction still appears to execute correctly — fair output is paid — while the wallet drain rides along. This requires social/UI-level deception or a malicious quote path, so likelihood is below an autonomous exploit but the loss is total for any token held by the signer.

### Recommendation
Enforce a venue/pool allowlist: constrain `assets` entries used as `pool` in dispatch to governance-approved venue addresses (or pin venue contract addresses per opcode), so a route cannot name attacker-deployed code. Short of that, clients must decode `routeXdr`, enumerate every contract the route will invoke, and refuse any signature request whose authorization tree contains children beyond the single expected input transfer — the check `verifyRouteBytes`/`verifyRoutePayload` in `skills/xoxno-swap-aggregator/payload.md` performs partially but does not inspect the signed auth tree.

### Proof of Concept
1. Attacker deploys a contract `RogueHopPool` exposing `swap()` which calls `token::Client::transfer(&victim, &attacker, &victim_balance)` on an unrelated wallet token (see `RogueHopPool` at `tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs:51-72`).
2. Attacker serves the victim a `routeXdr` (e.g., via a malicious or compromised quote endpoint) whose `assets` registry contains `RogueHopPool` as a hop `pool`, with a legitimate `token_in`/`token_out`/`min_out` so the route still pays out.
3. Victim calls `controller.swap_collateral(caller=victim, account_id, current, amount, new, swap=routeXdr)` (or `execute_strategy` directly). Simulation records `token.transfer(victim → attacker, wallet_balance)` as a child of the victim's auth entry.
4. Victim signs the simulated tree; the host executes the rogue transfer. Victim's entire wallet-token balance moves to the attacker while the swap still returns fair output (asserted at lines 224-226 and 265-268 of the test).

Mitigating controls already present (`authorize_transfer_as_current` exact-amount grant at `swap.rs:34`, `with_flash_guard` reentry guard, measured balance deltas at `swap.rs:42-54`) bound only the routed amount and are bypassed by design for this vector, as documented at `threat-model.md:154-165`.
