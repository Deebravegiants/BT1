### Title
No vulnerability found

### Summary
The proposed exploit path is not reachable because lamport mutation of any account (writable or not) is gated by `is_writable()` at the point of mutation, not merely checked afterward via the aggregate sum.

### Finding Description
The premise requires an account "not declared writable in the message" to have its lamports moved by a builtin program via CPI reentry, while the sum-based invariant fails to detect it because it excludes non-writable accounts. This premise is false on two counts. First, `transaction_accounts_lamports_sum` sums lamports over the *entire* `accounts: Vec<KeyedAccountSharedData>` array (all accounts referenced by `tx.account_keys()`, both writable and read-only), not just the writable subset, as seen in `svm/src/transaction_processor.rs` lines 1052-1061 and 1184-1188. So any lamport creation/destruction anywhere in the loaded account set would still be captured in `lamports_before_tx` vs. the post-execution sum. Second, and more fundamentally, `BorrowedInstructionAccount::set_lamports` in `transaction-context/src/instruction_accounts.rs` lines 120-128 explicitly rejects any lamport change on a non-writable account with `InstructionError::ReadonlyLamportChange`, regardless of caller (including builtins and reentrant CPI). This check is enforced at every single lamport mutation call site (`checked_add_lamports`/`checked_sub_lamports` both route through `set_lamports`), so there is no way for a builtin (System program or otherwise) to mutate lamports on an account not marked writable in the instruction's `InstructionAccount` metadata, which itself derives from the sanitized message's writable-account set. [1](#0-0) [2](#0-1) [3](#0-2) 

`touched_flags` is a bookkeeping mechanism for selective commit optimization (skipping unmodified writable accounts during `account_saver::collect_accounts_to_store`), not a security boundary for the lamport-conservation invariant — it is orthogonal to `transaction_accounts_lamports_sum`, which operates on the full `accounts` array independent of the touched state. [4](#0-3) 

### Impact Explanation
No exploitable impact: the described bypass path does not exist because the write-lock/writable-flag check at the account-mutation layer (`set_lamports`) independently and unconditionally prevents lamport changes on non-writable accounts, before any sum-based check is even reached.

### Likelihood Explanation
Not applicable — the precondition ("message declares fewer writable accounts than actually mutated via reentrant CPI") cannot be satisfied because the runtime enforces writability at the point of every lamport mutation, not just at commit time.

    /// Overwrites the number of lamports of this account (transaction wide)
    pub fn set_lamports(&mut self, lamports: u64) -> Result<(), InstructionError> {
        // An account not owned by the program cannot have its balance decrease
        if !self.is_owned_by_current_program() && lamports < self.get_lamports() {
            return Err(InstructionError::ExternalAccountLamportSpend);
        }
        // The balance of read-only may not change
        if !self.is_writable() {
            return Err(InstructionError::ReadonlyLamportChange);
        }
        // don't touch the account if the lamports do not change
        let old_lamports = self.get_lamports();
        if old_lamports == lamports {
            return Ok(());
        }

        let lamports_balance = (lamports as i128).saturating_sub(old_lamports as i128);
        self.transaction_context
            .accounts
            .add_lamports_delta(lamports_balance)?;

        self.touch()?;
        self.account.set_lamports(lamports);
        Ok(())
    }

fn collect_accounts_for_successful_tx<'a, T: SVMMessage>(
    collected_accounts: &mut Vec<(&'a Pubkey, &'a AccountSharedData)>,
    collected_account_transactions: &mut Option<Vec<&'a SanitizedTransaction>>,
    transaction: &'a T,
    transaction_ref: Option<&'a SanitizedTransaction>,
    transaction_accounts: &'a [KeyedAccountSharedData],
    touched_flags: &[bool],
) {
    for (i, (address, account)) in (0..transaction.account_keys().len()).zip(transaction_accounts) {
        if !transaction.is_writable(i) {
            continue;
        }

        // Skip write-locked accounts the transaction left unmodified.
        if !touched_flags[i] {
            continue;
        }

        // Accounts that are invoked and also not passed as an instruction
        // account to a program don't need to be stored because it's assumed
        // to be impossible for a committable transaction to modify an
        // invoked account if said account isn't passed to some program.
        if transaction.is_invoked(i) && !transaction.is_instruction_account(i) {
            continue;
        }

        collected_accounts.push((address, account));
        if let Some(collected_account_transactions) = collected_account_transactions {
            collected_account_transactions
                .push(transaction_ref.expect("transaction ref must exist if collecting"));
        }
    }
}
