Audit Report

## Title
Gateway's legacy web-API-trigger handler forwards attacker-controlled requests to all DON nodes without an allowlist/rate-limit check - ([File: core/services/gateway/handlers/capabilities/handler.go])

## Summary
`handler.HandleLegacyUserMessage` validates only payload shape, method name, and message staleness before converting the message to a request and broadcasting it to every DON member via `don.SendToNode`, and registering a pending callback in `h.savedCallbacks`. The code contains an explicit `// TODO: apply allowlist and rate-limiting here` comment immediately before the method check, confirming the missing authorization gate is a known, unimplemented gap rather than a misread of intended behavior.

## Finding Description
`HandleLegacyUserMessage` decodes the JSON payload, rejects zero timestamps, rejects stale messages, and rejects non-`web_api_trigger` methods, but performs no check of `msg.Body.Sender` against any DON-configured allowlist before proceeding: [1](#0-0) . After these checks it builds the request and unconditionally fans it out to every DON member: [2](#0-1) .

The message's `Sender` field is cryptographically derived from the signature during `Message.Validate()` [3](#0-2) , but any actor can generate their own ECDSA keypair and sign a well-formed message — signature validity alone proves nothing about authorization to submit `web_api_trigger` requests to a given DON.

By contrast, the sibling capability-trigger path that processes the same `MethodWebAPITrigger` payload (`triggerConnectorHandler.processTrigger` in `core/capabilities/webapi/trigger/trigger.go`) explicitly enforces a per-topic `allowedSenders` allowlist and a per-sender rate limiter before accepting the trigger, demonstrating that this check is a recognized security requirement for this exact message type that was simply never implemented in the legacy gateway-side handler. The gap is also independently acknowledged in the handler's own test suite: `// TODO: Validate Senders and rate limit check, pending question in trigger about where senders and rate limits are validated` [4](#0-3) , and the accompanying test only verifies that *invalid* (parse-error/stale/bad-method) messages don't leave dangling callbacks, never that unauthorized senders are rejected [5](#0-4) .

This is a real, unaddressed break of the intended trust boundary: any client able to reach the gateway's legacy-message endpoint for a DON configured with this handler can broadcast crafted trigger requests to all DON members and consume `h.savedCallbacks` slots without passing any sender/topic authorization.

## Impact Explanation
This maps to an in-scope "gateway request impersonation / allowlist bypass" category: an unauthorized sender can force the gateway to relay attacker-controlled `web_api_trigger` payloads to every node in the DON and occupy callback-table capacity meant to be gated by allowlist/rate-limit enforcement. Because `don.SendToNode` is called for every DON member per accepted message, this also creates DON-wide resource consumption (and, combined with `defaultMaxSavedCallbacks`/pruning logic, a callback-table exhaustion vector) driven entirely by unauthorized senders.

## Likelihood Explanation
Likelihood is high: no privileged key or credential is required — an attacker only needs to generate an ECDSA keypair, sign a well-formed message body with method `web_api_trigger` and a fresh timestamp, and submit it through the gateway's legacy user-message path. The missing check is explicitly flagged in code (`TODO`) and in the existing test suite as a known, open item, confirming this is not a hypothetical or already-mitigated gap.

## Recommendation
Implement the sender/topic allowlist and per-sender rate-limiting check in `HandleLegacyUserMessage` before constructing `req` or touching `h.savedCallbacks`/`don.SendToNode`, mirroring `triggerConnectorHandler.processTrigger`'s `allowedSenders` + `rateLimiter.Allow` pattern in `core/capabilities/webapi/trigger/trigger.go`. Reject unauthorized/rate-limited senders with an error response before any DON fan-out or callback registration occurs.

## Proof of Concept
1. Instantiate the handler as in `handler_test.go`'s `setupHandler`.
2. Sign a `TriggerRequestPayload` with `Method = "web_api_trigger"` using an arbitrary, non-allowlisted private key via `msg.Sign(key)` and `msg.Validate()` (as done in the `triggerRequest` helper) [6](#0-5) .
3. Call `handler.HandleLegacyUserMessage(ctx, msg, cb)` and observe that `don.SendToNode` is invoked for every DON member and `h.savedCallbacks` gains an entry, exactly as in the existing "happy case" test [7](#0-6) , regardless of whether the signing key belongs to an allowlisted sender for this DON — because no such allowlist check exists in the code path.

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageID) == 0 || len(m.Body.MessageID) > MessageIDMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageID, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonID) == 0 || len(m.Body.DonID) > MessageDonIDMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonID, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}

func triggerRequest(t *testing.T, key *ecdsa.PrivateKey, topics []string, methodName, timestamp, payload string) *api.Message {
	messageID := "12345"
	if methodName == "" {
		methodName = MethodWebAPITrigger
	}
	if timestamp == "" {
		timestamp = strconv.FormatInt(time.Now().Unix(), 10)
	}
	donID := "workflow_don_1"
	var payloadJSON []byte
	if payload == "" {
		ts, err := strconv.ParseInt(timestamp, 10, 64)
		require.NoError(t, err)
		reqPayload := webapicap.TriggerRequestPayload{
			TriggerId:      "web-api-trigger@1.0.0",
			TriggerEventId: "action_1234567890",
			Timestamp:      ts,
			Topics:         topics,
			Params: webapicap.TriggerRequestPayloadParams(map[string]any{
				"bid": "101",
				"ask": "102",
			}),
		}
		payloadJSON, err = json.Marshal(reqPayload)
		require.NoError(t, err)
	} else {
		payloadJSON = []byte(payload)
	}
	msg := &api.Message{
		Body: api.MessageBody{
			MessageID: messageID,
			Method:    methodName,
			DonID:     donID,
			Payload:   json.RawMessage(payloadJSON),
		},
	}
	err := msg.Sign(key)
	require.NoError(t, err)
	err = msg.Validate()
	require.NoError(t, err)
	return msg
}
