Audit Report

## Title
Unauthenticated exposure of LOOP plugin debug/pprof and metrics endpoints - (File: core/web/router.go, core/web/loop_registry.go)

## Summary
The `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` routes are registered via `loopRoutes` directly on the unauthenticated top-level `api` group, with no session/token auth middleware applied. This is inconsistent with the node's own pprof endpoints (`metricRoutes`), which are deliberately nested inside the `authv2` group requiring `auth.Authenticate` with token/session credentials.

## Finding Description
In `NewRouter`, `loopRoutes(app, api)` is called on the `api` group that only has rate limiting and session middleware attached — no auth check — at [2](#0-1) . `loopRoutes` itself registers the plugin discovery/metrics/pprof handlers with zero auth middleware: [3](#0-2) .

By contrast, the equivalent node pprof routes (`metricRoutes`) are deliberately called inside the authenticated `authv2` group: [1](#0-0)  and [4](#0-3) .

The handlers themselves perform no authentication or authorization check on the incoming `gin.Context` — `discoveryHandler`, `pluginMetricHandler`, `pluginPPROFHandler`, and `pluginPPROFPOSTSymbolHandler` all proceed straight to forwarding the request based solely on the `:name` path param, with attacker-controlled query parameters (`debug`, `gc`, `seconds`) passed through via `pprofURLVals`: [5](#0-4) [6](#0-5) . The response body from the plugin is streamed back verbatim via `doRequest`: [7](#0-6) .

This is a genuine inconsistency in the code, not a hypothetical: the asymmetry between `metricRoutes` (authenticated) and `loopRoutes` (unauthenticated) for functionally equivalent debug/pprof capability is directly visible in the router construction.

## Impact Explanation
Any unauthenticated client that can reach the node's HTTP API can enumerate registered LOOP plugins and their exposed metrics ports via `/discovery`, scrape plugin Prometheus metrics via `/plugins/:name/metrics`, and pull full pprof profiles (heap, goroutine, CPU profile, allocs, block, mutex, threadcreate) and symbol tables from any registered LOOP plugin process via `/plugins/:name/debug/pprof/*`. Heap and goroutine dumps can leak process memory contents, including potentially sensitive runtime state, internal addresses, and topology information — an information disclosure impact consistent with a "sensitive data exposure without authentication" bounty category, though it does not directly yield key/secret exfiltration, fund movement, or fully unauthenticated code execution.

## Likelihood Explanation
Reachable by any unprivileged client capable of issuing plain HTTP requests to the node's web server, with no credentials required. `loopRoutes` is unconditionally registered in `NewRouter` (not behind a feature flag), so the routes always exist regardless of whether any LOOP plugins are actually configured (unregistered plugin names simply return 404 from `l.registry.Get`).

## Recommendation
Move `loopRoutes` registration into an authenticated (and ideally admin-role-gated) group, mirroring `metricRoutes`'s placement inside `authv2` — e.g., wrap the group with `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)` and `auth.RequiresAdminRole` before exposing `/discovery`, `/plugins/:name/metrics`, and the pprof-forwarding routes.

## Proof of Concept
1. Start a chainlink node with at least one LOOP plugin registered (e.g. a Solana/EVM LOOPP relayer plugin).
2. Without any session cookie or API token, send `GET http://<node>:<port>/discovery` — this returns plugin names and ports per `discoveryHandler` (core/web/loop_registry.go:52-81).
3. Send `GET http://<node>:<port>/plugins/<name>/debug/pprof/heap?debug=1` — this returns a full heap dump forwarded from the plugin process, per `pluginPPROFHandler` (core/web/loop_registry.go:150-166), with no 401 response.
4. Compare with `GET http://<node>:<port>/debug/pprof/heap` (the node's own profile, registered via `metricRoutes` inside `authv2`), which correctly returns 401 Unauthorized without credentials, demonstrating the inconsistency.

func pprofURLVals(gc *gin.Context) (urlVals url.Values, timeout time.Duration) {

	}

}

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}

func (l *LoopRegistryServer) doRequest(gc *gin.Context, method, url string, body io.Reader, timeout time.Duration, pluginName string) {
	ctx, cancel := context.WithTimeout(gc.Request.Context(), timeout)
	defer cancel()
	req, err := http.NewRequestWithContext(ctx, method, url, body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin pprof request: %s", err))
		return
	}
	res, err := http.DefaultClient.Do(req)
	if err != nil {
		msg := "plugin pprof handler failed to post plugin url " + html.EscapeString(url)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q pprof", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}
