## Analog Found

### Title
Creator blacklisted by USDC permanently loses claimable protocol fees in `FeeVault.claim()` - (File: `packages/contracts/src/FeeVault.sol`)

### Summary
`FeeVault.claim()` always pays out to `msg.sender` with no ability to designate an alternate recipient. USDC (the fee asset used throughout alt.fun) can blacklist addresses; if a token creator's wallet is ever added to USDC's blacklist, every call to `claim()` reverts on the outbound `safeTransfer`, permanently freezing that creator's entire accrued fee balance in the vault with no recovery path.

### Finding Description
`FeeVault.claim()` reads the caller's `creatorBalance[msg.sender]`, zeroes it, and unconditionally transfers USDC to `msg.sender`: [1](#0-0) 

There is no `_to` parameter and no alternate withdrawal path (`claimProtocol()` similarly only pays the admin-set `feeTo`, and `sweepDonations()` is unrelated to creator balances). Because `SafeERC20.safeTransfer` reverts the whole transaction on a failed USDC transfer, a creator blacklisted by USDC's issuer cannot execute `claim()` at all — every attempt reverts, and since the balance is only zeroed after the (reverting) transfer succeeds, the funds simply sit un-claimable in the vault forever. There is no owner or protocol mechanism to redirect or recover a blacklisted creator's `creatorBalance`.

This mirrors the reported class exactly: a reward-bearing function hard-codes the payout recipient to the caller's own address (here, implicitly via `msg.sender` with no `_to` override at all, an even stricter version of the original bug's `_to == msg.sender` check), so a blacklist event on the reward token permanently freezes an eligible party's funds inside the contract.

Any creator who launches a token via `Zap.createToken` accrues fees automatically through `Zap._accrueFee` → `FeeVault.accrue`, so simply being a token creator is enough to be exposed — no privileged action or opt-in is required. [2](#0-1) 

### Impact Explanation
The creator's entire pooled USDC fee balance (`creatorBalance[creator]`) — which grows every time anyone trades their token, with no cap — becomes permanently unrecoverable. This is a direct, permanent loss of the creator's earned funds inside `FeeVault`, satisfying the "permanent freezing of creator funds" impact bar.

### Likelihood Explanation
USDC blacklisting is a real, historically exercised capability (Tornado Cash sanctions, law-enforcement freezes, compliance actions), and it requires zero cooperation or error from alt.fun or the creator — it is entirely at the discretion of Circle/USDC's issuer. Any active token creator is a持续 target for this freeze since fees accrue continuously and automatically.

### Recommendation
Add a caller-specified recipient parameter to `claim()` (mirroring the original report's fix), e.g. `claim(address to)`, while still keying the balance lookup/zeroing off `msg.sender`:
```solidity
function claim(address to) external nonReentrant returns (uint256 amount) {
    FeeVaultStorage storage $ = _s();
    amount = $.creatorBalance[msg.sender];
    if (amount == 0) revert NothingToClaim();
    $.creatorBalance[msg.sender] = 0;
    $.totalAccruedCreator -= amount;
    $.usdc.safeTransfer(to, amount);
    emit CreatorFeesClaimed(msg.sender, amount);
}
```
This lets a blacklisted creator route their claim to a fresh, non-blacklisted address without giving up control of *who* is authorized to claim (still gated by `msg.sender`'s balance).

### Proof of Concept
1. A creator launches a token via `Zap.createToken`, and trades accrue fees to `FeeVault.creatorBalance[creator]` via `Zap._accrueFee` / `FeeVault.accrue`.
2. USDC's issuer blacklists the creator's address (a documented, real-world USDC capability).
3. The creator calls `FeeVault.claim()`. Internally, `$.usdc.safeTransfer(msg.sender, amount)` reverts because `msg.sender` (the creator) is blacklisted by USDC.
4. Every future call to `claim()` reverts identically. Since there is no `_to` override and no other withdrawal function for creator balances, `creatorBalance[creator]` remains stuck in the vault indefinitely — a permanent freeze of the creator's earned fees.
