### Title
Stale `DelegateGrant` re-arms after position-NFT round-trip, letting a previously revoked-by-transfer manager borrow/withdraw the account — (File: contracts/controller/src/storage/account.rs)

### Summary
`DelegateGrant` is stamped with `granted_by` but never deleted on position-NFT transfer. `get_delegates` filters by `granted_by == current_owner`, so a transfer only *masks* the grant; if the NFT ever returns to the original grantor, the old delegate list is live again without any new authorization. This is the use-after-free analog: an authorization object that was logically invalidated (freed) is resurrected by reusing the same storage key.

### Finding Description
- Grants are stored under `ControllerKey::Delegates(account_id)` as `DelegateGrant { granted_by, delegates }` and read through `get_delegates`, which returns the list only when `grant.granted_by == *owner` [1](#0-0) .
- Nothing purges the key on NFT transfer. The new owner must call `add_delegate` (overwrite) or `remove_delegate` (which explicitly deletes a foreign grant) to destroy it [2](#0-1) .
- A delegate who is also a registered active position manager passes `require_owner_or_delegate`, the gate on `borrow`, `withdraw`, and the strategy verbs [3](#0-2) .
- The protocol's own docs acknowledge the re-arm: "The stale grant stays in storage and re-arms if the token returns to `granted_by`" [4](#0-3) , and delegates "may borrow or withdraw to arbitrary recipients" [5](#0-4) .

Attack path (all unprivileged entrypoints):
1. Victim V owns account `A` (NFT id `A`) holding collateral/debt and calls `add_delegate(A, M)` where `M` is an active position manager the attacker controls or can trigger (managers are contracts/bots acting on delegated accounts).
2. V transfers the NFT out — e.g., lists/sells it, uses it in an OTC swap, or moves it to a wallet contract. The grant reads empty for the new owner.
3. The NFT later returns to V — a cancelled listing, a buy-back, a routed trade settlement, or any intermediary that sends it back without calling `remove_delegate` (only V or a subsequent owner calling `remove_delegate`/`add_delegate` would purge it; an intermediary that never touches the controller leaves it intact).
4. `get_delegates(A, V)` now returns `[M]` again. `M` calls `borrow(A, asset, amount, M)` and `withdraw(A, asset, amount, M)`, draining collateral up to the LTV floor to an arbitrary recipient. V never re-consented; the documented mental model is "delegates lapse on transfer."

### Impact Explanation
Theft of user funds: a resurrected delegate can withdraw the account's collateral and originate fresh debt, sending proceeds to itself. The victim's position is left maximally leveraged or emptied, and the loss equals collateral value plus borrow capacity.

### Likelihood Explanation
Requires three conditions: the victim previously delegated to a manager the attacker can trigger (plausible — managers are third-party bots/routers), an NFT round-trip back to the victim through a path where no intermediate holder writes the delegate key (marketplace cancel/return, failed OTC, contract custodians that never call controller verbs), and no `remove_delegate` call in between. Moderate likelihood; the trigger (transfer + return) is cheap and the manager's power is unrestricted once active.

### Recommendation
Purge `ControllerKey::Delegates(account_id)` eagerly rather than masking it: hook NFT transfer notification (or have the controller delete the grant in any path that observes `granted_by != owner`, not just `remove_delegate`), and make `get_delegates`/authorization paths delete on mismatch so the grant can never silently re-arm. At minimum, every account-mutating entrypoint that loads the owner should drop foreign grants.

### Proof of Concept
The existing test suite already demonstrates the mechanics: `delegates_of_previous_owner_read_as_empty` shows the grant survives transfer masked, and `remove_delegate_purges_stale_grant_preventing_resurrection` confirms that absent an explicit `remove_delegate`, the grant would resurrect when the NFT returns [6](#0-5) . Concretely:

```rust
// 1. V delegates to active manager M while owning account A
add_delegate(&env, A, &victim, &manager);
// 2. NFT leaves V (sale/listing), grant reads empty for new owner
nft.transfer(&victim, &buyer, &token_id);
assert_eq!(get_delegates(&env, A, &buyer).len(), 0);
// 3. Buyer never touches delegates; NFT returns to V (cancel/buy-back)
nft.transfer(&buyer, &victim, &token_id);
// 4. Grant re-arms: M passes require_owner_or_delegate and drains
assert!(get_delegates(&env, A, &victim).contains(&manager));
// controller.borrow(A, asset, amount, M) / withdraw(A, asset, amount, M) succeed
```

pub(crate) fn get_delegates(env: &Env, account_id: u64, owner: &Address) -> Vec<Address> {
    get_user::<DelegateGrant>(env, &ControllerKey::Delegates(account_id))
        .filter(|grant| grant.granted_by == *owner)
        .map(|grant| grant.delegates)
        .unwrap_or_else(|| Vec::new(env))
}

pub(crate) fn is_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) -> bool {
    if caller == owner {
        return true;
    }
    let active_manager =
        storage::get_position_manager(env, caller).is_some_and(|config| config.is_active);
    active_manager && storage::get_delegates(env, account_id, owner).contains(caller)
}

/// Requires the owner or a registered, active manager delegated by that owner.
pub(crate) fn require_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) {
    if is_owner_or_delegate(env, account_id, caller, owner) {
        return;
    }
    panic_with_error!(env, GenericError::NotAuthorized);
}

fn remove_delegate_purges_stale_grant_preventing_resurrection() {
    let env = Env::default();
    env.mock_all_auths();
    let admin = Address::generate(&env);
    let contract_id = env.register(Controller, (admin,));
    let nft = setup_position_nft(&env, &contract_id);

    let alice = Address::generate(&env);
    let bob = Address::generate(&env);
    let delegate = Address::generate(&env);
    let account_id = u64::from(position_nft::PositionNftClient::new(&env, &nft).mint(&alice));

    env.as_contract(&contract_id, || {
        assert!(add_delegate(&env, account_id, &alice, &delegate));
        assert_eq!(get_delegates(&env, account_id, &alice).len(), 1);
    });

    position_nft::PositionNftClient::new(&env, &nft).transfer(
        &alice,
        &bob,
        &u32::try_from(account_id).unwrap(),
    );

    env.as_contract(&contract_id, || {
        assert!(!remove_delegate(&env, account_id, &bob, &delegate));
        assert!(
            !env.storage()
                .persistent()
                .has(&ControllerKey::Delegates(account_id)),
            "stale grant must be purged from storage, not merely read as empty"
        );
    });

    position_nft::PositionNftClient::new(&env, &nft).transfer(
        &bob,
        &alice,
        &u32::try_from(account_id).unwrap(),
    );

    env.as_contract(&contract_id, || {
        assert_eq!(
            get_delegates(&env, account_id, &alice).len(),
            0,
            "the purged grant must not resurrect when the NFT returns to its original owner"
        );
    });
