Audit Report

## Title
External Initiator `OutgoingSecret`/`OutgoingToken` stored in plaintext and `OutgoingToken` re-exposed to any authenticated node-API user via `GET /v2/external_initiators` - ([File: core/bridges/external_initiator.go])

## Summary
Chainlink generates an outgoing credential pair (`OutgoingToken`/`OutgoingSecret`) for each External Initiator that is used by the node to authenticate itself when calling back into the initiator, but unlike the incoming `Secret` (which is salted/hashed via `auth.HashedSecret`), these outgoing values are stored as raw plaintext in the `external_initiators` table and `OutgoingToken` is re-serialized on every subsequent `GET /v2/external_initiators` call. Any authenticated node-API user, even one holding only the lowest `UserRoleView` permission, can repeatedly retrieve this live outgoing credential.

## Finding Description
`NewExternalInitiator` hashes the incoming secret with `auth.HashedSecret` but assigns `OutgoingToken`/`OutgoingSecret` directly from `utils.NewSecret` with no hashing [1](#0-0) . The schema persists these as plain `text` columns [2](#0-1) , and `CreateExternalInitiator` inserts/returns them verbatim [3](#0-2) .

Critically, `ExternalInitiatorResource` (used for list responses, distinct from `ExternalInitiatorAuthentication` used only at creation time) includes `OutgoingToken` as a JSON field [4](#0-3) , and `ExternalInitiatorsController.Index` builds this resource from the ORM row on every call [5](#0-4) .

The route `GET /v2/external_initiators` requires only generic authentication (session or API token), with no `RequiresEditRole`/`RequiresAdminRole` wrapper [6](#0-5) . This is confirmed as intentional by the RBAC test table, where `GET /v2/external_initiators` has `viewOnlyAllowed: true` [7](#0-6) , meaning even the lowest-privilege `UserRoleView` node-API role can list all external initiators and recover `OutgoingToken` in plaintext repeatedly, not just once at creation.

## Impact Explanation
This is a real, confirmed design flaw: the outgoing authentication token used by the node to call back into an external initiator is stored unhashed and is retrievable indefinitely by any authenticated node-API user, including read-only (`view`) role holders. However, the impact is bounded: this credential does not grant access to the Chainlink node itself, to keys/secrets used for on-chain operations, to job execution, or to fund movement — it only allows an attacker who already holds valid node-API credentials (at minimum `view` role) to also impersonate the node when it calls into the paired external initiator's own server. This falls into the "credential/secret exposure to a lower-privileged authenticated party than intended" category, but it is privilege-*escalation-adjacent* rather than a bypass of node-API authentication itself, since it still strictly requires valid node-API credentials to reach the endpoint.

## Likelihood Explanation
Moderate-to-low in practice: exploitation requires already possessing valid, authenticated node-API credentials (minimum `view` role), which is a privileged starting point relative to an anonymous/unauthenticated attacker. The External Initiator feature must also be enabled and initiators must exist. This is not exploitable by a fully unprivileged, unauthenticated actor — it requires a legitimate but low-privilege operator account.

## Recommendation
Treat `OutgoingSecret`/`OutgoingToken` with the same care as the incoming `HashedSecret`: encrypt at rest or avoid re-exposing `OutgoingToken` in `ExternalInitiatorResource` for list/read calls after creation (mirroring the pattern already used for `Secret` in `ExternalInitiatorAuthentication`, which is only returned once on `Create`). At minimum, gate `GET /v2/external_initiators` behind `RequiresEditRole` if it must continue returning `OutgoingToken`.

## Proof of Concept
1. As an admin, `POST /v2/external_initiators` to create an EI — response contains `outgoingToken` (expected, first-time disclosure) [8](#0-7) .
2. As a separate node-API user with only `UserRoleView`, call `GET /v2/external_initiators` — the response array again contains `outgoingToken` in plaintext for every stored initiator [9](#0-8) , confirmed reachable by view-role per `core/web/auth/auth_test.go` RBAC table.

---

Note on scoring: while the technical claim (plaintext storage + re-exposure via `Index`) is fully verified and accurate, this requires a pre-existing authenticated node-API account (even at the lowest `view` role) — it is not exploitable by a fully unprivileged/unauthenticated external attacker. Whether this clears the bounty program's bar depends on whether "authenticated `view`-role node operator" counts as an acceptable starting privilege level for this program; per the stated rule "reject if the exploit needs operator or admin-role access," and given `view` is the lowest possible authenticated node-API role (analogous to a low-privilege operator account, not equivalent to an anonymous client), this claim sits at the boundary and should be flagged to a human triager rather than auto-accepted with a high severity.

func (eic *ExternalInitiatorsController) Create(c *gin.Context) {
	ctx := c.Request.Context()
	eir := &bridges.ExternalInitiatorRequest{}
	if !eic.App.GetConfig().JobPipeline().ExternalInitiatorsEnabled() {
		err := errors.New("The External Initiator feature is disabled by configuration")
		jsonAPIError(c, http.StatusMethodNotAllowed, err)
		return
	}

	eia := auth.NewToken()
	if err := c.ShouldBindJSON(eir); err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	ei, err := bridges.NewExternalInitiator(eia, eir)
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	if err := ValidateExternalInitiator(ctx, eir, eic.App.BridgeORM()); err != nil {
		jsonAPIError(c, http.StatusBadRequest, err)
		return
	}
	if err := eic.App.BridgeORM().CreateExternalInitiator(ctx, ei); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	eic.App.GetAuditLogger().Audit(audit.ExternalInitiatorCreated, map[string]any{

		"externalInitiatorName": ei.Name,
		"externalInitiatorURL":  ei.URL,
	})

	jsonAPIResponseWithStatus(c, resp, "external initiator authentication", http.StatusCreated)
}
