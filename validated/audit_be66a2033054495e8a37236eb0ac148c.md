### Title
Unvalidated `shop` parameter in `Oauth.begin_auth` allows redirecting the OAuth authorization request (and CSRF `state` nonce) to an attacker-controlled host — ([File: lib/shopify_api/auth/oauth.rb])

### Summary
`ShopifyAPI::Auth::Oauth.begin_auth` builds the OAuth authorization redirect URL directly from the caller-supplied `shop` string without ever passing it through `ShopifyAPI::Utils::ShopValidator.sanitize!`/`sanitize_shop_domain`, unlike every other OAuth-adjacent entry point in the gem (`token_exchange.rb`, `client_credentials.rb`, `refresh_token.rb`, `clients/graphql/storefront.rb`). This lets an attacker force the merchant's browser to send the app's `client_id` and the freshly generated anti-CSRF `state` nonce to a host that is not `*.myshopify.com`/`*.myshopify.io`/etc.

### Finding Description
`begin_auth` computes the authorize URL as: [1](#0-0) 

`auth_base_uri(shop)` performs no domain validation — it simply interpolates the raw `shop` value into `https://#{shop}/admin`: [2](#0-1) 

Compare this with `ShopifyAPI::Utils::ShopValidator`, which exists specifically to reject non-Shopify domains and is used by other credential-flow entry points in the gem: [3](#0-2) 

Because `begin_auth` skips this check, a host application that passes an attacker-influenced `shop` value straight through (a common integration pattern, since the whole point of the OAuth "install" endpoint is to accept a shop parameter from an unauthenticated visitor) will have this gem construct a redirect to an arbitrary attacker-chosen host. The state cookie is set in the same response: [4](#0-3) 

The bound identity that is broken here is: *the host that receives the CSRF `state` nonce and the app's public `client_id`* should equal *a genuine Shopify domain*, but the gem never enforces that equality — it only checks it much later, and only for the returning callback's HMAC (`Utils::HmacValidator.validate(auth_query)` in `validate_auth_callback`), never for the outbound redirect target. [5](#0-4) 

### Impact Explanation
This falls under "session fixation or forced OAuth completion" (High). An attacker can:
1. Cause the victim's browser to hit the app's install/begin-auth route with `shop=attacker-controlled-host`.
2. The gem sets the anti-CSRF `state` cookie in the victim's browser and redirects the browser to `https://attacker-controlled-host/admin/oauth/authorize?...&state=<nonce>&...`, disclosing the nonce to the attacker's server.
3. The attacker can now perform their own legitimate OAuth authorization with Shopify against a shop they control, obtain a valid `code`, and craft a callback HMAC (this part still requires Shopify to sign it for the attacker's own shop — which Shopify will do, since the attacker owns that shop) and redirect the victim's browser to the app's real callback URL using the stolen `state` value.
4. Because `validate_auth_callback` only checks `state == auth_query.state` against the cookie (not who initiated it), the victim's browser (holding the fixed `state` cookie) completes the OAuth dance and becomes associated with the attacker's shop/session in the app, a forced/fixated OAuth completion.

This does not directly leak the app's `client_secret` or an existing merchant's access token, but it does break the intended boundary that the OAuth handshake's `state` nonce should only ever be exposed to genuine Shopify infrastructure, enabling session-fixation-style forced completion, which the rules explicitly classify as High impact.

### Likelihood Explanation
Exploitability depends on the host application passing a user/query-supplied `shop` value into `begin_auth` without its own additional validation — which is the standard integration pattern for the "start install" route of a Shopify app (this route by design must accept an unauthenticated `shop` parameter, since the merchant hasn't authenticated yet). Every other place in this gem that accepts a `shop` string on an unauthenticated code path (`token_exchange.rb`, `client_credentials.rb`, `refresh_token.rb`, GraphQL storefront client) does perform this validation, indicating that the omission in `Oauth.begin_auth` is inconsistent with the gem's own established defensive pattern rather than an intentional design choice delegated to the host app.

### Recommendation
Validate `shop` in `Oauth.begin_auth` (and in `auth_base_uri`) using `ShopifyAPI::Utils::ShopValidator.sanitize!` before constructing the authorize redirect URL, raising `Errors::InvalidShopError` for any non-Shopify domain, consistent with `token_exchange.rb`, `client_credentials.rb`, `refresh_token.rb`, and `clients/graphql/storefront.rb`.

# typed: strict
# frozen_string_literal: true

require "addressable/uri"

module ShopifyAPI
  module Utils
    module ShopValidator
      TRUSTED_SHOPIFY_DOMAINS = T.let(
        [
          "shopify.com",
          "myshopify.io",
          "myshopify.com",
          "spin.dev",
          "shop.dev",
        ].freeze,
        T::Array[String],
      )

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
