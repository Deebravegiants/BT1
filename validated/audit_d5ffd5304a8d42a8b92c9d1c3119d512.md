### Title
Simplex FXFiller trusts an unguarded single-block Uniswap V4 spot price as its pool-based pricing oracle, enabling flash-loan price manipulation to drain solver funds - ([File: sdk/packages/simplex/src/strategies/fx.ts])

### Summary
The Inverse Finance incident lost ~$1.26M because the protocol priced collateral off an on-chain LP pool value that could be manipulated within a single transaction (via flash loan) instead of a manipulation-resistant oracle. The equivalent pattern exists in Hyperbridge's `Simplex` intent-solver reference implementation: when a trading pair has no static bid/ask curves, `FXFiller` prices the exotic token directly from a single Uniswap V4 pool's current `sqrtPriceX96`/tick — a spot AMM price with no TWAP — and the only defense (`checkPriceGuard`) is an operator-optional static reference band that is disabled unless explicitly configured.

### Finding Description
`UniswapV4FundingPlanner.getExoticTokenPrice` → `computeDirectPoolPriceUsd` derives the "USD price" of the exotic token straight from the live pool's `sqrtPriceX96`/tick (via `sdkPool.token0Price`/`token1Price`), i.e., a single spot read of one block's AMM state, with no TWAP or multi-block averaging. [1](#0-0) 

This spot price is consumed by `FXFiller.resolveLegRates` to price curveless USD-stable pairs, and by `referenceRate` to size confirmation depth, with `checkPriceGuard` as the only manipulation defense: [2](#0-1) [3](#0-2) 

`checkPriceGuard` only rejects a quote if a `referencePrice`/`maxDeviationBps` pair was explicitly configured for that chain; absent that config, every quote passes unconditionally: [4](#0-3) 

Both the config schema and docs confirm the guard is optional and, if omitted, "leaves the chain unguarded": [5](#0-4) [6](#0-5) 

The project's own internal flow documentation states plainly that `checkPriceGuard` "checks deviation from a static reference, not execution cost," and that the raw pool mid is extended linearly with no size/impact term: [7](#0-6) 

Even with the guard configured, its own test suite documents that it only bounds *how far* the spot price may drift, not whether the spot price itself was momentarily manipulated within the current block/transaction — an attacker can move the price up to (but within) the allowed `maxDeviationBps` band using a flash loan, and unguarded chains accept any price at all: [8](#0-7) 

**Root cause parity with Inverse Finance:** Inverse Finance's oracle derived collateral value from an on-chain LP price that a flash loan could distort within one transaction, letting an attacker borrow against inflated/deflated collateral. Here, `computeDirectPoolPriceUsd`/`getExoticTokenPrice` derive the fill price for a live cross-chain intent order from the same class of manipulable primitive — an un-TWAP'd `sqrtPriceX96` read of a single pool — and the guard against it is opt-in and configured per-operator, not enforced by the protocol.

### Impact Explanation
An attacker who places (or arranges) an `IntentGateway`/Simplex order against a curveless, Uniswap-V4-priced pair can flash-loan-manipulate the referenced pool's spot price immediately before the solver evaluates and fills the order. If no `referencePrice`/`maxDeviationBps` guard is configured for that chain (the documented default posture, and legal per config validation), the manipulated price passes unconditionally into `resolveLegRates`, causing the solver to deliver more output value than the true market price, funded from its own on-chain vault/LP inventory. Even where the guard is configured, an attacker can push the price to the edge of the allowed band, extracting the full deviation tolerance every time. This is concrete, direct theft of solver-held funds (the capital backing intent fills), matching the "unsound state/price commitment leading to unauthorized value transfer" impact class in scope.

### Likelihood Explanation
The attack requires only: (1) an operator running Simplex with Uniswap-V4 pool-based pricing on a pair without the optional guard configured, or with a wide/typical deviation band, and (2) the ability to flash-loan-manipulate the underlying pool's spot price within the same block the order is evaluated — a well-understood, cheap, and repeatable technique (as demonstrated twice against Inverse Finance within two months). No privileged access is needed; the attacker only needs to submit/trigger an order that resolves to the manipulated leg, which any unprivileged intent placer can do.

### Recommendation
- Do not rely on a single-block spot read (`sqrtPriceX96`/tick) as a pricing oracle; use a TWAP over multiple blocks/observations, or cross-check against an independent price source (e.g., Chainlink) before pricing a fill.
- Make the price guard (`referencePrice`/`maxDeviationBps`) mandatory whenever `[vault.uniswapV4]` pool-based pricing is enabled, rather than optional, and fail config validation if it is omitted.
- Consider sampling the pool price across multiple blocks or requiring a minimum settlement delay/confirmation depth specifically for venue-priced (curveless) legs, so a single-transaction manipulation cannot be monetized atomically.

### Proof of Concept
1. Operator runs Simplex with a curveless pair (e.g., USDC/EXOTIC) priced via `[vault.uniswapV4]`, without setting `referencePrice`/`maxDeviationBps` for the chain (a valid, documented configuration per `filler-toml.ts` validation). [9](#0-8) 
2. Attacker takes a flash loan and swaps heavily through the referenced Uniswap V4 pool in the same transaction/block to move `sqrtPriceX96` far from the true market price.
3. Attacker (or an accomplice) submits an `IntentGateway` order on the affected leg while the pool is still distorted.
4. `FXFiller.calculateProfitability` → `resolveLegRates` → `venuePriceMemo`/`getVenueUsdPrice` → `UniswapV4FundingPlanner.getExoticTokenPrice` reads the manipulated `sqrtPriceX96`, and since `checkPriceGuard` returns `true` unconditionally (no guard configured, per `fx.price-guard.test.ts` line 66-70), the solver fills at the distorted rate. [10](#0-9) 
5. Attacker reverses the pool manipulation (repays the flash loan) in the same transaction, keeping the solver's overpayment as profit — mirroring the exact flash-loan-oracle mechanics of the Inverse Finance incident.

```typescript
	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {

				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
	}
```

```typescript
	private async referenceRate(
		leg: ResolvedLeg,
		venueUsdPrice: (chain: string, token1Address: string) => Promise<Decimal | null>,
	): Promise<Decimal | null> {
		const policy = leg.pair.bidPricePolicy ?? leg.pair.askPricePolicy
		if (policy) {
			const rate = policy.getPrice(new Decimal(0))
			return rate.gt(0) ? rate : null
		}
		// Venue-priced pair: token0 is USD-stable (constructor invariant), so the
		// venue's USD-per-token1 quote inverts straight into token1-per-token0.
		const venueUsd = await venueUsdPrice(leg.token1Chain, leg.token1Address)
		if (!venueUsd) return null
		const venueRate = new Decimal(1).div(venueUsd)
		// Same guard as trade pricing: this rate sizes the order's USD notional
		// for confirmation depth, and a manipulated pool understating the value
		// would shrink the reorg protection — the exact attack the guard exists
		// to stop. Refusing to size skips the order, consistent with pricing.
		if (!this.checkPriceGuard(undefined, leg.token1Chain, venueRate)) return null
		return venueRate
	}
```

```text
## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.
```
