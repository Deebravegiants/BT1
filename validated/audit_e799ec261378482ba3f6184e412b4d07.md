### Title
Unprivileged `recapitalize` frees pool custody while supplier share claims remain live, leaving dangling claims that revert in the token transfer - (File: contracts/pool/tests/flows.rs)

### Summary
The ImageMagick bug class is "free the resource, then fail and leave live pointers to it." In `rs-lending-xlm--019` the resource is pool token custody and the "live pointers" are RAY-scaled supply shares plus the `cash` bookkeeping field. `recapitalize` releases real tokens from the pool to a caller-chosen payer without requiring any corresponding funding, minted shares, or book adjustment — yet the `cash` ledger continues to claim the funds are held. Suppliers' exits then clear the pool's own liquidity guard (which reads the book, not the balance) and crash inside the SAC transfer — a textbook use-after-free shape: freed custody, dangling claim, late failure.

### Finding Description
The repository's own regression test proves the path end-to-end: `contracts/pool/tests/flows.rs:3408-3483` (`test_unfunded_recapitalize_leaves_the_cash_book_overstating_custody`):

```rust
// Drain every token via an unfunded refund.
let custody = token.balance(&t.pool);
t.client().recapitalize(&hub(&t.asset), &payer, &custody);
assert_eq!(token.balance(&t.pool), 0, "custody is gone");

let book = t.state_snapshot().cash;
assert!(book >= deposit, "the book still claims more than the supplier's deposit");
```

- `recapitalize` is callable by an unprivileged address (`payer` is a freshly generated address) and transfers out the full physical balance.
- The `cash` book (`contracts/pool/README.md` lines 180-210: `supplied, borrowed, revenue, cash` as Ray/i128 bookkeeping) still reports the supplier's deposit, so `require_reserves`/liquidity guards read stale state and let exits through.
- The subsequent `withdraw` passes the pool's guards and fails inside the SAC with `BalanceError = 10` — the claim "dereferences" freed custody.
- The assert explicitly shows neither `InsufficientLiquidity` nor `PoolInsolvent` fired; the failure comes from the token contract, i.e., the dangling reference, not a pool check.

### Impact Explanation
- **Theft of user funds**: any address can call `recapitalize(hub_asset, payer, amount)` and receive the pool's real token balance up to the recorded custody, with no minted shares, no debt, and no solvency accounting.
- **Permanent/temporary freezing of remaining funds**: after the drain, suppliers holding scaled shares cannot withdraw — every exit that passes the book-based liquidity guard reverts inside the token transfer. The book-vs-custody divergence is not self-healing, so all remaining suppliers are frozen out until someone recapitalizes for real.

### Likelihood Explanation
Reachable by a single unprivileged address in one transaction: `recapitalize(&hub(asset), &attacker, &amount)`. No price manipulation, no timing, no privileged role, no multi-leg setup. The only precondition is that the pool holds token custody, which is the normal state.

### Recommendation
- Gate `recapitalize` behind an authorized role, or change it to a pull/funding pattern: require the caller to transfer tokens *in* (or prove a funded commitment) before custody is released.
- At minimum, reconcile `cash` against actual custody at release time and clamp the payout to the true balance while decrementing the book, so `cash` can never claim funds that were transferred out.
- Add a post-condition invariant `token.balance(pool) >= cash - pending_outflows` (the `backing_shortfall` guard already exists in `guards`; apply it on the release path).

### Proof of Concept
1. Supplier deposits: `supply(spoke, [[hub(asset), 10_000_000_000]])` — pool custody and `cash` both = 10_000_000_000.
2. Attacker (fresh address, no deposit): `recapitalize(hub(asset), attacker_payer, token.balance(pool))` → attacker receives all tokens; `token.balance(pool) == 0`; `state.cash` still ≥ deposit.
3. Supplier calls `withdraw(receiver, false, withdrawals=[(hub_asset, i128::MAX)])` → passes `require_reserves` and `PoolInsolvent` guards (book says funds exist) → reverts with SAC `BalanceError = 10` inside the transfer. Supplier receives nothing; the book continues to overstate custody after rollback.
