## Analysis Result

### Title
Division-by-zero panic (program crash / DoS) in `swap_token_amount_base_out` reachable via attacker-chosen `amount_out` in `SwapInstructionBaseOut` - (File: program/src/math.rs)

### Summary
The CVE describes a divide-by-zero crash in QEMU's virtio vring code triggered by attacker-controlled state (unset alignment) reaching an unguarded division. The Raydium AMM program has an analogous unguarded-division pattern: `Calculator::swap_token_amount_base_out` computes a denominator directly from a fully attacker-controlled instruction field (`swap.amount_out`) *before* any bounds check is performed, and feeds it into `checked_ceil_div`, whose internal `.unwrap()` panics on a zero divisor.

### Finding Description
`swap_token_amount_base_out` computes `denominator = total_pc_without_take_pnl.checked_sub(amount_out).unwrap()` (Coin2PC) or `total_coin_without_take_pnl.checked_sub(amount_out).unwrap()` (PC2Coin), then immediately divides by it via `checked_ceil_div(denominator).unwrap()`: [1](#0-0) 

`checked_ceil_div` internally calls `self.checked_div(rhs)?`, which returns `None` for a zero `rhs`, propagating `None` out of the function: [2](#0-1) 

The caller then unconditionally `.unwrap()`s that `Option`, so a `None` (from a zero denominator) causes an immediate Rust panic, aborting the whole transaction/program execution: [3](#0-2) 

Critically, in `swap_base_out` (and `swap_base_out_v2`), the calculation is performed **before** the check that would reject an out-of-range `amount_out`: [4](#0-3) [5](#0-4) 

If an attacker submits `swap.amount_out == total_pc_without_take_pnl` (Coin2PC direction) or `swap.amount_out == total_coin_without_take_pnl` (PC2Coin direction), `checked_sub` yields `0`, `checked_ceil_div` returns `None`, and the trailing `.unwrap()` panics — well before the `if swap.amount_out >= total_pc_without_take_pnl { return Err(...) }` guard at line 2214/2237 ever executes.

### Impact Explanation
A panic inside a Solana BPF program aborts the transaction, which by itself is only a failed transaction, not persistent state corruption. However, this is a program-crashing "unhandled panic on attacker-chosen zero divisor" bug directly analogous in root cause to CVE-2017-17381 (attacker controls a value that zeroes a divisor used in an unchecked division, crashing the host process). Any unprivileged user submitting a single `SwapInstructionBaseOut`/`SwapInstructionBaseOut2` transaction with `amount_out` set to exactly the pool's current PC or coin reserve can trigger this panic deterministically, at will, against a live pool — effectively a denial-of-service primitive against that swap path with zero cost beyond a failed tx fee, reachable from `Instruction::SwapBaseOut`/`SwapBaseOut2` processed in `Processor::process_swap_base_out` / `process_swap_base_out_v2`.

### Likelihood Explanation
High: `amount_out` is a raw `u64` deserialized straight from instruction data with no range validation prior to reaching the vulnerable arithmetic, and the current PC/coin vault balances used as the subtrahend are always observable on-chain (readable pool accounts), so an attacker can trivially compute the exact `amount_out` needed to zero the denominator for any given pool state and slot.

### Recommendation
Move the bounds check (`swap.amount_out >= total_pc_without_take_pnl` / `>= total_coin_without_take_pnl`) to occur before calling `Calculator::swap_token_amount_base_out`, and/or replace the `.unwrap()` calls in `swap_token_amount_base_out`/`checked_ceil_div` with proper `ok_or(AmmError::...)?` error propagation so a zero denominator returns a graceful `AmmError` instead of panicking.

### Proof of Concept
1. Query the pool's `amm_pc_vault`/`amm_coin_vault` token balances and `need_take_pnl_pc`/`need_take_pnl_coin` to derive `total_pc_without_take_pnl` via `Calculator::calc_total_without_take_pnl_no_orderbook` [6](#0-5) .
2. Submit a `SwapInstructionBaseOut` transaction (direction Coin2PC: `user_source` mint = coin, `user_destination` mint = pc) with `amount_out` set exactly equal to `total_pc_without_take_pnl`.
3. Execution reaches `swap_token_amount_base_out` where `denominator = total_pc_without_take_pnl.checked_sub(amount_out).unwrap()` evaluates to `0` [7](#0-6) .
4. `checked_ceil_div(0)` returns `None` internally due to `checked_div` on zero [8](#0-7) , and the caller's `.unwrap()` on line 346 panics, aborting the transaction/program before the later `swap.amount_out >= total_pc_without_take_pnl` guard at line 2214 is ever reached.

impl CheckedCeilDiv for U128 {
    fn checked_ceil_div(&self, rhs: Self) -> Option<Self> {
        let mut quotient = self.checked_div(rhs)?;
        let remainder = self.checked_rem(rhs)?;
        if remainder != U128::zero() {
            quotient = quotient.checked_add(U128::one())?;
        }
        Some(quotient)
    }
