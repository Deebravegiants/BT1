## Title
Chunk smuggling in BEEFY parachain header digest decoding causes forged/hidden ISMP state commitments — (File: `evm/src/consensus/Codec.sol`)

### Summary
`Codec.DecodeHeader` (used by the EVM BEEFY light client to decode SCALE-encoded Substrate parachain headers) mishandles the `Other` variant of a Substrate `DigestItem`. It reads only the 1-byte discriminant and, for `DIGEST_ITEM_OTHER`, sets a flag without consuming the length-prefixed `Vec<u8>` payload that Substrate's SCALE encoding places after that discriminant. The cursor (`ByteSlice.offset`) is never advanced past this payload, so every subsequent digest item is parsed starting from attacker-controlled bytes that were meant to be the `Other` digest's body — the same "unconsumed chunk body reinterpreted as a fresh header" bug class as the libpng CVE.

### Finding Description
`Codec.DecodeHeader` in [1](#0-0)  loops over `length` digest items, reading only a 1-byte `kind` and dispatching:

- `CONSENSUS` (4), `SEAL` (5), `PRERUNTIME` (6) → calls `decodeDigestItem`, which correctly reads a 4-byte engine id, a SCALE-compact length, then that many bytes — fully consuming the item [2](#0-1) .
- `OTHER` (0) → only sets `digest.isOther = true`; **no bytes are read at all**.
- `RUNTIME_ENVIRONMENT_UPDATED` (8) → correctly consumes nothing, because that Substrate variant genuinely carries no payload.

However, Substrate's `sp_runtime::DigestItem` variant 0 is `Other(Vec<u8>)`, which is SCALE-encoded as `0x00 ‖ compact-length ‖ bytes`. Because `Codec.sol` never reads the compact length or payload for `kind == 0`, the decoder's cursor stays pointed at the length-prefix byte(s) of the `Other` payload. The next loop iteration then reinterprets those bytes as the *next* digest's 1-byte `kind` discriminant plus whatever follows as its body — precisely the "unconsumed chunk body reinterpreted as a new header" pattern from the CVE.

This header decode result feeds directly into `HeaderImpl.stateCommitment`, which scans `self.digests` for a `Consensus` digest whose `consensusId == ISMP_CONSENSUS_ID` (mmr root + child-trie root) and one with `ISMP_TIMESTAMP_ID` (timestamp), and builds the `StateCommitment` used to authorize proof verification: [3](#0-2) .

Because the parser desyncs after any `Other` digest, an attacker who controls (or can influence) the byte layout of a submitted parachain header inside a BEEFY consensus proof can:
- Prepend a crafted `Other(Vec<u8>)` digest whose "unconsumed" length+payload bytes are engineered to be reinterpreted as a *fake* `Consensus` digest carrying attacker-chosen `mmrRoot`/`childTrieRoot`/timestamp — smuggling a forged commitment payload past digest-type filtering.
- Alternatively, cause the real `ISMP`/`ISTM` digest that legitimately follows an `Other` digest to be misread (wrong offset), corrupting or hiding the true commitment, or making `stateCommitment()` revert/misbehave depending on downstream digest layout.

### Impact Explanation
`Codec.DecodeHeader`/`HeaderImpl.stateCommitment` underpin the EVM BEEFY consensus client's parachain-header verification path (`modules/ismp/clients/beefy` mirrors the same logic on the Substrate side, and `EcdsaBeefy.sol`/`SP1Beefy.sol` consume `Codec.sol` on the EVM side). The `StateCommitment` (state root / overlay MMR root / timestamp) produced here is the trust anchor `HandlerV2.handlePostRequests` and `handleGetResponses` rely on (`host.stateMachineCommitment(...).overlayRoot`) to accept POST-request and GET-response MMR proofs [4](#0-3) . A desynced/forged commitment root could let a relayer submit forged message-delivery proofs (unauthorized app action / forged message delivery) or corrupt the trusted state such that a legitimate route can no longer deliver messages — matching the required impact bar (forged message delivery, unsound state commitment, or a route unable to deliver messages).

### Likelihood Explanation
Exploitability depends on whether an attacker (a relayer submitting a BEEFY consensus proof) can control or predict the exact byte content that will be inserted as the "smuggled" digest — parachain headers do include attacker-influenced digest logs in some setups (e.g., custom pallets/digests), but the specific ISMP/timestamp digests are added by the trusted parachain runtime itself, constraining how much of the header layout is attacker-choosable. I could not fully verify from the indexed code whether any parachain header this client accepts can realistically contain an `Other` digest under attacker influence (this would need runtime-level auditing of the relevant parachain's digest emission, which is outside indexed scope), so likelihood is Medium/uncertain rather than confirmed exploitable end-to-end.

### Recommendation
Fix `Codec.DecodeHeader` to correctly consume the `Other` variant per SCALE encoding: read a `ScaleCodec.decodeUintCompact` length and then `Bytes.read(slice, length)` for `kind == DIGEST_ITEM_OTHER`, storing it into `digest.other`. Add a regression test asserting that a header with an `Other` digest followed by an `ISMP`-consensus digest is decoded with the correct `stateCommitment()` output, and that trailing/garbage bytes after the last well-formed digest cause a revert rather than silent truncation.

### Proof of Concept
Conceptual (Solidity-level) PoC outline, since this is a decode-desync bug rather than a runtime exploit chain that can be fully demonstrated from the indexed code alone:
1. Construct a SCALE-encoded header body: `parentHash(32) ‖ compact(blockNumber) ‖ stateRoot(32) ‖ extrinsicsRoot(32) ‖ compact(digestCount=2)`.
2. Digest #1: `0x00` (Other) ‖ `compact(len=N)` ‖ `N` attacker-chosen bytes engineered so that, when the (buggy) decoder tries to read the *next* digest starting right after `0x00`, the byte at that position (`compact(len)`'s first byte) is interpreted as `kind == 0x04` (Consensus), followed by bytes decoding as `consensusId = "ISMP"` and attacker-chosen 64-byte data (fake mmrRoot/childTrieRoot).
3. Call `Codec.DecodeHeader` (or the BEEFY consensus verification entry point) with this header and observe that `HeaderImpl.stateCommitment` returns the attacker-chosen `overlayRoot`/`stateRoot`/`timestamp`, or alternatively silently drops the real ISMP digest due to offset desync — either outcome corrupts the state commitment used later in `HandlerV2` proof verification.

**Uncertainty**: I could not confirm within the indexed codebase whether the specific parachains tracked by this BEEFY client ever legitimately emit `Other` digest items or whether their content is attacker-influenceable end-to-end; a full exploitation chain would require verifying parachain runtime digest emission and the exact byte layout accepted by `verify_consensus`, which is beyond what the indexed files show.

    // @dev Deserializes a substrate header
    function DecodeHeader(bytes memory encoded) internal pure returns (Header memory) {
        ByteSlice memory slice = ByteSlice(encoded, 0);
        bytes32 parentHash = Bytes.toBytes32(Bytes.read(slice, 32));
        uint256 blockNumber = ScaleCodec.decodeUintCompact(slice);
        bytes32 stateRoot = Bytes.toBytes32(Bytes.read(slice, 32));
        bytes32 extrinsicsRoot = Bytes.toBytes32(Bytes.read(slice, 32));

        uint256 length = ScaleCodec.decodeUintCompact(slice);
        Digest[] memory digests = new Digest[](length);

        for (uint256 i = 0; i < length; i++) {
            uint8 kind = Bytes.readByte(slice);
            Digest memory digest;
            if (kind == DIGEST_ITEM_OTHER) {
                digest.isOther = true;
            } else if (kind == DIGEST_ITEM_CONSENSUS) {
                digest.isConsensus = true;
                digest.consensus = decodeDigestItem(slice);
            } else if (kind == DIGEST_ITEM_SEAL) {
                digest.isSeal = true;
                digest.seal = decodeDigestItem(slice);
            } else if (kind == DIGEST_ITEM_PRERUNTIME) {
                digest.isPreRuntime = true;
                digest.preruntime = decodeDigestItem(slice);
            } else if (kind == DIGEST_ITEM_RUNTIME_ENVIRONMENT_UPDATED) {
                digest.isRuntimeEnvironmentUpdated = true;
            }
            digests[i] = digest;
        }

        return Header(parentHash, blockNumber, stateRoot, extrinsicsRoot, digests);
    }

library HeaderImpl {
    /// Digest Item ID
    bytes4 public constant ISMP_CONSENSUS_ID = bytes4("ISMP");
    /// ConsensusID for the ISMP timestamp digest deposited by pallet-ismp
    bytes4 public constant ISMP_TIMESTAMP_ID = bytes4("ISTM");

    error TimestampNotFound();

    /// @dev Extracts the ISMP MMR root, child trie root, and timestamp from the header
    /// digests and returns them as a StateCommitment. Reverts if no timestamp digest is found.
    function stateCommitment(Header memory self) internal pure returns (StateCommitment memory) {
        bytes32 mmrRoot;
        bytes32 childTrieRoot;
        uint256 timestamp;

        for (uint256 j = 0; j < self.digests.length; j++) {
            if (self.digests[j].isConsensus && self.digests[j].consensus.consensusId == ISMP_CONSENSUS_ID) {
                mmrRoot = Bytes.toBytes32(Bytes.substr(self.digests[j].consensus.data, 0, 32));
                childTrieRoot = Bytes.toBytes32(Bytes.substr(self.digests[j].consensus.data, 32));
            }

            if (self.digests[j].isConsensus && self.digests[j].consensus.consensusId == ISMP_TIMESTAMP_ID) {
                timestamp = ScaleCodec.decodeUint256(self.digests[j].consensus.data);
            }
        }

        // sanity check
        if (timestamp == 0) revert TimestampNotFound();

        return StateCommitment({timestamp: timestamp, overlayRoot: mmrRoot, stateRoot: childTrieRoot});
    }
