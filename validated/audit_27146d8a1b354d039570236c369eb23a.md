### Title
Slashing-induced balance decrease permanently DoS's the staking pool via a hard-revert assertion in `internal_ping` - (File: `staking-pool/src/internal.rs`)

### Summary
The external Compound report flags that `DAIInterestRateModel.dsrPerBlock` performs `dsr - 1e27` without a floor check, so if the external Maker DSR value ever drops below `1e27`, every call that depends on it (`poke`, `getSupplyRate`) reverts, permanently blocking rate updates. The NEAR staking-pool contract has an analogous root cause: `internal_ping` performs a hard `assert!(total_balance >= self.last_total_balance)` before computing `total_balance - self.last_total_balance`, with no fallback path. If the validator's locked balance ever decreases relative to the last recorded total (which happens on slashing), this assertion fails unconditionally on every subsequent call, and since `internal_ping` is invoked by essentially every state-changing entry point, the entire contract becomes permanently unusable.

### Finding Description
`internal_ping` in [1](#0-0)  computes:
```
let total_balance = env::account_locked_balance() + env::account_balance() - env::attached_deposit();
assert!(total_balance >= self.last_total_balance, "The new total balance should not be less than the old total balance");
let total_reward = total_balance - self.last_total_balance;
```
This assumes the pool's total balance (locked + unlocked) never decreases between pings. That assumption only holds under a "no-slashing" condition, which the contract's own README explicitly flags as a caveat: [2](#0-1) . If the validator running the pool is slashed (e.g., due to double-signing or other protocol-level misbehavior), `account_locked_balance()` drops, `total_balance` becomes smaller than `self.last_total_balance`, and the `assert!` unconditionally reverts.

Because `internal_ping` is called at the top of virtually every state-changing public method — `ping`, `deposit`, `deposit_and_stake`, `withdraw`, `withdraw_all`, `stake`, `stake_all`, `unstake`, `unstake_all` ( [3](#0-2) ) — once slashing pushes `total_balance` below `last_total_balance`, every one of these entry points reverts forever. There is no mechanism to reset or adjust `last_total_balance` downward, and no unprivileged (or even owner) recovery path exists in the contract.

### Impact Explanation
This matches the "Permanent freezing, unrecoverable lock, or irrevocable loss of user or protocol funds ... unstake-withdraw ... flows" impact bucket. Once triggered, delegators can no longer `withdraw` their already-unstaked balance, `unstake` their staked balance, or `deposit`/`stake` new funds — the entire pool's NEAR balance becomes permanently locked with no owner-level escape hatch in the contract itself.

### Likelihood Explanation
Slashing is a real, if rare, occurrence in NEAR's protocol design (documented in the Nightshade paper, linked directly in the same README caveat). The contract explicitly acknowledges it does not handle slashing, which mirrors the Maker case: developers stated the negative condition "shouldn't" happen but did not defend against it in code. Any unprivileged delegator's ordinary calls to `withdraw`, `unstake`, `stake`, or `ping` are enough to hit the failing assertion once a slashing event has occurred — no attacker privilege is needed to trigger the revert itself, only the pre-existing external condition (analogous to the DSR governance change in the original report).

### Recommendation
Avoid a hard, permanently-fatal `assert!` on the balance-decrease path. Consider:
- Using `saturating_sub`/branching so `internal_ping` treats a balance decrease as `total_reward = 0` and updates `last_total_balance` to the new (lower) value instead of reverting.
- Adding an owner-controlled recovery method to resynchronize `last_total_balance` after a slashing event, so delegator withdraw/unstake flows are not permanently bricked.

### Proof of Concept
1. Initialize the staking pool contract normally; `last_total_balance` is set to the initial `account_balance` in `new` ( [4](#0-3) ).
2. Simulate the validator being slashed, i.e., `env::account_locked_balance()` decreases in the next epoch so that `account_locked_balance() + account_balance() - attached_deposit() < last_total_balance`.
3. Any account calls `ping()`, `deposit()`, `withdraw(amount)`, `stake(amount)`, or `unstake(amount)`.
4. `internal_ping` executes the `assert!(total_balance >= self.last_total_balance, ...)` check and panics, reverting the transaction.
5. Every subsequent call to any of these public methods (by any delegator, including the owner) reverts identically forever, since `last_total_balance` is never lowered — freezing all pooled NEAR in the contract.

```rust
    /// Distributes rewards after the new epoch. It's automatically called before every action.
    /// Returns true if the current epoch height is different from the last epoch height.
    pub(crate) fn internal_ping(&mut self) -> bool {
        let epoch_height = env::epoch_height();
        if self.last_epoch_height == epoch_height {
            return false;
        }
        self.last_epoch_height = epoch_height;

        // New total amount (both locked and unlocked balances).
        // NOTE: We need to subtract `attached_deposit` in case `ping` called from `deposit` call
        // since the attached deposit gets included in the `account_balance`, and we have not
        // accounted it yet.
        let total_balance =
            env::account_locked_balance() + env::account_balance() - env::attached_deposit();

        assert!(
            total_balance >= self.last_total_balance,
            "The new total balance should not be less than the old total balance"
        );
        let total_reward = total_balance - self.last_total_balance;
```

```rust
    pub fn ping(&mut self) {
        if self.internal_ping() {
            self.internal_restake();
        }

    /// Deposits the attached amount into the inner account of the predecessor.
    #[payable]
    pub fn deposit(&mut self) {
        let need_to_restake = self.internal_ping();

        self.internal_deposit();

        if need_to_restake {
            self.internal_restake();
        }
    }

    /// Deposits the attached amount into the inner account of the predecessor and stakes it.
    #[payable]
    pub fn deposit_and_stake(&mut self) {
        self.internal_ping();

        let amount = self.internal_deposit();
        self.internal_stake(amount);

        self.internal_restake();
    }

    /// Withdraws the entire unstaked balance from the predecessor account.
    /// It's only allowed if the `unstake` action was not performed in the four most recent epochs.
    pub fn withdraw_all(&mut self) {
        let need_to_restake = self.internal_ping();

        let account_id = env::predecessor_account_id();
        let account = self.internal_get_account(&account_id);
        self.internal_withdraw(account.unstaked);

        if need_to_restake {
            self.internal_restake();
        }
    }

    /// Withdraws the non staked balance for given account.

        let amount: Balance = amount.into();

        if need_to_restake {
            self.internal_restake();
        }
    }

        self.internal_restake();

    /// Stakes the given amount from the inner account of the predecessor.
```
