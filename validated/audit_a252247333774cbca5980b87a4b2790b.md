### Title
`SimplexPaymaster` prices gas fees from Chainlink feeds without an Arbitrum sequencer-uptime check - (File: evm/src/utils/SimplexPaymaster.sol)

### Summary
`SimplexPaymaster` is a permissionless ERC-4337 paymaster deployed across multiple EVM chains, including L2 rollups such as Arbitrum, to price ERC-20 gas payments against Chainlink `token/USD` and `native/USD` feeds. Its `_getOraclePrice` helper reads `latestRoundData()` and validates only positivity and staleness bounds, with no check for Arbitrum's L2 sequencer-uptime feed. [1](#0-0) 

### Finding Description
`_getOraclePrice` fetches Chainlink `latestRoundData()` and only rejects non-positive answers and answers older than `maxOracleAge`: [1](#0-0) 

This price feed is used both to price every sponsored UserOperation's gas fee (`_tokenPrice`, called from `_fetchDetails` during `validatePaymasterUserOp`) and to size `amountOutMin` for the treasury's `swapAndDeposit` fee-recycling swap: [2](#0-1) [3](#0-2) [4](#0-3) 

On Arbitrum, when the sequencer goes down, Chainlink's underlying oracle nodes can no longer relay fresh L1-derived answers to the L2 aggregator contract, so `latestRoundData()` can return a last-known-good price whose `updatedAt` may still fall inside the configured `maxOracleAge` window (or worse, once the sequencer resumes and processes a backlog of transactions, prices update in a burst that does not reflect real-time market conditions during the down window). Because the contract has no `IArbitrumSequencerUptimeFeed`-style check (per Chainlink's documented L2 pattern), it treats this potentially stale/incorrect price as valid and fresh for both fee-charging and swap-slippage-bound computation.

### Impact Explanation
Every UserOperation submitted through this paymaster during (or immediately following) a sequencer outage is priced using a `tokenPrice` derived from `_getOraclePrice`, which is fully reachable by any unprivileged solver/relayer sending a UserOp — there is no privileged caller involved in `_fetchDetails`/`_validatePaymasterUserOp`. If the stale/incorrect price undervalues the native asset relative to the ERC-20 fee token, users are overcharged in ERC-20 stablecoins for gas; if it overvalues native, the paymaster undercharges and drains its own deposited funds relative to actual gas spent, and `swapAndDeposit`'s oracle-derived `amountOutMin` (meant to bound slippage against a manipulated/stale price) becomes unreliable, allowing the treasury-only swap to execute at an unfavorable rate that doesn't actually protect against the real market price. This is a fund-safety issue (mispriced fee extraction / paymaster fund drain) reachable by an ordinary UserOp sender, not an admin/governance action.

### Likelihood Explanation
Likelihood is tied directly to Arbitrum sequencer downtime events, which have occurred previously (multi-hour outages are publicly documented). Since `SimplexPaymaster` is designed to be deployed on any Chainlink-supported chain (BSC, Base, Ethereum, and Arbitrum per its `Params.nativeOracle` doc-comment referencing "BNB/USD on BSC, ETH/USD on Ethereum, etc."), and there is no code gating deployment away from Arbitrum, any Arbitrum deployment inherits this gap. I could not directly confirm from the indexed subset of `docs/content/developers/evm/contract-addresses/mainnet.mdx` whether an Arbitrum-mainnet `SimplexPaymaster` address is currently published (the grep matched but full context wasn't retrieved before the tool budget ran out), so exposure should be verified against the actual deployment list for this contract.

### Recommendation
Add an Arbitrum L2 sequencer-uptime check (per Chainlink's documented pattern using `IArbitrumSequencerUptimeFeed`, e.g. reverting when the feed reports the sequencer is down or the answer hasn't matured past the recommended grace period) inside `_getOraclePrice`, gated on the chain the paymaster is deployed to, so that both fee-pricing (`_tokenPrice`) and the swap-slippage bound in `swapAndDeposit` reject Chainlink answers observed while (or shortly after) the Arbitrum sequencer was down.

### Proof of Concept
1. Deploy `SimplexPaymaster` on Arbitrum with a registered token and native oracle, as in the existing `SimplexPaymasterTest.t.sol` setup. [5](#0-4) 
2. Simulate an Arbitrum sequencer outage by having the mock `latestRoundData()` return a stale-but-still-"fresh"-per-`maxOracleAge` price (i.e., `updatedAt` within the allowed window but the true off-chain price has since diverged materially).
3. Submit a UserOp through `validatePaymasterUserOp`/`_fetchDetails`; observe that `_getOraclePrice` accepts the answer and `_tokenPrice` charges the sender/paymaster at the stale rate, since there is no sequencer-liveness gate comparable to `testStaleOracleReverts`/`testNonPositiveOraclePriceReverts` in the existing test suite.     function _fetchDetails(
        PackedUserOperation calldata userOp,
        bytes32 /* userOpHash */
    )
        internal
        view
        override
        returns (uint256 validationData, IERC20 token, uint256 tokenPrice)
    {
        bytes calldata data = userOp.paymasterData();
        if (data.length < 21) revert InvalidPaymasterData(data.length);

        uint8 mode = uint8(data[0]);
        if (mode != 0x00 && mode != 0x02) revert InvalidMode(mode);

        address tokenAddr = address(bytes20(data[1:21]));

        TokenConfig memory cfg = tokenConfigs[tokenAddr];
        if (address(cfg.tokenOracle) == address(0)) revert TokenNotRegistered(tokenAddr);
        if (!cfg.active) revert TokenNotActive(tokenAddr);

        tokenPrice = _tokenPrice(cfg);
        token = IERC20(tokenAddr);
        validationData = 0; // no time-range restriction

        if (mode == 0x02) {
            (,,, uint256 deadline,,,) = _parsePermit2Data(data);
            // Surfacing the permit deadline as validUntil lets bundlers drop
            // expiring ops instead of discovering it through a Permit2 revert.
            uint48 validUntil = deadline > type(uint48).max ? 0 : uint48(deadline);
            validationData = ERC4337Utils.packValidationData(true, 0, validUntil);
        }
    }

    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
