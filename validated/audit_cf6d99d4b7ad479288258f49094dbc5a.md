### Title
Wiped-out supply shares stay claimable after full bad-debt socialization because `supply_index` is floored at `RAY/1000` — a use-after-free of destroyed supplier claims - (File: contracts/pool/src/interest.rs)

### Summary
The kernel bug is a use-after-free: `rkvdec_remove` frees an object that is still referenced later. The analog in XOXNO Lending is in the pool's bad-debt socialization: when unpaid debt equals or exceeds the entire supplied value of a market, `apply_bad_debt_to_supply_index` should destroy every supplier claim, but instead clamps `supply_index` upward to `SUPPLY_INDEX_FLOOR_RAW` (`RAY/1000`). Supplier positions (scaled shares stored in the controller) are never burned, so "freed" claims remain dereferenceable: `unscale_supply_floor(scaled)` still returns a positive amount, and a subsequent `withdraw` pays real tokens to a position that was economically wiped out — draining cash belonging to later depositors.

### Finding Description
`apply_bad_debt_to_supply_index` in `contracts/pool/src/interest.rs:73-89` computes `remaining = total_supplied_value - min(bad_debt, total_supplied_value)`. On a full wipeout, `remaining == 0` and `reduction_factor == 0`, so the new index should be 0 — but line 88 applies `new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW))`, resurrecting the index to `RAY/1000`. Every pre-existing scaled position `S_old` therefore still unscales to `S_old * RAY/1000 / RAY > 0`.

This path is reachable by any unprivileged address: controller `clean_bad_debt` calls `pool_seize_positions_call` (`contracts/controller/src/positions/liquidation/bad_debt.rs:48-49`), which invokes `seize::apply` (`contracts/pool/src/ops/seize.rs:24-28`), whose `AccountPositionType::Borrow` leg calls `interest::apply_bad_debt_to_supply_index` and burns only the debt. The supply shares on the wiped side are never burned — the deposit-side leg merely reclassifies the *liquidated account's* shares via `absorb_supply_as_revenue`, while unrelated suppliers' positions remain stored with nonzero `scaled_amount`.

Later, `withdraw` (`contracts/pool/src/ops/withdraw.rs:57-89`) calls `resolve_withdrawal` → unscale at the floored index, `burn_position`, and `gate_and_debit`, which enforces only `require_reserves(net_transfer)` — i.e., cash availability — not whether the claim should exist. The repository's own regression test `test_raw_cache_floor_clamp_strands_claim_without_supply_guard` (`contracts/pool/tests/interest.rs:372-427`) demonstrates the exploit end-to-end: after the floor clamp, a wiped position withdraws `gross == fresh_cash`, exactly draining a fresh depositor's claim and leaving `cash < fresh_claim`.

### Impact Explanation
Theft of user funds / protocol insolvency. Any scaled supply position opened before a full bad-debt wipeout becomes a phantom claim worth `scaled * 10^-24` of its nominal value per unit — still real token-denominated value payable by `withdraw`. An attacker can deliberately supply dust-sized positions into a market, then trigger or wait for a wipeout-level `clean_bad_debt`, and withdraw against the resurrected floor index, consuming cash deposited by new suppliers after the wipeout. Each phantom claim is small but proportional to the pre-wipeout position size; with large positions or many accounts, aggregate drain can exceed subsequent real deposits, leaving the pool unable to honor legitimate claims — the "contract unable to operate from lack of token funds" condition.

### Likelihood Explanation
Requires a market wipeout (`bad_debt >= total_supplied_value`), i.e., near-total loss on a spoke — achievable when a borrower's collateral collapses faster than liquidation, or on a thin/spam hub market the attacker creates themselves (low utilization, self-originated dust positions, then direct token transfers to the pool to seed fresh cash, or simply waiting for organic deposits). `clean_bad_debt` is permissionless once an account's debt falls under the dust threshold logic. No privileged access, oracle manipulation, or timing race is needed; the bug is a deterministic accounting error in the floor clamp, so severity is bounded by how often full wipeouts occur rather than by exploit difficulty.

### Recommendation
When `remaining == 0` (full wipeout), zero out the claims instead of flooring the index: either allow `supply_index` to reach exactly 0 and handle the zero-index case in `unscale_supply_*`/`calculate_scaled_supply` (treat `supplied > 0` with `index == 0` as a burned book), or burn `supplied`/`revenue` shares to zero alongside the index. At minimum, gate `withdraw` so a position whose unscaled value derives solely from the `SUPPLY_INDEX_FLOOR_RAW` clamp after `reduction_factor == 0` cannot pay out cash — e.g., persist a per-market "wiped" flag or store total-supplied-value at socialization time and reject withdrawals that exceed it. The `SUPPLY_INDEX_FLOOR_RAW` clamp exists to avoid a zero index for *partial* reductions; it must not apply when the reduction factor is exactly zero.

### Proof of Concept
1. Attacker supplies `S = 1000e18` scaled shares into market `(hub, A)` and a second account borrows against it; collateral price collapses (or the attacker engineers a thin market) so `clean_bad_debt(account_id)` is permitted.
2. Controller `clean_bad_debt` → `pool_seize_positions_call` → `seize::apply` with `side = Borrow`, `scaled_amount = D`: `apply_bad_debt_to_supply_index` computes `bad_debt >= total_supplied_value`, sets `supply_index = RAY/1000`, burns `D` debt. Attacker's `S` supply position is untouched in controller storage.
3. Attacker (or a confederate) supplies fresh `fresh_cash` into market `A`, restoring `cash > 0`.
4. Attacker calls `withdraw` on the wiped position: `resolve_withdrawal` unscales `S` at `index = RAY/1000` → `gross > 0`; `require_reserves(gross)` passes because fresh cash covers it; tokens are paid out.
5. Result: `cash < fresh_supplier_claim`; the fresh depositor's funds were stolen. This is exactly the trace encoded in `contracts/pool/tests/interest.rs:414-426`, where `gross == fresh_cash` and the assertion `cash() < fresh_claim` holds. pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}

fn gate_and_debit(env: &Env, cache: &mut Cache, net_transfer: i128, skip_utilization_check: bool) {
    cache.require_reserves(net_transfer);

    if !skip_utilization_check {
        guards::require_utilization_below_max(env, cache);
    }
    guards::require_supply_for_debt(env, cache);
    cache.debit_cash(net_transfer);
}
