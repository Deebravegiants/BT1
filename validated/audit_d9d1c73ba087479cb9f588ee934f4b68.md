### Title
Division by zero panic via unvalidated `minimum_stake_divisor` genesis/epoch parameter - ([File: chain/epoch-manager/src/lib.rs])

### Summary
`minimum_stake_divisor` is a one-time-settable genesis/epoch configuration parameter used to compute the minimum allowed validator stake as `seat_price / minimum_stake_divisor`. The division is performed with `checked_div(...).unwrap()`, and unlike other genesis parameters (e.g. `gas_price_adjustment_rate`, `online_min/max_threshold`), no validation rejects a zero value for `minimum_stake_divisor`. If it is ever configured as `0`, any code path that calls `EpochManager::minimum_stake` (reachable when processing a user-submitted `StakeAction` transaction) panics.

### Finding Description
`EpochManager::minimum_stake` computes: [1](#0-0) 

```rust
pub fn minimum_stake(&self, prev_block_hash: &CryptoHash) -> Result<Balance, EpochError> {
    ...
    let stake_divisor = { config.minimum_stake_divisor };
    Ok(seat_price.checked_div(u128::from(stake_divisor)).unwrap())
}
```

`minimum_stake_divisor` is declared as a `GenesisConfig`/`EpochConfig` field with a default of `10`, but it is fully overridable via genesis/epoch-config JSON: [2](#0-1) [3](#0-2) 

Unlike other rational/threshold genesis parameters that are explicitly checked in `core/chain-configs/src/genesis_validate.rs` (e.g. `gas_price_adjustment_rate`, `online_min_threshold`, `online_max_threshold`), a search of `genesis_validate.rs` shows no validation entry for `minimum_stake_divisor`, meaning a genesis file (or a protocol-config diff/epoch-config JSON) with `minimum_stake_divisor: 0` would be accepted at genesis/epoch-config load time. This mirrors exactly the reported bug class: a parameter that "can be set only one time" (a cage/genesis-style parameter) is not checked for a zero value before being used as a divisor.

`checked_div` returns `None` when the divisor is `0`, and the subsequent `.unwrap()` will panic. This function backs the stake-validation logic used when handling `StakeAction`s (`InsufficientStake` computation documented in `docs/RuntimeSpec/Actions.md`), i.e. it is on the path triggered by an ordinary, unprivileged user submitting a `StakeAction` transaction: [4](#0-3) 

### Impact Explanation
If `minimum_stake_divisor` is ever `0` in the effective epoch config, every attempt to process a `StakeAction` (an action any account can submit) triggers `unwrap()` on `None`, causing the runtime thread executing that chunk to panic. Because this is invoked from chunk application (state transition) rather than a network/RPC-only path, a panic here would abort chunk processing for every node applying the same chunk deterministically, i.e. a chain-wide halt/crash rather than a single node's inconsistency. This matches the report's "system may become temporarily or fully blocked" impact class.

### Likelihood Explanation
This requires an operator/protocol-config mistake (setting `minimum_stake_divisor` to `0` in genesis or an epoch-config diff) — analogous to the external report's exploit scenario of an admin mis-parameterizing a one-time-settable field. There is no on-chain, purely user-triggerable way to change `minimum_stake_divisor` (it is not a runtime-mutable parameter set via a transaction), so likelihood is low but the same as the original report's "high difficulty" configuration-error class: the danger is that nothing in the validation code currently prevents this misconfiguration, unlike sibling parameters that are explicitly checked.

### Recommendation
Add an explicit genesis/epoch-config validation check (in `core/chain-configs/src/genesis_validate.rs`, alongside the existing `gas_price_adjustment_rate`/`online_min_threshold`/`online_max_threshold` checks) that rejects `minimum_stake_divisor == 0`. Additionally, change `EpochManager::minimum_stake` in `chain/epoch-manager/src/lib.rs` to return an `EpochError` instead of panicking via `.unwrap()` when `checked_div` returns `None`, so that even a latent misconfiguration degrades gracefully (transaction/action rejection) rather than crashing the node/chain.

### Proof of Concept
1. Configure a genesis (`GenesisConfig`) or an epoch-config diff with `minimum_stake_divisor: 0`. No existing validation in `core/chain-configs/src/genesis_validate.rs` rejects this value.
2. Start the network with this genesis; wait for validator seat price to be computed for an epoch (any non-zero seat price).
3. Submit any `StakeAction` transaction from any account.
4. Runtime action processing calls `EpochManager::minimum_stake`, which executes `seat_price.checked_div(u128::from(0)).unwrap()`, returning `None.unwrap()`, panicking the thread applying the chunk and halting/crashing all nodes that process that chunk deterministically.

Note: I was unable to fully confirm during this session (due to iteration limits) whether some other higher-level config-loading path (outside `genesis_validate.rs`) independently enforces `minimum_stake_divisor != 0`; the grep results only showed no matches for that field within `genesis_validate.rs`. This should be double-checked by directly inspecting `EpochConfigBuilder::build()` and any `TryFrom` validation for `EpochConfig`/`GenesisConfig` before treating this as a fully confirmed unguarded path.

    pub fn minimum_stake(&self, prev_block_hash: &CryptoHash) -> Result<Balance, EpochError> {
        let next_epoch_id = self.get_next_epoch_id_from_prev_block(prev_block_hash)?;
        let (protocol_version, seat_price) = {
            let epoch_info = self.get_epoch_info(&next_epoch_id)?;

        let config = self.config.for_protocol_version(protocol_version);

    }
