### Title
Permanent market freeze: RAY-scaled debt value overflows `i128` during accrual, reverting every pool verb - ([File: common/src/rates/compound.rs](common/src/rates/compound.rs), [contracts/pool/src/interest.rs](contracts/pool/src/interest.rs))

### Summary
Analogous to CVE-2021-2402 (a hang/crash → complete DoS), a market whose RAY-scaled total debt value approaches the `i128` ceiling permanently freezes: every state-mutating entrypoint runs `interest::global_sync` first, and accrual computes `scaled_to_original(borrowed, borrow_index)` — a `shares × index` product that panics with `MathOverflow` when it exceeds `i128::MAX`. Once the market crosses that threshold, no repay, withdraw, supply, seize, or liquidation can succeed, permanently freezing all user funds in the market. The index ceiling `MAX_BORROW_INDEX_RAY` (10^36 raw) does not protect against this because the value overflow fires before the index cap engages.

### Finding Description
Every pool mutation follows `Cache::load → interest::global_sync → mutate → guards → commit`. `global_sync` calls `accrue_chunk` → `accrue_step`, which re-derives the total debt value via `scaled_to_original(borrowed_scaled, borrow_index)` — an `i128` multiply-divide (`borrowed` is RAY-scaled shares, `borrow_index` is RAY). For a whale-scale market (`borrowed` shares ≈ 10^27 × token count), the product exceeds `i128::MAX` long before `borrow_index` reaches the 10^36 cap. The panic is unconditional and permanent: it depends only on `borrowed` and `borrow_index`, both of which can only grow absent successful repays — and repays are themselves blocked because they accrue first.

The protocol's own test harness demonstrates the freeze end-to-end: `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` seeds a 10^27-token market at ~98% utilization, advances time, and shows `update_indexes`, `withdraw`, and `repay` all reverting with `MathOverflow` while `borrow_index < MAX_BORROW_INDEX_RAY` (`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:316-361`). `INV-IDX-01` concedes the gap: "Bounded indexes do not guarantee representable position or market values" (`docs/reference/invariants.md:229-236`).

An unprivileged attacker constructs this with only standard verbs: `supply` a very large amount of a high-decimals (18-decimal) asset to the pool, `borrow` it near max utilization via the controller (with collateral in a second asset), then keep utilization pinned — no further action needed; time does the rest. Direct token transfers to the pool and third-party `supply` top-ups are also attacker-controlled levers to inflate `supplied`/`borrowed` share counts.

### Impact Explanation
Permanent freezing of funds: once `borrowed × borrow_index` exceeds `i128::MAX` in the accrual path, every entrypoint on that market (`supply`, `withdraw`, `borrow`, `repay`, `seize_positions`, `claim_revenue`, `recapitalize`, `flash_loan`) reverts in `global_sync` before touching state. Suppliers' deposits, borrowers' collateral claims, and protocol revenue in the market are all unreachable forever — `recapitalize` cannot rescue the market because it too accrues first. On the controller side, `update_indexes` fails, and any position whose health requires the frozen market's index (liquidations via `liquidate`, `clean_bad_debt`) is also bricked for that asset.

### Likelihood Explanation
Medium. The attack requires whale-scale capital: the harness uses ~10^9 × 10^18 units (10^27 raw) of an 18-decimal token at ~98% utilization to hit the cliff within decades on the steep curve segment — a large but finite capital requirement, and for a token with a large real supply (e.g., a meme/stable asset at cap `max_cap_for_decimals`) the absolute amount can be within reach. The attacker must also sustain high utilization for a sustained period, which requires either a genuinely large borrow (needing commensurate collateral, recoverable but locked) or a market with low `max_utilization`/thin liquidity. No privilege, oracle manipulation, or leaked key is needed — only `supply` and `borrow`. Likelihood is bounded by capital availability and the existence of a market whose allowed caps permit the share magnitude.

### Recommendation
Make accrual overflow-safe rather than relying on the index cap:
1. In `accrue_step`, saturate (rather than panic) when `scaled_to_original(borrowed, borrow_index)` overflows — e.g., clamp `borrow_index` at `MAX_BORROW_INDEX_RAY` earlier, or compute the debt value with saturating `I256` semantics so accrual becomes a no-op at the ceiling instead of a panic.
2. Alternatively, add a pre-check in `global_sync`/`accrue_chunk`: if the debt value overflows, freeze interest accrual for the market (`mark_accrued` without mutating indexes) so that repay/withdraw paths remain usable — the index cap already implies this behavior.
3. Enforce per-market supply/borrow caps (`max_cap_for_decimals` / `SpokeUsageContext::apply_entry`) tightly enough that `borrowed_scaled × MAX_BORROW_INDEX_RAY` cannot overflow `i128`, i.e., cap raw share counts below `i128::MAX / 10^36`.

### Proof of Concept
The protocol's own harness reproduces the freeze (`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-361`):

```rust
let mut t = LendingTest::new()
    .with_market(big("BIG18", 18, xlm_curve()))
    .with_market(col())
    .with_max_utilization_disabled_all_markets()
    .build();
lift_caps(&t, "BIG18", 18);
lift_caps(&t, "COL", 7);
let principal = BILLION * 10i128.pow(18);          // whale supply, unprivileged supply()
t.supply_raw(BOB, "BIG18", principal);
let debt = principal / 100 * 98;                    // 98% utilization
t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
t.borrow_raw(ALICE, "BIG18", debt);

loop {
    t.advance_time(YEAR_SECS);
    if let Err(e) = t.try_update_indexes_for(&["BIG18"]) { break e; }
}
// accrual now panics with MathOverflow; borrow_index < MAX_BORROW_INDEX_RAY
assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
// market permanently frozen: every verb accrues first
```

Root-cause chain: `entrypoint → Cache::load → interest::global_sync` (`contracts/pool/src/interest.rs:20-33`) → `accrue_chunk → accrue_step` → `scaled_to_original(borrowed, borrow_index)` (multiply-divide via `I256`→`i128`, panicking `MathOverflow` on overflow, same panic shape as `compound_interest` at `common/src/rates/compound.rs:36-42`). Note uncertainty: the exact line inside `accrue_step` where the value product overflows (`common/src/rates/index.rs`/`value.rs`) was not read directly in this review, but the harness test confirms the panic and the frozen-state consequence end-to-end.
