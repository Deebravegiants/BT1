### Title
Missing audit-log event on user role privilege escalation - ([File: core/web/user_controller.go])

### Summary
`UserController.UpdateRole` changes an API user's role (e.g. promoting a user from `view`/`run` to `admin`) but never emits an audit event, unlike every other sensitive credential/role-affecting operation in the same controller.

### Finding Description
`UserController.UpdateRole` binds the request, validates the target email/role, calls `u.App.AuthenticationProvider().UpdateRole(ctx, request.Email, request.NewRole)`, and returns the updated user resource — with no call to `u.App.GetAuditLogger().Audit(...)` anywhere in the function. [1](#0-0) 

The underlying ORM implementation similarly performs the role overwrite and purges the user's sessions without any audit/event emission — it only logs internal error cases via the regular (non-audit) logger: [2](#0-1) 

This is inconsistent with the rest of the same controller, where every other credential-affecting action (`Create`, `Delete` via the "unable to delete" path, `UpdatePassword`, `NewAPIToken`, `DeleteAPIToken`) explicitly calls `u.App.GetAuditLogger().Audit(...)` for both success and failure paths: [3](#0-2) [4](#0-3) [5](#0-4) 

There is no corresponding `audit.*` event type for role changes defined anywhere in the audit type catalog, confirming this is a genuine gap rather than an existing-but-unused event.

### Impact Explanation
Role changes are one of the most security-critical operations exposed by the node's API (`PATCH /v2/users`) — a role upgrade to `admin` grants full control over the node (spec management, key management, other users, funds movement via job specs). Because no audit event is emitted, off-chain monitoring/SIEM pipelines that rely on the Chainlink audit log (as intended by the existing `audit.PasswordResetSuccess`, `audit.APITokenCreated`, etc. events) have no way to detect that a user's privileges were escalated or downgraded. Combined with the fact that all existing sessions for the affected user are silently purged (`DELETE FROM sessions WHERE email = ...`), an operator reviewing the audit trail would have no record explaining a user's sudden logout or privilege change, delaying detection of unauthorized or malicious role changes.

### Likelihood Explanation
The `UpdateRole` endpoint is reachable by any authenticated API user holding the `admin` role (the operator boundary the report's rules exclude), so this is not exploitable by a fully unprivileged actor to escalate their own privileges directly (self-edit is blocked). However, the missing-event gap itself is deterministic and triggers on every legitimate role-change call, and it is directly analogous to the reported bug class: critical state (role/permissions) changes with no emitted event for off-chain detection.

### Recommendation
Add an audit log call in `UserController.UpdateRole` (mirroring the pattern already used elsewhere in the file), e.g. `u.App.GetAuditLogger().Audit(audit.UserRoleUpdated, map[string]any{"user": request.Email, "newRole": request.NewRole, "changedBy": sessionUser.Email})` immediately after the role update succeeds, and define a corresponding `UserRoleUpdated` audit event type in `core/logger/audit/audit_types.go`. Consider also emitting an event on failed attempts (e.g., invalid role) for consistency with other endpoints.

### Proof of Concept
1. As an authenticated `admin` user, call `PATCH /v2/users` with `{"email":"victim@example.com","newRole":"admin"}`.
2. Observe the role change succeeds (`200 OK`, user resource returned) and the target's existing sessions are purged.
3. Inspect the audit log output (as configured via `AuditLogger`) — no `UserRoleUpdated`/equivalent event is present, unlike `PasswordResetSuccess` or `APITokenCreated` events that appear for other user actions in the same controller.

// UpdateRole changes role field of a specified API user.
func (u *UserController) UpdateRole(c *gin.Context) {
	ctx := c.Request.Context()
	type updateUserRequest struct {
		Email   string `json:"email"`
		NewRole string `json:"newRole"`
	}

	var request updateUserRequest
	if err := c.ShouldBindJSON(&request); err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	// Don't allow current admin user to edit self
	sessionUser, ok := webauth.GetAuthenticatedUser(c)
	if !ok {
		jsonAPIError(c, http.StatusInternalServerError, errors.New("failed to obtain current user from context"))
		return
	}
	if strings.EqualFold(sessionUser.Email, request.Email) {
		jsonAPIError(c, http.StatusBadRequest, errors.New("can not change state or permissions of current admin user"))
		return
	}

	// In case email/role is not specified try to give friendlier/actionable error messages
	if request.Email == "" {
		jsonAPIError(c, http.StatusBadRequest, errors.New("email flag is empty, must specify an email"))
		return
	}
	if request.NewRole == "" {
		jsonAPIError(c, http.StatusBadRequest, errors.New("new-role flag is empty, must specify a new role, possible options are 'admin', 'edit', 'run', 'view'"))
		return
	}
	_, err := clsession.GetUserRole(request.NewRole)
	if err != nil {
		jsonAPIError(c, http.StatusBadRequest, errors.New("new role does not exist, possible options are 'admin', 'edit', 'run', 'view'"))
		return
	}

	user, err := u.App.AuthenticationProvider().UpdateRole(ctx, request.Email, request.NewRole)
	if err != nil {
		if errors.Is(err, clsession.ErrNotSupported) {
			jsonAPIError(c, http.StatusBadRequest, errUnsupportedForAuth)
			return
		}
		jsonAPIError(c, http.StatusInternalServerError, errors.Wrap(err, "error updating API user"))
		return
	}

	jsonAPIResponse(c, presenters.NewUserResource(user), "user")
}

// UpdateRole overwrites role field of the user specified by email.
func (o *orm) UpdateRole(ctx context.Context, email, newRole string) (sessions.User, error) {
	var userToEdit sessions.User

	if newRole == "" {
		return userToEdit, pkgerrors.New("user role must be specified")
	}

	err := sqlutil.TransactDataSource(ctx, o.ds, nil, func(tx sqlutil.DataSource) error {
		// First, attempt to load specified user by email
		if err := tx.GetContext(ctx, &userToEdit, "SELECT * FROM users WHERE lower(email) = lower($1)", email); err != nil {
			return pkgerrors.New("no matching user for provided email")
		}

		// Patch validated role
		userRole, err := sessions.GetUserRole(newRole)
		if err != nil {
			return err
		}
		userToEdit.Role = userRole

		_, err = tx.ExecContext(ctx, "DELETE FROM sessions WHERE email = lower($1)", email)
		if err != nil {
			o.lggr.Errorw("Failed to purge user sessions for UpdateRole", "err", err)
			return pkgerrors.New("error updating API user")
		}

		sql := "UPDATE users SET role = $1, updated_at = now() WHERE lower(email) = lower($2) RETURNING *"
		if err := tx.GetContext(ctx, &userToEdit, sql, userToEdit.Role, email); err != nil {
			o.lggr.Errorw("Error updating API user", "err", err)
			return pkgerrors.New("error updating API user")
		}

		return nil
	})

	return userToEdit, err
}
