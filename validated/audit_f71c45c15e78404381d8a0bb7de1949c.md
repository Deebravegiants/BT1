### Title
BEEFY consensus supermajority threshold counts raw vote entries instead of unique authorities, allowing a single compromised/reused signature to be replayed under distinct indices to forge quorum - ([File: evm/src/consensus/EcdsaBeefy.sol])

### Summary
Both the Solidity and Rust BEEFY consensus verifiers compute the 2/3+1 supermajority threshold purely from the *length* of the submitted votes/signatures array, without deduplicating by authority identity or `authorityIndex`. `Vote`/`SignatureWithAuthorityIndex` entries carry an attacker-chosen `authorityIndex` alongside a signature; nothing rejects two (or more) entries that recover to the same signer, or entries that redundantly claim the same `authorityIndex`. By contrast, the Pharos verifier in this same codebase explicitly guards this exact bug class with a `BTreeSet`-based `DuplicateParticipant` check [1](#0-0) , and the sync-committee/BSC verifiers are structurally immune because participation is a bitset where a validator position can only be set once [2](#0-1) . BEEFY's vote-array representation has no equivalent protection.

### Finding Description
The Solidity `EcdsaBeefy.verifyMmrUpdateProof` takes `sigLen = relayProof.signedCommitment.votes.length` and checks it against the supermajority threshold before doing any per-authority verification: [3](#0-2) 

Each `Vote` supplies its own `signature` and `authorityIndex`; the loop recovers an address per vote and builds a `MerkleMultiProof.Leaf` keyed on the attacker-supplied `authorityIndex`, then verifies membership. Crucially:
- `checkParticipationThreshold(sigLen, authoritySet.len)` at line 140 only counts array length — not distinct authority indices, not distinct recovered addresses.
- There is no `require`/check anywhere in this function, or in `Types.sol`, rejecting duplicate `vote.authorityIndex` values across the `votes` array.

The identical structure exists in the Rust light-client verifier used by `pallet-ismp`: [4](#0-3) 

`signatures_length = mmr.signed_commitment.signatures.len()` is checked against `check_participation_threshold` at line 131, and `authority_indices`/`authority_leaves` built at lines 146-162 are passed to `merkle_proof.verify(...)` with no uniqueness enforcement on `sig.index`.

This mirrors the sigstore-go bug class precisely: the threshold-satisfaction test counts *entries* (votes/signatures submitted) rather than *distinct authorities*, so a party who controls (or has leaked) a single authority's ECDSA key can submit that one signature multiple times under different (or even the same) `authorityIndex` values, inflating `sigLen`/`signatures_length` past the 2/3+1 bound while the number of truly independent signers backing the commitment can be far below threshold. If the underlying `MerkleMultiProof.VerifyProof` / `rs_merkle` multi-proof verification does not itself reject repeated indices/leaves (this codebase does not vendor that library, so its exact duplicate-handling behavior could not be directly inspected here), the forged quorum sails through both consensus clients, letting the attacker post an authority-set-forged MMR root/parachain header set as though it were finalized by BEEFY.

### Impact Explanation
BEEFY (`EcdsaBeefy.sol` and `pallet-ismp`'s `beefy/verifier`) is the primary consensus client anchoring Hyperbridge's cross-chain state commitments from the relay chain to every connected EVM/Substrate destination. A forged supermajority would let an attacker with one compromised (or leaked) BEEFY authority key push an arbitrary MMR root / parachain header, forging state commitments that downstream `pallet-ismp handle_unsigned`/`HandlerV2` message delivery and state-membership proofs trust as finalized. This is a direct path to forged message delivery and unbacked state commitments across all bridged chains relying on this consensus client — a Critical-severity class of impact (matching the CWE-345/347 categories in the analog report), though it requires possession of at least one legitimate signing key rather than zero trust assumptions, similar to the sigstore-go analog requiring compromise of one log authority.

### Likelihood Explanation
Exploitation requires control of at least one currently-active BEEFY authority signing key (or a leaked/stolen key), which is a real but non-trivial precondition — this is not exploitable by a fully unprivileged party with zero validator involvement, and unlike Pharos, BEEFY's participant set is large (Polkadot relay-chain validator set), making outright compromise harder than a single-relayer/API scenario. However, given the codebase already had to explicitly patch this exact bug class in the Pharos verifier (`DuplicateParticipant`), the absence of the same guard for BEEFY strongly suggests it was overlooked rather than intentionally deemed safe, and the actual safety currently rests entirely on an un-audited (in this review) property of the external `solidity-merkle-trees` / `rs_merkle` libraries correctly rejecting duplicate leaf indices — which was not confirmed.

### Recommendation
Add explicit deduplication before computing/checking the supermajority threshold in both verifiers:
- In `EcdsaBeefy.verifyMmrUpdateProof` (`evm/src/consensus/EcdsaBeefy.sol`), reject the proof if any `vote.authorityIndex` value repeats in `relayProof.signedCommitment.votes`, and/or dedupe by recovered `address` before computing `sigLen` used in `checkParticipationThreshold`.
- In `verify_mmr_update_proof` (`modules/consensus/beefy/verifier/src/lib.rs`), reject if `authority_indices` (or the corresponding recovered addresses) contains duplicates before comparing `signatures_length` against `check_participation_threshold`, mirroring the `BTreeSet`-based check already used in `modules/consensus/pharos/verifier/src/lib.rs::verify_validator_membership`.

### Proof of Concept
1. Obtain (or compromise) a single valid BEEFY authority ECDSA key, `k`, at real authority index `i` in the current authority set.
2. Compute `commitmentHash = keccak256(Codec.Encode(commitment))` for a target relay-chain commitment (either the real one, or a forged one whose only requirement is a fresh MMR root and `blockNumber > trusted latest height`).
3. Sign `commitmentHash` once with `k`, producing signature `sig`.
4. Construct `relayProof.signedCommitment.votes` as `⌈(2/3·N)+1⌉` copies of `Vote{signature: sig, authorityIndex: i}` (or the same signature replayed under other unused/duplicate index values) so that `sigLen` clears `checkParticipationThreshold`.
5. Submit this proof via `EcdsaBeefy.verify` (or the Rust equivalent via `update_client`); the participation check at `evm/src/consensus/EcdsaBeefy.sol` line 140 (or `modules/consensus/beefy/verifier/src/lib.rs` line 131) passes purely on entry count, and every recovered-address membership check against the merkle authority-set root succeeds because they all resolve to the one genuine key `i`.
6. If `MerkleMultiProof.VerifyProof`/`rs_merkle`'s multi-proof verify does not itself reject repeated `(index, hash)` leaf entries, the proof is accepted, advancing `trustedState`/`ConsensusState` and any embedded parachain/state commitments as though a real supermajority had signed — despite only one authority actually participating.

Note: this PoC's final step depends on the duplicate-index handling of the external `@polytope-labs/solidity-merkle-trees` and `rs_merkle` libraries, whose source was not available for direct inspection in this repository; this should be verified against those library implementations before treating the finding as fully confirmed.

fn verify_validator_membership(
	validator_set: &ValidatorSet,
	participants: &[BlsPublicKey],
) -> Result<(), Error> {
	let deduped: alloc::collections::BTreeSet<&[u8]> =
		participants.iter().map(|k| k.as_ref()).collect();
	if deduped.len() != participants.len() {
		return Err(Error::DuplicateParticipant);
	}
	if let Some(key) = participants.iter().find(|key| !validator_set.contains(key)) {
		return Err(Error::UnknownValidator { key: key.clone() });
	}
	Ok(())

pub fn verify_mmr_update_proof<H: Keccak256 + EcdsaRecover + Send + Sync>(
	mut trusted_state: ConsensusState,
	mmr: MmrProof,
) -> Result<(ConsensusState, H256), Error> {
	let signatures_length = mmr.signed_commitment.signatures.len();
	let latest_height = mmr.signed_commitment.commitment.block_number;

	if trusted_state.latest_beefy_height >= latest_height {
		return Err(Error::StaleHeight {
			trusted_height: trusted_state.latest_beefy_height,
			current_height: latest_height,
		});
	}

	let commitment = mmr.signed_commitment.commitment.clone();

	// Pick the authority set the commitment claims to be signed under, then judge
	// participation against that set alone.
	let authority_set = if commitment.validator_set_id == trusted_state.current_authorities.id {
		&trusted_state.current_authorities
	} else if commitment.validator_set_id == trusted_state.next_authorities.id {
		&trusted_state.next_authorities
	} else {
		return Err(Error::UnknownAuthoritySet { id: commitment.validator_set_id });
	};

	if !check_participation_threshold(signatures_length as u32, authority_set.len) {
		return Err(Error::SuperMajorityRequired);
	}

	let mmr_root_data = commitment
		.payload
		.get_raw(&MMR_ROOT_PAYLOAD_ID)
		.ok_or(Error::MmrRootHashMissing)?;

	if mmr_root_data.len() != 32 {
		return Err(Error::InvalidMmrRootHashLength { len: mmr_root_data.len() });
	}
	let mmr_root = H256::from_slice(mmr_root_data);

	let commitment_hash = H::keccak256(&commitment.encode());
	let mut authority_leaves: Vec<[u8; 32]> = Vec::new();
	let mut authority_indices = Vec::new();

	for sig in mmr.signed_commitment.signatures.iter() {
		let uncompressed = H::secp256k1_recover(&commitment_hash.0, &sig.signature)
			.map_err(|_| Error::FailedToRecoverPublicKey)?;

		let hashed_uncompressed = H::keccak256(&uncompressed);

		let mut eth_address = [0u8; 20];
		eth_address.copy_from_slice(&hashed_uncompressed.as_ref()[12..]);

		let authority_address_hash = H::keccak256(&eth_address);

		authority_leaves.push(authority_address_hash.into());
		authority_indices.push(sig.index as usize);
	}

	let merkle_proof = MerkleProof::<MerkleHasher<H>>::new(mmr.authority_proof.clone());

	let valid = merkle_proof.verify(
		authority_set.keyset_commitment.into(),
		&authority_indices,
		&authority_leaves,
		authority_set.len as usize,
	);

	if !valid {
		Err(Error::InvalidAuthoritiesProof)?;
	}
