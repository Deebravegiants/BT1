### Title
Unauthenticated relayer identity in `extract_signer` allows forging the delivering-relayer for relayer-fee attribution - (File: `modules/pallets/ismp/src/host.rs`)

### Summary
`pallet-ismp`'s `handle_unsigned` extrinsic is a permissionless, unsigned call that anyone can submit with a valid message proof [1](#0-0) . When a `RequestMessage`/`ResponseMessage` is executed, the pallet stores a "receipt" that records which account is credited as the delivering relayer, using `store_request_receipt`/`store_response_receipt` [2](#0-1) . Both call `extract_signer`, which decodes the caller-supplied `signer` bytes as a `Signature` enum and returns the embedded public key/address field via `.signer()` — **without ever cryptographically verifying that the signature is valid for anything** [3](#0-2) . `Signature::signer()` simply reads the struct field the caller populated [4](#0-3) ; it performs no `verify()` call.

### Finding Description
The `signer` field of `RequestMessage`/`ResponseMessage` is documented as "Signer information. Ideally should be their account identifier" and is fully attacker-controlled, since `handle_unsigned` requires no signed origin (`ensure_none(origin)?`) [1](#0-0) . During message execution, `handlers::handle_incoming_message` calls `host.store_request_receipt(&wrapped_req, &msg.signer)` with this raw, unverified byte string [5](#0-4) . `store_request_receipt` decodes it purely to extract an address/public key and writes that value into `RequestReceipts`/`ResponseReceipts` in the child trie as the "relayer" of record [2](#0-1) .

This receipt value is later trusted as ground truth for who delivered a message. `pallet-relayer`'s `decode_receipt_relayer` explicitly documents that for substrate destinations the stored value is "the signer bytes or a signature to recover the signer from" [6](#0-5) , and this decoded identity is what outbound-delivery reward claims (`process_outbound_request_delivery_claim`) check against a relayer-supplied signature to authorize a fee payout [7](#0-6) . Because the *receipt itself* was populated from an unauthenticated field, an attacker submitting `handle_unsigned` can set `msg.signer` to `Signature::Sr25519 { public_key: <attacker-controlled account>, signature: <arbitrary garbage> }` (or the `Evm`/`Ed25519` variants) and have that arbitrary identity permanently recorded as "the relayer who delivered this request" — with no proof of possession of any corresponding private key, since no signature check ever runs on this path.

By contrast, other places in the codebase that use the `signer` field for money movement do perform real cryptographic verification — e.g. `WeightFeeHandler::on_executed` (charges the request's fee payer) [8](#0-7)  and `messaging-incentives`'s `relayer_for` (mints incentive tokens) [9](#0-8)  both call `verify_and_get_sr25519_pubkey`. `extract_signer`/`store_request_receipt` is the one path that records a relayer identity for delivery-attribution purposes without any such check.

### Impact Explanation
The recorded receipt identity is the value that downstream reward/withdrawal logic (`decode_receipt_relayer`, outbound delivery reward claims) treats as the authenticated proof of "who gets paid for delivering this message." Since that identity can be forged for free by anyone submitting the free/unsigned `handle_unsigned` extrinsic, an attacker can consistently redirect relayer fees/rewards intended for the honest party who actually did the work (or simply mint fee credit for themselves on every message that passes through), resulting in theft of relayer fee funds/rewards — a concrete "unbacked" credit/fund-theft class impact, directly analogous to the CVE's "attackers could log in [authenticate] without authorization," here realized as "attackers can authenticate as an arbitrary relayer without authorization."

### Likelihood Explanation
`handle_unsigned` is by design callable by anyone with no signed origin and no economic cost beyond gas/weight — it is the primary permissionless relaying path exercised constantly in the codebase's own tests (e.g. `should_charge_fee_for_request`, `test_incentivize_relayer`) [10](#0-9) . Forging the `signer` field costs nothing extra (no valid signature is required for the `store_request_receipt` path), and requires only submitting a normal, otherwise-valid membership proof.

### Recommendation
`extract_signer`/`store_request_receipt`/`store_response_receipt` should cryptographically verify the supplied `Signature` (via `Signature::verify`) against a canonical message (e.g. the request/response commitment, or the submitting account) before trusting `.signer()` as the delivering relayer, mirroring the verification already performed in `WeightFeeHandler` and `messaging-incentives::relayer_for`. Alternatively, bind the recorded relayer identity to the actual transaction submitter (the account paying for/propagating the extrinsic) rather than an arbitrary self-declared field.

### Proof of Concept
1. Attacker observes a legitimate, still-undelivered `PostRequest` batch with a valid membership proof for `pallet-ismp` on Hyperbridge (or crafts their own if permitted destinations exist).
2. Attacker calls `Ismp::handle_unsigned(origin: None, messages: vec![Message::Request(RequestMessage { requests, proof, signer: Signature::Sr25519{ public_key: ATTACKER_TARGET, signature: [0u8;64] }.encode() })])`.
3. `handle_unsigned` passes `ensure_none` and executes via `Self::execute` → `handle_incoming_message` → `store_request_receipt(&req, &msg.signer)` [5](#0-4) .
4. `extract_signer` decodes the `Signature::Sr25519` and returns `public_key = ATTACKER_TARGET` without checking the (garbage) `signature` field at all [3](#0-2) .
5. `RequestReceipts[commitment] = ATTACKER_TARGET` is now on-chain state, provable via a standard storage/state proof to any downstream reward-claim logic that trusts this receipt as evidence of legitimate delivery.

Note: I was unable to fully trace, within the available tool budget, every downstream consumer of the on-chain `RequestReceipts`/`ResponseReceipts` value (e.g. the exact fund-transfer code path in `pallet-ismp-relayer`'s `accumulate_fees`) to confirm end-to-end that a real balance transfer is triggered purely off this unverified receipt for locally-processed (same-chain) requests versus only for the documented cross-chain outbound-reward claim path. The `outbound_request.rs`/`accumulate.rs` code and its accompanying design doc do establish that this receipt value is the authoritative "who delivered it" signal used to authorize reward payouts for cross-chain deliveries, which is sufficient to establish the improper-authentication root cause and its fund-theft potential, but a full audit of every reward-payment code path was not completed.

fn extract_signer(signer: &[u8]) -> Result<Vec<u8>, Error> {
	if signer.len() > 32 {
		Signature::decode(&mut signer.as_ref())
			.map(|sig| sig.signer())
			.map_err(|_| Error::SignatureDecodingFailed)
	} else {
		Ok(signer.to_vec())
	}
}

	/// Decode a proven `RequestReceipts[commitment]` value into the delivering
	/// relayer's bytes. EVM stores the address RLP encoded, substrate stores the
	/// signer bytes or a signature to recover the signer from. Used by both fee
	/// accumulation and the outbound request delivery claim.
	pub fn decode_receipt_relayer(state_id: StateMachine, raw: &[u8]) -> Result<Vec<u8>, Error<T>> {
		match state_id {
			s if crate::is_pharos(&s) =>
				if raw.len() == 32 {
					Ok(Address::from_slice(&raw[12..]).0.to_vec())
				} else {
					Err(Error::<T>::ProofValidationError)
				},
			s if s.is_evm() => {
				use alloy_rlp::Decodable;
				Ok(Address::decode(&mut &*raw)
					.map_err(|_| Error::<T>::ProofValidationError)?
					.0
					.to_vec())
			},
			s if s.is_substrate() => {
				use codec::Decode;
				let bytes =
					<Vec<u8>>::decode(&mut &*raw).map_err(|_| Error::<T>::ProofValidationError)?;
				Ok(if bytes.len() > 32 {
					Signature::decode(&mut &*bytes)
						.map_err(|_| Error::<T>::SignatureDecodingError)?
						.signer()
				} else {
					bytes
				})
			},
			_ => Err(Error::<T>::MismatchedStateMachine),
		}
	}

	/// Recover the relayer's account from the sr25519 signature on a
	/// `Message`'s `signer` field. Returns `None` if the message has
	/// no signer (e.g. consensus messages) or the signature is bad.
	fn relayer_for(message: &Message) -> Option<T::AccountId> {
		let (signer, signed) = match message {
			Message::Request(msg) =>
				(&msg.signer, sp_io::hashing::keccak_256(&msg.requests.encode())),
			Message::Response(msg) =>
				(&msg.signer, sp_io::hashing::keccak_256(&msg.requests.encode())),
			_ => return None,
		};
		Signature::decode(&mut &signer[..])
			.ok()?
			.verify_and_get_sr25519_pubkey(&signed, None)
			.ok()
			.map(T::AccountId::from)
	}

fn should_charge_fee_for_request() {

		Balances::mint_into(&signer_account, initial_balance).unwrap();

		let treasury_pallet_id = TreasuryAccount::get();
		let treasury_account = treasury_pallet_id.into_account_truncating();

		let post_request = PostRequest {
			source: id.state_id,
			dest: host.host_state_machine(),

			from: vec![1; 32],

			timeout_timestamp: 0,
			body: b"body".to_vec(),
		};

		let requests = vec![post_request];
		let signed_data = keccak_256(&requests.encode());
		let signature = signer_pair.sign(&signed_data);
		let signature = Signature::Sr25519 {
			public_key: signer_pair.public().to_raw_vec(),
			signature: signature.to_raw_vec(),
		};

		let request_message = RequestMessage {
			requests,
			proof: Proof {
				height: StateMachineHeight {
					id: StateMachineId { state_id: id.state_id, consensus_state_id: *b"mock" },
					height: 3,

				proof: vec![],
			},
			signer: signature.encode(),

		let expected_fee = 50 * UNIT;

		pallet_ismp::Pallet::<Test>::handle_unsigned(RuntimeOrigin::none(), vec![message]).unwrap();

		let final_signer_balance = Balances::balance(&signer_account);
		let final_treasury_balance = Balances::balance(&treasury_account);

		assert_eq!(final_signer_balance, initial_balance - expected_fee);
		assert_eq!(final_treasury_balance, initial_treasury_balance + expected_fee);
