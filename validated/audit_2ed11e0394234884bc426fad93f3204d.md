### Title
Unguarded Uniswap V4 spot-price venue pricing lets an attacker manipulate a thin pool to drain a Simplex solver's inventory - (File: sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts, sdk/packages/simplex/src/strategies/fx.ts)

### Summary
Simplex's `FXFiller` can price a curveless pair entirely off a live Uniswap V4 pool's instantaneous spot price instead of a static bid/ask curve. This is the same bug class as the USSD report: a protocol derives a mint/fill price directly from a single DEX pool's current price with no mandatory deviation/TWAP protection, so an attacker who can move that pool (especially one with thin liquidity, as flagged in the external report) can force the solver to fill orders at a manipulated rate.

### Finding Description
When `[vault.uniswapV4]` lists at least one position and a pair omits `bidPriceCurve`/`askPriceCurve`, `FXFiller` prices that pair from the pool's current spot price rather than an operator-defined curve, as described in `docs/content/developers/evm/simplex/pricing.mdx` ("Pool-Based Pricing"). The read path is:

`resolveLegRates` → `venuePriceMemo`/`getVenueUsdPrice` → `UniswapV4FundingPlanner.getExoticTokenPrice` → `computeDirectPoolPriceUsd`, which returns `sdkPool.token0Price`/`token1Price` — the raw instantaneous price derived from `sqrtPriceX96` — for the most-liquid qualifying pool [1](#0-0) [2](#0-1) .

This is a **spot price**, not a TWAP, with no size/impact term applied, as the internal design notes confirm: "`computeDirectPoolPriceUsd` returns the raw pool mid derived from `sqrtPriceX96`... and there is no size or impact term" [3](#0-2) .

The only defense is an **optional** price guard (`referencePrice` + `maxDeviationBps`) checked in `FXFiller.checkPriceGuard`, and both fields must be set together — "omit both to leave the chain unguarded" [4](#0-3) [5](#0-4) . Config validation only enforces that the two fields co-occur, never that they exist at all [6](#0-5) .

An attacker (an unprivileged intent placer, i.e. exactly the "intent solver"-adjacent user path) who can move the referenced Uniswap V4 pool — trivial when it is thin, mirroring the wBGL/wETH pool cited in the original USSD report — can push `computeDirectPoolPriceUsd`'s output far from fair value, then submit (or induce a fill of) an order priced off that manipulated quote before the pool reverts, extracting solver inventory at a bad rate.

### Impact Explanation
An exploited pool-price venue causes the Simplex solver to deliver output tokens (from its own wallet/vault or via Uniswap V4 LP withdrawal, `planWithdrawalForToken`) valued far above what it receives in input tokens, a direct and concrete loss of solver funds analogous to the USSD stablecoin's unbacked-mint exposure. Because pool-based pricing is explicitly designed for exactly the "thin, exotic-token pool" scenario (`cNGN`, etc. paired against USDC/USDT) that the external report warns about, the blast radius matches the reported bug class: manipulation of a low-liquidity DEX pool used as an oracle to steal value from a protocol counterpart.

### Likelihood Explanation
The price guard is opt-in and defaults to unguarded per the documented wizard flow ("A price guard is optional...") [7](#0-6) , and example configs ship it commented out [8](#0-7) . Any operator who follows the "Pool-Based Pricing" documentation without adding the optional guard, or who guards on other chains but forgets one, is exposed on every unguarded chain. The only mitigating factor is operator opt-in configuration and is not a protocol-level invariant, but the documentation itself frames the unguarded state as an accepted, reachable risk rather than something structurally prevented.

### Recommendation
Make the Uniswap V4 pool price guard mandatory whenever pool-based pricing is used for a pair (fail config validation if `referencePrice`/`maxDeviationBps` are absent for any chain backing a curveless pair), or replace the instantaneous `sqrtPriceX96`-derived spot price with a TWAP read from the pool's oracle observations, and apply a size/impact-aware price rather than a flat mid across the whole notional.

### Proof of Concept
1. Operator configures a curveless pair (e.g., `USDC/cNGN`) funded via `[vault.uniswapV4]` without setting `referencePrice`/`maxDeviationBps`, per the documented example in `pricing.mdx`.
2. Attacker identifies the configured Uniswap V4 position's pool has thin liquidity (as flagged for wBGL/wETH in the referenced report).
3. Attacker swaps a large amount through the pool to move `sqrtPriceX96` far from fair value.
4. Attacker (or a colluding solver-facing order) submits an order sized to the pair; `getExoticTokenPrice`/`computeDirectPoolPriceUsd` returns the manipulated spot price with no deviation check since no guard is configured [9](#0-8) .
5. Solver fills at the manipulated rate, delivering output tokens worth more than the input received; attacker reverses the pool manipulation and repeats.

		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}

		pos: HydratedV4Position,
		sdkPool: V4Pool,
		chain: string,
	): { exoticToken: string; priceUsd: Decimal } | null {
		const usdc = this.configService.getUsdcAsset(chain).toLowerCase()
		const usdt = this.configService.getUsdtAsset(chain).toLowerCase()
		const c0 = pos.currency0.toLowerCase()
		const c1 = pos.currency1.toLowerCase()

		if (c0 === usdc || c0 === usdt) {
			// currency0 is stable → exotic is currency1
			// token1Price = "token0 per token1" = USD per exotic

				priceUsd: new Decimal(sdkPool.token1Price.toFixed(18)),
			}

			return {
				exoticToken: c0,
				priceUsd: new Decimal(sdkPool.token0Price.toFixed(18)),

		}

		return null

## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.

	/**
	 * Validates a live venue quote against the static reference price for the chain.
	 * Returns true (pass) when no guard is configured, or no reference exists for the
	 * chain. Returns false when the quote (token1 per USD) deviates from the reference
	 * by more than `maxDeviationBps`, in which case the order must not be filled.
	 */
	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {
			this.logger.warn(
				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
	}

	// Per-position price guard: referencePrice and maxDeviationBps are optional but
	// must be set together. A given chain may not carry conflicting guard values.
	const guardByChain: Record<string, { referencePrice: string; maxDeviationBps: number }> = {}
	for (const position of uniswapV4?.positions ?? []) {
		const hasRef = position.referencePrice !== undefined
		const hasBps = position.maxDeviationBps !== undefined
		if (hasRef !== hasBps) {
			throw new Error(
				"vault.uniswapV4: a position price guard needs both 'referencePrice' and 'maxDeviationBps', or neither",
			)
		}
		if (!hasRef) continue

		const parsedRef = Number(position.referencePrice)
		if (!Number.isFinite(parsedRef) || parsedRef <= 0) {
			throw new Error(
				`vault.uniswapV4: position 'referencePrice' for chain '${position.chain}' must be a positive number`,
			)
		}
		if (
			!Number.isFinite(position.maxDeviationBps!) ||
			position.maxDeviationBps! <= 0 ||
			position.maxDeviationBps! > 10_000
		) {
			throw new Error(
				`vault.uniswapV4: position 'maxDeviationBps' for chain '${position.chain}' must be a number between 0 (exclusive) and 10000`,
			)
		}
		const existing = guardByChain[position.chain]
		if (
			existing &&
			(existing.referencePrice !== position.referencePrice || existing.maxDeviationBps !== position.maxDeviationBps)
		) {
			throw new Error(`vault.uniswapV4: conflicting price guard values for chain '${position.chain}'`)
		}
		guardByChain[position.chain] = {
			referencePrice: position.referencePrice!,
			maxDeviationBps: position.maxDeviationBps!,
		}
	}
