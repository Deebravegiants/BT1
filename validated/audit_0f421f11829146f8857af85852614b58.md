Based on my investigation, the tron variant `evm/tron/contracts/apps/IntentGatewayV2.sol` diverges materially from the audited/fixed main EVM contract at `evm/src/apps/IntentGatewayV2.sol`.

### Title
`placeOrder` in the Tron IntentGatewayV2 lacks reentrancy protection and duplicate-output-token guard present in the main EVM contract - (File: `evm/tron/contracts/apps/IntentGatewayV2.sol`)

### Summary
The canonical EVM `IntentGatewayV2.placeOrder` is guarded by `nonReentrant` (via `ReentrancyGuardTransient`) and additionally rejects duplicate output tokens using transient storage before any state/escrow mutation [1](#0-0) . The Tron port of the same contract implements `placeOrder` as a plain `public payable` function with **no reentrancy guard and no duplicate-output-token check**, while still performing external calls (`safeTransferFrom`, native `.call{value}`, `ICallDispatcher(dispatcher).dispatch(...)`) before/interleaved with escrow accounting updates (`_orders[commitment][token] += ...`) [2](#0-1) .

### Finding Description
This is the same class of bug as the XDEFI H-02 report: an externally-callable, value-affecting function performs external calls (ERC20 `safeTransferFrom`, `dispatcher.call{value}`, `ICallDispatcher.dispatch`) that can trigger a callback into the same contract, before the function's own accounting state is finalized/locked. In the reference (fixed) EVM contract, this exact function is wrapped in `nonReentrant` [3](#0-2) [4](#0-3) . In the Tron version, `placeOrder` has the same predispatch flow — transferring assets to the `CallDispatcher`, invoking `ICallDispatcher(dispatcher).dispatch(order.predispatch.call)` (an arbitrary external call that the caller fully controls the payload for), and only afterward crediting `_orders[commitment][token] += reducedInputs[i].amount` — but with no `nonReentrant` modifier on the function signature `function placeOrder(Order memory order, bytes32 graffiti) public payable` [5](#0-4) , and the predispatch/escrow-crediting loop at lines 389–450 [6](#0-5) .

Because the predispatch call executes arbitrary calldata via `ICallDispatcher`, and the nonce (`order.nonce = _nonce++`) is incremented before that call but escrow crediting (`_orders[commitment][token] += ...`) happens only after, a reentrant call into `placeOrder` (or into `fillOrder`, which reads `_orders`) during the predispatch dispatch could observe or manipulate intermediate escrow/nonce state that the non-reentrant EVM version explicitly prevents. The same missing-duplicate-output-token check (present in the EVM version via transient storage `tload`/`tstore`, lines 197–221) also removes a specific double-counting protection that exists on the audited contract [7](#0-6) .

### Impact Explanation
An unprivileged user submitting a `placeOrder` transaction with malicious `predispatch.call` payload (routed through `ICallDispatcher`) or a fee-on-transfer/malicious ERC20 as an input token can re-enter `placeOrder` (or other state-mutating entry points like `fillOrder`/`cancelOrder`) mid-execution. This can lead to escrow double-crediting or inconsistent nonce/commitment bookkeeping, enabling theft of escrowed funds or free minting of order commitments — a direct fund-theft class matching the required "concrete theft ... of funds" bar.

### Likelihood Explanation
Medium-High: `placeOrder` is a fully unprivileged, directly reachable entry point (any user can call it with attacker-controlled `predispatch.call` data routed to `ICallDispatcher.dispatch`), and the Tron file is a real deployed variant (`evm/tron/contracts/apps/IntentGatewayV2.sol`) alongside the hardened EVM version, indicating it was forked without carrying over the `nonReentrant` fix that the main contract received.

### Recommendation
Add a reentrancy guard (`nonReentrant` / `ReentrancyGuardTransient`, or Tron-compatible reentrancy lock since Tron may not support EIP-1153 transient storage) to `placeOrder` in `evm/tron/contracts/apps/IntentGatewayV2.sol`, matching the protection in `evm/src/apps/IntentGatewayV2.sol`. Also restore the duplicate-output-token rejection check before escrow crediting.

### Proof of Concept
Not independently executable from the index alone — this assessment is based on structural comparison of `evm/tron/contracts/apps/IntentGatewayV2.sol:338-506` against the hardened `evm/src/apps/IntentGatewayV2.sol:194-415`, which shows the `nonReentrant` modifier and duplicate-token check present in one and absent in the other. Given the limits of static indexing, a Devin session with full repo/build access should attempt to write a Foundry/Tron test analogous to `evm/tests/foundry/IntrinsicIntentsReentrancyTest.sol` (which already demonstrates the reentrancy attack pattern against the main gateway) against the Tron contract to confirm exploitability, since I could not fully verify whether Tron's toolchain provides an equivalent reentrancy-safe primitive elsewhere in the inheritance chain (`HyperApp`, `EIP712`) that might implicitly cover this gap.

        address hostAddr = host();
        // fill out the order preludes
        order.user = bytes32(uint256(uint160(msg.sender)));
        order.source = IDispatcher(hostAddr).host();
        order.nonce = _nonce++;

        // Calculate reduced inputs (after protocol fees) for commitment and escrow
        uint256 inputsLen = order.inputs.length;
        // Use destination-specific protocol fee, fallback to source chain fee if zero
        bytes32 destinationHash = keccak256(order.destination);
        uint256 protocolFeeBps = _destinationProtocolFees[destinationHash];
        if (protocolFeeBps == 0) {
            protocolFeeBps = _params.protocolFeeBps;
        }
        TokenInfo[] memory reducedInputs;
        bytes32 commitment;

        if (protocolFeeBps > 0) {
            reducedInputs = new TokenInfo[](inputsLen);
            for (uint256 i; i < inputsLen;) {
                uint256 originalAmount = order.inputs[i].amount;
                uint256 protocolFee = (originalAmount * protocolFeeBps) / 10_000;
                uint256 reducedAmount = originalAmount - protocolFee;
                address token = address(uint160(uint256(order.inputs[i].token)));

                // Emit DustCollected for protocol fee if non-zero
                if (protocolFee > 0) emit DustCollected(token, protocolFee);

                reducedInputs[i] = TokenInfo({token: order.inputs[i].token, amount: reducedAmount});
                unchecked {
                    ++i;
                }
            }

            // Temporarily swap inputs to calculate commitment with reduced amounts
            TokenInfo[] memory originalInputs = order.inputs;
            order.inputs = reducedInputs;
            commitment = keccak256(abi.encode(order));
            order.inputs = originalInputs;
        } else {
            // No protocol fees, use order.inputs directly
            reducedInputs = order.inputs;
            commitment = keccak256(abi.encode(order));
        }

        // escrow tokens
        uint256 msgValue = msg.value;
        if (order.predispatch.call.length > 0 && order.predispatch.assets.length > 0) {
            address dispatcher = _params.dispatcher;

            // Transfer all predispatch assets to the call dispatcher
            uint256 assetsLen = order.predispatch.assets.length;
            for (uint256 i; i < assetsLen;) {

                uint256 amount = order.predispatch.assets[i].amount;

            ICallDispatcher(dispatcher).dispatch(order.predispatch.call);

            // Transfer tokens from call dispatcher back to IntentGateway

            for (uint256 i; i < inputsLen;) {
                address token = address(uint160(uint256(order.inputs[i].token)));
                uint256 requiredAmount = order.inputs[i].amount;
                uint256 balance;

                if (token == address(0)) {
                    balance = address(dispatcher).balance;
                    if (balance < requiredAmount) revert InsufficientNativeToken();
