The insolvency path is the key area. Let me verify the rounding-to-whole-units revert in code.### Title
Insolvent account with high-value debt units can never be liquidated or cleaned: whole-unit repayment rounding makes every `liquidate` revert while the $5 dust gate blocks `clean_bad_debt`, leaving bad debt permanently unsocialized - ([File: contracts/controller/src/positions/liquidation/math.rs])

### Summary
The analog of the Opyn "adverse conditions eliminate liquidation incentives" report maps onto XOXNO Lending's liquidation pipeline, where the incentive is not a Dutch auction but a fixed-bonus seizure plan. On an insolvent account (`total_collateral < total_debt`), `normalize_repayment_plan` caps the liquidator's repayment at the collateral-backed quote `floor(C / (1 + base))` and then floors each kept repayment leg down to whole native units of the debt token (`keep_within_quote` branch of `process_excess_payment`). If the collateral-backed quote is smaller than one native unit of the debt token, every leg is dropped, `liquidate` reverts with `InvalidPayments`, and — because collateral remains above the $5 `is_socializable_bad_debt` dust cap — `clean_bad_debt` also reverts. The result is identical to the Opyn scenario: an unprivileged actor's position escapes every liquidation path, and the pool is left holding an obligation that is no longer backed by reachable collateral, correctable only by donation-style `repay` or the privileged `force_socialize_bad_debt`.

### Finding Description
In `build_liquidation_plan` (plan.rs:14), an insolvent account takes the quote branch `min(D, floor(C * WAD / (WAD + base)))` per `docs/reference/formulas.md:245`. `normalize_repayment_plan` (math.rs:188-205) then calls `process_excess_payment` with `insolvent = true`, which for each leg computes `new_amount = (usd - excess).div_floor(price).to_token_floor(decimals)` — a floor to whole token units (math.rs:668-672). A leg whose kept amount reaches zero is removed entirely (math.rs:685-686). `process_liquidation` subsequently calls `require_non_empty_payments(env, &result.repaid)` (mod.rs:66), reverting when all legs were dropped; the docs confirm this surfaces as `InvalidPayments` (16) (`docs/reference/formulas.md:261-262`, `skills/xoxno-lending-liquidations/SKILL.md:105-113`).

Meanwhile, the only permissionless bad-debt path, `clean_bad_debt` → `socialize_bad_debt(BadDebtGate::DustCapped)`, requires `is_socializable_bad_debt(total_debt, total_collateral)`, i.e. insolvency *and* collateral ≤ 5 WAD (mod.rs:230-235, 204-209). `force_socialize_bad_debt` has no dust cap but is owner-gated (mod.rs:245-249). Nothing in between lets an unprivileged caller resolve a mid-size insolvent account whose debt token's native unit exceeds `C / (1 + base)`.

### Impact Explanation
Protocol insolvency / permanent freezing of funds. The account's unbacked debt can never be written down via `apply_bad_debt_to_supply_index` because cleanup is unreachable, so the pool's books permanently overstate assets; when other suppliers withdraw, the shortfall is borne by them. The delinquent borrower's remaining collateral is also frozen — it cannot be seized by liquidators (every plan reverts) and cannot be withdrawn by the borrower (post-risk gates on `withdraw` require HF ≥ 1). This reproduces the Opyn outcome — the pool retains the obligation without an enforceable claim — through a purely mechanical cause (whole-unit rounding + dust-cap gap) rather than a market-price one, which makes it strictly worse: no market recovery is needed to trigger it.

### Likelihood Explanation
Requires a listed debt asset whose native unit value exceeds the collateral-backed quote while collateral sits above $5 — i.e., any high-price low-decimal token (e.g., a 3-decimal asset priced in the thousands, exactly like the harness's EXP at $10k/unit in `tests/test-harness/tests/controller/liquidation_extreme.rs:653-666`). A single unprivileged address creates the state by `supply` + `borrow`, then any collateral price decline (or debt-side price rise) that takes the account underwater while `floor(C/(1+base)) < 1` unit of the debt token permanently bricks liquidation for that account. The protocol itself defines the decimals and bonus stamps, so the window is deterministic and computable by the attacker before borrowing.

### Recommendation
- Do not floor kept insolvent repayment legs to whole token units when doing so would empty the plan; allow the liquidator to repay exactly `floor(C/(1+b))` worth of a leg, or treat "all legs dropped" as a `seize_all` full-collateral close priced at the base bonus.
- Alternatively, remove the collateral dust cap from the permissionless `clean_bad_debt` gate (or raise it / make it proportional), so any insolvent account that has been unliquidatable can be socialized without owner intervention.
- Optionally charge a borrow-side fee reserve to fund a permissionless `recapitalize` path for such stuck accounts, mirroring the report's subsidy recommendation.

### Proof of Concept
1. Bob supplies the debt asset liquidity; Alice `supply`s 1,000 units of collateral COL (7 decimals) and `borrow`s 1 unit of EXP (3 decimals, $10,000/unit).
2. COL price crashes so Alice's collateral is worth $6,000 (C = $6,000 < D ≈ $10,000; HF < 1, `is_liquidatable` = true).
3. Liquidator calls `get_liquidation_estimate(account, [(EXP, 1)], Transfer)` then `liquidate`. In `normalize_repayment_plan` the insolvent quote is `floor(6_000 / 1.05) ≈ $5,714 < $10,000`, so `process_excess_payment` keeps `to_token_floor` of less than one EXP unit → 0 → leg removed. `require_non_empty_payments` on the empty `repaid` reverts `InvalidPayments` (mod.rs:66). Every possible offer reverts identically.
4. `clean_bad_debt(account)` reverts `CannotCleanBadDebt` because `total_collateral` ($6,000) > 5 WAD (mod.rs:230-235).
5. The $4,000 bad debt remains unsocialized indefinitely; only owner `force_socialize_bad_debt` or a charitable `repay` can clear it.
