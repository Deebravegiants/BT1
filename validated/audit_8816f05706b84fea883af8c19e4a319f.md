### Title
Governance execution inside a flash-position callback can bypass updated oracle configuration - (File: contracts/controller/src/strategies/flash_position.rs)

### Summary
`flash_position` caches oracle prices before minting debt and invoking the caller-selected receiver. [1](#0-0)  During that callback, the receiver can permissionlessly execute a ready governance operation against the price aggregator, such as an oracle-configuration or tolerance change. [2](#0-1) [3](#0-2)  The controller nevertheless finishes the position using the previously cached `PriceFeedRaw`, so an oracle change that has already executed is not reflected in the solvency check. [4](#0-3) 

### Finding Description
`process_flash_position` calls `prefetch_strategy_prices` for the debt token, declared collateral tokens, and existing account assets before it enters the guarded funding-and-callback window. [5](#0-4)  `Context::fetch_prices` only fetches assets missing from `token_prices`, and `cached_price` later returns that retained feed without querying the aggregator again. [4](#0-3) 

The callback is arbitrary Wasm receiver code invoked while borrowed debt has already been minted and forwarded. [6](#0-5)  Governance `execute` permits `executor = None`, invokes the exact scheduled external operation, and clears it after success. [2](#0-1) [7](#0-6)  Because the target is the price aggregator rather than the controller, this path does not require re-entering the controller.

After the callback returns, the controller measures collateral, deposits it, and calls `strategy_finalize`. [8](#0-7) [9](#0-8)  That finalization still consumes the prices loaded before the receiver ran, creating a check-time/use-time gap across a permissionless governance execution.

### Impact Explanation
An attacker can open a leveraged account using a stale collateral valuation that a just-executed governance operation has replaced or invalidated. For example, the receiver executes a ready operation that changes collateral `C` from a stale high-valued feed to a lower-valued feed, transfers the minimum `C` to the controller, and keeps part of the borrowed `D`. The account passes the final risk check under the old cached price, but is immediately undercollateralized under the new configuration. Subsequent liquidation and bad-debt cleanup can socialize the resulting shortfall, causing protocol insolvency and supplier losses.

### Likelihood Explanation
Exploitation requires an already-ready, non-expired governance operation that materially changes the oracle result or validity for a debt or collateral asset, plus enough valuation divergence to cross the LTV or health-factor boundary. Once such an operation exists, an unprivileged caller can deterministically execute it inside their own flash-position receiver because `executor = None` removes the executor-role check. [10](#0-9)  The cached-price behavior makes the stale check deterministic rather than dependent on transaction ordering. [4](#0-3) 

### Recommendation
Invalidate and reload oracle feeds and relevant market configuration after the receiver callback and before collateral accounting and `strategy_finalize`. Calling `fetch_prices` on the same `Context` is insufficient because existing entries are retained; use a fresh pricing context or add an explicit cache invalidation/reload path. Alternatively, bind the operation to an oracle configuration generation or digest and revert if it changes between prefetch and finalization.

### Proof of Concept
1. Assume spoke `S` has listed collateral market `C` and flash-loanable debt market `D`, and governance has a ready operation `op` targeting the price aggregator that changes `C`’s oracle or tolerance so the currently fetched `C` feed is replaced or rejected.
2. Attacker deploys receiver `R` and calls `Controller::flash_position(caller=A, account_id=0, spoke_id=S, mode=Multiply, debt=D, amount=100, receiver=R, data=p, collaterals=[(C,min_c)], refund_assets=[])`.
3. The controller prefetches the old `C` and `D` prices before entering the callback. [5](#0-4) 
4. Inside `R.execute_flash_position`, call `Governance::execute(None, target=AGGREGATOR, function=op.function, args=op.args, predecessor=op.predecessor, salt=op.salt)`, activating the new oracle configuration.
5. `R` uses part of the forwarded `D` to acquire `min_c` of `C`, transfers `min_c` to the controller, and sends the remaining `D` to `A`.
6. The controller measures the `C` delta, deposits it, and evaluates health using the pre-callback cached price rather than the activated oracle configuration. [4](#0-3) [9](#0-8) 
7. The call succeeds and returns the new account id, but the account is undercollateralized under the now-active aggregator configuration; liquidation leaves residual debt for suppliers to absorb.

    /// Fetches missing prices in one aggregator call; retains cached prices.
    pub(crate) fn fetch_prices(&mut self, assets: &Vec<Address>) {
        let missing = collect_uncached_keys(&self.env, assets, &self.token_prices);
        if missing.is_empty() {
            return;
        }
        let fetched = external::price_aggregator::fetch_prices(&self.env, &missing);
        for (asset, feed) in fetched.iter() {
            self.token_prices.set(asset, feed);
        }
