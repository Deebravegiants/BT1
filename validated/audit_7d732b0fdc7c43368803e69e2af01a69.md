Audit Report

## Title
Unprivileged (View-role) users can enumerate `OutgoingToken` and `AccessKey` credentials for all External Initiators - (File: core/web/router.go, core/web/external_initiators_controller.go)

## Summary
The `GET /v2/external_initiators` route is registered without any role-based guard, while the sibling `POST`/`DELETE` routes for the same resource require `auth.RequiresEditRole`. As a result, any authenticated user — including one with the lowest-privilege `UserRoleView` role — can call this endpoint and receive the `AccessKey` and `OutgoingToken` for every registered External Initiator.

## Finding Description
In `core/web/router.go` (lines 263-266), the route group is defined as:
```go
eia := ExternalInitiatorsController{app}
authv2.GET("/external_initiators", paginatedRequest(eia.Index))
authv2.POST("/external_initiators", auth.RequiresEditRole(eia.Create))
authv2.DELETE("/external_initiators/:Name", auth.RequiresEditRole(eia.Destroy))
```
`Index` only inherits the generic `authv2` session/token middleware (`auth.Authenticate`), which is satisfied by any authenticated user regardless of role, unlike `RequiresEditRole` which explicitly rejects `UserRoleView` and `UserRoleRun` (confirmed in `core/web/auth/auth.go` lines 217-234).

`ExternalInitiatorsController.Index` (`core/web/external_initiators_controller.go` lines 50-59) fetches all external initiators and maps them through `presenters.NewExternalInitiatorResource`. That resource struct (`core/web/presenters/external_initiators.go` lines 57-77) includes `AccessKey` and `OutgoingToken` fields directly copied from the stored `bridges.ExternalInitiator` model and serialized to JSON as `accessKey` and `outgoingToken`. This is corroborated by the existing test `core/web/external_initiators_controller_test.go` (lines 104-126), which asserts these exact fields are present in the `Index` response.

No redaction, scrubbing, or role check occurs anywhere between the DB fetch and the JSON response for this route, so the read path has strictly weaker authorization than the write/management path for the same resource — breaking the role-boundary invariant the rest of the External Initiator API otherwise enforces.

## Impact Explanation
This is a genuine information-disclosure / role-boundary bypass: a `View`-role user, who is deliberately prevented from creating or destroying external initiators, can nonetheless read the `AccessKey` (initiator identity) and `OutgoingToken` (secret used by Chainlink to authenticate outbound callbacks to the initiator) for every initiator on the node. This does not expose the `IncomingToken`/`Secret` used to authenticate inbound requests (that value is not present in `ExternalInitiatorResource`), so it is not a full account-takeover primitive, but it is a clear over-exposure of privileged secret material to an under-privileged, legitimately-authenticated role — matching the "node API authentication/role bypass" and "key/secret exfiltration" impact categories.

## Likelihood Explanation
High feasibility: any node operator that provisions `View`-role users/API tokens (a normal, expected low-privilege access tier for dashboards/read-only integrations) can trivially issue a single authenticated `GET /v2/external_initiators` request with no additional preconditions, race conditions, or special access needed.

## Recommendation
Guard the `GET /v2/external_initiators` route with the same or a stricter role requirement as the mutation routes, e.g. `authv2.GET("/external_initiators", auth.RequiresEditRole(paginatedRequest(eia.Index)))`, or remove `AccessKey`/`OutgoingToken` from `ExternalInitiatorResource` (or omit them for callers below Edit role).

## Proof of Concept
1. As an `admin`/`edit` user, create an external initiator: `POST /v2/external_initiators` with `{"name":"victim-initiator"}`; note the returned `outgoingToken`.
2. Create/authenticate as a `View`-role user session or API token.
3. Call `GET /v2/external_initiators` as the `View` user.
4. Observe the JSON response includes `accessKey` and `outgoingToken` fields for `victim-initiator`, identical to privileged-only data, confirmed by the field mapping in `core/web/presenters/external_initiators.go:67-77` and the unguarded route registration in `core/web/router.go:264`. func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))

}
