### Title
Unvalidated `shop` parameter in `Oauth.begin_auth` enables forced-OAuth/host-injection redirect to an attacker-controlled authorize endpoint - (File: `lib/shopify_api/auth/oauth.rb`)

### Summary
### Finding Description
`ShopifyAPI::Auth::Oauth.begin_auth` builds the authorization redirect URL directly from the caller-supplied `shop:` argument without ever validating that it is a trusted Shopify domain: [1](#0-0) 

The URL host is produced by `auth_base_uri(shop)`, which simply interpolates the raw string into `https://#{shop}/admin`: [2](#0-1) 

`shop` is documented as coming straight from an unauthenticated request parameter supplied by the visiting browser, before any HMAC or session exists yet (this is literally the entry point that creates the state cookie): [3](#0-2) 

Every other flow in this gem that turns an untrusted `shop` string into a request host explicitly sanitizes it first with `Utils::ShopValidator.sanitize!`, which restricts the value to `TRUSTED_SHOPIFY_DOMAINS` (`myshopify.com`, `myshopify.io`, `spin.dev`, `shop.dev`, `shopify.com`): [4](#0-3) [5](#0-4) [6](#0-5) 

`begin_auth` is the one path in `lib/shopify_api/auth/oauth.rb` that never calls `ShopValidator`. The equality that should hold — "host redirected to by `begin_auth`" == "host validated as a genuine `*.myshopify.com` install target" — is broken: the host is whatever the anonymous caller supplied.

### Impact Explanation
Because `begin_auth`'s output embeds the app's real `client_id`, the real `redirect_uri` (pointing back to the legitimate app's callback), and a freshly generated `state` nonce that is simultaneously written into a cookie on the victim's browser, an attacker who supplies `shop=attacker-controlled-host` gets the library to hand back:

`https://attacker-controlled-host/oauth/authorize?client_id=<real client id>&scope=...&redirect_uri=https://<legit-app-host>/callback&state=<nonce>&grant_options[]=...`

If the host application (as documented) redirects the victim's browser to this URL, the victim lands on an attacker-controlled page instead of Shopify's real authorization screen, while the victim's browser already carries the legitimate app's session cookie set to the attacker-chosen `state`. The attacker can then complete their own genuine OAuth authorization (for a shop they control) and redirect back to the real `redirect_uri` with that same `state`, causing `validate_auth_callback`'s state check to pass: [7](#0-6) 

This is a forced-OAuth-completion / session-fixation pattern that lets an attacker splice their own (attacker-owned) Shopify store's session into the victim's browser/session state, which is explicitly listed as a High-impact analog in scope.

### Likelihood Explanation
`begin_auth` is by design the first, unauthenticated step of the OAuth flow and takes `shop` straight from request input in the documented integration pattern, so the missing validation is directly reachable by any unprivileged internet user who can cause the target app to invoke `begin_auth` with a `shop` value they control (e.g., a phishing link `https://legit-app.com/auth?shop=attacker.example`). No secrets or prior authentication are required.

### Recommendation
Call `Utils::ShopValidator.sanitize!(shop)` (or `sanitize_shop_domain`) at the top of `begin_auth`, exactly as is already done in `client_credentials.rb`, `refresh_token.rb`, and `token_exchange.rb`, and raise `Errors::InvalidShopError` before constructing `auth_base_uri`/`auth_route` if the shop is not a trusted Shopify domain.

### Proof of Concept
1. Attacker sends a victim a link to the host app's auth-start route with `shop=attacker.example` (a domain the attacker controls).
2. The host app calls `ShopifyAPI::Auth::Oauth.begin_auth(shop: "attacker.example", redirect_path: "/callback")`.
3. `begin_auth` returns `auth_route = "https://attacker.example/oauth/authorize?client_id=<real client_id>&scope=...&redirect_uri=https://legit-app.com/callback&state=<nonce>&grant_options[]=..."` and a `SessionCookie` containing `<nonce>`, set on the victim's browser.
4. The victim's browser is redirected to `attacker.example`, which the attacker controls; it never reaches Shopify.
5. Using the leaked `client_id`, `redirect_uri`, and observed `state` cookie value, the attacker completes a real OAuth grant for their own store and redirects the victim's browser to `https://legit-app.com/callback?code=<attacker's real code>&shop=attacker's real myshopify domain&state=<nonce>&hmac=<valid hmac>`, which `validate_auth_callback` accepts because the state matches the cookie planted in step 3.

        def begin_auth(shop:, redirect_path:, is_online: true, scope_override: nil)
          scope = if scope_override.nil?
            ShopifyAPI::Context.scope
          elsif scope_override.is_a?(ShopifyAPI::Auth::AuthScopes)
            scope_override
          else
            ShopifyAPI::Auth::AuthScopes.new(scope_override)
          end

          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = SecureRandom.alphanumeric(NONCE_LENGTH)

          cookie = SessionCookie.new(value: state, expires: Time.now + 60)

          query = {
            client_id: ShopifyAPI::Context.api_key,
            scope: scope.to_s,
            redirect_uri: "#{ShopifyAPI::Context.host}#{redirect_path}",
            state: state,
            "grant_options[]": is_online ? "per-user" : "",
          }

          query_string = URI.encode_www_form(query)
          auth_route = auth_base_uri(shop) + "/oauth/authorize?#{query_string}"

          { auth_route: auth_route, cookie: cookie }
        end

        def auth_base_uri(shop)
          return "https://#{shop}/admin" unless defined?(DevServer) && shop.include?(".my.shop.dev")

          # For first-party apps in development only, we leverage DevServer to build the admin base URI

            .new("admin-web")
          admin_host = admin_web.host!(nonstandard_host_prefix: "admin")
          shop_name = shop.split(".").first

          "https://#{admin_host}/store/#{shop_name}"
        end
