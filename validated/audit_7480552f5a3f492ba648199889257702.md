### Title
`EmporiumUpgradeable.payRelayFees` never verifies relay actually received the fee, letting an attacker fake relay payment via a signer address with no transfer logic - (`contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol`)

### Summary
When `stack.signerAddress != address(0)`, `EmporiumUpgradeable.payRelayFees` pays the relay by calling `IHinkalWallet(signerAddress).doSendToRelay(...)` and treats the call as fee-paid based purely on call success, with no post-call balance check on the relay. Because Solidity does not revert on an external call to a void-return interface function when the target address has no bytecode, an attacker can register `stack.signerAddress` as a plain EOA they control (trivially satisfying `verifyWallet`'s ECDSA check), causing `doSendToRelay` to silently no-op while `transact` completes and UTXO/accounting proceeds as if the relay fee was paid.

### Finding Description
The broken equality: *tokens leaving the action for the relay-fee leg == relayFee credited to `circomData.relay`* is not enforced when `signerAddress != address(0)`.

- `runAction` (`contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol:76-120`) decodes `EmporiumStack` (including `signerAddress`) from attacker-supplied `circomData.externalActionData.externalActionMetadata`, then calls `payRelayFees(circomData, stack.signerAddress, deltaAmountChanges)` at line 120.
- `payRelayFees` (lines 201-260) computes `relayFee = flatFee` when `signerAddress != address(0)` (line 236) and routes payment through `payRelay` → `sendToRelayFromWallet` (lines 186-199, 262-282), which calls `IHinkalWallet(signerAddress).doSendToRelay(relay, relayFee, feeToken)` [1](#0-0) .
- This call's only "check" is that the low-level call doesn't revert. Since `doSendToRelay` has no return value, Solidity does not perform an `extcodesize` check before decoding return data, so calling it against an address with no bytecode succeeds trivially without executing any transfer logic [2](#0-1) .
- `verifyWallet` (lines 302-349) only validates a signature recovers to `stack.signerAddress`; it does not require `signerAddress` to be a contract, nor does it verify that a real transfer capability exists [3](#0-2) . An attacker generates any keypair (e.g., their own EOA), sets `stack.signerAddress` to that EOA, and signs the EIP-712 struct themselves — this is a completely valid signature since they hold the private key.
- Only the `signerAddress == address(0)` fee path is protected, because it transfers directly from the Emporium contract's own balance, which *is* covered by the `balanceChange`/`BalanceChangeShouldBePositive` check later in `runAction` (lines 132-144) [4](#0-3) . That balance check only tracks the Emporium contract's own token balances, not the relay's balance, so it cannot catch a failed wallet→relay transfer in the `signerAddress != address(0)` branch.
- Attacker's call: submit a `transact` with `CircomData.externalActionData.externalActionMetadata` decoding to an `EmporiumStack` where `signerAddress` = attacker's own EOA (or any address without transfer logic they control the key for), `ops` empty or harmless, `feeStructure.flatFee` set to whatever the relay expects, and at least one `deltaAmountChanges[i] < 0` to trigger the fee loop. `verifyWallet` passes (valid self-signed signature), `doSendToRelay` silently no-ops against the EOA, and `runAction` returns normally with UTXOs created — the relay's fee token balance never increases.

### Impact Explanation
The relay (or protocol, depending on fee routing) never receives the `flatFee` it was owed for facilitating the `transact`, while the attacker's shielded-pool accounting, nullifier consumption, and UTXO issuance proceed as if the fee was paid. This is repeatable on every `transact` that uses the Emporium external action with a non-zero `signerAddress`, and constitutes theft/permanent loss of protocol/relay fees, matching the High severity category.

### Likelihood Explanation
No privileged role is required. The attacker only needs to: generate/own an ECDSA keypair (trivial), craft a `CircomData`/`EmporiumStack` with `signerAddress` set to that key's address, produce a valid EIP-712 signature over their own chosen `ops`/`maxFee`/`deadline` (trivial, since it's their own key), and set `feeStructure.flatFee` to whatever value is needed to pass off-chain relay expectations. No on-chain guard in `EmporiumUpgradeable` prevents this; the exploit is fully reproducible and repeatable per transaction. The only friction is if the relay's off-chain tooling independently simulates the call and checks its own balance delta before broadcasting — but that is an off-chain, non-enforced mitigation, not a contract guarantee.

### Recommendation
After calling `IHinkalWallet(signerAddress).doSendToRelay(...)`, verify the relay's actual token balance increased by `relayFee` (snapshot before/after, like the existing `balancesBefore`/`balancesAfter` pattern), and revert if not. Alternatively, require `signerAddress` to be a contract (`extcodesize > 0`) and have `doSendToRelay` return a success value that is explicitly checked, or route the flat-fee payment through the same balance-checked flow as the `signerAddress == address(0)` path instead of trusting an unverified external call.

### Proof of Concept
Foundry test outline:
1. Deploy `EmporiumUpgradeable`, `RelayStore`/relay address, a fee token (ERC20).
2. Build a `CircomData` with `feeStructure.flatFee = X`, `erc20TokenAddresses = [feeToken]`, `deltaAmountChanges = [-Y]` (Y > 0), and `externalActionData.externalActionMetadata` = `abi.encode(EmporiumStack({v,r,s, signerAddress: attackerEOA, ops: [], maxFee: X, deadline: future}))` where `(v,r,s)` is a valid EIP-712 signature produced by `attackerEOA`'s private key over the exact typed struct `EmporiumUpgradeable._hashEmporiumOps`/`EMPORIUM_SIGNATURE_TYPEHASH`.
3. Call `runAction` from an allowed recipient (mocking the Hinkal core contract as `msg.sender`).
4. Assert: `verifyWallet` does not revert (signature valid); `runAction` completes and returns a UTXO set.
5. Assertions on the equality: `relayBalanceOf(feeToken) == relayBalanceBefore` (i.e., unchanged, disproving fee payment) while the function completed successfully and `usedMessages[circomData.emporiumMessage] == true` (disproving that fee payment gated success). [1](#0-0) [5](#0-4) [2](#0-1)

    function payRelayFees(
        CircomData calldata circomData,
        address signerAddress,
        int256[] calldata deltaAmountChanges
    ) internal {
        FeeStructure calldata feeStructure = circomData.feeStructure;

        bool foundToken = false;

        for (uint256 i = 0; i < circomData.erc20TokenAddresses.length; i++) {
            // tokens deposited into Emporium are not charged
            if (deltaAmountChanges[i] >= 0) {
                continue;
            }

            address erc20TokenAddress = circomData.erc20TokenAddresses[i];
            bool isFeeToken = erc20TokenAddress == feeStructure.feeToken;

            if (isFeeToken) {
                foundToken = true;
            }

            uint256 relayFee = 0;
            uint256 flatFee = isFeeToken ? feeStructure.flatFee : 0;

            if (signerAddress == address(0)) {
                uint256 sumAbs = uint256(-deltaAmountChanges[i]);

                EmporiumStorageVars storage $ = _getEmporiumStorage();
                relayFee = $._hinkalHelper.calculateRelayFee(
                    sumAbs,
                    flatFee,
                    feeStructure.variableRate
                );
            } else {
                relayFee = flatFee;
            }

            payRelay(
                circomData.relay,
                signerAddress,
                relayFee,
                erc20TokenAddress
            );
        }

        if (!foundToken && feeStructure.flatFee != 0) {
            require(
                signerAddress != address(0),
                "Gas Token in Emporium is not found"
            );

            payRelay(
                circomData.relay,
                signerAddress,
                feeStructure.flatFee,
                feeStructure.feeToken
            );
        }
    }

    function verifyWallet(
        EmporiumStack memory stack,
        CircomData calldata circomData
    ) internal {
        EmporiumStorageVars storage $ = _getEmporiumStorage();

        if ($.usedMessages[circomData.emporiumMessage]) {
            revert UsedMessage();
        }

        $.usedMessages[circomData.emporiumMessage] = true;

        if (stack.signerAddress == address(0)) {
            return;
        }

        bytes32 hashedMessage = _hashTypedDataV4(
            keccak256(
                abi.encode(
                    EMPORIUM_SIGNATURE_TYPEHASH,
                    circomData.emporiumMessage,
                    _hashEmporiumOps(stack.ops),
                    stack.maxFee,
                    stack.deadline
                )
            )
        );

        (address recoveredAddress, ECDSA.RecoverError err) = ECDSA.tryRecover(
            hashedMessage,
            stack.v,
            stack.r,
            stack.s
        );
        bool verified = err == ECDSA.RecoverError.NoError &&
            recoveredAddress == stack.signerAddress;
        if (!verified) {
            revert InvalidSignature();
        }

        if (block.timestamp > stack.deadline) {
            revert SignatureExpired();
        }

        if (circomData.feeStructure.flatFee > stack.maxFee) {
            revert FeeExceedsSignedMax();
        }
    }
