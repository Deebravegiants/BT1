## Title
Malicious destination module can force the relayer to pay excessive gas by consuming unbounded gas in `onAccept` during `dispatchIncoming` - (File: `evm/src/core/EvmHost.sol`)

### Summary
`EvmHost.dispatchIncoming(PostRequest, address relayer)` forwards the entire remaining transaction gas to the destination module's `onAccept` callback via a raw, gas-unbounded `.call()`. Because `HandlerV2.handlePostRequests` (which triggers this) is permissionless and callable by any relayer submitting a proof, a malicious application contract that is the `to` of a request can consume an attacker-controlled, arbitrarily large amount of gas inside `onAccept`, forcing the relayer who delivers the message to pay for that gas — exactly the "Bull manipulates receive hook, Bear pays" pattern from the referenced report, with the relayer playing the role of the victim ("Bear") and the malicious destination app playing the role of the attacker ("Bull").

### Finding Description
`dispatchIncoming` performs:
```solidity
(bool success,) = address(destination)
    .call(abi.encodeWithSelector(IApp.onAccept.selector, IncomingPostRequest(request, relayer)));
``` [1](#0-0) 

No gas stipend is imposed on this call — it inherits all gas forwarded by the caller (`HandlerV2.handlePostRequests`), which is itself permissionless and invoked directly by the relayer's transaction:
```solidity
function handlePostRequests(IHost host, PostRequestMessage calldata request) external notFrozen(host) {
    ...
    for (uint256 i = 0; i < requestsLen; ++i) {
        ...
        host.dispatchIncoming(leaf.request, _msgSender());
    }
}
``` [2](#0-1) 

Because the destination address (`request.to`) is fully controlled by whoever dispatches the original request (it need only be a contract implementing `onAccept` for `IApp`), an attacker can deploy a module whose `onAccept` runs an expensive loop (e.g. repeated storage writes) before returning successfully — mirroring the malicious `onERC721Received` in the referenced report. The relayer submitting the proof for that request has no way to cap the sub-call's gas usage; the entire cost is billed against the relayer's transaction gas.

Documentation acknowledges this risk only as advisory guidance to app developers ("Keep callback gas costs reasonable as relayers pay initially" / "Use try-catch for external calls") [3](#0-2)  — but nothing in the protocol enforces a gas ceiling on the destination callback, so a malicious module is free to ignore this guidance.

Because `handlePostRequests` processes a batch of leaves in a single loop, and a caught OOG deep in one sub-call can propagate (or simply exhaust available gas for subsequent iterations), one malicious request placed in a batch can also degrade or fail delivery of the other, honest requests batched alongside it, since the relayer must supply enough gas for the entire batch upfront.

### Impact Explanation
A malicious application (reachable by anyone who can dispatch a POST request to it, i.e. any app author) can:
- Force honest relayers delivering requests destined for that malicious module to pay dramatically inflated gas fees for a single delivery, well beyond the legitimate cost of message dispatch.
- Discourage/deter relayers from delivering to that destination, effectively making that route unable to reliably deliver messages (a relayer will avoid a destination it cannot profitably serve), and
- When batched with other pending requests, degrade delivery of unrelated, honest messages sharing the same `handlePostRequests` transaction.

This is a direct, permissionless griefing vector against the relayer economics that Hyperbridge's fee model depends on, satisfying the "route unable to deliver messages" acceptance criterion.

### Likelihood Explanation
High. No privileged role is required: any account can deploy a contract with a gas-heavy `onAccept`, register it as an ISMP module `to` address, and dispatch a POST request destined for it from any source chain. Relayers are third parties who must submit `handlePostRequests` (permissionless) to earn fees, and they have no visibility/control preventing the malicious callback from consuming excess gas once invoked — the same limited-defense scenario as the original report (`try/catch` only limits revert propagation, not gas consumption).

### Recommendation
Cap the gas forwarded to `IApp.onAccept` (and analogously to `onGetResponse`, `onGetTimeout`, `onPostRequestTimeout` in `dispatchIncoming`/`dispatchTimeOut`) using an explicit gas stipend, e.g.:
```solidity
(bool success,) = destination.call{gas: MAX_CALLBACK_GAS}(
    abi.encodeWithSelector(IApp.onAccept.selector, IncomingPostRequest(request, relayer))
);
```
choosing `MAX_CALLBACK_GAS` conservatively (with a documented ceiling apps must respect), and consider surfacing this limit so relayers can safely bound gas per request when constructing batches, rather than relying purely on developer best-practice documentation.

### Proof of Concept
1. Deploy `MaliciousModule` implementing `IApp.onAccept` that runs a loop of storage writes consuming e.g. 20M gas before returning, i.e. mirroring `BvbMaliciousBull2` from the referenced report.
2. Register/announce `MaliciousModule` as the destination module id for a POST request on the destination chain (this is simply the `to` field the sender controls when dispatching a request).
3. Dispatch a POST request with `to = MaliciousModule` from any source chain app via `IDispatcher.dispatch`.
4. Wait for a relayer to submit `HandlerV2.handlePostRequests` with a valid MMR proof for the batch containing this leaf; `EvmHost.dispatchIncoming` invokes `MaliciousModule.onAccept` via unmetered `.call()`, forcing the relayer's transaction to burn the entire loop's gas (as in the ~29M gas `testElku32` result of the referenced report) at the relayer's expense in ETH.     function dispatchIncoming(PostRequest memory request, address relayer) external restrict(_hostParams.handler) {
        address destination = _bytesToAddress(request.to);
        uint256 size;
        assembly {
            size := extcodesize(destination)
        }
        if (size == 0) {
            // instead of reverting the entire batch, early return here.
            return;
        }

        // replay protection
        bytes32 commitment = request.hash();
        _requestReceipts[commitment] = relayer;

        (bool success,) = address(destination)
            .call(abi.encodeWithSelector(IApp.onAccept.selector, IncomingPostRequest(request, relayer)));

        if (!success) {
            // so that it can be retried
            delete _requestReceipts[commitment];
            return;
        }
        emit PostRequestHandled({commitment: commitment, relayer: relayer});
    }

    function handlePostRequests(IHost host, PostRequestMessage calldata request) external notFrozen(host) {
        uint256 timestamp = block.timestamp;
        uint256 delay = timestamp - host.stateMachineCommitmentUpdateTime(request.proof.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        uint256 requestsLen = request.requests.length;
        MerkleMountainRange.Leaf[] memory leaves = new MerkleMountainRange.Leaf[](requestsLen);

        for (uint256 i = 0; i < requestsLen; ++i) {
            PostRequestLeaf memory leaf = request.requests[i];
            // check destination
            if (!leaf.request.dest.equals(host.host())) revert InvalidMessageDestination();
            // check time-out
            if (timestamp >= leaf.request.timeout()) revert MessageTimedOut();
            leaves[i] = MerkleMountainRange.Leaf(leaf.index, leaf.request.hash());
        }

        bytes32 root = host.stateMachineCommitment(request.proof.height).overlayRoot;
        if (root == bytes32(0)) revert StateCommitmentNotFound();
        bool valid = MerkleMountainRange.VerifyProof(root, request.proof.multiproof, leaves, request.proof.leafCount);
        if (!valid) revert InvalidProof();

        for (uint256 i = 0; i < requestsLen; ++i) {
            PostRequestLeaf memory leaf = request.requests[i];
            // duplicate request?
            if (host.requestReceipts(leaf.request.hash()) != address(0)) revert DuplicateMessage();
            host.dispatchIncoming(leaf.request, _msgSender());
        }
    }
```
