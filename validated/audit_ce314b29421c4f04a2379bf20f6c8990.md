### Title
Unauthenticated `shop-domain` header value flows unsanitized into `WebhookMetadata#shop` used for tenant lookup - (File: lib/shopify_api/webhooks/request.rb)

### Summary
`Registry.process` only validates the webhook body's HMAC and never validates or sanitizes the `shop-domain` header before handing it to the handler as `data.shop`. Because the HMAC signable string is the raw body only, an attacker who legitimately receives a validly-signed webhook for their own shop can replay it against the victim app's webhook endpoint with an arbitrary `shop-domain` header value, and the forged shop string will pass through unchanged to the host app's handler.

### Finding Description
The broken binding: `value validated by HmacValidator (HMAC(raw_body))` should equal `value trusted by handler.handle as data.shop`, but instead `data.shop == request.shop == raw shopify-shop-domain header`, which is never included in the signable string and never passed through `ShopValidator.sanitize!`.

Code path: `Registry.process` calls `Utils::HmacValidator.validate(request)` [6](#0-5) , which calls `validate_signature`, comparing `verifiable_query.hmac` against `compute_signature(verifiable_query.to_signable_string, secret)` [2](#0-1) . For `Request`, `to_signable_string` returns only `@raw_body` [1](#0-0) , so the `shop-domain` header is completely outside the cryptographic binding. `Request#shop` simply reads `shopify_header("shop-domain")` with no format check, no trusted-domain check, and no call to `ShopValidator.sanitize!` anywhere in `request.rb` or `registry.rb` [3](#0-2) . `Registry.process` then constructs `WebhookMetadata.new(..., shop: request.shop, ...)` and calls `handler.handle(data: ...)` unconditionally [7](#0-6) .

Attacker's exact request: the attacker creates their own development shop, installs the app, and registers/receives a genuine webhook from Shopify to a server they control, capturing a `(raw_body, hmac)` pair that is validly signed with the real `api_secret_key` (which they never learn). They then POST that exact same `raw_body` and `hmac` header to the victim app's real webhook endpoint, but replace the `shopify-shop-domain` (or `x-shopify-shop-domain`) header with an arbitrary string — e.g. `victim-shop.myshopify.com`, or even a non-myshopify string since no domain validation occurs. `HmacValidator.validate` still returns `true` because the signature only covers `raw_body`, which is unchanged. `Registry.process` proceeds to call `handler.handle` with `data.shop` equal to the attacker-chosen string. If the host app uses `data.shop` as a lookup/write key (as the gem's own documented example does), this results in cross-tenant data corruption/access.

Existing guards do not close this gap: `ShopValidator.sanitize!` exists in the gem but is never invoked in the webhook processing path [8](#0-7) ; `HmacValidator` only guarantees body integrity, not header authenticity [9](#0-8) .

### Impact Explanation
An attacker who possesses any single genuine valid webhook (obtainable via their own free development shop) can replay it indefinitely against the same endpoint, substituting arbitrary `shop-domain` values on each replay while the body/HMAC pair remains valid. Any host app that follows the gem's documented usage pattern of trusting `data.shop` as the tenant key will process attacker-controlled tenant identifiers, resulting in cross-tenant access or data corruption — this matches the Critical severity category defined in the rules ("cross-tenant access").

### Likelihood Explanation
Preconditions are minimal and match the documented, expected usage of the gem: any app using `ShopifyAPI::Webhooks::Registry.process` with a `handler.handle` that keys off `data.shop` (as shown in the gem's own `docs/usage/webhooks.md` example) is affected. The attacker only needs a free Shopify development store, no privileged credentials, and can trivially replay a single previously captured `(body, hmac)` pair with a modified `shop-domain` header. This is fully repeatable and requires no knowledge of `api_secret_key`.

### Recommendation
In `Request#shop` (or in `Registry.process` before constructing `WebhookMetadata`), call `ShopValidator.sanitize!(shop-domain-header-value)` and raise `Errors::InvalidWebhookError` if it fails. Additionally, consider including the shop domain in the HMAC signable string (if Shopify's actual webhook signing supports/permits this) or, at minimum, cross-check the header shop domain against an expected/known list of installed shops maintained by the host app before invoking the handler, since the current design leaves the `shop-domain` header entirely outside the integrity check.

```ruby
# test/shopify_api/webhooks/registry_shop_forgery_test.rb
require "test_helper"

class RegistryShopForgeryTest < Minitest::Test
  def setup
    ShopifyAPI::Context.setup(
      api_key: "key", api_secret_key: "secret", api_version: "2023-01",
      host_name: "app.com", scope: "read_products", is_private: false, is_embedded: true,
    )
    ShopifyAPI::Webhooks::Registry.clear
  end

  def test_hmac_validator_never_binds_shop_domain
    # Assert ShopValidator.sanitize! is not invoked anywhere in request.rb/registry.rb path
    ShopifyAPI::Utils::ShopValidator.expects(:sanitize!).never

    raw_body = '{"id":1}'
    hmac = OpenSSL::HMAC.hexdigest(OpenSSL::Digest.new("sha256"), "secret", raw_body)
    hmac_b64 = Base64.strict_encode64([hmac].pack("H*"))

    request = ShopifyAPI::Webhooks::Request.new(
      raw_body: raw_body,
      headers: {
        "shopify-topic" => "orders/create",
        "shopify-hmac-sha256" => hmac_b64,
        "shopify-shop-domain" => "attacker-controlled-not-a-real-shop",
      },
    )

    # Binding check: valid body HMAC accepted despite arbitrary, non-myshopify shop header
    assert ShopifyAPI::Utils::HmacValidator.validate(request)
    assert_equal "attacker-controlled-not-a-real-shop", request.shop

    handler = Class.new do
      extend ShopifyAPI::Webhooks::WebhookHandler
      class << self
        attr_accessor :received_shop
        def handle(data:)
          self.received_shop = data.shop
        end
      end
    end

    ShopifyAPI::Webhooks::Registry.add_registration(
      topic: "orders/create", delivery_method: :http, path: "cb", handler: handler,
    )
    ShopifyAPI::Webhooks::Registry.process(request)

    # data.shop equals the unsanitized, attacker-forged header value
    assert_equal "attacker-controlled-not-a-real-shop", handler.received_shop
  end
end
```
