### Title
Uniswap V4 spot-price venue pricing has no manipulation resistance (raw `sqrtPriceX96` mid, no TWAP, optional guard) — ([File: sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts])

### Summary
Simplex's `FXFiller` prices curveless cross-asset pairs directly off a Uniswap V4 pool's instantaneous spot price (`sqrtPriceX96` at the current tick), the same class of "manipulate the on-chain price source, then trade against it" attack described in the BGM incident. The only defense is a per-position `referencePrice`/`maxDeviationBps` guard that is **optional** and, even when configured, only checks static deviation rather than any TWAP or execution-cost-aware price — leaving a single-block spot-price manipulation (e.g. a large swap/flash-loan against a thin pool) able to move the reported price within the tolerated band or entirely unguarded, causing the solver to over-deliver output tokens against an artificially skewed rate.

### Finding Description
`UniswapV4FundingPlanner.getExoticTokenPrice` picks the most-liquid position and calls `computeDirectPoolPriceUsd`, which derives price straight from the pool's `sqrtPriceX96`/tick read via `StateView.getSlot0` [1](#0-0) . This is documented explicitly as the raw pool mid with no size or impact term: `computeLegPolicyOutput` extends this mid linearly across the whole priced quantity, and the fee tier is read but never applied [2](#0-1) .

The rate feeds two places:
1. Trade pricing (`resolveLegRates`), which determines the actual output amount the solver delivers to the counterparty [3](#0-2) .
2. Confirmation-depth sizing (`referenceRate`), which determines how many block confirmations are required before a cross-chain fill is trusted [4](#0-3) .

The only mitigation, `checkPriceGuard`, is a static-reference deviation check that is opt-in per chain (`priceGuard` map) — "omit both to leave the chain unguarded" per the docs [5](#0-4) , and the guard itself is documented as checking "deviation from a static reference, not execution cost" [6](#0-5) . Implementation confirms: no guard configured, or no reference for the chain, always passes [7](#0-6) .

`UniswapV4LiquidityState.refresh` re-reads slot0 immediately before each pricing/withdrawal decision [8](#0-7) , so an attacker who moves the pool's spot price via a swap (analogous to BGM's price-manipulation attack against a thin-liquidity token) immediately changes the price Simplex will trade at on its very next read, within the same or an adjacent block.

### Impact Explanation
An attacker who can move a configured Uniswap V4 pool's spot price (feasible against thin/exotic-token pools, exactly the BGM scenario) can:
- Force the solver to deliver output tokens at a manipulated (favorable-to-attacker) rate, directly draining solver-held funds on the destination chain, when no price guard is configured for that chain (the guard is explicitly optional per position/chain).
- Even where a guard is configured, stay inside the tolerated `maxDeviationBps` band while still extracting the deviation as arbitrage against the solver, since the guard bounds deviation from a stale/static reference rather than defending against manipulation magnitude combined with trade size or pool depth.
- Shrink the computed USD notional used for `referenceRate`/confirmation-depth sizing, reducing the number of confirmations Simplex waits for on a cross-chain order and weakening reorg protection — a route to accepting an order that is later reversed by a chain reorg, per the code comment: "a manipulated pool understating the value would shrink the reorg protection — the exact attack the guard exists to stop" [9](#0-8) .

This is a concrete theft-of-funds vector against the solver's inventory, reachable by any unprivileged actor able to trade against the configured pool and then submit/trigger an order fill — matching the BGM report's price-manipulation bug class.

### Likelihood Explanation
Medium-to-High: the price guard is optional by design (documented as such), so any deployment that omits it for a chain, or that uses a widely-tolerant `maxDeviationBps`, is directly exposed. Exotic/illiquid token pools (the intended use case for this feature, e.g. cNGN) are precisely the pools most susceptible to spot-price manipulation with modest capital, mirroring the low-liquidity BGM token scenario.

### Recommendation
- Make the price guard mandatory (not optional) for any curveless/venue-priced pair, or refuse to price without it.
- Replace or supplement the instantaneous `sqrtPriceX96` mid with a TWAP (time-weighted average, using multiple blocks/observations) so a single-block manipulation cannot move the executed price.
- Incorporate pool depth/impact and the pool's own fee tier into `computeLegPolicyOutput` rather than extending the mid linearly, so a shallow pool cannot be trivially pushed to an attacker-favorable rate.
- Apply the same guard consistently to both the trade-pricing path and the confirmation-depth sizing path, and consider tightening `maxDeviationBps` bounds or making them size-aware.

### Proof of Concept
1. Attacker identifies a Simplex deployment with a `[vault.uniswapV4]` position configured for an exotic/thin-liquidity token pair with **no** `referencePrice`/`maxDeviationBps` guard set (permitted per config: "omit both to leave the chain unguarded") [5](#0-4) .
2. Attacker executes a large swap against the pool to move `sqrtPriceX96` (spot price) sharply in their favor.
3. Attacker immediately submits (or triggers) an order that Simplex's `FXFiller` will price via `getExoticTokenPrice` → `computeDirectPoolPriceUsd`, which reads the just-manipulated slot0 on the next `refresh()` call [8](#0-7) .
4. `resolveLegRates` computes the trade rate from this manipulated venue price and the solver delivers output tokens at the skewed rate [3](#0-2) , resulting in a loss to the solver equal to the manipulated spread, analogous to the attacker profit mechanism in the BGM incident.

	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}

	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {
			this.logger.warn(
				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
	}

	/**
	 * Minimum-size reference rate (token1 per token0) for a leg's pair: the
	 * bid curve at 0 (the side token1-input legs trade at), falling back to the
	 * ask curve, then the live venue quote for venue-priced pairs.
	 */
	private async referenceRate(
		leg: ResolvedLeg,
		venueUsdPrice: (chain: string, token1Address: string) => Promise<Decimal | null>,
	): Promise<Decimal | null> {
		const policy = leg.pair.bidPricePolicy ?? leg.pair.askPricePolicy
		if (policy) {
			const rate = policy.getPrice(new Decimal(0))
			return rate.gt(0) ? rate : null
		}
		// Venue-priced pair: token0 is USD-stable (constructor invariant), so the
		// venue's USD-per-token1 quote inverts straight into token1-per-token0.
		const venueUsd = await venueUsdPrice(leg.token1Chain, leg.token1Address)
		if (!venueUsd) return null
		const venueRate = new Decimal(1).div(venueUsd)
		// Same guard as trade pricing: this rate sizes the order's USD notional
		// for confirmation depth, and a manipulated pool understating the value
		// would shrink the reorg protection — the exact attack the guard exists
		// to stop. Refusing to size skips the order, consistent with pricing.
		if (!this.checkPriceGuard(undefined, leg.token1Chain, venueRate)) return null
		return venueRate
	}

```text
## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.
```

	async refresh(): Promise<void> {
		const client = this.clientManager.getPublicClient(this.chain)
		const chainId = chainIdFromIdentifier(this.chain)

		// Group positions by poolId to avoid duplicate pool state fetches
		const poolIds = new Set(this.tokenIdToPoolId.values())

		// Fetch slot0 + liquidity for each unique pool via StateView
		const poolStateMap = new Map<string, { sqrtPriceX96: bigint; tick: number; poolLiquidity: bigint }>()

		for (const poolId of poolIds) {
			const [slot0Result, poolLiquidity] = await Promise.all([
				client.readContract({
					address: this.stateView,
					abi: UNISWAP_V4_STATE_VIEW_ABI,
					functionName: "getSlot0",
					args: [poolId as HexString],
				}) as Promise<[bigint, number, number, number]>,
				client.readContract({
					address: this.stateView,
					abi: UNISWAP_V4_STATE_VIEW_ABI,
					functionName: "getLiquidity",
					args: [poolId as HexString],
				}) as Promise<bigint>,
			])

			poolStateMap.set(poolId, {
				sqrtPriceX96: slot0Result[0],
				tick: slot0Result[1],
				poolLiquidity,
			})
		}

		// Refresh per-position liquidity and rebuild SDK Pool objects
		for (const pos of this.positions.values()) {
			const key = pos.tokenId.toString()
			const poolId = this.tokenIdToPoolId.get(key)
			const poolState = poolId ? poolStateMap.get(poolId) : undefined
			if (!poolId || !poolState) {
				throw new Error(
					`UniswapV4 refresh: missing pool state for tokenId ${key} (poolId=${poolId ?? "undefined"})`,
				)
			}

			// Read current position liquidity
			const liquidity = (await client.readContract({
				address: pos.positionManager,
				abi: UNISWAP_V4_POSITION_MANAGER_ABI,
				functionName: "getPositionLiquidity",
				args: [pos.tokenId],
			})) as bigint

			pos.liquidity = liquidity
			const prevOnChain = this.lastOnChainLiquidity.get(key) ?? liquidity
			const decrease = prevOnChain > liquidity ? prevOnChain - liquidity : 0n
			const prevConsumed = this.consumed.get(key) ?? 0n
			const newConsumed = prevConsumed > decrease ? prevConsumed - decrease : 0n
			this.consumed.set(key, newConsumed)
			this.lastOnChainLiquidity.set(key, liquidity)
			pos.remainingLiquidity = liquidity > newConsumed ? liquidity - newConsumed : 0n
			pos.sqrtPriceX96 = poolState.sqrtPriceX96
