Found the analog: `Parachain.id` is declared as `uint256` in `evm/src/consensus/Types.sol`, but `verifyParachainHeaderProof` truncates it to `uint32` when computing the leaf hash used for the merkle-multi-proof over the BEEFY parachain-heads root.

### Title
Integer truncation of parachain ID from `uint256` to `uint32` in BEEFY merkle leaf hashing allows parachain header forgery/collision - (File: evm/src/consensus/EcdsaBeefy.sol)

### Summary
`verifyParachainHeaderProof` in [1](#0-0)  builds the merkle leaf that is checked against the on-chain BEEFY parachain-heads root by truncating the attacker-supplied `Parachain.id` (`uint256`, see [2](#0-1) ) down to `uint32` before hashing:

```solidity
leaves[i] = MerkleMultiProof.Leaf(
    para.index,
    keccak256(bytes.concat(ScaleCodec.encode32(uint32(para.id)), ScaleCodec.encodeBytes(para.header)))
);
...
intermediates[i] = IntermediateState({stateMachineId: para.id, height: header.number, commitment: commitment});
``` [3](#0-2) 

### Finding Description
The `id` value used to authenticate the leaf against the trusted BEEFY parachain-heads merkle root is `uint32(para.id)` — an unchecked narrowing cast of a `uint256` — while the `id` value that is subsequently trusted and returned as the `stateMachineId` in the resulting `IntermediateState` (used for all downstream consensus-state commitments and message routing) is the full, un-truncated `para.id`. This is the same class of bug as CWE-681 (Incorrect Conversion between Numeric Types) referenced in the external Xalan report: a value is validated/committed using a truncated representation, while a different, non-truncated representation is trusted for subsequent processing.

Because `Parachain.id` is caller-supplied `calldata` (part of `ParachainProof.parachains`, itself part of `BeefyConsensusProof` submitted by any relayer to `EcdsaBeefy.verify`), an attacker can choose `para.id = X + k*2^32` for any `k`. The truncated hash `uint32(para.id)` collides with the hash that would be produced by the legitimate parachain id `X mod 2^32`, so the merkle-multi-proof check in `MerkleMultiProof.VerifyProof` can be satisfied with a header that was actually finalized for state machine `X mod 2^32`, while the function returns `IntermediateState.stateMachineId = X + k*2^32` (or any distinct value sharing the low 32 bits) to the caller.

### Impact Explanation
The `stateMachineId` returned from `verifyParachainHeaderProof` is used by the coprocessor to attribute a proven state commitment (state root / MMR overlay root / timestamp) to a particular `StateMachine` id. Colliding the truncated hash lets an attacker present a state commitment that was legitimately finalized for one parachain as if it belonged to a different parachain id (any id congruent mod 2^32), without needing consensus/authority set collusion — the merkle proof itself is genuine and verifies, only the claimed identity of which chain it belongs to is forged via the truncation mismatch. This can let an attacker register a forged/duplicated state machine height/commitment or associate a real state root with the wrong `StateMachineId`, enabling forged message delivery or state-commitment confusion for messages routed by `HandlerV2`/`EvmHost` that key off `StateMachineId`.

### Likelihood Explanation
`EcdsaBeefy.verify` is reachable by any unprivileged relayer submitting a `BeefyConsensusProof` (via the consensus message dispatch path). The `Parachain.id` field is fully attacker-controlled `calldata` with no upper-bound check anywhere in `verifyParachainHeaderProof`, `Codec.DecodeHeader`, or the `ParachainProof` decode path. Exploitation only requires crafting an id value `> 2^32` that collides in the low 32 bits with a real parachain id whose header/proof the attacker already has (any already-finalized parachain header can be replayed under a different large id).

### Recommendation
Require `para.id <= type(uint32).max` (revert otherwise) before truncating, or change `ScaleCodec.encode32` usage to encode the full `para.id` width matching the wire-format that produced the trusted merkle root, so the value hashed into the leaf and the value trusted as `stateMachineId` are always identical and non-truncated.

### Proof of Concept
1. Attacker observes a legitimately finalized parachain header for parachain id `P` (`P < 2^32`) with a valid `ParachainProof` merkle-multi-proof against the trusted `headsRoot`.
2. Attacker resubmits the same `header`/`proof`/`index`, but sets `Parachain.id = P + 2^32` (or `P + k*2^32`) in the `ParachainProof.parachains[]` array passed to `EcdsaBeefy.verify`.
3. In `verifyParachainHeaderProof` ( [4](#0-3) ), `uint32(para.id)` truncates back to `P`, so `keccak256(encode32(uint32(para.id)) || header)` is identical to the genuine leaf hash, and `MerkleMultiProof.VerifyProof` succeeds against the real `headsRoot`.
4. The function returns `IntermediateState{ stateMachineId: P + 2^32, height: ..., commitment: ... }` — a state commitment for parachain `P`'s header now attributed to a different, attacker-chosen `stateMachineId`, which propagates into consensus state updates keyed by that id.

    // @dev Verifies that some parachain header has been finalized, given the current trusted consensus state.
    function verifyParachainHeaderProof(bytes32 headsRoot, ParachainProof memory proof)
        internal
        pure
        returns (IntermediateState[] memory)
    {
        uint256 len = proof.parachains.length;
        MerkleMultiProof.Leaf[] memory leaves = new MerkleMultiProof.Leaf[](len);
        IntermediateState[] memory intermediates = new IntermediateState[](len);

        for (uint256 i = 0; i < len; i++) {
            Parachain memory para = proof.parachains[i];
            Header memory header = Codec.DecodeHeader(para.header);
            if (header.number == 0) revert IllegalGenesisBlock();

            leaves[i] = MerkleMultiProof.Leaf(
                para.index,
                keccak256(bytes.concat(ScaleCodec.encode32(uint32(para.id)), ScaleCodec.encodeBytes(para.header)))
            );

            StateCommitment memory commitment = header.stateCommitment();
            intermediates[i] =
                IntermediateState({stateMachineId: para.id, height: header.number, commitment: commitment});
        }

        if (len > 0) {
            bool valid = MerkleMultiProof.VerifyProof(headsRoot, proof.proof, leaves, proof.leafCount);
            if (!valid) revert InvalidMmrProof();
        }

        return intermediates;
    }
```
