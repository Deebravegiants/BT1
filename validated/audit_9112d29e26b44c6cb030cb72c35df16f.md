### Title
Unchecked zero-denominator division panics `SwapBaseOut`/`SwapBaseOutV2` when `amount_out` equals pool reserves - (File: `program/src/math.rs`)

### Summary
`Calculator::swap_token_amount_base_out` computes a denominator by subtracting the user-supplied `amount_out` from the pool's total reserve, then divides by that denominator via `checked_ceil_div(...).unwrap()`. If `amount_out` exactly equals the reserve, the denominator is `0`, `checked_div` returns `None`, and the subsequent `.unwrap()` panics, aborting the transaction. This mirrors the reported `muldiv()` bug class where an unchecked zero denominator crashes the contract.

### Finding Description
In `swap_token_amount_base_out` [3](#0-2) , for `SwapDirection::Coin2PC`:
```
let denominator = total_pc_without_take_pnl.checked_sub(amount_out).unwrap();
amount_in = total_coin_without_take_pnl.checked_mul(amount_out).unwrap()
    .checked_ceil_div(denominator).unwrap()
```
`checked_ceil_div` internally does `self.checked_div(rhs)?` [4](#0-3) , which returns `None` when `rhs == 0`, propagating `None` out of `checked_ceil_div`; the outer `.unwrap()` then panics.

This is directly reachable: `process_swap_base_out` and `process_swap_base_out_v2` take `swap.amount_out` from unvalidated instruction data and pass it straight into `Calculator::swap_token_amount_base_out` at [1](#0-0)  and [5](#0-4) , with no prior check that `amount_out < total_pc_without_take_pnl` (Coin2PC) or `amount_out < total_coin_without_take_pnl` (PC2Coin). The only such bounds check (`swap.amount_out >= total_pc_without_take_pnl` → `InsufficientFunds`) occurs after this division, at [2](#0-1)  and [6](#0-5) , so it never prevents the panic.

An unprivileged swapper can therefore submit a `SwapBaseOut` (opcode 11) or `SwapBaseOutV2` instruction with `amount_out` set to the current `total_pc_without_take_pnl` (or `total_coin_without_take_pnl` for the reverse direction, obtained by reading the AMM's vault balances, which are public), triggering a runtime panic in the on-chain program.

### Impact Explanation
A panic inside a Solana program instruction simply fails that transaction; it does not corrupt persistent state or crash the validator/other users' funds. This causes only a denial-of-service for that specific transaction (and for any composed transaction that includes this instruction), not theft of funds, unbacked LP minting, or insolvency of pool accounting. Per the validation rules requiring "concrete theft or permanent freezing of user or LP funds, unbacked LP minting, insolvent pool accounting, or an unauthorized privileged effect," a single-instruction revert does not meet that bar — it is a transaction-level revert that any other user can retry successfully with a valid `amount_out`, and does not permanently freeze funds.

### Likelihood Explanation
Trivial to trigger: attacker just needs to read the vault balances (public, non-privileged) and submit `amount_out` equal to the reserve total. However, since the effect is limited to reverting the attacker's own (or a composed) transaction, there is no incentive for exploitation beyond griefing a specific transaction bundle, and no way to cause lasting damage.

### Recommendation
Add an explicit check that `amount_out < total_pc_without_take_pnl` (or `< total_coin_without_take_pnl`) before calling `swap_token_amount_base_out`, returning `AmmError::InsufficientFunds` (or similar) instead of relying on the unchecked subtraction/division to fail. Alternatively, replace `.unwrap()` on `checked_ceil_div` with a proper `ok_or(AmmError::...)?` propagation so the program returns a controlled error instead of panicking.

### Proof of Concept
1. Read `amm_pc_vault.amount` / `amm_coin_vault.amount` for a target pool (public account data) and compute `total_pc_without_take_pnl` via `Calculator::calc_total_without_take_pnl_no_orderbook`.
2. Submit a `SwapBaseOut` instruction (opcode 11) with `amount_out` set exactly equal to `total_pc_without_take_pnl` (direction Coin2PC) and any `max_amount_in`.
3. Inside `process_swap_base_out`, `swap_token_amount_base_out` computes `denominator = total_pc_without_take_pnl - amount_out = 0`, then `checked_ceil_div(0)` returns `None`, and `.unwrap()` panics, aborting the transaction before the later `InsufficientFunds` check at line 2214 is ever reached.     pub fn swap_token_amount_base_out(
        amount_out: U128,
        total_pc_without_take_pnl: U128,
        total_coin_without_take_pnl: U128,
        swap_direction: SwapDirection,
    ) -> U128 {
        let amount_in;
        match swap_direction {
            SwapDirection::Coin2PC => {
                // (x + delta_x) * (y + delta_y) = x * y
                // (coin + amount_in) * (pc - amount_out) = coin * pc
                // => amount_in = coin * pc / (pc - amount_out) - coin
                // => amount_in = (coin * pc - pc * coin + amount_out * coin) / (pc - amount_out)
                // => amount_in = (amount_out * coin) / (pc - amount_out)
                let denominator = total_pc_without_take_pnl.checked_sub(amount_out).unwrap();
                amount_in = total_coin_without_take_pnl
                    .checked_mul(amount_out)
                    .unwrap()
                    .checked_ceil_div(denominator)
                    .unwrap()
            }
            SwapDirection::PC2Coin => {
                // (x + delta_x) * (y + delta_y) = x * y
                // (pc + amount_in) * (coin - amount_out) = coin * pc
                // => amount_out = coin - coin * pc / (pc + amount_in)
                // => amount_out = (coin * pc + coin * amount_in - coin * pc) / (pc + amount_in)
                // => amount_out = coin * amount_in / (pc + amount_in)

                // => amount_in = coin * pc / (coin - amount_out) - pc
                // => amount_in = (coin * pc - pc * coin + pc * amount_out) / (coin - amount_out)
                // => amount_in = (pc * amount_out) / (coin - amount_out)
                let denominator = total_coin_without_take_pnl.checked_sub(amount_out).unwrap();
                amount_in = total_pc_without_take_pnl
                    .checked_mul(amount_out)
                    .unwrap()
                    .checked_ceil_div(denominator)
                    .unwrap()
            }
        }
        return amount_in;
    }

pub trait CheckedCeilDiv: Sized {
    /// Perform ceiling division
    fn checked_ceil_div(&self, rhs: Self) -> Option<Self>;
}

impl CheckedCeilDiv for u128 {
    fn checked_ceil_div(&self, rhs: Self) -> Option<Self> {
        let mut quotient = self.checked_div(rhs)?;
        let remainder = self.checked_rem(rhs)?;
        if remainder != 0 {
            quotient = quotient.checked_add(1)?;
        }
        Some(quotient)
    }
}

impl CheckedCeilDiv for U128 {
    fn checked_ceil_div(&self, rhs: Self) -> Option<Self> {
        let mut quotient = self.checked_div(rhs)?;
        let remainder = self.checked_rem(rhs)?;
        if remainder != U128::zero() {
            quotient = quotient.checked_add(U128::one())?;
        }
        Some(quotient)
    }
