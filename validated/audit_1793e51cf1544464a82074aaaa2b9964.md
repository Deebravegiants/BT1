### Title
Accrued share-value overflow permanently freezes a market - (File: `common/src/rates/simulate.rs`)

### Summary
**Severity: High.** A sufficiently large borrowed market can make the accrued debt value exceed `i128` before the borrow index reaches its configured ceiling. Because every pool mutation synchronizes interest before changing state, the resulting `MathOverflow` traps all subsequent `update_indexes`, repay, withdraw, liquidation, and related flows for that market. [1](#0-0) [2](#0-1) 

### Finding Description
`accrue_step` converts the market-wide scaled debt and supply into RAY asset values before calculating utilization, and later multiplies the same scaled debt by both the old and new borrow indexes. [1](#0-0) 

Those products use `Ray::mul`, which evaluates an exact `x * y / RAY` through `fp_core::mul_div_half_up`. [3](#0-2) 

Although the intermediate product is widened to `I256`, the final quotient must fit `i128`; otherwise `to_i128` returns `None` and the helper raises `MathOverflow`. [4](#0-3) [5](#0-4) 

The configured index ceiling is `1e36` raw, while a scaled debt amount near `1e36` raw already overflows when the index reaches roughly `1.7e29` raw, only about 170 times the initial index. [6](#0-5) 

The cap validation permits up to `i128::MAX / 10^(27 - decimals)` base units, so an 18-decimal market can admit hundreds of billions of whole tokens and therefore reach scaled totals near `1e36`. [7](#0-6) [8](#0-7) 

Once this state is reached, `global_sync` panics inside the accrual loop and never reaches `mark_accrued`, so the transaction rollback leaves `last_timestamp` unchanged and the same overflow repeats forever. [9](#0-8) [10](#0-9) 

### Impact Explanation
This permanently freezes all supplier and protocol funds in the affected market. Every pool operation loads a synchronized market first, including supply, borrow, withdraw, repay, strategy creation, seizure, recapitalization, and explicit index updates. [11](#0-10) 

The user-facing controller exposes the affected flows through `supply`, `borrow`, `withdraw`, `repay`, and permissionless `liquidate`. [12](#0-11) 

Even the pool owner cannot recover through `update_params` or `update_indexes` because those paths also perform accrual before applying their intended mutation. [13](#0-12) [14](#0-13) 

### Likelihood Explanation
The attacker only needs permissionless controller operations and enough of the debt asset or collateral to create a very large, high-utilization market. [15](#0-14) 

The numerical condition is deterministic rather than dependent on oracle manipulation or another user's mistake: once `borrowed * borrow_index / RAY` can no longer fit `i128`, the next accrual always fails. [16](#0-15) 

For example, `9.8e35` scaled debt overflows once the index exceeds approximately `1.736e29` raw, far below the `1e36` index ceiling. [6](#0-5) [4](#0-3) 

The substantial capital requirement and need for sustained index growth reduce likelihood, but the result is irreversible without privileged intervention or a contract upgrade. [13](#0-12) 

### Recommendation
Enforce market-size limits against the worst-case representable value, not only the token-decimal conversion limit. In particular, cap scaled `borrowed` and `supplied` so `scaled * MAX_*_INDEX / RAY` remains within `i128`, or redesign market totals and accrual arithmetic to use a wider representation end-to-end. The pre-accrual checks should use conservative ceilings so an admitted position can never later become unprocessable at the configured index bounds.

### Proof of Concept
Consider an admitted 18-decimal market with a large cap and a high-utilization rate model:

```rust
// Controller-facing sequence.
let debt_asset = HubAssetKey { hub_id, asset: debt_token };
let collateral_asset = HubAssetKey { hub_id, asset: collateral_token };

// 1. Supply enough collateral to support the debt position.
controller.supply(
    caller,
    0,
    spoke_id,
    vec![(collateral_asset, sufficient_collateral)],
);

// 2. Borrow 980_000_000_000_000_000_000_000_000 base units:
//    980 million whole tokens at 18 decimals.
controller.borrow(
    caller,
    account_id,
    vec![(debt_asset, 980_000_000_000_000_000_000_000_000)],
    None,
);

// 3. Later, call controller update_indexes for the debt market,
//    or cause the same sync through repay/withdraw/liquidate.
```

At 18 decimals, that debt has approximately `9.8e35` RAY-scaled shares before interest. `borrowed.mul(borrow_index)` overflows once `borrow_index` is around `173.6 RAY`, because the resulting debt value exceeds `i128::MAX`. [17](#0-16) 

The next accrual reverts in `accrue_step`, either while calculating `borrowed_original` and `supplied_original` or while calculating `new_total_debt`. [1](#0-0) [17](#0-16) 

Because `synced_market` performs this accrual before every market leg and `last_timestamp` is advanced only after all chunks complete, subsequent repayments and withdrawals encounter the same overflow and can never succeed. [11](#0-10) [9](#0-8)

```rust
pub fn calculate_supplier_rewards(
    env: &Env,
    params: &MarketParams,
    borrowed: Ray,
    new_borrow_index: Ray,
    old_borrow_index: Ray,
) -> (Ray, Ray) {
    let old_total_debt = borrowed.mul(env, old_borrow_index);
    let new_total_debt = borrowed.mul(env, new_borrow_index);

    let accrued_interest = new_total_debt.checked_sub(env, old_total_debt);

    let protocol_fee = params.reserve_factor.apply_to_ray(env, accrued_interest);
    let supplier_rewards = accrued_interest.checked_sub(env, protocol_fee);

    (supplier_rewards, protocol_fee)
```

```rust
/// Returns the largest cap, in asset base units, whose ray-scaled form still
/// fits in `i128`.
///
/// Returns 0 when `asset_decimals > RAY_DECIMALS`, since the ray form is not
/// representable in that case. Enforced by
/// [`require_cap_within_asset_domain`], so stored caps can never overflow the
/// asset→ray rescale.
pub fn max_cap_for_decimals(asset_decimals: u32) -> i128 {
    let Some(exp) = RAY_DECIMALS.checked_sub(asset_decimals) else {
        return 0;
    };
    let upscale = 10i128
        .checked_pow(exp)
        .expect("10^(RAY_DECIMALS - asset_decimals) fits i128 for asset_decimals <= RAY_DECIMALS");
    i128::MAX / upscale
```

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```

```rust
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
```
