### Title
Authenticated arbitrary command execution via `StandardCapabilities` job spec `command` field - (File: core/services/standardcapabilities/delegate.go)

### Summary
Chainlink node operators with an "Edit" (or higher) role can create a `standardcapabilities` job via the REST (`POST /v2/jobs`) or GraphQL (`createJob`) job-creation APIs. The job spec's `command` field is a free-form string that is later passed directly to `exec.Command` to spawn a LOOP plugin subprocess, with no validation restricting it to an allowed binary/path. This mirrors the CVE-2020-26670 bug class: an authenticated, non-admin actor abusing a "create new setting/spec" feature to achieve arbitrary command execution on the server.

### Finding Description
Job creation for `job.StandardCapabilities` accepts a TOML spec containing a `command` string field: [1](#0-0) 

Validation only checks that the command is non-empty — it does not restrict it to a known binary name, path, or allowlist: [2](#0-1) 

When the job is started, this `Command` string is threaded through `Delegate.ServicesForSpec` → `NewServices` → `NewStandardCapabilities`, and ultimately becomes the executable path handed to `plugins.NewCmdFactory`, which builds an `os/exec.Cmd` directly from the raw string: [3](#0-2) [4](#0-3) 

The job-creation endpoints reachable by an authenticated non-admin user are:
- REST: `POST /v2/jobs` → `JobsController.Create`, which parses the TOML and calls `App.AddJobV2`: [5](#0-4) 
- GraphQL: `createJob` mutation, gated only by `authenticateUserCanEdit`, which permits any user with role `edit` or `admin` (not `view`/`run`): [6](#0-5) [7](#0-6) 

Because the `command` field of a `standardcapabilities` job spec is unrestricted, an "Edit"-role user (a privilege tier below "Admin", intended for configuring bridges/jobs, not raw system access) can specify any path on the filesystem — including a path they can write to (e.g. via a bridge/adapter upload feature, `/tmp`, or any writable directory), or any pre-existing system binary — and have the node execute it as a subprocess with the node process's privileges. There is no allowlist enforcement for unknown commands (`GetCapabilityIDFromCommand` returns empty for unrecognized commands, and the delegate explicitly allows unknown commands to "bypass the allowlist check"): [8](#0-7) 

### Impact Explanation
This allows a non-admin authenticated actor (Edit role) to achieve arbitrary command/binary execution on the Chainlink node host, gaining the same execution context as the node process — which typically has access to secrets, private keys (ETH/OCR/P2P keys), the database, and network connectivity to chains. This is a direct match for CVE-2020-26670's bug class ("authenticated attacker executes arbitrary commands through a crafted 'Create a New Setting' request") and satisfies the "unauthorized job run" / "authentication or role bypass leading to command execution" acceptance criteria, since Edit-role is explicitly a lesser privilege than Admin yet suffices to reach code execution.

### Likelihood Explanation
Likelihood is high in any deployment where "Edit" role credentials are distributed to less-trusted operators/users (a common Chainlink RBAC pattern, distinguishing Edit from Admin). No additional bypass is needed beyond normal job-creation API usage with a crafted TOML spec.

### Recommendation
- Restrict `StandardCapabilitiesSpec.Command` to values from a fixed allowlist/registry of authorized capability binaries (already partially present via `IsAllowlisted`/`RegistryBasedLaunchAllowlist`, but bypassed entirely for "unknown" commands).
- Require Admin role (not Edit) to create/modify `standardcapabilities` job specs, since this job type effectively grants code execution.
- Validate that `Command` resolves to an absolute path within a trusted, non-writable capabilities directory (similar to `DefaultCapabilitiesDir` used in test/CRE tooling) and reject any other value, rather than trusting the LOOP registrar to police it.

### Proof of Concept
1. Authenticate as a user with role `edit` (not `admin`).
2. Submit a GraphQL `createJob` mutation (or `POST /v2/jobs`) with TOML:
```
type = "standardcapabilities"
schemaVersion = 1
name = "poc"
externalJobID = "<uuid>"
forwardingAllowed = false
command = "/tmp/evil_binary"
config = ""
```
3. Node spawns `/tmp/evil_binary` as a subprocess via `plugins.NewCmdFactory` → `exec.Command(lcfg.Cmd)` with the node's environment/privileges when the job is started (`AddJobV2` → `StartService`).

Note: I could not fully confirm from the indexed router configuration whether `POST /v2/jobs` REST route enforces `RequiresEditRole` specifically (the grep for the REST route wiring in `core/web/router.go` did not return conclusive line content within the available context), so the REST path's exact role gate should be verified directly in `core/web/router.go`; the GraphQL path's `edit`-role gate is confirmed via `authenticateUserCanEdit`.

func ValidatedStandardCapabilitiesSpec(tomlString string) (job.Job, error) {
	jb := job.Job{ExternalJobID: uuid.New()}

	tree, err := toml.Load(tomlString)
	if err != nil {
		return jb, errors.Wrap(err, "toml error on load standard capabilities")
	}

	err = tree.Unmarshal(&jb)
	if err != nil {
		return jb, errors.Wrap(err, "toml unmarshal error on standard capabilities spec")
	}

	var spec job.StandardCapabilitiesSpec
	err = tree.Unmarshal(&spec)
	if err != nil {
		return jb, errors.Wrap(err, "toml unmarshal error on standard capabilities job")
	}

	jb.StandardCapabilitiesSpec = &spec
	if jb.Type != job.StandardCapabilities {
		return jb, errors.Errorf("standard capabilities unsupported job type %s", jb.Type)
	}

	if len(jb.StandardCapabilitiesSpec.Command) == 0 {
		return jb, errors.Errorf("standard capabilities command must be set")
	}

// NewCmdFactory is helper to ensure synchronization between the loop registry and os cmd to exec the LOOP
func NewCmdFactory(register func(id string) (*RegisteredLoop, error), lcfg CmdConfig) (func() *exec.Cmd, error) {
	registeredLoop, err := register(lcfg.ID)
	if err != nil {
		return nil, fmt.Errorf("failed to register %s LOOP plugin: %w", lcfg.ID, err)
	}
	return func() *exec.Cmd {
		cmd := exec.Command(lcfg.Cmd) //#nosec G204 -- we control the value of the cmd so the lint/sec error is a false positive
		cmd.Env = append(cmd.Env, lcfg.Env...)
		cmd.Env = append(cmd.Env, registeredLoop.EnvCfg.AsCmdEnv()...)
		return cmd
	}, nil
}

func (s *StandardCapabilities) Start(ctx context.Context) error {

		envVars, err := plugins.ParseEnvFile(env.CapabilitiesPlugin.Env.Get())
		if err != nil {
			return fmt.Errorf("failed to parse capabilities env file: %w", err)
		}
		cmdFn, opts, err := s.pluginRegistrar.RegisterLOOP(plugins.CmdConfig{
			ID:  s.log.Name(),
			Cmd: s.command,
			Env: envVars,
		})
		if err != nil {
			return fmt.Errorf("error registering loop: %w", err)
		}

		s.capabilitiesLoop = loop.NewStandardCapabilitiesService(s.log, opts, cmdFn)
		if err = s.capabilitiesLoop.Start(ctx); err != nil {
			return fmt.Errorf("error starting standard capabilities service: %w", err)
		}

func (jc *JobsController) Create(c *gin.Context) {
	request := CreateJobRequest{}
	if err := c.ShouldBindJSON(&request); err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	jb, status, err := jc.validateJobSpec(c.Request.Context(), request.TOML)
	if err != nil {
		jsonAPIError(c, status, err)
		return
	}

	ctx, cancel := context.WithTimeout(c.Request.Context(), 5*time.Second)
	defer cancel()
	err = jc.App.AddJobV2(ctx, &jb)
	if err != nil {
		if errors.Is(errors.Cause(err), job.ErrNoSuchKeyBundle) || errors.As(err, &keystore.KeyNotFoundError{}) || errors.Is(errors.Cause(err), job.ErrNoSuchTransmitterKey) || errors.Is(errors.Cause(err), job.ErrNoSuchSendingKey) {
			jsonAPIError(c, http.StatusBadRequest, err)
			return
		}
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

// Authenticates the user from the session cookie and asserts at least 'edit' role.
func authenticateUserCanEdit(ctx context.Context) error {
	session, ok := auth.GetGQLAuthenticatedSession(ctx)
	if !ok {
		return unauthorizedError{}
	}
	switch session.User.Role {
	case sessions.UserRoleView, sessions.UserRoleRun:
		return RoleNotPermittedError{session.User.Role}
	default:
	}
	return nil
}
