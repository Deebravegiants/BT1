### Title
Unbounded dust supplies create persistent account and NFT storage - (File: contracts/controller/src/positions/supply.rs)

### Summary
An unprivileged caller can repeatedly invoke `supply` with `account_id = 0` and a one-base-unit deposit, causing each call to mint a new position NFT and create a separate controller account with a persistent supply position. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`Controller::supply` delegates to `process_supply`, which authenticates the caller, accepts any positive payment, and calls `load_or_create_account` with the caller-supplied `account_id`. [4](#0-3) 

When `account_id == 0`, `load_or_create_account` unconditionally creates a new account owned by the caller. [5](#0-4) 

Account creation mints a new NFT token id and stores `AccountMeta(account_id)`, while deposit processing writes the hub asset into `SupplyPositions(account_id)`. [2](#0-1) [6](#0-5) 

The pool rejects only deposits that mint zero scaled shares; it does not enforce a minimum token amount or minimum USD value. [3](#0-2) 

A supply position is removed only when its scaled amount reaches zero, and the account is deleted only when both position maps are empty, so leaving one economically meaningless unit preserves the account and its storage. [7](#0-6) 

### Impact Explanation
This is a storage denial-of-service issue: one address can force unbounded growth in controller account metadata, per-account position maps, and position-NFT ownership state. [2](#0-1) [6](#0-5) 

Because each new account can be opened with a one-base-unit deposit, using a low-value listed asset makes the marginal collateral cost negligible compared with the persistent storage and later TTL/restoration burden. [8](#0-7) [3](#0-2) 

At sufficient scale, the resulting storage-maintenance cost can exhaust the operational token budget needed to renew or restore protocol state, preventing normal contract operation until state is restored. [9](#0-8) [10](#0-9) 

### Likelihood Explanation
The attack requires no privileged role, borrowed liquidity, oracle manipulation, or foreign-account access: the caller authenticates, passes `account_id = 0`, selects a valid `spoke_id`, and supplies any positive amount that mints at least one share. [11](#0-10) [3](#0-2) 

The position-count limit bounds only the number of hub assets inside one account and does not limit the number of accounts or NFT ids a caller can create. [12](#0-11) 

### Recommendation
Enforce a minimum economically meaningful deposit for account-creating supplies, preferably denominated in USD and evaluated with conservative prices and indexes. [13](#0-12) 

For partial withdrawals, require every remaining supply leg to be either zero or at least that minimum, forcing dust positions to close completely instead of preserving account storage. [7](#0-6) 

### Proof of Concept
The repository already contains a harness PoC showing that one attacker can create 64 distinct persistent accounts using one raw unit per account. [14](#0-13) 

```rust
#[test]
fn poc_single_actor_spams_unbounded_dust_accounts() {
    let mut t = LendingTest::new().with_market(usdc_preset()).build();

    let attacker = t.get_or_create_user("attacker");
    let usdc = t.resolve_market("USDC");

    const N: u64 = 64;
    usdc.token_admin.mint(&attacker, &(N as i128));
    let asset = usdc.asset.clone();

    let ctrl = t.ctrl_client();
    let mut created: u64 = 0;
    let mut last_id: u64 = 0;
    for _ in 0..N {
        let dust = vec![&t.env, (hub_asset(asset.clone()), 1i128)];
        let id = ctrl.supply(&attacker, &0u64, &1u32, &dust);
        assert!(id > 0, "1-unit deposit must be accepted (no dust floor)");

        assert!(id > last_id, "each supply(id=0) must mint a new account id");
        assert!(
            ctrl.account_exists(&id),
            "spammed account persists in storage"
        );
        last_id = id;
        created += 1;
    }

    assert_eq!(created, N);
}
```

pub(crate) fn process_deposit(
    env: &Env,
    caller: &Address,
    account: &mut Account,
    aggregated: &AggregatedPayments,
    cache: &mut Context,
) {
    validate_position_entry_gates(
        env,
        account,
        aggregated,
        cache,
        AccountPositionType::Deposit,

    let pool_addr = cache.cached_pool_address();
    let mut entries: Vec<PoolSupplyEntry> = Vec::new(env);
    for (hub_asset, amount_in) in aggregated.iter() {
        let asset_config: AssetConfig = cache.require_spoke_asset(account.spoke_id, &hub_asset);

            env,
            &hub_asset.asset,

            &pool_addr,
            amount_in,
            GenericError::AmountMustBePositive,
        );
        let position = account.get_or_create_supply_position(&hub_asset, &asset_config);
        entries.push_back(PoolSupplyEntry {
            action: make_pool_action(&position, received, hub_asset.clone()),
        });
    }

    let results = pool_supply_call(env, &pool_addr, &entries);
    for_each_leg(env, &entries, &results, |entry, result| {
        merge_supply_leg(env, account, &entry.action, &result, cache);

pub(crate) fn validate_bulk_position_limits(
    env: &Env,
    account: &Account,
    position_type: AccountPositionType,
    aggregated: &AggregatedPayments,
) {
    let limits = storage::get_position_limits(env);

    let (current_count, max_allowed) = match position_type {
        AccountPositionType::Deposit => {
            (account.supply_positions.len(), limits.max_supply_positions)
        }
        AccountPositionType::Borrow => {
            (account.borrow_positions.len(), limits.max_borrow_positions)
        }
    };

    let mut seen: Map<HubAssetKey, bool> = Map::new(env);
    let mut new_positions_count: u32 = 0;
    for (hub_asset, _) in aggregated.iter() {
        if seen.contains_key(hub_asset.clone()) {
            continue;
        }
        seen.set(hub_asset.clone(), true);

        let already_present = match position_type {
            AccountPositionType::Deposit => account.supply_positions.contains_key(hub_asset),
            AccountPositionType::Borrow => account.borrow_positions.contains_key(hub_asset),
        };
        if !already_present {
            new_positions_count += 1;
        }
    }

    // Existing positions remain usable after governance lowers the position limit.
    if new_positions_count == 0 {
        return;
    }

    let total_positions = current_count
        .checked_add(new_positions_count)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));
    assert_with_error!(
        env,
        total_positions <= max_allowed,
        CollateralError::PositionLimitExceeded
    );
