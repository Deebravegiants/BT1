Audit Report

## Title
Unauthenticated exposure of internal plugin metrics and pprof debug endpoints via LOOP registry routes - (File: core/web/router.go)

## Summary
The `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` routes are registered on the top-level `api` gin route group in `NewRouter`, which applies only rate limiting and session middleware, with no `auth.Authenticate` call anywhere in the chain [1](#0-0) . This allows any network caller who can reach the node's web server, without a session cookie or API token, to enumerate LOOP plugins and pull raw pprof profiles (heap, goroutine, CPU) and Prometheus metrics forwarded from internal plugin ports.

## Finding Description
`loopRoutes` is called directly on the unauthenticated `api` group [2](#0-1) , and registers all four LOOP diagnostic endpoints with no additional auth check inside `loopRoutes` itself [3](#0-2) . This is inconsistent with the equivalent node-local pprof route group `metricRoutes`, which is explicitly nested only inside the authenticated `authv2` group under the comment "Debug routes accessible via authentication" [4](#0-3) , and with `/debug/vars`, which is wrapped in its own group requiring `auth.Authenticate` [5](#0-4) .

The handlers `pluginMetricHandler`, `pluginPPROFHandler`, and `pluginPPROFPOSTSymbolHandler` forward caller-supplied query parameters (`debug`, `gc`, `seconds`) and path parameter (`profile`) straight through to `http://<loopHostName>:<PrometheusPort>/...` on the internal plugin process, with no authorization check performed anywhere in `loop_registry.go` [6](#0-5) . The discovery handler at `/discovery` similarly requires no authentication and enumerates all registered plugin names/ports [7](#0-6) .

## Impact Explanation
An unauthenticated network caller with reachability to the node's HTTP API can retrieve full pprof heap dumps, goroutine traces, and CPU profiles from LOOP plugins, as well as raw Prometheus metrics, via routes that carry no session or role check. Heap/goroutine profiling data can expose in-memory secrets or internal state and reveal internal code structure — a real information-disclosure impact, consistent with the documented risk noted for `InsecurePPROFHeap` regarding exposure of "private key components" [8](#0-7) . This maps to an in-scope "key/secret exfiltration" / sensitive information disclosure impact class.

## Likelihood Explanation
Exploitability requires only network reachability to the node's web server port — no credentials, role, or session are needed, since the `api` group applies only rate-limiting/session middleware with no authentication gate [1](#0-0) . Likelihood is high in any deployment where this port is exposed to untrusted callers.

## Recommendation
Move `loopRoutes` registration under an authenticated group (mirroring `metricRoutes` under `authv2`), or wrap each route with `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)` and/or an admin-role requirement before forwarding to internal plugin pprof/metrics endpoints.

## Proof of Concept
1. Start a Chainlink node with a LOOP plugin registered.
2. Without any session cookie or API token, issue `GET /discovery` to enumerate plugin names and Prometheus ports (per `discoveryHandler` at `core/web/loop_registry.go:52-65`).
3. Issue `GET /plugins/<name>/debug/pprof/heap?debug=1` without authentication; `pluginPPROFHandler` forwards this unauthenticated to the internal plugin's `/debug/pprof/heap` endpoint and returns the raw profile data (`core/web/loop_registry.go:150-166`).

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}

func (l *LoopRegistryServer) pluginPPROFPOSTSymbolHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/symbol", l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	body, err := io.ReadAll(gc.Request.Body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error reading plugin pprof request body: %s", err))
		return
	}
	l.doRequest(gc, "POST", pluginURL, bytes.NewReader(body), timeout, pluginName)
}
