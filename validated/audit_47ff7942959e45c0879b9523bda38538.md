## Analysis

The THORChain exploit hinged on the protocol trusting unauthenticated/fallback data to authorize a refund — Bifrost accepted a forged deposit event from an unregistered vault as if it were legitimate. Hyperbridge's `IntentGatewayV2` has an analogous authentication weakness in its Tron production contract: `instance()` silently falls back to `address(this)` for any *unregistered* source chain, instead of reverting as the canonical EVM implementation does.

Compare the two implementations:

Canonical/hardened version (`evm/src/apps/intentsv2/IntentsBase.sol`): [1](#0-0) 

Tron production contract (`evm/tron/contracts/apps/IntentGatewayV2.sol`): [2](#0-1) 

and its use in `onAccept`'s `RedeemEscrow`/`RefundEscrow` dispatch: [3](#0-2) 

Instead of reverting with `UnknownInstance()` when no peer gateway is registered for a source state machine, `instance()` returns `address(this)` — i.e., "trust the module if its address equals my own address." `authenticate()` then compares the message's `from` field against this fallback value: [4](#0-3) 

### Title
Insecure fallback in `instance()` allows forged escrow redeem/refund authentication for unregistered source chains - (File: evm/tron/contracts/apps/IntentGatewayV2.sol)

### Summary
`IntentGatewayV2.instance()` in the Tron production contract returns `address(this)` when no explicit peer deployment is registered for a source state machine, rather than reverting. This value is used directly by `authenticate()` to validate the sender module of incoming `RedeemEscrow`/`RefundEscrow` requests, meaning any message whose `from` field equals the local gateway's own address will pass authentication — even if it originates from an *unregistered* state machine that Hyperbridge has never been told hosts a legitimate IntentGateway peer.

### Finding Description
`onAccept` dispatches `RedeemEscrow`/`RefundEscrow` bodies straight to `withdraw()` once `authenticate()` passes: [3](#0-2)  `withdraw()` then transfers out the full escrowed token balance to whatever beneficiary the forged body specifies: [5](#0-4) 

The authentication only checks that `instance(request.source) == module` — but for any chain that Hyperbridge has consensus support for yet has *not* had a `NewDeployment` registered for this gateway, `instance()` silently defaults to `address(this)`. Because IntentGateway proxies are commonly deployed at deterministic (CREATE2) addresses across chains for UX/consistency, an attacker can deploy an arbitrary malicious contract at that same address on any state machine Hyperbridge later adds (or any chain not yet paired), send a genuine (non-forged at the consensus layer) `PostRequest` from it, and have the destination gateway treat it as a legitimate IntentGateway peer — this is the same failure pattern as THORChain's Bifrost trusting an unregistered vault's event data without confirming the counterparty's legitimacy. The equivalent code path in the maintained EVM implementation explicitly reverts with `UnknownInstance()` for this exact case, confirming the fallback in the Tron contract is an unsafe regression rather than intentional design: [6](#0-5) 

### Impact Explanation
A successful forged `RedeemEscrow` or `RefundEscrow` message drains the full escrow balance of any outstanding order for the specified tokens to an attacker-chosen beneficiary, resulting in direct theft of user-escrowed funds — a concrete, high-severity loss, matching the impact class validated in the rules (concrete theft / unauthorized app action reachable via a single relayed proof/message).

### Likelihood Explanation
Exploitation requires the attacker to control a contract at the exact target address on a state machine that Hyperbridge trusts but for which this gateway has not registered a peer (`_instances` entry). This is realistic wherever deterministic (CREATE2/factory) deployment addresses are used across chains and salts/bytecode are public, or simply whenever a new consensus client is added to Hyperbridge before the corresponding `NewDeployment` governance action is dispatched to every existing gateway — a window where the fallback is live and exploitable.

### Recommendation
Change `instance()` in `evm/tron/contracts/apps/IntentGatewayV2.sol` to revert with `UnknownInstance` (or equivalent) when no explicit deployment is registered, matching `evm/src/apps/intentsv2/IntentsBase.sol`'s `_instance()`, so that `authenticate()` can never treat an unregistered source chain's module as implicitly trusted.

### Proof of Concept
1. Hyperbridge adds consensus support for state machine `X`, but no `NewDeployment` has yet been dispatched to the Tron `IntentGatewayV2` registering a peer for `X`.
2. Attacker deploys a contract at address `A == address(thisTronGateway)` on chain `X` (via CREATE2 with a known/public salt, or simply by being the first deployer at a chain where Polytope's canonical deployment address is predictable).
3. From that contract, attacker dispatches a `PostRequest` to the Tron gateway with `body = RequestKind.RedeemEscrow ++ abi.encode(WithdrawalRequest{commitment: <any escrowed order's commitment>, tokens: <that order's inputs>, beneficiary: <attacker>})`.
4. `onAccept` → `authenticate()` computes `instance(X) == address(this) == module`, passes.
5. `withdraw()` transfers the escrowed tokens to the attacker: [7](#0-6)

     * @dev Resolves the IntentGateway instance address for a given state machine.
     * Reverts with `UnknownInstance` if no remote deployment has been registered for that chain.
     * @param stateMachineId The raw state machine identifier bytes.
     * @return The gateway address for the given state machine.

    function _instance(bytes calldata stateMachineId) internal view returns (address) {
        address gateway = _instances[keccak256(stateMachineId)];
        if (gateway == address(0)) revert UnknownInstance();
        return gateway;

    function instance(bytes calldata stateMachineId) public view returns (address) {
        address gateway = _instances[keccak256(stateMachineId)];
        return gateway == address(0) ? address(this) : gateway;

    /**
     * @dev Checks that the request originates from a known instance of the IntentGateway.
     */
    function authenticate(PostRequest calldata request) internal view {
        if (request.from.length != 20) revert InvalidInput();
        address module = address(bytes20(request.from));
        // IntentGateway only accepts incoming assets from itself or known instances
        if (instance(request.source) != module) revert Unauthorized();
    }
