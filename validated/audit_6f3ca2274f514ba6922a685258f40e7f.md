### Title
Consensus relayer reward can be stolen by batching a trivial self-signed message with another relayer's consensus proof - ([File: modules/pallets/consensus-incentives/src/impls.rs])

### Summary
`pallet-consensus-incentives` attributes the *entire* reward for a batch of ISMP messages submitted via the permissionless `handle_unsigned` extrinsic to whichever account signed **only the first message** in that batch, while the reward amount is computed from the **highest `StateMachineUpdated` height across all messages in the batch**. Because `handle_unsigned` is unsigned/permissionless and anyone can bundle arbitrary valid messages (including proofs they merely observed/copied from other relayers), an attacker can prepend a cheap, minimal self-signed consensus message to a batch that also contains a large, high-value consensus proof authored by someone else, and collect the reward for the entire height advance.

### Finding Description
`handle_unsigned` in `modules/pallets/ismp/src/lib.rs` is explicitly documented as permissionless: *"an unsigned extrinsic that permits anyone [to] execute ISMP messages for free, provided they have valid proofs"* [1](#0-0) . It accepts a `Vec<Message>` and executes them as a batch via `Self::execute(messages.clone())`.

The `FeeHandler::on_executed` implementation in `pallet-consensus-incentives` receives the *whole batch* (`messages: Vec<MessageWithWeight>`) plus the *whole batch's* resulting events, and identifies "the relayer" using **only `messages.get(0)`**: [2](#0-1) 

It then collapses **all** `StateMachineUpdated` events in the batch (potentially produced by later, unrelated messages) into a per-state-machine "highest height reached" map and pays the reward for that full span to the single relayer recovered from message[0]'s signature: [3](#0-2) 

The reward itself is `(LatestHeight − Baseline) * CostPerBlock`, where `LatestHeight` is taken from the batch's highest observed `StateMachineUpdated::latest_height`: [4](#0-3) 

This is the same bug class as the reported `drawRandomNumber()` issue: a permissionless, parameter-driven call (`handle_unsigned(messages)`) lets the caller supply an array (`messages`) whose composition directly determines who is credited for state that is actually produced by processing *other* elements of that same array — exactly like `_slots` changing `lastDrawEligibleCount` and letting the caller immediately benefit from the manipulated outcome (`claimWinning`). Here, the caller controls which message occupies index 0 (attribution) while unrelated/legitimate messages later in the array drive the reward magnitude.

### Impact Explanation
An attacker (any unprivileged account able to submit an unsigned extrinsic) can:
1. Observe a pending or just-broadcast valid consensus proof from a legitimate relayer that will advance a state machine by many blocks (a large reward).
2. Submit `handle_unsigned` themselves with a batch where `messages[0]` is a trivial, cheaply produced consensus message they sign (e.g., a minimal 1-block advance or even a message that ultimately fails to be the actual driver of the reward-worthy event), followed by the legitimate relayer's copied/observed proof(s).
3. Because `on_executed` derives the relayer identity solely from `messages[0]` but sums rewards from `StateMachineUpdated` events across the *entire* batch (deduplicated to the highest height per state machine), the attacker is paid the full `$BRIDGE` treasury reward and reputation-asset mint for the height advance that the legitimate relayer actually produced.

This results in concrete theft of protocol funds from the `TreasuryAccount` and unearned reputation-asset minting (`T::ReputationAsset::mint_into`), which also feeds into collator/block-author selection weighting — an unbacked "mint" of both currency and reputation. This is a direct, permanent misallocation of funds triggerable by any address submitting a single unsigned extrinsic, satisfying "concrete theft ... or unbacked mint" criteria.

### Likelihood Explanation
Likelihood is high: `handle_unsigned` is designed to be filled by anyone with no staking/permission requirement, and valid consensus proofs are inherently public once broadcast (they must be observable on-chain or in the transaction pool to be relayed/verified in the first place). An attacker only needs to win the race to include the victim's valid proof as a later element in their own batch ahead of the legitimate relayer's own submission of that same proof, or piggy-back on an already-submitted batch's proof data before it is mined. No cryptographic secret is required — only ordering/bundling of the message array, which is entirely attacker-controlled input to `execute()`.

### Recommendation
Attribute (and pay) rewards per-message rather than per-batch:
- In `on_executed`, iterate `messages` alongside their corresponding events (or recompute events per-message) and recover the relayer signer for each individual `Message::Consensus` entry, crediting only the `StateMachineUpdated` events that resulted from that specific message.
- Do not assume `messages[0]`'s signer is responsible for events produced anywhere else in the batch; instead correlate each `StateMachineUpdated` event to the specific consensus message (e.g., by `state_machine_id`/height range) that produced it, or refuse to reward batches containing more than one `Consensus` message of different signers, forcing a single validated correspondence.

### Proof of Concept
1. Legitimate relayer `R1` constructs and is about to submit a consensus message `M1` (signed by `R1`) proving state machine `S` has advanced from height `1000` to height `2000` (a large reward under the current `cost_per_block`).
2. Attacker `A` observes/derives `M1` (proofs are public/verifiable data) and constructs their own trivial consensus message `M0` (signed by `A`) for the same or a different eligible advance (any valid, cheap update they can produce, e.g. re-affirming a small already-known range, or even one that itself yields no additional height progress but is still a valid `Message::Consensus`).
3. `A` calls `pallet_ismp::handle_unsigned(RuntimeOrigin::none(), vec![M0, M1])`.
4. `Self::execute` processes both messages, producing (at least) the `StateMachineUpdated { state_machine_id: S, latest_height: 2000 }` event driven by `M1`.
5. `on_executed` reads `messages.get(0)` → `M0`, recovers `A` as the relayer; it also collects all `StateMachineUpdated` events in the batch (including the one from `M1`) into `highest_per_state_machine`, computing `reward = (2000 - baseline) * cost_per_block` and paying it entirely to `A` via `T::Currency::transfer` and minting reputation to `A`, per [5](#0-4) .
6. `R1`'s subsequent, honest submission of `M1` alone (if not already consumed/duplicated by ISMP's replay protection) yields no additional reward since the height watermark (`LastRewardedHeight`) has already advanced to `2000`, per [6](#0-5) .

Note: Exact feasibility depends on internals of `Self::execute` (in `modules/pallets/ismp/src/impls.rs`, not fully inspected due to tool-call exhaustion) — specifically whether messages are fully independent/idempotent when replayed and whether ISMP's duplicate-proof handling would allow `A` to include `M1`'s raw proof bytes verbatim in their own batch. This should be verified with a live/simulation test (e.g., extending `modules/pallets/testsuite/src/tests/pallet_consensus_incentives.rs::test_incentivize_relayer`) before remediation is scoped, since I was unable to confirm from the available context whether `execute()` enforces any additional signer-consistency checks across messages in a batch.

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}

	fn on_executed(
		messages: Vec<MessageWithWeight>,
		events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});
