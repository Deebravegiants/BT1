### Title
Whale-market accrual overflows before index cap and permanently freezes exits, repayments, and liquidations - ([File: common/src/rates/simulate.rs])

### Summary
A market can reach a state where every pool mutation first calls `interest::global_sync`, but `accrue_step` overflows while converting aggregate scaled debt to its current value. `update_borrow_index` caps the index only after multiplying it by the interest factor, so the configured `MAX_BORROW_INDEX_RAY` does not prevent the preceding market-value multiplication from exhausting `i128`. Once the stored `borrowed * borrow_index` value crosses the representable RAY domain, `repay`, `withdraw`, `liquidate`, `borrow`, and even permissionless `update_indexes` all revert with `MathOverflow`, permanently freezing the affected market and its funds. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) 

### Finding Description
Every pool market leg loads state through `synced_market`, which invokes `interest::global_sync` before processing the operation. [1](#0-0) 

`global_sync` chunks elapsed time and calls `accrue_step`; `accrue_step` computes `borrowed_original = scaled_to_original(borrowed, borrow_index)` before it computes the capped next borrow index. [5](#0-4) [2](#0-1) 

`scaled_to_original` delegates to checked RAY multiplication, while `update_borrow_index` performs `old_index.mul(interest_factor)` before applying `MAX_BORROW_INDEX_RAY`; neither operation clamps the aggregate debt value to a safe bound. [4](#0-3) [3](#0-2) 

The regression test demonstrates the concrete cliff: a 1-billion-token, 18-decimal market borrowing 98% of supply under a steep configured curve eventually causes `update_indexes`, `withdraw`, and `repay` to return `MATH_OVERFLOW`, with `borrow_index` still below `MAX_BORROW_INDEX_RAY`. [6](#0-5) 

The reachable trigger is permissionless controller `update_indexes(caller, assets)` for the affected `HubAssetKey`; the function only requires authorization from the supplied caller and forwards the assets to the pool accrual path. [7](#0-6) 

### Impact Explanation
This produces permanent freezing of all funds dependent on the market: suppliers cannot withdraw, borrowers cannot repay, liquidators cannot liquidate, and routine index maintenance cannot succeed because all of those paths accrue first. [1](#0-0) [8](#0-7) 

Unlike a fail-closed safety check on invalid input, the panic arises from internally accumulated market state after valid operations and valid time progression. [9](#0-8) [2](#0-1) 

The index ceiling does not recover the market because the debt-value conversion overflows before a capped index can be installed. [3](#0-2) [10](#0-9) 

### Likelihood Explanation
The attack needs a market near the supported asset-domain maximum and sustained high utilization long enough for interest to push `borrowed * borrow_index` over the `i128` RAY-value domain. [11](#0-10) 

The deployed test reaches that state with one billion 18-decimal tokens, 98% utilization, and the configured 175% maximum-rate XLM curve; the protocol's own numeric documentation also acknowledges that accrued market values can overflow before index ceilings and block repayment or withdrawal. [11](#0-10) [12](#0-11) 

Capital and market-cap requirements make this less likely than an ordinary input-validation flaw, but once the state exists, any unprivileged caller can trigger the permanent freeze through `update_indexes`, and no ordinary user transaction can bypass it. [7](#0-6) 

### Recommendation
Bound the aggregate RAY value before evaluating utilization and index growth, rather than relying on the post-multiplication index cap. [2](#0-1) [3](#0-2) 

At minimum, make `accrue_step` use checked `borrowed * borrow_index` and `supplied * supply_index` values and clamp the index before the next representable-value boundary, while allowing exits or repayments to operate on the last committed safe index. [4](#0-3) [1](#0-0) 

Additionally, enforce market caps below the RAY-value ceiling at supply and borrow admission, taking future configured index growth into account instead of relying only on token-unit caps. [12](#0-11) 

### Proof of Concept
1. Create an 18-decimal market with a steep but accepted interest-rate curve, supply `1_000_000_000 * 10^18` base units, and borrow 98% of that supply. [13](#0-12) 
2. Advance ledger time until `borrowed * borrow_index` approaches the `i128` RAY-value ceiling while `borrow_index` remains below `MAX_BORROW_INDEX_RAY`. [14](#0-13) 
3. Call `update_indexes` on that `HubAssetKey`; `global_sync` calls `accrue_step`, `scaled_to_original` overflows, and the call returns `MATH_OVERFLOW`. [7](#0-6) [15](#0-14) [2](#0-1) 
4. Subsequent `repay` and `withdraw` calls still execute the same accrual prelude and fail identically, leaving the market's supplied and borrowed funds inaccessible. [1](#0-0) [8](#0-7)

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```

```rust
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
