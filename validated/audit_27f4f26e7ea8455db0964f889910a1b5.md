### Title
Withdraw/borrow authorize against the stale stored `account.owner` instead of the live NFT owner — after a position transfer the previous owner retains spending authority ([File: contracts/controller/src/positions/supply.rs])

### Summary
The position NFT defines account ownership canonically via `owner_of` (the controller comments state "the token owner (`owner_of`) is the account owner"), and `storage::account_owner` resolves the live NFT holder. Owner-sensitive account guards split into two sources of truth: `require_account_owner` (used by `renew_account`, `add_delegate`, `remove_delegate`) checks `storage::account_owner` — the live NFT owner — while `require_owner_or_delegate` (used by `withdraw`, `borrow`, and every strategy/liquidation account guard) is always invoked with `&account.owner`, the `Address` stored in the `Account` struct at mint time in `create_account`. Nothing in `PositionNft::transfer`/`approve`/`transfer_from` (stock OZ `NonFungibleToken`/`Enumerable` implementation) calls back into the controller to rewrite `account.owner`, and `create_account` is the only place the field is assigned. This mirrors the ActiveMQ bug class: authorization is evaluated against the wrong identity context — the stale creation-time owner rather than the current NFT owner — so authentication of the caller "succeeds" for an address that no longer owns the account.

### Finding Description
`Account.owner` is set once at mint:

`contracts/controller/src/account.rs:64-70` — `create_account` builds `Account { owner: owner.clone(), .. }` where `owner` is the minter. It is never reassigned; `set_account_delegate`, liquidation, and position merges only mutate positions/delegates, and there is no NFT-transfer hook that resyncs the field.

The two auth shapes diverge:

- `require_account_owner` (account.rs:143-148) resolves `storage::account_owner` — the live NFT `owner_of` — and asserts `owner == *caller`.
- `require_owner_or_delegate` (account.rs:130-140) accepts `caller == owner` where `owner` is the caller-supplied stored field, or a stored delegate.

Every spending entrypoint binds to the stored field:

- `process_withdraw` — supply.rs:149-150: `require_owner_or_delegate(env, account_id, caller, &account.owner)`, then pays out to `to.unwrap_or(caller)` — an arbitrary external recipient (supply.rs:152-157).
- `process_borrow` — debt.rs:42-45: same guard, then `recipient = to.unwrap_or_else(|| caller.clone())` — borrows against the account's collateral to an arbitrary `to`.
- `swap_collateral`, `repay_debt_with_collateral`, `multiply`, `flash_position`, `swap_debt`, `migrate_from_blend` — all pin `&account.owner` via `require_owner_or_delegate` / the `Migrate`/`Multiply` `AccountGuard` (account.rs:101-110).
- `resolve_seize_receiver` — liquidation/mod.rs:179-180 — credits seized shares to an account whose stored owner is the liquidator.

Meanwhile `PositionNft`'s OZ `transfer`/`transfer_from` (contract.rs:131-170, `NonFungibleToken`/`NonFungibleEnumerable` impls) updates only NFT-side `Owner`/`Balance` entries; the controller is not notified. So after any NFT transfer or sale, `account.owner` permanently names the *previous* holder.

### Impact Explanation
An attacker — the seller, or anyone who held the NFT before transferring it — retains full delegate-level authority over the account because `caller == account.owner` still holds for them:

1. `controller.withdraw(account_id, withdrawals, to: Some(attacker))` drains all collateral above the solvency floor; with no debt the floor is empty, so the full balance is stolen.
2. `controller.borrow(account_id, borrows, to: Some(attacker))` draws maximum debt against the new owner's collateral and sends it to the attacker.

This is theft of user funds with quantifiable loss bounded only by the position size. Separately, the *new* (rightful) owner fails `require_owner_or_delegate` on every verb except `supply`/`repay`/`liquidate`-target, so they cannot withdraw or borrow their own position — a secondary permanent freezing of funds for anyone who acquires a leveraged/collateralized position on the secondary market. The one door left to them is the delegate path only if the old owner had listed them, which they cannot arrange (delegates are stored under the stored owner key: `get_delegates(env, account_id, owner)`).

### Likelihood Explanation
The path is fully permissionless and requires no privileged state: `position-nft.transfer`/`transfer_from` are standard OZ entrypoints reachable by any holder. The exploit needs only that an NFT-backed account changes hands — secondary sale, OTC deal, or even an accidental transfer — after which the prior holder calls `controller.withdraw`/`borrow` directly. No oracle manipulation, no timing, no flash loan is required; the stored `account.owner` never expires. Cost of exploit is a single transaction; the only caveat is whether a runtime resync exists — no code path in `contracts/controller/src` writes `account.owner` after `create_account`, and the NFT has no transfer hook into the controller.

### Recommendation
Use one canonical owner source. In `require_owner_or_delegate` call sites — or inside `storage::get_account`/`get_account_borrow_only` — resolve the owner via `storage::account_owner(account_id)` (the live NFT `owner_of`) rather than the stored `account.owner` field, or overwrite `account.owner` from the NFT on every load. Alternatively, keep the stored field but have `PositionNft` invoke a controller `sync_owner(token_id)` callback inside `transfer`/`transfer_from` before ownership changes. Tests should assert that after an NFT transfer, the *new* owner passes `withdraw`/`borrow` guards and the *old* owner fails them.

### Proof of Concept
```rust
// 1. Alice supplies collateral; her account NFT (token id = account_id) is minted.
let alice_id = client.supply(alice, 0, SPOKE_ID, &usdc(10_000));

// 2. Alice transfers (sells) the position NFT to Bob on the NFT contract.
nft.transfer(alice, bob, alice_id);          // owner_of(alice_id) == bob now
//    Controller-side account.owner still == alice (set once in create_account).

// 3. Alice — the previous owner — calls withdraw to herself:
//    process_withdraw: caller.require_auth() (alice signs), then
//    require_owner_or_delegate(.., caller=alice, owner=account.owner=alice) passes.
client.withdraw(alice, alice_id, &usdc(i128::MAX), &Some(attacker));
//    -> all of Bob's collateral is paid out to `attacker`.

// 4. Bob, the true NFT owner, cannot act:
client.try_withdraw(bob, alice_id, &usdc(1), &None)
//    -> NotAuthorized: bob != account.owner (alice) and is not her delegate.
```
