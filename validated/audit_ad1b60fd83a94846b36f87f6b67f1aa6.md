### Title
Fee monitors and feeDataAtom emissions keep running/emitting after wallet lock due to missing `onLock` in `createFeesLifecyclePlugin` - ([File: features/fee-data-monitors/plugin/index.js])

### Summary
`createFeesLifecyclePlugin` only wires `onLoad`, `onUnlock`, and `onStop`, with no `onLock` hook, unlike sibling lifecycle plugins in the same codebase (e.g. `nftsLifecyclePlugin`, `assetsFeaturePlugin`, `txLogMonitorsPlugin`, `hardwareWalletTrezorPlugin`) which explicitly stop their monitors/observers on `onLock`. As a result, once `feeMonitors.start()` has been triggered by `onUnlock`, locking the wallet does not stop `feeMonitors` nor unregister the `feeDataAtom` observer, so `feeDataAtom` updates continue to be emitted over `port` while the wallet is locked.

### Finding Description
`createFeesLifecyclePlugin` in `features/fee-data-monitors/plugin/index.js` returns only `{ onLoad, onUnlock, onStop }`: [1](#0-0) 

- `onLoad` calls `observer.start()`, which begins emitting the (public, unauthenticated-read) `feeDataAtom` value over `port` on every atom update.
- `onUnlock` calls `feeMonitors.start()`, which starts per-asset fee monitors (`FeeMonitors#start`) driven by `baseAssetNamesToMonitorAtom`/`remoteConfigAtom` and writes results into `feeDataAtom` via `updateFee`.
- The only place `feeMonitors.stop()` and `observer.unregister()` are called is `onStop`, i.e., full application shutdown — there is no `onLock` at all. [2](#0-1) 

`createAtomObserver` (the observer factory) only stops emitting once `unregister()` is called; `start()`-then-lock does not implicitly stop it: [3](#0-2) 

Comparable features in the same repo do define `onLock` to stop their monitors/observers on lock, which is the established convention for lock-state hygiene: [4](#0-3) [5](#0-4) [6](#0-5) 

Because `feeMonitors` in `features/fee-data-monitors/monitor/index.js` keeps its `#unobserveBaseAssetNames` and `#unobserveRemoteConfig` subscriptions alive and its per-asset monitor instances (`#monitors`) running, and because the `feeDataAtom` observer stays registered/emitting, the plugin as written continues writing to and emitting `feeDataAtom` after a lock event with no code path to stop it short of full `onStop` (app teardown).

### Impact Explanation
`feeDataAtom` is `public: true` with no read authentication, and the observer relays its value to any listener on `port` (the same emitter also used for other lock-gated features such as `applicationLifecyclePlugin`'s `locked` event). The set of assets being fee-monitored is derived from `baseAssetNamesToMonitorAtom`/`availableAssetNamesAtom`, which reflect the wallet's active/enabled asset set tied to the unlocked account. Continuing to emit updates while locked leaks a proxy for "which assets are enabled/available" to any consumer subscribed to the port after lock, violating the invariant that locking should stop wallet-state activity/derived-info flow. This is a locked-state information-disclosure issue scoped to metadata (asset set), not funds or keys.

### Likelihood Explanation
Highly feasible and deterministic given the code as written: any environment where the SDK process/port stays alive across lock (browser-extension/background-process model) will exhibit this behavior automatically once `onUnlock` has run at least once, since nothing subsequently calls `feeMonitors.stop()`/`observer.unregister()` until `onStop`. No attacker interaction beyond normal lock usage is required; the gap is a straightforward missing hook, consistent with the pattern already fixed in sibling plugins.

### Recommendation
Add an `onLock` hook to `createFeesLifecyclePlugin` that stops `feeMonitors` and unregisters/stops the `feeDataAtom` observer (mirroring `nftsLifecyclePlugin`'s `onLock` and `assetsFeaturePlugin`'s `onLock`), and re-start both in `onUnlock` as currently done. Ensure `FeeMonitors#stop()` is awaited/robust to be called multiple times (start/stop/start cycles) since it will now be invoked on every lock/unlock cycle rather than only at app shutdown.

### Proof of Concept
Integration test in `features/fee-data-monitors/plugin/__tests__/index.test.js` (or equivalent):
1. Instantiate the plugin with mock `port`, `feeMonitors` (spy `start`/`stop`), and `feeDataAtom`.
2. Call `plugin.onLoad()` then `plugin.onUnlock()`; assert `feeMonitors.start` was called and `port.emit('feeData', ...)` fires on `feeDataAtom.set(...)`.
3. Simulate a lock event (call `plugin.onLock?.()` if present, or otherwise assert the application's lock lifecycle hook was invoked) and then mutate `feeDataAtom` again (e.g., via a spy on `FeeMonitors#updateFee` or directly setting the atom).
4. Assert that after the simulated lock: `feeMonitors.stop` was called and no further `port.emit('feeData', ...)` occurs for subsequent `feeDataAtom` mutations — currently this assertion fails because `onLock` does not exist and `feeMonitors`/observer remain active.

```javascript
const createFeesLifecyclePlugin = ({ port, feeMonitors, feeDataAtom }) => {
  const observer = createAtomObserver({ port, atom: feeDataAtom, event: 'feeData' })

  const onLoad = () => {
    observer.start()
  }

  const onUnlock = () => {
    feeMonitors.start()
  }

  const onStop = () => {
    feeMonitors.stop()
    observer.unregister()
  }

  return { onLoad, onUnlock, onStop }
}
```

```typescript
const createAtomObserver = <T>({ port, atom, event, immediateRegister = true }: Params<T>) => {
  let emitting = false
  let unobserve: Unsubscribe | undefined
  let lastMessage = -1

  const register = () => {
    if (unobserve) return

    unobserve = atom.observe((value) => {
      if (emitting) {
        port.emit(event, value)
        lastMessage = Date.now()
      }
    })
  }

  const unregister = () => {
    unobserve?.()
    unobserve = undefined
    emitting = false
  }

  const emitWhenReady = async () => {
    emitting = true
    const startTime = Date.now()
    const value = await atom.get()
    if (startTime > lastMessage) port.emit(event, value)
  }

  const start = () => {
    // Awaiting the atom.get() promise might delay the lifecycle hooks, so we don't do that.
    void emitWhenReady()
  }

  if (immediateRegister) {
    register()
  }

  return {
    register,
    unregister,
    start,
  }
```
