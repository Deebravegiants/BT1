### Title
Permanently-failing XCM messages (`Outcome::Incomplete` → `Ok(false)`) can jam a `pallet-message-queue` origin queue forever at near-zero cost, with no reap or overweight recovery path - (File: `polkadot/xcm/xcm-builder/src/process_xcm_message.rs`)

### Summary
`ProcessXcmMessage::process_message` maps `Outcome::Incomplete` to `Ok(false)` regardless of how little weight was `used` [1](#0-0) . The pre-flight overweight check is performed against the *worst-case prepared weight* (`XcmExecutor::prepare(..., Weight::MAX)`), not the actual `used` weight of a failing execution [2](#0-1) , so a message that is cheap to prepare but deterministically fails early during execution (e.g. a false `ExpectAsset`/`ExpectOrigin` check) will never be classified `Overweight` and will never emit `OverweightEnqueued`. Because `do_reap_page_inner` only allows reaping pages whose index is strictly less than `book_state.begin` (or when `cullable()` triggers on stale/overweight pages) [3](#0-2) , a page that is never advanced past (because its head message keeps returning `Ok(false)`) is neither reapable nor overweight-markable, leaving no privileged or automated recovery path.

### Finding Description
`ProcessXcmMessage::process_message` decodes and prepares the XCM, checks only that the *prepared/worst-case* weight fits (`required = pre.weight_of()`, checked with `meter.can_consume(required)`) [4](#0-3) , then executes. If execution returns `Outcome::Incomplete { used, .. }` (e.g., because an early instruction like `ExpectAsset` fails a condition the attacker controls to always be false), the function returns `Ok(false)` and only consumes the (small) `used` weight [1](#0-0) . This is functionally different from the `Outcome::Error` branch, which is treated as a genuine failure and consumes the full `required` weight, returning `Err(...)` [5](#0-4) .

In `pallet-message-queue`, `service_queues_impl` calls `bump_service_head` and then loops `service_queue` over the ready ring every block/service call, each incurring `T::WeightInfo::bump_service_head()` and `T::WeightInfo::service_queue_base() + ready_ring_unknit()` overhead regardless of whether the head message makes progress [6](#0-5) [7](#0-6) . A message that always returns `Ok(false)` is never marked `is_processed`, so `book_state.begin` cannot advance past the page containing it, and the page therefore never satisfies `page_index < book_state.begin`, which `do_reap_page_inner` requires before even checking `reapable`/`cullable` [3](#0-2) . It also never triggers `OverweightEnqueued`, since the classification of "overweight" is based on the worst-case `required` weight computed by `prepare`, not on the actual repeated `Incomplete` failures at runtime. Consequently there is no automated or privileged (`execute_overweight`/`reap_page`) path to clear this message once stuck; the pallet doc's own description of "permanently over-weight" recovery via `execute_overweight`/`OverweightEnqueued` does not apply here because the message was never classified overweight [8](#0-7) .

### Impact Explanation
The queue key for inbound XCM (UMP/DMP/HRMP) is the sending origin (e.g. a `ParaId`), not a per-account key, so a single unprivileged actor able to originate an XCM message from a given origin (e.g. via `pallet-xcm::send`, or a parachain's own outbound queue being processed on the relay chain/another parachain) can wedge that origin's message queue behind a permanently-`Incomplete` message. This blocks head-of-line progress for all subsequent messages from the same origin in that page, at a bounded but perpetual weight cost (`bump_service_head` + `service_queue_base` + the message's own small `used`/attempt cost) every servicing round, with no automatic or governance-driven reap/overweight recovery available through the normal `ServiceQueues`/`execute_overweight`/`reap_page` APIs.

### Likelihood Explanation
Feasible for any unprivileged user who can craft/send an XCM whose worst-case prepared weight is small (passes the `Overweight` check) but whose actual execution deterministically fails at a cheap, early instruction (`ExpectAsset`, `ExpectOrigin`, etc.) on every retry, e.g. asserting possession of an asset/origin that will never exist. This requires only standard, permissionless XCM-send capability; no privileged origin, proxy bypass, or storage manipulation is needed. The condition is fully deterministic and repeatable across arbitrarily many blocks.

### Recommendation
Distinguish "genuinely retryable" outcomes from "permanently failing" ones in `ProcessXcmMessage::process_message`: for `Outcome::Incomplete`, inspect the specific `error` (e.g. treat clearly-unsatisfiable/logic failures like `ExpectationFalse` differently from transient/backpressure conditions) and map deterministic failures to a terminal `Err(ProcessMessageError::Unsupported)` (consuming full weight and allowing the page to advance/be reaped) rather than `Ok(false)`. Alternatively, extend `pallet-message-queue` to track a retry counter per stuck head-of-page message and force it into the overweight/reapable path after N unsuccessful `Ok(false)` attempts, closing the gap where `do_reap_page_inner`'s `page_index < book_state.begin` precondition can never be satisfied for a stalled page.

### Proof of Concept
Integration/simulation test plan (using `substrate/frame/message-queue` test harness plus `ProcessXcmMessage`):
1. Construct an XCM whose worst-case `prepare` weight is small but which contains an early `ExpectAsset`/`ExpectOrigin` check guaranteed to fail (e.g. expecting an asset that is never in the holding register).
2. Enqueue this message into a test origin queue and call `MessageQueue::service_queues` for M blocks (e.g. M = 10,000).
3. Assert: (a) the message is never `Processed` (no `Event::Processed` with success), (b) no `Event::OverweightEnqueued` is ever emitted, (c) `do_reap_page(&origin, page_index)` returns `Err(Error::NotReapable)` on every attempt because `page_index >= book_state.begin`, and (d) cumulative cost equals `M * (bump_service_head + service_queue_base + ready_ring_unknit + used)`, growing unboundedly over blocks with no terminal state — demonstrating the message is never completed, never reapable, and never bounded in retry count, violating the stated invariant.

	fn do_reap_page_inner(origin: &MessageOriginOf<T>, page_index: PageIndex) -> DispatchResult {
		let mut book_state = BookStateFor::<T>::get(origin);
		// definitely not reapable if the page's index is no less than the `begin`ning of ready
		// pages.
		ensure!(page_index < book_state.begin, Error::<T>::NotReapable);

		let page = Pages::<T>::get(origin, page_index).ok_or(Error::<T>::NoPage)?;

		// definitely reapable if the page has no messages in it.
		let reapable = page.remaining.is_zero();

		// also reapable if the page index has dropped below our watermark.
		let cullable = || {
			let total_pages = book_state.count;
			let ready_pages = book_state.end.saturating_sub(book_state.begin).min(total_pages);

			// The number of stale pages - i.e. pages which contain unprocessed overweight messages.
			// We would prefer to keep these around but will restrict how far into history they can
			// extend if we notice that there's too many of them.
			//
			// We don't know *where* in history these pages are so we use a dynamic formula which
			// reduces the historical time horizon as the stale pages pile up and increases it as
			// they reduce.
			let stale_pages = total_pages - ready_pages;

			// The maximum number of stale pages (i.e. of overweight messages) allowed before
			// culling can happen at all. Once there are more stale pages than this, then historical
			// pages may be dropped, even if they contain unprocessed overweight messages.
			let max_stale = T::MaxStale::get();

			// The amount beyond the maximum which are being used. If it's not beyond the maximum
			// then we exit now since no culling is needed.
			let overflow = match stale_pages.checked_sub(max_stale + 1) {
				Some(x) => x + 1,
				None => return false,
			};

			// The special formula which tells us how deep into index-history we will pages. As
			// the overflow is greater (and thus the need to drop items from storage is more urgent)
			// this is reduced, allowing a greater range of pages to be culled.
			// With a minimum `overflow` (`1`), this returns `max_stale ** 2`, indicating we only
			// cull beyond that number of indices deep into history.
			// At this overflow increases, our depth reduces down to a limit of `max_stale`. We
			// never want to reduce below this since this will certainly allow enough pages to be
			// culled in order to bring `overflow` back to zero.
			let backlog = (max_stale * max_stale / overflow).max(max_stale);

			let watermark = book_state.begin.saturating_sub(backlog);
			page_index < watermark
		};
		ensure!(reapable || cullable(), Error::<T>::NotReapable);

	fn service_queue(
		origin: MessageOriginOf<T>,
		weight: &mut WeightMeter,
		overweight_limit: Weight,
	) -> (bool, Option<MessageOriginOf<T>>) {
		use PageExecutionStatus::*;
		if weight
			.try_consume(
				T::WeightInfo::service_queue_base()
					.saturating_add(T::WeightInfo::ready_ring_unknit()),
			)
			.is_err()
		{
			return (false, None);
		}

		let mut book_state = BookStateFor::<T>::get(&origin);
		let mut total_processed = 0;
		if T::QueuePausedQuery::is_paused(&origin) {
			let next_ready = book_state.ready_neighbours.as_ref().map(|x| x.next.clone());
			return (false, next_ready);
		}

		while book_state.end > book_state.begin {
			let (processed, status) =
				Self::service_page(&origin, &mut book_state, weight, overweight_limit);
			total_processed.saturating_accrue(processed);
			match status {
				// Store the page progress and do not go to the next one.
				Bailed | NoProgress => break,
				// Go to the next page if this one is at the end.
				NoMore => (),
			};
			book_state.begin.saturating_inc();
		}
