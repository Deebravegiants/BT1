### Title
Uncaught tainted-canvas SecurityError in `getIconData` permanently hangs `content.js` RPC bridge metadata promise - ([File: libraries/browser-extension-rpc/src/metadata.js])

### Summary
`getIconData` registers an `img.addEventListener('load', ...)` callback that calls `ctx.getImageData(...)` with no try/catch, unlike the sibling `getIconSize` function which already uses a try/catch pattern for similar untrusted-DOM parsing. If the resolved icon `href` is cross-origin and the response lacks CORS headers, the canvas becomes tainted and `getImageData` throws a `SecurityError` inside the `load` listener; because this throw happens asynchronously inside an event callback (not inside the `Promise` executor itself), it is not caught by the `new Promise(...)` construct and neither `resolve` nor `reject` is ever called.

### Finding Description
`getIcon()` in `libraries/browser-extension-rpc/src/metadata.js` selects an icon `<link>` from the DOM of the connecting page (`document.querySelectorAll('head > link[rel~="icon"]')`) or falls back to `favicon.ico`, both of which are fully attacker/page-controlled since any dapp origin loading this content script controls its own `<head>`. [1](#0-0)  `getIconData(href)` sets `img.crossOrigin = 'anonymous'` and, on `load`, draws the image to a canvas and calls `ctx.getImageData(0, 0, width, height)` with no error handling; only `img.onerror` is guarded via `resolve(null)`. [2](#0-1)  When the icon URL points to a cross-origin resource that responds without `Access-Control-Allow-Origin`, the browser still fires `load` (the image renders) but taints the canvas, so `ctx.getImageData` throws a `SecurityError`. That throw occurs inside the `addEventListener('load', ...)` callback, which is invoked asynchronously by the browser event loop — it is not inside the synchronous body of the `Promise` executor, so it does not trigger the executor's implicit try/catch-to-reject behavior. The exception simply propagates to the global error handler (logged/uncaught) and the constructed `Promise` returned by `getIconData` is left forever pending.

This pending promise is directly awaited in `content.js`: `const metadata = new Promise((resolve) => { window.addEventListener('load', async () => { ...; const icon = await getIcon(); resolve({ title, icon }) }) })`. [3](#0-2)  Since `getIcon()` never settles, the outer `metadata` promise never resolves. Every subsequent inbound RPC message handled by `transport.on('data', ...)` does `const senderMetadata = await metadata` before calling `channel.call(event, options)` or `channel.sendMessage(event, options)`, so all RPC traffic (connect/sign requests) is blocked indefinitely on this page once triggered. [4](#0-3)  The `getIconSize` function elsewhere in the same file already wraps its untrusted-data parsing in try/catch, showing the intended defensive pattern that `getIconData`'s `load` handler is missing. [5](#0-4) 

### Impact Explanation
This is a denial-of-service on the wallet's RPC bridge for the affected tab/origin: once the tainted-canvas exception fires, `content.js`'s `metadata` promise never resolves, so no RPC message (connect, sign request, etc.) originating from that page can ever be forwarded to the background/channel layer, since every dispatch path awaits `metadata` first. This does not itself cause key leakage, unauthorized signing, or origin-binding bypass — the RPC call is blocked, not misrouted — so the impact is scoped to availability/DoS of the wallet-connect flow for that page, not a signing/auth bypass.

### Likelihood Explanation
Highly feasible: an attacker only needs to control a normal, unprivileged web page and set an icon `<link rel="icon" href="https://cross-origin-host/no-cors-icon.png">` pointing at any cross-origin resource that doesn't send CORS headers (extremely common for arbitrary image URLs). No special privileges, social engineering, or wallet state are required — this is triggered automatically on page load via `window.addEventListener('load', ...)` in `content.js`, with no user interaction needed beyond visiting the page.

### Recommendation
Wrap the `load` handler body in `getIconData` in a try/catch (mirroring `getIconSize`), and call `resolve(null)` on any drawing/`getImageData` failure so metadata resolution degrades gracefully instead of hanging, e.g.:
```js
img.addEventListener('load', () => {
  try {
    // existing canvas/getImageData logic
    resolve({ width, height, data: base64(data) })
  } catch {
    resolve(null)
  }
})
```

### Proof of Concept
Unit test using a jsdom/mock `Image` that synchronously fires `load` and whose associated mocked `CanvasRenderingContext2D.getImageData` throws a `SecurityError` (simulating a tainted canvas from a non-CORS cross-origin icon):
1. Mock `document.createElement('canvas').getContext('2d')` to return a context whose `getImageData` throws `new DOMException('tainted canvas', 'SecurityError')`.
2. Mock global `Image` so that setting `.src` triggers the `load` listener asynchronously (via `queueMicrotask`), with `width`/`height` set.
3. Call `getIconData('https://cross-origin.example/icon.png')` and assert the returned promise settles (`resolves.toEqual(null)` or similar) within a timeout, instead of remaining pending forever (e.g., using `Promise.race` with a timeout that currently would win, proving the hang).
4. Currently expected failing behavior: the promise stays pending and the test times out / the uncaught `SecurityError` surfaces, demonstrating the unresolved-promise defect described.

const getIconData = (href) => {
  const img = new Image()

  img.crossOrigin = 'anonymous'
  img.src = href

  return new Promise((resolve) => {
    img.addEventListener('load', () => {
      const canvas = document.createElement('canvas')
      const ctx = canvas.getContext('2d')
      const dimensions = getIconDimensions(img, ICON_MAX_SIZE)

      const width = dimensions.width
      const height = dimensions.height

      canvas.width = width
      canvas.height = height

      ctx.drawImage(img, dimensions.dx, dimensions.dy, dimensions.dWidth, dimensions.dHeight)

      const { data } = ctx.getImageData(0, 0, width, height)

      resolve({ width, height, data: base64(data) })
    })

    // If can't compute, enable connecting dapp without icon. UI will render empty state

  })
