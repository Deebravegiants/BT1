Audit Report

## Title
Outgoing authentication token for External Initiators disclosed unredacted to view-only users - (File: core/web/presenters/external_initiators.go)

## Summary
The `GET /v2/external_initiators` endpoint, reachable by users holding only the `view` role, returns the `OutgoingToken` field in plaintext for every configured external initiator via `presenters.NewExternalInitiatorResource`. This token is a credential the Chainlink node uses to authenticate its callbacks to the external initiator service, so its disclosure to a read-only role violates the intended privilege separation between viewing job/run data and possessing operational secrets.

## Finding Description
`ExternalInitiator` persists `OutgoingToken` and `OutgoingSecret` in plaintext (unlike `HashedSecret`, which is hashed) because the node must resend them verbatim on outbound callbacks [4](#0-3) . The `Index` handler for `GET /v2/external_initiators` fetches all initiators and maps each into an `ExternalInitiatorResource` via `presenters.NewExternalInitiatorResource` [2](#0-1) . That constructor copies `ei.OutgoingToken` directly into the JSON-serialized `OutgoingToken` field [3](#0-2) , while deliberately excluding `OutgoingSecret`, showing the authors were aware some fields needed protection but missed `OutgoingToken`. The RBAC test table explicitly marks this route `viewOnlyAllowed: true`, confirming the route's authorization middleware permits the lowest-privileged authenticated role to reach it [5](#0-4) . No redaction, masking, or role elevation is applied anywhere along this path, unlike the `models.Secret`/`SecretURL` types elsewhere in the codebase, which format as `"xxxxx"`.

## Impact Explanation
A user with only the `view` role (including view-scoped API tokens or read-only LDAP/OIDC group members) can call `GET /v2/external_initiators` and obtain the plaintext `OutgoingToken` for every configured external initiator. This is a genuine secret-exfiltration issue: an authenticated but minimally privileged actor gains access to a credential intended to be known only by `edit`/`admin`-level operators, which is outside the scope of what a `view` role should expose. This maps to the in-scope "key/secret exfiltration" impact category, though the practical severity of using the leaked token to impersonate the node depends on how the receiving external-initiator server validates the callback (the paired `OutgoingSecret` is correctly withheld).

## Likelihood Explanation
Likelihood is realistic but bounded: it requires (1) the External Initiator feature to be enabled and configured with existing initiators, and (2) an attacker to already hold valid `view`-role credentials on the node (a low but non-zero privilege bar, as `view` is the entry-level authenticated role, easily provisioned to auditors/read-only accounts, or obtainable via LDAP `NodeReadOnly` group membership). Given valid `view` credentials, the exploit is trivially and repeatably reproducible with a single unauthenticated-role-bypass-free HTTP GET request.

## Recommendation
Remove `OutgoingToken` from `ExternalInitiatorResource`/`NewExternalInitiatorResource`, consistent with the existing omission of `OutgoingSecret`. If operators need visibility into the configured token, only expose it once at creation time via the already `edit`-gated `ExternalInitiatorAuthentication` response, or raise the required role for `GET /v2/external_initiators` to `edit`/`admin`.

## Proof of Concept
1. Enable the External Initiator feature (`JobPipeline.ExternalInitiatorsEnabled`) and create an initiator as an `admin`/`edit` user via `POST /v2/external_initiators`.
2. Create or use an existing user/API token with only the `view` role.
3. As the `view` user, send `GET /v2/external_initiators`.
4. Observe the JSON:API response includes `outgoingToken` in plaintext for each initiator, confirmed reachable per the RBAC test entry `{"GET", "/v2/external_initiators", true, true, true}` in `core/web/auth/auth_test.go`.

func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}
