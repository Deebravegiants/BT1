### Title
Unbounded scaled-value multiplication can permanently freeze a whale market - (File: common/src/rates/simulate.rs)

### Summary
`accrue_step` multiplies aggregate scaled debt and supply shares by their indexes before either utilization or the bounded index update is calculated. [1](#0-0)  When `borrowed * borrow_index` or `supplied * supply_index` exceeds `i128::MAX`, `scaled_to_original` panics through `Ray::mul`. [2](#0-1) [3](#0-2)  A sufficiently large, highly utilized market can therefore reach a debt-value overflow before the borrow index reaches its `10^36` cap. [4](#0-3) 

### Finding Description
The controller exposes `supply`, `borrow`, and permissionless `update_indexes`, where `account_id = 0` creates a new account and `update_indexes` only requires caller authorization. [5](#0-4) [6](#0-5)  An unprivileged user can create a liquidity account, create a collateral account, borrow most of the supplied asset, and later invoke `update_indexes` for that hub asset. [5](#0-4) [7](#0-6) 

Every ordinary pool leg calls `ops::load_leg`, which calls `synced_market`, and `synced_market` runs `interest::global_sync` before the requested operation is processed. [8](#0-7)  `global_sync` invokes `accrue_step`, whose first operation computes `borrowed_original = scaled_to_original(borrowed, borrow_index)`. [9](#0-8) [10](#0-9)  `scaled_to_original` calls `Ray::mul`, which computes `borrowed * borrow_index / RAY` and panics with `MathOverflow` when the mathematical result cannot fit in `i128`. [2](#0-1) [3](#0-2) 

The repository’s stress test demonstrates this exact cliff: one billion 18-decimal tokens at 98% utilization eventually causes `update_indexes` to return `MATH_OVERFLOW`, after which withdrawal and repayment hit the same error because they accrue first. [11](#0-10) 

### Impact Explanation
Once aggregate debt or supply value crosses the `i128` domain, every pool operation for that market reverts during pre-operation accrual. [8](#0-7)  Depositors cannot withdraw, borrowers cannot repay, liquidations cannot execute through seizure accrual, and the market becomes unable to perform its core operations. [12](#0-11) [13](#0-12) [14](#0-13)  This is permanent freezing of funds in the affected market absent a code-level migration or upgrade. [15](#0-14) 

### Likelihood Explanation
The attack requires a very large listed market, sufficient collateral to borrow approximately 98% of it, and enough elapsed time for the borrow index to multiply scaled debt beyond `i128::MAX`. [16](#0-15)  The required caps, utilization configuration, asset decimals, and rate parameters are nevertheless within accepted protocol bounds, and the checked-in test reaches the failure within the modeled horizon. [17](#0-16) [18](#0-17)  The capital and duration requirements make this a Medium-severity availability issue rather than an immediate exploit. [4](#0-3) 

### Recommendation
Accrual must not evaluate representability of aggregate value using a panicking `i128` product before applying index bounds. [19](#0-18)  Use widened arithmetic for utilization and accrued-interest calculations, dynamically cap scaled debt or supply so their indexed values remain representable, or clamp indexes against a market-size-dependent bound such as `i128::MAX / scaled_shares` rather than only against the static `10^36` index cap. [20](#0-19) [21](#0-20)  Any fix must also handle `calculate_supplier_rewards`, because it independently multiplies `borrowed` by both old and new borrow indexes. [21](#0-20)

        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

        years += 1;
        assert!(
            years <= 40,

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
