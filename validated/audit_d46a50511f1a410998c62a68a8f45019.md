Audit Report

## Title
Permissionless frequent `stake`/`unstake` calls truncate `reward_per_token` to zero via low-precision integer division - (File: `substrate/frame/asset-rewards/src/lib.rs`)

## Summary
`pallet-asset-rewards` recomputes `reward_per_token_stored` on every call to the permissionless `stake` and `unstake` extrinsics via `update_pool_and_staker_rewards` → `reward_per_token`, using a fixed-point scaling factor `PRECISION_SCALING_FACTOR` of only `4096` and truncating integer division (`ensure_div`). Because any signed account can call `stake`/`unstake` every block, forcing `rewardable_blocks_elapsed == 1` on each update, the per-call numerator `reward_rate_per_block * 1 * 4096` can be smaller than `total_tokens_staked`, causing the reward increment to truncate to `0` every block and permanently denying rewards to legitimate stakers, with no remainder/dust-carry mechanism to recover the loss.

## Finding Description
`reward_per_token` computes `reward_per_token_stored + reward_rate_per_block * rewardable_blocks_elapsed * PRECISION_SCALING_FACTOR / total_tokens_staked` using `ensure_mul`/`ensure_div`, confirmed at [1](#0-0) . `PRECISION_SCALING_FACTOR` is defined as a small `u16` constant of `4096`, far lower precision than fixed-point bases such as `10^18` used elsewhere in the runtime, confirmed at [2](#0-1) .

Both `stake` and `unstake` are permissionless (gated only by `ensure_signed`) and unconditionally invoke `update_pool_and_staker_rewards` before mutating balances, confirmed at [3](#0-2)  and [4](#0-3) , which in turn calls `reward_per_token`/`update_pool_rewards`, confirmed at [5](#0-4) . When an attacker calls `stake`/`unstake` every block, `rewardable_blocks_elapsed` is always `1`, so if `reward_rate_per_block * 4096 < total_tokens_staked`, the division truncates to `0` on every single update and `reward_per_token_stored` never advances. `derive_rewards` only adds deltas of `reward_per_token_stored` to a staker's `rewards` with no fractional remainder carried forward, confirmed at [6](#0-5) , so the truncated portion is not recoverable elsewhere. This differs materially from the un-attacked case, where updates occur less frequently, `rewardable_blocks_elapsed` accumulates to larger values between calls, and the numerator is correspondingly larger and less likely to truncate to zero — meaning the attack, not ordinary usage, is what forces the precision loss to become total and permanent.

Existing guards (`ensure_mul`/`ensure_div`/`ensure_add` from `EnsureMul`/`EnsureDiv`/`EnsureAdd`) only protect against overflow/panics; they do not address rounding loss, and there is no minimum-elapsed-blocks throttle or dust-accumulation buffer to prevent an attacker from repeatedly forcing single-block updates.

## Impact Explanation
All stakers in an affected pool (where `reward_rate_per_block * 4096` is small relative to `total_tokens_staked`, plausible for pools with low reward rates or high-decimal staked assets) permanently lose accrued rewards for every block the attack is sustained. The undistributed reward tokens remain stuck in the pool's dedicated account and are only recoverable by the pool admin via `cleanup_pool`, which additionally requires zero stakers, confirmed at [7](#0-6)  — so legitimate stakers cannot self-recover the lost rewards while staked. This is a concrete, unprivileged-user-triggerable fund-loss/denial-of-reward issue in an in-scope FRAME pallet.

## Likelihood Explanation
Any signed account can call `stake`/`unstake` with no minimum-amount restriction and no throttling beyond ordinary transaction fees, making the attack fully permissionless, cheap, and repeatable on every block. Because `PRECISION_SCALING_FACTOR` (4096) is drastically smaller than fixed-point bases like `10^18` used elsewhere (e.g., `FixedU128`-based reward counters in `pallet-nomination-pools`), the truncation threshold is reached far more easily here, making pools with realistic parameter choices (typical reward rates vs. staked-asset decimals) susceptible without requiring unusual assumptions.

## Recommendation
Increase `PRECISION_SCALING_FACTOR` to a much larger fixed-point base (e.g., a `10^18`-scale `FixedU128`-style representation, consistent with `pallet-nomination-pools`'s `current_reward_counter`) so per-block increments do not truncate to zero under realistic `reward_rate_per_block`/`total_tokens_staked` ratios. Additionally, track and carry forward fractional remainder ("dust") across updates in `reward_per_token` so that no reward accrual is permanently lost regardless of how frequently `stake`/`unstake` are called.

## Proof of Concept
1. Admin creates a pool via `create_pool` with a `reward_rate_per_block` and staked-asset decimals such that `reward_rate_per_block * 4096 < total_tokens_staked` once sufficient tokens are staked.
2. A legitimate staker calls `stake` with a large amount, raising `total_tokens_staked` to satisfy the inequality above.
3. An attacker (any signed account, potentially already holding a minimal stake) calls `stake`/`unstake` with a trivial amount every block.
4. Each call triggers `update_pool_and_staker_rewards` → `reward_per_token` with `rewardable_blocks_elapsed == 1`, so `reward_rate_per_block * 1 * 4096 / total_tokens_staked` evaluates to `0` via `ensure_div` truncation.
5. Observe that `reward_per_token_stored` never advances across many blocks of this attack, while `pool_info.last_update_block` keeps advancing — i.e., legitimate stakers accrue `0` net rewards for the duration of the attack despite reward emission being "consumed" block-by-block. This can be encoded as a unit test in `substrate/frame/asset-rewards/src/tests.rs` asserting `PoolStakers::<T>::get(pool_id, staker).rewards` remains `0` (or far below the undisturbed-update baseline) after N blocks of attacker-forced per-block `stake(0)`/`unstake(0)` calls, compared against a baseline scenario where no attacker updates occur and rewards accrue in one larger-elapsed-block calculation.

		pub fn stake(origin: OriginFor<T>, pool_id: PoolId, amount: T::Balance) -> DispatchResult {
			let staker = ensure_signed(origin)?;

			// Always start by updating staker and pool rewards.
			let pool_info = Pools::<T>::get(pool_id).ok_or(Error::<T>::NonExistentPool)?;
			let staker_info = PoolStakers::<T>::get(pool_id, &staker).unwrap_or_default();
			let (mut pool_info, mut staker_info) =
				Self::update_pool_and_staker_rewards(&pool_info, &staker_info)?;

			T::AssetsFreezer::increase_frozen(
				pool_info.staked_asset_id.clone(),
				&FreezeReason::Staked.into(),
				&staker,
				amount,
			)?;

			// Update Pools.
			pool_info.total_tokens_staked.ensure_add_assign(amount)?;

			Pools::<T>::insert(pool_id, pool_info);

			// Update PoolStakers.
			staker_info.amount.ensure_add_assign(amount)?;
			PoolStakers::<T>::insert(pool_id, &staker, staker_info);

			// Emit event.
			Self::deposit_event(Event::Staked { staker, pool_id, amount });

			Ok(())
		}

		pub fn unstake(
			origin: OriginFor<T>,
			pool_id: PoolId,
			amount: T::Balance,
			staker: Option<T::AccountId>,
		) -> DispatchResult {
			let caller = ensure_signed(origin)?;
			let staker = staker.unwrap_or(caller.clone());

			// Always start by updating the pool rewards.
			let pool_info = Pools::<T>::get(pool_id).ok_or(Error::<T>::NonExistentPool)?;
			let now = T::BlockNumberProvider::current_block_number();
			ensure!(now > pool_info.expiry_block || caller == staker, BadOrigin);

			let staker_info = PoolStakers::<T>::get(pool_id, &staker).unwrap_or_default();
			let (mut pool_info, mut staker_info) =
				Self::update_pool_and_staker_rewards(&pool_info, &staker_info)?;

			// Check the staker has enough staked tokens.
			ensure!(staker_info.amount >= amount, Error::<T>::NotEnoughTokens);

			// Unfreeze staker assets.
			T::AssetsFreezer::decrease_frozen(
				pool_info.staked_asset_id.clone(),
				&FreezeReason::Staked.into(),
				&staker,
				amount,
			)?;

			// Update Pools.
			pool_info.total_tokens_staked.ensure_sub_assign(amount)?;
			Pools::<T>::insert(pool_id, pool_info);

			// Update PoolStakers.
			staker_info.amount.ensure_sub_assign(amount)?;

			if staker_info.amount.is_zero() && staker_info.rewards.is_zero() {
				PoolStakers::<T>::remove(&pool_id, &staker);
			} else {
				PoolStakers::<T>::insert(&pool_id, &staker, staker_info);
			}

			// Emit event.
			Self::deposit_event(Event::Unstaked { caller, staker, pool_id, amount });

			Ok(())
		}

		#[pallet::call_index(8)]
		pub fn cleanup_pool(origin: OriginFor<T>, pool_id: PoolId) -> DispatchResult {
			let who = ensure_signed(origin)?;

			let pool_info = Pools::<T>::get(pool_id).ok_or(Error::<T>::NonExistentPool)?;
			ensure!(pool_info.admin == who, BadOrigin);

			let stakers = PoolStakers::<T>::iter_key_prefix(pool_id).next();
			ensure!(stakers.is_none(), Error::<T>::NonEmptyPool);

			let pool_balance = T::Assets::reducible_balance(
				pool_info.reward_asset_id.clone(),
				&pool_info.account,
				Preservation::Expendable,
				Fortitude::Polite,
			);
			T::Assets::transfer(
				pool_info.reward_asset_id,
				&pool_info.account,
				&pool_info.admin,
				pool_balance,
				Preservation::Expendable,
			)?;

			if let Some((who, cost)) = PoolCost::<T>::take(pool_id) {
				T::Consideration::drop(cost, &who)?;
			}

			Pools::<T>::remove(pool_id);

			Self::deposit_event(Event::PoolCleanedUp { pool_id });

			Ok(())
		}

			pool_info: &PoolInfoFor<T>,

			new_staker_info.reward_per_token_paid = pool_info.reward_per_token_stored;
			return Ok((pool_info, new_staker_info));

		/// Derives the current reward per token for this pool.
		pub(super) fn reward_per_token(
			pool_info: &PoolInfoFor<T>,
		) -> Result<T::Balance, DispatchError> {
			if pool_info.total_tokens_staked.is_zero() {
				return Ok(pool_info.reward_per_token_stored);
			}

			let rewardable_blocks_elapsed: u32 =
				match Self::last_block_reward_applicable(pool_info.expiry_block)
					.ensure_sub(pool_info.last_update_block)?
					.try_into()
				{
					Ok(b) => b,
					Err(_) => return Err(Error::<T>::BlockNumberConversionError.into()),
				};

			Ok(pool_info.reward_per_token_stored.ensure_add(
				pool_info
					.reward_rate_per_block
					.ensure_mul(rewardable_blocks_elapsed.into())?
					.ensure_mul(PRECISION_SCALING_FACTOR.into())?
					.ensure_div(pool_info.total_tokens_staked)?,
			)?)
		}
