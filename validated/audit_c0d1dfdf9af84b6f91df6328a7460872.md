## Finding

### Title
Hostile HyperSwap V2 pre-seed can force `Bonding._seedRebalancing`'s failed-swap fallback into a min()-donation mint, permanently mis-seeding the graduation LP - ([File: packages/contracts/src/Bonding.sol])

### Summary
The CVE describes a resource that is allocated but never freed on a failure path (missing `kfree()`), leaking it permanently. The closest reachable analog in alt.fun's contracts is in `Bonding.finalizeGraduation`'s LP-seeding logic: once phase 1 (`_enterGraduating`) fires, all curve-raised LT and up to `LP_RESERVE` (250M) tokens are irreversibly "allocated" to the pending graduation and parked on `Bonding` [1](#0-0) . The only "free" path is a successful `finalizeGraduation` call, which seeds the HyperSwap V2 pair and hands LP to `LPLock` [2](#0-1) . If an attacker pre-creates and pre-seeds the TOKEN/LT V2 pair before graduation, the seeding routine's failure-fallback path (`_seedDirectMint` called when `_pairRebalance` returns `false`) mints LP into a **non-empty, attacker-controlled** pool using Uniswap V2's `min()` formula, which can donate the larger side of the deposit to the attacker's pre-existing LP shares — with no rescue mechanism afterward, since `LPLock` has no withdraw path in v1 [3](#0-2) .

### Finding Description
`finalizeGraduation` reads the phase-1-cached `(tokensForLP, ltFromPair)` and calls `_seedUniswapV2Direct` [4](#0-3) . When the pool already has LP minted (`totalSupply() != 0` — i.e., the attacker pre-created the pair and called `pair.mint()` against a self-funded seed before graduation), it takes the "Regime 3" rebalancing path via `_seedRebalancing` [5](#0-4) .

That function only overpowers the pre-seed with a safe direct mint when **both** sides are below the tiny `DIRECT_MINT_PRESEED_BPS` (1 bp) band [6](#0-5) . Otherwise it attempts `_pairRebalance` to swap the pool toward the curve-close ratio, but explicitly falls back to `_seedDirectMint` — the exact function the natspec says is "used by the empty-pair regime" — whenever `_pairRebalance` returns `false` [7](#0-6) . `_pairRebalance` returns `false` in two conditions unrelated to the pre-seed being "dust": the no-fee swap size rounding to `0` because the pool is already at-or-past the target ratio (`newIn <= reserveIn` in `_noFeeSwapInput`) [8](#0-7) , or the pair's fee-charging `getAmountOut` quote rounding to zero [9](#0-8) .

An attacker can engineer a large pre-seeded pool (well above the 1bp "dust" band, so it isn't caught by the safe overpower branch) whose reserve ratio is deliberately set so `_noFeeSwapInput` computes `s == 0` (i.e., the pool sits just past the point where any swap is deemed necessary in the required direction), forcing the `false` return. `_seedRebalancing` then calls `_seedDirectMint(tokenAddress, lt, pair, tokensForLP, ltFromPair)` against that large, non-empty, attacker-skewed pool [10](#0-9) . `IUniswapV2Pair(pair).mint(...)` computes `liquidity = min(amount0*totalSupply/reserve0, amount1*totalSupply/reserve1)` — the exact "min() donation to the attacker's pre-existing LP" scenario the contract's own natspec describes as the danger `_seedRebalancing` was built to prevent [11](#0-10) . The under-valued side of `(tokensForLP, ltFromPair)` is absorbed as reserves with no LP claim, effectively donated to the attacker's existing LP position, while `LPLock.recordLock` then permanently locks whatever (mis-sized) `liquidity` results, with a one-shot guard and no correction path [12](#0-11) .

### Impact Explanation
This is the "LP seeded away from the curve close price" outcome explicitly listed as an acceptable impact class, and it directly transfers value: part of the graduating token's `tokensForLP`/`ltFromPair` (curve-raised trader funds, now irrevocably parked on `Bonding` from phase 1) is donated to the attacker's pre-existing LP position instead of the protocol-locked LP. Because `LPLock` has no withdraw/rescue path, the mis-seeded, donated portion is permanently unrecoverable — the same "allocated-but-never-freed" shape as the CVE, except here the leaked resource is real LT/token value rather than kernel memory.

### Likelihood Explanation
The attack requires only unprivileged, pre-graduation actions reachable by any wallet: pre-create the HyperSwap V2 TOKEN/LT pair and self-mint LP at an engineered ratio before the target token graduates — actions explicitly listed as in-scope reachable analogs. Timing the exact reserve ratio to hit the `s == 0` branch (rather than the safe "both sides tiny" overpower branch) requires care but is fully computable off-chain from `_noFeeSwapInput`'s formula, since `tokensForLP`/`ltFromPair` are derivable from the curve's public state before the closing buy.

### Recommendation
Route the `_pairRebalance == false` fallback in `_seedRebalancing` through the same "dust-band" safety check used for the direct-overpower branch (or reject/queue the deposit) instead of unconditionally calling `_seedDirectMint` against a non-empty pool of arbitrary size. Only fall back to a raw `pair.mint()` when the existing reserves are provably negligible relative to `(tokensForLP, ltFromPair)`, and otherwise force a full rebalance (even if it requires relaxing the `maxSwap` cap) or explicitly account for/refund the off-ratio donation instead of silently absorbing it into the pre-existing LP holder's share.

### Proof of Concept
1. Attacker calls `Bonding._ensureUniswapV2Pair`-equivalent externally (`IUniswapV2Factory.createPair(token, lt)`) for a token still on the curve, before it graduates.
2. Attacker seeds the pair with a large, deliberately skewed `(tokenReserve, ltReserve)` ratio via `pair.mint()`, sized so that once the token graduates, `_noFeeSwapInput(reserveIn, reserveOut, targetN, targetD, maxSwap)` evaluates `newIn <= reserveIn` (or the fee-adjusted quote rounds to zero) for the direction `_seedRebalancing` would need to swap.
3. Drive the target token to graduation (buy through `Zap.buy`/`Bonding.buy` until `canGraduate` trips), entering `Lifecycle.Graduating` and parking `ltFromPair`/`tokensForLP` on `Bonding` via `_enterGraduating`.
4. Call `Bonding.finalizeGraduation(token)` (permissionless). `_seedRebalancing` hits the `_pairRebalance == false` branch and calls `_seedDirectMint` against the attacker's non-empty, skewed pool.
5. `pair.mint()`'s `min()` formula donates the larger side of `(tokensForLP, ltFromPair)` to the attacker's pre-existing LP shares; `LPLock.recordLock` permanently locks the resulting mis-sized `liquidity` with no rescue path.

        // bricking on a Panic if any future code path or non-canonical

        LPLock($.lpLock).recordLock(tokenAddress, lpPair, liquidity);

    function _seedUniswapV2Direct(
        address tokenAddress,
        address lt,
        address pair,
        uint256 tokensForLP,
        uint256 ltFromPair,
        uint256 protectedLT
    ) internal returns (uint256 liquidity) {
        // Regime 2 — pull any donation pre-seed into this contract so it
        // doesn't pollute the post-swap ratio. Routed to `address(this)`
        // (NOT `lpLock`) so donated TOKEN can be burned and donated LT
        // can be swept to the owner via `_sweepLTToOwner` — `LPLock` has
        // no rescue path, so anything sent there is permanently stuck.
        // No-op on a freshly-created pair (balance == reserves == 0).
        IUniswapV2Pair(pair).skim(address(this));

        // Regime 1 — no LP minted yet (`totalSupply == 0`): a pristine empty
        // pair, or a dust pre-seed from `transfer(pair, dust) + sync()` that
        // leaves reserves non-zero while supply is still zero. Keying on
        // supply rather than reserves routes the dust shape here instead of
        // the rebalance path: with zero supply V2 mints from our amounts
        // alone, so the pool opens at the cached ratio and any dust becomes
        // reserves with no LP claim.
        if (IUniswapV2Pair(pair).totalSupply() == 0) {
            return _seedDirectMint(tokenAddress, lt, pair, tokensForLP, ltFromPair);
        }

        // Regime 3 — mint pre-seed: rebalance, then deposit balanced subset.
        // `lpLock_` re-read from storage inside `_routerDepositAndDispose`.
        // Reserves and token-ordering re-read inside `_seedRebalancing` to
        // keep this function's stack pressure under solc's 16-slot ceiling
        // without `viaIR`.
        return _seedRebalancing(tokenAddress, lt, pair, tokensForLP, ltFromPair, protectedLT);
    }

    function _seedRebalancing(
        address tokenAddress,
        address lt,
        address pair,
        uint256 tokensForLP,
        uint256 ltFromPair,
        uint256 protectedLT
    ) internal returns (uint256 liquidity) {
        (uint112 r0, uint112 r1,) = IUniswapV2Pair(pair).getReserves();
        bool tokenIs0 = IUniswapV2Pair(pair).token0() == tokenAddress;
        (uint256 reserveToken, uint256 reserveLT) = tokenIs0 ? (uint256(r0), uint256(r1)) : (uint256(r1), uint256(r0));

        // Below the band on BOTH sides, overpower the pre-seed with a direct
        // mint at the cached ratio: the rebalance swap is too coarse to reach
        // the ratio against such small reserves, and the pre-existing LP's
        // claim on the deposit stays bounded by `DIRECT_MINT_PRESEED_BPS`. A
        // side that is large relative to its LP target still takes the
        // rebalance path so it isn't donated under the empty-mint `min()`.
        if (
            reserveToken * BPS_DENOM <= tokensForLP * DIRECT_MINT_PRESEED_BPS
                && reserveLT * BPS_DENOM <= ltFromPair * DIRECT_MINT_PRESEED_BPS
        ) {
            return _seedDirectMint(tokenAddress, lt, pair, tokensForLP, ltFromPair);
        }

        // Budget reads `balanceOf(this)` rather than `tokensForLP` /
        // `ltFromPair` so any skim donation contributes to the rebalance
        // and not only to `_routerDepositAndDispose`'s deposit.
        // Direction: pool TOKEN-rich vs target ⇒ swap LT in (TOKEN out).
        // Pool LT-rich ⇒ swap TOKEN in (LT out). Bounded by uint112 reserves
        // and curve-close-shape targets, both products fit in uint256.
        // When `_pairRebalance` returns false the seed is too small for any
        // swap to move the ratio (its fee-charging quote rounds to zero), so
        // the reserves are negligible against this graduation's inventory:
        // overpower them with a direct mint at the cached ratio rather than
        // letting the router deposit at the attacker's ratio. A swap that
        // does fire leaves the pool ≈ at target for the router deposit.
        if (reserveToken * ltFromPair > reserveLT * tokensForLP) {
            // Pool TOKEN-rich. tokenIn = lt, tokenOut = tokenAddress.
            // tokenInIs0 = (lt is token0) = !tokenIs0.
            if (!_pairRebalance(
                    RebalanceParams({
                        pair: pair,
                        tokenIn: lt,
                        tokenInIs0: !tokenIs0,
                        reserveIn: reserveLT,
                        reserveOut: reserveToken,
                        targetN: ltFromPair,
                        targetD: tokensForLP,
                        maxSwap: _swapBudget(_ltSwapInventory(lt, protectedLT))
                    })
                )) {
                return _seedDirectMint(tokenAddress, lt, pair, tokensForLP, ltFromPair);
            }
        } else if (reserveToken * ltFromPair < reserveLT * tokensForLP) {
            // Pool LT-rich. tokenIn = tokenAddress, tokenInIs0 = tokenIs0.
            if (!_pairRebalance(
                    RebalanceParams({
                        pair: pair,
                        tokenIn: tokenAddress,
                        tokenInIs0: tokenIs0,
                        reserveIn: reserveToken,
                        reserveOut: reserveLT,
                        targetN: tokensForLP,
                        targetD: ltFromPair,
                        maxSwap: _swapBudget(IERC20(tokenAddress).balanceOf(address(this)))
                    })
                )) {
                return _seedDirectMint(tokenAddress, lt, pair, tokensForLP, ltFromPair);
            }
        }
        // else: pool already at curve-close ratio (rare — e.g. attacker
        // pre-seeded at exactly target). Skip swap, deposit directly.

        return _routerDepositAndDispose(tokenAddress, lt, protectedLT);
    }

    function _pairRebalance(
        RebalanceParams memory p
    ) internal returns (bool) {
        uint256 s = _noFeeSwapInput(p.reserveIn, p.reserveOut, p.targetN, p.targetD, p.maxSwap);
        if (s == 0) return false;

        // Quote from the pair so the output tracks its live fee; a value
        // derived from a stale fee rate would trip the pair's K-check.
        uint256 expectedOut = IUniswapV2Pair(p.pair).getAmountOut(s, p.tokenIn);
        if (expectedOut == 0) return false;

        IERC20(p.tokenIn).safeTransfer(p.pair, s);
        (uint256 amount0Out, uint256 amount1Out) = p.tokenInIs0 ? (uint256(0), expectedOut) : (expectedOut, uint256(0));
        IUniswapV2Pair(p.pair).swap(amount0Out, amount1Out, address(this), new bytes(0));
        return true;
    }

    function _noFeeSwapInput(
        uint256 reserveIn,
        uint256 reserveOut,
        uint256 targetN,
        uint256 targetD,
        uint256 maxSwap
    ) internal pure returns (uint256) {
        if (reserveIn == 0 || reserveOut == 0 || targetN == 0 || targetD == 0 || maxSwap == 0) {
            return 0;
        }
        uint256 product = Math.mulDiv(reserveIn * reserveOut, targetN, targetD);
        uint256 newIn = Math.sqrt(product);
        if (newIn <= reserveIn) return 0;
        uint256 s = newIn - reserveIn;
        return s > maxSwap ? maxSwap : s;
    }

    /// @notice Record an LP lock. LP tokens must already sit at this address.
    function recordLock(
        address token,
        address lpPair,
        uint256 amount
    ) external {
        LPLockStorage storage $ = _s();
        if (!$.isLocker[msg.sender]) revert NotAuthorized();
        if (lpPair == address(0)) revert ZeroAddress();
        if (amount == 0) revert ZeroAmount();
        // `lockedAt` is the one-shot sentinel: it is always set to a non-zero
        // timestamp on the first lock, so the guard holds for any `amount`.
        if ($.locks[token].lockedAt != 0) revert AlreadyLocked();
        if (IERC20(lpPair).balanceOf(address(this)) < amount) revert InsufficientLPBalance();
        $.locks[token] = LockInfo({lpPair: lpPair, amount: amount, lockedAt: block.timestamp});
        emit LPLocked(token, lpPair, amount);
    }
