## Analog Found

### Title
Missing relayer allowlist on Tron `IntentGatewayV2.onAccept` lets any relayer redeem escrows and push governance actions - (File: `evm/tron/contracts/apps/IntentGatewayV2.sol`)

### Summary
The EVM `IntentGatewayV2`/`ExtrinsicIntents` gateway gates every `onAccept` and `onGetResponse` delivery behind a single authorised `_relayer` before the message body is even decoded, explicitly so escrow redemptions, refunds, and every governance action (deployments, param updates, dust sweeps, upgrades) hold even if Hyperbridge's consensus itself is compromised or the delivering relayer is malicious. The Tron port of the same contract (`evm/tron/contracts/apps/IntentGatewayV2.sol`) implements the same `onAccept` dispatch surface but never performs this relayer check, so any account that can get a message delivered through the host can trigger privileged escrow and treasury actions.

### Finding Description
`ExtrinsicIntents._checkRelayer` is called unconditionally as the very first step of `onAccept`/`onGetResponse` on the canonical EVM gateway, before the request kind is even read: [1](#0-0) 

The changelog explicitly states the reason: the check exists "so the setter must not depend on [Hyperbridge's consensus]... the whole point is to hold even if Hyperbridge's consensus is compromised": [2](#0-1) 

The Tron `IntentGatewayV2.onAccept` implements the same request kinds (`RedeemEscrow`, `RefundEscrow`, `NewDeployment`, `UpdateParams`, `SweepDust`) but performs only `authenticate()`/source checks — never a relayer allowlist check: [3](#0-2) 

Because `onlyHost` only confirms the caller is the local `EvmHost` (which any relayer can invoke via `HandlerV2.handlePostRequests`/`handleGetResponses` once it produces a valid proof), and the `source == hyperbridge` check only validates provenance of the request's origin chain, there is no restriction on *which relayer* is permitted to deliver the message. This is precisely the missing authorization layer that the EVM gateway added as defense-in-depth against a forged/malicious delivery path — the Tron contract lacks it entirely.

### Impact Explanation
Any relayer capable of delivering a validly-proven (or maliciously-crafted, in a degraded-consensus scenario) ISMP message can:
- Trigger `RedeemEscrow`/`RefundEscrow` withdrawals of escrowed order funds.
- Trigger `SweepDust`, sending accumulated protocol dust to an attacker-controlled beneficiary.
- Trigger `NewDeployment`/`UpdateParams`, corrupting the gateway's peer-instance registry or fee parameters.

This maps to concrete theft of escrowed/treasury funds and unauthorized state mutation on the Tron deployment, matching the CVE's "unauthorized update, insert, or delete access" pattern from a low-privileged network actor.

### Likelihood Explanation
Exploitability requires only that a message reaches `EvmHost.dispatchIncoming` addressed to the Tron `IntentGatewayV2` — no privileged relayer key or governance access is needed, unlike the EVM gateway's `_relayer` gate. Any of the many relaying parties (which the system's own documentation treats as an untrusted/permissionless population) is unprivileged relative to this action but reachable via a single relayed message.

### Recommendation
Port the `_relayer`/`_checkRelayer` gate (or equivalent) from `evm/src/apps/intentsv2/ExtrinsicIntents.sol` into the Tron `IntentGatewayV2.onAccept`/`onGetResponse`, running it before any request-kind branching, along with `setRelayer`/`migrate`/`initialize` wiring consistent with the EVM implementation.

### Proof of Concept
1. Deploy/observe the Tron `IntentGatewayV2` contract with escrowed order funds present.
2. Any relayer (not a specially-authorised one, since none exists in this contract) submits a `PostRequestMessage` via `HandlerV2.handlePostRequests` carrying a `RedeemEscrow` or `SweepDust` body addressed to the gateway.
3. `EvmHost.dispatchIncoming` invokes `IntentGatewayV2.onAccept`, which only checks `onlyHost` and (for governance kinds) `source == hyperbridge` — with no check on the relaying account — and executes the withdrawal/sweep.
4. Compare against the EVM gateway where the same call would revert with `Unauthorized` from `_checkRelayer` unless submitted by the one authorised relayer, as demonstrated in `testOnAcceptRejectsUnlistedRelayer`: [4](#0-3)

     * @dev Once a relayer is set, rejects deliveries from anyone else before the body is read. The

    function _checkRelayer(address relayer) internal view {
        address authorised = _relayer;
        if (authorised != address(0) && relayer != authorised) revert Unauthorized();

    function onAccept(IncomingPostRequest calldata incoming) external override onlyHost {
        RequestKind kind = RequestKind(uint8(incoming.request.body[0]));
        if (kind == RequestKind.RedeemEscrow || kind == RequestKind.RefundEscrow) {
            authenticate(incoming.request);
            WithdrawalRequest memory body = abi.decode(incoming.request.body[1:], (WithdrawalRequest));
            return withdraw(body, kind == RequestKind.RefundEscrow);
        }

        // only hyperbridge is permitted to perfom these actions
        if (keccak256(incoming.request.source) != keccak256(IDispatcher(host()).hyperbridge())) revert Unauthorized();
        if (kind == RequestKind.NewDeployment) {
            NewDeployment memory body = abi.decode(incoming.request.body[1:], (NewDeployment));
            _instances[keccak256(body.stateMachineId)] = body.gateway;

            emit NewDeploymentAdded({stateMachineId: body.stateMachineId, gateway: body.gateway});
        } else if (kind == RequestKind.UpdateParams) {
            // Decode the body which includes optional destination-specific protocol fee updates
            ParamsUpdate memory update = abi.decode(incoming.request.body[1:], (ParamsUpdate));
            emit ParamsUpdated({previous: _params, current: update.params});
            _params = update.params;

            // Update destination-specific protocol fees if provided
            for (uint256 i; i < update.destinationFees.length;) {
                bytes32 stateMachineId = update.destinationFees[i].stateMachineId;
                uint256 feeBps = update.destinationFees[i].destinationFeeBps;
                _destinationProtocolFees[stateMachineId] = feeBps;

                unchecked {
                    ++i;
                }
                emit DestinationProtocolFeeUpdated(stateMachineId, feeBps);
            }
        } else if (kind == RequestKind.SweepDust) {
            SweepDust memory req = abi.decode(incoming.request.body[1:], (SweepDust));

            uint256 outputsLen = req.outputs.length;
            for (uint256 i; i < outputsLen;) {
                TokenInfo memory info = req.outputs[i];
                address token = address(uint160(uint256(info.token)));
                uint256 amount = info.amount;

                if (token == address(0)) {
                    (bool sent,) = req.beneficiary.call{value: amount}("");
                    if (!sent) revert InsufficientNativeToken();
                } else {
                    (bool success,) = token.call(abi.encodeWithSelector(IERC20.transfer.selector, req.beneficiary, amount));
                    if (!success) revert TransferFailed();
                }
                unchecked {
                    ++i;
                }
                emit DustSwept(token, amount, req.beneficiary);
            }
        }

    function testOnAcceptRejectsUnlistedRelayer() public {
        (PostRequest memory request, bytes32 commitment, uint256 amount) = _escrowedRedeemRequest();

        vm.prank(address(host));
        vm.expectRevert(IntentsBase.Unauthorized.selector);
        intentGateway.onAccept(IncomingPostRequest({relayer: filler, request: request}));
        assertEq(intentGateway._orders(commitment, address(usdc)), amount, "escrow untouched");
        assertEq(intentGateway._filled(commitment), address(0), "order not finalised");

        // The very same message goes through once the authorised relayer submits it.
        uint256 before = usdc.balanceOf(filler);
        vm.prank(address(host));
        intentGateway.onAccept(IncomingPostRequest({relayer: relayer, request: request}));
        assertEq(usdc.balanceOf(filler) - before, amount, "authorised relayer releases escrow");
        assertEq(intentGateway._filled(commitment), filler, "order finalised");
    }
