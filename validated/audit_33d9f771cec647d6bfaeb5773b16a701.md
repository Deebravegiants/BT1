### Title
Stale `TombStone.original_owner` surviving ungated object transfers allows a former owner to reclaim an object legitimately burnt by a later owner - (File: `aptos-move/framework/aptos-framework/sources/object.move`)

### Summary
`object::burn` performs a "soft burn" by attaching a `TombStone { original_owner }` resource to an object without changing its `owner` field [1](#0-0) . The object can still be transferred normally afterward through `transfer`/`transfer_raw`/`transfer_call`/`transfer_to_object`, all of which resolve to `transfer_raw_inner`, and none of them clear the `TombStone` resource [2](#0-1) . Only the ref-based transfer path (`transfer_with_ref`, used with `LinearTransferRef`) explicitly removes a stale `TombStone` before transferring, with an inline comment acknowledging the exact risk being avoided [3](#0-2) . `unburn` trusts the stored `original_owner` address whenever the object's current owner is `BURN_ADDRESS`, and transfers the object back to that stale address [4](#0-3) .

### Finding Description
The custody invariant broken here is analogous to the Gitcoin `reviewsByStatus` bug: a piece of authority-bearing state (`TombStone.original_owner`, granting a one-time reclaim right) is not reset when the object undergoes a state-changing action (an unrelated ownership transfer) that should invalidate it.

Concrete flow:
1. Owner `A` calls `object::burn(A, obj)`. This creates `TombStone { original_owner: A }` while `obj`'s `ObjectCore.owner` stays `A` [1](#0-0) .
2. `A` legitimately transfers `obj` to `B` using the normal, ungated `object::transfer` entry function. This calls `transfer_raw` → `verify_ungated_and_descendant` → `transfer_raw_inner`, which only updates `object_core.owner`; it does not touch or clear `TombStone` [5](#0-4) .
3. `B`, now the rightful owner, later decides to permanently burn the object using the legacy convention of sending it to `BURN_ADDRESS` (e.g., via a plain `transfer` call to `BURN_ADDRESS`, or any flow that results in `owner == BURN_ADDRESS`).
4. `A` calls `object::unburn(A, obj)`. Since `object_core.owner == BURN_ADDRESS`, the function takes the legacy branch, and because the still-existing (stale) `TombStone.original_owner` equals `A`, the assertion passes and `transfer_raw_inner(object_addr, A)` restores ownership to `A` [6](#0-5) .

`A` — who no longer has any legitimate claim on the object after transferring it away in step 2 — recovers an object that its rightful and most recent owner `B` intentionally and permanently burnt. The framework's own comment in `transfer_with_ref` confirms the developers recognized that a lingering `TombStone` must be cleared on transfer to prevent this exact reclaim-by-stale-owner scenario, but the fix was only applied to the `LinearTransferRef` path, not to the standard/ungated transfer entry points.

### Impact Explanation
This breaks object custody: ownership/reclaim authority (an object-model primitive used broadly for tokens, NFTs, and other object-held value) is unintentionally retained by a past owner across a legitimate transfer. It results in unauthorized owner reassignment of a live, object-held asset and defeats the "permanent, non-recoverable burn" guarantee `B` relied on. Since `object.move` underlies fungible-asset stores, digital-asset/token objects, and other value-bearing objects across the framework, any application relying on `object::burn`/`unburn` semantics for permanent destruction (or on the assumption that only the current owner can reclaim a tomb-stoned object) is exposed to theft/reclaim by a stale prior owner.

### Likelihood Explanation
The path only requires standard, permissionless entry functions (`burn`, `transfer`, and a subsequent send to `BURN_ADDRESS`, then `unburn`), all callable by ordinary unprivileged accounts, with `allow_ungated_transfer` left at its default (`true`). No special privileges, governance, or leaked keys are required — an attacker (a past owner) simply times a soft-burn before giving/selling the object away, then waits for `BURN_ADDRESS`.

### Recommendation
Clear the `TombStone` resource in `transfer_raw_inner` (or otherwise on every ownership-changing transfer path: `transfer`, `transfer_raw`, `transfer_call`, `transfer_to_object`), mirroring the same defensive clearing already done in `transfer_with_ref`, so that a stale `original_owner` can never be used to reclaim an object after it has changed hands.

### Proof of Concept
```
1. A: object::create_named_object / obtain Object<T> obj, A owns obj.
2. A: object::burn(A, obj)  // TombStone{original_owner: A}, owner stays A
3. A: object::transfer(A, obj, B)  // owner -> B, TombStone untouched
4. B: object::transfer(B, obj, BURN_ADDRESS)  // owner -> BURN_ADDRESS
5. A: object::unburn(A, obj)
   -> object_core.owner == BURN_ADDRESS
   -> TombStone.original_owner (stale) == A == signer
   -> transfer_raw_inner(obj, A)  // A reclaims an object B had burnt
```
This can be validated by extending the existing test suite in `object.move` (e.g., alongside `test_burn_and_unburn`/`test_cannot_unburn_after_transfer_with_ref`) with a case that performs a plain `transfer` (not `transfer_with_ref`) between step 2 and 3, showing `unburn` still succeeds for the stale original owner.     inline fun transfer_raw_inner(object: address, to: address) {
        let object_core = borrow_global_mut<ObjectCore>(object);
        if (object_core.owner != to) {
            event::emit(
                Transfer {
                    object,
                    from: object_core.owner,
                    to,
                },
            );
            object_core.owner = to;
        };

    /// Allow origin owners to reclaim any objects they previous burnt.
    public entry fun unburn<T: key>(
        original_owner: &signer,
        object: Object<T>,
    ) {
        let object_addr = object.inner;
        assert!(exists<TombStone>(object_addr), error::invalid_argument(EOBJECT_NOT_BURNT));

        // The new owner of the object can always unburn it, but if it's the burn address, we go to the old functionality
        let object_core = borrow_global<ObjectCore>(object_addr);
        if (object_core.owner == signer::address_of(original_owner)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object_addr);
        } else if (object_core.owner == BURN_ADDRESS) {
            // The old functionality
            let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
            assert!(
                original_owner_addr == signer::address_of(original_owner),
                error::permission_denied(ENOT_OBJECT_OWNER)
            );
            transfer_raw_inner(object_addr, original_owner_addr);
        } else {
            abort error::permission_denied(ENOT_OBJECT_OWNER);
        };
    }
