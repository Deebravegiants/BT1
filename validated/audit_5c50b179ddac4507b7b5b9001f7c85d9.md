### Title
Consensus relayer rewards paid entirely at current rate for backlog spanning rate changes - (File: `modules/pallets/consensus-incentives/src/impls.rs`)

### Summary
`pallet-consensus-incentives::calculate_reward` computes a relayer's reward as `(latest_height - baseline) * current_cost_per_block`, applying the *current* `StateMachinesCostPerBlock` rate to the entire unpaid block span, even if `update_cost_per_block` changed the rate one or more times between `baseline` (the `LastRewardedHeight` watermark) and `latest_height`. This is the same bug class as the reported DIA `getRewardForStakingStore` issue: rewards for a historical accrual period are calculated using only the rate in effect at settlement time, not the rate(s) actually in effect while the reward was accruing.

### Finding Description
`process_message` reads the current per-block cost and passes it into `calculate_reward`: [1](#0-0) 

`calculate_reward` then multiplies the *entire* unpaid block span (`latest_height - baseline`) by that single `block_cost` value: [2](#0-1) 

`baseline` is the persisted `LastRewardedHeight` watermark, which only advances on a successful reward and is not reset when the rate changes: [3](#0-2) 

`update_cost_per_block` can change the applicable rate for a state machine at any time via a simple storage write, with no snapshot of the previous rate, no accrual-index update, and no interaction with `LastRewardedHeight`: [4](#0-3) 

Because there is no accumulator/index tracking rewards accrued per block under each historical rate (the exact remediation recommended in the external report), any backlog of unpaid blocks — which can be arbitrarily large since consensus updates are relayer-submitted and not required at every block — is paid out entirely at whichever rate happens to be active when the relayer's `ConsensusMessage` is finally processed by `on_executed`/`process_message`: [5](#0-4) 

This is reachable by any relayer submitting a normal `ConsensusMessage` (an ordinary, permissionless ISMP dispatch/delivery path) — no privileged action is required from the relayer side to trigger the miscalculated payout; only the rate change itself (a routine, non-malicious governance parameter update, not an attack) is privileged.

### Impact Explanation
- If governance raises `cost_per_block` while a backlog of unpaid blocks (accrued under the old, lower rate) is outstanding, the relayer who eventually submits the next `ConsensusMessage` is paid the entire backlog at the new, higher rate — this is an unbacked overpayment out of the `TreasuryAccount`, i.e. a treasury-fund drain beyond what governance intended to allocate for the periods actually covered by the old rate.
- Conversely, if governance lowers the rate, relayers who already accrued value under the higher rate are permanently underpaid for that span — `LastRewardedHeight` advances past that span once any reward (even an incorrect one) is paid, so the difference can never be reclaimed. This is a permanent loss of rightfully-owed relayer rewards.
- Because relayers control the timing of when they submit the consensus proof that triggers `process_message`, a relayer can strategically delay submission until after a rate increase to maximize the treasury payout for blocks that accrued mostly under the old rate — extracting more value than the protocol intended.

### Likelihood Explanation
Rate updates via `update_cost_per_block` are an expected, routine governance operation (not requiring any malicious actor), and consensus updates are inherently irregular/relayer-driven, so there will regularly be an outstanding, non-trivial block backlog at the time any rate change takes effect. Any relayer who submits the next consensus message after a rate change automatically triggers the mispriced payout — no crafted proof or special conditions are needed beyond normal submission timing, making this easy to hit in practice and, in the overpayment direction, straightforward for a relayer to time deliberately.

### Recommendation
Introduce a reward accumulator/index analogous to the one recommended (and implemented by the client) for the DIA staking case: whenever `update_cost_per_block` changes the rate for a state machine, first settle/snapshot the reward accrued up to the current height at the *old* rate (or update a per-state-machine cumulative index), then apply the new rate only to blocks going forward. `calculate_reward` should sum contributions from each rate segment between `baseline` and `latest_height` rather than multiplying the full span by a single current rate.

### Proof of Concept
1. Governance sets `StateMachinesCostPerBlock[sm] = 100` via `update_cost_per_block`.
2. No consensus message is delivered for `sm` for 1000 blocks (backlog accrues, `LastRewardedHeight` stays at the old watermark).
3. Governance raises the rate: `update_cost_per_block(sm, 10_000)`.
4. A relayer submits a `ConsensusMessage` advancing `sm` to `latest_height`, triggering `on_executed` → `process_message` → `calculate_reward`.
5. `calculate_reward` computes `reward = 1000 * 10_000` — the entire backlog is paid at the new rate, whereas the protocol only intended `1000 * 100` for that period; the excess is drained from `TreasuryAccount`, mirroring the "identical stakes/backlogs receive different (incorrect) rewards depending on the current rate rather than the rate in effect during accrual" flaw described in the external report.

	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)

	fn on_executed(
		messages: Vec<MessageWithWeight>,
		events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});

		if let Some(relayer_account) = maybe_relayer_account {
			// When a batch contains multiple `StateMachineUpdated` events for the
			// same `state_machine_id` (sequential consensus updates for the same
			// chain), `calculate_reward` reads the same persisted
			// `(latest_commitment_height, previous_commitment_height)` pair on
			// every iteration and pays the same block-span reward N times.
			// Collapse the per-state-machine event stream to the single highest
			// `latest_height` so each state machine receives one reward per
			// batch, sized by the actual span of its commitment advance.
			let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
			for event in events {
				if let IsmpEvent::StateMachineUpdated(update) = event {
					highest_per_state_machine
						.entry(update.state_machine_id)
						.and_modify(|h| {
							if update.latest_height > *h {
								*h = update.latest_height;
							}
						})
						.or_insert(update.latest_height);
				}
			}

			for (state_machine_id, latest_height) in highest_per_state_machine {
				let state_machine_height =
					StateMachineHeight { id: state_machine_id.clone(), height: latest_height };

				let _ = Self::process_message(
					state_machine_height,
					state_machine_id,
					relayer_account.clone().into(),
				);
			}
		}

		#[pallet::call_index(0)]

			state_machine_id: StateMachineId,
