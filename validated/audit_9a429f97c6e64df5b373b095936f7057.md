## Title
`CallDispatcher.dispatch` is a public, unrestricted arbitrary-call executor — any residual ETH/ERC20 balance held by the shared dispatcher can be drained by anyone - ([File: evm/src/utils/CallDispatcher.sol])

### Summary
`CallDispatcher.dispatch()` executes attacker-supplied `Call[]` arrays with no access control whatsoever. This contract is the same "logic call" primitive as the referenced Gravity Bridge finding: it is designed to temporarily custody tokens/ETH on behalf of `HyperFungibleToken`, `WrappedHyperFungibleToken`, and `IntentGatewayV2` while composable post-processing calls run, but nothing restricts who may invoke `dispatch()` or on what balance it operates. Any ETH or ERC20 tokens that end up sitting on the `CallDispatcher` — whether from documented dust, an incompletely-swept swap, or an accidental/failed intermediate step — can be swept to an attacker by simply calling `dispatch()` directly with a `Call` that transfers the balance out.

### Finding Description
`CallDispatcher.dispatch` has no caller restriction: [1](#0-0) 

It also has an unguarded `receive()` so it can accept native ETH from anyone: [2](#0-1) 

The protocol explicitly relies on this same `CallDispatcher` instance temporarily holding real user funds by design. `HyperFungibleToken`/`WrappedHyperFungibleToken` mint or unlock tokens directly to the dispatcher address so its bundled calls can spend them: [3](#0-2) 

and the documentation instructs integrators to route funds to the dispatcher this way, explicitly warning that "the dispatcher contract holds tokens temporarily during execution": [4](#0-3) 

`IntentsBase._execute` similarly transfers order output assets to the dispatcher, dispatches the solver/user-supplied `order.output.call`, and only then sweeps back balances of the specific `order.output.assets` tokens declared for that order: [5](#0-4) 

Because the sweep only iterates the tokens listed in `order.output.assets[0..outputsLen)`, any token or native ETH balance left on the dispatcher that is *not* one of those declared assets (e.g. a swap byproduct token, unspent `Call.value`, or dust from any other app sharing the same dispatcher deployment) is never swept back and remains parked on the dispatcher indefinitely. Since `dispatch()` is callable by anyone with no ownership check, any observer can immediately drain that balance with a single `Call{to: token/attacker, value/data: transfer(attacker, balance)}`.

This mirrors the original report's root cause exactly: a component that can execute arbitrary attacker-chosen calls (`submitLogicCall` there, `CallDispatcher.dispatch` here) is not restricted from acting on funds it doesn't own, letting an unprivileged caller move out any balance sitting on that component.

### Impact Explanation
Any ETH or ERC20 balance that ends up on a deployed `CallDispatcher` — dust from swap byproducts, leftover `Call.value`, or any other unaccounted residual across the apps sharing that dispatcher (HFT, WrappedHFT, IntentGatewayV2) — is unconditionally and immediately theft by any address, since `dispatch()` performs no ownership, source, or balance-provenance check before executing the caller-supplied `Call[]`. This is a direct, unprivileged theft-of-funds primitive reachable by a single transaction, satisfying the "concrete theft of funds" bar.

### Likelihood Explanation
Likelihood is high given normal, documented usage: composable calldata execution (swap-then-forward patterns for HFT/WrappedHFT, or DeFi routing for intent outputs) routinely produces amounts that don't perfectly net to zero (slippage, rounding, byproduct tokens, unspent `Call.value`), and `IntentsBase._execute`'s sweep only covers the order's own declared output-asset list, not arbitrary tokens touched by the call. Any such residual is a standing, permanently exploitable balance since nothing ever expires or is access-controlled on the dispatcher.

### Recommendation
Restrict `CallDispatcher.dispatch` to only be callable by the authorized app contract(s) that are configured to use it (e.g. an allow-listed caller set at construction, or per-caller allow-listing by the apps that reference it), and/or have each app sweep *all* residual token/ETH balances left on the dispatcher after every call (not just the declared output-asset list), rather than only the tokens it explicitly expects. Alternatively, make the dispatcher ephemeral (deploy a fresh instance per call, e.g. via `CREATE2`/minimal proxy per dispatch) so it can never carry a standing balance between unrelated calls.

### Proof of Concept
1. Any legitimate cross-chain transfer/order routes tokens through a shared `CallDispatcher` as its `to`/temporary holder, per the documented pattern in `evm/src/apps/intentsv2/IntentsBase.sol` (`_execute`) or `HyperFungibleToken.onAccept`.
2. Due to slippage/rounding/byproduct tokens, or an incomplete `Call[]` sequence, some ETH or ERC20 balance remains on the `CallDispatcher` after the triggering transaction completes (not swept because it isn't part of `order.output.assets`, or because the app in question performs no sweep at all, as with `HyperFungibleToken`).
3. An attacker calls `CallDispatcher.dispatch(abi.encode([Call({to: attacker, value: address(dispatcher).balance, data: ""})]))` (for ETH) or a `Call` invoking `token.transfer(attacker, token.balanceOf(dispatcher))` (for ERC20 dust) directly — no permission is required since `dispatch()` is `external` with no modifier.
4. The residual balance is transferred to the attacker.

     *  @dev reverts if the target is not a contract or if any of the calls reverts.
     */
    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }

### Security

The `CallDispatcher` executes calls in its own context (not via `delegatecall`), so the HFT contract's storage is never at risk. If any call in the array reverts, the entire `onAccept` handler reverts — including the token mint/unlock. The request can then be retried by any relayer until the timeout expires. If no successful execution occurs before the timeout, the request times out and the sender is eligible for a refund on the source chain. Token approvals in the `Call[]` should use exact amounts rather than unlimited allowances, since the dispatcher contract holds tokens temporarily during execution.

    function _execute(Order calldata order, uint256 outputsLen) internal {
        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            } else {
                uint256 balance = IERC20(token).balanceOf(dispatcher);
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            }

            unchecked {
                ++i;
            }
        }
