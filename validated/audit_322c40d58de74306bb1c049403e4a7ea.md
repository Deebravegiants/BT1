### Title
Unbounded BEEFY signature count enables free CPU-amplification DoS during unsigned extrinsic verification - (File: `modules/consensus/beefy/verifier/src/lib.rs`)

### Summary
`pallet-ismp`'s `handle_unsigned` extrinsic is validated for free by every full node's transaction pool (`validate_unsigned` fully executes the message before block inclusion), and the BEEFY consensus verifier performs a secp256k1 signature-recovery loop over an attacker-controlled, upper-unbounded number of signatures *before* the cheap merkle-multiproof check that would reject a bogus/padded batch. This mirrors the Besu bug class: a message whose acceptance criteria are checked only after expensive, attacker-inflatable computation, letting a submitter force disproportionate verification time on every node that processes the message, for zero fee.

### Finding Description
`pallet_ismp::Pallet::handle_unsigned` is an unsigned extrinsic explicitly documented as executing "cross-chain messages... for free": [1](#0-0) 

`ValidateUnsigned::validate_unsigned` for this pallet calls `Self::execute(messages.clone())` — i.e., it fully runs consensus/message verification — during transaction-pool validation, which every peer performs upon receiving the gossiped extrinsic, before it is ever included in a block: [2](#0-1) 

The declared extrinsic weight is a flat constant regardless of the actual proof content or size, so the runtime's own accounting does not reflect the true cost of processing a given consensus message: [3](#0-2) 

For a `Message::Consensus` carrying a BEEFY proof, execution reaches `beefy-verifier`'s `verify_mmr_update_proof`. The only pre-loop check on the number of signatures is a *lower* bound (supermajority threshold, `len >= 2/3+1`); there is no *upper* bound before the code loops over every supplied signature and performs an ECDSA/secp256k1 public-key recovery for each one: [4](#0-3) 

Only *after* this recovery loop completes does the code run the (cheap) merkle multi-proof check of authority-set membership, which is what would actually reject a batch padded with bogus/duplicate signatures: [5](#0-4) 

The identical pattern exists in the Solidity BEEFY consensus client used on EVM hosts, where `checkParticipationThreshold` is also only a lower bound before the `ecrecover` loop: [6](#0-5) 

Since `sig_len`/`sigLen` is fully attacker-controlled (bounded only by the maximum extrinsic/block size), an attacker can submit one consensus message containing tens of thousands of 65-byte signature entries (a genuine 2/3+1 supermajority subset plus large amounts of padding), forcing tens of thousands of expensive elliptic-curve recovery operations to run before the proof is ultimately rejected by the merkle multi-proof check. This is exactly the Besu bug class: the cost of rejecting an invalid input is far higher than the cost of accepting a legitimate one, and that cost is incurred by every verifier (here, every Substrate full node's `validate_unsigned` gossip-validation path) before any fee or gas is charged.

### Impact Explanation
This is a network-wide, zero-cost-to-attacker CPU-amplification vector reachable from a single relayed/dispatched message:
- `validate_unsigned` runs on every full node that receives the gossiped extrinsic, not just the block author, so the attack's cost multiplies across the whole network of nodes relaying pallet-ismp traffic.
- Because `pallet_ismp::Call::handle_unsigned` messages are processed for free (no fee is charged for a rejected/invalid message during pool validation), an attacker pays only the bandwidth cost of constructing and gossiping a large message, not the CPU cost it imposes on verifiers.
- Repeated submission of such oversized consensus messages can slow down block-import/tx-pool processing across collators and relayer-adjacent infrastructure, delaying legitimate message delivery and consensus updates — a route-unable-to-deliver-messages condition consistent with the "Medium" severity class of the referenced Besu report, whose core harm was delaying block production for a bounded window via disproportionately expensive but ultimately-rejected verification work.

### Likelihood Explanation
Constructing the padded proof requires no special access: it only needs a legitimate supermajority subset of already-public signatures (or byte-garbage entries that still consume a recovery attempt) appended to satisfy the lower-bound check, and the message is submitted as an ordinary, permissionless, unsigned `handle_unsigned` extrinsic — no privileged role, governance, or malicious insider is required. The complexity is low: the same `MmrProof`/`RelayChainProof` wire format already accepts a `Vec` of signatures with no explicit length cap.

### Recommendation
Bound the accepted signature count to a small, fixed multiple of the trusted authority set size (e.g., reject if `signatures.len() > authority_set.len`) *before* entering the recovery loop, in both `modules/consensus/beefy/verifier/src/lib.rs::verify_mmr_update_proof` and `evm/src/consensus/EcdsaBeefy.sol::verifyMmrUpdateProof`. Additionally, consider computing a benchmarked, size-proportional weight for `handle_unsigned` (or per consensus-client type) rather than a flat constant, so the runtime's own weight/fee accounting reflects true verification cost and can reject oversized batches early.

### Proof of Concept
1. Take a valid BEEFY `SignedCommitment` for the current relay-chain block with a genuine supermajority of signatures (satisfies `check_participation_threshold`).
2. Append N additional bogus `SignatureWithAuthorityIndex` entries (arbitrary 65-byte blobs with unused indices) to `signed_commitment.signatures`, up to the size permitted by the extrinsic/block size limit.
3. Wrap this in a `ConsensusMessage` inside `Message::Consensus`, and submit it via `pallet_ismp::Call::handle_unsigned` as an unsigned extrinsic.
4. Every node's `validate_unsigned` (`modules/pallets/ismp/src/lib.rs` lines 614-626) calls `Self::execute`, which reaches `verify_mmr_update_proof` (`modules/consensus/beefy/verifier/src/lib.rs` lines 149-162) and performs `secp256k1_recover` for all N+supermajority signatures before the authority merkle-proof check at line 166 rejects the padded batch — consuming CPU time proportional to N on every node, for a transaction that is ultimately discarded and costs the submitter nothing beyond bandwidth.

pub fn verify_mmr_update_proof<H: Keccak256 + EcdsaRecover + Send + Sync>(
	mut trusted_state: ConsensusState,
	mmr: MmrProof,
) -> Result<(ConsensusState, H256), Error> {
	let signatures_length = mmr.signed_commitment.signatures.len();
	let latest_height = mmr.signed_commitment.commitment.block_number;

	if trusted_state.latest_beefy_height >= latest_height {
		return Err(Error::StaleHeight {
			trusted_height: trusted_state.latest_beefy_height,
			current_height: latest_height,
		});
	}

	let commitment = mmr.signed_commitment.commitment.clone();

	// Pick the authority set the commitment claims to be signed under, then judge
	// participation against that set alone.
	let authority_set = if commitment.validator_set_id == trusted_state.current_authorities.id {
		&trusted_state.current_authorities
	} else if commitment.validator_set_id == trusted_state.next_authorities.id {
		&trusted_state.next_authorities
	} else {
		return Err(Error::UnknownAuthoritySet { id: commitment.validator_set_id });
	};

	if !check_participation_threshold(signatures_length as u32, authority_set.len) {
		return Err(Error::SuperMajorityRequired);
	}

	let mmr_root_data = commitment
		.payload
		.get_raw(&MMR_ROOT_PAYLOAD_ID)
		.ok_or(Error::MmrRootHashMissing)?;

	if mmr_root_data.len() != 32 {
		return Err(Error::InvalidMmrRootHashLength { len: mmr_root_data.len() });
	}
	let mmr_root = H256::from_slice(mmr_root_data);

	let commitment_hash = H::keccak256(&commitment.encode());
	let mut authority_leaves: Vec<[u8; 32]> = Vec::new();
	let mut authority_indices = Vec::new();

	for sig in mmr.signed_commitment.signatures.iter() {
		let uncompressed = H::secp256k1_recover(&commitment_hash.0, &sig.signature)
			.map_err(|_| Error::FailedToRecoverPublicKey)?;

		let hashed_uncompressed = H::keccak256(&uncompressed);

		let mut eth_address = [0u8; 20];
		eth_address.copy_from_slice(&hashed_uncompressed.as_ref()[12..]);

		let authority_address_hash = H::keccak256(&eth_address);

		authority_leaves.push(authority_address_hash.into());
		authority_indices.push(sig.index as usize);
	}

                && commitment.validatorSetId != trustedState.nextAuthoritySet.id
