### Title
Missing "response already received" guard lets a `GetRequest` be timed out on the EVM host after its response was already delivered - (File: evm/src/core/HandlerV2.sol)

### Summary
`EvmHost.dispatchIncoming(GetResponse, relayer)` delivers a `GetResponse` to the originating module and pays the relayer fee, but never clears `_requestCommitments[commitment]` afterward. `HandlerV2.handleGetRequestTimeouts` later allows a `GetRequestTimeout` to be dispatched for the same commitment as long as `_requestCommitments` still has a non-zero `sender`, with no check that a response was already delivered. This mirrors a use-after-free class of bug: state that should have been "freed" once the request's lifecycle completed (response delivered) is left live and is reused to drive a conflicting second lifecycle event (timeout) against the same logical object.

### Finding Description
When a `GetRequest` originated from this EVM host receives its response, `dispatchIncoming(GetResponse, ...)` runs: [1](#0-0) 
It sets `_responseReceipts[commitment]`, invokes `onGetResponse` on the source module, and pays the relayer fee out of `_requestCommitments[commitment].fee` — but it never deletes `_requestCommitments[commitment]`. That mapping entry, keyed by the request commitment, remains populated indefinitely after a successful response.

Separately, `HandlerV2.handleGetRequestTimeouts` allows a relayer to submit a non-membership proof (against a Hyperbridge/Polkadot state height) and dispatch a timeout for any `GetRequest` whose `_requestCommitments` entry is still populated: [2](#0-1) 
The only guards are: the request is past its timeout timestamp relative to the *proof height's* timestamp, `meta.sender != address(0)`, and a non-membership proof of a response receipt key at that specific state height. None of these checks reference `host.responseReceipts(commitment)` — the EVM host's own record that the response has already been delivered locally. Once the check passes, `EvmHost.dispatchTimeOut` is invoked: [3](#0-2) 
which deletes `_requestCommitments[commitment]` and calls `onGetTimeout` on the original requesting module — a second, conflicting lifecycle callback for a request the module already handled via `onGetResponse`.

Contrast this with the Substrate ISMP core implementation, which explicitly guards against this exact scenario before processing a `Get` timeout: [4](#0-3) 
There is no equivalent `response_receipt`/`responseReceipts` check in the EVM `HandlerV2.handleGetRequestTimeouts` path, so the EVM implementation is missing the analogous defense that the Rust implementation already has.

### Impact Explanation
Any `IApp` module built on top of `EvmHost` that dispatches `GetRequest`s and relies on receiving exactly one terminal callback (`onGetResponse` XOR `onGetTimeout`) per request can be driven into an inconsistent state: it may release escrowed funds, mark an intent/order filled, or credit a balance on `onGetResponse`, and then receive a spurious `onGetTimeout` for the same request afterward, potentially causing it to also execute failure/refund logic for a request that already succeeded. Depending on the module's bookkeeping, this can lead to double-crediting, incorrect accounting, or fund loss/freezing in apps (token bridges, intent solvers) that treat `onGetTimeout` and `onGetResponse` as mutually exclusive, single-fire events — a state-confusion vulnerability of the same class as reusing a freed object.

### Likelihood Explanation
This is triggerable by any relayer able to produce a valid non-membership proof of a response-receipt key at some Hyperbridge state height whose timestamp is past the request's timeout — this does not require the response to be absent from the *destination* host's actual bookkeeping, only absent from the specific trie key checked at the chosen height, which is plausible for a request whose response arrived on the EVM host through the MMR/response path independently of that particular trie commitment. No privileged role is required; a permissionless relayer can submit `handleGetRequestTimeouts` for a request it can observe was already fulfilled.

### Recommendation
In `EvmHost.dispatchIncoming(GetResponse, ...)`, delete `_requestCommitments[commitment]` once the response has been successfully delivered (mirroring the pattern already used in `dispatchTimeOut`), and/or add an explicit check in `HandlerV2.handleGetRequestTimeouts` (and/or `EvmHost.dispatchTimeOut` for `Get`) that `host.responseReceipts(commitment).relayer == address(0)` before allowing the timeout to proceed, matching the guard already present in `modules/ismp/core/src/handlers/timeout.rs`.

### Proof of Concept
1. Module `M` on `EvmHost` dispatches a `GetRequest` via `dispatch(DispatchGet)`, creating `_requestCommitments[commitment]`.
2. A relayer submits a valid `GetResponseMessage` for this request; `HandlerV2.handleGetResponses` → `EvmHost.dispatchIncoming(GetResponse, relayer)` succeeds, invoking `M.onGetResponse(...)`. `_requestCommitments[commitment]` is **not** cleared.
3. After the request's `timeout` timestamp elapses, the relayer (or anyone) obtains/constructs a non-membership proof of the response-receipt key at some qualifying Hyperbridge state height and calls `HandlerV2.handleGetRequestTimeouts` with this request.
4. The checks (`timeout() > state.timestamp`, `meta.sender != 0`, non-membership proof) all pass because none of them consult `EvmHost._responseReceipts`. `EvmHost.dispatchTimeOut` executes and calls `M.onGetTimeout(...)` — a second, contradictory terminal callback for a request `M` already resolved in step 2.     function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
