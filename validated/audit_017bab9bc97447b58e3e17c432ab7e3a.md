### Title
Debt-value multiplication can overflow before the borrow-index cap and permanently freeze a market - (File: common/src/rates/index.rs)

### Summary
Interest accrual multiplies aggregate scaled debt by the newly capped borrow index without using a saturating or index-limit-aware conversion. When `borrowed * new_borrow_index` exceeds `i128::MAX`, the call panics before the capped index is committed. Because every market operation accrues interest before repayment, withdrawal, liquidation, or bad-debt cleanup, the first overflow permanently blocks recovery paths for that market.

### Finding Description
`accrue_step` caps the proposed borrow index at `MAX_BORROW_INDEX_RAY`, but `calculate_supplier_rewards` subsequently computes `borrowed.mul(env, new_borrow_index)` using the non-saturating `Ray::mul` path. [1](#0-0) [2](#0-1) 

The effective arithmetic ceiling is therefore not the configured index ceiling, but `i128::MAX / borrowed`. A sufficiently large debt book overflows while the capped borrow index is still below `MAX_BORROW_INDEX_RAY`. The repository's regression test demonstrates this state: a 1-billion-whole-token, 18-decimal market at sustained high utilization fails inside `scaled_to_original` before the index cap engages. [3](#0-2) 

All pool position legs call `load_leg`, which calls `synced_market`, which calls `interest::global_sync` before performing the requested operation. [4](#0-3)  Withdrawal, repayment, and other controller-facing operations consequently reach the same overflowing accrual before they can reduce debt or remove collateral.

### Impact Explanation
The market suffers permanent freezing of user funds. Suppliers cannot withdraw, borrowers cannot repay, liquidators cannot liquidate, and bad-debt cleanup cannot proceed because each path panics during mandatory accrual. [5](#0-4) 

The repository test explicitly verifies that, after the overflow, both withdrawal and repayment fail with `MathOverflow`. [6](#0-5) 

### Likelihood Explanation
This is a medium-likelihood, market-scale-dependent condition. It requires a very large scaled-debt total and enough elapsed time or interest growth for `borrowed * borrow_index` to cross the `i128` boundary. However, the vulnerable operation is an aggregate market total rather than a per-position limit, and once ordinary activity has brought the market near the boundary, any unprivileged caller can trigger the freeze through the public controller `update_indexes` path.

The documentation acknowledges that valid caps and bounded indexes do not ensure that future accrued values fit the RAY domain and that overflow can block repayment and withdrawal. [7](#0-6) 

### Recommendation
Prevent aggregate debt-value evaluation from overflowing during accrual:

- Detect `borrowed * proposed_index > i128::MAX` before calling non-saturating `Ray::mul`.
- Reduce the borrow index to `floor(i128::MAX / borrowed)` before committing it, or otherwise cap the index below the value-overflow boundary.
- Keep the resulting index below both `MAX_BORROW_INDEX_RAY` and the aggregate-value safety bound.
- Apply equivalent protection to aggregate supplied-value calculations and protocol-fee/reward calculations.
- Add a regression test proving that repayment, withdrawal, liquidation, and `clean_bad_debt` remain callable when the proposed index reaches either configured or arithmetic limits.

### Proof of Concept
```rust
// Preconditions:
// - An 18-decimal market with permissive supply and borrow caps.
// - Interest-rate parameters capable of sustained high-utilization growth.
// - The attacker controls enough collateral and tokens, or the market already
//   contains comparable organic supply/debt.

// 1. Build the vulnerable market state.
Controller::supply(
    caller = supplier,
    account_id = 0,
    spoke_id = spoke,
    assets = vec![
        (debt_asset,   1_000_000_000 * 10^18),
        (collateral,   sufficient_collateral),
    ],
);

Controller::borrow(
    caller = borrower,
    account_id = debt_account,
    borrows = vec![(debt_asset, approximately_98_percent_of_supply)],
    to = Some(borrower),
);

// 2. Allow the borrow index to grow until:
//    borrowed_shares * proposed_borrow_index > i128::MAX
//    while proposed_borrow_index < MAX_BORROW_INDEX_RAY.

// 3. Trigger mandatory accrual.
Controller::update_indexes(vec![debt_asset]);
// Reverts with GenericError::MathOverflow.

// 4. Recovery attempts also accrue first and revert:
Controller::repay(caller, debt_account, vec![(debt_asset, 1)]);
Controller::withdraw(owner, supplier_account, vec![(debt_asset, 1)], None);
Controller::liquidate(liquidator, debt_account, debt_payments, seize_mode);
```

The included test performs this sequence with `principal = BILLION * 10^18`, observes `MathOverflow` from `update_indexes`, then confirms that both `withdraw` and `repay` remain blocked. [8](#0-7)

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
