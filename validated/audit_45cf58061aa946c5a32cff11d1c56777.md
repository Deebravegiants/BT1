Confirmed: `update_cost_per_block` in `modules/pallets/consensus-incentives/src/lib.rs` never triggers reward accrual/checkpointing before rewriting `StateMachinesCostPerBlock`. This mirrors the reported bug class exactly — the analog is valid.

### Title
Changing `StateMachinesCostPerBlock` mid-span retroactively re-prices unrewarded blocks, mispricing relayer rewards - (File: modules/pallets/consensus-incentives/src/lib.rs)

### Summary
`pallet-consensus-incentives` rewards the relayer who submits a `ConsensusMessage` an amount computed as `(LatestHeight - PreviousHeight) * CostPerBlock`, using a persisted watermark (`LastRewardedHeight`) rather than paying out incrementally per block. When governance calls `update_cost_per_block` to change the reward rate, none of the already-elapsed-but-unrewarded block span is settled first, so the entire pending span — accrued under the old rate — is retroactively priced at the new rate the next time a relayer submits a proof. This is the same root cause as the reported `ActivePool.calcPendingSPYield` bug: a rate parameter is mutated without accruing/crystallizing the value that depends on elapsed time under the old rate.

### Finding Description
`calculate_reward` computes the reward for the next relayer to submit a consensus update as: [1](#0-0) 

The baseline (`LastRewardedHeight`) only advances when a reward is actually paid via `process_message`: [2](#0-1) 

`update_cost_per_block` mutates the rate in storage unconditionally, with no accrual/settlement step for the span between `LastRewardedHeight` and the chain's current `latest_commitment_height`: [3](#0-2) 

Because the reward for a given state machine is only realized lazily — at the moment some relayer next delivers a `ConsensusMessage` for it — any block span that has already elapsed but has not yet been claimed is unpriced at the time governance changes `cost_per_block`. The very next relayer to submit a proof for that state machine collects the reward for the *entire* elapsed span (old-rate blocks + new-rate blocks) priced entirely at the new `cost_per_block`, exactly analogous to `calcPendingSPYield` picking up the new `stabilityPoolYieldSplit` for interest that had already accrued under the old split.

### Impact Explanation
- If `cost_per_block` is increased, the relayer who happens to deliver the next consensus update after the change is overpaid for blocks that accrued under the old (lower) rate — a direct treasury drain, since rewards are paid from `T::TreasuryAccount` via `T::Currency::transfer`.
- If `cost_per_block` is decreased, relayers are underpaid for blocks that accrued under the old (higher) rate, which can silently starve relayer incentives for stretches of already-elapsed downtime that were priced when the rate was higher.
- Because this is a lazy, watermark-based accrual (not a per-block payout), the magnitude of the mispricing scales with how long a state machine goes without a consensus update relative to when governance changes the rate — potentially the entire backlog since the last update, not just one block.
- This is reachable by any unprivileged relayer simply by submitting (or timing the submission of) a `ConsensusMessage`; the attacker does not need to control governance, only to observe a rate change and race to be the one who "closes" the pending span.

### Likelihood Explanation
Governance rate changes to `StateMachinesCostPerBlock` are an expected, routine operation (the pallet's whole purpose is tunable per-chain incentive rates). Any relayer monitoring events can watch `StateMachineCostPerBlockUpdated` and, if the new rate is higher than the old one, is economically incentivized to be the very next one to deliver a consensus proof for that chain in order to capture the entire pending backlog at the inflated rate — a realistic, low-cost race condition rather than a contrived edge case.

### Recommendation
Before applying a new `cost_per_block` in `update_cost_per_block` (and `remove_incentives`), settle/checkpoint the pending reward span for that `state_machine_id` at the *old* rate: read `latest_commitment_height`, compute the reward for `(latest_commitment_height - LastRewardedHeight)` at the current `cost_per_block`, advance `LastRewardedHeight` to `latest_commitment_height`, and only then update the stored rate. This ensures every block span is always priced at the rate that was in effect when it elapsed, mirroring the "must accrue before changing it" fix pattern from the referenced report.

### Proof of Concept
1. Governance sets `StateMachinesCostPerBlock[SM] = 1` via `update_cost_per_block`; `LastRewardedHeight[SM]` is unset (defaults to `previous_commitment_height`).
2. Time passes; the state machine's `latest_commitment_height` advances by 1,000,000 blocks without any relayer submitting a `ConsensusMessage` for it (no reward claimed yet — nothing forces prompt claiming).
3. Governance calls `update_cost_per_block(SM, 100)` to raise the per-block rate, intending the new rate to apply going forward only. [4](#0-3) 
4. Any relayer submits the next `ConsensusMessage` (any valid proof for `SM`) and triggers `on_executed` → `process_message` → `calculate_reward`. [5](#0-4) 
5. `calculate_reward` computes `blocks = 1,000,000` (the entire pre-rate-change span, since `LastRewardedHeight` was never advanced) multiplied by the **new** `cost_per_block = 100`, instead of `1` — a 100x overpayment funded entirely from `TreasuryAccount`, collected by whichever relayer happened to submit first after the governance change. 	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}

		/// Update cost per block for a state machine
		#[pallet::call_index(0)]
		#[pallet::weight(T::WeightInfo::update_cost_per_block())]
		pub fn update_cost_per_block(
			origin: OriginFor<T>,
			state_machine_id: StateMachineId,
			cost_per_block: <T as pallet_ismp::Config>::Balance,
		) -> DispatchResult {
			T::IncentivesOrigin::ensure_origin(origin)?;

			StateMachinesCostPerBlock::<T>::mutate(state_machine_id.clone(), |maybe_cost| {
				*maybe_cost = Some(cost_per_block);
			});

			Self::deposit_event(Event::<T>::StateMachineCostPerBlockUpdated {
				state_machine_id,
				cost_per_block,
			});

			Ok(())
		}
