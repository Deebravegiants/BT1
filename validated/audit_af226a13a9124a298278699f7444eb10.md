### Title
Stale collateral positions can shield underwater accounts from liquidation - (File: `contracts/controller/src/positions/supply.rs`)

### Summary
`supply` can add a new collateral position without requiring that asset’s oracle price to be fresh and usable. Once the position exists, account-wide risk evaluation requires every collateral and debt asset price, so a single stale collateral leg makes `liquidate`, `clean_bad_debt`, and debt-checked `withdraw` revert with `PriceFeedStale`. An unprivileged borrower can therefore add a stale-asset dust leg to their own account and temporarily prevent liquidation while their real collateral deteriorates or debt accrues. [1](#0-0) 

### Finding Description
`process_supply` accepts an authenticated caller’s deposits, transfers the assets to the pool, merges each result, and persists the supply side without running the post-pool solvency gate used by `withdraw`. [2](#0-1) [3](#0-2) 

During supply merging, `merge_supply_leg` calls `refresh_supply_risk_params`, but that function only loads account prices when the refreshed liquidation tuple favors a liquidator and the account has debt. [4](#0-3) [5](#0-4)  Consequently, adding a new position can succeed without a valid price for that asset when no gated risk refresh is needed. [6](#0-5) 

Subsequent liquidation planning evaluates all stored supply and borrow positions together and requires a cached strict price for each asset. [7](#0-6) [8](#0-7)  Strict aggregator reads convert stale observations into `PriceFeedStale`, rather than returning a usable old price. [9](#0-8) [10](#0-9) 

The existing regression test demonstrates the exact sequence: Alice has USDC collateral and ETH debt, adds `0.001` WBTC while its Reflector observation is one hour old, then becomes underwater after USDC reprices. [11](#0-10)  The identical account then rejects `liquidate`, `clean_bad_debt`, and even withdrawal with `PRICE_FEED_STALE`, while a comparison account without the stale WBTC leg is liquidated normally. [12](#0-11) 

### Impact Explanation
A borrower can temporarily block third-party liquidation and bad-debt cleanup of their own underwater account by maintaining a collateral position whose feed is stale. [13](#0-12) [14](#0-13) 

The shield lasts only until the stale feed produces a fresh usable observation, but the delay can allow interest accrual or further collateral decline to deepen insolvency before liquidation becomes possible again. [15](#0-14)  This is a temporary freezing-of-liquidation impact and can contribute to protocol insolvency during an extended feed outage.

### Likelihood Explanation
The path is reachable by an ordinary account owner through `supply(caller, account_id, spoke_id, assets)`; third parties cannot create a new leg for another account, but an attacker can deliberately create and poison their own leveraged account. [16](#0-15) 

Likelihood is bounded because the attacker needs a listed asset whose oracle is already stale, and normal operation resumes as soon as that asset returns a fresh price. [17](#0-16)  The issue does not let the attacker choose an arbitrary stale timestamp or use an old price as valid collateral; it turns a fail-closed feed into a liquidation shield.

### Recommendation
When `supply` would create a new supply position on an account that has debt, require a strict aggregator `prices` result for the candidate asset before crediting it. Alternatively, use `quotes` and reject `valid=false` or `stale=true` for new collateral admission, while retaining softer handling for existing debt-free deposits. Relevant insertion points are `process_deposit` before `pool_supply_call`, or the new-position branch of `merge_supply_leg`. [18](#0-17) [19](#0-18) 

### Proof of Concept
The repository already contains a direct reproduction in `tests/test-harness/tests/controller/audit_supply_stale_shield.rs`:

1. Alice supplies USDC and borrows ETH. [20](#0-19) 
2. WBTC’s Reflector timestamp is moved one hour into the past. [21](#0-20) 
3. Alice successfully supplies `0.001` WBTC, creating a nonzero collateral leg despite the stale feed. [22](#0-21) 
4. USDC is repriced downward, making the account liquidatable. [23](#0-22) 
5. `liquidate`, `clean_bad_debt`, and `withdraw` all revert with `PRICE_FEED_STALE`. [24](#0-23) 
6. After WBTC receives a fresh price, the same liquidation succeeds. [17](#0-16)

    caller: &Address,
    account_id: u64,
    spoke_id: u32,

    let aggregated = payments::aggregate_positive_payments(env, assets);
    let mut cache = Context::new(env);

    let (acct_id, mut account) = account::load_or_create_account(

        account::AccountGuard::Supply,
        &mut cache,
    );

    require_third_party_existing_supply(env, account_id, acct_id, caller, &account, &aggregated);

    process_deposit(env, caller, &mut account, &aggregated, &mut cache);

    finalize_position_flow(
        env,
        acct_id,
        &account,
        &mut cache,
        PositionSides::Supply,
        false,
    );

        {
            return Some(OracleError::SanityBoundViolated);
        }
        None
    }

enum BadDebtGate {
    /// Permissionless: insolvent *and* collateral at or below the dust threshold.
    DustCapped,
    /// Owner-only: insolvent alone, with no cap on the collateral left behind.
    InsolventOnly,

/// Requires open debt and the selected insolvency gate, then cleans up the account.
fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    let keyed = PriceAggregatorClient::new(env, &aggregator).prices(&token_keys(env, assets));
    let mut out = Map::new(env);

            None => panic_with_error!(env, OracleError::OracleNotConfigured),
        }
    }
    out
