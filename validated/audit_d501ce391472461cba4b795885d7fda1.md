### Title
NULL Pointer Dereference in Vault `PublicKeyGet` Gateway Handler via Missing `params` Field - (File: `core/capabilities/vault/gw_handler.go`)

### Summary
`GatewayHandler.HandleGatewayMessage` routes `MethodPublicKeyGet` requests directly to `handlePublicKeyGet` without first passing them through `GatewayVaultRequestProcessor.ProcessRequest`, which is the only place that validates `req.Params != nil` for the other vault methods. `handlePublicKeyGet` then dereferences `*req.Params` unconditionally, so a request with a missing/null `params` field triggers a nil-pointer dereference panic, analogous to the NULL pointer dereference bug class in CVE-2019-7153 (crash caused by processing a crafted/incomplete input without validating a required field before use).

### Finding Description
In `HandleGatewayMessage`, all vault methods except `MethodPublicKeyGet` are routed through `h.requestProcessor.ProcessRequest`, whose per-method implementations (`processCreateSecretsRequest`, `processUpdateSecretsRequest`, `processDeleteSecretsRequest`, `processListSecretIdentifiersRequest`) all explicitly check `if req.Params == nil` before touching the params bytes: [1](#0-0) 

`MethodPublicKeyGet`, however, bypasses this pipeline entirely: [2](#0-1) 

and is handled directly by `handlePublicKeyGet`, which unmarshals `*req.Params` with no nil check: [3](#0-2) 

If `req.Params` is `nil` (i.e., the JSON-RPC request omits the `params` field, which is legal per the `jsonrpc.Request[json.RawMessage]` type and is only rejected inside `ProcessRequest`, not before), dereferencing `*req.Params` panics with a nil-pointer dereference.

This handler is invoked from the connector's read loop with no `recover()` wrapping: [4](#0-3) 

An unrecovered panic in this goroutine crashes the node process outright, since Go panics that escape a goroutine terminate the whole program.

### Impact Explanation
Any client able to reach the Gateway (the internet-facing entry point relaying vault JSON-RPC requests down to DON nodes) can send a `public_key_get` request with no `params` field. Because this method requires no prior authentication/authorization step (it deliberately skips `ProcessRequest`), an unprivileged, unauthenticated actor can crash the node's Vault gateway-connector goroutine/process, resulting in denial of service to the vault capability (and potentially the whole node process, since unrecovered panics in Go terminate the process by default). This matches the "Impact: High Availability" characterization of CVE-2019-7153 (CVSS `A:H`), where a NULL pointer dereference on unvalidated input caused a crash/DoS.

### Likelihood Explanation
Likelihood is high for reachability (no authentication barrier for this particular method) but the trigger condition is very simple: a single malformed request with an omitted `params` field. This requires no special privileges, matching "unprivileged-actor" analog criteria, and is trivially reproducible.

### Recommendation
Add an explicit `req.Params == nil` check at the top of `handlePublicKeyGet` (and defensively in `handleSecretsCreate`, `handleSecretsUpdate`, `handleSecretsDelete`, `handleSecretsList` as belt-and-suspenders, since they currently rely solely on `ProcessRequest` having already validated/re-marshaled params) before dereferencing, returning a `api.UserMessageParseError`/`api.InvalidParamsError` response instead of panicking. Additionally, consider wrapping `HandleGatewayMessage` dispatch (or the connector's `readLoop`) in a `recover()` to prevent any single malformed gateway message from crashing the entire node process.

### Proof of Concept
1. As an unprivileged client, submit a JSON-RPC request to the Gateway that gets routed to a node's Vault `GatewayHandler` with:
```json
{"jsonrpc":"2.0","id":"1","method":"vault_publicKeyGet"}
```
(note: no `params` field, so `req.Params` decodes to `nil`).
2. `HandleGatewayMessage` matches `case vaulttypes.MethodPublicKeyGet` and calls `h.handlePublicKeyGet(ctx, gatewayID, req)` directly (`gw_handler.go:207-208`), bypassing `ProcessRequest`'s nil check.
3. `handlePublicKeyGet` executes `json.Unmarshal(*req.Params, r)` (`gw_handler.go:366`) — dereferencing the nil `*json.RawMessage` pointer panics.
4. The panic propagates up through the connector's unrecovered `readLoop` goroutine (`connector.go:277-296`), crashing the node process.

func (h *GatewayHandler) handlePublicKeyGet(ctx context.Context, gatewayID string, req *jsonrpc.Request[json.RawMessage]) *jsonrpc.Response[json.RawMessage] {
	r := &vaultcommon.GetPublicKeyRequest{}
	if err := json.Unmarshal(*req.Params, r); err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.UserMessageParseError, err)
	}

	resp, err := h.secretsService.GetPublicKey(ctx, r)
	if err != nil {
		return h.errorResponse(ctx, gatewayID, req, api.HandlerError, fmt.Errorf("failed to get public key: %w", err))
	}
