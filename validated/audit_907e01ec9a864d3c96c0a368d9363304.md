### Title
Webhook shop-domain header is trusted for tenant routing without being covered by the HMAC signature - (File: `lib/shopify_api/webhooks/request.rb`)

### Summary
`ShopifyAPI::Webhooks::Request` exposes a `shop` attribute that is read directly from the `x-shopify-shop-domain` / `shopify-shop-domain` HTTP header, but the HMAC signature that `ShopifyAPI::Utils::HmacValidator` verifies only covers the raw request body. `Webhooks::Registry.process` passes this unauthenticated `shop` value straight into the `WebhookMetadata` object handed to the app's webhook handler, so the tenant identity used downstream is never bound to the cryptographic proof of authenticity.

### Finding Description
`Request#to_signable_string` returns only `@raw_body`: [1](#0-0) 

`Request#shop` is parsed from a header that is never included in that signable string: [2](#0-1) [3](#0-2) 

`HmacValidator.validate` computes the HMAC over `verifiable_query.to_signable_string` (i.e. the body only) and compares it with the `hmac` header value: [4](#0-3) 

`Registry.process` only gates on this HMAC check, then forwards `request.shop` — the unauthenticated header value — as the tenant identity into the handler: [5](#0-4) 

The identity binding that should hold is:
`shop asserted to the handler == shop that Shopify's HMAC actually vouches for`

Because the HMAC only binds `raw_body`, this equality is never enforced — `shop` is a field "acted on" (used for tenant routing/attribution in `WebhookMetadata`) but not covered by the HMAC.

### Impact Explanation
An attacker who operates their own shop with the app installed will receive genuine webhooks with a valid HMAC computed by Shopify over the body using the app's real secret. Because the signature does not cover the shop-domain header, the attacker can replay that exact body/HMAC pair while substituting the `x-shopify-shop-domain` header with an arbitrary victim shop domain. The gem's `HmacValidator.validate` will still report success (it only checks the untouched body), and `Registry.process` will hand the app's handler a `WebhookMetadata` claiming the event originated from the victim shop. Any application logic that trusts `WebhookMetadata#shop` for tenant lookup/routing (the documented purpose of this field) will then apply attacker-controlled body content under the victim's tenant context — a cross-tenant identity-binding bypass.

### Likelihood Explanation
Exploitation requires the attacker to already have a legitimate app installation (to obtain one authentic signed payload) but requires no access to `api_secret_key`, no privileged account beyond their own shop, and no TLS interception — only the ability to replay/modify HTTP headers of a request they legitimately received, which any unprivileged app-installer can do.

### Recommendation
Include the shop domain (and other identity-relevant headers such as topic/webhook-id) in the value that is HMAC-verified, or otherwise cryptographically bind the header to the body before trusting it, so that `Registry.process`/`WebhookMetadata` cannot be handed a shop value that wasn't part of what Shopify actually signed.

### Proof of Concept
1. Attacker installs the app on `attacker-shop.myshopify.com` and receives a real webhook: body `B`, `x-shopify-hmac-sha256: H` (valid signature of `B`), `x-shopify-shop-domain: attacker-shop.myshopify.com`.
2. Attacker resends the identical request to the app's webhook endpoint but changes only the header to `x-shopify-shop-domain: victim-shop.myshopify.com`, leaving body `B` and `H` untouched.
3. `Utils::HmacValidator.validate` recomputes HMAC over `raw_body == B`, which still equals `H`, so validation passes. [6](#0-5) 
4. `Registry.process` builds `WebhookMetadata.new(... shop: request.shop ...)` with `shop == "victim-shop.myshopify.com"`, even though that value was never authenticated. [7](#0-6)

          if result || Context.old_api_secret_key.nil? || T.must(Context.old_api_secret_key).empty?

        def validate_signature(verifiable_query, secret)
          received_signature = verifiable_query.hmac
          computed_signature = compute_signature(verifiable_query.to_signable_string, secret)
          OpenSSL.secure_compare(computed_signature, T.must(received_signature))
        end
