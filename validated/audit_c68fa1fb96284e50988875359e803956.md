Audit Report

## Title
CORS wildcard-origin allowlist bypass via missing-dot suffix match in gateway HTTP server - (File: `core/services/gateway/network/httpserver.go`)

## Summary
The gateway's public-facing HTTP server implements a wildcard-origin CORS allowlist by stripping the `*.` prefix from a configured allowed origin and then checking `strings.HasSuffix(originHost, allowedHost)`. This check does not verify that a `.` separator precedes the matched suffix, so an attacker-registered domain that merely ends with the allowed domain's characters (e.g. `evilethereum.org` matching an allowlist entry for `*.ethereum.org`) is incorrectly treated as a trusted subdomain, allowing CORS trust to be granted to an attacker-controlled origin.

## Finding Description
`isAllowedOrigin` computes the host allowlist match with a bare suffix comparison and no dot-boundary check: [1](#0-0) 

For a configured entry like `https://*.ethereum.org`, `allowedHost` becomes `ethereum.org` after stripping `*.`, and `strings.HasSuffix(originHost, "ethereum.org")` returns `true` for `evilethereum.org`, which is not a subdomain of `ethereum.org` — it's an entirely distinct domain that just shares a trailing byte sequence. The scheme/host/port parsing via `splitURL` performs only lowercasing and `net.SplitHostPort`/`url.Parse`, providing no additional normalization or validation that would prevent this: [2](#0-1) 

This allowlist result directly gates whether the server reflects the `Origin` header into `Access-Control-Allow-Origin`: [3](#0-2) 

No other validation, normalization, or origin canonicalization exists in this path to catch the missing dot-boundary requirement.

## Impact Explanation
When a gateway operator enables `CORSEnabled` and configures a wildcard entry in `CORSAllowedOrigins` (e.g., `*.ethereum.org`), an attacker who registers any domain ending in the allowed suffix without a dot separator (`evilethereum.org`, `notethereum.org`, etc.) will have their origin reflected in `Access-Control-Allow-Origin`. This lets cross-origin JavaScript served from the attacker's domain read gateway responses fetched by a victim's browser under credentialed/session-bound requests — a cross-origin response exposure and access-control bypass, mapping to the "cross-user response corruption"/allowlist-bypass impact category.

## Likelihood Explanation
Exploitation requires only: (1) the gateway operator to configure a wildcard entry in `CORSAllowedOrigins` — a documented, supported configuration feature, not a misuse of the API, and (2) the attacker to register any domain sharing the allowed suffix without a preceding dot, then lure a victim's browser to issue a cross-origin request. No credentials, host access, or race conditions are required, and the vulnerable code executes deterministically on every request carrying a crafted `Origin` header, satisfying reachability from an unprivileged client.

## Recommendation
Fix `isAllowedOrigin` to require a `.` (or exact equality) immediately before the matched suffix:
```go
if strings.HasPrefix(allowedHost, "*.") {
    suffix := allowedHost[1:] // keep the leading dot, e.g. ".ethereum.org"
    if strings.HasSuffix(originHost, suffix) {
        return true
    }
}
```
Add regression tests for adversarial suffix-sharing domains (`evilethereum.org`, `notethereum.org`) to `core/services/gateway/network/httpserver_test.go` to ensure they are rejected while legitimate subdomains (`api.ethereum.org`) still pass.

## Proof of Concept
1. Configure the gateway HTTP server with `CORSEnabled = true` and `CORSAllowedOrigins = ["https://*.ethereum.org"]`.
2. Attacker serves a page from `https://evilethereum.org` performing a cross-origin `fetch()` to the gateway endpoint with `Origin: https://evilethereum.org`.
3. In `handleRequest` → `isAllowedOrigin`, `originHost = "evilethereum.org"`, `allowedHost` (after stripping `*.`) = `"ethereum.org"`, and `strings.HasSuffix("evilethereum.org", "ethereum.org")` returns `true`.
4. The server responds with `Access-Control-Allow-Origin: https://evilethereum.org`, exposing the gateway response to attacker-controlled JavaScript running in the victim's browser context. [4](#0-3)

func (s *httpServer) isAllowedOrigin(origin string) bool {
	originScheme, originHost, originPort, err := s.splitURL(origin)
	if err != nil {
		s.lggr.Debug("error parsing origin URL", err)
		return false
	}
	for _, allowed := range s.config.CORSAllowedOrigins {
		// probably better to do this once when server starts and store it in a map
		// this is an easier solution so we don't have to apply more changes to the code
		// just need to be careful when specifying allowed origins in the config file
		allowedScheme, allowedHost, allowedPort, err := s.splitURL(allowed)
		if err != nil {
			s.lggr.Debug("error parsing allowed origin URL", err)
			continue
		}
		// skip if the scheme doesn't match at all
		if originScheme != allowedScheme {
			continue
		}
		// skip if the port doesn't match at all
		if originPort != allowedPort {
			continue
		}
		// check for exact host match (e.g., remix.com)
		if originHost == allowedHost {
			return true
		}
		// check for wildcard host match (e.g., *.remix.com)
		if strings.HasPrefix(allowedHost, "*.") {
			allowedHost = allowedHost[2:]
			if strings.HasSuffix(originHost, allowedHost) {
				return true
			}
		}
	}
	return false
}
