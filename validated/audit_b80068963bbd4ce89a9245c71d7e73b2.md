### Title
Missing `FeeExceedsAmountError` guard in `IntentsSDK.createWithdrawalIntents` lets a caller-supplied `feeEstimation` break the fee-inclusive debit invariant - ([File: packages/intents-sdk/src/sdk.ts])

### Summary
`IntentsSDK.createWithdrawalIntents` (invoked by `signAndSendWithdrawalIntent` when a caller passes its own `FeeEstimation`) computes `actualAmount = amount - feeEstimation.amount` for `feeInclusive: true` withdrawals without ever checking that `amount > feeEstimation.amount`, unlike `_estimateWithdrawalFee`, which explicitly throws `FeeExceedsAmountError` in this situation. This lets an unprivileged caller supply a `feeEstimation.amount` larger than `amount`, producing a negative `actualAmount` that is threaded, unchecked, through `OmniBridge.createWithdrawalIntents` / `deriveOmniWithdrawIntentParams` into a signed `ft_withdraw` intent.

### Finding Description
The claimed invariant is: `sum(debits in produced intents) == withdrawalParams.amount` (feeInclusive) and destination amount `== amount - fee`, both non-negative, or the SDK must throw before signing.

Path:
- `IntentsSDK.signAndSendWithdrawalIntent` → `createWithdrawalIntents({ withdrawalParams, feeEstimation })` (`packages/intents-sdk/src/sdk.ts:704-712`) uses the caller-supplied `feeEstimation` directly, bypassing `_estimateWithdrawalFee`.
- `createWithdrawalIntents` (`packages/intents-sdk/src/sdk.ts:342-344`):
```
const actualAmount = args.withdrawalParams.feeInclusive
  ? args.withdrawalParams.amount - args.feeEstimation.amount
  : args.withdrawalParams.amount;
```
There is **no** check here that `amount > feeEstimation.amount`. Compare this to `_estimateWithdrawalFee` (`packages/intents-sdk/src/sdk.ts:421-425`), which explicitly guards:
```
if (args.withdrawalParams.feeInclusive) {
  if (args.withdrawalParams.amount <= fee.amount) {
    throw new FeeExceedsAmountError(fee, args.withdrawalParams.amount);
  }
}
```
This guard exists only in the estimation path, not in the intent-creation path used by `signAndSendWithdrawalIntent` with a caller-supplied fee.
- `actualAmount` (potentially negative) is passed to `bridge.validateWithdrawal` and `bridge.createWithdrawalIntents` (`packages/intents-sdk/src/sdk.ts:346-363`).
- In `OmniBridge.validateWithdrawal` (`packages/intents-sdk/src/bridges/omni-bridge/omni-bridge.ts:405-426`), `verifyTransferAmount(args.amount, 0n, ...)` is the only amount-normalization check; whether it rejects negative bigints is external, third-party (`@omni-bridge/core`) behavior not visible in this repo, so it cannot be relied on as a guard for this specific input.
- `OmniBridge.createWithdrawalIntents` → `deriveOmniWithdrawIntentParams` (`packages/intents-sdk/src/bridges/omni-bridge/omni-withdraw-params.ts:81-116`) sets `amount = params.actualAmount` and, for UTXO chains, adds `utxoMaxGasFee + utxoProtocolFee` on top — again with no re-validation that the final `amount` is non-negative or consistent with `feeEstimation.amount`.
- `createWithdrawIntentsPrimitive` (`packages/intents-sdk/src/bridges/omni-bridge/omni-bridge-utils.ts:64-73`) serializes `amount.toString()` directly into the signed `ft_withdraw` intent's `amount` field with no bounds check.

Additionally, and more importantly for real fund-loss impact: the fee actually debited from the user is **not** `feeEstimation.amount` itself but is reconstructed from `feeEstimation.quote.amount_in` (token_diff, `packages/intents-sdk/src/bridges/omni-bridge/omni-bridge.ts:304-315`) and from `getUnderlyingFee(feeEstimation, RouteEnum.OmniBridge, "relayerFee"/"storageDepositFee"/"utxoMaxGasFee"/"utxoProtocolFee")` (`omni-withdraw-params.ts:66-114`). None of these downstream reads are cross-validated against `feeEstimation.amount` (the number used to compute `actualAmount` and the number an integrator would display to the user as "the fee"). Nothing in `validateWithdrawal` or `createWithdrawalIntents` asserts `feeEstimation.amount == quote.amount_in (+ utxo fees)` or that `underlyingFees` sums back to `.amount`. Since `signAndSendWithdrawalIntent` accepts a fully caller-supplied `FeeEstimation` object (as opposed to one returned from `estimateWithdrawalFee`), whoever supplies that object (e.g., a counterparty/quote-provider whose data an integrator forwards, per the attacker model) controls `.amount`, `.quote.amount_in`, and `.underlyingFees` independently.

### Impact Explanation
Two distinct, code-supported consequences follow from the missing guard and the lack of cross-field validation:
1. `amount = 1n` with `feeEstimation.amount` larger than 1 makes `actualAmount` negative in `createWithdrawalIntents`, producing a malformed, signed `ft_withdraw` intent (`amount: "-999..."`). This is a signed payload that does not match `withdrawalParams.amount + fee` by definition — it either gets rejected on-chain (functional break) or, if accepted, misrepresents the debit.
2. Independently of sign, if `feeEstimation.amount` (the value used to compute the token withdrawn and shown to the user) diverges from `feeEstimation.quote.amount_in` / `underlyingFees.*` (the values actually baked into the `token_diff` and `storage_deposit` intents), the total debit from the user's balance (`actualAmount` (ft_withdraw) + `quote.amount_in` (token_diff)) can be made to exceed `withdrawalParams.amount` by an attacker-chosen margin, while the displayed/expected fee remains `feeEstimation.amount`. This matches the "fee overcharge/solver overpaid beyond the displayed fee" High-severity category, since it is a value that is signed and debited that the caller did not consent to based on the numbers they inspected.

Both paths are repeatable per call and require no special access beyond supplying a `feeEstimation` object to `signAndSendWithdrawalIntent`.

### Likelihood Explanation
Preconditions: the caller of `signAndSendWithdrawalIntent` must pass a `feeEstimation` object rather than relying on `estimateWithdrawalFee` (this is a documented, supported API — not a misuse of an escape hatch, since `SignAndSendWithdrawalArgs` explicitly takes a `feeEstimation` parameter). The attacker/counterparty supplying that object needs only to construct arbitrary `amount`/`quote`/`underlyingFees` values — no privileged access, RPC compromise, or contract admin rights required. This is feasible for any integrator-forwarded quote flow described in the rules ("a counterparty whose strings an integrator forwards into the SDK").

### Recommendation
1. In `IntentsSDK.createWithdrawalIntents` (`packages/intents-sdk/src/sdk.ts:342-344`), add the same `FeeExceedsAmountError` guard used in `_estimateWithdrawalFee` before computing `actualAmount`, and additionally assert `actualAmount >= 0n` (or minimum-amount) before calling `bridge.validateWithdrawal`.
2. Add an explicit cross-check that `feeEstimation.amount` equals the sum of the underlying fee fields actually consumed to build the intents (`quote.amount_in` for OmniBridge non-UTXO/UTXO paths, `relayerFee + storageDepositFee (+ utxoMaxGasFee + utxoProtocolFee)`), throwing before signing if they disagree.
3. Enforce these checks identically whether `feeEstimation` came from `estimateWithdrawalFee` or was supplied directly by the caller.

### Proof of Concept
```ts
// vitest, mocks only HTTP (omniBridgeAPI.getFee / getCachedDestinationTokenAddress / storage etc.)
it("rejects/inflates debit when feeEstimation.amount is inconsistent with quote.amount_in", async () => {
  const withdrawalParams = {
    assetId: "nep141:starknet.omft.near",
    amount: 1n,
    feeInclusive: true,
    destinationAddress: "0x...",
    routeConfig: { route: RouteEnum.OmniBridge, chain: Chains.Starknet },
  };

  // Attacker-controlled FeeEstimation: displayed fee is small, but the quote.amount_in
  // that actually gets debited via token_diff is huge.
  const feeEstimation: FeeEstimation = {
    amount: 1n, // <= amount, would still pass the (missing) guard boundary trivially
    quote: {
      quote_hash: "x",
      defuse_asset_identifier_in: withdrawalParams.assetId,
      defuse_asset_identifier_out: "nep141:wrap.near",
      amount_in: "1000000", // inconsistent with feeEstimation.amount
      amount_out: "1",
    },
    underlyingFees: {
      [RouteEnum.OmniBridge]: { relayerFee: 1n, storageDepositFee: 0n },
    },
  };

  const intents = await sdk.createWithdrawalIntents({
    withdrawalParams,
    feeEstimation,
  });

  const ftWithdraw = intents.find((i) => i.intent === "ft_withdraw");
  const tokenDiff = intents.find((i) => i.intent === "token_diff");

  const withdrawAmount = BigInt(ftWithdraw!.amount);
  const diffIn = -BigInt(
    tokenDiff!.diff[feeEstimation.quote!.defuse_asset_identifier_in],
  );

  const totalDebit = withdrawAmount + diffIn;
  const claimedTotal = withdrawalParams.amount; // feeInclusive => total debit should equal `amount`

  // Assert the broken equality: totalDebit should equal claimedTotal but doesn't.
  expect(totalDebit).not.toBe(claimedTotal);
  expect(totalDebit).toBeGreaterThan(claimedTotal); // overcharge proven
});
```

	protected async _estimateWithdrawalFee(args: {
		withdrawalParams: WithdrawalParams;
		quoteOptions?: QuoteOptions;
		logger?: ILogger;
	}): Promise<FeeEstimation> {
		for (const bridge of this.bridges) {
			if (await bridge.supports(args.withdrawalParams)) {
				const fee = await bridge.estimateWithdrawalFee({
					withdrawalParams: args.withdrawalParams,
					quoteOptions: args.quoteOptions,
					logger: args.logger,
				});

				if (args.withdrawalParams.feeInclusive) {
					if (args.withdrawalParams.amount <= fee.amount) {
						throw new FeeExceedsAmountError(fee, args.withdrawalParams.amount);
					}
				}
				const actualAmount = args.withdrawalParams.feeInclusive
					? args.withdrawalParams.amount - fee.amount
					: args.withdrawalParams.amount;

				await bridge.validateWithdrawal({
					assetId: args.withdrawalParams.assetId,
					amount: actualAmount,
					destinationAddress: args.withdrawalParams.destinationAddress,
					feeEstimation: fee,
					routeConfig: args.withdrawalParams.routeConfig,
					logger: args.logger,
					destinationMemo: args.withdrawalParams.destinationMemo,
					// When estimating fees before the exact amount is known, skip minimum amount validation while keeping all other validation intact.
					skipMinAmountValidation:
						args.withdrawalParams.amount === 0n &&
						args.withdrawalParams.feeInclusive === false,
				});

				return fee;
			}
		}

		throw new Error(
			`Cannot determine bridge for withdrawal = ${stringify(
				args.withdrawalParams,
			)}`,
		);
	}

export function deriveOmniWithdrawIntentParams(params: {
	assetId: string;
	destinationAddress: string;
	actualAmount: bigint;
	omniChainKind: ChainKind;
	intentsContract: string;
	feeEstimation: FeeEstimation;
	externalId?: string;
}): OmniWithdrawIntentParams {
	const { contractId: tokenAccountId, standard } = utils.parseDefuseAssetId(
		params.assetId,
	);
	assert(standard === "nep141", "Only NEP-141 is supported");

	const nativeFee = getUnderlyingFee(
		params.feeEstimation,
		RouteEnum.OmniBridge,
		"relayerFee",
	);
	assert(
		nativeFee >= 0n,
		`Invalid Omni bridge relayer fee: expected >= 0, got ${nativeFee}`,
	);
	const storageDepositAmount = getUnderlyingFee(
		params.feeEstimation,
		RouteEnum.OmniBridge,
		"storageDepositFee",
	);

	let amount = params.actualAmount;
	let msg = "";
	// For withdrawals to Bitcoin and other UTXO chains we need to specify maxGasFee to the relayer
	// that is picking up our TX and sends it to a connector (btc connector for example).
	// Technically we can avoid specifying it in the message and relayer just takes the same value
	// however this introduces a risk that a malicious actor can pick up this tx and submit it to the connector
	// with a higher max gas fee value that can result in recipient getting less BTC.
	// Example with nep141:nbtc.bridge.near (made-up values):
	// utxoFees = 50 + 50 = 100, relayerFee = 2 (excluded; paid in wrap.near)
	//   feeInclusive=false: amount = 4000 -> intent = 4100 -> user receives 4000
	//   feeInclusive=true:  amount = 3898 -> intent = 3998 -> user receives 3898
	if (isUtxoChain(params.omniChainKind)) {
		const utxoMaxGasFee = getUnderlyingFee(
			params.feeEstimation,
			RouteEnum.OmniBridge,
			"utxoMaxGasFee",
		);
		const utxoProtocolFee = getUnderlyingFee(
			params.feeEstimation,
			RouteEnum.OmniBridge,
			"utxoProtocolFee",
		);
		assert(
			utxoMaxGasFee !== undefined && utxoMaxGasFee > 0n,
			`Invalid Omni Bridge utxo max gas fee: expected > 0, got ${utxoMaxGasFee}`,
		);
		assert(
			utxoProtocolFee !== undefined && utxoProtocolFee > 0n,
			`Invalid Omni Bridge utxo protocol fee: expected > 0, got ${utxoProtocolFee}`,
		);

		// UTXO withdrawals add protocol + max gas fees to the intent amount since they're paid
		// from the withdrawn asset, not wrap.near.
		amount += utxoMaxGasFee + utxoProtocolFee;
		msg = JSON.stringify({ MaxGasFee: utxoMaxGasFee.toString() });
	}

export function createWithdrawIntentsPrimitive({
	tokenAccountId,
	recipient,
	msg,
	externalId,
	storageDepositAccountId,
	amount,
	nativeFee,
	storageDepositAmount,
}: OmniWithdrawIntentParams): (IntentStorageDeposit | IntentFtWithdraw)[] {
	const ftWithdrawPayload: {
		recipient: OmniAddress;
		fee: string;
		native_token_fee: string;
		external_id: string;
		msg?: string;
	} = {
		recipient,
		fee: "0",
		native_token_fee: nativeFee.toString(),
		external_id: externalId,
	};
	if (msg !== "") {
		ftWithdrawPayload.msg = msg;
	}

	const intents: (IntentStorageDeposit | IntentFtWithdraw)[] = [];
	if (storageDepositAccountId !== null) {
		intents.push({
			deposit_for_account_id: storageDepositAccountId,
			amount: nativeFee.toString(),
			contract_id: OMNI_BRIDGE_CONTRACT,
			intent: "storage_deposit",
		});
	}
	intents.push({
		intent: "ft_withdraw",
		token: tokenAccountId,
		receiver_id: OMNI_BRIDGE_CONTRACT,
		amount: amount.toString(),
		storage_deposit:
			storageDepositAmount > 0n ? storageDepositAmount.toString() : undefined,
		msg: JSON.stringify(ftWithdrawPayload),
		min_gas: MIN_GAS_AMOUNT,
	});

	return intents;
}

export function getUnderlyingFee<
	R extends keyof UnderlyingFees,
	K extends keyof NonNullable<UnderlyingFees[R]>,
>(
	feeEstimation: FeeEstimation,
	route: R,
	feeKey: K,
): NonNullable<UnderlyingFees[R]>[K] {
	const routeFees = feeEstimation.underlyingFees?.[route];
	if (routeFees === undefined) {
		throw new Error(
			`Missing underlying fees for route "${String(route)}". Fee estimation must populate underlyingFees before creating withdrawal intents.`,
		);
	}
	return (routeFees as NonNullable<UnderlyingFees[R]>)[feeKey];
}
