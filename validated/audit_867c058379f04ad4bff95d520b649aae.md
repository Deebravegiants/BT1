Audit Report

## Title
JWT replay-protection check-then-act race in `WorkflowMetadataHandler.Authorize` allows duplicate authorization of a single-use signed workflow-trigger request - (File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go)

## Summary
`WorkflowMetadataHandler.Authorize` verifies a client-signed JWT bound to a JSON-RPC request digest and enforces one-time use via a `jti` replay cache, but the check (`isReplay`) and the commit (`recordUsage`) are two separate, independently-locked critical sections with no lock held across the whole `Authorize` call. Two concurrent requests carrying the identical signed JWT can both pass `isReplay` before either calls `recordUsage`, both being treated as validly authorized, breaking the single-use invariant explicitly documented for the `jti` field.

## Finding Description
`Authorize` is invoked from `httpTriggerHandler.authorizeRequest` for every unprivileged HTTP-trigger request received by the gateway [1](#0-0) . Inside `Authorize`, the JWT is verified, then `h.jwtCache.isReplay(claims.ID)` is checked, and only after the authorized-key lookup succeeds is `h.jwtCache.recordUsage(claims.ID)` called [2](#0-1) . The underlying cache confirms these are two disjoint lock acquisitions: `isReplay` takes an `RLock`, reads, and releases; `recordUsage` separately takes a `Lock` later [3](#0-2) . No mutex spans the full `Authorize` body, so two goroutines invoking `Authorize` concurrently with the same JWT can both observe "not yet used" and both succeed, defeating the single-use guarantee that the `jti` field is documented to enforce.

Downstream, `setupCallback` deduplicates by `req.ID` under `callbacksMu`, which mitigates full double execution when both racing requests share an identical `req.ID` [4](#0-3) , but this is a separate, independent control — it does not fix the authorization-layer race itself, and the report correctly notes uncertainty about whether `Digest()` binds `jti` tightly enough to prevent two distinct `req.ID`s from being authorized by one JWT.

## Impact Explanation
The vulnerability is a genuine TOCTOU/check-then-act race that breaks the intended one-time-use security property of the JWT-based gateway authorization for the HTTP trigger capability, reachable by any unprivileged client capable of sending two concurrent copies of the same signed request (self-triggered or via a duplicating intermediary). At minimum this is a concrete authentication/replay-control bypass at the authorization layer, matching the in-scope "node API authentication or role bypass" / "gateway request impersonation" impact categories. The reporter is appropriately conservative about the more severe scenario (duplicate real workflow execution), acknowledging it depends on `Digest()` internals not available in the index, so the confirmed impact is the replay-control bypass rather than a proven double-fund-movement or double-execution claim.

## Likelihood Explanation
Likelihood is moderate to high: exploitation only requires an unprivileged client to send the identical signed JWT/request twice in quick succession (e.g., two parallel HTTP POSTs), a trivial and readily reproducible action with no special privileges, and the vulnerable gap is present unconditionally on every `Authorize` call, as confirmed by the disjoint locking in `isReplay`/`recordUsage`.

## Recommendation
Make the replay check-and-record atomic by holding a single lock across an "insert-if-absent" operation (e.g., a `ClaimIfUnused(jti string) bool` method on `jwtReplayCache` that checks and inserts under one `Lock()`), and have `Authorize` call this once instead of separate `isReplay` + `recordUsage` calls — ideally reserving the `jti` before performing the more expensive authorized-key lookup so a losing racer fails fast.

## Proof of Concept
1. Sign one `JWTClaims` via `CreateRequestJWT` bound to a specific `jsonrpc.Request`, producing a single JWT with one `jti`.
2. Fire two goroutines that each call `WorkflowMetadataHandler.Authorize(workflowID, tokenString, req)` concurrently with the identical token and request.
3. Both goroutines execute `h.jwtCache.isReplay(claims.ID)` before either calls `h.jwtCache.recordUsage(claims.ID)`, observing `exists == false` and proceeding past the replay check [5](#0-4) .
4. Both calls to `Authorize` return `key, nil`, demonstrating the single-use JWT was accepted twice — contrary to the sequential-replay behavior verified by the existing test `JWT replay protection` in `workflow_metadata_handler_test.go`, which only exercises sequential (non-concurrent) reuse.

	defer h.callbacksMu.Unlock()

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}

func (cache *jwtReplayCache) isReplay(jti string) bool {
	cache.mu.RLock()
	defer cache.mu.RUnlock()

	_, exists := cache.cache[jti]
	return exists
}

func (cache *jwtReplayCache) recordUsage(jti string) {
	cache.mu.Lock()
	defer cache.mu.Unlock()

	cache.cache[jti] = time.Now()
}
