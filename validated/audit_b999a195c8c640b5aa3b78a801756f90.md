### Title
Signup completion callback (`SignupEnded`) never delivered to the paired app after `orb_relay` session establishment, leaving self-serve app sessions permanently unconfirmed — (File: `src/plans/mod.rs`)

### Summary
This is the strongest reachable analog to the reported bug class ("callback never invoked after a state-changing operation, leaving the counterpart party stuck/trapped"). In `orb-core`, the analog of an ERC721 mint/transfer is the self-serve signup flow: the orb calls `orb_relay_announce_orb_id` to bind an `orb_relay` session to a specific app instance [1](#0-0) , after which the app expects a `SignupEnded` "callback" message confirming the outcome, exactly as demonstrated in the relay protocol test harness [2](#0-1) .

### Finding Description
The completion notification is only sent from a single code path, `after_signup`, and that function has multiple early-return branches that skip sending `SignupEnded` entirely:

```
async fn after_signup(&mut self, orb: &mut Orb, signup_result: SignupResult) -> Result<()> {
    let SignupResult { capture_start, debug_report, .. } = signup_result;
    if self.skip_pipeline() {
        // This is just to give the UI ring some time to reset.
        sleep(Duration::from_secs(5)).await;
        return Ok(());
    }
    let Some(debug_report) = debug_report else { return Ok(()) };
    ...
    if orb.config.lock().await.self_serve {
        if let Some(relay) = orb.orb_relay.as_mut() {
            relay.send(self_serve::orb::v1::SignupEnded { ... }).await...
        }
    }
    Ok(())
}
``` [3](#0-2) 

Critically, the `skip_pipeline()` short-circuit at the top of `after_signup` executes unconditionally, before the `self_serve`/`orb_relay` notification logic is ever reached [4](#0-3) . Yet the `orb_relay` session binding (the "mint"/"transfer" analog) happens earlier in `do_signup`, driven purely by whether `qr_codes.user_data.orb_relay_app_id` is present — independent of whether the pipeline will later be skipped [5](#0-4) . The `skip_pipeline()`/`signup_extension_config` branch inside `do_signup` sets `result.success = true` and returns immediately without ever populating/clearing state that would trigger the app-facing callback [6](#0-5) .

The result: once an app has been paired to an orb session over `orb_relay` (analogous to a token having been minted/transferred to a smart-contract wallet), certain signup completion paths (`skip_pipeline()` true, or `debug_report` never populated) prevent the `SignupEnded` "callback" from ever being delivered — mirroring the reported issue where `onERC721Received` is never invoked after mint/transfer.

### Impact Explanation
An app that connected via `orb_relay_announce_orb_id` and is waiting on `self_serve::orb::v1::SignupEnded` to determine signup outcome will never receive this message on these paths, leaving the session in permanent limbo from the app's perspective — a cross-signup state bleed risk: the app cannot determine whether it should treat the session as complete, and a subsequent signup attempt could re-use/reconnect the same relay session state (`orb.orb_relay` persists until explicitly reset in `MasterPlan::run`) creating ambiguity about which biometric session a later `SignupEnded` belongs to [7](#0-6) . This matches the "trapped counterpart / missing confirmation callback" bug class, though the concrete confirmed impact is a stuck/ambiguous self-serve session state rather than direct biometric data disclosure or attestation forgery.

### Likelihood Explanation
Reachable in the normal self-serve signup flow whenever `skip_pipeline()` evaluates true or `debug_report` is `None`/absent when `after_signup` runs, both of which are legitimate, unprivileged-user-reachable states in the signup lifecycle (not requiring a malicious operator/peer). This requires no special hardware access and no test-only feature flags to trigger in principle, though I was unable to fully verify every caller/condition of `skip_pipeline()` (its definition wasn't retrieved before the tool budget ended) — this is a limitation in verification, not in the identified control-flow gap itself.

### Recommendation
- **Short term:** Ensure `after_signup` always sends `SignupEnded` to a connected `orb_relay` app session before any early return (including the `skip_pipeline()` branch), so a paired app is never left without a completion signal.
- **Long term:** Decouple relay-session teardown/notification from pipeline-skip logic, and add a session-level timeout/heartbeat on the app side (or a mandatory acknowledgement) so that an orb-relay session cannot outlive its intended signup and bleed into a subsequent one.

### Proof of Concept
1. App scans operator/user QR with `orb_relay_app_id` present and `self_serve` enabled; orb calls `orb_relay_announce_orb_id`, establishing `orb.orb_relay` [1](#0-0) .
2. Signup proceeds into `do_signup`, and `skip_pipeline()` (or `debug_report.signup_extension_config.is_some()`) evaluates true, causing an immediate return with `result.success = true` and no debug report path executed [6](#0-5) .
3. `after_signup` is invoked with this result; the `skip_pipeline()` branch fires first, sleeps 5s, and returns `Ok(())` without ever reaching the `orb.orb_relay` `SignupEnded` send [4](#0-3) .
4. The connected app, following the same wait pattern shown in the relay test harness, blocks indefinitely for a `SignupEnded` message that is never sent [8](#0-7) .

    async fn after_signup(&mut self, orb: &mut Orb, signup_result: SignupResult) -> Result<()> {
        let SignupResult { capture_start, debug_report, .. } = signup_result;
        if self.skip_pipeline() {
            // This is just to give the UI ring some time to reset.
            sleep(Duration::from_secs(5)).await;
            return Ok(());
        }
        let Some(debug_report) = debug_report else { return Ok(()) };

        tracing::info!("After-signup phase");
        dd_timing!("main.time.signup.full_signup", capture_start);

        let signup_status = debug_report.signup_status.clone();

        let enrollment_status = debug_report.enrollment_status.clone();
        let failure_feedback = debug_report.failure_feedback_after_capture_proto();
        Box::pin(self.upload_debug_report(orb, debug_report)).await?;

        if let Some(signup_status) = signup_status {
            Self::ui_complete_signup(orb, &signup_status, enrollment_status);
        }

        if orb.config.lock().await.self_serve {
            if let Some(relay) = orb.orb_relay.as_mut() {
                relay
                    .send(self_serve::orb::v1::SignupEnded {
                        success: signup_result.success,
                        failure_feedback,
                    })
                    .await
                    .inspect_err(|e| tracing::error!("Relay: Failed to SignupEnded: {e}"))?;
            }
        }

        Ok(())
    }
