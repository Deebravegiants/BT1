### Title
Simplex FX filler prices real fills from a raw, un-TWAP'd Uniswap V4 pool spot price, letting an attacker flash-loan-manipulate the pool to extract funder inventory - (File: `sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts`)

### Summary
Simplex's cross-asset ("exotic") pair filling can be configured with no static bid/ask curve at all; instead it prices the trade directly off the current tick of a Uniswap V4 pool the solver itself supplies liquidity for. That instantaneous, single-block spot price is exactly the kind of manipulable input the original Sandclock report (M-08) warns about — a spot AMM price used to value assets with no TWAP and only an optional, static deviation band as protection.

### Finding Description
`UniswapV4FundingPlanner.getExoticTokenPrice` derives the USD price of the exotic token straight from `sdkPool.token0Price`/`token1Price`, which is computed from the pool's current `sqrtPriceX96` read via `getSlot0` on every refresh: [1](#0-0) [2](#0-1) 

This price feeds `FXFiller.resolveLegRates`, which — for a curveless pair whose token0 is a USD stable — takes the venue quote as the actual trading rate used to compute the fill amount for a real order (not just a probe): [3](#0-2) 

The only defense is `checkPriceGuard`, comparing the live pool quote against a static `referencePrice` within `maxDeviationBps` — and this guard is explicitly optional: "The two fields must be set together; omit both to leave the chain unguarded," and even when configured it only bounds deviation from a stale reference, not manipulation cost/depth: [4](#0-3)  The project's own internal flow doc states this directly: "`checkPriceGuard` is the only defense on this path, and it checks deviation from a static reference, not execution cost." [5](#0-4) 

An unprivileged attacker who places a real cross-chain/same-chain intent order routed through this venue-priced pair can, in the same or an adjacent block, flash-loan swap through the solver's own Uniswap V4 pool to push `sqrtPriceX96` (and thus `token0Price`/`token1Price`) away from the true market price, submit their order to be filled at that skewed venue rate, then reverse the swap. Since `computeLegPolicyOutput` linearly extends the manipulated mid across the whole order size with no size/impact term, the attacker can extract solver-funded LP inventory (withdrawn atomically per `planWithdrawalForToken`) at a favorable rate, mirroring the Sandclock PoC pattern of manipulating a spot price used to value assets, executing against it, then reversing the manipulation to bank the difference.

### Impact Explanation
Successful manipulation directly drains the solver's Uniswap V4-funded inventory (real economic loss to the market maker backing user intents) at essentially the attacker's chosen exchange rate, bounded only by an optional static deviation band an operator may or may not configure, and by the target pool's own manipulability (flash-loanable liquidity). This is a concrete theft-of-funds vector against a funding venue that is reachable by any unprivileged order placer, without needing governance, admin, or relayer compromise.

### Likelihood Explanation
Likelihood is Medium: exploitation requires (1) the pool used for `[vault.uniswapV4]` LP funding to be shallow/manipulable relative to available flash-loan liquidity, and (2) the operator to have either left `referencePrice`/`maxDeviationBps` unconfigured or set a wide band. Both are realistic operator-configuration states the codebase explicitly allows ("omit both to leave the chain unguarded"), and the attack requires only submitting an ordinary intent order plus an unrelated on-chain swap — no privileged role needed.

### Recommendation
- Do not price real fills solely off a single-block pool spot price; require a TWAP (time-weighted average, e.g., over multiple blocks) as the primary venue price source, or corroborate with an independent oracle (Chainlink, as already used elsewhere in `SimplexPaymaster._getOraclePrice`).
- Make the price guard (`referencePrice`/`maxDeviationBps`) mandatory whenever `[vault.uniswapV4]` pool-based pricing is enabled, rather than optional, and tighten it to account for pool depth/manipulation cost, not just static deviation.
- Add a price-impact/size term to `computeDirectPoolPriceUsd`/`computeLegPolicyOutput` so large fills against thin liquidity are priced conservatively rather than linearly at the untouched mid.
- Consider a same-block/short-window lock or minimum settlement delay for venue-priced fills sourced from the solver's own LP position, analogous to the report's `_minLockPeriod > 0` recommendation, to blunt atomic flash-loan round-trips.

### Proof of Concept
1. Solver configures a curveless pair (e.g., USDC/CNGN) priced via `[vault.uniswapV4]` with a Uniswap V4 LP position and no `referencePrice`/`maxDeviationBps` guard (an explicitly supported configuration). [6](#0-5) 
2. Attacker flash-loans the stable/exotic token and swaps through the same Uniswap V4 pool the solver's position belongs to, moving `sqrtPriceX96` so `token0Price`/`token1Price` misrepresents the exotic token's true USD value.
3. Attacker places (or has already placed) an intent order on this pair; `FXFiller.resolveLegRates` calls `getVenueUsdPrice` → `UniswapV4FundingPlanner.getExoticTokenPrice`, which reads the now-manipulated `slot0` and returns the skewed price as the fill rate. [7](#0-6) [1](#0-0) 
4. `computeLegPolicyOutput` computes the fill amount at that skewed rate and pays it out from LP inventory withdrawn via `planWithdrawalForToken`. [8](#0-7) 
5. Attacker reverses the initial swap to restore the pool price and repays the flash loan, keeping the difference between the manipulated fill rate and the true market rate.

	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}

	private computeDirectPoolPriceUsd(
		pos: HydratedV4Position,
		sdkPool: V4Pool,
		chain: string,
	): { exoticToken: string; priceUsd: Decimal } | null {
		const usdc = this.configService.getUsdcAsset(chain).toLowerCase()
		const usdt = this.configService.getUsdtAsset(chain).toLowerCase()
		const c0 = pos.currency0.toLowerCase()
		const c1 = pos.currency1.toLowerCase()

		if (c0 === usdc || c0 === usdt) {
			// currency0 is stable → exotic is currency1
			// token1Price = "token0 per token1" = USD per exotic
			return {
				exoticToken: c1,
				priceUsd: new Decimal(sdkPool.token1Price.toFixed(18)),
			}
		}

		if (c1 === usdc || c1 === usdt) {
			// currency1 is stable → exotic is currency0
			// token0Price = "token1 per token0" = USD per exotic
			return {
				exoticToken: c0,
				priceUsd: new Decimal(sdkPool.token0Price.toFixed(18)),
			}
		}

		return null
	}

	private computeLegPolicyOutput(
		inputAmount: bigint,
		inputIsToken0: boolean,
		token0Decimals: number,
		token1Decimals: number,
		/**
		 * Token0 left in the pair's per-order exposure budget, or `null` to price the whole
		 * input unbudgeted. Only a price probe passes `null`: it commits no capital, so there
		 * is no exposure to ration, and a clamped quantity would silently misprice it.
		 */
		remainingToken0: Decimal | null,
		rate: Decimal,
	): { token0Used: Decimal; policyMaxOutput: bigint } | null {
		let legMaxToken0: Decimal
		if (inputIsToken0) {
			legMaxToken0 = new Decimal(formatUnits(inputAmount, token0Decimals))
		} else {
			legMaxToken0 = new Decimal(formatUnits(inputAmount, token1Decimals)).div(rate)
		}

		const token0ForLeg = remainingToken0 === null ? legMaxToken0 : Decimal.min(legMaxToken0, remainingToken0)
		if (token0ForLeg.lte(0)) {
			return null
		}

		let policyMaxOutput: bigint
		if (inputIsToken0) {
			// Output is token1: convert the token0 allocation at the pair rate.
			policyMaxOutput = BigInt(
				token0ForLeg.mul(rate).mul(new Decimal(10).pow(token1Decimals)).floor().toFixed(0),
			)
		} else {
			// Output is token0: pay out the token0 equivalent of the token1 input.
			policyMaxOutput = BigInt(token0ForLeg.mul(new Decimal(10).pow(token0Decimals)).floor().toFixed(0))
		}

		return { token0Used: token0ForLeg, policyMaxOutput }
	}

## Pool-Based Pricing

When **`[vault.uniswapV4]`** lists at least one position, cross-asset pairs without curves derive bid/ask prices from **Uniswap V4 pool state** (current tick). The pool acts as the price oracle instead of a static curve. Note this yields a **single** price used in both directions — a venue-priced pair has no bid/ask spread of its own, so its margin comes from `order.fees` alone.

With Uniswap V4 positions configured, you can **omit** `bidPriceCurve` and `askPriceCurve` on the pair. Pool pricing requires the pair's `token0` to be a USD stablecoin, and same-token pairs always need their curve. The optional **`spreadBps`** field (basis points) sets the slippage tolerance for on-chain LP redemptions; defaults to `50` (0.50%).

Uniswap V4 venue pricing uses pools that pair the exotic token with **USDC or USDT** (addresses from your chain config). When multiple positions exist for the same exotic token on a chain, the most-liquid qualifying pool's price is used.

```toml lineNumbers

[[pairs]]
token0 = "USDC"
token1 = "CNGN"
maxOrderSize = "5000"       # no curves — priced from the pool

[vault.uniswapV4]

<Callout type="info">
Startup validation requires a pricing source per pair: **either** bid/ask price curves, **or** at least one `[vault.uniswapV4]` position. A pair with neither fails validation.
</Callout>

## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.
