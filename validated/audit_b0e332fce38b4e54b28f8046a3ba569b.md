### Title
Unauthenticated TCP listener accepts arbitrary UI-control events into the signup pipeline - (File: src/agents/livestream/upstream.rs)

### Summary
`orb-core`'s livestream agent binds a plaintext TCP listener on `0.0.0.0:9201` and accepts data from the first client that connects, deserializing it directly into `livestream_event::Event` structures with `rkyv::from_bytes` and forwarding them into the orb's rendering/control pipeline. There is no authentication, no TLS, and no check on the connecting peer's identity — any client that can reach port 9201 can inject events. This mirrors the Trail-of-Bits finding about `InjectedProvider.ts` accepting `postMessage` data without validating `event.source`: in both cases, a message-passing endpoint trusts payload content without authenticating who sent it.

### Finding Description
The `Upstream` stream implementation binds and accepts connections unconditionally: [1](#0-0) 

On every poll it accepts any incoming connection (replacing any prior session) and then reads a length-prefixed buffer and deserializes it with `rkyv::from_bytes` into `Vec<livestream_event::Event>` without any authentication step, peer allow-list, or token check: [2](#0-1) [3](#0-2) 

These deserialized `UiEvents` are then dispatched into `livestream::mod.rs`'s event loop, which mutates the live rendering/capture-adjacent state (mirror point, QR-code overlay points, IR focus, IR exposure, target-eye selection): [4](#0-3) 

Just as the Ethereum content-script listener trusted `event.data` because it only checked a guessable `requestId` (not `event.source`), this TCP listener trusts any bytes that arrive on the socket because it performs no authentication of the connecting peer before deserializing and acting on the payload.

### Impact Explanation
The `Event::UiEvents` variants control focus, exposure, mirror point, and target-eye selection — parameters that affect what the biometric capture pipeline sees and records during a signup. An unauthenticated actor with network reachability to port 9201 (e.g., anyone on the same local/network segment as the orb, since the socket binds `0.0.0.0`) could inject arbitrary `Event` values to manipulate these live-capture parameters without any operator or app authorization, independent of the QR/session pairing and identity-binding flow that otherwise governs signup control. This is a concrete instance of an unauthenticated message-passing trust boundary reachable without privilege, matching the report's bug class (accept a message without verifying the sender).

### Likelihood Explanation
Exploitability requires only network-level reach to TCP port 9201 on the orb — no cryptographic secret, session token, or prior pairing is needed, since the listener is a bare `TcpListener::bind("0.0.0.0:9201")` with no TLS/auth handshake before payloads are deserialized and acted upon. This is comparable in difficulty to the original web-based finding (any page/origin can `postMessage`) — here, any network peer can connect and send framed `rkyv` payloads.

### Recommendation
- Require authentication (e.g., mutual TLS or a signed/keyed handshake) before accepting or processing any `Event` payloads on the livestream upstream socket, analogous to validating `event.source` in the browser fix.
- Bind to a loopback/local-only interface, or gate the listener behind an existing authenticated channel (e.g., only accept connections that have first authenticated via the D-Bus/relay session), rather than an open `0.0.0.0` TCP port.
- Validate/authorize each `Event` before applying it to focus/exposure/mirror/eye-target state, and document the authentication requirements for all internal message-passing endpoints, per the long-term recommendation in the original report.

### Proof of Concept
Given network access to the orb's IP on port 9201, an attacker can open a raw TCP connection and send an `rkyv`-serialized `Vec<livestream_event::Event>` (4-byte big-endian length prefix + payload) containing, e.g., a `SetMirrorPoint` or `Focus`/`Exposure` event, causing `Upstream::poll_next` to accept the connection and `EventReader::poll_stream` to deserialize and emit it as `Event::UiEvents`, which `livestream::mod.rs` applies directly to `gpu.app.set_mirror_point`/`set_ir_focus`/`set_ir_exposure` with no authentication check at any point in the chain [5](#0-4) [6](#0-5) .

Note: I could not fully confirm from the index whether the `livestream` feature (which gates this module, per `#[cfg(feature = "livestream")]` usage seen in `src/brokers/orb.rs`) is enabled in default production builds versus only in debug/manual-test tooling; this should be verified directly in `Cargo.toml`/build configuration before treating this as production-reachable, since the index only confirmed the feature name appears in `Cargo.toml` without showing whether it is part of the default feature set used on shipped orbs.

impl Upstream {
    pub async fn new() -> Result<Self> {
        let listener = TcpListener::bind(format!("0.0.0.0:{PORT}")).await?;
        Ok(Self { listener, stream: None })
    }
}

impl Stream for Upstream {
    type Item = Result<Event>;

    fn poll_next(mut self: Pin<&mut Self>, cx: &mut Context<'_>) -> Poll<Option<Self::Item>> {
        if let Some((stream, event_reader)) = &mut self.stream {
            match event_reader.poll_stream(cx, Pin::new(stream)) {
                Poll::Ready(events) => {
                    *event_reader = EventReader::default();
                    match events {
                        Ok(Some(events)) => {
                            return Poll::Ready(Some(Ok(Event::UiEvents(events))));
                        }
                        Ok(None) => {
                            self.stream = None;
                            return Poll::Ready(Some(Ok(Event::Closed)));
                        }
                        Err(err) => return Poll::Ready(Some(Err(err))),
                    }
                }
                Poll::Pending => {}
            }
        }
        match self.listener.poll_accept(cx) {
            Poll::Ready(Ok((stream, addr))) => {
                self.stream = Some((stream, EventReader::default()));
                Poll::Ready(Some(Ok(Event::Connected(addr))))
            }
            Poll::Ready(Err(err)) => {
                Poll::Ready(Some(Err(eyre!("Error accepting connection: {err}"))))
            }
            Poll::Pending => Poll::Pending,
        }
    }
