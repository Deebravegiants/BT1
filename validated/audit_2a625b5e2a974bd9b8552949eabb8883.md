### Title
`Oauth.validate_auth_callback` sends `client_secret` and OAuth `code` to an unvalidated `shop` host derived from the callback query - ([File: lib/shopify_api/auth/oauth.rb])

### Summary
`ShopifyAPI::Auth::Oauth.validate_auth_callback` builds the OAuth token-exchange HTTP request against a base URI derived directly from `auth_query.shop`, without ever passing that value through `Utils::ShopValidator.sanitize!`. Every other credential-sending code path in this gem (`TokenExchange.migrate_to_expiring_token`, and the `shop` used for building request hosts elsewhere) explicitly calls `ShopValidator.sanitize!` before using a caller-supplied `shop` string to build a request host. `validate_auth_callback` is missing this call, so the binding "the shop that authorizes the request equals the shop that receives the `client_secret`" is not enforced by this method itself.

### Finding Description
In `validate_auth_callback`: [1](#0-0) 

the flow is:
1. `Utils::HmacValidator.validate(auth_query)` is checked - this proves `auth_query.shop` (along with `code`, `host`, `state`, `timestamp`) was signed by Shopify with `Context.api_secret_key`, i.e. it proves *integrity*, not that the value is a syntactically-safe host.
2. `null_session = Auth::Session.new(shop: auth_query.shop)` stores the raw HMAC-verified string as `Session#shop` with no format/domain check. [2](#0-1) 
3. `Clients::HttpClient.new(session: null_session, base_path: "/admin/oauth")` builds the request base URI as `"https://#{api_host || session.shop}"`, i.e. directly interpolates `session.shop` into the request host. [3](#0-2) 
4. That client then POSTs `client_id`, `client_secret` (`Context.api_secret_key`), and the OAuth `code` to `https://#{auth_query.shop}/admin/oauth/access_token`. [4](#0-3) 

Compare this to `TokenExchange.migrate_to_expiring_token`, which takes the same kind of input (`shop:`) and explicitly does `validated_shop = Utils::ShopValidator.sanitize!(shop)` before constructing the session that is used to send `client_secret`: [5](#0-4) 

`ShopValidator.sanitize!` is the gem's designated mechanism for confirming a `shop` string is `*.myshopify.com`/`*.myshopify.io`/etc. before it is trusted as a request host: [6](#0-5) 

`validate_auth_callback` never calls it. The `shop == host that receives client_secret` binding it should enforce is:
`sanitize!(auth_query.shop) == host used by HttpClient`
but what is actually enforced is only:
`HMAC(auth_query.shop, ...) == valid signature`,
which is a weaker property (integrity of the bytes, not that the bytes are a safe/expected host format). HMAC validation guarantees the value came from Shopify unmodified, but Shopify's callback redirect itself echoes back the `shop` query parameter that the *app* originally supplied to `begin_auth`/the authorize URL - `begin_auth` also builds `auth_base_uri(shop)` from a raw, unsanitized `shop` argument with no `ShopValidator` call either: [7](#0-6) [8](#0-7) 

So if a host application forwards a request-supplied `shop` string into `begin_auth`/`validate_auth_callback` without separately sanitizing it (which the gem does not enforce or warn about at this layer, unlike `migrate_to_expiring_token`), the value that ultimately becomes both the OAuth-authorize host and the token-exchange host that receives `client_secret` is not constrained by this gem to Shopify's trusted domain list.

### Impact Explanation
If the unsanitized `shop`/`auth_query.shop` value reaches `Clients::HttpClient`, the app's `client_id`, `client_secret`, and the single-use OAuth `code` are POSTed to an attacker-influenced host, which is SSRF carrying the app's credentials (`client_secret`) and can lead to disclosure of the `client_secret`/authorization `code` to a non-Shopify server, and consequently theft of an access token for the shop.

### Likelihood Explanation
Likelihood depends on the host application passing an unsanitized `shop` parameter through to `begin_auth`/`validate_auth_callback`, since Shopify's official documented flow requires apps to validate `shop` themselves before starting OAuth. This gem does provide `Utils::ShopValidator` for exactly this purpose and does apply it in `TokenExchange.migrate_to_expiring_token`, but conspicuously omits it in `Oauth.begin_auth`/`validate_auth_callback`, so the inconsistency is real and the safety net the gem provides elsewhere for credential-sending code paths is absent here.

### Recommendation
In `lib/shopify_api/auth/oauth.rb`, sanitize the `shop` value with `Utils::ShopValidator.sanitize!` in both `begin_auth` (before building `auth_base_uri`) and `validate_auth_callback` (before constructing `null_session`/before sending the token-exchange request), mirroring the pattern already used in `TokenExchange.migrate_to_expiring_token`.

### Proof of Concept
1. Host application receives an inbound request with `shop=attacker-controlled-host.example.com` and, without validating the format itself, calls `ShopifyAPI::Auth::Oauth.begin_auth(shop: params[:shop], ...)`. `auth_base_uri` builds `"https://attacker-controlled-host.example.com/admin/oauth/authorize?..."` with no `ShopValidator` check. [8](#0-7) 
2. If the callback subsequently returns a `shop` value that still resolves to attacker infrastructure (e.g., because the app trusts an echoed non-Shopify-validated parameter, or the flow is otherwise coerced) and the HMAC still validates (attacker cannot forge the HMAC without the secret, but this only proves integrity of whatever string Shopify's authorize endpoint was fed - it does not prove that string is a legitimate `*.myshopify.com` domain), `validate_auth_callback` calls `Auth::Session.new(shop: auth_query.shop)` and `Clients::HttpClient.new(session: null_session, base_path: "/admin/oauth")`. [2](#0-1) 
3. `HttpClient#initialize` sets `@base_uri = "https://#{session.shop}"` and the subsequent `client.request(...)` POSTs `client_id`, `client_secret`, and `code` to `https://attacker-controlled-host.example.com/admin/oauth/access_token`. [3](#0-2)

        def validate_auth_callback(cookies:, auth_query:)
          unless Context.setup?
            raise Errors::ContextNotSetupError, "ShopifyAPI::Context not setup, please call ShopifyAPI::Context.setup"
          end
          raise Errors::InvalidOauthError, "Invalid OAuth callback." unless Utils::HmacValidator.validate(auth_query)
          raise Errors::UnsupportedOauthError, "Cannot perform OAuth for private apps." if Context.private?

          state = cookies[SessionCookie::SESSION_COOKIE_NAME]
          raise Errors::NoSessionCookieError unless state

          raise Errors::InvalidOauthError,
            "Invalid state in OAuth callback." unless state == auth_query.state

          null_session = Auth::Session.new(shop: auth_query.shop)
          body = {
            client_id: Context.api_key,
            client_secret: Context.api_secret_key,
            code: auth_query.code,
            expiring: Context.expiring_offline_access_tokens ? 1 : 0, # Only applicable for offline tokens
          }

          client = Clients::HttpClient.new(session: null_session, base_path: "/admin/oauth")
          response = begin
            client.request(
              Clients::HttpRequest.new(
                http_method: :post,
                path: "access_token",
                body: body,
                body_type: "application/json",
              ),
            )
          rescue ShopifyAPI::Errors::HttpResponseError => e
            raise Errors::RequestAccessTokenError,
              "Cannot complete OAuth process. Received a #{e.code} error while requesting access token."
          end

          session_params = T.cast(response.body, T::Hash[String, T.untyped]).to_h
          session = Session.from(shop: auth_query.shop,
            access_token_response: Oauth::AccessTokenResponse.from_hash(session_params))

        def auth_base_uri(shop)
          return "https://#{shop}/admin" unless defined?(DevServer) && shop.include?(".my.shop.dev")

          # For first-party apps in development only, we leverage DevServer to build the admin base URI

            .new("admin-web")
          admin_host = admin_web.host!(nonstandard_host_prefix: "admin")
          shop_name = shop.split(".").first

          "https://#{admin_host}/store/#{shop_name}"
        end

    module ShopValidator
      TRUSTED_SHOPIFY_DOMAINS = T.let(
        [
          "shopify.com",
          "myshopify.io",
          "myshopify.com",
          "spin.dev",
          "shop.dev",
        ].freeze,
        T::Array[String],
      )

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
