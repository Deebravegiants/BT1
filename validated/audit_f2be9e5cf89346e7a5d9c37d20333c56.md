### Title
Accrued market value overflow permanently freezes pool operations - ([File: common/src/rates/simulate.rs])

### Summary
Interest accrual converts total scaled debt and supply back into RAY-denominated value before updating indexes. Once either product exceeds the `i128` domain, every state-mutating operation that syncs the market aborts with `MathOverflow`. The public `update_indexes` path can trigger the condition, after which repayment, withdrawal, liquidation, further accrual, recapitalization, and revenue operations for that market all attempt the same accrual and fail. [1](#0-0) [2](#0-1) 

### Finding Description
`accrue_step` calls `scaled_to_original` for `borrowed * borrow_index` and `supplied * supply_index`. [3](#0-2) 

`scaled_to_original` delegates to `Ray::mul`, whose half-up multiply-divide widens the intermediate product to `I256` but still requires the final result to fit `i128`; otherwise it returns `None` and panics with `GenericError::MathOverflow`. [4](#0-3) [5](#0-4) 

The stored index caps do not bound the resulting position value: `update_borrow_index` caps only the index, while the market total is `borrowed * index`. [6](#0-5)  Consequently, a market can cross `scaled * index > i128::MAX` while the index remains below `MAX_BORROW_INDEX_RAY` or `MAX_SUPPLY_INDEX_RAY`.

The public controller path forwards `update_indexes(caller, assets)` to the pool. [7](#0-6)  The pool loads each requested market and invokes `global_sync`. [8](#0-7)  `global_sync` calls `accrue_step`, so the same address that supplied or borrowed through normal permissionless controller entrypoints can later invoke `update_indexes` and reach the failing conversion. [9](#0-8) [10](#0-9) 

Every market mutation uses `synced_market`, which runs `global_sync` before the requested operation. [11](#0-10)  `supply`, `borrow`, `withdraw`, `repay`, and other batch operations route through this sync path, so an overflowing market cannot be exited or repaired by the ordinary pool paths. [12](#0-11) 

### Impact Explanation
This is permanent freezing of user funds in the affected hub-asset market. Suppliers cannot withdraw, borrowers cannot repay, liquidators cannot liquidate, and protocol revenue cannot be processed because each operation accrues before performing its own state transition. [13](#0-12) 

The issue is not merely a failed transaction: accrual fails before a new `last_timestamp` or index can be committed, so retrying later encounters the same overflow and additional elapsed time cannot bypass the bad multiplication. [14](#0-13) [15](#0-14) 

The repository’s own harness demonstrates this end state: after the overflow is reached through public accrual, both `withdraw` and `repay` revert with `MATH_OVERFLOW`, and the borrow index remains below its cap. [16](#0-15) 

### Likelihood Explanation
Triggering the condition requires a very large market value and enough elapsed high-rate accrual for an index to make `scaled * index` exceed `i128::MAX`. [17](#0-16)  The token amount itself can remain within the protocol’s admitted cap and decimal domain; the failure occurs later when the accrued market valuation is recomputed. [18](#0-17) 

An attacker cannot unilaterally exceed a configured market cap, so feasibility depends on the deployed cap, token supply, collateral, and rate model. However, once such a market approaches the boundary, any authorized caller can submit `update_indexes` for its `HubAssetKey`; no owner, governance, borrower-specific, or special pool privilege is required at the trigger step. [7](#0-6) 

The regression test uses a billion-whole-token, 18-decimal market at 98% utilization and repeatedly advances time until ordinary public accrual fails. [19](#0-18) 

### Recommendation
Do not compute the market’s total accrued debt or supply as a mandatory `i128` value during synchronization. In `common/src/rates/simulate.rs`, carry utilization calculations in widened arithmetic or derive the ratio from `borrowed / supplied` without materializing either index-scaled total. [1](#0-0) 

For interest assignment, avoid calculating `borrowed * index` directly when the resulting RAY value may exceed `i128`. Possible approaches include widening the interest delta calculation, splitting scaled balances before multiplication, or capping accrual before the unrepresentable market-value boundary while preserving the stored index cap. Any fix must retain conservative debt rounding and avoid silently truncating user claims.

Add a regression path proving that after reaching the market-value boundary, at least `repay`, `withdraw`, `liquidate`, and `recapitalize` remain executable. A full-market arithmetic ceiling should constrain future risk-taking, not prevent exits or solvency repairs. [20](#0-19) 

### Proof of Concept
The existing test establishes a reachable scenario:

1. Configure an 18-decimal market with a steep rate curve and adequate caps.
2. Supply `1_000_000_000 * 10^18` units.
3. Supply sufficient collateral to another account and borrow 98% of the market.
4. Advance ledger time in one-year intervals.
5. Invoke controller `update_indexes(caller, vec![hub_asset])` until `accrue_step` computes `borrowed * borrow_index > i128::MAX`.
6. Subsequent `withdraw` and `repay` calls revert with `MathOverflow`.

The repository test performs those steps and asserts the resulting market freeze. [21](#0-20)

pub fn try_mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> Option<i128> {
    if x < 0 || y < 0 || d <= 0 {
        return None;
    }
    let half = d / 2;

    // Fast path: the biased product fits `i128`, so the whole computation is
    // native. `x * y + half` is non-negative here, so `/` is the floor the
    // widened path would produce.
    if let Some(biased) = x
        .checked_mul(y)
        .and_then(|product| product.checked_add(half))
    {
        return Some(biased / d);
    }

    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    x256.mul(&y256)
        .add(&I256::from_i128(env, half))
        .div(&d256)
        .to_i128()
}

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
