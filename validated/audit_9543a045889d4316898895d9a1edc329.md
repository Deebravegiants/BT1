Based on my investigation, I found a concrete unauthenticated state-mutation endpoint in the chainlink node's HTTP API that is directly analogous to the `setActivePool` authorization gap — a state-changing function reachable without any authentication or role check.

### Title
Unauthenticated Pipeline Run Resume Endpoint Allows Unprivileged State Mutation - (File: core/web/router.go, core/web/pipeline_runs_controller.go)

### Summary
The route `PATCH /v2/resume/:runID` is registered in an unauthenticated router group (`unauthedv2`) and dispatches directly to `PipelineRunsController.Resume`, which lacks any authentication middleware, role check (`RequiresRunRole`/`RequiresEditRole`/`RequiresAdminRole`), or external-initiator verification before mutating pipeline run state and injecting a result payload.

### Finding Description
In `core/web/router.go`, the `v2Routes` function registers the resume endpoint on the unauthenticated group before the authenticated group is even constructed: [1](#0-0) 

Unlike every other mutating route in the same file — which is wrapped with `auth.RequiresRunRole`, `auth.RequiresEditRole`, or `auth.RequiresAdminRole` — this one has zero authorization wrapper of any kind: [2](#0-1) 

The handler itself, `PipelineRunsController.Resume`, performs no session, token, or caller-identity check whatsoever. It only validates that `runID` parses as a UUID and that the request body decodes into a `pipeline.ResumeRequest`, then directly calls `prc.App.ResumeJobV2`: [3](#0-2) 

This flows into `ChainlinkApplication.ResumeJobV2` → `pipeline.Runner.ResumeRun` → `orm.UpdateTaskRunResult`, which updates the task run's output/error and transitions the pipeline run from `suspended` back to `running`, restarting pipeline execution with attacker-supplied `value`/`error` data: [4](#0-3) [5](#0-4) [6](#0-5) 

The only protection is that `runID` (a `taskID` UUID) must be known/guessed by the caller — there is no session, API token, or bridge/EI signature check enforced at the transport layer. This is the same root-cause pattern as the reported `RFPSimpleStrategy.setActivePool` issue: a state-mutating entry point with no access-control gate, relying solely on obscurity of an identifier rather than an authorization mechanism.

### Impact Explanation
An unprivileged network client who obtains or guesses a pending `taskID` (e.g., via log leakage, monitoring endpoints, or a job run that surfaces the ID) can inject arbitrary `value`/`error` results into any suspended pipeline run and force it to resume, potentially completing bridge/webhook-backed pipeline runs (e.g., VRF fulfillment triggers, external adapter callbacks) with attacker-controlled data. This can corrupt job execution results feeding on-chain reports or trigger unintended downstream logic, without requiring any Chainlink node credentials — directly matching "unauthorized job run" and "cross-user response confusion" impact categories.

### Likelihood Explanation
The endpoint is reachable by any client capable of reaching the node's HTTP API without authentication (`unauthedv2` group, no session/token/role middleware). The audit log call even self-identifies this action as `audit.UnauthedRunResumed`, confirming this behavior is a known, named exception to the platform's role-based access control model rather than a false-positive oversight. Exploitability is bounded by needing to know/guess the UUID `taskID`, but no additional secret or credential is enforced.

### Recommendation
Require the caller to present the bridge/external-initiator's shared secret (HMAC signature) or another out-of-band credential bound to the specific `taskID` before accepting a resume request, rather than relying solely on UUID unguessability. At minimum, rate-limit and audit-alert on this endpoint distinctly, and document/verify that `taskID` values are never exposed in logs, error messages, or other externally-reachable surfaces.

### Proof of Concept
1. Obtain a pending async task's `taskID` (UUID) for a suspended pipeline run (e.g., from logs, a leaked bridge callback URL, or by triggering a job with an async bridge task and observing the ID passed to the external adapter).
2. Without any authentication headers, session cookie, or API token, send:
```
PATCH /v2/resume/<taskID> HTTP/1.1
Content-Type: application/json

{"value": "<attacker-controlled-value>"}
```
3. The request succeeds (`200 OK`), the pipeline run transitions to `running`, and the task's output is set to the attacker-supplied value, as confirmed by `PipelineRunsController.Resume` at [7](#0-6)  requiring no caller identity at all.

// Resume finishes a task and resumes the pipeline run.
// Example:
// "PATCH <application>/jobs/:ID/runs/:runID"
func (prc *PipelineRunsController) Resume(c *gin.Context) {
	taskID, err := uuid.Parse(c.Param("runID"))
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	rr := pipeline.ResumeRequest{}
	decoder := json.NewDecoder(c.Request.Body)
	err = errors.Wrap(decoder.Decode(&rr), "failed to unmarshal JSON body")
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	result, err := rr.ToResult()
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	if err := prc.App.ResumeJobV2(c.Request.Context(), taskID, result); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
	c.Status(http.StatusOK)
}

func (r *runner) ResumeRun(ctx context.Context, taskID uuid.UUID, value any, err error) error {
	run, start, err := r.orm.UpdateTaskRunResult(ctx, taskID, Result{
		Value: value,
		Error: err,
	})
	if err != nil {
		return fmt.Errorf("failed to update task run result: %w", err)
	}

	// TODO: Should probably replace this with a listener to update events
	// which allows to pass in a transactionalised database to this function
	if start {
		// start the runner again
		go func() {
			ctx, cancel := r.chStop.NewCtx()
			defer cancel()
			if _, err := r.Run(ctx, &run, false, nil); err != nil {
				r.lggr.Errorw("Resume run failure", "err", err)
			}
			r.lggr.Debug("Resume run success")
		}()
	}
	return nil
}

func (o *orm) UpdateTaskRunResult(ctx context.Context, taskID uuid.UUID, result Result) (run Run, start bool, err error) {
	if result.OutputDB().Valid && result.ErrorDB().Valid {
		panic("run result must specify either output or error, not both")
	}
	err = o.transact(ctx, func(tx *orm) error {
		sql := `
		SELECT pipeline_runs.*, pipeline_specs.dot_dag_source "pipeline_spec.dot_dag_source", job_pipeline_specs.job_id "job_id"
		FROM pipeline_runs
		JOIN pipeline_task_runs ON (pipeline_task_runs.pipeline_run_id = pipeline_runs.id)
		JOIN pipeline_specs ON (pipeline_specs.id = pipeline_runs.pipeline_spec_id)
		JOIN job_pipeline_specs ON (job_pipeline_specs.pipeline_spec_id = pipeline_specs.id)
		WHERE pipeline_task_runs.id = $1 AND pipeline_runs.state in ('running', 'suspended')
		FOR UPDATE`
		if err = tx.ds.GetContext(ctx, &run, sql, taskID); err != nil {
			return fmt.Errorf("failed to find pipeline run for task ID %s: %w", taskID.String(), err)
		}

		// Update the task with result
		sql = `UPDATE pipeline_task_runs SET output = $2, error = $3, finished_at = $4 WHERE id = $1`
		if _, err = tx.ds.ExecContext(ctx, sql, taskID, result.OutputDB(), result.ErrorDB(), time.Now()); err != nil {
			return fmt.Errorf("failed to update pipeline task run: %w", err)
		}

		if run.State == RunStatusSuspended {
			start = true
			run.State = RunStatusRunning

			sql = `UPDATE pipeline_runs SET state = $2 WHERE id = $1`
			if _, err = tx.ds.ExecContext(ctx, sql, run.ID, run.State); err != nil {
				return fmt.Errorf("failed to update pipeline run state: %w", err)
			}
		}

		return loadAssociations(ctx, tx.ds, []*Run{&run})
	})

	return run, start, err
}
