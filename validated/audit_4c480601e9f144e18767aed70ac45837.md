### Title
Cadence-Dependent Interest Accrual: Permissionless `update_indexes` Makes Cumulative Interest Path-Dependent on Sync Frequency - (File: common/src/rates/simulate.rs)

### Summary
XOXNO Lending accrues interest in discrete steps: each `accrue_step` recomputes utilization and the borrow rate, then mints protocol-revenue shares into `supplied` before the next step. Because the permissionless `update_indexes` entrypoint (and every mutating op) commits a new accrual boundary via `global_sync`, the total interest accrued over a fixed wall-clock window depends on how many times sync is invoked — the same path-dependence bug class as the external report, where accrual is not purely a function of elapsed time.

### Finding Description
In `common/src/rates/simulate.rs::accrue_step`, each step:

1. Unscales `borrowed`/`supplied` at the **current** indexes, recomputes `utilization`, and re-derives `borrow_rate` from the curve.
2. Multiplies `borrow_index` by `compound_interest(rate, delta_ms)`.
3. Mints `revenue_shares` that the caller adds to `supplied`, changing the next step's utilization.

`contracts/pool/src/interest.rs::global_sync` splits the gap since `last_timestamp` into chunks of `MAX_COMPOUND_DELTA_MS` (1 year) and runs `accrue_chunk` per chunk, then `mark_accrued()`. `contracts/pool/src/ops/market.rs::accrue` (the `update_indexes` ABI) performs this with **no `require_auth`** — any address can force a sync boundary at millisecond granularity.

The consequence: utilization is re-evaluated at every sync boundary with (a) debt grown by the full accrued interest in the numerator and (b) `supplied` grown only by `revenue_shares` (reserve-factor fraction plus shortfall) in the denominator. Since reserve_factor < 100%, numerator grows faster than denominator, so each additional sync boundary nudges utilization — and therefore the borrow rate — upward for the remainder of the window. Formally, `ΔIndexes(T)` under N syncs differs from a single sync over T:

```
Δborrow_index(T | N syncs) > Δborrow_index(T | 1 sync)   for typical reserve_factor < 100%
```

i.e., accrued interest is a function of **settlement frequency**, not only elapsed time and rate path — the exact invariant the external report flags (`ΔCFI(10h) ≠ Σ ΔCFI(1h)`). The codebase itself documents this: `skills/xoxno-lending/math.md` states "realized index growth depends on update cadence", and `common/src/rates/simulate.rs:129-181` / `tests/fuzz/fuzz_targets/rates_and_index.rs` confirm each chunk re-reads utilization after revenue-share minting.

### Impact Explanation
- **Mis-accrual of interest**: borrowers' debt and suppliers' yield over the same elapsed time differ depending on how often `update_indexes` (or any op calling `global_sync`) is invoked. Users are charged/credited amounts that depend on an attacker-controllable call cadence rather than a protocol-defined accrual schedule.
- **Exploitable amplification**: a large supplier (or any beneficiary of higher accrual) can call `update_indexes` back-to-back each ledger — each call is a fresh sync boundary that re-rates utilization upward — realizing a higher cumulative borrow index than a single end-of-window accrual, extracting extra interest from borrowers. Conversely, actors who benefit from lower accrual cannot prevent others from syncing, so the bias is one-directional toward amplification.
- **Accounting distortion**: PnL, health-factor evolution, and liquidation timing all read the (path-dependent) indexes through `Context::cached_market_index`, so sync-frequency manipulation propagates into risk evaluation.

### Likelihood Explanation
`update_indexes` is permissionless (no auth in `accrue`), and every supply/borrow/withdraw/repay also triggers `global_sync`, so sync boundaries occur at arbitrary, user-influenced times with millisecond resolution. No downtime or privileged action is required; any unprivileged address with gas can add sync boundaries. The per-boundary rate drift is small per step but compounds monotonically in the same direction, so sustained spam over long horizons (low-activity markets accrue for weeks between organic syncs) produces measurable divergence — though the magnitude per call is bounded by the rate-curve slope and the extra compounding term, keeping this at Medium rather than High.

### Recommendation
1. Decouple the utilization re-rate from sync frequency: either fix the per-chunk rate to the rate at window start for sub-`MAX_COMPOUND_DELTA_MS` boundaries created only by cadence (i.e., evaluate utilization once per wall-clock chunk regardless of call frequency), or accrue in fixed-size epoch grid cells rather than at caller-chosen timestamps.
2. Add path-independence tests mirroring the external report's recommendation: assert `1 × T` accrual equals `N × (T/N)` accrual within a bounded tolerance, via `run_cadence`-style harness in `contracts/pool/tests/interest.rs`.
3. If cadence-dependence is accepted as intended continuous compounding, bound it: enforce a minimum sync interval or make `update_indexes` batch-only across markets so frequency cannot be arbitrarily increased.

### Proof of Concept
1. Market `(hub, X)` has `supplied = S`, `borrowed = B` with positive utilization and `reserve_factor < BPS`; `last_timestamp = t0`.
2. Path A: single call `update_indexes([hub_X])` at `t0 + T`. `global_sync` runs `accrue_step` over chunk(s) of T, producing `borrow_index_A`.
3. Path B: attacker calls `update_indexes([hub_X])` at `t0 + T/N` intervals (N calls). After each call, `accrue_step` recomputes `utilization` with `borrowed` unscaled at the now-larger `borrow_index` but `supplied` grown only by `revenue_shares` (reserve-factor share of interest), so `util` and `borrow_rate` are strictly higher for the next slice than in Path A.
4. Result: `borrow_index_B > borrow_index_A`, and `supply_index` diverges correspondingly. The extra debt is paid by borrowers and collected by suppliers/protocol — a transfer whose size scales with N, controllable by any unprivileged caller.

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```
