### Title
Unfunded overpayment refunds are paid out of pool custody without debiting cash or verifying reserves - (File: contracts/pool/src/ops/repay.rs)

### Summary
The bug class in the reference report is a guard that mishandles a return value: `pm_runtime_get_sync()` returns `1` on success, and `WARN_ON(ret)` fired on the benign positive value — the check used the wrong boundary (`!= 0` instead of `< 0`). The analog in XOXNO Lending is the overpayment-refund boundary in the pool's repay leg: `ops::repay::accounting` computes `overpayment` purely from the **declared** `action.amount` versus outstanding debt, then `apply` calls `Cache::transfer_out`, which sends real tokens out of pool custody **without** debiting the `cash` book and **without** calling `require_reserves`. The guard `net_repay == 0 || burned > 0` treats the "everything is excess" case as benign — exactly the wrong-boundary shape of the CVE — so a refund can be paid out even when no (or less than the declared) inbound transfer occurred. The same gap exists in `ops::recapitalize::apply` (excess over the shortfall), as documented by the repo's own test `test_unfunded_repay_overpayment_refund_also_pays_out_of_custody` [1](#0-0) .

### Finding Description
`resolve_repay` splits the declared `amount` into `(burned, overpayment)` where `overpayment = amount - current_debt_ceil` [2](#0-1) . `RepayOutcome.overpayment` is then transferred to `payer` via `cache.transfer_out(payer, overpayment)` [3](#0-2) . `transfer_out` performs a raw token transfer from the pool address and explicitly "does not adjust accounting cash" and performs no solvency check [4](#0-3) . Consequently, the refund boundary is the *declared* amount, not a *measured* inbound delta: when debt is dust or zero, the entire declared amount is classified as overpayment and paid from the pool's real token balance while `cash` stays untouched — the book then overstates reserves by the refunded amount, i.e., other suppliers' funds subsidize the payout. The test at flows.rs:3578-3611 demonstrates `repay` with `custody_before` declared and zero transferred in drains the full custody balance to `payer`.

### Impact Explanation
Theft of user funds / protocol insolvency: every unit refunded above what was actually paid in comes out of supplier custody while `cash` bookkeeping is never debited, so `require_backed_market`/`backing_shortfall` (which compare floored supply claims against `cash + debt` [5](#0-4) ) cannot see the loss until withdrawals fail against the real balance. A permissionless `recapitalize` with a declared amount exceeding the shortfall, or a repay whose declared amount exceeds the measured inbound transfer, mints a refund funded by other users' deposits.

### Likelihood Explanation
Reachability: `recapitalize` and `repay` are user-reachable entrypoints. The pool trusts that the caller (controller) pre-funded the declared amount; any path where the controller forwards a declared amount rather than a measured receipt — or where recapitalize's excess is computed off the declared cap — lets a single unprivileged account extract the difference. This requires no privileged role, no oracle manipulation, and no token-semantics assumptions beyond the pool paying refunds it never verified were funded.

### Recommendation
- Debit `cash` (or route through `debit_cash`/`require_reserves`) before refunding `overpayment`, so unfunded refunds fail with `InsufficientLiquidity` instead of draining custody [6](#0-5) .
- Better: bound the refund by a measured inbound delta — snapshot the pool balance before the leg and cap `overpayment` at `min(declared_excess, balance_delta)`, mirroring `balance_delta_since` used in the controller [7](#0-6) .
- Apply the same fix to `ops::recapitalize::apply`'s excess-over-shortfall refund.

### Proof of Concept
`test_unfunded_repay_overpayment_refund_also_pays_out_of_custody` (flows.rs:3590-3611): with a market holding `custody_before` in tokens and zero debt, calling `repay` with `amount = custody_before` yields `actual_amount = 0` (nothing credited) while `transfer_out` pays the full `custody_before` to `payer`; post-state `cash` is unchanged while the real balance is zero — custody and book permanently diverge. Repeating the pattern through `recapitalize` (declare amount > shortfall, refund = declared − shortfall) generalizes it to markets with debt.

```rust
/// The refund gap is not specific to `recapitalize`. Two pool legs refund an
/// excess derived from a declared inbound amount, not from the cash book:
/// `ops::recapitalize::apply` (the excess over the shortfall) and
/// `ops::repay::apply` (the excess over the debt). Neither refund debits `cash`
/// or passes `require_reserves`.
///
/// A repay against a market with no debt makes the entire declared amount an
/// overpayment: `current_debt_ceil` is zero, so `resolve_repay` takes the
/// full-close branch and `net_repay` is zero. The `RepayRoundsToZeroShares`
/// assert in `ops::repay::accounting` passes on its `net_repay == 0` disjunct,
/// and the whole amount is refunded out of real custody with the book untouched.
#[test]
fn test_unfunded_repay_overpayment_refund_also_pays_out_of_custody() {
    let t = TestSetup::new();
    let token = token::Client::new(&t.env, &t.asset);
    let payer = Address::generate(&t.env);

    let custody_before = token.balance(&t.pool);
    let before = t.state_snapshot();
    assert_eq!(
        before.cash, custody_before,
        "fixture guard: book and custody must start in sync"
    );
    assert_eq!(before.borrowed, 0, "fixture must carry no debt");

    // Nothing transferred in, no debt to retire: the whole amount is "excess".
    let credited = t
        .client()
        .repay(&payer, &t.ract(0, custody_before))
        .get_unchecked(0)
        .actual_amount;
    assert_eq!(credited, 0, "no debt was retired, so nothing is credited");
    assert_unfunded_refund_drained_custody(&t, &payer, custody_before, &before);
}
```

```rust
pub(crate) fn accounting(env: &Env, action: &PoolAction) -> RepayOutcome {
    let (mut cache, position) = ops::load_leg(env, action);
    let amount = action.amount;

    let (burned, overpayment) = cache.resolve_repay(amount, position);
    let net_repay = amount
        .checked_sub(overpayment)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));
    assert_with_error!(
        env,
        net_repay == 0 || burned.raw() > 0,
        GenericError::RepayRoundsToZeroShares
    );
```

```rust
    /// Rejects negative amounts; zero is a no-op. Does not adjust accounting cash.

        require_nonneg_amount(&self.env, amount);
        if amount == 0 {
            return;
        }
        let tok = token::Client::new(&self.env, &self.params.asset_id);
        tok.transfer(&self.env.current_contract_address(), recipient, &amount);
```

```rust
pub(crate) fn backing_shortfall(cache: &Cache) -> i128 {
    let supplied_claim = cache.unscale_supply_floor(cache.supplied());
    let outstanding_debt = cache.unscale_borrow_ceil(cache.borrowed());
    let backing = cache.cash().saturating_add(outstanding_debt);
    supplied_claim.saturating_sub(backing).max(0)
}
```
