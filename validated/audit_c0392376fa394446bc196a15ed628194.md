### Title
Stale delegate grants regain account control after NFT round-trip - (File: contracts/controller/src/storage/account.rs)

### Summary
Account delegation is keyed only by the granting owner’s address. A grant becomes inactive while another address owns the position NFT, but it is not permanently invalidated and becomes usable again if the NFT returns to the original owner. A previously approved position manager can then borrow or withdraw account assets to itself without authorization from the current ownership session. [1](#0-0) [2](#0-1) 

### Finding Description
`ControllerKey::Delegates(account_id)` stores one `DelegateGrant` containing `granted_by` and a delegate list. `get_delegates` returns that list only when `granted_by` equals the NFT’s current owner. [1](#0-0) 

An intervening owner can delete the stale grant by calling `remove_delegate`; however, no transfer hook or epoch automatically invalidates it. If the intervening owner makes no delegate update and transfers the NFT back, the old `granted_by` value matches again and the former delegate is restored. [3](#0-2) [4](#0-3) 

The delegated caller passes `is_owner_or_delegate` whenever its global position-manager registration remains active, because the live owner’s stored delegate list again contains that caller. [2](#0-1) 

Both `borrow` and `withdraw` accept this restored authorization and allow an arbitrary external recipient rather than forcing payment to the account owner. [5](#0-4) [6](#0-5) [7](#0-6) 

### Impact Explanation
A stale delegate can transfer borrowed assets to itself and withdraw collateral not required to preserve solvency. The position retains debt while its borrowing capacity and available collateral have been extracted, resulting in theft of user funds and a materially impaired account. [8](#0-7) [9](#0-8) 

### Likelihood Explanation
The attack requires three conditions: the original owner previously granted a delegate, that address remains an active position manager, and the NFT leaves and later returns without an intervening owner changing delegates. This is plausible during a sale-and-repurchase, temporary custody transfer, marketplace escrow, or other ownership round-trip. Once those conditions hold, exploitation is a single authorized `borrow` or `withdraw` call. The documented behavior confirms that grants can revive after the NFT returns. [10](#0-9) 

### Recommendation
Invalidate delegate grants on every ownership transition rather than merely hiding them while another owner holds the NFT. Store an NFT-maintained owner generation or transfer epoch inside `DelegateGrant`, increment it on transfer or burn, and require both `granted_by` and the current generation to match in `is_owner_or_delegate`. Alternatively, persist the last observed owner in controller account state and clear `ControllerKey::Delegates(account_id)` before authorization whenever the resolved NFT owner differs from that stored owner.

### Proof of Concept
1. Alice calls `supply(alice, 0, spoke_id, [(hub_asset, collateral)])`, creating `account_id`.
2. Alice calls `add_delegate(alice, account_id, mallory)` while Mallory is an active position manager. [11](#0-10) 
3. Alice transfers the position NFT to Bob. Bob neither calls `remove_delegate` nor adds a replacement delegate, so the stored `DelegateGrant { granted_by: alice, delegates: [mallory] }` remains.
4. Bob transfers the NFT back to Alice.
5. Mallory calls `borrow(mallory, account_id, [(debt_asset, amount)], Some(mallory))`. `mallory.require_auth()` succeeds, the resolved owner is Alice, the old delegate list matches again, and the pool pays Mallory subject only to post-borrow solvency. [12](#0-11) 
6. Mallory may also call `withdraw(mallory, account_id, [(collateral_asset, amount)], Some(mallory))` for collateral not required to keep the remaining debt solvent. [13](#0-12)

```rust
    account_id: u64,
    owner: &Address,

        env.storage().persistent().remove(&key);
```

```rust
pub(crate) fn is_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) -> bool {
    if caller == owner {
        return true;
    }

        storage::get_position_manager(env, caller).is_some_and(|config| config.is_active);
    active_manager && storage::get_delegates(env, account_id, owner).contains(caller)
```

```rust
/// Authenticates the NFT owner and updates delegates; grants require an active
/// manager. Emits an event only when the current owner's delegate list changes.
fn set_account_delegate(
    env: &Env,
    caller: &Address,
    account_id: u64,
    delegate: &Address,
    add: bool,
) {
    caller.require_auth();
    require_account_owner(env, account_id, caller);
    if add {
        // Reject dormant grants that could gain authority on later manager activation.
        assert_with_error!(
            env,
            storage::get_position_manager(env, delegate).is_some_and(|c| c.is_active),
            GenericError::NotAuthorized
        );
    }

    let changed = if add {
        storage::add_delegate(env, account_id, caller, delegate)
    } else {
        storage::remove_delegate(env, account_id, caller, delegate)
    };
```

```rust
impl NonFungibleToken for PositionNft {
    type ContractType = Enumerable;

    /// `{stored base_uri}{token_id}?isStatic=true&chain=STELLAR`
    ///
    /// Panics with the OZ `NonExistentToken` error for burned or never-minted
    /// ids, matching the stock behavior.
    fn token_uri(e: &Env, token_id: u32) -> String {
        let _owner = Base::owner_of(e, token_id);

        let base = Base::base_uri(e);
        let base_len = base.len() as usize;
        // OZ `set_metadata` caps the base at `MAX_BASE_URI_LEN` (200 bytes):
        // 200 + 10 digits (u32 max) + 28-byte suffix fits in 256.
        let mut buf = [0u8; 256];
        base.copy_into_slice(&mut buf[..base_len]);
        let mut len = base_len;
        // Decimal digits, most significant first. token_id >= 1 always
        // (id 0 is consumed at construction), so no zero special-case.
        let mut digits = [0u8; 10];
        let mut n = token_id;
        let mut count = 0usize;
        while n > 0 {
            digits[count] = b'0' + (n % 10) as u8;
            n /= 10;
            count += 1;
        }
        while count > 0 {
            count -= 1;
            buf[len] = digits[count];
            len += 1;
        }
        for b in TOKEN_URI_SUFFIX.bytes() {
            buf[len] = b;
            len += 1;
        }
        String::from_bytes(e, &buf[..len])
    }
}
```

```rust
/// Borrows the aggregated amounts to `recipient` and merges the debt results.
fn settle_borrow(
    env: &Env,
    account: &mut Account,
    recipient: &Address,
    aggregated: &AggregatedPayments,
    cache: &mut Context,
) {
    let pool_addr = cache.cached_pool_address();
    let mut entries: Vec<PoolBorrowEntry> = Vec::new(env);
    for (hub_asset, amount) in aggregated.iter() {
        let position = account.get_or_create_debt_position(&hub_asset);
        entries.push_back(PoolBorrowEntry {
            action: make_pool_action(&position, amount, hub_asset.clone()),
        });
    }
    let results = pool_borrow_call(env, &pool_addr, recipient, &entries);
    for_each_leg(env, &entries, &results, |entry, result| {
        merge_debt_leg(
            env,
            account,
            events::PositionAction::Borrow,
            &entry.action.hub_asset,
            LegDirection::Entry {
                asset_decimals: result.asset_decimals,
            },
            &LegOutcome::from(&result),
            cache,
        );
    });
```

```rust
    env: &Env,
    account: &mut Account,
    recipient: &Address,
    aggregated: &AggregatedPayments,
    cache: &mut Context,
) -> Vec<HubPayment> {
    let mut entries: Vec<PoolWithdrawEntry> = Vec::new(env);
    for (hub_asset, amount) in aggregated.iter() {
        enforce_spoke_asset_flags(
            env,
            cache,
            account.spoke_id,
            &hub_asset,
            FreezePolicy::AllowOnExit,
        );
        let position = get_supply_position_or_panic(env, account, &hub_asset);
        let requested = if amount == 0 {
            WITHDRAW_ALL_SENTINEL
        } else {
            amount
        };
        entries.push_back(PoolWithdrawEntry {
            action: make_pool_action(&position, requested, hub_asset.clone()),
            protocol_fee: 0,
        });
    }

    let results = apply_withdraw_batch(
        env,
        account,
        recipient,
        WithdrawKind::Normal,
        events::PositionAction::Withdraw,
        &entries,
        cache,
    );
    let mut paid: Vec<HubPayment> = Vec::new(env);
    for_each_leg(env, &entries, &results, |entry, result| {
        paid.push_back((entry.action.hub_asset, result.actual_amount));
    });
    paid
}
```

**File:** docs/explanation/threat-model.md (L81-87)
```markdown
An account delegate also needs active global position-manager registration.
Its grant is stamped with the granting owner's address, not a transfer epoch:
it becomes inactive while someone else holds the NFT and can revive if the
NFT returns before an intervening owner updates delegates. Owner revocation
is immediate; global deactivation takes effect when governance executes it.
Delegates can borrow/withdraw to their chosen recipient within account gates.
Those gates do not constrain them to acting in the owner's economic interest.
```
