## Analog found

### Title
Full-sellout graduation permanently reverts in `pair.mint()`, bricking `finalizeGraduation` and freezing curve-raised LT and reserved tokens - (File: `packages/contracts/src/Bonding.sol`)

### Summary
The Cairo report's root cause is a hard revert (`assert`) inside a cross-contract call path that the calling contract's design assumes will always be gracefully recoverable, leaving state permanently stuck. `alt.fun`'s `Bonding.finalizeGraduation` → `_seedUniswapV2Direct` → `_seedDirectMint` → `IUniswapV2Pair.mint()` chain has the same structural weakness: the deterministic parabola math that computes `tokensForLP` drives it to **zero** as the curve approaches full sellout, and `UniswapV2Pair.mint()` unconditionally reverts on `liquidity == 0` (`INSUFFICIENT_LIQUIDITY_MINTED`). Because `finalizeGraduation`'s inputs are cached and immutable once `Lifecycle.Graduating` is entered, every retry recomputes the exact same zero and reverts identically forever.

### Finding Description
`_prepareGraduationLiquidity` computes:
```
tokensForLP = assetReserve == 0 ? 0 : (ltFromPair * tokenReserve) / assetReserve;
``` [1](#0-0) 

The design's own natspec states the "parabola invariant" `tokensForLP(sold) = sold·(S−sold)/S` peaks at `S/4` and is guaranteed `≤ LP_RESERVE` — but it necessarily falls back to **near zero** as `sold → S` (i.e., as the curve's `tokenReserve` approaches zero on full sellout via the supply trigger, `IPair.tokenBalance() == 0`). [2](#0-1) 

Phase 2 (`finalizeGraduation`) then calls `_seedUniswapV2Direct`, which for the ~99% empty-pair case calls `_seedDirectMint`, transferring `tokensForLP` and `ltFromPair` to the pair and calling `IUniswapV2Pair(pair).mint(lpLock)` directly: [3](#0-2) 

Canonical `UniswapV2Pair.mint` computes `liquidity = sqrt(amount0 * amount1)` (first mint) or `min(amount0*totalSupply/reserve0, amount1*totalSupply/reserve1)` and reverts with `require(liquidity > 0, 'UniswapV2: INSUFFICIENT_LIQUIDITY_MINTED')` if the result rounds to zero — which is unavoidable once `tokensForLP` itself has rounded to `0` (or is small enough that the product/sqrt truncates to `0`). This is functionally identical to the Cairo report's `assert`: an unconditional revert deep in a call chain that the caller (`finalizeGraduation`) has no way to route around, versus a graceful `return false`/early-exit.

Once `_enterGraduating` has fired and cached `PendingGraduation{tokensForLP: 0, ltFromPair, ...}`, `finalizeGraduation` is deterministic and idempotent-input — every call (by keeper or any permissionless caller) recomputes the same zero `tokensForLP` and hits the same revert, with no code path to skip, retry with different values, or recover the token to `Lifecycle.Curve`.

### Impact Explanation
This permanently freezes:
- The full `ltFromPair` (real LT raised by the curve) already drained into `Bonding` via `Router.graduate` in phase 1
- Up to `LP_RESERVE` (250M) tokens reserved for LP seeding
- The token itself, stuck forever in `Lifecycle.Graduating` — trading is frozen (`isTrading` false) and it can never reach `Lifecycle.Graduated`, so post-grad `Zap` trading is also permanently unavailable

This matches the "permanent freezing of trader/creator/LP funds" impact bar. Given the project's own explicit design goal ("Phase 2 must never revert under any pre-seed shape" / "brick resistance") this is a direct violation of a documented invariant, mirroring the judge's High-severity rationale in the original report (inconsistent/irrecoverable terminal state vs. graceful handling). [4](#0-3) 

### Likelihood Explanation
Reachable by any unprivileged trader: simply buying out the curve to full sellout (`Bonding.buy`/`Zap.buy` driving `IPair.tokenBalance()` to `0`) triggers the supply-trigger graduation path, which is exactly the regime where `tokenReserve → 0` and `tokensForLP → 0` by the parabola's own shape. No attacker sophistication or pre-seeding is required — it is a natural consequence of a normal, permissionless full-sellout buy sequence, which is an expected and even encouraged usage pattern (the docs describe the supply trigger as handling "flat/bear markets" — an ordinary, not adversarial, scenario).

### Recommendation
- Add an explicit floor/guard in `_prepareGraduationLiquidity` or `_seedDirectMint` that detects a `tokensForLP` (or resulting `liquidity`) that would round to zero, and fall back to a minimum viable LP seed (e.g., clamp `tokensForLP` to a minimum of `1` scaled appropriately, or use a different seeding strategy for near-zero remainders) instead of letting `pair.mint()` hard-revert.
- Alternatively, wrap the `mint()` call and, on failure/zero-liquidity detection, route to a defined recovery path (e.g., burn the residual dust and mark the token `Graduated` with an empty/degenerate LP, or allow `transferCreator`-style admin rescue) rather than leaving `finalizeGraduation` permanently unresolvable.
- Add a regression test that drives a curve to exact full sellout via minimal LT and asserts `finalizeGraduation` succeeds (extending `test/GraduationInvariants.t.sol` / `test/TwoPhaseGraduation.t.sol`'s brick-resistance suite to cover the zero-`tokensForLP` edge, which currently is not explicitly tested per the visible test files).

### Proof of Concept
1. `Bonding.launch` a token normally (curve starts with `curveSupply = 750M` tokens, `LP_RESERVE = 250M` held back).
2. A trader (or sequence of traders) calls `Zap.buy` / `Bonding.buy` repeatedly until `IPair(pair).tokenBalance() == 0` (full sellout) — this is ordinary permissionless activity, not a griefing attack; per the parabola invariant, `tokensForLP(sold) = sold·(S−sold)/S → 0` as `sold → S`.
3. The threshold-crossing buy triggers `_enterGraduating` inline; `_prepareGraduationLiquidity` computes `tokensForLP` at or near `0` (rounds down due to integer division as `tokenReserve` is dust-small) and caches it in `pendingGraduation[token]`. [5](#0-4) 
4. Any address (keeper or rando) calls `Bonding.finalizeGraduation(token)`. `_seedUniswapV2Direct` → `_seedDirectMint` transfers `tokensForLP ≈ 0` tokens and `ltFromPair` LT to the freshly created pair and calls `pair.mint(lpLock)`.
5. `UniswapV2Pair.mint()` computes `liquidity = 0` and reverts with `INSUFFICIENT_LIQUIDITY_MINTED`. `finalizeGraduation` reverts.
6. Every subsequent call to `finalizeGraduation(token)` reverts identically (cached inputs are frozen while `Lifecycle.Graduating`), permanently stranding the token, its raised LT, and its reserved 250M tokens with no on-chain recovery path.
