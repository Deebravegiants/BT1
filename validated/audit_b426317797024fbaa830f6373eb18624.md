### Title
Reentrant relayer-fee zeroing via external app call before effects in `dispatchIncoming(GetResponse,...)` - (File: evm/src/core/EvmHost.sol)

### Summary
`EvmHost.dispatchIncoming(GetResponse, address relayer)` performs an untrusted external call to the destination module (`IApp.onGetResponse`) and only *afterwards* reads `_requestCommitments[commitment].fee` to pay the relayer. Because this read/pay step happens after the external call and `_requestCommitments` is not cleared or cached before the call, a malicious destination module can re-enter the protocol during `onGetResponse` and cause `_requestCommitments[commitment]` to be deleted before the outer frame resumes, silently zeroing the relayer's fee payout. This is the same bug class as CVE-2023-5380 (use of an object's state after it has been invalidated by an intervening operation triggered during processing of the same logical resource): the commitment record is destroyed mid-flight and the outer code proceeds to read/consume it as if it were still valid, with directly observable financial consequences instead of a crash.

### Finding Description
In `dispatchIncoming(GetResponse memory response, address relayer)`: [1](#0-0) 

the sequence is:
1. `_responseReceipts[commitment]` is set (replay protection) — this part correctly follows checks-effects-interactions.
2. An **external, attacker-controlled call** is made to `response.request.from` (the destination `IApp`) via `onGetResponse`.
3. Only *after* that external call returns is `_requestCommitments[commitment].fee` read and, if non-zero, transferred to the relayer.

`_requestCommitments[commitment]` can be deleted by `dispatchTimeOut(GetRequestTimeout, ...)`: [2](#0-1) 

Both `dispatchIncoming` and `dispatchTimeOut` are restricted to `_hostParams.handler`, i.e. they may only be invoked by the `HandlerV2` contract itself — but any relayer can drive `HandlerV2` through its unrestricted public entry points (`handleGetResponses`, `handleGetRequestTimeouts`): [3](#0-2) 

A destination module is fully attacker-controlled code (any contract can register itself as the `from`/`to` of a GET request it dispatches). During the `onGetResponse` callback in step 2 above, the malicious module can re-enter `HandlerV2.handleGetRequestTimeouts` with a state proof for the same request, which calls back into `host.dispatchTimeOut(...)` (permitted, since the caller is `HandlerV2`, satisfying `restrict(_hostParams.handler)`). This deletes `_requestCommitments[commitment]` before the outer `dispatchIncoming(GetResponse,...)` frame resumes execution and reads `fee`, so the relayer fee read at line 842 comes back as zero and no payment is made, while the attacker's own module can simultaneously receive a timeout refund of the same fee via `dispatchTimeOut`'s refund branch. The net effect is that the relayer who legitimately proved and delivered the response is paid nothing, and the funds are diverted back to the requester (the attacker) — a fee/reward-accounting fund-diversion bug reachable purely by a relayer delivering a message to an unprivileged, attacker-deployed `IApp` contract.

### Impact Explanation
This directly affects relayer fee and reward accounting, one of the explicitly in-scope impact categories: an unprivileged actor (deployer of a malicious `IApp` module that requests and consumes a GET response) can cause a relayer's earned fee to be silently withheld/misdirected through a reentrant deletion of the fee-bearing commitment before it is consumed, resulting in fund loss for honest relayers and fund diversion to the attacker.

### Likelihood Explanation
Exploitation requires only deploying an ordinary `IApp` contract with a malicious `onGetResponse` implementation and dispatching a GET request from it — no privileged role, governance, or admin access is needed. The reentrant call path (`onGetResponse` → `HandlerV2.handleGetRequestTimeouts` → `EvmHost.dispatchTimeOut`) is fully permitted by the existing `restrict(_hostParams.handler)` modifier since `HandlerV2` is the caller in both cases. The main constraint is producing a valid non-membership proof showing the timeout condition at some already-relayed state height, which is a proof-construction/timing exercise rather than a privilege barrier.

### Recommendation
Apply checks-effects-interactions in `dispatchIncoming(GetResponse, address)`: snapshot/read and clear (or otherwise lock) the fee metadata for `commitment` *before* invoking `IApp.onGetResponse`, and pay out using the pre-call snapshot rather than re-reading `_requestCommitments[commitment]` after the external call. Additionally, add reentrancy protection around the dispatch/handler entry points that mutate shared per-commitment state (`_requestCommitments`, `_requestReceipts`, `_responseReceipts`) so that a callback invoked from one dispatch path cannot recursively trigger another dispatch path against the same commitment mid-flight.

### Proof of Concept
1. Attacker deploys `EvilApp` implementing `IApp`; from `EvilApp`, dispatch a `DispatchGet` request (attacker pays the relayer fee) targeting itself as `from`.
2. A relayer produces and delivers the `GetResponse` via `HandlerV2.handleGetResponses`, which calls `EvmHost.dispatchIncoming(GetResponse, relayer)`: [4](#0-3) 
3. Inside `EvilApp.onGetResponse`, before returning, `EvilApp` calls `HandlerV2.handleGetRequestTimeouts` with a valid non-membership proof for the same request's response receipt at an already-relayed state height whose timestamp exceeds the request's timeout, invoking `host.dispatchTimeOut(GetRequestTimeout, meta, commitment)`: [5](#0-4) 
   This deletes `_requestCommitments[commitment]` and refunds `meta.fee` back to `meta.sender` (the attacker).
4. Execution returns to the outer `dispatchIncoming(GetResponse,...)` frame; `_requestCommitments[commitment].fee` is now `0`, so the relayer receives no fee payment, while the attacker has already been refunded the fee and still received the response data via `onGetResponse`.

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
