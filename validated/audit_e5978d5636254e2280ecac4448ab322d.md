### Title
Gateway `ProcessRequest` leaks raw internal JSON parsing error details to unauthenticated remote clients - ([File: core/services/gateway/gateway.go])

### Summary
The Chainlink Gateway's `ProcessRequest` function, which is the first entry point for all inbound HTTP requests from unprivileged/external clients, returns the raw Go `error.Error()` string from internal JSON-RPC decoding and codec unmarshalling directly in the JSON-RPC error response sent back to the caller. This mirrors the free5GC NEF bug class: internal parser error strings (e.g. Go's `encoding/json` messages like `invalid character 'x' after top-level value`) are echoed verbatim to remote, unauthenticated clients.

### Finding Description
`ProcessRequest` is invoked by the internet-facing HTTP server for every request hitting the gateway's user-facing port, before any authentication/allowlist checks are applied to determine a valid handler: [1](#0-0) 

When `jsonrpc2.DecodeRequest` fails to parse the raw request bytes, or when `g.codec.DecodeJSONRequest` fails to unmarshal the `params` field, the raw underlying Go error (`err.Error()`) is passed straight into `newError(...)`, which places it verbatim into the `Message` field of the JSON-RPC error response body: [2](#0-1) 

The codec itself also propagates raw `json.Unmarshal` errors without sanitization: [3](#0-2) 

This response is then written directly to the HTTP response body by the server: [4](#0-3) 

This code path is reachable by any unauthenticated client capable of sending an HTTP request to the gateway's public port — the JWT/auth header is only extracted and forwarded as a raw string, not validated before `ProcessRequest` runs the parse steps that can leak error text (line ~226-234 of `httpserver.go`).

### Impact Explanation
The leaked error strings originate from Go's standard `encoding/json` decoder and can reveal internal implementation details: exact byte offsets, field names/types expected by internal structs (`api.Message`, `jsonrpc2.Request`), and library-specific error phrasing. This is analogous to the free5GC/UDR NEF issue, where internal parser errors aided attacker fingerprinting of the service. It does not by itself grant authentication bypass, secret disclosure, or fund movement, but it does expose internal schema/implementation details useful for further attack reconnaissance (e.g., confirming exact library versions/behavior, or probing internal field names of `api.Message`).

### Likelihood Explanation
Very high — no authentication, allowlisting, or special network position is required. Any client that can reach the gateway's user HTTP port and send a malformed JSON body or malformed `params` field will trigger this path deterministically.

### Recommendation
Do not return raw `err.Error()` values from internal JSON decode/unmarshal failures directly to the client. Return a generic, static error message (e.g., `"invalid request format"`) in the JSON-RPC `Message` field, and log the detailed internal error server-side only, similar to the pattern already used elsewhere in the trigger handler (`"payload is not a valid JSON. Ensure that the request body is a well-formed JSON"` in `core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go`) rather than the raw parser error used in `gateway.go`'s `ProcessRequest`.

### Proof of Concept
1. Send a malformed JSON-RPC request to the gateway's public HTTP endpoint, e.g. a body with a trailing invalid token: `{"jsonrpc":"2.0","id":"1","method":"x","params":{}}n`.
2. `jsonrpc2.DecodeRequest` fails; `ProcessRequest` calls `newError("", api.UserMessageParseError, err.Error())`.
3. The HTTP response body contains the raw Go JSON decoder error message (e.g. `invalid character 'n' after top-level value`) in the `error.message` field of the JSON-RPC response, exposing internal parsing implementation details to the unauthenticated caller — directly matching the CVE-2025-69253 bug class. func (g *gateway) ProcessRequest(ctx context.Context, rawRequest []byte, auth string) (rawResponse []byte, httpStatusCode int) {
	// decode

	}

func newError(id string, errCode api.ErrorCode, errMsg string) ([]byte, int) {
	response := jsonrpc2.Response[json.RawMessage]{
		Version: jsonrpc2.JsonRpcVersion,
		ID:      id,
		Error: &jsonrpc2.WireError{
			Code:    api.ToJSONRPCErrorCode(errCode),
			Message: errMsg,
			Data:    nil,
		},
	}
	rawResponse, err := json.Marshal(response)
	if err != nil {
		rawResponse = []byte("fatal error" + err.Error())
	}
	promRequest.WithLabelValues(errCode.String()).Inc()
	return rawResponse, api.ToHTTPErrorCode(errCode)
}

func (j *JSONRPCCodec) DecodeRawRequest(msgBytes []byte, jwtToken string) (*Message, error) {
	jsonRequest, err := jsonrpc2.DecodeRequest[json.RawMessage](msgBytes, jwtToken)
	if err != nil {
		return nil, err
	}
	return j.DecodeJSONRequest(jsonRequest)
}

func (*JSONRPCCodec) DecodeJSONRequest(request jsonrpc2.Request[json.RawMessage]) (*Message, error) {
	var msg Message
	err := json.Unmarshal(*request.Params, &msg)
	if err != nil {
		return nil, err
	}
	msg.Body.MessageID = request.ID
	msg.Body.Method = request.Method
	return &msg, nil
}
