### Title
`SimplexPaymaster` prices ERC-20 gas payments from a raw Chainlink `latestRoundData()` answer with no circuit-breaker (min/max) bound check - ([File: evm/src/utils/SimplexPaymaster.sol])

### Summary
`SimplexPaymaster._getOraclePrice` only guards against a non-positive answer and staleness; it never checks the returned `answer` against the aggregator's `minAnswer`/`maxAnswer` circuit-breaker bounds. If a registered token's price crashes below the underlying Chainlink feed's `minAnswer`, the feed keeps reporting the frozen floor price, and the paymaster keeps using that stale-but-"fresh" price to compute how many tokens to pull from any unprivileged UserOp sender, exactly the bug class in the referenced report.

### Finding Description
`_getOraclePrice` is the sole price-validation function used by both the per-UserOp charging path and the fee-recycling swap path: [1](#0-0) 

It reverts on `answer <= 0` and on staleness (`block.timestamp - updatedAt > maxOracleAge`), but performs no check that `answer` is not sitting at the aggregator's `minAnswer`/`maxAnswer` bound. Chainlink aggregators clamp `latestRoundData()`'s `answer` to `[minAnswer, maxAnswer]`; when the real market price of a registered token drops through `minAnswer` (a LUNA/UST-style crash), the feed continues to report `minAnswer` with a perfectly fresh `updatedAt`, so neither of `_getOraclePrice`'s checks trips.

This price feeds directly into `_tokenPrice`, which is used by `_fetchDetails` (called during ERC-4337 validation for every UserOp that pays with a registered token) and by `swapAndDeposit`: [2](#0-1) [3](#0-2) 

`_fetchDetails` is reachable by any address that can construct a `PackedUserOperation` naming a registered token — this is precisely the "unprivileged message dispatcher" surface: nothing gates who can submit a UserOp against this paymaster with `mode 0x00`/`0x02` paymasterData, provided the named token is `active` in `tokenConfigs`: [4](#0-3) 

The comment at the top of `_tokenPrice`'s pricing formula documents the intended relationship (`tokenPrice = (nativeUsd * 10^tokenDecimals) / tokenUsd`), meaning an inflated (floored) `tokenUsd` produces a smaller `tokenPrice`, i.e. the contract charges fewer token units per unit of native gas than the token is actually worth: [5](#0-4) 

The only mitigation against a crashed token is manual governance action (`DeactivateToken`, delivered as a Hyperbridge governance message and processed in `onAccept`): [6](#0-5) [7](#0-6) 

This is reactive, not preventive: nothing in the pricing path itself detects that the aggregator has hit its floor, so an attacker who notices the crash before governance deactivates the token can exploit the frozen floor price during the intervening window.

### Impact Explanation
While the aggregator is clamped, any unprivileged UserOp sender can pay for gas with the crashed token at the stale floor price instead of its real market value, draining the treasury-funded EntryPoint deposit / the paymaster's subsidized gas at a steep discount relative to the token's true worth — effectively theft of value from the paymaster's treasury. The same stale price also corrupts `swapAndDeposit`'s on-chain minimum-output calculation (`_getOraclePrice` for both `nativeOracle` and the token), letting the treasury-gated swap execute at a mispriced rate, though that path is treasury-only and lower severity. The UserOp-charging path has no privilege gate, so it is the more relevant, higher-likelihood loss vector.

### Likelihood Explanation
This requires the confluence of (a) a registered token undergoing a real, severe market crash through its Chainlink feed's `minAnswer`, and (b) an attacker (or bundler-savvy user) exploiting the window before governance's `DeactivateToken` message is delivered and processed. This is a plausible, historically-observed event class (LUNA/UST on Venus) rather than a routine occurrence, but it is entirely triggerable by an ordinary UserOp sender with no special privileges once the market condition occurs, matching the required Medium severity and reachability bar.

### Recommendation
In `_getOraclePrice`, read and cache each aggregator's `minAnswer`/`maxAnswer` (or a governance-configured tighter band) at registration time, and revert if `answer <= minAnswer || answer >= maxAnswer`, mirroring the standard Chainlink circuit-breaker guard:
```solidity
if (answer <= 0) revert InvalidOraclePrice(...);
if (answer <= minAnswerFor[oracle] || answer >= maxAnswerFor[oracle]) revert InvalidOraclePrice(...);
if (block.timestamp - updatedAt > maxOracleAge) revert StaleOraclePrice(...);
```
This causes `_fetchDetails`/`swapAndDeposit` to revert instead of silently pricing off a frozen floor/ceiling value, forcing governance to react (or a fallback oracle to be used) rather than allowing exploitation during the crash window.

### Proof of Concept
1. Governance registers `TokenA` with Chainlink feed `F` via `RegisterToken` (`_registerToken`), `F.minAnswer = $1`.
2. Market crash: `TokenA`'s real price falls to `$0.10`; `F.latestRoundData()` keeps returning `answer = $1` (clamped) with a fresh `updatedAt`.
3. Attacker submits a UserOp with `paymasterData` mode `0x00`/`0x02` naming `TokenA`. `_fetchDetails` computes `tokenPrice` via `_tokenPrice` → `_getOraclePrice(cfg.tokenOracle, ...)`, which passes both the `answer > 0` and staleness checks since the feed is "healthy" per its own reporting.
4. The paymaster charges the attacker `TokenA` at the inflated `$1` valuation instead of the true `$0.10`, i.e., the attacker pays 10x less value than actual gas cost, draining the paymaster's EntryPoint deposit funded by the treasury.
5. This repeats for every UserOp until governance's `DeactivateToken` message is delivered and processed by `onAccept`.

```text
    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
```
