### Title

Permissionless index accrual can permanently freeze an overgrown market - (File: `contracts/pool/src/interest.rs`)

### Summary

A large market whose debt grows far enough can make index synchronization overflow `i128` before the borrow-index ceiling is reached. Once this occurs, every market operation that first accrues interest—repayment, withdrawal, liquidation, supply, borrowing, and further index updates—reverts, permanently locking funds without an administrative parameter change.

### Finding Description

Every pool mutation loads its market through `ops::synced_market`, which calls `interest::global_sync` before applying the requested operation. [1](#0-0) 

`global_sync` repeatedly calls `accrue_chunk` for elapsed periods, and `accrue_chunk` evaluates `accrue_step` against the market's scaled debt, scaled supply, borrow index, and supply index. [2](#0-1) [3](#0-2) 

Utilization converts scaled debt and supply into RAY-denominated asset values through `scaled_to_original`, whose checked arithmetic can overflow when scaled amount times index exceeds the `i128` range. [4](#0-3) [5](#0-4) 

The regression test demonstrates this state: a billion-token market at 98% utilization eventually makes `update_indexes` return `MathOverflow` while the stored borrow index remains below `MAX_BORROW_INDEX_RAY`. [6](#0-5) 

The same test confirms that withdrawal and repayment subsequently revert because both operations perform the failing accrual before their own logic. [7](#0-6) 

### Impact Explanation

This can permanently freeze all funds in the affected hub-asset market: suppliers cannot withdraw, borrowers cannot repay, and liquidators cannot liquidate because each path synchronizes the market first. [8](#0-7) 

Unlike the reported privileged parameter change, the trigger is reachable through ordinary `supply`, `borrow`, and permissionless `update_indexes` calls when market caps and collateral constraints admit the required book. [9](#0-8) [10](#0-9) 

### Likelihood Explanation

Likelihood is low under conservative market parameters because the attack requires a very large supplied balance, high utilization, a rate curve capable of substantial index growth, and enough collateral for the borrower. [11](#0-10) [12](#0-11) 

It is still attacker-reachable without privileged control when governance has listed a market with sufficiently high caps and a sufficiently steep rate model. [13](#0-12) 

### Recommendation

Bound RAY asset-value conversion independently of the index ceiling and make accrual fail safely before `scaled_to_original` overflows. Relevant mitigations include saturating or branching on overflow in utilization calculation, enforcing a stricter scaled-value ceiling during borrow/supply entry, and adding a recovery path that can reduce debt or update indexes without first evaluating the overflowing utilization path.

### Proof of Concept

1. A supplier calls `supply(caller, account_id = 0, spoke_id, [(debt_asset, principal)])` with an extremely large principal.
2. A borrower supplies sufficient collateral on another market and calls `borrow(caller, account_id, [(debt_asset, approximately 98% of supplied)])`.
3. Any signed caller invokes `update_indexes(caller, [debt_asset])` as ledger time advances.
4. Once `borrowed * borrow_index` or `supplied * supply_index` exceeds the `i128` RAY-value ceiling, `accrue_step` reverts with `MathOverflow`.
5. Later calls to `update_indexes`, `withdraw`, `repay`, and `liquidate` all revert at the same synchronization step, so the market cannot recover through normal user operations. [2](#0-1) [14](#0-13)

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

```rust
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}
```
