### Title
`TokenExchange.exchange_token` uses the unsanitized JWT `dest` claim as the shop host for the client-credentialed token request - (File: lib/shopify_api/auth/token_exchange.rb)

### Summary
`ShopifyAPI::Auth::TokenExchange.exchange_token` takes the `dest` claim straight out of `JwtPayload` and uses it, unsanitized, as the HTTP host to which it POSTs the app's `client_id`/`client_secret` for the OAuth token-exchange grant. Every other credentialed shop-host flow in this gem (`migrate_to_expiring_token`) explicitly funnels the `shop` value through `Utils::ShopValidator.sanitize!` before using it to build a request host, but `exchange_token` does not.

### Finding Description
`JwtPayload#shop` simply strips `"https://"` from the raw `dest` claim of the decoded JWT and returns the remainder verbatim: [1](#0-0) 

`JwtPayload#initialize` only verifies the signature and the `aud` claim; it never validates that `iss`/`dest` are a trusted `*.myshopify.com` (or `myshopify.io`/`spin.dev`/`shop.dev`) domain: [2](#0-1) 

`TokenExchange.exchange_token` takes this unsanitized `dest_shop` and passes it directly into `Auth::Session.new(shop: dest_shop)`, then uses that session (whose `shop` becomes the request host) to POST a body containing `client_id` and `client_secret` to `#{shop}/admin/oauth/access_token`: [3](#0-2) 

Compare this to `migrate_to_expiring_token` in the same file, which explicitly runs the shop parameter through `Utils::ShopValidator.sanitize!` — a helper that exists precisely to constrain shop hosts to `ShopValidator::TRUSTED_SHOPIFY_DOMAINS` — before building the credentialed request: [4](#0-3) [5](#0-4) 

The identity binding this breaks: `host that receives the app's client_secret` must equal `a validated *.myshopify.com/myshopify.io/spin.dev/shop.dev host`. In `exchange_token` the host that receives `client_secret` is simply `dest_shop`, whose only real constraint is that it round-trips as a string inside a JWT signed with `Context.api_secret_key`. Nothing in `JwtPayload` or `exchange_token` calls `ShopValidator.sanitize!` (or an equivalent allow-list check) on `dest` before it is used as an outbound request host.

### Impact Explanation
If `dest` is not constrained to Shopify's own domains, this is a High-impact SSRF-with-credentials pattern per the rules: a crafted/compromised session token whose `dest` claim points to an attacker-controlled host would cause the gem to send the app's `client_id` and `client_secret` (the exact credentials the rules flag as sensitive) to that host via `Clients::HttpClient`. This is functionally the same "identity-binding-not-checked-before-acting" bug class as the report's "vault registered without checking prior binding," analogized here to "shop host used to route a client-secret-bearing request without checking it against a trusted-domain binding" — the inconsistency with the sibling method `migrate_to_expiring_token`, which does perform this exact check, demonstrates the missing validation is a gap rather than an intentional design decision.

### Likelihood Explanation
Exploitability hinges entirely on how strictly Shopify constrains the `dest`/`iss` claims it issues and how well `JWT.decode`'s signature check prevents an attacker from independently minting a token with an arbitrary `dest`. Because the JWT is HMAC-signed with `Context.api_secret_key` (a value this gem's rules place out of scope for attacker possession), an unprivileged attacker cannot forge a token with an arbitrary `dest` without already holding the `api_secret_key`. I could not find, within this gem's code, any additional runtime source (independent of the signed JWT) that supplies `dest_shop` to `exchange_token`, so I could not confirm a route that lets an unprivileged internet user control `dest` without already possessing the app's secret.

### Recommendation
Route `dest_shop` (and `JwtPayload#shop`/`#dest`/`#iss`) through `Utils::ShopValidator.sanitize!` before it is used to construct any HTTP request host in `TokenExchange.exchange_token`, mirroring the validation already performed in `migrate_to_expiring_token`, so that the recipient of `client_id`/`client_secret` is always constrained to `ShopValidator::TRUSTED_SHOPIFY_DOMAINS`.

### Proof of Concept
Not constructible with the tools/context available: exploitation requires forging or otherwise obtaining a JWT with an attacker-controlled `dest` claim that still passes signature verification against `Context.api_secret_key`, which requires possession of the app's secret — a precondition this engagement's rules place out of scope. No independent, unauthenticated path that sets `dest_shop` was found in `lib/shopify_api/**` (excluding the excluded resource/test/doc paths).

        [
          "shopify.com",
          "myshopify.io",
          "myshopify.com",
          "spin.dev",
          "shop.dev",
        ].freeze,
        T::Array[String],

      class << self
        extend T::Sig

        sig do
          params(
            shop_domain: String,
            myshopify_domain: T.nilable(String),
          ).returns(T.nilable(String))
        end
        def sanitize_shop_domain(shop_domain, myshopify_domain: nil)
          uri = uri_from_shop_domain(shop_domain, myshopify_domain)
          return nil if uri.nil? || uri.host.nil? || uri.host.empty?

          trusted_domains(myshopify_domain).each do |trusted_domain|
            host = T.cast(uri.host, String)
            uri_domain = uri.domain
            next if uri_domain.nil?

            no_shop_name_in_subdomain = host == trusted_domain
            from_trusted_domain = trusted_domain == uri_domain

            if unified_admin?(uri) && from_trusted_domain
              return myshopify_domain_from_unified_admin(uri)
            end
            return nil if no_shop_name_in_subdomain || host.empty?
            return host if from_trusted_domain
          end
          nil
        end

        sig do
          params(
            shop: String,
            myshopify_domain: T.nilable(String),
          ).returns(String)
        end
        def sanitize!(shop, myshopify_domain: nil)
          host = sanitize_shop_domain(shop, myshopify_domain: myshopify_domain)
          if host.nil? || host.empty?
            raise Errors::InvalidShopError,
              "shop must be a trusted Shopify domain (see ShopValidator::TRUSTED_SHOPIFY_DOMAINS), got: #{shop.inspect}"
          end

          host
        end
