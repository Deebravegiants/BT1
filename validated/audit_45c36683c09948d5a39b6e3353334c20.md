### Title
The strategy fee can be bypassed by opening a leveraged position via `flash_position` instead of `multiply` - (File: contracts/controller/src/strategies/flash_position.rs)

### Summary
The pool charges a strategy fee (`flashloan_fee` bps) on debt drawn through `create_strategy` only when the controller passes `charge_fee = true`. The `multiply` entrypoint passes `true`, but `flash_position` passes `false` while delivering the same economic result: borrowed assets are minted, forwarded to a user-chosen receiver contract, the receiver produces collateral, and the collateral is deposited into the same leveraged position. An unprivileged user can therefore replicate any `multiply` flow through `flash_position` and pay zero fee, so the treasury never collects strategy fees that the fee parameter is meant to generate.

### Finding Description
`pool::create_strategy` withholds a fee computed from `params.flashloan_fee` only if the controller's `charge_fee` flag is set; the fee is kept in pool cash and minted as protocol revenue via `interest::add_protocol_revenue`. [1](#0-0)  The controller exposes two user-reachable leverage entrypoints that call it with opposite flags:

- `process_multiply` calls `borrow_into_controller(..., true, PositionAction::Multiply, ...)`, charging the fee. [2](#0-1) 
- `process_flash_position` → `mint_and_forward` calls `borrow_into_controller(..., false, PositionAction::FlashPos, ...)`, explicitly documented as "fee-free debt", and emits `fee: 0`. [3](#0-2) 

Functionally, `flash_position` subsumes `multiply`: it mints the debt, transfers the full `amount` to an arbitrary WASM `receiver`, invokes `execute_flash_position` on it, then measures and deposits whatever collateral assets the receiver returns, subject to the same `require_can_supply`, position gates, and `strategy_finalize` health checks as `multiply`. [4](#0-3)  The only extra constraint is `is_flashloanable` on the debt market and a receiver contract — both trivially satisfiable by the user's own receiver that performs the same swap `multiply` would do through the router. `require_flash_position_still_open` only forces the position to remain open, which is exactly what a `multiply` user wants anyway. [5](#0-4) 

The "fee-free" wording suggests this may be an intentional distinction, but it makes the `multiply` fee unenforceable: any fee-sensitive user routes around it, mirroring the reported `mintDepositInQueue` deposit-fee bypass where an alternate entrypoint reaches the same end state while skipping the treasury fee.

### Impact Explanation
The protocol's `flashloan_fee` revenue on leveraged-position opens is fully avoidable. All strategy volume migrates to `flash_position`, so `revenue` (and ultimately `claim_revenue` payouts) loses the strategy-fee component the parameterization implies. No user funds are stolen directly; the impact is lost unclaimed yield for the treasury — same as the source report.

### Likelihood Explanation
Any unprivileged account can call `flash_position` with its own receiver contract. There is no economic or technical barrier beyond the `is_flashloanable` flag, which is the same flag that makes flash borrowing attractive in the first place. Rational users always prefer the free path once they know it exists.

### Recommendation
Charge the strategy fee in `flash_position` identically to `multiply` (pass `charge_fee = true` in `mint_and_forward`), or — if fee-free flash positions are intentional — remove the fee from `multiply` as well, since an inconsistent fee policy provides no revenue while penalizing only users of the simpler entrypoint.

### Proof of Concept
1. Admin configures a market with `flashloan_fee = 50` bps and `is_flashloanable = true`, collateral market listed and supply-enabled.
2. User A calls `multiply(account, spoke, collateral=X, debt_to_flash_loan=1_000_000, debt=D, mode=Multiply, swap=...)`: pool mints debt for 1,000,000 and sends 995,000; 5,000 is booked as revenue via `add_protocol_revenue`. [6](#0-5) 
3. User B deploys a receiver implementing `execute_flash_position` that swaps the received debt asset into collateral X on a DEX and transfers X to the controller.
4. User B calls `flash_position` with the same `debt`, `amount=1_000_000`, `collaterals=[(X, min)]`, `receiver=B's contract`. The pool mints the full 1,000,000 with `charge_fee=false`, the receiver returns collateral X, `process_deposit` credits it, and `strategy_finalize` passes the same health checks as step 2.
5. Both accounts hold equivalent leveraged positions; treasury revenue from step 3 is zero versus 5,000 in step 2 — the fee was bypassed by choosing the alternate entrypoint.

Caveat: I could not fully verify `borrow_into_controller`'s internals (`strategies/mod.rs`) or whether governance docs classify the fee-free flash position as an accepted design decision; if it is a documented ADR choice, this finding should be rejected per the scope rules.

/// Computes the strategy fee from `flashloan_fee` bps when `charge_fee` is true;
/// returns 0 otherwise (does not consult the market flash-loan enable flag).
///
/// Panics if the fee would exceed principal when charging.
fn compute_fee(env: &Env, cache: &Cache, amount: i128, charge_fee: bool) -> i128 {
    if !charge_fee {
        return 0;
    }
    let fee = Bps::from(i128::from(cache.params().flashloan_fee)).flash_loan_fee_on(env, amount);
    assert_with_error!(env, fee <= amount, FlashLoanError::StrategyFeeExceeds);
    fee
}

/// Mints fee-free debt, verifies the controller receipt against the pool result,
/// then forwards it and returns the receiver's measured receipt.
fn mint_and_forward(
    env: &Env,
    account: &mut Account,
    debt: &HubAssetKey,
    amount: i128,
    receiver: &Address,
    cache: &mut Context,
) -> i128 {
    let controller = env.current_contract_address();
    let before = token::Client::new(env, &debt.asset).balance(&controller);

    let reported = borrow_into_controller(
        env,
        account,
        debt,
        amount,
        false,
        PositionAction::FlashPos,
        cache,
    );

    let measured = balance_delta_since(env, &debt.asset, &controller, before);
    assert_with_error!(env, measured == reported, GenericError::InternalError);
    assert_with_error!(env, measured > 0, GenericError::AmountMustBePositive);

    let forwarded = transfer_amount_measured(
        env,
        &debt.asset,
        &controller,
        receiver,
        measured,
        GenericError::AmountMustBePositive,
    );
    assert_with_error!(env, forwarded > 0, GenericError::AmountMustBePositive);
    forwarded
}

pub(crate) fn require_flash_position_still_open(env: &Env, account: &Account, debt: &HubAssetKey) {
    assert_with_error!(
        env,
        !account.is_empty() && !account.debt_free(),
        StrategyError::FlashPositionClosed
    );
    let Some(pos) = account.borrow_positions.get(debt.clone()) else {
        panic_with_error!(env, StrategyError::FlashPositionClosed);
    };
    assert_with_error!(
        env,
        pos.scaled_amount > 0 && !account.supply_positions.is_empty(),
        StrategyError::FlashPositionClosed
    );
}
