## Title
Uncontrolled Resource Consumption via Unbounded `handle_unsigned` Message Batches — ([File: modules/pallets/ismp/src/lib.rs])

### Summary
`pallet_ismp::Pallet::handle_unsigned` accepts an unbounded `Vec<Message>`, where each `Message` variant (`Request`, `Response`, `Timeout`, `Consensus`) in turn carries unbounded inner vectors (`requests: Vec<PostRequest>`, `requests: Vec<GetRequest>` with unbounded `keys: Vec<Vec<u8>>`, proof bytes, etc.). Because this is an **unsigned, free** extrinsic, the Substrate transaction pool's `ValidateUnsigned::validate_unsigned` implementation fully executes `Self::execute(messages.clone())` — i.e., runs complete consensus/state-proof/trie verification — on *every node* that merely receives the transaction over the p2p network, before any block inclusion or fee is charged. The `#[pallet::weight(weight())]` annotation on the call is a flat constant (`Weight::from_parts(300_000_000, 0)`) that does not scale with the number of messages, requests, or keys submitted, so nothing throttles or bounds the actual CPU/verification cost an attacker can trigger with a single crafted transaction.

### Finding Description
`handle_unsigned` is declared with a static weight: [1](#0-0) 
and the weight helper itself is a hard-coded constant unrelated to batch size: [2](#0-1) 

Crucially, `validate_unsigned` — which runs on **every node's transaction pool** for **every unsigned transaction received/gossiped**, not just the block author — performs the *entire* message-execution pipeline before deciding validity: [3](#0-2) 

The docs confirm this design intent (full execution during pool validation, assumed cheap): [4](#0-3) 

Nothing bounds the size of `messages: Vec<Message>`, nor the inner collections that drive the actual verification cost:
- `RequestMessage.requests: Vec<PostRequest>` and `ResponseMessage.requests: Vec<GetRequest>` are plain `Vec`, not `BoundedVec`.
- Each `GetRequest.keys` is an unbounded `Vec<Vec<u8>>`, and `verify_state_proof` loops over every key doing full trie/RLP/child-trie/SPV verification per key with no cap: [5](#0-4) [6](#0-5) [7](#0-6) 

The `pallet-state-coprocessor::handle_unsigned` variant is equally unbounded, with the same "execute fully in `validate_unsigned`" pattern and a flat DB-weight annotation unrelated to the number of `GetRequest`s or keys in the batch: [8](#0-7) 

An attacker with no privileges can submit (via RPC to any node, or by direct p2p gossip) a single `handle_unsigned` call containing thousands of `Message::Request`/`Message::Response` entries, each with the maximum practically-encodable number of keys/storage-proof nodes, or a consensus/fraud-proof message with maximally-sized cryptographic proof data. Every full node that receives this transaction (to gossip it or to consider it for inclusion) will run the full `execute()` path — cryptographic signature checks, trie/SPV proof walks, RLP decoding, MMR verification — before rejecting it (e.g., for a bad or already-used proof), since none of this validation is gated behind a cheap, size-based pre-check. Because it is a free/unsigned transaction, this can be repeated indefinitely, with content-hash "provides" tags trivially varied so pool dedup does not suppress resubmission, resulting in sustained CPU exhaustion across the validator/collator set.

### Impact Explanation
This maps to CWE-400 (Uncontrolled Resource Consumption) exactly as in the reported Kibana/Timelion analog: attacker-controlled input drives an amount of computation vastly disproportionate to the fixed cost the system assumes, causing a Denial of Service. Here the blast radius is broader than a single service — every full node (validator, collator, RPC node) that processes the unsigned extrinsic for pool validation pays the real verification cost, not just whichever node authors the block. Sustained submission of such transactions can degrade block production (validators/collators busy validating spam instead of producing/importing blocks) and RPC availability, which is a High-severity liveness/DoS impact to the "route unable to deliver messages" category called out in scope.

### Likelihood Explanation
Reachable by any external, unprivileged actor able to submit a transaction to a public RPC endpoint or gossip a transaction on the p2p network — no keys, governance, or special role required. The only friction is proof validity for consensus/timeout/response paths; but for the `Request` message path (or a consensus message using an already-known consensus_state_id with an intentionally malformed/huge but structurally-parseable proof), the expensive decode/verification work happens before the final rejection, and repeated variation defeats mempool dedup.

### Recommendation
- Enforce hard per-batch and per-message bounds (e.g. `BoundedVec` with a `MaxMessages`, `MaxRequestsPerMessage`, `MaxKeysPerGetRequest`, `MaxProofSize`) checked cheaply *before* any cryptographic or trie verification is attempted, both in `validate_unsigned` and in `execute`.
- Compute `#[pallet::weight(...)]` as a function of the actual submitted batch/message/key sizes rather than a flat constant, so oversized calls are rejected/priced at the extrinsic-length/weight-limit stage rather than only after full execution.
- Consider performing only cheap, size/structure sanity checks in `validate_unsigned` (deferring full proof verification to block execution) to avoid making network-wide pool validation as expensive as full execution.

### Proof of Concept
1. Craft a `pallet_ismp::Call::handle_unsigned { messages }` where `messages` is a `Vec<Message::Request(RequestMessage)>` containing many thousands of syntactically valid but ultimately-invalid `PostRequest`s (or a `Message::Response` with `GetRequest.keys` populated with tens of thousands of distinct keys and an oversized but decodable storage proof).
2. Submit this transaction unsigned via any public RPC node (`author_submitExtrinsic`) or directly gossip it on the p2p network.
3. Observe that every receiving node's transaction pool invokes `ValidateUnsigned::validate_unsigned`, which calls `Self::execute(messages.clone())` [9](#0-8) , performing full trie/SPV/signature verification for every request/key in the batch — work whose cost scales with attacker-chosen batch size — before finally rejecting the transaction as invalid (e.g., `UnknownRequest`/`InsufficientProofHeight`).
4. Repeat with minor content variation (changes `msg_hash`/`provides` tag) to bypass pool-level dedup and sustain the CPU load across nodes.

## Transaction fees

Pallet ISMP uses unsigned transactions for executing cross-chain messages. This means all cross-chain messages received are executed for free as unsigned transactions. The upside to this is that it cannot be exploited as a spam vector, since the transaction pool will check if the submitted extrinsics are valid before they are included in the pool. This validity check ensures that the transaction can be successfully executed and contains valid proofs. Malformed messages or those with invalid proofs are filtered out by the transaction pool validation logic preventing unnecessary processing and potential network congestion.

pub fn verify_state_proof<H: Keccak256 + Send + Sync>(
	keys: Vec<Vec<u8>>,
	root: H256,
	proof: &Proof,
	ismp_address: H160,
) -> Result<BTreeMap<Vec<u8>, Option<Vec<u8>>>, Error> {
	// Reject repeats before doing any work at all. They are already an error — repeats collapse
	// in the map returned below, so the caller's key-count check fails — but reaching that
	// check means every repeat has been verified first, and for account queries that is a
	// clone of the whole contract proof each time.
	let mut seen_keys = BTreeSet::new();
	for key in &keys {
		if !seen_keys.insert(key.as_slice()) {
			return Err(EvmStateMachineError::DuplicateKey.into());
		}
	}

	let evm_state_proof = decode_evm_state_proof(proof)?;
	let mut map = BTreeMap::new();
	let mut contract_to_keys = BTreeMap::new();
	let mut contract_account_queries = Vec::new();

	// Group keys by the contract address they belong to
	for key in keys {
		// For keys that are 52 bytes we expect the first 20 bytes to be the contract address and
		// the last 32 bytes the slot hash.
		// For keys that are 20 bytes we expect that to the
		// contract or account address.
		// For keys that are 32 bytes we expect that to be a slothash in
		// the Ismp EVM host
		let contract_address = if key.len() == 52 {
			H160::from_slice(&key[..20])
		} else if key.len() == 32 {
			ismp_address
		} else if key.len() == 20 {
			contract_account_queries.push(H160::from_slice(&key));
			continue;
		} else {
			return Err(EvmStateMachineError::UnsupportedKeyLength.into());
		};
		let entry = contract_to_keys.entry(contract_address.0.to_vec()).or_insert(vec![]);

		let slot_hash = if key.len() == 52 {
			H::keccak256(&key[20..]).0.to_vec()
		} else {
			H::keccak256(&key).0.to_vec()
		};

		entry.push((key, slot_hash));
	}

	// The storage proof must correspond exactly to the contracts a key was requested from:
	// every one covered, and nothing else. Both directions are settled here, before a single
	// entry is resolved — resolving one clones the whole contract proof and rebuilds its trie,
	// so checking as we go would let a proof padded with unrequested accounts do that work
	// before being rejected, and would make which error surfaces depend on map ordering.
	// The honest prover already emits exactly this set, deriving its map from the requested
	// keys, so nothing legitimate is turned away.
	let result = contract_to_keys
		.clone()
		.into_keys()
		.all(|contract| evm_state_proof.storage_proof.contains_key(&contract));
	if !result {
		return Err(EvmStateMachineError::IncompleteStorageProof.into());
	}

	if evm_state_proof
		.storage_proof
		.keys()
		.any(|contract| !contract_to_keys.contains_key(contract))
	{
		return Err(EvmStateMachineError::UnrequestedContractProof.into());
	}

	for (contract_address, storage_proof) in evm_state_proof.storage_proof {
		// Unreachable: the correspondence check above already rejected any entry without a
		// requested key. Kept as a hard error rather than a skip so the invariant survives if
		// that check is ever moved or relaxed.
		let Some(keys) = contract_to_keys.remove(&contract_address) else {
			return Err(EvmStateMachineError::UnrequestedContractProof.into());
		};

		let contract_root = get_contract_account::<H>(
			evm_state_proof.contract_proof.clone(),
			&contract_address,
			root,
		)?
		.storage_root
		.0
		.into();

		let slot_hashes = keys.iter().map(|(_, slot_hash)| slot_hash.clone()).collect();
		let values = get_values_from_proof::<H>(slot_hashes, contract_root, storage_proof)?;
		keys.into_iter().zip(values).for_each(|((key, _), value)| {
			map.insert(key, value);
		});
	}

/// Verify state proof and return key-value map.
pub fn verify_state_proof<H: Keccak256 + Send + Sync>(
	keys: Vec<Vec<u8>>,
	root: H256,
	proof: &Proof,
	ismp_address: H160,
) -> Result<BTreeMap<Vec<u8>, Option<Vec<u8>>>, Error> {
	let pharos_proof = decode_pharos_state_proof(proof)?;

	let state_root = root;

	// Pharos uses a flat trie — storage proofs verify directly against state_root.
	let mut map = BTreeMap::new();

	for key in keys {
		let (contract_addr, slot_hash) = if key.len() == 52 {
			// First 20 bytes = contract address, last 32 = slot hash
			let addr = H160::from_slice(&key[..20]);
			(addr, key[20..].to_vec())
		} else if key.len() == 32 {
			// Direct slot hash for the ISMP host contract
			(ismp_address, key.clone())
		} else if key.len() == 20 {
			// Account query which verifies account proof and return raw account value
			let address: [u8; 20] = key
				.clone()
				.try_into()
				.map_err(|e: Vec<u8>| PharosStateMachineError::InvalidAddressLength(e.len()))?;
			let account_data = pharos_proof
				.account_proofs
				.get(&key)
				.ok_or(PharosStateMachineError::MissingAccountProof)?;

			spv::verify_proof(
				&account_data.proof_nodes,
				&address,
				&account_data.raw_value,
				&state_root.0,
			)
			.map_err(|e| PharosStateMachineError::SpvVerificationFailed(alloc::format!("{e:?}")))?;

			map.insert(key, Some(account_data.raw_value.clone()));
			continue;
		} else {
			return Err(PharosStateMachineError::UnsupportedKeyLength.into());
		};

		let contract_address: [u8; 20] = contract_addr.0;

		let slot_key: [u8; 32] = slot_hash
			.clone()
			.try_into()
			.map_err(|e: Vec<u8>| PharosStateMachineError::InvalidSlotHashLength(e.len()))?;

		// Check if this is a non-existence proof
		if let Some(non_existence) = pharos_proof.non_existence_proofs.get(slot_key.as_slice()) {
			spv::verify_non_existence_proof(
				&non_existence.proof_nodes,
				&spv::build_storage_key(&contract_address, &slot_key),
				&state_root.0,
				&non_existence.sibling_proofs,
			)
			.map_err(|e| PharosStateMachineError::SpvVerificationFailed(alloc::format!("{e:?}")))?;
			map.insert(key, None);
			continue;
		}

		// Otherwise verify existence proof
		let storage_proof_nodes = pharos_proof
			.storage_proof
			.get(slot_key.as_slice())
			.ok_or(PharosStateMachineError::MissingStorageProof)?;

		let storage_value = pharos_proof
			.storage_values
			.get(&slot_hash)
			.ok_or(PharosStateMachineError::MissingStorageValue)?;

		// Pad value to 32 bytes for proof verification
		let mut padded_value = [0u8; 32];
		if storage_value.len() <= 32 {
			padded_value[32 - storage_value.len()..].copy_from_slice(storage_value);
		} else {
			return Err(PharosStateMachineError::StorageValueTooLarge.into());
		}

		spv::verify_proof(
			storage_proof_nodes,
			&spv::build_storage_key(&contract_address, &slot_key),
			&padded_value,
			&state_root.0,
		)
		.map_err(|e| PharosStateMachineError::SpvVerificationFailed(alloc::format!("{e:?}")))?;

		map.insert(key, Some(storage_value.clone()));
	}

	Ok(map)
}
