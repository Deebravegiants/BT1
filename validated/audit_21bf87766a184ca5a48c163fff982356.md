## Title
Unauthenticated legacy web-API trigger request drives unbounded workflow-DON fan-out and callback-map growth - ([File: core/services/gateway/handlers/capabilities/handler.go])

## Summary
`HandleLegacyUserMessage` in `core/services/gateway/handlers/capabilities/handler.go` accepts any structurally-valid, self-signed legacy `Message` and, after only payload/timestamp checks, unconditionally stores it in `savedCallbacks` and forwards it via `don.SendToNode` to **every** member of the targeted DON, with an explicit `// TODO: apply allowlist and rate-limiting here` marking the missing gateway-side check [1](#0-0) . `msg.Validate()` only requires that the signature recover to *some* ECDSA address — it does not check that address against any registry or allowlist [2](#0-1) , so any anonymous actor can generate a throwaway keypair, self-sign a `web_api_trigger` message with a valid `DonID`, and reach this fan-out path without possessing any real credential.

## Finding Description
`gateway.ProcessRequest` routes any request carrying a non-empty `DonID` down the "legacy" path, calling only `msg.Validate()` before dispatching to the DON's handler [3](#0-2) . `Validate()` checks field lengths and null-byte suffixes and then calls `ExtractSigner()`, which recovers *a* signer address from the signature — it never checks that address is a known/registered/allowlisted user [4](#0-3) . Because ECDSA keypair generation and signing are free and require no registration, this "signature" check is not an authentication control against unprivileged access — it is effectively a no-op gate confirmed by the test suite, which freely generates a fresh key and signs arbitrary messages to pass `Validate()` [5](#0-4) .

Once inside `HandleLegacyUserMessage`, the code validates payload structure and timestamp freshness, then reaches the explicit TODO marker before unconditionally storing the callback and fanning out to every DON member node [1](#0-0) . This confirms the claim's central assertion: the Gateway itself performs no allowlist/authorization check before persisting state and dispatching network RPCs to all DON nodes.

However, further investigation reveals a mitigating control the original report did not fully account for: the actual **workflow-trigger capability** on each node (`core/capabilities/webapi/trigger/trigger.go`) enforces its own `allowedSenders` and per-sender/global `rateLimiter` checks before a trigger is ever delivered to a workflow [6](#0-5) , and `RegisterTrigger` requires `AllowedSenders` to be non-empty [7](#0-6) . This means an attacker cannot actually cause unauthorized workflow *execution* — that impact is blocked downstream. What remains unmitigated, exactly as the claim states, is the **Gateway-to-node network fan-out** itself: the Gateway sends the RPC to every node in the DON regardless of sender identity, meaning the wasted network/CPU cost of dispatch and per-node rejection processing is fully attacker-controllable with no gateway-side authentication or rate limit gating it. The `savedCallbacks` map growth is separately bounded by `pruneCallbacks()` (`MaxSavedCallbacks`, `CallbackMaxAgeSec`) [8](#0-7) , as the report itself acknowledges.

I was unable to fully confirm, within available tool budget, whether any additional gateway-level global rate limiter exists in front of `ProcessRequest` outside of `handlers/capabilities/handler.go`'s node-side `nodeRateLimiter` (which the report correctly notes only rate-limits outgoing node responses, not incoming user triggers) — no `RateLimit`/`limiter` references were found in `core/services/gateway/gateway.go` itself, consistent with the claim that no gateway-level ingress rate limit exists for this path.

## Impact Explanation
This maps to a resource-exhaustion / availability impact class rather than unauthorized fund movement or key exfiltration: an unauthenticated caller can force the Gateway to dispatch network RPCs to every node of an arbitrary DON repeatedly, with no per-caller cost or gating, consuming Gateway and node network/CPU resources. It does **not** result in unauthorized workflow execution, since the node-side capability (`webapiTrigger`) independently enforces `allowedSenders` and rate limiting before actually invoking a workflow. The severity is therefore bounded to DON/gateway resource strain rather than the more severe "unauthorized job run" impact class, and is further capped by the existing `savedCallbacks` size/age eviction.

## Likelihood Explanation
The `// TODO: apply allowlist and rate-limiting here` comment in `core/services/gateway/handlers/capabilities/handler.go` confirms this is a known, unresolved gap. Exploitation only requires generating a throwaway ECDSA keypair (free, no registration), guessing/knowing a valid `DonID` string, and crafting a structurally valid `web_api_trigger` payload with a fresh timestamp — no credentials, session, or registered identity are required to reach the fan-out code path.

## Recommendation
Add gateway-side authorization/allowlisting (analogous to the Vault gateway's `Authorizer`/`AllowListBasedAuth` pattern) or a per-caller/global rate limiter in `HandleLegacyUserMessage`, gating the request before it is persisted to `savedCallbacks` or forwarded to DON nodes via `don.SendToNode`, so that fan-out cost cannot be driven unboundedly by unauthenticated/unregistered senders.

## Proof of Concept
1. Generate a fresh ECDSA keypair (`crypto.GenerateKey()` — no registration needed).
2. Construct an `api.Message` with `Body.DonID` set to a known/targeted workflow DON ID, `Body.Method = "web_api_trigger"`, and a valid `TriggerRequestPayload` (current timestamp, non-empty topics), then call `msg.Sign(privateKey)`.
3. Repeatedly POST this JSON-RPC-encoded legacy request to the Gateway's user HTTP endpoint (`gateway.ProcessRequest`) with unique `MessageID`s and no `Authorization` header.
4. Observe (as in `TestHandlerReceiveHTTPMessageFromClient`, `core/services/gateway/handlers/capabilities/handler_test.go` L236-260) that each request causes `don.SendToNode` to be invoked for every DON member, confirming unauthenticated fan-out; separately verify (as in `trigger_test.go`) that the node-side `allowedSenders` check independently blocks unauthorized workflow triggering from completing.

func (h *handler) pruneCallbacks() {
	h.mu.Lock()
	defer h.mu.Unlock()

	// First, remove expired callbacks.
	maxAge := time.Duration(h.config.CallbackMaxAgeSec) * time.Second
	now := time.Now()
	var expired int
	for id, cb := range h.savedCallbacks {
		if now.Sub(cb.createdAt) > maxAge {
			delete(h.savedCallbacks, id)
			expired++
		}
	}

	// If there are still too many callbacks, sort them by creation time and remove the oldest ones.
	maxSize := h.config.MaxSavedCallbacks
	var evicted int
	if len(h.savedCallbacks) > maxSize {
		type entry struct {
			id        string
			createdAt time.Time
		}
		entries := make([]entry, 0, len(h.savedCallbacks))
		for id, cb := range h.savedCallbacks {
			entries = append(entries, entry{id, cb.createdAt})
		}
		sort.Slice(entries, func(i, j int) bool {
			return entries[i].createdAt.Before(entries[j].createdAt)
		})
		// Trim to maxSize/2 to avoid sorting the list too frequently.
		for _, e := range entries[:len(entries)-maxSize/2] {
			delete(h.savedCallbacks, e.id)
			evicted++
		}
	}

	if expired > 0 || evicted > 0 {
		h.lggr.Infow("Pruned savedCallbacks", "expired", expired, "evicted", evicted, "remaining", len(h.savedCallbacks))
	}
}

func (m *Message) Validate() error {
	if m == nil {
		return errors.New("nil message")
	}
	if len(m.Signature) != MessageSignatureHexEncodedLen {
		return errors.New("invalid hex-encoded signature length")
	}
	if len(m.Body.MessageID) == 0 || len(m.Body.MessageID) > MessageIDMaxLen {
		return errors.New("invalid message ID length")
	}
	if strings.HasSuffix(m.Body.MessageID, NullChar) {
		return errors.New("message ID ending with null bytes")
	}
	if len(m.Body.Method) == 0 || len(m.Body.Method) > MessageMethodMaxLen {
		return errors.New("invalid method name length")
	}
	if strings.HasSuffix(m.Body.Method, NullChar) {
		return errors.New("method name ending with null bytes")
	}
	if len(m.Body.DonID) == 0 || len(m.Body.DonID) > MessageDonIDMaxLen {
		return errors.New("invalid DON ID length")
	}
	if strings.HasSuffix(m.Body.DonID, NullChar) {
		return errors.New("DON ID ending with null bytes")
	}
	if len(m.Body.Receiver) != 0 && len(m.Body.Receiver) != MessageReceiverLen {
		return errors.New("invalid Receiver length")
	}
	signerBytes, err := m.ExtractSigner()
	if err != nil {
		return err
	}
	m.Body.Sender = utils.StringToHex(string(signerBytes))
	return nil
}
