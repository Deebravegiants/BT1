Based on the code I was able to examine, this is a confirmed vulnerability.

### Title
Magic QR "reset_wifi_credentials" / "reset_mirror_calibration" actions execute privileged device resets before any operator authentication - (File: src/plans/qr_scan/operator.rs, src/plans/mod.rs)

### Summary
`qr_scan::operator::Data::try_parse` recognizes the unauthenticated regex pattern `magic_action:reset_wifi_credentials` / `magic_action:reset_mirror_calibration` and maps it to `Data::MagicResetWifi` / `Data::MagicResetMirror` [1](#0-0) . These variants are dispatched by `handle_magic_operator_qr_code`, which immediately calls `reset_wifi_and_ensure_network` or `reset_mirror_calibration` — with no operator credential check at all — before the code ever reaches `verify_operator_qr_code` (the backend call that validates operator identity) [2](#0-1) .

### Finding Description
In both `scan_initial_qr_codes` and `scan_remaining_qr_codes`, the flow is: scan a QR code presented to the camera → call `self.handle_magic_operator_qr_code(orb, operator_qr_code)` → only afterwards call `self.verify_operator_qr_code(...)` [3](#0-2) . `handle_magic_operator_qr_code` pattern-matches on the parsed `qr_scan::operator::Data`: for `Data::Normal(qr_code)` it simply forwards the code to be verified later, but for `Data::MagicResetMirror` / `Data::MagicResetWifi` it directly performs the privileged action (`reset_mirror_calibration`, `reset_wifi_and_ensure_network`) and returns `Ok(None)`, terminating the loop iteration without ever calling `verify_operator_qr_code` for that code [4](#0-3) . There is no operator-authorization gate, no session state requirement, and no check that a legitimate operator scan preceded this — any person able to present a QR code to the Orb's camera during the operator-scan phase (which occurs before any user identity or biometric capture, i.e., in the idle/unauthenticated phase) can trigger these actions. The regex itself imposes no secrecy or signature requirement — the string is public/guessable and documented in the repo's own test suite [5](#0-4) .

### Impact Explanation
`reset_wifi_and_ensure_network` calls `network::reset()`, which shells out to `wpa-supplicant-interface restore-default-config` and `reconfigure`, wiping the Orb's configured Wi-Fi credentials and forcing it to reconnect via whatever default/fallback network flow exists [6](#0-5) . `reset_mirror_calibration` overwrites the on-disk mirror calibration file and forces a live recalibration, degrading device targeting accuracy for legitimate signups until re-calibrated [7](#0-6) . Both are unauthenticated device-tampering / denial-of-service primitives reachable by anyone physically near an idle Orb — matching a "device state manipulation without authorization" bounty class, though it is a device-availability/config-integrity issue rather than a biometric/identity-binding compromise.

### Likelihood Explanation
Trivial and fully repeatable: the attacker only needs to print/display the exact string `magic_action:reset_wifi_credentials` or `magic_action:reset_mirror_calibration` as a QR code and present it during the normal operator-QR scanning phase, which is the default idle behavior of the device before any signup begins. No credentials, tokens, or operator device access are required.

### Recommendation
Gate `Data::MagicResetWifi` / `Data::MagicResetMirror` handling behind the same operator authentication used for `Data::Normal` (i.e., only accept magic actions embedded within, or immediately following, a QR code that has separately passed `verify_operator_qr_code`), or require a cryptographically signed/rotating token instead of a static well-known string.

### Proof of Concept
Integration test (extends existing `#[cfg(test)] mod tests` in `src/plans/qr_scan/operator.rs` / `src/plans/mod.rs`):
1. Build a `MasterPlan` via the existing test harness with `operator_qr_code(Some(Some("magic_action:reset_wifi_credentials")))`.
2. Call `ms.scan_operator_qr_code(&mut fake_orb, None)` then `ms.handle_magic_operator_qr_code(&mut fake_orb, op_code)`.
3. Assert that `reset_wifi_and_ensure_network`/`network::reset()` was invoked (e.g., via a mockable `network::reset` or observing `orb.ui.magic_qr_action_completed` firing) **without** any prior successful `verify_operator_qr_code` call having occurred — i.e., assert the action fires even though no backend operator-validation step was ever run for that code.
4. Expected (fixed) behavior: the reset action should only be honored if a prior/paired `verify_operator_qr_code` call for a `Normal` operator QR succeeded in the same session; the test should fail against current code (action fires unconditionally) and pass once gating is added.

                "reset_mirror_calibration" => Some(Data::MagicResetMirror),
                _ => None,
            };
        }
        None

    async fn handle_magic_operator_qr_code(
        &self,
        orb: &mut Orb,
        qr_code: qr_scan::operator::Data,
    ) -> Result<Option<qr_scan::user::Data>> {
        match qr_code {
            qr_scan::operator::Data::Normal(qr_code) => {
                tracing::info!("Operator QR-code detected: {qr_code:?}");
                Ok(Some(qr_code))
            }
            qr_scan::operator::Data::MagicResetMirror => {
                tracing::info!("Magic QR-code detected: Reset Mirror");
                dd_incr!("main.count.signup.during.general.magic_qr.reset_mirror");
                let result = self.reset_mirror_calibration(orb).await;
                if let Err(err) = &result {
                    tracing::error!("Failed to reset mirror calibration: {err}");
                }
                orb.ui.magic_qr_action_completed(result.is_ok());
                Ok(None)
            }
            qr_scan::operator::Data::MagicResetWifi => {
                tracing::info!("Magic QR-code detected: Reset Wi-Fi");
                dd_incr!("main.count.signup.during.general.magic_qr.reset_wifi");
                let result = self.reset_wifi_and_ensure_network(orb).await;
                if let Err(err) = &result {
                    tracing::error!("Failed to reset wifi: {err}");
                }
                orb.ui.magic_qr_action_completed(result.is_ok());
                Ok(None)
            }
        }
    }
