### Title
Unbounded accrued RAY valuation permanently freezes a saturated lending market - (File: common/src/rates/scaling.rs)

### Summary
A sufficiently large market at sustained high utilization can make accrued debt/supply value exceed the `i128` RAY domain before the borrow-index ceiling engages. [1](#0-0)   
Once that state is reached, every market mutation first runs accrual and reverts with `MathOverflow`, permanently blocking withdrawal, repayment, liquidation, and further index updates for that market. [2](#0-1) 

### Finding Description
`accrue_step` converts stored scaled borrow and supply balances to their original RAY values before calculating utilization and updating the borrow index. [3](#0-2)   
Both conversions call `scaled_to_original`, which performs `scaled.mul(index)` without saturation or an explicit pre-clamp. [4](#0-3)   
The underlying fixed-point multiplication panics with `MathOverflow` when the result does not fit `i128`. [5](#0-4)   
The index cap is checked only after that multiplication, so a large enough scaled balance can overflow the valuation before `MAX_BORROW_INDEX_RAY` is reached. [6](#0-5)   

An unprivileged account can create the precondition by supplying the market, supplying collateral in another market, borrowing nearly all available liquidity, and then calling `update_indexes(caller, [hub_asset])` after the index has grown sufficiently. [7](#0-6)   
The regression fixture demonstrates a one-billion-token, 18-decimal market at 98% utilization reaching the failure after multi-year accrual. [8](#0-7) 

### Impact Explanation
The failed accrual happens inside `global_sync`, which every mutation of the market executes before applying the requested operation. [9](#0-8)   
After the overflow point, no transaction can advance `last_timestamp` because the failing valuation occurs before `mark_accrued`, so subsequent operations repeat the same panic. [10](#0-9)   
The regression test confirms that both supplier withdrawal and borrower repayment revert with `MathOverflow`, while the stored borrow index remains below its configured ceiling. [11](#0-10)   
This permanently freezes all user funds and debt operations in the affected market unless an upgrade changes the arithmetic path. [12](#0-11) 

### Likelihood Explanation
The attack requires an extremely large token position and sustained high utilization long enough for the compounded index to cross the RAY-value boundary. [13](#0-12)   
No privileged call is required at exploitation time because `update_indexes` is callable by any authenticated caller, while `supply` and `borrow` can create the attacker's market state. [14](#0-13)   
The practical barrier is the capital requirement and token supply/cap constraints rather than an authorization barrier. [15](#0-14) 

### Recommendation
Make valuation overflow non-fatal before index growth is applied: compute utilization with widened arithmetic or saturating values, clamp the borrow index before unscaled valuation can overflow, and ensure `last_timestamp` advances through a capped no-interest step once the index ceiling applies. [16](#0-15)   
Regression coverage should assert that withdrawal, repayment, liquidation, and `update_indexes` remain callable at the market's maximum represented value rather than only testing the current overflow cliff. [11](#0-10) 

### Proof of Concept
The existing regression test constructs the reachable sequence:

1. Supply `1_000_000_000 * 10^18` base units of an 18-decimal asset to its market. [17](#0-16) 
2. Supply collateral in another market and borrow 98% of the first market's liquidity. [18](#0-17) 
3. Advance ledger time in yearly intervals and call the permissionless `update_indexes` path until accrual reverts. [19](#0-18) 
4. Observe `MathOverflow` while the borrow index is still below `MAX_BORROW_INDEX_RAY`. [20](#0-19) 
5. Subsequent `withdraw` and `repay` calls revert with the same `MathOverflow`, proving the market is frozen. [21](#0-20)

/// grows past 170x in a few years, and the next accrual panics inside

#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }

    assert_contract_error(failed, errors::MATH_OVERFLOW);

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
