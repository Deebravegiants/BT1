## Analysis

The Zebra advisory describes a stale "seen" entry that gets recorded early (before full validation completes) and is never cleaned up when validation subsequently rejects the item — permanently blocking legitimate future retries until an unrelated event or restart clears it (CWE-459, Incomplete Cleanup).

The closest concrete analog in this codebase is the Vault gateway authorization pipeline's `RequestReplayGuard`.

### Title
Vault replay-guard digest is recorded before owner-match validation and is never released on rejection, permanently locking out legitimate retries - (File: core/capabilities/vault/authorizer.go)

### Summary
`authorizer.AuthorizeRequest` records a request's replay-guard digest via `RequestReplayGuard.CheckAndRecord` immediately after the underlying auth mechanism (allowlist or JWT) succeeds, but *before* the subsequent `validateSecretOwnersMatchAuthorized` owner-binding check runs. [1](#0-0)  If that later owner check fails, the function returns an error but the digest that was already recorded is never removed.

### Finding Description
`RequestReplayGuard` only exposes `CheckAndRecord` (to record-or-reject a digest) and `ClearExpired`/`clearExpiredLocked` (time-based expiry); there is no method to release or un-record an entry on a downstream failure. [2](#0-1) 

In `authorizer.AuthorizeRequest`, the sequence is:
1. `a.authorizeRequest` — allowlist or JWT digest/signature check succeeds and returns an `AuthResult` with a digest and expiry.
2. `a.replayGuard.CheckAndRecord(authResult.Digest(), authResult.ExpiresAt())` — the digest is now permanently marked "seen" for the remainder of `ExpiresAt()`.
3. `validateSecretOwnersMatchAuthorized(req, authResult.AuthorizedOwner())` — only *after* step 2, this checks that the embedded secret/identifier owner fields in the request payload match the authorized owner. [1](#0-0) 

If step 3 fails, the error is returned to the caller, but the digest recorded in step 2 is not rolled back. Any later request — including a legitimate, corrected retry with the identical digest — will be rejected with `ErrRequestAlreadySeen` for the full remainder of the expiry window, exactly mirroring the Zebra pattern where a rejected item's "sent" marker is left behind and a subsequent honest item sharing that marker is treated as already handled.

For allowlist-based auth, the expiry recorded is the on-chain `allowlistedRequest.ExpiryTimestamp`, which can be a long window, [3](#0-2)  so the lockout can persist well beyond a single retry cycle — the same "no child block to trigger cleanup" durability problem described in the report.

### Impact Explanation
Once any single request hits the owner-mismatch path after passing digest authorization, the exact same digest can never again be authorized until natural expiry — even for the legitimate workflow owner attempting to correct and resubmit. Since Vault requests are content-addressed by digest, the only way to "retry" a rejected request is to resend byte-identical content, and that retry is now permanently blocked. This is a self-inflicted or externally-triggerable availability degradation of the Vault secrets pipeline (create/update/delete/list) for the affected owner, matching the bug class in the report (CWE-459, incomplete cleanup causing lockout of an otherwise-valid subsequent request).

### Likelihood Explanation
This path is reached on every Vault gateway request that passes digest/JWT-signature authorization; the owner-mismatch branch can be hit by ordinary client-side bugs (mismatched owner fields in a batch of encrypted secrets/identifiers) or deliberately if an unprivileged party can reproduce the exact byte-for-byte digest preimage. No malicious peer/node capability is required — this is a gateway-facing JSON-RPC authorization flow (`GatewayVaultRequestProcessor.authorizeAndStamp` → `Authorizer.AuthorizeRequest`), reachable from any unprivileged client hitting the Vault gateway handler. [4](#0-3) 

### Recommendation
Reorder the checks so `validateSecretOwnersMatchAuthorized` runs before `CheckAndRecord`, or add a `Release`/`Remove` method to `RequestReplayGuard` that is called on any failure path after `CheckAndRecord` succeeds, so a rejected digest does not permanently consume the replay-guard slot.

### Proof of Concept
1. Register (on-chain) an allowlisted digest `D` for owner `X` with a long expiry.
2. Submit a request whose serialized bytes hash to `D` but whose embedded `EncryptedSecret.Id.Owner`/`SecretIdentifier.Owner` field does not match `X` (a benign client bug, or an owner/tenant mismatch during a legitimate multi-step submission).
3. `AuthorizeRequest` succeeds through `CheckAndRecord(D, expiry)`, then fails at `validateSecretOwnersMatchAuthorized`, returning an error to the caller — but `D` is now permanently recorded as seen.
4. Resubmit the corrected, legitimate request with owner `X` and byte-identical content (same digest `D`): `CheckAndRecord` rejects it with `ErrRequestAlreadySeen` even though the first attempt never succeeded, for as long as `allowlistedRequest.ExpiryTimestamp` remains valid. [5](#0-4)

func (a *authorizer) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	authResult, err := a.authorizeRequest(ctx, req)
	if err != nil {
		return nil, err
	}
	if authResult == nil {
		err = errors.New("auth mechanism returned nil auth result")
		a.lggr.Errorw("auth mechanism returned nil auth result", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "")
		return nil, err
	}
	if err := a.replayGuard.CheckAndRecord(authResult.Digest(), authResult.ExpiresAt()); err != nil {
		a.lggr.Debugw("replay guard rejected request", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "digest", authResult.Digest(), "expiresAt", authResult.ExpiresAt(), "hasAuth", req.Auth != "", "error", err)
		return nil, err
	}
	if ownerErr := validateSecretOwnersMatchAuthorized(req, authResult.AuthorizedOwner()); ownerErr != nil {
		a.lggr.Errorw("owner binding rejected request", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "hasAuth", req.Auth != "", "error", ownerErr)
		return nil, ownerErr
	}
	a.lggr.Debugw("request authorized", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "digest", authResult.Digest(), "expiresAt", authResult.ExpiresAt(), "hasAuth", req.Auth != "")
	return authResult, nil
}

type RequestReplayGuard struct {
	mu      sync.Mutex
	seen    map[string]int64 // digest → unix expiry timestamp
	nowFunc func() time.Time // injectable for testing
}

// NewRequestReplayGuard creates a replay guard for authorized Vault requests.
func NewRequestReplayGuard() *RequestReplayGuard {
	return &RequestReplayGuard{
		seen:    make(map[string]int64),
		nowFunc: time.Now,
	}
}

// CheckAndRecord returns ErrRequestAlreadySeen if the digest was previously
// recorded and has not yet expired. Otherwise it records the digest with
// the given expiry timestamp (unix seconds, UTC).
//
// Expired entries are cleaned up on every call.
func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}

func (p *GatewayVaultRequestProcessor) authorizeAndStamp(
	ctx context.Context,
	req *jsonrpc.Request[json.RawMessage],
	stamp func(prefixedRequestID string) error,
) (*AuthorizedGatewayVaultRequest, error) {
	incomingOwner := ""
	if idx := strings.Index(req.ID, vaulttypes.RequestIDSeparator); idx != -1 {
		incomingOwner = req.ID[:idx]
	}

	p.lggr.Debugw("authorizing gateway vault request", "method", req.Method, "requestID", req.ID)
	authResult, err := p.authorizer.AuthorizeRequest(ctx, *req)
	if err != nil {
		authErr := fmt.Errorf("request not authorized: %w", err)
		p.lggr.Errorw("gateway vault request authorization failed", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "", "incomingOwner", incomingOwner, "error", authErr)
		return nil, authErr
	}

	originalRequestID := req.ID
	authorizedOwner := authResult.AuthorizedOwner()
	prefixedRequestID := authorizedOwner + vaulttypes.RequestIDSeparator + originalRequestID
	req.ID = prefixedRequestID

	if err := stamp(prefixedRequestID); err != nil {
		p.lggr.Errorw("failed to stamp authorized request params", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, fmt.Errorf("failed to stamp authorized request params: %w", err)
	}

	p.lggr.Debugw("authorized gateway vault request", "method", req.Method, "requestID", req.ID, "owner", authorizedOwner, "orgID", authResult.OrgID(), "workflowOwner", authResult.WorkflowOwner())
	return &AuthorizedGatewayVaultRequest{
		Req:        *req,
		AuthResult: authResult,
	}, nil
}
