## Title
Venue-priced pairs price fills from an unprotected Uniswap V4 spot price (`sqrtPriceX96`), enabling flash-loan/swap price manipulation against solver-funded fills - (File: `sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts`)

### Summary
When a Simplex `FXFiller` pair has no configured bid/ask curves, its price is derived directly from a Uniswap V4 pool's current spot price (`sqrtPriceX96`) rather than a time-weighted average price. The only defense is an optional, static `referencePrice`/`maxDeviationBps` band, which bounds deviation from a stale reference but does nothing to prevent a single-transaction spot-price manipulation that stays inside that band, or is left completely unguarded when the operator omits it. This mirrors the reported Blueberry `UniswapV2Oracle.getPrice` flash-loan issue: pricing is read straight from manipulable reserves/spot-price state with no TWAP.

### Finding Description
`UniswapV4FundingPlanner.getExoticTokenPrice` picks the most-liquid position for a token and calls `computeDirectPoolPriceUsd`, which returns `sdkPool.token0Price`/`token1Price` computed straight from the pool's live `sqrtPriceX96`: [1](#0-0) [2](#0-1) 

The underlying pool state is refreshed on demand right before pricing/withdrawal planning, reading `slot0` (spot `sqrtPriceX96`) with no averaging window: [3](#0-2) 

This price feeds `FXFiller.referenceRate` / `resolveLegRates`, inverted directly into the fill rate: [4](#0-3) 

The only mitigation is `checkPriceGuard`, which compares the live quote against a **static** `referencePrice` and rejects only if deviation exceeds `maxDeviationBps` — it is optional, and does not defend against manipulation that stays within the configured band: [5](#0-4) 

This is explicitly documented as a known trust assumption rather than a defense against execution-time manipulation: [6](#0-5) [7](#0-6) 

Configuration explicitly allows leaving a chain "unguarded" if `referencePrice`/`maxDeviationBps` are omitted: [8](#0-7) 

### Impact Explanation
An intent submitter (an unprivileged actor who can place an order via `IntentGateway`/`fillOrder` flow) can, in the same transaction/block as placing an order, manipulate the underlying Uniswap V4 pool's spot price (e.g. via a large swap or flash-loaned swap) so that `computeDirectPoolPriceUsd` returns a favorable price still within `maxDeviationBps` (or entirely unguarded if the operator did not configure the guard). The FXFiller then fills the order at this manipulated rate, funding the fill by withdrawing real LP capital from its Uniswap V4 position — resulting in a genuine loss of solver-held funds priced off a manipulated on-chain spot price, directly analogous to the reported `UniswapV2Oracle.getPrice` flash-loan exploit pattern (spot reserves/price used for pricing without TWAP).

### Likelihood Explanation
Likelihood is contingent on operator configuration: pairs must be curve-less/venue-priced (`[vault.uniswapV4]` configured without `bidPriceCurve`/`askPriceCurve`), and if `referencePrice`/`maxDeviationBps` are unset the pool price is fully trusted with zero deviation protection. Even with the guard configured, an attacker only needs to move the price within the allowed band to profit, which is achievable with sufficient capital/flash liquidity against thin V4 positions — a realistic, single-transaction attack requiring no privileged access.

### Recommendation
Do not price fills from raw pool spot price (`sqrtPriceX96`)/`slot0` alone. Use a TWAP oracle (e.g., Uniswap V4 truncated oracle observations or an external oracle) for `computeDirectPoolPriceUsd`, and/or make the price guard mandatory rather than optional, and add execution-time protections (e.g., minimum output / slippage checks tied to a manipulation-resistant reference, and size/impact-aware pricing) so a same-block or same-transaction spot-price shift cannot be exploited against solver-funded fills.

### Proof of Concept
1. Operator configures a curve-less pair (e.g., USDC/CNGN) funded via `[vault.uniswapV4]`, either without `referencePrice`/`maxDeviationBps`, or with a band wide enough to allow meaningful spot-price movement.
2. Attacker takes a flash loan and executes a large swap against the same Uniswap V4 pool the position lives in, shifting `sqrtPriceX96` favorably for the attacker's intended fill direction, staying within `maxDeviationBps` if configured.
3. In the same block, attacker submits/executes an intent order that `FXFiller` prices via `getExoticTokenPrice` → `computeDirectPoolPriceUsd`, which reads the now-manipulated `slot0` price.
4. `checkPriceGuard` passes (band not breached, or guard unconfigured), and the solver fills the order at the manipulated rate, funding it by withdrawing from its real V4 LP position (`UniswapV4FundingPlanner.planWithdrawalForToken`).
5. Attacker reverses the initial swap (repaying the flash loan) and nets the difference between the true market price and the manipulated fill price, at the solver's expense.

	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}

	private computeDirectPoolPriceUsd(
		pos: HydratedV4Position,
		sdkPool: V4Pool,
		chain: string,
	): { exoticToken: string; priceUsd: Decimal } | null {
		const usdc = this.configService.getUsdcAsset(chain).toLowerCase()
		const usdt = this.configService.getUsdtAsset(chain).toLowerCase()
		const c0 = pos.currency0.toLowerCase()
		const c1 = pos.currency1.toLowerCase()

		if (c0 === usdc || c0 === usdt) {
			// currency0 is stable → exotic is currency1
			// token1Price = "token0 per token1" = USD per exotic
			return {
				exoticToken: c1,
				priceUsd: new Decimal(sdkPool.token1Price.toFixed(18)),
			}
		}

		if (c1 === usdc || c1 === usdt) {
			// currency1 is stable → exotic is currency0
			// token0Price = "token1 per token0" = USD per exotic
			return {
				exoticToken: c0,
				priceUsd: new Decimal(sdkPool.token0Price.toFixed(18)),
			}
		}

		return null
	}

	/**
	 * Validates a live venue quote against the static reference price for the chain.
	 * Returns true (pass) when no guard is configured, or no reference exists for the
	 * chain. Returns false when the quote (token1 per USD) deviates from the reference
	 * by more than `maxDeviationBps`, in which case the order must not be filled.
	 */
	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {
			this.logger.warn(
				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
	}

	/**
	 * Minimum-size reference rate (token1 per token0) for a leg's pair: the
	 * bid curve at 0 (the side token1-input legs trade at), falling back to the
	 * ask curve, then the live venue quote for venue-priced pairs.
	 */
	private async referenceRate(
		leg: ResolvedLeg,
		venueUsdPrice: (chain: string, token1Address: string) => Promise<Decimal | null>,
	): Promise<Decimal | null> {
		const policy = leg.pair.bidPricePolicy ?? leg.pair.askPricePolicy
		if (policy) {
			const rate = policy.getPrice(new Decimal(0))
			return rate.gt(0) ? rate : null
		}
		// Venue-priced pair: token0 is USD-stable (constructor invariant), so the
		// venue's USD-per-token1 quote inverts straight into token1-per-token0.
		const venueUsd = await venueUsdPrice(leg.token1Chain, leg.token1Address)
		if (!venueUsd) return null
		const venueRate = new Decimal(1).div(venueUsd)
		// Same guard as trade pricing: this rate sizes the order's USD notional
		// for confirmation depth, and a manipulated pool understating the value
		// would shrink the reorg protection — the exact attack the guard exists
		// to stop. Refusing to size skips the order, consistent with pricing.
		if (!this.checkPriceGuard(undefined, leg.token1Chain, venueRate)) return null
		return venueRate
	}

`computeDirectPoolPriceUsd` returns the **raw pool mid** derived from `sqrtPriceX96`. The pool's
fee tier is read and stored on the hydrated position (`pos.fee`) but never applied to the price,
and there is no size or impact term — `computeLegPolicyOutput` extends the mid linearly across the
whole priced quantity. `checkPriceGuard` is the only defense on this path, and it checks deviation
from a static reference, not execution cost. A venue-priced pair that has to swap through its own
pool to source inventory pays a fee tier it never quoted against.

```text
## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.
```
