### Title
Whole-balance sweep of the shared `CallDispatcher` in `IntentGatewayV2` lets one order's predispatch/output calldata steal tokens left by another order - ([File: evm/src/apps/intentsv2/IntentsBase.sol])

### Summary
`IntentGatewayV2` (and its Tron port) route both pre-escrow ("predispatch") and post-fill ("output.call") arbitrary calldata through a single, persistent `CallDispatcher` contract returned by `_params.dispatcher`. After each such call, the gateway sweeps tokens back from the dispatcher using the dispatcher's **entire current `balanceOf`**, not the delta actually produced by that specific call. Because the dispatcher is one shared, long-lived contract used by every order (and can hold arbitrary ERC20 balances via its generic `dispatch()`/`receive()`), any token balance left behind by one order's calldata — intentionally or through an unswept intermediate token — is fully absorbed by whichever subsequent order happens to reference that token, exactly mirroring the Bunni root cause of transferring the *whole* balance instead of only the amount produced by the current operation.

### Finding Description
`IntentsBase._execute` runs an order's postdispatch calldata and then sweeps residual tokens purely by reading the dispatcher's full balance: [1](#0-0) 

`placeOrder`'s predispatch path does the same thing when preparing the sweep-back calls, sizing the transfer to `balanceOf(dispatcher)` rather than to the amount the predispatch call itself produced: [2](#0-1) 

The same pattern exists in the Tron port: [3](#0-2) 

`_params.dispatcher` is a single, gateway-wide address (not deployed per order), and `CallDispatcher` is a generic executor that can hold any ERC20 balance indefinitely and accepts native ETH via `receive()`: [4](#0-3) 

The sweep loops in both `_execute` and `placeOrder`'s predispatch phase are scoped only to the tokens listed in `order.output.assets` / `order.inputs`. Any token produced or received by the arbitrary predispatch/output calldata that is *not* one of those listed tokens is never swept and is left sitting in the shared `CallDispatcher`. Because the very next unrelated order that lists that same token as one of its own `inputs`/`output.assets` sweeps by `balanceOf(dispatcher)` (the whole balance), it will vacuum up and credit itself (or emit as its own `DustCollected`) any stray balance left by a prior, unrelated order/user — exactly the Bunni pattern of using the full contract balance as "the output of this operation" instead of the amount this operation actually produced.

### Impact Explanation
An attacker can craft `order.predispatch.call` or `order.output.call` payloads whose intermediate/leftover token is not part of the order's declared `inputs`/`output.assets`, permanently stranding value in the shared `CallDispatcher`. A subsequent order (their own, or anyone else's) that references that stranded token will sweep 100% of the dispatcher's balance for that token via `balanceOf(dispatcher)`, crediting it as escrow input (satisfying `order.inputs[i].amount` requirements "for free") or as protocol `DustCollected` misattributed to an unrelated order — in either case diverting funds that belonged to a different user's order/calldata execution. This is a direct loss-of-funds vector reachable by any unprivileged order placer or solver, matching the High severity of the original report.

### Likelihood Explanation
High: `placeOrder` and `fillOrder`'s output-calldata path are both permissionless entry points open to any user, and crafting calldata that leaves an unlisted token balance in the shared dispatcher (or simply waiting for another user's leftover) requires no special privileges — only a predispatch/output call whose produced token set differs from the declared `order.inputs`/`output.assets`.

### Recommendation
Never size the sweep-back transfer by the dispatcher's total `balanceOf`. Snapshot the dispatcher's per-token balance immediately before dispatching the predispatch/output call and sweep only the **delta** produced by that specific call (as is already correctly done for the gateway's own balance in the predispatch "received" calculation at `IntentGatewayV2.sol:291-311`). Extend that before/after delta accounting to the transfer-call sizing itself in both `placeOrder`'s predispatch phase and `IntentsBase._execute`'s postdispatch sweep, so a shared `CallDispatcher` can never be used to move balances belonging to a different order/user.

### Proof of Concept
1. User A places (or fills) an order whose `predispatch.call` (or `output.call`) is a multi-hop swap routed through the shared `CallDispatcher`; the swap's final hop unintentionally leaves 100 units of an intermediate token `T` in the dispatcher because `T` is not part of `order.inputs`/`order.output.assets`, so the sweep loop (`evm/src/apps/intentsv2/IntentsBase.sol:507-533` or `evm/src/apps/IntentGatewayV2.sol:263-287`) never touches it — `T` remains stuck in `CallDispatcher`.
2. Attacker places a new order whose `order.inputs` (predispatch) or `order.output.assets` (postdispatch) includes token `T` with a small `requiredAmount`, and whose own predispatch/output calldata produces little or none of `T` itself.
3. When the gateway builds the sweep transfer, it reads `balance = IERC20(T).balanceOf(dispatcher)` (`evm/src/apps/IntentGatewayV2.sol:274` / `evm/src/apps/intentsv2/IntentsBase.sol:518`), which now includes User A's stranded 100 units, satisfies `balance >= requiredAmount`, and sweeps the **entire** balance to the gateway on the attacker's order — crediting the attacker's escrow (or protocol dust under the attacker's transaction) with tokens that originated from User A's unrelated order.

import {ICallDispatcher, Call} from "@hyperbridge/core/interfaces/ICallDispatcher.sol";

/**
 * @title The CallDispatcher
 * @author Polytope Labs (hello@polytope.technology)
 *
 * @notice This contract is used to dispatch calls to other contracts.
 */
contract CallDispatcher is ICallDispatcher {
    /**
     * @dev error thrown when the target is not a contract.
     */
    error NotContract(address target);

    /**
     * @dev error thrown when a call fails.
     */
    error CallFailed(address target, bytes result);

    /**
     * @dev Receive function to accept ETH transfers
     */
    receive() external payable {}

    /**
     *  @dev reverts if the target is not a contract or if any of the calls reverts.
     */
    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
