## Analysis

The report describes a classic **missing access control** pattern: a function that performs a privileged/administrative action (overriding trade dispute state and prices) is exposed without any `onlyCegaAdmin`-style authorization check, so any caller can invoke it.

Searching `orb-core` for the closest structural analog — a privileged administrative action triggerable by an unauthenticated/unverified actor before any authorization check runs — the strongest match is the "magic QR-code" handling in the signup plan.

### Root cause

In the operator QR-code scan flow, `scan_operator_qr_code` first parses a raw QR string into `qr_scan::operator::Data` <cite repo="AYontt/orb-core--015" path="src/plans/qr_scan/operator.rs" start="35="60" /> — wait, corrected below.### Title
Missing Access Control on Magic QR-Code Actions Allows Unverified Actor to Trigger Privileged Orb Reconfiguration - (File: src/plans/mod.rs)

### Summary
The magic QR-code handler `handle_magic_operator_qr_code` executes privileged device-reconfiguration actions (mirror recalibration reset, WiFi/network reset) immediately upon scanning a QR code, before the operator/distributor is authenticated by the backend. This mirrors the `sfnProcessTradeDispute` pattern: a state-mutating, privileged-only action reachable without any `onlyCegaAdmin`-equivalent authorization check.

### Finding Description
The signup flow scans an "operator" QR code and dispatches it to `handle_magic_operator_qr_code` for `MagicResetMirror` / `MagicResetWifi` variants *before* the code is ever sent to the backend for verification via `verify_operator_qr_code` (which is the actual authorization boundary that confirms the scanning party is a registered/valid distributor/operator) [1](#0-0) .

Both call sites confirm the ordering: `scan_operator_qr_code` → `handle_magic_operator_qr_code` → `verify_operator_qr_code`, i.e. the magic action executes and returns before any backend authorization occurs [2](#0-1) [3](#0-2) .

The trigger condition itself is a bare regex match on the raw QR string content (`magic_action:reset_wifi_credentials` / `magic_action:reset_mirror_calibration`), with no signature, no cryptographic binding to an operator identity, and no backend round-trip — anyone who can present this string as a QR code to the Orb's camera satisfies it [4](#0-3) .

Once matched, the handler directly invokes privileged, hardware/state-mutating operations:
- `reset_mirror_calibration`, which overwrites the calibration file and forces mirror recalibration [5](#0-4) .
- `reset_wifi_and_ensure_network`, which resets the network stack and re-establishes a WiFi connection [6](#0-5) .

This is structurally identical to the reported bug class: a function capable of overriding privileged/administrative state (`sfnProcessTradeDispute` overriding price observations) that is reachable by any caller because the authorization check (`onlyCegaAdmin` / here, backend operator verification) is missing or, in this case, occurs only *after* the sensitive action has already been carried out.

### Impact Explanation
An unverified party — someone who is not a confirmed registered operator/distributor and has never passed `verify_operator_qr_code`'s backend check — can force the Orb to:
- Recalibrate its eye-tracking mirror mid-operation, altering iris/face capture geometry used for identity image capture, which can degrade or manipulate the quality/consistency of biometric captures relied upon for fraud/liveness assessment during a live or upcoming signup.
- Drop and reset the Orb's network connection, disrupting an in-progress signup session (denial of service to the signup pipeline) and forcing re-association through `wifi::Plan.ensure_network_connection`.

Because these actions are dispatched purely from unauthenticated QR-code content and bypass the operator-authorization boundary entirely, this is a genuine authorization-boundary bypass on privileged device state, not merely a cosmetic/no-impact issue.

### Likelihood Explanation
High. The QR string is static, publicly derivable from the regex/pattern in the codebase (`magic_action:reset_wifi_credentials`, `magic_action:reset_mirror_calibration`), requires no secret, no operator credential, and no network request to trigger — only physical presentation of a printed/displayed QR code to the Orb's camera during the operator QR-scan phase of any signup attempt.

### Recommendation
Move the `MagicResetMirror` / `MagicResetWifi` handling to occur only *after* `verify_operator_qr_code` succeeds (i.e., after the backend confirms the scanning party is a valid, authorized operator/distributor), so these privileged actions require the same authorization boundary as normal operator QR-code processing. Alternatively, require a signed/authenticated magic-action payload validated against a backend-issued credential before executing `reset_mirror_calibration` or `reset_wifi_and_ensure_network`.

### Proof of Concept
1. Generate/print a QR code containing the literal string `magic_action:reset_mirror_calibration` (or `magic_action:reset_wifi_credentials`).
2. Present it to the Orb during the operator QR-code scan step of the signup flow (`scan_operator_qr_code` in `src/plans/mod.rs`).
3. Observe that `handle_magic_operator_qr_code` matches `qr_scan::operator::Data::MagicResetMirror`/`MagicResetWifi` and immediately calls `reset_mirror_calibration`/`reset_wifi_and_ensure_network`, with `orb.ui.magic_qr_action_completed(...)` reporting success — all without any call having been made to `backend::operator_status::request` (the authorization check) [1](#0-0) [7](#0-6) .

    async fn handle_magic_operator_qr_code(
        &self,
        orb: &mut Orb,
        qr_code: qr_scan::operator::Data,
    ) -> Result<Option<qr_scan::user::Data>> {
        match qr_code {
            qr_scan::operator::Data::Normal(qr_code) => {
                tracing::info!("Operator QR-code detected: {qr_code:?}");
                Ok(Some(qr_code))
            }
            qr_scan::operator::Data::MagicResetMirror => {
                tracing::info!("Magic QR-code detected: Reset Mirror");
                dd_incr!("main.count.signup.during.general.magic_qr.reset_mirror");
                let result = self.reset_mirror_calibration(orb).await;
                if let Err(err) = &result {
                    tracing::error!("Failed to reset mirror calibration: {err}");
                }
                orb.ui.magic_qr_action_completed(result.is_ok());
                Ok(None)
            }
            qr_scan::operator::Data::MagicResetWifi => {
                tracing::info!("Magic QR-code detected: Reset Wi-Fi");
                dd_incr!("main.count.signup.during.general.magic_qr.reset_wifi");
                let result = self.reset_wifi_and_ensure_network(orb).await;
                if let Err(err) = &result {
                    tracing::error!("Failed to reset wifi: {err}");
                }
                orb.ui.magic_qr_action_completed(result.is_ok());
                Ok(None)
            }
        }
    }

/// Operator QR-code data.
#[derive(Clone, Debug)]
pub enum Data {
    /// Normal Operator QR-code.
    Normal(user::Data),
    /// Action to reconfigure WiFi.
    MagicResetWifi,
    /// Action to reset mirror calibration.
    MagicResetMirror,
}

impl Schema for Data {
    fn ui() -> ui::QrScanSchema {
        ui::QrScanSchema::Operator
    }

    fn try_parse(code: &str) -> Option<Self> {
        let normal = user::Data::try_parse(code)
            .filter(
                |d| if d.signup_extension() { d.signup_extension_config.is_some() } else { true },
            )
            .map(Data::Normal);
        if normal.is_some() {
            return normal;
        }
        if let Some(captures) = MAGIC_QR_CODE.captures(code) {
            return match captures
                .name("magic_action")
                .expect("magic_action group must be present")
                .as_str()
            {
                "reset_wifi_credentials" => Some(Data::MagicResetWifi),
                "reset_mirror_calibration" => Some(Data::MagicResetMirror),
                _ => None,
            };
        }
        None
    }
