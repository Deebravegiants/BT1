### Title
Duplicate input/output tokens in `IntentGatewayV2.placeOrder` are not rejected on the Tron variant, allowing escrow accounting corruption and over-release of funds - (File: evm/tron/contracts/apps/IntentGatewayV2.sol)

### Summary
The main EVM `IntentGatewayV2` contract (`evm/src/apps/IntentGatewayV2.sol`) explicitly guards `placeOrder` against duplicate `token` entries in both `order.output.assets` (via transient-storage dedup check) and `order.inputs` (via `if (_orders[commitment][token] != 0) revert InvalidInput();`), with a dedicated regression test suite ("DUPLICATE INPUT TOKEN REJECTION TESTS") noting this was a fix for "same-chain partial fills over-release repeated input escrow." The Tron fork of the same contract (`evm/tron/contracts/apps/IntentGatewayV2.sol`) reimplements `placeOrder` and `withdraw` independently but omits both checks entirely, reintroducing the exact bug class the main contract already had to fix.

### Finding Description
`evm/src/apps/IntentGatewayV2.sol` `placeOrder` (lines 194-373) rejects duplicate output tokens using transient storage: [1](#0-0) 
and rejects duplicate input tokens explicitly when crediting escrow: [2](#0-1) 

The Tron contract's `placeOrder` (`evm/tron/contracts/apps/IntentGatewayV2.sol`, lines 338-506) has neither check. It escrows tokens using `_orders[commitment][token] += reducedInputs[i].amount;`, silently merging multiple input legs that reference the same token address into a single accumulated bucket, and it never checks `order.output.assets` for repeated tokens at all: [3](#0-2) [4](#0-3) 

This is the same bug class described in the external report: an array (`order.inputs` / `order.output.assets`) that is expected to contain unique elements is not validated for duplicates, so the same element's "configuration" (its escrow bucket, or its output amount owed) gets merged/overwritten instead of being tracked independently, corrupting the accounting invariant the withdrawal logic depends on.

On withdrawal, `withdraw()` in the Tron contract (lines 691-714) decrements the merged per-token bucket for each `WithdrawalRequest.tokens[i]` entry independently: [5](#0-4) 
Because the escrow amount for a duplicated token is a single summed bucket rather than per-leg amounts, a withdrawal/partial-fill flow that references the same token more than once (matching the structure of `body.tokens`, which mirrors `order.inputs`) can release more of that token than was actually still owed for a given leg, or repeatedly drain the merged bucket across multiple partial-fill calls beyond what any single leg should permit — exactly the "over-release repeated input escrow" scenario the main contract's regression test (`testRevert_PlaceOrder_DuplicateInputTokens`) was written to prevent: [6](#0-5) 

Additionally, since duplicate output tokens are never rejected, a malicious order placer could construct an order whose `output.assets` lists the same token twice with different amounts, which downstream solver/fill logic (which iterates and sums or checks output requirements per asset) may double count or under-price, since the escrowed 100%-of-output invariant the main contract protects against is not enforced here.

### Impact Explanation
This is a fund-safety bug in an unprivileged, permissionless entry point (`placeOrder`, reachable by any user submitting an order) and in the escrow-release path (`withdraw`, invoked by any relayer supplying a valid delivery proof for `RedeemEscrow`/`RefundEscrow`, or via `onGetResponse` for refunds). Merged escrow buckets for duplicate tokens break the 1:1 mapping between order legs and escrowed value that partial fills, refunds, and finalization all rely on, enabling incorrect release amounts — i.e., a route where legitimate protocol funds can be over-released to a beneficiary or under-collateralized against solver obligations. This matches the "concrete theft or permanent freezing of funds" bar for a valid finding, and the pattern is proven to be exploitable because the main contract already needed and shipped a fix for the identical scenario.

### Likelihood Explanation
Medium-High: constructing an order with duplicate token entries in `inputs` or `output.assets` requires no special privileges — any user calling `placeOrder` can do it, and Tron does not reject it. The consequences depend on how the withdrawal/partial-fill request is subsequently constructed (by the relayer/coprocessor), but since the underlying merged accounting state is corrupted at escrow time regardless, any code path built assuming per-leg independent escrow (as the main contract does, and as its regression tests explicitly verify) will misbehave against the Tron deployment.

### Recommendation
Port the same duplicate-token guards from `evm/src/apps/IntentGatewayV2.sol` into `evm/tron/contracts/apps/IntentGatewayV2.sol`:
1. In `placeOrder`, reject duplicate `token` values in `order.output.assets` before processing (transient storage or an in-memory dedup check).
2. In `placeOrder`, reject duplicate `token` values in `order.inputs` when crediting `_orders[commitment][token]` (revert instead of accumulating via `+=`).
3. Add the equivalent regression tests (`testRevert_PlaceOrder_DuplicateInputTokens*`) to the Tron test suite to prevent regression.

    function placeOrder(Order memory order, bytes32 graffiti) public payable {
        // Validate that order has inputs
        if (order.inputs.length == 0) revert InvalidInput();

        address hostAddr = host();
        // fill out the order preludes
        order.user = bytes32(uint256(uint160(msg.sender)));
        order.source = IDispatcher(hostAddr).host();
        order.nonce = _nonce++;

        // Calculate reduced inputs (after protocol fees) for commitment and escrow
        uint256 inputsLen = order.inputs.length;
        // Use destination-specific protocol fee, fallback to source chain fee if zero
        bytes32 destinationHash = keccak256(order.destination);
        uint256 protocolFeeBps = _destinationProtocolFees[destinationHash];
        if (protocolFeeBps == 0) {
            protocolFeeBps = _params.protocolFeeBps;
        }
        TokenInfo[] memory reducedInputs;
        bytes32 commitment;

        if (protocolFeeBps > 0) {
            reducedInputs = new TokenInfo[](inputsLen);
            for (uint256 i; i < inputsLen;) {
                uint256 originalAmount = order.inputs[i].amount;
                uint256 protocolFee = (originalAmount * protocolFeeBps) / 10_000;
                uint256 reducedAmount = originalAmount - protocolFee;
                address token = address(uint160(uint256(order.inputs[i].token)));

                // Emit DustCollected for protocol fee if non-zero
                if (protocolFee > 0) emit DustCollected(token, protocolFee);

                reducedInputs[i] = TokenInfo({token: order.inputs[i].token, amount: reducedAmount});
                unchecked {
                    ++i;
                }
            }

            // Temporarily swap inputs to calculate commitment with reduced amounts
            TokenInfo[] memory originalInputs = order.inputs;
            order.inputs = reducedInputs;
            commitment = keccak256(abi.encode(order));
            order.inputs = originalInputs;
        } else {
            // No protocol fees, use order.inputs directly
            reducedInputs = order.inputs;
            commitment = keccak256(abi.encode(order));
        }

        // escrow tokens
        uint256 msgValue = msg.value;
        if (order.predispatch.call.length > 0 && order.predispatch.assets.length > 0) {
            address dispatcher = _params.dispatcher;

            // Transfer all predispatch assets to the call dispatcher
            uint256 assetsLen = order.predispatch.assets.length;
            for (uint256 i; i < assetsLen;) {
                address token = address(uint160(uint256(order.predispatch.assets[i].token)));
                uint256 amount = order.predispatch.assets[i].amount;

                if (token == address(0)) {
                    if (amount > msgValue) revert InsufficientNativeToken();
                    msgValue -= amount;

                    (bool sent,) = dispatcher.call{value: amount}("");
                    if (!sent) revert InsufficientNativeToken();
                } else {
                    IERC20(token).safeTransferFrom(msg.sender, dispatcher, amount);
                }

                unchecked {
                    ++i;
                }
            }

            // Execute the call dispatcher with predispatch call
            ICallDispatcher(dispatcher).dispatch(order.predispatch.call);

            // Transfer tokens from call dispatcher back to IntentGateway
            Call[] memory transferCalls = new Call[](inputsLen);
            for (uint256 i; i < inputsLen;) {
                address token = address(uint160(uint256(order.inputs[i].token)));
                uint256 requiredAmount = order.inputs[i].amount;
                uint256 balance;

                if (token == address(0)) {
                    balance = address(dispatcher).balance;
                    if (balance < requiredAmount) revert InsufficientNativeToken();
                    transferCalls[i] = Call({to: address(this), value: balance, data: ""});
                } else {
                    balance = IERC20(token).balanceOf(dispatcher);
                    if (balance < requiredAmount) revert InvalidInput();
                    transferCalls[i] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                }

                uint256 dust = balance - requiredAmount;
                if (dust > 0) emit DustCollected(token, dust);

                // Store reduced amount (after protocol fees) in escrow
                _orders[commitment][token] += reducedInputs[i].amount;

                unchecked {
                    ++i;
                }
            }

            // Execute transfer calls from call dispatcher
            ICallDispatcher(dispatcher).dispatch(abi.encode(transferCalls));
        } else {
            for (uint256 i; i < inputsLen;) {
                if (order.inputs[i].amount == 0) revert InvalidInput();
                address token = address(uint160(uint256(order.inputs[i].token)));
                if (token == address(0)) {
                    // native token
                    if (msgValue < order.inputs[i].amount) revert InsufficientNativeToken();
                    msgValue -= order.inputs[i].amount;
                } else {
                    IERC20(token).safeTransferFrom(msg.sender, address(this), order.inputs[i].amount);
                }

                // Store reduced amount (after protocol fees) in escrow
                _orders[commitment][token] += reducedInputs[i].amount;

                unchecked {
                    ++i;
                }
            }
        }

    /// @notice Placing an order with duplicate input tokens must revert.
    /// Regression test for: same-chain partial fills over-release repeated input escrow.
    function testRevert_PlaceOrder_DuplicateInputTokens() public {
        // Two input legs both using USDC — this previously merged into one escrow bucket
        TokenInfo[] memory inputs = new TokenInfo[](2);
        inputs[0] = TokenInfo({token: bytes32(uint256(uint160(address(usdc)))), amount: 1200 * 1e6});
        inputs[1] = TokenInfo({token: bytes32(uint256(uint160(address(usdc)))), amount: 1000 * 1e6});

        TokenInfo[] memory outputAssets = new TokenInfo[](2);
        outputAssets[0] = TokenInfo({token: bytes32(uint256(uint160(address(dai)))), amount: 500 * 1e18});
        outputAssets[1] = TokenInfo({token: bytes32(uint256(uint160(address(dai)))), amount: 1000 * 1e18});

        PaymentInfo memory output =
            PaymentInfo({beneficiary: bytes32(uint256(uint160(user))), assets: outputAssets, call: ""});

        Order memory order = Order({
            user: bytes32(0),
            source: "",
            destination: host.host(),
            deadline: block.number + 100,
            nonce: 0,
            fees: 0,
            session: address(0),
            predispatch: DispatchInfo({assets: new TokenInfo[](0), call: ""}),
            inputs: inputs,
            output: output
        });

        vm.startPrank(user);
        usdc.approve(address(intentGateway), 2200 * 1e6);
        vm.expectRevert(IntentsBase.InvalidInput.selector);
        intentGateway.placeOrder(order, bytes32(0));
        vm.stopPrank();
    }
