Found the analog: `HyperbridgeLzEndpoint.retryPayload` is an unguarded bypass of `pause()`.

### Title
Unpaused `retryPayload` bypasses `pause()` and still delivers cross-chain messages to OApps - (File: sdk/packages/lz-endpoint/contracts/HyperbridgeLzEndpoint.sol)

### Summary
`HyperbridgeLzEndpoint` guards its two message-delivery entry points, `send` and `onAccept`, with `whenNotPaused` [1](#0-0) [2](#0-1) . However, `retryPayload`, a third, permissionless entry point that also delivers a payload to an OApp via `lzReceive`, carries no `whenNotPaused` modifier at all [3](#0-2) . This mirrors the reported `Redeemer` bug class: the pause switch is applied inconsistently across functions that reach the same sensitive effect (delivering an inbound message / minting-equivalent side effects on the destination OApp), so pausing is trivially bypassable through a sibling function.

### Finding Description
`onAccept` is the primary inbound delivery path and is explicitly `onlyHost whenNotPaused` [4](#0-3) . When the OApp's `lzReceive` call reverts inside `onAccept`, the payload hash is stored for later retry rather than reverting the whole transaction [5](#0-4) .

`retryPayload` is the designated recovery mechanism for that stored payload, and it performs the exact same privileged action — calling `ILayerZeroReceiver(receiver).lzReceive(...)` — but it is declared without `whenNotPaused`:

```solidity
function retryPayload(
    address receiver,
    Origin calldata origin,
    bytes32 guid,
    bytes calldata message
) external payable {
    ...
    ILayerZeroReceiver(receiver).lzReceive{value: msg.value}(origin, guid, message, msg.sender, "");
    emit InboundPayloadResolved(receiver, origin.srcEid, origin.sender, origin.nonce);
}
``` [3](#0-2) 

Because `retryPayload` is `external` and callable by anyone (documented as "Permissionless" in its NatSpec) [6](#0-5) , any previously-stored inbound payload (one whose first `lzReceive` attempt reverted) can still be delivered to the destination OApp while the endpoint's owner believes cross-chain delivery is paused via `pause()` [7](#0-6) . This is precisely the analog of the `Redeemer` case: one canonical function (`onAccept`/`redeem`) is properly guarded, while a functionally-equivalent side door (`retryPayload`/`authRedeem`+`autoRedeem`) is not, defeating the purpose of `pause()`.

### Impact Explanation
When the contract owner pauses the endpoint (e.g., during an emergency — a compromised source chain, a malicious/forged relayed ISMP payload, or a bug in a specific OApp's `lzReceive` logic), the intent is to halt all delivery of inbound messages to downstream OApps. `retryPayload` undermines that intent: an attacker or bot can still trigger delivery of any queued payload to any OApp during the pause window, causing exactly the harm the pause was meant to prevent (e.g., an OApp mint/state-change triggered by a message the operator wanted frozen). This is a medium-severity availability/control-bypass issue affecting the emergency-pause guarantee of a bridge-facing adapter contract that is reachable by an unprivileged party (the message is dispatched by any user; delivery/retry is permissionless).

### Likelihood Explanation
For this to bite, a payload must first fail delivery in `onAccept` (stored via the try/catch), and then the owner must pause the contract — plausible in an incident-response scenario where the very payload causing trouble already reverted and got queued. At that point, any address can call `retryPayload` since it has no access control and no pause check, making exploitation trivial and requiring no special privileges.

### Recommendation
Add the `whenNotPaused` modifier to `retryPayload` (and audit other externally-reachable delivery paths such as `lzCompose`, which similarly delivers to `ILayerZeroComposer` without a pause check) so that the pause mechanism is enforced consistently across every path that can trigger inbound message execution.

### Proof of Concept
1. `pause()` is called by the owner to halt the adapter, `paused()` becomes `true`.
2. A message previously dispatched via ISMP to `onAccept` had failed `lzReceive` before the pause and its payload hash was stored (`InboundPayloadStored`).
3. Any address calls `retryPayload(receiver, origin, guid, message)`.
4. Because `retryPayload` has no `whenNotPaused` check, the call proceeds, `lzReceive` executes against `receiver`, and the queued cross-chain effect (e.g., mint on an OApp) is delivered despite the contract being paused.

    function onAccept(IncomingPostRequest calldata incoming) external override onlyHost whenNotPaused {
        PostRequest calldata request = incoming.request;

        // Verify source is this adapter on another chain
        if (keccak256(request.from) != keccak256(abi.encodePacked(address(this)))) revert UnknownSource();

        // Decode the LZ message from the ISMP body
        (
            bytes32 guid,
            uint32 srcEid,
            bytes32 sender,
            uint64 nonce,
            bytes32 receiver,
            bytes memory message
        ) = abi.decode(request.body, (bytes32, uint32, bytes32, uint64, bytes32, bytes));

        // Reject `expectedEid == 0` so unconfigured sources don't collide with `srcEid = 0`.
        uint32 expectedEid = _stateMachineToEid[keccak256(request.source)];
        if (expectedEid == 0 || expectedEid != srcEid) revert UnknownSource();

        // Validate and advance the nonce. The nonce is committed BEFORE (and independently of)
        // OApp execution: a reverting `lzReceive` must not roll back this write. Otherwise the
        // message would be retried forever at the same nonce and every later nonce would be
        // permanently rejected, bricking the (receiver, srcEid, sender) channel.
        address receiverAddr = address(uint160(uint256(receiver)));
        uint64 expectedNonce = _inboundNonce[receiverAddr][srcEid][sender] + 1;
        if (nonce != expectedNonce) revert InvalidNonce(expectedNonce, nonce);
        _inboundNonce[receiverAddr][srcEid][sender] = nonce;

        // Deliver to the OApp. Isolate the external call so a deterministic revert (zero
        // recipient, over-cap mint, blocklisted recipient, malformed payload, paused OApp, etc.)
        // does not revert `onAccept`. On failure the payload is retained for later retry/recovery
        // via retryPayload/clear/skip/nilify/burn.
        Origin memory origin = Origin({srcEid: srcEid, sender: sender, nonce: nonce});
        try ILayerZeroReceiver(receiverAddr).lzReceive(origin, guid, message, address(0), "") {
            // delivered successfully
        } catch {
            bytes32 payloadHash = keccak256(abi.encode(guid, message));
            _inboundPayloadHashes[receiverAddr][srcEid][sender][nonce] = payloadHash;
            emit InboundPayloadStored(receiverAddr, srcEid, sender, nonce, payloadHash);
        }
    }

    function retryPayload(
        address receiver,
        Origin calldata origin,
        bytes32 guid,
        bytes calldata message
    ) external payable {
        bytes32 stored = _inboundPayloadHashes[receiver][origin.srcEid][origin.sender][origin.nonce];
        if (stored == bytes32(0) || stored == NIL_PAYLOAD_HASH || stored != keccak256(abi.encode(guid, message))) {
            revert InvalidPayloadHash();
        }

        // Clear first; if the retry reverts, this deletion rolls back with the rest of the tx and
        // the payload remains recoverable.
        delete _inboundPayloadHashes[receiver][origin.srcEid][origin.sender][origin.nonce];

        ILayerZeroReceiver(receiver).lzReceive{value: msg.value}(origin, guid, message, msg.sender, "");
        emit InboundPayloadResolved(receiver, origin.srcEid, origin.sender, origin.nonce);
    }
