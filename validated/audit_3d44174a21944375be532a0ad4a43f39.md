Audit Report

## Title
Bridge `OutgoingToken` Stored and Served in Cleartext to Any Authenticated (View-Role) User via Bridge REST/GraphQL Read Endpoints - (File: core/bridges/bridge_type.go, core/web/presenters/bridges.go, core/web/router.go)

## Summary
`BridgeType.OutgoingToken` is generated once and persisted unhashed in the `bridge_types.outgoing_token` column, unlike `IncomingToken`, which is hashed before storage. It is then returned in cleartext on every subsequent `Index`/`Show` read of a bridge via the JSON API and GraphQL, and confirmed to be reachable by any authenticated user regardless of role, since `GET /v2/bridge_types` and `GET /v2/bridge_types/:BridgeName` have no role-gating wrapper in the router, unlike the bridge write endpoints.

## Finding Description
`NewBridgeType` generates `outgoingToken` and stores it directly in the persisted `BridgeType` struct without hashing, while `incomingToken` is hashed via `incomingTokenHash` before storage: [3](#0-2) . The schema stores `outgoing_token` as plain `text` with no hash/salt columns analogous to `incoming_token_hash`/`salt`: [4](#0-3) .

`BridgeResource`, used by both `Index` and `Show`, serializes `OutgoingToken` unconditionally (no `omitempty`), while `IncomingToken` is explicitly documented as one-time-only and marked `omitempty`: [5](#0-4) . The controller confirms both `Index` and `Show` return this resource on every call: [6](#0-5) . The GraphQL resolver exposes the same plaintext field: [7](#0-6) .

Critically, I verified the router-level authorization gap referenced as unconfirmed in the original report: `authv2.GET("/bridge_types", paginatedRequest(bt.Index))` and `authv2.GET("/bridge_types/:BridgeName", bt.Show)` carry no `auth.RequiresEditRole`/`RequiresRunRole`/`RequiresAdminRole` wrapper, whereas `Create`/`Update`/`Destroy` on the same resource do use `auth.RequiresEditRole`: [1](#0-0) . Since role enforcement in this codebase is opt-in per-route (`RequiresRunRole`, `RequiresEditRole`, `RequiresAdminRole` each independently check `user.Role`) [2](#0-1) , any authenticated session/token — including the lowest `view` role — that only passes generic `auth.Authenticate` reaches `bt.Index`/`bt.Show` and receives the plaintext `OutgoingToken` for every bridge in the node, not just ones the caller created.

## Impact Explanation
This is a genuine secret-disclosure issue: a `view`-role authenticated user (who cannot create/edit/delete bridges) can enumerate all bridges and obtain every bridge's plaintext `OutgoingToken`, which the node uses to authenticate its own outgoing webhook/callback calls to external adapters. This maps to the in-scope "key/secret exfiltration" impact category. It does not grant direct control of node funds or job execution, but does allow a low-privileged authenticated actor to impersonate the node's outgoing bridge traffic to external adapter systems, an escalation from `view` role to secrets otherwise reserved for `edit`/`admin`-created bridges.

## Likelihood Explanation
High likelihood in any multi-user node deployment: exploitation requires only a valid low-privileged (`view`-role) session or API token — the same one used for ordinary dashboard/API browsing — and standard, unmodified GET requests to `/v2/bridge_types` or `/v2/bridge_types/:BridgeName`, or the equivalent GraphQL `bridge` query. No misconfiguration, no host/DB access, and no privilege escalation exploit is needed; a user simply needs to be granted the lowest role by an admin, which is a normal, intended access-control tier in Chainlink (`view`, `run`, `edit`, `admin`).

## Recommendation
- Gate `GET /v2/bridge_types` and `GET /v2/bridge_types/:BridgeName` with at least `auth.RequiresEditRole` (or a dedicated read-role check equal to or above what protects other sensitive secret fields), consistent with how `Create`/`Update`/`Destroy` are already protected.
- Hash `OutgoingToken` before persistence (mirroring `IncomingTokenHash`/`Salt`) and reveal it in plaintext only at creation time, matching `IncomingToken`'s `omitempty` one-time-reveal pattern.
- Remove `OutgoingToken` from `BridgeResource` for `Index`/`Show` responses and from `BridgeResolver.OutgoingToken()`, or restrict it to `admin` role only.
- Add a rotate/regenerate endpoint for `OutgoingToken`.

## Proof of Concept
1. As `admin`, create a user with `view` role (`POST /v2/users` with role `view`).
2. As `admin` or `edit` user, create a bridge: `POST /v2/bridge_types` (response includes `outgoingToken`, expected one-time reveal).
3. Authenticate as the `view`-role user (session cookie or API token).
4. As the `view` user, call `GET /v2/bridge_types` or `GET /v2/bridge_types/:BridgeName` — per `core/web/router.go` L268-271, no role check blocks this request.
5. Observe the JSON response includes the plaintext `outgoingToken` field for the bridge (per `presenters.BridgeResource`), confirming a `view`-role user obtained a secret intended to be edit/admin-scoped and shown only once at creation.
6. Equivalent: as the `view` user, POST to `/query` GraphQL endpoint with `{ bridge(name: "...") { outgoingToken } }` and observe the same plaintext value returned by `BridgeResolver.OutgoingToken()`.

// Index lists Bridges, one page at a time.
func (btc *BridgeTypesController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	bridges, count, err := btc.App.BridgeORM().BridgeTypes(ctx, offset, size)

	resources := make([]presenters.BridgeResource, 0, len(bridges))
	for _, bridge := range bridges {
		resources = append(resources, *presenters.NewBridgeResource(bridge))
	}

	paginatedResponse(c, "Bridges", size, page, resources, count, err)
}

// Show returns the details of a specific Bridge.
func (btc *BridgeTypesController) Show(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	bt, err := btc.App.BridgeORM().FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}
