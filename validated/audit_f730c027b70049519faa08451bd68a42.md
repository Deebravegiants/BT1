### Title
Unbounded router approval + unchecked input-token balance in `ExternalActionSwap` allows draining leftover swap dust from other users - (File: `contracts/external-actions/swaps/ExternalActionSwap.sol`, `contracts/external-actions/swaps/LifiExternalAction.sol`)

### Summary
`ExternalActionSwap.swap()` only verifies the **output**-token balance delta after the router call; it never checks that exactly `inputAmount` of the **input** token was consumed. Combined with `approveUnlimited`, which grants the router a persistent max allowance that is never revoked or reconciled, any leftover/un-consumed input-token balance sitting in the shared external-action contract can be pulled by a later, unrelated swap and credited entirely to that caller's own output UTXO.

### Finding Description
`callRouter` in `LifiExternalAction.sol` grants the router an unlimited, persistent allowance via `approveUnlimited(inputToken, router)` [1](#0-0)  and `approveUnlimited` in `TransfererBase.sol` only tops the allowance back up when it drops below half of `type(uint256).max` — it is never reduced or reset to the exact amount that should be spendable for a given swap [2](#0-1) .

`ExternalActionSwap.swap()` computes `inputAmount` from the circuit-committed `deltaAmounts[0]` and forwards it to `callRouter`, but after the router call it only measures the **output**-token balance change (`swappedAmount = getERC20OrETHBalance(outputToken) - balanceBefore`) inside `callRouter` [3](#0-2) . Nowhere in `swap()` is the **input**-token balance of the contract checked before/after the router call to confirm exactly `inputAmount` was consumed [4](#0-3) .

Because `Hinkal._externalTransact` first pushes the withdrawn input amount to the external action address, then calls `runAction` [5](#0-4) , any transaction whose router call under-consumes the input token (rounding, partial fill, slippage-limited fill, or an intentionally crafted `externalActionMetadata`) leaves the difference sitting in the shared `LifiExternalAction` contract balance, with the router still holding unlimited approval over it. Since `externalActionMetadata` is arbitrary calldata chosen by whoever builds the `CircomData` (it is merely hashed into `calldataHash`/`signedMessageHash` for integrity, not restricted in content — see `getHashedCalldata1` and `getSignedMessageHash` in `CircomDataBuilder.sol` [6](#0-5) [7](#0-6) ), a later unrelated user can build their own swap's metadata to instruct the router to pull the *same input token* beyond their own `inputAmount`, consuming the dust left by a previous user. `swap()` only ever checks that the resulting output increase is `>= 0` slippage-wise via `require(circomData.slippageValues[1] != 0, ...)`, and Hinkal's outer balance check in `transact()` only enforces `balanceDif >= circomData.slippageValues[i]` per token, i.e. it never disallows the attacker's own input-token withdrawal being smaller than what was actually swapped out of the shared contract's stored balance [8](#0-7) .

The net effect: value that belongs to a previous depositor (temporarily stuck, unswapped input token dust in the external-action contract) is moved out and credited to a subsequent unrelated caller's UTXO, without ever being reflected in that caller's own `amountChanges`/`deltaAmounts` for the input token — breaking the balance equation that Hinkal is supposed to enforce per token.

### Impact Explanation
This is a temporary/permanent freezing-then-theft of protocol/user funds: dust left in the shared `LifiExternalAction` contract (belonging to a previous swap's depositor, or the protocol) is not returned via UTXO and is drainable by any other unprivileged EOA performing a legitimate-looking swap through the same contract. This matches the High/Critical impact classes: theft of user/protocol funds via unauthorized asset movement through an external action, since no wallet owner or prover authorized the transfer of the leftover balance to the attacker.

### Likelihood Explanation
Requires (1) some input-token dust to accumulate in the shared `LifiExternalAction` contract (plausible from rounding, partial fills, or slippage-limited swaps that don't consume the full transferred-in amount) and (2) an attacker able to craft `externalActionMetadata`/router calldata that causes the router to pull more than their own `inputAmount` from the contract's balance. Both are achievable by any user building their own proof/circomData since `externalActionMetadata` content is unconstrained beyond being hashed for integrity.

### Recommendation
After `callRouter` returns, verify that the input-token balance of the external-action contract decreased by exactly `inputAmount` (mirroring the output-token balance check already performed), and revert otherwise. Additionally, avoid `approveUnlimited`; approve only the exact `inputAmount` needed per swap and reset the allowance to zero after the call (as `approveERC20Token` already does elsewhere in `TransfererBase.sol`), so unconsumed allowance/dust cannot be reused across unrelated transactions.

### Proof of Concept
1. User A performs a LI.FI swap of token `T` for token `O` through `LifiExternalAction`. Due to slippage/partial fill, the router only consumes `inputAmount - d` of `T`, leaving `d` tokens of `T` sitting in the `LifiExternalAction` contract balance, with the router still holding unlimited approval on `T` (`approveUnlimited`) [9](#0-8) .
2. User B, withdrawing their own `inputAmount'` of token `T` from Hinkal, crafts `externalActionMetadata` for the router that specifies pulling `inputAmount' + d` of `T` (using the router's normal swap-from-caller-balance semantics, since the router already has unlimited approval and `T` balance `inputAmount' + d` is present in the contract).
3. `callRouter` measures only the output token increase and returns `swappedAmount` reflecting the larger trade; `swap()` never checks that only `inputAmount'` of `T` was drawn down [10](#0-9) .
4. User B's resulting output UTXO includes value derived from User A's stranded `d` tokens, which User A can never reclaim.

    function callRouter(
        address inputToken,
        uint256 inputAmount,
        address outputToken,
        bytes calldata externalActionMetadata
    ) internal override returns (uint256 swappedAmount) {
        uint256 balanceBefore = getERC20OrETHBalance(outputToken);

        if (inputToken == address(0)) {
            (bool success, ) = router.call{value: inputAmount}(
                externalActionMetadata
            );
            require(success, "LI.FI swap failed: native coin");
        } else {
            approveUnlimited(inputToken, router);
            (bool success, ) = router.call(externalActionMetadata);
            require(success, "LI.FI swap failed: erc-20 token");
        }

        swappedAmount = getERC20OrETHBalance(outputToken) - balanceBefore;
    }

    function swap(
        CircomData calldata circomData,
        int256[] calldata deltaAmounts
    ) internal returns (UTXO[] memory utxoSet) {
        address inputToken = circomData.erc20TokenAddresses[0];
        uint256 inputAmount = uint256(-deltaAmounts[0]);

        if (inputToken == circomData.feeStructure.feeToken) {
            inputAmount -= circomData.feeStructure.flatFee;
        }

        address outputToken = circomData.erc20TokenAddresses[1];

        require(
            circomData.slippageValues[1] != 0,
            "swap output slippage floor not set"
        );

        require(
            block.timestamp <= circomData.timeStamp + SWAP_DEADLINE_WINDOW,
            "swap expired"
        );

        uint256 swappedAmount = callRouter(
            inputToken,
            inputAmount,
            outputToken,
            circomData.externalActionData.externalActionMetadata
        );

        uint256 relayFee = circomData.feeStructure.flatFee;

        uint256 hinkalFee = hinkalHelper.calculateRelayFee(
            swappedAmount,
            0,
            circomData.feeStructure.variableRate
        );

        if (circomData.feeStructure.feeToken == outputToken) {
            sendToRelay(circomData.relay, relayFee + hinkalFee, outputToken);
        } else {
            sendToRelay(
                circomData.relay,
                relayFee,
                circomData.feeStructure.feeToken
            );
            sendToRelay(circomData.relay, hinkalFee, outputToken);
        }

        uint256 totalFee = hinkalFee +
            (outputToken == circomData.feeStructure.feeToken ? relayFee : 0);
        uint256 amountToSendToHinkal = swappedAmount - totalFee;

        transferERC20TokenOrETH(outputToken, msg.sender, amountToSendToHinkal);

        utxoSet = new UTXO[](1);
        utxoSet[0] = UTXO({
            amount: amountToSendToHinkal,
            erc20Address: outputToken,
            stealthAddressStructure: circomData.stealthAddressStructure,
            timeStamp: block.timestamp
        });
    }
