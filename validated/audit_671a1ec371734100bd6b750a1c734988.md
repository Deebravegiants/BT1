## Analysis

The reported bug class is **state-mutating functions with no access control**, reachable directly by any caller. Searching for an analogous pattern in the chainlink codebase (the node's web API, not on-chain contracts), the closest reachable analog is the `/v2/resume/:runID` route, which is registered on the **unauthenticated** route group and directly mutates pipeline run state and can force job resumption with attacker-supplied data.

### Title
Unauthenticated `PipelineRunsController.Resume` endpoint allows unauthorized resumption of any pipeline task run with attacker-controlled results - (File: `core/web/pipeline_runs_controller.go`)

### Summary
The `/v2/resume/:runID` HTTP route is registered on the `unauthedv2` router group (no session/token authentication middleware applied), yet its handler, `PipelineRunsController.Resume`, performs a state-changing operation: it finalizes a pending pipeline task run with a caller-supplied JSON body and resumes the entire job run.

### Finding Description
In `core/web/router.go`, the route is wired without any authentication middleware, unlike every other mutating route in `v2Routes`, which is wrapped in `auth.Authenticate(...)` and role checks such as `auth.RequiresRunRole` / `auth.RequiresEditRole`: [1](#0-0) 

```go
unauthedv2 := r.Group("/v2")
prc := PipelineRunsController{app}
...
unauthedv2.PATCH("/resume/:runID", prc.Resume)
```

The handler itself performs no authentication/authorization check — it parses the `runID` path parameter as a UUID, decodes an arbitrary JSON body into a `pipeline.ResumeRequest`, and immediately calls `App.ResumeJobV2`: [2](#0-1) 

`ResumeJobV2` forwards directly into the pipeline `Runner.ResumeRun`, which updates the task run result in the database and, if all pending tasks are resolved, restarts execution of the entire pipeline run with the supplied (attacker-controlled) value/error: [3](#0-2) [4](#0-3) 

The only thing standing between an unprivileged network caller and this state mutation is knowledge of the `taskID` (a UUID used internally as an async bridge callback token, embedded in the `responseURL` sent to external bridge adapters): [5](#0-4) 

This is the same bug class as `mintRebalancer`/`burnRebalancer`: a state-mutating entrypoint with **zero access-control middleware**, whose only protection is an implicit, non-authenticated secret (the UUID) rather than an explicit authorization check (role, session, API key, or HMAC/signature validation). Unlike proper authentication, there is no rate-limiting, no revocation, and no scoping to a specific caller/bridge — any party that obtains or brute/guesses a valid pending run's UUID can inject arbitrary results.

### Impact Explanation
An attacker who learns or brute-forces a pending task's UUID (e.g., leaked through the external bridge adapter's request logs, browser history, HTTP proxies, or any observability tooling capturing the `responseURL`) can supply arbitrary `Result`/`Error` values for that task and force the pipeline to resume/finalize with attacker-chosen data. Since these pipeline runs frequently feed price data into OCR/Flux Monitor jobs or trigger downstream on-chain transactions, this could corrupt data feeding on-chain reports or falsely mark a run as errored/completed — a direct integrity compromise of job execution with no authentication bypassing role checks used everywhere else in the router.

### Likelihood Explanation
Exploitation requires obtaining a valid pending task UUID, which is not trivial to guess (UUIDv4 space) but is exposed to whichever external system a bridge task calls out to, and to anything in that request's egress path (proxies/logs/network taps) — a real, if narrower, exposure than a fully public endpoint. This is a materially weaker protection than the authenticated/role-checked routes used for every other mutating action in the router.

### Recommendation
Require authentication akin to other run-mutating routes (`auth.RequiresRunRole`) or, since the design intentionally supports external bridge callbacks, replace the bare UUID with a signed/HMAC token (or per-run cryptographically random secret validated server-side, with single-use/expiry semantics) instead of relying solely on the task UUID as an implicit bearer credential. Add rate limiting and audit alerting on repeated resume attempts against unknown/mismatched UUIDs.

### Proof of Concept
1. Observe or intercept the `responseURL` sent by a `BridgeTask` (contains `/v2/resume/<taskUUID>`), e.g. via network logging on the bridge/EA side.
2. Send `PATCH /v2/resume/<taskUUID>` with a crafted JSON body (`{"data": {...arbitrary...}}` or an error payload) without any authentication headers.
3. Observe the pipeline run resumes/finalizes using the attacker-supplied value, as confirmed by test `TestPipelineRunsController_...` patterns and `runner.ResumeRun` at [4](#0-3) , with no authorization check anywhere in the call chain from `core/web/router.go` line 243 through `pipeline_runs_controller.go` `Resume`.

```go
func (prc *PipelineRunsController) Resume(c *gin.Context) {
	taskID, err := uuid.Parse(c.Param("runID"))
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	rr := pipeline.ResumeRequest{}
	decoder := json.NewDecoder(c.Request.Body)
	err = errors.Wrap(decoder.Decode(&rr), "failed to unmarshal JSON body")
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	result, err := rr.ToResult()
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	if err := prc.App.ResumeJobV2(c.Request.Context(), taskID, result); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
	c.Status(http.StatusOK)
}
```

```go
func (r *runner) ResumeRun(ctx context.Context, taskID uuid.UUID, value any, err error) error {
	run, start, err := r.orm.UpdateTaskRunResult(ctx, taskID, Result{
		Value: value,
		Error: err,
	})
	if err != nil {
		return fmt.Errorf("failed to update task run result: %w", err)
	}

	// TODO: Should probably replace this with a listener to update events
	// which allows to pass in a transactionalised database to this function
	if start {
		// start the runner again
		go func() {
			ctx, cancel := r.chStop.NewCtx()
			defer cancel()
			if _, err := r.Run(ctx, &run, false, nil); err != nil {
				r.lggr.Errorw("Resume run failure", "err", err)
			}
			r.lggr.Debug("Resume run success")
		}()
	}
	return nil
}
```
