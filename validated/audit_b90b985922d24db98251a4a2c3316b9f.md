### Title
Missing source-identity check on `RequestState` messages allows any relay peer to elicit the orb's last cached session message - (File: `orb-relay-client/src/client.rs`)

### Summary
In the `PollerAgent::main_loop` function, inbound relay messages are normally validated against the expected counterparty (`self.config.dst_id`) before being accepted, mirroring an "is this sender still an authorized party for this session" check. However, messages matching `self_serve::app::v1::RequestState` are handled in a special branch that runs *before* this identity check, so they are always answered with the client's cached `last_message`, regardless of whether `src.id` matches the bound session peer.

### Finding Description
The relay client (used by both the orb and the app to speak to each other via the relay server, keyed by `src_id`/`dst_id`/`session_id`) treats every inbound `RelayPayload` uniformly except for one type. Looking at the message loop: [1](#0-0) 

The `if self_serve::app::v1::RequestState::matches(&payload).is_some()` branch responds by re-sending `self.last_message.clone()` to `sender_tx` unconditionally. Only in the `else` branches is the sender's identity validated with `src.id != self.config.dst_id`, and only then is the "unexpected source" rejection path ( [2](#0-1) ) exercised.

This is structurally identical to the Maia bug: a per-message-type code path that skips the authorization/binding check ("is this counterparty still the one this session is paired with") that every other inbound message must pass, letting communication continue with a party that should be treated as unauthorized for this session/channel — just as a deactivated `BranchBridgeAgent` could still originate/receive calls because `callOut()`/`lzReceiveNonBlocking()` never checked `isBridgeAgent`.

`last_message` holds the most recently sent `RelayConnectRequest` (i.e., the last outgoing signup/session payload, e.g. `AnnounceOrbId`, `SignupEnded`, or other self-serve protocol state): [3](#0-2) [4](#0-3) 

### Impact Explanation
Because the `RequestState` fast-path is not gated by the `src.id == dst_id` binding check, any message routed to the client that the relay server labels as coming from *some* `src` (not necessarily the `dst_id` this client session is bound to) will still cause the orb (or app) to echo back its last cached session state. This can leak the last cross-signup/session protocol message (e.g. `AnnounceOrbId`, `SignupEnded` with failure feedback, or other self-serve state carrying session/orb identifiers) to an unintended or unauthorized counterparty, and represents cross-signup/session state bleed: state intended only for the currently paired app/orb session is disclosed to whichever entity's message reaches this branch, since the authorization check that exists specifically to filter out non-paired senders never runs for this message type.

### Likelihood Explanation
This triggers deterministically whenever a `RequestState` payload arrives with a `src` that is not the bound `dst_id` — there is no additional precondition or race required; the ordering of the `if`/`else if` in the match arm guarantees the identity check is unreachable for this message type. The likelihood of an unrelated/unpaired sender's `RequestState` message reaching this code path depends on relay-server-side routing guarantees, but the client-side check that is supposed to be the last line of defense against this is completely bypassed for this message type.

### Recommendation
Move the `src.id != self.config.dst_id` validation to apply uniformly, before dispatching on payload type, so that `RequestState` is only honored when it comes from the currently bound session peer:
```rust
if src.id != self.config.dst_id {
    tracing::error!("Skipping received message from unexpected source: {:?}", src.id);
} else if self_serve::app::v1::RequestState::matches(&payload).is_some() {
    sender_tx.send(self.last_message.clone()).await.wrap_err("Failed to send outgoing message")?;
} else {
    self.handle_message(...).await?;
}
```

### Proof of Concept
1. Client A connects as the orb with `dst_id = session_id_X` and previously sent `last_message = AnnounceOrbId { orb_id, ... }` for session X.
2. A relay message arrives at Client A whose `src.id != session_id_X` (i.e., not the currently bound app/session peer) but whose payload matches `self_serve::app::v1::RequestState`.
3. Per [5](#0-4) , Client A immediately re-sends `self.last_message` — the cached session-X state — without ever reaching the `src.id != self.config.dst_id` rejection at line 441, disclosing the last session-scoped message to a party never validated as the paired counterparty for that session.
