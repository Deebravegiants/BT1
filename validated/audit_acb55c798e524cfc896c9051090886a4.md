### Title
`socialize-debt` write-down uses two inconsistent ratios (`idx` vs `total-borrowed/principal-scaled`) causing `assets`/`total-borrowed` decrement to diverge from the debt actually erased - (File: `mainnet/contracts/vault/v0-vault-sbtc.clar`)

### Summary
`socialize-debt` computes two different quantities for the same "amount of debt to erase" — `debt-reduction` (used to write down `lindex`/`total-assets`, i.e. share price) and `principal-reduction` (used to decrement `assets` and `total-borrowed`) — from two different ratios that are not guaranteed to be equal. This creates a structural accounting divergence in the vault's insolvency bookkeeping that is independent of how the market computed `scaled-amount`.

### Finding Description
Identity that should hold: `debt-reduction == principal-reduction`, since both are meant to represent the token value of the same `scaled-amount` of bad debt being wiped from the books.

Code (`mainnet/contracts/vault/v0-vault-sbtc.clar:942-968`):
```
(debt-reduction (mul-div-down scaled-amount idx INDEX-PRECISION))
(principal-reduction (if (> scaled-principal u0)
                        (mul-div-down scaled-amount borrowed scaled-principal)
                        u0))
...
(var-set total-borrowed (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0))
(var-set assets (if (> current-assets principal-reduction) (- current-assets principal-reduction) u0))
``` [1](#0-0) 

`debt-reduction` is derived from the live global borrow `index` (`idx`), i.e. `scaled-amount * idx / INDEX-PRECISION`, which correctly represents the accrued (principal+interest) value of `scaled-amount` scaled units at the current index. `principal-reduction`, however, is derived from `borrowed / scaled-principal` — the ratio of the vault's aggregate `total-borrowed` register to the aggregate `principal-scaled` register. `total-borrowed` in this codebase's `system-repay` path is tracked as a nominal principal register, adjusted separately from `interest-paid` on each repay/system-repay event (see the sibling `principal-repaid`/`interest-paid`/`total-borrowed-new` fields emitted just above `socialize-debt`) [2](#0-1) , rather than being continuously re-derived as `principal-scaled * idx / INDEX-PRECISION`. Consequently `borrowed/scaled-principal` is effectively an average of historical/origination indices across all outstanding scaled principal, not the current `idx`. Once `idx` has drifted from `INDEX-PRECISION` (i.e. once any interest has accrued since inception), `borrowed/scaled-principal != idx/INDEX-PRECISION` in general, so `debt-reduction != principal-reduction` for the same `scaled-amount`.

Reachability: `socialize-debt` is only callable by the market (`check-caller-auth`) [3](#0-2) , and the market invokes it from `socialize-debt-asset` during a normal, unprivileged liquidation whenever a borrower's collateral is fully exhausted (`no-collateral-left`), passing the borrower's genuine remaining scaled debt (`debt-updated`) as `scaled-amount` [4](#0-3) . No oracle bug or DAO action is required — any ordinary liquidator calling `liquidate` on an undercollateralized position that leaves zero collateral triggers this path. (Note: the `scaled-amount` passed is the actual leftover uncollateralized scaled debt, not a `scaled-to-remove/scaled-debt` fraction as initially hypothesized in the question — but that correction does not remove the bug: the divergence is intrinsic to `socialize-debt`'s dual-ratio calculation and fires on every bad-debt socialization once `idx` has moved off `INDEX-PRECISION`, regardless of how `scaled-amount` was derived.)

Existing guards (`check-caller-auth`, `> scaled-amount u0`) only gate *who* can call the function and reject zero amounts; they do nothing to reconcile the two ratios. No slippage/min-out check applies since `socialize-debt` is an internal system call with no user-supplied bound.

### Impact Explanation
Every bad-debt socialization event where `idx > INDEX-PRECISION` (i.e., any time interest has accrued in the vault's history, which is the normal case) writes down `assets`/`total-borrowed` by an amount (`principal-reduction`) that differs from the amount by which `lindex`/`total-assets` (and thus share price for zft holders) is written down (`debt-reduction`). This is repeatable on every liquidation that fully exhausts a borrower's collateral. Depending on the sign of the divergence, either `assets` is under-decremented relative to the real solvency hit recorded via `lindex` (leaving a phantom asset balance that doesn't back real value — a silent insolvency/inflation of `total-borrowed`/`assets` state), or over-decremented (destroying more principal accounting than actually happened). Either direction breaks the internal consistency the protocol relies on to compute `total-assets` and share price, ultimately absorbed by zft depositors whose claims are calculated off state that has silently diverged from actual solvency — matching the Critical/protocol-insolvency category.

### Likelihood Explanation
Preconditions are trivial and require no privileged access: an ordinary liquidator triggers a normal liquidation of any undercollateralized position down to zero remaining collateral (a routine, economically-incentivized action liquidators already perform for the liquidation bonus). No oracle manipulation or capital beyond typical liquidation capital is needed. The divergence occurs on essentially every such liquidation once the vault has accrued any interest (which is the normal, expected long-run state of `idx`), making this highly likely to manifest in production rather than a rare edge case.

### Recommendation
Compute both `debt-reduction` and `principal-reduction` from the same authoritative ratio. Since `debt-reduction = scaled-amount * idx / INDEX-PRECISION` correctly represents the accrued value being erased, derive `principal-reduction` from the same `idx`-based conversion (or, if `total-borrowed`/`assets` must remain in nominal-principal terms, redefine them to always be kept in sync with `principal-scaled * idx / INDEX-PRECISION` via `accrue`, eliminating the independent `borrowed/scaled-principal` ratio entirely). Add an invariant test asserting `debt-reduction == principal-reduction` (or an explicit documented conversion between them) on every `socialize-debt` call.

### Proof of Concept
Clarinet/simnet test plan:
1. Deploy vault + market, set up two borrowers over time so that `total-borrowed` and `principal-scaled` are populated at *different* historical indices (borrow #1 early, let interest accrue, borrow #2 later), so `borrowed/scaled-principal != idx/INDEX-PRECISION`.
2. Advance blocks / call `accrue` so `idx > INDEX-PRECISION`.
3. Fully liquidate a borrower's position to zero collateral so the market calls `vault-socialize-debt` with the borrower's genuine remaining `scaled-amount` (`debt-updated`).
4. Read pre-call `assets`, `total-borrowed`, `lindex`, `total-assets`.
5. Call `socialize-debt scaled-amount` and read post-call `assets`, `total-borrowed`, `lindex`.
6. Assert:
   - `debt-reduction = mul-div-down(scaled-amount, idx, INDEX-PRECISION)`
   - `principal-reduction = mul-div-down(scaled-amount, borrowed, scaled-principal)`
   - `(old-assets - new-assets) == principal-reduction` (matches code)
   - `(old-assets - new-assets) != debt-reduction` (demonstrates the break)
   - Assert the resulting `new-lindex`-derived `total-assets` no longer matches `old-assets - principal-reduction` minus interest, i.e. the two bookkeeping systems (`assets`/`total-borrowed` vs `lindex`/`total-assets`) have permanently diverged by `|debt-reduction - principal-reduction|`.
