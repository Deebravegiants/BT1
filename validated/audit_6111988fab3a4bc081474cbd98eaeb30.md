## Custody Analog Found: Stale `TombStone` Reclaim Right Survives Ordinary Object Transfers, Enabling Object Theft From the Burn Address

### Title
Stale `TombStone.original_owner` persists across plain (non-ref) object transfers, letting a former owner reclaim an object from `BURN_ADDRESS` after a different, later owner burns it — (File: `aptos-move/framework/aptos-framework/sources/object.move`)

### Summary
`object::burn` marks an object as "soft-burnt" by attaching a `TombStone{original_owner}` resource while leaving the object's actual ownership and transferability untouched [1](#0-0) . The only code path that clears a stale `TombStone` on ownership change is `transfer_with_ref` (the `LinearTransferRef` / `TransferRef`-gated path) [2](#0-1) . The plain, address-based transfer path used by `object::transfer`, `object::transfer_call`, and `object::transfer_to_object` — all of which route through `transfer_raw` → `transfer_raw_inner` — never inspects or clears `TombStone` [3](#0-2) . Consequently a `TombStone.original_owner` recorded by owner A can outlive many subsequent legitimate ownership transfers made through the plain path. `unburn`'s "old functionality" branch, which is reached whenever the object's current owner is `BURN_ADDRESS`, trusts this stale `original_owner` field unconditionally and returns the object to it [4](#0-3) .

### Finding Description
1. Owner A owns object `O`. A calls `object::burn(A, O)`. This does not transfer `O` or disable `allow_ungated_transfer` — it only attaches `TombStone{original_owner: A}` while A remains the owner [5](#0-4) .
2. A later legitimately transfers `O` to B using the ordinary transfer entrypoints (`object::transfer`/`transfer_call`/`transfer_to_object`), which resolve to `transfer_raw_inner`. This function only checks `allow_ungated_transfer` along the ownership chain and updates `ObjectCore.owner`; it never touches `TombStone` [6](#0-5) . The stale `TombStone{original_owner: A}` silently persists on the object even though B is now the true owner.
3. At some later point, B (or any subsequent owner down a legitimate ownership chain) performs a normal transfer of `O` to `BURN_ADDRESS` (`0xff...ff`) — a legal, ungated destination for `transfer_raw`, since `verify_ungated_and_descendant` never special-cases `BURN_ADDRESS` [7](#0-6) . This is exactly the intended way a *current* owner is meant to hard-burn an object.
4. Because the stale `TombStone{original_owner: A}` was never cleared in step 2, `unburn`'s branch for `object_core.owner == BURN_ADDRESS` fires when **A** calls `unburn(A, O)`, matches `original_owner_addr == A`, and transfers `O` back to A [8](#0-7) .

The broken invariant: a "reclaim right" recorded via `TombStone` is supposed to belong to whoever actually placed the object at `BURN_ADDRESS` (or the object's owner at time of soft-burn), but the plain transfer path never invalidates or re-associates that right when ownership legitimately changes hands. A stale, unprivileged former owner (A) ends up with silent custody authority over an object it no longer owns, that authority activating precisely when a legitimate later owner performs the standard burn-to-address action.

### Impact Explanation
This is a genuine owner-reassignment/custody-control bug on Aptos object primitives, which back token objects, NFT collections, and any resource that uses the object model for custody. A former owner can regain control of (steal) an object it sold/transferred away, whenever any later legitimate owner sends that object to the standard burn address — undermining the "permanently destroyed / non-recoverable" guarantee the burn address is meant to provide, and instead redirecting value to an unprivileged, unrelated address (the original burner), which meets the "theft / owner reassignment of ... token objects" and "moves value to the wrong holder / destroys recovery rights" custody-impact criteria.

### Likelihood Explanation
Exploitation only requires: (a) calling the public, permissionless `object::burn` once as any owner, (b) subsequently transferring the object through any of the ordinary (non-`TransferRef`) transfer entrypoints — which are the default/most common transfer paths for objects and NFTs — and (c) waiting for or inducing any future owner to send the object to `BURN_ADDRESS`, itself a normal and expected action for anyone wanting to permanently retire an object. No privileged roles, governance, or race conditions are needed, and the sequence of operations is entirely composed of public entry functions.

### Recommendation
`transfer_raw_inner` (and therefore `transfer`, `transfer_call`, `transfer_to_object`) should clear any existing `TombStone` on ownership change, mirroring what `transfer_with_ref` already does, so that a `TombStone.original_owner` can never survive past the owner who created it. Alternatively, `unburn`'s `BURN_ADDRESS` branch should be removed/deprecated in favor of requiring all "hard burns" to route exclusively through `burn_object_with_transfer`-style logic that atomically sets and validates the tombstone at the same time ownership moves to `BURN_ADDRESS`, eliminating any window where a `TombStone` can be inherited from a prior, unrelated ownership epoch.

### Proof of Concept
```
// 1. A owns object O.
object::burn(A, O);                       // TombStone{original_owner: A} attached; A still owns O.

// 2. A legitimately sells/transfers O via a normal path (NOT via TransferRef).
object::transfer(A, O, B);                // transfer_raw_inner: owner updated to B, TombStone untouched.

// ... time passes, B is the legitimate, sole owner, unaware of the stale TombStone ...

// 3. B (or a later legitimate owner) burns O the standard way.
object::transfer(B, O, BURN_ADDRESS);     // owner updated to BURN_ADDRESS; stale TombStone still says original_owner = A.

// 4. A, who no longer owns O and did not perform this burn, reclaims it.
object::unburn(A, O);                     // owner == BURN_ADDRESS branch; original_owner_addr == A matches signer A; O transferred back to A.
```
A now controls `O`, even though B (or a downstream legitimate owner) is the party that actually performed the final burn and should be the only one able to reclaim it (or nobody should be able to, per the intended "permanent burn" semantics).

    inline fun transfer_raw_inner(object: address, to: address) {
        let object_core = borrow_global_mut<ObjectCore>(object);
        if (object_core.owner != to) {
            event::emit(
                Transfer {
                    object,
                    from: object_core.owner,
                    to,
                },
            );
            object_core.owner = to;
        };
    }

    fun verify_ungated_and_descendant(owner: address, destination: address) {
        let current_address = destination;
        assert!(
            exists<ObjectCore>(current_address),
            error::not_found(EOBJECT_DOES_NOT_EXIST),
        );

        let object = borrow_global<ObjectCore>(current_address);
        assert!(
            object.allow_ungated_transfer,
            error::permission_denied(ENO_UNGATED_TRANSFERS),
        );

        let current_address = object.owner;
        let count = 0;
        while (owner != current_address) {
            count += 1;
            assert!(count < MAXIMUM_OBJECT_NESTING, error::out_of_range(EMAXIMUM_NESTING));
            // At this point, the first object exists and so the more likely case is that the
            // object's owner is not an object. So we return a more sensible error.
            assert!(
                exists<ObjectCore>(current_address),
                error::permission_denied(ENOT_OBJECT_OWNER),
            );
            let object = borrow_global<ObjectCore>(current_address);
            assert!(
                object.allow_ungated_transfer,
                error::permission_denied(ENO_UNGATED_TRANSFERS),
            );
            current_address = object.owner;
        };
    }

    public entry fun burn<T: key>(owner: &signer, object: Object<T>) {
        let original_owner = signer::address_of(owner);
        assert!(is_owner(object, original_owner), error::permission_denied(ENOT_OBJECT_OWNER));
        let object_addr = object.inner;
        assert!(!exists<TombStone>(object_addr), EOBJECT_ALREADY_BURNT);
        move_to(&create_signer(object_addr), TombStone { original_owner });

    /// Allow origin owners to reclaim any objects they previous burnt.
    public entry fun unburn<T: key>(
        original_owner: &signer,
        object: Object<T>,
    ) {
        let object_addr = object.inner;
        assert!(exists<TombStone>(object_addr), error::invalid_argument(EOBJECT_NOT_BURNT));

        // The new owner of the object can always unburn it, but if it's the burn address, we go to the old functionality
        let object_core = borrow_global<ObjectCore>(object_addr);
        if (object_core.owner == signer::address_of(original_owner)) {
            let TombStone { original_owner: _ } = move_from<TombStone>(object_addr);
        } else if (object_core.owner == BURN_ADDRESS) {
            // The old functionality
            let TombStone { original_owner: original_owner_addr } = move_from<TombStone>(object_addr);
            assert!(
                original_owner_addr == signer::address_of(original_owner),
                error::permission_denied(ENOT_OBJECT_OWNER)
            );
            transfer_raw_inner(object_addr, original_owner_addr);
        } else {
            abort error::permission_denied(ENOT_OBJECT_OWNER);
        };
    }
