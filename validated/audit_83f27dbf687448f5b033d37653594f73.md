### Title
Unrestricted account enumeration in `WithdrawExcessLamports` allows permissionless lamport exfiltration from any pool's vaults - (File: `program/src/processor.rs`)

### Summary
The `WithdrawExcessLamports` instruction handler accepts an open-ended list of trailing accounts and sweeps "excess lamports" out of every one whose owner matches `spl_token::id()` or `program_id`, without any check binding those accounts to the specific AMM pool the caller is authorized to act on. This mirrors the ComfyUI bug class: a workflow/attacker-controlled account reference is used to reach and drain state without a containment check tying it to the caller's own resource.

### Finding Description
`process_withdraw_excess_lamports` only validates `token_program_info` and derives/validates `amm_authority_info` using the fixed, publicly-known nonce `254`: [1](#0-0) 

It then loops over *all remaining accounts supplied by the caller* with no restriction tying them to a specific pool, an owning wallet, or any pool-identifying account (no `amm_info`/`AmmInfo::load_mut_checked` binding is performed for these trailing accounts): [2](#0-1) 

For any account owned by the SPL Token program, `withdraw_excess_lamports_from_token` is invoked using the *shared* `amm_authority_info` (the single PDA derived from `AUTHORITY_AMM` with nonce 254 that is the vault authority for *every* Raydium pool created by `Initialize2`), and moves the "excess" lamports to `collect_lamports_info`, an attacker-supplied destination: [3](#0-2) 

Because `Initialize2` sets every pool's coin/pc vault owner to this same global `amm_authority` PDA, `amm_authority_info` legitimately authorizes the underlying `spl_token::instruction::sync_native` / `withdraw_excess_lamports` CPIs for *any* pool's vault—not just the pool the caller intends to operate on. There is no check anywhere in `process_withdraw_excess_lamports` that the supplied token accounts equal a specific `amm.coin_vault` / `amm.pc_vault` recorded in an `AmmInfo::load_mut_checked` account, unlike the pattern consistently used in `process_deposit`, `process_withdraw`, and the swap handlers (e.g. `check_assert_eq!(*amm_coin_vault_info.key, amm.coin_vault, ...)`): [4](#0-3) 

This is the same root-cause pattern as the ComfyUI report: a resource reference supplied by the caller (there, a filename; here, an arbitrary SPL-token/program-owned account) is used to reach and act on state with no containment/binding check restricting it to the caller's own authorized resource (there, the configured input directory; here, the specific pool being operated on).

### Impact Explanation
Any unprivileged party can submit a single `WithdrawExcessLamports` transaction, attach as trailing accounts the vault/mint/target-orders/other program-owned accounts belonging to *any* Raydium pool (all publicly discoverable on-chain), and set `collect_lamports_info` to an account they control. Every lamport balance above the rent-exempt minimum held in those accounts (e.g., from users over-funding wSOL vaults, dust, or lamport growth) is transferred to the attacker's destination instead of the legitimate pool/protocol owner, with no requirement that the caller be the owner, admin, or even LP of that pool. This is a concrete theft-of-funds primitive against SOL held by every deployed pool sharing the same `amm_authority` PDA.

### Likelihood Explanation
The instruction requires only a single transaction with attacker-chosen accounts and no privileged signature—`amm_authority_info`'s expected pubkey is deterministically derivable from `program_id` and the fixed nonce `254`, and target vault pubkeys are public on-chain data. No signer check restricts who may invoke this path or what `collect_lamports_info` may be, based on the code reviewed. (Note: the portion of `process_withdraw_excess_lamports` preceding the snippet shown, i.e. how `collect_lamports_info` itself is derived/validated, was not fully visible in the retrieved context; if that account is additionally constrained—e.g., to a fixed protocol-fee address—the destination side of the exploit would be limited accordingly, though the cross-pool vault-draining behavior via the shared authority would remain.)

### Recommendation
Bind every account processed by `WithdrawExcessLamports` to a specific `AmmInfo` loaded via `AmmInfo::load_mut_checked`, requiring the trailing accounts to equal that pool's own `coin_vault`, `pc_vault`, `lp_mint`, `target_orders`, etc. (as done in `process_deposit`/`process_withdraw`/swap handlers), and require the pool's admin/owner to sign, rather than allowing an open loop over arbitrary caller-supplied accounts under a shared global authority.

### Proof of Concept
1. Attacker builds a `WithdrawExcessLamports` instruction for the Raydium AMM program.
2. Accounts: `token_program_info` = SPL Token program, `amm_authority_info` = `find_program_address([AUTHORITY_AMM], program_id)` derived with nonce `254` (public), `collect_lamports_info` = attacker-owned account, followed by N trailing accounts = publicly known `coin_vault`/`pc_vault` (or other SPL-token/program-owned) accounts of one or more victim pools.
3. Submit the transaction as an unprivileged signer (fee payer only).
4. For each trailing account whose lamport balance exceeds the SPL Token rent-exempt minimum, `withdraw_excess_lamports_from_token` executes `sync_native`/`unwrap_lamports` or `withdraw_excess_lamports` CPIs authorized by the shared `amm_authority` PDA, transferring the excess lamports into `collect_lamports_info` — funds belonging to victim pools/protocol, not the caller.     fn withdraw_excess_lamports_from_token<'a>(
        token_program_info: &AccountInfo<'a>,
        source_account_info: &AccountInfo<'a>,
        destination_account_info: &AccountInfo<'a>,
        amm_authority_info: &AccountInfo<'a>,
        amm_seed: &[u8],
        nonce: u8,
    ) -> Result<(), ProgramError> {
        if source_account_info.data_len() == spl_token::state::Account::LEN {
            // Token Account

            let (is_native, amount_before_sync) = {
                let data = source_account_info.try_borrow_data()?;
                (
                    data[109] == 1,
                    u64::from_le_bytes(data[64..72].try_into().unwrap()),
                )
            };
            if is_native {
                // Native token account, use SyncNative and UnwrapLamports

                // Because directly using UnwrapLamports would affect the native token amount,
                // we first perform a SyncNative operation to convert all excess lamports into WSOL.
                // And then compare the difference in the amount before and after the conversion,
                // and finally perform the UnwrapLamports operation.
                invoke(
                    &spl_token::instruction::sync_native(
                        token_program_info.key,
                        source_account_info.key,
                    )?,
                    &[token_program_info.clone(), source_account_info.clone()],
                )?;

                let amount_after_sync = {
                    let data = source_account_info.try_borrow_data()?;
                    u64::from_le_bytes(data[64..72].try_into().unwrap())
                };
                let excess_lamports = amount_after_sync
                    .checked_sub(amount_before_sync)
                    .ok_or(ProgramError::InsufficientFunds)?;
                if excess_lamports == 0 {
                    return Ok(());
                } else {
                    Invokers::unwrap_lamports(
                        token_program_info.clone(),
                        source_account_info.clone(),
                        destination_account_info.clone(),
                        amm_authority_info.clone(),
                        amm_seed,
                        nonce,
                        Some(excess_lamports),
                    )?;
                    let amount_after_unwrap = {
                        let data = source_account_info.try_borrow_data()?;
                        u64::from_le_bytes(data[64..72].try_into().unwrap())
                    };
                    // Check the amount unchanged before and after these operations.
                    if amount_before_sync != amount_after_unwrap {
                        return Err(AmmError::LamportsCalculateError.into());
                    }
                }
            } else {
                // Not native token account, use WithdrawExcessLamports
                Invokers::withdraw_excess_lamports(
                    token_program_info.clone(),
                    source_account_info.clone(),
                    destination_account_info.clone(),
                    amm_authority_info.clone(),
                    amm_seed,
                    nonce,
                )?;
            }
        } else {
            // Mint Account, use WithdrawExcessLamports
            Invokers::withdraw_excess_lamports(
                token_program_info.clone(),
                source_account_info.clone(),
                destination_account_info.clone(),
                amm_authority_info.clone(),
                amm_seed,
                nonce,
            )?;
        }
        return Ok(());
    }
