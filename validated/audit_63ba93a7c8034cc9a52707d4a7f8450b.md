### Title
`vesting::withdraw_stake` sweeps the vesting contract's entire APT balance instead of only the amount just distributed, letting externally-sent APT be permanently re-appropriated to shareholders/operator - ([File: aptos-move/framework/aptos-framework/sources/vesting.move])

### Summary
`vesting::withdraw_stake` reads `coin::balance<AptosCoin>(contract_address)` after calling `staking_contract::distribute` and withdraws the *whole* balance of the vesting contract's resource account, rather than only the amount that `distribute` actually deposited in that call. This is structurally the same "whole balance instead of just the acquired funds" pattern described in the external report (Aave-margin whole-balance deposit).

### Finding Description
`withdraw_stake` is used by both `distribute()` and `terminate_vesting_contract`/`admin_withdraw` flows: [1](#0-0) 

```
fun withdraw_stake(vesting_contract: &VestingContract, contract_address: address): Coin<AptosCoin> {
    // Claim any withdrawable distribution from the staking contract. The withdrawn coins will be sent directly to
    // the vesting contract's account.
    staking_contract::distribute(contract_address, vesting_contract.staking.operator);
    let withdrawn_coins = coin::balance<AptosCoin>(contract_address);
    let contract_signer = &get_vesting_account_signer_internal(vesting_contract);
    coin::withdraw<AptosCoin>(contract_signer, withdrawn_coins)
}
```

Note the comment itself acknowledges the intent ("claim any withdrawable distribution ... sent directly to the vesting contract's account") but the implementation measures `coin::balance` of the whole account rather than diffing before/after the `staking_contract::distribute` call — exactly the anti-pattern flagged in the Sherlock report (`_tradeAmounts[i] = IERC20(_tradeAssets[i]).balanceOf(address(this))`).

The vesting contract's resource account (`contract_address`) is a public, deterministic address (derived from admin address + nonce/seed, exposed via `vesting_contracts` view function and `CreateVestingContract` event) and its `CoinStore<AptosCoin>` gets registered as a side effect of `staking_contract::distribute` depositing to it. Once a `CoinStore` exists at that address, any third party can send APT to it directly via a normal transfer (e.g., `aptos_account::transfer`), since resource accounts have no auth key to block incoming deposits.

`withdraw_stake` is invoked from `distribute()`: [2](#0-1) 

The returned `Coin<AptosCoin>` is then split among shareholders (and dust to the withdrawal address) purely according to `grant_pool` shares — there is no mechanism to identify or return coins that did not originate from the staking distribution.

### Impact Explanation
Any APT accidentally or intentionally sent to a vesting contract's resource account address is, on the next call to `distribute()`, `vest()`, or `terminate_vesting_contract`/`admin_withdraw`, swept up together with the legitimate staking distribution and redistributed to the vesting contract's shareholders (and operator, who can additionally take commission on it via `staking_contract::distribute`'s accounting, though commission there is computed on stake-pool rewards, not this literal balance). The original sender has no recovery path — the funds are custody-reassigned to unrelated shareholders/operator, matching "Supply or custody accounting corruption that moves value to the wrong holder or destroys recovery rights."

However, this requires a third party to send APT directly to a known but not user-facing resource-account address, which is closer to an accidental-transfer scenario than a directly and independently exploitable authority break (there is no privileged/unauthorized call needed — the loss is triggered by routine `distribute()` calls that anyone can invoke without additional preconditions, but the initial funds must first land in that account via someone else's mistake or deliberate donation).

### Likelihood Explanation
Low-to-medium. It requires either (a) a user mistakenly sending APT to a vesting-contract resource-account address instead of a normal account, or (b) a griefer intentionally donating APT to trigger unwanted redistribution/commission dynamics. The address is not typically advertised to end users as a payment destination, which reduces the chance of accidental transfers, but the address is discoverable on-chain via events/view functions, so it is not truly private.

### Recommendation
In `withdraw_stake`, record the vesting contract account's AptosCoin balance immediately before calling `staking_contract::distribute`, and withdraw only the delta (`balance_after - balance_before`) rather than the full account balance, mirroring the fix recommended in the referenced report (diff pre/post balances instead of trusting `balanceOf`/`coin::balance` of the whole account).

### Proof of Concept
Because tool access ended before I could trace `staking_contract::distribute`'s deposit path fully or write/run an actual Move test, I could not empirically confirm the exact deposit function used (whether it's `aptos_account::deposit_coins`, which auto-creates `CoinStore`s) or rule out an existing safeguard elsewhere in `staking_contract.move` that might prevent unsolicited deposits. This should be verified with a Devin session that:
1. Confirms `staking_contract::distribute`'s deposit function auto-registers/permits unsolicited `CoinStore` deposits at `contract_address`.
2. Writes a Move unit test: create a vesting contract, have an unrelated account call `aptos_account::transfer(unrelated, contract_address, X)`, then call `vesting::distribute(contract_address)`, and assert whether `X` gets paid out to shareholders instead of remaining recoverable by the sender.

Given I could not fully verify the CoinStore-registration precondition and the exact deposit call semantics within the remaining budget, treat this finding as **unconfirmed pending PoC verification** rather than a fully proven high/critical-severity bug.

    public entry fun distribute(contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        let coins = withdraw_stake(vesting_contract, contract_address);
        let total_distribution_amount = coin::value(&coins);
        if (total_distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        // Distribute coins to all shareholders in the vesting contract.
        let grant_pool = &vesting_contract.grant_pool;
        let shareholders = &grant_pool.shareholders();
        shareholders.for_each_ref(|shareholder| {
            let shareholder = *shareholder;
            let shares = pool_u64::shares(grant_pool, shareholder);
            let amount = pool_u64::shares_to_amount_with_total_coins(grant_pool, shares, total_distribution_amount);
            let share_of_coins = coin::extract(&mut coins, amount);
            let recipient_address = get_beneficiary(vesting_contract, shareholder);
            aptos_account::deposit_coins(recipient_address, share_of_coins);
        });
