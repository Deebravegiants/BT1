### Title
Missing Chainlink price-bounds/circuit-breaker check in `SimplexPaymaster._getOraclePrice` allows mispriced gas charges - (File: `evm/src/utils/SimplexPaymaster.sol`)

### Summary
`SimplexPaymaster._getOraclePrice` only validates that a Chainlink `answer` is positive and not stale; it never checks the answer against the feed's `minAnswer`/`maxAnswer` circuit-breaker bounds [2](#0-1) . If a configured feed's underlying asset crashes or spikes past the aggregator's hard-coded bounds, Chainlink will report the frozen boundary price rather than the true price, and this contract will treat it as valid and current.

### Finding Description
`_tokenPrice` computes the token amount a solver's UserOp must pay for gas by dividing `nativeUsd` by `tokenUsd`, both fetched from `_getOraclePrice` [3](#0-2) . `_getOraclePrice` only guards against `answer <= 0` and staleness beyond `maxOracleAge`; it performs no comparison against the aggregator's registered min/max answer bounds [4](#0-3) . This price feeds directly into `_fetchDetails` → `PaymasterERC20._erc20Cost`, which sets `tokenPrice` used to compute `prefundAmount` charged to the solver's UserOp during `_prefund` [5](#0-4) , and is directly exposed to any caller through `getTokenPrice`/`estimateTokenCost` [6](#0-5) .

This function is invoked on the reachable path used by the intent-solver fill flow: `ContractInteractionService.prepareBidUserOp` builds `paymasterAndData` for every solver bid through the Simplex paymaster [1](#0-0) , and `_prefund` pulls the resulting `prefundAmount` via Permit2 up to the signer-approved cap [7](#0-6) . If either the native/USD or token/USD feed hits its aggregator circuit-breaker bound (a real, documented Chainlink failure mode), the reported price freezes at that bound while the real market price diverges further — the contract has no way to detect or reject this condition.

### Impact Explanation
A frozen boundary price skews `tokenPrice` away from the true exchange rate, causing solvers to be either overcharged (when the true price moved further away from the stale bound in the paymaster's favor) or undercharged (protocol/treasury loses expected gas-cost recovery). Because `swapAndDeposit` also derives `amountOutMin` from the same unchecked oracle prices [8](#0-7) , a frozen price could also produce an unfavorable swap execution price when recycling fees, still bounded only by `swapSlippageBps` computed off the bad reference price. The severity is bounded by the design's own stated mitigation — permit amounts are kept small ("a few dollars") specifically to bound exposure to a malicious/faulty oracle [9](#0-8)  — so per-op loss is capped, but is not zero, and repeats across every sponsored UserOp until governance intervenes.

### Likelihood Explanation
Requires an underlying Chainlink feed to actually hit its aggregator's min/max circuit-breaker (a known, documented Chainlink behavior during extreme market events, e.g. depegs), which is a low-probability but real event; the contract's staleness/positivity checks give no protection against it since the stale boundary answer is neither zero nor "stale" in `updatedAt` terms.

### Recommendation
Extend `_getOraclePrice` to compare `answer` against the aggregator's `minAnswer`/`maxAnswer` (fetchable via `aggregator()` on the proxy, or configured per-feed by governance) and revert (e.g. with a new `PriceOutOfBounds` error) when the answer is at or beyond either bound, mirroring the staleness/positivity checks already present [4](#0-3) .

### Proof of Concept
1. Governance registers a token whose Chainlink feed has `minAnswer = X`.
2. The underlying asset price crashes below the level `X` represents; the aggregator freezes `latestRoundData().answer` at `X` (a fresh `updatedAt`, so it is not stale).
3. `_getOraclePrice` passes both the `answer <= 0` and staleness checks and returns `X` as the current price.
4. `_tokenPrice` computes an incorrect `tokenPrice` from this frozen value; every subsequent sponsored UserOp (`_fetchDetails`/`_prefund`) and every `swapAndDeposit` call charges/executes against the stale price until governance replaces the feed via `UpdateParams`/`RegisterToken`.

    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }

    /// @notice Current price in token base units per wei of gas (scaled by 1e18),
    ///         markup included. For offchain gas estimation.
    function getTokenPrice(address token) external view returns (uint256) {
        TokenConfig memory cfg = tokenConfigs[token];
        if (address(cfg.tokenOracle) == address(0)) revert TokenNotRegistered(token);

        return _tokenPrice(cfg);
    }

    /// @notice Estimate the token cost for a given gas amount and fee, mirroring
    ///         PaymasterERC20._erc20Cost (including its postOp gas cushion).
    function estimateTokenCost(address token, uint256 gasAmount, uint256 maxFeePerGas) external view returns (uint256) {
        TokenConfig memory cfg = tokenConfigs[token];
        if (address(cfg.tokenOracle) == address(0)) revert TokenNotRegistered(token);

        uint256 weiCost = gasAmount * maxFeePerGas + _postOpCost() * maxFeePerGas;
        return (weiCost * _tokenPrice(cfg)) / _tokenPriceDenominator();
    }
