### Title
Unauthenticated exposure of internal pprof profiling/debug data via LOOP plugin routes - (File: core/web/router.go, core/web/loop_registry.go)

### Summary
The Chainlink node's LOOP (Local-Out-Of-Process) plugin routes — `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` — are registered via `loopRoutes(app, api)` on the top-level `api` router group, which applies only rate limiting and session-cookie middleware, with no authentication check. [1](#0-0) 
This is architecturally inconsistent with the equivalent core pprof endpoints at `/v2/debug/pprof/*`, which are deliberately gated behind `auth.Authenticate` in the `authv2` group as "Debug routes accessible via authentication." [2](#0-1) 

### Finding Description
`loopRoutes` wires the `LoopRegistryServer` handlers directly with no `auth.Authenticate` middleware: [3](#0-2) 
`pluginPPROFHandler` forwards arbitrary caller-supplied query parameters (`debug`, `gc`, `seconds`, and the full `profile` path segment) to the internal per-plugin pprof server without any authorization check: [4](#0-3) 
and `pluginPPROFPOSTSymbolHandler` similarly proxies POST bodies unauthenticated: [5](#0-4) 
The intended design (per `plugins/README.md`) is that these are "very thin middleware" to route external Prometheus scraping to individual plugin metrics endpoints, but the pprof proxy paths go well beyond metrics scraping — they expose full pprof introspection (goroutine dumps, heap, block, mutex profiles, CPU profiles via `seconds`, and `cmdline`) for any named plugin without requiring the `ViewStatus`-equivalent authenticated session/role that every other administrative or debug surface in this router requires.

### Impact Explanation
pprof and metrics data can leak sensitive internal information: goroutine stack traces, memory contents/addresses, running command-line arguments (`cmdline`), and internal networking/plugin topology (via `/discovery`, which reveals internal host names and plugin names). An unauthenticated remote attacker who can reach the node's web server can enumerate plugin names via `/discovery` and then pull CPU/heap/goroutine profiles for each plugin, which is a confidentiality-impacting information disclosure comparable in class to CWE-862/863 (missing/incorrect authorization) — the same bug class as the Jenkins CVE-2022-34180 analog, where a status/debug endpoint was reachable without the required permission check.

### Likelihood Explanation
High for any node whose web server (`WebServer` HTTP port) is exposed to an untrusted network without an additional reverse-proxy authentication layer, since no credentials, tokens, or session cookies are required — the routes are simply mounted on the base `api` group alongside `/health` and other intentionally public endpoints, with no distinguishing authentication check.

### Recommendation
Require the same authentication used for `/v2/debug/pprof` (`auth.Authenticate` plus an appropriate role check such as `auth.RequiresAdminRole`) on the `loopRoutes` group in `core/web/router.go`, or restrict these plugin discovery/pprof proxy routes to loopback/internal-only access, consistent with how `metricRoutes` is protected.

### Proof of Concept
1. Start a Chainlink node with a LOOP plugin registered (e.g., Solana/Median LOOPP) and its web server port reachable.
2. Without any authentication headers or session cookie, issue `GET /discovery` to enumerate registered plugin names via `LabelMetaPluginName`.
3. For a discovered plugin name `X`, issue `GET /plugins/X/debug/pprof/goroutine?debug=2` or `GET /plugins/X/debug/pprof/profile?seconds=30` without credentials.
4. Observe the request succeeds with `200 OK` and returns full pprof profiling data, confirming the missing authorization check on this route group, as opposed to `GET /v2/debug/pprof/goroutine` which returns `401 Unauthorized` without a valid session/token.

func loopRoutes(app chainlink.Application, r *gin.RouterGroup) {
	loopRegistry := NewLoopRegistryServer(app)
	r.GET("/discovery", ginHandlerFromHTTP(loopRegistry.discoveryHandler))
	r.GET("/plugins/:name/metrics", loopRegistry.pluginMetricHandler)
	r.GET("/plugins/:name/debug/pprof/*profile", loopRegistry.pluginPPROFHandler)
	r.POST("/plugins/:name/debug/pprof/symbol", loopRegistry.pluginPPROFPOSTSymbolHandler)
}

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}

func (l *LoopRegistryServer) pluginPPROFPOSTSymbolHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/symbol", l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	body, err := io.ReadAll(gc.Request.Body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error reading plugin pprof request body: %s", err))
		return
	}
	l.doRequest(gc, "POST", pluginURL, bytes.NewReader(body), timeout, pluginName)
}
