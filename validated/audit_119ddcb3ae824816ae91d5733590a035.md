### Title
Unpriceable dust collateral leg permanently bricks liquidation and bad-debt cleanup - ([File: contracts/controller/src/risk/totals.rs])

### Summary
The CVE-2020-17525 bug class is "a request referencing a resource whose lookup crashes the entire servicing path". The analog on XOXNO Lending: `risk::calculate_account_risk_totals` strictly prices *every* supply and borrow position on an account, so any position whose oracle lookup fails (stale, missing, or discontinued feed) makes the whole risk computation panic. Both permissionless liquidation (`build_liquidation_plan`) and permissionless bad-debt cleanup (`socialize_bad_debt`) route through this function, so a borrower can make their account unliquidatable — and its bad debt un-cleanable — by holding even a dust-valued collateral in an asset whose feed is down.

### Finding Description
`liquidate` calls `plan::build_liquidation_plan`, which computes `risk::calculate_account_risk_totals` over `account.supply_positions` and `account.borrow_positions` before anything else [1](#0-0) . `clean_bad_debt` (and the owner-gated `force_socialize_bad_debt`) calls `socialize_bad_debt`, which runs the same totals computation before the dust/insolvency gates [2](#0-1) .

The totals function prices each leg strictly through `Context`-cached oracle reads: a stale or missing price for *any* leg panics the whole call — there is no skip, clamp, or per-leg `Option` handling. The harness test `audit_liquidate_and_clean_bricked_by_unpriceable_dust_leg` proves reachability end to end [3](#0-2) :

1. Borrower supplies 0.001 WBTC while the WBTC feed is stale — the `supply` entry succeeds because entry-side pricing tolerates it.
2. The borrower's USDC collateral crashes to half (HF < 1, account is liquidatable).
3. Every `liquidate` call reverts `PRICE_FEED_STALE` and every `clean_bad_debt` call reverts `PRICE_FEED_STALE`, until the WBTC feed goes fresh again.

An attacker can deliberately plant such a "poison leg" on their own account (permissionless `supply` to their own `account_id`, or `Credit` seizure receipt), choosing an asset whose feed is already dead or that they expect to be deprecated — the analog of requesting a "non-existing repository URL" that crashes the server module instead of returning an error.

### Impact Explanation
While the poison leg is in place, the account is immune to both liquidation paths and to dust-gated bad-debt cleanup: the protocol cannot seize collateral, cannot socialize the debt, and the position accrues interest unimpeded. If the feed never recovers (delisted feed, Reflector/RedStone source permanently stale beyond the tolerance bands), the freeze is permanent: the account's debt becomes unbacked protocol loss that `recapitalize` must absorb from donors rather than from the borrower's seized collateral — a direct path to protocol insolvency proportional to the borrowed amount. Even a transient outage gives temporary freezing of suppliers' funds backing that debt. This maps to the accepted impact classes "temporary freezing of funds" and "protocol insolvency".

### Likelihood Explanation
Reachable by any unprivileged address: `supply` on one's own account has no allowlist gate on which listed market is used, and a stale feed does not block entry (proven by the test planting the leg successfully). Oracle staleness is a routine occurrence (reflector outages, feed deprecation), so the trigger does not require adversarial oracle manipulation — only a listed market whose feed lapsed, which the attacker can wait for and then exploit cheaply with a dust deposit. Severity is bounded by needing an unpriceable *listed* asset, hence Medium rather than High.

### Recommendation
Make the risk-totals computation degrade instead of panic on a missing price: value an unpriceable collateral leg at zero (conservative for HF — it only makes the account *more* liquidatable) and treat an unpriceable debt leg as a blocker only if that leg is actually being repaid. Equivalently, `calculate_account_risk_totals` could return per-leg `Option` prices and let `build_liquidation_plan`/`socialize_bad_debt` drop unpriceable collateral legs from the seizure set while still admitting the account. `clean_bad_debt` in particular needs a path that works with zero oracle availability, since its job is precisely winding down accounts nobody else can touch.

### Proof of Concept
The repository already encodes the scenario as a test [3](#0-2) :

```rust
t.set_oracle_single_spot("WBTC");
t.supply(borrower, "USDC", 10_000.0);
t.borrow(borrower, "ETH", 3.0);
// Make the WBTC feed stale (1h old), then plant a dust WBTC supply leg:
t.mock_reflector_client().set_price_at(&wbtc, &usd(60_000), &(now - 3_600));
t.try_supply(borrower, "WBTC", 0.001); // succeeds
// Crash the USDC collateral price -> borrower is underwater:
t.set_price("USDC", usd_cents(50));
// Both permissionless exits revert:
try_liquidate(...)      -> PRICE_FEED_STALE
try_clean_bad_debt(...) -> PRICE_FEED_STALE
```

Attacker recipe on mainnet: monitor listed markets for a feed that has gone stale beyond the tolerance window, `supply` a minimal dust amount of that asset into the borrower's own account, then borrow maximum against real collateral. Until governance delists the asset or the feed revives, `liquidate` and `clean_bad_debt` both abort inside `calculate_account_risk_totals`, leaving the debt to accrue into bad debt that can only be absorbed via `recapitalize`.

```rust
fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    bad_debt::execute_bad_debt_cleanup(env, &mut cache, account_id, &account, &totals);
```

```rust
fn audit_liquidate_and_clean_bricked_by_unpriceable_dust_leg() {
    let mut t = LendingTest::new()
        .three_asset_usdc_eth_wbtc()
        .with_dust_disabled_all_markets()
        .build();

    t.set_oracle_single_spot("WBTC");

    t.supply(LIQUIDATOR, "USDC", 50_000.0);
    let borrower = test_harness::ALICE;
    t.supply(borrower, "USDC", 10_000.0);
    t.borrow(borrower, "ETH", 3.0);

    let fresh = t.try_liquidate(LIQUIDATOR, borrower, "ETH", 1.0);
    test_harness::assert_contract_error(fresh, errors::HEALTH_FACTOR_TOO_HIGH);

    t.advance_time(5_000);
    let now = t.env.ledger().timestamp();
    let wbtc = t.resolve_asset("WBTC");
    t.mock_reflector_client()
        .set_price_at(&wbtc, &usd(60_000), &(now - 3_600));

    let plant = t.try_supply(borrower, "WBTC", 0.001);
    assert!(
        plant.is_ok(),
        "supply must accept the fragile leg with a stale feed: {plant:?}"
    );

    t.set_price("USDC", usd_cents(50));

    let borrower_id = t.resolve_account_id(borrower);

    let liq = t.try_liquidate(LIQUIDATOR, borrower, "ETH", 1.0);
    test_harness::assert_contract_error(liq, errors::PRICE_FEED_STALE);

    let clean = t.try_clean_bad_debt_by_id(borrower_id);
    test_harness::assert_contract_error(clean, errors::PRICE_FEED_STALE);

    t.set_price("WBTC", usd(60_000));
    let recovered = t.try_liquidate(LIQUIDATOR, borrower, "ETH", 1.0);
    assert!(
        recovered.is_ok(),
        "once WBTC is fresh, the identical liquidation must succeed: {recovered:?}"
    );
    assert!(
        t.borrow_balance(borrower, "ETH") < 3.0,
        "post-recovery liquidation must reduce the borrower's debt"
    );
}
```
