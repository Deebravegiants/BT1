Audit Report

## Title
Bridge `OutgoingToken` credential exposed in plaintext to view-only role via `GET /v2/bridge_types` and `GET /v2/bridge_types/:BridgeName` - (File: core/web/presenters/bridges.go)

## Summary
`presenters.NewBridgeResource` unconditionally copies the plaintext `BridgeType.OutgoingToken` into the JSON API response with no redaction, unlike `IncomingToken` which is only populated on creation. The bridge listing/show endpoints that serialize this resource are reachable by a `view`-role authenticated user, as confirmed by the RBAC test matrix marking both routes `viewOnlyAllowed: true`.

## Finding Description
`BridgeType.OutgoingToken` is stored and transmitted in plaintext (`core/bridges/bridge_type.go` L55-68, L70-102), and `presenters.NewBridgeResource` (`core/web/presenters/bridges.go` L18, L37) copies it directly into the `outgoingToken` JSON field with no `omitempty` and no masking, while `IncomingToken` intentionally omits itself outside creation flows. `BridgeTypesController.Index` and `.Show` (`core/web/bridge_types_controller.go` L111-146) call this presenter directly for any successful request against `/v2/bridge_types` and `/v2/bridge_types/:BridgeName`. Both routes sit under the `authv2` route group, which only requires generic authentication (`auth.Authenticate` via token or session) — not an elevated role wrapper like `auth.RequiresAdminRole`/`auth.RequiresEditRole`, which the router does apply selectively to other sensitive endpoints (e.g., `/users`). This is corroborated by the `routesRolesMap` test table in `core/web/auth/auth_test.go` (L227-230) explicitly marking `GET /v2/bridge_types` and `GET /v2/bridge_types/MOCK` as `viewOnlyAllowed: true`, and by `TestRBAC_Routemap_ViewOnly` (L484-531), which asserts that a `sessions.UserRoleView` user does not get `401`/`403` on these routes. The presenter test fixture (`core/web/presenters/bridges_test.go` L39-54) further confirms the unredacted `outgoingToken` field appears in the serialized attributes. The project's own `models.Secret`/`config.SecretString` redaction pattern (`core/store/models/secrets.go` L7-12) shows secrets are expected to redact as `"xxxxx"` when marshaled — a protection `OutgoingToken` lacks entirely.

## Impact Explanation
`OutgoingToken` authenticates outbound requests from the Chainlink node to external bridge adapters. A `view`-role account — Chainlink's lowest-privilege authenticated role, intended for read-only dashboards/monitoring — can retrieve this token via a normal, unprivileged authenticated GET request and use it to impersonate the node when calling the external adapter, or tamper with adapter-side trust assumptions. This is a genuine secret-exfiltration issue mapping to the in-scope "key/secret exfiltration" impact category, since a lower-privileged role than the credential's intended trust boundary can read it in plaintext.

## Likelihood Explanation
Any operator who provisions a `view`-role API user (a standard, documented low-trust role) enables that user to trivially call `GET /v2/bridge_types` or `GET /v2/bridge_types/:BridgeName` with no further exploitation steps, privilege escalation, or additional access needed. Likelihood is high and reproducible on any node with configured bridges and a view-role credential, which is a common and intended operational configuration, not a misconfiguration.

## Recommendation
Redact `OutgoingToken` in `presenters.NewBridgeResource` for roles below `edit`/`admin` (mirroring `IncomingToken`'s creation-only exposure), or wrap the field in the `models.Secret`/`config.SecretString` redaction type used elsewhere before serialization so it never appears in plaintext in `Index`/`Show` responses.

## Proof of Concept
1. `chainlink admin users create --email=viewer@example.com --role=view`
2. Authenticate as that user and issue `GET /v2/bridge_types/<bridge-name>` (or `GET /v2/bridge_types`).
3. Observe `"outgoingToken": "<plaintext-token>"` in the JSON API `attributes`, consistent with `core/web/presenters/bridges_test.go` (L39-54) and confirmed reachable per `TestRBAC_Routemap_ViewOnly` in `core/web/auth/auth_test.go`.

// Index lists Bridges, one page at a time.
func (btc *BridgeTypesController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	bridges, count, err := btc.App.BridgeORM().BridgeTypes(ctx, offset, size)

	resources := make([]presenters.BridgeResource, 0, len(bridges))
	for _, bridge := range bridges {
		resources = append(resources, *presenters.NewBridgeResource(bridge))
	}

	paginatedResponse(c, "Bridges", size, page, resources, count, err)
}

// Show returns the details of a specific Bridge.
func (btc *BridgeTypesController) Show(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	bt, err := btc.App.BridgeORM().FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}

func TestRBAC_Routemap_ViewOnly(t *testing.T) {
	t.Parallel()
	app := cltest.NewApplicationEVMDisabled(t)
	require.NoError(t, app.Start(t.Context()))

	router := web.Router(t, app, nil)
	ts := httptest.NewServer(router)
	defer ts.Close()

	// Create a test run user to work with
	u := &cltest.User{Role: sessions.UserRoleView}
	client := app.NewHTTPClient(u)

	// Assert all view only routes
	for i, route := range routesRolesMap {
		t.Run(fmt.Sprintf("%d-%s-%s", i, route.verb, route.path), func(t *testing.T) {
			t.Parallel()
			var resp *http.Response
			var cleanup func()

			switch route.verb {
			case "GET":
				resp, cleanup = client.Get(route.path)
			case "POST":
				resp, cleanup = client.Post(route.path, nil)
			case "DELETE":
				resp, cleanup = client.Delete(route.path)
			case "PATCH":
				resp, cleanup = client.Patch(route.path, nil)
			case "PUT":
				resp, cleanup = client.Put(route.path, nil)
			default:
				t.Fatalf("Unknown HTTP verb %s\n", route.verb)
			}
			defer cleanup()

			// If this route only allows view only, don't expect an unauthorized response
			switch {
			case route.viewOnlyAllowed:
				assert.NotEqual(t, http.StatusUnauthorized, resp.StatusCode)
				assert.NotEqual(t, http.StatusForbidden, resp.StatusCode)
			case !route.EditAllowed:
				assert.Equal(t, http.StatusForbidden, resp.StatusCode)
			default:
				assert.Equal(t, http.StatusUnauthorized, resp.StatusCode)
			}
		})
	}
