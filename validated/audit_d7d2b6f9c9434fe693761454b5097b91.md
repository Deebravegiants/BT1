### Title
Missing `_requestCommitments` deletion after a successful GET response allows the relayer fee to be paid out twice - ([File: evm/src/core/EvmHost.sol])

### Summary
`EvmHost.dispatchIncoming(GetResponse memory response, address relayer)` pays the relayer fee out of `_requestCommitments[commitment]` on a successful `onGetResponse` delivery, but — unlike every other terminal ISMP delivery path in the same contract — it never deletes `_requestCommitments[commitment]` afterward. The stale `FeeMetadata{sender, fee}` entry remains fully populated (`sender != address(0)`), so the exact same commitment can later satisfy `HandlerV2.handleGetRequestTimeouts`'s "known request" check (`meta.sender == address(0)` revert guard) and pay the fee out a second time via `dispatchTimeOut(GetRequestTimeout,...)`. This is the logical analog of the CVE's double-free: a resource (fee metadata) that should be consumed/cleared exactly once is left "live" and can be freed/paid twice.

### Finding Description
Compare the four terminal dispatch paths in `EvmHost.sol`: [1](#0-0) 

`dispatchIncoming(GetResponse...)` transfers `fee = _requestCommitments[commitment].fee` to the relayer on success but **does not delete `_requestCommitments[commitment]`**.

Contrast with the two timeout paths, which both explicitly delete the commitment for replay protection before invoking the app callback, and restore it only if the callback fails: [2](#0-1) 

Because `_requestCommitments[commitment]` is never cleared after a successful GET response, `meta = host.requestCommitments(commitment)` still returns `sender != address(0)` for that commitment indefinitely. `HandlerV2.handleGetRequestTimeouts` uses exactly this field as its sole "is this request known/still pending" gate before verifying a non-membership proof and calling `host.dispatchTimeOut`: [3](#0-2) 

`dispatchTimeOut(GetRequestTimeout,...)` then unconditionally pays `meta.fee` to `meta.sender` (the original fee payer) once its own commitment check passes and the app callback succeeds — it has no additional check that a `GetResponse` was ever delivered for this commitment; it only trusts the `meta` handed to it by the handler and the non-membership proof of the (Hyperbridge-side) `RESPONSE_RECEIPTS_STORAGE_PREFIX` key, which is unrelated to the `_responseReceipts` mapping actually written on this EVM host by `dispatchIncoming(GetResponse...)`.

The root cause is the asymmetry: `dispatchIncoming(PostRequest)`, `dispatchTimeOut(PostRequestTimeout)`, and `dispatchTimeOut(GetRequestTimeout)` all clear their respective commitment/receipt state on the success path to make the operation single-use; `dispatchIncoming(GetResponse)` does not, leaving the fee metadata "unfreed" and re-claimable.

### Impact Explanation
An attacker (or a relayer colluding with the fee payer) can cause the same GET request's relayer fee to be paid twice from `EvmHost`'s fee-token balance: once to the legitimate relayer via `handleGetResponses` → `dispatchIncoming(GetResponse)`, and again to `meta.sender` via `handleGetRequestTimeouts` → `dispatchTimeOut(GetRequestTimeout)`, as long as a valid consensus-verified state height/proof can be produced showing no `RESPONSE_RECEIPTS_STORAGE_PREFIX` entry for the commitment on the routing side. This directly drains the host's `feeToken` reserves — a concrete theft of protocol/user funds reachable from a single relayed proof submission, matching the required "concrete theft ... unbacked mint ... forged message delivery" bar.

### Likelihood Explanation
Reachable by any unprivileged relayer that can submit a valid `GetRequestTimeout` proof (this is by design an unsigned/permissionless action anyone can submit, per the pattern seen elsewhere in the codebase, e.g. self-relay support). The only external dependency is producing a valid non-membership proof against a consensus-verified state root for the `RESPONSE_RECEIPTS_STORAGE_PREFIX` key on the routing side — the relayer/fee-payer needs no special privilege, and the underlying `_requestCommitments` staleness is unconditional (it is missing in the code, not gated by any race condition), so exploitability depends only on being able to time the timeout submission against a state height where that particular non-membership proof still validates.

### Recommendation
In `EvmHost.dispatchIncoming(GetResponse memory response, address relayer)`, delete `_requestCommitments[commitment]` immediately after (or as part of) the successful fee payout, mirroring the pattern already used in `dispatchTimeOut` for `PostRequestTimeout`/`GetRequestTimeout`. If retry-ability on a failed `onGetResponse` callback is desired, follow the same restore-on-failure pattern used elsewhere (delete before the external call, restore only if the call fails), so the commitment can only ever be consumed once.

### Proof of Concept
1. Dispatch a `GetRequest` via `EvmHost.dispatch(DispatchGet)`; this stores `_requestCommitments[commitment] = FeeMetadata{sender: payer, fee: F}` [4](#0-3) .
2. A relayer delivers the response through `HandlerV2.handleGetResponses` → `EvmHost.dispatchIncoming(GetResponse,...)`, which pays fee `F` to the relayer but leaves `_requestCommitments[commitment]` populated [5](#0-4) .
3. Later, a valid `GetRequestTimeout` proof (non-membership at some other/earlier consensus-verified state height) is submitted through `HandlerV2.handleGetRequestTimeouts`; because `host.requestCommitments(commitment).sender != address(0)` still holds, the `UnknownMessage` guard does not trigger, and `host.dispatchTimeOut(GetRequestTimeout,...)` pays fee `F` a second time to `meta.sender` [6](#0-5) [7](#0-6) .
4. Net effect: fee `F` has been transferred out of the host twice for a single GET request — a double-payout drained from the `feeToken` reserve.

Note: I was unable to fully trace, within the available context, whether Hyperbridge's routing-side state ever independently records a `ResponseReceipts` entry for GET responses in a way that would make step 3's non-membership proof fail after a genuine delivery; this would need to be confirmed against the pallet-ismp/Hyperbridge-side response handling to establish the exact height/timing window in which the duplicate-payout proof remains constructible. The missing `_requestCommitments` deletion itself, however, is a concrete, verifiable code defect regardless of that timing detail.

    /**
     * @dev Dispatch an incoming GET response to source module
     * @param response - get response
     */
    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

     * @dev Dispatch an incoming GET timeout to the source module.
     * @notice Does not refund any protocol fees.
     * @param timeout - timed-out get request bundled with the relayer that submitted the timeout proof
     * @param meta - fee metadata for the original request
     * @param commitment - request commitment
     */
    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
