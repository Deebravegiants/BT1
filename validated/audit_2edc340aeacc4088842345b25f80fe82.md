### Title
Emporium `EmporiumStack.ops` (arbitrary external calls) are unauthenticated and unreconciled against the balance equation - ([File: contracts/external-actions/emporium/upgradeable/EmporiumUpgradeable.sol])

### Summary
`EmporiumUpgradeable.runAction` decodes an attacker-supplied `EmporiumStack` (containing an array of `EmporiumOperation{endpoint, invokeWallet, value, callData}`) from `circomData.externalActionData.externalActionMetadata` and executes each op as a raw low-level call from the Emporium contract itself. When `stack.signerAddress == address(0)`, `verifyWallet` returns immediately without checking any signature over the ops, and neither the ZK circuit's public-input vector nor the Solidity `calldataHash`/`signedMessageHash` checks cover `externalActionMetadata`. Any unprivileged EOA that can produce an otherwise-valid Hinkal proof can therefore drive the Emporium contract to execute arbitrary calls, and any tokens moved this way are not reconciled unless their address happens to be included in the current call's `circomData.erc20TokenAddresses` array.

### Finding Description
`transact()` in [1](#0-0)  validates the proof and `calldataHash`, then calls `hinkalHelper.performHinkalChecks`, which enforces `CircomDataBuilder.getHashedCalldata(circomData) == circomData.calldataHash` and forms the circuit public-input vector via `formInputForCircom`/`formBasicInput` [2](#0-1) . Looking at `formBasicInput` and `getHashedCalldata2`, the public inputs and both calldata-hash helpers cover `rootHashHinkal`, `erc20TokenAddresses`, `amountChanges`, `inputNullifiers`, `outCommitments`, `calldataHash`, `timeStamp`, stealth-address fields, `hookData`, `encryptedOutputs`, `feeStructure`, `onChainCreation`, `originalSender`, and `extraData` [3](#0-2) [4](#0-3) . Nowhere is `circomData.externalActionData.externalActionMetadata` (the abi-encoded `EmporiumStack`) hashed into `calldataHash`, `signedMessageHash`, or fed into the circuit — it is a `CircomData` field acted upon but entirely outside the EdDSA-signed / circuit-checked equality.

Inside `EmporiumUpgradeable.runAction`, this unconstrained metadata is decoded and executed: [5](#0-4) 

`verifyWallet` only checks an EIP-712 signature over the ops when `stack.signerAddress != address(0)`; if the attacker sets `signerAddress = address(0)` it returns immediately with no signature check at all: [6](#0-5) 

With `signerAddress == address(0)`, every op falls into the "Stateless Interaction" branch, executed directly by the Emporium contract with attacker-chosen `endpoint`/`callData`/`value`: [7](#0-6) 

Afterwards, only the per-token balances for indices in `circomData.erc20TokenAddresses` are reconciled against `deltaAmountChanges` via `balancesBefore`/`balancesAfter`: [8](#0-7) 

Any token not listed in the (attacker-chosen, small) `erc20TokenAddresses` array for this call is never checked — its balance can be silently drained or approved-away by the injected ops with no revert. Because the Emporium contract is a shared, persistently-funded action target (it receives deposits transferred into it by `Hinkal._externalTransact` before `runAction` executes, and it can retain balances left over from other flows), the attacker gets to make the *contract itself* perform `approve`/`transfer`/`transferFrom` calls on tokens it currently holds, entirely outside the balance equation for tokens not declared by the attacker's own `erc20TokenAddresses` list.

This is the direct analog of the LBP "balanceOf reward accounting" bug class: the protocol's accounting equality (LBP's live-`balanceOf`-based reward math; here, Hinkal/Emporium's per-token `balanceChange` loop) does not cover every value-affecting action, so a value transfer effected through an unconstrained path escapes the equality check entirely.

### Impact Explanation
This breaks "a `CircomData` field acted on but outside `calldataHash` / `signedMessageHash` / the public-input vector" and "value moved by Hinkal or an external action but not counted in the balance equation." It also constitutes "a transferFrom / wallet op not authorised by the prover or signer," since neither the depositor's EdDSA signature (circuit) nor a wallet ECDSA signature (`verifyWallet`, skipped for `signerAddress == 0`) ever authorizes the specific `endpoint`/`callData` executed. Concretely, this allows theft of tokens/ETH held by the Emporium contract (protocol/relay funds or other users' in-flight balances) that are not part of the attacker's declared `erc20TokenAddresses` — a Critical/High impact (theft of protocol or user funds via unauthorized asset movement).

### Likelihood Explanation
Any unprivileged EOA that can produce a syntactically valid Hinkal proof for a trivial transaction (e.g., a tiny self-consistent deposit routed through the `Emporium` external action, which is one of the registered `externalActionMap` targets) can supply arbitrary `externalActionMetadata`. Because that field is never hashed into `calldataHash`/`signedMessageHash` nor placed in the circuit's public-input vector, the ZK proof gives no guarantee about its contents, and setting `stack.signerAddress = address(0)` removes the remaining EIP-712 check. No admin, relay, or victim key is required — the attacker only needs the Emporium contract to currently hold some balance of a token they don't declare in `erc20TokenAddresses`.

### Recommendation
Bind `circomData.externalActionData.externalActionMetadata` (or at minimum a hash of the decoded `EmporiumStack`, including `ops`) into `calldataHash`/`signedMessageHash` so the circuit/EdDSA signature constrains it, and/or require `verifyWallet` to always validate a signature over `stack.ops` regardless of `signerAddress`, disallowing an unauthenticated bypass. Additionally, ensure the balance-reconciliation loop in `EmporiumUpgradeable.runAction` covers every token whose balance could change as a result of executed ops, not just the attacker-declared `erc20TokenAddresses` subset.

### Proof of Concept
1. Attacker deposits a minimal amount of `tokenA` into Hinkal via `transact()` targeting the Emporium external action (`externalActionId` registered to `EmporiumUpgradeable`), with `circomData.erc20TokenAddresses = [tokenA]` and a valid (self-consistent) proof.
2. Attacker crafts `circomData.externalActionData.externalActionMetadata = abi.encode(EmporiumStack({signerAddress: address(0), ops: [EmporiumOperation({endpoint: tokenB, invokeWallet: false, value: 0, callData: abi.encodeCall(IERC20.transfer, (attacker, EmporiumBalanceOfTokenB))})], maxFee: 0, deadline: type(uint256).max})}`, where `tokenB` is a token currently held by the Emporium contract from other flows/dust, and is NOT included in `circomData.erc20TokenAddresses`.
3. Since `externalActionMetadata` is not part of `calldataHash`/`signedMessageHash`/circuit public inputs, the proof still verifies.
4. `runAction` executes `verifyWallet` (no-op since `signerAddress == address(0)`), then executes the injected op: Emporium calls `tokenB.transfer(attacker, amount)`, draining `tokenB` from the Emporium contract to the attacker.
5. The subsequent balance-reconciliation loop in `runAction` only iterates `circomData.erc20TokenAddresses` (i.e., `tokenA`), so the `tokenB` drain is never checked and the call succeeds.

    function performHinkalChecks(
        CircomData calldata circomData,
        Dimensions calldata dimensions,
        address sender
    ) external view returns (uint256[] memory) {
        require(
            (circomData.originalSender == address(0) &&
                circomData.relay != address(0)) ||
                (circomData.originalSender == sender &&
                    circomData.relay == address(0)),
            "invalid value for originalSender"
        );

        require(
            CircomDataBuilder.getHashedCalldata(circomData) ==
                circomData.calldataHash,
            "Calldata Hash Integrity Check Failed"
        );
        relayerIsValid(circomData.relay);
        dimensionsCheck(circomData, dimensions);
        checkOnchainCreation(circomData);

        return
            CircomDataBuilder.formInputForCircom(
                block.chainid,
                hinkalAddress,
                circomData
            );
    }

    function runAction(
        CircomData calldata circomData,
        int256[] calldata deltaAmountChanges
    ) external override onlyAllowedRecipient returns (UTXO[] memory) {
        EmporiumStack memory stack = abi.decode(
            circomData.externalActionData.externalActionMetadata,
            (EmporiumStack)
        );

        uint256[] memory balancesBefore = getBalancesForArray(
            circomData.erc20TokenAddresses
        );

        verifyWallet(stack, circomData);

        for (uint256 i = 0; i < stack.ops.length; i++) {
            EmporiumOperation memory op = stack.ops[i];

            bool success;
            bytes memory err;

            // CASE 1: Stateful Interaction
            if (op.invokeWallet && stack.signerAddress != address(0)) {
                (success, err) = IHinkalWallet(stack.signerAddress)
                    .callHinkalWallet(op.endpoint, op.callData, op.value);
            }
            // CASE 2: Stateless Interaction
            else {
                bytes4 selector = bytes4(op.callData);
                if (
                    selector == IHinkalWallet.callHinkalWallet.selector ||
                    selector == IHinkalWallet.doSendToRelay.selector
                ) {
                    revert UnauthorizedWalletCall();
                }

                (success, err) = op.endpoint.call{value: op.value}(op.callData);
            }

            if (!success) {
                revert CallFailed(err);
            }
        }
