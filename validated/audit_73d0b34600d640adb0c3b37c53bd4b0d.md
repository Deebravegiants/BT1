No vulnerability found for this question.

**Reasoning:**

The `deserialize` function in `vec_bytes.rs` simply decodes a sequence of raw byte arrays without validating UTF-8 or any encoding-specific canonicality, and that is by design. [1](#0-0) 

This is intentional: Move's `vector<u8>` type is byte-oriented, not string-oriented, so arguments consumed as seeds for `create_resource_address`/`create_object_address` are never expected to be UTF-8 or "canonical" in any sense — arbitrary bytes are the normal, valid input. [2](#0-1) [3](#0-2) 

The described attack requires finding two distinct seed byte vectors that cause a SHA3-256 preimage collision against an already-funded resource/object address. This is not a defect introduced by `vec_bytes::deserialize` accepting arbitrary bytes — it is a claim that SHA3-256 collision resistance can be broken by an unprivileged attacker, which is computationally infeasible (probability ~1/2^256, as explicitly documented in the framework itself). [4](#0-3) 

Additionally, even setting aside the infeasibility of the hash collision, `create_resource_account` already guards against hijacking an existing/funded account: it asserts the target address has no active `signer_capability_offer` and that its sequence number is `0` before taking control, which would block redirecting deposits to a pre-existing, already-used account. [5](#0-4) 

This finding conflates "accepts arbitrary non-UTF8 bytes" (intended, harmless) with "can engineer a hash collision" (cryptographically infeasible), and does not identify any actual defect in `vec_bytes::deserialize` or in the address-derivation/account-creation logic. No custody boundary is crossed by unprivileged input here.

    /// involves the use of a cryptographic hash operation and should be use thoughtfully.
    public fun create_resource_address(source: &address, seed: vector<u8>): address {
        let bytes = bcs::to_bytes(source);
        bytes.append(seed);
        bytes.push_back(DERIVE_RESOURCE_ACCOUNT_SCHEME);
        from_bcs::to_address(hash::sha3_256(bytes))
    }
