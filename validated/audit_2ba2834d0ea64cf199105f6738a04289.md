Audit Report

## Title
Global, workflow-unscoped `requestID` collision in HTTP Trigger Handler allows a caller authorized for any workflow to DoS other users' trigger requests - (File: `core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go`)

## Summary
The `httpTriggerHandler` stores in-flight requests in a single node-wide map keyed only by the caller-supplied `requestID`, with no namespacing by `workflowID` or owner. `setupCallback` rejects a request with `jsonrpc.ErrConflict` if that global map already contains an entry for the same `requestID`, regardless of which workflow the earlier entry belongs to, letting a caller authorized for one workflow deny another caller's unrelated request that happens to reuse the same ID.

## Finding Description
The `callbacks` map is declared as `map[string]savedCallback // requestID -> savedCallback` with no workflow-scoping in its key, at [1](#0-0) . `setupCallback` enforces uniqueness purely against this global map keyed by `requestID`, independent of `workflowID`: [2](#0-1) . `validateRequestID` only checks the ID is non-empty and contains no `/`, with no per-workflow scoping: [3](#0-2) .

Crucially, `setupCallback` is invoked only after `authorizeRequest`/`checkRateLimit` succeed, and `authorizeRequest` requires a valid ECDSA-signed JWT whose signer is one of the `workflowMetadataHandler.authorizedKeys` for the *targeted* `workflowID`: [4](#0-3) . This means a caller must have valid signing credentials for *some* registered workflow (their own, or one they are authorized to trigger) to reach `setupCallback` at all — but that workflow does not need to have any relationship to the victim's workflow. Once authorized for their own workflow A, an attacker can choose an arbitrary `requestID` (e.g., a predictable/sequential ID) and occupy the shared `h.callbacks` map entry before a legitimate caller with a valid JWT for a different workflow B sends a request using the same `requestID`. The victim's request hits the `found` check in `setupCallback` and is rejected outright, never reaching the DON.

`HandleNodeTriggerResponse` also routes node responses by `resp.ID` against this same global map, reinforcing that the ID is the sole disambiguator across the entire handler instance rather than per-workflow: [5](#0-4) .

## Impact Explanation
This is a cross-tenant denial-of-service: any caller who holds valid signing credentials for one registered workflow (a low bar — any legitimate CRE workflow owner/deployer) can grief an unrelated victim's HTTP-triggered workflow execution by pre-occupying a `requestID` the victim's client is predicted to use next. The victim's genuine request is rejected with `ErrConflict` and never dispatched to the DON, denying that specific trigger invocation without any credentials tied to the victim's workflow.

## Likelihood Explanation
Exploitation requires: (1) the attacker possess valid signing credentials for any registered workflow (achievable by deploying/registering a trivial workflow), and (2) the attacker be able to predict or guess a `requestID` the victim's client will use (plausible for common low-entropy/sequential/timestamp-based client ID schemes). Given these preconditions, the collision check is trivially triggerable with no rate limiting or scoping protecting against it, making this a realistic, low-cost griefing vector once workflow-authoring access is obtained.

## Recommendation
Scope the in-flight-request uniqueness check (and the `callbacks` map key) to a composite of `workflowID` (or workflow owner) plus `requestID`, so ID collisions can only occur within the same workflow/owner's own request stream, not across unrelated workflows/callers.

## Proof of Concept
1. Attacker registers/owns Workflow A with a valid signing key, and sends a `workflows.execute` request with JWT auth valid for Workflow A and `id = "1001"`.
2. `setupCallback` inserts `h.callbacks["1001"]` into the shared, node-wide map (`core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go:419-426`).
3. Victim's client, authorized separately for Workflow B, concurrently sends a legitimate `workflows.execute` request with the same `id = "1001"`.
4. Victim's request passes its own `authorizeRequest`/`checkRateLimit` for Workflow B but fails the `found` check in `setupCallback`, returning `jsonrpc.ErrConflict` and never reaching the DON — demonstrable via a Go unit test extending `TestHttpTriggerHandler_HandleUserTriggerRequest` in `http_trigger_handler_test.go`, registering two distinct workflows with distinct authorized keys, issuing two `HandleUserTriggerRequest` calls with the same `req.ID` but different valid workflow JWTs, and asserting the second call returns an `ErrConflict` user error.

func (h *httpTriggerHandler) validateRequestID(ctx context.Context, requestID string, callback handlers.Callback) error {
	if requestID == "" {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "'id' field is required and cannot be empty. Use a new unique request 'id' for each request", callback)
		return errors.New("empty request ID")
	}
	// Request IDs from users must not contain "/", since this character is reserved
	// for internal node-to-node message routing (e.g., "http_action/{workflowID}/{uuid}").
	if strings.Contains(requestID, "/") {
		h.handleUserError(ctx, requestID, jsonrpc.ErrInvalidRequest, "request ID must not contain '/'", callback)
		return errors.New("request ID must not contain '/'")
	}
	return nil
}

func (h *httpTriggerHandler) setupCallback(ctx context.Context, requestID string, callback handlers.Callback, requestStartTime time.Time, workflowID string) (<-chan struct{}, error) {
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()

	if _, found := h.callbacks[requestID]; found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrConflict, fmt.Sprintf("requestID: %s has already been used. Ensure the requestID is unique for each request.", requestID), callback)
		return nil, fmt.Errorf("in-flight request ID: %s", requestID)
	}

	h.lggr.Debugw("handling trigger response", "requestID", resp.ID, "nodeAddr", nodeAddr, "error", resp.Error, "result", resp.Result)
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}
