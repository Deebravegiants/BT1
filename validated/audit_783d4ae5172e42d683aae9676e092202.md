### Title
Attacker plants an Aquarius-LP dust collateral leg then drains the pool below `min_pool_value_wad`, permanently shielding their underwater account from liquidation and bad-debt cleanup - (File: contracts/price-aggregator/src/providers/aquarius.rs)

### Summary
The Asterisk CVE is a remotely triggerable denial of service. The in-scope analog is a denial of liquidation/cleanup that a single unprivileged borrower can cause deliberately. `supply` admits a new collateral leg without requiring a valid price for it, while every valuation-dependent exit path (`liquidate`, `clean_bad_debt`, `force_socialize_bad_debt`, `withdraw` on a leveraged account) strictly resolves **all** of the account's collateral prices. An account holding an Aquarius LP supply leg becomes unpriceable — and therefore unliquidatable and unsocializable — whenever the underlying Aquarius pool's total value falls below the oracle source's `min_pool_value_wad` floor. Because any liquidity provider in that Aquarius pool can withdraw reserves, an attacker who is (or becomes) an LP can cause the outage on demand, park an insolvent account behind it, and let debt accrue until it is pure bad debt that no permissionless or governance path can clean.

### Finding Description
1. `supply` does not need a price. The threat model confirms: "Supply needs no price, so an indebted borrower can add a dust leg of any listed collateral and choose which feed outage shields the account." [1](#0-0) 
2. Aquarius LP tokens are listed collateral (e.g., `XLMAQUA_LP`, `AQUAUSDC_LP` on hub 3), each priced by a single `AquariusLp` source carrying `min_pool_value_wad` (e.g., 500,000 USD WAD for XLMAQUA_LP). [2](#0-1) 
3. The LP price read hard-fails when pool value is below the floor: `if pool_value_wad < lp.min_pool_value_wad { return Err(OracleError::InsufficientAquariusLiquidity); }`. [3](#0-2) 
4. All risk valuations use strict prices and fail closed (INV-ORACLE-01): a missing/unusable required price aborts the operation, "including liquidation". [4](#0-3) 
5. `clean_bad_debt` and owner-gated `force_socialize_bad_debt` both compute `calculate_account_risk_totals` over the account's full supply book before gating, so the same unpriceable leg blocks both cleanup paths ("Missing or invalid required prices prevent cleanup"). [5](#0-4) [6](#0-5) 
6. The borrower cannot remove the leg themselves once underwater (`withdraw` also reverts on the stale/invalid price), so the shield is self-sustaining; the test `audit_liquidate_and_clean_bricked_by_unpriceable_dust_leg` demonstrates the same revert on `liquidate`, `clean_bad_debt`, and `withdraw` for an unpriceable dust leg. [7](#0-6) 

Root cause: LP fair-value pricing enforces a pool-liquidity floor that external parties control, and risk valuation requires **every** collateral leg to price, so one attacker-chosen fragile leg vetoes all recovery entrypoints on the account.

### Impact Explanation
Protocol insolvency. The attacker borrows against ordinary collateral plus a dust LP leg, lets the position go underwater (price move or accrued interest), then withdraws their liquidity from the Aquarius pool to push pool value under the floor. From that point: `liquidate` reverts, `clean_bad_debt` reverts, `force_socialize_bad_debt` reverts — debt accrues unbounded while the account can never be touched. When the outage ends (attacker redeposits or others add liquidity), the bad debt is socialized onto suppliers via the supply-index write-down. The attacker forfeits only the dust leg value; lenders absorb the unpaid debt.

### Likelihood Explanation
Medium. Requirements: the account's spoke must list an `AquariusLp`-priced asset (true on mainnet hub 3), and someone must drive the pool below `min_pool_value_wad`. An attacker who already provides liquidity can do this at will; on thin pools even non-LP conditions (other LPs exiting) trigger it. Cost is bounded (temporarily withdraw own liquidity; the dust leg is tiny). The shield persists as long as pool value stays under the floor, and the attacker controls both ends of that condition. It is a deliberate, repeatable DoS of the liquidation system per account, matching the CVE's remote-DoS class.

### Recommendation
- Do not let a single collateral leg veto account-level recovery: during `liquidate`/`clean_bad_debt`, treat legs whose price resolution fails as zero-value collateral (exclude from seizure plan and collateral total) rather than aborting the whole valuation, or add a dedicated permissionless "drop unpriceable leg" path that forfeits the leg to the pool.
- Alternatively, require a strict fresh price at `supply` time for newly opened collateral legs so a leg cannot be planted while already unpriceable (does not fix legs that later become unpriceable, so prefer the first option).
- Keep `min_pool_value_wad` floors conservative relative to pool depth, and alert on approach (the exporter alert `LendingLpPoolValueNearFloor` already exists — treat breaching it as actionable). [8](#0-7)
