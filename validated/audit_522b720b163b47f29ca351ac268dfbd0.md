### Title
Webhook Tenant Identity Not Bound by HMAC, Enabling Cross-Tenant Webhook Spoofing - (File: `lib/shopify_api/webhooks/request.rb`)

### Summary
`ShopifyAPI::Webhooks::Request` derives the tenant identity (`shop`) from the `X-Shopify-Shop-Domain` header, but the HMAC signature verified by `Utils::HmacValidator` only covers the raw request body. Any attacker who can obtain one valid `(raw_body, hmac)` pair for a webhook (trivially available to anyone who installs the app on their own store) can replay that exact body/HMAC pair while substituting an arbitrary victim shop domain in the unsigned header, and `Registry.process` will accept it as authentic.

### Finding Description
`Utils::HmacValidator.validate` verifies the signature only against `verifiable_query.to_signable_string`: [1](#0-0) 

For webhooks, `to_signable_string` returns only `@raw_body`: [2](#0-1) 

The `shop` identity used downstream is read from a header that is not part of the signed material at all: [3](#0-2) 

`Registry.process` validates the HMAC and then dispatches the handler using this unsigned `shop` value as the tenant identifier: [4](#0-3) 

The equality the check is supposed to guarantee is:
`hmac_verified(shop, body) == true` for the tuple actually processed.

What is actually guaranteed is only:
`hmac_verified(body) == true`, independent of `shop`.

Because `shop` is excluded from the signed bytes, an attacker can decouple the two: capture a legitimately-signed `(body, hmac)` pair for their own store (any Shopify merchant can install a public app and receive real webhooks for their own shop), then resend that identical body/HMAC pair with a forged `X-Shopify-Shop-Domain` header pointing at a different merchant. `HmacValidator.validate` still returns `true` because the body bytes are unchanged, and `Registry.process` forwards `shop: request.shop` (attacker-controlled) to the registered `WebhookHandler`.

### Impact Explanation
Any webhook handler that uses `data.shop` (from `WebhookMetadata`) to select which merchant's stored data to read, update, or delete will act on the wrong tenant's data using attacker-supplied body content, breaking multi-tenant isolation — a cross-tenant access condition. This requires no access token, no `client_secret`, and no privileged account: only the ability to install the app on an attacker-controlled shop to obtain one valid signed payload, which is then replayed with a substituted shop header.

### Likelihood Explanation
The precondition (installing the app on one's own store to harvest a valid body/HMAC pair, then replaying it with a modified header against the app's public webhook endpoint) is achievable by any unprivileged internet user with a free Shopify development/trial store, and requires no secret material belonging to Shopify or to the victim.

### Recommendation
Bind the shop identity into the verified material, or independently authenticate it, rather than trusting the header directly for tenant scoping:
- Include the shop domain (and ideally topic/webhook-id) in the signable string used by `HmacValidator`, or
- Cross-check `request.shop` against a known/expected shop (e.g., the shop associated with an existing installed session) before dispatching to the handler in `Registry.process`, and document that handlers must not treat `WebhookMetadata#shop` as authenticated unless independently corroborated.

### Proof of Concept
1. Install the target app on an attacker-owned shop `attacker.myshopify.com`. Trigger any webhook (e.g., `orders/create`) and capture the raw POST body and its `X-Shopify-Hmac-Sha256` header — both valid and Shopify-signed.
2. Replay the exact captured request to the app's webhook endpoint, changing only `X-Shopify-Shop-Domain` to `victim.myshopify.com`.
3. `ShopifyAPI::Webhooks::Registry.process` calls `Utils::HmacValidator.validate(request)`, which validates `HMAC(raw_body)` — unchanged from step 1, so it passes.
4. `handler.handle(data: WebhookMetadata.new(topic:, shop: "victim.myshopify.com", body: parsed_body, ...))` is invoked; the app now processes attacker-controlled body content under the victim shop's identity, breaking tenant isolation.
