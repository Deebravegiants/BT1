### Title
`TokenBucket`/`KeyedRateLimiter` grants unintended full-burst capacity to first-seen keys due to zero-initialized `last_update` clock anchored to a stale `base_time` - (File: `net-utils/src/token_bucket.rs`)

### Summary
`TokenBucket::new()` sets `last_update: AtomicU64::new(0)` while capturing `base_time = Instant::now()` at construction time. When a `TokenBucket` is used directly this is harmless, because the very first `time_us()` call returns a value close to `0` as well. However, `KeyedRateLimiter<K>` (used to per-key rate-limit e.g. IP addresses or peer pubkeys) creates new per-key buckets by cloning a long-lived `prototype_bucket` on demand, and `Clone` for `TokenBucket` copies the prototype's *original* `base_time` and its (permanently `0`) `last_update` verbatim into every newly-created bucket. This is analogous to the reported `RedemptionBatteryLib` bug where `battery.lastBlock` defaulted to `0` instead of the current block, producing an artificially huge "elapsed" delta on first use that is only bounded by the mechanism's maximum cap.

`update_state(now)` computes `elapsed = now.saturating_sub(last)` and mints `elapsed * new_tokens_per_us` tokens (capped only by `max_tokens` via `add_tokens`): [3](#0-2) 

`Clone` for `TokenBucket` copies the *prototype's* `base_time` and `last_update` into the freshly cloned bucket rather than re-anchoring them to the clone's actual creation time: [4](#0-3) 

`KeyedRateLimiter::consume_tokens` creates a new per-key bucket exactly this way whenever a key (e.g., a new IP address) is seen for the first time: [5](#0-4) 

Because the prototype bucket is only ever cloned (never itself driven through `consume_tokens`/`current_tokens`), its `last_update` remains `0` for the lifetime of the process, while its `base_time` is fixed at the moment the `KeyedRateLimiter` (and its prototype) was constructed — typically at node/service startup. Any time a brand-new key (e.g., a new peer IP or pubkey) is inserted after the process has been running for a while, the newly cloned bucket computes `now = Instant::now() - base_time` (a large value proportional to node uptime) versus `last = 0`, yielding a huge `elapsed`. `update_state` then mints tokens up to `max_tokens`, so the new bucket is created already fully charged to its maximum burst capacity instead of the intended smaller `initial_tokens` value.

This exactly mirrors the reported bug class: a "last-update" state variable defaults to `0` instead of "now," producing an inflated elapsed interval on first use that is silently capped by the mechanism's ceiling (`maxCharge` in the Reserve report, `max_tokens` here).

### Impact Explanation
`KeyedRateLimiter`-backed `TokenBucket`s are used for unprivileged, externally-triggerable throttling paths, e.g. per-IP QUIC connection rate limiting (`streamer/src/nonblocking/connection_rate_limiter.rs`, consumed from `streamer/src/nonblocking/quic.rs`) and other keyed rate limiters (`core/src/forwarding_stage.rs`, `core/src/repair/serve_repair.rs`, `streamer/src/nonblocking/simple_qos.rs`, `gossip/src/cluster_info.rs`). Any external, unprivileged actor that is the first to be rate-limited under a given key (e.g. the first connection from a never-before-seen IP address, which any attacker fully controls by rotating source IPs) is granted the bucket's full `max_tokens` burst allowance immediately rather than the smaller, intentionally-configured `initial_tokens` starting allowance whenever a rate limiter is configured with `initial_tokens < max_tokens` (a legitimate and common configuration, since `max_tokens` typically represents an allowed burst ceiling above the steady-state rate). This materially underprices/under-throttles the first request(s) from each new key relative to the intended rate-limiting policy, weakening a DoS-mitigation control on a validator-facing, unprivileged network path.

### Likelihood Explanation
High. The condition is triggered deterministically by any legitimate first-time use of a new key in a `KeyedRateLimiter` after any nonzero amount of wall-clock time has passed since the limiter/prototype was constructed (which is essentially always true once the node has been running). No race condition, privileged access, or special timing is required — an external, unprivileged client simply needs to be the first party using a fresh key (e.g., a new source IP for a QUIC connection).

### Recommendation
Set the newly cloned bucket's `last_update` and effectively its `base_time` reference point to "now" at clone time (or equivalently seed `last_update` with the new bucket's own `time_us()` value at construction), so that new per-key buckets start crediting from their own creation moment with `initial_tokens`, not from a stale, zero-anchored clock that lets `update_state` mint tokens for the entire uptime of the prototype.

### Proof of Concept
1. Start a service using `KeyedRateLimiter::new(target_capacity, TokenBucket::new(initial_tokens, max_tokens, rate), shards)` where `initial_tokens < max_tokens` (e.g. `ConnectionRateLimiter::new(limit_per_minute, max_burst, shards)` with `max_burst > limit_per_minute`).
2. Let the process run for a duration `Δt` such that `Δt * rate_per_us >= (max_tokens - initial_tokens)` (i.e., enough wall-clock time has elapsed since the limiter/prototype was created; this happens naturally after the node has been up for even a short period given typical rates).
3. From a brand-new key never seen before (e.g., a new source IP establishing a QUIC connection through `streamer/src/nonblocking/connection_rate_limiter.rs`), call `limiter.consume_tokens(key, n)`.
4. Internally this hits the `Entry::Vacant` branch, clones `prototype_bucket` (carrying `base_time` from limiter construction and `last_update = 0`), and calls `consume_tokens` on it: `now = time_us()` is large (≈`Δt` in microseconds), `last = 0`, so `update_state` mints tokens up to `max_tokens` before the very first debit — observably, `current_tokens()` immediately after first use will read `max_tokens` (minus the just-consumed amount) rather than `initial_tokens` (minus consumed).     /// Updates internal state of the bucket by
    /// depositing new tokens (if appropriate)
    fn update_state(&self, now: u64) {
        // fetch last update time
        let last = self.last_update.load(Ordering::SeqCst);

        // If time has not advanced, nothing to do.
        if now <= last {
            return;
        }

        // Try to claim the interval [last, now].
        // If we can not claim it, someone else will claim [last..some other time] when they
        // touch the bucket.
        // If we can claim interval [last, now], no other thread can credit tokens for it anymore.
        // If [last, now] is too short to mint any tokens, spare time will be preserved in credit_time_us.
        match self.last_update.compare_exchange(
            last,
            now,
            Ordering::AcqRel,  // winner publishes new timestamp
            Ordering::Acquire, // loser observes updates
        ) {
            Ok(_) => {
                // This thread won the race and is responsible for minting tokens
                let elapsed = now.saturating_sub(last);

                // also add leftovers from previous conversion attempts.
                // we do not care about who uses the spare_time_us, so relaxed is ok here.
                let elapsed =
                    elapsed.saturating_add(self.credit_time_us.swap(0, Ordering::Relaxed));

                let new_tokens_f64 = elapsed as f64 * self.new_tokens_per_us;

                // amount of full tokens to be minted
                let new_tokens = new_tokens_f64.floor() as u64;

                let time_to_return = if new_tokens >= 1 {
                    // Credit tokens, saturating at max_tokens
                    self.add_tokens(new_tokens);
                    // Fractional remainder of elapsed time (not enough to mint a whole token)
                    // that will be credited to other minters
                    (new_tokens_f64.fract() / self.new_tokens_per_us) as u64
                } else {
                    // No whole tokens minted → return whole interval
                    elapsed
                };
                // Save unused elapsed time for other threads
                self.credit_time_us
                    .fetch_add(time_to_return, Ordering::Relaxed);
            }
            Err(_) => {
                // Another thread advanced last_update first → nothing we can do now.
            }
        }
    }
