### Title
Unchecked RAY index accrual overflows before the index cap and permanently freezes a whale market - ([File: common/src/rates/index.rs])

### Summary
Interest accrual multiplies scaled supply or debt balances by their RAY index before applying the configured index ceiling. Once a sufficiently large, highly utilized market reaches an unscaled value above `i128::MAX`, `MathOverflow` reverts inside accrual before `MAX_BORROW_INDEX_RAY` or `MAX_SUPPLY_INDEX_RAY` can clamp the index. Because every state-changing pool operation synchronizes interest first, the affected market becomes unrecoverable through ordinary repay, withdraw, liquidation, or index-update calls. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`Cache::load` records both the stored accrual timestamp and current timestamp, while `global_sync` calls `accrue_chunk` for every elapsed interval before marking the market accrued. [4](#0-3) [1](#0-0) 

Each chunk calls `accrue_step` with the outstanding scaled `borrowed`, `supplied`, and current indexes, then commits the resulting indexes and revenue shares. [5](#0-4) 

On the debt side, `calculate_supplier_rewards` computes both `borrowed * old_borrow_index` and `borrowed * new_borrow_index` using `Ray::mul`. [6](#0-5) 

On the supply side, `update_supply_index` computes `supplied * old_index` before the new supply index is bounded. [7](#0-6) 

`Ray::mul` delegates to `mul_div_half_up`; although it uses an exact `I256` intermediate when necessary, an unrepresentable `i128` quotient still raises `MathOverflow`. [8](#0-7) [9](#0-8) 

The borrow-index ceiling is checked only after `old_index * interest_factor`, and the arithmetic in `calculate_supplier_rewards` and `update_supply_index` can still overflow after that index itself has been capped. [2](#0-1) [10](#0-9) 

### Impact Explanation
This causes permanent freezing of user funds and market operations. Since `global_sync` runs before market mutations, a supplier cannot withdraw, a borrower cannot repay, and a liquidator cannot execute a liquidation once the accrual expression exceeds `i128::MAX`; repeated calls recompute the same overflowing value before any state repair occurs. [1](#0-0) [11](#0-10) 

The in-repository regression test demonstrates that after the overflow, both `withdraw` and `repay` fail with `MATH_OVERFLOW`, while the stored borrow index remains below `MAX_BORROW_INDEX_RAY`, proving that the configured cap did not protect the market. [12](#0-11) 

An unprivileged attacker can establish the condition with controller `supply`, `borrow`, and later `update_indexes` calls: supply an extremely large balance to the target market, supply collateral and borrow most of that liquidity, then let sustained high utilization compound until any caller-triggered accrual crosses the `i128` value ceiling. `update_indexes` requires the caller's authorization but is exposed as an ordinary caller-authorized controller operation. [13](#0-12) [14](#0-13) 

### Likelihood Explanation
Likelihood is low because the attacker must genuinely control an enormous token balance: the demonstrated setup uses one billion whole tokens at 18 decimals as borrow-market liquidity and additional collateral, then drives approximately 98% utilization. [15](#0-14) 

The condition is nevertheless deterministic once such a market exists. Accrual is mandatory and time-based, the index is monotone for borrows, and the test reaches the cliff at sustained high utilization without requiring governance action, oracle manipulation, or a privileged role. [16](#0-15) [17](#0-16) 

### Recommendation
Bound the scaled-value computation, not merely the index result. In `common/src/rates/index.rs`, detect when `supplied`, `borrowed`, or an index is already at or above the relevant cap and use saturating or widened comparisons for `scaled * index / RAY`; alternatively cap the effective scaled share or index input before multiplication. Apply equivalent handling to `update_supply_index`, `supply_index_reward_shortfall`, `calculate_supplier_rewards`, bad-debt index adjustment, and all unscale paths so an over-domain state cannot make every subsequent `global_sync` revert. [7](#0-6) [18](#0-17) [19](#0-18) 

Add a recovery invariant that a market whose index has reached `MAX_BORROW_INDEX_RAY` or `MAX_SUPPLY_INDEX_RAY` remains serviceable: accrual should become a no-op or clamped calculation at the cap rather than attempting an unrepresentable balance valuation. The regression case should assert that repay, withdraw, liquidation, and `update_indexes` continue to function after the cap is reached. [1](#0-0) [20](#0-19) 

### Proof of Concept
The repository already contains an executable end-to-end proof in `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs`: it creates an 18-decimal market, lifts caps, supplies `BILLION * 10^18`, supplies collateral, and borrows `principal * 98 / 100`. [15](#0-14) 

It then advances time year by year and invokes `update_indexes` until the call returns `MATH_OVERFLOW`. [21](#0-20) 

The test verifies that the stored borrow index is still below `MAX_BORROW_INDEX_RAY`, then verifies that `withdraw` and `repay` both fail with `MATH_OVERFLOW`, establishing the market freeze and failed index cap. [22](#0-21)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
```

pub fn update_supply_index(env: &Env, supplied: Ray, old_index: Ray, rewards_increase: Ray) -> Ray {
    if supplied == Ray::ZERO || rewards_increase == Ray::ZERO {
        return old_index;
    }

    let total_supplied_value = supplied.mul(env, old_index);

    if total_supplied_value == Ray::ZERO {
        return old_index;
    }

    let new_value = total_supplied_value.checked_add(env, rewards_increase);
    let grown = fp_core::mul_div_floor_saturating(env, new_value.raw(), RAY, supplied.raw());

    let bounded_old = old_index.raw().min(MAX_SUPPLY_INDEX_RAY);
    Ray::from(grown.min(MAX_SUPPLY_INDEX_RAY).max(bounded_old))

pub fn supply_index_reward_shortfall(
    env: &Env,
    supplied: Ray,
    old_index: Ray,
    new_index: Ray,
    rewards_increase: Ray,

/// Splits the interest accrued on `borrowed` debt between `old_borrow_index`
/// and `new_borrow_index` into supplier rewards and protocol fee, per
/// `params.reserve_factor`. Returns `(supplier_rewards, protocol_fee)`.
///
/// Panics if `new_borrow_index` implies less total debt than
/// `old_borrow_index`, or if the rounded protocol fee exceeds the accrued
/// interest.
pub fn calculate_supplier_rewards(
    env: &Env,
    params: &MarketParams,
    borrowed: Ray,
    new_borrow_index: Ray,
    old_borrow_index: Ray,
) -> (Ray, Ray) {
    let old_total_debt = borrowed.mul(env, old_borrow_index);
    let new_total_debt = borrowed.mul(env, new_borrow_index);

    let accrued_interest = new_total_debt.checked_sub(env, old_total_debt);

    let protocol_fee = params.reserve_factor.apply_to_ray(env, accrued_interest);
    let supplier_rewards = accrued_interest.checked_sub(env, protocol_fee);

    (supplier_rewards, protocol_fee)

pub fn try_mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> Option<i128> {
    if x < 0 || y < 0 || d <= 0 {
        return None;
    }
    let half = d / 2;

    // Fast path: the biased product fits `i128`, so the whole computation is
    // native. `x * y + half` is non-negative here, so `/` is the floor the
    // widened path would produce.
    if let Some(biased) = x
        .checked_mul(y)
        .and_then(|product| product.checked_add(half))
    {
        return Some(biased / d);
    }

    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    x256.mul(&y256)
        .add(&I256::from_i128(env, half))
        .div(&d256)
        .to_i128()
}

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
```
