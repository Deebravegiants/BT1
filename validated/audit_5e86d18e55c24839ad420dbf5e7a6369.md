## Analog Found: CORS Wildcard-Origin Suffix Bypass in Gateway HTTP Server

### Title
Insufficient CORS Origin Validation via Wildcard Suffix Match Allows Cross-Origin Data Leak - (File: `core/services/gateway/network/httpserver.go`)

### Summary
The Gateway's HTTP server implements its own CORS origin allow-list logic in `isAllowedOrigin`, including a wildcard mode intended to match subdomains (e.g. `*.remix.com`). The wildcard check uses a plain string-suffix comparison instead of a domain-boundary-aware comparison, so any origin whose hostname string *ends with* the configured suffix — not just true subdomains — is treated as trusted and gets `Access-Control-Allow-Origin` reflected back with credentials-friendly headers.

### Finding Description
`isAllowedOrigin` strips the `*.` prefix from a configured entry and then does:
```go
if strings.HasPrefix(allowedHost, "*.") {
    allowedHost = allowedHost[2:]
    if strings.HasSuffix(originHost, allowedHost) {
        return true
    }
}
``` [1](#0-0) 

There is no check that the character immediately preceding the matched suffix is a `.` (dot) label separator. Consequently, for an allow-list entry `*.example.com` (which strips to `example.com`), any attacker-registered hostname that merely ends with the literal characters `example.com` — such as `evilexample.com` or `notexample.com` — will satisfy `strings.HasSuffix(originHost, "example.com")` and be treated as an allowed origin, even though it is not a subdomain of `example.com` and is fully controlled by an unrelated third party.

This result then flows directly into the response:
```go
if s.config.CORSEnabled {
    origin := r.Header.Get("Origin")
    if s.isAllowedOrigin(origin) {
        w.Header().Set("Access-Control-Allow-Origin", origin)
        w.Header().Set("Access-Control-Allow-Methods", "GET, POST, OPTIONS")
        w.Header().Set("Access-Control-Allow-Headers", "Content-Type")
    }
``` [2](#0-1) 

The trusted origin is echoed verbatim into `Access-Control-Allow-Origin`, so a browser on the attacker's page will treat the Gateway's response as same-origin-permitted, letting attacker JavaScript read the response body via `fetch`/`XMLHttpRequest`. This request path is reachable from any unauthenticated internet client hitting the Gateway's public-facing HTTP endpoint (`handleRequest`), which forwards the parsed body straight to `s.handler.ProcessRequest` (the JSON-RPC gateway dispatcher) — i.e., this is the internet-facing gateway envelope path called out as in-scope. [3](#0-2) 

This is the same root-cause bug class as CVE-2023-0141: "insufficient policy enforcement in CORS ... allowed a remote attacker to leak cross-origin data via a crafted HTML page." Both issues stem from an origin/hostname comparison that is too permissive (missing a strict boundary/anchor check), letting an attacker-controlled origin string satisfy a trust check it should not.

Note: The separate UI-facing `uiCorsHandler` (using `github.com/gin-contrib/cors`) in `core/web/router.go` does an exact list match with `AllowOrigins`, and does not implement the vulnerable wildcard-suffix logic, so it is not affected. [4](#0-3) 

### Impact Explanation
If a Gateway operator configures a wildcard `CORSAllowedOrigins` entry (e.g., `*.mycompany.com`), an unrelated attacker who registers or controls a domain that merely ends with that suffix string (e.g. `evilmycompany.com`) can craft an HTML page that triggers cross-origin `fetch` requests against the Gateway's HTTP endpoint. Because the CORS check passes, the browser exposes the JSON-RPC response body to the attacker's script, enabling cross-user response confusion / cross-origin data leak. Depending on what data flows through the Gateway (e.g., request/response envelopes tied to workflows, DON responses, capability responses), this could leak sensitive response content to an unauthorized third party.

### Likelihood Explanation
Exploitability requires: (1) the Gateway operator to have configured a wildcard CORS entry (documented and supported usage, not a misconfiguration outside the intended feature), and (2) the victim's browser to visit an attacker page while some session/credential-relevant flow triggers a request to the Gateway endpoint reflecting the attacker origin. Since wildcard subdomain allow-listing is an explicitly supported configuration option, and domain registration under an unrelated suffix-matching name is trivial for an attacker, likelihood is moderate — it requires social engineering (crafted page) similar to the original Chrome CVE, aligning with the CVSS `UI:R` vector.

### Recommendation
Fix `isAllowedOrigin` to require a proper label boundary when doing wildcard suffix matching, e.g. verify that the character immediately before the suffix match is `.`, or reconstruct and compare using `strings.HasSuffix(originHost, "."+allowedHost)` in addition to the exact match, e.g.:
```go
if strings.HasPrefix(allowedHost, "*.") {
    suffix := allowedHost[1:] // keep the leading dot: ".example.com"
    if strings.HasSuffix(originHost, suffix) {
        return true
    }
}
```
This ensures only genuine subdomains of the configured domain match, not arbitrary hostnames sharing a character suffix.

### Proof of Concept
1. Configure the Gateway with `CORSAllowedOrigins = ["*.example.com"]` and `CORSEnabled = true`.
2. From an attacker-controlled page hosted at `https://evilexample.com`, send:
```js
fetch("https://gateway.node/jsonrpc", {
  method: "POST",
  headers: {"Content-Type": "application/json"},
  body: JSON.stringify({ /* valid JSON-RPC envelope */ })
}).then(r => r.text()).then(console.log)
```
3. The Gateway's `isAllowedOrigin("https://evilexample.com")` computes `originHost = "evilexample.com"`, `allowedHost = "example.com"` (after stripping `*.`), and `strings.HasSuffix("evilexample.com", "example.com")` returns `true`, so the response is reflected with `Access-Control-Allow-Origin: https://evilexample.com`, letting the attacker script read the Gateway's response body cross-origin.

func uiCorsHandler(ao string) gin.HandlerFunc {

		AllowHeaders:     []string{"Origin", "Content-Type", "Accept"},

		AllowCredentials: true,
		MaxAge:           math.MaxInt32,
	}

		c.AllowAllOrigins = true
	} else if allowOrigins := strings.Split(ao, ","); len(allowOrigins) > 0 {
		c.AllowOrigins = allowOrigins
	}
	return cors.New(c)
