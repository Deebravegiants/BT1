### Title
`execute_self` runs unscheduled self-targeted admin operations — the only guard treats "never scheduled" as "not expired" - (File: contracts/governance/src/timelock/lifecycle.rs)

### Summary
The governance contract exposes two execute paths. `execute` (external targets) delegates to `stellar_governance::timelock::execute_operation`, which enforces that the operation was scheduled and its delay elapsed. `execute_self` and `execute_canceller_reset` instead call `set_execute_operation` plus `apply_self_op`/`apply_canceller_reset` directly — the only local gate is `require_operation_not_expired`, which explicitly skips the check when the operation's ready-ledger is `0` (unset, i.e. never scheduled). An inverted/missing-state check: a value meaning "does not exist" is treated as "cleared to execute".

### Finding Description
In `contracts/governance/src/timelock/lifecycle.rs:115-131`, `execute_self`:

```rust
let operation_id = prepare_execute(env, executor.as_ref(), &operation);
set_execute_operation(env, &operation);
apply_self_op(env, op);
finish_execute(env, &operation_id);
```

`prepare_execute` (`timelock/mod.rs:182-188`) only calls `authorize_executor` — which does nothing when `executor` is `None` (`mod.rs:77-82`, "When `None`, performs no auth or role check (anyone may drive execution)") — and `require_operation_not_expired`. That function (`mod.rs:87-99`) reads `get_operation_ledger` and **returns early when `ready_ledger <= 1`**, with the doc comment confirming `0` means "unset". So for an operation id that was never scheduled through `propose`, the entire authorization surface is: hash an `Operation`, see ledger `0`, skip the check, apply the admin op.

The contrast with `execute` (`lifecycle.rs:106-108`) makes the root cause precise: the external-target path calls `execute_operation`, the library primitive that validates scheduling/readiness; the self-target path replaces it with `set_execute_operation` (an execution-context marker, not a readiness check) and never verifies the operation was ever proposed or that its delay elapsed. The same shape exists in `execute_canceller_reset` (`timelock/recovery.rs:38-42`), which would let anyone replace the `CANCELLER_ROLE` set without the ~30-day `Recovery` delay.

### Impact Explanation
Any address can invoke `Governance::execute_self` with `executor: None` and an arbitrary self-targeting `AdminOperation` — e.g. `GrantGovRole` (self-grant `EXECUTOR_ROLE`/`CANCELLER_ROLE`), `TransferGovOwnership`, `UpdateGovDelay`, `SetPriceAggregator`, `SetSwapAggregator`, `SetAccumulator`, `ConfigureAssetOracle` — with any salt, bypassing the `PROPOSER_ROLE`, owner-only, and delay-tier checks in `propose` entirely. This is full governance takeover: redirecting the accumulator steals all future revenue; swapping the price aggregator enables oracle manipulation and theft of user funds across the controller/pool. The `RevokeGovRole`/`GrantGovRole` owner-restriction checks in `propose` (`lifecycle.rs:39-70`) are also bypassed since `apply_self_op` applies the op unconditionally.

### Likelihood Explanation
Certain if `set_execute_operation` does not itself re-validate readiness — the local code's own comments treat ledger `0`/unset as a state that "skips the check", indicating no other validation was intended at this layer. One caveat: the readiness logic of `set_execute_operation`/`execute_operation` lives in the external `stellar-governance` crate whose source is not indexed here; the finding holds because `execute_self` deliberately avoids `execute_operation` (the validating primitive) that the sibling `execute` uses, leaving `require_operation_not_expired` as the sole guard — and it is satisfied by an unscheduled id. The call requires no roles, no auth, and one transaction.

### Recommendation
In `execute_self` and `execute_canceller_reset`, require the operation to be scheduled and ready before applying it: assert `get_operation_ledger(env, &operation_id) > 1` and `env.ledger().sequence() >= ready_ledger` in `prepare_execute`, or route self-targeted operations through a readiness-validating primitive (equivalent to `execute_operation`) rather than the bare `set_execute_operation` marker. Treat `ready_ledger == 0` as `NotScheduled`, not as "not expired".

### Proof of Concept
1. Attacker (fresh address, no roles) calls `Governance::execute_self(None, AdminOperation::GrantGovRole { account: attacker, role: EXECUTOR_ROLE }, arbitrary_salt)`.
2. `operation_for_admin_op` resolves a self-targeted `Operation`; `prepare_execute` → `authorize_executor(None)` = no-op; `hash_operation` yields an id with no `OperationLedger` entry → `get_operation_ledger` = `0` → `require_operation_not_expired` returns.
3. `apply_self_op` grants the role. Attacker repeats with `TransferGovOwnership`/`SetPriceAggregator`/`SetAccumulator`, or uses `execute_canceller_reset` to seize the canceller set, achieving full control of the governance layer and every contract it administers — with zero delay and zero authorization.
