Audit Report

## Title
Unauthenticated disclosure of plugin memory/profiling statistics via `/plugins/:name/debug/pprof/*` and `/plugins/:name/metrics` routes - (File: `core/web/router.go`)

## Summary
`NewRouter` registers `loopRoutes` directly on the base `api` gin group, which only carries rate-limiting and session-cookie middleware, never an authentication check. This exposes `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` to any client that can reach the node's web server, without any session/token/role check.

## Finding Description
In `core/web/router.go`, the `api` group is built with only a rate limiter and cookie session middleware, and `loopRoutes(app, api)` is called on it directly with no auth wrapper: [1](#0-0) 

`loopRoutes` registers the plugin metrics/pprof/symbol endpoints with no `auth.Authenticate` middleware whatsoever: [2](#0-1) 

This is inconsistent with the rest of the router: `debugRoutes` wraps the analogous `/debug/vars` endpoint in `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)`: [3](#0-2) 

and `metricRoutes` (the node's own pprof handlers) is only ever registered inside the already-authenticated `authv2` group: [4](#0-3) 

`pluginPPROFHandler` in `core/web/loop_registry.go` takes the caller-supplied `:name` and `*profile` path params plus query values and forwards them unauthenticated and unauthorized to the internal LOOP plugin's pprof endpoint, returning the raw response body to the caller: [5](#0-4) 

`pluginMetricHandler` behaves the same way for `/plugins/:name/metrics`: [6](#0-5) 

I confirmed by reading the full `NewRouter` function that no other middleware (global `engine.Use(...)`) applies authentication either — the global middleware stack is limited to otel tracing, request-size limiting, logging, panic recovery, CORS, and security headers, none of which perform authentication: [7](#0-6) 

This confirms the claim's root cause is accurate: these four routes are reachable by a completely unauthenticated network client, and the disparity with `debugRoutes`/`metricRoutes` (which are explicitly wrapped in auth) shows this is an inconsistency in the code rather than an intentional design choice, since the analogous node-level pprof/debug endpoints are deliberately gated behind auth.

## Impact Explanation
An unauthenticated client that can reach the node's HTTP API can retrieve heap, goroutine, allocation, and other pprof profiles for any registered LOOP plugin, and can scrape the plugin's raw Prometheus `/metrics` output. This discloses internal memory contents, running goroutine stacks, and internal operational state without any credentials — a confidentiality-only information disclosure, directly analogous in kind to CVE-2025-5605 (unauthenticated access to memory-statistics endpoints via URL manipulation bypassing intended authentication). This maps to an in-scope "node API authentication bypass" class of issue since a route that should require session/token authentication (consistent with every structurally similar route in the same file) is reachable without any credential.

## Likelihood Explanation
High. The routes are unconditionally registered for any node with LOOP plugins configured (a common Chainlink deployment pattern, e.g. Solana/Starknet/median LOOPs), require no special network position beyond what's needed to reach the node's already-exposed web server, and need zero credentials, tokens, or session cookies to trigger.

## Recommendation
Wrap `loopRoutes` — or at minimum the `/plugins/:name/metrics` and `/plugins/:name/debug/pprof/*` routes — with the same `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)` middleware used for `authv2`, or move these handlers into the `authv2` group alongside `metricRoutes`. If `/discovery` and `/metrics` must remain reachable for external Prometheus scraping without session auth, consider a dedicated, narrowly-scoped Prometheus-only credential/allowlist rather than leaving the general-purpose pprof debug endpoints open.

## Proof of Concept
```
GET /plugins/<registered-plugin-name>/debug/pprof/heap HTTP/1.1
Host: <node-host>:<port>
```
No `Cookie`, API token header, or session is required. `pluginPPROFHandler` (`core/web/loop_registry.go:150-166`) forwards the request unauthenticated to the internal LOOP plugin process at `http://<loopHostName>:<PrometheusPort>/debug/pprof/heap` and returns the heap profile bytes directly to the caller. This can be verified with an integration test that spins up `NewRouter` with a registered LOOP plugin and issues the above request without any `Authorization`/session cookie, asserting a `200 OK` with pprof profile data returned.

```go
func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/metrics", l.loopHostName, p.EnvCfg.PrometheusPort)
	req, err := http.NewRequestWithContext(gc.Request.Context(), http.MethodGet, pluginURL, nil)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)
	if err != nil {
		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q metrics", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}
```

```go
func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
```
