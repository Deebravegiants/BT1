### Title
External Initiator `OutgoingToken` secret is disclosed to any authenticated node API caller via the initiator list endpoint - (File: `core/web/external_initiators_controller.go`)

### Summary
The croc advisory describes a secret (or fragments of it) being handed to a component that should never see it — an untrusted relay — because the value was folded into a piece of metadata (the room name) that gets sent over the wire. In this codebase, the same bug class (CWE-200, unnecessary disclosure of a security-relevant secret to a party that should not receive it) exists in the `ExternalInitiatorsController.Index` handler and its presenter, which returns the `OutgoingToken` credential — meant only for authenticating outbound webhook calls the node itself makes to a third-party URL — to any caller who can list external initiators via `GET /v2/external_initiators`.

### Finding Description
`bridges.NewExternalInitiator` generates two secrets when an External Initiator (EI) is registered: `OutgoingToken` and `OutgoingSecret`, both created with `utils.NewSecret(utils.DefaultSecretSize)`. [1](#0-0) 

These credentials are intended to be used only once, at creation time, to let the operator configure the corresponding external service — analogous to a "shared secret" that should never be echoed back through a channel other components/observers can read.

However, `ExternalInitiatorResource` (used by the `Index`/list endpoint, not just the one-time `Create` response) also carries `OutgoingToken`: [2](#0-1) 

And `ExternalInitiatorsController.Index` serializes every stored EI record — including `OutgoingToken` — for any request hitting `GET /v2/external_initiators`: [3](#0-2) [4](#0-3) 

This is confirmed by the test suite, which explicitly asserts that `OutgoingToken` is present in the paginated Index response body: [5](#0-4) 

Unlike the one-time `Create` response — where returning the freshly generated secret to its creator is expected and unavoidable — the `Index` (list) endpoint re-exposes this secret indefinitely to *every* caller that can reach the route, not just the party that originally created the EI. This mirrors the croc root cause: a secret value that should stay confined to the two legitimate parties (chainlink node ↔ specific external initiator) is instead persistently exposed through a generic, repeatedly-queryable channel (the initiator listing API), which functions here like the "untrusted relay" in the original bug — any authenticated caller with access to this route, not the intended recipient alone, can retrieve it.

### Impact Explanation
`OutgoingToken` (together with `OutgoingSecret`, sent in headers by the node when POSTing job-run notifications to the EI's configured URL) is the credential the external initiator's webhook endpoint uses to verify that a request genuinely originated from this Chainlink node. Disclosure of `OutgoingToken` to a party other than the intended external initiator operator allows that party to impersonate the node when calling the external initiator's own webhook, or to correlate/spoof legitimate node-to-EI traffic, undermining the authenticity guarantee the outgoing token/secret pair exists to provide (impact rating: Low/Medium — matches CVSS C:L of the source advisory).

### Likelihood Explanation
Any user capable of calling `GET /v2/external_initiators` — a routine, repeatable read-only API — receives the token for every registered EI, not only the one they created. Given External Initiators are typically registered once at setup and rarely rotated, and the Index endpoint is designed for general listing/inventory purposes, the secret is very likely to be exposed to a broader set of API consumers (e.g., other node operators/team members with read-level API access, monitoring integrations, etc.) than intended over the life of the credential.

### Recommendation
Do not include `OutgoingToken` (or any equivalent outgoing secret) in `ExternalInitiatorResource`/`Index` responses. Return it only once, at creation time, in the `ExternalInitiatorAuthentication` response (as is already done for `AccessKey`/`Secret`/`OutgoingSecret`), and omit or mask it from all subsequent list/read operations. If operators need to confirm the value later, provide a regenerate-and-redisplay-once flow instead of persisting it in a listable resource.

### Proof of Concept
1. Register an External Initiator: `POST /v2/external_initiators {"name":"foo","url":"http://example.com"}` → response includes `outgoingToken` (expected, one-time).
2. As any user/service able to hit `GET /v2/external_initiators?size=50`, observe that the response for `foo` (and every other registered EI) again contains its `outgoingToken` value, as demonstrated by the assertions in `core/web/external_initiators_controller_test.go:104-126` where `externalInitiators[0].OutgoingToken` is checked against the originally created value on every list call.

// NewExternalInitiator generates an ExternalInitiator from an
// auth.Token, hashing the password for storage
func NewExternalInitiator(
	eia *auth.Token,
	eir *ExternalInitiatorRequest,
) (*ExternalInitiator, error) {
	salt := utils.NewSecret(utils.DefaultSecretSize)
	hashedSecret, err := auth.HashedSecret(eia, salt)
	if err != nil {
		return nil, pkgerrors.Wrap(err, "error hashing secret for external initiator")
	}

	return &ExternalInitiator{
		Name:           strings.ToLower(eir.Name),
		URL:            eir.URL,
		AccessKey:      eia.AccessKey,
		HashedSecret:   hashedSecret,
		Salt:           salt,
		OutgoingToken:  utils.NewSecret(utils.DefaultSecretSize),
		OutgoingSecret: utils.NewSecret(utils.DefaultSecretSize),
	}, nil
}

func (eic *ExternalInitiatorsController) Index(c *gin.Context, size, page, offset int) {
	ctx := c.Request.Context()
	externalInitiators, count, err := eic.App.BridgeORM().ExternalInitiators(ctx, offset, size)
	resources := make([]presenters.ExternalInitiatorResource, 0, len(externalInitiators))
	for _, initiator := range externalInitiators {
		resources = append(resources, presenters.NewExternalInitiatorResource(initiator))
	}

	paginatedResponse(c, "externalInitiators", size, page, resources, count, err)
}

func (o *orm) ExternalInitiators(ctx context.Context, offset int, limit int) (initiators []ExternalInitiator, count int, err error) {
	err = o.transact(ctx, true, func(tx *orm) error {
		if err = tx.ds.GetContext(ctx, &count, "SELECT COUNT(*) FROM external_initiators"); err != nil {
			return pkgerrors.Wrap(err, "ExternalInitiators failed to get count")
		}

		sql := `SELECT * FROM external_initiators ORDER BY name asc LIMIT $1 OFFSET $2;`
		if err = tx.ds.SelectContext(ctx, &initiators, sql, limit, offset); err != nil {
			return pkgerrors.Wrap(err, "ExternalInitiators failed to load external_initiators")
		}
		return nil
	})
	return
}
