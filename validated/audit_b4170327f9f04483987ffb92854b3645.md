### Title
Excess native ETH sent to an LI.FI swap can be permanently trapped in `ExternalActionSwap` when the router refunds unspent value - ([File: contracts/external-actions/swaps/LifiExternalAction.sol])

### Summary
`LifiExternalAction.callRouter` forwards the entire `inputAmount` of native ETH to an external, arbitrary-calldata router call, but only measures the balance change of `outputToken` before/after the call. If the router does not consume all of the forwarded ETH (e.g. it refunds unspent value back to the caller, which is this same contract), the leftover native ETH is never detected, never swept, and never returned to the depositor — it is stranded in the contract, mirroring the H-3 "leak ETH to WETH" pattern where excess deposited value is not recovered after an exact-out/partial-fill trade.

### Finding Description
`ExternalActionSwap.swap()` computes `inputAmount` from the user/circuit-committed `deltaAmounts[0]` and calls `callRouter`, which for `LifiExternalAction` does: [1](#0-0) 

Only `outputToken`'s balance is snapshotted before/after the router call; the input token/ETH balance of the contract is never checked. `swap()` then computes `swappedAmount` purely from that output-token delta, deducts fees, and forwards `amountToSendToHinkal` of the **output** token back to `msg.sender` (the `Hinkal` contract): [2](#0-1) 

Any residual native ETH left in `ExternalActionSwap` after the router call (e.g. because the router's calldata specifies an amount lower than what was forwarded as `msg.value`, or the router refunds excess ETH to `msg.sender`, a common failure/refund path for aggregators) is not accounted for anywhere in this flow: it isn't part of `outputToken`'s balance, isn't part of the UTXO created, and isn't swept back to the user.

Crucially, `Hinkal.sol`'s balance equation only checks the *Hinkal contract's* own balance delta against `amountChanges`/UTXO sums — it never inspects what happens to funds once they leave Hinkal and enter the external action contract: [3](#0-2) 

`_externalTransact` transfers exactly `deltaAmountChanges[i]` (the committed input amount) from `Hinkal` to the external action address before calling `runAction`, so the full committed input value is delivered to `ExternalActionSwap`: [4](#0-3) 

There is no logic in `ExternalActionSwap`/`LifiExternalAction` to detect or recover any unspent portion of the input ETH after `callRouter` returns, unlike the analogous check done for `outputToken`. This breaks the equality "value forwarded into the external action == value the external action returns to Hinkal + value consumed by the swap": any leftover stays permanently in the `ExternalActionSwap` contract, inaccessible to the depositor, the relay, or any subsequent Hinkal transaction (there is no sweep/rescue function and no accounting that would let a legitimate withdraw pick it up).

### Impact Explanation
This results in permanent freezing of user funds: the ETH committed by the depositor (as `deltaAmounts[0]`, verified by the zk proof and part of the balance equation on the Hinkal side) is fully removed from the shielded pool, but if the router does not consume 100% of the forwarded `msg.value`, the unconsumed remainder is not returned to the user, not credited as a UTXO, and not recoverable through any subsequent Hinkal or external-action code path. This matches the "permanent freezing of user funds" impact category.

### Likelihood Explanation
This requires only an unprivileged EOA to submit a normal swap with ETH as `inputToken`. It depends on the LI.FI router's actual behavior for the constructed calldata (whether it refunds unspent native value or otherwise doesn't consume the full amount, which is a documented pattern for bridge/aggregator calls with variable gas/fee estimation, and can also be forced by supplying calldata matching a *lower* amount than the value transferred alongside it). It does not require any admin/owner privileges, malicious relayer, or oracle assumptions — it is a straightforward consequence of only tracking `outputToken` balance instead of also tracking/recovering unspent `inputToken` (ETH) balance.

### Recommendation
In `LifiExternalAction.callRouter` (and any future ETH-input `ExternalActionSwap` variant), snapshot the ETH balance before the router call as well, and after the call refund/re-forward any residual ETH balance back to `msg.sender` (Hinkal) so it can be accounted for as part of the swap UTXO/balance equation, exactly as recommended in the referenced report for the exact-out ETH-to-WETH case: never let value sent out for an external call go untracked on the way back.

### Proof of Concept
1. A user deposits ETH into Hinkal and calls `transact` with `externalActionId` pointing at `LifiExternalAction`, with `inputToken = address(0)` and `deltaAmounts[0] = -X` (so `X` ETH is transferred from `Hinkal` to `LifiExternalAction`).
2. `Hinkal._externalTransact` sends the full `X` ETH to `LifiExternalAction` and calls `runAction` → `swap` → `callRouter`.
3. `callRouter` forwards `X` ETH as `msg.value` together with `externalActionMetadata` calldata built for the LI.FI router. Suppose the router's route only requires `X - δ` ETH (e.g. due to fee/slippage buffers or a route that ends up using less than the max quoted amount) and refunds `δ` ETH back to `msg.sender` (`LifiExternalAction`).
4. `callRouter` only measures `outputToken` balance delta, so `swappedAmount` is computed correctly for `outputToken`, but the refunded `δ` ETH is now sitting in `LifiExternalAction`'s balance with no code path that references or moves it.
5. `swap()` sends `outputToken` proceeds back to Hinkal and creates a UTXO for `outputToken` only; the `δ` ETH is never included in any UTXO, never returned to the user, and remains permanently locked in the `ExternalActionSwap` contract.

Note: full confirmation of exact router refund behavior would require inspecting the specific LI.FI diamond/router integration parameters used off-chain to build `externalActionMetadata`, which are not part of this repository; the on-chain code path itself, however, demonstrably provides no mechanism to detect or recover unspent native input value.

    function callRouter(
        address inputToken,
        uint256 inputAmount,
        address outputToken,
        bytes calldata externalActionMetadata
    ) internal override returns (uint256 swappedAmount) {
        uint256 balanceBefore = getERC20OrETHBalance(outputToken);

        if (inputToken == address(0)) {
            (bool success, ) = router.call{value: inputAmount}(
                externalActionMetadata
            );
            require(success, "LI.FI swap failed: native coin");
        } else {
            approveUnlimited(inputToken, router);
            (bool success, ) = router.call(externalActionMetadata);
            require(success, "LI.FI swap failed: erc-20 token");
        }

        swappedAmount = getERC20OrETHBalance(outputToken) - balanceBefore;
    }

    function swap(
        CircomData calldata circomData,
        int256[] calldata deltaAmounts
    ) internal returns (UTXO[] memory utxoSet) {
        address inputToken = circomData.erc20TokenAddresses[0];
        uint256 inputAmount = uint256(-deltaAmounts[0]);

        if (inputToken == circomData.feeStructure.feeToken) {
            inputAmount -= circomData.feeStructure.flatFee;
        }

        address outputToken = circomData.erc20TokenAddresses[1];

        require(
            circomData.slippageValues[1] != 0,
            "swap output slippage floor not set"
        );

        require(
            block.timestamp <= circomData.timeStamp + SWAP_DEADLINE_WINDOW,
            "swap expired"
        );

        uint256 swappedAmount = callRouter(
            inputToken,
            inputAmount,
            outputToken,
            circomData.externalActionData.externalActionMetadata
        );

        uint256 relayFee = circomData.feeStructure.flatFee;

        uint256 hinkalFee = hinkalHelper.calculateRelayFee(
            swappedAmount,
            0,
            circomData.feeStructure.variableRate
        );

        if (circomData.feeStructure.feeToken == outputToken) {
            sendToRelay(circomData.relay, relayFee + hinkalFee, outputToken);
        } else {
            sendToRelay(
                circomData.relay,
                relayFee,
                circomData.feeStructure.feeToken
            );
            sendToRelay(circomData.relay, hinkalFee, outputToken);
        }

        uint256 totalFee = hinkalFee +
            (outputToken == circomData.feeStructure.feeToken ? relayFee : 0);
        uint256 amountToSendToHinkal = swappedAmount - totalFee;

        transferERC20TokenOrETH(outputToken, msg.sender, amountToSendToHinkal);

        utxoSet = new UTXO[](1);
        utxoSet[0] = UTXO({
            amount: amountToSendToHinkal,
            erc20Address: outputToken,
            stealthAddressStructure: circomData.stealthAddressStructure,
            timeStamp: block.timestamp
        });
    }
