## Analog Vulnerability Found

### Title
Users can place and escrow intent orders against an unregistered destination `stateMachineId`, permanently freezing funds - (File: `evm/src/apps/IntentGatewayV2.sol` / `evm/src/apps/intentsv2/ExtrinsicIntents.sol`)

### Summary
`placeOrder` escrows a user's input tokens for an `Order` whose `destination` field is an arbitrary, caller-supplied `bytes` state-machine identifier. Neither `placeOrder` nor `IntentGatewayV2` validates that a peer `IntentGateway` instance is actually registered (`_instances[keccak256(stateMachineId)]`) for that destination before accepting escrow. This mirrors the reported Derby bug class: a user-facing entry point accepts an unvalidated "vault/route number" and locks value against it before any check that the target actually exists.

### Finding Description
`placeOrder` in `evm/src/apps/IntentGatewayV2.sol` accepts `order.destination` as raw bytes with no lookup against `_instances`: [1](#0-0) 

The only place `order.destination` is resolved to a registered gateway address is later, inside cancel/fill flows, via `_instance()`: [2](#0-1) 

`_instance` reverts with `UnknownInstance` whenever `_instances[keccak256(stateMachineId)] == address(0)`. Critically, the **source-chain cancellation path** (`_cancelFromSource`, the only recovery path a user can invoke without cooperation from the fictitious destination chain) also calls `_instance(order.destination)` to build the storage-proof key: [3](#0-2) 

Because `placeOrder` never checks `_instances[keccak256(order.destination)]` before escrowing tokens, a user (or a buggy/malicious frontend/SDK integration) can place an order with a `destination` that has no registered `IntentGateway` peer deployment. The order's tokens are escrowed (`_orders[commitment][token] = amount`) exactly as in a legitimate order: [4](#0-3) 

Since no such destination gateway exists, no solver can ever produce a valid `_fillCrossChain` settlement referencing this destination, and the only self-service recovery route, `_cancelFromSource`, unconditionally reverts with `UnknownInstance` the moment it tries to resolve `order.destination`. `_cancelFromDest` is unreachable because it must be invoked on the (non-existent/unregistered) destination chain itself.

### Impact Explanation
This results in permanent freezing of user funds: escrowed input tokens (and any collected solver fees) become unrecoverable because (1) no solver can legitimately fill an order for an unregistered destination, and (2) the built-in cancellation/refund mechanism (`_cancelFromSource`) itself depends on `_instance(order.destination)` resolving successfully, which is guaranteed to fail for the same reason the order was bogus in the first place. This satisfies the "permanent freezing of funds" bar for Medium/High severity, directly analogous to the referenced report where users could lock tokens against a non-existent vault number with no recovery path and lost potential value.

### Likelihood Explanation
Reachable from a single unprivileged `placeOrder` transaction with attacker- or user-controlled `order.destination` bytes — no special privileges required. This can occur accidentally (typo/misconfigured destination identifier from an integrator or malformed frontend input) or be triggered deliberately to grief a specific counterparty/beneficiary's escrow, since `placeOrder` performs no destination-liveness check prior to moving funds into escrow.

### Recommendation
In `placeOrder`, validate `order.destination` against the registered peer set (e.g., call `_instance(order.destination)` — or a non-reverting variant — and revert early with a clear error, such as `UnknownInstance`, if no gateway is registered for that state machine) before transferring/escrowing any tokens. This prevents an order from ever entering an unrecoverable state and fails fast for the user instead of after funds are locked.

### Proof of Concept
1. Deploy `IntentGatewayV2` with peers registered only for `EVM-1` and `EVM-42161` (per `initialize`'s `peerChains`).
2. Call `placeOrder(order, graffiti)` with `order.destination = abi.encodePacked("EVM-999999")` (an unregistered/fictitious state machine) and valid `order.inputs`.
3. Observe tokens are escrowed successfully (`_orders[commitment][token]` populated), as in `evm/tests/foundry/IntentGatewayV2Test.sol` order-placement tests which use arbitrary `destination: abi.encodePacked("DEST_CHAIN")` values with no destination-registration check enforced by `placeOrder`.
4. No solver can call `fillOrder` for this destination because no corresponding `IntentGatewayV2` deployment authenticates to it.
5. Attempt `cancelOrder` from the source chain: `_cancelFromSource` calls `_instance(order.destination)`, which reverts with `UnknownInstance` since `_instances[keccak256("EVM-999999")] == address(0)`. The escrowed funds cannot be refunded through any code path.

    /**
     * @dev Resolves the IntentGateway instance address for a given state machine.
     * Reverts with `UnknownInstance` if no remote deployment has been registered for that chain.
     * @param stateMachineId The raw state machine identifier bytes.
     * @return The gateway address for the given state machine.
     */
    function _instance(bytes calldata stateMachineId) internal view returns (address) {
        address gateway = _instances[keccak256(stateMachineId)];
        if (gateway == address(0)) revert UnknownInstance();
        return gateway;
    }

    function _cancelFromSource(Order calldata order, CancelOptions calldata options, bytes32 commitment) internal {
        if (order.user != bytes32(uint256(uint160(msg.sender)))) revert Unauthorized();

        if (options.height <= order.deadline) revert NotExpired();

        uint256 inputsLen = order.inputs.length;
        for (uint256 i; i < inputsLen;) {
            if (_orders[commitment][address(uint160(uint256(order.inputs[i].token)))] == 0) revert UnknownOrder();

            unchecked {
                ++i;
            }
        }

        bytes memory context =
            abi.encode(WithdrawalRequest({commitment: commitment, tokens: order.inputs, beneficiary: order.user}));

        bytes[] memory keys = new bytes[](1);
        keys[0] = bytes.concat(abi.encodePacked(_instance(order.destination)), _calculateCommitmentSlotHash(commitment));
        DispatchGet memory request = DispatchGet({
            dest: order.destination,
            keys: keys,
            timeout: 0,
            height: options.height,
            fee: options.relayerFee,
            context: context,
            payer: msg.sender
        });

        address hostAddr = host();
        if (msg.value > 0) {
            IDispatcher(hostAddr).dispatch{value: msg.value}(request);
        } else {
            dispatchWithFeeToken(request);
        }
    }
