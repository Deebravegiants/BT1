### Title
Bonding curve buy AND sell can both be permanently frozen for a token by a single reverting call to the paired LT's `exchangeRate()` - ([File: packages/contracts/src/Bonding.sol])

### Summary
The SkyWalking-NodeJS advisory describes a service becoming completely unavailable when a single external dependency (the OAP backend) is unhealthy, because the agent's health-check path has no fallback and every request path depends on that one connection. Alt.fun has the same single-point-of-failure shape: `Bonding.canGraduate()` makes a mandatory external call to the paired LT's `exchangeRate()` [1](#0-0)  and that same function is invoked unconditionally on *both* the buy path and the sell path — there is no fallback and no way to skip it, so a single unhealthy/reverting LT call disables trading on both sides of the market for that token, unlike the "sell-only market" degradation the protocol explicitly designed for the mint-pause case.

### Finding Description
`canGraduate(token_)` reads `IPair(pair).tokenBalance()`; if that is non-zero (true for essentially every actively-trading curve) it unconditionally calls `IBounceLeveragedToken(info.ltAddress).exchangeRate()` [2](#0-1) .

This call is on the **hot path of every buy and every sell**, not just graduation:

- `Bonding.buy()` → `_executeBuy()` calls `canGraduate(tokenAddress)` immediately after every successful curve buy, and enters graduation if true [3](#0-2) . If `exchangeRate()` reverts, the whole buy transaction reverts (USDC pulled and LT minted are rolled back, but the trade never lands).
- `Bonding.sell()` calls `canGraduate(tokenAddress)` *before* executing the sell, specifically to prevent a curve sell from un-ripening a graduatable token [4](#0-3) . If `exchangeRate()` reverts here, the sell transaction reverts too.
- `Zap._sellInternal()` independently calls `bonding_.canGraduate(tokenAddress)` before routing to `_sellOnCurve`/`_sellOnUniswapV2` [5](#0-4) , so even a Zap-level sell attempt inherits the same dependency.

The protocol's own design notes acknowledge and explicitly *accept* an asymmetric DoS: if BounceTech pauses **minting** on the LT, buys revert but sells keep working via `redeem()`, framed as "a sell-only market is preferable to freezing both sides" [6](#0-5) . That design intent is silently broken by the `canGraduate()`/`exchangeRate()` dependency: since `exchangeRate()` is a *separate* external call from `mint()`/`redeem()`, and it is invoked unconditionally on the sell path too, any condition that makes the LT's `exchangeRate()` view revert (e.g., BounceTech pausing the whole contract including views, an underlying price-feed becoming stale/reverting inside `exchangeRate()`, or BounceTech's `GlobalStorage`/oracle wiring failing) freezes **both** buy and sell simultaneously — precisely the "freeze both sides" outcome the protocol says it wants to avoid.

There is no owner/admin bypass for `canGraduate()`, no cached/stale-tolerant fallback, and no way for `Bonding.sell()` or `Zap.sell()` to proceed without this call succeeding. `triggerGraduation()` (the permissionless escape hatch) also depends on the same `canGraduate()` call and thus offers no help [7](#0-6) . The protocol's own "Retired LTs" note only discusses the case where `exchangeRate()` keeps returning stale-but-valid data, not the case where the call reverts outright.

### Impact Explanation
Every trader and the token creator holding tokens/curve position for a token whose paired LT's `exchangeRate()` reverts is completely locked in: they cannot buy more, cannot sell to exit, and cannot force graduation (since that path also needs the same call to succeed). Their curve-side capital (LT and unsold tokens sitting in the `Pair`) is stuck with no exit route until the LT's `exchangeRate()` call recovers, which is outside the protocol's control since the LT is BounceTech's external contract. This is a permanent-freezing-of-funds condition until an external dependency heals, worse than the protocol's own accepted worst case ("sell-only market").

### Likelihood Explanation
This requires the paired LT's `exchangeRate()` to revert — a condition entirely controlled by the external BounceTech LT (e.g., a pause covering view functions, an oracle failure inside the LT's rate computation, or a BounceTech-side operational incident). Since `Bonding.launch()` accepts any LT registered in BounceTech's `Factory.ltExists` [8](#0-7) , and the protocol has no control over BounceTech's operational health, this is a realistic dependency-availability risk rather than a purely theoretical one, and it is not mitigated anywhere in the reachable contract code.

### Recommendation
Add a fallback/circuit-breaker so that a reverting `exchangeRate()` call cannot block the sell path: e.g., wrap the `exchangeRate()` call in `canGraduate()` in a low-level `staticcall` with try/catch semantics and treat a revert as "not graduatable" (defer only the USD-trigger leg, not the sell itself), so `Bonding.sell()`/`Zap.sell()` can still execute the actual sell even when the graduation-check leg is unavailable. At minimum, decouple the sell-side "don't un-ripen a graduatable token" guard from a hard dependency on a live external call succeeding.

### Proof of Concept
1. Launch a token against a mock/real LT via `Zap.createToken` and buy enough via `Zap.buy` so `IPair(pair).tokenBalance() != 0` (curve not fully sold) and the token is not yet graduated.
2. Cause the paired LT's `exchangeRate()` to revert (in tests: `vm.mockCallRevert(address(lt), abi.encodeWithSelector(IBounceLeveragedToken.exchangeRate.selector), "")`, modeling a paused/unhealthy BounceTech LT).
3. Call `Zap.buy(tokenAddr, ...)` — reverts inside `_executeBuy` → `canGraduate` → `exchangeRate()`.
4. Call `Zap.sell(tokenAddr, ...)` — reverts inside `Bonding.sell` → `canGraduate` → `exchangeRate()` (also reachable directly via `Bonding.sell`, see `test_sell_revertsWhenGraduatable` pattern at [9](#0-8)  which shows `canGraduate` is unconditionally evaluated on the sell path).
5. Both buy and sell now permanently revert for this token until the external LT's `exchangeRate()` call stops reverting — funds on the curve are frozen with no exit, contradicting the "sell-only market" fallback the codebase documents for the mint-pause scenario.

    function canGraduate(
        address token_
    ) public view returns (bool) {
        BondingStorage storage $ = _s();
        TokenInfo storage info = $.tokenInfo[token_];
        if (info.creator == address(0)) return false;
        if (info.lifecycle != Lifecycle.Curve) return false;

        address pair = info.pair;
        if (IPair(pair).tokenBalance() == 0) return true;

        (, uint256 assetReserve) = IPair(pair).getReserves();
        uint256 realLtRaised = assetReserve - _launchTimeVirtualLtReserve(token_, pair);
        uint256 valueUsd = (realLtRaised * IBounceLeveragedToken(info.ltAddress).exchangeRate()) / 1e18;
        return valueUsd >= $.graduationThresholdUsd;
    }
