### Title
Uniswap V4 spot price used as unguarded/weakly-guarded oracle for Simplex FX pricing and LP-funding sizing enables flashloan price manipulation - (File: sdk/packages/simplex/src/funding/uniswapV4/UniswapV4FundingPlanner.ts)

### Summary
Simplex's Uniswap V4 "pool-based pricing" venue prices curveless FX pairs directly from the live pool spot price (`sqrtPriceX96`), which is the same class of manipulable on-chain state as the `getSupplyProportion`/`balanceOf` pattern in the referenced USSD report. The deviation guard that is supposed to protect against this is optional and, even when configured, only checks against a static reference price rather than execution cost/impact, and the price used has no time-weighting whatsoever.

### Finding Description
`UniswapV4FundingPlanner.getExoticTokenPrice` picks the most-liquid position for the requested exotic token and calls `computeDirectPoolPriceUsd`, which returns `sdkPool.token0Price`/`token1Price` — a value derived straight from the pool's current `sqrtPriceX96` read via `getSlot0` in `UniswapV4LiquidityState.refresh()`: [1](#0-0) [2](#0-1) [3](#0-2) 

This price is the sole oracle for pairs configured without static bid/ask curves ("Pool-Based Pricing"), used both to quote a fill and to size the amount of liquidity withdrawn from the solver's LP position to fund it: [4](#0-3) 

The documented flow confirms there is no TWAP and no execution-impact/fee adjustment on this path: [5](#0-4) 

The only mitigation is an optional `referencePrice`/`maxDeviationBps` guard, explicitly documented as optional ("omit both to leave the chain unguarded") and only bounding deviation from a static reference, not execution cost: [6](#0-5) 

This mirrors the reported USSD bug class exactly: an unprivileged actor can move an AMM pool's instantaneous state (there, token balances; here, `sqrtPriceX96`) via a flashloan swap immediately before submitting/triggering pricing, causing the protocol to read a manipulated, momentarily-skewed price rather than a manipulation-resistant one (TWAP/oracle).

### Impact Explanation
Any external actor can submit a swap (flashloan-funded or otherwise) against the exact Uniswap V4 pool the solver's `[vault.uniswapV4]` position tracks, moving `sqrtPriceX96` in one direction, then immediately submit (or have relayed) an intent order that gets quoted/filled against `getExoticTokenPrice`. Because `computeLegPolicyOutput` linearly extends the manipulated mid-price across the full order size with no depth/impact term, the attacker can force the solver to (a) quote/fill at a price far from fair value, extracting value from the solver's inventory, and/or (b) trigger `planWithdrawalForToken` to withdraw more LP liquidity than the true market price would justify, directly depleting the solver's on-chain LP position. Where no `referencePrice`/`maxDeviationBps` guard is configured (an explicitly supported, "unguarded" configuration), there is no bound on the manipulation at all. This is a concrete theft-of-funds vector against solver capital reachable from a single unprivileged submitted order plus an ordinary DEX swap — no privileged role required.

### Likelihood Explanation
High for any solver operator who enables Uniswap V4 pool-based pricing (a documented, first-class configuration) without setting the optional guard, or who sets a guard with a deviation band wide enough to preserve normal price movement — the same band an attacker can walk the price to and hold via flashloan for one block/transaction. The attack requires only capital (flashloanable) and knowledge of the configured position/pool, both discoverable on-chain and from filler configuration norms documented publicly.

### Recommendation
Replace or supplement the raw `sqrtPriceX96`-derived spot price with a manipulation-resistant reference: a Uniswap V4 truncated-oracle/TWAP observation over a meaningful window, or an external oracle (Chainlink, etc.), before using it in `computeDirectPoolPriceUsd`. Make the `referencePrice`/`maxDeviationBps` guard mandatory rather than optional for any pair relying on pool-based pricing, and extend the guard to also bound the size/impact of the quoted amount relative to available on-chain liquidity, not just deviation from a static reference.

### Proof of Concept
1. Attacker identifies a solver running Simplex with `[vault.uniswapV4]` pool-based pricing configured for an exotic/stable pair, with no `referencePrice`/`maxDeviationBps` guard (or a loose one).
2. Attacker flashloans stable/exotic tokens and executes a large swap against the same Uniswap V4 pool the solver's position/`getExoticTokenPrice` reads (`UniswapV4LiquidityState.refresh` → `getSlot0`), pushing `sqrtPriceX96` far from the fair-market price.
3. In the same block/near-immediately, attacker submits an intent order priced via the curveless pair; `FXFiller` calls `getExoticTokenPrice` → `computeDirectPoolPriceUsd`, which returns the manipulated price, and `computeLegPolicyOutput`/`planWithdrawalForToken` size the fill and LP withdrawal off that skewed price.
4. Attacker reverses the initial swap (repaying the flashloan) after the solver's fill executes, having received the exotic/stable output at a rate far better than the pool's true price, at the solver's expense — draining the solver's wallet/LP inventory.

	async getExoticTokenPrice(chain: string, exoticToken: string): Promise<Decimal | null> {
		const state = this.stateByChain.get(chain)
		if (!state || !state.isHydrated()) return null

		try {
			await state.refresh()
		} catch (err) {
			this.logger.error({ err, chain }, "Failed to refresh state for price query")
			return null
		}

		const tokenLower = exoticToken.toLowerCase()
		let bestPrice: Decimal | null = null
		let bestLiquidity = 0n

		for (const pos of state.allPositions()) {
			if (pos.currency0.toLowerCase() !== tokenLower && pos.currency1.toLowerCase() !== tokenLower) continue
			const sdkPool = state.getSdkPool(pos.tokenId)
			if (!sdkPool) continue

			const result = this.computeDirectPoolPriceUsd(pos, sdkPool, chain)
			if (result && result.exoticToken.toLowerCase() === tokenLower) {
				const poolLiquidity = state.getPoolLiquidity(pos.tokenId)
				if (poolLiquidity > bestLiquidity) {
					bestPrice = result.priceUsd
					bestLiquidity = poolLiquidity
				}
			}
		}

		if (bestPrice) {
			this.logger.debug({ chain, token: tokenLower, priceUsd: bestPrice.toString() }, "Exotic token price computed")
		}
		return bestPrice
	}

	private computeDirectPoolPriceUsd(
		pos: HydratedV4Position,
		sdkPool: V4Pool,
		chain: string,
	): { exoticToken: string; priceUsd: Decimal } | null {
		const usdc = this.configService.getUsdcAsset(chain).toLowerCase()
		const usdt = this.configService.getUsdtAsset(chain).toLowerCase()
		const c0 = pos.currency0.toLowerCase()
		const c1 = pos.currency1.toLowerCase()

		if (c0 === usdc || c0 === usdt) {
			// currency0 is stable → exotic is currency1
			// token1Price = "token0 per token1" = USD per exotic
			return {
				exoticToken: c1,
				priceUsd: new Decimal(sdkPool.token1Price.toFixed(18)),
			}
		}

		if (c1 === usdc || c1 === usdt) {
			// currency1 is stable → exotic is currency0
			// token0Price = "token1 per token0" = USD per exotic
			return {
				exoticToken: c0,
				priceUsd: new Decimal(sdkPool.token0Price.toFixed(18)),
			}
		}

		return null
	}

	async refresh(): Promise<void> {
		const client = this.clientManager.getPublicClient(this.chain)
		const chainId = chainIdFromIdentifier(this.chain)

		// Group positions by poolId to avoid duplicate pool state fetches
		const poolIds = new Set(this.tokenIdToPoolId.values())

		// Fetch slot0 + liquidity for each unique pool via StateView
		const poolStateMap = new Map<string, { sqrtPriceX96: bigint; tick: number; poolLiquidity: bigint }>()

		for (const poolId of poolIds) {
			const [slot0Result, poolLiquidity] = await Promise.all([
				client.readContract({
					address: this.stateView,
					abi: UNISWAP_V4_STATE_VIEW_ABI,
					functionName: "getSlot0",
					args: [poolId as HexString],
				}) as Promise<[bigint, number, number, number]>,
				client.readContract({
					address: this.stateView,
					abi: UNISWAP_V4_STATE_VIEW_ABI,
					functionName: "getLiquidity",
					args: [poolId as HexString],
				}) as Promise<bigint>,
			])

			poolStateMap.set(poolId, {
				sqrtPriceX96: slot0Result[0],
				tick: slot0Result[1],
				poolLiquidity,
			})
		}

		// Refresh per-position liquidity and rebuild SDK Pool objects
		for (const pos of this.positions.values()) {
			const key = pos.tokenId.toString()
			const poolId = this.tokenIdToPoolId.get(key)
			const poolState = poolId ? poolStateMap.get(poolId) : undefined
			if (!poolId || !poolState) {
				throw new Error(
					`UniswapV4 refresh: missing pool state for tokenId ${key} (poolId=${poolId ?? "undefined"})`,
				)
			}

			// Read current position liquidity
			const liquidity = (await client.readContract({
				address: pos.positionManager,
				abi: UNISWAP_V4_POSITION_MANAGER_ABI,
				functionName: "getPositionLiquidity",
				args: [pos.tokenId],
			})) as bigint

			pos.liquidity = liquidity
			const prevOnChain = this.lastOnChainLiquidity.get(key) ?? liquidity
			const decrease = prevOnChain > liquidity ? prevOnChain - liquidity : 0n
			const prevConsumed = this.consumed.get(key) ?? 0n
			const newConsumed = prevConsumed > decrease ? prevConsumed - decrease : 0n
			this.consumed.set(key, newConsumed)
			this.lastOnChainLiquidity.set(key, liquidity)
			pos.remainingLiquidity = liquidity > newConsumed ? liquidity - newConsumed : 0n
			pos.sqrtPriceX96 = poolState.sqrtPriceX96
			pos.currentTick = poolState.tick

			// Build SDK Pool (without tick data provider — we only need amount calcs)
			const currency0 = currencyFromHydratedDecimals(chainId, pos.currency0, pos.decimals0)
			const currency1 = currencyFromHydratedDecimals(chainId, pos.currency1, pos.decimals1)

			const sdkPool = new V4Pool(
				currency0,
				currency1,
				pos.fee,
				pos.tickSpacing,
				pos.hooks,
				poolState.sqrtPriceX96.toString(),
				poolState.poolLiquidity.toString(),
				poolState.tick,
			)

## Pool-Based Pricing

When **`[vault.uniswapV4]`** lists at least one position, cross-asset pairs without curves derive bid/ask prices from **Uniswap V4 pool state** (current tick). The pool acts as the price oracle instead of a static curve. Note this yields a **single** price used in both directions — a venue-priced pair has no bid/ask spread of its own, so its margin comes from `order.fees` alone.

With Uniswap V4 positions configured, you can **omit** `bidPriceCurve` and `askPriceCurve` on the pair. Pool pricing requires the pair's `token0` to be a USD stablecoin, and same-token pairs always need their curve. The optional **`spreadBps`** field (basis points) sets the slippage tolerance for on-chain LP redemptions; defaults to `50` (0.50%).

Uniswap V4 venue pricing uses pools that pair the exotic token with **USDC or USDT** (addresses from your chain config). When multiple positions exist for the same exotic token on a chain, the most-liquid qualifying pool's price is used.

## Uniswap price guards

Pool-based pricing trusts the live pool, which leaves the solver exposed to a manipulated, stale, or thin pool returning a bad quote. To bound that risk, give a position a **`referencePrice`** and **`maxDeviationBps`**. Whenever the pool quote on that chain drifts more than `maxDeviationBps` above or below the reference, the solver refuses to fill — the order is rejected before any bid is submitted.

`referencePrice` is expressed in **exotic tokens per USD**, the same units as the bid/ask curves. The two fields must be set together; omit both to leave the chain unguarded.

```toml lineNumbers
[vault.uniswapV4]
# referencePrice is the expected cNGN per USD;
# reject if the quote is more than 2% off.
# The two go together — one without the other is rejected.
[[vault.uniswapV4.positions]]
chain           = "EVM-8453"
tokenId         = "2087350"
referencePrice  = "1575"
maxDeviationBps = 200
```
