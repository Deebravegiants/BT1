**Reasoning:**

The `execute_block` function performs `assert_eq!(transactions.num_shards(), self.num_shards())` synchronously and unconditionally *before* entering the dispatch loop that sends `ExecuteSubBlocks` commands to `command_txs[i]` [1](#0-0) . Since this is a single-threaded, sequential check-then-act sequence within one function call (no concurrent mutation of `self.command_txs` or `transactions` between the assert and the loop), there is no data race window where the assertion could pass and then the underlying vectors diverge in length — Rust's ownership model prevents `transactions` (moved into the function) or `self.command_txs` (an immutable `Vec` field) from being mutated concurrently by another thread during this call.

More fundamentally, `num_shards()` for `LocalExecutorClient` is fixed at node startup via `command_txs.len()`, which is set once when `LocalExecutorService::setup_local_executor_shards` is constructed based on a local configuration value, not on any transaction/block content [2](#0-1) [3](#0-2) . The `PartitionedTransactions` object is produced by the block partitioner using that same shard count as its parameter, not derived from or influenced by unprivileged transaction/authenticator/API input — an attacker submitting transactions cannot cause the partitioner to emit a different `num_shards()` than what the local executor was configured with.

Even in the hypothetical case where the assert were bypassed, `sub_blocks.into_iter().enumerate()` zips index `i` against `self.command_txs[i]` positionally; this only misroutes sub-blocks between shard worker threads within the *same validator's local process* — it does not change which account's write-set is applied, since the write-set for a transaction is determined by the transaction's own signer/sender inside the VM, not by which shard thread happens to execute it. Sharded execution results are ultimately reconciled and applied to global state via `sharded_aggregator_service::aggregate_and_update_total_supply` and the final `ShardedExecutionOutput`, not by shard identity [4](#0-3) . This mechanism is purely an internal parallel-execution optimization inside a single validator, out of reach of unprivileged remote input, and does not constitute a custody-boundary violation.

    pub fn setup_local_executor_shards(
        num_shards: usize,
        num_threads: Option<usize>,
    ) -> LocalExecutorClient<S> {
        let (global_executor, global_cross_shard_tx) = Self::setup_global_executor();
        let num_threads = num_threads
            .unwrap_or_else(|| (num_cpus::get() as f64 / num_shards as f64).ceil() as usize);
        let (command_txs, command_rxs): (
            Vec<Sender<ExecutorShardCommand<S>>>,
            Vec<Receiver<ExecutorShardCommand<S>>>,
        ) = (0..num_shards).map(|_| unbounded()).unzip();
        let (result_txs, result_rxs): (
            Vec<Sender<Result<Vec<Vec<TransactionOutput>>, VMStatus>>>,
            Vec<Receiver<Result<Vec<Vec<TransactionOutput>>, VMStatus>>>,
        ) = (0..num_shards).map(|_| unbounded()).unzip();
        // We need to create channels for each shard and each round. This is needed because individual
        // shards might send cross shard messages to other shards that will be consumed in different rounds.
        // Having a single channel per shard will cause a shard to receiver messages that is not intended in the current round.
        let (cross_shard_msg_txs, cross_shard_msg_rxs): (
            Vec<Vec<Sender<CrossShardMsg>>>,
            Vec<Vec<Receiver<CrossShardMsg>>>,
        ) = (0..num_shards)
            .map(|_| {
                (0..MAX_ALLOWED_PARTITIONING_ROUNDS)
                    .map(|_| unbounded())
                    .unzip()
            })
            .unzip();
        let executor_shards = command_rxs
            .into_iter()
            .zip(result_txs)
            .zip(cross_shard_msg_rxs)
            .enumerate()
            .map(|(shard_id, ((command_rx, result_tx), cross_shard_rxs))| {
                let cross_shard_client = LocalCrossShardClient::new(
                    global_cross_shard_tx.clone(),
                    cross_shard_msg_txs.clone(),
                    cross_shard_rxs,
                );
                Self::new(
                    shard_id as ShardId,
                    num_shards,
                    num_threads,
                    command_rx,
                    result_tx,
                    cross_shard_client,
                )
            })
            .collect();
        LocalExecutorClient::new(command_txs, result_rxs, executor_shards, global_executor)
    }
